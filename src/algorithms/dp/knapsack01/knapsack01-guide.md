# 0/1 배낭 — 조합을 세지 않고 용량별 최선을 한 줄씩 적는다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 조합을 전부 만들어 보는
방법에서 표 채우기까지 가는 경로를 따라갑니다. 마지막에는 실제로 동작하는 코드를 한 조각씩
만듭니다.

### 전체 컨셉

물건마다 무게와 가치가 있고 배낭에는 무게 한도가 있습니다. 같은 물건은 하나뿐이라 **담거나
두고 가거나 둘 중 하나**이고, 무게 합이 한도를 넘지 않게 하면서 가치 합을 가장 크게 만드는
것이 목표예요.

```text
물건 4개                     배낭 용량 7
  1번  무게1 가치1
  2번  무게3 가치4           담을 조합 = 2^4 = 16 가지
  3번  무게4 가치5           물건이 100개면 2^100 가지
  4번  무게5 가치7
```

조합을 통째로 볼 필요가 없다는 것이 이 알고리즘의 관찰입니다. 물건을 하나씩 늘려 가면서
「앞의 `i` 개만 놓고 골랐을 때 용량 `c` 로 얻는 최대 가치」를 표에 적어 두면, 다음 물건을 볼
때 그 표만 보면 돼요.

```text
표 한 칸 = "앞의 i 개로 용량 c 를 쓴 최선"

        c=0  1  2  3  4  5  6  7
  i=0     0  0  0  0  0  0  0  0     ← 물건이 없으면 전부 0
  i=1     0  1  1  1  1  1  1  1     ← 무게1·가치1 을 본 뒤
  i=2     0  1  1  4  5  5  5  5     ← 무게3·가치4 를 본 뒤
  i=3     0  1  1  4  5  6  6  9     ← 무게4·가치5 를 본 뒤
  i=4     0  1  1  4  5  7  8  9     ← 무게5·가치7 을 본 뒤
                                ↑ 답
```

새 물건 하나에 대한 선택지는 언제나 둘뿐입니다 — 두고 가거나, 담거나. 그래서 한 칸을 정하는
규칙도 둘로 갈려요.

| 상황 | 그 칸에 적을 값 |
| --- | --- |
| 남은 용량 `c` 가 무게 `w` 보다 작다 | **바로 윗 칸**의 값을 그대로 쓴다 |
| 담을 수 있다 | 두고 갔을 때(윗 칸)와 담았을 때(**무게만큼 왼쪽으로 간 윗 칸** + 가치) 중 큰 쪽 |

「무게만큼 왼쪽으로 간 윗 칸」이 이 알고리즘의 전부입니다. 이 물건을 담으면 용량이 `w` 만큼
줄어드니, 줄어든 용량을 **앞의 물건들만으로** 채운 최선을 이어받는 것이에요.

```text
dp[3][7] 을 정하는 장면 (무게4·가치5 를 볼 차례)

  두고 간다 →  dp[2][7] = 5
  담는다    →  dp[2][7-4] + 5 = dp[2][3] + 5 = 4 + 5 = 9
                     ↑ 윗 줄에서 가져온다. 같은 줄에서 가져오면
                       이 물건을 두 번 담게 된다.
  큰 쪽 9 를 적는다
```

표는 `(물건 수 + 1) × (용량 + 1)` 칸이고 한 칸에 비교 한 번이면 되므로, `2^n` 이 `n × W` 로
내려옵니다. 물건 100개·용량 10,000 이면 1,010,101 칸이라 1초 안에 끝나요. 입력이 무엇이든
표 전체를 한 번씩 채우니 운이 좋아 빨라지는 일도, 나빠서 느려지는 일도 없습니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **부분집합의 개수가 `2^n`** 이라는 셈. 이 글이 수치로 반박할 출발점입니다.
- **`dp[i][c]` 같은 2차원 첨자 읽기.** 표의 행과 열을 좌표로 가리켜요.
- **두 값 중 큰 쪽 고르기.** 한 칸을 정하는 데 이것만 씁니다.

몰라도 되는 것은 재귀·메모이제이션·그래프예요. 이 글은 표를 왼쪽 위에서 오른쪽 아래로 채우는
반복문만 씁니다.

### 아이디어 상세 — 용량별 최선의 표를 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function knapsack01(weights: number[], values: number[], W: number): number;
```

- 입력: 물건별 무게 `weights`, 같은 자리의 가치 `values`, 배낭의 무게 한도 `W`.
- 출력: **최대 가치 합 하나**. 어떤 물건을 골랐는지는 묻지 않아요.
- 제약: 물건 수 `n ≤ 100`, 무게·가치 각각 `10^4` 이하, 용량 `W ≤ 10^4`. 시간 1초.

여기서 한 가지 눈여겨볼 것이 있어요. 같은 물건이 하나씩만 있습니다. 반쪽만 담거나 두 개를
담는 선택지가 없어요.

```text
물건 하나에 대한 결정이 둘뿐이다
  ┗ 담는다 / 두고 간다
  ┗ 그래서 물건 n 개의 결정 조합이 2^n 가지가 된다
```

지금은 그냥 지나가도 됩니다. 이 성질이 필요해지는 자리가 뒤에 옵니다.

이 글이 쓰는 기호는 여섯이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 물건의 개수 | `n ≤ 100` |
| `W` | 배낭의 무게 한도 | `W ≤ 10^4` |
| `i` | 지금까지 본 물건 수. 표의 행 | `0 ≤ i ≤ n` |
| `c` | 쓸 수 있는 무게. 표의 열 | `0 ≤ c ≤ W` |
| `w` · `v` | 지금 보고 있는 물건 하나의 무게 · 가치 | `i` 번째 물건의 것 |
| `dp[i][c]` | 앞의 `i` 개만 놓고 골랐을 때 용량 `c` 로 얻는 최대 가치 | 이것이 표의 한 칸 |

가장 먼저 떠오르는 방법으로 시작합시다. 각 물건을 담을지 말지 정하는 것이니, 모든 결정
조합을 만들어 무게 합이 `W` 이하인 것 중 가치 합이 가장 큰 것을 고르면 됩니다.

```text
물건 4개 → 조합 2^4 = 16 가지
  {} {1} {2} {3} {4} {1,2} {1,3} {1,4} {2,3} {2,4} {3,4}
  {1,2,3} {1,2,4} {1,3,4} {2,3,4} {1,2,3,4}

물건 100개 → 2^100 ≈ 1.27 × 10^30 가지
  1초에 10^9 가지를 본다 해도
  1.27 × 10^21 초 ≈ 4 × 10^13 년   ← 우주 나이보다 길다
```

조합을 하나씩 보는 길은 여기서 끊깁니다. 넷이면 되는 방법이 백에서 안 되는 이유는 가짓수가
물건 하나마다 두 배가 되기 때문이에요. 그러면 이 `2^100` 안에 겹치는 일이 얼마나 섞여 있는지
봅시다. 16가지 중 앞부분을 공유하는 셋을 나란히 놓은 것이에요.

```text
{1,2}       무게 1+3=4   가치 1+4=5
{1,2,3}     무게 4+4=8   가치 5+5=10     ← 앞의 4 와 5 를 다시 셌다
{1,2,4}     무게 4+5=9   가치 5+7=12     ← 또 다시 셌다
```

앞부분 `{1,2}` 의 무게 합과 가치 합을 세 번 다시 셌습니다. 두 조합이 다른 자리는 마지막 물건
하나뿐인데 앞부분을 통째로 다시 센 셈이에요. 그러면 이런 생각을 해 볼 수 있습니다. 앞부분을
센 결과를 버리지 않고 **적어 두었다가** 이어받을 수는 없을까요?

해 봅시다. 물건을 왼쪽부터 하나씩 늘려 가면서, 그 시점까지의 부분해를 적어 둡니다. 그러면
비용은 **적어 둔 항목의 개수**가 돼요. 조합마다 한 항목씩 적으면 항목 수는 이렇습니다.

```text
물건을 하나씩 늘리며 조합을 전부 적는다  (무게 [1,3,4,5])
  i=0   {}                                                    1개
  i=1   {} {1}                                                2개
  i=2   {} {1} {2} {1,2}                                      4개
  i=3   … 8개
  i=4   … 16개                                     합계 31개
```

항목 수가 층마다 두 배가 되니 아무것도 줄지 않았습니다. 그러면 **무엇을 적어야** 항목이
줄어들까요? 여기서부터가 이 알고리즘의 핵심입니다.

같은 입력을 두 방식으로 처리하고 항목 수를 나란히 세 봅니다. 왼쪽은 방금 본 것이고, 오른쪽은
**무게 합이 같은 조합을 한 항목으로 합친** 것이에요. 합칠 때는 가치 합이 큰 쪽만 남깁니다.

```text
조합마다 하나 — 31개                    무게 합이 같으면 합친다 — 20개
  i=0   {}                       1개      i=0   무게 0                    1개
  i=1   {} {1}                   2개      i=1   무게 0 1                  2개
  i=2   {} {1} {2} {1,2}         4개      i=2   무게 0 1 3 4              4개
  i=3   8개                      8개      i=3   무게 0 1 3 4 5 7          6개
  i=4   16개                    16개      i=4   무게 0 1 3 4 5 6 7        7개
        └ 층마다 두 배                          └ 용량 7 을 넘는 것은 버렸다
```

31개가 20개가 됐습니다. 물건을 넷 더 붙여 여덟 개로 만들면 차이가 더 벌어져요. 같은 용량
`W = 7` 에 무게 `[1, 3, 4, 5, 2, 6, 3, 7]` 을 넣고 두 방식을 다시 셉니다.

```text
조합마다 하나 — 511개                   무게 합이 같으면 합친다 — 52개
  1 2 4 8 16 32 64 128 256                1 2 4 6 7 8 8 8 8
        └ 층마다 두 배로 계속 는다              └ 다섯째 층부터 8 에서 멈춘다
```

오른쪽에서 눈여겨볼 것은 **항목 수가 8에서 멈춘다**는 점입니다. 물건을 아무리 더 붙여도
한 층의 항목이 8개를 넘지 않아요. 용량이 7이라 무게 합으로 가능한 값이 `0`부터 `7`까지
여덟 가지뿐이기 때문입니다. 이 관찰이 다음 걸음의 재료예요.

그러면 합치는 기준을 개념으로 정합시다. 가장 단순한 후보부터 시험합니다. **무게 합 하나만**
기억하고 「지금까지 몇 번째 물건을 봤는가」는 안 기억하는 것이에요. 항목이 한 줄로 줄어드니
가장 적습니다.

```ts
const best = new Array<number>(W + 1).fill(0); // 한 줄만 유지한다
for (let i = 0; i < n; i++)
  for (let c = w[i]; c <= W; c++)
    best[c] = Math.max(best[c], best[c - w[i]] + v[i]);
```

같은 입력에 용량만 10으로 바꿔 실행하면 이 방식이 무엇을 놓치는지 값으로 확인됩니다.

```text
무게 [1,3,4,5]  가치 [1,4,5,7]  용량 10

한 줄만 유지     14     ← 무게5·가치7 짜리를 두 번 담았다 (무게 10, 가치 14)
층을 나눈다      13     ← 1번·3번·4번을 한 번씩 (무게 1+4+5=10, 가치 1+5+7=13)
```

`best[c - w]` 를 읽는 시점에 그 칸이 **이번 물건을 이미 담은 값**일 수 있어서 같은 물건이
두 번 들어갔습니다. 그러니 합치는 기준에 **몇 번째 물건까지 봤는가**가 함께 들어가야 해요.

> 상태는 두 수로 적습니다 — **본 물건 수 `i` 와 쓴 무게 `c`.** 그 상태의 값이 「그때 얻을 수
> 있는 최대 가치」이고, 이것이 `dp[i][c]` 입니다.

```text
합치는 기준       무게 합 c 만 같으면 합친다        → 같은 물건이 두 번 들어간다
                  본 물건 수 i 와 무게 합 c 가      → i 번째 물건은 i 층에서 한 번만 결정된다
                  둘 다 같을 때만 합친다
```

이 기준을 다섯 물건 앞의 작은 입력에 걸음마다 적용해 봅시다. 무게 `[1, 3, 4, 5]`,
가치 `[1, 4, 5, 7]`, 용량 `7` 이에요. 각 층에서 도달 가능한 무게 합과 그때의 최대 가치를
적습니다.

```text
i=0   무게 0                     가치 0
i=1   무게 0 1                   가치 0 1
i=2   무게 0 1 3 4               가치 0 1 4 5
i=3   무게 0 1 3 4 5 7           가치 0 1 4 5 5 9
i=4   무게 0 1 3 4 5 6 7         가치 0 1 4 5 7 8 9
                          ↑ 용량 7 에서 얻는 최대 가치가 9 다
```

각 상태 변수의 범위도 이 기준이 정합니다. 위에서 실제로 나온 값이 그대로 범위예요.

```text
i   0 부터 n 까지         물건을 하나씩 늘리므로 층이 n+1 개
c   0 부터 W 까지         무게 합이 W 를 넘으면 담을 수 없어 버린다
    → 항목 수는 아무리 많아도 (n+1)(W+1) 개
```

**상태를 이어받는 동작을 값으로 확인해 봅시다.** 쉬운 경우와 불안한 경우를 나눠서 봅니다.
쉬운 경우는 이번 물건을 담을 수 없는 칸이에요 — 윗 줄의 같은 자리를 그대로 씁니다.

```text
i=3 (무게4·가치5), c=2 를 정한다
  2 < 4 라 담을 수 없다
  dp[3][2] = dp[2][2] = 1        ← 윗 줄 같은 자리를 복사한다
```

불안한 경우는 담을 수 있는 칸입니다. **윗 줄에서 무게만큼 왼쪽으로 건너뛴 칸**을 읽어야
하는데, 그 칸이 아직 안 채워졌으면 아무 값이나 읽게 돼요. 한 줄을 왼쪽부터 오른쪽으로
채우면서 그 자리가 언제 준비되는지 확인합니다.

```text
i=3 줄 (무게4·가치5) 을 c=0 부터 채운다.  읽는 자리는 전부 i=2 줄이다

  c=0..3   c < 4 라 윗 줄 복사        dp[3][0..3] = 0 1 1 4
  c=4      두고 감 dp[2][4] = 5
           담음   dp[2][0] + 5 = 5   ← i=2 줄의 0번 칸. 이미 채워져 있다
           같으면 두고 간다            dp[3][4] = 5
  c=7      두고 감 dp[2][7] = 5
           담음   dp[2][3] + 5 = 9   ← i=2 줄의 3번 칸. 이미 채워져 있다
                                      dp[3][7] = 9
```

읽는 자리가 **언제나 윗 줄**이라 건너뛰는 칸이 없습니다. `i` 번째 줄을 채울 때 `i-1` 번째
줄은 이미 전부 채워져 있으니, `c - w` 가 0 이든 `W` 든 값이 준비돼 있어요. 왜 맞는지를
루프의 종료 조건으로 말하면, 바깥 루프가 `i` 를 하나 올리기 전에 안쪽 루프가 그 줄의
`c = 0 … W` 를 전부 채우기 때문입니다.

마지막으로 **항목을 어떻게 담을지**를 값으로 정합니다. 도달 가능한 무게 합만 모아 둘 수도
있고, `0 … W` 를 전부 미리 깔 수도 있어요. 두 방식의 항목 수를 실제로 세 봅시다.

```text
n = 50, W = 1000 (무게는 고정 생성식)

  도달 가능한 무게 합만 모은다     36,610 개    층별로 1 2 4 8 15 26 42 84 … 로 늘다가 포화
  0 … W 를 전부 깐다               51,051 개    (50+1) × (1000+1)
                                                └ 1.39 배
```

| 담는 방식 | 항목 수 | 한 항목을 읽는 비용 |
| --- | --- | --- |
| 도달 가능한 무게 합만 | 36,610 | 해시 조회 — 평균 상수 |
| `0 … W` 를 전부 | **51,051** | **배열 첨자 — 상수** |

항목 수는 도달 가능한 것만 모으는 쪽이 1.39배 적습니다. 그런데 그쪽은 어느 무게 합이 있는지
미리 알 수 없어 해시가 필요하고, 물건이 늘수록 도달 가능한 값이 `0 … W` 를 거의 덮어요.
위 층별 수열이 `1 2 4 8 15 26 42 84 …` 로 늘다가 포화하는 것이 그것입니다.

```text
전부 까는 쪽을 고른다
  항목 수는 1.39 배 많지만 → dp[i][c] 가 배열 첨자 두 번이다
  도달 못 하는 무게 합의 칸에는 "그 용량으로 얻는 최대 가치" 가 그대로 들어간다
    (무게 합 2 를 정확히 만들 수 없어도, 용량 2 로 얻는 최선은 1 이다)
```

**표 한 장이 나왔습니다.** 행이 `i = 0 … n`, 열이 `c = 0 … W`, 칸에 최대 가치를 적는 것이고,
`n = 4` · `W = 7` 이면 40칸입니다. 조합을 전부 세던 31개 항목이 층마다 두 배로 늘던 자리에서,
층 크기가 8로 고정된 표가 됐어요.

### 수행으로 알아보는 알고리즘 — 표 다섯 줄로 답 하나를 읽는다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지
가되, 조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const weights = [1, 3, 4, 5];
const values = [1, 4, 5, 7];
const W = 7;
// 이 절이 끝나면 9 가 나와야 한다
```

물건을 왜 하필 이 넷으로 뒀을까요? 칸을 정하는 세 갈래를 **모두 실행하게** 하려는 것입니다.
무게 5짜리가 없으면 「담는 쪽이 더 작아서 두고 간다」가 한 번도 나오지 않아요.

```text
표 dp 를 (n+1) × (W+1) 로 만들고 전부 0 으로 둔다

i 를 1 부터 n 까지:
    w ← i 번째 물건의 무게
    v ← i 번째 물건의 가치
    c 를 0 부터 W 까지:
        만약 c < w 이면:
            dp[i][c] ← dp[i-1][c]                     ① 못 담는다
        아니면:
            두고감 ← dp[i-1][c]
            담음   ← dp[i-1][c - w] + v
            dp[i][c] ← 두고감 ≥ 담음 ? 두고감 : 담음   ② 두고 간다 · ③ 담는다

dp[n][W] 를 돌려준다
```

#### 1. 0번째 줄을 0으로 깐다

「아이디어 상세」에서 층을 `i = 0` 부터 셌습니다. 그 0번째 층이 표의 첫 줄이에요. 이 줄이
없으면 `i = 1` 을 채울 때 가져올 윗 줄이 없습니다.

```ts
const n = values.length;
const dp = Array.from({ length: n + 1 }, () =>
  Array.from({ length: W + 1 }, () => 0),
);
```

실행하면 이렇게 나와요. 아직 값은 전부 0이고 자리만 잡혔습니다.

```text
        c=0  1  2  3  4  5  6  7
  i=0     0  0  0  0  0  0  0  0
  i=1     0  0  0  0  0  0  0  0     ← 아직 안 채운 줄
  i=2     0  0  0  0  0  0  0  0
  i=3     0  0  0  0  0  0  0  0
  i=4     0  0  0  0  0  0  0  0
```

| 왜 `+1` 인가 | |
| --- | --- |
| 줄이 `n + 1` 개 | 0번째 줄(「물건이 없다」)을 실제 칸으로 둔다 |
| 열이 `W + 1` 개 | 용량 0 칸(「아무것도 못 담는다」)을 실제 칸으로 둔다 |

둘 다 「아무것도 없는 상태」를 표 안에 넣는 것이라, 코드에 빈 입력 분기가 따로 안 생겨요.

#### 2. 한 물건을 놓고 한 줄을 채운다

바깥 루프가 물건, 안쪽 루프가 용량입니다. 「아이디어 상세」에서 확인한 「읽는 자리가 언제나
윗 줄」을 코드로 옮기면 두 줄에 이름을 붙이는 형태가 돼요.

```ts
for (let i = 1; i <= n; i++) {
  const w = weights[i - 1] as number;
  const v = values[i - 1] as number;
  const prev = dp[i - 1] as number[]; // 윗 줄 — 이 물건을 아직 안 본 층
  const cur = dp[i] as number[]; // 이번 줄 — 이 물건까지 본 층

  for (let c = 0; c <= W; c++) {
    // 여기서 한 칸이 정해진다
  }
}
```

이름을 붙여 두는 것은 편의가 아닙니다. **`prev` 에서만 읽는다**는 것이 이 알고리즘의 규칙
전부인데, 첨자로 쓰면 그 규칙이 `i - 1` 이라는 숫자 뒤로 숨어요.

```text
i 바깥 · c 안쪽 (옳다)        c 바깥 · i 안쪽 (틀린다)
  i=1 줄을 왼→오 로 완성        c=0 열을 위→아래 로 완성
  i=2 줄을 왼→오 로 완성        c=1 열을 채울 때 prev[c-w] 가
  …                              아직 안 채워진 열을 가리킬 수 있다
```

`weights[i - 1]` 인 것은 표의 `i` 가 1부터인데 배열은 0부터이기 때문입니다. 표의 `i` 번째
줄은 「앞의 `i` 개를 본 뒤」라서, 방금 추가된 물건이 배열의 `i - 1` 번이에요.

#### 3. 칸 하나를 세 갈래로 정한다

갈림길을 셋으로 나누어 둡니다. `Math.max` 한 줄로 줄이면 짧아지지만 **어느 쪽이 선택됐는지**가
코드에 남지 않아, 표를 따라갈 때 확인할 것이 사라져요.

```ts
if (c < w) {
  // ① 못 담는다 — 남은 용량이 이 물건의 무게보다 작다
  cur[c] = prev[c] as number;
} else {
  const skip = prev[c] as number;              // 두고 간다
  const take = (prev[c - w] as number) + v;    // 담는다
  // ② 두고 가는 쪽이 크거나 같다 · ③ 담는 쪽이 크다
  cur[c] = skip >= take ? skip : take;
}
```

여기서 가장 중요한 줄은 `take` 를 만드는 줄입니다. **`prev` 에서 읽는다**는 것이 같은 물건을
두 번 담지 않게 막는 자리이고, 코드 전체에서 여기 하나뿐이에요.

```text
prev[c-w] + v      이 물건을 아직 안 본 층에서 이어받는다              ✓
cur [c-w] + v      이 물건을 이미 담았을 수도 있는 값에 또 더한다      ✗
                   └ 「아이디어 상세」에서 14 가 나온 그 방식이다
```

동점(`skip === take`)에서 두고 가는 쪽을 고르는 것은 값에 영향이 없습니다. 다만 **어떤 물건을
골랐는지**를 나중에 거슬러 확인할 때 답이 달라지므로 한쪽으로 고정해 두는 편이 낫습니다.

#### 짚고 가기 — 비율이 높은 것부터 담으면 되지 않는다

가치를 무게로 나눈 값이 높은 것부터 담으면 될 것 같지 않나요? 분수 배낭(물건을 쪼갤 수 있는
문제)에서는 이 방법이 실제로 최적이라, 0/1 에서도 될 것 같습니다. 그 방법대로 실행해 봅시다.
무게 `[3, 4]`, 가치 `[4, 5]`, 용량 `4` 예요.

```text
비율   1번 물건 = 4/3 ≈ 1.33      2번 물건 = 5/4 = 1.25
       └ 높은 쪽을 먼저 담는다

담기   1번(무게3) 담음 → 남은 용량 1
       2번(무게4)은 1 에 안 들어감 → 버린다
       비율 순서로 담은 답 = 4        ✗

정답   2번 하나만 담으면 무게 4 로 딱 맞고 가치 5
       정답                = 5        ✓
```

비율이 높은 쪽을 담느라 **남은 용량 1을 버렸습니다.** 쪼갤 수 없으니 남은 용량은 그냥
낭비예요. 지금의 이득이 나중의 손해가 되는지 그 자리에서는 알 수 없다는 것이 이 방법이
0/1 에서 최적이 아닌 이유입니다.

```text
분수 배낭이라면        1번을 담고, 남은 1 에 2번을 1/4 만큼 담는다
                       가치 4 + 5×(1/4) = 5.25   ← 비율 순서가 최적이다

0/1 배낭이라면        남은 1 은 그냥 버려진다
                       가치 4                    ← 비율 순서가 최적이 아니다
```

물건을 쪼갤 수 있는지 없는지가 같은 절차를 최적에서 오답으로 바꿉니다.

#### 4. 표를 왼쪽 위부터 채워 내려간다

앞의 세 조각을 `knapsack01([1, 3, 4, 5], [1, 4, 5, 7], 7)` 에 적용하면 5줄 × 8칸이 채워집니다.
오른쪽에 그 칸이 어느 갈래로 정해졌는지를 함께 적었어요.

  i=1     0  1  1  1  1  1  1  1      ①③③③③③③③

한 칸이 정해질 때 조건이 어떻게 판정되는지 아홉 자리를 뽑아 적으면 아래와 같습니다.

| 단계 | 무슨 일 | 조건 판정 | 정해진 값 |
| --- | --- | --- | --- |
| T1 | `i=1` (w=1,v=1), `c=0` | `0 < 1` 참 → ① | `dp[1][0] = dp[0][0] = 0` |
| T2 | `i=1`, `c=1` | `1 < 1` 거짓 · `skip=0`, `take=dp[0][0]+1=1` · `0 >= 1` 거짓 → ③ | `dp[1][1] = 1` |
| T3 | `i=2` (w=3,v=4), `c=2` | `2 < 3` 참 → ① | `dp[2][2] = dp[1][2] = 1` |
| T4 | `i=2`, `c=3` | `skip=1`, `take=dp[1][0]+4=4` · `1 >= 4` 거짓 → ③ | `dp[2][3] = 4` |
| T5 | `i=3` (w=4,v=5), `c=4` | `skip=5`, `take=dp[2][0]+5=5` · `5 >= 5` 참 → ② | `dp[3][4] = 5` |
| T6 | `i=3`, `c=7` | `skip=5`, `take=dp[2][3]+5=9` · `5 >= 9` 거짓 → ③ | `dp[3][7] = 9` |
| T7 | `i=4` (w=5,v=7), `c=5` | `skip=6`, `take=dp[3][0]+7=7` · `6 >= 7` 거짓 → ③ | `dp[4][5] = 7` |
| T8 | `i=4`, `c=7` | `skip=9`, `take=dp[3][2]+7=8` · `9 >= 8` 참 → ② | `dp[4][7] = 9` |
| T9 | 읽기 | — | `dp[4][7] = 9` 를 돌려준다 |

**세 갈래가 모두 나왔습니다.** 표 전체 32칸(0번째 줄 제외)의 갈래 분포도 함께 적어 둡니다.

```text
①  못 담는다        13 칸      T1 · T3
②  두고 가는 쪽      2 칸      T5 · T8      ← 가장 드물다
③  담는 쪽          17 칸      T2 · T4 · T6 · T7
```

여기서 헷갈리기 쉬운 포인트는 T5입니다. 두고 가도 5, 담아도 5라 값이 같아요 — 무게4·가치5
하나를 담는 것과 무게1·가치1 + 무게3·가치4 를 담는 것이 같은 가치이고, 동점이라 `>=` 가
두고 가는 쪽을 골랐습니다. T8은 **마지막 물건이 답에 안 들어간다**는 것을 보여요. 무게5·가치7
을 담으면 남은 용량이 2뿐이라 `dp[3][2] = 1` 밖에 못 넣어 8이고, 두고 가면 9입니다.

#### 짚고 가기 — 줄 하나로 줄일 때 순회 방향이 답을 바꾼다

표를 다 채우고 나면 마지막 줄만 쓰니, 줄 하나만 유지하면 될 것 같지 않나요? 실제로 그렇게
줄일 수 있습니다. **다만 안쪽 루프의 방향이 바뀌어요.**

```ts
const dp1 = new Array<number>(W + 1).fill(0);
for (let i = 0; i < n; i++)
  for (let c = W; c >= weights[i]; c--)          // 오른쪽에서 왼쪽으로
    dp1[c] = Math.max(dp1[c], dp1[c - weights[i]] + values[i]);
```

**이 입력에서는 방향을 뒤집어도 답이 틀리지 않습니다.** 그래서 이 자리가 함정이에요 —
테스트가 통과하니 틀린 줄 모르고 넘어갑니다.

```text
무게 [1,3,4,5]  가치 [1,4,5,7]

용량 7    왼→오 9      오른→왼 9      ← 같다. 버그가 확인되지 않는다
용량 10   왼→오 14     오른→왼 13     ← 여기서 갈린다
용량 11   왼→오 15     오른→왼 13
```

왼쪽에서 오른쪽으로 순회하면 `dp1[c - w]` 가 **이번 물건을 이미 담은 값**입니다. 두 줄을 쓸
때 `prev` 가 하던 일을, 한 줄에서는 **아직 안 건드린 칸을 읽는 것**이 대신해요.

```text
용량 10, 무게5·가치7 을 왼→오 로 처리하면
  c=5    dp1[5] = max(dp1[5], dp1[0] + 7) = 7        여기서 5번 칸이 7 이 된다
  c=10   dp1[10] = max(dp1[10], dp1[5] + 7) = 14     ← 방금 담은 값을 또 이어받았다
                                    └ 같은 물건이 두 번 들어갔다
```

오른쪽에서 왼쪽으로 순회하면 `dp1[c - w]` 는 `c` 보다 작은 자리라 **아직 이번 물건을 반영하지
않은 값**입니다. 방향 하나가 `prev` 의 역할을 합니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 없어요 — 빈 입력은 `n = 0`
이라 바깥 루프가 한 번도 실행되지 않고 `dp[0][W] = 0` 이 그대로 답이 됩니다.

```ts
export function knapsack01(
  weights: number[],
  values: number[],
  W: number,
): number {
  const n = values.length;

  // dp[i][c] = 앞의 i 개만 놓고 골랐을 때, 용량 c 로 얻는 최대 가치.
  // 0 번째 줄은 "물건이 하나도 없다" 라 전부 0 이다.
  const dp = Array.from({ length: n + 1 }, () =>
    Array.from({ length: W + 1 }, () => 0),
  );

  for (let i = 1; i <= n; i++) {
    const w = weights[i - 1] as number;
    const v = values[i - 1] as number;
    const prev = dp[i - 1] as number[]; // 윗 줄 — 이 물건을 아직 안 본 층
    const cur = dp[i] as number[]; // 이번 줄 — 이 물건까지 본 층

    for (let c = 0; c <= W; c++) {
      if (c < w) {
        // ① 못 담는다 — 남은 용량이 이 물건의 무게보다 작다. 윗 줄의 값을 그대로 쓴다.
        cur[c] = prev[c] as number;
      } else {
        const skip = prev[c] as number;
        const take = (prev[c - w] as number) + v;
        // ② 두고 가는 쪽이 크거나 같다 · ③ 담는 쪽이 크다
        cur[c] = skip >= take ? skip : take;
      }
    }
  }

  return (dp[n] as number[])[W] as number;
}
```

```text
knapsack01([1,3,4,5], [1,4,5,7], 7)   →  9
knapsack01([], [], 10)                →  0
knapsack01([5], [42], 5)              →  42
knapsack01([10], [100], 5)            →  0
```

### 알아 두면 좋은 개념 — 마르코프 성질

「아이디어 상세」에서 조합을 합칠 때 근거로 쓴 문장이 있습니다 — *"`(i, c)` 가 같으면 앞으로
할 수 있는 일이 완전히 같다"*. 이 성질에는 이름이 있어요. **마르코프 성질**, 또는
무기억성이라고 합니다.

```text
{1,2} 로 무게 4 를 쓰고 왔다        ┐
{3}   로 무게 4 를 쓰고 왔다        ┘  →  (i=2 이후, 남은 용량 3) 에서 할 수 있는 일이 같다
       └ 어떤 경로로 왔는지는 앞으로에 아무 영향이 없다
```

다음에 일어날 수 있는 일이 **지금 상태에만** 달려 있고 거기까지 온 경로에는 안 달려 있다,
가 이 성질의 정의입니다. 표를 만들 수 있었던 것이 이 성질 덕분이에요 — 경로가 `2^n` 가지인데
상태는 `(n+1)(W+1)` 가지뿐이라, 같은 상태로 오는 경로를 한 칸에 합칠 수 있었습니다.

| 이 성질이 있으면 | 이 성질이 없으면 |
| --- | --- |
| 같은 상태의 경로를 한 칸에 합친다 | 경로마다 따로 기억해야 한다 |
| 칸 수가 상태 수만큼이다 | 칸 수가 경로 수만큼이다 |
| `dp[i][c]` 로 표가 만들어진다 | 표를 만들 수 없다 |

**상태를 무엇으로 잡느냐가 곧 이 성질을 만드는 일입니다.** 「아이디어 상세」에서 무게 합
하나만 기억했을 때 답이 틀린 것이 그 예예요 — 그 상태는 「몇 번째 물건까지 봤는가」를 안
담고 있어서, 앞으로 할 수 있는 일이 같지 않았습니다. `i` 를 상태에 넣는 순간 성질이
성립하고 표를 만들 수 있게 돼요.

같은 이름을 다른 자리에서도 만납니다. 최단 경로에서 「지금 어느 노드에 있는가」만으로 남은
경로가 정해지는 것, 마르코프 연쇄에서 다음 상태의 확률이 현재 상태에만 달린 것이 같은
성질이에요. **동적 계획법으로 풀리는 문제를 알아보는 첫 질문**이 「상태를 무엇으로 잡으면
이 성질이 성립하는가」입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 전이식이 어떻게 세워지는지,
무엇이 매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- 선택이 **이진**입니다 — 담거나 두고 가거나. 여러 개 담을 수 있으면 전이식이 달라져요.
- 용량이 **정수이고 작습니다.** 표의 열이 용량이라, 실수이거나 `10^9` 이면 표를 못 만듭니다.
- 제약이 **한 축**입니다. 부피까지 함께 막으면 표가 3차원이 돼요.
- 답이 **값 하나**입니다. 최대 가치만 물으면 표 하나로 끝납니다.

```text
네 조건이 표의 모양을 그대로 정한다
  이진 선택   → 칸 하나가 두 후보의 최댓값
  정수 용량   → 열이 c = 0 … W
  한 축       → 표가 2차원
  값 하나     → 표를 다 채우고 오른쪽 아래 칸만 읽는다
```

`n × W` 가 대략 `10^7` 아래면 그대로 동작해요. 이 문제의 제약(`100 × 10^4 = 10^6`)은 그 안에
넉넉히 들어갑니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "각 물건은 한 번만 사용할 수 있다"  "가져가거나 두고 간다"
  "무게 한도를 넘지 않게"  "예산 안에서"  "시간 안에서"
  "최대 가치 · 최대 만족도 · 최대 이익"

제약에 이런 모양이 보이면
  용량 상한이 명시돼 있고 그 값이 10^4 안팎    ← 표를 만들 수 있다는 신호
  물건 수가 100 안팎                          ← 2^n 은 불가능, n×W 는 가능
```

반대로 **「물건을 쪼갤 수 있다」** 가 보이면 비율 순서로 담는 것이 최적이고, **「같은 물건을
여러 개」** 가 보이면 무한 배낭이라 전이식의 첨자가 달라집니다.

#### 실제로 쓰이는 곳

**Google OR-Tools** 의 배낭 솔버가 이 절차를 한 옵션으로 그대로 싣습니다. `SolverType`
열거에 `KNAPSACK_DYNAMIC_PROGRAMMING_SOLVER` 가 있고, 소스 주석이 이렇게 적어요.

```text
"Limited to one dimension, this solver is based on a dynamic programming
 algorithm. The time and space complexity is O(capacity * number_of_items)."

  — ortools/algorithms/knapsack_solver.h (조회 2026-08-20)
```

이 글이 유도할 `Θ(nW)` 와 같은 식이고, "Limited to one dimension" 이 위에서 적은 「제약이 한
축」 조건을 그대로 말합니다.

| 같은 열거의 다른 솔버 | 언제 쓰는가 |
| --- | --- |
| `KNAPSACK_DYNAMIC_PROGRAMMING_SOLVER` | 제약이 한 축. 이 글의 절차 |
| `KNAPSACK_MULTIDIMENSION_BRANCH_AND_BOUND_SOLVER` | 제약이 여러 축. 공식 문서 예제의 기본값 |

제약이 여러 축이면 표를 만들 수 없어서 갈라지는 것이고, 이 경계가 곧 「최적인 문제의 모양」
에서 적은 조건입니다.

- 소스: [`ortools/algorithms/knapsack_solver.h`](https://raw.githubusercontent.com/google/or-tools/stable/ortools/algorithms/knapsack_solver.h) (조회 2026-08-20)
- 문서: [Google OR-Tools — Knapsack](https://developers.google.com/optimization/pack/knapsack) (조회 2026-08-20)

#### 경쟁 설계와의 대조

같은 답을 내는 **완전히 다른 표**가 있어요 — **가치 축 DP** 입니다. 축을 바꿔
`dp[i][g] = 가치 g 를 만드는 데 필요한 최소 무게` 를 채우고, 마지막에 무게가 `W` 이하인
가장 큰 가치를 읽습니다.

$$dp[i][g] = \min\bigl(dp[i-1][g],\; dp[i-1][g - v_i] + w_i\bigr)$$

```text
무게 축   표 크기 (n+1)(W+1)        열 = 용량
가치 축   표 크기 (n+1)(Σv+1)       열 = 가치 합
          ↑ 둘 다 옳고 둘 다 표 하나를 채운다. 다른 것은 표의 크기뿐이다.
```

같은 입력(`n = 50`, `W = 1000`, 무게·가치는 고정 생성식 `w[i] = (i·17 mod 100) + 1` ·
`v[i] = (i·37 mod 500) + 1`)에 둘을 걸고 **채운 표 칸 수**를 셌습니다. 전개에 쓰는
`n = 4, W = 7` 이 아니라 이쪽을 쓰는 이유는, 그 크기에서는 **40 대 108** 이라 방향은 같아도
2.7배뿐이라서 이 문제의 제약에서 실제로 벌어지는 차이를 나타내지 못하기 때문이에요.

| 설계 | 표 칸 |
| --- | --- |
| **무게 축 DP (이 가이드)** | **51,051** |
| 가치 축 DP | 617,552 |

무게 축이 12.1배 적습니다. 이 문제의 제약에서 용량은 `10^4` 인데 가치 합은 최대
`100 × 10^4 = 10^6` 이라, 가치 축 표가 그만큼 길어지기 때문이에요.

```text
어느 축이 짧은가로 고른다

  용량 10^4, 가치 합 10^6   →  무게 축 (열 10,001 개)      ← 이 문제
  용량 10^9, 가치 합 100    →  가치 축 (열 101 개)
```

**내주는 것이 분명합니다.** 가치가 전부 1이고 용량이 `10^9` 이면 무게 축은 표를 만들 수조차
없지만 가치 축은 열이 101개뿐이에요. 고르는 기준은 절차의 우열이 아니라 **어느 축이
짧은가** 하나이고, 그 값이 뒤집히면 선택도 뒤집힙니다.

### 수식 정의와 유도

상태를 기호로 정의하고, 그 정의를 작은 값에 넣어 검산하고, 전이식을 세운 다음, 제약 규모를
넣어 칸 수를 계산합니다.

```text
정의   상태 dp[i][c] 와 경계·답의 자리를 기호로 적는다
  ↓
검산   그 정의를 한 칸에 넣어 손으로 계산한다
  ↓
유도   선택이 둘뿐이라는 데서 전이식을 세운다
  ↓
계수   전이식이 채우는 칸 수에 제약 규모를 넣는다
```

**먼저 상태입니다.** 앞의 `i` 개만 놓고 골랐을 때 무게 합이 `c` 이하인 최대 가치 합을
`dp[i][c]` 로 적습니다.

$$dp[i][c] = \max\Bigl\{\textstyle\sum_{k \in S} v_k \;\Bigm|\; S \subseteq \{1,\dots,i\},\; \sum_{k \in S} w_k \le c \Bigr\}$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $i$ | 지금까지 본 물건 수 (표의 행) | $0 \le i \le n$ |
| $c$ | 쓸 수 있는 무게 (표의 열) | $0 \le c \le W$ |
| $w_i$ · $v_i$ | $i$ 번째 물건의 무게와 가치 | 각각 $10^4$ 이하 |

```text
경계  dp[0][c] = 0        고를 물건이 없으면 어떤 용량에서도 가치가 0
답    dp[n][W]            표의 오른쪽 아래 칸
```

**정의를 값에 넣어 검산해 봅시다.** $i = 2$, $c = 4$ 를 넣으면 $S$ 의 후보가 넷이고, 그중
무게 조건을 지키는 것의 가치 합을 비교합니다.

```text
S ⊆ {1, 2},  Σw ≤ 4        w = [1, 3],  v = [1, 4]

  S = {}        Σw = 0 ≤ 4   Σv = 0
  S = {1}       Σw = 1 ≤ 4   Σv = 1
  S = {2}       Σw = 3 ≤ 4   Σv = 4
  S = {1,2}     Σw = 4 ≤ 4   Σv = 5      ← 가장 크다
                                dp[2][4] = 5
```

파트 1 의 표에서 `i=2` 줄 `c=4` 칸이 5였고, 정의에서 직접 계산한 값과 같습니다.

**이제 전이식을 세웁니다.** $i$ 번째 물건에 대한 결정이 둘뿐이라는 것이 유일한 재료예요.
$S$ 를 그 물건을 포함하는 것과 포함하지 않는 것으로 가르면 각각이 $i-1$ 짜리 문제가 됩니다.

```text
S 를 두 무리로 가른다
  i ∉ S   →  S ⊆ {1,…,i-1},  Σw ≤ c            그 최대가 dp[i-1][c]
  i ∈ S   →  S∖{i} ⊆ {1,…,i-1},  Σw ≤ c - w_i  그 최대가 dp[i-1][c-w_i] + v_i
            └ c ≥ w_i 일 때만 이 무리가 비어 있지 않다
셋째 무리는 없다 — 0/1 배낭이라 "반만 담기" 가 없다
```

$$
dp[i][c] =
\begin{cases}
dp[i-1][c] & (c < w_i) \\[2pt]
\max\bigl(dp[i-1][c],\; dp[i-1][c-w_i] + v_i\bigr) & (c \ge w_i)
\end{cases}
$$

식을 그대로 코드로 옮기면 이만큼입니다. **식의 $w_i$ 를 코드에서는 `w`, $v_i$ 를 `v` 로
쓰고, 물건 번호 $i$ 는 1부터인데 배열은 0부터라 $i$ 번째 물건의 무게가 `weights[i-1]` 이에요** —
이 대응은 이 글 끝까지 같습니다.

```ts
const cell = (i: number, c: number): number => {
  const w = weights[i - 1] as number;
  const v = values[i - 1] as number;
  return c < w
    ? (dp[i - 1] as number[])[c] as number
    : Math.max((dp[i - 1] as number[])[c] as number,
               ((dp[i - 1] as number[])[c - w] as number) + v);
};

cell(3, 7); // max(dp[2][7], dp[2][3] + 5) = max(5, 9) = 9
```

**마지막으로 계수입니다.** 전이식 한 벌이 칸 하나를 정하고 그 안에 비교 한두 번과 덧셈
한 번만 있으므로, 총비용은 칸 수에 비례해요.

$$\text{칸 수} = (n+1)(W+1), \qquad \text{총비용} = \Theta(nW)$$

| `n` | `W` | 칸 수 | 조합 열거 `2^n` |
| --- | --- | --- | --- |
| 4 | 7 | 40 | 16 |
| 20 | 10^4 | 210,021 | 1.05 × 10^6 |
| **100** | **10^4** | **1,010,101** | **1.27 × 10^30** |

제약 최대에서 101만 칸입니다. 파트 1 에서 `4 × 10^13` 년이 걸린다고 센 완전 열거가 이 식에서
101만 칸이 됐고, `n` 이 커질수록 두 열의 차이가 벌어집니다.

### 불변식 — `dp[i][c]` 는 앞의 `i` 개만으로 용량 `c` 를 쓴 최대 가치다

파트 1 에서 코드가 동작하는 것을 아홉 자리로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지, 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> `i` 번째 줄을 채우고 난 시점에, 그 줄의 모든 칸 `dp[i][c]` 는 **앞의 `i` 개 물건만** 놓고
> 골라 무게 합을 `c` 이하로 맞췄을 때 얻는 최대 가치 합입니다.

```text
앞의 i 개 물건만       i+1 번째 이후는 아직 안 봤다는 뜻이다
무게 합 c 이하         정확히 c 가 아니라 c 를 넘지 않는 것 전부다
최대 가치 합           그 조건을 지키는 조합 중 가치가 가장 큰 것의 값이다
```

「줄 하나를 채우고 난 시점」이 중요합니다. 칸 하나가 정해질 때마다가 아니라 **한 줄이 끝난
시점**이에요. 그래야 다음 줄이 그 줄 전체를 안심하고 읽습니다.

```text
i-1 번째 줄이 전부 참  →  i 번째 줄을 채우는 동안 prev 의 어느 칸을 읽어도 참인 값
                       →  i 번째 줄이 끝나면 그 줄이 전부 참
```

**출발점부터 봅시다.** `i = 0` 줄은 고를 물건이 없어 어떤 `c` 에서도 가치가 0이고, 코드가 그
줄을 0으로 깔았으니 참입니다. 그 뒤로 한 줄이 채워질 때 각 칸이 두 갈래 중 하나로 정해지고,
두 갈래 모두 **윗 줄의 칸만** 읽어요.

| 칸이 정해지는 갈래 | 읽는 자리 | 그 값이 뜻하는 것 |
| --- | --- | --- |
| 담을 수 없다 (`c < w`) | `prev[c]` | 앞의 `i-1` 개로 용량 `c` 를 쓴 최선 |
| 두고 간다 | `prev[c]` | 같음 — `i` 번째를 안 쓴 최선 |
| 담는다 | `prev[c-w] + v` | 앞의 `i-1` 개로 `c-w` 를 쓴 최선에 `v` 를 더한 값 |

세 갈래가 모두 `prev` 만 읽으므로, `i` 번째 물건이 두 번 들어갈 자리가 없습니다. 그리고 앞의
`i` 개로 만들 수 있는 해는 이 물건을 쓰거나 안 쓰거나 둘 중 하나라, 두 후보의 최댓값보다 큰
해가 존재하지 않아요. 두 값은 각각 실제로 만들 수 있는 해의 가치이므로 작지도 않습니다.

```text
i=3 줄 (무게4·가치5) 을 채우는 동안 읽은 자리를 전부 적으면

  c=0  1  2  3   담을 수 없다  → prev[0..3] = 0 1 1 4
  c=4            두고 감 prev[4]=5   담음 prev[0]+5=5    → 5
  c=5            두고 감 prev[5]=5   담음 prev[1]+5=6    → 6
  c=6            두고 감 prev[6]=5   담음 prev[2]+5=6    → 6
  c=7            두고 감 prev[7]=5   담음 prev[3]+5=9    → 9
       └ 읽은 자리가 전부 i=2 줄이다. i=3 줄의 칸은 한 번도 읽지 않았다
```

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 표에서 일어나는 일 | 반환 |
| --- | --- | --- |
| `weights=[]`, `values=[]`, `W=10` | 0번째 줄만 있고 바깥 루프가 실행되지 않는다 | `0` |
| `W = 0` | 열이 `c=0` 하나뿐, 모든 물건이 `c < w` | `0` |
| 모두 `W` 보다 무겁다 (`[10,20,30]`, `W=5`) | 모든 칸이 윗 줄 복사 | `0` |
| 하나가 정확히 `W` (`[5]`, `[42]`, `W=5`) | `c=5` 에서 `max(0, 0+42)` | `42` |
| 무게가 전부 1인 물건 100개, `W=10^4` | 모든 칸이 담는 갈래 | `700` |

다섯 다 특별 분기 없이 같은 전이식으로 처리됩니다. 빈 배열도 `n = 0` 이라 `dp[0][W] = 0` 이
그대로 답이 돼요.

**이제 깨뜨려 봅시다.** 불변식을 지키던 줄이 어느 것인지는 바꿔 보면 확인됩니다. 담는 쪽
값을 가져오는 자리를 **윗 줄에서 같은 줄로** 한 글자만 고칩니다.

```ts
const take = (cur[c - w] as number) + v;
//             ~~~ prev 였다
```

무게 `[1, 3, 4, 5]`, 가치 `[1, 4, 5, 7]`, **용량 10** 으로 실행하면 이렇게 나옵니다.

```text
바른 코드   13      1번·3번·4번을 한 번씩  (무게 1+4+5=10, 가치 1+5+7=13)
한 줄 바꿈  14      4번을 두 번            (무게 5+5=10,   가치 7+7=14)
                    └ 물건이 하나뿐인데 두 번 담았다
```

`cur[c - w]` 는 「이번 물건까지 이미 본 층」의 값이라, 거기에 다시 가치를 더하면 같은 물건을
한 번 더 담게 됩니다. 불변식의 「앞의 `i` 개 물건만」이 깨진 것이고, 「용량 `c` 이하」는
그대로라 무게 합은 여전히 10이에요.

```text
같은 입력, 용량 7 에서는
  바른 코드    9
  한 줄 바꿈   9      ← 값이 같다. 이 입력만으로는 확인되지 않는다
```

용량 7에서는 같은 물건을 두 번 담을 여유가 없어 값이 갈리지 않습니다. 파트 1 의 「멈춤 —
줄 하나로 줄일 때 순회 방향이 답을 바꾼다」에서 왼→오 순회가 14를 낸 것과 같은 원인이에요.
한쪽은 첨자를, 다른 쪽은 순회 방향을 바꿨을 뿐 **이번 물건을 반영한 값을 다시 읽는다**는 점이
같습니다. 덧붙이면 이 변형은 틀린 코드가 아니라 **다른 문제의 정답**입니다 — 물건이 무한히
있는 무한 배낭에서는 같은 물건을 여러 번 담는 것이 허용되니까요.

### 비용 계산

#### 비용을 세는 과정

한 번의 호출이 하는 일은 셋이고, 셋을 다 더해야 총식이 됩니다.

| 하는 일 | 비용 |
| --- | --- |
| 표 만들기 | `(n+1)(W+1)` 칸을 0으로 채운다 |
| 표 채우기 | 바깥 `n` 번 × 안쪽 `W+1` 번. T1\~T8 이 그 칸 하나하나다 |
| 읽기 | `dp[n][W]` 한 칸. `O(1)` |

칸마다 하는 일은 비교 한두 번과 덧셈 한 번이라 상수예요. T1\~T8 어느 칸을 봐도 담을 수 없는
갈래든 담는 갈래든 하는 일이 같아서, 입력이 바뀌어도 칸당 비용이 흔들리지 않습니다.

```text
총식 = O((n+1)(W+1))  +  O(n(W+1))  +  O(1)   =  Θ(nW)
             ↑ 할당           ↑ 채우기      ↑ 읽기

n = 100, W = 10^4  →  101 × 10001 = 1,010,101 칸
```

메모리도 같은 크기입니다 — `Θ(nW)` 칸을 실제로 들고 있어요. 이 제약에서는
`1,010,101 × 8바이트 ≈ 8MB` 라 256MB 안에 들어갑니다. 답만 필요하면 파트 1 의 멈춤에서 본
대로 줄 하나로 줄여 `Θ(W)` 로 만들 수 있고, 그러면 표를 거슬러 확인해 「무엇을 골랐는지」를
복원할 수 없게 되는 것이 잃는 부분이에요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (모든 물건이 `W` 보다 무겁다) | `O(nW)` | `Θ(nW)` |
| **평균적인 경우** (입력을 아무렇게나 뽑아도) | `O(nW)` | `Θ(nW)` |
| **최악의 경우** (어떤 입력이든) | `O(nW)` | `Θ(nW)` |

**세 줄이 같습니다.** 이 알고리즘은 입력을 보고 일찍 끝내는 자리가 없어 표 `(n+1)(W+1)` 칸을
언제나 한 번씩 채워요. 모든 물건이 용량보다 무거워 답이 0이어도 칸 수는 그대로입니다 —
그때도 윗 칸을 복사하는 일을 칸마다 합니다.

**보장의 종류는 최악 보장입니다.** 기대값이 아니에요 — 코드에 무작위성이 없고 입력 분포를
가정하지도 않습니다. 같은 입력에 몇 번을 실행해도 같은 칸 수를 채워요.

```text
nW 의 W 는 입력의 "크기" 가 아니라 "값" 이다

  용량 10000 을 적는 데 글자 5 개        →  표의 열 10,001 개
  용량 1000000000 을 적는 데 글자 10 개  →  표의 열 10^9 + 1 개
        ↑ 글자는 두 배인데 표는 10^5 배
```

그래서 이 알고리즘은 **의사다항(pseudo-polynomial)** 이라고 불립니다. 입력을 적은 글자 수를
기준으로 보면 지수적이에요.

#### 최악을 만드는 입력

「어떤 입력이 최악인가」라는 물음이 이 알고리즘에서는 **입력의 내용과 무관**합니다. 무게와
가치를 어떻게 배치해도 채우는 칸 수가 같기 때문이에요.

```text
최악 = 크기 둘이 제약 최대일 때
       n = 100 · W = 10^4  →  101 × 10001 = 1,010,101 칸

이때 물건 값은 아무래도 좋다. 아래 둘은 칸 수가 정확히 같다.
  weights = [1,1,…,1]          values = [1,1,…,1]          → 1,010,101 칸
  weights = [10^4,…,10^4]      values = [10^4,…,10^4]      → 1,010,101 칸
       ↑ 전부 담긴다                    ↑ 하나만 담긴다
```

앞의 것은 모든 물건이 담기고 뒤의 것은 하나만 담기는데, 하는 일은 같습니다. 「정렬된 입력이
최악」처럼 자료의 모양을 원인으로 드는 통념이 여기서는 성립하지 않아요.

**진짜 최악은 제약 밖에 있습니다.** 이 문제는 `W ≤ 10^4` 로 막아 두었지만, 같은 코드에
`W = 10^9` 을 주면 표 할당에서 먼저 실패합니다 — `100 × 10^9` 칸은 배열로 잡을 수 없어요.
**이 알고리즘의 최악은 용량 값 하나가 정합니다.**

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 조합을 전부 세는 대신 **무게 합이 같은 것을
한 항목으로 합쳤고**, 합치는 기준에 「본 물건 수」를 함께 넣어 상태를 `(i, c)` 두 수로 적었고,
그 표가 정확한 답을 주는 근거는 **윗 줄만 읽는다**는 불변식입니다.

```text
물건을 하나씩 늘린다 → (i, c) 칸에 최대 가치를 적는다 → dp[n][W] 를 읽는다
        └ 층 크기가 W+1 로 고정된다      └ prev 만 읽어 같은 물건이 두 번 안 들어간다
```

먼저 답이 붙는 문제 하나입니다. 본문 T5 에서 `skip` 과 `take` 가 둘 다 5였어요. 코드가
`skip >= take` 대신 `skip > take` 였다면 `dp[3][4]` 의 **값**이 달라질까요?

```text
T5 :  skip = dp[2][4] = 5      take = dp[2][0] + 5 = 5
      skip >= take  →  두고 가는 쪽을 골랐다
      skip >  take  →  ?                        ← 이 자리를 직접 채워 봅시다
```

<!--check:tie-->
값은 안 달라집니다. 두 후보가 같은 값이면 어느 쪽을 골라도 그 칸에 같은 수가 적혀요.

```text
skip >= take   →  skip 을 고른다  →  dp[3][4] = 5
skip >  take   →  take 를 고른다  →  dp[3][4] = 5
                                     └ 둘 다 5 다
```

달라지는 것은 「그 수가 어떤 선택을 뜻하는가」뿐입니다 — 무게4·가치5 하나를 담은 것인지,
무게1·가치1 과 무게3·가치4 를 담은 것인지가 갈려요. 최대 가치만 반환하는 이 함수에서는 차이가
없고, 표를 거슬러 확인해 고른 물건 목록을 복원하는 코드를 더할 때만 답이 달라집니다.
<!--/check-->

```text
아래 넷은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 수행으로 알아보는 알고리즘 의 T3·T6      3 → 비용 계산
  2 → 아이디어 상세                            4 → 불변식
```

- T3에서 `dp[2][2]` 가 `dp[1][2]` 를 그대로 복사했습니다. 이 칸이 뜻하는 선택은 무엇일까요.
- 무게 합이 같은 조합을 합칠 때 「본 물건 수」를 함께 기억하지 않으면 용량 10에서 14가
  나왔습니다. 용량 7에서는 왜 9로 같게 나올까요.
- 총식에 표 할당 `O((n+1)(W+1))` 이 들어 있는데, 표를 줄 두 개로 줄이면 이 항이 어떻게
  바뀔까요.
- 물건을 두 개까지 담을 수 있는 문제라면 불변식의 어느 부분을 고쳐야 할까요.
