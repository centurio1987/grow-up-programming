# 최소 동전 개수 — 같은 줄에서 읽으면 같은 액면가를 몇 개든 쓰게 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 동전을 하나씩 놓아
보는 재귀에서 출발해 액면가를 하나씩 늘려 가는 DP 테이블까지 가고, 그 DP 테이블을 단계마다 값으로 푼 뒤, 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

액면가 몇 가지와 목표 금액이 있습니다. 같은 액면가를 **몇 개든** 쓸 수 있고, 고른 동전의 합이 목표 금액과
정확히 같으면서 **동전 개수가 가장 적은** 조합을 찾아 그 개수를 답하는 것이 목표예요. 어떤 조합으로도 못
만들면 `-1` 입니다. 액면가 `[3, 4, 1]` 로 금액 6 을 만드는 조합을 액면가마다 몇 개 썼는지로 적어 보면 이렇습니다.

<!--proof:concept-combos-->

| 조합 | 3 의 개수 | 4 의 개수 | 1 의 개수 | 동전 개수 |
| --- | ---: | ---: | ---: | ---: |
| 3 + 3 | 2 | 0 | 0 | 2 |
| 4 + 1 + 1 | 0 | 1 | 2 | 3 |
| 3 + 1 + 1 + 1 | 1 | 0 | 3 | 4 |
| 1 + 1 + 1 + 1 + 1 + 1 | 0 | 0 | 6 | 6 |

조합은 4 가지이고 동전 개수가 가장 적은 것은 3 + 3 의 2 개입니다. 정본 unboundedKnapsack([3, 4, 1], 6) 이 낸 값도 2 입니다.

<!--/proof-->

조합을 하나씩 만들어 보면 답은 맞지만, 금액이 커질수록 조합이 급격히 늘어요. 그런데 묻는 것은 **개수
하나**입니다. 같은 금액에 이른 조합끼리는 개수가 적은 쪽만 기억하면 되니, 조합을 만들지 않고 **금액마다 가장
적은 개수만 칸에 적어 두는 표**를 씁니다. 줄은 지금까지 연 액면가의 종류 수이고, 열은 금액이에요. `i` 번째
줄의 `a` 번째 칸에는 「앞의 `i` 종류를 몇 개든 써서 금액 `a` 를 만드는 가장 적은 동전 개수」를 적고, 그렇게
못 만드는 칸에는 `∞` 를 적습니다. 작은 입력의 답을 칸에 적어 두고 큰 입력의 답을 그 칸들에서 만드는 이런
표를 **DP 테이블**이라고 부릅니다. DP 는 동적 계획법(dynamic programming)의 줄임말이에요. 액면가 `[3, 4, 1]`,
금액 6 의 DP 테이블 전체를 그리면 이렇습니다.

<!--fig:concept-table-->
![unboundedKnapsack([3, 4, 1], 6) 의 DP 테이블 — 줄은 연 액면가, 열은 금액](./figs/concept-table.svg)

맨 위 줄 `i=0` 은 액면가를 하나도 열지 않은 줄이라 금액 0 칸만 0 이고 나머지는 `∞` 예요. 한 줄 내려갈 때마다
액면가 하나를 새로 열고, 오른쪽 끝 곁말이 그 줄에서 쓸 수 있는 액면가입니다. 답은 오른쪽 아래 칸
`dp[3][6] = 2` 예요. 칸 하나를 정하는 규칙은 둘로 갈립니다. 그 줄에서 새로 연 액면가를 `c` 라고 할게요.

| 경우 | 그 칸에 적는 값 |
| --- | --- |
| 금액 `a` 가 `c` 보다 작다 | 바로 윗 칸의 값 |
| 금액 `a` 가 `c` 이상이다 | 윗 칸(이 액면가를 안 쓴다)과, 같은 줄에서 `c` 칸 왼쪽에 1 을 더한 값(한 개 더 쓴다) 중 작은 쪽 |

「같은 줄에서 `c` 칸 왼쪽」이 이 알고리즘의 핵심입니다. 그 칸은 **이 액면가를 이미 쓸 수 있었던 줄**의 값이라,
거기에 한 개를 더하면 같은 액면가를 두 개 · 세 개 쓰는 것이 저절로 들어가요. `dp[1][6]` 을 정하는 자리를
그리면 이렇습니다. 강조색 굵은 테가 새로 정하는 칸이고, 진한 테를 두른 두 칸이 그 칸이 읽는 칸이에요.

<!--fig:concept-rule-->
![dp[1][6] 을 정하는 자리 — 윗 칸 dp[0][6] 과 같은 줄 3 칸 왼쪽 dp[1][3] 에 1 을 더한 값 중 작은 쪽](./figs/concept-rule.svg)

`dp[1][3]` 은 이미 3 을 한 개 쓴 값입니다. 거기에 1 을 더한 `dp[1][6] = 2` 는 3 을 두 개 쓴 값이에요. 액면가
종류 수를 `n`, 금액을 `A` 라고 하면 칸은 `(n+1) × (A+1)` 개이고, 칸 하나에 비교 한두 번이면 됩니다. 비용은
결과만 적어 `O(nA)` 이고, 칸 수를 세면 이렇습니다.

<!--proof:concept-size-->

```text
액면가 종류 n  금액 A  칸 (n+1)(A+1)
3                   6             28
100            10,000      1,010,101
```

입력이 무엇이든 모든 칸을 한 번씩 채우니, 운이 좋아 빨라지는 일도 나빠서 느려지는 일도 없습니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **2 차원 배열의 첨자 읽기.** `dp[i][a]` 는 `i` 번째 줄의 `a` 번째 칸입니다. 앞 첨자가 줄, 뒤 첨자가 열이에요.
- **두 수 중 작은 쪽 고르기.** 칸 하나를 정하는 데 이것과 덧셈 하나만 씁니다.
- **「만들 수 없다」를 값으로 두는 것.** 이 글은 그것을 `Infinity`(∞)로 적고, `∞ + 1` 이 다시 `∞` 이고 어떤
  수와 비교해도 지는 성질을 그대로 씁니다.

재귀 · 메모이제이션 · 그래프 탐색은 몰라도 됩니다. DP 테이블을 왼쪽 위에서 오른쪽 아래로 채우는 반복문만
써요. 같은 모양의 DP 테이블을 쓰는 편이 둘 있고, 셋은 **칸에 적는 것과 읽는 칸 하나**만 다릅니다.

| 이미 아는 것 | 이 글에서 쓰이는 자리 |
| --- | --- |
| 2 차원 첨자 | DP 테이블의 칸 `dp[i][a]` |
| 작은 쪽 고르기 | 칸 하나 = min(윗 칸, 같은 줄 왼쪽 칸 + 1) |
| ∞ 의 성질 | 못 만드는 칸을 따로 가르지 않는다 |
| [0/1 배낭](../knapsack01/knapsack01-guide.md) | 같은 DP 테이블인데 한 개 더 쓰는 쪽을 **윗 줄**에서 읽는다 |
| [동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) | 같은 줄에서 읽는데 작은 쪽을 고르지 않고 **더한다** |

### 아이디어를 떠올리는 과정 — 동전을 하나씩 놓아 보는 재귀에서 액면가를 하나씩 늘리는 DP 테이블까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 액면가 목록과 금액을 받아서, 그
금액을 정확히 만드는 가장 적은 동전 개수를 돌려줍니다.

```ts
function unboundedKnapsack(coins: number[], amount: number): number;
```

- 입력: 액면가 배열 `coins`(각 액면가를 **몇 개든** 쓸 수 있습니다)와 목표 금액 `amount`. 액면가는 1 이상의 정수입니다.
- 출력: **가장 적은 동전 개수 하나**. 어느 조합이 그 개수를 냈는지는 돌려주지 않아요. 금액 0 은 동전이 필요 없어
  0 이고, 어떤 조합으로도 못 만들면 `-1` 입니다.
- 규모: 액면가 종류 수는 100 이하, 액면가와 금액은 `10^4` 이하입니다. 비용은 흔한 채점 환경의 예산인 1 초에
  대어 잽니다. 이 규모로 잡은 까닭은 둘이 자릿수로 갈리는 것을 보이기 위해서예요 — 이 크기에서 DP 테이블은
  1 초 안에 채워지고, 아무것도 기억하지 않는 방법은 끝나지 않습니다.

눈여겨볼 것이 둘 있어요. **같은 액면가를 몇 개든 쓸 수 있다**는 것과, **액면가가 모두 1 이상**이라는 것입니다.

```text
같은 액면가를 몇 개든
  한 종류에 대한 결정이 "쓴다 / 안 쓴다" 가 아니라 "몇 개 쓰는가" 다

액면가가 1 이상
  동전을 하나 더 쓰면 남은 금액이 반드시 줄어든다  → a - c 가 a 보다 왼쪽이다
```

두 성질이 각각 필요해지는 자리가 뒤에 옵니다. 이 글이 쓰는 기호는 여섯이에요. 여기서 정하고 끝까지 같은 뜻으로
씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `n` | 액면가 종류의 수 | `n ≤ 100` |
| `A` | 목표 금액. 코드에서는 `amount` | `A ≤ 10^4` |
| `i` | 지금까지 연 액면가 종류 수. DP 테이블의 줄 | `0 ≤ i ≤ n` |
| `a` | 만들려는 금액. DP 테이블의 열 | `0 ≤ a ≤ A` |
| `c` | `i` 번째 줄에서 새로 여는 액면가 | `coins[i - 1]` |
| `dp[i][a]` | 앞의 `i` 종류를 몇 개든 써서 금액 `a` 를 만드는 가장 적은 동전 개수 | DP 테이블의 칸 하나 |

가장 먼저 떠오르는 방법으로 시작합시다. 동전 하나를 고르고 남은 금액을 같은 방법으로 푸는 것이니, 액면가마다
한 번씩 갈라 재귀로 내려가면 됩니다.

```ts
function 완전탐색(coins: number[], amount: number): number {
  const solve = (rest: number): number => {
    if (rest === 0) return 0;
    if (rest < 0) return Number.POSITIVE_INFINITY;
    let best = Number.POSITIVE_INFINITY;
    for (const c of coins) {
      const sub = solve(rest - c);
      if (sub + 1 < best) best = sub + 1;
    }
    return best;
  };
  const r = solve(amount);
  return Number.isFinite(r) ? r : -1;
}
```

이 방법은 **동전을 놓는 차례마다 한 번씩 갈라집니다.** 그러니 호출 수가 곧 일의 양이에요. 액면가 `[3, 4, 1]`
에서 실제로 세어 보고, 같은 값을 내는 점화식 `C(a) = 1 + Σ_c C(a − c)` 로 큰 금액까지 이어 봅시다.

<!--proof:origin-naive-calls-->

```text
금액    실제로 세어 본 호출  점화식이 내는 호출 수  DP 테이블 칸 수
6                        46                     46               28
10                      313                    313               44
15                    3,466                  3,466               64
20                   38,446                 38,446               84
25                  426,388                426,388              104
30                4,728,718              4,728,718              124
10,000          세지 못했다         1.91 × 10^2090           40,004
```

금액 30 까지는 실제로 실행해서 세어 봤고 점화식과 같았습니다. 금액이 5 늘 때마다 호출 수가 열 배 넘게 늘고,
금액 10,000 에서는 2,091 자리 수예요. **아무것도 기억하지 않는 재귀는 여기서 막힙니다.** 오른쪽 끝의 칸 수와는
자릿수부터 달라요.

그러면 이 재귀가 무엇을 되풀이하는지 봅시다. 금액 6 에서 3 을 먼저 놓든 1 셋을 먼저 놓든, 남은 금액이 3 이
되는 순간 **앞으로 할 일이 완전히 같아집니다.**

```text
6 에서 3 을 놓았다          →  남은 금액 3
6 에서 1 · 1 · 1 을 놓았다  →  남은 금액 3
  └ 둘 다 「3 을 가장 적은 개수로 만들면 몇 개인가」를 다시 묻는다
```

그 답은 한 번만 구하면 됩니다. 같은 입력을 두 방식으로 세어 봅시다. 왼쪽은 재귀가 그 금액을 실제로 다시 푼
횟수이고, 오른쪽은 **금액마다 값을 한 번만 정했을 때**의 횟수예요. 금액 12 로 두면 차이가 보입니다.

<!--proof:origin-solved-again-->

```text
금액  재귀가 그 금액을 푼 횟수  금액마다 한 번만 정하면
12                           1                        1
11                           1                        1
10                           1                        1
9                            2                        1
8                            4                        1
7                            6                        1
6                            9                        1
5                           15                        1
4                           25                        1
3                           40                        1
2                           64                        1
1                          104                        1
0                          169                        1
합계                       441                       13
```

441 이 13 이 됐습니다. 오른쪽에서 눈여겨볼 것은 **횟수에 위 끝이 있다**는 점이에요. 금액을 아무리 키워도 서로
다른 금액은 0 부터 `A` 까지 `A + 1` 가지뿐입니다. 그러니 비용은 **서로 다른 금액이 몇 가지인가**로 세면 되고,
남은 질문은 「값을 어떤 순서로 정해야 읽는 칸이 이미 정해져 있는가」 하나예요.

가장 손이 덜 가는 후보부터 시험합니다. 금액마다 최소 개수를 적는 한 줄짜리 배열을 두고, 순서를 따로 생각하지
않은 채 **큰 금액부터** 채우는 것이에요.

```ts
const dp = new Array<number>(amount + 1).fill(Number.POSITIVE_INFINITY);
dp[0] = 0;
for (let a = amount; a >= 1; a--) // 금액을 큰 쪽부터
  for (const c of coins)
    if (a >= c && (dp[a - c] as number) + 1 < (dp[a] as number))
      dp[a] = (dp[a - c] as number) + 1;
```

같은 한 줄 배열을 금액이 작은 쪽부터 채운 것과 나란히 실행하면 값이 이렇게 나옵니다.

<!--proof:origin-fill-order-->

```text
입력            정본  금액 작은 쪽부터  금액 큰 쪽부터
[3, 4, 1] / 6      2                 2              -1
[3, 4, 1] / 11     3                 3              -1
[1, 2, 5] / 11     3                 3              -1
[2] / 6            3                 3              -1
[1] / 5            5                 5              -1
[3, 4] / 5        -1                -1              -1
```

큰 금액부터 채운 쪽은 여섯 줄에서 전부 `-1` 이 나왔습니다. `dp[a]` 를 정할 때 읽는 `dp[a - c]` 는 `a` 보다
왼쪽인데, 큰 쪽부터 채우면 그 칸이 **아직 아무 값도 안 들어간 `∞`** 예요. 마지막 줄 `[3, 4] / 5` 는 셋이 다
`-1` 인데, 그 입력은 애초에 만들 수 없는 금액이라 순서가 답을 가르지 않습니다.

```text
금액 큰 쪽부터    dp[6] 을 정할 때 dp[3] 이 아직 ∞      →  ∞ + 1 은 여전히 ∞
금액 작은 쪽부터  dp[6] 을 정할 때 dp[3] 이 이미 정해졌다  →  그 값에 1 을 더한다
                    └ a - c 가 a 보다 왼쪽이라는 것이 순서를 정한다
```

**금액을 작은 쪽부터 정합니다.** 액면가가 1 이상이라 `a - c` 가 언제나 `a` 보다 왼쪽이고, 왼쪽부터 채우면 읽는
칸이 반드시 이미 정해져 있어요. 여기에 하나를 더합니다. 액면가를 한꺼번에 보지 않고 **한 줄에 하나씩** 열어,
줄마다 금액을 작은 쪽부터 채우는 것이에요. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **액면가를 하나씩 늘리는 DP 테이블**입니다. 줄은 연 액면가 종류 수 `i`, 열은 금액
`a` 이고, 칸 `dp[i][a]` 에 가장 적은 동전 개수를 적어요. 작은 금액부터 채운 한 줄짜리 배열도 답은 맞는데 왜
줄을 따로 두는지, 칸 하나가 어느 칸을 읽는지, 왜 그렇게 하면 같은 액면가가 몇 개든 쓰이는지는 다음 절에서
실현하는 순서대로 확인합니다.

### 아이디어 상세 — 액면가를 하나씩 늘리는 DP 테이블

이 아이디어를 한 문장으로 줄이면 이렇습니다. **액면가를 한 줄에 하나씩 열며 DP 테이블의 칸 `dp[i][a]` 에 「앞의
`i` 종류를 몇 개든 써서 금액 `a` 를 만드는 가장 적은 동전 개수」를 적고, 오른쪽 아래 칸을 답으로 읽습니다.** 이
방법은 DP 테이블이라는 구조 위에서 동작하는데, 칸 하나가 무엇을 적고 어느 칸과 이어지는지가 처음 보는
사람에게는 낯설어요. 그래서 DP 테이블을 먼저 따로 설명하고, 그다음 이 방법을 실현하는 순서대로 세 단계를
설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 씁니다.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 크기와 첫 줄 정하기 | 줄 `n+1` 개 · 줄마다 칸 `A+1` 개를 만들고 `i=0` 줄을 정한다 | — |
| 2단계 한 줄을 왼쪽부터 채우기 | 액면가 하나를 연 줄을 칸마다 윗 칸과 같은 줄 왼쪽 칸에서 정한다 | 1단계의 첫 줄 · 앞 줄 |
| 3단계 오른쪽 아래 칸 읽기 | `dp[n][A]` 가 유한하면 그 값을, `∞` 면 `-1` 을 돌려준다 | 2단계가 채운 마지막 줄 |

#### 먼저 알아 둘 개념 — DP 테이블

이 글의 DP 테이블은 **액면가를 하나씩 열 때마다 줄을 하나 더하고, 줄마다 금액 0 부터 `A` 까지 칸을 둔 표**입니다.
칸 `dp[i][a]` 에는 「앞의 `i` 종류를 몇 개든 써서 금액 `a` 를 만드는 가장 적은 동전 개수」가 적혀요. 여기서
헷갈리기 쉬운 것이 둘 있습니다. 칸에 적히는 것은 조합 **자체가 아니라 그 조합의 동전 개수**이고, 만들 수 없는
칸에는 0 이 아니라 **`∞`** 가 적혀요.

| 무엇 | 담는 것 | 이 글에서 쓰는 곳 |
| --- | --- | --- |
| 조합 | 액면가마다 몇 개 쓰는가를 적은 목록 하나 | 칸 하나가 무엇을 고른 값인지 설명할 때 |
| DP 테이블의 칸 | 그 조건을 만족하는 조합 중 **가장 적은 동전 개수**, 없으면 `∞` | `dp[i][a]` 가 가리킬 때 |

##### 칸마다 적힌 최소 개수

전체 컨셉의 그림에서 마지막 줄 `i=3` 은 액면가 3 · 4 · 1 을 모두 쓸 수 있는 줄입니다. 그 줄의 칸마다 동전 개수가
가장 적은 조합을 늘어놓으면 이렇습니다.

<!--proof:build-cell-meaning-->

| 금액 a | dp[3][a] | 동전 개수가 가장 적은 조합 |
| ---: | ---: | --- |
| 0 | 0 | 빈 조합 |
| 1 | 1 | 1 |
| 2 | 2 | 1 + 1 |
| 3 | 1 | 3 |
| 4 | 1 | 4 |
| 5 | 2 | 4 + 1 |
| 6 | 2 | 3 + 3 |

칸에 적힌 수와 가장 적은 조합의 동전 개수가 7 칸 가운데 7 칸에서 같습니다.

<!--/proof-->

한 줄 안에서는 왼쪽에서 오른쪽으로 갈수록 금액이 1 씩 커지지만, 칸의 값은 커지기만 하지 않아요. 금액 3 과 4 는
동전 하나로 만들어지니 금액 2 보다 적습니다. 한 줄 아래로 내려갈수록 쓸 수 있는 액면가가 한 종류씩 늘어서, 같은
열의 값은 줄어들거나 그대로예요. 금액 0 칸은 어느 줄에서나 **빈 조합**의 0 입니다.

##### 칸 하나를 읽는 법

칸은 `dp[i][a]` 처럼 번호 둘로 부릅니다. 앞 번호 `i` 로 줄을 골라 **쓸 수 있는 액면가**를 정하고, 뒤 번호 `a` 로
**만들 금액**을 정해요. `dp[2][6]` 이라면 2 번째 줄이라 앞의 두 종류 3 · 4 만 쓰고, 금액 6 을 만듭니다. 그림에서
대시로 그린 칸은 이번에 보지 않는 칸이에요.

<!--fig:build-read-cell-->
![dp[2][6] — 액면가 3 · 4 만 몇 개든 써서 금액 6 을 만드는 최소 개수](./figs/build-read-cell.svg)

그 조건을 만족하는 개수 목록을 모두 적고, 같은 줄의 `∞` 칸 하나도 함께 읽으면 이렇습니다.

<!--proof:build-read-one-->

| 칸 | 3 의 개수 | 4 의 개수 | 조합 | 동전 개수 |
| --- | ---: | ---: | --- | ---: |
| dp[2][6] | 2 | 0 | 3 + 3 | 2 |
| dp[2][5] | — | — | 없음 | — |

액면가 3 · 4 로 금액 6 을 만드는 조합은 1 가지이고 dp[2][6] = 2 입니다. 금액 5 를 만드는 조합은 없고 dp[2][5] = ∞ 입니다.

<!--/proof-->

조심할 점이 하나 있습니다. `i` 는 **몇 종류까지 쓰는가**이지 **몇 번째 종류 하나만 쓰는가**가 아니에요.
`dp[2][6]` 은 4 만 쓴 개수가 아니라 3 과 4 를 모두 쓸 수 있을 때의 개수입니다. 그리고 `∞` 는 「아직 안 정했다」가
아니라 「**정했는데, 이 액면가들로는 못 만든다**」예요.

##### 윗 칸과 같은 줄 왼쪽 칸

칸 하나는 이웃한 두 칸과 이어져 있습니다. 바로 윗 칸과, 같은 줄에서 `c` 칸 왼쪽이에요. 금액이 `c` 보다 작으면
윗 칸만 읽고, 아니면 둘 다 읽어 작은 쪽을 적습니다. 세 칸을 나란히 그렸어요 — 윗 칸만 읽는 칸, 한 개 더 쓰는 쪽이
작은 칸, 안 쓰는 쪽이 작은 칸입니다.

<!--fig:build-neighbors-->
![칸 하나가 읽는 이웃 — 윗 칸과, 같은 줄에서 c 칸 왼쪽](./figs/build-neighbors.svg)

왜 그 두 칸인지는 `dp[3][6]` 의 조합을 **새 액면가 1 을 썼는가**로 갈라 보면 보입니다. 1 을 안 쓴 조합은
액면가 3 · 4 만 쓴 조합이라 윗 칸 `dp[2][6]` 이 고르는 것과 같고, 1 을 쓴 조합은 1 을 하나 빼면 금액 5 의
조합이 됩니다.

<!--proof:build-neighbor-split-->

| 무리 | dp[3][6] 의 조합 | 동전 개수 | 1 을 한 개 뺀 조합 | 뺀 조합이 있는 칸 |
| --- | --- | ---: | --- | --- |
| 1 을 안 쓴 것 | 3 + 3 | 2 | — | dp[2][6] |
| 1 을 쓴 것 | 4 + 1 + 1 | 3 | 4 + 1 | dp[3][5] |
| 1 을 쓴 것 | 3 + 1 + 1 + 1 | 4 | 3 + 1 + 1 | dp[3][5] |
| 1 을 쓴 것 | 1 + 1 + 1 + 1 + 1 + 1 | 6 | 1 + 1 + 1 + 1 + 1 | dp[3][5] |

1 을 안 쓴 무리의 가장 적은 개수 2 는 dp[2][6] = 2 와, 1 을 쓴 무리의 가장 적은 개수 3 은 dp[3][5] + 1 = 2 + 1 = 3 과 같습니다.

<!--/proof-->

1 을 한 개 뺀 조합 `4 + 1` 에는 1 이 아직 하나 남아 있습니다. 그래서 뺀 조합은 **1 을 계속 쓸 수 있는 줄**, 곧
같은 줄 `i=3` 에 있어야 해요. 한 개를 빼도 같은 액면가를 또 쓸 수 있다는 것이 「같은 줄에서 읽는다」의
뜻입니다. 두 무리의 최소 중 작은 2 가 `dp[3][6]` 이에요.

##### 윗 줄에서 읽는 0/1 배낭과의 차이

같은 DP 테이블을 [0/1 배낭](../knapsack01/knapsack01-guide.md) 에서 먼저 봤다면 한 개 더 쓰는 쪽을 **윗 줄**에서
읽고 싶어집니다. 그쪽은 물건이 하나뿐이라 윗 줄에서 읽어야 맞았어요. 여기서 같은 자리를 윗 줄 `dp[i-1][a-c]`
에서 읽은 판을 만들어 마지막 줄을 칸마다 대조하면 이렇습니다. 진한 테를 두른 칸이 두 값이 다른 칸이에요.

<!--fig:build-contrast-->
![같은 액면가 [3, 4, 1] — a - c 를 같은 줄에서 읽은 DP 테이블과 윗 줄에서 읽은 판의 마지막 줄](./figs/build-contrast.svg)

윗 줄에서 읽은 판은 금액 2 와 6 을 못 만든다고 적습니다. 1 을 두 번, 3 을 두 번 써야 하는 금액이에요. 윗 줄은
「이 액면가를 아직 열지 않은 줄」이라 거기에 한 개를 더하면 그 액면가가 **한 개까지만** 들어갑니다. 칸 수는 같고
**읽는 줄 하나가 몇 개든과 한 개까지를 가르는** 모양입니다.

##### 액면가마다 줄을 따로 두는 까닭

줄 `i` 를 채울 때는 앞의 `i-1` 종류로 만든 최소(윗 줄)에 `i` 번째 액면가를 몇 개 더할지만 정합니다. 그래서 한
줄이 액면가 하나에 대한 결정을 모아 담아요. 어느 칸의 값이 윗 칸을 옮긴 것인지, 이번 액면가를 더 써서 줄어든
것인지가 줄마다 남습니다.

```text
줄 i=1   액면가 3 만          3 을 몇 개 쓸지 정한다
줄 i=2   액면가 3 · 4         i=1 줄의 최소에 4 를 몇 개 더할지 정한다
줄 i=3   액면가 3 · 4 · 1     i=2 줄의 최소에 1 을 몇 개 더할지 정한다
         └ 한 액면가의 결정은 그 액면가의 줄에서 모두 일어난다
```

#### 1단계 — DP 테이블의 크기와 첫 줄 정하기

DP 테이블에는 줄이 `n+1` 개, 줄마다 칸이 `A+1` 개 있습니다. `+1` 은 둘 다 「아무것도 없는 상태」를 칸으로 두는
자리예요. 액면가를 하나도 열지 않은 줄 `i=0` 과, 아무것도 만들지 않는 금액 0 칸입니다. 전개 입력과 규모의 끝에서
크기를 세면 이렇습니다.

<!--proof:build-size-->

| 액면가 종류 n | 금액 A | 줄 수 n+1 | 줄마다 칸 수 A+1 | 모든 칸 |
| ---: | ---: | ---: | ---: | ---: |
| 3 | 6 | 4 | 7 | 28 |
| 100 | 10,000 | 101 | 10,001 | 1,010,101 |

전개 입력에서 정본이 만든 DP 테이블은 4 줄 × 7 칸, 모두 28 칸입니다.

<!--/proof-->

첫 줄 `i=0` 은 계산하지 않고 바로 정합니다. 액면가가 없으면 만들 수 있는 금액은 0 하나이고, 동전이 0 개
들어요. 그래서 `dp[0][0] = 0` 이고 `dp[0][a] = ∞`(`a ≥ 1`)입니다. 전체 컨셉의 그림 맨 위 줄 `[0 ∞ ∞ ∞ ∞ ∞ ∞]`
이 그 모양이에요. `i` 의 범위는 0 부터 `n`, `a` 의 범위는 0 부터 `A` 입니다.

#### 2단계 — 한 줄을 왼쪽부터 채우기

줄 `i` 는 윗 줄 `i-1` 이 다 채워진 뒤에 채웁니다. 칸 `dp[i][a]` 는 두 경우로 정해요. 가장 쉬운 경우는 새 액면가
`c` 가 금액보다 커서 한 개도 못 쓰는 칸입니다. 그때는 새 액면가를 쓴 조합이 없으니 윗 칸을 그대로 옮겨요. 앞
그림의 `dp[2][3] = dp[1][3] = 1` 이 그 경우입니다.

불안한 경우는 같은 줄의 왼쪽 칸을 읽는 칸이에요. 윗 줄은 이미 다 채웠지만, 같은 줄은 지금 채우는 중입니다.
읽으려는 왼쪽 칸이 아직 정해지지 않았다면 첫 줄을 깔 때 넣어 둔 `∞` 를 읽고 틀린 값을 적게 돼요. `i=1` 줄을
왼쪽부터 채우며 그 칸이 언제 정해졌는지 확인해 봅시다.

<!--proof:build-fill-row-->

| a | 정한 차례 | 갈래 | 윗 칸 | 같은 줄 3 칸 왼쪽 + 1 | 왼쪽 칸을 정한 차례 | dp[1][a] |
| ---: | ---: | --- | --- | --- | --- | ---: |
| 0 | 1 | ② | dp[0][0] = 0 | — | — | 0 |
| 1 | 2 | ② | dp[0][1] = ∞ | — | — | ∞ |
| 2 | 3 | ② | dp[0][2] = ∞ | — | — | ∞ |
| 3 | 4 | ④ | dp[0][3] = ∞ | dp[1][0] + 1 = 0 + 1 | 1 번째 | 1 |
| 4 | 5 | ③ | dp[0][4] = ∞ | dp[1][1] + 1 = ∞ + 1 | 2 번째 | ∞ |
| 5 | 6 | ③ | dp[0][5] = ∞ | dp[1][2] + 1 = ∞ + 1 | 3 번째 | ∞ |
| 6 | 7 | ④ | dp[0][6] = ∞ | dp[1][3] + 1 = 1 + 1 | 4 번째 | 2 |

같은 줄에서 읽은 칸 4 개 가운데 4 개가 지금 칸보다 먼저 정해져 있었습니다.

<!--/proof-->

표의 ② 는 윗 칸을 옮긴 칸, ③ 은 안 쓰는 쪽이 작거나 같은 칸, ④ 는 한 개 더 쓰는 쪽이 작은 칸이에요. 왜 늘 먼저
정해져 있는지는 반복의 차례로 말할 수 있습니다. `c` 는 1 이상이라 `a - c` 는 언제나 `a` 보다 작고, 한 줄
안에서 금액을 0 부터 오름차순으로 채우니 `a` 번째 칸을 정할 때는 `0 … a-1` 이 이미 끝나 있어요. 한 줄의 칸은
`a = 0` 부터 `A` 까지 한 번씩만 정해지고 건너뛰는 칸이 없습니다. `a = 4` 와 `a = 5` 는 왼쪽 칸이 정해진 `∞` 라
한 개 더 쓰는 후보도 `∞` 가 되고, 비교에서 안 쓰는 쪽과 같아 ③ 으로 정해졌어요.

```text
같은 줄 왼쪽을 읽는다   →  3 을 이미 쓴 최소에 3 을 한 개 더하는 것까지 들어간다
                           → 한 액면가를 여러 개 쓰는 것이 이 한 칸으로 적힌다
윗 줄 왼쪽을 읽는다     →  3 을 아직 안 쓴 최소에만 3 을 더한다
                           → 한 액면가를 한 개까지만 쓰게 된다
```

#### 3단계 — 오른쪽 아래 칸 읽기

마지막 줄 `i = n` 을 다 채우면 모든 액면가를 쓸 수 있는 줄이 완성됩니다. 그 줄의 칸 `dp[n][a]` 는 금액 `a` 의
최소이고, 돌려주는 것은 그중 오른쪽 끝 `dp[n][A]` 예요. 다만 칸의 `∞` 는 돌려줄 값이 아니라서 `-1` 로 바꿉니다.
두 번째 줄과 마지막 줄을 금액마다 따로 호출한 답과 나란히 놓았습니다.

<!--proof:build-answer-->

| 금액 a | dp[2][a] | unboundedKnapsack([3, 4], a) | dp[3][a] | unboundedKnapsack([3, 4, 1], a) |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 | 0 |
| 1 | ∞ | -1 | 1 | 1 |
| 2 | ∞ | -1 | 2 | 2 |
| 3 | 1 | 1 | 1 | 1 |
| 4 | 1 | 1 | 1 | 1 |
| 5 | ∞ | -1 | 2 | 2 |
| 6 | 2 | 2 | 2 | 2 |

14 쌍 가운데 14 쌍에서 칸의 값과 반환값이 대응합니다 — 칸이 유한하면 그 값이고, ∞ 면 -1 입니다.

<!--/proof-->

`i` 번째 줄은 「앞의 `i` 종류만 받은 호출」의 답을 금액마다 들고 있는 셈입니다. 금액 여러 개를 물어야 한다면 한
번 채우고 마지막 줄을 읽으면 돼요.

#### 이 방법이 기대는 전제

이 방법은 전제 셋 위에서 성립합니다. 하나라도 빠지면 고르는 것이 최소가 아니게 되거나 칸을 읽는 차례가 어긋나요.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 새 액면가를 「한 개도 안 쓴 조합」과 「한 개 이상 쓴 조합」으로 가르면 빠지는 조합이 없다 | 2단계에서 두 후보 중 작은 쪽만 적는다 | 어느 무리에도 안 드는 조합의 개수를 놓친다 |
| 액면가는 1 이상이다 | 2단계에서 같은 줄 왼쪽 `a - c` 가 이미 정해져 있다 | `a - c` 가 `a` 자신이나 오른쪽이 되어 아직 안 정한 칸을 읽는다 |
| `∞` 는 어떤 개수보다 크고 `∞ + 1 = ∞` 이다 | 못 만드는 칸을 따로 가르지 않고 비교한다 | 못 만드는 칸이 답을 덮는다 |

두 무리에 관한 전제는 개수 목록에서 새 액면가의 개수가 0 이거나 1 이상이라는 사실이라 늘 참입니다. 세 번째
전제가 깨지면 무엇이 되는지는 「수행으로 알아보는 알고리즘」의 「짚고 가기 — 못 만드는 칸에 -1 을 적으면 모든
답이 -1 이 된다」에서 실행 결과로 봅니다. [동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) 는
액면가가 서로 달라야 한다는 전제가 하나 더 있었는데, 최소를 고르는 이 방법에는 없어요. 같은 액면가를 두 번 넣어
실행하면 이렇습니다.

<!--proof:build-premise-->

| 액면가 | 금액 | 정본의 답 | 겹친 액면가를 하나로 줄인 답 |
| --- | ---: | ---: | ---: |
| [3, 4, 1] | 6 | 2 | 2 |
| [3, 3, 4, 1] | 6 | 2 | 2 |
| [3, 4, 1, 1, 1] | 6 | 2 | 2 |
| [7] | 7 | 1 | 1 |
| [7, 7, 7] | 7 | 1 | 1 |

5 입력 모두 겹친 액면가를 하나로 줄여도 답이 그대로입니다.

<!--/proof-->

같은 액면가의 줄이 둘이면 둘째 줄은 첫째 줄과 같은 값을 다시 고릅니다. 개수를 **더하는** 조합 세기에서는 같은 1
두 개가 다른 종류로 두 번 세어졌지만, 작은 쪽을 **고르는** 여기서는 같은 후보가 두 번 나와도 최소가 바뀌지 않아요.

#### 상태를 (i, a) 두 수로 잡는 까닭

칸을 무엇으로 가를지가 이 방법이 정하는 값입니다. 떠올리는 과정에서 작은 금액부터 채운 한 줄짜리 배열도 답이
맞았으니, 줄을 두는 것과 안 두는 것, 그리고 줄을 둘 때 한 개 더 쓰는 쪽을 어느 줄에서 읽는지를 함께 재 봅시다.

<!--proof:state-size-->

| 상태 | [3, 4, 1] / 6 의 답 | [1, 2, 5] / 11 의 답 | 전개 입력의 칸 수 | n = 100 · A = 10,000 의 칸 수 |
| --- | ---: | ---: | ---: | ---: |
| 금액 a 하나 (한 줄, 작은 금액부터) | 2 | 3 | 7 | 10,001 |
| (i, a) · a - c 를 같은 줄에서 | 2 | 3 | 28 | 1,010,101 |
| (i, a) · a - c 를 윗 줄에서 | -1 | -1 | 28 | 1,010,101 |

정본의 답은 2 이고, 윗 줄에서 읽은 판은 -1 을 냅니다. 한 줄짜리는 답이 같고 칸이 (i, a) 의 101 분의 1 입니다.

<!--/proof-->

**줄은 정답을 위해 필요한 것이 아닙니다.** 한 줄짜리가 같은 답을 101 분의 1 칸으로 냅니다. 이 글이 `(i, a)` 를
쓰는 까닭은 둘이에요. 하나는 액면가 하나의 결정이 한 줄에 모여 칸마다 어느 갈래로 정해졌는지 보인다는 것이고,
다른 하나는 [0/1 배낭](../knapsack01/knapsack01-guide.md) 과의 차이가 「읽는 줄 하나」로 확인된다는 것입니다. 셋째
줄이 그 차이예요 — 같은 칸 수에 읽는 줄만 바꿨는데 답이 틀립니다. 답만 필요할 때 한 줄로 접는 법과 그때 지킬
방향은 「수행으로 알아보는 알고리즘」의 짚고 가기에서 봅니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 네 걸음이 됩니다. 이렇게 하면 금액 10,000 에서 호출 `1.91 × 10^2090` 번까지
가던 재귀가 칸 1,010,101 개 채우기가 돼요.

1. DP 테이블을 `(n+1) × (A+1)` 로 만들고 `∞` 로 채운 뒤 `dp[0][0] = 0` 으로 둔다
2. `i` 를 1 부터 `n` 까지 올리며 새 액면가 `c = coins[i-1]` 을 연다
3. 그 줄에서 `a` 를 0 부터 `A` 까지 올리며, `a < c` 면 윗 칸을 옮기고 아니면 윗 칸과 같은 줄 `c` 칸 왼쪽 + 1 중 작은 쪽을 적는다
4. `dp[n][A]` 가 유한하면 그 값을, `∞` 면 `-1` 을 돌려준다

### 수행으로 알아보는 알고리즘 — DP 테이블 네 줄을 스물세 걸음으로 채운다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const coins = [3, 4, 1];
const amount = 6;
// 이 절이 끝나면 2 가 나와야 한다
```

액면가를 왜 하필 이 순서로 뒀을까요? 칸을 정하는 네 갈래를 **모두 실행하게** 하려는 것입니다. 1 을 마지막 줄에 두면
앞 두 줄에 `∞` 칸이 남아, `∞` 가 어떻게 이어지고 언제 없어지는지가 DP 테이블에 보여요. 액면가 3 의 줄은 `a = 6` 에서
3 을 두 번 쓰는 자리가 곧바로 나오고, 큰 액면가부터 집는 방법이 최소를 놓치는 입력이기도 합니다. 절차 전체를 한 장으로
적으면 이렇습니다.

```text
DP 테이블 dp 를 (n+1) × (A+1) 로 만들고 전부 ∞ 로 둔다
dp[0][0] ← 0                                             ① 금액 0 은 동전 0 개

i 를 1 부터 n 까지:
    c ← i 번째 액면가
    a 를 0 부터 A 까지 (오름차순):
        만약 a < c 이면:
            dp[i][a] ← dp[i-1][a]                        ② 이 액면가는 못 쓴다
        아니면:
            안 쓴다  ← dp[i-1][a]
            한 개 더 ← dp[i][a-c] + 1
            dp[i][a] ← 둘 중 작은 쪽                     ③ 안 쓴다 · ④ 한 개 더

dp[n][A] 가 유한하면 그 값을, ∞ 면 -1 을 돌려준다
```

#### 1. DP 테이블을 만들고 첫 칸을 정한다

1단계에서 정한 크기대로 DP 테이블을 만들고, 첫 줄에서 값이 0 인 칸 하나를 정합니다. 나머지 칸은 `∞` 로 깔아 둬요.

```ts
const n = coins.length;

// dp[i][a] = 앞의 i 종류만 써서 금액 a 를 만드는 최소 동전 개수.
//            만들 수 없는 칸은 Infinity 로 남는다.
const dp = Array.from({ length: n + 1 }, () =>
  new Array<number>(amount + 1).fill(Number.POSITIVE_INFINITY),
);
// ① 금액 0 은 동전 0 개로 만든다.
(dp[0] as number[])[0] = 0;
```

실행하면 이렇게 나옵니다. 액면가가 없는 입력도 함께 넣었어요.

<!--proof:walk-init-->

```text
       a=0  1  2  3  4  5  6
  i=0    0  ∞  ∞  ∞  ∞  ∞  ∞
  i=1    ∞  ∞  ∞  ∞  ∞  ∞  ∞     ← 아직 안 정한 줄
  i=2    ∞  ∞  ∞  ∞  ∞  ∞  ∞     ← 아직 안 정한 줄
  i=3    ∞  ∞  ∞  ∞  ∞  ∞  ∞     ← 아직 안 정한 줄

coins = [], amount = 5  →  1 줄 × 6 칸, 칸을 하나도 안 정하고 dp[0][5] = ∞ 이라 -1 반환
coins = [], amount = 0  →  1 줄 × 1 칸, 칸을 하나도 안 정하고 dp[0][0] = 0 이라 0 반환
```

`i=1` 부터의 `∞` 는 아직 정하지 않은 칸이라 값에 뜻이 없고, 다음 조각이 한 칸씩 덮어써요. 액면가가 없으면 `n = 0`
이라 줄이 하나뿐이고, 다음 조각의 반복에 한 번도 들어가지 않아 `dp[0][A]` 가 그대로 답이 됩니다. 빈 입력을 위한 분기를
따로 두지 않아도 되는 까닭이 이 `+1` 이에요.

#### 2. 액면가 하나로 한 줄을 채운다

바깥 루프가 액면가, 안쪽 루프가 금액입니다. 2단계의 「한 줄을 왼쪽부터 채우기」를 코드로 옮기면 두 줄에 이름을
붙이는 모양이 돼요.

```ts
for (let i = 1; i <= n; i++) {
  const c = coins[i - 1] as number;
  const prev = dp[i - 1] as number[]; // 윗 줄 — 이 액면가를 아직 안 연 층
  const cur = dp[i] as number[]; // 이번 줄 — 이 액면가까지 연 층

  for (let a = 0; a <= amount; a++) {
    // 여기서 칸 하나가 정해진다
  }
}
```

이름을 붙여 두는 것은 편의가 아닙니다. **두 후보 중 하나를 `cur` 에서 읽는다**는 것이 이 알고리즘의 규칙
전부인데, 첨자로 쓰면 그 규칙이 `i` 와 `i - 1` 이라는 숫자 뒤로 숨어요. 코드 주석의 「층」은 DP 테이블의 줄을
가리킵니다. `coins[i - 1]` 인 것은 DP 테이블의 줄 번호가 1 부터인데 배열은 0 부터이기 때문이에요. 두 반복문이 칸을
정하는 차례는 이렇습니다.

<!--proof:walk-order-->

```text
i=1 (c=3)   a = 0 → 1 → 2 → 3 → 4 → 5 → 6
i=2 (c=4)   a = 0 → 1 → 2 → 3 → 4 → 5 → 6
i=3 (c=1)   a = 0 → 1 → 2 → 3 → 4 → 5 → 6
  └ 한 줄을 왼쪽 끝부터 오른쪽 끝까지 다 정한 뒤 다음 줄로 간다
```

#### 3. 두 후보를 만들어 작은 쪽을 적는다

후보 둘에 이름을 붙여 두고 비교합니다. `Math.min` 한 줄로 줄이면 짧아지지만 **어느 후보가 작아서 그 값이
됐는지**가 코드에 남지 않아, DP 테이블을 따라갈 때 확인할 것이 사라져요.

```ts
if (a < c) {
  // ② 이 액면가 하나가 이미 a 보다 크다 — 윗 줄을 그대로 옮긴다.
  cur[a] = prev[a] as number;
} else {
  const skip = prev[a] as number; // 이 액면가를 한 개도 안 쓴다
  const take = (cur[a - c] as number) + 1; // 이번 줄에서 한 개 더 쓴다
  // ③ 안 쓰는 쪽이 작거나 같다 · ④ 한 개 더 쓰는 쪽이 작다
  cur[a] = skip <= take ? skip : take;
}
```

여기서 가장 중요한 줄은 `take` 를 만드는 줄입니다. **`cur` 에서 읽는다**는 것이 같은 액면가를 몇 개든 쓰게 하는
자리이고, 코드 전체에서 여기 하나뿐이에요. `i=1` 줄에서 같은 자리를 윗 줄 `prev` 에서 읽었다면 무엇을 읽었을지
나란히 놓으면 이렇습니다.

<!--proof:walk-branch-read-->

```text
i=1 줄, c = 3     같은 줄에서        윗 줄에서
a = 3          cur[0] + 1 = 1  prev[0] + 1 = 1
a = 4          cur[1] + 1 = ∞  prev[1] + 1 = ∞
a = 5          cur[2] + 1 = ∞  prev[2] + 1 = ∞
a = 6          cur[3] + 1 = 2  prev[3] + 1 = ∞
  └ 두 값이 처음 달라지는 자리는 a = 6 이다. cur[3] 에는 3 을 이미 한 개 쓴 값이 들어 있다
```

`∞ + 1` 이 다시 `∞` 라는 것이 이 코드에서 분기 하나를 없애 줍니다. 못 만드는 칸을 읽어도 그 후보가 그냥 `∞` 로
남아 비교에서 지고, 「읽은 칸이 만들 수 있는 칸인가」를 따로 확인할 필요가 없어요. 마지막에 한 번만 유한한지 보고
`-1` 을 정합니다.

#### 짚고 가기 — 큰 액면가부터 집으면 최소가 안 된다

거스름돈을 실제로 셀 때 우리는 큰 지폐부터 집습니다. 그 방법이 여기서도 맞을 것 같고, 심지어 **우리가 쓰는
화폐로는 실제로 맞아요.** 몇 가지 액면가 목록에 대해 0 원부터 200 원까지 전수로 확인해 봅시다.

<!--proof:greedy-systems-->

```text
액면가                 0…200 에서 최소와 갈리는 금액  가장 작은 자리
[1, 5, 10, 25]                                  0 개            없음
[1, 10, 50, 100, 500]                           0 개            없음
[3, 4, 1]                                      49 개               6
[1, 4, 5]                                      77 개               8
```

**위 두 줄은 한 금액도 안 갈립니다.** 그래서 이 자리가 위험해요 — 실제 화폐 액면가로 테스트를 짜면 통과하고, 틀린
줄 모르고 넘어갑니다. 아래 두 줄은 다릅니다. 전개 입력 `[3, 4, 1]` 에서 두 방법이 실제로 낸 개수를 나란히 놓아
봅시다.

<!--proof:greedy-walk-->

```text
금액  큰 액면가부터 집는다  최소
6                        3     2
7                        2     2
8                        2     2
9                        3     3
10                       4     3
11                       3     3
12                       3     3
```

금액 6 에서 3 과 2 로 갈립니다. 큰 쪽인 4 를 집으면 남은 2 를 1 두 개로 채워야 해서 3 개가 되는데, 4 를 아예 안
집고 3 을 두 개 쓰면 2 개예요. 지금 가장 큰 것을 집는 결정이 남은 금액에서 무엇을 할 수 있는지를 바꾸고, 그
결정을 되돌릴 자리가 없습니다. 큰 것부터 집는 방법이 맞는 액면가 목록을 **정규 동전계**라고 부르고, 우리가 쓰는
화폐는 대부분 거기 속합니다. 액면가를 임의로 받으면 그 보장이 없어서 DP 테이블이 모든 금액의 최소를 따로 적어
두는 거예요.

#### 4. DP 테이블 네 줄을 스물세 걸음으로 채운다

앞의 세 조각을 이어 `unboundedKnapsack([3, 4, 1], 6)` 을 실행하면 스물세 걸음이 됩니다. 첫 줄을 까는 한 걸음, 칸
스물하나를 한 걸음에 하나씩, 답을 읽는 한 걸음이에요. 걸음마다 무대의 점선 칸은 아직 안 정한 칸, 강조색 굵은 테가
이번에 정한 칸, 진한 테를 두른 칸이 그 칸이 읽은 칸입니다. 먼저 첫 줄과 액면가 3 의 줄이에요.

| T19 | dp[3][3] | 1 | `3 < 1` **거짓** → ③ | 1 · 2 + 1 | 1 |
| T20 | dp[3][4] | 1 | `4 < 1` **거짓** → ③ | 1 · 1 + 1 | 1 |
| T21 | dp[3][5] | 1 | `5 < 1` **거짓** → ④ | ∞ · 1 + 1 | 2 |
| T22 | dp[3][6] | 1 | `6 < 1` **거짓** → ③ | 2 · 2 + 1 | 2 |
| T23 | dp[3][6] | — | 읽기 | 2 | 2 |

① 이 1 칸, ② 가 8 칸, ③ 이 7 칸, ④ 가 6 칸이고, 반환값은 2 입니다.

<!--/proof-->

**네 갈래가 모두 나왔습니다.** 여기서 확인하고 갈 자리는 T8 과 T22 예요. T8 에서 `dp[1][6]` 이 2 가 됐고 T15 가 그
2 를 윗 칸으로 받았으며, T22 에서도 답은 2 입니다. 세 칸의 2 는 모두 `3 + 3` 이에요. T22 는 1 을 하나 더 쓰는
후보(`dp[3][5] + 1 = 3`)보다 윗 칸의 2 가 작다는 것을 확인한 자리입니다. T6 · T7 · T14 는 두 후보가 모두 `∞` 라
③ 으로 정해졌어요. 금액 1 · 2 · 5 의 `∞` 는 T17 · T18 · T21 에서 액면가 1 이 열리면서 처음 유한한 값으로 바뀝니다.

#### 짚고 가기 — 못 만드는 칸에 -1 을 적으면 모든 답이 -1 이 된다

이 함수는 못 만들면 `-1` 을 돌려줍니다. 그러면 DP 테이블의 칸에도 `-1` 을 적어 두고 마지막에 그대로 읽으면 되겠다고
생각하기 쉬워요. `Infinity` 같은 특수한 값을 안 써도 되니 더 단순해 보입니다. 그대로 두고 실행해 봅시다.

```ts
// 못 만드는 칸을 Infinity 대신 -1 로 깔았다
const dp = Array.from({ length: n + 1 }, () =>
  new Array<number>(amount + 1).fill(-1),
);
(dp[0] as number[])[0] = 0;
// … 나머지는 그대로. skip <= take ? skip : take
```

몇 가지 입력에 적용해 보면 답이 어떻게 갈리는지 보입니다.

<!--proof:minus-one-->

```text
입력            정본  칸에 -1 을 적은 판
[3, 4, 1] / 6      2                  -1
[3, 4, 1] / 3      1                  -1
[1, 2, 5] / 11     3                  -1
[1] / 5            5                  -1
[2] / 3           -1                  -1
[5, 10] / 3       -1                  -1
```

**아래 둘에서는 답이 맞았습니다.** 원래 만들 수 없는 금액이라 `-1` 이 정답이었던 것이고, 그런 입력만 몇 개 넣어
보면 통과한 줄 알게 돼요. 위 넷은 만들 수 있는 금액인데도 `-1` 이 나왔습니다.

```text
-1 이 자리표시자가 못 되는 이유

  비교     min(-1, 어떤 개수) 는 언제나 -1     → 실제 개수가 있어도 -1 이 골라진다
  덧셈     -1 + 1 = 0                          → 못 만드는 칸이 "동전 0 개" 로 번진다

∞ 는 둘 다 안 일어난다
  비교     min(∞, 어떤 개수) = 그 개수
  덧셈     ∞ + 1 = ∞
```

자리표시자는 **그 자리에 올 수 있는 어떤 값보다도 커야** 합니다. 최소를 고르는 비교에서 지고, 거기에 1 을 더해도
여전히 커야 해요. `-1` 은 둘 다 반대라서 DP 테이블 전체를 덮어 버립니다.

#### 짚고 가기 — 한 줄로 줄이면 금액을 작은 쪽부터 채워야 한다

답만 필요하면 줄 하나만 두면 됩니다. 두 줄 `prev` · `cur` 대신 배열 하나 `best` 를 두고, 액면가마다 그 배열을 다시
쓰는 것이에요. [0/1 배낭](../knapsack01/knapsack01-guide.md) 을 봤다면 한 줄로 줄일 때 **큰 쪽부터** 채운다고
기억하고 있을 텐데, 여기서는 **방향이 반대**입니다.

```ts
const best = new Array<number>(amount + 1).fill(Number.POSITIVE_INFINITY);
best[0] = 0;
for (const c of coins)
  for (let a = c; a <= amount; a++) // 작은 금액부터
    best[a] = Math.min(best[a] as number, (best[a - c] as number) + 1);
```

금액을 바꿔 가며 두 방향과 DP 테이블, 윗 줄에서 읽은 판을 함께 실행했습니다.

<!--proof:one-row-dir-->

```text
금액  작은 금액부터  큰 금액부터  DP 테이블  윗 줄에서 읽은 판
2                 2           -1          2                 -1
4                 1            1          1                  1
5                 2            2          2                  2
6                 2           -1          2                 -1
7                 2            2          2                  2
8                 2            3          2                  3
```

작은 금액부터 채운 쪽은 여섯 금액에서 DP 테이블과 같고, 큰 금액부터 채운 쪽은 윗 줄에서 읽은 판과 같습니다. 금액
4 · 5 · 7 은 한 액면가를 두 번 쓸 필요가 없어서 네 판이 모두 같아요. **그래서 이 자리가 함정입니다.** 그런 금액만
시험하면 방향을 뒤집어도 통과해요. 첫 액면가 3 을 처리하는 동안 줄이 어떻게 바뀌는지 두 방향으로 그렸습니다. 작은
금액부터 채우면 `best[6]` 이 방금 쓴 `best[3]` 을 읽어요.

<!--fig:pause-one-row-up-->
![한 줄을 작은 금액부터 채울 때 — best[6] 이 방금 쓴 best[3] 을 읽는다](./figs/pause-one-row-up.svg)

`best[3] = 1` 은 3 을 이미 한 개 쓴 값이라, 거기에 1 을 더한 `best[6] = 2` 는 3 을 두 번 쓴 값입니다. 두 줄을 쓸 때
`cur` 가 하던 일을 작은 금액부터라는 방향이 대신해요. 큰 금액부터 채우면 `best[6]` 을 정할 때 `best[3]` 이 아직 이
액면가를 보지 않은 값입니다.

<!--fig:pause-one-row-down-->
![한 줄을 큰 금액부터 채울 때 — best[6] 이 아직 처리 전인 best[3] 을 읽는다](./figs/pause-one-row-down.svg)

그때 `best[3]` 은 `∞` 라 `best[6]` 도 `∞` 로 남고, 3 이 한 번만 들어가는 0/1 배낭이 됩니다. 한 줄로 접으면 **방향
하나가 「몇 개든」과 「한 개까지」를 가르는 자리**가 되고, 두 알고리즘이 한 줄 코드에서 다른 것은 안쪽 루프의
방향뿐이에요.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 마지막 두 줄뿐이에요 — DP 테이블의 오른쪽 아래
칸이 유한한지 보고 `∞` 면 `-1` 로 바꿉니다.

```ts
export function unboundedKnapsack(coins: number[], amount: number): number {
  const n = coins.length;

  // dp[i][a] = 앞의 i 종류만 써서 금액 a 를 만드는 최소 동전 개수.
  //            만들 수 없는 칸은 Infinity 로 남는다.
  const dp = Array.from({ length: n + 1 }, () =>
    new Array<number>(amount + 1).fill(Number.POSITIVE_INFINITY),
  );
  // ① 금액 0 은 동전 0 개로 만든다.
  (dp[0] as number[])[0] = 0;

  for (let i = 1; i <= n; i++) {
    const c = coins[i - 1] as number;
    const prev = dp[i - 1] as number[]; // 윗 줄 — 이 액면가를 아직 안 연 층
    const cur = dp[i] as number[]; // 이번 줄 — 이 액면가까지 연 층

    for (let a = 0; a <= amount; a++) {
      if (a < c) {
        // ② 이 액면가 하나가 이미 a 보다 크다 — 윗 줄을 그대로 옮긴다.
        cur[a] = prev[a] as number;
      } else {
        const skip = prev[a] as number; // 이 액면가를 한 개도 안 쓴다
        const take = (cur[a - c] as number) + 1; // 이번 줄에서 한 개 더 쓴다
        // ③ 안 쓰는 쪽이 작거나 같다 · ④ 한 개 더 쓰는 쪽이 작다
        cur[a] = skip <= take ? skip : take;
      }
    }
  }

  const best = (dp[n] as number[])[amount] as number;
  return Number.isFinite(best) ? best : -1;
}
```

실행하면 이렇게 나옵니다.

<!--proof:final-run-->

```text
unboundedKnapsack([3, 4, 1], 6)    →  2
unboundedKnapsack([1, 2, 5], 11)   →  3
unboundedKnapsack([1, 3, 4], 6)    →  2
unboundedKnapsack([2], 3)          →  -1
unboundedKnapsack([1], 0)          →  0
unboundedKnapsack([], 0)           →  0
unboundedKnapsack([], 5)           →  -1
unboundedKnapsack([7, 7, 7], 7)    →  1
unboundedKnapsack([5, 10], 3)      →  -1
unboundedKnapsack([10000], 10000)  →  1
```

### 알아 두면 좋은 개념 — 단위 가중 최단 경로로의 환원

파트 1 에서 채운 DP 테이블의 마지막 줄을 다시 봅시다. `dp[3][a]` 의 각 칸은 「그 금액을 만드는 데 동전을 최소 몇
개 놓는가」였어요. 동전 하나를 놓는 일을 **한 걸음**으로 읽으면 이 줄이 그대로 걸음 수가 됩니다.

```text
금액 a 를 꼭짓점, 액면가 c 마다 a 에서 a + c 로 가는 화살표를 둔다

  화살표 하나  = 동전 한 개      →  화살표의 가중치가 전부 1 이다
  dp[3][a]     = 0 에서 a 까지 가는 최소 화살표 수
  ∞            = 0 에서 갈 수 없는 꼭짓점
```

전개 입력 `[3, 4, 1]` 로 0 에서 출발해 한 걸음씩 넓혀 가며 처음 도달하는 금액을 모으면 마지막 줄과 같습니다.

<!--proof:related-steps-->

| 걸음 수 | 그 걸음 수로 처음 도달하는 금액 (0 … 6) | 마지막 줄의 값 |
| ---: | --- | --- |
| 0 | 0 | dp[3][0] = 0 |
| 1 | 1 · 3 · 4 | dp[3][1] = 1 · dp[3][3] = 1 · dp[3][4] = 1 |
| 2 | 2 · 5 · 6 | dp[3][2] = 2 · dp[3][5] = 2 · dp[3][6] = 2 |

금액 7 개 가운데 7 개에서 0 부터 센 최소 걸음 수와 dp[3][a] 가 같습니다.

<!--/proof-->

가중치가 전부 같은 그래프에서 최소 걸음 수를 구하는 것을 **단위 가중 최단 경로**라고 하고, 과제를 그 모양으로 바꿔
읽는 것을 **환원**이라고 합니다. 이름을 알아 두면 다른 자리에서 같은 것을 알아보게 돼요 —
[너비 우선 탐색 최단 경로](../../graph/bfsShortestPath/bfsShortestPath-guide.md) 가 같은 그래프를 층으로 넓혀 가며
푸는 절차이고, [다익스트라](../../shortest-path/dijkstra/dijkstra-guide.md) 는 그 가중치가 서로 다를 때의 절차입니다.
두 절차가 정하는 값이 같은 함수라는 것이 환원이 말해 주는 것이고, 너비 우선 탐색은 같은 값을 **다른 순서로** 정할
뿐이에요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 전이식과 도달 가능성이 어떻게 유도되는지, 무엇이 매
순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- 같은 항목을 **몇 개든** 쓸 수 있습니다. 한 개까지면 읽는 자리가 같은 줄이 아니라 윗 줄이에요.
- 항목의 값이 **1 이상의 정수**입니다. 0 이나 음수가 섞이면 `a - c` 가 `a` 보다 왼쪽이라는 보장이 없어 채우는
  순서를 정할 수 없습니다.
- 목표가 **정수이고 작습니다.** DP 테이블의 열이 목표 금액이라, 실수이거나 `10^15` 이면 DP 테이블을 못 만들어요.
- 답이 **가장 적은 개수 하나**입니다. 어느 조합이 그 개수를 냈는지까지 물으면 칸마다 고른 갈래를 따로 적어 두어야
  해요.

```text
네 조건이 DP 테이블의 모양을 그대로 정한다
  몇 개든        → 한 개 더 쓰는 후보를 같은 줄에서 읽는다
  1 이상 정수    → 금액을 작은 쪽부터 채운다
  정수 목표      → 열이 a = 0 … A
  개수 하나      → DP 테이블을 다 채우고 오른쪽 아래 칸만 읽는다
```

`n × A` 가 대략 `10^7` 아래면 그대로 동작해요. 이 글의 규모(`100 × 10^4 = 10^6`)는 그 안에 넉넉히 들고, 칸 하나에
비교 한 번과 덧셈 한 번뿐이라 1 초 안에 끝납니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "각 동전은 무한히 사용 가능하다"  "몇 개든"  "충분히 보유하고 있다"
  "최소 개수"  "가장 적은 수의"  "최소 몇 번"
  "정확히 만들 수 없으면 -1"  "불가능하면"

제약에 이런 모양이 보이면
  목표 금액이 명시돼 있고 그 값이 10^4 안팎   ← DP 테이블을 만들 수 있다는 신호
  액면가 종류가 100 안팎                     ← 조합 열거는 불가능, n×A 는 가능
```

반대로 **「각 항목을 한 번만」** 이 보이면 윗 줄에서 읽는 [0/1 배낭](../knapsack01/knapsack01-guide.md) 모양이고,
**「몇 가지 방법이 있는가」** 가 보이면 작은 쪽을 고르는 대신 더하는
[동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) 모양입니다. **「만들 수 있는가만」** 이 보이면
칸에 참/거짓을 적는 [부분집합 합 판정](../subsetSum/subsetSum-guide.md) 이에요.

| 묻는 것 | 같은 값을 쓰는 횟수 | 칸에 적는 것 | `a - c` 를 읽는 줄 |
| --- | --- | --- | --- |
| 최소 동전 개수 (이 글) | 제한 없음 | 최소 개수 | 같은 줄 `dp[i][a-c]` |
| 조합의 수 (동전 조합) | 제한 없음 | 가짓수 | 같은 줄 `dp[i][a-c]` |
| 최대 가치 (0/1 배낭) | 최대 한 번 | 최대 가치 | 윗 줄 `dp[i-1][a-c]` |
| 만들 수 있는가 (부분집합 합) | 최대 한 번 | 참/거짓 | 윗 줄 `dp[i-1][a-c]` |

#### 실제로 쓰이는 곳

**OpenMS** 는 질량분석 데이터를 다루는 오픈소스 프레임워크입니다. 측정된 정수 질량 하나를 아미노산 잔기 질량의 합으로
분해하는 `IntegerMassDecomposer` 가 이 과제와 같은 모양이에요 — 액면가가 잔기 질량이고 금액이 측정 질량입니다. 그
클래스의 주석이 이렇게 적어요.

```text
"The main idea is instead of using the classical dynamic programming
 algorithm, store the residues of the smallest decomposable numbers
 for every modulo of the smallest alphabet mass."

  — OpenMS src/openms/include/OpenMS/CHEMISTRY/MASSDECOMPOSITION/IMS/
    IntegerMassDecomposer.h (조회 2026-09-02)
```

*"the classical dynamic programming algorithm"* 이 이 글의 DP 테이블입니다. **그런데 그것을 안 씁니다.** 같은 저장소의
`Weights` 가 실수 질량을 정수로 바꾸는 규칙을 *"round(mass / precision) per entry"* 로 적어 두는데, 그 변환을 거치면
열 수가 곧 「질량 ÷ 정밀도」가 되기 때문이에요. 정밀도를 0.0001 Da 로 두고 계산해 봅시다.

<!--proof:mass-columns-->

```text
무엇                                                          값
이 글의 DP 테이블 — 열 수 (금액 0 … 10,000)               10,001
이 글의 DP 테이블 — 칸 수 (액면가 100 종)              1,010,101
질량 1,000 Da 를 0.0001 Da 로 끊은 열 수              10,000,001
질량 5,000 Da 를 0.0001 Da 로 끊은 열 수              50,000,001
알파벳 20 종일 때 5,000 Da 짜리 DP 테이블의 칸 수  1,050,000,021
```

열이 5천만이라 칸이 10억을 넘고, 게다가 그 크기가 **묻는 질량마다 다시 커집니다.** 인용한 주석의 잉여류 표는 크기가
「가장 작은 알파벳 질량」에만 달려 있어 묻는 질량과 무관해요. 「최적인 문제의 모양」에서 적은 세 번째 조건(목표가
작다)이 깨진 자리가 정확히 여기입니다.

#### 경쟁 설계와의 대조

같은 답을 **DP 테이블 없이** 내는 설계가 있어요 — **분기 한정 탐색**입니다. 액면가를 큰 것부터 정렬해 두고 「이
액면가를 몇 개 쓸 것인가」를 깊이 우선으로 정하되, 지금까지 찾은 최소 개수보다 나아질 수 없는 가지를 잘라 냅니다.

```text
DP 테이블 (이 가이드)  비용이 n × A 에 달려 있다     금액이 크면 DP 테이블을 못 만든다
분기 한정 탐색         비용이 가지치기에 달려 있다   자를 기준이 될 첫 답을 못 찾으면
                       └ 추가 칸이 금액과 무관하다   아무것도 못 자른다
```

남은 금액을 `rest`, 지금 보는 액면가를 `c` 라 하면 앞으로 필요한 동전이 적어도 `ceil(rest / c)` 개입니다. 그래서
`count + ceil(rest / c)` 가 이미 찾은 최소 개수 이상이면 그 아래를 안 봐요. **그 「이미 찾은 최소 개수」가 아직
없으면 이 조건이 한 번도 참이 되지 않습니다.**

액면가를 `[4, 6]` 으로 고정하고 **금액만 1 바꿔** 두 설계를 걸었습니다. 전개 입력 `[3, 4, 1] / 6` 은 칸이 스무 개
남짓이라 두 설계가 갈리지 않아서 금액을 올렸어요. 두 액면가가 다 짝수라 만들 수 있는 금액이 짝수뿐이고, 그래서 금액
하나로 「답이 있는 경우」와 「없는 경우」가 갈립니다. 입력은 난수 없이 이 값으로 고정했으니 시드가 없어요. 기본 연산은
DP 테이블 쪽에서 값을 정한 칸 하나당 1, 분기 한정 쪽에서 재귀 호출 하나당 1 · 개수를 하나 정해 보는 바퀴마다
1 입니다. 추가 칸은 입력 밖에 동시에 들고 있는 칸으로, DP 테이블 쪽은 표 전체, 분기 한정 쪽은 정렬한 액면가 사본과 가장
깊었던 재귀 프레임 수예요.

| 입력 | 액면가 | 금액 | 답 |
| --- | --- | --- | --- |
| A | `[4, 6]` | 9,996 | 1,666 |
| B | `[4, 6]` | 9,997 | -1 |

| 설계 | A 기본 연산 | A 추가 칸 | B 기본 연산 | B 추가 칸 |
| --- | --- | --- | --- | --- |
| **DP 테이블 (이 가이드)** | 29,991 | 29,991 | **29,994** | 29,994 |
| 분기 한정 탐색 | **3,335** | **4** | 4,171,669 | **5** |

<!--proof:alt-ratio-->

**금액 하나로 순서가 뒤집힙니다.** A 에서는 분기 한정이 기본 연산으로 9.0 배 적어요 — 6 을 1,666 개 쓰는 답을 곧바로
찾고, 그 뒤로는 가지치기가 거의 모든 가지를 잘라 냅니다. B 에서는 반대로 DP 테이블이 139 배 적습니다 — 답이 없어
`best` 가 끝까지 무한이고, 그러면 자를 기준이 없어 개수 조합을 전부 봅니다.

<!--/proof-->

같은 경계를 다른 규모에서 한 번 더 재 봤습니다. 액면가는 그대로 두고 금액만 바꿉니다.

| 금액 | DP 테이블 (이 가이드) | 분기 한정 탐색 | 더 적은 쪽 |
| --- | --- | --- | --- |
| 1,000 | 3,003 | 339 | **분기 한정 탐색** |
| 999 | 3,000 | 42,335 | **DP 테이블** |

<!--proof:alt-edge-ratio-->

**경계는 「답이 있는가」입니다.** 더 정확히는 가지치기가 기댈 첫 답을 언제 찾는가이고, 답이 아예 없으면 그 시점이
오지 않아요. 금액이 1 다를 뿐인데 한쪽은 8.9 배 앞서고 다른 쪽은 14.1 배 뒤집힙니다.

<!--/proof-->

**내주는 것이 분명합니다.** DP 테이블은 금액에 비례하는 칸을 언제나 잡는 것을 내주고 — 위 표에서 29,991 대 4 예요
— 그 대가로 **입력과 무관한 최악 보장**을 얻습니다. 분기 한정은 추가 칸을 액면가 종류 수 규모로
끝내는 대신 최악 보장을 내줘요. 금액이 `10^9` 이면 DP 테이블을 아예 못 만들어서 분기 한정 쪽만 남고, 답이 없는
입력이 섞이면 그쪽이 끝나지 않습니다. 어느 쪽이 우월한지가 아니라 **금액의 크기와 답의 존재 중 무엇이 보장되는가**가
선택을 정합니다.

### 수식 정의와 유도

개수 벡터의 집합으로 답을 정의하고, 그 정의를 작은 값에 넣어 검산하고, 두 가지를 유도한 다음 과제 규모를 넣습니다.
유도 하나는 전이식이고, 다른 하나는 **언제 `-1` 이 나오는가**예요.

```text
정의   금액을 만드는 개수 벡터의 집합 K(a) 와 그 최솟값 M(a)
  ↓
검산   그 정의를 금액 6 에 넣어 계산한다
  ↓
유도   최소 해에서 동전 하나를 떼어 전이식을 얻고,
       액면가가 둘이고 서로소일 때 못 만드는 가장 큰 금액을 닫는다
  ↓
계수   그 닫힌 형태에 과제 규모를 넣어 수치를 낸다
```

**먼저 집합입니다.** 액면가 $c_1, \dots, c_n$ 을 각각 몇 개 쓸지 적은 벡터 $k = (k_1, \dots, k_n)$ 중 합이 정확히
$a$ 가 되는 것을 모은 집합을 $K(a)$ 로 적습니다.

$$K(a) = \Bigl\{\, k \in \mathbb{Z}_{\ge 0}^{\,n} \;\Bigm|\; \textstyle\sum_{j=1}^{n} k_j c_j = a \,\Bigr\}, \qquad M(a) = \min_{k \in K(a)} \textstyle\sum_{j=1}^{n} k_j$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $a$ | 만들려는 금액 | $0 \le a \le A$ |
| $c_j$ | $j$ 번째 액면가 | $1 \le c_j \le 10^4$ |
| $k_j$ | 그 액면가를 몇 개 쓰는가 | $k_j \ge 0$, 위 끝 없음 |
| $M(a)$ | 금액 $a$ 를 만드는 가장 적은 동전 개수 | $K(a)$ 가 비면 $+\infty$ |

```text
경계  K(0) = {0 벡터}          아무것도 안 쓰면 합이 0 이다
      M(0) = 0
DP    dp[n][a] = M(a)          파트 1 의 DP 테이블 마지막 줄이 이 함수를 칸으로 적은 것이다
답    M(A) 가 유한하면 그 값, 아니면 -1
```

**정의를 값에 넣어 검산해 봅시다.** 액면가가 $c_1 = 3$, $c_2 = 4$, $c_3 = 1$ 이고 $a = 6$ 이면 $K(6)$ 의 원소를 다
적을 수 있습니다.

<!--proof:math-check-->

```text
3k₁ + 4k₂ + k₃ = 6  을 만족하는 (k₁, k₂, k₃)

  (0, 0, 6)   동전 6 개
  (0, 1, 2)   동전 3 개
  (1, 0, 3)   동전 4 개
  (2, 0, 0)   동전 2 개   ← 최소
                            M(6) = 2
```

파트 1 의 DP 테이블에서 `dp[3][6]` 이 2 였고, 정의에서 직접 고른 최솟값과 같습니다.

**이제 전이식을 유도합니다.** $M(a) \ge 1$ 인 최소 해 $k$ 를 하나 잡고, 실제로 쓴 동전 중 아무것이나 하나를 떼어
냅니다. 그 액면가가 $c_j$ 라고 하면 남은 벡터는 $a - c_j$ 를 만들고 개수가 $M(a) - 1$ 이에요.

```text
최소 해에서 c_j 짜리 한 개를 뗀다
  남은 것은 a - c_j 를 만드는 벡터이고 개수가 M(a) - 1 이다
  그것이 M(a - c_j) 보다 작을 수는 없다        →  M(a) - 1 ≥ M(a - c_j)

거꾸로 c_j ≤ a 인 아무 j 에 대해 a - c_j 의 최소 해에 c_j 를 한 개 더한다
  a 를 만드는 벡터이고 개수가 M(a - c_j) + 1 이다
  그것이 M(a) 보다 작을 수는 없다              →  M(a) ≤ M(a - c_j) + 1
```

위쪽 부등식은 최소 해가 실제로 쓴 액면가 $c_j$ 하나에서, 아래쪽 부등식은 $c_j \le a$ 인 모든 $j$ 에서 성립합니다. 아래쪽을
모든 $j$ 로 모으면 $M(a) \le 1 + \min_j M(a - c_j)$ 이고, 위쪽의 그 $j$ 하나가 $M(a) \ge 1 + M(a - c_j) \ge 1 + \min_j
M(a - c_j)$ 를 줍니다. 두 방향이 만나 $a \ge 1$ 에서 등식이 나와요. **떼어 낸 동전과 같은 액면가를 남은 벡터가 또
쓰고 있어도 됩니다** — 개수에 위 끝이 없다는 정의가 그 자리를 열어 두고, 그것이 코드에서 `cur` 를 읽는 줄이에요.

$$M(a) = 1 + \min_{\;j \,:\, c_j \le a} M(a - c_j), \qquad M(0) = 0$$

<!--proof:math-code-->

```ts
// 식을 그대로 옮긴 조각. 액면가 [3, 4, 1] 로 금액 6 을 계산한다.
const M = (a: number): number =>
  a === 0
    ? 0
    : Math.min(...coins.filter((c) => c <= a).map((c) => M(a - c) + 1));

M(6); // min(M(3)+1, M(2)+1, M(5)+1) = min(1+1, 2+1, 2+1) = 2
```

**여기서 본문에 없던 것이 나옵니다.** 위 식은 $M(a)$ 가 유한한지를 말해 주지 않아요. 액면가가 둘뿐이고 그 둘이
서로소일 때는 **못 만드는 가장 큰 금액이 닫힌 형태로 나옵니다.** 두 액면가를 $p$ 와 $q$ 라 하면 그 값은 아래와
같아요. **두 걸음으로 유도하는데, 먼저 그 값 자신을 못 만든다는 것부터입니다.**

$$g(p, q) = pq - p - q$$

```text
p 를 x 개, q 를 y 개 써서 p·x + q·y = g(p,q) = pq - p - q 를 만든다고 두면
  양변에 p + q 를 더한다      p(x+1) + q(y+1) = pq
  법 q 로 보면                p(x+1) ≡ 0 (mod q)
  p 와 q 가 서로소라           q | (x+1)      x+1 ≥ 1 이므로 x+1 ≥ q
  같은 방법으로                p | (y+1)      마찬가지로 y+1 ≥ p
  그러면                      p(x+1) + q(y+1) ≥ pq + pq = 2pq > pq
                              └ 위 등식과 어긋난다
```

두 번째 걸음은 $g(p,q)$ 보다 큰 금액은 전부 만들 수 있다는 것입니다. $p$ 와 $q$ 가 서로소라 $p x \equiv a \pmod q$ 를
만족하는 $x$ 가 $0 \le x \le q-1$ 안에 정확히 하나 있어요.

```text
그 x 를 잡으면 a - p·x 는 q 의 배수다

  a > pq - p - q 이고 x ≤ q - 1 이므로
    a - p·x  >  (pq - p - q) - p(q-1)  =  -q

  q 의 배수이면서 -q 보다 크면 0 이상이다
    y = (a - p·x) / q ≥ 0            →  a = p·x + q·y 로 만들 수 있다
```

전개 입력의 앞 두 액면가 3 과 4 가 서로소이므로 $g(3,4) = 12 - 3 - 4 = 5$ 입니다. 파트 1 의 DP 테이블에서 `i=2` 줄의
`∞` 인 열이 1 · 2 · 5 로, 가장 큰 것이 5 예요. 다른 액면가 쌍으로도 전수로 세어 대조해 봅시다.

<!--proof:frobenius-check-->

```text
p, q          못 만드는 금액  가장 큰 것  pq - p - q  개수  (p−1)(q−1)/2
2, 3                       1           1           1     1             1
3, 4                   1 2 5           5           5     3             3
3, 5                 1 2 4 7           7           7     4             4
4, 7    1 2 3 5 6 9 10 13 17          17          17     9             9
5, 6  1 2 3 4 7 8 9 13 14 19          19          19    10            10
```

다섯 쌍에서 가장 큰 값이 $pq - p - q$ 와 정확히 같고, 못 만드는 금액의 개수도 $(p-1)(q-1)/2$ 와 같았습니다. 개수 쪽은
이 글이 유도하지 않았고 값으로만 확인한 것이에요. **마지막으로 계수입니다** — 과제의 위 끝에 가까운 서로소 쌍
$p = 9{,}999$, $q = 10{,}000$ 을 위 식에 넣고, 같은 쌍으로 DP 테이블을 채워 금액 1 부터 10,000 까지를 직접 세었습니다.

<!--proof:frobenius-scale-->

```text
무엇                                             값
못 만드는 가장 큰 금액 pq - p - q        99,970,001
못 만드는 금액의 개수 (p−1)(q−1)/2       49,985,001
이 과제의 금액 위 끝 A                       10,000
금액 1 … 10,000 가운데 못 만드는 것           9,998
금액 1 … 10,000 가운데 만드는 것     9,999 · 10,000
```

못 만드는 가장 큰 금액이 9,997 만이고 과제의 금액 위 끝은 1 만이라, 이 두 액면가로는 **금액 1 … 10,000 가운데 두 개만
만들어집니다.** `-1` 은 예외적인 답이 아니라 규모 안에서 흔하게 나오는 답이고, 그래서 DP 테이블의 `∞` 를 마지막에 한
번 확인하는 줄이 필수예요.

### 불변식 — dp[i][a] 는 앞의 i 종류를 몇 개든 써서 금액 a 를 만드는 최소 동전 개수다

파트 1 에서 코드가 동작하는 것을 스물세 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지, 언제나 맞는다는 뜻은
아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> `i` 번째 줄의 `a` 번째 칸을 정하고 난 시점에, `dp[i][a]` 는 **앞의 `i` 종류만** 써서 각각을 **몇 개든** 골라 합을
> **정확히 `a`** 로 만드는 **최소 동전 개수**입니다. 그런 조합이 없으면 `∞` 예요.

```text
앞의 i 종류만    i+1 번째 이후는 아직 안 열었다는 뜻이다
몇 개든          같은 액면가를 두 번 이상 고른 것도 센다
정확히 a         a 이하가 아니라 정확히 a 다
최소 개수        만드는 방법의 수도, 아무 방법 하나도 아니다
```

「칸 하나를 정하고 난 시점」이 중요합니다. 줄 하나가 끝난 시점이 아니라 **칸 하나마다**예요. 같은 줄의 왼쪽 칸을
읽으므로, 왼쪽 칸이 이미 참이어야 이 칸이 참이 됩니다.

```text
i-1 번째 줄 전체가 참        ┐
i 번째 줄의 0 … a-1 이 참    ┘ → i 번째 줄의 a 번째 칸이 참
                               → a 를 오름차순으로 올리면 줄 전체가 참
```

**출발점부터 봅시다.** `i = 0` 줄은 쓸 액면가가 없어 금액 0 만 0 개로 만들 수 있고 나머지는 못 만드는데, 코드가 첫
칸에 0 을 두고 나머지를 `∞` 로 깔았으니 참입니다. 그 뒤로 칸 하나가 세 갈래 중 하나로 정해지고, 각 갈래가 읽는 칸은
아래와 같아요.

| 칸이 정해지는 갈래 | 읽는 칸 | 그 값이 뜻하는 것 |
| --- | --- | --- |
| 못 쓴다 (`a < c`) | `prev[a]` | 앞의 `i-1` 종류로 `a` 를 만드는 최소 개수 |
| 안 쓴다 | `prev[a]` | 같음 — `i` 번째를 한 개도 안 쓴 경우 |
| 한 개 더 | `cur[a-c] + 1` | 앞의 `i` 종류로 `a-c` 를 만든 뒤 한 개를 더한 것 |

세 번째 갈래가 이 불변식과 맞물리는 자리입니다. `cur[a-c]` 가 참이면 그 최소 조합에 `i` 번째 액면가를 한 개 더한 것도
앞의 `i` 종류만 쓴 조합이라, 후보가 실제로 있는 조합의 개수예요. 거꾸로 금액 `a` 를 만드는 조합은 `i` 번째를 한 개도
안 쓰거나 한 개 이상 쓰거나 둘 중 하나이고, 두 경우가 각각 두 후보에 대응하니 빠지는 조합이 없습니다. 모든 칸을
정의대로 직접 고른 값과 맞대 보면 이렇습니다.

<!--proof:invariant-cells-->

| 줄 | DP 테이블의 값 | 개수 목록에서 직접 고른 최소 | 어긋난 칸 |
| --- | --- | --- | ---: |
| i=0 | [0 ∞ ∞ ∞ ∞ ∞ ∞] | [0 ∞ ∞ ∞ ∞ ∞ ∞] | 0 |
| i=1 | [0 ∞ ∞ 1 ∞ ∞ 2] | [0 ∞ ∞ 1 ∞ ∞ 2] | 0 |
| i=2 | [0 ∞ ∞ 1 1 ∞ 2] | [0 ∞ ∞ 1 1 ∞ 2] | 0 |
| i=3 | [0 1 2 1 1 2 2] | [0 1 2 1 1 2 2] | 0 |

정의대로 직접 고른 값과 DP 테이블의 값을 28 칸에서 대조했고, 어긋난 칸은 0 개입니다.

<!--/proof-->

경계에 있는 입력들도 확인하고 갑시다. 칸을 어느 갈래로 정했는지 세었습니다.

<!--proof:invariant-edges-->

| 입력 | 줄 × 칸 | 윗 칸을 옮긴 칸 | 안 쓰는 쪽을 고른 칸 | 한 개 더 쓰는 쪽을 고른 칸 | 반환 |
| --- | --- | ---: | ---: | ---: | ---: |
| `coins=[], amount=0` | 1 × 1 | 0 | 0 | 0 | 0 |
| `coins=[], amount=5` | 1 × 6 | 0 | 0 | 0 | -1 |
| `coins=[3, 4, 1], amount=0` | 4 × 1 | 3 | 0 | 0 | 0 |
| `coins=[7, 7, 7], amount=7` | 4 × 8 | 21 | 2 | 1 | 1 |
| `coins=[5, 10], amount=3` | 3 × 4 | 8 | 0 | 0 | -1 |
| `coins=[1, 3, 4], amount=6` | 4 × 7 | 8 | 1 | 12 | 2 |
| `coins=[4, 1, 3], amount=6` | 4 × 7 | 8 | 5 | 8 | 2 |

7 입력 모두 칸을 세 갈래 가운데 하나로만 정했습니다.

<!--/proof-->

빈 배열은 줄이 하나뿐이라 칸을 하나도 정하지 않고 `dp[0][A]` 가 그대로 답이 됩니다. 금액 0 은 열이 하나뿐이라 모든
액면가가 `a < c` 로 윗 칸을 옮기고, 모든 액면가가 금액보다 큰 입력은 모든 칸이 윗 칸을 옮겨요. 겹친 액면가 `[7, 7, 7]`
은 둘째 · 셋째 줄이 첫 줄과 같은 값을 다시 고르고, 액면가 순서를 바꾼 두 입력은 중간 줄의 갈래 수가 달라도 답이
같습니다. 층은 액면가를 **어느 순서로 열든** 마지막 줄에서 같은 값으로 만나요. 모두 특별 분기 없이 같은 전이식으로
처리됩니다.

**이제 깨뜨려 봅시다.** 불변식에서 「몇 개든」과 「정확히 `a`」는 읽는 줄이 지키고, **「최소 동전 개수」는 그 줄이
아니라 세는 자리가 지킵니다.** 읽어 온 값에 1 을 더하는 그 한 자리를 지웁니다.

```ts
const take = (cur[a - c] as number); // ← + 1 을 뺐다
```

액면가와 금액을 바꿔 가며 실행하면 이렇게 나옵니다.

<!--proof:mutant-no-count-->

```text
입력            바른 코드  1 을 안 더한 코드
[3, 4, 1] / 6           2                  0
[3, 4, 1] / 5           2                  0
[1, 2, 5] / 11          3                  0
[3] / 9                 3                  0
[3, 4, 1] / 0           0                  0
[5, 10] / 3            -1                 -1
```

**위 넷이 전부 0 입니다.** 동전 0 개로 6 원을 만들었다는 답이라 바로 틀렸다는 것이 보이는데, 그 자리가 정확히
불변식의 마지막 낱말이에요. 1 을 안 더하면 칸에 남는 것이 `dp[0][0] = 0` 이 옮겨 다닌 자국뿐입니다. 금액마다 부른
결과를 늘어놓으면 마지막 줄 전체가 그렇게 바뀐 것이 보여요.

<!--proof:mutant-rows-->

```text
코드               unboundedKnapsack([3, 4, 1], a), a = 0 … 6
바른 코드                                       0 1 2 1 1 2 2
1 을 안 더한 코드                               0 0 0 0 0 0 0
```

**그런데 아래 둘은 답이 같았습니다.** 금액 0 은 원래 0 개이고, `[5, 10]` 으로 3 을 만드는 것은 원래 `-1` 이에요. 바뀐
코드도 못 만드는 칸은 `∞` 로 남기므로 **「만들 수 있는가」는 여전히 정확히 답합니다** — 잃은 것은 개수 하나뿐이고,
그 상태는 칸에 참/거짓만 적는 [부분집합 합 판정](../subsetSum/subsetSum-guide.md) 과 같은 질문에 답하는 모양이에요.
다만 그쪽은 각 값을 한 번까지만 쓰니, 이 변형이 답하는 것은 「몇 개든 써서 만들 수 있는가」입니다.

### 비용 계산

#### 비용을 세는 과정

전개의 스물세 걸음이 한 일을 걸음 번호로 모으면 셋입니다.

<!--proof:perf-derive-->

```text
T1          DP 테이블 4 × 7 칸을 ∞ 로 깔고 dp[0][0] 하나를 0 으로
T2~T22      칸 21 개를 한 걸음에 한 칸씩 — ② 8 칸 · ③ 7 칸 · ④ 6 칸
T23         dp[3][6] 한 칸을 읽고 유한한지 본다
            └ 칸마다 비교 1 번, ②가 아니면 덧셈 1 번과 비교 1 번이 더
```

한 번의 호출이 하는 일도 같은 셋이고, 셋을 다 더해야 총식이 됩니다.

| 하는 일 | 비용 |
| --- | --- |
| DP 테이블 만들기 (T1) | `(n+1)(A+1)` 칸을 `∞` 로 채운다 |
| 칸 채우기 (T2~T22) | 바깥 `n` 번 × 안쪽 `A+1` 번 |
| 읽기 (T23) | `dp[n][A]` 한 칸을 보고 유한한지 확인한다. `O(1)` |

칸마다 하는 일은 비교 한 번과, ② 가 아니면 덧셈 한 번과 비교 한 번이 더라 상수예요. T10 처럼 윗 칸을 옮기는 칸이든
T8 · T22 처럼 두 후보를 다 만드는 칸이든 하는 일이 상수 번이라, 입력이 바뀌어도 칸당 비용이 흔들리지 않습니다.
비용은 이 글 전체에서 **정한 칸의 수**로 셉니다.

```text
총식 = O((n+1)(A+1))  +  O(n(A+1))  +  O(1)   =  Θ(nA)
             ↑ 만들기         ↑ 채우기      ↑ 읽기
```

메모리도 같은 크기입니다. `Θ(nA)` 칸을 실제로 들고 있어요. 답만 필요하면 한 줄 `best` 로 접어 `Θ(A)` 로 줄일 수
있고, 그때 지킬 것은 「짚고 가기 — 한 줄로 줄이면 금액을 작은 쪽부터 채워야 한다」의 방향입니다. 잃는 것은 각
액면가의 결정이 어느 줄에서 일어났는지를 나중에 볼 수 없다는 것이에요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (모든 액면가가 금액보다 크다) | `O(nA)` | `Θ(nA)` |
| **평균적인 경우** (입력을 아무렇게나 뽑아도) | `O(nA)` | `Θ(nA)` |
| **최악의 경우** (어떤 입력이든) | `O(nA)` | `Θ(nA)` |

**세 줄이 같습니다.** 이 알고리즘은 입력을 보고 일찍 끝내는 자리가 없어 DP 테이블 `(n+1)(A+1)` 칸을 언제나 한 번씩
채워요. 안쪽 루프가 `a = 0` 에서 `A` 까지 반복하는 것이 그 까닭이고, 액면가가 전부 금액보다 커서 「못 쓴다」만 나오는
입력도 칸 수는 그대로입니다.

**보장의 종류는 최악 보장입니다.** 기대값이 아니에요. 코드에 무작위성이 없고 입력 분포를 가정하지도 않습니다. 같은
입력이면 몇 번을 실행해도 채운 칸 수가 같아요. 위 표의 「평균」 줄도 분포에 대한 기댓값이 아니라 **어떤 분포에서
뽑아도 같은 값**이라는 뜻입니다.

```text
nA 의 A 는 입력의 "크기" 가 아니라 "값" 이다

  금액 10000 을 적는 데 글자 5 개             →  한 줄의 칸 10,001 개
  금액 100000000000000 을 적는 데 글자 15 개  →  한 줄의 칸 10^14 + 1 개
        ↑ 글자는 세 배인데 칸은 10^10 배
```

그래서 이 알고리즘도 **의사다항(pseudo-polynomial)** 입니다. 입력을 적은 글자 수를 기준으로 보면 지수적이에요.
「실제로 쓰이는 곳」의 OpenMS 가 이 DP 테이블을 안 쓰는 것이 이 성질의 직접적인 결과입니다.

#### 최악을 만드는 입력

「어떤 입력이 최악인가」라는 물음이 위 코드에 대해서는 **입력의 내용과 무관**합니다. 액면가를 어떻게 두어도 채우는 칸
수가 같기 때문이에요. 다만 액면가가 금액보다 큰 칸은 윗 칸을 옮기는 일뿐이라, 한 줄로 접으면 그 칸은 아무 일도 안
하므로 `a = c` 부터 채우면 됩니다. 그 건너뛰기를 붙이면 그때부터는 입력이 비용을 가르고, 최악을 만드는 입력을
실제로 구성할 수 있어요. 규모의 끝에서 네 입력을 세었습니다.

<!--proof:worst-fill-->

```text
입력 (금액 = 10,000)             답  정본이 정한 칸  건너뛰기판이 정한 칸
액면가 100 종이 전부 1       10,000       1,010,101             1,010,001
액면가 100 종이 1 … 100         100       1,010,101             1,005,051
액면가 100 종이 전부 5,000        2       1,010,101               510,101
액면가 100 종이 전부 10,000       1       1,010,101                10,101
```

**첫 줄이 최악을 만드는 입력입니다.** 액면가를 전부 1 로 두면 건너뛸 칸이 액면가마다 한 칸씩밖에 없어 1,010,001 칸을
그대로 채웁니다. 마지막 줄은 반대로 액면가마다 한 칸씩만 남아 10,101 칸이라 100 배 적어요. 정본은 네 입력 모두
1,010,101 칸이라, 시간의 최악은 `n` 과 `A` 가 규모의 끝일 때 하나뿐입니다.

```text
액면가가 작다   a < c 인 칸이 거의 없다   → 건너뛸 것이 없다   → 1,010,001 칸
                  └ 액면가 100 종이 전부 1 · 금액 10,000 이 그것이다
액면가가 크다   a < c 인 칸이 거의 전부   → 대부분 건너뛴다    →    10,101 칸
```

가운데 두 줄은 그 사이입니다. 액면가의 **평균 크기**가 건너뛰는 칸 수를 정하고, 그 평균이 가장 작은 입력이 건너뛰기판의
최악이에요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 조합을 하나씩 만드는 대신 **같은 금액에 이른 길을 한 칸으로 합쳤고**,
한 개 더 쓰는 후보를 **같은 줄에서** 읽어 같은 액면가를 몇 개든 쓰게 했고, 그 결과 `1.91 × 10^2090` 번의 호출이
`(n+1)(A+1)` 칸 채우기로 내려왔습니다.

```text
액면가를 한 종류씩 연다 → (i, a) 칸에 최소 개수를 적는다 → dp[n][A] 를 읽는다
        └ 줄이 결정을 한 종류로 묶는다  └ 같은 줄을 읽어 몇 개든 쓴다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T8 에서 `dp[1][6] = dp[1][3] + 1 = 2` 였고, 읽어 온 `dp[1][3]` 은 T5 에서 정해진
1 이었어요. 그 1 은 어떤 조합을 뜻할까요? 그리고 그것이 `dp[1][6]` 에서는 어떤 조합이 될까요?

<!--proof:selfcheck-q-->

```text
T5 :  dp[1][3] = dp[1][0] + 1 = 1
T8 :  dp[1][6] = dp[1][3] + 1 = 2
      dp[1][3] = 1 이 뜻하는 조합 = ?
```

<!--check:carryCell-->
`dp[1][3] = 1` 은 앞의 한 종류 `[3]` 으로 금액 3 을 동전 1 개로 만들 수 있다는 뜻이고, 그 조합은 `3` 하나입니다. 거기에
같은 액면가 3 을 한 개 더하면 `3 + 3` 이 되고 금액이 6 이에요. 여기서 확인할 것은 **더하기 전과 후가 같은 줄에
있다**는 점입니다. `dp[1][3]` 이 이미 3 을 한 개 쓴 값인데도 거기에 3 을 또 더할 수 있어요. 「같은 줄에서 읽는다」가
하는 일이 그것 전부입니다.

<!--proof:selfcheck-a-->

```text
읽은 칸   그 칸의 조합        하는 일  금액 6 의 조합  동전 개수
dp[1][3]             3  3 을 한 개 더           3 + 3          2
dp[0][6]          없음   3 을 안 쓴다            없음          ∞
```
<!--/check-->

아래 넷은 답을 싣지 않았습니다. 막히면 차례대로 「수행으로 알아보는 알고리즘」의 T15, 「불변식」, 「아이디어 상세」의
「상태를 (i, a) 두 수로 잡는 까닭」, 「수식 정의와 유도」를 다시 보세요.

- T15 에서 `dp[2][6]` 은 윗 칸의 2 를 그대로 받았습니다. 4 를 한 개 쓰는 후보가 왜 `∞` 였는지 값으로 적어 보고,
  액면가에 2 를 하나 더 넣으면 그 칸이 어떻게 달라질지 예측해 보세요.
- 금액이 아니라 **개수에 위 끝**이 있다면(각 액면가를 최대 두 개까지) 불변식의 어느 낱말을 고쳐야 하고, DP 테이블은
  어떻게 달라질까요.
- 가장 적은 개수 대신 **그 조합 자체**를 돌려주려면 칸마다 무엇을 더 적어야 할까요. 칸 수가 얼마나 늘어날까요.
- 액면가가 셋 이상일 때 「못 만드는 가장 큰 금액」에도 $pq - p - q$ 같은 닫힌 형태가 있을까요. 액면가 `[6, 10, 15]`
  로 못 만드는 금액을 직접 세어 보면 무엇이 보일까요.

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### 동전 교환 최소 개수

풀 파일: [`unboundedKnapsack.ts`](./unboundedKnapsack.ts) · 테스트: [`unboundedKnapsack.test.ts`](./unboundedKnapsack.test.ts) · 실행: `bun test src/algorithms/dp/unboundedKnapsack/unboundedKnapsack.test.ts`

#### 한 줄 요약

> 함수는 동전 종류 배열과 목표 금액을 받아, 그 금액을 만드는 데 필요한 최소 동전 개수를 반환하며, 불가능하면 -1을 반환한다.

#### 스토리

환전소 직원 민지는 고객에게 거스름돈을 줄 때 항상 가장 적은 수의 동전을 건네고 싶다. 각 동전은 충분히 많이 보유하고 있어 같은 액면가를 여러 번 쓸 수 있다.

민지가 다루는 동전 종류와 잔돈 금액은 매번 다르다. 어떤 조합으로도 정확히 그 금액을 만들 수 없으면 고객에게 불가능하다고 안내해야 한다.

#### 함수 인터페이스

```ts
export function unboundedKnapsack(coins: number[], amount: number): number;
```

- `coins` — 사용할 수 있는 동전의 액면가 목록. 각 동전은 무한히 사용 가능하다.
- `amount` — 만들어야 할 목표 금액 (0 이상의 정수)
- 반환 — `amount`를 만드는 데 필요한 최소 동전 개수. 불가능하면 `-1`. `amount`가 0이면 `0`.

#### 제약 조건

- $1 \leq |coins| \leq 100$
- $1 \leq coins[i] \leq 10^4$
- $0 \leq amount \leq 10^4$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

각 동전은 몇 번이든 사용할 수 있다 (무한 공급).

`amount`가 $0$이면 동전이 필요 없으므로 $0$을 반환한다.

주어진 동전들로 `amount`를 정확히 만들 수 없으면 $-1$을 반환한다.

`coins`가 비어 있고 `amount`가 $0$이면 $0$, `amount`가 $0$보다 크면 $-1$을 반환한다.

#### 예시

```ts
unboundedKnapsack([1, 2, 5], 11);
// 3 — 5 + 5 + 1 = 11, 동전 3개

unboundedKnapsack([2], 3);
// -1 — 짝수 동전으로 홀수 금액을 만들 수 없음

unboundedKnapsack([1], 0);
// 0 — 목표 금액이 0이므로 동전 불필요

unboundedKnapsack([1, 3, 4], 6);
// 2 — 3 + 3 = 6, 동전 2개 (탐욕적으로 4+1+1=3개보다 적음)

unboundedKnapsack([5, 10], 3);
// -1 — 모든 동전이 목표 금액보다 큼
```
