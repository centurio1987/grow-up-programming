# 트리 최대 가중 독립집합 — 정점마다 칸을 둘로 갈라 올려야 부모가 자식의 선택을 안다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 부분집합을 전부
만들어 보는 방법에서 출발해 정점마다 칸 둘을 적는 트리 DP 까지 가고, 그 방법을 준비되는 차례대로 값으로 푼 뒤,
실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

정점마다 수가 하나씩 붙은 트리가 있습니다. 이 수를 정점의 **가중치**라고 부르고, 음수일 수도 있어요. 정점을
몇 개 고르되 **간선 하나로 바로 이어진 두 정점은 함께 고르지 않는다**는 조건을 지키면, 고른 정점들을
**독립집합**이라고 부릅니다. 이 글이 만드는 것은 독립집합 가운데 **가중치 합이 가장 큰 값**이에요. 아무것도
고르지 않은 빈 집합도 독립집합이라, 답은 0 아래로 내려가지 않습니다. 이 글이 끝까지 쓰는 트리는 정점 일곱 ·
간선 여섯이고, 정점 이름 옆 괄호 안의 수가 가중치입니다.

<!--fig:concept-tree-->
![전개 입력 — 강조한 정점 {0, 3, 4, 5} 의 합 22 가 가장 크다](./figs/concept-tree.svg)

강조한 네 정점이 답이 되는 독립집합이에요. 뿌리 0 을 골랐는데도 그 손자 3 · 4 · 5 를 함께 골랐습니다. 0 과 3
사이에는 정점 1 이 있어서 둘을 잇는 간선이 없기 때문이에요. 독립집합을 합이 큰 차례로 몇 개 늘어놓으면
이렇습니다.

<!--proof:concept-answer-->

| 고른 정점 | 가중치 | 합 |
| --- | --- | ---: |
| {0, 3, 4, 5} | 9 + 5 + 1 + 7 | 22 |
| {0, 3, 5} | 9 + 5 + 7 | 21 |
| {0, 3, 4, 6} | 9 + 5 + 1 + 4 | 19 |
| {} (빈 집합) | — | 0 |

정점 7 개의 부분집합 128 개 가운데 독립집합은 37 개이고, 합이 가장 큰 것은 {0, 3, 4, 5} 의 22 로 1 개뿐입니다. 정본이 낸 값도 22 입니다.

<!--/proof-->

부분집합을 전부 만들어 보면 답은 맞지만, 정점이 하나 늘 때마다 부분집합 수가 두 배가 됩니다. 그런데 묻는 것은
**합 하나**예요. 그래서 이 글의 방법은 부분집합을 만들지 않고, 정점마다 **칸 둘**을 두어 그 정점 아래쪽에서
얻을 수 있는 가장 큰 합을 적어 둡니다. 정점 `v` 와 그 아래 정점 전부를 `v` 의 **서브트리**라고 하면, 두 칸은
이렇게 갈립니다.

| 칸 | 적는 것 |
| --- | --- |
| `dp0[v]` | `v` 를 **안 고를 때** `v` 의 서브트리에서 얻는 가장 큰 합 |
| `dp1[v]` | `v` 를 **고를 때** `v` 의 서브트리에서 얻는 가장 큰 합 |

작은 입력의 답을 칸에 적어 두고 큰 입력의 답을 그 칸들에서 만드는 구조를 **DP 테이블**이라고 부릅니다. DP 는
동적 계획법(dynamic programming)의 줄임말이에요. 배낭 문제의 DP 테이블은 줄과 열이 있는 표지만, 이 글의 DP
테이블은 **칸이 트리의 정점에 달려** 있습니다. 전개 입력의 DP 테이블 전체를 그리면 이렇습니다. 정점 안
아랫줄의 두 수가 앞은 `dp0`, 뒤는 `dp1` 이에요.

<!--fig:concept-table-->
![DP 테이블 — 정점 안 아랫줄이 두 칸 dp0 · dp1, 뿌리의 두 칸은 15 · 22](./figs/concept-table.svg)

뿌리 0 의 두 칸이 15 와 22 이고, 큰 쪽 22 가 답입니다. 칸은 **잎에서 뿌리 쪽으로** 채워요. 부모의 두 칸은 자식의
두 칸만 보고 정하고, 규칙은 둘뿐입니다.

| 부모 `p` 의 칸 | 자식 `v` 마다 더하는 것 | 까닭 |
| --- | --- | --- |
| `dp0[p]` | `dp0[v]` 와 `dp1[v]` 중 큰 쪽 | `p` 를 안 골랐으니 `v` 는 골라도 되고 안 골라도 된다 |
| `dp1[p]` | `dp0[v]` 만 (여기에 `p` 의 가중치를 더한다) | `p` 를 골랐으니 바로 이어진 `v` 는 고를 수 없다 |

손자는 아무 제한도 받지 않습니다. `dp0[v]` 안에서 손자를 고를지 말지가 이미 정해져 있기 때문이에요. 이렇게
트리의 정점마다 DP 테이블의 칸을 두고 자식에서 부모로 채우는 방법을 **트리 DP** 라고 부릅니다. 정점 수를 `n`
이라 하면 칸은 `2n` 개이고, 칸 하나를 정하는 데 자식 수만큼 더하면 됩니다. 비용은 결과만 적어 `O(n)` 이에요.

<!--proof:concept-size-->

```text
정점 수 n  부분집합 2^n     DP 테이블 칸 2n
7          128              14
100,000    9.99 × 10^30102  200,000
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **트리라는 말의 뜻.** 정점이 `n` 개, 간선이 `n − 1` 개인 연결된 무방향 그래프이고 사이클이 없습니다. 정점 하나를
  **뿌리**로 정하면 나머지 정점마다 **부모**가 정확히 하나 생기고, 부모 쪽이 아닌 이웃이 **자식**이에요.
- **이웃 목록.** 정점마다 「이 정점과 이어진 정점들」을 모아 둔 배열입니다. 무방향 간선 하나는 양 끝 정점의 목록에
  한 번씩, 모두 두 번 들어가요. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **너비 우선 순회.** 시작 정점에서 가까운 것부터 차례로 방문하는 순회입니다. 모르면
  [너비 우선 탐색 최단 경로](../../graph/bfsShortestPath/bfsShortestPath-guide.md)를 먼저 보세요.
- **DP 테이블을 작은 입력부터 채운다는 생각.** 칸 하나의 값이 이미 채운 다른 칸에서 나오는 구조예요. 줄과 열이
  있는 DP 테이블은 [0/1 배낭](../knapsack01/knapsack01-guide.md)에 있습니다.

재귀와 최단 경로는 몰라도 됩니다. 이 글의 코드는 배열 넷과 반복문 둘로 끝나요. 이름이 비슷한 과제와 나란히 놓으면
이 글의 범위가 갈립니다.

| 과제 | 입력의 모양 | 이 글에서 |
| --- | --- | --- |
| 이웃하지 않게 골라 합을 가장 크게 | 트리 | 다룬다 |
| 이웃하지 않게 골라 합을 가장 크게 | 일렬 | 자식이 하나뿐인 경우로만 — [`houseRobber`](../../array/houseRobber/houseRobber-guide.md) |
| 이웃하지 않게 골라 합을 가장 크게 | 사이클이 있는 그래프 | 다루지 않는다 |
| 가장 먼 두 정점 사이의 거리 | 트리 | 같은 순회 뼈대를 쓰는 다른 과제 — [`treeDiameter`](../../tree/treeDiameter/treeDiameter-guide.md) |

### 아이디어를 떠올리는 과정 — 부분집합 전부 만들기에서 정점마다 칸 둘까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수 · 간선 목록 · 정점별 가중치를
받아서 독립집합의 가장 큰 가중치 합을 돌려줍니다.

```ts
function treeMaxIndependentSet(
  n: number,
  edges: [number, number][],
  weights: number[],
): number;
```

- 입력: 정점 수 `n`, 무방향 간선 목록 `edges`, 정점별 가중치 `weights`. 정점 번호는 0 부터 `n − 1` 까지이고,
  간선은 정확히 `n − 1` 개이며 그래프는 이어진 트리입니다. 뿌리는 정점 0 으로 둡니다.
- 출력: 독립집합의 가중치 합 가운데 가장 큰 값 하나. 어떤 정점을 골랐는지는 돌려주지 않아요. 빈 집합도
  후보라 답은 0 이상입니다.
- 규모: 정점 100,000 개 이하, 가중치는 -10,000 이상 10,000 이하의 정수. 규모를 이만큼 잡은 까닭은 전부 만들기가
  정점 수십 개에서 이미 끝나지 않는다는 것과, 이 글의 방법은 그 천 배가 넘는 규모에서도 한 번에 끝난다는 것을
  한 표에서 보이기 위해서예요. 가중치 합은 많아야 10 억이라 정수 계산이 넘치지 않습니다. 비용은 흔한 채점 환경의
  예산인 1 초, 곧 기본 연산 1 억 번에 대어 잽니다.

입력이 트리라는 것과 가중치에 음수가 섞일 수 있다는 것이 뒤에서 각각 쓰입니다. 음수가 있으면 빈 집합이 답이 될
수 있고, 트리가 아니면 이 방법이 조용히 틀려요. 그 자리는 뒤에서 값으로 확인합니다. 이 글이 쓰는 기호는 열한
개입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `n` | 정점 수 | `1 ≤ n ≤ 100,000` |
| `v` | 지금 보고 있는 정점의 번호 | `0 ≤ v < n` |
| `p` | 정점 `v` 의 부모 | 뿌리는 부모가 없다 |
| `w[v]` | 정점 `v` 의 가중치. 코드의 `weights[v]` | `-10,000 ≤ w[v] ≤ 10,000` |
| `C(v)` | 정점 `v` 의 자식 집합 | 잎이면 빈 집합 |
| `dp0[v]` | `v` 를 안 고를 때 `v` 의 서브트리에서 얻는 가장 큰 합 | 언제나 0 이상 |
| `dp1[v]` | `v` 를 고를 때 `v` 의 서브트리에서 얻는 가장 큰 합 | 음수일 수 있다 |
| `adj[v]` | 정점 `v` 의 이웃 목록 | 길이를 모두 더하면 `2(n − 1)` |
| `order` | 뿌리에서 너비 우선으로 방문한 정점의 차례 | 길이 `n`, 맨 앞이 뿌리 0 |
| `parent[v]` | `v` 의 부모 번호 | 뿌리는 `-1` |
| `k` | `order` 안의 자리 | `0 ≤ k < n` |

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 부분집합을 전부 만들어 보고, 이웃한 두 정점이 함께 든
것을 버린 뒤, 남은 것 중 합이 가장 큰 것을 고르면 돼요.

```ts
// 부분집합을 전부 만들어 독립집합만 남기고, 가장 큰 합을 고른다.
let best = 0;
for (let mask = 0; mask < 1 << n; mask++) {
  let ok = true;
  for (const [u, v] of edges) {
    if ((mask >> u) & 1 && (mask >> v) & 1) {
      ok = false; // 이웃한 두 정점이 함께 들었다
      break;
    }
  }
  if (!ok) continue;
  let sum = 0;
  for (let i = 0; i < n; i++) if ((mask >> i) & 1) sum += weights[i];
  if (sum > best) best = sum;
}
return best;
```

이 방법은 답이 맞습니다. 비용은 **기본 연산**으로 셉니다. 간선 하나를 확인하는 일, 정점 하나의 가중치를 보는
일, 이웃 목록에 항목 하나를 넣거나 읽는 일, 자손 하나의 칸을 부모의 칸에 더하는 일을 각각 한 번으로 세요. 이
기준은 글 끝까지 바꾸지 않습니다. 등뼈에 잎을 하나씩 매단 트리에서 정점을 늘려 가며 세고, 오른쪽 끝에 이 글의
방법이 하는 기본 연산을 나란히 놓았습니다.

<!--proof:origin-naive-->

| 정점 n | 부분집합 2^n | 그중 독립집합 | 전부 만들기의 기본 연산 | 트리 DP 의 기본 연산 |
| ---: | ---: | ---: | ---: | ---: |
| 4 | 16 | 8 | 70 | 15 |
| 8 | 256 | 60 | 1,484 | 35 |
| 12 | 4,096 | 448 | 24,184 | 55 |
| 16 | 65,536 | 3,344 | 372,752 | 75 |
| 20 | 1,048,576 | 24,960 | 5,721,504 | 95 |
| 100,000 | 9.99 × 10^30102 | 세지 않았다 | 2^n 이상 | 499,995 |

앞의 다섯 줄은 등뼈에 잎을 하나씩 매단 트리에서 실제로 센 값이고, 정점이 넷 늘 때마다 전부 만들기의 기본 연산이 15.3배에서 21.2배로 늘었습니다. 마지막 줄의 전부 만들기는 부분집합마다 간선을 적어도 하나 확인하므로 2^n 번 이상입니다. 정점이 60 개만 돼도 1.15 × 10^18 번 이상이라 초당 1 억 번으로 1.15 × 10^10 초가 넘습니다.

<!--/proof-->

정점 20 개에서 이미 572 만 번이고, 정점이 60 개면 백억 초가 넘습니다. 오른쪽 끝의 이 글의 방법은 정점 10 만 개에서
499,995 번이에요. 그러면 전부 만들기가 무엇을 되풀이하는지 봅시다. 뿌리의 두 자식 아래를 묶어 그리면 이렇습니다.

<!--fig:origin-subtrees-->
![뿌리의 두 자식 2 · 1 의 서브트리 — 두 묶음 사이를 잇는 간선은 0 개](./figs/origin-subtrees.svg)

두 서브트리 사이에는 간선이 하나도 없습니다. 트리에는 사이클이 없어서, 정점 2 아래의 정점과 정점 1 아래의 정점이
뿌리를 거치지 않고 이어질 길이 없기 때문이에요. 그러니 한쪽 서브트리에서 무엇을 골랐는지는 다른 쪽의 선택을
바꾸지 않습니다. 그런데 전부 만들기는 서브트리 하나의 조합을 **나머지 정점의 조합마다 다시** 만들어요. 가장 아래
정점 5 · 6 만 떼어 보면 이렇습니다.

<!--proof:origin-repeat-->

| 정점 5 · 6 의 조합 | 합 | 간선 [5, 6] | 전부 만들기에서 나오는 횟수 |
| --- | ---: | --- | ---: |
| {} | 0 | 남긴다 | 32 |
| {5} | 7 | 남긴다 | 32 |
| {6} | 4 | 남긴다 | 32 |
| {5, 6} | — | 둘이 이웃이라 버린다 | 32 |

네 조합이 저마다 32 번씩, 모두 128 번 나옵니다. 정점 7 개의 부분집합 수 2^7 = 128 과 같습니다.

<!--/proof-->

정점 5 · 6 에서 알아야 할 것은 네 조합 가운데 버리지 않은 셋뿐인데, 전부 만들기는 그 셋을 서른두 번씩 다시
셉니다. 서브트리마다 **부모가 물어볼 몇 가지만** 기억해 두면 이 되풀이가 없어져요. 가장 단순한 후보부터 시험해
보겠습니다. 부모가 물어볼 것이 「그 서브트리에서 얻는 가장 큰 합」 하나라고 보고, 정점마다 값 **하나**만 적어
부모에 그대로 더하는 판이에요. 같은 입력을 칸 둘로 처리한 정본과 나란히 실행했습니다.

<!--proof:origin-one-value-->

| 입력 | 칸 둘 (정본) | 값 하나만 | 두 답 |
| --- | ---: | ---: | --- |
| 전개 입력(정점 일곱) | 22 | 34 | 어긋난다 |
| 경로 0-1-2, 가중치 5 1 5 | 10 | 11 | 어긋난다 |
| 경로 0-1-2-3, 가중치 10 1 1 10 | 20 | 22 | 어긋난다 |
| 별, 가운데 10 · 잎 1 넷 | 10 | 14 | 어긋난다 |
| 별, 가운데 1 · 잎 5 넷 | 20 | 21 | 어긋난다 |
| 정점 하나, 가중치 -5 | 0 | 0 | 같다 |

값 하나만 올린 판은 정점 하나짜리를 빼고 전부 **더 큰 값**을 냈습니다. 전개 입력에서 34 인데, 어느 독립집합도
22 를 넘지 못하니 34 는 독립집합의 합이 아니에요. 정점 1 에서 무슨 일이 벌어지는지 따라가면 이렇습니다.

<!--proof:origin-one-value-trace-->

```text
자식의 값          best[3] = 5 · best[4] = 1  합 6
정점 1 을 고른 값  8 + 6 = 14                 best[1] = 14
그 합에 든 정점    {1, 3, 4}                  간선 [1, 3] · [1, 4] 의 양 끝이 함께 들었다
뿌리의 값          best[0] = 34               정본의 답 22
```

자식 3 과 4 의 값 6 에는 3 과 4 **자신**이 들어 있습니다. 거기에 정점 1 의 가중치를 더하면 1 과 그 자식 둘을 함께
고른 합이 돼요. 값 하나로는 부모가 **자식의 값 안에 자식 자신이 들었는지**를 알 수 없습니다. 여기서 관찰한 것이
다음 걸음의 재료예요. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **정점마다 칸 둘을 두는 트리 DP** 입니다. 값을 「자식 자신을 골랐는가」로 둘로 갈라 적어 두면, 부모는
자기를 고를 때 자식이 안 골라진 쪽만 받을 수 있어요. 칸 둘이 무엇을 담는지, 어떤 차례로 채워야 하는지, 왜 셋이나
넷이 아니라 둘인지는 다음 절에서 실현하는 차례대로 확인합니다.

> 부모를 고르면 자식은 안 고른 칸만, 부모를 안 고르면 자식의 두 칸 중 큰 쪽을 받는다.

### 아이디어 상세 — 정점마다 칸 둘을 채우는 트리 DP

이 아이디어를 한 문장으로 줄이면 이렇습니다. **정점마다 DP 테이블의 칸 둘 `dp0` · `dp1` 을 두고, 자식이 부모보다
먼저 오는 차례로 자식의 두 칸을 부모의 두 칸에 더한 뒤, 뿌리의 두 칸 중 큰 쪽을 답으로 읽습니다.** 칸이 표가
아니라 트리의 정점에 달려 있다는 것이 처음 보는 사람에게는 낯설어서, 그 DP 테이블을 먼저 따로 설명합니다.
그다음 실현하는 차례대로 다섯 단계를 설명해요. 앞 단계에서 만든 것을 뒤 단계에서 씁니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 이웃 목록 만들기 | 간선 하나를 양 끝의 목록에 넣는다 | — |
| 시작할 때 한 번 | 2단계 칸의 시작값 적기 | `dp0[v] = 0`, `dp1[v] = w[v]` 로 둔다 | — |
| 시작할 때 한 번 | 3단계 자식이 먼저 오는 순서 정하기 | 뿌리에서 너비 우선으로 `order` 와 `parent` 를 채운다 | 1단계의 `adj` |
| 자식마다 한 번 | 4단계 자식의 두 칸을 부모에 더하기 | `order` 를 뒤에서부터 읽어 자식의 두 칸을 부모의 두 칸에 더한다 | 2단계의 시작값 · 3단계의 `order` 와 `parent` |
| 끝에 한 번 | 5단계 뿌리의 두 칸에서 답 읽기 | `max(dp0[0], dp1[0])` 을 돌려준다 | 4단계가 채운 뿌리의 두 칸 |

#### 먼저 알아 둘 개념 — 정점에 달린 DP 테이블

이 글의 DP 테이블은 **정점마다 칸을 둘씩 단 것**입니다. 칸 `dp0[v]` 에는 「`v` 를 안 고르고 `v` 의 서브트리에서
고를 수 있는 독립집합의 가장 큰 합」이, 칸 `dp1[v]` 에는 「`v` 를 고르고 같은 서브트리에서 고를 수 있는 가장 큰
합」이 적혀요. 여기서 헷갈리기 쉬운 것이 둘 있습니다. 칸에 적히는 것은 고른 집합 **자체가 아니라 그 합**이고, 칸이
보는 범위는 트리 전체가 아니라 **그 정점의 서브트리**예요.

| 무엇 | 담는 것 | 이 글에서 쓰는 곳 |
| --- | --- | --- |
| 독립집합 | 고른 정점들의 목록 하나 | 칸 하나가 무엇을 고른 값인지 설명할 때 |
| DP 테이블의 칸 | 조건(그 정점을 고르는가)을 만족하는 서브트리 안 독립집합 중 **가장 큰 합** | `dp0[v]` · `dp1[v]` 가 가리킬 때 |

##### 정점마다 달린 두 칸

전개 입력의 DP 테이블 전체를 다시 그렸습니다. 강조한 정점이 잎이에요.

<!--fig:build-table-->
![잎 3 · 4 · 6 의 두 칸은 0 · 가중치, 위로 갈수록 서브트리가 커진다](./figs/build-table.svg)

잎 3 · 4 · 6 은 서브트리가 자기 하나뿐이라 `dp0` 이 0, `dp1` 이 자기
가중치예요. 위로 올라갈수록 서브트리가 커지고, 뿌리 0 의 서브트리는 트리 전체라 뿌리의 두 칸이 곧 답의 두 후보입니다.
정점 2 의 두 칸 `7 · 2` 처럼 `dp1` 이 `dp0` 보다 작은 정점도 있어요. 가중치가 음수인 정점은 고르지 않는 쪽이 클 수
있습니다.

##### 칸 하나를 읽는 법

칸은 `dp0[1]` 처럼 이름과 정점 번호로 부릅니다. 이름 `dp0` · `dp1` 로 **그 정점을 고르는가**를 정하고, 번호로 **어느
서브트리 안에서 고르는가**를 정해요. `dp0[1]` 이라면 정점 1 을 안 담고 서브트리 `{1, 3, 4}` 안에서 고릅니다.

<!--fig:build-read-cell-->
![dp0[1] = 6 — 정점 1 을 안 담고 서브트리 {1, 3, 4} 에서 고른 {3, 4} 의 합](./figs/build-read-cell.svg)

그림에서 대시로 그린 정점은 이 칸이 보지 않는 자리예요. 칸 넷을 골라, 서브트리의 부분집합을 전부 만들어 그 칸의
조건에 맞는 가장 큰 합과 맞대 봤습니다.

<!--proof:build-read-cell-->

| 칸 | 서브트리의 정점 | 조건 | 합이 가장 큰 독립집합 | 그 합 | 칸의 값 |
| --- | --- | --- | --- | ---: | ---: |
| dp0[1] | {1, 3, 4} | 1 을 안 담는다 | {3, 4} | 6 | 6 |
| dp1[1] | {1, 3, 4} | 1 을 담는다 | {1} | 8 | 8 |
| dp0[2] | {2, 5, 6} | 2 를 안 담는다 | {5} | 7 | 7 |
| dp1[2] | {2, 5, 6} | 2 를 담는다 | {2, 6} | 2 | 2 |

서브트리의 부분집합을 전부 만들어 고른 합과 칸의 값이 4 칸 가운데 4 칸에서 같습니다.

<!--/proof-->

조심할 점이 하나 있습니다. `dp1[2] = 2` 는 정점 2 를 **반드시** 담은 합이라, 가중치 -2 를 떠안고 손자 6 을 더한
값이에요. 정점 2 를 안 담는 쪽 `dp0[2] = 7` 이 더 크지만, 두 칸은 서로 다른 물음의 답이라 각자 제 값을 적습니다.
어느 쪽을 쓸지는 부모가 정해요.

##### 부모의 칸과 자식의 칸

칸끼리는 간선을 따라 이어져 있습니다. 부모의 두 칸은 자식들의 두 칸에서 나오고, 규칙은 전체 컨셉의 표 그대로예요.
자식 3 을 부모 1 에 더하는 걸음을 그리면 이렇습니다. 읽은 자식은 진한 테, 두 칸이 바뀐 부모는 강조색 굵은 테예요.

<!--fig:build-relation-->
![T6 — 자식 3 의 두 칸 0 · 5 에서 부모 1 의 두 칸이 6 · 8 로 자란다](./figs/build-relation.svg)

정점마다 자식의 칸으로 두 칸을 다시 만들어 DP 테이블과 맞대면 이렇습니다.

<!--proof:build-relation-->

| 정점 v | 자식 | 자식 칸으로 만든 dp0[v] | 자식 칸으로 만든 dp1[v] | DP 테이블의 두 칸 |
| --- | --- | --- | --- | --- |
| 0 | 2 · 1 | max(7, 2) + max(6, 8) = 15 | 9 + 7 + 6 = 22 | 15 · 22 |
| 1 | 3 · 4 | max(0, 5) + max(0, 1) = 6 | 8 + 0 + 0 = 8 | 6 · 8 |
| 2 | 5 | max(4, 7) = 7 | -2 + 4 = 2 | 7 · 2 |
| 3 | 없음 | 0 (자식 없음) | 5 (자식 없음) | 0 · 5 |
| 4 | 없음 | 0 (자식 없음) | 1 (자식 없음) | 0 · 1 |
| 5 | 6 | max(0, 4) = 4 | 7 + 0 = 7 | 4 · 7 |
| 6 | 없음 | 0 (자식 없음) | 4 (자식 없음) | 0 · 4 |

정점 7 개 가운데 자식의 칸으로 만든 두 값이 DP 테이블의 두 칸과 모두 같은 정점은 7 개입니다.

<!--/proof-->

잎은 자식이 없어 `dp0` 이 0, `dp1` 이 자기 가중치이고, 그 위의 정점은 전부 자식 칸의 합으로 나옵니다. 정점 0 의
`dp1` 이 `9 + 7 + 6` 인 것은 자식 2 · 1 의 **`dp0`** 만 더했기 때문이에요. 정점 0 을 고르면 바로 아래 2 와 1 은 고를
수 없지만, 그 아래 5 · 3 · 4 는 `dp0[2]` 와 `dp0[1]` 안에서 이미 골라져 있습니다.

##### 번호 차례로 늘어놓은 두 칸과의 차이

배낭 문제의 DP 테이블을 먼저 봤다면 이 칸들을 **정점 번호 차례의 두 줄**로 늘어놓고 싶어집니다. 그쪽은 칸 하나가
바로 윗 칸이나 같은 줄 왼쪽 칸처럼 **번호로 이웃한 칸**을 읽었어요. 트리 아래에 같은 두 칸을 정점 번호 차례의 두 줄로 옮기고, 부모 1 과 그 자식 3 · 4 를 두 곳에 함께 강조했습니다.

<!--fig:build-contrast-->
![같은 두 칸을 정점 번호 차례의 두 줄로 옮기면 — 부모 1 이 읽는 자식 3 · 4 의 칸이 번호 줄에서 떨어져 있다](./figs/build-contrast.svg)

트리에서는 간선 하나로 이웃한 칸이 번호 줄에서는 정점 2 를 사이에 두고 떨어져 있습니다. 부모와 자식 쌍 여섯을 모두
세면 이렇습니다.

<!--proof:build-contrast-->

| 부모 칸 | 읽는 자식 칸 | 번호 차이 | 번호 줄에서 |
| --- | --- | ---: | --- |
| 0 | 1 | 1 | 옆 칸 |
| 0 | 2 | 2 | 떨어진 칸 |
| 1 | 3 | 2 | 떨어진 칸 |
| 1 | 4 | 3 | 떨어진 칸 |
| 2 | 5 | 3 | 떨어진 칸 |
| 5 | 6 | 1 | 옆 칸 |

부모가 읽는 자식 칸 6 개 가운데 번호 줄에서 바로 옆 칸인 것은 2 개입니다.

<!--/proof-->

부모가 읽는 칸은 번호 줄에서 대부분 떨어져 있습니다. 칸이 어느 칸을 읽는지 정하는 것은 번호가 아니라 **간선**이라,
DP 테이블을 트리 모양 그대로 두고 채우는 차례도 트리에서 정해야 해요. 그 차례는 3단계가 만듭니다.

##### 칸을 둘로 두는 까닭

「아이디어를 떠올리는 과정」에서 값 하나만 올린 판이 34 를 냈습니다. 부모가 자기를 고를 때 **자식이 안 골라진
합**이 필요했는데, 값 하나에는 그것이 따로 남아 있지 않았어요. 칸을 「이 정점을 고르는가」로 둘로 가르면 그 합이
`dp0` 에 따로 남습니다. 그리고 서로 다른 자식의 서브트리 사이에는 간선이 없으니, 부모는 자식마다 따로 받은 값을
그냥 더하면 돼요. 두 칸이 답하는 물음을 모으면 이렇습니다.

| 부모가 묻는 것 | 답하는 칸 | 없으면 |
| --- | --- | --- |
| 나를 안 고를 때, 이 자식 쪽에서 얻는 가장 큰 합은 | `max(dp0[v], dp1[v])` | — |
| 나를 고를 때, 이 자식을 빼고 얻는 가장 큰 합은 | `dp0[v]` | 자식을 함께 고른 합을 받아 독립집합이 아닌 것을 센다 |

#### 1단계 — 이웃 목록 만들기

간선 목록은 `[u, v]` 쌍의 나열이라 「정점 1 과 이어진 정점이 누구인가」를 바로 답하지 못합니다. 간선을 한 번 읽으면서
양 끝의 목록에 서로를 넣어 두면 그 물음을 목록 하나로 답해요.

<!--proof:build-lists-->

| 정점 u | adj[u] | 길이 |
| --- | --- | ---: |
| 0 | [2, 1] | 2 |
| 1 | [0, 3, 4] | 3 |
| 2 | [0, 5] | 2 |
| 3 | [1] | 1 |
| 4 | [1] | 1 |
| 5 | [2, 6] | 2 |
| 6 | [5] | 1 |

길이를 모두 더한 12 는 간선 6 개의 두 배입니다.

<!--/proof-->

간선 목록에 적힌 차례가 그대로 목록 안의 차례가 됩니다. `adj[0]` 이 `[2, 1]` 인 것은 간선 `[0, 2]` 가 `[0, 1]` 보다
먼저 적혀 있어서예요. 이 차례가 3단계에서 어느 자식을 먼저 방문하는지를 정합니다. 이 목록에는 부모와 자식이 섞여
있어요. `adj[1]` 의 0 은 정점 1 의 부모이고 3 과 4 는 자식인데, 목록만 봐서는 구분되지 않습니다.

#### 2단계 — 칸의 시작값 적기

자식을 하나도 더하지 않은 시점의 두 칸을 적습니다. 정점 `v` 를 안 고르면 아직 더한 것이 없어 `dp0[v] = 0` 이고,
고르면 자기 가중치만 들어 있어 `dp1[v] = w[v]` 예요.

<!--proof:build-init-->

| 정점 v | w[v] | dp0[v] | dp1[v] | 남은 일 |
| --- | ---: | ---: | ---: | --- |
| 0 | 9 | 0 | 9 | 자식 2 · 1 을 더해야 한다 |
| 1 | 8 | 0 | 8 | 자식 3 · 4 를 더해야 한다 |
| 2 | -2 | 0 | -2 | 자식 5 를 더해야 한다 |
| 3 | 5 | 0 | 5 | 없다 — 잎이라 더할 자식이 없다 |
| 4 | 1 | 0 | 1 | 없다 — 잎이라 더할 자식이 없다 |
| 5 | 7 | 0 | 7 | 자식 6 을 더해야 한다 |
| 6 | 4 | 0 | 4 | 없다 — 잎이라 더할 자식이 없다 |

시작값에서 이미 끝난 정점은 잎 3 · 4 · 6 의 3 개입니다.

<!--/proof-->

잎은 서브트리가 자기 하나뿐이라, 시작값이 곧 끝값입니다. 쉬운 경우가 여기서 끝나요. 나머지 정점은 자식을 모두
더해야 끝이 나고, 그 일을 4단계가 합니다. 정점 2 의 `dp1` 은 -2 로 시작해요. 음수 가중치를 위한 갈래를 따로 두지
않습니다 — 5단계와 4단계의 「큰 쪽 고르기」가 음수 정점을 알아서 뺍니다.

#### 3단계 — 자식이 먼저 오는 순서 정하기

부모의 칸은 자식의 칸이 **끝난 뒤에** 채워야 합니다. 그 차례를 만들려면 먼저 누가 누구의 부모인지 알아야 해요.
뿌리 0 에서 너비 우선으로 방문하면서, 꺼낸 정점의 이웃 가운데 부모가 아닌 것을 자식으로 삼아 `order` 뒤에 붙입니다.
큐를 따로 만들지 않고 `order` 배열 자체를 큐로 써요 — 앞에서 `head` 가 읽고 뒤에서 `tail` 이 붙입니다.

<!--proof:build-order-->

| head | 꺼낸 정점 v | adj[v] | 부모라 건너뛴 이웃 | 순서 뒤에 붙인 이웃 | 그 뒤 order |
| ---: | ---: | --- | --- | --- | --- |
| 0 | 0 | [2, 1] | 없음 (뿌리) | 2 · 1 | [0, 2, 1] |
| 1 | 2 | [0, 5] | 0 | 5 | [0, 2, 1, 5] |
| 2 | 1 | [0, 3, 4] | 0 | 3 · 4 | [0, 2, 1, 5, 3, 4] |
| 3 | 5 | [2, 6] | 2 | 6 | [0, 2, 1, 5, 3, 4, 6] |
| 4 | 3 | [1] | 1 | 없음 | [0, 2, 1, 5, 3, 4, 6] |
| 5 | 4 | [1] | 1 | 없음 | [0, 2, 1, 5, 3, 4, 6] |
| 6 | 6 | [5] | 5 | 없음 | [0, 2, 1, 5, 3, 4, 6] |

order 는 [0, 2, 1, 5, 3, 4, 6] 이고 parent 는 [-1, 0, 0, 1, 1, 2, 5] 입니다. 부모가 -1 인 정점은 뿌리 0 하나입니다.

<!--/proof-->

부모라 건너뛴 이웃이 여섯 번 나옵니다. 방향 없는 간선은 양쪽 목록에 다 있어서, 꺼낸 정점의 목록에는 자기를 붙여
준 부모가 반드시 들어 있어요. 그 이웃을 건너뛰지 않으면 부모가 다시 `order` 에 붙고, 그 부모가 또 자식을 붙여
순회가 끝나지 않습니다. 너비 우선 순회는 정점을 꺼낼 때 그 자식을 뒤에 붙이므로, `order` 에서는 **부모가 언제나
자식보다 앞**입니다. 그러니 `order` 를 뒤에서부터 읽으면 자식이 부모보다 먼저 와요.

<!--proof:build-reverse-->

```text
너비 우선 order                     0  2  1  5  3  4  6  부모가 자식보다 앞
뒤에서부터 k = 6 … 1                6  4  3  5  1  2     자식이 부모보다 앞
order 에서 부모보다 뒤에 놓인 자식  6 / 6
```

`k` 를 1 에서 멈추는 까닭은 `order[0]` 이 뿌리라 더해 줄 부모가 없기 때문입니다. 뒤에서부터 읽은 여섯 자리가 4단계에서
부모에 더할 자식 여섯이에요.

#### 4단계 — 자식의 두 칸을 부모에 더하기

`order` 를 `k = n − 1` 부터 1 까지 읽으며, `v = order[k]` 의 두 칸을 부모 `p = parent[v]` 의 두 칸에 더합니다. 갈래는
전체 컨셉의 표 그대로 둘이에요 — `dp0[p]` 에는 `max(dp0[v], dp1[v])` 를, `dp1[p]` 에는 `dp0[v]` 를 더합니다. 쉬운 경우는
자식이 하나뿐인 부모예요. 한 번 더하면 끝납니다. 불안한 경우는 **자식이 여럿인 부모**입니다. 자식 하나를 더한 뒤의
값은 끝값이 아니라서, 자식을 빠짐없이 더해야 해요. 자식이 둘인 정점 1 의 두 칸이 자라는 자취입니다.

<!--proof:build-fold-many-->

```text
시작값     dp0[1] = 0                  dp1[1] = 8
T5 자식 4  dp0[1] = 0 + max(0, 1) = 1  dp1[1] = 8 + 0 = 8
T6 자식 3  dp0[1] = 1 + max(0, 5) = 6  dp1[1] = 8 + 0 = 8
```

T5 에서 `dp0[1]` 이 1 이 되고 T6 에서 6 이 됩니다. 둘은 다른 값이 아니라 **같은 칸이 자식 하나만큼 자란 것**이에요.
그 사이에 부모 0 이 정점 1 의 칸을 읽으면 덜 된 1 을 가져갑니다. 그런 일이 없다는 근거가 3단계의 차례예요. 정점
`v` 의 자식은 모두 `order` 에서 `v` 보다 뒤에 있고, `k` 를 줄이며 읽으니 `v` 가 부모에 더해지는 자리 `k` 에 이르기 전에
`v` 의 자식은 전부 `v` 에 더해졌습니다. 여섯 번의 더하기에서 그랬는지 확인했어요.

<!--proof:build-fold-ready-->

| 걸음 | 자식 → 부모 | 그때 자식의 두 칸 | 다 채운 뒤의 두 칸 | 읽은 값 |
| --- | --- | --- | --- | --- |
| T4 | 6 → 5 | 0 · 4 | 0 · 4 | 끝난 값 |
| T5 | 4 → 1 | 0 · 1 | 0 · 1 | 끝난 값 |
| T6 | 3 → 1 | 0 · 5 | 0 · 5 | 끝난 값 |
| T7 | 5 → 2 | 4 · 7 | 4 · 7 | 끝난 값 |
| T8 | 1 → 0 | 6 · 8 | 6 · 8 | 끝난 값 |
| T9 | 2 → 0 | 7 · 2 | 7 · 2 | 끝난 값 |

더하기 6 번 가운데 자식의 두 칸이 이미 끝난 값이었던 것은 6 번입니다.

<!--/proof-->

빠뜨리는 정점이 없다는 근거는 반복의 범위에 있습니다. `k` 가 `n − 1` 부터 1 까지 한 칸씩 줄어드니, 뿌리를 뺀 정점
`n − 1` 개가 정확히 한 번씩 부모에 더해져요. 트리에서 뿌리를 뺀 정점마다 부모가 하나이므로, 모든 부모-자식 쌍이
정확히 한 번씩 처리됩니다.

#### 5단계 — 뿌리의 두 칸에서 답 읽기

4단계가 끝나면 뿌리 0 의 두 칸에 트리 전체에 대한 두 후보가 남습니다. 뿌리는 부모가 없어서 두 칸 중 아무 쪽이나
고를 수 있어요. 두 칸이 각각 어떤 집합의 합인지 부분집합을 전부 만들어 찾으면 이렇습니다.

<!--proof:build-answer-->

```text
dp0[0] = 15          고른 정점 {1, 5}        8 + 7
dp1[0] = 22          고른 정점 {0, 3, 4, 5}  9 + 5 + 1 + 7
답 max(15, 22) = 22
```

뿌리를 고르는 쪽이 22 로 더 크니 22 를 돌려줍니다. 빈 집합도 답이 되는 자리가 여기예요. `dp0[0]` 은 `max(…)` 를
더한 합이고, 그 `max` 는 잎에서 `max(0, w)` 로 시작하므로 0 아래로 내려가지 않습니다. 가중치가 전부 음수면 모든
정점에서 `dp0` 쪽이 커서 0 만 위로 올라가고, 답이 0 이 돼요.

#### 이 방법이 기대는 전제

트리 DP 는 전제 둘에 기댑니다. 하나라도 빠지면 오류 없이 틀린 값이 나오거나 끝나지 않아요.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 그래프가 이어져 있다 | 3단계 — 뿌리 하나에서 한 번 순회하면 모든 정점을 방문한다 | 뿌리에서 안 이어진 정점이 DP 테이블에서 빠진다 |
| 사이클이 없다 | 2 · 4단계 — 서로 다른 자식의 서브트리 사이에 간선이 없어 자식마다 따로 더해도 된다 · 3단계 — 부모 하나만 건너뛰면 된다 | 이미 방문한 정점이 부모가 아닌 이웃으로 다시 나타나 순서 배열이 끝없이 자란다 |

두 전제를 하나씩 깨뜨린 입력을 실행했습니다.

<!--proof:build-premise-->

| 입력 | 간선 수 | 깨지는 전제 | 정본 절차가 낸 것 | 부분집합을 전부 만든 답 |
| --- | ---: | --- | --- | ---: |
| 정점 4 · 간선 [0, 1] [2, 3] · 가중치 1 1 5 5 | 2 | 이어져 있다 | 답 1 | 6 |
| 정점 3 · 간선 [0, 1] [1, 2] [2, 0] · 가중치 5 5 5 | 3 | 사이클이 없다 | 순서 배열이 30 칸까지 자랐다 | 5 |

첫 줄은 정점 2 · 3 이 뿌리에서 이어지지 않아 한 번도 방문되지 않았습니다. 둘째 줄은 같은 순회를 순서 배열 30 칸에서 멈추게 한 사본으로 돌렸고, 정점이 3 개인데 30 칸이 차도록 순회가 끝나지 않았습니다.

<!--/proof-->

첫 줄은 예외도 없이 1 을 냅니다. 둘째 줄의 사이클 입력은 정본 그대로 실행하면 멈추지 않아서, 순서 배열 길이에 상한을
둔 사본으로 쟀어요. 입력이 트리라는 것은 이 절차가 확인하는 것이 아니라 **받는 쪽이 보장하는 것**입니다.

#### 정점마다 칸을 둘 두는 까닭

정점마다 칸을 몇 개 둘지는 정할 값입니다. 하나 · 둘 · 넷을 같은 입력에 실행해 답과 칸 수와 자손 칸을 더한 횟수를
나란히 쟀어요. 「하나, 손자까지」는 값 하나만 두되 자식 대신 손자에게서 「나를 고른다」 쪽을 직접 받는 판이고,
「넷」은 「부모를 골랐는가」와 「나를 고르는가」의 네 조합에 칸을 하나씩 둔 판입니다.

<!--proof:build-state-count-->

| 입력 | 정점마다 칸 | 답 | 답의 옳고 그름 | DP 테이블 칸 수 | 자손 칸을 더한 횟수 |
| --- | --- | ---: | --- | ---: | ---: |
| 전개 입력 | 하나, 자식만 본다 | 34 | 틀린다 | 7 | 6 |
| 전개 입력 | 하나, 손자까지 본다 | 22 | 맞다 | 7 | 10 |
| 전개 입력 | 둘, 자식만 본다 | 22 | 맞다 | 14 | 6 |
| 전개 입력 | 넷, 자식만 본다 | 22 | 맞다 | 28 | 16 |
| 별 (가운데 1 · 잎 5 넷) | 하나, 자식만 본다 | 21 | 틀린다 | 5 | 4 |
| 별 (가운데 1 · 잎 5 넷) | 하나, 손자까지 본다 | 20 | 맞다 | 5 | 4 |
| 별 (가운데 1 · 잎 5 넷) | 둘, 자식만 본다 | 20 | 맞다 | 10 | 4 |
| 별 (가운데 1 · 잎 5 넷) | 넷, 자식만 본다 | 20 | 맞다 | 20 | 8 |

「하나, 손자까지」와 「넷」이 정본과 같은 답을 내는지는 정점 1~9 개짜리 무작위 트리 400 개에서도 따로 확인했고, 어긋난 트리는 0 개입니다.

<!--/proof-->

| 정점마다 칸 | 답 | 내주는 것 |
| --- | --- | --- |
| 하나, 자식만 | 틀린다 | — |
| 하나, 손자까지 | 맞다 | 칸은 절반인데 자손을 두 단계 내려가 읽어야 한다 |
| 둘, 자식만 | 맞다 | 칸이 `2n` 이고 자식을 한 번씩만 읽는다 |
| 넷, 자식만 | 맞다 | 답이 같은데 칸이 `4n` 이고 「부모를 골랐는데 나도 고른다」는 칸은 만들 수 없는 칸이다 |

**칸 둘이 이 글의 선택입니다.** 칸 하나로도 손자까지 읽으면 답이 맞지만, 그러려면 정점마다 자식의 자식까지 두 단계를
걸어야 해서 더한 횟수가 전개 입력에서 10 번으로 늘어요. 넷은 답이 같은데 칸과 더한 횟수만 늘어납니다. 별 모양에서
「하나, 손자까지」가 칸 둘과 횟수가 같은 것은 그 트리에 손자가 아예 없기 때문이에요.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 차례로 다시 적으면 이렇습니다. 부분집합 `2^n` 개를 만들던 일이 칸 `2n` 개를 채우는 일이 됐어요.

1. 간선 `[u, v]` 마다 `adj[u]` 에 `v` 를, `adj[v]` 에 `u` 를 넣는다
2. 정점마다 `dp0[v] = 0`, `dp1[v] = w[v]` 로 둔다
3. 뿌리 0 에서 너비 우선으로 `order` 와 `parent` 를 채운다 — 꺼낸 정점의 이웃 가운데 부모는 건너뛴다
4. `k` 를 `n − 1` 부터 1 까지 줄이며 `v = order[k]`, `p = parent[v]` 로 두고 `dp0[p] += max(dp0[v], dp1[v])`, `dp1[p] += dp0[v]`
5. `max(dp0[0], dp1[0])` 을 돌려준다

### 수행으로 알아보는 알고리즘 — 정점 일곱의 DP 테이블을 여섯 번 더해 22 를 낸다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 7;
const edges: [number, number][] = [[0, 2], [0, 1], [1, 3], [1, 4], [2, 5], [5, 6]];
const weights = [9, 8, -2, 5, 1, 7, 4];
// 이 절이 끝나면 22 가 나와야 한다 (정점 {0, 3, 4, 5})
```

이 입력을 고른 까닭은 **갈래가 한 입력에서 모두 실행되기 때문**입니다. 정점 1 은 자식이 둘이고 정점 2 · 5 는 자식이
하나라, 자식을 모아 더하는 자리와 하나만 더하는 자리가 함께 나와요. 정점 2 의 가중치가 음수라 안 고르는 쪽이 더 큰
정점이 실제로 생깁니다. 답이 뿌리와 손자 셋을 함께 고르는 모양이라 「못 고르게 되는 것은 바로 이어진 정점까지」가
값으로 확인되고, 간선을 `[0, 2]` 부터 적어 방문 순서가 정점 번호와 달라집니다. 절차 전체를 한 장으로 적으면 이렇습니다.

```text
treeMaxIndependentSet(n, edges, weights):
    간선 [u, v] 마다 adj[u] 에 v 를, adj[v] 에 u 를 넣는다
    정점마다 dp0 ← 0 · dp1 ← w[v]                                  ① 시작값
    뿌리 0 에서 너비 우선으로 order 와 parent 를 채운다:
        order 에서 v 를 꺼내고, adj[v] 의 이웃 u 마다:
            u 가 v 의 부모이면 건너뛴다                             ② 부모 쪽 간선
            parent[u] ← v, order 뒤에 u 를 붙인다                   ③ 자식
    k 를 n-1 부터 1 까지 줄이며:
        v ← order[k], p ← parent[v]
        dp0[p] ← dp0[p] + max(dp0[v], dp1[v])                      ④ p 를 안 고른다
        dp1[p] ← dp1[p] + dp0[v]                                   ⑤ p 를 고른다
    max(dp0[0], dp1[0]) 을 돌려준다                                 ⑥ 뿌리
```

#### 1. 간선 여섯 개를 이웃 목록으로 옮긴다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 정점마다 빈 목록을 만들어 두고, 간선 하나를 양 끝의 목록에 한 번씩
넣어요.

```ts
const adj: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  adj[u].push(v);
  adj[v].push(u);
}
```

T1 에서 전개 입력에 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walk-adj-->

```text
adj[0] = [2, 1]
adj[1] = [0, 3, 4]
adj[2] = [0, 5]
adj[3] = [1]        잎이라 이웃이 하나
adj[4] = [1]        잎이라 이웃이 하나
adj[5] = [2, 6]
adj[6] = [5]        잎이라 이웃이 하나
목록 길이의 합 12 = 간선 6 개의 두 배
```

잎 셋(3 · 4 · 6)은 이웃이 부모 하나뿐입니다. 부모와 자식을 가르는 일은 3번 조각이 해요.

#### 2. 정점마다 두 칸의 시작값을 적는다

「아이디어 상세」의 2단계입니다. DP 테이블의 두 칸을 배열 둘로 둡니다.

```ts
// ① 자식을 하나도 안 더한 시점의 시작값.
//    안 고르면 자기 가중치가 안 들어가고, 고르면 자기 가중치만 들어가 있다.
const dp0 = new Array<number>(n).fill(0);
const dp1 = [...weights];
```

T2 에서 실행하면 이렇게 나옵니다.

<!--proof:walk-init-->

```text
dp0 = [0, 0, 0, 0, 0, 0, 0]
dp1 = [9, 8, -2, 5, 1, 7, 4]
```

`dp1` 은 `weights` 를 그대로 베낀 것입니다. 정점 2 의 `dp1` 에 -2 가 그대로 들어가요.

#### 3. 뿌리에서 방문 순서와 부모를 정한다

「아이디어 상세」의 3단계입니다. `order` 를 큐로 쓰는 너비 우선 순회예요.

```ts
const order = new Array<number>(n).fill(0);
const parent = new Array<number>(n).fill(-1);
let tail = 1;
for (let head = 0; head < tail; head++) {
  const v = order[head];
  for (const u of adj[v]) {
    // ② 부모 쪽 간선은 건너뛴다 — 그쪽은 이미 지나온 자리다.
    if (u === parent[v]) continue;
    parent[u] = v;
    // ③ 자식을 순서 배열의 뒤에 붙인다.
    order[tail] = u;
    tail++;
  }
}
```

여기서 가장 중요한 줄은 `if (u === parent[v]) continue;` 입니다. `order` 를 0 으로 채워 두었으니 `order[0]` 이 뿌리 0
이고, `parent[0] = -1` 이라 뿌리에서는 아무 이웃도 건너뛰지 않아요. T3 에서 실행하면 이렇게 나옵니다.

<!--proof:walk-bfs-->

```text
order  = [0, 2, 1, 5, 3, 4, 6]
parent = [-1, 0, 0, 1, 1, 2, 5]
```

`order` 는 정점 번호 차례와 다릅니다. 정점 2 가 1 보다 앞인 것은 `adj[0]` 이 `[2, 1]` 이기 때문이에요.

#### 짚고 가기 — 순서를 뒤집지 않고 앞에서부터 더해도 될 것 같다

자식을 부모에 더하는 일은 어차피 정점마다 한 번씩이니 읽는 방향은 상관없어 보입니다. `order` 를 앞에서부터 읽어도 같은
정점을 같은 부모에 같은 횟수만큼 더하니까요. 그대로 적으면 이렇습니다.

```ts
for (let k = 1; k < n; k++) { // ← k = n - 1 부터 줄이던 것을 1 부터 늘린다
```

**이 코드는 예외를 내지 않고, 어떤 입력에서는 답까지 맞습니다.** 여섯 입력에 정본과 나란히 실행했습니다.

<!--proof:walk-order-mutant-->

| 입력 | 정본 | 앞에서부터 더한 판 | 두 답 |
| --- | ---: | ---: | --- |
| 전개 입력(정점 일곱) | 22 | 9 | 어긋난다 |
| 경로 0-1-2, 가중치 5 1 5 | 10 | 5 | 어긋난다 |
| 경로 0-1-2-3, 가중치 10 1 1 10 | 20 | 10 | 어긋난다 |
| 별, 가운데 10 · 잎 1 넷 | 10 | 10 | 같다 |
| 별, 가운데 1 · 잎 5 넷 | 20 | 20 | 같다 |
| 정점 하나, 가중치 -5 | 0 | 0 | 같다 |

아래 세 줄이 답이 맞는 자리예요. 별 모양은 뿌리를 뺀 정점이 전부 잎이라, 앞에서부터 읽어도 읽는 자식의 칸이 이미
끝난 시작값입니다. 정점 하나짜리는 더할 것이 없어요. **테스트가 별 모양과 정점 하나만 담고 있으면 이 잘못이
통과합니다.** 전개 입력에서 처음 세 번을 따라가면 이렇습니다.

<!--proof:walk-order-trace-->

```text
k=1  v=2 → 부모 0  dp0[0] = 0 + max(0, -2) = 0  자식 2 의 두 칸이 아직 0 · -2 (다 채우면 7 · 2)
k=2  v=1 → 부모 0  dp0[0] = 0 + max(0, 8) = 8   자식 1 의 두 칸이 아직 0 · 8 (다 채우면 6 · 8)
k=3  v=5 → 부모 2  dp0[2] = 0 + max(0, 7) = 7   자식 5 의 두 칸이 아직 0 · 7 (다 채우면 4 · 7)
끝                 답 max(8, 9) = 9             정본의 답 22
```

`k = 1` 에서 뿌리가 정점 2 의 칸을 읽는 순간, 2 의 자식 5 는 아직 2 에 더해지지 않았습니다. 뿌리는 덜 된 `0 · -2` 를
가져가고, 뒤에서 2 의 칸이 `7 · 2` 로 자라도 뿌리는 그것을 다시 읽지 않아요. 그래서 고칩니다 — `order` 는 반드시
뒤에서부터 읽습니다. 깊이가 1 인 트리(별)에서는 방향이 답을 안 바꾸지만, 깊이가 2 이상이면 위 표의 경로 두 줄처럼 바꿀 수 있습니다.

#### 4. 순서를 뒤에서부터 읽어 자식의 두 칸을 부모에 더한다

「아이디어 상세」의 4단계입니다. 갈래는 둘뿐이에요.

```ts
// 순서를 뒤에서부터 읽으면 자식이 부모보다 먼저 온다.
for (let k = n - 1; k >= 1; k--) {
  const v = order[k];
  const p = parent[v];
  // ④ 부모를 안 고르면 자식은 두 값 중 큰 쪽을 쓴다.
  dp0[p] = dp0[p] + Math.max(dp0[v], dp1[v]);
  // ⑤ 부모를 고르면 자식은 안 고르는 값만 쓸 수 있다.
  dp1[p] = dp1[p] + dp0[v];
}
```

T4 부터 T9 까지 여섯 번 더한 자취입니다. 마지막 두 칸은 **그 걸음이 끝난 뒤 부모의 두 칸**이에요.

<!--proof:walk-fold-->

| 걸음 | 순서 k | 자식 → 부모 | 큰 쪽 고르기 | ④ dp0[p] | ⑤ dp1[p] |
| --- | ---: | --- | --- | --- | --- |
| T4 | 6 | 6 → 5 | max(0, 4) = 4 | 0 + 4 = 4 | 7 + 0 = 7 |
| T5 | 5 | 4 → 1 | max(0, 1) = 1 | 0 + 1 = 1 | 8 + 0 = 8 |
| T6 | 4 | 3 → 1 | max(0, 5) = 5 | 1 + 5 = 6 | 8 + 0 = 8 |
| T7 | 3 | 5 → 2 | max(4, 7) = 7 | 0 + 7 = 7 | -2 + 4 = 2 |
| T8 | 2 | 1 → 0 | max(6, 8) = 8 | 0 + 8 = 8 | 9 + 6 = 15 |
| T9 | 1 | 2 → 0 | max(7, 2) = 7 | 8 + 7 = 15 | 15 + 7 = 22 |

여기서 가장 중요한 줄은 ⑤ `dp1[p] = dp1[p] + dp0[v];` 입니다. 부모를 고르는 칸에 자식의 `dp0` **만** 더하는 이 한 줄이
「이웃한 두 정점을 함께 고르지 않는다」를 지키는 자리 전부예요. T9 에서 `dp1[0]` 이 `15 + 7` 이 되는데, 그 7 은
정점 2 를 안 고른 `dp0[2]` 이고 그 안에서 정점 5 가 골라져 있습니다.

#### 5. 뿌리의 두 칸 중 큰 쪽을 돌려준다

「아이디어 상세」의 5단계입니다.

```ts
// ⑥ 빈 집합도 독립집합이라 dp0[0] 이 0 아래로 안 내려간다.
return Math.max(dp0[0], dp1[0]);
```

T10 에서 실행하면 이렇게 나옵니다.

<!--proof:walk-answer-->

```text
T10  max(dp0[0], dp1[0]) = max(15, 22) = 22   ⑥
```

`dp1[0]` 이 더 크니 뿌리를 고르는 쪽이 답입니다.

#### 짚고 가기 — 뿌리를 고르면 손자까지 못 고를 것 같다

정점 0 을 고르면 자식 1 과 2 를 못 고릅니다. 그러면 그 아래 3 · 4 · 5 도 못 고르게 되는 것 아닐까요? 「고른 정점
주변은 비워야 한다」고 읽으면 자연스러운 생각이에요. 그 오해대로 적으면 부모를 고를 때 자식의 서브트리에서 **손자
아래만** 쓰게 됩니다.

```ts
// 오해대로 적으면 — 고른 정점의 자식과 손자를 함께 버린다
let take = weights[v];
for (const u of kids[v]) {
  for (const g of kids[u]) take += skip[g]; // ← 손자 g 도 못 고른다고 보고 그 아래만 더한다
}
```

| 입력 | 정본 | 손자까지 버린 판 | 두 답 |
| --- | ---: | ---: | --- |
| 전개 입력(정점 일곱) | 22 | 15 | 어긋난다 |
| 경로 0-1-2, 가중치 5 1 5 | 10 | 5 | 어긋난다 |
| 경로 0-1-2-3, 가중치 10 1 1 10 | 20 | 20 | 같다 |
| 별, 가운데 10 · 잎 1 넷 | 10 | 10 | 같다 |
| 별, 가운데 1 · 잎 5 넷 | 20 | 20 | 같다 |
| 정점 하나, 가중치 -5 | 0 | 0 | 같다 |

**아래 네 줄에서는 답이 같습니다.** 별 모양은 손자가 아예 없고, 경로 `10 1 1 10` 은 답이 양 끝 둘이라 손자를 버려도
잃는 것이 없어요. 위 두 줄에서 갈립니다. 전개 입력을 따라가면 이렇습니다.

<!--proof:walk-grandchild-trace-->

```text
바른 답   뿌리 0 을 고르고 손자 5 · 3 · 4 도 고른다    {0, 3, 4, 5} = 22
오해대로  뿌리 0 을 고르면 손자 5 · 3 · 4 까지 버린다  고른다 쪽 = 9 + 4 + 0 + 0 = 13
          손자 아래는 증손자 6 뿐이다                  안 고른다 쪽 = 15
```

**못 고르게 되는 것은 간선 하나로 바로 이어진 정점까지입니다.** 코드에서 그 자리는 ⑤ 한 줄이에요 — 부모를 고를 때
자식의 `dp0` 을 받는데, 그 `dp0` 안에서 손자들은 이미 자유롭게 정해져 있습니다. 손자를 한 번 더 빼는 코드가 어디에도
없다는 것이 이 성질을 그대로 말해 줘요.

#### 6. 일곱 정점에서 열 걸음을 끝까지 실행한다

앞의 다섯 조각을 이어 실제로 실행하면 열 걸음이 나옵니다. 이웃 목록 만들기 · 시작값 적기 · 순서 정하기가 한 걸음씩,
자식 하나를 부모에 더하는 일 하나가 걸음 하나, 마지막이 답을 읽는 걸음이에요. 걸음 재생 패널에서 정점 안 아랫줄의

#### 7. 전체 코드

조각 다섯을 한 함수로 잇습니다. 앞에서 안 나온 것은 없고, 조각의 순서를 그대로 이어 붙인 것이 전체 코드예요. 배열
첨자 읽기에 붙은 `as number` 는 설정 `noUncheckedIndexedAccess` 가 첨자 읽기를 `number | undefined` 로 보기 때문에
단 타입 단언이고, 실행에는 아무 영향이 없습니다.

```ts
export function treeMaxIndependentSet(
  n: number,
  edges: [number, number][],
  weights: number[],
): number {
  // 이웃 목록 — 무방향이라 간선 하나를 양쪽 정점의 목록에 넣는다.
  const adj: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    (adj[u] as number[]).push(v);
    (adj[v] as number[]).push(u);
  }

  // ① 자식을 하나도 안 더한 시점의 시작값.
  //    안 고르면 자기 가중치가 안 들어가고, 고르면 자기 가중치만 들어가 있다.
  const dp0 = new Array<number>(n).fill(0);
  const dp1 = [...weights];

  // 뿌리 0 에서 너비 우선으로 방문 순서와 부모를 정한다.
  const order = new Array<number>(n).fill(0);
  const parent = new Array<number>(n).fill(-1);
  let tail = 1;
  for (let head = 0; head < tail; head++) {
    const v = order[head] as number;
    for (const u of adj[v] as number[]) {
      // ② 부모 쪽 간선은 건너뛴다 — 그쪽은 이미 지나온 자리다.
      if (u === parent[v]) continue;
      parent[u] = v;
      // ③ 자식을 순서 배열의 뒤에 붙인다.
      order[tail] = u;
      tail++;
    }
  }

  // 순서를 뒤에서부터 읽으면 자식이 부모보다 먼저 온다.
  for (let k = n - 1; k >= 1; k--) {
    const v = order[k] as number;
    const p = parent[v] as number;
    // ④ 부모를 안 고르면 자식은 두 값 중 큰 쪽을 쓴다.
    dp0[p] = (dp0[p] as number) + Math.max(dp0[v] as number, dp1[v] as number);
    // ⑤ 부모를 고르면 자식은 안 고르는 값만 쓸 수 있다.
    dp1[p] = (dp1[p] as number) + (dp0[v] as number);
  }

  // ⑥ 빈 집합도 독립집합이라 dp0[0] 이 0 아래로 안 내려간다.
  return Math.max(dp0[0] as number, dp1[0] as number);
}
```

재귀를 쓰지 않은 것도 이 모양의 일부입니다. 정점 100,000 개가 한 줄로 이어지면 재귀는 호출 깊이가 그대로 100,000 이
되지만, `order` 배열로 차례를 미리 정하면 깊이가 배열 길이가 될 뿐이에요. 여러 입력에 실행하면 이렇게 나옵니다.

```text

경로 0-1-2-3, 가중치 10 1 1 10  →  20
별, 가운데 1 · 잎 5 넷          →  20
정점 하나, 가중치 42            →  42
정점 하나, 가중치 -5            →  0
```

### 알아 두면 좋은 개념 — 최소 가중 정점 덮개

전개 입력에서 고른 정점은 `{0, 3, 4, 5}` 였고 남은 정점은 `{1, 2, 6}` 이었습니다. 남은 쪽을 따로 보면 성질 하나가
확인돼요 — **모든 간선이 남은 쪽 정점을 적어도 하나 끝점으로 갖습니다.**

<!--fig:related-cover-->
![굵은 테가 고른 쪽 {0, 3, 4, 5}, 진한 테가 남은 쪽 {1, 2, 6} — 남은 쪽의 합 10 이 간선 6 개를 모두 덮는다](./figs/related-cover.svg)

<!--proof:related-edges-->

| 간선 | 남은 쪽 {1, 2, 6} 에 든 끝점 |
| --- | --- |
| [0, 2] | 2 |
| [0, 1] | 1 |
| [1, 3] | 1 |
| [1, 4] | 1 |
| [2, 5] | 2 |
| [5, 6] | 6 |

간선 6 개 가운데 끝점 하나 이상이 남은 쪽에 든 간선은 6 개입니다.

<!--/proof-->

이렇게 **모든 간선의 끝점 중 적어도 하나를 담는 정점 집합**을 **정점 덮개**라고 부르고, 가중치 합을 가장 작게 만든
것을 최소 가중 정점 덮개라고 합니다. 고른 쪽이 독립집합이면 남은 쪽은 언제나 덮개예요 — 어떤 간선의 두 끝이 다 남은
쪽 밖이라면 두 끝이 다 고른 쪽이라 독립집합이 아니게 되니까요. 거꾸로 덮개의 나머지는 독립집합입니다. 그래서 가중치
합에서 독립집합의 최대 합을 빼면 정점 덮개의 최소 합이 나와요. 덮개를 직접 전부 만들어 맞대
봤습니다.

<!--proof:related-sum-->

| 입력 | 가중치 합 S | 독립집합의 최대 합 | S − 최대 합 | 정점 덮개의 최소 합 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 32 | 22 | 10 | 10 |
| 경로 0-1-2-3, 가중치 10 1 1 10 | 22 | 20 | 2 | 2 |
| 별, 가운데 10 · 잎 1 넷 | 14 | 10 | 4 | 4 |

정점 덮개의 최소 합은 덮개를 전부 만들어 직접 셌고, 세 입력 가운데 S − 최대 합과 같은 것이 3 개입니다.

<!--/proof-->

한쪽을 풀면 다른 쪽이 뺄셈 하나로 나옵니다. 같은 이름을 이 편 밖에서 다시 만나는 자리예요.

| 다시 나오는 자리 | 정점 덮개의 쓰임 |
| --- | --- |
| 이분 그래프의 최대 매칭 | 최소 정점 덮개의 크기가 최대 매칭의 크기와 같다 — [`maxBipartiteMatching`](../../graph-flow/maxBipartiteMatching/maxBipartiteMatching-guide.md) |
| 일반 그래프의 근사 | 정점 덮개는 일반 그래프에서 빠른 정확한 방법이 알려져 있지 않아, 두 배 안쪽으로 근사하는 절차를 쓴다 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 두 칸의 집합 정의에서 전이식과 답의 범위가 어떻게
나오는지, 무엇이 매 순간 참으로 남는지, 그리고 비용이 얼마인지 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 입력이 트리다 | 사이클이 있으면 자식의 서브트리 사이에 간선이 생겨 따로 더할 수 없다 | 뿌리에서 한 번 순회하고 부모 하나만 건너뛴다 |
| 제약이 바로 이어진 두 정점에만 걸린다 | 「거리 2 이하를 함께 못 고른다」로 바뀌면 부모가 받을 칸이 둘로 안 끝난다 | 칸이 둘이고 그중 `dp1` 만 제한을 받는다 |
| 정점의 상태를 몇 가지로 셀 수 있다 | 여기서는 고른다와 안 고른다 둘이다 | 배열 두 개 |
| 답이 합 하나다 | 어떤 정점을 골랐는지까지 알려면 두 칸 중 어느 쪽을 썼는지 기록을 더 남겨야 한다 | 뿌리의 두 칸만 읽는다 |

넷째 조건은 잘못 읽기 쉽습니다. 고른 정점 목록이 필요해도 이 절차를 버릴 까닭은 없고, 채운 DP 테이블을 뿌리에서
아래로 한 번 더 따라가면 목록이 나와요. 반대로 가중치의 범위가 크다는 것은 이 절차의 약점이 아닙니다. 칸 수가
가중치가 아니라 **정점 수**로 정해지기 때문이에요.

#### 문제에서 이것을 떠올리게 하는 단서

- 「트리」 · 「사이클이 없는 연결 그래프」 · 「간선이 `N − 1` 개」 — 입력이 트리라는 것을 지문이 보장하는 표현입니다.
- 「직접 연결된 두 곳을 함께 고를 수 없다」 · 「상사와 바로 아래 부하를 함께 부르지 않는다」 — 바로 이어진 두
  정점에만 걸리는 제약이에요.
- 「점수의 합이 가장 크게」 — 답이 합 하나라는 신호입니다.
- 정점마다 값이 붙어 있고 **음수가 허용된다** — 빈 집합이 답이 될 수 있다는 뜻이라, `dp0` 의 시작값 0 이 그 자리를 맡습니다.

단서처럼 보여도 이 절차가 아닌 자리가 있습니다.

| 지문의 모양 | 이 절차가 아닌 까닭 | 가는 곳 |
| --- | --- | --- |
| 이웃을 피해 고르는데 일렬로 놓였다 | 자식이 하나뿐인 트리라 칸 둘을 배열 한 줄로 줄일 수 있다 | [`houseRobber`](../../array/houseRobber/houseRobber-guide.md) |
| 이웃을 피해 고르는데 사이클이 있다 | 서브트리로 가를 수 없다 | 일반 그래프의 최대 독립집합 — 정확한 빠른 방법이 알려져 있지 않다 |
| 트리에서 가장 먼 두 정점 | 칸 둘이 아니라 거리 하나를 올린다 | [`treeDiameter`](../../tree/treeDiameter/treeDiameter-guide.md) |

#### 실제로 쓰이는 곳

**일반 그래프를 다루는 라이브러리는 이 과제를 근사로만 답합니다.** NetworkX 의 `maximum_independent_set` 은 이름이

복잡도 칸이 *"TODO"* 로 비어 있어요.

### 수식 정의와 유도

파트 1 이 값으로 보인 것은 전개 입력 하나에서 칸이 맞았다는 것입니다. 여기서는 두 칸을 집합으로 정의하고, 그 정의를
전개 입력에 넣어 검산하고, 전이식과 **답이 어느 범위에 드는가**를 유도한 다음 규모 상한을 넣습니다.

```text
정의   서브트리의 독립집합 족과 두 최적값 A(v) · B(v)
검산   그 정의를 정점 일곱에 넣어 DP 테이블의 두 칸과 맞춘다
유도   족을 두 무리로 갈라 전이식을 얻고, 깊이의 홀짝에서 답의 두 경계를 닫는다
계수   두 경계에 규모 상한을 넣어 수치를 낸다
```

뿌리를 0 으로 두면 정점 $v$ 마다 서브트리 $T_v$ 가 정해집니다. 그 안에서 어느 두 원소도 간선으로 이어지지 않은 정점
집합을 모은 족을 $\mathcal{I}(v)$ 로 적어요.

$$\mathcal{I}(v) = \{\, S \subseteq T_v \;:\; \text{$S$ 의 어느 두 정점도 간선으로 이어지지 않는다} \,\}$$

이 족을 $v$ 를 담은 것과 안 담은 것으로 가르면 두 최적값이 나옵니다.

$$A(v) = \max_{S \in \mathcal{I}(v),\; v \notin S} \sum_{x \in S} w[x], \qquad B(v) = \max_{S \in \mathcal{I}(v),\; v \in S} \sum_{x \in S} w[x]$$

| 기호 | 뜻 | 코드의 이름 |
| --- | --- | --- |
| $T_v$ | 정점 $v$ 와 그 아래 정점 전부 | 배열로 안 만든다 |
| $\mathcal{I}(v)$ | $T_v$ 안의 독립집합 전부 | 안 만든다 |
| $A(v)$ | $v$ 를 안 담은 것 중 가장 큰 합 | `dp0[v]` |
| $B(v)$ | $v$ 를 담은 것 중 가장 큰 합 | `dp1[v]` |

잎 $v$ 이면 $\mathcal{I}(v) = \{\{\}, \{v\}\}$ 라 $A(v) = 0$, $B(v) = w[v]$ 입니다. 빈 집합이 $\mathcal{I}(0)$ 에 있으므로
$A(0) \ge 0$ 이에요. **정의를 값에 넣어 검산해 봅시다.** 전개 입력의 정점 일곱에 대해 서브트리의 부분집합을 전부
만들어 독립인 것만 남기고 가장 큰 합을 고른 결과입니다.

<!--proof:math-check-->

| 정점 v | 서브트리의 정점 | 정의로 센 A(v) | dp0[v] | 정의로 센 B(v) | dp1[v] |
| --- | --- | ---: | ---: | ---: | ---: |
| 0 | 0 1 2 3 4 5 6 | 15 | 15 | 22 | 22 |
| 1 | 1 3 4 | 6 | 6 | 8 | 8 |
| 2 | 2 5 6 | 7 | 7 | 2 | 2 |
| 3 | 3 | 0 | 0 | 5 | 5 |
| 4 | 4 | 0 | 0 | 1 | 1 |
| 5 | 5 6 | 4 | 4 | 7 | 7 |
| 6 | 6 | 0 | 0 | 4 | 4 |

정점 7 개 가운데 정의로 센 두 값이 DP 테이블의 두 칸과 모두 같은 정점은 7 개입니다.

<!--/proof-->

**이제 전이식을 유도합니다.** $\mathcal{I}(v)$ 에서 $v$ 를 안 담은 집합 하나를 자식 $u$ 의 서브트리마다 잘라 보면, 조각
하나하나가 $\mathcal{I}(u)$ 의 원소입니다. 거꾸로 자식마다 $\mathcal{I}(u)$ 에서 하나씩 골라 합치면 다시 $v$ 를 안 담은
독립집합이에요. 서로 다른 자식의 서브트리 사이에 간선이 없고, $v$ 는 빠져 있으니 새로 이웃이 되는 쌍이 없기 때문입니다.
그래서 합의 최댓값은 자식마다 따로 고른 최댓값의 합이고, 자식 $u$ 쪽의 최댓값은 $u$ 를 담든 안 담든이라
$\max(A(u), B(u))$ 예요. $v$ 를 담은 집합은 $v$ 와 간선으로 이어진 자식 $u$ 를 담을 수 없으니, 자식 쪽에서 $u$ 를 안 담은
최댓값 $A(u)$ 만 쓸 수 있습니다. 손자는 $v$ 와 간선으로 이어지지 않아 $A(u)$ 안에서 제한 없이 정해져요.

$$A(v) = \sum_{u \in C(v)} \max\bigl(A(u),\, B(u)\bigr), \qquad B(v) = w[v] + \sum_{u \in C(v)} A(u)$$

식을 그대로 옮긴 조각입니다. `kids[v]` 는 $C(v)$ 를 배열로 적은 것이에요.

```ts
const A = (v: number): number =>
  kids[v].reduce((s, u) => s + Math.max(A(u), B(u)), 0);
const B = (v: number): number =>
  weights[v] + kids[v].reduce((s, u) => s + A(u), 0);
```

정점 1 에서 실행하면 이렇게 나옵니다.

<!--proof:math-snippet-->

```text
A(1) = max(A(3), B(3)) + max(A(4), B(4))  = max(0, 5) + max(0, 1)  = 6
B(1) = w[1] + A(3) + A(4)                 = 8 + 0 + 0              = 8
```

**여기서 본문에 없던 것이 나옵니다.** 위 식은 답이 얼마쯤인지를 말해 주지 않아요. 가중치가 전부 1 일 때는 답의 범위를
닫을 수 있는데, 그 근거가 **깊이의 홀짝**입니다. 뿌리에서 깊이가 짝수인 정점과 홀수인 정점으로 나누면 이렇습니다.

<!--fig:math-coloring-->
![깊이가 짝수인 정점 {0, 3, 4, 5}(진한 테)과 홀수인 정점 {1, 2, 6} — 간선마다 두 무리를 하나씩 잇는다](./figs/math-coloring.svg)

간선은 언제나 부모와 자식을 잇고, 둘의 깊이는 1 차이라 홀짝이 다릅니다. 그러니 짝수 무리만 모은 집합도, 홀수 무리만
모은 집합도 그 자체로 독립집합이에요. 두 무리 중 하나는 정점의 절반 이상을 담습니다 — 두 무리의 크기 합이 $n$ 이니
둘 다 $n/2$ 보다 작을 수는 없어요. 가중치가 전부 1 이면 집합의 합이 곧 크기라서 답은 $\lceil n/2 \rceil$ 이상입니다.
위로는 $n \ge 2$ 이면 간선이 하나 이상 있고 그 양 끝을 함께 담지 못하니 $n$ 개를 다 담을 수 없어요.

$$\Bigl\lceil \tfrac{n}{2} \Bigr\rceil \;\le\; \max\bigl(A(0), B(0)\bigr) \;\le\; n - 1 \qquad (n \ge 2,\ w \equiv 1)$$

경로는 한 칸 걸러 담는 것이 최선이라 하한에서, 별은 잎을 전부 담고 가운데만 빼는 것이 최선이라 상한에서 만납니다.
**마지막으로 규모 상한을 넣습니다.** 네 모양에서 답을 실제로 재고 두 경계와 나란히 놓았습니다.

| 모양 (가중치가 전부 1) | 정점 n | 답 | 하한 ⌈n/2⌉ | 상한 n−1 |
| --- | ---: | ---: | ---: | ---: |
| 경로 | 100,000 | 50,000 | 50,000 | 99,999 |
| 별 | 100,000 | 99,999 | 50,000 | 99,999 |
| 애벌레 | 100,000 | 50,000 | 50,000 | 99,999 |
| 완전 이진 트리 (높이 15) | 65,535 | 43,690 | 32,768 | 65,534 |

네 모양 가운데 답이 두 경계 사이에 든 것은 4 개입니다.

**두 경계가 다 타이트합니다.** 경로는 하한과, 별은 상한과 정확히 같아요. 완전 이진 트리의 43,690 은 그 사이이고,
정점 수의 3 분의 2 남짓입니다.

### 불변식 — 자식을 전부 더한 정점의 dp0[v] 와 dp1[v] 는 서브트리의 두 최적값이다

파트 1 에서 코드가 동작하는 것을 열 걸음으로 확인했습니다. 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는 뜻은
아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> 정점 `v` 의 **자식을 전부 더하고 난 시점부터**, `dp0[v]` 는 `v` 를 안 담는 `v` 의 서브트리 안 독립집합 중 가장 큰
> 합이고 `dp1[v]` 는 `v` 를 담는 것 중 가장 큰 합입니다. 그리고 그 시점은 `v` 가 부모에 더해지는 걸음보다 앞입니다.

```text
자식을 전부부터    자식 하나만 더한 칸은 아직 끝값이 아니다
v 를 안 담는다     dp0[v] 는 w[v] 를 담지 않는다
v 를 담는다        dp1[v] 는 w[v] 를 반드시 담는다
서브트리 안에서    v 의 조상이나 형제는 이 두 칸과 상관이 없다
```

「자식을 전부 더하고 난 시점부터」가 중요합니다. 자식 하나만 더한 칸은 끝값이 아니에요. T5 가 끝난 직후의 DP 테이블을
그리면 이렇습니다.

<!--fig:invariant-moment-->
![T5 직후 — 정점 1 은 자식 4 하나만 더해 두 칸이 1 · 8, 자식 3 이 남아 점선 테](./figs/invariant-moment.svg)

정점 1 은 자식 4 만 더해 `dp0[1] = 1` 이고, 자식 3 이 남아 점선 테입니다. 이때의 1 은 서브트리 `{1, 3, 4}` 의 최적값이
아니라서 불변식이 말하는 대상이 아직 아니에요. 정점 1 의 두 칸이 자라는 자취와 부모가 그 칸을 읽는 자리를 나란히
적었습니다.

<!--proof:invariant-growth-->

```text
T2 시작값            dp0[1] = 0  dp1[1] = 8
T5 자식 4            dp0[1] = 1  dp1[1] = 8
T6 자식 3            dp0[1] = 6  dp1[1] = 8  자식을 전부 더했다
T8 부모 0 이 읽는다  dp0[1] = 6  dp1[1] = 8  T6 뒤로 두 칸이 안 바뀐다
```

**출발점부터 봅시다.** 잎은 자식이 없으니 「자식을 전부 더한 시점」이 곧 시작값을 적은 시점이고, `dp0 = 0` 과
`dp1 = w[v]` 는 정의 그대로예요. 그 뒤로 상태를 바꾸는 갈래는 둘입니다.

| 갈래 | 바뀌는 상태 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| `dp0[p] += max(dp0[v], dp1[v])` | 부모 `p` 의 안 고르는 칸 | `p` 를 안 담으면 `v` 쪽에서는 `v` 를 담든 안 담든 가장 큰 합을 쓸 수 있다 |
| `dp1[p] += dp0[v]` | 부모 `p` 의 고르는 칸 | `p` 를 담으면 `v` 를 담을 수 없으니 `v` 를 안 담은 가장 큰 합만 쓴다 |

두 갈래가 읽는 `dp0[v]` · `dp1[v]` 는 불변식에 따라 이미 최적값입니다. `order` 에서 `v` 의 자식은 모두 `v` 보다 뒤에
있고 `k` 를 줄이며 읽으니, `v` 가 부모에 더해지는 걸음에서 `v` 는 자식을 전부 더한 뒤예요. 그리고 `p` 의 자식을
마지막 하나까지 더하면, 수식 절의 전이식이 말하는 두 합이 정확히 `p` 의 두 칸에 쌓입니다. 경계에 있는 입력도 확인하고
갑시다.

<!--proof:invariant-edges-->

| 입력 | 처리되는 자리 | 뿌리의 두 칸 | 정본의 답 |
| --- | --- | --- | ---: |
| 정점 하나, 가중치 42 | 더하는 반복문이 한 번도 실행되지 않는다 · dp1[0] 쪽이 크다 | 0 · 42 | 42 |
| 정점 하나, 가중치 -5 | 더하는 반복문이 한 번도 실행되지 않는다 · dp0[0] 쪽이 크다 | 0 · -5 | 0 |
| 경로 0-1-2, 가중치 -1 -2 -3 | 모든 정점에서 dp0 쪽이 커서 위로 0 만 올라간다 | 0 · -1 | 0 |
| 간선 하나, 가중치 5 와 7 | 뿌리의 dp0 이 자식 1 의 dp1 을 받는다 | 7 · 5 | 7 |
| 별, 가운데 1 · 잎 5 넷 | 뿌리의 dp0 에 잎 넷의 dp1 이 모두 더해진다 | 20 · 1 | 20 |

다섯 다 따로 갈래를 두지 않고 같은 두 줄로 처리됩니다. 첫 두 줄이 「빈 집합도 후보」를 코드 어디에서 지키는지 말해
줘요 — 따로 확인하는 곳이 없고, `dp0` 의 시작값 0 과 마지막 `Math.max` 가 그 일을 합니다.

**이제 깨뜨려 봅시다.** 불변식에서 「`v` 를 담는」을 지키는 것은 `dp1` 을 갱신하는 줄입니다. 자식의 `dp0` 만 받던 그
자리에서 두 칸 중 큰 쪽을 받게 **그 줄 하나만** 바꿉니다.

```ts
dp1[p] = (dp1[p] as number) + Math.max(dp0[v] as number, dp1[v] as number); // ← (dp0[v] as number) 였다
```

<!--proof:invariant-mutant-->

| 입력 | 바른 코드 | 큰 쪽을 더한 코드 | 두 답 |
| --- | ---: | ---: | --- |
| 전개 입력(정점 일곱) | 22 | 34 | 어긋난다 |
| 경로 0-1-2, 가중치 5 1 5 | 10 | 11 | 어긋난다 |
| 경로 0-1-2-3, 가중치 10 1 1 10 | 20 | 22 | 어긋난다 |
| 별, 가운데 10 · 잎 1 넷 | 10 | 14 | 어긋난다 |
| 별, 가운데 1 · 잎 5 넷 | 20 | 21 | 어긋난다 |
| 정점 하나, 가중치 -5 | 0 | 0 | 같다 |

**오른쪽 열이 「아이디어를 떠올리는 과정」의 「값 하나만」 판과 한 줄도 안 틀리고 같습니다.** 우연이 아니에요. 이 한
줄을 바꾸면 두 칸이 같은 것을 더하게 되어 `dp1[v]` 가 언제나 `dp0[v] + w[v]` 가 되고, 두 칸 중 큰 쪽은
`dp0[v] + max(0, w[v])` 가 됩니다. 값 하나만 올린 판이 쓰던 바로 그 식이에요. 전개 입력의 정점 1 에서 따라가면
이렇습니다.

<!--proof:invariant-mutant-trace-->

```text
바꾼 코드의 dp1[1]  8 + max(0, 5) + max(0, 1) = 14
그 합에 든 정점     {1, 3, 4} — 간선 [1, 3] · [1, 4] 의 양 끝이 함께 들었다
바른 코드의 dp1[1]  8 + 0 + 0 = 8
뿌리의 답           바꾼 코드 34 · 바른 코드 22
```

정점 1 과 그 자식 3 · 4 가 한 합에 들어갑니다. 간선 `[1, 3]` 과 `[1, 4]` 가 있는데도 셋을 함께 세니, 바꾼 코드는
독립집합이 아닌 것을 세고 있어요. 칸을 둘로 둔 까닭이 이 한 줄에 있다는 것이 여기서 확인됩니다.

### 비용 계산

#### 비용을 세는 과정

이 함수는 이웃 목록을 만들고, 트리를 한 번 순회하고, 자식을 부모에 한 번씩 더합니다. 비용은 파트 1 과 같은 기본
연산으로 셉니다. 전개 입력에서 세 갈래를 따로 셌어요.

<!--proof:perf-derive-->

| 갈래 | 기본 연산 | 근거 |
| --- | ---: | --- |
| 이웃 목록에 넣기 | 12 | T1 — 간선 6 개를 양쪽 목록에 한 번씩 |
| 이웃 목록 항목 읽기 | 12 | T3 — 순회가 목록 7 개를 한 번씩 끝까지 |
| 자식을 부모에 더하기 | 6 | T4~T9 — 뿌리를 뺀 정점마다 한 번 |

세 갈래의 합은 30 번이고, 5n − 5 = 30 과 같습니다.

<!--/proof-->

T1 이 간선 여섯을 양쪽 목록에 넣어 12 번, T3 의 순회가 목록 일곱을 끝까지 읽어 12 번, T4~T9 가 자식 여섯을 더해 6
번입니다. 갈래마다 일반식을 세우면 이렇습니다.

| 갈래 | 기본 연산 | 근거 |
| --- | --- | --- |
| 이웃 목록에 넣기 | `2(n − 1)` | 간선 `n − 1` 개가 양쪽 목록에 한 번씩 들어간다 |
| 이웃 목록 항목 읽기 | `2(n − 1)` | 정점마다 한 번 꺼내 그 목록을 끝까지 읽고, 목록 길이의 합이 `2(n − 1)` 이다 |
| 자식을 부모에 더하기 | `n − 1` | 뿌리를 뺀 정점마다 한 번 |

더하기 한 번에 드는 것은 `max` 하나와 덧셈 둘이라 상수예요. 잎을 더하든 큰 서브트리를 더하든 하는 일이 같습니다.
셋을 합치면 총식이 나와요.

$$2(n-1) + 2(n-1) + (n-1) = 5n - 5$$

모양이 다른 네 입력에서 센 값과 이 식을 맞대 봤습니다.

<!--proof:perf-closed-form-->

| 입력 | 정점 n | 센 기본 연산 | 5n − 5 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 7 | 30 | 30 |
| 경로 100 정점 | 100 | 495 | 495 |
| 별 1,000 정점 | 1,000 | 4,995 | 4,995 |
| 완전 이진 트리 20,000 정점 | 20,000 | 99,995 | 99,995 |

네 입력에서 센 값과 5n − 5 의 차이를 모두 더하면 0 입니다. 정점 100,000 개에 넣으면 5n − 5 = 499,995 번이고, 메모리는 이웃 목록 2(n − 1) 칸과 배열 넷의 4n 칸을 더한 6n − 2 = 599,998 칸입니다.

<!--/proof-->

배열 넷(`dp0` · `dp1` · `order` · `parent`)을 만드는 칸 쓰기 `4n` 은 기본 연산에 넣지 않았습니다. 넣어도 `9n − 5` 라
정점 수에 비례하는 것은 같아요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (정점 하나) | `O(n)` | `Θ(n)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(n)` | `Θ(n)` |
| **최악의 경우** (규모 상한까지 채운 트리) | `O(n)` | `Θ(n)` |

**세 칸이 같은 값이라는 것이 이 절차의 성질입니다.** 입력을 보고 일찍 끝내는 자리가 없어, 어떤 트리가 와도 정확히
`5n − 5` 번이에요. 최선과 최악이 같은 값이라 입력 분포를 어떻게 잡아도 기댓값이 같고, 평균을 따로 계산할 대상이
없습니다.

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요. 같은 입력을 두 번 넣으면
반환값도 기본 연산 수도 똑같이 나옵니다. 경계의 종류로 보면 `Θ(n)` 은 상한이자 하한이에요. 답을 알려면 모든 정점의
가중치를 한 번은 봐야 하므로 그보다 적게 할 방법이 없고, 위에서 센 대로 그보다 많이 하지도 않습니다.

| 물음 | 이 절차의 답 |
| --- | --- |
| 비용이 가중치의 크기에 달렸는가 | 아니다 — 칸 수가 정점 수로 정해진다 |
| 의사다항인가 | 아니다 — [0/1 배낭](../knapsack01/knapsack01-guide.md) 처럼 용량 값에 비례하는 칸을 쓰지 않는다 |

#### 최악을 만드는 입력

「깊은 트리가 최악」이라는 통념부터 확인합시다. 정점 수를 맞춰 네 모양을 실제로 실행하고, 같은 전이식을 재귀로 적은
판의 최대 호출 깊이를 나란히 놓았습니다.

<!--proof:perf-shape-->

| 모양 (n = 20,000, 가중치 전부 1) | 정본의 기본 연산 | 재귀판의 최대 호출 깊이 | 답 |
| --- | ---: | ---: | ---: |
| 경로 | 99,995 | 20,000 | 10,000 |
| 별 | 99,995 | 2 | 19,999 |
| 완전 이진 트리 | 99,995 | 15 | 13,331 |
| 애벌레 | 99,995 | 10,001 | 10,000 |

정본의 기본 연산은 네 모양에서 1 가지 값으로 나왔습니다.

<!--/proof-->

**기본 연산 칸이 네 줄 모두 같습니다.** 통념은 이 절차에서 거짓이에요. 반복문으로 적었으므로 트리의 깊이가 비용에
들어가지 않습니다. 답은 네 줄이 다 다른데 비용은 안 갈려요. 그러니 이 절차의 최악을 만드는 조건은 모양이 아니라
**정점 수 하나**입니다. 정점을 규모 상한 100,000 개까지 채우면 어떤 모양이든 `5n − 5` 번이에요.

그런데 모양이 비용을 가르는 판이 하나 있습니다 — 재귀로 적은 판이에요. 위 표의 셋째 칸이 그 값이고, 그 판에서 최악을
만드는 입력은 **깊이가 정점 수와 같아지는 한 줄 트리**입니다. 규모 상한에서 두 판을 나란히 실행해 봤습니다.

<!--proof:perf-deep-->

| 경로, n = 100,000, 가중치 전부 1 | 결과 |
| --- | --- |
| 반복판 (이 글의 코드) | 50,000 |
| 재귀판 | RangeError 로 멈춘다 |
| 재귀판이 쌓아야 할 호출 깊이 | 100,000 |

재귀판은 답을 내기 전에 멈춥니다. 시간 복잡도에는 안 나타나는 자리인데, 규모가 `n ≤ 100,000` 이고 트리 모양에 제한이
없으니 한 줄 트리가 그대로 입력으로 들어올 수 있어요. `order` 배열로 차례를 미리 정하는 이 글의 코드가 그 위험을
없앱니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 부분집합을 전부 만드는 대신 **정점마다 칸 둘만 채웠고**, 부모를 고를
때 자식의 `dp0` 만 받아 「이웃한 두 정점을 함께 고르지 않는다」를 지켰으며, 그 결과 `2^n` 이 `5n − 5` 로 내려왔습니다.

```text
잎에서 시작한다 → order 를 뒤에서부터 읽어 자식의 두 칸을 부모에 더한다 → 뿌리의 두 칸 중 큰 쪽을 읽는다
                  └ dp0[p] 는 큰 쪽을, dp1[p] 는 dp0 만 받는다
```

먼저 답이 붙는 문제 하나입니다. T4 와 T7 에서 아래 두 칸이 정해졌어요. T7 의 `4` 는 `dp0[5]` 인데, 그 `4` 는 어떤 정점을
고른 합일까요? 그리고 정점 2 를 고르는 칸에 그 정점이 함께 들어가도 되는 이유는 무엇일까요?

<!--proof:selfcheck-state-->

```text
T4  dp0[5] = 0 + max(dp0[6], dp1[6]) = 0 + max(0, 4) = 4
T7  dp1[2] = -2 + dp0[5] = -2 + 4 = 2
```

<!--check:carryUp-->
`4` 는 정점 6 하나만 고른 합입니다. `dp0[5]` 는 「정점 5 를 안 고를 때 5 의 서브트리에서 얻는 가장 큰 합」이고, 그
서브트리에는 5 와 6 뿐이라 6 만 고른 4 가 가장 커요. 2 와 6 사이에는 정점 5 가 있어 간선으로 바로 이어져 있지
않습니다. 그래서 둘을 함께 고를 수 있어요.

정점 2 를 고르면 못 고르게 되는 것은 자식 5 하나이고, 손자 6 은 `dp0[5]` 안에서 이미 골라져 있었습니다. 그 값을 그대로
받는 것이 ⑤ 한 줄이 하는 일 전부예요. 이 입력에서는 `w[2]` 가 음수라 `dp0[2]` 가 더 커서 정점 2 가 안 골라지지만, 그것은
가중치의 부호가 정한 것이지 규칙이 정한 것이 아닙니다. 부분집합을 전부 만들어 세 칸이 뜻하는 집합을 찾으면 이렇습니다.

<!--proof:selfcheck-sets-->

```text
dp0[5] = 4  고른 정점 {6}
dp1[2] = 2  고른 정점 {2, 6}
dp0[2] = 7  고른 정점 {5} — 이쪽이 커서 정점 2 는 안 골라진다
```
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「수행으로 알아보는 알고리즘」의 T8 · T9, 「불변식」, 「수식 정의와
유도」를 다시 보세요.

- T8 에서 `dp1[0]` 이 `9 + 6 = 15` 가 되고 T9 에서 `15 + 7 = 22` 가 됐습니다. 그 `6` 과 `7` 이 각각 어떤 정점을 고른
  합인지 적어 보고, 정점 1 의 가중치를 8 에서 20 으로 바꾸면 T8 · T9 의 네 값이 어떻게 달라질지 예측해 보세요.
- 제약이 「간선으로 이어진 둘」이 아니라 「거리가 2 이하인 둘」을 함께 못 고르는 것으로 바뀌면, 불변식의 어느 낱말을
  고쳐야 하고 정점마다 칸을 몇 개 두어야 할까요.
- 가중치가 전부 1 인 트리에서 답이 `n − 1` 이 되는 모양은 별뿐일까요. 정점 다섯짜리 트리를 전부 그려 보고 답이 4 가
  나오는 것을 찾아보세요.

#### 스토리

도시 계획가 혜원은 나무 형태로 연결된 지역 네트워크에 기지국을 설치하려 한다. 기지국끼리 직접 연결된 위치에 함께 설치하면 전파 간섭이 생기므로, 인접한 두 지점에는 동시에 설치할 수 없다. 각 지점은 설치 시 얻는 커버리지 점수(가중치)가 다르며, 음수 점수인 지점은 설치하지 않는 편이 낫다.

혜원은 간섭 없이 얻을 수 있는 커버리지 점수의 합을 최대로 만들고 싶다. 아무 지점도 선택하지 않는 것도 항상 선택지로 유효하다.

#### 함수 인터페이스

```ts
export function treeMaxIndependentSet(
  n: number,
  edges: [number, number][],
  weights: number[],
): number;
```

- `n` — 노드 수 ($1 \leq n \leq 10^5$)
- `edges` — 트리의 간선 목록 (길이 $n-1$의 무방향 간선 배열, 노드 번호 $0$~$n-1$, 루트는 $0$)
- `weights` — 각 노드의 가중치 (`weights[i]`는 노드 $i$의 가중치)
- 반환 — 어떤 두 인접 노드도 동시에 포함하지 않는 부분집합 중 가중치 합의 최댓값

#### 제약 조건

- $1 \leq n \leq 10^5$
- $-10^4 \leq weights[i] \leq 10^4$
- `edges`의 길이는 $n-1$이며, 주어진 그래프는 연결된 무방향 트리이다.
- 노드 번호는 $0$부터 $n-1$까지이며 루트는 $0$이다.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

독립집합이란 어떤 두 원소도 트리 상에서 인접(간선으로 직접 연결)하지 않는 노드들의 집합이다.

빈 집합도 독립집합으로 인정하며 합은 $0$이다. 따라서 가중치가 모두 음수라면 $0$을 반환한다.

가중치가 음수인 노드는 선택하지 않는 것이 유리할 수 있다.

#### 예시

```ts
treeMaxIndependentSet(1, [], [5]);
// 5 — 단일 노드이므로 그대로 선택

treeMaxIndependentSet(1, [], [-3]);
// 0 — 음수 가중치이므로 선택하지 않는 빈 집합이 최적

treeMaxIndependentSet(3, [[0, 1], [0, 2]], [1, 2, 3]);
// 5 — 노드 1(가중치 2)과 노드 2(가중치 3)을 선택; 노드 0과 인접하지 않음

treeMaxIndependentSet(4, [[0, 1], [1, 2], [2, 3]], [10, 1, 1, 10]);
// 20 — 노드 0(10)과 노드 3(10)을 선택; 서로 인접하지 않음

treeMaxIndependentSet(3, [[0, 1], [1, 2]], [-1, -2, -3]);
// 0 — 모든 가중치가 음수이므로 아무것도 선택하지 않음
```
