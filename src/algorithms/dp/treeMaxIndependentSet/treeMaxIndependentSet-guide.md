# 트리 최대 가중 독립집합 — 값을 둘로 갈라 올려야 부모가 자식의 선택 여부를 안다

## 파트 1 — 아이디어에서 동작하는 코드까지

먼저 전체 그림을 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 부분집합을 전부 만들어 보던
방법에서 노드마다 값 둘을 적는 방법까지 갑니다. 마지막에는 그 값을 채우는 코드를 조각째로
세워 봅니다.

### 전체 컨셉

노드마다 값이 붙은 트리가 주어집니다. 간선으로 직접 이어진 두 노드를 **함께 고를 수 없다**는
조건 아래에서, 고른 노드들의 값 합을 가장 크게 만드는 것이 목표예요. 아무것도 안 고르는 것도
후보라서 답은 0 아래로 안 내려갑니다.

```text
                 0 (w=9)
                /       \
        2 (w=-2)         1 (w=8)
        |               /     \
        5 (w=7)     3 (w=5)   4 (w=1)
        |
        6 (w=4)

  간선 하나로 이어진 둘은 함께 못 고른다
  0 과 1 · 0 과 2 · 1 과 3 · 1 과 4 · 2 와 5 · 5 와 6
```

이 트리의 답은 **22** 이고, 고른 노드는 `0 · 3 · 4 · 5` 입니다. 뿌리 0 을 골랐는데도 그
손자인 3 · 4 · 5 를 함께 고를 수 있다는 점이 눈여겨볼 자리예요.

```text
  고른 노드   0(9) + 3(5) + 4(1) + 5(7) = 22
  안 고른 노드 1 · 2 · 6

  0 과 3 은 간선으로 안 이어져 있다 (사이에 1 이 있다)
  0 과 5 도 마찬가지다 (사이에 2 가 있다)
      └ 못 고르게 되는 것은 바로 옆 한 칸까지다
```

후보를 전부 만들어 보는 방법은 제약 규모에서 쓸 수 없습니다. 노드가 `n` 개면 부분집합이
`2^n` 가지라, 노드가 예순만 돼도 초 단위로 못 끝나는 수가 돼요.

```text
노드 수 n        부분집합 2^n
   7                     128
  20               1,048,576
  60            1.15 × 10^18 (초 단위로 못 끝난다)
```

**서로 다른 자식의 서브트리 사이에는 간선이 없다**는 것이 이 문제의 관찰입니다. 트리에는
사이클이 없으니, 노드 1 아래의 노드와 노드 2 아래의 노드가 이어질 방법이 없어요. 그래서 두
서브트리의 답을 따로 정해 그냥 더해도 됩니다.

```text
        0
       / \
      2   1        2 아래의 노드와 1 아래의 노드는 절대 안 이어진다
      |  / \       → 두 쪽을 따로 정하고 더하면 된다
      5 3   4
      |
      6

  걸리는 것은 부모와 자식 사이 하나뿐이다
```

남은 문제는 하나예요 — **부모가 자식의 값을 받을 때, 그 값 안에 자식이 들어 있는지를 알아야
합니다.** 값을 하나만 올려 보내면 부모는 그것을 알 수 없어서, 자기를 고르면서 자식도 함께 고른
합을 받아 버려요. 그래서 노드마다 값을 **둘로 갈라** 올립니다.

| 값 | 뜻 | 자식에게서 무엇을 받는가 |
| --- | --- | --- |
| `dp0[v]` | `v` 를 **안 고를** 때 `v` 의 서브트리에서 얻는 최대 합 | 자식의 두 값 중 큰 쪽 |
| `dp1[v]` | `v` 를 **고를** 때 `v` 의 서브트리에서 얻는 최대 합 | 자식의 `dp0` 만 |

`dp1` 이 자식의 `dp0` 만 받는 것이 「인접한 둘을 함께 고르지 않는다」를 지키는 자리 전부입니다.
그 자식의 자식은 `dp0` 안에서 이미 자유롭게 정해져 있어서, 손자는 아무 제한도 안 받아요.

```text
잎에서 시작한다        dp0 = 0            dp1 = 그 노드의 값
자식을 하나씩 더한다   dp0 += max(자식 dp0, 자식 dp1)
                       dp1 += 자식 dp0
답                     max(dp0[뿌리], dp1[뿌리])
```

노드 하나를 정하는 데 자식 수만큼의 덧셈과 견주기만 들고, 각 노드는 자기 부모에게 정확히 한
번 더해집니다. 그래서 전체 비용이 노드 수에 비례하고, 노드가 10 만 개인 제약에서도 1 초 안에
끝나요. `2^n` 이 `n` 에 비례하는 일로 내려온 것이 이 알고리즘입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **간선 목록과 이웃 목록의 차이.** 간선 목록은 `[u, v]` 쌍의 나열이고, 이웃 목록은 노드마다
  「이 노드와 이어진 노드들」을 모아 둔 배열이에요.
- **트리라는 말의 뜻.** 노드가 `n` 개, 간선이 `n-1` 개인 연결된 무방향 그래프이고 사이클이
  없습니다. 어느 노드를 뿌리로 정해도 나머지 노드마다 부모가 정확히 하나 생겨요.
- **너비 우선 순회.** 시작 노드에서 가까운 것부터 차례로 방문하는 순회입니다. 모르면
  [너비 우선 탐색 최단 경로](../../graph/bfsShortestPath/bfsShortestPath-guide.md) 를 먼저
  보세요.
- **두 수 중 큰 쪽 고르기.** 한 노드를 정하는 데 이것과 덧셈만 씁니다.

몰라도 되는 것은 재귀와 그래프 최단 경로예요. 이 글의 코드는 배열 넷과 반복문 둘로 끝납니다.
[일렬로 놓인 집에서 이웃을 피해 고르기](../../array/houseRobber/houseRobber-guide.md) 를
봤다면 같은 조건을 트리에서 다시 만나게 되는데, 거기서는 「이전 집」 하나만 보면 됐지만 여기서는
**자식이 여럿**이라 값을 모아 올리는 자리가 생깁니다.

### 아이디어 상세 — 노드마다 값 둘을 적는 표를 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function treeMaxIndependentSet(
  n: number,
  edges: [number, number][],
  weights: number[],
): number;
```

- 입력: 노드 수 `n`, 무방향 간선 목록 `edges`(길이 `n-1`), 노드별 값 `weights`. 뿌리는 노드
  0 으로 정해져 있습니다.
- 출력: **합 하나**. 어떤 노드를 골랐는지는 묻지 않아요. 아무것도 안 고르는 빈 집합도 후보라
  답이 0 아래로 안 내려갑니다.
- 제약: `n ≤ 10^5`, 값은 `-10^4` 이상 `10^4` 이하의 정수. 시간 1 초, 메모리 256 MB.

값에 음수가 섞여 있다는 것과, 트리가 **연결돼 있다**는 것이 뒤에서 각각 필요해집니다. 지금은
그냥 지나가도 됩니다.

```text
값에 음수가 섞인다     아무것도 안 고르는 것이 답이 될 수 있다
트리가 연결돼 있다     뿌리 하나에서 한 번 순회하면 모든 노드를 방문한다
간선이 n-1 개다        사이클이 없다는 말과 같다
```

이 글이 쓰는 기호는 일곱이에요. 여기서 정한 뜻을 파트 2 까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 노드 수 | `n ≤ 10^5` |
| `v` | 지금 보고 있는 노드의 번호 | `0 ≤ v < n` |
| `p` | 노드 `v` 의 부모 노드 번호 | 뿌리는 부모가 없어 `-1` |
| `w[v]` | 노드 `v` 의 값. 함수 인자로는 `weights[v]` | `-10^4 ≤ w[v] ≤ 10^4` |
| `C(v)` | 노드 `v` 의 자식 노드 집합 | 잎이면 빈 집합 |
| `dp0[v]` | `v` 를 안 고를 때 `v` 의 서브트리에서 얻는 최대 합 | 언제나 0 이상 |
| `dp1[v]` | `v` 를 고를 때 `v` 의 서브트리에서 얻는 최대 합 | 음수가 될 수 있다 |

가장 먼저 떠오르는 방법으로 시작합시다. 조건을 만족하는 부분집합 중 최댓값을 고르라고 했으니,
부분집합을 전부 만들어 조건을 확인하고 합을 재면 됩니다.

```ts
function 전부만들기(
  n: number,
  edges: [number, number][],
  weights: number[],
): number {
  let best = 0;
  for (let mask = 0; mask < 1 << n; mask++) {
    let ok = true;
    for (const [u, v] of edges) {
      if ((mask >> u) & 1 && (mask >> v) & 1) {
        ok = false; // 인접한 둘이 함께 뽑혔다
        break;
      }
    }
    if (!ok) continue;
    let sum = 0;
    for (let i = 0; i < n; i++) if ((mask >> i) & 1) sum += weights[i] as number;
    if (sum > best) best = sum;
  }
  return best;
}
```

이 방법은 **노드 하나마다 두 갈래로 갈라집니다.** 그러니 부분집합 수가 곧 일의 양이고, 노드가
하나 늘 때마다 그 수가 두 배가 돼요. 얼마나 커지는지 애벌레 모양 트리에 실제로 실행해서 세어
보고, 오른쪽 끝에 이 글의 절차가 하는 일의 수를 나란히 놓아 봅시다.

<!--proof:naiveSubsets-->

```text
노드 수 n     부분집합 2^n  그중 독립인 것    검사 횟수  이 글의 일 수
4                       16               8           70             15
8                      256              60        1,484             35
12                   4,096             448       24,184             55
16                  65,536           3,344      372,752             75
20               1,048,576          24,960    5,721,504             95
100,000    9.99 × 10^30102     세지 못했다  세지 못했다        499,995
```

노드가 넷 늘 때마다 검사 횟수가 열다섯 배에서 스무 배씩 늘고, 제약 최대인 10 만에서는 부분집합 수가
30,103 자리입니다. 오른쪽 끝의 50 만과 견주면 자릿수 자체가 달라요.

```text
노드마다 두 갈래로 갈라진다  →  부분집합이 9.99 × 10^30102 가지
                                └ 답은 합 하나인데 일의 양이 이만큼인가?
```

그러면 이 방법이 무엇을 낭비하는지 봅시다. 노드 5 와 6 만 떼어 놓고 보면, 그 둘로 만들 수 있는
조합은 네 가지뿐이고 그중 인접하지 않은 것은 셋입니다. 그런데 부분집합을 전부 만들면 나머지
다섯 노드의 조합마다 그 셋이 **다시** 나와요.

```text
노드 5 와 6 만 본 조합            나머지 다섯 노드의 조합 수
  {}        합 0                   2^5 = 32 번씩 다시 나온다
  {5}       합 7                   32 번
  {6}       합 4                   32 번
  {5,6}     인접이라 버린다        32 번

  네 조합 × 32 = 128 = 2^7      전부 만들기가 세는 것이 이 128 이다
  그런데 5 의 서브트리에서 알아야 하는 것은 위 왼쪽 넉 줄뿐이다
```

**서브트리마다 값을 몇 개 정할 것인가**로 비용이 정해집니다. 서브트리 하나에서 나올 수 있는
조합이 몇 가지든, 부모가 그 서브트리에 대해 실제로 물어보는 것은 몇 가지뿐이에요. 그 개수가
곧 일의 양이 됩니다.

```text
서브트리마다 정할 값이 두 개면      전체 2n 개
서브트리마다 정할 값이 한 개면      전체 n 개
                                    └ 어느 쪽이 맞는 답을 내는가를 먼저 재야 한다
```

같은 입력을 두 방식으로 처리해 봅시다. 왼쪽은 서브트리마다 값을 **둘** 정하는 판이고, 오른쪽은
값을 **하나**(그 서브트리에서 얻는 최댓값)만 정해 부모에게 그대로 올려 보내는 판이에요.

<!--proof:oneValue-->

```text
입력                            정본 (값 둘)  값 하나만
전개 입력 (노드 7)                        22         34
경로 0-1-2, 가중치 5 1 5                  10         11
경로 0-1-2-3, 가중치 10 1 1 10            20         22
별, 중심 10 · 잎 1 넷                     10         14
별, 중심 1 · 잎 5 넷                      20         21
노드 하나, 가중치 -5                       0          0
```

값 하나만 올린 쪽은 전개 입력에서 34 를 냈습니다. 22 보다 12 큰 값이라 답이 아니에요 — 어느
독립집합도 22 를 넘지 못하는데 34 가 나온 것은 **인접한 둘을 함께 센 합**이기 때문입니다.

```text
값 하나만 올렸을 때 노드 1 에서 벌어지는 일

  자식 3 의 최댓값 5 · 자식 4 의 최댓값 1  →  합 6
  노드 1 을 고르면 8 을 더해 14
      └ 그런데 6 안에 3 과 4 가 들어 있고, 둘 다 1 의 자식이다
        1 과 3 을 함께 고른 셈이 된다
```

**부모는 자식의 값 안에 그 자식이 들어 있는지를 알아야 합니다.** 값 하나만 받으면 그것을 알
방법이 없어요. 이것이 다음 걸음의 재료입니다.

그래서 노드마다 값을 **부모와의 관계로 갈라** 둡니다. 「이 노드를 안 골랐을 때의 최적」과
「이 노드를 골랐을 때의 최적」 둘이에요. 부모는 자기 상황에 맞는 쪽을 골라 씁니다.

```text
부모 p 를 안 고른다   자식 v 는 골라도 되고 안 골라도 된다
                      → max(dp0[v], dp1[v]) 를 받는다

부모 p 를 고른다      자식 v 는 반드시 안 고른 쪽이어야 한다
                      → dp0[v] 만 받는다
```

이 기준을 전개 입력의 노드 1 에 적용해 봅시다. 자식은 3 과 4 이고 둘 다 잎이라 값이 이미
정해져 있어요.

```text
잎 3   dp0 = 0   dp1 = 5
잎 4   dp0 = 0   dp1 = 1

노드 1 을 안 고른다  dp0[1] = max(0,5) + max(0,1) = 5 + 1 = 6
노드 1 을 고른다     dp1[1] = 8 + 0 + 0 = 8
                          └ w[1]  └ 자식 3·4 의 dp0
```

노드 2 에도 같은 기준을 적용하면 값이 음수인 노드에서 무슨 일이 일어나는지 확인됩니다. 노드 2
의 자식은 5 하나이고, 5 의 값은 `dp0 = 4 · dp1 = 7` 입니다.

```text
노드 2 를 안 고른다  dp0[2] = max(4,7) = 7
노드 2 를 고른다     dp1[2] = -2 + 4 = 2
                          └ w[2] 가 음수라 고르는 쪽이 더 작다

  음수 노드를 위한 분기를 따로 두지 않는다 — 큰 쪽을 고르는 견주기가 그것을 대신한다
```

상태 변수의 범위도 이 기준이 정합니다. 노드마다 값이 둘이므로 정할 값이 `2n` 개이고, 값
하나를 정하는 데 자식 수만큼의 덧셈이 듭니다.

```text
dp0[v]   노드마다 하나      →  전체 n 개
dp1[v]   노드마다 하나      →  전체 n 개
                              → 정할 값이 2n 개

한 값을 정하는 데 드는 것   자식 수만큼의 덧셈과 견주기
모든 노드의 자식 수를 더하면  n - 1  (뿌리를 뺀 노드마다 부모가 하나씩)
```

**상태를 이어받는 동작을 값으로 확인해 봅시다.** 쉬운 경우는 잎이에요 — 더할 자식이 없어서
시작값이 곧 확정값입니다.

```text
잎 6   dp0 = 0        아무도 안 고른 빈 서브트리
       dp1 = 4        자기 자신만 고른다
       → 자식이 없으므로 더 볼 것이 없다
```

불안한 경우는 둘입니다. **자식이 여럿인 노드**와, **자식이 아직 안 정해진 노드**예요. 앞은
자식의 기여를 빠짐없이 더해야 하는 자리이고, 뒤는 순서를 정해야 하는 자리입니다.

```text
자식이 여럿이다 (노드 1 — 자식 4 를 먼저, 자식 3 을 나중에 더한다)
  자식 4 를 더하면      dp0[1] = 1      dp1[1] = 8
  자식 3 까지 더하면    dp0[1] = 6      dp1[1] = 8
      └ 하나만 더하고 멈추면 1 이 남는다. 둘 다 더해야 6 이다

자식이 아직 안 정해졌다 (노드 2 를 노드 5 보다 먼저 보면)
  dp0[2] = max(dp0[5], dp1[5]) = max(0, 7) = 7      ← 5 의 시작값을 읽는다
  실제로는 dp0[5] = 4 라 max(4, 7) = 7 이어야 한다
      └ 이 입력에서는 우연히 같지만, 노드 6 의 값이 5 보다 컸다면 갈린다
```

왜 맞는지를 코드의 종료 조건으로 말하면, **자식이 부모보다 먼저 확정되는 순서로 읽으면** 부모를
정할 때 자식의 두 값이 이미 들어 있기 때문입니다. 뿌리에서 너비 우선으로 방문 순서를 정하면
부모가 자식보다 먼저 나오므로, 그 순서를 뒤에서부터 읽으면 자식이 먼저 옵니다.

```text
너비 우선 순서    0  2  1  5  3  4  6      부모가 자식보다 먼저
뒤에서부터        6  4  3  5  1  2         자식이 부모보다 먼저
                  └ 자식을 부모에 더하는 것은 이 순서로 한다
```

마지막으로 **노드마다 값을 몇 개 둘 것인지**를 값으로 정합니다. 하나 · 둘 · 넷 네 판을 같은
입력에 실행해 답과 칸 수와 자손을 읽은 횟수를 나란히 재 봅시다. 「값 하나, 손자까지 본다」는
자식 대신 손자에게서 「나를 고른다」 쪽을 직접 받는 판이에요.

<!--proof:stateCount-->

```text
노드마다 몇 값을 두는가                         그 판이 낸 답  상태 칸 수  자손을 읽은 횟수
전개 입력 (노드 7) — 값 하나, 자식만 본다                  34           7                 6
전개 입력 (노드 7) — 값 하나, 손자까지 본다                22           7                10
전개 입력 (노드 7) — 값 둘, 자식만 본다                    22          14                 6
전개 입력 (노드 7) — 값 넷, 자식만 본다                    22          28                16
별 (중심 1 · 잎 5 넷) — 값 하나, 자식만 본다               21           5                 4
별 (중심 1 · 잎 5 넷) — 값 하나, 손자까지 본다             20           5                 4
별 (중심 1 · 잎 5 넷) — 값 둘, 자식만 본다                 20          10                 4
별 (중심 1 · 잎 5 넷) — 값 넷, 자식만 본다                 20          20                 8
```

| 판 | 답 | 무엇을 내주는가 |
| --- | --- | --- |
| 값 하나, 자식만 | 틀린다 | — |
| 값 하나, 손자까지 | 맞다 | 칸은 절반인데 자손을 10 번 읽는다 (이웃 목록을 두 단계 걸어야 한다) |
| 값 둘, 자식만 | 맞다 | 칸이 `2n` 이고 자손은 6 번만 읽는다 |
| 값 넷, 자식만 | 맞다 | 답이 같은데 칸이 `4n` 이고 읽기가 16 번이다 |

**값 둘이 이 글의 선택입니다.** 값 하나로도 손자까지 보면 답이 맞지만 그러려면 이웃 목록을 두
단계 걸어야 하고, 값 넷은 「부모를 골랐는데 나도 고른다」는 만들 수 없는 칸을 하나 들고 있어
칸만 늘어요. 별 모양에서 「값 하나, 손자까지」가 값 둘과 읽기 횟수가 같은 것은 그 트리에 손자가
아예 없기 때문입니다.

**표 하나가 나왔습니다.** 행이 노드, 열이 두 값인 `n × 2` 짜리 표이고, 노드 7 개면 14 칸이에요.
부분집합을 전부 만들던 128 가지가 14 칸을 채우는 일이 됐습니다.

### 수행으로 알아보는 알고리즘 — 노드 일곱을 여섯 번 접어 22 를 낸다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 고정하고 조각을
하나씩 늘리되, 조각마다 그 자리까지의 표를 실행해서 확인합니다.

```ts
const n = 7;
const edges: [number, number][] = [[0, 2], [0, 1], [1, 3], [1, 4], [2, 5], [5, 6]];
const weights = [9, 8, -2, 5, 1, 7, 4];
// 이 절이 끝나면 22 가 나와야 한다 (노드 0 · 3 · 4 · 5)
```

이 입력을 왜 이렇게 뒀을까요? 넷을 한꺼번에 확인하려는 것입니다. ⑴ 노드 1 은 자식이 둘이고
노드 2 · 5 는 자식이 하나라, 자식을 모아 더하는 자리와 하나만 더하는 자리가 함께 나옵니다.
⑵ 노드 2 의 값이 음수라 「안 고르는 쪽이 더 큰」 노드가 실제로 생겨요. ⑶ 답이 뿌리와 손자
셋을 함께 고르는 모양이라 「못 고르게 되는 것은 옆 한 칸까지」가 값으로 확인됩니다. ⑷ 간선을
`[0,2]` 부터 적은 것도 그 때문인데, 그래야 방문 순서가 노드 번호와 달라져 순서 배열이 무슨
일을 하는지 표에서 보입니다.

```text
이웃 목록 adj 를 만들고, 노드마다 dp0 ← 0 · dp1 ← w[v] 로 둔다        ①

뿌리 0 에서 너비 우선으로 order 와 parent 를 채운다:
    큐에서 v 를 꺼내고, adj[v] 의 이웃 u 마다:
        u 가 v 의 부모이면 건너뛴다                                   ②
        parent[u] ← v, order 뒤에 u 를 붙인다                         ③

k 를 n-1 부터 1 까지 줄이며:
    v ← order[k],  p ← parent[v]
    dp0[p] ← dp0[p] + max(dp0[v], dp1[v])                             ④
    dp1[p] ← dp1[p] + dp0[v]                                          ⑤

max(dp0[0], dp1[0]) 을 돌려준다                                       ⑥
```

#### 1. 간선 여섯 개를 노드 일곱 개의 이웃 목록으로 옮긴다

간선 목록은 `[u, v]` 쌍의 나열이라 「노드 1 의 이웃이 누구인가」를 바로 답하지 못합니다. 무방향
간선이므로 간선 하나를 **양쪽 노드의 목록에** 넣어요.

```ts
// 이웃 목록 — 무방향이라 간선 하나를 양쪽 노드의 목록에 넣는다.
const adj: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  (adj[u] as number[]).push(v);
  (adj[v] as number[]).push(u);
}
```

T1 을 실행하면 이렇게 나옵니다. 간선을 적은 차례가 목록 안의 차례를 정해요.

```text
adj[0] = [2, 1]      간선 [0,2] 가 [0,1] 보다 먼저 적혀 있다
adj[1] = [0, 3, 4]
adj[2] = [0, 5]
adj[3] = [1]
adj[4] = [1]
adj[5] = [2, 6]
adj[6] = [5]

  목록의 길이를 다 더하면 12 = 2 × 6 = 간선 수의 두 배
```

이 목록에는 부모와 자식이 섞여 있습니다. `adj[1]` 의 `0` 은 노드 1 의 부모이고 `3` 과 `4` 는
자식인데, 목록만 봐서는 구분이 안 돼요. 그 구분을 만드는 것이 T3 입니다.

#### 2. 노드마다 두 값의 시작값을 적는다

「아이디어 상세」에서 정한 두 값을 배열 둘로 둡니다. 자식을 하나도 안 더한 시점의 값이라,
`dp0` 은 0 이고 `dp1` 은 자기 값 하나예요.

```ts
// ① 자식을 하나도 안 더한 시점의 시작값.
//    안 고르면 자기 가중치가 안 들어가고, 고르면 자기 가중치만 들어가 있다.
const dp0 = new Array<number>(n).fill(0);
const dp1 = [...weights];
```

T2 를 실행하면 표가 이렇게 깔립니다. 잎인 3 · 4 · 6 은 더할 자식이 없어 이 값이 그대로
확정값이에요.

```text
노드        안 고른다 dp0   고른다 dp1   확정인가
0 (w=9)                 0            9   아직
1 (w=8)                 0            8   아직
2 (w=-2)                0           -2   아직
3 (w=5)                 0            5   확정 (잎)
4 (w=1)                 0            1   확정 (잎)
5 (w=7)                 0            7   아직
6 (w=4)                 0            4   확정 (잎)
```

`dp1` 에 음수가 그대로 들어간다는 점이 여기서 확인됩니다. 노드 2 의 `dp1` 은 `-2` 로 시작하고,
자식을 더한 뒤에도 `dp0` 보다 작으면 마지막 견주기에서 안 골라져요.

#### 3. 뿌리에서 방문 순서와 부모를 정한다

이웃 목록에 부모와 자식이 섞여 있으니, 뿌리 0 에서 한 번 순회해 **누가 누구의 부모인지**와
**어떤 차례로 볼 것인지**를 정합니다. 큐를 따로 만들지 않고 순서 배열 자체를 큐로 씁니다.

```ts
// 뿌리 0 에서 너비 우선으로 방문 순서와 부모를 정한다.
const order = new Array<number>(n).fill(0);
const parent = new Array<number>(n).fill(-1);
let tail = 1;
for (let head = 0; head < tail; head++) {
  const v = order[head] as number;
  for (const u of adj[v] as number[]) {
    // ② 부모 쪽 간선은 건너뛴다 — 그쪽은 이미 지나온 자리다.
    if (u === parent[v]) continue;
    parent[u] = v;
    // ③ 자식을 순서 배열의 뒤에 붙인다.
    order[tail] = u;
    tail++;
  }
}
```

T3 을 실행하면 순서와 부모가 이렇게 정해집니다. `head` 가 앞에서 읽고 `tail` 이 뒤에 붙이니
배열 하나가 큐 노릇을 해요.

```text
head  꺼낸 v  adj[v]     ② 로 건너뛴 것  ③ 으로 붙인 것   order
 0        0   [2, 1]     없음 (뿌리)      2, 1             0 2 1
 1        2   [0, 5]     0                5                0 2 1 5
 2        1   [0, 3, 4]  0                3, 4             0 2 1 5 3 4
 3        5   [2, 6]     2                6                0 2 1 5 3 4 6
 4        3   [1]        1                없음             그대로
 5        4   [1]        1                없음             그대로
 6        6   [5]        5                없음             그대로

  parent = [-1, 0, 0, 1, 1, 2, 5]      뿌리만 -1 이다
```

②가 없으면 이 순회가 끝나지 않습니다. 노드 1 에서 이웃 `0` 을 자식으로 붙이면 0 이 순서 배열에
다시 들어가고, 그 0 이 또 1 과 2 를 붙여요. 부모 쪽 간선 하나를 건너뛰는 것만으로 무방향
그래프에서 방향이 생깁니다.

#### 짚고 가기 — 순서를 뒤집지 않고 앞에서부터 더하면 시작값만 더해진다

자식을 부모에 더하는 일은 어차피 노드마다 한 번씩이니 순서는 상관없어 보입니다. 순서 배열을
앞에서부터 읽어도 같은 노드를 같은 횟수만큼 더하니까요. 그대로 두고 실행해 봅시다.

```ts
// 뒤에서부터가 아니라 앞에서부터 읽는다
for (let k = 1; k < n; k++) {
  const v = order[k] as number;
  const p = parent[v] as number;
  dp0[p] = (dp0[p] as number) + Math.max(dp0[v] as number, dp1[v] as number);
  dp1[p] = (dp1[p] as number) + (dp0[v] as number);
}
```

<!--proof:orderMutant-->

```text
입력                            정본  앞에서부터 더한 판
전개 입력 (노드 7)                22                   9
경로 0-1-2, 가중치 5 1 5          10                   5
경로 0-1-2-3, 가중치 10 1 1 10    20                  10
별, 중심 10 · 잎 1 넷             10                  10
별, 중심 1 · 잎 5 넷              20                  20
노드 하나, 가중치 -5               0                   0
```

**아래 셋에서는 답이 맞았습니다.** 별 모양은 잎이 전부 뿌리의 자식이라, 앞에서부터 읽어도
자식이 이미 확정된 잎이에요. 노드가 하나뿐인 입력도 더할 것이 없습니다. 그래서 별과 잎만으로
테스트를 짜면 이 잘못이 통과합니다.

```text
전개 입력에서 앞에서부터 읽으면

  k=1  v=2 → 부모 0    dp0[0] += max(0, -2) = 0     ← 노드 2 의 시작값을 읽었다
                       실제 확정값은 dp0[2] = 7 이다
  k=2  v=1 → 부모 0    dp0[0] += max(0, 8) = 8
                       실제 확정값은 dp0[1] = 6 · dp1[1] = 8
  k=3  v=5 → 부모 2    이제야 노드 2 가 갱신되는데 뿌리는 이미 읽고 지나갔다

  답 9 = max(dp0[0], dp1[0]) = max(8, 9)
```

**뒤에서부터 읽어야 하는 이유가 여기 있습니다.** 너비 우선 순서는 부모가 자식보다 먼저 나오도록
만든 것이라, 그것을 뒤집으면 자식이 부모보다 먼저 옵니다. 깊이가 1 인 트리(별)에서는 뒤집으나
마나 같지만 깊이가 2 이상이면 갈려요.

#### 4. 순서를 뒤에서부터 읽어 여섯 번 더한다

이제 자식을 부모에 더합니다. 갈래는 둘뿐이에요 — 부모를 안 고르면 자식의 두 값 중 큰 쪽을,
부모를 고르면 자식의 `dp0` 만 받습니다.

```ts
// 순서를 뒤에서부터 읽으면 자식이 부모보다 먼저 온다.
for (let k = n - 1; k >= 1; k--) {
  const v = order[k] as number;
  const p = parent[v] as number;
  // ④ 부모를 안 고르면 자식은 두 값 중 큰 쪽을 쓴다.
  dp0[p] = (dp0[p] as number) + Math.max(dp0[v] as number, dp1[v] as number);
  // ⑤ 부모를 고르면 자식은 안 고르는 값만 쓸 수 있다.
  dp1[p] = (dp1[p] as number) + (dp0[v] as number);
}
```

T4 부터 T9 까지 여섯 번 더한 자취입니다. 각 줄의 마지막 두 칸은 **그 걸음이 끝난 뒤 부모의 두
값**이에요.

#### 5. 뿌리의 두 값 중 큰 쪽을 돌려준다

표가 다 채워졌으니 뿌리 한 줄만 읽으면 됩니다. 뿌리는 부모가 없으니 두 갈래 중 아무 쪽이나
고를 수 있어요.

```ts
// ⑥ 빈 집합도 독립집합이라 dp0[0] 이 0 아래로 안 내려간다.
return Math.max(dp0[0] as number, dp1[0] as number);
```

T10 을 실행하면 22 가 나옵니다. `dp0[0]` 이 15 이고 `dp1[0]` 이 22 이니 뿌리를 고르는 쪽이 더
커요.

```text
dp1[0] = 22    노드 0 · 3 · 4 · 5 를 고른다     9 + 5 + 1 + 7
dp0[0] = 15    노드 1 · 5 를 고른다             8 + 7
               → 큰 쪽인 22 를 돌려준다  ⑥
```

⑥의 견주기가 **빈 집합도 답이 되게** 합니다. `dp0[0]` 은 자식의 두 값 중 큰 쪽을 더한 것이고 그
큰 쪽은 잎에서 `max(0, w)` 로 시작하므로 0 아래로 안 내려가요. 값이 전부 음수인 입력에서 답이
0 이 되는 것이 그 결과입니다.

#### 짚고 가기 — 뿌리를 고르면 손자까지 못 고른다는 오해

노드 0 을 고르면 자식 1 과 2 를 못 고릅니다. 그러면 그 아래인 3 · 4 · 5 도 못 고르게 되는 것
아닐까요? 「고른 노드 주변은 비워야 한다」고 읽으면 자연스러운 생각이에요. 그 오해대로 전개하면
자식의 서브트리에서 **손자 아래만** 쓰게 됩니다.

```ts
  //                                              그 아래만 더한다
```

부모를 고를 때 자식의 `dp0` 을 받는데, 그 `dp0` 안에서 손자들은 이미 자유롭게 정해져 있습니다.
손자를 한 번 더 제외하는 코드가 어디에도 없다는 것이 이 성질을 그대로 말해 줍니다.

#### 6. 전체 코드

조각 다섯을 한 함수로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 없어요 — 조각의 순서를
그대로 이어 붙인 것이 전체 코드입니다.

```ts
export function treeMaxIndependentSet(
  n: number,
  edges: [number, number][],
  weights: number[],
): number {
  // 이웃 목록 — 무방향이라 간선 하나를 양쪽 노드의 목록에 넣는다.
  const adj: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    (adj[u] as number[]).push(v);
    (adj[v] as number[]).push(u);
  }

  // ① 자식을 하나도 안 더한 시점의 시작값.
  //    안 고르면 자기 가중치가 안 들어가고, 고르면 자기 가중치만 들어가 있다.
  const dp0 = new Array<number>(n).fill(0);
  const dp1 = [...weights];

  // 뿌리 0 에서 너비 우선으로 방문 순서와 부모를 정한다.
  const order = new Array<number>(n).fill(0);
  const parent = new Array<number>(n).fill(-1);
  let tail = 1;
  for (let head = 0; head < tail; head++) {
    const v = order[head] as number;
    for (const u of adj[v] as number[]) {
      // ② 부모 쪽 간선은 건너뛴다 — 그쪽은 이미 지나온 자리다.
      if (u === parent[v]) continue;
      parent[u] = v;
      // ③ 자식을 순서 배열의 뒤에 붙인다.
      order[tail] = u;
      tail++;
    }
  }

  // 순서를 뒤에서부터 읽으면 자식이 부모보다 먼저 온다.
  for (let k = n - 1; k >= 1; k--) {
    const v = order[k] as number;
    const p = parent[v] as number;
    // ④ 부모를 안 고르면 자식은 두 값 중 큰 쪽을 쓴다.
    dp0[p] = (dp0[p] as number) + Math.max(dp0[v] as number, dp1[v] as number);
    // ⑤ 부모를 고르면 자식은 안 고르는 값만 쓸 수 있다.
    dp1[p] = (dp1[p] as number) + (dp0[v] as number);
  }

  // ⑥ 빈 집합도 독립집합이라 dp0[0] 이 0 아래로 안 내려간다.
  return Math.max(dp0[0] as number, dp1[0] as number);
}
```

실행하면 이렇게 나옵니다.

### 알아 두면 좋은 개념 — 최소 가중 정점 덮개

전개 입력에서 고른 노드는 `0 · 3 · 4 · 5` 였고 남은 노드는 `1 · 2 · 6` 이었습니다. 남은 쪽을
따로 보면 성질 하나가 확인돼요 — **모든 간선이 남은 쪽 노드를 적어도 하나 끝점으로 갖습니다.**

```text
간선        끝점 둘        남은 쪽(1 · 2 · 6)에 속한 끝점
[0, 1]      0  1           1
[0, 2]      0  2           2
[1, 3]      1  3           1
[1, 4]      1  4           1
[2, 5]      2  5           2
[5, 6]      5  6           6
                           └ 여섯 간선 전부가 남은 쪽 노드로 덮인다
```

이렇게 **모든 간선의 끝점 중 적어도 하나를 담는 노드 집합**을 정점 덮개라고 부르고, 그 값의 합을
가장 작게 만드는 것을 최소 가중 정점 덮개라고 합니다. 고른 쪽과 남은 쪽은 언제나 이 관계로 짝을
이뤄요 — 고른 쪽이 독립집합이면 남은 쪽은 덮개이고, 그 반대도 같습니다.

<!--proof:vertexCover-->

```text
입력                   전체 합 W  고른 쪽 (답)  남은 쪽 W − 답
전개 입력 (노드 7)            32            22              10
경로 0-1-2-3                  22            20               2
별, 중심 10 · 잎 1 넷         14            10               4
경로 0-1-2, 3 10 3            16            10               6
```

전체 합에서 답을 빼면 최소 가중 정점 덮개가 나옵니다. 이 이름을 알아 두면 다른 자리에서 같은
것을 알아보게 돼요 — 이분 그래프에서 최소 정점 덮개의 크기가 최대 매칭의 크기와 같다는 쾨니그
정리가 이 관계 위에서 성립하고, 일반 그래프에서 정점 덮개를 2 배 안쪽으로 근사하는 절차도 같은
대상을 다룹니다.

**여집합 관계는 대조가 아닙니다.** 같은 답을 두 이름으로 부르는 것이라, 한쪽을 풀면 다른 쪽이
뺄셈 하나로 나와요. 두 문제 중 어느 것을 풀지는 선택의 자리가 아닙니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 이 세운 것을 네 각도에서 따집니다. 이 절차를 부르는 자리는 어떤 모양인지, 두 값의
집합 정의에서 전이식과 답의 범위가 어떻게 나오는지, 자식을 다 더한 시점에 무엇이 참인지,
그리고 노드 10 만에서 하는 일이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- 입력이 **트리**입니다. 사이클이 하나라도 있으면 「서로 다른 자식의 서브트리 사이에 간선이
  없다」가 성립하지 않아, 자식의 값을 더하는 것만으로 답이 안 나옵니다.
- 제약이 **바로 옆 한 칸**에만 걸립니다. 「거리 2 이내를 함께 못 고른다」로 바뀌면 부모가
  받아야 하는 값이 둘로 안 끝나요.
- 각 노드의 상태가 **몇 가지로 셀 수 있습니다.** 여기서는 고른다와 안 고른다 둘이에요.
- 답이 **합 하나**입니다. 어떤 노드를 골랐는지까지 물으면 값과 함께 선택을 거슬러 확인할
  자취를 더 적어야 합니다.

```text
네 조건이 코드의 모양을 그대로 정한다
  트리          →  뿌리를 잡고 부모·자식으로 방향을 준다
  옆 한 칸      →  값이 둘, 그중 하나만 제한을 받는다
  상태가 둘     →  배열 두 개
  합 하나       →  표를 다 채우고 뿌리 한 줄만 읽는다
```

노드가 `10^5` 이면 하는 일이 50 만 번 남짓이라 1 초 안에 끝납니다. 값이 실수여도, 값의 범위가
아무리 커도 비용이 안 바뀌어요 — 표의 크기가 값이 아니라 **노드 수**로 정해지기 때문입니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "트리"  "사이클이 없는 연결 그래프"  "간선이 n-1 개"
  "인접한 두 노드를 동시에 선택할 수 없다"  "직접 연결된 곳에는 함께 둘 수 없다"
  "상사와 부하를 함께 부르지 않는다"  "간섭이 생긴다"
  "합을 최대로"  "점수의 합이 가장 큰"

제약에 이런 모양이 보이면
  노드 수가 10^5 안팎이고 간선이 노드 수 -1 개   ← 트리라는 신호
  노드마다 값이 붙어 있고 음수가 허용된다        ← 빈 집합이 답이 될 수 있다
```

같은 조건이 **일렬**로 놓이면 이전 한 칸만 보면 되는
[일렬로 놓인 집에서 이웃을 피해 고르기](../../array/houseRobber/houseRobber-guide.md) 이고,
그래프가 트리가 아니면 이 절차가 안 통합니다. 트리 위에서 자식의 값을 모아 부모를 정하는 이
모양은 [트리의 지름](../../tree/treeDiameter/treeDiameter-guide.md) 과 같은 순회 뼈대를 쓰되,
노드마다 들고 올라가는 값이 다릅니다.

| 무엇을 묻는가 | 입력의 모양 | 노드마다 드는 값 |
| --- | --- | --- |
| 인접하지 않게 골라 합 최대 (이 글) | 트리 | 고른다 · 안 고른다 두 값 |
| 이웃하지 않게 골라 합 최대 | 일렬 | 같은 두 값, 자식이 하나뿐 |
| 가장 먼 두 노드 사이의 거리 | 트리 | 거리 하나 |
| 순서를 지키며 전부 나열 | 방향 그래프 | 진입 차수 하나 |

#### 실제로 쓰이는 곳

**일반 그래프를 다루는 라이브러리는 이 문제를 근사로만 답합니다.** NetworkX 의
`maximum_independent_set` 은 이름이 `networkx.algorithms.approximation.clique` 아래 있고,

```text
igraph       igraph_independence_number 가 있는데 역시 가중치를 안 받고,
```

### 수식 정의와 유도

두 값을 집합으로 정의하고, 그 정의를 전개 입력에 넣어 검산하고, 두 가지를 유도한 다음 제약
규모를 넣습니다. 유도 하나는 전이식이고, 다른 하나는 **답이 어느 범위에 들어가는가**예요.

```text
정의   서브트리의 독립집합 족과 두 최적값 A(v) · B(v)
  ↓
검산   그 정의를 노드 일곱에 전부 넣어 표의 값과 맞춘다
  ↓
유도   ① 독립집합 족을 두 무리로 갈라 전이식을 얻는다
       ② 트리가 2색으로 칠해진다는 것에서 답의 하한과 상한을 닫는다
  ↓
계수   그 두 경계에 제약 규모를 넣어 수치를 낸다
```

**먼저 집합입니다.** 뿌리를 0 으로 고정하면 노드 $v$ 마다 서브트리 $T_v$ 가 정해집니다. 그
서브트리 안에서 어느 두 원소도 간선으로 안 이어진 노드 집합을 모은 족을 $\mathcal{I}(v)$ 로
적어요.

$$\mathcal{I}(v) = \{\, S \subseteq T_v \;:\; \text{$S$ 의 어느 두 노드도 간선으로 이어지지 않는다} \,\}$$

```text
이 족을 v 를 담은 것과 안 담은 것으로 가른다

  v ∉ S 인 것만 모아 최댓값을 고른다   →  A(v)
  v ∈ S 인 것만 모아 최댓값을 고른다   →  B(v)
      └ 두 무리를 합치면 I(v) 이고 서로 겹치는 원소가 없다
```

$$A(v) = \max_{S \in \mathcal{I}(v),\; v \notin S} \sum_{x \in S} w[x], \qquad B(v) = \max_{S \in \mathcal{I}(v),\; v \in S} \sum_{x \in S} w[x]$$

| 기호 | 뜻 | 코드의 이름 |
| --- | --- | --- |
| $T_v$ | 노드 $v$ 와 그 아래 노드 전부 | 배열로 안 만든다 |
| $\mathcal{I}(v)$ | $T_v$ 안의 독립집합 전부 | 안 만든다 |
| $A(v)$ | $v$ 를 안 담은 것 중 최대 합 | `dp0[v]` |
| $B(v)$ | $v$ 를 담은 것 중 최대 합 | `dp1[v]` |

```text
경계  잎 v 이면 I(v) = { {}, {v} }        A(v) = 0        B(v) = w[v]
답    max(A(0), B(0))                     빈 집합이 I(0) 에 있으므로 A(0) ≥ 0
```

**정의를 값에 넣어 검산해 봅시다.** 전개 입력의 노드 일곱에 대해 서브트리의 부분집합을 전부
만들어 독립인 것만 남기고 최댓값을 고른 결과입니다.

<!--proof:subtreeCheck-->

```text
노드 v  서브트리 노드  정의로 센 A(v)  표의 dp0  정의로 센 B(v)  표의 dp1
0       0 1 2 3 4 5 6              15        15              22        22
1               1 3 4               6         6               8         8
2               2 5 6               7         7               2         2
3                   3               0         0               5         5
4                   4               0         0               1         1
5                 5 6               4         4               7         7
6                   6               0         0               4         4
```

일곱 줄이 전부 같습니다. 파트 1 의 표가 이 정의를 칸으로 적은 것이라는 뜻이에요.

**이제 전이식을 유도합니다.** $\mathcal{I}(v)$ 에서 $v$ 를 안 담은 것만 모으면, 남는 것은 각
자식 $u$ 의 서브트리에서 고른 독립집합들의 합집합입니다. 서로 다른 자식의 서브트리 사이에 간선이
없으므로 어느 조합을 골라도 다시 독립집합이고, 그래서 자식마다 따로 최댓값을 골라 더할 수
있어요.

```text
v 를 안 담는다
  자식 u 의 서브트리에서 고른 것은 u 를 담아도 되고 안 담아도 된다
  → 자식마다 max(A(u), B(u))
  두 자식의 선택이 서로의 범위를 바꾸지 않으므로 그대로 더한다

v 를 담는다
  자식 u 는 v 와 간선으로 이어져 있으므로 담을 수 없다
  → 자식마다 A(u)
  손자는 v 와 간선으로 안 이어져 있어 A(u) 안에서 자유롭다
```

두 경우가 $\mathcal{I}(v)$ 를 남김없이 가르므로 아래 두 식이 나옵니다.

$$A(v) = \sum_{u \in C(v)} \max\bigl(A(u),\, B(u)\bigr), \qquad B(v) = w[v] + \sum_{u \in C(v)} A(u)$$

```ts
// 식을 그대로 옮긴 조각. 전개 입력의 노드 1 을 계산한다.
const A = (v: number): number =>
  (kids[v] as number[]).reduce((s, u) => s + Math.max(A(u), B(u)), 0);
const B = (v: number): number =>
  (weights[v] as number) + (kids[v] as number[]).reduce((s, u) => s + A(u), 0);

A(1); // max(A(3), B(3)) + max(A(4), B(4)) = max(0,5) + max(0,1) = 6
B(1); // 8 + A(3) + A(4) = 8 + 0 + 0 = 8
```

**여기서 본문에 없던 것이 나옵니다.** 위 식은 답이 얼마쯤인지를 말해 주지 않아요. 값이 전부 1
일 때는 답의 범위를 닫을 수 있는데, 그 근거가 **트리는 2색으로 칠해진다**는 것입니다.

```text
뿌리에서 깊이가 짝수인 노드를 검정, 홀수인 노드를 흰색으로 칠한다

  깊이 0        0                    검정
  깊이 1     2     1                 흰색
  깊이 2     5   3   4               검정
  깊이 3     6                       흰색

  간선은 언제나 깊이가 1 다른 두 노드를 잇는다 → 양 끝의 색이 다르다
  → 검정만 모은 집합도, 흰색만 모은 집합도 그 자체로 독립집합이다
```

두 색 중 하나는 노드의 절반 이상을 담습니다. 값이 전부 1 이면 그 집합의 합이 곧 크기이므로,
답은 $\lceil n/2 \rceil$ 이상이에요. 위로는 $n$ 개를 다 담을 수 없다는 것이 상한을 줍니다 —
$n \ge 2$ 이면 간선이 하나라도 있고 그 양 끝을 함께 담지 못하니까요.

$$\Bigl\lceil \tfrac{n}{2} \Bigr\rceil \;\le\; \max\bigl(A(0), B(0)\bigr) \;\le\; n - 1 \qquad (n \ge 2,\ w \equiv 1)$$

```text
두 경계가 각각 어느 모양에서 만나는가

  경로   한 칸 걸러 담는 것이 최선이다     ⌈n/2⌉ 에서 하한과 만난다
  별     잎을 전부 담으면 뿌리만 빠진다    n − 1 에서 상한과 만난다
```

**마지막으로 계수입니다.** 제약 상한에 가까운 크기에서 네 모양의 답을 실제로 재고 두 경계와
나란히 놓아 봅시다.

<!--proof:boundValues-->

```text
모양 (가중치가 전부 1)    노드 수 n      답  하한 ⌈n/2⌉  상한 n−1
경로                        100,000  50,000      50,000    99,999
별                          100,000  99,999      50,000    99,999
애벌레                      100,000  50,000      50,000    99,999
완전 이진 트리 (높이 15)     65,535  43,690      32,768    65,534
```

**두 경계가 다 타이트합니다.** 경로는 하한을 정확히 달성하고 별은 상한을 정확히 달성해요. 가운데
두 줄은 그 사이이고, 완전 이진 트리의 43,690 은 노드 수의 3 분의 2 남짓입니다 — 잎과 그
할아버지 층을 번갈아 담은 결과예요.

### 불변식 — 자식을 전부 더한 시점의 `dp0[v]` 와 `dp1[v]` 는 서브트리의 두 최적값이다

파트 1 에서 코드가 동작하는 것을 열 단계로 봤습니다. 그것은 노드 일곱짜리 입력 하나에서 맞았다는
뜻이지 어떤 트리에서도 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> 노드 `v` 의 **자식을 전부 더하고 난 시점**에, `dp0[v]` 는 `v` 를 안 담는 독립집합 중 최대
> 합이고 `dp1[v]` 는 `v` 를 담는 독립집합 중 최대 합입니다. 둘 다 `v` 의 서브트리 안에서만
> 고른 것이에요.

```text
자식을 전부      자식 하나만 더한 시점은 확정이 아니다 (T5 의 dp0[1] = 1 이 그것이다)
v 를 안 담는다   dp0 은 v 의 값을 절대 안 담는다
v 를 담는다      dp1 은 v 의 값을 반드시 담는다
서브트리 안에서  v 의 조상이나 형제는 이 값과 무관하다
```

「자식을 전부 더하고 난 시점」이라 적은 것이 이 알고리즘에서 중요합니다. 순서 배열을 뒤에서부터
읽으면 노드 `v` 가 부모에게 더해지는 시점보다 **먼저** `v` 의 자식이 전부 처리되기 때문에, 부모가
읽는 값은 언제나 확정값이에요.

```text
뒤에서부터 읽는다   order = [0, 2, 1, 5, 3, 4, 6] 을 6 → 1 로

  v 가 order 의 k 자리에 있으면 v 의 자식은 전부 k 보다 뒤에 있다
      └ 너비 우선이 부모를 자식보다 앞에 놓았기 때문
  k 를 줄이며 읽으면 자식이 v 보다 먼저 처리된다
```

**출발점부터 봅시다.** 잎은 자식이 없으니 「자식을 전부 더한 시점」이 곧 시작값을 적은 시점이고,
`dp0 = 0` 과 `dp1 = w[v]` 는 정의 그대로예요. 그 뒤로 자식 하나가 더해질 때마다 두 값이 각각
어떤 뜻을 이어받는지는 아래와 같습니다.

| 갱신하는 줄 | 읽는 자리 | 그 값이 뜻하는 것 |
| --- | --- | --- |
| `dp0[p] += max(dp0[v], dp1[v])` | 자식 `v` 의 두 값 | `p` 를 안 담으므로 `v` 는 담아도 되고 안 담아도 된다 |
| `dp1[p] += dp0[v]` | 자식 `v` 의 `dp0` | `p` 를 담으므로 `v` 는 담을 수 없다 |

둘째 줄이 이 불변식과 맞물리는 자리입니다. `dp0[v]` 는 「`v` 를 안 담는」 최적이라 거기에 `p` 를
더해도 `p` 와 `v` 가 함께 담기지 않아요. 거꾸로 `p` 를 담는 어떤 독립집합도 자식을 안 담으므로
빠지는 것도 없습니다.

```text
전개 입력에서 노드 1 의 두 값이 자라는 자취

  시작값       dp0[1] = 0      dp1[1] = 8
  T5 자식 4    dp0[1] = 1      dp1[1] = 8      max(0,1) 과 +0
  T6 자식 3    dp0[1] = 6      dp1[1] = 8      max(0,5) 와 +0
       └ 여기서 확정. 이 뒤로 노드 1 의 값은 안 바뀐다
  T8 에서 부모 0 이 이 확정값을 읽는다
```

경계에 있는 입력들도 확인하고 갑시다.

| 경계 입력 | 두 배열에서 벌어지는 일 | 반환 |
| --- | --- | --- |
| 노드 하나, 값 42 | 순서 배열이 한 칸이라 더하는 반복문이 한 번도 실행되지 않는다 | `42` |
| 노드 하나, 값 -5 | 같음. `dp0[0] = 0` 이 `dp1[0] = -5` 보다 크다 | `0` |
| 값이 전부 음수 | 모든 노드에서 `dp0` 이 `dp1` 보다 커서 위로 0 만 올라간다 | `0` |
| 간선 하나, 값 5 와 7 | `dp0[0] = 7`, `dp1[0] = 5 + 0` | `7` |
| 잎이 넷인 별, 잎이 전부 5 | `dp0[0] = 20`, `dp1[0] = 1 + 0` | `20` |
| 값이 같은 두 후보 | 견주기가 `Math.max` 라 어느 쪽을 골라도 합이 같다 | 갈리지 않는다 |

여섯 다 특별 분기 없이 같은 두 줄로 처리됩니다. 첫 두 줄이 「빈 집합도 후보」를 코드 어디에서
지키는지 말해 줘요 — 따로 확인하는 곳이 없고, `dp0` 의 시작값 0 과 마지막 견주기가 그 일을
합니다.

**이제 깨뜨려 봅시다.** 불변식에서 「`v` 를 담는」을 지키는 것은 `dp1` 을 갱신하는 줄입니다.
자식의 `dp0` 만 받던 그 자리에서 두 값 중 큰 쪽을 받게 바꿉니다.

```ts
dp1[p] = (dp1[p] as number) + Math.max(dp0[v] as number, dp1[v] as number);
//                            ~~~~~~~~~ (dp0[v] as number) 였다
```

<!--proof:invariantMutant-->

```text
입력                            바른 코드  큰 쪽을 더한 코드
전개 입력 (노드 7)                     22                 34
경로 0-1-2, 가중치 5 1 5               10                 11
경로 0-1-2-3, 가중치 10 1 1 10         20                 22
별, 중심 10 · 잎 1 넷                  10                 14
별, 중심 1 · 잎 5 넷                   20                 21
노드 하나, 가중치 -5                    0                  0
```

**오른쪽 열이 파트 1 의 「값 하나만 올린 판」과 글자 하나 안 틀리고 같습니다.** 우연이 아니에요 —
이 한 줄을 바꾸면 `dp1[v]` 가 `dp0[v] + w[v]` 로 굳어져서, 두 값 중 큰 쪽이 언제나
`dp0[v] + max(0, w[v])` 가 됩니다. 파트 1 의 「값 하나」 판이 쓰던 바로 그 식이에요. 값 둘을
든 이유가 이 한 줄에 있다는 것이 여기서 확인됩니다.

```text
전개 입력에서 34 가 나오는 자리

  바뀐 코드   dp1[1] = 8 + max(0,5) + max(0,1) = 14
              → 노드 1 과 그 자식 3 · 4 를 함께 담은 합이다
  간선 [1,3] 과 [1,4] 가 있는데도 셋이 한 답에 들어간다
              → 독립집합이 아닌 것을 세고 있다
```

### 비용 계산

#### 비용을 세는 과정

이 함수는 배열을 한 벌 만들고 트리를 두 번 지나갑니다. 셋을 각각 세어 더한 것이 총식이에요.

| 지나가는 자리 | 몇 번인가 |
| --- | --- |
| 이웃 목록 만들기 | 간선마다 두 번 넣는다 — `2(n-1)` 번 |
| 순서와 부모 정하기 | 노드마다 이웃 목록을 한 번씩 걸으므로 목록 길이의 합인 `2(n-1)` 번. T3 이 그 자취다 |
| 자식을 부모에 더하기 | 뿌리를 뺀 노드마다 한 번 — `n-1` 번. T4 부터 T9 가 그 여섯이다 |

한 번 더하는 데 드는 것은 견주기 하나와 덧셈 둘이라 상수예요. T4 처럼 잎을 더하든 T9 처럼 값이
큰 서브트리를 더하든 하는 일이 같아서, 입력이 바뀌어도 한 번당 비용이 안 바뀝니다.

```text
총식 = O(n) + O(2(n-1)) + O(2(n-1)) + O(n-1)  =  Θ(n)
        ↑ 배열 넷 할당   ↑ 목록 만들기 ↑ 순회   ↑ 더하기

n = 10^5  →  2(n-1) + 2(n-1) + (n-1) = 499,995 번
```

메모리도 노드 수에 비례합니다 — 이웃 목록이 `2(n-1)` 칸이고 `dp0`·`dp1`·`order`·`parent` 가
각각 `n` 칸이라 다 합쳐 `6n - 2` 칸이에요. 답만 필요하면 `order` 를 만들지 않고 재귀로 같은
순서를 낼 수 있는데, 그때 잃는 것은 최악 보장입니다 — 다음 절에서 값으로 봅니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (별 모양이라 깊이가 1 이다) | `O(n)` | `Θ(n)` |
| **평균적인 경우** (트리를 아무렇게나 뽑아도) | `O(n)` | `Θ(n)` |
| **최악의 경우** (어떤 트리든) | `O(n)` | `Θ(n)` |

**세 줄이 같습니다.** 이 절차는 입력을 보고 일찍 끝내는 자리가 없어 모든 노드와 모든 간선을
정확히 정해진 횟수만큼 봅니다. 이웃 목록의 길이 합이 언제나 `2(n-1)` 인 것이 그 이유이고, 트리의
모양은 그 합을 안 바꿔요.

**이 값은 최악 보장이지 기대값이 아닙니다.** 코드 어디에도 무작위로 고르는 자리가 없고, 트리를
어떤 분포에서 뽑았는지도 안 씁니다. 그래서 「평균」 줄의 `Θ(n)` 은 여러 입력에 걸친 평균값이
아니라 **트리를 하나 정하면 그 트리에서 언제나 나오는 값**이에요. 같은 입력을 백 번 실행해도
더한 횟수가 백 번 다 같습니다.

```text
n 은 입력의 "크기" 그대로다 — 값이 아니다

  값이 10^4 이든 10^18 이든 표의 칸 수가 안 바뀐다
  간선 수도 n-1 로 고정이라 따로 세는 항이 없다
      └ 표의 크기가 값에 달린 표 채우기(배낭 · 부분집합 합)와 갈리는 자리다
```

그래서 이 절차는 **의사다항이 아닙니다.** 입력을 적은 글자 수를 기준으로 봐도 다항이에요.
[0/1 배낭](../knapsack01/knapsack01-guide.md) 이 용량 값에 비례하는 칸을 쓰는 것과 다른
자리입니다.

#### 최악을 만드는 입력

「깊은 트리가 최악」이라는 통념부터 확인합시다. 노드 수를 맞춰 네 모양을 실제로 실행하고, 같은
점화식을 재귀로 적었을 때의 최대 호출 깊이를 나란히 놓아 봅니다.

<!--proof:shapeCost-->

```text
입력 모양 (n = 20,000)  반복판이 하는 일  재귀판의 최대 깊이      답
경로                              99,995              20,000  10,000
별                                99,995                   2  19,999
완전 이진 트리                    99,995                  15  13,331
애벌레                            99,995              10,001  10,000
```

**둘째 칸 네 줄이 정확히 같고 셋째 칸은 만 배까지 갈립니다.** 반복문으로 적었으므로 트리의 깊이가
비용에 안 들어가요 — 순서 배열의 길이는 어느 모양에서도 `n` 이고, 이웃 목록의 길이 합도
`2(n-1)` 로 고정입니다. 답은 네 줄이 다 다른데 비용은 안 갈립니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 부분집합을 전부 만드는 대신 **서브트리마다 값
둘만 정했고**, 부모를 고를 때 자식의 `dp0` 만 받아 「인접한 둘을 함께 고르지 않는다」를 지켰으며,
그 결과 `2^n` 이 `5n - 5` 로 내려왔습니다.

```text
잎에서 시작한다 → 자식을 부모에 더한다 → 뿌리의 두 값 중 큰 쪽을 읽는다
      └ 값 둘이 선택 여부를 남긴다   └ dp1 만 제한을 받는다
```

먼저 답이 붙는 문제 하나입니다. T7 에서 노드 5 를 부모 2 에 더할 때 `dp1[2]` 가 `-2 + 4 = 2` 가
됐어요. 그 `4` 는 `dp0[5]` 인데, `dp0[5]` 자체는 T4 에서 `max(0, 4)` 로 정해진 값입니다. 그
`4` 는 어떤 노드를 고른 합일까요? 그리고 노드 2 를 고르는 답에 그 노드가 함께 들어가도 되는
이유는 무엇일까요?

```text
T4 :  dp0[5] = max(dp0[6], dp1[6]) = max(0, 4) = 4
T7 :  dp1[2] = -2 + dp0[5] = -2 + 4 = 2
      4 가 뜻하는 집합 = ?      ← 이 자리를 직접 채워 봅시다
```

<!--check:carryUp-->

`4` 는 노드 6 하나만 고른 합입니다. `dp0[5]` 는 「노드 5 를 안 고를 때 5 의 서브트리에서 얻는
최대 합」이고, 그 서브트리에는 5 와 6 뿐이라 6 만 고른 4 가 최대예요.

```text
dp0[5] = 4       고른 노드 { 6 }
dp1[2] = -2 + 4  고른 노드 { 2, 6 }

  2 와 6 사이에는 노드 5 가 있다 → 간선으로 직접 안 이어져 있다
  그래서 둘을 함께 고를 수 있다
```

노드 2 를 고르면 못 고르게 되는 것은 자식인 5 하나입니다. 손자인 6 은 `dp0[5]` 안에서 이미 골라져
있었고, 그 값을 그대로 받는 것이 ⑤ 한 줄이 하는 일 전부예요. 이 입력에서는 `w[2]` 가 음수라 결국
`dp0[2] = 7` 이 더 커서 안 골라지지만, 그것은 값의 부호가 정한 것이지 규칙이 정한 것이 아닙니다.
