# tspBitmask — 방문 순서를 지우고 방문 집합만 남기면 상태가 (n-1)! 에서 2^n·n 으로 줄어드는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

먼저 문제 전체를 한 절에 담고, 그 절을 읽는 데 필요한 배경을 확인합니다. 그다음 방문 순서를
전부 만들어 보는 방법에서 시작해 방문 집합과 현재 위치만 남기는 방법까지 걸음마다 값을
이어받으며 갑니다. 끝에서는 그 아이디어를 조각 셋으로 나누어 실제 코드로 옮깁니다.

### 전체 컨셉

도시 `n` 개와 도시 사이의 이동 비용이 담긴 `n × n` 행렬을 받아, **도시 0 에서 출발해 모든
도시를 정확히 한 번씩 들르고 도시 0 으로 돌아오는 최소 비용**을 구하는 문제예요. 가는 비용과
오는 비용이 달라도 됩니다 — 방향이 있는 이동 비용입니다.

```text
도시 넷의 거리 행렬과 답
        -> 0   1   2   3
   0 :   0  10  15  20
   1 :  10   0  35  25
   2 :  15  35   0  30
   3 :  20  25  30   0

  0 -> 1 -> 3 -> 2 -> 0 이 10 + 25 + 30 + 15 = 80 이고 이것이 최소다
  방문 순서를 바꾸면 총 비용이 바뀐다. 그래서 순서를 고르는 문제다
```

정직하게 푸는 방법은 정해져 있어요. 도시 0 을 맨 앞에 두고 나머지 `n-1` 개 도시의 순서를
전부 만들어 비용을 재면 됩니다. 그런데 그 개수가 `(n-1)!` 이라 도시가 20 개면 18 자리 수가
돼요. 여기서 접을 자리가 하나 있습니다.

| 이름 | 무엇을 가리키는가 | 이 글의 표기 |
| --- | --- | --- |
| 방문 집합 | 지금까지 들른 도시들을 모아 놓은 것 | 정수 하나로 적고 `mask` 라 부릅니다 |
| 현재 위치 | 지금 서 있는 도시의 번호 | `v` 로 적습니다 |
| 상태 | 「방문 집합이 이것이고 현재 위치가 저것」인 한 벌 | `(mask, v)` 로 적습니다 |
| 접두 경로 | 도시 0 에서 출발해 여기까지 온 이동 순서 | 「접두 경로」 로 적습니다 |
| 투어 | 모든 도시를 한 번씩 들르고 도시 0 으로 돌아온 경로 전체 | 「투어」 로 적습니다 |

**접을 자리는 이것이에요.** 앞으로 얼마가 더 드는지는 **어떤 도시를 이미 들렀는가**와
**지금 어디에 있는가**에만 달려 있고, **그 도시들을 어떤 순서로 들렀는지에는 달려 있지
않습니다.** 그러니 순서가 다르지만 같은 상태에 이른 접두 경로들은 그중 가장 값이 작은 하나만
남기면 됩니다.

```text
순서가 다른 접두 경로 둘이 같은 상태로 모인다

  0 -> 1 -> 2 -> 3     들른 도시 {0,1,2,3} · 지금 3 에 있다
  0 -> 2 -> 1 -> 3     들른 도시 {0,1,2,3} · 지금 3 에 있다

  두 경로가 앞으로 할 수 있는 일은 글자 그대로 같다 — 남은 도시가 같고 출발점이 같으니까
  그러면 여기까지 든 비용이 큰 쪽은 어떤 투어에서도 쓸 일이 없다. 지워도 답이 안 바뀐다
```

방문 집합을 정수 하나로 적으면 이 「모아 두기」가 배열 첨자가 돼요. 도시 `i` 를 들렀으면
정수의 자리 `i` 를 1 로 두는 것입니다 — **비트 자리 번호가 곧 도시 번호**이고, 둘 사이에
어떤 변환도 없습니다.

```text
도시 넷일 때 방문 집합의 표기

  방문 집합  자리 3210  정수
  {0}        0001          1
  {0,1}      0011          3
  {0,2}      0101          5
  {0,1,2,3}  1111         15

  자리 i 가 도시 i 다. 들른 도시가 늘어나면 정수가 커진다
  자리를 하나 켜는 것이 도시를 하나 더 들르는 것이고, 그러면 정수도 반드시 커진다
```

그래서 상태 하나마다 값 한 칸을 두고, 그 칸에 「이 상태까지 온 접두 경로 중 최소 비용」을
적습니다. 방문 집합이 `2^n` 가지이고 현재 위치가 `n` 가지이니 칸이 `2^n · n` 개예요. 도시가
20 개면 순서 `(n-1)!` 이 18 자리 수인데 칸은 2,097 만 개입니다.

```text
도시 20 개에서 두 방법이 재야 하는 것

  순서를 전부 만든다   순열 19! = 121,645,100,408,832,000 개   18 자리 수
  상태마다 한 칸       칸 2^20 · 20 = 20,971,520 개            8 자리 수

  갈리는 것은 답이 아니라 세는 대상이다. 두 방법의 반환값은 같다
```

칸을 채우는 순서만 정하면 끝이에요. 방문 집합을 작은 정수부터 큰 정수까지 차례로 처리하면
「도시를 하나 더 들른 집합」은 언제나 뒤에 오므로, 어떤 칸을 채울 때 그 칸이 읽는 값은 이미
확정돼 있습니다. 칸 하나마다 다음 도시 후보가 `n` 개 미만이니 전체 비용이 `O(2^n · n^2)` 이고,
칸이 `2^n · n` 개이므로 저장 공간이 `O(2^n · n)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **집합을 정수의 비트로 적는 법.** `mask & (1 << i)` 가 「도시 `i` 를 들렀는가」이고
  `mask | (1 << i)` 가 「도시 `i` 를 더 들른 집합」입니다. 이 표기가 낯설면
  [서브마스크 열거 가이드](../../bit-manipulation/enumerateSubmasks/enumerateSubmasks-guide.md)
  가 같은 표기를 처음부터 세웁니다.
- **상태와 전이로 나눈 동적 계획법.** 「상태 하나에 값 한 칸을 두고, 작은 상태에서 큰 상태로
  값을 옮긴다」 는 구조를 이미 알고 있어야 해요. 칸을 하나씩 정해 가는 예가 필요하면
  [배낭 문제 가이드](../knapsack01/knapsack01-guide.md)가 같은 뼈대를 씁니다.
- **집합을 상태로 삼는 표.** 원소를 담았는가 아닌가로 상태를 가르는 표는
  [부분집합 합 가이드](../subsetSum/subsetSum-guide.md)에도 나옵니다. 이 글은 거기에 「지금
  어디에 있는가」 한 축을 더 붙인 것이에요.
- **인접 행렬로 준 그래프.** `dist[i][j]` 가 도시 `i` 에서 `j` 로 가는 비용이고, 이 문제에서는
  모든 도시 쌍 사이에 길이 있습니다. 행렬로 준 그래프를 다루는 예는
  [플로이드-워셜 가이드](../../shortest-path/floydWarshall/floydWarshall-guide.md)가 있어요.
- **「아직 도달하지 못함」을 값으로 적는 관례.** 이 글은 그 자리를
  `Number.POSITIVE_INFINITY` 로 두고 `INF` 라 적습니다. 어떤 유한한 투어 비용보다 큰 값이면
  같은 일을 합니다.

이 글이 다루는 것은 **모든 도시를 정확히 한 번씩 들르고 출발점으로 돌아오는 최소 비용을
정확히** 구하는 것이고, 답에 오차를 허용하는 근사는 다루지 않아요.

```text
모든 도시를 한 번씩 · 출발점으로 복귀 · 최소 비용 · 정확한 답   <- 이 글이 다루는 것
같은 문제인데 답이 최적의 1.5 배 안이기만 하면 된다             <- 근사가 맡는 것
도시가 수천 개다                                                <- 이 글의 방법으로는 못 푼다
모든 도시가 아니라 정해진 몇 곳만 들른다                        <- 다른 글이 다루는 것
```

### 아이디어 상세 — 방문 집합과 현재 위치를 상태로 삼는 아이디어를 떠올리는 과정

먼저 무엇을 만드는지부터 못 박습니다.

```ts
function tspBitmask(dist: number[][]): number;
```

- 입력: `n × n` 거리 행렬 `dist`. `dist[i][j]` 는 도시 `i` 에서 도시 `j` 로 가는 비용이고
  `dist[i][i]` 는 0 입니다. `dist[i][j]` 와 `dist[j][i]` 가 달라도 됩니다.
- 출력: 도시 0 에서 출발해 모든 도시를 정확히 한 번씩 들르고 도시 0 으로 돌아오는 최소 비용.
- 제약: `1 ≤ n ≤ 20`, `0 ≤ dist[i][j] ≤ 10^6`. 시간 1 초, 메모리 256 MB.

절이 달라져도 뜻이 바뀌지 않는 것부터 모아 둡니다. 이 글이 쓰는 기호는 여덟이에요.

| 기호 | 무엇을 가리키는가 | 이 문제에서의 범위 |
| --- | --- | --- |
| `n` | 도시의 개수. 코드의 `dist.length` 입니다 | `1 ≤ n ≤ 20` |
| `dist[i][j]` | 도시 `i` 에서 도시 `j` 로 가는 이동 비용 | 0 이상 `10^6` 이하의 정수 |
| `mask` | 방문 집합. 자리 `i` 가 1 이면 도시 `i` 를 들렀다는 뜻입니다 | `1` 이상 `FULL` 이하의 정수 |
| `FULL` | 모든 도시를 들른 방문 집합. 자리 `n` 개가 전부 1 입니다 | 도시 넷이면 `1111` |
| `v` | 현재 위치. 지금 서 있는 도시의 번호 | `0` 이상 `n-1` 이하 |
| `u` | 다음에 갈 도시의 번호 | `0` 이상 `n-1` 이하 |
| `dp[mask][v]` | 도시 0 에서 출발해 `mask` 를 정확히 들르고 지금 `v` 에 있는 접두 경로의 최소 비용 | 만들 수 없으면 `INF` |
| `INF` | 아직 도달하지 못했다는 표기 | `INF` 로 적습니다 |

`mask` 와 `v` 를 갈라 두는 것이 이 글의 뼈대입니다. 앞은 **무엇을 이미 했는가**이고 뒤는
**어디서 이어 가는가**예요. 둘 중 하나만 있으면 다음 걸음의 비용을 계산할 수 없는데, 그것이
왜 그런지는 아래에서 값으로 봅니다.

```text
상태 하나에 붙는 두 축

  mask   무엇을 이미 들렀는가    앞으로 갈 수 있는 도시가 무엇인지를 정한다
  v      지금 어디에 있는가      다음 이동 비용 dist[v][u] 의 앞 첨자를 정한다

  앞의 축만 남기면 다음 비용을 못 적고, 뒤의 축만 남기면 어디를 이미 들렀는지를 못 적는다
```

아무 기법 없이 푸는 법부터 세웁니다. **도시 0 을 맨 앞에 고정하고 나머지 도시의 순서를 전부
만들어** 비용을 재면 돼요. 전개 입력의 도시 넷으로 실제로 만들어 보면 순서가 여섯 가지입니다.

<!--proof:naivePerms-->

```text
방문 순서          구간 비용          합계
0 → 1 → 2 → 3 → 0  10 + 35 + 30 + 20    95
0 → 1 → 3 → 2 → 0  10 + 25 + 30 + 15    80
0 → 2 → 1 → 3 → 0  15 + 35 + 25 + 20    95
0 → 2 → 3 → 1 → 0  15 + 30 + 25 + 10    80
0 → 3 → 1 → 2 → 0  20 + 25 + 35 + 15    95
0 → 3 → 2 → 1 → 0  20 + 30 + 35 + 10    95

순열 6 개 · 덧셈 21 번 · 진입한 노드 16 개
가장 작은 합계 80
```

**여섯 가지 중 가장 작은 것이 80 입니다.** 그리고 `0 → 1 → 3 → 2 → 0` 과 `0 → 2 → 3 → 1 → 0`
이 둘 다 80 인데, 뒤엣것은 앞엣것을 거꾸로 놓은 것이라 방향이 대칭인 이 행렬에서는 값이 같아요.
도시가 넷이라 여섯 번으로 끝났지만, 이 방법이 재는 개수는 도시 수의 계승을 따라 커집니다.

<!--proof:naiveScale-->

```text
도시 n  순열 (n-1)!  순열 나열의 덧셈  상태 표의 전이      비
     4            6                21              15    1 배
     6          120               445             165    3 배
     8        5,040            18,739           1,351   14 배
    10      362,880         1,349,289           9,225  146 배

제약 상한 n = 20 에서
  순열 (n-1)!                    121,645,100,408,832,000 (18 자리)
  순열 나열의 덧셈               452,310,766,371,235,999 (18 자리)
  상태 표의 전이                 44,826,643 (8 자리)
  덧셈을 1 초에 10 억 번 한다면  14.3 년
  전이를 1 초에 10 억 번 한다면  0.045 초
```

**도시 10 개에서 이미 순열 나열의 덧셈이 상태 표의 전이보다 146 배 많습니다.** 그리고 제약
상한인 도시 20 개에서는 덧셈이 18 자리 수라, 1 초에 10 억 번을 더해도 14.3 년이 걸려요. 상태
표 쪽은 같은 자리에서 8 자리 수 4,482 만 번이고, 같은 속도로 0.045 초입니다.

```text
순열 나열이 무엇을 되풀이하는가

  0 -> 1 -> 2 -> 3 -> ...      앞의 세 도시를 들르고 3 에 있다
  0 -> 2 -> 1 -> 3 -> ...      앞의 세 도시를 들르고 3 에 있다

  두 줄의 「...」 자리에서 하는 일이 글자 그대로 같은데 나열은 그것을 두 번 계산한다
  도시가 하나 늘 때마다 그런 짝이 계승만큼 늘어난다 — 줄일 자리가 여기다
```

그 「같은 일」이 정말 같은지를 값으로 확인합시다. 도시 다섯짜리 행렬에서 접두 경로 둘이 같은
상태에 이르는 자리를 잡고, 거기서부터 남은 최소 비용을 따로 계산해 나란히 놓았어요.

<!--proof:orderFree-->

```text
접두 경로      방문 집합  위치  접두 비용  남은 최소 비용  전체
0 → 1 → 2 → 3  01111      3             7               9    16
0 → 2 → 1 → 3  01111      3            24               9    33

남은 최소 비용이 9 로 같으므로 접두 비용이 큰 쪽은 답이 될 수 없다
상태 (01111, 위치 3) 에 남기는 값은 7 하나다

도시 12 개에서 순열 나열이 진입하는 노드 108,505,112 개가
값이 들어가는 상태 11,265 개로 모인다 — 9,632 배다
```

**남은 최소 비용이 두 줄에서 같습니다.** 접두 비용은 7 과 24 로 다른데 그 뒤가 같으니, 24 쪽은
어떤 투어에서도 답이 될 수 없어요. 상태 하나에 값을 한 개만 남겨도 되는 근거가 이것입니다.
도시 12 개에서는 순열 나열이 진입하는 노드 1 억 850 만 개가 상태 11,265 개로 모입니다.

```text
무엇이 상태를 정하는가

  들른 도시의 집합      남은 도시가 무엇인지를 정한다        앞으로 갈 수 있는 곳
  현재 위치             다음 이동의 출발점을 정한다          다음 비용 dist[v][u]
  들른 순서             앞으로 하는 일에 아무 영향이 없다    버려도 되는 것

  앞의 둘만 남기고 셋째를 버리는 것이 이 알고리즘의 전부다
```

그런데 둘 다 남겨야 할까요? **가장 단순한 후보인 「방문 집합만 남기기」를 먼저 시험해 봅시다.**
위치를 지우면 다음 이동 비용 `dist[v][u]` 의 `v` 가 없어지므로, 집합 안의 도시 중 가장 작은
값을 골라 쓸 수밖에 없어요. 그렇게 만든 판을 실제로 실행하면 이렇게 나옵니다.

<!--proof:maskOnlyGap-->

```text
입력                     정본  위치를 뺀 판  차이
전개 입력 (도시 넷)        80            55    25
지름길이 생기는 도시 넷    10             7     3
생성식 도시 여섯          216           146    70
생성식 도시 여덟          208           103   105
비대칭 도시 셋              3             3     0

위치를 뺀 판은 집합 안의 어느 도시에서 출발해도 되는 것처럼 세므로

```

**전개 입력에서 80 이어야 할 답이 55 로 나옵니다.** 위치를 지우면 「지금 2 에 있는데 1 에서
출발하는 비용을 골라 쓰는」 일이 생기고, 그렇게 고른 구간들은 실제로 하나의 경로로 이어지지
않아요. 도시 여덟에서는 208 과 103 으로 차이가 105 까지 벌어집니다. 비대칭 도시 셋에서는 값이
우연히 맞는데, 답이 맞는 입력이 섞여 있다는 것이 이 판을 더 위험하게 만듭니다.

```text

                           앞 조각이 1 에서 끝나는데 뒤 조각이 2 에서 시작한다

  위치 한 축을 더 두는 값이 이것이다 — 조각이 실제로 이어진다는 보장
```

그러면 상태를 `(mask, v)` 둘로 두기로 하고, 그 결정이 낸 값을 셉니다. 상태의 개수와 전이의
개수를 실제로 세어 닫힌 형태와 나란히 놓았어요.

**잡는 칸은 `2^n · n` 인데 값이 드는 상태는 그중 일부입니다.** 도시 0 은 언제나 방문 집합 안에
있고 현재 위치도 방문 집합 안에 있어야 하므로, 도시 20 개에서 값이 드는 상태가 498 만 개로
잡는 칸 2,097 만 개의 23.8 % 예요. 전이는 4,482 만 개이고, 이것이 이 알고리즘이 실제로 하는
일의 크기입니다.

```text

  현재 위치가 n 가지                    위치 축

  칸 하나마다 다음 도시 후보가 n 개 미만

  둘 중 손댈 수 있는 것은 후보 개수뿐인데 그것이 이미 n 미만이라 더 줄일 자리가 없다
  칸의 개수는 문제가 정한다 — 도시 수가 20 을 넘으면 이 방법 자체를 쓸 수 없다
```

### 수행으로 알아보는 알고리즘 — 도시 넷의 상태 표를 열일곱 걸음으로 채운다

여기가 그 아이디어를 **실제로 작동하는 코드**로 바꾸는 자리입니다. 거리 행렬 하나를 정해 두고
조각을 하나씩 붙이되, 붙일 때마다 그 조각만 실행한 값을 확인하고 다음으로 넘어갑니다.

```ts
const dist = [
  [0, 10, 15, 20],
  [10, 0, 35, 25],
  [15, 35, 0, 30],
  [20, 25, 30, 0],
];
// 이 절이 끝나면 80 이 나와야 한다
```

왜 하필 도시 넷일까요? **순서가 다른 두 접두 경로가 같은 상태로 모이는 자리**가 나오는 가장
작은 크기이기 때문이에요. 도시가 셋이면 방문 집합과 위치를 정하는 순간 접두 경로가 하나로
정해져서 「모인다」가 한 번도 일어나지 않습니다. 일곱 갈래는 이 입력에서 전부 실행되고, 그
횟수는 아래에서 표로 봅니다.

```text
절차 전체를 한 장에

  T1        상태 표를 잡고 dp[0001][0] = 0 을 적는다           ① 상태 표  ② 출발 상태
            방문 집합 mask 를 1 부터 FULL 까지 차례로 처리한다:
  T2~T16      위치 v 가 mask 밖이면 건너뛴다                   ③ 방문 집합 밖
              그 상태가 아직 INF 면 건너뛴다                   ④ 도달하지 못한 상태
              아직 안 간 도시 u 마다:
                u 가 이미 mask 안이면 건너뛴다                 ⑤ 이미 들른 도시
                도착 상태의 값을 후보와 견준다                 ⑥ 값 갱신
  T17       마지막 도시마다 복귀 비용을 더해 최솟값을 고른다    ⑦ 복귀 비용
```

#### 1. 상태 표를 잡고 출발 상태를 놓는다

첫 조각이 준비입니다. 상태 표를 전부 `INF` 로 채우고, 도시 0 만 들렀고 위치가 0 이며 비용이
0 인 상태 하나에만 0 을 적어요.

```ts
const n = dist.length;
const FULL = (1 << n) - 1;
const dp = new Float64Array((FULL + 1) * n).fill(INF);   // ① 상태 표
dp[1 * n + 0] = 0;                                       // ② 출발 상태
```

표를 이차원 배열이 아니라 **한 줄로 편 것**을 봐 주세요. `dp[mask][v]` 는 `dp[mask * n + v]`
로 적습니다. 도시 20 개에서 이차원 배열로 잡으면 행 객체가 2^20 개, 곧 백만 개 넘게 따로 생기는데, 한 줄로
펴면 칸 하나가 8 바이트씩 이어 붙은 덩어리 하나예요.

```text
T1 이 끝난 시점

  FULL        1111 = 15          모든 도시를 들른 방문 집합이다
  칸 수       (15 + 1) x 4 = 64  2^n · n 과 같다
  값이 든 칸  dp[0001][0] = 0    나머지 63 칸은 INF 다

  자리 계산 dp[mask * n + v] 에서 n 이 곱해지는 것은 방문 집합 하나가 위치 n 칸을 갖기 때문이다
```

#### 2. 방문 집합 하나에서 전이를 만든다

둘째 조각이 본체입니다. 방문 집합 하나를 잡고, 그 안에 있으면서 값이 든 위치마다 아직 안 간
도시로 옮겨 가요.

```ts
for (let v = 0; v < n; v++) {
  if ((mask & (1 << v)) === 0) continue;      // ③ 방문 집합 밖
  const cur = dp[mask * n + v] as number;
  if (cur === INF) continue;                  // ④ 도달하지 못한 상태
  const row = dist[v] as number[];
  for (let u = 0; u < n; u++) {
    if ((mask & (1 << u)) !== 0) continue;    // ⑤ 이미 들른 도시
    const next = mask | (1 << u);
    const at = next * n + u;
    const cand = cur + (row[u] as number);
    if (cand < (dp[at] as number)) dp[at] = cand;   // ⑥ 값 갱신
  }
}
```

첫 방문 집합만 실행하면 이렇게 나옵니다. `mask` 가 `0001` 이라 값이 든 위치는 0 하나이고,
거기서 도시 1 · 2 · 3 으로 전이 셋이 나와요.

```text
T2 — 방문 집합 0001 에서
  값이 든 위치  v = 0        dp[0001][0] = 0

  u = 1   next = 0011   0 + dist[0][1] = 10   ->  dp[0011][1] = 10
  u = 2   next = 0101   0 + dist[0][2] = 15   ->  dp[0101][2] = 15
  u = 3   next = 1001   0 + dist[0][3] = 20   ->  dp[1001][3] = 20

  u = 0 은 ⑤ 가 걸러 낸다 — 도시 0 은 이미 mask 안에 있다
```

#### 멈춤 — 도달하지 못한 상태를 0 으로 두면 없는 경로가 최소가 된다

여기서 헷갈리기 쉬운 포인트는 상태 표를 `INF` 로 채우는 줄입니다. 「어차피 `min` 으로 고를
텐데 0 으로 채우면 안 되나」로 읽기 쉬워요. 그 줄만 바꿔 봅시다.

```ts
const dp = new Float64Array((FULL + 1) * n).fill(0);   // ← INF 대신 0 으로 채웠다
```

아니라 「아무 데도 안 간 상태를 완성된 투어로 읽었다」예요. 무엇이 사라졌는지를 값으로 봅시다.

아직 없다」를 뜻하는데, 0 으로 채우면 그 뜻을 적을 자리 자체가 없어져요. 그러면 도시 0 으로
들어오는 전이가 한 번도 일어난 적 없는데도 `dp[1111][0]` 이 0 으로 남고, 마지막 반복이 그
0 을 골라 옵니다.

```text

  0 으로 채운 판  dp[1111][0] = 0  같은 이유로 한 번도 안 고쳐졌는데 값이 0 이다

  마지막 반복은 「모든 도시를 들르고 v 에 있는 값」을 읽는다고 믿고 dp[1111][0] 을 읽는다
  그 자리에 0 이 있으면 「비용 0 으로 전부 들렀다」가 되고, 그것이 답으로 나온다
```

#### 3. 이미 들른 도시를 걸러 낸다

둘째 조각 안의 한 줄이 정확성을 지킵니다. 다음 도시 `u` 를 고를 때 **이미 방문 집합 안에 있는
도시는 제외**해야 해요. 이 한 줄이 「정확히 한 번씩」을 지킵니다.

```ts
if ((mask & (1 << u)) !== 0) continue;    // ⑤ 이미 들른 도시
```

이 줄이 전개 입력에서 몇 번 참이 되는지 세어 보면 37 번이에요. 방문 집합이 커질수록 걸러 내는
횟수가 늘어나고, 모든 도시를 들른 방문 집합에서는 후보 넷이 전부 걸립니다.

```text
T16 — 방문 집합 1111 에서
  값이 든 위치  v = 1 · 2 · 3      dp[1111][1] = 70 · dp[1111][2] = 65 · dp[1111][3] = 75

  u = 0   1111 & 0001 != 0   걸러 낸다
  u = 1   1111 & 0010 != 0   걸러 낸다
  u = 2   1111 & 0100 != 0   걸러 낸다
  u = 3   1111 & 1000 != 0   걸러 낸다

  전이가 하나도 안 나온다. 이 상태들은 마지막 복귀 계산에서만 쓰인다
```

#### 멈춤 — 그 검사를 빼도 답이 안 틀리는 입력이 있다

여기서 헷갈리기 쉬운 포인트는 「`next` 가 어차피 `mask` 와 같을 텐데 무슨 문제냐」입니다.
`u` 가 이미 `mask` 안이면 `mask | (1 << u)` 가 `mask` 그대로이니 값이 제자리에 적힐 뿐이라고
읽기 쉬워요. 그 줄을 빼 봅시다.

```ts
for (let u = 0; u < n; u++) {
  // 이미 들른 도시를 걸러 내던 줄이 있던 자리를 비웠다
  const next = mask | (1 << u);
```

#### 4. 열일곱 걸음을 끝까지 실행한다

여기까지의 조각을 이어 고정한 거리 행렬에 끝까지 넣으면 걸음이 열일곱 개 나옵니다. T1 이 준비이고,

#### 5. 복귀 비용을 더해 답을 고른다

셋째 조각이 답을 고르는 자리입니다. 모든 도시를 들른 방문 집합에서 각 위치마다 도시 0 으로

#### 6. 전체 코드

세 조각을 하나로 잇습니다. 앞에서 값으로 본 것 말고 새로 붙은 것은 **방문 집합을 1 부터
`FULL` 까지 차례로 처리하는 바깥 반복** 하나예요. 그 순서가 왜 그래야 하는지는 「불변식」 절이
값으로 봅니다.

```ts
/** 아직 도달하지 못한 상태의 값. 어떤 유한한 투어 비용보다 크다. */
export const INF = Number.POSITIVE_INFINITY;

export function tspBitmask(dist: number[][]): number {
  const n = dist.length;
  // 모든 도시를 방문한 방문 집합. 자리 i 가 1 이면 도시 i 를 방문했다는 뜻이다.
  const FULL = (1 << n) - 1;
  // ① 상태 표 — dp[mask * n + v] 가 dp[mask][v] 다. 한 줄로 펴서 한 번에 잡는다.
  const dp = new Float64Array((FULL + 1) * n).fill(INF);
  // ② 출발 상태 — 도시 0 만 방문했고 위치가 0 이며 비용이 0 이다.
  dp[1 * n + 0] = 0;

  for (let mask = 1; mask <= FULL; mask++) {
    for (let v = 0; v < n; v++) {
      // ③ 위치가 방문 집합 밖이면 그 상태는 만들어질 수 없다.
      if ((mask & (1 << v)) === 0) continue;
      const cur = dp[mask * n + v] as number;
      // ④ 아직 도달하지 못한 상태에서는 전이를 만들지 않는다.
      if (cur === INF) continue;
      const row = dist[v] as number[];
      for (let u = 0; u < n; u++) {
        // ⑤ 이미 방문한 도시로는 가지 않는다.
        if ((mask & (1 << u)) !== 0) continue;
        const next = mask | (1 << u);
        const at = next * n + u;
        const cand = cur + (row[u] as number);
        // ⑥ 같은 상태에 더 작은 비용으로 도달했으면 그 값으로 바꾼다.
        if (cand < (dp[at] as number)) dp[at] = cand;
      }
    }
  }

  let answer = INF;
  for (let last = 0; last < n; last++) {
    const back = dist[last] as number[];
    // ⑦ 마지막 도시에서 도시 0 으로 돌아오는 비용까지 더한 것이 투어 하나의 값이다.
    const cand = (dp[FULL * n + last] as number) + (back[0] as number);
    if (cand < answer) answer = cand;
  }
  return answer;
}
```

```text
tspBitmask([[0, 10, 15, 20], [10, 0, 35, 25], [15, 35, 0, 30], [20, 25, 30, 0]])  -> 80
tspBitmask([[0, 1, 10], [10, 0, 1], [1, 10, 0]])                                  -> 3
tspBitmask([[0, 5], [5, 0]])                                                      -> 10
tspBitmask([[0]])                                                                 -> 0
```

### 알아 두면 좋은 개념 — 상태 압축

이 절차가 순열을 상태 표로 바꿀 수 있었던 근거에는 이름이 붙어 있습니다. **지금까지 처리한
원소들의 집합을 정수 한 개의 비트로 적어 배열 첨자로 쓰는 것**을 **상태 압축**이라 불러요.
이 편에서 그것은 「들른 도시의 집합을 `mask` 라는 정수로 적고 `dp[mask][v]` 의 첨자로 쓴 것」
이고, 그 덕에 세는 대상이 순서 `(n-1)!` 개에서 집합 `2^n` 개로 바뀝니다.

```text
이 편의 어느 값이 상태 압축이었는가

  원소             도시 0 · 1 · 2 · 3            n 개
  집합             들른 도시의 모음              2^n 가지
  정수 표기        자리 i 가 도시 i              0011 = {0,1}
  첨자로 쓰는 자리 dp[mask][v] 의 mask           배열 첨자가 곧 집합이다

  T8 에서 접두 경로 0 -> 1 -> 2 와 0 -> 2 -> 1 이 같은 줄 0111 에 나란히 놓이고,
  거기서 나온 두 전이가 같은 칸 dp[1111][3] 에 값을 적으려 한 것이 압축의 값이다
  압축이 없으면 두 경로는 서로 다른 두 개의 순서로 끝까지 남고, 개수가 계승을 따라 커진다
```

같은 이름이 이 편 밖에서 다시 나옵니다. 셋 다 「집합을 정수의 비트로 적고 그 정수를 첨자로
쓴다」를 같은 모양으로 씁니다.

| 어디서 다시 만나는가 | 무엇이 원소인가 | 집합 첨자로 무엇을 하는가 |
| --- | --- | --- |
| 할당 문제 — 사람과 일을 1:1 로 짝짓기 | 이미 배정한 일 | 배정한 일의 집합마다 최소 비용을 적는다 |
| 해밀턴 경로의 개수 세기 | 이미 들른 정점 | 집합과 끝점마다 경로 수를 적는다 |
| 서브마스크 열거 | 마스크가 담은 원소 | 그 집합의 부분집합을 정수 연산으로 만든다 |

서브마스크 열거는 이 저장소에도 있어요 —
[서브마스크 열거 가이드](../../bit-manipulation/enumerateSubmasks/enumerateSubmasks-guide.md)
가 그 자리이고, 집합의 부분집합을 정수 뺄셈 한 번으로 만드는 방법을 다룹니다. **이름을 알아
두면 다시 만났을 때 「무엇이 원소이고 집합이 몇 개인가」부터 물을 수 있어요** — 원소가 20 개
안팎이면 이 편과 같은 방법이 그대로 갑니다.

#### 최적인 문제의 모양

- **정확한 답이 필요합니다.** 오차를 허용해도 되면 훨씬 적은 연산으로 끝나는 근사가 있고,

- **최악에서도 예측 가능한 비용이 필요합니다.** 같은 도시 수라면 거리 행렬이 무엇이든 살펴보는

```text
네 조건이 코드의 어느 줄로 나타나는가
  집합에만 달려 있다      -> 상태가 (mask, v) 둘로 끝난다
  원소가 20 개 안팎이다   -> 상태 표를 통째로 잡을 수 있다
  정확한 답이 필요하다    -> 후보를 하나도 버리지 않는다
  최악이 예측 가능하다    -> 가지치기를 안 쓴다

  둘째 줄이 이 절차의 자리이자 이 절차의 한계다
```

「원소가 20 개 안팎이다」 줄이 이 절차의 자리입니다. 도시가 수백 개면 상태 표를 잡는 것 자체가
불가능하고, 그때는 정확한 답을 포기하거나 문제의 특별한 구조를 쓰는 다른 방법으로 가야 해요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 있으면
  "모든 도시를 정확히 한 번씩"                 <- 방문 집합이 상태가 된다
  "n <= 20" 처럼 상한이 작다                   <- 2^n 이 배열에 들어간다
  "최소 비용" "정확한 최적해"                  <- 근사가 아니라 전수 계산이다
  "출발지로 돌아온다"                          <- 마지막에 복귀 비용을 더한다

제약이 이런 모양이면
  n 이 20 이하이고 시간 1 초                   <- 2^n · n^2 이 4 억 언저리다
  메모리 256 MB                                <- 2^n · n 칸이 160 MiB 라 그 안이다

반대로 이런 말이 있으면 해당하지 않는다
  "도시가 최대 10^5 개"                        <- 상태 표를 잡을 수 없다
  "최적의 1.5 배 안이면 된다"                  <- 근사가 맡는다
  "각 도시를 여러 번 지나도 된다"              <- 방문 집합이 상태가 되지 않는다
```

마지막 무리가 보이면 다른 절차로 갑니다. 도시가 아주 많고 답에 오차를 허용하면 근사나
지역 탐색이 그 자리를 맡고, 「정확히 한 번씩」이라는 조건이 없으면 문제 자체가
[플로이드-워셜](../../shortest-path/floydWarshall/floydWarshall-guide.md)이 푸는 모든 쌍
최단 경로에 가까워집니다.

#### 실제로 쓰이는 곳

- **`python-tsp` 의 `python_tsp/exact/dynamic_programming.py`** — 파이썬 패키지가 이 절차를
  **정확해 풀이**로 싣습니다. 파일이 `exact/` 아래 있고, 주석의 참고 문헌이
  `https://en.wikipedia.org/wiki/Held%E2%80%93Karp_algorithm#cite_note-5` 를 가리켜요. 상태를
  적는 자리가 `def dist(ni: int, N: frozenset) -> float:` 인데, `ni` 가 이 글의 `v`(현재
  위치)이고 `N` 이 **아직 안 간 도시의 집합**이라 이 글의 `mask` 를 뒤집어 적은 것입니다.
  첫 호출이 `best_distance = dist(0, N)` 이고, 경로를 복원하려고 `memo: dict[tuple, int] = {}`
  에 다음 도시를 함께 적어 둡니다.
  ([`python-tsp/python_tsp/exact/dynamic_programming.py`](https://github.com/fillipe-gsm/python-tsp/blob/master/python_tsp/exact/dynamic_programming.py),
  조회 2026-09-07)
- **`networkx` 의 `held_karp_ascent`** — 같은 이름이 **다른 것**을 가리키는 자리입니다.
  주석 첫 줄이 *"Minimizes the Held-Karp relaxation of the TSP for `G`"* 이고, 그 아래가
  *"The Held-Karp relaxation defines the lower bound for solutions to the ATSP, although it
  does return a fractional solution."* 라 적어요. 이 글의 절차가 내는 정확한 최솟값이 아니라
  **하한**을 내고, 답이 분수 값입니다. 이름이 같다고 같은 것을 계산하지 않아요.
  ([`networkx/algorithms/approximation/traveling_salesman.py`](https://github.com/networkx/networkx/blob/main/networkx/algorithms/approximation/traveling_salesman.py),
  조회 2026-09-07)

```text
두 구현이 이 글과 무엇이 다른가

  이 글        방문 집합을 정수로 적고 표를 앞에서 뒤로 채운다   전이 수를 이 글이 쟀다
  python-tsp   아직 안 간 집합을 frozenset 으로 적고 재귀한다    같은 상태를 뒤집어 적었다
  networkx     같은 이름이지만 하한을 내는 다른 절차다           정확한 최솟값이 아니다

  「배송 경로 최적화 제품이 이 절차를 그대로 쓴다」는 것은 이 글이 1 차 출처로 확인하지 못했다
  확인한 것은 위 두 구현 하나씩이다
```

#### 경쟁 설계와의 대조

같은 목표(정확한 최소 투어 비용)를 노리는 다른 절차로 **분기 한정**이 있습니다. 순열을 깊이
우선으로 만들되, 「지금까지 쌓은 비용 + 아직 안 간 도시마다 가장 작은 출발 간선」이 이미 찾아
둔 최선보다 작지 않으면 그 가지를 버리는 설계예요.

```text
두 설계가 하는 일
  이 가이드의 절차  상태를 전부 만들고 각 상태에 값 하나를 남긴다   칸을 2^n · n 개 잡는다
  분기 한정         순서를 만들되 하한으로 가지를 자른다            칸을 3n 개 잡는다

  앞은 「같은 상태로 모이는 것을 합쳐 순열을 안 만든다」 이고,
  뒤는 「순열을 만들되 가망 없는 가지를 안 만든다」 이다
```

두 설계를 같은 거리 행렬·같은 작업에 세우고 **기본 연산 수**를 셌어요 — 상태 하나를 살펴본
한 번과 다음 도시 후보 하나를 살펴본 한 번을 각각 하나로 셉니다. 입력은 격자 위의 점을 잇는 행렬과 모든 거리가 같은 행렬
둘이고, 분기 한정의 첫 상한은 가까운 도시부터 고르는 탐욕 투어에서 얻으므로 난수가 없어요.
**전개 입력만으로 재지 않은 이유**는 도시가 넷일 때 두 계수가 100 언저리여서 어느 쪽이 앞서는지
갈리는 자리를 못 보이기 때문이에요. 전개 입력의 값도 표 맨 위에 함께 둡니다.

| 입력 | 이 가이드의 절차 | 분기 한정 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 전개 입력 (도시 4 개) | 116 | **48** | 분기 한정이 적습니다 |
| 격자 좌표 도시 12 개 | 184,332 | **88,253** | 분기 한정이 2.1 배 적습니다 |
| 격자 좌표 도시 20 개 | 120,586,260 | **20,470,600** | 분기 한정이 5.9 배 적습니다 |
| 모든 거리가 같은 도시 12 개 | **184,332** | 754,471,630 | **여기서 순서가 뒤집힙니다** |

**같은 도시 수에서 행렬의 모양만 바꿔도 순서가 뒤집힙니다.** 도시 12 개에서 격자 좌표면 분기
한정이 88,253 대 184,332 로 앞서는데, 모든 거리가 같은 행렬에서는 754,471,630 대 184,332 로
4,093 배 뒤집혀요. 같은 계열 안에서 도시 수만 늘려도 경계가 나옵니다 — 모든 거리가 같은
행렬에서 분기 한정이 앞서는 마지막 도시 수가 5 개이고, 상태 표가 앞서는 첫 도시 수가 6 개예요.

```text
경계가 그 자리인 이유 — 하한이 얼마나 남는가

  모든 거리가 1 인 행렬에서 분기 한정의 하한 (간선 d 개를 쓴 시점)
    지금까지 쌓은 비용 d + 아직 안 간 도시 수 (n - 1 - d)  =  n - 1
    실제 투어 값은 n 이다 (간선이 n 개다)

  하한 n - 1 이 최선 n 보다 늘 작으므로 「>= best」 가 한 번도 참이 되지 않는다
  가지를 하나도 못 자르고 순열을 전부 만든다 -> 도시 12 개에서 7 억 5 천만 번

  격자 좌표에서는 각 점의 가장 가까운 이웃이 실제로 쓰는 간선과 비슷해 하한이 촘촘하고,
  그래서 가지가 많이 잘린다. 갈림의 축은 도시 수가 아니라 하한과 답 사이의 여유다
```

**저장 칸에서는 이 절차가 늘 더 씁니다.** 도시 20 개에서 20,971,520 칸 대 60 칸이에요. 그러니
이 절차가 내주는 것은 **저장 공간**과 **좋은 입력에서의 속도**이고, 얻는 것은 **최악에서의
보장**입니다 — 분기 한정은 같은 도시 12 개에서 88,253 과 754,471,630 사이로 갈리는데, 이 절차는
같은 도시 수에서 행렬이 무엇이든 계수가 한 자리도 안 움직여요. 그 실측은 「최악을 만드는 입력」에 있습니다.

```text
어떤 자리에서 어느 쪽을 고르는가

  거리가 좌표에서 나왔고 하한이 촘촘하다      분기 한정이 적다 (도시 20 개에서 5.9 배)
  거리가 서로 비슷해 하한이 헐겁다            상태 표가 적다 (도시 12 개에서 4,093 배)
  메모리가 모자란다                           분기 한정만 쓸 수 있다 (60 칸 대 2 천만 칸)
  최악에서의 시간 상한을 약속해야 한다        상태 표만 쓸 수 있다

  입력을 고를 수 없는 자리에서는 최악이 정해진 쪽을 고른다
```

### 수식 정의와 유도

방문 집합을 $S \subseteq \{0, 1, \dots, n-1\}$ 라 하고 현재 위치를 $v \in S$ 라 씁니다.
$dp[S][v]$ 는 도시 0 에서 출발해 $S$ 에 속한 도시를 정확히 한 번씩 들르고 지금 $v$ 에 있는
접두 경로의 최소 비용입니다. 코드에서는 $S$ 를 정수 하나로 적고 그 이름이 `mask` 예요.

$$dp[\{0\}][0] = 0, \qquad dp[S \cup \{u\}][u] = \min_{v \in S,\; u \notin S} \bigl( dp[S][v] + dist[v][u] \bigr)$$

```text
전이가 자르는 자리

  0 ─── … ─── v │ u
  └ S 를 들렀다 ┘ │ └ 새로 들르는 도시
      dp[S][v]        dist[v][u]

  u 를 하나 고르는 것이 「다음에 어디로 갈지」를 하나 고르는 것이다
  u ∉ S 라는 조건이 「정확히 한 번씩」을 식에 적은 것이고, 코드에서는 그 줄이 ⑤ 다
```

정의를 전개 입력의 상태 하나에 넣어 계산해 봅시다. 방문 집합 `1111` 의 위치 2 는 직전 위치가
0 · 1 · 3 중 하나일 수 있고, 그 직전 위치를 $w$ 라 적었어요.

<!--proof:mathCheck-->

```text
dp[1111][2] 를 정의대로 계산한다

직전 위치 w  직전 상태    그 값  dist[w][2]   합
          0  dp[1011][0]    INF          15  INF
          1  dp[1011][1]     45          35   80
          3  dp[1011][3]     35          30   65

정의가 낸 가장 작은 합 65 가 상태 표에 담긴 값 65 와 맞는다
```

직전 위치 0 이 `INF` 인 것은 도시 0 으로 들어오는 전이가 없기 때문이고, 나머지 둘 중 작은
65 가 그 상태의 값입니다. 답은 $S = \{0,\dots,n-1\}$ 에서 복귀 비용을 더한 것 중 최솟값이에요.

$$\text{답} = \min_{v} \bigl( dp[\{0,\dots,n-1\}][v] + dist[v][0] \bigr)$$

```text
정의에서 답까지 남은 한 걸음

  dp[S][v] 는 아직 도시 0 으로 돌아오기 전의 값이다
  S 가 전체 집합이면 남은 일이 복귀 하나뿐이고 그 비용이 dist[v][0] 이다
  v 를 고르는 것이 「마지막으로 어느 도시에 있었는가」를 고르는 것이라 최솟값을 취한다

  v 에 0 을 함께 넣어도 값이 안 바뀐다 — 도시가 둘 이상이면 그 자리가 INF 이기 때문이다
```

이제 **값이 드는 상태와 전이가 각각 몇 개인지** 임의의 $n$ 에 대해 닫습니다. 도시 0 은 어떤
접두 경로에도 들어 있으므로 $0 \in S$ 이고, 현재 위치는 $S$ 안이되 도시 0 은 출발 상태에서만
현재 위치가 될 수 있어요.

```text
상태를 세는 두 무리

  출발 상태            S = {0} · v = 0                       1 개
  그 밖의 상태         0 ∈ S · |S| = k >= 2 · v ∈ S \ {0}    S 를 고르는 수 x (k-1)

  |S| = k 인 S 중 0 을 담은 것은 나머지 n-1 개에서 k-1 개를 고르는 수와 같다
```

$|S| = k$ 이고 $0 \in S$ 인 집합이 $\binom{n-1}{k-1}$ 개이고 그 각각에서 현재 위치가 $k-1$
가지이므로, $j = k-1$ 로 두면 상태의 개수가 다음과 같이 닫힙니다.

$$1 + \sum_{j=1}^{n-1} \binom{n-1}{j} \, j = 1 + (n-1) \, 2^{\,n-2}$$

```text
합을 닫는 한 걸음

  Σ_{j=0}^{m} C(m, j) · j = m · 2^(m-1)      항등식이다 (m = n-1 로 둔다)
  j = 0 항은 0 이라 아래끝을 1 로 올려도 값이 같다
  -> 1 + (n-1) · 2^(n-2)

  n = 4 이면 1 + 3 · 4 = 13 이고, 앞의 실측 표 첫 줄이 13 이다
```

전이의 개수도 같은 방법으로 닫아요. 상태 하나가 만드는 전이는 $n - k$ 개이므로, 출발 상태의
$n-1$ 개에 나머지 상태의 합을 더합니다.

$$(n-1) + \sum_{j=1}^{n-2} \binom{n-1}{j} \, j \, (n-1-j) = (n-1) + (n-1)(n-2) \, 2^{\,n-3}$$

```ts
// 식을 그대로 옮긴 조각. 코드에서는 도시 수가 `n` 이다.
const liveStates = (n: number): number => 1 + (n - 1) * 2 ** (n - 2);
const transitions = (n: number): number =>
  n - 1 + (n - 1) * (n - 2) * 2 ** (n - 3);
```

식에 제약 규모를 넣어 수치를 냅니다. 순열 나열 쪽은 같은 규모에서 몇 자리 수가 되는지 함께
적었어요.

<!--proof:mathScale-->

```text
도시 n        전이         순열 나열의 덧셈  그 자릿수
    10       9,225                1,349,289     7 자리
    15     745,486          324,153,456,004    12 자리
    18   8,912,913    1,322,546,100,500,689    16 자리
    20  44,826,643  452,310,766,371,235,999    18 자리

제약 상한 n = 20 에서 두 값의 비는 10,090,221,709 배다
거리의 상한이 1,000,000 이므로 투어 하나의 비용은 최대 20,000,000 이고
배정밀도 정수 표현의 상한 9,007,199,254,740,991 의 450,359,963 분의 1 이다
```

**본문의 값만으로는 안 나오던 것이 여기서 나옵니다.** 앞의 실측은 도시 18 개까지였고 전개
입력은 전이가 15 개인 한 벌짜리 값인데, 위 유도는 **임의의 $n$ 에 대해** 상태가
$1 + (n-1)2^{n-2}$ 개이고 전이가 $(n-1) + (n-1)(n-2)2^{n-3}$ 개라는 닫힌 형태를 줍니다. 제약
상한에서 그 값이 4,482 만이고 순열 나열의 덧셈보다 100 억 배 적어요.

### 불변식 — dp[mask][v] 는 mask 를 정확히 들르고 v 에서 끝나는 접두 경로의 최소 비용이다

파트 1 의 열일곱 걸음이 보인 것은 거리 행렬 한 벌에서 80 이 나왔다는 사실 하나예요. 그것만으로는
다른 행렬에서도 맞는다고 말할 수 없어요. 그래서 **바깥 반복이 어디까지 갔든 참인 문장** 하나를
세우고, 그것이 걸음마다 참으로 남는지 값으로 확인합니다.

> 바깥 반복이 방문 집합 `mask` 를 처리하기 시작하는 시점에, `dp[mask][v]` 는 **이미 최종값**
> 입니다. 그 값은 도시 0 에서 출발해 `mask` 에 속한 도시를 정확히 한 번씩 들르고 지금 `v` 에
> 있는 접두 경로 중 최소 비용이고, 그런 경로가 없으면 `INF` 입니다.

```text
「이미 최종값」이 뜻하는 것

  dp[mask][v] 를 고칠 수 있는 전이는 어디서 오는가
    도착 상태가 (mask, v) 인 전이의 출발 상태는 (mask 에서 v 를 뺀 집합, w) 다
    그 집합은 mask 보다 자리 하나가 적으므로 정수로도 mask 보다 작다

  정수로 작다 -> 바깥 반복이 먼저 처리한다 -> mask 에 들어오는 시점에 전이가 다 끝났다
  이 한 줄이 「바깥 반복이 오름차순이다」에 걸려 있다
```

문장을 이 모양으로 세운 이유가 있어요. 「최소 비용이다」만 세우면 **언제** 최소인지가 안
정해지고, 그러면 「지금 읽는 값이 이미 확정된 것인가」를 말할 수 없습니다. 「바깥 반복이 그
방문 집합에 들어오는 시점」이 그 답이에요.

**첫 방문 집합에 들어가기 전부터 봅시다.** `mask = 1` 일 때 그 집합은 `{0}` 이고, 그 안의
위치는 0 하나뿐이며 `dp[1][0]` 은 준비 단계가 적은 0 입니다. 도시 0 에서 출발해 `{0}` 만 들른
접두 경로는 「아무 데도 안 갔다」 하나이고 비용이 0 이므로 문장이 참이에요.

| 갈래 | 하는 일 | 왜 문장이 그대로인가 |
| --- | --- | --- |
| 위치가 방문 집합 밖이라 건너뛴다 | 아무것도 안 한다 | 그 상태에 이르는 접두 경로가 없어 `INF` 가 맞다 |
| 값이 `INF` 라 건너뛴다 | 아무것도 안 한다 | 없는 경로에서 이어 붙일 것이 없다 |
| 이미 들른 도시라 건너뛴다 | 그 후보를 버린다 | 두 번 들르는 경로는 이 문장이 세는 대상이 아니다 |
| 도착 상태의 값을 바꾼다 | 더 작은 값을 적는다 | 도착 방문 집합이 지금 것보다 커서 아직 처리 전이다 |
| 값을 안 바꾼다 | 이미 있는 값을 남긴다 | 이미 있는 값이 이 후보보다 작거나 같다 |
| 복귀 비용을 더한다 | 투어 하나의 값을 만든다 | 모든 도시를 들른 방문 집합은 마지막에 처리된다 |

「도착 상태의 값을 바꾼다」 줄이 이 논증에서 가장 좁은 자리예요. 도착 방문 집합은 지금 것에
자리를 하나 더 켠 것이라 **정수로 반드시 크고**, 그래서 바깥 반복이 아직 그 집합을 처리하지
않았습니다. 지금 적는 값이 나중에 읽히는 것이지 이미 읽힌 값을 고치는 것이 아니에요.

횟수는 그 둘에 비례해서 총식의 차수를 바꾸지 않으므로 따로 세지 않았어요.

#### 케이스별 비용과 그 경계

**케이스**는 어떤 입력을 두고 하는 말이고 **경계**는 그 비용이 어떤 종류의 값인가를 두고 하는
말이라, 둘은 서로 다른 축이에요. 축을 섞어 적으면 두 정보가 함께 없어집니다.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`n = 1`) | `O(2^n · n^2)` | `Θ(1)` — 칸 둘을 잡고 반복이 한 바퀴다 |
| **평균적인 경우** (거리 행렬의 분포가 주어지지 않는다) | `O(2^n · n^2)` | 정의할 수 없다 |
| **최악의 경우** (`n ≥ 2` — 거리 행렬이 무엇이든) | `O(2^n · n^2)` | `Θ(2^n · n^2)` — 아래에서 재는 비가 1/8 로 다가간다 |

평균 칸을 비운 것은 **어떤 거리 행렬이 얼마나 자주 오는지를 문제가 말해 주지 않기** 때문이에요.
구현 쪽에도 난수가 한 줄도 없어서 무작위성이 거기서 생기지도 않습니다. 게다가 이 절차는 평균을
정의해도 얻는 것이 없어요 — 아래에서 보듯 거리 행렬을 바꿔도 살펴보는 상태 수와 전이 수가 안
바뀌기 때문입니다.

```text
상한과 타이트한 값을 가르는 자리
  O(2^n · n^2)       이보다 많은 연산은 어떤 입력에서도 없다        상한이다
  Theta(2^n · n^2)   n >= 2 이면 어떤 거리 행렬에서도 그 차수다      타이트한 값이다

  표의 세 줄은 전부 최악 보장이다. 기댓값이 아니고 입력 분포를 쓰지도 않는다
  이 절차에서는 그 최악 보장과 실제 연산 수가 같은 값이다. 아래가 그 실측이다
```

<!--proof:perfObserved-->

```text

     6               870        165        165           0.0716
    10            33,290      9,225      9,225           0.0901
    14           974,862    319,501    319,501           0.0995
    18        24,772,626  8,912,913  8,912,913           0.1049

마지막 열이 1/8 = 0.125 로 다가간다 — 전이 수가 2^n·n² 의 상수배다
```

**「전이 / (2^n·n²)」 열이 도시 6 개에서 0.0716, 18 개에서 0.1049 입니다.** 닫힌 형태
$(n-1)(n-2)2^{n-3}$ 을 $2^n n^2$ 로 나누면 $n$ 이 커질수록 $1/8 = 0.125$ 로 다가가고, 실측이
그 값을 아래에서 따라갑니다. 상수 $1/8$ 은 「방문 집합이 도시 0 을 담아야 한다」 · 「현재
위치가 그 안이어야 한다」 · 「다음 도시가 그 밖이어야 한다」 셋이 각각 절반씩 자른 결과예요.

21 개면 336 MiB 로 넘어요. 제약이 20 인 것은 비트 폭이 아니라 이 자리에서 정해진 값입니다.
비트 폭이 실제로 실패하는 곳은 훨씬 뒤인 도시 31 개이고, 32 개에서는 더 나쁜 일이 일어나요 —
`1 << 32` 가 1 이 되면서 `FULL` 이 0 이 되고, 예외도 없이 `INF` 를 돌려줍니다.

```text
셋 중 무엇이 먼저 막는가

  메모리        도시 21 개에서 336 MiB > 256 MB          여기가 실제 경계다
  비트 폭       도시 31 개에서 FULL 이 음수가 된다        RangeError 를 던진다
  정수 합       거리 상한 10^6 x 도시 20 개 = 2,000 만    9,007,199,254,740,991 의 4 억 5 천만 분의 1

  셋째 줄은 아예 걸리지 않는다. 투어 비용이 배정밀도 정수 표현의 상한에 4 억 5 천만 배 못 미친다
  「비트를 쓰니 정수 한계를 조심하라」 가 여기서는 합이 아니라 자리 수의 문제다
```

| 최악으로 만들 축 | 그 축을 최대로 만드는 입력 | 값 |
| --- | --- | --- |
| 전이 수 | 도시 수를 상한까지 올린다 — 거리 값은 무관하다 | 도시 20 개에서 44,826,643 |
| 값을 바꾼 횟수 | 비용 0 짜리 순환이 있는 행렬 | 도시 12 개에서 18,955 |
| 저장 칸 | 도시 수를 상한까지 올린다 | 20,971,520 칸 · 160 MiB |

**여기서 잰 무리는 도시 12 개짜리 행렬 다섯입니다.** 둘째 줄의 「값을 바꾼 횟수」는 그 다섯
안에서의 최대이고, 더 큰 값을 내는 행렬이 있는지는 확인하지 않았어요. 다른 도시 수에서도
「살펴본 상태 수가 행렬과 무관하다」가 유지되는지는 닫힌 형태가 답하고, 그 닫힌 형태를 도시
4 · 8 · 12 · 16 · 18 개에서 실측과 대조한 표가 앞에 있습니다.

### 스스로 점검하기

여기까지를 한 문단으로 줄이면 이렇습니다. 접두 경로를 「들른 도시의 집합」과 「지금 있는
도시」 둘로 요약하면 순서가 다른 경로들이 같은 상태로 모이고, 그 상태마다 최소 비용 하나만
남기면 세는 대상이 순열 `(n-1)!` 개에서 상태 `2^n · n` 칸으로 바뀌어요. 방문 집합을 정수로
적어 작은 것부터 처리하는 것이 그 표를 채우는 순서입니다.

```text
1.  상태 표를 INF 로 채우고 출발 상태 한 칸에만 0 을 적는다
2.  방문 집합 mask 를 1 부터 FULL 까지 차례로 처리한다
3.  mask 안에 있으면서 값이 든 위치 v 마다, 아직 안 간 도시 u 로 전이를 만든다
4.  도착 상태 (mask | (1 << u), u) 의 값이 더 크면 새 값으로 바꾼다
5.  마지막에 dp[FULL][last] + dist[last][0] 중 최솟값을 돌려준다
```

답이 함께 붙는 문제부터 하나 냅니다. 전개의 T8 에서 `dp[1111][3]` 을 만들려는 후보가 둘이었는데
접두 비용은 50 과 45 로 달랐고 합은 둘 다 75 였어요. 왜 합이 같아졌을까요?

```text
T8 의 두 후보
  dp[0111][1] = 50 에서 u = 3   50 + dist[1][3] = 50 + 25 = 75
  dp[0111][2] = 45 에서 u = 3   45 + dist[2][3] = 45 + 30 = 75
```

<!--check:whyTieAtT8-->
**뒤에 붙는 간선의 차이가 앞의 차이를 정확히 메웠기 때문입니다.** 접두 비용의 차이가
50 − 45 = 5 이고 마지막 간선의 차이가 30 − 25 = 5 라, 두 합이 나란히 75 가 됩니다. 두 접두
경로는 `0 → 2 → 1` 과 `0 → 1 → 2` 로 들른 집합이 `{0,1,2}` 로 같고 끝점만 1 과 2 로 달라요.

```text
쓰는 간선이 서로 다른데도 합이 같다
  0 -> 2 -> 1 -> 3   15 + 35 + 25 = 75
  0 -> 1 -> 2 -> 3   10 + 35 + 30 = 75

이 동점은 이 거리 행렬의 값이 만든 우연이지 대칭성이 보장하는 것이 아니다
대칭 행렬에서 「같은 순환을 반대로 읽어 값이 같아지는」 자리는 T17 의 80 두 줄이고, 여기가 아니다
```

**동점이든 아니든 코드가 하는 일은 같습니다.** ⑥ 은 「이미 있는 값보다 작은가」만 보므로,
같은 값이 두 번째로 오면 적지 않아요 — T8 둘째 줄의 판정이 그것입니다.
<!--/check-->

  가지가 하나도 안 잘렸습니다. 그렇다면 하한에 「마지막에 도시 0 으로 돌아오는 간선」을 하나
  더 더하면 어떻게 될까요? 그 하한이 여전히 옳은 하한인지 먼저 따지고,
  `tspBitmask-guide.alt.ts` 의 하한 식을 고쳐 도시 12 개에서 다시 세어 보세요.
- 「그 검사를 빼도 답이 안 틀리는 입력이 있다」에서 전개 입력은 답이 80 그대로였는데 상태 표는
  7 칸이 어긋나 있었습니다. 어긋난 7 칸이 어떤 방문 집합의 어떤 위치인지 먼저 예측하고,
  그 칸들이 왜 답에는 영향을 주지 못했는지 T17 의 복귀 계산으로 설명해 보세요.
- 「최악을 만드는 입력」에서 「값을 바꾼 횟수」만 행렬에 따라 갈렸고 폭이 1.7 배였습니다. 이
  횟수를 최대로 만드는 행렬은 어떤 모양일지 예측하고, 도시 12 개에서 실제로 세어 보세요.
  전이 하나가 값을 바꾸려면 이미 있는 값보다 작아야 한다는 것과, 전이가 도착 상태에 오는
  순서가 방문 집합의 정수 크기로 정해진다는 것 둘이 답의 재료입니다.
