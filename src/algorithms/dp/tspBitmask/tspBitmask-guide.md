# 비트마스크 외판원 순회 — 방문 순서를 지우고 들른 도시 집합만 남기면 순서가 DP 테이블 칸으로 줄어드는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 방문 순서를 전부
만들어 보는 방법에서 출발해 (들른 도시 집합, 지금 도시) 쌍마다 칸을 두는 DP 테이블까지 가고, 그 DP 테이블을
단계마다 값으로 푼 뒤, 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

도시 `n` 개와, 도시 사이를 옮겨 가는 비용을 적은 `n × n` 행렬이 있습니다. **도시 0 에서 출발해 모든 도시를
정확히 한 번씩 들르고 도시 0 으로 돌아오는 경로**를 순회라고 부르고, 이 글은 순회 가운데 비용 합이 가장 작은
것의 비용을 구합니다. 이 과제를 외판원 순회 문제(traveling salesman problem, TSP)라고 불러요. 가는 비용과 오는
비용은 달라도 됩니다. 도시 넷의 비용 행렬과 답은 이렇습니다.

<!--proof:concept-matrix-->

| 출발 도시 | 도착 0 | 도착 1 | 도착 2 | 도착 3 |
| --- | ---: | ---: | ---: | ---: |
| 도시 0 | 0 | 10 | 15 | 20 |
| 도시 1 | 10 | 0 | 35 | 25 |
| 도시 2 | 15 | 35 | 0 | 30 |
| 도시 3 | 20 | 25 | 30 | 0 |

순서 6 가지 가운데 비용이 가장 작은 순회는 0 → 1 → 3 → 2 → 0 이고, 비용 합은 10 + 25 + 30 + 15 = 80 입니다. 정본 tspBitmask(전개 입력) 이 낸 값도 80 입니다.

<!--/proof-->

같은 행렬을 그림으로 옮기면 이렇습니다. 이 행렬은 가는 비용과 오는 비용이 같아서 선 하나에 비용 하나를 적었고,
굵은 선이 비용이 가장 작은 순회예요.

<!--fig:concept-tour-->
![도시 넷과 비용이 가장 작은 순회 — 굵은 선이 순회, 흐린 선은 순회에 쓰지 않은 길](./figs/concept-tour.svg)

방문 순서를 전부 만들어 보면 답은 나오지만, 도시 0 을 맨 앞에 두고 나머지 `n-1` 개 도시를 늘어놓는 순서가
`(n-1)!` 가지라 도시가 조금만 늘어도 다 만들 수 없게 됩니다. 그래서 순서를 만들지 않고 **(들른 도시 집합, 지금
도시) 쌍마다 칸 하나에 그 쌍까지 오는 가장 작은 비용을 적어 두는 표**를 씁니다. 여기까지 어떤 순서로 왔든, 앞으로
드는 비용은 어느 도시를 이미 들렀는가와 지금 어디 있는가에만 달려 있기 때문이에요. 작은 입력의 답을 칸에 적어
두고 큰 입력의 답을 그 칸들에서 만드는 이런 표를 **DP 테이블**이라고 부릅니다. DP 는 동적 계획법(dynamic
programming)의 줄임말이고, 이 방법 전체는 Held–Karp 알고리즘이라는 이름으로도 알려져 있습니다.

들른 도시 집합은 정수 하나로 적습니다. 도시 `i` 를 들렀으면 정수의 자리 `i` 를 1 로 두는 **비트마스크**예요.
`1011₂` 는 자리 0 · 1 · 3 이 1 이라 도시 0 · 1 · 3 을 들렀다는 뜻이고, 이 글은 비트마스크를 이진 표기 끝에 `₂`
를 붙여 적습니다. DP 테이블의 줄이 이 비트마스크, 열이 지금 도시예요. 전개 입력의 DP 테이블을 다 채운 모습은
이렇습니다. 대시 칸은 지금 도시가 들른 집합 밖이라 쓸 일이 없는 칸이고, 점선 칸은 그 칸에 이르는 경로가 없어
값이 없는 칸입니다.

<!--fig:concept-table-->
![tspBitmask(전개 입력) 의 DP 테이블 — 줄은 들른 도시 집합, 열은 지금 도시](./figs/concept-table.svg)

모든 도시를 들른 줄 `1111₂` 의 칸 70 · 65 · 75 에 도시 0 으로 돌아오는 비용을 더한 것 가운데 가장 작은 80 이
답입니다. 칸은 `2^n · n` 개이고 칸 하나에서 다음 도시 후보를 `n` 개 보므로, 비용은 결과만 적으면
`O(2^n · n²)` 이고 메모리는 `O(2^n · n)` 이에요. 세는 대상이 순서에서 칸으로 바뀐 크기를 나란히 놓으면 이렇습니다.

<!--proof:concept-size-->

```text
도시 n         방문 순서 (n-1)!  DP 테이블 칸 2^n·n
     4                        6                  64
    20  121,645,100,408,832,000          20,971,520
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **비트마스크로 집합을 적는 법.** `mask & (1 << i)` 가 0 이 아니면 도시 `i` 가 집합에 있고, `mask | (1 << i)` 는
  도시 `i` 를 더한 집합입니다. 이 표기가 낯설면 [서브마스크 열거](../../bit-manipulation/enumerateSubmasks/enumerateSubmasks-guide.md)
  가이드의 「전체 컨셉」이 비트 자리와 원소의 대응을 처음부터 세웁니다. 이 글은 비트 연산 자체를 다시 설명하지
  않아요.
- **DP 테이블.** 칸마다 작은 입력의 답을 적어 두는 표입니다. 칸 하나를 읽는 법은
  [동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) 의 「먼저 알아 둘 개념 — DP 테이블」 절이,
  줄마다 한 가지를 더 보는 모양은 [0/1 배낭](../knapsack01/knapsack01-guide.md) 이 풀어 둡니다.
- **단순 경로를 깊이 우선으로 전부 만드는 법.** 떠올리는 과정의 출발점인 「방문 순서를 전부 만들기」가 이것이고,
  되돌아갈 때 표시를 지워 다음 경로를 만드는 방법은 [모든 단순 경로 열거](../../graph/dfsAllPaths/dfsAllPaths-guide.md)
  가 다룹니다.
- **인접 행렬로 준 그래프.** `dist[i][j]` 가 도시 `i` 에서 `j` 로 가는 비용이고, 이 과제에서는 모든 도시 쌍 사이에
  길이 있습니다. 행렬로 준 그래프를 다루는 예는 [플로이드-워셜](../../shortest-path/floydWarshall/floydWarshall-guide.md)
  에 있어요.
- **「아직 없음」을 값으로 적는 관례.** 아직 이르는 경로가 없는 칸을 `Number.POSITIVE_INFINITY` 로 두고 `INF` 라
  적습니다. 어떤 유한한 비용보다 커서 가장 작은 값을 고를 때 저절로 빠져요.

| 이미 아는 것 | 이 글에서 쓰이는 자리 |
| --- | --- |
| 비트마스크 | DP 테이블의 줄 번호 · 「이미 들른 도시인가」 검사 |
| DP 테이블 | (들른 도시 집합, 지금 도시) 쌍마다 칸 하나 |
| 단순 경로 열거 | 반박할 출발점 — 방문 순서를 전부 만들기 |
| 인접 행렬 | 이동 비용 `dist[v][u]` |
| `INF` | 이르는 경로가 없는 칸 |

이 글이 구하는 것은 **정확한** 비용이 가장 작은 순회 비용이고, 답에 오차를 허용하는 근사는 다루지 않아요. 도시를 모두
들르지 않고 정해진 몇 곳만 들르는 과제도 이 글의 대상이 아닙니다.

### 아이디어를 떠올리는 과정 — 방문 순서를 전부 만들기에서 (들른 도시 집합, 지금 도시) DP 테이블까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 비용 행렬을 받아 비용이 가장 작은 순회의 비용을
돌려줍니다.

```ts
function tspBitmask(dist: number[][]): number;
```

- 입력: `n × n` 비용 행렬 `dist`. `dist[i][j]` 는 도시 `i` 에서 도시 `j` 로 가는 비용이고 `dist[i][i]` 는 0 입니다.
  `dist[i][j]` 와 `dist[j][i]` 가 달라도 됩니다.
- 출력: 도시 0 에서 출발해 모든 도시를 정확히 한 번씩 들르고 도시 0 으로 돌아오는 가장 작은 비용 하나. 어떤 순서였는지는
  돌려주지 않아요. 도시가 하나면 움직일 곳이 없어 0 입니다.
- 규모: 도시는 20 개까지, 비용은 0 이상 `10^6` 이하의 정수입니다. 도시 수의 위 끝을 20 으로 잡은 것은 이 글의
  DP 테이블이 흔한 채점 환경의 메모리 예산 256 MB 에 드는 마지막 도시 수가 20 이라서예요 — 그 계산은
  「아이디어 상세」 1단계에 있습니다. 시간은 같은 환경의 예산인 1 초에 대어 잽니다.

이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 가리키는 것 | 이 과제에서 |
| --- | --- | --- |
| `n` | 도시의 개수. 코드의 `dist.length` | `1 ≤ n ≤ 20` |
| `dist[i][j]` | 도시 `i` 에서 도시 `j` 로 가는 비용 | 0 이상 `10^6` 이하의 정수 |
| `mask` | 들른 도시 집합. 자리 `i` 가 1 이면 도시 `i` 를 들렀다 | DP 테이블의 줄 번호 |
| `FULL` | 모든 도시를 들른 집합. 자리 `n` 개가 전부 1 | `2^n − 1` |
| `v` | 지금 도시 | DP 테이블의 열 번호, `0` 부터 `n-1` |
| `u` | 다음에 갈 도시 | `0` 부터 `n-1` |
| `dp[mask][v]` | 도시 0 에서 출발해 `mask` 의 도시를 한 번씩 들르고 지금 `v` 에 있는 접두 경로 가운데 가장 작은 비용 | DP 테이블의 칸 하나 |
| `INF` | 그 칸에 이르는 접두 경로가 아직 없다는 표기 | `Number.POSITIVE_INFINITY` |

접두 경로는 도시 0 에서 출발해 여기까지 온 이동 순서, 곧 순회의 앞부분입니다. 비용은 이 글 끝까지 **기본 연산**
하나로 셉니다. 경로를 만들다가 지금 자리(순서를 만드는 방법에서는 호출 하나, DP 테이블에서는 칸 하나)를 살펴본 한 번,
다음 도시 후보 하나를 살펴본 한 번, 도시 0 으로 돌아오는 비용을 더해 본 한 번이 각각 하나예요. 메모리는 DP 테이블의
칸 수에 칸 하나의 8 바이트를 곱해 세고, 1 MB 는 `10^6` 바이트입니다.

가장 먼저 떠오르는 방법으로 시작합시다. **도시 0 을 맨 앞에 두고 나머지 도시의 순서를 전부 만들어** 순회 비용을
잽니다. 깊이 우선으로 아직 안 간 도시를 하나씩 붙이고, 되돌아갈 때 표시를 지우면 순서가 하나씩 나와요.

```ts
function 순서전부(dist: number[][]): number {
  const n = dist.length;
  const used = new Array<boolean>(n).fill(false);
  used[0] = true;
  let best = Number.POSITIVE_INFINITY;
  const go = (at: number, count: number, cost: number): void => {
    if (count === n) {
      best = Math.min(best, cost + (dist[at]?.[0] as number)); // 순서 하나를 다 만들었다
      return;
    }
    for (let u = 1; u < n; u++) {
      if (used[u]) continue;
      used[u] = true;
      go(u, count + 1, cost + (dist[at]?.[u] as number));
      used[u] = false;
    }
  };
  go(0, 1, 0);
  return best;
}
```

전개 입력의 도시 넷으로 실제로 만들어 보면 순서가 여섯 가지입니다.

<!--proof:origin-orders-->

```text
방문 순서          구간 비용          합계
0 → 1 → 2 → 3 → 0  10 + 35 + 30 + 20    95
0 → 1 → 3 → 2 → 0  10 + 25 + 30 + 15    80
0 → 2 → 1 → 3 → 0  15 + 35 + 25 + 20    95
0 → 2 → 3 → 1 → 0  15 + 30 + 25 + 10    80
0 → 3 → 1 → 2 → 0  20 + 25 + 35 + 15    95
0 → 3 → 2 → 1 → 0  20 + 30 + 35 + 10    95

순서 6 개 · 호출 16 번 · 기본 연산 52 번
가장 작은 합계 80
```

여섯 가지 가운데 가장 작은 것이 80 입니다. 도시가 넷이라 여섯 번으로 끝났지만, 이 방법이 만드는 순서는 도시 수의
계승을 따라 늘어나요. 생성식 행렬 `dist[i][j] = ((7i + 13j) mod 90) + 1` 에 도시 수를 늘려 가며 두 방법의 기본
연산을 세었습니다. DP 테이블 쪽은 뒤에서 만들 방법을 미리 같은 입력에 실행한 값이에요.

<!--proof:origin-scale-->

```text
도시 n  순서 (n-1)!  순서 나열의 기본 연산  DP 테이블의 기본 연산      비
     4            6                     52                    116  0.4 배
     6          120                  1,476                    870  1.7 배
     8        5,040                 79,360                  5,640   14 배
    10      362,880              6,961,060                 33,290  209 배

도시 20 개에서 (닫힌 식으로 센 값)
  순서 나열의 기본 연산        4,423,701,511,889,104,000 (19 자리)
  DP 테이블의 기본 연산        120,586,260 (9 자리)
  1 초에 1 억 번으로 어림하면  순서 나열 약 1,402 년 · DP 테이블 약 1.21 초
```

**도시 넷에서는 순서를 만드는 쪽이 오히려 적습니다.** DP 테이블은 줄 15 개의 칸 60 개를 모두 살펴보는 값이 먼저 들기 때문이에요.
그런데 도시 여섯에서 순서가 뒤집히고, 열에서는 209 배가 됩니다. 도시 20 개에서는 순서를 만드는 쪽의 기본 연산이
19 자리 수라, 1 초에 1 억 번으로 어림하면 1,400 년쯤 걸려요. **순서를 전부 만드는 길은 여기서 막힙니다.** 같은 어림으로 DP 테이블은 1.21 초라
예산 1 초의 언저리예요. 1 초에 1 억 번은 단순 연산의 종류를 가리지 않고 하나로 센 거친 어림이라, 1.21 초는 예산을 넘는다는
판정이 아니라 예산 안팎이라는 뜻으로 읽습니다. 이 어림이 몇 배 틀려도 달라지지 않는 것은 두 방법이 열 자리 넘게 벌어진다는 사실이에요.

그러면 순서들 안에 되풀이하는 일이 얼마나 섞여 있는지 봅시다. 도시 다섯짜리 행렬에서 순서가 다른 접두 경로 둘이
같은 도시들을 들르고 같은 도시에 선 자리를 골라, 거기서부터 남은 도시를 들르고 돌아오는 가장 작은 비용을 따로
계산해 나란히 놓았어요.

<!--proof:origin-order-free-->

```text
접두 경로      들른 도시         지금 도시  접두 비용  남은 최소 비용  합
0 → 1 → 2 → 3  01111₂ {0,1,2,3}          3          7               9  16
0 → 2 → 1 → 3  01111₂ {0,1,2,3}          3         24               9  33

남은 최소 비용이 두 줄 모두 9 — 접두 비용이 큰 쪽은 어떤 순회에서도 답이 못 된다
칸 (01111₂, 3) 에 남길 값은 7 하나

도시 12 개(생성식 행렬)에서 순서 나열의 호출 108,505,112 번이
값이 든 칸 11,265 개로 모인다 — 9,632 배
```

**남은 최소 비용이 두 줄에서 같습니다.** 들른 도시와 지금 도시가 같으면 남은 도시와 출발점이 같아서, 앞으로 할 수
있는 일이 글자 그대로 같기 때문이에요. 그러니 접두 비용이 24 인 쪽은 어떤 순회에서도 답이 될 수 없고, 그 쌍에는
7 하나만 남기면 됩니다. 이렇게 합치면 비용이 **남기는 항목의 수**로 바뀌어요. 도시 12 개에서는 순서를 만드는 쪽이
들어가는 호출 1 억 850 만 번이 값이 든 칸 11,265 개로 모이고, 9,632 배 차이입니다.

```text
무엇이 앞으로의 비용을 정하는가

  들른 도시의 집합     남은 도시가 무엇인지를 정한다       앞으로 갈 수 있는 곳
  지금 도시            다음 이동의 출발점을 정한다         다음 비용 dist[v][u] 의 앞 첨자
  들른 순서            앞으로 하는 일에 영향이 없다        버려도 되는 것
```

합치는 기준을 정합시다. 가장 단순한 후보부터 시험합니다. **들른 도시 집합 하나만** 기억하고 지금 도시는 기억하지
않는 것이에요. 칸이 `2^n` 개로 가장 적습니다. 다만 다음 이동 비용 `dist[v][u]` 의 `v` 가 없으니, 집합 안의 도시
가운데 출발 비용이 가장 작은 도시를 골라 쓸 수밖에 없어요. 그렇게 만든 판을 실행하면 이렇게 나옵니다.

<!--proof:origin-mask-only-->

```text
입력                     정본  들른 집합만 둔 판  차이
전개 입력 (도시 넷)        80                 55    25
지름길이 생기는 도시 넷    10                  7     3
생성식 도시 여섯          216                146    70
생성식 도시 여덟          208                103   105
비대칭 도시 셋              3                  3     0

들른 집합만 둔 판은 집합 안의 어느 도시에서든 출발할 수 있는 것처럼 세므로
하나의 경로로 이어지지 않는 구간을 골라 답보다 작은 값을 낸다
```

**전개 입력에서 80 이어야 할 답이 55 로 나옵니다.** 지금 도시를 지우면 「도시 2 에 있는데 도시 1 에서 출발하는
비용을 골라 쓰는」 일이 생기고, 그렇게 고른 구간들은 하나의 경로로 이어지지 않아요. 생성식 도시 여덟에서는 208 과
103 으로 차이가 105 까지 벌어집니다. 비대칭 도시 셋에서는 답이 우연히 맞는데, 답이 맞는 입력이 섞여 있다는 것이 이
판을 더 알아채기 어렵게 만들어요. 합치는 기준에 **지금 도시**가 함께 들어가야 합니다. 지금까지 해 본 방법을 차례로
놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **(들른 도시 집합, 지금 도시) DP 테이블**입니다. 줄은 들른 도시 집합의 비트마스크
`mask`, 열은 지금 도시 `v` 이고, 칸 `dp[mask][v]` 에 가장 작은 접두 경로 비용을 적어요. 칸을 어떤 차례로 채우는지,
칸 하나가 어느 칸에서 값을 받는지, 왜 그 차례면 모든 칸이 제때 채워지는지는 다음 절에서 실현하는 순서대로
확인합니다.

### 아이디어 상세 — (들른 도시 집합, 지금 도시) DP 테이블

이 아이디어를 한 문장으로 줄이면 이렇습니다. **들른 도시 집합을 비트마스크로 적어 DP 테이블의 줄 번호로 쓰고,
작은 줄부터 값이 든 칸마다 아직 안 간 도시로 옮겨 간 비용을 뒤 줄의 칸에 적은 뒤, 모든 도시를 들른 줄에서
돌아오는 비용을 더해 가장 작은 것을 고릅니다.** 줄 번호가 비트마스크인 표는 처음 보면 낯설어서, 그 생김새를 먼저
따로 설명하고 실현하는 순서대로 세 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 처음 한 번 | 1단계 크기와 출발 칸 정하기 | `2^n` 줄 × `n` 칸을 `INF` 로 채우고 `dp[0001₂][0]` 에 0 을 적는다 | — |
| 방문 집합마다 | 2단계 작은 줄부터 뒤 줄로 전이 쓰기 | 값이 든 칸에서 아직 안 간 도시로 옮긴 비용을 도착 칸에 적는다 | 1단계의 출발 칸 · 앞 줄들이 적은 값 |
| 마지막 한 번 | 3단계 복귀 비용 더하기 | 줄 `FULL` 의 칸마다 `dist[v][0]` 을 더해 가장 작은 것을 고른다 | 2단계가 채운 줄 `FULL` |

#### 먼저 알아 둘 개념 — 줄 번호가 비트마스크인 DP 테이블

이 DP 테이블은 줄이 「몇 번째」가 아니라 「**어떤 도시들**」을 뜻한다는 점에서 이웃한 DP 편들의 표와 다릅니다.
배낭 가이드의 줄은 본 물건의 수라 위에서 아래로 한 줄씩 늘어나지만, 이 표의 줄 번호는 집합을 적은 정수라 줄
사이의 관계가 비트 자리로 정해져요. 여섯 가지로 나눠 설명합니다.

##### 칸 하나의 뜻

**줄 하나는 들른 도시 집합 하나이고, 칸 하나는 그 집합을 정확히 한 번씩 들른 뒤 지금 도시에 서 있는 모든 접두
경로 가운데 가장 작은 비용**입니다. 식으로 적으면 `dp[mask][v]` 이고, 그런 접두 경로가 하나도 없으면 `INF` 예요.
도시가 `n` 개면 집합이 `2^n` 개라 줄이 `2^n` 개이고, 줄마다 지금 도시 `n` 개만큼 칸이 있습니다.

##### 전개 입력 위의 모습

전개 입력의 DP 테이블은 「전체 컨셉」에서 한 장으로 보였습니다. 줄마다 들른 도시와, 그중 값이 든 칸을 적으면
이렇습니다.

<!--proof:build-rows-->

| 줄 | 들른 도시 | 지금 도시가 될 수 있는 열 | 값이 든 칸 |
| --- | --- | --- | --- |
| 0000₂ | {} | 없음 | 없음 |
| 0001₂ | {0} | 0 | v=0: 0 |
| 0010₂ | {1} | 1 | 없음 |
| 0011₂ | {0,1} | 0 · 1 | v=1: 10 |
| 0100₂ | {2} | 2 | 없음 |
| 0101₂ | {0,2} | 0 · 2 | v=2: 15 |
| 0110₂ | {1,2} | 1 · 2 | 없음 |
| 0111₂ | {0,1,2} | 0 · 1 · 2 | v=1: 50 · v=2: 45 |
| 1000₂ | {3} | 3 | 없음 |
| 1001₂ | {0,3} | 0 · 3 | v=3: 20 |
| 1010₂ | {1,3} | 1 · 3 | 없음 |
| 1011₂ | {0,1,3} | 0 · 1 · 3 | v=1: 45 · v=3: 35 |
| 1100₂ | {2,3} | 2 · 3 | 없음 |
| 1101₂ | {0,2,3} | 0 · 2 · 3 | v=2: 50 · v=3: 45 |
| 1110₂ | {1,2,3} | 1 · 2 · 3 | 없음 |
| 1111₂ | {0,1,2,3} | 0 · 1 · 2 · 3 | v=1: 70 · v=2: 65 · v=3: 75 |

16 줄 가운데 도시 0 을 담은 줄이 8 줄이고, 값이 든 칸은 모두 13 개입니다.

<!--/proof-->

도시 0 을 담지 않은 줄에는 값이 든 칸이 하나도 없습니다. 모든 접두 경로가 도시 0 에서 출발하니 들른 도시 집합에
도시 0 이 늘 들어 있기 때문이에요. 도시 0 을 담은 줄에서도 지금 도시가 0 인 칸은 출발 칸 `dp[0001₂][0]` 하나만
값이 있습니다. 도시 0 으로 되돌아가는 것은 모든 도시를 들른 뒤의 복귀뿐이라서요.

##### 칸 하나를 읽는 법

칸 `dp[1111₂][2]` 를 골라 읽어 보겠습니다. 줄 `1111₂` 는 자리 넷이 다 1 이라 도시 0 · 1 · 2 · 3 을 모두 들렀다는
뜻이고, 열 2 는 지금 도시 2 에 서 있다는 뜻이에요. 그림에서 대시로 그린 칸은 이번에 보지 않는 칸입니다.

<!--fig:build-read-cell-->
![dp[1111₂][2] — 들른 도시가 {0,1,2,3} 이고 지금 도시가 2 인 접두 경로의 가장 작은 비용](./figs/build-read-cell.svg)

그런 접두 경로를 모두 적으면 둘입니다.

<!--proof:build-read-one-->

| 접두 경로 | 구간 비용 | 비용 합 |
| --- | --- | ---: |
| 0 → 1 → 3 → 2 | 10 + 25 + 30 | 65 |
| 0 → 3 → 1 → 2 | 20 + 25 + 35 | 80 |

들른 도시가 {0,1,2,3} 이고 도시 2 에서 끝나는 접두 경로는 2 개이고, 가장 작은 것이 65 입니다. DP 테이블의 dp[1111₂][2] 도 65 입니다.

<!--/proof-->

두 경로는 들른 도시와 지금 도시가 같고 순서만 다릅니다. 칸은 그 둘을 한 자리에 모아 비용이 작은 쪽 65 만 남긴 것이에요.

##### 칸끼리의 관계

같은 줄의 이웃 칸은 **같은 도시들을 들렀지만 지금 서 있는 도시가 다른** 칸입니다. 줄 `1111₂` 의 70 · 65 · 75 는
모두 네 도시를 다 들른 접두 경로인데 끝이 도시 1 · 2 · 3 으로 달라요. 줄 사이의 관계는 비트 자리 하나로 정해집니다.
칸 `dp[mask][v]` 에 이르는 접두 경로의 바로 앞 칸은 **지금 도시 `v` 의 자리만 끈 줄**에 있어요. `dp[1111₂][2]` 라면
자리 2 를 끈 줄 `1011₂` 의 칸들이고, 그 칸에서 도시 2 로 가는 비용을 더한 것 가운데 가장 작은 것이 이 칸의
값입니다. 진한 테를 두른 칸이 기대는 칸, 강조색 굵은 테가 값을 받는 칸이에요.

<!--fig:build-relation-->
![dp[1111₂][2] 이 기대는 칸 — 도시 2 를 끈 줄 1011₂ 의 값 든 칸](./figs/build-relation.svg)

<!--proof:build-relation-->

| 바로 앞 도시 w | 기대는 칸 | 그 칸의 값 | dist[w][2] | 합 |
| ---: | --- | ---: | ---: | ---: |
| 0 | dp[1011₂][0] | INF | 15 | INF |
| 1 | dp[1011₂][1] | 45 | 35 | 80 |
| 3 | dp[1011₂][3] | 35 | 30 | 65 |

도시 2 를 끈 줄 1011₂ 의 칸 3 개에 이동 비용을 더한 합 가운데 가장 작은 것이 65 이고, dp[1111₂][2] 의 값 65 와 같습니다.

<!--/proof-->

자리 하나를 끈 줄은 정수로 늘 더 작습니다. 비트 하나가 1 에서 0 이 되면 그 자리의 값 `2^v` 만큼 줄어드니까요.
그래서 칸이 기대는 줄은 모두 자기보다 번호가 작은 줄이고, 이것이 2단계에서 채우는 차례를 정합니다.

##### 줄을 움직인 횟수로 둔 표와의 차이

배낭 가이드를 읽었다면 줄을 「지금까지 몇 번 움직였는가」로 두는 표를 먼저 떠올리기 쉽습니다. 줄이 `n` 개뿐이라
칸이 훨씬 적어요. 같은 전개 입력에 그 모양을 그려 보면 이렇습니다.

<!--fig:build-contrast-->
![줄을 움직인 횟수로 둔 판 — 같은 입력에서 답이 40](./figs/build-contrast.svg)

<!--proof:build-contrast-->

| 입력 | DP 테이블 칸 | DP 테이블의 답 | 움직인 횟수 판의 칸 | 움직인 횟수 판의 답 | 답의 이동 순서 |
| --- | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 64 | 80 | 16 | 40 | 0 → 1 → 0 → 1 → 0 |
| 비대칭 도시 셋 | 24 | 3 | 9 | 3 | 0 → 1 → 2 → 0 |
| 지름길이 생기는 도시 넷 | 64 | 10 | 16 | 8 | 0 → 2 → 1 → 2 → 0 |
| 도시 다섯 | 160 | 12 | 25 | 12 | 0 → 4 → 3 → 1 → 2 → 0 |

4 입력 가운데 2 입력에서 움직인 횟수 판의 답이 DP 테이블의 답보다 작습니다.

<!--/proof-->

전개 입력에서 답이 80 이 아니라 40 으로 나오고, 그 경로는 `0 → 1 → 0 → 1 → 0` 입니다. 움직인 횟수만 적으면 어느
도시를 이미 들렀는지 모르니, 비용이 작은 길을 오가며 같은 도시를 되풀이해 들르는 경로를 막지 못해요. 도시 다섯에서는 답이
우연히 맞지만, 칸 하나가 「어느 도시들을 들렀는가」를 담지 않는 한 그 답은 믿을 수 없습니다.

##### 줄이 들른 도시 집합이어야 하는 까닭

과제는 **모든 도시를 정확히 한 번씩** 들르라고 합니다. 앞으로 갈 수 있는 도시가 무엇인지는 이미 들른 도시의 집합이
정하고, 다음 이동 비용은 지금 도시가 정해요. 두 가지를 다 담는 가장 작은 칸이 (들른 도시 집합, 지금 도시) 쌍이고,
집합을 비트마스크 정수로 적으면 그 정수가 곧 배열의 줄 번호가 됩니다. 집합을 찾는 데 해시 표도 비교도 필요 없어요.

```text
칸이 담아야 하는 것과 그것을 담는 자리

  남은 도시가 무엇인가   ->  들른 도시 집합   ->  줄 번호 mask (비트 자리 i 가 도시 i)
  다음 비용의 출발점     ->  지금 도시        ->  열 번호 v
  들른 순서              ->  담지 않는다      ->  순서가 다른 접두 경로가 한 칸에 모인다
```

#### 1단계 — DP 테이블의 크기와 출발 칸 정하기

DP 테이블에는 줄이 `2^n` 개, 줄마다 칸이 `n` 개 있습니다. 정본은 이것을 `Float64Array` 한 줄로 펴서 잡으므로 칸
하나가 8 바이트예요. 전개 입력과 규모의 끝에서 크기를 세면 이렇습니다.

<!--proof:build-size-->

| 도시 n | 줄 2^n | 칸 2^n·n | 값이 든 칸 | 칸마다 8 바이트 | 256 MB 예산 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 4 | 16 | 64 | 13 | 512 바이트 | 든다 |
| 12 | 4,096 | 49,152 | 11,265 | 0.4 MB | 든다 |
| 20 | 1,048,576 | 20,971,520 | 4,980,737 (식) | 167.8 MB | 든다 |
| 21 | 2,097,152 | 44,040,192 | 10,485,761 (식) | 352.3 MB | 넘는다 |

전개 입력에서 정본이 잡은 DP 테이블은 16 줄 × 4 칸, 모두 64 칸이고 값이 든 칸은 13 개입니다.

<!--/proof-->

**도시 20 개에서 167.8 MB 로 256 MB 예산 안에 들고, 21 개에서는 352.3 MB 로 넘습니다.** 과제의 규모를 도시 20 개로
잡은 까닭이 이 줄이에요. 값이 든 칸은 도시 20 개에서 498 만 개쯤으로 잡은 칸의 4 분의 1 이 안 되는데, 어느 칸에
값이 들지는 채워 보기 전에 알 수 없어 칸을 모두 잡습니다.

칸은 처음에 모두 `INF` 로 채웁니다. 아직 어떤 접두 경로도 만들지 않았으니까요. 그다음 **출발 칸** 하나만 정합니다.
도시 0 만 들르고 도시 0 에 서 있는 칸 `dp[0001₂][0]` 이고, 아무 데도 가지 않았으니 비용이 0 이에요. 모든 접두
경로가 이 칸에서 출발합니다.

#### 2단계 — 작은 줄부터 뒤 줄로 전이 쓰기

줄을 `mask = 1` 부터 `FULL` 까지 번호 차례로 처리합니다. 한 줄에서는 값이 든 칸 `dp[mask][v]` 마다, 아직 들르지
않은 도시 `u` 로 옮겨 간 비용 `dp[mask][v] + dist[v][u]` 를 **도착 칸** `dp[mask | (1 << u)][u]` 에 적어요.
도착 칸에 이미 더 작거나 같은 값이 있으면 적지 않습니다. 칸 하나에서 다른 칸으로 값을 옮기는 이 한 번을 **전이**
라고 불러요.

가장 쉬운 경우는 도착 칸이 아직 `INF` 일 때입니다. 줄 `0001₂` 에서 도시 1 · 2 · 3 으로 가는 전이 셋이 모두
그렇고, 비용 10 · 15 · 20 이 그대로 도착 칸에 적혀요. 불안한 경우는 **도착 칸에 이미 값이 있을 때**입니다. 전개
입력에서는 칸 셋이 그런 자리였어요.

<!--proof:build-merges-->

| 걸음 | 도착 칸 | 먼저 온 후보 | 나중 온 후보 | 남은 값 |
| --- | --- | --- | --- | --- |
| T8 | dp[1111₂][3] | dp[0111₂][1] 에서 75 | dp[0111₂][2] 에서 75 | 75 |
| T12 | dp[1111₂][2] | dp[1011₂][1] 에서 80 | dp[1011₂][3] 에서 65 | 65 |
| T14 | dp[1111₂][1] | dp[1101₂][2] 에서 85 | dp[1101₂][3] 에서 70 | 70 |

전이 15 개가 칸 12 개에 들어갔고, 후보가 둘 온 칸이 3 개입니다.

<!--/proof-->

`dp[1111₂][2]` 에 두 후보가 오는 자리를 걸음마다 그리면 이렇습니다. 앞 후보 80 이 먼저 적히고, 뒤 후보 65 가
더 작아 그 자리를 바꿔요.

<!--fig:build-merge-->
![같은 칸 dp[1111₂][2] 에 두 전이가 온다 — 작은 쪽만 남는다](./figs/build-merge.svg)

T8 의 `dp[1111₂][3]` 에서는 뒤 후보도 75 라 적지 않습니다. 같은 값이면 어느 쪽을 남겨도 칸의 값이 같아요. 이
차례가 맞는 까닭은 전이의 도착 줄이 **언제나 출발 줄보다 뒤**라는 데 있습니다. 전이를 모두 모아 재 보았어요.

<!--proof:build-order-->

| 입력 | 전이 | 도착 줄이 출발 줄보다 뒤인 전이 | 줄 번호 차이의 최솟값 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 15 | 15 | 2 |
| 도시 다섯 | 52 | 52 | 2 |
| 생성식 도시 여덟 | 1,351 | 1,351 | 2 |

전이 1,418 개 가운데 도착 줄 번호가 출발 줄 번호보다 큰 것이 1,418 개입니다.

<!--/proof-->

도착 줄은 출발 줄에 자리 하나를 켠 것이라 번호가 적어도 2 커집니다. 도시 0 의 자리는 이미 켜져 있어 켜는 자리가 1
이상이니까요. 그러니 바깥 반복이 줄 `mask` 에 들어온 시점에는 그 줄로 들어오는 전이 — 모두 더 작은 줄에서 나온다
— 가 이미 다 끝났고, 칸의 값은 더 바뀌지 않습니다. 반복이 `mask = 1` 부터 `FULL` 까지 한 줄씩 빠짐없이 가므로
처리하지 않고 지나가는 줄도 없어요.

#### 3단계 — 모든 도시를 들른 줄에서 복귀 비용 더하기

마지막 줄 `FULL` 의 칸 `dp[FULL][v]` 는 모든 도시를 들르고 `v` 에 선 가장 작은 비용입니다. 여기에 도시 0 으로
돌아오는 비용 `dist[v][0]` 을 더하면 순회 하나의 비용이 되고, 그 가운데 가장 작은 것이 답이에요.

<!--proof:build-return-->

```text
마지막 도시  칸            칸의 값  복귀 비용  순회 비용
          0  dp[1111₂][0]      INF          0        INF
          1  dp[1111₂][1]       70         10         80
          2  dp[1111₂][2]       65         15         80
          3  dp[1111₂][3]       75         20         95

가장 작은 순회 비용 80
```

마지막 도시가 0 인 칸은 `INF` 라 후보가 못 됩니다. 도시 1 과 2 가 둘 다 80 인 것은 이 행렬의 가는 비용과 오는 비용이
같아서, 같은 순회를 반대 방향으로 읽은 두 값이기 때문이에요.

#### 이 방법이 기대는 전제

이 방법은 전제 셋 위에서 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 이동 비용이 도시 쌍만으로 정해진다 — 언제 가는지와 무관하다 | 순서가 다른 접두 경로를 한 칸에 모은다 | 같은 칸의 두 경로가 앞으로 드는 비용이 달라 비용이 작은 쪽만 남기면 답이 틀린다 |
| 도시 수가 정수 하나의 비트 폭 안에 든다 | 집합을 정수로 적어 줄 번호로 쓴다 | 집합 표기가 깨진다 |
| DP 테이블이 메모리에 든다 | 칸 `2^n · n` 개를 한 번에 잡는다 | 잡을 수 없다 |

첫째 전제는 「아이디어를 떠올리는 과정」에서 두 접두 경로의 남은 최소 비용이 같았던 것이 그 모습입니다. 둘째와
셋째는 도시 수를 올려 가며 실제로 재 보았어요. 자바스크립트의 비트 연산은 피연산자를 32 비트 정수로 자릅니다.

<!--proof:build-premise-bits-->

```text
도시 n          1 << n            FULL            칸 수        메모리  되는 일
    20       1,048,576       1,048,575       20,971,520      167.8 MB  집합 표기가 되고 256 MB 안에 든다
    21       2,097,152       2,097,151       44,040,192      352.3 MB  집합 표기는 되지만 256 MB 를 넘는다
    30   1,073,741,824   1,073,741,823   32,212,254,720  257,698.0 MB  집합 표기는 되지만 256 MB 를 넘는다
    31  -2,147,483,648  -2,147,483,649  -66,571,993,088             —  FULL 이 음수 — 칸 수가 음수가 된다
    32               1               0               32    256 바이트  1 << n 이 2^n 이 아니다

모든 거리가 1 인 행렬로 실제로 불러 보면
  도시 31  RangeError 를 던진다
  도시 32  INF 를 돌려준다
```

**메모리가 먼저 막습니다.** 도시 21 개에서 이미 256 MB 를 넘고, 비트 폭이 실제로 깨지는 것은 한참 뒤인 도시 31
개예요. 도시 32 개에서는 더 나쁜 일이 일어납니다. `1 << 32` 가 1 이 되어 `FULL` 이 0 이 되고, 예외도 없이 `INF` 를
돌려줘요. 규모 20 안에서는 셋 다 지켜집니다.

#### 출발 도시를 0 으로 고정하는 까닭

순회는 처음 도시로 돌아와 닫히는 고리라 어느 도시에서 읽기 시작해도 같은 순회입니다. 그래서 출발 도시를 0 으로 정해 두고
시작합니다. 도시마다 출발점으로 옮겨 놓고 답을 재 보았어요.

<!--proof:build-fix-start-->

| 출발 도시 | 비용이 가장 작은 순회 비용 | 값이 든 칸 |
| --- | ---: | ---: |
| 도시 0 | 80 | 13 |
| 도시 1 | 80 | 13 |
| 도시 2 | 80 | 13 |
| 도시 3 | 80 | 13 |

출발 도시 4 가지의 순회 비용이 모두 80 입니다. 도시 0 을 담지 않은 줄은 전개 입력에서 8 줄이고, 도시 20 개에서는 524,288 줄 · 83.9 MB 입니다.

<!--/proof-->

**출발 도시가 어디든 순회 비용이 80 으로 같습니다.** 출발 도시마다 DP 테이블을 따로 채우면 같은 답을 `n` 번 구하는
셈이라, 하나로 고정하는 것이 맞아요. 고정해서 내주는 것도 있습니다. 도시 0 을 담지 않은 줄은 끝까지 비어 있어서, 도시
20 개에서 83.9 MB 가 쓰이지 않은 채 잡혀 있어요. 그 줄을 빼고 `2^(n-1)` 줄만 잡으면 메모리가 반이 되지만, 줄 번호를
바꿔 적는 계산이 칸마다 붙습니다. 이 글의 정본은 줄 번호가 곧 비트마스크인 쪽을 골랐고, 규모 20 에서는 그래도 예산
안에 들어요.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다.

1. DP 테이블을 `2^n × n` 칸으로 잡아 모두 `INF` 로 채운다
2. 출발 칸 `dp[0001₂][0]` 에 0 을 적는다
3. `mask` 를 1 부터 `FULL` 까지 올리며, 값이 든 칸 `(mask, v)` 마다 아직 안 간 도시 `u` 로 옮긴 비용을 도착 칸에 더 작으면 적는다
4. 줄 `FULL` 의 칸마다 도시 0 으로 돌아오는 비용을 더한다
5. 그 가운데 가장 작은 것을 돌려준다

### 수행으로 알아보는 알고리즘 — 도시 넷의 DP 테이블을 열일곱 걸음으로 채운다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const dist = [
  [0, 10, 15, 20],
  [10, 0, 35, 25],
  [15, 35, 0, 30],
  [20, 25, 30, 0],
];
// 이 절이 끝나면 80 이 나와야 한다
```

왜 하필 도시 넷일까요? **순서가 다른 두 접두 경로가 같은 칸으로 모이는 자리**가 나오는 가장 작은 크기이기 때문이에요.
도시가 셋이면 들른 도시와 지금 도시를 정하는 순간 접두 경로가 하나로 정해져, 칸 하나에 후보가 둘 오는 일이 없습니다.

<!--proof:walk-why-four-->

| 입력 | 도시 수 | 전이 | 후보가 둘 이상 온 칸 |
| --- | ---: | ---: | ---: |
| 비대칭 도시 셋 | 3 | 4 | 0 |
| 모든 거리가 1 인 도시 셋 | 3 | 4 | 0 |
| 전개 입력 (도시 넷) | 4 | 15 | 3 |

도시 셋인 입력 둘에서는 후보가 둘 이상 온 칸이 0 개와 0 개이고, 전개 입력에서는 3 개입니다.

<!--/proof-->

절차 전체를 한 장으로 적으면 이렇습니다. 원문자는 코드에서 갈래마다 붙인 라벨이에요.

```text
DP 테이블 dp 를 (FULL + 1) × n 칸으로 잡고 전부 INF 로 채운다     ① DP 테이블
dp[0001₂][0] ← 0                                                  ② 출발 칸

mask 를 1 부터 FULL 까지:
    v 를 0 부터 n-1 까지:
        v 가 mask 밖이면 건너뛴다                                  ③ 방문 집합 밖
        dp[mask][v] 가 INF 면 건너뛴다                             ④ 값이 INF 인 칸
        u 를 0 부터 n-1 까지:
            u 가 이미 mask 안이면 건너뛴다                         ⑤ 이미 들른 도시
            후보 ← dp[mask][v] + dist[v][u]
            후보가 dp[mask | (1 << u)][u] 보다 작으면 바꾼다        ⑥ 값 갱신

last 를 0 부터 n-1 까지 dp[FULL][last] + dist[last][0] 의 최솟값    ⑦ 복귀 비용
```

#### 1. DP 테이블을 한 줄로 펴서 잡고 출발 칸을 놓는다

1단계에서 정한 크기대로 DP 테이블을 잡습니다. 이차원 배열이 아니라 **한 줄로 편** 배열이에요.

```ts
const n = dist.length;
const FULL = (1 << n) - 1;
const dp = new Float64Array((FULL + 1) * n).fill(INF); // ① DP 테이블
dp[1 * n + 0] = 0; // ② 출발 칸
```

`dp[mask][v]` 를 코드에서는 `dp[mask * n + v]` 로 적습니다. 줄 하나가 칸 `n` 개를 차지하니 `mask` 번째 줄은
`mask * n` 번째 칸에서 시작해요. 도시 20 개에서 이차원 배열로 잡으면 줄마다 배열 객체가 하나씩, 백만 개 넘게 따로
생기는데, 한 줄로 펴면 8 바이트 칸이 이어 붙은 덩어리 하나입니다. 실행하면 이렇게 나옵니다.

<!--proof:walk-init-->

```text
n           4
FULL        1111₂ = 15
칸 수       (15 + 1) × 4 = 64
값이 든 칸  dp[0001₂][0] = 0
INF 인 칸   63
```

#### 2. 방문 집합 하나에서 뒤 줄로 전이를 만든다

둘째 조각이 본체입니다. 줄 하나를 잡고, 그 줄의 값이 든 칸마다 아직 안 간 도시로 옮겨 가요.

```ts
for (let v = 0; v < n; v++) {
  if ((mask & (1 << v)) === 0) continue; // ③ 방문 집합 밖
  const cur = dp[mask * n + v] as number;
  if (cur === INF) continue; // ④ 값이 INF 인 칸
  const row = dist[v] as number[];
  for (let u = 0; u < n; u++) {
    if ((mask & (1 << u)) !== 0) continue; // ⑤ 이미 들른 도시
    const next = mask | (1 << u);
    const at = next * n + u;
    const cand = cur + (row[u] as number);
    if (cand < (dp[at] as number)) dp[at] = cand; // ⑥ 값 갱신
  }
}
```

첫 줄 `0001₂` 만 실행하면 이렇게 나옵니다. 값이 든 칸은 출발 칸 하나이고, 거기서 도시 1 · 2 · 3 으로 전이 셋이
나와요.

<!--proof:walk-t2-->

```text
T2 — 방문 집합 0001₂ 에서
  값이 든 칸  dp[0001₂][0] = 0

  u = 1   next = 0011₂   0 + dist[0][1] = 10   ->  dp[0011₂][1] = 10
  u = 2   next = 0101₂   0 + dist[0][2] = 15   ->  dp[0101₂][2] = 15
  u = 3   next = 1001₂   0 + dist[0][3] = 20   ->  dp[1001₂][3] = 20

  ⑤ 가 거른 후보 1 개 — u = 0 은 이미 mask 안에 있다
```

#### 짚고 가기 — 도달하지 못한 칸을 0 으로 채우면 없는 경로가 비용이 가장 작은 순회가 된다

여기서 헷갈리기 쉬운 포인트는 DP 테이블을 `INF` 로 채우는 줄입니다. 「어차피 가장 작은 것을 고를 텐데 0 으로
채우면 안 되나」로 읽기 쉬워요. 그 줄만 바꿔 봅시다.

```ts
const dp = new Float64Array((FULL + 1) * n).fill(0); // ← INF 대신 0 으로 채웠다
```

<!--proof:pause-zero-fill-->

```text
입력                     정본  0 으로 채운 판  판정
전개 입력                  80               0  다르다
비대칭 도시 셋              3               0  다르다
도시 다섯                  12               0  다르다
지름길이 생기는 도시 넷    10               0  다르다
도시 하나                   0               0  같다
```

**도시 하나짜리 입력만 빼고 전부 0 이 나옵니다.** 답 0 은 「비용 0 짜리 순회를 찾았다」가 아니라 「아무 데도 안 간
칸을 완성된 순회로 읽었다」예요. 무엇이 사라졌는지를 값으로 봅시다.

<!--proof:pause-zero-fill-state-->

```text
입력                     ④ 가 참 (정본)  ④ 가 참 (0 으로 채운 판)  정본의 dp[FULL][0]  0 으로 채운 판의 dp[FULL][0]
전개 입력                            19                         0                 INF                             0
비대칭 도시 셋                        7                         0                 INF                             0
도시 다섯                            47                         0                 INF                             0
지름길이 생기는 도시 넷              19                         0                 INF                             0
도시 하나                             0                         0                   0                             0

0 으로 채운 판에서는 ④ 가 한 번도 참이 되지 않는다 — 모든 칸이 비용 0 으로 이른 칸이 된다
그래서 마지막 반복이 도시 0 자리의 0 을 그대로 골라 온다
```

**정본에서 19 번 참이 되던 ④ 가 0 번이 됩니다.** `INF` 는 「이 칸에 이르는 접두 경로가 아직 없다」를 뜻하는데, 0 으로
채우면 그 뜻을 적을 자리가 없어져요. 그러면 도시 0 으로 들어오는 전이가 한 번도 없었는데도 `dp[1111₂][0]` 이 0 으로
남고, 마지막 반복이 그 0 을 골라 옵니다. 도시 하나짜리 입력에서 값이 같은 것은 그 입력의 답이 원래 0 이기 때문이에요.

#### 3. 이미 들른 도시를 거른다

둘째 조각 안의 한 줄이 「정확히 한 번씩」을 지킵니다. 다음 도시 `u` 를 고를 때 **이미 `mask` 안에 있는 도시는
제외**해요.

```ts
if ((mask & (1 << u)) !== 0) continue; // ⑤ 이미 들른 도시
```

모든 도시를 들른 줄 `1111₂` 에서는 후보가 전부 걸립니다.

<!--proof:walk-t16-->

```text
T16 — 방문 집합 1111₂ 에서
  값이 든 칸  dp[1111₂][1] = 70 · dp[1111₂][2] = 65 · dp[1111₂][3] = 75

  u = 0   1111₂ & 0001₂ != 0   거른다
  u = 1   1111₂ & 0010₂ != 0   거른다
  u = 2   1111₂ & 0100₂ != 0   거른다
  u = 3   1111₂ & 1000₂ != 0   거른다
```

#### 4. 복귀 비용을 더해 답을 고른다

셋째 조각이 답을 고릅니다. 모든 도시를 들른 줄에서 칸마다 도시 0 으로 돌아오는 비용을 더하고, 그 가운데 가장 작은
것을 돌려줘요.

```ts
let answer = INF;
for (let last = 0; last < n; last++) {
  const back = dist[last] as number[];
  const cand = (dp[FULL * n + last] as number) + (back[0] as number); // ⑦ 복귀 비용
  if (cand < answer) answer = cand;
}
return answer;
```

전개 입력의 값은 3단계에서 보였으니, 가는 비용과 오는 비용이 다른 비대칭 도시 셋에 실행해 봅니다.

#### 6. 전체 코드

조각을 하나로 잇습니다. 앞에서 값으로 본 것 말고 새로 들어간 것은 **줄을 1 부터 `FULL` 까지 차례로 처리하는 바깥
반복** 하나예요. 그 차례가 왜 그래야 하는지는 「불변식」 절이 값으로 봅니다.

```ts
export const INF = Number.POSITIVE_INFINITY;

export function tspBitmask(dist: number[][]): number {
  const n = dist.length;
  // 모든 도시를 방문한 방문 집합. 자리 i 가 1 이면 도시 i 를 방문했다는 뜻이다.
  const FULL = (1 << n) - 1;
  // ① DP 테이블 — dp[mask * n + v] 가 dp[mask][v] 다. 한 줄로 펴서 한 번에 잡는다.
  const dp = new Float64Array((FULL + 1) * n).fill(INF);
  // ② 출발 칸 — 도시 0 만 방문했고 지금 도시가 0 이며 비용이 0 이다.
  dp[1 * n + 0] = 0;

  for (let mask = 1; mask <= FULL; mask++) {
    for (let v = 0; v < n; v++) {
      // ③ 지금 도시가 방문 집합 밖이면 그 칸에 이르는 경로는 없다.
      if ((mask & (1 << v)) === 0) continue;
      const cur = dp[mask * n + v] as number;
      // ④ 값이 INF 인 칸(이르는 경로가 아직 없는 칸)에서는 전이를 만들지 않는다.
      if (cur === INF) continue;
      const row = dist[v] as number[];
      for (let u = 0; u < n; u++) {
        // ⑤ 이미 방문한 도시로는 가지 않는다.
        if ((mask & (1 << u)) !== 0) continue;
        const next = mask | (1 << u);
        const at = next * n + u;
        const cand = cur + (row[u] as number);
        // ⑥ 같은 칸에 더 작은 비용으로 이르렀으면 그 값으로 바꾼다.
        if (cand < (dp[at] as number)) dp[at] = cand;
      }
    }
  }

  let answer = INF;
  for (let last = 0; last < n; last++) {
    const back = dist[last] as number[];
    // ⑦ 마지막 도시에서 도시 0 으로 돌아오는 비용까지 더한 것이 순회 하나의 비용이다.
    const cand = (dp[FULL * n + last] as number) + (back[0] as number);
    if (cand < answer) answer = cand;
  }
  return answer;
}
```

실행하면 이렇게 나옵니다.

### 알아 두면 좋은 개념 — 상태 압축

이 절차가 방문 순서를 DP 테이블 칸으로 바꿀 수 있었던 근거에는 이름이 붙어 있습니다. **지금까지 처리한 원소들의
집합을 정수 한 개의 비트로 적어 배열 첨자로 쓰는 것**을 **상태 압축**이라고 불러요. 이 편에서는 들른 도시 집합을
`mask` 라는 정수로 적고, 그 정수에 `n` 을 곱해 한 줄로 편 DP 테이블의 칸 번호로 쓴 것이 그것입니다.

<!--proof:related-index-->

| 들른 도시 | 이진 표기 | 정수 mask | 칸 번호 mask·n + v |
| --- | --- | ---: | --- |
| {0,1} | 0011₂ | 3 | 12 ~ 15 |
| {0,1,3} | 1011₂ | 11 | 44 ~ 47 |
| {0,1,2,3} | 1111₂ | 15 | 60 ~ 63 |

전개 입력의 DP 테이블은 칸 64 개를 한 줄로 펴서 잡고, 방문 집합 하나가 이어진 칸 4 개를 차지합니다.

<!--/proof-->

같은 이름이 이 편 밖에서 다시 나옵니다. 셋 다 「집합을 정수의 비트로 적고 그 정수를 첨자로 쓴다」를 같은 모양으로
써요.

| 다시 만나는 자리 | 원소 | 집합 첨자로 하는 일 |
| --- | --- | --- |
| 할당 문제 — 사람과 일을 1:1 로 짝짓기 | 이미 맡긴 일 | 맡긴 일의 집합마다 가장 작은 비용을 적는다 |
| 해밀턴 경로의 개수 세기 | 이미 들른 정점 | 집합과 끝 정점마다 경로 수를 적는다 |
| 서브마스크 열거 | 마스크가 담은 원소 | 그 집합의 부분집합을 정수 연산으로 만든다 |

서브마스크 열거는 이 저장소에도 있어요 — [서브마스크 열거 가이드](../../bit-manipulation/enumerateSubmasks/enumerateSubmasks-guide.md)
가 그 자리입니다. 이름을 알아 두면 다시 만났을 때 「무엇이 원소이고 집합이 몇 개인가」부터 물을 수 있고, 원소가 20
개 안팎이면 이 편과 같은 방법이 그대로 갑니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 이 만든 절차를 여기서 따집니다. 이것을 고를 조건이 무엇인지, 칸 수와 전이 수를 임의의 도시 수에서 어떻게
닫는지, 바깥 반복이 지키는 문장이 무엇인지, 기본 연산이 몇 번인지 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

다음 넷이 함께 맞을 때예요.

- **앞으로 드는 비용이 「무엇을 이미 했는가」의 집합과 지금 자리에만 달려 있습니다.** 순서가 앞으로에 영향을 주면
  칸 하나에 접두 경로를 모을 수 없어요.
- **집합의 원소가 20 개 안팎입니다.** 칸이 `2^n · n` 개라 원소가 하나 늘 때마다 칸이 두 배 넘게 늘어납니다.
- **정확한 답이 필요합니다.** 오차를 허용해도 되면 훨씬 적은 연산으로 끝나는 근사가 있어요.
- **최악에서도 예측할 수 있는 비용이 필요합니다.** 같은 도시 수라면 비용 행렬이 무엇이든 기본 연산이 같아요. 그
  실측은 「최악을 만드는 입력」에 있습니다.

```text
네 조건이 코드의 어느 줄로 나타나는가
  집합과 지금 자리에만 달려 있다   ->  칸이 (mask, v) 둘로 끝난다
  원소가 20 개 안팎이다            ->  DP 테이블을 통째로 잡을 수 있다
  정확한 답이 필요하다             ->  후보를 버리지 않고 모두 비교한다
  최악이 예측 가능하다             ->  가지치기를 쓰지 않는다
```

「원소가 20 개 안팎이다」가 이 절차의 자리이자 한계입니다. 도시가 수백 개면 DP 테이블을 잡는 것 자체가 안 되고, 그때는
정확한 답을 포기하거나 과제의 특별한 구조를 쓰는 다른 방법으로 가야 해요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 있으면
  "모든 도시를 정확히 한 번씩"           <- 들른 도시 집합이 칸의 한 축이 된다
  "n <= 20" 처럼 상한이 작다              <- 2^n 이 배열에 들어간다
  "최소 비용" "정확한 최적해"             <- 근사가 아니라 전부 비교한다
  "출발지로 돌아온다"                     <- 마지막에 복귀 비용을 더한다

반대로 이런 말이 있으면 해당하지 않는다
  "도시가 최대 10^5 개"                   <- DP 테이블을 잡을 수 없다
  "최적의 몇 배 안이면 된다"              <- 근사가 맡는다
  "각 도시를 여러 번 지나도 된다"         <- 들른 도시 집합이 칸의 축이 되지 않는다
```

마지막 무리가 보이면 다른 절차로 갑니다. 「정확히 한 번씩」이라는 조건이 없으면 과제가
[플로이드-워셜](../../shortest-path/floydWarshall/floydWarshall-guide.md)이 푸는 모든 쌍 최단 경로에 가까워져요.

#### 실제로 쓰이는 곳

- **`python-tsp` 의 `python_tsp/exact/dynamic_programming.py`** — 파이썬 패키지가 이 절차를 **정확해 풀이**로 싣습니다.
  파일이 `exact/` 아래 있고, 주석의 참고 문헌이 `https://en.wikipedia.org/wiki/Held%E2%80%93Karp_algorithm#cite_note-5` 를
  가리켜요. 칸을 적는 자리가 `def dist(ni: int, N: frozenset) -> float:` 인데, `ni` 가 이 글의 `v`(지금 도시)이고 `N`
  이 **아직 안 간 도시의 집합**이라 이 글의 `mask` 를 뒤집어 적은 것입니다. 첫 호출이 `best_distance = dist(0, N)` 이고,
  경로를 되살리려고 `memo: dict[tuple, int] = {}` 에 다음 도시를 함께 적어 둡니다.
  ([`python-tsp/python_tsp/exact/dynamic_programming.py`](https://github.com/fillipe-gsm/python-tsp/blob/master/python_tsp/exact/dynamic_programming.py),
  조회 2026-09-07)
- **`networkx` 의 `held_karp_ascent`** — 같은 이름이 **다른 것**을 가리키는 자리입니다. 주석 첫 줄이 *"Minimizes the
  Held-Karp relaxation of the TSP for `G`"* 이고, 그 아래가 *"The Held-Karp relaxation defines the lower bound for
  solutions to the ATSP, although it does return a fractional solution."* 라 적어요. 이 글의 절차가 내는 정확한 최솟값이
  아니라 **하한**을 내고, 답이 분수 값입니다.
  ([`networkx/algorithms/approximation/traveling_salesman.py`](https://github.com/networkx/networkx/blob/main/networkx/algorithms/approximation/traveling_salesman.py),
  조회 2026-09-07)

```text
두 구현이 이 글과 무엇이 다른가

  이 글        들른 집합을 정수로 적고 DP 테이블을 앞에서 뒤로 채운다
  python-tsp   아직 안 간 집합을 frozenset 으로 적고 재귀한다         같은 칸을 뒤집어 적었다
  networkx     같은 이름이지만 하한을 내는 다른 절차다                 정확한 최솟값이 아니다
```

「배송 경로 최적화 제품이 이 절차를 그대로 쓴다」는 것은 이 글이 1 차 출처로 확인하지 못했습니다. 확인한 것은 위 두
구현이에요.

#### 경쟁 설계와의 대조

같은 목표(정확한 비용이 가장 작은 순회 비용)를 노리는 다른 절차로 **분기 한정**(branch and bound)이 있습니다. 방문 순서를
깊이 우선으로 만들되, 「지금까지 쌓은 비용 + 아직 안 간 도시마다 가장 작은 출발 비용」이 이미 찾아 둔 최선보다 작지
않으면 그 가지를 버리는 설계예요.

```text
두 설계가 하는 일
  DP 테이블   칸을 전부 만들고 칸마다 값 하나를 남긴다          같은 칸으로 모이는 것을 합쳐 순서를 안 만든다
  분기 한정   순서를 만들되 하한으로 가망 없는 가지를 자른다    칸을 잡지 않는다
```

두 설계를 같은 비용 행렬에 세우고 이 글의 기본 연산으로 셌어요. DP 테이블 쪽은 칸 하나를 살펴본 한 번 · 다음 도시
후보 하나를 살펴본 한 번 · 복귀 비용을 더한 한 번이고, 분기 한정 쪽은 호출 하나에 들어간 한 번 · 후보 하나를
살펴본 한 번 · 복귀 비용을 더한 한 번에, 하한을 만드는 준비와 첫 최선을 얻는 탐욕 순회(가까운 도시부터 고른다)까지
같은 자로 셉니다. 입력은 전개 입력, 격자 위의 점을 잇는 행렬(점 `i` 의 좌표가 `(i mod w, ⌊i / w⌋)` · `w = ⌈√n⌉` 이고
비용은 직선 거리에 100 을 곱해 반올림한 값), 모든 비용이 1 인 행렬이에요. 난수가 없어 시드도 없습니다. **전개 입력만으로
재지 않은 이유**는 도시가 넷이면 두 계수가 100 언저리라 어느 쪽이 앞서는지가 갈리는 자리를 보일 수 없기 때문이고,
전개 입력의 값도 표 맨 위에 함께 둡니다. 추가 칸은 입력 거리 행렬을 빼고 DP 테이블은 표 `2^n · n` 칸, 분기 한정은 방문 표 · 최소
간선 표 · 가장 깊을 때의 호출 틀을 셌고, 둘 다 재지 않고 식으로 적었어요.

<!--proof:alt-bench-->

| 입력 | DP 테이블 기본 연산 | 분기 한정 기본 연산 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 전개 입력 | 116 | 66 | 분기 한정이 1.8 배 적다 |
| 격자 좌표 도시 12 | 184,332 | 97,512 | 분기 한정이 1.9 배 적다 |
| 격자 좌표 도시 20 | 120,586,260 | 21,573,042 | 분기 한정이 5.6 배 적다 |
| 모든 거리가 같은 도시 12 | 184,332 | 902,893,542 | DP 테이블이 4,898 배 적다 |

모든 거리가 같은 행렬에서 도시 수를 늘리면 분기 한정이 적은 마지막 도시 수가 5 개, DP 테이블이 적은 첫 도시 수가 6 개입니다. 격자 좌표 도시 20 개에서 추가 칸은 DP 테이블 20,971,520 칸, 분기 한정 60 칸입니다.

<!--/proof-->

**같은 도시 수에서 행렬의 모양만 바꿔도 순서가 뒤집힙니다.** 도시 12 개에서 격자 좌표면 분기 한정이 97,512 대
184,332 로 앞서는데, 모든 비용이 같은 행렬에서는 902,893,542 대 184,332 로 뒤집혀요.

```text
뒤집히는 자리 — 하한이 얼마나 남는가

  모든 비용이 1 인 행렬에서 분기 한정의 하한은
    지금까지 쌓은 비용 + 아직 안 간 도시 수  =  도시 수 - 1
  실제 순회 비용은 도시 수 (이동이 도시 수만큼 있다)

  하한이 최선보다 늘 1 작으므로 「하한 >= 최선」 이 한 번도 참이 되지 않는다
  가지를 하나도 못 자르고 순서를 전부 만든다

  격자 좌표에서는 점마다 가장 가까운 이웃이 실제로 쓰는 이동과 비슷해 하한이 촘촘하고,
  그래서 가지가 많이 잘린다. 갈림의 축은 도시 수가 아니라 하한과 답 사이의 여유다
```

**추가 칸에서는 DP 테이블이 늘 더 씁니다.** 격자 좌표 도시 20 개에서 20,971,520 칸 대 60 칸이에요. 그러니 DP 테이블이
내주는 것은 **추가 칸**과 **하한이 촘촘한 입력에서의 기본 연산**이고, 얻는 것은 **최악에서의 보장**입니다 — 분기 한정은
같은 도시 12 개에서 97,512 와 902,893,542 사이로 갈리는데, DP 테이블은 같은 도시 수에서 행렬이 무엇이든 기본 연산이
한 자리도 안 움직여요.

```text
어떤 자리에서 어느 쪽을 고르는가

  비용이 좌표에서 나왔고 하한이 촘촘하다  분기 한정이 적다
  비용이 서로 비슷해 하한이 헐겁다        DP 테이블이 적다
  메모리가 모자란다                       분기 한정만 쓸 수 있다
  최악에서의 시간 상한을 약속해야 한다    DP 테이블만 쓸 수 있다
```

### 수식 정의와 유도

들른 도시 집합을 $S \subseteq \{0, 1, \dots, n-1\}$ 라 하고 지금 도시를 $v \in S$ 라 씁니다. $dp[S][v]$ 는 도시 0 에서
출발해 $S$ 에 속한 도시를 정확히 한 번씩 들르고 지금 $v$ 에 있는 접두 경로의 가장 작은 비용이고, 그런 경로가 없으면
$\infty$ 입니다. 식의 $S$ 를 코드에서는 `mask` 로 적어요.

$$
dp[S][v] = \min \Bigl\{ \textstyle\sum_{k=1}^{|S|-1} dist[p_{k-1}][p_k] \;\Bigm|\; p_0 = 0,\; p_{|S|-1} = v,\; \{p_0, \dots, p_{|S|-1}\} = S \Bigr\}
$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $S$ | 들른 도시 집합 — 코드의 `mask` | 도시 0 을 담은 부분집합 |
| $v$ | 지금 도시 — 코드의 `v` | $v \in S$ |
| $p_0, \dots, p_{\lvert S \rvert - 1}$ | 접두 경로가 들른 차례대로의 도시 | $p_0 = 0$ |
| $w$ | $v$ 바로 앞에 있던 도시 | $w \in S \setminus \{v\}$ |

정의를 전개 입력의 칸 하나에 넣어 계산해 봅시다. $S$ 가 네 도시 전부이고 $v = 1$ 이면 조건을 지키는 접두 경로가
둘입니다.

<!--proof:math-check-->

```text
S = {0,1,2,3} · v = 1 을 정의에 넣는다

  0 → 2 → 3 → 1   15 + 30 + 25 = 70
  0 → 3 → 2 → 1   20 + 30 + 35 = 85

  가장 작은 값 70 — DP 테이블의 dp[1111₂][1] = 70
```

**이제 전이식을 세웁니다.** 접두 경로의 마지막 이동은 바로 앞 도시 $w$ 에서 $v$ 로 오는 것이고, $w$ 를 떼면 남는 것은
$S \setminus \{v\}$ 를 들르고 $w$ 에서 끝나는 접두 경로예요. 그러니 $S$ 에서 $v$ 로 끝나는 비용이 가장 작은 경로는 $w$ 마다의
비용이 가장 작은 앞부분에 $dist[w][v]$ 를 더한 것 가운데 가장 작은 것입니다.

$$
dp[\{0\}][0] = 0, \qquad dp[S][v] = \min_{w \in S \setminus \{v\}} \bigl( dp[S \setminus \{v\}][w] + dist[w][v] \bigr)
$$

```text
전이가 자르는 자리

  0 ─── … ─── w │ v
  └ S∖{v} 를 들렀다 ┘   dist[w][v]

  w 를 하나 고르는 것이 「바로 앞에 어디 있었는가」를 고르는 것이다
  v ∉ S∖{v} 라는 것이 「정확히 한 번씩」이고, 코드에서는 그 줄이 ⑤ 다
```

같은 칸에 전이식을 넣으면 정의로 구한 값과 같은 값이 나옵니다. 코드는 이 식을 뒤집어, $w$ 쪽 칸에서 $v$ 쪽 칸으로 값을
옮겨 적어요.

<!--proof:math-recurrence-->

```text
S ∖ {1} = {0,2,3} 의 w 마다
  w = 0   dp[1101₂][0] + dist[0][1] = INF + 10 = INF
  w = 2   dp[1101₂][2] + dist[2][1] = 50 + 35 = 85
  w = 3   dp[1101₂][3] + dist[3][1] = 45 + 25 = 70

  최솟값 70 — dp[1111₂][1] = 70
```

답은 $S$ 가 전체 집합일 때 복귀 비용을 더한 것 가운데 최솟값입니다.

$$
\text{답} = \min_{v} \bigl( dp[\{0,\dots,n-1\}][v] + dist[v][0] \bigr)
$$

이제 **값이 든 칸과 전이가 각각 몇 개인지** 임의의 $n$ 에 대해 닫습니다. 값이 든 칸은 두 무리로 나뉘어요.

```text
값이 든 칸의 두 무리

  출발 칸        S = {0} · v = 0                          하나
  그 밖의 칸     0 ∈ S · |S| = k ≥ 2 · v ∈ S ∖ {0}         S 를 고르는 수 × (k − 1)

  |S| = k 이고 0 ∈ S 인 S 는 도시 0 을 뺀 n − 1 개에서 k − 1 개를 고르는 수만큼 있다
```

$|S| = k$ 이고 $0 \in S$ 인 집합이 $\binom{n-1}{k-1}$ 개이고 그 각각에서 $v$ 가 $k-1$ 가지이므로, $j = k-1$ 로 두면 다음과
같이 닫힙니다.

$$
1 + \sum_{j=1}^{n-1} \binom{n-1}{j} \, j = 1 + (n-1) \, 2^{\,n-2}
$$

합을 닫는 데는 항등식 $\sum_{j=0}^{m} \binom{m}{j} j = m \, 2^{m-1}$ 하나를 씁니다. 원소 $m$ 개에서 부분집합 하나와 그 안의
원소 하나를 고르는 방법을 두 가지로 센 것이에요.

```text
같은 것을 두 가지로 센다 — 부분집합 T 하나와 그 안의 원소 x 하나를 고르는 방법

  T 를 먼저 고른다    크기가 j 인 T 가 C(m, j) 개이고 x 가 j 가지     ->  Σ C(m, j) · j
  x 를 먼저 고른다    x 가 m 가지이고 나머지 m − 1 개는 넣거나 뺀다  ->  m · 2^(m−1)

  m = n − 1 로 둔다. j = 0 항은 0 이라 아래끝을 1 로 올려도 값이 같다
```

전이는 칸 하나가 아직 안 간 도시 $n - k$ 곳으로 하나씩 만들므로, 출발 칸의 $n-1$ 개에 나머지 칸의 합을 더합니다.

$$
(n-1) + \sum_{j=1}^{n-2} \binom{n-1}{j} \, j \, (n-1-j) = (n-1) + (n-1)(n-2) \, 2^{\,n-3}
$$

기본 연산은 칸을 살펴본 `(2^n − 1) · n` 번, 값이 든 칸마다 후보 `n` 개, 복귀 `n` 번의 합입니다. 식을 그대로 옮긴
조각이에요.

```ts
const liveStates = (n: number): number => 1 + (n - 1) * 2 ** (n - 2);
const transitions = (n: number): number => n - 1 + (n - 1) * (n - 2) * 2 ** (n - 3);
const basicOps = (n: number): number => (2 ** n - 1) * n + liveStates(n) * n + n;
```

### 불변식 — 방문 집합 mask 를 처리하기 시작할 때 dp[mask][v] 는 이미 가장 작은 접두 경로 비용이다

파트 1 의 열일곱 걸음이 보인 것은 비용 행렬 한 벌에서 80 이 나왔다는 사실 하나예요. 그것만으로는 다른 행렬에서도
맞는다고 말할 수 없습니다. 그래서 **바깥 반복이 어디까지 갔든 참인 문장** 하나를 세우고, 그것이 걸음마다 참으로
남는지 값으로 확인합니다.

> 바깥 반복이 방문 집합 `mask` 를 처리하기 시작하는 시점에, 모든 `v` 에 대해 `dp[mask][v]` 는 **이미 마지막 값**
> 입니다. 그 값은 도시 0 에서 출발해 `mask` 의 도시를 정확히 한 번씩 들르고 지금 `v` 에 있는 접두 경로 가운데 가장 작은
> 비용이고, 그런 경로가 없으면 `INF` 입니다.

```text
「이미 마지막 값」이 기대는 것

  dp[mask][v] 를 바꿀 수 있는 전이는 어디서 오는가
    출발 칸이 (mask 에서 v 를 뺀 집합, w) 인 전이뿐이다
    그 집합은 mask 보다 자리 하나가 적으므로 정수로도 mask 보다 작다

  정수로 작다  ->  바깥 반복이 먼저 처리한다  ->  mask 에 들어온 시점에 그 전이가 다 끝났다
```

문장을 이 모양으로 세운 이유가 있어요. 「가장 작은 비용이다」만 세우면 **언제** 가장 작은지가 안 정해지고, 그러면 「지금
읽는 값이 이미 정해진 것인가」를 말할 수 없습니다. 「바깥 반복이 그 방문 집합에 들어오는 시점」이 그 답이에요.

**첫 방문 집합에 들어가기 전부터 봅시다.** `mask = 1` 은 집합 `{0}` 이고, 그 안의 지금 도시는 0 하나뿐이며 `dp[0001₂][0]`
은 출발 칸을 놓을 때 적은 0 입니다. 도시 0 에서 출발해 도시 0 만 들른 접두 경로는 「아무 데도 안 갔다」 하나이고 비용이
0 이므로 문장이 참이에요. 그다음 줄을 하나씩 처리할 때 갈래마다 문장이 어떻게 지켜지는지 적으면 이렇습니다.

| 갈래 | 하는 일 | 문장이 그대로인 까닭 |
| --- | --- | --- |
| 지금 도시가 방문 집합 밖이라 건너뛴다 | 아무것도 안 한다 | 그 칸에 이르는 접두 경로가 없어 `INF` 가 맞다 |
| 값이 `INF` 라 건너뛴다 | 아무것도 안 한다 | 없는 경로에서 이어 붙일 것이 없다 |
| 이미 들른 도시라 건너뛴다 | 그 후보를 버린다 | 두 번 들르는 경로는 문장이 세는 대상이 아니다 |
| 도착 칸의 값을 바꾼다 | 더 작은 값을 적는다 | 도착 줄이 지금 줄보다 커서 아직 처리 전이다 |
| 값을 안 바꾼다 | 이미 있는 값을 남긴다 | 이미 있는 값이 이 후보보다 작거나 같다 |
| 복귀 비용을 더한다 | 순회 하나의 비용을 만든다 | 모든 도시를 들른 줄은 마지막에 처리된다 |

「도착 칸의 값을 바꾼다」 줄이 이 논증에서 가장 좁은 자리예요. 도착 줄은 지금 줄에 자리를 하나 더 켠 것이라 **정수로
반드시 크고**, 그래서 바깥 반복이 아직 그 줄을 처리하지 않았습니다. 지금 적는 값은 나중에 읽히는 것이지 이미 읽힌
값을 고치는 것이 아니에요. 그러면 줄 `mask` 에 들어온 시점의 `dp[mask][v]` 는 $w$ 마다의 전이를 모두 받은 값이고,
그 $w$ 쪽 칸들은 문장에 따라 이미 가장 작은 값이었으니, 전이식이 말하는 그대로의 가장 작은 값입니다. 칸마다 접두 경로를
전부 만들어 따로 구한 값과 맞대 보면 이렇습니다.

<!--proof:invariant-watch-->


### 비용 계산

#### 비용을 세는 과정

한 번 실행하는 동안 하는 일은 셋입니다. DP 테이블을 잡는 것, 줄마다 칸과 후보를 살펴보며 전이를 만드는 것, 마지막에
복귀 비용을 더하는 것이에요. 전개의 열일곱 걸음에서 기본 연산을 세었습니다.

```text
T1    —                  0            0     0               0  0
```

걸음마다 살펴본 칸은 4 개로 같고, 살펴본 후보만 달라집니다. **T3 · T5 · T7 · T9 · T11 · T13 · T15 는 도시 0 이 없는 줄이라
값이 든 칸이 없어 후보를 하나도 안 살펴보고**, T16 은 값이 든 칸 셋에서 후보 12 개를 살펴보지만 ⑤ 가 모두 걸러요. T8

돼요.

| 하는 일 | 비용 |
| --- | --- |
| DP 테이블 잡기 (T1) | 칸 `2^n · n` 개를 `INF` 로 채운다 — 메모리와 같은 수 |
| 칸 살펴보기 (T2~T16) | `(2^n − 1) · n` |
| 후보 살펴보기 (T2~T16) | 값이 든 칸 × `n` = `(1 + (n−1)·2^(n−2)) · n` |
| 복귀 (T17) | `n` |

```text
총식 = 칸 채우기 2^n·n  +  기본 연산 (2^n − 1)·n + (1 + (n−1)·2^(n−2))·n + n
     = Θ(2^n · n²)
                 └ 후보 살펴보기 항이 (n−1)·n·2^(n−2) 로 가장 크다
```

칸을 채우는 일은 기본 연산이 아니라 따로 적었어요. 칸 수 `2^n · n` 은 메모리와 같은 수이고, 기본 연산의 가장 큰 항보다
`n` 배 작아 총식의 차수를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 두 정보가 함께 없어져요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (같은 도시 수에서 가장 적게 일하는 행렬) | `O(2^n · n²)` | `Θ(2^n · n²)` |
| **평균적인 경우** (행렬을 아무렇게나 뽑아도) | `O(2^n · n²)` | `Θ(2^n · n²)` |
| **최악의 경우** (어떤 행렬이든) | `O(2^n · n²)` | `Θ(2^n · n²)` |

**세 줄이 같습니다.** 이 절차에는 입력을 보고 일찍 끝내는 자리가 없어, 같은 도시 수면 어떤 행렬에서도 같은 칸과 같은
후보를 살펴봐요. 칸을 살펴볼지는 `mask` 와 `v` 가, 후보를 살펴볼지는 칸에 값이 들었는지가 정하는데, 값이 드는 칸도
비용 값과 무관하게 「도시 0 을 담은 집합에서 도시 0 이 아닌 지금 도시」로 정해지기 때문입니다.

**보장의 종류는 최악 보장입니다.** 기댓값이 아니에요. 코드에 무작위성이 없고 입력 분포를 가정하지도 않습니다. 위 표의
「평균」 줄도 분포에 대한 기댓값이 아니라 **어떤 분포에서 뽑아도 같은 값**이라는 뜻이에요. 도시 수를 늘리며 기본 연산을
`2^n · n²` 으로 나누어 보면 이렇습니다.

<!--proof:perf-observed-->

```text
도시 n  기본 연산 (실측)     닫힌 식  기본 연산 / (2^n·n²)
     6               870         870                0.3776
    10            33,290      33,290                0.3251
    14           974,862     974,862                0.3036
    18        24,772,626  24,772,626                0.2917

마지막 열이 1/4 = 0.2500 로 다가간다
```

**마지막 열이 도시 6 개에서 0.3776, 18 개에서 0.2917 로 1/4 에 다가갑니다.** 기본 연산의 가장 큰 항 `(n−1) · n ·
2^(n−2)` 를 `2^n · n²` 으로 나누면 `n` 이 커질수록 1/4 로 가고, 실측이 그 값을 위에서 따라가요. 상수 1/4 은 「집합이
도시 0 을 담아야 한다」와 「지금 도시가 그 집합 안이어야 한다」가 각각 절반씩 자른 결과입니다. 메모리는 `Θ(2^n · n)`
이고, 규모 20 에서 167.8 MB 인 것은 1단계의 표에서 봤어요.

#### 최악을 만드는 입력

기본 연산을 가장 많이 하게 만들려면 비용 행렬을 어떻게 골라야 할까요. **고를 것이 없습니다.** 이 절차에는 가지치기가
없어서, 어떤 칸과 후보를 살펴보는지가 비용 값과 무관해요. 같은 도시 수에서 행렬 모양을 바꿔 가며 재 봅시다.

<!--proof:perf-worst-->

```text
거리 행렬 (도시 12)                  기본 연산    전이  값을 바꾼 횟수      반환값
모든 거리가 1                          184,332  56,331          11,264          12
모든 거리가 1,000,000                  184,332  56,331          11,264  12,000,000
생성식                                 184,332  56,331          15,014         162
비용 0 짜리 순회                       184,332  56,331          18,955           0
도시 0 에서 나가는 길의 비용만 크다    184,332  56,331          11,264   1,000,011

행렬 다섯에서 기본 연산과 전이는 한 자리도 안 움직이고, 값을 바꾼 횟수만 행렬을 탄다
```

**다섯 행렬에서 기본 연산과 전이가 글자 그대로 같습니다.** 184,332 와 56,331 이 다섯 줄 내내 그대로예요. 갈리는 것은
「값을 바꾼 횟수」 하나이고, 그마저도 11,264 에서 18,955 사이입니다. 분기 한정이 같은 도시 12 개에서 97,512 와
902,893,542 사이로 갈리는 것과 정면으로 대비돼요.

```text
왜 최악을 고를 수 없는가

  살펴보는 칸       mask 와 v 로만 정해진다         비용 값을 읽지 않는다
  살펴보는 후보     값이 든 칸마다 n 개             값이 드는 칸도 비용 값과 무관하다
  값을 바꾸는 횟수  후보가 이미 있는 값보다 작은가  여기만 비용 값을 읽는다
```

그러면 무엇이 이 절차를 막을까요. **도시 수 하나뿐이고, 그것도 비트 폭이 아니라 메모리가 먼저 막습니다.** 「이 방법이
기대는 전제」의 표가 그 실측이에요 — 도시 21 개에서 256 MB 를 넘고, 비트 폭은 도시 31 개에서야 깨집니다.

| 최악으로 만들 축 | 그 축을 최대로 만드는 입력 | 실측한 자리 |
| --- | --- | --- |
| 기본 연산 | 도시 수를 위 끝까지 올린다 — 비용 값은 무관하다 | 「수식 정의와 유도」의 규모 표 |
| 값을 바꾼 횟수 | 잰 다섯 행렬 가운데는 비용 0 짜리 순회가 있는 행렬 | 위 표 |
| 메모리 | 도시 수를 위 끝까지 올린다 | 1단계의 크기 표 |

**여기서 잰 무리는 도시 12 개짜리 행렬 다섯입니다.** 「값을 바꾼 횟수」는 그 다섯 안에서의 최대이고, 더 큰 값을 내는
행렬이 있는지는 확인하지 않았어요. 다른 도시 수에서도 「기본 연산이 행렬과 무관하다」가 유지되는지는 닫힌 형태가 답하고,
그 닫힌 형태를 도시 4 · 8 · 12 · 16 개에서 실측과 대조한 표가 「수식 정의와 유도」에 있습니다.

### 스스로 점검하기

여기까지를 한 문단으로 줄이면 이렇습니다. 접두 경로를 「들른 도시의 집합」과 「지금 도시」 둘로 요약하면 순서가 다른
경로들이 같은 칸으로 모이고, 그 칸마다 가장 작은 비용 하나만 남기면 세는 대상이 순서 `(n-1)!` 개에서 칸 `2^n · n` 개로
바뀌어요. 집합을 비트마스크로 적어 작은 줄부터 처리하는 것이 그 DP 테이블을 채우는 차례입니다.

```text
1.  DP 테이블을 INF 로 채우고 출발 칸 dp[0001₂][0] 에만 0 을 적는다
2.  줄 mask 를 1 부터 FULL 까지 차례로 처리한다
3.  mask 의 값이 든 칸 v 마다, 아직 안 간 도시 u 로 전이를 만든다
4.  도착 칸 (mask | (1 << u), u) 의 값이 더 크면 새 값으로 바꾼다
5.  마지막에 dp[FULL][last] + dist[last][0] 가운데 가장 작은 것을 돌려준다
```

답이 함께 붙는 문제부터 하나 냅니다. 전개의 T8 에서 `dp[1111₂][3]` 을 만들려는 후보가 둘이었어요. 두 칸의 값은 50 과
45 로 달랐는데 합은 둘 다 75 였습니다. 왜 합이 같아졌을까요?

<!--proof:selfcheck-t8-->

```text
T8 의 두 후보
  dp[0111₂][1] = 50 에서 u = 3   50 + dist[1][3] = 50 + 25 = 75
  dp[0111₂][2] = 45 에서 u = 3   45 + dist[2][3] = 45 + 30 = 75
```

<!--check:whyTieAtT8-->
**뒤에 붙는 이동 비용의 차이가 앞의 차이를 정확히 메웠기 때문입니다.** 두 후보의 접두 경로를 풀어 적으면 이렇습니다.

<!--proof:selfcheck-t8-paths-->

```text
두 후보의 경로
  0 -> 2 -> 1 -> 3   15 + 35 + 25 = 75
  0 -> 1 -> 2 -> 3   10 + 35 + 30 = 75

  접두 비용의 차 50 - 45 = 5 · 마지막 구간의 차 30 - 25 = 5
```

접두 비용이 5 만큼 다르고 마지막 이동 비용이 반대 방향으로 5 만큼 달라, 두 합이 나란히 75 가 됐어요. 이 동점은 이
행렬의 값이 만든 우연이지, 가는 비용과 오는 비용이 같아서 생긴 것이 아닙니다. 같은 순회를 반대로 읽어 값이 같아지는
자리는 T17 의 80 두 줄이에요. 동점이든 아니든 코드가 하는 일은 같습니다. ⑥ 은 「이미 있는 값보다 작은가」만 보므로,
같은 값이 두 번째로 오면 적지 않아요.
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 괄호 안의 절로 돌아가세요.

```text
1 → 경쟁 설계와의 대조
2 → 짚고 가기 — 이미 들른 도시 검사를 빼도 답이 안 틀리는 입력이 있다 · T17
3 → 최악을 만드는 입력
```

- 「경쟁 설계와의 대조」에서 모든 비용이 같은 행렬은 분기 한정의 하한이 늘 최선보다 1 작아서 가지가 하나도 안
  잘렸습니다. 하한에 「마지막에 도시 0 으로 돌아오는 이동」을 하나 더 더하면 어떻게 될까요? 그 하한이 여전히 옳은
  하한인지 먼저 따지고, `tspBitmask-guide.alt.ts` 의 하한 식을 고쳐 도시 12 개에서 다시 세어 보세요.
- 이미 들른 도시 검사를 뺀 판에서 전개 입력은 답이 80 그대로였는데 DP 테이블은 칸 7 개가 어긋나 있었습니다. 어긋난
  칸이 어느 줄의 어느 도시인지 먼저 예측하고, 그 칸들이 왜 답에는 영향을 못 줬는지 T17 의 복귀 계산으로 설명해 보세요.
- 「최악을 만드는 입력」에서 「값을 바꾼 횟수」만 행렬에 따라 갈렸습니다. 이 횟수를 가장 크게 만드는 행렬은 어떤
  모양일지 예측하고, 도시 12 개에서 실제로 세어 보세요. 전이 하나가 값을 바꾸려면 이미 있는 값보다 작아야 한다는 것과,
  전이가 도착 칸에 오는 차례가 줄 번호로 정해진다는 것이 답의 재료입니다.

## 실습 — 직접 풀어 보기

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### 외판원 순회 최소 비용

풀 파일: [`tspBitmask.ts`](./tspBitmask.ts) · 테스트: [`tspBitmask.test.ts`](./tspBitmask.test.ts) · 실행: `bun test src/algorithms/dp/tspBitmask/tspBitmask.test.ts`

#### 한 줄 요약

> 함수는 도시 간 거리 행렬을 받아, 모든 도시를 정확히 한 번씩 방문하고 출발 도시로 돌아오는 최소 비용을 반환한다.

#### 스토리

배송 회사의 경로 최적화 담당 현수는 하루에 여러 거점을 모두 들르고 다시 출발지로 돌아오는 최단 경로를 찾아야 한다. 거점마다 방문 순서를 달리하면 총 이동 거리가 크게 달라진다.

현수가 다루는 거점은 최대 $20$개이며, 각 거점 쌍 사이의 이동 비용이 주어진다. 가능한 모든 방문 순서를 시도하면 경우의 수가 너무 많아 시간이 부족하므로 효율적인 방법이 필요하다.

#### 함수 인터페이스

```ts
export function tspBitmask(dist: number[][]): number;
```

- `dist` — $n \times n$ 거리 행렬 (`dist[i][j]`는 도시 $i$에서 도시 $j$로 이동하는 비용)
- 반환 — 도시 $0$에서 출발하여 모든 도시를 정확히 한 번씩 방문하고 도시 $0$으로 돌아오는 최소 비용

#### 제약 조건

- $1 \leq n \leq 20$ (도시 수, `dist`는 $n \times n$ 정방 행렬)
- $0 \leq dist[i][j] \leq 10^6$
- $dist[i][i] = 0$
- 방향이 있는 그래프이므로 $dist[i][j] \neq dist[j][i]$일 수 있다.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

반드시 도시 $0$에서 출발하고 모든 $n$개의 도시를 정확히 한 번씩 방문한 뒤 도시 $0$으로 복귀해야 한다.

$n = 1$인 경우 다른 도시가 없으므로 비용은 $0$이다.

$n = 2$인 경우 0 → 1 → 0 경로밖에 없으므로 $dist[0][1] + dist[1][0]$을 반환한다.

#### 예시

```ts
tspBitmask([[0]]);
// 0 — 도시가 하나뿐이므로 이동 없음

tspBitmask([[0, 5], [5, 0]]);
// 10 — 0 → 1 → 0: 5 + 5 = 10

tspBitmask([
  [0, 10, 15, 20],
  [10,  0, 35, 25],
  [15, 35,  0, 30],
  [20, 25, 30,  0],
]);
// 80 — 0 → 1 → 3 → 2 → 0: 10 + 25 + 30 + 15 = 80

tspBitmask([
  [0, 1, 10],
  [10, 0, 1],
  [1, 10, 0],
]);
// 3 — 0 → 1 → 2 → 0: 1 + 1 + 1 = 3 (비대칭 행렬에서 방향 중요)
```
