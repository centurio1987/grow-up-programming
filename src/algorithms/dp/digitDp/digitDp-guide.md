# 자릿수 DP — 「아직 상한 N 에 붙어 있는가」 참·거짓 하나로 수를 세지 않고 자리마다 만들 수 있는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 수를 하나씩 세는 방법에서
출발해 붙음 표시를 단 자릿수 DP 테이블까지 가고, 그 방법을 단계마다 값으로 푼 뒤, 실제로 동작하는 코드를 한 조각씩
만듭니다.

### 전체 컨셉

`1` 이상 `N` 이하의 정수 중 **십진 자릿수의 합이 정확히 `K` 인 것이 몇 개인지** 셉니다. 자릿수 합은 수를 십진법으로
적었을 때 각 자리 숫자를 더한 값이에요 — `123` 이면 `1 + 2 + 3 = 6` 입니다. `N = 194` · `K = 10` 이면 이렇습니다.

<!--proof:concept-list-->

| 자리 수 | 자릿수 합이 10 인 수 | 개수 |
| --- | --- | ---: |
| 2 자리 | 19 · 28 · 37 · 46 · 55 · 64 · 73 · 82 · 91 | 9 |
| 3 자리 | 109 · 118 · 127 · 136 · 145 · 154 · 163 · 172 · 181 · 190 | 10 |

1 부터 194 까지 하나씩 세면 19 개이고, 정본 digitDp(194, 10) 도 19 를 냅니다.

<!--/proof-->

수를 하나씩 보면 셀 수는 있습니다. 그런데 `N` 이 `10^15` 이면 검사할 수가 1,000조 개이고, 그 수들을 적는 데 쓰는
**자리는 열여섯 개**뿐이에요. 그래서 이 방법은 수를 세는 대신 **맨 왼쪽 자리부터 숫자를 하나씩 정해 수를 만듭니다.**
자릿수 합은 정한 숫자를 더해 가면 되고, 정할 자리는 많아야 열여섯입니다.

만들다 보면 걸리는 것이 하나 있어요. 아무 숫자나 놓으면 `N` 을 넘는 수까지 만들어집니다. `194` 의 맨 왼쪽에 `2` 를
놓으면 그 순간 이미 `194` 보다 커요. 넘지 않으려면 자리마다 **여기까지 고른 숫자가 `N` 의 같은 자리 숫자와 전부 같은가**를
알아야 하고, 이 글은 그 참·거짓을 `tight` 라고 부릅니다.

| `tight` | 이름 | 이번 자리에 놓을 수 있는 숫자 |
| --- | --- | --- |
| 참 | **붙은 상태** — 앞 숫자가 `N` 의 앞부분과 전부 같다 | `0` 부터 `N` 의 이번 자리 숫자까지 |
| 거짓 | **풀린 상태** — 어느 자리에선가 `N` 보다 작은 숫자를 골랐다 | `0` 부터 `9` 까지 |

자리는 **왼쪽부터 0, 1, 2** 로 셉니다. `194` 의 자리 0 은 `1`, 자리 2 는 `4` 예요. 숫자를 정하는 도중의 모습은 세 값으로
적힙니다 — 지금 정할 자리 `pos`, 그 앞에서 고른 숫자의 합 `sum`, 그리고 `tight` 입니다. 이 셋을 **상태**라고 부릅니다.
`N = 194` · `K = 10` 에서 이 방법이 한 번이라도 들어간 상태를 전부 그리면 이렇습니다.

<!--fig:concept-states-->
![digitDp(194, 10) 의 상태 — 줄은 자리와 붙음 여부, 열은 앞 숫자의 합](./figs/concept-states.svg)

줄은 자리마다 둘입니다. 위 줄이 붙은 상태, 아래 줄이 풀린 상태예요. 열은 앞 숫자의 합이고, 칸의 수는 **그 상태에서
남은 자리를 채워 전체 합을 `K` 로 만드는 방법의 수**입니다. 대시로 그린 칸은 이 입력에서 한 번도 들어가지 않는 상태이고,
점선 칸 하나(자리 2 풀림 · 합 0)는 들어갔지만 값을 적지 않은 상태예요 — 남은 한 자리로는 합 10 을 만들 수 없어서입니다.
붙은 줄에는 자리마다 칸이 하나뿐인데, 붙은 상태는 `N` 의 앞부분을 그대로 따라온 경로 하나에서만 나오기 때문입니다. 맨
위 칸 19 가 곧 답이에요.

풀린 줄의 값은 칸에 적어 두고 다시 씁니다. 풀린 상태는 앞 숫자가 무엇이었든 합만 같으면 남은 일이 같아서, 서로 다른
수 여럿이 칸 하나를 나눠 쓰기 때문이에요. 작은 입력의 답을 칸에 적어 두고 큰 입력의 답을 그 칸들에서 만드는 이런 표를
**DP 테이블**이라고 부르고, DP 는 동적 계획법(dynamic programming)의 줄임말입니다. 이 글의 DP 테이블 `memo` 는 줄이
자리, 열이 합이고, **풀린 상태의 값만** 담습니다. 붙은 상태는 자리마다 하나라 DP 테이블 밖에 둬요. 과제의 위 끝에서
두 방법이 다루는 양은 이렇습니다.

<!--proof:concept-scale-->

| 방법 | 세는 것 | N = 10^15 · K = 135 |
| --- | --- | ---: |
| 수를 하나씩 센다 | 검사하는 수 | 1,000,000,000,000,000 |
| 자리마다 숫자를 정한다 | DP 테이블 memo 의 칸 | 16 × 136 = 2,176 |

10^15 는 16 자리로 적히고, DP 테이블의 칸 하나는 숫자를 많아야 10 개 놓아 보고 정해집니다.

<!--/proof-->

`N` 의 자리 수를 `L` 이라 하면, 비용은 결과만 적어 `O(L(K+1))` 입니다. `N` 의 값이 아니라 자리 수에 붙어요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **십진 자릿수와 자리 번호.** `194` 를 `[1, 9, 4]` 로 가르고 왼쪽부터 자리 0 · 1 · 2 라고 부릅니다. 이 글의 자리
  번호는 **가장 높은 자리가 0** 이에요. [이진 거듭제곱](../../number-theory/fastPower/fastPower-guide.md) 의 「자리
  `i`」는 이진 자리이고 가장 낮은 자리가 0 이라 방향이 반대입니다. 이 글은 숫자를 높은 자리부터 정하므로 그 차례대로
  번호를 붙였고, 자리 `pos` 는 `10^(L−1−pos)` 의 자리입니다.
- **자릿수 합.** 자리가 `L` 개면 자릿수 합은 많아야 `9L` 입니다.
- **DP 테이블과 재귀.** 칸 하나를 읽는 법과 이웃한 칸끼리의 관계는
  [동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) 의 「먼저 알아 둘 개념 — DP 테이블」 절이
  풀어 둡니다. 이 글은 DP 테이블을 반복문 대신 **재귀**로 채워요. 재귀 호출이 끝날 때 값을 칸에 적어 두고, 같은 칸이
  다시 필요하면 적힌 값을 씁니다.
- **이항계수 `C(n, r)` 읽기.** 파트 2 의 수식 절에서만 씁니다. 모르면
  [소수 법 이항계수](../../number-theory/binomialModP/binomialModP-guide.md) 를 보세요.

DP 테이블을 쓰는 다른 편을 봤다면 차이는 **한 축이 자리의 개수**라는 데 있습니다.

| 이미 아는 것 | 이 글에서 쓰이는 자리 |
| --- | --- |
| [0/1 배낭](../knapsack01/knapsack01-guide.md) · [부분집합 합 판정](../subsetSum/subsetSum-guide.md) | 한 축이 용량이나 합의 **값**이라 그 값이 커지면 DP 테이블도 커진다. 이 글은 한 축이 **자리 수**라 `N` 이 천 배가 되어도 줄이 셋 는다 |
| [동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) | 줄 차례로 반복문이 채운다. 이 글은 재귀가 필요한 칸만 채운다 |

### 아이디어를 떠올리는 과정 — 수를 하나씩 세기에서 붙음 표시를 단 자릿수 DP 테이블까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 상한과 목표 합을 받아서 개수를 돌려줍니다.

```ts
function digitDp(N: number, K: number): number;
```

- 입력: 상한 `N` 과 목표 자릿수 합 `K`.
- 출력: `1` 이상 `N` 이하의 정수 중 십진 자릿수 합이 정확히 `K` 인 것의 **개수 하나**. 어느 수들이었는지는 돌려주지
  않아요.
- 규모: `1 ≤ N ≤ 10^15`, `0 ≤ K ≤ 135`. 비용은 흔한 채점 환경의 예산인 1 초 · 256 MB 에 대어 잽니다. `N` 의 위 끝을
  `10^15` 로 잡은 까닭은 답을 배정밀도 정수로 정확히 셀 수 있게 하려는 것이에요 — 답은 `N` 이하라
  `2^53 ≈ 9.0 × 10^15` 을 넘지 않습니다. `K` 의 위 끝 135 는 `15 × 9` 예요. 자리가 열여섯인 수는 `10^15` 하나뿐이고
  그 자릿수 합이 1 이라, 자릿수 합이 가장 큰 수는 열다섯 자리에서 나옵니다.

이 글이 쓰는 기호는 여덟입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `N` | 세는 범위의 상한 | `1 ≤ N ≤ 10^15` |
| `K` | 목표 자릿수 합 | `0 ≤ K ≤ 135` |
| `L` | `N` 의 자리 개수 | `1 ≤ L ≤ 16` |
| `digits[pos]` | `N` 의 자리 `pos` 숫자. 자리 0 이 맨 왼쪽이다 | `0` 부터 `9` |
| `pos` | 지금 숫자를 정하는 자리 | `0 ≤ pos ≤ L` |
| `sum` | 자리 `pos` 앞에서 이미 고른 숫자의 합 | `0 ≤ sum ≤ K` |
| `tight` | 여기까지 고른 숫자가 `N` 의 같은 자리와 전부 같은가. 참이면 붙은 상태, 거짓이면 풀린 상태 | 참 · 거짓 |
| `memo[pos][sum]` | 풀린 상태로 자리 `pos` 에 합 `sum` 을 들고 왔을 때의 답. DP 테이블의 칸 하나 | `-1` 이면 아직 안 정했다 |

비용은 이 글 끝까지 **숫자 하나를 다룬 횟수**로 셉니다. 하나씩 세는 방법에서는 수에서 자리 하나를 떼어 더하는 일이고,
재귀에서는 숫자 하나를 놓아 다음 상태에 들어가는 일, 곧 재귀 호출 하나예요. 둘 다 덧셈 한두 번이라 같은 크기입니다.
메모리는 DP 테이블의 칸 수로 셉니다.

가장 먼저 떠오르는 방법으로 시작합시다. `1` 부터 `N` 까지 수를 하나씩 보고, 자릿수를 떼어 더한 다음 `K` 와 비교하는
것입니다.

```ts
function 하나씩센다(N: number, K: number): number {
  let count = 0;
  for (let x = 1; x <= N; x++) {
    let s = 0;
    let v = x;
    while (v > 0) {
      s += v % 10; // 마지막 자리를 떼어 더한다
      v = Math.floor(v / 10);
    }
    if (s === K) count++;
  }
  return count;
}
```

이 방법은 답을 틀리지 않습니다. 자리를 떼어 내는 횟수를 실제로 세어 보고, 수가 많아 실행할 수 없는 줄은 자리 수별로
수가 몇 개인지를 더한 식으로 냈어요.

<!--proof:origin-naive-->

| 상한 N | 검사하는 수 | 실제로 센 자리 떼기 | 식으로 낸 자리 떼기 |
| --- | ---: | ---: | ---: |
| 10^1 | 10 | 11 | 11 |
| 10^2 | 100 | 192 | 192 |
| 10^3 | 1,000 | 2,893 | 2,893 |
| 10^4 | 10,000 | 38,894 | 38,894 |
| 10^5 | 100,000 | 488,895 | 488,895 |
| 10^6 | 1,000,000 | 5,888,896 | 5,888,896 |
| 10^9 | 1,000,000,000 | 세지 않음 | 8,888,888,899 |
| 10^12 | 1,000,000,000,000 | 세지 않음 | 11,888,888,888,902 |
| 10^15 | 1,000,000,000,000,000 | 세지 않음 | 14,888,888,888,888,905 |

10^6 까지는 실제로 실행해 세었고 식으로 낸 값과 같습니다. 과제의 위 끝 10^15 에서 자리 떼기는 14,888,888,888,888,905 번이고, 초당 1 억 번으로 잡으면 1,723 일이 걸립니다.

<!--/proof-->

**하나씩 세는 방법은 여기서 막힙니다.** 비용이 `N` 을 적는 데 쓴 자리 수가 아니라 `N` 이라는 **값의 크기**에 붙어
있어서, `N` 이 천 배가 될 때마다 자리 떼기도 천 배 넘게 늘어요. 그러면 수를 왼쪽 자리부터 **만들면** 무엇이 달라지는지
봅시다. 목표 합을 10 으로 두고 세 자리를 채운다면, 앞 두 자리를 `1 9` 로 놓든 `2 8` 로 놓든 남은 일은 「마지막 한 자리로
합을 맞춘다」로 같습니다.

<!--proof:origin-same-rest-->

| 앞 두 자리 | 합 | 다음 상태 | 그 상태의 답 |
| --- | ---: | --- | ---: |
| 1 9 | 10 | 자리 2 · 합 10 · 풀림 | 1 |
| 2 8 | 10 | 자리 2 · 합 10 · 풀림 | 1 |
| 3 7 | 10 | 자리 2 · 합 10 · 풀림 | 1 |
| 9 1 | 10 | 자리 2 · 합 10 · 풀림 | 1 |

N = 999 · K = 10 에서 앞 두 자리 네 가지가 모두 같은 상태에 이르고, 그 상태의 답은 1 입니다.

<!--/proof-->

앞 두 자리가 달라도 남은 일이 **자리와 합**만으로 정해졌어요. 그러면 자리마다 숫자를 0 부터 차례로 놓아 보는 재귀를
세우고, 그 재귀가 같은 상태를 몇 번이나 다시 푸는지 세어 볼 수 있습니다. 같은 입력을 두 방식으로 셉니다. 왼쪽은 아무것도
기억하지 않는 재귀의 호출 수이고, 오른쪽은 그 호출들이 실제로 들어간 **서로 다른 상태의 개수**예요. 목표 합은 10 으로
고정했습니다.

<!--proof:origin-repeat-->

| 상한 N | 기억하지 않는 재귀의 호출 | 서로 다른 상태 | 배수 | 답 |
| --- | ---: | ---: | ---: | ---: |
| 9 가 3 개 | 348 | 32 | 11 | 63 |
| 9 가 5 개 | 4,343 | 54 | 80 | 996 |
| 9 가 7 개 | 31,786 | 76 | 418 | 8,001 |
| 9 가 9 개 | 167,905 | 98 | 1,713 | 43,749 |
| 9 가 11 개 | 705,356 | 120 | 5,878 | 184,745 |
| 9 가 13 개 | 2,496,043 | 142 | 17,578 | 646,633 |
| 9 가 15 개 | 7,726,030 | 164 | 47,110 | 1,961,241 |

9 가 15 개일 때 호출 7,726,030 번이 서로 다른 상태 164 개를 오갑니다. 자리가 둘 늘 때마다 상태는 22 개씩 늘었습니다.

<!--/proof-->

오른쪽 열이 자리 수에 비례해서만 늘어납니다. 호출은 자리가 둘 늘 때마다 몇 배씩 불어나는데, 서로 다른 상태는 같은 수만큼만
늘어요. 여기서 관찰한 것은 하나입니다. **상태의 개수가 자리 수로 묶여 있으니, 상태마다 답을 한 번씩만 정하면 됩니다.**

남은 질문은 상태를 무엇으로 두는가예요. 가장 단순한 후보부터 시험합니다. 첫째 후보는 상태를 `(자리, 합)` 둘로 두고
상한을 언제나 9 로 두는 것입니다. `N` 을 보지 않으니 칸 하나에 답 하나가 깔끔하게 붙어요.

```ts
// 상태를 (자리, 합) 둘로 두고 상한을 언제나 9 로 둔 판
for (let x = 0; x <= 9; x++) {
  total += 상한을9로(pos + 1, sum + x);
}
```

둘째 후보는 「여기까지 만든 접두사의 값」을 상태에 넣는 것입니다. 상한은 정확히 정해지지만 접두사 값이 `10^15`
가지까지 늘어나 하나씩 세는 방법과 규모가 같아지므로, 실행해 볼 것도 없이 버립니다. 셋째 후보는 붙음 여부로 상한은 가려
쓰되 **`(자리, 합)` 칸 하나를 붙은 상태와 풀린 상태가 함께 쓰는** 것이에요. 실행할 수 있는 둘을 정본과 나란히 놓았습니다.

<!--proof:origin-candidates-->

| 입력 | 정본 | 상태 (자리, 합) · 상한 9 | (자리, 합) 한 칸을 함께 쓰기 |
| --- | ---: | ---: | ---: |
| N = 194 · K = 10 | 19 | 63 | 19 |
| N = 100 · K = 2 | 3 | 6 | 4 |
| N = 10^15 · K = 50 | 10,614,794,989,443 | 56,550,683,448,208 | 12,229,144,871,393 |

입력 3 개 가운데 상한을 9 로 둔 판은 3 개, 한 칸을 함께 쓴 판은 2 개에서 정본과 다른 답을 냈습니다.

<!--/proof-->

**상한을 9 로 두면 `N = 194` 에서 63 이 나옵니다.** 자리마다 0 부터 9 까지 놓았으니 `194` 를 넘는 세 자리 수까지 세었기 때문이에요.
한 칸을 함께 쓰는 판은 `N = 194` 에서 맞다가 `N = 100 · K = 2` 에서 틀립니다. 틀린 자리를 찾으면 이렇습니다.

<!--proof:origin-shared-why-->

| 상태 | 앞 두 자리 | 마지막 자리 상한 | 그 상태의 답 |
| --- | --- | ---: | ---: |
| 자리 2 · 합 1 · 풀림 | 0 1 | 9 | 1 |
| 자리 2 · 합 1 · 붙음 | 1 0 | 0 | 0 |

두 상태가 같은 칸 (자리 2, 합 1) 에 오는데 답이 1 과 0 으로 다릅니다. 한 칸을 함께 쓰면 풀린 쪽이 먼저 적은 1 을 붙은 쪽이 읽어, 답이 3 이 아니라 4 가 됩니다.

<!--/proof-->

같은 `(자리, 합)` 인데 **이번 자리에 놓을 수 있는 숫자가 다릅니다.** 앞 두 자리가 `0 1` 이면 이미 `100` 보다 작아서
마지막 자리에 무엇이든 놓을 수 있고, `1 0` 이면 `N` 과 같게 따라왔으니 `0` 만 놓을 수 있어요. 필요한 것은 접두사의 값이
아니라 **붙은 상태인가 하나**입니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다. 앞 방법이 막힌 자리에서 다음
방법이 나왔고, 넷은 버리고 하나가 남았어요.

<!--fig:origin-approaches-->
![시도한 방법 다섯 — 넷은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **붙음 표시를 단 자릿수 DP 테이블**입니다. 상태를 `(자리, 합, 붙음)` 셋으로 두고, 그중 풀린
상태의 값만 DP 테이블 `memo[자리][합]` 에 적어요. 붙은 상태와 풀린 상태가 어떻게 생겼는지, 칸을 어떤 차례로 채우는지,
붙은 상태를 왜 DP 테이블 밖에 두는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 붙음 표시를 단 자릿수 DP 테이블

이 아이디어를 한 문장으로 줄이면 이렇습니다. **맨 왼쪽 자리부터 숫자를 놓아 가며 상태 `(자리, 합, 붙음)` 을 옮기고,
붙은 상태는 `N` 의 그 자리 숫자까지만 · 풀린 상태는 9 까지 놓되, 풀린 상태의 값만 DP 테이블에 적어 다시 씁니다.** 이
방법은 붙은 상태와 풀린 상태라는 구분 위에서 동작하는데, 처음 보는 사람에게는 이 구분이 낯설어요. 그래서 그 구분을 먼저
따로 설명하고, 그다음 실현하는 순서대로 다섯 단계를 설명합니다. 다섯 단계 모두 재귀 호출 하나 안에서 일어나고, 앞 단계가
만든 것을 뒤 단계가 씁니다.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 자리로 가르고 DP 테이블 깔기 | `digits` · `L` 을 만들고 `memo` 를 `L × (K+1)` 칸의 `-1` 로 둔다 | — |
| 2단계 상한과 다음 붙음 정하기 | 붙음에 따라 상한을 고르고, 놓은 숫자로 다음 자리의 붙음을 정한다 | 1단계의 `digits` |
| 3단계 풀린 상태의 칸 채우기 | 가지치기 · 기저 · 반복 끊기로 값을 내고 DP 테이블에 적는다 | 2단계의 상한 · 1단계의 `memo` |
| 4단계 붙은 상태에서 DP 테이블 읽기 | 붙은 상태가 풀린 칸으로 내려가면 적힌 값을 쓴다 | 3단계가 적은 칸 |
| 5단계 수 0 빼기 | 첫 호출의 값에서 `K = 0` 일 때만 1 을 뺀다 | 4단계까지 합친 첫 호출의 값 |

#### 먼저 알아 둘 개념 — 붙은 상태와 풀린 상태

붙은 상태는 **여기까지 고른 숫자가 `N` 의 같은 자리 숫자와 하나도 빠짐없이 같은 상태**입니다. 붙은 상태에서는 이번
자리에 `N` 의 그 자리 숫자보다 큰 숫자를 놓을 수 없어요. 한 번이라도 더 작은 숫자를 고르면 그 뒤는 무엇을 놓아도
`N` 이하라서, 그때부터를 풀린 상태라고 부릅니다. 풀린 상태는 다시 붙은 상태로 돌아가지 않아요.

##### 입력 위의 붙은 상태

`N = 194` 의 자리마다 붙은 상태와 풀린 상태가 어떤 합으로 오는지 그렸습니다. 강조 테를 두른 줄이 붙은 상태의 합이에요.

<!--fig:build-positions-->
![N = 194 의 자리마다 — 붙은 상태는 합 하나, 풀린 상태는 여러 합](./figs/build-positions.svg)

붙은 상태의 합은 `N` 의 앞 숫자를 더한 값 하나로 정해집니다. 자리 1 이면 `1`, 자리 2 면 `1 + 9 = 10` 이에요. 풀린
상태는 자리 0 에는 없고, 자리 1 에는 앞에 0 을 놓은 합 하나, 자리 2 에는 여러 합이 옵니다. 붙은 상태의 상한은 줄마다
`N` 의 그 자리 숫자이고, 풀린 상태의 상한은 언제나 9 예요.

##### 상태 하나를 읽는 법

상태 `(자리 1 · 합 1 · 붙음)` 을 골라 읽어 보겠습니다. 앞에 놓은 숫자가 `1` 이고 `N` 의 자리 0 과 같아 붙은 채로
왔어요. 그러니 이 상태가 맡는 수는 `1` 로 시작하면서 `194` 이하인 수, 곧 `100` 부터 `194` 까지입니다. 상태의 값은
그중 자릿수 합이 10 인 수의 개수예요. 상태 셋을 같은 방법으로 읽고, 맡는 범위를 하나씩 세어 대조했습니다.

<!--proof:build-read-state-->

| 상태 | 앞 숫자 | 이번 자리 상한 | 이 상태가 맡는 수 | 상태의 값 | 그 범위를 하나씩 센 개수 |
| --- | --- | ---: | --- | ---: | ---: |
| 자리 1 · 합 1 · 붙음 | 1 | 9 | 100 … 194 | 10 | 10 |
| 자리 1 · 합 0 · 풀림 | 0 | 9 | 000 … 099 | 9 | 9 |
| 자리 2 · 합 10 · 붙음 | 1 9 | 4 | 190 … 194 | 1 | 1 |

상태 3 개 가운데 3 개에서 상태의 값과, 맡는 범위의 수를 하나씩 보며 자릿수 합이 10 인 것을 센 개수가 같습니다.

<!--/proof-->

풀린 상태 `(자리 1 · 합 0 · 풀림)` 은 앞에 `0` 을 놓았으니 `000` 부터 `099` 까지, 곧 두 자리 이하의 수 전부를
맡습니다. 붙은 상태는 범위의 끝이 `N` 에서 잘리고, 풀린 상태는 앞 숫자 뒤로 모든 자리가 `0` 부터 `9` 까지 열려 있어요.

##### 붙은 상태와 풀린 상태가 이어지는 모양

상태에서 숫자 하나를 놓으면 다음 자리의 상태로 갑니다. 전개 입력에서 숫자를 놓아 본 상태마다 어디로 갔는지 모았어요.
마지막 자리의 풀린 상태는 다음이 기저뿐이라 뺐습니다.

<!--proof:build-transitions-->

| 상태 | 상한 | 놓는 숫자와 다음 상태 |
| --- | ---: | --- |
| 자리 0 · 합 0 · 붙음 | 1 | x = 0 → 자리 1 · 합 0 · 풀림<br>x = 1 → 자리 1 · 합 1 · 붙음 |
| 자리 1 · 합 0 · 풀림 | 9 | x = 0 … 9 → 자리 2 · 합 0 … 9 · 풀림 |
| 자리 1 · 합 1 · 붙음 | 9 | x = 0 … 8 → 자리 2 · 합 1 … 9 · 풀림<br>x = 9 → 자리 2 · 합 10 · 붙음 |
| 자리 2 · 합 10 · 붙음 | 4 | x = 0 → 자리 3 · 합 10 · 풀림 |

붙은 상태에서 나가는 길은 붙은 상태 하나와 풀린 상태 여럿이고, 풀린 상태에서 붙은 상태로 가는 길은 0 개입니다.

<!--/proof-->

붙은 상태에서 `N` 의 그 자리 숫자보다 작은 숫자를 놓으면 풀린 상태로 가고, 같은 숫자를 놓으면 붙은 채 다음 자리로
갑니다. 그래서 붙은 상태는 자리마다 하나씩 이어진 사슬이 되고, 그 사슬에서 풀린 상태가 가지처럼 갈라져 나와요.
풀린 상태에서는 풀린 상태로만 갑니다.

##### 이번 자리만 같은 것과의 차이

붙음을 처음 보면 **이번 자리 숫자가 `N` 의 그 자리 숫자와 같은가**로 읽기 쉽습니다. 코드로 적으면 다음 붙음을
`tight && x === digits[pos]` 가 아니라 `x === digits[pos]` 로 정하는 것이에요. 두 읽기를 같은 입력에 실행했습니다.

<!--proof:build-only-here-->

| 호출 | 앞 자리까지 본 정본 | 이번 자리만 본 판 |
| --- | ---: | ---: |
| digitDp(194, 10) | 19 | 19 |
| digitDp(194, 15) | 8 | 7 |
| digitDp(100, 2) | 3 | 2 |
| digitDp(990, 9) | 55 | 55 |
| digitDp(999, 27) | 1 | 1 |

N ≤ 2,000 · K ≤ 27 의 56,000 쌍을 모두 대조하면 23,734 쌍에서 답이 다릅니다.

<!--/proof-->

두 읽기가 전개 입력에서는 같은 답을 내지만 `N = 194 · K = 15` 에서 갈립니다. 앞 두 자리가 `0 9` 인 수는 자리 0 에서
이미 `N` 보다 작아졌는데, 이번 자리만 보는 판은 둘째 자리의 `9` 가 `digits[1]` 과 같다는 이유로 다시 붙은 상태로
바꿔 놓아요. 그러면 마지막 자리 상한이 `digits[2] = 4` 로 묶여 셀 수 있는 수를 놓칩니다. 붙음은 **앞 자리 전부**에 대한
물음입니다.

##### 참·거짓 하나로 충분한 까닭

수 `x` 가 `N` 이하인지는 두 수를 왼쪽부터 비교해 **처음 다른 자리**에서 정해집니다. 그 자리에서 `x` 가 작으면 뒤는
무엇이든 `N` 이하이고, 끝까지 다른 자리가 없으면 `x = N` 이에요. 그러니 숫자를 정하는 도중에 알아야 할 것은 「아직 다른
자리가 없었는가」 하나뿐입니다. 앞 두 자리로 올 수 있는 접두사를 전부 가르면 이렇습니다.

<!--proof:build-why-bool-->

| 앞 두 자리 | 개수 | N 의 앞 두 자리와 비교 | 마지막 자리 상한 |
| --- | ---: | --- | ---: |
| 00 … 18 | 19 | 어느 자리에선가 작다 | 9 |
| 19 | 1 | 전부 같다 | 4 |

앞 두 자리로 올 수 있는 20 가지 가운데 붙은 상태는 19 하나이고, 정본이 그 상태(자리 2 · 합 10 · 붙음)로 들어간 것도 한 번입니다.

<!--/proof-->

풀린 쪽 열아홉 가지는 앞 숫자가 서로 달라도 마지막 자리 상한이 똑같이 9 예요. 그래서 합만 같으면 한 칸을 나눠 쓸 수
있고, 붙은 쪽 하나만 따로 두면 됩니다.

#### 1단계 — 자리로 가르고 DP 테이블 깔기

`N` 을 문자열로 바꿔 자릿수 배열 `digits` 를 만들고, 그 길이를 `L` 로 둡니다. DP 테이블 `memo` 는 줄이 자리 `0` 부터
`L − 1`, 열이 합 `0` 부터 `K` 라 `L × (K+1)` 칸이에요. 자리 `L` 은 숫자를 다 정한 뒤라 값이 0 이나 1 로 바로 정해지므로
줄을 두지 않습니다. 칸은 모두 `-1`(아직 안 정함)로 깔아 둬요. 전개 입력과 과제의 위 끝에서 크기를 세면 이렇습니다.

<!--proof:build-size-->

| N | K | digits | L | DP 테이블 칸 L × (K+1) |
| --- | ---: | --- | ---: | ---: |
| 194 | 10 | [1, 9, 4] | 3 | 3 × 11 = 33 |
| 10^15 | 135 | [1, 0, …, 0] (0 이 15 개) | 16 | 16 × 136 = 2,176 |

전개 입력의 DP 테이블 33 칸 가운데 풀린 상태가 실제로 들어간 칸은 11 개입니다.

<!--/proof-->

풀린 상태로 자리 `pos` 에 오는 합은 앞 숫자 `pos` 개의 합이라 많아야 `9 · pos` 이고, 자리 0 에는 풀린 상태가 아예
없습니다. 그래서 들어가는 칸은 DP 테이블의 일부예요. 칸 자리는 처음에 다 잡아 두고, 들어가는 칸만 값을 적습니다.

#### 2단계 — 상한과 다음 붙음 정하기

이번 자리에 놓을 숫자의 위 끝은 붙음이 정합니다. 붙은 상태면 `digits[pos]`, 풀린 상태면 9 예요. 숫자 `x` 를 하나
놓을 때마다 다음 자리의 붙음도 함께 정해지는데, **지금 붙어 있고 `x` 가 `digits[pos]` 와 같을 때만** 다음 자리도 붙은
상태입니다. 전개 입력에서 숫자를 놓아 본 상태마다 상한과 놓아 본 숫자를 모았어요.

<!--proof:build-limits-->

| 상태 | 상한 | 놓아 본 x | ④ 로 끊은 자리 |
| --- | --- | --- | --- |
| 자리 0 · 합 0 · 붙음 | digits[0] = 1 | 0 · 1 | 없음 |
| 자리 1 · 합 0 · 풀림 | 9 | 0 … 9 | 없음 |
| 자리 2 · 합 1 · 풀림 | 9 | 0 … 9 | 없음 |
| 자리 2 · 합 2 · 풀림 | 9 | 0 … 8 | x = 9 (2 + 9 > 10) |
| 자리 1 · 합 1 · 붙음 | digits[1] = 9 | 0 … 9 | 없음 |
| 자리 2 · 합 10 · 붙음 | digits[2] = 4 | 0 | x = 1 (10 + 1 > 10) |

숫자를 놓아 본 상태 13 개 가운데 6 개를 실었습니다. 붙은 상태 3 개는 상한이 N 의 그 자리 숫자이고, 풀린 상태는 모두 9 입니다. 싣지 않은 자리 2 · 합 3 … 9 는 합 2 와 모양이 같습니다.

<!--/proof-->

놓아 본 숫자가 상한보다 적은 줄은 반복을 도중에 끊은 줄입니다. 합이 `K` 를 넘으면 숫자를 더 크게 놓아도 합이 줄어들
수 없으므로, 그 자리에서 반복을 끊어요. 이것이 갈래 ④ 입니다.

#### 3단계 — 풀린 상태의 칸 채우기

풀린 상태 하나의 값은 이번 자리에 `0` 부터 상한까지 놓아 얻은 다음 상태의 값을 더한 것이고, 그 합을 DP 테이블에
적습니다. 가장 쉬운 경우는 마지막 자리예요. 다음 상태가 숫자를 다 정한 뒤라, 합이 `K` 면 1(갈래 ②)이고 아니면 0 입니다.
불안한 경우는 **남은 자리를 전부 9 로 채워도 `K` 에 못 미치는 상태**예요. 그런 상태는 값을 구하기 전에 0 을 돌려주고
(갈래 ①) DP 테이블에 적지 않습니다. 마지막 자리에 풀린 상태로 오는 합 열 가지를 전부 실행했습니다.

<!--proof:build-fill-->

| 합 sum | 합을 10 으로 만드는 숫자 | 값 | ④ 로 끊은 자리 | 끝난 갈래 | DP 테이블 |
| --- | --- | ---: | --- | --- | --- |
| 0 | 없음 | 0 | 없음 | ① | -1 그대로 |
| 1 | x = 9 | 1 | 없음 | ⑤ | memo[2][1] = 1 |
| 2 | x = 8 | 1 | x = 9 | ⑤ | memo[2][2] = 1 |
| 3 | x = 7 | 1 | x = 8 | ⑤ | memo[2][3] = 1 |
| 4 | x = 6 | 1 | x = 7 | ⑤ | memo[2][4] = 1 |
| 5 | x = 5 | 1 | x = 6 | ⑤ | memo[2][5] = 1 |
| 6 | x = 4 | 1 | x = 5 | ⑤ | memo[2][6] = 1 |
| 7 | x = 3 | 1 | x = 4 | ⑤ | memo[2][7] = 1 |
| 8 | x = 2 | 1 | x = 3 | ⑤ | memo[2][8] = 1 |
| 9 | x = 1 | 1 | x = 2 | ⑤ | memo[2][9] = 1 |

마지막 자리에 풀린 상태로 오는 합 10 가지 가운데 9 칸이 DP 테이블에 적히고, 합 0 한 칸은 ① 이 먼저 0 을 돌려주어 -1 로 남습니다.

<!--/proof-->

합 0 줄은 갈래 ① 로 끝나 칸이 `-1` 로 남습니다. 합 1 줄은 `x = 9` 까지 다 놓아 보고, 합 2 부터는 합이 10 을 넘는
자리에서 ④ 로 끊어요. 반복이 끝나는 자리는 `x` 가 상한을 넘었을 때와 ④ 로 끊었을 때 둘뿐이고, ④ 로 끊은 뒤의 숫자는
합을 더 키울 뿐이라 빠뜨리는 수가 없습니다. 그래서 적힌 값은 그 상태가 맡는 수를 빠짐없이 한 번씩 센 것이에요.

#### 4단계 — 붙은 상태에서 DP 테이블 읽기

붙은 상태에서 `digits[pos]` 보다 작은 숫자를 놓으면 풀린 상태로 내려갑니다. 그 상태가 3단계에서 이미 정한 칸이면 다시
세지 않고 적힌 값을 읽어요(갈래 ③). 전개 입력의 `(자리 1 · 합 1 · 붙음)` 이 놓은 숫자마다 무엇을 했는지 모았습니다.

<!--proof:build-reads-->

| 놓은 숫자 | 다음 상태 | 하는 일 | 값 |
| --- | --- | --- | ---: |
| x = 0 | 자리 2 · 합 1 · 풀림 | ③ 이 memo[2][1] 에서 읽는다 | 1 |
| x = 1 | 자리 2 · 합 2 · 풀림 | ③ 이 memo[2][2] 에서 읽는다 | 1 |
| x = 2 | 자리 2 · 합 3 · 풀림 | ③ 이 memo[2][3] 에서 읽는다 | 1 |
| x = 3 | 자리 2 · 합 4 · 풀림 | ③ 이 memo[2][4] 에서 읽는다 | 1 |
| x = 4 | 자리 2 · 합 5 · 풀림 | ③ 이 memo[2][5] 에서 읽는다 | 1 |
| x = 5 | 자리 2 · 합 6 · 풀림 | ③ 이 memo[2][6] 에서 읽는다 | 1 |
| x = 6 | 자리 2 · 합 7 · 풀림 | ③ 이 memo[2][7] 에서 읽는다 | 1 |
| x = 7 | 자리 2 · 합 8 · 풀림 | ③ 이 memo[2][8] 에서 읽는다 | 1 |
| x = 8 | 자리 2 · 합 9 · 풀림 | ③ 이 memo[2][9] 에서 읽는다 | 1 |
| x = 9 | 자리 2 · 합 10 · 붙음 | DP 테이블을 거치지 않고 센다 | 1 |

자리 1 · 합 1 · 붙음 에서 ③ 이 9 번 실행되어 9 를 받고, 붙은 채 내려간 x = 9 가 1 을 더해 10 입니다. 전개 입력 전체에서 붙은 상태에 들어간 횟수는 3 번입니다.

<!--/proof-->

붙은 상태는 값을 구하고도 DP 테이블에 적지 않습니다. 붙은 상태로 자리 `pos` 에 오는 경로는 `N` 의 앞부분을 그대로
따라온 하나뿐이라, 적어 두어도 다시 찾을 일이 없어요. 그 사실은 아래 「붙은 상태를 DP 테이블 밖에 두는 까닭」에서
값으로 봅니다.

#### 5단계 — 수 0 빼기

첫 호출은 `(자리 0 · 합 0 · 붙음)` 입니다. 맨 앞에 0 을 놓는 것을 허용했으므로, 이 호출이 센 것은 「`L` 자리 문자열 중
`N` 이하이고 자릿수 합이 `K` 인 것」이고 그 안에 문자열 `00…0`, 곧 **수 0** 이 들어 있어요. 과제의 범위는 1 이상이라
그 하나를 빼야 하는데, 자릿수 합이 0 인 수는 0 뿐이라 `K = 0` 일 때만 뺍니다(갈래 ⑥).

<!--proof:build-zero-->

| 입력 | count(0, 0, true) | 빼는 수 | 답 |
| --- | ---: | ---: | ---: |
| N = 100 · K = 0 | 1 | 1 | 0 |
| N = 100 · K = 1 | 3 | 0 | 3 |
| N = 194 · K = 10 | 19 | 0 | 19 |

#### 이 방법이 기대는 전제

이 방법은 아래 넷이 함께 맞을 때 성립합니다. 하나라도 빠지면 DP 테이블의 한 칸이 한 가지 뜻을 갖지 못해요.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 범위가 `[0, N]` 처럼 한쪽 끝으로 주어진다 | 붙음 하나로 상한을 정한다 | 구간 `[A, B]` 면 `[0, B]` 와 `[0, A−1]` 을 따로 세어 뺀다 |
| 세는 조건을 왼쪽 자리부터 읽으며 판정할 수 있다 | 자리마다 합을 한 칸씩 옮긴다 | 조건이 수 전체를 봐야 판정되면 상태가 자리로 끊기지 않는다 |
| 판정에 필요한 누적 정보가 작다 | 열이 합 `0 … K` 로 끝난다 | 누적 정보의 가짓수만큼 열이 늘어 DP 테이블을 잡지 못한다 |
| 풀린 상태의 답이 앞 숫자와 무관하다 | 풀린 상태끼리 칸 하나를 나눠 쓴다 | 붙은 상태를 같은 칸에 넣으면 답이 틀린다 |

넷째 전제가 깨지는 모습은 「아이디어를 떠올리는 과정」의 `N = 100 · K = 2` 에서 이미 봤습니다. 붙은 상태와 풀린
상태가 칸 하나를 나눠 쓰자 답이 3 에서 4 가 됐어요. 셋째 전제는 세는 조건을 바꿔도 대개 남습니다 — 「숫자 7 이 한 번도
안 나온다」를 세면 합을 기억할 필요가 없어 열이 통째로 사라지고, 절차는 그대로예요.

#### 붙은 상태를 DP 테이블 밖에 두는 까닭

붙은 상태까지 칸에 넣으면 DP 테이블이 `(자리, 합, 붙음)` 세 첨자가 됩니다. 넣을 가치가 있는지는 붙은 상태에 몇 번
들어가고, 같은 붙은 상태에 다시 들어가는 일이 있는지로 정해져요. 자리 수와 모양이 다른 입력 다섯에 실행했습니다.

<!--proof:build-tight-once-->

| 입력 | 자리 수 L | 붙은 상태 수의 위 끝 L+1 | 붙은 상태에 들어간 횟수 | 같은 붙은 상태에 다시 들어간 횟수 | DP 테이블에 적은 칸 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 194 · K = 10 | 3 | 4 | 3 | 0 | 10 |
| 99,999 · K = 20 | 5 | 6 | 3 | 0 | 56 |
| 123,456,789 · K = 30 | 9 | 10 | 8 | 0 | 146 |
| 999,999,999,999,999 · K = 50 | 15 | 16 | 6 | 0 | 479 |
| 10^15 · K = 50 | 16 | 17 | 12 | 0 | 485 |

다섯 입력을 합쳐 같은 붙은 상태에 다시 들어간 횟수는 0 번입니다. 붙음까지 첨자로 두면 DP 테이블이 2 × 16 × 136 = 4,352 칸이고, 풀린 상태만 두면 16 × 136 = 2,176 칸입니다.

<!--/proof-->

붙은 상태에 들어간 횟수는 입력마다 `L + 1` 을 넘지 않고, 같은 붙은 상태에 다시 들어간 일은 한 번도 없습니다. 적어 두어도
읽힐 일이 없는 칸이라 DP 테이블을 절반으로 줄이는 쪽을 골랐어요. 가장 작게 잡으면 DP 테이블이 `N` 의 자리 수 × 합의
가짓수가 됩니다.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 이렇습니다. 이렇게 하면 `10^15` 개의 수를 하나씩 보던 일이 DP 테이블 칸
`L × (K+1)` 개를 정하는 일이 돼요.

1. `N` 을 자릿수 배열 `digits` 로 가르고, `memo` 를 `L × (K+1)` 칸의 `-1` 로 깐다
2. `count(pos, sum, tight)` 에서, 남은 자리를 9 로 채워도 `K` 에 못 미치면 0 을 돌려준다
3. 자리를 다 정했으면 합이 `K` 인지로 1 이나 0 을 돌려준다
4. 풀린 상태이고 `memo[pos][sum]` 이 정해져 있으면 그 값을 돌려준다
5. 상한을 `tight` 로 고르고, `x` 를 0 부터 상한까지 놓아 다음 상태의 값을 더한다 — 합이 `K` 를 넘으면 끊는다
6. 풀린 상태면 합을 `memo[pos][sum]` 에 적고, 합을 돌려준다
7. `count(0, 0, true)` 에서 `K = 0` 일 때만 1 을 빼서 돌려준다

### 수행으로 알아보는 알고리즘 — DP 테이블 열 칸을 열두 걸음으로 채워 194 까지 센다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const N = 194;
const K = 10;
// 이 절이 끝나면 19 가 나와야 한다
```

`N` 을 왜 하필 이 값으로 뒀을까요? 갈래를 한꺼번에 확인하려는 것입니다. 자리가 셋이라 DP 테이블 `3 × 11` 이 한 화면에
들어오고, 가운데 자리가 9 라 붙은 상태가 풀린 칸을 여러 번 읽는 자리가 생겨요. 마지막 자리가 4 라 붙은 상태의 상한이
9 보다 작아지는 자리도 나옵니다. 앞에 0 두 개를 놓은 상태는 남은 한 자리로 합 10 을 못 만들어 가지치기가 실행돼요.
절차 전체를 한 장으로 적으면 이렇습니다.

```text
digits ← N 을 왼쪽부터 자릿수로 가른 배열, L ← 그 길이
DP 테이블 memo 를 L × (K+1) 로 만들고 전부 -1 로 둔다

count(pos, sum, tight):
    sum + 9 × (L − pos) < K 이면 0 을 돌려준다          ① 남은 자리로 K 에 못 미친다
    pos = L 이면 sum = K 일 때 1, 아니면 0              ② 자리를 다 정했다
    tight 가 거짓이고 memo[pos][sum] 이 정해져 있으면   ③ DP 테이블에서 읽는다
        그 값을 돌려준다
    limit ← tight 이면 digits[pos], 아니면 9
    total ← 0
    x 를 0 부터 limit 까지:
        sum + x > K 이면 반복을 끊는다                  ④ 합이 K 를 넘었다
        total ← total + count(pos+1, sum+x, tight 이고 x = digits[pos])
    tight 가 거짓이면 memo[pos][sum] ← total            ⑤ 풀린 상태의 값만 적는다
    total 을 돌려준다

count(0, 0, 참) 에서 K = 0 이면 1 을 뺀 값을 돌려준다   ⑥ 수 0 은 [1, N] 밖이다
```

#### 1. N 을 자리로 가르고 DP 테이블을 깐다

「아이디어 상세」의 1단계에서 정한 크기대로 DP 테이블을 만듭니다. `-1` 이 「아직 안 정한 칸」이라는 표시예요.

```ts
const digits = [...String(N)].map(Number);
const L = digits.length;

// memo[pos][sum] = 풀린 상태(tight 가 거짓)로 자리 pos 에 왔을 때의 답. -1 은 아직 안 정한 칸이다.
const memo: number[][] = Array.from({ length: L }, () =>
  new Array<number>(K + 1).fill(-1),
);
```

실행하면 이렇게 나옵니다.

<!--proof:walk-init-->

```text
digits = [1, 9, 4] · L = 3
memo = 3 × 11 칸 · 전부 -1
  └ 첫 호출 count(0, 0, true) 가 들어가는 순간의 DP 테이블이다
```

#### 2. 이번 자리의 상한을 정하고 숫자를 놓는다

상한은 `tight` 가 고르고, 놓은 숫자가 다음 자리의 `tight` 를 정합니다. 여기서 가장 중요한 것은 `tight &&` 예요. 이번
자리만 같아서는 붙은 상태가 되지 않습니다.

```ts
const limit = tight ? (digits[pos] as number) : 9;
for (let x = 0; x <= limit; x++) {
  total += count(pos + 1, sum + x, tight && x === (digits[pos] as number));
}
```

첫 호출 `count(0, 0, true)` 에서 이 조각이 놓는 숫자는 이렇습니다.

<!--proof:walk-pick-->

| 놓는 숫자 | 비교 | 다음 tight | 다음 상태 |
| --- | --- | --- | --- |
| x = 0 | 0 < digits[0] = 1 | false — 풀린다 | 자리 1 · 합 0 · 풀림 |
| x = 1 | 1 = digits[0] = 1 | true — 붙은 채 | 자리 1 · 합 1 · 붙음 |
| x = 2 | 2 > digits[0] = 1 | 놓지 않는다 | 상한 밖 |

`x = 0` 쪽은 맨 앞이 0 인 세 자리 문자열, 곧 두 자리 이하의 수 전부입니다. `x = 1` 쪽은 `100` 부터 `194` 까지예요. 두
쪽을 더한 것이 답입니다.

#### 짚고 가기 — 표를 읽을 때 tight 를 안 보면 전개 입력에서는 답이 안 틀린다

갈래 ③ 은 `tight` 가 거짓일 때만 DP 테이블을 읽습니다. 그 조건을 빼고 언제나 읽으면 코드가 한 줄 짧아지고, 같은
`(자리, 합)` 이면 값도 같을 것처럼 보여요.

```ts
if (!tight) {                                    // ← 이 조건을 빼면
  const done = (memo[pos] as number[])[sum] as number;
  if (done !== -1) return done;                  //   붙은 상태도 풀린 칸의 값을 읽는다
}
```

**전개 입력에서는 답이 안 틀립니다.** `N = 194` 의 붙은 상태는 `(자리 1, 합 1)` · `(자리 2, 합 10)` 인데, 그 칸으로 오는
풀린 상태가 없어서 읽을 값이 없기 때문이에요. 여러 입력에 나란히 실행해 봅시다.

<!--proof:pause-shared-->

| 호출 | 바른 코드 | 표를 읽을 때 tight 를 안 본 코드 |
| --- | ---: | ---: |
| digitDp(194, 10) | 19 | 19 |
| digitDp(20, 2) | 3 | 3 |
| digitDp(100, 1) | 3 | 3 |
| digitDp(100, 2) | 3 | 4 |
| digitDp(100, 0) | 0 | 0 |
| digitDp(99, 18) | 1 | 1 |
| digitDp(999, 27) | 1 | 1 |
| digitDp(1,000, 1) | 4 | 4 |

N ≤ 3,000 · K ≤ 27 의 84,000 쌍을 모두 대조하면 27,855 쌍에서 답이 다릅니다.

<!--/proof-->

**`N = 100 · K = 2` 가 3 에서 4 로 갑니다.** 「아이디어를 떠올리는 과정」에서 본 칸과 같은 자리예요 — 풀린 상태가 먼저
`(자리 2, 합 1)` 에 1 을 적고, 마지막 자리 상한이 0 인 붙은 상태가 그 1 을 읽어 `101` 을 셉니다. 전개 입력 하나만
확인하면 갈리는 쌍을 하나도 만나지 않으니, 조건을 빼도 되는 것처럼 보이는 자리예요.

#### 3. 풀린 상태의 칸을 채운다

「아이디어 상세」의 3단계를 코드로 옮깁니다. 가지치기 ① 이 기저 ② 보다 먼저 옵니다.

```ts
// ① 남은 자리를 전부 9 로 채워도 합이 K 에 못 미친다.
if (sum + 9 * (L - pos) < K) return 0;
// ② 자리를 다 정했다 — 합이 K 인 것만 하나로 센다.
if (pos === L) return sum === K ? 1 : 0;
// ④ 합이 K 를 넘었다. x 가 커지면 더 넘으므로 이 자리에서 멈춘다.
if (sum + x > K) break;
// ⑤ 풀린 상태의 값만 DP 테이블에 적는다.
if (!tight) (memo[pos] as number[])[sum] = total;
```

첫 호출이 `x = 0` 으로 풀린 상태를 만든 뒤, 자리 2 의 풀린 칸을 다 채우고 자리 1 로 돌아온 순간의 DP 테이블입니다.

<!--proof:walk-fill-->

```text
자리 2 의 풀린 상태를 다 끝낸 직후
  memo[2] = [· 1 1 1 1 1 1 1 1 1 ·]
  memo[1] = [· · · · · · · · · · ·]
자리 1 · 합 0 · 풀림의 반복을 끝낸 직후
  memo[1] = [9 · · · · · · · · · ·]
  └ · 은 아직 -1 인 칸이다
```

#### 짚고 가기 — 가지치기를 빼도 답은 그대로다

갈래 ① 을 지우면 어떻게 될까요. 아래로 더 내려가긴 하지만 어차피 기저 ② 가 `sum = K` 를 검사하니 **답은 안
바뀝니다.** 여러 입력에 나란히 실행해 봅시다.

<!--proof:pause-prune-->

| 입력 | 가지치기 있는 답 | 없는 답 | 있을 때 들어간 상태 | 없을 때 들어간 상태 |
| --- | ---: | ---: | ---: | ---: |
| 194 · K = 10 | 19 | 19 | 78 | 88 |
| 999 · K = 27 | 1 | 1 | 31 | 301 |
| 999,999,999,999,999 · K = 135 | 1 | 1 | 151 | 9,601 |
| 999,999,999,999,999 · K = 100 | 457,119,685,656 | 457,119,685,656 | 3,860 | 8,920 |
| 10^15 · K = 50 | 10,614,794,989,443 | 10,614,794,989,443 | 4,448 | 5,603 |

입력 5 개 가운데 5 개에서 두 답이 같습니다. 9 가 15 개이고 K = 135 이면 들어간 상태가 151 번과 9,601 번으로 64 배 차이입니다.

<!--/proof-->

그래서 이 자리는 지나치기 쉬워요 — 답을 대조하는 테스트로는 가지치기가 있는지 없는지 구분되지 않습니다. 갈리는 것은
들어간 상태의 수이고, `K` 가 클수록 「채워도 모자란」 상태가 많아져 차이가 커져요. 가지치기가 DP 테이블을 읽기 **전에**
있는 것도 뜻이 있습니다. 그 상태의 답은 언제나 0 이고 식 하나로 판정되니, 칸을 쓰고 다시 읽는 것보다 다시 계산하는 편이
짧아요.

#### 4. 붙은 상태를 따라가며 DP 테이블을 읽는다

첫 호출로 돌아와 `x = 1` 을 놓으면 `digits[0]` 과 같아 붙은 채 자리 1 로 갑니다. 이제 자리 1 의 상한은
`digits[1] = 9` 이고, `x = 0 … 8` 을 놓으면 풀린 상태로 내려가 갈래 ③ 이 DP 테이블을 읽어요.

```ts
// ③ 풀린 상태이고 그 칸을 이미 정해 두었다.
if (!tight) {
  const done = (memo[pos] as number[])[sum] as number;
  if (done !== -1) return done;
}
```

전개 입력에서 이 조각이 실행된 자리를 세면 이렇습니다.

#### 짚고 가기 — 수 0 을 빼지 않으면 K = 0 에서 답이 1 이 된다

첫 호출은 맨 앞에 0 을 놓는 것을 허용하므로 문자열 `000`, 곧 **수 `0`** 도 셉니다. 자릿수 합이 0 이라 `K = 0` 일 때만
세어지고, 그래서 그때만 1 을 뺍니다 — 갈래 ⑥ 이에요. 그 뺄셈을 지우면 어떻게 되는지 실행해 봅시다.

<!--proof:pause-zero-->

| 호출 | 바른 코드 | 0 을 안 뺀 코드 |
| --- | ---: | ---: |
| digitDp(100, 0) | 0 | 1 |
| digitDp(1, 0) | 0 | 1 |
| digitDp(10^15, 0) | 0 | 1 |
| digitDp(100, 1) | 3 | 3 |
| digitDp(194, 10) | 19 | 19 |

**위 세 줄이 0 에서 1 로 갑니다.** `N` 이 100 이든 1 이든 `10^15` 이든 똑같이 1 이 나오는 것이 이 잘못의 모양이에요
— 잘못 센 것이 언제나 수 `0` 하나이기 때문입니다. `K` 가 0 이 아닌 아래 두 줄은 안 갈리니, `K = 0` 인 경우가 테스트에
없으면 이 줄이 빠진 채로 통과합니다.

#### 6. 전체 코드

조각을 한 함수로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 마지막 줄뿐이에요 — 첫 호출의 결과에서 수 `0` 을
뺍니다.

```ts
export function digitDp(N: number, K: number): number {
  const digits = [...String(N)].map(Number);
  const L = digits.length;

  // memo[pos][sum] = 풀린 상태(tight 가 거짓)로 자리 pos 에 왔을 때의 답. -1 은 아직 안 정한 칸이다.
  const memo: number[][] = Array.from({ length: L }, () =>
    new Array<number>(K + 1).fill(-1),
  );

  function count(pos: number, sum: number, tight: boolean): number {
    // ① 남은 자리를 전부 9 로 채워도 합이 K 에 못 미친다.
    if (sum + 9 * (L - pos) < K) return 0;
    // ② 자리를 다 정했다 — 합이 K 인 것만 하나로 센다.
    if (pos === L) return sum === K ? 1 : 0;
    // ③ 풀린 상태이고 그 칸을 이미 정해 두었다.
    if (!tight) {
      const done = (memo[pos] as number[])[sum] as number;
      if (done !== -1) return done;
    }

    const limit = tight ? (digits[pos] as number) : 9;
    let total = 0;
    for (let x = 0; x <= limit; x++) {
      // ④ 합이 K 를 넘었다. x 가 커지면 더 넘으므로 이 자리에서 멈춘다.
      if (sum + x > K) break;
      total += count(pos + 1, sum + x, tight && x === (digits[pos] as number));
    }

    // ⑤ 풀린 상태의 값만 DP 테이블에 적는다.
    if (!tight) (memo[pos] as number[])[sum] = total;
    return total;
  }

  // ⑥ 수 0 은 [1, N] 밖인데 count 가 그것을 한 번 센다. 자릿수 합이 0 인 수는 0 뿐이다.
  return count(0, 0, true) - (K === 0 ? 1 : 0);
}
```

기호표의 `pos` · `sum` · `tight` · `digits` · `memo` 를 코드에서도 같은 이름으로 씁니다. 실행하면 이렇게 나와요.

### 알아 두면 좋은 개념 — 사전식 순서로 세기

전개에서 `[0, 194]` 를 두 무리로 갈랐습니다. 맨 왼쪽 자리에 0 을 놓은 무리와 1 을 놓은 무리였고, 앞의 무리는 남은 두
자리를 마음대로 쓸 수 있었어요. 그 가르기를 자리마다 이어서 하면 `[0, N]` 전체가 **`N` 보다 처음 작아지는 자리**로
갈립니다.

<!--proof:related-split-->

N = 194 이면 이렇게 갈립니다.

| 처음 작아지는 자리 | 그 무리 | 자유 자리 | 수의 개수 |
| --- | --- | ---: | ---: |
| 자리 0 | 앞 숫자 없이 1 보다 작은 숫자 | 2 | 100 |
| 자리 1 | 1 뒤에 9 보다 작은 숫자 | 1 | 90 |
| 자리 2 | 19 뒤에 4 보다 작은 숫자 | 0 | 4 |
| 끝까지 같다 | 194 자신 | 0 | 1 |

N = 2,045 이면 이렇게 갈립니다.

| 처음 작아지는 자리 | 그 무리 | 자유 자리 | 수의 개수 |
| --- | --- | ---: | ---: |
| 자리 0 | 앞 숫자 없이 2 보다 작은 숫자 | 3 | 2,000 |
| 자리 1 | 2 뒤에 0 보다 작은 숫자 | 2 | 0 |
| 자리 2 | 20 뒤에 4 보다 작은 숫자 | 1 | 40 |
| 자리 3 | 204 뒤에 5 보다 작은 숫자 | 0 | 5 |
| 끝까지 같다 | 2045 자신 | 0 | 1 |

개수의 합이 195 와 2,046 이라 두 입력 모두 N + 1 과 같습니다.

<!--/proof-->

무리 하나가 「앞자리는 `N` 과 같고, 이 자리에서 처음 작아지고, 뒤는 마음대로」라서 서로 겹치지 않고 빠지는 수도 없어요.
붙은 상태는 이 가르기에서 **아직 어느 무리로도 가지 않은 경로**이고, 풀리는 순간이 곧 무리가 정해지는 순간입니다.

이 가르기를 **사전식 순서로 세기**, 또는 그 값을 순위로 읽어 **랭킹(ranking)** 이라고 부릅니다. 정해진 순서로 늘어놓은
대상들 중 어떤 것이 몇 번째인지를, 처음 갈라지는 자리마다 「그 뒤는 자유」인 개수를 더해 구하는 방식이에요. 같은
가르기를 다른 자리에서도 만납니다 — **`k` 번째 순열 구하기**는 첫 원소를 고정할 때마다 뒤가 `(n−1)!` 가지임을 이용해
자리마다 갈라 세고, [트라이](../../string/trie/trie-guide.md) 에서 사전순 `k` 번째 문자열을 찾는 것도 자식마다 그 아래에
몇 개가 있는지를 더해 가는 같은 가르기입니다. 이 글은 그 무리마다 「자릿수 합이 `K` 인 것」만 세는 자리까지 다뤘습니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, DP 테이블 없이 식으로 답을 낼 수 있는지, 무엇이 매 순간
참으로 남는지, 그리고 얼마나 드는지 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 어떤 범위 안의 수를 센다 | 범위가 `[0, N]` 처럼 한쪽 끝으로 주어진다. 구간 `[A, B]` 면 두 번 세어 뺀다 | 붙음 `tight` 하나로 상한을 정한다 |
| 조건을 왼쪽 자리부터 판정한다 | 자릿수 합 · 「숫자 7 이 안 나온다」 · 「이웃한 두 자리가 다르다」 | DP 테이블의 한 축이 자리다 |
| 누적 정보가 작다 | 여기서는 합 하나이고 그 범위가 `0` 부터 `K` 까지다 | DP 테이블의 다른 축이 합이다 |
| `N` 의 값은 커도 자리 수가 작다 | 비용이 값이 아니라 자리 수에 붙는다 | DP 테이블의 크기가 `N` 의 값과 무관하다 |

넷째 조건이 이 방법의 강점입니다. 목표 합을 과제의 위 끝 135 로 두고 `N` 만 키우면 DP 테이블의 크기가 이렇게 변해요.

<!--proof:fit-scale-->

| N | 자리 수 L | K = 135 일 때 DP 테이블 칸 |
| --- | ---: | ---: |
| 10^15 | 16 | 16 × 136 = 2,176 |
| 10^18 | 19 | 19 × 136 = 2,584 |
| 10^100 | 101 | 101 × 136 = 13,736 |

N 이 10^15 에서 10^100 으로 10^85 배가 되어도 자리 수는 16 에서 101 로 늘 뿐입니다.

<!--/proof-->

묻는 것을 「1 이상 `N` 이하의 수 중 숫자 7 이 안 들어간 것」으로 바꾸면 합을 기억할 필요가 없어져 DP 테이블의 열 축이
통째로 사라질 뿐, 절차는 그대로예요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "1 이상 N 이하의 수 중"  "A 이상 B 이하에서 ~ 를 만족하는 수의 개수"
  "각 자리의 숫자가"  "자릿수의 합이"  "숫자 4 를 포함하지 않는"  "인접한 두 자리가"

제약에 이런 모양이 보이면
  N ≤ 10^15 · 10^18 처럼 값이 크다      ← 하나씩 셀 수 없다는 신호
  자리 수는 15 ~ 20 안팎이다            ← 자리를 축으로 삼을 수 있다는 신호
  누적해야 할 정보가 하나둘이다         ← DP 테이블의 다른 축이 작다는 신호
```

반대로 **「집합에서 원소를 골라 담는다」** 가 보이면 상태의 한 축이 「항목 수」인
[0/1 배낭](../knapsack01/knapsack01-guide.md) 형태이고, **「자릿수를 자리별로 나누어 정렬한다」** 가 보이면
[기수 정렬](../../sorting/radixSort/radixSort-guide.md) 형태입니다. DP 테이블을 쓰는 이웃 과제와 나란히 놓으면 이렇습니다.

| 과제 | 상태 축 | DP 테이블의 크기가 붙는 것 |
| --- | --- | --- |
| 자릿수 조건을 만족하는 수의 개수 (이 글) | 자리와 누적 정보 `(pos, sum)` | `N` 의 **자리 수** |
| [0/1 배낭](../knapsack01/knapsack01-guide.md) | 항목 수와 용량 `(i, c)` | 용량의 **값** |
| [부분집합 합 판정](../subsetSum/subsetSum-guide.md) | 항목 수와 목표 합 `(i, t)` | 목표 합의 **값** |
| [동전 조합의 경우의 수](../coinChangeWays/coinChangeWays-guide.md) | 동전 종류와 금액 `(i, a)` | 금액의 **값** |

#### 실제로 쓰이는 곳

자릿수 합 함수 자체는 확인 절차와 알고리즘 분석 양쪽에서 오래 쓰였습니다. 자릿수 합의 확률적 성질을 정리한 조사 논문이
도입부 첫 문장을 이렇게 적었어요.

```text
"Positional numeral systems have long been used in the history of human civilizations,
 and the sum-of-digits function of an integer, which equals the sum of all its digits in
 some given base, appeared naturally in multitudinous applications such as divisibility
 check or check-sum algorithms."                                                  — §1

같은 절이 자릿수 합이 정확히 값으로 나타나는 자리를 목록으로 든다. 그중 둘.

"The number of comparators used by Batcher's bitonic sorting network"
"The minimum number of comparisons used by top-down recursive mergesort,
 bottom-up mergesort, queue-mergesort"

  — Chen, Hwang, Zacharovas, arXiv:1212.6697 (조회 2026-09-03)
```

그 논문이 다루는 것과 이 글이 세는 것은 **같은 대상을 확률로 보는가 개수로 보는가**의 차이입니다. 논문은 `[0, N)` 에서
수 하나를 고를 때 자릿수 합이 얼마가 될 확률을 다루고, 이 글은 자릿수 합이 `K` 인 수가 몇 개인지를 내요. 자릿수 합의
누적 함수를 다루는 최근 연구 하나는 그 결과가 **생물학 쪽 논문에서 나왔다**고 초록에 적었습니다.

#### 경쟁 설계와의 대조

같은 개수를 DP 테이블 없이 **식 하나로** 낼 수 있습니다. 자유 자리 `m` 개를 합 `t` 로 채우는 방법의 수를 `W(m, t)`
라 하면, 「사전식 순서로 세기」가 가른 무리마다 `W` 를 한 번씩 부르면 답이 나와요. `W` 의 닫힌 형태는 「수식 정의와
유도」가 냅니다. 두 설계를 같은 입력에 실행해 계수를 세 봅시다.

**입력을 왜 전개 입력으로 안 골랐는지 먼저 적습니다.** 전개는 `N = 194` · `K = 10` 이라 자리가 셋뿐이고, 그 크기에서는
기본 연산이 536 대 77 이라 어느 쪽이 왜 적은지가 값에서 나오지 않아요. 그래서 대조는 **과제의 위 끝**에서 합니다 —
`N` 은 열다섯 자리로 두고 `K` 만 갈아 끼웁니다. 두 설계의 모양이 달라 앞 절이 센 재귀 호출 수(**방문 노드**)로는 잴 수 없으므로, 이 절만
산술 · 비교 · 칸 접근 한 번을 각각 1 로 센 **기본 연산**으로 잽니다.

```text
입력 A   N = 999,999,999,999,999 · K = 115
입력 B   N = 999,999,999,999,999 · K = 116     A 에서 K 만 하나 올렸다
입력 C   N = 10^15 · K = 50                    N 의 모양이 다르다 (자릿수 합이 1 이다)
입력 D   N = 194 · K = 10                      전개 입력. 차이가 안 갈리는 것을 보이려고 함께 잰다

기본 연산  두 설계 모두 산술 · 비교 · 칸 접근 한 번을 각각 1 로 센다
추가 칸    입력 밖에 새로 잡아 동시에 들고 있는 칸 수. 메모 표 L × (K+1) 을 식으로 적었고
           자릿수 배열 · 재귀 스택 · BigInt 임시값은 뺐다
```

| 입력과 계수 | 자릿수 DP (이 글) | 별과 막대 닫힌 형태 |
| --- | --- | --- |
| 입력 A · 기본 연산 | 19,899 | **18,879** |
| 입력 B · 기본 연산 | **19,088** | 19,128 |
| 입력 C · 기본 연산 | 35,649 | **201** |
| 입력 D(전개) · 기본 연산 | 536 | **77** |
| 입력 A · 추가 칸 | 1,740 | **0** |
| 입력 C · 추가 칸 | 816 | **0** |

**입력 A 와 B 사이에서 순서가 뒤집힙니다.** `K` 를 115 에서 116 으로 하나만 올렸는데 19,899 대 18,879 였던 것이
19,088 대 19,128 이 돼요. 두 비용이 `K` 에 대해 반대로 움직이기 때문입니다.

```text
K 가 커질 때 두 설계의 비용이 가는 방향

  닫힌 형태   포함배제 항이 ⌊t/10⌋ + 1 개라 K 에 비례해 늘어난다        ↗
  자릿수 DP   상태 수가 K = 67 근처에서 가장 크고, 그 뒤로는 갈래 ①
              (남은 자리로 K 에 못 미친다) 이 늘어 줄어든다              ↘
        → N 이 9 가 15 개일 때 K = 116 에서 순서가 뒤집힌다
```

**뒤집히는 자리를 정하는 것은 `N` 의 자릿수 합입니다.** 닫힌 형태는 「이 자리에서 작아지는」 무리마다 `W` 를 한 번
부르므로 부르는 횟수가 `digits[0] + digits[1] + …` 예요. 입력 C 는 그 합이 1 이라 `W` 를 한 번만 부르고, `K = 50` 에서
35,649 대 201 이 됩니다. `N` 이 그 모양이면 어느 `K` 에서도 순서가 안 뒤집혀요.

**이 글의 절차가 내주는 축이 둘입니다.** 첫째는 추가 칸이에요 — 입력 A 에서 1,740 대 0 이고, 닫힌 형태는 DP 테이블을
아예 안 쓰므로 어느 입력에서도 안 뒤집힙니다. 둘째는 대부분의 `K` 에서의 연산 수입니다. `K` 가 116 아래이면 닫힌
형태가 앞서요.

| 축 | 자릿수 DP (이 글) | 별과 막대 닫힌 형태 | 뒤집히는가 |
| --- | --- | --- | --- |
| 기본 연산 | 입력 B 에서 19,088 | 입력 B 에서 19,128 | `K = 116` 에서 뒤집힌다 |
| 추가 칸 | 입력 A 에서 1,740 | 0 | 안 뒤집힌다 — 이쪽이 내주는 축이다 |
| 적용 범위 | 자릿수 조건이 바뀌어도 같은 틀 | 조건마다 식을 다시 유도한다 | 값의 축이 아니다 |
| 정확도 | 배정밀도로 끝까지 정확하다 | 중간 항이 `2^53` 을 넘는다 | 값의 축이 아니다 |

**그럼에도 이 글이 자릿수 DP 를 쓰는 축도 둘입니다.** 첫째는 적용 범위예요 — 닫힌 형태는 「자릿수 합이 `K`」일 때만
성립하는 식이라 조건이 「숫자 7 이 안 나온다」로 바뀌면 처음부터 다시 유도해야 하는데, 자릿수 DP 는 상태 정의만 바꾸면
같은 틀을 그대로 씁니다. 둘째는 정확도입니다 — 닫힌 형태는 포함배제라 답보다 훨씬 큰 항을 만들었다가 빼는 꼴이고, 그
항이 배정밀도 정수의 정확 범위를 넘으면 아래 자릿수 몇 개가 조용히 사라져요. 위 표의 계수를 `BigInt` 로 센 것이 그
때문이고, 그렇게 하면 곱셈 · 나눗셈이 더 듭니다.

항 둘만 더해도 정확 범위를 넘어섭니다. 자릿수 DP 쪽은 이 과제에서 답이 `10^15` 를 안 넘어 배정밀도로 끝까지 정확해요 —
값이 아니라 판정의 축이지만, 닫힌 형태를 그대로 쓰려면 큰 수 연산을 함께 들여야 한다는 뜻입니다.

두 설계 다 결정론적이라 같은 입력이면 몇 번을 실행해도 같은 계수가 나옵니다. 위 수치는 `digitDp-guide.alt.ts` 를
`tools/bench-alt.ts` 로 실행해 얻은 것이고, 입력 넷의 정의도 그 파일에 상수로 있어요.

### 수식 정의와 유도

`W(m, t)` 를 정의하고, 그 정의를 작은 값에 넣어 검산하고, 닫힌 형태를 유도한 다음 과제의 규모를 넣습니다.

```text
정의   자유 자리 m 개를 합 t 로 채우는 방법의 집합과 그 크기 W(m, t)
  ↓
검산   그 정의를 m = 2 에 넣어 원소를 적는다
  ↓
유도   생성 함수를 세워 포함배제로 닫힌 형태를 낸다
       답 전체를 "처음 작아지는 자리" 로 갈라 W 의 합으로 적는다
  ↓
계수   닫힌 형태에 과제의 위 끝을 넣어 수치를 낸다
```

**먼저 집합입니다.** 각 자리에 0 부터 9 까지의 숫자를 놓은 길이 `m` 의 수열 중 합이 `t` 인 것들을 모읍니다.

$$F(m, t) = \Bigl\{\,(a_1, \dots, a_m) \;\Bigm|\; 0 \le a_i \le 9,\ \sum_{i=1}^{m} a_i = t \,\Bigr\}, \qquad W(m, t) = \bigl\lvert F(m, t) \bigr\rvert$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $m$ | 마음대로 쓸 수 있는 자리의 개수 | $0 \le m \le L$ |
| $t$ | 그 자리들이 만들어야 하는 합 | $0 \le t \le 9m$ |
| $F(m,t)$ | 그런 수열의 집합 | — |
| $W(m,t)$ | 그 집합의 크기 | $t < 0$ 이거나 $t > 9m$ 이면 $0$ |
| $d_p$ | `N` 의 자리 `p` 숫자 — 파트 1 의 `digits[p]` 와 같다 | $0 \le d_p \le 9$ |
| $S_p$ | $d_0 + \dots + d_{p-1}$ — 자리 `p` 앞까지의 합 | $S_0 = 0$ |
| $A(N,K)$ | 이 과제의 답 — 파트 1 의 `digitDp(N, K)` 와 같다 | $A(N,K) \ge 0$ |

**정의를 값에 넣어 검산해 봅시다.** $m = 2$ 이고 $t = 5$ 면 두 자리의 합이 5 인 수열이고, $t = 10$ 이면 「각 자리가
9 이하」라는 조건이 실제로 걸립니다.

<!--proof:math-enumerate-->

```text
F(2, 5) 의 원소
  (0,5) (1,4) (2,3) (3,2) (4,1) (5,0)   →  W(2, 5) = 6

F(2, 10) 의 원소
  (1,9) 부터 (9,1) 까지 9 개   →  W(2, 10) = 9
  (0,10) 과 (10,0) 은 자리 하나가 9 를 넘어 들지 않는다

(1 + z + … + z^9)^2 의 z^5 계수 = 6
```

마지막 줄이 다음 유도의 출발점입니다. 자리 하나가 만들 수 있는 합을 지수로 적어 `1 + z + … + z^9` 로 두고 자리 `m`
개를 곱하면, `z^a · z^b = z^(a+b)` 라 합이 지수에서 더해져 $z^t$ 의 계수가 그대로 $W(m, t)$ 가 됩니다.

$$\sum_{t \ge 0} W(m,t)\, z^t \;=\; \bigl(1 + z + \dots + z^9\bigr)^m \;=\; \left(\frac{1 - z^{10}}{1 - z}\right)^{m} \;=\; (1-z^{10})^m \cdot (1-z)^{-m}$$

```text
가운데 등호는 등비수열의 합이다      1 + z + … + z^9 = (1 − z^10) / (1 − z)

두 인수가 각각 무엇을 뜻하는가
  (1 − z)^(−m)     자리 상한을 잊고 합 t 를 m 자리에 나누는 별과 막대
  (1 − z^10)^m     그중 어느 자리가 10 이상이 된 경우를 빼는 항
```

두 인수를 각각 펼칩니다. 앞은 항이 유한한 이항 전개이고, 뒤는 음의 지수 이항 전개예요.

$$(1-z^{10})^m = \sum_{j \ge 0} (-1)^j \binom{m}{j} z^{10j}, \qquad (1-z)^{-m} = \sum_{i \ge 0} \binom{i + m - 1}{m-1} z^{i}$$

```text
두 급수를 곱해 z^t 의 계수를 모은다

  앞에서 z^(10j) 를 고르고 뒤에서 z^i 를 고르면 지수가 10j + i 다
  그 합이 t 인 짝만 남으므로 i = t − 10j 를 넣는다
  j 는 10j ≤ t 인 동안만 있으므로 항이 ⌊t/10⌋ + 1 개다
```

계수를 모으면 닫힌 형태가 나옵니다. 항이 $\lfloor t/10 \rfloor + 1$ 개뿐이라 DP 테이블을 채우지 않고도 값이 나오고,
아래가 그 식을 그대로 옮긴 코드예요.

$$W(m, t) \;=\; \sum_{j = 0}^{\lfloor t/10 \rfloor} (-1)^j \binom{m}{j} \binom{t - 10j + m - 1}{m - 1}$$

```ts
// W(m, t) = Σ_j (−1)^j C(m, j) C(t − 10j + m − 1, m − 1)
const ways = (m: number, t: number): bigint => {
  if (t < 0) return 0n;
  let s = 0n;
  for (let j = 0; j * 10 <= t; j++) {
    const term = binom(m, j) * binom(t - 10 * j + m - 1, m - 1);
    s += j % 2 === 0 ? term : -term;
  }
  return s;
};
```

표로 센 값과 닫힌 형태를 나란히 놓았습니다. 오른쪽 열은 포함배제의 항이 몇 개인지예요.

<!--proof:math-check-->

| 식 | 표로 센 값 | 닫힌 형태 | 포함배제 항 수 |
| --- | ---: | ---: | ---: |
| W(1, 5) | 1 | 1 | 1 |
| W(2, 5) | 6 | 6 | 1 |
| W(2, 10) | 9 | 9 | 2 |
| W(2, 18) | 1 | 1 | 2 |
| W(3, 12) | 73 | 73 | 2 |
| W(4, 20) | 633 | 633 | 3 |
| W(15, 10) | 1,961,241 | 1,961,241 | 2 |
| W(15, 67) | 35,460,394,945,125 | 35,460,394,945,125 | 7 |
| W(15, 135) | 1 | 1 | 14 |

9 줄 가운데 9 줄에서 표로 센 값과 닫힌 형태가 같습니다.

<!--/proof-->

$t < 10$ 이면 항이 하나라 닫힌 형태가 별과 막대 그대로이고, $t$ 가 10 씩 커질 때마다 「자리 하나가 9 를 넘은 경우」를
빼는 항이 하나씩 붙어요. $W(15, 135)$ 가 1 인 것은 자리 열다섯이 전부 9 인 수열 하나뿐이라는 뜻입니다.

**둘째 유도는 답 전체를 `W` 의 합으로 적는 것입니다.** 「사전식 순서로 세기」가 `[0, N]` 을 「처음 작아지는 자리」로
갈랐고, 자리 `p` 에서 처음 작아지는 무리를 자리마다 적으면 이렇습니다.

| 자리 | 놓는 것 | 식에 들어가는 몫 |
| --- | --- | --- |
| 앞 `p` 자리 | `N` 과 같은 숫자 | 그 합이 $S_p$ 로 정해진다 |
| 자리 `p` | $x < d_p$ | 고를 $x$ 가 $d_p$ 가지다 |
| 뒤 $L-p-1$ 자리 | 아무 숫자 | 합 $K - S_p - x$ 를 $W$ 가 센다 |
| 끝까지 같다 | `N` 자신 | $S_L = K$ 일 때 하나를 더한다 |
| 전부 0 | 수 0 | $K = 0$ 일 때 하나를 뺀다 |

$$A(N, K) \;=\; \sum_{p=0}^{L-1} \; \sum_{x=0}^{d_p - 1} W\bigl(L - p - 1,\; K - S_p - x\bigr) \;+\; [\,S_L = K\,] \;-\; [\,K = 0\,]$$

위 식에 전개 입력을 넣어 검산합니다.

<!--proof:math-split-->

| 갈라지는 자리 | S_p | 자유 자리 m | 고르는 x | 각 항 | 무리의 합 |
| --- | ---: | ---: | --- | --- | ---: |
| p = 0 | 0 | 2 | 0 | W(2, 10) = 9 | 9 |
| p = 1 | 1 | 1 | 0 … 8 | W(1, 9) = 1 + … + W(1, 1) = 1 | 9 |
| p = 2 | 10 | 0 | 0 … 3 | W(0, 0) = 1 + … + W(0, -3) = 0 | 1 |

N 자신은 자릿수 합이 14 라 세어지지 않고, K = 10 이라 수 0 을 빼는 항은 0 입니다. 합 19 가 digitDp(194, 10) = 19 와 같습니다.

<!--/proof-->

첫 무리 9 가 T7 이 `memo[1][0]` 에 적은 값과 같고, 둘째 무리 9 가 T9 가 DP 테이블에서 읽은 값의 합, 셋째 무리 1 이
T10 이 센 190 입니다.

**마지막으로 계수입니다.** 과제의 위 끝 `N = 10^15` 를 넣으면 자리가 열여섯이고 맨 앞이 1 이라, 위 식이 한 줄로
줄어듭니다 — 맨 앞에서 작아지는 무리는 자유 자리가 열다섯이고, 뒤의 자리들은 $d_p = 0$ 이라 고를 $x$ 가 없어 무리가 비기
때문이에요.

```text
N = 10^15 의 자릿수는 1 0 0 … 0 (자리 열여섯)

  p = 0 무리    x < 1 이라 x = 0 하나 · 자유 자리 15    →  W(15, K)
  p ≥ 1 무리    d_p = 0 이라 고를 x 가 없다             →  0
  끝까지 같다   10^15 자신이고 자릿수 합이 1 이다        →  [K = 1]
        → A(10^15, K) = W(15, K) + [K = 1] − [K = 0]
```

<!--proof:math-scale-->

| 항목 | 값 |
| --- | ---: |
| W(15, t) 를 t = 0 … 135 에 걸쳐 더한 값 | 1,000,000,000,000,000 |
| 가장 큰 W(15, t) 의 t | 67 |
| W(15, 67) | 35,460,394,945,125 |
| digitDp(10^15, 67) | 35,460,394,945,125 |
| W(15, 1) + 1 | 16 |
| digitDp(10^15, 1) | 16 |
| digitDp(10^15, 135) | 1 |

파트 1 은 자리 셋에서 DP 테이블 열 칸을 채웠을 뿐이라, 임의의 자리 수에서 답이 어떤 모양인지를 값으로는 알 수
없었습니다. 닫힌 형태가 그것을 일반화해요 — `K = 1` 의 답이 $W(15,1) + 1$ 로 나오고, 가장 큰 답이 $W(15, t)$ 가 가장
큰 `t` 에서 나오며, `W(15, t)` 를 `t` 전체에 걸쳐 더하면 정확히 `10^15` 가 됩니다.

### 불변식 — memo[pos][sum] 은 풀린 상태로 그 자리에 왔을 때 남은 자리를 채우는 방법의 수다

파트 1 에서 코드가 동작하는 것을 열두 걸음으로 봤습니다. 그것은 세 자리짜리 입력 하나에서 맞았다는 뜻이지, 어떤
입력에서도 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 한 문장으로 세우고, 각 갈래가 그 문장을 지키는지
값으로 따져 봅니다.

> `memo[pos][sum]` 에 값이 **적혀 있는 시점**에, 그 값은 「자리 `pos` 앞의 숫자 합이 `sum` 인 **풀린 상태**에서, 남은
> `L − pos` 자리에 0 부터 9 까지를 자유롭게 채워 전체 합을 `K` 로 만드는 방법의 수」와 같습니다.

```text
적혀 있는 시점     값을 적기 전에는 아직 그 시점이 아니다 (-1 인 칸은 아무것도 주장하지 않는다)
풀린 상태          상한이 9 인 상태다. 붙은 상태의 답은 이 칸에 담기지 않는다
자유롭게 채워      digits 를 더 보지 않는다. 그래서 이 값이 N 과 무관해진다
전체 합을 K 로     이미 고른 sum 을 뺀 K − sum 을 남은 자리로 만든다는 뜻이다
```

「풀린 상태」라고 적은 것이 이 알고리즘에서는 **DP 테이블이 `N` 을 잊어도 되는 근거**입니다. 한 번이라도 `N` 의 자리보다
작은 숫자를 골랐으면 그 뒤로는 무엇을 놓아도 `N` 이하이므로, 남은 일이 `digits` 와 무관해져요.

**출발점부터 봅시다.** DP 테이블은 전부 `-1` 로 깔려 있어서 아무 칸도 불변식을 주장하지 않는 상태로 시작합니다. 그 뒤로
칸이 정해지는 자리는 DP 테이블에 적는 줄 `memo[pos][sum] = total` 하나뿐이고, 거기에 이르는 반복이 더하는 값은 아래 셋 중 하나예요.

| 더하는 값 | 그 값이 뜻하는 것 | 적는 순간 이미 옳은 까닭 |
| --- | --- | --- |
| 아래 자리의 `memo[pos+1][sum+x]` | 풀린 상태로 다음 자리에 왔을 때의 답 | 재귀가 그 값을 먼저 끝내고 돌아온다. 적힌 값이면 불변식이 이미 성립한다 |
| 기저 `pos === L` 이 돌려준 0 이나 1 | 자리를 다 정한 뒤의 판정 | `digits` 를 안 본다 |
| 가지치기 `sum + 9 × (L − pos) < K` 가 돌려준 0 | 남은 자리로 `K` 에 못 미친다 | 남은 자리가 `L − pos` 개라는 것만으로 판정된다 |

풀린 상태의 반복은 `x` 를 0 부터 9 까지(합이 `K` 를 넘어 끊기 전까지) 놓고, 놓은 뒤의 상태도 풀린 상태라 세 값 모두 `digits` 를
보지 않습니다. 그래서 적는 값이 불변식의 문장과 같아요. **적는 줄의 가드 `if (!tight)` 가 이 불변식과 맞물리는 자리입니다.**
붙은 상태의 반복은 상한이 `digits[pos]` 라 셈이 `N` 에 묶여 있는데, 그 값을 같은 칸에 적으면 칸의 뜻이 「자유롭게
채워」와 어긋나요. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

| 입력 | DP 테이블과 갈래 | 돌려주는 값 |
| --- | --- | ---: |
| N = 1 · K = 1 | 자리가 하나이고 붙은 상태만 들어간다. DP 테이블에 적은 칸 0 | 1 |
| N = 1 · K = 2 | 후보 0 · 1 을 다 놓아도 합 2 에 못 미친다. 적은 칸 0 | 0 |
| N = 100 · K = 0 | 마지막 줄이 첫 호출의 값에서 수 0 하나를 뺀다 | 0 |
| N = 99 · K = 20 | 0 + 9 × 2 < 20 이 참이라 첫 호출이 가지치기에 걸린다. 들어간 상태 1 | 0 |
| N = 999 · K = 27 | 9 가 아닌 숫자를 고르면 가지치기에 걸려 붙은 상태만 끝까지 간다. 적은 칸 0 | 1 |
| N = 10^15 · K = 135 | 맨 앞이 1 이라 뒤 15 자리가 전부 9 여야 한다. 적은 칸 15 | 1 |

**이제 깨뜨려 봅시다.** 불변식의 「풀린 상태」를 지키는 것은 다음 상태의 `tight` 를 자리마다 다시 정하는 한 조각입니다.
그 조각을 `tight` 를 그대로 물려주는 것으로 바꾸면, 한 번 참이던 `tight` 가 끝까지 참으로 남아 풀린 상태가 아예 생기지
않고 상한이 끝까지 `digits[pos]` 에 묶여요.

```ts
total += count(pos + 1, sum + x, tight);
//                                ~~~~~ 원래는 tight && x === (digits[pos] as number)
```

상한과 목표 합을 바꿔 가며 실행하면 이렇게 나옵니다.

<!--proof:invariant-mutant-->

| 호출 | 바른 코드 | tight 를 그대로 물려준 코드 |
| --- | ---: | ---: |
| digitDp(194, 10) | 19 | 9 |
| digitDp(990, 9) | 55 | 10 |
| digitDp(20, 2) | 3 | 1 |
| digitDp(100, 1) | 3 | 1 |
| digitDp(999, 27) | 1 | 1 |
| digitDp(9, 5) | 1 | 1 |
| digitDp(10^15, 50) | 10,614,794,989,443 | 0 |

호출 7 개 가운데 5 개에서 답이 작아졌습니다.

<!--/proof-->

`N = 194 · K = 10` 이 19 에서 9 로 가고, `N = 10^15 · K = 50` 은 0 이 돼요. 자리마다 `digits[pos]` 보다 작은 숫자를
고른 뒤의 자유가 통째로 사라지고, 남는 것은 모든 자리가 `N` 의 그 자리 숫자 이하인 수뿐입니다. `N = 999 · K = 27` 과
`N = 9 · K = 5` 는 답이 안 갈려요. `N` 의 자리가 전부 9 이면 상한이 `digits[pos]` 든 9 든 같은 값이라, 그런 입력만으로
확인하면 이 변형이 통과합니다.

### 비용 계산

#### 비용을 세는 과정

호출 하나가 하는 일을 넷으로 가르고, 넷을 더해 총식을 만듭니다.

| 일 | 횟수 |
| --- | --- |
| DP 테이블 만들기 | `L(K+1)` 칸을 `-1` 로 채운다. T1 이 그것이다 |
| 풀린 상태의 칸 정하기 | 많아야 `L(K+1)` 칸. 칸마다 숫자를 열 개까지 놓아 본다. T5 · T6 · T7 이 그 칸들이다 |
| 붙은 상태 지나가기 | 많아야 `L+1` 번. DP 테이블을 안 쓰고 매번 새로 센다. T2 · T8 · T10 · T11 · T12 가 그것이다 |
| DP 테이블에서 읽기 | 이미 정한 칸으로 다시 왔을 때 한 번. T9 의 아홉 번이 그것이다 |

칸 하나를 정할 때 하는 일은 숫자를 많아야 열 번 놓아 보는 것이고, 한 번마다 덧셈 하나 · 비교 하나 · 재귀 하나라
상수예요. 붙은 상태도 같은 모양이라 열 번을 넘지 않습니다. 그래서 **풀린 칸이 몇 개인지와 붙은 상태가 몇 개인지만
세면** 됩니다.

<!--proof:perf-count-->

| 항목 | 식 | L = 16 · K = 135 |
| --- | --- | ---: |
| 풀린 상태 = DP 테이블 칸 | L × (K+1) | 2,176 |
| 붙은 상태 | L + 1 이하 | 17 |
| 상태 합계 | L(K+1) + L + 1 이하 | 2,193 |
| 숫자를 놓아 보는 일 | 상태마다 10 번 이하 | 21,930 |
| 재귀의 깊이 | L + 1 | 17 |

```text
총식 = Θ(L(K+1))  +  O(10 · L(K+1))  +  O(10 · (L+1))  +  Θ(1)  =  Θ(L(K+1))
        ↑ DP 테이블    ↑ 풀린 칸 정하기     ↑ 붙은 상태 지나가기  ↑ 마지막 뺄셈
          만들기
```

`L` 은 `N` 의 자리 수라 `L = ⌊log₁₀ N⌋ + 1` 입니다. `N` 으로 다시 적으면 `Θ((K+1) log N)` 이에요 — **`N` 의 값이 아니라 그
로그에 붙습니다.** DP 테이블에 실제로 몇 칸을 적는지는 입력에 따라 갈리니 세어 봅시다.

<!--proof:perf-visit-->

| 입력 | 자리 수 L | DP 테이블 칸 L(K+1) | 실제로 적은 칸 | 들어간 상태 |
| --- | ---: | ---: | ---: | ---: |
| 194 · K = 10 | 3 | 33 | 10 | 78 |
| 999,999,999,999,999 · K = 50 | 15 | 765 | 479 | 4,436 |
| 999,999,999,999,999 · K = 135 | 15 | 2,040 | 0 | 151 |
| 10^15 · K = 50 | 16 | 816 | 485 | 4,448 |
| 123,456,789,012,345 · K = 50 | 15 | 765 | 434 | 4,034 |

자리가 15 이상이고 적은 칸이 있는 입력에서 적은 칸은 DP 테이블의 57% 에서 63% 입니다.

<!--/proof-->

**`999,999,999,999,999 · K = 135` 줄은 0 칸입니다.** 자리 열다섯이 전부 9 여야 하는 값이라, 어느 자리에서 9 보다 작은 숫자를 고르는
순간 갈래 ① 에 걸려 DP 테이블을 쓰기 전에 돌아와요. 다른 열다섯 자리 줄에서 적는 칸이 DP 테이블의 일부인 것은, 자리
`pos` 앞의 합이 `9 · pos` 를 못 넘어 위쪽 줄의 오른쪽 칸들이 안 쓰이기 때문입니다. 메모리는 DP 테이블의 칸 수와 같고,
재귀의 깊이는 `L + 1` 이에요 — 둘 다 앞의 셈 표에 값이 있습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`K` 가 `9L` 에 가깝다) | `O(L(K+1))` | `Θ(L(K+1))` |
| **평균적인 경우** (`N` · `K` 를 어떤 분포에서 뽑아도) | `O(L(K+1))` | `Θ(L(K+1))` |
| **최악의 경우** (어떤 입력이든) | `O(L(K+1))` | `Θ(L(K+1))` |

**세 줄이 같습니다.** DP 테이블을 만드는 일이 입력과 무관하게 `L(K+1)` 칸이기 때문이에요. 그 뒤에 상태를 몇 개
지나가는지는 입력에 따라 `Θ(L)` 에서 `Θ(L(K+1))` 까지 갈리는데, 그 폭이 총식의 앞 항 안쪽이라 차수를 못 바꿉니다.

```text
갈리는 것과 안 갈리는 것

  DP 테이블을 만드는 일   L(K+1) 칸             입력이 무엇이든 같다
  값을 정하는 상태         Θ(L) ~ Θ(L(K+1))      K 와 N 의 모양에 따라 갈린다
  총식                     Θ(L(K+1))             앞의 항이 언제나 남는다
```

**「평균」 줄이 분포에 대한 기댓값을 뜻하는 것이 아닙니다.** 이 과제에는 입력의 분포가 주어져 있지 않아요 — `N` 을
고정하고 `K` 를 고르는지, `K` 를 고정하고 `N` 을 고르는지에 따라 「평균」이 다른 말이 됩니다. 위 표의 그 줄이 뜻하는
것은 **어느 분포에서 뽑아도 같은 차수**라는 것이고, 그것이 성립하는 이유가 곧 DP 테이블 만들기가 입력과 무관하다는
사실입니다. **보장의 종류는 최악 보장입니다.** 기댓값이 아니에요 — 코드에 무작위성이 없고 입력의 분포를 가정하는 자리도 없습니다.
같은 `(N, K)` 면 몇 번을 실행해도 들어간 상태 수와 적은 칸 수가 같아요.

총식의 `L` 은 `N` 의 **값**이 아니라 **자리 수**입니다. 「최적인 문제의 모양」에서 본 것처럼 `N` 이 `10^85` 배가 되어도
`L` 은 85 만 늘어요. 그래서 이 알고리즘은 **의사다항이 아닙니다.** 비용이 입력에 적힌 값의 크기가 아니라 그 값을 적는 데
쓴 자리 수에 붙으니, 같은 2 차원 DP 테이블을 쓰면서도 [0/1 배낭](../knapsack01/knapsack01-guide.md) 이나
[부분집합 합 판정](../subsetSum/subsetSum-guide.md) 과 갈리는 자리가 여기예요. `K` 쪽은 값에 붙지만 그 위 끝이 135 로
정해져 있습니다.

#### 최악을 만드는 입력

「어떤 입력이 최악인가」는 두 축에서 답이 다릅니다. DP 테이블의 크기는 `K` 와 자리 수만으로 정해지고, 실제로 들어가는
상태 수는 `N` 의 모양과 `K` 가 함께 정해요. 열다섯 · 열여섯 자리 상한 여럿을 실제로 실행해 세어 봅시다.

<!--proof:worst-input-->

| 입력 | 답 | 적은 칸 | 들어간 상태 | DP 테이블 칸 L(K+1) |
| --- | ---: | ---: | ---: | ---: |
| 9 가 15 개 · K = 67 | 35,460,394,945,125 | 511 | 4,861 | 1,020 |
| 9 가 15 개 · K = 135 | 1 | 0 | 151 | 2,040 |
| 9 가 15 개 · K = 1 | 15 | 28 | 45 | 30 |
| 10^15 · K = 67 | 35,460,394,945,125 | 519 | 4,871 | 1,088 |
| 10^15 · K = 50 | 10,614,794,989,443 | 485 | 4,448 | 816 |
| 123456789012345 · K = 67 | 4,138,534,544,771 | 451 | 4,295 | 1,020 |
| 555555555555555 · K = 67 | 19,997,000,871,390 | 483 | 4,597 | 1,020 |

들어간 상태가 가장 많은 입력은 10^15 · K = 67 의 4,871 번입니다.

<!--/proof-->

**`K = 67` 줄들이 상태를 가장 많이 지나갑니다.** 자유 자리 열다섯의 합이 67 근처일 때 만들 수 있는 조합이 가장 많고,
그것이 곧 `W(15, t)` 가 가장 큰 자리예요 — 「수식 정의와 유도」가 낸 가장 큰 `W(15, t)` 의 `t` 가 여기서 상태 수가 가장
많은 자리와 같습니다.

```text
시간 최악 = 자리가 열여섯이고 K 가 67 근처일 때
  K 가 0 이나 135 에 가까우면 대부분이 갈래 ① 에 걸려 상태가 백 개 안팎으로 내려간다
  N 의 모양은 붙은 상태의 사슬만 바꾸므로 폭이 크지 않다

메모리 최악 = K 가 135 이고 자리가 열여섯일 때
  DP 테이블이 16 × 136 칸이다. 실제로 적히는 칸 수와는 다른 축이다
```

**답의 크기가 최악을 만드는 자리는 이 과제에 없습니다.** 답이 많아야 `N` 이하의 수의 개수라 `10^15` 를 안 넘고,
배정밀도 정수가 정확히 세는 범위(`2^53 ≈ 9.0 × 10^15`) 안쪽이에요. 값이 커져서 덧셈이 뜻을 잃는 자리는 이 규모에서는
생기지 않습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 수를 하나씩 세는 대신 **왼쪽 자리부터 숫자를 정해 만들었고**, 상한을
넘지 않게 하는 데 필요한 것이 「아직 `N` 의 앞부분에 붙어 있는가」 참 · 거짓 하나뿐이라는 것을 확인했으며, 그 결과
`10^15` 번의 검사가 DP 테이블 `L × (K+1)` 칸을 정하는 일로 내려왔습니다.

```text
N 을 자리로 가른다 → 붙음으로 상한을 정한다 → 풀린 상태의 칸만 DP 테이블에 적는다 → K = 0 이면 1 을 뺀다
        └ 자리 L 개          └ digits[pos] 또는 9        └ 붙은 상태는 다시 안 읽힌다
```

먼저 답이 붙는 문제 하나입니다. `N = 999` 이면 자리가 셋이고 모든 자리의 상한이 9 라 붙은 상태가 아무것도 제한하지
않아요. 그러면 `digitDp(999, K)` 와, 자유 자리 셋을 합 `K` 로 채우는 방법의 수 `W(3, K)` 사이에 어떤 관계가
성립할까요?

```text
T2 에서 상한이 digits[0] = 1 이라 고를 숫자가 둘이었다
N = 999 라면 그 자리의 상한이 9 라 열 개를 다 고를 수 있다
      → 붙은 상태든 풀린 상태든 고를 수 있는 숫자가 같다 = ?
```

<!--check:zeroGap-->

**`K = 0` 을 빼면 둘이 같습니다.** 모든 자리의 상한이 9 이면 붙은 상태가 상한을 좁히는 일이 한 번도 없으므로, 이
절차가 세는 것이 「자유 자리 셋을 합 `K` 로 채우는 방법의 수」와 같아져요. `K = 0` 에서만 차이가 나는 것은 갈래 ⑥ 이
수 `0` 을 빼기 때문입니다. `K = 28` 처럼 자리 셋의 합으로 만들 수 없는 값이면 둘 다 0 이고, 코드에서는 첫 호출이
갈래 ① 에 걸립니다.

「경쟁 설계와의 대조」와 「수식 정의와 유도」를 다시 보세요.

- T9 는 DP 테이블을 아홉 번 읽었고 T10 은 DP 테이블을 읽지도 쓰지도 않았습니다. `N` 을 194 에서 984 로 바꾸면 그 두
  걸음이 각각 몇 번이 될지, 그리고 DP 테이블에 적히는 칸이 몇 개가 될지 예측해 보세요.
- 「자릿수 합이 `K`」 대신 「숫자 7 이 한 번도 안 나온다」를 세려면 상태 셋 중 무엇이 없어지고 무엇이 남을까요. 그때
  불변식의 어느 낱말이 달라지는지도 적어 보세요.
- 닫힌 형태는 `K` 가 커질수록 항이 늘고 자릿수 DP 는 `K = 67` 을 넘으면 상태가 줄었습니다. 그러면 `N` 의 자리 수를
  열다섯에서 늘려 가면 두 곡선이 만나는 `K` 는 어느 쪽으로 움직일지, 그 이유를 각 설계의 비용식으로 적어 보세요.

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### 자릿수 합이 K인 수의 개수

풀 파일: [`digitDp.ts`](./digitDp.ts) · 테스트: [`digitDp.test.ts`](./digitDp.test.ts) · 실행: `bun test src/algorithms/dp/digitDp/digitDp.test.ts`

#### 한 줄 요약

> 함수는 상한 N과 목표 합 K를 받아, 1 이상 N 이하의 정수 중 십진 자릿수의 합이 정확히 K인 수의 개수를 반환한다.

#### 스토리

품질 관리 팀의 태호는 생산 일련번호 중 특별한 성질을 갖는 것만 골라내는 검사 도구를 만들고 있다. 일련번호는 1부터 시작하며, 공장 규정에 따라 각 자릿수를 모두 더한 값이 특정 숫자와 일치하는 제품에는 별도 마킹이 필요하다.

현재 배치의 마지막 일련번호 N이 정해지면, 1부터 N까지 번호 중 자릿수 합이 정확히 K인 것이 몇 개인지 빠르게 알아야 한다. 태호의 공장에서는 N이 10의 15제곱까지 커질 수 있어서, 일일이 세는 방식으로는 시간이 부족하다.

#### 함수 인터페이스

```ts
export function digitDp(N: number, K: number): number;
```

- `N` — 범위의 상한 ($1$ 이상 $10^{15}$ 이하의 양의 정수)
- `K` — 목표 자릿수 합 ($0$ 이상 $135$ 이하)
- 반환 — $1$ 이상 $N$ 이하의 정수 중 십진 자릿수 합이 정확히 $K$인 수의 개수

#### 제약 조건

- $1 \leq N \leq 10^{15}$
- $0 \leq K \leq 135$ ($15$자리 수의 자릿수 합 최대값은 $15 \times 9 = 135$)
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

자릿수 합이란 수를 십진법으로 표기했을 때 각 자리의 숫자를 모두 더한 값이다. 예컨대 $123$의 자릿수 합은 $1 + 2 + 3 = 6$이다.

$K = 0$인 경우, $1$ 이상의 정수 중 자릿수 합이 $0$인 수는 없으므로 $0$을 반환한다.

$K$가 $N$의 자릿수 개수 $\times 9$보다 크면 가능한 수가 없으므로 $0$을 반환한다.

#### 예시

```ts
digitDp(9, 5);
// 1 — 1~9 중 자릿수 합이 5인 수: 5

digitDp(100, 1);
// 3 — 1~100 중 자릿수 합이 1인 수: 1, 10, 100

digitDp(20, 2);
// 3 — 1~20 중 자릿수 합이 2인 수: 2, 11, 20

digitDp(99, 18);
// 1 — 두 자리 수 중 자릿수 합이 18인 수: 99

digitDp(100, 0);
// 0 — 1 이상에서 자릿수 합이 0인 수는 없음
```
