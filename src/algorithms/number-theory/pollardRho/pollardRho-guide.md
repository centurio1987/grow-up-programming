# 폴라드 로 — 소인수 p 의 이름을 모르는 채로도 법 p 에서 먼저 겹치는 자리를 최대공약수 하나가 잡아낸다

## 파트 1 — 아이디어에서 동작하는 코드까지

약수를 하나씩 시험하는 방법이 어느 규모에서 감당이 안 되는지를 값으로 확인하고, 약수를
찾아 나서는 대신 **수열 하나를 두 법으로 읽는** 방법을 세우는 데까지 갑니다. 마지막에는
실제로 동작하는 코드를 조각으로 나눠 만듭니다.

### 전체 컨셉

정수 `n` 하나를 받아 **비자명한 약수** 하나를 돌려주는 함수입니다. 비자명한 약수란 1 도 `n`
자신도 아닌 약수를 말해요. `n` 이 짝수이면 2 를 돌려주고, `n` 이 소수이면 그런 약수가 아예
없으므로 `n` 자신을 돌려줍니다.

```text
pollardRho(8051n) 이 내는 것

  8,051 = 83 × 97          1 과 8,051 말고도 약수가 있다
  ────────────────
  돌려주는 값은 97          8,051 을 97 로 나눈 나머지가 0 이고 97 은 1 도 8,051 도 아니다
```

약수를 직접 찾는 방법으로는 큰 `n` 을 감당할 수 없습니다. 가장 작은 소인수는 `√n` 이하에
있으므로 3 부터 `√n` 까지 홀수만 나눠 봐도 반드시 찾지만, `n` 이 `10^18` 이면 그 나눗셈이
5 억 번입니다.

| 방법 | `n = 10^18` 근방에서 몇 번 | 한 번이 무슨 연산인가 |
| --- | --- | --- |
| 2 부터 `n − 1` 까지 나눈다 | 약 100경 번 | `n % d` |
| 3 부터 `√n` 까지 홀수로 나눈다 | 약 5 억 번 | `n % d` |
| 이 글의 절차 | 한 입력에서 실측 79 만 8,912 번 | `n` 을 법으로 하는 곱셈이나 나눗셈 |

**약수를 찾아 나서는 대신 소인수가 있다는 사실만 쓰는 것**이 이 절차의 출발입니다. 정수
하나를 제곱해 상수를 더하고 `n` 으로 나눈 나머지를 취하는 것을 되풀이하면 수열 하나가
나오는데, 그 수열을 **`n` 이 아니라 소인수 `p` 로 나눈 나머지**로 읽으면 값이 놓일 자리가
훨씬 적습니다.

<!--proof:concept-two-mods-->

```text
걸음      x0  x1  x2   x3     x4     x5   x6
법 8,051   2   5  26  677  7,474  2,839  871
법 97      2   5  26   95      5     26   95
법 83      2   5  26   13      4     17   41

└ 둘째 줄은 값이 놓일 자리가 8,051 개이고 셋째 줄은 97 개다.
  셋째 줄에서 x4 가 앞에 나온 값과 같아지고, 같은 자리에서 둘째 줄의 값은 아직
  앞의 어느 값과도 같지 않다. 넷째 줄(법 83)도 아직 겹치지 않았다
```

값이 놓일 자리가 유한하므로 두 수열 다 언젠가는 앞에 나온 값을 다시 만납니다. 자리가 적은
쪽이 먼저 만나고, 그때 두 값 `x` 와 `y` 는 `x ≡ y (mod p)` 이면서 `x ≢ y (mod n)` 일 수
있어요. 그러면 `x − y` 는 `p` 의 배수인데 `n` 의 배수는 아니고, 그것이 `gcd(|x − y|, n)` 을
1 도 `n` 도 아닌 값으로 만듭니다.

```text
그 자리를 잡는 한 줄

  x = 677,  y = 871       법 97 에서 둘 다 95 다
  |x − y| = 194 = 2 × 97  97 의 배수이고 8,051 의 배수는 아니다
  ────────────────
  gcd(194, 8051) = 97     p 의 이름을 한 번도 쓰지 않고 p 를 얻었다
```

**절차가 `p` 를 아는 것이 아니라는 점이 핵심입니다.** 코드는 법 `n` 위에서만 계산하고, 법
`p` 위의 겹침은 최대공약수가 대신 알아냅니다. 겹치는 자리를 찾는 방법은 두 자리를 서로 다른
속도로 나아가게 하는 것이고, 상수를 바꾸면 수열 전체가 바뀌므로 실패하면 상수를 올려 다시
시작합니다.

```text
절차의 뼈대

  짝수이면 2                          나눗셈 한 번으로 끝난다
  소수이면 n 자신                     비자명한 약수가 없다
  아니면 수열 하나를 만들어           상수 c 가 수열 하나를 정한다
    두 자리를 다른 속도로 나아가게 하고
    차와 n 의 최대공약수를 매 걸음 본다
  1 도 n 도 아닌 값이 나오면 그것이 답
  n 이 나오면 c 를 올려 다시
```

걸음 수는 소인수 `p` 가 정합니다 — 자리가 `p` 개인 수열이 처음 겹치기까지 `√p` 규모의
걸음이 걸리고, 가장 작은 소인수는 `√n` 이하이므로 `n^(1/4)` 규모가 돼요. **이 값은 최악을
막아 주는 보장이 아니라 기대되는 크기입니다** — 어떤 입력에서 몇 걸음이 걸리는지는 그 입력의
수열이 언제 겹치는가에 달려 있고, 상한을 닫아 주는 정리는 없습니다. 그 구분과 계수는 파트 2
가 다룹니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **나머지 연산과 합동.** `a ≡ b (mod m)` 이 `a` 와 `b` 를 `m` 으로 나눈 나머지가 같다는
  뜻이고, 코드로는 `a % m === b % m` 이라는 것. 이 글의 계산은 전부 이 위에서 이뤄집니다.
- **최대공약수와 유클리드 호제법.** `gcd(a, b)` 를 나머지 연산의 반복으로 구하는 방법과
  `gcd(0, m) = m` 이라는 규약. [최대공약수 가이드](../gcd/gcd-guide.md)가 그 절차를 다루고,
  이 글은 그것을 부품으로 그대로 씁니다.
- **소수와 합성수, 그리고 소수 판정.** 2 이상이면서 1 과 자기 자신 말고는 약수가 없는 수가
  소수라는 것. 큰 수를 빠르게 판정하는 절차는
  [소수 판정 가이드](../millerRabin/millerRabin-guide.md)에 있고, 정의를 그대로 옮긴 판은
  [시행 나눗셈 소수 판정 가이드](../isPrimeTrial/isPrimeTrial-guide.md)에 있어요.
- **모듈러 거듭제곱.** `a^e mod m` 을 지수를 반씩 접어 구하는 방법.
  [빠른 거듭제곱 가이드](../fastPower/fastPower-guide.md)가 다룹니다. 소수 판정 안에서만
  쓰입니다.
- **`bigint` 와 정수 정밀도.** JavaScript 의 `number` 는 배정밀도 실수라 정수를 오차 없이
  담는 범위가 `2^53 − 1` 까지이고, 그보다 큰 정수는 `bigint` 로 다뤄야 한다는 것.

```text
이 글이 답하는 것과 답하지 않는 것

  n 의 비자명한 약수 하나                이 글이 답한다
  n 이 소수인가                          반환값이 n 자신인 것으로 알 수 있고, 판정 자체는 부품이다
  n 의 소인수 전부를 나열하라            답하지 않는다 — 이 절차를 재귀로 다시 적용할 일이다
             └ 돌려주는 값이 소수라는 보장도 없다
```

### 아이디어 상세 — 법 p 충돌을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function pollardRho(n: bigint): bigint;
```

- 입력: 정수 하나. `n ≥ 2` 입니다.
- 출력: `n` 의 약수 `d` 하나. `1 < d ≤ n` 이고, `n` 이 합성수이면 `1 < d < n` 입니다.
- 계약의 경계: `n` 이 짝수이면 2 이고 `n` 이 소수이면 `n` 자신입니다. 비자명한 약수가 여럿일
  때 어느 것을 돌려줘도 됩니다.
- 제약: 시간 1 초, 메모리 256 MB. 원본 시험 파일의 가장 큰 입력이
  `1,000,000,007 × 1,000,000,009 = 1,000,000,016,000,000,063` 이라 이 글은 규모를
  `2 ≤ n < 2^64` 로 잡고 셉니다.

이 글이 쓰는 기호는 여덟이에요. 입력과 상태 변수를 먼저 두고, 걸음 수를 셀 때만 쓰는 기호를
뒤에 둡니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 약수를 찾을 정수 | 입력. `2 ≤ n < 2^64` |
| `p` | `n` 의 소인수 하나 | 절차가 이름을 모르는 채로 쓰는 값 |
| `c` | 수열 하나를 정하는 상수 | 1 에서 시작하고 실패하면 1 씩 올린다 |
| `f` | 다음 값을 만드는 함수 | `f(t) = (t² + c) mod n` |
| `x` | 느린 자리 | 한 걸음에 `f` 를 한 번 거친다 |
| `y` | 빠른 자리 | 한 걸음에 `f` 를 두 번 거친다 |
| `d` | 그 걸음의 최대공약수 | `gcd(\|x − y\|, n)` |
| `k` | 한 라운드 안의 걸음 수 | 두 자리를 몇 번 나아가게 했는가. 라운드를 합친 값은 `Σk` 로 적는다 |

```text
기호가 어디에 사는가

  n          함수 인자        한 번 받으면 끝까지 안 바뀐다
  p          이름이 없는 값   코드 어디에도 나오지 않는다. 논증에만 나온다
  c          라운드마다 하나  실패하면 1 씩 올라가고 그때 f 가 통째로 바뀐다
  f          c 와 n 이 정한다 라운드 안에서는 고정이다
  x·y        걸음마다의 상태  라운드가 바뀌면 둘 다 시작값으로 되돌아간다
  d          걸음마다 새로    앞 걸음의 d 를 이어받지 않는다
  k          한 라운드의 걸음 수  비용의 재료다. 라운드를 합치면 Σk 다
```

가장 먼저 떠오르는 방법으로 시작합시다. **약수의 정의를 그대로 옮겨 3 부터 `√n` 까지 홀수로
나눠 보는 것**이에요. 나누어떨어지는 수를 처음 만나면 그것이 답이고, 끝까지 못 만나면 `n` 은
소수입니다.

```ts
// 정의를 그대로 옮긴 판. 답은 맞지만 나눗셈 횟수가 √n 을 따라간다.
if (n % 2n === 0n) return 2n;
for (let d = 3n; d * d <= n; d += 2n) {
  if (n % d === 0n) return d;
}
return n;
```

```text
10^6 근방                   2,021,027                  711           941

10^18 근방  1,000,001,018,000,007,077          500,000,254       798,912

└ 셋째 칸은 실행하지 않고 √n 을 구해 센 값이고, 넷째 칸은 정본을 실행해 센
  기본 연산이다. 두 칸의 단위는 같다 — n 크기의 두 수를 곱하거나 나눈 횟수다.
  셋째 칸은 줄마다 커지는데 넷째 칸은 그렇지 않다 — 걸음 수가 수열이 언제 겹치는가에
  달려 있어서 같은 자릿수 안에서도 값이 갈린다
```

**제약 규모 근방에서 5 억 번입니다.** 1 초 안에 끝내야 하는데 나눗셈 하나에 1 나노초를 쓴다고
해도 0.5 초이고, `bigint` 나눗셈은 그보다 훨씬 느려요. 넷째 칸이 목표인데, 그 칸은 나눗셈을
줄여서 나온 값이 아니라 **약수를 찾아 나서는 일 자체를 그만둔** 결과입니다.

```text
두 방향

  약수를 더 적게 시험한다   후보를 √n 까지, 다시 6m±1 로 줄인다.  10^18 에서 약 3 억 3 천만 번
  약수를 시험하지 않는다    소인수가 있다는 사실만 쓴다.          걸음 수가 √p 규모가 된다
                            └ 뒤쪽이 이 글의 방향이다
```

**소인수가 있다는 사실만 쓰려면 `p` 를 법으로 하는 계산이 필요해 보입니다.** 그런데 `p` 를
모르는 채로도 그 계산이 이미 일어나고 있어요. `x` 를 제곱해 상수를 더하고 `n` 으로 나눈
나머지를 취하면, 그 값을 다시 `p` 로 나눈 나머지는 **`p` 를 법으로 같은 계산을 한 결과와
같습니다** — `p` 가 `n` 을 나누기 때문입니다.

```text
왜 같은가 — n = 8,051, p = 97, c = 1 에서

  x = 26 에서 다음 값을 법 8,051 로            26² + 1 = 677,  677 mod 8051 = 677
  그 결과를 법 97 로                           677 mod 97 = 95
  ────────────────
  26 을 먼저 법 97 로 줄이고 계산하면          26 mod 97 = 26,  26² + 1 = 677,  677 mod 97 = 95
  두 길의 값이 95 로 같다.  97 이 8,051 을 나누므로 어느 순서로 줄여도 결과가 같다
```

작은 입력 하나를 잡고 실제로 걸어 봅시다. `n = 8,051 = 83 × 97` 이고 상수는 `c = 1`,
시작값은 `x = y = 2` 입니다. 느린 자리는 한 걸음에 `f` 를 한 번, 빠른 자리는 두 번 거칩니다.

```text
걸음    x      y  x mod 97  y mod 97  x mod 83  y mod 83  |x − y|  gcd(|x − y|, 8051)
   1    5     26         5        26         5        26       21                   1
   2   26  7,474        26         5        26         4    7,448                   1
   3  677    871        95        95        13        41      194                  97

└ 넷째 칸과 다섯째 칸이 3 걸음에서 처음 같아지고, 그때 두 칸의 값은 95 이다.
  같은 걸음에서 여섯째 칸과 일곱째 칸은 다르고 둘째 칸과 셋째 칸도 다르다 —
  법 97 에서만 겹쳤다. 마지막 칸이 그 자리에서 97 을 낸다
```

**세 번째 걸음에서 법 97 의 두 칸이 95 로 같아집니다.** 같은 걸음에서 법 8,051 의 값은
677 과 871 로 다르고 법 83 의 값도 13 과 41 로 다르니, 겹침이 일어난 곳은 법 97 하나예요.
그 자리에서 `|x − y| = 194` 가 97 의 배수이고 8,051 의 배수는 아니라 최대공약수가 97 이
됩니다.

```text
코드가 계산하는 층과 논증이 보는 층

  코드가 계산한다   법 8,051 위의 x 와 y      그 차와 8,051 의 최대공약수 하나
  논증이 본다       법 97 위의 x 와 y         둘이 같아지는 자리
  ────────────────
  아래 줄은 코드에 한 번도 나오지 않는다. 97 이라는 값은 gcd 가 낸 뒤에야 알려진다
```

**여기가 이 글의 관찰입니다.** 겹침은 자리가 적은 법에서 먼저 일어나고, 코드는 그것을 보지
않고도 최대공약수 한 번으로 알아냅니다. 그러면 「법이 작을수록 먼저 겹친다」가 실제로 값에서
그렇게 나오는지 확인해 둡시다 — 같은 수열을 여러 법으로 따로 읽어 첫 겹침 걸음을 셉니다.

```text
         8,051             97                3               15           9          89
       111,403            101                9               36          10         333
     2,021,027          1,009               49              735          31       1,421
   110,107,021         10,007               40              270         100      10,493
10,101,203,027        100,003              518            1,480         316     100,504

└ 같은 수열 하나를 두 법으로 따로 읽은 결과다. 첫 줄이 전개 입력이고 나머지 넷은
  두 소인수가 같은 자릿수인 입력이다. 셋째 칸이 넷째 칸보다 줄마다 작다.
  셋째 칸은 다섯째 칸과 같은 자릿수인데 넷째 칸은 여섯째 칸보다 작은 줄이 있다
```

**셋째 칸이 넷째 칸보다 줄마다 작습니다.** 전개 입력에서는 3 대 15 이고, 두 소인수가 `10^5`
근방인 입력에서는 518 대 1,480 이에요. 셋째 칸은 다섯째 칸(`√p`)과 같은 자릿수에 머무는데,
넷째 칸은 여섯째 칸(`√n`)보다 오히려 작습니다 — 270 대 10,493 이 그 줄이에요. 기다리는 쪽이
`√n` 규모라는 것은 **자리가 `n` 개인 수열의 기대치**이고, 실제 값은 그 아래로도 갑니다.
그래도 셋째 칸이 넷째 칸보다 작다는 순서는 다섯 줄 내내 지켜집니다.

```text
두 칸의 차이가 곧 이 절차의 값이다

  법 n 의 겹침을 기다린다     자리가 n 개라 기대치가 √n 규모다
  법 p 의 겹침을 기다린다     자리가 p 개라 기대치가 √p 규모다
  ────────────────
  가장 작은 소인수는 √n 이하이므로 √p 는 n^(1/4) 이하다.
  넷째 칸이 √n 보다 작은 것은 법 n 의 수열이 법 p 와 나머지 소인수 q 의 수열을 겹쳐 만든
  것이기 때문이고(n = p × q), 그 규칙은 아래에서 값으로 확인한다 —
  기대치는 상한이 아니라 눈금이다
```

**그 「무엇」 을 개념으로 정의합시다 — 법 `p` 충돌입니다.** 걸음 `k` 에서 `x` 와 `y` 가
`x ≡ y (mod p)` 이면서 `x ≢ y (mod n)` 인 상태를 법 `p` 충돌이라 부릅니다. 이 상태에 이르면
`p` 가 `|x − y|` 를 나누고 `n` 도 나누므로 `gcd(|x − y|, n)` 이 `p` 의 배수이면서 `n` 은
아닌 값이 돼요.

- **두 자리를 어떻게 나아가게 하는가**가 이 개념을 쓸 수 있게 만드는 장치입니다. 한 걸음에
  `x` 는 `f` 를 한 번, `y` 는 두 번 거치므로 한 라운드 안에서 `k` 걸음 뒤 `x` 는 `k` 번째
  값이고 `y` 는 `2k` 번째 값이에요. 법 `p` 위의 수열이 꼬리 `μ` 개와 순환 마디 `λ` 개로 이뤄져 있으면
  `k` 가 `λ` 의 배수이면서 `μ` 이상이 되는 첫 자리에서 두 값이 같아집니다.
- **그래서 `k` 의 이동 범위는 `μ` 이상 `μ + λ` 이하**입니다. 두 값이 같아지는 첫 자리를
  넘길 수 없어요 — `k` 가 1 씩 늘고 `λ` 의 배수는 `λ` 칸마다 오기 때문입니다.
- **`c` 는 수열 전체를 정합니다.** 한 상수로 법 `p` 충돌 없이 법 `n` 충돌에 먼저 이르면
  최대공약수가 `n` 이 되고, 그때는 그 상수로 더 얻을 것이 없어 상수를 올려 다시 시작합니다.

```text
법 p 위에서 수열이 놓이는 모양 — 꼬리 μ 와 순환 마디 λ

  x0 → x1 → x2 → x3 → x4 → x5
                  ↑            ↓
                  x8 ← x7 ← x6
  ────────────────
  꼬리 μ = 3 개, 순환 마디 λ = 6 개.
  느린 자리가 k 번째, 빠른 자리가 2k 번째이므로 2k − k 의 차인 k 가 λ 의 배수일 때 겹친다
```

**법 `n` 위의 `μ` 와 `λ` 는 법 `p` 와 법 `q` 의 것에서 나옵니다.** `n = p × q` 이면 법 `n`
의 값 하나가 법 `p` 의 값과 법 `q` 의 값 한 쌍으로 정해지기 때문이에요. 네 입력에서 재
봅시다.

<!--proof:cycle-lcm-->

```text
  n = p × q  λp  λq  λp 와 λq 의 최소공배수   λn  μp 와 μq 중 큰 쪽  μn
      8,051   3   5                      15   15                  4   4
    111,403   9   2                      18   18                 31  31
  2,021,027  49  15                     735  735                 38  38
110,107,021   5  54                     270  270                 93  93

└ 넷째 칸과 다섯째 칸이 네 줄 내내 같고, 여섯째 칸과 일곱째 칸도 네 줄 내내 같다.
  법 n 의 값 하나가 법 p 의 값과 법 q 의 값 한 쌍으로 정해지므로 마디는 두 마디의
  최소공배수이고 꼬리는 두 꼬리 중 긴 쪽이다 — 최소공배수가 곱보다 작으면 법 n 의
  첫 겹침도 √n 보다 앞선다
```

**넷째 칸과 다섯째 칸이 줄마다 같습니다.** `λn` 이 `λp` 와 `λq` 의 최소공배수이고 `μn` 은
둘 중 긴 쪽이에요. 최소공배수가 두 마디의 곱보다 작으면 법 `n` 의 첫 겹침도 `√n` 보다
앞서고, 앞의 표 넷째 칸이 여섯째 칸보다 작았던 것이 그 자리입니다. 마디를 정하는 규칙까지
값으로 봤으니 **속도 비를 정말 1 대 2 로 둬야 하는지도 시험해 봅시다** — 비가 1 대 1 이면
두 자리가 언제나 같은 값이라 차가 0 이 되고 `gcd(0, n) = n` 이라 그 라운드는 아무것도 못
내며, 비를 3 이나 4 로 올리면 걸음 수는 줄 수 있지만 걸음마다 `f` 를 더 많이 부릅니다.

<!--proof:speed-ratio-->

```text
속도 비  약수를 못 낸 입력  걸음 합  f 호출 합
1 대 1                   5        5         10
1 대 2                   0      537      1,611
1 대 3                   0      515      2,060
1 대 4                   0      530      2,650

└ 입력 다섯은 8,051 · 10,403 과 두 소인수가 각각 10^3 · 10^4 · 10^5
  근방인 반소수 셋이고, 상수는 다섯 줄 모두 c = 1 이다. 첫 줄은 두 자리가 언제나 같은
  값이라 차가 0 이고 gcd(0, n) = n 이므로 다섯 입력 모두 약수를 못 낸다. 나머지 셋 중
  마지막 칸이 가장 작은 것이 1 대 2 다
```

**걸음 합이 가장 작은 것은 1 대 3 인데 `f` 호출 합이 가장 작은 것은 1 대 2 입니다.**
1 대 3 은 걸음이 515 로 1 대 2 의 537 보다 적지만, 걸음마다 `f` 를 네 번 부르므로 호출
합이 2,060 으로 1,611 보다 큽니다. 비용을 정하는 것은 걸음 수가 아니라 `f` 호출 수예요.

```text
걸음 하나의 값이 비에 따라 달라진다

  1 대 2      f 호출 3 번    x 한 번 + y 두 번
  1 대 3      f 호출 4 번    x 한 번 + y 세 번
  1 대 4      f 호출 5 번    x 한 번 + y 네 번
  ────────────────
  걸음 수가 조금 줄어도 걸음 하나가 그만큼 커지면 총 호출은 늘어난다
```

마지막으로 **첫 충돌 걸음이 정말 `√p` 규모인지**를 여러 `p` 에서 확인합니다. 법을 소수 하나로
두고 같은 함수를 실행해 두 자리가 처음 같아지는 걸음을 세면 됩니다.

<!--proof:birthday-sweep-->

```text
    소수 p  √p 를 내림한 값  첫 충돌 걸음 k  k / √p
       101               10               9    0.90
     1,009               31              49    1.58
    10,007              100              40    0.40
   100,003              316             518    1.64
 1,000,003            1,000           1,276    1.28
10,000,019            3,162           6,420    2.03

└ f(t) = (t² + 1) mod p 를 p 마다 따로 실행해 잰 값이다. 첫 칸이
  101 에서 10,000,019 로 약 10 만 배 커지는 동안 셋째 칸은
  9 에서 6,420 으로 커지고 마지막 칸은 0.90 과 2.03 사이에 머문다.
  표본이 여섯이라 이 여섯에서 그렇다는 것이고 모든 p 에 대한 주장이 아니다
```

**마지막 칸이 0.90 과 2.03 사이에 있습니다.** `p` 가 10 만 배 커지는 동안 첫 충돌 걸음은
9 에서 6,420 으로 커졌고, 그 값을 `√p` 로 나눈 몫은 한 자릿수 안에 머물러요. 여섯 개의
표본이 그렇다는 것이고 모든 `p` 에 대한 주장은 아닙니다 — 그 주장이 어디까지 가능한지는
파트 2 에서 식으로 따집니다.

### 수행으로 알아보는 알고리즘 — 8,051 에서 97 을 찾아낸다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지
가되, 조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const n = 8051n;
// 이 절을 지나면 답이 97n 으로 정해진다
```

이 입력을 왜 골랐을까요? `8,051 = 83 × 97` 이라 두 소인수가 밑 목록 열둘보다 커서 소수
판정을 통과해 내려가고, **첫 상수 `c = 1` 로 세 걸음 만에 답이 나와** 손으로 따라갈 수
있습니다. 그리고 겹침이 큰 소인수 97 에서만 일어나 「법 `p` 충돌」이 값으로 나타나요.

```text
pollardRho(n):
    n 이 짝수이면 2                                 ① 짝수를 거른다
    n 이 소수이면 n                                 ② 비자명한 약수가 없는 입력을 거른다
    c ← 1 부터 하나씩:
        f(t) = (t² + c) mod n                       ③ 상수 하나가 수열 하나를 정한다
        x ← 2,  y ← 2,  d ← 1                       ④ d 는 계산이 아니라 초기화다
        d 가 1 인 동안 되풀이:
            x ← f(x),  y ← f(f(y))                  ⑤ 한 걸음과 두 걸음
            d ← gcd(|x − y|, n)                     ⑥ 차와 n 의 최대공약수
        d 가 n 이 아니면 d 를 반환                  ⑦ 비자명한 약수를 찾았다
        아니면 c 를 올려 다시                       ⑧ 이 상수로는 못 찾는다
```

#### 1. 짝수와 소수를 먼저 가른다

앞에 사전 판정 둘을 둡니다. 짝수는 2 가 곧 답이라 수열을 만들 이유가 없고, 소수는 비자명한
약수가 아예 없어 어떤 상수로도 답이 나오지 않아요.

```ts
if (n % 2n === 0n) return 2n;             // ① 짝수를 거른다
if (isPrime(n)) return n;                 // ② 비자명한 약수가 없는 입력을 거른다
```

이 조각만 전개 입력에 실행하면 갈래 둘이 하나도 답을 돌려주지 않습니다.

```text
T1  n = 8,051       ① 의 n % 2 가 1 이라 거짓이다
                    나눗셈 한 번을 쓰고 아래로 내려간다

T2  n = 8,051       ② 의 소수 판정이 거짓이다 (8,051 = 83 × 97)
                    밑 열둘을 고정한 판정이 기본 연산 54 번을 쓰고 합성수라고 답한다
                    └ 여기를 지났다는 것은 n 이 홀수이고 비자명한 약수가 있다는 뜻이다
```

`②` 의 소수 판정은 이 편이 만드는 것이 아니라 부품입니다. 어떤 밑 열둘을 왜 쓰는지는 소수
판정 편이 다루고, 여기서 필요한 것은 「이 입력에 비자명한 약수가 있는가」 하나예요.

#### 2. 수열 하나를 두 속도로 진행시킨다

상수 `c` 를 정하면 함수 `f` 가 정해지고, 그 `f` 로 두 자리를 서로 다른 속도로 나아가게
합니다. `d` 는 계산하지 않고 1 로 둡니다 — 시작값이 같아 `|x − y| = 0` 이고
`gcd(0, n) = n` 이라 계산해 넣으면 루프 조건이 처음부터 거짓이 되기 때문이에요.

```ts
const f = (t: bigint): bigint => (t * t + c) % n;   // ③ 상수 하나가 수열 하나를 정한다
let x = 2n;
let y = 2n;
let d = 1n;                                         // ④ 계산이 아니라 초기화다

x = f(x);                                           // ⑤ 느린 자리는 한 걸음
y = f(f(y));                                        //    빠른 자리는 두 걸음
```

전개 입력에서 첫 걸음까지 실행하면 이렇게 나옵니다.

```text
T3  c = 1        f(t) = (t² + 1) mod 8051
                 x = 2,  y = 2,  d = 1                     아직 아무 계산도 하지 않았다

T4  한 걸음      x ← f(2) = 5
                 y ← f(f(2)) = f(5) = 26
                 ────────────────
                 |x − y| = 21 이고 이 값이 다음 걸음의 재료다
```

`f(f(y))` 를 한 번에 적는 것이 「두 걸음」의 전부입니다. `y` 를 두 번 갱신하는 대신 함수를
두 번 겹쳐 부르면 중간값을 따로 둘 필요가 없어요.

#### 짚고 가기 — 소수 판정을 빼도 될 것 같다

`②` 가 군더더기로 보이는 자리입니다. 소수를 넣으면 어차피 비자명한 약수가 없으니 수열이
알아서 아무것도 못 찾고 끝날 것 같아요. 그리고 합성수만 넣는다면 그 줄은 나눗셈만 더 하는
셈으로 보입니다.

```ts
if (isPrime(n)) return n;   // ← 이 줄을 빼면?
```

**먼저 확인해 둘 것이 있습니다 — 합성수 입력에서는 실제로 답이 안 바뀝니다.**

<!--proof:mutant-no-prime-guard-->

```text
  입력  소인수     정본  소수 판정을 뺀 판  두 칸
 8,051  83 × 97      97                 97  같다
    21  3 × 7         3                  3  같다
    25  5 × 5         5                  5  같다
    63  3 × 3 × 7    21                 21  같다
10,403  101 × 103   101                101  같다

└ 다섯 줄 다 합성수이고 셋째 칸과 넷째 칸이 줄마다 같다. 소수 판정은 합성수 입력의
  답에 아무것도 더하지 않는다 — 그 줄이 무엇을 막는지는 아래 표가 보인다
```

**다섯 줄 다 같은 값입니다.** 그러니 이 줄이 막는 것은 합성수 쪽이 아니에요. 소수를 넣어
보면 무엇이 달라지는지가 나옵니다 — 다만 그 판은 끝나지 않으므로 상수 `c` 를 몇 번까지
올릴지 한도를 두고 실행합니다.

<!--proof:pause-prime-loops-->

```text
     입력  정의대로       정본  소수 판정을 뺀 판  그때까지의 걸음
       97  소수             97  c = 30 까지 없음               273
    8,053  소수          8,053  c = 30 까지 없음             2,649
1,000,003  소수      1,000,003  c = 30 까지 없음            30,187

└ 세 줄 다 소수라 비자명한 약수가 없다. 넷째 칸은 c 를 30 까지 올려도 답이 없고,
  한도를 안 두면 그 자리에서 끝나지 않는다. 셋째 칸은 소수 판정이 그 자리에서
  n 자신을 돌려준 값이다
```

**소수에서는 어떤 상수로도 답이 나오지 않습니다.** `n` 이 소수이면 `gcd(|x − y|, n)` 이
가질 수 있는 값은 1 과 `n` 둘뿐이라 `d !== n` 검사를 통과할 값 자체가 없어요. 그래서
`c` 가 끝없이 올라갑니다.

```text
소수에서 최대공약수가 가질 수 있는 값

  n 이 소수      약수가 1 과 n 둘뿐이다        gcd 는 1 이거나 n 이다
  n 이 합성수    그 사이에 약수가 있다         gcd 가 그 사이 값이 될 수 있다
  ────────────────
  1 이면 루프가 계속되고 n 이면 상수를 올린다.  소수는 이 둘만 오가서 끝나지 않는다
```

#### 3. 차의 최대공약수가 약수를 낸다

두 자리를 나아가게 했으면 그 차와 `n` 의 최대공약수를 봅니다. 이 한 줄이 「법 `p` 에서
겹쳤는가」를 `p` 를 모르는 채로 판정하는 자리예요.

```ts
d = gcd(x > y ? x - y : y - x, n);   // ⑥ 차와 n 의 최대공약수
```

두 걸음을 더 실행하면 답이 나옵니다.

```text
T5  두 걸음      x ← f(5) = 26
                 y ← f(f(26)) = f(677) = 7,474
                 |x − y| = 7,448,  gcd(7448, 8051) = 1        아직 겹치지 않았다

T6  세 걸음      x ← f(26) = 677
                 y ← f(f(7474)) = 871
                 |x − y| = 194 = 2 × 97
                 ────────────────
                 gcd(194, 8051) = 97 이므로 d 가 1 이 아니게 되어 루프가 끝난다
```

`x > y` 를 보는 삼항 연산은 절댓값을 취하는 것입니다. 정본의 `gcd` 는 음이 아닌 두 수를
받는다고 적혀 있는데 `bigint` 뺄셈은 음수를 그대로 내므로, 그 삼항 연산이 없으면 계약 밖의
값이 들어가요.

```ts
d = gcd(x - y, n);   // ← 절댓값을 안 취하면?
```

<!--proof:mutant-no-abs-->

```text
             입력       정본  절댓값을 안 취한 판  셋째 칸은      두 칸
                9          3                   -3  약수가 아니다  어긋난다
            8,051         97                   -1  약수가 아니다  어긋난다
           10,403        101                 -101  약수가 아니다  어긋난다
               63         21                  -21  약수가 아니다  어긋난다
              325         25                   -1  약수가 아니다  어긋난다
1,000,036,000,099  1,000,033                   -1  약수가 아니다  어긋난다

└ 셋째 칸이 줄마다 음수다. 유클리드 호제법이 나머지의 부호를
  피제수에서 가져오므로 음수를 넣으면 결과의 부호가 따라오고, 그 값은 n 의 약수가 아니다.
  9 의 줄은 크기가 3 이라 절댓값은 정본과 같지만 부호가 어긋나 계약의 「1 < d」를 지키지 못한다
```

**셋째 칸이 줄마다 음수입니다.** 유클리드 호제법의 `x % y` 는 나머지의 부호를 피제수에서
가져오므로, 음수로 시작하면 결과의 부호가 따라옵니다. `-1` 이나 `-101` 은 `n` 의 약수가
아니라 계약이 요구하는 `1 < d` 를 아예 만족하지 못해요.

#### 짚고 가기 — 나온 약수가 소수일 것 같다

`gcd` 가 낸 값이 소인수처럼 보이는 자리입니다. 전개 입력에서 97 이 나왔고 그것이 소수라
「이 절차는 소인수를 준다」로 읽기 쉬워요. 하지만 계약이 요구하는 것은 **비자명한 약수**이지
소인수가 아닙니다.

```ts
const d = pollardRho(63n);   // 63 = 3 × 3 × 7 이면 무엇이 나올까?
```

두 소인수가 같은 걸음에서 함께 겹치면 최대공약수가 그 둘의 곱을 냅니다.

<!--proof:pause-composite-divisor-->

```text
  입력  n 의 소인수  반환값 d  d 의 소인수  d 는    n / d
    63  3 × 3 × 7          21  3 × 7        합성수      3
   105  3 × 5 × 7          21  3 × 7        합성수      5
   325  5 × 5 × 13         25  5 × 5        합성수     13
 8,051  83 × 97            97  97           소수       83
10,403  101 × 103         101  101          소수      103

└ 다섯 줄 모두 n 을 d 로 나눈 나머지가 0 이다. 다섯째 칸이 「합성수」인 줄에서는
  d 를 한 번 더 갈라야 소인수가 나온다 — 계약이 요구하는 것은 「비자명한 약수」이지
  「소인수」가 아니다
```

**63 과 105 에서 21 이, 325 에서 25 가 나옵니다.** 셋 다 합성수예요. `63 = 3 × 3 × 7` 에서
법 3 충돌과 법 7 충돌이 같은 걸음에 일어나면 `|x − y|` 가 21 의 배수가 되고, 그때
`gcd(|x − y|, 63)` 은 21 입니다.

```text
겹침이 둘 이상이면 곱이 나온다 — n = 63 에서

  법 3 에서 겹쳤다      3 이 |x − y| 를 나눈다
  법 7 에서도 겹쳤다    7 도 |x − y| 를 나눈다
  ────────────────
  21 이 |x − y| 를 나누고 63 도 나눈다.  gcd 는 21 이고 63 이 아니라 반환된다
```

소인수 전부가 필요하면 얻은 `d` 와 `n / d` 에 같은 절차를 다시 적용하면 됩니다. 그
재귀는 이 편의 계약 밖이고, 여기서 지켜야 할 것은 「`n` 을 나누고 1 도 `n` 도 아니다」
하나예요.

#### 5. 전체 코드

지금까지의 조각을 한 벌로 모읍니다. 새로 들어간 것은 `gcd` 와 `modPow` 와 `isPrime` 셋이에요
— 조각에서는 이름만 쓰고 지나갔는데, 여기서는 그 함수들의 본문까지 함께 싣습니다. 그리고
조각이 리터럴로 적었던 시작값 `2n` 과 첫 상수 `1n` 이 여기서는 이름 붙은 상수 `X0` 과 `C0`
입니다 — 씨앗을 한자리에 모아 두면 「무작위가 어디에도 없다」가 코드에서 확인됩니다.

```ts
/** 결정론적 소수 판정에 쓰는 밑 열둘 — 처음 열두 소수다. */
const BASES = [2n, 3n, 5n, 7n, 11n, 13n, 17n, 19n, 23n, 29n, 31n, 37n];

/** 수열의 시작값. 이 값과 `C0` 이 이 절차의 씨앗 전부다. */
const X0 = 2n;

/** 첫 상수. 이 상수로 못 찾으면 1 씩 올려 다른 수열을 만든다. */
const C0 = 1n;

/** 유클리드 호제법. 두 인자는 음이 아니고 `b` 는 `n` 이라 언제나 양수다. */
function gcd(a: bigint, b: bigint): bigint {
  let x = a;
  let y = b;
  while (y !== 0n) {
    const t = x % y;
    x = y;
    y = t;
  }
  return x;
}

/** `base` 의 `exp` 제곱을 법 `mod` 에서 구한다 — `fastPower` 편의 절차를 그대로 쓴다. */
function modPow(base: bigint, exp: bigint, mod: bigint): bigint {
  let result = 1n % mod;
  let b = base % mod;
  let e = exp;
  while (e > 0n) {
    if ((e & 1n) === 1n) result = (result * b) % mod;
    b = (b * b) % mod;
    e >>= 1n;
  }
  return result;
}

/** 밑 열둘을 고정한 밀러-라빈 판정 — `millerRabin` 편의 절차를 부품으로 그대로 쓴다. */
function isPrime(n: bigint): boolean {
  if (n < 2n) return false;
  for (const a of BASES) {
    if (n === a) return true;
    if (n % a === 0n) return false;
  }
  let d = n - 1n;
  let s = 0;
  while ((d & 1n) === 0n) {
    d >>= 1n;
    s += 1;
  }
  for (const a of BASES) {
    let x = modPow(a, d, n);
    if (x === 1n || x === n - 1n) continue;
    let witness = true;
    for (let i = 1; i < s; i++) {
      x = (x * x) % n;
      if (x === n - 1n) {
        witness = false;
        break;
      }
    }
    if (witness) return false;
  }
  return true;
}

export function pollardRho(n: bigint): bigint {
  // ① 짝수는 2 가 곧 답이다. 아래 수열은 홀수만 다룬다.
  if (n % 2n === 0n) return 2n;

  // ② 소수에는 비자명한 약수가 없다. 이 줄이 없으면 소수 입력에서 절차가 끝나지 않는다.
  if (isPrime(n)) return n;

  for (let c = C0; ; c += 1n) {
    // ③ 상수 c 하나가 수열 하나를 정한다. 두 자리를 같은 값에서 출발시킨다.
    const f = (t: bigint): bigint => (t * t + c) % n;
    let x = X0;
    let y = X0;
    // ④ 계산이 아니라 의도적인 초기화다. gcd(0, n) 이 n 이라 계산해 넣으면 루프 조건이
    //    처음부터 거짓이 된다.
    let d = 1n;

    while (d === 1n) {
      // ⑤ 느린 자리는 한 걸음, 빠른 자리는 두 걸음 나아간다.
      x = f(x);
      y = f(f(y));
      // ⑥ 두 자리의 차와 n 의 최대공약수. mod p 에서 겹치면 여기서 p 의 배수가 나온다.
      d = gcd(x > y ? x - y : y - x, n);
    }

    // ⑦ 1 도 n 도 아니면 비자명한 약수다.
    if (d !== n) return d;

    // ⑧ d = n 이면 이 c 로는 못 찾는다. 다음 c 가 다른 수열을 만든다.
  }
}
```

이 코드를 전개 입력과 규모가 다른 네 입력에 그대로 실행하면 이렇게 나옵니다.

| 입력 | 반환값 | 어디서 답했나 | 기본 연산 |
| --- | --- | --- | --- |
| `8051n` | `97n` | 상수 1 의 세 걸음 | 93 |
| `21n` | `3n` | 상수 2 의 두 걸음 | 29 |
| `1000003n` | `1000003n` | `②` 의 소수 판정 | 661 |
| `1000036000099n` | `1000033n` | 상수 1 의 1,276 걸음 | 39,224 |

### 알아 두면 좋은 개념 — 사이클 탐지 (플로이드)

전개에서 두 자리를 1 대 2 로 나아가게 한 것은 이 편만의 장치가 아닙니다. **한 값에서 시작해
같은 함수를 되풀이 적용하는 수열이 언제 같은 값을 다시 만나는지**를 추가 메모리 없이 찾는
방법에 이름이 붙어 있어요 — 플로이드의 사이클 탐지입니다.

수열이 꼬리와 순환 마디로 이뤄져 있을 때, 느린 자리가 `k` 번째이고 빠른 자리가 `2k` 번째
이므로 둘의 자리 차가 `k` 입니다. 그 차가 순환 마디 길이의 배수가 되고 두 자리가 모두 마디
안에 있으면 같은 값이 되고, 그 조건을 처음 만족하는 `k` 가 곧 만나는 자리예요. 지나온 값을
하나도 저장하지 않으므로 메모리가 상수입니다.

```text
본문의 어느 값이 이 개념이었는가 — 법 97 위의 수열

  걸음     0    1    2    3
  x (1배)  2    5   26   95        느린 자리
  y (2배)  2   26    5   95        빠른 자리
                          ↑
                          걸음 3 에서 두 자리가 같아졌다.
                          저장한 것은 x 와 y 두 값뿐이다
```

**같은 개념을 다시 만나는 자리**가 셋 있습니다. 연결 리스트에 순환이 있는지 판정할 때 두
포인터를 1 대 2 로 나아가게 하고, `1..n` 범위의 값 `n+1` 개에서 중복 하나를 찾을 때 배열을
함수로 보아 같은 방법을 쓰며, 이산 로그를 같은 모양으로 푸는 절차도 이 탐지를 씁니다.
저장 없이 순환을 찾는다는 점이 셋 다 같아요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 은 법 `p` 충돌이라는 개념을 세워 코드까지 만들었습니다. 여기서는 그 절차를 언제
고르는지, 반환값이 무엇을 보장하는지, 걸음 수가 무엇으로 정해지는지를 따집니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **인수분해할 수가 크고 개수는 적다.** `n` 이 `10^12` 를 넘어가면 약수를 하나씩 시험하는
  절차가 감당이 안 되는데, 이쪽은 걸음 수가 가장 작은 소인수의 제곱근 규모입니다.
- **약수 하나만 있으면 된다.** 소인수 전부가 필요하면 같은 절차를 재귀로 다시 적용하는
  구조가 되고, 그때도 한 번의 호출이 하는 일은 약수 하나입니다.
- **미리 만들어 둘 표가 없다.** 계약이 질의 하나를 받고 끝나는 모양이라 전처리를 걸 자리가
  없는데, 로 루프가 들고 있는 상태가 스칼라 넷이고 소수 판정까지 합쳐도 상수 칸이라 그
  계약과 어긋나지 않습니다.
- **평균이 좋으면 되고 최악을 보장할 필요가 없다.** 걸음 수의 상한을 닫아 주는 정리가 없어서
  최악을 계약으로 걸어야 하는 자리에는 못 씁니다.

```text
이 절차의 자리가 아닌 문제

  10^6 아래 수를 여러 개 인수분해한다     체로 최소 소인수 표를 만드는 편이 적다
  n 이 소수인지만 알면 된다               소수 판정 하나로 끝난다. 이 절차는 그것을 부품으로 쓴다
  최악 실행 시간을 계약으로 걸어야 한다   상한을 닫아 주는 정리가 없다
  RSA 규모(수백 자리)를 인수분해한다      타원곡선법이나 수체 체가 표준이다
```

셋째 줄이 이 절차의 경계입니다. 기대되는 걸음 수는 `n^(1/4)` 규모인데 그것은 수열이
무작위처럼 움직인다고 볼 때의 값이고, 어떤 `n` 에서도 그 안에 끝난다는 보장이 아니에요.

#### 문제에서 이것을 떠올리게 하는 단서

- 「`n` 을 소인수분해하라」에 `n` 의 상한이 `10^18` 이나 `2^64` 로 붙어 있다.
- 「약수를 하나만 찾아라」 — 전부가 아니라 하나라고 적혀 있으면 이 절차의 계약과 같습니다.
- 「`n = p × q` 이고 `p` 와 `q` 는 소수」 — 두 소인수가 비슷한 크기이면 약수를 하나씩
  시험하는 절차가 가장 불리한 모양이에요.
- 「소인수의 개수나 합을 구하라」에 `n` 이 크다 — 인수분해가 먼저 필요한 자리입니다.
- 「시행 나눗셈으로는 시간 초과」가 지문이나 예제에 암시돼 있다.

```text
「인수분해」가 나와도 다른 절차로 가는 자리

  「1 부터 10^6 까지 각 수의 소인수」   체가 최소 소인수 표를 한 번에 만든다
  「n 이 소수인지 판정하라」            소수 판정 하나로 끝난다
  「n 이 2^128 아래다」                 이 글이 확인한 규모 밖이다
```

미리 알 수 없으니 부르는 쪽이 끊을 자리를 정합니다.

#### 경쟁 설계와의 대조

경쟁 설계는 **폴라드 p−1 을 앞에 세운 두 단계 판**입니다. 한계 `B` 를 하나 정하고, `a` 를
2 에서 시작해 `a ← a^j mod n` 을 `j = 2, 3, …, B` 로 되풀이한 뒤 `gcd(a − 1, n)` 을 보는
단계를 먼저 실행하고, 거기서 못 찾으면 정본과 **같은** 로 절차로 내려갑니다. 되풀이가 끝난
`a` 는 `2^(B!) mod n` 이에요. 두 설계 다 언제나 비자명한 약수를 돌려주므로 계수가 저울질이
됩니다.

```text
두 설계가 갈리는 자리는 p − 1 의 소인수 크기 하나다

  정본            수열 하나를 두 속도로 진행시킨다        걸음 수가 √p 규모다
  경쟁 설계       a^(B!) − 1 과 n 의 최대공약수를 본다    p − 1 이 B-매끄러우면 그 자리에서 끝난다
                  └ p − 1 의 소인수가 전부 B 이하인 것을 「B-매끄럽다」고 부른다
```

**입력은 전개 입력을 그대로 두고 두 가족을 더했습니다.** 전개 입력 하나로는 뒤집히는 자리를
보일 수 없어요 — `8,051` 에서는 두 소인수의 `p − 1` 이 둘 다 작아 경쟁 설계의 첫 단계가
둘을 동시에 잡고 최대공약수가 `n` 이 되어 답을 못 냅니다. 그래서 큰 쪽 소인수를
`1,000,003` 으로 고정하고 작은 쪽만 두 가족에서 뽑았습니다 — 「`10^6` 위에서 처음 나오는,
`p − 1` 의 소인수가 전부 200 이하인 소수」와 「`10^6` 위에서 처음 나오는, `(p − 1) / 2` 도
소수인 소수」예요. 난수가 없어 몇 번을 실행해도 같은 값이 나옵니다.

<!--proof:alt-counts-->

```text
무엇                                      폴라드 로  두 단계 판  적은 쪽
전개 입력 8,051 기본 연산                        93       1,132  폴라드 로
매끄러운 p 기본 연산                         39,070       4,193  두 단계 판
안전 소수 p 기본 연산                         7,666      11,933  폴라드 로
갈리는 부분이 동시에 들고 있는 스칼라 칸          4           4  같다
고를 값의 개수                                    0           1  폴라드 로

└ 매끄러운 p 는 1,000,253 이고 안전 소수 p 는 1,000,667 이다.
  두 입력은 각각 1,000,256,000,759 와 1,000,670,002,001 이고 큰 쪽 소인수는 둘 다 1,000,003 이다.
  마지막 칸이 위 세 줄에서 갈리고 넷째 줄에서는 두 설계가 같다 — 한계 B = 200 으로 잰 값이다
```

**둘째 줄과 셋째 줄에서 순서가 뒤집힙니다.** 매끄러운 `p` 에서는 39,070 대 4,193 으로 경쟁
설계가 9 배 넘게 적고, 안전 소수 `p` 에서는 7,666 대 11,933 으로 정본이 적어요. 갈리는
조건은 하나입니다 — `p − 1` 의 가장 큰 소인수가 `B` 이하인가.

```text
왜 그 조건 하나로 갈리는가

  p − 1 이 B-매끄럽다       B! 가 p − 1 의 배수라 a^(B!) ≡ 1 (mod p)      첫 단계가 p 를 낸다
  p − 1 에 큰 소인수가 있다 B! 가 p − 1 의 배수가 아니다                  첫 단계가 헛일이 된다
  ────────────────
  헛일이 된 만큼은 그대로 손해다.  안전 소수에서 11,933 − 7,666 = 4,267 이 그 값이다
```

**한계 `B` 를 어디에 두느냐가 그 손해의 크기를 정합니다.** 여섯 값으로 재 보면 매끄러운
쪽은 어느 지점부터 좋아지다 멈추고 안전 소수 쪽은 계속 나빠져요.

<!--proof:alt-bound-->

```text
한계 B  매끄러운 p 를 어디서 찾나  매끄러운 p  안전 소수 p  둘의 합
    50  로 단계                        39,853        8,446   48,299
   100  로 단계                        40,913        9,513   50,426
   200  p-1 단계                        4,193       11,933   16,126
   400  p-1 단계                        4,193       17,363   21,556
   800  p-1 단계                        4,193       29,415   33,608
 1,600  p-1 단계                        4,193       55,958   60,151

└ 마지막 칸이 가장 작은 줄은 B = 200 이고 그때 16,126 이다.
  B 를 올리면 매끄러운 쪽은 좋아지다 멈추고 안전 소수 쪽은 계속 나빠진다 —
  안전 소수의 p − 1 은 1,000,666 = 2 × 500,333 이라
  B 가 500,333 보다 작으면 p-1 단계가 그 소인수를 못 찾는다
```

**두 가족의 합이 가장 작은 것은 `B = 200` 이고 16,126 입니다.** 100 에서 200 으로 올릴 때
매끄러운 쪽이 40,913 에서 4,193 으로 내려가는데, 그 자리가 `p − 1` 의 가장 큰 소인수인
179 를 `B` 가 넘어서는 지점이에요. 200 을 넘어서면 매끄러운 쪽은 4,193 에 머물고 안전 소수
쪽만 11,933 · 17,363 · 29,415 · 55,958 로 커집니다.

**이 절차가 내주는 것과 얻는 것을 적어 둡시다.** 내주는 것은 **`p − 1` 이 매끄러운 입력에서의
기본 연산**입니다 — 39,070 대 4,193 으로 9 배 넘게 더 써요. 얻는 것은 **`p − 1` 의 모양을
모를 때의 연산**(안전 소수에서 7,666 대 11,933), 그리고 **고를 값이 하나도 없다는 것**입니다.
경쟁 설계의 200 은 이 두 가족에서 잰 값이라 다른 입력 가족에서는 다시 골라야 해요. **저장
칸은 이 대조에서 갈리지 않습니다** — 두 설계가 공유하는 앞단(짝수 검사·소수 판정)을 빼고
세면 둘 다 넷이라 4 대 4 입니다.

### 수식 정의와 유도

법 `m` 위의 수열과 그 수열이 처음 같은 값을 다시 만나는 자리를 정식으로 정의합니다. $m$ 은
2 이상의 정수, $c$ 는 상수, $x_0$ 은 시작값입니다.

$$x_{i+1} \equiv x_i^2 + c \pmod m, \qquad \rho(m, c) = \min\{\, k \ge 1 \;:\; x_k \equiv x_{2k} \pmod m \,\}$$

```text
정의를 m = 97, c = 1, x0 = 2 에 넣으면

  i        0    1    2    3    4    5
  x_i      2    5   26   95    5   26
  x_2i     2   26    5   95   26    5
                          ↑
                          k = 3 에서 처음 x_k ≡ x_2k 다.   ρ(97, 1) = 3
```

`f` 가 $\{0, \dots, m-1\}$ 위에서 값을 고르게 뽑는다고 보면, 서로 다른 $k$ 개의 값이 전부
다를 확률은 생일 문제의 그것과 같습니다. 그 확률이 $1/2$ 아래로 내려가는 $k$ 가 $\sqrt{m}$
규모라는 것이 생일 문제의 결론이고, 그래서 $\rho(m, c)$ 의 기댓값도 같은 규모로 봅니다.

$$\Pr[\text{$k$ 개가 전부 다르다}] = \prod_{i=1}^{k-1}\Bigl(1 - \frac{i}{m}\Bigr) \approx e^{-k^2/(2m)}, \qquad \mathbb{E}\bigl[\rho(m, c)\bigr] = \Theta(\sqrt{m})$$

```ts
// 위 확률식을 그대로 옮긴 조각. 실제로 수열을 만들지 않고 값만 계산한다.
const allDistinct = (k: number, m: number): number =>
  Math.exp((-k * (k - 1)) / (2 * m));
```

정의가 실제 값과 맞는지 네 소수에서 검산합니다. 같은 `p` 를 상수 넷으로 실행해 $\rho(p, c)$
를 재고 그 평균을 $\sqrt{p}$ 로 나눠 봅니다.

<!--proof:math-check-->

```text
      p  √p 를 내림한 값  c = 1  c = 2  c = 3  c = 4  네 값의 평균 / √p
     97                9      3      8      6      9               0.72
  1,009               31     49     26     22     34               1.06
 10,007              100     40    110     76     54               0.70
100,003              316    518    387    198    384               1.18

└ 셋째 칸부터 여섯째 칸까지가 같은 p 를 상수 넷으로 실행해 잰 첫 충돌 걸음이다.
  같은 p 에서도 상수에 따라 값이 갈리고, 마지막 칸은 네 값의 평균을 √p 로 나눈 것이다.
  p 가 97 에서 100,003 으로 약 1,000 배 커지는 동안 마지막 칸은 1 근방에 머문다
```

**마지막 칸이 0.70 과 1.18 사이입니다.** 같은 `p` 에서도 상수에 따라 값이 크게 갈리는데
(10,007 에서 40 과 110), 넷의 평균은 `√p` 근방에 머물러요. 이것이 $\Theta(\sqrt{m})$ 이
**개별 값이 아니라 기댓값에 대한 진술**이라는 뜻입니다. 이 결과를 `n` 의 인수분해에 옮기면,
`n` 이 합성수일 때 가장 작은 소인수 `p` 가 $p \le \sqrt{n}$ 을 만족하고 절차가 보는 것은
법 `p` 위의 겹침이므로 걸음 수의 기댓값이 `n` 하나로 닫힙니다.

$$\mathbb{E}[k] = \Theta\bigl(\sqrt{p}\bigr) \;\le\; \Theta\bigl(\sqrt{\sqrt{n}}\bigr) \;=\; \Theta\bigl(n^{1/4}\bigr)$$

```text
두 방법의 걸음 수를 같은 n 에서 견주면

  약수를 하나씩 시험한다      √n / 2 번의 나눗셈          n 이 커지면 √n 을 따라간다
  법 p 의 겹침을 기다린다     n^(1/4) 규모의 걸음         지수가 절반이다
  ────────────────
  비트 길이 d = log₂ n 으로 다시 쓰면 2^(d/2) 대 2^(d/4) 다.
  둘 다 비트 길이에 대해서는 지수이고, 이 절차는 그 지수를 반으로 줄인다
```

**제약 규모에 넣어 봅시다.** 규모마다 두 값이 얼마가 되는지를 나란히 놓습니다.

<!--proof:math-scale-->

```text
규모                             n  정의를 옮긴 방법의 나눗셈 √n / 2  이 절차의 걸음 n^(1/4)  셋째를 넷째로 나눈 값
10^4                        10,000                                50                      10                      5
10^8                   100,000,000                             5,000                     100                     50
10^12            1,000,000,000,000                           500,000                   1,000                    500
10^16       10,000,000,000,000,000                        50,000,000                  10,000                  5,000
2^64    18,446,744,073,709,551,616                     2,147,483,648                  65,536                 32,768
10^20  100,000,000,000,000,000,000                     5,000,000,000                 100,000                 50,000

└ 계약 상한 2^64 = 18,446,744,073,709,551,616 이 다섯째 줄이다.
  셋째 칸과 넷째 칸은 실행하지 않고 √ 를 한 번과 두 번 구해 센 값이라 상수 배가
  안 담겨 있다 — 마지막 칸은 두 방법의 걸음 수 비이지 실행 시간의 비가 아니다
```

**계약 상한 `2^64` 에서 21 억 대 6 만 5 천입니다.** 3 만 배가 넘는 차이인데, 이 값은 걸음
수의 비이지 실행 시간의 비가 아니에요 — 이 절차의 걸음 하나는 `f` 호출 세 번과 최대공약수
한 번이라 나눗셈 한 번보다 비용이 큽니다. 그 상수 배까지 담은 계수는 아래에서 셉니다.

### 불변식 — 반환하는 `d` 는 언제나 `n` 의 약수이고 반환하는 자리에서 `1 < d < n` 이다

파트 1 의 일곱 걸음은 `n = 8,051` 하나에서 답이 나온 기록입니다. 그 기록만으로는 다른
입력에서도 반환값이 계약을 지키는지가 성립하지 않아요. 걸음마다 참인 문장을 세우고 값으로
확인합시다.

> 로 루프의 매 걸음 직후 `d = gcd(|x − y|, n)` 이고, 최대공약수의 정의상 `d` 는 언제나
> `n` 의 약수입니다. 반환하는 자리에서는 그 위에 `d ≠ 1` 과 `d ≠ n` 이 함께 참입니다.

```text
전개 입력에서 걸음마다 무엇이 보장됐나

  걸음   d     n 의 약수인가   반환할 수 있는가
  T4     1     그렇다          아니다 — d = 1 이라 루프가 계속된다
  T5     1     그렇다          아니다 — 같은 이유다
  T6     97    그렇다          그렇다 — 1 도 8,051 도 아니다
         ────────────────
         앞의 두 걸음에서도 문장의 앞부분은 참이다. 반환을 막는 것은 뒷부분이다
```

**세 자리가 문장을 나눠 집니다.** 최대공약수 계산이 「`n` 의 약수」를 지고, 루프 조건
`d === 1n` 이 「`d ≠ 1`」을 지며, 반환 검사 `d !== n` 이 「`d ≠ n`」을 집니다. 갈래마다 어느
자리가 무엇을 보장하는지 적어 둡시다.

| 어느 자리를 지날 때 | `d` 가 어떻게 바뀌는가 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| 초기화 `let d = 1n` | `d ← 1` | 1 은 모든 정수의 약수라 앞부분이 참이다. 뒷부분은 아직 아니다 |
| 최대공약수 `gcd(\|x − y\|, n)` | `d ← gcd(…, n)` | 최대공약수의 정의상 `n` 을 나눈다. 차가 0 이면 `gcd(0, n) = n` 이라 `d = n` 이다 |
| 루프 조건 `d === 1n` 이 거짓 | `d` 가 그대로 남는다 | `d ≠ 1` 이 여기서 정해진다 |
| 반환 검사 `d !== n` 이 참 | `d` 를 그대로 돌려준다 | `d ≠ n` 이 여기서 정해져 셋이 모두 참이 된다 |
| 반환 검사가 거짓 | 상수를 올려 처음부터 | `d = n` 이라 돌려줄 수 없다. 다른 수열로 다시 시작한다 |

**둘째 줄이 경계를 함께 집니다.** `x` 와 `y` 가 법 `n` 에서까지 같아지면 차가 0 이고
`gcd(0, n) = n` 이라 `d = n` 이 돼요. 그것이 넷째 줄을 거짓으로 만들어 상수를 올리게 하는
자리입니다.

<!--proof:edge-values-->

```text
   입력 n  어느 갈래가 답하나       정본  시행 나눗셈  d 는  자리
        2  짝수                        2            2  약수  n 자신
        3  소수                        3            3  약수  n 자신
        4  짝수                        2            2  약수  1 < d < n
        9  로                          3            3  약수  1 < d < n
       15  로                          3            3  약수  1 < d < n
       21  로                          3            3  약수  1 < d < n
       25  로                          5            5  약수  1 < d < n
       49  로                          7            7  약수  1 < d < n
       63  로                         21            3  약수  1 < d < n
    8,051  로                         97           83  약수  1 < d < n
1,000,003  소수                1,000,003    1,000,003  약수  n 자신
2,000,006  짝수                        2            2  약수  1 < d < n

└ 다섯째 칸이 열두 줄 내내 「약수」다. 셋째 칸과 넷째 칸이 갈리는 줄이 있는데
  두 절차가 같은 약수를 고를 이유가 없어서다 — 계약이 요구하는 것은 「어느 것이든
  하나」다. 여섯째 칸이 「n 자신」인 줄은 둘째 칸이 「소수」인 줄과 정확히 같다
```

**다섯째 칸이 열두 줄 내내 「약수」입니다.** 셋째 칸과 넷째 칸이 63 과 8,051 에서 갈리는데,
두 절차가 같은 약수를 고를 이유가 없어서예요 — 계약이 요구하는 것은 「어느 것이든 하나」
입니다. 그리고 여섯째 칸이 「`n` 자신」인 줄은 둘째 칸이 「소수」인 줄과 정확히 같아요.

**이제 깨뜨려 봅시다.** 문장의 뒷부분 「`d ≠ n`」을 지키는 것은 반환 검사 한 줄입니다. 그
검사를 빼면 첫 라운드가 낸 `d` 를 그대로 돌려주게 돼요.

```ts
return d;   // ← if (d !== n) return d; 이었다
```

<!--proof:mutant-return-any-->

```text
 입력  소인수     정본  반환 검사를 뺀 판  뺀 판이 낸 d 의 자리  두 칸

   15  3 × 5         3                  3  1 < d < n             같다
   21  3 × 7         3                 21  n 자신이다            어긋난다
   25  5 × 5         5                 25  n 자신이다            어긋난다
   63  3 × 3 × 7    21                 21  1 < d < n             같다

└ 넷째 칸이 21 과 25 에서 입력 자신과 같은 값이다. 합성수인데 n 자신을 돌려준 것이라
  계약의 「1 < d < n」이 깨진다. 나머지 네 줄은 첫 상수 c = 1 이 곧바로 비자명한
  약수를 내는 줄이라 두 판의 답이 같다
```

**21 과 25 에서 입력 자신이 나옵니다.** 둘 다 합성수인데 `d = n` 을 돌려준 것이라 계약의
「`1 < d < n`」이 깨져요. 나머지 네 줄은 첫 상수가 곧바로 비자명한 약수를 내는 줄이라 두
판의 답이 같습니다.

```text
21 에서 무슨 일이 일어나는가 — c = 1, f(t) = (t² + 1) mod 21

  x ← f(2) = 5,  y ← f(f(2)) = f(5) = 26 mod 21 = 5      두 값이 같아졌다
  |x − y| = 0,  gcd(0, 21) = 21                          d 가 n 이다
  ────────────────
  정본은 여기서 상수를 2 로 올려 다시 시작하고 두 걸음 만에 3 을 낸다.
  검사를 뺀 판은 21 을 그대로 돌려주고, 21 은 21 의 자명한 약수다
```

### 비용 계산

#### 비용을 세는 과정

세는 단위를 먼저 정합니다. **`n` 크기의 두 수를 곱하거나 나누는 연산 하나를 1 로 셉니다.**
`f(t) = (t² + c) mod n` 은 곱 하나와 나머지 하나라 2 이고, 유클리드 호제법의 `x % y` 한
번은 1 이며, 짝수 검사 `n % 2n` 도 1 이에요. 비교와 덧셈은 세지 않습니다.

```text
전개 입력에서 실제로 한 일 — 기본 연산 93 번

  ① 짝수 검사 (T1)                 1 번   n % 2 를 한 번
  ② 소수 판정 (T2)                54 번   밑 열둘을 고정한 판정이 쓴 값
  ⑤ f 호출 (T4·T5·T6)             18 번   걸음마다 세 번 × 2 × 3 걸음
  ⑥ 최대공약수 (T4·T5·T6)         20 번   세 번의 유클리드 나눗셈 합
  ③ ④ ⑦ 판정                       0 번   비교라 세는 단위에 안 넣는다
  ─────────────────
  1 + 54 + 18 + 20 = 93
```

횟수가 정해지는 자리는 셋입니다. 소수 판정이 쓴 몫을 `P`, 라운드를 합친 걸음 수를 `Σk`,
유클리드 나눗셈의 합을 `G` 로 적습니다.

| 무엇 | 몇 번 | 근거 |
| --- | --- | --- |
| 짝수 검사 | 1 번 | 언제나 한 번이다 |
| 소수 판정 | `P` 번 | 밑 열둘의 거듭제곱. 짝수 입력에서는 0 이다 |
| `f` 호출 | `6·Σk` 번 | 걸음마다 `f` 를 세 번 부르고 한 번이 기본 연산 2 다 |
| 유클리드 나눗셈 | `G` 번 | 걸음마다 다르다. 합으로 센다 |

```text
총식 — 어디서 멈추느냐가 전부를 정한다

  ① 에서 답하면        기본 연산 1                    짝수다
  ② 에서 답하면        1 + P                          소수다
  로 루프에 내려가면   1 + P + 6·Σk + G               Σk 는 라운드를 합친 걸음 수다
  ─────────────────
  P 는 소수 판정 편이 낸 값이고, Σk 와 G 는 이 절차가 실행해야 알 수 있는 값이다
```

식이 실행과 같은 값을 내는지 일곱 입력에서 확인합니다.

<!--proof:perf-formula-->

```text
             입력  소수 판정 P  로 루프 걸음 합 Σk  유클리드 나눗셈 G  식이 내는 기본 연산  실행이 센 기본 연산
        2,000,006            0                   0                  0                    1                    1
        1,000,003          660                   0                  0                  661                  661
            8,051           54                   3                 20                   93                   93
               21            2                   3                  8                   29                   29
           10,403           48                   9                 73                  176                  176
      110,107,021           84                  40                672                  997                  997
1,001,006,003,009          124               1,276             31,443               39,224               39,224

└ 다섯째 칸과 여섯째 칸이 일곱 줄 내내 같다. 다섯째 칸은 1 + P + 6Σk + G 를 계산한
  값이고 앞의 세 칸이 그 P·Σk·G 다. 위 두 줄은 로 루프에 내려가지 않아 Σk 와 G 가 0 이다
```

**다섯째 칸과 여섯째 칸이 일곱 줄 내내 같습니다.** 전개 입력의 줄이 `1 + 54 + 6×3 + 20 = 93`
이고 그것이 T1 부터 T7 까지의 합이에요. `G` 를 `Σk` 로 나눈 걸음당 나눗셈 수는 `n` 이
커질수록 늡니다 — 8,051 에서 20 ÷ 3 = 6.7 이고 10,403 에서 73 ÷ 9 = 8.1 이며
110,107,021 에서 672 ÷ 40 = 16.8 이고 `10^12` 규모에서 31,443 ÷ 1,276 = 24.6 이에요.
유클리드 호제법이 `n` 의 비트 수를 따라가기 때문입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (짝수다) | `O(1)` | `Θ(1)` |
| **평균적인 경우** (수열이 값을 고르게 뽑는다고 볼 때) | `O(n^(1/4) log n)` | 정하지 않았다 |
| **최악의 경우** (수열이 가장 늦게 겹치는 입력) | 알려진 상한이 없다 | 정하지 않았다 |

**최악 줄에 알려진 상한이 없는 것이 이 절차의 성질입니다.** 걸음 수는 법 `p` 위의 수열이 언제
겹치는가에 달려 있는데, 그것을 어떤 `n` 에서도 `n^(1/4)` 안이라고 보장해 주는 정리가 없어요.
상수를 올려 다시 시작하는 갈래가 몇 번 실행될지도 마찬가지입니다.

```text
경계의 종류와 보장의 종류를 갈라 적으면

  O(n^(1/4) log n)   상한이고, 「수열이 값을 고르게 뽑는다」는 가정 위에서의 기댓값이다
  최악 보장          없다.  어떤 n 에서도 그 안에 끝난다고 말할 수 없다
  ────────────────
  log n 은 걸음 하나의 값이다 — 유클리드 호제법이 n 의 비트 수를 따라간다.
  기댓값이 무엇에 대한 것인가: 입력 분포가 아니라 f 를 무작위 함수로 본 가정에 대한 것이다
```

**보장의 종류는 기댓값이지 최악 보장이 아닙니다.** 그리고 그 기댓값은 입력이 어떤 분포로
들어오는지에 대한 것도 아니에요 — 「`f(t) = (t² + c) mod p` 가 값을 고르게 뽑는다」는 가정
위에서의 값입니다. 그 가정이 참인지는 증명돼 있지 않고, 위 표본 여섯이 그것과 어긋나지
않았다는 것까지가 이 글이 확인한 전부입니다.

```text
같은 상한 아래에서 실제 걸음을 정하는 것

  가장 작은 소인수가 2 다        나눗셈 한 번으로 끝난다            기본 연산 1
  n 이 소수다                    소수 판정에서 끝난다               기본 연산 1 + P
  가장 작은 소인수가 작다        법 p 의 자리가 적어 빨리 겹친다    걸음 수가 √p 규모
  두 소인수가 √n 근방이다        법 p 의 자리가 가장 많다           걸음 수가 n^(1/4) 규모다
```

#### 최악을 만드는 입력

「`n` 이 크면 최악」이라는 통념부터 확인합시다. 제약 규모 근처의 수를 모양만 바꿔 가며 정본에
넣으면 계수가 이렇게 갈립니다.

<!--proof:worst-shapes-->

```text
입력 모양                                                    n  로 루프 걸음  기본 연산
짝수                                 2,000,000,000,000,000,006             0          1
가장 작은 소인수가 3                 3,000,000,000,000,000,009             1         14
가장 작은 소인수가 10^3 근방         1,009,000,000,000,037,333            49      2,193
가장 작은 소인수가 10^6 근방         1,000,003,000,039,000,117         1,276     54,023
두 소인수가 모두 10^9 근방           1,000,001,018,000,007,077        18,970    798,912
2^64 아래 두 소인수가 가장 큰 모양  18,446,744,030,759,878,681        80,073  3,572,015
소수                                 1,000,000,000,000,000,003             0      2,029

└ 일곱 줄의 n 이 전부 10^18 이상인데 마지막 칸이 1 과 3,572,015 사이로
  갈린다. n 이 아니라 가장 작은 소인수가 계수를 정한다 — 마지막 줄은 소수라 로 루프에
  내려가지도 않는다. 여섯째 줄은 4,294,967,291 의 제곱이고 2^64 아래에서
  가장 작은 소인수가 가장 클 수 있는 모양이다
```

**통념은 절반만 맞습니다.** 일곱 줄의 `n` 이 전부 `10^18` 이상인데 기본 연산이 1 번부터
3,572,015 번까지 벌어져요. `n` 이 정하는 것은 가장 작은 소인수가 가질 수 있는 **상한**뿐이고,
실제 값은 그 소인수가 어디 있는가가 정합니다.

```text
같은 규모에서 350 만 배 넘게 갈리는 자리

  2 × (10^18 근방 소수)          짝수 갈래가 나눗셈 한 번으로 끝낸다     기본 연산 1
  (2^32 바로 아래 소수)²         가장 작은 소인수가 2^32 근방이다        기본 연산 3,572,015
  ────────────────
  둘 다 10^18 을 넘는다.  갈리는 것은 가장 작은 소인수 하나다
```

**최악을 실제로 구성해 봅시다.** 걸음 수가 `√p` 규모이고 `p` 는 가장 작은 소인수이므로,
`p` 를 가능한 한 크게 만들면 됩니다. 가장 작은 소인수가 가장 클 수 있는 모양은 **소인수가
정확히 둘이고 둘의 크기가 같은 것**이에요 — 셋 이상이면 가장 작은 것이 `n^(1/3)` 이하로
내려갑니다.

```text
제약 규모 안에서 최악 입력을 구성하는 순서

  첫째   소인수를 둘로 정한다        셋이면 가장 작은 것이 n^(1/3) 이하로 내려간다
  둘째   둘의 크기를 같게 한다       p = q 이면 p 가 √n 으로 가장 크다
  셋째   그 크기를 규모 상한에서     p² < 2^64 이므로 p 는 2^32 아래에서 가장 큰 소수다
  ────────────────
  p = 4,294,967,291 이고 n = p² = 18,446,744,030,759,878,681 < 2^64 다.
  위 표의 여섯째 줄이 그것이고 로 루프가 80,073 걸음, 기본 연산이 3,572,015 다
```

가장 적은 일을 하는 입력은 반대쪽입니다. 짝수이면 나눗셈 한 번으로 끝나고, 소수이면 소수
판정만 하고 끝나요. 그리고 **소인수가 여럿이면 오히려 쉬워집니다** — `10^18` 규모라도 가장
작은 소인수가 3 이면 기본 연산이 14 번입니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 수열 하나를 법 `n` 위에서 만들되 그 수열이
**법 `p` 위에서 먼저 겹치는 자리**를 노리고, 겹쳤는지를 `gcd(|x − y|, n)` 한 번으로 판정해
`p` 의 이름을 모르는 채로 약수를 얻었습니다. 겹침을 찾는 장치가 두 자리를 1 대 2 로 나아가게
하는 것이고, 한 상수로 못 찾으면 상수를 올려 다른 수열로 다시 시작해요.

```text
짝수인가  →  소수인가  →  수열 하나를 만든다  →  두 자리를 나아가게 하고 gcd 를 본다
                                   │                              │
                                   │                              └ 1 도 n 도 아니면 답이다
                                   └ 상수 c 가 수열을 정한다.  n 이 나오면 c 를 올린다
```

먼저 답이 붙는 문제 하나입니다. 전개는 `n = 8,051` 이었고 T4 부터 T6 까지 세 걸음으로 답이
나왔어요. **같은 코드에 `n = 21` 을 넣으면 상수가 몇 번 바뀌고 각 상수에서 몇 걸음이
걸립니까?**

```text
21 = 3 × 7,   f(t) = (t² + c) mod 21,   x = y = 2

  c = 1 의 첫 걸음    x = ?,  y = ?,  |x − y| = ?,  d = ?
  그 d 가 21 이면     ⑦ 이 거짓이 되어 무엇이 실행되는가?
  c = 2 에서          몇 걸음 만에 1 < d < 21 이 되는가?
```

<!--check:retry21-->
답: 상수가 한 번 바뀌고, `c = 1` 은 한 걸음, `c = 2` 는 두 걸음입니다. `c = 1` 에서
`x = f(2) = 5` 이고 `y = f(f(2)) = f(5) = 26 mod 21 = 5` 라 두 값이 같아져 `|x − y| = 0`
이고 `gcd(0, 21) = 21` 이에요. 그것이 `n` 자신이라 `⑦` 이 거짓이 되고 `⑧` 이 실행됩니다.

<!--proof:check-retry-->

```text
상수 c  걸음   x   y  |x − y|   d
     1     1   5   5        0  21
     2     1   6  17       11   1
     2     2  17  11        6   3

└ c = 1 의 첫 걸음에서 d 가 21 이 되는데 그것이 n 자신이라 ⑧ 이 실행된다.
  c = 2 가 2 걸음에서 3 을 내고 정본의 반환값도 3 이다.
  기본 연산은 모두 29 번이다
```
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 불변식              3 → 최악을 만드는 입력
  2 → 수식 정의와 유도
```

- T6 에서 `|x − y| = 194 = 2 × 97` 이라 `gcd(194, 8051) = 97` 이 나왔습니다. 만약 같은
  걸음에서 차가 `2 × 83 × 97 = 16,102` 였다면 최대공약수가 얼마가 되고, 그 값이 반환될 수
  있습니까 — 불변식의 어느 부분이 그것을 막습니까?
- 「수식 정의와 유도」가 걸음 수의 기댓값을 `n^(1/4)` 규모로 닫았습니다. 소인수가 셋인
  `n = p³` 꼴에서는 가장 작은 소인수가 `n^(1/3)` 이니 그 규모가 어떻게 바뀌고, `n = 10^18`
  에서 두 모양의 걸음 수가 각각 얼마가 됩니까?
- 「최악을 만드는 입력」이 소인수 둘의 크기가 같은 모양이라고 했습니다. `2^64` 아래에서 그
  모양의 `n` 을 하나 구성해 보고, 같은 규모에서 기본 연산이 가장 적은 **홀 합성수**는 어떤
  모양이어야 하는지 적어 보세요.
