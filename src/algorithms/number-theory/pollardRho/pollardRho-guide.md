# 폴라드 로 — 수열이 법 p 에서 먼저 되풀이되는 자리를 두 걸음 차이의 최대공약수가 잡아낸다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 약수를 하나씩
시험하는 시행 나눗셈에서 출발해 두 걸음 차이의 최대공약수까지 가고, 그 방법을 단계마다 값으로 푼 뒤, 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

정수 `n` 하나를 받아 **비자명한 약수** 하나를 돌려주는 일을 다룹니다. 비자명한 약수는 1 도 `n` 자신도 아닌
약수예요. 다루는 범위는 `2 ≤ n < 2^64` 이고, `n` 이 짝수이면 2 를, `n` 이 소수이면 비자명한 약수가 없으니 `n`
자신을 돌려줍니다. 짝수는 첫 검사(①)가, 소수는 소수 판정(②)이 답하고, 나머지는 아래에서 설명할 수열을 되풀이하는
반복이 답해요. 이 반복을 **로 루프**라고 부릅니다. 입력 다섯에 이 글의 절차를 실행한 결과입니다.

<!--proof:concept-answer-->

| 입력 n | 소인수 | 돌려준 값 d | n ÷ d | 답한 갈래 |
| ---: | --- | ---: | ---: | --- |
| 8,051 | 83 × 97 | 97 | 83 | 로 루프 |
| 21 | 3 × 7 | 3 | 7 | 로 루프 |
| 63 | 3 × 3 × 7 | 21 | 3 | 로 루프 |
| 2,000,006 | 2 × 1,000,003 | 2 | 1,000,003 | ① 짝수 |
| 1,000,003 | 소수 | 1,000,003 | 1 | ② 소수 |

5 줄 가운데 n 을 d 로 나눈 나머지가 0 인 줄은 5 개입니다. d 가 소수가 아닌 줄은 63 의 줄입니다.

<!--/proof-->

돌려준 값은 약수이기만 하면 됩니다. 63 에서 나온 21 처럼 소수가 아닐 수도 있어요. 약수를 찾는 가장 쉬운 길은
2 부터 차례로 나눠 보는 것인데, 그 길은 가장 작은 소인수에 이를 때까지 나눠야 합니다. 이 글의 절차는 약수를
하나도 시험하지 않습니다. 대신 **수열** 하나를 만들어요.

```text
x₀ = 2
x_(i+1) = (x_i² + c) mod n        c 는 상수 — 처음에는 1 이다
```

이 수열을 `n` 의 소인수 `p` 로 나눈 나머지로 다시 읽으면, 값이 놓일 자리가 `p` 개뿐이라 `n` 개인 원래 수열보다
훨씬 빨리 앞에 나온 값을 다시 만납니다. 한 번 같은 값을 만나면 그 뒤로는 같은 값들을 같은 차례로 되풀이해요.
되풀이되지 않는 앞부분을 **꼬리**, 되풀이되는 부분을 **마디**라고 부르고, 꼬리 끝에 마디가 붙은 모양이 그리스
문자 ρ(로)를 닮아 **ρ 모양**이라고 부릅니다. `n = 8,051 = 83 × 97` 의 수열을 법 97 과 법 8,051 로 읽으면 이렇게
생겼습니다.

<!--fig:concept-rho-->
![같은 수열을 법 97 과 법 8,051 로 읽은 ρ 모양](./figs/concept-rho.svg)

정점 안의 큰 수가 값이고, 아래 줄이 그 값이 나오는 자리입니다. 법 97 에서는 `x₄` 가 `x₁` 과 같은 값이라 꼬리
한 칸 뒤에 마디 세 칸이 되풀이되고, 법 8,051 에서는 `x₁₉` 에 이르러서야 `x₄` 와 같아집니다. 코드는 97 을 모르니
법 97 의 값을 직접 볼 수 없어요. 그런데 법 97 에서 같은 두 칸은 차가 97 의 배수라, 그 차와 `n` 의 최대공약수가
97 을 내놓습니다.

<!--proof:concept-gcd-->

```text
법 97 에서 같은 두 칸   x₁ = 5 · x₄ = 7,474           둘 다 97 로 나눈 나머지가 5
두 칸의 차              7,474 − 5 = 7,469 = 97 × 77   8,051 의 배수는 아니다
8,051 과의 최대공약수   gcd(7,469, 8,051) = 97
```

남은 일은 **어느 두 칸을 비교하느냐**입니다. 이 글의 절차는 걸음마다 한 칸씩 나아가는 **느린 자리** `x` 와 두
칸씩 나아가는 **빠른 자리** `y` 를 두고, 걸음마다 둘의 차와 `n` 의 최대공약수 하나만 봅니다. 두 자리가 법 `p`
의 마디 안에서 같은 칸에 놓이는 걸음이 오면 그 최대공약수가 `p` 의 배수가 돼요.

| 이름 | 뜻 |
| --- | --- |
| 비자명한 약수 | 1 도 `n` 도 아닌 약수 |
| 수열 | `x₀ = 2` 에서 시작해 `(x² + c) mod n` 을 되풀이한 값의 줄 |
| ρ 모양 | 수열을 한 법으로 읽었을 때 되풀이되지 않는 꼬리와 되풀이되는 마디가 이어진 모양 |
| 느린 자리 · 빠른 자리 | 수열 위를 한 걸음에 한 칸 · 두 칸씩 나아가는 두 값 `x` · `y` |

비용은 나머지 연산(`%`)의 횟수로 셉니다. 시행 나눗셈과 나란히 세면 이렇습니다.

<!--proof:concept-scale-->

| 입력 | n | 시행 나눗셈 | 폴라드 로 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 8,051 | 29 | 65 |
| 두 소인수가 10^6 근방 | 1,001,006,003,009 | 333,336 | 35,342 |
| 2^64 아래에서 가장 작은 소인수가 가장 큰 모양 | 18,446,744,030,759,878,681 | 1,431,655,765 | 3,331,703 |

두 열 모두 나머지 연산의 횟수입니다. 시행 나눗셈은 가장 작은 소인수까지 후보를 나눈 횟수이고, 폴라드 로는 소수 판정을 포함한 전부입니다.

<!--/proof-->

걸음 수는 가장 작은 소인수 `p` 의 제곱근 규모라 `n^(1/4)` 규모가 됩니다. 다만 이것은 기대되는 크기이지
어떤 입력에서도 그 안에 끝난다는 보장이 아니에요. 소수 판정과 최대공약수는 이웃한 편의 절차를 부품으로 씁니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **나머지 연산과 합동.** `a ≡ b (mod m)` 이 `a` 와 `b` 를 `m` 으로 나눈 나머지가 같다는 뜻이라는 것. 이 글의
  계산은 전부 이 위에서 이뤄집니다.
- **최대공약수와 유클리드 호제법.** `gcd(a, b)` 를 나머지 연산의 되풀이로 구하는 방법과 `gcd(0, m) = m` 이라는
  규약. [최대공약수 가이드](../gcd/gcd-guide.md)가 그 절차를 다루고, 이 글은 음이 아닌 두 수를 받는 판을
  부품으로 씁니다.
- **소수 판정(밀러-라빈).** 밑 열둘을 고정해 `2^64` 아래에서 소수인지 확정하는 판정. 이 글의 첫 사전 판정이
  그 절차를 그대로 부르고, 그 판정이 쓰는 나머지 연산도 그 편이 센 값을 그대로 씁니다.
  [소수 판정 가이드](../millerRabin/millerRabin-guide.md)에 있어요.
- **시행 나눗셈.** 2 · 3 으로 나눈 뒤 `6k±1` 후보로 차례로 나눠 보는 판정. 이 글의 출발점입니다.
  [시행 나눗셈 가이드](../isPrimeTrial/isPrimeTrial-guide.md)에 있어요.
- **`bigint` 와 정수 정밀도.** JavaScript 의 `number` 는 정수를 오차 없이 담는 범위가 `2^53` 까지이고, 그보다
  큰 정수는 `bigint` 로 다뤄야 한다는 것.

이 글이 다루는 것은 **큰 수 하나에서 비자명한 약수 하나를 찾는 일**입니다. 가까운 일을 다루는 글이 셋 더 있어요.

| 하는 일 | 다루는 글 |
| --- | --- |
| 수 하나가 소수인지 확정한다 | [`millerRabin`](../millerRabin/millerRabin-guide.md) |
| 작은 수 하나가 소수인지 약수로 묻는다 | [`isPrimeTrial`](../isPrimeTrial/isPrimeTrial-guide.md) |
| 두 수의 최대공약수를 구한다 | [`gcd`](../gcd/gcd-guide.md) |

이 절차가 돌려주는 것은 약수 하나입니다. 소인수를 전부 구하려면 얻은 `d` 와 `n / d` 에 같은 절차를 다시
적용해야 해요.

### 아이디어를 떠올리는 과정 — 시행 나눗셈에서 두 걸음 차이의 최대공약수까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정수를 받아 그 약수 하나를
돌려줍니다.

```ts
function pollardRho(n: bigint): bigint;
```

- 입력: 정수 `n` 하나입니다. `n ≥ 2` 예요.
- 출력: `n` 의 약수 `d` 하나. `1 < d ≤ n` 이고, `n` 이 합성수이면 `1 < d < n` 입니다. 비자명한 약수가 여럿이면
  어느 것을 돌려줘도 됩니다.
- 규모: `2 ≤ n < 2^64` 입니다. 소수 판정 편의 밑 열둘이 확정 판정을 내는 범위이고, 부호 없는 64 비트 정수가
  담는 범위라 흔히 받는 입력이에요. 이 범위에서는 약수를 하나씩 시험하는 방법이 예산을 넘는 모습을 수치로 볼 수
  있습니다. 비용은 흔한 채점 환경의 예산인 1 초(기본 연산 1 초에 1 억 번)에 대어 잽니다. 소수 판정 편 · 시행
  나눗셈 편과 같은 예산입니다.

이 글이 쓰는 기호입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `n` | 약수를 찾을 정수 | 입력. `2 ≤ n < 2^64` |
| `p` | `n` 의 소인수 하나 | 절차가 이름을 모르는 채로 쓰는 값. 논증에만 나온다 |
| `q` | `n = p × q` 로 쓸 때 다른 쪽 | 논증에만 나온다 |
| `c` | 수열 하나를 정하는 상수 | 1 에서 시작하고 실패하면 1 씩 올린다 |
| `f` | 다음 값을 만드는 함수 | `f(t) = (t² + c) mod n` |
| `x_i` | 수열의 `i` 번째 값 | `x₀ = 2`, `x_(i+1) = f(x_i)` |
| `x` · `y` | 느린 자리 · 빠른 자리 | 걸음 `k` 뒤에 `x = x_k`, `y = x_2k` |
| `k` | 한 라운드 안의 걸음 수 | 두 자리를 몇 번 나아가게 했는가 |
| `d` | 그 걸음의 최대공약수 | `gcd(\|x − y\|, n)` |
| `μ` · `λ` | ρ 모양의 꼬리와 마디의 칸 수 | 어느 법으로 읽느냐에 따라 다르다 |

비용과 메모리는 끝까지 아래 두 단위로 셉니다. 소수 판정 편 · 시행 나눗셈 편 · 최대공약수 편과 같은 단위예요.

| 단위 | 하나로 세는 것 | 세지 않는 것 |
| --- | --- | --- |
| 나머지 연산 | `%` 한 번 — 짝수 검사 `n % 2n`, 수열 한 칸 `(t * t + c) % n`, 유클리드 호제법의 `x % y`, 소수 판정 안의 `%` | 곱셈 · 덧셈 · 뺄셈 · 비교 |
| 저장 칸 | 들고 있는 값 하나 | 돌려주는 약수 |

가장 먼저 떠오르는 방법으로 시작합시다. 약수를 하나씩 시험하는 것이고, 그중 나눗셈이 가장 적은 판이 시행
나눗셈 편의 절차예요. 2 와 3 으로 나눠 본 뒤 `√n` 이하의 `6k±1` 후보로 차례로 나눠, 처음 나누어떨어지는 수를
돌려줍니다.

```ts
// 시행 나눗셈 편의 절차를 약수 찾기로 옮긴 판. 답은 맞지만 가장 작은 소인수까지 나눈다.
if (n % 2n === 0n) return 2n;
if (n % 3n === 0n) return 3n;
for (let d = 5n, step = 2n; d * d <= n; d += step, step = 6n - step) {
  if (n % d === 0n) return d;
}
return n;
```

두 소인수가 같은 자릿수이면 가장 작은 소인수가 `√n` 근처라 나눗셈이 가장 많습니다. 규모마다 그런 입력을 골라
나눗셈을 세었어요.

<!--proof:origin-trial-->

| 규모 | n | 가장 작은 소인수 | 나눗셈 | 시간(1 초에 1 억 번) |
| --- | ---: | ---: | ---: | ---: |
| 10^6 | 2,021,027 | 1,009 | 338 | 0.00 초 |
| 10^12 | 1,001,006,003,009 | 1,000,003 | 333,336 | 0.00 초 |
| 10^18 | 1,000,001,018,000,007,077 | 1,000,000,007 | 333,333,337 | 3.33 초 |
| 2^64 | 18,446,744,030,759,878,681 | 4,294,967,291 | 1,431,655,765 | 14.32 초 |

나눗셈 횟수는 시행 나눗셈 편의 닫힌 형태 2 + C(p) 로 셌고, 그 편의 세는 판을 실제로 실행한 위 2 줄에서 두 값이 어긋난 줄은 0 개입니다.

<!--/proof-->

**`2^64` 근방에서 14 초가 넘습니다.** `10^18` 에서도 예산의 세 배가 넘어요. 약수를 하나씩 시험하는 한 가장 작은
소인수 `p` 까지 가야 합니다. 그러면 `p` 를 시험하지 않고 `p` 를 얻는 길이 있을까요. 최대공약수가 그 길입니다.
두 수 `a` · `b` 가 `p` 로 나눈 나머지가 같으면 `a − b` 는 `p` 의 배수라, `gcd(|a − b|, n)` 이 `p` 의 배수가 돼요.
`p` 의 이름을 몰라도 됩니다. 필요한 것은 **`p` 로 나눈 나머지가 같은 두 수**입니다.

첫 후보는 그런 두 수를 무작정 모으는 것입니다. 수열 값을 한 칸씩 늘리며, 새 값과 앞의 모든 값의 차를 `n` 과
최대공약수로 봐요. 8,051 에서 실행하면 이렇습니다.

<!--proof:origin-pairs-walk-->

| 새 값 | 앞 값 | 차 | 8,051 과의 최대공약수 |
| --- | --- | ---: | ---: |
| x₁ = 5 | x₀ = 2 | 3 | 1 |
| x₂ = 26 | x₀ = 2 | 24 | 1 |
| x₂ = 26 | x₁ = 5 | 21 | 1 |
| x₃ = 677 | x₀ = 2 | 675 | 1 |
| x₃ = 677 | x₁ = 5 | 672 | 1 |
| x₃ = 677 | x₂ = 26 | 651 | 1 |
| x₄ = 7,474 | x₀ = 2 | 7,472 | 1 |
| x₄ = 7,474 | x₁ = 5 | 7,469 | 97 |

값 5 개를 모으는 동안 쌍 8 개를 봤고, 마지막 쌍에서 97 이 나왔습니다.

<!--/proof-->

쌍 여덟 개째에서 `x₄ − x₁ = 7,469` 가 97 의 배수라 97 이 나옵니다. 모은 값은 다섯 개뿐이에요. 법 97 에서는 값이
놓일 자리가 97 개라 값을 몇 개만 모아도 같은 나머지가 생깁니다. 문제는 쌍의 수입니다. 값이 `v` 개면 쌍이 `v²/2`
개 가까이 되니, 규모를 올려 시행 나눗셈과 나란히 세었어요.

<!--proof:origin-pairs-->

| n | 모은 값 | 본 쌍 | 쌍마다 본 판의 나머지 연산 | 시행 나눗셈 |
| ---: | ---: | ---: | ---: | ---: |
| 8,051 | 5 | 8 | 62 | 29 |
| 10,403 | 18 | 140 | 1,201 | 35 |
| 2,021,027 | 50 | 1,177 | 15,759 | 338 |
| 110,107,021 | 45 | 986 | 16,558 | 3,337 |
| 10,101,203,027 | 446 | 99,196 | 2,047,353 | 33,336 |

마지막 줄에서 쌍마다 본 판은 시행 나눗셈의 61.4 배를 씁니다. 나머지 연산은 수열 한 칸에 한 번, 최대공약수의 나머지마다 한 번으로 셌습니다.

<!--/proof-->

**모은 값은 적은데 쌍이 너무 많습니다.** 두 소인수가 `10^5` 근방인 마지막 줄에서 값은 446 개이고, 쌍은 99,196
개예요. 값의 수를 줄인 만큼 쌍의 수가 그 제곱으로 늘어 시행 나눗셈보다 많이 씁니다. 볼 쌍을 줄여야 해요. 줄일
실마리가 수열에 있습니다. 수열의 다음 값은 앞 값 하나로만 정해지므로, 두 칸이 법 97 에서 한 번 같으면 그 다음
칸끼리도 같아요. 8,051 의 수열에서 간격이 같은 쌍을 이어서 봤습니다.

<!--proof:origin-persist-->

| 두 칸 | 두 값 | 97 로 나눈 나머지 | 차 | 8,051 과의 최대공약수 |
| --- | --- | --- | ---: | ---: |
| x₁ · x₄ | 5 · 7,474 | 5 · 5 | 7,469 | 97 |
| x₂ · x₅ | 26 · 2,839 | 26 · 26 | 2,813 | 97 |
| x₃ · x₆ | 677 · 871 | 95 · 95 | 194 | 97 |

3 쌍 모두 두 칸의 간격이 3 칸이고, 최대공약수가 97 입니다.

<!--/proof-->

**간격 3 칸인 쌍이 세 번 다 97 을 냅니다.** 법 97 에서 한 번 겹친 수열은 그 뒤로 간격 3 칸마다 계속 겹쳐요.
그러니 모든 쌍을 볼 필요가 없고, 간격이 걸음마다 한 칸씩 늘어나는 쌍 하나만 봐도 간격이 3 의 배수가 되는 걸음에서
겹침을 만납니다. 느린 자리를 `x_k`, 빠른 자리를 `x_2k` 에 두면 둘의 간격이 `k` 라 걸음마다 한 칸씩 늘어요. 같은
입력을 두 방식으로 처리해 나란히 세었습니다.

<!--proof:origin-two-ways-->

| n | 쌍마다 — 본 쌍 | 쌍마다 — 나머지 연산 | 두 걸음 차이 — 걸음 | 두 걸음 차이 — 나머지 연산 |
| ---: | ---: | ---: | ---: | ---: |
| 8,051 | 8 | 62 | 3 | 29 |
| 10,403 | 140 | 1,201 | 9 | 100 |
| 2,021,027 | 1,177 | 15,759 | 45 | 729 |
| 110,107,021 | 986 | 16,558 | 40 | 792 |
| 10,101,203,027 | 99,196 | 2,047,353 | 440 | 10,471 |

두 판 모두 짝수 검사와 소수 판정을 빼고 셌습니다. 마지막 줄에서 두 걸음 차이만 보는 판의 나머지 연산은 쌍마다 보는 판의 195.5 분의 1 입니다.

<!--/proof-->

**두 걸음 차이만 보는 판이 쌍마다 보는 판보다 모든 줄에서 적습니다.** 걸음마다 수열 칸 셋과 최대공약수 하나를
쓰고, 걸음 수가 쌍마다 보는 판의 모은 값 수와 같은 자릿수예요. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **두 걸음 차이의 최대공약수**입니다. 수열 하나를 법 `n` 위에서 만들되, 느린 자리와 빠른 자리의 차와
`n` 의 최대공약수를 걸음마다 봐서, 법 `p` 에서 먼저 일어나는 되풀이를 `p` 를 모르는 채로 알아채는 방법이에요. 이
절차를 폴라드 로라고 부릅니다. 수열이 법 `p` 에서 어떤 모양으로 되풀이되는지, 두 자리가 언제 만나는지, 최대공약수가
`n` 자신이 나오면 어떻게 하는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 두 걸음 차이의 최대공약수

이 아이디어를 한 문장으로 줄이면 이렇습니다. **짝수와 소수를 먼저 거른 뒤 상수 `c` 로 수열 하나를 정하고,
느린 자리와 빠른 자리를 한 칸 · 두 칸씩 나아가게 하며, 둘의 차와 `n` 의 최대공약수가 1 이 아니게 되는 걸음에서
멈춥니다.** 미리 만들어 두는 표가 없어서 네 단계 모두 수 하나를 받을 때마다 해요.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 짝수와 소수 거르기 | 짝수에 2 를, 소수에 `n` 자신을 돌려준다 | — |
| 2단계 수열 하나 정하기 | 상수 `c` 로 `f` 를 정하고 두 자리를 `x₀ = 2` 에 둔다 | 1단계를 지난 `n`(홀 합성수) |
| 3단계 두 속도로 나아가기 | 걸음마다 `x` 를 한 칸, `y` 를 두 칸 옮긴다 | 2단계의 `f` 와 시작값 |
| 4단계 차의 최대공약수로 알아채기 | `d = gcd(\|x − y\|, n)` 이 1 이 아니면 멈추고, `n` 이면 `c` 를 올린다 | 3단계의 `x` · `y` |

#### 먼저 알아 둘 개념 — ρ 모양

이 아이디어의 한 문장이 기대는 이름은 **ρ 모양**입니다. 두 자리가 왜 언젠가 만나는지도, 몇 걸음 뒤에 만나는지도
수열이 한 법에서 어떤 모양으로 되풀이되는지에서 나와요.

##### 쉬운 말 정의

ρ 모양은 **수열을 한 법으로 읽었을 때, 한 번만 지나가는 앞부분(꼬리) 뒤에 같은 값들이 같은 차례로 되풀이되는
고리(마디)가 붙은 모양**입니다. 꼬리의 칸 수를 `μ`, 마디의 칸 수를 `λ` 로 적어요. 칸 `i` 가 `μ` 이상이면 `x_i` 와
`x_(i+λ)` 가 그 법에서 같습니다.

##### 전개 입력 위의 모양

전개 입력 8,051 의 두 소인수 97 과 83 으로 같은 수열을 읽으면 이렇게 생겼습니다. 정점 아래 줄은 그 값이 나오는
자리 가운데 `x₆` 까지입니다.

<!--fig:build-rho-->
![8,051 의 두 소인수로 읽은 수열 — 법 97 과 법 83 의 ρ 모양](./figs/build-rho.svg)

법 97 은 꼬리가 `x₀` 한 칸이고 마디가 `5 → 26 → 95` 세 칸이에요. 법 83 은 꼬리가 네 칸이고 마디가 다섯 칸이라,
`x₆` 까지 가도 되풀이가 아직 시작되지 않았습니다. 전개가 만드는 일곱 칸 안에서 되풀이가 일어나는 법은 97 하나예요.

##### 정점 하나를 읽는 법

법 97 의 정점 95 를 골라 이름에서 값까지 따라가 봅시다. 그 정점에 적힌 두 자리의 원래 값을 97 로 나누고, 다음
정점으로 가는 계산까지 적었어요.

<!--proof:rho-read-->

```text
값이 95 인 정점   법 97 의 마디에 있다
x₃ = 677          677 mod 97 = 95
x₆ = 871          871 mod 97 = 95
다음 정점         (95² + 1) mod 97 = 5 — 마디의 첫 칸 x₁ 의 값
```

`x₃` 과 `x₆` 은 법 8,051 에서는 다른 값인데 법 97 에서는 같은 정점에 놓입니다. 정점 95 에서 한 칸 나아가면 5 로
돌아가고, 그것이 마디의 끝에서 처음으로 가는 간선이에요.

##### 이웃 정점끼리의 관계

한 정점에서 다음 정점으로 가는 간선은 `f` 하나입니다. 그런데 법 `n` 의 값 하나는 법 `p` 의 값과 법 `q` 의 값
한 쌍으로 정해져요. 그래서 법 `n` 의 모양은 두 모양에서 나옵니다. 네 입력에서 셋의 꼬리와 마디를 재었어요.

<!--proof:rho-combine-->

| n = p × q | 법 p 의 꼬리 · 마디 | 법 q 의 꼬리 · 마디 | 두 마디의 최소공배수 | 법 n 의 마디 | 두 꼬리 중 긴 쪽 | 법 n 의 꼬리 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 8,051 = 97 × 83 | 1 · 3 | 4 · 5 | 15 | 15 | 4 | 4 |
| 111,403 = 101 × 1,103 | 8 · 9 | 31 · 2 | 18 | 18 | 31 | 31 |
| 2,021,027 = 1,009 × 2,003 | 0 · 49 | 38 · 15 | 735 | 735 | 38 | 38 |
| 110,107,021 = 10,007 × 11,003 | 39 · 5 | 93 · 54 | 270 | 270 | 93 | 93 |

4 줄 가운데 넷째 칸과 다섯째 칸이 같은 줄은 4 개, 여섯째 칸과 일곱째 칸이 같은 줄은 4 개입니다.

<!--/proof-->

**법 `n` 의 마디는 두 마디의 최소공배수이고, 꼬리는 두 꼬리 중 긴 쪽입니다.** 법 `n` 에서 되풀이되려면 법 `p`
와 법 `q` 에서 동시에 되풀이되어야 하기 때문이에요. 8,051 에서 법 `n` 의 마디가 15 칸이라 `x₁₉` 에 이르러서야
되풀이되는데, 법 97 의 마디는 세 칸이라 훨씬 먼저 되풀이됩니다.

##### 헷갈리기 쉬운 모양과의 비교

처음 보면 「값이 `m` 개뿐이니 수열이 `m` 칸을 다 돈 뒤에야 되풀이된다」고 떠올리기 쉽습니다. 한 칸씩 값을
옮기는 수열 `t + 1` 이 그런 모양이에요. 같은 법에서 `t² + 1` 과 `t + 1` 의 꼬리와 마디를 나란히 재었습니다.

<!--proof:rho-vs-ring-->

| 법 m | t² + 1 의 꼬리 | t² + 1 의 마디 | t + 1 의 꼬리 | t + 1 의 마디 |
| ---: | ---: | ---: | ---: | ---: |
| 97 | 1 | 3 | 0 | 97 |
| 83 | 4 | 5 | 0 | 83 |
| 1,009 | 0 | 49 | 0 | 1,009 |
| 10,007 | 39 | 5 | 0 | 10,007 |
| 100,003 | 496 | 74 | 0 | 100,003 |

t + 1 은 5 줄 가운데 5 줄에서 꼬리가 0 이고 마디가 m 과 같습니다. 법 100,003 에서 t² + 1 의 마디는 74 칸입니다.

<!--/proof-->

`t + 1` 은 꼬리 없이 `m` 칸짜리 고리 하나라, 되풀이까지 `m` 칸을 다 지나가야 합니다. `t² + 1` 은 법 100,003
에서도 마디가 74 칸이에요. 되풀이가 빨리 오는 것은 값이 `m` 개라서가 아니라 제곱이 값을 섞기 때문입니다.

##### 이렇게 생긴 까닭

값이 놓일 자리가 `m` 개뿐이니 `m + 1` 칸 안에 반드시 앞 값과 같은 값이 나오고, 다음 값이 앞 값 하나로만 정해지니
그 뒤로는 같은 차례가 되풀이됩니다. 꼬리가 생기는 것은 제곱이 두 값을 한 값으로 보내기 때문이에요. `t` 와 `m − t`
는 제곱이 같아서, 한 정점으로 들어오는 간선이 둘일 수 있습니다. 그래서 첫 값 `x₀` 이 마디 밖에 남을 수 있고, 마디의
길이는 `m` 보다 훨씬 짧게 끝날 수 있어요.

#### 1단계 — 짝수와 소수 거르기

수열을 만들기 전에 두 가지를 거릅니다. 짝수는 2 가 곧 답이라 수열을 만들 이유가 없고, 소수는 비자명한 약수가
없어 어떤 상수로도 답이 나오지 않아요. 소수 판정은 소수 판정 편의 밑 열둘 판정을 그대로 부릅니다. 경계 입력을
넣어 어느 자리가 답하는지 봤습니다.

<!--proof:build-pre-->

| 입력 n | 답하는 자리 | 여기까지 나머지 연산 | 정본 |
| ---: | --- | ---: | ---: |
| 4 | ① 짝수 | 1 | 2 |
| 2,000,006 | ① 짝수 | 1 | 2 |
| 97 | ② 소수 | 129 | 97 |
| 1,000,003 | ② 소수 | 361 | 1,000,003 |
| 21 | 로 루프로 내려간다 | 3 | 3 |
| 8,051 | 로 루프로 내려간다 | 36 | 97 |

6 입력 가운데 로 루프까지 내려간 것은 21 · 8,051 입니다. 소수 판정의 몫은 소수 판정 편의 기록 사본이 센 값입니다.

<!--/proof-->

이 단계를 지난 `n` 은 3 이상의 홀 합성수입니다. 그래서 `n` 은 적어도 두 소인수의 곱이고, 그중 작은 쪽 `p` 는
`√n` 이하예요. 뒤의 세 단계가 이 두 사실에 기댑니다.

#### 2단계 — 수열 하나 정하기

상수 `c` 를 정하면 `f(t) = (t² + c) mod n` 이 정해지고, 두 자리를 같은 시작값 2 에 둡니다. 여기서 확인할 것이
하나 있어요. 코드는 법 `n` 위에서만 계산하는데, 그 값을 `p` 로 나눈 나머지가 법 `p` 위에서 따로 계산한 수열과
같아야 1단계의 약속(작은 쪽 소인수 `p` 에서 먼저 되풀이된다)이 쓸모가 있습니다. 전개 입력에서 두 길을 나란히
적었어요.

<!--proof:build-two-roads-->

| 칸 | 법 8,051 에서 만든 값 | 그 값을 97 로 나눈 나머지 | 법 97 에서 바로 만든 값 |
| --- | ---: | ---: | ---: |
| x₀ | 2 | 2 | 2 |
| x₁ | 5 | 5 | 5 |
| x₂ | 26 | 26 | 26 |
| x₃ | 677 | 95 | 95 |
| x₄ | 7,474 | 5 | 5 |
| x₅ | 2,839 | 26 | 26 |
| x₆ | 871 | 95 | 95 |

7 칸 가운데 셋째 칸과 넷째 칸이 같은 칸은 7 개입니다.

<!--/proof-->

**일곱 칸 모두 같습니다.** `p` 가 `n` 을 나누므로 `n` 으로 나눈 나머지를 다시 `p` 로 나누면 `p` 로 바로 나눈
나머지와 같고, 제곱과 덧셈은 법을 바꿔도 순서를 따지지 않아요. 그래서 법 `n` 의 수열 하나 안에 법 `p` 의 수열이
통째로 들어 있습니다. 코드가 만드는 것은 법 `n` 의 수열 하나뿐이고, 법 `p` 의 수열은 논증에만 나와요.

#### 3단계 — 두 속도로 나아가기

걸음마다 느린 자리 `x` 를 `f` 에 한 번, 빠른 자리 `y` 를 `f` 에 두 번 넣습니다. `k` 걸음 뒤 `x = x_k`,
`y = x_2k` 이고 둘의 간격이 `k` 예요. 법 97 의 ρ 위에서 두 자리가 어디에 놓이는지 걸음마다 그렸습니다.

<!--fig:build-floyd-->
![법 97 의 ρ 위에서 느린 자리와 빠른 자리 — k = 3 에서 같은 정점에 놓인다](./figs/build-floyd.svg)

`k = 3` 에서 두 자리가 정점 95 에 함께 놓입니다. 두 자리가 같은 정점에 놓이려면 둘 다 마디 안이어야 하고(`k ≥ μ`),
간격 `k` 가 마디 길이 `λ` 의 배수여야 해요. 그러니 두 자리가 처음 만나는 걸음은 `max(μ, 1)` 이상인 `λ` 의 배수
가운데 가장 작은 것입니다. 여러 법에서 이 식과 실제로 처음 만난 걸음을 나란히 놓았어요.

<!--proof:build-meet-->

| 법 m | 꼬리 μ | 마디 λ | 식이 내는 첫 만남 k | 실제로 처음 같아진 k |
| ---: | ---: | ---: | ---: | ---: |
| 97 | 1 | 3 | 3 | 3 |
| 83 | 4 | 5 | 5 | 5 |
| 8,051 | 4 | 15 | 15 | 15 |
| 101 | 8 | 9 | 9 | 9 |
| 1,009 | 0 | 49 | 49 | 49 |
| 10,007 | 39 | 5 | 40 | 40 |

6 줄 가운데 넷째 칸과 다섯째 칸이 같은 줄은 6 개입니다. 식은 max(μ, 1) 이상인 λ 의 배수 가운데 가장 작은 것입니다.

<!--/proof-->

**여섯 줄 모두 식과 실행이 같습니다.** 이 식에서 걸음 수의 범위도 나와요. `λ` 의 배수는 `λ` 칸마다 오므로
`max(μ, 1)` 에서 `λ − 1` 칸 안에 하나가 있고, 첫 만남은 `μ + λ` 걸음을 넘지 않습니다. 걸음 수가 `p` 의 크기를
어떻게 따라가는지 소수 여섯에서 재었습니다.

<!--proof:build-size-->

| 소수 p | √p 를 내림한 값 | 꼬리 + 마디 | 첫 만남 k | k / √p |
| ---: | ---: | ---: | ---: | ---: |
| 101 | 10 | 17 | 9 | 0.90 |
| 1,009 | 31 | 49 | 49 | 1.58 |
| 10,007 | 100 | 44 | 40 | 0.40 |
| 100,003 | 316 | 570 | 518 | 1.64 |
| 1,000,003 | 1,000 | 1,289 | 1,276 | 1.28 |
| 10,000,019 | 3,162 | 6,422 | 6,420 | 2.03 |

6 줄 가운데 넷째 칸이 셋째 칸을 넘지 않는 줄은 6 개이고, 마지막 칸은 0.40 과 2.03 사이입니다.

<!--/proof-->

`p` 가 약 10 만 배 커지는 동안 첫 만남 걸음을 `√p` 로 나눈 값은 0.40 과 2.03 사이에 머뭅니다. 여섯 표본에서 그렇다는
것이고 모든 `p` 에 대한 주장은 아니에요. `√p` 규모가 어디서 나오는지는 파트 2 의 수식 절이 다룹니다.

#### 4단계 — 차의 최대공약수로 알아채기

걸음마다 `d = gcd(|x − y|, n)` 을 봅니다. 두 자리가 법 `p` 에서 같은 정점에 놓였으면 `|x − y|` 가 `p` 의
배수라 `d` 도 `p` 의 배수예요. 전개 입력의 세 걸음을 두 소인수로 나눈 나머지와 함께 적었습니다.

<!--proof:build-gcd-->

| 걸음 k | x | y | x · y 를 97 로 나눈 나머지 | x · y 를 83 으로 나눈 나머지 | d |
| ---: | ---: | ---: | --- | --- | ---: |
| 1 | 5 | 26 | 5 · 26 | 5 · 26 | 1 |
| 2 | 26 | 7,474 | 26 · 5 | 26 · 4 | 1 |
| 3 | 677 | 871 | 95 · 95 | 13 · 41 | 97 |

3 걸음에서 97 로 나눈 나머지만 같아지고, 그 걸음의 d 가 97 입니다.

<!--/proof-->

`d` 는 세 가지 값을 가집니다. 1 이면 어느 소인수에서도 아직 안 만났으니 한 걸음 더 가요. 1 도 `n` 도 아니면
비자명한 약수라 돌려줍니다. `n` 이면 모든 소인수에서 같은 걸음에 만났다는 뜻이라 이 수열로는 약수를 가를 수
없어요. 그때는 상수를 올려 다른 수열로 다시 시작합니다. 세 번째 경우가 25 에서 일어나요.

<!--proof:build-gcd-n-->

| 상수 c | 걸음 k | x | y | \|x − y\| | d |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 5 | 1 | 4 | 1 |
| 1 | 2 | 1 | 5 | 4 | 1 |
| 1 | 3 | 2 | 2 | 0 | 25 |
| 2 | 1 | 6 | 13 | 7 | 1 |
| 2 | 2 | 13 | 18 | 5 | 5 |

n = 25 에서 c = 1 은 3 걸음에서 d 가 25 가 되어 약수를 못 내고, 정본은 c 를 올려 5 를 돌려줍니다.

<!--/proof-->

`c = 1` 의 셋째 걸음에서 두 자리가 법 25 에서 같은 값 2 가 되어 차가 0 이고, `gcd(0, 25) = 25` 입니다. 상수를
2 로 올리면 수열이 통째로 바뀌어, 둘째 걸음에서 5 가 나와요.

#### 이 방법이 기대는 전제

폴라드 로는 아래 세 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| `f` 가 덧셈과 곱셈만으로 된 식이다 | 2단계 — 법 `n` 의 수열 안에 법 `p` 의 수열이 들어 있다 | 법 `p` 의 되풀이가 법 `n` 의 계산에 안 나타난다 |
| `n` 이 합성수다 | 4단계 — 1 도 `n` 도 아닌 `d` 가 있을 수 있다 | `d` 가 1 과 `n` 만 오가 끝나지 않는다 |
| `t * t` 를 오차 없이 담는다 | 2단계의 `f` | 수열이 법 `n` 의 수열이 아니게 되어 되풀이의 약속이 깨진다 |

둘째 전제가 1단계에서 소수를 거르는 까닭이고, 그것을 빼면 무엇이 되는지는 「수행으로 알아보는 알고리즘」의 짚고
가기가 실행으로 보입니다. 셋째 전제의 크기를 재었어요.

<!--proof:premise-bigint-->

| 값 | 크기 |
| --- | ---: |
| number 가 정수를 오차 없이 담는 한계 2^53 | 9,007,199,254,740,992 |
| 과제의 상한 2^64 | 18,446,744,073,709,551,616 |
| 2^64 아래에서 가장 큰 제곱 입력 n | 18,446,744,030,759,878,681 |
| 그 n 에서 t * t 가 될 수 있는 가장 큰 값 (n − 1)² | 340,282,365,336,375,215,908,205,976,408,318,542,400 |
| 전개 입력 8,051 의 걸음이 만든 가장 큰 t * t | 55,860,676 |

넷째 줄은 이진수로 128 자리이고, 정본은 모든 값을 bigint 로 계산합니다.

<!--/proof-->

`n` 이 `2^64` 근방이면 `t * t` 가 128 비트까지 자라 `number` 로는 담을 수 없습니다. 정본은 처음부터 끝까지
`bigint` 로 계산해요. 전개 입력은 곱이 `2^53` 안쪽이라 작은 입력으로 시험하면 이 차이가 안 보입니다.

#### 속도 비를 1 대 2 로 둔 까닭

느린 자리 한 칸에 빠른 자리 두 칸이 꼭 필요한지 시험해 봅시다. 비를 1 대 1 · 2 · 3 · 4 로 놓고 같은 입력 여섯을
실행해 걸음과 나머지 연산을 세었어요.

<!--proof:speed-ratio-->

| 속도 비 | 약수를 못 낸 입력 | 걸음 합 | 수열 칸 합 | 최대공약수의 나머지 연산 합 | 나머지 연산 합 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 대 1 | 6 | 6 | 12 | 6 | 18 |
| 1 대 2 | 0 | 1,813 | 5,439 | 41,953 | 47,392 |
| 1 대 3 | 0 | 1,733 | 6,932 | 39,632 | 46,564 |
| 1 대 4 | 0 | 1,806 | 9,030 | 42,118 | 51,148 |

입력 6 개에 상수 c = 1 하나로 잰 값입니다. 수열 칸 합이 가장 적은 비는 1 대 2, 나머지 연산 합이 가장 적은 비는 1 대 3 이고, 두 비의 나머지 연산 합 차이는 1 대 2 의 1.7 % 입니다.

<!--/proof-->

1 대 1 은 여섯 입력 모두 약수를 못 냅니다. 두 자리가 언제나 같은 칸이라 차가 0 이고 `gcd(0, n) = n` 이기
때문이에요. 1 대 2 · 3 · 4 는 모두 답을 내고, 나머지 연산 합의 차이는 10 % 안쪽입니다. 수열 칸만 세면 1 대 2 가
가장 적지만, 최대공약수까지 세면 1 대 3 이 1.7 % 적어요. 걸음마다 최대공약수가 수열 칸보다 많은 나머지 연산을
쓰기 때문입니다. 비용으로는 어느 비도 뚜렷이 적지 않으니, 이 글은 **간격이 걸음마다 정확히 한 칸씩 늘어** 첫
만남 걸음이 3단계의 식 하나로 정해지는 1 대 2 를 씁니다.

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 이렇습니다.

1. `n` 이 짝수이면 2 를 돌려준다
2. `n` 이 소수이면 `n` 을 돌려준다
3. `c = 1` 부터 상수 하나를 골라 `f(t) = (t² + c) mod n` 을 정하고, `x = y = 2`, `d = 1` 로 둔다
4. `d = 1` 인 동안 `x ← f(x)`, `y ← f(f(y))`, `d ← gcd(|x − y|, n)` 을 되풀이한다
5. `d ≠ n` 이면 `d` 를 돌려주고, `d = n` 이면 `c` 를 1 올려 3 으로 간다

### 수행으로 알아보는 알고리즘 — 8,051 에서 97 을 찾는다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 8051n;
// 이 절이 끝나면 97n 이 나와야 한다
```

왜 하필 8,051 일까요? `8,051 = 83 × 97` 이라 두 소인수가 밑 목록 열둘보다 커서 소수 판정까지 내려가고, **첫
상수 `c = 1` 로 세 걸음 만에 답이 나와** 손으로 따라갈 수 있기 때문입니다. 그리고 세 걸음 안에서 되풀이가 97
하나에서만 일어나, 법 `p` 에서 먼저 겹친다는 것이 값으로 확인돼요.

```text
pollardRho(n):
    n 이 짝수이면 2                                 ① 짝수를 거른다
    n 이 소수이면 n                                 ② 비자명한 약수가 없는 입력을 거른다
    c ← 1 부터 하나씩:
        f(t) = (t² + c) mod n                       ③ 상수 하나가 수열 하나를 정한다
        x ← 2,  y ← 2,  d ← 1                       ④ d 는 계산이 아니라 초기화다
        d 가 1 인 동안 되풀이:
            x ← f(x),  y ← f(f(y))                  ⑤ 한 칸과 두 칸
            d ← gcd(|x − y|, n)                     ⑥ 차와 n 의 최대공약수
        d 가 n 이 아니면 d 를 돌려준다              ⑦ 비자명한 약수를 찾았다
        아니면 c 를 올려 다시                       ⑧ 이 상수로는 못 찾는다
```

#### 1. 짝수와 소수를 먼저 가른다

앞에 사전 판정 둘을 둡니다. 이 둘이 있어야 뒤의 수열이 홀 합성수만 다룬다고 가정할 수 있어요.

```ts
if (n % 2n === 0n) return 2n; // ① 짝수를 거른다
if (isPrime(n)) return n; // ② 비자명한 약수가 없는 입력을 거른다
```

이 조각만 전개 입력에 실행하면 두 갈래가 하나도 답을 돌려주지 않습니다.

<!--proof:walk-pre-->

```text
T1   n = 8,051   ① 의 n % 2n 이 1 이라 거짓이다. 나머지 연산 1 번
T2   n = 8,051   ② 의 소수 판정이 합성수라고 답한다. 나머지 연산 35 번
```

T2 를 지났다는 것은 8,051 이 홀수이고 비자명한 약수가 있다는 뜻입니다. `②` 의 판정이 쓴 나머지 연산은 소수 판정
편의 기록 사본이 센 값이에요.

#### 짚고 가기 — 소수 판정을 빼도 될 것 같다

`②` 가 군더더기로 보이는 자리입니다. 소수를 넣으면 어차피 비자명한 약수가 없으니 수열이 알아서 아무것도 못
찾고 끝날 것 같아요. 그 생각대로 그 줄을 지워 봅시다.

```ts
if (isPrime(n)) return n; // ← 이 줄을 지웠다
```

**먼저 확인해 둘 것이 있습니다 — 합성수 입력에서는 실제로 답이 안 바뀝니다.**

<!--proof:mutant-no-prime-guard-->

| 입력 | 소인수 | 정본 | 소수 판정을 뺀 판 | 두 답 |
| ---: | --- | ---: | ---: | --- |
| 8,051 | 83 × 97 | 97 | 97 | 같다 |
| 21 | 3 × 7 | 3 | 3 | 같다 |
| 25 | 5 × 5 | 5 | 5 | 같다 |
| 63 | 3 × 3 × 7 | 21 | 21 | 같다 |
| 10,403 | 101 × 103 | 101 | 101 | 같다 |

다섯 줄 다 합성수이고, 두 답이 어긋난 줄은 0 개입니다.

<!--/proof-->

다섯 줄 다 같은 값이니 이 줄이 막는 것은 합성수 쪽이 아니에요. 소수를 넣어 보면 무엇이 달라지는지 나옵니다.
다만 그 판은 끝나지 않으므로 상수 `c` 를 몇 번까지 올릴지 한도를 두고 실행했어요.

<!--proof:pause-prime-loops-->

| 입력 | 정의대로 | 정본 | 소수 판정을 뺀 판 | 그때까지의 걸음 |
| ---: | --- | ---: | --- | ---: |
| 97 | 소수 | 97 | c = 30 까지 답이 없다 | 273 |
| 8,053 | 소수 | 8,053 | c = 30 까지 답이 없다 | 2,649 |
| 1,000,003 | 소수 | 1,000,003 | c = 30 까지 답이 없다 | 30,187 |

소수 판정을 뺀 판은 c 를 30 까지 올리고 멈추게 한도를 둔 사본으로 잰 값입니다.

<!--/proof-->

**소수에서는 어떤 상수로도 답이 나오지 않습니다.** `n` 이 소수이면 `gcd(|x − y|, n)` 이 가질 수 있는 값이 1 과 `n`
둘뿐이라, 1 이면 루프가 이어지고 `n` 이면 상수가 올라가요. 비자명한 약수라는 세 번째 값이 없으니 `c` 가 끝없이
올라갑니다. 그래서 테스트를 합성수로만 짜면 이 줄을 지워도 모든 시험이 통과하는데, 소수 하나가 들어오는 순간 절차가
멈추지 않아요.

#### 2. 수열 하나를 두 속도로 진행시킨다

상수 `c` 를 정하면 `f` 가 정해지고, 그 `f` 로 두 자리를 서로 다른 속도로 나아가게 합니다. `d` 는 계산하지 않고 1
로 둬요. 시작값이 같아 `|x − y| = 0` 이고 `gcd(0, n) = n` 이라, 계산해 넣으면 루프 조건이 처음부터 거짓이 되기
때문입니다.

```ts
const f = (t: bigint): bigint => (t * t + c) % n; // ③ 상수 하나가 수열 하나를 정한다
let x = 2n;
let y = 2n;
let d = 1n; // ④ 계산이 아니라 초기화다

x = f(x); // ⑤ 느린 자리는 한 칸
y = f(f(y)); //    빠른 자리는 두 칸
```

전개 입력에서 첫 걸음까지 실행하면 이렇게 나옵니다.

<!--proof:walk-seq-->

```text
T3   c = 1    f(t) = (t² + 1) mod 8,051 · x = y = 2 · d = 1
T4   1 걸음   x ← f(2) = 5
              y ← f(f(2)) = f(5) = 26
              |x − y| = 21 · gcd(21, 8,051) = 1
```

`f(f(y))` 를 한 번에 적는 것이 「두 칸」의 전부입니다. 빠른 자리가 지나간 `x₁ = 5` 는 따로 두지 않고 버려요. 다음
걸음에 느린 자리가 같은 값을 다시 계산하므로 저장할 필요가 없습니다.

#### 3. 차의 최대공약수가 약수를 낸다

두 자리를 나아가게 했으면 그 차와 `n` 의 최대공약수를 봅니다. 이 한 줄이 「법 `p` 에서 같은 정점에 놓였는가」를
`p` 를 모르는 채로 판정하는 자리예요.

```ts
d = gcd(x > y ? x - y : y - x, n); // ⑥ 차와 n 의 최대공약수
```

두 걸음을 더 실행하면 답이 나옵니다.

<!--proof:walk-gcd-->

```text
T5   2 걸음   x ← f(5) = 26
              y ← f(f(26)) = f(677) = 7,474
              |x − y| = 7,448 · gcd(7,448, 8,051) = 1
T6   3 걸음   x ← f(26) = 677
              y ← f(f(7,474)) = f(2,839) = 871
              |x − y| = 194 · gcd(194, 8,051) = 97
```

`x > y` 를 보는 삼항 연산은 절댓값을 취하는 것입니다. 정본의 `gcd` 는 음이 아닌 두 수를 받는다고 적혀 있는데
`bigint` 뺄셈은 음수를 그대로 내요. 그 삼항 연산을 빼면 무엇이 나오는지 실행해 봤습니다.

```ts
d = gcd(x - y, n); // ← 절댓값을 안 취하면?
```

<!--proof:mutant-no-abs-->

| 입력 | 정본 | 절댓값을 안 취한 판 | 뺀 판의 값 | 두 답 |
| ---: | ---: | ---: | --- | --- |
| 9 | 3 | -3 | 약수가 아니다 | 어긋난다 |
| 8,051 | 97 | -1 | 약수가 아니다 | 어긋난다 |
| 10,403 | 101 | -101 | 약수가 아니다 | 어긋난다 |
| 63 | 21 | -21 | 약수가 아니다 | 어긋난다 |
| 325 | 25 | -1 | 약수가 아니다 | 어긋난다 |
| 1,000,036,000,099 | 1,000,033 | -1 | 약수가 아니다 | 어긋난다 |

셋째 칸이 음수인 줄은 6 줄 가운데 6 개입니다.

<!--/proof-->

**셋째 칸이 줄마다 음수입니다.** 유클리드 호제법의 `x % y` 는 나머지의 부호를 나누어지는 수에서 가져오므로,
음수로 시작하면 결과의 부호가 따라옵니다. `-1` 이나 `-101` 은 계약이 요구하는 `1 < d` 를 만족하지 못해요. 9 의
줄은 크기가 3 이라 정본과 절댓값이 같지만 부호가 틀립니다.

#### 짚고 가기 — 나온 약수가 소수일 것 같다

`gcd` 가 낸 값이 소인수처럼 보이는 자리입니다. 전개 입력에서 97 이 나왔고 그것이 소수라 「이 절차는 소인수를
준다」로 읽기 쉬워요. 그 생각대로라면 63 에서도 3 이나 7 이 나와야 합니다.

```ts
const d = pollardRho(63n); // 63 = 3 × 3 × 7 이면 무엇이 나올까?
```

<!--proof:pause-composite-divisor-->

| 입력 | n 의 소인수 | 돌려준 값 d | d 의 소인수 | n ÷ d |
| ---: | --- | ---: | --- | ---: |
| 63 | 3 × 3 × 7 | 21 | 3 × 7 | 3 |
| 105 | 3 × 5 × 7 | 21 | 3 × 7 | 5 |
| 325 | 5 × 5 × 13 | 25 | 5 × 5 | 13 |
| 8,051 | 83 × 97 | 97 | 소수 | 83 |
| 10,403 | 101 × 103 | 101 | 소수 | 103 |

다섯 줄 모두 n 을 d 로 나눈 나머지가 0 이고, d 가 소수가 아닌 줄은 63 · 105 · 325 의 줄입니다.

<!--/proof-->

**63 과 105 에서 21 이, 325 에서 25 가 나옵니다.** 셋 다 소수가 아니에요. `63 = 3 × 3 × 7` 에서 법 3 과 법 7 의
되풀이가 같은 걸음에 일어나면 `|x − y|` 가 3 과 7 을 함께 가지고, 그때 최대공약수가 21 입니다. 계약이 요구하는
것은 「`n` 을 나누고 1 도 `n` 도 아니다」 하나라 21 도 맞는 답이에요. 소인수 전부가 필요하면 얻은 `d` 와 `n / d`
에 같은 절차를 다시 적용합니다.

#### 4. 8,051 을 처음부터 끝까지 실행한다

조각을 이어 전개 입력에 실행하면 일곱 걸음이 나옵니다. 무대의 윗줄이 법 8,051 의 수열이고, 괄호가 지금까지 만든
칸, ▲ 가 느린 자리 `x`(칸 `k`)와 빠른 자리 `y`(칸 `2k`)예요. 그 아래 두 줄은 같은 칸을 97 과 83 으로 나눈

#### 5. 전체 코드

지금까지의 조각을 한 벌로 모읍니다. 새로 들어간 것은 `gcd` 와 `modPow` 와 `isPrime` 셋이에요. 조각에서는
이름만 쓰고 지나갔는데, 여기서는 그 함수들의 본문까지 함께 싣습니다. 그리고 조각이 리터럴로 적었던 시작값 `2n`
과 첫 상수 `1n` 이 여기서는 이름 붙은 상수 `X0` 과 `C0` 입니다. 무작위가 어디에도 없어서 같은 입력에서 언제나
같은 값이 나와요.

```ts
/** 결정론적 소수 판정에 쓰는 밑 열둘 — 처음 열두 소수다. */
const BASES = [2n, 3n, 5n, 7n, 11n, 13n, 17n, 19n, 23n, 29n, 31n, 37n];

/** 수열의 시작값. 이 값과 `C0` 이 이 절차의 씨앗 전부다. */
const X0 = 2n;

/** 첫 상수. 이 상수로 못 찾으면 1 씩 올려 다른 수열을 만든다. */
const C0 = 1n;

/** 유클리드 호제법. 두 인자는 음이 아니고 `b` 는 `n` 이라 언제나 양수다. */
function gcd(a: bigint, b: bigint): bigint {
  let x = a;
  let y = b;
  while (y !== 0n) {
    const t = x % y;
    x = y;
    y = t;
  }
  return x;
}

/** `base` 의 `exp` 제곱을 법 `mod` 에서 구한다 — `fastPower` 편의 절차를 그대로 쓴다. */
function modPow(base: bigint, exp: bigint, mod: bigint): bigint {
  let result = 1n % mod;
  let b = base % mod;
  let e = exp;
  while (e > 0n) {
    if ((e & 1n) === 1n) result = (result * b) % mod;
    b = (b * b) % mod;
    e >>= 1n;
  }
  return result;
}

/** 밑 열둘을 고정한 밀러-라빈 판정 — `millerRabin` 편의 절차를 부품으로 그대로 쓴다. */
function isPrime(n: bigint): boolean {
  if (n < 2n) return false;
  for (const a of BASES) {
    if (n === a) return true;
    if (n % a === 0n) return false;
  }
  let d = n - 1n;
  let s = 0;
  while ((d & 1n) === 0n) {
    d >>= 1n;
    s += 1;
  }
  for (const a of BASES) {
    let x = modPow(a, d, n);
    if (x === 1n || x === n - 1n) continue;
    let witness = true;
    for (let i = 1; i < s; i++) {
      x = (x * x) % n;
      if (x === n - 1n) {
        witness = false;
        break;
      }
    }
    if (witness) return false;
  }
  return true;
}

export function pollardRho(n: bigint): bigint {
  // ① 짝수는 2 가 곧 답이다. 아래 수열은 홀수만 다룬다.
  if (n % 2n === 0n) return 2n;

  // ② 소수에는 비자명한 약수가 없다. 이 줄이 없으면 소수 입력에서 절차가 끝나지 않는다.
  if (isPrime(n)) return n;

  for (let c = C0; ; c += 1n) {
    // ③ 상수 c 하나가 수열 하나를 정한다. 두 자리를 같은 값에서 출발시킨다.
    const f = (t: bigint): bigint => (t * t + c) % n;
    let x = X0;
    let y = X0;
    // ④ 계산이 아니라 의도적인 초기화다. gcd(0, n) 이 n 이라 계산해 넣으면 루프 조건이
    //    처음부터 거짓이 된다.
    let d = 1n;

    while (d === 1n) {
      // ⑤ 느린 자리는 한 걸음, 빠른 자리는 두 걸음 나아간다.
      x = f(x);
      y = f(f(y));
      // ⑥ 두 자리의 차와 n 의 최대공약수. mod p 에서 겹치면 여기서 p 의 배수가 나온다.
      d = gcd(x > y ? x - y : y - x, n);
    }

    // ⑦ 1 도 n 도 아니면 비자명한 약수다.
    if (d !== n) return d;

    // ⑧ d = n 이면 이 c 로는 못 찾는다. 다음 c 가 다른 수열을 만든다.
  }
}
```

### 알아 두면 좋은 개념 — 사이클 탐지 (플로이드)

전개에서 두 자리를 1 대 2 로 나아가게 한 것은 이 편만의 장치가 아닙니다. **한 값에서 시작해 같은 함수를 되풀이
적용한 수열이 언제 되풀이되는지**를 지나온 값을 저장하지 않고 찾는 방법에 이름이 붙어 있어요. 플로이드의 사이클
탐지이고, 흔히 「거북이와 토끼」라고 부릅니다. 본문의 어느 값이 그것이었는지 법 97 위에서 다시 짚었어요.

<!--proof:related-floyd-->

| 걸음 k | 느린 자리 x | 빠른 자리 y | 두 값 |
| ---: | --- | --- | --- |
| 0 | x₀ = 2 | x₀ = 2 | 출발 |
| 1 | x₁ = 5 | x₂ = 26 | 다르다 |
| 2 | x₂ = 26 | x₄ = 5 | 다르다 |
| 3 | x₃ = 95 | x₆ = 95 | 같다 |

법 97 위의 수열입니다. 걸음 3 에서 두 값이 처음 같아지고, 그때까지 들고 있던 값은 x 와 y 둘뿐입니다.

<!--/proof-->

3단계의 첫 만남 식이 이 방법의 핵심입니다. 두 자리가 마디 안에 들어온 뒤 간격이 마디 길이의 배수가 되는 걸음에서
같은 값이 되고, 그 걸음은 꼬리와 마디를 더한 칸 수를 넘지 않아요. 같은 방법을 다시 만나는 자리가 둘 있습니다.
연결 리스트에 고리가 있는지 판정할 때 두 포인터를 1 대 2 로 나아가게 하고, `1..n` 범위의 값 `n + 1` 개에서 중복
하나를 찾을 때 배열을 함수로 보아 같은 방법을 씁니다. 둘 다 저장 없이 되풀이를 찾는다는 점이 같아요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 은 두 걸음 차이의 최대공약수로 법 `p` 의 되풀이를 알아채는 절차를 세워 코드까지 만들었습니다. 여기서는
그 절차를 언제 고르는지, 걸음 수를 식으로 어떻게 닫는지, 반환값이 무엇을 보장하는지, 나머지 연산이 몇 번인지를
따집니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 인수분해할 수가 크고 개수는 적다 | 시행 나눗셈은 가장 작은 소인수 `p` 를 따라가지만 이 절차는 `√p` 규모를 따라간다 | 두 자리의 차 하나만 걸음마다 본다 |
| 약수 하나면 된다 | 소인수 전부가 아니라 비자명한 약수 하나를 낸다 | `d` 가 1 이 아니게 되는 첫 걸음에서 돌려준다 |
| 미리 만들어 둘 표가 없다 | 체처럼 `n` 에 비례하는 칸을 만들지 않는다 | 들고 있는 것이 `c` · `x` · `y` · `d` 넷이다 |
| 최악을 보장할 필요가 없다 | 걸음 수의 상한을 닫아 주는 정리가 없다 | 루프가 `d` 가 바뀔 때까지 이어진다 |

넷째 줄이 이 절차의 경계입니다. 기대되는 걸음 수는 `n^(1/4)` 규모인데, 그것은 수열이 값을 고르게 뽑는다고 볼
때의 값이고 어떤 `n` 에서도 그 안에 끝난다는 보장이 아니에요. 이 절차의 자리가 아닌 문제는 이렇습니다.

| 하는 일 | 이 절차가 맞지 않는 까닭 | 가는 곳 |
| --- | --- | --- |
| `10^6` 아래 수를 여러 개 인수분해한다 | 수마다 수열을 새로 만든다 | 체로 최소 소인수 표를 만든다 |
| `n` 이 소수인지만 알면 된다 | 이 절차는 그 판정을 부품으로 쓴다 | 밀러-라빈 판정 |
| 최악 실행 시간을 계약으로 걸어야 한다 | 상한을 닫아 주는 정리가 없다 | 결정론적 상한이 있는 다른 방법 |
| 수백 자리 수를 인수분해한다 | `√p` 규모 자체가 너무 크다 | 타원곡선법이나 수체 체 |

#### 문제에서 이것을 떠올리게 하는 단서

지문에 아래 말이 보이면 이 절차를 떠올립니다.

| 지문의 말 | 떠올릴 것 |
| --- | --- |
| 「`n` 을 소인수분해하라」 + `n` 의 상한이 `10^18` 이나 `2^64` | 시행 나눗셈으로는 예산을 넘는다 |
| 「약수를 하나만 찾아라」 | 이 절차의 계약과 같다 |
| 「`n = p × q` 이고 `p` 와 `q` 는 소수」 | 두 소인수가 비슷한 크기면 시행 나눗셈이 가장 불리하다 |
| 「소인수의 개수나 합을 구하라」 + 큰 `n` | 인수분해가 먼저 필요하다 |

반대로 아래 말이 보이면 다른 절차로 갑니다.

| 지문의 말 | 가는 곳 |
| --- | --- |
| 「1 부터 `10^6` 까지 각 수의 소인수」 | 체가 최소 소인수 표를 한 번에 만든다 |
| 「`n` 이 소수인지 판정하라」 | 소수 판정 하나로 끝난다 |
| 「`n` 이 `2^128` 아래다」 | 이 글이 확인한 규모 밖이다 |

#### 실제로 쓰이는 곳

- **GNU coreutils 의 `factor`** — 인수분해 명령의 본체가 이 절차입니다. 소스에 `factor_using_pollard_rho` 라는
  함수가 있고 그 위 주석이
  *"Insert into FACTORS the result of factoring N, using Pollard-rho with starting value A.  N must be odd."*
  로 **홀수만 받는다**는 것까지 이 글과 같게 적혀 있어요. 파일 머리의 알고리즘 설명은
  *"(3) Factor any remaining composite part using Pollard-Brent rho."* 라고 적어 이 절차가 마지막 단계임을
  밝힙니다 ([소스](https://github.com/coreutils/coreutils/blob/master/src/factor.c), 조회일 2026-09-05).
- **SymPy** — `sympy.ntheory.factor_` 의 `pollard_rho` 가
  *"Use Pollard's rho method to try to extract a nontrivial factor of ``n``. The returned factor may be a composite number."*
  라고 적습니다. **돌려주는 값이 합성수일 수 있다**는 것을 문서가 정해 둔 자리이고, 이 글의 둘째 짚고 가기가 같은
  사실을 값으로 보인 자리예요. 서명은 `def pollard_rho(n, s=2, a=1, retries=5, seed=1234, max_steps=None, F=None):`
  이고 실패하면 *"a new ``a`` and ``s`` will be supplied"* 라 상수를 바꿔 다시 시작합니다
  ([소스](https://github.com/sympy/sympy/blob/master/sympy/ntheory/factor_.py), 조회일 2026-09-05).
- **FLINT** — 다중 정밀도 수론 라이브러리의 `n_factor_pollard_brent` 가
  `int n_factor_pollard_brent(ulong *factor, flint_rand_t state, ulong n, ulong max_tries, ulong max_iters)`
  라는 서명을 갖습니다. `max_tries` 와 `max_iters` 두 한도가 인자로 나와 있는 것이 이 절차에 **최악 보장이
  없다**는 사실의 실물이에요 ([소스](https://github.com/flintlib/flint/blob/main/src/ulong_extras/factor_pollard_brent.c),
  조회일 2026-09-05).

세 구현과 이 글의 차이는 이렇습니다.

| 구현 | 원문에서 확인한 것 | 이 글과 다른 자리 |
| --- | --- | --- |
| coreutils | 홀수만 받고, 다른 방법으로 못 가른 합성수에 마지막으로 적용한다 | 두 자리를 옮기는 방식이 브렌트의 변형이다 |
| SymPy | 반환값이 합성수일 수 있고, 실패하면 상수를 바꾼다 | 서명에 `seed` 와 `retries` 인자가 있다 |
| FLINT | 시도 횟수와 걸음 수에 한도를 인자로 받는다 | 부르는 쪽이 한도를 정한다. 이 글의 정본에는 한도가 없다 |

상수를 바꿔 다시 시작하는 구조와 반환값이 합성수일 수 있다는 성질이 셋에 공통입니다. 세 구현의 내부 세부는 위
원문 말고는 확인하지 않았어요.

#### 경쟁 설계와의 대조

경쟁 설계는 **폴라드 p−1 을 앞에 세운 두 단계 판**입니다. 한계 `B` 를 하나 정하고, `a` 를 2 에서 시작해
`a ← a^j mod n` 을 `j = 2, 3, …, B` 로 되풀이한 뒤 `gcd(a − 1, n)` 을 보는 단계를 먼저 실행하고, 거기서 못
찾으면 정본과 **같은** 로 절차로 내려갑니다. 되풀이가 끝난 `a` 는 `2^(B!) mod n` 이에요. 두 설계 다 언제나
비자명한 약수를 돌려주므로 계수로 비교할 수 있습니다. 세는 단위는 이 글 전체와 같은 나머지 연산이에요.

| 설계 | 앞 단계 | 그 뒤 |
| --- | --- | --- |
| 정본 | 없다 | 두 걸음 차이의 최대공약수 |
| 경쟁 설계 | `2^(B!) − 1` 과 `n` 의 최대공약수 | 같은 두 걸음 차이의 최대공약수 |

**입력은 전개 입력을 그대로 두고 두 가족을 더했습니다.** 전개 입력 하나로는 뒤집히는 자리를 보일 수 없어요.
두 설계는 `p − 1` 의 소인수 크기에 따라 갈려서, 큰 쪽 소인수를 1,000,003 으로 고정하고 작은 쪽 `p` 만 두 가족에서
뽑았습니다. 「`10^6` 위에서 처음 나오는, `p − 1` 의 소인수가 전부 200 이하인 소수」와 「`10^6` 위에서 처음 나오는,
`(p − 1) / 2` 도 소수인 소수」예요. 난수가 없어 몇 번을 실행해도 같은 값이 나옵니다.

<!--proof:alt-counts-->

| 항목 | 폴라드 로 | 두 단계 판 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 전개 입력 8,051 기본 연산 | 65 | 711 | 폴라드 로 |
| 매끄러운 p 기본 연산 | 35,181 | 2,521 | 두 단계 판 |
| 안전 소수 p 기본 연산 | 6,858 | 9,437 | 폴라드 로 |
| 갈리는 부분이 동시에 들고 있는 스칼라 칸 | 4 | 4 | 같다 |
| 고를 값의 개수 | 0 | 1 | 폴라드 로 |

매끄러운 p 는 1,000,253 이고 안전 소수 p 는 1,000,667 입니다. 두 입력은 각각 1,000,256,000,759 와 1,000,670,002,001 이고, 한계 B = 200 으로 잰 값입니다.

<!--/proof-->

**둘째 줄과 셋째 줄에서 순서가 뒤집힙니다.** 매끄러운 `p` 에서는 경쟁 설계가 적고, 안전 소수 `p` 에서는 정본이
적어요. 갈리는 조건은 하나입니다. `p − 1` 의 가장 큰 소인수가 `B` 이하이면 `B!` 가 `p − 1` 의 배수라
`2^(B!) ≡ 1 (mod p)` 이 되어 첫 단계가 `p` 를 내고, 그렇지 않으면 첫 단계가 헛일이 되어 그만큼 더 씁니다. 전개
입력에서는 두 소인수의 `p − 1` 이 둘 다 작아 첫 단계가 둘을 동시에 잡고 최대공약수가 `n` 이 되어 로 단계로
내려가요. 한계 `B` 를 바꿔 가며 재었습니다.

<!--proof:alt-bound-->

| 한계 B | 매끄러운 p 를 찾는 단계 | 매끄러운 p | 안전 소수 p | 둘의 합 |
| ---: | --- | ---: | ---: | ---: |
| 50 | 로 단계 | 35,685 | 7,359 | 43,044 |
| 100 | 로 단계 | 36,325 | 8,006 | 44,331 |
| 200 | p-1 단계 | 2,521 | 9,437 | 11,958 |
| 400 | p-1 단계 | 2,521 | 12,590 | 15,111 |
| 800 | p-1 단계 | 2,521 | 19,489 | 22,010 |
| 1,600 | p-1 단계 | 2,521 | 34,527 | 37,048 |

둘의 합이 가장 작은 줄은 B = 200 이고 그때 11,958 입니다. 매끄러운 p 의 p − 1 에서 가장 큰 소인수는 179 이고, 안전 소수의 p − 1 은 1,000,666 = 2 × 500,333 입니다.

<!--/proof-->

**두 가족의 합이 가장 작은 것은 `B = 200` 입니다.** 100 에서 200 으로 올릴 때 매끄러운 쪽이 로 단계에서 p−1
단계로 바뀌는데, 그 자리가 `p − 1` 의 가장 큰 소인수 179 를 `B` 가 넘어서는 지점이에요. 200 을 넘어서면 매끄러운
쪽은 그대로이고 안전 소수 쪽만 커집니다.

**이 절차가 내주는 것과 얻는 것을 적어 둡시다.** 내주는 것은 **`p − 1` 이 매끄러운 입력에서의 연산**입니다. 얻는
것은 **`p − 1` 의 모양을 모를 때의 연산**, 그리고 **고를 값이 하나도 없다는 것**이에요. 경쟁 설계의 200 은 이 두
가족에서 잰 값이라 다른 입력 가족에서는 다시 골라야 합니다. 저장 칸은 두 설계가 공유하는 앞단을 빼고 세면 둘 다
넷이라 이 대조에서 갈리지 않아요. 우열이 반대가 되는 조건은 입력의 `p − 1` 이 매끄러운가입니다.

### 수식 정의와 유도

법 `m` 위의 수열과 그 수열에서 두 자리가 처음 만나는 걸음을 정식으로 정의합니다. $m$ 은 2 이상의 정수, $c$ 는
상수, $x_0 = 2$ 는 시작값이에요.

$$x_{i+1} \equiv x_i^2 + c \pmod m, \qquad \rho(m, c) = \min\{\, k \ge 1 \;:\; x_k \equiv x_{2k} \pmod m \,\}$$

정의를 $m = 97$, $c = 1$ 에 넣으면 이렇습니다.

<!--proof:math-define-->

```text
i      0   1    2    3
x_i    2   5    26   95
x_2i   2   26   5    95

i = 3 에서 처음 x_i ≡ x_2i 이므로 ρ(97, 1) = 3
```

`f` 가 $\{0, \dots, m-1\}$ 위에서 값을 고르게 뽑는다고 보면, 수열의 앞 $k$ 칸이 전부 다를 확률은 생일 문제의
그것과 같습니다. $i$ 번째 칸이 앞의 $i$ 개와 다를 확률이 $1 - i/m$ 이고, 그것을 곱한 뒤 $1 - t \le e^{-t}$ 를
쓰면 이렇게 돼요.

$$\Pr[\text{앞 } k \text{ 칸이 전부 다르다}] = \prod_{i=1}^{k-1}\Bigl(1 - \frac{i}{m}\Bigr) \le \prod_{i=1}^{k-1} e^{-i/m} = e^{-k(k-1)/(2m)}$$

지수 $k(k-1)/(2m)$ 이 1 규모가 되는 $k$ 가 $\sqrt{2m}$ 근방이라, 첫 되풀이까지의 칸 수 $\mu + \lambda$ 의 기댓값이
$\Theta(\sqrt{m})$ 입니다. 3단계에서 본 대로 첫 만남 $\rho(m, c)$ 는 $\mu + \lambda$ 를 넘지 않으니, 같은 가정 아래
$\mathbb{E}[\rho(m, c)] = O(\sqrt{m})$ 이에요.

```ts
// 위 확률식의 오른쪽을 그대로 옮긴 조각. 실제로 수열을 만들지 않고 값만 계산한다.
const allDistinctBound = (k: number, m: number): number =>
  Math.exp((-k * (k - 1)) / (2 * m));
```

정의가 실제 값과 맞는지 네 소수에서 검산합니다. 같은 `p` 를 상수 넷으로 실행해 $\rho(p, c)$ 를 재고 그 평균을
$\sqrt{p}$ 로 나눴어요.

<!--proof:math-check-->

| p | √p 를 내림한 값 | c = 1 | c = 2 | c = 3 | c = 4 | 네 값의 평균 / √p |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 97 | 9 | 3 | 8 | 6 | 9 | 0.72 |
| 1,009 | 31 | 49 | 26 | 22 | 34 | 1.06 |
| 10,007 | 100 | 40 | 110 | 76 | 54 | 0.70 |
| 100,003 | 316 | 518 | 387 | 198 | 384 | 1.18 |

셋째 칸부터 여섯째 칸까지가 같은 p 를 상수 넷으로 실행해 잰 첫 만남 걸음이고, 마지막 칸은 0.70 과 1.18 사이입니다.

<!--/proof-->

**같은 `p` 에서도 상수에 따라 값이 크게 갈리는데, 넷의 평균은 `√p` 근방에 머뭅니다.** 10,007 에서 40 과 110
이 그 예예요. $O(\sqrt{m})$ 이 개별 값이 아니라 기댓값에 대한 진술이라는 뜻입니다. 이 결과를 `n` 의 인수분해에
옮깁니다. 절차가 멈추는 것은 가장 작은 소인수 `p` 에서 두 자리가 만날 때이거나 그 전이고, 1단계를 지난 `n` 은
홀 합성수라 $p \le \sqrt{n}$ 이에요. 그러니 걸음 수의 기댓값이 `n` 하나로 닫힙니다.

$$\mathbb{E}[k] = O\bigl(\sqrt{p}\bigr), \qquad p \le \sqrt{n} \;\Rightarrow\; \mathbb{E}[k] = O\bigl(n^{1/4}\bigr)$$

규모마다 두 값이 얼마가 되는지 나란히 놓았습니다.

<!--proof:math-scale-->

| 규모 n | √n 을 내림한 값 | n^(1/4) 을 내림한 값 | 둘째를 셋째로 나눈 값 |
| --- | ---: | ---: | ---: |
| 10^4 | 100 | 10 | 10 |
| 10^8 | 10,000 | 100 | 100 |
| 10^12 | 1,000,000 | 1,000 | 1,000 |
| 10^16 | 100,000,000 | 10,000 | 10,000 |
| 2^64 | 4,294,967,296 | 65,536 | 65,536 |

둘째 칸과 셋째 칸은 실행하지 않고 제곱근을 한 번과 두 번 구한 값이라 상수 배가 담겨 있지 않습니다.

<!--/proof-->

**계약 상한 `2^64` 에서 `√n` 은 약 43 억이고 `n^(1/4)` 은 65,536 입니다.** 시행 나눗셈은 가장 작은 소인수 `p`
를 따라가고 이 절차는 `√p` 를 따라가니, 지수가 절반이에요. 다만 이 절차의 걸음 하나는 수열 칸 셋과 최대공약수
하나라 나눗셈 한 번보다 비용이 큽니다. 그 상수 배까지 담은 계수는 비용 계산에서 셉니다.

### 불변식 — 돌려주는 d 는 언제나 n 의 약수이고 로 루프가 돌려줄 때는 1 < d < n 이다

파트 1 의 일곱 걸음은 `n = 8,051` 하나에서 답이 나온 기록입니다. 그 기록만으로는 다른 입력에서도 반환값이 계약을
지키는지 알 수 없어요. 걸음마다 참인 문장을 세우고 값으로 확인합시다.

> 로 루프의 매 걸음 직후 `d = gcd(|x − y|, n)` 이고, 최대공약수의 정의에 따라 `d` 는 `n` 의 약수입니다. 로
> 루프가 돌려주는 자리에서는 그 위에 `d ≠ 1` 과 `d ≠ n` 이 함께 참입니다.

<!--proof:invariant-walk-->

| 걸음 | d | n 의 약수 여부 | 반환 여부 |
| --- | ---: | --- | --- |
| T4 | 1 | 그렇다 | 아니다 — d = 1 |
| T5 | 1 | 그렇다 | 아니다 — d = 1 |
| T6 | 97 | 그렇다 | 그렇다 — 1 도 n 도 아니다 |

3 걸음 가운데 d 가 8,051 의 약수인 걸음은 3 개입니다.

<!--/proof-->

**세 자리가 문장을 나눠 맡습니다.** 최대공약수 계산이 「`n` 의 약수」를, 루프 조건 `d === 1n` 이 「`d ≠ 1`」을,
반환 검사 `d !== n` 이 「`d ≠ n`」을 맡아요. 상태를 바꾸는 자리마다 적으면 이렇습니다.

| 지나는 자리 | `d` 의 변화 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| 초기화 `let d = 1n` | `d ← 1` | 1 은 모든 정수의 약수라 앞부분이 참이다. 뒷부분은 아직 아니다 |
| 최대공약수 `gcd(\|x − y\|, n)` | `d ← gcd(…, n)` | 최대공약수의 정의에 따라 `n` 을 나눈다. 차가 0 이면 `gcd(0, n) = n` 이다 |
| 루프 조건 `d === 1n` 이 거짓 | 그대로 | `d ≠ 1` 이 여기서 정해진다 |
| 반환 검사 `d !== n` 이 참 | 그대로 돌려준다 | `d ≠ n` 이 여기서 정해져 셋이 모두 참이 된다 |
| 반환 검사가 거짓 | 상수를 올려 처음부터 | `d = n` 이라 돌려줄 수 없다. 다른 수열로 다시 시작한다 |

둘째 줄이 경계를 함께 맡습니다. 두 자리가 법 `n` 에서까지 같아지면 차가 0 이고 `d = n` 이 되어, 넷째 줄이 거짓이
되고 상수가 올라가요. 경계 입력이 어느 갈래에서 답하는지도 함께 봤습니다.

<!--proof:edge-values-->

| 입력 n | 답한 갈래 | 정본 | 시행 나눗셈 | d 는 | 자리 |
| ---: | --- | ---: | ---: | --- | --- |
| 2 | 짝수 검사 | 2 | 2 | 약수 | n 자신 |
| 3 | 소수 판정 | 3 | 3 | 약수 | n 자신 |
| 4 | 짝수 검사 | 2 | 2 | 약수 | 1 < d < n |
| 9 | 로 루프 | 3 | 3 | 약수 | 1 < d < n |
| 15 | 로 루프 | 3 | 3 | 약수 | 1 < d < n |
| 21 | 로 루프 | 3 | 3 | 약수 | 1 < d < n |
| 25 | 로 루프 | 5 | 5 | 약수 | 1 < d < n |
| 49 | 로 루프 | 7 | 7 | 약수 | 1 < d < n |
| 63 | 로 루프 | 21 | 3 | 약수 | 1 < d < n |
| 8,051 | 로 루프 | 97 | 83 | 약수 | 1 < d < n |
| 1,000,003 | 소수 판정 | 1,000,003 | 1,000,003 | 약수 | n 자신 |
| 2,000,006 | 짝수 검사 | 2 | 2 | 약수 | 1 < d < n |

12 줄 가운데 다섯째 칸이 「약수」인 줄은 12 개입니다. 셋째 칸과 넷째 칸이 갈리는 줄은 63 · 8,051 입니다.

<!--/proof-->

**열두 줄 내내 「약수」입니다.** 63 과 8,051 에서 정본과 시행 나눗셈이 다른 값을 내는데, 두 절차가 같은 약수를
고를 이유가 없어서예요. 계약이 요구하는 것은 「어느 것이든 하나」입니다. 「`n` 자신」인 줄은 2 · 3 · 1,000,003
이고, 셋 다 소수라 비자명한 약수가 없는 입력이에요. 2 는 짝수 검사가, 나머지 둘은 소수 판정이 답했습니다.

**이제 깨뜨려 봅시다.** 문장의 뒷부분 「`d ≠ n`」을 지키는 것은 반환 검사 한 줄입니다. 그 검사를 빼면 첫 라운드가
낸 `d` 를 그대로 돌려주게 돼요.

```ts
return d; // ← if (d !== n) return d; 이었다
```

<!--proof:mutant-return-any-->

| 입력 | 소인수 | 정본 | 반환 검사를 뺀 판 | 뺀 판이 낸 d | 두 답 |
| ---: | --- | ---: | ---: | --- | --- |
| 9 | 3 × 3 | 3 | 3 | 1 < d < n | 같다 |
| 15 | 3 × 5 | 3 | 3 | 1 < d < n | 같다 |
| 21 | 3 × 7 | 3 | 21 | n 자신 | 어긋난다 |
| 25 | 5 × 5 | 5 | 25 | n 자신 | 어긋난다 |
| 63 | 3 × 3 × 7 | 21 | 21 | 1 < d < n | 같다 |
| 8,051 | 83 × 97 | 97 | 97 | 1 < d < n | 같다 |

다섯째 칸이 「n 자신」인 줄은 합성수인데 입력 자신을 돌려준 줄입니다.

<!--/proof-->

**21 과 25 에서 입력 자신이 나옵니다.** 둘 다 합성수인데 `d = n` 을 돌려준 것이라 계약의 「`1 < d < n`」이
깨져요. 나머지 네 줄은 첫 상수가 곧바로 비자명한 약수를 내는 입력이라 두 판의 답이 같습니다. 21 에서 무슨 일이
일어나는지 따라가 봤어요.

<!--proof:why-21-->

```text
c = 1 · f(t) = (t² + 1) mod 21
x ← f(2) = 5                     y ← f(f(2)) = f(5) = 5
|x − y| = 0                      gcd(0, 21) = 21
정본은 c = 2 로 다시 시작해      2 걸음 만에 3 을 낸다
```

첫 걸음에서 두 자리가 법 3 과 법 7 에서 동시에 만나 차가 0 이 됩니다. 정본은 여기서 상수를 올리고, 검사를 뺀 판은
21 을 그대로 돌려줘요.

### 비용 계산

#### 비용을 세는 과정

세는 단위는 파트 1 에서 정한 나머지 연산입니다. 전개 입력에서 실제로 한 일을 걸음마다 나누면 이렇습니다.

<!--proof:perf-walk-->

| 걸음 | 하는 일 | 나머지 연산 |
| --- | --- | ---: |
| T1 | 짝수 검사 | 1 |
| T2 | 소수 판정 | 35 |
| T4 | 수열 칸 3 개 · 최대공약수 | 3 + 7 = 10 |
| T5 | 수열 칸 3 개 · 최대공약수 | 3 + 10 = 13 |
| T6 | 수열 칸 3 개 · 최대공약수 | 3 + 3 = 6 |

더하면 65 이고, 기록 사본이 센 전체 65 와 같습니다. T3 · T7 은 비교뿐이라 0 입니다.

<!--/proof-->

T1 의 짝수 검사 한 번, T2 의 소수 판정, T4 · T5 · T6 의 수열 칸 셋과 최대공약수가 전부예요. 횟수가 정해지는
자리는 셋입니다. 소수 판정이 쓴 몫을 `P`, 라운드를 합친 걸음 수를 `Σk`, 최대공약수가 쓴 나머지 연산의 합을 `G`
로 적습니다.

| 자리 | 몇 번 | 근거 |
| --- | --- | --- |
| `①` 의 짝수 검사 | 1 번 | 언제나 한 번이다 |
| `②` 의 소수 판정 | `P` 번 | 소수 판정 편이 센 값이다. 짝수 입력에서는 0 이다 |
| `⑤` 의 수열 칸 | 걸음마다 3 번 | `f(x)` 한 번과 `f(f(y))` 두 번 |
| `⑥` 의 최대공약수 | 걸음마다 다르다 | 유클리드 호제법의 나눗셈 수. 합 `G` 로 센다 |

그러니 로 루프까지 내려가는 입력의 총식은 `1 + P + 3Σk + G` 이고, `①` 에서 답하면 1, `②` 에서 답하면 `1 + P`
입니다. 식이 실행과 같은 값을 내는지 일곱 입력에서 확인했어요.

<!--proof:perf-formula-->

| 입력 | 소수 판정 P | 걸음 합 Σk | 최대공약수 G | 걸음당 G | 식 1 + P + 3Σk + G | 실행이 센 값 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2,000,006 | 0 | 0 | 0 | — | 1 | 1 |
| 1,000,003 | 360 | 0 | 0 | — | 361 | 361 |
| 8,051 | 35 | 3 | 20 | 6.7 | 65 | 65 |
| 21 | 2 | 3 | 8 | 2.7 | 20 | 20 |
| 10,403 | 32 | 9 | 73 | 8.1 | 133 | 133 |
| 110,107,021 | 50 | 40 | 672 | 16.8 | 843 | 843 |
| 1,001,006,003,009 | 70 | 1,276 | 31,443 | 24.6 | 35,342 | 35,342 |

7 줄 가운데 여섯째 칸과 일곱째 칸이 같은 줄은 7 개입니다.

<!--/proof-->

**식과 실행이 일곱 줄 내내 같습니다.** 다섯째 칸의 걸음당 `G` 가 `n` 이 커질수록 늘어요. 8,051 에서 6.7 이고
`10^12` 규모에서 24.6 입니다. 유클리드 호제법의 나눗셈 수가 `n` 의 자릿수를 따라가기 때문이에요. 그래서 걸음
하나의 비용은 수열 칸 셋보다 최대공약수가 더 큽니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| 최선 — 짝수 | `O(1)` | `Θ(1)` |
| 평균 — 수열이 값을 고르게 뽑는다고 볼 때의 기댓값 | `O(n^(1/4) log n)` | 정하지 않았다 |
| 최악 — 수열이 가장 늦게 되풀이되는 입력 | 알려진 상한이 없다 | 정하지 않았다 |

총식을 정확히 쓰면 로 루프까지 내려가는 입력에서 `1 + P + 3Σk + G` 입니다. `P` 는 소수 판정 편이 `O(log n)` 으로
닫았고, `G` 는 걸음마다 `O(log n)` 이라 총식이 `O(Σk · log n)` 이에요. `Σk` 의 기댓값을 수식 절이 `O(n^(1/4))` 로
닫았으니 평균 줄의 상한이 나옵니다.

**보장의 종류는 기댓값이지 최악 보장이 아닙니다.** 그리고 그 기댓값은 입력이 어떤 분포로 들어오는지에 대한 것도
아니에요. 「`f(t) = (t² + c) mod p` 가 값을 고르게 뽑는다」는 가정 위에서의 값입니다. 이 절차에는 난수가 없으니
같은 `n` 에서 언제나 같은 걸음 수가 나오고, 그 걸음 수가 기댓값 근처인지는 입력마다 다릅니다. 그 가정이 참인지는
증명되어 있지 않고, 3단계와 수식 절의 표본이 그것과 어긋나지 않았다는 것까지가 이 글이 확인한 전부예요. 상수를
올려 다시 시작하는 갈래가 몇 번 실행될지도 닫아 주는 정리가 없습니다.

#### 최악을 만드는 입력

「`n` 이 크면 최악」이라는 통념부터 확인합시다. `10^18` 이상인 수를 모양만 바꿔 가며 정본에 넣었어요.

<!--proof:worst-shapes-->

| 입력 모양 | n | 가장 작은 소인수 | 로 루프 걸음 | 나머지 연산 |
| --- | ---: | ---: | ---: | ---: |
| 짝수 | 2,000,000,000,000,000,006 | 2 | 0 | 1 |
| 가장 작은 소인수가 3 | 3,000,000,000,000,000,009 | 3 | 1 | 11 |
| 가장 작은 소인수가 10^3 근방 | 1,009,000,000,000,037,333 | 1,009 | 49 | 1,963 |
| 가장 작은 소인수가 10^6 근방 | 1,000,003,000,039,000,117 | 1,000,003 | 1,276 | 50,109 |
| 두 소인수가 모두 10^9 근방 | 1,000,001,018,000,007,077 | 1,000,000,007 | 18,970 | 741,912 |
| 2^64 아래에서 가장 작은 소인수가 가장 큰 모양 | 18,446,744,030,759,878,681 | 4,294,967,291 | 80,073 | 3,331,703 |
| 소수 | 1,000,000,000,000,000,003 | 1,000,000,000,000,000,003 | 0 | 1,045 |

일곱 줄의 n 이 전부 10^18 이상인데 마지막 칸은 1 부터 3,331,703 까지 갈립니다.

<!--/proof-->

**통념은 절반만 맞습니다.** 일곱 줄의 `n` 이 전부 `10^18` 이상인데 나머지 연산이 1 번부터 3,331,703 번까지
벌어져요. `n` 이 정하는 것은 가장 작은 소인수가 가질 수 있는 상한뿐이고, 실제 값은 그 소인수가 어디 있는가가
정합니다. 마지막 줄은 소수라 로 루프에 내려가지도 않아요.

**최악을 실제로 구성해 봅시다.** 걸음 수가 `√p` 규모이고 `p` 는 가장 작은 소인수이므로, `p` 를 가능한 한 크게
만들면 됩니다.

<!--proof:worst-construct-->

```text
첫째   소인수를 둘로 정한다                  셋이면 가장 작은 것이 n^(1/3) 이하로 내려간다
둘째   둘의 크기를 같게 한다                 p = q 이면 p 가 √n 으로 가장 크다
셋째   p² < 2^64 에서 p 를 가장 크게         p = 4,294,967,291 · 2^32 아래에서 가장 큰 소수
       n = p² = 18,446,744,030,759,878,681   로 루프 80,073 걸음 · 나머지 연산 3,331,703 번 · 0.03 초
```

가장 작은 소인수가 가장 클 수 있는 모양은 **소인수가 정확히 둘이고 둘의 크기가 같은 것**이에요. 그 입력에서도
나머지 연산이 예산 1 초의 3 % 남짓입니다. 반대쪽으로, 소인수가 여럿이면 오히려 쉬워집니다. `10^18` 규모라도
가장 작은 소인수가 3 이면 나머지 연산이 11 번이에요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 수열 하나를 법 `n` 위에서 만들되, 그 수열이 **법 `p` 에서 먼저
되풀이되는 자리**를 노리고, 되풀이를 느린 자리와 빠른 자리의 차의 최대공약수 하나로 알아채 `p` 의 이름을 모르는
채로 약수를 얻었습니다. 한 상수로 못 찾으면 상수를 올려 다른 수열로 다시 시작해요.

```text
짝수인가 → 소수인가 → 상수 c 로 수열을 정한다 → x 한 칸 · y 두 칸 · gcd 를 본다
                              │                                  │
                              │                                  └ 1 도 n 도 아니면 돌려준다
                              └ gcd 가 n 이면 c 를 올린다
```

먼저 답이 붙는 문제 하나입니다. 전개는 `n = 8,051` 이었고 T4 부터 T6 까지 세 걸음으로 답이 나왔어요. **같은
코드에 `n = 21` 을 넣으면 상수가 몇 번 바뀌고, 각 상수에서 몇 걸음이 걸릴까요?**

<!--check:retry21-->
답: 상수가 한 번 바뀌고, `c = 1` 은 한 걸음, `c = 2` 는 두 걸음입니다. `c = 1` 의 첫 걸음에서 두 자리가 같은 값이
되어 `d` 가 21 자신이 되고, 그래서 `⑦` 이 거짓이 되어 `⑧` 이 실행돼요.

<!--proof:check-retry-->

| 상수 c | 걸음 k | x | y | \|x − y\| | d |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 5 | 5 | 0 | 21 |
| 2 | 1 | 6 | 17 | 11 | 1 |
| 2 | 2 | 17 | 11 | 6 | 3 |

정본의 반환값은 3 이고, 나머지 연산은 모두 20 번입니다.

<!--/proof-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「불변식」, 「수식 정의와 유도」, 「최악을 만드는 입력」을 다시
보세요.

- T6 에서 `|x − y| = 194` 라 `gcd(194, 8051) = 97` 이 나왔습니다. 같은 걸음의 차가 `83 × 97 × 2` 였다면 최대공약수가
  얼마가 되고, 그 값이 반환될 수 있을까요? 불변식의 어느 부분이 그것을 막나요?
- 「수식 정의와 유도」가 걸음 수의 기댓값을 `n^(1/4)` 규모로 닫았습니다. `n = p³` 꼴이면 가장 작은 소인수가 `n^(1/3)`
  이니 그 규모가 어떻게 바뀌고, `n = 10^18` 근방에서 두 모양의 걸음 수가 각각 몇 자리가 될까요?
- 「최악을 만드는 입력」이 소인수 둘의 크기가 같은 모양이라고 했습니다. `2^64` 아래에서 나머지 연산이 가장 적은 **홀
  합성수**는 어떤 모양이어야 하고, 그 수에서 로 루프는 몇 걸음이 걸릴까요?

### 비자명한 약수 찾기 (Pollard's Rho)

풀 파일: [`pollardRho.ts`](./pollardRho.ts) · 테스트: [`pollardRho.test.ts`](./pollardRho.test.ts) · 실행: `bun test src/algorithms/number-theory/pollardRho/pollardRho.test.ts`

#### 한 줄 요약

> 함수는 합성수 `n`을 받아 1도 `n`도 아닌 약수 하나를 반환한다.

#### 스토리

보안 연구원이 오래된 RSA 모듈러스를 분석하고 있다. 모듈러스 $n$이 두 소수 $p \times q$의 곱이라면 암호를 해독할 수 있다. $n$이 20자리 수라면 시행 나눗셈으로 약수를 찾으려면 $10^{10}$번 이상 나눠야 해서 현실적이지 않다.

연구원은 $n$의 비자명한 약수, 즉 1이나 $n$이 아닌 약수를 하나만 찾으면 된다. 나머지 분해는 이 약수를 재귀적으로 적용하면 된다.

$n$이 짝수면 즉시 2를 반환할 수 있다. $n$이 소수이면 비자명한 약수가 존재하지 않으므로 $n$ 자체를 반환한다.

#### 함수 인터페이스

```ts
export function pollardRho(n: bigint): bigint;
```

- `n` — 약수를 찾을 정수, $n \geq 2$인 bigint
- 반환 — $n$의 약수 $d$, $1 < d \leq n$; 합성수이면 $1 < d < n$, 소수이면 $d = n$

#### 제약 조건

- $n \geq 2$ (bigint)
- 합성수 입력 권장; 소수 입력 시 $n$ 자체 반환 허용
- $n$이 짝수이면 즉시 $2$를 반환해도 됨
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

$n$의 비자명한 약수 $d$ ($1 < d < n$)를 하나 반환한다.

- 반환값 $d$는 반드시 $n \bmod d = 0$을 만족해야 한다.
- 여러 비자명한 약수가 있을 때 어느 것을 반환해도 무방하다.
- $n$이 소수이면 $d = n$을 반환한다.
- $n$이 짝수이면 $d = 2$를 반환한다.

#### 예시

```ts
pollardRho(15n);      // 3n 또는 5n  — 15 = 3 × 5, 둘 중 하나
pollardRho(8n);       // 2n          — 짝수이므로 2
pollardRho(49n);      // 7n          — 49 = 7 × 7
pollardRho(91n);      // 7n 또는 13n — 91 = 7 × 13
pollardRho(10403n);   // 101n 또는 103n — 10403 = 101 × 103
pollardRho(1_000_003n); // 1_000_003n — 소수이면 자기 자신
```
