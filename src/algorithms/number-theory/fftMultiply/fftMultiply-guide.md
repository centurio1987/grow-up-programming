# 다항식 곱셈 — 계수를 값으로 바꿔 두면 곱셈이 자리마다 한 번으로 끝난다

## 파트 1 — 아이디어에서 동작하는 코드까지

계수를 짝지어 곱하는 셈이 길이 십만에서 왜 못 쓰는지 수로 확인한 다음, 다항식을 **여러
점에서의 값**으로 적어 두면 곱셈이 자리마다 한 번으로 끝난다는 데까지 갑니다. 그 왕복
비용을 줄이는 점 묶음을 찾고, 그것을 코드 조각으로 옮겨 실행되는 모습까지 봅니다.

### 전체 컨셉

정수 계수 배열 둘을 받아 **곱 다항식의 계수 배열**을 돌려주는 함수입니다. 배열 `a` 의 `i`
번째 값은 `x^i` 의 계수이고, 곱의 `k` 번째 계수는 자리 번호가 `k` 로 더해지는 모든 짝을
합한 값이에요. 한쪽이 빈 배열이면 곱도 빈 배열입니다.

```text
fftMultiply([3, 1, 4, 1], [2, 5]) 가 내는 것

  A = 3 + x + 4x² + x³        B = 2 + 5x
  ────────────────
  c₀ = 3·2                                  = 6
  c₁ = 3·5 + 1·2                            = 17
  c₂ = 1·5 + 4·2                            = 13
  c₃ = 4·5 + 1·2                            = 22
  c₄ = 1·5                                  = 5
  ────────────────
  돌려주는 값은 [6, 17, 13, 22, 5]          길이는 4 + 2 − 1 = 5
```

정의를 그대로 옮기면 계수 한 쌍마다 곱셈이 한 번이라 길이 `n` 과 `m` 에서 `n·m` 번입니다.
길이가 십만씩이면 백억 번이라 1 초 안에 끝나지 않아요.

| 방법 | 길이 십만씩에서 몇 번 | 한 번이 무슨 연산인가 |
| --- | --- | --- |
| 계수 한 쌍씩 곱해 더한다 | 100 억 번 | 실수 곱 하나와 덧셈 하나 |
| 이 글의 절차 | 실측 9,410 만 번 | 실수 곱·덧셈·뺄셈, 그리고 삼각함수 호출 |

**계수 대신 값으로 표현을 바꾸는 것**이 이 절차의 출발입니다. 차수가 `d` 이하인 다항식은
서로 다른 점 `d + 1` 개에서의 값으로도 남김없이 정해집니다 — 직선 하나가 두 점으로 정해지는
것과 같은 사실이에요. 그리고 **값 표현끼리는 자리마다 한 번 곱하면 그것이 곱의 값 표현**
입니다. `A(x)·B(x)` 는 어느 점에서든 두 값의 곱이니까요.

```text
표현을 바꿨다가 되돌아오는 세 걸음

  계수 표현                     값 표현                        계수 표현
  A = [3, 1, 4, 1]  ──평가──▶  A(x₀) … A(x₇)  ┐
  B = [2, 5]        ──평가──▶  B(x₀) … B(x₇)  ┤ 자리마다 한 번 곱한다
                                                ▼
                               C(xₖ) = A(xₖ)·B(xₖ)
                                                │ 보간
                                                ▼
                               C = [6, 17, 13, 22, 5]
```

문제는 왕복 비용입니다. 점을 아무렇게나 고르면 평가 한 번이 자리 수만큼 걸리고 보간은 그보다
더 걸려서, 왕복만으로 이미 `n·m` 을 넘어요. **평가할 점을 복소수 단위근으로 고르면** 그
왕복 비용이 통째로 작아집니다. 점의 수를 2 의 거듭제곱 `N` 으로 잡고 각도를 `N` 등분한
단위원 위의 점을 쓰면, 그 점들은 제곱했을 때 `N/2` 등분 점으로 겹쳐요. 그래서 길이 `N` 짜리
평가 하나가 길이 `N/2` 짜리 평가 **둘**로 쪼개지고, 그 쪼개기를 `log₂ N` 번 반복하면 평가가
끝납니다. 이렇게 계산한 값 묶음을 이산 푸리에 변환이라 부릅니다.

```text
길이 8 짜리 평가 하나가 절반 둘로

  자리 0 1 2 3 4 5 6 7 의 계수
        │
        ├─ 짝수 자리 0 2 4 6 만 모은 것 → 길이 4 짜리 평가
        └─ 홀수 자리 1 3 5 7 만 모은 것 → 길이 4 짜리 평가
        ────────────────
  둘을 각각 한 번씩 더하고 빼면 길이 8 짜리 평가 여덟 값이 나온다
```

그래서 전체가 **평가 두 번 → 자리마다 곱 → 보간 한 번**이고, 비용은 두 길이의 합에 그
로그를 곱한 만큼입니다. 결과값만 적으면 $\Theta((n+m)\log(n+m))$ 이에요.

**한 가지 대가가 있습니다.** 단위근은 실수부와 허수부가 무리수라 계산이 부동소수로
이뤄지고, 정수 계수를 되찾으려면 마지막에 반올림해야 합니다. 계수가 크고 길이가 길면 참값이
배정밀도가 담을 수 있는 정수 범위를 넘어서 반올림이 다른 정수를 내는 자리가 실제로 생겨요.
그 자리를 어디서부터인지 실행으로 재는 것이 이 글의 한 대목입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **다항식과 계수 배열.** `[3, 1, 4, 1]` 이 `3 + x + 4x² + x³` 을 뜻한다는 것, 그리고 두
  다항식의 곱이 자리 번호가 더해지는 짝을 전부 합한 것이라는 것.
- **복소수의 덧셈과 곱셈.** $(p + qi)(r + si) = (pr - qs) + (ps + qr)i$ 이고 $i^2 = -1$
  이라는 것. 이 글은 복소수를 실수 두 개(`re`·`im`)로 나눠 배열에 담습니다. **허수 단위는
  수식 글꼴 $i$ 로만 적고, 코드 글꼴 `i` 는 언제나 배열의 자리 번호입니다.**
- **삼각함수와 단위원.** `cos θ` 와 `sin θ` 가 단위원 위의 한 점의 좌표라는 것, 그리고 그
  점을 각도 `θ` 로 적을 수 있다는 것.
- **거듭제곱을 반씩 접는 방식.** 크기를 절반으로 줄이며 `log₂ N` 번 반복하면 끝난다는 셈법.
  [빠른 거듭제곱 가이드](../fastPower/fastPower-guide.md)가 같은 셈법을 지수에 씁니다.
- **배정밀도 실수와 정수 정밀도.** JavaScript 의 `number` 가 배정밀도 실수이고, 정수를 오차
  없이 담는 범위가 `2^53` 까지라는 것. 그 범위를 넘어가면 이웃한 정수 둘이 같은 값이 됩니다.
- **큰 정수 곱셈(`bigint`).** 자릿수 제한 없이 정확한 곱을 내는 정수 타입이 있다는 것.
  이 글은 「정답」을 정의하는 데만 씁니다.

```text
이 글이 답하는 것과 답하지 않는 것

  두 계수 배열의 곱 계수                    이 글이 답한다
  계수가 얼마나 커도 되는가                 실행으로 재서 답한다
  결과를 어떤 소수로 나눈 나머지            답하지 않는다 — 정수 나머지 위의 변환이 할 일이다
  임의 길이의 이산 푸리에 변환              답하지 않는다 — 이 글은 2 의 거듭제곱 길이만 다룬다
```

### 아이디어 상세 — 값 표현을 떠올리는 과정

만들 함수의 모양부터 못 박고 갑시다.

```ts
function fftMultiply(a: number[], b: number[]): number[];
```

- 입력: 정수 계수 배열 둘. `a` 의 길이가 `n`, `b` 의 길이가 `m` 입니다.
- 출력: 곱 다항식의 계수 배열. 길이는 정확히 `n + m − 1` 이고, 한쪽이 빈 배열이면 `[]` 입니다.
- 계약의 경계: 계수는 정수이고 결과 계수도 정수입니다. 부동소수로 계산한 뒤 반올림해서 돌려줍니다.
- 제약: 시간 1 초, 메모리 256 MB. 원본 시험 파일의 가장 큰 입력이 `2^16 = 65,536` 이라 이
  글은 규모를 `n, m ≤ 100,000` 으로 잡고 셉니다.

이 편에서 끝까지 나오는 기호는 여덟이에요. 입력과 길이를 앞에, 변환 안에서만 쓰는 것을 뒤에 둡니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 배열 `a` 의 길이 | 입력. `1 ≤ n ≤ 100,000` |
| `m` | 배열 `b` 의 길이 | 입력. `1 ≤ m ≤ 100,000` |
| `L` | 결과 길이 | `n + m − 1` |
| `N` | 패딩 길이 | `L` 이상인 가장 작은 2 의 거듭제곱 |
| `M` | 계수 절댓값의 상한 | 정확성의 한계를 재는 축 |
| `c` | 곱 다항식의 계수 | `c` 의 `k` 번째 값이 답의 `k` 번째 칸이다 |
| `ω` | `N` 등분 단위근 | 각도 `2π/N` 인 복소수. 실수부와 허수부 둘로 나눠 담는다 |
| `len` | 나비 연산이 한 바퀴에 다루는 블록 길이 | 2 에서 시작해 `N` 까지 두 배씩 |

```text
기호가 어디에 사는가

  n · m      함수 인자의 길이   한 번 받으면 끝까지 안 바뀐다
  L          n 과 m 이 정한다   반환 배열의 길이와 같다
  N          L 이 정한다        배열 넷을 이 길이로 잡는다
  M          입력의 성질        코드 어디에도 나오지 않는다. 정확성 논의에만 나온다
  c          답                 반올림 뒤의 정수다
  ω          N 이 정한다        각 자리의 회전량을 나타낸다
  len        바퀴마다 두 배     바퀴 안에서는 고정이다
```

식의 `L`·`N`·`len` 은 코드에서는 `resultLen`·`size`·`len` 이고, `ω` 는 실수 둘로 나뉘어 `wRe` 와 `wIm` 입니다.
계수 상한과 곱 계수는 코드에 이름이 없어요 — 앞은 입력의 성질이라 계산에 안 나오고, 뒤는 반환 배열 자체입니다.

제일 먼저 손이 가는 방법부터 세워 봅시다. **곱셈의 정의를 그대로 이중 반복으로 옮기는
것**이에요. 자리 `i` 의 값과 자리 `j` 의 값을 곱해 자리 `i + j` 에 더하면 됩니다.

```ts
// 정의를 그대로 옮긴 판. 답은 맞지만 곱셈 횟수가 두 길이의 곱을 따라간다.
const out = new Array(a.length + b.length - 1).fill(0);
for (let i = 0; i < a.length; i++) {
  for (let j = 0; j < b.length; j++) {
    out[i + j] += a[i] * b[j];
  }
}
```

**제약 규모에서 100 억 번입니다.** 1 초 안에 끝내야 하는데 곱셈 하나에 1 나노초를 쓴다고
해도 10 초예요. 마지막 줄의 「이 글의 절차 — 연산 전부」 칸이 목표인데, 그 칸은 곱셈을 빨리
하는 방법이 아니라 **곱셈을 적게 하는 표현**에서 나옵니다.

```text
두 방향

  곱셈을 더 빨리 한다          같은 횟수를 더 짧은 시간에.  제약 규모에서 여전히 100 억 번
  곱셈 횟수 자체를 줄인다      표현을 바꿔 자리마다 한 번.  길이의 로그배로 줄어든다
                               └ 뒤쪽이 이 글의 방향이다
```

**표현을 바꾼다는 것이 무슨 뜻인지 값으로 봅시다.** `A` 와 `B` 를 계수로 적는 대신 서로 다른
다섯 점에서의 값으로 적어 봅니다. 곱 `C` 는 차수가 4 이므로 다섯 값이면 남김없이 정해져요.

```text
점 x  A(x)  B(x)  A(x) × B(x)   C(x)
   0     3     2            6      6
   1     9     7           63     63
   2    29    12          348    348
   3    69    17        1,173  1,173
   4   135    22        2,970  2,970

└ 「A(x) × B(x)」 칸은 두 값을 그냥 곱한 것이고 「C(x)」 칸은 답 [6, 17, 13, 22, 5] 의
  그 점에서의 값이다. 잰 점이 5 개이고 두 칸이 줄마다 같으므로, 이 값들이
  차수 4 이하인 다항식 하나를 유일하게 정한다
```

**두 값을 그냥 곱하기만 하면 곱의 값이 나옵니다.** 다섯 점에서 곱셈이 다섯 번이고, 계수를
직접 곱했으면 여덟 번이었어요. 길이가 커지면 이 차이가 벌어집니다 — 계수 쪽은 `n·m` 이고
값 쪽은 점의 수만큼이라 `n + m − 1` 이니까요.

```text
같은 곱을 두 표현에서

  계수 표현    자리 짝마다 한 번    n · m 번
  값 표현      점마다 한 번         n + m − 1 번
  ────────────────
  길이 100,000 씩이면 100 억 번 대 199,999 번
```

**그런데 여기에는 아직 값을 얻는 비용이 빠져 있습니다.** 점 `x` 하나에서 `A(x)` 를 구하려면
호너 방식으로 곱셈 `n − 1` 번이 들고, 점이 `n + m − 1` 개예요. 되돌아오는 보간은 라그랑주
공식으로 점 수의 제곱만큼 듭니다. 실제로 세어 봅시다.

```text
  자릿수이고 「보간 — 라그랑주」 칸은 그보다 훨씬 크다. 「되찾은 계수」 칸은 보간이
  낸 계수가 정의 그대로 곱한 값과 같은지인데, 점을 0 부터 차례로 고르면 기저
  다항식의 계수가 30 자리를 넘어서 배정밀도가 그것을 못 담는다. 값 표현으로 옮기는
  것만으로는 비용도 정확성도 얻는 것이 없다
```

**값 표현으로 옮기는 것만으로는 아무것도 줄지 않습니다.** 평가와 보간의 비용이 곱셈보다 크고,
점을 0 부터 차례로 고르면 보간이 되찾은 계수가 정답과 갈리기까지 해요. 그러니 이제 물을 것은
하나입니다 — **평가할 점을 어떻게 고르면 평가와 보간의 비용이 작아지는가.**

**점을 다른 값으로 바꿔 봐도 소용이 없습니다.** 위 표가 `0, 1, 2, …` 로 잰 것인데, 점의
값이 무엇이든 호너 방식의 곱셈 횟수는 계수 수와 점 수의 곱으로 같아요. 필요한 것은 점의
값이 아니라 **점들 사이의 관계**입니다.

```text
점을 고르는 두 기준

  값이 다루기 쉬운가        0 · 1 · 2 · 3 … 은 손으로 계산하기 쉽다.  비용은 그대로다
  점들 사이에 관계가 있는가 한 점이 다른 점에서 나오면 계산을 나눠 쓸 수 있다
                            └ 뒤쪽이 필요한 기준이다
```

**필요한 관계는 「제곱하면 개수가 반으로 준다」입니다.** 점 `N` 개를 골랐는데 그것들을 전부
제곱했더니 서로 다른 값이 `N/2` 개뿐이라면, 짝수 자리 계수만 모은 다항식은 그 `N/2` 개
점에서만 평가하면 됩니다. 홀수 자리도 마찬가지고요. 그러면 크기 `N` 짜리 일이 크기 `N/2`
짜리 둘이 됩니다.

$$A(x) = A_{\text{even}}(x^2) + x\,A_{\text{odd}}(x^2)$$

```text
쪼개기가 성립하는 조건

  A(x) 를 짝수 자리와 홀수 자리로 가른다     A_even 과 A_odd 가 나온다
  둘 다 x² 만 받는다                         평가할 것은 x 가 아니라 x² 의 값이다
  ────────────────
  그러니 x² 의 가짓수가 절반이면 일이 절반짜리 둘로 갈린다
```

**그런 점 묶음이 실제로 있습니다.** 각도를 `N` 등분한 단위원 위의 점 `N` 개예요. `k` 번째
점은 각도 `2πk/N` 이고, 제곱하면 각도가 두 배가 되어 `N/2` 등분 점으로 옮겨 갑니다. 서로
다른 `N` 개가 제곱 뒤에 서로 다른 `N/2` 개가 되는 것이죠. 이 점 묶음을 `ω` 의 거듭제곱으로
적고, 그 점들에서의 값 묶음을 **이산 푸리에 변환**이라 부릅니다.

```text
N = 8 일 때 각도와 제곱

  k        0    1    2    3    4    5    6    7
  각도     0   45°  90°  135° 180° 225° 270° 315°
  제곱하면 0   90° 180°  270°   0°  90° 180°  270°
  ────────────────
  여덟 개가 제곱 뒤에 네 개로 겹친다 — 0° · 90° · 180° · 270°
```

**이 관계가 실제로 값에서 어떻게 나타나는지 봅시다.** `A = [3, 1, 4, 1]` 을 길이 8 로 0 을
채워 평가한 값과, 짝수 자리만 모은 `[3, 4]` · 홀수 자리만 모은 `[1, 1]` 을 길이 4 로 평가한
값을 나란히 놓습니다.

<!--proof:root-split-->

```text
k  짝수 자리 넷의 변환  홀수 자리 넷의 변환  전체 변환 k  전체 변환 k+4
0  7 0                  2 0                  9 0          5 0
1  3 4                  1 1                  3 5.414      3 2.586
2  -1 0                 0 0                  -1 0         -1 0
3  3 -4                 1 -1                 3 -2.586     3 -5.414

  짝수 자리만 모은 계수  [3, 4]
  홀수 자리만 모은 계수  [1, 1]

└ 각 칸은 실수부와 허수부를 한 칸에 적은 것이고 소수 셋째 자리에서 반올림했다.
  「전체 변환 k」 칸과 「전체 변환 k+4」 칸이 왼쪽 두 칸의 같은 재료로 만들어진다 —
  앞쪽은 더한 것이고 뒤쪽은 뺀 것이다. 큰 평가 하나가 절반짜리 둘로 갈렸다
```

**앞 절반은 더한 것이고 뒤 절반은 뺀 것입니다.** 자리 `k` 의 값은 짝수 쪽 값에 홀수 쪽 값을
`ω^k` 배 해서 더한 것이고, 자리 `k + 4` 의 값은 같은 둘을 뺀 것이에요. 각도가 반 바퀴 차이
나면 부호만 뒤집히기 때문입니다. 이 더하고 빼는 한 쌍을 **나비 연산**이라 부릅니다.

```text
나비 연산 하나

  짝수 쪽 값 u ─────────┬────────▶ u + ω^k · v      자리 k
                        │
  홀수 쪽 값 v ──× ω^k ─┴────────▶ u − ω^k · v      자리 k + N/2
```

**이제 남은 값 하나는 패딩 길이 `N` 입니다.** 반으로 계속 쪼개려면 `N` 이 2 의 거듭제곱이어야
하고, 자리마다 곱한 값에서 계수를 다시 얻으려면 `N` 이 결과 길이 `L` 이상이어야 해요. 그
둘을 만족하는 값이 여럿이니 실제로 시험해 봅시다.

```text

         16        4         32  [6, 17, 13, 22, 5]  같다

└ 답은 모든 줄이 같고 나비 연산만 는다. 그래서 결과 길이 이상인 2 의 거듭제곱 중
  가장 작은 것을 고른다
```

**답은 안 바뀌고 나비 연산만 늘어납니다.** 그래서 `L` 이상인 2 의 거듭제곱 중 **가장 작은
것**을 고릅니다. 여기까지가 준비이고, 이제 이 셋을 코드로 옮깁니다 — 값으로 옮기기 · 자리마다
곱하기 · 계수로 되돌리기.

#### 1. 빈 입력을 거르고 결과 길이와 패딩 길이를 정한다

**빈 배열이 들어오면 아래 계산이 성립하지 않습니다.** 길이가 0 이면 결과 길이가 `−1` 이 되고
그 길이로 배열을 잡을 수 없어요. 그래서 갈래 `①` 이 먼저 걸러 냅니다.

```ts
if (a.length === 0 || b.length === 0) return []; // ①

const resultLen = a.length + b.length - 1;
let size = 1;
while (size < resultLen) size <<= 1; // L 이상인 가장 작은 2 의 거듭제곱
```

전개 입력에서 `a.length` 가 4 이고 `b.length` 가 2 라 `①` 의 조건이 거짓입니다. `resultLen`
은 `4 + 2 − 1 = 5` 이고, `size` 는 1 → 2 → 4 → 8 로 세 번 두 배가 되어 8 이 돼요(T1).

```text
T1 의 값

  a.length = 4,  b.length = 2
  ①  4 === 0 || 2 === 0        →  거짓,  계속 진행
  resultLen = 4 + 2 − 1 = 5
  size:  1 < 5 → 2,  2 < 5 → 4,  4 < 5 → 8,  8 < 5 이 거짓 → 멈춤
  ────────────────
  L = 5,  N = 8
```

#### 2. 계수를 복소수 배열의 실수부에 옮긴다

복소수 배열 하나를 **실수부 배열과 허수부 배열 둘**로 나눠 담습니다. 객체 하나에 두 수를
담는 것보다 배열 접근이 곧바르고, `Float64Array` 는 길이를 정할 때 0 으로 채워지므로 남는
칸을 따로 손볼 일이 없어요.

```ts
const aRe = new Float64Array(size); // ②
const aIm = new Float64Array(size);
const bRe = new Float64Array(size);
const bIm = new Float64Array(size);
for (let i = 0; i < a.length; i++) aRe[i] = a[i] as number;
for (let i = 0; i < b.length; i++) bRe[i] = b[i] as number;
```

`a` 의 네 값이 `aRe` 의 앞 네 칸에 들어가고 뒤 네 칸은 0 입니다. `b` 는 두 값이라 앞 두 칸만
채워져요. 허수부는 넷 다 0 입니다(T2).

#### 3. 비트 역순으로 한 번 재배치한다

**짝수 자리와 홀수 자리를 나누는 일을 미리 해 둡니다.** 쪼개기를 끝까지 이어 가면 각
계수가 결국 어느 칸에 놓이는지가 정해져 있고, 그 칸은 **자리 번호의 이진 표기를 뒤집은
값**이에요. 한 번에 그 자리로 옮겨 두면 뒤로는 쪼갤 일이 없습니다.

```ts
for (let i = 1, j = 0; i < size; i++) {
  // ③ j 를 i 의 이진 표기를 뒤집은 값으로 유지한다
  let bit = size >> 1;
  for (; (j & bit) !== 0; bit >>= 1) j ^= bit;
  j ^= bit;
  if (i < j) {
    const swapRe = re[i] as number;
    re[i] = re[j] as number;
    re[j] = swapRe;
  }
}
```

`A` 의 여덟 자리 중 실제로 맞바뀌는 것은 1 과 4, 3 과 6 두 짝입니다. 나머지 넷은 뒤집어도
자기 자리예요. 재배치 뒤 배열은 `3 0 4 0 1 0 1 0` 이 됩니다(T3).

```text
T3 — 자리 번호를 뒤집는다

  자리    0     1     2     3     4     5     6     7
  이진   000   001   010   011   100   101   110   111
  뒤집기 000   100   010   110   001   101   011   111
  새 자리  0     4     2     6     1     5     3     7
  ────────────────
  값     3     0     4     0     1     0     1     0     ← 자리 4·6 은 패딩된 0 이다
```

#### 멈춤 — 맞바꾸는 조건을 「두 자리가 다르면」으로 써도 될 것 같다

`i < j` 라는 조건은 더 넓혀도 될 것처럼 보입니다. 자기 자리가 아닌 것만 맞바꾸면 되니 `i !== j` 가 더
곧바른 표현으로 보여요. **그렇게 쓰면 재배치가 통째로 없던 일이 됩니다.** 자리 1 과 4 를
`i = 1` 에서 한 번 맞바꾸고, `i = 4` 에서 또 한 번 맞바꾸기 때문입니다.

```ts
if (i !== j) {              // ← 이렇게 바꾸면
  const swapRe = re[i] as number;
  re[i] = re[j] as number;
  re[j] = swapRe;
}
```

```text

     1  001          4  100   맞바꾼다

     3  011          6  110   맞바꾼다

     5  101          5  101   지나간다

     7  111          7  111   지나간다

길이 4 · 2 — 패딩 8  [6, 17, 13, 22, 5]  [11, 14, 7, 4, 0]           어긋난다

└ 패딩 길이가 2 인 줄은 그 조건을 실제로 지나간다 — 자리 1 을 뒤집으면 자리 1 이라
  두 판 다 맞바꾸지 않는다. 패딩 길이가 1 인 줄은 그 조건까지 가지도 못한다. 맞바꿀
  짝이 생기는 순간부터 갈리는데, 조건을 넓히면 같은 짝을 i 쪽에서 한 번, j 쪽에서
  또 한 번 맞바꿔 재배치가 통째로 없던 일이 된다
```

**같은 짝을 두 번 맞바꾸면 제자리로 되돌아옵니다.** 그래서 `i < j` 는 최적화가 아니라 정확성
조건이에요. 표의 아래 두 줄은 답이 같은데, 이유가 서로 다릅니다 — 패딩 길이가 2 인 줄은 그
조건을 실제로 지나가지만 뒤집은 자리가 자기 자리라 어느 판도 맞바꾸지 않고, 패딩 길이가 1 인
줄은 그 조건까지 가지도 않아요. **답이 맞는다고 이 줄이 옳은 것은 아닙니다.**

#### 4. 블록 길이를 두 배씩 늘리며 나비 연산을 반복한다

재배치가 끝났으니 이제 **아래에서 위로** 합쳐 올라갑니다. 블록 길이 `len` 이 2 일 때는 이웃한
두 칸을 짝지어 더하고 빼고, 4 일 때는 두 칸 건너뛴 짝을, 8 일 때는 네 칸 건너뛴 짝을
짝짓습니다. 회전 인자 `ω^j` 는 `Math.cos` 과 `Math.sin` 으로 자리마다 만들어요.

```ts
for (let len = 2; len <= size; len <<= 1) {
  const half = len >> 1;
  const ang = ((2 * Math.PI) / len) * (invert ? -1 : 1);
  for (let start = 0; start < size; start += len) {
    for (let j = 0; j < half; j++) {
      const wRe = Math.cos(ang * j); // ④
      const wIm = Math.sin(ang * j);
      const top = start + j;
      const bot = top + half;
      const uRe = re[top] as number;
      const uIm = im[top] as number;
      const vRe = (re[bot] as number) * wRe - (im[bot] as number) * wIm;
      const vIm = (re[bot] as number) * wIm + (im[bot] as number) * wRe;
      re[top] = uRe + vRe;
      im[top] = uIm + vIm;
      re[bot] = uRe - vRe;
      im[bot] = uIm - vIm;
    }
  }
}
```

`A` 의 첫 바퀴(`len = 2`)에서는 짝의 아래쪽이 전부 0 이라 위아래가 같은 값이 됩니다 —
`3 3 4 4 1 1 1 1` 이에요(T4). 둘째 바퀴(`len = 4`)에서 회전 인자에 `i` 가 들어가면서
허수부가 처음으로 0 이 아니게 되고(T5), 셋째 바퀴(`len = 8`)에서 무리수 회전 인자가
들어와 값이 소수로 벌어집니다(T6).

```text
T4·T5·T6 — A 의 세 바퀴

  시작    3    0    4    0    1    0    1    0        (재배치 직후)
  len 2   3    3    4    4    1    1    1    1        허수부 전부 0
  len 4   7    3   -1    3    2    1    0    1        허수부 0 4 0 -4 0 1 0 -1
  len 8   9    3   -1    3    5    3   -1    3        허수부 0 5.414 0 -2.586 …
  ────────────────
  len 4 의 앞 네 칸이 [3, 4] 의 변환이고 뒤 네 칸이 [1, 1] 의 변환이다
```

`B` 도 똑같은 세 바퀴를 지납니다(T7). 항이 둘뿐이라 재배치 뒤 값이 있는 칸이 자리 0 과 4
둘이고, 마지막 바퀴가 끝나면 여덟 자리 전부에 값이 놓여요.

**여기서 회전 인자를 만드는 방법을 하나 정해야 합니다.** `Math.cos` 을 자리마다 다시 부르는
대신, `ω` 를 한 번 구해 두고 곱해 이어 가면 삼각함수 호출이 바퀴마다 두 번으로 줄어요.
곱셈 둘이 삼각함수 둘보다 비용이 작으니 그럴듯한 절약입니다. 실제로 재 봅시다.

```text

  자리마다 다시 부른다   Math.cos(ang·j) · Math.sin(ang·j)    삼각함수 호출이 나비마다 둘
```

#### 멈춤 — 나비 연산의 두 줄을 순서대로 써도 될 것 같다

위쪽 칸과 아래쪽 칸을 각각 한 번씩 쓰니, 값을 지역 변수로 빼지 않고 배열에서 바로 읽어도 될
것처럼 보입니다. **위쪽을 먼저 덮어쓰면 아래쪽이 읽을 값이 사라집니다.**

```ts
re[top] = uRe + vRe;
re[bot] = (re[top] as number) - vRe;    // ← 이렇게 바꾸면
```

이 자리는 실제 값을 봐야 무엇이 어떻게 어긋나는지 확인되는데, 그 대조는 「불변식」 절이 각
바퀴의 값과 함께 합니다. 여기서 기억할 것은 하나예요.

> 나비 연산의 두 출력은 **같은 두 입력**에서 나온다. 하나를 쓰기 전에 둘 다 읽어 둔다.

#### 5. 같은 자리끼리 복소수 곱을 한 번 한다

두 값 표현이 준비됐으니 이제 자리마다 한 번씩 곱합니다. 여기가 이 절차 전체에서 **원래 하려던
곱셈이 실제로 일어나는 유일한 자리**예요.

```ts
for (let i = 0; i < size; i++) {
  const mulRe = // ⑤
    (aRe[i] as number) * (bRe[i] as number) -
    (aIm[i] as number) * (bIm[i] as number);
  const mulIm =
    (aRe[i] as number) * (bIm[i] as number) +
    (aIm[i] as number) * (bRe[i] as number);
  aRe[i] = mulRe;
  aIm[i] = mulIm;
}
```

자리 0 은 양쪽 다 허수부가 0 이라 `9 × 7 = 63` 이고, 나머지 자리는 복소수 곱 공식대로

#### 멈춤 — 반올림이 언제나 정답을 되살릴 것 같다

지금까지 반올림은 `1e-15` 규모의 차이만 지웠습니다. 그러니 계수가 얼마나 커도 반올림이

값이 배정밀도가 담을 수 있는 정수 범위에 가까워지면 그 오차가 0.5 를 넘습니다.

```text

  ────────────────
```

#### 8. 전체 코드

조각을 이어 붙인 것이 아래 코드입니다. 앞에서 안 나온 것이 둘 있어요 — `padLength` 는 3번
걸음의 두 줄을 함수로 뺀 것이고, 변환 안의 허수부 맞바꾸기는 3번 걸음에서 실수부만 보였던
것을 짝지어 채운 것입니다.

```ts
/** `want` 이상인 가장 작은 2 의 거듭제곱. */
function padLength(want: number): number {
  let size = 1;
  while (size < want) size <<= 1;
  return size;
}

function transform(re: Float64Array, im: Float64Array, invert: boolean): void {
  const size = re.length;

  // ③ 비트 역순 재배치 — 자리 `i` 의 이진 표기를 뒤집은 자리가 `j` 다. 두 자리를 한 번만
  // 맞바꾸려고 `i < j` 일 때만 손댄다.
  for (let i = 1, j = 0; i < size; i++) {
    let bit = size >> 1;
    for (; (j & bit) !== 0; bit >>= 1) j ^= bit;
    j ^= bit;
    if (i < j) {
      const swapRe = re[i] as number;
      re[i] = re[j] as number;
      re[j] = swapRe;
      const swapIm = im[i] as number;
      im[i] = im[j] as number;
      im[j] = swapIm;
    }
  }

  // ④ 블록 길이 `len` 을 2 배씩 늘리며 나비 연산을 반복한다. 위쪽 칸은 그대로 두고 아래쪽
  // 칸에 회전 인자를 곱한 값을 더하고 뺀다.
  for (let len = 2; len <= size; len <<= 1) {
    const half = len >> 1;
    const ang = ((2 * Math.PI) / len) * (invert ? -1 : 1);
    for (let start = 0; start < size; start += len) {
      for (let j = 0; j < half; j++) {
        const wRe = Math.cos(ang * j);
        const wIm = Math.sin(ang * j);
        const top = start + j;
        const bot = top + half;
        const uRe = re[top] as number;
        const uIm = im[top] as number;
        const vRe = (re[bot] as number) * wRe - (im[bot] as number) * wIm;
        const vIm = (re[bot] as number) * wIm + (im[bot] as number) * wRe;
        re[top] = uRe + vRe;
        im[top] = uIm + vIm;
        re[bot] = uRe - vRe;
        im[bot] = uIm - vIm;
      }
    }
  }

  // ⑥ 역변환이면 배열 전체를 길이로 한 번 나눈다. 나눗셈은 여기 한 자리뿐이다.
  if (invert) {
    for (let i = 0; i < size; i++) {
      re[i] = (re[i] as number) / size;
      im[i] = (im[i] as number) / size;
    }
  }
}

export function fftMultiply(a: number[], b: number[]): number[] {
  // ① 한쪽이 비어 있으면 곱도 비어 있다. 아래 계산은 길이가 1 이상인 것을 전제한다.
  if (a.length === 0 || b.length === 0) return [];

  const resultLen = a.length + b.length - 1;
  const size = padLength(resultLen);

  // ② 두 계수 배열을 실수부에 옮기고 남는 칸과 허수부는 0 으로 둔다.
  const aRe = new Float64Array(size);
  const aIm = new Float64Array(size);
  const bRe = new Float64Array(size);
  const bIm = new Float64Array(size);
  for (let i = 0; i < a.length; i++) aRe[i] = a[i] as number;
  for (let i = 0; i < b.length; i++) bRe[i] = b[i] as number;

  transform(aRe, aIm, false);
  transform(bRe, bIm, false);

  // ⑤ 같은 자리끼리 복소수 곱 한 번. 여기서 곱 다항식의 값 표현이 나온다.
  for (let i = 0; i < size; i++) {
    const mulRe =
      (aRe[i] as number) * (bRe[i] as number) -
      (aIm[i] as number) * (bIm[i] as number);
    const mulIm =
      (aRe[i] as number) * (bIm[i] as number) +
      (aIm[i] as number) * (bRe[i] as number);
    aRe[i] = mulRe;
    aIm[i] = mulIm;
  }

  transform(aRe, aIm, true);

  // ⑦ 앞 `resultLen` 칸의 실수부를 정수로 반올림한 것이 답이다. 아주 작은 음수를 반올림하면
  // 부호가 붙은 0 이 나오므로 그 자리만 부호 없는 0 으로 맞춘다.
  const out = new Array<number>(resultLen);
  for (let i = 0; i < resultLen; i++) {
    const rounded = Math.round(aRe[i] as number);
    out[i] = rounded === 0 ? 0 : rounded;
  }
  return out;
}
```

### 알아 두면 좋은 개념 — 변환 · 계산 · 역변환

이 절차가 한 일에 이름을 붙이면 **변환 · 계산 · 역변환**입니다. 어려운 연산을 그 자리에서
빨리 하려 하지 않고, 그 연산이 쉬워지는 표현으로 옮겨 계산한 뒤 되돌아오는 방식이에요.

| 무엇 | 변환 | 옮긴 뒤의 연산 | 역변환 |
| --- | --- | --- | --- |
| 이 글 | 계수 → 자리별 값 | 자리마다 곱 한 번 | 값 → 계수 |
| 차분 배열 | 값 → 이웃 차 | 구간 갱신이 두 칸 손보기 | 차 → 값(누적) |
| 로그 자 | 수 → 로그 | 곱셈이 덧셈 | 로그 → 수 |

이 편의 어느 값이 그것이었는지 확인해 둡시다. `[3, 1, 4, 1]` 이 `9 3 -1 3 5 3 -1 3` 로 바뀐 것이
변환이고, 그 여덟 값을 `B` 의 여덟 값과 자리마다 곱한 것이 「옮긴 뒤의 연산」이며, 그 결과를
`[6, 17, 13, 22, 5]` 로 되돌린 것이 역변환입니다.

```text
같은 모양이 어디에 또 나오는가

  이 글      곱셈이 O(n·m) → 자리마다 한 번  왕복 비용이 O(N log N)
  차분 배열  구간 갱신이 O(길이) → 두 칸     왕복 비용이 O(N)
  로그 자    곱셈 → 덧셈                     왕복 비용이 표 읽기 두 번
  ────────────────
  이득이 남으려면 왕복 비용이 옮긴 뒤의 이득보다 작아야 한다
```

[차분 배열 가이드](../../array/diffArrayRangeUpdate/diffArrayRangeUpdate-guide.md)가 같은
모양을 정수 덧셈만으로 보입니다. 왕복 비용이 그쪽은 배열 한 번 읽기이고 이쪽은 변환 세 번이라,
같은 방식이라도 이득이 남는 규모가 갈려요.

## 파트 2 — 적용 조건 · 보장 · 비용

이 절차가 어떤 문제에 맞는지, 무엇을 늘 지키는지, 비용이 어떻게 나오는지를 따집니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **두 수열의 합성곱을 구하는 문제.** 출력 자리 `k` 의 값이 입력 자리 `i` 와 `j` 를 `i + j = k`
  로 짝지어 합한 꼴이면 그대로 맞습니다. 다항식 곱, 큰 정수 곱, 확률분포의 합, 신호의 필터가
  전부 이 모양이에요.
- **두 입력의 길이가 둘 다 크다.** 한쪽이 아주 짧으면(수십 이하) 자리 짝을 그냥 지나는 편이
  적습니다 — 이 절차는 짧은 쪽 길이와 무관하게 패딩 길이에 비례한 비용을 씁니다.
- **계수가 정수이고 참값이 배정밀도 범위 안에 있다.** 길이와 계수 상한을 곱해 본 값이
  `10^15` 자리에 못 미치면 반올림이 정답을 되살립니다.
- **결과 전체가 필요하다.** 한두 자리만 필요하면 그 자리만 정의대로 세는 편이 적어요.

```text
맞는 모양과 안 맞는 모양

  길이 100,000 씩 · 계수 1,000 이하    맞는다     참값이 10^11 자리다
  길이 100,000 과 3 · 계수 1,000 이하  안 맞는다  자리 짝이 30 만 개뿐이다
  길이 100,000 씩 · 계수 10^7          안 맞는다  참값이 10^19 자리라 반올림이 못 되살린다
  자리 하나만 필요                     안 맞는다  그 자리만 세면 100,000 번이다
```

#### 문제에서 이것을 떠올리게 하는 단서

- 「두 수열의 **모든 짝**을 더한다」·「자리 번호가 더해지는 짝」·「합성곱」이라는 말이 나온다.
- 출력 길이가 **입력 길이의 합에서 1 을 뺀 값**으로 명시돼 있다.
- 이중 반복으로 적으면 곱셈이 `10^9` 을 넘는데 시간 제한이 1~2 초다.
- 「큰 정수의 곱」·「자릿수가 10 만인 수 둘을 곱하라」처럼 자리올림만 다르고 뼈대가 같은 문제다.
- 「어떤 값이 나오는 경우의 수를 전부 세라」처럼 **두 분포를 합치는** 문제다.

```text
단서에서 이 절차까지

  「모든 짝을 더한다」   →  합성곱이다
  출력 길이 = n + m − 1  →  선형 합성곱이다(순환이 아니다)
  n·m 이 10^9 을 넘는다  →  자리 짝을 지나는 것으로는 안 된다
  계수가 정수이고 작다   →  부동소수 변환으로 충분하다
```

#### 실제로 쓰이는 곳

- **GMP(GNU Multiple Precision Arithmetic Library)** — 아주 큰 정수의 곱셈에 Schönhage–
  Strassen 방식의 FFT 를 씁니다. 매뉴얼의 「FFT Multiplication」 절이 *"At large to very
  large sizes a Fermat style FFT multiplication is used, following Schönhage and
  Strassen"* 이라 적었습니다.
  ([GMP 매뉴얼 · FFT Multiplication](https://gmplib.org/manual/FFT-Multiplication), 조회 2026-09-06)
- **SciPy** — `scipy.signal.fftconvolve` 가 *"Convolve two N-dimensional arrays using FFT."*
  로 정의돼 있고, 설명 첫 문장이 *"Convolve `in1` and `in2` using the fast Fourier
  transform method, with the output size determined by the mode argument."* 입니다.
  ([SciPy 문서 · fftconvolve](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.fftconvolve.html), 조회 2026-09-06)
- **NTL(A Library for doing Number Theory)** — 정수 계수 다항식 곱셈이 네 방식 중 하나를
  고르는데, 그중 둘이 FFT 계열입니다. 문서가 *"Schoenhage & Strassen --- performs an FFT by
  working modulo a 'Fermat number' of appropriate size"* 와 *"CRT/FFT --- performs an FFT by
  working modulo several small primes"* 로 적었고, 나머지 둘이 classical 과 Karatsuba 입니다.
  ([NTL 문서 · ZZX](https://libntl.org/doc/ZZX.cpp.html), 조회 2026-09-06)
- **FFTW** — 변환 자체를 전담하는 라이브러리로, 스스로를 *"a C subroutine library for
  computing the discrete Fourier transform (DFT) in one or more dimensions, of arbitrary
  input size, and of both real and complex data"* 라 소개합니다. SciPy 와 여러 수치
  라이브러리가 이것을 부품으로 씁니다.
  ([FFTW 홈페이지](https://www.fftw.org/), 조회 2026-09-06)

#### 경쟁 설계와의 대조

**카라추바 곱셈**과 견줍니다. 같은 문제를 풀고, 부동소수를 한 번도 쓰지 않으며, 두 계수 배열을
절반씩 잘라 절반 곱 **셋**으로 절반 곱 넷을 대신하는 방식이에요. 길이가 32 이하로 내려가면
정의 그대로 곱합니다.

```text
절반 곱 넷을 셋으로

  h = 자른 자리 — 두 길이 중 긴 쪽의 절반이다
  A = A_low + x^h·A_high        B = B_low + x^h·B_high
  ────────────────
  z0 = A_low·B_low                                    절반 곱 1
  z2 = A_high·B_high                                  절반 곱 2
  z1 = (A_low + A_high)(B_low + B_high) − z0 − z2     절반 곱 3
  ────────────────
  A·B = z0 + x^h·z1 + x^2h·z2
```

**대조에 쓰는 입력이 전개 입력과 다릅니다.** 전개 입력은 길이가 4 와 2 라 두 설계 다 정의
그대로 곱는 자리에서 끝나 계수가 안 갈려요. 그래서 같은 생성식으로 길이 512 와 1,024 짜리
배열을 만들어 씁니다 — 계수는 선형 합동 생성기로 `[0, 1000]` 을 고르게 지나고, 두 설계에
같은 배열을 넣고 답이 같은지 매 실행에서 대조합니다.

**정확성 축은 길이에 따라 순서가 뒤집힙니다.** 길이 64 에서는 카라추바가 계수 상한
15,000,000 까지 정답을 내고 이 글의 절차는 10,000,000 까지예요 — 반올림 오차가 먼저 답을 바꿉니다.
길이 1,024 에서는 반대로 이 글의 절차가 2,000,000 까지, 카라추바가 1,000,000 까지입니다 —

### 수식 정의와 유도

$N$ 을 2 의 거듭제곱이라 하고, 길이 $N$ 짜리 계수 배열 $a$ 에 대해 다음을 정의합니다.

$$\omega = e^{2\pi i/N},\qquad \operatorname{DFT}(a)[k] = \sum_{j=0}^{N-1} a_j\,\omega^{jk}\quad (k = 0,\dots,N-1)$$

```text
정의에 들어가는 세 값

  N        변환 길이. 2 의 거듭제곱이다
  ω        각도 2π/N 인 복소수.  ω^N = 1,  ω^(N/2) = -1,  ω² = N/2 등분 단위근
  a_j      자리 j 의 계수.  j 가 배열 길이를 넘으면 0 이다
```

$\omega$ 는 각도 $2\pi/N$ 인 단위원 위의 점이고, $\omega^N = 1$ · $\omega^{N/2} = -1$ ·
$\omega^2 = e^{2\pi i/(N/2)}$ 입니다. 마지막 것이 **제곱하면 $N/2$ 등분 단위근이 된다**는
사실이고, 아래 유도가 그것 하나에서 나옵니다.

**정의를 작은 값에 넣어 봅시다.** $N = 8$ 이고 $a = [3, 1, 4, 1, 0, 0, 0, 0]$ 일 때
$\operatorname{DFT}(a)[1]$ 은 $3 + \omega + 4\omega^2 + \omega^3$ 입니다. $\omega =
\tfrac{\sqrt2}{2}(1 + i)$ · $\omega^2 = i$ · $\omega^3 = \tfrac{\sqrt2}{2}(-1 + i)$ 를 넣으면
실수부가 $3 + \tfrac{\sqrt2}{2} - \tfrac{\sqrt2}{2} = 3$ 이고 허수부가 $\tfrac{\sqrt2}{2} + 4
+ \tfrac{\sqrt2}{2} = 4 + \sqrt2 \approx 5.414$ 예요. 여덟 자리를 전부 이렇게 계산해 절차가
낸 값과 견줍니다.

```text
DFT(a)[1] 을 정의로 손 계산

  3 · ω⁰ = 3
  1 · ω¹ = 0.707 + 0.707i
  4 · ω² = 4i
  1 · ω³ = -0.707 + 0.707i
  ────────────────
  합 = 3 + (4 + √2)i ≈ 3 + 5.414i
```

```text
  판정은 반올림 전 값의 차가 1e-9 보다 작은가로 했다
```

**이제 유도입니다.** 정의의 합을 짝수 자리와 홀수 자리로 가릅니다. $j = 2t$ 와 $j = 2t+1$ 로
나눠 쓰면 이렇습니다.

$$\operatorname{DFT}(a)[k] = \sum_{t=0}^{N/2-1} a_{2t}\,\omega^{2tk} + \omega^{k}\sum_{t=0}^{N/2-1} a_{2t+1}\,\omega^{2tk}$$

```text
합을 둘로 가르는 셈

  j = 0 2 4 6 …      a_(2t) 만 모은다        지수가 ω^(2tk)
  j = 1 3 5 7 …      a_(2t+1) 만 모은다      지수가 ω^((2t+1)k) = ω^k · ω^(2tk)
  ────────────────
  ω^k 는 t 에 안 달렸으므로 합 밖으로 뺀다
```

$\omega^2$ 가 $N/2$ 등분 단위근이므로 두 합은 각각 **길이 $N/2$ 짜리 변환**입니다. 짝수 자리만
모은 배열을 $e$, 홀수 자리만 모은 배열을 $o$ 라 하면 $k < N/2$ 에서 이렇게 됩니다.

$$\operatorname{DFT}(a)[k] = \operatorname{DFT}(e)[k] + \omega^{k}\,\operatorname{DFT}(o)[k]$$

```text
지금까지 얻은 것

  k < N/2 의 값 N/2 개      짝수 쪽 변환과 홀수 쪽 변환에서 만들었다
  k ≥ N/2 의 값 N/2 개      아직 안 만들었다
  ────────────────
  남은 절반을 정의에 다시 넣어 본다
```

**나머지 절반은 같은 두 값에서 나옵니다.** $k$ 를 $k + N/2$ 로 바꿔 넣으면 짝수 쪽 지수는
$\omega^{2t(k+N/2)} = \omega^{2tk}\cdot(\omega^{N})^{t} = \omega^{2tk}$ 라 그대로이고, 홀수
쪽 앞에 붙는 인자만 $\omega^{k+N/2} = \omega^{k}\cdot\omega^{N/2} = -\omega^{k}$ 로 부호가
뒤집힙니다.

$$\operatorname{DFT}(a)[k+N/2] = \operatorname{DFT}(e)[k] - \omega^{k}\,\operatorname{DFT}(o)[k]$$

```text
두 식이 만드는 한 쌍

  u = DFT(e)[k]              위쪽 재료
  v = ω^k · DFT(o)[k]        아래쪽 재료
  ────────────────
  자리 k 는 u + v,  자리 k + N/2 는 u − v — 재료 둘로 자리 둘을 낸다
```

두 식이 코드의 나비 연산 네 줄과 같은 것입니다. 식의 $\omega^k$ 가 코드에서는 `wRe` 와 `wIm`
두 실수이고, $\operatorname{DFT}(e)[k]$ 가 `uRe`·`uIm` 이며 $\omega^k \operatorname{DFT}(o)[k]$
가 `vRe`·`vIm` 이에요.

```ts
// 위 두 식을 그대로 옮긴 조각
const vRe = (re[bot] as number) * wRe - (im[bot] as number) * wIm;
re[top] = uRe + vRe; // DFT(a)[k]
re[bot] = uRe - vRe; // DFT(a)[k + N/2]
```

**비용의 점화식이 여기서 나옵니다.** 길이 $N$ 짜리 변환이 길이 $N/2$ 짜리 둘과 나비 연산
$N/2$ 개로 이뤄지므로, 나비 연산 수 $F(N)$ 은 이렇습니다.

$$F(N) = 2F(N/2) + \tfrac{N}{2},\qquad F(1) = 0$$

```text
점화식을 펴는 셈

  F(N)/N        = F(N/2)/(N/2) + 1/2
  F(N/2)/(N/2)  = F(N/4)/(N/4) + 1/2
  …
  F(2)/2        = F(1)/1       + 1/2
  ────────────────
  1/2 이 t 번 더해져 F(N)/N = t/2 다
```

$N = 2^t$ 로 두고 양변을 $N$ 으로 나누면 $F(N)/N = F(N/2)/(N/2) + \tfrac12$ 이고, 이것을 $t$
번 펴면 $F(N)/N = t/2$ 예요. 즉 $F(N) = \tfrac{N}{2}\log_2 N$ 입니다. 나비 하나가 쓰는 기본
연산이 11 번, 삼각함수 호출이 2 번이고 변환을 세 번 부르므로, 자리별 곱 $6N$ 과 나눗셈 $2N$
을 더해 전체가 이렇게 닫힙니다.

$$\text{기본 연산} = 33\cdot\tfrac{N}{2}\log_2 N + 8N,\qquad \text{삼각함수 호출} = 3N\log_2 N$$

```text

  나비 하나       기본 연산 11 번,  삼각함수 2 번
  변환 하나       나비 (N/2)·log₂N 개
  변환 세 번      33 = 3 × 11,  6 = 3 × 2 → 삼각함수는 6·(N/2)·log₂N = 3N·log₂N
  나비 밖         자리별 곱 6N,  나눗셈 2N  →  합쳐서 8N
```

### 불변식 — 블록 길이 `len` 바퀴를 마치면 각 `len` 칸 블록이 그 블록이 맡은 부분열의 변환이다

**언제 참인가부터 적습니다.** 나비 연산의 바퀴 하나가 끝난 시점입니다. 바퀴 도중에는 참이
아니에요 — 한 블록 안에서 위쪽 칸만 갱신되고 아래쪽 칸이 아직 옛값인 순간이 있으니까요.

**무엇이 참인가.** 배열을 앞에서부터 `len` 칸씩 끊었을 때, 각 블록은 원래 배열에서
`N/len` 칸마다 하나씩 고른 부분열의 변환값 `len` 개를 담고 있습니다. 어느 나머지에서
시작하는 부분열인지는 **블록 번호의 이진 표기를 뒤집은 값**이 정해요.

```text
N = 8 일 때 블록이 맡는 부분열

  블록 길이  블록 0                블록 1        블록 2    블록 3
          1  자리 0                자리 4        자리 2    자리 6

          4  자리 0 2 4 6          자리 1 3 5 7
          8  자리 0 1 2 3 4 5 6 7
  ────────────────
  블록 길이 1 의 블록 4~7 은 자리 1 · 5 · 3 · 7 이다
```

**기저는 재배치 직후입니다.** 그때 `len` 은 1 이고 블록 하나에 칸이 하나뿐이라, 길이 1 짜리
변환이 자기 자신이라는 정의로 곧바로 성립해요. 재배치가 각 칸에 자리 번호를 뒤집은 자리의
값을 놓아 두었으니 「블록이 맡는 부분열」도 그 한 자리입니다.

**바퀴 하나가 그것을 이어받는 것을 값으로 봅시다.** 길이 8 짜리 실행에서 네 시점의 각 블록을
정의 그대로 변환한 값과 견줍니다.

**이제 불변식을 지키던 줄을 깨뜨려 봅시다.** 나비 연산이 불변식을 이어받게 하는 것은 **두
출력이 같은 두 입력에서 나온다**는 것이고, 그것을 지키는 줄이 위쪽 칸을 지역 변수로 빼 두는
자리입니다. 아래쪽 칸을 계산할 때 배열의 위쪽 칸을 되읽으면 그 값은 이미 덮인 뒤예요.

```ts
re[bot] = (re[top] as number) - vRe;    // ← 이렇게 바꾸면
```

<!--proof:inv-mutant-->

```text
자리 k  정본  위쪽 칸을 되읽은 판  판정
     0     6                   10  어긋난다
     1    17                   19  어긋난다
     2    13                   15  어긋난다
     3    22                   13  어긋난다
     4     5                   10  어긋난다

입력                  정본                위쪽 칸을 되읽은 판   판정
길이 4 · 2 — 패딩 8   [6, 17, 13, 22, 5]  [10, 19, 15, 13, 10]  어긋난다
길이 2 · 2 — 패딩 4   [3, 10, 8]          [4, 10, 6]            어긋난다
값이 전부 0 — 패딩 2  [0, 0]              [0, 0]                같다
길이 1 · 1 — 패딩 1   [42]                [42]                  같다

└ 값이 전부 0 인 줄은 나비 연산을 실제로 지나간다 — 더하고 뺄 값이 0 이라 덮어쓴
  값을 되읽어도 결과가 같다. 패딩 길이가 1 인 줄은 나비 연산까지 가지도 못한다.
  0 이 아닌 값이 하나라도 있으면 위쪽 칸이 먼저 덮이고 아래쪽 칸이 그 덮인 값을 읽는다
```

**다섯 자리가 전부 틀립니다.** 정본이 `[6, 17, 13, 22, 5]` 인데 `[10, 19, 15, 13, 10]` 이
나와요. 되읽은 값이 `uRe + vRe` 이므로 아래쪽 칸이 `uRe + vRe − vRe = uRe` 가 되고, 빼기가
사라져 블록이 자기 부분열의 변환을 담지 못합니다. 아래 표의 끝 두 줄은 답이 같은데, 값이
전부 0 인 줄은 나비 연산을 실제로 지나가면서도 더하고 뺄 값이 0 이라 같은 것이고, 패딩
길이가 1 인 줄은 나비 연산까지 가지도 않은 것이에요. **둘 다 이 줄이 옳다는 증거는
아닙니다.**

### 비용 계산

#### 비용을 세는 과정

**세는 단위를 먼저 정합니다.** 기본 연산은 실수 한 쌍에 대한 곱·덧셈·뺄셈 각 한 번이고,
삼각함수 호출은 `Math.cos`·`Math.sin` 한 번씩입니다. 둘을 따로 세는 이유는 값이 다르기
때문이에요 — 삼각함수 호출이 곱셈보다 훨씬 비쌉니다.

**나비 연산 하나를 세어 봅시다.** T4 의 한 나비를 그대로 따라가면 회전 인자의 각도 계산 한
번, 복소수 곱 하나(곱 넷과 덧뺄셈 둘), 위아래 네 칸의 덧뺄셈 넷이라 기본 연산 11 번이고
삼각함수 호출이 2 번입니다.

```text
나비 하나의 연산

  ang * j                                     곱 1
  vRe = re[bot]·wRe − im[bot]·wIm             곱 2  뺄셈 1
  vIm = re[bot]·wIm + im[bot]·wRe             곱 2  덧셈 1
  re[top] · im[top] · re[bot] · im[bot]       덧뺄셈 4
  ────────────────
  기본 연산 11 번,  Math.cos 과 Math.sin 각 1 번
```

**바퀴와 나비의 수를 셉니다.** T4·T5·T6 이 한 변환의 세 바퀴이고, 바퀴 하나가 배열 전체를
`len` 칸씩 끊어 블록마다 `len/2` 개의 나비를 하므로 바퀴마다 `N/2` 개예요. 바퀴 수는 `len` 이
2 에서 `N` 까지 두 배씩이라 `log₂ N` 개입니다. 변환은 T6 · T7 · T10 에서 세 번 불려요.

**나비 밖의 연산도 셉니다.** T8 의 자리별 복소수 곱이 자리마다 6 번이라 `6N` 이고, T11 의
나눗셈이 자리마다 2 번이라 `2N` 입니다. 재배치는 값을 옮기기만 해서 산술이 없어요.

```text
한 변환의 나비 수

  바퀴 수          log₂ N 개        len 이 2 에서 N 까지 두 배씩
  바퀴마다 나비    N/2 개           블록 N/len 개 × 블록마다 len/2 개
  ────────────────
  변환 하나에 (N/2)·log₂ N 개,  세 번 부르므로 (3N/2)·log₂ N 개
```

<!--proof:perf-formula-->

```text
길이 n = m  패딩 길이 N  바퀴  나비 연산 전부  기본 연산  삼각함수  닫힌 형태와
         2            4     2              12        164        24  같다
         4            8     3              36        460        72  같다
         8           16     4              96      1,184       192  같다
        16           32     5             240      2,896       480  같다
     1,024        2,048    11          33,792    388,096    67,584  같다

  나비 하나가 쓰는 기본 연산   11 번
  나비 하나가 부르는 삼각함수  2 번
  변환을 부르는 횟수           3 번
  나비 밖의 기본 연산          8N 번 — 자리별 곱 6N 과 나눗셈 2N
```

**닫힌 형태가 실측과 맞습니다.** 길이 1,024 에서 나비가 33,792 개이고 기본 연산이 388,096 번,
삼각함수 호출이 67,584 번이에요.

#### 케이스별 비용과 그 경계

**이 절차의 비용은 값에 안 달렸습니다.** 계수가 무엇이든 바퀴 수와 나비 수가 같고, 분기가
값에 따라 갈리는 자리가 없어요. 그래서 최악과 평균이 같은 값이고, 경계는 상한이 아니라
**타이트한 값**입니다.

| 케이스 | 기본 연산 | 경계의 종류 | 무엇이 그것을 정하는가 |
| --- | --- | --- | --- |
| 최악 | $33\cdot\tfrac{N}{2}\log_2 N + 8N$ | 타이트 $\Theta$ | 패딩 길이 `N` 하나 |
| 평균 | 같다 | 타이트 $\Theta$ | 입력 분포와 무관하다 |
| 최선 | 같다 | 타이트 $\Theta$ | 값이 전부 0 이어도 같다 |

**총식을 `n` 과 `m` 으로 적으면 이렇습니다.** `N` 은 `n + m − 1` 이상인 가장 작은 2 의
거듭제곱이므로 `n + m − 1 ≤ N < 2(n + m − 1)` 이고, 따라서 전체가
$\Theta((n+m)\log(n+m))$ 이에요. 앞뒤로 붙는 항은 배열 넷을 잡는 `4N` 칸과 반환 배열 `L` 칸
뿐이고 정렬이나 전처리는 없습니다.

**보장의 종류는 최악 보장입니다.** 무작위성을 쓰지 않고 입력 분포를 가정하지 않아요. 기댓값이
아니라 모든 입력에서 같은 값입니다.

```text
보장을 두 축으로

  케이스     최악 · 평균 · 최선이 전부 같은 값이다
  경계       상한이 아니라 타이트한 값이다 — 세어서 나온 식이 곧 실측이다
  ────────────────
  정확성 보장은 별개다 — 계수 크기와 길이에 매인다
```

**정확성 보장은 비용 보장과 다릅니다.** 비용은 어떤 입력에서나 같지만, 답이 정확한지는 참값이
배정밀도 범위 안인가에 달렸어요. 그 한계는 「멈춤 — 반올림이 언제나 정답을 되살릴 것 같다」
에서 실행으로 쟀습니다.

### 스스로 점검하기

**이 글이 한 일은 표현을 바꾼 것입니다.** 계수 표현에서는 자리 짝마다 곱셈이 필요하지만 값
표현에서는 자리마다 한 번이면 되고, 그 왕복 비용을 단위근으로 줄인 것이 이 절차예요. 값으로
옮기는 데 `(N/2)log₂N` 개의 나비 연산이 들고, 그것을 세 번 하면 곱셈이 끝납니다.

```text
이 글이 세운 것

  값 표현      점 N 개에서의 값.  자리마다 한 번 곱하면 그것이 곱의 값 표현이다
  단위근       제곱하면 가짓수가 절반으로 주는 점 묶음
  나비 연산    절반짜리 둘에서 자리 둘을 낸다 — u + v 와 u − v
  ────────────────
  변환 두 번 + 자리별 곱 + 역방향 변환 한 번이 전부다
```

**예측 문제 하나 풀어 볼까요?** 길이 513 과 512 인 배열 둘을 곱하면 결과 길이와 패딩 길이가
얼마이고, 변환 하나에 나비 연산이 몇 개일까요?

<!--proof:check-pad-->

```text
두 길이        결과 길이  패딩 길이  바퀴  변환 하나의 나비
4 × 2                  5          8     3                12
5 × 5                  9         16     4                32
8 × 1                  8          8     3                12
513 × 512          1,024      1,024    10             5,120
1,000 × 1,000      1,999      2,048    11            11,264
```

<!--check:padTo1024-->
답: 결과 길이는 `513 + 512 − 1 = 1,024` 이고, 1,024 가 이미 2 의 거듭제곱이라 패딩 길이도
1,024 입니다. 바퀴가 10 개이고 바퀴마다 나비가 512 개라 변환 하나에 5,120 개예요.
<!--/check-->

**하나 더 물어봅시다.** T11 에서 배열 전체를 8 로 나눴는데, 그 나눗셈을 T9 와 T10 의 바퀴마다
2 로 나누는 것으로 바꾸면 답이 어떻게 될까요?

```text
나눗셈을 어디서 하는가

  지금      바퀴 셋을 마친 뒤 8 로 한 번          나눗셈 N 번
  바꾸면    바퀴마다 2 로,  2 × 2 × 2 = 8         나눗셈 N·log₂N 번
```

<!--check:divideEachRound-->
답: 바퀴가 세 번이므로 `2 × 2 × 2 = 8` 로 나뉘어 **같은 답**이 나옵니다. 다만 나눗셈 횟수가
`N` 번에서 `N·log₂N` 번으로 늘고, 나눗셈이 바퀴마다 끼면 중간 값이 작아져 오차가 달라집니다.
`N` 이 2 의 거듭제곱이라 이 등식이 성립하는 것이고, 길이가 2 의 거듭제곱이 아닌 변환에서는
같은 방식으로 나눌 수 없어요.
<!--/check-->
