# 확장 유클리드 호제법 — 나머지를 만든 몫 하나가 계수 갱신까지 정한다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 확인하고, 그 그림을 읽는 데 필요한 것을 정한 다음, 계수를 대입해 **찾던**
방법에서 계수를 걸음마다 **만들어 내는** 방법까지 갑니다. 마지막에는 실제로 동작하는 코드를
조각으로 나눠 만듭니다.

### 전체 컨셉

두 정수 `a`, `b` 의 최대공약수 `g` 는 언제나 `a·x + b·y` 꼴로 적을 수 있습니다. 그렇게 적어
주는 정수 쌍 `(x, y)` 를 **베주 계수**라고 부르고, 이 절차가 만드는 것은 `g` 와 그 쌍
`(x, y)` 셋입니다.

```text
extendedEuclidean(-510n, 183n) 이 내는 것

  g = 3                                  -510 과 183 의 최대공약수
  x = -14,  y = -39
  -510 × (-14) + 183 × (-39)  =  7,140 - 7,137  =  3      ← 셋이 이 식을 만족한다
```

`g` 만 필요하면 유클리드 호제법으로 끝납니다. 그 절차는 큰 쪽을 작은 쪽으로 나눈 나머지로 두
수를 바꿔 가며 나머지가 0 이 되는 자리의 값을 답으로 내고, 몫은 쓰고 나서 버려요. **버린 몫이
이 글의 재료입니다.**

```text
510 과 183 의 나머지 수열 — 몫을 버리지 않고 함께 적으면

  510 = 2 × 183 + 144        몫 2
  183 = 1 × 144 +  39        몫 1
  144 = 3 ×  39 +  27        몫 3
   39 = 1 ×  27 +  12        몫 1
   27 = 2 ×  12 +   3        몫 2      ← 이 3 이 최대공약수다
   12 = 4 ×   3 +   0        몫 4
```

**이 글의 결정적인 관찰은 하나입니다.** 위 수열의 **모든 항이 처음 두 수의 정수 조합으로
적힌다**는 것이에요. `144 = 510 - 2×183` 이고, 그 아래 `39 = 183 - 144 = 183 - (510 - 2×183)
= -510 + 3×183` 입니다. 한 항을 `510 · s + 183 · t` 로 적을 때의 두 계수를 `s` 와 `t` 라
부르면, 한 항 아래로 갈 때마다 `s` 와 `t` 도 **같은 몫으로** 함께 바뀝니다.

```text
나머지마다 계수 두 개를 함께 적어 두면

  항    값     510 · s + 183 · t 로 적으면        s      t
  r0   510     510 × 1   + 183 × 0                1      0
  r1   183     510 × 0   + 183 × 1                0      1
  r2   144     510 × 1   + 183 × (-2)             1     -2      ← s, t 도 몫 2 로 갱신됐다
  r3    39     510 × (-1) + 183 × 3              -1      3      ← 몫 1 로 갱신
  r6     3     510 × 14  + 183 × (-39)           14    -39      ← 답의 계수가 여기 있다
```

계수를 따로 찾아 나설 필요가 없다는 뜻입니다. 나머지를 만드는 그 자리에서 계수 두 벌을 같은
식으로 갱신하면, 나머지가 0 이 되는 순간 그 앞 항의 계수가 곧 답이에요. 걸음 수는 유클리드
호제법과 똑같고, 걸음마다 곱셈 두 번과 뺄셈 두 번이 더 붙을 뿐입니다.

```text
계수를 대입해 찾는 방법과 함께 만드는 방법

  x 를 0, ±1, ±2, … 대입한다   후보 수가 |x| 에 비례한다   2.2e18 개
  걸음마다 계수를 갱신한다      나눗셈 횟수와 같다          89 번
                                └ 피보나치 이웃인 19 자리 두 수에서 잰 값이다.
                                  같은 19 자리라도 입력에 따라 3 개와 2 번이 되기도 한다
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **유클리드 호제법.** 두 수를 나머지로 바꿔 나가며 최대공약수를 구하는 절차입니다. 이 글은
  그 나머지 수열을 그대로 쓰고 몫만 더 씁니다 —
  [최대공약수 가이드](../gcd/gcd-guide.md)가 그 절차와 걸음 수 상한을 다룹니다.
- **나머지 있는 나눗셈.** 정수 하나를 다른 정수로 나누면 몫과 나머지가 하나씩 정해지고,
  나머지가 나누는 수보다 작다는 것. 이 글의 갱신식이 그 성질을 그대로 씁니다.
- **정수 조합.** 두 수에 정수를 곱해 더한 값이 무엇이 되는지 — 특히 어떤 수가 두 수를 모두
  나누면 그 두 수의 정수 조합도 나눈다는 성질입니다.
- **`bigint`** — JavaScript 에서 자릿수 제한이 없는 정수 타입입니다. 리터럴에 `n` 을 붙여
  적고, 계수가 입력만큼 커져도 넘치지 않아요.
- **`bigint` 의 `/` 가 0 방향으로 자르고 피제수의 부호를 따른다는 것.** `-12n / 5n` 이
  `-2n` 입니다. 이 글은 그래서 부호를 먼저 떼어 냅니다.

마지막 두 항목이 흐릿하면 뒤가 어긋납니다. 부호를 떼고 마지막에 다시 붙이는 자리가 있는데,
그 자리는 전개의 첫 걸음과 불변식 절의 경계 표에서 값으로 확인해요.

### 아이디어 상세 — 나머지마다 계수를 함께 적어 두는 방법을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function extendedEuclidean(
  a: bigint,
  b: bigint,
): { g: bigint; x: bigint; y: bigint };
```

- 입력: 정수 둘. `a` 와 `b` 에 각각 음수와 0 이 들어올 수 있습니다.
- 출력: `{ g, x, y }`. `g` 는 `|a|` 와 `|b|` 의 최대공약수로 언제나 0 이상이고,
  `a·x + b·y = g` 를 정확히 만족해야 합니다.
- 계약의 경계: `a = b = 0` 이면 셋 다 0 입니다. `b = 0` 이면 `g = |a|` 이고 `a·x = g` 를
  만족하는 `x` 를, `a = 0` 이면 `g = |b|` 이고 `b·y = g` 를 만족하는 `y` 를 냅니다.
- 제약: 계약이 `bigint` 라 두 인자의 자릿수에 상한이 없습니다. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `a` · `b` | 두 입력 | 음수·0·양수 모두 가능 |
| `A` · `B` | 두 입력의 절댓값 | 절차는 이 둘로 시작한다 |
| `g` | 최대공약수 | 반환값의 첫 자리, 언제나 0 이상 |
| `x` · `y` | 베주 계수 | `a·x + b·y = g` 를 만족하는 정수 쌍 |
| `q` | 이번 걸음의 몫 | `r0` 를 `r1` 로 나눈 몫 |
| `r0` · `r1` | 나머지 수열의 이웃한 두 항 | 처음 값은 `A` 와 `B` |
| `s0` · `s1` | 두 항에 붙는 `a` 쪽 계수 | 처음 값은 1 과 0 |
| `t0` · `t1` | 두 항에 붙는 `b` 쪽 계수 | 처음 값은 0 과 1 |

`A` 와 `B` 는 변수로 두지 않고 `r0`·`r1` 의 처음 값이 됩니다. 계수가 두 벌인 것은 조합이
`a` 쪽과 `b` 쪽 둘로 이루어지기 때문이고, 벌마다 항이 둘인 것은 갱신식이 **이웃한 두 항**을
쓰기 때문이에요.

```text
기호가 어디에 사는가

  a·b          함수 인자              읽고 나서 부호만 떼어 따로 적어 둔다
  A·B          그 절댓값              r0·r1 의 처음 값이다
  q            걸음 안의 임시 값       세 벌의 갱신에 전부 같은 값이 쓰인다
  r0·r1        나머지 수열            0 이 되면 멈춘다
  s0·s1        a 쪽 계수              끝났을 때의 s0 가 x 가 된다
  t0·t1        b 쪽 계수              끝났을 때의 t0 가 y 가 된다
```

가장 먼저 떠오르는 방법으로 시작합시다. **`g` 를 유클리드 호제법으로 먼저 구해 두고, `x` 를
`0, ±1, ±2, …` 로 대입해 보는 것**이에요. `g - a·x` 가 `b` 로 나누어떨어지는 순간 그 몫이
`y` 입니다. 정의를 그대로 옮긴 풀이입니다.

```text
전개 입력에서 대입해 보면

  g = 3,  a = -510,  b = 183
  x =  0   →  (3 - (-510)×0) / 183 = 3/183        정수가 아니다
  x =  1   →  (3 + 510) / 183 = 513/183           정수가 아니다
  x = -1   →  (3 - 510) / 183 = -507/183          정수가 아니다
  …
  x = -14  →  (3 - 7,140) / 183 = -7,137/183 = -39   ✓ 찾았다
              └ 0 부터 ±14 까지 전부 대입하면 29 개다
```

이 방법은 답이 맞아요. 그런데 대입 횟수가 `|x|` 에 비례하고, `|x|` 는 입력의 **값**만큼 커질
수 있습니다. 자릿수를 늘려 가며 재 봅시다 — 마지막 몫만 2 이고 나머지가 전부 1 인 피보나치
이웃 쌍이 그 극단이에요.

```text
작은 쪽 자릿수   입력 (피보나치 이웃)                                                           |x|                대입 후보 수   초당 1억 번 기준
             2   21 과 13                                                                         5                          11            0.000초
             3   987 과 610                                                                     233                         467            0.000초
             4   6,765 과 4,181                                                               1,597                       3,195            0.000초
             6   832,040 과 514,229                                                         196,418                     392,837            0.004초
             9   1,134,903,170 과 701,408,733                                           267,914,296                 535,828,593              5.4초
            19   4,660,046,610,375,530,309 과 2,880,067,194,370,816,120   1,100,087,778,366,101,931   2,200,175,556,732,203,863              698년
        └ 계약이 bigint 라 자릿수에 상한이 없다. 자릿수가 하나 늘면 후보 수가 열 배씩 는다
```

**아홉 자리에서 이미 5.4 초이고 열아홉 자리면 698 년입니다.** `g` 자체는 나눗셈 백 번 안쪽에
나오는데 계수를 찾는 데 값에 비례하는 일을 하면 앞뒤가 안 맞아요.

```text
방향을 바꾼다 — 계수를 찾지 말고 나머지와 함께 만든다

  대입해서 찾으면   맞는 x 를 만날 때까지 후보를 본다
  함께 만들면       나머지를 만드는 자리에서 계수도 같이 정해져야 한다
    ┗ 그러려면 「나머지가 처음 두 수로 어떻게 적히는가」를 걸음마다 알고 있어야 한다
```

그 물음부터 값으로 확인합시다. 첫 나머지 `144` 는 등식 `510 = 2 × 183 + 144` 를 옮기면
`144 = 510 - 2 × 183` 이고, 계수로는 `(1, -2)` 예요. 그다음 나머지 `39` 는
`39 = 183 - 1 × 144` 인데 여기서 `144` 자리에 방금 얻은 조합을 넣으면
`39 = 183 - (510 - 2 × 183) = 510 × (-1) + 183 × 3` 이 됩니다.

```text
두 걸음을 손으로 이어 보면

  144 = 510 - 2×183                       → 계수 (1, -2)
   39 = 183 - 1×144
      = 183 - 1×(510 - 2×183)             ← 144 자리에 위 조합을 넣는다
      = -510 + 3×183                      → 계수 (-1, 3)
        └ 옛 계수 (0, 1) 에서 (1, -2) 의 몫 1 배를 뺀 것과 같다: (0,1) - 1×(1,-2) = (-1, 3)
```

**갱신식이 나머지의 것과 글자 그대로 같습니다.** 나머지가 `r0 - q·r1` 이면 계수도
`s0 - q·s1` 과 `t0 - q·t1` 이에요. 여덟 걸음을 끝까지 이어 붙이면 이렇게 됩니다.

<!--proof:combo-walk-->

```text
항   나머지   510 · s + 183 · t           계산하면
r0      510   510 × (1) + 183 × (0)            510
r1      183   510 × (0) + 183 × (1)            183
r2      144   510 × (1) + 183 × (-2)           144
r3       39   510 × (-1) + 183 × (3)            39
r4       27   510 × (4) + 183 × (-11)           27
r5       12   510 × (-5) + 183 × (14)           12
r6        3   510 × (14) + 183 × (-39)           3
r7        0   510 × (-61) + 183 × (170)          0
```

**넷째 칸이 둘째 칸과 여덟 줄 내내 같습니다.** 그리고 `r6 = 3` 줄의 계수 `(14, -39)` 가 곧
답이에요 — 절차는 여기까지 오면 더 할 일이 없습니다. 이제 비용이 무엇에 달렸는지 봅시다.
대입 탐색은 `|x|` 가 정하고 계수 갱신은 걸음 수가 정하는데, **작은 쪽 자릿수를 19 로 맞추고
몫의 분포만 바꿔** 두 값을 나란히 재면 이렇게 갈려요.

<!--proof:search-split-->

```text
입력                                     작은 쪽 자릿수                         |x|                대입 후보 수   걸음 수
몫이 거의 다 1 — F(91) 과 F(90)                      19   1,100,087,778,366,101,931   2,200,175,556,732,203,863        89
몫이 전부 2 — P(48) 과 P(47)                         19     835,002,744,095,575,440   1,670,005,488,191,150,881        49
몫 하나가 아주 큼 — 10^19 과 10^19 - 1               19                           1                           3         2
```

**셋째 줄이 그 자리입니다.** 자릿수가 같은데 후보 수는 3 개이고, 첫 줄은 2.2e18 개예요.
자릿수가 비용을 정하지 않고 **몫의 분포**가 정합니다. 그리고 대입 탐색은 그 분포를 미리 모른
채로 후보를 하나씩 봐야 해요 — 걸음 수 쪽은 셋 다 100 아래입니다.

```text
같은 19 자리에서 두 방법이 무엇에 달렸는가

  대입 탐색     |x| 에 달렸다        3 개에서 2.2e18 개까지 갈린다
  계수 갱신     걸음 수에 달렸다     2 번에서 89 번까지 갈린다
                └ 두 값이 같은 방향으로 움직이지만 규모가 열여덟 자리 차이가 난다
```

**여기서 개념을 세웁니다.** 나머지 수열의 각 항에 「그 항을 `A` 와 `B` 로 적는 계수 쌍」을
붙여 두고, 항을 만들 때 쓴 몫으로 계수도 함께 갱신하는 것이에요. 그런데 그 전에 더 단순한
후보를 하나 시험해 봅시다 — **몫을 순서대로 다 적어 두었다가 마지막에 거슬러 계산하는
방법**입니다.

```text
몫을 다 적어 두었다가 거슬러 계산하면

  1단계   나머지 수열만 만들며 몫 2 1 3 1 2 4 를 순서대로 저장한다
  2단계   맨 끝에서 (1, 0) 으로 시작해 몫을 역순으로 대입하며 계수를 만든다
          └ 답은 같다. 그런데 몫을 담을 자리가 걸음 수만큼 필요하고,
            걸음 수는 계산해 보기 전에는 모른다
```

<!--proof:keep-quotients-->

```text
입력                    걸음 수   몫을 적어 두면 칸   걸음마다 갱신하면 칸
전개 입력 -510 과 183         6                   6                      6
F(91) 과 F(90)               89                  89                      6
P(48) 과 P(47)               49                  49                      6
```

전개 입력에서는 두 칸 수가 6 으로 같지만, 걸음이 늘면 왼쪽만 따라 늡니다. **그래서 몫을
저장하지 않고 그 자리에서 쓰기로 합니다** — 몫 `q` 를 얻은 그 걸음 안에서 나머지와 계수 두
벌을 함께 갱신하면 필요한 칸이 여섯으로 고정돼요.

```text
한 걸음이 하는 일 — 같은 q 로 세 자리를 갱신한다

  (r0, r1)  ←  (r1, r0 - q·r1)      나머지 수열
  (s0, s1)  ←  (s1, s0 - q·s1)      a 쪽 계수
  (t0, t1)  ←  (t1, t0 - q·t1)      b 쪽 계수
              └ 세 줄의 오른쪽이 글자 하나만 다르다. 그것이 이 절차의 전부다
```

각 값이 어디까지 움직이는지도 여기서 정해집니다. 나머지는 매 걸음 줄어들어 0 에서 멈추고,
두 계수는 첫 항을 지나면 절댓값이 **줄지 않으면서** 각각 `B / (2g)` 와 `A / (2g)` 를 넘지
않아요.

```text
전개 입력에서 세 벌이 어디까지 가는가
```

### 수행으로 알아보는 알고리즘 — 510 과 183 에서 베주 계수를 만든다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const a = -510n;
const b = 183n;
// 이 절이 끝나면 { g: 3n, x: -14n, y: -39n } 이 나와야 한다
```

이 입력을 왜 골랐을까요? 첫 인자가 **음수**라 부호를 떼고 다시 붙이는 갈래가 실행되고, 몫이
`2 1 3 1 2 4` 로 **한쪽으로 치우치지 않아** 몫이 큰 걸음과 1 인 걸음이 섞이며, 최대공약수가
1 이 아닌 3 이라 계수와 `g` 의 관계까지 함께 확인되기 때문입니다.

```text
extendedEuclidean(a, b):
    부호를 따로 적어 두고 r0 ← |a|, r1 ← |b|            ① 처음 값을 정한다
    (s0, s1) ← (1, 0),  (t0, t1) ← (0, 1)
    r1 이 0 이 아닌 동안:
        q ← r0 를 r1 로 나눈 몫
        (r0, r1) ← (r1, r0 - q·r1)
        (s0, s1) ← (s1, s0 - q·s1)                     ② 몫 하나로 세 자리를 갱신한다
        (t0, t1) ← (t1, t0 - q·t1)
    g ← r0, x ← 부호 × s0, y ← 부호 × t0               ③ 부호를 다시 붙여 셋을 낸다
```

#### 1. 부호를 떼고 계수 두 벌의 처음 값을 정한다

최대공약수는 부호와 무관하지만 계수는 부호를 탑니다. 그래서 부호를 따로 적어 두고 절댓값으로
계산한 다음, 마지막에 계수에만 다시 붙여요.

```ts
const signA = a < 0n ? -1n : 1n;  // ① 처음 값을 정한다
const signB = b < 0n ? -1n : 1n;
let r0 = a < 0n ? -a : a;
let r1 = b < 0n ? -b : b;
let s0 = 1n;
let s1 = 0n;
let t0 = 0n;
let t1 = 1n;
```

계수의 처음 값이 왜 `(1, 0)` 과 `(0, 1)` 인지가 이 조각의 전부입니다. `r0` 자리에 있는 수는
`510` 이고 그것은 `510 × 1 + 183 × 0` 이며, `r1` 자리의 `183` 은 `510 × 0 + 183 × 1` 이에요.

```text
T1  a = -510  →  r0 = 510,  부호 -1 을 따로 적어 둔다
    b =  183  →  r1 = 183,  부호 +1
    s 두 항 (s0, s1) = (1, 0)        t 두 항 (t0, t1) = (0, 1)
    r0 에 붙는 쌍은 s0 와 t0 다      510 = 510×1 + 183×0
    r1 에 붙는 쌍은 s1 과 t1 이다    183 = 510×0 + 183×1        ①
```

#### 2. 몫 하나로 세 자리를 함께 갱신한다

이제 반복입니다. 몫 `q` 를 한 번 구하고 그 값을 세 벌에 전부 씁니다.

```ts
while (r1 !== 0n) {
  const q = r0 / r1;
  [r0, r1] = [r1, r0 - q * r1];
  [s0, s1] = [s1, s0 - q * s1];   // ② 몫 하나로 세 자리를 갱신한다
  [t0, t1] = [t1, t0 - q * t1];
}
```

두 걸음만 실행하면 이렇게 나옵니다.

```text
T2  q = 2   510 = 2 × 183 + 144
            (r0, r1) → (183, 144)   (s0, s1) → (0, 1)    (t0, t1) → (1, -2)
            검산: 510×1 + 183×(-2) = 144                                     ②

T3  q = 1   183 = 1 × 144 + 39
            (r0, r1) → (144, 39)    (s0, s1) → (1, -1)   (t0, t1) → (-2, 3)
            검산: 510×(-1) + 183×3 = 39                                      ②
```

**나머지는 매 걸음 줄고, 계수는 첫 걸음을 지나면 절댓값이 줄지 않습니다.** 두 값이 반대
방향으로 움직이는 것이 이 반복이 하는 일 전부예요.

#### 짚고 가기 — 계수를 한 줄씩 대입해도 될 것 같다

`[s0, s1] = [s1, s0 - q * s1]` 는 두 값을 **동시에** 바꾸는 문장입니다. 익숙한 모양으로 풀어
두 문장으로 나누고 싶어져요.

```ts
s0 = s1;
s1 = s0 - q * s1;   // ← s0 가 이미 새 값이라 옛 s0 가 사라졌다
```

첫 문장이 `s0` 를 덮어쓰고 나면 둘째 문장의 `s0` 는 이미 `s1` 입니다. 그래서 계산되는 값이
`s1 - q·s1` 이 되고, 첫 걸음에서 `q = 2` 이므로 `0 - 2×0 = 0` 이 나와 그 뒤로 `s` 가 계속 0 에
머물러요.

결과 위 두 줄의 항등식이 3 과 1 이어야 하는 자리에서 -7,137 과 35 를 냅니다.

#### 짚고 가기 — y 는 마지막에 나눗셈 한 번으로 되찾아도 될 것 같다

계수 두 벌을 다 갱신하는 것이 낭비로 보입니다. `a·x + b·y = g` 에서 `x` 만 있으면
`y = (g - a·x) / b` 로 나오니까, `t` 갱신 두 줄을 지우고 마지막에 나눗셈 한 번만 하면 될 것
같아요.

```ts
// t0, t1 을 아예 두지 않고
const y = (g - a * x) / b;   // ← b 가 0 이면 여기서 0 으로 나눈다
```

**이 판은 `b` 가 0 이 아닌 모든 입력에서 정본과 같은 값을 냅니다.** `b ≠ 0` 이면 `y` 가 식
하나로 유일하게 정해지기 때문이에요.


**셋째 줄이 그 자리입니다.** 계약이 `b = 0` 을 허용하고 그때 `g = |a|`, `y = 0` 을 내라고
적었는데, 이 판은 그 자리에서 `0n / 0n` 을 계산하다 예외를 냅니다. `b = 0` 만 따로 거르면
고칠 수 있지만 그러면 갈래가 하나 늘고, `t` 두 줄을 그냥 두면 갈래가 늘지 않아요.

#### 4. 전체 코드

지금까지의 조각을 한 벌로 모읍니다. 새로 들어간 것은 없어요 — 조각 셋을 순서대로 이어 붙인
것이 전부입니다.

```ts
export function extendedEuclidean(
  a: bigint,
  b: bigint,
): { g: bigint; x: bigint; y: bigint } {
  // ① 부호를 따로 적어 두고 절댓값으로 시작한다. 계수 두 벌의 처음 값도 여기서 정한다.
  const signA = a < 0n ? -1n : 1n;
  const signB = b < 0n ? -1n : 1n;
  let r0 = a < 0n ? -a : a;
  let r1 = b < 0n ? -b : b;
  let s0 = 1n;
  let s1 = 0n;
  let t0 = 0n;
  let t1 = 1n;

  // ② 나머지를 만든 몫 q 로 계수 두 벌을 같은 식으로 갱신한다.
  while (r1 !== 0n) {
    const q = r0 / r1;
    [r0, r1] = [r1, r0 - q * r1];
    [s0, s1] = [s1, s0 - q * s1];
    [t0, t1] = [t1, t0 - q * t1];
  }

  // ③ r1 이 0 이 된 순간의 r0 가 g 다. 절댓값으로 계산했으므로 계수에 부호를 다시 붙인다.
  if (r0 === 0n) return { g: 0n, x: 0n, y: 0n };
  return { g: r0, x: signA * s0, y: signB * t0 };
}
```

네 입력에 실행한 결과입니다.

```text
전개가 쓰는 -510 과 183   3   -14   -39           3

한쪽이 0 인 7 과 0        7     1     0           7
둘 다 0                   0     0     0           0
```

### 알아 두면 좋은 개념 — 일차 디오판토스 방정식

전개의 T7 에서 반복이 끝날 때 계수 두 벌에 각각 값이 둘씩 남아 있었습니다. 답으로 쓴 것은
`(s0, t0) = (14, -39)` 이고, 버린 쪽은 `(s1, t1) = (-61, 170)` 이에요. 그 버린 쌍에 이름이
붙어 있습니다.

```text
버린 쌍이 무엇인가

  s1 = -61   |s1| = 61 = 183 / 3 = B / g
  t1 = 170   |t1| = 170 = 510 / 3 = A / g
             └ 510×(-61) + 183×170 = 0 이다. 0 을 만드는 조합이라 답에 더해도 답이 안 변한다
```

그래서 해가 하나가 아닙니다. 미지수가 정수여야 하는 방정식을 **디오판토스 방정식**이라 하고,
`a·x + b·y = c` 꼴이 그중 **일차** 디오판토스 방정식이에요. 이 방정식은 `g` 가 `c` 를 나눌
때만 해가 있고, 해가 있으면 무한히 많습니다.

<!--proof:general-solution-->

```text
 k   x = -14 + 61k   y = -39 + 170k   a·x + b·y
-1             -75             -209           3
 0             -14              -39           3
 1              47              131           3
 2             108              301           3
        └ 마지막 항의 계수 두 개가 (-61, 170) 이고, 그 절댓값이 B / g = 61 과 A / g = 170 다
```

| 이 글의 것 | 일차 디오판토스 방정식으로 말하면 |
| --- | --- |
| 반환하는 `(x, y)` | `a·x + b·y = g` 의 한 해 |
| 버린 `(s1, t1)` | 해와 해 사이의 간격, 즉 `a·x + b·y = 0` 의 기본 해 |
| `g` 가 `c` 를 나누는가 | `a·x + b·y = c` 에 해가 있는지의 판정 |
| `g = 1` 인 경우 | `a·x ≡ 1 (mod b)`, 곧 모듈러 역원 |

**같은 이름을 다시 만나는 자리**가 셋 있습니다. 중국인의 나머지 정리에서 두 합동식을 합칠 때,
동전 두 종류로 만들 수 있는 금액을 셀 때, 그리고 격자에서 `a·x + b·y = c` 위의 정수점을 셀
때예요. 셋 다 「해가 있는가」와 「간격이 얼마인가」 둘만 있으면 풀립니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 이 절차를 세우고 동작까지 확인했습니다. 여기서는 이 절차를 언제 쓰는지, 무엇이 항상
참인지, 비용이 얼마인지를 따집니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **최대공약수와 함께 그것을 만드는 계수가 필요하다.** `g` 만 필요하면 계수 두 벌을 위한
  여섯 줄(처음 값 네 줄과 갱신 두 줄)이 그냥 낭비입니다.
- **법이 소수가 아닐 수 있다.** 모듈러 역원을 페르마의 소정리로 구하려면 법이 소수여야 하는데,
  이 절차는 `gcd(a, b) = 1` 이기만 하면 됩니다. 서로소가 아니면 그 사실 자체를 `g` 로 알려줘요.
- **수가 크다.** 걸음이 값이 아니라 자릿수에 비례해서만 늘어납니다.
- **입력의 부호와 0 을 따로 안 걸러도 된다.** 부호를 적어 두는 두 줄과 마지막 두 줄이 그것을
  흡수해요.

```text
이 절차가 잘 안 맞는 모양

  g 만 필요하다              계수를 위한 여섯 줄이 그대로 낭비다
  법이 고정된 소수다         거듭제곱 한 번으로 역원이 나오고 분기가 없어 상수 시간 구현이 쉽다
  수가 세 개 이상이다        둘씩 접어야 한다. 계수는 그때마다 다시 합성해야 한다
```

셋째 줄이 이 절차의 한계입니다. 세 수의 최대공약수를 한 번에 만드는 계수 셋을 직접 내지는
않아요.

#### 문제에서 이것을 떠올리게 하는 단서

- 「`a·x + b·y = c` 를 만족하는 **정수** `x`, `y`」 — 일차 디오판토스 방정식의 표준 문형입니다.
- 「`a` 의 `mod m` **역원**」 — `a·x + m·y = 1` 의 `x` 가 그 역원이고, `m` 이 소수가 아니어도
  됩니다.
- 「나머지 조건 두 개를 **동시에** 만족하는 수」 — 중국인의 나머지 정리이고, 두 합동식을 합칠
  때 이 절차의 계수를 씁니다.
- 「두 종류의 단위로 **정확히** 만들 수 있는 최소 단위와 그 조합」 — `g` 가 그 최소 단위이고
  `(x, y)` 가 조합입니다.
- 「분수 `p/q` 를 분모가 작은 분수로 근사」 — 나머지 수열의 계수가 곧 근사 분수의 분자와
  분모입니다.

```text
단서가 가리키지 않는 자리

  「최대공약수만 구하라」        유클리드 호제법이면 된다. 계수를 만들 이유가 없다
  「a^k mod m 을 구하라」        거듭제곱을 반으로 접는 절차의 자리다
  「소인수분해하라」             계수는 소인수분해를 알려주지 않는다
```

#### 실제로 쓰이는 곳

- **Go 표준 라이브러리** — `math/big` 의 `(*Int).GCD` 가 이 문제와 **같은 계약**을 씁니다.
  공식 문서가 *"GCD sets z to the greatest common divisor of a and b and returns z. If x or
  y are not nil, GCD sets their value such that z = a*x + b*y."* 라고 적고, 0 이 들어오는
  경우까지 못 박아요 — *"If a == b == 0, GCD sets z = x = y = 0."* ·
  *"If a == 0 and b != 0, GCD sets z = |b|, x = 0, y = sign(b) * 1."* ·
  *"If a != 0 and b == 0, GCD sets z = |a|, x = sign(a) * 1, y = 0."*
  ([공식 문서](https://pkg.go.dev/math/big#Int.GCD), 조회일 2026-09-03)
- **Java 표준 라이브러리** — `BigInteger.modInverse` 가 이 절차의 대표적인 소비자입니다.
  공식 문서가 *"Returns a BigInteger whose value is (this^-1 mod m)."* 로 적고, 던지는 조건을
  *"m ≤ 0, or this BigInteger has no multiplicative inverse mod m (that is, this BigInteger
  is not relatively prime to m)."* 로 밝혀요 — 「서로소일 때만 역원이 있다」가 그대로입니다.
  ([공식 문서](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/math/BigInteger.html), 조회일 2026-09-03)

```text
두 문서에서 확인한 것

  Go     「z = a*x + b*y」 · 「a == b == 0 이면 z = x = y = 0」 · 부호가 붙는 세 경계
  Java   「서로소가 아니면 역원이 없다」 — 이 글의 g 가 1 인지를 묻는 것과 같다
         └ 위 네 줄만 원문에서 확인했다. 두 라이브러리가 안에서 어떤 절차를 쓰는지는
           이 글이 확인하지 않았다
```

**이 문제의 계약이 Go 의 계약과 글자 단위로 같다는 것**이 이 절의 값입니다. 0 과 부호를 다루는
방식이 관례로 굳어 있고, 이 글의 코드 첫 네 줄과 마지막 두 줄이 그 관례를 그대로 지킵니다.

#### 경쟁 설계와의 대조

경쟁 설계는 **최소 절댓값 나머지 판**입니다. 몫을 내림 대신 **반올림**해서 나머지를 나누는 수의
절반 아래로 잡아요. 나머지가 음수가 될 수 있고, 그래서 나머지 수열 자체가 정본과 다릅니다.

```text
두 판이 한 걸음에서 무엇을 다르게 하는가

  나머지 판   q = ⌊r0 / r1⌋              나머지가 0 이상 r1 미만
  중심 판     q = r0 / r1 을 반올림       나머지의 절댓값이 r1 의 절반 이하
              └ 값이 한 걸음에 적어도 절반으로 줄어 걸음 수가 정본 이하다.
                대신 걸음마다 반올림 판정이 붙고, 몫을 한 칸 옮긴 걸음에는 보정까지 붙는다
```

**입력은 전개 입력을 그대로 두고 몫의 분포가 다른 셋을 더했습니다.** 두 판이 갈리는 축이 몫의
분포인데 전개 입력(510 · 183)의 몫은 `2 1 3 1 2 4` 로 섞여 있어 치우친 자리가 안 보여요.
그래서 마지막 몫만 2 이고 나머지가 전부 1 인 피보나치 이웃 `F(91)`·`F(90)`, 몫이 전부 2 인 펠 수열 이웃
`P(48)`·`P(47)`(`P(0)=1`·`P(1)=2`·`P(k+1)=2·P(k)+P(k-1)`), 그리고 몫이 섞이고 값이 큰
`1,000,000,007`·`998,244,353` 을 더합니다. 넷 다 상수라 몇 번을 실행해도 같은 값이 나와요.

<!--proof:alt-counts-->

```text
입력            나머지 판 걸음   중심 판 걸음   나머지 판 기본 연산   중심 판 기본 연산   적은 쪽
전개 입력                    6              4                    85                  78   중심 판
피보나치 이웃               89             45                 1,247                 943   중심 판
펠 수열 이웃                49             49                   687                 835   나머지 판
큰 소수 쌍                   9              8                   127                 142   나머지 판
        └ 계수의 절댓값이 네 입력에서 두 설계 모두 같은가: 그렇다
```

**위 두 줄과 아래 두 줄에서 순서가 뒤집힙니다.** 걸음 수는 네 줄 다 중심 판이 적거나 같은데,
기본 연산 수는 위 둘에서 중심 판이 적고 아래 둘에서 나머지 판이 적어요.

```text
뒤집히는 조건이 값으로 나온다

  나머지 판   기본 연산 = 14 × 걸음 + 1                      걸음마다 하는 일이 일정하다
  중심 판     기본 연산 = 17 × 걸음 + 4 × 옮긴 걸음 + 2       걸음마다 셋이 더 붙는다
  ─────────────────
  걸음이 정본의 2/3 아래로 줄어야 중심 판의 기본 연산도 적다
    피보나치 이웃 45/89 = 0.51  →  중심 판       펠 수열 이웃 49/49 = 1.00  →  나머지 판
    전개 입력      4/6 = 0.67  →  중심 판       큰 소수 쌍     8/9 = 0.89  →  나머지 판
      └ 옮긴 걸음은 차례로 2 · 44 · 0 · 1 이다. 펠 수열 이웃은 나머지가 이미 절반 아래라
        몫을 한 번도 안 옮기는데, 걸음도 안 줄어 반올림 판정 세 연산만 더 붙는다
```

**이 절차가 내주는 것과 얻는 것을 적어 둡시다.** 내주는 것은 **걸음 수**입니다 — 네 입력에서
한 번도 중심 판보다 적지 않았고, 몫이 거의 다 1 인 입력에서는 두 배로 벌어져요. 얻는 것은
**걸음마다의 단순함과 부호**입니다. 나머지가 언제나 0 이상이라 마지막에 `g` 의 부호를 맞추는
자리가 없고, 반올림 판정과 보정 네 연산이 통째로 빠집니다. 계수의 절댓값은 네 입력에서 두 판이
같았으므로 그 축은 갈리지 않아요.

### 수식 정의와 유도

파트 1 이 값으로 보인 것은 「이 입력에서 `|s0|` 가 14 이고 상한이 30」입니다. **임의의 입력에서
계수가 얼마나 커지는가**는 값으로 못 얻어요. 여기서 닫힌 형태로 냅니다.

기호 넷을 정의합니다. `A`·`B` 는 파트 1 에서 정한 그대로이고, `n` 과 `g` 를 여기서 더합니다.

| 기호 | 정의 |
| --- | --- |
| $A, B$ | 두 입력의 절댓값. 편의상 $A > B \ge 1$ 로 둔다 |
| $r_i, s_i, t_i$ | 나머지 수열의 $i$ 번째 항과 그 항에 붙는 계수 쌍 |
| $n$ | $r_{n+1} = 0$ 이 되는 첫 지표. 나눗셈이 실행된 횟수다 |
| $g$ | $r_n$, 곧 최대공약수 |

나머지 수열부터 정의합니다.

$$r_0 = A,\quad r_1 = B,\qquad q_i = \left\lfloor \frac{r_{i-1}}{r_i} \right\rfloor,\qquad r_{i+1} = r_{i-1} - q_i\, r_i$$

```text
i = 1 에 넣어 계산하면

  q_1   = ⌊510 / 183⌋ = 2
  r_2   = r_0 - q_1 · r_1 = 510 - 2 × 183 = 144
```

계수 두 벌은 **같은 점화식**을 쓰고 처음 값만 다릅니다.

$$s_0 = 1,\ s_1 = 0,\qquad s_{i+1} = s_{i-1} - q_i\, s_i \qquad\qquad t_0 = 0,\ t_1 = 1,\qquad t_{i+1} = t_{i-1} - q_i\, t_i$$

```ts
// 위 세 점화식을 그대로 옮긴 조각. 세 줄의 오른쪽이 글자 하나만 다르다.
const q = r0 / r1;
[r0, r1] = [r1, r0 - q * r1];
[s0, s1] = [s1, s0 - q * s1];
[t0, t1] = [t1, t0 - q * t1];
```

정의를 전개 입력에 넣어 검산합시다. `A = 510`, `B = 183` 이고 `n = 6` 입니다.

<!--proof:math-check-->

```text
i   r_i   s_i   t_i   A·s_i + B·t_i   s_i·t_{i+1} - s_{i+1}·t_i
0   510     1     0             510                           1
1   183     0     1             183                          -1
2   144     1    -2             144                           1
3    39    -1     3              39                          -1
4    27     4   -11              27                           1
5    12    -5    14              12                          -1
6     3    14   -39               3                           1
7     0   -61   170               0                           —
        └ A = 510, B = 183 다. 다섯째 칸이 둘째 칸과 언제나 같고
          여섯째 칸이 +1 과 -1 을 번갈아 낸다
```

다섯째 칸이 말하는 것을 식으로 적으면 다음과 같고, 귀납으로 확인됩니다.

$$A\,s_i + B\,t_i = r_i \qquad (0 \le i \le n+1)$$

```text
기저 둘을 전개 입력의 값으로 확인하면

  i = 0   510 × 1 + 183 × 0 = 510 = r_0       그렇다
  i = 1   510 × 0 + 183 × 1 = 183 = r_1       그렇다
```

단계는 점화식을 대입하기만 하면 됩니다.

$$A\,s_{i+1} + B\,t_{i+1} = A(s_{i-1} - q_i s_i) + B(t_{i-1} - q_i t_i) = (A s_{i-1} + B t_{i-1}) - q_i (A s_i + B t_i) = r_{i-1} - q_i r_i = r_{i+1}$$

```text
i = 1 에서 이 변형을 값으로 확인하면

  A·s_2 + B·t_2 = (A·s_0 + B·t_0) - q_1 × (A·s_1 + B·t_1)
                = 510 - 2 × 183
                = 144 = r_2                                  그렇다
```

여섯째 칸도 같은 방법으로 닫힙니다. $D_i = s_i t_{i+1} - s_{i+1} t_i$ 라 두면
$D_0 = 1\cdot 1 - 0\cdot 0 = 1$ 이고, $D_{i+1}$ 을 정의대로 편 다음 점화식을 넣으면
$q_{i+1}$ 이 든 항이 서로 지워져 $D_{i+1} = -D_i$ 가 됩니다. 그래서 $D_i = (-1)^i$ 예요.

```text
D_{i+1} 을 펴 보면 — q 가 든 항이 서로 지워진다

  D_{i+1} = s_{i+1}·t_{i+2} - s_{i+2}·t_{i+1}
          = s_{i+1}(t_i - q_{i+1}·t_{i+1}) - (s_i - q_{i+1}·s_{i+1})·t_{i+1}
          = s_{i+1}·t_i - q_{i+1}·s_{i+1}·t_{i+1} - s_i·t_{i+1} + q_{i+1}·s_{i+1}·t_{i+1}
          = -(s_i·t_{i+1} - s_{i+1}·t_i)  =  -D_i
```

이제 **계수의 상한**을 냅니다. 먼저 마지막 항의 계수부터 정해요. $r_{n+1} = 0$ 이므로
$A s_{n+1} + B t_{n+1} = 0$ 이고, 양변을 $g$ 로 나누면 $(A/g)\,s_{n+1} = -(B/g)\,t_{n+1}$ 입니다.
$A/g$ 와 $B/g$ 는 서로소이고 $|D_n| = 1$ 이라 $s_{n+1}$ 과 $t_{n+1}$ 도 서로소이므로, 남는 것은
하나뿐이에요.

$$|s_{n+1}| = \frac{B}{g}, \qquad |t_{n+1}| = \frac{A}{g}$$

```text
전개 입력에서 확인하면

  |s_7| = 61  = 183 / 3 = B / g       ✓
  |t_7| = 170 = 510 / 3 = A / g       ✓
```

다음은 두 가지입니다. 첫째, $s$ 의 부호가 걸음마다 번갈아 나오므로 $|s_{i+1}| = |s_{i-1}| + q_i |s_i|$
이고, 따라서 $|s_i|$ 는 $i \ge 1$ 에서 비감소예요. 둘째, **마지막 몫은 2 이상**입니다 —
$r_{n-1} = q_n r_n$ 인데 $r_{n-1} > r_n$ 이므로 $q_n = 1$ 일 수 없어요. 둘을 이으면 상한이
나옵니다.

$$|s_{n+1}| = |s_{n-1}| + q_n |s_n| \;\ge\; q_n |s_n| \;\ge\; 2|s_n| \quad\Longrightarrow\quad |x| = |s_n| \le \frac{B}{2g}, \qquad |y| = |t_n| \le \frac{A}{2g}$$

```text
전개 입력의 마지막 걸음에서 확인하면

  q_6 = 4 >= 2                              마지막 몫이 2 이상이다
  |s_7| = 61 = |s_5| + 4 × |s_6| = 5 + 56   등식이 성립한다
  |s_6| = 14 <= 61 / 2 = 30.5               상한 B / (2g) = 30 아래다
```

제약 규모에 넣어 봅시다. 암호에서 흔히 쓰는 2,048 비트 법은 십진 617 자리이고, 그 크기의 두
수에서 계수가 몇 자리가 되는지를 실제로 재면 이렇게 나와요.

<!--proof:coef-bound-->

```text
A 와 B                         A 자릿수   g         |x|      B / (2g)         |y|      A / (2g)
510 과 183                            3   3          14            30          39            85
6,765 과 4,181                        4   1       1,597         2,090       2,584         3,382
1,000,000,007 과 998,244,353         10   1   4,915,446   499,122,176   4,924,091   500,000,003
19 자리 두 수                        19   1     19 자리       19 자리     19 자리       19 자리
617 자리 두 수                      617   1    616 자리      616 자리    616 자리      617 자리
        └ 다섯 줄 다 |x| 가 B / (2g) 이하이고 |y| 가 A / (2g) 이하다
```

**계수가 입력보다 커지지 않습니다.** 617 자리 입력에서 `|x|` 가 616 자리예요. 계수를 담을 칸을
입력을 담을 칸과 같은 규모로 잡으면 되고, 걸음 수를 미리 몰라도 넘칠 걱정이 없습니다.
$A = B$ 는 이 상한 밖입니다 — 걸음 하나로 끝나 $|y| = 1$ 인데 $A/(2g) = 1/2$ 이에요.

### 불변식 — 걸음마다 두 계수가 그 자리의 나머지를 두 입력의 절댓값으로 적어 준다

파트 1 에서 코드가 동작하는 것을 일곱 단계로 확인했습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이
실제로 유지되는지 확인해 봅시다.

> 반복문의 한 바퀴가 끝날 때마다 `A·s0 + B·t0 = r0` 과 `A·s1 + B·t1 = r1` 이 **둘 다**
> 참입니다. 그리고 `r1` 은 매 바퀴 엄격하게 줄어듭니다.

```text
                두 항                계수 두 벌                 검산
   T1        (510, 183)      (1, 0) 과 (0, 1)          510×1 + 183×0 = 510
   T4        (144,  39)      (1, -1) 과 (-2, 3)        510×1 + 183×(-2) = 144
   T7        (  3,   0)      (14, -61) 과 (-39, 170)   510×14 + 183×(-39) = 3
                  ^                                        ^
                  나머지는 계속 줄고                       검산은 언제나 그 줄의 r0 다
```

**두 등식이 함께 참이라는 것이 중요합니다.** 하나만 참이면 다음 걸음의 갱신식에 넣을 재료가
모자라요 — 새 등식은 옛 등식 **둘의 차**로 만들어지기 때문입니다. 그리고 「한 바퀴가 끝날
때마다」이지 반복이 끝난 뒤 한 번이 아닙니다.

**출발점부터 봅시다.** 반복이 시작되기 전 `(r0, r1)` 은 `(A, B)` 이고 계수는 `(1, 0)` 과
`(0, 1)` 이라, 두 등식이 `A = A·1 + B·0` 과 `B = A·0 + B·1` 로 곧바로 참입니다. 그 뒤로 상태를
바꾸는 갈래는 하나뿐이에요.

| 무슨 일 | 무엇이 바뀌는가 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| `r1` 이 0 이 아니다 | 세 벌이 전부 `(둘째, 첫째 - q × 둘째)` 가 된다 | 새 `r1` 은 `r0 - q·r1` 이고 새 계수도 같은 식이라, 옛 두 등식의 차가 곧 새 등식이다. 그리고 `r0 - q·r1 < r1` 이므로 새 `r1` 이 옛 `r1` 보다 작다 |
| `r1` 이 0 이다 | 아무것도 안 바뀐다 | 반복이 끝난다. 그때 `A·s0 + B·t0 = r0 = g` 이고 그것이 구하려던 식이다 |

**차를 세우는 것이 유지의 전부입니다.** 옛 등식 둘이 `A·s0 + B·t0 = r0` 과 `A·s1 + B·t1 = r1`
이면, 위에서 아래의 `q` 배를 빼면 `A·(s0 - q·s1) + B·(t0 - q·t1) = r0 - q·r1` 이 됩니다. 왼쪽이
새 계수의 조합이고 오른쪽이 새 나머지예요.

```text
한 바퀴가 두 등식을 어떻게 이어 주는가

  옛 첫째   A·s0 + B·t0 = r0
  옛 둘째   A·s1 + B·t1 = r1
  ─────────  첫째에서 둘째의 q 배를 뺀다
  새 둘째   A·(s0 - q·s1) + B·(t0 - q·t1) = r0 - q·r1
  새 첫째   옛 둘째를 그대로 옮긴 것이라 이미 참이다
```

**나머지가 줄어든다는 쪽이 종료를 보장합니다.** `r0 - q·r1` 은 `r1` 보다 작은 음이 아닌 정수이므로 `r1` 이 매
바퀴 엄격하게 줄고, 음이 아닌 정수는 무한히 줄 수 없어요. 경계에 있는 입력들도 확인하고
갑시다.

<!--proof:edge-values-->

```text
입력                         g     x    y   a·x + b·y
둘 다 0                      0     0    0           0
뒤가 0 인 7 과 0             7     1    0           7
앞이 0 인 0 과 9             9     0    1           9
같은 값 13 과 13            13     0    1          13
앞이 더 작은 5 와 17         1     7   -2           1
둘 다 음수인 -510 과 -183    3   -14   39           3
뒤만 음수인 510 과 -183      3    14   39           3
```

`0 과 9` 가 이 절차의 경계입니다. `r0` 가 0 이어도 첫 걸음의 몫이 0 이라 두 항이 `(9, 0)` 으로
자리를 바꾸고, `r0` 에 붙는 계수 쌍이 `(s0, t0) = (0, 1)` 이 되어 `0×0 + 9×1 = 9` 로 답이
나와요. 크기를 미리 견주는 코드가 없어도 되는 이유가 여기 있습니다.

**이제 깨뜨려 봅시다.** 앞에서 「차를 세운다」로 적은 그 자리를 지키던 줄은 계수 갱신 두
줄이에요. 그중
`t` 쪽 한 줄에서 뺄셈을 덧셈으로 바꿉니다.

```ts
[t0, t1] = [t1, t0 + q * t1];   // ← 뺄셈이었다
```

<!--proof:mutant-t-plus-->

```text
입력                      정본 (g, x, y)   뺄셈을 덧셈으로 바꾼 판 (g, x, y)   a·x + b·y
전개가 쓰는 -510 과 183   (3, -14, -39)    (3, -14, 39)                           14,277
서로소인 17 과 5          (1, -2, 7)       (1, -2, 7)                                  1
한쪽이 0 인 7 과 0        (7, 1, 0)        (7, 1, 0)                                   7
둘 다 0                   (0, 0, 0)        (0, 0, 0)                                   0
```

**첫 줄에서 `y` 의 부호가 뒤집혀 항등식이 3 대신 14,277 을 냅니다.** 덧셈으로 바꾸면 `t` 의
부호가 번갈아 나오지 않아 `|t|` 는 그대로인데 부호만 전부 양수가 되고, 그래서 두 등식의 차가
아니라 합이 세워집니다. 둘째 줄에서 값이 같은 것은 걸음 수가 3 으로 홀수라 두 부호가 우연히
맞았기 때문이고, 아래 두 줄은 반복이 실행되지 않는 입력이에요.

### 비용 계산

#### 비용을 세는 과정

한 번의 반복이 하는 일은 몫 하나를 구하고 세 벌을 옮기는 것뿐입니다. 전개의 값으로 확인하면
T2 부터 T7 까지 여섯 걸음이고 T1 은 처음 값을 정하는 걸음이에요.

```text
전개 입력에서 실제로 한 일

  부호 판정과 절댓값     4 번        T1. 인자마다 부호 하나와 절댓값 하나다
  나눗셈                 6 번        T2~T7. 걸음마다 한 번
  곱셈                  18 번        걸음마다 세 번 (r · s · t)
  뺄셈                  18 번        걸음마다 세 번
  대입                  36 번        걸음마다 여섯 번
  반복 판정              7 번        걸음마다 한 번 + 마지막 한 번
                         └ 첫 줄 넷을 뺀 다섯 줄은 걸음 수가 정하고 그 합이 85 다.
                           경쟁 설계 대조 표의 왼쪽 칸이 그 85 이고, 처음 값을 정하는
                           네 번은 걸음 수와 무관해 거기서 뺀다
```

세어야 하는 것이 셋입니다.

| 무엇 | 몇 번 | 근거 |
| --- | --- | --- |
| 처음 값 설정 | 언제나 상수 | 부호 둘 · 절댓값 둘 · 계수 넷 |
| 걸음 수 | `n` 번 | 나머지 수열이 유클리드 호제법의 것과 같다 |
| 걸음 안의 일 | 걸음마다 14 번 | 나눗셈 1 · 곱셈 3 · 뺄셈 3 · 대입 6 · 판정 1 |

전개 입력에 넣으면 `14 × 6 + 1 = 85` 이고, 그 값이 경쟁 설계 대조 표의 왼쪽 칸과 같습니다.

**걸음 수의 상한은 유클리드 호제법의 것을 그대로 씁니다.** 나머지 수열이 같으므로 걸음 수도
같아요 — 작은 쪽의 십진 자릿수를 `d` 라 하면 `n ≤ 4.785·d + 1` 이고, 그 유도는
[최대공약수 가이드](../gcd/gcd-guide.md)의 「수식 정의와 유도」에 있습니다.

```text
총식 — 이 절차가 하는 일 전부

  걸음 수          n <= 4.785 d + 1        gcd 편이 닫은 상한. d 는 작은 쪽의 십진 자릿수
  걸음마다         기본 연산 14 번          그중 나눗셈 1 · 곱셈 3
  피연산자         나머지는 A 이하          계수는 |x| <= B/(2g) · |y| <= A/(2g) 라
                                            둘 다 입력의 자릿수를 안 넘는다
  ─────────────────
  = Θ(d) 번의 연산이고 연산 하나가 자릿수에 비례한다
    고정폭 정수라면 그것이 곧 Θ(log min(|a|, |b|)) 다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (한쪽이 다른 쪽의 배수) | `O(1)` 걸음 | `Θ(1)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(d)` | 정하지 않았다 |
| **최악의 경우** (몫이 거의 다 1 인 쌍) | `O(d)` | `Θ(d)` |

**최선과 최악이 갈리는 절차입니다.** 한쪽이 다른 쪽의 배수면 첫 나머지가 0 이라 걸음 하나로
끝나고, 몫이 거의 다 1 인 쌍이면 자릿수에 비례하는 횟수가 필요해요.

```text
무엇이 최선과 최악을 가르는가 — 몫의 크기 하나다

  몫이 크다      한 걸음이 많이 줄인다      10^19 과 10^18 은 걸음 하나
  몫이 1 이다    한 걸음이 조금 줄인다      19 자리 피보나치 이웃은 걸음 89
                 └ 계수의 절댓값도 같은 방향으로 갈린다: 0 과 1.1e18 이다
```

**평균은 타이트 경계를 안 적었습니다.** 입력 분포를 정하지 않았기 때문이에요. 분포를 정하면 값이
정해지지만 이 글은 그 사실을 유도하지 않으므로 표에 값으로 적지 않습니다.

```text
최악 보장     어떤 입력에도 4.785 d + 1 걸음을 넘지 않는다      ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다     ← 이 절차는 여기 해당하지 않는다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요.
같은 입력을 두 번 넣으면 반환값도 걸음 수도 똑같이 나옵니다.

#### 최악을 만드는 입력

「큰 수가 최악」이라는 통념부터 확인합시다. 작은 쪽 자릿수를 19 로 맞추고 모양만 다섯 가지로
바꿔 실제로 실행하면 값이 크게 갈립니다.

```text
자릿수가 같은데 걸음이 갈리는 다섯 모양

  몫이 거의 다 1     두 수의 비가 황금비에 가깝다
  몫이 전부 2        두 수의 비가 1 + √2 에 가깝다
  몫 하나가 아주 큼  두 값의 차가 1 이다
  한쪽이 배수        첫 나머지가 0 이다
  둘 다 같은 값      첫 나머지가 0 이다
```

<!--proof:shape-values-->

```text
입력 모양                        작은 쪽 자릿수   걸음 수                         |x|                           g
몫이 거의 다 1 (피보나치 이웃)               19        89   1,100,087,778,366,101,931                           1
몫이 전부 2 (펠 수열 이웃)                   19        49     835,002,744,095,575,440                           1
몫 하나가 아주 큼                            19         2                           1                           1
한쪽이 다른 쪽의 배수                        19         1                           0   1,000,000,000,000,000,000
둘 다 같은 값                                19         1                           0   1,000,000,000,000,000,000
```

**첫 줄과 셋째 줄을 견주세요.** 자릿수가 19 로 같은데 걸음이 89 번과 2 번입니다. 통념은 이
절차에서 절반만 맞아요 — 자릿수가 상한을 정하지만 실제 횟수는 몫이 정합니다.

```text
최악은 몫을 될 수 있는 한 1 로 만드는 입력이다

  비가 황금비에 가까운 두 수     한 걸음이 값을 조금만 줄인다
  그것이 곧 피보나치 이웃 쌍     F(k) / F(k-1) 이 황금비로 수렴한다
  자릿수를 제약 상한까지 채운다  걸음 수와 |x| 가 함께 상한에 이른다
                                 └ 몫 전부를 1 로 만들 수는 없다 — 마지막 몫은 2 이상이라는
                                   것을 「수식 정의와 유도」가 보였다. 피보나치 이웃도
                                   89 개 중 마지막 하나만 2 다
```

이 편에서는 최악이 **두 가지를 함께** 최악으로 만듭니다. 걸음이 89 번이면서 `|x|` 도
1.1e18 로 상한 `B / (2g)` 에 가장 가까워요. 가장 적은 일을 하는 입력은 반대쪽입니다 — 한쪽이
다른 쪽의 배수면 걸음 하나에 끝나고 `|x|` 는 0 입니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 계수를 대입해 **찾던** 것을 나머지와 함께
**만드는** 것으로 바꿨고, 만드는 방법은 나머지를 만든 몫을 계수 두 벌에 그대로 다시 쓰는 것이며,
그 근거는 등식 둘의 차가 다시 같은 꼴의 등식이라는 것 하나입니다.

```text
부호를 떼고 (1,0)·(0,1) 로 시작 → 몫 하나로 세 자리를 갱신 → r1 이 0 이면 부호를 다시 붙인다
                                    └ A·s + B·t = r 이 그대로다      └ s0 가 x, t0 가 y 다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T7 에서 반복이 끝날 때 계수 두 벌에 값이 둘씩 남아
있었어요. 답으로 쓴 것은 `(s0, t0) = (14, -39)` 이고 버린 것은 `(s1, t1) = (-61, 170)` 입니다.
**버린 두 수는 각각 무엇입니까** — 그리고 그것으로 무엇을 할 수 있습니까?

```text
T7   q=4   12 = 4 × 3 + 0   → (r0,r1)=(3,0)  (s0,s1)=(14,-61)  (t0,t1)=(-39,170)
                                                       ^^^              ^^^
                                                       이 둘은 무엇인가?
```

<!--check:lastPair-->
답: `B / g` 와 `A / g` 에 부호를 붙인 것입니다. `183 / 3 = 61` 이고 `510 / 3 = 170` 이에요.
`510 × (-61) + 183 × 170 = 0` 이므로 이 쌍은 **0 을 만드는 조합**이고, 답에 몇 배를 더해도
등식이 그대로 유지됩니다.

```text
버린 쌍으로 다른 해를 만들면

  k = 0   x = -14,  y = -39      -510×(-14) + 183×(-39) = 3
  k = 1   x =  47,  y = 131      -510×47 + 183×131 = 3
  k = 2   x = 108,  y = 301      -510×108 + 183×301 = 3
          └ x 는 61 씩, y 는 170 씩 옮겨 간다. 그것이 일차 디오판토스 방정식의 일반해다
```
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 불변식                       3 → 최악을 만드는 입력
  2 → 수식 정의와 유도
```

- 불변식은 「`r1` 이 매 바퀴 엄격하게 줄어든다」고 말합니다. 그러면 `|s1|` 은 어떻습니까 — 매
  바퀴 커집니까, 아니면 그대로인 걸음이 있습니까. T2 와 T3 의 값을 보고 답해 보세요.
- 유도가 낸 상한은 `|x| ≤ B / (2g)` 였고 전개 입력에서 실측이 14, 상한이 30 이었습니다.
  그러면 `B` 를 고정했을 때 그 상한에 가장 가까운 입력은 무엇입니까 — 그리고 그 입력의 두
  수를 어떻게 만들겠습니까.
- 최악 입력에서 `g` 가 1 이었습니다. `g` 가 3 이면서 걸음이 가장 많은 열아홉 자리 입력은 어떻게
  만들 수 있습니까. 그때 걸음 수와 `|x|` 는 `g` 가 1 일 때와 견주어 어떻게 됩니까.
