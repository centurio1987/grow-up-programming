# 이진 거듭제곱 — 지수를 한 칸 옮길 때마다 곱셈이 많아야 두 번인 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 밑을 지수만큼
차례로 곱하는 방법에서 출발해 지수의 비트 수만큼만 곱하는 방법까지 가고, 그 방법을 단계마다 값으로 푼 뒤,
실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

정수 셋을 받아 **밑을 지수만큼 거듭제곱한 값을 법으로 나눈 나머지**를 구하는 과제입니다. 밑 `base`,
지수 `exp`, 법 `mod` 셋이고, 법은 나누는 수를 말해요. 답은 언제나 `0` 이상 `mod` 미만입니다. 이 글의 전개
입력 하나를 먼저 값으로 보겠습니다.

<!--proof:conceptTask-->
```text
fastPower(3n, 26n, 1000n)
  거듭제곱   3^26 = 2,541,865,828,329
  나머지     2,541,865,828,329 mod 1,000 = 329
```

가장 정직한 방법은 밑을 지수만큼 차례로 곱하는 것입니다. 그러면 곱셈 횟수가 지수 그 자체라, 지수가
`10^18` 이면 곱셈도 `10^18` 번이에요. 이 글이 세우는 방법은 곱셈 횟수를 **지수의 비트 수**로 줄입니다.
그 방법의 이름이 **이진 거듭제곱**(binary exponentiation)이고, 이 글은 끝까지 이 이름 하나로 부릅니다.

이진 거듭제곱이 쓰는 것은 지수의 **이진 표현**입니다. 어떤 자연수든 2 의 거듭제곱들의 합으로 딱 한 가지
방법으로 적히고, 그 합에 어느 자리가 들어갔는지를 0 과 1 로 늘어놓은 것이 이진 표현이에요. 자리 번호는
가장 낮은 자리(맨 오른쪽)가 0 이고 왼쪽으로 갈수록 하나씩 커집니다. 비트가 1 인 자리를 **켜진 자리**라고
부르겠습니다.

<!--fig:concept-bits-->
![26 의 켜진 자리 1 · 3 · 4 — 그 자리의 거듭제곱 셋을 곱하면 답이다](./figs/concept-bits.svg)

지수가 합으로 적히면 거듭제곱은 곱으로 갈라집니다. `3^26 = 3^(16 + 8 + 2) = 3^16 · 3^8 · 3^2` 이라, 그림
맨 아래 줄에서 켜진 자리의 칸 셋만 곱하면 답이 나와요. 맨 아래 줄의 칸을 **자리의 거듭제곱**이라고
부릅니다. 자리 `i` 의 거듭제곱은 `base^(2^i)` 를 법으로 줄인 값이고, 오른쪽 칸을 제곱하면 왼쪽 칸이 됩니다.
그래서 자리 하나에 곱셈이 한 번씩 들어요.

지수의 비트를 낮은 자리부터 한 번 지나가면 끝납니다. 자리마다 밑을 제곱해 다음 자리의 거듭제곱을 만들고,
그 자리가 켜져 있으면 누적값에 한 번 더 곱해요. 곱셈 횟수는 비트 수와 1 인 비트 수를 더한 값입니다.

<!--proof:conceptCost-->
| 지수 exp | 차례로 곱하기의 곱셈 | 이진 거듭제곱의 곱셈 | 비트 수 | 1 인 비트 수 |
| ---: | ---: | ---: | ---: | ---: |
| 26 | 26 | 8 | 5 | 3 |
| 1,000,000,000,000,000,000 | 1,000,000,000,000,000,000 | 84 | 60 | 24 |

지수 10^18 에서 곱셈이 1,000,000,000,000,000,000 번에서 84 번으로 줄었고, 84 는 비트 수 60 과 1 인 비트 수 24 를 더한 값입니다.

<!--/proof-->

들고 있는 값은 누적값 · 밑 · 남은 지수 셋뿐이라 추가로 쓰는 메모리가 `O(1)` 이고, 곱셈 횟수가 지수의
자릿수를 따라가므로 시간은 `O(log exp)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **나머지 연산의 성질.** 곱한 뒤에 나머지를 구하는 것과, 각각 나머지를 구한 뒤에 곱하고 다시 나머지를
  구하는 것이 같은 값을 냅니다. 이 성질이 있어야 중간값을 법 안에 묶어 둘 수 있어요.
- **자연수의 이진 표현.** 어떤 자연수든 2 의 거듭제곱의 합으로 딱 한 가지 방법으로 적힌다는 것과, 그
  표현의 자릿수가 수의 크기의 로그에 비례한다는 것입니다.
- **지수법칙 두 줄.** `x^(u+v) = x^u · x^v` 와 `(x^u)^2 = x^(2u)` 입니다. 이 글의 절차 전체가 이 둘에서
  나옵니다.
- **비트 AND(`&`)와 오른쪽 시프트(`>>`).** `e & 1n` 은 `e` 의 가장 낮은 자리 비트이고, `e >> 1n` 은 모든
  자리를 한 칸 아래로 내린 값입니다. 모르면
  [`binaryGap`](../../bit-manipulation/binaryGap/binaryGap-guide.md) 이 같은 두 연산으로 자리를 하나씩
  읽습니다.
- **JavaScript 의 `bigint`.** 이 글의 코드는 `bigint` 로 곱합니다. 같은 코드를 `number` 로 옮기면 어디서
  어긋나는지는 첫 번째 「짚고 가기」에서 값으로 확인합니다.

이 글이 구하는 값을 재료로 쓰는 알고리즘으로는 [`millerRabin`](../millerRabin/millerRabin-guide.md) 과
[`binomialModP`](../binomialModP/binomialModP-guide.md) 가 있습니다. 거꾸로 밑과 결과를 알 때 지수를 찾는
일은 [`babyStepGiantStep`](../babyStepGiantStep/babyStepGiantStep-guide.md) 이 다룹니다.

### 아이디어를 떠올리는 과정 — 밑을 차례로 곱하기에서 이진 거듭제곱까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 밑 · 지수 · 법을 받아 나머지를
돌려줍니다.

```ts
function fastPower(base: bigint, exp: bigint, mod: bigint): bigint;
```

- 입력: 밑 `base` 는 임의의 정수이고 음수여도 됩니다. 지수 `exp` 는 `0` 이상, 법 `mod` 는 `1` 이상입니다.
- 출력: `base` 를 `exp` 번 곱한 값을 `mod` 로 나눈 나머지. 범위는 `0` 이상 `mod` 미만입니다.
- 규모: 지수는 64 비트 정수로 받는 경우가 흔해서, 이 글은 그 범위 안의 어림수 `10^18` 을 상한으로 잡고
  잽니다. 법은 흔히 쓰는 소수 `1,000,000,007` 언저리까지 봅니다. 비용은 흔한 채점 환경의 예산인 1 초(단순
  연산 1 초에 1 억 번)에 대어 잽니다.

이 글이 쓰는 기호는 아홉입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `base` | 입력으로 받는 밑 | 임의의 정수, 음수를 포함한다 |
| `exp` | 입력으로 받는 지수 | `0 ≤ exp ≤ 10^18` |
| `mod` | 입력으로 받는 법. 나누는 수다 | `mod ≥ 1` |
| `i` | 지수의 자리 번호. 가장 낮은 자리가 0 이다 | `exp = 10^18` 이면 0 부터 59 까지 |
| `b` | 코드가 들고 있는 밑. 바퀴 `i` 를 시작할 때 자리 `i` 의 거듭제곱이다 | `0 ≤ b < mod` |
| `e` | 코드가 들고 있는 남은 지수. 바퀴마다 한 칸 아래로 옮긴다 | `0 ≤ e ≤ exp` |
| `result` | 코드가 누적하는 값. 마지막에 이 값이 답이 된다 | `0 ≤ result < mod` |
| `n` | `exp` 의 비트 수 | `exp = 10^18` 이면 60 |
| `s` | `exp` 의 이진 표현에서 1 인 비트의 개수 | `exp = 10^18` 이면 24 |

「바퀴」는 반복문 본문을 한 번 실행하는 것을 말합니다. 바퀴 하나가 비트 하나를 처리하므로 바퀴 수와
`n` 이 같고, 바퀴 `i` 가 자리 `i` 를 처리해요. 비용은 끝까지 **모듈러 곱셈 횟수**(곱한 뒤 법으로 줄이는
곱셈 한 번을 하나로 센다)로 세고, 메모리는 **추가 칸**(입력 `base` · `exp` · `mod` 밖에 새로 잡아 들고 있는 값의
개수)으로 셉니다.

가장 먼저 떠오르는 방법으로 시작합시다. `result` 를 `1` 에서 출발시켜 밑을 `exp` 번 곱하는 것입니다.

```ts
function repeatedMultiply(base: bigint, exp: bigint, mod: bigint): bigint {
  let acc = 1n % mod;
  const b = ((base % mod) + mod) % mod;
  for (let i = 0n; i < exp; i++) {
    acc = (acc * b) % mod; // 지수 하나마다 곱셈 한 번
  }
  return acc;
}
```

이 방법은 답을 틀리지 않습니다. 하는 일의 양이 **지수 그 자체**라, 규모를 넣어 보면 몇 번인지 바로 나와요.

<!--proof:costNaive-->
| 지수 exp | 곱셈 횟수 | 초당 1 억 번일 때 시간 |
| ---: | ---: | ---: |
| 26 | 26 | 0.00000026 초 |
| 1,000 | 1,000 | 0.00001 초 |
| 1,000,000 | 1,000,000 | 0.01 초 |
| 1,000,000,000 | 1,000,000,000 | 10 초 |
| 1,000,000,000,000,000,000 | 1,000,000,000,000,000,000 | 10,000,000,000 초 |

마지막 줄의 10,000,000,000 초는 약 317 년입니다.

<!--/proof-->

지수가 `10^9` 이면 이미 10 초로 예산의 열 배이고, `10^18` 이면 수백 년입니다. 그러면 이 곱셈들 안에서 무엇이
되풀이되는지 봅시다. 곱셈 한 번이 지수에 하는 일은 두 가지뿐이에요.

| 곱셈 | 지수의 변화 |
| --- | --- |
| `x^u` 에 밑 `x` 를 곱한다 | `u` 에서 `u + 1` 로 |
| `x^u` 를 자기 자신과 곱한다 | `u` 에서 `2u` 로 |

아래 줄은 곱셈 한 번으로 지수를 두 배로 만듭니다. 그러면 지수를 1 씩 올라가는 대신, 거꾸로 2 로 나눠
내려가 보면 몇 걸음이 되는지 셀 수 있어요. 지수 26 을 2 로 나눠 봅시다.

<!--proof:halveChain-->
| e | e 를 2 로 나눈 몫 | 나머지 |
| ---: | ---: | ---: |
| 26 | 13 | 0 |
| 13 | 6 | 1 |
| 6 | 3 | 0 |
| 3 | 1 | 1 |
| 1 | 0 | 1 |

5 번 나누어 0 이 됐고, 나머지를 아래 줄부터 읽으면 11010 으로 26 의 이진 표기입니다.

<!--/proof-->

나머지가 0 이면 그 걸음의 지수가 짝수, 1 이면 홀수입니다. 이제 가장 아래에서부터 거슬러 올라가면서 실제
값을 잇습니다. `3^0 = 1` 에서 출발해 한 걸음 올라갈 때마다 직전 값을 제곱하고, 홀수 걸음이면 밑 3 을 한 번
더 곱해요.

<!--proof:foldChain-->
| 구하는 값 | 직전 값으로 하는 일 | 값 | 누적 곱셈 |
| --- | --- | ---: | ---: |
| 3^0 | — | 1 | 0 |
| 3^1 | 제곱한 뒤 밑을 한 번 더 | 3 | 2 |
| 3^3 | 제곱한 뒤 밑을 한 번 더 | 27 | 4 |
| 3^6 | 제곱 | 729 | 5 |
| 3^13 | 제곱한 뒤 밑을 한 번 더 | 1,594,323 | 7 |
| 3^26 | 제곱 | 2,541,865,828,329 | 8 |

3^26 을 곱셈 8 번으로 얻었습니다. 차례로 곱하면 26 번입니다.

<!--/proof-->

여기서 비용이 무엇으로 정해지는지가 드러납니다. 제곱은 2 로 나누는 걸음마다 한 번이고, 밑을 한 번 더
곱하는 것은 나머지가 1 이었던 걸음마다 한 번이에요. 앞의 것은 이진 표기의 자릿수 `n`, 뒤의 것은 그중 1 인
자리의 수 `s` 입니다. 같은 지수를 두 방식으로 처리해 곱셈 횟수를 나란히 세어 보겠습니다.

<!--proof:costTwoWays-->
| 지수 exp | 차례로 곱하기 | 반씩 줄이기 | 비트 수 n | 1 인 비트 수 s |
| ---: | ---: | ---: | ---: | ---: |
| 26 | 26 | 8 | 5 | 3 |
| 1,000 | 1,000 | 16 | 10 | 6 |
| 1,000,000 | 1,000,000 | 27 | 20 | 7 |
| 1,000,000,000 | 1,000,000,000 | 43 | 30 | 13 |
| 1,000,000,000,000,000,000 | 1,000,000,000,000,000,000 | 84 | 60 | 24 |

5 규모 모두에서 반씩 줄이기의 곱셈 횟수가 n 과 s 를 더한 값과 같습니다.

<!--/proof-->

셋째 열은 지수의 크기가 아니라 지수를 2 로 적었을 때의 모양에서 나옵니다. 여기서 관찰한 것은 하나예요.
**지수의 비트마다 곱셈이 많아야 두 번 든다**는 것입니다.

이 관찰을 절차로 세우기 전에, 더 단순한 후보부터 시험해 봅시다. 「제곱이 지수를 두 배로 만드는 것이
요점이니 제곱만 되풀이하면 되지 않나」가 그것이에요. 밑을 제곱하고 또 제곱해, 지수를 넘지 않는 가장 큰 2 의
거듭제곱까지 올라가는 것입니다.

<!--proof:squaringOnly-->
| 입력 | 정본의 답 | 제곱만 되풀이한 답 | 실제로 구한 지수 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 3^26 mod 1000 | 329 | 721 | 16 | 틀리다 |
| 3^16 mod 1000 | 721 | 721 | 16 | 같다 |
| 2^10 mod 1000 | 24 | 256 | 8 | 틀리다 |
| 5^7 mod 100 | 25 | 25 | 4 | 같다 |
| 3^13 mod 1000 | 323 | 561 | 8 | 틀리다 |

넷째 줄은 5^4 mod 100 과 5^7 mod 100 이 둘 다 25 라 같게 나왔고, 실제로 구한 지수는 4 입니다.

<!--/proof-->

지수가 2 의 거듭제곱이면 같은 값이 나오지만, 26 처럼 그 사이에 있는 지수는 만들 수 없습니다. 제곱만
되풀이하면 지수가 1 · 2 · 4 · 8 · 16 · 32 로만 가고, 26 은 16 과 32 사이에 있어요. 모자란 10 을 채울 방법이
이 후보에는 없습니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **이진 거듭제곱**입니다. 지수를 이진 표현으로 적고, 자리마다 밑을 제곱해 그 자리의 거듭제곱을
만들면서, 켜진 자리의 거듭제곱만 누적값에 곱하는 방법이에요. 자리의 거듭제곱이 어떻게 생겼는지, 자리를
어떻게 하나씩 읽는지, 누적은 언제 하는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 이진 거듭제곱

이 아이디어를 한 문장으로 줄이면 이렇습니다. **지수의 비트를 가장 낮은 자리부터 하나씩 읽으면서, 자리마다
밑을 제곱해 그 자리의 거듭제곱을 만들고, 비트가 1 인 자리의 거듭제곱만 누적값에 곱합니다.** 미리 만들어
두는 것이 없어서 세 단계 모두 호출 한 번 안에서 바퀴마다 해요.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 지수를 자리로 나누기 | `e & 1n` 으로 이번 자리의 비트를 읽고 `e` 를 한 칸 옮긴다 | — |
| 2단계 자리의 거듭제곱 만들기 | 바퀴를 시작할 때의 `b` 를 제곱해 다음 자리의 거듭제곱으로 둔다 | 1단계가 정한 바퀴 수 |
| 3단계 켜진 자리의 거듭제곱 누적하기 | 비트가 1 이면 `result` 에 `b` 를 곱한다 | 1단계의 비트 · 2단계의 `b` |

#### 먼저 알아 둘 개념 — 자리의 거듭제곱

이 아이디어의 한 문장이 기대는 이름은 **자리의 거듭제곱**입니다. 곱셈 횟수가 줄어드는 것도, 켜진 자리만
곱하면 답이 되는 것도 이 줄이 어떻게 생겼는지에서 나와요.

##### 쉬운 말 정의

자리의 거듭제곱은 **지수의 자리마다 하나씩 두는, 밑을 그 자리의 크기만큼 거듭제곱한 값**입니다. 자리 `i`
의 크기는 `2^i` 이므로 자리 `i` 의 거듭제곱은 `base^(2^i)` 이고, 이 글에서는 늘 법으로 줄인 값으로 둡니다.
코드에서는 바퀴 `i` 를 시작할 때의 `b` 가 이 값이에요.

##### 전개 입력 위의 모양

밑 3, 법 1,000 에서 자리 0 부터 5 까지 그리면 이렇습니다. 그림은 이진 표기처럼 높은 자리를 왼쪽에 둡니다.

<!--fig:build-powers-->
![자리 i 의 거듭제곱 3^(2^i) mod 1000 — 왼쪽 칸은 오른쪽 이웃을 제곱한 값](./figs/build-powers.svg)

자리 5 까지 그린 까닭이 있습니다. 26 의 비트는 자리 4 까지인데, 코드는 마지막 바퀴에서도 제곱을 한 번 해서
자리 5 의 거듭제곱까지 만들어요. 그 값이 어디에도 쓰이지 않는다는 것은 「수행으로 알아보는 알고리즘」의 T7
에서 확인합니다.

##### 칸 하나를 읽는 법

칸 하나를 골라 이름에서 값까지 따라가 봅시다. 자리 3 을 고르면 지수는 `2^3` 이고, 그 거듭제곱을 법으로
줄이면 칸의 값이 나옵니다.

<!--proof:powersRead-->
```text
자리 3 의 거듭제곱
  지수        2^3 = 8
  값          3^8 = 6,561
  법 안으로   6,561 mod 1,000 = 561
  정본 기록   바퀴 3 을 시작할 때 b = 561
```

정의대로 구한 값과 정본이 바퀴 3 을 시작할 때 들고 있던 `b` 가 같습니다. 칸의 값은 그 자리의 크기만큼
밑을 곱한 것을 법 안으로 옮긴 것이에요.

##### 이웃 칸끼리의 관계

오른쪽 이웃과의 관계는 제곱 하나입니다. 지수법칙 `(x^u)^2 = x^(2u)` 에서 `u = 2^i` 로 두면
`(base^(2^i))^2 = base^(2^(i+1))` 이라, 자리 `i` 의 거듭제곱을 제곱하면 자리 `i + 1` 의 거듭제곱이에요.
그림의 ▲ 두 칸이 그 관계이고, 이 관계가 2단계의 전부입니다.

제곱한 뒤 법으로 줄여도 되는 것은 나머지 연산의 성질 덕분입니다. 법으로 줄인 값끼리 곱하고 다시 줄여도,
줄이기 전의 값을 곱하고 줄인 것과 같은 나머지가 나와요. 그래서 칸의 값은 늘 `mod` 미만에 머뭅니다.

##### 헷갈리기 쉬운 모양과의 비교

처음 보면 「밑을 한 번씩 더 곱한 줄」, 곧 `base^i` 를 먼저 떠올리기 쉽습니다. 두 줄을 같은 여섯 칸에
나란히 놓아 봅시다.

<!--proof:powersVsLinear-->
| 자리 i | 지수 2^i | 3^(2^i) mod 1000 | 지수 i | 3^i mod 1000 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 1 | 3 | 0 | 1 |
| 1 | 2 | 9 | 1 | 3 |
| 2 | 4 | 81 | 2 | 9 |
| 3 | 8 | 561 | 3 | 27 |
| 4 | 16 | 721 | 4 | 81 |
| 5 | 32 | 841 | 5 | 243 |

같은 6 칸으로 자리의 거듭제곱은 지수 32 까지, 밑의 i 제곱은 지수 5 까지 갑니다. 지수 26 을 만들려면 뒤쪽은 칸이 27 개 있어야 하고, 앞쪽은 5 칸 중 켜진 3 칸을 곱하면 됩니다.

<!--/proof-->

`base^i` 의 줄은 이웃 칸이 밑 한 번 차이라 칸 하나가 지수를 1 씩만 올립니다. 자리의 거듭제곱은 이웃 칸이
제곱 차이라 칸 하나가 지수를 두 배로 올려요. 같은 칸 수로 갈 수 있는 지수가 이만큼 벌어집니다.

##### 이렇게 생긴 까닭

지수가 이진 표현으로 `2^i` 들의 합이 되니, 그 합에 들어가는 조각이 정확히 `base^(2^i)` 들입니다. 그래서
자리마다 이 값 하나씩만 있으면 어떤 지수든 켜진 자리를 골라 곱해서 만들 수 있어요. 자리 수가 `n` 개뿐이라
칸도 `n` 개면 충분하고, 칸을 오른쪽부터 제곱 한 번씩으로 채우므로 곱셈이 `n` 번 듭니다. 전체 컨셉의
그림이 켜진 자리 셋을 골라 곱한 모습이었어요.

#### 1단계 — 지수를 자리로 나누기

지수의 자리를 가장 낮은 것부터 하나씩 읽습니다. 가장 낮은 자리의 비트는 `e & 1n` 이고, 읽은 뒤에는
`e >>= 1n` 으로 모든 자리를 한 칸 아래로 내려 다음 자리를 가장 낮은 자리로 가져와요. 26 에 실행하면
이렇습니다.

<!--proof:stage1Bits-->
| 바퀴 | e | e 의 이진 표기 | e & 1 | e >> 1 |
| ---: | ---: | --- | ---: | ---: |
| 0 | 26 | 11010₂ | 0 | 13 |
| 1 | 13 | 1101₂ | 1 | 6 |
| 2 | 6 | 110₂ | 0 | 3 |
| 3 | 3 | 11₂ | 1 | 1 |
| 4 | 1 | 1₂ | 1 | 0 |

e 가 5 바퀴 만에 0 이 됐고, 바퀴마다 읽은 e & 1 을 차례로 적은 0 1 0 1 1 이 26 의 비트를 자리 0 부터 적은 것입니다.

<!--/proof-->

`e >> 1n` 은 2 로 나눈 몫과 같아서, 이 표는 「아이디어를 떠올리는 과정」에서 26 을 2 로 나눠 내려간 표와 같은
수를 지나갑니다. 비트를 문자열로 바꿔 왼쪽부터 읽는 방법도 있지만, 그러면 문자열의 칸 번호와 자리 번호가
거꾸로 가요. 시프트로 읽으면 바퀴 번호가 곧 자리 번호입니다.

빠뜨리는 자리가 없다는 것은 반복의 종료 조건으로 말할 수 있습니다. 반복은 `e > 0n` 인 동안 계속되고,
`e` 는 바퀴마다 한 칸씩 내려가 비트 수 `n` 바퀴째에 0 이 돼요. 그래서 자리 0 부터 자리 `n − 1` 까지 각
자리를 정확히 한 번씩 읽습니다.

#### 2단계 — 자리의 거듭제곱 만들기

1단계가 자리를 하나 읽을 때마다, 그 자리의 거듭제곱 `b` 를 제곱해 다음 자리의 거듭제곱으로 바꿔 둡니다.
`b = (b * b) % mod` 한 줄이고, 첫 바퀴의 `b` 는 밑을 법 안으로 옮긴 값이에요.

<!--proof:stage2Squares-->
| 바퀴 | 바퀴 시작 b | b · b | 법으로 줄인 b | 3^(2^(i+1)) mod 1000 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 3 | 9 | 9 | 9 |
| 1 | 9 | 81 | 81 | 81 |
| 2 | 81 | 6,561 | 561 | 561 |
| 3 | 561 | 314,721 | 721 | 721 |
| 4 | 721 | 519,841 | 841 | 841 |

5 바퀴 모두 제곱해 줄인 값이 정의대로 구한 다음 자리의 거듭제곱과 같습니다. 곱하기 전의 b 는 늘 1,000 미만이고, 곱한 값은 가장 커도 519,841 입니다.

<!--/proof-->

크기도 여기서 정해집니다. `b` 는 법으로 줄인 값이라 늘 `mod` 미만이고, 제곱한 중간값은 `(mod − 1)^2` 을
넘지 않아요. 법이 1,000 이면 그 값이 여섯 자리 안이지만, 법이 `10^9` 언저리면 열여덟 자리까지 갑니다. 이
차이가 `bigint` 를 쓰는 까닭이고, 첫 번째 「짚고 가기」가 그 자리를 값으로 보입니다.

#### 3단계 — 켜진 자리의 거듭제곱 누적하기

1단계가 읽은 비트가 1 이면, 2단계가 제곱하기 **전**의 `b` — 곧 이번 자리의 거듭제곱 — 를 `result` 에
곱합니다. 쉬운 경우는 비트가 1 인 바퀴이고, 불안한 경우는 비트가 0 인 바퀴예요. 비트가 0 이면 `result` 가
그대로라 아무 일도 없는 것처럼 보이는데, 그 바퀴에서도 `b` 는 제곱돼야 합니다. 바퀴마다 두 값을 적으면
이렇습니다.

<!--proof:stage3Acc-->
| 자리 i | 비트 | 바퀴 시작 b | 바퀴 시작 result | 바퀴 끝 result |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 3 | 1 | 1 |
| 1 | 1 | 9 | 1 | 9 |
| 2 | 0 | 81 | 9 | 9 |
| 3 | 1 | 561 | 9 | 49 |
| 4 | 1 | 721 | 49 | 329 |

result 는 비트가 1 인 3 바퀴에서만 바뀌었습니다. 비트가 0 인 자리 0 · 2 에서도 b 는 3 → 9, 81 → 561 로 제곱됐고, 그 값을 다음 자리가 썼습니다.

<!--/proof-->

비트가 0 인 바퀴에서 제곱을 건너뛰면 다음 자리가 자기 거듭제곱이 아니라 한 자리 아래의 값을 받습니다. 그
결과가 어떤 답으로 나오는지는 「불변식」에서 제곱하는 줄을 지워 확인해요. 반복이 끝났을 때 `result` 가
정말 켜진 자리의 거듭제곱의 곱인지 따로 곱해서 맞춰 봅시다.

<!--proof:onBitsProduct-->
```text
켜진 자리          1 · 3 · 4
그 자리의 지수     2 + 8 + 16 = 26
그 자리의 거듭제곱 9 · 561 · 721 mod 1000 = 329
정본의 답          329
```

켜진 자리의 지수를 더하면 26 이 되고, 그 자리의 거듭제곱을 곱해 줄이면 정본의 답이 나옵니다. 반복은 1단계의
종료 조건대로 모든 자리를 한 번씩 읽으므로, 켜진 자리 `s` 개가 빠짐없이 한 번씩 곱해져요.

#### 이 방법이 기대는 전제

이진 거듭제곱은 아래 두 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 곱셈이 결합법칙을 지킨다 | 켜진 자리의 거듭제곱을 어떤 순서로 묶어 곱해도 같은 값이다 | 곱하는 순서에 따라 답이 달라진다 |
| 곱한 뒤 법으로 줄여도 나머지가 같다 | 2단계와 3단계가 곱할 때마다 줄인다 | 중간값을 줄일 수 없어 자릿수가 지수를 따라 커진다 |

둘째 전제가 없을 때의 모습은 첫 번째 「짚고 가기」가 실행 결과로 보입니다. 첫째 전제는 밑이 수가 아니어도
된다는 뜻이기도 해서, 파트 1 의 마지막 절에서 행렬과 문자열에 같은 절차를 걸어 봅니다.

#### 2 로 나누는 까닭

지수를 2 가 아니라 `k` 로 나눠 내려가도 같은 생각이 통합니다. 자리마다 밑을 `k` 제곱하고(곱셈 `k − 1` 번),
그 자리의 숫자만큼 누적하면 돼요. `k` 를 몇 가지로 놓고 두 지수에서 곱셈을 세었습니다.

<!--proof:foldRadix-->
| 나누는 수 | 지수 26 의 곱셈 | 지수 10^18 의 곱셈 |
| --- | ---: | ---: |
| 차례로 곱하기 | 26 | 1,000,000,000,000,000,000 |
| k = 2 | 8 | 84 |
| k = 3 | 12 | 116 |
| k = 4 | 14 | 127 |
| k = 8 | 19 | 197 |
| k = 10 | 26 | 172 |

k 를 쓰는 다섯 줄 가운데 두 지수 모두 k = 2 가 가장 적습니다. 10^18 을 십진법으로 적으면 자리 숫자의 합이 1 이라 누적 곱셈이 1 번뿐이고, 그래서 k = 10 이 k = 8 보다 적습니다.

<!--/proof-->

`k` 를 키우면 자리 수는 줄지만 자리 하나를 만드는 곱셈이 `k − 1` 번으로 늘어납니다. 두 힘이 맞물려 `k = 2`
에서 가장 적어지고, 임의의 지수에서도 그런지는 「수식 정의와 유도」에서 식으로 풉니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 여섯 걸음이 됩니다. 2 · 3 · 4 · 5 가 반복 한 바퀴이고, 3 이 3단계,
4 가 2단계, 5 가 1단계예요. 이렇게 하면 곱셈이 지수만큼이던 것이 지수의 비트 수의 두 배 이하가 됩니다.

1. `result` 를 `1` 을 `mod` 로 나눈 나머지로, `b` 를 `base` 를 `[0, mod)` 로 옮긴 값으로 둔다
2. `e` 를 `exp` 로 두고, `e` 가 0 보다 큰 동안 아래를 되풀이한다
3. `e` 의 최하위 비트가 1 이면 `result` 에 `b` 를 곱하고 `mod` 로 줄인다
4. `b` 를 제곱하고 `mod` 로 줄인다
5. `e` 를 오른쪽으로 한 칸 옮긴다
6. `result` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 비트 다섯 개로 3^26 을 법 1,000 에서 구한다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walkInput-->
```ts
const [base, exp, mod] = [3n, 26n, 1000n];
// 이 절이 끝나면 329n 이 나와야 한다
```

왜 하필 이 셋일까요? 지수 26 의 이진 표현 `11010` 에 **0 인 비트와 1 인 비트가 둘 다 있고**, 최하위 비트가
0 이라 누적을 건너뛰는 갈래가 첫 바퀴에서 먼저 나옵니다. 밑 3 과 법 1,000 은 중간값이 여섯 자리 안이라
표로 읽혀요.

```text
fastPower(base, exp, mod):
    result ← 1 % mod,  b ← base 를 [0, mod) 로,  e ← exp         ① 초기화
    e > 0 인 동안:                                                ② 남은 비트가 있는가
        e 의 최하위 비트가 1 이면  result ← result · b % mod     ③ 누적
        b ← b · b % mod                                           ④ 다음 자리의 거듭제곱
        e ← e 를 오른쪽으로 한 칸                                 ⑤ 다음 비트로
    result 를 반환한다
```

#### 1. 두 값을 법 안으로 옮긴다

첫 조각은 준비입니다. 누적값을 `1` 에서 출발시키고 밑을 법 안으로 옮기며, 아직 반복문에는 들어가지 않아요.

```ts
let result = 1n % mod; // ① 1 도 mod 로 나눈 나머지로 둔다
let b = ((base % mod) + mod) % mod; // ① 밑을 [0, mod) 안으로 옮긴다
let e = exp;
```

`①` 의 두 줄이 각각 경계 하나씩을 맡습니다. 첫 줄의 `1n % mod` 는 `mod` 가 `1` 일 때 `0` 을 만들고, 둘째
줄은 음수 밑을 `0` 이상으로 옮겨요. 실행하면 이렇게 나옵니다.

<!--proof:walkInit-->
```text
T1 이 끝난 시점 — base = 3, exp = 26, mod = 1000
  result = 1
  b      = 3
  e      = 26
```

경계에 있는 입력을 넣으면 두 줄이 이렇게 나옵니다.

<!--proof:walkInitEdges-->
| 입력 | 1n % mod | base % mod | ((base % mod) + mod) % mod |
| --- | ---: | ---: | ---: |
| base = 5, mod = 1 | 0 | 0 | 0 |
| base = -3, mod = 5 | 1 | -3 | 2 |
| base = 1005, mod = 1000 | 1 | 5 | 5 |
| base = 3, mod = 1000 | 1 | 3 | 3 |

base % mod 가 음수로 나온 줄은 1 개이고, mod 를 더해 한 번 더 줄이면 모든 줄이 0 이상 mod 미만이 됩니다.

<!--/proof-->

둘째 줄에 `+ mod` 가 붙은 이유가 `base = -3` 줄에 있습니다. JavaScript 의 `%` 는 나머지의 부호를 왼쪽 값에
맞추므로 밑이 음수면 결과도 음수이고, 그대로 두면 답이 `[0, mod)` 를 벗어나요.

#### 짚고 가기 — 나머지를 마지막에 한 번만 구해도 bigint 에서는 답이 안 틀린다

여기서 헷갈리기 쉬운 포인트는 **나머지를 언제 구하는가**입니다. 「곱셈을 다 하고 마지막에 한 번만 나머지를
구해도 같은 값 아닌가」로 읽기 쉬워요. 그 생각대로 적어 봅시다.

```ts
function lastModOnly(base: bigint, exp: bigint, mod: bigint): bigint {
  let acc = 1n;
  for (let i = 0n; i < exp; i++) acc = acc * base; // 나머지를 안 구하고 계속 곱한다
  return ((acc % mod) + mod) % mod; // 마지막에 한 번만
}
```

**`bigint` 로 적으면 답이 한 번도 안 틀립니다.** 그런데 중간값의 자릿수가 지수를 따라 커지고, 같은 코드를
`number` 로 옮기면 그때는 답이 어긋나요.

<!--proof:pauseLastMod-->
| 입력 | 정본의 답 | 마지막에 한 번만 | 중간값의 자릿수 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 3^26 mod 1000 | 329 | 329 | 13 | 같다 |
| 3^40 mod 1000 | 801 | 801 | 20 | 같다 |
| 2^64 mod 1000 | 616 | 616 | 20 | 같다 |
| 7^50 mod 13 | 10 | 10 | 43 | 같다 |

밑이 3 일 때 중간값의 자릿수는 지수를 따라 커집니다.

| 지수 exp | 3^exp 의 자릿수 |
| ---: | ---: |
| 26 | 13 |
| 1,000 | 478 |
| 100,000 | 47,713 |
| 1,000,000,000,000,000,000 | 약 4.7712e+17 |

같은 방법을 number 로 하면 답이 어긋납니다.

| 입력 | 정본의 답 | number 로 마지막에 한 번만 | 판정 |
| --- | ---: | ---: | --- |
| 3^33 mod 1000 | 523 | 523 | 같다 |
| 3^34 mod 1000 | 569 | 568 | 틀리다 |
| 3^40 mod 1000 | 801 | 768 | 틀리다 |
| 2^1023 mod 1000 | 608 | 608 | 같다 |
| 2^1024 mod 1000 | 216 | NaN | 틀리다 |

밑이 3 일 때 3^exp 가 2^53 = 9,007,199,254,740,992 보다 커지는 첫 지수는 34 이고, number 로 2^1024 를 계산하면 Infinity 가 됩니다.

<!--/proof-->

첫 표에서 답이 안 틀린다는 것을 먼저 적어 둡니다. `bigint` 는 자릿수를 필요한 만큼 늘리므로 값이 정확하고,
그래서 작은 입력만 시험하면 이 자리를 끝까지 모르고 넘어가요. 그래도 곱할 때마다 줄여야 하는 까닭은 둘째
표에 있습니다. 지수가 `10^18` 이면 중간값의 자릿수가 `10^17` 규모라 메모리에 담을 수 없어요.

그러면 곱할 때마다 줄이기만 하면 `number` 로도 되느냐 하면, 그렇지 않습니다. 줄인 값끼리 곱한 중간값도
`(mod − 1)^2` 까지 가기 때문이에요. 정본을 그대로 `number` 로 옮긴 사본을 실행하면 이렇습니다.

<!--proof:pauseNumberPort-->
| 입력 | 정본의 답 | number 로 옮긴 사본 | 가장 큰 중간 곱 | 2^53 초과 | 판정 |
| --- | ---: | ---: | ---: | --- | --- |
| 전개 입력 3^26 mod 1000 | 329 | 329 | 519,841 | 아니요 | 같다 |
| 3^(10^18) mod 1,000,000,007 | 246336683 | 161209770 | 987,454,991,051,874,601 | 예 | 틀리다 |
| 2^(10^9) mod 1,000,000,007 | 140625001 | 534304927 | 730,523,252,424,640,900 | 예 | 틀리다 |

법이 1,000 이면 가장 큰 곱도 2^53 아래라 number 로 옮긴 사본이 맞고, 법이 1,000,000,007 이면 곱이 2^53 을 넘어 답이 어긋납니다.

<!--/proof-->

`number` 는 `2^53` 을 넘는 정수를 정확히 담지 못합니다. 법이 `10^9` 언저리면 중간 곱이 그 한계를 넘어 한
자리가 반올림되고, 그 뒤의 모든 곱셈이 틀린 값을 이어받아요. 그래서 이 글의 정본은 **곱할 때마다 법으로
줄이고, 그 곱셈을 `bigint` 로 합니다.**

#### 2. 최하위 비트를 보고 누적한 뒤 밑을 제곱한다

둘째 조각은 반복문입니다. 바퀴 하나가 비트 하나를 처리해요 — 최하위 비트가 1 이면 누적하고, 그다음 밑을
제곱하고, 지수를 한 칸 옮깁니다.

```ts
while (e > 0n) {
  // ② 남은 비트가 있는가
  if ((e & 1n) === 1n) {
    result = (result * b) % mod; // ③ 그 자리의 거듭제곱을 누적한다
  }
  b = (b * b) % mod; // ④ 다음 자리의 거듭제곱을 만든다
  e >>= 1n; // ⑤ 다음 비트로 옮긴다
}
```

앞 세 바퀴만 실행하면 이렇게 나옵니다.

<!--proof:walkLoopHead-->
| 걸음 | 바퀴 시작 e | 이번 비트 | 바퀴 시작 b | ③ 뒤 result | ④ 뒤 b | ⑤ 뒤 e |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| T2 | 26 | 0 | 3 | 1 | 9 | 13 |
| T3 | 13 | 1 | 9 | 9 | 81 | 6 |
| T4 | 6 | 0 | 81 | 9 | 561 | 3 |

② 는 e 가 26 · 13 · 6 · 3 · 1 일 때 참이고 0 에서 처음 거짓이 됩니다. ③ 은 5 바퀴 중 3 바퀴에서만 실행되고 ④ · ⑤ 는 5 바퀴 다 실행됩니다.

<!--/proof-->

T3 이 이 세 줄의 핵심입니다. 비트가 1 이라 `result` 가 처음으로 바뀐 자리이고, 곱한 `b = 9` 는 T2 의 `④` 가
3 을 제곱해 만들어 둔 값이에요. `③` 이 쓰는 `b` 는 이번 자리의 거듭제곱이고 `④` 가 만드는 `b` 는 다음 자리의
것이라, 두 줄의 순서가 곧 자리의 순서입니다.

#### 짚고 가기 — 제곱을 먼저 하면 한 자리 위의 거듭제곱을 곱한다

여기서 헷갈리기 쉬운 포인트는 `③` 과 `④` 의 순서입니다. 「어차피 같은 바퀴 안이니 밑을 먼저 제곱하고 비트를
봐도 되지 않나」로 읽기 쉬워요. 두 줄의 자리를 바꿔 봅시다.

```ts
while (e > 0n) {
  b = (b * b) % mod; // 제곱을 먼저 했다
  if ((e & 1n) === 1n) result = (result * b) % mod;
  e >>= 1n;
}
```

다섯 입력에 실행해 봅니다.

<!--proof:pauseSquareFirst-->
| 입력 | 정본의 답 | 제곱을 먼저 한 답 | 판정 |
| --- | ---: | ---: | --- |
| 전개 입력 3^26 mod 1000 | 329 | 241 | 틀리다 |
| 2^10 mod 7 | 2 | 4 | 틀리다 |
| 2^13 mod 5 | 2 | 4 | 틀리다 |
| 7^0 mod 13 | 1 | 1 | 같다 |
| 10^4 mod 9 | 1 | 1 | 같다 |

지수가 0 이면 바퀴가 없어 같고, 10^4 mod 9 는 10 mod 9 가 1 이라 몇 번 제곱해도 1 입니다.

<!--/proof-->

어긋나는 이유는 하나입니다. 바퀴 `i` 를 시작할 때의 `b` 가 자리 `i` 의 거듭제곱인데, 제곱을 먼저 하면 그
자리에서 자리 `i + 1` 의 거듭제곱을 곱하게 돼요.

<!--proof:pauseSquareFirstPlace-->
```text
전개 입력에서 자리 1 의 비트를 볼 때 곱해지는 b
  정상 순서   3^2 = 9
  바꾼 순서   3^4 = 81
```

자리 1 은 26 의 `2` 를 채워야 하는데, 바꾼 순서는 26 에 없는 `4` 를 채웁니다. 켜진 자리마다 한 자리씩 위의
값이 들어가 답이 통째로 달라져요.

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 `result` 를 돌려주는 마지막 한 줄뿐이에요 —
지수가 `0` 이면 반복문이 한 번도 실행되지 않아 `1n % mod` 가 그대로 답이 됩니다.

```ts
export function fastPower(base: bigint, exp: bigint, mod: bigint): bigint {
  // ① 두 값을 법 안으로 옮기고 시작한다 — result 는 1 을 mod 로 나눈 나머지이고(mod 가 1
  //    이면 이 값이 0 이다), b 는 base 를 [0, mod) 로 옮긴 값이다.
  let result = 1n % mod;
  let b = ((base % mod) + mod) % mod;
  let e = exp;

  while (e > 0n) {
    // ② 아직 처리할 비트가 남았는가 — 남아 있으면 아래 세 줄을 한 번 실행한다.
    if ((e & 1n) === 1n) {
      // ③ 이번 비트가 1 이면 그 자리의 값을 result 에 곱해 둔다.
      result = (result * b) % mod;
    }
    // ④ 밑을 제곱해 다음 비트 자리의 값으로 만든다.
    b = (b * b) % mod;
    // ⑤ 지수를 오른쪽으로 한 칸 옮겨 다음 비트를 최하위로 보낸다.
    e >>= 1n;
  }

  return result;
}
```

```text
fastPower(3n, 26n, 1000n)       → 329n
fastPower(2n, 10n, 1000n)       → 24n
fastPower(123n, 0n, 1000n)      → 1n
fastPower(5n, 100n, 1n)         → 0n
fastPower(-3n, 3n, 5n)          → 3n
fastPower(1005n, 2n, 1000n)     → 25n
```

### 알아 두면 좋은 개념 — 결합법칙만 요구하는 거듭제곱

이 절차가 밑에 대해 쓴 성질은 둘뿐입니다 — `(x · y) · z = x · (y · z)` 인 **결합법칙**과, 곱해도 값이 안
바뀌는 **항등원** 1 이에요. 교환법칙도, 역원도, 값이 수인지도 한 번도 쓰지 않았습니다. 결합법칙과 항등원만
있는 구조를 **모노이드**라고 부르고, 이진 거듭제곱은 모노이드의 원소를 거듭제곱하는 절차입니다.

그래서 같은 절차가 **수가 아닌 대상**에도 그대로 걸립니다. 곱셈 자리에 다른 결합 연산을 끼우고 지수 26 을
넣으면 이렇게 나와요.

<!--proof:relatedMonoid-->
| 밑 | 곱셈 자리의 연산 | 항등원 | 지수 26 으로 만든 값 |
| --- | --- | --- | --- |
| 법 1000 의 정수 3 | 곱한 뒤 나머지 | 1 | 329 |
| 2×2 행렬 [[1,1],[1,0]] | 행렬 곱(법 1000) | 단위 행렬 | [[418,393],[393,25]] |
| 문자열 "ab" | 이어 붙이기 | 빈 문자열 | 길이 52 의 문자열 |

세 경우 모두 켜진 자리 1 · 3 · 4 의 값만 곱했습니다. 행렬의 오른쪽 위 칸 393 은 피보나치 수 F(26) = 121,393 을 1,000 으로 나눈 나머지입니다.

<!--/proof-->

바뀐 것은 곱셈의 뜻 하나뿐이고, 켜진 자리와 바퀴 수는 밑이 무엇이든 그대로입니다. 행렬로 바꾼 사례는
[`matrixPowerFibonacci`](../../bit-manipulation/matrixPowerFibonacci/matrixPowerFibonacci-guide.md) 가 다룹니다.
지수를 거꾸로 찾는 [`babyStepGiantStep`](../babyStepGiantStep/babyStepGiantStep-guide.md) 의 정본도 같은 절차를
`power` 라는 이름으로 싣고, 큰 걸음의 보폭을 구하는 데 써요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 곱셈 횟수를 임의의 지수로 어떻게 내는지,
무엇이 매 바퀴 참으로 남는지, 그리고 곱셈이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 같은 값을 여러 번 곱한다 | 서로 다른 값을 곱하는 것이면 자리의 거듭제곱을 다시 쓸 수 없다 | `b` 하나를 제곱해 자리마다 다시 쓴다 |
| 곱셈이 결합법칙을 지킨다 | 이 조건만 있으면 밑이 수가 아니어도 된다 | 곱셈 자리에 행렬 곱이 와도 코드 모양이 같다 |
| 곱셈 한 번의 비용이 일정하다 | 법으로 줄여 값을 `mod` 미만으로 묶는 것이 이 조건을 만든다 | 곱할 때마다 `% mod` 를 붙인다 |
| 답이 한 번 필요하다 | 같은 밑에 지수만 바꿔 여러 번 물으면 미리 표를 만드는 설계가 따로 있다 | 미리 만드는 표가 없다 |

셋째 줄이 이 절차의 경계입니다. 법이 없어 값이 계속 커지는 과제에서는 곱셈 한 번의 비용이 자릿수를 따라
커지므로, 곱셈 횟수만 세는 이 글의 계산이 그대로는 시간이 되지 않아요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "거듭제곱을 법으로 나눈 나머지를 구하라"   <- 법이 붙은 거듭제곱이다
  "지수가 10^18 까지"  "매우 큰 지수"        <- 지수만큼 곱할 수 없다
  "역원"  "1,000,000,007 로 나눈 나머지"     <- 페르마의 소정리로 a^(p-2) 를 구한다
  "수열의 먼 항을 구하라"  "선형 점화식"     <- 행렬로 바꿔 같은 절차를 쓴다

제약에 이런 모양이 보이면
  지수가 32 비트를 넘어 64 비트 정수로 들어온다
  법이 소수이고 10^9 언저리다

반대로 이런 말이 보이면 해당하지 않는다
  "지수가 음수일 수 있다"                    <- 역원이 있어야 하고 법이 소수여야 한다
  "법 없이 정확한 값을 출력하라"             <- 값의 자릿수가 지수를 따라 커진다
```

첫 무리의 셋째 줄이 이 절차가 가장 자주 쓰이는 자리입니다. 법이 소수 `p` 이고 `a` 가 `p` 의 배수가 아니면
페르마의 소정리로 `a^(p−1) ≡ 1 (mod p)` 이고, 양변을 나누면 `a · a^(p−2) ≡ 1` 이라 `a` 의 역원이
`a^(p−2) mod p` 예요. 나눗셈 하나가 지수 `p − 2` 짜리 거듭제곱 한 번으로 바뀌고, 그 지수가 `10^9` 언저리라
이진 거듭제곱이 그대로 필요합니다.

#### 실제로 쓰이는 곳

- **CPython 의 세 인자 `pow`.** `Objects/longobject.c` 의 `long_pow` 가 이 절차를 싣습니다. 주석이 *"For
  exponentiation, use the binary left-to-right algorithm unless the exponent contains more than
  HUGE_EXP_CUTOFF bits. In that case, do (no more than) EXP_WINDOW_SIZE bits at a time."* 라고 적고,
  `#define EXP_WINDOW_SIZE 5` 와 `#define HUGE_EXP_CUTOFF 60` 이 그 아래 있어요. 지수가 60 비트 아래면 비트
  하나씩 처리하고, 그보다 크면 다음 절이 다루는 설계로 갈아탑니다. CPython 은 높은 자리부터 읽는
  left-to-right 판이고, 이 글은 낮은 자리부터 읽는 판입니다. 곱셈 횟수는 둘이 같아요.
  ([`Objects/longobject.c`](https://raw.githubusercontent.com/python/cpython/main/Objects/longobject.c),
  조회 2026-08-30)

```text
CPython 이 남긴 계산 (같은 파일의 주석)
  "Suppose the exponent has bit length e. All ways of doing this need e squarings."
  "The binary method also needs a multiply for each bit set."
  "the binary method needs about e/2 extra mults and the window method about 16 + e/5"
```

- **Go 표준 라이브러리 `math/big`.** `src/math/big/nat.go` 의 `expNN` 이 같은 일을 하고, 주석이 *"If m != 0
  (i.e., len(m) != 0), expNN sets z to x\*\*y mod m; otherwise it sets z to x\*\*y."* 로 이 함수가 구하는 값을
  적습니다. 인용문의 `m` 이 이 글의 `mod` 이고 `y` 가 `exp` 예요. 큰 지수에서는 `expNNWindowed` 로 갈아타는데,
  그 주석이 *"expNNWindowed calculates x\*\*y mod m using a fixed, 4-bit window, where m = 2\*\*logM."* 입니다.
  ([`src/math/big/nat.go`](https://raw.githubusercontent.com/golang/go/master/src/math/big/nat.go), 조회
  2026-08-30)

CPython 주석의 앞 두 줄이 이 글이 센 `n + s` 와 같은 계산입니다 — 인용문의 `e` 는 지수의 비트 수라 이 글의
`n` 이에요. 두 구현을 같은 기준으로 나란히 놓으면 이렇습니다.

| 기준 | 이 글 | CPython | Go |
| --- | --- | --- | --- |
| 작은 지수의 절차 | 비트 하나씩 | binary left-to-right | `expNN` 의 기본 경로 |
| 큰 지수의 절차 | 없다 | `EXP_WINDOW_SIZE` 5 비트 창 | `expNNWindowed` 의 4 비트 창 |
| 갈아타는 기준 | 없다 | `HUGE_EXP_CUTOFF` 60 비트 | 주석으로 확인하지 못했습니다 |

Go 쪽의 갈아타는 기준은 소스의 조건문에 있고 주석 문장으로 적혀 있지 않아 **원문 인용으로 옮기지
못했습니다.** 둘 다 지수가 작을 때는 비트 하나씩 처리하고 클 때만 창 방식으로 갈아타는데, 그 갈림이 다음
절의 주제예요.

#### 경쟁 설계와의 대조

같은 목표(같은 밑의 거듭제곱을 법에서 구하는 것)를 노리는 다른 절차로 **5 비트 슬라이딩 창**이 있습니다.
밑의 홀수 거듭제곱 `base^1, base^3, …, base^31` 을 미리 표로 만들어 두고, 지수의 비트를 최상위부터 최대
다섯 개씩 묶어 표의 칸 하나를 한 번에 곱하는 방식이에요. 두 설계가 지수 하나를 처리하는 방법은 이렇게
갈립니다.

| 설계 | 자리마다 | 곱셈이 한 번 더 드는 때 | 미리 만드는 것 |
| --- | --- | --- | --- |
| 이진 거듭제곱 | 제곱 한 번 | 켜진 자리마다 | 없다 |
| 5 비트 창 | 제곱 한 번 | 묶음마다 | 표 16 칸(곱셈 16 번) |

같은 밑(`3`)과 같은 법(`1,000,000,007`)에 두 설계를 실행하고 **모듈러 곱셈 횟수**를 셌습니다. 지수는
다섯이에요 — 전개 입력 `26`, 40 비트, 41 비트, 과제 규모 `10^18`, 그리고 1,024 비트입니다. 전개 입력이 아닌
넷은 생성식 `exp(n) = (3^n mod 2^n) | 2^(n−1)` 로 만들었고, 최상위 비트를 세워 정확히 `n` 비트가 되게 한
것이에요. 난수를 쓰지 않아 시드가 없습니다. **전개 입력만으로 재지 않은 이유**는 그 지수가 비트 다섯이라 표를
만드는 곱셈 16 번이 전체를 덮어, 두 설계의 계수가 규모에 따라 어떻게 갈리는지 보이지 않기 때문입니다.

| 지수 | 이진 거듭제곱 | 5 비트 창 | 적은 쪽 |
| --- | --- | --- | --- |
| 전개 입력 26 | **8** | 17 | 이진 거듭제곱 |
| 40 비트 | **58** | **58** | 같다 |
| 41 비트 | 68 | **59** | 5 비트 창 |
| `10^18` (60 비트) | 84 | **78** | 5 비트 창 |
| 1,024 비트 | 1,503 | **1,206** | 5 비트 창 |

**추가 칸은 3 개 대 19 개입니다.** 이진 거듭제곱은 `result` · `b` · `e` 셋이고, 창 방식은 여기에 표
16 칸을 더했어요. 둘 다 재지 않고 개수를 적은 값이고 입력은 세지 않습니다.
메모리에서는 이진 거듭제곱이 늘 적어요. 갈리는 것은 곱셈 횟수이고, 이
생성식에서 순서가 처음 뒤집히는 자리가 **지수 41 비트**입니다. 창 방식이 먼저 내는 곱셈 16 번은 지수의 비트
수와 상관없이 고정이고, 이진 거듭제곱이 켜진 비트마다 더 내는 곱셈과 창 방식이 묶음마다 더 내는 곱셈의 차이가
16 을 넘는 자리에서 순서가 바뀌어요.

**이진 거듭제곱이 내주는 것은 큰 지수에서의 곱셈 횟수입니다.** 1,024 비트에서 1,503 번 대 1,206 번이고, 그
대신 얻는 것이 셋이에요 — 추가 칸이 3 개로 끝나고, 표를 만드는 전처리가 없고, 반복문 하나라 창의 아래 끝을
찾는 규칙을 따로 맞출 일이 없습니다. 축을 넷으로 갈라 적으면 이렇습니다.

| 축 | 이진 거듭제곱 | 5 비트 창 | 적은 쪽 |
| --- | --- | --- | --- |
| 1,024 비트 지수의 곱셈 | 1,503 | 1,206 | 5 비트 창 |
| 추가 칸 | 3 | 19 | 이진 거듭제곱 |
| 전처리 곱셈 | 없다 | 16 | 이진 거듭제곱 |
| 구현 | 반복문 하나 | 창의 아래 끝을 찾는 규칙이 따로 있다 | 이진 거듭제곱 |

**우열이 반대가 되는 조건은 지수의 비트 수입니다.** 지수가 41 비트 아래면 이진 거듭제곱이 곱셈도 적거나 같고
추가 칸도 적어요. 41 비트 위면 창 방식이 곱셈이 적고, 추가 칸은 3 대 19 로 뒤집니다. 이 글의 과제 규모는
60 비트라 윗줄이고, `10^18` 에서 84 대 78 이에요. 추가 칸을 얼마나 아끼려는가가 남은 갈림입니다. CPython 이
갈아타는 기준을 60 비트로 둔 것도 같은 갈림이고, 창 너비를 1 로 두면 표가 한 칸이 되어 두 절차가 같아집니다.

### 수식 정의와 유도

`c_i` 를 `exp` 의 자리 `i` 의 비트라 하고, `β_i` 를 자리 `i` 의 거듭제곱이라 합니다. `n` 은 비트 수, `s` 는
1 인 비트의 개수예요. `n` 의 식은 `exp` 가 `1` 이상일 때의 것이고, `exp = 0` 이면 비트가 하나도 없어 `n` 도
`s` 도 `0` 입니다.

$$\text{exp} = \sum_{i=0}^{n-1} c_i 2^i, \quad c_i \in \{0, 1\}, \qquad n = \lfloor \log_2 \text{exp} \rfloor + 1, \qquad s = \sum_{i=0}^{n-1} c_i$$

$$\beta_0 = \text{base} \bmod \text{mod}, \qquad \beta_{i+1} = \beta_i^2 \bmod \text{mod}, \qquad \beta_i = \text{base}^{2^i} \bmod \text{mod}$$

**정의를 값에 넣어 검산해 봅시다.** 전개 입력의 다섯 자리를 전부 넣습니다.

<!--proof:mathCheck-->
| 자리 | 2^i | c_i | β_i = 3^(2^i) mod 1000 |
| --- | ---: | ---: | ---: |
| i = 0 | 1 | 0 | 3 |
| i = 1 | 2 | 1 | 9 |
| i = 2 | 4 | 0 | 81 |
| i = 3 | 8 | 1 | 561 |
| i = 4 | 16 | 1 | 721 |

켜진 자리의 β 만 곱하면 9 · 561 · 721 mod 1000 = 329 이고, 켜진 자리의 2^i 를 더하면 2 + 8 + 16 = 26 입니다. n = 5, s = 3, n + s = 8 이고, 정본의 답 329 와 같습니다.

<!--/proof-->

**이제 유도합니다.** 지수법칙 `x^(u+v) = x^u · x^v` 를 이진 표현에 적용하면 거듭제곱이 자리마다의 값들의
곱으로 갈라져요.

$$\text{base}^{\text{exp}} = \text{base}^{\sum_i c_i 2^i} = \prod_{i=0}^{n-1} \bigl(\text{base}^{2^i}\bigr)^{c_i} = \prod_{i : c_i = 1} \beta_i \pmod{\text{mod}}$$

변형은 셋이고, 남은 것이 켜진 자리의 `β_i` 들의 곱입니다. 등호마다 한 일은 이렇습니다.

| 등호 | 한 일 | 근거 |
| --- | --- | --- |
| 첫째 | `exp` 를 이진 표현으로 바꿔 적었다 | 정의를 그대로 넣었다 |
| 둘째 | 지수의 합을 거듭제곱의 곱으로 갈랐다 | `x^(u+v) = x^u · x^v` |
| 셋째 | `c_i = 0` 인 항을 지웠다 | `x^0 = 1` |

곱셈 횟수도 같은 식에서 나옵니다. `β` 를 자리 하나 올리는 데 곱셈이 한 번, 켜진 자리를 누적하는 데 곱셈이 한
번이에요.

$$M(\text{exp}) = \underbrace{n}_{\beta \text{ 를 올린다}} + \underbrace{s}_{\text{누적한다}}, \qquad n + 1 \le M(\text{exp}) \le 2n$$

경계 둘은 `s` 가 1 이상 `n` 이하라서 나옵니다. 최상위 비트는 `n` 의 정의상 1 이므로 `exp ≥ 1` 에서 `s = 0` 인
경우가 없어요.

| 경계 | `s` 의 값 | 그런 지수 | `M` |
| --- | --- | --- | --- |
| 가장 작을 때 | `s = 1` | `exp` 가 2 의 거듭제곱 | `n + 1` |
| 가장 클 때 | `s = n` | `exp` 의 비트가 전부 1 | `2n` |

여기서 본문의 값만으로는 안 나오는 것이 나옵니다. **나누는 수 `k` 를 임의로 두었을 때 `k = 2` 가 최소라는
것**이에요. `k` 로 나누면 자리 수가 `log_k(exp)` 이고, 자리 하나에 드는 곱셈이 `k − 1` 에 그 자리의 숫자를
더한 값입니다. 자리의 숫자가 `0` 부터 `k − 1` 까지 고르게 나온다고 보면 그 평균이 `(k − 1) / 2` 예요.

$$M_k(\text{exp}) \approx \frac{\ln \text{exp}}{\ln k}\left(k - 1 + \frac{k-1}{2}\right) = \frac{3}{2} \cdot \frac{k-1}{\ln k} \cdot \ln \text{exp}$$

`ln exp` 는 `k` 와 상관없는 값이라, 최소가 되는 `k` 는 `(k − 1) / ln k` 하나로 정해집니다.

<!--proof:mathRadix-->
| k | k − 1 | ln k | (k − 1) / ln k |
| ---: | ---: | ---: | ---: |
| 2 | 1 | 0.6931 | 1.4427 |
| 3 | 2 | 1.0986 | 1.8205 |
| 4 | 3 | 1.3863 | 2.1640 |
| 8 | 7 | 2.0794 | 3.3663 |
| 10 | 9 | 2.3026 | 3.9087 |

다섯 값 가운데 k = 2 가 가장 작습니다.

<!--/proof-->

`k = 2` 를 넣으면 `(k − 1) / 2 = 0.5` 라, 자리 하나에 제곱 한 번과 평균 절반 번의 누적이 듭니다. 실제로 `n + s`
에서 `s` 가 `n` 의 절반 언저리예요. 이 비율을 그대로 옮긴 조각이 아래입니다.

```ts
// 자리 하나를 올리는 데 드는 곱셈. k = 2 면 1 번, k = 4 면 3 번이다.
const perPlace = (k: number): number => k - 1;
// 자리 수. k 가 커질수록 줄지만 perPlace 가 그보다 빨리 커진다.
const places = (exp: number, k: number): number => Math.log(exp) / Math.log(k);
```

닫힌 형태를 실측과 맞추고 과제 규모의 계수를 냅니다.

<!--proof:mathScale-->
| 지수 exp | n | s | 실측 곱셈 | n + s | 하한 n + 1 | 상한 2n |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 26 | 5 | 3 | 8 | 8 | 6 | 10 |
| 1,000 | 10 | 6 | 16 | 16 | 11 | 20 |
| 1,000,000 | 20 | 7 | 27 | 27 | 21 | 40 |
| 1,000,000,000 | 30 | 13 | 43 | 43 | 31 | 60 |
| 1,000,000,000,000,000,000 | 60 | 24 | 84 | 84 | 61 | 120 |

실측과 닫힌 형태가 5 규모에서 같습니다. 과제 규모 10^18 의 곱셈은 84 번이고, 차례로 곱하는 방법의 1,000,000,000,000,000,000 번과 비교하면 자릿수가 19 에서 2 로 줄었습니다.

<!--/proof-->

### 불변식 — 바퀴를 시작할 때마다 result · b^e 가 법에서 base^exp 와 같다

파트 1 에서 코드가 동작하는 것을 일곱 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지 언제나
맞는다는 뜻은 아니에요. 무엇이 **매 바퀴 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해
봅시다.

> **반복문의 각 바퀴를 시작하는 시점과 반복이 끝난 시점마다**, `result · b^e ≡ base^exp (mod mod)` 가
> 참입니다. 여기서 `base` 와 `exp` 는 처음 받은 입력이고 `result` · `b` · `e` 는 그 시점의 값입니다.

<!--proof:invariantRounds-->
| 시점 | result | b | e | result · b^e mod 1000 | 3^26 mod 1000 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 바퀴 0 시작 | 1 | 3 | 26 | 329 | 329 |
| 바퀴 1 시작 | 1 | 9 | 13 | 329 | 329 |
| 바퀴 2 시작 | 9 | 81 | 6 | 329 | 329 |
| 바퀴 3 시작 | 9 | 561 | 3 | 329 | 329 |
| 바퀴 4 시작 | 49 | 721 | 1 | 329 | 329 |
| 반복이 끝난 뒤 | 329 | 841 | 0 | 329 | 329 |

6 시점 모두에서 두 값이 329 로 같습니다.

<!--/proof-->

전개 입력의 여섯 시점에서 두 쪽을 값으로 대어 본 것이 위 표입니다. 문장 하나에 두 몫이 들어 있어요.
`result` 는 이미 처리한 자리들의 곱이고, `b^e` 는 아직 처리하지 않은 몫입니다. 바퀴가 하는 일은 남은 몫에서
자리 하나를 떼어 이미 처리한 쪽으로 옮기는 것이고, 바퀴 도중에는 세 줄 사이에서 잠깐 어긋나므로 「시작하는
시점」이 문장에 꼭 들어가야 해요.

**출발점부터 봅시다.** 반복문에 들어가기 전 `result` 는 `1 % mod`, `b` 는 `base` 를 법 안으로 옮긴 값, `e` 는
`exp` 입니다. 그러면 왼쪽이 `1 · base^exp` 라 오른쪽과 같아요. 그다음 한 바퀴는 `e` 가 짝수인가 홀수인가에
따라 둘 중 하나를 합니다.

| 바퀴 시작의 `e` | 바퀴가 하는 일 | 바퀴 끝의 왼쪽 | 유지되는 근거 |
| --- | --- | --- | --- |
| 짝수 | 누적을 건너뛰고 `b` 를 `b^2` 로, `e` 를 `e/2` 로 | `result · (b^2)^(e/2)` | `b^e = (b^2)^(e/2)` |
| 홀수 | `result` 를 `result · b` 로, 나머지는 위와 같이 | `(result · b) · (b^2)^((e−1)/2)` | `b^e = b · (b^2)^((e−1)/2)` |

정수 `e` 는 짝수이거나 홀수이고 그 사이의 다른 경우가 없으므로, 두 줄이 갈래를 빠짐없이 덮어요. 홀수 줄은
`b^e` 에서 `b` 하나를 떼어 `result` 쪽으로 옮긴 것이고, 남는 지수 `e − 1` 이 짝수라 짝수 줄과 같은 모양이
됩니다. 반복이 끝나면 `e = 0` 이라 `b^0 = 1` 이고, 그래서 `result` 자체가 답이에요.

**경계에 있는 입력도 확인하고 갑시다.** 아래 일곱 줄이 이 함수가 받을 수 있는 모양의 끝입니다.

<!--proof:invariantEdges-->
| 입력 | 처리되는 자리 | 정본의 답 | 정의로 구한 값 |
| --- | --- | ---: | ---: |
| exp = 0 (123^0 mod 1000) | 반복문이 한 번도 실행되지 않는다 | 1 | 1 |
| mod = 1 (5^100 mod 1) | result 의 시작값이 0 이다 | 0 | 0 |
| base = 0, exp = 0 (0^0 mod 7) | 반복문이 없다 | 1 | 1 |
| base = 0, exp > 0 (0^5 mod 7) | 첫 켜진 자리에서 result 가 0 이 된다 | 0 | 0 |
| base 가 음수 ((-3)^3 mod 5) | 시작에서 [0, mod) 로 옮긴다 | 3 | 3 |
| base 가 mod 보다 크다 (1005^2 mod 1000) | 시작에서 mod 로 줄인다 | 25 | 25 |
| exp 가 2 의 거듭제곱 (3^1024 mod 1000) | 켜진 자리가 하나뿐이다 | 481 | 481 |

7 입력 모두에서 정본의 답이 정의로 구한 값과 같습니다. 마지막 줄의 곱셈은 12 번으로 비트 수 11 에 1 을 더한 값입니다.

<!--/proof-->

**이제 깨뜨려 봅시다.** 불변식에서 `b^e` 를 유지하던 줄은 밑을 제곱하는 그 한 줄이에요. 「비트가 0 인 바퀴는
아무 일도 안 하니 제곱도 필요 없지 않나」라는 생각으로 그 줄에서 제곱을 없애 봅니다.

```ts
while (e > 0n) {
  if ((e & 1n) === 1n) result = (result * b) % mod;
  b = b % mod; // ← 제곱을 없앴다. 원래는 b = (b * b) % mod 다
  e >>= 1n;
}
```

실행하면 이렇게 나옵니다.

<!--proof:mutantNoSquare-->
| 입력 | 정본의 답 | 제곱을 없앤 답 | 판정 |
| --- | ---: | ---: | --- |
| 전개 입력 3^26 mod 1000 | 329 | 27 | 틀리다 |
| 2^10 mod 1000 | 24 | 4 | 틀리다 |
| 3^5 mod 100 | 43 | 9 | 틀리다 |
| 2^1 mod 7 | 2 | 2 | 같다 |
| 7^0 mod 13 | 1 | 1 | 같다 |

<!--/proof-->

제곱이 없어지면 `b` 는 제자리인데 `e` 는 그대로 한 칸씩 내려갑니다. 그러면 남은 몫이 `(b^2)^(e/2)` 가 아니라
`b^(e/2)` 가 되어, 바퀴마다 남은 지수의 절반이 사라져요. 전개 입력에서 두 `b` 를 나란히 놓으면 이렇습니다.

<!--proof:mutantNoSquarePlaces-->
```text
전개 입력에서 바퀴를 시작할 때의 b
  정본           3 9 81 561 721
  제곱을 없앤 것 3 3 3 3 3
  변이가 낸 답   27   (1 인 비트 3 개)
```

변이의 `b` 는 자리 0 에 머물러, 켜진 자리마다 밑을 한 번씩만 곱합니다. 그래서 답이 1 인 비트 수만큼 밑을 곱한
값이 돼요. 마지막 두 줄이 「같다」로 나온 것에도 이유가 있습니다. 지수가 1 이면 바퀴가 한 번뿐이라 제곱한 값을
쓸 자리가 없고, 지수가 0 이면 바퀴 자체가 없어요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 무리입니다 — 두 값을 법 안으로 옮기는 것, 바퀴마다 비트 하나를 처리하는 것,
답을 돌려주는 것이에요. 전개의 걸음으로 세면 이렇게 나뉩니다.

<!--proof:perfCount-->
| 무리 | 걸음 | 걸음 수 | 걸음마다 제곱 | 걸음마다 누적 | 이 입력의 곱셈 |
| --- | --- | ---: | ---: | ---: | ---: |
| 초기화 | T1 | 1 | 0 | 0 | 0 |
| 바퀴 | T2 ~ T6 | 5 | 1 | 0 또는 1 | 8 |
| 반환 | T7 | 1 | 0 | 0 | 0 |
| 합계 |  |  |  |  | 8 |

제곱 5 번과 누적 3 번입니다. 앞은 비트 수 n 이고 뒤는 1 인 비트 수 s 입니다.

<!--/proof-->

T1 과 T7 은 값을 옮기기만 하는 자리라 곱셈이 없습니다. `1n % mod` 와 `((base % mod) + mod) % mod` 는 나머지
연산이지 곱셈이 아니에요. 바퀴 하나는 T2 에서 보듯 제곱 한 번에, T3 처럼 비트가 1 이면 누적 한 번이 더
붙습니다. 그래서 전체가 `n + s` 번이에요.

여기서 세지 않은 것도 적어 둡니다. 나머지 연산 `n + s` 번과 비트 검사 `n` 번은 둘 다 곱셈 횟수에 비례하므로
차수를 바꾸지 않아요. `bigint` 곱셈 한 번의 비용까지 세면 여기에 법의 자릿수에 따른 값이 곱해지는데, 법이
고정이면 그 값도 상수입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`exp` 가 2 의 거듭제곱) | `O(log exp)` | `Θ(log exp)` — 곱셈이 `n + 1` 번이다 |
| **평균적인 경우** (비트가 고르게 무작위라면 `s ≈ n/2`) | `O(log exp)` | `Θ(log exp)` |
| **최악의 경우** (`exp` 의 비트가 전부 1) | `O(log exp)` | `Θ(log exp)` — 곱셈이 `2n` 번이다 |

세 줄이 같은 차수인 것이 이 절차의 성질입니다. 최선과 최악의 곱셈 횟수가 `n + 1` 과 `2n` 이라 두 배 안에서만
갈리고, 두 값 다 `n` 에 비례해요. 최선에서도 곱셈이 `n + 1` 번이라 아래로도 `n` 에 비례하므로 `Θ` 로 적을 수
있습니다.

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리가 하나도 없다는 것이 이 절차의 특징이에요 — 표도,
정렬도, 미리 만드는 값도 없습니다. 모듈러 곱셈은 `n + s` 번이고 `n = ⌊log₂ exp⌋ + 1`, `1 ≤ s ≤ n` 이며,
추가 칸은 `result` · `b` · `e` 셋입니다. 과제 규모에 넣으면 이렇습니다.

<!--proof:perfTotal-->
```text
exp = 10^18 에서
  n = ⌊log2 exp⌋ + 1   60
  s                    24
  모듈러 곱셈 n + s    84
  추가 칸              result · b · e 셋
```

**보장의 종류는 최악 보장입니다.** 해시도, 무작위성도, 분할 상환도 쓰지 않아요 — 어떤 입력을 넣어도 곱셈이
`2n` 번을 넘지 않습니다. 평균적인 경우의 `s ≈ n/2` 는 「지수의 비트가 고르게 무작위라면」이라는 입력 분포
가정이 붙은 값이고, 구현이 만드는 무작위성이 아니라서 같은 지수에는 늘 같은 횟수가 나와요.

#### 최악을 만드는 입력

곱셈 횟수를 최대로 만들려면 **비트 수와 1 인 비트의 개수를 함께 최대로** 해야 합니다. 지수를 과제의 상한으로
두는 것만으로는 부족해요. 값으로 확인해 봅시다.

<!--proof:worstShape-->
| 지수의 모양 | 지수 exp | 비트 수 n | 1 인 비트 수 s | 곱셈 n + s |
| --- | ---: | ---: | ---: | ---: |
| 2^59 | 576,460,752,303,423,488 | 60 | 1 | 61 |
| 10^18 (과제의 상한) | 1,000,000,000,000,000,000 | 60 | 24 | 84 |
| 2^59 − 1 | 576,460,752,303,423,487 | 59 | 59 | 118 |
| 2^59 + 2^58 − 1 | 864,691,128,455,135,231 | 60 | 59 | 119 |

상한 아래에서 곱셈이 가장 많은 지수는 마지막 줄의 864,691,128,455,135,231 이고 119 번입니다. 셋째 줄의 지수는 상한의 약 58% 인데 곱셈이 118 번으로 상한의 84 번보다 많습니다.

<!--/proof-->

**「지수가 클수록 느리다」는 이 절차에서 성립하지 않습니다.** 셋째 줄은 상한보다 작은 지수인데 곱셈이 더
많아요. 마지막 줄의 지수를 만드는 방법은 하나입니다. 상한 `10^18` 의 비트 수 60 을 유지하면서 1 인 비트를
최대한 세우는 것이고, 최상위 두 자리 아래를 전부 1 로 채운 `2^59 + 2^58 − 1` 이 상한을 넘지 않는 가장 많은
1 이에요.

추가 칸의 최악은 입력과 상관없이 셋이고, 반환값은 `mod − 1` 까지 갑니다. 축마다 최악을 만드는 입력이 다르고,
곱셈 횟수의 최악은 지수의 비트 모양만 봅니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 지수를 이진수로 적어 **켜진 자리의 거듭제곱만 곱했고**, 그
값들은 직전 자리를 제곱해 하나씩 나오며, 곱셈 횟수는 지수의 크기가 아니라 비트 수와 1 인 비트의 개수의
합입니다.

```text
지수를 자리로 나눈다 → 자리마다 b 를 제곱한다 → 켜진 자리에서만 result 에 곱한다 → e 가 0 이면 result
                        └ 비트가 0 인 자리에서도 제곱한다. 그래야 다음 자리가 제 거듭제곱을 받는다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T6 은 마지막 바퀴였고, 거기서 `④` 가 `b` 를 제곱했어요. 그런데 그
값은 어디에도 쓰이지 않습니다. 그러면 마지막 바퀴에서 `④` 를 건너뛰도록 조건을 붙이는 것이 나을까요?

<!--proof:selfcheckT6-->
```text
T6   e = 1   비트 1   b = 721   result → 329   ④ 가 b 를 841 로 만든다
```

<!--check:whySquareAlways-->
붙일 수 있지만 얻는 것이 적습니다. 마지막 바퀴인지 판단하려면 바퀴 안에서 `e` 가 1 인지 검사해야 하고, 그
검사는 바퀴마다 한 번씩 늘어나요. 그렇게 해서 아끼는 곱셈은 호출 하나마다 **정확히 한 번**입니다.

곱셈 횟수의 차수는 `n + s` 로 그대로이고, 아끼는 한 번은 상수항입니다. 아래 표처럼 지수가 클수록 그 비율이
작아지고, 대신 바퀴마다 검사가 하나씩 붙어요. 그래서 이 글의 정본은 조건을 붙이지 않습니다.

<!--proof:selfcheckSkipLast-->
| 지수 exp | 매 바퀴 제곱 | 마지막 제곱을 건너뜀 | 줄어든 비율 |
| --- | ---: | ---: | ---: |
| 26 | 8 | 7 | 12.5% |
| 10^18 | 84 | 83 | 1.2% |

<!--/proof-->
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「경쟁 설계와의 대조」, 두 번째 「짚고 가기」, 「수식 정의와
유도」를 다시 보세요.

- 밑이 고정이고 지수만 `Q` 번 바뀌는 과제로 바꾸면, 5 비트 창 방식의 표 16 칸을 한 번만 만들어 `Q` 번 다시 쓸
  수 있습니다. 두 설계의 곱셈 횟수를 `Q` 와 지수의 비트 수로 각각 쓰고, 어느 `Q` 부터 순서가 뒤집히는지
  따져 보세요.
- `③` 과 `④` 의 순서를 바꾼 코드가 T3 에서 어떤 값을 곱하게 되는지, 그리고 그 값이 정상 순서의 값과 몇 자리
  어긋나는지 손으로 채워 보세요. 걸음 하나하나의 `b` 를 T2 부터 T6 까지 두 줄로 나란히 적어 비교하면 됩니다.
- 지수가 음수일 수도 있다고 요구가 바뀌면 무엇이 더 필요할까요? 법이 소수 `p` 일 때
  `a^(−1) ≡ a^(p−2) (mod p)` 라는 것을 쓸 수 있는데, 그러려면 `a` 에 어떤 조건이 붙어야 하는지와 `p` 가
  소수가 아니면 왜 이 방법이 성립하지 않는지를 적어 보세요.

## 실습 — 직접 풀어 보기

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### 빠른 거듭제곱 (Fast Exponentiation)

풀 파일: [`fastPower.ts`](./fastPower.ts) · 테스트: [`fastPower.test.ts`](./fastPower.test.ts) · 실행: `bun test src/algorithms/number-theory/fastPower/fastPower.test.ts`

#### 한 줄 요약

> 함수는 밑 `base`, 지수 `exp`, 모듈러 `mod`를 받아 $\text{base}^{\text{exp}} \bmod \text{mod}$를 반환한다.

#### 스토리

보안 팀이 RSA 암호화 시스템을 구현하고 있다. 암호화 과정에서 수백 자리 수를 수만 번 거듭제곱해야 한다. $2^{1{,}000{,}000{,}000}$처럼 지수가 10억 단위인 계산을 반복해야 한다.

단순히 `base`를 `exp`번 곱하면 수십 년이 걸린다. 수십 밀리초 안에 결과를 내야 하는 실시간 통신에는 쓸 수 없다.

결과는 모듈러 연산으로 항상 일정 범위 내로 유지되어야 하며, 결과가 $[0, \text{mod})$ 범위를 벗어나면 안 된다.

#### 함수 인터페이스

```ts
export function fastPower(base: bigint, exp: bigint, mod: bigint): bigint;
```

- `base` — 밑, 임의의 bigint
- `exp` — 지수, $\text{exp} \geq 0$인 bigint
- `mod` — 모듈러, $\text{mod} \geq 1$인 bigint
- 반환 — $\text{base}^{\text{exp}} \bmod \text{mod}$, 범위 $[0,\ \text{mod})$

#### 제약 조건

- $\text{exp} \geq 0$ (bigint)
- $\text{mod} \geq 1$ (bigint)
- `base`는 임의의 정수 (음수 포함)
- 결과는 항상 $[0,\ \text{mod})$ 범위로 정규화
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

다음 값을 계산해 반환한다.

$$\text{base}^{\text{exp}} \bmod \text{mod}$$

경계 동작:

- $\text{exp} = 0$이면 결과는 $1 \bmod \text{mod}$
- $\text{mod} = 1$이면 결과는 항상 $0$
- `base`가 `mod`보다 클 때도 먼저 $\bmod \text{mod}$로 정규화한 뒤 계산한다

#### 예시

```ts
fastPower(2n, 10n, 1000n);              // 24n  — 2^10 = 1024, 1024 mod 1000 = 24
fastPower(3n, 5n, 100n);               // 43n  — 3^5 = 243, 243 mod 100 = 43
fastPower(123n, 0n, 1000n);            // 1n   — 지수 0이면 1 mod 1000 = 1
fastPower(5n, 100n, 1n);               // 0n   — mod 1이면 항상 0
fastPower(1005n, 2n, 1000n);           // 25n  — 1005 mod 1000 = 5, 5^2 = 25
fastPower(2n, 1000000000n, 1000000007n); // 페르마 소정리 활용 가능 케이스
```
