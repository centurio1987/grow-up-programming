# findAllOccurrences — 이미 맞은 부분이 다음 시작 자리를 스스로 알려 주는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 시작 자리를
하나씩 다 대조하는 방법에서 출발해 실패 함수까지 가고, 실패 함수를 단계마다 값으로 푼 뒤, 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

텍스트 `T` 안에서 패턴 `P` 가 **시작하는 자리를 전부** 오름차순으로 찾는 과제입니다. 앞 등장이 끝나기
전에 다음 등장이 시작해도 둘 다 답이에요. 텍스트 `ababcababab` 에서 패턴 `abab` 를 찾으면 이렇습니다.

<!--fig:concept-overlap-->
![ababcababab 에서 abab 가 시작하는 자리 셋 — 뒤의 둘은 두 칸을 함께 쓴다](./figs/concept-overlap.svg)

가장 먼저 떠오르는 방법은 시작 자리 후보를 하나씩 놓고, 그 자리부터 패턴과 글자를 비교하는 것입니다.
어긋나면 그 후보를 버리고 **바로 다음 자리에서 패턴의 첫 글자부터** 다시 비교해요. 텍스트와 패턴이
길어지면 비교가 후보 수와 패턴 길이의 곱만큼 늘어나서, 길이가 10 만인 텍스트에서는 수십억 번이 됩니다.

그런데 어긋난 순간 우리는 이미 알고 있는 것이 있습니다. 방금까지 맞은 글자들이 **패턴의 앞부분과
같다**는 사실이에요. 그 사실만으로 다음 후보 가운데 여럿이 이미 틀렸다는 것이 정해집니다. 문자열의
앞에서 잘라 낸 조각을 **접두사**, 뒤에서 잘라 낸 조각을 **접미사**라 하고, 원래 문자열보다 짧은 조각을
**진 조각**이라고 부릅니다. 패턴의 앞 `i + 1` 글자에서 **앞부분이자 뒷부분인 가장 긴 진 조각의 길이**를
자리마다 적어 둔 것을 **실패 함수** `fail` 이라고 부릅니다. 이 글은 그 구조를 끝까지 이 이름 하나로
부릅니다. 패턴 `abab` 의 마지막 자리를 읽으면 이렇습니다.

<!--fig:concept-fail-->
![fail[3] = 2 — abab 의 앞 두 글자와 뒤 두 글자가 ab 로 같다](./figs/concept-fail.svg)

네 자리를 모두 적으면 실패 함수가 됩니다.

<!--proof:concept-fail-->

| 자리 i | P[0..i] | fail[i] | 앞부분이자 뒷부분인 가장 긴 진 조각 |
| ---: | --- | ---: | --- |
| 0 | a | 0 | 없음 |
| 1 | ab | 0 | 없음 |
| 2 | aba | 1 | a |
| 3 | abab | 2 | ab |

abab 의 앞 2 글자와 뒤 2 글자가 둘 다 ab 라서 fail[3] 은 2 입니다.

<!--/proof-->

실패 함수는 **패턴만 보고** 만들 수 있어서 텍스트와 상관없이 한 번만 만들면 됩니다. 대조하다 어긋나면
텍스트 자리는 그대로 두고 맞은 길이만 실패 함수가 가리키는 값으로 줄여요. 그래서 텍스트 자리는
처음부터 끝까지 한 칸씩 앞으로만 갑니다. 이 절차를 만든 세 사람의 이름을 따서 크누스–모리스–프랫
(Knuth–Morris–Pratt, KMP) 알고리즘이라고 부르고, 비용을 결과만 적으면 `O(n + m)` 입니다. `n` 은
텍스트 길이, `m` 은 패턴 길이예요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **접두사와 접미사가 무엇인지.** `abab` 의 접두사는 빈 문자열 · `a` · `ab` · `aba` · `abab` 다섯이고,
  접미사는 빈 문자열 · `b` · `ab` · `bab` · `abab` 다섯이에요.
- **진 조각이 무엇인지.** 원래 문자열 자기 자신을 뺀 조각입니다. `abab` 의 진 접두사는 빈 문자열 · `a` ·
  `ab` · `aba` 넷이에요. 이 글의 실패 함수는 **진** 조각만 셉니다.
- **문자열의 글자를 자리 번호로 바로 읽을 수 있다는 것.** 글자 하나를 읽는 데 드는 일이 문자열 길이와
  상관없습니다.
- **겹치는 등장이 무엇인지.** `aaaa` 에서 `aa` 는 자리 0 · 1 · 2 에서 각각 시작하고, 이 글은 그 셋을 다
  답으로 셉니다.

이 글이 다루는 것은 **패턴 하나를 텍스트 하나에서 찾는 일**입니다. 가까운 과제는 다른 가이드가 다뤄요.

| 과제 | 다루는 가이드 |
| --- | --- |
| 패턴 하나의 시작 자리를 전부 찾는다 | 이 글 |
| 패턴 여러 개를 한 번의 대조로 함께 찾는다 | [`ahoCorasick`](../ahoCorasick/ahoCorasick-guide.md) |
| 고정된 텍스트 가운데의 조각을 여러 번 묻는다 | [`suffixArray`](../suffixArray/suffixArray-guide.md) |

### 아이디어를 떠올리는 과정 — 시작 자리 전수 대조에서 실패 함수까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다.

```ts
function findAllOccurrences(text: string, pattern: string): number[];
```

- 입력: 소문자 영문(`a`–`z`)으로 된 텍스트와 패턴. 둘 다 비어 있을 수 있습니다.
- 출력: 패턴이 시작하는 자리 번호를 오름차순으로 담은 배열. 겹치는 등장도 전부 담고, 등장이 없으면 빈
  배열입니다. 빈 패턴과 텍스트보다 긴 패턴도 빈 배열이에요.
- 규모: 텍스트 길이 `n` 과 패턴 길이 `m` 이 각각 0 이상 10 만 이하입니다. 비용은 흔한 채점 환경의 예산인
  1 초(단순 연산 1 초에 1 억 번)에 대어 잽니다.

이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `T` | 텍스트 | 소문자 영문 문자열 |
| `P` | 패턴 | 소문자 영문 문자열 |
| `n` | 텍스트 길이 | `0 ≤ n ≤ 100,000` |
| `m` | 패턴 길이 | `0 ≤ m ≤ 100,000` |
| `i` | 지금 보는 텍스트 자리 | `0 ≤ i ≤ n−1`. 작아지지 않는다 |
| `j` | 지금까지 맞은 글자 수 | `0 ≤ j ≤ m` |
| `fail` | 실패 함수 | 칸이 `m` 개다 |
| `k` | 실패 함수를 만들 때의 맞은 글자 수 | `0 ≤ k < m` |

`T[a..b]` 는 텍스트의 자리 `a` 부터 자리 `b` 까지를 양 끝 포함해 잘라 낸 조각이고, `P[0..j-1]` 은 패턴의
앞 `j` 글자예요.

가장 먼저 떠오르는 방법으로 시작합시다. 시작 자리 후보를 `0` 부터 `n − m` 까지 놓고, 각각에서 패턴과
글자를 앞에서부터 비교합니다.

```ts
const found: number[] = [];
for (let i = 0; i + m <= n; i++) {
  let ok = true;
  for (let j = 0; j < m; j++) {
    if (text[i + j] !== pattern[j]) {
      ok = false;
      break;
    }
  }
  if (ok) found.push(i);
}
```

이 방법이 하는 일의 양은 **후보 수 × 후보 하나의 비교 횟수**입니다. 패턴이 짧으면 후보는 많고 비교는
적으며, 패턴이 길면 그 반대예요. 텍스트와 패턴을 둘 다 `a` 로만 채워 **후보마다 끝까지 비교되게** 두고
패턴 길이를 바꿔 가며 세었습니다.

<!--proof:naive-cost-->

| 패턴 길이 m | 시작 자리 수 | 비교 횟수(실측) | (n−m+1)m | 찾은 자리 수 |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 11 | 22 | 22 | 11 |
| 3 | 10 | 30 | 30 | 10 |
| 4 | 9 | 36 | 36 | 9 |
| 6 | 7 | 42 | 42 | 7 |
| 9 | 4 | 36 | 36 | 4 |
| 11 | 2 | 22 | 22 | 2 |

텍스트는 a 12 개, 패턴은 a m 개입니다. 과제 규모 n = 100,000 에서 (n−m+1)m 이 가장 커지는 m 을 전수로 찾으면 m = 50,000 이고, 그때 비교가 2,500,050,000 번, 초당 1 억 번 기준 25.0 초입니다.

<!--/proof-->

패턴이 텍스트의 절반 길이일 때 곱이 가장 크고, 과제 규모에서는 예산 1 초의 스물다섯 배가 걸립니다.
양 끝(`m = 1` · `m = n`)이 아니라 가운데가 최악이라는 것도 이 표에서 나와요. 그러면 이 비교들 가운데
무엇이 되풀이되는지 봅시다. 텍스트 `aaaa` 에서 패턴 `aab` 를 찾으면 두 후보가 이렇게 읽습니다.

<!--proof:origin-reread-->

| 시작 자리 | 읽은 칸 | 맞은 글자 수 | 비교 횟수 | 앞 자리가 이미 읽은 칸 |
| ---: | --- | ---: | ---: | --- |
| 0 | T[0] T[1] T[2] | 2 | 3 | 없음 |
| 1 | T[1] T[2] T[3] | 2 | 3 | T[1] T[2] |

텍스트 "aaaa" 에서 패턴 "aab" 를 찾았습니다. 비교 6 번 가운데 2 번이 이미 읽은 칸을 다시 읽은 것입니다.

<!--/proof-->

자리 1 이 읽는 `T[1]` 과 `T[2]` 는 자리 0 이 이미 읽은 글자입니다. 같은 텍스트 글자를 후보마다 처음부터
다시 읽는 것이 되풀이의 실체예요. 비용이 무엇에 달렸는지 보려고 같은 입력을 두 방식으로 처리해 실제
비교 횟수를 나란히 세었습니다. 한쪽은 후보를 하나씩 다 대조하는 방식이고, 다른 쪽은 실패 함수를 미리
만들어 두고 텍스트를 한 번만 지나가는 방식이에요.

<!--proof:cost-two-ways-->

| 입력의 모양 (n = 12) | 텍스트 / 패턴 | 전수 대조 | 실패 함수 만들기 | 텍스트 대조 | 실패 함수 방식 합 |
| --- | --- | ---: | ---: | ---: | ---: |
| 전개 입력 | "abacabababab" / "abab" | 22 | 4 | 23 | 27 |
| 전부 같은 글자 | "aaaaaaaaaaaa" / "aaab" | 36 | 6 | 32 | 38 |
| 패턴이 되풀이된다 | "abababababab" / "abab" | 24 | 4 | 23 | 27 |
| 첫 글자부터 어긋난다 | "cccccccccccc" / "abab" | 9 | 4 | 12 | 16 |

같은 모양(텍스트가 전부 a · 패턴은 그 절반 길이)에서 규모만 키우면 이렇습니다.

| n | m | 전수 대조 | 실패 함수 방식 |
| ---: | ---: | ---: | ---: |
| 12 | 6 | 42 | 32 |
| 120 | 60 | 3,660 | 356 |
| 1,200 | 600 | 360,600 | 3,596 |
| 12,000 | 6,000 | 36,006,000 | 35,996 |

n 을 열 배 할 때마다 전수 대조는 87.1 · 98.5 · 99.9 배가 되고, 실패 함수 방식은 11.1 · 10.1 · 10.0 배가 됩니다.

<!--/proof-->

**열두 글자에서는 전수 대조 쪽이 거의 다 적습니다.** 실패 함수를 만드는 비교가 그대로 더해지기
때문이에요. 갈리는 것은 규모가 커질 때입니다. 여기서 관찰할 것은 하나예요. 전수 대조의 비용은 **후보
수에 후보 하나의 비교가 곱해지고**, 실패 함수 방식의 비용은 텍스트 길이만 따라갑니다. 뒤쪽은 텍스트
자리가 한 번도 작아지지 않기 때문이에요.

그 관찰을 아이디어로 세우기 전에 더 단순한 후보부터 시험합시다. 「어긋나면 **이미 맞은 길이만큼** 시작
자리를 옮긴다」가 그것이에요. 맞은 만큼은 이미 확인했으니 건너뛰어도 되겠다는 생각입니다.

```ts
let i = 0;
while (i + m <= n) {
  let j = 0;
  while (j < m && text[i + j] === pattern[j]) j++;
  if (j === m) {
    found.push(i);
    i += m; // 맞았으면 패턴 길이만큼 건너뛴다
  } else {
    i += Math.max(1, j); // 어긋났으면 맞은 길이만큼 건너뛴다
  }
}
```

네 입력에 실행하면 이렇게 나옵니다.

<!--proof:restart-candidates-->

| 입력 | 정본이 낸 답 | 맞은 길이만큼 옮긴 답 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 "abacabababab" / "abab" | [4, 6, 8] | [4, 8] | 어긋난다 |
| "aaaa" / "aa" | [0, 1, 2] | [0, 2] | 어긋난다 |
| "abcabc" / "abc" | [0, 3] | [0, 3] | 같다 |
| "ababcababab" / "abab" | [0, 5, 7] | [0, 5] | 어긋난다 |

네 입력 가운데 답이 같은 것은 "abcabc" / "abc" 하나이고, 그 입력만 등장이 서로 겹치지 않습니다.

<!--/proof-->

건너뛴 구간 **안에서** 다음 등장이 시작할 수 있다는 것이 이 후보가 놓치는 자리예요. `aaaa` 에서 자리 0 의
등장은 자리 1 까지인데, 다음 등장이 바로 자리 1 에서 시작합니다. 그러니 어긋났을 때 **맞은 글자 가운데
얼마를 남기고 이어 갈지**를 따로 정해야 해요.

남길 길이를 정하는 후보는 셋입니다. `0` 으로 통째로 버리기, 하나씩 줄이기, 그리고 **맞은 조각에서
앞부분이자 뒷부분인 가장 긴 진 조각의 길이**로 줄이기예요. 마지막 후보가 바로 전체 컨셉에서 이름을 붙인
실패 함수의 값입니다. 텍스트 자리는 그대로 두고 맞은 길이 `j` 만 바꾸는 세 사본을 다섯 입력에 실행했어요.

<!--proof:pullback-choice-->

| 입력 | 정답 | 0 으로 버리기 | 하나씩 줄이기 | 실패 함수 값으로 줄이기 |
| --- | --- | --- | --- | --- |
| 전개 입력 "abacabababab" / "abab" | [4, 6, 8] | [4, 6, 8] | [4, 6, 8] | [4, 6, 8] |
| "aaab" / "aab" | [1] | 없음 | [1] | [1] |
| "abba" / "aba" | 없음 | 없음 | [1] | 없음 |
| "aabaabaaa" / "aabaa" | [0, 3] | [0, 3] | [0, 3] | [0, 3] |
| "aaaaa" / "aaa" | [0, 1, 2] | [0, 1, 2] | [0, 1, 2] | [0, 1, 2] |

다섯 입력 가운데 답이 틀린 입력은 0 으로 버리는 후보가 1 개, 하나씩 줄이는 후보가 1 개, 실패 함수 값으로 줄이는 후보가 0 개입니다.

<!--/proof-->

**두 후보가 서로 다른 자리에서 어긋납니다.** `0` 으로 버리면 `"aaab"` 에서 살아 있는 후보를 지워 자리 1
의 등장을 놓치고, 하나씩 줄이면 `"abba"` 에서 없는 자리 1 을 답으로 냅니다. 지금까지 해 본 방법을 차례로
놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **실패 함수**입니다. 패턴만 보고 자리마다 앞부분이자 뒷부분인 가장 긴 진
조각의 길이를 적어 두고, 대조하다 어긋나면 텍스트 자리는 그대로 둔 채 맞은 길이만 그 값으로 줄여요.
실패 함수가 어떻게 생겼는지, 어떻게 채우는지, 대조에서 어떻게 쓰는지는 다음 절에서 실현하는 순서대로
확인합니다.

### 아이디어 상세 — 실패 함수

이 아이디어를 한 문장으로 줄이면 이렇습니다. **패턴만 보고 실패 함수를 한 번 채운 뒤, 텍스트를 한
글자씩 대조하다 어긋나면 맞은 길이를 실패 함수 값으로 줄이고, 다 맞으면 시작 자리를 적고 같은 방법으로
이어 갑니다.** 실패 함수는 처음 보는 사람에게 낯선 구조라 먼저 따로 설명하고, 그다음 실현하는 순서대로
세 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 패턴을 받았을 때 한 번 | 1단계 실패 함수 채우기 | 패턴의 자리마다 `fail[i]` 를 적는다 | — |
| 텍스트 글자마다 | 2단계 어긋나면 줄이기 | 맞은 길이 `j` 를 `fail[j-1]` 로 줄인다 | 1단계의 `fail` |
| 텍스트 글자마다 | 3단계 다 맞으면 적고 이어 가기 | 시작 자리를 적고 `j` 를 `fail[m-1]` 로 줄인다 | 1단계의 `fail` · 2단계의 `j` |

#### 먼저 알아 둘 개념 — 실패 함수

실패 함수는 **패턴의 자리 `i` 마다, 패턴의 앞 `i + 1` 글자에서 앞부분이자 뒷부분인 가장 긴 진 조각의
길이를 적은 줄**입니다. 식으로 쓰면 `fail[i] = max { b | b < i + 1, P[0..b-1] = P[i-b+1..i] }` 이고,
그런 `b` 가 없으면 0 이에요.

##### 패턴 위에 놓은 실패 함수

패턴 `abab` 의 네 자리에서 앞부분과 뒷부분을 괄호로 표시하고, 그 길이를 아래 `fail` 줄에 채웠습니다.
실선 괄호가 앞부분, 대시 괄호가 뒷부분이에요.

<!--fig:build-fail-film-->
![패턴 abab 의 실패 함수 — 자리마다 앞부분이자 뒷부분인 가장 긴 진 조각](./figs/build-fail-film.svg)

자리 0 과 1 에서는 앞부분이자 뒷부분인 진 조각이 없어 0 이고, 자리 2 에서는 `a`, 자리 3 에서는 `ab` 가
그 조각이라 1 과 2 가 됩니다.

##### 칸 하나를 읽는 법

`fail[3]` 을 골라 읽어 보겠습니다. 첨자 3 은 「패턴의 앞 네 글자 `P[0..3]`」을 가리키고, 값 2 는 그 네
글자의 앞 두 글자와 뒤 두 글자가 같다는 뜻이에요.

<!--proof:build-read-one-->

```text
fail[3] = 2
  가리키는 조각   P[0..3] = abab
  앞 2 글자       P[0..1] = ab
  뒤 2 글자       P[2..3] = ab
  뜻              맞은 4 글자의 뒤 2 글자는 그대로 P 의 앞 2 글자다
```

대조에서 이 값이 쓰이는 자리는 이렇습니다. 텍스트에서 네 글자가 맞은 직후라면, 그 네 글자의 뒤 두
글자는 그대로 패턴의 앞 두 글자예요. 그래서 맞은 길이를 4 에서 2 로 줄이면 확인한 두 글자를 버리지 않고
다음 글자부터 이어서 비교할 수 있습니다.

##### 이웃 칸끼리의 관계

이웃한 두 칸은 두 가지로 이어져 있습니다. 하나는 **한 칸 오른쪽으로 갈 때 값이 많아야 1 늘어난다**는
것이고, 다른 하나는 **경계의 경계도 경계**라는 것이에요. 패턴 `aabaa` 로 확인하면 이렇습니다.

<!--proof:build-neighbors-->

| i | P[0..i] | fail[i−1] + 1 | fail[i] | 앞 칸에서 |
| ---: | --- | ---: | ---: | --- |
| 0 | a | — | 0 | — |
| 1 | aa | 1 | 1 | 1 늘었다 |
| 2 | aab | 2 | 0 | 1 줄었다 |
| 3 | aaba | 1 | 1 | 1 늘었다 |
| 4 | aabaa | 2 | 2 | 1 늘었다 |

패턴 aabaa 에서 fail[i] 가 fail[i−1] + 1 을 넘는 자리는 없습니다. 자리 4 의 경계를 긴 것부터 모두 얻으려면 fail[4] = 2 → fail[1] = 1 → fail[0] = 0 으로 따라갑니다.

<!--/proof-->

첫째 관계는 앞부분이자 뒷부분인 조각의 끝 글자를 떼면 앞 칸의 조각이 되기 때문에 생깁니다. 길이 `b`
짜리 조각이 자리 `i` 에서 성립하면, 끝 글자를 뗀 길이 `b − 1` 짜리 조각이 자리 `i − 1` 에서 성립해요.
그래서 `fail[i] − 1 ≤ fail[i−1]` 입니다. 둘째 관계는 대조에서 어긋났을 때 **남은 후보 길이를 긴 것부터
빠짐없이** 얻는 방법을 줍니다.

##### 겹치지 않는 조각만 센 값과의 차이

「앞부분과 뒷부분은 서로 겹치지 않아야 한다」고 읽기 쉽습니다. `abab` 에서는 앞 `ab` 와 뒤 `ab` 가
겹치지 않으니 두 값이 같아요. 같은 글자가 이어진 패턴 `aaaa` 에서는 두 값이 갈립니다.

<!--proof:build-no-overlap-->

| i | P[0..i] | 실패 함수 | 겹치지 않게 센 값 |
| ---: | --- | ---: | ---: |
| 0 | a | 0 | 0 |
| 1 | aa | 1 | 1 |
| 2 | aaa | 2 | 1 |
| 3 | aaaa | 3 | 2 |

텍스트 "aaaaa" 에서 패턴 "aaaa" 를 찾으면 실패 함수로는 [0, 1], 겹치지 않게 센 값으로는 [0] 이 나옵니다.

<!--/proof-->

실패 함수는 앞부분과 뒷부분이 **겹쳐도 셉니다.** `aaa` 에서 앞 `aa` 와 뒤 `aa` 는 가운데 `a` 를 함께
쓰지만, 둘이 같다는 사실은 그대로 쓸 수 있어요. 겹치지 않게 세면 남길 길이가 짧아져서 `"aaaaa"` 의 자리 1
등장을 놓칩니다.

##### 가장 긴 조각을 적는 까닭

어긋난 자리에서 살아남는 후보는 **맞은 조각의 뒷부분이면서 패턴의 앞부분인 것**뿐입니다. 앞 절의
`"aaaa"` 에서 봤듯이 그 후보를 하나라도 지우면 등장을 놓쳐요. 가장 긴 것 하나만 적어 두면 둘째 관계로
나머지 후보를 긴 것부터 모두 얻을 수 있어서, 칸 하나에 수 하나만 적어도 됩니다. 모든 자리에 칸이 있는
것은 어긋나는 자리가 패턴의 어느 자리든 될 수 있기 때문이에요.

#### 1단계 — 실패 함수 채우기

실패 함수는 패턴을 자기 자신에 대조하며 채웁니다. `k` 는 「자리 `i − 1` 까지에서 앞부분이자 뒷부분인
가장 긴 조각의 길이」이고, 자리 `i` 에서 `P[i]` 와 `P[k]` 가 같으면 그 조각을 한 글자 늘려 `k + 1` 이
됩니다. 다르면 이웃 칸끼리의 둘째 관계대로 `k` 를 `fail[k-1]` 로 줄여 가며 다시 비교해요. 가장 쉬운 경우는
줄일 일이 없는 패턴이고, 불안한 경우는 한 번 늘린 길이를 다시 줄여야 하는 패턴입니다.

<!--proof:build-fill-->

패턴 abab 는 이렇습니다. fail[0] 은 늘 0 이라 i = 1 부터 채웁니다.

| i | P[i] | 들어올 때 k | 줄인 차례 | P[i] 와 P[k] | fail[i] |
| ---: | --- | ---: | --- | --- | ---: |
| 1 | b | 0 | — | 다르다 | 0 |
| 2 | a | 0 | — | 같다 | 1 |
| 3 | b | 1 | — | 같다 | 2 |

패턴 aabaa 는 이렇습니다.

| i | P[i] | 들어올 때 k | 줄인 차례 | P[i] 와 P[k] | fail[i] |
| ---: | --- | ---: | --- | --- | ---: |
| 1 | a | 0 | — | 같다 | 1 |
| 2 | b | 1 | 0 | 다르다 | 0 |
| 3 | a | 0 | — | 같다 | 1 |
| 4 | a | 1 | — | 같다 | 2 |

abab 는 줄이는 자리가 한 번도 없고, aabaa 는 i = 2 에서 k 를 1 에서 0 으로 줄입니다. 채운 표는 abab 가 [0, 0, 1, 2], aabaa 가 [0, 1, 0, 1, 2] 입니다.

<!--/proof-->

`aabaa` 의 `i = 2` 에서는 `k = 1` 로 들어와 `P[2] = b` 와 `P[1] = a` 가 달라 `k` 를 `fail[0] = 0` 으로
줄이고, 다시 `P[0] = a` 와도 달라 `fail[2] = 0` 이 됩니다. 줄이기는 `k` 가 0 이 되거나 같은 글자를 만나면
끝나고, 그 사이 경계의 경계를 긴 것부터 하나씩 봤으므로 놓친 후보가 없어요. 값의 범위는
`0 ≤ fail[i] ≤ i` 이고, 칸은 패턴 길이만큼 `m` 개입니다.

#### 2단계 — 어긋나면 맞은 길이를 실패 함수 값으로 줄이기

이제 텍스트를 대조합니다. `j` 는 「텍스트 자리 `i − 1` 까지에서 끝나며 패턴의 앞부분과 같은 가장 긴 조각의
길이」예요. `T[i]` 와 `P[j]` 가 같으면 `j` 를 하나 늘리고, 다르면 `j` 를 `fail[j-1]` 로 줄여 다시
비교합니다. 전개 입력 `T = abacabababab` 의 자리 2 와 3 을 보면 쉬운 경우와 여러 번 줄이는 경우가 나란히
나와요.

<!--proof:build-shrink-->

| 텍스트 자리 i | 들어올 때 j | 비교한 글자 | 결과 | 다음 j |
| ---: | ---: | --- | --- | --- |
| 2 | 2 | T[2] = a 와 P[2] = a | 같다 | j = 3 |
| 3 | 3 | T[3] = c 와 P[3] = b | 다르다 | j = fail[2] = 1 |
|  |  | T[3] = c 와 P[1] = b | 다르다 | j = fail[0] = 0 |
|  |  | T[3] = c 와 P[0] = a | 다르다 | j 는 0 그대로 |

텍스트 자리 3 에서 비교는 3 번이고, i 는 3 에 머문 채 j 만 3 에서 0 으로 내려갔습니다.

<!--/proof-->

자리 3 에서 `j = 3` 은 「`T[0..2] = aba` 가 `P[0..2]` 와 같다」는 뜻이었습니다. `fail[2] = 1` 로 줄이면 그
세 글자의 끝 한 글자 `a` 가 패턴의 첫 글자와 같다는 것만 남기고, 거기서도 어긋나 0 까지 내려갑니다. 줄이기가
끝나는 자리는 `j` 가 0 이 되거나 같은 글자를 만난 곳이라, 살아 있는 후보를 긴 것부터 모두 봤어요.

#### 3단계 — 다 맞으면 시작 자리를 적고 이어 가기

`j` 가 `m` 이 되면 패턴 전체가 맞은 것이니 시작 자리 `i − m + 1` 을 적습니다. 그다음 `j` 를 0 으로 두지
않고 `fail[m-1]` 로 줄여요. 맞은 `m` 글자의 뒷부분이 다음 등장의 앞부분일 수 있기 때문입니다.

<!--proof:build-continue-->

| 텍스트 자리 i | 들어올 때 j | 비교한 글자 | 적은 시작 자리 | 나갈 때 j |
| ---: | ---: | --- | ---: | ---: |
| 7 | 3 | T[7] = b 와 P[3] = b | 4 | 2 |
| 8 | 2 | T[8] = a 와 P[2] = a | — | 3 |
| 9 | 3 | T[9] = b 와 P[3] = b | 6 | 2 |

자리 4 를 적은 뒤 j 가 fail[3] = 2 로 줄어서, 두 글자 뒤에 자리 6 의 등장이 잡힙니다.

<!--/proof-->

`fail[m-1]` 은 `m` 보다 작으므로 줄인 뒤의 `j` 는 늘 `m` 보다 작고, 같은 시작 자리를 두 번 적는 일이 없어요.

#### 이 방법이 기대는 전제

실패 함수는 두 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 글자 비교가 「같다 / 다르다」 둘로 갈리고, 같음이 이어진다 | 1단계에서 패턴을 자기 자신에 대조해 얻은 값을 2단계에서 텍스트에 쓴다 | 패턴끼리 같은 것이 텍스트와도 같다는 보장이 없어 후보를 잘못 지운다 |
| 패턴이 대조 내내 바뀌지 않는다 | 1단계를 한 번만 한다 | 패턴이 바뀔 때마다 실패 함수를 다시 채워야 한다 |

첫째 전제가 깨지는 흔한 모양은 아무 글자와 같은 `?` 가 섞인 패턴입니다. 두 방식에서 글자 같음만 바꿔
실행하면 이렇게 나와요.

<!--proof:build-premise-wildcard-->

| 텍스트 | 패턴 | 실패 함수 방식 | 시작 자리를 다 대조 | 판정 |
| --- | --- | --- | --- | --- |
| "aaab" | "a?b" | 없음 | [1] | 어긋난다 |
| "aabb" | "a?b" | [0] | [0, 1] | 어긋난다 |
| "abab" | "a?b" | 없음 | 없음 | 같다 |

패턴의 ? 는 아무 글자와 같다고 두고, 두 방식에서 글자 같음만 그렇게 바꿨습니다.

<!--/proof-->

`"aaab"` 에서 `a?b` 는 자리 1 에서 시작하는데, 실패 함수 방식은 찾지 못합니다. `?` 가 `a` 와도 같고 `b` 와도
같아서, 패턴끼리 비교해 얻은 경계가 텍스트의 글자에 대해서는 참이 아니게 되기 때문이에요.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 여섯 걸음이 됩니다. 이렇게 하면 과제 규모에서 비교가 수십억 번이던
것이 수십만 번이 됩니다.

1. 답이 없는 두 경우(빈 패턴 · 패턴이 텍스트보다 길다)를 먼저 걸러 낸다
2. 패턴만 보고 실패 함수를 채운다
3. 텍스트 자리 `i` 를 0 부터 `n − 1` 까지 한 칸씩 올린다
4. `T[i]` 와 `P[j]` 가 다르면 `j` 를 `fail[j-1]` 로 줄이기를 되풀이한다
5. 같으면 `j` 를 하나 늘린다
6. `j` 가 `m` 이 되면 시작 자리 `i − m + 1` 을 적고 `j` 를 `fail[m-1]` 로 줄인다

### 수행으로 알아보는 알고리즘 — 열두 글자에서 겹치는 시작 자리 셋을 찾는다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const T = "abacabababab";
const P = "abab";
// 이 절이 끝나면 [4, 6, 8] 이 나와야 한다
```

왜 하필 이 열두 글자일까요? 세 갈래가 다 실행되고(맞음 · 어긋나서 줄이기 · 줄일 것이 없음), 어긋나는
자리에서 `j` 가 **한 번이 아니라 두 번** 줄며, 찾은 자리 셋이 **서로 겹치기** 때문이에요. 겹치는 등장을
놓치는 실수가 이 입력에서 실제로 확인됩니다.

```text
findAllOccurrences(T, P):
    답이 없는 두 경우면 빈 배열을 돌려준다              ①
    k ← 0
    i = 1 … m-1 마다:
        P[i] ≠ P[k] 인 동안 k ← fail[k-1]               ②
        P[i] = P[k] 이면 k ← k + 1                      ③
        fail[i] ← k
    j ← 0
    i = 0 … n-1 마다:
        T[i] ≠ P[j] 인 동안 j ← fail[j-1]               ④
        T[i] = P[j] 이면 j ← j + 1                      ⑤
        j = m 이면 i-m+1 을 적고 j ← fail[m-1]          ⑥
    적어 둔 자리들을 돌려준다
```

#### 1. 패턴만 보고 실패 함수를 만든다

첫 조각은 준비입니다. 텍스트는 아직 보지 않고, 답이 없는 두 경우를 걸러 낸 다음 패턴만으로 실패 함수를
채워요.

```ts
const n = text.length;
const m = pattern.length;
const found: number[] = [];
if (m === 0 || n < m) return found; // ① 답이 없는 두 경우

const fail = new Array<number>(m).fill(0);
let k = 0;
for (let i = 1; i < m; i++) {
  while (k > 0 && pattern[i] !== pattern[k]) k = fail[k - 1] as number; // ② 줄이기
  if (pattern[i] === pattern[k]) k++; // ③ 늘리기
  fail[i] = k;
}
```

`①` 의 조건은 전개 입력에서 둘 다 거짓이라 아무것도 걸러 내지 않아요. 참이 되는 것은 빈 패턴과 긴 패턴이고,
그때는 실패 함수를 만들기도 전에 빈 배열이 나갑니다.

<!--proof:walk-guard-->

```text
findAllOccurrences("abc", "")                m = 0 이라 참   →  []
findAllOccurrences("ab", "abcd")             n < m 이라 참   →  []
findAllOccurrences("abacabababab", "abab")   둘 다 거짓      →  [4, 6, 8]
```

실패 함수를 만드는 조각만 떼어 세 패턴에 실행하면 이렇게 나옵니다. 앞의 둘은 「아이디어 상세」의 1단계
표와 같은 값이에요.

<!--proof:walk-fail-calls-->

```text
"abab"    →  fail = [0, 0, 1, 2]
"aabaa"   →  fail = [0, 1, 0, 1, 2]
"aaab"    →  fail = [0, 1, 2, 0]
```

#### 짚고 가기 — 진 조각 조건을 빼면 줄여도 줄어들지 않는다

「앞부분이자 뒷부분인 가장 긴 것」이라면 `abab` 전체도 자기 자신의 앞부분이자 뒷부분이니 `fail[3] = 4`
아닌가, 하고 읽기 쉽습니다. 그 생각대로 표를 만들면 값이 늘 자리 번호보다 하나 큰 수가 돼요. 두 표로 전개
입력을 대조했습니다.

<!--proof:pause-proper-->

| i | P[i] | 진 조각만 센 값 | 자기 자신도 센 값 |
| ---: | --- | ---: | ---: |
| 0 | a | 0 | 1 |
| 1 | b | 0 | 2 |
| 2 | a | 1 | 3 |
| 3 | b | 2 | 4 |

전개 입력 "abacabababab" 를 진 조각만 센 표로 대조하면 [4, 6, 8] 이 나옵니다. 자기 자신도 센 표로 대조하면 자리 3 에서 j = 3 일 때 fail[2] = 3 이라 줄여도 j 가 3 그대로이고, 1,000 번을 줄여도 그 자리를 벗어나지 못합니다.

<!--/proof-->

**어느 문자열이든 자기 자신은 자기의 앞부분이자 뒷부분입니다.** 그것을 세면 `j` 를 `fail[j-1]` 로 줄여도 값이
그대로라, 어긋난 자리를 영영 벗어나지 못해요. 「진」 조각만 세는 것은 줄이기가 실제로 줄어들게 하는 조건입니다.

#### 2. 텍스트를 한 글자씩 대조한다

둘째 조각은 대조입니다. 텍스트 자리 `i` 를 하나씩 올리면서 세 갈래 중 하나를 실행하고, `j` 가 `m` 이 되면
시작 자리를 적어요.

```ts
let j = 0;
for (let i = 0; i < n; i++) {
  while (j > 0 && text[i] !== pattern[j]) j = fail[j - 1] as number; // ④ 줄이기
  if (text[i] === pattern[j]) j++; // ⑤ 늘리기
  if (j === m) {
    // ⑥ 다 맞았다
    found.push(i - m + 1);
    j = fail[j - 1] as number;
  }
}
```

앞 네 걸음만 실행하면 이렇게 나옵니다.

<!--proof:walk-first-four-->

| 걸음 | i | T[i] | 들어올 때 j | 실행한 갈래 | 나갈 때 j |
| --- | ---: | --- | ---: | --- | ---: |
| T1 | 0 | a | 0 | ⑤ 늘리기 | 1 |
| T2 | 1 | b | 1 | ⑤ 늘리기 | 2 |
| T3 | 2 | a | 2 | ⑤ 늘리기 | 3 |
| T4 | 3 | c | 3 | ④ 줄이기 2 번 | 0 |

T4 가 이 네 줄의 핵심입니다. `i` 는 3 그대로인데 `j` 만 3 에서 0 으로 내려가요. 텍스트 자리를 되돌리지 않고
패턴 쪽만 줄인 것이고, 그 자세한 값은 「아이디어 상세」의 2단계 표가 보인 것과 같습니다.

#### 짚고 가기 — 다 맞은 뒤 맞은 길이를 0 으로 두면 겹치는 등장이 빠진다

`⑥` 의 마지막 줄을 「패턴을 다 찾았으니 처음부터 다시 시작하면 되겠다」로 읽기 쉽습니다. 그 생각대로 한 줄만
바꿔 봅시다.

```ts
if (j === m) {
  found.push(i - m + 1);
  j = 0; // fail[j - 1] 이 아니라 0 으로 두었다
}
```

네 입력으로 확인해 봅니다.

<!--proof:pause-match-reset-->

| 입력 | 정본이 낸 답 | 0 으로 둔 답 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 "abacabababab" / "abab" | [4, 6, 8] | [4, 8] | 어긋난다 |
| "aaaa" / "aa" | [0, 1, 2] | [0, 2] | 어긋난다 |
| "abcabc" / "abc" | [0, 3] | [0, 3] | 같다 |
| "ababcababab" / "abab" | [0, 5, 7] | [0, 5] | 어긋난다 |

**셋째 줄 `"abcabc"` 에서는 답이 안 틀립니다.** 등장이 서로 떨어져 있는 입력은 전부 통과하므로, 겹치는 입력을
시험에 넣지 않으면 끝까지 모르고 넘어가요. `abcabc` 는 자리 0 의 등장이 자리 2 에서 끝나고 다음 등장이 자리
3 에서 시작해서, `j` 를 0 으로 둬도 자리 3 을 처음부터 볼 수 있습니다. `aaaa` 에서는 자리 0 의 등장이 자리 1
까지인데 다음 등장이 자리 1 에서 시작해, `j` 를 0 으로 두는 순간 그 자리를 이미 지나친 것이 돼요.

걸음의 마지막 비교에서 패턴이 놓인 자리예요. 실선 괄호는 맞은 부분, 대시 괄호는 다 맞은 뒤 이어 갈 부분이고,
아래 세 줄은 패턴 · 실패 함수 · 답입니다. ▲ 는 그 걸음에 읽은 칸이에요.

#### 짚고 가기 — 텍스트 자리가 작아지지 않는 것과 비교가 n 번인 것은 다르다

「`i` 가 되돌아가지 않으니 글자 비교가 정확히 `n` 번이겠다」로 읽기 쉽습니다. 위 표의 「비교 횟수」 열을 더해
보면 그렇지 않아요. 입력의 모양 넷과 긴 입력 하나에서 텍스트 대조의 비교 횟수를 세었습니다.

<!--proof:pause-compare-count-->

| 입력의 모양 | n | 텍스트 대조 비교 횟수 | 3n | n 에 대한 배수 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 12 | 23 | 36 | 1.92 배 |
| 전부 같은 글자 | 12 | 32 | 36 | 2.67 배 |
| 패턴이 되풀이된다 | 12 | 23 | 36 | 1.92 배 |
| 첫 글자부터 어긋난다 | 12 | 12 | 36 | 1.00 배 |

텍스트가 a 100,000 개이고 패턴이 a 999 개 뒤에 b 하나이면 텍스트 대조 비교 횟수가 299,000 번으로, 3n = 300,000 의 99.7 % 입니다.

<!--/proof-->

**`i` 가 안 작아진다는 것은 텍스트 자리를 다시 방문하지 않는다는 뜻이지, 그 자리에서 비교를 한 번만 한다는
뜻이 아닙니다.** 같은 `i` 에서 `j` 가 줄어들 때마다 그 자리의 글자를 다른 패턴 글자와 다시 비교해요. T4 가 한
자리에서 세 번 비교한 걸음이었습니다. 그래도 비교는 `3n` 을 넘지 않는데, 그 까닭은 「비용 계산」에서 셉니다.

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 마지막에 `found` 를 돌려주는 한 줄뿐이에요.
등장이 하나도 없으면 아무것도 안 담긴 빈 배열이 그대로 답이 됩니다.

```ts
export function findAllOccurrences(text: string, pattern: string): number[] {
  const n = text.length;
  const m = pattern.length;
  const found: number[] = [];
  // ① 답이 있을 수 없는 두 경우를 먼저 걸러 낸다 — 빈 패턴이거나 패턴이 텍스트보다 길다.
  if (m === 0 || n < m) return found;

  // fail[i] 는 pattern[0..i] 의 진 접두사이면서 진 접미사인 것 중 가장 긴 것의 길이다.
  const fail = new Array<number>(m).fill(0);
  let k = 0;
  for (let i = 1; i < m; i++) {
    // ② 글자가 다르면 이어 둔 길이를 fail 이 가리키는 값으로 줄인다.
    while (k > 0 && pattern[i] !== pattern[k]) k = fail[k - 1] as number;
    // ③ 글자가 같으면 이어 둔 길이를 하나 늘린다.
    if (pattern[i] === pattern[k]) k++;
    fail[i] = k;
  }

  let j = 0;
  for (let i = 0; i < n; i++) {
    // ④ 글자가 다르면 맞은 길이를 fail 이 가리키는 값으로 줄인다. i 는 그대로 둔다.
    while (j > 0 && text[i] !== pattern[j]) j = fail[j - 1] as number;
    // ⑤ 글자가 같으면 맞은 길이를 하나 늘린다.
    if (text[i] === pattern[j]) j++;
    if (j === m) {
      // ⑥ 패턴 전체가 맞았다. 시작 자리를 적고, 겹치는 등장을 놓치지 않도록 맞은 길이를
      //    통째로 버리지 않고 fail 이 가리키는 값으로 줄인다.
      found.push(i - m + 1);
      j = fail[j - 1] as number;
    }
  }
  return found;
}
```

<!--proof:final-calls-->

```text
findAllOccurrences("abacabababab", "abab")   →  [4, 6, 8]
findAllOccurrences("ababcababab", "abab")    →  [0, 5, 7]
findAllOccurrences("aaaa", "aa")             →  [0, 1, 2]
findAllOccurrences("abc", "d")               →  []
findAllOccurrences("abc", "")                →  []
findAllOccurrences("", "a")                  →  []
```

### 알아 두면 좋은 개념 — 유한 상태 기계

전개에서 `j` 가 한 일에는 이름이 붙어 있습니다. `j` 는 텍스트의 자리도 아니고 답도 아니고, **지금까지 읽은
텍스트에 대해 앞으로 필요한 것을 전부 담은 수 하나**였어요. 글자가 하나 들어올 때마다 그 수가 다음 수로 바뀌고,
그 바뀜이 오직 「지금 수」와 「들어온 글자」로만 정해집니다. 이렇게 **상태 하나와 입력 하나로 다음 상태가
정해지는 장치**를 유한 상태 기계라고 부릅니다. 패턴 `abab` 의 상태와 글자마다의 다음 상태를 실패 함수로
계산했어요.

<!--proof:related-automaton-->

| 지금 상태 j | 글자 a | 글자 b | 그 밖의 글자 |
| ---: | --- | --- | --- |
| 0 | 1 | 0 | 0 |
| 1 | 1 | 2 | 0 |
| 2 | 3 | 0 | 0 |
| 3 | 1 | 2 (자리를 적는다) | 0 |

전개 입력 "abacabababab" 를 이 표만 따라 읽어도 답 [4, 6, 8] 이 나옵니다.

<!--/proof-->

T3 은 상태 2 에서 `a` 를 받아 3 이 됐고, T4 는 상태 3 에서 그 밖의 글자 `c` 를 받아 0 이 됐어요. T8 · T10 ·
T12 는 상태 3 에서 `b` 를 받아 시작 자리를 적은 걸음입니다. 실패 함수는 이 표를 **통째로 적어 두지 않고 필요한
만큼만** 계산하는 방법이에요. 표를 다 적으면 칸이 `m × 26` 개인데 실패 함수는 `m` 개이고, 그 대신 전이 하나에
줄이기가 여러 번 들 수 있습니다. 같은 장치는 다른 자리에서도 다시 나와요.

| 다시 나오는 자리 | 상태 | 전이를 정하는 것 |
| --- | --- | --- |
| 여러 패턴을 한 번에 찾기([`ahoCorasick`](../ahoCorasick/ahoCorasick-guide.md)) | 트라이의 노드 하나 | 노드와 들어온 글자 |
| 정규식 엔진 | 정규식을 옮긴 상태 하나 | 상태와 들어온 글자 |
| 어휘 분석기 | 지금까지 읽은 낱말의 종류 | 종류와 들어온 글자 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 실패 함수를 식으로 어떻게 적는지, 무엇이 매
걸음 참으로 남는지, 그리고 비교가 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 찾는 것이 패턴 하나다 | 패턴이 여럿이면 실패 함수를 패턴마다 만들고 텍스트를 패턴 수만큼 다시 읽는다 | 실패 함수가 하나다 |
| 모든 시작 자리가 필요하고 겹치는 등장도 센다 | 첫 등장만 필요하면 다른 절차도 같은 일을 한다 | 다 맞은 뒤에도 멈추지 않고 이어 간다 |
| 최악 보장이 필요하다 | 어떤 텍스트가 들어와도 비교가 `3(n + m)` 을 넘지 않아야 한다 | 해시나 건너뛰기에 기대지 않는다 |
| 텍스트를 한 번 지나가는 것으로 충분하다 | 텍스트가 파일이나 네트워크로 조각조각 들어와도 된다 | 텍스트 자리가 앞으로만 간다 |

셋째 줄이 이 절차의 자리입니다. 해시로 자리마다 값을 비교하는 방법은 평균으로는 더 적게 드는 대신 **해시가
우연히 같아지는 경우**를 다시 대조해야 하고, 건너뛰기로 자리를 뛰어넘는 방법은 텍스트의 글자 가짓수가 적을수록
건너뛰는 폭이 줄어들어요.

| 과제 | 쓰는 것 | 까닭 |
| --- | --- | --- |
| 패턴 하나의 모든 시작 자리 | 실패 함수 | 최악에서도 `3(n + m)` 을 넘지 않는다 |
| 패턴 수백 개를 한 번에 | 여러 패턴용 자동 장치 | 텍스트를 한 번만 읽는다 |
| 텍스트가 고정이고 질의가 많다 | 접미사 구조 | 텍스트를 한 번 전처리해 둔다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "모든 등장 위치"  "몇 군데에 나오는가"        ← 첫 등장에서 멈추면 안 된다
  "겹치는 경우도 포함"  "겹쳐서 등장해도"       ← 다 맞은 뒤 0 으로 두면 안 된다는 신호다
  "O(n + m)"  "선형 시간"                       ← 후보를 다 대조하는 방식을 막는다
  "텍스트가 스트림으로 들어온다"                ← 텍스트를 저장하지 않아도 되는 절차가 필요하다

제약에 이런 모양이 보이면
  텍스트와 패턴이 둘 다 길어서 두 길이의 곱이 예산을 넘는다
  패턴이 자기 앞부분을 되풀이한다(aaaa · abab)

반대로 이런 말이 보이면 해당하지 않는다
  "패턴이 여러 개"  "사전에 있는 단어 전부"     ← 패턴마다 만들면 텍스트를 여러 번 읽는다
  "텍스트는 고정이고 질의가 많다"              ← 텍스트 쪽을 전처리하는 편이 적게 든다
  "가장 긴 공통 부분 문자열"  "편집 거리"       ← 정확히 같은 조각을 찾는 문제가 아니다
```

세 번째 무리가 보이면 다른 절차로 갑니다. 패턴이 여럿이면 [`ahoCorasick`](../ahoCorasick/ahoCorasick-guide.md)
쪽이고, 텍스트가 고정이고 질의가 반복되면 [`suffixArray`](../suffixArray/suffixArray-guide.md) 쪽이에요.

#### 실제로 쓰이는 곳

- **리눅스 커널의 문자열 검색 모듈 `lib/ts_kmp.c`.** 파일 첫머리가 이 절차를 이름 그대로 적습니다 —
  *"lib/ts_kmp.c Knuth-Morris-Pratt text search implementation"* 이고, 이어서 *"Implements a linear-time
  string-matching algorithm due to Knuth, Morris, and Pratt"* 라 적혀 있어요. 같은 파일의 `kmp_find` 안에 이 글의
  대조 루프가 그대로 있습니다 — 대소문자를 무시하는 선택지를 뺀 모양으로 적으면
  `while (q > 0 && kmp->pattern[q] != text[i]) q = kmp->prefix_tbl[q - 1];` 가 `④` 이고
  `if (kmp->pattern[q] == text[i]) q++;` 가 `⑤` 예요. 실패 함수를 채우는 `compute_prefix_tbl` 도 같은 모양이고,
  `kmp_init` 은 길이 0 인 패턴을 `-EINVAL` 로 거부합니다 — 이 글의 `①` 이 거기서는 초기화 단계의 판정입니다.
  ([`lib/ts_kmp.c`](https://github.com/torvalds/linux/blob/master/lib/ts_kmp.c), 조회 2026-09-02)
- **같은 커널의 `net/netfilter/xt_string.c`.** 패킷 안의 문자열을 찾는 방화벽 규칙이고,
  `textsearch_prepare(conf->algo, conf->pattern, conf->patlen, ...)` 로 **이름으로 절차를 고릅니다.** 그 이름 중
  하나가 위 모듈이 등록한 `kmp` 예요.
  ([`net/netfilter/xt_string.c`](https://github.com/torvalds/linux/blob/master/net/netfilter/xt_string.c),
  조회 2026-09-02)

커널 구현과 이 글은 다 맞은 뒤에 하는 일이 다릅니다.

| 구현 | 다 맞은 뒤 | 까닭 |
| --- | --- | --- |
| 커널 `kmp_find` | `q == pattern_len` 이 되면 그 자리를 돌려주고 끝낸다 | 첫 등장만 찾는다 |
| 이 글 | 시작 자리를 적고 `j` 를 `fail[m-1]` 로 줄여 계속 대조한다 | 겹치는 등장까지 모든 시작 자리가 필요하다 |

**표준 라이브러리의 문자열 찾기가 이 절차를 쓴다는 것은 1 차 출처로 확인하지 못했습니다.** 파이썬의 경우는
오히려 반대인 것이 확인돼요 — CPython 의 `Objects/stringlib/fastsearch.h` 는 첫머리에 *"If the strings are long
enough, use Crochemore and Perrin's Two-Way algorithm, which has worst-case O(n) runtime and best-case O(n/k)"* 라
적고, 짧은 입력에는 `default_find` 를 씁니다. 확인한 것은 위의 커널 모듈 둘입니다.
([`Objects/stringlib/fastsearch.h`](https://github.com/python/cpython/blob/main/Objects/stringlib/fastsearch.h),
조회 2026-09-02)

#### 경쟁 설계와의 대조

같은 목표(텍스트에서 패턴의 모든 시작 자리를 찾는 것)를 노리는 다른 절차로 **호스풀 방식(Boyer–Moore–Horspool)**
이 있습니다. 패턴을 놓은 자리의 **오른쪽 끝부터** 왼쪽으로 비교하고, 어긋나면 그 자리의 마지막 텍스트 글자가
패턴 안에서 마지막으로 나온 곳을 보고 패턴을 그만큼 옮기는 방식이에요.

| 설계 | 비교하는 방향 | 어긋났을 때 | 안 읽는 글자 |
| --- | --- | --- | --- |
| 실패 함수 방식 | 왼쪽부터 | 맞은 길이만 줄인다. 텍스트 자리는 안 작아진다 | 없다 |
| 호스풀 방식 | 오른쪽부터 | 패턴 전체를 여러 칸 옮긴다 | 생긴다. 옮기는 폭은 글자 가짓수에 달렸다 |

같은 생성식으로 만든 텍스트와 패턴에 두 설계를 걸고 **글자 비교 횟수**를 셌습니다. 텍스트는 길이 100,000 이고
`T[i]` 를 알파벳의 `(i × 7919) mod σ` 번째 글자로 두었어요. `σ` 는 실제로 쓰는 글자의 가짓수이고, 패턴은 같은
생성식의 30,000 번 자리에서 잘라 낸 여덟 글자입니다. **전개 입력을 그대로 쓰지 않은 이유**는 호스풀이 옮기는
폭이 패턴 길이를 넘지 못해, 열두 글자짜리 입력에서는 두 설계의 계수가 상수에 묻히기 때문입니다.

<!--proof:alt-compare-->

| 글자 가짓수 σ | 실패 함수 방식 | 호스풀 방식 | 적은 쪽 |
| ---: | ---: | ---: | --- |
| 1 | 200012 | 799944 | 실패 함수 방식 · 4.00 배 |
| 3 | 200010 | 266648 | 실패 함수 방식 · 1.33 배 |
| 4 | 200009 | 199992 | 호스풀 방식 · 1.00 배 |
| 26 | 126929 | 42306 | 호스풀 방식 · 3.00 배 |

추가 칸(입력과 답 배열을 빼고 새로 잡는 표의 칸)은 실패 함수 방식이 8 개, 호스풀 방식이 26 개입니다.

<!--/proof-->

실패 함수 쪽은 글자 가짓수와 상관없이 20 만 언저리이고, 호스풀 쪽은 글자 가짓수가 늘수록 한 번에 옮기는 폭이
커져서 적어집니다. 글자 가짓수가 1 이면 호스풀은 한 칸씩만 옮기며 자리마다 여덟 글자를 다 비교해요. 두 쪽이
갈리는 자리가 이 생성식에서 **글자 가짓수 4** 입니다. 추가 칸은 이 입력에서 갈리지 않고 실패 함수 쪽이 계속
적어요 — 실패 함수는 패턴 길이만큼이고 호스풀의 옮김 표는 문자 집합의 크기만큼입니다.

**이 절차가 내주는 것은 큰 문자 집합에서의 비교 횟수입니다.** 알파벳 26 글자를 다 쓰는 텍스트에서는 호스풀이
42306 번으로 이쪽의 126929 번보다 적어요. 그 대신 얻는 것이 둘입니다. 하나는 **최악 보장**이에요 — 실패 함수
방식은 어떤 입력에서도 `3(n + m)` 을 넘지 않지만, 호스풀은 글자 가짓수 1 에서 보듯 `(n − m + 1)m` 까지 갑니다.
다른 하나는 **추가 칸**이에요 — 실패 함수는 패턴 길이만큼이라 문자 집합이 커져도 늘지 않습니다. 축을 갈라
적으면 이렇습니다.

| 축 | 실패 함수 방식 | 호스풀 방식 | 적은 쪽 |
| --- | --- | --- | --- |
| 글자 26 가짓수에서의 비교 횟수 | 126929 | 42306 | 호스풀 방식 |
| 글자 1 가짓수에서의 비교 횟수 | 200012 | 799944 | 실패 함수 방식 |
| 최악 보장 | `3(n + m)` | `(n − m + 1)m` | 실패 함수 방식 |
| 추가 칸 | 패턴 길이 `m` | 문자 집합의 크기 | 이 과제에서는 실패 함수 방식 |

**우열이 반대가 되는 조건이 분명합니다.** 글자 가짓수가 적거나 텍스트가 패턴과 비슷한 모양을 되풀이할 수 있고
최악 보장이 필요하면 실패 함수 방식이고, 문자 집합이 크고 입력이 고르게 섞여 최악 보장이 필요 없으면 호스풀
방식이에요.

### 수식 정의와 유도

문자열 `s` 의 **경계**를 정의합니다. `s` 의 진 접두사이면서 동시에 진 접미사인 조각의 길이를 모은 집합이에요.

$$\mathcal{B}(s) = \{\, b \mid 0 \le b < |s|,\ s[0..b-1] = s[|s|-b..|s|-1] \,\} \qquad\qquad \operatorname{fail}(i) = \max \mathcal{B}(P[0..i])$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $b$ | 조각의 길이 하나. 이 절에서만 쓰는 자유 변수 | $0 \le b < \lvert s \rvert$ |
| $s[0..b-1]$ | `s` 의 앞 `b` 글자. `b = 0` 이면 빈 문자열 | — |
| $s[\lvert s\rvert-b..\lvert s\rvert-1]$ | `s` 의 뒤 `b` 글자 | — |
| $\mathcal{B}(s)$ | 둘이 같아지는 `b` 를 전부 모은 집합. `b` 가 `s` 의 길이인 경우는 빼므로 「진」이다 | 0 은 늘 들어 있다 |
| $\operatorname{fail}(i)$ | `P[0..i]` 에 대한 그 집합의 최댓값 | $0 \le \operatorname{fail}(i) \le i$ |

정의를 작은 패턴 셋에 넣어 확인하고 갑시다. 진 조각을 손으로 다 나열하고 그중 가장 긴 것을 고르면 실패 함수의
값과 같아야 해요.

<!--proof:math-check-->

| P | i | P[0..i] | 접두사이자 접미사인 진 조각 | fail[i] |
| --- | ---: | --- | --- | ---: |
| abab | 0 | a | 없음 | 0 |
| abab | 1 | ab | 없음 | 0 |
| abab | 2 | aba | a | 1 |
| abab | 3 | abab | ab | 2 |
| aabaa | 0 | a | 없음 | 0 |
| aabaa | 1 | aa | a | 1 |
| aabaa | 2 | aab | 없음 | 0 |
| aabaa | 3 | aaba | a | 1 |
| aabaa | 4 | aabaa | a · aa | 2 |
| aaab | 0 | a | 없음 | 0 |
| aaab | 1 | aa | a | 1 |
| aaab | 2 | aaa | a · aa | 2 |
| aaab | 3 | aaab | 없음 | 0 |

이제 유도합니다. 첫째로 **경계의 경계도 경계**예요. `b` 가 `P[0..i]` 의 경계 길이이면 `P[0..b-1]` 은
`P[0..i]` 의 앞부분이자 뒷부분이고, 그 조각의 경계 길이 `c` 를 잡으면 `P[0..c-1]` 은 `P[0..b-1]` 의
뒷부분이므로 `P[0..i]` 의 뒷부분이기도 합니다. 앞부분인 것은 처음부터 참이에요. 거꾸로 `P[0..i]` 의 경계 가운데
`fail(i)` 보다 짧은 것은 `P[0..fail(i)-1]` 의 경계이기도 하므로, 경계를 긴 것부터 모두 나열하면 이렇습니다.

$$\mathcal{B}(P[0..i]) = \{\, \operatorname{fail}(i),\ \operatorname{fail}(\operatorname{fail}(i)-1),\ \dots,\ 0 \,\}$$

<!--proof:math-chain-->

```text
P = aabaa 에서 자리 4 의 경계를 전부 얻는 차례
  fail(4) = 2                 aa
  fail(2 − 1) = fail(1) = 1   a
  fail(1 − 1) = fail(0) = 0   빈 문자열
```

이 사실이 대조 루프의 `while` 을 정당하게 만듭니다. 어긋난 자리에서 남은 후보는 경계 길이뿐인데, `fail` 을
되풀이해 적용하면 그 후보를 **큰 것부터 빠짐없이** 얻기 때문이에요. 정의를 그대로 옮긴 조각은 이렇습니다.

```ts
// 정의를 그대로 옮긴 조각. 실제 절차는 이 나열을 실패 함수 한 번 읽기로 대신한다.
const borders = (s: string): number[] =>
  Array.from({ length: s.length }, (_, b) => b).filter(
    (b) => s.slice(0, b) === s.slice(s.length - b),
  );
```

둘째로 **비교 횟수의 상한**을 닫습니다. 한 걸음은 늘리기 판정 한 번과 줄이기 판정 몇 번으로 이루어지는데,
줄이기 판정은 같은 글자를 만나면 그 걸음의 줄이기를 끝내고, 다른 글자를 만나면 `j` 를 최소 1 줄여요. `j` 는 한
걸음에 많아야 1 늘고 음수가 되지 않으므로, 전체 감소량이 전체 증가량 `n` 이하입니다.

$$\text{비교 횟수} \le \underbrace{n}_{\text{늘리기 판정}} + \underbrace{n}_{\text{같은 글자로 끝난 줄이기 판정}} + \underbrace{n}_{\text{다른 글자로 줄인 판정}} = 3n$$

세 항이 각각 `n` 을 넘지 못하는 까닭은 이렇습니다.

| 항 | 한 걸음에서 | 전체에서 |
| --- | --- | --- |
| 늘리기 판정 | 정확히 한 번 | `n` 번 |
| 같은 글자로 끝난 줄이기 판정 | 그 순간 줄이기가 끝나므로 많아야 한 번 | `n` 번 이하 |
| 다른 글자로 줄인 판정 | 한 번마다 `j` 가 1 이상 준다 | 전체 증가량 `n` 이하 |

실패 함수를 채우는 쪽도 같은 논증이라 `3m` 이하이고, 합쳐서 `3(n + m)` 입니다.

셋째로 **전수 대조의 최악**을 닫습니다. 그쪽의 비교 횟수는 후보 수 `n − m + 1` 과 후보 하나의 비교 `m` 의
곱이고, 두 항의 합이 `m` 과 상관없이 고정이므로 두 항이 같아지는 자리에서 곱이 가장 큽니다.

$$(n-m+1)\,m \le \left\lfloor \frac{(n+1)^2}{4} \right\rfloor \qquad \text{등호는 } m = \frac{n+1}{2} \text{ 근처}$$

<!--proof:math-peak-->

```text
두 항의 합         (n − m + 1) + m = n + 1           m 과 상관없이 고정이다
n = 100,000 이면   m = 50,000 에서 50,001 × 50,000   = 2,500,050,000
```

두 식에 규모를 넣어 실측과 대조합니다.

<!--proof:math-scale-->

| n | m | 전수 대조(실측) | (n−m+1)m | 실패 함수 방식(실측) | 3(n+m) |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 12 | 6 | 42 | 42 | 32 | 54 |
| 120 | 60 | 3,660 | 3,660 | 356 | 540 |
| 1,200 | 600 | 360,600 | 360,600 | 3,596 | 5,400 |
| 12,000 | 6,000 | 36,006,000 | 36,006,000 | 35,996 | 54,000 |

과제 규모 n = 100,000 · m = 50,000 에서는 (n−m+1)m 이 2,500,050,000 이고, 실패 함수 방식의 실측 비교 횟수는 299,996 번, 상한 3(n+m) 은 450,000 입니다. 두 방식의 비교 횟수 비는 8,334 배입니다.

<!--/proof-->

실측값이 닫힌 형태와 네 규모에서 정확히 같습니다. 마지막 문장이 과제 규모의 값이에요 — 같은 답을 내는 데 드는
비교 횟수가 수십억 대 수십만입니다.

### 불변식 — 걸음이 끝난 시점의 j 는 텍스트의 그 자리에서 끝나며 패턴의 앞부분과 같은 가장 긴 조각의 길이다

파트 1 에서 코드가 동작하는 것을 열두 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고 그것이 실제로 유지되는지 확인해 봅시다.

> 텍스트 자리 `i` 를 처리한 직후, `j` 는 `T[0..i]` 의 뒷부분이면서 `P` 의 앞부분인 조각 가운데 **가장 긴
> 것**의 길이와 같습니다. 다만 `j = m` 이 되는 순간에는 시작 자리를 적고 곧바로 `fail[m-1]` 로 줄이므로,
> 걸음이 끝난 시점의 `j` 는 언제나 `m` 보다 작습니다.

<!--fig:invariant-window-->
![T9 가 끝난 시점 — j = 3 은 자리 8 에서 끝나며 P 의 앞부분과 같은 가장 긴 조각의 길이다](./figs/invariant-window.svg)

문장이 둘인 것에 이유가 있습니다. 앞 문장은 다음 걸음이 이어받을 값을 정하고, 뒤 문장은 `j` 가 `m` 에 머무르지
않는다는 것 — 곧 **같은 시작 자리를 두 번 적지 않는다**는 것을 말해요. 이 문장은 「자리 `i` 를 막 처리한
직후」에 참이고, 걸음 도중에는 줄이는 사이에 잠깐 어긋납니다.

**출발점부터 봅시다.** 루프에 들어가기 전 `j` 는 0 입니다. 아직 아무 글자도 안 읽었으니 빈 조각 하나가 후보의
전부이고, 그 길이가 0 이라 앞 문장이 참이에요. 그다음 걸음마다 넷 중 하나가 실행됩니다.

| 걸음에서 하는 일 | 바꾸는 값 | 앞 문장이 유지되는 근거 |
| --- | --- | --- |
| 같을 때 늘리기 | `j` 를 1 늘린다 | 길이 `j` 짜리 조각의 뒤에 같은 글자를 이어 붙인 것이고, 그보다 긴 후보는 앞 걸음의 「가장 긴」 조건 때문에 없다 |
| 다를 때 줄이기 | `j` 를 `fail[j-1]` 로 줄인다 | 더 짧은 후보는 `P[0..j-1]` 의 경계 길이뿐이고, 그중 가장 긴 것이다 |
| 다 맞았을 때 | 자리를 적고 `fail[m-1]` 로 줄인다 | `m` 자신을 뺀 후보 가운데 가장 긴 것이다 |
| 끝낼 때 | `i = n−1` 을 마친다 | 텍스트의 모든 자리에서 위 셋 중 하나를 실행했다 |

둘째 줄이 이 논증의 핵심입니다. 길이 `j` 짜리 조각이 어긋났을 때 살아남는 후보를 모양마다 갈라 보면 이래요.

| 후보의 모양 | 살아 있음 | 근거 |
| --- | --- | --- |
| 길이가 `j` 보다 크다 | 아니다 | `T[0..i-1]` 에서 끝나는 조각 가운데 `P` 의 앞부분인 가장 긴 것이 `j` 였다 |
| 길이가 `j` 이고 다음 글자가 다르다 | 아니다 | 방금 `T[i]` 와 `P[j]` 가 다른 것을 확인했다 |
| 길이가 `j` 보다 작다 | 경계 길이만 | 그 길이의 앞부분이 `P[0..j-1]` 의 뒷부분과 같아야 한다 |

경계 길이의 나열이 `fail` 을 되풀이해 적용한 것과 같으므로, 큰 것부터 하나씩 보는 것으로 후보를 빠짐없이
검토합니다. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

| 입력의 모양 | 텍스트 / 패턴 | 처리되는 자리 | 답 |
| --- | --- | --- | --- |
| 빈 패턴 | "hello" / "" | 조기 반환 m === 0 이 참이다 | 없음 |
| 빈 텍스트 | "" / "a" | 조기 반환 n < m 이 참이다 | 없음 |
| 패턴이 텍스트보다 길다 | "ab" / "abcd" | 조기 반환 n < m 이 참이다 | 없음 |
| 텍스트와 패턴이 같다 | "abc" / "abc" | 마지막 걸음에서 j = m 이 된다 | [0] |
| 모두 같은 글자 | "aaaaa" / "aaa" | 매 걸음 늘리기가 실행된다 | [0, 1, 2] |
| 길이 1 · 같은 글자 | "a" / "a" | 걸음이 하나뿐이다 | [0] |
| 길이 1 · 다른 글자 | "a" / "b" | 걸음이 하나뿐이다 | 없음 |

**이제 깨뜨려 봅시다.** 앞 문장을 지키던 줄은 어긋났을 때 `j` 를 `fail[j-1]` 로 줄이는 그 한 줄이에요. 「어차피
줄어들기만 하면 되니 하나씩 줄여도 같은 자리를 지나가겠다」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
for (let i = 0; i < n; i++) {
  while (j > 0 && text[i] !== pattern[j]) j = j - 1; // fail 이 아니라 하나씩 줄였다
  if (text[i] === pattern[j]) j++;
  if (j === m) {
    found.push(i - m + 1);
    j = fail[j - 1] as number;
  }
}
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-step-back-->

| 입력 | 정본이 낸 답 | 하나씩 줄인 답 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 "abacabababab" / "abab" | [4, 6, 8] | [4, 6, 8] | 같다 |
| "aaab" / "aab" | [1] | [1] | 같다 |
| "abba" / "aba" | 없음 | [1] | 어긋난다 |
| "aabaabaaa" / "aabaa" | [0, 3] | [0, 3] | 같다 |
| "aaaaa" / "aaa" | [0, 1, 2] | [0, 1, 2] | 같다 |

답이 어긋나는 입력이 하나뿐이라, 이 바꿈은 시험을 쉽게 통과합니다. 어긋나는 `"abba"` 에서 두 코드의 `j` 를
자리마다 나란히 적으면 이렇습니다.

<!--proof:mutant-abba-trace-->

| 자리 i | T[i] | 정본의 j | 하나씩 줄인 쪽의 j |
| ---: | --- | ---: | ---: |
| 0 | a | 1 | 1 |
| 1 | b | 2 | 2 |
| 2 | b | 0 | 2 |
| 3 | a | 1 | 1 |

하나씩 줄인 쪽은 자리 1 을 답으로 적는데, T[1..3] = bba 라 패턴 aba 와 다릅니다.

<!--/proof-->

표에서 두 열이 처음 갈리는 자리가 불변식이 깨진 곳입니다. 정본은 거기서 `j` 를 경계 길이까지 한 번에 내렸고,
하나씩 줄인 쪽은 한 칸만 줄인 뒤 다음 비교가 우연히 같아 다시 늘렸어요. 그 `j` 는 「그 자리에서 끝나며 패턴의
앞부분과 같은 조각의 길이」가 아닙니다. 불변식이 깨져 `j` 가 실제로 맞은 길이가 아니게 되면, `j === m` 이 「패턴
전체가 맞았다」를 더는 뜻하지 않아요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 두 무리입니다 — 패턴만 보고 실패 함수를 채우는 것과, 텍스트를 한 번 지나며 대조하는
것이에요. 전개의 걸음으로 확인하면 이렇게 나뉩니다.

<!--proof:perf-count-->

| 무리 | 걸음 | 걸음 수 | 비교 횟수 |
| --- | --- | ---: | ---: |
| 실패 함수 만들기 | 패턴 4 글자 | 3 | 4 |
| 텍스트 대조 | T1 부터 T12 까지 | 12 | 23 |
| 합계 |  |  | 27 |

텍스트 대조의 걸음을 비교 횟수로 나누면 1 번인 걸음이 2 개(T1 · T5), 2 번인 걸음이 9 개, 3 번 이상인 걸음이 1 개(T4)입니다. 걸음마다 한 번은 반드시 비교하므로 12 번은 늘 들고, 나머지 11 번이 줄이기 판정에서 나왔습니다.

<!--/proof-->

T1 과 T5 는 들어올 때 `j` 가 0 이라 줄이기 판정 자체를 하지 않았고, T4 는 두 번 줄이느라 세 번 비교했어요.
두 무리를 더한 총식과 전개 입력의 값은 이렇습니다.

<!--proof:perf-total-->

```text
총식             비교 횟수 = 표 만들기 + 텍스트 대조 ≤ 3m + 3n = 3(n + m)
n = 12 · m = 4   상한 48 · 실측 27
추가 칸          fail 표 4 칸 + 찾은 자리 3 칸
```

**비교 횟수가 입력의 내용에 달렸습니다.** 같은 `n = 12` 라도 텍스트와 패턴이 서로 얼마나 비슷한지에 따라 텍스트
대조가 12 번에서 32 번까지 갈렸어요(「짚고 가기 — 텍스트 자리가 작아지지 않는 것과 비교가 n 번인 것은 다르다」의
표). 줄이기가 몇 번 실행되는지가 그 차이입니다. 여기서 센 것은 글자 비교 전부이고, 자리 번호를 하나 올리는 일과
배열에 값을 담는 일은 세지 않았어요. 둘 다 비교 횟수에 비례하므로 총식의 차수는 그대로입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 글자부터 어긋난다) | `O(n + m)` | `Θ(n + m)` — 텍스트를 다 읽고 실패 함수도 다 채운다 |
| **평균적인 경우** (입력 분포를 가정하지 않는다) | `O(n + m)` | `Θ(n + m)` |
| **최악의 경우** (줄이기가 상한까지 실행된다) | `O(n + m)` | `Θ(n + m)` — 실제로 도달한다 |

세 줄이 다 같은 것이 이 절차의 성질입니다. 비교 횟수가 `n + m` 과 `3(n + m)` 사이에 갇혀 있어서 입력을 어떻게
바꿔도 차수가 안 바뀌어요. `O(n + m)` 은 비교가 그보다 많지 않다는 것만 말하는 상한이고, `Θ(n + m)` 은 위아래로
같은 차수라 실제로 그만큼 든다는 것까지 말합니다. 텍스트를 끝까지 읽어야 모든 등장을 셀 수 있으므로 아래로도
`n` 이 들어요.

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리는 실패 함수 하나뿐이에요 — 정렬도, 해시도, 좌표 압축도
하지 않습니다.

<!--proof:perf-scale-->

```text
총식                       Θ(n + m) 시간 + Θ(m + r) 추가 메모리 (r 은 찾은 자리 수, r ≤ n − m + 1)
n = 100,000 · m = 50,000   비교 299,996 번 · fail 표 50,000 칸 · 찾은 자리 50,001 칸
```

**보장의 종류는 전부 최악 보장입니다.** 해시도, 무작위성도, 입력 분포 가정도 쓰지 않아요. 글자는 자리 번호로
바로 읽어 해시 충돌이라는 개념이 없고, 줄이기의 총합은 늘어난 총합이 상한을 주며, 건너뛰지 않으므로 텍스트의
글자 가짓수도 보지 않습니다. 그래서 어떤 텍스트와 패턴을 넣어도 비교가 `3(n + m)` 을 넘지 않아요.

#### 최악을 만드는 입력

비교를 최대로 만들려면 **줄이기가 많이 실행되게** 해야 합니다. 줄이기가 실행되는 자리는 `j` 가 클 때 어긋나는
곳이니, 텍스트가 패턴의 앞부분과 계속 맞다가 한 글자에서 어긋나는 모양이에요. 그것을 값으로 확인해 봅시다.

<!--proof:worst-shape-->

| 입력의 모양 (n = 100,000) | 실패 함수 만들기 | 텍스트 대조 | 합 | 찾은 자리 수 |
| --- | ---: | ---: | ---: | ---: |
| 텍스트가 전부 a · 패턴 a 999 개 + b | 2,994 | 299,000 | 301,994 | 0 |
| 텍스트가 전부 a · 패턴 a 1,000 개 | 1,997 | 199,999 | 201,996 | 99,001 |
| 텍스트가 전부 a · 패턴 aab | 3 | 299,997 | 300,000 | 0 |
| a 999 개 + b 를 100 번 이은 텍스트 · 같은 패턴 | 2,994 | 199,900 | 202,894 | 100 |
| 텍스트가 전부 c · 패턴 a 999 개 + b | 2,994 | 100,000 | 102,994 | 0 |

텍스트를 a 20,000 개로 고정하고 패턴을 a 여러 개 + b 로 두어 길이를 2 부터 200 까지 바꿔 가며 재면, 텍스트 대조가 가장 많은 패턴 길이는 3 이고 그때 59,997 번으로 3n = 60,000 에 3 모자랍니다.

<!--/proof-->

**「패턴이 길수록 느리다」는 이 절차에서 거짓입니다.** 텍스트 대조가 가장 많은 것은 패턴 `aab` 이고, 패턴이
1,000 글자여도 오히려 더 적어요. `aab` 는 두 글자가 맞을 때마다 셋째 글자에서 어긋나 두 번 줄이므로, 한 자리에
비교가 세 번씩 듭니다. 최악은 축마다 다른 입력이 만듭니다. 텍스트 대조의 최악은 짧고 앞부분이 되풀이되는 패턴,
실패 함수 채우기의 최악은 길고 자기 앞부분을 되풀이하는 패턴, 답의 개수의 최악은 텍스트와 같은 글자로만 된
패턴이에요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 어긋난 순간 **이미 맞은 부분이 무엇인지 알고 있으므로** 살아남는
후보는 그 조각의 경계뿐이고, 그 값을 패턴만 보고 실패 함수에 미리 적어 두면 텍스트 자리가 한 번도 작아지지
않습니다.

| 차례 | 하는 일 | 비교 횟수의 상한 |
| --- | --- | --- |
| 1 | 패턴만 보고 실패 함수를 채운다 | `3m` |
| 2 | 텍스트를 한 글자씩 대조하고, 어긋나면 실패 함수 값으로 줄인다 | `3n` |
| 3 | 다 맞으면 자리를 적고 `fail[m-1]` 로 줄여 이어 간다 | 2 에 들어 있다 |

먼저 답이 붙는 문제 하나입니다. 전개의 T8 은 자리 4 를 적은 걸음이었고, 그 직후 `j` 가 4 에서 2 로 줄었어요.
그런데 T9 에서는 텍스트 자리 8 의 글자를 `P[2]` 와 비교합니다. `P[0]` 과 `P[1]` 은 왜 비교하지 않을까요?

<!--proof:selfcheck-t8-->

```text
T8 이 끝난 시점   j = 2                      T[6..7] = ab 가 P[0..1] 과 같다
T9 가 하는 일     T[8] 을 P[2] 와 비교한다   앞 2 글자는 이미 맞아 있다
```

<!--check:whySkipTwo-->
`j = 2` 라는 값이 **앞 두 글자가 이미 맞아 있다는 사실 자체**이기 때문입니다. T8 이 자리 4 의 등장을 적고 `j` 를
`fail[3] = 2` 로 줄인 것은 「`abab` 의 뒤 두 글자 `ab` 가 앞 두 글자 `ab` 와 같다」는 뜻이고, 그 두 글자는
텍스트의 자리 6 과 7 에 그대로 있어요. 다시 비교해도 같은 답이 나오고 비교만 두 번 늘어납니다. `j` 를 0 으로
두는 것이 바로 그 확인을 버리는 일이고, 그때 자리 6 의 등장을 통째로 놓쳐요.

<!--proof:selfcheck-answer-->

### 부분 문자열 등장 위치 검색

풀 파일: [`findAllOccurrences.ts`](./findAllOccurrences.ts) · 테스트: [`findAllOccurrences.test.ts`](./findAllOccurrences.test.ts) · 실행: `bun test src/algorithms/string/findAllOccurrences/findAllOccurrences.test.ts`

#### 한 줄 요약

> `findAllOccurrences(text, pattern)`은 텍스트와 패턴을 받아, 패턴이 텍스트 안에서 등장하는 모든 시작 위치를 오름차순 배열로 반환한다.

#### 스토리

편집자 준호는 수십만 글자짜리 원고 안에서 특정 단어가 몇 군데나 쓰였는지 전수 확인해야 한다. "찾기" 기능이 처음 발견한 위치만 알려줄 때는 나머지를 일일이 손으로 넘겨야 했다.

준호에게는 패턴이 나타나는 위치를 모조리 돌려주는 도구가 필요하다. 원고가 길어도 빠르게, 그리고 겹쳐서 등장하는 경우도 빠짐없이 잡아야 한다.

#### 함수 인터페이스

```ts
export function findAllOccurrences(text: string, pattern: string): number[];
```

- `text` — 검색 대상 텍스트
- `pattern` — 검색할 패턴
- 반환 — 패턴이 시작하는 인덱스(0-based) 배열, 오름차순 정렬. 등장하지 않으면 빈 배열.

#### 제약 조건

- $0 \leq |text| \leq 10^5$
- $0 \leq |pattern| \leq 10^5$
- 문자 집합: 소문자 영문 알파벳 (`a`–`z`)
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

텍스트 $T$(길이 $n$)와 패턴 $P$(길이 $m$)가 주어질 때, $T$ 내에서 $P$가 등장하는 모든 시작 위치를 오름차순으로 반환한다.

$$\text{Occ}(T, P) = \{\, i \mid 0 \leq i \leq n - m,\; T[i \ldots i+m-1] = P \,\}$$

겹치는 등장도 모두 포함한다. 예를 들어 `"aaaa"`에서 `"aa"`는 위치 0, 1, 2에서 모두 매칭된다.

**빈 패턴 규약**: $m = 0$이면 빈 배열을 반환한다. 빈 텍스트($n = 0$)에 비어 있지 않은 패턴을 검색하면 빈 배열을 반환한다.

#### 예시

```ts
findAllOccurrences("ababcababab", "abab");  // [0, 5, 7] — 겹침 포함 전체 매칭
findAllOccurrences("aaaa", "aa");           // [0, 1, 2] — 겹치는 3곳
findAllOccurrences("abc", "d");             // [] — 패턴 없음
findAllOccurrences("abc", "");              // [] — 빈 패턴 규약
findAllOccurrences("", "a");               // [] — 빈 텍스트
```
