# kasaiLcp — 앞 자리에서 맞춘 글자를 하나만 버리고 이어받으면 견주기 총합이 선형이 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

접미사 배열이 이미 주어진 자리에서 무엇을 더 구해야 하는지부터 잡습니다. 그다음 짝마다
처음부터 견주는 방법이 왜 안 되는지를 값으로 보이고, 견주는 차례를 바꿔 앞 자리의 결과를
이어받는 규칙에 이르기까지 걸음마다 끊지 않고 갑니다. 마지막에는 조각 코드를 이어 붙여
실행되는 함수 하나를 만듭니다.

### 전체 컨셉

문자열 `s` 와 그 접미사 배열 `sa` 를 받아, **사전순으로 이웃한 두 접미사가 앞에서부터 몇
글자를 함께 가지는지**를 그 차례대로 담은 배열을 돌려주는 문제예요. 접미사란 문자열의 어느
자리부터 끝까지를 잘라 낸 조각이고, 자리 `i` 에서 시작하는 접미사를 `s[i..]` 라고 적을게요.
두 문자열이 앞에서부터 몇 글자를 함께 가지는지를 **최장 공통 접두사** 길이라고 부르고, 이
글은 그것을 짧게 **공통 앞부분 길이**라고 적습니다.

<!--proof:concept-lcp-table-->

```text
칸     시작 자리  접미사  이웃         공통 앞부분 길이
sa[0]          5  a       ana                         1
sa[1]          3  ana     anana                       3
sa[2]          1  anana   banana                      0
sa[3]          0  banana  na                          0
sa[4]          4  na      nana                        2
sa[5]          2  nana    이웃이 없다                 0
```

넷째 열이 셋째 열을 한 칸 위로 옮긴 것이고, 다섯째 열이 답입니다 — 곧 `[1, 3, 0, 0, 2, 0]`
이에요. 마지막 칸이 0 인 것은 계산 결과가 아니라 규약입니다. 접미사 배열의 마지막 칸에는
사전순으로 뒤에 오는 접미사가 없어서 함께 가지는 글자를 잴 이웃 자체가 없고, 그 자리를 0 으로
채우기로 정한 것이에요.

```text
사전순으로 이웃한 두 접미사가 함께 가지는 글자

  자리 5 의 a      와 자리 3 의 ana      a   까지 같고 앞쪽이 먼저 끝난다   길이 1
  자리 3 의 ana    와 자리 1 의 anana    ana 까지 같고 앞쪽이 먼저 끝난다   길이 3
  자리 1 의 anana  와 자리 0 의 banana   첫 글자 a 와 b 가 다르다           길이 0
└ 앞쪽이 먼저 끝나면 그 길이가 답이고, 글자가 갈리면 갈린 자리까지가 답이다
```

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 이웃한 두 칸을 꺼내 그 두 접미사를
앞에서부터 한 글자씩 대조하고, 처음 갈리는 자리에서 멈춰 그때까지 센 글자 수를 적는 것이에요.
그런데 이 방법은 같은 글자가 길게 이어지는 문자열에서 견주기가 자리 수의 제곱으로 늘어나요.

<!--proof:concept-naive-cost-->

```text
     n  같은 글자만 있을 때의 글자 견주기    n(n−1)/2
     6                                 15          15
    12                                 66          66
   100                              4,950       4,950
 1,000                            499,500     499,500
10,000                         49,995,000  49,995,000

제약 최댓값 n = 100,000 에서 n(n−1)/2 = 4,999,950,000 번이다
1 초 안에 끝나는 규모가 아니다
```

제약이 `a` 만 10 만 개인 문자열을 허용하므로, 최악 보장이 필요하면 이 방법을 쓸 수 없어요.

**이 글이 쓰는 방법은 견주는 차례를 바꿉니다.** 접미사 배열의 칸 순서가 아니라 **원본
문자열의 자리 순서**로 자리 `i` 를 하나씩 처리하고, 자리 하나를 끝낼 때 맞춘 글자 수에서
**하나만 줄여 다음 자리로 넘깁니다.** 넘긴 값은 다음 자리가 견주기를 시작하는 **시작값**이
되고, 그 값 아래의 글자는 다시 대조하지 않아도 되는 것이 보장돼요.

```text
차례를 바꾸고 이어받으면 무엇이 달라지는가

  칸 순서로 짝마다 0 부터   sa[0]·sa[1] 을 견주고, sa[1]·sa[2] 를 다시 0 부터 견준다
                            앞 짝에서 확인한 글자를 뒤 짝이 다시 읽는다
  자리 순서로 이어받는다    자리 i 를 끝낸 값에서 1 을 뺀 값으로 자리 i+1 을 시작한다
                            그 값 아래의 글자는 이미 같다는 것이 정해져 있다
└ 두 방법이 내는 답은 같다. 갈리는 것은 글자를 몇 번 읽는가다
```

접미사 배열에서 자리 `i` 의 접미사 **바로 뒤에 오는** 접미사를 자리 `i` 의 **이웃**이라고
부를게요. 자리 순서로 처리하려면 그 이웃이 누구인지를 빠르게 알아야 하는데, 그것을
**역배열** 하나가 해결합니다 — 칸 번호를 `r` 이라 할 때 `inv[sa[r]] = r` 을 `n` 칸에 적어
두면 자리 `i` 의 이웃은 `sa[inv[i] + 1]` 한 번의 읽기로 나와요.

```text
절차 한 장

  준비   inv[sa[r]] = r 을 n 칸에 적는다
    |
    |    k = 0 에서 시작한다
    v
  자리 i = 0, 1, ..., n−1 을 차례로
    |    inv[i] 가 마지막 칸이면 이웃이 없다. k 를 0 으로 되돌리고 넘어간다
    |    아니면 이웃 j = sa[inv[i]+1] 을 얻고, s[i+k] 와 s[j+k] 가 같은 동안 k 를 늘린다
    |    lcp[inv[i]] 에 k 를 적고, k 가 0 보다 크면 하나 줄인다
    v
  답    lcp 를 돌려준다
└ 자리마다 하는 일이 정해져 있고, 글자 견주기만 자리에 따라 달라진다
```

자리 `n` 개를 한 번씩 지나므로 바깥 반복은 `n` 번이고, 글자 견주기는 전부 합쳐 `2n` 번을
넘지 않습니다. 전체가 `O(n)` 이라 제약 최댓값에서도 20 만 번 언저리로 끝나요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **사전순이 무엇인지.** 앞에서부터 글자를 대조하다가 처음 갈리는 자리로 정하고, 갈리는 자리
  없이 한쪽이 먼저 끝나면 짧은 쪽이 앞입니다. `ab` 는 `abc` 보다 앞이고 `b` 는 `abc` 보다
  뒤예요.
- **접미사 배열이 무엇인지.** 접미사 `n` 개를 사전순으로 늘어놓았을 때 각각이 시작하는 자리
  번호를 그 차례대로 담은 배열입니다. 이 글은 그것을 **이미 만들어진 재료로 받습니다** —
  만드는 방법은 [`suffixArray`](../suffixArray/suffixArray-guide.md) 가 다뤄요.
- **순열과 그 역이 무엇인지.** 접미사 배열은 `0` 부터 `n−1` 까지를 정확히 한 번씩 담은 배열,
  곧 순열입니다. 순열의 역은 「값이 있던 자리」와 「자리에 있던 값」을 맞바꾼 것이에요.
- **배열 칸 하나를 꺼내는 값이 배열 길이와 상관없다는 것.** 이 절차는 `sa[inv[i] + 1]` 처럼
  계산한 번호로 칸을 바로 꺼내 쓰는데, 그 값이 `n` 이 얼마든 일정합니다.

이 글이 다루는 것은 **이미 정해진 차례에서 이웃 짝의 공통 앞부분 길이를 전부 구하는 일
하나**입니다. 접미사 배열을 만드는 일도, 그렇게 얻은 배열로 부분 문자열을 찾는 일도 이 글의
범위 밖이에요.

```text
  접미사를 사전순으로 늘어놓는다              <- 다른 글이 다루는 것 (재료로 받는다)
  이웃한 두 접미사의 공통 앞부분 길이를 잰다  <- 이 글이 다루는 것
  그 길이 배열로 서로 다른 부분 문자열을 센다 <- 또 다른 글이 다루는 것
```

### 아이디어 상세 — 이어받는 규칙을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function kasaiLcp(s: string, sa: number[]): number[];
```

- 입력: 소문자 영문(`a`–`z`)으로 된 문자열 `s` 와, `s` 의 올바른 접미사 배열 `sa`.
- 출력: 길이 `n` 인 정수 배열. `r` 번째 칸에 **`sa[r]` 의 접미사와 `sa[r+1]` 의 접미사가
  함께 가지는 앞부분의 길이**를 담고, 마지막 칸은 규약대로 0 입니다.
- 제약: `1 ≤ n ≤ 100,000`, 목표 값 `O(n)`. 시간 1 초, 메모리 256 MB.
- 전제: `sa` 가 실제로 `s` 의 접미사 배열이라는 것은 문제가 보장합니다. 이 함수는 그것을
  검사하지 않아요.

이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `s` | 입력 문자열 | 소문자 영문 |
| `n` | 문자열 길이 | `1 ≤ n ≤ 100,000` |
| `sa` | 접미사 배열 | `sa[r]` 이 사전순 `r` 번째 접미사의 시작 자리 |
| `inv` | `sa` 의 역배열 | `inv[i]` 가 자리 `i` 의 접미사가 놓인 칸 번호 |
| `i` | 지금 처리하는 원본 문자열의 자리 | `0 ≤ i ≤ n−1` |
| `j` | 자리 `i` 의 이웃이 시작하는 자리 | `j = sa[inv[i] + 1]` |
| `k` | 지금까지 같음을 확인한 글자 수 | 자리 사이를 이어서 넘어간다 |
| `lcp` | 답 배열 | 칸이 `n` 개 |

`s[i..]` 는 자리 `i` 에서 문자열 끝까지이고, `s[i]` 는 자리 `i` 의 글자 하나예요. 코드에서도
`s`·`n`·`sa`·`inv`·`i`·`j`·`k`·`lcp` 를 그대로 씁니다.

가장 단순한 방법으로 시작합시다. 접미사 배열의 이웃한 두 칸을 꺼내, 그 두 접미사를 앞에서부터
한 글자씩 대조하는 것이에요.

```ts
const lcp = new Array<number>(n).fill(0);
for (let r = 0; r + 1 < n; r++) {
  const a = sa[r] as number;
  const b = sa[r + 1] as number;
  let k = 0;                                            // 짝마다 0 에서 다시 센다
  while (a + k < n && b + k < n && s[a + k] === s[b + k]) k++;
  lcp[r] = k;
}
```

문제가 되는 줄은 `let k = 0;` 입니다. 짝을 바꿀 때마다 세던 값을 버리고 처음부터 다시 세므로,
앞 짝에서 이미 같다고 확인한 글자를 뒤 짝이 또 읽어요. 네 글자짜리 입력에서 그것을 세어
봅시다.

<!--proof:build-repeat-->

```text
s = "aaaa" · sa = [3, 2, 1, 0]

견주는 두 칸   앞 접미사  뒤 접미사  같은 글자  공통 앞부분
sa[0] · sa[1]  "a"        "aa"               1            1
sa[1] · sa[2]  "aa"       "aaa"              2            2
sa[2] · sa[3]  "aaa"      "aaaa"             3            3

자리                 0  1  2  3
그 글자를 읽은 횟수  1  3  5  3

같은 글자를 확인한 견주기 6 번 · 글자가 달라 멈춘 견주기 0 번
```

자리 2 의 글자 하나가 다섯 번 읽혔습니다. 같은 글자가 이어질수록 이 되풀이가 길어지고, 그것이
앞에서 본 `n(n−1)/2` 의 정체예요.

```text
같은 글자를 다시 읽는 자리 — s = "aaaa"

  sa[0]·sa[1]   a a           자리 3 과 2 를 한 번 대조한다
  sa[1]·sa[2]   a a a         자리 2 부터 다시 시작한다. 방금 확인한 것을 또 읽는다
  sa[2]·sa[3]   a a a a       자리 1 부터 다시 시작한다. 두 번 확인한 것을 또 읽는다
└ 대조가 길어지는 것이 아니라, 앞 짝이 확인한 결과를 버리는 것이 원인이다
```

버리지 않으려면 **다음에 볼 짝이 방금 본 짝과 겹치는 부분을 많이 가져야** 합니다. 그런데
접미사 배열의 칸 순서로 가면 그 겹침이 보장되지 않아요 — `sa[r]` 과 `sa[r+1]` 은 사전순으로
이웃일 뿐 원본 문자열에서는 아무 관계가 없습니다.

```text
두 차례에서 이웃이 되는 것 — s = "banana"

  칸 순서    sa = 5 · 3 · 1 · 0 · 4 · 2      자리가 5 에서 3 으로, 3 에서 1 로 건너뛴다
  자리 순서  i  = 0 · 1 · 2 · 3 · 4 · 5      자리가 한 칸씩만 옮겨 간다
└ 자리 순서로 가면 이번 접미사가 지난 접미사에서 첫 글자 하나만 없앤 것이다
```

자리 순서로 가면 이번에 보는 접미사 `s[i..]` 가 직전에 본 `s[i−1..]` 에서 첫 글자 하나만
없앤 것입니다. 그러면 직전에 확인한 글자들이 이번에도 그대로 쓰일 여지가 생겨요. 그 여지가
실제로 값을 줄이는지, 같은 입력을 세 방법으로 처리해 **글자를 몇 번 읽는지** 나란히 세어
봅시다.

<!--proof:build-two-orders-->

```text
입력                      처리 방식                         같은 글자 확인  글자가 달라 멈춤  글자 견주기 합
전개 입력 "banana"        접미사 배열 순서 · 짝마다 0 부터               6                 2               8
전개 입력 "banana"        자리 순서 · 자리마다 0 부터                    6                 2               8
전개 입력 "banana"        자리 순서 · k 를 이어받는다                    3                 2               5
"aaaa"                    접미사 배열 순서 · 짝마다 0 부터               6                 0               6
"aaaa"                    자리 순서 · 자리마다 0 부터                    6                 0               6
"aaaa"                    자리 순서 · k 를 이어받는다                    3                 0               3
"mississippi"             접미사 배열 순서 · 짝마다 0 부터              13                 9              22
"mississippi"             자리 순서 · 자리마다 0 부터                   13                 9              22
"mississippi"             자리 순서 · k 를 이어받는다                    7                 9              16
같은 글자 n = 1,000       접미사 배열 순서 · 짝마다 0 부터         499,500                 0         499,500
같은 글자 n = 1,000       자리 순서 · 자리마다 0 부터              499,500                 0         499,500
같은 글자 n = 1,000       자리 순서 · k 를 이어받는다                  999                 0             999
무작위 두 글자 n = 1,000  접미사 배열 순서 · 짝마다 0 부터           9,058               991          10,049
무작위 두 글자 n = 1,000  자리 순서 · 자리마다 0 부터                9,058               991          10,049
무작위 두 글자 n = 1,000  자리 순서 · k 를 이어받는다                  998               991           1,989
```

**차례만 바꾼 가운데 줄은 첫 줄과 값이 하나도 다르지 않습니다.** 같은 글자 1,000 개짜리에서
두 방법 다 499,500 번이에요. 값을 준 것은 셋째 줄이고, 셋째 줄이 가운데 줄에 더한 것은
「자리 하나를 끝낸 `k` 를 다음 자리가 이어받는다」 하나뿐입니다.

```text
셋이 무엇으로 갈리는가 — 같은 글자 1,000 개

  칸 순서 · 짝마다 0 부터    499,500 번    앞 짝의 결과를 버린다
  자리 순서 · 자리마다 0 부터 499,500 번   차례만 바꿨고 결과는 여전히 버린다
  자리 순서 · 이어받는다          999 번   차례를 바꾼 것이 이어받기를 가능하게 했다
└ 차례 바꾸기는 그 자체로 값을 안 준다. 이어받기가 성립할 자리를 만들어 줄 뿐이다
```

이제 이어받는 규칙을 정확히 세웁니다. **자리 `i` 를 끝낸 `k` 에서 1 을 뺀 값이 자리 `i+1` 의
견주기 시작값입니다.** 하나를 빼는 이유는 접미사가 한 글자 짧아졌기 때문이에요 —
`s[i..]` 와 그 이웃이 `h` 글자를 함께 가졌다면, 양쪽에서 첫 글자를 하나씩 없앤 짝은 `h−1`
글자를 함께 가집니다.

```text
왜 정확히 하나인가 — s = "banana" 의 자리 3 에서 자리 4 로

  자리 3   ana     이웃 anana    앞에서부터 a n a 셋이 같다              h = 3
  각 첫 글자를 하나씩 없애면
  자리 4   na      이웃 nana     앞에서부터 n a 둘이 같다                h − 1 = 2
└ 없앤 것이 양쪽에서 같은 글자 하나라 함께 가지는 부분도 정확히 하나 줄어든다
   다만 자리 4 의 진짜 이웃은 anana 에서 앞 글자를 없앤 nana 가 아닐 수도 있다
```

마지막 줄이 이 규칙의 조심할 자리입니다. 자리 `i+1` 의 진짜 이웃은 접미사 배열이 정하는
것이지 「직전 자리의 이웃에서 첫 글자를 없앤 것」이 아니에요. 그런데도 `h−1` 이 안전한 것은 진짜
이웃이 사전순으로 그 사이에 있어서 **함께 가지는 글자가 `h−1` 보다 적을 수 없기** 때문입니다.

<!--proof:build-carry-->

```text
자리 i  inv[i]  이웃 j  이어받은 k  진짜 값  판정            늘린 횟수
     0       3       4           0        0  넘지 않는다             0
     1       2       0           0        0  넘지 않는다             0
     2       5    없다           0     없다  견줄 짝이 없다          0
     3       1       1           0        3  넘지 않는다             3
     4       4       2           2        2  넘지 않는다             0
     5       0       3           1        1  넘지 않는다             0

이어받기가 없앤 견주기 3 번
늘린 횟수의 합 3 · 글자가 달라 멈춘 횟수 2
```

여섯 자리 전부에서 이어받은 값이 진짜 값을 넘지 않았고, 자리 4 와 자리 5 에서는 이어받은
값이 곧 진짜 값이라 글자를 한 번도 읽지 않았습니다. 자리 2 는 이웃이 없는 자리인데 그때
이어받은 값이 0 이라 잃을 것이 없었어요.

```text
가장 쉬운 자리와 가장 불안한 자리 — s = "banana"

  가장 쉬운 자리   i = 0, 1   첫 글자부터 달라 k 가 0 그대로다. 이어받을 것이 없다
  이어받는 자리    i = 4, 5   각각 2 와 1 을 이어받고 그대로 답이 된다
  가장 불안한 자리 i = 2      이웃이 없어 답을 안 적는다. k 를 0 으로 되돌린다
└ 셋째 줄이 불안한 이유는 "적지 않고 넘어간 자리의 k 가 그대로 다음 자리로 넘어가면?" 이다
   그 자리에 들어올 때 k 가 0 이라는 것은 아래 멈춤 하나가 값으로 확인한다
```

이 규칙이 정하는 것은 **`k` 의 이동 범위**입니다. `k` 는 자리 하나에서 많아야 1 만큼 줄고,
자리 `n` 개를 지나는 동안 줄어드는 총량이 `n` 을 넘지 못하므로 늘어나는 총량도 그만큼으로
묶여요. 늘어나는 횟수가 곧 「같음을 확인한 글자 견주기」라 그 값이 `n` 언저리에서 멈추는데,
그러면 하필 1 을 빼는 이유가 남습니다. 0 을 빼면 어떻게 되고 2 를 빼면 어떻게 되는지를
실제로 실행해서 재 봅시다.

<!--proof:build-drop-->

```text

전개 입력 "banana"                        0  아니오                 5
전개 입력 "banana"                        1  예                     5
전개 입력 "banana"                        2  예                     7
전개 입력 "banana"                        3  예                     8
전개 입력 "banana"                     전부  예                     8
"mississippi"                             0  아니오                10
"mississippi"                             1  예                    16
"mississippi"                             2  예                    19
"mississippi"                             3  예                    21
"mississippi"                          전부  예                    22

같은 글자 n = 1,000                       1  예                   999
같은 글자 n = 1,000                       2  예                 1,997
같은 글자 n = 1,000                       3  예                 2,994
같은 글자 n = 1,000                    전부  예               499,500

무작위 두 글자 n = 1,000                  3  예                 3,974
무작위 두 글자 n = 1,000               전부  예                10,049

빼는 양이 0 이면 답이 맞지 않고, 1 보다 크면 답은 맞으면서 견주기가 는다
```

**빼는 양이 0 이면 답이 맞지 않고, 2 이상이면 답은 맞으면서 견주기가 늡니다.** 같은 글자
1,000 개에서 1 을 빼면 999 번인데 2 를 빼면 1,997 번이고, 아예 전부 빼면(자리마다 0 에서 다시
세면) 499,500 번이에요. 1 은 **답이 맞는 값 중 가장 큰 것**이고 그래서 견주기가 가장 적습니다.

```text
빼는 양을 바꾸면 두 가지가 반대로 움직인다

  0 을 뺀다     이어받은 값이 진짜 값보다 커질 수 있다      답이 틀린다
  1 을 뺀다     이어받은 값이 진짜 값 이하로 가장 크다      답이 맞고 견주기가 가장 적다
  2 이상을 뺀다 이어받은 값이 더 작아진다                   답은 맞고 견주기가 는다
└ 가운데 줄이 답이다. 정확성이 위쪽 경계를 정하고, 견주기가 아래쪽을 정한다
```

절차가 여섯 줄로 정리됩니다.

```text
얻은 절차 한 벌
  1. inv[sa[r]] = r 을 n 칸에 적는다
  2. k 를 0 으로 두고 자리 i 를 0 부터 n−1 까지 차례로 본다
  3.   inv[i] 가 마지막 칸이면 답을 적지 않고 k 를 0 으로 되돌린다
  4.   아니면 이웃 j = sa[inv[i]+1] 을 얻는다
  5.   s[i+k] 와 s[j+k] 가 같은 동안 k 를 하나씩 늘린다
  6.   lcp[inv[i]] 에 k 를 적고, k 가 0 보다 크면 하나 줄인다
       └ 499,500 번이던 것이 999 번이 된다
```

### 수행으로 알아보는 알고리즘 — 여섯 글자에서 자리 여섯을 원본 차례로 처리한다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const s = "banana";
const sa = [5, 3, 1, 0, 4, 2];
// 이 절이 끝나면 [1, 3, 0, 0, 2, 0] 이 나와야 한다
```

왜 하필 이 여섯 글자일까요? 여섯 갈래가 다 실행되고(역배열 · 이웃 없음 · 이웃 얻기 · 글자
견주기 · 기록 · 하나 줄이기), 견주기가 멈추는 두 가지 이유가 둘 다 나오며(글자가 다르다 ·
문자열 끝을 넘었다), 이어받은 `k` 가 실제로 견주기를 없애는 자리가 둘 있기 때문이에요.
접미사 배열 `[5, 3, 1, 0, 4, 2]` 는 [`suffixArray`](../suffixArray/suffixArray-guide.md) 편이
같은 문자열에서 낸 것과 같습니다.

```text
절차 전체를 한 장으로

  준비   T1        ① 역배열 inv 를 만든다. k = 0
  본체   T2 ~ T7   자리 i = 0 부터 5 까지 차례로
                     ② inv[i] 가 마지막 칸이면 k 를 0 으로 되돌리고 넘어간다
                     ③ 이웃 j = sa[inv[i]+1] 을 얻는다
                     ④ s[i+k] 와 s[j+k] 가 같은 동안 k 를 늘린다
                     ⑤ lcp[inv[i]] 에 k 를 적는다
                     ⑥ k 가 0 보다 크면 하나 줄여 다음 자리에 넘긴다
  끝     T8        lcp 를 돌려준다
```

#### 1. 자리와 칸을 잇는 역배열을 만든다

첫 조각은 준비입니다. 자리 순서로 처리하려면 자리 `i` 가 접미사 배열의 몇 번째 칸인지를
알아야 하고, 그것을 미리 배열 하나에 적어 둡니다.

```ts
const inv = new Array<number>(n).fill(0);
// ① 역배열 — 자리 `i` 에서 시작하는 접미사가 `sa` 의 몇 번째 칸에 있는지 적어 둔다.
for (let r = 0; r < n; r++) inv[sa[r] as number] = r;
```

`①` 이 하는 일은 `sa` 를 한 번 지나면서 값과 자리를 맞바꾸는 것뿐이에요. `sa[r]` 이 `i` 라면
`inv[i]` 가 `r` 입니다.

<!--proof:walk-inv-->

```text
자리 i  s[i]  접미사 s[i..]  inv[i]  sa[i]
     0  b     banana              3      5
     1  a     anana               2      3
     2  n     nana                5      1
     3  a     ana                 1      0
     4  n     na                  4      4
     5  a     a                   0      2

sa  = [5, 3, 1, 0, 4, 2]
inv = [3, 2, 5, 1, 4, 0]
inv[sa[r]] = r 이 여섯 칸에서 모두 맞는가  예
```

여기까지가 T1 입니다. `lcp` 는 아직 전부 0 이고 `inv` 만 값을 가지고 있어요.

#### 멈춤 — 역배열을 반대로 채우면 다른 이웃을 가리킨다

여기서 헷갈리기 쉬운 포인트는 역배열을 채우는 방향입니다. 「자리 `i` 에 대응하는 값을
적는 것이니 `inv[i] = sa[i]` 아닌가」로 읽기 쉬워요. 그 생각대로 한 줄만 바꿔 봅시다.

```ts
for (let r = 0; r < n; r++) inv[r] = sa[r] as number;   // ← 값과 자리를 안 맞바꿨다
```

두 판을 작은 입력 여덟 개에 실행해 나란히 놓습니다.

#### 2. 앞의 세 자리를 처리한다

둘째 조각은 자리 하나를 처리하는 본체입니다. 이웃이 있는지 먼저 확인하고, 있으면 그 이웃을
얻어 글자를 견준 뒤 그 값을 자리 번호가 아니라 **칸 번호**에 적어요.

```ts
// ② 이웃이 없는 자리 — `sa` 의 마지막 칸이라 견줄 접미사가 없다. 값을 적지 않는다.
if (inv[i] === n - 1) {
  k = 0;
  continue;
}
// ③ 이웃이 시작하는 자리. 역배열이 있어 배열 읽기 한 번으로 얻는다.
const j = sa[(inv[i] as number) + 1] as number;
// ④ 이어받은 `k` 에서 시작해 글자가 같은 동안 하나씩 늘린다.
while (i + k < n && j + k < n && s[i + k] === s[j + k]) k++;
// ⑤ 이 자리의 답은 `sa` 안에서의 순위 칸에 적는다.
lcp[inv[i] as number] = k;
```

`②` 가 `③` 보다 먼저 와야 하는 이유가 있어요. `inv[i]` 가 `n−1` 이면 `sa[inv[i] + 1]` 이
`sa[n]` 이라 배열 밖입니다. 순서를 바꾸면 그 읽기가 먼저 실행돼요.

<!--proof:walk-early-->

```text
걸음  자리 i  inv[i]  이웃 j  들어올 때 k  기록         멈춘 이유      lcp
T2         0       3       4            0  lcp[3] = 0   글자가 다르다  [0, 0, 0, 0, 0, 0]
T3         1       2       0            0  lcp[2] = 0   글자가 다르다  [0, 0, 0, 0, 0, 0]
T4         2       5    없다            0  적지 않는다  이웃이 없다    [0, 0, 0, 0, 0, 0]
```

T2 와 T3 은 첫 글자부터 달라 `k` 가 0 그대로이고, T4 는 `②` 가 참이라 답을 적지 않고
넘어갑니다. `lcp` 는 세 걸음 뒤에도 전부 0 이에요.

#### 멈춤 — 답을 자리 번호 칸에 적으면 다른 배열이 나온다

여기서 헷갈리기 쉬운 포인트는 `⑤` 의 왼쪽입니다. 자리 `i` 를 차례로 보고 있으니 「`i` 번째
반복이 `lcp[i]` 를 채운다」로 읽기 쉬워요. 그 생각대로 한 줄만 바꿔 봅시다.

```ts
lcp[i] = k;   // ← 칸 번호가 아니라 자리 번호에 적었다
```

```text
"cabbage"           [4, 0, 3, 2, 1, 6, 5]               아니오
"abracadabra"       [2, 6, 10, 3, 7, 4, 8, 1, 5, 9, 0]  아니오
```

셋째 열이 「예」인 두 줄이 위 표에서 답이 안 바뀐 두 줄과 정확히 같습니다. `banana` 에서는
`[0, 0, 0, 3, 2, 1]` 이 나오는데, 이 배열은 아무 값이나가 아니라 **같은 값을 자리 순서로
늘어놓은 것**입니다.

```text
같은 여섯 값이 두 차례로 늘어선다 — s = "banana"

  자리 i        0  1  2  3  4  5
  그 자리의 값  0  0  -  3  2  1     자리 2 는 이웃이 없어 값이 없다
  inv[i]        3  2  5  1  4  0
  칸 번호 순    1  3  0  0  2  0     위 줄의 값을 inv[i] 칸으로 옮긴 것이다
└ 정본은 셋째 줄을 써서 넷째 줄을 만들고, 바꾼 판은 둘째 줄을 그대로 답으로 낸다
```

#### 3. 같은 글자를 세어 k 를 3 까지 늘린다

셋째 조각은 `④` 의 반복입니다. 자리 `i` 와 이웃 `j` 를 `k` 만큼 떨어진 자리에서 대조하고,
같으면 `k` 를 하나 늘려요.

```ts
while (i + k < n && j + k < n && s[i + k] === s[j + k]) k++;
// ⑥ 다음 자리에는 하나만 줄여서 넘긴다.
if (k > 0) k--;
```

멈추는 이유가 둘입니다 — 글자가 다르거나, 둘 중 하나가 문자열 끝을 넘거나예요. 자리 3 에서
그 둘 중 어느 쪽으로 멈추는지 한 걸음씩 봅시다.

<!--proof:walk-extend-->

```text
i = 3 의 접미사 "ana" · 이웃 j = 1 의 접미사 "anana"

k  앞 자리  글자  뒤 자리  글자  판정
0  s[3]     a     s[1]     a     같다 — k 를 하나 늘린다
1  s[4]     n     s[2]     n     같다 — k 를 하나 늘린다
2  s[5]     a     s[3]     a     같다 — k 를 하나 늘린다
3  s[6]     없다  s[4]     n     문자열 끝을 넘어 멈춘다

이 자리가 적는 값        lcp[1] = 3
다음 자리로 넘기는 값    k = 2
```

T5 가 이 걸음입니다. 세 번 같음을 확인해 `k` 가 3 이 되고, 자리 3 + 3 = 6 이 문자열 끝을
넘어 멈춰요. `⑤` 가 `lcp[1] = 3` 을 적고 `⑥` 이 2 를 다음 자리로 넘깁니다.

```text
자리 3 이 넘긴 2 가 자리 4 에서 무엇을 없애는가

  이어받지 않으면  자리 4 는 k = 0 에서 n·a 를 다시 대조한다        견주기 2 번
  이어받으면       자리 4 는 k = 2 에서 시작하고 4+2 = 6 이 끝이다  견주기 0 번
└ 자리 4 가 없앤 견주기 2 번은 자리 3 이 이미 확인한 그 두 글자다
```

#### 멈춤 — 되돌리기 줄을 빼도 답이 안 바뀐다

여기서 헷갈리기 쉬운 포인트는 `②` 안의 `k = 0` 입니다. `k` 가 방금 T5 에서 처음으로 0 이
아닌 값이 됐으니 이 물음이 생기는 자리예요 — 「값을 안 적고 넘어가는 자리인데 `k` 를 그대로
두면 낡은 값이 다음 자리로 넘어가 답이 틀린다」로 읽기 쉽습니다. 그 줄을 빼고 여덟 입력에
실행해 봅시다.


그 갈래에 들어올 때 `k` 가 **이미 0** 이기 때문입니다.


들어올 때 `k` 가 0 인 것은 우연이 아니라 규칙에서 나옵니다. 자리 `i` 가 0 이 아닌 `k` 를
이어받았다면 직전 자리가 `k+1` 글자를 이웃과 함께 가졌다는 뜻이고, 그러면 `s[i..]` 보다
사전순으로 뒤에 오는 접미사가 실제로 존재해서 `s[i..]` 가 마지막 칸일 수 없어요.

```text

  k > 0 을 이어받았다        직전 자리가 이웃과 h = k+1 >= 2 글자를 함께 가졌다
  그 이웃의 첫 글자를 없앤 접미사가 존재하고, s[i..] 보다 사전순으로 뒤에 있다
  그러므로                   s[i..] 는 사전순 마지막이 아니다. inv[i] != n−1 이다
└ 그 줄이 하는 일은 이 사실을 코드에 적어 두는 것이다. 값을 바꾸는 일은 하지 않는다
```

이 줄을 그래도 남기는 이유는 둘이에요. 첫째로 위 논증이 참이라는 것을 코드만 보고 알 수는
없어서, 그 줄이 없으면 읽는 사람이 「낡은 값이 넘어가는가」를 매번 다시 따져야 합니다.
둘째로 위 논증은 `sa` 가 올바른 접미사 배열이라는 전제를 씁니다 — 그 전제가 깨지는 자리에서
이 줄이 하는 일이 생겨요.

것은 `inv` 가 `sa` 의 역이라 값 `n−1` 을 가지는 자리가 정확히 하나이기 때문이에요. 답이 정말
맞는지도 확인하고 갑시다 — 표의 두 접미사를 직접 잘라 대조하면 아래와 같아요.

| 이웃한 두 칸 | 두 접미사 | 함께 가지는 앞부분 | 왜 거기서 멈추는가 |
| --- | --- | --- | --- |
| `sa[0]`=5, `sa[1]`=3 | `a` · `ana` | `a` | 앞쪽이 먼저 끝난다 |
| `sa[1]`=3, `sa[2]`=1 | `ana` · `anana` | `ana` | 앞쪽이 먼저 끝난다 |
| `sa[2]`=1, `sa[3]`=0 | `anana` · `banana` | 없다 | 첫 글자 `a` 와 `b` 가 다르다 |
| `sa[3]`=0, `sa[4]`=4 | `banana` · `na` | 없다 | 첫 글자 `b` 와 `n` 이 다르다 |
| `sa[4]`=4, `sa[5]`=2 | `na` · `nana` | `na` | 앞쪽이 먼저 끝난다 |

#### 5. 전체 코드

세 조각을 한 함수로 잇습니다. 앞에서 값으로 확인하지 않은 것이 하나 남아 있는데 `n` 이 1 인
경우예요 — 자리가 하나뿐이면 `inv[0]` 이 곧 `n−1` 이라 `②` 가 참이 되고, `lcp` 가 초기값
`[0]` 그대로 나갑니다.

```ts
export function kasaiLcp(s: string, sa: number[]): number[] {
  const n = s.length;
  const lcp = new Array<number>(n).fill(0);

  // ① 역배열 — 자리 `i` 에서 시작하는 접미사가 `sa` 의 몇 번째 칸에 있는지 적어 둔다.
  const inv = new Array<number>(n).fill(0);
  for (let r = 0; r < n; r++) inv[sa[r] as number] = r;

  let k = 0;
  for (let i = 0; i < n; i++) {
    // ② 이웃이 없는 자리 — `sa` 의 마지막 칸이라 견줄 접미사가 없다. 값을 적지 않는다.
    if (inv[i] === n - 1) {
      k = 0;
      continue;
    }

    // ③ 이웃이 시작하는 자리. 역배열이 있어 배열 읽기 한 번으로 얻는다.
    const j = sa[(inv[i] as number) + 1] as number;

    // ④ 이어받은 `k` 에서 시작해 글자가 같은 동안 하나씩 늘린다. 둘 중 하나가 문자열 끝을
    // 넘으면 거기서 멈춘다.
    while (i + k < n && j + k < n && s[i + k] === s[j + k]) k++;

    // ⑤ 이 자리의 답은 `sa` 안에서의 순위 칸에 적는다.
    lcp[inv[i] as number] = k;

    // ⑥ 다음 자리에는 하나만 줄여서 넘긴다.
    if (k > 0) k--;
  }

  return lcp;
}
```

```text
kasaiLcp("banana", [5, 3, 1, 0, 4, 2])  ->  [1, 3, 0, 0, 2, 0]
kasaiLcp("aaaa", [3, 2, 1, 0])          ->  [1, 2, 3, 0]
kasaiLcp("abab", [2, 0, 3, 1])          ->  [2, 0, 1, 0]
kasaiLcp("abc", [0, 1, 2])              ->  [0, 0, 0]
kasaiLcp("a", [0])                      ->  [0]
```

### 알아 두면 좋은 개념 — 순열의 역

전개의 `inv` 배열이 한 일에는 이미 이름이 있습니다. `sa` 는 `0` 부터 `n−1` 까지를 정확히 한
번씩 담은 배열, 곧 **순열**이고 `inv` 는 그 **역**이에요. 순열의 역이란 「`x` 번째 자리에
있던 값」과 「값 `x` 가 있던 자리」를 맞바꾼 것이고, 두 번 적용하면 원래대로 돌아옵니다.

<!--proof:related-inverse-->

```text
x  sa[x]  inv[sa[x]]  inv[x]  sa[inv[x]]
0      5           0       3           0
1      3           1       2           1
2      1           2       5           2
3      0           3       1           3
4      4           4       4           4
5      2           5       0           5

셋째 열과 다섯째 열이 첫째 열과 같은가  예
```

셋째 열과 다섯째 열이 첫째 열과 똑같습니다. `inv[sa[x]] = x` 와 `sa[inv[x]] = x` 가 둘 다
성립한다는 뜻이고, 그래서 이 두 배열은 같은 대응을 양쪽 방향에서 읽은 것이에요.

```text
같은 대응을 두 방향으로 읽는다

  sa  : 칸 --> 자리     "0 번 칸에는 자리 5 의 접미사가 있다"
  inv : 자리 --> 칸     "자리 5 의 접미사는 0 번 칸에 있다"

  이 절차가 필요로 한 것은 오른쪽 방향이다
  자리 i 로 순회하면서 "이 자리가 몇 번 칸인가" 를 물어야 하기 때문이다
└ 왼쪽만 들고 있으면 그 물음에 답하는 데 배열 전체를 다시 읽어야 한다
```

같은 뒤집기는 다른 자리에서도 나옵니다. [`suffixArray`](../suffixArray/suffixArray-guide.md)
의 `rank` 배열이 바로 이 `inv` 이고, 계수 정렬이 값마다 놓을 자리를 정할 때 만드는 표도 같은
대응의 반대 방향이에요 — [`countingSort`](../../sorting/countingSort/countingSort-guide.md) 가
그것을 다룹니다. 좌표 압축에서 「압축한 번호 → 원래 값」과 「원래 값 → 압축한 번호」를 둘 다
들고 있는 것도 같은 짝입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

여기서는 파트 1 이 세운 절차를 네 각도에서 따집니다 — 어느 문제 모양에 이것이 답인가,
이어받기가 안전하다는 것을 식으로 적으면 무엇이 새로 나오는가, 자리마다 참으로 남는 문장이
무엇인가, 글자와 배열 칸을 몇 번 읽는가.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **접미사 배열이 이미 있습니다.** 이 절차는 `sa` 를 재료로 받고 만들지 않아요. `sa` 를
  만드는 값은 이 절차와 별개로 들고, 이 글은 그 값을 세지 않습니다.
- **이웃 짝 전부가 필요합니다.** 짝 하나의 값만 필요하면 그 짝만 직접 대조하는 것이 더 적어요.
  `n−1` 개를 다 구해야 할 때 이어받기가 값을 냅니다.
- **최악 보장이 필요합니다.** 어떤 문자열이 들어와도 글자 견주기가 `2n−2` 를 넘지 않아야
  하는 자리예요.

```text
세 조건이 코드의 모양을 그대로 정한다
  sa 가 이미 있다        -> 역배열 한 벌만 더 만들면 된다
  이웃 짝 전부가 필요    -> 자리 n 개를 한 번씩 지나는 반복 하나로 끝난다
  최악 보장이 필요       -> 되풀이가 심한 문자열에서도 견주기가 n 에 비례한다
```

| 무엇을 묻는가 | 무엇을 쓰는가 | 왜 |
| --- | --- | --- |
| 이웃 짝 전부의 공통 앞부분 길이 | 이 절차 | 자리 순서 순회 하나로 끝난다 |
| 임의의 두 접미사 짝 하나 | 이 배열 위의 구간 최솟값 질의 | 배열을 먼저 만들어 두고 답한다 |
| 서로 다른 부분 문자열의 개수 | 이 배열의 합 | `n(n+1)/2` 에서 이 배열의 합을 뺀다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "인접한 두 접미사가 공유하는 길이"                  <- 이 배열 자체가 답이다
  "가장 긴 반복되는 부분 문자열"                      <- 이 배열의 최댓값이다
  "서로 다른 부분 문자열의 개수"                      <- 전체 접미사 길이 합에서 이 배열 합을 뺀다
  "m 번 이상 나오는 가장 긴 조각"                     <- 길이 m−1 짜리 구간의 최솟값 중 가장 큰 값이다

제약에 이런 모양이 보이면
  |s| 가 10^5 이고 O(n) 을 요구한다
  접미사 배열이 입력으로 함께 주어진다
  같은 글자가 길게 이어질 수 있다고 적혀 있다

반대로 이런 말이 보이면 해당하지 않는다
  "두 접미사 짝 하나의 공통 앞부분"                    <- 그 짝만 직접 대조하는 것이 더 적다
  "문자열이 계속 바뀐다"  "글자를 삽입·삭제한다"       <- sa 부터 다시 만들어야 한다
  "글자가 어긋나는 것을 허용한다"                      <- 공통 앞부분이라는 개념 자체가 안 맞는다
```

첫째 무리의 마지막 줄은 이 배열이 다른 문제의 재료가 되는 자리입니다. 이웃 짝의 값을 알면
접미사 배열의 어느 구간에 대해서도 「그 구간 전체가 함께 가지는 앞부분」이 그 구간 안 값들의
최솟값이 되고, 그 성질 위에서 여러 문제가 풀려요.

### 수식 정의와 유도

자리 `i` 의 이웃과 그 이웃과의 공통 앞부분을 기호로 정합니다. `i` 가 접미사 배열의 마지막 칸이
아닐 때 `j(i) = sa[inv[i] + 1]` 을 자리 `i` 의 이웃이라고 하고, 두 접미사가 함께 가지는
앞부분의 길이를 `h(i)` 라고 적을게요.

$$h(i) \;=\; \max\bigl\{\, t \ge 0 \;:\; t \le \min\bigl(n-i,\ n-j(i)\bigr),\ \ s[i \ldots i+t-1] = s[j(i) \ldots j(i)+t-1] \,\bigr\}$$

```text
식을 읽는 법
  i        원본 문자열의 자리. 0 부터 n−1 까지다
  j(i)     자리 i 의 접미사 바로 뒤에 오는 접미사가 시작하는 자리
  t        견주는 두 조각의 길이. 둘 중 짧은 접미사의 길이를 넘지 못한다
  h(i)     그 둘이 앞에서부터 함께 가지는 글자 수
           └ inv[i] 가 n−1 이면 이웃이 없어 h(i) 를 정의하지 않는다
```

정의가 실제로 그 값을 내는지부터 봅시다. `s = "banana"` 의 여섯 자리에 정의를 그대로 넣어
계산하고, 그 값이 전개가 이어받은 `k` 와 어떻게 맞물리는지 나란히 놓습니다.

<!--proof:math-check-->

```text
자리 i  h(i)  h(i−1)  h(i) ≥ h(i−1) − 1  이어받은 k
     0     0       -  -                           0
     1     0       0  맞다                        0
     2  없다       0  -                           0
     3     3       -  -                           0
     4     2       3  맞다                        2
     5     1       2  맞다                        1

h 를 순위 순서로 다시 늘어놓으면  [1, 3, 0, 0, 2, 0]
정본이 낸 답                      [1, 3, 0, 0, 2, 0]
```

`h` 를 자리 순서로 늘어놓은 것과 답을 칸 순서로 늘어놓은 것이 서로 다른 배열이고, 둘을 잇는
것이 `inv` 입니다. 그리고 넷째 열이 전부 「맞다」인 것이 유도의 대상이에요 — 첫째로 **`h` 는
자리가 하나 늘 때 1 보다 많이 줄지 않는다**는 것입니다. `h(i-1) = h` 이고 `h ≥ 2` 라고
두면, 이웃 `s[j(i-1)..]` 는 `s[i-1..]` 보다 사전순으로 뒤에 있고 둘이 앞의 `h` 글자를 함께
가져요.

$$s[i-1] = s[j(i-1)] \quad\text{이므로}\quad s[i \ldots] \;<\; s[j(i-1)+1 \ldots] \quad\text{이고}\quad s[i \ldots i+h-2] = s[j(i-1)+1 \ldots j(i-1)+h-1]$$

```text
양쪽에서 첫 글자를 하나씩 없애면
  없애기 전   s[i−1 ...]  <  s[j(i−1) ...]    함께 가지는 앞부분이 h 글자다
  없앤 뒤     s[i ...]    <  s[j(i−1)+1 ...]  함께 가지는 앞부분이 h−1 글자다
              └ 대소 관계가 유지되는 것은 없앤 글자가 양쪽에서 같은 하나이기 때문이다
                 h >= 2 이면 j(i−1)+1 <= n−1 이라 그 접미사가 실제로 존재한다
```

둘째로 **사전순으로 사이에 있는 접미사는 그 공통 앞부분을 물려받습니다.** 자리 `i` 의 진짜
이웃 `s[j(i)..]` 는 `s[i..]` 보다 큰 접미사 중 가장 작은 것이므로
`s[i..] < s[j(i)..] ≤ s[j(i-1)+1..]` 이고, 양 끝이 앞의 `h-1` 글자를 함께 가지면 사이의 것도
같은 `h-1` 글자를 가질 수밖에 없어요.

$$h(i) \;\ge\; h(i-1) - 1 \qquad (h(i-1) \ge 2)$$

```ts
// 식을 그대로 옮긴 조각. 실제 절차는 이 하한을 k 의 시작값으로 쓴다.
const lowerBound = (prev: number): number => Math.max(prev - 1, 0);
```

이 부등식이 이어받기를 정당하게 만듭니다. 그리고 여기서 **견주기 총합의 닫힌 형태**가 나와요.
`k` 는 자리마다 많아야 1 줄고, 시작값과 마지막 값이 둘 다 0 이므로 늘어난 총량과 줄어든 총량이
정확히 같습니다.

$$\sum_{i} (\text{늘어난 양}) \;=\; \sum_{i} (\text{줄어든 양}) \;=\; \bigl|\{\, i : h(i) \ge 1 \,\}\bigr| \;\le\; n-1$$

```text
마지막 값이 0 인 이유
  마지막 자리 i = n−1 의 접미사는 글자 하나짜리다
  이웃이 있으면 h(n−1) <= 1 이므로 하나 줄이면 0 이 된다
  이웃이 없으면 그 갈래가 k 를 0 으로 되돌린다
└ 시작값도 0 이고 마지막 값도 0 이라 늘어난 총량과 줄어든 총량이 같다
```

줄어드는 일은 답을 적은 값이 1 이상일 때만 일어나고, 답을 적는 자리는 이웃이 있는 `n−1` 개
뿐입니다. 그러므로 **같음을 확인한 견주기는 `n−1` 번을 넘지 않아요.** 글자가 달라 멈추는
견주기도 이웃이 있는 자리마다 많아야 한 번이므로 같은 `n−1` 이 상한이고, 둘을 더하면
`2n−2` 입니다.

$$C(n) \;=\; (\text{같음 확인}) + (\text{다름 확인}) \;\le\; (n-1) + (n-1) \;=\; 2n-2$$

```text
두 항이 각각 어디서 나오는가
  같음 확인  k 가 하나 늘어난 횟수      = 줄어든 총량 = h(i) >= 1 인 자리 수 <= n−1
  다름 확인  반복이 글자 차이로 멈춘 수  자리마다 많아야 한 번이고 이웃이 있는 자리가 n−1 개다
└ 두 항의 상한이 같은 n−1 이라 합이 2n−2 다. 아래 표가 그 상한과 실측을 나란히 놓는다
```

```text

전개 입력 "banana"            6                          3                       2      5         10  0.500
"mississippi"                11                          7                       9     16         20  0.800
같은 글자 n = 1,000       1,000                        999                       0    999      1,998  0.500

피보나치 n = 1,000        1,000                        998                     609  1,607      1,998  0.804
무작위 두 글자 n = 1,000  1,000                        998                     991  1,989      1,998  0.995
무작위 26 글자 n = 1,000  1,000                        974                     997  1,971      1,998  0.986
```

일곱 입력 다 상한 안이고, 무작위 두 글자에서 그 값이 상한의 99.5 % 까지 올라갑니다. 이
`2n−2` 는 본문이 잰 일곱 값만으로는 나오지 않는 진술이에요 — **임의의 문자열에서** 성립하는
값이고, 제약 최댓값을 넣으면 이렇게 됩니다.


### 불변식 — 자리를 시작할 때의 k 는 그 자리의 진짜 공통 앞부분 길이를 넘지 않는다

파트 1 은 여섯 글자짜리 문자열 하나에서 답이 나오는 것까지 보였습니다. 그것은 그 입력에서
맞았다는 뜻이지 어떤 입력에서도 맞는다는 뜻이 아니에요. 무엇이 **자리마다 참으로 남는지**를
문장으로 세우고 그것이 실제로 유지되는지 확인해 봅시다.

> 바깥 반복이 자리 `i` 를 시작하는 시점에서, `k` 는 `h(i)` 이하입니다. 자리 `i` 에 이웃이
> 없으면 그 시점의 `k` 는 0 이에요.

```text
문장이 참이 되는 시점을 왜 밝히는가
  자리를 시작하는 시점   k 는 아직 이어받은 값이다. 이 문장이 참이다
  견주기 반복이 끝난 뒤  k 는 이미 h(i) 와 같아졌다. 이하가 아니라 같다
  하나 줄인 뒤           k 는 h(i)−1 이고 다음 자리의 시작 시점 값이 된다
└ 시점을 안 밝히면 "이하" 와 "같다" 가 같은 문장 안에서 뒤섞인다
```

**출발점부터 봅시다.** 첫 자리에 들어갈 때 `k` 는 0 이고, 0 은 어떤 길이보다도 크지 않으므로
문장이 성립합니다. 자리를 하나 넘길 때 문장이 유지되는 갈래는 셋이에요.

| 갈래 | 그 자리에서 하는 일 | 다음 자리의 시작값이 안전한 근거 |
| --- | --- | --- |
| 이웃이 없다 | 답을 적지 않고 `k` 를 0 으로 되돌린다 | 0 은 어떤 길이보다도 크지 않다 |
| 이웃이 있고 적은 값이 0 이다 | `k` 를 그대로 둔다 | 그 값이 이미 0 이다 |
| 이웃이 있고 적은 값이 1 이상이다 | `k` 를 하나 줄인다 | 유도한 부등식 `h(i) ≥ h(i−1) − 1` |

셋째 줄이 이 논증의 핵심입니다. 앞 절이 유도한 부등식이 그 줄의 근거이고, 그 부등식이
성립하지 않으면 이어받은 값이 진짜 값보다 커지는데 **견주기 반복은 값을 늘리기만 하므로**
그 넘친 값이 그대로 적히게 돼요.

<!--proof:invariant-watch-->

```text
입력                      n  확인한 자리  이어받은 값이 진짜 값과 같은 자리  판정
전개 입력 "banana"        6            6                                  4  지킨다
"aaaa"                    4            4                                  2  지킨다
"mississippi"            11           11                                  6  지킨다
"abracadabra"            11           11                                  7  지킨다
피보나치 n = 500        500          500                                497  지킨다
무작위 두 글자 n = 500  500          500                                348  지킨다
```

여섯 입력의 모든 자리에서 문장이 유지됐고, 이어받은 값이 진짜 값과 **같아지는** 자리도
적지 않습니다. 피보나치 문자열에서는 500 자리 중 497 자리가 그랬어요 — 그런 자리에서는 글자를
한 번도 안 읽고 답이 정해집니다. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

```text
경계                   입력    sa            답            마지막 칸  글자 견주기
길이 1                 "a"     [0]           [0]                   0            0
두 글자가 같다         "aa"    [1, 0]        [1, 0]                0            1
두 글자가 다르다       "ab"    [0, 1]        [0, 0]                0            1
뒤가 앞보다 작다       "ba"    [1, 0]        [0, 0]                0            1
전부 같은 글자         "aaaa"  [3, 2, 1, 0]  [1, 2, 3, 0]          0            3
전부 다른 글자         "abcd"  [0, 1, 2, 3]  [0, 0, 0, 0]          0            3
되풀이                 "abab"  [2, 0, 3, 1]  [2, 0, 1, 0]          0            3
앞이 같고 끝만 다르다  "aaab"  [0, 1, 2, 3]  [2, 1, 0, 0]          0            5
```

길이 1 은 바깥 반복이 한 번 실행되지만 그 한 번이 이웃 없는 갈래라 `lcp` 가 `[0]` 그대로
나갑니다. 전부 다른 글자는 반대쪽 경계로, 모든 자리가 첫 글자에서 갈려 견주기가 이웃이 있는 자리마다
한 번씩이에요. 마지막 칸은 여덟 경계 전부에서 0 입니다.

**이제 깨뜨려 봅시다.** 문장을 지키던 줄은 답을 적은 뒤의 하나 줄이기예요. 「이미 확인한
글자를 왜 버리는가, 그대로 이어받으면 견주기가 더 줄지 않는가」라는 생각으로 그 줄을 빼 봅니다.

```ts
lcp[inv[i] as number] = k;
if (k > 0) k--;   // ← 이 줄을 통째로 뺐다
```

<!--proof:mutant-no-decrement-->

```text
입력                정본                               하나 줄이기를 뺀 판                판정
전개 입력 "banana"  [1, 3, 0, 0, 2, 0]                 [3, 3, 0, 0, 3, 0]                 어긋난다

```

`banana` 에서 `[1, 3, 0, 0, 2, 0]` 이어야 할 답이 `[3, 3, 0, 0, 3, 0]` 이 됩니다. 자리 3 이
적은 3 을 자리 4 가 그대로 이어받았는데 자리 4 의 진짜 값은 2 라, 견주기 반복이 한 번도
실행되지 않은 채 3 이 적혔어요.

```text
"banana" 에서 어긋나는 자리

  자리 4 의 진짜 값     2      접미사 na 와 nana 는 na 둘을 함께 가진다
  정본이 이어받은 값    2      3 에서 하나 줄인 값이다. 견주기 0 번으로 2 를 적는다
  변이가 이어받은 값    3      줄이지 않은 값이다. i+k = 7 이 이미 끝을 넘어 반복이 멈춘다
                               견주기 0 번으로 3 을 적는다. 있지도 않은 글자를 셌다
└ 반복 조건이 "끝을 넘으면 멈춘다" 라서, 넘치게 이어받은 값은 줄어들 기회가 없다
```

`abc` 에서만 답이 안 바뀌는 것도 같은 이유예요. 그 입력은 모든 자리의 `h` 가 0 이라 줄일
값 자체가 없고, 그래서 이 줄을 빼도 실행이 똑같습니다.

### 비용 계산

#### 비용을 세는 과정

실행 한 번을 두 무리로 가릅니다. 역배열을 만드는 자리가 하나이고, 그다음은 자리 `n` 개를
차례로 지나는 자리예요. 전개의 여덟 걸음에 각각 얼마가 들었는지 세 봅니다.

<!--proof:perf-count-->

```text
걸음  자리 i  같은 글자 확인  달라서 멈춤  배열 칸 접근
T2         0               0            1             4
T3         1               0            1             4
T4         2               0            0             1
T5         3               3            0             4
T6         4               0            0             4
T7         5               0            0             4

역배열을 만드는 데 배열 칸 접근 12 번
바깥 반복의 배열 칸 접근 21 번 · 합 33 번
글자 견주기는 같은 글자 확인 3 번 + 달라서 멈춤 2 번 = 5 번
```

T5 만 글자 견주기 세 번을 쓰고 T2·T3 이 한 번씩, 나머지 셋은 0 번입니다. 배열 칸 접근은
반대로 자리마다 거의 같아요 — 이웃이 있는 자리는 4 번, 이웃이 없는 T4 만 1 번입니다.

```text
총식 = 역배열 만들기        +  자리 n 개
       └ 배열 칸 2n 번         └ 이웃이 있으면 배열 칸 4 번, 없으면 1 번
                                  그리고 글자 견주기 (자리마다 다르다)

  배열 칸 접근  2n + 4(n−1) + 1 = 6n − 3      입력의 내용과 상관없이 같다
  글자 견주기   같음 확인 + 다름 확인 <= 2n−2  입력의 내용이 정한다
  추가로 잡는 칸  inv 가 n 칸 · lcp 가 n 칸 = 2n
└ n = 6 이면 배열 칸 33 번이고 위 표의 합과 같다. n = 100,000 이면 599,997 번이다
```

여기서 센 것은 배열 칸 읽기·쓰기와 글자 읽기 둘입니다. 안 센 것은 자리 번호를 하나 올리는
일과 두 정수를 대조하는 일인데, 둘 다 위 두 값에 비례하므로 총식의 차수가 그대로예요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (모든 자리가 첫 글자에서 갈린다) | `O(n)` | `Θ(n)` — 자리 `n` 개를 반드시 지난다 |
| **평균적인 경우** (글자를 균등하게 뽑는다고 두면) | `O(n)` | `Θ(n)` — 최선과 최악이 같은 차수다 |
| **최악의 경우** (앞이 다 같고 끝 한 글자만 다르다) | `O(n)` | `Θ(n)` — 글자 견주기가 `2n−3` 까지 간다 |

**세 줄이 같은 것이 이 절차의 성질입니다.** 케이스가 정하는 것은 차수가 아니라 계수뿐이에요.
그 계수가 어디까지 갈리는지를 여덟 모양에서 실제로 재 봅시다.

<!--proof:perf-shapes-->

```text
입력 모양 (n = 10,000)    같은 글자 확인  달라서 멈춤  글자 견주기  그 값 / n  배열 칸 접근
전부 같은 글자                     9,999            0        9,999      1.000        59,997
두 글자가 번갈아 나온다            9,998            1        9,999      1.000        59,997
앞이 다 같고 끝만 다르다           9,998        9,999       19,997      2.000        59,997
주기 6 되풀이                      9,997            2        9,999      1.000        59,997
피보나치 문자열                    9,998        4,180       14,178      1.418        59,997
무작위 두 글자                     9,998        9,984       19,982      1.998        59,997
무작위 26 글자                     9,974        9,997       19,971      1.997        59,997
글자가 오름차순                    9,974           25        9,999      1.000        59,997

배열 칸 접근은 모양과 상관없이 같다 — 바깥 반복이 자리마다 정해진 횟수만 접근한다
```

계수가 1.000 과 2.000 사이에서 갈립니다. 배열 칸 접근은 여덟 모양 전부 59,997 로 같은데,
그 값이 `6n−3` 이라 입력의 내용이 아니라 `n` 만으로 정해지기 때문이에요.

```text
총식 = Θ(n) 자료 접근 + Θ(n) 추가 칸
       │                 └ inv 가 n 칸 · lcp 가 n 칸
       └ 배열 칸 6n−3 번 (입력과 무관) + 글자 견주기 2n−2 번 이하 (입력이 정한다)

  n = 100,000 이면 배열 칸 599,997 번 · 글자 견주기 199,998 번 이하 · 잡는 칸 200,000 개
└ 앞뒤로 붙는 전처리는 역배열 하나뿐이다. 정렬도, 해시도, 좌표 압축도 쓰지 않는다
```

**최악 보장입니다.** 위 상한을 내는 논증에 확률이 한 글자도 들어가지 않았어요. 평균 줄에
있는 `Θ(n)` 도 입력 분포에 대한 기댓값이 아니라 **최선과 최악이 같은 차수라서 어떤 분포에서도
같은 값이 되는 것**이고, 분포가 정하는 것은 계수가 1 쪽인가 2 쪽인가뿐입니다.

그런 모양을 여럿 세워 제약 최댓값에서 재 봅시다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 접미사 배열의 칸 순서가 아니라 원본 자리
순서로 처리하면 이번 접미사가 직전 접미사에서 첫 글자 하나만 없앤 것이 되고, 그래서 직전에
맞춘 길이에서 **1 만 줄인 값**을 견주기의 시작값으로 쓸 수 있어 전체가 `O(n)` 이 됩니다.

```text
한 바퀴가 하는 일
  역배열을 만든다       자리 --> 칸 방향을 미리 적어 둔다
  자리 i 를 차례로 본다  칸 순서가 아니라 원본 자리 순서다
  이웃 j 를 얻는다       sa[inv[i]+1] 배열 읽기 한 번이다
  같은 동안 k 를 늘린다  이 늘림의 총합이 n−1 번 이하다
  하나 줄여 넘긴다       다음 자리의 시작값이 된다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T6 과 T7 은 이어받은 값이 그대로 답이 되어 글자를
한 번도 안 읽은 걸음이었어요. 그 두 자리에서만 이어받기를 없애고 `k = 0` 부터 다시 세게 하면
글자 견주기가 몇 번 늘어날까요?

```text
걸음  자리 i  접미사  이웃의 접미사  이어받은 k  이 걸음의 글자 견주기
T6         4  na      nana                    2                    0 번
T7         5  a       ana                     1                    0 번
```

<!--check:carrySaves-->
세 번 늘어납니다. 자리 4 는 `n` 과 `a` 두 글자를 다시 대조해 2 번, 자리 5 는 `a` 하나를 다시
대조해 1 번이에요. 이어받은 값이 곧 그 자리의 진짜 값이었으니 다시 세도 답은 같고 견주기만
늡니다.

```text
전개 입력 "banana" 에서 이어받기가 없애는 견주기
  이어받으면       같음 확인 3 · 다름 확인 2   합 5 번
  이어받지 않으면  같음 확인 6 · 다름 확인 2   합 8 번
└ 늘어난 3 번이 자리 4 의 2 번과 자리 5 의 1 번이다
   아래쪽 8 번은 짝마다 0 부터 세는 방법의 값과 같다
```

이어받기가 없애는 것은 「같음 확인」뿐이고 「다름 확인」은 자리마다 그대로 남습니다.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 번 → 전개의 여덟 걸음
  2 번 → 두 번째 「멈춤」
  3 번 → 「수식 정의와 유도」와 「최악을 만드는 입력」
```

- `s = "abab"`, `sa = [2, 0, 3, 1]` 로 전개를 처음부터 따라가 보세요. `inv` 는 무엇이고, 자리
  0 부터 3 까지 각각 이어받은 `k` 와 적은 값은 무엇일까요? 최종 답은 `[2, 0, 1, 0]` 이 나와야
  합니다. 글자 견주기가 몇 번이었는지도 세어 보세요.
- 답을 `lcp[inv[i]]` 가 아니라 `lcp[i]` 에 적으면 `banana` 에서 `[0, 0, 0, 3, 2, 1]` 이
  나왔습니다. 이 배열도 쓸모가 있는 값인데, **무엇을 담고 있는 배열인지**와 **이 배열 하나만
  가지고 원래 답을 만들려면 무엇이 더 필요한지**를 한 문장씩 적어 보세요.
- 유도한 상한은 `2n−2` 인데 전수 실행이 낸 최댓값은 `2n−3` 이었습니다. 두 상한 `n−1` 이
  각각 어느 자리에서 하나씩 나오는지 적고, **한 자리가 「같음 확인」과 「다름 확인」을 둘 다
  내려면 무엇이 필요한지**를 자리 `n−1` 을 예로 들어 따져 보세요. 전수 실행에서 최댓값을 낸
  문자열이 그 자리를 어떻게 쓰는지도 함께 보면 됩니다.
