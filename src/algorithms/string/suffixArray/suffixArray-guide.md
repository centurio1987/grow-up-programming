# suffixArray — 앞 바퀴가 매긴 순위를 재료로 쓰면 글자를 다시 읽지 않아도 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

접미사가 무엇이고 답이 어떤 모양인지부터 잡습니다. 그다음 접미사를 통째로 견주는 방법이 왜
막히는지를 값으로 보이고, 거기서 순위 두 개만 견주는 방법에 이르는 길을 걸음마다 끊지 않고
갑니다. 마지막에는 조각 코드를 이어 붙여 실행되는 함수 하나를 만듭니다.

### 전체 컨셉

문자열 `s` 를 받아 **모든 접미사를 사전순으로 늘어놓았을 때 각각이 시작하는 자리 번호**를
그 순서대로 담은 배열을 돌려주는 문제예요. 접미사란 문자열의 어느 자리부터 끝까지를 잘라 낸
조각입니다 — 자리 `i` 에서 시작하는 접미사를 `s[i..]` 라고 적을게요. 길이 `n` 인 문자열에는
접미사가 정확히 `n` 개 있고, 서로 길이가 달라서 **같은 접미사는 두 개 없습니다.**

<!--proof:concept-banana-->

```text
자리   시작 자리 i  접미사 s[i..]  길이
sa[0]            5  a                 1
sa[1]            3  ana               3
sa[2]            1  anana             5
sa[3]            0  banana            6
sa[4]            4  na                2
sa[5]            2  nana              4
```

셋째 열의 접미사를 위에서 아래로 읽으면 사전순입니다. 답은 둘째 열을 위에서 아래로 모은 것,
곧 `[5, 3, 1, 0, 4, 2]` 예요. 사전순은 두 문자열의 앞에서부터 글자를 견주다가 처음 갈리는 자리에서 정해지고, 갈리는
자리 없이 한쪽이 먼저 끝나면 **짧은 쪽이 앞**입니다 — `a` 가 `ana` 보다 앞인 것이 그 규칙입니다.

```text
사전순이 두 접미사를 가르는 두 가지 방식

  갈리는 글자가 있다     anana 와 banana      첫 글자 a 와 b 에서 정해진다
  갈리는 글자가 없다     a 와 ana             a 가 먼저 끝난다. 짧은 쪽이 앞이다
                         ana 와 anana         ana 가 먼저 끝난다. 짧은 쪽이 앞이다
└ 접미사끼리는 길이가 다 달라 둘째 방식이 언제나 결말을 낸다. 같은 접미사가 없다는 뜻이다
```

가장 먼저 떠오르는 방법은 접미사를 실제로 잘라 내어 문자열 정렬에 넣는 것입니다. 그런데 이
방법은 정렬을 시작하기도 전에 걸려요. 접미사 `n` 개의 길이 합이 `n + (n−1) + … + 1` 이라서,
잘라 낸 것을 다 들고 있으려면 글자 `n(n+1)/2` 개가 필요합니다.

<!--proof:concept-slice-cost-->

```text
      n  접미사를 다 잘라 담을 때의 글자 수 n(n+1)/2  글자 하나를 1바이트로 잡으면
      6                                           21                     21 바이트
  1,000                                      500,500                500,500 바이트
100,000                                5,000,050,000                      4,768 MB

메모리 제한은 256 MB 다. 글자 하나를 1바이트로 잡아도 4,768 MB 이고,
자바스크립트 문자열은 글자 하나에 그보다 더 쓴다
```

잘라 내지 않고 자리 번호만 들고서 필요할 때마다 글자를 견주어도 문제가 남습니다. 두 접미사가
앞부분을 길게 공유하면 견주기 한 번에 그 공유 길이만큼 글자를 읽어야 하고, `a` 만 10 만 개인
문자열이 제약 안에 있어서 그 값이 실제로 커집니다.

**이 글이 쓰는 방법은 접미사를 통째로 견주지 않습니다.** 대신 **앞에서 잘라 낸 짧은 조각의
순위**를 배열 하나에 적어 두고, 바퀴마다 그 조각 길이를 두 배로 늘려 갑니다. 길이 `L` 조각의
순위를 이미 알고 있으면, 길이 `2L` 조각의 순서는 **앞 `L` 글자의 순위와 뒤 `L` 글자의 순위를
이어 붙인 쌍**을 견주는 것으로 정해져요. 글자를 다시 읽지 않고 정수 두 개만 견주면 됩니다.

```text
길이 4 조각 anan 을 견주는 두 가지 방법

  글자로 견준다     a n a n 을 상대와 한 글자씩 대조한다    많아야 4 번
  순위 쌍으로 본다  앞 두 글자 an 의 순위를 배열에서 읽고   한 번
                    뒤 두 글자 an 의 순위를 배열에서 읽어   한 번
                    정수 두 개짜리 쌍 하나를 상대와 견준다
└ 조각이 길어져도 쌍은 언제나 정수 두 개다. 견주기 값이 조각 길이를 따라가지 않는다
```

쌍을 만들려면 순위 배열을 두 자리에서 읽기만 하면 되고, 쌍으로 자리들을 다시 늘어놓는 일은
값의 범위가 `n` 으로 묶여 있어 계수 정렬 두 번으로 끝납니다. 그렇게 한 바퀴를 마치면 조각
길이가 두 배가 되므로, 조각이 접미사 전체를 덮을 때까지 필요한 바퀴 수가 `⌈log₂ n⌉` 이하예요.
전체 값은 `O(n log n)` 이 되고, `n` 이 10 만이어도 바퀴가 열일곱 번을 넘지 않습니다.

```text
바퀴가 하는 일 한 장

  길이 1 조각의 순위       글자 코드를 그대로 쓴다
      |
      |  쌍 (앞 조각 순위, 뒤 조각 순위) 를 만들고 계수 정렬 두 번으로 늘어놓는다
      v
  길이 2 조각의 순위
      |
      |  같은 일을 되풀이한다
      v
  길이 4 조각의 순위  ->  ...  ->  조각 길이가 n 에 이르면 순위가 전부 달라진다
└ 순위가 전부 달라진 시점의 늘어놓은 순서가 곧 답이다
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **사전순이 무엇인지.** 앞에서부터 글자를 견주다가 처음 갈리는 자리로 정하고, 갈리는 자리
  없이 한쪽이 끝나면 짧은 쪽이 앞입니다. `ab` 는 `abc` 보다 앞이고, `b` 는 `abc` 보다 뒤예요.
- **안정 정렬이 무엇인지.** 키가 같은 두 원소의 앞뒤가 정렬 뒤에도 들어올 때와 같은 정렬을
  말합니다. 이 글의 절차는 그 성질에 통째로 기대고 있어요.
- **계수 정렬이 무엇인지.** 키가 `0` 이상 `K` 미만의 정수일 때 각 값이 몇 번 나오는지 세고
  누적합으로 자리를 정해 견주기 없이 늘어놓는 정렬입니다. 값 하나마다 칸을 하나 잡으므로
  `O(n + K)` 예요. 모르면 [`countingSort`](../../sorting/countingSort/countingSort-guide.md)
  가 그것만 다룹니다.
- **자리 번호로 배열 칸이나 글자 하나를 꺼내는 값이 배열 길이와 상관없다는 것.** 이 절차는
  자리 `i+gap` 의 순위를 배열에서 바로 꺼내 쓰는데, 그 값이 `gap` 이 얼마든 일정합니다.

이 글이 다루는 것은 **접미사의 순서를 정하는 일 하나**입니다. 그 순서를 얻은 뒤에 이웃한 두
접미사가 앞부분을 몇 글자나 공유하는지(최장 공통 접두사)를 구하는 것은 별개의 절차이고,
[`kasaiLcp`](../kasaiLcp/kasaiLcp-problem.md) 가 그것을 다뤄요. 이 글은 그 값을 만들지도, 쓰지도
않습니다.

```text
  접미사를 사전순으로 늘어놓는다              <- 이 글이 다루는 것
  늘어놓은 뒤 이웃한 둘의 공통 앞부분을 잰다  <- 다른 글이 다루는 것
  패턴 하나가 나오는 자리를 전부 찾는다       <- 또 다른 글이 다루는 것
```

### 아이디어 상세 — 순위 쌍을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function suffixArray(s: string): number[];
```

- 입력: 소문자 영문(`a`–`z`)으로 된 문자열 하나.
- 출력: 길이 `n` 인 정수 배열. `k` 번째 칸에 **사전순 `k` 번째 접미사의 시작 자리**를 담습니다.
  접미사는 서로 길이가 달라 같은 것이 없으므로 답은 언제나 하나예요.
- 제약: `1 ≤ n ≤ 100,000`, 목표 값 `O(n log n)`. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `s` | 입력 문자열 | 소문자 영문 |
| `n` | 문자열 길이 | `1 ≤ n ≤ 100,000` |
| `i` | 접미사가 시작하는 문자열 자리 | `0 ≤ i ≤ n−1` |
| `sa` | 답 배열 | `sa[k]` 가 사전순 `k` 번째 접미사의 시작 자리 |
| `gap` | 순위를 이미 알고 있는 조각의 길이 | 1 에서 시작해 바퀴마다 두 배 |
| `rank` | 자리 `i` 에서 시작하는 길이 `gap` 조각의 순위 | 칸이 `n` 개 |
| `span` | 순위가 가질 수 있는 값의 개수 | 순위가 전부 다르면 `n` 이다 |

`s[i..j]` 라고 적으면 자리 `i` 와 자리 `j` 를 둘 다 담은 조각이고, `s[i..]` 는 자리 `i` 에서
문자열 끝까지입니다. 식의 `gap` 과 `rank` 를 코드의 이름으로도 `gap`·`rank` 를 씁니다.

가장 단순한 방법으로 시작합시다. 자리 번호를 늘어놓고, 두 자리를 견줄 때마다 그 두 접미사의
글자를 앞에서부터 대조하는 것이에요.

```ts
const sa = Array.from({ length: n }, (_, i) => i);
sa.sort((a, b) => {
  let k = 0;
  while (a + k < n && b + k < n) {          // 공통 앞부분만큼 글자를 다시 읽는다
    if (s[a + k] !== s[b + k]) return s[a + k] < s[b + k] ? -1 : 1;
    k++;
  }
  return n - a < n - b ? -1 : 1;            // 갈리는 자리 없이 한쪽이 끝났다
});
```

이 방법이 하는 일의 양은 **견주기 횟수 × 견주기 하나가 읽는 글자 수**입니다. 견주기 횟수는
정렬이 정하므로 `n log n` 언저리이고, 견주기 하나가 읽는 글자 수는 **두 접미사가 앞부분을
얼마나 길게 공유하는가**에 달렸어요. 그래서 공유가 가장 길어지는 입력에서 값을 재 봅니다.

두 방법을 같은 입력에 적용해 **자료 접근**을 나란히 세겠습니다. 두 방법이 같은 자로 재지려면
단위가 하나여야 하는데, 견주기 횟수도 글자 읽기도 그 자리에 못 옵니다.

```text
무엇을 세면 두 방법이 같은 자로 재지는가
  견주기 횟수만    계수 정렬은 견주기를 한 번도 하지 않는다        한쪽이 0 이 된다
  글자 읽기만      순위 쌍 방식은 첫 바퀴 말고는 글자를 안 읽는다  한쪽이 0 이 된다
  자료 접근        배열 칸 읽기·쓰기 + 글자 읽기                   양쪽 다 값이 나온다
└ 이 글은 마지막 줄을 쓴다. 아래 표의 모든 수가 그 단위다
```

<!--proof:build-two-ways-->

```text
     n  직접 견주기(전부 a)  이 방식(전부 a)  직접 견주기(무작위)  이 방식(무작위)
    12                  306            2,076                  154            1,074
   120               44,512           23,774                3,430            7,747

제약 최댓값 n = 100,000 에서는
입력               직접 견주기     이 방식    몇 배
전부 같은 글자  77,909,041,216  46,262,802  1684 배
무작위 26 글자               —   8,563,020        —

└ n 을 열 배로 키우면 왼쪽은 백 배가 되고 오른쪽은 열 배 남짓에 그친다
```

**열두 글자에서는 네 값 다 직접 견주기 쪽이 적습니다.** 계수 정렬이 글자 코드 범위만큼 칸을
잡는 값이 규모와 상관없이 붙어 있어서, 규모가 작으면 그 항 하나가 전체를 정합니다. 그리고
**무작위 26 글자 열에서는 12,000 글자에서도 직접 견주기가 더 적습니다** — 서로 다른 글자가
섞여 있으면 두 접미사가 대개 한두 글자에서 갈려서, 견주기 하나가 읽는 글자 수가 2 언저리에
머무릅니다.

| 입력의 모양 | 견주기 하나가 읽는 글자 수 | 직접 견주기의 값 |
| --- | --- | --- |
| 무작위 26 글자 | 2 언저리 | `n log n` 언저리로 충분히 적다 |
| 전부 같은 글자 | 짧은 쪽 접미사의 길이만큼 | `n` 에 비례해 늘어 전체가 `n² log n` 이 된다 |

여기서 관찰할 것은 하나예요. **직접 견주기의 값은 접미사끼리 앞부분을 얼마나 길게 공유하는가에
달렸고, 그 공유 길이는 입력이 정합니다.** 제약이 `a` 만 10 만 개인 문자열을 허용하므로, 최악
보장이 필요하면 이 방법을 쓸 수 없어요 — 779 억 번은 1 초 안에 끝나지 않습니다.

```text
같은 두 접미사를 견줄 때 각 방법이 읽는 것

  s = aaaaaaaaaa 에서 s[0..] 과 s[1..] 을 견준다
    직접 견주기  a a a a a a a a a  아홉 글자를 다 읽고 길이로 정한다  글자 18 번
    순위 쌍      앞 조각 순위 하나 + 뒤 조각 순위 하나                 배열 4 번
└ 아래쪽은 조각 길이가 얼마든 배열을 네 번 읽는다
```

그러면 **글자를 다시 읽지 않으려면 무엇을 들고 있어야 하는가**가 남습니다. 후보 중 가장 적게
들고 있는 것을 먼저 세워 봅시다 — 「첫 글자의 순위 하나만 들고 있자」예요. 첫 글자가 다르면 그것으로 순서가
정해지니, 남는 것은 첫 글자가 같은 자리들뿐입니다.

```text
s = banana 에서 첫 글자만으로 가른 무리

  a  자리 1 · 3 · 5     셋이 한 무리에 남는다
  b  자리 0
  n  자리 2 · 4         둘이 한 무리에 남는다
└ 여섯 자리 중 다섯이 아직 안 갈렸다. 첫 글자 하나로는 부족하다
```

첫 글자로 못 가른 자리들을 가르려면 **둘째 글자부터**를 봐야 하는데, 그것이 바로
「자리 `i+1` 에서 시작하는 접미사의 순서」예요. 그리고 우리는 그것을 이미 같은 형태로 들고
있습니다 — 첫 글자의 순위 배열이 그것입니다. **자리 `i` 의 앞 한 글자 순위와 자리 `i+1` 의 앞
한 글자 순위를 이어 붙이면 자리 `i` 의 앞 두 글자 순서가 나옵니다.**

<!--proof:build-reuse-->

```text
i  s[i..i+1]  앞 조각 순위  뒤 조각 순위  쌍
0  ba                   98            98  (98, 98)
1  an                   97           111  (97, 111)
2  na                  110            98  (110, 98)
3  an                   97           111  (97, 111)
4  na                  110            98  (110, 98)
5  a                    97             0  (97, 0)

쌍을 사전식으로 늘어놓은 순서   [5, 1, 3, 0, 2, 4]
두 글자로 잘라 직접 견준 순서   [5, 1, 3, 0, 2, 4]
└ 두 줄이 같다. 글자를 다시 읽지 않고 순위 두 개만 견주어도 순서가 같게 나온다
```

**뒤 조각 순위가 순위 그대로가 아니라 하나씩 커져 있고, 자리 5 는 0 입니다.** 자리 5 의 뒤
조각은 문자열 끝을 넘어 존재하지 않는데, 사전순 규칙이 「없으면 짧은 쪽이 앞」이므로 그 자리는
**어떤 실제 순위보다도 작은 값**을 받아야 해요. 계수 정렬의 칸 번호로 쓰려면 음수를 못 쓰니,
실제 순위를 전부 1 씩 올려 0 을 비우고, 그 0 을 「없음」의 자리로 씁니다.

이제 이것을 개념으로 세웁니다. **`rank[i]` 는 자리 `i` 에서 시작하는 길이 `gap` 조각의
순위이고, 다음 바퀴의 키는 `(rank[i], rank[i + gap])` 라는 쌍입니다.** 이 정의가 정하는 것은
두 가지예요.

| 무엇이 정해지는가 | 어떻게 |
| --- | --- |
| 한 바퀴에 덮는 조각 길이 | `gap` 에서 `2·gap` 으로 두 배가 된다 |
| 한 바퀴가 읽는 배열 칸 | 자리마다 `rank[i]` 와 `rank[i+gap]` 둘, 곧 `2n` 번 |

`gap` 이 커져도 자리 하나가 읽는 순위 칸은 언제나 둘이라, **바퀴 하나가 읽는 순위 칸이
`gap` 과 상관없이 `2n` 개입니다**(계수 정렬이 잡는 칸은 따로 붙습니다). 그러면 전체 값은 바퀴 수가 정하고, 바퀴 수는 「조각 길이를 한 바퀴에 몇
배로 늘리는가」가 정해요. 그 배수를 실제로 바꿔 가며 재 봅니다.

<!--proof:build-growth-->


**가장 적은 것은 두 배가 아니라 세 배입니다.** 두 배는 그보다 8.1 % 많아요. 그런데도 이 글이
두 배를 쓰는 이유는 그 8.1 % 를 내주고 얻는 것이 있기 때문입니다 — 배수를 `m` 으로 하면 키가
성분 `m` 개짜리가 되어 계수 정렬이 바퀴마다 `m` 번이고 순위 재부여의 판정도 `m` 개 값
대조입니다. 두 배면 키가 **쌍 하나**라 정렬이 두 번이고 판정이 두 값 대조로 끝나요.

```text
배수를 키우면 두 항이 반대로 움직인다
  바퀴 수         m 이 커지면 준다      x2 는 17 · x16 은 5
  바퀴 하나의 값  m 이 커지면 는다      정렬이 m 번이다
  둘의 곱         m = 3 에서 가장 작다  x2 와는 8.1 % 차이다
└ 8 부터 늘어나는 것은 바퀴 수가 더 줄지 않는데 바퀴 하나가 계속 커지기 때문이다
```

이렇게 해서 절차가 여섯 줄로 정리됩니다.

```text
얻은 절차 한 벌
  1. 길이 1 조각의 순위를 글자 코드로 둔다
  2. gap 을 1 로 두고 gap 이 n 보다 작은 동안 되풀이한다
  3.   자리마다 쌍 (rank[i], rank[i+gap]) 을 만든다. 뒤가 없으면 0 이다
  4.   뒤 성분으로 안정 정렬하고, 그 결과를 앞 성분으로 다시 안정 정렬한다
  5.   이웃한 두 자리의 쌍이 다를 때만 순위를 하나 올려 새 rank 를 만든다
  6.   순위가 전부 달라졌으면 멈추고, 아니면 gap 을 두 배로 한다
       └ 779 억 번이던 것이 4,626 만 번이 된다
```

### 수행으로 알아보는 알고리즘 — 여섯 글자에서 두 바퀴로 접미사 순서를 정한다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const s = "banana";
// 이 절이 끝나면 [5, 3, 1, 0, 4, 2] 가 나와야 한다
```

왜 하필 이 여섯 글자일까요? 다섯 갈래가 다 실행되고(첫 순위 · 뒤 조각이 범위를 넘음 · 계수
정렬 · 쌍이 같아 순위 유지 · 종료 판정), 바퀴가 **두 번**이라 「앞 바퀴의 순위를 재료로 쓴다」가
말이 아니라 값으로 확인되며, 같은 순위가 두 쌍(`an` 무리와 `na` 무리) 남아 다섯째 갈래가
첫 바퀴에서는 거짓이고 둘째 바퀴에서 참이 되기 때문이에요.

```text
절차 전체를 한 장으로

  준비      ① 글자 코드를 길이 1 조각의 순위로 둔다
  T2~T5     gap = 1 :
              ② 쌍 (rank[i], rank[i+1]) 을 만든다. 뒤가 없으면 0 이다
              ③ 뒤 성분 · 앞 성분 순서로 계수 정렬 두 번
              ④ 같은 쌍끼리 묶어 새 순위를 매긴다
              ⑤ 순위가 전부 달라졌는가 — 아니면 gap 을 두 배로
  T6~T9     gap = 2 : 같은 다섯 걸음을 되풀이한다
  끝        늘어놓은 자리 번호를 돌려준다
```

#### 1. 문제를 고정하고 첫 순위를 매긴다

첫 조각은 준비입니다. 답 배열은 자리 번호를 그대로 담아 두고, 길이 1 조각의 순위는 글자
코드로 둡니다.

```ts
const n = s.length;
let sa = Array.from({ length: n }, (_, i) => i);
// ① 길이 1 조각의 순위는 글자 코드를 그대로 쓴다. 대소 관계가 사전순과 같으면 충분하다.
let rank = Array.from({ length: n }, (_, i) => s.charCodeAt(i));
let span = 128;
```

`①` 이 글자 코드를 그대로 쓰는 것에 이유가 있어요. 순위가 `0`·`1`·`2` 처럼 빈틈없이 이어질
필요가 없고, **대소 관계와 같음 관계만 사전순과 맞으면** 됩니다. `a` 가 97 이고 `b` 가 98 이라
글자 코드의 대소가 곧 알파벳 순서예요. `span` 을 128 로 두는 것은 계수 정렬이 잡을 칸 수를
글자 코드 범위로 잡아 두는 것입니다.

<!--proof:walk-init-->

```text

1  a                      97
2  n                     110
3  a                      97

sa = [0, 1, 2, 3, 4, 5]   아직 정렬 전이라 자리 번호 그대로다
```

여기까지가 T1 입니다. `sa` 는 아직 아무 뜻이 없고 `rank` 만 값을 들고 있어요.

#### 2. 뒤 조각의 순위를 붙여 쌍을 만든다

둘째 조각은 키 만들기입니다. 자리마다 앞 조각의 순위와 뒤 조각의 순위를 이어 쌍을 만들어요.

```ts
const front = (i: number): number => rank[i] as number;
// ② 뒤 조각의 순위. 문자열 끝을 넘으면 0 을 두어 같은 앞 조각 안에서 맨 앞에 오게 한다.
const back = (i: number): number =>
  i + gap < n ? (rank[i + gap] as number) + 1 : 0;
```

`②` 가 `+ 1` 을 붙이는 것과 `: 0` 을 두는 것이 한 쌍입니다. 실제 순위를 1 씩 올려 0 을 비워
두고, 뒤 조각이 없는 자리에 그 0 을 줘요. 그러면 같은 앞 조각을 가진 무리 안에서 **뒤 조각이
없는 자리가 언제나 맨 앞**이 됩니다.

`s[1..2]` 와 `s[3..4]` 가 둘 다 `an` 이라는 뜻이에요. 이 둘은 이 바퀴에서 안 갈립니다.

크게 처리하자」로 읽기 쉬워요 — 그러면 그 자리가 같은 앞 조각 무리의 맨 뒤로 갑니다. 그 생각

#### 3. 계수 정렬 두 번으로 쌍을 정렬한다

셋째 조각은 정렬입니다. 쌍을 사전식으로 늘어놓아야 하는데, 두 성분 다 값이 `0` 이상 `span`
이하의 정수라 계수 정렬을 쓸 수 있어요. **뒤 성분으로 먼저, 앞 성분으로 나중**에 걸고 둘 다
안정이어야 합니다.

```ts
// ③ 뒤 조각으로 먼저 안정 정렬하고, 그 결과를 앞 조각으로 다시 안정 정렬한다.
for (const key of [back, front]) sa = countingSortBy(sa, key, span + 1);
```

```ts
function countingSortBy(
  order: number[],
  key: (i: number) => number,
  span: number,
): number[] {
  const count = new Array<number>(span).fill(0);
  for (const i of order) count[key(i)] = (count[key(i)] as number) + 1;
  for (let v = 1; v < span; v++) {
    count[v] = (count[v] as number) + (count[v - 1] as number);
  }
  const out = new Array<number>(order.length).fill(0);
  for (let p = order.length - 1; p >= 0; p--) {   // 뒤에서부터 놓아야 안정이다
    const i = order[p] as number;
    const k = key(i);
    count[k] = (count[k] as number) - 1;
    out[count[k] as number] = i;
  }
  return out;
}
```

T3 과 T4 가 이 두 번입니다. T3 은 뒤 성분 `[98, 111, 98, 111, 98, 0]` 으로 `[5, 0, 2, 4, 1, 3]`
을 만들고, T4 는 앞 성분 `[98, 97, 110, 97, 110, 97]` 으로 그 줄을 다시 늘어놓아
`[5, 1, 3, 0, 2, 4]` 를 만들어요.

```text

   T4 의 무리 안에 남는 것, 그것이 안정 정렬의 값이다
```

#### 4. 같은 쌍끼리 묶어 새 순위를 매긴다

넷째 조각은 순위 재부여입니다. 늘어놓은 줄을 왼쪽에서 오른쪽으로 읽으며, 이웃한 두 자리의
쌍이 다를 때만 순위를 하나 올려요.

```ts
const next = new Array<number>(n).fill(0);
let top = 0;
for (let j = 1; j < n; j++) {
  const a = sa[j - 1] as number;
  const b = sa[j] as number;
  // ④ 이웃한 두 자리의 쌍이 다를 때만 순위를 하나 올린다. 같으면 아직 못 가른 것이다.
  if (front(a) !== front(b) || back(a) !== back(b)) top++;
  next[b] = top;
}
rank = next;
span = top + 1;
```

**이웃만 견주는 것으로 충분한 이유**는 줄이 이미 쌍 기준으로 늘어서 있기 때문입니다. 쌍이 같은
자리들은 반드시 서로 붙어 있고, 쌍이 갈리는 자리마다 값을 하나 올리면 그 값이 곧 「앞에 몇
종류의 쌍이 있었는가」예요. 그래서 `top` 의 마지막 값 더하기 1 이 서로 다른 쌍의 개수입니다.

```text
T5 가 하는 일 — 늘어놓은 줄 [5, 1, 3, 0, 2, 4] 를 왼쪽부터

  자리   5        1        3        0        2        4
  쌍     (97,0)   (97,111) (97,111) (98,98)  (110,98) (110,98)
  판정   시작     다르다   같다     다르다   다르다   같다
  top    0        1        1        2        3        3
└ next 에 자리 순서로 담으면 rank = [2, 1, 3, 1, 3, 0] 이고 span 은 4 다
```

#### 6. 전체 코드

다섯 조각을 한 함수로 잇습니다. 앞에서 값으로 확인하지 않은 것이 하나 남아 있는데, 바퀴를
감싸는 `for` 문의 조건 `gap < n` 이에요 — `n` 이 1 이면 이 조건이 처음부터 거짓이라 바퀴가
한 번도 실행되지 않고 `[0]` 이 그대로 답이 됩니다.

```ts
/**
 * 값이 `[0, span)` 안의 정수인 키로 `order` 를 **안정** 정렬한다.
 *
 * 안정이라는 것은 키가 같은 두 자리의 앞뒤가 들어올 때의 앞뒤와 같다는 뜻이다. 이 성질이
 * 없으면 뒤 조각으로 매겨 둔 순서가 앞 조각 정렬에서 지워진다.
 */
function countingSortBy(
  order: number[],
  key: (i: number) => number,
  span: number,
): number[] {
  const count = new Array<number>(span).fill(0);
  for (const i of order) count[key(i)] = (count[key(i)] as number) + 1;
  for (let v = 1; v < span; v++) {
    count[v] = (count[v] as number) + (count[v - 1] as number);
  }
  const out = new Array<number>(order.length).fill(0);
  for (let p = order.length - 1; p >= 0; p--) {
    const i = order[p] as number;
    const k = key(i);
    count[k] = (count[k] as number) - 1;
    out[count[k] as number] = i;
  }
  return out;
}

export function suffixArray(s: string): number[] {
  const n = s.length;
  let sa = Array.from({ length: n }, (_, i) => i);
  // ① 길이 1 조각의 순위는 글자 코드를 그대로 쓴다. 대소 관계가 사전순과 같으면 충분하다.
  let rank = Array.from({ length: n }, (_, i) => s.charCodeAt(i));
  let span = 128;

  for (let gap = 1; gap < n; gap *= 2) {
    const front = (i: number): number => rank[i] as number;
    // ② 뒤 조각의 순위. 문자열 끝을 넘으면 0 을 두어 같은 앞 조각 안에서 맨 앞에 오게 한다.
    const back = (i: number): number =>
      i + gap < n ? (rank[i + gap] as number) + 1 : 0;

    // ③ 뒤 조각으로 먼저 안정 정렬하고, 그 결과를 앞 조각으로 다시 안정 정렬한다.
    for (const key of [back, front]) sa = countingSortBy(sa, key, span + 1);

    const next = new Array<number>(n).fill(0);
    let top = 0;
    for (let j = 1; j < n; j++) {
      const a = sa[j - 1] as number;
      const b = sa[j] as number;
      // ④ 이웃한 두 자리의 쌍이 다를 때만 순위를 하나 올린다. 같으면 아직 못 가른 것이다.
      if (front(a) !== front(b) || back(a) !== back(b)) top++;
      next[b] = top;
    }
    rank = next;
    span = top + 1;

    // ⑤ 순위가 전부 달라졌으면 조각을 더 늘려도 순서가 안 바뀐다.
    if (span === n) break;
  }
  return sa;
}
```

```text
suffixArray("aaaa")         ->  [3, 2, 1, 0]
suffixArray("abc")          ->  [0, 1, 2]
suffixArray("a")            ->  [0]
```

### 알아 두면 좋은 개념 — 분할 정련

전개의 `rank` 배열이 한 일에는 이미 이름이 있습니다. 순위 배열은 자리 `n` 개를 **같은 순위끼리
묶은 무리**로 나눈 것이고, 바퀴마다 그 무리가 더 잘게 갈립니다. 한 번 갈린 자리들이 다시
합쳐지는 일은 없어요 — 갈렸다는 것은 조각이 이미 다르다는 뜻이고, 조각을 더 늘려도 다른 것이
같아지지는 않으니까요. **이미 나눠 둔 무리를 조건 하나로 더 잘게 나누기만 하는 절차**를 분할
정련이라고 부릅니다.

<!--proof:related-refine-->

```text

T1                 1        3  {1,3,5} {0} {2,4}
T5                 2        4  {5} {1,3} {0} {2,4}
T9                 4        6  {5} {3} {1} {0} {4} {2}
```

무리 수가 3 → 4 → 6 으로 늘기만 하고, 어느 걸음에서도 두 무리가 하나로 합쳐지지 않습니다.
T9 에서 `{1,3}` 과 `{2,4}` 가 각각 둘로 갈리는 것이 마지막 갈림이고, 무리 수가 `n` 이 되면 더
갈릴 것이 없어 절차가 멈춰요. 이 글의 종료 조건 `span === n` 은 「무리 수가 자리 수와 같다」를
그대로 적은 것입니다.

```text
같은 방식이 나오는 다른 자리
  유한 상태 기계 최소화   같은 상태로 묶어 두고 전이가 갈리는 무리를 쪼갠다
  그래프 색칠 다듬기      같은 색으로 시작해 이웃의 색 목록이 다르면 색을 나눈다
  DFA 등가 판정           두 기계의 상태를 한 무리에 넣고 갈리는 자리를 찾는다
└ 셋 다 "무리는 잘게만 갈린다" 는 성질 하나로 멈추는 시점이 정해진다
```

## 파트 2 — 적용 조건 · 보장 · 비용

여기서는 파트 1 이 세운 절차를 네 각도에서 따집니다 — 어느 문제 모양에 이것이 답인가, 순위와
쌍을 식으로 적으면 무엇이 새로 나오는가, 매 바퀴 참으로 남는 문장이 무엇인가, 자료 접근이
몇 번인가.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **문자열 하나가 고정되어 있고 그 위의 물음이 여럿**입니다. 접미사 배열은 전처리이고, 만들어
  두면 부분 문자열 찾기·가장 긴 되풀이 조각·서로 다른 부분 문자열 세기가 모두 그 위에서 풀려요.
- **최악 보장이 필요합니다.** 어떤 문자열이 들어와도 값의 차수가 `n log n` 을 넘지 않아야
  하는 자리예요.
- **글자 집합이 작습니다.** 계수 정렬의 칸 배열이 처음 한 바퀴에 글자 코드 범위만큼 잡히므로,
  그 값이 `n` 에 묻힐 만큼 작아야 합니다.
- **구현을 짧게 유지해야 합니다.** 이 절차는 계수 정렬 하나와 그것을 되풀이하는 루프 하나로
  끝나요. 재귀도, 별도 자료구조도 없습니다.

```text
네 조건이 코드의 모양을 그대로 정한다
  문자열이 고정이다     -> 한 번 만들어 두고 여러 물음에 쓴다
  최악 보장이 필요      -> 입력의 되풀이 정도에 값이 안 달리게 한다
  글자 집합이 작다      -> 계수 정렬의 칸 배열이 n 에 묻힌다
  구현을 짧게           -> 재귀도, 별도 자료구조도 쓰지 않는다
```

| 무엇을 묻는가 | 무엇을 쓰는가 | 왜 |
| --- | --- | --- |
| 고정된 문자열에 부분 문자열 물음이 여럿 | 접미사 배열 | 한 번 만들어 두고 이분 탐색으로 답한다 |
| 패턴 하나가 나오는 자리 전부 | 실패 함수 방식 | 전처리가 패턴 길이에 비례한다 |
| 패턴 수백 개를 한 번에 | 여러 패턴용 자동 장치 | 텍스트를 한 번만 읽는다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "문자열이 주어지고 질의가 Q 개"  "같은 문자열에 여러 번"   <- 전처리를 한 번만 하면 된다
  "가장 긴 반복되는 부분 문자열"                             <- 접미사를 사전순으로 늘어놓아야 한다
  "서로 다른 부분 문자열의 개수"                             <- 접미사 배열과 공통 앞부분 길이가 재료다
  "사전순으로 k 번째"                                        <- 순서 자체가 답이다

제약에 이런 모양이 보이면
  |s| 가 10^5 이고 O(n log n) 을 요구한다
  글자가 소문자 영문으로 한정된다
  같은 글자가 길게 이어질 수 있다고 적혀 있다

반대로 이런 말이 보이면 해당하지 않는다
  "패턴 하나의 등장 위치"                                    <- 텍스트를 한 번 지나가는 절차가 더 적다
  "문자열이 계속 바뀐다"  "글자를 삽입·삭제한다"             <- 바뀔 때마다 다시 만들어야 한다
  "두 문자열의 편집 거리"  "가장 비슷한 조각"                <- 글자가 어긋나는 것을 허용하는 문제다
```

두 번째 무리의 마지막 줄이 이 절차의 한계입니다. 접미사 배열은 문자열이 고정이라는 것에 통째로
기대고 있어서, 글자 하나가 바뀌면 순위 배열 전체를 다시 만들어야 해요. 패턴 하나만 찾으면
되는 자리는 [`findAllOccurrences`](../findAllOccurrences/findAllOccurrences-problem.md) 쪽이고,
패턴이 여럿이면 [`ahoCorasick`](../ahoCorasick/ahoCorasick-problem.md) 쪽입니다.

#### 실제로 쓰이는 곳

- **바이너리 차분 도구 `bsdiff`.** 콜린 퍼시벌이 2003–2005 년에 쓴 것이고
  ([프로젝트 쪽](https://www.daemonology.net/bsdiff/), 조회 2026-09-04) 소개 문장이
  *"bsdiff and bspatch are tools for building and applying patches to binary files"* 입니다.
  소스의 `qsufsort` 함수가 **이 글과 같은 바퀴 구조**예요 — 바깥 루프가
  `for(h=1;I[0]!=-(oldsize+1);h+=h)` 라 조각 길이 `h` 를 `h+=h` 로 두 배씩 늘리고, 시작값을
  `for(i=0;i<oldsize;i++) V[i]=buckets[old[i]];` 로 글자 통 번호에서 가져옵니다. 이 글의
  `gap` 이 거기서는 `h` 이고 `rank` 가 `V` 예요. 다만 무리를 가르는 방식은 다릅니다 — 그쪽은
  계수 정렬이 아니라 `split(int64_t *I,int64_t *V,int64_t start,int64_t len,int64_t h)` 이라는
  재귀 분할을 씁니다.
  ([`bsdiff.c`](https://github.com/mendsley/bsdiff/blob/master/bsdiff.c), 조회 2026-09-04)
- **크로미움의 바이너리 차분 부품 `zucchini`.** `components/zucchini/suffix_array.h` 가 접미사
  배열 만들기를 두 가지로 싣습니다 — 주석이 *"the naive suffix sorting algorithm that uses
  std::sort with lexicographic compare"* 와 *"suffix array induced sorting (SA-IS) algorithm
  with linear time and memory complexity"* 라 적어요. 크롬 업데이트의 차분 패치가 이것을 씁니다.
  ([`components/zucchini/suffix_array.h`](https://chromium.googlesource.com/chromium/src/+/HEAD/components/zucchini/suffix_array.h),
  조회 2026-09-04)
- **압축기 `zstd` 의 사전 학습기.** `lib/dictBuilder/zdict.c` 가
  `int const divSuftSortResult = divsufsort((const unsigned char*)buffer, (int*)suffix, (int)bufferSize, 0);`
  로 입력 전체의 접미사 배열을 만든 뒤, 사전순으로 이웃한 자리들에서 자주 나오는 조각을 찾아
  사전에 담습니다.
  ([`lib/dictBuilder/zdict.c`](https://github.com/facebook/zstd/blob/dev/lib/dictBuilder/zdict.c),
  조회 2026-09-04)

```text
셋이 접미사 배열에 기대는 자리
  bsdiff    옛 파일의 모든 자리를 사전순으로 늘어놓고 새 파일의 조각을 이분 탐색으로 찾는다
  zucchini  같은 일을 하되 만들기를 선형 시간 절차로 바꿨다
  zstd      이웃한 접미사들이 공유하는 앞부분에서 자주 나오는 조각을 뽑는다
└ 셋 다 "문자열이 고정이고 물음이 여럿" 이라는 모양이다
```

#### 경쟁 설계와의 대조

같은 답(접미사 배열)을 내는 다른 절차로 **갈라 정렬**(DC3, Kärkkäinen–Sanders skew)이
있습니다. 자리를 3 으로 나눈 나머지로 갈라, 나머지가 1 과 2 인 자리들을 세 글자 묶음으로 이름
붙여 **재귀로** 정렬한 뒤, 나머지가 0 인 자리를 그 결과에서 유도해 두 줄을 합치는 방식이에요.
바퀴를 되풀이하지 않으므로 입력이 얼마나 되풀이되는지와 상관없이 값이 정해집니다.

```text
두 설계가 조각을 늘리는 방식
  배가 기법   길이 1 -> 2 -> 4 -> ... 순위가 전부 갈릴 때까지 바퀴를 되풀이한다
  갈라 정렬   자리를 3 으로 나눠 3 분의 2 를 재귀로 정렬하고 나머지를 유도해 합친다
└ 위쪽은 바퀴 수가 입력에 달렸고, 아래쪽은 입력과 상관없이 재귀 깊이가 log 3/2 n 이다
```

같은 생성식으로 만든 문자열에 두 설계를 걸고 **자료 접근**을 셌습니다. 문자열은 mulberry32
난수(씨앗 `0x9e3779b9`)로 만든 소문자 26 글자짜리이고, **길이 `n` 하나만** 바꿉니다.
**전개 입력(여섯 글자)을 그대로 쓰지 않은 이유**는 그 규모에서는 두 설계의 값이 계수 정렬 칸
배열 같은 상수 항에 묻혀 갈리지 않기 때문이에요.

| 입력 | 배가 기법 | 갈라 정렬 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 무작위 26 글자 `n` = 90 | 5,992 | **3,757** | 갈라 정렬이 1.59 배 적습니다 |
| 무작위 26 글자 `n` = 91 | **6,047** | 6,654 | **여기서 순서가 뒤집힙니다** |
| 무작위 26 글자 `n` = 1,039 | **60,047** | 73,999 | 배가가 1.23 배 적습니다 |
| 무작위 26 글자 `n` = 1,040 | 92,324 | **74,008** | **여기서 순서가 뒤집힙니다** |
| 무작위 26 글자 `n` = 100,000 | 8,563,020 | **6,639,408** | 갈라 정렬이 1.29 배 적습니다 |
| 전부 같은 글자 `n` = 100,000 | 46,262,802 | **11,353,439** | 갈라 정렬이 4.07 배 적습니다 |

**순서가 두 번 뒤집힙니다.** 아래쪽 경계는 `n` = 90 과 91 사이인데, 거기서는 **갈라 정렬**의
값이 3,757 에서 6,654 로 77 % 뛰어요 — 재귀가 한 단 깊어지는 자리입니다. 위쪽 경계는 1,039 와
1,040 사이이고 이번에는 **배가 기법**의 값이 54 % 뜁니다. 갈라 정렬은 그 한 글자에 0.01 % 만
늘어요. 배가 기법이 그 자리에서 **바퀴를 두 번에서 세 번으로** 늘리기 때문입니다 — 길이 1,040
부터는 앞 네 글자가 같은 접미사 짝이 생겨 길이 4 조각으로는 안 갈립니다.

```text
경계가 그 자리인 이유
  n = 1,039  앞 네 글자가 다 다르다         바퀴 두 번으로 끝난다    60,047
  n = 1,040  앞 네 글자가 같은 짝이 생긴다  바퀴가 세 번이 된다      92,324
  갈라 정렬  바퀴라는 것이 없다             재귀 깊이만 log 로 는다  73,999 -> 74,008
└ 배가 기법의 값은 계단으로 뛰고, 갈라 정렬의 값은 매끄럽게 는다
```

「길이 4 조각으로는 안 갈린다」도 산문으로 두지 않고 세 봅니다.

<!--proof:alt-boundary-->

```text
같은 생성식(mulberry32 · 알파벳 26 글자)의 문자열에서
    n  길이 4 조각이 같은 자리 짝  가장 긴 공통 앞부분  배가 기법 바퀴 수
1,039                           0                    3                  2
1,040                           1                    4                  3

└ 1,040 에서 길이 4 조각이 같은 짝이 처음 생긴다. 그래서 바퀴가 하나 늘어난다
```

**갈라 정렬이 늘 적은 것은 아닙니다.** 잡는 칸은 반대로 갈려요.

| 축 | 배가 기법 | 갈라 정렬 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 동시에 잡는 칸의 최댓값 (`n` = 100,000) | **389,908** | 550,535 | 배가가 1.41 배 적습니다 |

갈라 정렬은 재귀 단계마다 배열 넷을 새로 잡고 그것이 바닥까지 살아 있어야 해서, 잡는 칸이
`n` 의 5.5 배로 쌓입니다. 배가 기법은 어느 시점에도 배열 넷(`sa`·`rank`·다음 순위·계수 칸)만
살아 있어서 `n` 의 3.9 배에서 멈춰요.

```text
이 절차가 내주는 것과 얻는 것
  내주는 것   되풀이가 심한 문자열에서의 자료 접근   전부 같은 글자에서 4.07 배 많다
  얻는 것 1   잡는 칸                                1.41 배 적다
  얻는 것 2   구현 길이                              재귀도 없고 배열도 넷뿐이다
  얻는 것 3   n 이 91 부터 1,039 까지면 자료 접근도 적다
└ 되풀이가 심한 큰 입력이 실제로 들어오는 자리라면 갈라 정렬 쪽이 답이다
```

이 문제의 제약은 `n` 이 10 만이고 `a` 만 10 만 개인 입력을 허용하므로, **자료 접근만 보면 갈라
정렬이 낫습니다.** 그럼에도 이 글이 배가 기법을 가르치는 이유는 얻는 것 셋에 있어요 — 특히 이
문제는 1 초 안에 4,626 만 번을 끝내면 되는 자리라 두 설계가 다 통과하고, 그때 남는 기준은 잡는
칸과 구현 길이입니다. **같은 지문에서 문자열이 훨씬 길어지거나 되풀이가 훨씬 심해지면 이 판정은
다시 해야 해요.**

### 수식 정의와 유도

길이 `L` 조각의 **순위**를 정의합니다. 자리 `i` 의 길이 `L` 조각을 $b_L(i)$ 라고 적을게요 —
문자열 끝을 넘으면 남은 만큼만 잘라 씁니다.

$$b_L(i) = s[i \ldots \min(i+L-1,\ n-1)] \qquad r_L(i) = \bigl|\{\, b_L(j) : 0 \le j < n,\ b_L(j) < b_L(i) \,\}\bigr|$$

```text
식을 읽는 법
  L          조각 길이. 바퀴마다 두 배가 된다
  b_L(i)     자리 i 에서 L 글자를 잘라 낸 것. 끝을 넘으면 남은 만큼만이다
  r_L(i)     b_L(i) 보다 사전순으로 앞인 조각이 몇 종류인가
             └ 같은 조각은 한 번만 세므로 같은 조각을 가진 자리는 같은 값을 받는다
```

정의가 실제로 그 값을 내는지부터 봅시다. `s = banana` 에서 `L` 을 1·2·4 로 두고 조각을 손으로
나열한 뒤 정의대로 세면, 그 값이 전개의 `rank` 와 같아야 해요.

<!--proof:math-check-->

```text
k  조각 길이 2^k  s[i..i+2^k-1]            정의대로 매긴 순위  서로 다른 조각 수
0              1  b a n a n a              [1, 0, 2, 0, 2, 0]                  3
1              2  ba an na an na a         [2, 1, 3, 1, 3, 0]                  4
2              4  bana anan nana ana na a  [3, 2, 5, 1, 4, 0]                  6

└ 조각이 문자열 끝을 넘으면 남은 만큼만 잘라 쓴다. 짧은 조각이 언제나 앞이다
```

`k` 가 1 과 2 인 줄은 전개의 T5·T9 가 낸 `rank` 와 글자 그대로 같습니다. `k` 가 0 인 줄만
다른데, 정의는 `[1, 0, 2, 0, 2, 0]` 이고 코드는 글자 코드 `[98, 97, 110, 97, 110, 97]` 이에요.
**둘은 값이 다르지만 대소 관계와 같음 관계가 같습니다.** 아래 유도가 쓰는 것이 그 두 관계뿐이라
어느 쪽을 넣어도 정렬 결과가 같고, 값이 빈틈없이 이어져야 하는 것은 종료 판정 하나뿐인데 그
판정은 첫 재부여 뒤부터 실행됩니다.

```text
정의가 담는 두 관계
  대소   r_L(i) < r_L(j)    <=>   b_L(i) 가 b_L(j) 보다 사전순으로 앞이다
  같음   r_L(i) = r_L(j)    <=>   b_L(i) 와 b_L(j) 가 글자까지 같다
└ 값이 빈틈없이 이어지는가는 이 둘과 상관없다. 글자 코드가 첫 바퀴에 그대로 쓰이는 근거다
```

이제 유도합니다. 첫째로 **쌍 견주기가 조각 견주기와 같다**는 것입니다. 자리 `i` 의 길이 `2L`
조각은 앞 `L` 글자와 뒤 `L` 글자로 정확히 갈리므로, 두 자리 `i`·`j` 를 견주는 일은 앞 반쪽을
견주고 같으면 뒤 반쪽을 견주는 일과 같아요.

$$b_{2L}(i) < b_{2L}(j) \iff \bigl(r_L(i),\ r_L(i+L)\bigr) < \bigl(r_L(j),\ r_L(j+L)\bigr) \text{ (사전식)}$$

```text
두 경우로 갈라 확인한다
  앞 반쪽이 다르다   b_L(i) != b_L(j)     r_L 이 다르므로 첫 성분에서 정해진다
  앞 반쪽이 같다     b_L(i) == b_L(j)     r_L 이 같으므로 둘째 성분이 정한다
                     └ 둘째 성분은 b_L(i+L) 과 b_L(j+L) 의 순위다
  뒤 반쪽이 없다     i+L >= n             조각이 앞 반쪽에서 끝난다. 짧은 쪽이 앞이므로
                     가장 작은 값을 준다. 코드는 0 을 비워 두고 그것을 쓴다
```

이 사실이 바퀴 하나를 정당하게 만듭니다. 그리고 여기서 **바퀴 수의 상한**이 나와요. 조각 길이가
`1, 2, 4, …` 로 가다가 `L ≥ n` 이 되면 조각이 접미사 전체를 덮고, 접미사는 서로 길이가 달라
같은 것이 없으므로 순위가 전부 달라집니다.

$$R(n) \le \lceil \log_2 n \rceil$$

```text
상한을 값에 넣으면
  n = 6        ⌈log2 6⌉ = 3      전개 입력은 두 바퀴로 끝났으니 상한 안이다
  n = 100,000  ⌈log2 100,000⌉ = 17
└ 상한은 조각 길이가 n 을 덮는 시점이고, 순위가 그전에 다 갈리면 더 일찍 멈춘다
```

<!--proof:math-rounds-->

```text
      n  ⌈log2 n⌉  실측 바퀴 수   자료 접근
     10         4             4       1,858
    100         7             7      19,974
  1,000        10            10     273,748
 10,000        14            14   3,823,444
100,000        17            17  46,262,802
```

전부 같은 글자에서는 실측 바퀴 수가 상한과 정확히 같습니다. 이 상한이 뜻하는 것은 **임의의
문자열에서** 바퀴 수가 `⌈log₂ n⌉` 을 넘지 않는다는 것이고, 제약 최댓값에서 그 값이 17 이에요.
본문이 잰 다섯 값만으로는 나오지 않는 진술입니다.

```text
바퀴 수를 더 줄이려면 배수를 키워야 하는데, 그러면 다른 항이 는다
  바퀴 수                ⌈log_m n⌉  m 이 커지면 준다
  바퀴 하나의 정렬 횟수  m          m 이 커지면 는다
└ 둘의 곱이 정렬 횟수의 총합이다. 한쪽만 보면 m 을 키우는 것이 언제나 이득으로 보인다
```

셋째로 **한 바퀴에 늘리는 배수의 최적값**을 닫습니다. 배수를 `m` 으로 하면 키가 성분 `m`
개짜리라 바퀴마다 계수 정렬이 `m` 번이고, 조각 길이가 `m` 배씩 가므로 바퀴 수가
`⌈log_m n⌉` 입니다. 정렬 횟수의 총합을 `P(m)` 이라 하면 이렇게 돼요.

$$P(m) = m \left\lceil \log_m n \right\rceil \approx \frac{m}{\ln m} \ln n \qquad \frac{d}{dm}\left(\frac{m}{\ln m}\right) = \frac{\ln m - 1}{(\ln m)^2}$$

```ts
// 식을 그대로 옮긴 조각. 실제 절차는 m = 2 를 박아 둔 것이다.
const passes = (m: number, n: number): number =>
  m * Math.ceil(Math.log(n) / Math.log(m));
```

미분값이 0 이 되는 자리는 `ln m = 1`, 곧 `m = e` 입니다. 그보다 작으면 미분값이 음수라 줄고,
크면 양수라 늘어요. `e` 는 정수가 아니므로 최솟값에 가장 가까운 정수는 그 자리를 사이에 둔
2 와 3 이고, 4 부터는 `m` 이 커질수록 값이 계속 늡니다.

<!--proof:math-optimum-->

```text

 2     2.885                 34      46,262,802
 3     2.731                 33      42,807,740
 4     2.885                 36      45,463,602
 5     3.107                 40               —
 8     3.847                 48      57,491,052
16     5.771                 80      93,002,186

m / ln m 이 가장 작은 실수는 m = e = 2.718 이고, 그 값은 2.718 이다
정수는 2 와 3 이 그 자리를 사이에 두고 있어 2.885 과 2.731 으로 5.6 % 안에 모인다
```

닫힌 형태가 실측의 모양을 그대로 맞춥니다 — `m` 이 2·3·4 일 때 `m/ln m` 이 2.885·2.731·2.885
로 가운데가 가장 작고, 자료 접근도 같은 모양이에요. `m = 4` 가 `m = 2` 와 `m/ln m` 값이
정확히 같은 것도 실측에서 46,262,802 대 45,463,602 로 1.8 % 안에 들어 맞습니다.

### 불변식 — 바퀴가 끝난 시점의 순위는 그 길이 조각의 사전순 대소와 같음을 그대로 담는다

파트 1 은 여섯 글자짜리 문자열 하나에서 답이 나오는 것까지 보였습니다. 그것은 그 입력에서
맞았다는 뜻이지 어떤 입력에서도 맞는다는 뜻이 아니에요. 무엇이 **매 바퀴 참으로 남는지**를 문장으로 세우고 그것이
실제로 유지되는지 확인해 봅시다.

> `gap` 이 `L` 인 바퀴가 끝난 직후, 모든 자리 짝 `(i, j)` 에 대해 `rank[i] < rank[j]` 인 것과
> `s` 의 자리 `i` 에서 잘라 낸 길이 `2L` 조각이 자리 `j` 의 것보다 사전순으로 앞인 것이 서로
> 필요충분입니다. 그리고 `rank[i] === rank[j]` 인 것과 두 조각이 **같은** 것이 서로
> 필요충분이에요.

```text
두 관계를 다 담아야 하는 이유
  대소만 담으면  다음 바퀴가 "앞 반쪽이 같다" 를 판정할 수 없다
  같음만 담으면  정렬이 순서를 못 정한다
└ 문장이 참이 되는 시점은 "바퀴가 끝난 직후" 다. 바퀴 도중에는 정렬만 끝나고
   순위가 아직 옛 값이라 두 관계가 잠깐 어긋난다
```

**출발점부터 봅시다.** 첫 바퀴에 들어가기 전 `rank[i]` 는 글자 코드이고, 글자 코드의 대소가
알파벳 순서이며 같은 글자면 같은 코드입니다. 그래서 `L = 1` 짜리 조각에 대해 두 관계가 다
참이에요.

| 걸음 | 하는 일 | 두 관계가 유지되는 근거 |
| --- | --- | --- |
| 시작 | 글자 코드를 순위로 둔다 | 코드의 대소가 알파벳 순서이고 같은 글자면 같은 코드다 |
| 쌍 만들기 | `(front, back)` 을 붙인다 | 앞 반쪽·뒤 반쪽의 순위가 각각 그 반쪽의 관계를 담고 있다 |
| 정렬 두 번 | 뒤·앞 순서로 안정 정렬 | 쌍의 사전식 순서로 늘어선다 |
| 재부여 | 이웃 쌍이 다를 때만 올린다 | 쌍이 같으면 같은 값, 다르면 큰 값을 받는다 |
| 종료 | `span === n` 이면 멈춘다 | 순위가 전부 다르면 조각을 늘려도 관계가 안 바뀐다 |

넷째 줄이 이 논증의 핵심입니다. 늘어선 줄에서 이웃만 견주어도 되는 것은 **같은 쌍을 가진
자리들이 반드시 붙어 있기** 때문이에요 — 줄이 쌍 기준으로 늘어서 있으므로 같은 쌍이 떨어져
있으면 그 사이에 그 쌍보다 크고 작은 쌍이 동시에 있어야 하는데, 그런 값은 없습니다.

<!--proof:invariant-rounds-->

```text

└ 모든 자리 쌍 (i, j) 에 대해 순위의 대소·같음이 조각의 사전순 대소·같음과 맞는지 전수로 확인했다
```

초기값 `[0]` 그대로 나가요. 전부 다른 글자는 반대쪽 경계로, 첫 바퀴의 재부여에서 `span` 이
바로 `n` 이 되어 한 바퀴로 끝납니다.

**이제 깨뜨려 봅시다.** 두 관계를 지키던 줄은 재부여의 판정 한 줄이에요. 「어차피 정렬이 끝난
줄이니 앞 성분만 견주어도 순서는 그대로겠다」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
if (front(a) !== front(b)) top++;   // 뒤 성분을 안 견줬다
```

### 비용 계산

#### 비용을 세는 과정

실행 한 번을 두 무리로 가릅니다. 글자를 읽어 첫 순위를 매기는 자리가 하나이고, 그다음은
바퀴를 되풀이하는 자리예요. 전개의 아홉 걸음에 각각 얼마가 들었는지 세 봅니다.

<!--proof:perf-count-->

```text
전개 입력 "banana" (n = 6)
무리            걸음     자료 접근
첫 순위 매기기  T1               6
1 번째 바퀴     T2 ~ T5        916
2 번째 바퀴     T6 ~ T9        168
합계            T1 ~ T9      1,090

└ 바퀴 하나가 900 을 넘는데 n 은 6 이다. 계수 정렬의 칸 배열이 첫 바퀴에는
   글자 코드 범위 129 칸이라 그 항이 n 을 압도한다

입력                  n  바퀴 수 R   자료 접근  바퀴 하나당 n 의 몇 배
무작위 26 글자  100,000          3   8,563,020                    28.5
전부 같은 글자  100,000         17  46,262,802                    27.2

└ n 이 커지면 바퀴 하나가 n 의 스물일곱 배 언저리로 모인다. 갈리는 것은 바퀴 수뿐이다
```

첫 바퀴(T2~T5)가 둘째 바퀴(T6~T9)의 다섯 배가 넘는 것이 여섯 글자짜리 입력의 특징입니다. 첫
바퀴의 계수 정렬은 글자 코드 범위인 129 칸을 잡고 그 칸을 누적합으로 한 번 지나가는데, 둘째
바퀴는 `span` 이 4 라 5 칸만 잡아요. 글자 집합 크기를 `Σ` 라고 하면 첫 바퀴에만 `Σ` 항이
붙습니다.

```text
총식 = 첫 순위      +  바퀴 R 번
       └ 글자 n 번     └ 계수 정렬 두 번 + 순위 재부여 한 번

  계수 정렬 한 번  세기 4n + 누적합 3·span + 되놓기 6n               = 10n + 3·span
  재부여 한 번     자리마다 sa 두 칸 · 쌍 네 값 · next 한 칸         = 7n 이하
  바퀴 하나        계수 정렬 두 번 + 재부여 한 번                    = 27n + 6·span 언저리
                   span <= n 이고 첫 바퀴만 그 자리에 Σ 가 들어간다  (이 문제에서 Σ = 128)
└ 위 표의 실측이 바퀴 하나당 n 의 27.2 배와 28.5 배다. 세어 적은 27n 과 맞는다
   n = 100,000 · R = 17 이면 4,626 만 번이고, 잡는 칸은 3n + span 으로 실측 389,908 이다
```

여기서 센 것은 배열 칸 읽기·쓰기와 글자 읽기 전부입니다. 안 센 것은 자리 번호를 하나 올리는
일과 두 정수를 견주는 일인데, 둘 다 자료 접근 수에 비례하므로 총식의 차수가 그대로예요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 글자가 전부 다르다) | `O(n + Σ)` | `Θ(n + Σ)` — 바퀴가 한 번이다 |
| **평균적인 경우** (글자를 균등하게 뽑는다고 두면) | `O(n log log n)` | 타이트한 값은 확인 안 함 |
| **최악의 경우** (전부 같은 글자) | `O(n log n)` | `Θ(n log n)` — 실제로 도달한다 |

세 줄이 다른 것이 이 절차의 성질입니다. 바퀴 수가 「접미사 짝이 앞부분을 얼마나 길게
공유하는가」에 달렸고, 그 값이 입력마다 달라요.

```text
바퀴 수 R 이 무엇으로 정해지는가 — 가장 긴 공통 앞부분 길이를 K 라 하면
R 은 ⌈log2 (K+1)⌉ 언저리다

  첫 글자가 전부 다르면   K = 0              R = 1
  전부 같은 글자면        K = n − 1          R = ⌈log2 n⌉ 이고 이것이 상한이다
  글자를 균등하게 뽑으면  K 가 log n 언저리  R 이 log log n 언저리다
└ 평균은 입력 분포를 가정해야 정의된다. 이 문제는 분포를 안 주므로 최악만 보장한다
```

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리는 첫 순위 매기기 하나뿐이에요 — 좌표
압축도, 해시도 쓰지 않습니다.

```text
총식 = Θ((n + Σ) · R) 자료 접근 + Θ(n + Σ) 추가 칸
       │                          └ sa · rank · next 각 n 칸과 계수 칸 max(Σ, span) 칸
       └ R <= ⌈log2 n⌉ 이고 Σ 는 글자 코드 범위다

n = 100,000 · Σ = 128 · R = 17 이면 자료 접근 46,262,802 번, 잡는 칸 389,908 개
```

**최악 보장입니다.** 바퀴 수의 상한이 입력의 내용과 상관없이 `⌈log₂ n⌉` 이고, 그 상한을 내는
논증에 확률이 한 글자도 들어가지 않아요. 위 표의 평균 줄에 있는 `log log n` 은 성격이 다릅니다 —
**글자를 균등하게 뽑는다는 입력 분포에 대한 기댓값**이고, 구현이 만드는 무작위성이 아니에요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 길이 `L` 조각의 순위를 이미 알고 있으면 길이
`2L` 조각의 순서는 **순위 두 개를 이어 붙인 쌍**으로 정해지므로, 조각을 두 배씩 늘려 가면 글자를
다시 읽지 않고 `⌈log₂ n⌉` 바퀴 안에 접미사 전체의 순서가 나옵니다.

```text
글자 코드를 순위로 둔다 → 쌍을 만든다 → 계수 정렬 두 번 → 같은 쌍끼리 묶어 순위를 다시 매긴다
└ 글자를 읽는 건 여기뿐   └ 순위 칸 2n 번  └ 첫 바퀴만 Σ 항   └ 순위가 전부 다르면 멈춘다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T5 는 `rank` 를 `[2, 1, 3, 1, 3, 0]` 으로 만든 걸음이고,
자리 1 과 3 이 둘 다 1 이었어요. 그런데 T8 이 낸 줄에서는 자리 3 이 자리 1 보다 앞에 있습니다.
같은 순위였던 둘의 앞뒤를 정한 것은 무엇일까요?

```text
T5 가 끝난 시점    rank[1] = rank[3] = 1     둘 다 an 이라 아직 안 갈렸다
T8 이 낸 줄        [5, 3, 1, 0, 4, 2]        3 이 1 보다 앞이다
```

<!--check:whyThreeFirst-->
둘째 바퀴에서 붙인 **뒤 조각의 순위**입니다. 자리 1 의 뒤 조각은 `s[3..4]` 곧 `an` 이라 순위
1 을 하나 올려 2 를 받고, 자리 3 의 뒤 조각은 `s[5..]` 곧 `a` 라 순위 0 을 하나 올려 1 을 받아요. 쌍이
`(1, 2)` 와 `(1, 1)` 로 갈리고 뒤 성분이 작은 자리 3 이 앞에 옵니다.

```text
길이 4 조각으로 보면
  자리 1  anan                 앞 두 글자 an · 뒤 두 글자 an
  자리 3  ana                  앞 두 글자 an · 뒤는 한 글자 a 뿐이다
  사전순  ana 가 anan 보다 앞  갈리는 자리 없이 앞이 끝나 짧은 쪽이 앞이다
└ 뒤 조각의 순위 0 이 실제 순위 1 보다 작은 값이라 그 규칙이 쌍 견주기로 그대로 옮겨진다
```

같은 자리에서 뒤 조각이 없는 자리에 0 이 아니라 큰 값을 줬다면 순서가 반대가 됩니다.
