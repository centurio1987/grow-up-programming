# 접미사 배열 — 앞 바퀴가 매긴 순위 두 개를 이으면 글자를 다시 읽지 않아도 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 접미사를 글자로
비교해 정렬하는 방법에서 출발해 조각 길이를 두 배씩 늘리는 배가 기법까지 가고, 그 방법을 단계마다 값으로
푼 뒤, 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

문자열의 어느 자리부터 끝까지를 잘라 낸 조각을 **접미사**라고 부릅니다. 자리 `i` 에서 시작하는 접미사를
`s[i..]` 라고 적을게요. 길이 `n` 인 문자열에는 접미사가 정확히 `n` 개 있고, 서로 길이가 달라서 같은
접미사가 둘 있는 일은 없습니다. 이 글이 만드는 **접미사 배열**은 모든 접미사를 사전순으로 늘어놓았을 때
각 접미사가 시작하는 자리 번호를 그 순서대로 담은 배열이에요. 이 글은 이 배열을 끝까지 `sa` 라는 이름
하나로 부릅니다. `s = "banana"` 의 접미사 배열을 문자열 위에 그리면 이렇습니다.

<!--fig:concept-suffixes-->
![banana 의 접미사 배열 — 사전순 k 번째 접미사가 문자열의 어느 자리를 덮는가](./figs/concept-suffixes.svg)

줄 하나가 접미사 하나이고, 위에서 아래로 사전순입니다. `sa[k]` 의 `k` 는 **사전순으로 몇 번째인가**이고,
칸에 든 값은 **문자열의 몇 번째 자리에서 시작하는가**예요. 같은 내용을 표로 적으면 이렇습니다.

<!--proof:concept-banana-->

| 사전순 자리 k | sa[k] | 접미사 s[sa[k]..] | 길이 |
| ---: | ---: | --- | ---: |
| 0 | 5 | a | 1 |
| 1 | 3 | ana | 3 |
| 2 | 1 | anana | 5 |
| 3 | 0 | banana | 6 |
| 4 | 4 | na | 2 |
| 5 | 2 | nana | 4 |

셋째 열을 위에서 아래로 읽으면 사전순이고, 둘째 열을 모은 [5, 3, 1, 0, 4, 2] 이 접미사 배열입니다.

<!--/proof-->

사전순은 두 문자열을 앞에서부터 글자 단위로 비교하다가 처음 다른 글자에서 정해지고, 다른 글자 없이 한쪽이
먼저 끝나면 **짧은 쪽이 앞**입니다. `a` 가 `ana` 보다 앞이고 `ana` 가 `anana` 보다 앞인 것이 그 규칙이에요.
접미사끼리는 길이가 다 달라서 이 둘째 규칙이 언제나 결말을 냅니다.

접미사를 통째로 비교하면 두 접미사가 앞부분을 길게 공유할 때 그 길이만큼 글자를 매번 다시 읽어야 합니다.
이 글의 방법은 접미사를 통째로 비교하지 않고, **자리마다 그 자리에서 시작하는 짧은 조각이 사전순으로 몇
번째 종류인지**를 적어 둡니다. 이 줄을 **순위 배열** `rank` 라고 부르겠습니다. 같은 조각에는 같은 순위가
붙어요. 조각 길이가 2 인 순위 배열을 문자열 위에 그리면 이렇습니다.

<!--fig:concept-rank2-->
![길이 2 조각의 순위 배열 — 자리마다 두 글자를 잘라 사전순 종류 번호를 적는다](./figs/concept-rank2.svg)

자리 1 과 자리 3 은 둘 다 `an` 이라 순위가 같고, 자리 5 는 문자열 끝이라 `a` 한 글자만 남아 가장 앞인 0 을
받습니다. 길이 `L` 조각의 순위를 알고 있으면, 자리 `i` 의 길이 `2L` 조각은 **앞 `L` 글자의 순위 `rank[i]`
와 뒤 `L` 글자의 순위 `rank[i+L]`** 두 수로 정해져요. 두 수를 이은 쌍으로 자리를 다시 늘어놓으면 길이 `2L`
조각의 순위가 나오고, 글자는 다시 읽지 않습니다. 조각 길이를 1 · 2 · 4 · … 로 두 배씩 늘리는 이 방법을
**배가 기법**(prefix doubling)이라고 부릅니다.

<!--proof:concept-cost-->

| 입력 | n | 바퀴 수 | 자료 접근 |
| --- | ---: | ---: | ---: |
| "banana" | 6 | 2 | 1,090 |
| 무작위 26 글자 | 100,000 | 3 | 8,563,020 |
| 전부 같은 글자 | 100,000 | 17 | 46,262,802 |

무작위 26 글자는 mulberry32(씨앗 0x9e3779b9)로 만든 문자열입니다. 바퀴 수가 가장 많은 것은 전부 같은 글자의 17 바퀴입니다.

<!--/proof-->

한 바퀴에 조각 길이가 두 배가 되므로 바퀴 수는 `⌈log₂ n⌉` 을 넘지 않습니다. 바퀴 하나는 쌍을 계수 정렬
두 번으로 늘어놓는 일이라 `n` 에 비례해요. 비용을 결과만 적으면 `O(n log n)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **사전순이 무엇인지.** 앞에서부터 글자를 비교하다 처음 다른 글자로 정하고, 다른 글자 없이 한쪽이 끝나면
  짧은 쪽이 앞입니다. `ab` 는 `abc` 보다 앞이고, `b` 는 `abc` 보다 뒤예요.
- **안정 정렬이 무엇인지.** 키가 같은 두 원소의 앞뒤가 정렬 뒤에도 들어올 때와 같은 정렬입니다. 이 글의
  절차는 그 성질에 통째로 기대고 있어요.
- **계수 정렬이 무엇인지.** 키가 `0` 이상 `K` 미만의 정수일 때 값마다 개수를 세고 누적합으로 자리를 정해,
  두 원소를 비교하지 않고 늘어놓는 정렬입니다. 모르면
  [계수 정렬 가이드](../../sorting/countingSort/countingSort-guide.md)가 그것만 다뤄요.
- **자릿수 정렬이 무엇인지.** 키가 자리 여럿으로 된 값을 낮은 자리부터 한 자리씩 안정 정렬하면 전체 순서가
  나옵니다. 이 글의 쌍 정렬은 자리가 둘인 자릿수 정렬이에요.
  [자릿수 정렬 가이드](../../sorting/radixSort/radixSort-guide.md)가 그 원리를 다룹니다.
- **배열 칸을 번호로 바로 읽는 비용이 배열 길이와 상관없다는 것.** 이 절차는 자리 `i + gap` 의 순위를
  배열에서 바로 꺼내 쓰는데, 그 비용이 `gap` 이 얼마든 같습니다.

이 글이 다루는 것은 **접미사의 순서를 정하는 일 하나**입니다. 그 순서를 얻은 뒤 이웃한 두 접미사가 앞부분을
몇 글자나 공유하는지(최장 공통 접두사)를 구하는 것은 별개의 절차이고,
[카사이 LCP 가이드](../kasaiLcp/kasaiLcp-guide.md)가 그것을 다뤄요. 이 글은 그 값을 만들지도 쓰지도
않습니다.

| 과제 | 다루는 글 |
| --- | --- |
| 접미사를 사전순으로 늘어놓는다 | 이 글 |
| 늘어놓은 뒤 이웃한 둘의 공통 앞부분 길이를 잰다 | [카사이 LCP 가이드](../kasaiLcp/kasaiLcp-guide.md) |
| 패턴 하나가 나오는 자리를 전부 찾는다 | [실패 함수 가이드](../findAllOccurrences/findAllOccurrences-guide.md) |

### 아이디어를 떠올리는 과정 — 글자 비교 정렬에서 배가 기법까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 문자열을 받아 접미사 배열을
돌려줍니다.

```ts
function suffixArray(s: string): number[];
```

- 입력: 소문자 영문(`a`–`z`)으로 된 문자열 `s`.
- 출력: 길이 `n` 인 정수 배열. `k` 번째 칸에 **사전순 `k` 번째 접미사의 시작 자리**를 담습니다. 접미사는
  서로 길이가 달라 같은 것이 없으므로 답은 언제나 하나예요.
- 규모: 문자열 길이 `n` 은 1 이상 100,000 이하이고, 같은 글자가 길게 이어진 문자열도 들어옵니다. 비용은
  흔한 채점 환경의 예산인 1 초 · 256 MB 에 대어 재고, 1 초는 단순 연산 1 억 번으로 잡습니다.

이 글이 끝까지 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `s` | 입력 문자열 | 소문자 영문 |
| `n` | 문자열 길이 | `1 ≤ n ≤ 100,000` |
| `i` | 문자열 안의 자리. 접미사 `s[i..]` 가 시작하는 곳 | `0 ≤ i ≤ n − 1` |
| `k` | 사전순 자리. 접미사 배열의 칸 번호 | `0 ≤ k ≤ n − 1` |
| `sa` | 접미사 배열 | `sa[k]` 가 사전순 `k` 번째 접미사의 시작 자리 |
| `gap` | 순위를 이미 아는 조각의 길이 | 1 에서 시작해 바퀴마다 두 배 |
| `rank` | 순위 배열. `rank[i]` 가 자리 `i` 의 길이 `gap` 조각의 순위 | 칸이 `n` 개 |
| `span` | 순위가 가질 수 있는 값의 개수. 계수 정렬이 잡을 칸 수를 정한다 | 순위가 전부 다르면 `n` |

`s[i..j]` 는 자리 `i` 부터 자리 `j` 까지 양 끝을 담은 조각이고, 문자열 끝을 넘는 부분은 없는 것으로
칩니다. 비용은 글 전체에서 **자료 접근** 하나로 셉니다. 배열 칸을 읽거나 쓴 횟수와 문자열 글자를 읽은 횟수의
합이에요. 비교 횟수만 세면 계수 정렬 쪽이 0 이 되고, 글자 읽기만 세면 배가 기법이 첫 바퀴 뒤로 0 이 되어
두 방법을 같은 자로 잴 수 없기 때문입니다.

가장 먼저 떠오르는 방법은 접미사 `n` 개를 실제 문자열로 잘라 문자열 정렬에 넣는 것입니다. 이 방법은 정렬을
시작하기도 전에 메모리에서 막혀요. 접미사의 길이 합이 `n + (n − 1) + … + 1` 이라서입니다.

<!--proof:origin-slice-cost-->

| n | 잘라 낸 글자 수 n(n+1)/2 | 글자 하나를 1 바이트로 잡은 메모리 |
| ---: | ---: | ---: |
| 6 | 21 | 21 바이트 |
| 1,000 | 500,500 | 500,500 바이트 |
| 100,000 | 5,000,050,000 | 4,768 MB |

n = 100,000 에서 4,768 MB 이고, 예산 256 MB 의 18.6 배입니다.

<!--/proof-->

잘라 내지 않고 **시작 자리만 들고**, 두 자리를 비교할 때마다 두 접미사의 글자를 앞에서부터 읽어도 됩니다.
이것을 이 글에서는 **글자 비교 정렬**이라고 부를게요.

```ts
const sa = Array.from({ length: n }, (_, i) => i);
sa.sort((a, b) => {
  let k = 0;
  while (a + k < n && b + k < n) {
    if (s[a + k] !== s[b + k]) return s[a + k] < s[b + k] ? -1 : 1;
    k++;
  }
  return n - a < n - b ? -1 : 1; // 다른 글자 없이 한쪽이 끝났다
});
```

답은 틀리지 않습니다. 하는 일의 양은 **비교 횟수 × 비교 한 번이 읽는 글자 수**이고, 비교 한 번이 읽는 글자
수는 두 접미사가 앞부분을 얼마나 길게 공유하는가에 달렸어요. 규모를 열 배씩 키우며 두 입력 모양에서 배가
기법과 나란히 세어 보겠습니다. 비교 순서가 엔진마다 다른 `sort` 대신 합치기 정렬로 세서 셈이 늘 같습니다.

<!--proof:origin-two-ways-->

| n | 글자 비교 정렬 · 전부 a | 배가 기법 · 전부 a | 글자 비교 정렬 · 무작위 | 배가 기법 · 무작위 |
| ---: | ---: | ---: | ---: | ---: |
| 12 | 306 | 2,076 | 154 | 1,074 |
| 120 | 44,512 | 23,774 | 3,430 | 7,747 |
| 1,200 | 6,684,440 | 362,390 | 62,250 | 106,189 |
| 12,000 | 901,928,384 | 4,581,444 | 906,950 | 1,034,741 |

전부 같은 글자 n = 100,000 에서는 글자 비교 정렬이 77,909,041,216 번, 배가 기법이 46,262,802 번으로 1,684 배 차이입니다.

<!--/proof-->

**무작위 글자에서는 글자 비교 정렬이 더 적습니다.** 서로 다른 글자가 섞여 있으면 두 접미사가 대개 한두
글자에서 갈려, 비교 한 번이 읽는 글자가 몇 개 안 되거든요. 열두 글자에서는 전부 `a` 인 입력에서도 글자 비교
정렬이 적은데, 배가 기법의 계수 정렬이 글자 코드 범위만큼 칸을 잡는 비용이 규모와 상관없이 붙어 있어서예요.
그런데 **전부 같은 글자**에서는 규모를 열 배 키울 때마다 글자 비교 정렬이 백 배 넘게 늘고, `n = 100,000` 에서
약 779 억 번이 됩니다. 예산 1 초의 수백 배예요. 과제가 같은 글자가 길게 이어진 문자열을 허용하므로 이 방법은
쓸 수 없습니다.

두 방법이 같은 두 접미사를 비교할 때 무엇을 읽는지 보면 차이가 어디서 오는지 보입니다.

<!--proof:origin-one-compare-->

| 방법 | s[0..] 과 s[1..] 을 비교하며 읽는 것 | 자료 접근 |
| --- | --- | ---: |
| 글자 비교 | 두 접미사의 글자 9 쌍 | 18 |
| 순위 쌍 (gap = 8) | rank[0] · rank[8] · rank[1] · rank[9] | 4 |

s 는 a 열 개입니다. 글자 비교는 짧은 쪽이 끝날 때까지 9 쌍을 다 읽고, 순위 쌍은 gap 이 얼마든 4 칸을 읽습니다.

<!--/proof-->

여기서 관찰한 것은 하나입니다. **글자 비교 정렬은 공통 앞부분을 비교할 때마다 다시 읽고, 그 공통 앞부분의
길이는 입력이 정합니다.** 한 번 읽은 결과를 적어 두면 다시 읽지 않아도 될 거예요. 가장 적게 적어 두는 후보부터
세워 봅시다. **첫 글자의 순위 하나만** 적어 두는 것입니다. 첫 글자가 다르면 그것으로 순서가 정해지니,
남는 것은 첫 글자가 같은 자리들뿐이에요.

<!--proof:origin-first-char-->

| 첫 글자 | 순위(글자 코드) | 자리 | 무리 크기 |
| --- | ---: | --- | ---: |
| a | 97 | 1 · 3 · 5 | 3 개 |
| b | 98 | 0 | 1 개 |
| n | 110 | 2 · 4 | 2 개 |

6 자리 중 5 자리가 둘 이상인 무리에 남아, 첫 글자의 순위만으로는 순서가 정해지지 않습니다.

<!--/proof-->

첫 글자로 못 가른 자리를 가르려면 **둘째 글자부터**를 봐야 하는데, 자리 `i` 의 둘째 글자부터는 곧 자리
`i + 1` 에서 시작하는 문자열입니다. 그리고 자리 `i + 1` 의 첫 글자 순위는 방금 적은 줄에 이미 있어요. **자리
`i` 의 순위와 자리 `i + 1` 의 순위를 이어 붙이면 자리 `i` 의 앞 두 글자 순서가 나옵니다.** 뒤 성분을 1 씩
올리고 자리 5 에 0 을 두는 까닭은 아이디어 상세의 2단계에서 봅니다.

<!--proof:origin-reuse-->

| i | s[i..i+1] | 앞 성분 rank[i] | 뒤 성분 | 쌍 |
| ---: | --- | ---: | --- | --- |
| 0 | ba | 98 | rank[1] + 1 = 98 | (98, 98) |
| 1 | an | 97 | rank[2] + 1 = 111 | (97, 111) |
| 2 | na | 110 | rank[3] + 1 = 98 | (110, 98) |
| 3 | an | 97 | rank[4] + 1 = 111 | (97, 111) |
| 4 | na | 110 | rank[5] + 1 = 98 | (110, 98) |
| 5 | a | 97 | 0 (자리 6 이 없다) | (97, 0) |

쌍을 사전식으로 늘어놓은 순서는 [5, 1, 3, 0, 2, 4] 이고, 두 글자를 잘라 문자열로 비교한 순서는 [5, 1, 3, 0, 2, 4] 입니다. 두 순서가 같습니다.

<!--/proof-->

길이 1 순위로 길이 2 순서를 얻었으니, 같은 일을 되풀이하는 길이 둘입니다. 하나는 **한 바퀴에 한 글자씩**
늘리는 것이에요. 쌍 (길이 `L` 조각의 순위, 자리 `i + L` 의 글자) 로 길이 `L + 1` 조각의 순위를 만듭니다.
다른 하나는 뒤에 붙이는 것도 **이미 순위를 아는 길이 `L` 조각**으로 두어, 쌍 (`rank[i]`, `rank[i+L]`) 로 길이
`2L` 조각의 순위를 만드는 것이에요. 전부 같은 글자에서 둘을 세면 이렇습니다.

<!--proof:origin-plus-one-->

| 늘리는 방법 | 바퀴 수 | 자료 접근 |
| --- | ---: | ---: |
| 한 글자씩 | 1,999 | 106,705,003 |
| 두 배씩 | 11 | 600,790 |

a 가 2,000 개인 문자열에서 한 글자씩 늘리면 바퀴가 n − 1 = 1,999 번이고, 자료 접근이 두 배씩의 177.6 배입니다.

<!--/proof-->

한 글자씩 늘리면 바퀴가 `n − 1` 번이라, `n = 100,000` 이면 바퀴가 99,999 번입니다. 바퀴 하나가 `n` 에 비례하니
글자 비교 정렬의 최악과 같은 `n²` 규모예요. 두 배씩 늘리면 바퀴가 `⌈log₂ n⌉` 번입니다. 지금까지 해 본 방법을
차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 다섯 — 넷은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **배가 기법**입니다. 자리마다 길이 `gap` 조각의 순위를 순위 배열에 적어 두고, 쌍
(`rank[i]`, `rank[i+gap]`) 로 자리를 늘어놓아 길이 `2·gap` 조각의 순위를 만드는 일을 순위가 전부 다를 때까지
되풀이해요. 순위 배열이 어떻게 생겼는지, 쌍을 어떻게 늘어놓는지, 새 순위를 어떻게 매기는지는 다음 절에서
실현하는 순서대로 확인합니다.

### 아이디어 상세 — 배가 기법

이 아이디어를 한 문장으로 줄이면 이렇습니다. **글자 코드를 길이 1 조각의 순위로 두고, 바퀴마다 쌍
(`rank[i]`, `rank[i+gap]`) 을 계수 정렬 두 번으로 늘어놓은 뒤 이웃한 쌍이 다를 때만 올려 새 순위를 매기는 일을,
순위가 전부 다를 때까지 `gap` 을 두 배씩 늘리며 되풀이합니다.** 순위 배열은 처음 보는 사람에게 낯선 구조라
먼저 따로 설명하고, 그다음 실현하는 순서대로 다섯 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 길이 1 순위 매기기 | 글자 코드를 `rank` 로, 자리 번호를 `sa` 로 둔다 | — |
| 바퀴마다 | 2단계 앞 성분과 뒤 성분으로 쌍 만들기 | 자리마다 (`rank[i]`, `rank[i+gap]` + 1 또는 0) 을 만든다 | 1단계나 앞 바퀴 4단계의 `rank` |
| 바퀴마다 | 3단계 계수 정렬 두 번으로 쌍 늘어놓기 | 뒤 성분, 앞 성분 순서로 `sa` 를 안정 정렬한다 | 2단계의 쌍 |
| 바퀴마다 | 4단계 같은 쌍끼리 묶어 순위 다시 매기기 | 늘어선 `sa` 에서 이웃 쌍이 다를 때만 순위를 올린다 | 3단계의 `sa` · 2단계의 쌍 |
| 바퀴마다 | 5단계 다 갈렸는지 보고 조각 길이 늘리기 | `span` 이 `n` 이면 멈추고, 아니면 `gap` 을 두 배로 | 4단계의 `span` |

#### 먼저 알아 둘 개념 — 순위 배열

순위 배열은 **문자열의 자리마다, 그 자리에서 시작하는 길이 `L` 조각이 사전순으로 몇 번째 종류인지 적은
줄**입니다. 가장 앞인 종류가 0 이고, 같은 조각에는 같은 값이 붙어요. 식으로 쓰면 `rank[i]` 는 「자리 `i` 의
길이 `L` 조각보다 사전순으로 앞인 서로 다른 조각의 개수」입니다. 끝을 넘는 조각은 남은 글자만큼 짧아져요.

##### 입력 위에 놓은 순위 배열

`"banana"` 의 순위 배열을 조각 길이 1 · 2 · 4 세 층으로 쌓으면 이렇습니다. 곁말의 종류 수가 그 층에 서로 다른
조각이 몇 가지인지예요.

<!--fig:build-levels-->
![banana 의 순위 배열 세 층 — 층이 오를수록 조각 길이가 두 배가 된다](./figs/build-levels.svg)

길이 1 층은 글자 코드 그대로라 97 · 98 · 110 처럼 큰 수이고, 그 위 두 층은 0 부터 빈틈없이 이어진 수입니다.
둘이 다른 까닭은 1단계에서 봐요. 길이 4 층에서는 여섯 자리가 전부 다른 값을 받았습니다.

##### 칸 하나를 읽는 법

길이 2 층의 칸 3 을 골라 이름에서 조각과 값까지 따라가 봅시다.

<!--proof:build-read-one-->

```text
길이 2 순위[3] = 1
  가리키는 조각   s[3..4] = an
  조각의 종류     a < an < ba < na
  읽는 법         an 보다 앞인 종류가 a 로 1 개다
```

칸 번호 3 은 문자열의 자리이고, 값 1 은 사전순 종류 번호입니다. 길이 2 층에서 자리 1 도 `an` 이라 같은 1 을
받아요. 이 층만으로는 자리 1 과 자리 3 의 앞뒤를 정할 수 없다는 뜻입니다.

##### 이웃한 층끼리의 관계

위층의 칸 하나는 아래층의 칸 **둘**이 정합니다. 길이 4 조각 `anan` 은 앞 두 글자 `an` 과 뒤 두 글자 `an`
으로 정확히 갈리고, 두 조각의 순위가 길이 2 층의 칸 1 과 칸 3 에 있어요.

<!--fig:build-pair-->
![길이 4 조각 anan 의 순위는 길이 2 층의 두 칸이 정한다](./figs/build-pair.svg)

그리고 층이 오를수록 같은 순위끼리 묶인 무리가 **잘게 갈리기만** 합니다. 층마다 무리를 적으면 이렇습니다.

<!--proof:build-refine-->

| 층 | 무리 수 | 같은 순위끼리 묶은 자리 |
| --- | ---: | --- |
| 길이 1 순위 | 3 | {1,3,5} {0} {2,4} |
| 길이 2 순위 | 4 | {5} {1,3} {0} {2,4} |
| 길이 4 순위 | 6 | {5} {3} {1} {0} {4} {2} |

아래층에서 순위가 달랐던 두 자리가 위층에서 같은 순위가 된 경우는 0 번입니다.

<!--/proof-->

아래층에서 조각이 달랐던 두 자리는 조각을 늘려도 앞부분이 이미 달라 위층에서도 다릅니다. 그래서 무리가
합쳐지는 일이 없고, 무리 수가 `n` 이 되는 층에서 모든 자리가 갈립니다.

##### 접미사 배열의 칸 번호와의 차이

순위 배열을 「자리 `i` 의 접미사가 접미사 배열에서 몇 번째 칸에 있는가」로 읽기 쉽습니다. 마지막 층에서는
두 값이 같지만, 그 전의 층에서는 다른 값이에요. 길이 2 층으로 나란히 적으면 이렇습니다.

<!--proof:build-inverse-->

| 자리 i | s[i..i+1] | 길이 2 순위의 칸 i | 접미사 배열에서의 자리 k |
| ---: | --- | ---: | ---: |
| 0 | ba | 2 | 3 |
| 1 | an | 1 | 2 |
| 2 | na | 3 | 5 |
| 3 | an | 1 | 1 |
| 4 | na | 3 | 4 |
| 5 | a | 0 | 0 |

6 자리 중 4 자리에서 두 값이 다릅니다. 길이 2 순위에는 서로 다른 값이 4 개뿐이라 같은 값이 겹쳐 나옵니다.

<!--/proof-->

순위 배열은 **조각이 같으면 같은 값**을 줍니다. 접미사 배열의 칸 번호는 자리마다 다 다른 값이라 「아직 못
가렸다」를 담지 못해요. 층이 오를 때 필요한 것이 바로 「앞 절반이 같은가」라서, 순위 배열이 칸 번호가 아니라
종류 번호를 적습니다.

##### 순위 배열이 이렇게 생긴 까닭

위층 칸 하나를 채우려면 아래층의 칸 `i` 와 칸 `i + L` 을 읽어야 하고, `i` 는 어느 자리든 될 수 있습니다. 그래서
모든 자리에 칸이 있어야 해요. 값은 두 가지 관계만 맞으면 됩니다. 조각이 사전순으로 앞이면 값이 작고, 조각이
같으면 값이 같다는 것이에요. 대소는 쌍을 늘어놓는 데 쓰이고, 같음은 쌍이 같은지 판정하는 데 쓰입니다.

#### 1단계 — 길이 1 순위 매기기

첫 층은 글자 코드를 그대로 씁니다. 순위가 0 부터 빈틈없이 이어질 필요는 없고, 앞의 두 관계만 맞으면 되기
때문이에요. 소문자의 글자 코드는 알파벳 순서대로 커집니다.

<!--proof:build-codes-->

| 글자 | 글자 코드 | 0 부터 매긴 순위 |
| --- | ---: | ---: |
| a | 97 | 0 |
| b | 98 | 1 |
| n | 110 | 2 |

두 열의 값은 다르지만 글자 a < b < n 의 대소 순서를 똑같이 담습니다.

<!--/proof-->

글자 코드는 128 보다 작으므로 첫 바퀴의 계수 정렬은 칸을 `span = 128` 에 맞춰 잡습니다. 접미사 배열 `sa` 는
아직 순서를 모르니 자리 번호 `[0, 1, 2, 3, 4, 5]` 를 그대로 담아 둬요. 층의 칸 수는 언제나 `n` 이고, 첫 층의
값은 97 부터 122 사이입니다.

#### 2단계 — 앞 성분과 뒤 성분으로 쌍 만들기

자리마다 쌍을 만듭니다. 앞 성분은 `rank[i]` 이고, 뒤 성분은 `rank[i + gap]` 에 1 을 더한 값이에요. 쉬운 경우는
뒤 조각이 문자열 안에 있는 자리입니다. 불안한 경우는 `i + gap` 이 `n` 이상이라 **뒤 조각이 없는** 자리예요.
사전순은 「다른 글자 없이 먼저 끝나면 짧은 쪽이 앞」이므로 그 자리는 어떤 실제 순위보다도 작은 값을 받아야
합니다. 계수 정렬의 칸 번호로 쓰려면 음수는 안 되니, 실제 순위를 전부 1 씩 올려 0 을 비우고 그 0 을 「뒤
조각 없음」에 줍니다. 뒤 조각이 없는 자리가 둘인 둘째 바퀴(`gap = 2`)의 쌍입니다.

<!--proof:build-pairs-->

| i | s[i..i+3] | 앞 성분 rank[i] | 뒤 성분 | 쌍 |
| ---: | --- | ---: | --- | --- |
| 0 | bana | 2 | rank[2] + 1 = 4 | (2, 4) |
| 1 | anan | 1 | rank[3] + 1 = 2 | (1, 2) |
| 2 | nana | 3 | rank[4] + 1 = 4 | (3, 4) |
| 3 | ana | 1 | rank[5] + 1 = 1 | (1, 1) |
| 4 | na | 3 | 0 (자리 6 이 없다) | (3, 0) |
| 5 | a | 0 | 0 (자리 7 이 없다) | (0, 0) |

gap = 2 에서 뒤 조각이 문자열 끝을 넘는 자리는 2 곳이고, 그 자리의 뒤 성분은 0 입니다.

<!--/proof-->

자리 4 와 5 는 뒤 조각이 없어 뒤 성분이 0 이고, 자리 3 의 뒤 조각은 한 글자 `a` 라 그 순위 0 에 1 을 더해
1 입니다. 자리 1 의 뒤 성분은 2 라서, 앞 성분이 1 로 같은 자리 1 과 3 이 이 쌍에서 갈려요. 뒤 성분의 범위는
0 이상 `span` 이하이고, 그래서 계수 정렬은 칸을 `span + 1` 개 잡습니다.

#### 3단계 — 계수 정렬 두 번으로 쌍 늘어놓기

쌍을 사전식으로 늘어놓습니다. 두 성분이 다 작은 범위의 정수라 계수 정렬을 쓸 수 있고, 자리가 둘인 자릿수
정렬과 같은 순서로 두 번 실행해요. **뒤 성분으로 먼저, 앞 성분으로 나중**이고 둘 다 안정 정렬이어야 합니다.
나중에 한 정렬이 앞 성분 순서를 정하고, 앞 성분이 같은 자리끼리는 먼저 한 정렬이 정한 뒤 성분 순서가 남아요.
첫 바퀴에서 두 정렬 사이의 `sa` 를 적으면 이렇습니다.

<!--proof:build-stable-->

| 사전순 자리 k | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 뒤 성분으로 정렬한 sa | 5 | 0 | 2 | 4 | 1 | 3 |
| 그 자리의 앞 성분 | 97 | 98 | 110 | 110 | 97 | 97 |
| 앞 성분으로 정렬한 sa | 5 | 1 | 3 | 0 | 2 | 4 |

앞 성분이 97 인 자리는 첫 줄에서 5 · 1 · 3 순서였고 셋째 줄에서도 5 · 1 · 3 순서입니다.

<!--/proof-->

앞 성분이 97 인 세 자리는 뒤 성분 순서로 5 · 1 · 3 이 되었고, 앞 성분 정렬이 그 앞뒤를 그대로 두었습니다.
자리 1 과 3 은 뒤 성분까지 111 로 같아 이 바퀴에서는 안 갈려요. 계수 정렬은 칸마다 한 번씩 놓고 끝나므로 두
원소가 한 칸에 겹치지 않습니다.

#### 4단계 — 같은 쌍끼리 묶어 순위 다시 매기기

늘어선 `sa` 를 왼쪽부터 읽으며 이웃한 두 자리의 쌍을 비교하고, **다를 때만** 순위를 하나 올립니다. 줄이 이미
쌍 기준으로 늘어서 있으므로 같은 쌍을 가진 자리들은 서로 붙어 있어요. 그래서 이웃끼리만 비교해도 모든 같은
쌍이 한 무리가 됩니다. 첫 바퀴의 판정을 모두 적으면 이렇습니다.

<!--proof:build-rerank-->

| j | a = sa[j−1] | b = sa[j] | a 의 쌍 | b 의 쌍 | 두 쌍 | top |
| ---: | ---: | ---: | --- | --- | --- | ---: |
| 1 | 5 | 1 | (97, 0) | (97, 111) | 다르다 | 1 |
| 2 | 1 | 3 | (97, 111) | (97, 111) | 같다 | 1 |
| 3 | 3 | 0 | (97, 111) | (98, 98) | 다르다 | 2 |
| 4 | 0 | 2 | (98, 98) | (110, 98) | 다르다 | 3 |
| 5 | 2 | 4 | (110, 98) | (110, 98) | 같다 | 3 |

마지막 top 이 3 이라 span = 4 고, 자리 순서로 모은 새 순위 배열은 [2, 1, 3, 1, 3, 0] 입니다.

<!--/proof-->

`top` 은 「지금까지 서로 다른 쌍이 몇 종류 지나갔는가 − 1」이라 마지막 값에 1 을 더하면 서로 다른 쌍의 개수,
곧 다음 바퀴의 `span` 입니다. 새 순위는 `sa` 를 따라 매기지만 적는 자리는 문자열 자리 `b` 라서, 결과가 다시
자리 순서의 순위 배열이 돼요. 반복은 `j` 가 1 부터 `n − 1` 까지 한 번씩이므로 `sa[0]` 을 뺀 모든 자리가 정확히
한 번 적히고, `sa[0]` 자리는 처음 채운 0 을 그대로 가집니다.

#### 5단계 — 다 갈렸는지 보고 조각 길이 늘리기

`span` 이 `n` 이면 순위가 전부 다르다는 뜻입니다. 조각을 더 늘려도 이미 다른 앞부분이 순서를 정하므로 `sa` 가
바뀌지 않아 여기서 멈춰요. 아니면 `gap` 을 두 배로 늘려 2단계로 돌아갑니다.

<!--proof:build-stop-->

| 바퀴 | gap | 가른 조각 길이 | 끝난 뒤 span | n | span === n |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 2 | 4 | 6 | 거짓 — gap 을 두 배로 |
| 2 | 2 | 4 | 6 | 6 | 참 — 멈춘다 |

바퀴 2 번으로 끝났고, 답은 [5, 3, 1, 0, 4, 2] 입니다.

<!--/proof-->

멈추는 시점은 늦어도 `gap` 이 `n` 이상이 된 바퀴입니다. 그때는 조각이 접미사 전체를 덮고, 접미사는 서로
길이가 달라 같은 것이 없기 때문이에요. 그래서 바퀴 수는 `⌈log₂ n⌉` 을 넘지 않습니다.

#### 이 방법이 기대는 전제

배가 기법은 아래 세 전제에 기대고 있습니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 문자열이 바뀌지 않는다 | 모든 단계가 같은 `s` 의 순위를 쌓는다 | 글자 하나가 바뀌면 순위 배열 전체를 다시 만든다 |
| 순위의 대소와 같음이 조각의 사전순과 맞는다 | 2단계의 쌍 · 4단계의 판정 | 쌍의 순서가 조각의 순서와 달라진다 |
| 순위가 계수 정렬의 칸 수보다 작은 정수다 | 1단계의 `span = 128` · 3단계의 칸 번호 | 칸 밖의 번호에 개수를 적어 자리를 잃는다 |

셋째 전제가 깨지는 흔한 모양은 글자 코드가 128 이상인 글자가 섞인 입력입니다. 과제는 소문자 영문만 받지만,
그 밖의 글자를 넣으면 이렇게 나와요.

<!--proof:build-premise-ascii-->

| 입력 | 가장 큰 글자 코드 | 정본이 낸 답 | 바른 답 | 답의 모양 |
| --- | ---: | --- | --- | --- |
| "aé" | 233 | [0, 0] | [0, 1] | 순열이 아니다 |
| "caféa" | 233 | [4, 1, 0, 0, 0] | [4, 1, 0, 2, 3] | 순열이 아니다 |
| "abcΩ" | 937 | [1, 0, 0, 0] | [0, 1, 2, 3] | 순열이 아니다 |
| "가나" | 45,208 | [0, 0] | [0, 1] | 순열이 아니다 |

4 벌 모두 예외 없이 끝났고, 그중 4 벌은 같은 자리 번호가 두 번 이상 나오는 배열을 돌려줬습니다.

<!--/proof-->

`"aé"` 의 `é` 는 글자 코드가 233 인데 계수 정렬의 칸은 129 개뿐입니다. 자바스크립트 배열은 칸 밖의 번호에
값을 적어도 오류를 내지 않아, 그 자리의 개수가 누적합에 들어가지 못해요. 자리가 정해지지 않은 칸에는 처음
채운 0 이 남습니다. 넓은 글자를 받으려면 첫 순위를 0 부터 다시 매기거나 `span` 을 가장 큰 글자 코드에 맞춰야
해요.

#### 두 배씩 늘리는 까닭

한 바퀴에 조각을 `m` 배로 늘리면 바퀴 수는 줄지만, 키가 성분 `m` 개짜리가 되어 바퀴마다 계수 정렬이 `m` 번이고
판정도 `m` 개 값을 비교합니다. 전부 같은 글자에서 `m` 을 다섯 가지로 두고 실제로 셌습니다.

<!--proof:build-growth-->

| 배수 | 바퀴 수 | 자료 접근 | 가장 적은 것과의 비 |
| --- | ---: | ---: | --- |
| x2 | 17 | 46,262,802 | 1.081 배 |
| x3 | 11 | 42,807,740 | 가장 적다 |
| x4 | 9 | 45,463,602 | 1.062 배 |
| x8 | 6 | 57,491,052 | 1.343 배 |
| x16 | 5 | 93,002,186 | 2.173 배 |

전부 같은 글자 100,000 개에서 가장 적은 것은 x3 이고, x2 는 그보다 8.1 % 많습니다.

<!--/proof-->

**가장 적은 것은 두 배가 아니라 세 배입니다.** `m` 을 키우면 바퀴 수는 17 에서 5 로 줄지만 바퀴 하나의 정렬은
2 번에서 16 번으로 늘고, 그 곱이 세 배 언저리에서 가장 작아요. 그런데도 이 글이 두 배를 쓰는 까닭은 그 몇 %
를 내주고 얻는 것이 있기 때문입니다. 두 배면 키가 **쌍 하나**라 정렬이 두 번이고, 판정이 두 값 비교로 끝나며,
코드에 성분 목록을 둘 필요가 없어요. 임의의 `n` 에서 가장 적은 `m` 을 식으로 푸는 일은 파트 2 의 「수식 정의와
유도」가 합니다.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 여섯 걸음이 됩니다. 이렇게 하면 전부 같은 글자 100,000 개에서 약 779 억
번이던 자료 접근이 약 4,626 만 번이 됩니다.

1. `sa` 를 자리 번호로, `rank` 를 글자 코드로, `span` 을 128 로 둔다
2. `gap` 을 1 로 두고 `gap < n` 인 동안 아래를 되풀이한다
3. 자리마다 쌍 (`rank[i]`, `rank[i+gap]` + 1) 을 만들고, 뒤 조각이 없으면 뒤 성분을 0 으로 둔다
4. 뒤 성분으로 안정 정렬하고, 그 결과를 앞 성분으로 다시 안정 정렬한다
5. `sa` 를 왼쪽부터 읽으며 이웃한 쌍이 다를 때만 순위를 올려 새 `rank` 와 `span` 을 만든다
6. `span` 이 `n` 이면 멈추고, 아니면 `gap` 을 두 배로 한다

### 수행으로 알아보는 알고리즘 — 여섯 글자에서 두 바퀴로 접미사 배열을 만든다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다
그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const s = "banana";
// 이 절이 끝나면 [5, 3, 1, 0, 4, 2] 이 나와야 한다
```

왜 하필 이 여섯 글자일까요? 코드의 다섯 갈래를 **모두 실행하게** 하려는 것입니다. 바퀴가 두 번이라 앞 바퀴의
순위를 재료로 쓰는 것이 값으로 보이고, 첫 바퀴 끝에 같은 순위가 두 무리(`an` 과 `na`) 남아 「쌍이 같아 순위를
안 올린다」와 「아직 안 갈려 한 바퀴 더」가 실행돼요. 둘째 바퀴에서는 뒤 조각이 없는 자리가 둘이라 0 을 두는
갈래도 여러 번 나옵니다.

```text
suffixArray(s):
    sa ← 자리 번호,  rank ← 글자 코드,  span ← 128          ① 첫 순위
    gap ← 1 부터 gap < n 인 동안 두 배씩:
        front(i) = rank[i]
        back(i)  = rank[i+gap] + 1,  i+gap ≥ n 이면 0       ② 범위 밖
        back 으로, 그다음 front 로 안정 계수 정렬            ③ 정렬 두 번
        이웃한 쌍이 다를 때만 top 을 올려 next 에 적는다     ④ 같으면 그대로
        rank ← next,  span ← top + 1
        span = n 이면 멈춘다                                ⑤ 종료
    sa 를 반환한다
```

#### 1. 첫 순위를 글자 코드로 둔다

답 배열은 자리 번호를 그대로 담아 두고, 길이 1 조각의 순위는 글자 코드로 둡니다.

```ts
const n = s.length;
let sa = Array.from({ length: n }, (_, i) => i);
// ① 길이 1 조각의 순위는 글자 코드를 그대로 쓴다. 대소 관계가 사전순과 같으면 충분하다.
let rank = Array.from({ length: n }, (_, i) => s.charCodeAt(i));
let span = 128;
```

실행하면 이렇게 나옵니다. 여기까지가 T1 이에요.

<!--proof:walk-init-->

```text

sa   = [0, 1, 2, 3, 4, 5]   아직 정렬 전이라 자리 번호 그대로
```

#### 2. 뒤 성분을 붙여 쌍을 만든다

자리마다 앞 성분과 뒤 성분을 돌려주는 함수 둘을 둡니다. 쌍을 배열로 만들어 두지 않고, 정렬과 판정이 필요할
때마다 순위 배열에서 바로 읽어요.

```ts
const front = (i: number): number => rank[i] as number;
// ② 뒤 조각의 순위. 문자열 끝을 넘으면 0 을 두어 같은 앞 조각 안에서 맨 앞에 오게 한다.
const back = (i: number): number =>
  i + gap < n ? (rank[i + gap] as number) + 1 : 0;
```

여기서 가장 중요한 것은 `+ 1` 과 `: 0` 이 한 쌍이라는 것입니다. 실제 순위를 1 씩 올려 비운 0 을 뒤 조각이
없는 자리에 줘요. 첫 바퀴(T2)에서 두 함수가 자리마다 내는 값입니다.

<!--proof:walk-pair-->

```text
gap = 1
front(i) = rank[i]                 [98, 97, 110, 97, 110, 97]
back(i)  = rank[i+1] + 1 또는 0     [98, 111, 98, 111, 98, 0]
자리 5 는 i + 1 = 6 이 n = 6 보다 작지 않아 0 이다
```

#### 짚고 가기 — 범위를 넘은 자리를 큰 값으로 두면 짧은 접미사가 뒤로 간다

여기서 헷갈리기 쉬운 포인트는 뒤 조각이 없는 자리에 무엇을 넣는가입니다. 「비교할 것이 없으니 크게 두자」로
읽기 쉬워요. 그 생각대로 한 줄만 바꿔 봅시다.

```ts
const back = (i: number): number =>
  i + gap < n ? (rank[i + gap] as number) : span; // 0 이 아니라 가장 큰 값으로 두었다
```

#### 3. 계수 정렬 두 번으로 쌍을 늘어놓는다

정렬 한 줄이 두 번의 계수 정렬입니다. 키 함수만 바꿔 같은 정렬을 두 번 부르고, 칸 수는 뒤 성분의 범위에 맞춰
`span + 1` 이에요.

```ts
// ③ 뒤 조각으로 먼저 안정 정렬하고, 그 결과를 앞 조각으로 다시 안정 정렬한다.
for (const key of [back, front]) sa = countingSortBy(sa, key, span + 1);
```

```ts
function countingSortBy(
  order: number[],
  key: (i: number) => number,
  span: number,
): number[] {
  const count = new Array<number>(span).fill(0);
  for (const i of order) count[key(i)] = (count[key(i)] as number) + 1;
  for (let v = 1; v < span; v++) {
    count[v] = (count[v] as number) + (count[v - 1] as number);
  }
  const out = new Array<number>(order.length).fill(0);
  for (let p = order.length - 1; p >= 0; p--) {
    const i = order[p] as number;
    const k = key(i);
    count[k] = (count[k] as number) - 1;
    out[count[k] as number] = i;
  }
  return out;
}
```

`order` 를 **뒤에서부터** 읽어 누적 개수의 끝 칸부터 채우는 것이 안정성을 만듭니다. 첫 바퀴의 T3 과 T4 가
이 두 번이에요.

<!--proof:walk-sort-->

```text
뒤 성분으로 정렬한 뒤    sa = [5, 0, 2, 4, 1, 3]
앞 성분으로 정렬한 뒤    sa = [5, 1, 3, 0, 2, 4]
```

#### 짚고 가기 — 정렬 순서를 뒤바꾸거나 안정성을 잃으면 조용히 틀린다

여기서 헷갈리기 쉬운 포인트는 두 정렬의 순서입니다. 「앞 성분이 더 중요하니 먼저 정렬하자」로 읽기 쉬워요.
그리고 계수 정렬을 앞에서부터 놓아도 정렬은 되니, 뒤에서부터 놓는 까닭도 잘 안 보입니다. 두 사본을 각각
만들어 여덟 입력에 실행해 봅시다.

```ts
for (const key of [front, back]) sa = countingSortBy(sa, key, span + 1); // 순서를 뒤바꿨다
```

**두 사본이 서로 다른 이유로 어긋납니다.** 앞 성분을 먼저 정렬하면 나중에 한 뒤 성분 정렬이 앞 성분 무리를
흩어 놓아요. 나중 정렬은 앞 성분을 아예 보지 않으니까요. 안정성을 없애면 앞 성분이 같은 무리 안의 앞뒤가
뒤집혀, 먼저 한 정렬이 매겨 둔 뒤 성분 순서가 지워집니다. 둘 다 「먼저 한 정렬의 결과를 나중 정렬이
보존하는가」 하나를 어긴 것이고, 두 사본 다 답이 우연히 맞는 입력이 섞여 있어 그 줄만 보면 잘못을 못 찾습니다.

#### 4. 같은 쌍끼리 묶어 새 순위를 매긴다

늘어선 줄을 왼쪽부터 읽으며 이웃한 두 자리의 쌍이 다를 때만 순위를 하나 올립니다. 새 순위는 새 배열 `next`
에 적어요.

```ts
const next = new Array<number>(n).fill(0);
let top = 0;
for (let j = 1; j < n; j++) {
  const a = sa[j - 1] as number;
  const b = sa[j] as number;
  // ④ 이웃한 두 자리의 쌍이 다를 때만 순위를 하나 올린다. 같으면 아직 못 가른 것이다.
  if (front(a) !== front(b) || back(a) !== back(b)) top++;
  next[b] = top;
}
rank = next;
span = top + 1;
```

첫 바퀴의 T5 가 이 조각입니다. 판정 하나하나는 아이디어 상세의 4단계 표와 같고, 조각이 내는 값은 이렇습니다.

<!--proof:walk-rerank-->

```text
next = [2, 1, 3, 1, 3, 0]   자리 순서로 담은 새 순위
span = top + 1 = 3 + 1 = 4
span === n  →  4 === 6 이 거짓
```

#### 짚고 가기 — 새 순위를 제자리에 덮어쓰면 아직 읽어야 할 값이 사라진다

여기서 헷갈리기 쉬운 포인트는 `next` 라는 새 배열이 왜 필요한가입니다. 「순위를 새로 매기는 것이니 `rank` 를
그 자리에서 고쳐도 되겠다」로 읽기 쉬워요. 그런데 판정에 쓰는 `front(a)` 와 `back(a)` 는 **앞 바퀴의 `rank`
를 읽습니다.**

```ts
const next = rank; // 새 배열을 잡지 않고 rank 를 그대로 썼다
```

#### 6. 전체 코드

조각을 한 함수로 잇습니다. 앞에서 값으로 확인하지 않은 것이 하나 남아 있는데, 바퀴를 감싸는 `for` 문의 조건
`gap < n` 이에요. `n` 이 1 이면 이 조건이 처음부터 거짓이라 바퀴가 한 번도 실행되지 않고 `[0]` 이 그대로 답이
됩니다.

```ts
function countingSortBy(
  order: number[],
  key: (i: number) => number,
  span: number,
): number[] {
  const count = new Array<number>(span).fill(0);
  for (const i of order) count[key(i)] = (count[key(i)] as number) + 1;
  for (let v = 1; v < span; v++) {
    count[v] = (count[v] as number) + (count[v - 1] as number);
  }
  const out = new Array<number>(order.length).fill(0);
  for (let p = order.length - 1; p >= 0; p--) {
    const i = order[p] as number;
    const k = key(i);
    count[k] = (count[k] as number) - 1;
    out[count[k] as number] = i;
  }
  return out;
}

export function suffixArray(s: string): number[] {
  const n = s.length;
  let sa = Array.from({ length: n }, (_, i) => i);
  // ① 길이 1 조각의 순위는 글자 코드를 그대로 쓴다. 대소 관계가 사전순과 같으면 충분하다.
  let rank = Array.from({ length: n }, (_, i) => s.charCodeAt(i));
  let span = 128;

  for (let gap = 1; gap < n; gap *= 2) {
    const front = (i: number): number => rank[i] as number;
    // ② 뒤 조각의 순위. 문자열 끝을 넘으면 0 을 두어 같은 앞 조각 안에서 맨 앞에 오게 한다.
    const back = (i: number): number =>
      i + gap < n ? (rank[i + gap] as number) + 1 : 0;

    // ③ 뒤 조각으로 먼저 안정 정렬하고, 그 결과를 앞 조각으로 다시 안정 정렬한다.
    for (const key of [back, front]) sa = countingSortBy(sa, key, span + 1);

    const next = new Array<number>(n).fill(0);
    let top = 0;
    for (let j = 1; j < n; j++) {
      const a = sa[j - 1] as number;
      const b = sa[j] as number;
      // ④ 이웃한 두 자리의 쌍이 다를 때만 순위를 하나 올린다. 같으면 아직 못 가른 것이다.
      if (front(a) !== front(b) || back(a) !== back(b)) top++;
      next[b] = top;
    }
    rank = next;
    span = top + 1;

    // ⑤ 순위가 전부 달라졌으면 조각을 더 늘려도 순서가 안 바뀐다.
    if (span === n) break;
  }
  return sa;
}
```

```text
suffixArray("a")          ->  [0]
```

### 알아 두면 좋은 개념 — 분할 정련

전개의 순위 배열이 한 일에는 이미 이름이 있습니다. 순위 배열은 자리 `n` 개를 **같은 순위끼리 묶은 무리**로
나눈 것이고, 바퀴마다 그 무리가 더 잘게 갈렸어요. **이미 나눠 둔 무리를 조건 하나로 더 잘게 나누기만 하는
절차**를 분할 정련(partition refinement)이라고 부릅니다.

<!--proof:related-refine-->

| 걸음 | 가른 조각 길이 | 무리 수 | 무리 |
| --- | ---: | ---: | --- |
| T1 | 1 | 3 | {1,3,5} {0} {2,4} |
| T5 | 2 | 4 | {5} {1,3} {0} {2,4} |
| T9 | 4 | 6 | {5} {3} {1} {0} {4} {2} |

무리 수가 3 → 4 → 6 으로 늘기만 하고, 마지막 무리 수가 n = 6 과 같습니다.

<!--/proof-->

이 글의 종료 조건 `span === n` 은 「무리 수가 자리 수와 같다」를 그대로 적은 것입니다. 같은 이름의 절차가
다른 자리에서도 나와요.

| 다시 나오는 자리 | 처음 무리 | 무리를 가르는 조건 |
| --- | --- | --- |
| 유한 상태 기계 최소화 | 받아들이는 상태와 아닌 상태 | 같은 글자로 가는 상태가 다른 무리다 |
| 그래프 색칠 다듬기 | 모든 정점이 같은 색 | 이웃의 색 목록이 다르다 |
| 접미사 배열(이 글) | 첫 글자가 같은 자리 | 뒤 조각의 순위가 다르다 |

세 자리 모두 무리는 잘게 갈리기만 하고 합쳐지지 않아서, 무리 수가 더 늘지 않는 시점에 절차가 끝납니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 이 세운 절차를 따져 봅니다. 어느 과제 모양에 이것이 맞는지, 순위와 쌍을 식으로 적으면 무엇이 새로
나오는지, 매 바퀴 참으로 남는 문장이 무엇인지, 자료 접근이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 문자열 하나가 고정되고 그 위의 물음이 여럿이다 | 접미사 배열은 전처리이고, 만들어 두면 부분 문자열 찾기 · 가장 긴 되풀이 조각 · 서로 다른 부분 문자열 세기가 그 위에서 풀린다 | 한 번 만든 `sa` 를 돌려주고 끝난다 |
| 최악 보장이 필요하다 | 어떤 문자열이 들어와도 비용의 차수가 `n log n` 을 넘지 않아야 한다 | 바퀴 수가 `⌈log₂ n⌉` 로 묶인다 |
| 글자 집합이 작다 | 첫 바퀴의 계수 정렬이 글자 코드 범위만큼 칸을 잡는다 | `span = 128` |
| 구현을 짧게 유지해야 한다 | 재귀도 별도 자료구조도 없다 | 계수 정렬 하나와 그것을 되풀이하는 루프 하나 |

같은 문자열 과제라도 물음의 모양에 따라 맞는 절차가 다릅니다.

| 물음 | 맞는 절차 | 까닭 |
| --- | --- | --- |
| 고정된 문자열에 부분 문자열 물음이 여럿 | 접미사 배열 | 한 번 만들어 두고 이진 탐색으로 답한다 |
| 패턴 하나가 나오는 자리 전부 | [실패 함수](../findAllOccurrences/findAllOccurrences-guide.md) | 전처리가 패턴 길이에 비례한다 |
| 패턴 수백 개를 한 번에 | [아호–코라식](../ahoCorasick/ahoCorasick-guide.md) | 텍스트를 한 번만 읽는다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "문자열이 주어지고 질의가 Q 개"   "같은 문자열에 여러 번"   ← 전처리를 한 번만 하면 된다
  "가장 긴 반복되는 부분 문자열"                              ← 접미사를 사전순으로 늘어놓아야 한다
  "서로 다른 부분 문자열의 개수"                              ← 접미사 배열과 공통 앞부분 길이가 재료다
  "사전순으로 k 번째"                                         ← 순서 자체가 답이다

제약에 이런 모양이 보이면
  |s| 가 10^5 이고 O(n log n) 을 요구한다
  글자가 소문자 영문으로 한정된다
  같은 글자가 길게 이어질 수 있다고 적혀 있다
```

반대로 「패턴 하나의 등장 위치」를 묻거나, 「문자열이 계속 바뀐다」 · 「글자를 삽입 · 삭제한다」가 보이면 이
단서는 해당하지 않습니다. 접미사 배열은 문자열이 고정이라는 것에 통째로 기대고 있어서, 글자 하나가 바뀌면
순위 배열 전체를 다시 만들어야 해요. 「두 문자열의 편집 거리」처럼 글자가 어긋나는 것을 허용하는 물음도 다른
절차의 몫입니다.

- **바이너리 차분 도구 `bsdiff`.** 콜린 퍼시벌이 2003–2005 년에 쓴 것이고
  ([프로젝트 쪽](https://www.daemonology.net/bsdiff/), 조회 2026-09-04) 소개 문장이
  *"bsdiff and bspatch are tools for building and applying patches to binary files"* 입니다.

  `for(h=1;I[0]!=-(oldsize+1);h+=h)` 라 조각 길이 `h` 를 `h+=h` 로 두 배씩 늘리고, 시작값을
  `for(i=0;i<oldsize;i++) V[i]=buckets[old[i]];` 로 글자 통 번호에서 가져옵니다. 이 글의

  ([`bsdiff.c`](https://github.com/mendsley/bsdiff/blob/master/bsdiff.c), 조회 2026-09-04)
- **크로미움의 바이너리 차분 부품 `zucchini`.** `components/zucchini/suffix_array.h` 가 접미사
  배열 만들기를 두 가지로 싣습니다 — 주석이 *"the naive suffix sorting algorithm that uses
  std::sort with lexicographic compare"* 와 *"suffix array induced sorting (SA-IS) algorithm
  with linear time and memory complexity"* 라 적어요. 크롬 업데이트의 차분 패치가 이것을 씁니다.
  ([`components/zucchini/suffix_array.h`](https://chromium.googlesource.com/chromium/src/+/HEAD/components/zucchini/suffix_array.h),
  조회 2026-09-04)

#### 경쟁 설계와의 대조

같은 답(접미사 배열)을 내는 다른 절차로 **갈라 정렬**(DC3, Kärkkäinen–Sanders skew)이 있습니다. 자리를 3 으로
나눈 나머지로 갈라, 나머지가 1 과 2 인 자리들을 세 글자 묶음으로 이름 붙여 **재귀로** 정렬한 뒤, 나머지가 0 인
자리를 그 결과에서 유도해 두 줄을 합치는 방식이에요. 바퀴를 되풀이하지 않으므로 입력이 얼마나 되풀이되는지와
상관없이 비용이 정해집니다.

| 설계 | 조각을 늘리는 방식 | 비용을 정하는 것 |
| --- | --- | --- |
| 배가 기법 | 길이 1 → 2 → 4 → … 순위가 전부 갈릴 때까지 바퀴를 되풀이한다 | 바퀴 수 — 입력이 정한다 |
| 갈라 정렬 | 자리를 3 으로 나눠 3 분의 2 를 재귀로 정렬하고 나머지를 유도해 합친다 | 재귀 깊이 — 길이 `n` 만 정한다 |

같은 생성식으로 만든 문자열에 두 설계를 두고 **자료 접근**(배열 칸 읽기·쓰기와 문자열 글자 읽기의 합. 칸을
잡으며 0 으로 채우는 초기화 쓰기는 넣지 않았어요)을 셌습니다. 자릿수 정렬 편의 칸 접근에 글자 읽기를 더한
잣대입니다. 문자열은 mulberry32 난수(씨앗
`0x9e3779b9`)로 만든 소문자 26 글자짜리이고, **길이 `n` 하나만** 바꿉니다. 전개 입력(여섯 글자)을 그대로 쓰지
않은 까닭은 그 규모에서는 두 설계의 값이 계수 정렬 칸 같은 상수 항에 묻혀 갈리지 않기 때문이에요.

<!--proof:alt-bench-->

| 입력 | 배가 기법 | 갈라 정렬 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 무작위 26 글자 n = 90 | 5,992 | 3,757 | 갈라 정렬 · 1.59 배 |
| 무작위 26 글자 n = 91 | 6,047 | 6,654 | 배가 기법 · 1.10 배 |
| 무작위 26 글자 n = 1,039 | 60,047 | 73,999 | 배가 기법 · 1.23 배 |
| 무작위 26 글자 n = 1,040 | 92,324 | 74,008 | 갈라 정렬 · 1.25 배 |
| 무작위 26 글자 n = 100,000 | 8,563,020 | 6,639,408 | 갈라 정렬 · 1.29 배 |
| 전부 같은 글자 n = 100,000 | 46,262,802 | 11,353,439 | 갈라 정렬 · 4.07 배 |

n = 90 에서 91 로 한 글자 늘 때 갈라 정렬의 자료 접근이 77.11 % 늘고, n = 1,039 에서 1,040 으로 늘 때는 배가 기법이 53.75 % · 갈라 정렬이 0.01 % 늡니다.

<!--/proof-->

**순서가 두 번 뒤집힙니다.** 아래쪽 경계는 `n` = 90 과 91 사이이고 거기서는 갈라 정렬의 값이 뜁니다. 재귀가 한
단 깊어지는 자리예요. 위쪽 경계는 1,039 와 1,040 사이이고, 이번에는 배가 기법이 뛰고 갈라 정렬은 거의 그대로입니다.
배가 기법이 그 자리에서 **바퀴를 두 번에서 세 번으로** 늘리기 때문이에요. 「길이 4 조각으로는 안 갈린다」도
산문으로 두지 않고 세어 봅니다.

<!--proof:alt-boundary-->

| n | 길이 4 조각이 같은 자리 짝 | 가장 긴 공통 앞부분 | 배가 기법 바퀴 수 |
| ---: | ---: | ---: | ---: |
| 1,039 | 0 | 3 | 2 |
| 1,040 | 1 | 4 | 3 |

n = 1,040 에서 길이 4 조각이 같은 짝이 처음 생기고, 바퀴가 2 번에서 3 번으로 늡니다.

<!--/proof-->

**갈라 정렬이 늘 적은 것은 아닙니다.** **추가 칸**은 반대로 갈려요. 원래 문자열은 빼고, 문자열을 옮겨 담은 순위
배열과 답 배열까지 넣어 동시에 살아 있는 칸의 최댓값을 셌습니다.

<!--proof:alt-cells-->

| 축 | 배가 기법 | 갈라 정렬 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 추가 칸 (무작위 26 글자 n = 100,000) | 389,908 | 550,535 | 배가 기법 · 1.41 배 |

추가 칸이 배가 기법은 n 의 3.9 배, 갈라 정렬은 n 의 5.5 배입니다.

<!--/proof-->

갈라 정렬은 재귀 단계마다 배열 넷을 새로 잡고 그것이 바닥까지 살아 있어야 합니다. 배가 기법은 어느 시점에도
`sa` · `rank` · `next` · 계수 칸만 살아 있어요. 이 절차가 내주는 것과 얻는 것을 축으로 적으면 이렇습니다.

| 축 | 배가 기법이 내주는 것 · 얻는 것 |
| --- | --- |
| 되풀이가 심한 문자열의 자료 접근 | 내준다 — 전부 같은 글자에서 갈라 정렬보다 많다 |
| 추가 칸 | 얻는다 — 갈라 정렬보다 적다 |
| 구현 길이 | 얻는다 — 재귀가 없고 배열이 넷뿐이다 |
| 길이 91 부터 1,039 까지의 자료 접근 | 얻는다 — 이 구간에서는 배가 기법이 적다 |

과제 규모는 `n` 이 10 만이고 `a` 만 10 만 개인 입력을 허용하므로, **자료 접근만 보면 갈라 정렬이 낫습니다.**
그럼에도 이 글이 배가 기법을 가르치는 까닭은 얻는 것 셋에 있어요. 이 규모에서는 배가 기법의 최악도 약 4,626 만
번이라 1 초 예산 안에 들고, 그때 남는 기준은 추가 칸과 구현 길이입니다. **문자열이 훨씬 길어지거나 되풀이가
훨씬 심해지면 이 판정은 다시 해야 해요.**

### 수식 정의와 유도

길이 `L` 조각과 그 **순위**를 정의합니다. 자리 `i` 의 길이 `L` 조각을 $b_L(i)$ 라 적고, 문자열 끝을 넘으면 남은
만큼만 잘라 씁니다.

$$
b_L(i) = s[i \ldots \min(i+L-1,\ n-1)] \qquad r_L(i) = \bigl|\{\, b_L(j) : 0 \le j < n,\ b_L(j) < b_L(i) \,\}\bigr|
$$

| 기호 | 뜻 |
| --- | --- |
| $L$ | 조각 길이. 바퀴마다 두 배가 된다 |
| $b_L(i)$ | 자리 $i$ 에서 $L$ 글자를 잘라 낸 조각. 끝을 넘으면 남은 만큼만이다 |
| $r_L(i)$ | $b_L(i)$ 보다 사전순으로 앞인 조각의 **종류 수**. 같은 조각을 가진 자리는 같은 값을 받는다 |

**정의가 실제로 그 값을 내는지부터 봅시다.** `s = banana` 에서 $L$ 을 1 · 2 · 4 로 두고 조각을 나열한 뒤 정의대로
세고, 코드의 `rank` 와 나란히 놓습니다.

<!--proof:math-check-->

| k | 조각 길이 2^k | 자리 0 부터의 조각 | 정의대로 매긴 r | 코드의 rank | 서로 다른 조각 수 |
| ---: | ---: | --- | --- | --- | ---: |
| 0 | 1 | b a n a n a | [1, 0, 2, 0, 2, 0] | [98, 97, 110, 97, 110, 97] | 3 |
| 1 | 2 | ba an na an na a | [2, 1, 3, 1, 3, 0] | [2, 1, 3, 1, 3, 0] | 4 |
| 2 | 4 | bana anan nana ana na a | [3, 2, 5, 1, 4, 0] | [3, 2, 5, 1, 4, 0] | 6 |

k = 1 · 2 인 줄은 정의의 값과 코드의 rank 가 글자 그대로 같습니다.

<!--/proof-->

$k = 0$ 인 줄만 다릅니다. 정의는 0 · 1 · 2 이고 코드는 글자 코드예요. **둘은 값이 다르지만 대소 관계와 같음
관계가 같습니다.** 아래 유도가 쓰는 것이 그 두 관계뿐이라 어느 쪽을 넣어도 정렬 결과가 같아요.

$$
r_L(i) < r_L(j) \iff b_L(i) \text{ 가 } b_L(j) \text{ 보다 사전순으로 앞이다} \qquad r_L(i) = r_L(j) \iff b_L(i) = b_L(j)
$$

**첫째로, 쌍 비교가 조각 비교와 같다**는 것을 유도합니다. 자리 $i$ 의 길이 $2L$ 조각은 앞 $L$ 글자와 뒤 $L$ 글자로
정확히 갈리므로, 두 자리 $i$ · $j$ 를 비교하는 일은 앞 절반을 비교하고 같으면 뒤 절반을 비교하는 일과 같아요.
아래 식을 경우 셋으로 가르면 빠지는 자리가 없습니다.

$$
b_{2L}(i) < b_{2L}(j) \iff \bigl(r_L(i),\ r_L(i+L)\bigr) < \bigl(r_L(j),\ r_L(j+L)\bigr) \quad \text{(사전식)}
$$

| 경우 | 조건 | 쌍에서 정해지는 자리 |
| --- | --- | --- |
| 앞 절반이 다르다 | $b_L(i) \ne b_L(j)$ | $r_L$ 이 다르므로 첫 성분에서 정해진다 |
| 앞 절반이 같다 | $b_L(i) = b_L(j)$ | $r_L$ 이 같으므로 둘째 성분, 곧 $b_L(i+L)$ 과 $b_L(j+L)$ 의 순위가 정한다 |
| 뒤 절반이 없다 | $i + L \ge n$ | 조각이 앞 절반에서 끝난다. 짧은 쪽이 앞이므로 가장 작은 값을 준다 — 코드는 0 을 비워 두고 그것을 쓴다 |

**둘째로, 바퀴 수의 상한**이 나옵니다. 조각 길이가 $1, 2, 4, \ldots$ 로 가다가 $L \ge n$ 이 되면 조각이 접미사
전체를 덮고, 접미사는 서로 길이가 달라 같은 것이 없으므로 순위가 전부 달라져요. 바퀴 수를 $R(n)$ 이라 하면
이렇습니다.

$$
R(n) \le \lceil \log_2 n \rceil
$$

<!--proof:math-rounds-->

| n | ⌈log₂ n⌉ | 실측 바퀴 수 | 자료 접근 |
| ---: | ---: | ---: | ---: |
| 10 | 4 | 4 | 1,858 |
| 100 | 7 | 7 | 19,974 |
| 1,000 | 10 | 10 | 273,748 |
| 10,000 | 14 | 14 | 3,823,444 |
| 100,000 | 17 | 17 | 46,262,802 |

전부 같은 글자에서는 5 규모 모두 실측 바퀴 수가 상한과 같습니다.

<!--/proof-->

이 상한이 말하는 것은 **임의의 문자열에서** 바퀴 수가 $\lceil \log_2 n \rceil$ 을 넘지 않는다는 것이고, 표가 잰
다섯 규모만으로는 나오지 않는 진술입니다.

**셋째로, 한 바퀴에 늘리는 배수의 최적값**을 닫습니다. 배수를 $m$ 으로 하면 키가 성분 $m$ 개라 바퀴마다 계수
정렬이 $m$ 번이고, 조각 길이가 $m$ 배씩 가므로 바퀴 수가 $\lceil \log_m n \rceil$ 입니다. 정렬 횟수의 총합을
$P(m)$ 이라 하면 이렇게 돼요.

$$
P(m) = m \left\lceil \log_m n \right\rceil \approx \frac{m}{\ln m} \ln n
$$

```ts
// 식을 그대로 옮긴 조각. 실제 절차는 m = 2 를 박아 둔 것이다.
const passes = (m: number, n: number): number =>
  m * Math.ceil(Math.log(n) / Math.log(m));
```

$\ln n$ 은 $m$ 과 상관없으니 $m / \ln m$ 을 가장 작게 하는 $m$ 을 찾으면 됩니다. 미분하면 이렇습니다.

$$
\frac{d}{dm}\left(\frac{m}{\ln m}\right) = \frac{\ln m - 1}{(\ln m)^2}
$$

분모 $(\ln m)^2$ 은 $m > 1$ 에서 늘 양수입니다. 그래서 부호는 분자 $\ln m - 1$ 이 정해요. $m < e$ 면 음수라
$m / \ln m$ 이 줄고, $m > e$ 면 양수라 늡니다. 가장 작은 자리는 $\ln m = 1$, 곧 $m = e$ 이고, $e$ 는 정수가
아니므로 가장 가까운 정수는 그 자리를 사이에 둔 2 와 3 입니다.

<!--proof:math-optimum-->

| m | m / ln m | m·⌈log_m 100,000⌉ | 자료 접근 실측 |
| ---: | ---: | ---: | ---: |
| 2 | 2.885 | 34 | 46,262,802 |
| 3 | 2.731 | 33 | 42,807,740 |
| 4 | 2.885 | 36 | 45,463,602 |
| 5 | 3.107 | 40 | — |
| 8 | 3.847 | 48 | 57,491,052 |
| 16 | 5.771 | 80 | 93,002,186 |

m / ln m 이 가장 작은 실수는 m = e = 2.718 이고, 정수 2 와 3 의 값 2.885 와 2.731 은 5.7 % 차이입니다.

<!--/proof-->

닫힌 형태가 실측의 모양을 그대로 맞춥니다. $m$ 이 2 · 3 · 4 일 때 $m / \ln m$ 이 가운데에서 가장 작고, 자료 접근도
같은 모양이에요. $m = 4$ 의 $m / \ln m$ 이 $m = 2$ 와 정확히 같은 것은 $4 / \ln 4 = 4 / (2 \ln 2) = 2 / \ln 2$
이기 때문이고, 실측에서도 두 값이 가깝습니다.

### 불변식 — 바퀴가 끝난 시점의 순위는 그 길이 조각의 사전순 대소와 같음을 그대로 담는다

파트 1 은 여섯 글자짜리 문자열 하나에서 답이 나오는 것까지 보였습니다. 그것은 그 입력에서 맞았다는 뜻이지
어떤 입력에서도 맞는다는 뜻이 아니에요. 무엇이 **매 바퀴 참으로 남는지**를 문장으로 세우고 그것이 실제로
유지되는지 확인해 봅시다. 순위가 담아야 할 관계는 둘이고, 다음 바퀴가 둘을 서로 다른 곳에 씁니다.

| 관계 | 다음 바퀴에서 쓰는 곳 | 빠지면 |
| --- | --- | --- |
| 대소 | 3단계의 정렬 두 번 | 쌍의 순서가 조각의 순서와 달라진다 |
| 같음 | 4단계의 쌍 비교 | 「앞 절반이 같다」를 판정할 수 없다 |

> `gap` 이 `L` 인 바퀴가 끝난 직후, 모든 자리 짝 `(i, j)` 에 대해 `rank[i] < rank[j]` 인 것과 자리 `i` 의 길이
> `2L` 조각이 자리 `j` 의 것보다 사전순으로 앞인 것이 서로 필요충분입니다. 그리고 `rank[i] === rank[j]` 인 것과
> 두 조각이 **같은** 것이 서로 필요충분이에요.

「바퀴가 끝난 직후」가 중요합니다. 바퀴 도중에는 정렬만 끝나고 순위가 아직 옛 값이라 두 관계가 잠깐 어긋나요.
**출발점부터 봅시다.** 첫 바퀴에 들어가기 전 `rank[i]` 는 글자 코드이고, 글자 코드의 대소가 알파벳 순서이며
같은 글자면 같은 코드입니다. 그래서 길이 1 조각에 대해 두 관계가 다 참이에요. 바퀴 하나의 걸음마다 두 관계가
유지되는 근거는 이렇습니다.

| 걸음 | 하는 일 | 두 관계가 유지되는 근거 |
| --- | --- | --- |
| 쌍 만들기 | `(front, back)` 을 붙인다 | 앞 절반 · 뒤 절반의 순위가 각각 그 절반의 관계를 담고 있다. 뒤 절반이 없으면 0 이라 가장 작다 |
| 정렬 두 번 | 뒤 · 앞 순서로 안정 정렬한다 | 쌍의 사전식 순서로 늘어선다. 쌍의 사전식 순서가 길이 `2L` 조각의 순서다 |
| 재부여 | 이웃 쌍이 다를 때만 올린다 | 같은 쌍은 붙어 있어 같은 값을, 뒤의 다른 쌍은 더 큰 값을 받는다 |
| 종료 | `span === n` 이면 멈춘다 | 순위가 전부 다르면 조각을 늘려도 관계가 안 바뀐다 |

재부여가 이 논증의 핵심입니다. 늘어선 줄에서 이웃만 비교해도 되는 것은 **같은 쌍을 가진 자리들이 반드시 붙어
있기** 때문이에요. 줄이 쌍 기준으로 늘어서 있으니, 같은 쌍 둘이 떨어져 있다면 그 사이 칸의 쌍은 둘보다 크지도
작지도 않아야 합니다. 그런 쌍은 같은 쌍뿐이라 사이 칸도 같은 무리입니다. 네 입력의 모든 바퀴에서 두 관계를
전수로 대조했습니다.

<!--proof:invariant-rounds-->

| 입력 | 가른 조각 길이 | 바퀴가 끝난 시점의 rank | span | 조각 순서와 대조 |
| --- | ---: | --- | ---: | --- |
| "banana" | 2 | [2, 1, 3, 1, 3, 0] | 4 | 맞다 |
| "banana" | 4 | [3, 2, 5, 1, 4, 0] | 6 | 맞다 |
| "aaaa" | 2 | [1, 1, 1, 0] | 2 | 맞다 |
| "aaaa" | 4 | [3, 2, 1, 0] | 4 | 맞다 |
| "abab" | 2 | [0, 2, 0, 1] | 3 | 맞다 |
| "abab" | 4 | [1, 3, 0, 2] | 4 | 맞다 |
| "mississippi" | 2 | [3, 2, 7, 6, 2, 7, 6, 1, 5, 4, 0] | 8 | 맞다 |
| "mississippi" | 4 | [3, 2, 9, 7, 2, 8, 6, 1, 5, 4, 0] | 10 | 맞다 |
| "mississippi" | 8 | [4, 3, 10, 8, 2, 9, 7, 1, 6, 5, 0] | 11 | 맞다 |

바퀴 9 개에서 자리 짝 499 개를 전수로 대조했고, 순위의 대소 · 같음이 조각의 사전순 대소 · 같음과 틀린 바퀴는 0 개입니다.

<!--/proof-->

**경계에 있는 입력도 확인하고 갑시다.**

<!--proof:invariant-edges-->

| 경계 | 입력 | 바퀴 수 | 답 |
| --- | --- | ---: | --- |
| 길이 1 | "a" | 0 | [0] |
| 두 글자가 같다 | "aa" | 1 | [1, 0] |
| 두 글자가 다르다 | "ab" | 1 | [0, 1] |
| 뒤가 앞보다 작다 | "ba" | 1 | [1, 0] |
| 전부 같은 글자 | "aaaa" | 2 | [3, 2, 1, 0] |
| 전부 다른 글자 | "abcd" | 1 | [0, 1, 2, 3] |
| 되풀이 | "abab" | 2 | [2, 0, 3, 1] |

<!--/proof-->

길이 1 은 바퀴가 한 번도 실행되지 않는 자리입니다. `gap < n` 이 처음부터 거짓이라 `sa` 가 초기값 `[0]` 그대로
나가요. 전부 다른 글자는 반대쪽 경계로, 첫 바퀴의 재부여에서 `span` 이 바로 `n` 이 되어 한 바퀴로 끝납니다.

**이제 깨뜨려 봅시다.** 두 관계를 지키던 줄은 재부여의 판정 한 줄이에요. 「어차피 정렬이 끝난 줄이니 앞 성분만
비교해도 순서는 그대로겠다」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
if (front(a) !== front(b)) top++; // 뒤 성분을 비교하지 않았다
```

<!--proof:mutant-front-only-->

| 입력 | 정본이 낸 답 | 앞 성분만 비교한 답 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 "banana" | [5, 3, 1, 0, 4, 2] | [5, 3, 1, 0, 4, 2] | 같다 |
| "aaaa" | [3, 2, 1, 0] | [3, 2, 0, 1] | 어긋난다 |
| "abab" | [2, 0, 3, 1] | [2, 0, 3, 1] | 같다 |
| "mississippi" | [10, 7, 4, 1, 0, 9, 8, 6, 3, 5, 2] | [10, 7, 4, 1, 0, 9, 8, 6, 3, 5, 2] | 같다 |
| "abc" | [0, 1, 2] | [0, 1, 2] | 같다 |
| "aab" | [0, 1, 2] | [1, 0, 2] | 어긋난다 |
| "cabbage" | [1, 4, 3, 2, 0, 6, 5] | [4, 1, 3, 2, 0, 6, 5] | 어긋난다 |
| "abracadabra" | [10, 7, 0, 3, 5, 8, 1, 4, 6, 9, 2] | [10, 7, 3, 5, 0, 8, 1, 4, 6, 9, 2] | 어긋난다 |

8 입력 중 4 입력에서 답이 어긋났고, "banana" · "abab" · "mississippi" · "abc" 에서는 같았습니다.

<!--/proof-->

**전개 입력에서는 답이 안 바뀝니다.** `banana` 만 시험하면 이 잘못을 못 찾아요. 전개 입력은 첫 바퀴에서 앞 성분이
같은 자리가 뒤 성분까지 같아서, 뒤 성분을 안 봐도 무리가 같게 나오기 때문입니다. `"aaaa"` 의 첫 바퀴를 두
판정으로 나란히 매기면 이유가 보입니다.

<!--proof:mutant-front-only-aaaa-->

| 재부여 판정 | 첫 바퀴 뒤 rank | 무리 수 |
| --- | --- | ---: |
| 쌍의 두 성분을 다 비교 | [1, 1, 1, 0] | 2 |
| 앞 성분만 비교 | [0, 0, 0, 0] | 1 |

첫 바퀴의 쌍은 자리 순서로 (97, 98) · (97, 98) · (97, 98) · (97, 0) 입니다. 앞 성분만 비교하면 네 자리가 무리 1 개로 남습니다.

<!--/proof-->

옳은 재부여에서는 자리 3 만 뒤 성분 0 으로 갈려 무리가 둘인데, 앞 성분만 보면 네 자리의 앞 성분이 전부 97 이라
하나도 안 갈립니다. 「같음」을 잘못 담은 순위를 다음 바퀴가 그대로 물려받아, 다음 바퀴의 판정도 앞 성분만 보므로
또 안 갈려요. 결국 정렬이 남긴 앞뒤가 그대로 답이 됩니다.

### 비용 계산

#### 비용을 세는 과정

실행 한 번을 두 무리로 가릅니다. 글자를 읽어 첫 순위를 매기는 자리가 하나이고, 그다음은 바퀴를 되풀이하는
자리예요. 전개의 아홉 걸음에 각각 얼마가 들었는지 셉니다.

<!--proof:perf-count-->

| 무리 | 걸음 | 자료 접근 |
| --- | --- | ---: |
| 첫 순위 매기기 | T1 | 6 |
| 1 번째 바퀴 | T2~T5 | 916 |
| 2 번째 바퀴 | T6~T9 | 168 |
| 합계 | T1~T9 | 1,090 |

첫 바퀴가 둘째 바퀴의 5.5 배입니다. 첫 바퀴의 계수 정렬은 글자 코드 범위에 맞춘 129 칸을 잡고, 둘째 바퀴는 span + 1 = 5 칸만 잡습니다.

<!--/proof-->

첫 바퀴(T2\~T5)가 둘째 바퀴(T6\~T9)보다 훨씬 많은 것은 여섯 글자짜리 입력의 특징입니다. 첫 바퀴의 계수 정렬은
글자 코드 범위에 맞춰 칸을 잡고 그 칸을 누적합으로 한 번 지나가는데, 둘째 바퀴는 `span` 이 작아 칸이 몇 개
안 돼요. 규모가 크면 이 항이 `n` 에 묻힙니다.

<!--proof:perf-scale-->

| 입력 | n | 바퀴 수 R | 자료 접근 | 바퀴 하나당 n 의 몇 배 |
| --- | ---: | ---: | ---: | ---: |
| 무작위 26 글자 | 100,000 | 3 | 8,563,020 | 28.5 |
| 전부 같은 글자 | 100,000 | 17 | 46,262,802 | 27.2 |

바퀴 하나당 자료 접근이 n 의 28.5 배와 27.2 배로 모이고, 두 입력을 가르는 것은 바퀴 수입니다.

<!--/proof-->

바퀴 하나가 `n` 의 몇 배인지를 코드에서 세면 이렇습니다. `span` 은 그 바퀴에 계수 정렬이 잡는 칸 수를 정하는
값이에요.

| 조각 | 자리 하나에서 하는 자료 접근 | 합 |
| --- | --- | --- |
| 계수 정렬의 세기 | `order` 한 칸 · 키의 `rank` 한 칸 · `count` 읽기 한 번 · 쓰기 한 번 | `4n` |
| 계수 정렬의 누적합 | 칸마다 두 칸 읽기 · 한 칸 쓰기 | `3·span` |
| 계수 정렬의 되놓기 | `order` · 키의 `rank` · `count` 읽기 · 쓰기 · 다시 읽기 · `out` 쓰기 | `6n` |
| 재부여 | `sa` 두 칸 · 쌍의 네 값 · `next` 한 칸. 앞 성분이 다르면 뒤 성분은 안 읽는다 | `7n` 이하 |
| 바퀴 하나 | 계수 정렬 두 번 + 재부여 한 번 | `27n + 6·span` 이하 |

뒤 조각이 없는 자리는 `rank` 를 안 읽어 한 번씩 적고, 재부여는 앞 성분에서 갈리면 뒤 성분을 안 읽으니, 실측이
`27n` 언저리에 모이는 것이 이 셈과 맞습니다. 안 센 것은 자리 번호를 하나 올리는 일과 두 정수를 비교하는 일인데,
둘 다 자료 접근 수에 비례하므로 총식의 차수가 그대로예요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요. 글자 집합
크기를 `Σ` 라 적겠습니다. 이 코드에서는 `Σ = 128` 입니다.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 글자가 전부 다르다) | `O(n + Σ)` | `Θ(n + Σ)` — 바퀴가 한 번이다 |
| **평균적인 경우** (글자를 균등하게 뽑는다고 두면) | `O(n log log n)` | 타이트한 값은 확인 안 함 |
| **최악의 경우** (전부 같은 글자) | `O(n log n)` | `Θ(n log n)` — 실제로 도달한다 |

세 줄이 다른 것이 이 절차의 성질입니다. 바퀴 수가 「접미사 짝이 앞부분을 얼마나 길게 공유하는가」에 달렸고,
그 값이 입력마다 달라요. 가장 긴 공통 앞부분 길이를 `K` 라 하면 바퀴 수는 `⌈log₂(K + 1)⌉` 언저리입니다.

| 입력 | `K` | 바퀴 수 `R` |
| --- | --- | --- |
| 첫 글자가 전부 다르다 | 0 | 1 |
| 전부 같은 글자 | `n − 1` | `⌈log₂ n⌉` — 상한 |
| 글자를 균등하게 뽑는다 | `log n` 언저리 | `log log n` 언저리 |

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리는 첫 순위 매기기 하나뿐이에요 — 좌표 압축도 해시도
쓰지 않습니다.

$$
\text{자료 접근} = \Theta\bigl((n + \Sigma)\cdot R\bigr), \qquad R \le \lceil \log_2 n \rceil
$$

$$
\text{추가 칸} = \Theta(n + \Sigma) \quad \text{— sa · rank · next 각 } n \text{ 칸과 계수 칸 } \max(\Sigma, \text{span}) + 1 \text{ 칸}
$$

**최악 보장입니다.** 바퀴 수의 상한이 입력의 내용과 상관없이 `⌈log₂ n⌉` 이고, 그 상한을 내는 논증에 확률이 한
글자도 들어가지 않아요. 평균 줄의 `log log n` 은 성격이 다릅니다 — **글자를 균등하게 뽑는다는 입력 분포에 대한
기댓값**이고, 구현이 만드는 무작위성이 아니에요.

#### 최악을 만드는 입력

바퀴 수를 최대로 만들려면 **접미사 짝이 앞부분을 최대한 길게 공유하게** 해야 합니다. 그런 모양을 여럿 세워
실제로 재 봅시다.

<!--proof:worst-shape-->

| 입력의 모양 | 바퀴 수 | 자료 접근 | 추가 칸 |
| --- | ---: | ---: | ---: |
| 전부 같은 글자 | 17 | 46,262,802 | 365,537 |
| 두 글자가 번갈아 나온다 | 17 | 46,262,864 | 365,538 |
| 앞이 다 같고 끝만 다르다 | 17 | 46,262,881 | 365,538 |
| 여섯 글자가 되풀이된다 | 17 | 46,261,274 | 365,530 |
| 무작위 두 글자 | 5 | 13,806,232 | 351,104 |
| 무작위 26 글자 | 3 | 8,563,020 | 389,908 |
| 글자가 오름차순으로 늘어선다 | 12 | 32,918,230 | 353,249 |

n = 100,000 입니다. 바퀴 수가 상한 17 에 이른 모양이 4 개이고, 그 안의 자료 접근 차이는 0.0035 % 입니다. 자료 접근이 가장 많은 것은 「앞이 다 같고 끝만 다르다」 입니다.

<!--/proof-->

**바퀴 수 17 을 채우는 모양이 하나가 아닙니다.** 네 모양이 다 상한에 이르고, 되풀이가 주기 1 이든 2 이든 6 이든
바퀴 수가 같으면 값이 거의 같아요. 그 넷의 차이는 바퀴 수가 아니라 마지막 바퀴에서 `span` 이 얼마나 컸는가의
차이입니다.

| 모양 | 되풀이 주기 | 앞부분을 길게 공유하는 짝 |
| --- | --- | --- |
| `aaaa…a` | 1 | 어떤 두 접미사도 짧은 쪽 길이만큼 공유한다 |
| `abab…` | 2 | 자리가 둘씩 짝지어 길게 공유한다 |
| `aaa…ab` | 없음 | 앞의 자리들이 서로 길게 공유한다 |
| `abcabb…` | 6 | 여섯 자리씩 짝지어 길게 공유한다 |

**「정렬된 문자열이 최악이다」는 이 절차에서 거짓입니다.** 물려받은 통념을 검증 없이 쓰지 않고 실행으로
확인해 봤어요.

<!--proof:worst-sorted-->

| n | 무작위 바퀴 | 무작위 접근 | 정렬 바퀴 | 정렬 접근 | 많은 쪽 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1,000 | 2 | 57,878 | 6 | 169,946 | 정렬된 쪽 |
| 10,000 | 3 | 862,933 | 9 | 2,492,680 | 정렬된 쪽 |

<!--/proof-->

정렬된 문자열이 무작위보다 많이 드는 것은 맞습니다. 같은 글자가 길게 이어지는 구간이 생기니까 바퀴가 늘어요.
하지만 **최악은 아닙니다.** 앞의 표에서 `n = 100,000` 의 정렬된 문자열은 12 바퀴이고 전부 같은 글자는 17
바퀴예요. 정렬된 문자열은 글자마다 구간이 갈라져 있어서 가장 긴 공통 앞부분이 `n / 26` 언저리에 그칩니다.
무엇을 최악으로 만드는가에 따라 입력이 다릅니다.

| 최악으로 만들 값 | 입력 |
| --- | --- |
| 바퀴 수 | `a` 100,000 개(또는 되풀이 주기가 짧은 것) |
| 자료 접근 | `a` 99,999 개 뒤에 `b` 하나 |
| 추가 칸 | 무작위 26 글자 |

**추가 칸의 최악이 자료 접근의 최악과 반대쪽 입력입니다.** 계수 칸이 `span` 만큼 잡히는데, `span` 은 순위가
빨리 갈릴수록 커져요. 무작위 26 글자는 첫 재부여에서 `span` 이 이미 크게 잡히고, 전부 같은 글자는 `span` 이 2
부터 천천히 자랍니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 길이 `L` 조각의 순위를 이미 알고 있으면 길이 `2L` 조각의
순서는 **순위 두 개를 이어 붙인 쌍**으로 정해지므로, 조각을 두 배씩 늘려 가면 글자를 다시 읽지 않고
`⌈log₂ n⌉` 바퀴 안에 접미사 배열이 나옵니다.

```text
글자 코드를 순위로 → 쌍을 만든다 → 계수 정렬 두 번 → 같은 쌍끼리 묶어 순위를 다시 매긴다 → 다 갈리면 멈춘다
└ 글자를 읽는 건 여기뿐         └ 뒤 성분 먼저 · 둘 다 안정   └ 이웃만 비교한다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T5 는 `rank` 를 `[2, 1, 3, 1, 3, 0]` 으로 만든 걸음이고, 자리 1 과 3 이
둘 다 1 이었어요. 그런데 T8 이 낸 줄에서는 자리 3 이 자리 1 보다 앞에 있습니다. 같은 순위였던 둘의 앞뒤를 정한
것은 무엇일까요?

### 접미사 정렬 배열

풀 파일: [`suffixArray.ts`](./suffixArray.ts) · 테스트: [`suffixArray.test.ts`](./suffixArray.test.ts) · 실행: `bun test src/algorithms/string/suffixArray/suffixArray.test.ts`

#### 한 줄 요약

> `suffixArray(s)`는 문자열을 받아, 모든 접미사를 사전순으로 정렬했을 때 각 접미사의 시작 인덱스를 순서대로 담은 배열을 반환한다.

#### 스토리

생물정보학 연구소의 태호는 긴 유전자 서열 안에서 반복 구간이나 패턴 분포를 분석하고 싶다. 모든 위치에서 시작하는 부분 서열을 정렬된 상태로 보면 이런 분석이 훨씬 쉬워진다.

서열의 길이가 수십만에 달하는 만큼, 모든 접미사를 단순 정렬로 처리하는 방법은 시간이 너무 오래 걸린다. 태호에게는 대규모 문자열에서도 빠르게 접미사 순서를 결정하는 도구가 필요하다.

#### 함수 인터페이스

```ts
export function suffixArray(s: string): number[];
```

- `s` — 입력 문자열
- 반환 — 길이 $n = |s|$의 정수 배열. `result[k]`는 $k$번째로 작은 접미사의 시작 인덱스(0-based).

#### 제약 조건

- $1 \leq |s| \leq 10^5$
- 문자 집합: 소문자 영문 알파벳 (`a`–`z`)
- 시간 복잡도: $O(n \log n)$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

문자열 $s$(길이 $n$)의 모든 접미사 $\{ s[i \ldots n-1] \mid 0 \leq i < n \}$를 사전순(lexicographic order)으로 정렬했을 때, 각 접미사의 시작 인덱스를 담은 배열을 반환한다.

$$\text{SA}[k] = i \;\iff\; s[i \ldots n-1] \text{은 } (k+1)\text{번째로 작은 접미사}$$

두 접미사 $s[i \ldots]$와 $s[j \ldots]$의 사전 순서는 일반적인 문자열 비교 규칙을 따른다.

#### 예시

```ts
suffixArray("banana");
// [5, 3, 1, 0, 4, 2]
// sa[0]=5 → "a"
// sa[1]=3 → "ana"
// sa[2]=1 → "anana"
// sa[3]=0 → "banana"
// sa[4]=4 → "na"
// sa[5]=2 → "nana"

suffixArray("abc");
// [0, 1, 2] — "a" < "ab" < "abc"... 가장 짧은 접미사부터 순서대로

suffixArray("aaaa");
// [3, 2, 1, 0] — 짧은 접미사일수록 사전순 앞

suffixArray("a");
// [0] — 단일 문자
```
