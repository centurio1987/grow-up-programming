# 접미사 자동자 — 끝나는 자리가 같은 부분 문자열을 한 상태로 묶으면 상태가 2n 개를 넘지 않는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 부분 문자열을 전부
집합에 담는 방법에서 출발해 끝나는 자리 집합으로 묶은 상태까지 가고, 그 상태를 준비되는 차례대로 값으로 푼 뒤,
실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

문자열 하나를 한 번 전처리해 두고 두 가지 물음에 답하는 과제입니다. 하나는 **서로 다른 부분 문자열이 몇
개인가**이고, 다른 하나는 **주어진 문자열이 부분 문자열인가**예요. 부분 문자열은 원래 문자열에서 연속한 한
토막이고, 빈 문자열은 개수에 넣지 않습니다. 길이가 `n` 이면 부분 문자열은 `n(n+1)/2` 개까지 나올 수 있어서,
하나씩 만들어 세는 방법은 규모가 커지면 쓸 수 없어요.

이 글은 부분 문자열을 **끝나는 자리**로 묶습니다. 부분 문자열 하나가 원래 문자열 안에서 끝나는 자리를 모두 모은
것을 그 문자열의 **끝나는 자리 집합**이라고 부릅니다. 문자열 `aabab` 에서 부분 문자열이 놓인 자리를 전부
그리고, 끝나는 자리 집합이 같은 것끼리 한 묶음으로 모았습니다. 자리는 0 부터 셉니다.

<!--fig:concept-endpos-->
![aabab 의 부분 문자열이 놓인 자리 전부 — 끝나는 자리 집합이 같은 것끼리 한 묶음](./figs/concept-endpos.svg)

`ba` · `aba` · `aaba` 는 셋 다 자리 3 에서만 끝나서 한 묶음이고, `b` 와 `ab` 는 자리 2 와 4 에서 끝나서 한
묶음입니다. 한 묶음 안의 문자열은 길이가 하나씩 이어지고, 짧은 것이 긴 것의 끝부분이에요. 이 묶음 하나를
**상태** 하나로 두고, 상태 사이를 글자로 잇는 구조를 **접미사 자동자**(suffix automaton)라고 부릅니다. 상태마다
담는 문자열과 개수를 적으면 이렇습니다.

<!--proof:concept-count-->

| 상태 | 담는 문자열 | 끝나는 자리 | 가장 긴 것의 길이 | 담는 개수 |
| --- | --- | --- | ---: | ---: |
| 상태 1 | a | {0, 1, 3} | 1 | 1 |
| 상태 2 | aa | {1} | 2 | 1 |
| 상태 3 | aab | {2} | 3 | 1 |
| 상태 4 | ba · aba · aaba | {3} | 4 | 3 |
| 상태 5 | bab · abab · aabab | {4} | 5 | 3 |
| 상태 6 | b · ab | {2, 4} | 2 | 2 |

뿌리를 뺀 상태 6 개가 담는 개수를 더하면 11 이고, "aabab" 의 서로 다른 부분 문자열도 11 개입니다.

<!--/proof-->

상태가 담는 개수를 더하면 서로 다른 부분 문자열의 개수가 나옵니다. 상태에는 둘이 더 붙어요. 하나는 **전이**로,
그 상태의 문자열 뒤에 글자 하나를 붙였을 때 어느 상태로 가는지를 적은 것입니다. 다른 하나는 **접미사 링크**로,
그 상태의 가장 짧은 문자열에서 앞 글자 하나를 뗀 것이 든 상태를 가리키는 화살표예요. `aabab` 의 접미사 자동자를
그리면 이렇게 생겼습니다.

<!--fig:concept-automaton-->
![aabab 의 접미사 자동자 — 굵은 실선은 전이, 대시는 접미사 링크](./figs/concept-automaton.svg)

상태 이름 자리에 그 상태가 담는 문자열을 적었습니다. 굵은 실선이 전이이고 그 위의 글자가 붙이는 글자예요.
대시가 접미사 링크입니다. 상태 4 의 가장 짧은 문자열 `ba` 에서 앞 글자를 떼면 `a` 이고, `a` 는 상태 1 에 있어서
상태 4 의 대시가 상태 1 로 갑니다.

두 물음은 이 구조 위에서 짧아집니다. 부분 문자열인지는 뿌리에서 글자마다 전이를 따라가 끝까지 가는지로 알고,
개수는 상태마다 담는 개수를 더하면 됩니다. 만드는 쪽은 글자를 왼쪽부터 하나씩 붙이며 상태를 한두 개씩 늘리고,
접미사 링크를 거슬러 올라가며 전이를 채워요. 상태는 `2n-1` 개를 넘지 않고, 결과만 적으면 만들기가 `O(n)`,
찾기가 검색 문자열 길이에 비례하는 `O(m)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **부분 문자열 · 접두사 · 접미사.** 부분 문자열은 연속한 한 토막이고, 맨 앞에서 시작하는 토막이 접두사, 맨 뒤에서
  끝나는 토막이 접미사입니다. `aab` 의 접미사는 `aab` · `ab` · `b` 와 빈 문자열이에요.
- **트라이.** 여러 문자열의 접두사마다 마디를 하나씩 두고, 글자 하나를 붙인 접두사를 자식으로 잇는 나무입니다.
  모르면 [`trie`](../trie/trie-guide.md) 를 먼저 읽으세요. 이 글은 트라이를 가장 단순한 후보로만 씁니다.
- **상태와 전이로 문자열을 읽는 구조.** 상태 하나에서 글자 하나를 받아 다음 상태로 가는 구조입니다. 노드마다 링크를
  하나 더 달아 끝부분으로 옮겨 가는 모양은 [`ahoCorasick`](../ahoCorasick/ahoCorasick-guide.md) 의 실패 링크가
  같은 착상이에요. 모르면 그 가이드의 「먼저 알아 둘 개념」 절을 보세요.
- **집합이 같은 것끼리 묶기.** 두 대상에 붙은 집합이 완전히 같을 때만 한 묶음에 넣는 것입니다. 원소 수가 같은 것과는
  다릅니다.

이름이 비슷한 과제를 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 다루는 가이드 |
| --- | --- |
| 패턴 여럿의 시작 자리를 텍스트 한 번의 읽기로 전부 찾는다 | [`ahoCorasick`](../ahoCorasick/ahoCorasick-guide.md) |
| 고정된 문자열의 접미사를 사전순으로 늘어놓는다 | [`suffixArray`](../suffixArray/suffixArray-guide.md) |
| 사전순으로 이웃한 접미사의 공통 앞부분 길이를 구한다 | [`kasaiLcp`](../kasaiLcp/kasaiLcp-guide.md) |
| 고정된 문자열의 서로 다른 부분 문자열을 세고, 부분 문자열인지 묻는다 | 이 글 |

### 아이디어를 떠올리는 과정 — 부분 문자열을 전부 집합에 담는 방법에서 끝나는 자리 집합으로 묶은 상태까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다.

```ts
export class SuffixAutomaton {
  constructor(s: string);
  countDistinctSubstrings(): number;
  contains(t: string): boolean;
}
```

- 입력: 생성자가 받는 문자열 `s`. 글자는 소문자 영문(`a`–`z`)입니다.
- 출력: `countDistinctSubstrings()` 는 `s` 의 서로 다른 비어 있지 않은 부분 문자열의 개수이고, `contains(t)` 는
  `t` 가 `s` 의 부분 문자열이면 `true` 입니다. 빈 문자열 `t` 는 늘 `true` 이고, `s` 보다 긴 `t` 는 `false` 예요.
- 규모: `s` 와 `t` 의 길이가 각각 10 만 이하입니다. 비용은 흔한 채점 환경의 예산인 1 초(단순 연산 1 초에 1 억 번)와
  256 MB 에 대어 잽니다.

이 글이 쓰는 기호를 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `n` | 전처리할 문자열의 길이 | `n ≤ 100,000` |
| `s` | 전처리할 문자열. 생성자가 받습니다 | 소문자 영문 |
| `t` | `contains` 가 받는 검색 문자열 | 길이 `m ≤ 100,000` |
| `m` | 검색 문자열의 길이 | `m ≤ 100,000` |
| `c` | 지금 붙이고 있는 글자 | `s` 에서 하나씩 꺼냅니다 |
| `endpos(w)` | 문자열 `w` 가 `s` 안에서 끝나는 자리의 집합. 자리는 0 부터 셉니다 | — |
| `len[v]` | 상태 `v` 가 담는 문자열 가운데 가장 긴 것의 길이 | 뿌리는 0 |
| `link[v]` | 상태 `v` 의 접미사 링크 | 뿌리만 `-1` |
| `next[v]` | 상태 `v` 의 전이 표. 글자 하나를 받으면 어느 상태로 가는가 | — |
| `last` | 지금까지 읽은 접두사 전체를 담는 상태 | 처음엔 뿌리 |
| `cur` · `p` · `q` · `clone` | 글자 하나를 붙이는 동안만 쓰는 상태 이름. 차례로 새 상태 · 거슬러 올라가는 자리 · 그 자리의 전이가 가리키는 상태 · 복제 상태 | — |

비용은 글 전체에서 **자료 접근** 하나로 셉니다. 배열 칸이나 전이 표 항목을 읽거나 쓴 횟수와 문자열 글자를 읽은
횟수의 합이에요. 전이 표 항목 하나는 배열 칸 하나로 치고, 지역 변수를 바꾸거나 반복 조건을 비교한 것은 세지
않습니다. 접미사 배열 · 카사이 LCP 가이드가 배열 칸과 글자 읽기를 세는 방식과 같아요.

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 시작 자리와 끝 자리를 다 잡아 토막을 만들고 집합에
넣으면 개수가 나오고, `contains` 는 그 집합에 물으면 돼요.

```ts
const seen = new Set<string>();
for (let i = 0; i < s.length; i++) {
  for (let j = i + 1; j <= s.length; j++) {
    seen.add(s.slice(i, j)); // 토막을 글자까지 다 만들어 넣는다
  }
}
```

무작위 문자열에서 이 방법과, 이 글이 만들 접미사 자동자의 자료 접근을 세었습니다.

<!--proof:origin-cost-->

| n | 서로 다른 부분 문자열 | 집합에 전부 담기 | 시간 | 접미사 자동자 | 시간 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 36 | 156 | 0.001 초 미만 | 120 | 0.001 초 미만 |
| 64 | 2,039 | 47,840 | 0.001 초 미만 | 1,395 | 0.001 초 미만 |
| 512 | 130,703 | 22,632,192 | 0.226 초 | 11,633 | 0.001 초 미만 |
| 100,000 | 4,999,757,733 | 166,676,666,750,000 | 1,666,767 초 | 2,310,526 | 0.023 초 |

문자열은 mulberry32(씨앗 0x9e3779b9)로 스물여섯 글자에서 고른 무작위 문자열입니다. 시간은 자료 접근을 초당 1 억 번으로 나눈 값입니다. 집합에 전부 담기의 n = 100,000 줄은 식 n(n+1)(n+2)/6 + n(n+1)/2 로 낸 값이고, 그 식은 위 세 규모에서 실행한 값과 같습니다.

<!--/proof-->

과제 규모 `n = 100,000` 에서 집합에 전부 담기는 166 조 번이 넘어 예산 1 초를 한참 넘기고, 서로 다른 부분 문자열만
해도 50 억 개라 담을 메모리도 없어요. 자료 접근이 세제곱으로 자라는 것은 토막을 **글자까지 다 만들기** 때문입니다.
무엇을 되풀이하는지부터 세어 봐야 해요. 전개에서 끝까지 쓸 작은 입력을 여기서 잡겠습니다. 다섯 글자 `aabab`
이에요. 시작 자리마다 만든 부분 문자열을 적었습니다.

<!--proof:origin-repeat-->

| 시작 자리 | 거기서 만든 부분 문자열 | 개수 |
| ---: | --- | ---: |
| 0 | a · aa · aab · aaba · aabab | 5 |
| 1 | a · ab · aba · abab | 4 |
| 2 | b · ba · bab | 3 |
| 3 | a · ab | 2 |
| 4 | b | 1 |

모두 15 개를 만들었고 그중 서로 다른 것은 11 개라, 같은 것을 4 번 다시 만들었습니다.

<!--/proof-->

시작 자리 0 과 1 과 3 에서 `a` 를 세 번 만들었고, 시작 자리 1 과 3 에서 `ab` 를 두 번 만들었습니다. **같은
문자열이 여러 번 만들어지는 것은 그 문자열이 여러 자리에 나타나기 때문이에요.** 같은 토막을 한 번만 적는 가장
단순한 후보는 모든 접미사를 트라이에 담는 것입니다. 트라이에서는 서로 다른 부분 문자열 하나가 마디 하나라,
찾기는 검색 문자열 길이만큼 내려가면 되고 개수는 마디 수에서 뿌리를 빼면 돼요. 이 후보의 마디 수를 이 글이 만들
접미사 자동자의 상태 수와 나란히 세었습니다.

<!--proof:origin-trie-->

| n | 문자열 모양 | 접미사 트라이의 마디 | 접미사 자동자의 상태 |
| ---: | --- | ---: | ---: |
| 8 | 무작위 26 글자 | 37 | 9 |
| 8 | 첫 글자만 다르다 | 16 | 15 |
| 16 | 무작위 26 글자 | 135 | 19 |
| 16 | 첫 글자만 다르다 | 32 | 31 |
| 32 | 무작위 26 글자 | 518 | 42 |
| 32 | 첫 글자만 다르다 | 64 | 63 |
| 64 | 무작위 26 글자 | 2,040 | 85 |
| 64 | 첫 글자만 다르다 | 128 | 127 |
| 100,000 | 무작위 26 글자 | 4,999,757,734 | 127,296 |

트라이의 마디는 서로 다른 부분 문자열마다 하나에 뿌리 하나를 더한 수이고, 위 여덟 줄에서 그 수가 직접 만든 트라이의 마디 수와 같습니다. 그래서 n = 100,000 줄의 마디 수는 트라이를 만들지 않고 정본이 센 부분 문자열 수에 1 을 더해 냈습니다. 마디 하나를 4 바이트로만 어림해도 20.0 GB 입니다.

<!--/proof-->

**마디 수가 문자열 길이의 제곱으로 자랍니다.** 무작위 문자열은 같은 토막이 거의 없어서 서로 다른 부분 문자열이
`n(n+1)/2` 에 가깝고, 트라이는 그만큼 마디를 만들어요. 반대로 첫 글자만 다른 문자열에서는 마디와 상태가 거의
같습니다. 부분 문자열이 많아서 곤란한 입력일수록 트라이가 무거워지고, 상태 수는 어느 모양에서도 `n` 에 비례해요.
그 차이가 어디서 오는지 전개 입력의 트라이에서 봅시다. 마디마다 그 마디의 문자열이 끝나는 자리를 재고, 끝나는
자리가 같은 마디끼리 합쳤을 때 어느 상태가 되는지 적었습니다.

| ba | {3} | 상태 4 |
| bab | {4} | 상태 5 |

마디 12 개가 상태 7 개로 합쳐집니다. 마디 66 쌍 가운데 「끝나는 자리가 같다」와 「같은 상태로 합쳐진다」가 일치하는 쌍이 66 쌍입니다.

<!--/proof-->

`aaba` · `aba` · `ba` 는 트라이의 서로 다른 가지에 있는 마디 셋인데, 셋 다 자리 3 에서만 끝나서 상태 4 하나로
합쳐집니다. 합친 마디의 문자열 뒤에는 붙일 수 있는 글자도 같아요. 끝나는 자리가 같으면 그다음 자리의 글자도
같기 때문입니다. 그러니 「트라이를 다 만든 뒤 끝나는 자리가 같은 마디를 합친다」가 둘째 후보인데, 합치기 전에
트라이를 먼저 만들어야 해서 마디 수의 문제가 그대로 남습니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **끝나는 자리 집합으로 묶은 상태**입니다. 트라이를 거치지 않고, 글자를 왼쪽부터 하나씩
붙이며 그 묶음을 곧바로 유지해요. 묶음이 어떻게 생겼는지, 글자 하나를 붙일 때 묶음이 어떻게 바뀌는지, 다 만든
뒤 어떻게 쓰는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 끝나는 자리 집합으로 묶은 상태

이 아이디어를 한 문장으로 줄이면 이렇습니다. **끝나는 자리 집합이 같은 부분 문자열을 한 상태에 담고, 글자를 하나씩
붙일 때마다 접두사 전체를 담는 상태를 만든 뒤 접미사 링크를 거슬러 올라가며 전이를 채우고, 길이가 안 맞는 상태만
둘로 가릅니다.** 끝나는 자리 집합과 접미사 링크는 처음 보는 사람에게 낯선 개념이라 먼저 따로 설명하고, 그다음
실현하는 순서대로 다섯 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 글자마다 | 1단계 접두사 전체를 담는 상태 만들기 | 새 상태 `cur` 를 만들고 `len[cur]` 를 `len[last] + 1` 로 둔다 | 앞 글자에서 정한 `last` |
| 글자마다 | 2단계 접미사 링크를 거슬러 올라가며 빈 전이 채우기 | `last` 에서 접미사 링크를 따라 오르며 `c` 전이가 없는 상태에 `cur` 를 적는다 | 1단계의 `cur` · 앞 글자까지의 접미사 링크 |
| 글자마다 | 3단계 멈춘 자리에서 접미사 링크 정하기 | 뿌리를 지났으면 뿌리, 길이가 맞으면 `q` 를 `cur` 의 접미사 링크로 둔다 | 2단계가 멈춘 `p` |
| 글자마다, 길이가 안 맞을 때만 | 4단계 복제 상태로 q 가르기 | `q` 의 짧은 쪽을 복제 상태로 떼어 내고 전이와 링크를 옮긴다 | 3단계의 `p` · `q` |
| 질의마다 | 5단계 개수 세기와 찾기 | 상태마다 `len[v] − len[link[v]]` 를 더하고, 전이를 따라간다 | 1~4단계가 만든 자동자 |

#### 먼저 알아 둘 개념 — 끝나는 자리 집합

부분 문자열 `w` 의 끝나는 자리 집합 `endpos(w)` 는 **`w` 가 `s` 안에 나타나는 자리마다 그 마지막 글자의 자리를 모은
것**입니다. 끝나는 자리 집합이 같은 부분 문자열들이 한 상태에 들어가요.

##### 입력 위의 끝나는 자리 집합

상태마다 가장 긴 문자열이 `aabab` 의 어느 자리에 놓이는지 그렸습니다. 막대의 오른쪽 끝이 끝나는 자리예요.

<!--fig:build-endpos-longest-->
![상태마다 가장 긴 문자열이 놓인 자리 — 막대의 오른쪽 끝이 끝나는 자리다](./figs/build-endpos-longest.svg)

상태 6 의 가장 긴 문자열 `ab` 는 두 번 나타나서 막대가 둘이고, 끝나는 자리가 2 와 4 입니다. 상태 4 의 `aaba` 는
한 번 나타나서 끝나는 자리가 3 하나예요. 같은 상태의 짧은 문자열은 이 막대의 오른쪽 끝을 그대로 두고 왼쪽을 깎은
것이라, 끝나는 자리가 가장 긴 것과 같습니다.

##### 상태 하나를 읽는 법

상태 4 를 골라 읽어 보겠습니다. 가장 긴 문자열 `aaba` 의 접미사를 긴 것부터 늘어놓고, 끝나는 자리와 그것이 든
상태를 봐요.

<!--proof:build-endpos-read-->

| 길이 | 접미사 | 끝나는 자리 | 담긴 상태 |
| ---: | --- | --- | --- |
| 4 | aaba | {3} | 상태 4 |
| 3 | aba | {3} | 상태 4 |
| 2 | ba | {3} | 상태 4 |
| 1 | a | {0, 1, 3} | 상태 1 |
| 0 | 빈 문자열 | 모든 자리 | 상태 0 |

끝나는 자리가 {3} 인 것은 길이 2 부터 4 까지 3 개이고, 길이 1 에서 끝나는 자리가 늘어나 다른 상태로 넘어갑니다.

<!--/proof-->

길이 4 · 3 · 2 는 끝나는 자리가 `{3}` 으로 같아 상태 4 에 들고, 길이 1 의 `a` 에서 끝나는 자리가 `{0, 1, 3}` 으로
늘어나 상태 1 로 넘어갑니다. 상태 하나는 **가장 긴 문자열의 접미사 가운데 길이가 이어진 한 구간**이에요. 그래서
상태를 가장 긴 것의 길이 `len[v]` 와 가장 짧은 것의 길이 둘로 적을 수 있습니다.

##### 상태끼리의 관계

접미사가 짧아질수록 끝나는 자리 집합은 커지기만 합니다. 긴 쪽이 나타나는 자리마다 짧은 쪽도 같은 자리에서
끝나기 때문이에요. 상태마다 가장 짧은 문자열에서 앞 글자를 한 번 더 떼면 어느 상태로 가는지 적고, 상태 두 개를
고르는 모든 쌍에서 끝나는 자리 집합이 어떻게 만나는지 세었습니다.

<!--proof:build-endpos-relations-->

| 상태 | 끝나는 자리 | 가장 짧은 것 | 앞 글자를 뗀 것 | 그것이 든 상태 | 그 상태의 끝나는 자리 |
| --- | --- | --- | --- | --- | --- |
| 상태 1 | {0, 1, 3} | a | 빈 문자열 | 상태 0 | 모든 자리 |
| 상태 2 | {1} | aa | a | 상태 1 | {0, 1, 3} |
| 상태 3 | {2} | aab | ab | 상태 6 | {2, 4} |
| 상태 4 | {3} | ba | a | 상태 1 | {0, 1, 3} |
| 상태 5 | {4} | bab | ab | 상태 6 | {2, 4} |
| 상태 6 | {2, 4} | b | 빈 문자열 | 상태 0 | 모든 자리 |

뿌리를 포함한 상태 7 개에서 두 상태를 고르는 21 쌍 가운데 한쪽이 다른 쪽을 품는 쌍이 10 쌍, 겹치는 자리가 없는 쌍이 11 쌍, 일부만 겹치는 쌍이 0 쌍입니다.

<!--/proof-->

가장 짧은 것에서 한 글자를 떼면 끝나는 자리가 더 큰 상태로 갑니다. 상태 3 의 `{2}` 에서 `ab` 의 `{2, 4}` 로,
상태 5 의 `{4}` 에서도 같은 `{2, 4}` 로 가요. 그리고 두 상태의 끝나는 자리 집합은 **한쪽이 다른 쪽을 품거나 전혀
겹치지 않거나** 둘 중 하나이고, 일부만 겹치는 쌍은 0 쌍입니다. 두 문자열이 같은 자리에서 끝나면 짧은 쪽이 긴
쪽의 접미사라서, 겹치는 자리가 하나라도 있으면 짧은 쪽이 나타나는 자리가 긴 쪽의 자리를 모두 품어요.

##### 끝나는 자리 수로 묶은 것과의 차이

「같은 자리에서 끝난다」를 「같은 횟수만큼 나타난다」로 읽기 쉽습니다. 끝나는 자리 **수**가 같은 것끼리 묶으면
이렇게 됩니다.

<!--proof:build-endpos-count-->

| 끝나는 자리 수 | 묶인 문자열 | 개수 | 길이 구간 |
| ---: | --- | ---: | --- |
| 3 | a | 1 | 이어진다 |
| 2 | b · ab | 2 | 이어진다 |
| 1 | aa · ba · aab · aba · bab · aaba · abab · aabab | 8 | 안 이어진다 |

끝나는 자리 수로 묶으면 무리가 3 개이고, 그중 길이 구간 하나로 적을 수 없는 무리가 1 개입니다. 끝나는 자리 집합으로 묶으면 무리가 6 개이고 그런 무리가 없습니다.

<!--/proof-->

한 번만 나타나는 문자열 여덟이 한 무리로 섞였습니다. `aa` 와 `ba` 는 길이가 같아 한 구간에 둘 수 없고, `bab` 는
`aabab` 의 접미사지만 `aa` 는 아니라서 가장 긴 것의 접미사 구간으로도 적을 수 없어요. 개수만 보면 서로 다른
자리에 나타나는 문자열이 섞이므로, 묶는 기준은 끝나는 자리의 **집합**이어야 합니다.

##### 끝나는 자리 집합으로 묶는 까닭

한 상태의 문자열에 같은 글자를 붙이면 그 결과가 모두 한 상태로 갑니다. 상태마다 글자를 붙여 확인했어요.

<!--proof:build-endpos-move-->

| 상태 | 붙인 글자 | 붙인 문자열 | 그것이 든 상태 |
| --- | --- | --- | --- |
| 상태 1 | a | aa | 상태 2 |
| 상태 1 | b | ab | 상태 6 |
| 상태 2 | b | aab | 상태 3 |
| 상태 3 | a | aaba | 상태 4 |
| 상태 4 | b | bab · abab · aabab | 상태 5 · 상태 5 · 상태 5 |
| 상태 6 | a | ba · aba | 상태 4 · 상태 4 |

글자를 붙여 부분 문자열이 되는 6 가지 모두에서, 한 상태의 문자열이 전부 같은 상태로 옮겨 가는 것이 6 가지입니다.

<!--/proof-->

끝나는 자리 집합이 같으면 그 바로 다음 자리의 글자도 같아서, 글자 `c` 를 붙인 뒤의 끝나는 자리 집합도 같습니다.
그래서 상태마다 전이 표를 하나만 두면 되고, 찾기가 글자마다 전이 하나를 따라갈 수 있어요.

| 요구 | 모양에서 채우는 것 |
| --- | --- |
| 개수를 세려면 상태 하나가 담는 개수가 바로 나와야 한다 | 상태가 가장 긴 것의 접미사 가운데 길이가 이어진 구간이라, 두 길이의 차가 개수다 |
| 찾으려면 문자열마다 갈 곳이 하나로 정해져야 한다 | 한 상태의 문자열에 같은 글자를 붙이면 모두 한 상태로 간다 |
| 상태 수가 `n` 에 비례해야 한다 | 끝나는 자리 집합들은 품거나 안 겹치므로 나무 모양으로 늘어선다. 개수는 1단계와 4단계에서 센다 |

#### 먼저 알아 둘 개념 — 접미사 링크

접미사 링크는 **상태마다, 그 상태의 가장 짧은 문자열에서 앞 글자 하나를 뗀 것이 든 상태를 가리키는 화살표**입니다.
가장 짧은 것이 한 글자이면 뗀 것은 빈 문자열이라 뿌리를 가리켜요. 뿌리에는 접미사 링크가 없고, 코드에서는
`link[0] = -1` 로 적습니다.

##### 자동자 위의 접미사 링크

전개 입력의 상태 일곱에 접미사 링크를 모두 그렸습니다. 전이는 흐리게 두었어요.

<!--fig:build-links-->
![상태마다 접미사 링크 하나 — 대시가 접미사 링크, 흐린 실선이 전이](./figs/build-links.svg)

대시는 모두 왼쪽, 더 짧은 문자열을 담는 상태로 갑니다. 상태 3 과 상태 5 는 둘 다 상태 6 으로 가고, 상태 2 와
상태 4 는 상태 1 로 가요.

##### 링크 하나를 읽는 법

상태 4 를 골라 링크를 따라가 보겠습니다.

<!--proof:build-link-read-->

| 읽을 것 | 상태 4 |
| --- | --- |
| 상태 | 상태 4 |
| 담는 문자열 | ba · aba · aaba |
| 가장 짧은 것 | ba |
| 앞 글자 하나를 뗀 것 | a |
| 그것이 든 상태 | 상태 1 |
| link[4] | 1 |
| len[1] + 1 | 2 |
| 가장 짧은 것의 길이 | 2 |

접미사 링크가 가리키는 상태 1 의 가장 긴 것에 한 글자를 더한 길이가 상태 4 의 가장 짧은 것의 길이 2 와 같습니다.

<!--/proof-->

상태 4 의 가장 짧은 것 `ba` 에서 `b` 를 떼면 `a` 이고, `a` 는 상태 1 에 있습니다. 링크가 가리키는 상태의 `len` 에
1 을 더하면 원래 상태의 가장 짧은 길이가 나오므로, 상태마다 가장 짧은 길이를 따로 적지 않아도 돼요. 가장 짧은
길이는 늘 `len[link[v]] + 1` 입니다.

##### 링크끼리의 관계

상태마다 링크가 가리키는 상태의 `len` 과 끝나는 자리를 나란히 놓고, 마지막 상태에서 링크를 거듭 따라가 봤습니다.

<!--proof:build-link-relations-->

| 상태 | len | 접미사 링크 | 링크의 len | 끝나는 자리 | 링크의 끝나는 자리 |
| --- | ---: | --- | ---: | --- | --- |
| 상태 1 | 1 | 상태 0 | 0 | {0, 1, 3} | 모든 자리 |
| 상태 2 | 2 | 상태 1 | 1 | {1} | {0, 1, 3} |
| 상태 3 | 3 | 상태 6 | 2 | {2} | {2, 4} |
| 상태 4 | 4 | 상태 1 | 1 | {3} | {0, 1, 3} |
| 상태 5 | 5 | 상태 6 | 2 | {4} | {2, 4} |
| 상태 6 | 2 | 상태 0 | 0 | {2, 4} | 모든 자리 |

상태 6 개 가운데 6 개에서 링크의 len 이 더 작고, 6 개에서 링크의 끝나는 자리가 자기 것을 품으며 더 큽니다. 마지막 상태 5 에서 링크를 따라가면 상태 5 → 상태 6 → 상태 0 이고, 그 상태들이 담은 문자열 6 개가 "aabab" 의 접미사 6 개(빈 문자열 포함)와 하나도 빠짐없이 맞습니다.

<!--/proof-->

링크를 따라가면 `len` 이 늘 줄고 끝나는 자리 집합은 늘 커집니다. `len` 이 줄기만 하니 링크를 거듭 따라가면 반드시
뿌리에 이르고, 상태마다 링크가 하나라서 링크 전체는 뿌리 하나인 나무예요. 마지막 상태 5 는 접두사 전체 `aabab` 를
담고 있으니, 거기서 링크를 따라가면 `aabab` 의 접미사가 긴 것부터 하나도 빠짐없이 나옵니다. 2단계가 이 성질로
전이를 채워요.

##### 가장 긴 것에서 뗀 것과의 차이

「앞 글자를 떼면 짧은 쪽으로 간다」만 기억하면 가장 긴 문자열에서 떼기 쉽습니다. 그렇게 정하면 이렇게 됩니다.

<!--proof:build-link-longest-->

| 상태 | 가장 긴 것 | 앞 글자를 뗀 것 | 그것이 든 상태 | 접미사 링크 |
| --- | --- | --- | --- | --- |
| 상태 1 | a | 빈 문자열 | 상태 0 | 상태 0 |
| 상태 2 | aa | a | 상태 1 | 상태 1 |
| 상태 3 | aab | ab | 상태 6 | 상태 6 |
| 상태 4 | aaba | aba | 상태 4 | 상태 1 |
| 상태 5 | aabab | abab | 상태 5 | 상태 6 |
| 상태 6 | ab | b | 상태 6 | 상태 0 |

가장 긴 것에서 떼면 상태 6 개 가운데 3 개가 자기 자신을 가리킵니다.

<!--/proof-->

상태 4 의 가장 긴 것 `aaba` 에서 떼면 `aba` 인데, `aba` 는 같은 상태 4 에 있어요. 상태가 길이 두 개 이상을 담으면
가장 긴 것에서 한 글자를 뗀 것도 같은 상태에 남기 때문에, 그 화살표는 자기 자신으로 돌아옵니다. 가장 짧은 것에서
떼야 비로소 상태 밖으로 나가요.

##### 가장 짧은 것에서 떼는 까닭

| 요구 | 모양에서 채우는 것 |
| --- | --- |
| 글자를 붙일 때 지금 접두사의 접미사를 전부 차례로 봐야 한다 | `last` 에서 링크를 따라가면 접미사가 긴 것부터 빠짐없이 한 번씩 나온다 |
| 상태 하나가 담는 개수를 바로 내야 한다 | 가장 짧은 길이가 `len[link[v]] + 1` 이라 `len` 둘의 차가 개수다 |
| 따라가기가 반드시 끝나야 한다 | 링크를 따라가면 `len` 이 줄기만 해서 뿌리에서 멈춘다 |

#### 1단계 — 접두사 전체를 담는 상태 만들기

글자 `c` 를 붙이면 지금까지 읽은 접두사 전체가 새 부분 문자열이 됩니다. 이 접두사는 문자열 안에서 지금 자리에서만
끝나므로, 이전의 어떤 상태와도 끝나는 자리 집합이 같지 않아요. 그래서 글자마다 새 상태 `cur` 를 반드시 하나
만들고, `len[cur]` 를 앞 접두사를 담던 상태 `last` 의 `len` 에 1 을 더한 값으로 둡니다.

<!--proof:build-cur-->

| 글자 자리 | 글자 | 읽은 접두사 | last | len[last] | cur | len[cur] |
| ---: | --- | --- | --- | ---: | --- | ---: |
| 0 | a | "a" | 상태 0 | 0 | 상태 1 | 1 |
| 1 | a | "aa" | 상태 1 | 1 | 상태 2 | 2 |
| 2 | b | "aab" | 상태 2 | 2 | 상태 3 | 3 |
| 3 | a | "aaba" | 상태 3 | 3 | 상태 4 | 4 |
| 4 | b | "aabab" | 상태 4 | 4 | 상태 5 | 5 |

다섯 글자 모두에서 len[cur] 가 읽은 접두사의 길이와 같습니다.

<!--/proof-->

`last` 는 늘 앞 글자에서 만든 `cur` 이고, `len[cur]` 가 읽은 접두사의 길이와 같습니다. `cur` 가 담는 문자열의 짧은
쪽 끝은 아직 모릅니다. 그것은 접미사 링크가 정해지는 3단계에서 정해져요.

#### 2단계 — 접미사 링크를 거슬러 올라가며 빈 전이 채우기

`c` 를 붙이면 앞 접두사의 접미사마다 뒤에 `c` 를 붙인 것이 새로 지금 자리에서 끝납니다. 앞 접두사의 접미사는
1단계 전의 `last` 에서 접미사 링크를 따라가면 긴 것부터 나오니, 그 차례로 올라가며 상태마다 `c` 전이가 있는지
봐요. **전이가 없으면** 그 상태의 문자열 뒤에 `c` 를 붙인 것이 이번에 처음 나타난 것이라 `cur` 를 적고 한 칸 더
올라갑니다. **전이가 있으면** 거기서 멈춥니다. 그 상태 `p` 와 그보다 짧은 접미사들은 `c` 를 붙인 것이 이미 앞에서
나타났기 때문이에요. 다섯 글자에서 올라간 자리와 멈춘 자리입니다.

<!--proof:build-fill-->

| 글자 자리 | 글자 | 올라간 상태 | 전이를 적은 상태 | 멈춘 자리 |
| ---: | --- | --- | --- | --- |
| 0 | a | 상태 0 | 상태 0 | -1 (뿌리를 지났다) |
| 1 | a | 상태 1 → 상태 0 | 상태 1 | 상태 0 |
| 2 | b | 상태 2 → 상태 1 → 상태 0 | 상태 2 · 상태 1 · 상태 0 | -1 (뿌리를 지났다) |
| 3 | a | 상태 3 → 상태 0 | 상태 3 | 상태 0 |
| 4 | b | 상태 4 → 상태 1 | 상태 4 | 상태 1 |

다섯 글자가 적은 전이는 모두 7 개이고, 멈춘 자리가 -1 인 글자는 2 개입니다.

<!--/proof-->

가장 쉬운 경우는 자리 0 의 `a` 입니다. 뿌리 하나뿐이라 뿌리에 `a` 전이를 적고 링크가 `-1` 이라 멈출 곳이 없어요.
자리 2 의 `b` 는 `b` 가 처음 나오는 글자라 상태 2 · 1 · 0 을 모두 거치며 `b` 전이를 셋 적습니다. 그 걸음의 자동자를
그렸습니다.

<!--fig:build-fill-frame-->
![자리 2 의 b — 상태 2 · 1 · 0 에 b 전이를 적고 뿌리를 지나친다](./figs/build-fill-frame.svg)

굵은 테가 이번에 만든 상태 3, 강조한 간선이 이번에 적은 전이 셋과 접미사 링크이고, 굵은 대시가 올라가며 거친
접미사 링크예요. 반복은 `p` 가 `-1` 이 되거나 `c` 전이가 있는 상태를 만나면 끝나고, 그사이 거친 상태는 링크를
따라 긴 것부터 하나씩이라 건너뛴 접미사가 없습니다.

#### 3단계 — 멈춘 자리에서 접미사 링크 정하기

2단계가 어디서 멈췄는지가 `cur` 의 접미사 링크를 정합니다. 뿌리를 지나쳐 `p = -1` 이 됐다면 `c` 로 끝나는 문자열이
전부 이번에 처음 나타난 것이라, `cur` 의 가장 짧은 문자열은 `c` 한 글자이고 링크는 뿌리예요. 멈췄다면 `p` 의 `c`
전이가 가리키는 상태를 `q` 라 부르고, `len[p] + 1` 과 `len[q]` 를 비교합니다.

<!--proof:build-link-set-->

| 글자 자리 | 글자 | 멈춘 p | q | len[p]+1 · len[q] | 갈래 | 정한 링크 |
| ---: | --- | --- | --- | --- | --- | --- |
| 0 | a | -1 | - | - | 뿌리로 잇는다 | link[1] = 0 |
| 1 | a | 상태 0 | 상태 1 | 1 · 1 | 길이가 이어진다 | link[2] = 1 |
| 2 | b | -1 | - | - | 뿌리로 잇는다 | link[3] = 0 |
| 3 | a | 상태 0 | 상태 1 | 1 · 1 | 길이가 이어진다 | link[4] = 1 |
| 4 | b | 상태 1 | 상태 3 | 2 · 3 | 복제한다 | link[5] = 6 |

다섯 글자가 세 갈래를 모두 지납니다. 뿌리로 잇는 글자가 2 개, 길이가 이어지는 글자가 2 개, 복제하는 글자가 1 개입니다.

<!--/proof-->

`len[p] + 1` 과 `len[q]` 가 같다는 것은 `q` 의 가장 긴 문자열이 정확히 「`p` 의 가장 긴 것 뒤에 `c`」라는
뜻입니다. `q` 의 문자열은 모두 그보다 짧거나 같으니 이번 자리에서도 함께 끝나고, `q` 를 가르지 않고 `cur` 의 링크로
쓸 수 있어요. 자리 1 과 3 의 `a` 가 그 갈래입니다. 자리 4 의 `b` 에서는 `len[1] + 1 = 2` 인데 `len[3] = 3` 이라 맞지
않습니다. 그 갈래가 4단계예요.

#### 4단계 — 복제 상태로 q 가르기

`len[p] + 1` 이 `len[q]` 보다 작으면 `q` 가 담은 문자열 가운데 **짧은 쪽만** 이번 자리에서도 끝납니다. 그러면 `q` 의
문자열들이 더는 같은 끝나는 자리 집합을 갖지 않으니, `q` 를 둘로 갈라요. 짧은 쪽을 담을 복제 상태 `clone` 을 만들어
`len[clone]` 을 `len[p] + 1` 로 두고, `q` 의 접미사 링크와 전이 표를 물려받게 합니다. 그다음 `p` 에서 링크를 따라
오르며 `c` 전이가 `q` 를 가리키던 상태를 `clone` 으로 옮기고, `q` 와 `cur` 의 링크를 `clone` 으로 둡니다. 자리 4 의
`b` 를 세 걸음으로 갈라 상태마다 값을 적었어요.

<!--proof:build-clone-->

| 걸음 | 하는 일 | 상태 3 (q) | 상태 6 (복제) | 상태 5 (cur) | 상태 0 / 상태 1 의 전이 |
| --- | --- | --- | --- | --- | --- |
| T6 | 전이를 채우고 멈춘다 | len 3 · 링크 0 · a→4 | 아직 없음 | len 5 · 링크 없음 · 비어 있음 | a→1 b→3 / a→2 b→3 |
| T7 | 복제 상태를 만든다 | len 3 · 링크 0 · a→4 | len 2 · 링크 0 · a→4 | len 5 · 링크 없음 · 비어 있음 | a→1 b→3 / a→2 b→3 |
| T8 | 전이와 링크를 옮긴다 | len 3 · 링크 6 · a→4 | len 2 · 링크 0 · a→4 | len 5 · 링크 6 · 비어 있음 | a→1 b→6 / a→2 b→6 |

멈춘 p 는 상태 1 이고 len[p] + 1 = 2 가 len[q] = 3 보다 작습니다. 다 만든 뒤 복제 상태 6 이 담는 문자열은 b · ab 이고, 상태 3 이 담는 문자열은 aab 하나입니다. 전이를 옮긴 상태는 상태 1 · 상태 0 입니다.

<!--/proof-->

<!--fig:build-clone-film-->
![자리 4 의 b — 멈추고, 복제하고, 옮긴다](./figs/build-clone-film.svg)

갈리기 전 상태 3 은 `b` · `ab` · `aab` 셋을 담았습니다. 자리 4 에서 끝나는 것은 `b` 와 `ab` 뿐이고 `aab` 는
아니에요. 복제 상태 6 이 그 둘을 가져가고 상태 3 에는 `aab` 만 남습니다. 옮기는 반복은 `c` 전이가 `q` 가 아닌
상태를 만나거나 `p` 가 `-1` 이 되면 끝나요. 그 위의 상태들은 `c` 전이가 `q` 보다 짧은 쪽을 이미 가리키고 있어서
옮길 것이 없습니다.

글자 하나가 늘리는 상태는 `cur` 하나에 복제 상태 많아야 하나라, 상태 수는 글자 수에 비례합니다. 문자열 모양을
바꿔 가며 상태와 전이를 세었습니다.

<!--proof:build-state-scale-->

| n | 같은 글자만 쓴 것의 상태 | 첫 글자만 다른 것의 상태 | 2n-1 | 앞뒤가 다른 것의 전이 | 3n-4 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 9 | 15 | 15 | 20 | 20 |
| 64 | 65 | 127 | 127 | 188 | 188 |
| 512 | 513 | 1,023 | 1,023 | 1,532 | 1,532 |
| 4,096 | 4,097 | 8,191 | 8,191 | 12,284 | 12,284 |
| 100,000 | 100,001 | 199,999 | 199,999 | 299,996 | 299,996 |

다섯 규모 모두에서 첫 글자만 다른 문자열의 상태가 2n-1 과 같고, 앞뒤가 다른 문자열의 전이가 3n-4 와 같습니다. 같은 글자만 쓴 문자열의 상태는 n+1 입니다.

<!--/proof-->

상태가 가장 많은 것은 첫 글자만 다른 문자열로 `2n-1` 과 같고, 전이가 가장 많은 것은 앞뒤가 다른 문자열로 `3n-4` 와
같습니다. 과제 규모 10 만 글자에서 상태는 20 만 개 아래예요. 같은 글자만 쓰면 복제가 한 번도 일어나지 않아 상태가
`n+1` 개입니다.

#### 5단계 — 개수 세기와 찾기

다 만든 자동자에서 개수는 상태마다 담는 개수 `len[v] − len[link[v]]` 를 뿌리를 빼고 더한 것입니다. 부분 문자열
하나는 끝나는 자리 집합이 하나라 정확히 한 상태에 들어서, 겹쳐 세거나 빠뜨리는 문자열이 없어요. 찾기는 뿌리에서
글자마다 전이를 따라가고, 전이가 한 번이라도 없으면 부분 문자열이 아닙니다. 경계를 포함한 여섯 검색 문자열을
찾았습니다.

<!--proof:build-query-->

| 찾는 문자열 | 지나간 상태 | 멈춘 까닭 | contains |
| --- | --- | --- | --- |
| 빈 문자열 | 상태 0 | 끝까지 갔다 | true |
| "a" | 상태 0 → 상태 1 | 끝까지 갔다 | true |
| "aba" | 상태 0 → 상태 1 → 상태 6 → 상태 4 | 끝까지 갔다 | true |
| "bb" | 상태 0 → 상태 6 | 자리 1 의 b 전이가 없다 | false |
| "aabab" | 상태 0 → 상태 1 → 상태 2 → 상태 3 → 상태 4 → 상태 5 | 끝까지 갔다 | true |
| "aababa" | 상태 0 → 상태 1 → 상태 2 → 상태 3 → 상태 4 → 상태 5 | 자리 5 의 a 전이가 없다 | false |

같은 자동자로 센 서로 다른 부분 문자열은 11 개입니다.

<!--/proof-->

빈 문자열은 따라갈 글자가 없어 뿌리에서 끝까지 간 것으로 `true` 이고, `s` 전체 `aabab` 은 상태 5 까지 갑니다.
`aababa` 는 `s` 보다 길어서, 상태 5 에 `a` 전이가 없는 자리에서 멈춰요.

#### 이 방법이 기대는 전제

끝나는 자리 집합으로 묶은 상태는 아래 두 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 문자열이 뒤로만 자란다 | 1단계~4단계가 옛 상태의 `len` 을 바꾸지 않고 상태를 더하기만 한다 | 앞에 글자를 붙이거나 가운데를 지우면 옛 상태의 끝나는 자리가 통째로 바뀌어 처음부터 다시 만든다 |
| 글자 비교가 「같다 / 다르다」 둘로 갈린다 | 끝나는 자리 하나에 문자열 하나가 정해진다 | 아무 글자와 같은 자리가 있으면 한 자리에서 끝나는 문자열이 여럿이 되어 묶음이 겹친다 |

첫째 전제가 깨지는 모양을 값으로 봅시다. 전개 입력 앞이나 뒤에 글자를 하나 붙이고, 옛 상태 여섯이 새 자동자에서
번호와 `len` 과 가장 긴 문자열을 그대로 지니는지 셌습니다.

<!--proof:build-premise-append-->

| 바꾼 방식 | 문자열 | 번호와 len 이 그대로인 옛 상태 | 새 상태 수 |
| --- | --- | ---: | ---: |
| 뒤에 a 를 붙인다 | "aababa" | 6 / 6 | 9 |
| 뒤에 b 를 붙인다 | "aababb" | 6 / 6 | 9 |
| 앞에 a 를 붙인다 | "aaabab" | 2 / 6 | 8 |
| 앞에 b 를 붙인다 | "baabab" | 0 / 6 | 9 |

뒤에 붙이면 옛 상태가 번호와 가장 긴 문자열을 그대로 지니고, 앞에 붙이면 그렇지 않은 옛 상태가 생깁니다.

<!--/proof-->

뒤에 붙이면 옛 상태가 그대로 남고 새 상태만 더해집니다. 앞에 붙이면 옛 문자열의 끝나는 자리가 한 칸씩 옮겨 가고
묶음도 달라져서, 같은 번호로 남는 옛 상태가 줄어요. 그래서 문자열의 앞이 바뀌는 과제에서는 이 구조를 처음부터
다시 만들어야 합니다.

전이 표는 상태마다 글자 수만큼 칸을 두는 방법과, 실제로 있는 전이만 맵에 담는 방법이 있습니다. 앞 방법은 칸
하나를 곧바로 읽어 빠르지만 칸 수가 문자 집합 크기에 비례해요. 과제 규모에서 두 모양의 문자열로 칸 수를 셌습니다.

| 무작위 26 글자 | 26 | 127,296 | 3,309,696 | 13 MB | 226,932 |
| 무작위 26 글자 | 256 | 127,296 | 32,587,776 | 130 MB | 226,932 |
| 무작위 26 글자 | 65,536 | 127,296 | 8,342,470,656 | 33,370 MB | 226,932 |
| 앞뒤가 다르다 | 26 | 199,998 | 5,199,948 | 21 MB | 299,996 |
| 앞뒤가 다르다 | 256 | 199,998 | 51,199,488 | 205 MB | 299,996 |
| 앞뒤가 다르다 | 65,536 | 199,998 | 13,107,068,928 | 52,428 MB | 299,996 |

n = 100,000 에서 상태와 전이는 정본과 같은 절차의 사본이 센 값이고, 칸 수와 바이트는 그 상태 수에 문자 집합 크기를 곱한 식의 값입니다.

<!--/proof-->

소문자 영문이면 칸을 둬도 256 MB 안에 들지만, 문자 집합이 커지면 칸 방식은 곧바로 수십 GB 가 됩니다. 맵에 든
전이는 문자 집합과 상관없이 `3n-4` 개를 넘지 않아요. 이 글의 정본은 문자 집합이 바뀌어도 그대로 쓰도록 **맵으로
둡니다.** 칸을 내주는 대신 전이 하나를 찾는 데 맵 조회 한 번이 들어요.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 이렇게 됩니다.

1. 뿌리 상태 하나(`len 0` · 링크 `-1` · 빈 전이 표)로 시작하고 `last` 를 뿌리로 둔다
2. 글자 `c` 마다 새 상태 `cur` 를 만들어 `len[cur] = len[last] + 1` 로 둔다
3. `p = last` 에서 접미사 링크를 따라 오르며, `c` 전이가 없는 상태에 `cur` 를 적는다
4. `p` 가 `-1` 이면 `cur` 의 링크를 뿌리로 둔다
5. 멈췄으면 `q = next[p][c]` 로 두고, `len[p] + 1 = len[q]` 이면 `cur` 의 링크를 `q` 로 둔다
6. 아니면 `q` 를 복제한 `clone` 을 만들고, `q` 를 가리키던 `c` 전이를 `clone` 으로 옮긴 뒤 `q` 와 `cur` 의 링크를 `clone` 으로 둔다
7. `last` 를 `cur` 로 옮기고 다음 글자로 간다
8. 개수는 뿌리를 뺀 상태마다 `len[v] − len[link[v]]` 를 더하고, 찾기는 뿌리에서 전이를 따라간다

### 수행으로 알아보는 알고리즘 — 다섯 글자 aabab 를 열한 걸음으로 처리한다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const sam = new SuffixAutomaton("aabab");
sam.contains("aba");
sam.contains("bb");
sam.countDistinctSubstrings();
```

왜 하필 이 문자열일까요? 갈래 셋이 한 입력에서 모두 실행되기 때문이에요. 뿌리를 지나쳐 뿌리로 잇는 글자(자리 0 ·
2), 길이가 맞아 `q` 를 그대로 잇는 글자(자리 1 · 3), 길이가 안 맞아 복제 상태를 만드는 글자(자리 4)가 모두 나옵니다.
복제가 마지막 글자에서 한 번만 일어나서 그 앞뒤를 나란히 볼 수 있어요. 검색 문자열 둘은 끝까지 가는 것과 중간에
멈추는 것입니다.

```text
절차 전체를 한 장으로 — 라벨 아홉이 어디에 붙는가
  T1        뿌리 상태 하나로 시작한다
  T2~T6     글자마다
              상태 하나를 새로 만든다                     ① 상태 만들기
              새 상태 cur 에 len[last] + 1 을 적는다      ② 글자 받기
              링크를 거슬러 오르며 빈 전이에만 cur 를 적는다  ③ 전이 채우기
              끝까지 올라갔으면 cur 의 링크를 뿌리로       ④ 뿌리로 잇기
              len[p] + 1 과 len[q] 가 같으면 q 로          ⑤ 그대로 잇기
  T7        다르면 q 의 짧은 쪽만 갖는 복제 상태를 만든다   ⑥ 복제하기
  T8        q 를 가리키던 전이 중 모자란 것을 복제로 옮긴다 ⑦ 전이 옮기기
  T9~T10    뿌리에서 글자마다 전이를 따라간다             ⑨ 찾기
  T11       뿌리를 뺀 상태마다 len 과 len[link] 의 차를 더한다  ⑧ 개수 세기
```

#### 1. 세 배열과 뿌리 상태를 둔다

첫 조각은 상태를 담는 배열 셋입니다. 세 배열의 **같은 자리**가 한 상태의 전부이고, 처음에는 빈 문자열만 담는 뿌리
상태 0 하나로 채워요. `link[0]` 이 `-1` 인 것은 빈 문자열에서는 뗄 글자가 없기 때문입니다.

```ts
/** 상태 `v` 가 담는 문자열 중 가장 긴 것의 길이. */
private readonly len: number[] = [0];

/** 상태 `v` 의 접미사 링크. 뿌리 상태 0 만 `-1` 이다. */
private readonly link: number[] = [-1];

/** 상태 `v` 의 전이 표 — 글자 하나를 받으면 어느 상태로 가는가. */
private readonly next: Map<string, number>[] = [new Map()];
```

상태를 하나 더 만드는 자리는 두 곳(새 글자를 받을 때와 복제할 때)이라 조각으로 떼어 둡니다. 세 배열에 한꺼번에
더하고 그 자리 번호를 돌려주면 돼요.

```ts
/** ① 상태 하나를 새로 만든다. 세 배열의 같은 자리가 그 상태의 전부다. */
private create(len: number, link: number, next: Map<string, number>): number {
  this.len.push(len);
  this.link.push(link);
  this.next.push(next);
  return this.len.length - 1;
}
```

빈 문자열로 만들면 T1 의 상태가 그대로 남습니다.

<!--proof:walk-init-->

```text
상태 수   1
len       [0]
link      [-1]
전이 수   0
```

#### 2. 글자를 받아 새 상태를 만들고 빈 전이만 채운다

둘째 조각은 「아이디어 상세」의 1단계와 2단계, 그리고 3단계의 뿌리 갈래입니다. `②` 가 `cur` 를 만들고, `③` 이
접미사 링크를 거슬러 오르며 `c` 전이가 비어 있는 상태에만 `cur` 를 적어요.

```ts
// ② 글자 하나를 받는다. 새 상태 `cur` 는 여기까지 읽은 접두사 전체를 담는다.
const cur = this.create((this.len[last] as number) + 1, -1, new Map());
let p = last;

// ③ 링크를 거슬러 올라가며 `c` 전이가 **비어 있는** 상태에만 `cur` 를 적는다.
while (p !== -1 && !(this.next[p] as Map<string, number>).has(c)) {
  (this.next[p] as Map<string, number>).set(c, cur);
  p = this.link[p] as number;
}

if (p === -1) {
  // ④ 뿌리까지 올라가도록 `c` 전이가 없었다 — `cur` 의 링크는 뿌리다.
  this.link[cur] = 0;
}
```

글자 넷(T2~T5)까지 이 조각과 다음 조각을 실행하면 걸음마다 이렇게 나옵니다. T2 와 T4 가 뿌리를 지나쳐 `p = -1`
로 멈춘 걸음이에요.

<!--proof:walk-fill-->

```text
걸음   글자   cur   전이를 적은 상태   멈춘 p   link[cur]
T2     0:a    1     0                  -1       0
T3     1:a    2     1                  0        1
T4     2:b    3     2 1 0              -1       0
T5     3:a    4     3                  0        1
```

T4 에서 전이를 셋 적은 것은 그때까지 `b` 전이를 가진 상태가 하나도 없어서입니다. **`p` 가 `-1` 이 되었다는 것은
`b` 로 끝나는 부분 문자열이 지금 처음 나왔다는 뜻**이고, 그래서 상태 3 의 가장 짧은 문자열은 `b` 한 글자이고
링크가 뿌리예요.

#### 짚고 가기 — 이미 있는 전이를 덮어쓰면 개수가 부풀어 오른다

여기서 헷갈리기 쉬운 포인트는 **왜 비어 있는 전이만 채우는가**입니다. 「지금 붙인 글자로 끝나는 가장 긴 것이
`cur` 니까 전부 `cur` 를 가리켜야 하지 않나」로 읽으면 조건이 군더더기로 보여요. 그 생각대로 조건을 빼면 반복은
뿌리까지 무조건 올라가며 전부 덮어씁니다.

```ts
while (p !== -1 && true) {   // ← 바꾼 줄. 정본은 전이가 비어 있는지 함께 본다
```

| 문자열 | 정본 | 있는 전이를 덮어쓴 판 | 판정 |
| --- | ---: | ---: | --- |
| "aabab" | 11 | 15 | 어긋난다 |
| "abab" | 7 | 10 | 어긋난다 |
| "aaa" | 3 | 6 | 어긋난다 |
| "banana" | 15 | 21 | 어긋난다 |

문자열 4 개 가운데 4 개에서 개수가 정본과 갈립니다. 네 문자열 모두 둘째 글자부터 그 반복을 지나갑니다.

<!--/proof-->

`"aabab"` 이 11 대신 15 입니다. 이미 있는 전이는 **더 짧은 접미사 뒤에 `c` 를 붙인 것이 앞에서 이미 나타났다**는
기록이라, 그것을 `cur` 로 덮으면 그 문자열이 앞 자리에서 끝났다는 사실이 지워져요. 그러면 `cur` 의 링크가 뿌리로
가고 `cur` 가 담는 길이 구간이 실제보다 넓어져서, 이미 센 문자열을 다시 셉니다.

#### 3. 전이가 이미 있는 자리에서 길이를 비교한다

셋째 조각은 3단계의 나머지 갈래입니다. 반복이 `p` 에서 멈췄으면 `p` 의 `c` 전이가 가리키는 `q` 를 꺼내 `len[p] + 1`
과 `len[q]` 를 비교해요.

```ts
const q = (this.next[p] as Map<string, number>).get(c) as number;
if ((this.len[p] as number) + 1 === (this.len[q] as number)) {
  // ⑤ `p` 뒤에 `c` 를 붙인 길이가 `q` 의 가장 긴 문자열과 같다 — `q` 를 그대로
  // 링크로 쓴다.
  this.link[cur] = q;
}
```

T3 과 T5 가 이 갈래를 지납니다.

<!--proof:walk-equal-->

```text
걸음   p   q   len[p]+1   len[q]   link[cur]
T3     0   1   1          1        1
T5     0   1   1          1        1
```

두 걸음 다 `p` 가 뿌리이고 `q` 가 상태 1 이에요. `len[0] + 1` 과 `len[1]` 이 둘 다 1 이라 `⑤` 로 갑니다.

#### 짚고 가기 — 길이가 안 맞는데 q 를 그대로 이으면 개수가 모자란다

여기서 헷갈리기 쉬운 포인트는 **길이 비교가 왜 필요한가**입니다. 「전이를 따라간 곳이 곧 그 문자열이 든 상태니까
그것을 링크로 쓰면 되지 않나」로 읽으면 비교가 없어도 될 것 같아요. 그 생각대로 조건을 늘 참으로 두면 복제 갈래는
한 번도 실행되지 않습니다.

```ts
if (true) {   // ← 바꾼 줄. 정본은 len[p] + 1 과 len[q] 를 비교한다
```

<!--proof:pause-no-clone-->

| 문자열 | 정본 | 복제를 안 만든 판 | 판정 |
| --- | ---: | ---: | --- |
| "aabab" | 11 | 10 | 어긋난다 |
| "abcbc" | 12 | 10 | 어긋난다 |
| "banana" | 15 | 12 | 어긋난다 |
| "abab" | 7 | 7 | 같다 |

복제를 한 번도 안 하는 문자열은 "abab" 이고, 문자열 4 개 가운데 3 개에서 개수가 정본보다 작습니다.

<!--/proof-->

`"aabab"` 이 11 대신 10 입니다. 자리 4 에서 `q` 는 상태 3 이고, 상태 3 은 `b` · `ab` · `aab` 를 담고 있었어요.
`q` 를 통째로 링크로 쓰면 `aab` 도 자리 4 에서 끝나는 것처럼 되어 `cur` 의 구간이 길이 4 부터로 좁아지고, `bab`
하나가 어느 상태에도 안 들어가 개수가 하나 줄어요. 복제가 없는 `"abab"` 에서만 답이 같은 것이 그 근거입니다.

#### 4. 길이가 안 맞으면 복제 상태를 만든다

넷째 조각은 4단계입니다. `⑥` 이 복제 상태를 만들고 `⑦` 이 전이를 옮겨요.

```ts
// ⑥ 길이가 어긋난다. `q` 가 담고 있던 문자열 중 **짧은 쪽만** 갖는 복제 상태를
// 만든다. 전이 표는 복사해서 넘긴다.
const cloneLen = (this.len[p] as number) + 1;
const cloneNext = new Map(this.next[q] as Map<string, number>);
const clone = this.create(
  cloneLen,
  this.link[q] as number,
  cloneNext,
);

// ⑦ `q` 를 가리키던 `c` 전이 중 길이가 모자란 것을 복제 상태로 바꾼다.
while (p !== -1 && (this.next[p] as Map<string, number>).get(c) === q) {
  (this.next[p] as Map<string, number>).set(c, clone);
  p = this.link[p] as number;
}

this.link[q] = clone;
this.link[cur] = clone;
```

여기서 가장 중요한 줄은 `const cloneLen = (this.len[p] as number) + 1;` 입니다. 이 줄이 정하는 값이 곧 **가르는
자리**예요. 복제 상태가 길이 `len[link[q]] + 1` 부터 `len[p] + 1` 까지를 담고 `q` 는 그 뒤부터 `len[q]` 까지를 담게
되어, 두 구간이 겹치지도 벌어지지도 않습니다. T6 부터 T8 까지를 마친 뒤의 값입니다.

<!--proof:walk-clone-->

```text
cloneLen            2
clone               6
link[6]             0
⑦ 이 옮긴 상태      1 0
link[3] · link[5]   6 · 6

상태 0              len 0   link -1   a→1 b→6
상태 1              len 1   link 0    a→2 b→6
상태 2              len 2   link 1    b→3
상태 3              len 3   link 6    a→4
상태 4              len 4   link 1    b→5
상태 5              len 5   link 6    비어 있음
상태 6              len 2   link 0    a→4
```

복제 상태 6 이 상태 3 의 전이 `a→4` 를 물려받았고, `⑦` 이 상태 1 과 0 의 `b` 전이를 3 에서 6 으로 옮겼어요.

#### 짚고 가기 — 전이 표를 복사하지 않고 함께 쓰면 짧은 입력에서는 답이 안 틀린다

여기서 헷갈리기 쉬운 포인트는 **전이 표를 왜 복사하는가**입니다. 복제 상태가 만들어진 순간 `q` 와 전이가 똑같으니
같은 객체를 함께 써도 될 것 같아요. 그렇게 바꿔 봅시다.

```ts
const cloneNext = this.next[q] as Map<string, number>;   // ← 바꾼 줄. 정본은 복사한다
```

**전개 입력에서는 답이 안 틀립니다.** 복제 뒤에 글자가 더 붙지 않으니 함께 쓴 전이 표를 고치는 걸음이 없어요.
갈리는 것은 복제 뒤에도 글자가 이어지는 문자열입니다.

<!--proof:pause-share-next-->

| 문자열 | 정본 | 전이 표를 함께 쓴 판 | 판정 |
| --- | ---: | ---: | --- |
| "aabab" | 11 | 11 | 같다 |
| "abcbc" | 12 | 12 | 같다 |
| "banana" | 15 | 15 | 같다 |
| "abbaba" | 15 | 14 | 어긋난다 |
| "abbabb" | 14 | 14 | 같다 |

문자열 5 개 가운데 5 개가 복제를 한 번 이상 하고, 개수가 정본과 갈리는 것은 1 개입니다. 알파벳 두 글자로 만든 길이 1~6 문자열 126 개를 전수로 걸면 갈리는 것이 2 개이고, 가장 짧은 것은 길이 6 의 "abbaba" 입니다.

<!--/proof-->

복제 뒤에 `③` 이 복제 상태나 `q` 에 새 전이를 적는 걸음이 오면, 함께 쓰는 판에서는 그 전이가 양쪽에 한꺼번에
생깁니다. 둘은 담은 문자열이 다르므로 한쪽에만 있어야 할 전이가 다른 쪽에도 생기고, 그다음 글자에서 `③` 이
멈추는 자리가 달라져요. 테스트가 짧은 입력만 담고 있으면 이 자리는 통과합니다. 그래도 복사하는 까닭은, 답이 안
틀린다는 것이 이 입력들에서 그 걸음이 오지 않았다는 뜻일 뿐이기 때문이에요.

#### 5. 전이를 따라가 부분 문자열인지 답한다

다섯째 조각은 5단계의 찾기입니다. 만들기보다 훨씬 짧아요.

```ts
contains(t: string): boolean {
  // ⑨ 뿌리에서 글자마다 전이를 따라간다. 전이가 한 번이라도 없으면 부분 문자열이 아니고,
  // 끝까지 갔으면 부분 문자열이다. 빈 문자열은 반복이 한 번도 실행되지 않아 `true` 다.
  let v = 0;
  for (const c of t) {
    const to = (this.next[v] as Map<string, number>).get(c);
    if (to === undefined) return false;
    v = to;
  }
  return true;
}
```

#### 6. 길이 차의 합으로 서로 다른 부분 문자열을 센다

여섯째 조각은 5단계의 개수 세기입니다.

```ts
countDistinctSubstrings(): number {
  // ⑧ 상태 `v` 가 담는 문자열은 길이 `len[link[v]] + 1` 부터 `len[v]` 까지라 그 개수가
  // 두 길이의 차다. 뿌리를 뺀 전부를 더하면 서로 다른 부분 문자열의 총수가 된다.
  let total = 0;
  for (let v = 1; v < this.len.length; v++) {
    const parent = this.link[v] as number;
    total += (this.len[v] as number) - (this.len[parent] as number);
  }
  return total;
}
```

#### 8. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 둘이에요. 글자를 하나씩 꺼내는 바깥 반복문과, 그
끝에서 `last` 를 새 상태로 옮기는 한 줄입니다.

```ts
export class SuffixAutomaton {
  /** 상태 `v` 가 담는 문자열 중 가장 긴 것의 길이. */
  private readonly len: number[] = [0];

  /** 상태 `v` 의 접미사 링크. 뿌리 상태 0 만 `-1` 이다. */
  private readonly link: number[] = [-1];

  /** 상태 `v` 의 전이 표 — 글자 하나를 받으면 어느 상태로 가는가. */
  private readonly next: Map<string, number>[] = [new Map()];

  constructor(s: string) {
    let last = 0;

    for (const c of s) {
      // ② 글자 하나를 받는다. 새 상태 `cur` 는 여기까지 읽은 접두사 전체를 담는다.
      const cur = this.create((this.len[last] as number) + 1, -1, new Map());
      let p = last;

      // ③ 링크를 거슬러 올라가며 `c` 전이가 **비어 있는** 상태에만 `cur` 를 적는다. 이미
      // 있는 전이는 더 짧은 접미사가 이미 쓰고 있는 것이라 덮어쓰지 않는다.
      while (p !== -1 && !(this.next[p] as Map<string, number>).has(c)) {
        (this.next[p] as Map<string, number>).set(c, cur);
        p = this.link[p] as number;
      }

      if (p === -1) {
        // ④ 뿌리까지 올라가도록 `c` 전이가 없었다 — `cur` 의 링크는 뿌리다.
        this.link[cur] = 0;
      } else {
        const q = (this.next[p] as Map<string, number>).get(c) as number;
        if ((this.len[p] as number) + 1 === (this.len[q] as number)) {
          // ⑤ `p` 뒤에 `c` 를 붙인 길이가 `q` 의 가장 긴 문자열과 같다 — `q` 를 그대로
          // 링크로 쓴다.
          this.link[cur] = q;
        } else {
          // ⑥ 길이가 어긋난다. `q` 가 담고 있던 문자열 중 **짧은 쪽만** 갖는 복제 상태를
          // 만든다. 전이 표는 복사해서 넘긴다 — 같은 객체를 함께 쓰면 뒤에 적히는 전이가
          // 양쪽에 한꺼번에 보인다.
          const cloneLen = (this.len[p] as number) + 1;
          const cloneNext = new Map(this.next[q] as Map<string, number>);
          const clone = this.create(
            cloneLen,
            this.link[q] as number,
            cloneNext,
          );

          // ⑦ `q` 를 가리키던 `c` 전이 중 길이가 모자란 것을 복제 상태로 바꾼다.
          while (
            p !== -1 &&
            (this.next[p] as Map<string, number>).get(c) === q
          ) {
            (this.next[p] as Map<string, number>).set(c, clone);
            p = this.link[p] as number;
          }

          this.link[q] = clone;
          this.link[cur] = clone;
        }
      }

      last = cur;
    }
  }

  countDistinctSubstrings(): number {
    // ⑧ 상태 `v` 가 담는 문자열은 길이 `len[link[v]] + 1` 부터 `len[v]` 까지라 그 개수가
    // 두 길이의 차다. 뿌리를 뺀 전부를 더하면 서로 다른 부분 문자열의 총수가 된다.
    let total = 0;
    for (let v = 1; v < this.len.length; v++) {
      const parent = this.link[v] as number;
      total += (this.len[v] as number) - (this.len[parent] as number);
    }
    return total;
  }

  contains(t: string): boolean {
    // ⑨ 뿌리에서 글자마다 전이를 따라간다. 전이가 한 번이라도 없으면 부분 문자열이 아니고,
    // 끝까지 갔으면 부분 문자열이다. 빈 문자열은 반복이 한 번도 실행되지 않아 `true` 다.
    let v = 0;
    for (const c of t) {
      const to = (this.next[v] as Map<string, number>).get(c);
      if (to === undefined) return false;
      v = to;
    }
    return true;
  }

  /** ① 상태 하나를 새로 만든다. 세 배열의 같은 자리가 그 상태의 전부다. */
  private create(len: number, link: number, next: Map<string, number>): number {
    this.len.push(len);
    this.link.push(link);
    this.next.push(next);
    return this.len.length - 1;
  }
}
```

```text

new SuffixAutomaton("abcbc")    개수 12   "bcb" true · "abc" true · "bca" false · "" true
new SuffixAutomaton("aaa")      개수 3    "aaa" true · "aaaa" false
new SuffixAutomaton("banana")   개수 15   "ana" true · "nb" false
new SuffixAutomaton("a")        개수 1    "a" true · "b" false
```

첫 줄은 전개 입력이고, 나머지 네 줄에는 전개에서 안 나온 자리가 들어 있습니다. `abcbc` 줄은 빈 검색 문자열과 복제를 여러 번
하는 `s`, `aaa` 줄은 같은 글자만 되풀이한 `s` 와 그보다 긴 검색 문자열, `banana` 줄은 길이가 다른 반복이 겹친
`s`, `a` 줄은 한 글자짜리 `s` 예요.

### 알아 두면 좋은 개념 — 마이힐-네로드 동치

파트 1 이 쓴 묶음 기준에는 이름이 있습니다. 두 문자열을 **「뒤에 무엇을 붙일 수 있는가가 같으면」 한 묶음**으로 모으는
방식을 **마이힐-네로드 동치**(Myhill–Nerode equivalence)라고 불러요. 이 글은 끝나는 자리 집합으로 묶었는데, 전개
입력에서 두 기준을 나란히 놓으면 이렇습니다.

<!--proof:related-nerode-->

| 상태 | 그 무리의 문자열 | 끝나는 자리 | 뒤에 붙일 수 있는 글자 | 전이 표의 글자 | 무리 안의 문자열끼리 |
| --- | --- | --- | --- | --- | --- |
| 상태 1 | a | {0, 1, 3} | a b | a b | 하나로 같음 |
| 상태 6 | b · ab | {2, 4} | a | a | 하나로 같음 |
| 상태 2 | aa | {1} | b | b | 하나로 같음 |
| 상태 4 | ba · aba · aaba | {3} | b | b | 하나로 같음 |
| 상태 3 | aab | {2} | a | a | 하나로 같음 |
| 상태 5 | bab · abab · aabab | {4} | 없음 | 없음 | 하나로 같음 |

무리 6 개에서 「뒤에 붙일 수 있는 글자」는 4 가지이고, 전이 표의 글자와 갈리는 무리는 0 개입니다.

<!--/proof-->

한 상태 안의 문자열은 「뒤에 붙일 수 있는 글자」가 하나로 같고, 그것이 전이 표의 글자와 같습니다. 끝나는 자리
집합이 같으면 그 바로 다음 글자의 모음도 같기 때문이에요. 이 글의 상태가 곧 그 동치로 묶은 묶음이라, 「아이디어
상세」가 상태마다 전이 표를 하나만 둔 자리가 이 이름이 붙는 자리입니다. 같은 이름을 다른 자리에서도 만나요.

| 다시 나오는 자리 | 한 상태로 묶는 기준 |
| --- | --- |
| 유한 상태 기계의 최소화 | 앞으로 받아들일 문자열이 같은 상태 |
| 어떤 언어를 읽는 기계의 상태 수 하한 | 그 언어에서 뒤에 붙일 수 있는 것이 같은 접두사 |
| 실패 함수([`findAllOccurrences`](../findAllOccurrences/findAllOccurrences-guide.md)) | 지금까지 맞춘 접두사의 길이가 같은 자리 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 상태 수를 식으로 어떻게 닫는지, 무엇이 글자마다 참으로
남는지, 그리고 자료 접근이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **문자열이 하나로 고정이고 그 위의 물음이 여럿 들어옵니다.** 만드는 데 드는 일을 물음 여럿이 나눠 지는 모양이에요.
  다만 개수를 묻는 물음은 **하나만 있어도** 이 구조가 필요합니다 — 부분 문자열을 실제로 만들면 제곱으로 자라니까요.
- **물음이 부분 문자열에 대한 것입니다.** 「이것이 부분 문자열인가」 · 「서로 다른 부분 문자열이 몇 개인가」 · 「가장
  긴 공통 부분 문자열이 무엇인가」가 그 모양이에요.
- **답이 정확해야 합니다.** 해시로 부분 문자열을 비교하면 훨씬 짧게 적히지만 충돌을 감수해야 하는데, 이 절차는
  충돌이 없어요.
- **문자열이 뒤로만 자랍니다.** 글자를 뒤에 하나 붙이는 일이 옛 상태의 `len` 을 안 건드려서, 문자열이 자라는 중에도
  앞부분을 다시 만들지 않아요. 앞쪽이 바뀌거나 가운데가 지워지는 과제면 처음부터 다시 만들어야 합니다.
- **부분 문자열이 문자열 길이에 비해 많습니다.** 글자가 잘 안 겹치는 입력일수록 얻는 것이 커요 — 「아이디어를
  떠올리는 과정」의 트라이 비교에서 무작위 64 글자는 마디가 상태의 수십 배였고, 첫 글자만 다른 64 글자는 거의
  같았습니다.

#### 문제에서 이것을 떠올리게 하는 단서

- 지문이 **서로 다른 부분 문자열의 개수**를 묻습니다. 부분 문자열을 실제로 만들면 제곱으로 자라기 때문에 묶는
  구조가 있어야 풀려요.
- 문자열 하나가 주어지고 **질의가 여러 개** 들어옵니다. 전처리와 질의가 갈라진 모양이에요.
- 문자열 길이가 10 만 언저리인데 **부분 문자열을 다 보라는 물음**입니다. 곱하면 50 억이라 전부 만드는 방법이 막히는
  규모예요.
- **가장 긴 공통 부분 문자열**이나 **어떤 문자열이 몇 번 나오는가**를 묻습니다. 둘 다 이 구조 위에서 상태를
  따라가는 것으로 풀립니다.
- 지문이 **정확한 답**을 요구하고 확률적 실패를 허용하지 않습니다.

### 수식 정의와 유도

문자열 $s$ 의 길이를 $n$ 이라 하고 자리를 0 부터 셉니다. 문자열 $w$ 가 $s$ 안에서 끝나는 자리의 집합과, 그 집합으로 두
문자열을 묶는 관계를 아래 식으로 적고, 그 정의를 전개 입력의 세 문자열에 넣은 값을 식 아래 표에 적었어요.

$$
\operatorname{endpos}(w) = \{\, i \mid s[i-|w|+1 \dots i] = w \,\} \qquad u \sim v \iff \operatorname{endpos}(u) = \operatorname{endpos}(v)
$$

<!--proof:math-define-->

| w | w 가 놓인 구간 | endpos(w) | 담긴 상태 |
| --- | --- | --- | --- |
| b | [2,2] · [4,4] | {2, 4} | 상태 6 |
| ab | [1,2] · [3,4] | {2, 4} | 상태 6 |
| aab | [0,2] | {2} | 상태 3 |

b 와 ab 는 endpos 가 같아 한 상태에 들고, aab 는 endpos 가 달라 다른 상태에 듭니다.

<!--/proof-->

묶음 하나가 상태 하나이고, 상태 $v$ 가 담는 문자열 가운데 가장 긴 것의 길이를 $\operatorname{len}(v)$ 라 적습니다.
코드의 `len[v]` 예요. 한 묶음 안의 문자열은 길이가 이어지므로 그 묶음이 담는 길이 구간과 개수는 아래 식과 같습니다.
**검산 — 여섯 묶음 전부에서 식의 양쪽이 같은 수를 내는지 식 아래 표에 적었습니다.**

$$
\operatorname{len}(\operatorname{link}(v)) + 1 \;\le\; |w| \;\le\; \operatorname{len}(v) \qquad \#\{w \in v\} = \operatorname{len}(v) - \operatorname{len}(\operatorname{link}(v))
$$

<!--proof:math-check-->

| 끝나는 자리 | 그 무리의 문자열 | 상태 | len(v) | len(link(v)) + 1 | 무리 크기 | len(v) − len(link(v)) |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| {0, 1, 3} | a | 상태 1 | 1 | 1 | 1 | 1 |
| {2, 4} | b · ab | 상태 6 | 2 | 1 | 2 | 2 |
| {1} | aa | 상태 2 | 2 | 2 | 1 | 1 |
| {3} | ba · aba · aaba | 상태 4 | 4 | 2 | 3 | 3 |
| {2} | aab | 상태 3 | 3 | 3 | 1 | 1 |
| {4} | bab · abab · aabab | 상태 5 | 5 | 3 | 3 | 3 |

무리 6 개 가운데 6 개에서 무리 크기와 두 len 의 차가 같고, 뿌리를 뺀 상태도 6 개입니다.

<!--/proof-->

**유도 하나 — 상태 수는 $2n-1$ 을 넘지 못합니다**($n \ge 2$). 글자를 하나 붙일 때 상태가 몇 개 늘 수 있는지 세면 나와요.

- 뿌리 하나로 시작하므로 붙이기 전 상태는 1 개입니다.
- 글자 하나를 붙이면 $\operatorname{cur}$ 가 반드시 하나 생기고, 복제는 있어도 하나입니다. 그래서 한 글자에 상태가
  **많아야 2 개** 늡니다.
- **첫 글자에서는 복제가 안 생깁니다.** 그 시점의 상태는 뿌리뿐이라 전이가 하나도 없고, 반복이 뿌리를 지나쳐 $p$ 가
  $-1$ 이 됩니다.
- **둘째 글자에서도 복제가 안 생깁니다.** 그 시점의 상태는 뿌리($\operatorname{len} = 0$)와 상태 1($\operatorname{len} = 1$)
  둘뿐인데, 상태 1 의 전이 표가 아직 비어 있어서 반복이 거기서 멈추지 못합니다. 멈출 수 있는 자리는 뿌리뿐이고
  그때 $q$ 는 상태 1 이에요. $\operatorname{len}(p) + 1 = 1 = \operatorname{len}(q)$ 라 길이가 맞아 복제 갈래로 안 갑니다.
- 그래서 상태 수는 아래 식으로 닫힙니다. 글자 자리마다 상태가 가장 많이 느는 수를 작은 문자열 전수에서 재면 위 네
  줄과 맞고, 그 값을 식 아래 표에 적었습니다.

$$
1 + 1 + 1 + 2(n-2) = 2n - 1
$$

<!--proof:math-growth-->

| 글자 자리 | 상태가 가장 많이 는 수 |
| ---: | ---: |
| 0 | +1 |
| 1 | +1 |
| 2 | +2 |
| 3 | +2 |
| 4 | +2 |
| 5 | +2 |
| 6 | +2 |
| 7 | +2 |

알파벳 세 글자로 만든 길이 1~8 문자열 9,840 개를 전수로 만들었습니다. 자리 0 과 자리 1 에서는 늘 1 개씩 늘고, 자리 2 부터는 가장 많을 때 2 개씩 늡니다.

<!--/proof-->

식을 그대로 옮긴 조각입니다.

```ts
// 상태 수의 상한 — n ≥ 2 에서 2n-1, 한 글자짜리는 뿌리와 상태 하나로 2 다.
const stateBound = (n: number): number => (n >= 2 ? 2 * n - 1 : n + 1);
```

**유도 둘 — 서로 다른 부분 문자열의 개수는 상태마다의 길이 차를 더한 것입니다.** 부분 문자열 하나는 끝나는 자리
집합이 하나라 어느 한 상태에 정확히 한 번 들어갑니다. 상태 $v$ 가 담는 것은 위 구간의 길이마다 하나씩이라 개수가
두 값의 차이고, 그래서 총수는 아래 식입니다. 링크로 이어진 두 상태의 구간은 겹치지도 벌어지지도 않아요.
$\operatorname{link}(v)$ 의 구간이 $\operatorname{len}(\operatorname{link}(v))$ 에서 끝나고 $v$ 의 구간이 바로 다음 수
$\operatorname{len}(\operatorname{link}(v)) + 1$ 에서 시작하기 때문이에요. **계수 — 식에 과제 규모를 넣은 값은 식 아래
표에 적었습니다.**

$$
\sum_{v \ne 0} \bigl(\operatorname{len}(v) - \operatorname{len}(\operatorname{link}(v))\bigr)
$$

<!--proof:math-scale-->

| n | 상한 2n-1 | 첫 글자만 다른 것 | 무작위 26 글자 | 같은 글자만 쓴 것 | 부분 문자열 상한 n(n+1)/2 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 15 | 15 | 9 | 9 | 36 |
| 64 | 127 | 127 | 85 | 65 | 2,080 |
| 512 | 1,023 | 1,023 | 649 | 513 | 131,328 |
| 4,096 | 8,191 | 8,191 | 5,216 | 4,097 | 8,390,656 |

가운데 세 열이 상태 수이고 어느 줄에서도 2n-1 을 넘지 않습니다. n = 100,000 이면 상태 수의 상한은 199,999 개이고 서로 다른 부분 문자열의 상한은 5,000,050,000 개입니다.

<!--/proof-->

부분 문자열은 50 억 개인데 상태는 20 만 개 아래입니다. 상한 $2n-1$ 은 어느 모양에서도 안 깨지고 첫 글자만 다른
문자열이 그 값을 정확히 칩니다.

### 불변식 — 한 상태가 담은 문자열은 끝나는 자리 집합이 서로 같다

**불변식을 문장 하나로 세웁니다.** 글자 하나를 붙이는 일이 끝난 시점마다, 모든 상태 `v` 에 대해 「`v` 가 담은
문자열들」의 끝나는 자리 집합이 **서로 같습니다.** 여기서 끝나는 자리는 **그때까지 읽은 접두사 안에서** 센 것이에요.
「언제」가 중요합니다. 글자를 붙이는 도중에는 이 문장이 참이 아닌 자리가 있어요.

| 시점 | 덜 정해진 것 | 불변식 |
| --- | --- | --- |
| 전이를 채우는 도중 | `cur` 의 접미사 링크가 아직 없다 | 참이 아니다 |
| 전이를 옮기는 도중 | `q` 의 접미사 링크가 아직 옛 값이다 | 참이 아니다 |
| 글자 하나를 끝낸 뒤 | 모든 상태에 접미사 링크가 있다 | 참이다 |

이 불변식이 있으면 두 물음의 답이 한 줄로 따라와요. 개수 세기는 상태가 담은 문자열이 길이 구간 하나라는 것에서
나오고, 찾기는 전이를 따라간 끝자리가 곧 그 문자열이 든 상태라는 것에서 나옵니다.

**그것이 유지되는 것을 상태값으로 봅니다.** 상태를 바꾸는 갈래는 셋입니다.

| 갈래 | 조건 | 하는 일 |
| --- | --- | --- |
| 뿌리로 잇는다 | `p` 가 `-1` 까지 올라갔다 | 이 글자로 끝나는 것이 처음 나왔으므로 `cur` 의 링크를 뿌리로 둔다 |
| 길이가 이어진다 | `len[p] + 1` 과 `len[q]` 가 같다 | `q` 를 가르지 않고 `cur` 의 링크로 쓴다 |
| 복제한다 | `len[p] + 1` 이 `len[q]` 보다 작다 | `q` 를 짧은 쪽과 긴 쪽으로 가른다 |

전개 입력의 다섯 글자가 셋을 모두 지납니다. 글자마다 새 상태가 담은 문자열과 그 끝나는 자리를 적었어요.

<!--proof:invariant-hold-->

| 글자 | 지난 갈래 | 새 상태 | 담는 길이 | 그 문자열 | 끝나는 자리 |
| --- | --- | --- | --- | --- | --- |
| 자리 0 | 뿌리로 잇는다 | 상태 1 | 1 부터 1 까지 | a | {0} |
| 자리 1 | 길이가 이어진다 | 상태 2 | 2 부터 2 까지 | aa | {1} |
| 자리 2 | 뿌리로 잇는다 | 상태 3 | 1 부터 3 까지 | b · ab · aab | {2} |
| 자리 3 | 길이가 이어진다 | 상태 4 | 2 부터 4 까지 | ba · aba · aaba | {3} |
| 자리 4 | 복제한다 | 상태 5 | 3 부터 5 까지 | bab · abab · aabab | {4} |

끝나는 자리는 그 글자까지 읽은 접두사 안에서 센 것입니다. 다섯 글자 가운데 5 글자에서, 새 상태가 담은 문자열의 끝나는 자리 집합이 서로 모두 같습니다.

<!--/proof-->

자리 2 를 보면 상태 3 이 `b` · `ab` · `aab` 셋을 담는데 그 시점(접두사 `"aab"`)에서는 셋 다 자리 2 에서 끝나요.
나중에 글자가 더 붙어 `b` 와 `ab` 가 자리 4 에서도 끝나게 되는 순간이 자리 4 의 글자이고, 그때 복제가 그 셋을 둘로
갈라 불변식을 되살립니다. 이어서 경계에 가까운 입력들을 봅시다 — 빈 문자열, 한 글자, 두 글자 두 가지, 같은 글자만
다섯, 첫 글자만 다른 다섯입니다.

<!--proof:invariant-edge-->

| 입력 | 문자열 | n | 상태 | 전이 | 서로 다른 부분 문자열 | contains("") | contains("b") |
| --- | --- | ---: | ---: | ---: | ---: | --- | --- |
| 빈 문자열 | "" | 0 | 1 | 0 | 0 | true | false |
| 한 글자 | "a" | 1 | 2 | 1 | 1 | true | false |
| 같은 글자 둘 | "aa" | 2 | 3 | 2 | 2 | true | false |
| 다른 글자 둘 | "ab" | 2 | 3 | 3 | 3 | true | true |
| 같은 글자 다섯 | "aaaaa" | 5 | 6 | 5 | 5 | true | false |
| 첫 글자만 다른 다섯 | "abbbb" | 5 | 9 | 9 | 9 | true | true |

<!--/proof-->

빈 문자열에서는 반복이 한 번도 실행되지 않아 뿌리만 남고 개수가 0 이며, `contains("")` 가 `true` 인 것도 같은
까닭이에요. 한 글자짜리에서는 상태가 둘이라 `2n-1 = 1` 을 넘는데, **상한이 `n ≥ 2` 에서만 성립한다**고 적은 것이 그
자리입니다. 같은 글자만 다섯이면 상태가 여섯으로 가장 적고, 첫 글자만 다른 다섯이면 아홉으로 `2n-1` 을 정확히
칩니다.

**깨뜨려서 확인합니다.** 끝나는 자리 집합이 같게 유지되는 것은 복제 상태의 길이를 정하는
`const cloneLen = (this.len[p] as number) + 1;` 한 줄 덕분이에요. 그 값이 곧 가르는 자리라서, `q` 의 길이로 바꾸면
두 구간이 겹칩니다.

```ts
const cloneLen = this.len[q] as number;   // ← 바꾼 줄. 정본은 len[p] + 1 이다
```

<!--proof:mutant-clone-len-->

| 문자열 | 정본 | 복제 길이를 q 로 둔 판 | 판정 |
| --- | ---: | ---: | --- |
| "aabab" | 11 | 10 | 어긋난다 |
| "abcbc" | 12 | 10 | 어긋난다 |
| "banana" | 15 | 12 | 어긋난다 |
| "abab" | 7 | 7 | 같다 |

복제를 한 번 이상 하는 문자열을 알파벳 두 글자로 만든 길이 12 이하 · 세 글자로 만든 길이 8 이하에서 전수로 모으면 16,886 개이고, 그중 복제 길이를 q 로 둔 판의 개수가 정본과 같은 것은 0 개입니다.

<!--/proof-->

`"aabab"` 이 11 대신 10 이에요. 복제 상태와 `q` 의 길이가 같아지면 `q` 가 담는 구간이 빈 구간이 되고, `q` · 복제
상태 · `cur` 셋의 몫이 함께 어긋나 합이 줄어듭니다. 표의 `"abab"` 행이 같은 것은 그 문자열이 이 줄을 아예 안 지나가기
때문이고, 지나가는 문자열을 전수로 재면 답이 같은 것이 하나도 없다는 것을 표 아래 문장이 냅니다.

**개수를 세는 줄도 같은 방식으로 확인합니다.** 상태가 담는 개수를 `len` 과 `len[link]` 의 차가 아니라 `len` 자체로
두면 접미사 링크가 이미 담은 몫을 두 번 세게 돼요.

```ts
total += (this.len[v] as number) - 0;   // ← 바꾼 줄. 정본은 len[link[v]] 를 뺀다
```

<!--proof:mutant-count-all-->

| 문자열 | 정본 | 링크 몫을 안 뺀 판 | 판정 |
| --- | ---: | ---: | --- |
| "aabab" | 11 | 17 | 어긋난다 |
| "abab" | 7 | 10 | 어긋난다 |
| "aaa" | 3 | 6 | 어긋난다 |
| "abcbc" | 12 | 18 | 어긋난다 |

문자열 4 개 가운데 4 개에서 개수가 정본보다 큽니다.

<!--/proof-->

`"aaa"` 가 3 대신 6 이 되는 것이 가장 알아보기 쉬운 자리입니다. 상태 셋의 `len` 이 1 · 2 · 3 이라 그 합이 6 이고,
링크 몫을 빼야 1 · 1 · 1 이 되어 3 이 나와요.

### 비용 계산

#### 비용을 세는 과정

전개가 지나간 걸음을 그대로 세어 봅니다. 만들기가 T1 부터 T8 까지이고 찾기가 T9 · T10 이며 개수 세기가 T11 이라,
셋을 갈라 적으면 어느 몫이 어디서 나오는지 확인할 수 있어요.

<!--proof:perf-derive-->

| 센 것 | 횟수 | 걸음 |
| --- | ---: | --- |
| 글자를 받은 횟수 | 5 | T2 ~ T8 |
| 새 상태를 만든 횟수 | 6 | T2 ~ T7 |
| ③ 이 전이를 적은 횟수 | 7 | T2 ~ T6 |
| ⑦ 이 전이를 옮긴 횟수 | 2 | T8 |
| 복제한 횟수 | 1 | T7 |
| 복제가 복사한 전이 항목 | 1 | T7 |
| 세기의 자료 접근 | 18 | T11 |
| 찾기의 자료 접근 | 10 | T9 · T10 |
| 만들기의 자료 접근 | 80 | T1 ~ T8 |

③ 이 적은 전이 7 개와 복제가 복사한 항목 1 개를 더하면 8 이고, 다 만든 자동자의 전이 수도 8 개입니다.

<!--/proof-->

**전이가 생기는 자리는 둘뿐이라 항등식이 하나 나옵니다.** `③` 이 한 번마다 없던 전이를 정확히 하나 적고(T2 ~ T6),
복제가 `q` 의 전이 표를 항목 단위로 복사해요(T7). `⑦` 은 있는 전이를 옮기기만 하고 새로 만들지 않습니다(T8). 그래서
**③ 이 적은 전이와 복사 항목을 더하면 전이 수와 정확히 같습니다.** 전이 수가 `3n-4` 를 안 넘으므로 앞의 둘도 거기서
함께 묶입니다.

**`⑦` 이 전이를 옮긴 횟수만 다른 논법이 필요합니다.** 새 전이를 안 만드니 전이 수로 묶을 수 없어요. **이 글은 그
횟수의 상한을 닫지 않고 실측만 적습니다** — 아래 표에서 길이 4,096 짜리 다섯 모양의 `⑦` 이 어느 모양에서도 `n` 을
안 넘었다는 것이 확인한 전부입니다.

#### 케이스별 비용과 그 경계

아래 표는 두 축을 갈라 놓았습니다. 왼쪽의 **케이스**가 「어떤 입력이 들어왔는가」이고 오른쪽의 **경계**가 「그
케이스에서 값을 어떤 종류의 한계로 적었는가」입니다.

| 무엇 | 케이스 | 경계 | 총식 |
| --- | --- | --- | --- |
| 상태 수 | 최악 | 타이트 $\Theta(n)$ | $2n-1$ 이하이고 첫 글자만 다른 문자열이 달성한다 |
| 전이 수 | 최악 | 실측 상한 | 재 본 모양 전부에서 $3n-4$ 이하. 이 글은 그것이 상한임을 증명하지 않는다 |
| 만들기 | 최악 | 상한 $O(n)$ | 글자마다의 상수 항에 「③ 이 적은 전이 + 복사 항목 = 전이 수 $\le 3n-4$」와 `⑦` 이 옮긴 횟수(실측 $n$ 이하)를 더한 것 |
| 개수 세기 | 모든 입력 | 타이트 $\Theta(n)$ | 뿌리를 뺀 상태마다 자료 접근 3 번이라 $3(2n-2)$ 이하 |
| 찾기 한 번 | 최악 | 타이트 $\Theta(m)$ | 검색 문자열 길이 $m$ 마다 자료 접근 2 번이라 $2m$ 이하 |
| 저장 칸 | 최악 | 타이트 $\Theta(n)$ | `len` 과 `link` 가 각 $2n-1$ 칸에 전이 표 항목 $3n-4$ 개 |

**개수 세기와 찾기에 타이트를 적은 근거는 최댓값이 늘 나온다는 것입니다.** 개수 세기는 상태 하나마다 반드시 세 번을
읽고, 찾기는 검색 문자열이 실제로 부분 문자열이면 글자 하나마다 반드시 두 번을 읽어요. 전이 수를 「실측 상한」으로
적은 것은 `3n-4` 가 상한이라는 것을 이 글이 증명하지 않았기 때문입니다. 다섯 모양을 같은 길이로 재면 이렇습니다.

<!--proof:perf-bounds-->

| 문자열 모양 | 상태 | 전이 | ③ 적은 전이 | ⑦ 옮긴 전이 | 복사 항목 | 자료 접근 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 같은 글자만 | 4,097 | 4,096 | 4,096 | 0 | 0 | 65,535 |
| 두 글자를 번갈아 | 4,097 | 4,097 | 4,097 | 0 | 0 | 65,534 |
| 첫 글자만 다르다 | 8,191 | 8,191 | 4,097 | 4,094 | 4,094 | 126,943 |
| 앞뒤가 다르다 | 8,190 | 12,284 | 8,191 | 4,093 | 4,093 | 139,206 |
| 무작위 26 글자 | 5,216 | 9,292 | 8,139 | 1,168 | 1,153 | 94,538 |

n 은 4,096 입니다. 다섯 모양 모두 「③ 적은 전이 + 복사 항목 = 전이」가 성립하고, 자료 접근의 가장 큰 값과 가장 작은 값의 비는 2.1 배입니다.

<!--/proof-->

갈리는 것은 복제입니다. 같은 글자만 되풀이하거나 두 글자를 번갈아 쓰면 복사 항목이 0 개이고, 첫 글자만 다르거나
앞뒤가 다르면 복사 항목이 `n` 에 가깝습니다. 그래도 모양을 바꿔 자료 접근의 자릿수가 바뀌지는 않아요.

**보장의 종류도 갈라 둡니다 — 위 값들은 최악 보장이고 기대값이 아닙니다.** 절차에 난수가 한 군데도 없고 입력이 어떤
분포에서 왔다고 가정하지도 않으니까요. 다만 **전이 수의 `3n-4` 만은 보장이 아니라 실측입니다** — 재 본 모양
어디서도 안 넘었다는 뜻이고 증명은 이 글 밖에 있어요. 평균은 입력 분포를 먼저 정해야 나오는 값이라 이 글에서는
정의하지 않습니다.

#### 최악을 만드는 입력

최악을 짐작으로 적지 않습니다. 앞에서 상한을 칠 것으로 본 두 모양을 규모별로 전부 재서, 그 값에 실제로 이르는지
봅니다.

<!--proof:perf-worst-->

| n | 첫 글자만 다른 것의 상태 | 2n-1 | 앞뒤가 다른 것의 전이 | 3n-4 | 앞뒤가 다른 것의 자료 접근 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 64 | 127 | 127 | 188 | 188 | 2,118 |
| 512 | 1,023 | 1,023 | 1,532 | 1,532 | 17,350 |
| 4,096 | 8,191 | 8,191 | 12,284 | 12,284 | 139,206 |
| 100,000 | 199,999 | 199,999 | 299,996 | 299,996 | 3,399,942 |

n = 100,000 에서 앞뒤가 다른 문자열의 자료 접근은 3,399,942 번이고 초당 1 억 번으로 나누면 0.034 초입니다. 같은 규모에서 집합에 전부 담기는 식으로 166,676,666,750,000 번입니다.

<!--/proof-->

첫 글자만 다른 문자열이 상태 `2n-1` 을 정확히 치고, 가운데가 같고 앞뒤가 다른 문자열이 전이 `3n-4` 를 정확히 칩니다.
두 모양이 최악인 까닭은 이렇습니다.

| 문자열 모양 | 가장 커지는 값 | 까닭 |
| --- | --- | --- |
| 첫 글자만 다르다 | 상태 수 | `b` 만으로 된 접미사가 길이마다 하나씩이라 셋째 글자부터 글자마다 복제가 일어난다 |
| 앞뒤가 다르다 | 전이 수 | 끝의 `c` 가 모든 `b` 묶음에서 새 전이를 하나씩 더 만든다 |
| 같은 글자만 | 가장 적은 상태 수 | 묶음이 길이 하나씩이라 복제가 한 번도 일어나지 않는다 |

**최악을 만드는 것은 문자열의 길이가 아니라 모양입니다.** 같은 10 만 글자라도 같은 글자만 되풀이하면 상태가 `n+1`
개이고 첫 글자만 다르면 `2n-1` 개예요. 두 배 차이이고, 두 값 다 `2n` 아래에 있습니다.

### 스스로 점검하기

**회수.** 부분 문자열을 **끝나는 자리 집합**으로 묶으면 묶음이 `2n-1` 개를 안 넘고, 묶음 하나가 담는 문자열은 길이가
이어져 `len` 과 `link` 둘로 적힙니다. 글자를 하나씩 붙이며 접미사 링크를 거슬러 올라가 전이를 채우고, 길이가 안 맞는
자리에서만 상태를 둘로 가르면 만드는 일이 `n` 에 비례해요. 개수는 길이 차의 합이고 찾기는 전이를 따라가는
것입니다.

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### 서로 다른 부분 문자열 집합 관리

풀 파일: [`suffixAutomaton.ts`](./suffixAutomaton.ts) · 테스트: [`suffixAutomaton.test.ts`](./suffixAutomaton.test.ts) · 실행: `bun test src/algorithms/string/suffixAutomaton/suffixAutomaton.test.ts`

#### 한 줄 요약

> `SuffixAutomaton`은 문자열을 받아 구축되며, 서로 다른 비공 부분 문자열의 총 개수를 세고 특정 문자열이 부분 문자열인지 판단하는 두 연산을 제공한다.

#### 스토리

표절 검사 시스템을 만드는 하은은 원본 문서 안에 어떤 부분 문자열이 얼마나 다양하게 존재하는지 빠르게 파악해야 한다. 문서를 한 번 전처리해 두면, 이후 의심 문장이 원본의 일부인지 즉시 확인할 수 있어야 한다.

문서가 수십만 자에 달하기 때문에 모든 부분 문자열을 직접 열거하는 방식은 시간과 공간 모두 감당이 안 된다. 하은에게는 선형 시간 전처리만으로 두 질의를 모두 처리할 수 있는 자료구조가 필요하다.

#### 함수 인터페이스

```ts
export class SuffixAutomaton {
  constructor(s: string);
  countDistinctSubstrings(): number;
  contains(t: string): boolean;
}
```

- `constructor(s)` — 문자열 `s`로부터 자료구조를 구축한다.
- `countDistinctSubstrings()` — `s`의 서로 다른 비공(non-empty) 부분 문자열의 개수를 반환한다.
- `contains(t)` — `t`가 `s`의 부분 문자열이면 `true`, 아니면 `false`. 빈 문자열 `t`는 모든 문자열의 부분 문자열이므로 `true`.

#### 제약 조건

- $1 \leq |s| \leq 10^5$
- $0 \leq |t| \leq 10^5$
- 문자 집합: 소문자 영문 알파벳 (`a`–`z`)
- 구축 시간 복잡도: $O(n)$
- `contains(t)` 시간 복잡도: $O(|t|)$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

`countDistinctSubstrings()`는 다음 집합의 크기를 반환한다:

$$\#\{\, w \neq \varepsilon \mid w \text{는 } s \text{의 부분 문자열}\,\}$$

`contains(t)`는 $t = \varepsilon$ (빈 문자열)이면 `true`를 반환한다. `t`가 `s`보다 길면 `false`를 반환한다.

#### 예시

```ts
const sam = new SuffixAutomaton("abcbc");
sam.countDistinctSubstrings();
// 12
// {"a","b","c","ab","bc","cb","abc","bcb","cbc","abcb","bcbc","abcbc"}

sam.contains("bcb");   // true  — "abcbc"의 부분 문자열
sam.contains("abc");   // true
sam.contains("bca");   // false — 존재하지 않는 패턴
sam.contains("");      // true  — 빈 문자열은 항상 true

const sam2 = new SuffixAutomaton("aaa");
sam2.countDistinctSubstrings();  // 3 → {"a","aa","aaa"}

const sam3 = new SuffixAutomaton("abc");
sam3.countDistinctSubstrings();  // 6 → {"a","b","c","ab","bc","abc"}
```
