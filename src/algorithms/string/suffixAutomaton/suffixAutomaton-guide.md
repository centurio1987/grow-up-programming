# 접미사 오토마톤 — 끝나는 자리가 같은 부분 문자열을 한 상태에 담으면 상태가 2n 개를 안 넘는다

## 파트 1 — 아이디어에서 동작하는 코드까지

여기서는 셋을 합니다 — 풀 문제를 못 박고, 부분 문자열을 끝나는 자리로 묶는 방법을 세우고,
그 방법 위에서 개수 세기와 부분 문자열 판정을 둘 다 답하는 코드를 완성합니다.

### 전체 컨셉

입력은 **문자열 하나**뿐입니다. 그 문자열을 한 번 전처리해 두고 두 가지 물음에
답해야 해요. 하나는 **서로 다른 부분 문자열이 몇 개인가**이고, 다른 하나는 **주어진 문자열이
부분 문자열인가**입니다. 여기서 부분 문자열이란 원래 문자열에서 연속한 한 토막을 뜻하고,
빈 문자열은 세지 않습니다.

```text
문자열 "aabab" 의 부분 문자열을 전부 적으면

  길이 1  a b
  길이 2  aa ab ba
  길이 3  aab aba bab
  길이 4  aaba abab
  길이 5  aabab

  서로 다른 것 11 개
  같은 것을 여러 번 만든 횟수 4 번 — 시작 자리를 다 세면 15 개가 나온다
```

물음 자체는 어렵지 않습니다. 시작 자리와 끝 자리를 다 잡아 부분 문자열을 만들고 집합에
담으면 개수가 나오고, 찾는 쪽도 자리마다 견주면 됩니다. 문제는 개수예요 — 길이가 `n` 이면
부분 문자열은 최대 `n(n+1)/2` 개이고, `n` 이 10 만이면 50 억 개입니다. **개수를 세려고 그
50 억 개를 만들 수는 없습니다.**

**이 알고리즘의 관찰은 부분 문자열을 「끝나는 자리 집합」으로 묶으면 무리 수가 `2n` 개를 안
넘는다는 것입니다.** 문자열 `w` 가 원래 문자열 안에서 끝나는 자리를 전부 모은 것을 `w` 의
끝나는 자리 집합이라고 부릅시다. 이 집합이 같은 부분 문자열끼리 한 무리로 묶으면, 부분
문자열이 11 개인 문자열에서 무리는 여섯 개가 됩니다.

```text
"aabab" 의 부분 문자열을 끝나는 자리로 묶으면 (자리는 1 부터 센다)

  끝나는 자리 1 2 4    a
  끝나는 자리 2        aa
  끝나는 자리 3        aab
  끝나는 자리 3 5      b ab
  끝나는 자리 4        ba aba aaba
  끝나는 자리 5        bab abab aabab

  부분 문자열 11 개  →  무리 6 개
```

**한 무리 안의 문자열은 길이가 하나씩 이어지고, 짧은 것이 긴 것의 접미사입니다.** 위에서
`ba` · `aba` · `aaba` 가 길이 2 · 3 · 4 로 이어지고 앞의 것이 뒤의 것의 뒤쪽 토막이에요.
그래서 무리 하나는 **길이 구간 하나**로 적을 수 있고, 그 무리가 담은 문자열의 개수는 구간의
길이입니다. 무리마다 그 구간의 길이를 더하면 서로 다른 부분 문자열의 총수가 나와요.

무리 하나를 **상태** 하나로 두고 상태에 번호를 붙입니다. 상태마다 셋을 적어 둬요.

```text
상태 하나가 들고 있는 것

  len    그 상태가 담는 문자열 중 가장 긴 것의 길이
  link   그 상태의 가장 짧은 문자열에서 앞 글자를 하나 뗀 것이 든 상태
  next   글자 하나를 받으면 어느 상태로 가는가 (전이 표)

  뿌리 상태 0 은 빈 문자열만 담는다. len 은 0 이고 link 는 없다
```

`link` 를 따라가면 담는 문자열이 짧아지므로, 상태 하나가 담는 문자열의 길이 구간은
`len[link] + 1` 부터 `len` 까지입니다. 그러면 개수 세기는 **뿌리를 뺀 모든 상태에서 `len` 과
`len[link]` 의 차를 더하는 것**이 되고, 부분 문자열 판정은 **뿌리에서 글자마다 `next` 를
따라가 끝까지 갔는가**를 보는 것이 됩니다.

```text
"aabab" 의 상태 여섯 (뿌리 제외)

  상태  len  link  len[link]  차   담는 문자열
     1    1     0          0   1   a
     2    2     1          1   1   aa
     3    3     6          2   1   aab
     4    4     1          1   3   ba aba aaba
     5    5     6          2   3   bab abab aabab
     6    2     0          0   2   b ab

  차의 합 1+1+1+3+3+2 = 11 — 부분 문자열 개수와 같다
```

만드는 절차도 무겁지 않습니다. 글자를 왼쪽부터 하나씩 붙이면서 상태를 한 개나 두 개 늘리고,
`link` 를 거슬러 올라가며 전이를 채우면 끝이에요. 글자 하나가 상태를 최대 두 개 늘리므로 상태
수는 `2n` 개 아래로 묶이고, 만드는 데 드는 일도 `n` 에 비례합니다. 찾기는 검색 문자열의 길이에
비례해요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **부분 문자열 · 접두사 · 접미사가 무엇인지** — 부분 문자열은 연속한 한 토막이고, 접두사는
  맨 앞에서 시작하는 토막, 접미사는 맨 뒤에서 끝나는 토막입니다. 세 낱말을 이 글이 끝까지
  그 뜻으로 씁니다.
- **상태와 전이로 문자열을 읽는 기계** — 상태 하나에서 글자 하나를 받아 다음 상태로 가는
  구조입니다. 낯설면 [문자열에서 패턴 위치 모두 찾기](../findAllOccurrences/findAllOccurrences-guide.md)
  의 「알아 두면 좋은 개념」 절이 같은 구조를 다룹니다.
- **트라이** — 문자열 여럿을 글자 단위로 겹쳐 담는 나무 구조.
  [트라이로 접두사 검색](../trie/trie-guide.md) 이 그것을 처음부터 세웁니다. 이 글은 트라이를
  **대조 상대로만** 씁니다.
- **접미사 링크** — 지금 문자열에서 앞 글자를 떼어 낸 것이 어디 있는지 가리키는 연결입니다.
  [아호-코라식](../ahoCorasick/ahoCorasick-guide.md) 이 같은 이름의 연결을 씁니다.
  **이 글은 줄여서 「링크」라고 부릅니다.**
- **집합이 같은 것끼리 묶는다는 것** — 두 대상에 붙은 집합이 완전히 같을 때만 한 무리로
  넣는 것. 이 글의 「끝나는 자리 집합」이 그 기준입니다.

**안 써도 되는 것도 밝혀 둡니다.** 접미사 배열과 LCP 배열은 이 글에 등장하지 않고
([접미사 배열](../suffixArray/suffixArray-guide.md) ·
[카사이 알고리즘](../kasaiLcp/kasaiLcp-guide.md)), 해시도 쓰지 않습니다. 답이 정확해야 하므로
충돌을 감수하는 방법은 후보가 아니에요.

### 아이디어 상세 — 끝나는 자리로 부분 문자열을 묶는 방법을 떠올리는 과정

**첫째, 문제를 고정합니다.**

```ts
export class SuffixAutomaton {
  constructor(s: string);
  countDistinctSubstrings(): number;
  contains(t: string): boolean;
}
```

- 생성자가 받는 `s` 가 전처리할 문자열이고, 글자는 소문자 영문 스물여섯 가지입니다.
- `countDistinctSubstrings()` 는 `s` 의 서로 다른 **비어 있지 않은** 부분 문자열 개수를
  돌려줍니다.
- `contains(t)` 는 `t` 가 `s` 의 부분 문자열이면 `true` 입니다. 빈 문자열은 언제나 `true` 이고,
  `t` 가 `s` 보다 길면 `false` 예요.
- 제약은 `1 <= |s| <= 100,000` 이고 `0 <= |t| <= 100,000` 입니다. 만드는 데 `O(n)`,
  `contains` 에 `O(|t|)` 를 요구하고, 시간 제한 1 초 · 메모리 제한 256 MB 입니다.

이 글 끝까지 나오는 **기호는 열이에요.** 아래 표가 그 아홉의 정본이고, 절이 바뀌어도
같은 글자는 같은 것을 가리킵니다.

| 기호 | 무엇 |
| --- | --- |
| `n` | 전처리할 문자열의 길이 |
| `s` | 전처리할 문자열. 생성자가 받습니다 |
| `t` | `contains` 가 받는 검색 문자열 |
| `c` | 지금 붙이고 있는 글자. 바깥 반복문이 `s` 에서 하나씩 꺼내는 값입니다 |
| `endpos(w)` | 문자열 `w` 가 `s` 안에서 **끝나는 자리**를 모은 집합. 자리는 1 부터 셉니다 |
| `len[v]` | 상태 `v` 가 담는 문자열 중 가장 긴 것의 길이 |
| `link[v]` | 상태 `v` 의 **링크**. 그 상태의 가장 짧은 문자열에서 앞 글자를 하나 뗀 것이 든 상태이고, 뿌리만 `-1` 입니다 |
| `next[v]` | 상태 `v` 의 **전이 표**. 글자 하나를 받으면 어느 상태로 가는가 |
| `last` | 지금까지 읽은 접두사 전체를 담는 상태 |
| `cur` · `p` · `q` · `clone` | 글자 하나를 붙이는 동안만 쓰는 상태 이름. 차례로 새 상태 · 거슬러 올라가는 자리 · 그 자리의 전이가 가리키는 상태 · 복제 상태입니다 |

**무엇을 세어 비용을 말할지도 미리 못 박습니다.** 이 글의 단위는 **자료 접근**이고, 배열 칸
하나를 읽은 것 · 쓴 것 · 전이 표 항목 하나를 읽은 것 · 쓴 것이 각각 한 번입니다. 벽시계는 안
씁니다 — 실행마다 수가 달라지면 원고의 수와 실측이 같은지를 판정할 방법이 없어요.

```text
자료 접근을 세는 기준

  세는 것     배열 칸 하나를 읽은 것 · 쓴 것 · 전이 표 항목 하나를 읽은 것 · 쓴 것
  두 번       next[p] 에 항목이 있는지 보고 그 자리에 적는 한 걸음 — 읽고 쓰므로 2 번이다
  세 번       len[v] 와 len[link[v]] 를 읽어 차를 더하는 한 줄 — link[v] 까지 3 번이다
  안 세는 것  지역 변수를 올린 것 · 반복 조건을 견준 것 · 벽시계
```

**둘째, 기법 없이 푸는 방법을 세워 수치로 반박합니다.** 정의를 그대로 옮기면 코드가 나와요 —
시작 자리와 끝 자리를 다 잡아 토막을 만들고 집합에 넣으면 개수가 나오고, `contains` 는 그
집합에 물으면 됩니다. 답이 맞는 것은 정의에서 곧바로 따라오고, 걸리는 것은 만든 토막의
개수와 그 토막들을 적는 데 든 글자 수예요.

```text

문자열은 알파벳 스물여섯 글자를 차례로 되풀이한 것이다. 만든 부분 문자열이 n(n+1)/2
개이고 읽은 글자 수 합이 n(n+1)(n+2)/6 이라 둘의 합이 집합에 담는 방법의 자료 접근이고,
세 규모에서 실행값과 식이 같다
제약 규모 n = 100,000 이면
  집합에 전부 담기  166,676,666,750,000 번 — 식으로 낸 값이고 실행하지 않았다
  접미사 오토마톤   1,599,974 번
```

**166 조 번은 1 초 안에 안 끝납니다.** 자료 접근이 규모에 따라 세제곱으로 자라는 것은 부분
문자열을 **글자까지 다 적기** 때문이에요. 개수만 놓고 봐도 50 억 개라 담을 자리가 없습니다.
같은 일을 몇 번씩 되풀이하고 있는지부터 세어 볼 차례예요.

<!--proof:naiveRepeat-->

```text
시작 자리  거기서 만든 부분 문자열  개수
        1  a aa aab aaba aabab         5
        2  a ab aba abab               4
        3  b ba bab                    3
        4  a ab                        2
        5  b                           1

만든 부분 문자열          15 개
그중 서로 다른 것         11 개
같은 것을 다시 만든 횟수  4 번
```

**서로 다른 것은 11 개인데 15 개를 만들었습니다.** 시작 자리 1 에서 만든 `a` 와 시작 자리 2 에서
만든 `a` 가 같은 문자열이고, 시작 자리 2 의 `ab` 와 시작 자리 4 의 `ab` 도 그래요. **같은
문자열이 여러 번 만들어지는 것은 그것이 여러 자리에 나타나기 때문입니다.** 그렇다면 「어디에
나타나는가」 자체를 묶는 기준으로 삼아 볼 만해요.

```text
같은 문자열이 여러 번 만들어지는 자리

  a   시작 자리 1 · 2 · 4 에서 각각 한 번씩
  ab  시작 자리 2 · 4 에서 각각 한 번씩
```

**셋째, 나타나는 자리를 끝 쪽으로 적어 봅니다.** 시작 자리로 적으면 길이가 다른 것들이 한데
섞여요 — 위 표의 둘째 줄에서 `a` · `ab` · `aba` · `abab` 가 전부 시작 자리 2 를 갖는데 넷은
서로 다른 무리에 들어가야 합니다. **끝나는 자리로 적으면 사정이 달라집니다.**

```text
무리  부분 문자열  끝나는 자리  길이
   1  a            1 2 4           1
   2  b            3 5             1
      ab                           2
   3  aa           2               2
   4  ba           4               2
      aba                          3
      aaba                         4
   5  aab          3               3
   6  bab          5               3
      abab                         4
      aabab                        5

서로 다른 부분 문자열                     11 개
끝나는 자리가 같은 무리                   6 개
가장 큰 무리가 담은 문자열                3 개
한 무리 안에서 길이가 이어지지 않는 자리  0 개
```

**11 개가 여섯 무리로 묶였습니다.** 그리고 한 무리 안에서 길이가 이어지지 않는 자리가 하나도
없어요 — `b` 와 `ab` 는 길이 1 과 2 이고, `ba` · `aba` · `aaba` 는 2 · 3 · 4 입니다. 이유를
길이 순으로 따라가 봅시다. 두 문자열이 같은 자리에서 끝나면 짧은 쪽은 긴 쪽의 뒤쪽 토막이고,
**뒤쪽 토막은 긴 쪽이 나타나는 자리마다 함께 나타나므로** 끝나는 자리 집합이 짧아질수록
커지기만 합니다. 양 끝의 집합이 같으면 그 사이에 낀 길이의 집합도 같을 수밖에 없어요.

```text
끝나는 자리가 같으면 왜 길이가 이어지는가

  ba 와 aaba 는 둘 다 자리 4 에서 끝난다

  자리   1  2  3  4  5
  글자   a  a  b  a  b
  ba           └──┘
  aba       └─────┘
  aaba   └────────┘

  자리 4 에서 끝나는 길이 2 · 3 · 4 짜리가 전부 한 무리다
```

**넷째, 묶는 것이 실제로 이득인지 두 방법을 재서 봅니다.** 묶지 않는 방법은 모든 접미사를
트라이에 담는 것이고, 그때 마디 하나가 서로 다른 부분 문자열 하나입니다. 묶는 방법은 위처럼
끝나는 자리로 무리를 만드는 것이에요. 같은 문자열에 둘을 실행해 개수를 나란히 적어 봅시다.

```text
 n  문자열 모양           접미사 트라이의 마디  무리로 묶은 상태    몇 배
```

2,040 개인데 무리는 85 개로 24 배 차이예요. 반대로 첫 글자만 다른 문자열에서는 128 대 127 로
거의 같습니다. **묶어서 얻는 것은 겹침이 적을 때 나오고, 그때가 바로 부분 문자열이 많아서
곤란한 경우입니다.** 이제 무리를 어떻게 적을지 정해야 해요.

**다섯째, 무리 하나를 상태 하나로 두고 무엇을 적을지 정합니다.** 무리 안의 문자열은 길이가
이어지므로 **가장 긴 것의 길이 하나와 가장 짧은 것의 길이 하나**만 적으면 무리 전체가 정해져요.
가장 긴 것의 길이를 `len[v]` 라 적고, 가장 짧은 쪽은 따로 적지 않고 **한 글자 뗀 것이 든
상태**를 `link[v]` 로 가리킵니다.

```text
왜 가장 짧은 길이를 따로 안 적는가

  상태 4 는 ba · aba · aaba 를 담는다. 가장 짧은 것은 ba 이고 길이 2 다
  ba 에서 앞 글자 b 를 떼면 a 가 되고, a 는 상태 1 에 있다. 그래서 link[4] = 1 이다
  len[1] 이 1 이므로 상태 4 의 가장 짧은 길이는 1 + 1 = 2 로 나온다

  가장 짧은 길이 = len[link[v]] + 1
```

이렇게 두면 상태 하나가 담는 문자열의 개수가 `len[v] - len[link[v]]` 로 바로 나옵니다.
전이 표 `next[v]` 는 그 무리의 문자열 뒤에 글자 하나를 붙였을 때 어느 무리로 가는지를 적은
것이고, 뿌리에서 글자를 따라가면 그 문자열이 든 상태에 도착해요.

글자를 하나씩 붙이며 상태를 늘리는 것입니다.

### 수행으로 알아보는 알고리즘 — 다섯 글자 aabab 을 열한 걸음으로 처리한다

이 절이 끝까지 붙들고 가는 입력은 다섯 글자 `"aabab"` 하나입니다. 이 문자열을 고른 이유는
**갈래 셋을 한 입력에서 모두 실행**하기 때문이에요 — 링크를 끝까지 거슬러 올라가 뿌리로 잇는 갈래(글자 1·3),
길이가 이어져 그대로 잇는 갈래(글자 2·4), 길이가 어긋나 복제 상태를 만드는 갈래(글자 5)입니다.
복제가 마지막 글자에서 한 번만 일어나서 그 앞뒤를 나란히 볼 수 있어요.

#### 1. 뿌리 상태 하나로 시작한다

첫 조각이 하는 일은 하나입니다 — 빈 문자열만 담는 상태 0 을 만들고 배열 셋을 그 상태 하나로
채웁니다. `link[0]` 이 `-1` 인 것은 빈 문자열에서는 뗄 글자가 없기 때문이에요.

```ts
/** 상태 `v` 가 담는 문자열 중 가장 긴 것의 길이. */
private readonly len: number[] = [0];

/** 상태 `v` 의 접미사 링크. 뿌리 상태 0 만 `-1` 이다. */
private readonly link: number[] = [-1];

/** 상태 `v` 의 전이 표 — 글자 하나를 받으면 어느 상태로 가는가. */
private readonly next: Map<string, number>[] = [new Map()];
```

상태를 하나 더 만드는 자리는 두 곳(새 글자를 받을 때와 복제할 때)이라 조각으로 떼어 둡니다.
세 배열의 **같은 자리**가 한 상태의 전부라서, 셋에 한꺼번에 더하고 그 자리 번호를
돌려주면 돼요.

```ts
/** ① 상태 하나를 새로 만든다. 세 배열의 같은 자리가 그 상태의 전부다. */
private create(len: number, link: number, next: Map<string, number>): number {
  this.len.push(len);
  this.link.push(link);
  this.next.push(next);
  return this.len.length - 1;
}
```

#### 2. 첫째·셋째 글자 — 새 상태를 만들고 빈 전이만 채운다

글자 하나를 붙이면 **그때까지 읽은 접두사 전체**를 담는 상태가 하나 필요합니다. 그 상태를
`cur` 라 부르고 `len[cur]` 를 `len[last] + 1` 로 둡니다. 그다음 `last` 에서 링크를 거슬러
올라가며 그 글자 전이가 **비어 있는** 상태에만 `cur` 를 적어요.

```ts
// ② 글자 하나를 받는다. 새 상태 `cur` 는 여기까지 읽은 접두사 전체를 담는다.
const cur = this.create((this.len[last] as number) + 1, -1, new Map());
let p = last;

// ③ 링크를 거슬러 올라가며 `c` 전이가 **비어 있는** 상태에만 `cur` 를 적는다.
while (p !== -1 && !(this.next[p] as Map<string, number>).has(c)) {
  (this.next[p] as Map<string, number>).set(c, cur);
  p = this.link[p] as number;
}

if (p === -1) {
  // ④ 뿌리까지 올라가도록 `c` 전이가 없었다 — `cur` 의 링크는 뿌리다.
  this.link[cur] = 0;
}
```

`b` 로 끝나는 부분 문자열이 지금 처음 나왔다는 뜻**이고, 그러면 상태 3 의 가장 짧은 문자열은
길이 1 이라 링크가 뿌리입니다.

#### 멈춤 — 이미 있는 전이를 덮어쓰면 무엇이 틀리는가

여기서 헷갈리기 쉬운 포인트는 **왜 비어 있는 전이만 채우는가**입니다. 「지금 붙인 글자로 끝나는
가장 긴 것이 `cur` 니까 전부 `cur` 를 가리켜야 하지 않나」로 읽으면 조건이 군더더기로 보여요.
오해를 그대로 전개해 봅시다 — 조건을 빼면 반복은 뿌리까지 무조건 올라가며 전부 덮어씁니다.

#### 3. 둘째·넷째 글자 — 전이가 이미 있는 자리에서 길이를 견준다

반복이 `p` 에서 멈췄다는 것은 `p` 가 담은 문자열 뒤에 이 글자를 붙인 것이 **이미 어느
무리에 있다**는 뜻입니다. 그 무리를 `q` 라 부르고, `q` 가 담은 가장 긴 문자열의 길이와
`len[p] + 1` 을 견줍니다.

```ts
const q = (this.next[p] as Map<string, number>).get(c) as number;
if ((this.len[p] as number) + 1 === (this.len[q] as number)) {
  // ⑤ `p` 뒤에 `c` 를 붙인 길이가 `q` 의 가장 긴 문자열과 같다 — `q` 를 그대로
  // 링크로 쓴다.
  this.link[cur] = q;
}
```

```text
"banana"    15                 12  다르다
"abab"       7                  7  같다

복제가 한 번도 일어나지 않는 "abab" 에서만 답이 같다
```

**개수가 모자라게 나옵니다.** `"aabab"` 이 11 대신 10 이에요. `len[p] + 1` 이 `len[q]` 보다
작다는 것은 **`q` 에 담긴 문자열 중 일부만 지금 자리에서 끝난다**는 뜻입니다. `q` 를 통째로
링크로 쓰면 담기지 않는 문자열이 생기고 그만큼 개수가 줍니다. 복제가 아예 없는
`"abab"` 에서만 답이 같은 것이 그 근거예요 — 그 문자열은 이 갈래를 한 번도 안 지나갑니다.

#### 4. 다섯째 글자 — 길이가 어긋나 복제 상태를 만든다

길이가 어긋나면 `q` 를 **둘로 쪼갭니다.** 짧은 쪽만 갖는 새 상태를 만들어 `len` 을
`len[p] + 1` 로 두고, `q` 의 링크와 전이 표를 물려받게 해요. 그다음 `q` 를 가리키던 전이 중
길이가 모자란 것을 새 상태로 바꿉니다.

```ts
// ⑥ 길이가 어긋난다. `q` 가 담고 있던 문자열 중 **짧은 쪽만** 갖는 복제 상태를
// 만든다. 전이 표는 복사해서 넘긴다.
const cloneLen = (this.len[p] as number) + 1;
const cloneNext = new Map(this.next[q] as Map<string, number>);
const clone = this.create(
  cloneLen,
  this.link[q] as number,
  cloneNext,
);

// ⑦ `q` 를 가리키던 `c` 전이 중 길이가 모자란 것을 복제 상태로 바꾼다.
while (p !== -1 && (this.next[p] as Map<string, number>).get(c) === q) {
  (this.next[p] as Map<string, number>).set(c, clone);
  p = this.link[p] as number;
}

this.link[q] = clone;
this.link[cur] = clone;
```

여기서 가장 중요한 줄은 `const cloneLen = (this.len[p] as number) + 1;` 입니다. 이 줄이 정하는
값이 곧 **쪼개는 자리**예요. 복제 상태가 길이 `len[link[q]] + 1` 부터 `len[p] + 1` 까지를 담고
`q` 는 그 뒤부터 `len[q]` 까지를 담게 되어, 두 구간이 겹치지도 벌어지지도 않습니다.
T6 부터 T8 까지가 이렇게 실행돼요.

#### 5. 만든 오토마톤으로 부분 문자열인지 답한다

찾기는 만들기보다 훨씬 짧습니다. 뿌리에서 시작해 글자마다 전이를 따라가고, 전이가 한 번이라도
없으면 부분 문자열이 아니에요.

```ts
  // 끝까지 갔으면 부분 문자열이다. 빈 문자열은 반복이 한 번도 실행되지 않아 `true` 다.
```

#### 6. 길이 차의 합으로 서로 다른 부분 문자열을 센다

마지막 조각은 개수 세기입니다. 상태 하나가 담는 문자열은 길이 `len[link[v]] + 1` 부터
`len[v]` 까지라 개수가 두 길이의 차이고, 뿌리를 뺀 전부를 더하면 총수가 나와요.

```ts
countDistinctSubstrings(): number {
  // ⑧ 상태 `v` 가 담는 문자열은 길이 `len[link[v]] + 1` 부터 `len[v]` 까지라 그 개수가
  // 두 길이의 차다. 뿌리를 뺀 전부를 더하면 서로 다른 부분 문자열의 총수가 된다.
  let total = 0;
  for (let v = 1; v < this.len.length; v++) {
    const parent = this.link[v] as number;
    total += (this.len[v] as number) - (this.len[parent] as number);
  }
  return total;
}
```

#### 7. 전체 코드

지금까지 나온 조각을 한 클래스에 담으면 아래가 됩니다. 앞에서 안 나온 것은 둘뿐이에요 —
글자를 하나씩 꺼내는 바깥 반복문과, 그 끝에서 `last` 를 새 상태로 옮기는 한 줄입니다.

```ts
export class SuffixAutomaton {
  /** 상태 `v` 가 담는 문자열 중 가장 긴 것의 길이. */
  private readonly len: number[] = [0];

  /** 상태 `v` 의 접미사 링크. 뿌리 상태 0 만 `-1` 이다. */
  private readonly link: number[] = [-1];

  /** 상태 `v` 의 전이 표 — 글자 하나를 받으면 어느 상태로 가는가. */
  private readonly next: Map<string, number>[] = [new Map()];

  constructor(s: string) {
    let last = 0;

    for (const c of s) {
      // ② 글자 하나를 받는다. 새 상태 `cur` 는 여기까지 읽은 접두사 전체를 담는다.
      const cur = this.create((this.len[last] as number) + 1, -1, new Map());
      let p = last;

      // ③ 링크를 거슬러 올라가며 `c` 전이가 **비어 있는** 상태에만 `cur` 를 적는다. 이미
      // 있는 전이는 더 짧은 접미사가 이미 쓰고 있는 것이라 덮어쓰지 않는다.
      while (p !== -1 && !(this.next[p] as Map<string, number>).has(c)) {
        (this.next[p] as Map<string, number>).set(c, cur);
        p = this.link[p] as number;
      }

      if (p === -1) {
        // ④ 뿌리까지 올라가도록 `c` 전이가 없었다 — `cur` 의 링크는 뿌리다.
        this.link[cur] = 0;
      } else {
        const q = (this.next[p] as Map<string, number>).get(c) as number;
        if ((this.len[p] as number) + 1 === (this.len[q] as number)) {
          // ⑤ `p` 뒤에 `c` 를 붙인 길이가 `q` 의 가장 긴 문자열과 같다 — `q` 를 그대로
          // 링크로 쓴다.
          this.link[cur] = q;
        } else {
          // ⑥ 길이가 어긋난다. `q` 가 담고 있던 문자열 중 **짧은 쪽만** 갖는 복제 상태를
          // 만든다. 전이 표는 복사해서 넘긴다 — 같은 객체를 함께 쓰면 뒤에 적히는 전이가
          // 양쪽에 한꺼번에 보인다.
          const cloneLen = (this.len[p] as number) + 1;
          const cloneNext = new Map(this.next[q] as Map<string, number>);
          const clone = this.create(
            cloneLen,
            this.link[q] as number,
            cloneNext,
          );

          // ⑦ `q` 를 가리키던 `c` 전이 중 길이가 모자란 것을 복제 상태로 바꾼다.
          while (
            p !== -1 &&
            (this.next[p] as Map<string, number>).get(c) === q
          ) {
            (this.next[p] as Map<string, number>).set(c, clone);
            p = this.link[p] as number;
          }

          this.link[q] = clone;
          this.link[cur] = clone;
        }
      }

      last = cur;
    }
  }

  countDistinctSubstrings(): number {
    // ⑧ 상태 `v` 가 담는 문자열은 길이 `len[link[v]] + 1` 부터 `len[v]` 까지라 그 개수가
    // 두 길이의 차다. 뿌리를 뺀 전부를 더하면 서로 다른 부분 문자열의 총수가 된다.
    let total = 0;
    for (let v = 1; v < this.len.length; v++) {
      const parent = this.link[v] as number;
      total += (this.len[v] as number) - (this.len[parent] as number);
    }
    return total;
  }

  contains(t: string): boolean {
    // ⑨ 뿌리에서 글자마다 전이를 따라간다. 전이가 한 번이라도 없으면 부분 문자열이 아니고,
    // 끝까지 갔으면 부분 문자열이다. 빈 문자열은 반복이 한 번도 실행되지 않아 `true` 다.
    let v = 0;
    for (const c of t) {
      const to = (this.next[v] as Map<string, number>).get(c);
      if (to === undefined) return false;
      v = to;
    }
    return true;
  }

  /** ① 상태 하나를 새로 만든다. 세 배열의 같은 자리가 그 상태의 전부다. */
  private create(len: number, link: number, next: Map<string, number>): number {
    this.len.push(len);
    this.link.push(link);
    this.next.push(next);
    return this.len.length - 1;
  }
}
```

### 알아 두면 좋은 개념 — 마이힐-네로드 동치

파트 1 이 쓴 묶음 기준에는 이름이 있습니다. 두 문자열을 「**뒤에 무엇을 붙일 수 있는가가
같으면** 한 무리」로 묶는 방식을 **마이힐-네로드 동치**(Myhill–Nerode equivalence)라고 불러요.
이 글은 끝나는 자리 집합으로 묶었는데, 두 기준이 같은 무리를 냅니다.

<!--proof:relatedNerode-->

```text
상태  그 무리의 문자열  끝나는 자리  뒤에 붙일 수 있는 글자  next 의 키  무리 안이 서로
   1  a                 1 2 4        a b                     a b         같다
   6  b ab              3 5          a                       a           같다
   2  aa                2            b                       b           같다
   4  ba aba aaba       4            b                       b           같다
   3  aab               3            a                       a           같다
   5  bab abab aabab    5            없다                    없다        같다

무리 수                               6 개
서로 다른 「뒤에 붙일 수 있는 글자」  4 가지
next 의 키와 다른 무리                0 개
```

**여섯 무리에서 「뒤에 붙일 수 있는 글자」가 `next` 의 키와 하나도 안 어긋납니다.** 「뒤에
붙일 수 있는 글자」란 끝나는 자리 **바로 다음 글자**를 모은 것이라, 끝나는 자리 집합이 같으면
그 모음도 같은 집합이 될 수밖에 없어요. 거꾸로 그래서 **전이 표를 상태마다 하나만 두면 되는
것**입니다. 상태 5 는 그 모음이 비었는데, 그 무리의 문자열이 전부 문자열의 맨 끝에서 끝나
다음 글자가 없기 때문이에요.

같은 이름을 다른 자리에서도 만납니다. 유한 상태 기계를 최소화할 때 「같은 상태로 묶어도
되는가」를 판정하는 기준이 이것이고, 어떤 언어를 읽는 기계의 **상태 수 하한**도 이 동치류의
개수로 정해져요. [문자열에서 패턴 위치 모두 찾기](../findAllOccurrences/findAllOccurrences-guide.md)
의 실패 함수도 「지금까지 맞춘 접두사 길이」로 묶은 동치류를 상태로 삼습니다. 이웃 편의
「유한 상태 기계」가 **기계의 모양**을 말한다면 이 이름은 **무엇을 한 상태로 볼 것인가**를
말하는 것이라 층이 달라요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 이 만든 것을 이제 뜯어 봅니다. 이 절차를 골라야 하는 문제가 어떤 모양인지, 값 대신
기호로 적었을 때 무엇이 더 나오는지, 글자를 붙이는 내내 깨지지 않는 문장이 무엇인지, 그리고

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **문자열이 하나로 고정이고 그 위의 물음이 여럿 들어옵니다.** 만드는 데 드는 일을 물음
  여럿이 나눠 지는 모양이에요. 다만 개수를 묻는 물음은 **하나만 있어도** 이 구조가 필요합니다 —
  부분 문자열을 실제로 만들면 제곱으로 자라니까요.
- **물음이 부분 문자열에 대한 것입니다.** 「이것이 부분 문자열인가」 · 「서로 다른 부분
  문자열이 몇 개인가」 · 「가장 긴 공통 부분 문자열이 무엇인가」가 그 모양이에요.
- **답이 정확해야 합니다.** 해시로 부분 문자열을 견주면 훨씬 짧게 적히지만 충돌을 감수해야
  하는데, 이 절차는 충돌이 없어요.
- **문자열이 뒤로만 자랍니다.** 글자를 뒤에 하나 붙이는 것이 앞서 만든 상태의 `len` 을 안
  건드리는 일이라, 문자열이 자라는 중에도 앞부분을 다시 만들지 않아요. 앞쪽이 바뀌거나 가운데가
  지워지는 문제면 통째로 다시 만들어야 합니다.
- **부분 문자열이 문자열 길이에 비해 많습니다.** 글자가 잘 안 겹치는 입력일수록 얻는 것이
  커요 — 「아이디어 상세」의 넷째 걸음에서 64 글자짜리 두 모양이 24.0 배와 1.0 배로 갈렸습니다.

#### 문제에서 이것을 떠올리게 하는 단서

- 지문이 **서로 다른 부분 문자열의 개수**를 묻습니다. 이 물음은 부분 문자열을 실제로 만들면
  제곱으로 자라기 때문에 묶는 구조가 있어야 풀려요.
- 문자열 하나가 주어지고 **질의가 여러 개** 들어옵니다. 전처리와 질의가 갈라진 모양이에요.
- 문자열 길이가 10 만 언저리인데 **부분 문자열을 다 보라는 물음**입니다. 곱하면 50 억이라
  전부 만드는 방법이 막히는 규모예요.
- **가장 긴 공통 부분 문자열**이나 **어떤 문자열이 몇 번 나오는가**를 묻습니다. 둘 다 이
  구조 위에서 상태를 따라가는 것으로 풀립니다.
- 지문이 **정확한 답**을 요구하고 확률적 실패를 허용하지 않습니다.

### 수식 정의와 유도

문자열 $s$ 의 길이를 $n$ 이라 하고 자리를 1 부터 셉니다. 문자열 $w$ 가 $s$ 안에서 끝나는
자리를 모은 집합과, 그 집합으로 두 문자열을 묶는 관계를 이렇게 적어요.

$$\operatorname{endpos}(w) = \\{\, i \mid s[i-|w|+1 \dots i] = w \,\\} \qquad u \sim v \iff \operatorname{endpos}(u) = \operatorname{endpos}(v)$$

```text
정의를 "aabab" 의 두 문자열에 넣어 봅니다

  endpos("b")   = {3, 5}    자리 3 과 5 의 글자가 b 다
  endpos("ab")  = {3, 5}    자리 2~3 과 4~5 가 ab 다
  두 집합이 같으므로 b 와 ab 는 한 무리다

  endpos("aab") = {3}       자리 1~3 뿐이다
  {3} 과 {3, 5} 는 다르므로 aab 는 다른 무리다
```

무리 하나가 상태 하나이고, 상태 $v$ 가 담는 문자열 중 가장 긴 것의 길이를
$\operatorname{len}(v)$ 라 적습니다. 한 무리 안의 문자열은 길이가 이어지므로 그 무리가 담는
문자열의 길이는 $\operatorname{len}(\operatorname{link}(v)) + 1$ 부터 $\operatorname{len}(v)$
까지이고, 개수는 두 값의 차입니다.

```text
상태 하나가 담는 길이 구간

  가장 짧은 것  len(link(v)) + 1
  가장 긴 것    len(v)
  개수          len(v) - len(link(v))
```

**검산 — 여섯 무리 전부에서 양쪽이 같은 수를 내는지 봅니다.**

<!--proof:mathCheck-->

```text
끝나는 자리  그 무리의 문자열  상태  len  len[link]+1  무리 크기  len - len[link]  판정
1 2 4        a                    1    1            1          1                1  같다
3 5          b ab                 6    2            1          2                2  같다
2            aa                   2    2            2          1                1  같다
4            ba aba aaba          4    4            2          3                3  같다
3            aab                  3    3            3          1                1  같다
5            bab abab aabab       5    5            3          3                3  같다

무리 수            6 개
뿌리를 뺀 상태 수  6 개
```

**유도 하나 — 상태 수는 $2n-1$ 을 넘지 못합니다**($n \ge 2$). 글자를 하나 붙일 때 상태가 몇
개 느는지 세면 나와요.

- 뿌리 하나로 시작하므로 붙이기 전 상태는 1 개입니다.
- 글자 하나를 붙이면 $\operatorname{cur}$ 가 반드시 하나 생기고, 복제는 있어도 하나입니다.
  그래서 한 글자에 상태가 **최대 2 개** 늡니다.
- **첫 글자에서는 복제가 안 생깁니다.** 그 시점의 상태는 뿌리뿐이라 전이가 하나도 없고,
  반복이 뿌리를 지나쳐 $p$ 가 $-1$ 이 됩니다.
- **둘째 글자에서도 복제가 안 생깁니다.** 그 시점의 상태는 뿌리($\operatorname{len} = 0$)와
  상태 1($\operatorname{len} = 1$) 둘뿐인데, 상태 1 의 전이 표가 아직 비어 있어서 반복이 거기서
  멈추지 못합니다. 멈출 수 있는 자리는 뿌리뿐이고 그때 $q$ 는 상태 1 이에요.
  $\operatorname{len}(p) + 1 = 1 = \operatorname{len}(q)$ 라 길이가 이어져 복제 갈래로 안 갑니다.
- 그래서 상태 수는 $1 + 1 + 1 + 2(n-2) = 2n-1$ 이하입니다.

```text
글자마다 상태가 몇 개 느는가

  뿌리      +1
  글자 1    +1       복제가 없다 (전이가 하나도 없어 뿌리를 지나친다)
  글자 2    +1       복제가 없다 (len[p]+1 과 len[q] 가 둘 다 1 이다)
  글자 3~n  +2 이하  cur 하나에 복제 하나
  합계      1 + 1 + 1 + 2(n-2) = 2n-1
```

```ts
// 식을 그대로 옮긴 조각 — 상태 수의 상한만 센다.
const stateBound = (n: number): number => (n >= 2 ? 2 * n - 1 : 2);
```

**유도 둘 — 서로 다른 부분 문자열의 개수는 상태마다의 길이 차를 더한 것입니다.** 부분 문자열
하나는 어느 한 무리에 정확히 한 번 들어가므로, 무리마다 담은 개수를 더하면 전체가 됩니다.
무리 $v$ 가 담는 것은 길이 $\operatorname{len}(\operatorname{link}(v)) + 1$ 부터
$\operatorname{len}(v)$ 까지의 문자열 하나씩이라 개수가 두 값의 차예요. 그래서 총수는
$\sum_{v \ne 0} (\operatorname{len}(v) - \operatorname{len}(\operatorname{link}(v)))$ 입니다.

```text
두 구간이 왜 겹치지도 벌어지지도 않는가

  link(v) 가 담는 길이  len(link(link(v))) + 1 부터 len(link(v)) 까지
  v 가 담는 길이        len(link(v)) + 1 부터 len(v) 까지
  이어지는 자리         앞이 끝난 다음 수에서 뒤가 시작해 빈틈도 겹침도 없다
```

166 조 글자가 되는데, 그것을 상태 20 만 개와 전이 30 만 개로 옮겨 적는 것이 이 절차가
하는 일이에요.

### 불변식 — 한 상태가 담은 문자열은 끝나는 자리 집합이 서로 같다

**첫째, 불변식을 문장 하나로 세웁니다.** 글자 하나를 붙이는 일이 끝난 시점마다, 모든 상태
`v` 에 대해 「`v` 가 담은 문자열들」의 끝나는 자리 집합이 **서로 같습니다.** 여기서 끝나는
자리는 **그때까지 읽은 접두사 안에서** 센 것이에요. 「언제」가 중요합니다 — 글자를 붙이는
도중에는 링크가 아직 안 정해진 상태가 있어서 이 문장이 참이 아니고, 한 글자를 끝낸 뒤에는
참입니다.

```text
불변식이 참인 시점과 아닌 시점

  전이를 채우는 도중   cur 의 링크가 아직 없다 — 참이 아니다
  전이를 옮기는 도중   q 의 링크가 아직 옛 값이다 — 참이 아니다
  글자 하나를 끝낸 뒤  모든 상태에 링크가 있다 — 참이다
```

이 불변식이 있으면 두 물음의 답이 한 줄로 따라와요. 개수 세기는 상태가 담은 문자열이 길이
구간 하나라는 것에서 나오고, 찾기는 전이를 따라간 끝자리가 곧 그 문자열이 든 상태라는 것에서
나옵니다.

```text
상태를 바꾸는 갈래 셋

  뿌리로 잇는다    p 가 -1 까지 올라갔다 — 이 글자로 끝나는 것이 처음 나왔다
  길이가 이어진다  len[p] + 1 과 len[q] 가 같다 — q 를 가를 필요가 없다
  복제한다         len[p] + 1 이 len[q] 보다 작다 — q 를 둘로 가른다
```

**둘째, 각 갈래가 그것을 지키는 것을 상태값으로 봅니다.** 전개 입력의 다섯 걸음이 위 셋을
모두 지납니다.

<!--proof:invariantHold-->

```text
걸음  지난 갈래        새 상태  담는 길이      그 문자열       끝나는 자리  판정
T2    뿌리로 잇는다          1  1 부터 1 까지  a               1            지켜진다
T3    길이가 이어진다        2  2 부터 2 까지  aa              2            지켜진다
T4    뿌리로 잇는다          3  1 부터 3 까지  b ab aab        3            지켜진다
T5    길이가 이어진다        4  2 부터 4 까지  ba aba aaba     4            지켜진다
T6    복제한다               5  3 부터 5 까지  bab abab aabab  5            지켜진다

끝나는 자리는 그 걸음까지 읽은 접두사 안에서 센 것이다. 판정은 한 상태가 담은
문자열들의 끝나는 자리 집합이 서로 같은지를 본다
```

**다섯 걸음 모두 지켜집니다.** T4 를 보면 상태 3 이 `b` · `ab` · `aab` 셋을 담는데 그
시점(접두사 `"aab"`)에서는 셋 다 자리 3 에서 끝나요. 나중에 글자가 더 붙어 `b` 와 `ab` 가
자리 5 에서도 끝나게 되는 순간이 T6 이고, 그때 복제가 그 셋을 둘로 갈라 불변식을 되살립니다.
이어서 경계에 가까운 입력들을 봅시다 — 빈 문자열, 한 글자, 두 글자 두 가지, 같은 글자만 다섯,
첫 글자만 다른 다섯입니다.

<!--proof:invariantEdge-->

```text
입력                 문자열   n  상태  전이  서로 다른 부분 문자열  contains("")  contains("b")
빈 문자열            ""       0     1     0                      0  true          false
한 글자              "a"      1     2     1                      1  true          false
같은 글자 둘         "aa"     2     3     2                      2  true          false
다른 글자 둘         "ab"     2     3     3                      3  true          true
같은 글자 다섯       "aaaaa"  5     6     5                      5  true          false
첫 글자만 다른 다섯  "abbbb"  5     9     9                      9  true          true
```

**빈 문자열에서 상태가 하나이고 개수가 0 입니다.** 반복이 한 번도 실행되지 않아 뿌리만
남고, `contains("")` 가 `true` 인 것도 같은 이유예요. 한 글자짜리에서는 상태가 둘이라
`2n-1 = 1` 을 넘는데, **상한이 `n >= 2` 에서만 성립한다**고 적은 것이 그 자리입니다. 같은
글자만 다섯이면 상태가 여섯으로 가장 적고, 첫 글자만 다른 다섯이면 아홉으로 `2n-1` 을 정확히
칩니다.

**셋째, 그 문장을 떠받치던 줄을 바꿔 봅니다.** 끝나는 자리 집합이 같게 유지되는 것은 복제
상태의 길이를 정하는 `const cloneLen = (this.len[p] as number) + 1;` 한 줄 덕분이에요. 그 값이
곧 가르는 자리라서, `q` 의 길이로 바꾸면 두 구간이 겹칩니다.

```ts
const cloneLen = this.len[q] as number;   // ← 바꾼 줄. 정본은 len[p] + 1 이다
```

<!--proof:mutantCloneLen-->


안 지나가요 — 지나가는 문자열을 전수로 재면 답이 같은 것이 하나도 없다는 것을 블록의 아래
두 줄이 냅니다.

**개수를 세는 줄도 같은 방식으로 확인합니다.** 상태가 담는 개수를 `len` 과 `len[link]` 의

```ts
total += (this.len[v] as number) - 0;   // ← 바꾼 줄. 정본은 len[link[v]] 를 뺀다
```

상태 셋의 `len` 이 1 · 2 · 3 이라 그 합이 6 이고, 링크 몫을 빼야 1 · 1 · 1 이 되어 3 이 나와요.

### 비용 계산

#### 비용을 세는 과정

전개가 지나간 걸음을 그대로 세어 봅니다. 만들기가 T1 부터 T8 까지이고 찾기가 T9 · T10 이며
개수 세기가 T11 이라, 셋을 갈라 적으면 어느 몫이 어디서 나오는지가 보입니다.

<!--proof:perfDerive-->

```text
무엇                     몇 번  왜 그 수인가
글자를 받은 걸음             5  글자마다 한 번
새 상태를 만든 횟수          6  글자마다 하나에 복제 하나
③ 이 전이를 적은 걸음        7  적을 때마다 전이가 하나 는다
⑦ 이 전이를 바꾼 걸음        2  복제 한 번에 이어지는 반복
복제한 횟수                  1  길이가 어긋난 걸음 수
복제가 복사한 전이 항목      1  복제마다 q 의 전이 표 크기

③ 걸음 + 복사 항목   7 + 1 = 8 개

```

**전이가 생기는 자리는 둘뿐이라 항등식이 하나 나옵니다.** ③ 이 한 걸음마다 없던 전이를
정확히 하나 적고, 복제가 `q` 의 전이 표를 항목 단위로 복사해요. ⑦ 은 있는 전이를 바꾸기만
하고 새로 만들지 않습니다. 그래서 **③ 걸음 수와 복사 항목 수를 더하면 전이 수와 정확히
같습니다** — 전개 입력에서 7 과 1 을 더한 8 이 전이 수 8 이에요. 전이 수가 `3n-4` 를 안
넘으므로 앞의 둘도 거기서 함께 묶입니다.

**⑦ 이 전이를 바꾼 걸음만 다른 논법이 필요합니다.** 새 전이를 안 만드니 전이 수로 묶을 수
없어요. **이 글은 그 걸음 수의 상한을 닫지 않고 실측만 적습니다** — 아래 표에서 길이 4,096
짜리 다섯 모양의 ⑦ 걸음이 0 에서 4,094 까지이고 어느 모양에서도 `n` 을 안 넘었다는 것이
확인한 전부입니다.

#### 케이스별 비용과 그 경계

아래 표는 두 축을 갈라 놓았습니다. 왼쪽의 **케이스**가 「어떤 입력이 들어왔는가」이고
오른쪽의 **경계**가 「그 케이스에서 값을 어떤 종류의 한계로 적었는가」입니다.

| 무엇 | 케이스 | 경계 | 총식 |
| --- | --- | --- | --- |
| 상태 수 | 최악 | 타이트 $\Theta(n)$ | $2n-1$ 이하이고 첫 글자만 다른 문자열이 달성한다 |
| 전이 수 | 최악 | 실측 상한 | 재 본 모양 전부에서 $3n-4$ 이하. 이 글은 그것이 상한임을 증명하지 않는다 |
| 만들기 | 최악 | 상한 $O(n)$ | 글자마다의 상수 항에 「③ 걸음 + 복사 항목 = 전이 수 $\le 3n-4$」와 ⑦ 걸음(실측 $n$ 이하)을 더한 것 |
| 개수 세기 | 모든 입력 | 타이트 $\Theta(n)$ | 뿌리를 뺀 상태마다 자료 접근 3 번이라 $3(2n-2)$ 이하 |
| 찾기 한 번 | 최악 | 타이트 $\Theta(m)$ | 검색 문자열 길이 $m$ 마다 자료 접근 2 번이라 $2m$ 이하 |
| 저장 칸 | 최악 | 타이트 $\Theta(n)$ | `len` 과 `link` 가 각 $2n-1$ 칸에 전이 표 항목 $3n-4$ 개 |

**개수 세기와 찾기에 타이트를 적은 근거는 최댓값이 늘 나온다는 것입니다.** 개수 세기는 상태
하나마다 반드시 세 번을 읽고, 찾기는 검색 문자열이 실제로 부분 문자열이면 글자 하나마다
반드시 두 번을 읽어요. 전이 수를 「실측 상한」으로 적은 것은 `3n-4` 가 상한이라는 것을 이 글이 증명하지
않았기 때문입니다.

```text

같은 글자만         4,097   4,096   4,096       0          0     65,535
```

**다섯 모양에서 자료 접근이 65,510 에서 139,206 사이입니다.** 가장 큰 것과 가장 작은 것의

되풀이하거나 두 글자를 번갈아 쓰면 복사 항목이 0 개이고, 첫 글자만 다르면 4,094 개 · 앞뒤가

**보장의 종류도 갈라 둡니다 — 위 값들은 최악 보장이고 기대값이 아닙니다.** 절차에 난수가
한 군데도 없고 입력이 어떤 분포에서 왔다고 가정하지도 않으니까요. 다만 **전이 수의 `3n-4`
만은 보장이 아니라 실측입니다** — 재 본 모양 어디서도 안 넘었다는 뜻이고 증명은 이 글 밖에
있어요. 평균은 입력 분포를 먼저 정해야 나오는 값이라 이 글에서는 정의하지 않습니다.

### 스스로 점검하기

**회수.** 부분 문자열을 **끝나는 자리 집합**으로 묶으면 무리가 `2n-1` 개를 안 넘고, 무리 하나가
담는 문자열은 길이가 이어져 `len` 과 `link` 둘로 적힙니다. 글자를 하나씩 붙이며 링크를 거슬러
올라가 전이를 채우고, 길이가 어긋나는 자리에서만 무리를 둘로 쪼개면 만드는 일이 `n` 에
비례해요. 개수는 길이 차의 합이고 찾기는 전이를 따라가는 것입니다.

```text
1.  뿌리 상태 하나로 시작한다
2.  글자마다 새 상태 cur 를 만들고 len[cur] 를 len[last] + 1 로 둔다
3.  link 를 거슬러 올라가며 비어 있는 전이에만 cur 를 적는다
4.  멈춘 자리에서 len[p] + 1 과 len[q] 를 견주고, 어긋나면 복제 상태를 만든다
5.  개수는 상태마다 len - len[link] 를 더한 것이고, 찾기는 전이를 따라가는 것이다
```

잠깐, 확인 하나만 해 볼까요? 전개 입력 `"aabab"` 뒤에 글자 `a` 를 하나 더 붙여
`"aababa"` 를 만들면, 여섯 번째 글자에서 어느 갈래를 지나고 상태는 몇 개가 될까요?

```text
확인할 것

  여섯 번째 글자 a 를 붙일 때 ③ 이 어디서 멈추는가
  len[p] + 1 과 len[q] 가 같은가 어긋나는가
  끝난 뒤 상태 수와 서로 다른 부분 문자열 개수

  힌트  T8 이 낸 전이 표에서 상태 5 의 a 전이부터 보세요
```

전이를 적고 링크를 따라 상태 6 으로 올라가는데, 상태 6 에는 `a` 전이가 있어 거기서 멈춰요.
