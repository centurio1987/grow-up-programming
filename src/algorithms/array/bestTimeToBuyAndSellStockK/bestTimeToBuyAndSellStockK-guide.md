# bestTimeToBuyAndSellStockK — 거래 번호를 상태의 축으로 세우면 조합 열거가 표 한 장이 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 거래 짝을 전부 골라 보는
방법에서 날마다 상태 몇 개만 이어받는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

날짜 순서로 놓인 주식 가격 배열 `P` 와 정수 `k` 를 받아 **최대 `k` 번 사고팔았을 때의 최대
이익**을 돌려주는 문제예요. 한 거래는 매수 하루와 매도 하루의 짝이고, 앞 거래를 팔고 나서야
다음 매수를 할 수 있습니다. 거래를 한 번도 안 해도 되므로 답은 언제나 `0` 이상이에요.

```text
날 번호    0    1    2    3    4    5
가격       2    6    3    9    5    7

거래를 두 번까지 할 때의 후보 몇 개
  날 0 에 사서 날 1 에 판다 + 날 2 에 사서 날 3 에 판다    (6-2) + (9-3) = 10
  날 0 에 사서 날 3 에 판다                                 9-2       =  7
  날 2 에 사서 날 3 에 판다 + 날 4 에 사서 날 5 에 판다    (9-3) + (7-5) =  8
  날 0 에 사서 날 1 에 판다 + 날 4 에 사서 날 5 에 판다    (6-2) + (7-5) =  6
  날 0 에 사서 날 3 에 판다 + 날 2 에 사서 날 5 에 판다    앞 거래를 팔기 전에 샀으므로 후보가 아니다
  └ 이익이 가장 큰 후보는 첫 줄의 10 이고, 그것이 이 배열에서 k = 2 일 때의 답이다
```

**`k` 가 답을 정합니다.** 같은 가격 배열이라도 몇 번까지 거래할 수 있는지에 따라 답이 달라져요.
이 배열에는 이익이 나는 상승 구간이 셋 있어서, 거래를 셋까지 허용하면 답이 12 까지 올라가고 그
뒤로는 더 올라가지 않습니다.

| `k` | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 답 | 7 | 10 | 12 | 12 | 12 |
| 쓰는 거래 수 | 1 | 2 | 3 | 3 | 3 |

거래 짝을 하나씩 골라 보는 것으로는 끝나지 않아요. 거래 하나가 날 두 개를 쓰므로 `t` 번 거래하는
방법은 `N` 개의 날에서 `2t` 개를 고르는 것이고, `t` 를 `0` 부터 `k` 까지 더하면 후보의 개수가
됩니다.

```text
거래 집합의 개수 = C(N, 0) + C(N, 2) + C(N, 4) + ... + C(N, 2k)

  N = 6,     k = 2     1 + 15 + 15                       =            31 개
  N = 24,    k = 2     1 + 276 + 10,626                  =        10,903 개
  N = 1,000, k = 100   같은 합을 100 항까지                =  216 자리 수
  └ 마지막 줄은 1 초 제한 안에 다 만들어 볼 수 없다
```

여기서 **지금이 몇 번째 거래인지와 주식을 들고 있는지를 상태로** 세웁니다. 날을 왼쪽에서
오른쪽으로 한 번 읽으면서, 날 하나를 지날 때마다 상태마다의 최대 이익을 갱신하는 것이에요.
`k = 2` 라면 상태가 다섯 개입니다.

```text
k = 2 일 때의 상태 다섯

  free[0]   거래를 한 번도 안 마친 상태          이익은 언제나 0
  hold[1]   1번째 매수를 마치고 아직 안 판 상태  산 값을 이미 뺀 이익이라 음수일 수 있다
  free[1]   1번째 매도까지 마친 상태             거래 한 번까지 했을 때의 최대 이익
  hold[2]   2번째 매수를 마치고 아직 안 판 상태
  free[2]   2번째 매도까지 마친 상태             거래 두 번까지 했을 때의 최대 이익
  └ 상태가 2k + 1 개다. 답은 마지막 상태인 free[k] 다
```

상태 사이의 이동은 두 가지뿐이에요 — **사거나 팔거나**입니다. 오늘 `t` 번째로 사려면 `t-1`
번째 매도까지 끝나 있어야 하고, 오늘 `t` 번째로 팔려면 `t` 번째 매수까지 끝나 있어야 해요.

```text
날 j 의 가격이 P[j] 일 때 상태 하나를 갱신하는 규칙

  hold[t]   어제까지의 hold[t] 와 (free[t-1] - P[j]) 중 큰 쪽
  free[t]   어제까지의 free[t] 와 (hold[t] + P[j]) 중 큰 쪽
  └ 과거에서 읽는 것이 어제까지의 상태값뿐이라 배열을 다시 볼 일이 없다
```

날마다 `t` 를 `1` 부터 `k` 까지 올리며 이 두 줄을 실행하면 `N` 번의 날 × `k` 번의 거래 번호가
되므로 연산 수가 `N` 과 `k` 의 곱에 비례합니다. 제약이 `N ≤ 1,000` · `k ≤ 100` 이니 40 만 번
언저리이고, 들고 있는 값은 배열 칸 `2(k+1)` 개뿐이에요. 216 자리였던 것이 여섯 자리가 됩니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **거래 한 번일 때의 최대 이익을 구하는 방법.** 파는 날을 고정하면 사는 날이 「어제까지의
  최저가」 하나로 정해진다는 그 풀이입니다. 모르면
  [`bestTimeToBuyAndSellStock`](../bestTimeToBuyAndSellStock/bestTimeToBuyAndSellStock-guide.md)
  를 먼저 보세요.
- **여러 값을 지나가며 최댓값 하나를 들고 가는 방법.** 지금까지의 최댓값과 새 값을 견주어 더
  큰 쪽으로 바꾸는 패턴이고, 이 글은 그 패턴을 상태마다 하나씩 씁니다.
- **「상태」가 무슨 뜻인지.** 앞으로 무엇을 할 수 있는지가 같으면 같은 상태입니다. 여기서는
  「몇 번째 거래까지 끝냈는가」와 「지금 주식을 들고 있는가」 둘이 그것을 정해요.
- **`-∞` 를 시작값으로 쓰는 관례.** 최댓값을 구할 때 「아직 아무 후보도 없다」를 나타내는
  값이고, 여기에는 무엇을 더해도 다른 후보에게 집니다.

이 글이 다루는 것은 **거래 횟수에 상한이 있는 경우**입니다. 상한이 1 인 경우는
[`bestTimeToBuyAndSellStock`](../bestTimeToBuyAndSellStock/bestTimeToBuyAndSellStock-guide.md)
가 다루고, 값을 고를지 말지가 이웃 관계로 얽히는 문제는
[`houseRobber`](../houseRobber/houseRobber-guide.md) 가 다룹니다.

```text
한 번 사고 한 번 팔 때의 최대 이익        ← 다른 글이 다루는 것
최대 k 번까지 사고팔 때의 최대 이익       ← 이 글이 다루는 것
이웃하지 않게 골라서 합을 최대로 한다     ← 또 다른 글이 다루는 것
```

### 아이디어 상세 — 거래 번호와 보유 여부를 상태로 세우는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function bestTimeToBuyAndSellStockK(k: number, prices: number[]): number;
```

- 입력: 거래 횟수 상한 `k` 와 날짜 순서로 정렬된 정수 가격 배열 `prices`.
- 출력: 최대 `k` 번의 매수·매도로 얻을 수 있는 최대 이익. 매도가 끝나야 다음 매수를 할 수
  있고, 같은 날 팔고 다시 사는 것은 허용됩니다. 이익이 나는 조합이 없으면 `0` 입니다.
- 제약: `1 ≤ N ≤ 1,000`, `0 ≤ k ≤ 100`, `0 ≤ P[j] ≤ 10,000`. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `N` | 날짜의 개수 | `1 ≤ N ≤ 1,000` |
| `k` | 거래 횟수의 상한 | `0 ≤ k ≤ 100` |
| `P` | 입력 가격 배열. `P[j]` 는 날 `j` 의 가격 | `0 ≤ P[j] ≤ 10,000` |
| `j` | 날 번호 | `0 ≤ j ≤ N−1` |
| `t` | 거래 번호. 몇 번째 거래인가 | `1 ≤ t ≤ k` · `t = 0` 은 거래를 하나도 안 마친 자리 |
| `hold[t]` | `t` 번째 매수를 마치고 아직 안 판 상태의 최대 이익 | 값 하나 |
| `free[t]` | `t` 번째 매도까지 마친 상태의 최대 이익 | 값 하나 |

`hold` 와 `free` 는 배열이고 칸 번호가 거래 번호 `t` 입니다. `free[0]` 은 거래를 하나도 안
마친 상태라 언제나 `0` 이고, 답은 `free[k]` 예요. 날 번호 `j` 는 배열의 칸 번호가 아니라
**표를 채우는 순서**라서 `hold`·`free` 의 칸 번호와 겹치지 않습니다.

가장 먼저 떠오르는 방법으로 시작합시다. 거래 집합이 「겹치지 않는 매수·매도 짝의 목록」으로
정해지니, 그런 목록을 전부 만들어 이익의 합을 구하고 최댓값을 갱신하는 것이에요.

```ts
let best = 0;
const walk = (start: number, left: number, acc: number): void => {
  best = Math.max(best, acc);                    // 집합 하나마다 비교 한 번
  if (left === 0) return;
  for (let b = start; b < prices.length; b++) {
    for (let s = b + 1; s < prices.length; s++) {
      const gain = (prices[s] as number) - (prices[b] as number);   // 뺄셈 한 번
      walk(s + 1, left - 1, acc + gain);                            // 덧셈 한 번
    }
  }
};
walk(0, k, 0);
```

`b` 는 매수일이고 `s` 는 매도일입니다. 매도일과 다음 매수일이 같은 짝은 하나로 합쳐도 이익이
같으므로, 다음 매수일을 매도일보다 뒤에서 고르는 위 제한으로도 최선을 놓치지 않아요. 그러면
만들어지는 집합의 수가 정확히 `N` 개의 날에서 `2t` 개를 고르는 방법의 합입니다.

```text
N (k = 2)  실제로 만든 집합  Σ C(N, 2t)
        6                31          31
       12               562         562
       18             3,214       3,214
       24            10,903      10,903

제약 규모 N = 1,000 · k = 100 에서는
  거래 집합의 수                      705343...  216 자리 수
  거래 번호 축을 갖는 표의 기본 연산      400,000  6 자리 수
  └ 위는 1 초 안에 다 만들어 볼 수 없고, 아래는 여유 있게 끝난다
```

제약 규모에서 216 자리입니다. 1 초 안에 다 만들어 볼 수 없어요. 그러면 이 216 자리 안에서
무엇이 되풀이되는지 봅시다.

```text
P = [2 6 3 9 5 7] 에서 k = 2 의 집합 몇 개

  {(0,1), (2,3)}   4 + 6 = 10   날 4 와 날 5 를 안 쓴다
  {(0,1), (2,5)}   4 + 4 =  8   앞 거래가 같다
  {(0,1), (4,5)}   4 + 2 =  6   앞 거래가 같다
  {(0,3), (4,5)}   7 + 2 =  9   앞 거래만 다르다
  └ 앞의 셋은 첫 거래가 똑같고 두 번째 거래만 다르다. 같은 앞부분을 몇 번이고 다시 만든다
```

앞 거래가 같은 집합들이 **첫 거래의 이익을 매번 다시 계산**하고 있습니다. 그런데 두 번째 거래를
고를 때 앞쪽에서 알아야 할 것은 「어느 날에 사고 팔았는가」가 아니라 「거기까지의 이익이
얼마인가」 하나뿐이에요.

```text
날 4 에서 2번째 매수를 할 때 앞쪽에서 필요한 것

  {(0,1)} 로 끝냈다        거기까지의 이익 4
  {(0,3)} 로 끝냈다        거기까지의 이익 7
  {(2,3)} 로 끝냈다        거기까지의 이익 6
  이 셋 중 최선            7
  └ 앞으로 할 수 있는 일이 셋 다 같으므로, 앞쪽을 이익 하나로 줄여도 답이 안 바뀐다
```

이제 같은 배열을 두 방식으로 처리하고 실제 계수를 나란히 세어 봅시다. 왼쪽은 집합을 전부
만드는 방식이고, 오른쪽은 날마다 거래 번호별 상태를 이어받는 방식이에요. 날 수를 늘린 줄은
생성식 `P[j] = (j × 37) mod 23` 으로 만든 입력입니다.

<!--proof:costTwoWays-->

```text
방식 (N = 6 · k = 2)                   덧셈·뺄셈  비교  기본 연산 합
거래 집합을 전부 만들어 이익을 더한다         60    31            91
날마다 거래 번호별 상태를 이어받는다          24    24            48

같은 k = 2 에서 날 수만 늘리면
   N    거래 집합을 전부 만든다    날마다 이어받는다
   6                         91                   48
  12                      1,684                   96
  18                      9,640                  144
  24                     32,707                  192
  └ 위는 C(N, 4) 를 따라 늘고, 아래는 날 수에 그대로 비례한다
```

두 줄의 관계가 닫힌 형태로 나옵니다. 위쪽은 집합 하나마다 비교 한 번과 뻗어 나가는 자리마다
덧셈·뺄셈 둘이라 `3 × (집합 수) − 2` 이고, 아래쪽은 (날, 거래 번호) 하나마다 넷이라 `4Nk` 예요.

| 방식 | 기본 연산의 닫힌 형태 | 무엇을 따라가는가 |
| --- | --- | --- |
| 집합을 전부 만들기 | `3 × (집합 수) − 2` | 집합의 개수를 따라간다 |
| 날마다 상태 이어받기 | `4Nk` | 날 수와 거래 상한의 곱을 따라간다 |

그 관찰을 상태로 세우기 전에, 더 단순한 후보부터 시험합시다. 거래가 한 번일 때 쓰던 상태를
그대로 가져오는 것이에요 — 「지금까지의 최저가」 하나만 들고 갑니다.

<!--proof:refuteSingleState-->

```text
입력                         정본이 낸 답  지금까지의 최저가 하나만  판정
전개 입력 k=2 [2 6 3 9 5 7]            10                         7  틀리다
k=2 [1 5 3 6]                           7                         5  틀리다
k=2 [3 2 6 5 0 3]                       7                         4  틀리다
k=2 [1 2 3 4 5]                         4                         4  같다
k=2 [5 4 3 2 1]                         0                         0  같다

└ 이익이 나는 상승 구간이 둘 이상인 입력에서 어긋난다. 그 상태는 「몇 번째 거래인가」를 못 담는다
```

이 후보가 어긋나는 이유는 하나입니다. 최저가 하나로는 **지금까지 몇 번 거래했는지**를 담을 수
없어서, 이익이 나는 상승 구간이 둘 이상이어도 그중 하나밖에 못 세요.

```text
P = [1 5 3 6] 에서 두 후보가 갈리는 자리
  최저가 하나만 든다   1 에 사서 6 에 판 5 를 답으로 낸다        거래 한 번의 답이다
  거래 번호를 든다     (1→5) 와 (3→6) 을 따로 세어 7 을 낸다    거래 두 번의 답이다
  └ 상태에 「몇 번째 거래인가」가 없으면 두 번째 거래를 시작할 자리가 없다
```

그러니 **거래 번호를 상태의 축으로 세운다**는 것이 절차에 있어야 합니다. 여기서 진짜 개념이
나와요. 상태를 「거래 번호 `t`」와 「지금 주식을 들고 있는가」 둘로 정하는 것입니다.

```text
상태를 정하는 규칙

  free[t]   t 번째 매도까지 마쳤고 지금은 안 들고 있다   시작값 0
  hold[t]   t 번째 매수까지 마쳤고 지금 들고 있다        시작값 -∞
  옮겨 가는 길   free[t-1] --매수--> hold[t] --매도--> free[t]
  └ 상태가 2k + 1 개이고, 길은 상태마다 하나씩 들어오는 화살표 하나뿐이다
```

개념이 정하는 것은 **들고 가는 값의 개수와 그 값이 바뀌는 범위**입니다. 날 하나를 지날 때마다
상태 `2k` 개가 각각 한 번씩 갱신되고, 그 계산에 필요한 과거는 어제까지의 상태값뿐이에요.

```text
날 하나를 지날 때
  읽는 과거        어제까지의 상태 2k + 1 개   그보다 앞의 날은 읽지 않는다
  새로 정하는 값   상태 2k 개                  각각 비교 한 번이다
  답의 자리        free[k]                     마지막 날의 그 값이 답이다
  └ 그래서 들고 가야 할 것이 배열 칸 2(k + 1) 개다 — 상태 2k + 1 개에 한 번도 안 쓰는 hold[0] 이 한 칸 붙는다
```

**쉬운 경우와 불안한 경우를 나눠서 값으로 확인합시다.** 쉬운 경우는 거래 번호가 1 일 때예요.
`free[0]` 이 언제나 `0` 이라 `hold[1]` 은 「지금까지의 최저가에 마이너스를 붙인 값」이 되고,
이것은 거래가 한 번일 때의 풀이와 같은 것입니다.

```text
거래 번호 1 은 거래 한 번 문제와 같다 — P = [2 6 3 9 5 7]
  날 0   hold[1] = 0 - 2 = -2   free[1] = 0        지금까지의 최저가 2
  날 1   hold[1] = -2 그대로    free[1] = 4        6 - 2 = 4
  날 3   hold[1] = -2 그대로    free[1] = 7        9 - 2 = 7
  └ hold[1] 에 마이너스를 붙이면 2 이고, 그것이 지금까지의 최저가다
```

불안한 경우는 **거래 번호가 2 이상일 때**입니다. `hold[2]` 는 `free[1]` 을 읽는데, 그 `free[1]`
이 날마다 커지므로 `hold[2]` 도 뒤늦게 올라갈 수 있는 자리예요.

```text
거래 번호 2 는 free[1] 이 커질 때마다 다시 좋아진다
  날 0   free[1] = 0   hold[2] = 0 - 2 = -2
  날 2   free[1] = 4   hold[2] = 4 - 3 = 1     free[1] 이 커진 뒤라 -2 에서 1 로 올라간다
  날 4   free[1] = 7   hold[2] = 7 - 5 = 2     free[1] 이 또 커진 뒤라 1 에서 2 로 올라간다
  └ 앞 거래를 나중에 더 좋은 짝으로 바꾸는 것이 이 갱신이다. 다시 계산하지 않고 값 하나만 읽는다
```

그런데 이미 확정된 이익은 내려가지 않습니다. `hold[2]` 가 올라가도 `free[2]` 는 최댓값 갱신이라
그대로 남고, 다음에 더 좋은 매도일이 나타날 때만 커져요.

```text
날 4 에서 hold[2] 가 1 에서 2 로 올라갈 때
  갱신 전             hold[2] = 1   free[2] = 10
  갱신 후             hold[2] = 2   free[2] = 10 그대로
  오늘 파는 후보      2 + 5 = 7     10 보다 작아서 안 바뀐다
  └ hold 는 앞으로 팔 날을 위한 값이고, free 는 이미 확정된 답이다
```

빠뜨리는 자리가 없다는 것은 두 반복의 종료 조건으로 말할 수 있습니다. 바깥은 `j` 를 `0` 부터
`N−1` 까지 하나씩 올리고 안쪽은 `t` 를 `1` 부터 `k` 까지 하나씩 올리므로, `(j, t)` 짝이 정확히
한 번씩 실행돼요.

```text
두 반복이 끝난 시점
  실행된 짝   (0,1) (0,2) ... (N-1,k)   N × k 개, 각각 정확히 한 번
  안 본 자리  없다                      free[0] 은 갱신 대상이 아니라 늘 0 이다
  └ 날 × 거래 번호의 모든 칸이 빠짐없이 한 번씩 값으로 만들어진다
```

이제 「거래 번호를 축으로 두는 것」이 값에서 무엇을 바꾸는지 확인합니다. 거래 상한 `k` 를
1 부터 5 까지 놓고 같은 배열에 실행했어요.

```text
k  답  표의 기본 연산  거래 집합 수  열거의 기본 연산
1   7              24            16                46
2  10              48            31                91
3  12              72            32                94

└ 답은 k = 3 부터 12 에서 멈추는데 표가 하는 일은 k 에 그대로 비례해 는다
```

답이 `k = 3` 에서 멈추는 것은 이 배열에 이익이 나는 상승 구간이 셋뿐이기 때문입니다. 표가 하는
일은 그 뒤로도 `k` 에 비례해 늘지만 답은 안 커져요. 그리고 열거 쪽은 `k = 3` 을 넘으면 새로
만들 집합이 없어서 94 에서 멈춥니다.

```text
얻은 절차 한 벌

  2. 날을 0 부터 N-1 까지 차례로 읽으며
  3.   거래 번호 t 를 1 부터 k 까지 올리며
  4.     hold[t] 를 hold[t] 와 (free[t-1] - 오늘 가격) 중 큰 쪽으로 바꾼다
  5.     free[t] 를 free[t] 와 (hold[t] + 오늘 가격) 중 큰 쪽으로 바꾼다
  6. free[k] 를 돌려준다
     └ 216 자리이던 것이 여섯 자리가 된다
```

### 수행으로 알아보는 알고리즘 — 여섯 날을 한 번 읽어 두 거래의 최대 이익을 낸다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각
마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const k = 2;
const prices = [2, 6, 3, 9, 5, 7];
// 이 절이 끝나면 10 이 나와야 한다
```

왜 하필 이 여섯 날과 `k = 2` 일까요? 이익이 나는 상승 구간이 셋인데 거래는 둘까지라 **`k` 가
실제로 답을 제한하고**, 답 10 이 한 거래로는 안 나오며(한 번이면 7), `hold[2]` 가 두 번 올라가
「앞 거래를 나중에 더 좋은 짝으로 바꾸는」 갱신이 실행되기 때문이에요.

```text
절차 전체를 한 장으로

  T1       hold 를 -∞ 로, free 를 0 으로 채운다      ① 두 상태 배열의 시작값
           날 0 부터 날 N-1 까지 차례로:              ② 읽을 날이 남았는가
  T2~T7      거래 번호 t 를 1 부터 k 까지:            ③ 거래 번호가 k 를 넘지 않았는가
               t 번째 매수를 갱신한다                 ④ 매수 갱신
               t 번째 매도를 갱신한다                 ⑤ 매도 갱신
  T8       free[k] 를 돌려준다
```

#### 1. 두 상태 배열을 시작값으로 둔다

첫 조각은 준비입니다. 칸 번호 `0` 부터 `k` 까지의 배열 둘을 잡고, 아직 반복에는 들어가지
않아요.

```ts
const hold = new Array<number>(k + 1).fill(Number.NEGATIVE_INFINITY);   // ① 보유 상태
const free = new Array<number>(k + 1).fill(0);                          // ① 비보유 상태
```

`①` 의 두 시작값이 **서로 다른 것**이 이 조각의 요점입니다. 첫날 전에는 어떤 매수도 일어나지
않았으니 보유 상태에 도달할 방법이 없고, 거래를 한 번도 안 한 이익은 `0` 이에요.

```text
T1 이 끝난 시점
  hold = [-∞ -∞ -∞]   칸 번호 0 1 2. 어느 것도 도달할 수 없는 상태다
  free = [  0   0  0]  거래를 t 번까지 했을 때의 이익이고, 아직 아무것도 안 했다
  └ free[0] 은 이 뒤로 한 번도 안 바뀐다. 갱신 대상이 t = 1 부터이기 때문이다
```

#### 멈춤 — 가장 큰 거래를 먼저 확정하고 그 두 날을 지우면 답이 두 방향으로 어긋난다

여기서 헷갈리기 쉬운 포인트는 **거래를 하나씩 확정해도 되는가**입니다. 「가장 이익이 큰 거래를
먼저 잡고, 그 매수일과 매도일을 배열에서 지운 다음 남은 날에서 같은 일을 `k` 번 되풀이하면
되지 않나」로 읽기 쉬워요. 그 생각대로 적어 봅시다.

```ts
let days = [...prices];
let total = 0;
for (let round = 0; round < k; round++) {
  let buyAt = -1, sellAt = -1, gain = 0;
  for (let b = 0; b < days.length; b++) {
    for (let s = b + 1; s < days.length; s++) {
      if ((days[s] as number) - (days[b] as number) > gain) {
        gain = (days[s] as number) - (days[b] as number);
        buyAt = b; sellAt = s;                        // 가장 큰 거래를 먼저 확정했다
      }
    }
  }
  if (gain === 0) break;
  total += gain;
  days = days.filter((_, idx) => idx !== buyAt && idx !== sellAt);
}
```

다섯 입력으로 확인해 봅니다.


**어긋나는 방향이 둘**이라는 것이 이 실수의 성격입니다. 날을 지우면 남은 날들이 앞뒤로 붙어
버려서, 지운 두 날 사이에 있던 날끼리 짝을 지어도 그것이 겹치는 거래인지 알 수 없어요.

```text

  남은 날  [6 3 5 7]                                      원래 날 번호로는 1 2 4 5

  └ 두 거래가 시간에서 겹치는데 지운 배열에서는 그것이 안 보인다. 정본의 답은 10 이다

[1 5 3 6] 에서 아래로 어긋나는 자리
  1 바퀴   가장 큰 거래는 1 에 사서 6 에 판 5 다           날 0 과 날 3 을 지운다
  남은 날  [5 3]                                          내려가기만 해서 이익이 없다

  └ 큰 거래 하나를 둘로 쪼개는 것이 이득인 자리를 못 본다
```

#### 2. 하루를 읽고 거래 번호를 1 부터 k 까지 올린다

둘째 조각은 순회입니다. 날 하나마다 거래 번호를 `1` 부터 `k` 까지 올리며 매수와 매도를 차례로
갱신해요.

```ts
for (const price of prices) {                                   // ② 읽을 날이 남았는가
  for (let t = 1; t <= k; t++) {                                // ③ 거래 번호가 k 를 넘지 않았는가
    hold[t] = Math.max(hold[t] as number, (free[t - 1] as number) - price);   // ④ 매수 갱신
    free[t] = Math.max(free[t] as number, (hold[t] as number) + price);       // ⑤ 매도 갱신
  }
}
```

`②` 는 여섯 날 동안 참이고 일곱 번째에 거짓이 됩니다. `③` 은 날마다 `t = 1` 과 `t = 2` 에서
참이고 `t = 3` 에서 거짓이 돼요. `④` 와 `⑤` 는 그래서 날마다 두 번씩, 모두 열두 번씩
실행됩니다. 앞 세 날만 실행하면 이렇게 나와요.

| 걸음 | `j` | `P[j]` | `hold[1]` | `free[1]` | `hold[2]` | `free[2]` |
| --- | --- | --- | --- | --- | --- | --- |
| T2 | 0 | 2 | -2 | 0 | -2 | 0 |
| T3 | 1 | 6 | -2 | 4 | -2 | 4 |
| T4 | 2 | 3 | -2 | 4 | 1 | 4 |

T4 가 이 세 줄의 핵심입니다. `hold[2]` 가 `-2` 에서 `1` 로 올라간 자리이고, 그 값은 같은 날
안에서 이미 갱신된 `free[1] = 4` 에서 오늘 가격 3 을 뺀 것이에요.

```text
T4 가 하는 일
  t = 1   hold[1] = max(-2, 0 - 3) = -2        free[1] = max(4, -2 + 3) = 4
  t = 2   hold[2] = max(-2, 4 - 3) = 1         free[2] = max(4, 1 + 3) = 4
  └ t = 2 가 읽는 free[1] 은 같은 날 t = 1 이 방금 확정한 값이다. 같은 날 팔고 다시 사는 것이 허용된다
```

#### 멈춤 — 거래 상한을 크게 잡아도 답이 줄어들지 않는다

여기서 헷갈리기 쉬운 포인트는 `free[k]` 를 읽는다는 것입니다. 「`free[k]` 는 **정확히** `k` 번
거래했을 때의 이익이니, `k` 를 크게 잡으면 안 해도 될 거래까지 억지로 하게 되어 답이 작아지는
것 아닌가」로 읽기 쉬워요. 그 걱정대로라면 배열 전체의 최댓값을 답으로 내야 합니다.

```ts
return Math.max(...free);   // free[k] 대신 배열 전체의 최댓값을 답으로 냈다
```

**이 문제에서는 답이 한 번도 안 갈립니다.** 다섯 입력으로 확인해 봅니다.

<!--proof:pauseRowMax-->

```text
입력                         정본이 낸 답  free 배열의 최댓값  판정
전개 입력 k=2 [2 6 3 9 5 7]            10                  10  같다
k=1 [2 6 3 9 5 7]                       7                   7  같다
k=5 [2 6 3 9 5 7]                      12                  12  같다
k=3 [5 4 3 2 1]                         0                   0  같다
k=4 [1 2 3 4 5]                         4                   4  같다

전개 입력을 k = 6 로 한 번 실행한 뒤의 free 배열
  t        0  1   2   3   4   5   6
  free[t]  0  7  10  12  12  12  12
  └ 7 칸이 한 번도 안 줄어든다. 마지막 칸이 곧 그 줄의 최댓값이다
```

답이 안 갈린다는 것을 먼저 적어 둡니다. 그래도 이 자리를 넘어가면 안 되는 이유는, `free[k]`
하나만 읽어도 되는 근거를 모르면 코드를 읽다가 매번 이 자리에서 멈추기 때문이에요. 근거는
`free` 가 칸 번호에 대해 한 번도 안 줄어든다는 것입니다.

```text
free 가 칸 번호를 따라 안 줄어드는 이유

  기저 t = 1       free[1] 은 0 에서 시작해 max 로만 바뀐다   free[0] = 0 이라 free[1] ≥ free[0]
                   hold[1] 은 -∞ 가 아닌 값을 받는다           hold[0] 은 -∞ 그대로라 hold[1] ≥ hold[0]
  단계 t ≥ 2       hold[t] 는 free[t-1] 을 읽고               hold[t-1] 은 free[t-2] 를 읽는다
                   free[t-1] ≥ free[t-2] 가 이미 참이므로     hold[t] ≥ hold[t-1] 이 된다
                   free[t] 는 hold[t] 를, free[t-1] 은 hold[t-1] 을 읽으므로 free[t] ≥ free[t-1]
  └ 칸 번호가 하나 늘 때마다 「거래를 한 번 더 해도 된다」가 붙으므로 후보가 늘기만 한다
```

「거래를 `t` 번까지 한다」는 「거래를 `t-1` 번까지 한다」를 이미 담고 있어서, `free[t]` 가
`free[t-1]` 보다 작아질 수 없습니다. 그래서 마지막 칸이 곧 그 배열의 최댓값이에요.

#### 3. 여섯 날을 끝까지 읽어 답을 낸다

두 조각을 이어 고정 입력에 실행하면 여덟 걸음이 나옵니다. T1 은 준비, T2 부터 T7 까지가 여섯
날의 순회, T8 이 반환이에요.


**다섯 갈래가 모두 실행됐습니다.** 오른쪽 열에 `hold` 와 `free` 가 함께 적히는 걸음이 없는
것에도 이유가 있어요. 거래 번호 1 에서 보면 분명합니다 — `hold[1]` 이 올라가는 날은 오늘
가격이 지금까지의 최저가보다 낮은 날이고, 그런 날에 오늘 파는 이익은 `0` 이라 `free[1]` 을 못
올려요. 거래 번호 2 에서도 이 전개에서는 같은 자리가 안 나옵니다.

| 라벨 | 무엇 | 전개에서 |
| --- | --- | --- |
| `①` | 두 상태 배열의 시작값 | T1 에서 한 번 |
| `②` | 읽을 날이 남았는가 | T2 부터 T7 까지 참 · T8 에서 거짓 |
| `③` | 거래 번호가 `k` 를 넘지 않았는가 | 날마다 `t = 1` `t = 2` 에서 참 · `t = 3` 에서 거짓 |
| `④` | 매수 갱신 | T2 T4 T6 에서 값이 바뀌고 T3 T5 T7 에서는 그대로 |
| `⑤` | 매도 갱신 | T3 T5 에서 값이 바뀌고 T2 T4 T6 T7 에서는 그대로 |

답이 정말 두 거래의 이익 합인지 확인하고 갑니다. `free[2] = 10` 을 만든 것은 날 0 에 사서 날 1
에 팔고 날 2 에 사서 날 3 에 판 것이고, 그 네 가격을 직접 빼고 더하면 같은 수가 나와야 해요.

| 무엇 | 값 |
| --- | --- |
| 1번째 거래의 매수일과 매도일 | 날 0 과 날 1 |
| 그 두 날의 가격 | 2 와 6 |
| 2번째 거래의 매수일과 매도일 | 날 2 와 날 3 |
| 그 두 날의 가격 | 3 과 9 |
| 직접 더한 값 | (6 - 2) + (9 - 3) = 10 |
| 마지막 걸음 T7 의 `free[2]` | 10 |

#### 멈춤 — 매수 갱신이 읽는 자리를 한 칸 옮기면 거래 상한이 사라진다

여기서 헷갈리기 쉬운 포인트는 `④` 가 **어느 칸을 읽는가**입니다. 「어차피 같은 날의 값이니
`free[t-1]` 이든 `free[t]` 든 비슷하지 않나」로 읽기 쉬워요. 한 글자만 바꿔 봅시다.

```ts
hold[t] = Math.max(hold[t] as number, (free[t] as number) - price);   // 칸 번호를 t 로 읽었다
```

다섯 입력으로 확인해 봅니다.

<!--proof:pauseSameIndex-->

```text
입력                         정본이 낸 답  같은 거래 번호를 읽은 답  판정
전개 입력 k=2 [2 6 3 9 5 7]            10                        12  틀리다

k=1 [1 2 3 4 5]                         4                         4  같다

└ 변이가 전개 입력에서 낸 답과 거래 횟수를 세지 않았을 때의 답이 둘 다 12 이다 — 상한이 통째로 사라진다
```

읽는 칸이 같아지면 **거래를 몇 번 했는지가 어디에도 안 남습니다.** `t` 번째 매수가 `t` 번째
매도 뒤에 다시 올 수 있게 되므로, 같은 칸 안에서 사고팔기를 몇 번이든 되풀이할 수 있어요.

```text
칸 번호를 t 로 읽으면 무엇이 되는가
  원래           free[t-1] --매수--> hold[t] --매도--> free[t]   화살표가 앞 칸에서 들어온다
  바꾼 뒤        free[t] --매수--> hold[t] --매도--> free[t]      화살표가 제자리로 돌아온다
  그 결과        칸 하나가 거래 횟수 제한 없는 문제를 푼다
  └ 전개 입력의 답이 10 에서 12 로 커진다. 12 는 거래 횟수를 안 셀 때의 답이다
```

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 `free[k]` 를 돌려주는 마지막 한
줄뿐이에요 — `k` 가 `0` 이면 배열 길이가 1 이라 안쪽 반복이 한 번도 실행되지 않고 `free[0] = 0`
이 그대로 답이 되며, 날이 하나뿐이면 그날 사서 그날 판 이익 `0` 만 후보에 들어옵니다.

```ts
export function bestTimeToBuyAndSellStockK(
  k: number,
  prices: number[],
): number {
  // ① 두 상태 배열을 시작값으로 둔다. `hold[t]` 는 t 번째 매수를 마치고 아직 안 판 상태의
  //    최대 이익이고, `free[t]` 는 t 번째 매도까지 마친 상태의 최대 이익이다. 첫날 전에는
  //    매수를 마친 상태에 도달할 방법이 없고, 거래를 한 번도 안 한 이익은 0 이다.
  const hold = new Array<number>(k + 1).fill(Number.NEGATIVE_INFINITY);
  const free = new Array<number>(k + 1).fill(0);

  for (const price of prices) {
    // ② 아직 안 읽은 날이 남았는가 — 남아 있으면 그 날 하나에서 아래 두 줄을 k 번 실행한다.
    for (let t = 1; t <= k; t++) {
      // ③ 거래 번호가 k 를 넘지 않았는가 — 넘으면 오늘의 갱신을 끝내고 다음 날로 간다.
      // ④ t 번째 매수를 오늘 하는 쪽과 어제까지 이미 해 둔 쪽 중 큰 값을 남긴다. 오늘 사려면
      //    직전 거래까지 끝나 있어야 하므로 거래 번호가 하나 작은 매도 상태에서 출발한다.
      hold[t] = Math.max(hold[t] as number, (free[t - 1] as number) - price);
      // ⑤ t 번째 매도를 오늘 하는 쪽과 어제까지 이미 해 둔 쪽 중 큰 값을 남긴다.
      free[t] = Math.max(free[t] as number, (hold[t] as number) + price);
    }
  }

  return free[k] as number;
}
```

```text
bestTimeToBuyAndSellStockK(2, [2, 6, 3, 9, 5, 7])   → 10
bestTimeToBuyAndSellStockK(1, [2, 6, 3, 9, 5, 7])   →  7
bestTimeToBuyAndSellStockK(2, [2, 4, 1, 5])         →  6
bestTimeToBuyAndSellStockK(0, [1, 5, 3, 8])         →  0
bestTimeToBuyAndSellStockK(100, [0, 10000])         → 10000
```

### 알아 두면 좋은 개념 — 상태 기계 동적 계획법

이 절차가 세운 상태 다섯은 이름이 붙어 있는 모양입니다. 상태를 꼭짓점으로, 상태 사이의 이동을
화살표로 그리고 **입력 하나를 읽을 때마다 모든 꼭짓점의 값을 한 걸음씩 갱신하는** 방식을
**상태 기계 동적 계획법**이라고 불러요.

```text
날 하나가 화살표 넷을 한 번씩 시험한다 (아래 값은 날 3 을 처리한 직후)

  free[0] --매수--> hold[1] --매도--> free[1] --매수--> hold[2] --매도--> free[2]
     0                -2                7                 1                10

  화살표를 지날 때 하는 일
    매수 화살표   앞 꼭짓점의 값에서 오늘 가격을 뺀다
    매도 화살표   앞 꼭짓점의 값에 오늘 가격을 더한다
  └ 꼭짓점 하나가 코드의 배열 칸 하나이고, 화살표 하나가 코드 한 줄이다
```

꼭짓점과 화살표를 그려 두면 **문제가 바뀌었을 때 무엇을 고칠지가 그림 위에서 정해집니다.**
같은 문제 무리의 변형 셋이 이 그림에서 어떻게 갈리는지 보면 그것이 확인돼요.

| 문제가 이렇게 바뀌면 | 그림에서 무엇이 바뀌는가 | 코드에서 무엇이 바뀌는가 |
| --- | --- | --- |
| 거래마다 수수료 `f` 를 뗀다 | 매도 화살표에 `− f` 가 붙는다 | 매도 갱신 줄에 뺄셈 하나 |
| 팔고 하루 쉬어야 다시 살 수 있다 | 꼭짓점 사이에 「쉬는 중」이 하나 늘어난다 | 배열이 하나 더 늘어난다 |
| 거래 횟수에 상한이 없다 | 매수 화살표가 제자리로 돌아온다 | 칸 번호 `t` 가 없어진다 |

이 이름은 이 편 밖에서도 쓰입니다. 문자열을 한 글자씩 읽으며 「지금까지 읽은 것이 어떤 모양인가」
를 꼭짓점으로 두는 문자열 매칭, 신호를 읽으며 「지금 어느 구간에 있는가」를 꼭짓점으로 두는 은닉
마르코프 모형의 비터비 알고리즘이 같은 모양이에요.

```text
같은 모양이 나오는 다른 자리
  주식 문제 무리     보유 · 비보유 · 쉬는 중을 꼭짓점으로 둔다
  문자열 매칭        지금까지 맞춘 글자 수를 꼭짓점으로 둔다
  비터비 알고리즘    지금 어느 은닉 상태에 있는가를 꼭짓점으로 둔다
  └ 셋 다 「입력 하나를 읽을 때마다 모든 꼭짓점을 한 번씩 갱신한다」가 같다
```

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 상태와 이동을 식으로 어떻게
적는지, 무엇이 매 걸음 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **입력을 한 방향으로 읽으면서 답을 만들 수 있습니다.** 날짜처럼 순서가 정해진 축이 있고,
  뒤에서 앞으로 되돌아갈 일이 없어야 해요.
- **「지금까지 무엇을 했는가」가 몇 개 안 되는 상태로 줄어듭니다.** 여기서는 거래 번호와 보유
  여부의 짝이고, 그래서 상태가 `2k + 1` 개예요.
- **고를 것의 개수에 상한이 있고 그 상한이 작습니다.** 상한이 상태의 축이 되므로, 상한이 크면
  표도 그만큼 커져요.
- 답이 **한 번만** 필요합니다. 가격이 바뀌면 처음부터 다시 읽어야 해요.

```text
네 조건이 코드의 모양을 그대로 정한다
  한 방향으로 읽는다         → 바깥 반복이 날짜 하나뿐이다
  상태가 몇 개 안 된다       → 배열 둘로 끝난다
  개수에 상한이 있다         → 그 상한이 배열의 길이가 된다
  답이 한 번 필요하다        → 한 번 읽고 끝난다
```

세 번째 줄이 이 절차의 경계입니다. 상한 `k` 가 커지면 표가 그만큼 커지고, `k` 가 날 수의 절반을
넘으면 상한이 아무것도 제한하지 않아 표를 더 키우는 것이 낭비가 돼요.

```text
거래를 한 번만 한다        지금까지의 최저가 하나를 들고 간다     bestTimeToBuyAndSellStock
거래를 k 번까지 한다       거래 번호마다 상태를 따로 든다         이 글의 절차
거래 횟수에 상한이 없다    하루치 상승분을 전부 더한다            반복 한 번으로 끝난다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "최대 k 번"  "k 번 이하로"  "많아야 k 개"      ← 개수 상한이 상태의 축이 된다
  "겹치지 않게 고른다"  "앞 것을 끝내야 다음"    ← 상태에 「지금 무엇을 하는 중인가」가 필요하다
  "사고파는 것을 되풀이한다"                     ← 보유·비보유 두 상태가 번갈아 나온다
  "하지 않아도 된다"                             ← 시작값이 0 이고 답이 0 이상이다

제약에 이런 모양이 보이면
  N 과 k 의 곱이 10^6 언저리 이하다
  개수 상한 k 가 따로 주어진다

반대로 이런 말이 보이면 해당하지 않는다
  "횟수 제한이 없다"                             ← 상태의 축이 없어져 반복 한 번으로 끝난다
  "동시에 여러 주식을 들 수 있다"                ← 보유 상태가 하나로 안 줄어든다
  "질의가 여러 번 들어온다"  "가격이 바뀐다"     ← 읽기를 매번 다시 해야 한다
  "k 가 10^5 이상이다"                           ← 표가 N × k 라 다 못 채운다
```

마지막 무리가 보이면 다른 절차로 갑니다. 거래 횟수에 상한이 없거나 상한이 날 수의 절반을 넘으면
하루치 상승분을 더하는 것으로 끝나고, 그 사이의 큰 상한은 아래 「경쟁 설계와의 대조」 쪽 방식이
연산 수가 적어요.

#### 실제로 쓰이는 곳

- **`ruptures` — 시계열의 변화점을 찾는 파이썬 라이브러리.** `Dynp` 클래스 설명이 *"Find
  optimal change points using dynamic programming. Given a segment model, it computes the best
  partition for which the sum of errors is minimum."* 이고, 답을 물을 때 `predict(n_bkps)` 로
  **구간의 개수를 인자로 받습니다.** 개수를 상태의 축으로 두고 표를 채우는 자리가 이 글과 같은
  것이에요. 다른 것은 그쪽이 신호를 빈틈없이 나누는 문제라 「보유·비보유」 두 상태가 없다는
  점입니다.
  ([`Dynp` 공식 문서](https://centre-borelli.github.io/ruptures-docs/code-reference/detection/dynp-reference/),
  [저장소](https://github.com/deepcharles/ruptures), 조회 2026-08-31)

```python
algo = rpt.Dynp(model="l2").fit(signal)
result = algo.predict(n_bkps=3)
```

- **Csűrös, M. (2004). "Maximum-scoring segment sets." IEEE/ACM Transactions on Computational
  Biology and Bioinformatics 1(4), 139–150.** 점수 배열에서 **겹치지 않는 구간들을 골라 점수 합을
  최대로 하는 문제**를 다루고, DNA·단백질 분절과 서열 정렬 후처리를 응용으로 듭니다. 가격 배열의
  하루치 차이를 점수로 두면 이 글의 문제와 같은 것이 돼요 — 거래 하나의 이익이 그 구간의 차이
  합이기 때문입니다.
  ([출판사 목록](https://dl.acm.org/doi/10.1109/TCBB.2004.43),
  [PubMed 목록](https://pubmed.ncbi.nlm.nih.gov/17051696/), 조회 2026-08-31)

```text
가격 배열을 하루치 차이로 바꾸면 구간 고르기가 된다
  가격 P        2    6    3    9    5    7
  차이 D             4   -3    6   -4    2      D[j] = P[j] - P[j-1]
  거래 (0,1)         4                          구간 [1,1] 의 합
  거래 (2,3)                   6                구간 [3,3] 의 합
  └ 겹치지 않는 구간 두 개를 골라 합을 최대로 하는 것과 같다. 답도 4 + 6 = 10 으로 같다
```

**거래 횟수 상한이 붙은 이 절차 그대로를 이름 붙여 제공하는 표준 라이브러리는 1 차 출처로
확인하지 못했습니다.** 위 논문도 출판사 목록에서 서지 사항과 초록의 요지만 확인했고 본문은 열지
못했어요. 확인한 것은 개수를 상태의 축으로 두는 표가 실제 라이브러리에 있다는 것과, 이 문제의
일반형이 유전체 분석 문헌에서 다뤄진다는 것 둘입니다.

#### 경쟁 설계와의 대조

같은 목표(거래 상한이 `k` 일 때의 최대 이익을 아는 것)를 노리는 다른 절차로 **거래 하나마다
벌금을 매기고 그 벌금을 이분 탐색하는 방식**이 있습니다. 거래 횟수를 세지 않는 대신 매도할 때마다
벌금 `lam` 을 빼고 한 바퀴 실행하면, 벌금이 클수록 최적이 되는 거래 수가 줄어들어요. 거래 수가
`k` 이하가 되는 가장 작은 정수 벌금을 찾은 다음 `이익 + lam × k` 를 내면 답이 나옵니다.

```text
두 설계가 거래 상한을 다루는 방법
  거래 번호 축을 갖는 표   상한을 배열의 길이로 둔다. 상한이 커지면 배열이 커진다
  거래마다 벌금            상한을 벌금 하나로 바꾼다. 벌금 후보를 이분 탐색한다
  └ 앞은 k 에 비례해 일이 늘고, 뒤는 가격의 범위에만 달렸다
```

같은 입력·같은 거래 상한에 두 설계를 걸고 **기본 연산 수**(덧셈·뺄셈 + 비교)를 셌습니다. 가격
배열은 `N = 1,000` 이고 `P[j] = (j × 617) mod 1,001` 로 만들었어요. 벌금 후보를 이분 탐색하는
범위는 제약이 정한 가격의 최댓값을 따라 `0` 부터 `10,000` 까지입니다. **전개 입력을 그대로 쓰지 않은 이유**는 여섯 날에
`k = 2` 로는 두 설계가 갈리는 축인 `k` 를 넓게 놓을 수 없기 때문이에요.

| 거래 상한 `k` | 거래 번호 축을 갖는 표 | 거래마다 벌금 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 1 | **4,000** | 70,014 | 표가 17 배 넘게 적습니다 |
| 17 | **68,000** | 70,014 | 표가 근소하게 적습니다 |
| 18 | 72,000 | **70,014** | **여기서 순서가 뒤집힙니다** |
| 100 | 400,000 | **70,014** | 벌금 쪽이 5 배 넘게 적습니다 |

**저장 칸은 `k = 1` 에서 4 개로 같고 `k = 100` 에서 202 개 대 4 개입니다.** 표 쪽만 `k` 를 따라
늘어나요 — 갈리는 것은 연산 수이고, 그 경계가 이 입력에서 **거래 상한 18** 입니다.

```text
경계가 그 자리인 이유

  표가 거래 상한 하나마다 더 쓰는 연산 수   4 × 1,000 = 4,000
  벌금 쪽이 상한과 상관없이 쓰는 연산 수    5,001 × 14 = 70,014
                                            한 바퀴 5,001 · 위 네 상한에서 다 13 바퀴와 마지막 한 바퀴
  70,014 를 4,000 으로 나누면 17.5          실측에서 뒤집히는 자리가 거래 상한 18 이다
```

**이 절차가 내주는 것은 큰 거래 상한입니다.** `k` 가 커지면 표의 줄이 그만큼 늘어나 연산 수와
저장 칸이 함께 커져요. 그 대신 얻는 것이 셋입니다.

```text
거래 번호 축을 갖는 표가 얻는 것
  작은 상한의 비용   k = 1 에서 4,000 대 70,014     벌금 쪽은 상한이 1 이어도 이분 탐색을 한다
  한 번에 다 낸다    free[1] 부터 free[k] 까지      상한마다의 답이 한 실행에서 전부 나온다
  가정이 없다        max 두 줄이 전부다             벌금 쪽은 상한을 올릴 때 늘어나는 이익이
                                                    줄어든다는 성질이 참이어야 답이 맞는다
  └ 벌금 쪽은 가격이 정수이고 범위가 정해져 있어야 이분 탐색이 정확히 끝난다
```

문제가 `k ≤ 100` 을 제약으로 주었으니 상한이 17 이하인 입력에서는 표가 답입니다. 같은 지문에서
**거래 상한이 18 을 넘는 순간** 이 판정은 다시 해야 해요.

### 수식 정의와 유도

거래 집합과 상태를 기호로 정의합니다. 거래 집합 `S` 는 매수일과 매도일의 짝을 시간 순서로 늘어
놓은 것이고, 그 이익은 짝마다의 차이를 더한 값이에요.

$$S = \{(b_1, s_1), \dots, (b_r, s_r)\},\quad b_1 \le s_1 < b_2 \le s_2 < \cdots < b_r \le s_r, \qquad \text{profit}(S) = \sum_{u=1}^{r} \bigl(P[s_u] - P[b_u]\bigr)$$

```text
정의를 값에 넣어 봅니다 — P 의 값 2 6 3 9 5 7
  S = {(0,1), (2,3)}   (6 - 2) + (9 - 3)   = 10
  S = {(0,3)}          (9 - 2)             =  7
  S = {}               빈 합                =  0
  S = {(0,3), (2,5)}   둘째 매수일 2 가 첫 매도일 3 보다 앞이라 시간 순서를 안 지킨다
```

답은 거래 수 `r` 이 `k` 이하인 집합들 중 이익이 가장 큰 것입니다. 상태 둘도 기호로 적어요 —
날 `0` 부터 날 `j` 까지만 쓴다는 제한이 두 정의의 핵심입니다.

$$\text{답} = \max_{|S| \le k} \text{profit}(S), \qquad \text{free}_t(j) = \max_{\substack{|S| \le t \\ s_u \le j}} \text{profit}(S), \qquad \text{hold}_t(j) = \max_{\substack{|S| = t,\ s_t \text{ 는 아직 없음} \\ b_t \le j}} \Bigl(\text{profit}(S) - P[b_t]\Bigr)$$

```text
정의를 집합으로 펴서 값에 넣어 봅니다 — P 의 값 2 6 3 9 5 7
  free_1(3)   날 3 까지 · 거래 1 번까지     {(0,3)} 이 최선이라            9 - 2   =  7
  free_2(3)   날 3 까지 · 거래 2 번까지     {(0,1), (2,3)} 이 최선이라     4 + 6   = 10
  hold_2(2)   날 2 까지 · 2번째 매수까지    {(0,1)} 뒤 날 2 에 샀으므로    4 - 3   =  1
  └ hold 는 산 값을 이미 뺀 값이라 아직 이익이 아니다. 파는 날이 정해져야 이익이 된다
```

식의 $\text{free}_t$ 와 $\text{hold}_t$ 는 코드에서 `free` 와 `hold` 이고, 아래 첨자 `t` 가 배열의
칸 번호입니다. 날 번호 `j` 는 코드에 배열로 남지 않아요 — 날을 하나씩 읽으며 같은 칸을 덮어쓰기
때문입니다. 정의를 전개 입력에 넣어 확인하고 갑시다. 날 `j` 까지만 잘라 낸 가격 배열에 절차를
그대로 걸면 그 값이 나와야 해요.

<!--proof:mathCheck-->

```text
j  날 0 부터 날 j 까지의 가격  free_1(j)  free_2(j)
0  [2]                                 0          0
1  [2 6]                               4          4
2  [2 6 3]                             4          4
3  [2 6 3 9]                           7         10
4  [2 6 3 9 5]                         7         10
5  [2 6 3 9 5 7]                       7         10

└ 마지막 줄의 free_2(5) = 10 이 이 문제의 답이다. 두 열 다 j 가 늘어도 안 줄어든다
```

이제 유도합니다. 날 `j` 를 처리한 직후의 상태를 **그 날에 무엇을 했는가**로 가르면 후보가 둘로
완전히 갈려요.

$$\text{hold}_t(j) = \max\bigl(\text{hold}_t(j-1),\ \text{free}_{t-1}(j) - P[j]\bigr), \qquad \text{free}_t(j) = \max\bigl(\text{free}_t(j-1),\ \text{hold}_t(j) + P[j]\bigr)$$

```text
왜 두 항뿐인가
  hold 의 첫 항   오늘 사지 않았다   어제까지 이미 t 번째 매수를 마친 상태 그대로다
  hold 의 둘째 항 오늘 샀다          t-1 번째 매도까지 끝난 상태에서 오늘 가격을 뺀다
  free 의 첫 항   오늘 팔지 않았다   어제까지 이미 t 번째 매도를 마친 상태 그대로다
  free 의 둘째 항 오늘 팔았다        t 번째 매수를 마친 상태에 오늘 가격을 더한다
  └ 오늘 산 것과 안 산 것 사이에 다른 경우가 없다. 같은 날 사고파는 것은 두 항에 함께 들어간다
```

`hold` 의 둘째 항이 $\text{free}_{t-1}(j-1)$ 이 아니라 $\text{free}_{t-1}(j)$ 인 것에 이유가
있습니다. 문제가 같은 날 팔고 다시 사는 것을 허용하므로, 오늘의 `t-1` 번째 매도까지 마친 상태에서
오늘 다시 살 수 있어요. 코드에서 거래 번호를 작은 쪽부터 올리는 것이 이 자리입니다.

```text
같은 날에 팔고 다시 사는 자리 — 날 2 (가격 3)
  t = 1 을 먼저      free_1(2) = 4            날 1 에 판 이익이 오늘 값으로 확정된다
  t = 2 가 읽는다    hold_2(2) = 4 - 3 = 1    방금 확정된 free_1(2) 에서 오늘 가격을 뺀다
  어제 값을 읽으면   free_1(1) = 4            이 입력에서는 두 값이 같아 결과가 안 갈린다
  └ 두 값이 갈리는 것은 날 j 에 t-1 번째 매도가 처음으로 좋아질 때다. 그때 오늘 다시 사는 길이 열린다
```

여기서 본문의 값만으로는 안 나오는 것이 나옵니다. **거래 상한을 아무리 크게 잡아도 `⌊N/2⌋` 를
넘으면 답이 안 커진다**는 것이에요. 이익이 나는 거래를 `r` 개 겹치지 않게 늘어놓으려면 날이 몇
개 필요한지를 세면 나옵니다.

$$b_1 < s_1 < b_2 < s_2 < \cdots < b_r < s_r \quad \Longrightarrow \quad 2r \le N \quad \Longrightarrow \quad r \le \left\lfloor \frac{N}{2} \right\rfloor$$

```text
왜 매수일과 매도일이 전부 다른 날이어도 되는가
  b_u = s_u 인 거래         이익이 0 이라 빼도 답이 안 줄어든다
  s_u = b_{u+1} 인 두 거래  하나로 합치면 이익이 같고 거래 수가 하나 줄어든다
  남는 것                   b_1 < s_1 < b_2 < ... < s_r 꼴이고 날이 2r 개 필요하다
  └ 그래서 답을 만드는 거래 수는 ⌊N/2⌋ 를 넘지 않는다
```

등호가 서는 입력도 있습니다. 가격이 두 값 사이를 번갈아 오가면 `⌊N/2⌋` 번을 다 씁니다.

<!--proof:mathCap-->

```text
 N  ⌊N/2⌋  상한 ⌊N/2⌋-1  상한 ⌊N/2⌋  상한 N  ⌊N/2⌋ 를 다 쓰는가
 4      2        10,000      20,000  20,000  예
 6      3        20,000      30,000  30,000  예
 8      4        30,000      40,000  40,000  예
10      5        40,000      50,000  50,000  예
12      6        50,000      60,000  60,000  예

가격이 0 과 10,000 사이를 번갈아 오가는 입력이다. 넷째 열과 다섯째 열이 같고 셋째 열은 그보다 작다
└ 상한을 ⌊N/2⌋ 보다 크게 잡아도 답이 안 커지고, ⌊N/2⌋ 보다 작게 잡으면 작아진다
```

제약 규모를 넣어 봅시다. `N = 1,000` 이면 유효한 상한이 `⌊N/2⌋ = 500` 이고 제약이 정한 `k` 의
최댓값은 100 이라, 이 문제에서는 상한이 늘 실제로 답을 제한합니다. 그때 표가 하는 일이
`4Nk = 400,000` 이고, 같은 답을 집합 열거로 내면 216 자리 수만큼의 집합을 만들어야 해요.

```ts
// 식을 그대로 옮긴 조각. 날 j 하나를 처리하는 부분이다.
const step = (j: number, t: number, hold: number[], free: number[], P: number[]): void => {
  hold[t] = Math.max(hold[t] as number, (free[t - 1] as number) - (P[j] as number));
  free[t] = Math.max(free[t] as number, (hold[t] as number) + (P[j] as number));
};
```

### 불변식 — free[t] 는 날 j 까지 최대 t 번 거래했을 때의 최대 이익이다

파트 1 에서 코드가 동작하는 것을 여덟 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고 그것이
실제로 유지되는지 확인해 봅시다.

> 날 `j` 를 처리한 직후, 모든 `t` 에 대해 `free[t]` 는 날 `0` 부터 날 `j` 까지만 놓고 거래를
> 최대 `t` 번 했을 때의 최대 이익과 같고, `hold[t]` 는 같은 범위에서 `t` 번째 매수까지 마치고
> 아직 안 판 상태의 최대 이익과 같습니다.

```text
  free[t] 가 뜻하는 것   날 0 부터 날 j 까지, 거래 t 번까지의 최대 이익
  hold[t] 가 뜻하는 것   같은 범위에서 t 번째 매수까지 마친 상태의 최대 이익

  둘 다 「날 j 를 다 처리한 직후」에 참이다   거래 번호를 올리는 도중에는 t 보다 큰 칸이 아직 어제 값이다
```

문장이 둘인 것에 이유가 있습니다. 앞 문장은 다음 날이 이어받을 값을 정하고, 뒤 문장은 **반복이
끝났을 때 `free[k]` 를 그대로 돌려줘도 된다**는 것을 말해요. 둘 중 하나만 빠져도 두 줄이 왜 그
모양인지 근거가 사라집니다.

**출발점부터 봅시다.** 첫날을 읽기 전 `hold` 는 전부 `-∞` 이고 `free` 는 전부 `0` 입니다. 날이
하나도 없으면 어떤 매수도 마칠 수 없어 앞 문장이 참이고, 거래를 하나도 안 한 이익이 `0` 뿐이라
뒤 문장도 참이에요.

| 걸음 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 시작 | `hold` 를 `-∞`, `free` 를 `0` 으로 채운다 | 매수를 마친 상태가 없다 | 이익이 `0` 뿐이다 |
| `j = 0` | 두 줄을 `t = 1..k` 로 실행한다 | 오늘 사는 것 하나가 후보다 | 오늘 사서 오늘 판 `0` 이 후보다 |
| 임의의 `j` | 같은 두 줄을 실행한다 | 어제까지의 값과 오늘 사는 값을 견준다 | 어제까지의 값과 오늘 파는 값을 견준다 |
| 종료 | `j = N−1` 을 마친다 | `hold[t]` 가 전 범위의 값이다 | `free[k]` 가 날 `0` 부터 날 `N−1` 까지 전부 |

셋째 줄이 이 논증의 핵심입니다. 날 `j` 까지만 놓고 본 답은 **오늘 판 것**과 **오늘 안 판 것**
둘로 완전히 갈리고, 그 사이의 다른 경우가 없어요.

| 후보의 모양 | 그 무리의 최댓값 | 근거 |
| --- | --- | --- |
| 마지막 매도가 날 `j` 보다 앞이다 | 어제까지의 `free[t]` | 뒤 문장이 어제 걸음에서 참이었다 |
| 마지막 매도가 바로 날 `j` 다 | `hold[t] + P[j]` | 그런 후보 중 최선은 `t` 번째 매수까지 최선으로 마친 것이다 |
| 둘을 합치면 | 둘 중 큰 값 | 두 무리가 겹치지도 빠지지도 않는다 |

「거래를 `t` 번보다 적게 한다」는 따로 세지 않아도 됩니다 — 시작값이 `0` 이고 갱신이 최댓값이라
첫 무리의 `free[t]` 안에 이미 들어 있어요. 둘째 줄의 `hold[t]` 는 앞 문장에서 옵니다. 앞 문장이
참이라 그 자리에 쓸 수 있는 것이고, 그래서 두 문장이 서로를 떠받쳐요.

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| `k` 가 `0` 이다 | 배열 길이가 1 이라 안쪽 반복이 한 번도 실행되지 않는다 | `free[0] = 0` 이 그대로 답이다 |
| 날이 하나뿐이다 | 바깥 반복이 한 번만 실행된다 | 오늘 사서 오늘 판 `0` 이 답이다 |
| 날이 둘이다 | 바깥 반복이 두 번 실행된다 | `max(0, P[1] − P[0])` 이 된다 |
| 가격이 계속 낮아진다 | 매도 후보가 매번 `0` 이라 최댓값을 못 올린다 | `0` 이 답이다 |
| 가격이 계속 높아진다 | 첫날에 사서 마지막 날에 판다 | `P[N−1] − P[0]` 이 답이다 |
| 가격이 전부 같다 | 매도 후보가 매번 `0` 이다 | `0` 이 답이다 |
| `0` 다음에 `10,000` 이 나온다 | 첫날에 사서 다음 날에 판다 | `10,000` 이 답이다 |

**이제 깨뜨려 봅시다.** 앞 문장을 지키던 줄은 보유 상태의 시작값을 정하는 그 한 줄이에요.
「최댓값을 구하는 것이니 시작값을 `0` 으로 두면 되지 않나」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
const hold = new Array<number>(k + 1).fill(0);   // -∞ 가 아니라 0 에서 시작했다
const free = new Array<number>(k + 1).fill(0);
```

실행하면 이렇게 나옵니다.

<!--proof:mutantHoldFromZero-->

```text
입력                         정본이 낸 답  보유 시작값을 0 으로 둔 답  판정
전개 입력 k=2 [2 6 3 9 5 7]            10                          12  틀리다
k=1 [2 6 3 9 5 7]                       7                           9  틀리다
k=2 [1 5 3 6]                           7                           8  틀리다
k=1 [7 6 5]                             0                           7  틀리다
k=2 [5 4 3 2 1]                         0                           5  틀리다

└ 첫날 hold[1] 이 0 이면 free[1] 이 0 + 2 = 2 로 커진다. 사지 않은 주식을 판 이익이라 전개 입력의 답이 12 로 커진다
```

앞 문장이 깨지면 `hold[t]` 의 뜻이 바뀌고, 그러면 뒤 문장의 근거도 함께 사라집니다. 시작값 `0`
은 「사지 않고도 `t` 번째 매수를 마친 상태에 있다」를 뜻하게 되고, 그 상태로 오늘 팔면 가격이
그대로 이익이 돼요.

```text
전개 입력에서 두 값이 갈리는 자리
  정본의 free[1]      날 0 에서 0          아직 아무 이익도 없다
  변이의 free[1]      날 0 에서 2          사지 않은 주식을 2 에 판 값이다
  변이가 내는 답      12                   사지 않고 판 이익이 후보로 들어간 결과다
  └ 시작값이 「도달할 수 없다」를 뜻하지 않으면 매수를 건너뛴 경로가 후보로 들어온다
```

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 무리입니다 — 배열 둘을 시작값으로 채우는 것, 날마다 거래 번호를
올리며 두 줄을 실행하는 것, 답을 돌려주는 것이에요. 전개의 걸음으로 확인하면 이렇게 나뉩니다.

<!--proof:perfCount-->

```text
무리    어느 걸음인가    걸음 수  걸음마다 덧셈·뺄셈  걸음마다 비교  이 입력에서
초기화  T1                     1                   0              0            0
순회    T2 부터 T7 까지        6                   4              4           48
반환    T8                     1                   0              0            0
합계                                                                          48

└ 덧셈·뺄셈 24 번과 비교 24 번이고, 둘 다 날 수 6 과 거래 상한 2 에서만 나온 수다
```

T1 과 T8 은 값을 옮기기만 하는 자리라 덧셈·뺄셈도 비교도 없습니다. 그래서 이 입력의 기본 연산이
48 번이에요.

```text
총식 = 초기화 + 순회 + 반환

  초기화             0
  순회               4Nk
  반환               0
  기본 연산          4Nk
  N = 6, k = 2 이면  48 로 위 표와 같다
  읽는 칸            N 번 (날마다 P[j] 를 한 번씩)
  잡는 칸            2(k + 1) 개
```

**연산 수가 입력의 내용과 무관하게 정해집니다.** 가격이 오르든 내리든, 답이 앞에서 만들어지든
뒤에서 만들어지든 걸음 수가 같아요 — (날, 거래 번호) 하나에 하는 일이 덧셈·뺄셈 둘과 비교 둘로
고정이기 때문입니다.

```text
여기서 센 것은 덧셈·뺄셈과 비교 전부다
  추가로 잡는 메모리   배열 칸 2(k + 1) 개
  안 센 것             배열 읽기 N 번과 두 반복의 변수 증가 N + Nk 번
                       둘 다 N 과 Nk 에 비례하므로 총식의 차수는 그대로다
                       └ 날마다의 표를 다 남기는 방식이면 여기에 칸 2N(k + 1) 개가 더 붙는다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`k` 가 `0` 이다) | `O(N(k+1))` | `Θ(N)` — 안쪽 반복이 한 번도 실행되지 않는다 |
| **평균적인 경우** (가격 분포와 무관하다) | `O(N(k+1))` | `Θ(N(k+1))` |
| **최악의 경우** (`N` 과 `k` 가 제약 최댓값이다) | `O(N(k+1))` | `Θ(N(k+1))` — 실제로 도달한다 |

가운데와 아래 줄이 같은 것이 이 절차의 성질입니다. 걸음 수가 `N` 과 `k` 둘로만 정해져서 가격을
어떻게 바꿔도 연산 수가 같아요.

```text
상한과 타이트한 값을 가르는 자리
  O(N(k+1))   이 절차의 연산 수가 그보다 크지 않다는 것만 말한다      상한이다
  Θ(N(k+1))   위아래로 같은 차수라 실제로 그만큼 든다는 것도 말한다   타이트한 값이다
  └ 이 절차는 (날, 거래 번호) 하나마다 반드시 네 번의 기본 연산을 하므로 Θ 로 적을 수 있다
```

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리가 하나도 없다는 것이 이 절차의
특징이에요 — 정렬도, 접두사 배열도, 하루치 차이 배열도 따로 만들지 않습니다.

```text
총식 = Θ(N(k+1)) 시간 + Θ(k+1) 추가 메모리

  시간     덧셈·뺄셈 2Nk · 비교 2Nk · 읽기 N · 배열 채우기 2(k+1)
  메모리   배열 칸 2(k+1) 개

N = 1,000, k = 100 이면 기본 연산이 정확히 400,000 번, 잡는 칸이 202 개다
```

**보장의 종류는 전부 최악 보장입니다.** 해시도, 무작위성도, 분할 상환도 쓰지 않아요 — 어떤
입력을 넣어도 기본 연산 수가 `4Nk` 로 같습니다.

```text
기댓값이 끼어들 자리가 없다
  칸을 찾는 방법     칸 번호로 바로 간다         해시 충돌이라는 개념이 없다
  걸음 수            가격을 안 보고 정해진다     분포를 가정할 필요가 없다
  칸 하나의 비용     항상 덧셈·뺄셈 2 와 비교 2  평균이 아니라 상수다
  └ 최악 보장과 평균 비용이 같은 수다
```

#### 최악을 만드는 입력

연산 수를 최대로 만드는 방법은 하나뿐입니다 — **`N` 과 `k` 를 제약의 최댓값으로 두는 것**이에요.
가격의 모양은 연산 수를 바꾸지 못합니다. 그것을 값으로 확인해 봅시다.

<!--proof:worstShape-->

```text
입력의 모양 (N = 1,000 · k = 100)  덧셈·뺄셈     비교  기본 연산  값이 바뀐 자리         답
가격이 하루도 안 바뀐다              200,000  200,000    400,000             100          0
가격이 날마다 1 씩 내려간다          200,000  200,000    400,000         100,000          0
가격이 날마다 1 씩 올라간다          200,000  200,000    400,000         100,000        999
0 과 10,000 이 번갈아 나온다         200,000  200,000    400,000          10,100  1,000,000

가운데 세 열이 네 줄 다 같고 오른쪽 두 열만 다르다. 갱신 자리는 네 줄 다 2Nk = 200,000 개다
답이 가장 커지는 입력은 마지막 줄이고, 그때 답은 k × 10,000 = 1,000,000 이다
└ 기본 연산은 N 과 k 만 보고, 값이 바뀐 자리와 답은 가격의 모양을 본다
```

**「값이 자주 바뀌면 느리다」는 이 절차에서 성립하지 않습니다.** 물려받은 통념이 여기서는 맞지
않아요 — 둘째 줄은 갱신 자리 200,000 개 중 100,000 개에서 값이 실제로 바뀌고 첫째 줄은 100
개뿐인데, 기본 연산은 둘 다 400,000 입니다. `Math.max` 가 어느 쪽을 고르든 비교가 한 번이기
때문이에요.

```text
최악은 축마다 다른 입력이 만든다
  연산 수의 최악   N = 1,000 · k = 100    가격의 모양과 무관하다. 400,000 번
  잡는 칸의 최악   k = 100                가격과 무관하다. 202 개
  답 크기의 최악   0 과 10,000 이 번갈아  답이 1,000,000 이 된다
  └ 앞의 둘은 N 과 k 만 보고, 셋째는 가격의 범위와 min(k, ⌊N/2⌋) 을 함께 본다
```

**답 크기의 최악에는 `k` 와 `N` 이 둘 다 들어갑니다.** 거래 하나가 낼 수 있는 이익이 최대
`10,000` 이고 답을 만드는 거래 수가 `min(k, ⌊N/2⌋)` 을 넘지 못하므로, 그 둘의 곱이 답의 상한이
에요.

| 최악으로 만들 축 | 입력 | 값 |
| --- | --- | --- |
| 연산 수 | `N = 1,000` · `k = 100`, 가격은 무엇이든 | 400,000 |
| 잡는 칸 | `k = 100`, 가격은 무엇이든 | 202 |
| 답의 크기 | `N = 1,000` · `k = 100`, `0` 과 `10,000` 이 번갈아 나온다 | 1,000,000 |

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 「몇 번째 거래인가」와 「지금 들고 있는가」를
상태의 축으로 세워 후보를 상태 `2k + 1` 개로 줄였고, 날 하나를 읽을 때마다 그 상태들을 한 번씩
갱신하며, 답은 마지막 칸인 `free[k]` 입니다.

```text
1.   상태를 (거래 번호, 보유 여부) 로 둔다   후보가 2k + 1 개로 줄어든다
2.   날마다 상태를 한 번씩 갱신한다          매수는 뺄셈, 매도는 덧셈
3.   마지막 칸 free[k] 가 답이다             칸 번호를 따라 안 줄어들기 때문이다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T4 는 `P[2] = 3` 을 처리한 걸음이었고, `hold[2]` 가 `-2`
에서 `1` 로 올라갔어요. 그런데 이 걸음에서 `free[2]` 는 4 그대로였습니다. `hold[2]` 가 3 만큼
올라갔는데 `free[2]` 가 안 따라 올라간 이유가 무엇일까요?

```text
T4   P[2] = 3   hold[2] = max(-2, 4 - 3) = 1   free[2] = max(4, 1 + 3) = 4
```

<!--check:whyFreeStays-->
**같은 날에 사고 같은 날에 판 것이라 이익이 앞 거래의 이익 그대로이기 때문**입니다. `hold[2]`
가 `free[1] - P[2]` 로 올라갔으니 거기에 `P[2]` 를 다시 더하면 `free[1]` 이 되고, 그 값은 이미
`free[2]` 안에 들어 있어요.

```text
hold[2] 가 오늘 올라간 값으로 오늘 팔면
  hold[2] 의 새 값   free[1] - P[2] = 4 - 3 = 1
  오늘 파는 후보     (free[1] - P[2]) + P[2] = free[1] = 4
  free[2] 의 옛 값   4                                   이미 같은 값이다
  └ 오늘 사서 오늘 판 거래는 이익이 0 이라 답을 못 올린다
```

`free[2]` 가 커지려면 `hold[2]` 가 **어제까지** 올라가 있어야 하고 오늘 가격이 그때보다 높아야
합니다. T5 가 그 자리예요 — T4 가 만든 `hold[2] = 1` 에 T5 의 가격 9 를 더해 10 이 됩니다.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 번 문제   「수식 정의와 유도」
  2 번 문제   「알아 두면 좋은 개념」
  3 번 문제   「경쟁 설계와의 대조」
```

- 답을 만든 거래의 매수일과 매도일까지 함께 돌려주려면 무엇을 더 들고 가야 할까요? 전개 입력에서
  답의 네 날이 날 0 · 날 1 · 날 2 · 날 3 인 것을, 값 몇 개를 더 두면 알아낼 수 있는지 적어
  보세요. 상태마다 「그 값이 어느 날에 정해졌는가」를 함께 적어 두는 것이 실마리입니다.
- 문제가 「거래마다 수수료 `f` 를 뗀다」로 바뀌면 코드의 어느 줄을 어떻게 고쳐야 할까요? T5 에서
  `free[2]` 가 10 이 된 자리를 `f = 1` 로 다시 계산해 보고, 그때 답이 몇이 되는지 손으로 채워
  보세요.
- 거래 상한 `k` 를 고정하고 날 수 `N` 만 늘리면 두 설계의 연산 수가 각각 어떻게 되나요? 표 쪽과
  벌금 쪽의 식을 `N` 과 `k` 로 세우고, 뒤집히는 자리가 `N` 에 따라 어떻게 움직이는지 따져 보세요.
