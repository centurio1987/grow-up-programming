# sparseTableRangeMin — 겹치는 두 조각으로 덮어도 최솟값이 안 바뀌는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 질의마다 구간을 차례로
읽는 방법에서 미리 적어 둔 두 칸을 견주는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

배열이 질의 도중에 **한 번도 바뀌지 않는다면**, 구간의 최솟값을 미리 적어 둘 수 있어요.
다만 구간의 짝이 너무 많아서 전부 적을 수는 없습니다. 그래서 **칸 수가 2 의 거듭제곱인
구간만** 적어 둡니다. 칸 수가 `2^k` 인 구간을 담은 줄을 **`k` 층**이라고 부를게요.

```text
인덱스        0  1  2  3  4  5
A 의 값       5  2  7  4  6  3

0 층          5  2  7  4  6  3    칸 하나가 1 칸을 덮는다 · 칸 6 개
1 층          2  2  4  4  3       칸 하나가 2 칸을 덮는다 · 칸 5 개
2 층          2  2  3             칸 하나가 4 칸을 덮는다 · 칸 3 개
```

이 표로 아무 구간이나 답할 수 있을까요? 칸 수가 6 인 구간 `[0,5]` 에는 딱 맞는 조각이
없습니다. 6 은 2 의 거듭제곱이 아니니까요. 그래서 **4 칸짜리 조각 둘**을 씁니다 — 하나는
왼쪽 끝에서 시작하고 하나는 오른쪽 끝에서 끝나게 놓아요. 구간의 모든 칸이 두 조각 중 적어도
한쪽에 들어 있는 것을 **덮는다**고 적을게요.

```text
인덱스        0  1  2  3  4  5
A 의 값       5  2  7  4  6  3

왼쪽 조각   └───4 칸───┘          2 층의 칸 0, 값 2
오른쪽 조각       └───4 칸───┘    2 층의 칸 2, 값 3
                  └ 겹친 칸 2 개. 답은 2 다
```

가운데 두 칸이 두 조각에 함께 들어 있습니다. **최솟값에서는 그것이 문제가 되지 않아요** —
같은 값을 두 번 넣어도 최솟값은 그대로이기 때문입니다. `min(2, 2) = 2` 이고 `min(3, 3) = 3`
이에요. 이 성질을 **멱등**이라고 부릅니다.

```text
최솟값   min(x, x) = x        같은 값을 두 번 넣어도 그대로다      겹쳐도 된다
합       x + x = 2x           같은 값을 두 번 넣으면 두 배가 된다  겹치면 안 된다
                              └ 겹쳐 덮기가 되는 연산과 안 되는 연산이 여기서 갈린다
```

그래서 절차가 둘로 끝납니다. 표를 한 번 쌓고, 질의마다 그 표에서 **칸 두 개를 읽어 견주는**
것이에요. 표를 쌓는 데 `O(n log n)`, 질의 하나에 `O(1)` 입니다.

```text
전처리  아래층 두 칸을 견줘 위층 한 칸을 정한다      칸 수 n log n 규모
질의    두 조각을 읽어 더 작은 쪽을 답한다           구간의 칸 수와 무관하게 견주기 1 번
        └ n 칸짜리 배열과 q 개짜리 질의에서 O(n log n + q) 다
```

조건 하나가 여기 붙습니다. **원소 하나가 바뀌면 그 원소를 덮는 칸이 층마다 흩어져 있어요.**
0 층에서는 한 칸, 1 층에서는 두 칸, 2 층에서는 네 칸이 그 원소를 덮으므로, 고쳐야 할 자리가
층을 올라갈수록 늘어납니다.

```text
A[2] 를 7 에서 1 로 고쳤다면

  옛 표   0 층  5  2  7  4  6  3      1 층  2  2  4  4  3      2 층  2  2  3
  새 표   0 층  5  2  1  4  6  3      1 층  2  1  1  4  3      2 층  1  1  1
                      └ 한 칸을 고쳤는데 위 두 층이 다섯 칸 달라진다
```

그래서 이 절차는 **표를 고치는 코드를 아예 갖지 않습니다.** 문제가 「배열은 질의 중
변경되지 않는다」고 못 박았기 때문에 그 코드가 필요 없는 것이고, 그 문장이 빠지면 이 절차는
쓸 수 없어요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **구간 최솟값**이 무엇인지. 인덱스 `l` 부터 `r` 까지의 값 중 가장 작은 수예요. 건너뛰지
  않고 그 사이를 전부 봅니다.
- **2 의 거듭제곱**과 **밑이 2 인 로그의 내림**. `⌊log₂ 6⌋ = 2` 는 「6 이하인 2 의 거듭제곱
  중 가장 큰 것이 `2² = 4`」라는 뜻입니다.
- **정적**이라는 말의 뜻. 여기서는 「질의를 처리하는 동안 원소가 바뀌지 않는다」는 뜻이고,
  배열의 크기가 고정이라는 뜻이 아닙니다.
- **비트 시프트** `x >> 1`(2 로 나눈 몫)과 `1 << k`(`2^k`). 코드가 이 둘을 씁니다.
- **미리 계산해 두고 질의에 답하는 방식**이 왜 값을 하는지. 흐릿하면
  [`prefixSumRangeQuery`](../prefixSumRangeQuery/prefixSumRangeQuery-problem.md) 를 먼저 봅니다.

```text
[5 2 7 4 6 3] 에서
  구간 [2,5] 의 최솟값을 답하라      3       ← 이 글이 하는 것. 구간은 문제가 준다
  값이 3 인 자리를 찾아라            5       ← 찾아야 할 것이 자리다. 다른 문제다
  원소 하나를 고치고 다시 물어라     —       ← 배열이 바뀐다. 이 글의 조건 밖이다
```

마지막 줄이 이 글의 경계입니다. 갱신이 섞이는 문제는
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 쪽이에요.

### 아이디어 상세 — 겹치는 두 조각으로 덮기를 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function sparseTableRangeMin(
  A: number[],
  queries: Array<[number, number]>,
): number[];
```

- 입력: 정수 배열 `A` 와 질의 목록 `queries`. 질의 `[l, r]` 은 **양끝을 포함하는** 인덱스
  구간이고, 이 배열은 질의를 다 처리할 때까지 그대로입니다.
- 출력: 각 질의의 구간 최솟값을 **입력 순서 그대로** 담은 배열. 질의가 없으면 빈 배열.
- 제약: `1 ≤ n ≤ 100,000`, `0 ≤ q ≤ 100,000`, `−10^9 ≤ A[i] ≤ 10^9`, `0 ≤ l ≤ r ≤ n−1`.
  배열은 질의 중 바뀌지 않습니다. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 여섯이에요. 여기서 못 박고 뒤에서 바꾸지 않습니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 배열 `A` 의 길이 | `n ≤ 100,000` |
| `q` | 질의의 개수 | `q ≤ 100,000` |
| `A[i]` | 배열의 `i` 번째 값. 표를 다 쌓은 뒤에도 그대로입니다 | `−10^9` 이상 `10^9` 이하 |
| `l` · `r` | 질의 구간의 왼쪽 끝 · 오른쪽 끝. 양끝을 포함합니다 | `0 ≤ l ≤ r ≤ n−1` |
| `k` | 층 번호. 층 `k` 의 칸 하나가 덮는 **칸 수**가 `2^k` 입니다 | `0 ≤ k ≤ ⌊log₂ n⌋` |
| `st[k][i]` | 층 `k` 의 칸 `i`. **인덱스 구간 `[i, i+2^k−1]`** 의 최솟값입니다 | 층마다 칸이 `n − 2^k + 1` 개 |

`st[k][i]` 의 두 첨자를 헷갈리지 않게 한 번 더 못 박을게요. **앞 첨자 `k` 가 「몇 칸을
덮는가」이고 뒤 첨자 `i` 가 「어디서 시작하는가」입니다.** 그 칸이 덮는 구간의 왼쪽 끝은
`i`, 오른쪽 끝은 `i + 2^k − 1` 이에요.

```text
st[2][1] 은
  덮는 칸 수    2^2 = 4 칸
  왼쪽 끝       i = 1
  오른쪽 끝     1 + 4 − 1 = 4
                └ 인덱스 구간 [1,4] 의 최솟값, 곧 min(2, 7, 4, 6) = 2 다
```

가장 먼저 떠오르는 방법으로 시작합시다. 질의가 오면 그 구간을 왼쪽부터 오른쪽까지 차례로
읽으며 가장 작은 값을 기억하는 것이에요.

```ts
const answers = queries.map(([l, r]) => {
  let best = A[l] as number;
  for (let i = l + 1; i <= r; i++) best = Math.min(best, A[i] as number);
  return best;
});
```

이 방법의 비용은 **질의 하나가 하는 견주기 수의 합**입니다. 모든 질의가 배열 전체를 묻는
입력을 넣으면 질의마다 `n−1` 번을 견줘요.

<!--proof:cost-scan-->

```text
  n = q     견주기(실측)         q(n−1)  초당 1억 번 기준
      6               30             30      0.01 초 미만
    100            9,900          9,900      0.01 초 미만
  1,000          999,000        999,000      0.01 초 미만
100,000  (실행하지 않음)  9,999,900,000         100.00 초

└ 모든 질의가 배열 전체를 묻는 입력이다. 제약 규모에서 1 초 제한을 크게 넘는다
```

100 억 번입니다. 단순 연산을 초당 1 억 번으로 잡아도 100 초가 걸려요. 제약이 10 만인데 이
방법으로는 1 초 안에 못 끝냅니다.

```text
목표는 이것이다
  지금       질의 하나가 구간의 칸 수만큼 견준다  전부 합치면 q(n−1) 번
  가려는 곳  질의 하나가 정해진 횟수만 견준다     구간의 칸 수와 무관하다
             └ 질의 하나의 비용을 구간의 칸 수에서 떼어 놓는 것이 목표다
```

**구간 합이라면 여기서 답이 나옵니다.** 왼쪽 끝을 0 으로 고정한 합을 미리 적어 두고 두 칸을
빼면 되니까요. 최솟값에도 같은 수를 써 보면 어떨까요. `m[i]` 를 `A[0]` 부터 `A[i]` 까지의
최솟값이라고 두고, `[2,5]` 의 답을 `m[5]` 와 `m[1]` 로 만들어 보는 것입니다.

<!--proof:prefix-min-fails-->

```text
배열           접두 최솟값 m  m[1]  m[5]  [2,5] 의 답
[5 2 7 4 6 3]  [5 2 2 2 2 2]     2     2            3
[5 2 7 4 6 9]  [5 2 2 2 2 2]     2     2            4

└ 두 배열이 접두 최솟값 표에서 같은 값을 갖는데 답은 3 과 4 로 다르다
```

두 배열이 `m[1]` 에서도 `m[5]` 에서도 같은 값 2 를 갖는데 답은 3 과 4 로 다릅니다. **같은
입력 두 개가 같은 두 칸을 내는데 답이 다르다면, 그 두 칸으로는 답이 정해지지 않아요.**
덧셈에는 뺄셈이 있어서 앞부분을 덜어 낼 수 있는데, 최솟값에는 「덜어 내기」가 없습니다.

```text
덧셈    3 + 5 = 8      8 에서 3 을 빼면 5 가 남는다        앞부분을 덜어 낼 수 있다
최솟값  min(3, 5) = 3  3 에서 3 을 덜어 내면?              5 를 되찾을 방법이 없다
                       └ 그래서 왼쪽 끝을 0 으로 고정한 표 하나로는 안 된다
```

그러면 **왼쪽 끝을 고정하지 않은 조각**을 저장해야 합니다. 어떤 조각을 몇 개나 저장할지가
남은 질문이에요. 먼저 같은 입력에 두 방식을 걸어 견주기 수를 세어 봅시다. 방식 A 는 질의마다
구간을 차례로 읽는 것이고, 방식 B 는 칸 수가 2 의 거듭제곱인 조각을 미리 저장하는 것입니다.

<!--proof:cost-two-ways-->

```text
질의   구간의 칸 수  차례로 읽기  층으로 쌓은 표
[0,4]             5            4               1
[1,2]             2            1               1
[3,3]             1            0               1
[0,5]             6            5               1
[2,5]             4            3               1

방식    무엇을 하는가                        견주기
방식 A  질의마다 구간을 차례로 읽는다        전처리 0 번 · 질의 13 번
방식 B  칸 수 2^k 짜리 조각을 미리 저장한다  전처리 8 번 · 질의 5 번

└ 답은 [2 2 4 2 3] 로 같고, 오른쪽 열이 전부 1 이다
```

13 대 13 입니다. 여섯 칸에서는 총합이 같아요 — 여기서 볼 것은 총합이 아니라 **오른쪽 열이
전부 1** 이라는 것 하나입니다. 방식 B 에서 질의 하나의 견주기가 구간의 칸 수와 아무 상관이
없어요.

```text
구간의 칸 수       5   2   1   6   4    질의 다섯의 칸 수가 제각각이다
방식 A 의 견주기   4   1   0   5   3    칸 수를 그대로 따라간다
방식 B 의 견주기   1   1   1   1   1    칸 수를 안 본다
                  └ 질의가 열 배로 늘어도 아래 줄은 1 그대로다
```

그러면 어떤 조각을 저장해야 할까요. 가장 욕심 없는 후보부터 시험합시다 — 「올 수 있는 질의가
유한하니 답을 전부 미리 계산해 두면 되지 않나」입니다. 그러면 어떤 질의가 와도 표를 한 번
읽고 끝나요.

<!--proof:cost-precompute-all-->

```text
      n  모든 짝을 담는 표  층으로 쌓은 표
      6                 21              14
    100              5,050             580
  1,000            500,500           8,987
100,000      5,000,050,000       1,568,946

└ 왼쪽은 n 이 열 배가 되면 백 배가 되고, 오른쪽은 열 배를 조금 넘는다
```

`n = 100,000` 이면 칸이 50 억 개입니다. 정수 하나를 8 바이트로 잡아도 40 GB 라 256 MB 제한에
들어가지 않아요. **왼쪽 끝과 오른쪽 끝을 둘 다 자유롭게 두면 짝의 수가 `n²` 규모**가 되는
것이 원인이라, 저장할 조각을 골라내야 합니다.

```text
끝 둘을 다 자유롭게 두면          담을 짝이 n(n+1)/2 개다
칸 수를 2 의 거듭제곱으로만 두면  담을 줄이 ⌊log₂ n⌋ + 1 개로 준다
                                  └ 남은 질문은 「골라내고도 답이 나오는가」다
```

여기서 진짜 개념이 나옵니다. **칸 수가 `2^k` 인 구간의 최솟값만 저장하고, 임의의 구간은 그런
조각 둘로 덮는 것**이에요. `k` 를 「구간의 칸 수 이하인 2 의 거듭제곱 중 가장 큰 것」의 지수로
고르면, 조각 하나는 구간을 넘지 않고 조각 둘이면 구간을 다 덮습니다.

```text
질의 [l,r] 의 칸 수를 len 이라 하면
  k          2^k ≤ len 인 가장 큰 k             len = 6 이면 k = 2
  왼쪽 조각  [l, l+2^k−1]                       [0,3]
  오른쪽 조각 [r−2^k+1, r]                      [2,5]
             └ 둘 다 구간 안에 있고, 둘을 합치면 구간 전체가 된다
```

이 정의를 실제 입력의 세 질의에 걸음마다 적용해 봅시다. 칸 수가 2 의 거듭제곱이 아닌 것과
맞는 것을 함께 보면 겹침이 어떻게 생기는지 확인됩니다.

```text
인덱스        0  1  2  3  4  5
A 의 값       5  2  7  4  6  3

왼쪽 조각   └───4 칸───┘          2 층의 칸 0, 값 2
오른쪽 조각       └───4 칸───┘    2 층의 칸 2, 값 3
                  └ 겹친 칸 2 개. 답은 2 다
```

칸 수가 5 인 `[0,4]` 도 같은 `k = 2` 를 쓰는데, 구간이 한 칸 짧아진 만큼 겹친 칸이 한 칸
늘어납니다.

```text
인덱스        0  1  2  3  4  5
A 의 값       5  2  7  4  6  3

왼쪽 조각   └───4 칸───┘          2 층의 칸 0, 값 2
오른쪽 조각    └───4 칸───┘       2 층의 칸 1, 값 2
               └ 겹친 칸 3 개. 답은 2 다
```

칸 수가 4 인 `[2,5]` 는 조각 하나로 딱 맞습니다. 그때 두 조각은 **같은 칸**을 가리켜요.

```text
인덱스        0  1  2  3  4  5
A 의 값       5  2  7  4  6  3

왼쪽 조각         └───4 칸───┘    2 층의 칸 2, 값 3
오른쪽 조각       └───4 칸───┘    2 층의 칸 2, 값 3
                  └ 겹친 칸 4 개. 답은 3 다
```

셋 다 겹친 칸이 하나 이상입니다. 겹치지 않는 경우가 없다는 것이 뒤에서 값을 하니 기억해
두세요. 이제 표를 **어떻게 채우는지**를 정합니다. 위층 칸 하나는 아래층 칸 둘을 견주면
나와요 — 칸 수 `2^k` 짜리 구간은 칸 수 `2^(k−1)` 짜리 구간 둘로 정확히 갈리기 때문입니다.

```text
2 층의 칸 1 을 만든다
  덮을 구간     [1,4], 칸 4 개
  왼쪽 절반     [1,2] = 1 층의 칸 1, 값 2
  오른쪽 절반   [3,4] = 1 층의 칸 3, 값 4
  min(2, 4)     2
                └ 여기서는 두 절반이 안 겹친다. 표를 채울 때는 정확히 반씩 가른다
```

각 상태의 크기도 여기서 정해집니다. 층은 `⌊log₂ n⌋ + 1` 개이고, 층 `k` 의 칸은 `n − 2^k + 1`
개예요 — 오른쪽 끝이 배열을 넘어가는 자리는 만들 수 없으니까요.

```text
층 수        ⌊log₂ n⌋ + 1 개    n=6 이면 3 개
층 k 의 칸   n − 2^k + 1 개     2 층이면 6 − 4 + 1 = 3 개
읽는 조각    질의마다 2 개      구간의 칸 수가 1 이든 n 이든 2 개다
```

마지막으로 **왜 하필 2 의 거듭제곱인지**를 값으로 확인합니다. 저장하는 칸 수를 밑 `b` 의
거듭제곱으로 두면(층 `k` 가 `b^k` 칸을 덮게 하면), 질의는 조각 `⌈len / b^k⌉` 개로 덮여요.
밑을 넷으로 두고 같은 질의 목록에서 세었습니다.

<!--proof:cost-base-->

```text
n = 6 · 질의 다섯 개
밑   층 수  표 칸 수  표 만들기 견주기  질의당 조각 수
b=2      3        14                 8               2
b=3      2        10                 8               2
b=4      2         9                 9               2
b=6      2         7                 5               5

n = 1,000 · 질의 1,000 개
밑   층 수  표 칸 수  표 만들기 견주기  질의당 조각 수
b=2     10     8,987             7,987               2
b=3      7     5,914             9,828               3
b=4      5     4,664            10,992               4
b=6      4     3,745            13,725               6

└ 밑을 키우면 표 칸이 줄고 표 만들기 견주기와 조각 수가 는다. 답은 넷 다 같다
```

**「중간 어딘가가 낫다」가 아니라 한쪽 끝이 답입니다.** `n = 1,000` 에서 `b = 2` 는 표 칸이
8,987 로 가장 많은 대신 표 만들기 견주기가 7,987 로 가장 적고 질의당 조각도 2 로 가장
적어요. 표 칸을 3,745 까지 줄이려면 견주기를 13,725 로 늘리고 질의마다 조각 6 개를 읽어야
합니다.

```text
이 문제에서 표 칸을 아낄 이유가 있는가
  메모리 제한   256 MB
  b=2 의 표     n = 100,000 에서 1,568,946 칸 · 8 바이트면 11.97 MiB
                └ 제한의 5 % 도 안 쓴다. 그래서 표 칸을 내주고 견주기를 사는 b=2 가 답이다
```

얻은 절차는 한 벌입니다.

```text
1. 칸 수마다 층 번호를 미리 적어 둔다
2. 0 층에 배열을 그대로 옮긴다
3. 층을 올리며 아래층 두 칸을 견줘 위층 한 칸을 채운다
4. 질의 [l,r] 이 오면 층 k 를 고르고 칸 l 과 칸 r−2^k+1 을 견준다
     └ 10 만 칸 · 10 만 질의에서 100 억 번이던 견주기가 156 만 번이 된다
```

### 수행으로 알아보는 알고리즘 — 표 세 층을 쌓고 다섯 질의를 답한다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const A = [5, 2, 7, 4, 6, 3];
const queries: Array<[number, number]> = [[0, 4], [1, 2], [3, 3], [0, 5], [2, 5]];
// 이 절이 끝나면 [2, 2, 4, 2, 3] 이 나와야 한다
```

왜 하필 이 다섯 질의일까요? `[0,4]` 와 `[0,5]` 는 칸 수가 2 의 거듭제곱이 아니라 **두 조각이
서로 다른 칸**을 가리키고, `[1,2]` 와 `[2,5]` 는 거듭제곱이라 **두 조각이 같은 칸**을
가리켜요. `[3,3]` 은 한 칸짜리라 0 층을 씁니다. 이 절차가 답하는 구간의 모양이 다 나와요.

```text
절차 전체를 한 장으로

    칸 수 m 마다 층 번호를 적어 둔다 (m = 2 … n)
    0 층에 배열을 그대로 옮긴다
    층 k 를 1 부터 ⌊log₂ n⌋ 까지 올리며:
        칸 i 마다 아래층의 칸 i 와 칸 i+2^(k−1) 을 견줘 적는다      ① 표 쌓기
    질의 [l,r] 을 순서대로 받으며:
        층 번호 표에서 k 를 읽고
        층 k 의 칸 l 과 칸 r−2^k+1 을 견줘 답한다                   ② 질의
```

#### 1. 구간의 칸 수에서 층 번호를 정수 연산으로 구한다

질의마다 `⌊log₂ len⌋` 을 계산하는 대신, 칸 수마다 답을 미리 적어 둡니다. 칸 수를 `m` 이라
적을게요. `m` 의 층 번호는 **`m` 의 절반 자리의 층 번호에 1 을 더한 것**이에요 — 칸 수가
두 배가 될 때마다 지수가 하나 오르니까요.

```ts
const logTable = new Array<number>(n + 1).fill(0);
for (let m = 2; m <= n; m++) {
  logTable[m] = (logTable[m >> 1] as number) + 1;
}
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

```text
칸 수 m       0  1  2  3  4  5  6
logTable[m]   0  0  1  1  2  2  2
                    └ m=2 는 logTable[1]+1 = 1 · m=4 는 logTable[2]+1 = 2 다
                      m=0 과 m=1 은 채우지 않고 0 으로 둔 초깃값이다
```

여기서 가장 중요한 것은 `m >> 1` 입니다. 절반 자리를 읽기 때문에 표가 **이미 정해진 자리만**
참조해요. 오른쪽으로 한 칸 시프트하는 것이 2 로 나눈 몫이고, 그 몫은 언제나 `m` 보다 작아서
아직 안 채운 칸을 읽는 일이 없습니다.

#### 짚고 가기 — 층 번호를 `Math.log2` 로 구하면 어긋나는가

여기서 헷갈리기 쉬운 포인트는 「굳이 표를 만들 것 없이 `Math.floor(Math.log2(m))` 을 쓰면
되지 않나」입니다. 그리고 그 반대편에 「부동소수라 2 의 거듭제곱 경계에서 한 칸 어긋난다」는
말도 같이 붙어 다녀요. 둘 중 어느 쪽이 맞는지 실행으로 봅시다.

<!--proof:pause-log-float-->

```text
칸 수 m  정수 표 k  log2 를 내림     2^k  2^(k+1)  판정
      1          0             0       1        2  같다
      2          1             1       2        4  같다
      3          1             1       2        4  같다
      4          2             2       4        8  같다
      7          2             2       4        8  같다
      8          3             3       8       16  같다
  1,023          9             9     512    1,024  같다
  1,024         10            10   1,024    2,048  같다
 65,535         15            15  32,768   65,536  같다
 65,536         16            16  65,536  131,072  같다
100,000         16            16  65,536  131,072  같다

└ m 을 1 부터 100,000 까지 전수로 대조했다 — 두 방식이 어긋난 자리 0 개 · 2^k ≤ m < 2^(k+1) 이 깨진 자리 0 개
```

**어긋나는 `m` 이 이 제약 안에는 없습니다.** 오른쪽 두 열이 그 근거예요 — 정수 표가 낸 `k`
가 `2^k ≤ m < 2^(k+1)` 을 10 만 자리 전부에서 만족합니다. 그러니 「경계에서 틀린다」는 말은
이 문제의 범위에서는 거짓이에요.

```text
그래도 표를 두는 이유
  질의 하나의 연산   Math.log2 는 부동소수 로그 1 번 + 내림 1 번
                     정수 표는 배열 읽기 1 번
  값의 성질          정수 표는 정수 연산만 쓴다. 어긋날 여지 자체가 없다
                     └ 「이 범위에서는 안 틀린다」와 「틀릴 수 없다」는 다른 보장이다
```

한 줄로 정리하면, `Math.log2` 를 써도 이 문제는 통과합니다. 표를 두는 것은 틀림을 막으려는
것이 아니라 **질의당 연산을 배열 읽기 하나로 줄이고 보장의 종류를 바꾸려는 것**이에요.

#### 2. 0 층에 배열을 그대로 옮긴다

0 층의 칸 하나는 `2^0 = 1` 칸을 덮습니다. 한 칸짜리 구간의 최솟값은 그 값 자체라, 배열을
그대로 복사하면 끝이에요.

```ts
const st: number[][] = [A.slice()];
```

`T2` 에서 이 조각만 실행하면 층이 하나 생깁니다.

```text
st[0]      5  2  7  4  6  3      A 와 같다
칸 수      6 개                  n − 2^0 + 1 = 6
                                 └ 여기서부터 위로 쌓는다
```

`A.slice()` 로 **복사본**을 두는 것이 중요합니다. `A` 를 그대로 넣으면 표가 입력 배열과 같은
객체가 되어, 부르는 쪽이 나중에 `A` 를 고쳤을 때 표가 조용히 따라 바뀌어요.

#### 3. 아래층 두 칸을 견줘 위층 한 칸을 정한다

층 `k` 의 칸 `i` 는 인덱스 구간 `[i, i+2^k−1]` 을 덮습니다. 그 구간을 반으로 가르면 왼쪽
절반은 `[i, i+2^(k−1)−1]`, 오른쪽 절반은 `[i+2^(k−1), i+2^k−1]` 이고, 둘 다 아래층에 이미
있어요.

```ts
for (let k = 1; k <= (logTable[n] as number); k++) {
  const below = st[k - 1] as number[];
  const width = 1 << k;
  const half = width >> 1;
  const row = new Array<number>(n - width + 1);
  for (let i = 0; i + width <= n; i++) {
    // ① 표 쌓기 — 아래층의 두 칸을 견줘 위층 한 칸을 정한다.
    row[i] = Math.min(below[i] as number, below[i + half] as number);
  }
  st.push(row);
}
```

이 조각만 실행하면 여덟 걸음이 나옵니다. 1 층의 다섯 칸이 `T3` 부터 `T7` 이고, 2 층의 세
칸이 `T8` 부터 `T10` 이에요.

<!--viz:build-->
```text
걸음  층 k  칸 i  아래층 왼쪽  아래층 오른쪽  새 칸  채운 칸 수
T3       1     0            5              2      2           1
T4       1     1            2              7      2           2
T5       1     2            7              4      4           3
T6       1     3            4              6      4           4
T7       1     4            6              3      3           5
T8       2     0            2              4      2           6
T9       2     1            2              4      2           7
T10      2     2            4              3      3           8
```

여기서 가장 중요한 줄은 `row[i] = Math.min(below[i], below[i + half])` 입니다. 오른쪽 조각의
자리가 `i + half` 라는 것, 그러니까 **한 칸 옆이 아니라 절반 옆**이라는 것이 이 줄의
전부예요. `half` 는 `k = 1` 일 때만 1 이고 그 위로는 2, 4, 8 로 커집니다.

```text
층 k  width = 2^k  half = 2^(k−1)  칸 i 가 읽는 두 자리
1               2               1  i 와 i+1
2               4               2  i 와 i+2
3               8               4  i 와 i+4
                                   └ k=1 에서만 half 가 1 이다
```

#### 짚고 가기 — 층마다 반복하는 범위를 안 줄여도 답이 안 틀린다

여기서 헷갈리기 쉬운 포인트는 `i + width <= n` 이라는 조건입니다. 「어차피 칸마다 값을 넣는
것이니 `i < n` 으로 두면 안 되나」로 읽기 쉬워요. 그렇게 두면 층마다 칸이 `n` 개가 되고,
아래층에 없는 자리를 읽게 됩니다.

<!--proof:pause-no-guard-levels-->

```text
층    칸 수  범위를 줄인 표  칸 수  안 줄인 표           판정
0 층      6  [5 2 7 4 6 3]       6  [5 2 7 4 6 3]        같다
1 층      5  [2 2 4 4 3]         6  [2 2 4 4 3 NaN]      어긋난다
2 층      3  [2 2 3]             6  [2 2 3 NaN NaN NaN]  어긋난다

└ 아래층에 없는 칸을 읽은 자리에 값이 아닌 것이 들어가고, 그것이 위층으로 옮겨 간다
```

표가 이렇게 망가지는데, **답은 하나도 안 틀립니다.** 정본과 이 변경을 여덟 입력에 나란히
걸어 봤어요.

<!--proof:pause-no-guard-answers-->

```text
입력                     가드가 막은 칸  정본         범위를 안 줄인 판  판정
전개 입력 [5 2 7 4 6 3]               4  [2 2 4 2 3]  [2 2 4 2 3]        같다
[42]                                  0  [42]         [42]               같다
[3 1]                                 1  [1]          [1]                같다
[3 1 4]                               1  [1 1]        [1 1]              같다
[3 1 4 1 5 9 2 6]                    11  [1 1 2]      [1 1 2]            같다
[1 2 3 4 5]                           4  [1 4]        [1 4]              같다
[-3 -1 -5 2]                          4  [-5]         [-5]               같다
[5 5 5 5]                             4  [5]          [5]                같다
```

「가드가 막은 칸」 열이 여덟 줄 중 일곱 줄에서 0 이 아닙니다 — 그 줄들은 바뀐 자리를 실제로
지나갔는데도 답이 같아요. 이유는 **질의가 읽는 자리와 값이 아닌 것이 들어간 자리가 겹치지
않기** 때문입니다.

```text
층 k 의 칸을 자리로 갈라 보면
  질의가 읽는 칸              0 … n − 2^k        오른쪽 끝이 배열 안인 자리다
  값이 아닌 칸                n − 2^k + 1 … n−1  가드가 막던 자리다
  k+1 층의 칸 i 가 읽는 자리  i 와 i + 2^k       질의가 읽는 칸이면 i ≤ n − 2^(k+1) 이다
                              └ 그러면 i + 2^k ≤ n − 2^k 라, 읽는 두 자리가 다 왼쪽 구역 안이다
```

테스트가 통과하니 이 변경은 그대로 남습니다. 그래도 고치는 이유는 **표가 커지기**
때문이에요.

<!--proof:pause-no-guard-cells-->

```text
      n  층 수  범위를 줄인 칸  안 줄인 칸  값이 아닌 칸  그만큼의 메모리
      6      3              14          18             4         0.00 MiB
  1,000     10           8,987      10,000         1,013         0.01 MiB
100,000     17       1,568,946   1,700,000       131,054         1.00 MiB

└ 답은 그대로인데 표에 값이 아닌 칸이 그만큼 쌓인다
```

제약 상한에서 값이 아닌 칸이 131,054 개, 메모리로는 1.00 MiB 입니다. 답으로는 안 보이고
메모리로만 보이는 종류의 결함이라, 이런 자리는 답이 맞는지가 아니라 **표가 정의대로
생겼는지**로 확인해야 해요.

#### 4. 구간을 두 조각으로 덮어 질의 하나를 답한다

표가 다 쌓였으면 질의 하나는 세 줄로 끝납니다. 층을 고르고, 두 자리를 읽고, 더 작은 쪽을
답해요.

```ts
const result: number[] = [];
for (const [l, r] of queries) {
  // ② 질의 — 구간을 칸 수가 같은 두 조각으로 덮는다. 왼쪽 끝에서 한 조각, 오른쪽 끝에서
  // 한 조각이고 가운데가 겹쳐도 최솟값은 안 바뀐다.
  const k = logTable[r - l + 1] as number;
  const row = st[k] as number[];
  result.push(Math.min(row[l] as number, row[r - (1 << k) + 1] as number));
}
```

첫 질의 `[0,4]` 에 이 조각만 실행한 결과입니다. 이것이 `T11` 이에요.

```text
들어올 때   l=0  r=4           표는 0 층 5 2 7 4 6 3 · 1 층 2 2 4 4 3 · 2 층 2 2 3 이다
칸 수       r − l + 1 = 5
층 번호     logTable[5] = 2    4 칸짜리 조각을 쓴다
읽는 칸     st[2][0] = 2       왼쪽 끝에서 시작하는 조각
            st[2][1] = 2       오른쪽 끝에서 끝나는 조각, 시작 자리는 4 − 4 + 1 = 1
견주면      min(2, 2) = 2      결과 목록이 [2] 가 된다
            └ 구간이 다섯 칸인데 읽은 칸은 둘이다
```

#### 짚고 가기 — 겹친 칸을 두 번 세도 최솟값이 안 바뀐다

여기서 헷갈리기 쉬운 포인트는 겹침입니다. 「같은 칸을 두 번 넣는데 답이 맞을 리가 있나」로
읽기 쉬워요. 실제로 그 걱정이 맞는 연산이 있습니다 — 같은 표를 **합**으로 만들면 겹친 칸이
두 번 더해집니다. 두 표를 같은 다섯 질의로 실행해 봤어요.

<!--proof:pause-overlap-->

```text
같은 표를 최솟값으로 만들었을 때
질의   층 k  두 조각      겹친 칸  구간의 최솟값  두 조각의 최솟값  판정
[0,4]     2  [0,3] [1,4]        3              2                 2  같다
[1,2]     1  [1,2] [1,2]        2              2                 2  같다
[3,3]     0  [3,3] [3,3]        1              4                 4  같다
[0,5]     2  [0,3] [2,5]        2              2                 2  같다
[2,5]     2  [2,5] [2,5]        4              3                 3  같다

같은 표를 합으로 만들었을 때
질의   겹친 칸  구간의 합  두 조각의 합  판정
[0,4]        3         24            37  어긋난다
[1,2]        2          9            18  어긋난다
[3,3]        1          4             8  어긋난다
[0,5]        2         27            38  어긋난다
[2,5]        4         20            40  어긋난다

└ 겹친 칸이 가장 적은 질의에서도 1 칸이라, 합으로 만든 표는 다섯 질의가 전부 어긋난다
```

**합은 다섯 질의가 전부 틀립니다.** 「겹친 칸」 열이 다섯 줄 다 1 이상이라 예외가 없어요.
그런데 같은 겹침에서 최솟값은 다섯 줄 다 맞습니다. 갈림은 연산의 성질 하나예요.

```text
질의 [3,3] 을 보면
  두 조각      [3,3] 과 [3,3]      한 칸짜리라 완전히 같은 칸이다
  최솟값       min(4, 4) = 4       정답 4 와 같다
  합           4 + 4 = 8           정답 4 의 두 배다
               └ min 은 같은 값을 두 번 넣어도 그대로이고, 덧셈은 그렇지 않다
```

겹친 칸이 0 이 되는 질의가 아예 없다는 것도 확인해 둡시다. 조각 둘은 각각 `2^k` 칸이라 칸
수 합이 `2·2^k` 이고, `k` 의 정의에서 `len < 2^(k+1) = 2·2^k` 이므로 그 합이 `len` 보다
큽니다. 두 조각이 다 구간 안에 있으니 남는 칸은 겹친 칸뿐이에요.

```text
겹친 칸 수 = 2·2^k − len
  len = 5, k = 2   8 − 5 = 3
  len = 4, k = 2   8 − 4 = 4
  len = 1, k = 0   2 − 1 = 1
                   └ len < 2^(k+1) = 2·2^k 이므로 이 값은 언제나 1 이상이다
```

#### 6. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 결과 목록을 빈 배열로
시작하는 한 줄뿐이에요 — 질의가 하나도 없으면 그 값이 그대로 답이 됩니다.

```ts
export function sparseTableRangeMin(
  A: number[],
  queries: Array<[number, number]>,
): number[] {
  const n = A.length;

  // 칸 수가 `m` 인 구간이 쓸 층 번호를 정수 연산만으로 미리 적어 둔다. 절반 자리의 값에
  // 1 을 더한 것이 그 자리의 값이다.
  const logTable = new Array<number>(n + 1).fill(0);
  for (let m = 2; m <= n; m++) {
    logTable[m] = (logTable[m >> 1] as number) + 1;
  }

  // 층 `k` 의 칸 `i` 에는 인덱스 구간 [i, i + 2^k − 1] 의 최솟값을 담는다. 0 층은 배열
  // 그대로이고, 위층은 아래층 두 칸에서 나온다.
  const st: number[][] = [A.slice()];
  for (let k = 1; k <= (logTable[n] as number); k++) {
    const below = st[k - 1] as number[];
    const width = 1 << k;
    const half = width >> 1;
    const row = new Array<number>(n - width + 1);
    for (let i = 0; i + width <= n; i++) {
      // ① 표 쌓기 — 아래층의 두 칸을 견줘 위층 한 칸을 정한다.
      row[i] = Math.min(below[i] as number, below[i + half] as number);
    }
    st.push(row);
  }

  const result: number[] = [];
  for (const [l, r] of queries) {
    // ② 질의 — 구간을 칸 수가 같은 두 조각으로 덮는다. 왼쪽 끝에서 한 조각, 오른쪽 끝에서
    // 한 조각이고 가운데가 겹쳐도 최솟값은 안 바뀐다.
    const k = logTable[r - l + 1] as number;
    const row = st[k] as number[];
    result.push(Math.min(row[l] as number, row[r - (1 << k) + 1] as number));
  }

  return result;
}
```

```text
sparseTableRangeMin([5, 2, 7, 4, 6, 3], [[0,4], [1,2], [3,3], [0,5], [2,5]])
  →  [2, 2, 4, 2, 3]
sparseTableRangeMin([1, 2, 3], [])             →  []
sparseTableRangeMin([-3, -1, -5, 2], [[0,3]])  →  [-5]
sparseTableRangeMin([42], [[0,0]])             →  [42]
```

### 알아 두면 좋은 개념 — 멱등인 연산

이 절차가 `min` 에 요구한 성질을 한 문장으로 줄이면 **「같은 값을 두 번 넣어도 결과가
그대로다」** 입니다. 어떤 연산 `f` 가 `f(x, x) = x` 를 만족하면 그 연산을 **멱등**이라고
불러요. 「짚고 가기」에서 값으로 본 것이 그것입니다 — `min(4, 4) = 4` 라 `[3,3]` 의 답이 맞았고,
`4 + 4 = 8` 이라 합은 틀렸어요.

| 연산 | `f(x, x)` | 멱등인가 | 겹치는 두 조각으로 덮는가 | 접두 표 두 칸으로 되는가 |
| --- | --- | --- | --- | --- |
| 최솟값 | `min(x,x) = x` | 그렇습니다 | 됩니다. 이 글이 그것입니다 | 안 됩니다. 덜어 내기가 없습니다 |
| 최댓값 | `max(x,x) = x` | 그렇습니다 | 됩니다 | 안 됩니다 |
| 최대공약수 | `gcd(x,x) = x` | 그렇습니다 | 됩니다 | 안 됩니다 |
| 비트 논리곱 | `x & x = x` | 그렇습니다 | 됩니다 | 안 됩니다 |
| 덧셈 | `x + x = 2x` | 아닙니다 | 안 됩니다 | 됩니다. 뺄셈이 앞부분을 덜어 냅니다 |
| 곱셈 | `x · x = x²` | 아닙니다 | 안 됩니다 | 값에 `0` 이 없을 때만 됩니다 |

오른쪽 두 열이 서로 반대로 갈리는 것이 이 표의 요점입니다. **덜어 내기가 있는 연산은 접두
표로 가고, 멱등인 연산은 겹쳐 덮기로 갑니다.** 둘 다 아닌 연산은 겹치지 않게 갈라 합치는
자료구조로 가요.

```text
같은 구간 질의를 세 방식이 나누어 맡는다

  접두 표      두 칸을 덜어 낸다                 덧셈 · 배타적 논리합          덜어 내기가 있어야 한다
  겹쳐 덮기    두 조각을 합친다                  최솟값 · 최댓값 · 최대공약수  멱등이어야 한다
  갈라 합치기  겹치지 않게 여러 조각으로 가른다  위의 전부 + 곱셈 · 행렬 곱    결합 법칙만 있으면 된다
               └ 요구 조건이 강한 쪽일수록 질의 하나의 비용이 작다
```

같은 이름을 다시 만나는 자리가 셋입니다. 구간 최대공약수 질의가 같은 표를 그대로 쓰고,
자리마다 켜진 비트를 묻는 구간 논리곱 질의도 같아요. 그리고 나무에서 두 마디의 가장 가까운
공통 조상을 찾는 문제는 오일러 투어로 배열을 만든 뒤 이 표를 그대로 씁니다.
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 이 다루는
「결합 법칙 + 항등원」은 위 표의 맨 아래 줄이고, 이 글이 요구하는 멱등은 **그 위에 하나 더
붙는 조건**이에요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제가 이 표를 부르는지, 덮기가 임의의 구간에서 왜
성립하는지, 표의 칸이 무엇을 보장하는지, 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- 배열이 **질의를 처리하는 동안 바뀌지 않습니다.** 원소 하나가 바뀌면 그 원소를 덮는 칸이
  층마다 흩어져 있어서 표를 다시 쌓아야 해요.
- 질의가 **연속 구간**을 묻습니다. 인덱스를 골라 담는 질의라면 미리 저장한 조각으로 덮을 수
  없어요.
- 구간에 매기는 연산이 **멱등**입니다. 최솟값·최댓값·최대공약수가 그렇고, 합은 아닙니다.
- 질의 수 `q` 가 **표를 쌓는 비용을 갚을 만큼** 많습니다. 질의가 한두 개면 그냥 구간을
  차례로 읽는 편이 적어요.

```text
네 조건이 코드의 모양을 그대로 정한다
  정적 배열      → 표를 다시 쌓는 코드가 아예 없다
  연속 구간      → 두 끝 l 과 r 만 받으면 상태가 끝난다
  멱등인 연산    → 조각이 둘이면 되고 겹침을 안 따진다
  질의가 많다    → 표 쌓기 n log n 을 q 개가 나눠 진다
```

마지막 줄에 경계가 있습니다. 표를 쌓는 견주기가 `n = 100,000` 에서 1,468,946 번이고 질의
하나는 1 번이니, 질의가 적으면 표를 쌓는 것이 오히려 손해예요.

```text
n = 100,000 일 때 (견주기만 센다)
  질의 1 개, 구간 100 칸  차례로 읽으면 99 번        표를 쌓으면 1,468,947 번
  질의 100,000 개         차례로 읽으면 최악 100 억  표를 쌓으면 1,568,946 번
                          └ 질의 수가 이 둘의 순서를 정한다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "배열은 변경되지 않는다"  "정적"  "미리 주어진다"  ← 결정적인 신호다
  "구간 [l, r] 의 최솟값"  "최댓값"  "최대공약수"
  "질의가 Q 개 주어진다"  "각 질의에 대해 답하라"    ← 질의가 많다는 뜻이다

제약에 이런 모양이 보이면
  지문의 N 과 Q(이 글의 n 과 q)가 둘 다 10^5 이상이라 곱이 못 들어간다
  n log n 칸이 메모리 제한 안에 들어간다

반대로 이런 말이 보이면 해당하지 않는다
  "i 번째 원소를 v 로 바꾼다"  "갱신 질의"         ← 배열이 바뀐다
  "구간의 합"  "구간의 곱"                         ← 멱등이 아니다
  n 이 10^7 이상이라 n log n 칸이 메모리를 넘는다
```

마지막 무리 중 하나라도 걸리면 이 표를 쓸 수 없습니다. 갱신이 섞이면
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 이 답이고,
연산이 합이면 [`prefixSumRangeQuery`](../prefixSumRangeQuery/prefixSumRangeQuery-problem.md)
가 답이에요.

#### 실제로 쓰이는 곳

- **kactl 의 `content/data-structures/RMQ.h`** — KTH 의 공개 알고리즘 라이브러리입니다.
  파일 주석이 이 자료구조를 `"Range Minimum Queries on an array. Returns min(V[a], V[a + 1],
  ... V[b - 1]) in constant time."` 로 적고 시간 복잡도를 `O(|V| log |V| + Q)` 로 적어요.
  표를 쌓는 줄이 `jmp[k][j] = min(jmp[k - 1][j], jmp[k - 1][j + pw]);` 로 이 글의 ① 과 같은
  모양입니다.
  ([kactl RMQ.h](https://github.com/kth-competitive-programming/kactl/blob/main/content/data-structures/RMQ.h),
  조회 2026-09-08)
- **sdsl-lite 의 `include/sdsl/rmq_support_sparse_table.hpp`** — 간결 자료구조 라이브러리의
  구간 최솟값 지원 클래스입니다. 질의가 `size_type k = bits::hi(r-l);` 로 층을 고르고
  `const size_type rr = r-(1ULL<<k)+1;` 로 오른쪽 조각의 시작 자리를 잡아요. **값이 아니라
  자리를 저장한다**는 것이 이 글과 다른 점입니다 — 최솟값이 어느 인덱스에 있었는지까지
  답해야 하는 쪽이라 그렇습니다.
  ([sdsl-lite rmq_support_sparse_table.hpp](https://github.com/simongog/sdsl-lite/blob/master/include/sdsl/rmq_support_sparse_table.hpp),
  조회 2026-09-08)
- **이름의 출처** — Bender 와 Farach-Colton 의 2000 년 논문 「The LCA Problem Revisited」가
  이 절차에 `"the Sparse Table (ST) algorithm for RMQ"` 라는 이름을 붙였습니다. 같은 절이
  아이디어를 `"The idea is to precompute each query whose length is a power of two."` 로
  적고, 질의를 `"We select two overlapping blocks that entirely cover the subrange"` 로
  적어요. 전처리와 질의의 복잡도를 각각 `O(n log n)` 과 `O(1)` 로 적습니다.
  ([The LCA Problem Revisited (PDF)](https://www3.cs.stonybrook.edu/~bender/newpub/BenderFa00-lca.pdf),
  조회 2026-09-08)

```text
세 출처와 이 글의 차이
  kactl      구간을 [a, b) 로 잡고 값을 저장한다       층 번호를 __builtin_clz 로 구한다
  sdsl-lite  양끝을 포함하고 최솟값의 자리를 저장한다  층 번호를 bits::hi 로 구한다
  논문       양끝을 포함하고 최솟값의 자리를 저장한다  층 번호를 ⌊log(j−i)⌋ 로 구한다
  이 글      양끝을 포함하고 최솟값을 저장한다         층 번호를 정수 표에서 읽는다
             └ 넷 다 「조각 둘로 겹쳐 덮는다」는 같고, 저장하는 것과 층 번호를 구하는 법이 다르다
```

#### 경쟁 설계와의 대조

같은 목표(구간 최솟값 질의에 답하기)를 노리는 다른 절차로 **세그먼트 트리**가 있습니다.
마디 하나가 자기 아래 구간의 최솟값을 들고 있어서, 질의는 **겹치지 않는 마디 여럿**으로
구간을 갈라 합쳐요. 갱신은 그 잎에서 뿌리까지의 조상만 다시 계산하면 끝납니다.

```text
같은 질문에 두 설계가 답하는 방식

  스파스 테이블   겹치는 두 조각으로 덮는다        읽는 칸이 언제나 2 개, 표를 쌓는 값이 크다
  세그먼트 트리   겹치지 않는 마디로 갈라 합친다   읽는 칸이 최대 2⌈log₂ n⌉ 개, 갱신을 받는다
                  └ 이쪽은 질의 하나의 비용이 작고 표를 쌓는 비용이 크며 갱신을 못 받는다
```

같은 입력·같은 작업 목록에 두 설계를 걸고 **배열 접근 수**(읽기 + 쓰기)를 셌습니다. 배열은
`n = 2,048` 이고 `A[i] = (733i) mod 1009` 입니다. 질의 목록의 `j` 번째는
`a = (577j) mod n` 과 `b = (1231j) mod n` 을 만들어 작은 쪽을 왼쪽 끝으로 뒀고, `u` 번째

고르게 끼웠어요. 전개가 쓰는 여섯 칸짜리 입력으로는 층이 셋뿐이라 두 설계의 계수가 상수에 묻혀서

### 수식 정의와 유도

표를 기호로 정의합니다. 층 `k` 의 칸 `i` 는 인덱스 구간 `[i, i+2^k−1]` 의 최솟값이고, 그
구간이 배열 안에 들어가는 `i` 에만 정의됩니다.

$$\operatorname{st}[k][i] = \min\{\, A[t] \;:\; i \le t \le i + 2^{k} - 1 \,\}, \qquad 0 \le k \le \lfloor \log_2 n \rfloor, \quad 0 \le i \le n - 2^{k}$$

```text
정의를 값에 넣어 봅니다 — A 의 값 5 2 7 4 6 3

  st[0][3] = min{A[3]}                    = 4
  st[1][3] = min{A[3], A[4]}              = min(4, 6) = 4
  st[2][1] = min{A[1], A[2], A[3], A[4]}  = min(2, 7, 4, 6) = 2
             └ 정의 하나가 칸 하나를 정하고, 첨자 둘이 시작 자리와 칸 수를 나눠 맡는다
```

이 정의에서 **표를 채우는 재귀식**이 나옵니다. 칸 수 `2^k` 짜리 구간은 칸 수 `2^(k−1)` 짜리
구간 둘로 겹치지 않게 갈리고, 최솟값은 갈래마다의 최솟값 중 더 작은 쪽이에요.

$$\operatorname{st}[k][i] = \min\bigl(\operatorname{st}[k-1][i],\; \operatorname{st}[k-1][i + 2^{k-1}]\bigr)$$

```text
재귀식을 값에 넣어 봅니다

  st[2][1] = min( st[1][1], st[1][3] )
           = min( min(A[1], A[2]), min(A[3], A[4]) )
           = min( 2, 4 ) = 2
             └ 위에서 정의로 직접 계산한 2 와 같다
```

다음은 **덮기**입니다. 임의의 `l ≤ r` 에 대해 `len = r − l + 1` 로 두고
`k = ⌊log₂ len⌋` 이라 하면, 두 조각이 구간을 정확히 덮는다는 것을 보입니다. `k` 의 정의에서
부등식 둘이 나와요.

$$2^{k} \le \mathit{len} < 2^{k+1}$$

```text
두 조각이 구간 안에 있는가
  왼쪽 조각   [l, l + 2^k − 1]        2^k ≤ len 이므로 l + 2^k − 1 ≤ l + len − 1 = r
  오른쪽 조각 [r − 2^k + 1, r]        2^k ≤ len 이므로 r − 2^k + 1 ≥ r − len + 1 = l
              └ 둘 다 왼쪽 끝이 l 이상이고 오른쪽 끝이 r 이하다
```

이제 둘을 합치면 구간이 다 덮이는지 봅니다. 왼쪽 조각이 `l + 2^k − 1` 까지 덮고 오른쪽
조각이 `r − 2^k + 1` 부터 덮으므로, 빠지는 칸이 없으려면 오른쪽 조각의 시작이 왼쪽 조각의
끝 바로 다음 이하여야 해요.

$$r - 2^{k} + 1 \le l + 2^{k} \iff \mathit{len} = r - l + 1 \le 2^{k+1}$$

```text
부등식의 각 항이 왜 그런가
  len < 2^(k+1) 이다         k 가 2^k ≤ len 인 가장 큰 지수이므로
  그러면 len ≤ 2^(k+1) 이다  더 약한 부등식이라 그대로 성립한다
  그래서 빠지는 칸이 없다    오른쪽 조각의 시작이 왼쪽 조각의 끝 다음 이하다
                             └ 겹친 칸 수는 (l + 2^k) − (r − 2^k + 1) = 2^(k+1) − len 이다
```

겹친 칸 수가 `2^(k+1) − len` 이고 `len < 2^(k+1)` 이므로 이 값은 **언제나 1 이상**입니다.
겹치지 않는 경우가 없어요. 그래서 두 조각의 최솟값을 그냥 견줘도 되는 근거가 필요하고, 그것이
멱등입니다.

$$\min\bigl(\operatorname{st}[k][l],\; \operatorname{st}[k][r - 2^{k} + 1]\bigr) = \min\{\, A[t] \;:\; l \le t \le r \,\}$$

```text
양변이 왜 같은가
  왼쪽 ≥ 오른쪽  두 조각의 칸이 전부 [l,r] 안에 있다. 그러면 조각 하나의 최솟값이
                 [l,r] 의 최솟값 이상이고, 두 값 중 작은 쪽도 그렇다
  왼쪽 ≤ 오른쪽  [l,r] 의 최솟값을 내는 칸이 두 조각 중 한쪽에 들어 있다. 그 조각의
                 최솟값은 그 칸의 값 이하이고, 왼쪽은 그 조각의 최솟값 이하다
                 └ 겹친 칸은 두 조각에 한 번씩 들어가는데 min(x, x) = x 라 값이 안 바뀐다
```

식을 그대로 옮기면 코드가 이렇게 됩니다. 표를 미리 쌓지 않고 매번 계산하는 조각이라, 식의
`st[k][i]` 를 코드에서는 `stCell` 로 적었어요.

```ts
// 정의를 그대로 옮긴 조각. 정의를 확인하는 용도이고 실제 절차는 이것을 쓰지 않는다.
const stCell = (A: number[], k: number, i: number): number => {
  let best = A[i] as number;
  for (let t = i; t <= i + (1 << k) - 1; t++) best = Math.min(best, A[t] as number);
  return best;
};
```

마지막으로 **표의 칸 수**를 닫힌 형태로 냅니다. `K = ⌊log₂ n⌋` 로 두면 층은 `K+1` 개이고 층
`k` 의 칸은 `n − 2^k + 1` 개이므로, 등비수열의 합으로 접힙니다.

$$\sum_{k=0}^{K}\bigl(n - 2^{k} + 1\bigr) = (K+1)(n+1) - \bigl(2^{K+1} - 1\bigr)$$

```text
등비수열의 합을 편다
  Σ (n + 1)  층 0 부터 K 까지 n+1 을 더한다  (K+1)(n+1)
  Σ 2^k      k = 0 부터 K 까지 더한다        2^(K+1) − 1
             └ 앞에서 뒤를 빼면 위 식이 된다
```

```text
      n  층 수  닫힌 형태  실측 칸 수  8 바이트 기준  n(⌊log₂n⌋+1)
      6      3         14          14       0.00 MiB            18
  1,000     10      8,987       8,987       0.07 MiB        10,000
100,000     17  1,568,946   1,568,946      11.97 MiB     1,700,000

└ 닫힌 형태와 실측이 세 규모에서 같다. 오른쪽 끝은 층마다 칸을 안 줄였을 때의 값이다
```

제약 상한에서 1,568,946 칸이고 정수 하나를 8 바이트로 잡으면 11.97 MiB 입니다. 메모리 제한
256 MB 의 5 % 아래예요. 오른쪽 끝 열은 층마다 칸을 `n` 개로 두었을 때의 값이고, 그 차이가
131,054 칸입니다.

### 불변식 — 층 k 의 칸 i 는 인덱스 구간 [i, i+2^k−1] 의 최솟값이다

파트 1 에서 코드가 동작하는 것을 열다섯 걸음으로 봤습니다. 그런데 그건 입력 하나에서
맞았다는 뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로
세우고 그것이 실제로 유지되는지 확인해 봅시다.

> 층 `k` 를 다 채운 시점마다, 그 층의 모든 칸 `i` 는 인덱스 구간 `[i, i+2^k−1]` 의
> 최솟값입니다. 그리고 표를 다 쌓은 뒤 배열이 바뀌지 않으므로, 그 성질은 질의를 몇 개
> 처리하든 그대로 남습니다.

```text
       0        1        2      …   n − 2^k        그 뒤
 층 k  ●        ●        ●      …   ●              없음
       └ 칸마다 「그 자리에서 시작하는 2^k 칸의 최솟값」이 들어 있다  ← 앞 문장
         질의는 이 층을 읽기만 하고 고치지 않는다                     ← 뒤 문장
```

문장을 둘로 나눈 이유가 있습니다. 앞 문장은 **표의 칸이 정의와 어긋나지 않는다**는 것이고,
뒤 문장은 **표를 다 쌓은 뒤에는 아무것도 그 칸을 바꾸지 않는다**는 것이에요. 앞이 빠지면 답이
틀리고, 뒤가 빠지면 같은 질의를 두 번 물었을 때 답이 달라질 수 있습니다.

**출발점부터 봅시다.** 0 층은 배열의 복사본이고, 「한 칸짜리 구간의 최솟값은 그 값 자체」가
참입니다. 그 뒤 층 하나가 오를 때마다 아래층의 두 칸에서 나와요.

| 층 | 채우는 식 | 앞 문장이 유지되는 근거 |
| --- | --- | --- |
| `k = 0` | `st[0][i] = A[i]` | 칸 하나짜리 구간의 최솟값은 그 값이다 |
| `k = 1` | `st[1][i] = min(st[0][i], st[0][i+1])` | 두 칸을 한 칸씩 갈랐고 아래층이 각각 참이다 |
| `k` 일반 | `st[k][i] = min(st[k−1][i], st[k−1][i+2^(k−1)])` | 직전 층이 두 절반을 각각 참으로 만들어 뒀다 |
| 층 종료 | `i` 가 `n − 2^k` 까지 | 오른쪽 끝이 배열 안인 칸만 만들었다 |

그것을 실제 값으로 확인합니다. 전개 입력의 표를 다 쌓은 뒤, 각 칸을 정의대로 직접 계산한
값과 대조했어요.

<!--proof:invariant-levels-->

```text
층    칸 수  칸의 값        덮는 칸 수  확인한 칸  어긋난 칸
0 층      6  [5 2 7 4 6 3]           1          6          0
1 층      5  [2 2 4 4 3]             2          5          0
2 층      3  [2 2 3]                 4          3          0

└ 정의를 직접 계산한 값과 표의 값을 14 칸에서 대조했고 어긋난 칸이 0 개다
```

뒤 문장은 질의 루프가 집니다. 그 루프에는 `st` 나 `A` 에 값을 쓰는 줄이 하나도 없어요 —
`Math.min` 으로 두 칸을 읽어 결과 목록에 덧붙이는 것이 전부입니다. 그래서 첫 질의가 보는 표와
마지막 질의가 보는 표가 같아요. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

```text
경계               배열           질의         답     정의를 직접 계산한 값과
질의 목록이 빔     [1 2 3]        없음         []     같다
원소 하나          [42]           [0,0]        [42]   같다
한 칸짜리 질의     [5 2 7 4 6 3]  [3,3]        [4]    같다
배열 전체          [5 2 7 4 6 3]  [0,5]        [2]    같다
값이 전부 같음     [5 5 5 5]      [1,2]        [5]    같다
음수가 섞임        [-3 -1 -5 2]   [0,3]        [-5]   같다
같은 질의를 두 번  [5 2 7 4 6 3]  [0,4] [0,4]  [2 2]  같다

└ 일곱 줄 다 정의를 직접 계산한 값과 같다
```

원소가 하나뿐인 배열에서는 `logTable[1] = 0` 이라 층이 0 층 하나뿐이고, 위층을 만드는 루프가
한 번도 실행되지 않습니다. 값이 전부 같은 배열에서는 모든 칸이 같은 값이 되고, 음수가 섞여도
견주기가 부호를 그대로 가져와요.

**이제 깨뜨려 봅시다.** 앞 문장을 지키던 줄은 위층 한 칸을 정하는 그 한 줄이고, 그 줄에서
불변식이 걸려 있는 자리는 **오른쪽 조각의 시작 자리**입니다. 「어차피 옆 칸이니」라는 생각으로
`i + half` 를 `i + 1` 로 바꿔 봅니다.

```ts
row[i] = Math.min(below[i] as number, below[i + 1] as number);   // ← half 대신 1
```

이렇게 두면 층 `k` 의 칸이 `2^k` 칸이 아니라 `2^(k−1) + 1` 칸을 덮게 됩니다. `k = 1` 에서는
`half` 가 1 이라 아무 차이가 없고, `k = 2` 부터 갈려요.

<!--proof:mutant-next-cell-->

```text
입력                     절반이 1 이 아닌 칸  정본         한 칸 옆을 읽은 판  판정
전개 입력 [5 2 7 4 6 3]                    3  [2 2 4 2 3]  [2 2 4 2 4]         어긋난다
[42]                                       0  [42]         [42]                같다
[3 1]                                      0  [1]          [1]                 같다
[3 1 4]                                    0  [1 1]        [1 1]               같다
[3 1 4 1 5 9 2 6]                          6  [1 1 2]      [1 1 2]             같다
[1 2 3 4 5]                                2  [1 4]        [1 4]               같다
[-3 -1 -5 2]                               1  [-5]         [-5]                같다
[5 5 5 5]                                  1  [5]          [5]                 같다
```

전개 입력의 마지막 질의가 3 대신 4 를 냈습니다. `[2,5]` 는 2 층의 칸 2 를 읽는데, 그 칸이
`min(A[2..5]) = 3` 이 아니라 `min(A[2..4]) = 4` 가 되었어요 — `A[5] = 3` 이 빠진 것입니다.

```text
2 층의 칸 2 가 무엇이 되는가
  바른 코드   min(st[1][2], st[1][4]) = min(4, 3) = 3     인덱스 구간 [2,5] 를 덮는다
  바꾼 코드   min(st[1][2], st[1][3]) = min(4, 4) = 4     인덱스 구간 [2,4] 만 덮는다
              └ 오른쪽 끝 A[5] = 3 이 표에 안 들어가서 답이 커진다
```

「절반이 1 이 아닌 칸」 열을 함께 봐야 나머지 일곱 줄이 읽힙니다. 그 값이 0 인 세 줄은 애초에
2 층이 없어서 바뀐 자리를 지나가지 않았고, 값이 1 이상인 네 줄은 지나갔는데도 답이 같아요 —
그 입력들에서는 빠진 칸이 최솟값이 아니었을 뿐입니다. **답이 같다는 것이 무해하다는 뜻이
아니라는 것**이 이 열이 있는 이유예요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 종류입니다 — 층 번호 표를 채우는 것, 표를 쌓으며 견주는 것,
질의마다 두 칸을 견주는 것이에요. 전개의 값으로 확인하면 층 번호 표가 T1 한 걸음이고, 표
쌓기가 T3부터 T10까지 여덟 번, 질의가 T11부터 T15까지 다섯 번이었습니다.

```text
층 번호 표   T1                            m 이 2 부터 n 까지 → 덧셈 n−1 번
표 쌓기      T3 T4 T5 T6 T7 T8 T9 T10      층 k 마다 n − 2^k + 1 칸 → 견주기 8 번
질의         T11 T12 T13 T14 T15           질의 하나에 견주기 1 번 → 5 번
                                           └ 표 쌓기 8 + 질의 5 = 13 번
```

표 쌓기의 견주기 수는 층마다의 칸 수를 더한 것입니다. `K = ⌊log₂ n⌋` 으로 두면 층 `1` 부터
`K` 까지 각각 `n − 2^k + 1` 칸이므로 등비수열의 합으로 접혀요.

$$\sum_{k=1}^{K}\bigl(n - 2^{k} + 1\bigr) = K(n+1) - \bigl(2^{K+1} - 2\bigr)$$

```text
같은 합을 층 1 부터 K 까지만 더한다
  Σ (n + 1)  층이 K 개다               K(n+1)
  Σ 2^k      k = 1 부터 K 까지 더한다  2^(K+1) − 2
             └ 0 층은 견주기가 없어서 빠진다
```

<!--proof:perf-scale-->

```text
  n = q  표 만들기(실측)  K(n+1) − (2^(K+1) − 2)     질의  견주기 합  차례로 읽기 최악
      6                8                       8        6         14                30
  1,000            7,987                   7,987    1,000      8,987           999,000
100,000        1,468,946               1,468,946  100,000  1,568,946     9,999,900,000

└ 닫힌 형태와 실측이 세 규모에서 같다. 오른쪽 끝은 같은 규모에서 질의마다 구간을 차례로 읽었을 때의 값이다
```

닫힌 형태와 실측이 세 규모에서 같습니다. 여기서 센 것은 **견주기 수**이고, 층 번호 표를
채우는 덧셈 `n−1` 번과 0 층을 복사하는 `n` 번은 따로예요.

```text
총식 = 층 번호 표 + 0 층 복사 + 표 쌓기 견주기 + 질의 견주기
       └ n−1      └ n         └ K(n+1) − (2^(K+1) − 2)   └ q

       n = q = 100,000 이면 99,999 + 100,000 + 1,468,946 + 100,000 = 1,768,945 번
       추가로 잡는 칸은 층 번호 표 n+1 칸과 표 1,568,946 칸이다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 축이 다릅니다. 「최악은 `O`,
평균은 `Θ`」처럼 한쪽을 다른 쪽에 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (질의가 전부 한 칸짜리) | `O(n log n + q)` | `Θ(n log n + q)` |
| **평균적인 경우** (입력 분포와 무관하다) | `O(n log n + q)` | `Θ(n log n + q)` |
| **최악의 경우** (질의가 전부 배열 전체) | `O(n log n + q)` | `Θ(n log n + q)` — 실제로 도달한다 |

세 줄이 전부 같습니다. 최선과 최악이 **상수 계수에서도 안 갈려요** — 표를 쌓는 견주기는
`n` 만으로 정해지고 질의 하나의 견주기는 언제나 1 이라, 값이 입력의 내용에도 질의의 모양에도
반응하지 않기 때문입니다.

```text
비교 대상과 나란히 놓으면 이 성질이 확인된다
  차례로 읽기     최선 0 번           최악 q(n−1) 번        질의의 모양이 비용을 정한다
  층으로 쌓은 표  최선 n log n + q    최악 n log n + q      질의의 모양이 비용을 안 바꾼다
                  └ 아래 줄에 최선과 최악이 없다는 것이 이 표를 쌓는 대가로 얻는 것이다
```

**총식을 한 번은 정확히 적습니다.** 이 절차에는 정렬도 좌표압축도 없고, 표 앞에 붙는 것이
층 번호 표 하나뿐이라 항이 단순해요.

```text
총식 = Θ(n log n + q) 시간 + Θ(n log n) 추가 메모리
       └ 표 쌓기 Θ(n log n) + 질의 q 개 × Θ(1)    └ 표 1,568,946 칸 + 층 번호 표 100,001 칸

n = q = 100,000 이면 견주기가 1,568,946 번이고 표가 11.97 MiB 다
```

**보장의 종류는 최악 보장입니다.** 기댓값이 아니에요. 이 코드에는 난수가 없고 입력의 분포를
가정하는 자리도 없어서, 어떤 배열과 어떤 질의를 넣어도 견주기 수가 위 식 그대로입니다.

```text
기댓값이면      같은 입력을 두 번 넣었을 때 값이 다를 수 있다   ← 이 절차는 해당 없다
최악 보장이면   어떤 입력이든 상한 아래다                       ← 이쪽이다
                └ 이 절차는 상한이 아니라 정확한 값이 나와서 그보다 강하다
```

#### 최악을 만드는 입력

견주기를 최대로 만드는 방법은 하나뿐입니다 — **`n` 과 `q` 를 제약의 최댓값으로 두는 것**
이에요. 배열의 모양도 질의의 모양도 아무 상관이 없습니다. 「정렬된 배열이면 느리다」는 흔한
통념이 여기서 성립하는지 값으로 확인해 봅시다.


**「정렬된 배열이면 느리다」는 이 절차에서 거짓입니다.** 오름차순과 내림차순이 같은 8,987

```text
그래서 최악은 모양이 아니라 규모로만 만들어진다

```

한 가지만 다릅니다. **`n` 이 커지면 시간보다 메모리가 먼저 막혀요.** 표가 `n log n` 칸이라

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 칸 수가 2 의 거듭제곱인 구간의 최솟값만 미리
적어 두고, 임의의 구간은 그런 조각 **둘로 겹쳐 덮어** 답합니다. 겹쳐도 되는 근거가 멱등이고,
표를 다시 쌓지 않아도 되는 근거가 「배열이 안 바뀐다」예요.

```text
층을 ⌊log₂ n⌋ + 1 개 쌓는다 → 위층은 아래층 두 칸에서 나온다 → 질의는 두 조각을 견준다
        └ 칸이 n log n 규모   └ 견주기 K(n+1) − (2^(K+1) − 2)   └ 구간의 칸 수와 무관
```

먼저 답이 붙는 문제 하나입니다. 전개의 T15 는 질의 `[2,5]` 를 답했는데, 두 조각이 **같은
칸**을 가리켰어요. 같은 칸을 두 번 읽느니 한 번만 읽으면 되지 않을까요?

```text
T15   l=2  r=5   칸 수 4   층 2   st[2][2] 와 st[2][2]   답 3
                 └ 두 자리가 같다. 한 번만 읽으면 읽기가 하나 준다
```

<!--check:samecell-->
줄일 수 있습니다. 다만 그러려면 `l === r - (1 << k) + 1` 인지 검사하는 분기가 질의마다 하나
늘어요. 질의 `q` 개에 검사 `q` 번을 더해서 칸 수가 2 의 거듭제곱인 질의에서만 읽기 하나를
줄이는 것이라, 그런 질의가 절반을 넘지 않으면 오히려 연산이 늡니다.

```text
분기가 없을 때  질의 하나 = 읽기 2 + 견주기 1       = 3
분기가 있을 때  거듭제곱 = 검사 1 + 읽기 1          = 2
                그 밖 = 검사 1 + 읽기 2 + 견주기 1  = 4
                └ 칸 수가 2 의 거듭제곱인 질의가 절반이면 평균이 3 으로 같아진다
```

그리고 분기를 하나 더하면 그 분기가 틀릴 자리도 하나 생깁니다. 겹침을 아예 안 따지기로 한
것이 이 절차의 선택이었고, 그 선택이 값을 하는 근거를 「짚고 가기」에서 값으로 봤어요.

  견주기를 `n = 100,000` 에서 각각 세어 견주고, 질의 수가 몇 개부터 표가 앞서는지 구해 보세요.
