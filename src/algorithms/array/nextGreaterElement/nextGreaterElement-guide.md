# nextGreaterElement — 답을 미뤄 둔 자리를 쌓아 두면 큰 값 하나가 여러 자리를 한꺼번에 끝내는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 자리마다 오른쪽을 따로
읽는 방법에서 답을 미뤄 둔 자리만 남기는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

배열의 각 자리에 대해 **오른쪽에서 처음 만나는 더 큰 값**을 답해야 합니다. 「더 크다」는
엄격한 부등호라 같은 값은 답이 되지 않고, 오른쪽에 더 큰 값이 하나도 없으면 그 자리의 답은
`-1` 이에요.

자리마다 오른쪽을 따로 읽으면 같은 구간을 몇 번씩 다시 읽습니다. 그 되풀이를 없애는 관찰은
하나예요 — **어떤 값이 지금 자리의 답이라면, 그 값은 더 왼쪽에 있는 여러 자리의 답이기도
하다.**

```text
nums   2  1  2  4  3
자리   0  1  2  3  4

자리 3 의 값 4 를 읽는 순간
  자리 2 (값 2)   4 가 오른쪽에서 처음 만나는 더 큰 값이다     답 4
  자리 0 (값 2)   그 사이에 4 보다 큰 값이 없었다              답 4
  자리 1 (값 1)   그전에 자리 2 의 값 2 로 답이 이미 정해졌다  답 2
                  └ 값 하나를 읽는 것이 두 자리의 답을 함께 정한다
```

그러니 **답이 아직 정해지지 않은 자리를 모아 두었다가, 큰 값을 만나는 순간 한꺼번에
확정**하면 됩니다. 모아 둔 자리에는 성질이 하나 붙어요 — 자리 번호가 커지는 방향으로 값이
커지지 않습니다. 커지는 짝이 있었다면 왼쪽 것이 오른쪽 것을 답으로 받고 이미 빠졌을
테니까요.

```text
읽은 자리를 왼쪽부터 모아 두면 (아래 줄에 그 자리의 값을 적었다)

  자리 0 을 읽고     모은 자리 0        값 2
  자리 1 을 읽고     모은 자리 0 1      값 2 1     1 은 2 보다 작아 그대로 모인다
  자리 2 를 읽으면   모은 자리 0 2      값 2 2     자리 1 이 답 2 를 받고 빠진다
  자리 3 을 읽으면   모은 자리 3        값 4       자리 2 와 자리 0 이 답 4 를 받고 빠진다
                     └ 모인 값은 먼저 들어온 쪽에서 나중에 들어온 쪽으로 커지지 않는다
```

모아 둔 자리는 **나중에 넣은 것이 먼저 빠집니다.** 나중에 넣은 자리일수록 값이 작으니 큰
값을 만났을 때 먼저 조건을 만족하기 때문이에요. 그 순서를 그대로 지키는 담는 통이 스택이고,
담는 것은 값이 아니라 **자리 번호**입니다 — 답을 적을 칸이 어디인지 알아야 하니까요.

```text
이 글은 통의 내용을 [0 2] 처럼 한 줄로 적는다

  왼쪽 끝    먼저 들어온 자리다. 이 글은 **바닥**이라고 부른다
  오른쪽 끝  나중에 들어온 자리이고 먼저 나갈 자리다. 이 글은 **꼭대기**라고 부른다
             └ 그래서 「바닥에서 꼭대기로 값이 커지지 않는다」가 위 그림의 성질이다
```

```text
한 걸음이 하는 일은 둘뿐이다

  1. 꼭대기가 가리키는 값이 지금 값보다 작으면 꺼내고, 꺼낸 자리의 답을 지금 값으로 적는다
     └ 더 꺼낼 것이 없을 때까지 되풀이한다
  2. 그다음 지금 자리를 넣는다
     └ 자리마다 한 번 들어가고 많아야 한 번 나오므로 걸음의 총수가 배열 길이에 비례한다
```

각 자리가 한 번 들어가고 많아야 한 번 나오므로 전체가 `O(N)` 입니다. 배열을 한 번 지나는
것과 같은 규모예요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **배열의 인덱스.** `nums[i]` 가 `i` 번째 값이고 `i` 는 0 부터 셉니다.
- **스택.** 마지막에 넣은 것이 가장 먼저 나오는 담는 통이에요. 넣기 · 꺼내기 · 꼭대기 보기가
  각각 한 번에 끝납니다. 흐릿하면
  [`monotonicStack`](../../../data-structures/linear/monotonicStack/monotonicStack.ts) 을
  먼저 봅니다.
- **엄격한 부등호와 느슨한 부등호의 차이.** `a < b` 와 `a ≤ b` 는 `a = b` 인 자리에서
  갈립니다. 이 문제의 답은 「엄격하게 큰 값」이라 그 자리가 답을 바꿉니다.
- **`O(N)` 표기.** 비용이 입력 길이에 비례한다는 뜻이고, 여기서는 배열을 한 번 지나는 것과
  같은 규모입니다.

「오른쪽에서 처음 만나는 어떤 값」이라는 말만으로는 절차가 안 정해집니다. **무엇을 묻는가**와
**어느 쪽을 보는가**가 함께 있어야 갈려요.

```text
[2 1 2 4 3] 에서
  자리마다 오른쪽에서 처음 더 큰 값        [4 2 4 -1 -1]   ← 이 글이 답하는 것
  자리마다 왼쪽에서 처음 더 큰 값          [-1 2 -1 -1 4]  ← 방향만 뒤집으면 된다
  길이 3 인 창마다 최댓값                  [2 4 4]         ← 이 글은 안 한다. 넣고 빼는 쪽이 둘이다
  자리마다 오른쪽에서 처음 더 작은 값      [1 -1 -1 3 -1]  ← 부등호만 뒤집으면 된다
```

창이 움직이는 문제는 양 끝에서 넣고 빼는 통이 필요해
[`slidingWindowMaximum`](../slidingWindowMaximum/slidingWindowMaximum-problem.md) 쪽이고,
답을 값이 아니라 넓이로 묶는 문제는
[`largestRectangleInHistogram`](../largestRectangleInHistogram/largestRectangleInHistogram-problem.md)
쪽입니다.

### 아이디어 상세 — 답을 미뤄 둔 자리만 남기는 방법을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
export function nextGreaterElement(nums: number[]): number[];
```

- 입력: 정수 배열 `nums`.
- 출력: 길이가 같은 배열. `i` 번째 값은 `nums[i]` 보다 **오른쪽**에 있는 값 중 처음으로
  **엄격하게** 큰 값이고, 그런 값이 없으면 `-1` 입니다. 마지막 자리는 언제나 `-1` 이에요.
- 제약: `1 ≤ N ≤ 100,000`, `−10^9 ≤ nums[i] ≤ 10^9`. 시간 1초, 메모리 256 MB.

이 글이 쓰는 기호는 아홉이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `N` | 배열 `nums` 의 길이 | `1 ≤ N ≤ 100,000` |
| `nums[i]` | 배열의 `i` 번째 값. 0 부터 셉니다 | `−10^9` 이상 `10^9` 이하 |
| `i` | 지금 읽고 있는 자리 | `0 ≤ i < N` |
| `result[i]` | 자리 `i` 의 답. 없으면 `-1` | 길이가 `N` 입니다 |
| `stack` | 답이 아직 정해지지 않은 자리를 담는 통 | 값이 아니라 자리 번호를 담습니다 |
| `top` | `stack` 꼭대기가 가리키는 자리 | 통이 비면 없습니다 |
| `P` | 한 번의 실행에서 자리를 꺼낸 총횟수 | `0 ≤ P ≤ N − 1` |
| `B` | 꺼낼 것이 남았는데도 조건이 안 맞아 멈춘 걸음의 수 | `0 ≤ B ≤ N − 1` |
| `S` | 순회가 끝났을 때 `stack` 에 남은 자리의 개수 | `1 ≤ S ≤ N` |

가장 먼저 떠오르는 방법으로 시작합시다. 정의를 글자 그대로 옮기는 것이에요 — 자리마다
자기 오른쪽을 차례로 읽어 처음 만나는 더 큰 값에서 멈춥니다.

```ts
for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) {
    if ((nums[j] ?? 0) > (nums[i] ?? 0)) {
      result[i] = nums[j] ?? 0; // 처음 만난 더 큰 값에서 멈춘다
      break;
    }
  }
}
```

답은 맞습니다. 문제는 **오른쪽에 더 큰 값이 없을 때**예요 — 그때는 배열 끝까지 읽고 아무것도
못 얻습니다. 감소 수열이면 모든 자리가 그렇습니다.

<!--proof:naive-scale-->

```text
N             차례로 읽기 · 견준 횟수  차례로 읽기 · 배열 접근  이 절차 · 배열 접근
1,000                         499,500                  501,500                4,998
10,000                     49,995,000               50,015,000               49,998
100,000 (식)            4,999,950,000            5,000,150,000              499,998

└ 입력은 감소 수열이다 — 차례로 읽기의 최악이고, 답이 전부 -1 인 입력이다
  차례로 읽기는 N(N−1)/2 로 커지고 이 절차는 5N − 2 로 커진다
```

제약 상한 `N = 100,000` 에서 견준 횟수가 **약 50 억**입니다. 단순 연산을 초당 1 억 번으로
잡아도 50 초가 걸려요. 시간 제한이 1 초이니 이 방법으로는 안 됩니다.

같은 구간을 몇 번 다시 읽는지 작은 입력에서 봅시다. `nums = [2 1 2 4 3]` 에서 자리 0 과 자리
1 과 자리 2 가 읽는 구간이 겹칩니다.

```text
자리 0 (값 2)   자리 1 · 2 · 3 을 읽고 4 에서 멈춘다      세 번 읽었다
자리 1 (값 1)   자리 2 를 읽고 2 에서 멈춘다              한 번 읽었다
자리 2 (값 2)   자리 3 을 읽고 4 에서 멈춘다              한 번 읽었다
자리 3 (값 4)   자리 4 를 읽고 못 찾는다                  한 번 읽었다
                └ 자리 3 의 값 4 를 자리 0 과 자리 2 가 따로 읽는다. 같은 값을 두 번 읽었다
```

값 4 하나가 자리 0 과 자리 2 **둘의 답**입니다. 그런데 위 방법은 그 값을 자리마다 따로
읽어요. 여기서 방향을 뒤집어 봅시다 — 「자리 `i` 의 답이 무엇인가」가 아니라 **「지금 읽은
값이 누구의 답인가」** 로요.

```text
자리 3 의 값 4 를 읽었을 때, 4 를 답으로 받을 자리는 누구인가

  자리 2 (값 2)   4 > 2 라 받는다.        자리 2 와 자리 3 사이에 아무것도 없다
  자리 0 (값 2)   4 > 2 라 받는다.        그 사이의 값 1 과 2 는 둘 다 2 를 못 넘었다
  자리 1 (값 1)   못 받는다.              값 2 가 먼저 1 을 넘어 답이 이미 정해졌다
                  └ 「받을 자리」는 답이 아직 없는 자리 중에서만 나온다
```

그러면 답이 아직 없는 자리를 어딘가에 남겨 두어야 합니다. 두 방법을 같은 입력에서 재
봅시다 — 자리마다 오른쪽을 차례로 읽는 것과, 답이 없는 자리를 남겨 두고 꼭대기부터 보는
것이에요. 입력은 `nums[i] = (7919 i) mod 1009` 인 1,024 칸입니다.

<!--proof:two-ways-->

```text
방식                                   견준 횟수  배열 접근  답
매번 오른쪽을 차례로 읽는다                8,254     11,316  같다
미정 자리를 남겨 두고 꼭대기부터 본다      2,030      8,146  같다

└ 입력은 nums[i] = (7919 i) mod 1009 인 1,024 칸이다. 답은 둘 다 같다
  견준 횟수가 8,254 에서 2,030 로 줄었다 — 뒤엣것은 자리마다 두 번을 안 넘는다
```

견준 횟수가 8,254 에서 2,030 으로 줄었습니다. 여기서 관찰할 것은 **답이 없는 자리를 남겨
두면 오른쪽을 다시 읽을 필요가 없어진다**는 것 하나예요. 남은 것은 「어떻게 남기는가」이고,
그 답이 이 절차의 전부입니다.

가장 단순한 후보를 먼저 시험해 봅시다. **직전 한 자리만 남기는 것**이에요. 답이 없는 자리가
하나뿐이라면 견주기가 걸음마다 한 번으로 끝납니다.

```text
직전 한 자리만 남기면 nums = [2 1 2 4 3] 에서

  자리 0 을 읽고         남은 자리 0        값 2
  자리 1 을 읽으면       남은 자리 1        값 1     자리 0 을 버렸다
  자리 2 를 읽으면       남은 자리 2        값 2     자리 1 은 답 2 를 받았다
  자리 3 을 읽으면       남은 자리 3        값 4     자리 2 는 답 4 를 받았다
                         └ 자리 0 은 이미 버려져 답 4 를 못 받는다. 답이 -1 로 남는다
```

자리 0 의 답이 `-1` 로 남습니다. 옳은 답은 4 예요. **버린 자리는 답을 영영 못 받습니다.**
그러니 몇 자리까지 남길지를 값으로 정해 봅시다 — 남기는 칸 수를 바꿔 가며 틀린 자리의 개수를
셉니다.

<!--proof:keep-how-many-->

```text
남기는 자리 수        견준 횟수  틀린 자리
1                         1,023        858
2                         1,178        703
4                         1,488        393
8                         2,012         18
12                        2,024          6
13                        2,027          3
14                        2,030          0
전부(1,024)               2,030          0
전부 · 아래까지 검사      8,254          0

└ 이 입력에서 스택이 가장 깊었을 때가 15 칸이고, 틀린 자리가 0 이 되는 것은 14 부터다
  같은 스윕을 「감소 수열 1,023 칸 뒤에 가장 큰 값 하나」로 다시 재면 1,023 부터라, 상한을 둘 수 없다
  마지막 줄은 다 남기되 꼭대기에서 안 멈추고 아래까지 맞대 본 것이다 — 답은 같고 견준 횟수만 는다
```

두 가지가 나왔습니다. 첫째, **남기는 칸 수에 상한을 둘 수 없습니다** — 이 입력에서는 14 면
됐지만 감소 수열 뒤에 큰 값 하나를 붙이면 1,023 까지 남겨야 해요. 둘째, **다 남기더라도 아래까지
맞대 보면 견준 횟수가 8,254 로 되돌아갑니다.**

그러니 절차를 정하는 것은 「몇 개를 남기는가」가 아니라 **「어디서 멈추는가」**입니다. 남은
자리의 값이 바닥에서 꼭대기로 커지지 않는다는 성질이 그 멈춤을 정당하게 만들어요.

```text
남은 자리의 값이 커지지 않는 이유

  자리 j 와 자리 k 가 둘 다 남아 있고 j < k 라면
      nums[j] < nums[k] 일 수 없다 — 그랬다면 자리 k 를 읽는 걸음에서 자리 j 가 답을 받고 빠졌다
  그러니 nums[j] ≥ nums[k] 다
      └ 꼭대기가 조건을 안 만족하면 그 아래는 값이 더 커서 더더욱 안 만족한다. 그래서 멈춰도 된다
```

절차가 이것으로 닫힙니다.

```text
얻은 절차 한 벌
  1. 답 배열을 -1 로 깔아 둔다 — 답이 없는 자리가 그 값을 그대로 쓴다
  2. 왼쪽에서 오른쪽으로 자리를 하나씩 읽는다
       꼭대기의 값이 지금 값보다 엄격하게 작은 동안 꺼내고, 꺼낸 자리의 답을 지금 값으로 적는다
       그다음 지금 자리를 넣는다
       └ 10 만 칸에서 50 억 번이던 견주기가 20 만 번 아래가 된다
```

### 수행으로 알아보는 알고리즘 — 다섯 칸을 아홉 걸음으로 지난다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const nums = [2, 1, 2, 4, 3];
// 이 절이 끝나면 [4, 2, 4, -1, -1] 이 나와야 한다
```

왜 하필 이 다섯일까요? 문제 문서의 첫 예시를 그대로 가져온 것이고, 이 다섯이 **갈래를 전부
실행**하기 때문이에요. 같은 값 2 가 두 번 나와서 엄격한 부등호가 실제로 쓰이고, 값 4 하나가
두 자리를 한꺼번에 꺼내며, 마지막 두 자리는 답을 못 받고 남습니다.

```text
절차 전체를 한 장으로

  result 를 -1 로 채운다 (길이 N)                                      ①
  stack 을 빈 통으로 잡는다

  자리 i 를 0 부터 N-1 까지 읽으며:
      꼭대기가 있고 그 값이 nums[i] 보다 엄격하게 작은 동안             ②
          꺼내고 그 자리의 답에 nums[i] 를 적는다                       ③
      지금 자리 i 를 넣는다                                             ④

  result 를 돌려준다 — 남은 자리는 ① 이 깔아 둔 -1 그대로다             ⑤
```

#### 1. 답이 없다는 표시를 미리 깔아 둔다

답 배열을 `-1` 로 채워 두는 것이 이 조각의 전부인데, 그 한 줄이 순회 뒤의 뒷정리를
없앱니다.

```ts
const n = nums.length;
const result = new Array<number>(n).fill(-1); // ① 답 없음을 초기값으로 깐다
const stack: number[] = [];
```

이 조각만 실행하면 이렇게 됩니다.

```text
걸음   하는 일                        result                stack
—      길이 5 짜리 배열을 -1 로 채운다  [-1 -1 -1 -1 -1]      []
       └ 답이 없는 자리와 아직 안 정해진 자리가 지금은 같은 모습이다
```

두 자리를 구분하는 것은 **순회가 끝난 시점**입니다. 그때까지 `stack` 에 남아 있는 자리가
답이 없는 자리이고, `-1` 이 이미 그 자리에 적혀 있어요.

#### 2. 꼭대기와 맞대 보고 엄격하게 작을 때만 꺼낸다

한 걸음의 핵심이 이 조각입니다. 꼭대기가 가리키는 값을 지금 값과 맞대 보고, 엄격하게 작을
때만 꺼내 답을 적어요.

```ts
const cur = nums[i] ?? 0;
while (stack.length > 0) {
  const top = stack[stack.length - 1] ?? 0;
  // ② 꼭대기의 값이 지금 값보다 **엄격하게** 작을 때만 꺼낸다.
  if ((nums[top] ?? 0) >= cur) break;
  stack.pop();
  result[top] = cur; // ③ 꺼낸 자리의 답이 지금 값으로 정해진다
}
```

`i = 3` (값 4)에서 이 조각만 실행하면 두 번 꺼냅니다. 그 앞까지의 상태는 `stack` 이 자리
0 과 자리 2 를 담고 있는 상태예요.

```text
견주기   꼭대기   그 값   지금 값   꺼내는가   꺼낸 뒤 stack   result
1        자리 2       2         4   꺼낸다     [0]             [-1 2 4 -1 -1]
2        자리 0       2         4   꺼낸다     []              [4 2 4 -1 -1]
3        없다         —         4   멈춘다     []              [4 2 4 -1 -1]
         └ 세 번째 견주기는 일어나지 않는다. 통이 비어 반복 조건이 거짓이다
```

`>=` 로 적힌 조건이 「엄격하게 작을 때만 꺼낸다」의 다른 표현입니다. 꼭대기의 값이 지금 값과
**같을 때도 멈춰야** 하기 때문이에요 — 같은 값은 답이 되지 않습니다.

#### 멈춤 — 꺼내기를 한 번만 하면 왼쪽에 남은 자리가 답을 못 받는다

여기서 헷갈리기 쉬운 지점은 `while` 입니다. 「한 걸음에 한 자리씩만 꺼내도 결국 다 꺼내지지
않나」로 읽히는데, **꺼낼 자리가 여럿인 걸음이 실제로 있습니다.**

```text
한 번만 꺼내면 nums = [2 1 2 4 3] 에서

  자리 3 을 읽을 때   자리 2 를 꺼내고 답 4 를 적는다     여기서 반복이 끝난다
                      자리 0 은 stack 에 그대로 남는다
  자리 4 를 읽을 때   꼭대기 자리 3 의 값 4 가 3 보다 크다 → 멈춘다
                      └ 자리 0 은 끝까지 안 꺼내진다. 답이 -1 로 남는다
```

꺼내기를 한 번만 하는 코드에 같은 입력들을 실행해 봅시다.

<!--proof:pause-once-only-->

```text
입력         바른 코드      한 번만 꺼내는 코드
[2 1 2 4 3]  [4 2 4 -1 -1]  [-1 2 4 -1 -1]       답이 다르다
[1 2 3 4]    [2 3 4 -1]     [2 3 4 -1]           답이 같다
[4 3 2 1]    [-1 -1 -1 -1]  [-1 -1 -1 -1]        답이 같다
[1 5 2 6]    [5 6 6 -1]     [5 -1 6 -1]          답이 다르다

└ 한 걸음에 두 자리 이상을 꺼내야 하는 입력에서만 답이 갈린다
  증가 수열은 걸음마다 한 자리씩만 꺼내므로 이 코드로도 답이 맞는다
```

**두 번째와 세 번째 줄이 이 멈춤을 두는 이유입니다.** 증가 수열과 감소 수열에서는 답이 안
틀려요. 한 걸음에 두 자리 이상을 꺼내야 하는 입력이 하나라도 있어야 이 줄이 검사되고, 그런
입력이 없는 시험은 이 코드를 통과시킵니다.

#### 3. 더 꺼낼 것이 없으면 지금 자리를 넣는다

꺼내기가 끝나면 지금 자리를 넣습니다. 지금 자리는 **자기 답을 아직 못 받은 자리**이므로 넣는
것이 정의 그대로예요.

```ts
stack.push(i); // ④ 답이 아직 없는 자리로 넣는다
```

넣는 자리가 언제나 꼭대기가 되고, 그 값이 통 안에서 가장 작습니다. 꺼내기가 먼저 끝났기
때문이에요.

```text
걸음      꺼내기가 끝난 뒤 stack   넣은 자리   넣은 뒤 stack   값(바닥→꼭대기)
i = 0     []                       0           [0]             2
i = 1     [0]                      1           [0 1]           2 1
i = 2     [0]                      2           [0 2]           2 2
i = 3     []                       3           [3]             4
i = 4     [3]                      4           [3 4]           4 3
          └ 넣은 뒤의 값이 바닥에서 꼭대기로 커지지 않는다. 같은 값 2 2 는 허용된다
```

순서를 뒤집어 먼저 넣고 꺼내기를 시작하면 자기 자신이 꺼내기 대상이 됩니다. `nums[i]` 가
`nums[i]` 보다 작을 수는 없어 아무것도 안 꺼내지고, 그러면 답이 전부 `-1` 로 남아요.

#### 멈춤 — 순회가 끝나도 한 번도 안 꺼내지는 자리가 있다

여기서 헷갈리기 쉬운 지점은 초기값 `-1` 입니다. 「어차피 모든 자리가 언젠가 꺼내지니 초기값은
아무것이나 되지 않나」로 읽히는데, **꺼내지지 않고 끝나는 자리가 늘 있습니다.**

```text
nums = [2 1 2 4 3] 의 순회가 끝난 시점

  stack 에 남은 자리   3 (값 4) · 4 (값 3)
  자리 3 의 오른쪽     값 3 하나뿐이고 4 보다 작다        더 큰 값이 없다
  자리 4 의 오른쪽     아무것도 없다                      더 큰 값이 없다
                       └ 남은 자리는 「답이 없는 자리」와 정확히 같다 (⑤ 가 그 값을 그대로 쓴다)
```

초기값을 `0` 으로 깔아 둔 코드에 같은 입력들을 실행해 봅시다.

<!--proof:pause-fill-zero-->

```text
입력         바른 코드      0 을 깔아 둔 코드
[2 1 2 4 3]  [4 2 4 -1 -1]  [4 2 4 0 0]        답이 다르다
[1 2 3 4]    [2 3 4 -1]     [2 3 4 0]          답이 다르다
[4 3 2 1]    [-1 -1 -1 -1]  [0 0 0 0]          답이 다르다

└ 한 번도 안 꺼내진 자리가 그대로 남는다. 감소 수열은 다섯 자리가 전부 그렇다
```

세 입력 모두 답이 갈립니다. 증가 수열에서도 마지막 한 자리는 남고, 감소 수열에서는 네 자리가
전부 남아요. **순회 뒤에 따로 뒷정리하는 코드가 없는 것은 이 초기값이 그 일을 미리 해 두었기
때문입니다.**

#### 4. 세 조각을 이어 다섯 칸을 지난다

세 조각을 하나로 이어 고정 입력에 실행하면 아홉 걸음이 나옵니다. 한 걸음이 「지금 값 읽기」나
「견주기 한 번」이나 「자리 넣기」 중 하나예요.

| 걸음 | 자리 `i` | 꼭대기 | 하는 일 | 그 결과 | 갈래 |
| --- | --- | --- | --- | --- | --- |
| T1 | 0 | 없다 | 통이 비어 바로 넣는다 | `stack` 이 자리 0 | ④ |
| T2 | 1 | 자리 0 (값 2) | 2 는 1 보다 작지 않아 멈춘다 | `stack` 이 자리 0 · 1 | ② ④ |
| T3 | 2 | 자리 1 (값 1) | 1 < 2 라 꺼낸다 | `result[1] = 2` | ② ③ |
| T4 | 2 | 자리 0 (값 2) | 2 는 2 보다 작지 않아 멈춘다 | `stack` 이 자리 0 · 2 | ② ④ |
| T5 | 3 | 자리 2 (값 2) | 2 < 4 라 꺼낸다 | `result[2] = 4` | ② ③ |
| T6 | 3 | 자리 0 (값 2) | 2 < 4 라 꺼낸다 | `result[0] = 4` | ② ③ |
| T7 | 3 | 없다 | 통이 비어 넣는다 | `stack` 이 자리 3 | ④ |
| T8 | 4 | 자리 3 (값 4) | 4 는 3 보다 작지 않아 멈춘다 | `stack` 이 자리 3 · 4 | ② ④ |

같은 아홉 걸음을 `stack` 과 `result` 의 값으로 나란히 놓으면 답이 언제 정해지는지가
확인됩니다.


**다섯 갈래가 모두 나왔습니다.** ① 은 T1 앞의 초기화, ② 는 T2·T3·T4·T5·T6·T8, ③ 은
T3·T5·T6, ④ 는 T1·T2·T4·T7·T8, ⑤ 는 T9 입니다. 값 4 하나가 T5 와 T6 에서 두 자리의 답을
한꺼번에 정한 것이 이 절차의 핵심이에요.

#### 멈춤 — 이 문제가 묻는 것은 자리 번호가 아니라 값이다

여기서 헷갈리기 쉬운 지점은 `result[top]` 에 무엇을 적는가입니다. 꺼내는 걸음에서 손에 든
것이 둘이라 — 지금 자리 `i` 와 지금 값 `nums[i]` — 어느 쪽을 적는지가 갈려요.

```text
같은 문제의 두 갈래

  다음 큰 원소       result[top] = nums[i]    T5 에서 4 를 적는다     이 글이 답하는 것
  다음 큰 원소의 자리 result[top] = i          T5 에서 3 을 적는다     자리 번호를 묻는 문제
  며칠 뒤인가        result[top] = i - top     T5 에서 1 을 적는다     기다린 칸 수를 묻는 문제
                     └ 세 문제의 코드가 이 한 줄에서만 갈린다
```

자리 번호를 적은 코드에 같은 입력들을 실행해 봅시다.

<!--proof:pause-write-index-->

```text
입력         바른 코드      자리 번호를 적은 코드
[2 1 2 4 3]  [4 2 4 -1 -1]  [3 2 3 -1 -1]          답이 다르다
[0 1 2 3]    [1 2 3 -1]     [1 2 3 -1]             답이 같다
[0 1 2 3 4]  [1 2 3 4 -1]   [1 2 3 4 -1]           답이 같다
[1 2 3 4]    [2 3 4 -1]     [1 2 3 -1]             답이 다르다

└ nums[i] = i 인 배열에서는 값과 자리 번호가 같아 답이 안 갈린다
  그런 배열만으로 시험하면 이 코드가 통과한다
```

**두 번째와 세 번째 줄이 이 멈춤을 두는 이유입니다.** `nums[i] = i` 인 배열은 값과 자리
번호가 같아 두 코드의 답이 글자 그대로 같아요. 시험 목록이 `[0 1 2 3]` 같은 배열로만
채워져 있으면 이 코드는 에러 없이 통과하고, 틀린 줄 모르는 채로 남습니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 `n` 이 0 일 때 루프가 한 번도
실행되지 않아 빈 배열이 그대로 나온다는 것 하나뿐이에요.

```ts
export function nextGreaterElement(nums: number[]): number[] {
  const n = nums.length;
  // 답이 없는 자리의 값을 미리 깔아 둔다. 순회가 끝나고 스택에 남은 자리가 이 값을 그대로 쓴다.
  const result = new Array<number>(n).fill(-1); // ① 답 없음을 초기값으로 깐다
  // 답이 아직 정해지지 않은 **자리**만 담는다. 값이 아니라 자리다 — 답을 적을 칸을 알아야 한다.
  const stack: number[] = [];

  for (let i = 0; i < n; i++) {
    const cur = nums[i] ?? 0;
    while (stack.length > 0) {
      const top = stack[stack.length - 1] ?? 0;
      // ② 꼭대기의 값이 지금 값보다 **엄격하게** 작을 때만 꺼낸다.
      if ((nums[top] ?? 0) >= cur) break;
      stack.pop();
      result[top] = cur; // ③ 꺼낸 자리의 답이 지금 값으로 정해진다
    }
    stack.push(i); // ④ 답이 아직 없는 자리로 넣는다
  }

  return result; // ⑤ 스택에 남은 자리는 ① 이 깔아 둔 -1 을 그대로 쓴다
}
```

```text
nextGreaterElement([2, 1, 2, 4, 3])   →  [4, 2, 4, -1, -1]
nextGreaterElement([5])               →  [-1]
nextGreaterElement([5, 5, 5])         →  [-1, -1, -1]
nextGreaterElement([2, 7, 3, 5, 1, 6])→  [7, -1, 5, 6, 6, -1]
```

### 알아 두면 좋은 개념 — 괄호 구조

자리 `i` 는 자기가 들어간 걸음부터 꺼내지는 걸음까지 답을 기다립니다. 그 **기다리는 구간**을
전개의 아홉 걸음에서 뽑아 나란히 놓으면 성질이 하나 확인돼요.

```text
자리   기다리기 시작   답을 받은 걸음   기다린 구간
   0   T1              T6              [T1,T6]
   1   T2              T3              [T2,T3]
   2   T4              T5              [T4,T5]
   3   T7              끝까지          [T7,T9]
   4   T8              끝까지          [T8,T9]

걸음      T1   T2   T3   T4   T5   T6   T7   T8   T9
자리 0    +========================+                          T1 에 들어가 T6 에 꺼내졌다
자리 1         +====+                                         [T2,T3] 이 [T1,T6] 안에 온전히 들어간다
자리 2                   +====+                               [T4,T5] 도 [T1,T6] 안에 온전히 들어간다
자리 3                                  +=========+           끝까지 안 꺼내졌다
자리 4                                       +====+           끝까지 안 꺼내졌다
               └ [T2,T3] 과 [T4,T5] 는 겹치는 열이 하나도 없다 — 서로 떨어져 있다
```

어느 두 구간도 **절반만 걸치지 않습니다.** 포개지거나(하나가 다른 하나 안에 들어가거나)
떨어져 있거나 둘 중 하나예요. 이런 모양을 **괄호 구조**라고 하고, 여는 괄호와 닫는 괄호가
짝을 이루는 규칙이 정확히 이것입니다.

```text
같은 구조를 괄호로 적으면 (여는 괄호가 들어간 걸음, 닫는 괄호가 꺼내진 걸음이다)

  실제로 나온 모양    0(  1(  1)  2(  2)  0)     자리 1 과 자리 2 가 자리 0 안에 온전히 들어간다
  나올 수 없는 모양   0(  1(  0)  1)             자리 0 이 자리 1 보다 먼저 닫힌다
                      └ 자리 0 을 먼저 꺼내려면 꼭대기가 자리 0 이어야 하는데,
                        자리 1 이 나중에 들어갔으므로 꼭대기는 자리 1 이다. 그래서 이 모양은 안 나온다
```

이 성질이 **나중에 넣은 것이 먼저 나오는 통**을 쓸 수 있는 근거입니다. 짝이 절반만 걸치면
가운데 것을 먼저 꺼낼 수 없어 통 하나로는 안 되고, 자리마다 따로 표를 들어야 해요.

| 같은 이름을 다시 만나는 자리 | 무엇이 구간인가 | 짝을 맞추는 것 |
| --- | --- | --- |
| 괄호 짝 맞추기 · 식 파싱 | 여는 괄호부터 닫는 괄호까지 | 스택 하나 |
| 깊이 우선 탐색의 방문 시각과 종료 시각 | 정점에 들어간 때부터 나온 때까지 | 재귀 호출 스택 |
| 이 글의 기다리는 구간 | 자리가 들어간 때부터 꺼내진 때까지 | `stack` |

깊이 우선 탐색 쪽은 이 성질을 **괄호 정리**라는 이름으로 부르고,
[`dfsTraversal`](../../graph/dfsTraversal/dfsTraversal-problem.md) 이 같은 구조를 다룹니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅시다. 어떤 문제에 이것을 쓰는지, 답과 기록을 식으로 어떻게
적는지, 무엇이 매 걸음 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **자리마다 답을 다 필요로 합니다.** 몇 자리만 궁금하면 그 자리에서 오른쪽을 차례로 읽는
  쪽이 배열 전체를 지나는 것보다 적을 수 있습니다.
- **배열이 답을 만드는 동안 바뀌지 않습니다.** 값 하나가 바뀌면 답 배열이 통째로 낡습니다.
- **답을 정하는 기준이 「한쪽 방향으로 처음 만나는, 순서가 있는 비교」입니다.** 크다·작다처럼
  두 값을 견줘 한쪽을 버릴 수 있어야 합니다.

```text
세 조건이 코드의 모양을 그대로 정한다
  자리마다 답이 필요하다   → 배열을 한 번 지나며 모든 답을 정하는 코드가 된다
  배열이 안 바뀐다         → 답을 한 벌 만들어 두고 다시 안 만든다
  견줘서 한쪽을 버린다     → 꼭대기 하나만 보고 멈출 수 있다
```

마지막 조건이 가장 자주 걸립니다. 「오른쪽에서 처음 만나는 짝수」처럼 두 값을 견주는 것이
아닌 기준이면 꼭대기에서 멈출 근거가 없어져요.

```text
기준이 견주기인가

  오른쪽에서 처음 더 큰 값       크다·작다로 한쪽을 버릴 수 있다     ← 이 절차가 된다
  오른쪽에서 처음 더 작은 값     부등호만 뒤집으면 된다              ← 이 절차가 된다
  오른쪽에서 처음 나오는 짝수    앞의 값이 뒤의 값을 못 가린다       ← 이 절차가 아니다
                                 └ 짝수는 자리마다 따로 봐야 하고, 그건 표 하나로 끝난다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "오른쪽에서 처음으로 더 큰"  "다음으로 큰"  "며칠을 기다려야"   ← 결정적인 신호다
  "왼쪽에서 가장 가까운 더 작은"  "양쪽으로 뻗을 수 있는 최대 길이"
  "각 원소에 대해 …를 구하라"                                    ← 자리마다 답이 필요하다는 뜻이다

제약에 이런 모양이 보이면
  N 이 10^5 이상이라 N² 이 못 들어간다
  값의 범위가 넓어 값을 인덱스로 못 쓴다                         ← 세는 표로는 안 된다는 뜻이다

반대로 이런 말이 보이면 해당하지 않는다
  "구간 [l, r] 에서"  "질의가 주어진다"                          ← 구간 자료구조 쪽이다
  "i 번째 값을 v 로 바꾼다"                                      ← 답 배열이 통째로 낡는다
  "창을 한 칸씩 옮기며"                                          ← 양 끝에서 넣고 빼는 통이 필요하다
```

마지막 무리가 보이면 다른 절차로 갑니다. 창이 움직이면
[`monotonicQueue`](../../../data-structures/linear/monotonicQueue/monotonicQueue.ts) ·
[`slidingWindowMaximum`](../slidingWindowMaximum/slidingWindowMaximum-problem.md) 쪽이고,
구간 질의가 붙으면
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 쪽이에요.

#### 실제로 쓰이는 곳

- **`sdsl-lite` 의 `construct_supercartesian_tree_bp`** — 구간 최솟값 질의를 상수 시간에
  답하는 자료구조를 세울 때 쓰는 함수입니다. 머리 주석이 *"Calculate the balanced parentheses
  of the Super-Cartesian tree, described in Ohlebusch and Gog (SPIRE 2009)"* 이고, 본문의
  반복이 `while (vec_stack.size() > 0 and l < vec_stack.top()) { vec_stack.pop(); ++k; }`
  입니다. **부등호 방향만 반대**예요 — 이 글은 「더 큰 값」을 찾느라 작은 것을 꺼내고, 저쪽은
  최솟값을 다루느라 큰 것을 꺼냅니다.
  ([`include/sdsl/suffix_tree_helper.hpp`](https://github.com/simongog/sdsl-lite/blob/master/include/sdsl/suffix_tree_helper.hpp),
  조회 2026-09-03)
- **CPython 의 어휘 분석기 `Parser/lexer/lexer.c`** — 들여쓰기 칸 수를 통에 쌓아 두었다가,
  줄의 들여쓰기가 꼭대기보다 작으면 꺼내면서 `DEDENT` 토큰을 냅니다. 반복이
  `while (tok->indent > 0 && col < tok->indstack[tok->indent]) { tok->pendin--; tok->indent--; }`
  이고, 주석이 `/* Dedent -- any number, must be consistent */` 로 **한 걸음에 여러 개를
  꺼낸다**는 것을 그 자리에 적어 뒀어요.
  ([`Parser/lexer/lexer.c`](https://github.com/python/cpython/blob/main/Parser/lexer/lexer.c),
  조회 2026-09-03)
- **파이썬 언어 레퍼런스 2.1.8 Indentation** — 그 통의 규칙을 명세가 직접 적어 둔 자리입니다.
  *"The numbers pushed on the stack will always be strictly increasing from bottom to top …
  If it is smaller, it must be one of the numbers occurring on the stack; all numbers on the
  stack that are larger are popped off"* — **바닥에서 꼭대기로 커진다**는 성질과 **큰 것을 전부
  꺼낸다**는 규칙이 문장으로 나와 있어요.
  ([Lexical analysis — Indentation](https://docs.python.org/3/reference/lexical_analysis.html),
  조회 2026-09-03)

```text
셋이 통에 담는 것을 나란히 두면

  이 글          답이 아직 없는 자리 번호     값이 바닥에서 꼭대기로 커지지 않는다
  sdsl-lite      아직 짝을 못 찾은 값         값이 바닥에서 꼭대기로 작아지지 않는다
  CPython        아직 안 닫힌 들여쓰기 칸 수  값이 바닥에서 꼭대기로 커진다
                 └ 셋 다 「꼭대기 하나만 보고 멈춰도 되는가」가 성립하는 순서로 담는다
```

#### 경쟁 설계와의 대조

같은 목표(자리마다 오른쪽에서 처음 만나는 더 큰 값 답하기)를 노리는 다른 절차로 **구간
최댓값 트리**가 있습니다. 마디마다 그 구간의 최댓값을 들고 있다가, `nums[i]` 보다 큰 값이 든
가장 왼쪽 잎을 위에서 내려가며 찾는 방식이에요.

```text
같은 질문에 두 설계가 답하는 방식

  단조 스택        배열을 한 번 지나며 모든 답을 한꺼번에 정한다   자리 하나만 물어도 전체를 지난다
  구간 최댓값 트리 물어본 자리마다 위에서 내려가며 찾는다          갱신이 와도 마디 몇 개만 고친다
                   └ 「몇 자리를 묻는가」와 「배열이 바뀌는가」 둘이 갈림점이다
```

같은 입력·같은 작업 목록에 두 설계를 걸고 **배열 접근 수**(읽기 + 쓰기)를 셌습니다. 배열은
`N = 1,024` 이고 `nums[i] = (7919 i) mod 1009`, 질의 `t` 번째는 자리 `(23 t) mod N` 을 묻고,
갱신 `k` 번째는 `nums[(59 k) mod N]` 를 `(31 k) mod 1009` 로 덮어씁니다. 갱신은 질의 사이에
고르게 끼웠어요. 전개가 쓰는 다섯 칸짜리 입력에서는 트리의 깊이가 셋뿐이라 두 설계의 계수가
열 몇 번짜리 상수에 묻히므로, 「아이디어 상세」 ④⑥ 과 **같은 생성식**의 1,024 칸 입력을 쓰고
질의 수와 갱신 수만 바꿉니다.

**배열이 안 바뀐다고 두면 「몇 자리를 묻는가」 하나가 순서를 정합니다.**

| 갱신 0 회 | 단조 스택 | 구간 최댓값 트리 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 질의 53 개 | 8,199 | **8,194** | 트리가 5 번 적습니다 |
| 질의 54 개 | **8,200** | 8,211 | **여기서 순서가 뒤집힙니다** |
| 질의 4,096 개 | **12,242** | 88,129 | 이쪽이 7.2 배 적습니다 |

**묻는 자리를 1,024 개로 묶어 두면 「배열이 몇 번 바뀌는가」가 순서를 다시 뒤집습니다.**

| 질의 1,024 개 | 단조 스택 | 구간 최댓값 트리 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 갱신 0 회 | **9,170** | 27,406 | 이쪽이 3.0 배 적습니다 |
| 갱신 2 회 | **25,464** | 27,470 | 2,006 번 차이로 아직 이쪽입니다 |
| 갱신 3 회 | 33,611 | **27,502** | **여기서 순서가 뒤집힙니다** |
| 갱신 1,024 회 | 8,355,655 | **59,569** | 트리가 140 배 적습니다 |

추가로 잡는 칸은 단조 스택이 **1,039** 이고 구간 최댓값 트리가 **2,048** 입니다. 이 축은 어느
비율에서도 안 갈려요 — 답 배열 1,024 칸에 스택이 가장 깊었을 때의 15 칸을 더한 것이 앞엣
것이고, 뒤엣것은 잎을 2 의 거듭제곱으로 맞춘 트리 전체입니다.

```text
경계가 그 자리인 이유

  한 벌 만들기   단조 스택 8,146 번             구간 최댓값 트리 7,165 번
                 차이 981 을 질의 쪽 이득으로 갚아야 순서가 뒤집힌다
  질의 하나      단조 스택 1                    구간 최댓값 트리 평균 19.4
                 (8,194 − 7,165) ÷ 53 = 19.4 이고 질의당 차이가 18.4 다
                 981 을 18.4 로 나누면 53.3 이고, 실측은 53 에서 54 로 넘어가는 자리다
  갱신 하나      단조 스택 8,147                구간 최댓값 트리 32
                 (25,464 − 9,170) ÷ 2 = 8,147 · (27,470 − 27,406) ÷ 2 = 32
                 질의 1,024 개에서 벌어진 차이 27,406 − 9,170 = 18,236 을 갱신당 차이 8,115 로
                 나누면 2.25 이고, 실측은 2 에서 3 으로 넘어가는 자리다
```

**이 절차가 내주는 것은 갱신 하나의 비용입니다.** 값 하나가 바뀌면 답 배열이 통째로 낡아
8,147 번을 다시 써야 하는데 트리는 32 번으로 끝나요. 그 대신 얻는 것이 자리마다 답을 다
필요로 할 때의 비용과 추가 칸이고, **자리를 54 개 이상 묻는다고 지문이 정하는 순간** 이쪽이
앞섭니다. 이 문제의 지문은 자리마다 답을 다 요구하고 갱신을 말하지 않으므로 단조 스택
쪽이지만, **갱신이 세 번만 섞여 들어와도** 이 판정은 다시 해야 합니다.

### 수식 정의와 유도

답과 **기록**을 정의합니다. 기록은 오른쪽에 자기보다 큰 값이 하나도 없는 자리예요.

$$g(i) = \min\{\, j \mid i < j < N,\ \mathit{nums}[j] > \mathit{nums}[i] \,\}$$

```text
정의를 읽는 법 (1)
  g(i) 는 조건을 만족하는 자리 중 **가장 작은** 것이다 — 「처음 만나는」이 그 뜻이다
  그런 자리가 아예 없을 수도 있고, 그때는 g(i) 가 정의되지 않는다
```

$$R[i] = \begin{cases} \mathit{nums}[g(i)] & g(i) \text{ 가 있을 때} \\ -1 & \text{없을 때} \end{cases}$$

```text
정의를 읽는 법 (2)
  R[i] 는 g(i) 자리의 값이다
  g(i) 가 없는 자리에만 -1 이 들어간다 — 값 -1 이 배열에 실제로 있어도 헷갈리지 않는다
```

$$\mathit{rec} = \{\, i \mid \mathit{nums}[j] \le \mathit{nums}[i] \ \text{ for all } j > i \,\}, \qquad S = |\mathit{rec}|$$

```text
정의를 읽는 법 (3)
  i 가 기록이라는 것은 g(i) 가 없다는 것과 같은 말이다
  S 는 기록의 개수이고, 마지막 자리는 언제나 기록이라 S ≥ 1 이다
```

정의를 코드로 그대로 옮기면 이렇게 됩니다. 식의 `R[i]` 를 코드에서는 `result` 라 적고,
기록을 가려내는 조건은 `isRecord` 라는 이름을 씁니다.

```ts
// 정의를 그대로 옮긴 조각. 정의를 확인하는 용도이고 실제 절차는 이것을 쓰지 않는다.
const isRecord = (nums: number[], i: number): boolean =>
  nums.slice(i + 1).every((v) => v <= (nums[i] ?? 0));
```

정의를 전개 입력의 다섯 자리에 그대로 넣어 봅시다.

<!--proof:records-check-->

```text
자리 i  nums[i]  오른쪽에서 처음 더 큰 값  기록인가
0             2  자리 3 의 4               아니다
1             1  자리 2 의 2               아니다
2             2  자리 3 의 4               아니다
3             4  없다                      그렇다
4             3  없다                      그렇다

└ 기록이 2 개(자리 3 · 4)이고, 순회가 끝났을 때 스택에 남은 자리도 2 개다
  꺼낸 횟수는 3 이고 N − S = 5 − 2 = 3 과 같다
```

이제 그 일치가 우연이 아님을 유도합니다. **순회가 끝난 시점의 `stack` 은 정확히 기록의
집합입니다.** 양방향으로 보입니다.

```text
(⊆)  자리 i 가 끝까지 남았다
     → 어느 걸음도 자리 i 를 못 꺼냈다
     → nums[j] > nums[i] 인 j > i 가 하나도 없다
        그런 j 가 있었다면, 걸음 j 에서 자리 i 위에 있는 자리들의 값은 nums[i] 이하라
        전부 nums[j] 보다 작아 먼저 꺼내지고, 그다음 자리 i 가 꼭대기가 되어 함께 꺼내졌다
     → 모든 j > i 에서 nums[j] ≤ nums[i] 다
     → i 는 기록이다

(⊇)  자리 i 가 기록이다
     → 모든 j > i 에서 nums[j] ≤ nums[i] 다
     → 꺼내는 조건이 한 번도 참이 안 된다
     → 자리 i 는 끝까지 남는다
```

자리는 한 번 들어가고 많아야 한 번 나오므로 **꺼낸 총횟수가 `P = N − S`** 입니다. 멈춘 걸음의
수 `B` 도 같은 방식으로 닫혀요 — 걸음 `i` 가 멈추려면 꺼내기가 끝난 뒤 꼭대기가 남아 있어야
하는데, `stack` 의 맨 아래는 언제나 `nums[0..i−1]` 의 최댓값이 있는 자리입니다.

$$P = N - S, \qquad B = \bigl|\{\, i \mid \max(\mathit{nums}[0..i-1]) \ge \mathit{nums}[i] \,\}\bigr|$$

```text
정의를 읽는 법 (4)
  B 는 「지금 값이 왼쪽 최댓값을 못 넘은 걸음」의 수다
  i = 0 은 왼쪽이 비어 있어 여기 안 들어간다. 그래서 B ≤ N − 1 이다
```

**여기부터가 본문의 값만으로는 안 나오는 자리입니다.** 파트 1 은 다섯 칸에서 `S = 2` 하나를
보였을 뿐인데, `S` 가 평균 얼마인지는 그 한 점으로 알 수 없어요. 값이 전부 다른 배열이 **어떤
순서로 와도 같은 확률**이라고 두면 두 기댓값이 닫힌 형태로 나옵니다.

$$\Pr[\,i \in \mathit{rec}\,] = \frac{1}{N-i} \;\Longrightarrow\; \mathbb{E}[S] = \sum_{i=0}^{N-1}\frac{1}{N-i} = \sum_{k=1}^{N}\frac{1}{k} = H_N$$

```text
유도를 읽는 법 (1)
  자리 i 가 기록이려면 nums[i] 가 nums[i..N-1] 의 최댓값이어야 한다
      그 구간의 칸이 N − i 개이고 어느 칸이 최댓값이든 확률이 같으니 1/(N−i) 다
```

$$\Pr[\,\text{걸음 } i \text{ 가 멈춘다}\,] = 1 - \frac{1}{i+1} \;\Longrightarrow\; \mathbb{E}[B] = N - H_N$$

```text
유도를 읽는 법 (2)
  걸음 i 가 멈추려면 nums[i] 가 nums[0..i] 의 최댓값이 아니어야 한다
      그 구간의 칸이 i + 1 개이니 최댓값일 확률이 1/(i+1) 이고, 그 나머지가 답이다
```

식이 맞는지 순열을 전수로 세어 대조합니다. 길이 `N` 인 순열 `N!` 개를 전부 만들어 기록의
개수를 평균 낸 값이에요.

<!--proof:records-average-->

```text
N  순열 전수 평균 기록 수       H_N  차이
1                1.000000  1.000000     0
2                1.500000  1.500000     0
3                1.833333  1.833333     0
4                2.083333  2.083333     0
5                2.283333  2.283333     0
6                2.450000  2.450000     0
7                2.592857  2.592857     0
8                2.717857  2.717857     0

└ 두 열이 여덟 줄에서 모두 같다. N = 100,000 이면 H_N = 12.0901 이고,
  평균 접근 8N − 5·H_N = 799,939.5 · 최악 8N − 7 = 799,993 이다
```

제약 상한을 넣으면 `H_N = 12.0901` 입니다. **10 만 칸을 지나도 끝에 남는 자리가 평균 열두
개**라는 뜻이고, 그래서 꺼낸 횟수가 평균 `100,000 − 12.09` 로 거의 `N` 입니다. 배열 접근이
`3N + 3P + 2B` 이므로 평균이 `8N − 5H_N = 799,939.5` 이고 최악 `8N − 7 = 799,993` 과 **53.5 번**
차이예요 — 이 절차는 평균과 최악이 거의 같습니다.

### 불변식 — 스택에 남은 자리는 답이 아직 없는 자리 전부다

파트 1 에서 코드가 동작하는 것을 아홉 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고 그것이
실제로 유지되는지 확인해 봅시다.

> 걸음 하나가 끝난 시점마다, `stack` 은 자리 `0` 부터 `i` 까지 중 **답이 아직 정해지지 않은
> 자리 전부**를 담고 있고, 바닥에서 꼭대기로 자리 번호가 커지며 그 자리의 값은 커지지 않습니다.
> 이미 답이 정해진 자리는 `stack` 에 없고 `result` 에 값이 적혀 있습니다.

```text
   자리 0   ●   답이 아직 없다 → stack 에 있다
   자리 1   ○   답이 정해졌다   → result 에 값이 있다
   자리 2   ●
                └ ● 만 stack 에 있고 ○ 는 없다. 두 곳에 함께 있는 자리는 생기지 않는다
```

「걸음이 끝난 시점」을 빠뜨리면 이 문장이 거짓이 됩니다. 꺼내기가 **진행 중인** 동안은 꺼낸
자리가 `stack` 에서 빠졌는데 `result` 에는 아직 안 적힌 순간이 있어요. T5 와 T6 사이가 그
자리입니다.

```text
T5 를 마친 순간과 T6 을 마친 순간

  T5 뒤   stack 이 자리 0     result 가 [-1 2 4 -1 -1]    자리 2 가 양쪽에서 정리됐다
  T6 뒤   stack 이 비었다     result 가 [4 2 4 -1 -1]     자리 0 도 정리됐다
          └ 두 걸음 사이에는 자리 0 이 stack 에서 빠졌지만 result 는 아직 -1 이다
```

**갈래마다 확인합시다.** 상태를 바꾸는 자리가 셋이고, 나머지는 상태를 안 건드립니다.

| 어느 자리를 지날 때 | 하는 일 | 성질이 유지되는 근거 |
| --- | --- | --- |
| 초기화 | `result` 를 `-1` 로 채운다 | 아직 아무 자리도 안 읽었으니 `stack` 이 비어 있고 답도 없다 |
| 꺼내기 — 꼭대기의 값이 `cur` 보다 작다 | `stack` 에서 빼고 `result` 에 적는다 | 빠진 자리가 그 걸음에서 답을 받으므로 「답이 없는 자리 전부」가 유지된다 |
| 멈춤 — 꼭대기의 값이 `cur` 이상이다 | 아무것도 안 한다 | 꼭대기의 값이 지금 값 이상이면 그 아래는 더 커서 더더욱 조건을 안 만족한다 |
| 넣기 | `stack` 에 자리 `i` 를 넣는다 | 자리 `i` 는 방금 읽혔고 답이 아직 없다. 값이 통 안에서 가장 작아 순서도 유지된다 |
| 반환 | 아무것도 안 한다 | `stack` 에 남은 자리는 답이 없는 자리이고 `-1` 이 이미 적혀 있다 |

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| `N = 1` | 넣기만 하고 순회가 끝난다 | `[-1]` |
| `N = 2` 증가 | 두 번째 걸음이 첫 자리를 꺼낸다 | `[2, -1]` |
| `N = 2` 감소 | 아무것도 안 꺼낸다 | `[-1, -1]` |
| 값이 전부 같음 | 조건이 한 번도 참이 안 된다 | `[-1, -1, -1]` |
| 감소 수열 | 위와 같은 갈래 | `[-1, -1, -1, -1]` |
| 음수만 있음 | 값의 부호는 견주기에 안 쓰인다 | `[-2, -1, -1]` |
| 최댓값이 맨 앞 | 첫 자리가 끝까지 남는다 | 첫 자리의 답이 `-1` |

마지막 줄이 「답이 `-1` 인 자리는 마지막 자리뿐」이라는 오해를 막는 자리입니다. 가장 큰 값이
어디에 있든 그 자리의 답은 `-1` 이에요.

**이제 깨뜨려 봅시다.** 성질을 지키던 줄은 꺼내는 조건의 부등호 한 줄입니다. 「같은 값도
어차피 순서상 뒤엣것이 늦게 오니 꺼내도 되지 않나」라는 생각으로 그 조건을 느슨하게 바꿔
봅니다.

```ts
if ((nums[top] ?? 0) > cur) break; // 같은 값에서 멈추지 않는다
```

<!--proof:mutant-loose-compare-->

```text
입력         바른 코드      느슨하게 꺼내는 코드
[5 5 5]      [-1 -1 -1]     [5 5 -1]              답이 다르다
[2 1 2 4 3]  [4 2 4 -1 -1]  [2 2 4 -1 -1]         답이 다르다
[1 2 3 4]    [2 3 4 -1]     [2 3 4 -1]            답이 같다
[4 3 2 1]    [-1 -1 -1 -1]  [-1 -1 -1 -1]         답이 같다

└ 같은 값이 두 번 이상 나오는 입력에서만 답이 갈린다
  값이 전부 다른 입력만으로 시험하면 이 코드가 통과한다
```

`[5 5 5]` 에서 답이 `[5 5 -1]` 이 됩니다. 5 는 5 보다 크지 않으니 답이 될 수 없는데도 적혔어요.
전개 입력에서는 자리 0 의 답이 4 대신 2 가 되는데, **자리 0 이 같은 값 2 에게 너무 일찍 꺼내져
진짜 답인 4 를 못 만난 것**입니다.

```text
바른 조건    자리 0 (값 2)  같은 값 2 에서 멈춘다      나중에 값 4 를 만나 답 4 를 받는다
느슨한 조건  자리 0 (값 2)  같은 값 2 에서 꺼내진다    답 2 로 확정되고 끝난다
             └ 불변식의 「답이 아직 없는 자리 전부」가 깨진다 — 답이 없는데 통에서 빠졌다
```

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 다섯뿐입니다 — 답 배열을 깔고, 지금 값을 읽고, 꼭대기와 맞대 보고,
답을 적고, 자리를 넣는 것. 전개의 값으로 확인하면 T1 부터 T8 까지가 그 넷을 나눠 맡고 T9 는
아무것도 안 합니다.

<!--proof:walk-cost-->

```text
갈래                       걸음               배열 접근
답 없음을 깐다 ①           —                          5
지금 값을 읽는다           T1·T2·T3·T5·T8             5
꼭대기와 맞대 본다 ②       T2·T3·T4·T5·T6·T8         12
답을 확정한다 ③            T3·T5·T6                   3
자리를 넣는다 ④            T1·T2·T4·T7·T8             5
남은 자리는 그대로 둔다 ⑤  T9                         0
합                                                   30

└ 같은 입력을 매번 오른쪽을 차례로 읽어 처리하면 19 번이다.
  다섯 칸에서는 답 배열을 까는 5 번과 자리 넣기 5 번이 전체의 3 분의 1 이라 아직 손해다
```

세는 것은 **배열 접근 전부**입니다 — 답 배열의 쓰기, `nums` 의 읽기, `stack` 의 읽기와 쓰기.
견주기 한 번이 접근 둘인 것은 꼭대기를 읽고 그 자리의 값을 또 읽기 때문이에요.

```text
갈래별로 몇 번인가
  답 배열 깔기   N 번          자리마다 한 번씩 쓴다
  지금 값 읽기   N 번          걸음마다 한 번
  견주기         2(P + B) 번   꺼낸 횟수 P 에 멈춘 걸음 B 를 더한 것이 견준 횟수다
  답 적기        P 번          꺼낼 때마다 한 번
  자리 넣기      N 번          자리마다 한 번씩 쓴다
                 └ 다 더하면 3N + 3P + 2B 다. 전개는 N=5 · P=3 · B=3 이라 15 + 9 + 6 = 30 이다
```

`P` 와 `B` 의 상한이 총식을 닫습니다. `P ≤ N − 1` 이고 `B ≤ N − 1` 이므로 접근이
`3N + 3(N−1) + 2(N−1) = 8N − 5` 아래인데, 두 상한이 **동시에** 달성되지는 않아요 — `P = N − 1`
이면 마지막 걸음이 통을 비우고 끝나므로 그 걸음은 멈춘 걸음이 아닙니다.

```text
제약 규모 N = 100,000 에서
  가장 적은 입력   P = 0 · B = N−1        3N + 2(N−1) = 5N − 2 = 499,998
  가장 많은 입력   P = N−1 · B = N−2      3N + 3(N−1) + 2(N−2) = 8N − 7 = 799,993
  평균(균등 가정)  P = N−H_N · B = N−H_N  8N − 5·H_N = 799,939.5
                   └ 1 초 제한에 견주면 여유가 크다. 루프 제어가 접근 수를 안 넘어 같은 규모다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안
돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (감소 수열 · 값이 전부 같음) | `O(N)` | `Θ(N)` — 접근 `5N − 2` |
| **평균적인 경우** (순서의 분포를 정해야 한다) | `O(N)` | 분포를 정하면 `Θ(N)` — 접근 `8N − 5H_N` |
| **최악의 경우** (아래 절이 구성하는 입력) | `O(N)` | `Θ(N)` — 접근 `8N − 7`, 실제로 도달합니다 |

세 케이스가 **경계의 종류에서는 안 갈립니다.** 셋 다 타이트하게 `Θ(N)` 이고, 갈리는 것은
상수예요 — 5 와 8 사이입니다. 이 절차에서 「최악이 느리다」는 말은 상수가 1.6 배라는 뜻이지
차수가 다르다는 뜻이 아닙니다.

```text
같은 N = 1,024 에서 상수만 갈린다 (아래 절이 잰 값이다)
  감소 수열                        5,118    한 번도 안 꺼낸다
  증가 수열                        6,141    매번 꺼내지만 한 번도 안 멈춘다
  곱셈 해시로 만든 배열            8,146    거의 매번 꺼내고 거의 매번 멈춘다
  두 번째로 큰 값이 맨 앞인 배열   8,185    꺼내기와 멈춤이 둘 다 최대다
                                   └ 가장 적은 것과 가장 많은 것의 비가 1.6 이다
```

가운데 줄이 정의되지 않는 이유를 적어 둡니다. 이 문제는 값이 **어떤 순서로 오는지 말하지
않아요.** 순서의 분포를 하나 정하면(모든 순열이 같은 확률이라고 두면) 평균이 `8N − 5H_N` 이
되지만, 그것은 문제가 준 조건이 아니라 이 글이 놓은 가정입니다.

```text
총식 = Θ(N) 시간 + Θ(N) 추가 메모리
       └ 접근 3N + 3P + 2B, 5N−2 ≤ 접근 ≤ 8N−7    └ 답 배열 N 칸 + 스택 최대 N 칸
          앞뒤로 붙는 전처리가 없다. 정렬도 좌표 압축도 안 쓴다
```

**약속으로 내놓는 것은 최악 보장 하나입니다.** 코드에 난수가 없으니 같은 배열을 두 번 넣으면
같은 횟수가 나오고, 어떤 배열을 넣어도 `8N − 7` 아래라는 것이 조건 없이 성립합니다. `8N − 5H_N`
은 그 약속의 일부가 아니라 **입력 분포를 하나 놓았을 때의 기댓값**이에요 — 구현이 만드는
무작위성이 아니라 **모든 순서가 같은 확률**이라는 가정에서 나온 값이고, 실제 입력이 그 분포를
따르지 않으면 성립하지 않습니다.

#### 최악을 만드는 입력

「정렬된 배열이면 느리다」가 이 절차에서는 절반만 맞습니다. 증가 수열은 자리마다 답을 받으니
꺼내기가 최대인데, **멈추는 걸음이 하나도 없어** 접근이 `6N − 3` 에 그쳐요. 그것을 값으로
확인해 봅시다.

<!--proof:worst-shape-->

```text
입력의 모양                                                 꺼낸 횟수 P  멈춰 선 걸음 B  남은 자리 S  3N + 3P + 2B  실측 접근
감소 수열                                                             0           1,023        1,024         5,118      5,118
전부 같은 값                                                          0           1,023        1,024         5,118      5,118
곱셈 해시                                                         1,014           1,016           10         8,146      8,146
증가 수열                                                         1,023               0            1         6,141      6,141
두 번째로 큰 값이 맨 앞 · 가운데 증가 · 가장 큰 값이 맨 뒤        1,023           1,022            1         8,185      8,185

└ 다섯째 열과 여섯째 열이 모든 줄에서 같다. N = 1,024 에서 가장 많은 것은 8,185 이고 8N − 7 과 같다
  길이 2~8 순열을 전수로 살펴 8N − 7 을 넘는 입력을 찾았고 결과는 0 개다(길이 8 의 최댓값 57 = 8·8 − 7)
```

최악은 **꺼내기와 멈춤을 동시에 최대로 만드는 입력**입니다. 두 번째로 큰 값을 맨 앞에 두면
가운데 걸음이 전부 그 값에서 멈추고, 가장 큰 값을 맨 뒤에 두면 마지막 걸음이 통을 통째로
비웁니다.

```text
N = 8 로 그 입력을 적으면  [7 0 1 2 3 4 5 8]

  걸음 1     꼭대기 7 이 0 보다 크다                꺼낼 것 없이 멈춘다
  걸음 2~6   바로 앞 자리를 꺼내고 꼭대기 7 에서 멈춘다  걸음마다 한 자리씩 다섯 자리를 꺼낸다
  걸음 7     지금 값 8 이 통 안의 두 값보다 크다     자리 6 과 자리 0 을 꺼내고 통이 빈다
             └ 꺼낸 횟수 5 + 2 = 7 = N−1 이고 멈춘 걸음 1 + 5 = 6 = N−2 다. 둘 다 상한이다
```

그러니 최악은 **값의 크기가 아니라 놓인 순서**가 만듭니다. 같은 값들을 다르게 늘어놓기만 해도
접근이 `5N − 2` 에서 `8N − 7` 까지 갈려요.

```text
왜 B 가 N−1 까지는 못 가는가

  걸음 N−1 이 멈춘다   → 꺼내기가 끝난 뒤에도 꼭대기가 남아 있다
                       → 그 자리와 자리 N−1 이 둘 다 끝까지 남아 S ≥ 2 다
                       → P = N − S ≤ N − 2 가 되어 3P 쪽에서 3 을 잃는다
                       └ 3P 로 3 을 잃고 2B 로 2 를 얻으므로 합이 줄어든다. 그래서 8N − 7 이 상한이다
```

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 답이 아직 없는 자리만 통에 담아 두고, 값이
바닥에서 꼭대기로 커지지 않게 유지했으며, 큰 값을 만나는 순간 꼭대기부터 꺼내 답을 한꺼번에
확정했습니다.

```text
  1. 답 배열을 -1 로 깔아 둔다                 답이 없는 자리가 그 값을 그대로 쓴다
  2. 왼쪽에서 오른쪽으로 자리를 하나씩 읽는다  걸음마다 값을 한 번 읽는다
  3. 꼭대기가 지금 값보다 작은 동안 꺼낸다     꺼낸 자리의 답이 지금 값이다
  4. 지금 자리를 넣는다                        N=100,000 에서 접근이 799,993 번 이하다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T6 에서 자리 0 이 꺼내지면서 답 4 를 받았어요. 그런데
자리 0 과 자리 3 사이에는 자리 1 과 자리 2 가 있고, 자리 2 의 값도 2 라 자리 0 과 **같습니다.**
자리 0 은 왜 자리 2 를 지나 자리 3 까지 기다렸을까요?

```text
T4    자리 2 를 넣기 직전   꼭대기가 자리 0 (값 2)   2 는 2 보다 작지 않아 멈췄다
T6    자리 0 을 꺼냈다      지금 값이 4              2 < 4 라 꺼냈다
      └ 사이에 있던 자리 1 과 자리 2 는 자리 0 을 못 꺼냈다
```

답이 되려면 **엄격하게 커야** 하기 때문입니다. 자리 1 의 값 1 은 2 보다 작고, 자리 2 의 값 2 는
2 와 같아요. 둘 다 「2 보다 엄격하게 크다」를 만족하지 못하므로 자리 0 의 답이 될 수 없고,
그래서 자리 0 은 `stack` 에 그대로 남아 자리 3 의 값 4 를 기다립니다.

```text
자리 0 이 만난 값   견주기            꺼내지는가
자리 1 의 1         1 > 2 가 거짓     아니다. 애초에 자리 1 이 자리 0 위에 쌓였다
자리 2 의 2         2 > 2 가 거짓     아니다. T4 에서 멈췄다
자리 3 의 4         4 > 2 가 참       그렇다. T6 에서 꺼내졌다
                    └ 같은 값이 「막지도 답이 되지도 못한다」는 것이 이 문제의 엄격한 부등호다
```
