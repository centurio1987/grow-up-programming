# longestCommonSubsequence — 마지막 두 글자만 보면 문제가 한 칸 작아지는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 공통 부분 수열 후보를 전부
만들어 보는 방법에서 표 하나를 채우는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

두 문자열 `s` 와 `t` 를 받아 **양쪽 모두의 부분 수열이 되는 문자열 중 가장 긴 것의 길이**를
돌려주는 문제예요. 부분 수열은 원래 순서를 지키며 글자를 0 개 이상 고른 것이고, 고른 자리가
연속일 필요는 없습니다.

```text
s = a b c d e        s 에서 0 2 4 번 글자를 고르면
    ^   ^   ^        "ace" 가 나온다

t = a c e            t 에서 0 1 2 번 글자를 고르면
    ^ ^ ^            같은 "ace" 가 나온다

  "ace"  양쪽 모두의 부분 수열이고 길이가 3 이다
  "ade"  s 의 부분 수열이지만 t 에는 d 가 없다
  "ec"   두 글자가 s 에서도 t 에서도 이 순서로 나오지 않는다
```

고를 수 있는 후보를 전부 만들어 보는 것으로는 끝나지 않습니다. `s` 의 길이를 `n` 이라 하면
`s` 에서 글자를 고르는 방법이 `2` 의 `n` 제곱 가지예요.

```text
후보의 개수
  s 에서 글자를 고르는 방법   글자마다 고른다/안 고른다   2^n 가지
  n = 5 이면                                              32 가지
  n = 1,000 이면                                          302 자리 수
  └ 1 초 제한 안에 다 만들어 볼 수 없다
```

여기서 **두 문자열의 마지막 글자만** 봅니다. 그 둘이 같으면 그 글자를 답에 넣는 것이 최선이고,
다르면 둘 중 한쪽의 마지막 글자는 답에 못 들어갑니다. 어느 쪽이든 문제가 한 칸 작아져요.

```text
마지막 글자를 보면

  같다     s = ...c 와 t = ...c   그 c 를 쓰고 양쪽에서 하나씩 뗀다   답 = 작아진 문제 + 1
  다르다   s = ...b 와 t = ...c   b 를 버리거나 c 를 버린다           답 = 둘 중 큰 쪽
  └ 어느 갈래든 남는 것은 두 문자열의 앞부분, 곧 접두어 한 쌍이다
```

그래서 필요한 것이 **접두어 쌍마다의 답** 하나입니다. `s` 의 앞 `i` 글자와 `t` 의 앞 `j` 글자만
놓고 본 답을 `dp[i][j]` 라 적으면, 위 두 갈래가 그대로 이웃 칸을 읽는 규칙이 돼요. `t` 의 길이는
`m` 이라 적고, 표의 `∅` 는 한 글자도 안 본 자리, 곧 빈 문자열입니다.

| | `j=0` ∅ | `j=1` a | `j=2` c | `j=3` e |
| --- | --- | --- | --- | --- |
| `i=0` ∅ | 0 | 0 | 0 | 0 |
| `i=1` a | 0 | 1 | 1 | 1 |
| `i=2` b | 0 | 1 | 1 | 1 |
| `i=3` c | 0 | 1 | 2 | 2 |
| `i=4` d | 0 | 1 | 2 | 2 |
| `i=5` e | 0 | 1 | 2 | 3 |

첫 줄과 첫 열의 `0` 은 계산해서 얻은 값이 아닙니다. 한쪽이 빈 문자열이면 공통 부분 수열도 빈
문자열뿐이라, 정의에서 바로 나오는 값이에요. 나머지 칸은 왼쪽 위·위·왼쪽 세 이웃만 읽습니다.

```text
칸 하나가 읽는 자리

  dp[i-1][j-1]  dp[i-1][j]      마지막 글자가 같으면   왼쪽 위 + 1
  dp[i][j-1]    dp[i][j]        다르면                 위와 왼쪽 중 큰 값
  └ 셋 다 이 칸보다 왼쪽이거나 위다. 그래서 왼쪽 위부터 채워 내려가면 언제나 준비돼 있다
```

칸이 `(n+1)(m+1)` 개이고 칸 하나에 드는 일이 문자 비교 한 번과 값 결정 한 번이라, 시간이
`O(nm)` 이고 표에 쓰는 칸도 `O(nm)` 입니다. 후보를 전부 만드는 것이 302 자리였던 것과 견주면
`n = m = 1,000` 에서 100 만 칸 언저리예요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **부분 수열과 부분 문자열이 다르다는 것.** 부분 수열은 고른 자리가 떨어져 있어도 되고,
  부분 문자열은 연속이어야 합니다. 이 차이 하나가 뒤에 나올 규칙을 통째로 바꿔요.
- **2 차원 배열의 칸을 첨자 둘로 찾아가는 일.** 칸 하나를 읽는 데 드는 일이 배열 크기와
  상관없다는 사실까지 필요합니다.
- **작은 문제의 답으로 큰 문제의 답을 만드는 방식.** 여기서는 「앞 `i` 글자와 앞 `j` 글자」의
  답을 모아 「앞 `i+1` 글자와 앞 `j+1` 글자」의 답을 만듭니다.
- **문자열의 첨자가 0 부터 시작한다는 것.** 표의 첨자는 1 부터 세는데 문자열은 0 부터라,
  둘을 잇는 자리에서 `1` 이 하나 어긋나기 쉽습니다.

이 글이 다루는 것은 **길이만** 구하는 문제입니다. 같은 표를 쓰되 글자를 바꾸고 넣고 지우는
비용까지 재는 문제는
[`editDistance`](../editDistance/editDistance-problem.md) 가 다루고, 한 문자열 안에서
증가하는 부분 수열을 찾는 문제는
[`longestIncreasingSubsequence`](../longestIncreasingSubsequence/longestIncreasingSubsequence-problem.md)
가 다룹니다.

```text
두 문자열의 공통 부분 수열 길이     ← 이 글이 다루는 것
두 문자열을 같게 만드는 최소 비용   ← 다른 글이 다루는 것
한 문자열의 증가하는 부분 수열      ← 또 다른 글이 다루는 것
```

### 아이디어 상세 — 접두어 쌍이라는 상태를 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function longestCommonSubsequence(s: string, t: string): number;
```

- 입력: 두 문자열 `s` 와 `t`. 글자는 ASCII 범위이고 빈 문자열일 수 있습니다.
- 출력: `s` 와 `t` 모두의 부분 수열인 문자열 중 가장 긴 것의 **길이**. 문자열 자체가 아니라
  길이만 돌려줍니다.
- 제약: `0 ≤ n ≤ 1,000`, `0 ≤ m ≤ 1,000`. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `s` | 첫 번째 문자열 | 길이가 `n` 이다 |
| `t` | 두 번째 문자열 | 길이가 `m` 이다 |
| `n` | `s` 의 길이 | `0 ≤ n ≤ 1,000` |
| `m` | `t` 의 길이 | `0 ≤ m ≤ 1,000` |
| `i` | `s` 를 앞에서부터 몇 글자 보았는가 | `0 ≤ i ≤ n` |
| `j` | `t` 를 앞에서부터 몇 글자 보았는가 | `0 ≤ j ≤ m` |
| `dp[i][j]` | `s` 의 앞 `i` 글자와 `t` 의 앞 `j` 글자만 놓고 본 답 | 표의 칸 하나 |
| `r` | 마지막 글자가 같은 칸의 개수 — `s[i−1] = t[j−1]` 인 `(i, j)` 의 수 | `0 ≤ r ≤ nm` |

`i` 와 `j` 는 **본 글자의 개수**이지 자리 번호가 아닙니다. 그래서 칸 `(i, j)` 가 견주는 두
글자는 `s[i−1]` 과 `t[j−1]` 이에요 — 문자열의 첨자가 0 부터라 하나씩 당겨집니다.

가장 먼저 떠오르는 방법으로 시작합시다. 답이 `s` 의 부분 수열이니, `s` 의 부분 수열을 전부
만들어 각각이 `t` 의 부분 수열인지 확인하고 가장 긴 것을 고르는 것이에요.

```ts
let best = 0;
for (let mask = 0; mask < 1 << s.length; mask++) {
  const w = [...s].filter((_, k) => (mask >> k) & 1).join("");  // 후보 하나
  let at = 0;
  for (const ch of t) if (at < w.length && w[at] === ch) at++;   // t 를 한 번 읽는다
  if (at === w.length && w.length > best) best = w.length;
}
```

이 방법이 하는 일의 양은 **후보의 개수**입니다. 후보가 `2` 의 `n` 제곱 개이고 후보 하나마다
`t` 를 한 번씩 읽어요.

<!--proof:costEnumerate-->

```text
s        t      만든 후보 수  읽은 t 의 글자 수  기본 연산 합
"abc"    "ace"             8                 24            32
"abcd"   "ace"            16                 48            64
"abcde"  "ace"            32                 96           128

제약 규모 |s| = |t| = 1,000 이면
  만든 후보 수  302 자리
  기본 연산 합  305 자리
  └ 후보 하나마다 t 를 한 번씩 읽으므로 기본 연산은 후보 수에 1,001 을 곱한 값이다
  └ 후보 수가 s 의 길이를 지수로 올린다. 1 초 안에 다 만들어 볼 수 없다
```

302 자리입니다. 제약이 1,000 인데 이 방법으로는 우주가 끝나도 못 끝냅니다. 그러면 이 안에서
무엇이 되풀이되는지 봅시다.

지문의 정의를 재귀로 옮기면 후보를 만드는 대신 **마지막 글자만 보고 문제를 줄이는** 형태가
됩니다. 앞에서 본 두 갈래 그대로예요.

```ts
function f(i: number, j: number): number {
  if (i === 0 || j === 0) return 0;
  if (s[i - 1] === t[j - 1]) return f(i - 1, j - 1) + 1;
  return Math.max(f(i - 1, j), f(i, j - 1));
}
```

이제 **길이는 같고 글자만 다른 두 입력**에 이 재귀를 걸고, 한 번 낸 값을 적어 두는 방식과
나란히 세어 봅시다. 왼쪽은 기억 없이 그대로 다시 부르는 방식이고, 오른쪽은 칸에 적어 두는
방식이에요.

<!--proof:costTwoWays-->

```text
입력                          두 길이  기억 없이 부른 횟수  표에서 채운 칸
"abcde" 와 "ace"              5 x 3                     15              15
"abcde" 와 "vwx"              5 x 3                    111              15
"abcdefghij" 와 "klmnopqrst"  10 x 10              369,511             100

└ 첫 두 줄은 길이가 같고 글자만 다른데 왼쪽 열이 7.4 배로 갈린다
└ 오른쪽 열은 글자를 안 보고 두 길이의 곱으로 정해진다
```

같은 `5 x 3` 인데 왼쪽 열이 15 와 111 로 갈립니다. 마지막 글자가 같으면 재귀가 한 갈래로만
내려가고, 다르면 두 갈래로 벌어지기 때문이에요. 여기서 관찰할 것은 그 하나입니다 — **오른쪽
열은 글자를 아예 안 보고 두 길이의 곱으로 정해집니다.**

| 방식 | 하는 일의 양 | 무엇을 따라가는가 |
| --- | --- | --- |
| 기억 없이 다시 부르기 | 갈래가 벌어지는 만큼 | 글자가 겹치는 정도를 따라간다 |
| 칸에 적어 두기 | 두 길이의 곱 | 글자와 상관없이 같다 |

그 관찰을 개념으로 세우기 전에, 더 단순한 후보부터 확인합시다. 「양쪽에 다 있는 글자를 세어
겹치는 만큼 더하면 그것이 답이다」가 그것이에요.

<!--proof:costFrequency-->

```text
입력                        정본이 낸 답  겹치는 글자 개수  판정
전개 입력 "abcde" 와 "ace"             3                 3  같다
"ab" 와 "ba"                           1                 2  틀리다
"cab" 와 "abc"                         2                 3  틀리다
"abc" 와 "cba"                         1                 3  틀리다

└ 양쪽에 다 있는 글자라도 나오는 순서가 반대면 함께 고를 수 없다. 그 자리에서 값이 커진다
```

이 후보가 어긋나는 이유는 하나입니다. 부분 수열은 **고른 글자들이 양쪽에서 같은 순서로**
나와야 하는데, 개수만 세면 그 순서를 아예 안 봐요.

```text
s = "ab" 와 t = "ba" 에서 두 방식이 갈리는 자리
  개수만 센다   a 도 b 도 양쪽에 하나씩 있다        2
  순서를 본다   "ab" 는 t 에서 순서가 반대다        a 나 b 중 하나만 쓸 수 있다
                "ba" 는 s 에서 순서가 반대다
  └ 순서를 지켜 고를 수 있는 것은 한 글자뿐이라 1 이 맞다
```

그러니 **어느 글자를 골랐는지가 아니라 어디까지 보았는지**를 들고 가야 합니다. 여기서 진짜
개념이 나와요. 두 문자열을 각각 앞에서부터 몇 글자 보았는지, 그 **접두어 쌍 `(i, j)`** 하나가
상태입니다.

```text
접두어 쌍 (i, j) 가 정하는 것

  i    s 를 앞에서부터 i 글자 보았다   i 는 0 부터 n 까지   n+1 가지
  j    t 를 앞에서부터 j 글자 보았다   j 는 0 부터 m 까지   m+1 가지
  상태 수                              (n+1)(m+1) 가지
  └ 어떤 경로로 여기까지 왔는지는 상태에 안 들어간다. 앞으로 할 수 있는 일이 같기 때문이다
```

이 상태를 전개 입력 `s = "abcde"` · `t = "ace"` 에 걸음마다 적용해 봅시다. 상태 `(5, 3)` 에서
시작해 마지막 글자를 견주며 한 칸씩 작아지는 자리를 값으로 따라가면 이렇게 나와요.

| 걸음 | 상태 `(i, j)` | 견주는 두 글자 | 어느 갈래 | 다음 상태 | 지금까지 모은 글자 |
| --- | --- | --- | --- | --- | --- |
| 1 | `(5, 3)` | `s[4]='e'` · `t[2]='e'` | 같다 | `(4, 2)` | `e` |
| 2 | `(4, 2)` | `s[3]='d'` · `t[1]='c'` | 다르다 | `(3, 2)` | `e` |
| 3 | `(3, 2)` | `s[2]='c'` · `t[1]='c'` | 같다 | `(2, 1)` | `ce` |
| 4 | `(2, 1)` | `s[1]='b'` · `t[0]='a'` | 다르다 | `(1, 1)` | `ce` |
| 5 | `(1, 1)` | `s[0]='a'` · `t[0]='a'` | 같다 | `(0, 0)` | `ace` |
| 6 | `(0, 0)` | 한쪽이 비었다 | 끝 | — | `ace` — 길이 3 |

2 번 걸음의 「다르다」에서 `(3, 2)` 를 고른 것은 두 갈래 `(3, 2)` 와 `(4, 1)` 중 값이 큰 쪽이기
때문입니다. 걸음마다 상태의 두 수 중 적어도 하나가 줄어드니, 어떤 경로를 따라가도 `(0, 0)` 에
닫혀요.

```text
상태의 이동 범위
  같은 갈래   i 가 1 줄고 j 도 1 준다         대각선으로 한 칸
  다른 갈래   i 나 j 중 하나만 1 준다         위로 한 칸 또는 왼쪽으로 한 칸
  걸음 수     i + j 가 매번 최소 1 줄어든다   많아야 n + m 걸음
  └ 그래서 상태 (n+1)(m+1) 개를 한 번씩만 채우면 전부가 나온다
```

**쉬운 경우와 불안한 경우를 나눠서 값으로 확인합시다.** 쉬운 경우는 이미 채운 줄이 위에 있을
때예요. 세 이웃이 전부 준비돼 있어 읽기만 하면 됩니다.

```text
이미 채운 줄이 있는 자리 — 칸 (3, 2)
  왼쪽 위 dp[2][1] = 1   앞 줄에서 채웠다
  위      dp[2][2] = 1   앞 줄에서 채웠다
  왼쪽    dp[3][1] = 1   같은 줄에서 방금 채웠다
  마지막 글자가 'c' 로 같으니 왼쪽 위 1 에 1 을 더해 2 다
```

불안한 경우는 **처음 채우는 줄**입니다. 위에 아무 줄도 없고 왼쪽에도 아무 칸이 없는 자리라,
읽을 이웃이 없어 보이는 자리예요.

```text
처음 채우는 줄 — 칸 (1, 1)
  왼쪽 위 dp[0][0]   s 도 t 도 0 글자다      정의에서 0
  위      dp[0][1]   s 가 0 글자다           정의에서 0
  왼쪽    dp[1][0]   t 가 0 글자다           정의에서 0
  └ 0 번째 줄과 0 번째 열을 표 안에 실제 칸으로 두면 이 자리에 특별한 분기가 안 생긴다
```

그래서 빈 문자열 자리를 표 밖으로 빼지 않고 **줄 하나와 열 하나로 실제로 깔아** 둡니다. 그러면
`i = 1` 이든 `i = 500` 이든 읽는 규칙이 글자 그대로 같아져요.

```text
0 번째 줄과 열을 깔아 두면
  칸 (1, 1)     dp[0][0] 과 dp[0][1] 과 dp[1][0] 을 읽는다   전부 0
  칸 (500, 7)   dp[499][6] 과 dp[499][7] 과 dp[500][6]       앞에서 채운 값
  └ 두 자리에서 코드가 같다. 빈 입력을 위한 분기가 따로 없다
```

빠뜨리는 칸이 없다는 것은 루프의 종료 조건으로 말할 수 있습니다. 바깥 루프가 `i` 를 `1` 부터
`n` 까지, 안쪽 루프가 `j` 를 `1` 부터 `m` 까지 올리며 칸 하나를 **정확히 한 번씩** 정해요.

```text
두 루프가 끝난 시점
  정해진 칸   dp[1][1] 부터 dp[n][m] 까지   nm 개, 각각 정확히 한 번
  안 정한 칸  0 번째 줄과 0 번째 열         정의에서 이미 0 이다
  └ 답이 되는 dp[n][m] 은 마지막에 정해지는 칸이다
```

이제 「상태를 접두어 쌍으로」가 정말 필요한지 값으로 확인합니다. 무엇을 상태로 잡는지를 네
가지로 두고 같은 입력 다섯에 실행했어요.

### 수행으로 알아보는 알고리즘 — 표 여섯 줄을 채워 답 하나를 읽는다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각
마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const s = "abcde";
const t = "ace";
// 이 절이 끝나면 3 이 나와야 한다
```

왜 하필 이 둘일까요? 마지막 글자가 같은 칸과 다른 칸이 둘 다 여러 번 나오고, `t` 에 아예 없는
글자 `b` 와 `d` 가 있어 **줄 전체가 윗줄을 그대로 이어받는 경우**까지 실행되기 때문이에요.
답 3 이 오른쪽 아래 칸에서 만들어지는 것도 이 입력에서 확인됩니다.

```text
절차 전체를 한 장으로

  T1       (n+1) x (m+1) 짜리 표를 깔고 전부 0 으로 둔다   ① 표 깔기
           i 를 1 부터 n 까지:
  T2~T6      j 를 1 부터 m 까지:                           ② 채울 칸이 남았는가
               마지막 글자가 같으면 왼쪽 위 + 1            ③ 같다
               다르면 위와 왼쪽 중 큰 값                   ④ 다르다
  T7       dp[n][m] 을 돌려준다
```

#### 1. 표를 깔고 테두리를 0 으로 둔다

첫 조각은 준비입니다. 줄을 `n + 1` 개, 열을 `m + 1` 개로 잡고 전부 `0` 으로 채우며, 아직
루프에는 들어가지 않아요.

```ts
const n = s.length;
const m = t.length;
const dp: number[][] = Array.from({ length: n + 1 }, () =>
  new Array<number>(m + 1).fill(0),   // ① 표 깔기
);
```

`①` 에서 `+1` 이 둘인 것이 이 조각의 요점입니다 — 0 번째 줄은 「`s` 를 한 글자도 안 봤다」이고
0 번째 열은 「`t` 를 한 글자도 안 봤다」예요. 둘 다 답이 `0` 이라 `fill(0)` 하나가 그 값까지
함께 깝니다.

```text
T1 이 끝난 시점 — 줄 6 개 · 열 4 개
  0 번째 줄   값 0 0 0 0       s 가 빈 문자열인 자리다
  0 번째 열   값 0 0 0 0 0 0   t 가 빈 문자열인 자리다
  나머지 칸   값 0             아직 안 채운 칸이고, 값이 0 인 것은 우연이다
  └ 테두리의 0 은 정의에서 나온 값이고, 안쪽의 0 은 곧 덮어쓴다
```

#### 2. 칸 하나를 두 갈래로 정한다

둘째 조각은 칸 하나를 정하는 규칙입니다. 두 루프로 칸을 왼쪽 위부터 차례로 채워 내려가고, 칸마다
마지막 글자를 견주어 갈래를 고릅니다.

```ts
for (let i = 1; i <= n; i++) {
  const prev = dp[i - 1] as number[];   // 윗줄 — s 의 앞 i-1 글자까지만 본 층
  const cur = dp[i] as number[];        // 이번 줄 — s 의 앞 i 글자까지 본 층

  for (let j = 1; j <= m; j++) {                                  // ② 채울 칸이 남았는가
    if (s[i - 1] === t[j - 1]) {
      cur[j] = (prev[j - 1] as number) + 1;                       // ③ 같다
    } else {
      cur[j] = Math.max(prev[j] as number, cur[j - 1] as number); // ④ 다르다
    }
  }
}
```

`prev` 와 `cur` 에 이름을 붙여 두는 것은 편의가 아닙니다. **`③` 이 읽는 왼쪽 위 칸이 반드시
윗줄이라는 것**이 같은 글자를 두 번 쓰지 않게 막는 자리이고, 첨자로 적으면 그 규칙이 `i - 1`
이라는 수 뒤에 숨어요.

앞 세 줄만 실행하면 이렇게 나옵니다. `②` 는 `j` 가 `1` 부터 `3` 까지일 때 참이고 `4` 에서 처음
거짓이 됩니다.

| 걸음 | 줄 | `s` 의 글자 | `j=0` | `j=1` a | `j=2` c | `j=3` e | 갈래 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T2 | `i=1` | a | 0 | 1 | 1 | 1 | `③④④` |
| T3 | `i=2` | b | 0 | 1 | 1 | 1 | `④④④` |
| T4 | `i=3` | c | 0 | 1 | 2 | 2 | `④③④` |

T4 가 이 세 줄의 핵심입니다. `j=2` 에서 `'c'` 가 같아 왼쪽 위 `dp[2][1] = 1` 에 1 을 더해 2 가
되고, 그 2 가 `④` 를 통해 오른쪽으로 이어져요.

```text
T4 의 j=2 가 하는 일
  견주는 두 글자   s[2] = 'c' 와 t[1] = 'c'   같다 — ③ 이다
  읽는 칸          dp[2][1] = 1               왼쪽 위, 곧 윗줄의 왼쪽 칸이다
  적는 값          1 + 1 = 2                  이 표에서 2 가 처음 나오는 자리다
  └ 윗줄에서 읽으므로 'c' 를 두 번 세는 일이 없다
```

#### 짚고 가기 — 불일치 칸에 0 을 적으면 다른 문제를 푼다

여기서 헷갈리기 쉬운 포인트는 `④` 입니다. 「글자가 다르면 이어지던 것이 끊긴 것이니 그 칸에
0 을 적어야 하지 않나」로 읽기 쉬워요. 그 생각대로 한 줄만 바꿔 봅시다.

```ts
cur[j] = s[i - 1] === t[j - 1] ? (prev[j - 1] as number) + 1 : 0;   // 다르면 0 을 적는다
```

네 입력으로 확인해 봅니다. 오른쪽 아래 칸과 표 전체의 최댓값을 함께 적었어요.

#### 짚고 가기 — 마지막 글자가 같은 칸에서 후보 셋을 다 봐도 답이 안 갈린다

여기서 헷갈리기 쉬운 포인트는 `③` 입니다. 「같다고 무조건 왼쪽 위를 쓰면, 위나 왼쪽이 더 큰
경우를 놓치지 않나」로 읽기 쉬워요. 그 생각대로 한 줄만 바꿔 봅시다.

```ts
cur[j] = Math.max(
  (prev[j - 1] as number) + 1,   // 왼쪽 위 + 1
  prev[j] as number,             // 위
  cur[j - 1] as number,          // 왼쪽
);
```

└ 셋 다 대각선 + 1 이 나머지 둘보다 작지 않다. 그래서 답이 안 갈리고, 비교만 두 번씩 늘어난다

**답이 한 번도 안 갈립니다.** 그러니 이 자리는 「틀린 코드」가 아니라 「필요 없는 코드」예요.
왜 필요 없는지에 근거가 있습니다.

```text
왼쪽 위 + 1 이 나머지 둘보다 작을 수 없는 이유
  위 칸        dp[i-1][j]     s 를 한 글자 덜 본 답이다
  왼쪽 위      dp[i-1][j-1]   거기서 t 도 한 글자 덜 본 답이다
  두 값의 차   많아야 1       글자를 하나 더 줬다고 답이 둘 늘 수는 없다
  결론         왼쪽 위 + 1    dp[i-1][j] 도 dp[i][j-1] 도 이 값을 넘지 못한다
```

이 성질을 쓰지 않고 후보 셋을 다 보면 답은 같고 비교만 칸마다 두 번씩 늘어납니다. 그리고 「같은
글자는 반드시 쓴다」라는 사실이 코드에서 사라져, 읽는 사람이 그것을 다시 확인해야 해요.

#### 짚고 가기 — 줄 하나로 줄일 때 왼쪽 칸과 왼쪽 위 칸은 서로 다른 값이다

표를 다 채우고 나면 마지막 칸만 쓰니, 줄 하나만 유지하면 될 것 같지 않나요? 실제로 줄일 수
있습니다. **다만 왼쪽 위 칸을 왼쪽 칸으로 대신하면 안 돼요.**

```ts
const dp = new Array<number>(m + 1).fill(0);
for (let i = 1; i <= n; i++) {
  for (let j = 1; j <= m; j++) {
    dp[j] =
      s[i - 1] === t[j - 1]
        ? (dp[j - 1] as number) + 1              // 왼쪽 칸을 왼쪽 위 대신 썼다
        : Math.max(dp[j] as number, dp[j - 1] as number);
  }
}
```

고치는 방법은 덮어쓰기 **직전에** 그 칸의 값을 따로 챙겨 두는 것입니다. 위 표의 넷째 열이 그렇게
고친 사본의 답이고, 다섯 줄 다 정본과 같아요.

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 오른쪽 아래 칸을 돌려주는
마지막 한 줄뿐이에요 — 한쪽이 빈 문자열이면 루프가 한 번도 실행되지 않아 `dp[0][0]` 인 `0` 이
그대로 답이 됩니다.

```ts
export function longestCommonSubsequence(s: string, t: string): number {
  const n = s.length;
  const m = t.length;

  // ① 표를 (n+1) × (m+1) 로 깔고 전부 0 으로 둔다. 0 번째 줄과 0 번째 열은 한쪽이 빈
  //    문자열인 자리라, 그 0 이 계산 결과가 아니라 정의에서 바로 나온 값이다.
  const dp: number[][] = Array.from({ length: n + 1 }, () =>
    new Array<number>(m + 1).fill(0),
  );

  for (let i = 1; i <= n; i++) {
    const prev = dp[i - 1] as number[]; // 윗줄 — s 의 앞 i-1 글자까지만 본 층
    const cur = dp[i] as number[]; // 이번 줄 — s 의 앞 i 글자까지 본 층

    for (let j = 1; j <= m; j++) {
      // ② 채울 칸이 남았는가 — 남아 있으면 아래 두 갈래 중 하나로 이 칸을 정한다.
      if (s[i - 1] === t[j - 1]) {
        // ③ 마지막 글자가 같다 — 그 글자를 쓰고, 남은 것은 대각선 칸의 답이다.
        cur[j] = (prev[j - 1] as number) + 1;
      } else {
        // ④ 마지막 글자가 다르다 — 한쪽의 마지막 글자를 버린 두 답 중 큰 쪽을 이어받는다.
        cur[j] = Math.max(prev[j] as number, cur[j - 1] as number);
      }
    }
  }

  return (dp[n] as number[])[m] as number;
}
```

```text
longestCommonSubsequence("abcde", "ace")      → 3
longestCommonSubsequence("AGGTAB", "GXTXAYB") → 4
longestCommonSubsequence("abc", "def")        → 0
longestCommonSubsequence("", "abc")           → 0
longestCommonSubsequence("a", "a")            → 1
```

### 알아 두면 좋은 개념 — 중복 부분 문제

기억 없이 부르는 재귀가 111 번이었던 것과 표의 칸이 15 개였던 것 사이에는 이름이 붙은 차이가
있습니다. 서로 다른 갈래가 **같은 상태에 다시 도착하는 것**을 중복 부분 문제라고 불러요.

```text
f(2,2) 를 펼치면 — s = "abcde" 와 t = "ace"

  f(2,2)         s[1]='b' 와 t[1]='c' 가 다르다
    f(1,2)       s[0]='a' 와 t[1]='c' 가 다르다
      f(0,2)     0
      f(1,1)     s[0]='a' 와 t[0]='a' 가 같다
    f(2,1)       s[1]='b' 와 t[0]='a' 가 다르다
      f(1,1)     같은 상태를 두 번째로 부른다
      f(2,0)     0
  └ f(1,1) 이 서로 다른 두 갈래에서 각각 처음부터 다시 계산된다
```

같은 상태가 다시 나온다는 것은 **그 값을 한 번만 내고 적어 두면 된다**는 뜻입니다. 그래서 갈래의
수가 아니라 상태의 수가 비용이 돼요.

| 공통 글자가 없는 입력 | 갈래의 수 | 상태의 수 |
| --- | --- | --- |
| `s = "abcde"` · `t = "vwx"` | 111 번 부른다 | 24 칸 |
| 길이가 둘 다 1,000 | 601 자리 | 1,002,001 칸 |
| 무엇이 정하는가 | 글자가 겹치는 정도 | 두 길이의 곱 |

같은 이름을 다른 자리에서도 만납니다. 물건을 담을지 말지 고르는 문제에서 「몇 번째 물건까지
보았는가와 남은 용량」이 같으면 앞으로 할 수 있는 일이 같고, 금액을 만드는 방법을 세는 문제에서
「몇 번째 동전까지 보았는가와 남은 금액」이 같으면 그 뒤가 같아요.

```text
같은 모양이 나오는 다른 자리
  0/1 배낭         몇 번째 물건까지 보았는가와 남은 용량
  동전 조합 세기   몇 번째 동전까지 보았는가와 남은 금액
  편집 거리        s 를 앞에서 몇 글자, t 를 앞에서 몇 글자 보았는가
  └ 셋 다 「어떤 경로로 왔는지는 앞으로에 영향이 없다」가 성립하고, 그래서 표가 만들어진다
```

**상태를 무엇으로 잡느냐가 곧 이 성질을 만드는 일입니다.** 「고른 글자 목록까지」를 상태에 넣으면
같은 상태에 다시 도착하는 일이 거의 없어져 칸이 302 자리가 되고, 「글자 개수만」으로 줄이면
같은 상태에 도착하는 것들이 앞으로 할 수 있는 일까지 같지는 않아서 답이 어긋납니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 규칙을 식으로 어떻게 세우는지,
무엇이 매 칸 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **두 수열을 앞에서부터 한 글자씩 맞춰 가고, 순서를 지켜야 합니다.** 순서를 안 지켜도 되면
  글자 개수만 세면 되고 이 절차가 필요 없어요.
- **마지막 한 자리를 보는 것만으로 갈래가 유한하게 갈립니다.** 여기서는 같다·다르다 둘이고,
  그래서 칸 하나가 이웃 셋만 읽습니다.
- **두 길이의 곱이 감당할 만합니다.** `nm` 이 100 만이면 되지만 `10^9` 이면 표를 못 깝니다.
- 답이 **한 번** 필요합니다. 문자열이 바뀌면 표를 처음부터 다시 채워야 해요.

```text
네 조건이 코드의 모양을 그대로 정한다
  순서를 지켜야 한다          → 상태가 접두어 쌍이다
  갈래가 둘이다               → 칸 하나가 이웃 셋만 읽는다
  두 길이의 곱이 감당된다     → 표를 통째로 깔 수 있다
  답이 한 번 필요하다         → 표를 한 번 채우고 끝난다
```

세 번째 줄이 이 절차의 경계입니다. 글자가 아니라 파일의 줄을 견주는 경우처럼 두 길이가 수십만이
되면 `nm` 이 `10^10` 을 넘어, 표를 통째로 채우는 방식 자체가 성립하지 않아요.

```text
두 길이의 곱이 정하는 것
  n = m = 1,000        칸 1,002,001            표를 깐다
  n = m = 100,000      칸 10,000,200,001       칸 하나가 4 바이트여도 40 GB 다
  └ 앞은 이 글의 절차, 뒤는 다른 절차를 찾아야 하는 자리다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "부분 수열"  "순서를 유지한 채 골라"  "연속일 필요는 없다"   ← 순서 제약이 있는 고르기다
  "두 문자열의 공통"  "둘 다에 나타나는"                       ← 상태가 접두어 쌍이다
  "가장 긴"  "최대 개수"                                       ← 칸에 적는 값이 길이다
  "유사도"  "두 서열을 비교"                                   ← 같은 표의 확장이다

제약에 이런 모양이 보이면
  두 길이가 1,000 언저리라 곱이 100 만이다
  두 길이의 곱은 감당되는데 각각의 지수는 감당이 안 된다

반대로 이런 말이 보이면 해당하지 않는다
  "연속된"  "부분 문자열"                      ← 불일치에서 값을 이어받으면 안 된다
  "두 길이가 10^5 이다"                        ← 표를 통째로 깔 수 없다
  "질의가 여러 번"  "문자열이 중간에 바뀐다"   ← 표를 매번 다시 채워야 한다
```

첫 무리와 마지막 무리를 가르는 것이 「연속」 한 단어입니다. 연속을 요구하면
[`editDistance`](../editDistance/editDistance-problem.md) 쪽의 격자 표가 아니라 불일치 칸에 0 을
적는 표가 되고, 답도 오른쪽 아래가 아니라 표 전체의 최댓값이에요.

#### 실제로 쓰이는 곳

- **UNIX `diff` — 두 파일의 줄을 견주는 표준 도구.** 이 도구를 만든 사람들이 쓴 기술 보고서가
  *"The central algorithm of diff solves the 'longest common subsequence problem' to find the
  lines that do not change between files."* 라고 적었습니다. 같은 보고서 1 절이 이 글의 표와
  같은 규칙을 그대로 세워요 — 한쪽이 비면 0, 두 줄이 같으면 대각선에 1 을 더하고, 다르면 위와
  왼쪽 중 큰 값입니다. 이어서 *"the dynamic program is O(mn) in time,
  and—even worse—O(mn) in space"* 라 적고 그 다음 절부터 이 비용을 줄이는 방법으로 넘어갑니다. **그 보고서는
  첫째 파일의 줄 수를 `m`, 둘째를 `n` 이라 부르는데 이 글과 반대입니다.**
  ([Hunt · McIlroy, "An Algorithm for Differential File Comparison", Bell Laboratories
  Computing Science Technical Report #41, 1976](https://www.cs.dartmouth.edu/~doug/diff.pdf),
  조회 2026-08-30)

- **EMBOSS `needle` — 두 생물 서열의 전역 정렬 도구.** 문서가 *"Needleman-Wunsch global
  alignment of two sequences"* 를 *"uses a dynamic programming method to ensure the alignment is
  optimum"* 로 설명하고, 비용을 *"in the order of mn steps, where n and m are the sequence
  lengths"* 로 적습니다. 같은 격자 표를 채우되 칸에 적는 값이 길이가 아니라 **점수**이고, 글자가
  다를 때와 빈자리를 넣을 때의 벌점이 따로 있어요.
  ([EMBOSS 6.6 `needle` 문서](https://emboss.sourceforge.net/apps/release/6.6/emboss/apps/needle.html),
  조회 2026-08-30)

```text
같은 표가 무엇을 세느냐에 따라
  공통 부분 수열 길이   같으면 +1, 다르면 이어받기           이 글의 절차
  편집 거리             바꾸기와 넣기와 지우기에 각각 비용   두 문자열을 같게 만드는 최소 비용
  전역 정렬 점수        일치 점수와 빈자리 벌점              EMBOSS needle
  └ 칸이 읽는 이웃 셋은 그대로이고, 칸에 적는 값의 뜻만 바뀐다
```

**지금의 `git diff` 는 이 표를 통째로 채우지 않습니다.** 기본 알고리즘이 `myers` 이고
([`git diff` 문서](https://git-scm.com/docs/git-diff), 조회 2026-08-30), 그 구현인
`xdiff/xdiffi.c` 가 *"An O(ND) Difference Algorithm and its Variations, by Eugene Myers"* 를
근거로 적어 둡니다
([git 저장소](https://github.com/git/git/blob/master/xdiff/xdiffi.c), 조회 2026-08-30).

#### 경쟁 설계와의 대조

같은 목표(두 문자열의 공통 부분 수열 길이를 아는 것)를 노리는 다른 절차로 **일치 쌍
따라가기**가 있습니다. 위 `diff` 보고서가 *"The diff algorithm improves on the simple dynamic
program by attending only to essential matches"* 라 적은 바로 그 방식이에요. 표를 깔지 않고
**마지막 글자가 같은 칸만** 방문하며, 자리 하나를 넣을 때마다 이분 탐색으로 그 자리가 만드는
길이를 찾습니다.

```text
두 설계가 하는 일
  표 채우기          nm 칸을 전부 방문한다. 글자가 겹치든 말든 방문 수가 같다
  일치 쌍 따라가기   글자가 같은 칸 r 개만 방문하고, 하나마다 이분 탐색을 한다
  └ r 이 작으면 뒤쪽이 적고, r 이 nm 에 가까우면 이분 탐색만큼 더 든다
```

같은 생성식·같은 길이의 입력에 두 설계를 걸고 **기본 연산 수**(문자 비교 · 값 비교 · 덧셈)를
셌습니다. 두 문자열의 길이는 둘 다 200 이고, 알파벳 크기 `A` 를 바꿔 가며 `s[k]` 를 문자 코드
`48 + (37k mod A)`, `t[k]` 를 `48 + ((53k + 11) mod A)` 로 만들었어요(`k` 는 0 부터 199 까지의
자리 번호입니다). **전개 입력을 그대로
쓰지 않은 이유**는 `"abcde"` 와 `"ace"` 에서는 표가 15 칸뿐이라 두 설계의 계수가 준비 비용에
묻히기 때문입니다.

| 알파벳 크기 `A` | 마지막 글자가 같은 칸 `r` | 표 채우기 | 일치 쌍 따라가기 | 어느 쪽이 적은가 |
| --- | --- | --- | --- | --- |
| 2 | 20,000 | **80,000** | 145,687 | 표 쪽이 1.8 배 적습니다 |
| 3 | 13,333 | **80,000** | 95,193 | 표 쪽이 1.2 배 적습니다 |
| 4 | 10,000 | 80,000 | **73,051** | **여기서 순서가 뒤집힙니다** |
| 8 | 5,000 | 80,000 | **36,703** | 일치 쌍 쪽이 2.2 배 적습니다 |
| 26 | 1,538 | 80,000 | **9,428** | 일치 쌍 쪽이 8.5 배 적습니다 |
| 64 | 626 | 80,000 | **3,872** | 일치 쌍 쪽이 20.7 배 적습니다 |

**경계는 `r` 입니다.** 표 채우기는 `A` 가 무엇이든 80,000 으로 고정이고, 일치 쌍 따라가기만
`r` 을 따라 움직여요. 두 문자열이 전부 같은 글자면 `r` 이 40,000 으로 가득 차고 그때
일치 쌍 따라가기는 291,018 이 됩니다 — 표 채우기보다 3.6 배 많아요.

```text
경계가 그 자리인 이유
  표 채우기          2nm = 80,000                r 을 아예 안 본다
  일치 쌍 따라가기   r 이 커질수록 함께 커진다   r = 10,000 에 73,051 · r = 13,333 에 95,193
  둘이 같아지는 r    11,000 언저리               알파벳 4 의 10,000 과 3 의 13,333 사이다
```

**저장 칸에서는 안 갈립니다.** 표 채우기가 40,401 칸, 일치 쌍 따라가기가 401 칸으로 끝까지
일치 쌍 쪽이 적어요 — 갈리는 것은 연산 수 하나입니다.

```text
표 채우기가 내주는 것과 얻는 것
  내주는 것   저장 칸       40,401 대 401. 표를 통째로 들고 있다
  내주는 것   드문 일치     알파벳이 크면 연산 수가 20 배 넘게 많다
  얻는 것     최악 보장     입력이 무엇이든 2nm 다. 상대는 291,018 까지 커진다
  얻는 것     구현          루프 둘로 끝난다. 상대는 위치 목록·문턱 배열·이분 탐색이 필요하다
  얻는 것     확장          표가 남아 있어 고른 글자 자체를 거슬러 확인할 수 있다
```

문제가 두 길이 1,000 이하에서 답을 한 번 요구하니 이 문제에서는 표 채우기가 답입니다. 표를
통째로 깔 수 있고 어떤 입력에서도 연산 수가 `2nm` 으로 보장돼요. 같은 지문에서 **글자 종류가
많은 긴 입력이 계속 들어오는 순간** 이 판정은 다시 해야 합니다 — 알파벳 64 에서는 상대가
20.7 배 적었습니다.

### 수식 정의와 유도

기호를 먼저 정의합니다. 문자열 `x` 의 부분 수열 전체를 $\mathrm{Sub}(x)$ 라 적고, 두 접두어의
공통 부분 수열 집합과 그중 가장 긴 것의 길이를 이렇게 둡니다.

$$C(i, j) = \mathrm{Sub}(s[1..i]) \cap \mathrm{Sub}(t[1..j]), \qquad dp[i][j] = \max_{w \in C(i,j)} |w|$$

```text
정의를 말로 펴면
  Sub(x)     x 에서 0 개 이상의 글자를 원래 순서대로 골라 이어 붙인 문자열 전부
  s[1..i]    s 의 앞 i 글자. i = 0 이면 빈 문자열이다
  C(i, j)    두 접두어 모두의 부분 수열인 문자열 전부
  dp[i][j]   그중 가장 긴 것의 길이
  └ 빈 문자열은 어떤 문자열의 부분 수열이므로 C(i, j) 는 결코 비지 않는다
```

정의를 작은 값에 넣어 확인하고 갑시다.

<!--proof:mathCheck-->

```text
i  j  s 의 앞 i 글자  t 의 앞 j 글자  공통 부분 수열 전부  그중 가장 긴 것의 길이  dp[i][j]
0  0  ""              ""              ""                                        0         0
0  1  ""              "b"             ""                                        0         0
0  2  ""              "ba"            ""                                        0         0
1  0  "a"             ""              ""                                        0         0
1  1  "a"             "b"             ""                                        0         0
1  2  "a"             "ba"            "" "a"                                    1         1
2  0  "ab"            ""              ""                                        0         0
2  1  "ab"            "b"             "" "b"                                    1         1
2  2  "ab"            "ba"            "" "a" "b"                                1         1

└ 오른쪽 두 열이 아홉 줄 다 같다. 정의대로 센 값과 표의 값이 같다는 뜻이다
```

아홉 줄 전부에서 정의대로 센 값과 표의 값이 같습니다. 이제 유도합니다. 먼저 보조 성질 하나가
필요해요 — **접두어를 한 글자 늘렸을 때 답은 그대로이거나 정확히 1 늘어납니다.**

$$dp[i][j] \le dp[i-1][j] + 1, \qquad dp[i][j] \le dp[i][j-1] + 1$$

```text
왜 2 는 못 늘어나는가
  dp[i][j] 를 만든 문자열 w 를 가져온다         길이가 dp[i][j] 다
  w 에서 마지막 글자 하나를 지운다              길이가 dp[i][j] - 1 이고 여전히 양쪽의 부분 수열이다
  지운 뒤의 w 는 s 의 앞 i-1 글자에도 들어간다  s[i-1] 을 쓰는 자리가 많아야 하나였기 때문이다
  따라서 dp[i-1][j] 는 dp[i][j] - 1 이상이다    왼쪽 칸도 같은 이유로 그렇다
```

이제 마지막 두 글자를 견주어 두 경우로 가릅니다. 문자 비교의 결과가 「같다」와 「다르다」
둘뿐이라 이 둘이 경우의 전부이고 서로 겹치지 않아요.

$$dp[i][j] = \begin{cases} dp[i-1][j-1] + 1 & (s[i-1] = t[j-1]) \\ \max\bigl(dp[i-1][j],\; dp[i][j-1]\bigr) & (s[i-1] \ne t[j-1]) \end{cases}$$

```text
같은 경우의 두 방향
  하한   dp[i-1][j-1] 짜리 문자열 뒤에 같은 글자를 붙인다   dp[i][j] ≥ dp[i-1][j-1] + 1
  상한   그 글자를 안 쓰는 답은 dp[i-1][j] 나 dp[i][j-1] 을 넘지 못한다
         보조 성질에 따라 그 둘도 dp[i-1][j-1] + 1 을 넘지 못한다
  └ 두 방향이 만나 등호가 된다

다른 경우의 두 방향
  상한   두 글자가 다르니 둘을 함께 마지막으로 쓸 수 없다   한쪽은 반드시 버린다
  하한   버린 쪽의 값이 그대로 이 칸의 공통 부분 수열이다
  └ 후보가 dp[i-1][j] 와 dp[i][j-1] 둘뿐이고 둘 다 달성되므로 큰 쪽이 답이다
```

식을 그대로 옮기면 이런 조각이 됩니다. 표를 안 쓰고 정의만 따라간 형태예요.

```ts
const f = (i: number, j: number): number =>
  i === 0 || j === 0
    ? 0
    : s[i - 1] === t[j - 1]
      ? f(i - 1, j - 1) + 1
      : Math.max(f(i - 1, j), f(i, j - 1));
```

식의 `dp` 는 코드에서 `cur` 과 `prev` 두 이름으로 나뉩니다.

| 식 | 코드 | 무엇 |
| --- | --- | --- |
| `dp[i][j]` | `cur[j]` | 지금 정하는 칸 |
| `dp[i-1][j-1]` | `prev[j-1]` | 윗줄의 왼쪽 열 |
| `dp[i-1][j]` | `prev[j]` | 윗줄의 같은 열 |
| `dp[i][j-1]` | `cur[j-1]` | 같은 줄의 바로 앞 칸 |

여기서 본문의 값만으로는 안 나오는 것이 나옵니다. **위 조각을 그대로 부르면 몇 번 불리는가**를
임의의 `i`·`j` 에 대해 닫을 수 있어요. 공통 글자가 하나도 없는 두 문자열에서 호출 수를
$K(i,j)$ 라 적으면 이렇게 됩니다.

$$K(i, 0) = K(0, j) = 1, \qquad K(i, j) = 1 + K(i-1, j) + K(i, j-1)$$

```text
점화식을 작은 값에 넣어 봅니다
  K(1,1)   1 + K(0,1) + K(1,0)   = 1 + 1 + 1   = 3
  K(1,2)   1 + K(0,2) + K(1,1)   = 1 + 1 + 3   = 5
  K(2,2)   1 + K(1,2) + K(2,1)   = 1 + 5 + 5   = 11
```

이 점화식이 이항계수 $\binom{a}{b}$ 의 점화식과 같은 모양이라는 것에서 닫힌 형태가 나옵니다.
아래 그림에서는 그 이항계수를 `binom(a, b)` 로 적습니다.

$$K(i, j) = 2\binom{i+j}{i} - 1$$

```text
귀납으로 확인한다
  기저   K(i,0) = 2 * binom(i,i) - 1 = 2 * 1 - 1 = 1     K(0,j) 도 같다
  단계   1 + [2 * binom(i+j-1, i-1) - 1] + [2 * binom(i+j-1, i) - 1]
       = 2 * [binom(i+j-1, i-1) + binom(i+j-1, i)] - 1
       = 2 * binom(i+j, i) - 1                         파스칼 규칙을 한 번 쓴다
```

실측과 대조하고 제약 규모를 넣습니다.

<!--proof:mathCallCount-->

```text
i = j  부른 횟수(실측)  2 * binom(i+j, i) - 1
    1                3                      3
    2               11                     11
    3               39                     39
    4              139                    139
    5              503                    503
    6            1,847                  1,847

제약 규모 i = j = 1,000 을 두 식에 넣으면
  2 * binom(i+j, i) - 1   601 자리

```

여섯 규모에서 실측값이 닫힌 형태와 정확히 같습니다. 마지막 줄이 이 문제의 제약 규모예요 —
같은 답을 내는 데 601 자리와 1,002,001 이 갈립니다.

### 불변식 — `dp[i][j]` 는 `s` 의 앞 `i` 글자와 `t` 의 앞 `j` 글자만 놓고 본 답이다

파트 1 에서 코드가 동작하는 것을 일곱 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 칸 참으로 남는지**를 문장으로 세우고 그것이
실제로 유지되는지 확인해 봅시다.

> 안쪽 루프가 칸 `(i, j)` 를 정한 직후, `dp[i][j]` 는 `s` 의 앞 `i` 글자와 `t` 의 앞 `j` 글자
> 만 놓고 본 이 문제의 답과 같습니다.

```text
  무엇이   dp[i][j] 한 칸
  언제     그 칸을 정한 직후다. 그 전에는 fill(0) 이 깔아 둔 0 이 들어 있다
  왜       칸을 정하는 순간 세 이웃이 이미 참이어야 하기 때문이다
```

「언제」를 빠뜨리면 안 됩니다. 표를 깐 직후에는 안쪽 칸이 전부 `0` 인데 그 `0` 은 답이 아니라
아직 안 정한 자리이고, 테두리의 `0` 만 정의에서 나온 참값이에요.

**출발점부터 봅시다.** 루프에 들어가기 전 0 번째 줄과 0 번째 열은 한쪽이 빈 문자열인 자리이고,
빈 문자열과의 공통 부분 수열은 빈 문자열뿐이라 답이 `0` 입니다.

| 자리 | 하는 일 | 문장이 유지되는 근거 |
| --- | --- | --- |
| 테두리 | `fill(0)` 이 깔아 둔다 | 한쪽이 빈 문자열이라 답이 `0` 이다 |
| 마지막 글자가 같은 칸 | 왼쪽 위에 1 을 더한다 | 그 글자를 쓰는 것이 최적이고, 남은 것이 왼쪽 위 칸이다 |
| 마지막 글자가 다른 칸 | 위와 왼쪽 중 큰 값 | 한쪽의 마지막 글자는 반드시 버려지고, 그 둘이 후보의 전부다 |
| 종료 | `(n, m)` 을 정한다 | 두 문자열 전체를 놓고 본 답이다 |

가운데 두 줄이 이 논증의 핵심입니다. 각각이 읽는 이웃 셋은 **앞 줄이거나 같은 줄의 왼쪽**이라,
두 루프가 위에서 아래로 그리고 왼쪽에서 오른쪽으로 나아가는 동안 이미 정해져 있어요.

| 읽는 이웃 | 어디인가 | 언제 정해졌는가 |
| --- | --- | --- |
| `dp[i-1][j-1]` | 앞 줄의 왼쪽 열 | 앞 줄을 채울 때 |
| `dp[i-1][j]` | 앞 줄의 같은 열 | 앞 줄을 채울 때 |
| `dp[i][j-1]` | 같은 줄의 바로 앞 칸 | 이 줄에서 방금 |

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| 둘 다 빈 문자열 | 두 루프가 한 번도 실행되지 않는다 | `dp[0][0]` 인 `0` 이 답이다 |
| 한쪽만 빈 문자열 | 안쪽 루프가 한 번도 실행되지 않는다 | `0` 이 답이다 |
| 한 글자씩이고 같다 | 칸 하나를 정한다 | `dp[0][0] + 1 = 1` 이다 |
| 한 글자씩이고 다르다 | 칸 하나를 정한다 | 위와 왼쪽이 둘 다 `0` 이라 `0` 이다 |
| 공통 글자가 하나도 없다 | 모든 칸이 다른 갈래다 | `0` 이 끝까지 이어진다 |
| 두 문자열이 같다 | 대각선 칸이 전부 같은 갈래다 | 길이가 그대로 답이다 |

**이제 깨뜨려 봅시다.** 문장을 지키던 줄은 **마지막 글자가 다를 때 값을 정하는 줄**이에요.
「어차피 한 칸 작아지는 것이니 대각선을 쓰면 되지 않나」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
for (let j = 1; j <= m; j++) {
  if (s[i - 1] === t[j - 1]) {
    cur[j] = (prev[j - 1] as number) + 1;
  } else {
    cur[j] = prev[j - 1] as number;   // 위와 왼쪽 대신 왼쪽 위를 그대로 썼다
  }
}
```

실행하면 이렇게 나옵니다.

<!--proof:mutantDiagonalOnMismatch-->

```text
입력                        정본이 낸 답  불일치에도 대각선을 쓴 답  판정
전개 입력 "abcde" 와 "ace"             3                          1  틀리다
"abc" 와 "abc"                         3                          3  같다
"AGGTAB" 와 "GXTXAYB"                  4                          1  틀리다
"abc" 와 "aabbcc"                      3                          1  틀리다
"ab" 와 "ba"                           1                          0  틀리다

전개 입력에서 마지막 줄이 [0 1 2 3] 에서 [0 0 0 1] 로 바뀐다
└ 대각선은 양쪽에서 한 글자씩 버린 값이라, 한쪽만 버리면 되는 자리에서 이미 얻은 것까지 함께 버린다
```

문장이 깨지는 자리가 보입니다. 왼쪽 위 칸은 **양쪽에서 한 글자씩 버린** 답인데, 마지막 글자가
다를 때 버려야 하는 것은 **한쪽뿐**이에요. 두 글자를 함께 버리면 그 사이에서 이미 얻은 것까지
사라집니다.

```text
"abcde" 와 "ace" 에서 두 값이 갈리는 자리
  정본의 마지막 줄   0 1 2 3   a 와 c 와 e 를 차례로 얻는다
  변이의 마지막 줄   0 0 0 1   대각선만 따라가 한 줄에 한 칸씩 옮겨진다
  변이가 세는 것               끝을 맞춰 놓았을 때 같은 자리의 글자가 몇 번 맞는가
  └ 그것은 자리를 맞춰 놓고 세는 값이라, 순서만 지키면 되는 이 문제의 답이 아니다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (한쪽이 빈 문자열이다) | `O(nm)` | `Θ(n + m)` — 안쪽 루프가 한 번도 실행되지 않는다 |
| **평균적인 경우** (입력 분포와 무관하다) | `O(nm)` | `Θ(nm)` |
| **최악의 경우** (둘 다 제약의 최댓값이다) | `O(nm)` | `Θ(nm)` — 실제로 도달한다 |

가운데와 아래 줄이 같은 것이 이 절차의 성질입니다. 칸 수가 두 길이로 고정이라 글자를 어떻게
바꿔도 연산 수가 같아요.

```text
상한과 타이트한 값을 가르는 자리
  연산 수가 그보다 크지 않다는 것만 말한다             상한이다          O(nm)
  위아래로 같은 차수라 실제로 그만큼 든다고도 말한다   타이트한 값이다   Θ(nm)
  └ 이 절차는 칸마다 반드시 두 번의 기본 연산을 하므로 Θ 로 적을 수 있다
```

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리가 하나도 없다는 것이 이 절차의
특징이에요 — 정렬도, 위치 목록도, 해시도 만들지 않습니다.

```text
총식 = Θ(nm) 시간 + Θ(nm) 추가 메모리

  시간     문자 비교 nm · 값 결정 nm · 표를 0 으로 까는 일 (n+1)(m+1)
  메모리   칸 (n+1)(m+1) 개

n = m = 1,000 이면 기본 연산이 정확히 2,000,000 번, 잡는 칸이 1,002,001 개다
```

**보장의 종류는 전부 최악 보장입니다.** 해시도, 무작위성도, 분할 상환도 쓰지 않아요 — 어떤
입력을 넣어도 연산 수가 `2nm` 으로 같습니다.

```text
기댓값이 끼어들 자리가 없다
  칸을 찾는 방법   첨자 둘로 바로 간다        해시 충돌이라는 개념이 없다
  칸 수            글자를 안 보고 정해진다    분포를 가정할 필요가 없다
  칸 하나의 비용   항상 문자 비교 1 과 값 1   평균이 아니라 상수다
  └ 최악 보장과 평균 비용이 같은 수다
```

#### 최악을 만드는 입력

연산 수를 최대로 만드는 방법은 하나뿐입니다 — **두 길이를 제약의 최댓값으로 두는 것**이에요.
글자의 모양은 연산 수를 바꾸지 못합니다. 그것을 값으로 확인해 봅시다.

<!--proof:worstShape-->

```text
입력의 모양 (|s| = |t| = 1,000)      문자 비교    값 결정  기본 연산     답
두 문자열이 같다                     1,000,000  1,000,000  2,000,000  1,000
공통 글자가 하나도 없다              1,000,000  1,000,000  2,000,000      0
글자가 둘씩 번갈아 나온다            1,000,000  1,000,000  2,000,000    999
한쪽 글자가 하나 걸러 하나씩 겹친다  1,000,000  1,000,000  2,000,000    500

가운데 세 열이 네 줄 다 같고 오른쪽 열만 다르다
└ 답이 가장 커지는 입력은 두 문자열이 같은 것이고, 그때 답은 짧은 쪽의 길이 1,000 이다
```

**「글자가 많이 겹치면 느리다」는 이 절차에서 성립하지 않습니다.** 물려받은 통념이 여기서는
맞지 않아요 — 첫 줄은 모든 칸이 같은 갈래이고 둘째 줄은 모든 칸이 다른 갈래인데 연산 수가 둘 다
2,000,000 입니다. 어느 갈래든 값을 정하는 일이 한 번이기 때문이에요.

```text
최악은 축마다 다른 입력이 만든다
  연산 수의 최악   n = m = 1,000          글자의 모양과 무관하다. 2,000,000 번
  잡는 칸의 최악   n = m = 1,000          1,002,001 칸. 이것도 글자를 안 본다
  답 크기의 최악   두 문자열이 같다       답이 짧은 쪽의 길이 1,000 이 된다
  └ 셋 다 두 길이만 보고, 셋째만 글자의 모양도 함께 본다
```

**답 크기의 최악은 짧은 쪽의 길이입니다.** 공통 부분 수열은 양쪽 모두의 부분 수열이라 어느
쪽보다도 길 수 없고, 두 문자열이 같으면 그 상한과 정확히 같아집니다.

| 최악으로 만들 축 | 입력 | 값 |
| --- | --- | --- |
| 연산 수 | `n = m = 1,000`, 글자는 무엇이든 | 2,000,000 |
| 잡는 칸 | `n = m = 1,000`, 글자는 무엇이든 | 1,002,001 |
| 답의 크기 | 같은 문자열 둘, 길이 1,000 | 1,000 |

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 두 문자열의 **마지막 글자만** 견주면 문제가 한
칸 작아지고, 남는 것이 접두어 한 쌍이라 상태가 `(n+1)(m+1)` 개로 닫히며, 그 표를 왼쪽 위부터
채우면 오른쪽 아래 칸이 답입니다.

```text
1.   마지막 두 글자를 견준다          갈래가 둘로 갈린다
2.   같으면 왼쪽 위에 1 을 더한다     문자 비교 한 번과 덧셈 한 번
3.   다르면 위와 왼쪽 중 큰 값        문자 비교 한 번과 값 비교 한 번
4.   오른쪽 아래 칸을 돌려준다        마지막으로 정해지는 칸이다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T3 은 `s` 의 `'b'` 를 처리한 줄이었고, 세 칸이 전부
윗줄과 같은 값 `0 1 1 1` 로 나왔어요. 그런데 이 줄에서도 칸 셋이 모두 실행됩니다. 값이 그대로일
것이 뻔한데 이 줄을 왜 건너뛰지 않을까요?

```text
T3   i=2   s 의 글자 'b'   줄 = 0 1 1 1   윗줄 T2 와 글자 하나 다르지 않다
```

<!--check:whyKeepRow-->
건너뛸 수 있는지 **미리 알 수 없기** 때문입니다. `'b'` 가 `t` 에 없다는 것을 알려면 `t` 를 한 번
읽어야 하고, 그 읽기가 지금 하는 문자 비교와 같은 `m` 번이에요. 조건을 하나 더 쓰고도 연산 수는
그대로인 절차가 되므로 얻는 것이 없습니다.

```text
줄 하나를 건너뛰려면
  필요한 것   s[i-1] 이 t 에 있는지 먼저 본다   문자 비교 m 번
  드는 것     그 비교가 지금 하는 비교와 같다   문자 비교 m 번
  얻는 것     없다                              값 결정 m 번만 줄어든다
  └ 미리 세어 두는 방법은 있지만 그것은 표를 채우는 절차가 아니라 다른 설계다
```

`t` 에 없는 글자를 걸러 내는 것 자체는 「경쟁 설계와의 대조」의 일치 쌍 따라가기가 하는 일이고,
그쪽은 표를 아예 안 만드는 대신 이분 탐색을 붙입니다.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 번 문제   세 번째 「짚고 가기」
  2 번 문제   「수식 정의와 유도」
  3 번 문제   「경쟁 설계와의 대조」
```

- 줄 하나만 유지하는 방식에서 왼쪽 위 값을 챙기는 변수를 하나 두면 됩니다. 그 변수를 언제
  읽고 언제 갱신해야 하는지, `"bab"` 와 `"aaaa"` 에서 줄이 어떻게 바뀌는지 손으로 채워
  보세요. 세 번째 「짚고 가기」의 표가 그 입력에서 정본과 갈리는 것을 이미 값으로 보였습니다.
- 답이 되는 문자열 자체를 돌려주려면 표에서 무엇을 어떻게 거슬러 확인해야 할까요? 전개의 T6
  에서 시작해 칸을 거꾸로 따라가면 `"ace"` 가 나오는 경로를 적어 보세요. 어느 칸에서 위로,
  어느 칸에서 왼쪽으로, 어느 칸에서 대각선으로 가야 하는지가 규칙입니다.
- 두 문자열의 길이가 각각 100,000 이라면 이 표를 못 깝니다. 「경쟁 설계와의 대조」의 일치 쌍
  따라가기가 그 규모에서 몇 번의 기본 연산이 되는지 `r` 로 식을 세우고, `r` 이 얼마 이하일 때
  1 초 안에 끝나는지 따져 보세요.
