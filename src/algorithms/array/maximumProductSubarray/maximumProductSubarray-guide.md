# maximumProductSubarray — 직전 칸의 최솟값이 다음 칸의 최댓값이 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 후보를 전부 만들어 보는
방법에서 배열을 한 번만 순회하는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로 동작하는
코드를 한 조각씩 만듭니다.

### 전체 컨셉

정수 배열 `A` 를 받아 **연속된 부분 배열의 곱 중 최댓값**을 돌려주는 문제예요. 부분 배열은
칸을 건너뛰지 않고 이어서 고른 것이고, **아무 칸도 안 고르는 것은 후보가 아닙니다.** 그래서
칸이 하나뿐인 배열에서는 그 값이 음수여도 그대로 답이 돼요.

```text
A 의 칸 번호    0     1     2    3    4     5
A 의 값         2    -3    -2    4    0    -1

후보 몇 개
  칸 0 부터 3 까지   값 2 -3 -2 4   곱 48   ← 이 배열의 답이다
  칸 1 부터 2 까지   값 -3 -2       곱 6
  칸 3 부터 3 까지   값 4           곱 4
  칸 0 부터 5 까지   값 전부        곱 0    ← 0 이 하나라도 들어가면 곱이 0 이다
```

후보를 하나씩 만들어 보는 것으로는 끝나지 않습니다. 배열의 길이를 `N` 이라 하면, 왼쪽 끝과
오른쪽 끝을 둘 다 고르는 것이라 후보의 개수가 `N` 의 제곱에 비례해요.

```text
후보의 개수
  왼쪽 끝을 고르는 방법     N 가지
  오른쪽 끝을 고르는 방법   그 왼쪽 끝부터 배열의 끝까지
  전부 세면                 N(N+1)/2 개
  N = 100,000 이면          5,000,050,000 개
                            └ 1 초 제한 안에 다 만들어 볼 수 없다
```

여기서 **오른쪽 끝을 한 칸에 고정**합니다. 그 칸의 번호를 `i` 라고 부르면, 칸 `i` 에서 끝나는
후보가 셋으로 줄어요.

```text
오른쪽 끝을 칸 i 로 고정하면 후보가 셋으로 줄어든다

  후보 1   A[i]                      칸 i 하나로 새로 시작한다
  후보 2   직전 칸의 최댓값 × A[i]   앞의 구간에 칸 i 를 이어 붙인다
  후보 3   직전 칸의 최솟값 × A[i]   같은 자리에 최솟값을 이어 붙인다
           └ 셋 중 가장 큰 것이 칸 i 에서 끝나는 곱의 최댓값이다
```

후보 3 이 이 문제의 전부입니다. **음수를 곱하면 대소 관계가 뒤집히므로**, 직전 칸에서 가장
작았던 값이 다음 칸에서 가장 커질 수 있어요.

```text
칸 2 에서 무슨 일이 생기는가 — A[2] = -2 는 음수다

  직전 칸의 최댓값 -3 에 곱하면   (-3) × (-2) = 6
  직전 칸의 최솟값 -6 에 곱하면   (-6) × (-2) = 12
                                  └ 작았던 쪽이 더 큰 값이 된다
```

그래서 칸마다 최댓값과 최솟값을 **함께** 정합니다. 둘이 같은 후보 셋에서 나오므로 한 걸음에
두 값이 같이 새로 정해져요.

| 칸 번호 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| `A` 의 값 | 2 | -3 | -2 | 4 | 0 | -1 |
| 그 칸에서 끝나는 곱의 최댓값 | 2 | -3 | 12 | 48 | 0 | 0 |
| 그 칸에서 끝나는 곱의 최솟값 | 2 | -6 | -2 | -8 | 0 | -1 |
| 거기까지의 최댓값 | 2 | 2 | 12 | 48 | 48 | 48 |

둘째 줄과 넷째 줄이 다르다는 것을 봐 주세요. **답은 마지막 칸의 값 0 이 아니라 48** 이고, 그
48 은 칸 3 에서 만들어졌습니다. 그래서 순회하는 동안 값 세 개를 따로 들고 가야 해요.

```text
들고 가는 값 셋
  칸 i 에서 끝나는 곱의 최댓값   후보 셋 중 가장 큰 것으로 매 칸 새로 정해진다
  칸 i 에서 끝나는 곱의 최솟값   같은 후보 셋 중 가장 작은 것이다
  지금까지 본 최댓값             앞의 첫 값이 그보다 커질 때만 바뀐다
                                 └ 배열을 한 번 순회하는 동안 셋 다 유지된다
```

배열을 한 번만 순회하므로 시간은 `O(N)` 이고, 추가로 잡는 메모리는 값 세 개뿐이라 `O(1)`
입니다. 후보를 하나씩 만들어 보는 것이 100 억 번 언저리였던 것과 견주면 70 만 번 언저리예요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **부분 배열이 무엇인지.** 칸 `l` 부터 `r` 까지를 **건너뛰지 않고** 전부 고른 것이고 양끝을
  포함합니다. 칸을 골라 담는 집합(부분 수열)과는 다른 것이에요.
- **음수를 곱하면 대소 관계가 뒤집힌다는 것.** `a < b` 일 때 `c` 가 양수면 `a × c < b × c`
  이고, `c` 가 음수면 `a × c > b × c` 입니다. 이 글의 전부가 이 한 줄에서 나와요.
- **배열의 칸을 읽는 일이 한 번에 얼마나 드는지.** 칸 번호로 바로 찾아가므로 칸 하나를 읽는
  데 드는 일이 배열 길이와 상관없습니다.
- **합이 가장 큰 부분 배열을 어떻게 구하는지.** 같은 모양의 문제를 덧셈으로 푼 것이고, 흐릿하면
  [`kadane`](../kadane/kadane-problem.md) 을 먼저 봅니다. 거기서는 이어받는 값이 하나인데 왜
  여기서는 둘인지가 이 글의 주제예요.

「곱이 가장 큰 구간 하나」와 「합이 가장 큰 구간 하나」는 다른 문제입니다. 뒤쪽은
[`kadane`](../kadane/kadane-problem.md) 이 다루는 것이고, 구간을 여러 번 묻는 것은
[`prefixSumRangeQuery`](../prefixSumRangeQuery/prefixSumRangeQuery-problem.md) 쪽이에요.

```text
곱이 가장 큰 구간의 곱 하나      ← 이 글이 다루는 것
합이 가장 큰 구간의 합 하나      ← 다른 글이 다루는 것
구간마다 곱을 여러 번 묻는 질의  ← 또 다른 글이 다루는 것
```

### 아이디어 상세 — 최댓값과 최솟값을 함께 이어받기를 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function maximumProductSubarray(A: number[]): number;
```

- 입력: 정수 배열 `A`. 길이는 1 이상입니다.
- 출력: 비어 있지 않은 연속 부분 배열의 곱 중 최댓값. 배열의 값이 하나뿐이면 그 값이 답입니다.
- 제약: `1 ≤ N ≤ 100,000`, `−10 ≤ A[i] ≤ 10`. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `N` | 배열의 길이 | `1 ≤ N ≤ 100,000` |
| `A` | 입력 배열 | `−10 ≤ A[i] ≤ 10` |
| `i` | 지금 보고 있는 칸 번호 | `0 ≤ i ≤ N−1` |
| `l` · `r` | 부분 배열의 왼쪽 끝 · 오른쪽 끝. 양끝을 포함합니다 | `0 ≤ l ≤ r ≤ N−1` |
| `P(l, r)` | 칸 `l` 부터 칸 `r` 까지의 곱 | 답의 후보 하나 |
| `mx[i]` | 칸 `i` 에서 끝나는 부분 배열 곱의 최댓값 | 칸마다 하나씩 있다 |
| `mn[i]` | 칸 `i` 에서 끝나는 부분 배열 곱의 최솟값 | 칸마다 하나씩 있다 |
| `best` | 지금까지 본 `mx` 값 중 최댓값 | 그 값이 곧 답이 된다 |

식의 두 값을 코드에서는 `curMax` 와 `curMin` 으로 적고, 그 최댓값을 `best` 로 적습니다.

가장 먼저 떠오르는 방법으로 시작합시다. 후보가 `(l, r)` 쌍으로 정해지니 쌍을 전부 만들어
곱을 구하고 최댓값을 갱신하는 것이에요.

```ts
let best = A[0] as number;
for (let l = 0; l < A.length; l++) {
  let p = 1;
  for (let r = l; r < A.length; r++) {
    p *= A[r] as number;             // 쌍 하나마다 곱셈 한 번
    best = Math.max(best, p);        // 쌍 하나마다 비교 한 번
  }
}
```

이 방법이 하는 일의 양은 **쌍의 개수**입니다. 쌍이 `N(N+1)/2` 개이고 쌍 하나마다 곱셈과 비교가
한 번씩이라 기본 연산이 `N(N+1)` 번이에요.

<!--proof:naive-cost-->

```text
    N  쌍의 개수  기본 연산(실측)     N(N+1)
    6         21               42         42
  100      5,050           10,100     10,100
1,000    500,500        1,001,000  1,001,000

제약 규모 N = 100,000 을 닫힌 형태에 넣으면
  쌍의 개수           5,000,050,000
  기본 연산          10,000,100,000
  초당 1 억 번 기준          100 초
  └ 세 규모에서 실측이 N(N+1) 과 같으므로 마지막 줄도 그 식으로 낸 값이다
```

100 억 번입니다. 제약이 10 만인데 이 방법으로는 1 초 안에 못 끝냅니다. 그러면 이 100 억 안에서
무엇이 되풀이되는지 봅시다.

```text
A = [2 -3 -2] 에서 쌍마다 만든 곱

  l=0   p = 2   p = 2×(-3) = -6   p = (-6)×(-2) = 12   곱셈 3 번
  l=1           p = -3            p = (-3)×(-2) = 6    곱셈 2 번
  l=2                             p = -2               곱셈 1 번
                                  └ 세 줄이 같은 칸 2 를 각각 다시 곱한다
```

왼쪽 끝이 하나 바뀔 때마다 안쪽 루프가 **처음부터 다시** 곱하고 있습니다. 그런데 우리가 원하는
것은 곱 하나하나가 아니라 그중 최댓값이라, 중간에 만든 곱을 전부 들고 있을 이유가 없어요.

```text
칸 2 에서 끝나는 후보 셋의 곱
  l=0               2 × (-3) × (-2)   = 12
  l=1                   (-3) × (-2)   = 6
  l=2                          (-2)   = -2
  이 셋 중 최댓값                     = 12
  이 셋 중 최솟값                     = -2
                                      └ 이 두 수만으로 칸 3 을 정할 수 있는지는 아직 확인하지 않았다
```

이제 같은 배열을 두 방식으로 처리하고 실제 계수를 나란히 세어 봅시다. 왼쪽은 쌍을 전부 만드는
방식이고, 오른쪽은 칸마다 직전 결과를 이어받는 방식이에요.

<!--proof:cost-two-ways-->

```text
방식 (N = 6)                       곱셈  비교  기본 연산 합
모든 (l, r) 쌍의 곱을 각각 만든다    21    21            42
칸마다 직전 결과를 이어받는다        10    25            35

제약 규모 N = 100,000 이면
  모든 쌍의 곱        10,000,100,000
  직전 결과 이어받기         699,993
  └ 위는 쌍의 개수를 따라 늘고, 아래는 칸 수만 따라 늘어난다
```

여섯 칸에서는 차이가 7 번뿐입니다. 갈리는 것은 규모가 커질 때예요 — 위는 쌍의 개수를 따라
늘고, 아래는 칸 수만 따라 늡니다.

| 방식 | 칸 하나에 드는 연산 | 무엇을 따라가는가 |
| --- | --- | --- |
| 모든 쌍 만들기 | 그 칸에서 시작하는 쌍의 개수만큼 | 남은 칸 수를 따라간다 |
| 칸마다 이어받기 | 곱셈 2 · 비교 5 | 배열 길이와 상관없이 같다 |

오른쪽 방식이 칸 하나에 쓰는 연산이 고정됩니다. 여기서 관찰할 것은 그 하나예요 — 칸 하나를
처리하는 연산 수가 배열의 길이와 상관없어집니다.

그 관찰을 개념으로 세우기 전에, 더 단순한 후보부터 시험합시다. 「칸마다 최댓값 하나만
이어받는다」가 그것이에요. 합이 가장 큰 부분 배열이 그렇게 풀립니다.

```ts
let cur = A[0] as number;
let best = A[0] as number;
for (let i = 1; i < A.length; i++) {
  const x = A[i] as number;
  cur = Math.max(x, cur * x);      // 최댓값 하나만 이어받는다
  best = Math.max(best, cur);
}
```

이 후보를 다섯 입력에 실제로 실행하면 세 줄이 어긋납니다.

<!--proof:carry-max-only-->

```text
입력                        정본이 낸 답  최댓값만 이어받은 답  판정
전개 입력 [2 -3 -2 4 0 -1]            48                    24  틀리다
[3 -2 -5]                             30                    10  틀리다
[-2 3 -4]                             24                     3  틀리다
[2 3 4]                               24                    24  같다
[1 2 3]                                6                     6  같다

└ 음수가 짝수 개 들어간 구간이 답인 입력에서 어긋난다. 값이 전부 양수면 답이 같다
```

`[3 -2 -5]` 가 이 후보의 문제를 가장 짧게 보입니다. 칸 1 에서 버린 값이 칸 2 의 답을 만들
재료였어요.

```text
A = [3 -2 -5] 에서 최댓값만 이어받으면
  칸 0   최댓값 3
  칸 1   후보는 -2 와 3 × (-2) = -6 이라 최댓값이 -2 이고, -6 은 여기서 사라진다
  칸 2   후보는 -5 와 (-2) × (-5) = 10 이라 최댓값이 10 이 된다
         └ 사라진 -6 에 -5 를 곱하면 30 이고, 그것이 진짜 답이다
```

그러니 **직전 칸의 최솟값도 함께 이어받는다**는 것이 절차에 있어야 합니다. 여기서 진짜 개념이
나와요. 칸 `i` 에서 끝나는 곱의 최댓값 `mx[i]` 와 최솟값 `mn[i]` 를 같은 후보 셋에서 정하는
것입니다.

```text
mx[i] 와 mn[i] 를 정하는 규칙 — 후보 셋이 둘의 재료를 함께 준다

  후보 1   A[i]             칸 i 하나로 새로 시작한다
  후보 2   mx[i−1] × A[i]   직전 칸의 최댓값에 이어 붙인다
  후보 3   mn[i−1] × A[i]   직전 칸의 최솟값에 이어 붙인다
  mx[i]    셋 중 가장 큰 것
  mn[i]    셋 중 가장 작은 것
           └ mx[0] 과 mn[0] 은 후보가 하나뿐이라 둘 다 A[0] 이다
```

개념이 정하는 것은 **이어받는 값의 개수와 그 값이 바뀌는 범위**입니다. 칸 하나를 지날 때마다
값 두 개가 새로 정해지고, 그 계산에 필요한 과거는 직전 칸의 두 값뿐이에요.

```text
칸 하나를 지날 때
  읽는 과거        mx[i−1] 과 mn[i−1] 둘   칸 i−2 보다 앞은 읽지 않는다
  새로 정하는 값   mx[i] 와 mn[i] 둘       같은 후보 셋에서 함께 나온다
  답의 후보        mx[0] 부터 mx[N−1]      그중 최댓값이 답이다
                   └ 이어받을 것이 두 값이고, 답을 담을 것이 하나 더 있다
```

**쉬운 경우와 불안한 경우를 나눠서 값으로 확인합시다.** 쉬운 경우는 `A[i]` 가 양수일 때예요.
곱셈이 대소 관계를 지키므로 최댓값은 최댓값에서, 최솟값은 최솟값에서 나옵니다.

```text
쉬운 경우 — 칸 3 의 A[3] = 4 는 양수다
  mx[2] = 12   이어 붙이면 12 × 4 = 48
  mn[2] = -2   이어 붙이면 (-2) × 4 = -8
  mx[3] = 48   새로 시작하면 4 라서 48 이 크다
  mn[3] = -8   └ 부호가 안 바뀌므로 최댓값은 최댓값에서, 최솟값은 최솟값에서 온다
```

불안한 경우는 **`A[i]` 가 음수일 때**입니다. 최댓값과 최솟값의 자리가 서로 바뀌는 자리이고,
여기서 최솟값을 이어받는 것이 실제로 값을 만들어요.

```text
불안한 경우 — 칸 2 의 A[2] = -2 는 음수다
  mx[1] = -3   이어 붙이면 (-3) × (-2) = 6
  mn[1] = -6   이어 붙이면 (-6) × (-2) = 12
  mx[2] = 12   직전 최솟값에서 온 값이다
  mn[2] = -2   └ 최댓값의 재료가 직전 최솟값으로 바뀌었다
```

`A[i]` 가 0 인 자리도 값으로 확인하고 갑시다. 후보 셋이 모두 0 이 되므로 이어받는 두 값이 함께
0 이 됩니다.

```text
0 을 지나는 자리 — 칸 4 의 A[4] = 0
  후보 셋     0 · 48 × 0 = 0 · (-8) × 0 = 0
  mx[4] = 0   셋이 같은 값이라 최댓값과 최솟값이 함께 0 이 된다
  mn[4] = 0
  best = 48   0 은 48 보다 작아 지금까지의 최댓값을 바꾸지 못한다
              └ 0 은 이어받은 값을 끊지만, 이미 만든 답은 best 에 남는다
```

빠뜨리는 칸이 없다는 것은 루프의 종료 조건으로 말할 수 있습니다. 루프는 `i` 를 `1` 부터
`N−1` 까지 하나씩 올리며 실행되고, 한 번 실행할 때마다 `mx[i]` 와 `mn[i]` 를 **정확히 한 번씩**
정해요.

```text
루프가 끝난 시점
  정해진 값   mx[0] mn[0] … mx[N−1] mn[N−1]   칸마다 둘씩, 각각 정확히 한 번
  안 본 칸    없다                            칸 0 은 루프에 들어가기 전에 정해진다
              └ 답의 후보 N 개가 빠짐없이 한 번씩 만들어진다
```

이제 「이어받는 값이 둘」이 정말 필요한지 값으로 확인합니다. 이어받는 값의 개수를 0 · 1 · 2 ·
`2N` 네 가지로 두고 같은 입력 넷에 실행했어요.

<!--proof:state-size-->

```text
입력                      정답  값 0 개  값 1 개  값 2 개  값 2N 개
[2 -3 -2 4 0 -1]            48        4       24       48        48
[3 -2 -5]                   30        3       10       30        30
[2 0 3]                      3        3        3        3         3
[-4 -3 -2]                  12       -2       12       12        12
어긋난 입력 수                        3        2        0         0
N = 100,000 에서 쓰는 칸              1        1        2   200,000

└ 값 하나짜리 후보 둘은 어긋나는 입력이 남는다. 어긋나지 않는 가장 작은 상태가 값 둘이다
```

값 0 개는 가장 큰 원소 하나를 답으로 내는 것이고, 값 1 개는 최댓값만 이어받는 것입니다. 앞은
여러 칸을 곱해 커지는 경우를 놓치고, 뒤는 음수 둘이 만나 양수가 되는 경우를 놓쳐요.

```text
얻은 절차 한 벌
  1. curMax · curMin · best 를 모두 A[0] 으로 둔다
  2. 칸 1 부터 마지막 칸까지 차례로 읽으며
  3.   후보 셋 A[i] · curMax × A[i] · curMin × A[i] 를 만든다
  4.   curMax 를 셋 중 가장 큰 것, curMin 을 셋 중 가장 작은 것으로 바꾼다
  5.   best 를 best 와 curMax 중 큰 쪽으로 바꾼다
  6. best 를 돌려준다
       └ 100 억 번이던 것이 70 만 번 언저리가 된다
```

### 수행으로 알아보는 알고리즘 — 여섯 칸을 한 번 순회해 최대 부분곱을 낸다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const A = [2, -3, -2, 4, 0, -1];
// 이 절이 끝나면 48 이 나와야 한다
```

왜 하필 이 여섯 칸일까요? 후보 셋이 최댓값 쪽에서도 최솟값 쪽에서도 각각 한 번 이상 골라지고,
음수 둘이 곱해져 양수가 되는 자리가 있고(칸 2), 0 을 지나는 자리가 있으며(칸 4), **답이 마지막
칸이 아니라 칸 3 에서 만들어지기** 때문이에요. 마지막 값을 답으로 착각하는 자리가 이 입력에서
실제로 확인됩니다.

```text
절차 전체를 한 장으로

  T1      curMax · curMin · best 를 A[0] 으로 둔다   ① 세 값을 첫 칸의 값으로
          칸 1 부터 마지막 칸까지 차례로:            ② 순회할 칸이 남았는가
  T2~T6   이어 붙이는 후보 둘을 만든다               ③ 후보 만들기
          최댓값과 최솟값을 같은 셋에서 정한다       ④ 두 값 함께 정하기
          best 와 curMax 중 큰 쪽을 best 에 적는다   ⑤ 최댓값 갱신
  T7      best 를 돌려준다
```

#### 1. 세 값을 첫 칸의 값으로 시작한다

첫 조각은 준비입니다. `A[0]` 을 세 곳에 적어 두고, 아직 루프에는 들어가지 않아요.

```ts
let curMax = A[0] as number;   // ① 칸 0 에서 끝나는 곱의 최댓값
let curMin = A[0] as number;   // ① 같은 칸의 최솟값
let best = A[0] as number;     // ① 지금까지 본 최댓값
```

`①` 이 셋 다 `2` 로 시작하는 것이 이 조각의 전부입니다. 칸 0 에서 끝나는 부분 배열은 `[A[0]]`
하나뿐이라 그 곱의 최댓값과 최솟값이 둘 다 `A[0]` 이고, 그때까지 본 최댓값도 같은 값이에요.

```text
T1 이 끝난 시점
  curMax = 2   칸 0 에서 끝나는 곱의 최댓값이다
  curMin = 2   같은 칸의 최솟값이고, 후보가 하나뿐이라 값이 같다
  best = 2     칸 0 까지의 답이다
               └ 셋이 같은 값이지만 뜻이 다르고, 다음 걸음부터 갈라진다
```

#### 멈춤 — 최댓값의 후보에서 「새로 시작」을 빼면 답이 0 에 머문다

여기서 헷갈리기 쉬운 포인트는 후보의 개수입니다. 「이어 붙이는 후보 둘이면 충분하고, `A[i]`
하나짜리 구간은 그 둘 중 하나에 이미 들어 있지 않나」로 읽기 쉬워요. 그 생각대로 후보 하나를
빼 봅시다.

```ts
curMax = Math.max(grown, flipped);   // A[i] 하나짜리 후보를 뺐다
```

이렇게 하면 칸 `i` 에서 새로 시작하는 구간이 후보에서 사라집니다. 다섯 입력으로 확인해 봅니다.

<!--proof:pause-drop-fresh-->

```text
입력                        정본이 낸 답  새로 시작을 뺀 답  판정
전개 입력 [2 -3 -2 4 0 -1]            48                 48  같다
[2 0 3]                                3                  2  틀리다
[0 5]                                  5                  0  틀리다
[1 -2 3]                               3                  1  틀리다
[-10 -10]                            100                100  같다

└ 전개 입력에서는 답이 같다. 0 뒤에서 답이 만들어지는 입력에서만 어긋난다
```

**전개 입력에서 답이 안 틀린다는 것**이 이 실수의 성격입니다. 0 을 지난 뒤에 답이 만들어지는
입력을 시험에 넣지 않으면 끝까지 모르고 넘어가요.

```text
[2 0 3] 의 칸 2 에서 두 방식이 갈리는 자리
  후보 셋   3 · 0 × 3 = 0 · 0 × 3 = 0   가장 큰 것이 3 이다
  후보 둘   0 × 3 = 0 · 0 × 3 = 0       가장 큰 것이 0 이다
            └ 0 을 지나면 이어 붙이는 후보가 둘 다 0 이라, 새로 시작하는 후보가 없으면 답이 0 에 머문다
```

#### 2. 칸마다 후보 셋에서 최댓값과 최솟값을 함께 정한다

둘째 조각은 순회입니다. 칸 하나마다 이어 붙이는 후보 둘을 만들고, `A[i]` 를 더해 셋으로 만든
다음, 그 셋에서 최댓값과 최솟값을 함께 골라요.

```ts
for (let i = 1; i < A.length; i++) {      // ② 순회할 칸이 남았는가
  const x = A[i] as number;
  const grown = curMax * x;               // ③ 직전 최댓값에 이어 붙인 후보
  const flipped = curMin * x;             // ③ 직전 최솟값에 이어 붙인 후보
  curMax = Math.max(x, grown, flipped);   // ④ 셋 중 가장 큰 것
  curMin = Math.min(x, grown, flipped);   // ④ 셋 중 가장 작은 것
  best = Math.max(best, curMax);          // ⑤ 최댓값 갱신
}
```

`②` 는 `i` 가 `1` 부터 `5` 까지일 때 참이고 `6` 에서 처음 거짓이 됩니다. `③`·`④`·`⑤` 는 그
다섯 걸음에서 각각 한 번씩 실행돼요. 앞 두 걸음만 실행하면 이렇게 나옵니다.

| 걸음 | `i` | `A[i]` | 새로 시작 | 최댓값에 잇기 | 최솟값에 잇기 | `curMax` | `curMin` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T2 | 1 | -3 | -3 | -6 | -6 | -3 | -6 |
| T3 | 2 | -2 | -2 | 6 | 12 | 12 | -2 |

T3 이 이 두 줄의 핵심입니다. `curMax` 가 `12` 가 됐는데 그 재료는 직전 최댓값 `-3` 이 아니라
직전 최솟값 `-6` 이에요.

```text
T3 이 하는 일
  들고 있던 값   curMax = -3 · curMin = -6   칸 1 에서 끝나는 곱의 최댓값과 최솟값
  후보 셋        -2 · 6 · 12                 새로 시작 · 최댓값에 잇기 · 최솟값에 잇기
  고른 값        curMax = 12 · curMin = -2   가장 큰 것과 가장 작은 것을 같은 셋에서 골랐다
                 └ 최솟값을 안 이어받았으면 12 를 만들 재료가 없다
```

#### 멈춤 — 최솟값을 이미 갱신된 최댓값으로 계산하면 답이 커진다

여기서 헷갈리기 쉬운 포인트는 두 줄이 보는 `curMax` 입니다. 「어차피 같은 걸음에서 하는 일이니
`grown` 을 따로 둘 것 없이 그 자리에서 다시 곱하면 되지 않나」로 읽기 쉬워요. 그렇게 적어
봅시다.

```ts
curMax = Math.max(x, grown, flipped);
curMin = Math.min(x, curMax * x, flipped);   // 방금 갱신된 curMax 를 다시 곱했다
```

이렇게 하면 두 줄이 **서로 다른 후보 셋**을 봅니다. 다섯 입력으로 확인해 봅니다.

<!--proof:pause-stale-max-->

```text
입력                        정본이 낸 답  갱신된 값을 쓴 답  판정
전개 입력 [2 -3 -2 4 0 -1]            48                 48  같다
[-7 2 -1 -8]                          16                112  틀리다
[1 -2 -3 -4]                          12                 72  틀리다
[2 3 4]                               24                 24  같다
[-10 -10]                            100                100  같다

└ 전개 입력에서는 답이 같다. 음수가 셋 이상 이어지는 입력에서 어긋난다
```

**전개 입력에서도 답이 안 틀립니다.** 음수가 셋 이상 이어지는 입력에서만 어긋나므로, 그런
입력을 시험에 넣지 않으면 통과해요.

```text
[-7 2 -1 -8] 의 칸 2 에서 갈리는 자리
  정본        curMin = min(-1, 2 × (-1) = -2, (-14) × (-1) = 14) = -2
  갱신된 값   curMax 가 먼저 14 로 바뀌고, curMin = min(-1, 14 × (-1) = -14, 14) = -14
              칸 3 에서 (-14) × (-8) = 112 가 만들어져 답이 16 대신 112 가 된다
              └ 두 줄이 서로 다른 후보 셋을 보면 최솟값이 실제보다 작아진다
```

#### 3. 여섯 칸을 끝까지 순회해 답을 낸다

두 조각을 이어 고정 입력에 실행하면 일곱 걸음이 나옵니다. T1 은 준비, T2 부터 T6 까지가 순회,
T7 이 반환이며, 마지막에 남는 값이 48 입니다.

```text
A 의 값         2    -3    -2     4     0    -1

curMin          2    -6    -2    -8     0    -1
best            2     2    12    48    48    48
                                 └ best 는 여기서 마지막으로 커진다
```

걸음마다의 상태값을 펼치면 이렇게 나옵니다. 가운데 세 열이 후보 셋이고, 오른쪽 두 열이 그
셋에서 고른 값이에요.

```text

T2    1    -3         -3             -6             -6      -3      -6     2
T3    2    -2         -2              6             12      12      -2    12

└ best 가 마지막으로 커지는 곳은 칸 3 이고, 그 뒤 두 걸음은 curMax 만 바뀐다. 답은 48 이다
```

후보 셋이 어느 걸음에서 골라졌는지도 세어 둡시다. 최댓값 쪽과 최솟값 쪽을 갈라서 봅니다.

<!--proof:walk-branches-->

```text

└ 후보 셋이 최댓값 쪽에서도 최솟값 쪽에서도 각각 한 번 이상 골라졌다
  값이 같아 후보 여럿이 함께 적힌 걸음은 T2 · T5 · T6 이다
```

**다섯 갈래가 모두 실행됐습니다.** `①` 은 T1 에서 한 번이고, `②` 는 T2 부터 T6 까지 참이며
T7 에서 거짓이 됩니다. `③`·`④`·`⑤` 는 다섯 걸음에서 각각 한 번씩 실행됐고, `⑤` 가 `best` 를
실제로 바꾼 것은 T3 과 T4 두 번이에요.

| 무엇 | 어디서 | 몇 번 |
| --- | --- | --- |
| `①` 세 값을 첫 칸의 값으로 | T1 | 1 |
| `②` 순회할 칸이 남았는가 | T2~T6 에서 참 · T7 에서 거짓 | 6 |
| `③` 후보 만들기 | T2~T6 | 5 |
| `④` 두 값 함께 정하기 | T2~T6 | 5 |
| `⑤` 최댓값 갱신 | T2~T6, 그중 T3·T4 에서 값이 바뀐다 | 5 |

답이 정말 그 구간의 곱인지 확인하고 갑니다. `best` 를 만든 것은 칸 0 부터 칸 3 까지이고, 그
값들을 직접 곱하면 같은 수가 나와야 해요.

| 무엇 | 값 |
| --- | --- |
| `best` 를 만든 구간 | 칸 0 부터 칸 3 까지 |
| 그 칸들의 값 | 2 · -3 · -2 · 4 |
| 직접 곱한 값 | 2 × (-3) × (-2) × 4 = 48 |
| T6 이 낸 `best` | 48 |

#### 멈춤 — 마지막 칸의 최댓값을 답으로 읽으면 앞에서 만든 답을 놓친다

여기서 헷갈리기 쉬운 포인트는 답을 어디서 읽는가입니다. 「칸마다 최댓값을 정해 왔으니 마지막
칸의 값이 답 아닌가」로 읽기 쉬워요. `best` 를 없애고 `curMax` 를 돌려주는 것이 그 생각입니다.

```ts
return curMax;                 // best 대신 마지막 칸의 최댓값을 돌려줬다
```

`curMax` 는 **칸 `N−1` 에서 끝나는** 곱의 최댓값이라, 답이 배열 가운데에서 끝나면 그 값을 못
봅니다. 다섯 입력으로 확인해 봅니다.

<!--proof:pause-answer-last-->

```text
입력                        정본이 낸 답  마지막 칸의 최댓값  판정
전개 입력 [2 -3 -2 4 0 -1]            48                   0  틀리다
[2 3 -2 4]                             6                   4  틀리다
[1 2 3]                                6                   6  같다
[-10 -10]                            100                 100  같다
[-2]                                  -2                  -2  같다

└ 답이 마지막 칸에서 끝나는 입력에서는 같다. 답이 배열 가운데에서 끝나면 어긋난다
```

첫 줄이 이 실수를 가장 크게 보입니다. 전개 입력은 마지막 칸 앞에 0 이 있어서 `curMax` 가 0 으로
내려간 채 끝나는데, 답은 그 앞에서 만들어진 48 이에요.

```text
[2 -3 -2 4 0 -1] 에서 칸마다 끝나는 곱의 최댓값
  칸 3   48   여기가 답이다
  칸 4    0   A[4] = 0 이라 후보 셋이 모두 0 이 된다
  칸 5    0   후보는 -1 · 0 · 0 이라 가장 큰 것이 0 이다
              └ 마지막 값만 읽으면 앞에서 만든 48 을 통째로 놓친다
```

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 `best` 를 돌려주는 마지막 한
줄뿐이에요 — 배열의 길이가 1 이면 루프가 한 번도 실행되지 않아 `A[0]` 이 그대로 답이 됩니다.

```ts
export function maximumProductSubarray(A: number[]): number {
  // ① 세 값을 첫 칸의 값으로 시작한다 — 빈 부분 배열이 후보가 아니라서 1 이나 0 에서
  //    출발하지 않는다. curMax 와 curMin 은 칸 0 에서 끝나는 곱의 최댓값과 최솟값이고,
  //    best 는 지금까지 본 최댓값이다.
  let curMax = A[0] as number;
  let curMin = A[0] as number;
  let best = A[0] as number;

  for (let i = 1; i < A.length; i++) {
    // ② 순회할 칸이 남았는가 — 남아 있으면 아래를 한 번 실행한다.
    const x = A[i] as number;
    // ③ 이어 붙이는 후보 둘을 갱신 전에 만들어 둔다. 아래 두 줄이 같은 후보 셋을 본다.
    const grown = curMax * x;
    const flipped = curMin * x;
    // ④ 칸 i 에서 끝나는 곱의 최댓값과 최솟값을 같은 후보 셋에서 함께 정한다.
    curMax = Math.max(x, grown, flipped);
    curMin = Math.min(x, grown, flipped);
    // ⑤ 지금까지 본 최댓값을 갱신한다. curMax 를 먼저 고친 뒤라 칸 i 의 값이 후보에 들어간다.
    best = Math.max(best, curMax);
  }

  return best;
}
```

```text
maximumProductSubarray([2, -3, -2, 4, 0, -1])   →  48
maximumProductSubarray([2, 3, -2, 4])           →   6
maximumProductSubarray([-2, 3, -4])             →  24
maximumProductSubarray([-2, 0, -1])             →   0
maximumProductSubarray([-2])                    →  -2
```

### 알아 두면 좋은 개념 — 구간 산술

이 절차가 칸마다 들고 있는 두 값을 한 쌍으로 읽으면 **구간** 하나입니다. `curMin` 이 왼쪽 끝,
`curMax` 가 오른쪽 끝이에요. 그러면 한 걸음이 하는 일은 **구간에 수 하나를 곱하고, 거기에 점
하나를 더해 다시 구간으로 만드는 것**입니다.

```text
칸 i 의 두 값을 구간 하나로 읽으면

  칸 1 의 구간          [-6, -3]              curMin = -6 · curMax = -3
  A[2] = -2 를 곱하면   [-6, -3] × [-2, -2]   네 모서리 곱은 12 · 12 · 6 · 6
  그 결과 구간          [6, 12]               음수를 곱해 양끝의 자리가 바뀌었다
  새로 시작을 더하면    [-2, 12]              구간 [-2, -2] 를 함께 담는 가장 작은 구간이다
                        └ 칸 2 의 curMin = -2 · curMax = 12 가 그 구간의 양끝이다
```

수 대신 **구간을 값으로 삼아 사칙연산을 정의한 것**을 구간 산술이라고 부릅니다. 곱셈의 정의가
이 글의 후보 셋과 같은 모양이에요 — 두 구간의 양끝에서 만든 **네 개의 곱** 중 가장 작은 것과
가장 큰 것이 결과 구간의 양끝입니다.

```text
같은 규칙이 나오는 다른 자리
  구간 산술   구간 둘을 곱할 때 네 모서리 곱의 최솟값과 최댓값을 낸다
  게임 트리   상대 차례에서 부호를 뒤집어 최댓값과 최솟값을 맞바꾼다
  분기 한정   상한과 하한을 함께 들고 가지를 잘라 낸다
              └ 셋 다 「한쪽 끝만으로는 다음 끝을 못 정한다」가 이유다
```

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 후보 셋 규칙을 식으로 어떻게
적는지, 무엇이 매 걸음 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- 고르는 것이 **연속 구간**입니다. 칸을 건너뛰며 골라도 되면 후보가 셋으로 줄지 않아요.
- 구간의 값이 **직전 구간의 값에서 한 번에 이어집니다.** 곱셈이 그렇고, 이어받는 값이 둘로
  늘어난 것은 곱셈이 대소 관계를 뒤집기 때문입니다.
- 답이 **한 번만** 필요합니다. 배열이 바뀌면 처음부터 다시 순회해야 해요.
- 값이 **표현 범위 안에** 있습니다. 원소의 절댓값이 작게 묶여 있거나 배열이 짧아야 곱을
  `number` 하나에 담을 수 있어요.

```text
네 조건이 코드의 모양을 그대로 정한다
  연속 구간           → 칸 i 의 후보가 셋으로 줄어든다
  한 번에 이음        → 직전 결과 둘만 들고 있으면 된다
  답이 한 번          → 순회 한 번으로 끝난다
  값이 표현 범위 안   → 답을 number 하나에 담을 수 있다
```

네 번째 줄이 이 절차의 경계입니다. 같은 규칙이 덧셈이면 이어받는 값이 하나로 줄고, 구간을
여러 번 물으면 배열을 트리에 담는 쪽이 됩니다.

```text
합을 최대로 한다        칸마다 값 하나를 이어받는다              kadane
곱을 최대로 한다        칸마다 최댓값과 최솟값 둘을 이어받는다   이 글의 절차
구간을 여러 번 묻는다   배열을 트리에 담는다                     세그먼트 트리
                        └ 가운데 줄만 값을 둘 이어받는다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "연속된 부분 배열"  "이어진 구간"  "연속한 며칠"   ← 고르는 것이 연속 구간이다
  "곱이 최대인"  "가장 큰 곱"  "최대 배율"           ← 답이 곱의 최댓값 하나다
  "구간은 비어 있을 수 없다"  "하루 이상"            ← 1 을 답으로 쓰면 안 된다는 신호다
  "값이 음수일 수도 있다"                            ← 최솟값을 함께 이어받으라는 신호다
  "0 이 들어 있을 수 있다"                           ← 이어받은 값이 함께 0 이 되는 자리가 있다

제약에 이런 모양이 보이면
  N 이 10^5 이상이라 N(N+1)/2 개의 후보를 다 만들 수 없다
  원소의 절댓값이 작게 묶여 있어 곱이 표현 범위 안에 든다

반대로 이런 말이 보이면 해당하지 않는다
  "원소를 골라 담는다"  "순서를 바꿔도 된다"         ← 연속 구간이 아니다
  "구간의 합"                                        ← 값 하나만 이어받으면 된다
  "질의가 여러 번 들어온다"  "값이 중간에 바뀐다"    ← 순회를 매번 다시 해야 한다
```

세 번째 무리가 보이면 다른 절차로 갑니다. 합을 다루면
[`kadane`](../kadane/kadane-problem.md) 쪽이고, 값이 바뀌며 질의가 반복되면
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 과 같은 트리
쪽이에요.

#### 실제로 쓰이는 곳

- **`inari` — Rust 의 구간 산술 라이브러리** — README 가 *"inari is a Rust implementation of
  interval arithmetic"* 라고 적고, *"It conforms to IEEE Std 1788.1-2017. It also implements a
  subset of IEEE Std 1788-2015"* 로 준거 표준을 밝힙니다. 이 글의 후보 셋과 같은 규칙이 그
  라이브러리의 곱셈에 들어 있어요.
  ([`inari` README](https://github.com/unageek/inari), 조회 2026-08-30)
- **같은 저장소의 `src/arith.rs`** — 두 구간이 다 0 을 걸치는 경우의 곱셈이 `let r = max(xy,
  zw);` 로 끝납니다. `xy` 와 `zw` 는 각각 한쪽 끝에서 만든 곱 둘을 담고 있고, 그 둘을 성분마다
  견주어 결과 구간의 끝을 정해요 — 한쪽 끝만 보면 결과의 끝을 못 정한다는 것이 이 글과 같은
  자리입니다. ([`src/arith.rs`](https://github.com/unageek/inari/blob/main/src/arith.rs),
  조회 2026-08-30)

```text
구간 산술과 이 글의 대응

  구간의 양끝            [최솟값, 최댓값]        이 글의 curMin 과 curMax
  구간 × 수              네 모서리 곱을 만든다   이 글은 한쪽이 점이라 곱이 둘이다
  결과의 양끝            그중 최솟값과 최댓값    이 글의 Math.min 과 Math.max
                         └ 다른 것은 「새로 시작」 후보 하나를 더 담는다는 자리뿐이다
```

**이 절차를 그 이름으로 제공하는 표준 라이브러리는 1 차 출처로 확인하지 못했습니다.** 검색으로
나오는 것은 문제 풀이 모음과 학습용 저장소이고, 제품 코드에 들어간 자리는 못 찾았어요. 확인한
것은 위의 구간 산술 구현 하나이고, 그것은 이 문제를 푸는 것이 아니라 **같은 규칙을 쓰는** 자리
입니다.

#### 경쟁 설계와의 대조

같은 목표(배열의 최대 부분곱을 아는 것)를 노리는 다른 절차로 **세그먼트 트리**가 있습니다.
마디마다 그 구간의 여섯 값(전체 곱 · 왼쪽 끝에서 시작하는 곱의 최댓값과 최솟값 · 오른쪽 끝에서
끝나는 곱의 최댓값과 최솟값 · 최대 부분곱)을 들고, 두 마디를 합칠 때 여섯을 함께 만드는
방식이에요. **최솟값을 함께 드는 이유가 이 글의 관찰과 같습니다** — 왼쪽 마디의 뒤쪽 곱과
오른쪽 마디의 앞쪽 곱이 둘 다 음수면 그 곱이 최댓값이 되므로, 네 모서리 곱을 다 만들어야 해요.

```text
두 설계가 값 하나를 바꿀 때 하는 일

  칸마다 이어받기   칸 하나를 고쳐 두고, 답을 물으면 배열을 처음부터 다시 순회한다
  세그먼트 트리     잎 하나를 고치고 뿌리까지 log N 번 합친다. 답은 뿌리에 이미 적혀 있다
                    └ 갱신은 이어받기가 적고, 반복 질의는 세그먼트 트리가 적다
```

같은 입력·같은 작업 목록에 두 설계를 걸고 **기본 연산 수**(곱셈 + 비교)를 셌습니다. 배열은
`N = 1,024` 이고 `A[k] = (37k mod 3) − 1` 로 만들었어요. 갱신은 1,024 개인데 `k` 번째가 칸
`91k mod N` 의 값을 `(53k mod 3) − 1` 로 바꿉니다. 질의는 「지금 배열의 최대 부분곱」을 묻는
것이고 갱신 사이에 고르게 끼웠으며, 목록의 끝에서 두 설계가 다 한 번 답합니다. **전개 입력을
그대로 쓰지 않은 이유**는 여섯 칸에서는 세그먼트 트리가 한 번 갱신할 때 합치는 마디가 셋뿐이라
두 설계의 계수가 상수에 묻히기 때문이고, **값을 −1 · 0 · 1 로 둔 이유**는 1,024 칸의 곱이
표현 범위를 넘어 두 설계의 답 대조가 성립하지 않기 때문입니다. 두 설계 다 값을 보지 않고
정해진 수의 연산을 하므로 값의 범위는 계수를 바꾸지 않아요.

| 섞인 질의 | 칸마다 이어받기 | 세그먼트 트리 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 0 회 | **7,161** | 247,786 | 이어받기가 34 배 적습니다 |
| 33 회 | **243,474** | 247,786 | 이어받기가 근소하게 적습니다 |
| 34 회 | 250,635 | **247,786** | **여기서 순서가 뒤집힙니다** |
| 1,024 회 | 7,340,025 | **247,786** | 세그먼트 트리가 29 배 적습니다 |

**저장 칸은 3 개 대 12,288 개입니다.** 메모리에서는 갈리지 않고 한쪽이 계속 적어요 — 갈리는
것은 연산 수이고, 그 경계가 이 입력에서 **질의 34 회**입니다.

```text
경계가 그 자리인 이유

  질의 하나를 더할 때 늘어나는 연산 수   이어받기 7,161 · 세그먼트 트리 0
  세그먼트 트리가 미리 낸 연산 수        247,786 = 트리 세우기 22,506 + 갱신 225,280
  247,786 ÷ 7,161 ≈ 34.6                 실측에서 뒤집히는 자리가 34 회다
```

**이 절차가 내주는 것은 반복 질의입니다.** 값 하나가 바뀔 때마다 답을 다시 물으면 그때마다
배열 전체를 순회해서, 질의 하나가 7,161 번의 연산이 돼요. 그 대신 얻는 것이 셋입니다.

```text
칸마다 이어받기가 얻는 것
  저장 칸   값 세 개로 끝난다   세그먼트 트리는 마디마다 값 여섯을 든다
  전처리    없다                트리를 세우는 데만 22,506 번이 든다
  구현      루프 하나           합치기 규칙 여섯을 따로 맞춰야 한다
            └ 이 문제는 질의가 한 번이라 첫 열이 답이다
```

문제가 「배열 하나의 최대 부분곱」을 한 번 요구하니 이 문제에서는 칸마다 이어받기가 답입니다.
같은 지문에서 **값이 바뀌며 답을 34 회 넘게 다시 묻는 순간** 이 판정은 다시 해야 해요.

### 수식 정의와 유도

구간의 곱과 답을 기호로 정의합니다. `P(l, r)` 은 칸 `l` 부터 칸 `r` 까지의 곱이고, 답은 그중
최댓값이에요.

$$P(l, r) = \prod_{k=l}^{r} A[k] \quad (0 \le l \le r \le N-1) \qquad\qquad \text{답} = \max_{0 \le l \le r \le N-1} P(l, r)$$

```text
정의를 값에 넣어 봅니다 — A 의 값 2 -3 -2 4 0 -1

  P(0, 3)   = 2 × (-3) × (-2) × 4   = 48
  P(1, 2)   = (-3) × (-2)           = 6
  P(4, 5)   = 0 × (-1)              = 0
  P(3, 1)   = l 이 r 보다 크다      = 정의되지 않는다
```

오른쪽 끝을 고정한 값도 정의합니다. `mx[i]` 와 `mn[i]` 는 오른쪽 끝이 칸 `i` 인 후보들의 곱 중
최댓값과 최솟값이고, 답은 `mx` 값 `N` 개의 최댓값이에요.

$$mx[i] = \max_{0 \le l \le i} P(l, i), \qquad mn[i] = \min_{0 \le l \le i} P(l, i), \qquad \text{답} = \max_{0 \le i \le N-1} mx[i]$$

```text
정의를 칸 2 에 넣어 봅니다 — 오른쪽 끝이 칸 2 인 후보는 셋이다

  P(0, 2) = 12   P(1, 2) = 6   P(2, 2) = -2
                 └ 이 셋의 최댓값이 mx[2] = 12 이고 최솟값이 mn[2] = -2 다
```

여섯 칸 전부에서 같은 것을 확인하고 갑시다. 왼쪽 끝을 다 펴서 센 값과 후보 셋만 본 값이 같아야
정의와 절차가 같은 것을 말하는 것입니다.

<!--proof:math-check-->

```text
오른쪽 끝이 칸 3 인 후보 4 개를 정의대로 만든다

  P(0, 3) = 2 × (-3) × (-2) × 4      = 48
  P(1, 3) = (-3) × (-2) × 4          = 24
  P(2, 3) = (-2) × 4                 = -8
  P(3, 3) = 4                        = 4

i  정의로 센 mx[i]  점화식의 curMax  정의로 센 mn[i]  점화식의 curMin
0                2                2                2                2
1               -3               -3               -6               -6
2               12               12               -2               -2
3               48               48               -8               -8
4                0                0                0                0
5                0                0               -1               -1

└ 두 쌍이 여섯 칸에서 모두 같다. 정의를 다 펴서 센 값과 후보 셋만 본 값이 어긋나지 않는다
```

이제 유도합니다. 오른쪽 끝이 칸 `i` 인 후보들의 곱을 모아 집합 `S_i` 라고 부르면, 그 집합이
직전 집합에서 한 걸음으로 나와요. 칸 `i` 하나짜리 후보와, `S_{i-1}` 의 각 원소에 `A[i]` 를
곱한 것을 합친 것입니다.

$$S_i = \{\, P(l, i) \mid 0 \le l \le i \,\} \qquad\qquad S_i = \{A[i]\} \cup \bigl\{\, s \cdot A[i] \;\bigm|\; s \in S_{i-1} \,\bigr\}$$

```text
S_i 를 값으로 만들어 봅니다

  S_0   {2}
  S_1   {-3} ∪ {2 × (-3)}                   = {-6, -3}
  S_2   {-2} ∪ {(-6) × (-2), (-3) × (-2)}   = {-2, 6, 12}
        └ 원소가 칸마다 하나씩 늘지만, 다음 걸음에 쓰이는 것은 양끝 둘뿐이다
```

여기에 곱셈의 성질 하나를 넣습니다. 유한집합 `S` 와 수 `c` 에 대해, `c` 가 0 이상이면 곱셈이
대소 관계를 지키고 `c` 가 음수면 뒤집어요.

$$c \ge 0 \implies \max(cS) = c \cdot \max S \qquad\qquad c < 0 \implies \max(cS) = c \cdot \min S$$

```text
왜 후보가 셋뿐인가

  c ≥ 0 이면   max(cS) = c · max S   곱셈이 대소 관계를 지킨다
  c < 0 이면   max(cS) = c · min S   곱셈이 대소 관계를 뒤집는다
               └ 어느 쪽이든 c · max S 와 c · min S 둘 중 하나라 후보가 둘로 닫힌다
```

`c` 의 부호를 모르는 채로 두 경우를 합치면 `c` 를 곱한 집합의 최댓값이 `c × max S` 와
`c × min S` 중 큰 쪽이 됩니다. 여기에 `A[i]` 하나짜리 후보를 더하면 파트 1 이 값으로 보인
규칙이 식으로 나와요. 임의의 `N` 과 임의의 배열에 대해 얻은 것입니다.

$$mx[i] = \max\bigl(A[i],\; mx[i-1] \cdot A[i],\; mn[i-1] \cdot A[i]\bigr) \qquad (1 \le i \le N-1)$$

```ts
// 정의를 그대로 옮긴 조각. 실제 절차는 이 목록을 만들지 않고 두 수만 이어받는다.
const endingAt = (A: number[], i: number): number[] =>
  Array.from({ length: i + 1 }, (_, l) =>
    A.slice(l, i + 1).reduce((p, v) => p * v, 1),
  );
```

같은 논법을 최솟값에 그대로 적용하면 짝이 되는 식이 나옵니다. 기저는 칸 0 이고, 거기서는 후보가
하나뿐이라 두 값이 같아요.

$$mn[i] = \min\bigl(A[i],\; mx[i-1] \cdot A[i],\; mn[i-1] \cdot A[i]\bigr), \qquad mx[0] = mn[0] = A[0]$$

```text
식과 코드가 같은 것을 부르는 이름
  mx[i]            curMax    칸 i 에서 끝나는 곱의 최댓값
  mn[i]            curMin    같은 칸의 최솟값
  mx[i−1] × A[i]   grown     최댓값에 이어 붙인 후보
  mn[i−1] × A[i]   flipped   최솟값에 이어 붙인 후보
```

위 `endingAt` 조각은 칸 하나를 만드는 데 앞쪽 구간을 다시 다 곱하므로 전부 더하면 `N(N+1)/2`
개의 곱을 만듭니다. 직전 값 둘을 이어받으면 칸 하나가 곱셈 두 번이라 `2(N−1)` 번이에요.
마지막으로 제약 규모를 넣습니다. `|A[i]| ≤ 10` 이므로 `|P(l, r)| ≤ 10^(r−l+1) ≤ 10^N` 이고,
`N = 100,000` 이면 답이 `10^100000` 까지 커질 수 있어요. 그 값이 `number` 에 담기는지를 실제로
확인해 봅니다.

<!--proof:math-limits-->

```text
정확한 정수로 남는 한계 — 전부 10 인 배열
  칸 수             정본이 낸 답                 정확한 답  판정
     22  10000000000000000000000   10000000000000000000000  같다
     23  99999999999999991611392  100000000000000000000000  다르다

표현 범위의 한계 — 같은 배열
  칸 수            정본이 낸 답  정확한 답의 자릿수  판정
    308  9.999999999999998e+307                 309  표현된다
    309                Infinity                 310  표현되지 않는다

제약 규모 N = 100,000 에서
  가장 큰 답                                   10^100,000
  그 답의 자릿수                                  100,001
  double 의 상한                  1.7976931348623157e+308
  값이 정확한 가장 긴 10 의 연속                    22 칸
  표현되는 가장 긴 10 의 연속                      308 칸
  └ 절차의 연산 수는 100,000 칸에서도 699,993 번이고, 먼저 걸리는 것은 답을 담는 그릇이다
```

식이 말하는 것은 **연산 수가 아니라 값의 크기**입니다. 절차는 10 만 칸에서도 70 만 번으로
끝나는데, 답 쪽이 먼저 배정밀도 부동소수점의 한계에 도달해요. 이 가이드의 코드는 그 한계를
그대로 물려받고, 정확한 큰 정수가 필요하면 `BigInt` 나 로그 변환으로 가는 자리입니다.

### 불변식 — curMax 와 curMin 은 칸 i 에서 끝나는 곱의 최댓값과 최솟값이다

파트 1 에서 코드가 동작하는 것을 일곱 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고 그것이
실제로 유지되는지 확인해 봅시다.

> 루프가 칸 `i` 를 처리한 직후, `curMax` 는 `mx[i]` 와 같고 `curMin` 은 `mn[i]` 와 같으며
> `best` 는 `mx[0]` 부터 `mx[i]` 까지의 최댓값과 같습니다.

```text
  curMax 가 뜻하는 것   칸 i 에서 끝나는 부분 배열 중 곱이 가장 큰 것의 곱
  curMin 이 뜻하는 것   같은 후보 중 곱이 가장 작은 것의 곱
  best 가 뜻하는 것     칸 0 부터 칸 i 까지만 놓고 본 이 문제의 답
  언제 참인가           칸 i 를 막 처리한 직후. 걸음 도중에는 세 줄 사이에서 잠깐 어긋난다
```

문장이 셋인 것에 이유가 있습니다. 앞의 둘은 다음 걸음이 이어받을 값을 정하고, 마지막 하나는
**루프가 끝났을 때 `best` 를 그대로 돌려줘도 된다**는 것을 말해요. 셋 중 하나만 빠져도 루프의
세 줄이 왜 그 모양인지 근거가 사라집니다.

**출발점부터 봅시다.** 루프에 들어가기 전 세 값은 모두 `A[0]` 입니다. 칸 0 에서 끝나는 부분
배열이 `[A[0]]` 하나뿐이라 그 곱의 최댓값과 최솟값이 둘 다 `A[0]` 이고, 그 하나가 후보의
전부라 마지막 문장도 참이에요.

| 걸음 | 하는 일 | 앞의 두 문장이 유지되는 근거 | 마지막 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 시작 | 셋 다 `A[0]` 으로 둔다 | 후보가 `[A[0]]` 하나다 | 그 하나가 전부다 |
| `i = 1` | 후보 셋을 만들어 최댓값과 최솟값을 고른다 | 칸 1 에서 끝나는 후보가 둘뿐이다 | `mx[0]` 과 `mx[1]` 중 큰 쪽이 된다 |
| 임의의 `i` | 같은 세 줄을 실행한다 | 직전 걸음이 `mx[i−1]` 과 `mn[i−1]` 을 만들어 뒀다 | 직전 최댓값과 `mx[i]` 를 견준다 |
| 종료 | `i = N−1` 을 마친다 | `curMax` 가 `mx[N−1]` 이다 | `mx[0]` 부터 `mx[N−1]` 까지 전부 |

셋째 줄이 이 논증의 핵심입니다. 칸 `i` 에서 끝나는 부분 배열은 **시작이 `i` 인 것**과 **시작이
`i` 보다 앞인 것** 둘로 완전히 갈리고, 뒤쪽 무리의 곱은 직전 무리의 곱에 `A[i]` 를 곱한 것이라
그 무리의 양끝이 직전 무리의 양끝에서 나와요.

| 후보의 모양 | 그 무리의 최댓값 | 그 무리의 최솟값 | 근거 |
| --- | --- | --- | --- |
| 시작이 칸 `i` 다 | `A[i]` | `A[i]` | 그런 후보가 `[A[i]]` 하나뿐이다 |
| 시작이 칸 `i` 보다 앞이다 | `mx[i−1] × A[i]` 와 `mn[i−1] × A[i]` 중 큰 쪽 | 그 둘 중 작은 쪽 | 곱셈이 `A[i]` 의 부호에 따라 대소 관계를 지키거나 뒤집는다 |
| 두 무리를 합치면 | 셋 중 가장 큰 것 | 셋 중 가장 작은 것 | 두 무리가 겹치지도 빠지지도 않는다 |

둘째 줄의 `mn[i−1]` 이 앞의 두 문장에서 옵니다. 최솟값 문장이 참이라 그 자리에 쓸 수 있는
것이고, 그래서 세 문장이 서로를 떠받쳐요. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

```text
경계                       입력        끝난 뒤 curMax  끝난 뒤 curMin     답
칸이 하나이고 값이 양수다  [7]                      7               7      7
칸이 하나이고 값이 음수다  [-7]                    -7              -7     -7
칸이 하나이고 값이 0 이다  [0]                      0               0      0
칸이 둘이다                [-10 -10]              100             -10    100
값이 전부 음수다           [-4 -3 -2]               6             -24     12
값이 전부 양수다           [2 3 4]                 24               4     24
값이 전부 0 이다           [0 0 0]                  0               0      0
0 이 가운데를 끊는다       [-2 0 -1]                0              -1      0
값이 전부 최댓값 10 이다   [10 10 10]           1,000              10  1,000

└ 칸이 하나면 루프가 한 번도 실행되지 않아 세 값이 A[0] 그대로 남는다
```

칸이 하나뿐인 입력은 루프가 한 번도 실행되지 않아 세 값이 `A[0]` 그대로 남고, 값이 전부 음수인
입력은 음수를 짝수 개 고른 구간이 답이 됩니다. 값이 전부 0 인 입력에서는 후보 셋이 언제나 0
이라 두 값이 함께 0 으로 남아요.

**이제 깨뜨려 봅시다.** 최솟값 문장을 지키던 줄은 `curMin` 을 정하는 그 한 줄이에요. 「최솟값은
어차피 최댓값을 고르고 남은 것이니 직전 최솟값까지 볼 필요가 있나」라는 생각으로 그 줄에서
이어받는 후보 하나를 빼 봅니다.

```ts
curMin = Math.min(x, grown);   // 직전 최솟값을 이어받는 후보를 뺐다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-min-no-carry-->

```text
입력                        정본이 낸 답  이어받기를 뺀 답  판정
전개 입력 [2 -3 -2 4 0 -1]            48                48  같다
[-3 2 5 -4]                          120                10  틀리다
[-2 3 3 -3]                           54                 9  틀리다
[2 3 4]                               24                24  같다
[-10 -10]                            100               100  같다

[-3 2 5 -4] 에서 칸마다의 최솟값
  칸 번호                0   1    2    3
  정본의 curMin         -3  -6  -30  -40
  이어받기를 뺀 curMin  -3  -6    5  -40
  └ 칸 2 에서 갈리고, 칸 3 의 부호 뒤집기가 그 값을 쓰는 순간 답이 어긋난다
```

최솟값 문장이 깨지면 `curMin` 의 뜻이 바뀌고, 그러면 다음 걸음의 후보 3 이 아무것도 아닌 값을
곱하게 됩니다. `curMax` 는 여전히 세 후보 중 가장 큰 것이지만 그 후보 하나가 거짓이에요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 무리입니다 — 세 값을 시작값으로 두는 것, 칸마다 후보 셋을 만들어
두 값을 정하고 최댓값을 갱신하는 것, 답을 돌려주는 것이에요. 전개의 걸음으로 확인하면 이렇게
나뉩니다.

<!--proof:perf-count-->

```text
무리    어느 걸음인가    걸음 수  걸음마다 곱셈  걸음마다 비교  이 입력에서
초기화  T1                     1              0              0            0
순회    T2 부터 T6 까지        5              2              5           35
반환    T7                     1              0              0            0
합계                                                                     35

└ 곱셈 10 번과 비교 25 번이고, 둘 다 칸 수 6 에서만 나온 수다
```

T1 과 T7 은 값을 옮기기만 하는 자리라 곱셈도 비교도 없습니다. 그래서 이 입력의 기본 연산이
35 번이에요.

```text
총식
  초기화    0
  순회      7(N − 1)   칸마다 곱셈 2 · 비교 5
  반환      0
  합계      7N − 7     N = 6 이면 35 로 위 표와 같다
  읽는 칸   N 번       칸마다 A[i] 를 한 번씩 읽는다
```

**연산 수가 입력의 내용과 무관하게 정해집니다.** 값이 양수든 음수든 0 이든, 답이 앞에서 끝나든
뒤에서 끝나든 걸음 수가 같아요 — 칸마다 하는 일이 곱셈 둘과 비교 다섯으로 고정이기 때문입니다.

```text
여기서 센 것은 곱셈과 비교 전부다
  추가로 잡는 메모리   값 세 개 (curMax · curMin · best)
  안 센 것             배열 읽기 N 번과 루프 변수 증가 N−1 번
                       둘 다 칸 수에 비례하므로 총식의 차수는 그대로다
                       └ mx 와 mn 을 배열로 만드는 방식이면 여기에 칸 2N 개가 더 붙는다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (칸이 하나다) | `O(N)` | `Θ(1)` — 루프가 한 번도 실행되지 않는다 |
| **평균적인 경우** (입력 분포와 무관하다) | `O(N)` | `Θ(N)` |
| **최악의 경우** (칸이 `N` 개다) | `O(N)` | `Θ(N)` — 실제로 도달한다 |

가운데와 아래 줄이 같은 것이 이 절차의 성질입니다. 걸음 수가 칸 수 하나로 고정이라 입력의
값을 어떻게 바꿔도 연산 수가 같아요.

```text
상한과 타이트한 값을 가르는 자리
  O(N)   이 절차의 연산 수가 그보다 크지 않다는 것만 말한다      상한이다
  Θ(N)   위아래로 같은 차수라 실제로 그만큼 든다는 것도 말한다   타이트한 값이다
         └ 이 절차는 칸마다 반드시 일곱 번을 세므로 Θ 로 적을 수 있다
```

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리가 하나도 없다는 것이 이 절차의
특징이에요 — 정렬도, 접두 곱 배열도, 트리 만들기도 하지 않습니다.

```text
총식 = Θ(N) 시간 + Θ(1) 추가 메모리
       │           └ 값 세 개
       └ 곱셈 2(N−1) · 비교 5(N−1) · 읽기 N

N = 100,000 이면 기본 연산이 정확히 699,993 번, 잡는 칸이 3 개다
```

**보장의 종류는 전부 최악 보장입니다.** 해시도, 무작위성도, 분할 상환도 쓰지 않아요 — 어떤
입력을 넣어도 연산 수가 `7N − 7` 로 같습니다.

```text
기댓값이 끼어들 자리가 없다
  칸을 찾는 방법   칸 번호로 바로 간다       해시 충돌이라는 개념이 없다
  걸음 수          입력을 안 보고 정해진다   분포를 가정할 필요가 없다
  칸 하나의 비용   항상 곱셈 2 · 비교 5      평균이 아니라 상수다
                   └ 최악 보장과 평균 비용이 같은 수다
```

#### 최악을 만드는 입력

연산 수를 최대로 만드는 방법은 하나뿐입니다 — **`N` 을 제약의 최댓값으로 두는 것**이에요. 값의
모양은 연산 수를 바꾸지 못합니다. 그것을 값으로 확인해 봅시다.

<!--proof:worst-shape-->

```text
입력의 모양 (N = 1,000)           곱셈   비교  기본 연산        답
전부 1 이다                      1,998  4,995      6,993         1
전부 -1 이다                     1,998  4,995      6,993         1
1 과 -1 이 번갈아 나온다         1,998  4,995      6,993         1
한 칸만 10 이고 나머지는 0 이다  1,998  4,995      6,993        10
전부 10 이다                     1,998  4,995      6,993  Infinity

가운데 세 열이 다섯 줄 다 같고 오른쪽 열만 다르다
마지막 줄은 답이 double 의 표현 범위를 넘은 자리이고, 연산 수는 그때도 같다
```

**「음수가 많으면 갈래를 더 자주 갈아 느리다」는 이 절차에서 거짓입니다.** 물려받은 통념이
여기서는 성립하지 않아요 — 둘째 줄은 음수만으로 이루어졌고 첫째 줄은 양수만으로 이루어졌는데
연산 수가 둘 다 6,993 입니다. 후보 셋에서 최댓값과 최솟값을 고르는 비교가 어느 것이 골라지든
같은 횟수이기 때문이에요.

```text
최악은 축마다 다른 입력이 만든다
  연산 수의 최악   N = 100,000          값의 모양과 무관하다. 699,993 번
  잡는 칸의 최악   어떤 입력이든 같다   값 세 개
  답 크기의 최악   10 을 100,000 칸     10^100,000 이라 number 로 표현되지 않는다
                   └ 앞의 둘은 N 만 보고, 셋째만 값을 본다
```

값의 크기가 최악이 되는 입력은 따로 만들어야 합니다. 모든 칸이 최댓값 10 이면 전체 곱이 답이
되고, 그 값은 제약 안에서 가장 크되 `number` 로는 담기지 않아요.

| 최악으로 만들 축 | 입력 | 값 |
| --- | --- | --- |
| 연산 수 | `N = 100,000`, 값은 무엇이든 | 699,993 |
| 잡는 칸 | 어떤 입력이든 | 3 |
| 답의 크기 | `10` 이 100,000 칸 | `10^100000` — `number` 로 표현되지 않는다 |

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 오른쪽 끝을 칸 하나에 고정해 후보를 **셋**으로
줄였고, 곱셈이 음수에서 대소 관계를 뒤집으므로 최솟값을 함께 이어받아야 하며, 답은 마지막 칸의
값이 아니라 **지나온 최댓값들의 최댓값**입니다.

```text
한 걸음이 하는 일
  1.   curMax · curMin · best 를 A[0] 으로 둔다   값 세 개
  2.   칸마다 후보 셋에서 두 값을 함께 정한다     곱셈 2 · 비교 4
  3.   best 와 curMax 중 큰 쪽을 best 에 적는다   비교 1
```

먼저 답이 붙는 문제 하나입니다. 전개의 T5 는 `A[4] = 0` 을 처리한 걸음이었고, `curMax` 와
`curMin` 이 함께 0 으로 내려갔어요. 그런데 이 걸음에서도 `best` 는 48 을 그대로 들고 있습니다.
0 을 지나면 이어받은 값이 다 사라지는데, 왜 답은 안 사라질까요?

```text
  T5   A[4] = 0   후보 0 · 0 · 0   curMax = 0 · curMin = 0   best = 48 그대로
       └ 이어받은 두 값이 함께 0 이 되었고 best 만 살아남았다
```

<!--check:whyBestSurvives-->
`best` 와 `curMax` 가 **다른 것을 뜻하기** 때문입니다. `curMax` 는 「칸 `i` 에서 **끝나는**
곱의 최댓값」이라 칸 4 를 지나면 그 자리에서 끝나는 구간만 보고, 0 이 들어간 구간의 곱은 전부
0 이에요. `best` 는 「칸 0 부터 칸 `i` 까지 **어디서 끝나든** 가장 큰 곱」이라 칸 3 에서 만든
48 을 계속 들고 있습니다.

```text
두 값이 보는 범위
  curMax   오른쪽 끝이 칸 i 인 후보만       0 이 들어가면 함께 0 이 된다
  best     오른쪽 끝이 칸 0 부터 칸 i 까지  앞에서 만든 값이 남는다
           └ 그래서 0 은 이어받기를 끊을 뿐 답을 지우지 못한다
```

이 성질이 「멈춤」 셋째 절의 반례와 같은 자리입니다. `best` 없이 `curMax` 를 돌려주면 칸 4 의
0 이 답을 통째로 지워요.
<!--/check-->
