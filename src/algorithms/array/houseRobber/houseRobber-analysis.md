# houseRobber 솔루션 분석

## 1. 접근 방향 분석

메인 엔트리 `houseRobber`는 `houseRobberDp1`(변수 2개 롤링 DP)에 위임한다. 이 방향은 올바르며, 이 문제에 대해 점근적으로 최적인 접근이다.

- 상태 정의: $f(i)$ = "인덱스 $0$부터 $i$까지의 집만 고려했을 때, 인접 선택 금지 조건 아래 얻을 수 있는 최대 합"
- 점화식: $f(i) = \max\bigl(f(i-1),\; f(i-2) + nums[i]\bigr)$
- 기저: $f(-1) = 0$, $f(0) = nums[0]$
- 답: $f(N-1)$

파일에는 세 단계의 구현이 공존한다.

| 함수 | 방식 | 시간 | 공간 |
|------|------|------|------|
| `houseRobberNaive` | 순수 재귀 | $O(2^N)$ | $O(N)$ (콜스택) |
| `houseRobberDp2` | 1D 테이블 바텀업 | $O(N)$ | $O(N)$ |
| `houseRobberDp1` (현재 사용) | 변수 2개 롤링 | $O(N)$ | $O(1)$ |

## 2. 정확성 분석

### 테스트 결과 요약

```
bun test src/algorithms/array/houseRobber/houseRobber.test.ts

```

| 그룹 | 테스트 | 결과 |
|------|--------|------|
| 기본 | `[1,2,3,1] → 4`, `[2,7,9,3,1] → 12`, `[2,1,1,2] → 4` | ✅ |
| 엣지 | 빈 배열 → 0, `[0,0,0] → 0`, `[5,5,5,5,5] → 15`, `[1,3,1] → 3` | ✅ |
| 바운더리 | N=1 → `nums[0]`, N=2 → 큰 값, `[10000,1,10000] → 20000` | ✅ |
| 성능 | N=100,000을 100ms 이내 처리 | ✅ |

### `houseRobberDp1` (메인 경로) 검증

- $N = 0$: `nums.length === 0` 가드로 0 반환. 올바르다.
- $N = 1$: `nums[1] !== undefined ? nums[1] : prev` 분기로 `cur = max(nums[0], nums[0]) = nums[0]`. 루프는 실행되지 않고 `cur` 반환. 올바르다.
- $N \geq 2$: 루프 불변식 — $i$번째 반복 시작 시점에 `prev` $= f(i-2)$, `cur` $= f(i-1)$. 갱신식 `cur = max(cur, prev + nums[i])`는 점화식과 정확히 일치하고, `tmpPrev`로 갱신 전의 `cur`를 보존해 `prev`로 넘긴다. 올바르다.

### 잠재 결함 — `houseRobberDp2`의 N=1 경계 (현재 미사용 경로)

`houseRobberDp2`는 테스트가 실행하지 않는 경로이지만(엔트리가 Dp1만 호출), $N = 1$ 입력에서 결함이 있다.

```ts
const dp = Array.from({ length: nums.length }, () => 0); // N=1이면 길이 1
dp[0] = nums[0]!;
dp[1] = Math.max(dp[0]!, nums[1]!); // nums[1]은 undefined
```

- `nums[1]`은 `undefined`인데 `!` 단언으로 타입 검사를 우회한다 (`noUncheckedIndexedAccess`의 보호를 무력화).
- `Math.max(x, undefined)`는 `NaN`이므로 `dp[1] = NaN`이 배열 범위 밖(길이 1인 배열의 인덱스 1)에 기록된다.
- 반환값은 `dp[nums.length - 1] = dp[0]`이라 **결과는 우연히 올바르지만**, `NaN`을 범위 밖에 쓰는 코드는 이후 수정 시 버그로 발현될 수 있는 잠재 결함이다.

수정안: `dp[1]` 대입 전에 `if (nums.length === 1) return nums[0]!;` 가드를 추가하거나, Dp1처럼 `nums[1] !== undefined` 분기를 사용한다.

### `houseRobberNaive`의 한계 (설계상 의도된 참조 구현)

- 시간 $O(2^N)$: 제약 $N \leq 100{,}000$에서는 시간 제한 1초를 초과한다.
- 재귀 깊이가 $N$에 비례하므로 큰 $N$에서 콜스택 오버플로가 발생한다.
- 메인 엔트리가 호출하지 않으므로 제출 정확성에는 영향이 없다.

### 테스트 커버리지 참고

테스트는 `houseRobber`(= Dp1)만 검증한다. `houseRobberDp2`와 `houseRobberNaive`는 어떤 테스트도 거치지 않으므로, 위 잠재 결함이 테스트로 드러나지 않는다. 세 구현을 같은 케이스 셋으로 교차 검증하면(단, Naive는 작은 $N$만) 커버리지 공백이 해소된다.

## 3. 최적화 분석

현재 메인 경로(`houseRobberDp1`)는 시간 $O(N)$, 추가 공간 $O(1)$이다.

**점근적으로 더 이상의 개선은 불가능하다.** 모든 원소를 최소 한 번 읽지 않으면 답을 확정할 수 없으므로 시간 하한은 $\Omega(N)$이고, 추가 공간 $O(1)$은 이미 최소이다. 성능 테스트(N=100,000)도 100ms 한도 내에서 통과한다.

### 3.1 핵심 아이디어 (현재 구현이 도달한 지점의 정리)

문제의 답은 "마지막 집을 선택했는가"라는 단 하나의 이분법으로 분해된다.

1. 집이 $0$번부터 $i$번까지 있다고 하자. 최적 선택은 반드시 다음 두 경우 중 하나에 속한다.
   - **경우 A — $i$번 집을 선택하지 않음**: 남은 문제는 "$0$번부터 $i-1$번까지에서의 최대 합"이며, 그 값은 정의에 의해 $f(i-1)$이다.
   - **경우 B — $i$번 집을 선택함**: 인접 금지 조건에 의해 $i-1$번 집은 선택할 수 없다. 남은 문제는 "$0$번부터 $i-2$번까지에서의 최대 합"이며, 그 값은 $f(i-2)$이다. 따라서 이 경우의 값은 $f(i-2) + nums[i]$이다.
2. 두 경우 외의 선택은 존재하지 않고($i$번 집은 선택하거나 하지 않거나 둘 중 하나), 두 경우 각각에서 최적값을 취했으므로:
   $$f(i) = \max\bigl(f(i-1),\; f(i-2) + nums[i]\bigr)$$
3. $f(i)$를 계산하는 데 필요한 과거 값은 $f(i-1)$과 $f(i-2)$ **두 개뿐**이다. $f(i-3)$ 이전 값은 어떤 계산에도 참조되지 않는다. 따라서 길이 $N$의 테이블을 유지할 필요 없이, 변수 두 개(`prev` $= f(i-2)$, `cur` $= f(i-1)$)만 유지하며 앞으로 굴리면 공간이 $O(N) \to O(1)$로 줄어든다.

### 3.1.1 알고리즘 원형에서의 전개 과정

원형은 **선형 DP**(1차원 순차 결정 문제)이며, 그래프 용어로는 "경로 그래프에서의 최대 가중 독립 집합(maximum weight independent set on a path)"이다. 전개는 네 단계다.

**단계 1 — 완전 탐색 재귀 (`houseRobberNaive`)**: $O(2^N)$

$i$번 집에서 "선택 / 비선택" 두 가지로 분기한다.

```
recursive(i):
    if i < 0: return 0
    skip    = recursive(i - 1)            # i번 집 비선택
    applied = recursive(i - 2) + nums[i]  # i번 집 선택
    return max(skip, applied)
```

각 호출이 두 개의 하위 호출을 만들므로 호출 횟수는 $N$에 대해 지수적으로 증가한다.

**단계 2 — 중복 부분 문제의 발견 → Memoization**: $O(2^N) \to O(N)$

재귀의 상태는 정수 $i$ 하나이고, $i$가 가질 수 있는 값은 $-2$부터 $N-1$까지 총 $N+2$가지뿐이다. 호출 트리는 $O(2^N)$개의 노드를 갖지만 서로 다른 상태는 $O(N)$개이므로, 상태별 결과를 캐시하면 각 상태는 한 번만 계산되어 전체 시간이 $O(N)$이 된다.

**단계 3 — 바텀업 테이블 (`houseRobberDp2`)**: 공간 $O(N)$

재귀 방향을 뒤집어, 작은 $i$부터 큰 $i$ 순서로 테이블을 채운다.

- `dp[0] = nums[0]`
- `dp[1] = max(nums[0], nums[1])`
- $i \geq 2$: `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`
- 답: `dp[N-1]`

콜스택이 사라지고 접근 패턴이 순차적이 된다. 시간 $O(N)$, 공간 $O(N)$.

**단계 4 — 의존성 폭 분석 → 변수 롤링 (`houseRobberDp1`)**: 공간 $O(N) \to O(1)$

`dp[i]` 계산이 참조하는 칸은 `dp[i-1]`, `dp[i-2]` 정확히 두 개다. 즉 의존성의 폭이 상수 2이므로, 테이블 대신 두 변수만 유지한다.

| 시점 | `prev` | `cur` |
|------|--------|-------|
| $i$번째 반복 시작 | $f(i-2)$ | $f(i-1)$ |
| $i$번째 반복 종료 | $f(i-1)$ | $f(i)$ |

갱신 순서가 중요하다. `cur`를 덮어쓰기 **전에** 기존 `cur`( $= f(i-1)$ )를 `tmpPrev`에 보존해야, 갱신 후 `prev`에 정확히 $f(i-1)$이 들어간다. 현재 구현은 이 순서를 지키고 있다.

| 구현 | 시간 | 공간 |
|------|------|------|
| Naive 재귀 | $O(2^N)$ | $O(N)$ |
| Memoized 재귀 | $O(N)$ | $O(N)$ |
| 1D 바텀업 (`houseRobberDp2`) | $O(N)$ | $O(N)$ |
| 변수 롤링 (`houseRobberDp1`, 현재) | $O(N)$ | $O(1)$ |

## 4. 요약

- 접근 방향: 올바르다. 선형 DP의 최종 최적화 단계(변수 롤링)까지 도달했다.
- 정확성: 메인 경로 기준 결함 없음. 테스트 11/11 통과.
- 잠재 결함 1건: `houseRobberDp2`의 $N=1$ 입력에서 `nums[1]!` 단언으로 `NaN`이 배열 범위 밖에 기록됨(반환값은 우연히 정상, 현재 미사용 경로).
- 최적화 여지: 점근적으로 없음. 시간 $O(N)$ / 공간 $O(1)$이 이 문제의 하한이다.
