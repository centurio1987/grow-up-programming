# slidingWindowMaximum — 왼쪽 끝이 빠진 뒤에 답이 될 자리를 미리 줄 세워 두는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

창이 한 칸 이동할 때 무엇이 달라지는지부터 확인하고, 그 변화를 최댓값 하나로는 감당하지
못한다는 것을 값으로 봅니다. 거기서 후보를 줄 세우는 규칙을 세우고 실제로 동작하는 코드까지
조각으로 만듭니다.

### 전체 컨셉

정수 배열 `nums` 와 창의 칸 수 `k` 를 받아, 크기 `k` 인 창이 왼쪽에서 오른쪽으로 한 칸씩
이동하며 지나는 **모든 위치의 최댓값**을 순서대로 답해야 합니다. 창의 위치가 `N − k + 1` 개
이므로 답도 그만큼 나와요.

```text
nums = [1 3 -1 -3 5 3 6 7] · k = 3

자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
창 [0,2]      #   #   #                      최댓값 3
창 [1,3]          #   #   #                  최댓값 3
창 [2,4]              #   #   #              최댓값 5
창 [3,5]                  #   #   #          최댓값 5
창 [4,6]                      #   #   #      최댓값 6
창 [5,7]                          #   #   #  최댓값 7
                                             └ 답은 [3 3 5 5 6 7] 여섯 개다
```

창마다 `k` 칸을 처음부터 다시 읽으면 답 하나에 `k` 번을 읽으니, 읽기만 세도 전체가
`k(N − k + 1)` 번입니다.
그런데 이웃한 두 창은 `k − 1` 칸을 그대로 공유해요. 창이 한 칸 이동할 때 실제로 달라지는
것은 **양 끝 둘뿐**입니다.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
창 [2,4]              #   #   #              최댓값 5
창 [3,5]                  #   #   #          최댓값 5
                   빠짐        들어옴
```

새로 들어오는 칸은 다루기 쉽습니다 — 들어온 값이 지금까지의 최댓값보다 크면 그것이 새
최댓값이에요. 문제는 빠져나가는 칸입니다. **그 칸이 그 창의 답이었으면, 남은 `k − 1` 칸 중
누가 그 자리를 이어받는지 알 수 없습니다.**

```text
nums = [5 9 1 3 1 1] · k = 3 에서 최댓값 하나와 그 자리만 기억하면

자리          0   1   2   3   4   5
값            5   9   1   3   1   1
창 [0,2]      #   #   #              최댓값 9  자리 1 이 창 안이라 그대로 쓴다
창 [1,3]          #   #   #          최댓값 9  자리 1 이 아직 창 안이다
창 [2,4]              #   #   #      최댓값 3  자리 1 이 창을 벗어났다 — 남은 셋을 다시 세야 한다
창 [3,5]                  #   #   #  최댓값 3  다시 세어 얻은 자리 3 이 창 안이라 그대로 쓴다
```

그래서 「지금의 최댓값」 하나가 아니라 **「왼쪽 끝이 빠진 뒤에 답이 될 자리」까지 함께**
들고 있어야 합니다. 무엇을 들고 있어야 하는지는 규칙 하나로 정해져요 — 지금 자리 `u` 를
읽었는데 그보다 **왼쪽에 있으면서 값이 더 작은** 자리 `t` 가 남아 있으면, `t` 는 앞으로
어떤 창에서도 답이 될 수 없습니다. 답을 아직 안 낸 창은 오른쪽 끝이 `u` 이상인 것들뿐이고,
그중 `t` 를 담은 창은 `t < u` 이므로 `u` 도 함께 담기 때문이에요.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
                      t       u
                      └ 자리 4 를 읽은 시점에 아직 답을 안 낸 창은 [2,4] · [3,5] · [4,6] · [5,7] 넷이고
                        그중 자리 2 를 담은 것은 [2,4] 하나인데 거기에 자리 4 도 들어 있다
                        그 창의 최댓값은 5 이상이라 값 -1 인 자리 2 는 답이 될 일이 없다 — 버려도 된다
```

이 규칙으로 걸러 내고 남은 자리들은 저절로 한 방향으로 놓입니다. 자리 번호가 커지는 방향
으로 값이 커지지 않아요 — 커지는 짝이 있었다면 왼쪽 것이 이미 버려졌을 테니까요. 담는 통에
필요한 연산이 셋인데, **한쪽 끝에서만 넣고 빼는 통으로는 안 됩니다.**

```text
표기 약속 — 통에 든 자리 번호를 [1 2 3] 꼴로 나열해 적는다

  왼쪽 끝    창의 왼쪽에 가장 가까운 자리이고 이 글은 **앞**이라 부른다
  오른쪽 끝  방금 붙인 자리이고 이 글은 **뒤**라 부른다

  한 걸음이 하는 일 셋
    1. 창을 벗어난 자리를 **앞**에서 버린다
    2. 지금 값보다 작은 자리를 **뒤**에서 버린다
    3. 지금 자리를 **뒤**에 붙인다
       └ 뒤에서 넣고 빼면서 앞에서도 버려야 한다. 양쪽 끝을 다 쓰는 통이 덱이다
```

그러면 창이 다 찰 때마다 **통의 앞이 그 창의 답**입니다. 값이 앞에서 뒤로 커지지 않으므로
가장 큰 것이 앞에 있고, 앞에 남아 있다는 것은 창 안이라는 뜻이니까요. 자리 하나가 한 번
들어가고 많아야 한 번 나오므로 전체 비용이 `O(N)` 이고, `k` 는 거기 들어가지 않습니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **배열의 인덱스.** 자리 번호는 0 부터 세고, `nums[3]` 은 네 번째 칸의 값입니다.
- **창(윈도우)과 그 위치.** 이 글은 왼쪽 끝이 `a` 이고 오른쪽 끝이 `b` 인 창을 `[a,b]` 로
  적습니다. 칸 수가 `k` 이면 `b = a + k − 1` 이에요.
- **덱.** 양쪽 끝에서 넣고 뺄 수 있는 담는 통입니다. 넣기 · 앞에서 빼기 · 뒤에서 빼기 ·
  앞 보기가 각각 한 번에 끝나요. 흐릿하면
  [`deque`](../../../data-structures/linear/deque/deque-guide.md) 를
  먼저 봅니다.
- **`O(N)` 표기.** 비용이 입력 길이에 비례한다는 뜻이고, 여기서는 배열을 한 번 차례로 읽는
  것과 같은 규모입니다.

「구간마다 무엇을 구한다」는 말만으로는 절차가 안 정해집니다. **구간의 길이가 고정인가**와
**무엇을 묻는가**가 함께 있어야 갈려요.

```text
nums = [1 3 -1 -3 5 3 6 7] 에서
  길이 3 인 창마다 최댓값             [3 3 5 5 6 7]       ← 이 글이 답하는 것
  길이 3 인 창마다 최솟값             [-1 -3 -3 -3 3 3]   ← 부등호만 뒤집으면 된다
  길이 3 인 창마다 합                 [3 -1 1 5 14 16]    ← 이 글은 안 한다. 누적합 한 줄로 끝난다
  자리마다 오른쪽에서 처음 더 큰 값   [3 5 5 5 6 7 7 -1]  ← 이 글은 안 한다. 창이 없다
  묻는 구간의 길이가 질의마다 다르다  —                   ← 이 글은 안 한다. 앞뒤가 함께 움직인다
```

합처럼 모든 칸이 값에 기여하는 것은 누적합 쪽이고, 창 없이 자리마다 답하는 문제는
[`nextGreaterElement`](../nextGreaterElement/nextGreaterElement-problem.md) 쪽입니다. 길이가
질의마다 다른 구간 최댓값은
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 쪽이에요.

### 아이디어 상세 — 앞으로 답이 될 자리를 줄 세우는 방법을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
export function slidingWindowMaximum(nums: number[], k: number): number[];
```

- 입력: 정수 배열 `nums` 와 창의 칸 수 `k`.
- 출력: 창이 지나는 각 위치의 최댓값을 순서대로 담은 배열. 길이가 `N − k + 1` 입니다.
- 제약: `1 ≤ N ≤ 100,000`, `1 ≤ k ≤ N`, `−10,000 ≤ nums[i] ≤ 10,000`. 시간 1 초,
  메모리 256 MB.

여기서 쓰는 기호는 열입니다. 표에 없는 이름은 처음 나오는 자리에서 바로 정의해요.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `N` | 배열 `nums` 의 길이 | `1 ≤ N ≤ 100,000` |
| `k` | 창의 칸 수 | `1 ≤ k ≤ N` |
| `nums[i]` | 배열의 `i` 번째 값. 0 부터 셉니다 | `−10,000` 이상 `10,000` 이하 |
| `i` | 지금 읽고 있는 자리이자 창의 오른쪽 끝 | `0 ≤ i < N` |
| `cand` | 앞으로 답이 될 수 있는 자리를 담는 통 | 값이 아니라 자리 번호를 담습니다 |
| `front` | `cand` 의 맨 앞이 가리키는 자리 | 통이 비면 없습니다 |
| `result` | 창마다의 답을 순서대로 담은 배열 | 길이가 `N − k + 1` 입니다 |
| `P` | 한 번의 실행에서 **뒤**에서 버린 후보의 수 | `0 ≤ P ≤ N − 1` |
| `F` | 창을 벗어나 **앞**에서 버린 후보의 수 | `0 ≤ F ≤ N − 1` |
| `B` | 버릴 것이 남았는데도 조건이 안 맞아 멈춘 걸음의 수 | `0 ≤ B ≤ N − 1` |

가장 먼저 떠오르는 방법으로 시작합시다. 정의를 글자 그대로 옮기는 것이에요 — 창 하나마다
그 안의 `k` 칸을 처음부터 차례로 읽어 가장 큰 값을 찾습니다.

```ts
for (let i = 0; i + k <= n; i++) {
  let best = nums[i] ?? 0;
  for (let j = i + 1; j < i + k; j++) {
    const v = nums[j] ?? 0;
    if (v > best) best = v; // 창 하나에 k 칸을 다시 읽는다
  }
  result.push(best);
}
```

답은 맞습니다. 문제는 창의 개수와 창의 크기가 **곱해진다**는 것이에요.

<!--proof:rescan-scale-->

```text
           N       k  창마다 다시 세기 · 자료 접근  이 절차 · 자료 접근
       1,000     100                        91,001               10,644
      10,000   1,000                     9,010,001              106,921
100,000 (식)  10,000                   900,100,001            1,069,781

└ 입력은 nums[i] = (2731 i) mod 1201 이다. 창마다 다시 세기는 어느 입력에서나 같은 횟수다
  다시 세기는 (k+1)(N−k+1) 로 커진다. k 를 50,000 로 두면 2,500,100,001 이다
```

제약 상한 `N = 100,000` 에 `k = 10,000` 을 넣으면 자료 접근이 **9 억 번**입니다. 단순 연산을
초당 1 억 번으로 잡아도 9 초가 걸려요. `k` 를 절반인 50,000 으로 두면 25 억 번이 됩니다.
시간 제한이 1 초이니 이 방법으로는 안 됩니다.

같은 칸을 몇 번씩 다시 읽는지 작은 입력에서 봅시다. 창 `[0,2]` 와 창 `[1,3]` 은 두 칸을
공유하는데, 위 코드는 그 두 칸을 각각 다시 읽어요.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
창 [0,2]      #   #   #                      최댓값 3
창 [1,3]          #   #   #                  최댓값 3
공유하는 칸       =   =                      두 칸이 겹친다
```

겹치는 두 칸의 최댓값 3 은 두 창이 함께 쓰는 값입니다. 그러니 창이 한 칸 이동할 때 **바뀐
것만 반영**하면 될 것 같아요. 그 생각을 가장 단순하게 옮기면 「지금까지의 최댓값과 그 자리를
하나만 기억한다」가 됩니다.

```ts
if (at <= i - k) {
  // 기억하던 자리가 창을 벗어났다 — 남은 k 칸을 다시 센다
  best = Number.NEGATIVE_INFINITY;
  for (let j = Math.max(0, i - k + 1); j <= i; j++) { /* … */ }
} else if (v >= best) {
  best = v; // 새 값이 더 크면 그것으로 갱신한다
  at = i;
}
```

세 방식을 같은 입력에 적용해 자료 접근 수를 나란히 재 봅시다. 입력은 두 벌이에요 — 값이 골고루
섞인 `nums[i] = (2731 i) mod 1201` 인 1,024 칸과, 같은 길이의 감소 수열입니다.

<!--proof:three-ways-->

```text
입력         창마다 다시 세기  최댓값 하나만  그중 다시 센 걸음  후보를 줄 세우기  세 답이
곱셈 나머지            32,769          2,433                 13            11,012  같다
감소 수열              32,769         33,761                992             9,088  같다

└ N = 1,024 · k = 32 이고 자료 접근 수를 센다. 세 방식의 답은 모두 같다
  곱셈 나머지는 nums[i] = (2731 i) mod 1201 이고, 감소 수열은 nums[i] = N − i 다
```

**두 줄이 반대 방향으로 갈립니다.** 값이 골고루 섞인 입력에서 「최댓값 하나만」은 2,433 번으로
가장 적어요 — 1,024 걸음 중 다시 센 것이 13 번뿐입니다. 그런데 감소 수열에서는 33,761 번으로
**창마다 다시 세는 32,769 번보다도 많습니다.** 1,024 걸음 중 992 번을 다시 세면서, 기억하고
갱신하는 몫까지 더해지기 때문이에요.

여기서 비용이 무엇에 달렸는지가 확인됩니다 — **답이 창을 벗어나는 횟수**입니다. 그 횟수는
입력의 모양이 정하고 우리가 고를 수 없어요. 그러니 「하나만 기억한다」를 고쳐야 하는데,
고칠 방향은 **다시 세는 일 자체를 없애는 것**입니다.

```text
답이 창을 벗어났을 때 무엇이 필요한가

  창 [1,3] 의 답이 자리 1        다음 창 [2,4] 에서 자리 1 이 빠진다
  남은 자리 2 · 3 · 4 중 하나가 새 답이다
      └ 그 하나를 그때 찾으면 k 칸을 다시 세야 한다.
        미리 알고 있었다면 다시 셀 일이 없다 — 그 「미리」가 이 절차의 전부다
```

무엇을 미리 알고 있어야 하는지는 「전체 컨셉」의 규칙이 정합니다. 이미 읽은 자리 중에 `t`
오른쪽에 있으면서 값이 더 큰 것이 있으면 `t` 는 버려도 되고, 없으면 남겨야 해요. 그 규칙을
전개 입력에 걸음마다 적용하면 통의 내용이 이렇게 정해집니다.

```text
걸음  자리 i  통(앞→뒤)  그 자리의 값  이 걸음이 버린 것                       답
T1    0       [0]        1             없다                                    —
T2    1       [1]        3             뒤에서 자리 0                           —
T3    2       [1 2]      3 -1          없다                                    3
T4    3       [1 2 3]    3 -1 -3       없다                                    3
T5    4       [4]        5             앞에서 자리 1 · 뒤에서 자리 3 · 자리 2  5
T6    5       [4 5]      5 3           없다                                    5
T7    6       [6]        6             뒤에서 자리 5 · 자리 4                  6
T8    7       [7]        7             뒤에서 자리 6                           7
```

**버리는 방향이 둘이라는 것이 여기서 확인됩니다.** 뒤에서 버리는 것은 「오른쪽에 더 큰 값이
생겼다」이고, 앞에서 버리는 것은 「창을 벗어났다」예요. T5 가 둘을 함께 하는 걸음입니다.
그리고 두 가지가 함께 정해집니다 — 통에는 창 안의 자리만 담으므로 크기가 `k` 를 못 넘고,
자리 하나가 한 번 들어가 많아야 한 번 나오므로 넣고 빼는 일의 총수가 `2N` 을 못 넘어요.
이제 `k` 를 바꿔 가며 실제로 재 봅시다 — 창마다 다시 세기가 `k` 를 따라 어떻게 커지는지,
이 절차는 어떤지, 통이 얼마나 깊어지는지를 함께 봅니다.

<!--proof:k-sweep-->

```text
    k  다시 세기 · 곱셈 나머지  이 절차 · 곱셈 나머지  후보 최대  이 절차 · 감소 수열  후보 최대
    1                    2,048                  7,166          1                7,166          1
    2                    3,069                  9,208          2                9,208          2
    8                    9,153                 10,864          3                9,184          8
   32                   32,769                 11,012          4                9,088         32
  128                  115,713                 10,826          5                8,704        128
  512                  263,169                  9,689          8                7,168        512
1,024                    1,025                  8,153          8                5,120      1,024

└ N = 1,024 고정이다. 다시 세기는 k 를 따라 263,169 까지 커지는데
  이 절차는 7,166 에서 11,012 사이에 머무르다 k 가 커지면 오히려 줄어든다
  후보 최대는 k 가 아니라 입력의 모양이 정한다 — 곱셈 나머지는 여덟을 안 넘고 감소 수열은 k 까지 찬다
```

**셋이 나왔습니다.** 첫째, 이 절차의 자료 접근은 `k` 를 따라 늘지 않습니다 — 오히려 `k` 가
커지면 창의 개수가 줄어 접근이 줄어요. 둘째, 통의 깊이는 `k` 가 아니라 입력의 모양이 정합니다.
셋째, 그러므로 `k` 는 시간 비용에서 빠지고 **잡는 칸에만** 남습니다.

```text
얻은 절차 한 벌
  1. 후보 통을 빈 채로 두고 답 배열을 빈 채로 둔다
  2. 자리 0 부터 자리 N-1 까지 왼쪽에서 오른쪽으로 읽으며
       창을 벗어난 맨 앞 후보를 버린다
       지금 값보다 작은 뒤쪽 후보를 버릴 수 있는 만큼 버린다
       지금 자리를 뒤에 붙인다
       창이 다 찼으면 맨 앞 후보의 값을 답에 적는다
       └ 10 만 칸에 창 1 만 칸이면 9 억 번이던 접근이 107 만 번으로 준다
```

### 수행으로 알아보는 알고리즘 — 창 셋짜리로 여덟 칸을 지나며 답 여섯 개를 낸다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const nums = [1, 3, -1, -3, 5, 3, 6, 7];
const k = 3;
// 이 절이 끝나면 [3, 3, 5, 5, 6, 7] 이 나와야 한다
```

왜 하필 이 여덟 칸일까요? 문제 문서의 첫 예시를 그대로 가져온 것이고, 이 여덟이 **갈래를
전부 실행**하기 때문이에요. 통이 비어 바로 붙이는 걸음과 뒤에서 여럿을 버리는 걸음이 둘 다
나오고, 앞에서 버리는 걸음이 한 번 있으며, 창이 덜 찬 걸음도 둘 있고, 음수도 섞여 있습니다.

```text
절차 전체를 한 장으로

  result 를 빈 배열로, cand 를 빈 통으로 잡는다                       ①

  i 를 0 부터 N-1 까지 하나씩 늘리며:
      cur 은 이번 걸음의 값 nums[i] 다
      맨 앞 후보가 i - k 이하이면 앞에서 버린다                       ②
      뒤쪽 후보의 값이 cur 보다 작은 동안 뒤에서 버린다               ③
      지금 자리 i 를 뒤에 붙인다                                      ④
      i 가 k - 1 이상이면 맨 앞 후보의 값을 result 에 적는다          ⑤

  result 를 돌려준다
```

#### 1. 후보를 담을 통과 답 배열을 잡는다

답 배열과 통을 빈 채로 잡는 것이 이 조각의 전부인데, 답 배열을 **미리 길이를 정해 두지
않는다**는 것이 뒤에서 한 번 쓰입니다.

```ts
const n = nums.length;
const result: number[] = []; // ① 창 하나에 답 하나. 길이가 n - k + 1 이 된다
const cand: number[] = [];
```

이 조각까지만 실행한 상태는 이렇습니다.

```text
걸음   하는 일                       cand   result
—      빈 통과 빈 배열을 잡는다      []     []
       └ 답의 길이는 미리 정하지 않는다. 창이 다 찰 때마다 하나씩 붙는다
```

답의 개수가 `N − k + 1` 인 것은 창의 개수가 그만큼이기 때문이에요. 그 수를 미리 계산해 두지
않아도, 창이 다 찬 걸음마다 하나씩 붙이면 저절로 맞습니다.

#### 2. 창을 벗어난 맨 앞 후보를 버린다

오른쪽 끝이 `i` 인 창의 왼쪽 끝은 `i − k + 1` 입니다. 그러니 자리 번호가 `i − k` 이하인
후보는 창 밖이에요.

```ts
const cur = nums[i] ?? 0;
// ② 창을 벗어난 맨 앞 후보를 버린다. 한 걸음에 많아야 하나다.
if (cand.length > 0 && (cand[0] ?? 0) <= i - k) cand.shift();
```

`i = 4` 에서 이 조각만 실행하면 한 번 버립니다. 그 앞까지의 상태는 통이 자리 1 · 2 · 3 을
담고 있는 상태예요.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
T4 뒤 통          o   o   o
창 [2,4]              #   #   #
                  ^
                  맨 앞 자리 1 이 i - k = 4 - 3 = 1 이하라 창 밖이다. 앞에서 버린다
```

`<=` 로 적힌 조건이 「창을 벗어났다」의 다른 표현입니다. 창의 왼쪽 끝이 `i − k + 1` 이므로
자리 `i − k` 는 **방금 벗어난 경계**이고, 그 자리까지 버려야 해요.

#### 짚고 가기 — 앞에서 버리는 일은 한 걸음에 많아야 한 번이다

여기서 헷갈리기 쉬운 지점은 `if` 입니다. 「뒤에서 버릴 때는 `while` 인데 앞에서는 왜 한
번인가, 여러 개가 한꺼번에 창을 벗어날 수도 있지 않나」로 읽혀요.

```text
직전 걸음이 끝난 시점에 통에 남은 자리는 전부 창 [i-1-k+1, i-1] 안이다
    즉 자리 번호가 i - k 이상이다
이번 걸음의 조건은 자리 번호 ≤ i - k 다
    두 조건을 함께 만족하는 자리 번호는 i - k 하나뿐이고, 자리 번호는 서로 다르다
        └ 그러니 이번 걸음에서 창을 벗어난 후보는 많아야 하나다
```

되풀이해서 버리는 코드에 같은 입력들을 실행해 봅시다.

<!--proof:pause-expiry-while-->

```text
입력                     바른 코드      되풀이해 버리는 코드
[1 3 -1 -3 5 3 6 7] k=3  [3 3 5 5 6 7]  [3 3 5 5 6 7]         답이 같다
[5 4 3 2 1] k=2          [5 4 3 2]      [5 4 3 2]             답이 같다
[1 2 3 4 5] k=3          [3 4 5]        [3 4 5]               답이 같다
[7 7 7 7] k=2            [7 7 7]        [7 7 7]               답이 같다

└ 네 입력에서 답이 한 줄도 안 갈린다
  입력 5 개의 모든 창 크기 2,065 벌을 실행해 한 걸음에 두 번 이상 버린 자리를 세었고 결과는 0 개다
```

**답이 안 갈립니다.** `while` 로 적어도 두 번째 반복이 한 번도 실행되지 않아요. 그래도 `if`
로 적는 이유는 읽는 사람에게 **한 번이면 충분하다는 사실 자체를 알리기 위해서**입니다.
`while` 로 적으면 「한 걸음에 여러 개가 빠질 수 있구나」로 읽히고, 그 오해는 비용을 셀 때
바로 틀린 값을 만들어요.

#### 3. 지금 값보다 작은 뒤쪽 후보를 버리고 지금 자리를 붙인다

한 걸음의 핵심이 이 조각입니다. 뒤쪽 후보의 값을 지금 값과 맞대 보고, 더 작을 때만 버려요.

```ts
// ③ 지금 값보다 작은 뒤쪽 후보를 버린다. 값이 같으면 멈춘다.
while (cand.length > 0 && (nums[cand[cand.length - 1] ?? 0] ?? 0) < cur) {
  cand.pop();
}
cand.push(i); // ④ 지금 자리를 뒤에 붙인다
```

`i = 4` (값 5)에서 이 조각만 실행하면 두 번 버립니다. 앞에서 자리 1 을 이미 버린 뒤라 통은
자리 2 와 자리 3 을 담고 있어요.

```text
맞대 보기  뒤쪽 후보  그 값   cur  버리는가  버린 뒤 cand
1          자리 3        -3     5  버린다    [2]
2          자리 2        -1     5  버린다    []
3          없다           —     5  멈춘다    []
           └ 세 번째 맞대 보기는 일어나지 않는다. 통이 비어 반복 조건이 거짓이다
```

버리기가 끝난 뒤 붙이므로 지금 자리는 언제나 뒤가 되고, 그 값이 통 안에서 가장 작아요 —
같은 값이 앞에 남아 있을 수는 있습니다. 순서를 뒤집어 먼저 붙이면 자기 자신이 버리기 대상이
되는데, 자기 값이 자기 값보다 작을 수는 없어 아무 일도 일어나지 않습니다.

#### 4. 창이 다 차면 맨 앞이 답이다

창이 처음으로 다 차는 걸음은 `i = k − 1` 입니다. 그전까지는 창이 아직 `k` 칸을 못 채웠으니
답을 적지 않아요.

```ts
// ⑤ 창이 다 찼으면 맨 앞 후보의 값이 그 창의 답이다
if (i >= k - 1) result.push(nums[cand[0] ?? 0] ?? 0);
```

전개 입력에서 답이 적히는 걸음과 안 적히는 걸음이 이렇게 갈립니다.

```text
걸음  자리 i  i >= k-1 인가  맨 앞 front  그 값  result 에 붙는 것
T1         0  0 >= 2 거짓    자리 0           1  없다
T2         1  1 >= 2 거짓    자리 1           3  없다
T3         2  2 >= 2 참      자리 1           3  3
T4         3  3 >= 2 참      자리 1           3  3
T5         4  4 >= 2 참      자리 4           5  5
T6         5  5 >= 2 참      자리 4           5  5
T7         6  6 >= 2 참      자리 6           6  6
T8         7  7 >= 2 참      자리 7           7  7

└ 참인 걸음이 여섯이고, 창의 개수 N - k + 1 = 8 - 3 + 1 = 6 과 같다
```

#### 짚고 가기 — 창이 다 차기 전에 답을 적으면 개수부터 달라진다

여기서 헷갈리기 쉬운 지점은 `i >= k - 1` 입니다. 「어차피 맨 앞이 지금까지의 최댓값이니 그냥
걸음마다 적으면 되지 않나」로 읽히는데, **창이 덜 찬 동안의 최댓값은 답이 아닙니다.**

```text
i = 1 시점 (k = 3)

  읽은 칸        자리 0 과 자리 1 뿐이다      값 1 과 3
  맨 앞의 값     3
  창 [-1,1]      왼쪽 끝이 -1 이라 배열 밖이다
                 └ 이 자리에는 창이 없다. 그런데도 적으면 답이 하나 늘어난다
```

그 조건을 없앤 코드에 같은 입력들을 실행해 봅시다.

<!--proof:pause-no-warmup-->

```text
입력                     바른 코드      창이 덜 찼을 때도 적는 코드
[1 3 -1 -3 5 3 6 7] k=3  [3 3 5 5 6 7]  [1 3 3 3 5 5 6 7]            답이 다르다
[3 1 5 2] k=4            [5]            [3 3 5 5]                    답이 다르다
[3 1 5 2] k=1            [3 1 5 2]      [3 1 5 2]                    답이 같다
[9 8 7 6 5] k=2          [9 8 7 6]      [9 9 8 7 6]                  답이 다르다

└ 답의 개수부터 다르다 — 바른 코드는 N − k + 1 개이고 변이는 N 개다
  k = 1 이면 창이 첫 걸음에 이미 다 차므로 두 코드가 같은 답을 낸다
```

**세 번째 줄이 이 멈춤을 두는 이유입니다.** `k = 1` 이면 첫 걸음에 창이 이미 다 차므로 두
코드의 답이 글자 그대로 같아요. 시험 목록이 `k = 1` 인 케이스로만 채워져 있으면 이 코드는
에러 없이 통과하고, 틀린 줄 모르는 채로 남습니다.

#### 짚고 가기 — 앞에서 버리는 한 번과 배열이 실제로 옮기는 칸

여기서 헷갈리기 쉬운 지점은 `shift` 입니다. 「덱은 앞에서 버리는 것도 한 번에 끝나니 `shift`
도 한 번이다」로 읽히는데, **자바스크립트 배열의 `shift` 는 남은 칸을 전부 앞으로 옮깁니다.**

```text
cand 가 [1 2 3] 일 때 shift 를 부르면

  덱의 계약         앞에서 하나 버린다                                   연산 한 번
  배열의 실제 동작  자리 2 를 0 번 칸으로, 자리 3 을 1 번 칸으로 옮긴다  칸 2 개를 옮긴다
                    └ 통에 든 후보가 많을수록 옮기는 칸이 는다
```

통이 얼마나 깊은지에 따라 그 차이가 얼마나 벌어지는지 실제로 재 봅시다.

<!--proof:pause-shift-cost-->

```text
입력               N      k  앞에서 버린 횟수  실제로 옮긴 칸
감소 수열      1,024     32               992          30,752
감소 수열    100,000  1,000            99,000      98,901,000
곱셈 나머지    1,024     32                13              26
곱셈 나머지  100,000  1,000                82             492

└ 앞에서 버리는 일을 덱의 계약대로 한 번으로 세면 넷째 열이고, 배열의 shift 가 실제로
  옮긴 칸은 다섯째 열이다. 통에 든 후보가 적으면 둘의 차이가 거의 없다
```

**답은 안 틀립니다** — 갈리는 것은 옮긴 칸 수뿐이에요. 값이 골고루 섞인 입력에서는 통이
아홉 칸을 안 넘어 차이가 492 대 82 로 작습니다. 감소 수열에서는 통이 `k` 까지 차서 9,890 만
칸이 옮겨져요. 계약대로 한 번에 끝내려면 길이 `k` 짜리 고리 버퍼를 쓰면 되고, 아래 「실제로
쓰이는 곳」의 두 구현이 실제로 그렇게 합니다.

#### 5. 여덟 칸을 여덟 걸음으로 지난다

네 조각을 하나로 이어 고정 입력에 실행하면 여덟 걸음이 나옵니다. 한 걸음이 자리 하나이고,
그 안에서 앞에서 버리기 · 뒤에서 버리기 · 붙이기 · 답 적기가 순서대로 일어나요.

| 걸음 | 자리 `i` | 앞에서 버린 것 | 뒤에서 버린 것 | 붙인 뒤 `cand` | 답 | 갈래 |
| --- | --- | --- | --- | --- | --- | --- |
| T1 | 0 | 통이 비었다 | 통이 비었다 | `[0]` | 창이 덜 찼다 | ① ② ③ ④ |
| T2 | 1 | `0 <= -2` 거짓 | 값 1 이 3 보다 작다 | `[1]` | 창이 덜 찼다 | ② ③ ④ |
| T3 | 2 | `1 <= -1` 거짓 | 값 3 이 -1 보다 크다 | `[1 2]` | 3 | ② ③ ④ ⑤ |
| T4 | 3 | `1 <= 0` 거짓 | 값 -1 이 -3 보다 크다 | `[1 2 3]` | 3 | ② ③ ④ ⑤ |
| T5 | 4 | `1 <= 1` 참 — 자리 1 | 값 -3 과 -1 이 5 보다 작다 | `[4]` | 5 | ② ③ ④ ⑤ |
| T6 | 5 | `4 <= 2` 거짓 | 값 5 가 3 보다 크다 | `[4 5]` | 5 | ② ③ ④ ⑤ |
| T7 | 6 | `4 <= 3` 거짓 | 값 3 과 5 가 6 보다 작다 | `[6]` | 6 | ② ③ ④ ⑤ |
| T8 | 7 | `6 <= 4` 거짓 | 값 6 이 7 보다 작다 | `[7]` | 7 | ② ③ ④ ⑤ |

같은 여덟 걸음을 창과 통과 답의 값으로 나란히 놓으면 답이 언제 정해지는지가 확인됩니다.

```text

T1         0  덜 찼다  [0]          1             []
T2         1  덜 찼다  [1]          3             []
T3         2  [0,2]    [1 2]        3 -1          [3]
T4         3  [1,3]    [1 2 3]      3 -1 -3       [3 3]
T5         4  [2,4]    [4]          5             [3 3 5]
T6         5  [3,5]    [4 5]        5 3           [3 3 5 5]
T7         6  [4,6]    [6]          6             [3 3 5 5 6]
T8         7  [5,7]    [7]          7             [3 3 5 5 6 7]

└ cand 의 값이 어느 줄에서도 앞에서 뒤로 커지지 않는다
```

<!--result:walk=[3, 3, 5, 5, 6, 7]-->

**다섯 갈래가 모두 나왔습니다.** ① 은 반복이 시작되기 전에 한 번이라 표에서는 T1 줄에 함께
적었고, ② 는 T1 부터 T8 까지 매 걸음 검사하되 실제로 버린 것은 T5 뿐이며, ③ 도 매 걸음
검사하되 실제로 버린 것은 T2·T5·T7·T8 입니다. ④ 는 매 걸음이고 ⑤ 는 T3 부터 T8 까지 여섯
걸음이에요. T5 가 앞뒤로 함께 버리는 유일한 걸음입니다.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
T4 뒤 통          o   o   o
창 [2,4]              #   #   #
T5 뒤 통                      o
                  └ T5 는 앞에서 자리 1 을, 뒤에서 자리 3 과 자리 2 를 버린다. 셋이 한 걸음이다
```

#### 6. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 하나뿐이에요 — 배열이 비어
있으면 반복이 한 번도 실행되지 않고 빈 배열이 그대로 나옵니다.

```ts
export function slidingWindowMaximum(nums: number[], k: number): number[] {
  const n = nums.length;
  const result: number[] = []; // ① 창 하나에 답 하나. 길이가 n - k + 1 이 된다
  // 앞으로 답이 될 수 있는 **자리**만 담는다. 앞이 창의 왼쪽에 가깝고 뒤가 오른쪽에 가깝다.
  const cand: number[] = [];

  for (let i = 0; i < n; i++) {
    const cur = nums[i] ?? 0;
    // ② 창을 벗어난 맨 앞 후보를 버린다. 한 걸음에 많아야 하나다.
    if (cand.length > 0 && (cand[0] ?? 0) <= i - k) cand.shift();
    // ③ 지금 값보다 작은 뒤쪽 후보를 버린다. 값이 같으면 멈춘다.
    while (cand.length > 0 && (nums[cand[cand.length - 1] ?? 0] ?? 0) < cur) {
      cand.pop();
    }
    cand.push(i); // ④ 지금 자리를 뒤에 붙인다
    // ⑤ 창이 다 찼으면 맨 앞 후보의 값이 그 창의 답이다
    if (i >= k - 1) result.push(nums[cand[0] ?? 0] ?? 0);
  }

  return result;
}
```

```text
slidingWindowMaximum([1, 3, -1, -3, 5, 3, 6, 7], 3)  →  [3, 3, 5, 5, 6, 7]
slidingWindowMaximum([3, 1, 5, 2], 1)                →  [3, 1, 5, 2]
slidingWindowMaximum([3, 1, 5, 2], 4)                →  [5]
slidingWindowMaximum([-3, -1, -4, -2], 2)            →  [-1, -1, -2]
```

### 알아 두면 좋은 개념 — 형태학의 팽창과 침식

이 절차가 낸 답 `[3 3 5 5 6 7]` 을 원래 배열과 나란히 놓으면 모양이 하나 확인됩니다.
큰 값이 자기 자리에서 **왼쪽으로 최대 `k − 1` 칸까지** 나타나 있어요 — 값 5 는 `nums` 의
자리 4 에 있는데 창 [2,4] 와 창 [3,5] 의 답이 되어 답의 셋째·넷째 칸에 나옵니다.

```text
자리          0   1   2   3   4   5   6   7
원래 값       1   3  -1  -3   5   3   6   7
팽창          3   3   5   5   6   7
침식         -1  -3  -3  -3   3   3
              └ 팽창의 각 칸은 그 자리에서 시작하는 세 칸 창의 최댓값이고, 침식은 그 창의 최솟값이다
```

길이 `k` 인 창의 최댓값을 자리마다 구하는 것을 영상 처리에서는 **팽창**(dilation)이라 하고,
같은 창의 최솟값을 구하는 것을 **침식**(erosion)이라 부릅니다. 창 대신 「구조 요소」라는
말을 쓰고, 이 문제의 창처럼 길이만 있고 모양이 평평한 구조 요소를 평평한 구조 요소라 해요.

| 이름을 다시 만나는 자리 | 무엇이 창인가 | 무엇을 구하는가 |
| --- | --- | --- |
| 이 글의 창 최댓값 | 길이 `k` 인 1 차원 구간 | 팽창 |
| 이 글의 부등호를 뒤집은 것 | 같은 구간 | 침식 |
| 사진의 잡티 제거 | 가로 `a` × 세로 `b` 인 사각형 | 침식 뒤에 팽창(열림) |
| 소리 신호의 봉우리 따라가기 | 길이 `k` 인 시간 구간 | 팽창 |

**2 차원 사각형 구조 요소는 1 차원 두 번으로 갈라집니다.** 가로로 한 번 팽창하고 세로로 한
번 팽창하면 사각형 팽창과 같은 결과가 나와요. 그래서 영상 처리 라이브러리는 이 글의 절차나
그 사촌을 줄마다 · 열마다 한 번씩 부릅니다.

```text
3 x 3 팽창을 두 번으로 가르면

  가로 1 x 3 팽창    줄마다 창 셋짜리 최댓값을 구한다
  세로 3 x 1 팽창    그 결과의 열마다 창 셋짜리 최댓값을 구한다
                     └ 칸마다 아홉을 견주는 대신 셋씩 두 번이라, 구조 요소가 커질수록 차이가 커진다
```

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅시다. 어떤 문제에 이것을 쓰는지, 후보 집합을 식으로 어떻게
정의하는지, 매 걸음 무엇이 참으로 남는지, 비용이 얼마인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **구간의 길이가 하나로 고정입니다.** 질의마다 길이가 다르면 창의 양 끝이 함께 움직여
  「앞에서 하나 버리고 뒤에서 붙인다」가 성립하지 않아요.
- **구간의 값이 최댓값이나 최솟값처럼 「하나가 나머지를 가린다」로 정해집니다.** 합처럼 모든
  칸이 값에 기여하면 뒤쪽 후보를 버릴 근거가 없습니다.
- **창이 한 방향으로만 이동합니다.** 왼쪽으로 되돌아가는 질의가 섞이면 이미 버린 자리가
  다시 필요해집니다.

```text
세 조건이 코드의 모양을 그대로 정한다
  길이가 고정이다         → 앞에서 버리는 조건이 자리 번호 하나로 적힌다
  하나가 나머지를 가린다  → 뒤쪽 후보를 버릴 수 있다
  한 방향으로만 이동한다  → 버린 자리를 다시 안 본다
```

두 번째 조건이 가장 자주 걸립니다. 「가린다」가 성립하려면 두 값을 견줘 한쪽을 버려도 답이
안 바뀌어야 해요.

```text
창의 값이 무엇으로 정해지는가

  창의 최댓값                  더 큰 값 하나가 나머지를 가린다        ← 이 절차가 된다
  창의 최솟값                  부등호만 뒤집으면 된다                 ← 이 절차가 된다
  창의 합                      모든 칸이 기여한다                     ← 이 절차가 아니다
                               └ 누적합 한 줄로 끝나고, 통이 할 일이 없다
  창 안 서로 다른 값의 개수    한 값이 다른 값을 못 가린다            ← 이 절차가 아니다
                               └ 값마다 개수를 세는 표가 필요하다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "크기 k 인 윈도우"  "연속한 k 개"  "최근 k 개 중 최댓값"       ← 결정적인 신호다
  "모든 길이 k 부분배열에 대해 최댓값을 구하라"
  "창을 한 칸씩 옮기며"                                          ← 창이 한 방향으로만 간다는 뜻이다

제약에 이런 모양이 보이면
  N 이 10^5 이상인데 k 도 크다                                   ← N·k 가 못 들어간다는 뜻이다
  값의 범위가 넓어 값마다 칸을 잡을 수 없다                      ← 값을 인덱스로 쓰는 표가 못 들어간다는 뜻이다

반대로 이런 말이 보이면 해당하지 않는다
  "구간 [l, r] 이 질의로 주어진다"                               ← 길이가 고정이 아니다
  "중간에 값이 바뀐다"                                           ← 답을 처음부터 다시 만들어야 한다
  "합이 s 이하인 가장 긴 구간"                                   ← 양 끝이 함께 움직인다
```

마지막 무리가 보이면 다른 절차로 갑니다. 길이가 질의마다 다르면
[`segmentTreeRangeMin`](../segmentTreeRangeMin/segmentTreeRangeMin-problem.md) 쪽이고,
양 끝이 함께 움직이는 문제는
[`longestSubarrayAtMostSum`](../longestSubarrayAtMostSum/longestSubarrayAtMostSum-problem.md)
쪽이에요.

#### 실제로 쓰이는 곳

- **pandas 의 `roll_max` · `roll_min`** — `Series.rolling(k).max()` 가 부르는 함수입니다.
  후보 통에서 뒤쪽을 버리는 반복이
  `while (not candidates.empty() and values[k] >= values[candidates.back()]): candidates.pop_back()`
  이고, 앞쪽을 버리는 반복이
  `while not candidates.empty() and candidates.front() < stash_start: candidates.pop_front()`
  이며 답을 `output[i] = values[candidates.front()]` 로 적어요. **부등호가 `>=` 라 값이 같은
  옛 후보도 버립니다** — 이 글은 `<` 로 두어 남기는 쪽이고, 둘 다 답은 같습니다.
  ([`pandas/_libs/window/aggregations.pyx`](https://github.com/pandas-dev/pandas/blob/main/pandas/_libs/window/aggregations.pyx),
  조회 2026-09-03)
- **SciPy 의 `ndimage` 1 차원 최소·최대 필터 `NI_MinOrMaxFilter1D`** — `scipy.ndimage.maximum_filter1d`
  가 부르는 C 함수입니다. 후보마다 **값과 「죽는 시점」을 함께** 담아 두고
  `if (minpair->death == ll) { INCREASE_RING_PTR(minpair) }` 로 앞을 버려요. 담는 통이
  배열이 아니라 **고리 버퍼**(`ring`)라 앞에서 버릴 때 칸을 옮기지 않습니다 — 위 멈춤이
  말한 자리를 그렇게 처리한 실물이에요. 주석이 원저자를 밝혀 뒀습니다 —
  *"Original code by Richard Harter, adapted from: http://www.richardhartersworld.com/cri/2001/slidingmin.html"*.
  ([`scipy/ndimage/src/ni_filters.c`](https://github.com/scipy/scipy/blob/main/scipy/ndimage/src/ni_filters.c),
  조회 2026-09-03)
- **Bottleneck 의 `move_max` · `move_min`** — 넘파이 배열용 이동 집계 패키지입니다. 주석이
  *"move_min, move_max, move_argmin, and move_argmax are based on the minimum on a sliding
  window algorithm by Richard Harter"* 이고, 뒤에서 버리는 반복이
  `while (last->value FLIP ai) { if (last == ring) last = end; last--; }` 로 **고리 버퍼를
  거꾸로** 지납니다. pandas 의 주석이 이 구현을 출처로 밝히고 있어요 —
  *"Prior version of moving maximum / minimum code taken from Bottleneck"*.
  ([`bottleneck/src/move_template.c`](https://github.com/pydata/bottleneck/blob/master/bottleneck/src/move_template.c),
  조회 2026-09-03)

```text
네 구현이 통에 담는 것과 앞에서 버리는 방법을 나란히 두면

              통에 담는 것         앞에서 버릴 때             그때 옮기는 칸
  이 글       자리 번호            배열의 shift               남은 칸을 옮긴다
  pandas      자리 번호            덱의 pop_front             C++ 의 deque 가 맡는다
  SciPy       값과 만료 시점의 쌍  고리 버퍼의 시작을 옮긴다  안 옮긴다
  Bottleneck  값과 만료 시점의 쌍  고리 버퍼의 시작을 옮긴다  안 옮긴다

└ 네 구현 다 「자리인지 시점인지」를 함께 담는다. 값만으로는 창을 벗어났는지 알 수 없다
```

#### 경쟁 설계와의 대조

같은 목표(길이 `k` 인 창마다 최댓값)를 노리는 다른 절차로 **조각마다 접두·접미 최댓값 표를
미리 적어 두는 방법**이 있습니다. 배열을 `k` 칸씩 조각으로 끊고, 조각 안에서 왼쪽부터의
최댓값과 오른쪽부터의 최댓값을 각각 한 벌씩 만들어 두는 방식이에요. van Herk(1992)와
Gil–Werman(1993)이 낸 방법이고, 영상 처리의 사각형 구조 요소 필터가 이것을 씁니다.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
조각          A   A   A   B   B   B   C   C
접두 최대     1   3   3  -3   5   5   6   7
접미 최대     3   3  -1   5   5   3   7   7
              └ 접두 최대는 조각의 왼쪽 끝부터, 접미 최대는 조각의 오른쪽 끝까지 이어 놓은 값이다
```

길이 `k` 인 창은 이어진 `k` 칸이므로 **조각의 마지막 칸을 정확히 하나** 담습니다. 그 칸에서
창이 둘로 갈리니, 창의 최댓값은 「왼쪽 끝의 접미 최대」와 「오른쪽 끝의 접두 최대」 중 큰
쪽이에요.

```text
창        왼쪽 끝의 접미 최대  오른쪽 끝의 접두 최대  둘 중 큰 쪽  실제 최댓값
창 [0,2]                    3                      3            3            3
창 [1,3]                    3                     -3            3            3
창 [2,4]                   -1                      5            5            5
창 [3,5]                    5                      5            5            5
창 [4,6]                    5                      6            6            6
창 [5,7]                    3                      7            7            7
```

두 설계를 같은 입력·같은 창 크기에 적용해 **자료 접근 수**(읽기 + 쓰기)를 셌습니다. 입력은
「아이디어 상세」 ④⑥ 과 같은 두 벌이에요 — `nums[i] = (2731 i) mod 1201` 인 1,024 칸과 같은
길이의 감소 수열입니다. 전개가 쓰는 여덟 칸으로는 표 두 벌이 열 몇 번짜리 상수에 묻혀 두
설계의 순서가 안 갈려서 1,024 칸을 씁니다.

**감소 수열을 고정하고 창 크기만 바꾸면 순서가 뒤집힙니다.**

| 감소 수열 1,024 칸 | 후보 줄 세우기 | 조각 접두·접미 표 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| `k = 2` | 9208 | **8189** | 조각 표가 1,019 번 적습니다 |
| `k = 44` | 9040 | **9039** | 1 번 차이로 아직 조각 표입니다 |
| `k = 45` | **9036** | 9038 | **여기서 순서가 뒤집힙니다** |
| `k = 1,024` | **5120** | 6145 | 이쪽이 1,025 번 적습니다 |

**같은 창 크기에서 입력의 모양만 바꿔도 순서가 뒤집힙니다.** 조각 표 방식의 접근 수는 배열의
값에 전혀 안 매이고 길이와 창 크기만으로 정해지는데, 후보를 줄 세우는 쪽은 값의 순서를 따라
움직이기 때문이에요.

| 1,024 칸 | 후보 줄 세우기 | 조각 접두·접미 표 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 감소 수열 · `k = 45` | **9036** | 9038 | 이쪽이 2 번 적습니다 |
| 곱셈 나머지 · `k = 45` | 10999 | **9038** | 조각 표가 1.22 배 적습니다 |
| 감소 수열 · `k = 1,024` | **5120** | 6145 | 이쪽이 1.20 배 적습니다 |
| 곱셈 나머지 · `k = 1,024` | 8153 | **6145** | 조각 표가 1.33 배 적습니다 |

추가로 잡는 칸은 갈리지 않습니다. 후보 줄 세우기는 감소 수열에서 통이 가장 깊어져 `k = 45`
에 **45** 칸, `k = 1,024` 에 **1024** 칸이고, 조각 표는 두 경우 다 **2048** 칸이에요 —
길이 `N` 짜리 표 두 벌이라 창 크기와 무관합니다.

```text
경계가 그 자리인 이유 (감소 수열에서는 두 계수가 닫힌 형태로 나온다)

  후보 줄 세우기     9N − 4k               뒤에서 버리는 일이 한 번도 없고 걸음마다 멈춘다
  조각 접두·접미 표  9N − 3k + 3 − 2⌈N/k⌉  조각 수가 ⌈N/k⌉ 이고 조각마다 두 칸을 그대로 적는다
  두 식을 견주면     2⌈N/k⌉ < k + 3        일 때 앞엣것이 적다
                     k = 44 이면 2·24 = 48 이고 44 + 3 = 47 이라 거짓 (9040 대 9039)
                     k = 45 이면 2·23 = 46 이고 45 + 3 = 48 이라 참   (9036 대 9038)

└ 대략 k > √(2N) 이고 N = 1,024 에서 √2048 = 45.25 다
```

**이 절차가 내주는 것은 값이 골고루 섞인 입력에서의 접근 수입니다.** 뒤에서 버리는 일과 멈추는
걸음이 둘 다 많아지면 걸음당 맞대 보기가 늘어나는데, 조각 표 방식은 입력이 무엇이든 같은
횟수라 그 자리에서 1.22 배 앞섭니다. 그 대신 얻는 것이 둘이에요 — **잡는 칸이 창 크기까지만**
이고(45 대 2048), **값이 들어오는 대로 답을 낼 수 있습니다.** 조각 표 방식은 배열 전체를 두
번 지나야 표가 완성되므로 마지막 값이 들어오기 전에는 첫 창의 답도 못 냅니다.

### 수식 정의와 유도

창과 답을 정의합니다. 기호표의 `i` 를 그대로 써요 — **창의 오른쪽 끝**이고 지금 읽고 있는
자리입니다.

$$W(i) = [\,i-k+1,\; i\,], \qquad M(i) = \max_{i-k+1 \le t \le i} \mathit{nums}[t]$$

```text
정의를 읽는 법 (1)
  W(i) 는 오른쪽 끝이 i 인 창이고 k − 1 ≤ i ≤ N − 1 이다
  M(i) 는 그 창의 최댓값이고, 답 배열의 i − k + 1 번째가 이 값이다
```

$$C(i) = \{\, t \mid i-k+1 \le t \le i,\ \ \mathit{nums}[t] \ge \mathit{nums}[u] \ \text{ for all } u \text{ with } t < u \le i \,\}$$

```text
정의를 읽는 법 (2)
  C(i) 는 자리 i 까지 읽은 시점의 **후보 집합**이다
  조건 둘이다 — 창 W(i) 안에 있고, 자기 오른쪽에 자기보다 큰 값이 없다
  이 집합이 담는 것을 코드에서는 `cand` 가 담고, M(i) 는 `result` 에 차례로 적힌다
```

정의를 코드로 그대로 옮기면 이렇게 됩니다.

```ts
// 정의를 글자 그대로 옮긴 조각. 검산용이고 실제 절차는 이것을 부르지 않는다.
const isCandidate = (
  nums: number[],
  k: number,
  i: number,
  t: number,
): boolean =>
  t >= i - k + 1 &&
  t <= i &&
  nums.slice(t + 1, i + 1).every((v) => v <= (nums[t] ?? 0));
```

정의를 전개 입력의 여덟 걸음에 그대로 넣어 봅시다.

```text

T1    0            [0]               [0]        같다  —
T2    1            [1]               [1]        같다  —

  맨 앞의 값은 i ≥ 2 인 걸음마다 그 창의 최댓값과 같다
```

이제 그 일치가 우연이 아님을 유도합니다. **걸음 `i` 를 끝낸 시점의 통이 정확히 `C(i)`**
라는 것이고, 양방향으로 보입니다.

```text
(⊆)  자리 t 가 통에 남아 있다
     → 어느 걸음도 자리 t 를 앞에서 버리지 않았다  → t ≥ i − k + 1 이다
     → 어느 걸음도 자리 t 를 뒤에서 버리지 않았다
        걸음 u 가 뒤에서 버리는 조건이 nums[t] < nums[u] 이므로,
        t < u ≤ i 인 어느 u 에서도 그 조건이 거짓이었다
     → 모든 u 에서 nums[t] ≥ nums[u] 다
     → t 는 C(i) 의 원소다

(⊇)  t 가 C(i) 의 원소다
     → t ≥ i − k + 1 이라 앞에서 버려지지 않았다
     → t < u ≤ i 인 모든 u 에서 nums[t] ≥ nums[u] 이므로 뒤에서 버려질 조건이 한 번도 참이 아니다
        (자리 t 위에 쌓인 것이 먼저 버려지고 나서야 t 가 뒤가 되는데, 그때도 조건이 거짓이다)
     → t 는 통에 남아 있다
```

`C(i)` 의 가장 작은 원소가 창의 최댓값 자리입니다. 창 안의 어떤 자리 `s` 를 잡아도, `s` 가
후보가 아니면 오른쪽에 자기보다 큰 값이 있고 그 자리를 따라가면 결국 후보에 이르러요.
후보들의 값은 앞에서 뒤로 커지지 않으므로 가장 큰 것이 맨 앞입니다.

$$|C(i)| \le \min(k,\; i+1), \qquad P + F = N - |C(N-1)|$$

```text
유도를 읽는 법 (1)
  |C(i)| ≤ k 는 창 안의 자리만 담기 때문이다. 등호는 창 안의 값이 비증가일 때 선다
  |C(i)| ≤ i + 1 은 아직 i + 1 칸밖에 안 읽었기 때문이다
  P + F = N − |C(N−1)| 은 넣은 것이 N 개이고 남은 것이 |C(N−1)| 개이기 때문이다
```

여기서 자료 접근의 총식이 닫힙니다. 걸음마다 값을 한 번 읽고, 통이 비지 않았으면 맨 앞을 한
번 읽고, 맞대 보기 한 번에 두 번 읽고, 버릴 때마다 한 번 쓰고, 붙일 때 한 번 쓰고, 답을
적는 걸음마다 세 번 접근합니다. 맞대 본 횟수가 `P + B` 이므로 이렇게 돼요.

$$T(N,k) = 3N - 1 + F + 3P + 2B + 3(N-k+1)$$

```text
식을 읽는 법
  3N − 1 은 입력 값 읽기 N · 뒤에 붙이기 N · 맨 앞 보기 N − 1 을 더한 것이다
  F 는 앞에서 버린 횟수, 3P 는 맞대 보기 둘과 버리기 하나, 2B 는 멈춘 걸음의 맞대 보기다
  3(N − k + 1) 은 창마다 맨 앞 읽기 · 그 값 읽기 · 답 쓰기 셋이다
```

<!--proof:cost-formula-->

```text
입력             N      k      P      F      B  3N−1+F+3P+2B+3(N−k+1)  실측 접근
전개 입력        8      3      6      1      3                     66         66
곱셈 나머지  1,024      2    743    279    280                  9,208      9,208
곱셈 나머지  1,024     45  1,009     13    974                 10,999     10,999
곱셈 나머지  1,024  1,024  1,019      0  1,011                  8,153      8,153

감소 수열    1,024     45      0    979  1,023                  9,036      9,036
감소 수열    1,024  1,024      0      0  1,023                  5,120      5,120

└ 일곱째 열과 여덟째 열이 어긋난 줄이 0 개다
  제약 상한 N = 100,000 · k = 1,000 에서 이 입력의 실측은 1,096,624 이고 상한 11N − 3k − 5 는 1,096,995 이다
```

**여기부터가 본문의 값만으로는 안 나오는 자리입니다.** 파트 1 은 여덟 칸에서 한 점을 보였을
뿐인데, 총식에 상한을 넣으면 임의의 `N` 과 `k` 에서 접근 수가 닫힙니다. `3P + F` 는 `P` 가
클수록 크므로 `F = 0` 에서 가장 크고, `B` 는 걸음 0 이 통이 비어 멈출 수 없으니 `N − 1` 을
못 넘어요. 그리고 마지막 걸음이 멈췄다면 그 걸음이 붙인 자리와 그 아래 자리가 둘 다 남아
`|C(N-1)| ≥ 2` 입니다.

$$T(N,k) \le 3N-1+3(N-2)+2(N-1)+3(N-k+1) = 11N - 3k - 6$$

```text
유도를 읽는 법 (2)
  B = N − 1 이면 |C(N−1)| ≥ 2 이므로 P ≤ N − 2 다 — 위 식이 그 경우다
  B = N − 2 로 한 칸 양보하면 P ≤ N − 1 이 되어 11N − 3k − 5 가 된다
  둘 중 큰 쪽이 상한이므로 T(N,k) ≤ 11N − 3k − 5 다
  N = 100,000 · k = 1,000 에서 1,096,995 이고, 창마다 다시 세기의 99,100,001 과 90.3 배 차이다
```

**이 상한은 타이트하지 않습니다.** 실제로 두 상한을 동시에 달성하는 입력은 없고, 여섯 모양을
전수로 살펴 얻은 최댓값이 상한보다 작아요 — 그 값은 아래 「최악을 만드는 입력」이 냅니다.
그래도 이 식이 주는 것이 하나 있습니다. `k` 가 **음의 계수로만** 들어간다는 것이에요 —
창을 키우면 창의 개수가 줄어 접근이 줄고, 늘어나는 항은 없습니다.

### 불변식 — 통에 남은 자리는 창 안에서 오른쪽에 더 큰 값이 없는 자리 전부다

파트 1 은 여덟 걸음에서 이 코드가 옳은 답을 낸다는 것만 확인했습니다. 입력 하나에서 맞았다는
말이지 언제나 맞는다는 말이 아니에요. **매 걸음 참으로 남는 것**을 문장 하나로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> 걸음 `i` 를 끝낸 시점마다 `cand` 는 자리 `i − k + 1` 부터 `i` 까지 중 **오른쪽에 자기보다
> 큰 값이 없는 자리 전부**를 담고 있고, 앞에서 뒤로 자리 번호가 커지며 그 자리의 값은
> 커지지 않습니다. 그리고 창이 다 찬 걸음에서는 맨 앞의 값이 그 창의 최댓값입니다.

```text
자리          0   1   2   3   4   5   6   7
값            1   3  -1  -3   5   3   6   7
창 [1,3]          #   #   #
통                o   o   o
                  └ T4 를 마친 시점이다. 셋 다 창 안이고 값이 3 -1 -3 으로 커지지 않는다
                    자리 1 의 오른쪽인 자리 2 · 3 의 값이 둘 다 3 보다 작아 자리 1 이 남아 있다
```

「걸음을 끝낸 시점」을 빠뜨리면 이 문장이 거짓이 됩니다. 걸음 한가운데에는 앞에서 버렸는데
뒤에서 아직 안 버린 순간이 있고, 그 순간의 통은 창 안이지만 「오른쪽에 더 큰 값이 없는 자리
전부」가 아니에요.

```text
T5 의 한가운데

  앞에서 버린 직후   통이 [2 3]   자리 2 의 값 -1 은 오른쪽의 5 보다 작다   조건이 거짓이다
  뒤에서 다 버린 뒤  통이 []      아직 자리 4 를 안 붙였다                   조건이 거짓이다
  걸음을 끝낸 뒤     통이 [4]     조건이 참이다
```

**갈래를 하나씩 확인합시다.** 다섯 중 통의 내용을 바꾸는 것이 셋이고, 초기화는 빈 통을
만들며 답 적기는 통을 안 건드립니다.

| 어느 자리를 지날 때 | 하는 일 | 성질이 유지되는 근거 |
| --- | --- | --- |
| 초기화 | 빈 통과 빈 답 배열을 잡는다 | 담긴 자리가 없어 조건이 공허하게 참이다 |
| 앞에서 버리기 | 자리 번호가 `i − k` 이하인 맨 앞을 뺀다 | 뺀 자리는 창 밖이고, 남은 자리의 순서와 값 관계는 안 바뀐다 |
| 뒤에서 버리기 | 값이 `cur` 보다 작은 뒤쪽을 뺀다 | 뺀 자리는 오른쪽에 더 큰 값(`cur`)이 생겼으므로 조건을 잃었다 |
| 붙이기 | 자리 `i` 를 뒤에 붙인다 | 자리 `i` 는 오른쪽이 비어 조건이 참이고, 남은 뒤쪽의 값이 `cur` 이상이라 순서도 유지된다 |
| 답 적기 | 맨 앞의 값을 적는다 | 통을 안 건드린다 |

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| `[7]`, `k = 1` | 붙이기만 하고 바로 답을 적는다 | `[7]` |
| `[3, 1, 5, 2]`, `k = 1` | 걸음마다 앞에서 하나 버리고 하나 붙인다 | `[3, 1, 5, 2]` |
| `[3, 1, 5, 2]`, `k = 4` (`k = N`) | 앞에서 한 번도 안 버리고 마지막에 한 번 적는다 | `[5]` |
| `[5, 5, 5, 5]`, `k = 2` | 값이 같아 뒤에서 한 번도 안 버린다 | `[5, 5, 5]` |
| `[9, 8, 7, 6, 5]`, `k = 2` | 뒤에서 안 버리고 앞에서만 버린다 | `[9, 8, 7, 6]` |
| `[1, 2, 3, 4, 5]`, `k = 3` | 걸음마다 뒤를 통째로 버린다 | `[3, 4, 5]` |
| `[-3, -1, -4, -2]`, `k = 2` | 값의 부호는 견주기에 안 쓰인다 | `[-1, -1, -2]` |

`k = 1` 과 `k = N` 이 이 절차의 두 끝입니다. `k = 1` 이면 통에 자리가 하나뿐이라 앞에서
버리기가 걸음마다 일어나고, `k = N` 이면 앞에서 버리기가 한 번도 안 일어나요.

**이제 깨뜨려 봅시다.** 「창 안의 자리만 담는다」를 지키던 줄은 앞에서 버리는 조건의 부등호
한 줄입니다. 「자리 번호가 창의 왼쪽 끝보다 작을 때 버리면 되니 등호는 없어도 되지 않나」
라는 생각으로 그 등호를 떼어 봅니다.

```ts
if (cand.length > 0 && (cand[0] ?? 0) < i - k) cand.shift(); // 등호를 뗐다
```

<!--proof:mutant-expiry-strict-->

```text
입력                     바른 코드      등호를 뗀 코드
[1 3 -1 -3 5 3 6 7] k=3  [3 3 5 5 6 7]  [3 3 5 5 6 7]   답이 같다
[9 1 1 1 1] k=2          [9 1 1 1]      [9 9 1 1]       답이 다르다
[1 2 3 4 5] k=3          [3 4 5]        [3 4 5]         답이 같다
[5 4 3 2 1] k=2          [5 4 3 2]      [5 5 4 3]       답이 다르다

└ 창을 막 벗어난 자리가 한 걸음 더 살아남아 지난 창의 최댓값이 다시 나온다
  값이 계속 커지는 입력에서는 맨 앞이 언제나 방금 넣은 자리라 답이 안 갈린다
```

`[9 1 1 1 1]` 에서 두 번째 답이 1 대신 9 가 됩니다. 창 `[1,2]` 의 값은 1 과 1 이라 최댓값이
1 인데, 자리 0 이 한 걸음 더 남아 그 값 9 를 답으로 낸 것이에요.

```text
  바른 조건       자리 0 이 0 ≤ 1 − 2 = −1 을 만족하지 않아 걸음 1 에는 남고, 걸음 2 에서 0 ≤ 0 이라 버려진다
  등호를 뗀 조건  걸음 2 에서 0 < 0 이 거짓이라 안 버려지고, 걸음 3 에서야 0 < 1 로 버려진다

└ 불변식의 「창 안의 자리만 담는다」가 걸음 2 에서 거짓이 된다
```

### 비용 계산

#### 비용을 세는 과정

세는 것은 **자료 접근 수**(읽기 + 쓰기) 전부입니다 — `nums` 읽기, 통 읽기와 쓰기, 답 배열
쓰기. 통의 앞·뒤 어느 쪽에서 넣고 빼도 한 번으로 세요. 전개의 여덟 걸음으로 확인합시다.

```text

지금 값을 읽는다             T1~T8                8

창을 벗어난 후보를 버린다 ②  T5                   1

└ 같은 입력을 창마다 다시 세면 24 번이다. 여덟 칸에서는 아직 이쪽이 많다
  맞대 본 횟수가 9 이고 그중 버린 것이 6 · 멈춘 걸음이 3 이다
```

맞대 보기 한 번이 접근 둘인 것은 뒤쪽 후보를 읽고 그 자리의 값을 또 읽기 때문이에요. 답을
적는 걸음이 셋인 것도 같은 이유입니다 — 맨 앞을 읽고, 그 자리의 값을 읽고, 답 배열에 씁니다.

```text
갈래별로 몇 번인가

  지금 값 읽기   N 번             걸음마다 한 번
  맨 앞 보기     N − 1 번         걸음 0 만 통이 비어 있다
  앞에서 버리기  F 번             창을 벗어난 자리마다 한 번
  맞대 보기      2(P + B) 번      버린 횟수에 멈춘 걸음을 더한 것이 맞대 본 횟수다
  뒤에서 버리기  P 번             버릴 때마다 한 번
  뒤에 붙이기    N 번             자리마다 한 번
  답 적기        3(N − k + 1) 번  창마다 세 번

└ 다 더하면 3N − 1 + F + 3P + 2B + 3(N − k + 1) 이다
  전개는 N=8 · k=3 · P=6 · F=1 · B=3 이라 23 + 1 + 18 + 6 + 18 = 66 이다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`k = N` 인 감소 수열) | `O(N)` | `Θ(N)` — 접근 `5N`, 실제로 도달합니다 |
| **평균적인 경우** (값의 순서에 분포를 정해야 한다) | `O(N)` | 분포를 정해야 값이 나옵니다 |
| **최악의 경우** (아래 절이 구성하는 입력) | `O(N)` | `Θ(N)` — 차수는 타이트하고 상수는 `11N − 3k − 5` 이하까지만 압니다 |

세 케이스가 **경계의 종류에서는 안 갈립니다.** 셋 다 `Θ(N)` 이고 갈리는 것은 상수예요 —
`N = 1,024` 에서 5,120 과 11,040 사이입니다. 이 절차에서 「최악이 느리다」는 말은 상수가
2.2 배라는 뜻이지 차수가 다르다는 뜻이 아닙니다.

```text
세 줄의 경계가 서로 다른 종류다

  최선         5N            실제로 그 값이 나오는 입력이 있다      타이트한 값이다
  최악의 상한  11N − 3k − 5  그 값에 이르는 입력을 못 찾았다        상한이지 타이트한 값이 아니다
  실측 최대    11,040        여섯 모양 × 창 크기 1,024 벌의 최댓값  그 k 의 상한과 105 차이다

└ 상한과 실측 최대를 같은 줄에 적지 않는 이유가 이것이다
```

평균 줄이 비어 있는 이유를 적어 둡니다. 이 문제의 지문은 값이 **어떤 순서로 오는지 정하지
않습니다.** 순서에 분포를 하나 놓으면(값이 전부 다르고 모든 나열이 같은 확률이라고 두면)
`P` 와 `B` 의 기댓값이 나오는데, 그 분포는 지문이 준 것이 아니라 이 글이 놓은 가정이에요.

```text
총식 = Θ(N) 시간 + Θ(k) 추가 메모리

  시간    접근 3N − 1 + F + 3P + 2B + 3(N − k + 1)  5N ≤ 접근 ≤ 11N − 3k − 5
  메모리  통이 최대 min(k, N) 칸                    답 배열 N − k + 1 칸은 출력이라 안 센다

└ 앞이나 뒤에 미리 만들어 두는 표가 없다 — 정렬도 좌표 압축도 안 쓴다
```

**약속으로 내놓는 것은 최악 보장 하나입니다.** 코드에 난수가 없으니 같은 배열과 같은 창
크기를 두 번 넣으면 같은 횟수가 나오고, 어떤 입력을 넣어도 `11N − 3k − 5` 아래라는 것이
조건 없이 성립합니다. 평균 쪽은 그 약속에 안 들어가요 — **입력 분포를 하나 놓았을 때의
기댓값**이고, 실제 입력이 그 분포를 따르지 않으면 성립하지 않습니다.

#### 최악을 만드는 입력

「값이 큰 순서대로 늘어놓으면 느리다」가 이 절차에서는 반대입니다. 감소 수열은 뒤에서 버리는
일이 한 번도 없어 `P = 0` 이고, 접근이 가장 적은 쪽이에요. 접근을 크게 하려면 **버리는 일과
멈추는 일을 동시에 많이** 만들어야 합니다.

<!--proof:worst-shape-->

```text
입력의 모양                      뒤에서 버림 P  앞에서 버림 F  멈춘 걸음 B  후보 최대    총식  실측 접근
감소 수열                                    0            979        1,023         45   9,036      9,036
전부 같은 값                                 0            979        1,023         45   9,036      9,036
증가 수열                                1,023              0            0          1   9,080      9,080
곱셈 나머지                              1,009             13          974          4  10,999     10,999
창마다 큰 값 하나 · 나머지 증가          1,000             22        1,001          2  11,035     11,035
이웃 둘씩 자리를 바꾼 증가 수열          1,022              0          512          2  10,101     10,101

└ N = 1,024 · k = 45 다. 여섯째 열과 일곱째 열이 모든 줄에서 같다
  여섯 모양 × 창 크기 1,024 벌을 전수로 살펴 가장 적은 것이 5,120(감소 수열 · k=1,024 · 5N)이고
  가장 많은 것이 11,040(창마다 큰 값 하나 · 나머지 증가 · k=38)이며 그때의 상한 11N − 3k − 5 는 11,145 이다
```

최악을 만드는 입력은 **창 하나에 큰 값을 하나씩 심고 그 사이를 증가시킨 것**입니다. 심어 둔
큰 값이 통의 앞에 남아 걸음을 멈추게 하고, 그 사이의 증가하는 값들이 바로 앞 자리를 버리게
만들어요 — 총식의 `2B` 와 `3P` 가 함께 커지는 것이 이 모양입니다.

```text
k = 3 · N = 9 로 그 입력을 적으면  nums = [100 1 2 99 1 2 98 1 2]

걸음    지금 값  이 걸음이 한 일                붙인 뒤 통
걸음 0  100      버릴 것이 없다                 [0]
걸음 1  1        멈춘다                         [0 1]
걸음 2  2        뒤에서 자리 1 · 멈춘다         [0 2]
걸음 3  99       앞에서 자리 0 · 뒤에서 자리 2  [3]
걸음 4  1        멈춘다                         [3 4]
걸음 5  2        뒤에서 자리 4 · 멈춘다         [3 5]
걸음 6  98       앞에서 자리 3 · 뒤에서 자리 5  [6]
걸음 7  1        멈춘다                         [6 7]
걸음 8  2        뒤에서 자리 7 · 멈춘다         [6 8]

└ 심어 둔 큰 값이 통의 앞에 남아 걸음 1 · 2 · 4 · 5 · 7 · 8 을 전부 멈추게 하고,
  그 사이의 1 과 2 가 걸음 2 · 5 · 8 에서 바로 앞 자리를 버리게 한다. P=5 · F=2 · B=6 이다
```

그러니 최악은 **값의 크기가 아니라 놓인 순서**가 만듭니다. 같은 값들을 다르게 늘어놓기만
해도 `N = 1,024` 에서 접근이 5,120 에서 11,040 까지 갈려요. 그리고 그 폭이 2.2 배뿐이라,
이 절차는 최악을 따로 걱정할 일이 없습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 창이 이동할 때 왼쪽 끝이 빠지는 것이 문제이고,
그래서 **지금의 답 하나가 아니라 앞으로 답이 될 자리 전부**를 자리 번호로 담아 두었으며,
오른쪽에 더 큰 값이 생긴 자리는 뒤에서, 창을 벗어난 자리는 앞에서 버렸습니다.

```text
  1. 후보 통과 답 배열을 빈 채로 둔다           담는 것은 값이 아니라 자리 번호다
  2. 창을 벗어난 맨 앞을 버린다                 한 걸음에 많아야 한 번이다
  3. 지금 값보다 작은 뒤쪽을 버린다             같은 값에서는 멈춘다
  4. 지금 자리를 붙이고, 창이 다 찼으면 적는다  N=100,000 · k=1,000 에서 접근이 110 만 번 아래다
```

먼저 답이 붙는 문제 하나입니다. T4 를 마친 시점의 통은 `[1 2 3]` 이고 그 값이 3 · -1 · -3
이에요. 그런데 자리 2 와 자리 3 의 값은 창 `[1,3]` 의 최댓값 3 에 한참 못 미칩니다. 지금
답에 아무 보탬도 안 되는 이 둘을 왜 담아 두었을까요?

```text
T4    통이 [1 2 3]      답은 맨 앞 자리 1 의 값 3
T5    자리 1 이 창을 벗어난다
      └ 이때 자리 2 와 자리 3 이 없었다면 무엇을 답으로 낼 수 있을까
```

<!--check:whyKeepSmallOnes-->
**자리 1 이 빠진 뒤에 답이 될 자리**이기 때문입니다. 창 `[2,4]` 에서 자리 1 은 밖이고, 그때
답이 될 수 있는 것은 자리 2 · 3 · 4 뿐이에요. 그 셋을 그 자리에서 찾으려면 창을 다시 세야
하는데, 미리 담아 두었으므로 앞에서 하나 버리는 것으로 끝납니다.

이 입력에서는 T5 의 값 5 가 자리 2 와 자리 3 을 함께 버려서 결과적으로 둘이 안 쓰였습니다.
쓰이는 경우를 보려면 값 5 대신 값 -2 를 넣어 보면 돼요 — `[1 3 -1 -3 -2 3 6 7]` 에서 창
`[2,4]` 의 답은 -1 이고, 그 -1 이 바로 T4 에서 담아 둔 자리 2 입니다.

```text
자리          0   1   2   3   4   5   6   7
바꾼 값       1   3  -1  -3  -2   3   6   7
창 [2,4]              #   #   #
                      └ 답은 자리 2 의 -1 이다. T4 에서 담아 두지 않았으면 다시 세야 했다
```
<!--/check-->

  어느 갈래인지도 함께 적어 보세요. `[1 3 -1 -3 5 3 6 7]` 에 `k = 3` 으로 답이
  `[-1 -3 -3 -3 3 3]` 으로 나오는지 확인해 보세요.
- 뒤에서 버리는 조건을 `<` 에서 `<=` 로 바꾸면 답은 안 갈리는데 통의 내용은 달라집니다.
  `[7 7 7 7]` 에 `k = 2` 로 두 판본의 통을 걸음마다 적어 보고, 통이 가장 깊었을 때의 칸 수가
  어느 쪽이 작은지 세어 보세요. 전개 입력에서는 T1 부터 T8 까지 두 판본의 통이 한 걸음도
  안 갈리는데, 그 이유도 함께 적어 보세요.

  그대로 쓸 수 있을까요? 못 쓴다면 어느 갈래가 성립하지 않는지 적고, 배열을 뒤집어 푸는
  방법이 왜 되는지도 함께 적어 보세요.
