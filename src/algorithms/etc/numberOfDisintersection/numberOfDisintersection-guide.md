# 구간 교차 쌍 세기 — 오른쪽 끝이 먼저인 쪽에서 쌍을 한 번씩만 세는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 모든 쌍을
하나씩 대조하는 방법에서 출발해, 끝 좌표를 정렬해 두고 한 번 차례로 읽는 방법까지 갑니다. 그 방법을
단계마다 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

수직선 위에 원판이 여러 개 있습니다. 원판 `j` 는 중심이 `(j, 0)` 이고 반지름이 `A[j]` 예요. 원판을
수직선에 비추면 **구간** `[j − A[j], j + A[j]]` 가 되고, 두 원판이 한 점이라도 함께 가지는지는 두 구간이
겹치는지와 같습니다. 그래서 할 일은 「서로 겹치는 구간 쌍이 몇 개인가」를 세는 것이에요. 원판 여섯
개를 수직선에 그려 보면 이렇습니다. 괄호 하나가 원판 하나이고, 맨 위 줄이 수직선의 좌표입니다. 괄호가 원판이
차지하는 좌표이고, 맨 아래 줄의 `▲` 는 어느 원판의 오른쪽 끝인 좌표예요.

<!--fig:concept-sweep-->
![원판 6 개를 수직선의 구간으로 — 기준점은 오른쪽 끝 5 자리에서 멈춘다](./figs/concept-sweep.svg)

쌍을 하나씩 대조하면 원판이 `n` 개일 때 `n(n−1)/2` 번을 봐야 합니다. 대신 **기준점 하나를 왼쪽에서
오른쪽으로 옮기며**, 그림 맨 아래 줄의 `▲` 자리, 곧 원판의 오른쪽 끝에서만 멈춥니다. 멈출 때마다
「이 자리보다 왼쪽에서 이미 시작한 원판이 몇 개인가」 하나만 세요. 이렇게 기준점을 한쪽으로만 옮기며
그 자리까지의 상태를 고쳐 가는 방식을 **스윕 라인**(sweep line)이라고 부릅니다. 이 글은 이 방식을 끝까지
스윕 라인이라고 부를게요.

멈춘 자리에서 셀 수 있는 것은 시작한 원판의 수뿐입니다. 그 안에는 이미 오른쪽 끝을 지나 **닫힌**
원판과, 지금 멈춘 자리의 주인인 원판 자신이 들어 있어요. 둘을 빼면 남는 원판은 이 자리 이전에
시작했고 이 자리 이후에 끝나니, 지금 닫히는 원판과 반드시 겹칩니다.

| 기준점이 멈춘 자리에서 | 원판 수 | 지금 닫히는 원판과 |
| --- | --- | --- |
| 이 자리 이하에서 시작한 원판 | 셀 수 있다 | 아래 셋을 합친 것이다 |
| 그중 먼저 닫힌 원판 | 멈춘 횟수로 안다 | 그 원판이 닫힐 때 이미 셌다 |
| 그중 자기 자신 | 1 | 쌍이 아니다 |
| 나머지 | 위에서 두 수를 뺀 값 | 반드시 겹친다. 여기서 더한다 |

이렇게 하면 겹치는 쌍 하나는 **오른쪽 끝이 먼저 오는 원판이 닫힐 때 딱 한 번** 더해집니다. 셀 때
원판 번호가 필요 없어서, 왼쪽 끝들과 오른쪽 끝들을 **따로** 정렬해 두기만 하면 됩니다. 비용은 정렬이
`O(n log n)` 이고, 그 뒤 한 번 차례로 읽는 것은 `O(n)` 이에요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **닫힌 구간**의 뜻. `[a, b]` 는 `a` 와 `b` 를 모두 포함하므로, `[−1, 1]` 과 `[1, 3]` 은 점 1 을 함께
가져서 겹칩니다.
- **정렬**이 무엇을 해 주는지. 수를 오름차순으로 늘어놓으면 앞에서부터 읽을 때 값이 줄지 않습니다.
정렬 비용이 `O(n log n)` 이라는 것만 알면 충분하고, 정렬 알고리즘의 내부는 몰라도 됩니다. 궁금하면
[`quicksort`](../../sorting/quicksort/quicksort-guide.md) 를 보세요.
- **두 포인터**로 정렬된 배열을 한 번만 차례로 읽는 방식. 한 포인터가 앞으로만 가면 전체 이동이 배열 길이를
넘지 않는다는 점을 씁니다. 이 저장소에 따로 쓴 가이드는 없습니다.
- JavaScript 의 `Array.prototype.sort` 는 비교 함수를 주지 않으면 값을 **문자열로** 비교합니다.
코드에서 `sort((a, b) => a − b)` 를 쓰는 까닭이에요.

이 글이 다루는 범위는 아래 세 물음으로 갈립니다.

| 물음 | 이 글에서 |
| --- | --- |
| 겹치는 쌍이 **몇 개**인가 | 다룬다 |
| 겹치는 쌍을 **모두 나열**하라 | 다루지 않는다. 답의 크기만큼 시간이 들어 세는 것과 다른 과제다 |
| 구간이 하나씩 **추가·삭제**될 때마다 다시 세라 | 다루지 않는다. 정렬을 한 번 하고 끝내는 절차라 조건 밖이다 |

### 아이디어를 떠올리는 과정 — 모든 쌍 대조에서 오른쪽 끝 순서 스윕 라인까지

먼저 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 반지름 배열을 받아 교차하는 원판 쌍의 수를
돌려줍니다.

```ts
function countIntersectingDiscs(A: number[], limit?: number): number;
```

- 입력: 음이 아닌 정수 배열 `A` 입니다. 원판 `j` 는 중심이 `(j, 0)` 이고 반지름이 `A[j]` 예요.
`limit` 은 셀 쌍 수의 상한이고, 주지 않으면 10,000,000 입니다.
- 출력: 두 원판이 적어도 한 점을 함께 가지는 **순서 없는 쌍** `(j, k)`, `j < k` 의 수입니다. 경계의
한 점만 함께 가져도 교차로 셉니다. 그 수가 `limit` 을 넘으면 −1 을 돌려줘요.
- 규모: `0 ≤ n ≤ 100,000`, `0 ≤ A[j] ≤ 2,147,483,647` 입니다. 비용은 흔한 채점 환경의 예산인 시간
1 초에 대어 잽니다.

이 글에서 쓰는 기호는 여덟 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `n` | 원판의 개수, 곧 `A` 의 길이 | `n ≤ 100,000` |
| `A[j]` | 원판 `j` 의 반지름 | `0` 이상 `2,147,483,647` 이하 |
| `j` · `k` | 원판 번호. 원판 `j` 는 구간 `[j − A[j], j + A[j]]` 를 차지합니다 | `0 ≤ j, k ≤ n − 1` |
| `limit` | 쌍 수의 상한. 넘으면 −1 입니다 | 기본값 10,000,000 |
| `starts` · `ends` | 모든 원판의 왼쪽 끝 · 오른쪽 끝을 **각각 따로** 오름차순 정렬한 배열 | 길이 `n` |
| `i` | `ends` 안의 자리. 스윕 라인이 `i` 번째로 멈춘 오른쪽 끝이 `ends[i]` 입니다 | `0 ≤ i ≤ n − 1` |
| `opened` | 지금 멈춘 오른쪽 끝 이하에서 시작한 원판의 수 | `0` 이상 `n` 이하 |
| `count` | 지금까지 더한 교차 쌍의 수 | `limit` 을 넘으면 멈춘다 |

이제 아이디어를 찾아 나섭니다. 출발점은 아무 기법도 쓰지 않는 방법이에요. 두 원판 `j < k` 를 모두
짝지어, 중심 사이 거리 `k − j` 가 반지름의 합 `A[j] + A[k]` 이하인지 봅니다.

```ts
let count = 0;
for (let j = 0; j < n; j++) {
  for (let k = j + 1; k < n; k++) {
    if (k - j <= A[j] + A[k]) count++;
  }
}
```

이 방법이 얼마나 오래 걸리는지는 **쌍을 대조한 횟수**로 셉니다. 어떤 입력이든 쌍마다 한 번씩
보므로 횟수는 입력 값과 상관없이 `n(n−1)/2` 입니다.

<!--proof:cost-pairs-->

| n | 대조 횟수(실측) | n(n−1)/2 | 초당 1억 번 기준 |
| ---: | ---: | ---: | ---: |
| 6 | 15 | 15 | 0.01 초 미만 |
| 100 | 4,950 | 4,950 | 0.01 초 미만 |
| 1,000 | 499,500 | 499,500 | 0.01 초 미만 |
| 100,000 | (실행하지 않음) | 4,999,950,000 | 50.00 초 |

<!--/proof-->

규모의 최댓값에서는 약 50 억 번입니다. 컴퓨터가 단순한 연산을 1 초에 1 억 번쯤 한다고 잡아도 50 초가
걸려요. 예산 1 초의 50 배라서 이 방법으로는 안 됩니다. 쌍을 하나씩 보는 한 이 수는 줄지 않으니,
**쌍을 보지 않고 쌍의 수를 세는** 방법이 필요합니다.

그 방법을 찾으려고 원판을 구간으로 옮겨 봅시다. 원판 `j` 의 왼쪽 끝은 `j − A[j]`, 오른쪽 끝은
`j + A[j]` 입니다. 작은 입력 `A = [1, 5, 2, 1, 4, 0]` 에 넣어 보면 이렇습니다.

<!--proof:origin-intervals-->

| 원판 | 반지름 A[j] | 왼쪽 끝 j − A[j] | 오른쪽 끝 j + A[j] | 구간 |
| --- | ---: | ---: | ---: | --- |
| 원판 0 | 1 | -1 | 1 | [-1,1] |
| 원판 1 | 5 | -4 | 6 | [-4,6] |
| 원판 2 | 2 | 0 | 4 | [0,4] |
| 원판 3 | 1 | 2 | 4 | [2,4] |
| 원판 4 | 4 | 0 | 8 | [0,8] |
| 원판 5 | 0 | 5 | 5 | [5,5] |

<!--/proof-->

두 구간이 겹치려면 **각자의 시작이 상대의 끝 이하**여야 합니다. 조건이 둘인데, `j < k` 로 번호가 작은
쪽을 앞에 두면 하나는 저절로 참이에요. `j − A[j] ≤ j < k ≤ k + A[k]` 라서 `j` 의 시작은 언제나 `k` 의
끝 이하이기 때문입니다. 열다섯 쌍 모두에서 두 조건을 따져 보았습니다. 가운데 열을 보세요.

<!--proof:origin-condition-->

| 쌍 (j, k) | k 의 시작 ≤ j 의 끝 | j 의 시작 ≤ k 의 끝 | 정의로 본 결과 |
| --- | --- | --- | --- |
| (0, 1) | -4 ≤ 1 → 참 | -1 ≤ 6 → 참 | 교차 |
| (0, 2) | 0 ≤ 1 → 참 | -1 ≤ 4 → 참 | 교차 |
| (0, 3) | 2 ≤ 1 → 거짓 | -1 ≤ 4 → 참 | 떨어짐 |
| (0, 4) | 0 ≤ 1 → 참 | -1 ≤ 8 → 참 | 교차 |
| (0, 5) | 5 ≤ 1 → 거짓 | -1 ≤ 5 → 참 | 떨어짐 |
| (1, 2) | 0 ≤ 6 → 참 | -4 ≤ 4 → 참 | 교차 |
| (1, 3) | 2 ≤ 6 → 참 | -4 ≤ 4 → 참 | 교차 |
| (1, 4) | 0 ≤ 6 → 참 | -4 ≤ 8 → 참 | 교차 |
| (1, 5) | 5 ≤ 6 → 참 | -4 ≤ 5 → 참 | 교차 |
| (2, 3) | 2 ≤ 4 → 참 | 0 ≤ 4 → 참 | 교차 |
| (2, 4) | 0 ≤ 4 → 참 | 0 ≤ 8 → 참 | 교차 |
| (2, 5) | 5 ≤ 4 → 거짓 | 0 ≤ 5 → 참 | 떨어짐 |
| (3, 4) | 0 ≤ 4 → 참 | 2 ≤ 8 → 참 | 교차 |
| (3, 5) | 5 ≤ 4 → 거짓 | 2 ≤ 5 → 참 | 떨어짐 |
| (4, 5) | 5 ≤ 8 → 참 | 0 ≤ 5 → 참 | 교차 |

쌍 15 개 가운데 오른쪽 열이 참인 쌍이 15 개이고, 교차하는 쌍은 11 개입니다.

<!--/proof-->

가운데 열이 모두 참입니다. 교차를 가르는 것은 왼쪽 열 「`k` 의 시작 ≤ `j` 의 끝」 하나뿐이에요. 다만
이것만으로는 대조 횟수가 줄지 않습니다. 여전히 쌍마다 한 번 보니까요.

가장 단순한 후보를 먼저 시험해 봅시다. 쌍 수에는 상한 `limit` 이 있으니, 「세다가 상한을 넘으면
바로 멈추면 빨라지지 않을까」 하는 생각이에요. 원판 5,000 개로 세어 보았습니다.

<!--proof:limit-stop-fails-->

n = 5,000 에서 반지름 모양 셋으로 세었습니다. 상한은 10,000,000 입니다.

| 반지름 모양 | 교차 쌍 | 끝까지 대조 | 상한에서 멈춘 답 | 상한에서 멈춘 대조 |
| --- | ---: | ---: | ---: | ---: |
| 전부 0 | 0 | 12,497,500 | 0 | 12,497,500 |
| 전부 n | 12,497,500 | 12,497,500 | −1 | 10,000,001 |
| 생성식 (37j + 11) mod 50 | 246,042 | 12,497,500 | 246,042 | 12,497,500 |

<!--/proof-->

멈추는 것은 답이 상한을 넘을 때뿐입니다. 반지름이 전부 0 이면 교차 쌍이 0 이라 한 번도 멈추지 않고
12,497,500 번을 모두 대조해요. 원판이 100,000 개이고 반지름이 전부 0 이면 앞 표의 50 억 번이 그대로
남습니다. 상한은 **답이 클 때만** 시간을 줄이고, 답이 작은 입력은 구해 주지 못해요.

다른 쪽에서 접근해 봅시다. 원판 `j` 의 짝이 되는 조건 「상대의 시작 ≤ `j` 의 끝」은 상대 번호를 몰라도
셀 수 있습니다. 모든 원판의 시작 좌표 가운데 `j` 의 끝 이하인 것의 **개수**만 알면 되니까요. 문제는 그
개수에 짝이 아닌 원판도 섞인다는 점입니다. 원판을 오른쪽 끝이 작은 순서로 늘어놓고, 그 개수에서 무엇이
섞였는지 원판 번호로 확인해 보았어요.

<!--proof:origin-rank-->

| 끝 순서 i | 원판 | 오른쪽 끝 | 시작이 그 끝 이하인 원판 수 | 먼저 닫힌 원판 | 남는 원판 |
| ---: | --- | ---: | ---: | --- | --- |
| 0 | 원판 0 | 1 | 4 | 없음 | 원판 1 · 원판 2 · 원판 4 |
| 1 | 원판 2 | 4 | 5 | 원판 0 | 원판 1 · 원판 3 · 원판 4 |
| 2 | 원판 3 | 4 | 5 | 원판 0 · 원판 2 | 원판 1 · 원판 4 |
| 3 | 원판 5 | 5 | 6 | 원판 0 · 원판 2 · 원판 3 | 원판 1 · 원판 4 |
| 4 | 원판 1 | 6 | 6 | 원판 0 · 원판 2 · 원판 3 · 원판 5 | 원판 4 |
| 5 | 원판 4 | 8 | 6 | 원판 0 · 원판 2 · 원판 3 · 원판 5 · 원판 1 | 없음 |

<!--/proof-->

「시작이 그 끝 이하인 원판 수」에서 섞인 것은 두 가지입니다. 하나는 원판 자신이고, 다른 하나는 **먼저
닫힌 원판**, 곧 오른쪽 끝이 앞서는 원판이에요. 먼저 닫힌 원판은 오른쪽 끝이 지금 끝 이하이고 시작은
그보다도 앞이니 늘 이 개수에 들어갑니다. 끝 순서 `i` 번째 원판이라면 먼저 닫힌 원판이 정확히 `i` 개라서,
빼야 할 수는 자신까지 `i + 1` 개예요. 줄 0 에서는 4 − 1 = 3 이고 줄 1 에서는
5 − 2 = 3 입니다. 「남는 원판」 열의 개수와 같아요.

먼저 닫힌 원판과의 쌍은 버려도 되는지가 남습니다. 버려도 됩니다. 그 쌍은 먼저 닫힌 원판의 줄에서
이미 셌거나, 겹치지 않아 셀 필요가 없었어요. 줄 1 의 원판 2 에서 빠진 원판 0 은 줄 0 의 「남는 원판」에
원판 2 로 이미 들어 있습니다. 같은 입력을 두 방식으로 처리한 계수를 나란히 놓으면 이렇습니다. 끝 순서
방식의 「여는 비교」는 시작 좌표가 지금 끝 이하인지 본 횟수예요.

<!--proof:cost-two-ways-->

| 입력 | 모든 쌍 대조 | 끝 순서 방식의 정렬 비교 | 끝 순서 방식의 여는 비교 | 답(모든 쌍) | 답(끝 순서) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 15 | 18 | 9 | 11 | 11 |
| 생성식 n = 1,000 | 499,500 | 13,693 | 1,972 | 48,042 | 48,042 |

<!--/proof-->

원판 여섯 개에서는 끝 순서 방식이 정렬까지 합쳐 27 번으로 오히려 많습니다. 원판 1,000 개에서는
모든 쌍 대조가 499,500 번인데 끝 순서 방식은 정렬 13,693 번과 여는 비교 1,972 번이에요. 여는 비교가
원판 수의 두 배를 넘지 않는 것이 눈여겨볼 점입니다. 오른쪽 끝이 작은 것부터 보니 「그 끝 이하에서
시작한 원판」은 늘기만 하고, 앞에서 센 원판을 다시 볼 까닭이 없기 때문이에요.

지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **오른쪽 끝 순서 스윕 라인**입니다. 기준점을 오른쪽 끝이 작은 것부터 옮기며 「시작한
원판 수 − (먼저 닫힌 원판 수 + 1)」을 더합니다. 다음 절에서 이 방법을 실현하는 순서대로 풀어 봅니다.

### 아이디어 상세 — 오른쪽 끝 순서 스윕 라인

이 아이디어를 한 문장으로 줄이면 이렇습니다. **원판의 왼쪽 끝과 오른쪽 끝을 따로 정렬해 두고, 오른쪽 끝을
작은 것부터 하나씩 멈추며 「그 끝 이하에서 시작한 원판 수 − (멈춘 횟수)」를 더합니다.** 이 방법은 스윕
라인이라는 방식 위에서 동작하므로 스윕 라인부터 따로 설명하고, 그다음 다섯 단계를 실현 순서대로
설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 읽기 전에 한 번 | 1단계 원판을 두 끝 좌표로 바꾸기 | 원판마다 왼쪽 끝 · 오른쪽 끝을 구한다 | — |
| 읽기 전에 한 번 | 2단계 두 끝 좌표를 따로 정렬하기 | `starts` · `ends` 를 만든다 | 1단계의 좌표 |
| 오른쪽 끝마다 | 3단계 열린 원판 세기 | `opened` 를 앞으로만 옮긴다 | 2단계의 두 배열 |
| 오른쪽 끝마다 | 4단계 먼저 닫힌 원판과 자기 자신 빼기 | `opened − (i + 1)` 을 더한다 | 3단계의 `opened` |
| 오른쪽 끝마다 | 5단계 상한에서 멈추기 | `count > limit` 이면 −1 | 4단계의 `count` |

#### 먼저 알아 둘 개념 — 스윕 라인

스윕 라인은 **수직선 위의 기준점 하나를 한쪽 방향으로만 옮기면서, 그 점이 멈출 때마다 「지금까지
지나온 것」에 대한 상태를 고치는 방식**입니다. 이 글에서 기준점은 왼쪽에서 오른쪽으로 가고, 원판의
오른쪽 끝에서만 멈추며, 상태는 「멈춘 자리 이하에서 시작한 원판 수」 하나예요. 헷갈리기 쉬운 것이 하나
있습니다. 원판에는 두 가지 시점이 있어요.

| 원판의 시점 | 기준점과의 관계 | 이 글에서 부르는 말 |
| --- | --- | --- |
| 시작 | 왼쪽 끝이 기준점 이하가 됐다 | 시작한 원판 · 연 원판 |
| 닫힘 | 오른쪽 끝에 기준점이 멈췄다 | 닫힌 원판 |

##### 기준점이 멈추는 자리

「전체 컨셉」의 그림에서 맨 아래 줄 `▲` 가 기준점이 멈추는 자리입니다. 원판 여섯의 오른쪽 끝
`1 · 4 · 4 · 5 · 6 · 8` 이에요. 4 에는 원판 2 와 원판 3 이 함께 끝나서 `▲` 는 다섯 개지만, 멈춤은
원판마다 한 번씩 여섯 번입니다. 멈출 때마다 원판이 어느 상태인지 원판 번호로 적으면 이렇습니다. 끝이
같은 원판은 번호가 작은 쪽을 먼저 닫았어요.

<!--proof:sweep-stops-->

| 멈춤 i | 기준점 x | 여기서 닫히는 원판 | 시작한 원판 수 | 닫힌 원판(이번 포함) | 시작했고 아직 안 닫힌 원판 |
| ---: | ---: | --- | ---: | --- | --- |
| 0 | 1 | 원판 0 | 4 | 원판 0 | 원판 1 · 원판 2 · 원판 4 |
| 1 | 4 | 원판 2 | 5 | 원판 0 · 원판 2 | 원판 1 · 원판 3 · 원판 4 |
| 2 | 4 | 원판 3 | 5 | 원판 0 · 원판 2 · 원판 3 | 원판 1 · 원판 4 |
| 3 | 5 | 원판 5 | 6 | 원판 0 · 원판 2 · 원판 3 · 원판 5 | 원판 1 · 원판 4 |
| 4 | 6 | 원판 1 | 6 | 원판 0 · 원판 2 · 원판 3 · 원판 5 · 원판 1 | 원판 4 |
| 5 | 8 | 원판 4 | 6 | 원판 0 · 원판 2 · 원판 3 · 원판 5 · 원판 1 · 원판 4 | 없음 |

<!--/proof-->

##### 멈춤 하나를 읽는 법

멈춤 `i = 1` 을 읽어 봅시다. 기준점 `x = 4` 이고 여기서 원판 2 가 닫힙니다. 왼쪽 끝이 4 이하인 원판은
원판 0 · 1 · 2 · 3 · 4 다섯이고, 원판 5 는 왼쪽 끝이 5 라 아직 시작하지 않았어요. 다섯 가운데 원판 0 은
멈춤 0 에서 이미 닫혔고 원판 2 는 지금 닫힙니다. 남는 원판 1 · 3 · 4 는 4 이하에서 시작했고 4 이후에
끝나므로, 모두 점 4 를 원판 2 와 함께 가집니다.

| 읽는 순서 | 멈춤 1 에서 | 값 |
| --- | --- | --- |
| 기준점 | 오른쪽 끝 순서 1 번째 | `x = 4` |
| 시작한 원판 | 왼쪽 끝이 4 이하 | 5 개 |
| 빼는 원판 | 먼저 닫힌 원판 0 + 자기 자신 원판 2 | 2 개 |
| 새 짝 | 원판 1 · 3 · 4 | 5 − 2 = 3 개 |

멈춤 1 을 수직선 위에 그리면 이렇습니다. 대시 괄호가 먼저 닫힌 원판, 강조 괄호가 지금 닫히는 원판, 실선
괄호가 남는 짝이에요.

<!--fig:concept-stop-one-->
![멈춤 1 — 연 원판 5 개에서 먼저 닫힌 1 개와 자신을 빼면 새 짝 3 개](./figs/concept-stop-one.svg)

##### 이웃한 멈춤 사이의 관계

기준점이 오른쪽으로만 가므로 「시작한 원판 수」는 멈출 때마다 **줄지 않습니다.** 앞 표의 열이 4 · 5 ·
5 · 6 · 6 · 6 이에요. 닫힌 원판은 멈출 때마다 정확히 하나씩 늘고요. 그래서 다음 멈춤에서 할 일은 이전
멈춤 이후 새로 시작한 원판만 더 세는 것뿐입니다.

| 멈춤 사이 | 시작한 원판 수 | 닫힌 원판 수 |
| --- | --- | --- |
| 이전 → 다음 | 같거나 늘어난다 | 하나 늘어난다 |
| 다시 세야 하는 것 | 이전 기준점과 다음 기준점 사이에서 시작한 원판 | 없다 |

##### 좌표를 한 칸씩 옮기는 모양과의 차이

스윕 라인을 처음 보면 기준점을 좌표 **한 칸씩** 옮기며 모든 자리에서 멈추는 모양을 떠올리기 쉽습니다.
두 모양이 멈추는 자리 수를 비교해 보았어요.

<!--proof:sweep-vs-grid-->

| 입력 | 좌표를 한 칸씩 옮길 때 멈추는 자리 | 오른쪽 끝에서만 멈출 때 |
| --- | ---: | ---: |
| 전개 입력 | 13 | 6 |
| 최대 반지름 둘 | 4,294,967,296 | 2 |
| n = 100,000 · 전부 0 | 100,000 | 100,000 |

<!--/proof-->

전개 입력에서는 13 대 6 이라 차이가 작습니다. 반지름이 최대인 원판 두 개에서는 좌표 칸이 약 43 억
개인데, 오른쪽 끝에서만 멈추면 두 번이면 끝나요. 한 칸씩 옮기는 모양은 비용이 **좌표 범위**를 따라가고,
끝에서만 멈추는 모양은 **원판 수**를 따라갑니다.

##### 오른쪽 끝에서만 멈추는 까닭

세야 할 값이 바뀌는 순간은 원판이 닫히는 순간뿐입니다. 쌍을 원판이 닫힐 때 더하기로 했으니, 두 오른쪽 끝
사이의 좌표에서 멈춰도 더할 것이 없어요. 그래서 멈추는 자리를 오른쪽 끝 `n` 개로 줄일 수 있고, 그 자리를
작은 것부터 방문하려면 오른쪽 끝을 정렬해야 합니다.

| 기준점이 있는 곳 | 더할 것 | 멈출 필요 |
| --- | --- | --- |
| 원판의 오른쪽 끝 | 그 원판의 새 짝 | 있다 |
| 두 오른쪽 끝 사이 | 없다 | 없다 |

#### 1단계 — 원판을 두 끝 좌표로 바꾸기

원판 `j` 는 수직선에서 `[j − A[j], j + A[j]]` 를 차지합니다. 원판 여섯의 좌표는 「아이디어를 떠올리는
과정」의 첫 표에 있어요. 여기서 확인할 것은 좌표의 **범위**입니다. `j` 는 0 부터 99,999 까지입니다.
`A[j]` 는 2,147,483,647 까지라서 좌표가 이렇게 퍼져요.

| 좌표 | 가장 작은 값 | 가장 큰 값 |
| --- | --- | --- |
| 왼쪽 끝 `j − A[j]` | `0 − 2,147,483,647 = −2,147,483,647` | `99,999 − 0 = 99,999` |
| 오른쪽 끝 `j + A[j]` | `0 + 0 = 0` | `99,999 + 2,147,483,647 = 2,147,583,646` |

가장 큰 오른쪽 끝 2,147,583,646 은 32 비트 부호 있는 정수의 최댓값 2,147,483,647 을 넘습니다.
JavaScript 의 수는 2^53 까지 정수를 정확히 담으므로 이 코드에서는 문제가 없지만, 32 비트 정수 타입이
있는 언어로 옮길 때는 64 비트 타입으로 계산해야 해요.

#### 2단계 — 두 끝 좌표를 따로 정렬하기

왼쪽 끝을 모은 배열과 오른쪽 끝을 모은 배열을 **각각** 오름차순으로 정렬합니다. 어느 왼쪽 끝이 어느
원판의 것인지는 버려요. 스윕 라인이 쓰는 것은 「기준점 이하인 왼쪽 끝이 몇 개인가」라는 개수뿐이고,
개수는 원판 번호를 몰라도 셀 수 있기 때문입니다.

<!--proof:build-sorted-->

| 배열 | 원판 번호 순 | 오름차순으로 정렬한 뒤 |
| --- | --- | --- |
| 왼쪽 끝 starts | [-1 -4 0 2 0 5] | [-4 -1 0 0 2 5] |
| 오른쪽 끝 ends | [1 6 4 4 8 5] | [1 4 4 5 6 8] |

<!--/proof-->

정렬한 뒤의 `starts` 에서 −4 는 원판 1 의 것이고 −1 은 원판 0 의 것이지만, 배열에는 그 사실이 남지
않습니다. 그래도 답이 맞는지는 「수행으로 알아보는 알고리즘」의 첫 「짚고 가기」에서 전수로 확인해요.

#### 3단계 — 오른쪽 끝마다 열린 원판 세기

`ends` 를 앞에서부터 읽으며 `ends[i]` 에 멈춥니다. 멈출 때마다 `starts` 에서 `ends[i]` 이하인 값이
몇 개인지를 `opened` 에 둡니다. `ends` 가 오름차순이라 `ends[i]` 이하인 `starts` 는 이전 멈춤의 것을
모두 포함하니, `opened` 를 처음부터 다시 셀 필요 없이 **이어서 앞으로만** 옮기면 돼요.

<!--proof:build-opened-->
```text
끝 순서 i       0  1  2  3  4  5
ends[i]         1  4  4  5  6  8
이번에 연 수    4  1  0  1  0  0
opened          4  5  5  6  6  6
```
<!--/proof-->

「이번에 연 수」를 모두 더하면 6 이고, 원판 수와 같습니다. `opened` 는 뒤로 가지 않고 `n` 을 넘지
않으므로, 여섯 번 멈추는 동안 연 원판은 모두 합쳐 `n` 개예요. 이 합이 이 단계의 비용을 정합니다.

#### 4단계 — 먼저 닫힌 원판과 자기 자신 빼기

멈춤 `i` 에서 `opened` 에는 먼저 닫힌 원판 `i` 개와 지금 닫히는 원판 자신이 들어 있습니다. 먼저 닫힌
원판은 오른쪽 끝이 `ends[i]` 이하이고 왼쪽 끝은 그보다 작거나 같아서 반드시 들어 있고, 자신도 왼쪽 끝이
자기 오른쪽 끝 이하라서 들어 있어요. 그래서 `opened − (i + 1)` 이 새 짝의 수입니다. 번호 없이 센 이 값이
원판 번호로 직접 찾은 새 짝의 수와 같은지 멈춤마다 대조했습니다.

<!--proof:build-subtract-->

| 끝 순서 i | 오른쪽 끝 | 연 원판 수 | 뺄 수 i + 1 | 더할 수 | 원판 번호로 찾은 새 짝 | 판정 |
| ---: | ---: | ---: | ---: | ---: | --- | --- |
| 0 | 1 | 4 | 1 | 3 | 원판 1 · 원판 2 · 원판 4 | 같다 |
| 1 | 4 | 5 | 2 | 3 | 원판 1 · 원판 3 · 원판 4 | 같다 |
| 2 | 4 | 5 | 3 | 2 | 원판 1 · 원판 4 | 같다 |
| 3 | 5 | 6 | 4 | 2 | 원판 1 · 원판 4 | 같다 |
| 4 | 6 | 6 | 5 | 1 | 원판 4 | 같다 |
| 5 | 8 | 6 | 6 | 0 | 없음 | 같다 |

더할 수의 합은 11 이고, 모든 쌍을 대조한 답도 11 입니다.

<!--/proof-->

끝이 4 로 같은 원판 2 와 원판 3 을 봅시다. 두 원판은 점 4 를 함께 가지므로 교차합니다. 멈춤 1 에서
원판 2 가 먼저 닫히고, 그때 `opened = 5` 에는 원판 3 이 들어 있으며 원판 3 은 아직 닫히지 않았어요. 그래서
이 쌍은 멈춤 1 에서 한 번 더해지고, 멈춤 2 에서는 원판 2 가 「먼저 닫힌 원판」으로 빠집니다. 끝이 같은
원판끼리의 순서는 정렬이 정하는 대로 두어도 쌍을 한 번씩만 셉니다.

| 멈춤 | 닫히는 원판 | 원판 2 · 3 의 쌍 |
| --- | --- | --- |
| 1 | 원판 2 | 원판 3 이 아직 안 닫혀 새 짝으로 더한다 |
| 2 | 원판 3 | 원판 2 가 먼저 닫힌 원판이라 뺀다 |

#### 5단계 — 상한에서 멈추기

`count` 는 줄지 않습니다. 멈출 때마다 더하는 `opened − (i + 1)` 이 0 이상이기 때문이에요. 그래서 한 번
`limit` 을 넘으면 끝까지 세어도 넘은 채로 남고, 그 자리에서 −1 을 돌려주면 됩니다. 원판이 100,000 개이면
쌍은 최대 4,999,950,000 개라 상한 10,000,000 의 약 500 배까지 갈 수 있어요.

| 걸음을 마친 뒤 | `count` 와 `limit` | 할 일 |
| --- | --- | --- |
| `count ≤ limit` | 아직 넘지 않았다 | 다음 오른쪽 끝으로 간다 |
| `count > limit` | 넘었고 다시 내려오지 않는다 | −1 을 돌려주고 끝낸다 |

이 멈춤은 「아이디어를 떠올리는 과정」에서 버린 「상한에서 멈추기」와 같은 줄이지만 하는 일이 다릅니다.
그때는 멈춤이 속도를 낼 유일한 수단이었고, 여기서는 이미 빠른 절차에 답의 규칙을 입히는 것뿐이에요.

#### 이 방법이 기대는 전제

오른쪽 끝 순서 스윕 라인은 아래 전제에 기댑니다. 하나라도 빠지면 답이 틀리거나 쓸 수 없어요.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 원판마다 왼쪽 끝 ≤ 오른쪽 끝(반지름 ≥ 0) | 4단계 먼저 닫힌 원판과 자신이 `opened` 에 들어 있다 | 뺀 값이 음수가 되어 답이 틀린다 |
| 두 구간은 서로의 시작이 상대의 끝 이하일 때 겹친다 | 4단계 남는 원판이 반드시 짝이다 | 수직선 밖의 도형이면 이 조건이 아니다 |
| 원판이 도중에 바뀌지 않는다 | 2단계 정렬을 한 번만 한다 | 원판이 바뀔 때마다 다시 정렬해야 한다 |
| 경계 접촉을 교차로 센다 | 3단계 여는 조건이 `≤` 다 | 접촉을 빼려면 조건과 뺄 수를 함께 고쳐야 한다 |

마지막 줄의 「함께 고쳐야 한다」가 무엇을 뜻하는지는 「수행으로 알아보는 알고리즘」의
「짚고 가기 — 여는 조건에서 등호를 빼면」이 실행 결과로 보여 줍니다.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 네 걸음이 됩니다. 3~5단계는 오른쪽 끝마다 하는 한 걸음으로
묶여요.

1. 원판마다 왼쪽 끝 `j − A[j]` 와 오른쪽 끝 `j + A[j]` 를 구한다
2. 두 끝 좌표를 각각 오름차순으로 정렬해 `starts` · `ends` 로 둔다
3. `ends[i]` 마다 `starts[opened] ≤ ends[i]` 인 동안 `opened` 를 늘린다
4. `count` 에 `opened − (i + 1)` 을 더하고, `limit` 을 넘으면 −1 을 돌려준다

### 수행으로 알아보는 알고리즘 — 원판 여섯의 오른쪽 끝에서 여섯 번 멈춘다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 정해 끝까지
가져가되, 코드 조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

```ts
const A = [1, 5, 2, 1, 4, 0];
// 이 절이 끝나면 11 이 나와야 한다
```

이 입력을 고른 까닭은 이 절차가 만나는 모양이 다 들어 있어서입니다. 원판 2 와 3 은 오른쪽 끝이 같고,
원판 2 와 4 는 왼쪽 끝이 같으며, 원판 5 는 반지름이 0 이에요. 원판 1 · 4 는 다른 원판 여럿을 감싸고,
원판 0 과 5 는 떨어져 있습니다. 끝의 몇 걸음에서는 `opened` 가 이미 `n` 이라 while 이 다른 조건으로 멈춰요. 빠진 모양이 없습니다.

```text
절차 전체를 한 장으로

    starts ← 원판마다 j − A[j] 를 모아 오름차순 정렬
    ends   ← 원판마다 j + A[j] 를 모아 오름차순 정렬
    오른쪽 끝 ends[i] 를 i = 0 부터 n − 1 까지 차례로:
        ① 열기 — starts[opened] ≤ ends[i] 인 동안 opened 를 1 늘린다
        ② 세기 — count 에 opened − (i + 1) 을 더한다
        ③ 넘침 — count > limit 이면 −1 을 돌려준다
    count 를 돌려준다
```

#### 1. 두 끝 좌표를 모아 정렬한다

원판 번호 `j` 와 반지름 `r = A[j]` 로 두 끝을 만들고, 두 배열을 따로 정렬합니다. `map` 의 콜백은
`(값, 인덱스)` 순서로 인자를 받으므로 `(r, j)` 로 받아야 해요.

```ts
const starts = A.map((r, j) => j - r).sort((a, b) => a - b);
const ends = A.map((r, j) => j + r).sort((a, b) => a - b);
```

이 두 줄을 실행한 결과가 `T1` 과 `T2` 입니다.

<!--proof:walk-sorted-->
```text
T1  starts = [-4 -1 0 0 2 5]      원판 번호 순 [-1 -4 0 2 0 5] 을 정렬했다
T2  ends   = [1 4 4 5 6 8]         원판 번호 순 [1 6 4 4 8 5] 을 정렬했다
```
<!--/proof-->

여기서 가장 중요한 것은 `sort` 에 넘긴 `(a, b) => a − b` 입니다. 비교 함수가 없으면 `sort` 는 값을
문자열로 바꿔 사전 순으로 늘어놓아, `[10, 9]` 가 그대로 남고 `[−4, −1]` 이 `[−1, −4]` 가 돼요. 그러면
`starts` 가 오름차순이라는 3단계의 전제가 깨집니다.

#### 짚고 가기 — 두 끝을 따로 정렬해도 원판 짝이 필요 없는 까닭

여기서 헷갈리기 쉬운 부분이 있습니다. 「왼쪽 끝과 오른쪽 끝을 따로 정렬하면 어느 끝이 어느 원판의
것인지 사라지는데, 그래도 답이 맞을까」라는 걱정이에요. 원판 짝을 지킨 판을 따로 만들어 비교해
보았습니다. 짝을 지킨 판은 원판을 오른쪽 끝 순서로 늘어놓고, 원판마다 뒤에 오는 원판의 **자기** 왼쪽
끝을 하나씩 비교해 셉니다.

<!--proof:pause-separate-->

| 입력 | 따로 정렬한 판(정본) | 원판 짝을 지킨 판 | 판정 |
| --- | ---: | ---: | --- |
| 전개 입력 [1 5 2 1 4 0] | 11 | 11 | 같다 |
| [1 1] | 1 | 1 | 같다 |
| [0 0] | 0 | 0 | 같다 |
| [0 0 0] | 0 | 0 | 같다 |
| [10 10 10] | 3 | 3 | 같다 |
| [5] | 0 | 0 | 같다 |
| [] | 0 | 0 | 같다 |
| [0 1 0 1 0] | 5 | 5 | 같다 |
| [3 0 0 0 3] | 7 | 7 | 같다 |

길이가 0 부터 6 까지이고 반지름이 0 부터 3 까지인 배열 5,461 개를 전수로 대조했습니다. 두 판의 답이 어긋난 배열은 0 개입니다.

<!--/proof-->

**두 판의 답은 한 번도 갈리지 않습니다.** 까닭은 4단계가 쓰는 것이 원판 번호가 아니라 개수이기
때문이에요. 멈춤 `i` 에서 빼는 `i + 1` 은 「먼저 닫힌 원판과 자신은 모두 `ends[i]` 이하에서 시작했다」는
사실만으로 정해지고, 그 사실은 어느 왼쪽 끝이 누구의 것인지와 상관이 없습니다.

| 비교할 것 | 따로 정렬 | 원판 짝을 지킨 정렬 |
| --- | --- | --- |
| 멈춤마다 필요한 것 | `ends[i]` 이하인 왼쪽 끝의 **개수** | 뒤에 오는 원판마다 왼쪽 끝 비교 |
| 멈춤 하나의 비용 | 새로 연 원판 수만큼 | 뒤에 남은 원판 수만큼 |
| 전체 비용 | 정렬 + `2n` 이하 | 정렬 + `n(n−1)/2` |

짝을 지키면 답은 같아도 비용이 모든 쌍 대조와 같아집니다. 번호를 버리는 것이 속도를 내는 자리예요.

#### 2. 오른쪽 끝 이하에서 시작한 원판을 연다

첫 오른쪽 끝에 멈추고, 그 끝 이하에서 시작한 원판을 셉니다. `opened` 는 다음 멈춤으로 넘어가도 0 으로
되돌리지 않아요.

```ts
let opened = 0;
const end = ends[i] as number;
while (opened < n && (starts[opened] as number) <= end) {
  // ① 열기 — 이 오른쪽 끝 이하에서 시작한 원판을 하나 더 센다.
  opened++;
}
```

`i = 0` 으로 이 조각만 실행한 걸음이 `T3` 입니다. while 조건의 참과 거짓을 실제 값으로 적었어요.

<!--proof:walk-open-first-->
```text
T3  end = ends[0] = 1
    starts[0] = -4 ≤ 1 참 → ① opened = 1
    starts[1] = -1 ≤ 1 참 → ① opened = 2
    starts[2] = 0 ≤ 1 참 → ① opened = 3
    starts[3] = 0 ≤ 1 참 → ① opened = 4
    starts[4] = 2 ≤ 1 거짓 → 멈춘다. opened = 4
```
<!--/proof-->

while 이 멈추는 조건은 둘입니다. 다음 왼쪽 끝이 지금 오른쪽 끝보다 크거나(`T3` 의 `2 ≤ 1` 거짓), 모든
원판을 이미 열어 `opened < n` 이 거짓이거나예요. 뒤쪽 조건은 뒤 걸음 `T6` 부터 나옵니다.

#### 짚고 가기 — 여는 조건에서 등호를 빼면 반지름 0 인 원판이 자기 자신을 못 연다

여기서 헷갈리기 쉬운 부분은 `<=` 의 등호입니다. 「왼쪽 끝이 오른쪽 끝과 딱 같은 경우는 드무니 `<` 로
써도 되지 않나」라고 읽기 쉬워요. 여는 조건 한 곳만 `<` 로 바꾼 코드를 정본과 함께 실행해 보았습니다.
「시작 = 끝 인 짝」 열은 왼쪽 끝 하나와 오른쪽 끝 하나가 같은 좌표인 경우의 수이고, 등호만이 그 비교를
참으로 만듭니다.

<!--proof:pause-touch-->

| 입력 | 시작 = 끝 인 짝 | 정본 | 등호를 뺀 판 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 [1 5 2 1 4 0] | 1 | 11 | 10 | 어긋난다 |
| [1 1] | 0 | 1 | 1 | 같다 |
| [0 0] | 2 | 0 | -2 | 어긋난다 |
| [0 0 0] | 3 | 0 | -3 | 어긋난다 |
| [10 10 10] | 0 | 3 | 3 | 같다 |
| [5] | 0 | 0 | 0 | 같다 |
| [] | 0 | 0 | 0 | 같다 |
| [0 1 0 1 0] | 8 | 5 | -3 | 어긋난다 |
| [3 0 0 0 3] | 5 | 7 | 2 | 어긋난다 |

<!--/proof-->

전개 입력에서 답이 11 대신 10 이 나오고, `[0 0]` 에서는 **−2** 가 나옵니다. 반지름이 0 인 원판은 왼쪽
끝과 오른쪽 끝이 같아서, 등호가 없으면 자기 오른쪽 끝에 멈췄을 때 자기 자신을 열지 못해요. 그런데 4단계는
자신이 `opened` 에 들어 있다고 보고 1 을 빼므로 더하는 값이 음수가 됩니다. 등호는 경계 접촉을 셀지
말지만 정하는 것이 아니라, **4단계의 뺄셈이 기대는 전제**를 지키는 자리예요. 한 글자가 답의 부호까지 바꿉니다.

| 입력 `[0 0]` 의 멈춤 | 정본 `opened` | 등호를 뺀 판 `opened` | 더하는 값(정본 / 뺀 판) |
| --- | --- | --- | --- |
| 오른쪽 끝 0 | 1 | 0 | 0 / −1 |
| 오른쪽 끝 1 | 2 | 1 | 0 / −1 |

`[1 1]` 과 `[10 10 10]` 은 답이 같습니다. 두 입력에는 「시작 = 끝 인 짝」이 0 개라 바뀐 비교를 한 번도
참과 거짓이 갈리게 지나가지 않았어요. 이런 입력만으로 시험하면 이 실수는 통과합니다.

#### 3. 먼저 닫힌 원판을 빼고 새 짝을 더한다

연 원판 가운데 먼저 닫힌 `i` 개와 자신을 빼서 더합니다. 이 줄을 `i` 에 대한 반복 안에 두면 스윕 라인이
완성돼요.

```ts
let count = 0;
let opened = 0;
for (let i = 0; i < n; i++) {
  const end = ends[i] as number;
  while (opened < n && (starts[opened] as number) <= end) {
    // ① 열기 — 이 오른쪽 끝 이하에서 시작한 원판을 하나 더 센다.
    opened++;
  }
  // ② 세기 — 열린 원판에서 먼저 닫힌 i 개와 자기 자신을 뺀 나머지가 새로 만나는 원판이다.
  count += opened - (i + 1);
}
```

고정 입력에 끝까지 실행하면 걸음이 여섯 나옵니다. `T3` 부터 `T8` 까지가 `i = 0` 부터 5 까지예요. 무대는
정렬하는 `T1` · `T2` 부터 그렸습니다. 위 줄이 `starts`, 아래 줄이 `ends` 이고, 괄호 「연 원판」은 지금까지 연
`starts` 의 앞부분, 위 줄의 ▲ 는 이번에 새로 연 칸, 아래 줄의 ▲ 는 이번에 멈춘 오른쪽 끝입니다.

<!--fig:walk-sweep-->
![countIntersectingDiscs([1, 5, 2, 1, 4, 0]) 의 여덟 걸음 T1~T8](./figs/walk-sweep.svg)

걸음마다 조건의 참과 거짓을 적었습니다. ③ 조건은 다음 걸음에서 넣을 줄이지만, 상한 10,000,000 으로 미리
따져 적었어요.

<!--proof:walk-trace-->

| 걸음 | i | end | ① 로 연 수 | while 이 멈춘 조건 | opened | ② 더한 수 | count | ③ 조건 |
| --- | ---: | ---: | ---: | --- | ---: | --- | ---: | --- |
| T3 | 0 | 1 | 4 | 2 ≤ 1 거짓 | 4 | 4 − 1 = 3 | 3 | 3 > 10,000,000 거짓 |
| T4 | 1 | 4 | 1 | 5 ≤ 4 거짓 | 5 | 5 − 2 = 3 | 6 | 6 > 10,000,000 거짓 |
| T5 | 2 | 4 | 0 | 5 ≤ 4 거짓 | 5 | 5 − 3 = 2 | 8 | 8 > 10,000,000 거짓 |
| T6 | 3 | 5 | 1 | opened < n 거짓 | 6 | 6 − 4 = 2 | 10 | 10 > 10,000,000 거짓 |
| T7 | 4 | 6 | 0 | opened < n 거짓 | 6 | 6 − 5 = 1 | 11 | 11 > 10,000,000 거짓 |
| T8 | 5 | 8 | 0 | opened < n 거짓 | 6 | 6 − 6 = 0 | 11 | 11 > 10,000,000 거짓 |

<!--/proof-->

**① 과 ② 가 모두 실행됐습니다.** ① 은 `T3` 에서 네 번, `T4` · `T6` 에서 한 번씩 모두 여섯 번 실행됐고, ② 는
여섯 걸음마다 한 번씩 실행됐어요. while 이 멈춘 조건도 두 가지가 다 나왔습니다. `T3` 부터 `T5` 까지는 왼쪽 끝이
커서, `T6` 부터 `T8` 까지는 원판을 모두 열어서 멈췄어요. 반환값은 마지막 `count` 인 11 입니다.

| 갈래 | 하는 일 | 걸음 | 실행 횟수 |
| --- | --- | --- | ---: |
| ① | 원판을 연다 | T3 T4 T6 | 6 번 |
| ② | 새 짝을 더한다 | T3 T4 T5 T6 T7 T8 | 6 번 |

`T5` 에서는 ① 이 한 번도 실행되지 않았는데 ② 는 2 를 더했습니다. 새로 연 원판이 없어도, 먼저 열려
있다가 아직 닫히지 않은 원판이 지금 닫히는 원판 3 의 짝이기 때문이에요.

#### 4. 상한을 넘으면 −1 로 멈춘다

마지막으로 상한을 넣습니다. `count` 가 줄지 않으니 넘는 즉시 돌려줘도 됩니다.

```ts
if (count > limit) {
  // ③ 넘침 — 상한을 넘었으니 더 세지 않는다.
  return -1;
}
```

상한 10,000,000 으로는 고정 입력의 답 11 이 넘지 않아 ③ 이 실행되지 않습니다. 그래서 같은 입력에
`limit = 10` 을 넘겨 한 번 더 실행했어요. `T3` 부터 `T6` 까지는 앞 걸음과 같고, `T7` 에서 ③ 이 실행됩니다.

<!--proof:walk-limit-->

| 걸음 | count | ③ 조건 |
| --- | ---: | --- |
| T3 | 3 | 3 > 10 거짓 |
| T4 | 6 | 6 > 10 거짓 |
| T5 | 8 | 8 > 10 거짓 |
| T6 | 10 | 10 > 10 거짓 |
| T7 | 11 | 11 > 10 참 → ③ return −1 |

정본에 상한 10 을 넘겨 실행한 반환값은 -1 이고, 상한을 안 넘긴 반환값은 11 입니다.

<!--/proof-->

`T6` 의 `10 > 10` 은 거짓이라 멈추지 않습니다. 상한과 **같은** 값은 아직 넘은 것이 아니므로 `>` 가 맞아요.
`T7` 에서 11 이 되는 순간 ③ 이 −1 을 돌려주고, `T8` 은 실행되지 않습니다.

#### 5. 전체 코드

조각을 하나로 이어 붙입니다. 앞에서 확인한 것 말고 새로 들어간 것은 상한의 기본값을 상수로 둔 줄과,
원판이 없을 때 `ends` 가 비어 반복을 한 번도 실행하지 않고 0 을 돌려주는 흐름뿐이에요.

```ts
export const DEFAULT_LIMIT = 10_000_000;

export function countIntersectingDiscs(
  A: number[],
  limit = DEFAULT_LIMIT,
): number {
  const n = A.length;
  // 원판 j 는 수직선 위의 구간 [j − A[j], j + A[j]] 이다. 두 끝을 따로 모아 오름차순으로 둔다.
  const starts = A.map((r, j) => j - r).sort((a, b) => a - b);
  const ends = A.map((r, j) => j + r).sort((a, b) => a - b);

  let count = 0;
  let opened = 0;
  for (let i = 0; i < n; i++) {
    const end = ends[i] as number;
    while (opened < n && (starts[opened] as number) <= end) {
      // ① 열기 — 이 오른쪽 끝 이하에서 시작한 원판을 하나 더 센다.
      opened++;
    }
    // ② 세기 — 열린 원판에서 먼저 닫힌 i 개와 자기 자신을 뺀 나머지가 새로 만나는 원판이다.
    count += opened - (i + 1);
    if (count > limit) {
      // ③ 넘침 — 상한을 넘었으니 더 세지 않는다.
      return -1;
    }
  }
  return count;
}
```

```text
countIntersectingDiscs([1, 5, 2, 1, 4, 0])        →  11
countIntersectingDiscs([1, 5, 2, 1, 4, 0], 10)    →  -1
countIntersectingDiscs([])                        →  0
countIntersectingDiscs([0, 0, 0])                 →  0
```

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 오른쪽 끝 순서 스윕 라인이 맞는지, 걸음마다 무엇이
참으로 남는지, 비용이 얼마인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때 오른쪽 끝 순서 스윕 라인이 가장 알맞습니다.

- 대상이 **수직선 위의 닫힌 구간**입니다. 원판처럼 중심과 반지름으로 주어져도 구간으로 옮길 수 있으면
  됩니다.
- 묻는 것이 겹치는 쌍의 **개수**입니다. 쌍을 모두 나열해야 하면 답의 크기만큼 시간이 들어요.
- 구간이 **한 번에 다 주어지고** 도중에 바뀌지 않습니다. 정렬을 한 번 하고 한 번 차례로 읽는 절차예요.
- 구간 수 `n` 이 커서 `n(n−1)/2` 번 대조가 예산을 넘습니다. `n = 100,000` 이면 약 50 억 번이에요.

| 조건 | 코드에 나타나는 모양 |
| --- | --- |
| 닫힌 구간 | 여는 조건이 `≤` 다 |
| 개수만 묻는다 | 원판 번호를 버리고 두 배열을 따로 정렬한다 |
| 한 번에 주어진다 | 정렬이 반복 밖에 한 번 있다 |
| 구간이 많다 | 반복 안의 일이 모두 합쳐 `2n` 번 비교 이하다 |

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 뜻 | 스윕 라인 사용 |
| --- | --- | --- | --- |
| 지문 | "겹치는 쌍의 수" "교차하는 쌍의 수" | 개수를 묻는다 | 쓴다 |
| 지문 | "중심 `i`, 반지름 `A[i]`" "시작 시각과 끝 시각" | 구간으로 옮길 수 있다 | 쓴다 |
| 지문 | "경계에서 만나도 겹친 것으로 본다" | 닫힌 구간이다. 여는 조건을 `≤` 로 둔다 | 쓴다 |
| 제약 | 구간 수가 10^5 규모 | 모든 쌍 대조가 예산을 넘는다 | 쓴다 |
| 지문 | "답이 10^7 을 넘으면 −1" | 답이 `n²` 규모로 커질 수 있다 | 쓴다. 상한은 반복 안에서 확인한다 |
| 지문 | "겹치는 쌍을 모두 출력하라" | 나열을 묻는다 | 개수 세기만으로는 안 된다 |
| 지문 | "구간을 추가하거나 지운다" | 구간이 바뀐다 | 한 번 정렬하는 절차로는 안 된다 |

#### 실제로 쓰이는 곳

  구현입니다. 헤더는 이 클래스를 `"The btAxisSweep3 is an efficient implementation of the 3d axis sweep and

  ([btAxisSweep3.h](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/BroadphaseCollision/btAxisSweep3.h),
  [btAxisSweep3Internal.h](https://github.com/bulletphysics/bullet3/blob/master/src/BulletCollision/BroadphaseCollision/btAxisSweep3Internal.h),

  ([bedtools intersect](https://bedtools.readthedocs.io/en/latest/content/tools/intersect.html), 조회 2026-09-29)

| --- | --- | --- | --- |
| Bullet `btAxisSweep3` | 물체를 감싼 상자의 축별 범위 | 축마다 시작점 · 끝점 | 물체가 움직이면 정렬을 조금씩 고쳐 겹침을 늘리고 줄인다 |

| 이 글 | 원판의 수직선 위 범위 | 왼쪽 끝 · 오른쪽 끝을 따로 | 개수만 세므로 원판 번호를 버린다 |

### 불변식 — 멈춤 i 를 마치면 count 는 끝 순서 0 ~ i 번 원판이 앞선 쪽인 교차 쌍의 수이다

파트 1 에서 코드가 동작하는 모습을 여섯 걸음으로 확인했습니다. 하지만 그것은 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. **매 걸음 참으로 남는 것**이 무엇인지 문장으로 세우고, 그것이
실제로 유지되는지 확인해 봅시다. 여기서 「끝 순서 `p` 번 원판」은 오른쪽 끝을 오름차순으로 늘어놓았을 때
`p` 번째 원판이고, 끝이 같으면 정렬이 정한 순서를 따릅니다.

> 반복의 `i` 번째 걸음을 마친 시점마다 `opened` 는 `ends[i]` 이하인 왼쪽 끝의 개수이고, `count` 는 교차하는
> 쌍 가운데 끝 순서가 앞선 원판이 0 ~ `i` 번인 쌍의 수입니다.

<!--fig:invariant-stop-->
![멈춤 2 — 새로 연 원판이 없어도 opened 5 가 이어지고, 먼저 닫힌 2 개와 자신을 빼 새 짝 2 개, count = 8](./figs/invariant-stop.svg)

| 문장 | 참인 것 | 지키는 코드 |
| --- | --- | --- |
| 앞 문장 | `opened = #{ p : starts[p] ≤ ends[i] }` | 여는 while 과 그 조건의 `≤` |
| 뒤 문장 | `count` = 앞선 쪽이 0 ~ `i` 번인 교차 쌍의 수 | 새 짝을 더하는 줄의 `opened − (i + 1)` |

두 문장은 서로 기댑니다. 앞 문장이 참이어야 `opened − (i + 1)` 이 끝 순서 `i` 번 원판의 새 짝의 수가
되고, 그래야 뒤 문장이 한 걸음 더 참으로 남아요. 반복이 끝나면 `i = n − 1` 이라 뒤 문장의 「0 ~ `n − 1`
번」은 모든 원판이고, 교차하는 쌍은 모두 앞선 쪽이 있으니 `count` 가 답입니다.

**출발점부터 봅시다.** 반복 전에는 `opened = 0`, `count = 0` 이고, 아직 멈춘 자리가 없으니 센 쌍도 없어서
참이에요. 걸음 하나가 두 문장을 어떻게 이어받는지 적으면 이렇습니다.

| 갈래 | 코드 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 원판을 연다 | `opened++` | `starts` 가 오름차순이라 `ends[i]` 이하인 값은 앞쪽에 몰려 있다 | — |
| while 이 멈춘다 | 조건 거짓 | 다음 값이 `ends[i]` 보다 크거나 남은 값이 없다 | — |
| 새 짝을 더한다 | `count += …` | — | 앞선 쪽이 `i` 번인 교차 쌍이 정확히 `opened − (i + 1)` 개다 |
| 상한을 넘는다 | `return -1` | — | `count` 가 줄지 않아 넘은 채로 끝난다 |

「새 짝을 더한다」 줄의 「정확히」를 풀어 보겠습니다. 끝 순서 0 ~ `i − 1` 번 원판 `i` 개와 `i` 번 원판 자신은 왼쪽 끝이
`ends[i]` 이하라서 `opened` 에 들어 있어요. 나머지 원판 `q` 는 끝 순서가 `i` 보다 뒤이면서 왼쪽 끝이
`ends[i]` 이하입니다. 그러면 `q` 의 시작 ≤ `i` 번의 끝이고, `i` 번의 시작 ≤ `i` 번의 끝 ≤ `q` 의 끝이라
두 원판은 겹쳐요. 거꾸로 끝 순서가 뒤이면서 겹치는 원판은 시작이 `ends[i]` 이하이므로 모두 `opened`
안에 있습니다.

이것을 실제 값으로 확인합니다. 걸음마다 `opened` 와 `count` 를 정의대로 직접 센 값과 대조했어요.

<!--proof:invariant-steps-->

| 걸음 | opened | 시작이 end 이하인 원판(직접 셈) | count | 앞선 원판이 끝 순서 0 ~ i 인 교차 쌍(직접 셈) | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| T3 | 4 | 4 | 3 | 3 | 같다 |
| T4 | 5 | 5 | 6 | 6 | 같다 |
| T5 | 5 | 5 | 8 | 8 | 같다 |
| T6 | 6 | 6 | 10 | 10 | 같다 |
| T7 | 6 | 6 | 11 | 11 | 같다 |
| T8 | 6 | 6 | 11 | 11 | 같다 |

여섯 걸음 모두에서 두 값을 직접 센 값과 대조했고, 어긋난 걸음은 0 개입니다.

<!--/proof-->

경계에 있는 입력도 확인하고 넘어갑시다. 답을 모든 쌍을 대조한 값과 비교했습니다.

<!--proof:invariant-edges-->

| 경계 | 반지름 | 답 | 모든 쌍을 대조한 값과 |
| --- | --- | ---: | --- |
| 원판이 없음 | [] | 0 | 같다 |
| 원판 하나 | [5] | 0 | 같다 |
| 원판 둘이 겹침 | [1 1] | 1 | 같다 |
| 한 점짜리 둘, 거리 1 | [0 0] | 0 | 같다 |
| 모두 서로 겹침 | [10 10 10] | 3 | 같다 |
| 반지름이 모두 0 | [0 0 0] | 0 | 같다 |
| 최대 반지름 둘 | [2147483647 2147483647] | 1 | 같다 |

<!--/proof-->

원판이 없으면 `n = 0` 이라 반복이 한 번도 실행되지 않고 `count = 0` 을 돌려줍니다. 원판이 하나면 멈춤 하나에서
`opened = 1`, 더하는 값이 `1 − 1 = 0` 이에요. `[0 0]` 은 두 점이 거리 1 만큼 떨어져 있어서, 멈춤 0 에서
왼쪽 끝 1 이 오른쪽 끝 0 보다 커 `opened = 1` 에 머물고 0 을 더합니다. 반지름이 최대인 원판 두 개는 오른쪽 끝이
2,147,483,648 로 32 비트 정수 범위를 넘습니다. JavaScript 의 수는 이 값을 정확히 담아 답 1 이 나와요.

**이제 코드 한 곳을 바꿔 확인해 봅시다.** 뒤 문장을 지키는 것은 새 짝을 더하는 줄이고, 그 줄에서
불변식과 직접 맞물리는 자리는 **먼저 닫힌 원판을 빼는 항**입니다. 「자기 자신만 빼면 된다」는 생각으로
`opened − (i + 1)` 을 `opened − 1` 로 바꿔 보겠습니다.

```ts
count += opened - 1;   // ← i + 1 대신 1
```

<!--proof:mutant-no-closed-->

| 입력 | 먼저 닫힌 원판 수의 합 | 정본 | 먼저 닫힌 원판을 안 뺀 판 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 [1 5 2 1 4 0] | 15 | 11 | 26 | 어긋난다 |
| [1 1] | 1 | 1 | 2 | 어긋난다 |
| [0 0] | 1 | 0 | 1 | 어긋난다 |
| [0 0 0] | 3 | 0 | 3 | 어긋난다 |
| [10 10 10] | 3 | 3 | 6 | 어긋난다 |
| [5] | 0 | 0 | 0 | 같다 |
| [] | 0 | 0 | 0 | 같다 |
| [0 1 0 1 0] | 10 | 5 | 15 | 어긋난다 |
| [3 0 0 0 3] | 10 | 7 | 17 | 어긋난다 |

<!--/proof-->

전개 입력의 답이 11 에서 26 으로 늘었습니다. 늘어난 15 는 「먼저 닫힌 원판 수의 합」 열의 값과 같아요.
멈춤 `i` 마다 먼저 닫힌 원판 `i` 개를 짝으로 한 번 더 셌으니 `0 + 1 + 2 + 3 + 4 + 5 = 15` 가 더해진 것이고,
그 원판들과의 쌍은 앞선 쪽의 걸음에서 이미 셌거나 아예 겹치지 않는 쌍입니다.

| 코드 | 멈춤 5 (원판 4 가 닫힌다)에서 더하는 값 | 그 값이 가리키는 것 |
| --- | --- | --- |
| 바른 코드 | `6 − 6 = 0` | 새 짝이 없다 |
| 바꾼 코드 | `6 − 1 = 5` | 먼저 닫힌 원판 0 · 2 · 3 · 5 · 1 을 다시 짝으로 센다 |

원판이 없거나 하나뿐인 두 줄만 답이 같은데, 먼저 닫힌 원판 수의 합이 0 이라 바뀐 항이 값을 한 번도
바꾸지 않았기 때문이에요. 원판이 둘 이상이면 이 변이는 언제나 `n(n−1)/2` 만큼 더 셉니다.

### 비용 계산

#### 비용을 세는 과정

한 번 실행할 때 하는 일은 세 가지입니다. 두 배열을 정렬하는 일, 원판을 여는 비교, 걸음마다 새 짝을
더하는 일이에요. 전개 입력의 걸음으로 보면 정렬이 T1 · T2, 여는 비교와 더하기가 T3 부터 T8 까지였습니다.

| 하는 일 | 걸음 | 비용 |
| --- | --- | --- |
| 정렬 두 번 | T1 T2 | 비교 18 번(Bun 의 내장 정렬로 실측) |
| 여는 비교 | T3 ~ T8 | 참 6 번(원판 수) + 거짓 3 번(T3 · T4 · T5) = 9 번 |
| 새 짝 더하기 | T3 ~ T8 | 걸음마다 1 번 → 6 번 |

여는 비교가 `2n` 을 넘지 않는 까닭은 두 가지로 나뉩니다. 참이 된 비교는 `opened` 를 1 늘리고 `opened` 는
`n` 을 넘지 않으니 모두 합쳐 `n` 번 이하예요. 거짓이 된 비교는 while 을 끝내므로 걸음마다 한 번 이하이고,
걸음이 `n` 개이니 `n` 번 이하입니다. 전개 입력에서는 참 6 번과 거짓 3 번이었고, `T6` 부터 `T8` 까지는 `opened < n`
이 먼저 거짓이 되어 비교가 없었어요. 규모를 키워 세어 보았습니다.

| 6 | 18 | 9 | 12 | 6 | 11 |
| 1,000 | 13,693 | 1,972 | 2,000 | 1,000 | 48,042 |
| 100,000 | 2,034,853 | 199,972 | 200,000 | 100,000 | 4,948,542 |

<!--/proof-->

세 규모 모두 여는 비교가 `2n` 이하입니다. 비용의 대부분은 정렬이에요. `n = 100,000` 에서 정렬 비교는
여는 비교의 10 배쯤 됩니다. 정렬 비교의 수는 엔진의 정렬 구현에 달려 있으므로
이 저장소의 Bun 에서 잰 값이고, 규모는 `n log₂ n` 을 따릅니다.

| 항목 | 횟수 | `n = 100,000` 일 때(실측) |
| --- | --- | ---: |
| 정렬 두 번(비교) | `O(n log n)` | 2,034,853 |
| 여는 비교 | `2n` 이하 | 199,972 |
| 새 짝 더하기 | `n` 이하 | 100,000 |

추가로 잡는 메모리는 `starts` 와 `ends` 두 배열, 곧 `2n` 칸입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 서로 다른 축입니다. 「최악은 `O`, 평균은
`Θ`」처럼 한쪽을 다른 쪽에 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (상한을 일찍 넘어 반복이 빨리 끝난다) | `O(n log n)` | `Θ(n log n)` — 정렬은 반복 전에 끝까지 한다 |
| **평균적인 경우** (입력 분포를 정하지 않으면 정의되지 않는다) | `O(n log n)` | 분포를 정하면 `Θ(n log n)` |
| **최악의 경우** (답이 상한 이하라 반복을 끝까지 실행한다) | `O(n log n)` | `Θ(n log n)` |

평균 줄은 분포 없이는 뜻이 없습니다. 다만 세 줄의 상한이 모두 정렬 비용 하나로 정해지므로, 어떤 분포를
잡아도 `O(n log n)` 을 넘지 않아요.

**총식을 한 번은 정확히 적어 둡니다.** 정렬 두 번과 한 번 차례로 읽기가 전부예요.

| 자원 | 총식 | 이루는 것 | `n = 100,000` 일 때 |
| --- | --- | --- | --- |
| 시간 | `Θ(n log n)` | 정렬 `2 × Θ(n log n)` + 여는 비교 `≤ 2n` + 더하기 `≤ n` | 비교 2,234,825 번 + 더하기 100,000 번 |
| 추가 메모리 | `Θ(n)` | `starts` · `ends` | `2n` = 200,000 칸 |

**보장의 종류는 최악 보장입니다.** 이 코드에는 난수가 없고 입력 분포를 가정하는 곳도 없어요. 정렬도 최악
`O(n log n)` 인 엔진 구현을 전제합니다.

| 보장의 종류 | 뜻 | 이 절차 |
| --- | --- | --- |
| 기댓값이면 | 같은 규모라도 입력에 따라 상한을 넘을 수 있다 | 이 절차는 해당 없다 |
| 최악 보장이면 | 어떤 입력이든 상한 아래다 | 이쪽이다 |

#### 최악을 만드는 입력

반복을 가장 오래 실행하게 하는 입력은 **답이 상한 이하라서 끝까지 반복하는 입력**입니다. 「원판이 크면 쌍이 많아
느리다」는 생각이 여기서도 맞는지 값으로 확인해 봅시다.

<!--proof:worst-shape-->

n = 100,000 에서 반지름 모양 다섯으로 세었습니다.

| 반지름 모양 | 정렬 비교 | 여는 비교 | 바깥 반복 | 답 |
| --- | ---: | ---: | ---: | ---: |
| 전부 0 | 199,998 | 199,999 | 100,000 | 0 |
| 전부 1 | 199,998 | 199,997 | 100,000 | 199,997 |
| 생성식 (37j + 11) mod 50 | 2,034,853 | 199,972 | 100,000 | 4,948,542 |
| 짝수 번은 j, 홀수 번은 1 | 2,450,351 | 50,336 | 201 | −1 |
| 전부 n | 199,998 | 100,000 | 101 | −1 |

<!--/proof-->

**「원판이 크면 느리다」는 이 절차에서는 틀린 말입니다.** 반지름이 전부 `n` 이면 쌍이 약 50 억 개인데도,
바깥 반복이 101 번 만에 상한을 넘어 끝나요. 반대로 반지름이 전부 0 인 입력은 답이 0 이라 100,000 번을
끝까지 반복합니다. 여는 비교가 가장 많은 것도 이쪽이에요.

| 입력 | 바깥 반복 | 여는 비교 | 정렬 비교 |
| --- | ---: | ---: | --- |
| 전부 0 | 100,000 | 199,999 | 이미 정렬돼 있어 199,998 번이다 |
| 짝수 번은 `j`, 홀수 번은 1 | 201 | 50,336 | 다섯 모양 중 가장 많은 2,450,351 번이다 |

그래서 최악은 두 부분으로 나눠 만들어집니다. 반복 쪽은 **답을 상한 이하로 두면** 끝까지 반복하고, 정렬 쪽은
**좌표를 흩어 놓으면** 비교가 늘어요. 생성식 입력은 두 가지를 함께 가져 정렬 비교 2,034,853 번과 반복
100,000 번을 모두 씁니다. 그래도 비교가 모두 합쳐 약 223 만 번이라 예산 1 초에 여유가 커요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하겠습니다. 구간의 왼쪽 끝과 오른쪽 끝을 **따로** 정렬하고, 오른쪽 끝마다
「그 끝 이하에서 시작한 구간 수 − (먼저 닫힌 구간 수 + 1)」을 더합니다. 쌍은 오른쪽 끝이 먼저 오는 쪽에서
한 번만 세지고, 여는 포인터가 뒤로 가지 않아 차례로 읽기가 `2n` 번 비교 안에 끝나요.

| 순서 | 하는 일 | 규모 |
| ---: | --- | --- |
| 1 | 두 끝 좌표를 따로 정렬한다 | `O(n log n)` |
| 2 | 오른쪽 끝마다 `opened` 를 앞으로 옮긴다 | 모두 합쳐 `2n` 번 비교 이하 |
| 3 | `opened − (i + 1)` 을 더하고 상한을 본다 | 걸음마다 1 번 |

먼저 답이 붙은 문제 하나입니다. 전개 입력의 T5 는 ① 을 한 번도 실행하지 않았는데 2 를 더했어요. 그 2 는
어느 원판과의 쌍일까요?

| 걸음 | i | end | ① 로 연 수 | opened | 더한 수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| T5 | 2 | 4 | 0 | 5 | 2 |

<!--check:c1-->
답: 원판 1 과 원판 4 입니다. T5 는 오른쪽 끝 4 의 두 번째 멈춤이라 여기서 닫히는 원판은 원판 3(구간 `[2,4]`)이에요.
`opened = 5` 에 든 원판은 0 · 1 · 2 · 3 · 4 이고, 그중 원판 0 · 2 는 먼저 닫혔고 원판 3 은 자신입니다.

| 원판 | 구간 | T5 에서 |
| --- | --- | --- |
| 원판 0 | `[-1,1]` | 먼저 닫혔다. 원판 3 과 겹치지 않는다 |
| 원판 2 | `[0,4]` | 먼저 닫혔다. 원판 3 과의 쌍은 T4 에서 이미 셌다 |
| 원판 3 | `[2,4]` | 자기 자신 |
| 원판 1 | `[-4,6]` | 남는다. 원판 3 과 겹친다 |
| 원판 4 | `[0,8]` | 남는다. 원판 3 과 겹친다 |

새로 연 원판이 없어도, 이전 걸음에서 열렸고 아직 닫히지 않은 원판은 지금 닫히는 원판의 짝이 됩니다.

### Number of Disc Intersections

풀 파일: [`numberOfDisintersection.ts`](./numberOfDisintersection.ts) · 테스트: [`numberOfDisintersection.test.ts`](./numberOfDisintersection.test.ts) · 실행: `bun test src/algorithms/etc/numberOfDisintersection/numberOfDisintersection.test.ts`

#### 한 줄 요약

> 함수는 원판의 반지름 배열을 받아 서로 교차하는 원판 쌍의 수를 반환한다.

#### 스토리

물리학 실험에서 수직 막대들이 수평 수직선 위에 일정 간격으로 꽂혀 있다. 각 막대 끝에는 원판이 달려 있는데, 원판마다 크기가 다르다. $J$번 막대는 수직선 위 좌표 $J$에 위치하고, 원판의 반지름은 $A[J]$다.

연구자는 어떤 두 원판이 서로 겹치는지(경계 포함) 알고 싶다. 두 원판이 겹친다는 것은 적어도 하나의 공통점을 갖는다는 뜻이다. 교차하는 쌍이 너무 많으면 분석이 의미 없으므로, $10{,}000{,}000$을 초과하면 $-1$을 반환하기로 약속했다.

주어진 원판 배열에서 교차하는 순서 없는 쌍의 수를 구하라.

#### 함수 인터페이스

```ts
export function solution(A: number[]): number;
```

- `A` — 길이 $N$인 비음수 정수 배열. `A[J]`는 $J$번 원판의 반지름
- 반환 — 교차하는 원판 쌍의 수. $10{,}000{,}000$ 초과 시 $-1$

#### 제약 조건

- $0 \leq N \leq 100{,}000$ ($N$은 `A`의 길이)
- 각 원소는 $0 \leq A[J] \leq 2{,}147{,}483{,}647$인 정수
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

$J$번 원판의 중심은 $(J, 0)$이고 반지름은 $A[J]$이므로, x축 위의 구간 $[J - A[J],\; J + A[J]]$를 차지한다.

두 원판 $J$, $K$ ($J \neq K$)가 교차하는 조건은 다음과 같다.

$$\text{intersect}(J, K) \iff |J - K| \leq A[J] + A[K]$$

교차하는 순서 없는 쌍 $(J, K)$의 전체 수를 반환한다. 단, 이 수가 $10{,}000{,}000$을 초과하면 $-1$을 반환한다.

#### 예시

```ts
solution([1, 5, 2, 1, 4, 0]);
// 11
// 원판 0: [-1, 1], 원판 1: [-4, 6], 원판 2: [0, 4]
// 원판 3: [2, 4],  원판 4: [0, 8],  원판 5: [5, 5]
// 원판 1은 0, 2, 3, 4, 5 모두와 교차 (5쌍)
// 원판 4는 0, 2, 3, 5와 교차 (4쌍, 1과의 쌍은 이미 계산)
// 원판 2는 0, 3과 추가 교차 (2쌍)
// 합계 11쌍

solution([]);  // 0 — 원판이 없어 쌍 없음
solution([0]); // 0 — 원판이 하나뿐이어서 쌍 불가
solution([1, 1]); // 1 — 원판 0: [-1,1], 원판 1: [0,2], 구간 [0,1] 이 겹침

solution([0, 0, 0]);
// 0 — 원판 0: [0,0], 원판 1: [1,1], 원판 2: [2,2]
//     인접 원판 간 거리가 1이고 반지름 합은 0이어서 교차 불가
```
