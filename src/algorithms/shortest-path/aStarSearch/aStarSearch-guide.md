# A* 탐색 — 키에 목표까지의 추정을 더하면 목표 반대쪽 정점을 꺼내지 않고도 같은 답이 나오는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 경로를 전부
나열하는 방법에서 출발해, 우선순위 큐의 키에 목표까지 남은 비용의 추정을 더하는 방법까지 갑니다. 그 방법을
준비되는 차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

간선마다 0 이상의 수가 붙은 방향 그래프를 생각해 봅시다. 간선에 붙은 수를 **가중치**라고 부르고, 경로
하나의 **비용**은 그 경로가 지나는 간선의 가중치를 모두 더한 값입니다. 이 글의 절차는 시작 정점 `src` 하나와
목표 정점 `goal` 하나를 받아 **그 둘을 잇는 경로 중 비용이 가장 작은 것의 비용**을 구합니다. 여기에 하나가 더
주어져요. 정점마다 **목표까지 남은 비용을 짐작한 수**인 **추정** `h(v)` 입니다. 추정은 실제로 남은 최소
비용을 **넘지 않는다**는 약속을 지켜야 하고, 그 약속을 지키는 추정을 **허용 가능하다**고 부릅니다. 정점
여덟 · 간선 여덟인 그래프를 좌표 위에 놓고, 목표 정점 6 까지의 맨해튼 거리(가로 차이와 세로 차이의 합)를
추정으로 쓰면 이렇습니다.

<!--fig:concept-graph-->
![전개 입력 — 간선 옆 수는 가중치, 이름 옆 h 는 목표 6 까지의 추정, 정점 안 g 는 끝났을 때의 비용](./figs/concept-graph.svg)

정점 이름 옆의 `h` 가 추정이고, 정점 안의 `g` 는 절차가 끝났을 때 그 정점까지 찾아 둔 가장 작은 비용이에요.
정점 0 은 좌표 (0, 0), 목표 6 은 (8, 0) 이라 추정이 8 입니다. 굵은 실선은 그 비용을 낸 간선이고, 목표의
`g` 16 이 답이에요. 정점 7 은 목표 반대쪽 (0, 5) 에 있어 추정이 13 이고, 대시 테로 그린 것은 이 글의 절차가
그 정점을 한 번도 **확장**하지 않았다는 뜻입니다. 확장은 우선순위 큐에서 꺼낸 정점의 나가는 간선을 전부
완화하는 일을 말해요.

바꾸는 것은 [`dijkstra`](../dijkstra/dijkstra-guide.md) 편의 절차에서 한 자리뿐입니다. 다익스트라는
우선순위 큐의 **키**(꺼낼 차례를 정하는 수)를 지금까지 찾은 비용 `g` 로 두고, 이 글은 **`g` 에 추정 `h` 를
더한 값**으로 둬요. 그림 아래 두 줄이 두 키로 확장한 차례입니다. 키가 `g` 뿐이면 정점 7 을 다섯째로
확장하고, `g + h` 이면 정점 7 이 끝까지 안 나옵니다. 답은 둘 다 16 이에요. 모양이 다른 배치 다섯에서 두 키를
나란히 실행하면 이렇습니다.

<!--proof:concept-cases-->

| 배치 | 정점 | 간선 | 답 | 추정을 쓴 판의 확장 | 추정이 0 인 판의 확장 | 두 답 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 8 | 8 | 16 | 6 | 7 | 같다 |
| 사슬 64 | 64 | 63 | 63 | 63 | 63 | 같다 |
| 별 64 | 64 | 124 | 2 | 3 | 63 | 같다 |
| 격자 8×8 | 64 | 224 | 14 | 27 | 63 | 같다 |
| 격자 16×16 | 256 | 960 | 30 | 59 | 255 | 같다 |

배치 5 개 가운데 두 판의 답이 같은 배치가 5 개입니다. 확장한 정점 수의 차이가 가장 큰 배치는 격자 16×16 이고 59 대 255 입니다. 사슬 64 는 지나갈 길이 하나뿐이라 두 판 모두 63 개를 확장합니다.

<!--/proof-->

추정이 0 인 판은 키가 `g` 뿐이라 다익스트라와 같은 차례로 꺼냅니다. 답은 어느 배치에서도 갈리지 않고,
갈리는 것은 확장한 정점 수예요. 격자에서 무엇이 갈리는지는 칸 위에 그리면 바로 보입니다. 왼쪽 위에서 출발해
오른쪽 아래 목표로 가는 8×8 격자에서, 확장한 정점마다 그 차례를 적었어요.

<!--fig:concept-grid-->
![격자 8×8 — 칸의 수는 확장한 차례, 빈 칸은 한 번도 확장하지 않은 정점](./figs/concept-grid.svg)

키가 `g + h` 인 판은 맨 위 두 줄과 오른쪽 두 열만 확장하고, 키가 `g` 인 판은 목표를 뺀 칸을 전부 확장합니다.
격자의 한 변을 두 배씩 늘리면 이 차이가 이렇게 벌어져요.

<!--proof:concept-growth-->

| 격자 | 정점 | 추정을 쓴 판의 확장 | 추정이 0 인 판의 확장 |
| --- | ---: | ---: | ---: |
| 8×8 | 64 | 27 | 63 |
| 16×16 | 256 | 59 | 255 |
| 32×32 | 1,024 | 123 | 1,023 |
| 64×64 | 4,096 | 251 | 4,095 |

한 변을 두 배로 늘릴 때마다 몇 배가 되었는지 나누면 이렇습니다.

| 한 변 | 정점 | 추정을 쓴 판의 확장 | 추정이 0 인 판의 확장 |
| --- | ---: | ---: | ---: |
| 8 → 16 | 4.00 | 2.19 | 4.05 |
| 16 → 32 | 4.00 | 2.08 | 4.01 |
| 32 → 64 | 4.00 | 2.04 | 4.00 |

정점이 4 배가 될 때 추정이 0 인 판의 확장은 4.05 · 4.01 · 4.00 배이고, 추정을 쓴 판은 2.19 · 2.08 · 2.04 배입니다.

<!--/proof-->

정점이 네 배가 되면 추정이 0 인 판의 확장도 네 배가 되고, 추정을 쓴 판은 두 배 언저리에 머뭅니다. 추정이
실제 최소 비용을 넘지 않는 한 답은 한 번도 안 바뀌어요. 할 일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선 하나를 꼬리 정점의 목록에 한 번 넣는다 | 간선마다 한 번 |
| 우선순위 큐에서 꺼내기 | 키가 가장 작은 항목을 꺼내 목표면 그 비용을 돌려준다 | 넣은 항목마다 많아야 한 번, 한 번에 `log` 번의 비교 |
| 완화 | 확장한 정점에서 나가는 간선마다 `g` 를 고칠지 본다 | 간선마다 한 번(추정이 일관적일 때) |
| 우선순위 큐에 넣기 | 완화가 값을 고쳤을 때만 추정을 불러 키를 만들어 넣는다 | 간선마다 많아야 한 번, 한 번에 `log` 번의 비교 |
| 모두 | | `O((V + E) log E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **다익스트라 절차.** 가중치가 0 이상인 그래프에서 우선순위 큐가 비용이 가장 작은 항목을 내주게 두고, 꺼낸
  정점의 간선을 완화하는 절차입니다. 이 글은 그 큐의 키 하나만 바꾸므로 확정 · 뒤처진 기록 같은 말을 그 편에서
  가져와요. 모르면 [`dijkstra`](../dijkstra/dijkstra-guide.md) 를 먼저 보세요.
- **완화.** 간선 `u → v` 하나를 보고 `g[u] + w` 가 `g[v]` 보다 작으면 `g[v]` 를 그 값으로 고치는 일입니다.
  [`dijkstra`](../dijkstra/dijkstra-guide.md) 편이 「먼저 알아 둘 개념」으로 따로 다뤄요.
- **우선순위 큐와 이진 힙.** 키가 가장 작은 항목을 먼저 내주는 목록이고, 이진 힙은 그것을 배열 하나로 만드는
  흔한 방법입니다. 넣기와 꺼내기가 각각 항목 수의 `log` 번 비교로 끝나요. 자료구조 자체가 궁금하면
  [`minHeap` 가이드](../../../data-structures/heap/minHeap/minHeap-guide.mdx)를 보세요.
- **맨해튼 거리.** 두 점 `(x1, y1)` 과 `(x2, y2)` 사이의 `|x1 − x2| + |y1 − y2|` 입니다. 이 글은 이 값을
  전개 입력의 추정으로 씁니다.
- **상한과 하한.** 「이 값을 넘지 않는다」와 「이 값보다 작지 않다」를 갈라 말할 수 있어야 합니다. 추정은
  실제로 남은 비용의 하한이어야 하고, 그 조건을 이 글은 「넘지 않는다」로 적어요.

이름이 비슷한 과제 넷을 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 가중치 | 이 글에서 |
| --- | --- | --- |
| 시작 정점 하나에서 목표 정점 하나까지, 추정을 함께 받는다 | 0 이상 | 다룬다 |
| 시작 정점 하나에서 모든 정점까지 | 0 이상 | 다루지 않는다 — [`dijkstra`](../dijkstra/dijkstra-guide.md) |
| 시작 정점 하나에서의 최단 거리 | 음수가 있다 | 다루지 않는다 — [`bellmanFord`](../bellmanFord/bellmanFord-guide.md) |
| 시작 정점 하나에서 간선을 가장 적게 지나는 거리 | 없음 | 다루지 않는다 — [`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) |

### 아이디어를 떠올리는 과정 — 경로 전부 나열하기에서 목표까지의 추정을 키에 더하기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수, 간선 목록, 시작 정점,
목표 정점, 그리고 추정 함수를 받아 두 정점을 잇는 최소 비용을 돌려줍니다.

```ts
type Edge = [number, number, number];

function aStarSearch(
  n: number,
  edges: Edge[],
  src: number,
  goal: number,
  h: (v: number) => number,
): number;
```

- 입력: 정점 수 `n`, 원소가 `[u, v, w]` 인 방향 간선 목록 `edges`, 시작 정점 `src`, 목표 정점 `goal`, 정점을
  받아 추정을 돌려주는 함수 `h`. 정점 번호는 `0` 부터 `n − 1` 이고, 가중치 `w` 는 0 이상의 정수입니다.
- 출력: `src` 에서 `goal` 까지의 최소 비용. 갈 수 없으면 `Infinity`, `src` 와 `goal` 이 같으면 `0` 입니다.
- 추정의 약속: 모든 정점 `v` 에서 `0 ≤ h(v) ≤ d(v, goal)` — 아래 기호표의 `d` 입니다.
- 규모: `1 ≤ V ≤ 100,000`, `0 ≤ E ≤ 200,000`, `0 ≤ w ≤ 10^9`. 이 규모는 이 글이 정한 값이에요.
  [`dijkstra`](../dijkstra/dijkstra-guide.md) 편과 같은 규모로 두어 두 편의 수를 그대로 나란히 놓을 수 있게
  했습니다. 비용은 흔한 채점 환경의 예산인 1 초(단순 연산 1 억 번 기준) · 256 MB 에 대어 잽니다.

이 글이 쓰는 기호는 열 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점의 개수. 코드의 `n` 입니다 | `1 ≤ V ≤ 100,000` |
| `E` | 간선의 개수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 200,000` |
| `src` | 시작 정점의 번호 | `0 ≤ src ≤ V−1` |
| `goal` | 목표 정점의 번호 | `0 ≤ goal ≤ V−1` |
| `u` · `v` | 정점 번호. 간선 `u → v` 를 읽는 자리에서 `u` 가 꼬리, `v` 가 머리입니다 | `0` 부터 `V−1` |
| `w` | 간선 `u → v` 의 가중치 | `0 ≤ w ≤ 10^9` |
| `g[v]` | 코드가 지금 들고 있는 값. `src` 에서 `v` 로 가는 **실재하는 경로 하나**의 비용입니다 | 길이 `V` 인 배열 |
| `h(v)` | `v` 에서 `goal` 까지 남은 비용의 추정. 코드의 함수 `h` 입니다 | 정점마다 고정인 수 하나 |
| `f` | 우선순위 큐 항목의 키. 넣을 때의 `g[v]` 에 `h(v)` 를 더한 값입니다 | 수 하나 |
| `d(u, v)` | `u` 에서 `v` 까지의 **실제 최소 비용**. 경로가 없으면 `Infinity` | 답이 곧 `d(src, goal)` |

우선순위 큐의 항목 하나는 `(정점, 넣을 때의 비용, 키)` 세 수로 적습니다. 코드의 `open.push(v, ng, ng + h(v))`
와 같은 차례예요. `g[v]` 는 지금까지 찾은 값이고 `d(src, v)` 는 그 값이 끝내 같아져야 할 목표입니다.

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 최소 비용은 경로의 비용 중 가장 작은 것이니,
**시작에서 목표로 가는 단순 경로를 전부 만들어** 그중 가장 작은 비용을 고릅니다. 이 방법은 어떤 입력에서도
답이 맞아요.

```ts
// 가장 단순한 방법 — 경로를 하나도 안 거르고 전부 만들어 본다.
function walk(u: number, spent: number): void {
  if (u === goal) best = Math.min(best, spent);
  seen[u] = true;
  for (const [v, w] of adj[u]) if (!seen[v]) walk(v, spent + w);
  seen[u] = false;
}
```

만들어야 하는 경로가 몇 개인지 세면 규모를 못 견디는 까닭이 값으로 나옵니다. 모든 정점 쌍이 간선으로 이어진
완전 그래프에서 두 정점을 잇는 단순 경로를 셌어요.

<!--proof:origin-brute-->

| 정점 | 단순 경로의 수 | 1 초에 1 억 개를 만들 때 |
| ---: | ---: | --- |
| 5 | 16 | 1 초 안 |
| 8 | 1,957 | 1 초 안 |
| 10 | 109,601 | 1 초 안 |
| 12 | 9,864,101 | 1 초 안 |
| 15 | 16,926,797,486 | 169 초 |

정점 3 · 4 · 5 · 6 · 7 개인 완전 그래프 5 개에서 경로를 하나씩 세어 식과 맞댔고, 모두 일치했습니다. 전개 입력은 간선이 8 개뿐이라 시작에서 목표까지의 경로가 2 개입니다.

<!--/proof-->

정점 열다섯에서 이미 169 초입니다. 규모의 상한인 정점 10 만에서는 경로를 세는 일부터 끝나지 않아요. 경로가
많아지는 까닭은 앞부분이 같은 경로들이 그 앞부분의 비용을 경로마다 처음부터 다시 더하기 때문입니다. 그래서
다음 후보는 **경로가 아니라 정점마다 비용 하나를 들고 고쳐 가는** 방법이고, 그 방법의 완성형이 우선순위 큐에서
비용이 가장 작은 항목부터 꺼내는 다익스트라예요. 목표를 꺼내는 순간 멈추게만 바꾸면 이 과제에 그대로 씁니다.
전개 입력에 실행해 확장한 차례를 적고, 키에 추정을 더한 판을 옆에 놓았습니다.

<!--proof:origin-dijkstra-->

| 키 | 확장한 차례 | 확장한 정점 수 | 정점 7 | 답 |
| --- | --- | ---: | --- | ---: |
| 비용 g | 0 → 1 → 2 → 4 → 7 → 3 → 5 | 7 | 확장한다 | 16 |
| 비용 g + 추정 h | 0 → 2 → 1 → 4 → 3 → 5 | 6 | 안 한다 | 16 |

두 판의 답은 16 으로 같습니다. 정점 7 의 키는 비용 5 에 추정 13 을 더한 18 입니다.

<!--/proof-->

다익스트라는 정점 7 의 비용이 5 라서 정점 3 · 5 보다 먼저 확장합니다. 정점 7 은 목표 반대쪽에 있고 나가는 간선이
하나도 없어서, 확장해도 얻는 것이 없는 정점이에요. **꺼내는 차례에 목표가 어디 있는지가 들어 있지 않은 것**이
이 헛일의 원인입니다. 규모의 상한에서 얼마나 되는지 재려면 잣대가 하나 있어야 해요. 이 글은 **기본 연산**을
힙 안에서 키를 비교한 횟수 · 간선을 완화해 본 횟수 · 추정 함수를 부른 횟수의 합으로 셉니다. 간선이 규모 안에
드는 가장 큰 정사각 격자에서 두 키를 쟀습니다.

<!--proof:origin-scale-->

| 키 | 확장한 정점 | 큐에 넣은 항목 | 기본 연산 | 답 |
| --- | ---: | ---: | ---: | ---: |
| 비용 g | 50,175 | 50,176 | 877,675 | 446 |
| 비용 g + 추정 h | 891 | 1,335 | 7,574 | 446 |

격자 224×224 는 정점 50,176 개 · 방향 간선 199,808 개로, 간선이 규모의 상한 200,000 안에 드는 가장 큰 정사각 격자입니다. 키가 비용뿐인 판은 정점 50,176 개 가운데 50,175 개를 확장했고, 기본 연산이 추정을 더한 판의 115.9 배입니다.

<!--/proof-->

다익스트라의 기본 연산 877,675 번은 예산 1 초 안에 넉넉히 듭니다. 그래도 목표를 찾으려고 정점을 거의 전부
확장했고, 추정을 더한 판은 같은 답을 확장 891 번으로 냈어요. 관찰한 것은 하나입니다. **꺼내는 차례에 목표까지
남은 몫이 들어가면 목표 반대쪽 정점이 큐 뒤쪽으로 옮겨집니다.** 그러면 남은 몫을 어떻게 넣을까요. 가장 단순한 후보는
키를 추정 하나로 두는 것이에요. 세 키를 같은 두 배치에서 시험했습니다.

<!--proof:origin-keys-->

| 배치 | 키 | 답 | 확장한 정점 수 | 최소 여부 |
| --- | --- | ---: | ---: | --- |
| 전개 입력 | 비용 g | 16 | 7 | 최소다 |
| 전개 입력 | 추정 h | 19 | 4 | 최소가 아니다 |
| 전개 입력 | 비용 g + 추정 h | 16 | 6 | 최소다 |
| 격자 16×16 | 비용 g | 30 | 255 | 최소다 |
| 격자 16×16 | 추정 h | 30 | 30 | 최소다 |
| 격자 16×16 | 비용 g + 추정 h | 30 | 59 | 최소다 |

여섯 줄 가운데 답이 최소가 아닌 줄은 1 개이고, 모두 키가 추정 h 하나인 줄입니다.

<!--/proof-->

키가 추정 하나이면 확장은 가장 적지만 전개 입력에서 16 이 아니라 19 를 냅니다. 목표에 가까워 보이는 정점 2 쪽
길을 먼저 끝까지 따라가 버려서, 지나온 비용이 더 큰 길로 목표에 먼저 이르기 때문이에요. 지나온 비용 `g` 를 버리면
최소를 지킬 수 없고, 추정 `h` 를 버리면 목표 쪽을 먼저 꺼내지 못합니다. 지금까지 해 본 방법을 차례로 놓으면
이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **목표까지의 추정을 키에 더하기**입니다. 우선순위 큐의 키를 `g + h` 로 두고, 목표를
처음 꺼내는 순간 그 항목의 비용을 답으로 돌려줘요. 추정이 어떤 조건을 지켜야 답이 맞는지, 키를 어디서
만드는지, 값이 줄어든 정점의 옛 항목은 어떻게 하는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 목표까지의 추정을 키에 더하기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **우선순위 큐에서 키 `g + h` 가 가장 작은 항목을 꺼내, 목표이면 그
비용을 돌려주고 아니면 그 정점의 간선을 완화해 값이 줄어든 이웃을 키 `g + h` 로 넣는 일을 되풀이합니다.** 이
문장이 기대는 것이 「허용 가능한 추정」인데, 추정이라는 말을 처음 보는 사람에게는 어떤 수가 허용되고 어떤 수가
안 되는지가 낯설어요. 그래서 그 개념을 먼저 따로 설명하고, 그다음 실현하는 순서대로 세 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 시작값 적기 | 이웃 목록을 만들고 `g` 를 채우고 `(src, 0, h(src))` 를 큐에 넣는다 | — |
| 큐가 빌 때까지 | 2단계 키가 가장 작은 항목 꺼내기 | 꺼낸 정점이 목표면 그 비용을 돌려준다 | 1단계의 `g` 와 우선순위 큐 |
| 목표가 아닐 때마다 | 3단계 뒤처진 기록을 거르고 이웃 완화하기 | 옛 항목은 버리고, 간선마다 `g[v]` 를 고치고 고친 이웃을 키 `g + h` 로 넣는다 | 1단계의 이웃 목록 · 2단계가 꺼낸 항목 |

#### 먼저 알아 둘 개념 — 허용 가능한 추정

추정 `h(v)` 는 **정점 `v` 에서 목표까지 가려면 적어도 이만큼은 든다고 짐작한 수**입니다. 그 짐작이 실제로 남은
최소 비용보다 크지 않으면 **허용 가능한 추정**이라고 불러요. 식으로 적으면 모든 정점에서 이렇습니다.

$$
h(v) \le d(v, \text{goal})
$$

##### 입력 위의 추정

전개 입력의 정점마다 추정 `h` 와, 그 정점에서 목표까지의 실제 최소 비용 `d` 를 함께 적었습니다. 이름 옆 수가
추정이고 정점 안 수가 실제 최소 비용이에요.

<!--fig:build-admissible-->
![정점마다의 추정 h 와 목표까지의 실제 최소 비용 d — 모든 정점에서 h ≤ d](./figs/build-admissible.svg)

정점마다 두 수를 나란히 놓으면 이렇습니다.

<!--proof:build-admissible-->

| 정점 | 좌표 | 추정 h(v) | 실제 최소 비용 d(v, goal) | 실제 값과의 비교 |
| --- | --- | ---: | ---: | --- |
| 0 | (0, 0) | 8 | 16 | 넘지 않는다 |
| 1 | (2, 1) | 7 | 13 | 넘지 않는다 |
| 2 | (3, 0) | 5 | 15 | 넘지 않는다 |
| 3 | (5, 0) | 3 | 8 | 넘지 않는다 |
| 4 | (4, 1) | 5 | 11 | 넘지 않는다 |
| 5 | (6, 0) | 2 | 6 | 넘지 않는다 |
| 6 | (8, 0) | 0 | 0 | 넘지 않는다 |
| 7 | (0, 5) | 13 | Infinity | 넘지 않는다 |

정점 8 개 가운데 추정이 실제 최소 비용을 넘는 정점은 0 개입니다.

<!--/proof-->

목표 6 은 두 수가 다 0 입니다. 정점 7 은 목표로 가는 경로가 없어 실제 최소 비용이 `Infinity` 라서, 어떤 유한한
추정도 그 값을 넘지 못해요. 이 입력의 맨해튼 거리가 왜 넘지 않는지는 아래 「이웃한 두 정점의 추정」의 표가
간선마다 보이고, 그 성질에서 허용 가능이 나온다는 것은 「수식 정의와 유도」가 식으로 보입니다.

##### 추정 하나를 읽는 법

정점 4 하나를 골라 추정이 어디서 나오고 실제 값과 어떻게 대어지는지 항마다 읽어 보겠습니다.

<!--proof:build-read-one-->

| 항 | 보는 것 | 값 |
| --- | --- | --- |
| 정점의 좌표 | xy[4] | (4, 1) |
| 목표의 좌표 | xy[6] | (8, 0) |
| 추정 | \|8 − 4\| + \|0 − 1\| | 5 |
| 비용이 가장 작은 경로 | 4→3→5→6 | 3 + 2 + 6 = 11 |
| 둘의 관계 | 5 ≤ 11 | 넘지 않는다 |

추정은 좌표 둘만 보고 뺄셈 두 번으로 나오고, 실제 최소 비용은 그래프를 다 풀어야 나옵니다. 이 차이가 추정을
쓰는 까닭이에요. 추정은 적은 연산으로 구하는 대신 실제 값보다 작을 수 있고, 절차는 그 작음을 받아들이도록 만들어집니다.

##### 이웃한 두 정점의 추정

간선 하나로 이어진 두 정점의 추정은 서로 어떻게 놓일까요. 간선 `u → v` 를 하나 지날 때 추정이 줄어든 폭
`h(u) − h(v)` 를 그 간선의 가중치와 나란히 놓았습니다.

<!--proof:build-edge-->

| 간선 | 가중치 w | h(u) | h(v) | 줄어든 추정 h(u) − h(v) | w 와의 비교 |
| --- | ---: | ---: | ---: | ---: | --- |
| 0→1 | 3 | 8 | 7 | 1 | 넘지 않는다 |
| 0→2 | 4 | 8 | 5 | 3 | 넘지 않는다 |
| 0→7 | 5 | 8 | 13 | -5 | 넘지 않는다 |
| 1→4 | 2 | 7 | 5 | 2 | 넘지 않는다 |
| 2→3 | 7 | 5 | 3 | 2 | 넘지 않는다 |
| 4→3 | 3 | 5 | 3 | 2 | 넘지 않는다 |
| 3→5 | 2 | 3 | 2 | 1 | 넘지 않는다 |
| 5→6 | 6 | 2 | 0 | 2 | 넘지 않는다 |

간선 8 개 가운데 줄어든 추정이 가중치를 넘는 간선은 0 개입니다. 줄어든 추정이 음수인 간선(목표에서 멀어지는 간선)은 1 개입니다.

<!--/proof-->

간선을 하나 지나며 실제로 쓴 비용 `w` 가 추정이 줄어든 폭 이상이면, 그 간선을 지날 때 키 `g + h` 가 줄지
않습니다 — `g` 가 `w` 만큼 늘고 `h` 가 그보다 덜 주니까요. 이 성질을 **일관된 추정**이라고 부르고,
「수식 정의와 유도」에서 일관이면 허용 가능하다는 것을 식으로 보입니다. 이웃한 정점끼리의 관계가 일관이고,
정점 하나와 목표 사이의 관계가 허용 가능이에요.

##### 한 정점에서만 넘는 추정과의 차이

「추정은 실제 값에 가까울수록 좋으니, 조금 넘더라도 대부분의 정점에서 맞으면 되지 않나」라고 읽기 쉽습니다.
정점 1 하나의 추정만 실제 최소 비용 13 을 넘는 20 으로 바꾸고 나머지는 맨해튼 거리 그대로 둔 판을 실행했어요.

<!--fig:build-over-->
![정점 1 의 추정만 20 으로 부풀린 판 — 굵은 간선이 비용을 낸 간선, 목표의 g 가 답](./figs/build-over.svg)

두 판이 꺼낸 차례와 답을 나란히 놓으면 이렇습니다.

<!--proof:build-over-->

| 추정 | h(1) | 꺼낸 차례 | 답의 경로 | 답 |
| --- | ---: | --- | --- | ---: |
| 맨해튼 거리 | 7 | 0 → 2 → 1 → 4 → 3 → 5 → 3 → 6 | 0→1→4→3→5→6 | 16 |
| 정점 1 만 20 | 20 | 0 → 2 → 3 → 5 → 7 → 6 | 0→2→3→5→6 | 19 |

두 추정은 정점 1 하나에서만 다르고, 정점 1 의 실제 최소 비용은 13 입니다. 정점 1 의 추정을 20 으로 두면 답이 16 에서 19 로 바뀝니다.

<!--/proof-->

정점 여덟 가운데 일곱은 추정이 그대로인데 답이 틀렸습니다. 넘는 정점이 최소 비용 경로 위에 하나만 있어도,
그 정점의 키가 커져 큐 뒤쪽에 놓이고, 그 길을 끝까지 못 따라가요. **「가깝다」는 조건이 아니고 「넘지 않는다」가 조건입니다.**
0 은 실제 비용이 얼마든 넘지 않으니 언제나 허용 가능하고, 그때 절차는 다익스트라와 같아집니다.

> 추정은 모자라도 되고, 넘으면 안 된다.

##### 넘지 않아야 하는 까닭

이 절차는 목표를 **처음 꺼낼 때** 그 비용을 답으로 돌려줍니다. 그것이 맞으려면 최소 비용 경로 위의 정점들이
목표보다 먼저 나와야 해요. 최소 비용 경로 위 정점마다, 시작에서 그 정점까지의 최소 비용에 추정을 더한 키를
두 추정으로 계산했습니다.

<!--proof:build-why-->

| 최소 비용 경로의 정점 | 시작에서의 최소 비용 | 맨해튼 추정 | 맨해튼 키 | 정점 1 만 넘는 추정 | 그때의 키 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 8 | 8 | 8 | 8 |
| 1 | 3 | 7 | 10 | 20 | 23 |
| 4 | 5 | 5 | 10 | 5 | 10 |
| 3 | 8 | 3 | 11 | 3 | 11 |
| 5 | 10 | 2 | 12 | 2 | 12 |
| 6 | 16 | 0 | 16 | 0 | 16 |

맨해튼 거리에서는 최소 비용 경로 위 정점의 키가 모두 답 16 이하입니다. 정점 1 만 넘는 추정에서는 정점 1 의 키가 23 이라서, 키 19 로 목표를 먼저 꺼냅니다.

<!--/proof-->

최소 비용 경로 위 정점 `x` 의 키는 `d(src, x) + h(x)` 이고, `h(x) ≤ d(x, goal)` 이면 그 합이
`d(src, x) + d(x, goal) = d(src, goal)`, 곧 답을 넘지 않습니다. 비용이 답보다 큰 길로 목표에 이른 항목은 키가 그
비용이라 답보다 크니, 그 항목보다 최소 비용 경로 위의 정점이 먼저 나와요. 추정이 넘는 정점에서는 이 합이 답을
넘을 수 있고, 표의 정점 1 이 키 23 으로 그 자리입니다. 이 한 줄의 부등식이 「목표를 처음 꺼낸 값이 답이다」의
근거이고, 파트 2 의 「불변식」이 걸음마다 그것을 확인해요.

#### 1단계 — 시작값 적기

간선 목록을 꼬리 정점별 이웃 목록으로 바꾸고, `g` 를 전부 `Infinity` 로 채운 뒤 시작 정점만 0 을 적습니다.
그리고 우선순위 큐에 항목 `(src, 0, h(src))` 하나를 넣어요. 키가 0 이 아니라 `h(src)` 인 것이 다익스트라와
처음 달라지는 자리입니다.

<!--proof:stage-start-->

| 정점 | adj — (이웃, 가중치) | g | h |
| --- | --- | --- | ---: |
| 0 | (1, 3) (2, 4) (7, 5) | 0 | 8 |
| 1 | (4, 2) | Infinity | 7 |
| 2 | (3, 7) | Infinity | 5 |
| 3 | (5, 2) | Infinity | 3 |
| 4 | (3, 3) | Infinity | 5 |
| 5 | (6, 6) | Infinity | 2 |
| 6 | 없음 | Infinity | 0 |
| 7 | 없음 | Infinity | 13 |

이웃 목록의 칸은 모두 8 개로 간선 수와 같고, 우선순위 큐에는 항목 (0, 0, 8) 하나가 들어 있습니다.

<!--/proof-->

추정 `h` 는 표에 적었지만 코드는 배열로 들고 있지 않습니다. 필요할 때 함수 `h` 를 부르고, 그 자리는 항목을
큐에 넣을 때 하나뿐이에요.

#### 2단계 — 키가 가장 작은 항목 꺼내기

우선순위 큐에서 키가 가장 작은 항목 `(u, g, f)` 를 꺼냅니다. `u` 가 목표면 그 항목의 비용 `g` 를 돌려주고
끝내요. 목표가 아니면 3단계로 갑니다. 시작 정점을 확장한 직후의 큐를 보면 꺼낼 차례를 키가 정한다는 것이
드러납니다. 무대 아래 두 줄이 우선순위 큐이고, 꺼낼 차례대로 늘어놓은 것이에요.

<!--fig:build-queue-->
![T2 가 끝난 뒤 — 큐 맨 앞은 비용이 가장 작은 정점이 아니라 키가 가장 작은 정점 2](./figs/build-queue.svg)

큐에 든 세 항목의 비용과 추정과 키를 나란히 놓았습니다.

<!--proof:stage-key-->

| 정점 | 간선 가중치 | 비용 g | 추정 h | 키 g + h | 꺼낼 차례 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 3 | 3 | 7 | 10 | 2 |
| 2 | 4 | 4 | 5 | 9 | 1 |
| 7 | 5 | 5 | 13 | 18 | 3 |

비용이 가장 작은 것은 정점 1 이고 키가 가장 작은 것은 정점 2 입니다. 큐 맨 앞은 정점 2 입니다.

<!--/proof-->

정점 7 과 정점 2 는 비용이 1 차이인데, 추정이 13 과 5 라서 키는 18 과 9 로 벌어집니다. 목표에서 먼 정점의
항목일수록 큐 뒤로 가요. 목표 항목을 꺼내는 순간 멈춰도 되는 근거는 「넘지 않아야 하는 까닭」의 부등식입니다.
목표 항목보다 키가 작은 항목이 큐에 남아 있는 동안은 목표를 꺼낼 차례가 오지 않고, 최소 비용 경로 위의
정점은 키가 답 이하라서 그 전에 다 나와요.

| 꺼낸 항목 | 뜻 | 하는 일 |
| --- | --- | --- |
| 정점이 목표다 | 남은 어떤 항목보다 키가 작다 — 비용이 더 작은 길이 남아 있지 않다 | 그 비용을 돌려주고 끝낸다 |
| 목표가 아니다 | 그 정점에서 더 나아가 볼 차례다 | 3단계로 |

#### 3단계 — 뒤처진 기록을 거르고 이웃 완화하기

꺼낸 항목의 비용이 지금의 `g[u]` 보다 크면 그 항목은 `g[u]` 가 더 작아지기 전에 넣어 둔 **뒤처진 기록**이라
버립니다. 아니면 `u` 를 확장해요. 이웃 목록을 읽으며 간선마다 완화하고, 값이 줄어든 이웃 `v` 만 새 항목
`(v, g[v], g[v] + h(v))` 로 넣습니다. 불안한 경우는 **이미 큐에 항목이 있는 이웃의 값을 더 작게 고칠 때**예요.
이 글은 옛 항목을 지우지 않고 그대로 두고, 꺼내는 자리에서 뒤처진 기록으로 걸러 냅니다. 전개 입력의 셋째부터
다섯째 걸음이 그 자리입니다.

<!--proof:stage-relax-->

| 걸음 | 꺼낸 항목 | 완화 | 걸음이 끝난 뒤 큐 — 꺼낼 차례 | 그중 뒤처진 기록 |
| --- | --- | --- | --- | --- |
| T3 | (2, 4, 9) | 2→3 g[3] = Infinity → 11 | (1, 3, 10) (3, 11, 14) (7, 5, 18) | 없음 |
| T4 | (1, 3, 10) | 1→4 g[4] = Infinity → 5 | (4, 5, 10) (3, 11, 14) (7, 5, 18) | 없음 |
| T5 | (4, 5, 10) | 4→3 g[3] = 11 → 8 | (3, 8, 11) (3, 11, 14) (7, 5, 18) | (3, 11, 14) |

T5 가 끝나면 정점 3 짜리 항목이 2 개 들어 있고, 그중 뒤처진 기록은 (3, 11, 14) 입니다.

<!--/proof-->

T3 이 정점 3 에 11 을 적고 키 14 로 넣었는데, T5 가 비용이 더 작은 길 `4 → 3` 으로 8 을 찾아 키 11 짜리 항목을 하나 더
넣었습니다. 키 14 짜리는 이제 쓸모가 없지만 이진 힙에는 가운데 항목을 지우는 연산이 없어 그대로 남아요. 그
항목은 뒤에 꺼내질 때 비용 11 이 `g[3] = 8` 보다 커서 버려집니다. 반복이 끝나는 까닭도 종료 조건으로 말할 수
있어요. 항목은 넣을 때만 늘고 꺼낼 때만 주는데, 넣는 일은 완화가 값을 고칠 때뿐이고 값은 줄어들기만 하므로
넣는 횟수에 끝이 있습니다. 그래서 목표를 꺼내거나 큐가 비거나 둘 중 하나로 반드시 멈춰요.

| 꺼낸 항목의 비용과 `g[u]` | 뜻 | 하는 일 |
| --- | --- | --- |
| 비용 = `g[u]` | 이 항목이 그 정점의 가장 새 값이다 | 확장한다 |
| 비용 > `g[u]` | 더 작은 값으로 고치기 전에 넣은 항목이다 | 이웃을 안 보고 버린다 |

#### 이 방법이 기대는 전제

전제는 둘입니다. 하나는 「넘지 않아야 하는 까닭」의 부등식이 기대는 **추정이 허용 가능하다**는 것이고, 깨지면
어떻게 되는지는 「한 정점에서만 넘는 추정과의 차이」가 이미 값으로 보였어요 — 16 이 나와야 하는 자리에서 19 가
나옵니다. 다른 하나는 **가중치가 0 이상**이라는 것입니다. 간선을 더 지나면 비용이 줄지 않아야, 목표를 처음
꺼낸 뒤에 비용이 더 작은 길이 나타나지 않아요. 음수 간선이 하나 있는 입력에 추정을 전부 0 으로 두고 실행했습니다.

<!--proof:premise-negative-->

| 입력 | 추정 | 정본의 답 | 경로를 전부 만든 답 | 두 답 |
| --- | --- | ---: | ---: | --- |
| 0→2(1) 0→1(5) 1→2(-10) | 전부 0 | 1 | -5 | 어긋난다 |

정본은 목표 2 를 키 1 로 먼저 꺼내 멈추고, 비용이 -5 인 경로를 보지 못합니다.

<!--/proof-->

다익스트라는 목표를 꺼내도 멈추지 않고 큐를 끝까지 비우므로 같은 입력에서 답을 고칠 기회가 남는데, 이 절차는
목표를 꺼내는 순간 멈춰서 그 기회가 없어요. 음수 가중치가 있으면 [`bellmanFord`](../bellmanFord/bellmanFord-guide.md)
처럼 확정을 쓰지 않는 절차로 가야 합니다.

| 전제 | 쓰이는 곳 | 깨지면 |
| --- | --- | --- |
| 추정이 허용 가능하다 | 2단계에서 목표를 처음 꺼낼 때 멈춘다 | 최소 비용 경로 위 정점이 목표보다 뒤에 나와 더 큰 값을 돌려준다 |
| 가중치가 0 이상이다 | 목표를 꺼낸 뒤 비용이 더 작은 길이 없다 | 음수 간선 너머의 비용이 더 작은 길을 보기 전에 멈춘다 |
| 옛 항목은 비용이 `g` 보다 크다 | 3단계에서 뒤처진 기록을 알아보는 판정 | 걸러 낼 기준이 없어 같은 정점을 여러 번 확장한다 |

#### 추정을 모든 정점에 같은 규칙으로 주는 까닭

남은 선택은 **추정 함수를 무엇으로 두느냐**입니다. 0 은 늘 허용 가능하고, 정확한 값(실제 최소 비용)도 허용
가능해요. 둘 사이에서 정보를 얼마나 줄지를 손잡이로 삼아 시험했습니다. 32×32 격자에서 정점 중 일부에만 정확한
추정(목표까지의 맨해튼 거리)을 주고 나머지에는 0 을 주되, 그 비율을 0% 에서 100% 까지 올렸어요. 어느 정점이 그
비율에 드는지는 정점 번호를 섞는 고정 해시가 정합니다. 0 도 정확한 값도 넘지 않으니 어느 비율에서도 추정은
허용 가능합니다.

<!--proof:build-ratio-->

| 정확한 추정을 받은 정점 | 확장한 정점 | 그중 재확장 | 기본 연산 | 답 |
| --- | ---: | ---: | ---: | ---: |
| 0% | 1,023 | 0 | 12,212 | 62 |
| 10% | 901 | 0 | 13,416 | 62 |
| 20% | 1,525 | 580 | 28,376 | 62 |
| 30% | 2,555 | 1,591 | 55,560 | 62 |
| 40% | 756 | 198 | 16,367 | 62 |
| 50% | 494 | 85 | 10,661 | 62 |
| 60% | 703 | 146 | 14,107 | 62 |
| 70% | 459 | 46 | 8,238 | 62 |
| 80% | 275 | 8 | 4,268 | 62 |
| 90% | 148 | 0 | 1,794 | 62 |
| 100% | 123 | 0 | 1,040 | 62 |

격자 32×32 (정점 1,024 · 방향 간선 3,968) 에서 잰 값이고, 답의 종류는 1 가지입니다. 확장이 가장 적은 비율은 100% (123 개), 가장 많은 비율은 30% (2,555 개)입니다. 재확장이 0 이 아닌 비율은 20% · 30% · 40% · 50% · 60% · 70% · 80% 입니다.

<!--/proof-->

**정보를 더 준다고 늘 일이 주는 것이 아닙니다.** 30% 에서는 확장이 2,555 개로 추정이 0 인 판의 1,023 개보다
많아요. 재확장(이미 확장한 정점을 더 작은 비용으로 다시 확장하는 것)이 1,591 번 붙었기 때문입니다. 정확한 값과
0 이 섞이면 이웃한 두 정점의 추정이 가중치보다 크게 어긋나는 간선이 생기고, 그 간선에서 일관성이 깨져요. 그러면
한 번 확장한 정점에 비용이 더 작은 길이 뒤늦게 이릅니다. 0% 와 100% 는 모든 정점에 같은 규칙을 준 것이라 재확장이 0 이고,
그중 100% 가 가장 적습니다. 그래서 이 글은 **추정을 모든 정점에 같은 규칙(전개 입력에서는 맨해튼 거리)으로
줍니다.** 일관성이 깨졌을 때 무엇을 지켜야 답이 맞는지는 「수행으로 알아보는 알고리즘」의 셋째 짚고 가기가
보입니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 둘째부터 넷째가 반복 한 바퀴예요.

1. 간선 목록을 이웃 목록 `adj` 로 바꾸고, `g` 를 `Infinity` 로 채운 뒤 `g[src] = 0`, 큐에 `(src, 0, h(src))` 를 넣는다
2. 큐가 빌 때까지 키가 가장 작은 항목 `(u, gu, f)` 를 꺼낸다
3. `u` 가 목표면 `gu` 를 돌려주고, `gu` 가 `g[u]` 보다 크면 버리고 2 로 돌아간다
4. `u` 에서 나가는 간선 `(v, w)` 마다 `gu + w` 가 `g[v]` 보다 작으면 고쳐 적고 `(v, gu + w, gu + w + h(v))` 를 넣는다
5. 큐가 비면 `Infinity` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 정점 여덟을 아홉 걸음으로 처리한다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 그래프 하나를 정해 끝까지 가져가되, 코드
조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 8;
const edges: [number, number, number][] = [
  [0, 1, 3], [0, 2, 4], [0, 7, 5], [1, 4, 2], [2, 3, 7], [4, 3, 3], [3, 5, 2], [5, 6, 6],
];
const src = 0;
const goal = 6;
const xy: [number, number][] = [[0, 0], [2, 1], [3, 0], [5, 0], [4, 1], [6, 0], [8, 0], [0, 5]];
const h = (v: number): number =>
  Math.abs(xy[goal][0] - xy[v][0]) + Math.abs(xy[goal][1] - xy[v][1]);
// 이 절이 끝나면 나와야 하는 값: 16
```

왜 이 여덟 정점을 골랐을까요? 한 입력에서 **갈래가 거의 다 실행되기** 때문입니다. 값을 처음 적는 완화, 이미
적힌 값을 더 작게 고치는 완화(`4→3`), 뒤처진 기록을 버리는 갈래(정점 3 을 두 번째로 꺼낼 때), 목표를 꺼내
돌려주는 갈래가 다 나와요. 목표 반대쪽 정점 7 이 한 번도 확장되지 않고 큐에 남는 자리도 함께 나옵니다. 이
입력에 안 나오는 거짓 쪽 둘은 다섯째 조각 뒤에 작은 입력으로 따로 실행합니다.

```text
절차 전체를 한 장으로

  T1     g 를 Infinity 로 채우고 g[src] = 0 을 적는다                ① 시작값
         이웃 목록을 만들고 (src, 0, h(src)) 를 큐에 넣는다
         큐에 항목이 남아 있는 동안:                                ② 반복 조건
  T2~T9    키가 가장 작은 항목 (u, gu, f) 를 꺼낸다
           u 가 goal 이면 gu 를 돌려준다                            ③ 목표
           gu 가 g[u] 보다 크면 버린다                              ④ 뒤처진 기록
           u 의 간선마다 gu + w 로 완화하고, 고치면 키 g + h 로 넣는다  ⑤ 완화
         큐가 비면 Infinity 를 돌려준다
```

#### 1. 비용 배열과 이웃 목록을 시작값으로 둔다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 비용 배열을 `Infinity` 로 채우고, 간선 목록을 이웃 목록으로 바꾸고,
시작 정점만 0 을 적은 뒤 우선순위 큐에 항목 하나를 넣어요. 코드에서는 비용 배열이 `g`, 이웃 목록이 `adj`,
우선순위 큐가 `open` 입니다.

```ts
// ① 시작값 — 아직 아무 경로도 못 찾았으므로 전부 `Infinity` 이고 시작 정점만 `0` 이다.
const g: number[] = Array.from({ length: n }, () => Number.POSITIVE_INFINITY);
const adj: [number, number][][] = Array.from({ length: n }, () => []);
for (const [u, v, w] of edges) (adj[u] as [number, number][]).push([v, w]);

g[src] = 0;
const open = new MinHeap();
open.push(src, 0, h(src));
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walk-t1-->

```text
T1 이 끝난 시점
  g     [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity]
  adj   0:[(1, 3) (2, 4) (7, 5)]  1:[(4, 2)]  2:[(3, 7)]  3:[(5, 2)]  4:[(3, 3)]  5:[(6, 6)]  6:[]  7:[]
  open  (0, 0, 8)
```

`open.push` 의 인자가 셋이라는 것을 봐 주세요. 둘째가 넣을 때의 비용이고 셋째가 키입니다. 비용을 함께 싣지
않으면 꺼낸 항목이 뒤처진 기록인지 가를 때 키에서 추정을 빼야 하고, 그러려면 추정 함수를 한 번 더 불러야 해요.

#### 2. 항목 셋을 키로 줄 세우는 이진 힙을 만든다

둘째 조각은 우선순위 큐입니다. 배열 하나로 완전 이진 트리를 담고, 자리 `i` 의 부모를 `(i-1)/2` 의 몫으로
둡니다. 넣을 때는 맨 끝에 두고 **셋째 칸의 키**가 부모보다 작은 동안 부모와 맞바꿔 올려요. 다익스트라 편의
힙과 다른 것은 항목이 세 칸이고 키가 셋째 칸이라는 것 하나입니다.

```ts
push(node: number, cost: number, key: number): void {
  this.items.push([node, cost, key]);
  let i = this.items.length - 1;
  while (i > 0) {
    const parent = (i - 1) >> 1;
    if (this.key(i) >= this.key(parent)) break;   // 부모가 더 작거나 같으면 자리를 지킨다
    this.swap(i, parent);
    i = parent;
  }
}
```

꺼낼 때는 뿌리를 내주고, 마지막 항목을 뿌리로 옮긴 뒤 자식 중 키가 작은 쪽보다 크면 맞바꿔 내립니다. 전개
입력의 T2 가 넣는 세 항목으로 실행하면 배열이 이렇게 바뀌어요.

<!--proof:walk-heap-->

```text
T2 가 넣는 항목 셋을 빈 힙에 차례로 넣고 한 번 꺼낸다 — 배열에 놓인 순서 그대로
  넣기 전                []
  (1, 3, 10) 을 넣은 뒤  [(1, 3, 10)]
  (2, 4, 9) 를 넣은 뒤   [(2, 4, 9), (1, 3, 10)]
  (7, 5, 18) 을 넣은 뒤  [(2, 4, 9), (1, 3, 10), (7, 5, 18)]
  한 번 꺼낸 뒤          [(1, 3, 10), (7, 5, 18)]  꺼낸 항목 (2, 4, 9)
```

`(2, 4, 9)` 는 둘째로 넣었는데 키 9 가 10 보다 작아 뿌리로 올라갔고, 꺼내기가 그것을 먼저 내줬습니다. 비용
4 는 비용 3 보다 큰데도 먼저 나와요. 이 자료구조가 지키는 것은 「부모의 키가 자식의 키 이하다」 하나뿐이고, 그
하나만으로 뿌리의 키가 가장 작다는 것이 나옵니다. 그래서 이 글의 그림들은 우선순위 큐를 배열 순서가 아니라
**꺼낼 차례대로** 늘어놓습니다.

#### 3. 꺼낸 항목이 목표면 그 비용을 돌려준다

셋째 조각은 반복의 머리입니다. 큐에서 항목을 꺼내고, 그 정점이 목표면 항목의 비용을 돌려줘요.

```ts
// ② 큐에 남은 항목이 있는가 — 없으면 목표까지 이어지는 경로가 없다.
while (open.size() > 0) {
  const [u, gu] = open.pop() as [number, number, number];

  // ③ 목표를 꺼냈는가 — 처음 꺼내는 그 순간의 비용이 곧 답이다.
  if (u === goal) return gu;
```

첫 바퀴 `T2` 를 실행하면 이렇게 나옵니다. 넷째 조각(완화)까지 붙여서 한 바퀴를 끝까지 적었어요.

<!--proof:walk-t2-->

| T2 에서 본 것 | 값 |
| --- | --- |
| 꺼낸 항목 | (0, 0, 8) |
| 목표인가 | 0 === 6 이 거짓 |
| 뒤처진 기록인가 | 0 > g[0] = 0 이 거짓 |
| 0→1 완화 | Infinity > 0 + 3 이라 g[1] = 3 · 키 3 + 7 = 10 · 큐에 (1, 3, 10) |
| 0→2 완화 | Infinity > 0 + 4 라 g[2] = 4 · 키 4 + 5 = 9 · 큐에 (2, 4, 9) |
| 0→7 완화 | Infinity > 0 + 5 라 g[7] = 5 · 키 5 + 13 = 18 · 큐에 (7, 5, 18) |
| 큐 — 꺼낼 차례 | (2, 4, 9) (1, 3, 10) (7, 5, 18) |

`③` 은 꺼낸 **뒤에** 봅니다. 목표 항목을 큐에 넣는 순간이 아니라 꺼내는 순간이 답이 정해지는 때예요.

#### 짚고 가기 — 목표의 값을 처음 줄인 자리에서 돌려주면 답이 커진다

여기서 헷갈리기 쉬운 포인트는 `③` 의 자리입니다. 목표의 비용을 처음 고쳐 적는 순간 그 값이 목표까지의 경로
하나를 뜻하니, 「그때 바로 돌려주면 꺼낼 때까지 기다리는 걸음을 아낄 수 있다」로 읽기 쉬워요. 완화하는 자리에서
`v === goal` 이면 바로 돌려주는 판을 만들어 실행해 봅시다.

```ts
        g[v] = ng;
        if (v === goal) return ng;   // ← 줄이자마자 반환하는 판
```

<!--proof:pause-early-->

| 배치 | 정점 | 정본 | 줄이자마자 반환하는 판 | 두 답 |
| --- | ---: | ---: | ---: | --- |
| 돌아가는 경로가 더 작다 | 4 | 3 | 10 | 어긋난다 |
| 전개 입력 | 8 | 16 | 16 | 같다 |
| 사슬 여섯 | 6 | 5 | 5 | 같다 |
| 격자 8×8 | 64 | 14 | 14 | 같다 |
| 두 경로의 비용 차이가 1 | 4 | 11 | 11 | 같다 |

돌아가는 경로가 더 작은 배치에서 정본은 3, 줄이자마자 반환하는 판은 10 을 냅니다.

<!--/proof-->

**다섯 배치 중 넷은 답이 그대로입니다.** 목표를 처음 줄인 값이 마침 최소였을 뿐이고, 그래서 이 실수는 테스트를
그냥 지나가기 쉬워요. 돌아가는 경로가 더 작은 배치는 시작에서 목표로 바로 가는 간선이 가중치 10 이고, 세 간선을
돌아가면 1 + 1 + 1 로 3 입니다. 바로 가는 간선이 먼저 완화되므로 그 판은 10 을 돌려주고 멈춰요. 값을 줄인 자리는
「그때까지 찾은 것 중 가장 작다」일 뿐이고, 꺼낸 자리여야 「남은 어떤 항목보다 키가 작다」가 됩니다.

| 자리 | 그 순간 참인 것 | 답으로서 |
| --- | --- | --- |
| 목표의 값을 줄인 자리 | 그때까지 찾은 경로 중 하나의 비용이다 | 비용이 더 작은 길이 아직 큐에 있을 수 있다 |
| 목표를 꺼낸 자리 | 큐에 남은 어떤 항목보다 키가 작다 | 비용이 더 작은 길이 남아 있지 않다 |

#### 4. 뒤처진 기록을 거르고 이웃을 완화한다

넷째 조각이 본체입니다. 꺼낸 항목이 뒤처진 기록이면 버리고, 아니면 그 정점의 간선마다 `gu + w` 를 만들어 지금
적힌 값보다 작을 때만 고쳐 적고, 키 `ng + h(v)` 로 큐에 넣어요.

```ts
    // ④ 뒤처진 기록인가 — 넣을 때의 비용이 지금 적힌 값보다 크면 그 항목은 버린다.
    if (gu > (g[u] as number)) continue;

    for (const [v, w] of adj[u] as [number, number][]) {
      const ng = gu + w;
      // ⑤ 완화 — 지금 적힌 값보다 작을 때만 고쳐 적고 `ng + h(v)` 를 키로 넣는다.
      if (ng < (g[v] as number)) {
        g[v] = ng;
        open.push(v, ng, ng + h(v));
      }
    }
```

**여기서 가장 중요한 줄은 `open.push(v, ng, ng + h(v))` 입니다.** 둘째 인자 `ng` 는 `④` 가 뒤처진 기록을
가를 때 쓰고, 셋째 인자 `ng + h(v)` 가 꺼낼 차례를 정해요. 셋째 인자에서 `h(v)` 를 빼면 다익스트라이고, `ng` 를
빼면 키가 추정 하나인 판이 됩니다. 값을 한 번 고치는 T5 와, 그때 남은 옛 항목을 버리는 T8 을 실행하면 이렇게
나와요.

<!--proof:walk-t5t8-->

| 걸음 | 본 것 | 값 |
| --- | --- | --- |
| T5 | 꺼낸 항목 | (4, 5, 10) |
| T5 | 4→3 완화 | 11 > 5 + 3 이라 g[3] = 8 · 큐에 (3, 8, 11) |
| T5 | 큐 — 꺼낼 차례 | (3, 8, 11) (3, 11, 14) (7, 5, 18) |
| T8 | 꺼낸 항목 | (3, 11, 14) |
| T8 | 뒤처진 기록인가 | 11 > g[3] = 8 이 참이라 버린다 |
| T8 | 큐 — 꺼낼 차례 | (6, 16, 16) (7, 5, 18) |

T5 가 끝나면 정점 3 짜리 항목이 둘이고, 옛 값 11 짜리는 지우지 않고 그대로 둡니다. 세 걸음 뒤 T8 이 그 항목을
꺼내 `④` 로 버려요.

#### 짚고 가기 — 뒤처진 기록을 거르는 줄을 빼도 답은 안 틀린다

여기서 헷갈리기 쉬운 포인트는 `④` 한 줄입니다. 「어차피 완화는 더 작을 때만 고치니, 뒤처진 기록을 확장해도
아무것도 안 바뀌는 것 아닌가」로 읽기 쉬워요. 그 줄을 지운 판을 실행해 봅시다.

```ts
    // if (gu > (g[u] as number)) continue;   ← 이 줄을 지운 판
```

<!--proof:pause-stale-->

| 배치 | 정점 | 정본 | 버리는 줄이 없는 판 | 두 답 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 8 | 16 | 16 | 같다 |
| 전개 입력 · 일관성이 깨진 추정 | 8 | 16 | 16 | 같다 |
| 돌아가는 경로가 더 작다 | 4 | 3 | 3 | 같다 |
| 사슬 여섯 | 6 | 5 | 5 | 같다 |
| 격자 8×8 | 64 | 14 | 14 | 같다 |

배치 5 개 가운데 두 답이 같은 배치는 5 개입니다.

<!--/proof-->

**답은 한 배치도 안 틀립니다.** 뒤처진 기록의 비용은 지금 적힌 `g[u]` 보다 크고, 거기서 뻗어 나가는 값도 그만큼
커서 어떤 정점의 값도 줄이지 못해요. 그러면 이 줄은 무엇을 지킬까요. 답이 아니라 **일의 양**입니다. 뒤처진
기록이 실제로 쌓이는 배치를 섞어 확장한 정점 수를 정본과 나란히 셌습니다.

<!--proof:pause-stale-work-->

| 배치 | 정본이 버린 항목 | 정본의 확장 | 버리는 줄이 없는 판의 확장 | 늘어난 확장 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 1 | 6 | 7 | 1 |
| 전개 입력 · 일관성이 깨진 추정 | 0 | 8 | 8 | 0 |
| 격자 16×16 · 추정 30% | 1 | 262 | 263 | 1 |
| 완전 DAG 128 · 추정이 정확 | 0 | 127 | 127 | 0 |
| 완전 DAG 128 · 추정이 전부 0 | 3,908 | 127 | 4,035 | 3,908 |

늘어난 확장이 가장 많은 배치는 「완전 DAG 128 · 추정이 전부 0」 이고, 정본이 버린 항목 3,908 개를 그 판은 하나씩 확장합니다.

<!--/proof-->

완전 DAG 는 앞 정점에서 뒤 정점으로 가는 간선이 전부 있고, 가중치를 `2(j−i)−1` 로 잡아 **간선 하나하나가
반드시 값을 줄이게** 만든 배치예요. 같은 정점 짜리 항목이 큐에 잔뜩 쌓이고, 정본은 그중 3,908 개를 꺼내자마자
버립니다. 줄을 지운 판은 그 3,908 개를 하나씩 확장해 127 개이던 확장이 4,035 개가 돼요.

| 그 줄 | 이웃을 보는 항목 | 확장 |
| --- | --- | --- |
| 있다 | 비용이 `g[u]` 와 같은 항목만 | 추정이 일관적이면 정점마다 한 번 |
| 지웠다 | 뒤처진 기록도 | 버렸어야 할 항목 수만큼 늘어난다 |

#### 5. 아홉 걸음을 끝까지 실행한다

네 조각을 이어 고정 입력에 실행하면 아홉 걸음이 나옵니다. T1 은 준비, T2 부터 T9 까지가 큐에서 항목을 하나씩
꺼내는 반복이고, T9 가 목표를 꺼내 답을 돌려주는 자리예요. 걸음 재생 패널에서 정점 이름 옆 `h` 는 추정, 정점
안 `g` 는 지금까지 찾은 비용이고, 점선 정점은 아직 값이 없는 정점입니다. 굵은 실선은 지금 그 정점의 비용을 낸
간선이에요. 무대 아래 두 줄이 우선순위 큐를 꺼낼 차례대로 늘어놓은 것이고, 같은 칸의 정점과 키가 항목
하나입니다. 이번 걸음에 넣은 항목은 굵은 테로, 이미 뒤처진 기록은 대시 테로 흐리게 그렸어요.

T9 가 그것을 꺼내요. 정점 7 의 항목은 키 18 로 끝까지 큐에 남았습니다.

이 입력에서 거짓 쪽이 안 나온 조건이 둘 있습니다. `②` 는 목표를 꺼내 멈추느라 큐가 비는 일이 없었고, `⑤` 는
완화한 간선 여덟이 모두 값을 줄였어요. 두 거짓 쪽을 작은 입력 둘로 실행했습니다.

#### 짚고 가기 — 확장을 마친 정점을 다시 안 고치면 일관되지 않은 추정에서 답이 틀린다

여기서 헷갈리기 쉬운 포인트는 **한 정점을 두 번 확장하는 일**입니다. 전개 입력에서는 정점마다 확장이 한 번씩이라
「확장을 마친 정점은 표시해 두고 다시 안 고치면 되지 않나」로 읽기 쉬워요. 확장을 마친 정점의 값을 더는 못
고치게 막은 판을 실행해 봅시다.

```ts
    if (gu > (g[u] as number)) continue;
    g[u] = Number.NEGATIVE_INFINITY;   // ← 확장을 마친 정점을 다시 안 고치게 막은 판
```

<!--proof:pause-closed-->

| 배치 | 정점 | 정본 | 다시 안 고치는 판 | 두 답 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 · 일관성이 깨진 추정 | 8 | 16 | 19 | 어긋난다 |
| 전개 입력 | 8 | 16 | 16 | 같다 |
| 전개 입력 · 추정 0 | 8 | 16 | 16 | 같다 |
| 사슬 여섯 | 6 | 5 | 5 | 같다 |
| 격자 8×8 | 64 | 14 | 14 | 같다 |

일관성이 깨진 추정에서 정본은 정점을 2 번 다시 확장해 16 을 내고, 다시 안 고치는 판은 19 를 냅니다.

<!--/proof-->

**추정이 일관적인 넷은 답이 그대로입니다.** 일관된 추정에서는 한 번 확장한 정점에 비용이 더 작은 길이 뒤늦게 오지 않아서
막을 것이 없어요. 답이 갈리는 배치의 추정은 정점 3 에 0, 정점 4 에 11 을 줍니다. 둘 다 실제 최소 비용을 넘지 않아
허용 가능하지만, 간선 `4 → 3` 에서 추정이 11 에서 0 으로 가중치 3 보다 크게 줄어 일관성이 깨져요. 그 배치에서 정본이
꺼낸 차례를 적으면 이렇습니다.

<!--proof:pause-closed-where-->

| 꺼낸 차례 | 꺼낸 항목 | 한 일 |
| ---: | --- | --- |
| 1 | (0, 0, 8) | 확장 · g[1] = 3 · g[2] = 4 · g[7] = 5 |
| 2 | (2, 4, 9) | 확장 · g[3] = 11 |

| 9 | (6, 16, 16) | 목표라 반환 |

정본은 정점 3 을 2 번 확장합니다 — 처음은 비용 11, 다음은 비용 8 입니다.

정점 3 이 키 11 로 먼저 나와 비용 11 로 확장되고, 뒤에 정점 4 가 나와 간선 `4 → 3` 으로 비용 8 을 찾습니다. 정본은
그 8 을 받아 정점 3 을 한 번 더 확장하고 목표까지 16 을 퍼뜨려요. 다시 안 고치는 판은 정점 3 의 값을 막아 두어 8 을
받지 못하고, 첫 확장이 만든 19 를 돌려줍니다. 이 글의 코드는 표시 배열을 따로 두지 않고 `④` 의 비용 비교로만
거르므로, 값이 줄어든 정점은 언제든 다시 확장할 수 있어요.

#### 6. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 둘이에요. 반복이 끝나도 목표를 못 꺼냈을 때
`Infinity` 를 돌려주는 마지막 줄과, 이진 힙의 `pop` 이 빈 배열에서 `undefined` 를 돌려주는 갈래입니다. 반복 조건이
`size() > 0` 이라 뒤엣것은 실제로 실행되지 않지만 타입이 그것을 요구해요.

```ts
export type Edge = [number, number, number];

export function aStarSearch(
  n: number,
  edges: Edge[],
  src: number,
  goal: number,
  h: (v: number) => number,
): number {
  // ① 시작값 — 아직 아무 경로도 못 찾았으므로 전부 `Infinity` 이고 시작 정점만 `0` 이다.
  const g: number[] = Array.from({ length: n }, () => Number.POSITIVE_INFINITY);
  const adj: [number, number][][] = Array.from({ length: n }, () => []);
  for (const [u, v, w] of edges) (adj[u] as [number, number][]).push([v, w]);

  g[src] = 0;
  const open = new MinHeap();
  open.push(src, 0, h(src));

  // ② 큐에 남은 항목이 있는가 — 없으면 목표까지 이어지는 경로가 없다.
  while (open.size() > 0) {
    const [u, gu] = open.pop() as [number, number, number];

    // ③ 목표를 꺼냈는가 — 처음 꺼내는 그 순간의 비용이 곧 답이다.
    if (u === goal) return gu;

    // ④ 뒤처진 기록인가 — 넣을 때의 비용이 지금 적힌 값보다 크면 그 항목은 버린다.
    if (gu > (g[u] as number)) continue;

    for (const [v, w] of adj[u] as [number, number][]) {
      const ng = gu + w;
      // ⑤ 완화 — 지금 적힌 값보다 작을 때만 고쳐 적고 `ng + h(v)` 를 키로 넣는다.
      if (ng < (g[v] as number)) {
        g[v] = ng;
        open.push(v, ng, ng + h(v));
      }
    }
  }

  return Number.POSITIVE_INFINITY;
}

class MinHeap {
  private items: [number, number, number][] = [];

  size(): number {
    return this.items.length;
  }

  push(node: number, cost: number, key: number): void {
    this.items.push([node, cost, key]);
    let i = this.items.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.key(i) >= this.key(parent)) break;
      this.swap(i, parent);
      i = parent;
    }
  }

  pop(): [number, number, number] | undefined {
    const top = this.items[0];
    const last = this.items.pop();
    if (top === undefined || last === undefined) return undefined;
    if (this.items.length > 0) {
      this.items[0] = last;
      let i = 0;
      for (;;) {
        const left = 2 * i + 1;
        const right = 2 * i + 2;
        let small = i;
        if (left < this.items.length && this.key(left) < this.key(small)) {
          small = left;
        }
        if (right < this.items.length && this.key(right) < this.key(small)) {
          small = right;
        }
        if (small === i) break;
        this.swap(i, small);
        i = small;
      }
    }
    return top;
  }

  private key(i: number): number {
    return (this.items[i] as [number, number, number])[2];
  }

  private swap(a: number, b: number): void {
    const t = this.items[a] as [number, number, number];
    this.items[a] = this.items[b] as [number, number, number];
    this.items[b] = t;
  }
}
```

### 알아 두면 좋은 개념 — 최적 우선 탐색

지금까지 손댄 것은 **우선순위 큐의 키 하나**뿐이었습니다. 꺼내고, 버리고, 완화하고, 넣는 나머지 절차는 다익스트라와
한 글자도 다르지 않아요. 저장소에서 「지금 가장 좋아 보이는 것」을 꺼내 확장하기를 되풀이하고, 「좋아 보인다」의
뜻만 키로 정하는 이 틀을 **최적 우선 탐색(best-first search)** 이라고 부릅니다. 「아이디어를 떠올리는 과정」에서 세
키를 같은 입력에 넣어 본 표가 바로 이 틀 안에서 키만 바꾼 것이었어요. 같은 틀에 이름이 붙은 절차를 늘어놓으면
이렇습니다.

| 절차 | 꺼내는 규칙 | 항목에 딸린 키 |
| --- | --- | --- |
| 너비 우선 탐색 | 가장 먼저 넣은 것 | 없다 — 넣은 차례가 곧 꺼내는 차례다 |
| 다익스트라 | 키가 가장 작은 것 | 지금까지의 비용 `g` |
| 탐욕 최적 우선 탐색 | 키가 가장 작은 것 | 추정 `h` |
| A* 탐색(이 글) | 키가 가장 작은 것 | `g + h` |
| 프림 | 키가 가장 작은 것 | 그 정점을 트리에 붙이는 간선 하나의 가중치 |

키가 추정 하나인 탐욕 최적 우선 탐색은 「아이디어를 떠올리는 과정」의 표에서 전개 입력에 16 대신 19 를 냈습니다.
같은 이름이 [`primMst`](../../graph-flow/primMst/primMst-guide.md) 편에도 나와요. 그쪽은 키를 「트리에 붙이는 간선
하나의 가중치」로 둔 자리이고, 가중치가 없는 그래프의
[`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) 는 키 없이 넣은 차례로 꺼내는 자리입니다.
**절차를 고르는 것이 아니라 키를 고르는 것**이라는 관점이 이 이름이 주는 것이에요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 추정에 무엇을 요구하고 그 대가로 무엇을 보장하는지,
무엇이 매 걸음 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 목표가 하나로 정해져 있다 | 모든 정점까지의 비용이 필요하면 추정으로 걸러 낼 것이 없다 | 목표를 꺼내는 순간 `return gu` 로 멈춘다 |
| 정점마다 목표까지의 하한을 적은 연산으로 낼 수 있다 | 좌표가 있으면 직선 거리나 맨해튼 거리가 그 하한이다 | 넣을 때마다 `h(v)` 를 한 번 부른다 |
| 그 하한이 실제 값에 가깝고, 모든 정점에 같은 규칙으로 준다 | 느슨하면 다익스트라와 같아지고, 섞으면 재확장이 붙는다 | 키 `ng + h(v)` 가 목표 쪽 항목을 앞으로 당긴다 |
| 가중치가 0 이상이다 | 음수가 하나라도 있으면 목표를 꺼낸 뒤 비용이 더 작은 길이 나올 수 있다 | 목표를 처음 꺼낸 값을 답으로 쓴다 |

셋째 조건의 값은 「아이디어 상세」의 「추정을 모든 정점에 같은 규칙으로 주는 까닭」이 보였습니다. 32×32 격자에서
정확한 추정을 모든 정점에 주면 확장이 123 개이고 전부 0 이면 1,023 개였어요. 넷째 조건이 깨지면
[`bellmanFord`](../bellmanFord/bellmanFord-guide.md) 쪽으로 가야 합니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "출발지에서 목적지까지"                      <- 목표가 하나다
  "좌표" "위치" "격자" "미로"                  <- 뺄셈 두 번으로 하한을 낼 수 있다
  "추정" "휴리스틱" "예상 거리"                <- 추정 함수가 주어진다
  "실제 거리를 넘지 않는다"                    <- 그 추정이 허용 가능하다

제약에 이런 모양이 보이면
  정점이 10^5 규모인데 묻는 목표가 하나다      <- 전부 확장하는 것이 헛일이다

반대로 이런 말이 보이면 해당하지 않는다
  "한 곳에서 각 지점까지"                      <- 목표가 정점 전부다
  "비용이 음수일 수 있다"                      <- 목표를 처음 꺼낸 값이 답이 아니다
  "좌표가 없다" "추정을 줄 수 없다"            <- 추정이 0 이면 다익스트라와 같다
```

마지막 무리가 보이면 다른 절차로 갑니다. 목표가 정점 전부면 [`dijkstra`](../dijkstra/dijkstra-guide.md) 가 같은 큐로
한 번에 답하고, 가중치가 0 과 1 두 가지뿐이면 [`zeroOneBfs`](../../graph/zeroOneBfs/zeroOneBfs-guide.md) 가 있어요.
추정 없이 목표 하나를 빨리 찾아야 하면 아래 「경쟁 설계와의 대조」의 양방향 다익스트라를 봅니다.

#### 실제로 쓰이는 곳

- **Boost Graph Library 의 `astar_search`** — C++ 그래프 라이브러리 Boost.Graph 의 A* 구현입니다. 문서가
  *"Unlike best-first search, A\* takes into account the known cost from the start of the search to v; the paths
  A\* takes are guided by a function f(v) = g(v) + h(v), where h(v) is the heuristic function, and g(v)
  (sometimes denoted c(s, v)) is the known cost from the start to v."* 라고 적고 있어요. 이 글의 키 `g + h` 가
  그대로 규격 문장에 들어가 있는 자리입니다. 1차 출처:
  [Boost.Graph `astar_search` 문서](https://www.boost.org/doc/libs/1_86_0/libs/graph/doc/astar_search.html)
  (2026-09-07 조회).
- **NetworkX 의 `astar_path`** — 파이썬 그래프 라이브러리의 A* 구현입니다. 소스의 문서 문자열이 *"If the heuristic
  is inadmissible (if it might overestimate the cost of reaching the goal from a node), the result may not be a
  shortest path."* 라고 적고, 같은 자리에 *"The algorithm does not support updating heuristic values for the same
  node due to caching the first heuristic calculation per node."* 도 함께 적어 뒀어요. 1차 출처:
  [`networkx/algorithms/shortest_paths/astar.py`](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/shortest_paths/astar.py)
  (2026-09-07 조회).
- **Godot 엔진의 `AStarGrid2D`** — 게임 엔진 Godot 이 격자 길찾기를 위해 내장한 클래스입니다. 문서가
  *"AStarGrid2D is a variant of AStar2D that is specialized for partial 2D grids."* 라고 적고, 기본 추정이 유클리드
  거리라고 명시합니다. 1차 출처:
  [Godot `AStarGrid2D` 문서](https://docs.godotengine.org/en/stable/classes/class_astargrid2d.html)
  (2026-09-07 조회).
- **원 논문** — P. Hart · N. Nilsson · B. Raphael, *"A Formal Basis for the Heuristic Determination of Minimum Cost
  Paths"*, IEEE Transactions on Systems Science and Cybernetics, 1968
  ([DOI 10.1109/TSSC.1968.300136](https://doi.org/10.1109/TSSC.1968.300136)).

#### 경쟁 설계와의 대조

**경쟁 설계는 양방향 다익스트라입니다.** 시작에서 앞으로 가는 탐색과 목표에서 뒤로 가는 탐색을 함께 진행하고, 두
탐색이 만난 자리의 비용 합을 답 후보로 적어 두었다가 **두 앞머리 키의 합이 그 후보 이상이 되면** 멈춰요. 추정
함수를 한 번도 안 부르는 대신 **역방향 이웃 목록**을 만들어야 합니다. 이 설계도 정확한 답을 내고, 잴 때마다
정본과 답을 대조했어요.

| 설계 | 목표 쪽으로 좁히는 수단 | 따로 필요한 것 |
| --- | --- | --- |
| 이 가이드의 절차 | 추정이 목표 쪽 항목을 큐 앞으로 당긴다 | 허용 가능한 추정 |
| 양방향 다익스트라 | 양쪽에서 좁혀 들어가 만나는 자리에서 멈춘다 | 역방향 이웃 목록 |

**같은 입력에서 같은 잣대로 나란히 잽니다.** 잣대는 둘이에요. 하나는 「아이디어를 떠올리는 과정」에서 정한
**기본 연산**(힙 안의 비교 · 완화 시도 · 추정 호출의 합)이고, 다른 하나는 비용 배열의 칸과 힙이 가장 커졌을 때의
항목 수를 더한 **저장 칸**입니다. 두 잣대 모두 간선 목록을 이웃 목록으로 옮기는 몫은 빼고 셉니다 — 그 몫은 아래에
따로 더해 봐요. 입력은 한 변 32 인 격자(정점 1,024 · 방향 간선 3,968)로 고정하고 **추정의 정보량 하나만** 바꿉니다.
정점 중 몇 퍼센트에 정확한 맨해튼 거리를 주고 나머지에 0 을 주는가이고, 어느 정점이 그 몇 퍼센트인지는 정점 번호를
섞는 고정 해시가 정해요. 전개 입력은 정점이 여덟뿐이라 정보량을 바꿀 자리가 없어 격자를 따로 썼고, 전개 입력의
값도 첫 두 줄에 함께 실었습니다. 입력과 생성식은 `aStarSearch-guide.alt.ts` 에 상수로 있습니다.

| 입력 | 계수 | 이 절차 | 양방향 다익스트라 | 적은 쪽 |
| --- | --- | ---: | ---: | --- |
| 전개 입력(정점 8) | 기본 연산 | 30 | 17 | 양방향 |
| 전개 입력(정점 8) | 저장 칸 | 11 | 20 | 이 절차 |
| 격자 · 추정 0% | 기본 연산 | 12,212 | 10,900 | 양방향 |
| 격자 · 추정 30% | 기본 연산 | 55,560 | 10,900 | 양방향 |
| 격자 · 추정 76% | 기본 연산 | 11,737 | 10,900 | 양방향 |
| 격자 · 추정 77% | 기본 연산 | 7,355 | 10,900 | 이 절차 |
| 격자 · 추정 100% | 기본 연산 | 1,040 | 10,900 | 이 절차 |

### 수식 정의와 유도

간선 $u \to v$ 의 가중치를 $w(u, v) \ge 0$ 이라 쓰고, $u$ 에서 $v$ 로 가는 경로들의 비용 중 가장 작은 값을
$d(u, v)$ 라 씁니다. 경로가 없으면 $d(u, v) = \infty$ 로 둬요. 추정 함수 $h$ 가 만족할 수 있는 조건은 둘입니다.

$$
h(v) \le d(v, \text{goal}) \quad \text{(허용 가능)} \qquad h(u) \le w(u, v) + h(v) \quad \text{(일관)}
$$

두 조건이 보는 자리가 다릅니다.

| 조건 | 보는 자리 | 조건의 수 |
| --- | --- | --- |
| 허용 가능 | 정점 하나와 목표 사이 — 그 정점의 추정이 실제 값을 안 넘는가 | 정점마다 하나, `V` 개 |
| 일관 | 간선 하나 — 간선을 지날 때 추정이 가중치보다 크게 줄지 않는가 | 간선마다 하나, `E` 개 |

**일관이면 허용 가능합니다.** $v$ 에서 목표까지의 최소 비용 경로를 $v = u_0 \to u_1 \to \cdots \to u_k = \text{goal}$
이라 두고 일관 조건을 $i = 0$ 부터 $k-1$ 까지 적은 뒤, 왼쪽끼리 오른쪽끼리 더합니다. 그러면 $h(u_1)$ 부터
$h(u_{k-1})$ 까지가 양쪽에 한 번씩 나와 지워지고 양 끝만 남아요. 이렇게 가운데 항이 지워지는 합을 망원합이라고
부릅니다.

$$
\begin{aligned}
h(u_0) &\le w(u_0, u_1) + h(u_1) \\
h(u_1) &\le w(u_1, u_2) + h(u_2) \\
&\;\;\vdots \\
h(u_{k-1}) &\le w(u_{k-1}, u_k) + h(u_k)
\end{aligned}
$$

$$
h(u_0) \le \sum_{i=0}^{k-1} w(u_i, u_{i+1}) + h(u_k) = d(v, \text{goal}) + h(\text{goal})
$$

목표에서는 일관 조건만으로 $h(\text{goal})$ 이 정해지지 않으므로, 추정이 0 이상이고 목표에서 0 이라는 것을 따로
둡니다(전개 입력의 맨해튼 거리는 목표에서 0 입니다). 그러면 위 식이 곧 $h(v) \le d(v, \text{goal})$ 이에요. **거꾸로는
성립하지 않습니다** — 전개 입력에 쓴 두 추정을 간선마다 넣어 확인합니다.

<!--proof:math-consistent-->

맨해튼 거리입니다.

| 간선 | w | h(u) | h(v) | w + h(v) | h(u) ≤ w + h(v) |
| --- | ---: | ---: | ---: | ---: | --- |
| 0→1 | 3 | 8 | 7 | 10 | 성립한다 |
| 0→2 | 4 | 8 | 5 | 9 | 성립한다 |
| 0→7 | 5 | 8 | 13 | 18 | 성립한다 |
| 1→4 | 2 | 7 | 5 | 7 | 성립한다 |
| 2→3 | 7 | 5 | 3 | 10 | 성립한다 |
| 4→3 | 3 | 5 | 3 | 6 | 성립한다 |
| 3→5 | 2 | 3 | 2 | 4 | 성립한다 |
| 5→6 | 6 | 2 | 0 | 6 | 성립한다 |

정점 3 에 0, 정점 4 에 11 을 준 추정입니다.

| 간선 | w | h(u) | h(v) | w + h(v) | h(u) ≤ w + h(v) |
| --- | ---: | ---: | ---: | ---: | --- |
| 0→1 | 3 | 8 | 7 | 10 | 성립한다 |
| 0→2 | 4 | 8 | 5 | 9 | 성립한다 |

| 4→3 | 3 | 11 | 0 | 3 | 성립하지 않는다 |

아래 추정에서 조건이 성립하지 않는 간선은 1 개이고, 그 추정도 정점마다 실제 최소 비용을 넘지 않습니다.

<!--/proof-->

아래 추정은 허용 가능한데 간선 `4 → 3` 에서 일관 조건이 성립하지 않습니다. 허용 가능은 정점 여덟에 대한 조건이고
일관은 간선 여덟에 대한 조건이라, 정점마다 통과해도 간선에서 걸릴 수 있어요.

**일관 조건은 간선 가중치를 다시 매기는 것으로 다시 적힙니다.** 간선마다 도착 정점의 추정을 더하고 출발 정점의
추정을 빼면, 일관 조건이 곧 「다시 매긴 가중치가 음수가 아니다」가 됩니다.

$$
w'(u, v) = w(u, v) - h(u) + h(v) \ge 0 \iff h(u) \le w(u, v) + h(v)
$$

```ts
// 다시 매긴 가중치. 일관 조건은 이 값이 음수가 아니라는 것과 같은 말이다.
const shifted = w - h(u) + h(v);
```

경로 $P = u_0 \to \cdots \to u_k$ 의 비용을 $c(P)$, 다시 매긴 비용을 $c'(P)$ 라 쓰면, 여기서도 가운데 항이
$-h(u_i) + h(u_i)$ 꼴로 부호를 바꿔 두 번씩 나와 지워집니다.

$$
c'(P) = \sum_{i=0}^{k-1} \bigl(w(u_i, u_{i+1}) - h(u_i) + h(u_{i+1})\bigr) = c(P) - h(u_0) + h(u_k)
$$

남는 것은 $-h(u_0) + h(u_k)$ 뿐이고, 그것은 경로가 아니라 양 끝만으로 정해지는 값입니다. 전개 입력의 간선과 최소
비용 경로에 넣어 검산합니다.

<!--proof:math-reweight-->

| 간선 | w | h(u) | h(v) | w − h(u) + h(v) |
| --- | ---: | ---: | ---: | ---: |
| 0→1 | 3 | 8 | 7 | 2 |
| 0→2 | 4 | 8 | 5 | 1 |
| 0→7 | 5 | 8 | 13 | 10 |
| 1→4 | 2 | 7 | 5 | 0 |
| 2→3 | 7 | 5 | 3 | 5 |
| 4→3 | 3 | 5 | 3 | 1 |
| 3→5 | 2 | 3 | 2 | 1 |
| 5→6 | 6 | 2 | 0 | 4 |

다시 매긴 가중치가 음수인 간선은 0 개입니다. 최소 비용 경로 0→1→4→3→5→6 의 원래 비용은 16, 다시 매긴 비용은 8 이고, 그 차이 8 이 h(0) − h(6) = 8 과 같습니다.

<!--/proof-->

**시작과 목표가 같은 경로들은 전부 같은 값만큼 옮겨집니다.** $u_0 = \text{src}$ 이고 $u_k = \text{goal}$ 이면
$c'(P) = c(P) - h(\text{src}) + h(\text{goal})$ 이고, 이 값에서 빼고 더하는 두 항은 경로마다 다르지 않아요. 그래서
다시 매긴 그래프에서 가장 작은 경로가 원래 그래프에서도 가장 작습니다. 이 절차의 키 $g + h$ 는 다시 매긴 그래프에서의
비용에 $h(\text{src})$ 를 더한 것이라, 일관된 추정에서는 이 절차가 **다시 매긴 그래프 위의 다익스트라**와 같은 차례로
꺼냅니다. 다시 매긴 가중치가 음수가 아니니 다익스트라처럼 정점마다 확장이 한 번으로 끝나요.

**확장되는 정점도 식으로 좁혀집니다.** 답을 $C = d(\text{src}, \text{goal})$ 이라 두고 정점 $v$ 의 값을
$F(v) = d(\text{src}, v) + h(v)$ 라 두면, 일관된 추정에서 확장한 정점의 모임은 두 모임 사이에 듭니다.

$$
\{\, v : F(v) < C \,\} \subseteq \{\text{확장된 정점}\} \subseteq \{\, v : F(v) \le C \,\}
$$

| 무리 | 확장되는가 | 까닭 |
| --- | --- | --- |
| $F(v) < C$ | 반드시 확장된다 | 그 정점의 항목이 목표 항목보다 키가 작아 먼저 나온다 |
| $F(v) = C$ | 될 수도 아닐 수도 있다 | 목표와 키가 같아 힙의 앞뒤가 정한다 |
| $F(v) > C$ | 한 번도 확장되지 않는다 | 그 정점의 어느 항목도 키가 $C$ 보다 커서 목표가 먼저 나온다 |

가운데 줄이 있어서 등식이 아니라 사이에 드는 관계로 적습니다. 세 배치에서 세어 대조했어요.

<!--proof:math-expand-->

| 배치 | 정점 | 답 C | F(v) < C 인 정점 | 확장한 정점 | F(v) ≤ C 인 정점 | 확장한 정점 수의 자리 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 8 | 16 | 6 | 6 | 7 | 사이에 든다 |
| 격자 8×8 | 64 | 14 | 0 | 27 | 64 | 사이에 든다 |
| 사슬 여섯 | 6 | 5 | 0 | 5 | 6 | 사이에 든다 |

배치 3 개 가운데 확장한 정점 수가 두 수 사이를 벗어난 배치는 0 개입니다.

<!--/proof-->

격자는 가중치가 전부 1 이고 추정이 맨해튼 거리라 모든 정점에서 $F(v)$ 가 답과 같습니다. 그래서 첫 수가 0 이고
셋째 수가 정점 전부예요. 확장한 27 개는 힙이 키가 같은 항목을 어떤 차례로 내주느냐가 정한 값입니다.

**마지막으로 규모를 넣습니다.** 추정이 일관되면 정점마다 확장이 한 번이고, 확장 한 번이 그 정점의 나가는 간선을
한 번씩 보므로 완화 시도가 모두 합쳐 $E$ 번 이하예요. 큐에 들어가는 항목은 시작 항목 하나에 완화가 값을 고친 횟수를
더한 것이라 $E + 1$ 을 넘지 않고, 추정 호출도 넣을 때마다 한 번이라 같은 수입니다. 항목 하나는 넣을 때 힙의 높이만큼
한 번씩, 꺼낼 때 높이만큼 두 번씩(두 자식과) 비교해요.

$$
\text{기본 연산} \le \underbrace{E}_{\text{완화 시도}} + \underbrace{(E+1)}_{\text{추정 호출}} + \underbrace{3(E+1)\lceil \log_2 (E+1) \rceil}_{\text{힙 안의 비교}}
$$

<!--proof:math-scale-->

| 항 | 닫힌 형태 | 규모의 상한에서 |
| --- | --- | ---: |
| 확장한 정점 | V | 100,000 |
| 큐에 들어가는 항목 | E + 1 | 200,001 |
| 완화 시도 | E | 200,000 |
| 추정 호출 | E + 1 | 200,001 |
| 항목 하나를 넣고 꺼내는 힙 안의 비교 | 3⌈log₂(E+1)⌉ | 54 |
| 힙 안의 비교 전부 | 3(E+1)⌈log₂(E+1)⌉ | 10,800,054 |
| 기본 연산 전부 | E + (E+1) + 3(E+1)⌈log₂(E+1)⌉ | 11,200,055 |

V = 100,000 · E = 200,000 을 넣은 값이고, 기본 연산 전부는 1 초에 1 억 번 기준으로 0.112 초입니다.

<!--/proof-->

이 상한은 추정이 일관적일 때의 것입니다. 추정이 걸러 내는 만큼 실제 값은 이보다 작아지고, 걸러 내지 못하면 상한이
그대로 값이 돼요. 일관성이 없으면 첫 줄이 $V$ 로 막히지 않고, 그러면 아래 줄의 상한도 함께 풀립니다.

### 불변식 — 꺼낸 항목의 키는 답을 넘지 않는다

파트 1 에서 코드가 동작하는 것을 아홉 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는 뜻은
아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> 추정이 허용 가능하고 가중치가 0 이상이면, 목표를 꺼내기 전까지 큐에서 항목을 꺼낸 **그 직후마다** 그 항목의 키는
> 답 `d(src, goal)` 을 넘지 않습니다.

| 시점 | 불변식이 말하는 것 |
| --- | --- |
| 항목을 꺼낸 직후 | 그 항목의 키가 답 이하다 |
| 항목이 큐 안에 머무는 동안 | 말하지 않는다 — 답보다 큰 키도 얼마든지 머문다 |
| 목표를 꺼낸 직후 | 목표 항목의 키가 답 이하이고, 반복이 끝난다 |

「언제」가 중요해요. 전개 입력의 정점 7 은 키 18 로 끝까지 큐 안에 머물렀지만 한 번도 꺼내지 않았으니 불변식과
어긋나지 않습니다. 왜 넘지 않는지는 세 줄로 이어집니다.

| 단계 | 참인 것 | 근거 |
| --- | --- | --- |
| 최소 비용 경로 위에 항목이 남아 있다 | 아직 목표를 안 꺼냈다면 최소 비용 경로 위에 「비용이 이미 최소인 채로 큐에 든」 정점 `x` 가 있다 | 시작 정점이 그런 정점으로 출발하고, 그런 정점을 꺼내 확장하면 경로의 다음 정점이 최소 비용으로 들어간다 |
| 그 항목의 키가 답 이하다 | `d(src, x) + h(x) ≤ d(src, x) + d(x, goal) = d(src, goal)` | 가운데 부등호가 허용 가능 조건이다 |
| 꺼낸 키가 답 이하다 | 꺼낸 항목의 키 ≤ `x` 의 항목의 키 | 큐는 키가 가장 작은 것을 내준다 |

첫 줄의 등호 `d(src, x) + d(x, goal) = d(src, goal)` 은 `x` 가 최소 비용 경로 위에 있어서 성립합니다. 둘째 줄이
허용 가능 조건에 기대고, 셋째 줄이 우선순위 큐에 기대요. **목표를 꺼낸 걸음에서도 같은 부등식이 성립하므로, 그때의
키 = 목표의 비용이 답 이하이고, 그 비용은 실재하는 경로의 비용이라 답 이상입니다.** 둘이 같으니 목표를 처음 꺼낸
값이 답이에요.

**유지되는 것을 걸음마다 값으로 봅니다.** 실행이 꺼낼 때마다 그 키를 답과 비교해 넘은 횟수를 셌어요. 배치는 추정을
바꾼 것 셋과 모양이 다른 것 넷입니다.

<!--proof:invariant-steps-->

| 배치 | 꺼낸 항목 | 답 | 가장 큰 꺼낸 키 | 키가 답을 넘은 꺼내기 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 8 | 16 | 16 | 0 |
| 전개 입력 · 추정 0 | 9 | 16 | 16 | 0 |
| 전개 입력 · 일관성이 깨진 추정 | 9 | 16 | 16 | 0 |
| 돌아가는 경로가 더 작다 | 4 | 3 | 3 | 0 |
| 사슬 여섯 | 6 | 5 | 5 | 0 |
| 격자 8×8 | 28 | 14 | 14 | 0 |
| 격자 16×16 · 추정 30% | 264 | 30 | 30 | 0 |

배치 7 개에서 꺼낼 때마다 비교해 키가 답을 넘은 꺼내기는 모두 0 번이고, 가장 큰 꺼낸 키가 답과 같은 배치가 7 개입니다.

<!--/proof-->

**어긋난 꺼내기가 0 번입니다.** 가장 큰 꺼낸 키가 어느 배치에서도 답과 같은 것은, 그 꺼내기가 목표를 꺼내는 마지막
걸음이고 거기서 등호가 성립하기 때문이에요. 일관성이 깨진 추정에서도 0 번인 것을 봐 주세요 — 이 불변식은 일관성이
아니라 허용 가능성에만 기댑니다.

**엣지 케이스도 같은 자리에서 봅니다.** 정점이 하나뿐인 경우, 간선이 없는 경우, 목표에 이르는 경로가 없는 경우,
가중치가 전부 0 인 경우, 같은 두 정점 사이에 간선이 여럿인 경우, 가중치가 규모의 상한인 경우, 자기 자신으로 가는
간선이 있는 경우를 놓고, 경로를 전부 만들어 고른 답과 대조했습니다.

<!--proof:invariant-edges-->

| 배치 | 정점 | 정본의 답 | 경로를 전부 만든 답 | 꺼낸 항목 | 두 답 |
| --- | ---: | ---: | ---: | ---: | --- |
| 정점 하나 · 시작이 곧 목표 | 1 | 0 | 0 | 1 | 같다 |
| 간선이 없고 목표가 다르다 | 2 | Infinity | Infinity | 1 | 같다 |
| 목표로 가는 간선이 없다 | 3 | Infinity | Infinity | 2 | 같다 |
| 가중치가 전부 0 | 3 | 0 | 0 | 3 | 같다 |
| 같은 두 정점 사이에 간선 셋 | 2 | 3 | 3 | 2 | 같다 |
| 가중치가 10^9 | 3 | 2,000,000,000 | 2,000,000,000 | 3 | 같다 |
| 자기 자신으로 가는 간선 | 2 | 2 | 2 | 2 | 같다 |

배치 7 개 가운데 두 답이 같은 배치는 7 개입니다.

<!--/proof-->

시작이 곧 목표면 처음 꺼내는 항목이 목표라 0 이 그대로 나옵니다. 목표에 이르는 경로가 없으면 넣은 항목을 다 꺼낸 뒤
큐가 비어 `Infinity` 가 나와요. 자기 자신으로 가는 간선은 `ng < g[v]` 가 `g[u] + 5 < g[u]` 라서 값을 못 줄이고
지나갑니다. 가중치가 전부 0 이면 키가 줄지 않은 채 같은 값으로 이어지는데, 불변식은 「넘지 않는다」라서 등호로
그대로 성립해요.

**이제 깨뜨려 봅시다.** 위 논증이 기댄 자리는 「키를 만들 때 추정을 그대로 더한다」는 한 줄이에요. 그 줄에서 추정을
두 배로 부풀리면, 부풀린 추정이 실제 값을 넘는 정점에서 둘째 단계의 부등호가 깨집니다.

```ts
        open.push(v, ng, ng + 2 * h(v));   // ← 추정을 두 배로 부풀린 판
```

<!--proof:mutant-inflate-->

| 배치 | 정점 | 정본 | 두 배로 부풀린 판 | 두 답 |
| --- | ---: | ---: | ---: | --- |
| 두 경로의 비용 차이가 1 | 4 | 11 | 12 | 어긋난다 |
| 전개 입력 | 8 | 16 | 16 | 같다 |
| 돌아가는 경로가 더 작다 | 4 | 3 | 3 | 같다 |
| 사슬 여섯 | 6 | 5 | 5 | 같다 |
| 격자 8×8 | 64 | 14 | 14 | 같다 |

같은 배치에서 꺼낸 키가 답을 넘은 꺼내기를 세면 이렇습니다.

| 배치 | 정본의 가장 큰 꺼낸 키 | 부풀린 판의 가장 큰 꺼낸 키 | 답 | 부풀린 판에서 키가 답을 넘은 꺼내기 |
| --- | ---: | ---: | ---: | ---: |
| 두 경로의 비용 차이가 1 | 11 | 18 | 11 | 2 |
| 전개 입력 | 16 | 17 | 16 | 1 |
| 격자 8×8 | 14 | 27 | 14 | 13 |

두 경로의 비용 차이가 1 인 배치에서 정본은 11 을, 부풀린 판은 12 를 냅니다.

<!--/proof-->

**두 경로의 비용 차이가 1 인 배치에서 11 대신 12 가 나옵니다.** 그 배치는 목표로 가는 길이 둘이고 하나는 1 + 10 = 11,
다른 하나는 6 + 6 = 12 예요. 부풀린 판에서는 앞 길의 첫 정점 키가 1 + 2×10 = 21 이 되어 뒤 길의 6 + 2×6 = 18 보다
커지고, 그래서 뒤 길이 먼저 목표에 이릅니다. 둘째 표가 그 자리를 값으로 보여요 — 부풀린 판의 가장 큰 꺼낸 키가 18 로
답 11 을 넘고, 넘은 꺼내기가 2 번입니다. 전개 입력과 격자는 키가 답을 넘은 꺼내기가 있는데도 답이 그대로예요. 불변식이
깨진 것과 답이 틀린 것은 다른 일이고, 불변식이 깨지면 답을 지키던 근거가 사라질 뿐입니다.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 무리입니다. 간선 목록을 이웃 목록으로 바꾸는 것, 우선순위 큐에 넣고 꺼내는 것, 확장한
정점의 간선을 완화하는 것이에요. 이 글의 잣대는 「아이디어를 떠올리는 과정」에서 정한 기본 연산(힙 안의 비교 · 완화
시도 · 추정 호출)이고, 이웃 목록 만들기는 따로 셉니다. 전개의 걸음으로 확인하면 이렇게 나뉩니다.

<!--proof:perf-count-->

| 무리 | 걸음 | 횟수 |
| --- | --- | ---: |
| 이웃 목록 만들기 | T1 | 8 |
| 큐에 넣기 | T1 과 값을 고친 걸음 | 9 |
| 큐에서 꺼내기 | T2 ~ T9 | 8 |
| 그중 확장 | T2 · T3 · T4 · T5 · T6 · T7 | 6 |
| 그중 뒤처진 기록 버리기 | T8 | 1 |
| 그중 목표라 돌려주기 | T9 | 1 |
| 완화 시도 | T2 · T3 · T4 · T5 · T6 · T7 | 8 |
| 추정 호출 | 큐에 넣을 때마다 | 9 |
| 힙 안의 비교 | 넣기와 꺼내기 안에서 | 13 |

정점 V = 8 · 간선 E = 8 인 입력입니다. 기본 연산은 비교 13 + 완화 시도 8 + 추정 호출 9 = 30 번이고, 「경쟁 설계와의 대조」의 전개 입력 값 30 과 같습니다. 큐가 가장 컸을 때 항목은 3 개입니다.

<!--/proof-->

T8 은 꺼내자마자 버린 걸음이라 완화 시도가 0 이고, T9 는 목표를 꺼내 멈춘 걸음이라 역시 0 입니다. 그래서 완화 시도가
확장한 여섯 걸음의 나가는 간선 수를 더한 8 이에요. 큐에 넣기 9 번은 시작 항목 1 개에 값을 고친 완화 8 번을 더한 것이고,
추정 호출도 넣을 때만 부르므로 같은 9 번입니다. 이것을 임의의 그래프로 넓히면 이렇게 됩니다.

| 항 | 횟수 | 근거 |
| --- | --- | --- |
| 이웃 목록 만들기 | `V + E` | 정점마다 빈 목록 하나, 간선마다 넣기 한 번 |
| 완화 시도 | `E` 번 이하 | 추정이 일관되면 정점마다 확장이 한 번이고, 확장이 자기 간선을 한 번씩 읽는다 |
| 추정 호출 · 큐에 넣기 | 각각 `E + 1` 번 이하 | 시작 항목 하나 + 완화가 값을 고친 횟수 |
| 큐에서 꺼내기 | `E + 1` 번 이하 | 넣은 항목보다 많이 꺼낼 수 없다 |
| 힙 안의 비교 | 항목 하나에 `3⌈log2(E + 1)⌉` 번 이하 | 넣기는 높이만큼 한 번씩, 꺼내기는 높이만큼 두 번씩 |

넷을 더하면 시간이 `Θ(V + E) + O(E log E) = O((V + E) log E)` 이고, 메모리는 비용 배열 `Θ(V)` 와 이웃 목록
`Θ(V + E)` 와 우선순위 큐 `O(E)` 를 더한 `O(V + E)` 입니다. 추정이 목표 쪽 항목만 꺼내게 하면 실제 값은 이보다 훨씬
작아요. 추정이 정확한 격자를 키우며 같은 계수를 다시 잽니다.

<!--proof:perf-growth-->

| 격자 | 정점 | 간선 | 넣은 항목 | 완화 시도 | 기본 연산 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 8×8 | 64 | 224 | 39 | 90 | 220 |
| 16×16 | 256 | 960 | 87 | 202 | 494 |
| 32×32 | 1,024 | 3,968 | 183 | 426 | 1,040 |
| 64×64 | 4,096 | 16,128 | 375 | 874 | 2,130 |

한 변을 두 배로 늘릴 때마다 몇 배가 되었는지 나누면 이렇습니다.

| 한 변 | 정점 | 넣은 항목 | 기본 연산 |
| --- | ---: | ---: | ---: |
| 8 → 16 | 4.00 | 2.23 | 2.25 |
| 16 → 32 | 4.00 | 2.10 | 2.11 |
| 32 → 64 | 4.00 | 2.05 | 2.05 |

<!--/proof-->

정점이 네 배가 될 때 넣은 항목과 기본 연산은 두 배 언저리로만 늘어납니다. 확장이 시작과 목표를 잇는 좁은 띠에
머물기 때문이고, 그 띠의 폭이 한 변의 길이를 따라가요.

**여기서 센 것은 기본 연산 셋과 이웃 목록 만들기입니다.** 배열 칸을 읽고 쓰는 횟수와 반복 변수를 올리는 횟수는 세지
않았어요. 둘 다 위 값들에 비례하므로 총식의 차수가 그대로입니다. 추정 함수 안쪽의 비용도 세지 않았습니다. 좌표 뺄셈
두 번이면 상수이고, 표를 뒤지는 추정이면 그만큼이 호출 수에 곱해져요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요. 아래 표는 추정이
일관적일 때의 것입니다.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (시작이 곧 목표) | `O((V + E) log E)` | `Θ(V + E)` — 이웃 목록을 만들고 항목 하나를 꺼낸다 |
| **평균적인 경우** (입력 분포를 정하지 않는다) | `O((V + E) log E)` | 정의하지 않는다 |
| **최악의 경우** (간선 하나하나가 값을 고친다) | `O((V + E) log E)` | `Θ(V + E log E)` — 완전 DAG 에서 실제로 도달한다 |

평균을 정의하지 않는 이유는 **정할 분포가 둘인데 과제가 어느 것도 주지 않기 때문**입니다. 그래프가 어떤 분포에서
오는가와 추정 함수가 어떤 분포에서 오는가예요. 확장한 정점 수 `K` 는 추정의 정확도에 따라 목표로 가는 띠의 폭까지
줄어드는데(32×32 격자에서 추정이 정확하면 `K` 가 123), 그 값은 입력마다 달라 한 식으로 적지 않습니다.

| 경계 | 뜻 | 종류 |
| --- | --- | --- |
| `O((V + E) log E)` | 추정이 일관적이면 연산 수가 그보다 크지 않다 | 상한 |
| `Θ(V + E)` | 이웃 목록을 만드는 데 반드시 드는 값이다 | 타이트한 값 |
| 힙 부분 | 큐에 들어가는 항목 수가 입력과 추정에 따라 갈려 한 값으로 못 적는다 | 상한만 |

**총식을 한 번 정확히 적습니다.** 앞에 붙는 전처리는 이웃 목록 하나뿐이고 정렬도 좌표 압축도 하지 않아요. 추정이
일관될 때 `V + E` 번에 이웃 목록을 만들고, 그 뒤에 완화 시도 `E` 번 이하 · 추정 호출 `E + 1` 번 이하 · 힙 안의 비교
`3(E + 1)⌈log2(E + 1)⌉` 번 이하가 붙습니다.

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없어서, 그래프와 추정이 같으면 연산 수도 언제나 같아요.
다만 이 보장은 **추정이 일관적일 때만** 서요. 허용 가능하기만 한 추정에서는 정점마다 확장이 한 번이라는 것이 성립하지 않아
재확장이 붙고, 32×32 격자에서 확장이 정점 수의 2.50 배까지 갔습니다(아래 「최악을 만드는 입력」). 그 경우의 일반적인
상한은 이 글에서 세우지 않았습니다.

#### 최악을 만드는 입력

**최악을 실제로 구성해 확인합니다.** 「추정이 없을 때가 최악」이라는 말은 물려받은 것이라 값으로 확인하기 전에는
쓰지 않아요. 정점 수를 256 으로 맞춘 모양 여섯을 놓고 무엇이 가장 커지는지 재 봤습니다. 완전 DAG 는 `i → j` 의
가중치를 `2(j−i)−1` 로 두어, 앞 정점을 확장할 때마다 뒤 정점의 값이 1 씩 줄어들게 만든 것이에요.

<!--proof:worst-shape-->

| 배치 | 간선 | 확장 | 그중 재확장 | 넣은 항목 | 큐가 가장 컸을 때 | 기본 연산 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 격자 16×16 · 추정이 정확 | 960 | 59 | 0 | 87 | 28 | 494 |
| 격자 16×16 · 추정이 전부 0 | 960 | 255 | 0 | 256 | 19 | 2,564 |
| 격자 16×16 · 추정 30% | 960 | 262 | 79 | 349 | 98 | 4,118 |
| 사슬 256 · 추정이 정확 | 255 | 255 | 0 | 256 | 1 | 511 |
| 별 256 · 추정이 정확 | 508 | 3 | 0 | 256 | 254 | 772 |
| 완전 DAG 256 · 추정이 정확 | 32,640 | 255 | 0 | 32,641 | 32,386 | 140,913 |

정점이 256 개인 모양 6 개입니다. 확장이 가장 많은 것은 「격자 16×16 · 추정 30%」 로 262 개이고 그중 79 개가 재확장입니다. 넣은 항목이 가장 많은 것은 「완전 DAG 256 · 추정이 정확」 로 32,641 개 — 간선 수 32,640 에 1 을 더한 값 — 이고, 큐가 가장 커지는 것도 「완전 DAG 256 · 추정이 정확」 로 32,386 개입니다. 기본 연산이 가장 많은 것은 「완전 DAG 256 · 추정이 정확」 입니다.

<!--/proof-->

**가장 커지는 것이 하나가 아닙니다.** 확장이 가장 많은 것은 추정을 30% 만 준 격자이고, 넣은 항목 · 큐의 크기 · 기본
연산이 가장 많은 것은 추정이 정확한 완전 DAG 예요. 추정이 정확해도 최악이 나온다는 것을 봐 주세요. 완전 DAG 는 완화가
매번 성공해 항목이 `E + 1` 개로 쌓이는 모양이라, 추정이 목표 쪽을 가리켜도 간선 수만큼의 일은 그대로 남습니다.

| 최악의 모양 | 커지는 것 | 정하는 것 |
| --- | --- | --- |
| 추정을 일부 정점에만 준 격자 | 확장 — 같은 정점을 여러 번 확장한다 | 추정이 일관되지 않은 간선 |
| 완전 DAG | 넣은 항목 · 큐의 크기 · 기본 연산 — 항목이 `E + 1` 개 쌓인다 | 완화가 매번 성공하는 가중치 배치 |

**재확장이 규모에 따라 얼마나 커지는지도 잽니다.** 한 변을 키우며 정보량 비율을 차례로 재고 확장이 가장 많아지는
자리를 골랐어요.

<!--proof:worst-reopen-->

| 격자 | 정점 | 확장이 가장 많은 비율 | 확장 | 그중 재확장 | 확장 ÷ 정점 |
| --- | ---: | --- | ---: | ---: | ---: |
| 8×8 | 64 | 50% | 72 | 17 | 1.13 |
| 16×16 | 256 | 20% | 353 | 98 | 1.38 |
| 32×32 | 1,024 | 30% | 2,555 | 1,591 | 2.50 |
| 64×64 | 4,096 | 30% | 7,717 | 4,832 | 1.88 |

비율 11 가지를 재고 확장이 가장 많은 자리를 골랐습니다. 확장이 정점 수를 넘는 격자가 4 개이고, 가장 큰 배수는 32×32 격자의 2.50 입니다.

<!--/proof-->

**네 규모 모두에서 확장이 정점 수를 넘습니다.** 32×32 격자에서 2.50 배까지 가고, 그 배수가 규모를 따라 한쪽으로만
움직이지 않아요. 「정점마다 확장이 한 번」이라는 보장은 추정이 일관적일 때만 서고, 허용 가능하기만 한 추정에 그
보장을 기대면 위 표만큼 어긋납니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 우선순위 큐의 키를 비용 `g` 가 아니라 **비용과 목표까지의 추정을
더한 `g + h`** 로 두고, 목표를 처음 꺼낼 때 그 비용을 돌려줍니다. 추정이 실제 최소 비용을 넘지 않는 한 답은 다익스트라와
같고, 확장하는 정점이 목표 쪽으로 좁혀져요.

```text
간선 목록 → 이웃 목록 → (src, 0, h(src)) 를 큐에 → 키가 가장 작은 항목을 꺼낸다 → 목표면 돌려준다
                                                    └ 비용 > g[u] 이면 버린다  └ 아니면 완화하고 키 g + h 로 넣는다
```

먼저 답이 붙는 문제 하나입니다. T7 에서 목표 6 의 비용이 이미 16 으로 적혔는데, 왜 그 자리에서 16 을 돌려주지 않고
두 걸음을 더 갔을까요?

<!--proof:selfcheck-t7-->

```text
T7 이 끝난 뒤 큐(꺼낼 차례)  (3, 11, 14) (6, 16, 16) (7, 5, 18)
그때의 g[6]                  16
그때의 g[3]                  8
```

<!--check:whyNotAtT7-->
T7 이 끝난 시점의 큐 맨 앞은 키 14 인 `(3, 11, 14)` 입니다. 키가 16 보다 작은 항목이 남아 있는 동안은, 그 항목에서
목표까지 비용이 16 보다 작은 길이 이어질 수 있다는 가능성을 지울 수 없어요. T8 이 그 항목을 꺼내 보니 비용 11 이 지금의
`g[3] = 8` 보다 커서 뒤처진 기록이었고, 버려졌습니다. 그제야 큐 맨 앞이 목표 항목 `(6, 16, 16)` 이 되고, T9 가 그것을
꺼내 16 을 돌려줍니다.

| 걸음 | 큐 맨 앞 | 목표를 꺼낼 차례 |
| --- | --- | --- |
| T7 이 끝난 뒤 | `(3, 11, 14)` | 아니다 — 키 14 가 16 보다 작다 |
| T8 이 끝난 뒤 | `(6, 16, 16)` | 그렇다 — 남은 키 중 가장 작다 |
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「수행으로 알아보는 알고리즘」의 걸음 표, 셋째 짚고 가기, 「아이디어
상세」의 「넘지 않아야 하는 까닭」을 다시 보세요.

- 전개 입력에서 간선 `0→7` 의 가중치를 5 에서 1 로 바꾸면 정점 7 의 키가 얼마가 되고, T1~T9 가운데 어느 걸음 앞에서
  그 정점이 꺼내질지 먼저 답한 다음 정본을 실행해 맞춰 보세요.
- 셋째 짚고 가기의 일관성이 깨진 추정은 정점 3 에 0, 정점 4 에 11 을 줬습니다. 정점 4 의 추정만 11 에서 5 로
  되돌리면 다시 안 고치는 판의 답이 16 으로 돌아올지, 정점 3 의 0 만으로도 19 가 남을지 먼저 따져 보고 실행해 확인해
  보세요.
- 이 함수가 비용 대신 「최소 비용 경로의 정점 목록」을 돌려주게 하려면 무엇을 더 들어야 할까요? 지금 코드는 어느
  정점에서 왔는지를 안 적습니다. 뒤처진 기록을 버릴 때 그 기록이 남긴 「어디서 왔는가」는 어떻게 되어야 하는지도 함께
  정해 보세요.

### A* 탐색

풀 파일: [`aStarSearch.ts`](./aStarSearch.ts) · 테스트: [`aStarSearch.test.ts`](./aStarSearch.test.ts) · 실행: `bun test src/algorithms/shortest-path/aStarSearch/aStarSearch.test.ts`

#### 한 줄 요약

> 함수는 그래프, 시작 정점, 목표 정점, 휴리스틱 함수를 받아 시작에서 목표까지의 최단 경로 비용을 반환한다.

#### 스토리

지도 앱 개발자 지수는 수백만 개의 교차로가 이어진 도시 지도에서 경로를 탐색하는 기능을 만들고 있다. 문제는 교차로 수가 너무 많아서 모든 경로를 탐색하면 시간이 너무 오래 걸린다는 것이다.

지수는 목적지까지의 직선 거리를 미리 알 수 있다면 탐색 방향을 목적지 쪽으로 집중할 수 있다는 아이디어를 떠올렸다. "현재까지 이동한 실제 거리"와 "여기서 목적지까지 추정 거리"를 합산해 우선순위를 정하면 불필요한 방향은 탐색하지 않아도 된다.

단, 이 추정값은 실제 거리를 절대 초과해서는 안 된다. 과대평가를 하면 정작 최단 경로를 놓칠 수 있기 때문이다. 추정값이 정확할수록 탐색 속도가 빨라지고, 추정값이 항상 0이면 모든 방향을 균등하게 탐색하는 기존 방식과 동일해진다.

#### 함수 인터페이스

```ts
export function aStarSearch(
  n: number,
  edges: [number, number, number][],
  src: number,
  goal: number,
  h: (v: number) => number,
): number;
```

- `n` — 정점 수. 정점 번호는 $0$부터 $n - 1$.
- `edges` — 방향 간선 목록. 각 원소는 $[u, v, w]$ 형태이며 가중치 $w \geq 0$인 방향 간선 $u \to v$.
- `src` — 시작 정점 번호.
- `goal` — 목표 정점 번호.
- `h` — 휴리스틱 함수. `h(v)`는 정점 $v$에서 목표 정점까지의 추정 비용. admissible 조건 $0 \leq h(v) \leq d(v, \text{goal})$을 만족한다고 보장된다.
- 반환 — $\text{src} \to \text{goal}$의 최단 경로 비용. 도달할 수 없으면 `Infinity`.

#### 제약 조건

- $1 \leq V \leq 10^5$ (정점 수)
- $0 \leq E \leq 2 \cdot 10^5$ (간선 수)
- $0 \leq w(u, v) \leq 10^9$ (가중치; 음수 없음)
- $0 \leq h(v) \leq d(v, \text{goal})$ (admissible 휴리스틱)
- $0 \leq \text{src}, \text{goal} < V$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

가중치가 음수가 아닌 방향 그래프 $G = (V, E)$가 주어진다. 시작 정점 $\text{src}$에서 목표 정점 $\text{goal}$까지의 최단 경로 비용을 구하라.

각 정점 $v$에는 admissible 휴리스틱 $h(v)$가 제공된다. $h(v)$는 $v$에서 $\text{goal}$까지의 실제 최단 거리를 절대 초과하지 않는다. $h \equiv 0$으로 설정하면 일반 단일 출발지 최단 경로 탐색과 동일하게 동작해야 한다.

- $\text{src} = \text{goal}$이면 경로 비용은 $0$이다.
- 목표 정점에 도달할 수 없으면 `Infinity`를 반환한다.
- 동일한 두 정점 사이에 다중 간선이 있으면 모두 고려해야 한다.

#### 예시

```ts
// 정점 5개, 0 → 4로 가는 최단 경로
const edges: [number, number, number][] = [
  [0, 1, 1],
  [0, 2, 4],
  [1, 2, 2],
  [1, 3, 5],
  [2, 3, 1],
  [3, 4, 3],
];
aStarSearch(5, edges, 0, 4, () => 0); // 7 — 0→1→2→3→4 비용 합산

// src === goal이면 비용은 항상 0
aStarSearch(3, [[0, 1, 10]], 1, 1, () => 0); // 0 — 출발지와 목적지 동일

// 도달 불가능한 목표
aStarSearch(3, [[0, 1, 2]], 0, 2, () => 0); // Infinity — 정점 2로 가는 간선 없음

// admissible 휴리스틱 사용 (남은 정점 수로 추정)
const edgesLinear: [number, number, number][] = [
  [0, 1, 1],
  [1, 2, 1],
  [2, 3, 1],
  [0, 2, 10],
];
aStarSearch(4, edgesLinear, 0, 3, (v) => Math.max(0, 3 - v)); // 3 — 0→1→2→3 비용 합산
```
