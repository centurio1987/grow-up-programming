# 플로이드-워셜 — 경유해도 되는 정점을 번호 순으로 하나씩 늘리면 거리 행렬 하나에서 모든 쌍의 최단 거리가 함께 나오는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 경로를 전부
나열하는 방법에서 출발해, 중간에 거쳐도 되는 정점을 번호 순으로 하나씩 늘려 가는 방법까지 갑니다. 그 방법을
준비되는 차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

간선마다 수가 하나씩 붙은 방향 그래프를 생각해 봅시다. 간선에 붙은 수를 **가중치**라고 부르고, 경로 하나의
**비용**은 그 경로가 지나는 간선의 가중치를 모두 더한 값입니다. `u` 에서 `v` 로 가는 경로 가운데 비용이 가장
작은 것의 비용이 `u` 에서 `v` 까지의 **최단 거리**예요. 이 글이 구하는 것은 출발점 하나의 최단 거리가 아니라
**모든 정점 쌍**의 최단 거리이고, 가중치에는 음수가 섞일 수 있습니다. 정점 다섯 · 간선 일곱인 그래프로
시작합니다.

<!--fig:concept-graph-->
![전개 입력 — 정점 다섯 · 간선 일곱, 간선 옆 수는 가중치](./figs/concept-graph.svg)

`0 → 1` 은 가중치 3 과 4 인 간선이 두 개 있고, `1 → 2` 는 가중치가 음수입니다. 정점 4 는 나가는 간선만 있고
들어오는 간선이 없어요. 모든 쌍의 답은 `V × V` 칸짜리 2 차원 배열 하나에 담깁니다. 줄 `u` · 열 `v` 칸에
`u` 에서 `v` 까지의 최단 거리를 적은 이 배열을 **거리 행렬**(distance matrix)이라고 부르고, 코드에서는 `dist`
로 적습니다. 갈 길이 없는 칸에는 `INF`(코드의 `Number.POSITIVE_INFINITY`)를 적어요.

<!--fig:concept-matrix-->
![답인 거리 행렬 — 칸 (u, v) 는 u 에서 v 로 가는 최단 거리, 점선 칸은 INF](./figs/concept-matrix.svg)

줄 3 · 열 0 칸을 읽으면 정점 3 에서 정점 0 까지의 최단 거리입니다. 열 4 가 통째로 점선인 것은 어느 정점도
정점 4 로 갈 수 없기 때문이에요. 이 절차는 거리 행렬을 간선만으로 채워 둔 뒤 칸을 계속 줄여 갑니다. 줄이는
방법은 하나뿐입니다. 경로의 양 끝이 아닌 정점, 곧 경로가 지나가는 정점을 **중간 정점**이라고 부르는데, 정점
`k` 를 중간에 두는 길 `u → … → k → … → v` 의 비용 `dist[u][k] + dist[k][v]` 가 지금 적힌 `dist[u][v]` 보다
작으면 그 값으로 고쳐요. 더 짧은 길을 찾았을 때 값을 고쳐 적는 이 일을 **완화**라고 합니다.

<!--fig:concept-relax-->
![라운드 2 가 칸 (3, 0) 을 완화 — dist[3][2] + dist[2][0] 이 INF 보다 작다](./figs/concept-relax.svg)

테를 두른 두 칸 `(3, 2)` 와 `(2, 0)` 을 읽어 더한 값이 강조한 칸 `(3, 0)` 에 들어갔습니다. 이 절차는 중간에 둘
정점 `k` 를 **번호 순으로 하나씩** 정합니다. 정점 `k` 하나를 정해 모든 칸을 한 번씩 완화하는 일을 **라운드
`k`** 라고 부르고, `k = 0` 부터 `k = V − 1` 까지 라운드를 한 번씩 합니다. 라운드 `k` 가 끝나면 중간 정점으로
`0` 부터 `k` 까지를 쓸 수 있게 된 거예요.

<!--proof:conceptRounds-->

| 라운드 k | 중간에 쓸 수 있는 정점 | 고친 칸 |
| ---: | --- | --- |
| 0 | 0 | (2, 1) → 8 |
| 1 | 0 · 1 | (0, 2) → 1 · (3, 2) → -1 |
| 2 | 0 · 1 · 2 | (0, 3) → 4 · (1, 0) → 3 · (1, 3) → 1 · (3, 0) → 4 |
| 3 | 0 · 1 · 2 · 3 | (2, 1) → 4 · (4, 0) → 6 · (4, 1) → 3 · (4, 2) → 1 |
| 4 | 0 · 1 · 2 · 3 · 4 | 없음 |

라운드 5 번이 고친 칸은 모두 11 개이고, 한 칸도 못 고친 라운드는 4 입니다. 마지막 라운드가 끝난 거리 행렬은 정본이 돌려준 답과 칸마다 같습니다.

<!--/proof-->

라운드 3 이 칸 `(2, 1)` 을 8 에서 4 로 한 번 더 줄였다는 것을 봐 주세요. 라운드 0 에서는 중간 정점으로 0
만 쓸 수 있어 `2 → 0 → 1` 이 최선이었는데, 라운드 3 에서 3 을 쓸 수 있게 되자 `2 → 3 → 1` 이 후보에 들어온
것입니다. 한 가지 전제가 있어요. 가중치의 합이 0 보다 작은 순환, 곧 **음수 사이클**이 있으면 그 순환을 돌 때마다
비용이 줄어 최단 거리가 정해지지 않습니다. 이 글은 음수 사이클이 없는 그래프를 다룹니다. 할 일을 나누어 보면
이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 거리 행렬 만들기 | 대각선에 0, 간선 칸에 가중치, 나머지에 `INF` 를 적는다 | 칸마다 한 번 · 간선마다 한 번 |
| 라운드 하나 | 정점 `k` 를 중간에 두는 후보로 모든 칸을 완화한다 | 칸마다 한 번 |
| 라운드 되풀이 | `k = 0` 부터 `V − 1` 까지 | 라운드 `V` 번 |
| 모두 | | `O(V³)` — `V` 는 정점 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **완화.** 더 짧은 길을 찾았을 때만 적힌 거리를 고치는 연산입니다. 한 번 적은 거리를 왜 다시 고치는지, 적힌
  값이 늘 실재하는 경로의 비용인 까닭은 [`dijkstra`](../dijkstra/dijkstra-guide.md) 의 「먼저 알아 둘 개념 —
  완화」가 자세히 다룹니다.
- **출발점 하나의 최단 거리와 음수 가중치.** 가중치에 음수가 있을 때 출발점 하나의 최단 거리를 구하는 절차가
  [`bellmanFord`](../bellmanFord/bellmanFord-guide.md) 입니다. 이 글은 그 절차를 출발점마다 되풀이하는 방법에서
  출발하고, 그 편의 「간선을 k 개 이하로 쓰는 최단 비용」과 이 글의 층을 나란히 놓아 봅니다.
- **인접 행렬.** 간선 목록을 `V × V` 배열로 옮겨 적은 것입니다. 거리 행렬이 그 배열에서 시작해요. 자료구조가
  궁금하면 [`graphAdjMatrix` 가이드](../../../data-structures/graph-repr/graphAdjMatrix/graphAdjMatrix-guide.mdx)
  를 보세요.
- **단순 경로와 순환.** 같은 정점을 두 번 지나지 않는 경로가 단순 경로이고, 출발한 정점으로 되돌아오는 경로가
  순환입니다. 음수 사이클이 없으면 최단 경로를 단순 경로 가운데서 고를 수 있어요.
- **`INF` 와의 덧셈과 비교.** `INF + w` 는 `INF` 이고 `INF < INF` 는 거짓입니다. 그래서 「길이 없다」가 덧셈에
  섞여도 값을 잘못 고치는 일이 생기지 않아요.

이름이 비슷한 과제 넷을 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 그래프 | 이 글에서 |
| --- | --- | --- |
| 모든 정점 쌍의 최단 거리 | 음수 가중치가 있어도 된다 · 음수 사이클은 없다 | 다룬다 |
| 출발점 하나에서 모든 정점까지의 최단 거리와 음수 사이클 판정 | 음수 가중치가 있어도 된다 | 다루지 않는다 — [`bellmanFord`](../bellmanFord/bellmanFord-guide.md) |
| 출발점 하나에서 모든 정점까지의 최단 거리 | 가중치가 0 이상 | 다루지 않는다 — [`dijkstra`](../dijkstra/dijkstra-guide.md) |
| 출발점 하나에서 간선을 가장 적게 지나는 거리 | 가중치가 없다 | 다루지 않는다 — [`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) |

### 아이디어를 떠올리는 과정 — 경로 전부 나열하기에서 경유 정점을 번호 순으로 넓히기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아서 거리
행렬을 돌려줍니다.

```ts
function floydWarshall(
  n: number,
  edges: [number, number, number][],
): number[][];
```

- 입력: 정점 수 `n` 과 원소가 `[u, v, w]` 인 방향 간선 목록 `edges`. 정점 번호는 `0` 부터 `n − 1` 이고, 가중치
  `w` 는 음수일 수 있습니다. 같은 방향 간선이 여럿일 수 있고, 음수 사이클은 없습니다.
- 출력: `n × n` 거리 행렬. `dist[u][v]` 가 `u → v` 최단 거리이고, 갈 수 없으면 `INF`, `dist[v][v]` 는 0 입니다.
- 규모: `1 ≤ V ≤ 500`, `0 ≤ E ≤ V(V−1)`, `−10^6 ≤ w ≤ 10^6`. 두 값 다 이 글이 정한 것이에요. 정점 수 500 은
  뒤에서 만들 절차의 비용이 `V³` 에 달려 있어서, 그 값이 흔한 채점 환경의 예산인 1 초(단순 연산 1 억 번 기준)
  언저리에 머무는 수로 골랐습니다. 메모리는 같은 환경의 예산 256 MB 에 대어 잽니다.

이 글이 쓰는 기호는 여덟 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점의 개수. 코드의 `n` 입니다 | `1 ≤ V ≤ 500` |
| `E` | 간선의 개수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ V(V−1)` |
| `u` · `v` | 경로의 출발 정점과 도착 정점. 거리 행렬의 줄 번호와 열 번호입니다 | `0` 부터 `V−1` |
| `k` | 라운드의 번호이자 그 라운드에 중간에 두는 정점 | `0` 부터 `V−1` |
| `w` | 간선 하나의 가중치 | `−10^6 ≤ w ≤ 10^6` |
| `dist[u][v]` | 거리 행렬의 칸. 코드가 지금 들고 있는 `u → v` 의 값입니다 | `V × V` 칸 |
| `opt_k(u, v)` | 중간 정점을 `0` 부터 `k` 까지만 쓰는 `u → v` 최단 비용. 정의는 「아이디어 상세」가 값으로 풉니다 | `k = −1` 이면 중간 정점을 안 쓴다 |
| `INF` | 아직 이어지는 길을 못 찾은 칸의 값 | 어떤 유한한 거리보다 크다 |

`u` · `v` 와 `k` 를 가르는 것이 이 글의 뼈대입니다. 앞의 둘은 **경로의 양 끝**이고 `k` 는 **경로의 중간**이에요.
비용은 이 글 끝까지 **기본 연산**으로 셉니다. 거리 행렬이나 거리 배열의 칸 하나를 채운 것, 간선 하나를 읽은
것, 행을 건너뛸지 판정한 것, 후보 하나를 비교한 것을 각각 한 번으로 세는 기준이에요. 가장 먼저 떠오르는 방법은
정의를 그대로 옮기는 것입니다. 정점 쌍마다 **단순 경로를 전부 만들어** 가장 작은 비용을 고르면 음수 가중치가
있어도 답이 맞아요. 간선이 가장 많은 그래프에서 그 경로가 몇 개인지 세었습니다.

<!--proof:naiveScale-->

| 정점 V | 간선 E | 단순 경로 수 (모든 쌍) | 센 방법 |
| ---: | ---: | --- | --- |
| 4 | 12 | 60 | 실행 |
| 6 | 30 | 1,950 | 실행 |
| 8 | 56 | 109,592 | 실행 |
| 10 | 90 | 9,864,090 | 식 |
| 500 | 249,500 | 1,135 자리 수 | 식 |

간선은 모든 순서쌍에 하나씩 둔 그래프입니다. 정점 4 · 6 · 8 은 경로를 실제로 따라가 셌고, 같은 수를 낸 식으로 정점 10 과 500 을 셌습니다.

<!--/proof-->

정점 열 개에서 벌써 천만 개에 가깝고, 규모의 상한에서는 경로 수가 천 자리를 넘습니다. 경로를 하나하나 고르는
대신 **쌍마다 값 하나를 들고 고쳐 가야** 해요. 그 방법을 이미 하나 알고 있습니다. 출발점 하나의 최단 거리는
`bellmanFord` 가 음수 가중치가 있어도 구하니, 그것을 출발점마다 한 번씩 부르면 됩니다.

```ts
const dist: number[][] = [];
for (let s = 0; s < n; s++) {
  dist.push(bellmanFord(n, edges, s).dist);   // 출발점 하나의 거리 배열
}
```

간선이 가장 많은 그래프에서 이 방법의 기본 연산을 세었습니다. 한 라운드가 한 칸도 못 고치면 그 출발점을 일찍
끝내는 판을 실제로 실행한 값과, 출발점마다 라운드를 `V − 1` 번 다 채울 때의 상한을 나란히 놓았어요.

<!--proof:perSource-->

| 정점 V | 간선 E | 실행한 기본 연산 | 라운드를 다 채운 상한 |
| ---: | ---: | ---: | ---: |
| 10 | 90 | 3,340 | 8,200 |
| 50 | 2,450 | 585,600 | 6,005,000 |
| 200 | 39,800 | 68,814,400 | 1,584,080,000 |
| 500 | 249,500 | 794,159,000 | 62,250,500,000 |

정점 500 에서 실행한 기본 연산은 794,159,000 번이고, 출발점마다 라운드를 V − 1 번 다 채우는 입력이면 62,250,500,000 번입니다.

<!--/proof-->

실행한 값만 해도 초당 1 억 번 기준으로 1 초를 넘고, 상한은 그 수십 배입니다. 어디서 일이 늘어나는지
전개 입력에서 세어 봅시다. 출발점 다섯을 따로 계산하면서 간선마다 몇 번 읽었고 그중 몇 번 값을 고쳤는지
나눴어요.

<!--proof:repeatObserved-->

| 간선 | 읽은 횟수 | 값을 고친 횟수 | 못 고친 횟수 |
| --- | ---: | ---: | ---: |
| 0 → 1 (3) | 13 | 1 | 12 |
| 0 → 1 (4) | 13 | 0 | 13 |
| 1 → 2 (-2) | 13 | 4 | 9 |
| 2 → 0 (5) | 13 | 4 | 9 |
| 2 → 3 (3) | 13 | 3 | 10 |
| 3 → 1 (1) | 13 | 3 | 10 |
| 4 → 3 (2) | 13 | 1 | 12 |

출발점 5 개를 따로 계산하면 간선을 모두 91 번 읽고, 그중 값을 고친 것은 16 번입니다.

<!--/proof-->

모든 간선을 출발점마다 몇 라운드씩 다시 읽는데, 값을 고친 것은 그중 일부입니다. 간선 `1 → 2` 는 네 번 값을
고쳤는데 그 네 번은 출발점이 서로 달라요. 출발점 0 의 경로 `0 → 1 → 2 → 3` 과 출발점 3 의 경로 `3 → 1 → 2 → 0`
은 「1 에서 2 까지」라는 같은 토막을 쓰지만, 출발점을 따로 계산하는 한 그 토막을 매번 처음부터 다시 찾습니다.
그러면 **모든 쌍을 거리 행렬 하나에 담고 함께 채우면** 한 번 찾은 토막을 모든 출발점이 읽을 수 있어요. 이 글이
만들 절차가 그렇게 합니다. 같은 입력을 두 방식으로 처리해 기본 연산을 나란히 놓았습니다.

<!--proof:twoWays-->

| 입력 | 정점 | 간선 | 출발점마다 벨만-포드 | 거리 행렬 하나를 함께 채우기 | 적은 쪽 |
| --- | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 5 | 7 | 116 | 137 | 출발점마다 |
| 사이클 그래프 | 20 | 20 | 1,560 | 5,400 | 출발점마다 |
| 성긴 그래프 | 60 | 180 | 58,320 | 97,320 | 출발점마다 |
| 촘촘한 그래프 | 60 | 3,540 | 1,058,520 | 226,740 | 함께 채우기 |

4 개 입력 모두에서 두 방식이 낸 거리 행렬은 칸마다 같습니다.

<!--/proof-->

**갈리는 자리는 간선의 밀도입니다.** 간선이 적으면 출발점마다 따로 하는 쪽이 적고, 간선이 정점 수의 제곱에
가까우면 함께 채우는 쪽이 적어요. 앞쪽의 비용은 간선 수 `E` 에 붙고 뒤쪽은 칸 수 `V²` 에 붙기 때문입니다.
규모의 상한은 `E` 가 `V(V−1)` 까지 가니, 함께 채우는 방법을 정확한 규칙으로 바꿔 봅시다. 가장 단순한 후보는
「모든 칸에 모든 `k` 를 한 번씩 넣어 `dist[u][k] + dist[k][v]` 가 작으면 고친다」, 곧 **경유를 한 번만 허용**하는
것이에요. 간선 두 개짜리 길까지만 보는 셈입니다.

<!--proof:oneRoundCheck-->

| 출발 u | 경유를 한 번만 허용한 행 | 정본의 행 | 비교 |
| ---: | --- | --- | --- |
| 0 | 0 3 1 INF INF | 0 3 1 4 INF | 다르다 |
| 1 | 3 0 -2 1 INF | 3 0 -2 1 INF | 같다 |
| 2 | 5 4 0 3 INF | 5 4 0 3 INF | 같다 |
| 3 | INF 1 -1 0 INF | 4 1 -1 0 INF | 다르다 |
| 4 | INF 3 INF 2 0 | 6 3 1 2 0 | 다르다 |

다른 칸은 4 개이고, 칸마다 경유를 한 번만 허용한 값 → 정본의 값은 (0, 3) INF → 4 · (3, 0) INF → 4 · (4, 0) INF → 6 · (4, 2) INF → 1 입니다.

<!--/proof-->

**네 칸이 틀립니다.** 칸 `(4, 0)` 의 진짜 최단 경로는 `4 → 3 → 1 → 2 → 0` 이라 중간 정점이 셋인데, 경유를 한
번만 허용하면 `4 → x → 0` 꼴만 봅니다. 그러니 허용을 넓혀야 하고, 넓히는 축은 둘이에요. **경유 횟수**를 넓히는
축은 거리 행렬끼리 더하기와 최솟값으로 곱해 간선 수 한도를 1 · 2 · 4 … 로 배씩 늘립니다. **경유 정점의 번호**를
넓히는 축은 중간에 쓸 수 있는 정점을 `{0}` → `{0, 1}` → `{0, 1, 2}` … 로 하나씩 늘리며 거리 행렬을 제자리에서
고쳐요. 둘 다 답은 맞으니 같은 입력에서 기본 연산을 쟀습니다.

<!--proof:widenWays-->

| 정점 V | 거리 행렬 곱 | 경유 횟수를 배로 늘리기 | 경유 정점 번호를 하나씩 넓히기 | 앞의 것 ÷ 뒤의 것 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 3 | 1,848 | 696 | 2.66 배 |
| 16 | 4 | 17,904 | 4,848 | 3.69 배 |
| 32 | 5 | 170,976 | 35,808 | 4.77 배 |
| 64 | 6 | 1,605,568 | 274,368 | 5.85 배 |
| 128 | 7 | 14,827,392 | 2,146,176 | 6.91 배 |

간선은 모든 순서쌍에 둔 그래프이고, 5 개 규모 모두에서 두 방법이 낸 거리 행렬은 칸마다 같습니다.

<!--/proof-->

번호를 하나씩 넓히는 쪽이 적고, 그 차이가 규모를 따라 커집니다. 앞의 축은 곱 한 번이 칸마다 가운데 정점 `V`
개를 비교해 `V³` 이고 그 곱을 `log V` 번 하지만, 뒤의 축은 라운드 하나가 칸마다 후보 하나만 비교해 `V²` 이고
그 라운드를 `V` 번 합니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다. 앞 방법이 막힌 자리에서 다음 방법이
나왔어요.

<!--fig:origin-approaches-->
![시도한 방법 다섯 — 넷은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **경유 정점을 번호 순으로 넓히기**입니다. 라운드 `k` 에서 정점 `k` 를 중간에 둘 수
있게 하고, 모든 칸을 그 후보 하나로 완화해요. 왜 후보 하나로 충분한지, 거리 행렬 하나를 제자리에서 고쳐도 되는지는
다음 절에서 값으로 확인합니다.

### 아이디어 상세 — 경유 정점을 번호 순으로 넓히기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **거리 행렬을 간선으로 채운 뒤, `k = 0` 부터 `V − 1` 까지 라운드마다
모든 칸 `(u, v)` 를 `dist[u][k] + dist[k][v]` 로 완화합니다.** 이 방법은 「라운드 `k` 가 끝나면 중간 정점을
`0..k` 만 쓰는 경로까지 다 반영돼 있다」는 성질 위에서 동작하는데, 그 「중간 정점을 `0..k` 만 쓰는 최단 비용」이
처음 보면 낯설어요. 그래서 그것을 먼저 따로 설명하고, 그다음 실현하는 순서대로 세 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 거리 행렬을 층 -1 로 채우기 | 대각선 0 · 간선 칸에 가장 작은 가중치 · 나머지 `INF` | — |
| 라운드마다 | 2단계 경유 정점 k 하나로 모든 칸 완화하기 | `k` 행과 `k` 열을 읽어 모든 칸의 후보를 만든다 | 1단계 또는 앞 라운드의 거리 행렬 |
| 라운드 사이 | 3단계 k 를 0 부터 V−1 까지 올리기 | 라운드를 번호 순으로 되풀이하고 마지막 거리 행렬을 돌려준다 | 2단계가 고친 거리 행렬 |

#### 먼저 알아 둘 개념 — 중간 정점을 0..k 만 쓰는 최단 비용

**중간 정점을 `0..k` 만 쓰는 최단 비용**은 `u` 에서 `v` 로 가는 경로 가운데 **중간 정점의 번호가 모두 `k`
이하인 것들** 중에서 가장 작은 비용입니다. 이 글은 그 값을 `opt_k(u, v)` 로 적어요. 그런 경로가 하나도 없으면
`INF` 이고, `k = −1` 이면 중간 정점을 하나도 쓰지 않으니 빈 경로와 간선 하나짜리 경로만 남습니다. 칸마다 값
하나씩, `k` 마다 `V × V` 한 벌이 생기므로 이 글은 `k` 번째 벌을 **층 `k`** 라고 부릅니다.

##### 입력 위의 층

전개 입력에서 층 -1 부터 층 4 까지를 그렸습니다. 칸의 값이 그 층의 `opt_k(u, v)` 이고, 강조한 칸은 앞 층보다 값이
줄어든 칸이에요. 테를 두른 칸은 `k` 행과 `k` 열입니다.

<!--fig:build-layers-->
![층 k = -1 … 4 — 칸 (u, v) 는 중간 정점을 0..k 만 쓰는 최단 비용](./figs/build-layers.svg)

층마다 값이 있는 칸과 줄어든 칸을 세면 이렇습니다.

<!--proof:layerChanges-->

| 층 k | 중간에 쓸 수 있는 정점 | 값이 있는 칸 | 앞 층보다 줄어든 칸 |
| ---: | --- | ---: | ---: |
| -1 | 없음 | 11 | — |
| 0 | 0 | 12 | 1 |
| 1 | 0 · 1 | 14 | 2 |
| 2 | 0 · 1 · 2 | 18 | 4 |
| 3 | 0 · 1 · 2 · 3 | 21 | 4 |
| 4 | 0 · 1 · 2 · 3 · 4 | 21 | 0 |

층 4 는 정본이 돌려준 답과 25 칸 가운데 25 칸이 같습니다.

<!--/proof-->

층이 오를수록 값이 있는 칸이 늘고, 있던 값은 같거나 작아집니다. 층 `k` 는 층 `k−1` 이 쓸 수 있던 경로를 모두
쓸 수 있고 정점 `k` 를 지나는 경로까지 후보로 받기 때문이에요. 층 3 에서 줄 4 가 처음 채워진 것은 정점 4 에서
나가는 유일한 간선이 `4 → 3` 이라 3 을 중간에 쓸 수 있어야 어디로든 가기 때문입니다.

##### 칸 하나를 읽는 법

칸 `(2, 1)` 을 골라 이름에서 경로까지 따라가 봅시다. `opt_k(2, 1)` 은 「정점 2 에서 정점 1 로 가는 경로 중 중간
정점의 번호가 모두 `k` 이하인 것들의 가장 작은 비용」입니다. 정점 2 에서 1 로 가는 단순 경로를 전부 놓고 중간
정점으로 거르면 이렇게 나와요.

<!--proof:layerRead-->

| 경로 | 중간 정점 | 비용 | 후보에 드는 층 |
| --- | --- | ---: | --- |
| 2→0→1 | 0 | 8 | 층 0 부터 |
| 2→3→1 | 3 | 4 | 층 3 부터 |

정의대로 계산한 opt_k(2, 1) 의 값은 층 -1 INF · 층 0 8 · 층 1 8 · 층 2 8 · 층 3 4 · 층 4 4 입니다.

<!--/proof-->

경로 `2→0→1` 의 중간 정점은 0 하나라 층 0 부터 후보에 들고, `2→3→1` 의 중간 정점은 3 이라 층 3 부터 듭니다.
그래서 칸 `(2, 1)` 은 층 -1 에서 `INF`, 층 0 · 1 · 2 에서 8, 층 3 부터 4 예요. 경로가 후보에 드는 층은 **중간
정점 가운데 가장 큰 번호**가 정합니다.

##### 층과 층 사이

층 `k` 의 칸은 층 `k−1` 만 보고 만들 수 있습니다. 중간 정점을 `0..k` 만 쓰는 최단 경로는 정점 `k` 를 **안 쓰거나
한 번 씁니다.** 음수 사이클이 없으면 최단 경로를 단순 경로에서 고를 수 있어 `k` 를 두 번 지날 일이 없기 때문이에요.
안 쓰면 그 비용은 `opt_{k−1}(u, v)` 이고, 쓰면 경로를 `k` 에서 끊은 앞 토막 `u → … → k` 와 뒤 토막 `k → … → v`
는 각각 중간 정점이 `0..k−1` 뿐이라 `opt_{k−1}(u, k) + opt_{k−1}(k, v)` 입니다. 칸 `(3, 0)` 의 층 2 값을 층 1
에서 만들어 봅니다.

<!--proof:layerStep-->

| 후보 | 식 | 값 |
| --- | --- | --- |
| 정점 2 를 안 쓴다 | opt_1(3, 0) | INF |
| 정점 2 에서 끊는다 | opt_1(3, 2) + opt_1(2, 0) | -1 + 5 = 4 |

두 후보 가운데 작은 값이 4 이고, 정의대로 계산한 opt_2(3, 0) 도 4 입니다.

<!--/proof-->

둘째 후보가 **완화 하나**와 같은 모양입니다. `k` 열의 칸과 `k` 행의 칸을 더해 지금 칸과 비교하고 작은 쪽을
남겨요. 그래서 거리 행렬의 모든 칸을 한 번씩 이렇게 완화하면 층 하나를 올리는 일이 됩니다. 그리고 후보는 칸마다
**딱 둘**입니다. 가운데 정점을 모두 따져 볼 필요가 없어요.

##### 간선 수로 자른 층과의 차이

층을 처음 보면 `bellmanFord` 의 층, 곧 「간선을 몇 개 이하로 쓰는 최단 비용」과 같은 것으로 읽기 쉽습니다. 층
`k` 는 중간 정점을 많아야 `k + 1` 개 쓰니 간선을 `k + 2` 개 이하로 쓰는 경로예요. 두 층을 같은 입력에서
나란히 놓았습니다.

<!--proof:layerVsEdges-->

| 층 k | 간선 수 한도 | 값이 다른 칸 | 층 k 쪽이 더 작은 칸 |
| ---: | ---: | ---: | ---: |
| 0 | 2 | 6 | 0 |
| 1 | 3 | 7 | 0 |
| 2 | 4 | 4 | 0 |
| 3 | 5 | 0 | 0 |

층 0 에서 칸 (0, 2) 는 INF 인데 간선 2 개 이하로 자른 값은 1 입니다. 층 k 쪽이 더 작은 칸은 4 줄을 합쳐 0 개입니다.

<!--/proof-->

간선 수로 자른 쪽은 중간 정점의 **번호를 가리지 않으므로** 같거나 더 작고, 층 `k` 쪽이 더 작은 칸은 하나도
없습니다. 층 0 의 칸 `(0, 2)` 는 경로 `0 → 1 → 2` 가 중간 정점 1 을 써서 아직 후보가 아니에요. 두 층은 서로
다른 것이고, 그 차이가 비용을 가릅니다.

| 층을 하나 올리는 일 | 칸 하나의 후보 | 층 하나의 후보 비교 | 필요한 층 수 |
| --- | --- | --- | --- |
| 간선 수 한도를 두 배로 — 거리 행렬끼리 곱한다 | 가운데 정점마다 하나 | `V³` | `log V` 안팎 |
| 중간 정점을 하나 더 허용한다 — 층 `k` | 지금 값 · `k` 에서 끊은 값 | `V²` | `V` |

##### 층이 이렇게 생긴 까닭

아이디어가 요구하는 것은 **층 하나를 적은 비용으로 올리는 것**과 **마지막 층이 답인 것** 둘입니다. 중간 정점을 번호로
허용하면 새로 허용한 정점 `k` 에서 경로를 한 번만 끊으면 되니 칸마다 후보가 둘이고, 층 `V−1` 에서는 모든 정점을
중간에 쓸 수 있어 제한이 없어져요. 앞의 층 표에서 층 4 가 정본의 답과 칸마다 같았던 것이 그 뜻입니다.

| 층의 성질 | 까닭 | 이 절차에서 쓰이는 곳 |
| --- | --- | --- |
| 층 `k` 는 층 `k−1` 보다 크지 않다 | 후보가 늘기만 한다 | 라운드가 값을 줄이기만 한다 |
| 층 `k` 는 층 `k−1` 과 완화 한 벌로 만든다 | `k` 를 쓰는 경로는 `k` 에서 끊은 두 토막이다 | 라운드 하나가 층 하나를 올린다 |
| 층 `V−1` 이 답이다 | 중간 정점의 제한이 없어진다 | 마지막 라운드의 거리 행렬을 돌려준다 |

#### 1단계 — 거리 행렬을 층 -1 로 채우기

거리 행렬의 대각선에 0 을 적고, 간선 `u → v` 마다 칸 `(u, v)` 에 가중치를 적되 이미 더 작은 값이 있으면 그대로
둡니다. 나머지 칸은 `INF` 예요. 이 거리 행렬이 곧 층 -1 입니다. 중간 정점을 안 쓰는 경로는 빈 경로와 간선 하나짜리
경로뿐이기 때문이에요.

<!--proof:stageStart-->

| 출발 u | v = 0 | v = 1 | v = 2 | v = 3 | v = 4 |
| --- | ---: | ---: | ---: | ---: | ---: |
| u = 0 | 0 | 3 | INF | INF | INF |
| u = 1 | INF | 0 | -2 | INF | INF |
| u = 2 | 5 | INF | 0 | 3 | INF |
| u = 3 | INF | 1 | INF | 0 | INF |
| u = 4 | INF | INF | INF | 2 | 0 |

값이 있는 칸은 11 개이고 나머지 14 칸은 INF 입니다. 간선 0 → 1 은 가중치 3 · 4 로 둘이라 3 만 남았고, 이 거리 행렬은 층 -1 과 25 칸이 같습니다.

<!--/proof-->

대각선의 0 은 **간선을 하나도 안 쓰는 빈 경로**입니다. 자리를 채운 것이 아니라 뒤에서 쓰이는 값이에요. 라운드
`k` 가 줄 `k` 를 완화할 때 후보가 `dist[k][k] + dist[k][v] = 0 + dist[k][v]` 가 되어 값을 그대로 두는 것이 그
덕분입니다.

#### 2단계 — 경유 정점 k 하나로 모든 칸 완화하기

라운드 `k` 는 줄 `u` 마다 `dist[u][k]` 를 먼저 봅니다. `INF` 면 `u` 에서 `k` 로 가는 길이 없으니 `k` 를 지나는
`u → v` 경로도 없어 그 줄을 통째로 건너뛰어요. 아니면 열 `v` 마다 후보 `dist[u][k] + dist[k][v]` 를 만들어 지금
값보다 작을 때 고칩니다. 전개 입력의 라운드 2 를 줄마다 적었습니다.

<!--proof:stageRound-->

| 행 u | dist[u][2] | 그 행 | 고친 칸 |
| ---: | ---: | --- | --- |
| 0 | 1 | 들어간다 | (0, 3) = 1 + 3 = 4 < INF |
| 1 | -2 | 들어간다 | (1, 0) = -2 + 5 = 3 < INF · (1, 3) = -2 + 3 = 1 < INF |
| 2 | 0 | 들어간다 | 없음 |
| 3 | -1 | 들어간다 | (3, 0) = -1 + 5 = 4 < INF |
| 4 | INF | 건너뛴다 | — |

라운드 2 는 후보를 20 개 비교해 4 칸을 고쳤고, 2 행과 2 열에서 고친 칸은 0 개입니다.

<!--/proof-->

불안한 자리는 **같은 라운드 안에서 이미 고친 칸을 다시 읽는** 경우입니다. 식은 층 `k−1` 의 값을 읽으라고 하는데,
코드는 거리 행렬 하나를 제자리에서 고쳐요. 그런데 라운드 `k` 가 읽는 칸은 `k` 열(`dist[u][k]`)과 `k` 행
(`dist[k][v]`)뿐이고, 위 표의 마지막 문장처럼 그 두 줄은 라운드 동안 한 칸도 안 바뀝니다. 칸 `(u, k)` 의 후보는
`dist[u][k] + dist[k][k]` 인데 음수 사이클이 없으면 `dist[k][k] = 0` 이라 지금 값보다 작아질 수 없기 때문이에요.
`k` 행도 같은 이유로 그대로입니다.

| 줄 `u` 에서 | 하는 일 | 거리 행렬 |
| --- | --- | --- |
| `dist[u][k]` 가 `INF` 다 | 줄을 건너뛴다 | 그대로 |
| 후보 `dist[u][k] + dist[k][v]` 가 `dist[u][v]` 보다 작다 | 칸을 고친다 | 칸 하나가 줄어든다 |
| 후보가 작지 않다 | 그대로 둔다 | 그대로 |

#### 3단계 — k 를 0 부터 V−1 까지 올리기

라운드를 `k = 0` 부터 번호 순으로 한 번씩 합니다. 라운드 `k` 가 끝날 때마다 거리 행렬을 층 `k` 와 맞대었어요.

<!--proof:stageRounds-->

| 끝낸 라운드 k | 고친 칸 | 층 k 와 다른 칸 | 답과 같은 칸 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 0 | 15 |
| 1 | 2 | 0 | 17 |
| 2 | 4 | 0 | 21 |
| 3 | 4 | 0 | 25 |
| 4 | 0 | 0 | 25 |

칸은 25 개입니다. 라운드 4 를 끝낸 거리 행렬이 정본이 돌려준 답입니다.

<!--/proof-->

라운드마다 거리 행렬이 층 `k` 와 칸마다 같습니다. 그러니 라운드 `V−1` 을 끝내면 층 `V−1`, 곧 답이 남아요. 이
입력에서는 라운드 3 에서 이미 답에 이르렀지만, 마지막 라운드를 빼도 되는 것은 아닙니다. 그 자리는 파트 2 의
「불변식」에서 마지막 정점을 빼 보며 확인합니다.

#### 이 방법이 기대는 전제

「라운드 `k` 가 `k` 행과 `k` 열을 안 고친다」와 「최단 경로는 `k` 를 한 번만 지난다」는 둘 다 **음수 사이클이
없을 때** 성립합니다. 음수 사이클이 있으면 최단 거리가 정해지지 않으니, 이 절차가 그때 돌려주는 거리 행렬은 답이
아니라 라운드를 다 한 뒤의 값일 뿐이에요. `bellmanFord` 편이 쓴 음수 사이클 입력과 전개 입력에 정본을 실행했습니다.

<!--proof:premiseCycle-->

| 입력 | 반환한 대각선 dist[v][v] | 라운드 k 가 k 행·k 열에서 고친 칸 | 음수 사이클 |
| --- | --- | ---: | --- |
| 전개 입력 | 0 · 0 · 0 · 0 · 0 | 0 | 없다 |
| 0→1(1) 1→2(-1) 2→0(-1) | -1 · -1 · -2 | 5 | 있다 |

음수 사이클 입력에서 정본이 돌려준 거리 행렬은 [-1, 0, -1] [-2, -1, -2] [-2, -1, -2] 입니다.

<!--/proof-->

음수 사이클 입력에서는 대각선이 0 보다 작아지고, 라운드 `k` 가 `k` 행과 `k` 열까지 고칩니다. 대각선 `dist[v][v]`
는 `v` 에서 `v` 로 돌아오는 순환 가운데 비용이 가장 작은 것이라, 그것이 음수라는 것이 곧 `v` 를 지나는 음수 사이클이 있다는 뜻이에요.

| 전제 | 쓰이는 곳 | 깨지면 |
| --- | --- | --- |
| 음수 사이클이 없다 | 최단 경로가 `k` 를 한 번만 지난다 · 라운드 `k` 가 `k` 행·`k` 열을 안 고친다 | 대각선이 음수로 남고 거리 행렬은 답이 아니다 |

#### 거리 행렬 하나를 제자리에서 고치는 까닭

식을 그대로 옮기면 층 `k−1` 을 담은 거리 행렬과 층 `k` 를 적을 거리 행렬을 따로 두고 번갈아 써야 합니다. 2단계에서
본 대로 라운드 `k` 가 읽는 `k` 행·`k` 열이 라운드 동안 안 바뀌면, 하나를 제자리에서 고쳐도 같은 값을 읽어요. 두
판을 여러 입력에 실행하고 저장 칸을 세었습니다.

<!--proof:inPlace-->

| 입력 | 정점 | 두 판의 답이 다른 칸 | 라운드 k 가 k 행·k 열에서 고친 칸 | 저장 칸 (둘) | 저장 칸 (하나) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 5 | 0 | 0 | 50 | 25 |
| 한 줄 그래프 | 6 | 0 | 0 | 72 | 36 |
| 사이클 그래프 | 6 | 0 | 0 | 72 | 36 |
| 성긴 그래프 | 9 | 0 | 0 | 162 | 81 |

정점 500 에서는 저장 칸이 500,000 개 대 250,000 개입니다.

<!--/proof-->

네 입력 모두 두 판의 답이 같고, 라운드 `k` 가 `k` 행·`k` 열에서 고친 칸이 0 개입니다. 거리 행렬 하나로 하면 저장
칸이 절반이에요. 식이 요구하는 「층 `k−1` 의 값」이 제자리에서도 그대로 남아 있으니 둘을 둘 까닭이 없습니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 이렇습니다.

1. 거리 행렬을 만들어 대각선에 0, 나머지에 `INF` 를 적는다
2. 간선마다 칸 `(u, v)` 에 가중치를 적되 더 작을 때만 적는다
3. `k = 0` 부터 `V − 1` 까지 라운드를 되풀이한다
4. 라운드 안에서 줄 `u` 마다 `dist[u][k]` 가 `INF` 면 건너뛴다
5. 아니면 열 `v` 마다 `dist[u][k] + dist[k][v]` 가 `dist[u][v]` 보다 작을 때 고친다
6. 마지막 라운드가 끝난 거리 행렬을 돌려준다

### 수행으로 알아보는 알고리즘 — 정점 다섯을 일곱 걸음으로 푼다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 그래프 하나를 정해 끝까지 가져가되, 코드
조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

<!--proof:walkInput-->

```ts
const n = 5;
const edges: [number, number, number][] = [
  [0, 1, 3], [0, 1, 4], [1, 2, -2], [2, 0, 5],
  [2, 3, 3], [3, 1, 1], [4, 3, 2],
];
// 이 절이 끝나면 나와야 하는 값:
//   [0, 3, 1, 4, Infinity]
//   [3, 0, -2, 1, Infinity]
//   [5, 4, 0, 3, Infinity]
//   [4, 1, -1, 0, Infinity]
//   [6, 3, 1, 2, 0]
```

왜 이 그래프일까요? **같은 방향 간선 둘**과 **음수 간선**과 **아무도 도달하지 못하는 정점**을 함께 담아, 다섯
갈래를 이 한 입력에서 전부 실행하기 때문이에요. 라운드마다 무슨 일이 일어나는지 미리 세어 두면 이렇습니다.

<!--proof:walkChoice-->

| 라운드 k | 고친 칸 | 건너뛴 행 | 비교한 후보 |
| ---: | ---: | --- | ---: |
| 0 | 1 | 1 · 3 · 4 | 10 |
| 1 | 2 | 4 | 20 |
| 2 | 4 | 4 | 20 |
| 3 | 4 | 없음 | 25 |
| 4 | 0 | 0 · 1 · 2 · 3 | 5 |

라운드 5 번 가운데 4 번이 칸을 고치고 1 번은 한 칸도 못 고칩니다. 건너뛴 행이 있는 라운드가 4 번입니다.

<!--/proof-->

마지막 라운드가 한 칸도 못 고치는 자리까지 이 한 그래프에 들어 있습니다. 아무도 정점 4 로 갈 수 없어 4 를 지나는
길이 없기 때문이에요. 절차 전체를 한 장으로 적으면 이렇습니다.

```text
절차 전체를 한 장으로

  T1     거리 행렬을 만들어 대각선을 0 · 나머지를 INF 로 둔다     ① 칸 채우기
         간선마다 더 작은 가중치만 칸에 옮겨 적는다              ② 간선 옮겨 적기
  T2~T6  라운드를 k = 0 부터 n − 1 까지 되풀이한다:
           줄 u 마다 dist[u][k] 가 INF 면 건너뛴다                 ③ 행 건너뛰기
           열 v 마다 후보 dist[u][k] + dist[k][v] 를 만든다        ④ 후보
           후보가 dist[u][v] 보다 작으면 고친다                   ⑤ 완화
  T7     거리 행렬을 돌려준다
```

#### 1. 거리 행렬을 만들고 간선을 옮겨 적는다

「아이디어 상세」의 1단계를 코드로 옮깁니다. `n × n` 배열을 만들어 대각선에 0 을, 나머지에 `INF` 를 적고, 간선을
칸에 옮겨 적어요.

```ts
const dist: number[][] = Array.from({ length: n }, (_, u) =>
  Array.from({ length: n }, (_, v) => (u === v ? 0 : INF)),   // ① 칸 채우기
);

for (const [u, v, w] of edges) {                              // ② 간선 옮겨 적기
  const row = dist[u] as number[];
  if (w < (row[v] as number)) row[v] = w;
}
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walkInit-->

```text
     v=0  v=1  v=2  v=3  v=4
u=0  0    3    INF  INF  INF
u=1  INF  0    -2   INF  INF
u=2  5    INF  0    3    INF
u=3  INF  1    INF  0    INF
u=4  INF  INF  INF  2    0
```

`②` 의 `if (w < row[v])` 가 이 입력에서 곧장 일합니다. `0 → 1` 이 가중치 3 과 4 로 둘인데, 그냥 덮어쓰면 뒤에
적힌 4 가 남아요. 비교를 거치니 작은 3 이 남았습니다.

#### 2. 경유 정점 0 으로 한 라운드 완화한다

2단계를 코드로 옮깁니다. 라운드 하나는 `k` 를 고정하고 모든 `u` 와 `v` 를 지나가요. `k` 행은 반복 밖에서 한 번
읽어 `viaK` 에 두고, 줄마다 `dist[u][k]` 를 `toK` 에 둡니다.

```ts
const viaK = dist[k] as number[];
for (let u = 0; u < n; u++) {
  const row = dist[u] as number[];
  const toK = row[k] as number;
  if (toK === INF) continue;                              // ③ 행 건너뛰기
  for (let v = 0; v < n; v++) {
    const through = toK + (viaK[v] as number);            // ④ 후보
    if (through < (row[v] as number)) row[v] = through;   // ⑤ 완화
  }
}
```

`k = 0` 하나로 이 조각을 실행하면 거리 행렬이 이렇게 바뀝니다.

<!--proof:walkK0-->

```text
     v=0  v=1  v=2  v=3  v=4
u=0  0    3    INF  INF  INF
u=1  INF  0    -2   INF  INF
u=2  5    8    0    3    INF
u=3  INF  1    INF  0    INF
u=4  INF  INF  INF  2    0

건너뛴 행    u=1 u=3 u=4
고친 칸      (2, 1) = 5 + 3 = 8
비교한 후보  10
```

`③` 이 여기서 실제로 일합니다. `dist[1][0]` · `dist[3][0]` · `dist[4][0]` 이 전부 `INF` 라 그 세 줄은 0 을 지나는
길이 아예 없어요. 남은 두 줄에서 후보를 만들어 고친 칸은 `(2, 1)` 하나이고, 경로 `2 → 0 → 1` 의 비용입니다.

#### 짚고 가기 — 경유 정점을 가장 안쪽 반복에 두면 어떤 그래프에서는 답이 틀린다

여기서 헷갈리기 쉬운 포인트는 **세 반복문의 순서**입니다. 「칸 `(u, v)` 를 고정해 놓고 그 칸에 모든 `k` 를
넣어 보는 편이 자연스럽지 않나」로 읽기 쉬워요. 그 생각대로 `k` 를 가장 안쪽에 두어 봅시다.

```ts
for (let u = 0; u < n; u++) {
  const row = dist[u] as number[];
  for (let v = 0; v < n; v++) {
    for (let k = 0; k < n; k++) {                            // k 가 가장 안쪽이다
      const through = (row[k] as number) + ((dist[k] as number[])[v] as number);
      if (through < (row[v] as number)) row[v] = through;
    }
  }
}
```

<!--proof:pauseLoopOrder-->

| 입력 | 칸 수 | k 를 안쪽에 둔 판과 다른 칸 | 답 |
| --- | ---: | ---: | --- |
| 전개 입력 (정점 5) | 25 | 0 | 같다 |
| 한 줄 그래프 (정점 6) | 36 | 0 | 같다 |
| 사이클 그래프 (정점 6) | 36 | 6 | 다르다 |
| 성긴 그래프 (정점 9 · 간선 20) | 81 | 0 | 같다 |

입력 4 개 가운데 답이 다른 것은 1 개입니다.

<!--/proof-->

**네 입력 가운데 셋에서 답이 안 갈립니다.** 전개 입력에서도 맞으니, 이 순서로 적어 놓고 작은 시험을 실행하면 통과할
수 있어요. 갈리는 것은 사이클 그래프이고, 다른 칸은 전부 `INF` 로 남았습니다.

<!--proof:pauseLoopOrderCells-->

| 칸 | 정본 | k 를 안쪽에 둔 판 |
| --- | ---: | ---: |
| (1, 0) | 20 | INF |
| (2, 0) | 18 | INF |
| (2, 1) | 19 | INF |
| (3, 0) | 15 | INF |
| (3, 1) | 16 | INF |
| (3, 2) | 18 | INF |

사이클 그래프의 간선은 0→1(1) 1→2(2) 2→3(3) 3→4(4) 4→5(5) 5→0(6) 입니다.

<!--/proof-->

줄을 하나씩 끝낼 때마다 거리 행렬을 그렸습니다. 대시로 흐린 줄은 아직 손대지 않은 줄이에요.

<!--fig:pause-loop-order-->
![k 를 가장 안쪽에 둔 판 — 줄을 하나 끝낼 때마다의 거리 행렬](./figs/pause-loop-order.svg)

`1 → 0` 은 `1 → 2 → 3 → 4 → 5 → 0` 을 지나야 합니다. 그런데 줄 1 을 처리하는 시점에 줄 2 · 3 · 4 는 아직 간선만
적힌 처음 상태라 `dist[2][0]` · `dist[3][0]` · `dist[4][0]` 이 모두 `INF` 이고, 더할 재료가 없어요. 줄 1 은 한 번
끝나면 다시 오지 않으니 그 칸은 `INF` 로 굳습니다.

| 반복 순서 | 칸 `(u, v)` 를 완화할 때 `dist[u][k]` · `dist[k][v]` 가 담은 것 |
| --- | --- |
| `k` 가 바깥 | 층 `k−1` 의 값 — 라운드 `k` 를 시작할 때 모든 칸이 층 `k−1` 까지 채워져 있다 |
| `k` 가 안쪽 | 줄 `k > u` 는 간선만 적힌 처음 값 — 뒤 줄이 아직 채워지지 않았다 |

> 「무엇이 채워졌는가」를 정하는 것이 바깥 반복이다. 그 자리는 `k` 의 것이다.

#### 3. 경유 정점을 1 · 2 · 3 · 4 로 넓힌다

셋째 조각은 새로 만들 것이 없습니다. 바로 앞 조각을 `k` 를 바꿔 가며 되풀이하면 돼요. 이 바깥 반복이 3단계입니다.

```ts
for (let k = 0; k < n; k++) {
  // 바로 앞 조각(③ · ④ · ⑤)을 이 안에 넣는다
}
```

남은 네 라운드를 실행한 결과입니다.

<!--proof:walkRounds-->

| 걸음 | 라운드 k | 고친 칸 | 비교한 후보 |
| --- | ---: | --- | ---: |
| T3 | 1 | (0, 2) = 3 + (-2) = 1 · (3, 2) = 1 + (-2) = -1 | 20 |
| T4 | 2 | (0, 3) = 1 + 3 = 4 · (1, 0) = -2 + 5 = 3 · (1, 3) = -2 + 3 = 1 · (3, 0) = -1 + 5 = 4 | 20 |
| T5 | 3 | (2, 1) = 3 + 1 = 4 · (4, 0) = 2 + 4 = 6 · (4, 1) = 2 + 1 = 3 · (4, 2) = 2 + (-1) = 1 | 25 |
| T6 | 4 | 없음 | 5 |

T6 이 끝난 거리 행렬은 [0 3 1 4 INF] [3 0 -2 1 INF] [5 4 0 3 INF] [4 1 -1 0 INF] [6 3 1 2 0] 입니다.

<!--/proof-->

**T4 가 앞 라운드의 결과를 재료로 씁니다.** `(3, 0)` 이 `-1 + 5 = 4` 가 되는데, 그 `-1` 은 T3 이 만든 `dist[3][2]`,
곧 경로 `3 → 1 → 2` 의 비용이에요. 거기에 간선 `2 → 0` 을 이어 중간 정점이 둘인 경로 `3 → 1 → 2 → 0` 이
나왔습니다. 라운드를 넘길 때마다 경로가 한 토막씩 길어지는 것이 층을 올린다는 말의 뜻이에요. T5 는 줄 4 가 처음
들어오는 라운드입니다. `dist[4][3] = 2` 라 3 을 지날 수 있게 되자 그 줄의 세 칸이 한꺼번에 채워졌어요.

#### 짚고 가기 — 행을 건너뛰는 줄을 빼도 답은 안 틀린다

여기서 헷갈리기 쉬운 포인트는 `③` 한 줄입니다. 「`INF` 를 더해도 어차피 `INF` 라 안 고쳐질 텐데 굳이 판정해야
하나」로 읽기 쉬워요. 그 줄을 빼 봅시다.

```ts
  const toK = row[k] as number;
  // ③ 이 있던 자리를 비웠다
  for (let v = 0; v < n; v++) {
```

전부 통과해요. 그 자체는 참입니다. 갈리는 것은 답이 아니라 기본 연산이에요.

성긴 그래프에서 두 배 넘게 일합니다. 반대로 별 모양과 촘촘한 그래프에서는 두 값이 같은데, 그 두 그래프는 라운드를
시작할 때 모든 정점이 `k` 로 갈 수 있어 건너뛸 줄이 없기 때문이에요. 「답이 맞으니 됐다」로 넘어가면 성긴 입력에서
두 배를 일하는 코드가 시험을 통과한 채로 남습니다.

| `③` 이 | 무엇 | 까닭 |
| --- | --- | --- |
| 자르는 것 | `u` 에서 `k` 로 못 가는 줄 전체 — 안쪽 반복 `V` 번 | `k` 를 지나는 `u → v` 경로가 하나도 없다 |
| 못 자르는 것 | `u` 에서 `k` 로는 가는데 `k` 에서 `v` 로 못 가는 칸 | 칸마다 `④` 를 해 봐야 안다 |

#### 4. 일곱 걸음을 끝까지 실행한다

세 조각을 이어 고정 입력에 실행하면 일곱 걸음이 나옵니다. T1 은 거리 행렬 만들기, T2 부터 T6 까지가 라운드
다섯 번, T7 이 반환이에요. 걸음 재생 패널에서 줄은 출발 정점 `u`, 열은 도착 정점 `v` 이고, 점선 칸이 `INF` 입니다.
테를 두른 칸이 그 라운드가 읽는 `k` 행과 `k` 열, 강조한 칸이 고친 칸이고, 대시로 흐린 칸이 `③` 으로 건너뛴 줄이에요.

실었어요. `④` 와 `⑤` 의 차이가 후보를 만들고도 못 고친 횟수입니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인하지 않은 것은 `INF` 를 최상위 상수로 뺀 자리 하나뿐이고, 나머지는 조각
셋을 이은 것이라 동작이 그대로예요.

```ts
// 아직 이어지는 길을 못 찾은 칸에 넣어 두는 값. 어떤 유한한 거리보다 크다.
export const INF = Number.POSITIVE_INFINITY;

export function floydWarshall(
  n: number,
  edges: [number, number, number][],
): number[][] {
  // ① 거리 행렬 — 자기 자신은 0, 나머지는 아직 모르는 값이다.
  const dist: number[][] = Array.from({ length: n }, (_, u) =>
    Array.from({ length: n }, (_, v) => (u === v ? 0 : INF)),
  );

  // ② 간선을 옮겨 적는다 — 같은 방향 간선이 여럿이면 더 작은 가중치만 남긴다.
  for (const [u, v, w] of edges) {
    const row = dist[u] as number[];
    if (w < (row[v] as number)) row[v] = w;
  }

  for (let k = 0; k < n; k++) {
    const viaK = dist[k] as number[];
    for (let u = 0; u < n; u++) {
      const row = dist[u] as number[];
      const toK = row[k] as number;
      // ③ u 에서 k 로 가는 길이 없으면 k 를 경유하는 길도 없다 — 이 행은 건너뛴다.
      if (toK === INF) continue;
      for (let v = 0; v < n; v++) {
        // ④ k 를 경유하는 길의 길이 — 앞 토막과 뒤 토막을 더한다.
        const through = toK + (viaK[v] as number);
        // ⑤ 지금 적힌 값보다 짧으면 그 값으로 고친다.
        if (through < (row[v] as number)) row[v] = through;
      }
    }
  }

  return dist;
}
```

실행하면 이렇게 나옵니다.

```text
floydWarshall(3, [[0, 1, -1], [1, 2, -2]])            -> [[0, -1, -3], [Infinity, 0, -2], [Infinity, Infinity, 0]]
```

### 알아 두면 좋은 개념 — (min, +) 경로 대수

라운드 하나가 하는 일을 다시 보면 연산이 둘뿐입니다. **두 토막을 이을 때는 더하고(`+`), 여러 후보 중에서 고를
때는 작은 쪽을 남겨요(`min`).** 이 두 연산 한 벌을 **(min, +) 경로 대수**라고 부릅니다. 이 편에서 그것은 `④` 의
`toK + viaK[v]` 와 `⑤` 의 `through < row[v]` 였어요. 같은 세 겹 반복에 두 연산만 갈아 끼워 전개 입력에 실행했습니다.

<!--proof:relatedAlgebra-->

| 이을 때 | 고를 때 | 칸 (u, v) 의 뜻 | 전개 입력의 3 행 |
| --- | --- | --- | --- |
| `+` | `min` | 최단 거리 | 4 1 -1 0 INF |
| `and` | `or` | u 에서 v 로 갈 수 있는가 | 참 참 참 참 거짓 |
| `max` | `min` | 지나는 간선 중 가장 큰 가중치가 가장 작은 길의 그 가중치 | 5 1 1 − INF |

첫 줄은 정본이 돌려준 3 행과 칸마다 같습니다. 셋째 줄의 − 는 출발과 도착이 같아 간선을 지나지 않는 칸입니다.

<!--/proof-->

둘째 줄이 워셜(Warshall)의 **도달 가능성** 계산입니다. 덧셈을 논리곱으로, 「더 작은가」를 논리합으로 바꾸면 그대로
나와요. 셋째 줄은 지나는 간선 가운데 가장 무거운 것을 가장 가볍게 하는 길이고, 그 반대(가장 좁은 구간을 가장 넓게)는
네트워크 대역폭 계산에 쓰입니다.

| 다른 자리 | 이을 때와 고를 때 | 얻는 것 |
| --- | --- | --- |
| 거듭제곱으로 점화식 풀기 | `×` 와 `+` | 행렬을 `log n` 번 곱해 `n` 번째 항 |
| 정규식에서 오토마타 만들기 | 이어 붙이기와 선택 | 상태 사이의 문자열 집합 |
| 「아이디어를 떠올리는 과정」의 경유 횟수 배로 늘리기 | `+` 와 `min` | 간선 수 한도를 두 배로 늘린 거리 행렬 |

첫 줄은 이 저장소에도 있어요 — [`fastPower`](../../number-theory/fastPower/fastPower-guide.md) 가 그 자리입니다.
이름을 알아 두면 「이 과제도 세 겹 반복으로 되나」를 물을 때 이을 때와 고를 때 두 자리부터 확인하게 됩니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 층을 식으로 어떻게 적는지, 무엇이 매 라운드 참으로
남는지, 그리고 기본 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 모든 쌍의 답이 필요하다 | 출발점 하나만 물으면 그 출발점만 계산하는 절차가 적게 일한다 | 답이 `V × V` 거리 행렬이다 |
| 정점 수가 작다 | 비용이 `V³` 이다 | 세 겹 반복이 `V` 번씩 실행된다 |
| 간선이 촘촘하다 | 간선 수가 `V²` 에 가까우면 출발점마다 따로 하는 쪽의 비용이 `V²E` 로 커진다 | 비용이 간선 수와 거의 무관하다 |
| 음수 가중치가 있을 수 있다 | 가중치가 전부 0 이상이면 출발점마다 `dijkstra` 를 쓰는 쪽이 성긴 그래프에서 적다 | 음수를 따로 다루지 않고 그대로 더한다 |

첫 두 조건이 이 절차의 자리입니다. 간선이 성기면 같은 목표를 간선 수에 비례해 푸는 설계가 적게 일하고, 그 경계는
아래 「경쟁 설계와의 대조」가 값으로 냅니다. **음수 사이클 판정에도 이 절차를 씁니다.** 반복이 끝난 뒤 대각선
`dist[v][v]` 가 0 보다 작은 `v` 가 있으면 그 정점을 지나는 음수 사이클이 있다는 뜻이에요. 「이 방법이 기대는 전제」의
표가 그 자리였습니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "모든 쌍" "임의의 두 지점" "표를 미리 만들어 두고 조회"  <- 답이 V × V 다
  "질의가 여러 번 들어온다"                                <- 한 번 만들어 두고 계속 읽는다
  "보조금" "할인" "이득이 나는 구간"                       <- 가중치가 음수일 수 있다
  "순환해도 계속 이득이 나는 구간은 없다"                  <- 음수 사이클이 없다는 약속이다
  "A 에서 B 로 갈 수 있는가를 모든 쌍에 대해"              <- (and, or) 로 바꾼 같은 반복

제약에 이런 모양이 보이면
  정점이 수백 개 이하다  <- V^3 을 감당할 수 있다
  간선이 V^2 급이다      <- 출발점마다 따로 계산하는 쪽보다 적게 일한다

반대로 이런 말이 보이면 해당하지 않는다
  "출발점은 하나다"         <- 거리 행렬 전체를 만드는 값을 치를 까닭이 없다
  "정점이 10 만 개다"       <- V^3 은 물론 V^2 칸도 잡을 수 없다
  "간선이 정점 수의 몇 배"  <- 성긴 그래프라 다른 설계가 적게 일한다
```

마지막 무리가 보이면 다른 절차로 갑니다. 출발점이 하나이고 가중치가 0 이상이면
[`dijkstra`](../dijkstra/dijkstra-guide.md) 쪽이고, 음수 가중치가 있으면 [`bellmanFord`](../bellmanFord/bellmanFord-guide.md)
나 [`spfa`](../spfa/spfa-guide.md) 쪽입니다.

### 수식 정의와 유도

정점 집합을 `{0, 1, …, V−1}` 이라 하고, 경로의 **중간 정점**을 출발 정점과 도착 정점을 뺀 나머지 정점이라 정의합니다.
$\mathcal{P}_k(u, v)$ 는 $u$ 에서 $v$ 로 가는 경로 가운데 중간 정점의 번호가 모두 $k$ 이하인 것의 집합이고, 원소가
하나도 없는 집합의 최솟값은 $\infty$ 로 약속해요.

$$\mathrm{opt}_k(u, v) = \min_{P \in \mathcal{P}_k(u, v)} \sum_{(a, b, w) \in P} w, \qquad \mathrm{opt}_{-1}(u,v) = \begin{cases} 0 & (u = v) \\ \min w(u,v) & (u \to v \text{ 간선이 있다}) \\ \infty & (\text{그 밖}) \end{cases}$$

이 정의를 전개 입력의 칸 셋에 넣었습니다.

<!--proof:mathCheck-->

| k | 중간에 쓸 수 있는 정점 | opt_k(2, 1) | opt_k(4, 0) | opt_k(3, 2) |
| ---: | --- | ---: | ---: | ---: |
| -1 | 없음 | INF | INF | INF |
| 0 | 0 | 8 | INF | INF |
| 1 | 0 · 1 | 8 | INF | -1 |
| 2 | 0 · 1 · 2 | 8 | INF | -1 |
| 3 | 0 · 1 · 2 · 3 | 4 | 6 | -1 |
| 4 | 0 · 1 · 2 · 3 · 4 | 4 | 6 | -1 |

세 열 모두 절차를 쓰지 않고 단순 경로를 전부 만들어 고른 값입니다.

<!--/proof-->

`opt_0(2, 1) = 8` 은 경로 `2 → 0 → 1` 의 비용 `5 + 3` 이고, `opt_3(2, 1) = 4` 는 경로 `2 → 3 → 1` 의 비용 `3 + 1`
입니다. `opt_2(4, 0)` 이 아직 `INF` 인 것은 정점 4 에서 나가는 유일한 간선이 `4 → 3` 이라 3 을 중간에 못 쓰면 어디로도
못 가기 때문이에요.

이제 점화식을 유도합니다. $\mathcal{P}_k(u, v)$ 의 경로를 **정점 $k$ 를 중간에 쓰는가**로 두 무리로 가릅니다. 안 쓰는
무리는 정의상 $\mathcal{P}_{k-1}(u, v)$ 이고 그 최솟값이 $\mathrm{opt}_{k-1}(u, v)$ 예요. 쓰는 무리에서는 최단 경로를
단순 경로에서 고를 수 있으므로(음수 사이클이 없으면 순환을 빼도 비용이 늘지 않는다) $k$ 가 한 번만 나오고, $k$ 에서
끊은 두 토막은 중간 정점이 $k-1$ 이하라 각각 $\mathcal{P}_{k-1}(u, k)$ 와 $\mathcal{P}_{k-1}(k, v)$ 의 원소입니다.

$$\mathrm{opt}_k(u,v) = \min\bigl(\mathrm{opt}_{k-1}(u,v),\; \mathrm{opt}_{k-1}(u,k) + \mathrm{opt}_{k-1}(k,v)\bigr)$$

| 무리 | 경로의 모양 | 그 무리의 최솟값 |
| --- | --- | --- |
| $k$ 를 안 쓴다 | $u \to \cdots \to v$, 중간이 $0..k-1$ | $\mathrm{opt}_{k-1}(u, v)$ |
| $k$ 를 쓴다 | $u \to \cdots \to k$ 와 $k \to \cdots \to v$, 두 토막 다 중간이 $0..k-1$ | $\mathrm{opt}_{k-1}(u, k) + \mathrm{opt}_{k-1}(k, v)$ |

식은 $\mathrm{opt}_{k-1}$ 두 칸을 읽어 $\mathrm{opt}_k$ 를 만드는데, 코드는 거리 행렬 하나를 제자리에서 고칩니다. 그래도
값이 같은 까닭을 식으로 확인합시다. $v = k$ 를 넣으면 이렇게 됩니다.

$$\mathrm{opt}_k(u,k) = \min\bigl(\mathrm{opt}_{k-1}(u,k),\; \mathrm{opt}_{k-1}(u,k) + \mathrm{opt}_{k-1}(k,k)\bigr) = \mathrm{opt}_{k-1}(u,k)$$

둘째 항은 첫째 항에 $\mathrm{opt}_{k-1}(k, k)$ 를 더한 것입니다. $\mathrm{opt}_{k-1}(k, k)$ 는 $k$ 에서 $k$ 로 오는 경로 가운데
비용이 가장 작은 것인데, 빈 경로의 0 이 후보에 있으니 0 이하이고, 음수 사이클이 없으니 0 보다 작을 수 없어 정확히 0 이에요.
그래서 둘째 항이 첫째 항과 같고 `min` 이 첫째 항을 냅니다. 곧 $k$ 열은 라운드 $k$ 에서 안 바뀌고, $u = k$ 를 넣으면
같은 계산이 $k$ 행에 대해 성립해요. 식의 $\mathrm{opt}_{k-1}(u,k)$ 가 코드의 `toK` 이고 $\mathrm{opt}_{k-1}(k,v)$ 가
`viaK[v]` 입니다. 이름이 갈린 것은 코드가 두 값을 반복 밖에서 한 번씩 읽어 두기 때문이에요.

```ts
// 식을 그대로 옮긴 조각. 칸 하나를 층 k−1 에서 층 k 로 올린다.
const next = (cur: number, toK: number, fromK: number): number =>
  Math.min(cur, toK + fromK);
```

비용의 닫힌 형태를 냅니다. 라운드가 $V$ 번, 라운드 하나가 행 판정 $V$ 번과 후보 비교 최대 $V^2$ 번을 하고, 그 앞에
칸 채우기 $V^2$ 번과 간선 읽기 $E$ 번이 붙어요. 이 합을 $T(V, E)$ 라 쓰면 이렇게 됩니다.

$$T(V, E) \;\le\; \underbrace{V^2}_{\text{칸 채우기}} + \underbrace{E}_{\text{간선 읽기}} + \underbrace{V \cdot V}_{\text{행 판정}} + \underbrace{V \cdot V \cdot V}_{\text{후보 비교}} = V^3 + 2V^2 + E$$

후보 비교만 부등식이고 나머지 세 항은 입력과 무관하게 정확히 그 횟수입니다. 건너뛰는 행이 하나도 없는 그래프에서
실제로 세면 이렇습니다.

<!--proof:mathBound-->

| 정점 V | 간선 E | 실행한 기본 연산 | V³ + 2V² + E | 앞 ÷ 뒤 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 14 | 654 | 654 | 1.000 |
| 32 | 62 | 34,878 | 34,878 | 1.000 |
| 128 | 254 | 2,130,174 | 2,130,174 | 1.000 |
| 200 | 398 | 8,080,398 | 8,080,398 | 1.000 |

그래프는 정점 0 과 나머지를 양방향으로 이은 별 모양입니다. 정점 500 · 간선 249,500 을 식에 넣으면 125,749,500 번이고, 거리의 절댓값은 (V − 1) × 1,000,000 = 499,000,000 을 넘지 않습니다.

<!--/proof-->

**여기서 본문의 값만으로는 안 나오는 것이 나옵니다.** 파트 1 이 보인 것은 정점 다섯의 한 벌짜리 값인데, 위 유도는
**임의의 `V` 와 `E`** 에 대해 기본 연산이 `V³ + 2V² + E` 를 넘지 않고 별 모양에서 그 값에 이른다는 것을 줍니다. 규모의
상한을 넣은 값과, 거리가 자바스크립트 수가 정수를 정확히 담는 범위 안에 머문다는 것도 함께 나와요.

### 불변식 — 라운드 k 가 끝나면 거리 행렬의 모든 칸이 층 k 의 값과 같다

파트 1 의 일곱 걸음은 그래프 하나에서 답이 나왔다는 기록입니다. 그 하나로는 다른 입력에서도 같은 일이 일어난다는
근거가 안 되므로, **라운드를 몇 번 끝냈든 참으로 남는 문장**을 세우고 그것이 유지되는지를 값으로 확인합니다.

> 라운드 `k` 가 끝난 시점에 모든 `u` · `v` 에 대해 `dist[u][v] = opt_k(u, v)` 입니다. 라운드에 들어가기 전에는
> `dist[u][v] = opt_{-1}(u, v)` 입니다.

| 문장이 말하는 것 | 쓰이는 곳 |
| --- | --- |
| 거리 행렬의 모든 칸이 같은 시점의 같은 제한 아래에서 답이다 | 다음 라운드가 `dist[u][k]` 와 `dist[k][v]` 를 층 `k` 의 값으로 읽는다 |
| 마지막 라운드에서 제한이 「번호가 `V−1` 이하」가 된다 | 그것은 제한이 없는 것과 같아 마지막 거리 행렬이 답이다 |

**라운드에 들어가기 전부터 봅시다.** 1단계가 적은 거리 행렬은 대각선 0 과 간선 칸의 가장 작은 가중치이고, 중간 정점을
안 쓰는 경로는 빈 경로와 간선 하나짜리 경로뿐이라 층 -1 과 같습니다. 그 뒤로 상태를 바꾸는 갈래는 넷이에요.

| 갈래 | 하는 일 | 문장이 유지되는 근거 |
| --- | --- | --- |
| 행 건너뛰기 | `dist[u][k]` 가 `INF` 인 줄을 안 본다 | `u` 에서 `k` 로 가는 길이 없어 `k` 를 쓰는 무리가 비었다 — 최솟값은 `opt_{k−1}(u, v)` 그대로다 |
| 후보 만들기 | `dist[u][k] + dist[k][v]` | 두 칸이 라운드 동안 안 바뀌어 `opt_{k−1}(u, k) + opt_{k−1}(k, v)` 다 |
| 완화 | 후보가 작으면 고친다 | 점화식의 두 항 중 작은 쪽을 남긴다 |
| 다음 라운드 | `k` 를 하나 올린다 | 층 `k` 가 다 적힌 채로 다음 라운드의 재료가 된다 |

「행 건너뛰기」 줄이 이 논증에서 가장 좁은 자리입니다. 건너뛰면 그 줄의 칸을 하나도 안 보는데 문장이 유지되는 것은
`dist[u][k] = INF` 가 곧 `opt_{k−1}(u, k) = ∞` 이라서예요. 그러면 `k` 를 쓰는 무리가 비어 있고, 빈 무리의 최솟값
`∞` 는 적힌 값을 못 바꿉니다. 전개 입력에서 라운드마다 확인하면 이렇습니다.

<!--proof:invariantWatch-->

| 끝낸 라운드 k | 중간에 쓸 수 있는 정점 | 맞댄 칸 | 다른 칸 |
| ---: | --- | ---: | ---: |
| 0 | 0 | 25 | 0 |
| 1 | 0 · 1 | 25 | 0 |
| 2 | 0 · 1 · 2 | 25 | 0 |
| 3 | 0 · 1 · 2 · 3 | 25 | 0 |
| 4 | 0 · 1 · 2 · 3 · 4 | 25 | 0 |

정의대로 계산한 값은 단순 경로를 전부 만들어 고른 것이라 절차와 다른 길로 얻었습니다.

<!--/proof-->

**엣지 케이스를 함께 봅시다.** 경계에 있는 입력 여덟에 같은 대조를 했어요.

<!--proof:invariantEdges-->

| 경계 입력 | 정점 | 간선 | 답의 INF 칸 | 라운드마다 층과 다른 칸의 최댓값 |
| --- | ---: | ---: | ---: | ---: |
| 정점 하나 · 간선 없음 | 1 | 0 | 0 | 0 |
| 정점 넷 · 간선 없음 | 4 | 0 | 12 | 0 |
| 가중치가 전부 0 | 3 | 2 | 3 | 0 |
| 같은 방향 간선 셋 | 2 | 3 | 1 | 0 |
| 음수 간선 둘 | 3 | 2 | 3 | 0 |
| 아무도 못 가는 정점 | 3 | 1 | 5 | 0 |
| 한 줄 그래프 (정점 6) | 6 | 5 | 15 | 0 |
| 사이클 그래프 (정점 6) | 6 | 6 | 0 | 0 |

정점이 하나면 라운드가 1 번이고 비교하는 후보가 1 개입니다.

<!--/proof-->

정점이 하나면 라운드가 한 번이고 후보도 하나입니다. 그 한 번은 `dist[0][0]` 을 `dist[0][0] + dist[0][0] = 0` 과
비교하는 것이라 값이 안 바뀌어요. 간선이 없는 그래프에서는 대각선을 뺀 칸이 전부 `INF` 로 남고, 그것이 「길이 없다」의
올바른 답입니다. 같은 방향 간선이 셋이면 1단계가 가장 작은 가중치를 남기고, 가중치 0 은 같은 값을 넘겨줄 뿐
`through < row[v]` 가 거짓이라 칸을 흔들지 않습니다.

**이제 그 줄을 망가뜨려 봅시다.** 문장이 「라운드 `V−1` 이 끝나면 층 `V−1`」까지 가게 떠받치는 자리는 라운드의 범위를
정하는 `for (let k = 0; k < n; k++)` 한 줄입니다. 「마지막 정점은 어차피 마지막이니 중간 정점 후보에서 빼도 되지
않나」라는 생각으로 그 줄만 바꿔 봅니다.

```ts
  for (let k = 0; k < n - 1; k++) {   // 마지막 정점을 뺐다
```

<!--proof:mutantShortK-->

| 입력 | 다른 칸 | 처음 다른 칸 | 정본 | 마지막 정점을 뺀 판 | 판정 |
| --- | ---: | --- | --- | --- | --- |
| 전개 입력 (정점 5) | 0 | — | — | — | 같다 |
| 한 줄 그래프 (정점 6) | 0 | — | — | — | 같다 |
| 사이클 그래프 (정점 6) | 10 | (1, 0) | 20 | INF | 어긋난다 |

<!--/proof-->

**사이클 그래프에서 칸이 어긋나고 `(1, 0)` 이 `INF` 로 나옵니다.** 앞의 두 입력에서 답이 안 갈리는 것이 이 변이의 성질을
그대로 보여요. 전개 입력은 아무도 정점 4 로 못 가서 4 를 지나는 경로가 없고, 한 줄 그래프는 마지막 정점에서 나가는 간선이
없습니다. 두 경우 다 마지막 정점이 중간 정점으로 쓰일 일이 없어 빼도 티가 안 나요.

| 판 | 끝난 시점의 거리 행렬 | 문장이 요구하는 것 |
| --- | --- | --- |
| 정본 | 층 `V−1` | 층 `V−1` |
| 마지막 정점을 뺀 판 | 층 `V−2` — 번호 `V−1` 을 중간에 못 쓴다 | 층 `V−1` |

사이클 `0→1→2→3→4→5→0` 에서 `1 → 0` 은 5 를 반드시 지납니다. 「마지막이니 안 쓴다」는 도착점으로서의 이야기이고,
중간 정점으로서는 다른 정점과 똑같이 쓰여요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 넷입니다. 거리 행렬의 칸을 채우는 것, 간선을 읽어 옮겨 적는 것, 라운드마다 줄을 건너뛸지
판정하는 것, 그리고 후보를 비교하는 것이에요. 네 가지를 하나씩 세는 것이 이 글의 기본 연산입니다. 전개의 일곱 걸음에서
셉니다.

<!--proof:perfCount-->

| 걸음 | 라운드 k | 들어간 행 | 건너뛴 행 | 이 걸음의 기본 연산 | 누적 |
| --- | --- | ---: | ---: | --- | ---: |
| T1 | — | — | — | 칸 채우기 25 + 간선 읽기 7 | 32 |
| T2 | 0 | 2 | 3 | 행 판정 5 + 후보 비교 10 | 47 |
| T3 | 1 | 4 | 1 | 행 판정 5 + 후보 비교 20 | 72 |
| T4 | 2 | 4 | 1 | 행 판정 5 + 후보 비교 20 | 97 |
| T5 | 3 | 5 | 0 | 행 판정 5 + 후보 비교 25 | 127 |
| T6 | 4 | 1 | 4 | 행 판정 5 + 후보 비교 5 | 137 |
| T7 | — | — | — | 0 | 137 |

칸 채우기 25 번 · 간선 읽기 7 번 · 행 판정 25 번 · 후보 비교 80 번을 더해 137 번입니다.

<!--/proof-->

라운드마다 후보 비교가 다르다는 것을 봐 주세요. **한 라운드가 비교하는 후보는 「그 라운드에 들어간 줄의 수 × V」입니다.**
T5 는 다섯 줄이 다 들어와 후보가 가장 많고, T6 은 한 줄만 들어와 가장 적어요. 행 판정은 건너뛰든 안 건너뛰든 라운드마다
`V` 번입니다. 이것을 임의의 입력으로 넓히면 총식이 됩니다. 라운드 `k` 에 들어간 줄의 수를 `r_k` 라고 적어요.

| 항 | 횟수 | 근거 |
| --- | --- | --- |
| 칸 채우기 | `V²` | 거리 행렬의 칸마다 한 번 |
| 간선 읽기 | `E` | 간선마다 한 번 |
| 행 판정 | `V²` | 라운드 `V` 번 × 줄 `V` 개 |
| 후보 비교 | `V × (r_0 + … + r_{V−1})` | 들어간 줄마다 열 `V` 개 |
| 합 | `2V² + E + V × Σ r_k` | `r_k ≤ V` 이므로 `V³ + 2V² + E` 이하 |

**여기서 센 것은 기본 연산 넷 전부입니다.** 배열 칸을 읽는 횟수와 반복 변수를 올리는 횟수는 세지 않았어요. 둘 다 위
값에 비례하므로 총식의 차수가 그대로입니다. 메모리는 같은 기준으로 거리 행렬의 저장 칸 `V²` 이고, 입력인 간선 목록은
읽기만 합니다.

<!--proof:perfMemory-->

```text
V = 500  저장 칸 V^2             250,000 칸
         Float64Array 로 잡으면  2,000,000 바이트
         number[][] 로 잡으면    칸마다 8 바이트에 행마다 배열 머리가 붙는다
```

#### 케이스별 비용과 그 경계

어떤 입력인가를 말하는 **케이스**와 어떤 종류의 값인가를 말하는 **경계**는 서로 다른 갈래입니다. 한 갈래의 이름을 다른
갈래에 붙이면 두 정보가 함께 사라져요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (간선이 없다) | `O(V³)` | `Θ(V²)` — 줄마다 자기 줄만 들어온다 |
| **평균적인 경우** (입력 분포를 정의하지 않는다) | `O(V³)` | 정의하지 않는다 |
| **최악의 경우** (모든 라운드에 모든 줄이 들어온다) | `O(V³)` | `Θ(V³)` — 실제로 도달한다 |

평균을 정의하지 않는 이유는 **들어가는 줄의 수를 정하는 것이 그래프의 도달 관계**이기 때문입니다. 정점 수와 간선 수를
고정해도 간선을 어디에 두는가에 따라 갈리고, 그 분포를 과제가 주지 않아요. 절차 쪽에도 난수가 없어 구현이 무작위성을
만들지 않습니다. 같은 정점 60 개로 모양을 바꿔 가며 재 보면 이렇습니다.

<!--proof:perfObserved-->

| 그래프 (정점 60) | 간선 | 기본 연산 | V³ + 2V² + E | 앞 ÷ 뒤 |
| --- | ---: | ---: | ---: | ---: |
| 간선이 없다 | 0 | 10,800 | 223,200 | 0.048 |
| 한 줄 그래프 | 59 | 117,059 | 223,259 | 0.524 |
| 성긴 그래프 | 180 | 97,320 | 223,380 | 0.436 |
| 사이클 그래프 | 60 | 120,600 | 223,260 | 0.540 |
| 별 모양 | 118 | 223,318 | 223,318 | 1.000 |
| 촘촘한 그래프 | 3,540 | 226,740 | 226,740 | 1.000 |

간선이 없으면 기본 연산이 10,800 번이고, 그것은 3V² = 10,800 과 같습니다.

<!--/proof-->

간선이 없으면 줄마다 자기 줄(`dist[u][u] = 0`)만 들어와 라운드마다 후보가 `V` 개이고, 칸 채우기 · 행 판정과 합쳐 `3V²`
입니다. 별 모양과 촘촘한 그래프는 상한을 그대로 채우고, 그 사이의 그래프는 앞 라운드에서 도달 관계가 아직 안 만들어져
건너뛰는 줄이 남아요.

```text
상한과 타이트한 값을 가르는 자리
  O(V^3)      기본 연산이 그보다 크지 않다는 것만 말한다   상한이다
  Theta(V^2)  간선이 없으면 기본 연산이 정확히 3V^2 이다   타이트한 값이다

기댓값이 끼어들 자리가 없다
  라운드의 차례      k = 0 부터 번호 순이다              난수를 안 쓴다
  칸을 찾는 방법     번호로 배열 칸에 바로 간다          해시 충돌이라는 개념이 없다
```

**총식을 한 번은 빠짐없이 적습니다.** 이 절차에는 앞뒤로 붙는 전처리가 없어요 — 정렬도, 이웃 목록도, 좌표 압축도
하지 않습니다. `Θ(V² + E)` 시간에 거리 행렬을 채우고 그 뒤에 `O(V³)` 짜리 라운드가 붙어 `O(V³ + V² + E) = O(V³)` 로
끝납니다(`E ≤ V(V−1)`). **위의 값은 전부 최악 보장입니다.** 기댓값이 아니라 상한이라는 뜻이고, 어떤 그래프를 넣어도 그
값을 넘지 않아요.

#### 최악을 만드는 입력

기본 연산을 최대로 만들려면 **모든 라운드에서 건너뛰는 줄이 하나도 없어야** 합니다. 그러려면 라운드 `k` 를 시작하는
시점에 모든 `u` 가 `k` 로 갈 수 있어야 해요. 「간선을 많이 두면 되겠지」로 넘기지 않고 모양을 바꿔 가며 재 봅시다.

<!--proof:worstShape-->

| 그래프 (정점 60) | 간선 | 서로 도달하는 쌍 | 후보 비교 | 기본 연산 |
| --- | ---: | ---: | ---: | ---: |
| 간선이 없다 | 0 | 60 | 3,600 | 10,800 |
| 한 줄 그래프 | 59 | 1,830 | 109,800 | 117,059 |
| 사이클 그래프 | 60 | 3,600 | 113,340 | 120,600 |
| 성긴 그래프 | 600 | 3,600 | 142,500 | 150,300 |
| 별 모양 | 118 | 3,600 | 216,000 | 223,318 |
| 촘촘한 그래프 | 3,540 | 3,600 | 216,000 | 226,740 |

후보 비교가 가장 많은 값은 216,000 번 = V³ 이고, 그 값을 내는 모양이 2 가지입니다. 그중 간선이 가장 적은 것은 별 모양 · 간선 118 개입니다.

<!--/proof-->

**사이클 그래프가 최악이 아닙니다.** 모든 쌍이 서로 도달하는데도 상한에 한참 못 미치는데, 라운드 0 을 시작하는 시점에
0 으로 곧장 갈 수 있는 정점이 「0 의 바로 앞 정점」 하나뿐이라 나머지 줄이 전부 건너뛰어지기 때문이에요. **간선 수가
정하는 것이 아닙니다.**

| 모양 | 라운드 0 에서 `dist[u][0]` 이 유한한 줄 | 그 뒤 라운드 |
| --- | --- | --- |
| 별 모양 — 정점 0 과 나머지를 양방향으로 잇는다 | 모든 줄 | `u → 0 → k` 가 있어 계속 모든 줄 |
| 사이클 | 0 과 그 바로 앞 정점 | 앞쪽 라운드에서 줄이 많이 잘린다 |

규모를 4 배씩 늘려도 상한을 채우는지 봅니다.

<!--proof:worstGrowth-->

| 정점 V | 별 모양의 간선 | 기본 연산 | V³ + 2V² + E | 앞 ÷ 뒤 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 30 | 4,638 | 4,638 | 1.000 |
| 64 | 126 | 270,462 | 270,462 | 1.000 |
| 256 | 510 | 16,908,798 | 16,908,798 | 1.000 |
| 500 | 998 | 125,500,998 | 125,500,998 | 1.000 |

정점 500 에서 간선이 998 개뿐인 별 모양이 상한을 그대로 채웁니다.

<!--/proof-->

「앞 ÷ 뒤」 열이 네 규모 모두에서 1 입니다. 상한이 헐거운 값이 아니라 실제로 도달하는 값이라는 뜻이고, 그래서
`Θ(V³)` 라고 적을 수 있어요. 규모의 상한에서 간선이 천 개도 안 되는데 상한을 채우니, **간선을 적게 주는 것이 이
절차를 빠르게 만들어 주지 않습니다.**

| 최악으로 만들 축 | 그 축을 최대로 만드는 입력 |
| --- | --- |
| 기본 연산 | 별 모양 — 간선 `2(V − 1)` 개로 상한을 채운다 |
| 저장 칸 | 정점 수를 규모의 상한까지 올린다 — 간선 수와 무관하다 |
| 거리 값의 크기 | 가중치가 모두 상한인 한 줄 그래프 — 「수식 정의와 유도」의 `(V − 1) × 10^6` |

**여기서 잰 무리는 음수 사이클이 없는 그래프들입니다.** 음수 사이클이 있는 그래프는 최단 거리가 정의되지 않으므로
대상이 아니고, 확인한 것은 「이 무리에서 기본 연산이 `V³ + 2V² + E` 를 안 넘고 별 모양에서 그 값에 이른다」 까지예요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 거리 행렬을 간선으로 채운 다음, 중간에 둘 수 있는 정점을 `0` 부터
`V−1` 까지 하나씩 늘려 가며 라운드마다 모든 칸을 `dist[u][k] + dist[k][v]` 로 완화합니다. 그렇게 해도 되는 근거는
「라운드 `k` 가 끝나면 거리 행렬이 층 `k` 와 같다」이고, 비용의 상한은 `V³ + 2V² + E` 예요.

```text
dist 를 대각선 0 · 간선 · INF 로 → k = 0 .. V−1: 줄 u 마다 dist[u][k] 가 INF 면 건너뛰고
                                                  아니면 열 v 마다 dist[u][k] + dist[k][v] 로 완화 → dist 를 돌려준다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T3 과 T4 가 끝난 뒤의 줄 3 을 놓았습니다.

<!--proof:checkQuestion-->

| 걸음 | 라운드 k | dist[3] 줄 |
| --- | ---: | --- |
| T3 | 1 | INF 1 -1 0 INF |
| T4 | 2 | 4 1 -1 0 INF |

<!--/proof-->

T4 는 칸 넷을 한꺼번에 고쳤어요. 그중 `(3, 0)` 이 `INF` 에서 4 가 되는데, 그
4 는 간선 두 개의 합이 아닙니다. 어디서 온 값일까요?

<!--check:whereFourComesFrom-->
**T3 이 만든 `dist[3][2] = -1` 과 간선 `2 → 0` 의 5 를 더한 값입니다.** `-1` 자체가 경로 `3 → 1 → 2` 의 비용이라 이미
간선 둘의 합이고, 거기에 `2 → 0` 을 이으면 간선 셋짜리 경로 `3 → 1 → 2 → 0` 이 돼요. T4 가 고친 칸을 다시 보면
이렇습니다.

<!--proof:checkT4-->

| 칸 | 라운드 앞의 값 | dist[u][2] + dist[2][v] | 라운드 뒤의 값 |
| --- | ---: | --- | ---: |
| (0, 3) | INF | 1 + 3 | 4 |
| (1, 0) | INF | -2 + 5 | 3 |
| (1, 3) | INF | -2 + 3 | 1 |
| (3, 0) | INF | -1 + 5 | 4 |

고친 4 칸 가운데 라운드 앞의 값이 INF 였던 칸은 4 개입니다. 왼쪽 항이 T3 에서 만든 값인 칸은 (0, 3) · (3, 0) 입니다.

<!--/proof-->

**라운드를 넘기면서 경로가 한 토막씩 길어지는 것**이 이 표의 내용입니다. 왼쪽 항이 어디서 왔는가로 칸을 가르면
이렇습니다.

| 왼쪽 항 `dist[u][2]` | 칸의 경로 |
| --- | --- |
| 앞 라운드가 만든 값 | 앞 라운드의 경로에 한 토막을 더 이은 경로 |
| 처음부터 있던 간선 값 | 간선 둘을 처음 이은 경로 |
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「짚고 가기 — 행을 건너뛰는 줄을 빼도 답은 안 틀린다」, 「불변식」,
「최악을 만드는 입력」을 다시 보세요.

- 행을 건너뛰는 줄을 빼도 답이 안 틀리고 기본 연산만 늘었습니다. 그렇다면 **열** 쪽에도 같은 판정을 넣어
  `dist[k][v]` 가 `INF` 인 `v` 를 건너뛰면 어떻게 될까요? 답이 갈리는지 기본 연산이 갈리는지를 먼저 예측하고, 전개의
  T2 에서 건너뛸 열이 몇 개인지 세어 보세요.
- 라운드의 차례를 `k = V−1` 부터 `0` 까지 거꾸로 두면 무엇이 나올지 예측해 보세요. 층의 정의를 「중간 정점의 번호가
  `k` 이상」으로 바꿔 적어 보면 그 차례에서도 같은 점화식이 성립하는지가 나오고, 거기서 답이 갈리는지까지 이어집니다.
- 별 모양이 `V³` 을 정확히 채웠습니다. 간선을 그보다 더 줄이면서 같은 값을 만들 수 있을까요? 라운드 0 에서 모든 줄이
  들어오려면 `dist[u][0]` 이 전부 유한해야 하므로 0 으로 들어오는 간선이 `V−1` 개 필요하고, 뒤 라운드가 이어지려면 0
  에서 나가는 간선도 있어야 합니다. 그 둘이 간선 수의 아래 끝을 정해요.

### Floyd-Warshall 모든 쌍 최단 경로

풀 파일: [`floydWarshall.ts`](./floydWarshall.ts) · 테스트: [`floydWarshall.test.ts`](./floydWarshall.test.ts) · 실행: `bun test src/algorithms/shortest-path/floydWarshall/floydWarshall.test.ts`

#### 한 줄 요약

> 함수는 음수 간선을 포함할 수 있는 그래프를 받아 모든 정점 쌍 사이의 최단 거리를 담은 2차원 배열을 반환한다.

#### 스토리

도시 계획 연구원 태연은 도시 내 모든 지역 간 이동 비용을 분석해야 한다. 어떤 구간은 보조금이 지급되어 음수 비용이 발생하기도 한다. 단, 전체 구간을 순환해도 계속 이득이 발생하는 구간은 없다고 가정한다.

태연이 필요한 것은 특정 두 지점 간의 경로가 아니라, 모든 지역 쌍 사이의 최솟값 표다. 이 표가 있으면 어떤 출발지와 목적지의 조합이든 즉시 최소 비용을 조회할 수 있다.

지역 수가 수백 개이므로, 모든 쌍의 최단 거리를 한 번에 계산하는 방법이 필요하다.

#### 함수 인터페이스

```ts
export function floydWarshall(
  n: number,
  edges: [number, number, number][],
): number[][];
```

- `n` — 정점 수. 정점 번호는 $0$부터 $n - 1$.
- `edges` — 방향 간선 목록. 각 원소는 $[u, v, w]$ 형태이며 가중치 $w$ (음수 허용)인 방향 간선 $u \to v$.
- 반환 — 크기 $n \times n$인 2차원 배열 $D$. $D[u][v]$는 $u \to v$의 최단 거리. 도달할 수 없는 쌍은 `Infinity`. $D[v][v] = 0$.

#### 제약 조건

- $1 \leq V \leq 500$ (정점 수)
- $0 \leq E \leq V \cdot (V - 1)$ (간선 수)
- $-10^6 \leq w(u, v) \leq 10^6$ (가중치; 음수 허용)
- 음수 사이클은 존재하지 않는다
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

음수 가중치를 포함할 수 있는 방향 그래프 $G = (V, E)$가 주어진다 (단, 음수 사이클 없음). 모든 정점 쌍 $(u, v)$에 대한 최단 거리 $d(u, v)$를 구하라.

최단 거리는 경로 위 간선 가중치의 합이 최소인 경로 비용으로 정의된다.

- 모든 $v$에 대해 $D[v][v] = 0$이다.
- 도달할 수 없는 쌍의 거리는 `Infinity`다.
- 동일한 두 정점 사이에 다중 간선이 있으면 더 작은 가중치를 사용한다.
- 방향 그래프이므로 $D[u][v] \neq D[v][u]$일 수 있다.

#### 예시

```ts
// 음수 간선 포함, 간접 경로가 더 짧은 경우
const edges: [number, number, number][] = [
  [0, 1, 3],
  [1, 2, 2],
  [0, 2, 10],
  [2, 0, 4],
];
floydWarshall(3, edges);
// [
//   [0, 3, 5],   — 0→2: 0→1→2 = 5 (직접 간선 10보다 짧음)
//   [6, 0, 2],   — 1→0: 1→2→0 = 6
//   [4, 7, 0],   — 2→1: 2→0→1 = 7
// ]

// 도달 불가능한 쌍은 Infinity
floydWarshall(3, [[0, 1, 1]]);
// [
//   [0,        1,        Infinity],
//   [Infinity, 0,        Infinity],
//   [Infinity, Infinity, 0       ],
// ]

// 간선이 없는 그래프: 대각선만 0
floydWarshall(2, []);
// [
//   [0,        Infinity],
//   [Infinity, 0       ],
// ]

// 방향성: u→v와 v→u 거리는 독립적
floydWarshall(2, [[0, 1, 3], [1, 0, 7]]);
// [
//   [0, 3],
//   [7, 0],
// ]
```
