# 다익스트라 — 우선순위 큐에서 거리가 가장 작은 정점을 꺼내면 그 거리가 이미 최단인 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 경로를 전부
나열하는 방법에서 출발해, 거리가 가장 작은 정점부터 하나씩 확정하는 방법까지 갑니다. 그 방법을 준비되는
차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

간선마다 0 이상의 수가 붙은 방향 그래프를 생각해 봅시다. 간선에 붙은 수를 **가중치**라고 부르고, 경로
하나의 **비용**은 그 경로가 지나는 간선의 가중치를 모두 더한 값입니다. 시작 정점 `src` 에서 정점 `v` 까지
가는 경로 중 비용이 가장 작은 것의 비용을 `v` 까지의 **최단 거리**라고 해요. 이 글의 절차는 시작 정점 하나에서
모든 정점까지의 최단 거리를 한 번에 구합니다. 정점 여섯 · 간선 일곱인 그래프에서 정점 0 을 시작 정점으로
두고 최단 거리를 정점 안에 적으면 이렇습니다.

<!--fig:concept-graph-->
![전개 입력 — 간선 옆 수는 가중치, 정점 안의 수는 정점 0 에서의 최단 거리](./figs/concept-graph.svg)

굵은 실선은 최단 거리를 만든 간선입니다. 정점 5 는 들어오는 간선이 하나도 없어 갈 길이 없고, 이 글은
그 자리에 `Infinity` 를 적어 「도달할 수 없다」를 나타냅니다. 정점 1 의 최단 거리는 곧장 가는 간선의 가중치
4 가 아니라 3 이에요. 정점 1 과 4 로 가는 경로를 전부 늘어놓으면 이렇습니다.

<!--proof:conceptPaths-->

| 도착 정점 | 경로 | 간선 수 | 비용 | 비용이 |
| --- | --- | ---: | ---: | --- |
| 1 | 0→1 | 1 | 4 |  |
| 1 | 0→2→1 | 2 | 3 | 가장 작다 |
| 1 | 0→2→3→4→1 | 4 | 16 |  |
| 4 | 0→1→3→4 | 3 | 8 |  |
| 4 | 0→2→1→3→4 | 4 | 7 | 가장 작다 |
| 4 | 0→2→3→4 | 3 | 9 |  |

정점 1 까지는 간선 하나짜리 경로의 비용이 4 이고 가장 작은 비용은 3 입니다. 정본이 낸 거리는 dist[1] = 3 · dist[4] = 7 입니다.

<!--/proof-->

간선을 하나 더 지나는 경로가 비용이 더 작을 수 있습니다. 그래서 가중치가 없는 그래프에서 쓰는 너비 우선 탐색(가까운 정점부터 한 겹씩
넓혀 가는 순회)처럼 「처음 만난 순간의 값이 곧 답」이라고 할 수 없어요. 이 절차는 정점마다 **지금까지 찾은 가장 작은 비용** `dist[v]` 를 들고, 더 작은
비용을 찾을 때마다 고쳐 적습니다. 간선 `u → v` 하나를 보고 `dist[u] + w` 가 `dist[v]` 보다 작으면
`dist[v]` 를 그 값으로 고치는 일을 **완화**라고 불러요. 정점 1 은 처음에 간선 `0 → 1` 로 4 를 받았다가,
간선 `2 → 1` 을 완화할 때 `1 + 2 = 3` 으로 고쳐집니다.

그러면 언제 `dist[v]` 가 더는 안 줄어든다고 믿을 수 있을까요? 답은 **거리가 가장 작은 정점부터 처리하는
것**입니다. 가중치가 음수가 아니라서, 지금 가장 작은 값을 가진 정점으로 가는 다른 길은 그 값 이상인 곳을
거쳐야 하고 간선을 더 지날수록 비용은 커지기만 해요. 그래서 그 정점의 값은 그 순간 답으로 굳혀도 됩니다.
이것을 정점을 **확정**한다고 부릅니다. 그림 아래 두 줄이 이 글의 절차가 정점을 확정한 차례와 그때의
거리이고, 거리가 한 번도 줄지 않고 커지기만 합니다. 거리가 가장 작은 정점을 매번 골라 내는 장치가 **우선순위 큐**입니다. 항목마다 키가 붙어 있고, 꺼낼 때
**키가 가장 작은 항목**을 먼저 내주는 목록이에요. 이 절차는 항목 하나를 `(정점, 그때 적은 거리)` 로 넣고,
그 거리를 키로 씁니다. 이 글은 우선순위 큐를 배열 하나로 된 **이진 힙**으로 만들어요. 할 일을 나누어
보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선 하나를 꼬리 정점의 목록에 한 번 넣는다 | 간선마다 한 번 |
| 우선순위 큐에서 꺼내기 | 키가 가장 작은 항목을 꺼내 그 정점을 확정한다 | 넣은 항목마다 한 번, 한 번에 `log` 번의 비교 |
| 완화 | 확정한 정점에서 나가는 간선마다 `dist` 를 고칠지 본다 | 간선마다 한 번 |
| 우선순위 큐에 넣기 | 완화가 값을 고쳤을 때만 새 항목을 넣는다 | 간선마다 많아야 한 번, 한 번에 `log` 번의 비교 |
| 모두 | | `O((V + E) log E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **방향 간선과 이웃 목록.** 간선 하나를 `[u, v, w]` 세 수로 적고 죽 늘어놓은 것이 간선 목록이고, 그것을
  꼬리 정점별로 모아 한 정점에서 나가는 간선을 바로 찾게 만든 것이 이웃 목록입니다. `u → v` 로 적힌
  간선은 `u` 에서 `v` 쪽으로만 씁니다. 모르면
  [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **너비 우선 탐색으로 구하는 최단 거리.** 간선에 가중치가 없는 그래프에서 큐로 거리를 채우는 방법입니다. 이
  글은 그 방법이 가중치가 붙으면 왜 부족한지에서 출발해요. 모르면
  [`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) 를 먼저 보세요.
- **우선순위 큐와 이진 힙.** 키가 가장 작은 항목을 먼저 내주는 목록이고, 이진 힙은 그것을 배열 하나로
  만드는 흔한 방법입니다. 넣기와 꺼내기가 각각 항목 수의 `log` 번 비교로 끝나요. 자료구조 자체가 궁금하면
  [`minHeap` 가이드](../../../data-structures/heap/minHeap/minHeap-guide.mdx)를 보세요.
- **`Infinity` 와의 비교와 덧셈.** 아직 길을 못 찾은 상태를 `Infinity` 로 두면 「어떤 유한한 값도 그보다
  작다」가 그대로 성립합니다. 그래서 처음 값을 적는 갈래를 따로 쓰지 않아도 됩니다.

이름이 비슷한 과제 넷을 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 가중치 | 이 글에서 |
| --- | --- | --- |
| 시작 정점 하나에서 모든 정점까지의 최단 거리 | 0 이상 | 다룬다 |
| 시작 정점 하나에서 간선을 가장 적게 지나는 거리 | 없음 | 다루지 않는다 — [`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) |
| 시작 정점 하나에서의 최단 거리 | 음수가 있다 | 다루지 않는다 — [`bellmanFord`](../bellmanFord/bellmanFord-guide.md) |
| 모든 정점 쌍 사이의 최단 거리 | 음수가 있어도 된다 | 다루지 않는다 — [`floydWarshall`](../floydWarshall/floydWarshall-guide.md) |

### 아이디어를 떠올리는 과정 — 경로 전부 나열하기에서 거리가 가장 작은 정점부터 확정하기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수, 간선 목록, 시작 정점을
받아서 모든 정점까지의 최단 거리를 돌려줍니다.

```ts
function dijkstra(n: number, edges: [number, number, number][], src: number): number[];
```

- 입력: 정점 수 `n`, 원소가 `[u, v, w]` 인 방향 간선 목록 `edges`, 시작 정점 `src`. 정점 번호는 `0` 부터
  `n − 1` 이고, 가중치 `w` 는 0 이상입니다.
- 출력: 길이 `n` 인 배열. `v` 번째 칸에 `src` 에서 `v` 까지의 최단 거리가 들어가고, 갈 수 없으면
  `Infinity`, `src` 자신은 `0` 입니다.
- 규모: `1 ≤ V ≤ 100,000`, `0 ≤ E ≤ 200,000`, `0 ≤ w ≤ 10^9`. 비용은 흔한 채점 환경의 예산인 시간 1 초,
  메모리 256 MB 에 대어 잽니다.

이 글이 쓰는 기호는 여덟 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점의 개수. 코드의 `n` 입니다 | `1 ≤ V ≤ 100,000` |
| `E` | 간선의 개수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 200,000` |
| `src` | 시작 정점의 번호 | `0 ≤ src ≤ V−1` |
| `u` · `v` | 정점 번호. 간선 `u → v` 를 읽는 자리에서 `u` 가 꼬리, `v` 가 머리입니다 | `0` 부터 `V−1` |
| `w` | 간선 `u → v` 의 가중치 | `0 ≤ w ≤ 10^9` |
| `dist[v]` | 코드가 지금 들고 있는 값. `src` 에서 `v` 로 가는 **실재하는 경로 하나**의 비용입니다 | 길이 `V` 인 배열 |
| `opt(v)` | `src` 에서 `v` 까지의 **진짜 최단 거리**. `dist[v]` 가 끝내 같아져야 하는 값입니다 | 정점마다 하나 |
| `d` | 우선순위 큐에서 꺼낸 항목의 키. 그 항목을 넣던 시점의 `dist[u]` 입니다 | 수 하나 |

`dist[v]` 와 `opt(v)` 를 가르는 것이 이 글의 뼈대입니다. 앞은 지금까지 찾은 값이고 뒤는 그 값이 결국
같아져야 할 목표예요. 꺼낸 키 `d` 는 **넣던 시점의** `dist[u]` 라서, 그 사이에 `dist[u]` 가 더 작아졌으면
둘이 어긋납니다.

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 최단 거리는 경로의 비용 중 가장 작은 것이니,
**시작 정점에서 나가는 경로를 전부 만들어** 도착 정점마다 가장 작은 비용을 고릅니다. 그것이 벅차면 그다음
후보는 **간선 목록 전체를 라운드마다 다시 읽으며** `dist[u] + w` 가 `dist[v]` 보다 작으면 고치고, 한
라운드가 아무것도 못 고칠 때 멈추는 방법이에요. 둘 다 답은 맞습니다. 비용을 재려고 두 방법에 가장 불리한
그래프를 하나씩 골랐어요. 경로 나열에는 다이아몬드 넷(`a→b` · `a→c` · `b→d` · `c→d`)을 한 줄로 이은
**다이아몬드 사슬**을, 라운드 방식에는 사슬 `0 → 1 → …` 을 간선 목록 뒤에서부터 적은 **거꾸로 놓은
사슬**을 씁니다.

<!--proof:naiveScale-->

| 입력 | 정점 V | 간선 E | 센 값 | 센 방법 |
| --- | ---: | ---: | --- | --- |
| 다이아몬드 사슬 | 7 | 8 | 끝 정점까지의 경로 4 개 | 실행 |
| 다이아몬드 사슬 | 13 | 16 | 끝 정점까지의 경로 16 개 | 실행 |
| 다이아몬드 사슬 | 25 | 32 | 끝 정점까지의 경로 256 개 | 실행 |
| 다이아몬드 사슬 | 37 | 48 | 끝 정점까지의 경로 4,096 개 | 실행 |
| 거꾸로 놓은 사슬 | 10 | 18 | 라운드 10 번 · 간선 읽기 180 번 | 실행 |
| 거꾸로 놓은 사슬 | 100 | 198 | 라운드 100 번 · 간선 읽기 19,800 번 | 실행 |
| 거꾸로 놓은 사슬 | 1,000 | 1,998 | 라운드 1,000 번 · 간선 읽기 1,998,000 번 | 실행 |
| 다이아몬드 사슬 | 100,000 | 133,332 | 끝 정점까지의 경로 2^33,333 개 — 10,035 자리 수 | 식 |
| 거꾸로 놓은 사슬 | 100,000 | 199,998 | 라운드 100,000 번 · 간선 읽기 19,999,800,000 번 | 식 |

실행한 줄은 경로 수가 모두 2^k(k 는 다이아몬드 수), 간선 읽기가 모두 V × E 와 일치했고, 마지막 두 줄은 그 식으로 낸 값입니다. 간선 읽기 19,999,800,000 번은 1 초에 1 억 번 기준 200 초입니다.

<!--/proof-->

다이아몬드 사슬은 간선이 정점 수와 비슷한 성긴 그래프인데도 다이아몬드 하나마다 경로가 두 배가 돼요.
규모 안에서 만들 수 있는 가장 긴 다이아몬드 사슬이면 경로 수가 만 자리를 넘습니다. 라운드 방식은 약 200 억
번이라 예산 1 초의 200 배예요. 그 200 억 안에서 무엇이 되풀이되는지 봅시다. 앞의 여섯 정점 그래프를 라운드
방식으로 처리하면서 간선마다 한 일을 적었습니다.

<!--proof:roundTrace-->

| 라운드 | 간선 u→v | dist[u] + w | 그때 dist[v] | 한 일 |
| --- | --- | --- | --- | --- |
| 1 | 0→1 | 0 + 4 = 4 | Infinity | dist[1] = 4 |
| 1 | 0→2 | 0 + 1 = 1 | Infinity | dist[2] = 1 |
| 1 | 2→1 | 1 + 2 = 3 | 4 | dist[1] = 3 |
| 1 | 1→3 | 3 + 1 = 4 | Infinity | dist[3] = 4 |
| 1 | 2→3 | 1 + 5 = 6 | 4 | 그대로 |
| 1 | 3→4 | 4 + 3 = 7 | Infinity | dist[4] = 7 |
| 1 | 4→1 | 7 + 7 = 14 | 3 | 그대로 |
| 2 | 0→1 | 0 + 4 = 4 | 3 | 그대로 |
| 2 | 0→2 | 0 + 1 = 1 | 1 | 그대로 |
| 2 | 2→1 | 1 + 2 = 3 | 3 | 그대로 |
| 2 | 1→3 | 3 + 1 = 4 | 4 | 그대로 |
| 2 | 2→3 | 1 + 5 = 6 | 4 | 그대로 |
| 2 | 3→4 | 4 + 3 = 7 | 7 | 그대로 |
| 2 | 4→1 | 7 + 7 = 14 | 3 | 그대로 |

라운드 2 번 동안 간선을 14 번 읽었고, 마지막 라운드는 7 번 읽어 0 번 고쳤습니다.

<!--/proof-->

라운드 2 는 간선 일곱을 다시 읽고 하나도 고치지 않았습니다. **값이 다 정해진 정점의 간선까지 라운드마다
다시 읽는 것**이 헛일이에요. 이 그래프는 간선 순서가 마침 맞아 라운드 1 에서 값이 다 정해졌는데, 순서를
거꾸로 하면 같은 그래프에서 라운드가 늘어납니다. 그러면 정점마다 **값이 더는 안 바뀔 때 한 번만** 그 정점의
간선을 읽으면 어떨까요. 같은 그래프를 세 방식으로 처리하고 **완화 시도**(간선 하나를 읽고 `dist[u] + w` 와
`dist[v]` 를 비교한 횟수)를 세었습니다. 셋째 줄은 정점을 한 번씩 확정하며 그 정점의 간선만 읽는 방식이에요.

<!--proof:roundVsOrder-->

| 방식 | 완화 시도 | 되풀이한 단위 | 결과 dist |
| --- | ---: | --- | --- |
| 간선 목록을 라운드마다 다시 읽는다 | 14 | 라운드 2 번 | [0, 3, 1, 4, 7, Infinity] |
| 같은 방식, 간선 순서를 거꾸로 | 35 | 라운드 5 번 | [0, 3, 1, 4, 7, Infinity] |
| 정점을 한 번씩 확정하며 그 정점의 간선만 읽는다 | 7 | 꺼낸 항목 7 개 | [0, 3, 1, 4, 7, Infinity] |

세 결과가 모두 일치하고, 완화 시도는 14 · 35 · 7 번입니다. 간선은 7 개입니다.

<!--/proof-->

간선 순서만 거꾸로 했는데 라운드가 2 번에서 5 번으로, 완화 시도가 14 번에서 35 번으로 늘었습니다. 셋째 줄의
완화 시도 7 번은 이 그래프의 간선 수와 같아요. 여기서 관찰한 것은 하나입니다. **정점을 한 번씩만 확정할 수
있으면 간선도 한 번씩만 읽힙니다.**

| 방식 | 간선 하나를 읽는 횟수 | 그 횟수를 정하는 것 |
| --- | --- | --- |
| 라운드마다 다시 읽기 | 라운드 수만큼 | 값이 언제 정해지는지 모른다 |
| 정점을 한 번씩 확정하기 | 한 번 | 확정한 정점만 자기 간선을 읽는다 |

그런데 **어떤 차례로 정점을 꺼내야** 꺼낸 정점의 값이 더는 안 바뀔까요. 값을 고친 정점을 대기 목록에 넣고
하나씩 꺼내 간선을 완화하되, 꺼내는 차례만 바꿔 네 후보를 시험했습니다. 번호가 가장 작은 것, 먼저 넣은 것
(너비 우선 탐색의 큐), 나중에 넣은 것, 그리고 그때 적힌 거리 — 이것을 키로 부릅니다 — 가 가장 작은
것이에요. 넷 다 값을 고치면 그 정점을 다시 넣으므로 답은 맞고, 갈리는 것은 완화 시도입니다. 그래프는 전개
입력과, 먼저 찾은 큰 값이 나중에 작은 값으로 고쳐지는 자리가 정점마다 있는 **지름길 64**, 생성식으로 만든
**성긴 64** 셋이에요.

<!--proof:orderCandidates-->

| 꺼내는 순서 | 전개 입력 | 지름길 64 | 성긴 64 | 간선 수 E 와 |
| --- | ---: | ---: | ---: | --- |
| 번호가 가장 작은 것 먼저 | 8 | 125 | 398 | E 보다 큰 곳이 있음 |
| 먼저 넣은 것 먼저 | 10 | 186 | 244 | E 보다 큰 곳이 있음 |
| 나중에 넣은 것 먼저 | 9 | 125 | 1,265 | E 보다 큰 곳이 있음 |
| 키가 가장 작은 것 먼저 | 7 | 125 | 190 | 셋 다 E 와 같음 |
| 간선 수 E | 7 | 125 | 190 |  |

네 순서 모두 세 그래프에서 정본과 같은 답을 냈습니다. 완화 시도가 세 그래프 모두에서 간선 수와 같은 순서는 「키가 가장 작은 것 먼저」 하나입니다.

<!--/proof-->

너비 우선 탐색의 큐인 「먼저 넣은 것 먼저」는 세 그래프 모두에서 간선 수보다 많이 읽습니다. 먼저 꺼낸 정점의
값이 뒤에 더 작아져 그 정점을 다시 꺼내고, 그 간선을 또 읽기 때문이에요. 키가 가장 작은 것을 먼저 꺼낼 때만
세 그래프 모두에서 완화 시도가 간선 수와 같습니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **거리가 가장 작은 정점부터 확정하기**입니다. 우선순위 큐에서 키가 가장 작은 항목을
꺼내 그 정점을 확정하고, 확정한 정점의 간선만 완화해요. 꺼낸 정점의 값이 왜 더는 안 바뀌는지, 값을 고친
정점의 옛 항목은 어떻게 하는지, 그 우선순위 큐를 무엇으로 만드는지는 다음 절에서 실현하는 순서대로
확인합니다.

### 아이디어 상세 — 거리가 가장 작은 정점부터 확정하기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **우선순위 큐에서 키가 가장 작은 항목을 꺼내 그 정점을 확정하고,
확정한 정점에서 나가는 간선을 완화해 값이 줄어든 이웃만 새 항목으로 넣는 일을 큐가 빌 때까지 되풀이합니다.**
이 방법은 완화라는 연산 위에서 동작하는데, 가중치가 없는 그래프에서 너비 우선 탐색만 해 본 사람에게는
「한 번 적은 거리를 다시 고친다」가 낯설어요. 그래서 완화를 먼저 따로 설명하고, 그다음 실현하는 순서대로
세 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 시작값 적기 | 이웃 목록을 만들고 `dist` 를 채우고 `(src, 0)` 을 큐에 넣는다 | — |
| 큐가 빌 때까지 | 2단계 거리가 가장 작은 항목을 꺼내 확정하기 | 꺼낸 키가 `dist[u]` 와 같으면 확정, 크면 버린다 | 1단계의 `dist` 와 우선순위 큐 |
| 확정할 때마다 | 3단계 확정한 정점의 간선 완화하기 | 간선마다 `dist[v]` 를 고치고 고친 이웃만 큐에 넣는다 | 1단계의 이웃 목록 · 2단계가 확정한 정점 |

#### 먼저 알아 둘 개념 — 완화

완화는 **간선 하나를 보고, 그 간선을 이어 붙인 경로의 비용이 지금 적힌 값보다 작으면 그 값으로 고치는 일**입니다. 식으로
적으면 `dist[v] ← min(dist[v], dist[u] + w)` 예요. `dist[u]` 가 `u` 까지 가는 실재하는 경로 하나의 비용이니,
`dist[u] + w` 는 그 경로 끝에 간선 `u → v` 를 붙인 경로의 비용입니다.

##### 입력 위의 완화

전개 입력에서 이 글의 절차가 간선 일곱을 각각 한 번씩 완화했습니다. 간선 옆에 그때 계산한 `dist[u] + w` 를
적고, 값을 못 줄인 간선은 흐리게 그렸어요. 정점 안의 수는 끝난 뒤의 거리입니다.

<!--fig:build-relax-->
![간선마다 한 번씩 완화한 값 — 흐린 간선은 값을 못 줄였다](./figs/build-relax.svg)

일곱 번의 완화를 걸음 차례대로 늘어놓으면 이렇습니다.

<!--proof:relaxAll-->

| 걸음 | 간선 u→v | dist[u] + w | 그때 dist[v] | 한 일 | 남은 dist[v] |
| --- | --- | --- | --- | --- | --- |
| T2 | 0→1 | 0 + 4 = 4 | Infinity | 처음 적는다 | 4 |
| T2 | 0→2 | 0 + 1 = 1 | Infinity | 처음 적는다 | 1 |
| T3 | 2→1 | 1 + 2 = 3 | 4 | 더 작게 고친다 | 3 |
| T3 | 2→3 | 1 + 5 = 6 | Infinity | 처음 적는다 | 6 |
| T4 | 1→3 | 3 + 1 = 4 | 6 | 더 작게 고친다 | 4 |
| T6 | 3→4 | 4 + 3 = 7 | Infinity | 처음 적는다 | 7 |
| T8 | 4→1 | 7 + 7 = 14 | 3 | 그대로 둔다 | 3 |

완화 7 번 가운데 처음 적은 것이 4 번, 더 작게 고친 것이 2 번, 그대로 둔 것이 1 번입니다.

<!--/proof-->

완화에는 세 갈래가 있어요. 머리에 아직 값이 없으면 처음 적고, 있으면 더 작을 때만 고치고, 아니면 그대로
둡니다. 셋 다 「작은 쪽을 남긴다」 하나로 처리돼서 코드에서는 갈래가 하나예요.

##### 완화 하나를 읽는 법

가장 눈여겨볼 것은 이미 값이 있는 머리를 고치는 완화입니다. 그런 완화 하나를 골라 항마다 읽어 보겠습니다.

<!--proof:relaxOne-->

| 항 | 보는 것 | 값 |
| --- | --- | ---: |
| 꼬리의 거리 | dist[2] | 1 |
| 간선의 가중치 | w(2→1) | 2 |
| 간선을 이은 후보 | dist[2] + w | 3 |
| 머리에 적혀 있던 값 | dist[1] | 4 |
| 남는 값 | min(4, 3) | 3 |

T3 의 간선 2→1 입니다. 후보 3 이 적혀 있던 4 보다 작아서 dist[1] 의 값을 3 으로 고칩니다.

<!--/proof-->

꼬리의 거리에 가중치를 더한 것이 후보이고, 후보와 적혀 있던 값 중 작은 쪽이 남습니다. 후보가 크거나 같으면
아무것도 안 바뀌어요.

##### 한 정점에 적히는 값의 차례

완화는 한 정점의 값을 여러 번 고칠 수 있습니다. 정점마다 적힌 값을 차례대로 모으고, 그 값을 낸 경로를
함께 적었어요. 경로는 값을 적을 때 쓴 간선의 꼬리를 거슬러 올라가 얻은 것입니다.

<!--proof:relaxHistory-->

| 정점 | 적힌 값의 차례 | 경로와 그 비용 |
| --- | --- | --- |
| 1 | Infinity → 4 → 3 | 4 = 0→1 · 3 = 0→2→1 |
| 2 | Infinity → 1 | 1 = 0→2 |
| 3 | Infinity → 6 → 4 | 6 = 0→2→3 · 4 = 0→2→1→3 |
| 4 | Infinity → 7 | 7 = 0→2→1→3→4 |
| 5 | Infinity | 없음 |

적힌 값 6 개 가운데 그 경로의 비용과 다른 값은 0 개이고, 앞에 적힌 값보다 작지 않은 값이 뒤에 적힌 경우는 0 번입니다.

<!--/proof-->

두 관계가 모든 정점에서 성립합니다. 하나는 **적힌 값마다 그 비용을 가진 경로가 실제로 있다**는 것이에요.
그래서 `dist[v]` 는 언제나 `opt(v)` 이상입니다. 다른 하나는 **뒤에 적힌 값이 앞 값보다 늘 작다**는 것이에요.
완화는 작을 때만 고치니까요. 정점 1 과 3 은 두 번 적혔고, 두 번째 값이 첫 번째보다 작습니다.

| 관계 | 까닭 |
| --- | --- |
| `dist[v]` 는 실재하는 경로의 비용이다 | 실재하는 경로 끝에 실재하는 간선을 붙인 값만 적는다 |
| `dist[v]` 는 줄어들기만 한다 | 후보가 더 작을 때만 고친다 |
| 그래서 `dist[v] ≥ opt(v)` 가 늘 참이다 | 실재하는 경로의 비용은 가장 작은 비용 이상이다 |

##### 처음 적은 값으로 굳히는 방식과의 차이

완화를 처음 보면 너비 우선 탐색의 규칙대로 **처음 적은 값을 답으로 굳히면 되지 않나**라고 읽기 쉽습니다. 먼저
넣은 정점을 먼저 꺼내고, 이웃에 아직 값이 없을 때만 「꺼낸 정점의 거리 + 가중치」를 적는 방식이에요. 같은
입력에서 두 방식을 나란히 놓았습니다.

<!--proof:firstWrite-->

| 정점 | 처음 적은 값으로 굳힌 답 | 완화로 고친 답(정본) | 두 답 |
| --- | ---: | ---: | --- |
| 0 | 0 | 0 | 같다 |
| 1 | 4 | 3 | 어긋난다 |
| 2 | 1 | 1 | 같다 |
| 3 | 5 | 4 | 어긋난다 |
| 4 | 8 | 7 | 어긋난다 |
| 5 | Infinity | Infinity | 같다 |

여섯 정점 가운데 두 답이 어긋나는 정점은 3 개입니다.

<!--/proof-->

정점 1 이 처음 받은 값은 간선 `0 → 1` 의 4 였고, 굳히면 뒤에 찾은 3 을 받아들일 자리가 없습니다. 정점 3 과
4 는 그 잘못된 4 를 이어받아 1 씩 커졌어요. 가중치가 모두 같은 그래프에서는 먼저 만난 길이 간선을 가장 적게
지나고 그래서 가장 짧지만, 가중치가 다르면 간선을 더 지나는 길의 비용이 더 작을 수 있습니다.

| 읽는 방법 | 정점 1 에 적히는 값 | 결과 |
| --- | --- | --- |
| 처음 적은 값으로 굳힌다 | 4 하나 | 뒤에 찾은 비용이 더 작은 길을 버린다 |
| 완화로 고친다 | 4 다음에 3 | 비용이 더 작은 길을 찾을 때마다 받아들인다 |

##### 완화가 필요한 까닭

앞의 두 표가 이유를 함께 보여 줍니다. 가중치가 붙으면 「먼저 찾은 길」과 「가장 싼 길」이 다른 경우가 생기고,
어느 쪽이 먼저 나올지는 그래프가 정합니다. 그래서 값을 굳히지 않고 **들고 있다가 비용이 더 작은 길이 나오면
고치는** 연산이 있어야 해요. 그리고 이 고침이 언제 끝나는지를 정하는 것이 다음 단계들의 몫입니다. 완화가
줄 수 있는 것은 「`dist[v]` 는 실재하는 경로의 비용이고 줄어들기만 한다」까지이고, **언제 `dist[v]` 가
`opt(v)` 에 이르렀는지**는 완화만으로는 알 수 없어요.

#### 1단계 — 시작값 적기

간선 목록을 꼬리 정점별 이웃 목록으로 바꾸고, `dist` 를 전부 `Infinity` 로 채운 뒤 시작 정점만 0 을 적습니다.
그리고 우선순위 큐에 항목 `(src, 0)` 하나를 넣어요. `Infinity` 는 「아직 길을 못 찾았다」의 표기이고, 어떤
유한한 후보도 그보다 작아서 처음 적는 완화가 따로 갈래를 두지 않아도 됩니다.

<!--proof:stageStart-->

| 정점 | adj — (이웃, 가중치) | dist |
| --- | --- | --- |
| 0 | (1, 4) (2, 1) | 0 |
| 1 | (3, 1) | Infinity |
| 2 | (1, 2) (3, 5) | Infinity |
| 3 | (4, 3) | Infinity |
| 4 | (1, 7) | Infinity |
| 5 | 없음 | Infinity |

이웃 목록의 칸은 모두 7 개로 간선 수와 같고, 우선순위 큐에는 항목 (0, 0) 하나가 들어 있습니다.

<!--/proof-->

정점 5 는 이웃 목록이 비어 있고 들어오는 간선도 없어서, 이 뒤로 한 번도 값이 바뀌지 않습니다.

#### 2단계 — 거리가 가장 작은 항목을 꺼내 확정하기

우선순위 큐에서 키가 가장 작은 항목 `(u, d)` 를 꺼냅니다. 갈래는 둘이에요. `d` 가 지금의 `dist[u]` 와 같으면
그 순간 `dist[u]` 가 `opt(u)` 라서 정점 `u` 를 확정하고 3단계로 갑니다. `d` 가 `dist[u]` 보다 크면 그 항목은
`dist[u]` 가 더 작아지기 전에 넣어 둔 **뒤처진 기록**이라 버려요. 확정이 왜 맞는지를 한 시점에서 먼저
보겠습니다. T3 이 끝난 뒤의 모습이에요. 무대 아래 두 줄이 우선순위 큐이고, 꺼낼 차례대로 늘어놓은 것입니다.

<!--fig:build-settle-->
![T3 이 끝난 뒤 — 큐 맨 앞의 키가 남은 키 중 가장 작다](./figs/build-settle.svg)

큐 맨 앞은 `(1, 3)` 이고 다음은 `(1, 4)` · `(3, 6)` 입니다. 정점 1 로 가는 다른 길이 처음 만나는 확정 안 된
정점은 확정한 정점에서 간선 하나로 이어진 곳이라, 이미 큐 안에서 3 이상의 키로 기다리고 있어요. 그 정점에서
간선을 더 지나면 가중치가 0 이상이라 비용이 줄지 않습니다. 그러니 비용이 3 보다 작은 길이 뒤에 나올 수 없어요. 전개
입력의 꺼내기 일곱 번을 전부 적으면 이렇습니다.

<!--proof:stagePop-->

| 걸음 | 꺼낸 항목 | 그때 dist[u] | 판정 | 꺼낸 뒤 큐에 남은 키 |
| --- | --- | --- | --- | --- |
| T2 | (0, 0) | 0 | 키 = dist[u] — 확정 | 없음 |
| T3 | (2, 1) | 1 | 키 = dist[u] — 확정 | 4 |
| T4 | (1, 3) | 3 | 키 = dist[u] — 확정 | 4 6 |
| T5 | (1, 4) | 3 | 키 > dist[u] — 뒤처진 기록 | 4 6 |
| T6 | (3, 4) | 4 | 키 = dist[u] — 확정 | 6 |
| T7 | (3, 6) | 4 | 키 > dist[u] — 뒤처진 기록 | 7 |
| T8 | (4, 7) | 7 | 키 = dist[u] — 확정 | 없음 |

꺼낸 키는 차례로 0 1 3 4 4 6 7 이고 앞보다 작아진 적이 0 번입니다. 확정한 거리는 차례로 0 1 3 4 7 이고, 확정한 뒤 거리가 다시 바뀐 정점은 0 개입니다.

<!--/proof-->

꺼낼 때마다 큐에 남은 키가 모두 꺼낸 키 이상이었습니다. 3단계가 새로 넣는 키도 꺼낸 키에 0 이상의 가중치를
더한 것이라 꺼낸 키보다 작을 수 없어요. 그래서 **꺼낸 키는 줄지 않는 차례로 나오고**, 확정한 거리도 한 번
적힌 뒤로 바뀌지 않습니다. 뒤처진 기록을 꺼낸 두 걸음(T5 · T7)은 키가 그 정점의 확정한 거리보다 커서
판정이 「버린다」로 갈렸어요.

| 꺼낸 키와 `dist[u]` | 뜻 | 하는 일 |
| --- | --- | --- |
| `d = dist[u]` | 이 항목이 그 정점의 가장 새 값이고, 남은 키 중 가장 작다 | 확정하고 3단계로 |
| `d > dist[u]` | 더 작은 값으로 고치기 전에 넣은 항목이다 | 이웃을 안 보고 버린다 |

#### 3단계 — 확정한 정점의 간선 완화하기

확정한 정점 `u` 의 이웃 목록을 읽으며 간선마다 완화합니다. 값이 줄어든 이웃 `v` 만 새 항목 `(v, dist[v])` 로
우선순위 큐에 넣어요. 쉬운 경우는 처음 값을 적는 이웃이고, 불안한 경우는 **이미 큐에 항목이 있는 이웃의 값을
더 작게 고칠 때**입니다. 그 옛 항목을 어떻게 할까요? 이 글은 지우지 않고 그대로 둡니다. 옛 항목은 키가 지금
적힌 값보다 커서 2단계가 꺼내는 자리에서 뒤처진 기록으로 걸러 내요. 걸음마다 넣은 항목과, 걸음이 끝난 뒤
큐에 남은 항목을 꺼낼 차례대로 적었습니다.

<!--proof:stageQueue-->

| 걸음 | 넣은 항목 | 걸음이 끝난 뒤 큐 — 꺼낼 차례 | 그중 뒤처진 기록 |
| --- | --- | --- | --- |
| T1 | (0, 0) | (0, 0) | 없음 |
| T2 | (1, 4) (2, 1) | (2, 1) (1, 4) | 없음 |
| T3 | (1, 3) (3, 6) | (1, 3) (1, 4) (3, 6) | (1, 4) |
| T4 | (3, 4) | (1, 4) (3, 4) (3, 6) | (1, 4) (3, 6) |
| T5 | 없음 | (3, 4) (3, 6) | (3, 6) |
| T6 | (4, 7) | (3, 6) (4, 7) | (3, 6) |
| T7 | 없음 | (4, 7) | 없음 |
| T8 | 없음 | 비어 있음 | 없음 |

넣은 항목은 7 개이고 꺼낸 항목도 7 개라 큐가 비었습니다. 뒤처진 기록은 가장 많을 때 2 개가 함께 있었습니다. 확정한 정점은 5 개이고, 한 번도 큐에 안 들어간 정점 5 의 거리는 Infinity 로 남았습니다.

<!--/proof-->

T3 에서 정점 1 의 값이 4 에서 3 으로 줄면서 `(1, 3)` 이 들어가고, 먼저 들어가 있던 `(1, 4)` 는 뒤처진 기록이
됐습니다. T4 에서는 정점 3 이 같은 일을 겪어요. 옛 항목들은 큐 뒤쪽에 남아 있다가 T5 · T7 에 꺼내져
버려졌습니다. 반복이 끝나는 까닭은 종료 조건으로 말할 수 있어요. 항목은 넣을 때만 늘고 꺼낼 때만 주는데,
넣는 일은 완화가 값을 고칠 때뿐이고 값은 줄어들기만 하므로 넣는 횟수에 끝이 있습니다. 큐가 비었다는 것은 넣은
항목을 하나도 남김없이 꺼냈다는 뜻이고, 그래서 확정할 수 있는 정점은 모두 확정됐어요.

#### 이 방법이 기대는 전제

확정이 맞는 근거는 2단계에서 본 「간선을 더 지나면 비용이 줄지 않는다」 하나이고, 그것은 **가중치가 0
이상**이라는 전제에서 나옵니다. 가중치에 음수가 하나 들어가면 이 전제가 깨져요. 음수 간선이 하나 있는 두
입력에 이 글의 코드를 그대로 실행했습니다.

<!--proof:premiseNegative-->

| 입력 | 두 번 확정한 정점 | 완화 시도 | 간선 수 | 정본의 답 | 경로를 전부 만든 답 |
| --- | --- | ---: | ---: | --- | --- |
| 0->1(0) 0->2(1) 2->1(-5) 1->3(0) | 1 · 3 | 5 | 4 | [0, -4, 1, -4] | [0, -4, 1, -4] |
| 0->1(2) 0->2(3) 2->1(-2) 1->3(1) | 1 | 5 | 4 | [0, 1, 3, 2] | [0, 1, 3, 2] |

두 입력 모두 한 번 확정한 정점을 뒤에서 더 작은 키로 다시 꺼내 확정했고, 완화 시도가 간선 수보다 많습니다.

<!--/proof-->

두 입력 모두 답은 맞게 나왔는데, 그것은 옛 항목을 지우지 않고 값이 줄면 다시 넣는 이 코드의 모양 덕분입니다.
**확정했다는 판단은 틀렸어요.** 첫 입력에서 정점 1 은 키 0 으로 확정된 뒤 음수 간선 `2 → 1` 때문에 -4 로 다시
줄었고, 그래서 한 번 더 꺼내졌습니다. 완화 시도가 간선 수보다 많아졌으니 「간선을 한 번씩만 읽는다」는 비용
보장도 사라졌어요. 음수 가중치가 있으면 확정을 쓰지 않는 다른 절차가 필요합니다.

| 전제 | 쓰이는 곳 | 깨지면 |
| --- | --- | --- |
| 가중치가 0 이상이다 | 2단계의 확정 판정 · 3단계가 넣는 키가 꺼낸 키 이상이라는 것 | 확정한 정점의 값이 다시 줄어 그 정점을 또 꺼낸다 |
| 옛 항목은 키가 `dist` 보다 크다 | 2단계에서 뒤처진 기록을 알아보는 판정 | 걸러 낼 기준이 없어 같은 정점을 여러 번 처리한다 |

#### 우선순위 큐를 이진 힙으로 만드는 까닭

남은 것은 「키가 가장 작은 항목」을 **무엇으로 고르느냐**입니다. 항목을 배열에 담아 두고 꺼낼 때마다 처음부터
읽어 가장 작은 것을 찾는 방법과, 이진 힙에 담아 두는 방법 둘을 같은 그래프들에 적용하고 고르느라 비교한 횟수를
세었어요.

<!--proof:heapVsScan-->

| 정점 V | 간선 E | 완화 시도 | 배열에서 찾기 | 이진 힙 | 몇 배 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 46 | 46 | 102 | 86 | 1.2 배 |
| 64 | 190 | 190 | 1,429 | 524 | 2.7 배 |
| 256 | 766 | 766 | 26,777 | 3,708 | 7.2 배 |
| 1,024 | 3,070 | 3,070 | 347,162 | 17,551 | 19.8 배 |

네 규모 모두 두 방법의 완화 시도와 답이 일치했고, 갈린 것은 고르느라 비교한 횟수뿐입니다.

<!--/proof-->

정점이 열여섯이면 1.2 배라 차이가 없다시피 한데, 1,024 개가 되면 19.8 배입니다. 배열에서 찾기는 꺼낼 때마다
큐에 든 항목을 전부 읽고, 이진 힙은 넣고 꺼낼 때 트리의 높이만큼만 비교하기 때문이에요. 정점이 더 늘수록
차이도 더 벌어지므로 우선순위 큐를 이진 힙으로 만듭니다. 이진 힙을 코드로 옮기는 일은 「수행으로 알아보는
알고리즘」의 2. 에서 합니다.

| 우선순위 큐를 만드는 방법 | 꺼낼 때 | 넣을 때 |
| --- | --- | --- |
| 배열에서 찾기 | 항목 전부를 읽는다 | 끝에 붙인다 |
| 이진 힙 | 트리 높이만큼 비교한다 | 트리 높이만큼 비교한다 |

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 셋째와 넷째가 반복 한 바퀴예요. 라운드 방식이면
약 200 억 번이던 간선 읽기가 간선 수 `E` 번이 됩니다.

1. 간선 목록을 이웃 목록 `adj` 로 바꾸고, `dist` 를 `Infinity` 로 채운 뒤 `dist[src] = 0`, 큐에 `(src, 0)` 을 넣는다
2. 큐가 빌 때까지 키가 가장 작은 항목 `(u, d)` 를 꺼낸다
3. `d` 가 `dist[u]` 보다 크면 버리고 2 로 돌아간다
4. `u` 에서 나가는 간선 `(v, w)` 마다 `d + w` 가 `dist[v]` 보다 작으면 고쳐 적고 `(v, d + w)` 를 넣는다
5. 큐가 비면 `dist` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 여섯 정점을 아홉 걸음으로 확정한다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 그래프 하나를 정해 끝까지 가져가되, 코드
조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

<!--proof:walkInput-->

```ts
const n = 6;
const edges: [number, number, number][] = [
  [0, 1, 4], [0, 2, 1], [2, 1, 2], [1, 3, 1], [2, 3, 5], [3, 4, 3], [4, 1, 7],
];
const src = 0;
// 이 절이 끝나면 나와야 하는 값: [0, 3, 1, 4, 7, Infinity]
```

왜 이 여섯 정점을 골랐을까요? **네 갈래가 한 입력에서 전부 실행되기** 때문입니다. 처음 값을 적는 완화
(`0→1` · `0→2`), 이미 적힌 값을 더 작게 고치는 완화(`2→1` · `1→3`), 고칠 것이 없는 간선(`4→1`), 뒤처진 기록을
버리는 갈래(정점 1 과 3 을 두 번째로 꺼낼 때) 넷이에요. 정점 5 가 `Infinity` 로 남아 도달하지 못하는 자리도
함께 나옵니다.

```text
절차 전체를 한 장으로

  T1     dist 를 Infinity 로 채우고 dist[src] = 0 을 적는다        ① 시작값
         이웃 목록을 만들고 (src, 0) 을 큐에 넣는다
         큐에 항목이 남아 있는 동안:                              ② 반복 조건
  T2~T8    키가 가장 작은 항목 (u, d) 를 꺼낸다
           d 가 dist[u] 보다 크면 버린다                          ③ 뒤처진 기록
           u 의 간선마다 d + w 로 완화하고, 고치면 큐에 넣는다    ④ 완화
  T9     dist 를 돌려준다
```

#### 1. 거리 배열과 이웃 목록을 시작값으로 둔다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 거리 배열을 `Infinity` 로 채우고, 간선 목록을 이웃 목록으로 바꾸고,
시작 정점만 0 을 적은 뒤 우선순위 큐에 항목 하나를 넣어요. 코드에서는 거리 배열이 `dist`, 이웃 목록이 `adj`,
우선순위 큐가 `pq` 입니다.

```ts
const dist: number[] = Array.from({ length: n }, () => Number.POSITIVE_INFINITY);
const adj: [number, number][][] = Array.from({ length: n }, () => []);
for (const [u, v, w] of edges) (adj[u] as [number, number][]).push([v, w]);

dist[src] = 0;                    // ① 시작 정점만 0 이다
const pq = new MinHeap();
pq.push(src, 0);                  // ① 항목 하나로 시작한다
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walkT1-->

```text
T1 이 끝난 시점
  dist  [0, Infinity, Infinity, Infinity, Infinity, Infinity]
  adj   0:[(1, 4) (2, 1)]  1:[(3, 1)]  2:[(1, 2) (3, 5)]  3:[(4, 3)]  4:[(1, 7)]  5:[]
  pq    (0, 0)
```

`①` 의 두 줄이 뜻하는 것이 다릅니다. 하나는 「`src` 까지 가는 비용이 0 이다」이고, 다른 하나는 「그 사실에서
출발해 이웃을 볼 차례가 남았다」예요.

#### 짚고 가기 — 같은 정점을 큐에 두 번 넣지 않으려 막으면 답이 틀린다

여기서 헷갈리기 쉬운 포인트는 **큐에 같은 정점이 여러 번 들어간다**는 것입니다. 「정점 하나에 항목 하나면
충분하지 않나, 이미 들어 있으면 안 넣으면 되지」로 읽기 쉬워요. 그 생각대로 큐에 들어 있는지를 표시하는
배열을 하나 더 두고 막아 봅시다.

```ts
const inBag = Array.from({ length: n }, () => false);
// … 완화하는 자리에서
if (nd < (dist[v] as number)) {
  dist[v] = nd;
  if (inBag[v] === true) continue;   // 이미 큐에 있으면 안 넣는다
  inBag[v] = true;
  bag.push([v, nd]);
}
```

세 입력으로 확인해 봅니다.

<!--proof:pauseNoDuplicate-->

| 입력 | 정본이 낸 답 | 중복을 막은 답 | 두 답 |
| --- | --- | --- | --- |
| 전개 입력 | [0, 3, 1, 4, 7, Infinity] | [0, 3, 1, 6, 9, Infinity] | 어긋난다 |
| 삼각형 0->1->2, 0->2 | [0, 2, 5] | [0, 2, 5] | 같다 |
| 사슬 0->1->2->3 (가중치 2) | [0, 2, 4, 6] | [0, 2, 4, 6] | 같다 |

전개 입력에서 `dist[3]` 이 4 가 아니라 6, `dist[4]` 가 7 이 아니라 9 로 나옵니다. 두 판이 꺼낸 항목을 차례로
놓으면 갈리는 자리가 보여요.

<!--proof:pauseNoDuplicateWhere-->

| 꺼낸 차례 | 정본 | 중복을 막은 판 |
| --- | --- | --- |
| 1 | (0, 0) 확정 | (0, 0) 확정 |
| 2 | (2, 1) 확정 | (2, 1) 확정 |
| 3 | (1, 3) 확정 | (1, 4) 버림 |
| 4 | (1, 4) 버림 | (3, 6) 확정 |
| 5 | (3, 4) 확정 | (4, 9) 확정 |
| 6 | (3, 6) 버림 | — |
| 7 | (4, 7) 확정 | — |

정점 1 을 확정한 횟수는 정본이 1 번, 중복을 막은 판이 0 번입니다.

<!--/proof-->

세 번째 꺼내기에서 갈립니다. 정점 1 의 값이 4 에서 3 으로 줄었는데, 막은 판은 이미 `(1, 4)` 가 들어 있다며
`(1, 3)` 을 넣지 않았어요. 그 `(1, 4)` 를 꺼내면 키 4 가 `dist[1] = 3` 보다 커서 버려지고, 정점 1 은 한 번도
확정되지 않습니다. 간선 `1 → 3` 이 아예 완화되지 않아 정점 3 과 4 가 비용이 더 큰 길의 값에 머물러요. 삼각형과
사슬에서는 답이 안 틀린다는 것도 봐 주세요. 큐에 든 정점의 값을 다시 고칠 일이 없는 그래프라서, 그런 입력만
시험하면 이 실수가 통과합니다.

#### 2. 키가 가장 작은 항목을 내주는 이진 힙을 만든다

둘째 조각은 우선순위 큐입니다. 배열 하나로 완전 이진 트리를 담고, 자리 `i` 의 부모를 `(i-1)/2` 의 몫으로
둡니다. 넣을 때는 맨 끝에 두고 부모보다 작은 동안 부모와 맞바꿔 올려요.

```ts
push(node: number, key: number): void {
  this.items.push([node, key]);
  let i = this.items.length - 1;
  while (i > 0) {
    const parent = (i - 1) >> 1;
    if (this.key(i) >= this.key(parent)) break;   // 부모가 더 작거나 같으면 자리를 지킨다
    this.swap(i, parent);
    i = parent;
  }
}
```

꺼낼 때는 뿌리를 내주고, 마지막 항목을 뿌리로 옮긴 뒤 자식 중 작은 쪽보다 크면 맞바꿔 내립니다. 키 넷을
넣고 한 번 꺼내면 배열이 이렇게 바뀌어요.

<!--proof:walkHeap-->

```text
키 4 · 3 · 6 · 1 을 차례로 넣고 한 번 꺼낸다 — 배열에 놓인 순서 그대로
  넣기 전        []
  4 를 넣은 뒤   [4]
  3 을 넣은 뒤   [3, 4]
  6 을 넣은 뒤   [3, 4, 6]
  1 을 넣은 뒤   [1, 3, 6, 4]
  한 번 꺼낸 뒤  [3, 4, 6]  꺼낸 키 1

꺼낸 뒤 부모가 자식 이하인 자리 2 / 2
```

배열이 정렬돼 있지 않다는 것을 봐 주세요. 이 자료구조가 지키는 것은 「부모가 자식 이하다」 하나뿐이고, 그
하나만으로 뿌리가 가장 작다는 것이 나옵니다. 트리의 높이가 항목 수의 `log` 라서 넣기와 꺼내기가 그만큼의
비교로 끝나요. 그래서 이 글의 그림들은 우선순위 큐를 배열 순서가 아니라 **꺼낼 차례대로** 늘어놓습니다 —
독자가 알아야 할 것은 다음에 무엇이 나오는가이지 배열 안의 자리가 아니기 때문이에요.

#### 3. 꺼낸 정점에서 나가는 간선을 완화한다

셋째 조각이 본체입니다. 큐에서 항목을 꺼내고, 뒤처진 기록이면 버리고, 아니면 그 정점의 간선마다 `d + w` 를
만들어 지금 적힌 값보다 작을 때만 고쳐 적고 큐에 넣어요.

```ts
while (pq.size() > 0) {                      // ② 큐에 항목이 남아 있는가
  const [u, d] = pq.pop() as [number, number];
  if (d > (dist[u] as number)) continue;     // ③ 뒤처진 기록이면 버린다

  for (const [v, w] of adj[u] as [number, number][]) {
    const nd = d + w;
    if (nd < (dist[v] as number)) {          // ④ 더 작을 때만 고쳐 적는다
      dist[v] = nd;
      pq.push(v, nd);
    }
  }
}
```

`T2` 와 `T3` 만 실행하면 이렇게 나옵니다.

<!--proof:walkT2T3-->

```text
T2  꺼낸 항목 (0, 0)  0 = dist[0] 이라 확정
    0→1 완화       Infinity > 0+4 -> dist[1] = 4 · 큐에 (1, 4)
    0→2 완화       Infinity > 0+1 -> dist[2] = 1 · 큐에 (2, 1)
    큐(꺼낼 차례)  (2, 1) (1, 4)
T3  꺼낸 항목 (2, 1)  1 = dist[2] 이라 확정
    2→1 완화       4 > 1+2 -> dist[1] = 3 · 큐에 (1, 3)
    2→3 완화       Infinity > 1+5 -> dist[3] = 6 · 큐에 (3, 6)
    큐(꺼낼 차례)  (1, 3) (1, 4) (3, 6)
```

T2 가 넣은 두 항목 중 나중에 넣은 `(2, 1)` 이 먼저 나옵니다. 넣은 차례가 아니라 키가 차례를 정하기 때문이에요.
T3 이 끝나면 정점 1 짜리 항목이 둘이고, 옛 값 4 짜리는 지우지 않고 그대로 둡니다.

#### 짚고 가기 — 뒤처진 기록을 걸러 내는 줄을 빼도 답은 안 틀린다

여기서 헷갈리기 쉬운 포인트는 `③` 한 줄입니다. 「어차피 완화는 더 작을 때만 고치니, 뒤처진 기록을 꺼내도
아무것도 안 바뀌는 것 아닌가」로 읽기 쉬워요. 그 줄을 통째로 빼 봅시다.

```ts
while (pq.size() > 0) {
  const [u, d] = pq.pop() as [number, number];
  // ← `if (d > (dist[u] as number)) continue;` 줄을 지웠다
  for (const [v, w] of adj[u] as [number, number][]) {
    const nd = d + w;
    if (nd < (dist[v] as number)) { dist[v] = nd; pq.push(v, nd); }
  }
}
```

**답은 한 칸도 안 갈립니다.** 테스트가 통과하니 무엇이 달라졌는지 모르고 넘어가는 자리예요. 대신 완화 시도가
늘어납니다. 세 그래프에서 답과 계수를 함께 봤어요.

<!--proof:pauseStaleCheck-->

| 입력 | 간선 E | 줄이 있을 때 완화 시도 | 줄을 뺐을 때 완화 시도 | 두 답 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 7 | 7 | 9 | 칸마다 같다 |
| 지름길 64 | 125 | 125 | 186 | 칸마다 같다 |
| 성긴 64 | 190 | 190 | 214 | 칸마다 같다 |

전개 입력에서 늘어난 완화 시도 2 번은 뒤처진 기록을 꺼낸 T5 · T7 에서 그 정점의 이웃을 다시 읽은 수를 더한 것입니다.

<!--/proof-->

답이 안 갈리는 이유는 뒤처진 기록의 키 `d` 가 지금의 `dist[u]` 보다 크기 때문입니다. 그 키로 만든 `d + w` 는
확정한 값으로 만든 것보다 커서 `dist[v]` 를 못 줄여요. 대신 그 이웃들을 읽는 일은 그대로 듭니다. 이 한 줄이
지키는 것은 답이 아니라 **「완화 시도 = `E`」라는 등식**이고, 비용을 셀 때 그 등식이 총식의 뼈대가 됩니다.

| 그 줄 | 이웃을 보는 정점 | 완화 시도 |
| --- | --- | --- |
| 있다 | 확정한 정점만 | 간선 수 `E` 와 같다 |
| 뺐다 | 뒤처진 기록을 꺼낸 정점도 | `E` 보다 많다 |

#### 4. 아홉 걸음을 끝까지 실행한다

세 조각을 이어 고정 입력에 실행하면 아홉 걸음이 나옵니다. T1 은 준비, T2 부터 T8 까지가 큐에서 항목을
하나씩 꺼내는 반복, T9 가 반환이에요. 걸음 재생 패널에서 정점 안의 「거리」는 확정한 값, 「후보」는 아직 줄어들
수 있는 값이고, 점선 정점은 아직 값이 없는 정점입니다. 굵은 실선은 지금 그 정점의 값을 낸 간선이에요. 무대
아래 두 줄이 우선순위 큐를 꺼낼 차례대로 늘어놓은 것이고, 같은 칸의 정점과 키가 항목 하나입니다. 이번
걸음에 넣은 항목은 굵은 테로, 이미 뒤처진 기록은 대시 테로 흐리게 그렸어요.

뒤였기 때문이에요. 꺼낸 키가 0 1 3 4 4 6 7 로 한 번도 줄지 않았다는 것도 봐 주세요. 「키가 가장 작은 것부터
꺼낸다」와 「가중치가 0 이상이다」가 함께 만든 결과입니다.

#### 짚고 가기 — 꺼낸 정점을 표시해 두는 것으로 갈음해도 가중치가 0 이상이면 답이 같다

여기서 헷갈리기 쉬운 포인트는 `③` 을 **어떻게** 쓰느냐입니다. 「확정한 정점은 두 번 볼 이유가 없으니, 표시
배열을 두고 표시된 정점을 건너뛰면 되지 않나」로 읽기 쉬워요. 그 생각대로 키 비교 대신 표시로 걸러 봅시다.

```ts
const seen = Array.from({ length: n }, () => false);
// … 꺼낸 자리에서
if (seen[u] === true) continue;   // 키가 아니라 표시로 거른다
seen[u] = true;
```

가중치가 모두 0 이상인 입력입니다.

| 입력 | 정점 V | 정본의 답과 방문 표시로 갈음한 답 |
| --- | ---: | --- |
| 전개 입력 | 6 | 칸마다 같다 |
| 삼각형 0->1->2, 0->2 | 3 | 칸마다 같다 |
| 사슬 0->1->2->3 (가중치 2) | 4 | 칸마다 같다 |
| 지름길 64 | 64 | 칸마다 같다 |
| 성긴 64 | 64 | 칸마다 같다 |

가중치에 음수가 하나 들어간 입력입니다.

| 입력 | 정본이 낸 답 | 방문 표시로 갈음한 답 | 경로를 전부 만든 답 |
| --- | --- | --- | --- |
| 0->1(0) 0->2(1) 2->1(-5) 1->3(0) | [0, -4, 1, -4] | [0, -4, 1, 0] | [0, -4, 1, -4] |
| 0->1(2) 0->2(3) 2->1(-2) 1->3(1) | [0, 1, 3, 2] | [0, 1, 3, 3] | [0, 1, 3, 2] |

<!--/proof-->

**가중치가 0 이상인 입력에서는 답이 한 칸도 안 갈립니다.** 확정한 정점의 거리가 다시 줄지 않으니, 표시로 걸러도
버려지는 항목이 같아요. 그럼에도 이 글이 키로 거르는 까닭은 가중치에 음수가 섞이는 순간 두 코드가 갈리기
때문입니다. 위 둘째 표의 첫 입력에서 두 판이 꺼낸 항목을 차례로 놓았어요.

<!--proof:pauseVisitedWhere-->

| 꺼낸 차례 | 키로 거르는 판(정본) | 표시로 거르는 판 |
| --- | --- | --- |
| 1 | (0, 0) 이웃을 본다 | (0, 0) 이웃을 본다 |
| 2 | (1, 0) 이웃을 본다 | (1, 0) 이웃을 본다 |
| 3 | (3, 0) 이웃을 본다 | (3, 0) 이웃을 본다 |
| 4 | (2, 1) 이웃을 본다 | (2, 1) 이웃을 본다 |
| 5 | (1, -4) 이웃을 본다 | (1, -4) 버림 |
| 6 | (3, -4) 이웃을 본다 | — |

다섯 번째 꺼내기에서 갈립니다. 음수 간선 `2 → 1` 이 정점 1 의 값을 -4 로 줄여 `(1, -4)` 가 들어갔는데, 표시로
거르는 판은 정점 1 에 이미 표시가 있어 그 항목을 버려요. 그래서 간선 `1 → 3` 이 다시 완화되지 않고 `dist[3]` 이
0 에 머뭅니다. 키로 거르는 판은 키 -4 가 `dist[1]` 과 같아 이웃을 다시 보고 -4 를 적어요. 음수 가중치는 이
알고리즘의 전제 밖이지만(「아이디어 상세」의 「이 방법이 기대는 전제」), 키로 거르면 배열 하나를 덜 잡고 전제가
깨졌을 때도 답을 덜 망가뜨립니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 이진 힙의 `pop` 이 빈 배열에서 `undefined` 를
돌려주는 갈래뿐이에요. 반복 조건이 `size() > 0` 이라 그 갈래는 실제로 실행되지 않지만, 타입이 그것을
요구합니다.

```ts
export type Edge = [number, number, number];

export function dijkstra(n: number, edges: Edge[], src: number): number[] {
  // ① 시작값 — 아직 아무 경로도 못 찾았으므로 전부 `Infinity` 이고 시작 정점만 `0` 이다.
  const dist: number[] = Array.from(
    { length: n },
    () => Number.POSITIVE_INFINITY,
  );
  const adj: [number, number][][] = Array.from({ length: n }, () => []);
  for (const [u, v, w] of edges) (adj[u] as [number, number][]).push([v, w]);

  dist[src] = 0;
  const pq = new MinHeap();
  pq.push(src, 0);

  // ② 큐에 남은 항목이 있는가 — 없으면 더 고칠 거리가 없다.
  while (pq.size() > 0) {
    const [u, d] = pq.pop() as [number, number];

    // ③ 뒤처진 기록인가 — 꺼낸 키가 지금 적힌 거리보다 크면 그 항목은 버린다.
    if (d > (dist[u] as number)) continue;

    for (const [v, w] of adj[u] as [number, number][]) {
      const nd = d + w;
      // ④ 완화 — 지금 적힌 거리보다 작을 때만 고쳐 적고 큐에 넣는다.
      if (nd < (dist[v] as number)) {
        dist[v] = nd;
        pq.push(v, nd);
      }
    }
  }

  return dist;
}

class MinHeap {
  private items: [number, number][] = [];

  size(): number {
    return this.items.length;
  }

  push(node: number, key: number): void {
    this.items.push([node, key]);
    let i = this.items.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.key(i) >= this.key(parent)) break;
      this.swap(i, parent);
      i = parent;
    }
  }

  pop(): [number, number] | undefined {
    const top = this.items[0];
    const last = this.items.pop();
    if (top === undefined || last === undefined) return undefined;
    if (this.items.length > 0) {
      this.items[0] = last;
      let i = 0;
      for (;;) {
        const left = 2 * i + 1;
        const right = 2 * i + 2;
        let small = i;
        if (left < this.items.length && this.key(left) < this.key(small)) {
          small = left;
        }
        if (right < this.items.length && this.key(right) < this.key(small)) {
          small = right;
        }
        if (small === i) break;
        this.swap(i, small);
        i = small;
      }
    }
    return top;
  }

  private key(i: number): number {
    return (this.items[i] as [number, number])[1];
  }

  private swap(a: number, b: number): void {
    const t = this.items[a] as [number, number];
    this.items[a] = this.items[b] as [number, number];
    this.items[b] = t;
  }
}
```

실행하면 이렇게 나옵니다.

dijkstra(4, [[0,1,1],[1,2,1],[2,3,1]], 0)                                  -> [0, 1, 2, 3]

### 알아 두면 좋은 개념 — 최적 부분 구조

이 절차가 `dist[3]` 을 정한 방식에는 이름이 붙어 있습니다. T4 에서 `dist[3] = dist[1] + 1` 로 적었는데, 그것이
답이 되려면 **정점 3 까지의 최단 경로의 앞부분이 정점 1 까지의 최단 경로여야** 해요. 어떤 문제의 가장 좋은
해가 더 작은 문제의 가장 좋은 해로 이루어지는 이 성질을 **최적 부분 구조**라고 부릅니다.

앞부분 4 개 가운데 비용이 그 끝 정점의 dist 와 일치하는 것은 4 개입니다.

<!--/proof-->

앞부분마다 끝 정점의 최단 거리와 같아요. 완화가 `dist[u] + w` 로 `v` 의 후보를 만드는 것이 이 성질에 기댄
것이고, `u` 까지의 값이 최단이 아니면 그 후보가 무엇을 뜻하는지 알 수 없습니다. 같은 성질이 다른 최단 경로
알고리즘과 동적 계획법에서도 부분 문제의 모양만 바꿔 다시 나와요.

| 다른 자리 | 부분 문제 |
| --- | --- |
| 플로이드-워셜 | 가운데를 정점 `k` 까지만 써서 가는 최단 거리 |
| 벨만-포드 | 간선을 `k` 개 이하로 써서 가는 최단 거리 |
| 배낭 문제 | 앞의 `i` 개 물건과 용량 `c` 로 만드는 최대 가치 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 최단 거리와 비용 상한을 식으로 어떻게 적는지,
무엇이 매 걸음 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 가중치가 0 이상이다 | 음수가 하나라도 있으면 확정 판정이 성립하지 않는다 | 꺼낸 키가 `dist[u]` 와 같으면 다시 보지 않는다 |
| 시작 정점이 하나다 | 여러 시작 정점을 물으면 그 수만큼 다시 실행한다 | 거리 배열이 한 벌이다 |
| 간선이 정점 수의 제곱보다 훨씬 적다 | 간선이 촘촘하면 배열에서 찾는 방식이 힙보다 나을 수 있다 | 우선순위 큐가 이진 힙이다 |
| 그래프를 미리 다 받아 둘 수 있다 | 이웃 목록을 한 번 만들고 시작한다 | `adj` 를 먼저 만들고 그 뒤로는 고치지 않는다 |

첫 조건이 깨지면 무엇이 어긋나는지는 「아이디어 상세」의 「이 방법이 기대는 전제」가 값으로 보였습니다. 그때는
확정을 쓰지 않고 간선 전부를 `V−1` 번까지 되풀이해 완화하는
[`bellmanFord`](../bellmanFord/bellmanFord-guide.md) 쪽으로 가야 해요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "이동 비용" "통행료" "소요 시간" "거리"      <- 간선에 가중치가 있다
  "비용은 항상 0 이상" "음수 없음"             <- 확정 판정을 쓸 수 있다
  "한 곳에서 각 지점까지"                      <- 시작 정점이 하나다
  "가장 저렴한 경로의 비용"                    <- 경로 자체가 아니라 합이 답이다

제약에 이런 모양이 보이면
  정점이 10^5 규모이고 간선도 그 몇 배 정도다  <- 정점 수의 제곱에 드는 방식은 안 된다
  가중치가 10^9 까지 커진다                    <- 거리 합이 32 비트 정수를 넘을 수 있다

반대로 이런 말이 보이면 해당하지 않는다
  "비용이 음수일 수 있다" "이득이 나는 구간"   <- 확정 판정이 성립하지 않는다
  "모든 정점 쌍 사이의 거리"                   <- 시작 정점이 V 개다
  "간선 수를 세라" "가중치가 전부 1"           <- 너비 우선 탐색이 힙 없이 같은 답을 낸다
```

마지막 무리가 보이면 다른 절차로 갑니다. 가중치가 전부 같으면
[`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) 가 힙 없이 같은 답을 내고, 가중치가 0 과
1 두 가지뿐이면 [`zeroOneBfs`](../../graph/zeroOneBfs/zeroOneBfs-guide.md) 가 있어요. 정점 쌍 전부를 물으면
아래 「경쟁 설계와의 대조」를 봅니다.

#### 경쟁 설계와의 대조

같은 목표(시작 정점에서 모든 정점까지의 최단 거리를 아는 것)를 노리는 다른 절차로 **플로이드-워셜**이
있습니다. 정점 쌍마다 칸을 하나 두고 「가운데를 정점 `k` 로 지나면 더 작아지는가」를 모든 `(k, i, j)` 에서 한
번씩 물어, **한 번의 실행으로 모든 시작 정점의 답**을 함께 만드는 방식이에요. 시작 정점 하나를 물으면 그 표의
한 줄을 읽으면 됩니다.

| 설계 | 시작 정점 하나를 답하는 일 | 시작 정점 하나를 더하는 일 |
| --- | --- | --- |
| 이 가이드의 절차 | 그 시작 정점에서 우선순위 큐를 한 번 비운다 | 시작 정점마다 다시 한다 |
| 플로이드-워셜 | 정점 쌍 표를 한 번 만든다 | 표의 한 줄을 읽으면 끝난다 |

같은 그래프 · 같은 작업 목록에 두 설계를 적용하고 **기본 연산 수**(완화 시도 · 힙 안의 비교 · 삼중 반복 안의
비교 · 표 칸 채우기)를 `tools/bench-alt.ts` 로 세었습니다. 그래프는 정점 `V = 200` 이고 정점마다 나가는 간선을
`D = 199` 개 만들되 자기 자신으로 가는 것은 뺀 밀집 그래프예요. 정점 `i` 의 `k` 번째 이웃은
`(i·37 + k·11) mod 200` 이고 그 간선의 가중치는 `((i·29 + k·13) mod 50) + 1` 입니다. 작업 목록은 서로 다른
시작 정점 `q` 개에 거리 배열을 묻는 것이고, `q` 번째 시작 정점은 `((q−1)·7) mod 200` 이에요. **전개 입력을
그대로 쓰지 않은 이유**는 그 그래프가 정점 여섯이라 시작 정점을 여섯 개까지밖에 못 늘려서, 우열이 뒤집히는
자리를 만들 수 없기 때문입니다.

저장 칸은 이 절차가 계속 적고, 갈리는 것은 연산 수입니다. 그 경계가 이 입력에서 **시작 정점 173 개**예요. 경계가
그 자리인 까닭은 두 설계의 계수를 증가분으로 나누면 나옵니다.

<!--proof:altBoundary-->

```text
출발점 하나를 더할 때 이 절차   47,055 언저리 — 출발점 200 개의 9,410,944 을 200 으로 나눈 값

```

**이 절차가 내주는 것은 시작 정점이 여러 개인 작업입니다.** 시작 정점이 하나 늘 때마다 큐를 처음부터 다시
비워야 해서 시작 정점 하나에 드는 연산이 표의 한 줄보다 훨씬 많아요. 그 대신 얻는 것이 셋입니다. 저장 칸이 정점 쌍
표보다 훨씬 적고, 시작 정점 하나만 물으면 연산이 표 방식의 172 분의 1 쯤이며, 도달하지 못하는 정점은 큐에 한
번도 안 들어가 비용이 들지 않아요. 전개 입력처럼 작은 그래프에서도 이 절차가 적습니다. 그래서 시작 정점 하나의
거리 배열을 한 번 구하는 과제에는 이 절차를 쓰고, 같은 그래프에서 **시작 정점을 173 개 이상 묻는 순간** 이
판정을 다시 합니다.

| 축 | 이 가이드의 절차 | 플로이드-워셜 |
| --- | --- | --- |
| 시작 정점 하나의 연산 | 적다 | 표 전체를 만든다 |
| 시작 정점이 모두일 때의 연산 | 시작 정점마다 다시 해서 많다 | 한 번이라 적다 |
| 저장 칸 | 거리 배열과 큐 | 정점 쌍 표 |
| 음수 가중치 | 못 쓴다 | 음수 사이클만 없으면 쓴다 |

### 수식 정의와 유도

경로와 최단 거리를 기호로 정의합니다. $\mathcal{P}(v)$ 는 `src` 에서 $v$ 로 가는 단순 경로의 집합이고, 그 집합의
원소 하나를 $P$ 라고 씁니다. 경로의 비용은 $P$ 위의 간선 $(a, b, w)$ 들의 가중치를 더한 값이고, 그 집합의
최솟값이 답이에요. 집합이 비어 있으면 최솟값을 $\infty$ 로 둡니다.

$$\mathcal{P}(v) = \{\,(e_1, \dots, e_k) : e_1 \text{ 은 } src \text{ 에서 나가고 } e_k \text{ 는 } v \text{ 로 들어간다}\,\}, \qquad \mathrm{cost}(P) = \sum_{(a,b,w) \in P} w$$

$$\mathrm{opt}(v) = \min_{P \in \mathcal{P}(v)} \mathrm{cost}(P), \qquad \mathcal{P}(v) = \varnothing \text{ 이면 } \mathrm{opt}(v) = \infty$$

정의를 전개 입력에 넣어 봅시다. 정점 1 · 4 · 5 의 경로 집합과 그 최솟값이에요.

<!--proof:mathPaths-->

```text
P(1)    0→1 (cost 4) · 0→2→1 (cost 3) · 0→2→3→4→1 (cost 16)
opt(1)  min{4, 3, 16} = 3
P(4)    0→1→3→4 (cost 8) · 0→2→1→3→4 (cost 7) · 0→2→3→4 (cost 9)
opt(4)  min{8, 7, 9} = 7
P(5)    원소가 하나도 없다 — 공집합
opt(5)  공집합의 최솟값 = Infinity
```

공집합의 최솟값을 `Infinity` 로 둔 것이 「도달할 수 없다」의 표기입니다. 같은 정의를 여섯 정점 전부에 넣어
이 절차의 `dist` 와 나란히 놓았습니다.

<!--proof:mathCheck-->

| 정점 v | 경로를 전부 만들어 고른 최솟값 | 이 절차의 dist[v] | 두 값 |
| --- | ---: | ---: | --- |
| 0 | 0 | 0 | 같다 |
| 1 | 3 | 3 | 같다 |
| 2 | 1 | 1 | 같다 |
| 3 | 4 | 4 | 같다 |
| 4 | 7 | 7 | 같다 |
| 5 | Infinity | Infinity | 같다 |

이제 유도합니다. 완화를 식으로 적으면 「간선 하나를 이어 붙인 후보와 지금 값 중 작은 쪽」입니다.

$$\mathrm{relax}(u, v, w): \quad \mathrm{dist}[v] \leftarrow \min\bigl(\mathrm{dist}[v],\; \mathrm{dist}[u] + w\bigr)$$

```ts
// 식을 그대로 옮긴 조각. 코드에서는 `nd` 가 dist[u] + w 이고 `dist` 가 dist 배열이다.
const nd = d + w;
if (nd < (dist[v] as number)) dist[v] = nd;
```

여기서 본문의 값만으로는 안 나오는 것이 나옵니다. **큐에 들어가는 항목 수의 상한**이에요. 완화가 값을 고칠 때만
항목이 들어가고, 확정한 정점은 자기 간선을 한 번만 읽으므로 간선 하나가 항목을 많아야 하나 만듭니다. 시작 항목
하나를 더하면 이렇습니다.

$$\text{넣은 항목 수} \le E + 1, \qquad \text{꺼낸 항목 수} = \text{넣은 항목 수} \le E + 1$$

| 항목 | 근거 |
| --- | --- |
| 넣은 항목 수 | 시작 항목 하나 + 완화가 값을 고친 횟수. 간선 하나는 꼬리가 확정될 때 한 번만 읽힌다 |
| 꺼낸 항목 수 | 반복이 끝나면 큐가 비므로 넣은 수와 같다 |
| 이진 힙의 크기 | 넣은 수를 넘지 않는다 |

이진 힙의 높이는 크기의 $\log_2$ 이고, 넣기는 높이만큼 한 번씩, 꺼내기는 높이만큼 두 번씩(두 자식과) 비교합니다. 두 상한을 곱하면 힙 안의 비교가 닫힌 형태로 묶여요.

$$\text{힙의 크기} \le E + 1 \;\Longrightarrow\; \text{한 연산의 비교} \le 2\lceil \log_2 (E+1) \rceil$$

$$\text{힙 안의 비교} \le \underbrace{2(E+1)}_{\text{넣기 + 꺼내기}} \times 2\lceil \log_2 (E+1) \rceil = 4(E+1)\lceil \log_2 (E+1) \rceil$$

이 닫힌 형태에 규모를 넣으면, 배열에서 가장 작은 것을 찾는 방식($V$ 번 꺼내며 매번 정점 배열 $V$ 칸을 읽어
$V^2$)과 갈리는 자리가 값으로 나옵니다.

<!--proof:mathScale-->

| 정점 V | 간선 E | 힙 연산 수 | 실측 비교 | 4(E+1)⌈log2(E+1)⌉ |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 46 | 44 | 86 | 1,128 |
| 64 | 190 | 140 | 524 | 6,112 |
| 256 | 766 | 646 | 3,708 | 30,680 |
| 1,024 | 3,070 | 2,322 | 17,551 | 147,408 |

규모 V = 100,000 · E = 200,000 에 넣으면 이렇습니다.

| 항 | 식 | 값 |
| --- | --- | ---: |
| 큐에 들어가는 항목 | E + 1 | 200,001 개 이하 |
| 힙 연산 수 | 2(E + 1) | 400,002 번 이하 |
| 한 연산의 비교 | 2⌈log2(E+1)⌉ | 36 번 이하 |
| 곱한 값 | 4(E+1)⌈log2(E+1)⌉ | 14,400,072 번 이하 |
| 정점 배열을 매번 읽는 방식 | V² | 10,000,000,000 번 |

두 식이 뒤집히는 첫 간선 수는 E = 92,592,592 입니다. 규모의 상한 200,000 의 463 배이고, 정점 100,000 개로 만들 수 있는 간선 수 V(V−1) = 9,999,900,000 안에 듭니다.

<!--/proof-->

마지막 문장이 이 절이 주는 것입니다. **규모 안에서는 이진 힙이 늘 앞서고**, 두 식이 뒤집히려면 간선이 약 9,259
만 개여야 하는데 그것은 규모의 상한 20 만의 463 배예요. 정점 10 만 개로 만들 수 있는 간선 수 안에는 들어가므로,
간선이 그만큼 촘촘한 그래프에서는 판정이 달라집니다.

### 불변식 — 꺼낸 키가 dist[u] 와 같으면 그 거리는 다시 줄지 않는다

파트 1 에서 코드가 동작하는 것을 아홉 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> 어느 걸음이 끝난 뒤에나 `dist[v]` 는 `src` 에서 `v` 로 가는 **실재하는 경로 하나**의 비용입니다(아직 못
> 찾았으면 `Infinity`). 그리고 큐에서 꺼낸 항목의 키가 그때의 `dist[u]` 와 같으면, **그 순간 `dist[u]` 는
> `opt(u)` 와 같습니다.**

| 문장 | 뜻 | 말하는 시점 |
| --- | --- | --- |
| 앞 문장 | `dist[v]` 는 지어낸 수가 아니라 실제 경로 하나의 비용이다 — 그래서 `opt(v)` 이상이다 | 모든 걸음이 끝난 뒤 |
| 뒤 문장 | 그렇게 꺼낸 `dist[u]` 는 더 줄어들 수 없다 | 꺼낸 직후 |

문장이 둘인 데는 이유가 있습니다. 앞 문장은 `dist[v]` 가 답보다 **작아지지 않는다**는 것을 주고, 뒤 문장은
확정한 값을 다시 볼 필요가 없다는 것을 줘요. 둘 중 하나만 빠져도 반복의 두 줄이 왜 그 모양인지 근거가
사라집니다.

**출발점부터 봅시다.** 반복에 들어가기 전 `dist[src]` 는 `0` 이고 나머지는 `Infinity` 입니다. 길이 0 인 경로의
비용이 `0` 이라 앞 문장이 참이고, 아직 아무것도 안 꺼냈으니 뒤 문장은 말할 것이 없어요. 그 뒤로 상태를 바꾸는
갈래는 넷입니다.

| 걸음 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 시작 | `dist[src] = 0`, 나머지 `Infinity` | 길이 0 인 경로가 있다 | 꺼낸 것이 없다 |
| 완화 | `dist[v]` 를 `d + w` 로 고친다 | `u` 까지의 경로에 간선 하나를 이었다 | `dist` 를 줄이기만 한다 |
| 꺼내기 | 키가 가장 작은 항목을 낸다 | `dist` 를 안 바꾼다 | 아래 경로 조각 표 |
| 버리기 | 키가 `dist[u]` 보다 크면 넘어간다 | `dist` 를 안 바꾼다 | 그 항목은 이미 지난 값이다 |

셋째 줄이 이 논증의 핵심입니다. 꺼낸 키 `d` 가 `dist[u]` 와 같을 때, `src` 에서 `u` 로 가는 아무 경로 `P` 나
잡아 그 위에서 **아직 확정 안 된 첫 정점**을 `x` 라고 부릅시다. `u` 자신이 아직 확정 전이라 `x` 는 반드시 있고,
`x` 의 바로 앞 정점은 확정된 것이라 그 간선이 이미 완화됐어요.

| 경로 조각 | 그 값 | 근거 |
| --- | --- | --- |
| `src` 부터 `x` 까지의 비용 | `dist[x]` 이상 | `x` 의 앞 정점이 확정될 때 그 간선을 완화했으니 `dist[x]` 는 이 비용 이하다 |
| `dist[x]` | `d` 이상 | `dist[x]` 를 키로 가진 항목이 큐에 있고, `d` 는 큐에서 가장 작은 키다 |
| `x` 부터 `u` 까지 남은 간선의 합 | `0` 이상 | 가중치가 음수가 아니다 |
| 셋을 더한 `P` 의 비용 | `d` 이상 | 첫째 ≥ 둘째 ≥ `d` 이고 셋째 ≥ 0 이다 |

어느 경로도 비용이 `d` 보다 작지 않으니 `opt(u) ≥ d = dist[u]` 이고, 앞 문장에서 `dist[u] ≥ opt(u)` 이므로 둘이
같습니다. 가중치가 0 이면 셋째 줄의 합이 0 일 수 있어 비용이 정확히 `d` 가 되는데, 그때도 `d` 보다 **작아지지는**
않으므로 확정이 성립해요. 음수 가중치에서 성립하지 않게 되는 곳이 바로 이 셋째 줄입니다.

**엣지 케이스를 함께 봅시다.** 경계에 있는 입력 여섯에 이 글의 코드를 실행하고, 넣은 항목과 완화 시도를 세었어요.

<!--proof:invariantEdges-->

| 경계 입력 | 간선 | 결과 | 넣은 항목 | 완화 시도 | 값을 고친 완화 |
| --- | --- | --- | ---: | ---: | ---: |
| 정점이 하나뿐이다 | 없음 | [0] | 1 | 0 | 0 |
| 간선이 하나도 없다 | 없음 | [Infinity, 0, Infinity] | 1 | 0 | 0 |
| 도달할 수 없는 정점이 있다 | 0→1(3) | [0, 3, Infinity] | 2 | 1 | 1 |
| 가중치가 0 이다 | 0→1(0) 1→2(0) | [0, 0, 0] | 3 | 2 | 2 |
| 같은 두 정점에 간선이 여럿이다 | 0→1(10) 0→1(3) 0→1(7) | [0, 3] | 3 | 3 | 2 |
| 자기 자신을 가리키는 간선이 있다 | 0→0(5) 0→1(2) | [0, 2] | 2 | 2 | 1 |

정점이 하나뿐이거나 간선이 없으면 시작 항목 하나를 꺼내고 끝납니다. 도달할 수 없는 정점은 큐에 한 번도 안 들어가
`Infinity` 로 남아요. 가중치 0 간선은 같은 값을 넘겨 줄 뿐 두 문장을 깨지 않고, 같은 두 정점 사이의 간선 셋은 셋
다 완화되지만 값을 고치는 것은 작아지는 두 번뿐입니다. 자기 자신을 가리키는 간선은 `d + w` 가 `dist[u]` 보다
작을 수 없어 아무 일도 하지 않아요.

**이제 깨뜨려 봅시다.** 앞 문장을 지키던 줄은 완화 값을 만드는 `const nd = d + w;` 한 줄이에요. 「어차피 간선
가중치가 비용인데 지나온 값을 왜 더하나」라는 생각으로 그 줄을 `const nd = w;` 로 바꿔 봅니다.

```ts
for (const [v, w] of adj[u] as [number, number][]) {
  const nd = w;                              // ← 지나온 비용을 더하지 않았다
  if (nd < (dist[v] as number)) {
    dist[v] = nd;
    pq.push(v, nd);
  }
}
```

실행하면 이렇게 나옵니다.

<!--proof:mutantLastEdge-->

| 입력 | 정본이 낸 답 | 마지막 간선만 적은 답 | 두 답 |
| --- | --- | --- | --- |
| 전개 입력 | [0, 3, 1, 4, 7, Infinity] | [0, 2, 1, 1, 3, Infinity] | 어긋난다 |
| 삼각형 0->1->2, 0->2 | [0, 2, 5] | [0, 2, 3] | 어긋난다 |
| 사슬 0->1->2->3 (가중치 2) | [0, 2, 4, 6] | [0, 2, 2, 2] | 어긋난다 |

전개 입력에서 변이가 적은 dist[3] 는 1 이고, 정점 3 으로 들어오는 간선 중 가장 작은 가중치는 1 입니다. 정본의 dist[3] 는 4 입니다.

<!--/proof-->

앞 문장이 깨지면 `dist[v]` 는 더 이상 「실재하는 경로 하나의 비용」이 아닙니다. 전개 입력에서 변이의 `dist[3]` 은
정점 3 으로 들어오는 간선의 가중치 하나만 적은 값이고, 그 비용으로 정점 3 까지 가는 경로는 없어요. 꺼낸 키도
경로 비용이 아니게 되니 뒤 문장의 「확정」도 뜻을 잃습니다. 세 입력 모두 답이 어긋나서, 어떤 입력으로 시험해도
이 실수는 확인돼요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 무리입니다. 간선 목록을 이웃 목록으로 바꾸는 것, 우선순위 큐에 넣고 꺼내는 것,
확정한 정점의 간선을 완화하는 것이에요. 전개의 걸음으로 확인하면 이렇게 나뉩니다.

<!--proof:perfCount-->

| 무리 | 걸음 | 횟수 |
| --- | --- | ---: |
| 이웃 목록 만들기 | T1 | 7 |
| 큐에 넣기 | T1 과 값을 고친 걸음 | 7 |
| 큐에서 꺼내기 | T2 ~ T8 | 7 |
| 뒤처진 기록 버리기 | T5 · T7 | 2 |
| 완화 시도 | T2 · T3 · T4 · T6 · T8 | 7 |
| 힙 안의 비교 | 넣기와 꺼내기 안에서 | 7 |

정점 V = 6 · 간선 E = 7 인 입력입니다. 완화 시도 7 번은 E 와 같고, 큐에 넣기 7 번은 시작 항목 1 개에 값을 고친 완화 6 번을 더한 것이며, 큐에서 꺼내기 7 번은 넣은 수와 같습니다.

<!--/proof-->

T5 와 T7 은 꺼내자마자 버린 걸음이라 완화 시도가 0 입니다. 그래서 완화 시도가 정확히 간선 수와 같아요. 이것을
임의의 그래프로 넓히면 총식이 됩니다.

| 항 | 횟수 | 근거 |
| --- | --- | --- |
| 이웃 목록 만들기 | `V + E` | 정점마다 빈 목록 하나, 간선마다 넣기 한 번 |
| 큐에 넣기와 꺼내기 | `2(E + 1)` 번 이하 | 간선 하나가 값을 고치는 것은 꼬리가 확정될 때 한 번뿐이다 |
| 큐 연산 한 번의 비교 | `2⌈log2(E + 1)⌉` 번 이하 | 이진 힙의 높이만큼 오르내린다 |
| 완화 시도 | `E` | 확정한 정점이 자기 간선을 한 번씩 읽는다 |

넷을 더하면 총식이 `O(V + E) + O(E log E) = O((V + E) log E)` 이고, 메모리는 거리 배열 `Θ(V)` 와 이웃 목록
`Θ(V + E)` 와 우선순위 큐 `O(E)` 를 더한 `O(V + E)` 입니다.

**여기서 센 것은 완화 시도와 큐 안의 비교 전부입니다.** 배열 칸을 읽고 쓰는 횟수와 반복 변수를 올리는 횟수는
세지 않았어요. 둘 다 위 값들에 비례하므로 총식의 차수가 그대로입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (간선이 하나도 없다) | `O((V + E) log E)` | `Θ(V)` — 배열을 만들고 항목 하나를 꺼낸다 |
| **평균적인 경우** (입력 분포를 정하지 않는다) | `O((V + E) log E)` | 정의하지 않는다 |
| **최악의 경우** (간선 하나하나가 값을 고친다) | `O((V + E) log E)` | `Θ(V + E log E)` — 실제로 도달한다 |

평균을 정의하지 않는 이유는 **그래프의 분포를 정할 방법이 없기 때문**입니다. 정점 수와 간선 수를 고정해도
어느 간선이 실제로 값을 고치는가는 가중치의 배치에 달려 있고, 그 배치의 분포를 과제가 주지 않아요.

| 경계 | 뜻 | 종류 |
| --- | --- | --- |
| `O((V + E) log E)` | 연산 수가 그보다 크지 않다 | 상한 |
| `Θ(V + E)` | 이웃 목록을 만드는 데 반드시 드는 값이다 | 타이트한 값 |
| 힙 부분 | 큐에 들어가는 항목 수가 입력의 모양에 따라 갈려 한 값으로 못 적는다 | 상한만 |

힙 부분이 모양에 따라 얼마나 갈리는지는 아래 「최악을 만드는 입력」의 표가 보여 줍니다. **총식을 한 번은 정확히
적습니다.** 앞에 붙는 전처리는 이웃 목록 하나뿐이고 정렬도 좌표 압축도 하지 않아요 — `Θ(V + E)` 시간에 이웃
목록을 만들고, 그 뒤에 `O(E log E)` 짜리 큐 연산과 `Θ(E)` 짜리 완화 시도가 붙습니다.

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고, 정점은 번호로 배열 칸에 바로 찾아가며, 이진 힙의
높이는 항목 수로만 정해져요. 해시도 무작위성도 분할 상환도 쓰지 않으니 어떤 그래프를 넣어도 위 상한을 넘지
않습니다.

#### 최악을 만드는 입력

연산 수를 최대로 만드는 방법이 축마다 다릅니다. 완화 시도는 간선 수만 보고, 큐에 넣는 횟수는 **간선 하나하나가
실제로 값을 고치는 모양**에서 최대가 돼요. 정점 64 개로 모양 다섯을 실제로 만들어 재 봤습니다. 마지막 줄의 완전
DAG 는 `i → j` 의 가중치를 `2(j−i)−1` 로 두어, 앞의 정점이 확정될 때마다 뒤의 값이 1 씩 줄어들게 만든 것이에요.

<!--proof:worstShape-->

| 모양 (V = 64) | 간선 E | 완화 시도 | 큐에 넣기 | 힙 안의 비교 |
| --- | ---: | ---: | ---: | ---: |
| 사슬 | 63 | 63 | 64 | 0 |
| 별 | 63 | 63 | 64 | 183 |
| 지름길 | 125 | 125 | 126 | 621 |
| 완전 그래프 (가중치 전부 1) | 4,032 | 4,032 | 64 | 183 |
| 완전 DAG (가중치 2(j-i)-1) | 2,016 | 2,016 | 2,017 | 37,416 |

다섯 모양 모두 완화 시도가 간선 수와 같았고, 큐에 넣기와 힙 안의 비교만 모양에 따라 갈렸습니다.

<!--/proof-->

**「간선이 많으면 큐도 커진다」는 이 절차에서 성립하지 않습니다.** 가중치가 전부 1 인 완전 그래프는 간선이
4,032 개인데 큐에 넣기가 64 번뿐이에요. 정점 0 에서 한 번에 전부 1 로 채워져 그 뒤로 고칠 것이 없기 때문입니다.
반대로 완전 DAG 는 간선이 그 절반인데 큐에 넣기가 2,017 번으로 `E + 1` 에 정확히 이르러요. 규모의 상한에서 축마다
최악을 모으면 이렇습니다.

<!--proof:worstAxes-->

| 최악으로 만들 축 | 입력 | 값 |
| --- | --- | ---: |
| 완화 시도 | 간선 E = 200,000, 모양은 무엇이든 | 200,000 |
| 큐에 넣기 | 간선 하나하나가 값을 고치는 완전 DAG | E + 1 = 200,001 |
| 거리 값 | 가중치 1,000,000,000 짜리 사슬 V = 100,000 | (V − 1) × 1,000,000,000 = 99,999,000,000,000 |

정점 1,000 개 사슬을 실행하면 끝 정점의 거리가 999,000,000,000 으로 식과 일치합니다. 거리 값의 최악 99,999,000,000,000 은 자바스크립트 수가 정수를 정확히 담는 한계 9,007,199,254,740,991 보다 작습니다.

<!--/proof-->

셋째 줄은 정점 수와 가중치 상한이 함께 정하고, 앞의 둘은 간선 수만 봅니다. 거리 값이 약 10^14 까지 커지므로
32 비트 정수로는 담을 수 없고, 자바스크립트의 수로는 정확히 담깁니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 우선순위 큐에서 **키가 가장 작은 항목**을 꺼내 키가 `dist[u]` 와
같으면 그 정점을 확정하고, 확정한 정점의 간선만 완화하며, 값을 고칠 때만 새 항목을 넣습니다. 옛 항목은 지우지
않고 꺼낼 때 뒤처진 기록으로 걸러 내요.

```text
간선 목록 → 이웃 목록 → (src, 0) 을 큐에 → 키가 가장 작은 항목을 꺼낸다 → 확정한 정점의 간선을 완화한다
                                            └ 키 > dist[u] 이면 버린다      └ 고친 이웃만 큐에 넣는다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T5 는 정점 1 을 두 번째로 꺼낸 걸음이었어요. T4 에서 이미 정점 1 을
확정했는데, 왜 그 옛 항목을 큐에서 미리 지우지 않고 T5 까지 남겨 두었을까요?

### Dijkstra 최단 경로

풀 파일: [`dijkstra.ts`](./dijkstra.ts) · 테스트: [`dijkstra.test.ts`](./dijkstra.test.ts) · 실행: `bun test src/algorithms/shortest-path/dijkstra/dijkstra.test.ts`

#### 한 줄 요약

> 함수는 음수가 아닌 가중치의 방향 그래프와 시작 정점을 받아 각 정점까지의 최단 거리 배열을 반환한다.

#### 스토리

물류 회사의 배송 경로 시스템을 개발하는 수빈은 창고에서 각 배송지까지의 최소 이동 비용을 계산해야 한다. 도로마다 통행료나 연료비 같은 이동 비용이 붙어 있고, 비용은 항상 0 이상이다.

수빈은 배송 기사들이 출발지에서 각 목적지까지 가장 저렴하게 이동할 수 있는 경로 비용을 미리 계산해 두고 싶다. 도로는 단방향인 경우도 있어서 A에서 B로 가는 비용과 B에서 A로 가는 비용이 다를 수 있다.

출발 창고 하나를 기준으로 나머지 모든 배송지까지의 최소 비용을 한 번에 구하면 배송 계획을 효율적으로 세울 수 있다.

#### 함수 인터페이스

```ts
export function dijkstra(
  n: number,
  edges: [number, number, number][],
  src: number,
): number[];
```

- `n` — 정점 수. 정점 번호는 $0$부터 $n - 1$.
- `edges` — 방향 간선 목록. 각 원소는 $[u, v, w]$ 형태이며 가중치 $w \geq 0$인 방향 간선 $u \to v$.
- `src` — 시작 정점 번호.
- 반환 — 길이 $n$인 배열. 인덱스 $v$에는 $\text{src} \to v$의 최단 거리. 도달할 수 없는 정점은 `Infinity`.

#### 제약 조건

- $1 \leq V \leq 10^5$ (정점 수)
- $0 \leq E \leq 2 \cdot 10^5$ (간선 수)
- $0 \leq w(u, v) \leq 10^9$ (가중치; 음수 없음)
- $0 \leq \text{src} < V$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

가중치가 음수가 아닌 방향 그래프 $G = (V, E)$가 주어진다. 시작 정점 $\text{src}$에서 모든 정점 $v$까지의 최단 거리 $d(\text{src}, v)$를 구하라.

최단 거리는 경로 위 간선 가중치의 합이 최소인 경로 비용으로 정의된다:

$$d(\text{src}, v) = \min_{P \in \mathcal{P}(\text{src}, v)} \sum_{(u, w) \in P} w(u, w)$$

여기서 $\mathcal{P}(\text{src}, v)$는 $\text{src} \to v$ 경로의 집합이다.

- $\text{src}$ 자신까지의 거리는 $0$이다.
- 도달할 수 없는 정점의 거리는 `Infinity`다.
- 동일한 두 정점 사이에 다중 간선이 있으면 모두 고려해야 한다.
- 셀프 루프(자기 자신을 향하는 간선)는 거리 갱신에 영향을 주지 않는다.

#### 예시

```ts
// 여러 경로 중 최단 경로 선택
const edges: [number, number, number][] = [
  [0, 1, 4],
  [0, 2, 1],
  [2, 1, 2],
  [1, 3, 1],
  [2, 3, 5],
];
dijkstra(4, edges, 0);
// [0, 3, 1, 4]
// — 0→1 최단: 0→2→1 = 3 (직접 간선 4보다 짧음)

// 도달 불가능한 정점은 Infinity
dijkstra(3, [[0, 1, 2]], 0);
// [0, 2, Infinity] — 정점 2로 가는 간선 없음

// 간선이 없을 때 시작점만 0
dijkstra(3, [], 1);
// [Infinity, 0, Infinity] — src만 0, 나머지 Infinity

// 방향 그래프: 역방향 간선은 사용 불가
dijkstra(2, [[0, 1, 5]], 1);
// [Infinity, 0] — 1→0 방향 간선이 없으므로 정점 0은 도달 불가
```
