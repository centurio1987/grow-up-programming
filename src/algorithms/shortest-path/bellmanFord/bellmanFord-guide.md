# 벨만-포드 — 간선 목록을 V−1 라운드 완화하면 최단 거리가 나오고 한 라운드 더 줄면 음수 사이클인 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 경로를 전부
나열하는 방법에서 출발해, 간선 목록 전체를 정해진 라운드 수만큼 다시 읽는 방법까지 갑니다. 그 방법을 준비되는
차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

간선마다 수가 하나씩 붙은 방향 그래프를 생각해 봅시다. 간선에 붙은 수를 **가중치**라고 부르고, 경로 하나의
**비용**은 그 경로가 지나는 간선의 가중치를 모두 더한 값입니다. 시작 정점 `src` 에서 정점 `v` 까지 가는 경로 중
비용이 가장 작은 것의 비용이 `v` 까지의 **최단 거리**예요. 이 글이 다루는 그래프는 가중치에 **음수가 섞일 수
있고, 사이클도 있을 수 있습니다.** 정점 일곱 · 간선 여덟인 그래프에서 정점 0 을 시작 정점으로 두고 최단 거리를
정점 안에 적으면 이렇습니다.

<!--fig:concept-graph-->
![전개 입력 — 간선 옆 수는 가중치, 정점 안의 수는 정점 0 에서의 최단 거리](./figs/concept-graph.svg)

굵은 실선은 최단 거리를 만든 간선입니다. 정점 6 은 나가는 간선만 있고 들어오는 간선이 없어서 시작 정점에서 갈
길이 없고, 이 글은 그 자리에 `Infinity` 를 적어 「도달할 수 없다」를 나타냅니다. 정점 2 와 3 으로 가는 경로를
전부 늘어놓으면 이렇습니다.

<!--proof:conceptPaths-->

| 도착 정점 | 경로 | 간선 수 | 비용 | 최소 |
| --- | --- | ---: | ---: | --- |
| 2 | 0→2 | 1 | 9 |  |
| 2 | 0→1→2 | 2 | 7 | 가장 작다 |
| 3 | 0→2→3 | 2 | 6 |  |
| 3 | 0→1→2→3 | 3 | 4 | 가장 작다 |

정점 2 로 곧장 가는 간선의 비용은 9 이고, 정본이 낸 거리는 dist[2] = 7 · dist[3] = 4 입니다.

<!--/proof-->

정점 3 으로 가는 두 경로를 봐 주세요. 간선을 하나 더 지나는 쪽이 비용이 작습니다. 가중치 −3 인 간선 `2 → 3` 이
있어서 **간선을 더 지나도 합이 줄어들 수 있기** 때문이에요. 그래서 이 절차는 정점마다 **지금까지 찾은 가장
작은 비용** `dist[v]` 를 들고 있다가, 더 작은 비용을 찾을 때마다 고쳐 적습니다. 간선 `u → v` 하나를 보고
`dist[u] + w` 가 `dist[v]` 보다 작으면 `dist[v]` 를 그 값으로 고치는 일을 **완화**라고 불러요.

이 절차는 완화를 **라운드** 단위로 합니다. 라운드 하나는 **간선 목록을 처음부터 끝까지 한 번 읽으며 간선마다
완화하는 일**이에요. 정점을 고르는 차례 같은 것은 없고, 간선이 목록에 적힌 차례 그대로 읽습니다. 위 그래프에
라운드를 하나씩 되풀이하며 라운드가 끝날 때마다 `dist` 를 적으면 이렇습니다.

<!--proof:conceptRounds-->

| 라운드 | 고친 칸 | changed | 라운드가 끝난 dist |
| ---: | ---: | --- | --- |
| 1 | 2 | true | [0, 4, 9, Infinity, Infinity, Infinity, Infinity] |
| 2 | 2 | true | [0, 4, 7, 6, Infinity, Infinity, Infinity] |
| 3 | 2 | true | [0, 4, 7, 4, 8, Infinity, Infinity] |
| 4 | 2 | true | [0, 4, 7, 4, 6, 9, Infinity] |
| 5 | 1 | true | [0, 4, 7, 4, 6, 7, Infinity] |
| 6 | 0 | false | [0, 4, 7, 4, 6, 7, Infinity] |

라운드 6 은 라운드 5 가 끝난 dist 를 그대로 받아 같은 간선 8 개를 읽었고, 고친 칸이 0 개입니다.

<!--/proof-->

`changed` 는 그 라운드가 한 칸이라도 고쳤는지를 적은 값입니다. 라운드 6 이 한 칸도 못 고치자 절차가 끝났고,
그 줄이 위 그림의 최단 거리와 같아요. 한 가지가 더 걸립니다. 가중치의 합이 0 보다 작은 순환 경로, 곧 **음수
사이클**이 있으면 최단 거리라는 것이 정해지지 않아요. 그 순환을 한 번 더 지날 때마다 비용이 줄기 때문입니다.

<!--fig:concept-cycle-->
![음수 사이클 0→1→2→0 — 가중치 합이 0 보다 작다](./figs/concept-cycle.svg)

간선 목록 `[0,1,1] [1,2,-1] [2,0,-1]` 을 여러 번 읽어 보면 값이 끝없이 줄어듭니다.

<!--proof:conceptCycle-->

| 간선 목록을 읽은 횟수 | dist |
| --- | --- |
| 1 번 | [-1, 1, 0] |
| 2 번 | [-2, 0, -1] |
| 3 번 | [-3, -1, -2] |

순환 0→1→2→0 의 가중치 합은 1 + (-1) + (-1) = -1 이고, 목록을 한 번 읽을 때마다 세 정점의 값이 모두 1 씩 줄었습니다.

<!--/proof-->

그래서 이 절차는 거리 배열 `dist` 와 함께 **시작 정점에서 갈 수 있는 음수 사이클이 있는가**를 `hasNegativeCycle`
로 돌려줍니다. 음수 사이클이 없으면 라운드를 **`V − 1` 번**(`V` 는 정점 수) 되풀이하면 최단 거리가 다 나오고,
**한 라운드를 더 읽었는데 값이 또 줄면** 음수 사이클이 있다는 뜻이에요. 할 일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 거리 배열 만들기 | 정점마다 칸 하나를 `Infinity` 로 채우고 시작 정점만 0 을 적는다 | 정점마다 한 번 |
| 라운드 하나 | 간선 목록을 적힌 차례대로 읽으며 간선마다 완화한다 | 간선마다 한 번 |
| 라운드 되풀이 | 고친 칸이 없으면 멈추고, `V` 번째 라운드까지 고치면 음수 사이클로 판정한다 | 라운드 `V` 번 이하 |
| 모두 | | `O(V·E)` — `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **방향 간선과 간선 목록.** 간선 하나를 `[u, v, w]` 세 수로 적고 죽 늘어놓은 것이 간선 목록입니다. `u → v` 로
  적힌 간선은 `u` 에서 `v` 쪽으로만 씁니다. 이 절차는 간선 목록을 이웃 목록으로 바꾸지 않고 적힌 그대로 읽어요.
  이웃 목록과의 차이가 궁금하면
  [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **완화.** `dist[u] + w` 가 `dist[v]` 보다 작을 때만 `dist[v]` 를 고치는 연산입니다. 한 번 적은 거리를 왜 다시
  고치는지, 적힌 값이 늘 실재하는 경로의 비용인 까닭은 [`dijkstra`](../dijkstra/dijkstra-guide.md) 의 「먼저
  알아 둘 개념 — 완화」가 자세히 다룹니다.
- **거리가 가장 작은 정점부터 확정하는 방법.** 가중치가 0 이상이면 [`dijkstra`](../dijkstra/dijkstra-guide.md)
  가 그렇게 해서 간선을 한 번씩만 읽습니다. 이 글은 그 방법이 음수 가중치에서 왜 틀리는지에서 출발해요.
- **단순 경로와 순환.** 같은 정점을 두 번 지나지 않는 경로가 단순 경로이고, 출발한 정점으로 되돌아오는 경로가
  순환입니다. 정점이 `V` 개면 단순 경로는 간선을 많아야 `V − 1` 개 지나요.
- **`Infinity` 와의 비교와 덧셈.** 아직 길을 못 찾은 상태를 `Infinity` 로 두면 「어떤 유한한 값도 그보다
  작다」가 그대로 성립합니다. 그래서 처음 값을 적는 갈래를 따로 쓰지 않아도 돼요.

이름이 비슷한 과제 넷을 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 그래프 | 이 글에서 |
| --- | --- | --- |
| 시작 정점 하나에서 모든 정점까지의 최단 거리와 음수 사이클 판정 | 사이클도 음수 가중치도 있어도 된다 | 다룬다 |
| 시작 정점 하나에서 모든 정점까지의 최단 거리 | 가중치가 0 이상 | 다루지 않는다 — [`dijkstra`](../dijkstra/dijkstra-guide.md) |
| 시작 정점 하나에서 모든 정점까지의 최단 거리 | 사이클이 없다 · 음수 가중치가 있어도 된다 | 다루지 않는다 — [`dagShortestPath`](../dagShortestPath/dagShortestPath-guide.md) |
| 시작 정점 하나에서 간선을 가장 적게 지나는 거리 | 가중치가 없다 | 다루지 않는다 — [`bfsShortestPath`](../../graph/bfsShortestPath/bfsShortestPath-guide.md) |

### 아이디어를 떠올리는 과정 — 경로 전부 나열하기에서 V−1 라운드 완화하기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수, 간선 목록, 시작 정점을 받아서
모든 정점까지의 최단 거리와 음수 사이클이 있는지를 함께 돌려줍니다.

```ts
function bellmanFord(
  n: number,
  edges: [number, number, number][],
  src: number,
): { dist: number[]; hasNegativeCycle: boolean };
```

- 입력: 정점 수 `n`, 원소가 `[u, v, w]` 인 방향 간선 목록 `edges`, 시작 정점 `src`. 정점 번호는 `0` 부터
  `n − 1` 이고, 가중치 `w` 는 음수일 수 있습니다. 간선이 목록에 적힌 차례는 입력이 정하고, 푸는 쪽이 고르지
  않아요.
- 출력: `dist` 는 길이 `n` 인 배열이고 `v` 번째 칸에 `src` 에서 `v` 까지의 최단 거리가 들어갑니다. 갈 수 없으면
  `Infinity` 예요. `hasNegativeCycle` 은 `src` 에서 갈 수 있는 음수 사이클이 있으면 `true` 입니다.
- 규모: `1 ≤ V ≤ 500`, `0 ≤ E ≤ V(V−1)`, `−10^9 ≤ w ≤ 10^9`. 간선은 두 정점 사이에 방향마다 하나씩 둘 수 있는
  만큼까지 둡니다. 정점 수 500 은 이 글이 정한 값이에요 — 뒤에서 만들 절차는 간선 읽기가 `V × E` 에 달려 있어서,
  그 곱이 흔한 채점 환경의 예산인 1 초(단순 연산 1 억 번 기준) 언저리에 머무는 정점 수를 골랐습니다.

이 글이 쓰는 기호는 여덟 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점의 개수. 코드의 `n` 입니다 | `1 ≤ V ≤ 500` |
| `E` | 간선의 개수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ V(V−1)` |
| `src` | 시작 정점의 번호 | `0 ≤ src ≤ V−1` |
| `u` · `v` | 정점 번호. 간선 `u → v` 를 읽는 자리에서 `u` 가 꼬리, `v` 가 머리입니다 | `0` 부터 `V−1` |
| `w` | 간선 `u → v` 의 가중치 | `−10^9 ≤ w ≤ 10^9` |
| `dist[v]` | 코드가 지금 들고 있는 값. `src` 에서 `v` 로 가는 **실재하는 경로 하나**의 비용입니다 | 길이 `V` 인 배열 |
| `opt(v)` | `src` 에서 `v` 까지의 **진짜 최단 거리**. `dist[v]` 가 끝내 같아져야 하는 값입니다 | 정점마다 하나 |
| `k` | 라운드의 번호. `k` 번째 라운드는 간선 목록을 `k` 번째로 읽는 일입니다 | `1` 부터 `V` 까지 |

`dist[v]` 와 `opt(v)` 를 가르는 것이 이 글의 뼈대입니다. 앞은 지금까지 찾은 값이고 뒤는 그 값이 결국 같아져야 할
목표예요. 가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 최단 거리는 경로의 비용 중 가장 작은 것이니,
**시작 정점에서 나가는 단순 경로를 전부 만들어** 도착 정점마다 가장 작은 비용을 고릅니다. 음수 가중치가 있어도
답은 맞아요. 간선이 가장 많은 그래프(완전 그래프)에서 그 경로가 몇 개인지 세었습니다.

<!--proof:naiveScale-->

| 정점 V | 간선 E | 단순 경로 수 | 센 방법 |
| ---: | ---: | --- | --- |
| 4 | 12 | 15 | 실행 |
| 6 | 30 | 325 | 실행 |
| 8 | 56 | 13,699 | 실행 |
| 10 | 90 | 986,409 | 실행 |
| 500 | 249,500 | 499! 이상 — 1,132 자리 수 | 식 |

정점 10 개 완전 그래프에서 단순 경로가 986,409 개입니다. 정점이 V 개인 완전 그래프는 출발점을 뺀 V−1 개를 모두 지나는 경로만 해도 (V−1)! 개라, 마지막 줄은 V = 500 을 그 식에 넣은 값입니다.

<!--/proof-->

정점 열 개에서 벌써 백만 개에 가깝고, 규모의 상한에서는 경로 수가 천 자리를 넘습니다. 경로를 하나하나 고르는
대신 **정점마다 값 하나를 들고 고쳐 가야** 해요. 그 방법을 이미 하나 알고 있습니다. 가중치가 0 이상일 때
`dijkstra` 는 거리가 가장 작은 정점을 꺼내 **확정하고 다시 보지 않아서** 간선을 한 번씩만 읽어요. 그 규칙을 음수
가중치가 있는 입력에 그대로 적용했습니다. 앞의 두 입력은 `dijkstra` 가이드가 「이 방법이 기대는 전제」에서 쓴
입력이에요.

<!--proof:originSettle-->

| 입력 | 확정한 정점을 다시 보지 않는 답 | 경로를 전부 만든 답 | 어긋난 정점 |
| --- | --- | --- | --- |
| 0->1(0) 0->2(1) 2->1(-5) 1->3(0) | [0, -4, 1, 0] | [0, -4, 1, -4] | 3 |
| 0->1(2) 0->2(3) 2->1(-2) 1->3(1) | [0, 1, 3, 3] | [0, 1, 3, 2] | 3 |
| 전개 입력 | [0, 4, 7, 4, 6, 7, Infinity] | [0, 4, 7, 4, 6, 7, Infinity] | 없음 |

입력 3 개 가운데 2 개에서 답이 어긋났습니다.

<!--/proof-->

둘째 입력에서 정점을 확정한 차례와 그때의 값을 늘어놓으면 어긋나는 자리가 보입니다.

<!--proof:originSettleWhere-->

| 확정한 차례 | 정점 | 확정한 값 | 경로를 전부 만든 값 |
| ---: | --- | ---: | ---: |
| 1 | 0 | 0 | 0 |
| 2 | 1 | 2 | 1 |
| 3 | 2 | 3 | 3 |
| 4 | 3 | 3 | 2 |

확정한 값이 경로를 전부 만든 값과 다른 정점은 1 · 3 입니다.

<!--/proof-->

정점 1 은 값 2 로 확정됐는데, 그 뒤에 확정한 정점 2 에서 나가는 가중치 −2 인 간선이 정점 1 로 가는 값을 1 로
줄입니다. 확정한 정점의 간선은 다시 읽지 않으니 정점 3 은 옛 값 2 에 1 을 더한 3 에 머물러요. **음수 간선은
확정한 값을 뒤에서 줄입니다.** 그러니 확정을 버리고, 간선 목록 전체를 **라운드마다 다시 읽어** 고칠 것이 없을
때까지 되풀이해 봅시다. 전개 입력을 그 방식으로 처리하되, 간선이 적힌 순서와 그것을 뒤집은 순서 둘로 실행했어요.

<!--proof:orderRounds-->

| 간선 목록의 순서 | 라운드 | 간선 읽기 | 첫 라운드가 값을 적은 정점 | 결과 dist |
| --- | ---: | ---: | --- | --- |
| 적힌 순서 | 6 | 48 | 1 · 2 | [0, 4, 7, 4, 6, 7, Infinity] |
| 그 순서를 뒤집은 것 | 2 | 16 | 2 · 1 · 3 · 4 · 5 | [0, 4, 7, 4, 6, 7, Infinity] |

두 순서의 결과 dist 가 같고, 라운드는 6 번과 2 번입니다.

<!--/proof-->

답은 둘 다 맞고, **간선 읽기**(간선 하나를 목록에서 읽은 횟수)가 48 번과 16 번으로 갈렸습니다. 뒤집은 순서는 사슬
`0 → 1 → 2 → 3 → 4 → 5` 를 따라가는 방향이라, 앞 정점의 값이 정해진 뒤에 다음 간선을 읽어 첫 라운드가 정점 다섯
개의 값을 이어서 적어요. 적힌 순서는 그 반대라 라운드마다 한두 정점씩만 늘어납니다. 그런데 이 방식에는 순서보다
큰 문제가 있어요. 음수 사이클이 있는 입력에서는 **고칠 것이 없어지는 때가 오지 않습니다.**

<!--proof:originNoStop-->

| 라운드 | 고친 칸 | dist |
| ---: | ---: | --- |
| 1 | 3 | [-1, 1, 0] |
| 2 | 3 | [-2, 0, -1] |
| 3 | 3 | [-3, -1, -2] |
| 4 | 3 | [-4, -2, -3] |
| 5 | 3 | [-5, -3, -4] |
| 6 | 3 | [-6, -4, -5] |

6 라운드 모두 고친 칸이 있었고, 마지막 라운드가 끝난 뒤에도 dist[0] 이 -6 으로 줄어 있습니다.

<!--/proof-->

「고칠 것이 없을 때까지」만으로는 멈추지 않으니, **몇 라운드면 충분한지**를 알아야 합니다. 앞에서 순서만 바꿔도
라운드 수가 갈렸어요. 그러면 가장 단순한 후보는 「간선을 좋은 순서로 정렬해 두는 것」입니다. 전개 입력의 간선
여덟 개를 늘어놓는 순서를 전부 실행해 라운드 수를 세었습니다.

<!--proof:orderSweepBlock-->

| 라운드 수 | 그 라운드 수가 나온 순서 | 비율 |
| ---: | ---: | ---: |
| 2 | 336 | 0.8 % |
| 3 | 8,736 | 21.7 % |
| 4 | 22,176 | 55.0 % |
| 5 | 8,736 | 21.7 % |
| 6 | 336 | 0.8 % |

간선 여덟 개의 순서 40,320 가지를 전부 실행했고, 답이 정본과 다른 순서는 0 개입니다. 라운드 수는 가장 적을 때 2 번, 가장 많을 때 6 번입니다.

<!--/proof-->

한 라운드로 끝나는 순서는 하나도 없고, 가장 적은 2 라운드짜리도 0.8 % 뿐입니다. 그 순서를 고르려면 **값이 어느
차례로 정해지는지, 곧 최단 경로를 이미 알아야** 해요. 답을 알아야 순서를 고를 수 있으니 이 후보는 쓸 수 없습니다.
남은 길은 순서를 고르지 않고 **어떤 순서에서도 충분한 라운드 수를 상한으로 잡는 것**이에요. 라운드 수를 `k` 로
잘라 실행하고, 그때의 `dist` 가 정답과 같아지는 `k` 를 찾았습니다. 오른쪽 열은 같은 실험을 순서 전부에 대해 한
것이에요.

<!--proof:capSweep-->

| 라운드 상한 k | 적힌 순서의 dist | 정답과 | 40,320 가지 중 정답인 순서 |
| ---: | --- | --- | ---: |
| 0 | [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] | 다르다 | 0 |
| 1 | [0, 4, 9, Infinity, Infinity, Infinity, Infinity] | 다르다 | 336 |
| 2 | [0, 4, 7, 6, Infinity, Infinity, Infinity] | 다르다 | 9,072 |
| 3 | [0, 4, 7, 4, 8, Infinity, Infinity] | 다르다 | 31,248 |
| 4 | [0, 4, 7, 4, 6, 9, Infinity] | 다르다 | 39,984 |
| 5 | [0, 4, 7, 4, 6, 7, Infinity] | 같다 | 40,320 |
| 6 | [0, 4, 7, 4, 6, 7, Infinity] | 같다 | 40,320 |

정점 V = 7 이라 V−1 = 6 입니다. 40,320 가지 순서가 모두 정답이 되는 가장 작은 k 는 5 입니다.

<!--/proof-->

`k = 5` 에서 모든 순서가 정답이 되고, `V − 1 = 6` 은 그보다 하나 넉넉합니다. `k = 4` 에서는 39,984 가지가 맞고
336 가지가 틀리니, **한 순서만 시험하고 상한을 정하면 안 된다**는 것도 이 표가 보여 줘요. 상한이 왜 `V − 1` 인지는
단순 경로가 간선을 많아야 `V − 1` 개 지난다는 데서 나오는데, 그 이유는 다음 절에서 값으로 풉니다. 지금까지 해 본
방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 다섯 — 넷은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **간선 목록을 V−1 라운드 완화하고 한 라운드 더 읽기**입니다. 음수 사이클이 없으면
`V − 1` 라운드 안에 값이 다 정해지므로, 그 뒤에 읽는 라운드는 한 칸도 못 고쳐야 해요. 그 라운드가 값을 고치면
음수 사이클이 있다는 뜻입니다.

### 아이디어 상세 — 간선 목록을 V−1 라운드 완화하고 한 라운드 더 읽기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **거리 배열을 시작값으로 두고, 간선 목록을 적힌 차례대로 읽으며
완화하는 라운드를 되풀이하되, 한 라운드가 한 칸도 못 고치면 멈추고, `V` 번째 라운드까지 고치면 음수 사이클로
판정합니다.** 이 방법은 「`k` 번째 라운드가 끝나면 간선을 `k` 개 이하로 쓰는 경로까지는 다 반영돼 있다」는 성질
위에서 동작하는데, 그 「간선을 `k` 개 이하로 쓰는 최단 비용」이 처음 보면 낯설어요. 그래서 그것을 먼저 따로
설명하고, 그다음 실현하는 순서대로 네 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 시작값 적기 | `dist` 를 `Infinity` 로 채우고 `dist[src] = 0` 을 적는다 | — |
| 라운드마다 | 2단계 간선 목록을 한 라운드 완화하기 | 간선을 적힌 차례대로 읽어 완화하고, 고쳤는지를 `changed` 에 남긴다 | 1단계의 `dist` |
| 라운드가 끝날 때마다 | 3단계 고친 것이 없으면 멈추기 | `changed` 가 거짓이면 음수 사이클 없음으로 끝낸다 | 2단계의 `changed` |
| `V` 번째 라운드가 끝날 때 | 4단계 음수 사이클 판정하기 | 그때도 `changed` 가 참이면 음수 사이클 있음으로 끝낸다 | 2단계의 `changed` · 3단계를 지나온 라운드 수 |

#### 먼저 알아 둘 개념 — 간선을 k 개 이하로 쓰는 최단 비용

**간선을 `k` 개 이하로 쓰는 최단 비용**은 `src` 에서 `v` 로 가는 경로 가운데 **간선을 `k` 개까지만 쓰는 것들**
중에서 가장 작은 비용입니다. 이 글은 그 값을 `opt_k(v)` 로 적어요. 그런 경로가 하나도 없으면 `Infinity` 이고,
`k` 에 제한이 없는 값이 `opt(v)` 입니다. 정점마다 값 하나씩, `k` 마다 한 줄이 생기므로 이 글은 `k` 번째 줄을 **층
`k`** 라고 부릅니다.

##### 입력 위의 층

전개 입력에서 층 0 부터 층 6 까지를 그렸습니다. 정점 안의 값이 그 층의 `opt_k(v)` 이고, 굵은 간선이 그 값을 낸
경로의 마지막 간선이에요. 이번 층에서 값이 줄어든 정점은 굵은 테로 그렸습니다.

<!--fig:build-layers-->
![층 k = 0 … 6 — 정점 안의 값은 간선을 k 개 이하로 쓰는 최단 비용](./figs/build-layers.svg)

같은 값을 층마다 한 줄로 모으면 이렇습니다.

<!--proof:layerTable-->

| k | 정점 0 | 정점 1 | 정점 2 | 정점 3 | 정점 4 | 정점 5 | 정점 6 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | Infinity | Infinity | Infinity | Infinity | Infinity | Infinity |
| 1 | 0 | 4 | 9 | Infinity | Infinity | Infinity | Infinity |
| 2 | 0 | 4 | 7 | 6 | Infinity | Infinity | Infinity |
| 3 | 0 | 4 | 7 | 4 | 8 | Infinity | Infinity |
| 4 | 0 | 4 | 7 | 4 | 6 | 9 | Infinity |
| 5 | 0 | 4 | 7 | 4 | 6 | 7 | Infinity |
| 6 | 0 | 4 | 7 | 4 | 6 | 7 | Infinity |

k = 5 부터 줄이 더 바뀌지 않고, 그 줄이 정본의 답 [0, 4, 7, 4, 6, 7, Infinity] 과 같습니다.

<!--/proof-->

층이 오를수록 값이 있는 정점이 늘고, 있던 값은 같거나 작아집니다. 층 `k` 는 층 `k−1` 이 쓸 수 있던 경로를 모두
쓸 수 있고 간선 하나를 더 쓰는 경로까지 후보로 받기 때문이에요.

##### 칸 하나를 읽는 법

칸 하나를 골라 이름에서 경로까지 따라가 봅시다. `opt_3(3)` 은 「정점 3 으로 가는 경로 중 간선을 3 개 이하로 쓰는
것들의 가장 작은 비용」입니다. 정점 3 으로 가는 경로를 전부 놓고 간선 수로 거르면 이렇게 나와요.

<!--proof:layerRead-->

| 경로 | 간선 수 | 비용 | 간선 3 개 이하 |
| --- | ---: | ---: | --- |
| 0→2→3 | 2 | 6 | 든다 |
| 0→1→2→3 | 3 | 4 | 든다 |

간선 3 개 이하에 드는 경로의 비용 중 가장 작은 값은 4 이고, 층 계산이 낸 opt_3(3) 도 4 입니다.

<!--/proof-->

층 2 에서는 간선 셋짜리 `0→1→2→3` 이 빠지므로 `opt_2(3)` 은 6 이에요. 층 표의 정점 3 열이 6 에서 4 로 바뀌는
자리가 바로 그 경로가 후보에 들어온 자리입니다.

##### 층과 층 사이

층 `k` 의 칸은 층 `k−1` 만 보고 만들 수 있습니다. 간선을 `k` 개 이하로 쓰는 경로는 `k−1` 개 이하로 쓰는
경로이거나, 그런 경로 끝에 간선 하나를 이은 것이기 때문이에요. 정점 5 의 층 5 칸을 층 4 에서 만들어 봅니다. 정점
5 로 들어오는 간선은 `4 → 5` 와 `6 → 5` 둘입니다.

<!--proof:layerStep-->

| 후보 | 식 | 값 |
| --- | --- | --- |
| 간선을 더 쓰지 않는다 | opt_4(5) | 9 |
| 간선 4→5 를 끝에 잇는다 | opt_4(4) + 1 | 6 + 1 = 7 |
| 간선 6→5 를 끝에 잇는다 | opt_4(6) + 2 | Infinity + 2 = Infinity |

후보 3 개 가운데 가장 작은 값이 7 이고, 층 계산이 낸 opt_5(5) 와 같습니다.

<!--/proof-->

둘째 후보가 **완화 하나**와 같은 모양입니다. 꼬리의 값에 가중치를 더해 머리의 값과 비교하고 작은 쪽을 남겨요.
그래서 간선 목록 전체를 한 번 읽으며 완화하면 한 층을 올리는 일이 됩니다. 정점 6 처럼 꼬리의 값이 `Infinity` 인
간선은 후보를 만들지 못해요.

##### 라운드 뒤의 dist 와의 차이

층을 처음 보면 「`k` 번째 라운드가 끝난 `dist` 가 곧 층 `k`」라고 읽기 쉽습니다. 전개 입력의 간선 목록을 뒤집은
순서로 실행하고 두 줄을 나란히 놓았어요.

<!--proof:layerVsRound-->

| k | 라운드 k 뒤의 dist | opt_k | opt_k 와의 관계 |
| ---: | --- | --- | --- |
| 0 | [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] | [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] | 칸마다 같다 |
| 1 | [0, 4, 7, 4, 6, 7, Infinity] | [0, 4, 9, Infinity, Infinity, Infinity, Infinity] | 더 작은 칸이 있다 |
| 2 | [0, 4, 7, 4, 6, 7, Infinity] | [0, 4, 7, 6, Infinity, Infinity, Infinity] | 더 작은 칸이 있다 |

간선 목록을 뒤집은 순서로 실행했고, 라운드는 2 번에서 끝났습니다.

<!--/proof-->

라운드 1 이 끝났을 때 `dist[5]` 는 벌써 7 인데 `opt_1(5)` 는 `Infinity` 예요. 한 라운드 안에서 앞에 읽은 간선이
적은 값을 뒤에 읽는 간선이 곧바로 쓰므로, 라운드 하나가 층 하나보다 더 올라갈 수 있습니다. 그래서 둘의 관계는
「같다」가 아니라 「**라운드 `k` 뒤의 `dist[v]` 는 `opt_k(v)` 보다 크지 않다**」예요. 층은 **라운드가 적어도
이만큼은 해 둔다**는 바닥이고, 라운드가 그보다 더 해 두는 것은 간선이 적힌 순서에 달려 있습니다.

##### 층이 멈추는 자리

층을 세운 까닭은 **몇 층이면 끝나는지**를 셀 수 있어서입니다. 음수 사이클이 없으면 최단 경로는 같은 정점을 두 번
지나지 않아요. 순환을 한 번 지나 봐야 비용이 줄지 않으니 빼도 되기 때문입니다. 같은 정점을 두 번 지나지 않는
경로는 간선을 많아야 `V − 1` 개 쓰므로, 층 `V − 1` 에서 모든 최단 경로가 후보에 들어와 있어요. 음수 사이클이 있는
입력과 나란히 놓으면 차이가 보입니다.

<!--proof:layerStop-->

| k | 전개 입력의 opt_k | 음수 사이클 입력의 opt_k |
| ---: | --- | --- |
| 0 | [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] | [0, Infinity, Infinity] |
| 1 | [0, 4, 9, Infinity, Infinity, Infinity, Infinity] | [0, 1, Infinity] |
| 2 | [0, 4, 7, 6, Infinity, Infinity, Infinity] | [0, 1, 0] |
| 3 | [0, 4, 7, 4, 8, Infinity, Infinity] | [-1, 1, 0] |
| 4 | [0, 4, 7, 4, 6, 9, Infinity] | [-1, 0, 0] |
| 5 | [0, 4, 7, 4, 6, 7, Infinity] | [-1, 0, -1] |
| 6 | [0, 4, 7, 4, 6, 7, Infinity] | [-2, 0, -1] |

전개 입력은 정점 7 개라 V−1 = 6 이고, 음수 사이클 입력은 정점 3 개라 V−1 = 2 입니다.

<!--/proof-->

전개 입력은 층 5 에서 멈추고 층 `V − 1 = 6` 도 같은 줄입니다. 음수 사이클 입력은 층 `V − 1 = 2` 를 지나서도 층
3 · 5 · 6 에서 값이 계속 줄어요. **층이 `V − 1` 에서 멈추는가**가 곧 음수 사이클이 없는가이고, 이것이 라운드
상한과 판정 둘 다의 근거입니다.

| 층의 성질 | 까닭 | 이 절차에서 쓰이는 곳 |
| --- | --- | --- |
| 층 `k` 는 층 `k−1` 보다 크지 않다 | 후보가 늘기만 한다 | 라운드가 값을 줄이기만 한다 |
| 층 `k` 는 층 `k−1` 과 완화 한 벌로 만든다 | 간선 하나를 더 잇는 것이 완화다 | 라운드 하나가 층을 적어도 하나 올린다 |
| 음수 사이클이 없으면 층 `V−1` 이 `opt` 다 | 최단 경로가 간선을 많아야 `V−1` 개 쓴다 | 라운드 상한 `V−1` · `V` 번째 라운드의 판정 |

#### 1단계 — 시작값 적기

거리 배열 `dist` 를 전부 `Infinity` 로 채우고 시작 정점만 0 을 적습니다. 이 줄이 곧 층 0 이에요. 간선을 하나도
안 쓰고 갈 수 있는 곳은 시작 정점뿐이고 그 비용이 0 이기 때문입니다.

<!--proof:stageStart-->

| 정점 | dist |
| ---: | --- |
| 0 | 0 |
| 1 | Infinity |
| 2 | Infinity |
| 3 | Infinity |
| 4 | Infinity |
| 5 | Infinity |
| 6 | Infinity |

값이 있는 칸은 dist[0] = 0 하나이고, 나머지 6 칸은 Infinity 입니다.

<!--/proof-->

이 절차는 이웃 목록을 만들지 않습니다. 정점마다 나가는 간선을 찾을 일이 없고 간선 목록 전체를 차례로 읽기만 하기
때문이에요.

#### 2단계 — 간선 목록을 한 라운드 완화하기

간선 목록을 처음부터 끝까지 적힌 차례대로 읽으며 간선마다 완화합니다. 꼬리의 값이 `Infinity` 인 간선은 이을
경로가 없으니 넘어가고, 한 칸이라도 고쳤으면 `changed` 를 참으로 남겨요. 쉬운 경우는 처음 값을 적는 간선이고,
불안한 경우는 **같은 라운드 안에서 앞에 읽은 간선이 적은 값이 뒤에서 낡는** 때입니다. 전개 입력의 둘째 라운드를
간선마다 적었습니다.

<!--proof:stageRound-->

| 차례 | 간선 u→v | dist[u] + w | 그때 dist[v] | 한 일 |
| ---: | --- | --- | --- | --- |
| 1 | 4→5 | dist[4] 가 Infinity | Infinity | 넘어간다 |
| 2 | 3→4 | dist[3] 이 Infinity | Infinity | 넘어간다 |
| 3 | 2→3 | 9 + (-3) = 6 | Infinity | dist[3] = 6 |
| 4 | 1→2 | 4 + 3 = 7 | 9 | dist[2] = 7 |
| 5 | 0→1 | 0 + 4 = 4 | 4 | 그대로 |
| 6 | 0→2 | 0 + 9 = 9 | 7 | 그대로 |
| 7 | 6→5 | dist[6] 이 Infinity | Infinity | 넘어간다 |
| 8 | 5→1 | dist[5] 가 Infinity | 4 | 넘어간다 |

라운드 2 에서 2→3 이 dist[2] = 9 로 dist[3] = 6 을 적은 뒤, 4 번째 간선 1→2 가 dist[2] 를 9 에서 7 로 줄였습니다.

<!--/proof-->

`dist[3] = 6` 은 곧 낡은 값이 된 9 로 만든 값이에요. 그래도 틀린 값은 아닙니다. `0 → 2 → 3` 이라는 실재하는 경로의
비용이고, 층 2 의 `opt_2(3)` 도 6 이니까요. 낡은 값은 다음 라운드가 같은 간선을 다시 읽을 때 고쳐집니다. 이
라운드가 끝나면 모든 정점에서 `dist[v] ≤ opt_2(v)` 가 성립하는데, 그것이 매 라운드 유지되는 까닭은 파트 2 의
「불변식」에서 따집니다.

| 간선을 읽을 때 | 하는 일 | `changed` |
| --- | --- | --- |
| 꼬리의 `dist[u]` 가 `Infinity` 다 | 넘어간다 | 그대로 |
| `dist[u] + w < dist[v]` 다 | `dist[v]` 를 고친다 | 참이 된다 |
| `dist[u] + w ≥ dist[v]` 다 | 그대로 둔다 | 그대로 |

#### 3단계 — 고친 것이 없으면 멈추기

라운드 하나가 한 칸도 못 고쳤으면 그 뒤 라운드도 한 칸도 못 고칩니다. 다음 라운드는 **같은 간선 목록**을 **같은
`dist`** 에서 같은 차례로 읽으니 모든 비교가 앞 라운드와 똑같이 거짓이기 때문이에요. 「전체 컨셉」의 라운드 표에서
라운드 6 이 그 자리였습니다. 라운드 5 가 끝난 `dist` 를 그대로 받아 간선 8 개를 읽었고 고친 칸이 0 개였어요.

그래서 `changed` 가 거짓이면 거기서 끝내도 되고, 그때의 `dist` 가 답입니다. 멈춘 `dist` 는 모든 간선에 대해
`dist[u] + w ≥ dist[v]` 를 만족하는데, 이 조건이 성립하면 어떤 경로를 따라가도 비용이 `dist[v]` 보다 작아질 수
없어요. 경로의 간선마다 이 부등식을 더하면 가운데 항이 지워지고 `dist[src] + (경로의 비용) ≥ dist[v]` 가 남기
때문입니다.

| 멈춘 뒤 | 까닭 |
| --- | --- |
| 다음 라운드도 못 고친다 | 같은 목록 · 같은 `dist` · 같은 비교 |
| `dist[v] ≤ (src 에서 v 로 가는 아무 경로의 비용)` | 간선마다 `dist[u] + w ≥ dist[v]` 를 경로를 따라 더한다 |
| `dist[v]` 는 실재하는 경로의 비용이다 | 실재하는 경로 끝에 실재하는 간선을 이은 값만 적는다 |
| 그래서 `dist[v] = opt(v)` | 위의 두 줄이 양쪽에서 막는다 |

#### 4단계 — V 번째 라운드로 음수 사이클 판정하기

음수 사이클이 없으면 층 `V − 1` 이 `opt` 이고, 라운드 `k` 뒤의 `dist` 는 층 `k` 보다 크지 않으니 `V − 1` 번째
라운드가 끝나면 `dist` 가 답에 이릅니다. 그러면 `V` 번째 라운드는 한 칸도 못 고쳐야 해요. 반대로 **`V` 번째
라운드가 끝났는데도 `changed` 가 참이면** 앞의 가정, 곧 「음수 사이클이 없다」가 성립하지 않는다는 뜻입니다.
여러 입력에서 마지막 라운드가 무엇을 했는지 세었어요.

<!--proof:stageDetect-->

| 입력 | 정점 V | 실행한 라운드 | 마지막 라운드가 고친 칸 | hasNegativeCycle |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 7 | 6 | 0 | false |
| 음수 사이클 0->1->2->0 | 3 | 3 | 3 | true |
| 도달할 수 없는 음수 사이클 | 3 | 1 | 0 | false |
| 시작 정점의 음수 자기 간선 0->0(-1) | 2 | 2 | 2 | true |
| 가중치 합이 0 인 순환 1->2->1 | 3 | 2 | 0 | false |

hasNegativeCycle 칸은 정본이 낸 값입니다.

<!--/proof-->

음수 사이클이 있는 두 입력은 라운드를 `V` 번 다 실행하고 마지막 라운드에서도 칸을 고쳤습니다. 나머지 셋은 그 전에
고친 칸이 없는 라운드를 만나 3단계에서 끝났어요. 가중치 합이 0 인 순환은 한 번 더 지나도 비용이 그대로라 고칠 것을
만들지 않습니다.

| 마지막 라운드 | 판정 | 까닭 |
| --- | --- | --- |
| `V` 번째보다 앞에서 고친 칸이 0 이다 | `false` | 3단계에서 멈췄다 |
| `V` 번째인데 고친 칸이 있다 | `true` | 음수 사이클이 없으면 이 라운드는 고칠 것이 없어야 한다 |

#### 이 방법이 기대는 전제

라운드 상한 `V − 1` 은 「최단 경로가 단순 경로다」라는 전제에서 나왔고, 그 전제는 **시작 정점에서 갈 수 있는 음수
사이클이 없을 때** 성립합니다. 음수 사이클이 있으면 최단 거리가 정해지지 않으니, 이 절차가 그때 돌려주는 `dist`
는 답이 아니라 `V` 라운드를 읽은 뒤의 값일 뿐이에요. 세 입력에서 돌려준 `dist` 뒤에 라운드를 하나 더 읽어 봤습니다.

<!--proof:premiseCycle-->

| 입력 | 돌려준 dist | hasNegativeCycle | 한 라운드 더 읽은 dist |
| --- | --- | --- | --- |
| 전개 입력 | [0, 4, 7, 4, 6, 7, Infinity] | false | 없다 |
| 음수 사이클 0->1->2->0 | [-3, -1, -2] | true | [-4, -2, -3] |
| 도달할 수 없는 음수 사이클 | [0, Infinity, Infinity] | false | 없다 |

마지막 열은 정본이 돌려준 뒤 라운드를 하나 더 읽었을 때 값이 바뀌면 그 dist 를, 안 바뀌면 「없다」를 적었습니다.

<!--/proof-->

음수 사이클 입력에서는 한 라운드를 더 읽자 세 칸이 모두 또 줄었습니다. 그래서 `hasNegativeCycle` 이 `true` 일 때
`dist` 를 최단 거리로 쓰면 안 돼요. 도달할 수 없는 음수 사이클은 반대입니다. 그 사이클의 정점은 `Infinity` 로 남아
완화가 한 번도 일어나지 않으므로 판정에 걸리지 않고, `dist` 도 그대로 답이에요.

| 전제 | 쓰이는 곳 | 깨지면 |
| --- | --- | --- |
| 시작 정점에서 갈 수 있는 음수 사이클이 없다 | 라운드 상한 `V − 1` · 3단계에서 멈춘 `dist` 가 답이라는 것 | `V` 번째 라운드도 값을 고친다 — 4단계가 그것을 판정으로 바꾼다 |
| 아직 값이 없는 정점은 `Infinity` 다 | 꼬리의 값이 없는 간선을 건너뛰는 것 | 도달할 수 없는 음수 사이클까지 판정에 걸린다(「수행으로 알아보는 알고리즘」 첫 짚고 가기) |

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 둘째부터 넷째가 라운드 한 번이에요.

1. `dist` 를 `Infinity` 로 채우고 `dist[src] = 0` 을 적는다
2. 라운드를 `k = 1` 부터 `V` 까지 되풀이하며, 간선 목록을 적힌 차례대로 읽어 꼬리의 값이 없으면 넘어가고 아니면 완화한다
3. 그 라운드가 한 칸도 못 고쳤으면 `{ dist, hasNegativeCycle: false }` 를 돌려준다
4. `k = V` 인데 고쳤으면 `{ dist, hasNegativeCycle: true }` 를 돌려준다
5. 아니면 다음 라운드로 간다

### 수행으로 알아보는 알고리즘 — 간선 여덟 개를 여섯 라운드 읽는다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 그래프 하나를 정해 끝까지 가져가되, 코드
조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

<!--proof:walkInput-->

```ts
const n = 7;
const edges: [number, number, number][] = [
  [4, 5, 1], [3, 4, 2], [2, 3, -3], [1, 2, 3],
  [0, 1, 4], [0, 2, 9], [6, 5, 2], [5, 1, 7],
];
const src = 0;
// 이 절이 끝나면 나와야 하는 값: { dist: [0, 4, 7, 4, 6, 7, Infinity], hasNegativeCycle: false }
```

왜 이 여덟 간선일까요? 「아이디어를 떠올리는 과정」에서 순서 40,320 가지를 전부 실행했을 때 **라운드 수가 가장
많은 6 이 되는 336 가지 중 하나**이기 때문이에요. 사슬 `0 → 1 → 2 → 3 → 4 → 5` 를 거꾸로 적어 두어 라운드마다
값이 한두 정점씩만 늘고, 그래서 여섯 갈래 중 다섯이 한 입력에서 실행됩니다. 정점 6 은 들어오는 간선이 없어
`Infinity` 로 남고, `5 → 1` 은 값을 못 고치는 간선이에요.

```text
절차 전체를 한 장으로

  T1     dist 를 Infinity 로 채우고 dist[src] = 0 을 적는다     ① 시작값
         라운드를 최대 n 번 되풀이한다:                         ② 라운드
  T2~T7    간선 [u, v, w] 마다
             dist[u] 가 Infinity 면 넘어간다                    ③ 값이 없는 정점
             dist[u] + w 가 dist[v] 보다 작으면 고쳐 적는다     ④ 완화
           그 라운드가 한 칸도 못 고쳤으면 끝낸다               ⑤ 조기 종료
           n 번째 라운드인데도 고쳤으면 끝낸다                  ⑥ 음수 사이클
  T8     dist 와 판정을 돌려준다
```

#### 1. 거리 배열을 시작값으로 둔다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 길이 `n` 인 배열을 만들어 전부 `Infinity` 로 채우고 `src` 칸에만
`0` 을 적어요.

```ts
const dist: number[] = Array.from(
  { length: n },
  () => Number.POSITIVE_INFINITY,
);
dist[src] = 0;                    // ① 시작 정점만 0 이다
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walkT1-->

```text
T1 이 끝난 시점
  dist       [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity]
  간선 목록  [4,5,1] [3,4,2] [2,3,-3] [1,2,3] [0,1,4] [0,2,9] [6,5,2] [5,1,7]
  읽은 간선  0 개
```

`①` 이 뜻하는 것은 「`src` 까지 가는 데 드는 비용이 0 이다」 하나예요. 나머지 칸의 `Infinity` 는 아직 아무 경로도
못 찾았다는 표시이고, 이 표시가 다음 조각에서 갈래 `③` 의 조건이 됩니다.

#### 2. 간선 목록을 한 라운드 읽는다

2단계를 코드로 옮깁니다. 간선 목록을 처음부터 끝까지 읽으면서 간선마다 완화하고, 무엇인가 고쳤는지를 `changed`
에 남겨요.

```ts
let changed = false;
for (const [u, v, w] of edges) {
  if (dist[u] === Number.POSITIVE_INFINITY) continue;   // ③ 값이 없는 정점
  const nd = (dist[u] as number) + w;
  if (nd < (dist[v] as number)) {                       // ④ 완화
    dist[v] = nd;
    changed = true;
  }
}
```

첫 라운드만 실행하면 이렇게 나옵니다.

<!--proof:walkT2-->

```text
T2 — 첫 라운드가 간선 여덟 개를 차례로 읽는다
  [4,5,1]   dist[4] 가 Infinity — ③ 넘어간다
  [3,4,2]   dist[3] 이 Infinity — ③ 넘어간다
  [2,3,-3]  dist[2] 가 Infinity — ③ 넘어간다
  [1,2,3]   dist[1] 이 Infinity — ③ 넘어간다
  [0,1,4]   0 + 4 = 4 < Infinity — ④ dist[1] = 4
  [0,2,9]   0 + 9 = 9 < Infinity — ④ dist[2] = 9
  [6,5,2]   dist[6] 이 Infinity — ③ 넘어간다
  [5,1,7]   dist[5] 가 Infinity — ③ 넘어간다

  라운드가 끝난 dist  [0, 4, 9, Infinity, Infinity, Infinity, Infinity]
  changed             true
```

여덟 간선 중 여섯이 `③` 이었다는 것을 봐 주세요. 목록의 순서가 사슬과 반대라서 첫 라운드가 할 수 있는 일이
「출발점에서 나가는 간선 두 개」뿐입니다.

#### 짚고 가기 — 값이 없는 정점을 건너뛰는 줄을 빼도 Infinity 를 쓰면 답이 안 틀린다

여기서 헷갈리기 쉬운 포인트는 `③` 한 줄입니다. 「`dist[u]` 가 `Infinity` 면 `Infinity + w` 도 `Infinity` 라
어차피 완화 조건이 거짓인데, 이 줄이 왜 필요한가」로 읽기 쉬워요. 그 줄을 통째로 빼 봅시다.

```ts
for (const [u, v, w] of edges) {
  // ③ 이 있던 자리를 비웠다
  const nd = (dist[u] as number) + w;
  if (nd < (dist[v] as number)) { dist[v] = nd; changed = true; }
}
```

<!--proof:pauseGuard-->

```text
입력                        정본                                  ③ 을 뺀 판                            판정
전개 입력                   [0, 4, 7, 4, 6, 7, Infinity] · false  [0, 4, 7, 4, 6, 7, Infinity] · false  같다
음수 사이클 0->1->2->0      [-3, -1, -2] · true                   [-3, -1, -2] · true                   같다
도달할 수 없는 음수 사이클  [0, Infinity, Infinity] · false       [0, Infinity, Infinity] · false       같다

「아직 값이 없다」를 Infinity 대신 10^15 로 적고 ③ 도 뺀 판
입력                        정본   10^15 을 쓰고 ③ 을 뺀 판  판정
전개 입력                   false  false                     같다
음수 사이클 0->1->2->0      true   true                      같다
도달할 수 없는 음수 사이클  false  true                      다르다

전개 입력에서 ③ 이 참이 된 횟수  16 번 (간선 읽기 48 번 중)
```

**위쪽 표에서는 답이 한 칸도 안 갈립니다.** `Infinity + w` 가 `Infinity` 이고 `Infinity < Infinity` 가 거짓이라,
그 줄이 없어도 값이 안 바뀌어요. 그래서 이 줄을 뺀 채로 시험을 실행해도 전부 통과합니다. 아래쪽 표가 그럼에도 이
줄을 두는 이유예요. 「아직 값이 없다」를 `Infinity` 가 아니라 큰 수 하나로 적는 구현이 흔한데, 그 순간 `③` 이
없으면 도달할 수 없는 음수 사이클에서 답이 틀립니다. 그 입력에서 두 판이 라운드마다 적은 값을 놓았어요.

<!--proof:pauseGuardWhere-->

```text
입력  1 -(1)-> 2 · 2 -(-5)-> 1 · src = 0

  판              라운드  라운드가 끝난 dist
  정본            1       [0, Infinity, Infinity]
  10^15 을 쓴 판  1       [0, 999,999,999,999,995, 10^15]
  10^15 을 쓴 판  2       [0, 999,999,999,999,991, 999,999,999,999,996]
  10^15 을 쓴 판  3       [0, 999,999,999,999,987, 999,999,999,999,992]

  정본            라운드 1 에서 끝나 hasNegativeCycle = false
  10^15 을 쓴 판  라운드 3 = n 까지 고쳐 hasNegativeCycle = true
```

`10^15 − 5` 가 `10^15` 보다 작으니 「값이 없는」 정점에서 나가는 간선이 완화를 일으키고, 그 사이클이 라운드마다
값을 줄여 `n` 번째 라운드까지 고칩니다. 정본은 `③` 이 두 간선을 매번 건너뛰어 첫 라운드에서 끝나요. 이 줄은 답을
지키는 줄이 아니라 **「값이 없다」를 무엇으로 적든 판정이 그 표기에 딸리지 않게 하는 줄**이고, 전개 입력에서
간선 읽기 48 번 중 16 번의 덧셈과 비교를 덜어 주기도 합니다.

#### 3. 고친 것이 없으면 멈추고, n 번째 라운드면 음수 사이클로 판정한다

3단계와 4단계를 코드로 옮깁니다. 앞 조각을 라운드 반복 안에 넣고, 라운드가 끝날 때마다 두 조건을 봅니다.

```ts
for (let round = 1; round <= n; round++) {              // ② 라운드
  let changed = false;
  // … 간선 목록을 한 라운드 읽는다 …
  if (!changed) return { dist, hasNegativeCycle: false };  // ⑤ 조기 종료
  if (round === n) return { dist, hasNegativeCycle: true }; // ⑥ 음수 사이클
}
```

이 조각을 전개 입력과 음수 사이클 입력에 실행하면 서로 다른 `return` 으로 끝납니다.

<!--proof:walkStop-->

```text
전개 입력               n = 7  라운드 6 에서 changed = false · round === n 이 false  ⑤ 조기 종료 -> hasNegativeCycle = false
음수 사이클 0->1->2->0  n = 3  라운드 3 에서 changed = true · round === n 이 true    ⑥ 음수 사이클 -> hasNegativeCycle = true
```

`⑤` 와 `⑥` 이 한 쌍입니다. `⑤` 로 끝나지 않고 `n` 번째 라운드까지 왔다는 것은 **`n` 번째 라운드도 값을 고쳤다**는
뜻이고, 라운드 상한이 `V − 1` 이므로 그것은 음수 사이클이 있을 때만 가능해요.

#### 짚고 가기 — 라운드를 V−1 번만 실행하면 음수 사이클을 못 찾는다

여기서 헷갈리기 쉬운 포인트는 `②` 의 상한입니다. 「라운드 상한이 `V − 1` 이라고 해 놓고 왜 반복은 `V` 번까지
하는가, `V − 1` 이면 되는 것 아닌가」로 읽기 쉬워요. 그 생각대로 상한을 하나 줄여 봅시다.

```ts
for (let round = 1; round < n; round++) {   // n 번째 라운드를 실행하지 않는다
  // … 나머지는 같다 …
}
```

<!--proof:pauseShortLoop-->

```text
입력                        정본                                  라운드를 n−1 번만 실행한 판           판정
전개 입력                   [0, 4, 7, 4, 6, 7, Infinity] · false  [0, 4, 7, 4, 6, 7, Infinity] · false  같다
음수 사이클 0->1->2->0      [-3, -1, -2] · true                   [-2, 0, -1] · false                   다르다
도달할 수 없는 음수 사이클  [0, Infinity, Infinity] · false       [0, Infinity, Infinity] · false       같다
```

**전개 입력에서는 답이 같고 음수 사이클 입력에서 갈립니다.** `true` 여야 하는 판정이 `false` 로 나오고 `dist` 도
한 라운드 덜 읽은 값이 돼요. 두 판이 라운드마다 한 일을 놓으면 이렇습니다.

<!--proof:pauseShortLoopWhere-->

```text
음수 사이클 0->1->2->0 · n = 3
  정본           라운드 1 고침 3 · 라운드 2 고침 3 · 라운드 3 고침 3
                 라운드 3 에서 round === n 이 참 -> ⑥ -> [-3, -1, -2] · true
  n−1 번만 실행  라운드 1 고침 3 · 라운드 2 고침 3
                 round === n 이 한 번도 참이 안 되고 루프 뒤 return -> [-2, 0, -1] · false
```

**`V − 1` 은 거리를 완성하는 데 드는 라운드 수이고, 음수 사이클 판정은 그 뒤에 한 라운드를 더 읽어야 나옵니다.**
전개 입력에서 답이 같은 까닭은 그 그래프가 라운드 6 에서 `⑤` 로 끝나서, 상한을 6 으로 줄여도 같은 자리에서 같은
값을 돌려주기 때문이에요.

| 목적 | 라운드 | 까닭 |
| --- | --- | --- |
| 최단 거리를 완성한다 | `V − 1` | 최단 경로가 지나는 간선이 많아야 `V − 1` 개다 |
| 음수 사이클을 판정한다 | 그 뒤 1 | 완성됐다면 더 고쳐질 것이 없어야 한다 |
| 이 코드의 반복 | `V` | 위 둘을 한 반복에서 끝낸다 |

반환이에요. 걸음 재생 패널에서 정점 안의 수는 그 라운드가 끝난 뒤의 `dist` 이고, 점선 정점은 아직 값이 없는
정점입니다. 굵은 실선은 지금 그 정점의 값을 낸 간선이에요. 무대 아래 두 줄이 간선 목록을 적힌 차례대로 늘어놓은

조기 종료와 음수 사이클은 한 입력에서 함께 참이 될 수 없습니다. `⑤` 로 끝나면 `⑥` 에 이르지 못하기 때문이에요.
그래서 `⑥` 은 음수 사이클 `0 → 1 → 2 → 0` 을 넣어 확인했고, 그 입력에서는 `③` 과 `⑤` 가 0 번입니다.

#### 짚고 가기 — 조기 종료를 빼면 음수 사이클이 없어도 판정이 true 가 된다

여기서 헷갈리기 쉬운 포인트는 `⑤` 의 직무입니다. 「조기 종료는 빨리 끝내려고 붙인 곁가지이니 빼도 답은 같겠지」로
읽기 쉬워요. 그 줄이 참이 되지 못하게 막아 봅시다.

```ts
if (false) return { dist, hasNegativeCycle: false };      // ⑤ 를 막았다
if (round === n) return { dist, hasNegativeCycle: true };
```

<!--proof:pauseEarlyExit-->

```text

도달할 수 없는 음수 사이클  [0, Infinity, Infinity] · false       [0, Infinity, Infinity] · true       다르다
```

`dist` 는 한 칸도 안 갈리는데 `hasNegativeCycle` 이 `false` 에서 `true` 로 바뀝니다. `⑥` 의 조건이 `round === n`
하나뿐이라, `⑤` 가 막히면 **음수 사이클이 없는 그래프도 `n` 번째 라운드에 이르러 `true` 를 돌려줘요.**

<!--proof:pauseEarlyExitWhere-->

```text

  정본          라운드 6 이 고친 칸 0 -> ⑤ 가 참 -> false 로 반환
  ⑤ 를 막은 판  라운드 6 도 그대로 지나간다 -> 라운드 7 에서 round === n -> true 로 반환
```

`⑤` 는 「빨리 끝내는 장치」가 아니라 `⑥` 이 참이 되는 조건의 절반입니다. 「`n` 번째 라운드에 이르렀다」가 「`n`
번째 라운드도 고쳤다」와 같은 뜻이 되려면 `⑤` 가 있어야 해요.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 반복 뒤의 `return` 하나뿐인데, `n ≥ 1` 이면 `⑤`
나 `⑥` 중 하나가 반드시 먼저 돌려주므로 그 줄은 실행되지 않아요. 타입이 그것을 요구해서 둔 자리입니다.

```ts
export type Edge = [number, number, number];

export interface Result {
  dist: number[];
  hasNegativeCycle: boolean;
}

export function bellmanFord(n: number, edges: Edge[], src: number): Result {
  // ① 시작값 — 아직 아무 경로도 찾지 못했으므로 전부 `Infinity` 이고 시작 정점만 `0` 이다.
  const dist: number[] = Array.from(
    { length: n },
    () => Number.POSITIVE_INFINITY,
  );
  dist[src] = 0;

  // ② 라운드 — 간선 목록을 처음부터 끝까지 한 번 읽는 것이 라운드 하나다. 많아야 `n` 라운드다.
  for (let round = 1; round <= n; round++) {
    let changed = false;

    for (const [u, v, w] of edges) {
      // ③ 값이 없는 정점 — `dist[u]` 가 `Infinity` 면 `u` 까지 가는 경로를 아직 못 찾았다.
      if (dist[u] === Number.POSITIVE_INFINITY) continue;

      const nd = (dist[u] as number) + w;
      // ④ 완화 — 지금 적힌 값보다 작을 때만 고쳐 적고, 고쳤다는 사실을 남긴다.
      if (nd < (dist[v] as number)) {
        dist[v] = nd;
        changed = true;
      }
    }

    // ⑤ 조기 종료 — 한 라운드가 한 칸도 못 고치면 그 뒤 라운드도 못 고친다.
    if (!changed) return { dist, hasNegativeCycle: false };

    // ⑥ 음수 사이클 — `n` 번째 라운드가 아직도 값을 고치면 줄어드는 자리가 끝나지 않는다.
    if (round === n) return { dist, hasNegativeCycle: true };
  }

  return { dist, hasNegativeCycle: false };
}
```

실행하면 이렇게 나옵니다.

```text

bellmanFord(3, [[0,1,1],[1,2,-1],[2,0,-1]], 0)                                         -> { dist: [-3, -1, -2], hasNegativeCycle: true }
bellmanFord(3, [[1,2,1],[2,1,-5]], 0)                                                  -> { dist: [0, Infinity, Infinity], hasNegativeCycle: false }
bellmanFord(3, [], 1)                                                                  -> { dist: [Infinity, 0, Infinity], hasNegativeCycle: false }

```

### 알아 두면 좋은 개념 — 고정점 반복

이 절차가 반복을 끝낸 방식에는 이름이 붙어 있습니다. T7 에서 「간선 여덟 개를 다시 읽었는데 고칠 것이 없다」를
확인하고 멈췄는데, 같은 규칙을 한 번 더 적용해도 상태가 바뀌지 않는 그 상태를 **고정점**이라고 부르고, 고정점에
이를 때까지 규칙을 되풀이하는 것을 **고정점 반복**이라고 합니다. 라운드 하나를 적용하는 일을 규칙 `F` 라고 부르고
걸음마다 놓으면 이렇습니다.

<!--proof:relatedFixed-->

```text
  T1 의 dist  [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity]  F 를 적용하면 T2 의 dist 가 된다
  T2 의 dist  [0, 4, 9, Infinity, Infinity, Infinity, Infinity]                F 를 적용하면 T3 의 dist 가 된다
  T3 의 dist  [0, 4, 7, 6, Infinity, Infinity, Infinity]                       F 를 적용하면 T4 의 dist 가 된다
  T4 의 dist  [0, 4, 7, 4, 8, Infinity, Infinity]                              F 를 적용하면 T5 의 dist 가 된다
  T5 의 dist  [0, 4, 7, 4, 6, 9, Infinity]                                     F 를 적용하면 T6 의 dist 가 된다
  T6 의 dist  [0, 4, 7, 4, 6, 7, Infinity]                                     F 를 적용해도 그대로다
```

`⑤` 가 검사하는 것이 바로 「`F(x) = x` 인가」입니다. 이 관점에서 보면 `V − 1` 라운드라는 상한은 **고정점에 이르기까지
몇 번이면 되는지의 보장**이고, 음수 사이클은 **고정점이 없는 경우**예요. 값이 계속 작아지기만 해서 `F(x) = x` 인
`x` 가 없습니다. 같은 모양이 다른 자리에서도 나옵니다.

| 다른 자리 | 규칙 F | 고정점의 뜻 |
| --- | --- | --- |
| 컴파일러의 데이터 흐름 분석 | 각 지점의 「도달하는 정의 집합」을 이웃에서 다시 계산한다 | 더 늘어날 정의가 없다 |
| 마르코프 결정 과정의 값 반복 | 각 상태의 기대 보상을 한 걸음 앞으로 다시 계산한다 | 최적 가치 함수 |
| 정규 표현식 엔진의 `ε` 닫힘 | 지금 상태 집합에 `ε` 로 갈 수 있는 상태를 더한다 | 더 더할 상태가 없다 |

셋 다 「규칙을 되풀이하다 상태가 안 바뀌면 멈춘다」와 「몇 번이면 반드시 멈추는가」 두 질문을 같은 모양으로 답합니다.
뒤 질문의 답이 이 편에서는 `V − 1` 이었어요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 라운드 상한을 식으로 어떻게 적는지, 무엇이 매
라운드 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 가중치에 음수가 있다 | 음수가 하나도 없으면 확정 판정이 성립해 `dijkstra` 가 간선을 한 번씩만 읽는다 | 확정이 없고 간선 목록을 라운드마다 다시 읽는다 |
| 음수 사이클이 있는지 함께 묻는다 | 거리와 판정을 한 번의 실행으로 같이 낸다 | 반복의 상한이 `V − 1` 이 아니라 `V` 다 |
| 정점 수가 크지 않다 | 간선 읽기가 `V × E` 까지 간다 | 라운드마다 간선 목록 전체를 읽는다 |
| 사이클이 있을 수 있다 | 사이클이 없으면 위상 순서로 한 번씩만 완화하면 된다 | 정점의 차례를 정하지 않는다 |

첫 조건이 이 절차의 자리입니다. 가중치가 전부 0 이상이면 [`dijkstra`](../dijkstra/dijkstra-guide.md) 쪽이 같은
답을 훨씬 적은 연산으로 내고, 사이클이 없는 방향 그래프면
[`dagShortestPath`](../dagShortestPath/dagShortestPath-guide.md) 가 위상 순서로 한 번에 끝냅니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "손해" "이득" "환급" "할인"                  <- 가중치가 음수일 수 있다
  "무한히 이득이 나는 순환" "차익거래"         <- 음수 사이클 판정을 묻는다
  "비용이 음수일 수 있다"                      <- 확정 판정을 쓰는 절차가 안 된다
  "한 지점에서 각 지점까지"                    <- 시작 정점이 하나다

제약에 이런 모양이 보이면
  정점이 수백 개이고 간선이 정점 수의 제곱 언저리다  <- V x E 가 1 억 대라 감당할 수 있다
  가중치가 10^9 까지 커진다                    <- 거리 합이 32 비트 정수를 넘을 수 있다

반대로 이런 말이 보이면 해당하지 않는다
  "비용은 항상 0 이상"                         <- 확정 판정을 쓰는 절차가 더 적다
  "정점이 10^5 개"                             <- V x E 가 감당할 수 없다
  "모든 정점 쌍 사이의 거리"                   <- 시작 정점이 V 개다
```

마지막 무리가 보이면 다른 절차로 갑니다. 정점 쌍 전부를 물으면
[플로이드-워셜](../floydWarshall/floydWarshall-guide.md)이 적고, 정점이 10 만 개인데
가중치가 0 이상이면 [`dijkstra`](../dijkstra/dijkstra-guide.md) 가 그 자리를 맡아요.

#### 실제로 쓰이는 곳

- **RIP — 라우터가 이웃과 거리 표를 주고받아 경로를 정하는 인터넷 표준.** 표준 문서가 이 알고리즘을 이름으로
  지정합니다. *"RIP is a routing protocol based on the Bellman-Ford (or distance vector) algorithm."* 그리고 같은
  문서가 **라운드 상한을 프로토콜의 제약으로** 옮겨 적어 두었어요 — *"The protocol is limited to networks whose
  longest path (the network's diameter) is 15 hops."* 이 글의 `V − 1` 이 거기서는 15 라는 상수가 된 자리입니다.
  ([RFC 2453 "RIP Version 2" §3.1·§3.2](https://www.rfc-editor.org/rfc/rfc2453.txt), 1998-11, 조회 2026-09-04)
- **Boost Graph Library 의 `bellman_ford_shortest_paths`** — 문서가 라운드 수와 판정 방법을 그대로 적습니다.
  *"The algorithm repeats this loop |V| times after which it is guaranteed that the distances to each vertex have
  been reduced to the minimum possible unless there is a negative cycle in the graph."* 판정은 목록을 한 번 더
  읽어 확인하는 방식이라 *"The algorithm loops over the edges in the graph one final time to check if all the edges
  were minimized"* 로 적혀 있고, 이 글이 `⑤`·`⑥` 으로 한 반복에 합친 것과 갈리는 자리예요.
  ([`bellman_ford_shortest_paths`](https://www.boost.org/doc/libs/1_86_0/libs/graph/doc/bellman_ford_shortest.html),
  조회 2026-09-04)
- **NetworkX 의 `negative_edge_cycle`** — 음수 사이클 판정만 따로 내주는 함수입니다. *"Returns True if there
  exists a negative edge cycle anywhere in G."* 여기서 `anywhere` 가 이 글의 과제와 갈리는 자리인데, 그 문서가
  어떻게 넓히는지도 함께 적어 두었어요 — *"finds negative cycles on any component by first adding a new node
  connected to every node, and starting bellman_ford_predecessor_and_distance on that node."*
  ([`negative_edge_cycle`](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.shortest_paths.weighted.negative_edge_cycle.html),
  조회 2026-09-04)

| 쓰이는 곳 | 하는 일 | 판정하는 음수 사이클 |
| --- | --- | --- |
| RIP 라우터 | 이웃이 보낸 거리 표에 자기 링크 비용을 더해 자기 표를 고친다 | 판정하지 않고 거리 상한 15 로 막는다 |
| Boost | 간선 목록을 정점 수만큼 읽고 한 번 더 읽어 판정한다 | 시작 정점에서 갈 수 있는 것 |
| NetworkX | 모든 정점으로 가는 새 정점을 하나 더해 판정한다 | 그래프 어디에든 있는 것 |

#### 경쟁 설계와의 대조

같은 목표(음수 가중치가 있는 그래프에서 한 출발점 최단 거리와 음수 사이클 판정)를 노리는 다른 절차로
**SPFA**(Shortest Path Faster Algorithm)가 있습니다. 라운드라는 개념을 버리고, **값이 고쳐진 정점만 큐에 넣어 그
정점에서 나가는 간선만** 다시 읽는 방식이에요. 음수 사이클은 정점마다 큐에 넣은 횟수를 세다가 그것이 `V` 에
이르면 판정합니다. 음수 사이클이 없으면 한 정점을 `V − 1` 번보다 많이 넣지 않는다는 상한과 그 판정은
[`spfa`](../spfa/spfa-guide.md) 편의 「이 방법이 기대는 전제」가 다룹니다.

| 설계 | 한 번의 실행에서 읽는 간선 | 비용을 정하는 것 |
| --- | --- | --- |
| 이 가이드의 절차 | 라운드마다 간선 목록 전체 | 라운드 수 |
| SPFA | 고쳐진 정점에서 나가는 간선 — 그 정점을 여러 번 꺼내면 여러 번 | 한 정점을 몇 번 꺼내는가 |

같은 그래프 · 같은 작업에 두 설계를 적용하고 **기본 연산**을 `tools/bench-alt.ts` 로 세었습니다. 기본 연산은 이
글의 비용 기준인 간선 읽기에 큐에 넣고 꺼낸 횟수를 더한 것이라, 큐가 없는 이 절차에서는 간선 읽기와 같아요. 거리
배열을 채우는 초기화 쓰기는 두 설계 모두 세지 않았습니다. 메모리는 입력 밖에 잡은 칸이 가장 많았을 때의 **추가 칸**으로
셉니다. 거리 배열 칸에 보조 배열 칸과 큐가 가장 길었을 때의 항목 수(항목 하나를 한 칸)를 더하고, 입력 간선 목록과
SPFA 가 만드는 이웃 목록은 넣지 않았어요. 그래프는 사슬 16 개가 허브
하나로 들어가고 그 허브에서 잎 `p` 개로 나가는 모양이에요. 사슬 간선의 가중치는 첫 칸만 100 이고 나머지는 1 이며,
사슬 `i` 에서 허브로 가는 간선의 가중치는 `2(16 − i)` 라 사슬을 더 깊이 지날수록 허브까지의 값이 1 씩 작아집니다.
**간선 목록에서 사슬은 내림차순으로 적어요** — 이 순서가 라운드 방식에 가장 불리한 자리입니다. **전개 입력을
그대로 쓰지 않은 이유**는 그 그래프가 정점 일곱이라 허브의 간선 수를 늘릴 자리가 없기 때문이에요.

| --- | ---: | ---: | --- | ---: |
| 1 개 | 561 | 106 | SPFA | 455 |
| 65 개 | 1,649 | 1,642 | SPFA | 7 |

추가 칸은 잎 4,096 개에서 이 가이드의 절차가 4,115 개, SPFA 가 16,440 개입니다. 전개 입력에서는 기본 연산이 48 번 대 19 번, 추가 칸이 8 개 대 23 개입니다. 두 계수는 잎 66 개에서 같아지고 67 개부터 이 절차가 적습니다.

경계가 그 자리인 까닭은 잎을 하나 더할 때 두 계수가 얼마씩 느는지로 나옵니다.

입력에서도 48 번 대 19 번으로 많아요. 고칠 것이 없는 간선도 라운드마다 다시 읽는 것이 그 대가입니다. 그 대신 얻는
것이 셋이에요.

| 축 | 이 가이드의 절차 | SPFA |
| --- | --- | --- |
| 추가 칸 | 거리 배열과 `changed` 하나 | 거리 배열 · 큐 표시 · 넣은 횟수 배열 · 큐 |
| 한 정점의 간선을 여러 번 읽는 그래프 | 라운드 수만큼만 읽는다 | 그 정점을 꺼낸 횟수만큼 읽고 큐 연산이 붙는다 |
| 최악의 보장 | 라운드가 `V` 를 넘지 않는다 | 한 정점을 `V` 번까지 꺼낼 수 있다 |

같은 그래프에서 **한 정점의 값이 여러 번 고쳐지고 그 정점의 나가는 간선이 많아지는 순간** 이 판정은 다시 해야
합니다. 위 그래프에서는 그 경계가 잎 66 개였어요.

### 수식 정의와 유도

간선 수에 제한을 둔 최단 비용을 기호로 정의합니다. $\mathcal{P}_k(v)$ 는 `src` 에서 $v$ 로 가는 경로 중 **간선을
$k$ 개 이하로 쓰는 것**의 집합이고, 그 집합의 원소 하나를 $P$ 라고 씁니다. 원소가 하나도 없는 집합의 최솟값은
$\infty$ 로 약속해요.

$$\mathcal{P}_k(v) = \{\, P : P \text{ 는 } src \text{ 에서 } v \text{ 로 가는 경로이고 } |P| \le k \,\}, \qquad \mathrm{opt}_k(v) = \min_{P \in \mathcal{P}_k(v)} \sum_{(a,b,w) \in P} w$$

정의를 그대로 계산하는 방법(단순 경로를 전부 만들어 간선 수가 $k$ 이하인 것만 골라 최솟값을 취하기)과 아래
점화식으로 층을 하나씩 올리는 방법을 전개 입력에서 나란히 놓았습니다.

<!--proof:mathCheck-->

```text
출발점 0 에서 나가는 단순 경로가 10 개다

k  경로를 전부 만들어 고른 최솟값                                   점화식이 낸 값                                                   판정
0  [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity]  [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity]  같다
1  [0, 4, 9, Infinity, Infinity, Infinity, Infinity]                [0, 4, 9, Infinity, Infinity, Infinity, Infinity]                같다
2  [0, 4, 7, 6, Infinity, Infinity, Infinity]                       [0, 4, 7, 6, Infinity, Infinity, Infinity]                       같다
3  [0, 4, 7, 4, 8, Infinity, Infinity]                              [0, 4, 7, 4, 8, Infinity, Infinity]                              같다
4  [0, 4, 7, 4, 6, 9, Infinity]                                     [0, 4, 7, 4, 6, 9, Infinity]                                     같다
5  [0, 4, 7, 4, 6, 7, Infinity]                                     [0, 4, 7, 4, 6, 7, Infinity]                                     같다
6  [0, 4, 7, 4, 6, 7, Infinity]                                     [0, 4, 7, 4, 6, 7, Infinity]                                     같다
```

점화식은 이렇게 유도합니다. 간선을 $k$ 개 이하로 쓰는 경로는 **간선을 $k-1$ 개 이하로 쓰는 경로**이거나, 그런
경로 뒤에 간선 $(u, v, w)$ 하나를 이은 것이에요. 앞의 경우의 최솟값이 $\mathrm{opt}_{k-1}(v)$ 이고, 뒤의 경우는
앞부분이 $u$ 까지 가는 $k-1$ 개 이하 경로이므로 그 최솟값이 $\mathrm{opt}_{k-1}(u) + w$ 입니다. 두 경우를 합치면
이렇게 돼요.

$$\mathrm{opt}_k(v) = \min\Bigl(\mathrm{opt}_{k-1}(v),\ \min_{(u,v,w) \in E} \bigl(\mathrm{opt}_{k-1}(u) + w\bigr)\Bigr), \qquad \mathrm{opt}_0(src) = 0,\ \mathrm{opt}_0(v \ne src) = \infty$$

```ts
// 식을 그대로 옮긴 조각. `cur` 가 opt_(k−1) 의 줄이고 `next` 가 opt_k 의 줄이다.
const next = cur.slice();
for (const [u, v, w] of edges) {
  const nd = (cur[u] as number) + w;
  if (nd < (next[v] as number)) next[v] = nd;
}
```

여기서 본문의 값만으로는 안 나오는 것이 나옵니다. **$k$ 를 어디까지 올려야 하는지의 일반식**이에요. 시작 정점에서
갈 수 있는 음수 사이클이 없으면, 순환을 품은 경로는 그 순환을 빼도 비용이 늘지 않으므로 최단 경로를 단순 경로 중에서
고를 수 있습니다. 정점이 $V$ 개인 그래프에서 단순 경로는 간선을 많아야 $V-1$ 개 쓰므로 $\mathcal{P}_{V-1}(v)$ 가
이미 최단 경로를 품고 있어요.

$$\text{음수 사이클이 없으면} \quad \mathrm{opt}(v) = \mathrm{opt}_{V-1}(v) = \mathrm{opt}_{V}(v)$$

| 걸음 | 얻는 것 |
| --- | --- |
| 점화식 | $\mathrm{opt}_k$ 를 $\mathrm{opt}_{k-1}$ 과 완화 한 벌로 계산하는 방법 |
| 단순 경로 논증 | $k$ 를 $V-1$ 까지만 올리면 된다는 것 |
| 라운드와의 대응(불변식) | $k$ 번째 라운드 뒤의 `dist` 가 $\mathrm{opt}_k$ 보다 크지 않다는 것 |
| 대우 | $\mathrm{opt}_{V} \ne \mathrm{opt}_{V-1}$ 이면, 곧 $V$ 번째 라운드가 값을 고치면 음수 사이클이 있다는 것 |

이 일반식에 규모를 넣으면 라운드 상한, 간선 읽기 상한, 그리고 거리 값이 얼마나 커질 수 있는지가 나옵니다.

<!--proof:mathScale-->

```text
정점 V  간선 E = V(V−1)  라운드 상한 V−1  간선 읽기 상한 V x E
10      90               9                900
100     9,900            99               990,000
500     249,500          499              124,750,000

제약 상한에서
  거리 값의 절댓값         (V−1) x 1,000,000,000 = 499,000,000,000 까지
  정수를 정확히 담는 한계  2^53 − 1 = 9,007,199,254,740,991
  둘의 비                  18,050 배 넘게 남는다
```

마지막 줄이 이 절이 함께 주는 것이에요. 단순 경로의 간선이 많아야 `V − 1` 개이니 거리 값의 절댓값도 그 수에 가중치
상한을 곱한 값을 넘지 않고, 그것이 자바스크립트 수가 정수를 정확히 담는 한계보다 만 배 넘게 작아서 이 규모에서는
덧셈이 값을 잃을 자리가 없습니다.

### 불변식 — k 번째 라운드가 끝나면 dist 가 간선 k 개 이하 최단 비용보다 크지 않다

파트 1 의 여덟 걸음은 그래프 하나에서 답이 나왔다는 기록입니다. 그 하나로는 다른 입력에서도 같은 일이 일어난다는
근거가 안 되므로, **라운드가 몇 번 실행되든 참으로 남는 문장**을 세우고 그것이 유지되는지를 값으로 확인합니다.

> `k` 번째 라운드가 끝난 시점에 모든 정점에서 `dist[v] ≤ opt_k(v)` 입니다. 그리고 `dist[v]` 가 유한한 값이면
> **그 값에 해당하는 경로가 실제로 존재합니다.**

| 문장 | 뜻 | 둘이 함께 주는 것 |
| --- | --- | --- |
| 앞 문장 | 라운드를 `k` 번 실행하면 간선 `k` 개 이하짜리 답까지는 이미 들어와 있다 | `dist` 가 답을 향해 충분히 빨리 내려간다 |
| 뒤 문장 | `dist` 에 적힌 수는 지어낸 것이 아니라 실제 경로의 비용이다 — 그래서 `opt(v)` 이상이다 | `dist` 가 답보다 아래로 내려가지 않는다 |

**라운드에 들어가기 전부터 봅시다.** 그 시점의 `dist` 는 `src` 칸만 0 이고 나머지가 `Infinity` 이니 층 0 과 같아서
앞 문장이 참이고, `Infinity` 는 「경로가 없다」의 표기라 뒤 문장도 참이에요. 그 뒤로 상태를 바꾸는 갈래는 넷입니다.

| 갈래 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 시작값 | `dist[src] = 0`, 나머지 `Infinity` | 층 0 과 같다 | `0` 은 길이 0 인 경로의 비용이다 |
| 값이 없는 정점 넘어가기 | 그 간선을 읽고 지나간다 | `opt_{k−1}(u)` 도 `Infinity` 라 이 간선이 층을 줄이지 않는다 | `dist` 를 안 바꾼다 |
| 완화 | `dist[v]` 를 `dist[u] + w` 로 고친다 | 아래 문단 | `u` 까지의 실재하는 경로에 간선 하나를 이었다 |
| 조기 종료 | 반복을 끝낸다 | 다음 라운드도 같은 `dist` 를 낸다 | `dist` 를 안 바꾼다 |

셋째 줄이 이 논증의 핵심입니다. 간선을 `k` 개 이하로 쓰는 최단 경로 중 간선을 정확히 하나 이상 쓰는 것을 잡고, 그
마지막 간선을 `(u, v, w)` 라고 합시다. 그 앞부분은 `u` 까지 간선 `k−1` 개 이하를 쓰는 경로라서 비용이
`opt_{k−1}(u)` 이상이에요. `k−1` 번째 라운드가 끝난 시점에 `dist[u] ≤ opt_{k−1}(u)` 이고(앞 문장, 귀납 가정),
값은 줄어들기만 하므로 `k` 번째 라운드가 그 간선을 읽는 순간에도 `dist[u]` 는 그 이하입니다. 그 순간 완화가
`dist[v] ≤ dist[u] + w ≤ opt_{k−1}(u) + w` 를 만들고, 앞의 점화식에서 이 값의 최솟값이 `opt_k(v)` 이므로
`dist[v] ≤ opt_k(v)` 가 남아요. 전개 입력에서 확인하면 이렇습니다.

<!--proof:invariantRounds-->

| k | 라운드 k 뒤의 dist | opt_k | opt_k 와의 관계 |
| ---: | --- | --- | --- |
| 0 | [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] | [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] | 크지 않다 |
| 1 | [0, 4, 9, Infinity, Infinity, Infinity, Infinity] | [0, 4, 9, Infinity, Infinity, Infinity, Infinity] | 크지 않다 |
| 2 | [0, 4, 7, 6, Infinity, Infinity, Infinity] | [0, 4, 7, 6, Infinity, Infinity, Infinity] | 크지 않다 |
| 3 | [0, 4, 7, 4, 8, Infinity, Infinity] | [0, 4, 7, 4, 8, Infinity, Infinity] | 크지 않다 |
| 4 | [0, 4, 7, 4, 6, 9, Infinity] | [0, 4, 7, 4, 6, 9, Infinity] | 크지 않다 |
| 5 | [0, 4, 7, 4, 6, 7, Infinity] | [0, 4, 7, 4, 6, 7, Infinity] | 크지 않다 |
| 6 | [0, 4, 7, 4, 6, 7, Infinity] | [0, 4, 7, 4, 6, 7, Infinity] | 크지 않다 |

적힌 순서에서는 모든 라운드가 층과 칸마다 같았습니다. 목록을 뒤집은 순서에서는 라운드 1 이 벌써 층 1 보다 작은 칸을
만든다는 것을 「먼저 알아 둘 개념」의 「라운드 뒤의 dist 와의 차이」가 보였어요 — 앞 문장을 「같다」가 아니라
「크지 않다」로 세운 까닭입니다. **엣지 케이스를 함께 봅시다.** 경계에 있는 입력 여섯에 정본을 실행했어요.

<!--proof:invariantEdges-->

| 경계 입력 | dist | hasNegativeCycle | 라운드 | 간선 읽기 |
| --- | --- | --- | ---: | ---: |
| 정점이 하나이고 간선이 없다 | [0] | false | 1 | 0 |
| 정점이 여럿인데 간선이 없다 | [Infinity, 0, Infinity] | false | 1 | 0 |
| 도달할 수 없는 정점이 있다 | [0, 5, Infinity] | false | 2 | 2 |
| 가중치가 0 이다 | [0, 0, 0] | false | 2 | 4 |
| 가중치 합이 0 인 순환 | [0, 2, 1] | false | 2 | 6 |
| 시작 정점의 음수 자기 간선 | [-2, -1] | true | 2 | 4 |

간선이 없으면 첫 라운드가 아무것도 못 읽고 고친 칸 없이 끝납니다. 도달할 수 없는 정점은 `Infinity` 로 남고,
가중치 0 간선은 같은 값을 넘겨줄 뿐 `nd < dist[v]` 가 거짓이라 라운드를 늘리지 않아요. 합이 0 인 순환도 한 번 더
지나 봐야 같은 값이라 고칠 것을 만들지 않습니다. 시작 정점의 음수 자기 간선은 라운드마다 `dist[0]` 을 줄여 정점
수 `V = 2` 번째 라운드에서도 고치므로 `true` 예요.

**이제 그 줄을 망가뜨려 봅시다.** 앞 문장을 떠받치는 자리는 완화 조건 `if (nd < dist[v])` 한 줄이에요. 「더 작을
때 고치는 것이나 더 클 때 고치는 것이나 어차피 값을 고치는 것 아닌가」라는 생각으로 그 부등호 방향만 뒤집어
봅니다.

```ts
for (const [u, v, w] of edges) {
  if (dist[u] === Number.POSITIVE_INFINITY) continue;
  const nd = (dist[u] as number) + w;
  if (nd > (dist[v] as number)) {   // 부등호를 뒤집었다
    dist[v] = nd;
    changed = true;
  }
}
```

<!--proof:mutantDirection-->

```text
입력                        정본                                  부등호를 뒤집은 판
전개 입력                   [0, 4, 7, 4, 6, 7, Infinity] · false  [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity] · false
음수 사이클 0->1->2->0      [-3, -1, -2] · true                   [0, Infinity, Infinity] · false
도달할 수 없는 음수 사이클  [0, Infinity, Infinity] · false       [0, Infinity, Infinity] · false
```

`dist` 가 시작값에서 한 칸도 안 움직입니다. `Infinity` 보다 큰 유한한 값이 없어서 조건이 한 번도 참이 되지 못하고,
그래서 첫 라운드가 `changed = false` 로 끝나 조기 종료 갈래에서 돌려줘요. 음수 사이클이 있는 입력에서도 판정이
`false` 로 뒤집힙니다.

<!--proof:mutantDirectionWhere-->

```text
전개 입력의 첫 라운드
  opt_1                       [0, 4, 9, Infinity, Infinity, Infinity, Infinity]
  뒤집은 판이 돌려준 dist     [0, Infinity, Infinity, Infinity, Infinity, Infinity, Infinity]
  dist 가 opt_1 보다 큰 정점  1 · 2
```

간선 하나짜리 경로 `0 → 1` 이 있는데 `dist[1]` 이 `Infinity` 이니 앞 문장이 첫 라운드에서 거짓이 됩니다. 뒤 문장은
그대로 참이에요 — 안 적는 것은 틀리게 적는 것이 아니기 때문입니다. 앞 문장이 깨지면 「`V − 1` 라운드 뒤의 `dist` 가
답」이라는 결론도 함께 사라져요.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 둘입니다. 거리 배열을 만드는 것과, 라운드마다 간선 목록 전체를 읽는 것이에요. 이웃 목록도
큐도 만들지 않으니 앞뒤로 붙는 전처리가 없습니다. 전개의 걸음마다 간선 읽기를 세면 이렇습니다.

<!--proof:perfCount-->

| 걸음 | 라운드 | 간선 읽기 | 그중 ③ | 여기까지 누적 |
| --- | ---: | ---: | ---: | ---: |
| T2 | 1 | 8 | 6 | 8 |
| T3 | 2 | 8 | 4 | 16 |
| T4 | 3 | 8 | 3 | 24 |
| T5 | 4 | 8 | 1 | 32 |
| T6 | 5 | 8 | 1 | 40 |
| T7 | 6 | 8 | 1 | 48 |

라운드 6 번 × 간선 8 개 = 48 번이고, 그중 ③ 이 16 번, ④ 가 값을 고친 것이 9 번입니다.

<!--/proof-->

라운드 하나가 읽는 간선 수가 8 로 고정이라는 것을 봐 주세요. **몇 개를 고쳤는지와 상관없이 목록 전체를 읽습니다.**
T7 은 한 칸도 안 고쳤는데도 8 개를 읽었고, 그 8 번이 「고칠 것이 없다」를 확인하는 값이에요. 이것을 임의의 입력으로
넓히면 총식이 됩니다. 라운드 수를 `R` 이라고 적어요.

| 항 | 횟수 | 근거 |
| --- | --- | --- |
| 거리 배열 만들기 | `V` | 정점마다 칸 하나 |
| 라운드 수 `R` | `V` 이하 | `⑤` 로 더 일찍 끝날 수 있고, `⑥` 이 `V` 번째에서 끝낸다 |
| 라운드 하나의 간선 읽기 | `E` | 간선 목록 전체를 읽는다 |
| 합 | `V + R × E` | `R ≤ V` 이므로 `V + V × E` 이하 |

두 규모에 넣으면 이렇습니다.

<!--proof:perfTotal-->

```text
  V = 7 · E = 8          R = 6    7 + 6 x 8 = 55
  V = 500 · E = 249,500  R ≤ 500  500 + 500 x 249,500 = 124,750,500 이하
```

**여기서 센 것은 간선 읽기 전부와 거리 배열의 칸입니다.** 배열 칸을 읽고 쓰는 횟수와 반복 변수를 올리는 횟수는
세지 않았어요 — 둘 다 위 값에 비례하므로 총식의 차수가 그대로입니다. 메모리는 같은 기준으로 거리 배열 `V` 칸과
`changed` 하나라 `Θ(V)` 이고, 입력인 간선 목록은 적힌 그대로 읽기만 합니다.

#### 케이스별 비용과 그 경계

어떤 입력인가를 말하는 **케이스**와 어떤 종류의 값인가를 말하는 **경계**는 서로 다른 갈래입니다. 한 갈래의 이름을
다른 갈래에 붙이면 두 정보가 함께 사라져요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 라운드가 한 칸도 못 고친다) | `O(V·E)` | `Θ(V + E)` — 배열을 만들고 목록을 한 번 읽는다 |
| **평균적인 경우** (입력 분포를 정의하지 않는다) | `O(V·E)` | 정의하지 않는다 |
| **최악의 경우** (라운드가 `V` 번 실행된다) | `O(V·E)` | `Θ(V·E)` — 실제로 도달한다 |

평균을 정의하지 않는 이유는 **라운드 수를 정하는 것이 간선 목록의 순서**이기 때문입니다. 정점 수와 간선 수를 고정해도
순서에 따라 라운드가 갈리고, 그 순서의 분포를 과제가 주지 않아요. 「아이디어를 떠올리는 과정」의 순서 40,320 가지
실측이 같은 그래프에서 그 갈림이 2 라운드부터 6 라운드까지라는 것을 보였습니다.

```text
상한과 타이트한 값을 가르는 자리
  O(V·E)      이 절차의 간선 읽기가 그보다 크지 않다는 것만 말한다   상한이다
  Theta(V+E)  거리 배열을 만들고 목록을 한 번은 읽는다는 것          타이트한 값이다

기댓값이 끼어들 자리가 없다
  간선을 고르는 순서   목록에 적힌 그대로다        난수를 안 쓴다
  정점을 찾는 방법     번호로 배열 칸에 바로 간다  해시 충돌이라는 개념이 없다
  라운드를 끝내는 조건 한 칸도 못 고쳤는가         분포를 가정할 필요가 없다
```

**총식을 한 번은 빠짐없이 적습니다.** 이 절차에는 앞뒤로 붙는 전처리가 하나도 없어요 — 이웃 목록도, 정렬도, 좌표
압축도 하지 않습니다. `Θ(V)` 시간에 거리 배열을 만들고 그 뒤에 `O(V·E)` 짜리 라운드가 붙어 `O(V + V·E) = O(V·E)`
로 끝납니다. **위의 값은 전부 최악 보장입니다.** 기댓값이 아니라 상한이라는 뜻이고, 어떤 그래프와 어떤 간선 순서를
넣어도 그 값을 넘지 않아요.

#### 최악을 만드는 입력

연산 수를 최대로 만드는 방법이 축마다 다릅니다. 라운드 수는 그래프의 모양과 **간선 목록의 순서**가 함께 정하고,
간선 읽기는 그 라운드 수에 **간선 수**를 곱한 값이에요. 정점 64 개로 모양 다섯을 실제로 만들어 재 봤습니다.

<!--proof:worstShape-->

| 모양 (V = 64) | 간선 E | 라운드 | 간선 읽기 | 음수 사이클 |
| --- | ---: | ---: | ---: | --- |
| 사슬, 오름차순으로 적음 | 63 | 2 | 126 | false |
| 사슬, 내림차순으로 적음 | 63 | 64 | 4,032 | false |
| 완전 그래프 | 4,032 | 2 | 8,064 | false |
| 내림차순 사슬 + 나머지 간선 | 4,032 | 64 | 258,048 | false |
| 음수 사이클이 있는 사슬 | 64 | 64 | 4,096 | true |

라운드 수는 가장 많을 때 V = 64 번이고, 그때 간선 읽기는 V × E 입니다.

<!--/proof-->

**「간선이 많으면 라운드도 늘어난다」는 이 절차에서 성립하지 않습니다.** 완전 그래프는 간선이 4,032 개인데 라운드가
2 뿐이에요 — 정점 0 에서 나가는 간선이 목록의 맨 앞에 있어 첫 라운드가 전부를 정하고 둘째 라운드는 고칠 것을 하나도
못 찾기 때문입니다. 반대로 사슬은 간선이 63 개뿐인데 순서를 뒤집으면 라운드가 64 가 돼요. 축마다 최악을 모으면
이렇습니다.

<!--proof:worstAxes-->

| 최악으로 만들 축 | 그 축을 최대로 만드는 입력 (V = 64) | 그 축의 값 | 다른 축의 값 |
| --- | --- | --- | --- |
| 라운드 수 | 내림차순 사슬 (E = 63) | 라운드 64 | 간선 읽기 4,032 |
| 간선 읽기 | 내림차순 사슬 + 나머지 간선 (E = 4,032) | 간선 읽기 258,048 | 라운드 64 |
| 거리 값의 크기 | 가중치 10^9 짜리 오름차순 사슬 | dist[63] = 63,000,000,000 | 라운드 2 |

세 입력이 서로 다르고, 한 입력이 세 축을 함께 최대로 만들지 않습니다.

<!--/proof-->

라운드 수만 최대로 만든 내림차순 사슬은 간선이 63 개뿐이라 간선 읽기가 4,032 에 그치고, 거기에 나머지 간선을 전부
채우면 같은 라운드 64 에서 간선 읽기가 258,048 로 64 배가 돼요. 채운 간선의 가중치를 `10^9` 로 두어 한 번도 값을
못 고치게 했기 때문에 라운드 수는 사슬이 정합니다. 같은 모양을 규모의 상한에서 실행하면 이렇습니다.

<!--proof:worstLimit-->

| 최악으로 만들 축 | 규모의 상한에서의 입력 | 값 |
| --- | --- | --- |
| 라운드 수 | 정점 500 개 사슬을 내림차순으로 적는다 | 라운드 500 |
| 간선 읽기 | 그 사슬에 나머지 간선을 전부 채운다 (E = 249,500) | 124,750,000 번 |
| 거리 값의 크기 | 가중치 10^9 짜리 오름차순 사슬 | dist[499] = 499,000,000,000 |

셋 다 실행한 값입니다. 둘째 줄의 124,750,000 번은 V × E = 500 × 249,500 과 같습니다.

<!--/proof-->

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 간선 목록을 **라운드마다 적힌 차례대로 읽으며 완화**하고, 한
라운드가 한 칸도 못 고치면 거기서 끝내며, `V` 번째 라운드까지 계속 고쳐지면 음수 사이클로 판정합니다. 라운드 상한이
`V − 1` 인 근거는 최단 경로가 지나는 간선이 그만큼이라는 것이에요.

```text
dist 를 Infinity 로, dist[src] = 0 → 라운드: 간선 목록을 차례대로 읽으며 완화 → 고친 칸이 없으면 false 로 끝
                                                                            └ V 번째 라운드도 고치면 true 로 끝
```

먼저 답이 붙는 문제 하나입니다. 전개의 T3 은 `dist[3]` 을 6 으로 적었는데 T4 에서 그것이 4 로 바뀌었어요. 「한 번
적힌 값이 다시 바뀐다」가 이 절차에서 왜 문제가 되지 않을까요?

<!--proof:selfcheckT3T4-->

```text
T3 의 dist             [0, 4, 7, 6, Infinity, Infinity, Infinity]
T4 의 dist             [0, 4, 7, 4, 8, Infinity, Infinity]
값이 있다가 바뀐 자리  dist[3] 이 6 에서 4 로
```

<!--check:whyRewriteIsFine-->
`dist[3]` 이 **줄어드는 방향으로만** 바뀌기 때문입니다. 불변식의 뒤 문장이 「유한한 값이면 그 값에 해당하는 경로가
실제로 있다」이므로 6 도 4 도 실재하는 경로의 비용이에요. 「먼저 알아 둘 개념」의 「칸 하나를 읽는 법」 표에서 6 은
간선 두 개짜리 `0→2→3` 의 비용이고, 4 는 간선 세 개짜리 `0→1→2→3` 의 비용입니다. 라운드가 하나 늘 때마다 간선을
하나 더 쓰는 경로가 후보에 들어오므로 값이 바뀌는 것이 정상이고, 안 바뀌는 것이 끝났다는 신호예요.

| 라운드가 늘 때 | 값의 방향 | 뜻 |
| --- | --- | --- |
| 값이 줄어든다 | 아래로만 | 간선을 더 쓰는 경로가 더 작은 비용으로 들어왔다 |
| 값이 그대로다 | 없음 | 고정점 — 3단계가 멈추는 자리 |
| 값이 늘어난다 | 위로 | 불변식이 깨졌다 — 부등호를 뒤집은 판이 그 자리였다 |
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「경쟁 설계와의 대조」, 「수행으로 알아보는 알고리즘」의 라운드를
`V−1` 번만 실행하는 짚고 가기, 「최악을 만드는 입력」을 다시 보세요.

- 잎이 66 개일 때 두 설계의 기본 연산이 1,666 으로 같았습니다. 잎을 하나 더할 때 SPFA 가 허브를 몇 번 꺼내는지가
  경계를 정했는데, 허브까지의 가중치 `2(16 − i)` 를 `16 − i` 로 바꾸면 허브를 꺼내는 횟수가 어떻게 되는지 예측하고
  경계가 어느 쪽으로 옮겨질지 따져 보세요.
- 라운드 상한을 `V − 1` 로 줄이면 전개 입력의 거리는 그대로인데 음수 사이클 판정이 사라졌어요. 상한을 `V − 2` 로
  줄이면 전개 입력의 거리도 틀릴까요? T6 과 T7 에서 고친 칸 수를 보고 답하고, 거리가 처음 틀리는 간선 순서를
  하나 만들어 보세요.
- 「내림차순 사슬 + 나머지 간선」이 라운드 64 를 유지한 것은 채운 간선의 가중치가 `10^9` 이라 한 번도 값을 못
  고쳤기 때문입니다. 채운 간선의 가중치를 1 로 바꾸면 라운드 수가 어떻게 되는지 예측하고, 그 예측이 맞는지 세어
  보세요.

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### Bellman-Ford 최단 경로

풀 파일: [`bellmanFord.ts`](./bellmanFord.ts) · 테스트: [`bellmanFord.test.ts`](./bellmanFord.test.ts) · 실행: `bun test src/algorithms/shortest-path/bellmanFord/bellmanFord.test.ts`

#### 한 줄 요약

> 함수는 음수 간선을 포함할 수 있는 그래프와 시작 정점을 받아 각 정점까지의 최단 거리 배열과 음수 사이클 존재 여부를 반환한다.

#### 스토리

금융 분석가 민호는 여러 나라의 환율 데이터로 환전 경로를 계산하는 시스템을 만들고 있다. 일부 환전 경로는 수수료가 붙어 비용이 추가되지만, 특정 프로모션 경로는 오히려 마이너스 비용, 즉 이득이 발생한다.

문제는 어떤 환전 경로를 순환하면 돌 때마다 계속 이득이 생기는 "무한 차익거래" 경로가 생길 수 있다는 점이다. 이런 경우 최단 비용이 무한히 작아지므로 최단 경로 자체가 의미 없어진다.

민호는 두 가지를 동시에 알아야 한다. 첫째, 그런 무한 차익거래 경로가 존재하는지 여부. 둘째, 그런 경로가 없다면 시작점에서 각 환전처까지의 실제 최솟값. 두 정보를 함께 반환하는 함수가 필요하다.

#### 함수 인터페이스

```ts
export function bellmanFord(
  n: number,
  edges: [number, number, number][],
  src: number,
): { dist: number[]; hasNegativeCycle: boolean };
```

- `n` — 정점 수. 정점 번호는 $0$부터 $n - 1$.
- `edges` — 방향 간선 목록. 각 원소는 $[u, v, w]$ 형태이며 가중치 $w$ (음수 허용)인 방향 간선 $u \to v$.
- `src` — 시작 정점 번호.
- 반환 — `{ dist, hasNegativeCycle }` 객체.
  - `dist[v]` — $\text{src} \to v$의 최단 거리. 도달할 수 없으면 `Infinity`.
  - `hasNegativeCycle` — $\text{src}$에서 도달 가능한 음수 사이클이 존재하면 `true`, 그렇지 않으면 `false`. `src`에서 도달할 수 없는 음수 사이클은 `false`로 판정한다.

#### 제약 조건

- $1 \leq V \leq 500$ (정점 수)
- $0 \leq E \leq V \cdot (V - 1)$ (간선 수)
- $-10^9 \leq w(u, v) \leq 10^9$ (가중치; 음수 허용)
- $0 \leq \text{src} < V$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

음수 가중치를 포함할 수 있는 방향 그래프 $G = (V, E)$가 주어진다. 시작 정점 $\text{src}$에서 모든 정점 $v$까지의 최단 거리 $d(\text{src}, v)$를 구하라.

최단 거리는 경로 위 간선 가중치의 합이 최소인 경로 비용으로 정의된다. 음수 사이클이 없을 때만 최단 거리가 유한하게 정의된다.

- $\text{src}$에서 도달 가능한 음수 사이클이 있으면 `hasNegativeCycle`을 `true`로 반환한다.
- `src` 자신까지의 거리는 $0$이다.
- 도달할 수 없는 정점의 거리는 `Infinity`다.
- 음수 셀프 루프(자기 자신을 향하는 음수 간선)도 음수 사이클로 처리한다.

#### 예시

```ts
// 음수 간선이 있지만 음수 사이클은 없음
const e1: [number, number, number][] = [
  [0, 1, 4],
  [0, 2, 5],
  [1, 2, -3],
  [2, 3, 4],
];
bellmanFord(4, e1, 0);
// { dist: [0, 4, 1, 5], hasNegativeCycle: false }
// — 0→2 최단: 0→1→2 = 1 (직접 간선 5보다 짧음)

// src에서 도달 가능한 음수 사이클
const e2: [number, number, number][] = [
  [0, 1, 1],
  [1, 2, -1],
  [2, 0, -1],
];
bellmanFord(3, e2, 0).hasNegativeCycle; // true — 0→1→2→0 합계 = -1

// src에서 도달할 수 없는 음수 사이클은 false
const e3: [number, number, number][] = [
  [1, 2, 1],
  [2, 1, -5],
];
bellmanFord(3, e3, 0).hasNegativeCycle; // false — 1↔2 사이클은 0에서 도달 불가

// 간선이 없는 그래프
bellmanFord(3, [], 1);
// { dist: [Infinity, 0, Infinity], hasNegativeCycle: false }
```
