# rotatingCalipersDiameter — 껍질의 변을 차례로 따라갈 때 그 변에서 가장 먼 꼭짓점이 앞으로만 가는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 점 쌍을 전부 재는
방법에서 출발해 회전하는 캘리퍼스에 이르고, 회전하는 캘리퍼스를 단계마다 값으로 푼 뒤, 실제로 동작하는 코드를
한 조각씩 만듭니다.

### 전체 컨셉

평면 위의 점 여러 개를 받아 **가장 멀리 떨어진 두 점 사이 거리의 제곱**을 돌려줍니다. 이 값을 점 집합의
**지름**(의 제곱)이라고 부릅니다. 거리 대신 제곱을 다루는 이유는 하나예요. 좌표가 정수면 제곱 거리도 정수라서
비교에 오차가 끼지 않고, 제곱근은 크기 순서를 바꾸지 않으니 가장 먼 쌍을 고르는 데도 지장이 없습니다.

가장 먼 두 점은 언제나 점 전부를 감싸는 가장 작은 볼록 다각형, 곧 **볼록 껍질**의 꼭짓점입니다. 그래서 먼저
껍질을 세우고, 그 껍질을 평행한 두 직선 사이에 끼웁니다. 껍질 전체를 한쪽에 두고 껍질과 만나는 직선을
지지선이라고 부르고, 평행한 두 지지선이 동시에 지나는 두 꼭짓점을 **대척점 쌍**이라고 부릅니다. 지름의 두
끝은 반드시 대척점 쌍이에요. 이 글이 끝까지 쓰는 점 여덟 개와 그 껍질, 그리고 지름인 대척점 쌍을 그렸습니다.
점선 테의 두 점은 껍질 안쪽 점이고, 굵은 테의 두 꼭짓점이 지름의 두 끝입니다.

<!--fig:concept-calipers-->
![전개 입력 여덟 점의 볼록 껍질 — 평행한 두 지지선과 지름인 대척점 쌍](./figs/concept-calipers.svg)

꼭짓점에는 가장 왼쪽 아래 점부터 반시계 방향으로 `h0` · `h1` · … 번호를 붙였어요. 한 지지선은 껍질의 변
`h2→h3` 에 붙어 있고, 반대편 지지선은 그 변과 평행하게 `h0` 을 지납니다. 두 지지선을 함께 기울여 가면 지지선에 놓이는 꼭짓점이 차례로 바뀌는데, 그렇게 대척점 쌍을 차례로 재는 절차를 **회전하는
캘리퍼스**(rotating calipers)라고 부릅니다. 캘리퍼스는 물체를 두 평행한 턱 사이에 물려 폭을 재는 도구의
이름이고, 이 글은 그 이름을 절차의 이름으로만 씁니다. 대척점 쌍이 후보를 얼마나 줄이는지 몇 입력에서 세었어요.

<!--proof:concept-hull-->

| 입력 | 점 n | 껍질 꼭짓점 m | 점 쌍 | 껍질 꼭짓점 쌍 | 대척점 쌍 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 8 | 6 | 28 | 15 | 7 |
| 정사각형 네 점 | 4 | 4 | 6 | 6 | 6 |
| 원 위의 점 16 | 16 | 16 | 120 | 120 | 24 |
| 원 위의 점 64 | 64 | 64 | 2,016 | 2,016 | 96 |

전개 입력의 답은 제곱 거리 73 이고, 모든 쌍을 잰 답 73 과 같습니다.

<!--/proof-->

껍질이 후보를 먼저 줄이고, 대척점 쌍이 껍질 꼭짓점 쌍을 다시 줄입니다. 껍질 꼭짓점이 `m` 개면 대척점 쌍은
많아야 `2m` 개예요. 변 하나마다 그 변에서 **가장 먼 꼭짓점**을 찾고 변의 두 끝과 짝지으면 대척점 쌍 둘이
나오는데, 변을 반시계 방향으로 한 칸씩 옮길 때 그 가장 먼 꼭짓점도 반시계 방향으로만 옮겨 갑니다. 그래서 가장
먼 꼭짓점을 가리키는 첨자 하나를 변을 따라 앞으로만 보내면 대척점 쌍이 전부 나오고, 껍질을 세운 뒤의 일은 `m`
에 비례합니다. 점 `n` 개에 드는 비용은 껍질을 세우는 정렬이 정해서 결과만 적으면 `O(n log n)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **볼록 껍질.** 점 전부를 감싸는 가장 작은 볼록 다각형입니다. 이 글은 껍질을 **반시계 방향**으로 늘어놓은
  꼭짓점 배열로 받고, 변 위의 공선 중간 점은 꼭짓점이 아니라고 봐요. 껍질을 세우는 절차는
  [`convexHull` 가이드](../convexHull/convexHull-guide.md)가 단조 사슬 둘로 다루고, 이 글은 그 코드를 그대로
  씁니다.
- **방향 판정(세 점의 꺾임).** 점 `o` 에서 `a` 로 간 다음 `b` 로 갈 때 왼쪽으로 꺾이면 양수, 오른쪽이면 음수, 한
  직선 위면 0 입니다. 같은 판정을 선분 교차에 쓴 편이
  [`segmentsIntersect` 가이드](../segmentsIntersect/segmentsIntersect-guide.md)이고, 다각형 안팎 판정에 쓴 편이
  [`pointInPolygon` 가이드](../pointInPolygon/pointInPolygon-guide.md)예요.
- **외적과 삼각형 넓이.** 벡터 $u$ 와 $v$ 의 외적 $u_x v_y - u_y v_x$ 는 두 벡터가 만드는 평행사변형의 부호 있는
  넓이입니다. 그 절반이 삼각형의 넓이이고, 밑변이 같은 두 삼각형은 넓이가 큰 쪽의 꼭대기가 밑변에서 더 멉니다.
  다각형 넓이를 이 외적으로 모으는 편이 [`polygonArea` 가이드](../polygonArea/polygonArea-guide.md)입니다.
- **배정밀도 부동소수점 수가 정수를 오차 없이 담는 범위가 정해져 있다는 것.** 자바스크립트의 `number` 는
  `Number.MAX_SAFE_INTEGER` 보다 큰 정수를 반올림해서 담습니다. 좌표가 크면 제곱 거리가 그 범위를 넘으므로 이
  글은 판정과 답을 `bigint`(자릿수에 상한이 없는 정수 타입)로 냅니다. 같은 이야기를 방향 판정에서 다룬 편이
  [`convexHull` 가이드](../convexHull/convexHull-guide.md)입니다.

### 아이디어를 떠올리는 과정 — 모든 쌍 재기에서 회전하는 캘리퍼스까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 점 배열을 받아 가장 먼 두 점 사이
거리의 제곱을 돌려줍니다.

```ts
type Point = [number, number];

function rotatingCalipersDiameter(points: Point[]): number;
```

- 입력: 평면 위의 점 배열 하나. 각 원소가 `[x, y]` 이고 순서에 아무 약속이 없습니다. 같은 좌표가 여러 번 들어올
  수 있어요.
- 출력: 가장 먼 두 점 사이 거리의 **제곱**. 0 이상의 수이고, 점이 하나뿐이거나 모두 같은 좌표면 0 입니다.
- 규모: 이 글은 점 `n` 이 10 만 개 이하이고 좌표가 절댓값 `10^9` 이하의 정수인 과제로 잽니다. 점 10 만 개는
  흔한 채점 환경의 예산 1 초(단순 연산 1 억 번)에 대어 볼 때 점 수의 제곱이 드는 방법과 `n log n` 이 드는 방법이
  뚜렷이 갈리는 규모예요. 좌표 상한을 `10^9` 로 두는 것은 제곱 거리가 배정밀도가 정수를 오차 없이 담는 범위를
  넘게 해서, 값의 크기가 답과 판정에 끼치는 영향까지 함께 보려는 것입니다.

비용은 **기본 연산**의 횟수입니다. 좌표 비교(정렬하며 두 점의 좌표를 비교한 횟수와 이웃한 점이 같은 좌표인지
확인한 횟수) · 방향 판정 · 거리 계산(두 점의 제곱 거리를 만들어 지금까지의 최댓값과 비교한 일)을 각각 1 로 센
합이고, 정렬은 합치기 정렬로 셉니다. 메모리는 입력 밖에 **추가로 잡는 칸**의 수예요. 이 글의 비용은 전부 이
두 기준으로 잰 것이에요. 이 글이 쓰는 기호는 열이고, 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `n` | 입력 점의 개수 | `n ≤ 100,000` |
| `C` | 좌표의 절댓값 상한 | `10^9` |
| `u` | 그중 서로 다른 좌표의 개수 | `u ≤ n` |
| `m` | 볼록 껍질 꼭짓점의 개수. 코드에서는 `k` 다 | `m ≤ u` |
| `h_i` | 껍질의 `i` 번째 꼭짓점. 반시계 방향으로 번호가 붙는다. 코드에서는 `hull[i]` 다 | `i` 는 0 부터 `m − 1` 까지 |
| `i` | 지금 보는 변의 앞 끝 첨자. 변은 `h_i → h_{i+1}` 이다 | 한 칸씩 는다 |
| `a` · `b` · `f` | 지금 보는 변의 앞 끝 · 뒤 끝과 그 변에서 가장 먼 꼭짓점 | 걸음마다 다른 점을 가리킨다 |
| `far` | `f` 의 첨자 | 반복 바깥에 두고 이어 쓴다 |
| `best` | 지금까지 잰 가장 큰 제곱 거리 | 마지막 값이 답이다 |
| `d²(p,q)` | 두 점 사이 거리의 제곱. 코드에서는 `squared(p, q)` 다 | 좌표가 정수면 정수다 |

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 점 쌍을 하나도 거르지 않고 전부 재서 가장 큰 제곱
거리를 고르면 언제나 맞는 답이 나와요.

```ts
function allPairs(points: Point[]): bigint {
  let best = 0n;
  for (let i = 0; i < points.length; i++) {
    for (let j = i + 1; j < points.length; j++) {
      const d = squared(points[i], points[j]);
      if (d > best) best = d;
    }
  }
  return best;
}
```

쌍마다 거리 계산을 한 번 하므로 기본 연산은 쌍의 수 `n(n−1)/2` 입니다. 과제의 규모를 넣으면 이렇습니다.

<!--proof:origin-brute-->

| 점 n | 기본 연산 n(n−1)/2 | 시간(초당 1 억 번) |
| ---: | ---: | ---: |
| 8 | 28 | 0.000 초 |
| 1,000 | 499,500 | 0.005 초 |
| 10,000 | 49,995,000 | 0.500 초 |
| 100,000 | 4,999,950,000 | 50.0 초 |

전개 입력 여덟 점을 실제로 모두 재면 거리 계산이 28 번이고, 가장 큰 제곱 거리는 73 입니다. 점이 100,000 개면 4,999,950,000 번이라 예산 1 초의 50 배입니다.

<!--/proof-->

점이 10 만 개면 예산의 수십 배라 쓸 수 없습니다. 재지 않아도 되는 쌍을 찾아야 하는데, 전개 입력의 스물여덟
쌍을 두 부류로 나눠 보면 한 부류가 통째로 쓸모없어요.

<!--proof:origin-kinds-->

| 쌍의 종류 | 쌍 수 | 가장 큰 제곱 거리 |
| --- | ---: | ---: |
| 두 점 다 볼록 껍질의 꼭짓점 | 15 | 73 |
| 껍질 안쪽 점이 낀 쌍 | 13 | 34 |

껍질 안쪽 점은 (3,3) 과 (5,2) 입니다. 안쪽 점이 낀 쌍의 가장 큰 값 34 는 답 73 보다 작습니다.

<!--/proof-->

**껍질 안쪽 점이 낀 쌍은 답이 될 수 없습니다.** 까닭은 이렇습니다. 점 `q` 를 하나 고정하면 점 `p` 에서 `q`
까지의 거리 $\lVert p - q \rVert$ 는 $p$ 에 대해 볼록한 함수입니다 — 선분 위의 점 $p = t\,a + (1-t)\,b$
($0 \le t \le 1$)에 대해 삼각 부등식으로 $\lVert p - q\rVert \le t\lVert a - q\rVert + (1-t)\lVert b - q\rVert$ 이고,
오른쪽은 두 끝의 거리 가운데 큰 쪽을 넘지 못해요. 껍질 안쪽 점 `p` 를 지나는 직선을 아무렇게나 그으면 껍질의
경계와 두 점에서 만나고, `p` 는 그 두 점 사이에 있으니 둘 중 하나보다 `q` 에서 멀 수 없습니다. 경계 위의 그 점은
다시 껍질의 한 변 위에 있으므로 같은 논리로 그 변의 두 꼭짓점 가운데 하나보다 멀 수 없고요. 그러니 어떤 `q` 에
대해서도 `p` 보다 먼 껍질 꼭짓점이 있고, 안쪽 점을 지워도 답이 바뀌지 않습니다.

그러면 껍질을 세우고 껍질 꼭짓점 쌍만 재 봅시다. 흩어진 점은 한 변이 `10^9` 인 정사각형 안에 고정한 씨앗의
난수로 뿌린 것이고, 원 위의 점은 반지름이 `10^9` 인 원에서 각을 등분해 반올림한 것이에요.

<!--proof:origin-hull-pairs-->

| 입력 | 껍질 꼭짓점 m | 껍질을 세우는 기본 연산 | 껍질 꼭짓점 쌍 | 기본 연산 합 | 시간(초당 1 억 번) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 37 | 15 | 52 | 0.000 초 |
| 흩어진 점 100,000 개 | 30 | 2,036,560 | 435 | 2,036,995 | 0.020 초 |
| 원 위의 점 100,000 개 | 100,000 | 1,284,456 | 4,999,950,000 | 5,001,234,456 | 50.0 초 |

원 위의 점은 100,000 개가 전부 껍질 꼭짓점이라, 쌍만 세어도 모든 쌍을 재는 방법과 같은 4,999,950,000 번입니다.

<!--/proof-->

흩어진 점에서는 껍질 꼭짓점이 몇십 개라 껍질을 세운 뒤의 일이 거의 없었는데, 원 위의 점에서는 모든 점이 껍질
꼭짓점이라 모든 쌍을 재는 방법과 다를 바가 없습니다. **비용이 점 수가 아니라 껍질 꼭짓점 수 `m` 에 달려 있고, `m` 은 `n` 만큼
커질 수 있어요.** 껍질 꼭짓점 쌍도 전부 볼 수는 없다는 뜻입니다.

껍질 꼭짓점 쌍 가운데 무엇만 보면 될까요? 지름의 두 끝을 `p` · `q` 라 하면, `p` 를 지나 선분 `pq` 에 수직인
직선과 `q` 를 지나는 같은 방향의 직선 사이에 점이 전부 들어 있습니다(밖에 점이 있으면 그 점이 `p` 나 `q` 와 더 먼
쌍을 만들어요). 두 직선이 평행한 지지선이라는 뜻이고, 그 방향을 조금씩 기울이면 지지선이 껍질의 어느 변과
나란해지는 순간이 옵니다. 그 순간 한 지지선은 변 하나를 품고 반대편 지지선은 그 변에서 **가장 먼 꼭짓점**을
지나요. 그러니 변마다 가장 먼 꼭짓점을 찾아 변의 두 끝과 짝지으면 됩니다. 변에서 먼 정도는 그 변을 밑변으로 삼은
삼각형의 넓이로 잽니다. 전개 입력의 껍질에서 변마다 꼭짓점 전부의 넓이를 적으면 이렇습니다.

<!--proof:origin-far-->

| 변 | h0 | h1 | h2 | h3 | h4 | h5 | 넓이가 가장 큰 꼭짓점 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| h0→h1 | 0 | 0 | 18 | 36 | 42 | 24 | h4 |
| h1→h2 | 18 | 0 | 0 | 12 | 26 | 26 | h4 · h5 |
| h2→h3 | 30 | 12 | 0 | 0 | 10 | 22 | h0 |
| h3→h4 | 30 | 24 | 10 | 0 | 0 | 14 | h0 |
| h4→h5 | 8 | 26 | 26 | 14 | 0 | 0 | h1 · h2 |
| h5→h0 | 0 | 24 | 32 | 24 | 8 | 0 | h2 |

칸의 값은 그 변을 밑변으로, 그 꼭짓점을 꼭대기로 삼은 삼각형 넓이의 2 배입니다. 넓이가 가장 큰 꼭짓점이 둘인 변은 h1→h2 와 h4→h5 입니다.

<!--/proof-->

변마다 넓이가 가장 큰 꼭짓점을 처음부터 찾는 판을 먼저 세어 봅시다. 변 하나를 볼 때마다 그 변의 다음
꼭짓점에서 출발해, 다음 꼭짓점의 넓이가 더 큰 동안 한 칸씩 전진하는 판이에요. 옆 칸은 뒤에서 세울 판 — 가장 먼
꼭짓점을 가리키는 첨자 `far` 를 변마다 되돌리지 않고 이어 쓰는 판 — 의 값입니다.

<!--proof:origin-reset-->

| 입력 | 껍질 꼭짓점 m | 변마다 처음부터 찾을 때의 방향 판정 | far 를 이어 쓸 때의 방향 판정 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 6 | 20 | 13 |
| 원 위의 점 4,096 개 | 4,096 | 8,388,608 | 10,238 |
| 원 위의 점 100,000 개 | 100,000 | 5,000,000,000 | 249,998 |

처음부터 찾는 판의 100,000 개 값은 이어 쓰는 판이 낸 변마다의 far 에서 센 것이고, 4,096 개까지는 처음부터 찾는 판을 실제로 실행해 같은 값을 확인했습니다. 그 판의 기본 연산은 5,001,484,456 번이라 50.0 초 입니다.

<!--/proof-->

처음부터 찾는 판은 변 하나마다 껍질을 반 바퀴쯤 읽으므로 원 위의 점에서 `m` 의 제곱에 비례해 늘었습니다. 이어
쓰는 판이 맞는 답을 내는 근거는 위 넓이 표의 마지막 열을 가로로 늘어놓으면 나와요.

<!--proof:origin-forward-->

| 변 | h0→h1 | h1→h2 | h2→h3 | h3→h4 | h4→h5 | h5→h0 |
| --- | --- | --- | --- | --- | --- | --- |
| 넓이가 가장 큰 꼭짓점 | h4 | h4 · h5 | h0 | h0 | h1 · h2 | h2 |

변이 h0→h1 에서 h5→h0 까지 한 칸씩 갈 때, 넓이가 가장 큰 꼭짓점은 h5 다음을 h0 으로 이어 세면 한 번도 뒤로 가지 않습니다.

<!--/proof-->

**변이 한 칸 갈 때 넓이가 가장 큰 꼭짓점도 앞으로만 갑니다.** 그렇다면 앞 변에서 찾은 자리에서 이어서 찾아도
놓치는 꼭짓점이 없고, `far` 는 변 전체를 따라가는 동안 껍질을 한 바퀴 남짓만 움직여요. 이어 쓰는 판의 규모는
이렇습니다.

<!--proof:origin-calipers-->

| 입력 | 껍질 꼭짓점 m | 껍질을 세우는 기본 연산 | 껍질을 세운 뒤의 기본 연산 | 기본 연산 합 | 시간(초당 1 억 번) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 37 | 25 | 62 | 0.000 초 |
| 흩어진 점 100,000 개 | 30 | 2,036,560 | 131 | 2,036,691 | 0.020 초 |
| 원 위의 점 100,000 개 | 100,000 | 1,284,456 | 449,998 | 1,734,454 | 0.017 초 |

<!--/proof-->

지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **회전하는 캘리퍼스**입니다. 볼록 껍질을 세우고, 변을 반시계 방향으로 하나씩 보며,
그 변에서 넓이가 가장 큰 꼭짓점을 가리키는 `far` 를 앞으로만 보내고, 변의 두 끝과 `far` 가 만드는 대척점 쌍 둘을
재요. 대척점 쌍이 어떻게 생겼는지, 무엇을 먼저 준비하고 어떤 차례로 재는지는 다음 절에서 실현하는 순서대로
확인합니다.

### 아이디어 상세 — 회전하는 캘리퍼스

이 아이디어를 한 문장으로 줄이면 이렇습니다. **볼록 껍질을 반시계 방향으로 세워 두고, 변을 차례로 보며 그 변에서
넓이가 가장 큰 꼭짓점까지 `far` 를 앞으로만 보낸 뒤, 변의 두 끝과 `far` 가 만드는 대척점 쌍 둘로 가장 큰 제곱
거리를 고칩니다.** 이 절은 먼저 대척점 쌍이 무엇인지 그림과 값으로 보고, 회전하는 캘리퍼스를 실현하는 순서대로 네
단계를 설명합니다. 1단계는 입력마다 한 번이고, 3단계와 4단계는 변 하나마다 해요.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 볼록 껍질 세우기 | 점을 반시계 방향 껍질 꼭짓점 배열로 줄인다 | — |
| 2단계 변에서 더 먼 꼭짓점 가르기 | 두 꼭짓점 가운데 어느 쪽이 변에서 더 먼지를 외적 하나의 부호로 낸다 | — |
| 3단계 변을 따라 far 를 앞으로 보내기 | 변마다 다음 꼭짓점이 더 먼 동안 `far` 를 한 칸씩 전진시킨다 | 1단계의 껍질 · 2단계의 판정 |
| 4단계 대척점 쌍 둘로 best 고르기 | 변의 두 끝과 `far` 의 꼭짓점을 짝지은 쌍 둘을 재서 `best` 를 고친다 | 3단계의 `far` |

#### 먼저 알아 둘 개념 — 대척점 쌍

대척점 쌍은 **볼록 껍질을 평행한 두 지지선 사이에 끼웠을 때 두 지지선이 각각 지나는 두 꼭짓점**입니다. 지지선은
껍질의 꼭짓점이나 변을 지나면서 껍질 전체를 한쪽에 두는 직선이고, 방향 하나를 정하면 그 방향의 지지선이 양쪽에
하나씩 정해져요. 이 글은 지지선 하나가 껍질의 변 `h_i → h_{i+1}` 을 품는 방향만 봅니다. 그때 반대편 지지선이
지나는 꼭짓점이 그 변에서 가장 먼 꼭짓점 `f` 이고, 대척점 쌍은 `(h_i, f)` 와 `(h_{i+1}, f)` 둘입니다.

##### 입력 위의 대척점 쌍

전개 입력의 대척점 쌍을 전부 그렸습니다. 가는 실선이 껍질의 변이고, 대시 간선이 대척점 쌍이며, 간선 위 수가 그
쌍의 제곱 거리입니다. 굵게 그린 간선이 가장 큰 쌍이에요.

<!--fig:build-antipodal-->
![전개 입력의 대척점 쌍 — 간선 위 수는 제곱 거리](./figs/build-antipodal.svg)

변마다 쌍을 둘씩 내면 겹치는 쌍이 생깁니다. 쌍마다 어느 변이 그 쌍을 냈는지 모으면 이렇습니다.

<!--proof:build-antipodal-->

| 대척점 쌍 | 제곱 거리 | 그 쌍을 낸 변 |
| --- | ---: | --- |
| h0–h4 | 53 | h0→h1 · h3→h4 |
| h1–h4 | 65 | h0→h1 · h1→h2 · h4→h5 |
| h2–h4 | 52 | h1→h2 |
| h0–h2 | 73 | h2→h3 · h5→h0 |
| h0–h3 | 72 | h2→h3 · h3→h4 |
| h1–h5 | 52 | h4→h5 |
| h2–h5 | 65 | h5→h0 |

변 6 개가 쌍을 12 번 내고, 겹치는 것을 빼면 대척점 쌍은 7 개입니다. 그중 가장 큰 제곱 거리 73 이 모든 쌍을 잰 답과 같습니다.

<!--/proof-->

`h0–h2` 는 변 `h2→h3` 에서 한 번, 변 `h5→h0` 에서 한 번 나왔습니다. 한 대척점 쌍이 여러 변에서 나오는 것은 그 쌍의
두 지지선을 기울이는 동안 한 지지선이 두 꼭짓점 가운데 어느 한쪽에 붙은 변과 나란해질 때마다 한 번씩 나오기 때문이에요.
`h1–h4` 는 `h1` 에 붙은 두 변과 `h4` 에 붙은 한 변에서 세 번 나왔습니다.

##### 대척점 쌍 하나를 읽는 법

변 `h0→h1` 에서 대척점 쌍을 읽어 봅시다. 변을 품는 지지선은 `y = 0` 이고, 꼭짓점마다 그 변을 밑변으로 삼은
삼각형 넓이의 2 배를 적으면 넓이가 가장 큰 꼭짓점을 반대편 지지선이 지납니다. 정점 아래 수가 그 넓이이고, 굵은 테의
정점이 가장 먼 꼭짓점, 테가 조금 굵은 두 정점이 변의 두 끝이에요.

<!--fig:build-read-->
![변 h0→h1 의 대척점 쌍 — 넓이가 가장 큰 h4 를 반대편 지지선이 지난다](./figs/build-read.svg)

<!--proof:build-read-->

| 꼭짓점 | 좌표 | 변 h0→h1 에서의 넓이의 2 배 |
| --- | --- | ---: |
| h0 | (0,0) | 0 |
| h1 | (6,0) | 0 |
| h2 | (8,3) | 18 |
| h3 | (6,6) | 36 |
| h4 | (2,7) | 42 |
| h5 | (0,4) | 24 |

넓이가 가장 큰 꼭짓점은 h4 (2,7) 입니다. 변의 두 끝과 짝지은 대척점 쌍 h0–h4 와 h1–h4 의 제곱 거리는 53 과 65 입니다.

<!--/proof-->

읽는 차례는 셋입니다. 변을 고르고, 그 변에서 넓이가 가장 큰 꼭짓점을 찾고, 변의 두 끝을 그 꼭짓점과 하나씩
짝지어요. 넓이는 밑변이 같으니 높이에 비례하므로, 넓이가 가장 큰 꼭짓점이 곧 변에서 가장 먼 꼭짓점입니다.

##### 이웃한 변의 대척점 쌍끼리의 관계

이웃한 두 변의 가장 먼 꼭짓점은 같거나, 반시계 방향으로 몇 칸 앞입니다. 변을 차례로 보며 `far` 가 앞 변의 자리에서
몇 칸 옮겨 갔는지 세었어요.

<!--proof:build-monotone-->

| 변 | 넓이가 가장 큰 꼭짓점 | far | 앞 변의 far 에서 앞으로 옮긴 칸 |
| --- | --- | --- | ---: |
| h0→h1 | h4 | h4 | 3 |
| h1→h2 | h4 · h5 | h4 | 0 |
| h2→h3 | h0 | h0 | 2 |
| h3→h4 | h0 | h0 | 0 |
| h4→h5 | h1 · h2 | h1 | 1 |
| h5→h0 | h2 | h2 | 1 |

여섯 변 모두에서 far 가 넓이가 가장 큰 꼭짓점 가운데 하나이고, 옮긴 칸을 더하면 7 칸으로 껍질 꼭짓점 수 6 의 두 배보다 적습니다.

<!--/proof-->

넓이가 가장 큰 꼭짓점이 둘인 변(`h1→h2` · `h4→h5`)에서는 `far` 가 둘 가운데 앞쪽에 멈춥니다. 뒤쪽 꼭짓점은 바로
다음 변에서 `far` 가 한 칸 옮겨 가며 만나므로 빠지는 쌍이 없어요. 옮긴 칸의 합이 꼭짓점 수의 두 배보다 적다는
것은 `far` 가 변 전체를 따라가는 동안 껍질을 한 바퀴 남짓만 움직였다는 뜻입니다.

##### 꼭짓점에서 가장 먼 꼭짓점과의 차이

대척점을 「꼭짓점 하나에서 **거리**가 가장 먼 꼭짓점」으로 읽기 쉽습니다. 그러나 대척점 쌍을 정하는 것은 변에서의
**넓이**(높이)예요. 같은 껍질에서 두 기준으로 찾은 꼭짓점을 나란히 놓으면 이렇습니다.

<!--proof:build-vertex-far-->

| 변 a→b | 변에서 넓이가 가장 큰 꼭짓점 | a 에서 거리가 가장 먼 꼭짓점 | b 에서 거리가 가장 먼 꼭짓점 |
| --- | --- | --- | --- |
| h0→h1 | h4 | h2 | h4 |
| h1→h2 | h4 · h5 | h4 | h0 |
| h2→h3 | h0 | h0 | h0 |
| h3→h4 | h0 | h0 | h1 |
| h4→h5 | h1 · h2 | h1 | h2 |
| h5→h0 | h2 | h2 | h2 |

여섯 변 가운데 1 변에서 넓이가 가장 큰 꼭짓점과 앞 끝 a 에서 거리가 가장 먼 꼭짓점이 다릅니다.

<!--/proof-->

변 `h0→h1` 에서 넓이로는 `h4` 가, 앞 끝 `h0` 에서 거리로는 `h2` 가 가장 멉니다. 거리로 찾는 꼭짓점은 변이 아니라
점 하나에 매인 값이라 이웃한 두 꼭짓점 사이의 관계를 주지 않아요. 넓이는 변마다 한 봉우리를 이루며 변을 따라 앞으로만
가는 값이고, 그 성질이 3단계의 근거가 됩니다.

##### 대척점 쌍만 보아도 되는 까닭

지름의 두 끝 `h0` · `h2` 에서 `h0→h2` 방향의 성분을 재면, 점 전부가 두 끝의 값 사이에 들어갑니다. 그림의 두 선이
그 방향에 수직인 직선이고, 정점 아래 수가 `h0` 에서 잰 성분이에요.

<!--fig:build-why-->
![지름에 수직인 두 직선 사이에 점 전부가 있다](./figs/build-why.svg)

<!--proof:build-why-->

| 점 | h0 에서 잰 h0→h2 방향 (8,3) 의 성분 |
| --- | ---: |
| (0,0) | 0 |
| (6,0) | 48 |
| (8,3) | 73 |
| (6,6) | 66 |
| (2,7) | 37 |
| (0,4) | 12 |
| (3,3) | 33 |
| (5,2) | 46 |

가장 작은 값 0 과 가장 큰 값 73 은 지름의 두 끝 (0,0) 과 (8,3) 의 값이고, 나머지 점은 전부 그 사이에 있습니다.

<!--/proof-->

점 전부가 두 직선 사이에 있으니 두 직선은 평행한 지지선이고, 지름의 두 끝은 대척점 쌍입니다. 만약 어떤 점 `r` 의
성분이 `h2` 의 성분보다 크면 `h0` 에서 `r` 까지가 `h0` 에서 `h2` 까지보다 멀고, `h0` 의 성분보다 작으면 `h2` 에서 `r`
까지가 더 멀어서, 어느 쪽이든 `h0–h2` 가 지름이라는 데 어긋나요.
그리고 두 지지선을 기울이면서 지나는 꼭짓점이 바뀌는 자리는 한 지지선이 변과 나란해지는 순간뿐이라, 변 `m` 개만
보면 대척점 쌍이 전부 나옵니다.

#### 1단계 — 볼록 껍질 세우기

점을 볼록 껍질의 꼭짓점 배열로 줄입니다. 절차는 [`convexHull` 가이드](../convexHull/convexHull-guide.md)의 단조
사슬 둘 그대로이고, 반시계 방향으로 가장 왼쪽 아래 꼭짓점부터 받아요.

<!--proof:build-hull-->

| 점 | 껍질에서의 자리 |
| --- | --- |
| (0,0) | 꼭짓점 h0 |
| (6,0) | 꼭짓점 h1 |
| (8,3) | 꼭짓점 h2 |
| (6,6) | 꼭짓점 h3 |
| (2,7) | 꼭짓점 h4 |
| (0,4) | 꼭짓점 h5 |
| (3,3) | 껍질 안쪽 |
| (5,2) | 껍질 안쪽 |

점 8 개 가운데 6 개가 껍질 꼭짓점이고, 반시계 방향 차례는 (0,0) (6,0) (8,3) (6,6) (2,7) (0,4) 입니다.

<!--/proof-->

안쪽 점 둘이 빠져 뒤의 단계는 꼭짓점 여섯만 봅니다. 이 단계의 비용이 정렬 때문에 `n log n` 이고, 뒤의 단계는 전부
`m` 에 비례합니다.

#### 2단계 — 변에서 더 먼 꼭짓점 가르기

`far` 를 전진시킬지 정하려면 **두 꼭짓점 `c` · `d` 가운데 어느 쪽이 변 `a→b` 에서 더 먼가**를 알아야 합니다.
거리를 실제로 재면 제곱근이 끼어들므로 넓이로 재요. 변 `a→b` 를 밑변으로 삼은 삼각형 넓이의 2 배는
$(b-a)\times(c-a)$ 이고, 두 넓이의 차는 외적 하나로 줄어듭니다.

$$
(b-a)\times(d-a) - (b-a)\times(c-a) = (b-a)\times\bigl((d-a)-(c-a)\bigr) = (b-a)\times(d-c)
$$

앞의 등호는 외적이 두 번째 벡터에 대해 선형이라 성립하고, 뒤의 등호는 $(d-a)-(c-a) = d-c$ 라 성립해요. 부호가 양수면
`d` 가 더 멀고, 0 이면 같고, 음수면 `c` 가 더 멉니다. 전개 입력의 두 변에서 이웃한 두 꼭짓점을 차례로 넣어 확인했어요.

<!--proof:build-cross-->

| 변 a→b | c → d | c 의 넓이 2 배 | d 의 넓이 2 배 | 넓이 2 배의 차 | (b−a)×(d−c) |
| --- | --- | ---: | ---: | ---: | ---: |
| h0→h1 | h1 → h2 | 0 | 18 | 18 | 18 |
| h0→h1 | h2 → h3 | 18 | 36 | 18 | 18 |
| h0→h1 | h3 → h4 | 36 | 42 | 6 | 6 |
| h0→h1 | h4 → h5 | 42 | 24 | -18 | -18 |
| h2→h3 | h0 → h1 | 30 | 12 | -18 | -18 |
| h2→h3 | h3 → h4 | 0 | 10 | 10 | 10 |
| h2→h3 | h4 → h5 | 10 | 22 | 12 | 12 |
| h2→h3 | h5 → h0 | 22 | 30 | 8 | 8 |

8 줄 가운데 넓이의 차와 외적이 다른 줄은 0 줄입니다.

<!--/proof-->

이 단계가 앞 단계에서 받는 것은 없고, 3단계가 이 판정을 씁니다. 판정은 부호만 필요하므로 코드에서는 부호만 돌려주는
`crossSign` 을 쓰고, 좌표가 커서 곱이 배정밀도 범위를 넘을 때 부호를 정확히 정하는 일은
[`convexHull` 가이드](../convexHull/convexHull-guide.md)의 방향 판정과 같은 방식을 씁니다.

#### 3단계 — 변을 따라 far 를 앞으로 보내기

변 `h_i → h_{i+1}` 마다 2단계의 판정으로 `hull[far + 1]` 이 `hull[far]` 보다 더 먼지 묻고, 더 먼 동안 `far` 를 한
칸씩 전진시킵니다. `far` 는 반복 바깥에 두고 변마다 되돌리지 않아요. 첫 변을 보기 전 `far` 는 1 입니다 — 첫 변
`h0→h1` 의 두 끝은 그 변에서 넓이가 0 이라 가장 먼 꼭짓점일 수 없으니까요.

가장 쉬운 걸음은 판정 한 번에 멈추는 걸음이고, 가장 불안한 걸음은 한 걸음에 여러 칸 전진하는 걸음과 넓이가 같은
꼭짓점을 만나는 걸음입니다. 전개 입력의 첫 두 변이 그 둘이라 무대에 그렸어요. 굵은 테의 정점이 멈춘 `far`, 테가
조금 굵은 정점이 이번 걸음에 읽은 꼭짓점이고, 두 대시선이 변의 지지선과 `far` 를 지나는 평행한 지지선입니다.

<!--fig:build-advance-film-->
![far 를 이어 보내는 두 걸음 — 세 칸 전진하는 변과 한 칸도 안 가는 변](./figs/build-advance-film.svg)

여섯 변에서 차례로 나온 판정을 모두 적으면 이렇습니다.

<!--proof:build-advance-->

| 변 | 이어받은 far | 차례로 나온 판정 | 멈춘 far | 넓이가 가장 큰 꼭짓점 |
| --- | --- | --- | --- | --- |
| h0→h1 | h1 | 1 1 1 -1 | h4 | h4 |
| h1→h2 | h4 | 0 | h4 | h4 · h5 |
| h2→h3 | h4 | 1 1 -1 | h0 | h0 |
| h3→h4 | h0 | -1 | h0 | h0 |
| h4→h5 | h0 | 1 0 | h1 | h1 · h2 |
| h5→h0 | h1 | 1 -1 | h2 | h2 |

판정은 모두 13 번이고 그중 7 번이 전진, 6 번이 멈춤입니다. 멈춘 far 가 여섯 변 모두 넓이가 가장 큰 꼭짓점 가운데 하나입니다.

<!--/proof-->

변 `h0→h1` 은 `far` 를 1 에서 세 칸 전진시켜 `h4` 에 멈추고, 변 `h1→h2` 는 `h4` 와 `h5` 의 넓이가 같아 판정값 0 으로
한 칸도 안 갑니다. 멈춘 자리가 맞는 근거는 두 가지예요. 하나는 넓이의 모양입니다. 볼록 다각형에서 한 변에 대한 넓이는
꼭짓점을 반시계 방향으로 따라가면 늘다가 한 번 줄기 시작해 끝까지 줄어서, 처음으로 늘지 않는 자리가 가장 큰 자리입니다.
반복이 끝나는 조건이 「다음 꼭짓점이 더 멀지 않다」 하나뿐이라 멈춘 자리는 그 자리예요. 다른 하나는 이어받는 자리입니다.
변이 한 칸 가면 가장 큰 자리도 앞으로만 가므로 앞 변이 멈춘 자리에서 이어서 찾아도 그 사이에 가장 큰 자리가 숨어 있을 수
없습니다.

크기도 여기서 정해집니다. `far` 는 첫 변에서 가장 먼 꼭짓점까지 `m − 2` 칸을 넘게 가지 않고, 그 뒤로는 변 전체를
따라가는 동안 한 바퀴를 넘게 가지 않으므로 전진 총수는 `2m` 보다 작아요. 판정은 변마다 멈추는 한 번에 전진 횟수를
더한 것이라 `3m` 보다 작습니다. 위 표의 판정 수가 그 한도 안의 값입니다.

#### 4단계 — 대척점 쌍 둘로 best 고르기

3단계가 멈춘 `far` 의 꼭짓점 `f` 를 변의 두 끝과 하나씩 짝지어 제곱 거리 둘을 재고, 지금까지의 `best` 보다 크면
고칩니다. 변마다 이 두 쌍이 대척점 쌍이에요.

<!--proof:build-best-->

| 변 | 대척점 쌍 둘 | 제곱 거리 둘 | 앞의 best | 뒤의 best |
| --- | --- | --- | ---: | ---: |
| h0→h1 | h0–h4 · h1–h4 | 53 · 65 | 0 | 65 |
| h1→h2 | h1–h4 · h2–h4 | 65 · 52 | 65 | 65 |
| h2→h3 | h0–h2 · h0–h3 | 73 · 72 | 65 | 73 |
| h3→h4 | h0–h3 · h0–h4 | 72 · 53 | 73 | 73 |
| h4→h5 | h1–h4 · h1–h5 | 65 · 52 | 73 | 73 |
| h5→h0 | h2–h5 · h0–h2 | 65 · 73 | 73 | 73 |

best 가 바뀐 변은 h0→h1 · h2→h3 이고, 마지막 best 73 이 답입니다.

<!--/proof-->

모든 대척점 쌍이 적어도 한 변에서 나오므로 마지막 `best` 가 대척점 쌍의 최댓값이고, 지름은 대척점 쌍이므로 그 값이
답입니다. 거리 계산은 변마다 둘이라 `2m` 번이에요.

#### 이 방법이 기대는 전제

회전하는 캘리퍼스는 아래 세 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 껍질이 볼록이고 반시계 방향으로 늘어서 있다 | 3단계에서 넓이가 한 봉우리이고 앞으로만 간다 | 판정의 부호가 뒤집혀 `far` 가 가장 먼 꼭짓점에 가지 못한다 |
| 방향 판정의 부호가 정확하다 | 2단계 · 3단계에서 전진할지 정한다 | 좌표가 크면 배정밀도 값이 0 으로 접혀 더 먼 꼭짓점 앞에서 멈춘다 |
| 제곱 거리가 정확하다 | 4단계에서 `best` 를 고친다 | 배정밀도로 재면 좌표가 클 때 값이 반올림된다 |

껍질의 차례가 어긋날 때의 모습을 먼저 봅니다. 같은 꼭짓점을 시계 방향으로 넣으면 이렇게 나와요.

<!--proof:build-premise-cw-->

| 껍질의 차례 | 꼭짓점 | 캘리퍼스가 낸 제곱 거리 |
| --- | --- | ---: |
| 반시계 방향(정본의 껍질) | (0,0) (6,0) (8,3) (6,6) (2,7) (0,4) | 73 |
| 시계 방향(같은 꼭짓점을 거꾸로) | (0,4) (2,7) (6,6) (8,3) (6,0) (0,0) | 36 |

모든 쌍을 잰 답은 73 입니다.

<!--/proof-->

시계 방향 껍질에서는 변 `a→b` 의 왼쪽이 껍질 바깥이라 안쪽 꼭짓점의 넓이가 음수가 되고, 「더 멀다」의 부호가 거꾸로
읽혀 `far` 가 가장 먼 꼭짓점을 지나칩니다. 1단계가 반시계 방향으로 돌려주는 것이 이 전제를 지키는 자리예요. 방향 판정의
부호가 깨질 때의 모습은 「수식 정의와 유도」에서, 제곱 거리가 깨질 때의 모습은 「수행으로 알아보는 알고리즘」의 「제곱
거리는 배정밀도로 재도 될 것 같다」에서 실행 결과로 봅니다. 그 절의 「같은 거리에서도 전진해도 될 것 같다」는 전제가 아니라
코드의 비교 한 자리 — 넓이가 같을 때 멈추는가 — 를 다룹니다.

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 이렇습니다.

1. 점의 볼록 껍질을 반시계 방향으로 세우고, 꼭짓점이 둘보다 적으면 0 을 돌려준다
2. `best` 를 0, `far` 를 1 로 두고 변 `h_i → h_{i+1}` 을 `i` 가 0 부터 `m − 1` 까지 차례로 본다
3. 변마다 다음 꼭짓점이 더 먼 동안 `far` 를 한 칸씩 전진시킨다
4. 변의 두 끝과 `hull[far]` 의 제곱 거리 둘로 `best` 를 고친다
5. 변을 다 보면 `best` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 점 여덟 개에서 지름의 제곱을 낸다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 점 여덟 개를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const points: Point[] = [[0, 0], [6, 0], [8, 3], [6, 6], [2, 7], [0, 4], [3, 3], [5, 2]];
// 이 절이 끝나면 73 이 나와야 한다
```

왜 하필 이 여덟일까요? 안쪽 점이 둘이라 껍질이 후보를 줄이는 자리가 값으로 확인되고, 한 걸음에 세 칸 전진하는 변과 한
칸도 안 가는 변이 함께 나오며, 넓이가 가장 큰 꼭짓점이 둘인 변이 두 개 있어 판정값 0 에서 멈추는 갈래까지 실행되기
때문이에요. 절차 전체는 이렇습니다.

```text
rotatingCalipersDiameter(points):
    hull ← points 의 볼록 껍질(반시계), k ← hull 의 길이
    k < 2 이면 0 을 낸다                                        ③ 잴 쌍이 없다
    best ← 0, far ← 1
    i 를 0 부터 k−1 까지:
        a ← hull[i], b ← hull[(i+1) mod k]
        hull[far+1] 이 변 a→b 에서 hull[far] 보다 더 먼 동안:   ④ far 를 전진시킨다
            far ← (far+1) mod k
        f ← hull[far]
        best ← best, d²(a,f), d²(b,f) 가운데 가장 큰 값         ⑤ 대척점 쌍 둘
    best 를 배정밀도로 옮겨 낸다

crossSign(u, v):
    외적을 배정밀도로 재서 절댓값이 SAFE 보다 크면 그 부호        ①
    아니면 큰 정수로 다시 재서 그 부호                          ②
```

#### 1. 껍질을 세우고 시작 자리를 정한다

첫 조각은 1단계입니다. 껍질을 세우면 꼭짓점이 반시계 방향으로 담긴 배열 하나가 남고, 그 길이가 `k` 예요. 꼭짓점이 둘
미만이면 잴 쌍이 없으므로 그 자리에서 0 을 냅니다.

```ts
const hull = convexHull(points);
const k = hull.length;
// ③ 서로 다른 점이 둘 미만이면 잴 쌍이 아예 없다.
if (k < 2) return 0n;

let best = 0n;
let far = 1;
```

전개 입력에 실행한 것이 T1 이고, 이렇게 나옵니다. `③` 은 전개 입력에서 거짓이라 반복으로 가고, 점이 하나뿐이거나 같은
좌표만 있는 입력에서 참이 돼요.

<!--proof:walk-hull-->

```text
hull              [(0,0) (6,0) (8,3) (6,6) (2,7) (0,4)]
k                 6
껍질에서 빠진 점  (3,3) (5,2)
k < 2             6 < 2 → 거짓, 반복으로 간다
best · far        0 · 1
```

#### 짚고 가기 — 무게중심에서 가장 먼 두 점이 지름일 것 같다

여기서 헷갈리기 쉬운 자리는 「가장 먼 두 점」을 고르는 방법입니다. 「점들의 무게중심을 구하고 거기서 가장 먼 점 두 개를
고르면 지름이겠다」로 읽기 쉬워요. 껍질도 필요 없고 한 번 읽으면 끝나니 훨씬 간단해 보입니다. 그 생각대로 적어 봅시다.

```ts
// 무게중심에서 먼 순으로 정렬해 앞의 둘을 고르는 판
const cx = points.reduce((s, p) => s + p[0], 0) / points.length;
const cy = points.reduce((s, p) => s + p[1], 0) / points.length;
const 거리 = (p: Point) => (p[0] - cx) ** 2 + (p[1] - cy) ** 2;
const sorted = [...points].sort((p, q) => 거리(q) - 거리(p));
```

세 입력으로 확인해 봅니다.

<!--proof:pause-centroid-->

| 입력 | 무게중심에서 가장 먼 두 점 | 그 쌍의 제곱 거리 | 지름의 제곱 | 대조 |
| --- | --- | ---: | ---: | --- |
| 전개 입력 | (0,0)–(8,3) | 73 | 73 | 같다 |
| 여섯 점 (4,0)(0,6)(8,8)(4,4)(2,4)(6,2) | (8,8)–(0,6) | 68 | 80 | 어긋난다 |
| 다섯 점 (0,2)(0,8)(6,8)(4,8)(6,6) | (0,2)–(0,8) | 36 | 72 | 어긋난다 |

<!--/proof-->

**전개 입력에서는 이 판이 정답을 냅니다.** 무게중심에서 가장 먼 두 점이 마침 지름의 두 끝이라서예요. 그럼에도 쓸 수
없는 것은 같은 규모 안의 다른 입력에서 답이 갈리기 때문입니다. 다섯 점 배치에서 무슨 일이 일어나는지 무게중심까지의
거리로 늘어놓으면 이렇습니다.

<!--proof:pause-centroid-why-->

| 차례 | 점 | 무게중심까지의 제곱 거리 |
| ---: | --- | ---: |
| 1 | (0,2) | 29.60 |
| 2 | (0,8) | 12.80 |
| 3 | (6,8) | 10.40 |
| 4 | (6,6) | 8.00 |
| 5 | (4,8) | 3.20 |

무게중심은 (3.2, 6.4) 입니다. 가장 먼 두 점 (0,2) 와 (0,8) 사이의 제곱 거리는 36 이고, 지름은 (0,2)–(6,8) 의 72 입니다.

<!--/proof-->

무게중심에서 먼 두 점이 **서로** 멀다는 보장이 없습니다. 두 점이 무게중심의 같은 쪽에 몰려 있으면 둘 사이는 가까워요.
지름은 점 둘의 관계이고, 점 하나씩의 성질로는 정해지지 않습니다.

#### 2. 외적 한 번으로 더 먼 꼭짓점을 가른다

이 조각은 2단계입니다. 변 `a→b` 에서 `d` 가 `c` 보다 더 먼지를 외적 `(b − a) × (d − c)` 의 부호로 내요. 부호는
`crossSign` 이 정하고, 배정밀도로 먼저 재서 값이 `SAFE` 보다 크면 그 부호를 그대로 쓰고 아니면 큰 정수로 다시 잽니다.

```ts
const SAFE = 2048;

export function crossSign(ux: number, uy: number, vx: number, vy: number): number {
  // ① 먼저 배정밀도로 재고, 값이 오차 한계보다 크면 그 부호를 그대로 쓴다.
  const approx = ux * vy - uy * vx;
  if (approx > SAFE || approx < -SAFE) return approx > 0 ? 1 : -1;
  // ② 오차 한계 안이면 부호를 못 믿는다. 큰 정수로 다시 재서 확정한다.
  const exact = BigInt(ux) * BigInt(vy) - BigInt(uy) * BigInt(vx);
  return exact > 0n ? 1 : exact < 0n ? -1 : 0;
}

export function farther(a: Point, b: Point, c: Point, d: Point): boolean {
  return crossSign(b[0] - a[0], b[1] - a[1], d[0] - c[0], d[1] - c[1]) > 0;
}
```

첫 변 `h0→h1` 에서 이 판정을 실행하면 `far` 가 어디서 멈추는지 나옵니다.

<!--proof:walk-turn-->

| c = hull[far] | d = hull[far+1] | crossSign | 넓이 2 배의 차 | far |
| --- | --- | ---: | ---: | --- |
| h1 | h2 | 1 | 18 | 전진한다 |
| h2 | h3 | 1 | 18 | 전진한다 |
| h3 | h4 | 1 | 6 | 전진한다 |
| h4 | h5 | -1 | -18 | 멈춘다 |

변 h0→h1 에서 판정 4 번 가운데 3 번 전진하고 far 가 h4 에서 멈춥니다. crossSign 과 넓이 차의 부호가 어긋난 줄은 없습니다.

<!--/proof-->

**여기서 가장 중요한 줄은 `> 0` 입니다.** 판정값이 양수일 때만, 곧 다음 꼭짓점이 **더** 멀 때만 전진해요. 같은 거리에서는
멈춥니다. 그 부등호가 왜 그 모양이어야 하는지 바로 다음 짚고 가기에서 봅니다.

#### 짚고 가기 — 같은 거리에서도 전진해도 될 것 같다

여기서 헷갈리기 쉬운 자리는 동점입니다. 「넓이가 같으면 어느 꼭짓점을 골라도 같으니 전진해도 되겠다」로 읽기 쉬워요.
부등호 하나만 바꾸면 되니 자연스러운 생각입니다.

```ts
export function farther(a: Point, b: Point, c: Point, d: Point): boolean {
  return crossSign(b[0] - a[0], b[1] - a[1], d[0] - c[0], d[1] - c[1]) >= 0; // ←
}
```

네 입력으로 확인해 봅니다.

<!--proof:pause-geq-->

| 입력 | 정본 | 같은 거리에서도 전진하는 판 | 바꾼 줄을 지나간 횟수 | 대조 |
| --- | ---: | --- | ---: | --- |
| 전개 입력 | 73 | 73 | 13 | 같다 |
| 정사각형 네 점 | 32 | 32 | 8 | 같다 |
| 공선인 네 점 (0,0)(2,0)(5,0)(9,0) | 81 | 전진 2,000 회에서 끊었다 | 2 | 어긋난다 |
| 같은 점 셋 (5,5) | 0 | 0 | 0 | 같다 |

<!--/proof-->

**전개 입력과 정사각형에서는 답이 같습니다.** 동점인 변에서 한 칸 더 가도 그 꼭짓점이 같은 거리라 결과가 같기
때문이에요. 그럼에도 고치는 이유는 껍질이 선분인 입력에서 반복이 멈추지 않기 때문입니다. 공선인 네 점의 껍질에서 두
변을 보면 이렇습니다.

<!--proof:pause-geq-line-->

| 변 a→b | b − a | far 가 h1 일 때의 d − c | crossSign |
| --- | --- | --- | ---: |
| h0→h1 | (9,0) | (-9,0) | 0 |
| h1→h0 | (-9,0) | (-9,0) | 0 |

껍질은 (0,0) (9,0) 두 점이고, 두 변의 방향이 정확히 반대라 판정값이 늘 0 입니다.

<!--/proof-->

`>=` 는 판정값 0 에서도 전진하므로 `far` 가 두 꼭짓점 사이를 끝없이 오가요. 같은 점 셋은 껍질이 한 점이라 바꾼 줄을 한
번도 지나가지 않고, 그래서 「같다」입니다. 전개 입력에서 중간 값까지 같았는지는 「불변식」 절이 따로 셉니다.

#### 3. 변마다 far 를 보내고 대척점 쌍 둘을 잰다

이번 조각이 3단계와 4단계이고 이 절차의 본체입니다. 변 하나마다 `far` 를 더 갈 수 없을 때까지 전진시키고, 그 자리에서
대척점 쌍 둘을 재요.

```ts
for (let i = 0; i < k; i++) {
  const a = hull[i] as Point;
  const b = hull[(i + 1) % k] as Point;
  // ④ 다음 꼭짓점이 이 변에서 더 멀면 far 를 전진시킨다. far 는 뒤로 가지 않는다.
  while (farther(a, b, hull[far] as Point, hull[(far + 1) % k] as Point))
    far = (far + 1) % k;
  const f = hull[far] as Point;
  // ⑤ 이 변의 두 끝점과 가장 먼 꼭짓점이 만드는 쌍 둘이 대척점 쌍이다.
  best = larger(best, squared(a, f));
  best = larger(best, squared(b, f));
}
```

**여기서 가장 중요한 줄은 `while` 입니다.** 한 변에서 여러 칸을 전진할 수 있어야 `far` 가 그 변의 가장 먼 꼭짓점까지
갑니다. 그리고 `far` 를 반복 바깥에 두었으므로 다음 변은 그 자리에서 이어서 찾아요. 실행하면 여덟 걸음이 이렇게
나옵니다. 걸음마다 정점 아래 수가 그 변에서의 넓이의 2 배이고 굵은 테의 정점이 멈춘 `far` 입니다. 대시 간선은 이번에 잰
대척점 쌍 둘과 앞 걸음에 잰 쌍이고, 두 대시선이 평행한 두 지지선이에요.

#### 짚고 가기 — 제곱 거리는 배정밀도로 재도 될 것 같다

여기서 헷갈리기 쉬운 자리는 `squared` 의 산술입니다. 「곱셈 둘과 덧셈 하나인데 `number` 로 해도 되겠다」로 읽기 쉬워요.
큰 정수 연산은 배정밀도보다 느리니 그럴듯한 생각입니다.

```ts
export function squared(a: Point, b: Point): bigint {
  const dx = BigInt(a[0] - b[0]);
  const dy = BigInt(a[1] - b[1]);
  return BigInt((a[0] - b[0]) * (a[0] - b[0]) + (a[1] - b[1]) * (a[1] - b[1])); // ←
}
```

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 안 나온 것은 껍질을 세우는 함수 넷(`sideOf` · `turnAtEnd` · `buildChain` ·
`convexHull`)과 큰 값을 고르는 `larger` 하나입니다. 껍질을 세우는 넷은 `convexHull` 가이드와 같은 절차이고, `sideOf`
만 `crossSign` 을 불러 방향 판정을 한 벌로 씁니다.

```ts
export type Point = [number, number];

const SAFE = 2048;

export function crossSign(
  ux: number,
  uy: number,
  vx: number,
  vy: number,
): number {
  // ① 먼저 배정밀도로 재고, 값이 오차 한계보다 크면 그 부호를 그대로 쓴다.
  const approx = ux * vy - uy * vx;
  if (approx > SAFE || approx < -SAFE) return approx > 0 ? 1 : -1;
  // ② 오차 한계 안이면 부호를 못 믿는다. 큰 정수로 다시 재서 확정한다.
  const exact = BigInt(ux) * BigInt(vy) - BigInt(uy) * BigInt(vx);
  return exact > 0n ? 1 : exact < 0n ? -1 : 0;
}

export function sideOf(o: Point, a: Point, b: Point): number {
  return crossSign(a[0] - o[0], a[1] - o[1], b[0] - o[0], b[1] - o[1]);
}

function turnAtEnd(chain: Point[], p: Point): number {
  const o = chain.at(-2);
  const a = chain.at(-1);
  if (o === undefined || a === undefined) return 1;
  return sideOf(o, a, p);
}

function buildChain(seq: Point[]): Point[] {
  const chain: Point[] = [];
  for (const p of seq) {
    while (chain.length >= 2 && turnAtEnd(chain, p) <= 0) chain.pop();
    chain.push(p);
  }
  return chain;
}

export function convexHull(points: Point[]): Point[] {
  const sorted = [...points].sort((p, q) => p[0] - q[0] || p[1] - q[1]);

  // 정렬해 두면 같은 좌표가 이웃하므로, 바로 앞 점과만 비교해도 중복이 전부 걸러진다.
  const uniq: Point[] = [];
  for (const p of sorted) {
    const last = uniq.at(-1);
    if (last === undefined || last[0] !== p[0] || last[1] !== p[1])
      uniq.push(p);
  }
  if (uniq.length <= 2) return uniq;

  const lower = buildChain(uniq);
  const upper = buildChain([...uniq].reverse());
  lower.pop();
  upper.pop();
  return [...lower, ...upper];
}

export function squared(a: Point, b: Point): bigint {
  const dx = BigInt(a[0] - b[0]);
  const dy = BigInt(a[1] - b[1]);
  return dx * dx + dy * dy;
}

function larger(x: bigint, y: bigint): bigint {
  return x > y ? x : y;
}

export function farther(a: Point, b: Point, c: Point, d: Point): boolean {
  return crossSign(b[0] - a[0], b[1] - a[1], d[0] - c[0], d[1] - c[1]) > 0;
}

export function diameterSquared(points: Point[]): bigint {
  const hull = convexHull(points);
  const k = hull.length;
  // ③ 서로 다른 점이 둘 미만이면 잴 쌍이 아예 없다.
  if (k < 2) return 0n;

  let best = 0n;
  let far = 1;
  for (let i = 0; i < k; i++) {
    const a = hull[i] as Point;
    const b = hull[(i + 1) % k] as Point;
    // ④ 다음 꼭짓점이 이 변에서 더 멀면 far 를 전진시킨다. far 는 뒤로 가지 않는다.
    while (farther(a, b, hull[far] as Point, hull[(far + 1) % k] as Point))
      far = (far + 1) % k;
    const f = hull[far] as Point;
    // ⑤ 이 변의 두 끝점과 가장 먼 꼭짓점이 만드는 쌍 둘이 대척점 쌍이다.
    best = larger(best, squared(a, f));
    best = larger(best, squared(b, f));
  }
  return best;
}

export function rotatingCalipersDiameter(points: Point[]): number {
  return Number(diameterSquared(points));
}
```

여러 입력에 실행한 결과입니다. 모든 입력에서 점 쌍을 전부 잰 답과 같은지 사이드카가 함께 확인했어요.

### 알아 두면 좋은 개념 — 지지 함수

파트 1 에서 변마다 그 변에서 가장 먼 꼭짓점을 찾았습니다. 그것은 「변에 수직인 안쪽 방향으로 가장 멀리 나간 꼭짓점」과
같은 말이에요. 방향 하나를 정하면 그 방향으로 가장 멀리 나간 값이 정해지는데, 그 대응에 이름이 붙어 있습니다. 볼록 집합
$K$ 와 방향 벡터 $u$ 에 대해 $h_K(u) = \max_{p \in K} \langle p, u \rangle$ 를 $K$ 의 **지지 함수**(support function)라고
합니다. 최댓값을 내는 점이 그 방향의 **지지점**이고, 그 점을 지나며 $u$ 에 수직인 직선이 지지선이에요.

전개 입력의 껍질에서 변마다 그 변에 수직인 안쪽 방향을 넣어 지지값을 내면 이렇습니다.

<!--proof:related-support-->

| 변 | 그 변에 수직인 안쪽 방향 u | 지지값 h(u) | 그 값을 내는 꼭짓점 | 그 변의 far |
| --- | --- | ---: | --- | --- |
| h0→h1 | (0,6) | 42 | h4 | h4 |
| h1→h2 | (-3,2) | 8 | h4 · h5 | h4 |
| h2→h3 | (-3,-2) | 0 | h0 | h0 |
| h3→h4 | (-1,-4) | 0 | h0 | h0 |
| h4→h5 | (3,-2) | 18 | h1 · h2 | h1 |
| h5→h0 | (4,0) | 32 | h2 | h2 |

지지값을 가장 크게 하는 꼭짓점 가운데 그 변의 far 가 없는 변은 0 개입니다.

<!--/proof-->

지지값을 가장 크게 하는 꼭짓점이 그 변의 `far` 와 같습니다. 회전하는 캘리퍼스를 지지 함수로 다시 말하면 「방향을 반
바퀴 기울이며 $u$ 와 $-u$ 의 지지점 쌍을 재는 것」이고, 같은 이름을 다시 만나는 자리가 여럿이에요.

| 다시 나오는 자리 | 지지 함수가 하는 일 |
| --- | --- |
| 두 볼록 집합의 민코프스키 합 | 합집합을 만들지 않고 두 지지 함수를 더해 방향마다의 값을 낸다 |
| 충돌 판정의 GJK 절차 | 방향을 주고 지지점만 물어보며 두 도형의 거리를 좁힌다 |
| 최소 넓이로 감싸는 직사각형 | 지지선 네 개를 함께 기울이며 변마다 넓이를 잰다 |

## 파트 2 — 적용 조건 · 보장 · 비용

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 점 집합 전체에서 가장 먼 두 점을 묻는다 | 점 하나에서 먼 점이 아니라 쌍이 대상이고 답이 수 하나다 | `best` 하나를 끝까지 고친다 |
| 좌표가 정수이고 제곱 거리로 답해도 된다 | 제곱근을 안 부르면 판정과 답이 정수 연산으로 닫힌다 | `squared` 와 `crossSign` 이 큰 정수를 쓴다 |
| 점이 전부 미리 주어진다 | 한 번에 받아 껍질을 세울 수 있다 | 맨 앞에서 `convexHull` 을 한 번 부른다 |
| 한 번만 묻는다 | 점이 바뀔 때마다 물으면 껍질을 매번 새로 세워야 한다 | 껍질을 세운 뒤 한 바퀴로 끝난다 |

비슷해 보이는 과제와 쓰는 절차를 가르면 이렇습니다.

| 과제 | 쓰는 절차 | 까닭 |
| --- | --- | --- |
| 점 집합의 가장 먼 두 점 | 볼록 껍질 + 회전하는 캘리퍼스 | 답이 대척점 쌍 가운데 있다 |
| 점 집합의 가장 가까운 두 점 | [분할선 띠](../closestPairOfPoints/closestPairOfPoints-guide.md) | 답이 껍질 안쪽에 있을 수 있어 껍질로 후보를 못 줄인다 |
| 점을 감싸는 최소 넓이 직사각형 | 볼록 껍질 + 지지선 네 개 | 같은 골격에 지지선 쌍을 하나 더 둔다 |
| 3 차원 점의 가장 먼 두 점 | 다른 절차 | 대척점 쌍의 수가 꼭짓점 수에 비례한다는 보장이 없다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "가장 멀리 떨어진 두 점"  "점 집합의 지름"          <- 이 절차 그 자체다
  "모든 점을 담는 가장 작은 직사각형 · 띠"            <- 지지선을 기울이는 같은 골격이다
  "볼록 다각형의 폭"                                  <- 평행한 두 지지선 사이의 거리다

제약에 이런 모양이 보이면
  점이 10^5 개 안팎이고 좌표가 정수이며 거리의 제곱을 답하라고 한다

반대로 이런 말이 보이면 해당하지 않는다
  "가장 가까운 두 점"                   <- 분할 정복이나 격자 나누기의 자리다
  "점이 하나씩 추가되며 매번 답"        <- 껍질을 다시 세우는 비용이 매번 붙는다
  "점이 다각형 안에 있는가"             <- 반직선 교차 세기의 자리다
```

점 집합의 껍질을 세우는 일 자체는 [`convexHull`](../convexHull/convexHull-guide.md) 쪽이고, 가장 가까운 두 점은
[`closestPairOfPoints`](../closestPairOfPoints/closestPairOfPoints-guide.md) 쪽이에요.

#### 실제로 쓰이는 곳

- **OpenCV** — `modules/imgproc/src/rotcalipers.cpp` 가 이 절차를 담고 있습니다. 함수 머리 주석이 *"Rotating
  calipers algorithm with some applications"* 이고, 모드가
  `enum { CALIPERS_MAXHEIGHT=0, CALIPERS_MINAREARECT=1, CALIPERS_MAXDIST=2 };` 셋으로 갈려 있어요. 본체의 주석은
  *"all of edges will be checked while rotating calipers by 90 degrees"* 이고, 공개 함수 `cv::minAreaRect` 가 볼록
  껍질을 먼저 구한 뒤 `rotatingCalipers( hpoints, n, clockwise ? -1.f : 1.f, CALIPERS_MINAREARECT, (float*)out );`
  로 부릅니다. 이 파일에서 실제로 불리는 모드는 `CALIPERS_MINAREARECT` 하나이고 나머지 둘은 정의만 되어 있습니다.
  ([소스](https://github.com/opencv/opencv/blob/4.x/modules/imgproc/src/rotcalipers.cpp), 조회일 2026-09-08)
- **CGAL** — 최소 감싸는 도형을 구하는 함수 셋의 구현 절이 이 절차를 명시합니다. `min_rectangle_2` 와
  `min_strip_2` 의 구현 절이 *"We use a rotating caliper algorithm [14] with worst case running time linear in the
  number of input points."* 이고, `min_parallelogram_2` 는 같은 문장에 참고 문헌만 `[12], [15]` 로 다릅니다.
  ([공식 문서](https://doc.cgal.org/latest/Bounding_volumes/group__PkgBoundingVolumesRef.html), 조회일 2026-09-08)

인용한 두 곳이 이 글과 어디서 같고 다른지 모으면 이렇습니다.

| 출처 | 이 글과 같은 것 | 이 글과 다른 것 |
| --- | --- | --- |
| OpenCV | 껍질을 먼저 구하고 캘리퍼스를 부르는 순서 | 지름 모드는 정의만 있고, 실제로 부르는 것은 최소 넓이 직사각형이다 |
| CGAL | 지지선을 기울이는 골격 · 최악 선형 | 지름이 아니라 감싸는 도형(직사각형 · 띠 · 평행사변형)에 쓴다 |

두 구현이 동점을 안에서 어떻게 다루는지는 이 글이 확인하지 않았습니다. 지름 자체를 공개 함수로 내놓은 자리는 두 곳
다 아니었고, 이 절차가 실전에서 쓰이는 모양은 「지름을 구한다」보다 「지지선을 기울이는 골격을 다른 과제에 쓴다」에
가깝습니다.

#### 경쟁 설계와의 대조

같은 목표(껍질을 세운 뒤 가장 먼 두 꼭짓점을 찾는 것)를 노리는 다른 설계로 **껍질 위 모든 쌍**을 재는 판이 있습니다.
볼록 껍질을 세우는 데까지는 회전하는 캘리퍼스와 똑같이 하고, 그 뒤에 `far` 를 두지 않고 껍질 꼭짓점 쌍을 전부 재서 가장
큰 것을 고릅니다. 껍질을 세우는 비용이 같으므로 **껍질을 세운 뒤에 하는 일**만 세어요. 계수는 이 글의 기준 그대로
기본 연산(방향 판정 + 거리 계산)이고, 잡는 칸은 껍질 배열과 값 칸 셋입니다.

입력은 껍질 꼭짓점 수를 바꿔 가며 잡습니다. 전개 입력(껍질 여섯)을 그대로 넣고, 규모를 키운 입력을 더했어요 — 전개
입력은 껍질 크기가 여섯으로 고정이라 두 설계를 가르는 값이 움직이지 않기 때문입니다. 규모를 키운 입력은 반지름 1,000,000 인
원 위에서 각을 등분해 반올림한 점이고, 모든 점이 껍질 꼭짓점이라는 것을 하네스가 만들 때마다 실행으로 확인합니다.

<!--proof:alt-counts-->

| 입력 | 껍질 꼭짓점 m | 회전하는 캘리퍼스 | 껍질 위 모든 쌍 | 기본 연산이 적은 쪽 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 6 | 25 | 15 | 껍질 위 모든 쌍 |
| 원 위의 점 9 | 9 | 39 | 36 | 껍질 위 모든 쌍 |
| 원 위의 점 10 | 10 | 43 | 45 | 회전하는 캘리퍼스 |
| 원 위의 점 64 | 64 | 286 | 2,016 | 회전하는 캘리퍼스 |
| 원 위의 점 1,024 | 1,024 | 4,606 | 523,776 | 회전하는 캘리퍼스 |

껍질 꼭짓점 1,024 개에서 거리 계산은 2,048 대 523,776 이고 방향 판정은 2,558 대 0 입니다. 잡는 칸은 1,027 대 1,027 로 같고, 기본 연산이 적은 쪽은 껍질 꼭짓점이 10 개가 되는 자리에서 바뀝니다.

<!--/proof-->

**껍질 꼭짓점이 아홉과 열 사이에서 적은 쪽이 바뀝니다.** 회전하는 캘리퍼스는 방향 판정 `m + (전진 총수)` 와 거리 계산 `2m`
을 쓰고, 껍질 위 모든 쌍은 거리 계산 `m(m−1)/2` 만 씁니다. 앞은 `m` 에 비례하고 뒤는 `m` 의 제곱에 비례하므로 `m` 이
작으면 뒤가 적고, 크면 앞이 적어요.

**회전하는 캘리퍼스가 내주는 것은 둘입니다.** 껍질이 아홉 이하일 때 연산이 더 많고, 상대는 방향 판정을 한 번도 하지 않는
대신 이 절차는 방향 판정을 해야 합니다. 방향 판정은 오차 한계 안이면 큰 정수로 다시 재는 갈래가 있어 거리 계산보다 갈래가
많고, 껍질이 반시계 방향이라는 전제에도 기대요. 상대는 껍질의 순서를 아예 쓰지 않습니다. 잡는 칸은 두 설계가 같습니다.
그러니 **껍질 꼭짓점이 몇 개인지 알 수 없는 과제라면** 회전하는 캘리퍼스가 답이고, 「껍질이 삼각형이다」처럼 껍질이 작다고
정해진 과제에서는 모든 쌍을 재는 쪽이 연산도 적고 코드도 짧습니다.

### 수식 정의와 유도

좌표 상한 $C$ 가 주어졌을 때 판정과 답을 배정밀도로 내도 되는 경계를 닫힌 형태로 냅니다. 파트 1 의 실행은 좌표 상한
`10^9` 에서 값이 갈린다는 것을 보였지만, **어느 좌표 상한까지가 안전한가**는 값으로 못 얻어요.

기호 넷을 정의합니다. 파트 1 의 기호표에서 정한 `C` 에 배정밀도 모형을 더한 것이에요.

| 기호 | 정의 |
| --- | --- |
| $C$ | 좌표의 절댓값 상한 |
| $S$ | 배정밀도가 정확히 담는 정수의 상한. $S = 2^{53}$ |
| $\mathrm{fl}(x)$ | 실수 $x$ 를 가장 가까운 배정밀도 수로 옮긴 값 |
| $\varepsilon$ | 배정밀도의 상대 오차 상한. $\varepsilon = 2^{-53}$ |

판정과 답에 쓰는 두 값을 정식으로 적습니다.

$$
\operatorname{cross}(u, v) = u_x v_y - u_y v_x, \qquad \operatorname{d^2}(p, q) = (p_x - q_x)^2 + (p_y - q_y)^2
$$

정의를 전개 입력에 넣어 확인합니다.

<!--proof:math-define-->

| 식 | 넣은 값 | 결과 |
| --- | --- | ---: |
| cross(u, v) | u = h1 − h0 = (6,0) · v = h2 − h1 = (2,3) → 6·3 − 0·2 | 18 |
| d²(h0, h2) | (-8)² + (-3)² | 73 |

<!--/proof-->

두 값의 크기 상한을 좌표 상한으로 적습니다. 좌표가 $[-C, C]$ 안이면 두 좌표의 차는 $[-2C, 2C]$ 안이고, 차 둘의 곱은
$4C^2$ 을 넘지 못해요. 외적과 제곱 거리는 그런 곱 둘을 빼거나 더한 것이라 $8C^2$ 을 넘지 못합니다.

$$
|u_x v_y| \le 4C^2, \qquad |\operatorname{cross}(u,v)| \le 8C^2, \qquad \operatorname{d^2}(p,q) \le 8C^2
$$

배정밀도로 외적을 계산하면 곱 둘과 뺄셈 하나에서 각각 반올림이 붙습니다. 곱 하나의 절대 오차는 그 값의 크기에
$\varepsilon$ 을 곱한 것 이하라 $4C^2\varepsilon$ 을 넘지 못하고, 뺄셈의 결과는 $8C^2$ 을 넘지 않으므로 그 반올림도
$8C^2\varepsilon$ 이하예요. 셋을 더하면 한계가 나옵니다. $16 = 2^4$ 이라 지수가 줄어요.

$$
\bigl|\mathrm{fl}(\operatorname{cross}) - \operatorname{cross}\bigr| \le 4C^2\varepsilon + 4C^2\varepsilon + 8C^2\varepsilon = 16C^2 \cdot 2^{-53} = \frac{C^2}{2^{49}}
$$

```ts
// 위 오차 한계를 그대로 옮긴 조각. SAFE 는 C^2/2^49 보다 큰 2 의 거듭제곱이다.
const errorBound = (cap: number): number => cap ** 2 / 2 ** 49;
```

좌표 상한을 몇 가지 넣어 한계를 계산하면 이렇습니다.

<!--proof:math-check-->

| 좌표 상한 C | 곱의 상한 4C² | 2^53 초과 | 오차 한계 C²/2^49 |
| ---: | ---: | --- | ---: |
| 1,000 | 4,000,000 | 안 넘는다 | 1.78e-9 |
| 23,726,566 | 2,251,799,736,609,424 | 안 넘는다 | 0.99999997 |
| 33,554,432 | 4,503,599,627,370,496 | 안 넘는다 | 2.00000000 |
| 47,453,133 | 9,007,199,326,062,756 | 넘는다 | 4.00000003 |
| 1,000,000,000 | 4,000,000,000,000,000,000 | 넘는다 | 1776.35683940 |

2^53 = 9,007,199,254,740,992 입니다. C = 10^9 에서 외적과 제곱 거리의 상한 8C² 은 2^53 의 888.2 배이고(8C² = 8,000,000,000,000,000,000), 오차 한계 1776.36 보다 큰 2 의 거듭제곱 가운데 가장 작은 것이 SAFE = 2,048 입니다.

<!--/proof-->

**`SAFE` 를 2,048 로 둔 근거가 그 표의 마지막 줄입니다.** 배정밀도로 잰 값의 절댓값이 한계보다 크면 참값도 같은 부호예요.
참값은 배정밀도 값에서 한계 이하만큼 떨어져 있으니, 배정밀도 값이 한계보다 멀리 0 에서 떨어져 있으면 참값도 0 의 같은
쪽에 있기 때문입니다.

**부호가 반대로 뒤집히지는 않습니다.** $\mathrm{fl}$ 은 단조 증가라 $A \le B$ 이면 $\mathrm{fl}(A) \le \mathrm{fl}(B)$ 이고,
외적의 두 곱을 $A = u_x v_y$ · $B = u_y v_x$ 로 두면 $A > B$ 일 때 $\mathrm{fl}(A) \ge \mathrm{fl}(B)$ 라 배정밀도 값이 음수가
되지 않아요. 잃는 것은 부호가 아니라 **0 과의 구분**입니다. 성분이 이웃한 큰 정수인 벡터로 확인했습니다.

<!--proof:math-sign-->

| 벡터 두 개 | 정확한 외적 | 배정밀도 값 | 차 | 정본 부호 | 배정밀도만 쓴 부호 |
| --- | ---: | ---: | ---: | ---: | ---: |
| u=(1000, 999) v=(1001, 1000) | 1 | 1 | 0 | 1 | 1 |
| u=(100000000, 99999999) v=(100000001, 100000000) | 1 | 0 | -1 | 1 | 0 |
| u=(1000000000, 999999999) v=(1000000001, 1000000000) | 1 | 0 | -1 | 1 | 0 |
| u=(2000000000, 1999999999) v=(2000000000, 1999999999) | 0 | 0 | 0 | 0 | 0 |

성분이 이웃한 큰 정수인 벡터 쌍 200,000 개에서 배정밀도 부호가 0 으로 접힌 것은 55,563 개이고 부호가 반대로 뒤집힌 것은 0 개입니다. 가장 큰 오차는 511 입니다.

<!--/proof-->

이제 두 경계를 닫습니다. 앞의 경계는 큰 정수로 다시 재지 않아도 부호가 정해지는 좌표 상한이에요. 외적은 정수라 오차 한계가
1 보다 작으면 배정밀도 값과 참값의 차가 1 보다 작고, 참값이 0 이 아닌 정수인 이상 부호가 같습니다.

$$
\frac{C^2}{2^{49}} < 1 \iff C^2 < 2^{49} \iff C < 2^{24.5}
$$

뒤의 경계는 제곱 거리 자체가 배정밀도에 정확히 담기는 좌표 상한입니다. 제곱 거리의 상한 $8C^2$ 이 $S$ 이하이면 돼요.

$$
8C^2 \le 2^{53} \iff C^2 \le 2^{50} \iff C \le 2^{25}
$$

```ts
// 두 경계를 그대로 옮긴 조각. 앞은 부호가, 뒤는 제곱 거리가 배정밀도로 정확한 좌표 상한인가를 묻는다.
const signExact = (cap: number): boolean => cap ** 2 / 2 ** 49 < 1;
const valueExact = (cap: number): boolean => 8n * BigInt(cap) ** 2n <= 2n ** 53n;
```

두 경계를 실행으로 확인하면 이렇습니다.

<!--proof:math-caps-->

| 좌표 상한 C | 제곱 거리 상한 8C² | 2^53 이내 | 외적 오차 한계 | 큰 정수로 다시 재기 |
| ---: | ---: | --- | ---: | --- |
| 23,726,566 | 4,503,599,473,218,848 | 그렇다 | 0.99999997 | 필요 없다 |
| 23,726,567 | 4,503,599,852,843,912 | 그렇다 | 1.00000005 | 필요하다 |
| 33,554,432 | 9,007,199,254,740,992 | 그렇다 | 2.00000000 | 필요하다 |
| 33,554,433 | 9,007,199,791,611,912 | 아니다 | 2.00000012 | 필요하다 |
| 1,000,000,000 | 8,000,000,000,000,000,000 | 아니다 | 1776.35683940 | 필요하다 |

제곱 거리가 배정밀도로 정확한 가장 큰 좌표 상한은 33,554,432 고, 큰 정수로 다시 재지 않아도 부호가 확정되는 가장 큰 좌표 상한은 23,726,566 입니다.

<!--/proof-->

**닫힌 형태가 낸 두 자리가 실측과 같습니다.** 뒤의 경계가 앞의 경계보다 크므로 부호를 잃는 일이 값을 잃는 일보다 작은 좌표에서
먼저 일어나요. 이 과제의 좌표 상한 `10^9` 은 두 경계를 모두 넘으므로 **판정과 답을 둘 다 큰 정수로 내야** 합니다.

### 불변식 — far 는 그 변에서 넓이가 가장 큰 꼭짓점이고 한 바퀴 안에서 뒤로 가지 않는다

파트 1 에서 코드가 동작하는 것을 여덟 걸음으로 봤습니다. 그건 점 여덟 개에서 맞았다는 뜻이지 언제나 맞는다는 뜻은
아니에요. 변 하나를 끝낼 때마다 무엇이 참으로 남는지를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> 바깥 반복이 변 `h_i → h_{i+1}` 하나를 끝낸 직후, `hull[far]` 는 **그 변에서 넓이가 가장 큰 꼭짓점 가운데 하나**이고,
> 그 변에서 `far` 가 옮겨 간 칸 수는 **앞 변의 `far` 에서 이번 `far` 까지 반시계 방향으로 센 거리**와 같습니다.

| 절반 | 말하는 것 | 없으면 |
| --- | --- | --- |
| 앞 절반 | 변마다 잰 쌍이 그 변의 대척점 쌍이다 | 대척점 쌍이 아닌 쌍을 재고 지름을 놓친다 |
| 뒤 절반 | `far` 가 앞으로만 가서 전진 총수가 껍질 한 바퀴 남짓이다 | 변마다 처음부터 찾는 판처럼 비용이 `m` 의 제곱이 된다 |

**출발점부터 봅시다.** 첫 변을 보기 전 `far` 는 1 이고, 그 자리는 아직 어떤 변에 대해서도 가장 크다고 주장하지 않습니다.
첫 변의 반복이 끝나야 두 절반이 처음으로 참이 돼요. 그 뒤로 한 변 안에서 상태를 바꾸는 갈래는 둘뿐입니다.

| 갈래 | 하는 일 | 두 절반이 유지되는 근거 |
| --- | --- | --- |
| 다음 꼭짓점이 더 멀다 | `far` 가 한 칸 늘어난다 | 넓이가 늘어나는 쪽으로만 옮기므로 아직 가장 큰 자리를 지나치지 않았다 |
| 다음 꼭짓점이 더 멀지 않다 | 아무것도 안 바뀌고 반복이 끝난다 | 넓이는 봉우리가 하나라 처음으로 늘지 않는 자리가 가장 큰 자리다. 변이 한 칸 가면 가장 큰 자리도 앞으로만 가므로 다음 변이 여기서 이어받아도 된다 |

「봉우리가 하나」인 까닭은 이렇습니다. 변 `a→b` 를 품는 직선에서 꼭짓점까지의 높이를 반시계 방향으로 적으면, 볼록
다각형의 이웃한 두 변은 그 직선에 대해 기울기가 한 방향으로만 바뀌어서 높이가 늘다가 한 번 줄기 시작하면 다시 늘지
않아요. 그리고 변이 반시계 방향으로 한 칸 가면 그 변을 품는 직선의 방향도 반시계 방향으로 기울어지므로 가장 높은 꼭짓점도
뒤로 가지 않습니다. 둘이 걸음마다 실제로 유지되는지는 손으로 세지 않고 실행이 판정합니다. 전개 입력과, 껍질 꼭짓점을 3
개부터 64 개까지 바꾼 원 위의 점, 그리고 4 × 4 격자에서 다섯 점 이하로 뽑은 묶음 전부를 넣어 걸음마다 확인했어요.

<!--proof:invariant-far-->

| 입력 묶음 | 확인한 걸음 | far 가 넓이가 가장 큰 꼭짓점이 아닌 걸음 | far 가 뒤로 간 걸음 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 6 | 0 | 0 |
| 원 위의 점 3 개부터 64 개까지 | 2,077 | 0 | 0 |
| 4 × 4 격자에서 다섯 점 이하로 뽑은 묶음 전부 | 26,032 | 0 | 0 |

모든 입력에서 전진 총수를 껍질 꼭짓점 수로 나눈 값의 가장 큰 것은 1.48 입니다.

<!--/proof-->

**경계에 있는 입력도 확인하고 갑시다.** 점이 없거나 하나이거나, 같은 좌표만 있거나, 전부 한 직선 위에 있거나, 좌표가
상한인 자리예요.

<!--proof:invariant-edges-->

| 입력 | 껍질 꼭짓점 m | 제곱 거리 | 경계인 까닭 |
| --- | ---: | ---: | --- |
| [] | 0 | 0 | 점이 없어 껍질도 비고 반복을 한 번도 하지 않는다 |
| [(3,4)] | 1 | 0 | 껍질이 한 점이라 잴 쌍이 없다 |
| [(7,7),(7,7)] | 1 | 0 | 같은 좌표가 둘이라 껍질이 한 점으로 줄어든다 |
| [(0,0),(3,4)] | 2 | 25 | 껍질이 선분이라 두 변이 서로 반대 방향이다 |
| [(0,0),(2,0),(5,0),(9,0)] | 2 | 81 | 공선이라 가운데 두 점이 껍질에서 빠진다 |
| [(0,0),(0,0),(3,4)] | 2 | 25 | 같은 점이 섞여도 껍질에는 한 번만 담긴다 |
| 좌표 상한의 대각선 두 끝 | 2 | 8,000,000,000,000,000,000 | 제곱 거리가 이 과제의 가장 큰 값이다 |

<!--/proof-->

껍질이 한 점 이하면 반복을 한 번도 하지 않고, 껍질이 선분이면 두 변이 서로 반대 방향이라 판정값이 늘 0 이어서 `far` 가
움직이지 않은 채 두 끝의 거리를 잽니다. 두 경우 모두 두 절반이 참이에요.

**이제 깨뜨려 봅시다.** 뒤 절반을 지키던 줄은 전진을 되풀이하는 `while` 한 줄입니다. 그 줄을 `if` 로 바꾸면 변마다 많아야
한 칸만 전진해요.

```ts
    if (farther(a, b, hull[far] as Point, hull[(far + 1) % k] as Point)) // ←
      far = (far + 1) % k;
```

<!--proof:mutant-once-->

| 입력 | 정본 | 변마다 한 번만 전진하는 판 | 바꾼 줄을 지나간 횟수 | 대조 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 73 | 73 | 6 | 같다 |
| 정사각형 네 점 | 32 | 32 | 4 | 같다 |
| 원 위의 점 16 | 4,000,002,475,592 | 585,788,385,618 | 16 | 어긋난다 |
| 같은 점 셋 (5,5) | 0 | 0 | 0 | 같다 |

<!--/proof-->

**「원 위의 점 16」 줄이 그 자리입니다.** 전개 입력과 정사각형에서 답이 같은 것은 전진이 변마다 한 칸을 넘지 않는 배치라서예요.
원 위의 점 16 에서는 첫 변에서 이미 여러 칸을 가야 하는데 한 칸만 가서, 그 차이가 끝까지 좁혀지지 않습니다.

<!--proof:mutant-once-steps-->

| 변 | 정본의 far | 한 번만 전진하는 판의 far | 정본의 best | 그 판의 best |
| --- | --- | --- | ---: | ---: |
| h0→h1 | h8 | h2 | 4,000,000,000,000 | 585,786,618,898 |
| h1→h2 | h9 | h3 | 4,000,002,131,556 | 585,788,385,618 |
| h2→h3 | h10 | h4 | 4,000,002,475,592 | 585,788,385,618 |
| h3→h4 | h11 | h5 | 4,000,002,475,592 | 585,788,385,618 |
| h15→h0 | h7 | h1 | 4,000,002,475,592 | 585,788,385,618 |

첨자는 원 위의 점 16 의 껍질 h0…h15 고, 앞의 네 변과 마지막 변만 적었습니다. 마지막 변에서 far 는 h7 대 h1 입니다.

<!--/proof-->

**「답이 같다」인 줄도 안전하다는 뜻이 아닙니다.** 바꾼 줄을 지나가고도 답이 같으면 그 변이가 무해한 것인지, 중간 값이
갈렸다가 뒤 걸음이 상쇄한 것인지 갈라야 해요. 세 변이와 세 입력을 변마다 나란히 실행해 `far` 와 `best` 를 비교했습니다.

<!--proof:mutant-same-steps-->

| 변이 | 입력 | 바꾼 줄을 지나간 횟수 | 중간 값이 갈린 걸음 | 확인한 걸음 | 답 |
| --- | --- | ---: | ---: | ---: | --- |
| 제곱 거리를 배정밀도로 낸 판 | 전개 입력 | 12 | 0 | 6 | 그대로 |
| 제곱 거리를 배정밀도로 낸 판 | 정사각형 네 점 | 8 | 0 | 4 | 그대로 |
| 제곱 거리를 배정밀도로 낸 판 | 공선인 네 점 | 4 | 0 | 2 | 그대로 |
| 같은 거리에서도 전진하는 판 | 전개 입력 | 13 | 2 | 6 | 그대로 |
| 같은 거리에서도 전진하는 판 | 정사각형 네 점 | 8 | 4 | 4 | 그대로 |
| 같은 거리에서도 전진하는 판 | 공선인 네 점 | 2 | — | — | 멈추지 않는다 |
| 변마다 한 번만 전진하는 판 | 전개 입력 | 6 | 0 | 6 | 그대로 |
| 변마다 한 번만 전진하는 판 | 정사각형 네 점 | 4 | 0 | 4 | 그대로 |
| 변마다 한 번만 전진하는 판 | 공선인 네 점 | 2 | 0 | 2 | 그대로 |

중간 값은 걸음마다의 far 와 best 두 값이고, 정본과 변이를 변마다 나란히 실행해 비교했습니다.

<!--/proof-->

「같은 거리에서도 전진하는 판」은 전개 입력과 정사각형에서 답은 그대로인데 중간 값이 갈렸습니다. 동점인 변에서 한 칸 더
갔기 때문이고, 그 두 꼭짓점이 같은 거리라 마지막 `best` 만 같은 값으로 돌아와요. 나머지 두 변이는 이 입력들에서 중간 값까지
같았습니다 — 배정밀도 판은 좌표가 작아 반올림이 한 번도 일어나지 않았고, 한 번만 전진하는 판은 전진이 변마다 한 칸을 넘지
않는 배치였기 때문입니다.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 다섯 무리입니다 — 정렬의 좌표 비교, 같은 좌표 확인, 껍질을 세우는 방향 판정, 캘리퍼스의 전진
판정, 거리 계산이에요. 전개의 걸음으로 가르면 T1 이 앞의 셋, T2~T7 이 뒤의 둘입니다. 「상한」 칸의 정렬 비교는 합치기 정렬이
`n` 개를 정렬할 때 드는 비교의 최악값 `n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1` 이고, 껍질을 세우는 방향 판정의 상한 `4u − m − 6` 은
[`convexHull` 가이드](../convexHull/convexHull-guide.md)의 「수식 정의와 유도」가 유도한 식이에요.

<!--proof:perf-ops-->

| 하는 일 | 걸음 | 실측 | 상한 |
| --- | --- | ---: | ---: |
| 좌표로 정렬한다 | T1 | 13 | 17 |
| 같은 좌표를 확인한다 | T1 | 8 | 8 |
| 껍질을 세우는 방향 판정 | T1 | 16 | 20 |
| 캘리퍼스의 전진 판정 | T2~T7 | 13 | 18 |
| 거리 계산 | T2~T7 | 12 | 12 |

실측 합계는 62 번이고, 다섯 항의 상한을 더하면 75 번입니다. 캘리퍼스의 전진 판정 13 번은 멈춤 6 번과 전진 7 번을 더한 값입니다.

<!--/proof-->

캘리퍼스의 상한 둘은 3단계와 4단계에서 셌습니다. 전진 판정은 변마다 멈추는 한 번에 전진 횟수를 더한 것이고 전진 총수가
`2m` 보다 작으므로 `3m` 이하이며, 거리 계산은 변마다 둘이라 정확히 `2m` 이에요. 캘리퍼스 쪽이 `m` 에 비례하는지 껍질 꼭짓점을
네 배씩 키우며 세었습니다.

<!--proof:perf-growth-->

| 껍질 꼭짓점 m | 전진 판정 | 거리 계산 | 껍질을 세운 뒤의 기본 연산 | m 으로 나눈 값 | 앞 줄과의 비 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 8 | 8 | 16 | 4.00 | — |
| 16 | 38 | 32 | 70 | 4.38 | 4.38 |
| 64 | 158 | 128 | 286 | 4.47 | 4.09 |
| 256 | 638 | 512 | 1,150 | 4.49 | 4.02 |
| 1,024 | 2,558 | 2,048 | 4,606 | 4.50 | 4.01 |

원 위의 점은 반지름 1,000,000 인 원에서 각을 등분해 반올림한 점이라 모든 점이 껍질 꼭짓점입니다.

<!--/proof-->

앞 줄과의 비가 4 에 가까워지고 `m` 으로 나눈 값이 한곳에 모입니다. 껍질을 네 배로 하면 캘리퍼스의 일도 네 배가 된다는 뜻이고,
그것이 `m` 에 비례한다는 말이에요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요. 이 글이 세는 합치기
정렬로 적었습니다.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (같은 좌표만 있어 껍질이 한 점이다) | `O(n log n)` | `Θ(n log n)` — 합치기 정렬은 어떤 입력에서도 비교를 `n log n` 규모로 한다 |
| **평균적인 경우** (입력 분포를 가정하지 않는다) | `O(n log n)` | `Θ(n log n)` — 모든 입력에서 같은 차수라 분포와 상관없다 |
| **최악의 경우** (모든 점이 껍질 꼭짓점이다) | `O(n log n)` | `Θ(n log n)` — 실제로 도달한다 |

세 줄이 다 같은 것은 정렬 때문입니다. 캘리퍼스 쪽만 떼면 껍질이 한 점일 때 0 번이고 모든 점이 꼭짓점일 때 `n` 에 비례해 크게
갈리지만, 정렬이 그보다 큰 항이라 총식에서 가려져요. **총식을 한 번은 정확히 적습니다.** 앞에 붙는 것은 껍질을 세우는 일이고,
뒤에 붙는 것은 없어요 — 해시도, 좌표 압축도 안 씁니다.

$$
\text{기본 연산} \le \bigl(n\lceil\log_2 n\rceil - 2^{\lceil\log_2 n\rceil} + 1\bigr) + n + (4u - m - 6) + 5m = \Theta(n \log n)
$$

$$
\text{추가로 잡는 칸} = n + 2u + m + 3 = \Theta(n)
$$

잡는 칸은 정렬 사본 `n`, 중복을 지운 목록 `u`, 뒤집은 사본 `u`, 껍질 `m`, 그리고 `best` · `far` · `i` 세 칸입니다. 두 식에
전개 입력과 점 10 만 개를 넣으면 이렇습니다(첫 식은 서로 다른 점이 셋 이상일 때의 식이에요).

<!--proof:perf-total-->

| 입력 | n | u | m | 기본 연산 상한 | 기본 연산 실측 | 잡는 칸 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 8 | 8 | 6 | 75 | 62 | 33 |
| 흩어진 점 100,000 개 | 100,000 | 100,000 | 30 | 2,069,043 | 2,036,691 | 300,033 |
| 원 위의 점 100,000 개 | 100,000 | 100,000 | 100,000 | 2,468,923 | 1,734,454 | 400,003 |

<!--/proof-->

**보장의 종류는 전부 최악 보장입니다.** 난수를 부르는 자리가 한 곳도 없고 입력이 어떤 분포에서 왔는지도 가정하지 않아요. 같은
입력이면 언제나 같은 계수가 나오고, 판정과 답이 큰 정수로 확정되므로 반올림에 따라 답이 갈리는 일도 없습니다.

| 정사각형 테두리 위의 점 | 100,000 | 4 | 1,284,455 | 16 | 1,284,471 | 300,007 |
| 원 위의 점 | 100,000 | 100,000 | 1,284,456 | 449,998 | 1,734,454 | 400,003 |
| 한 직선 위의 점 | 100,000 | 2 | 1,115,020 | 6 | 1,115,026 | 300,005 |
| 같은 좌표만 | 1 | 1 | 915,024 | 0 | 915,024 | 100,004 |

점은 다섯 모양 모두 100,000 개입니다. 기본 연산 합이 가장 많은 모양은 정사각형 안에 흩어 놓은 점(2,036,691 번), 껍질을 세운 뒤의 기본 연산이 가장 많은 모양은 원 위의 점(449,998 번), 잡는 칸이 가장 많은 모양은 원 위의 점(400,003 칸)입니다.

<!--/proof-->

**통념은 절반만 맞습니다.** 점 수가 정렬 비용을 정하지만, 캘리퍼스 비용은 **껍질에 남는 점의 비율**이 정해요. 캘리퍼스 쪽이
가장 많은 모양은 모든 점이 껍질 꼭짓점인 원 위의 점이고, 합계가 가장 많은 모양은 흩어진 점입니다 — 정렬 비교와 껍질의 방향 판정을
합한 「껍질을 세우는 기본 연산」이 흩어진 점에서 가장 많기 때문이에요. 두 기준의 최악이 서로 다른 입력이고, 잡는 칸은 `m`
이 가장 큰 원 위의 점에서 가장 많습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 점 쌍을 **전부 재던** 것을 껍질 위 **대척점 쌍만 재는** 것으로 바꿨고,
대척점 쌍은 변마다 넓이가 가장 큰 꼭짓점을 가리키는 `far` 를 앞으로만 보내며 찾습니다.

```text
껍질을 세우고 → 변마다 넓이가 가장 큰 꼭짓점까지 far 를 전진시켜 → 쌍 둘로 best 를 고친다
                 └ 넓이 차가 외적 하나다        └ far 는 뒤로 가지 않는다     └ 마지막 best 가 답이다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T3 에서 변 `h1→h2` 의 넓이가 가장 큰 꼭짓점이 `h4` 와 `h5` 둘이었고 `far` 는 앞쪽인
`h4` 에 멈췄어요. **`h5` 에 멈췄다면 답이 달라졌을까요?**

<!--check:tieChoice-->
답: **달라지지 않습니다.** 그 걸음의 대척점 쌍 둘이 자리만 바꿔 나오기 때문이에요. 두 값 가운데 큰 쪽만 `best` 에 들어가므로
그 걸음 뒤의 `best` 가 같고, 뒤 걸음도 같게 이어집니다. 동점이 생기는 것은 **두 변이 서로 반대 방향으로 평행할
때**이고, 그때 두 꼭짓점은 같은 지지선 위에 나란히 놓입니다. 어느 쪽에 멈추든 다음 변에서 나머지 하나를 지나가므로
대척점 쌍을 빠뜨리지 않아요. 격자에서 뽑은 묶음 전부에서 어긋난 걸음이 없다는 것이 「불변식」 절의 표입니다. 두 자리에
각각 멈추게 하고 끝까지 실행해 보면 이렇습니다.

| --- | ---: | ---: | ---: | ---: | ---: |
| h4 | 26 | 65 | 52 | 65 | 73 |
| h5 | 26 | 52 | 65 | 65 | 73 |

h4 · h5 를 바꿔 넣어도 끝까지 실행한 답은 둘 다 73 입니다.

보세요.

- 전진 총수의 상한은 왜 `m` 이 아니라 `2m` 입니까? 전개의 T2 에서 `far` 가 1 에서 출발해 여러 칸을 간 것과, 그 뒤로 변을 다
  보는 동안 한 바퀴를 넘지 않는 것을 두 토막으로 나눠 적어 보세요.
- 좌표 상한이 `10^9` 가 아니라 `10^6` 인 과제라고 합시다. `crossSign` 에서 큰 정수로 다시 재는 자리와 `squared` 의 큰 정수를

### 점 집합의 지름 (제곱 거리)

풀 파일: [`rotatingCalipersDiameter.ts`](./rotatingCalipersDiameter.ts) · 테스트: [`rotatingCalipersDiameter.test.ts`](./rotatingCalipersDiameter.test.ts) · 실행: `bun test src/algorithms/geometry/rotatingCalipersDiameter/rotatingCalipersDiameter.test.ts`

#### 한 줄 요약

> 2D 평면 위 점 배열이 주어질 때, 가장 멀리 떨어진 두 점 사이 거리의 **제곱**을 반환한다.

#### 스토리

우주 관측소의 데이터 분석팀은 관측 구역 안 별들의 좌표를 가지고 있다. 관측 구역의 "지름"을 구하려고 하는데, 지름이란 가장 멀리 떨어진 두 별 사이의 거리를 뜻한다.

정밀 계산이 필요한 상황에서 부동소수점 오차를 피하기 위해, 거리 자체가 아니라 거리의 제곱을 반환하기로 했다. 별들의 좌표는 정수이므로 제곱 거리도 정수로 딱 떨어진다.

주어진 점 집합에서 가장 멀리 떨어진 두 점 사이 거리의 제곱을 구하는 함수를 만들어라.

#### 함수 인터페이스

```ts
export type Point = [number, number];

export function rotatingCalipersDiameter(points: Point[]): number;
```

- `points` — 2D 평면 위 점 배열. 각 원소는 `[x, y]` 형태. 배열의 길이는 $N$.
- 반환 — 가장 멀리 떨어진 두 점 사이의 거리의 제곱. $\geq 0$ 인 수.

#### 제약 조건

- $2 \leq N \leq 10^5$ — 점의 개수는 최소 2개
- $-10^9 \leq x, y \leq 10^9$ — 정수 좌표 권장
- 반환값은 $\geq 0$ 이며, 좌표가 정수이면 반환값도 정수
- 최대 반환값은 $2 \times (2 \times 10^9)^2 = 8 \times 10^{18}$ 이다. $2^{53}$ 을 넘는 답은 정확한 제곱 거리에 가장 가까운 배정밀도 값으로 돌려준다
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

2D 평면 위 $N$ 개의 점 $P = \{p_1, \ldots, p_N\}$ 에서 서로 다른 인덱스 $i \neq j$ 인 두 점 사이의 거리가 최대인 쌍의 거리 제곱을 반환한다.

$$\mathrm{diam}^2(P) = \max_{i \neq j} \left( (x_i - x_j)^2 + (y_i - y_j)^2 \right)$$

- 두 점의 좌표가 동일하면 제곱 거리는 $0$ 이다.
- 반환값은 제곱 거리이므로 루트를 취하지 않는다.
- 좌표 범위가 $\pm 10^9$ 이므로, 축마다 두 좌표의 차이가 최대 $2 \times 10^9$ 이고 두 축의 제곱을 더하면 $8 \times 10^{18}$ 까지 커진다. 계산 도중에 자릿수를 잃지 않아야 한다.

#### 예시

```ts
// 두 점만 있는 경우
rotatingCalipersDiameter([[0, 0], [3, 4]]); // 25 — 3²+4²=25

// 정사각형 — 대각선이 지름
rotatingCalipersDiameter([[0, 0], [1, 0], [1, 1], [0, 1]]); // 2 — √2의 제곱

// 직사각형 — 대각선이 지름
rotatingCalipersDiameter([[0, 0], [4, 0], [4, 6], [0, 6]]); // 52 — 4²+6²=52

// 내부 점이 많아도 외곽 두 점이 답
rotatingCalipersDiameter([[0, 0], [10, 0], [5, 5], [4, 3], [6, 2]]); // 100 — (0,0)과 (10,0)

// 공선 점들 — 양 끝점 사이
rotatingCalipersDiameter([[0, 0], [2, 0], [5, 0], [9, 0]]); // 81 — 9²=81

// 동일 좌표 두 점
rotatingCalipersDiameter([[7, 7], [7, 7]]); // 0 — 같은 점

// 큰 좌표 — 오버플로 없이 처리
rotatingCalipersDiameter([[-1_000_000_000, 0], [1_000_000_000, 0], [0, 0]]); // 4e18 — (2×10⁹)²
```
