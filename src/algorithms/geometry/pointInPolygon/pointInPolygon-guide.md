# pointInPolygon — 반직선이 변과 교차하는 횟수의 홀짝 하나로 안팎이 갈리는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 좌표 칸마다 안팎을
적어 두는 방법에서 출발해 반직선 교차 세기에 이르고, 그 방법을 단계마다 값으로 푼 뒤, 실제로 동작하는 코드를
한 조각씩 만듭니다.

### 전체 컨셉

평면 위의 점 하나와 단순 다각형 하나를 받아 **점이 다각형의 내부이거나 경계 위이면 `true`**, 외부이면
`false` 를 돌려줍니다. 다각형은 볼록해도 되고 오목해도 되며, 꼭짓점이 시계 방향으로 주어지든 반시계 방향으로
주어지든 답이 같아야 해요.

이 판정을 **반직선 교차 세기**로 합니다. 영어 자료에서는 ray casting 또는 crossing number 라고 부르는
방법이에요. 묻는 점에서 오른쪽으로 끝없이 뻗는 반쪽 직선, 곧 **반직선**을 긋고, 그 반직선이 다각형의 변과
몇 번 만나는지 셉니다. 반직선이 변과 한 점에서 만나 그 변을 가로지르는 것을 **교차**라고 부르고, 그 횟수를
**교차 수**라고 부르겠습니다. 교차 수가 홀수면 내부, 짝수면 외부예요. 이 글이 끝까지 쓰는 L 자 다각형에
점 둘의 반직선을 그렸습니다. 화살촉은 변의 방향이고, 대시가 반직선입니다.

<!--fig:concept-rays-->
![L 자 다각형과 두 점 q1 · q2 의 반직선 — 화살촉은 변의 방향, 대시가 반직선](./figs/concept-rays.svg)

`q1` 의 반직선은 오른쪽 벽 `e2` 와 한 번 교차해서 홀수라 내부입니다. `q2` 는 L 자가 파인 자리에 있어서
오른쪽으로 가는 동안 벽을 하나도 만나지 않고, 교차 수 0 이 짝수라 외부예요. 오목한 자리라고 갈래를 더 두지
않고, 규칙 하나로 둘 다 답이 나옵니다. 점 여섯에 이 규칙을 적용하면 이렇게 갈립니다.

<!--proof:concept-cases-->

| 배치 | 질의 점 | 교차 수 | 답을 정한 것 | 답 |
| --- | --- | ---: | --- | --- |
| 내부 | (1,1) | 1 | 홀수 | true |
| 오목한 자리라 외부 | (3,3) | 0 | 짝수 | false |
| 변 위 | (2,3) | 0 | 변 위 | true |
| 꼭짓점 위 | (0,0) | 0 | 변 위 | true |
| 오른쪽 바깥 | (5,1) | 0 | 짝수 | false |
| 위쪽 바깥 | (1,5) | 0 | 짝수 | false |

다각형은 L 자 여섯 변 (0,0) (4,0) (4,2) (2,2) (2,4) (0,4) 입니다. 여섯 줄 가운데 2 줄은 점이 변 위라 교차 수와 상관없이 답이 true 이고, 나머지 4 줄은 교차 수가 홀수인지로 답이 정해졌습니다.

<!--/proof-->

변 위와 꼭짓점 위의 점은 **교차 수로 가르지 않습니다.** 경계 위의 점은 내부로 셀 점인데, 그 점에서 뻗은
반직선의 교차 수는 홀수로 나오기도 하고 짝수로 나오기도 해요. 그래서 이 절차는 변마다 교차를 세기 전에 **점이
그 변 위에 있는가**를 먼저 묻고, 그렇다면 그 자리에서 `true` 를 돌려줍니다. 변 하나에 묻는 것을 차례로 놓으면
셋이에요.

| 묻는 것 | 참일 때 하는 일 |
| --- | --- |
| 점이 이 변 위에 있는가 | 그 자리에서 `true` 를 돌려준다 |
| 이 변이 반직선의 높이를 지나는가 | 셋째 물음으로 간다. 거짓이면 이 변은 볼 것이 없다 |
| 그 높이에서 변이 점의 오른쪽에 있는가 | 교차이므로 홀짝을 뒤집는다 |

셋 다 도구 하나로 답합니다. 점 `o` 에서 `a` 로 간 다음 `b` 로 갈 때 **왼쪽으로 꺾이는가 · 오른쪽으로
꺾이는가 · 한 직선 위인가**를 재는 **방향 판정**이고, 코드에서는 `sideOf(o, a, b)` 가 차례로 1 · -1 · 0 을
돌려줘요. 이 값을 **판정값**이라고 부릅니다. 변의 두 끝점과 묻는 점을 넣으면 점이 변의 왼쪽인지 오른쪽인지
직선 위인지가 나오고, 교점의 좌표는 한 번도 구하지 않아요. 남은 어려움은 산술입니다. 판정값은 두 좌표 차의
곱 둘과 뺄셈 하나로 만드는데, 좌표가 `10^9` 까지 커지면 그 곱이 배정밀도 수가 정수를 오차 없이 담는 범위를
넘어가요.

<!--proof:concept-exact-->

| 좌표 상한 | 좌표의 차 | 곱의 최댓값 | 배정밀도에 정확히 담기 |
| ---: | ---: | ---: | --- |
| 1,000 | 2,000 | 4.00e+6 | 담긴다 |
| 1,000,000 | 2,000,000 | 4.00e+12 | 담긴다 |
| 23,726,566 | 47,453,132 | 2.25e+15 | 담긴다 |
| 1,000,000,000 | 2,000,000,000 | 4.00e+18 | 안 담긴다 |

배정밀도가 정수를 오차 없이 담는 한계 Number.MAX_SAFE_INTEGER 는 9,007,199,254,740,991 이고, 좌표 상한 1,000,000,000 에서 곱 하나의 최댓값은 그 한계의 444 배가 넘습니다.

<!--/proof-->

그래서 판정 하나를 두 겹으로 둡니다. 배정밀도로 먼저 재 보고 값이 오차 한계보다 크면 그 부호를 그대로 쓰고,
한계 안이면 큰 정수로 다시 재서 확정해요. 질의 하나는 변마다 위의 물음을 한 번씩 묻고 끝나므로 연산 수가
꼭짓점 수에 비례해 `O(n)` 이고, 추가로 잡는 칸은 홀짝을 담는 값 하나라 `O(1)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **좌표평면 위의 점과 벡터.** 두 점의 차 `(a_x − o_x, a_y − o_y)` 를 `o` 에서 `a` 로 가는 방향으로 읽을 수
  있어야 해요. 방향 판정이 그 차 둘로만 만들어집니다.
- **두 벡터 외적의 부호가 회전 방향을 뜻한다는 것.** 외적이 양수면 앞 벡터에서 뒤 벡터로 반시계 방향으로 돈
  것입니다. 같은 판정을 점 집합의 껍질을 쌓는 데 쓰는 이야기는 [`convexHull` 가이드](../convexHull/convexHull-guide.md)에,
  선분 둘의 끝점 넷에 쓰는 이야기는 [`segmentsIntersect` 가이드](../segmentsIntersect/segmentsIntersect-guide.md)에
  있어요. 이 글은 그 판정에 **변의 두 끝점과 묻는 점**을 넣습니다.
- **단순 다각형이 무엇인가.** 변끼리 서로 가로지르지 않고 한 바퀴 닫히는 다각형입니다. 이 성질이 있어야
  「닫힌 경계가 평면을 안과 밖 둘로 가른다」가 성립해요.
- **반개구간 표기.** `[a, b)` 처럼 한쪽 끝만 포함하는 구간입니다. 이 글의 높이 판정이 그 모양이에요.
- **배정밀도 수가 정수를 오차 없이 담는 범위가 정해져 있다는 것과 큰 정수 자료형.** 자바스크립트의
  `number` 는 `Number.MAX_SAFE_INTEGER` 보다 큰 정수를 반올림해서 담고, `BigInt` 는 자릿수 제한 없이
  정확한 대신 연산 하나가 배정밀도보다 비용이 큽니다.

같은 방향 판정이 쓰이는 이웃 과제를 함께 놓으면 이 글의 자리가 보입니다.

| 과제 | 다루는 글 |
| --- | --- |
| 점 하나가 다각형 안에 있는가 | 이 글 |
| 두 선분이 한 점이라도 공유하는가 | [`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-guide.md) |
| 점 집합을 감싸는 가장 작은 볼록 다각형 | [`convexHull`](../convexHull/convexHull-guide.md) |
| 다각형의 넓이 | [`polygonArea`](../polygonArea/polygonArea-guide.md) |

### 아이디어를 떠올리는 과정 — 격자 표에서 반직선 교차 세기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 점 하나와 꼭짓점 배열 하나를 받아
참과 거짓을 돌려줍니다.

```ts
type Point = [number, number];

function pointInPolygon(p: Point, polygon: Point[]): boolean;
```

- 입력: 판정할 점 `p` 와 꼭짓점 배열 `polygon`. 꼭짓점은 경계를 따라 차례로 주어지고, 마지막 꼭짓점과 첫
  꼭짓점이 저절로 이어집니다. 다각형은 변끼리 가로지르지 않는 단순 다각형이고 볼록 · 오목 둘 다 올 수 있어요.
- 출력: 점이 내부이거나 경계 위이면 `true`, 외부이면 `false`. 변 위와 꼭짓점 위가 전부 `true` 입니다.
- 규모: 꼭짓점은 3 개 이상 `10^5` 개 이하이고, 좌표는 절댓값 `10^9` 이하의 정수예요. 좌표 상한을 `10^9` 로
  두는 것은 두 좌표 차의 곱이 배정밀도가 정수를 오차 없이 담는 범위를 넘게 해서, 판정값의 부호를 정확히
  정하는 일까지 함께 보려는 것입니다([`convexHull`](../convexHull/convexHull-guide.md) ·
  [`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-guide.md) 와 같은 상한). 꼭짓점 수 상한
  `10^5` 는 질의마다 변을 전부 보는 방법이 질의 하나에 연산을 얼마나 쓰는지 가늠할 만큼으로 둔 것이에요.
  메모리는 흔한 채점 환경의 예산인 256 MB 에 대어 잽니다.

비용은 **기본 연산**으로 셉니다. 좌표 읽기 · 곱셈(배정밀도 · 큰 정수) · 큰 정수 변환 · 좌표 비교를 각각 1 로
센 합이고, 나눗셈은 그것을 쓰는 방법에서만 따로 셉니다. 이 글의 비용은 전부 이 기준으로 잰 것이에요. 이 글이
쓰는 기호는 여덟입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `n` | 다각형의 꼭짓점 수 | 3 이상 `10^5` 이하 |
| `p` | 판정할 점 | 두 좌표를 `p_x` · `p_y` 로 적고, 코드의 `py` 가 `p_y` 다 |
| `a` · `b` | 지금 보는 변의 두 끝점 | `a` 가 앞, `b` 가 뒤이고 좌표를 `a_x` · `a_y` 로 적는다 |
| `o` · `a` · `b` | 방향 판정이 받는 세 점 | `o → a → b` 순서로 꺾임을 잰다. 변을 볼 때는 변의 두 끝점과 `p` 가 들어간다 |
| `d` | 변 하나에 대한 판정값 | `1` · `-1` · `0` 셋 중 하나 |
| `inside` | 여기까지 센 교차 수의 홀짝 | 홀수면 참 |
| `C` | 좌표의 절댓값 상한 | `10^9` |
| `SAFE` | 배정밀도로 잰 판정값의 부호를 그대로 믿는 하한 | 정본에서 2,048 |

기호 `a` · `b` 는 두 줄에 걸쳐 있어요. 변을 볼 때는 변의 두 끝점이고, 방향 판정의 자리로 읽을 때는 `o` 에 변의
앞 끝점, `a` 에 뒤 끝점, `b` 에 `p` 가 들어갑니다. 변 이름 `e1` ~ `e6` 과 전개의 점 이름은 그 값을 처음 쓰는
자리에서 정해요.

가장 먼저 떠오르는 방법은 **답을 미리 다 적어 두는 것**입니다. 좌표 칸마다 안인지 밖인지를 표에 적어 두고,
질의가 오면 그 칸을 읽기만 해요. 표는 이렇게 채웁니다. 다각형의 변을 표에 긋고, 표 바깥에서 변을 넘지 않고
이어진 칸을 모두 밖으로 적은 뒤, 남은 칸을 안으로 봐요. 이 글이 끝까지 쓰는 L 자 다각형의 꼭짓점은
`(0,0)` `(4,0)` `(4,2)` `(2,2)` `(2,4)` `(0,4)` 이고, 그 표를 그렸습니다.

<!--fig:origin-grid-->
![격자 표 — L 자 다각형의 칸마다 안 · 경계 · 밖을 미리 적는다](./figs/origin-grid.svg)

경계 위의 칸은 안으로 셉니다. 이 표의 답은 정본과 같은데, 표의 크기가 좌표 범위의 제곱이에요.

<!--proof:origin-grid-->

| 표를 만드는 범위 | 한 변의 칸 | 칸 수 | 1 비트씩 잡은 바이트 |
| --- | ---: | ---: | ---: |
| L 자 다각형 | 5 | 25 | 4 |
| 좌표 -1,000,000,000 ~ 1,000,000,000 | 2,000,000,001 | 4,000,000,004,000,000,001 | 500,000,000,500,000,001 |

L 자 다각형의 25 칸 가운데 정본과 답이 같은 칸은 25 칸입니다. 좌표 범위 전체의 표는 256 MB(268,435,456 바이트)의 1,862,645,151 배입니다.

<!--/proof-->

**이 방법은 답이 맞는데 표가 안 들어갑니다.** 좌표 범위 전체에서 칸마다 1 비트만 잡아도 표의 둘째 줄처럼
256 MB 를 한참 넘어요. 칸을 채우는 연산도 칸 수만큼이고, 다각형이 바뀌면 표를 통째로 다시 만들어야 합니다. 세 자리가 다 좌표
범위에 매여 있고 꼭짓점 수는 한 번도 나오지 않아요.

표가 커진 까닭은 **모든 점의 답**을 만들었기 때문이고, 과제가 묻는 것은 점 하나입니다. 그 점에서 오른쪽으로
반직선을 뻗어 변과 몇 번 교차하는지 세면 어떻게 되는지 확인합니다. 변 이름은 정본이 변을 보는 순서대로 붙였어요.

<!--proof:origin-ray-->

| 이름 | 질의 점 | 교차하는 변 | 교차 수 | 홀짝 | 답 |
| --- | --- | --- | ---: | --- | --- |
| q1 | (1,1) | e2 | 1 | 홀수 | true |
| q2 | (3,3) | 없다 | 0 | 짝수 | false |
| 아래쪽 안 | (3,1) | e2 | 1 | 홀수 | true |
| 위쪽 바깥 | (3,4) | 없다 | 0 | 짝수 | false |

변 이름은 e6 (0,4)-(0,0) · e1 (0,0)-(4,0) · e2 (4,0)-(4,2) · e3 (4,2)-(2,2) · e4 (2,2)-(2,4) · e5 (2,4)-(0,4) 입니다. 교차 수가 홀수인 점은 2 개이고, 정본이 내부로 답한 점도 2 개입니다.

<!--/proof-->

**교차 수가 홀수인 점만 내부입니다.** 오목한 자리의 `q2` 도, 위쪽 바깥의 점도 같은 규칙으로 갈려서 다각형의
모양을 미리 볼 필요가 없어요. 이 방법은 질의마다 변을 한 번씩만 보고 미리 만들어 두는 것이 없습니다. 이제 정할
것은 **변 하나에서 교차를 어떻게 판정하는가**예요.

| 방법 | 하는 일 | 쓰는 연산 |
| --- | --- | --- |
| 교점의 x 를 구해 비교한다 | 변이 높이 `p_y` 를 지나는 자리의 `x` 를 나눗셈으로 구해 `p_x` 보다 큰지 본다 | 곱 · 나눗셈 · 실수 비교 |
| 부호만 비교한다 | 점이 변의 어느 쪽인지 판정값으로 재고, 변이 위로 가는지와 맞춰 본다 | 곱 · 좌표 비교 |

두 방법을 같은 입력에서 재 봤습니다. 다각형은 꼭짓점 열 개짜리 별이고, 질의 점은 씨앗 20,260,904 로 만든 좌표
쌍 20,000 개예요. 별을 고른 것은 L 자의 변이 전부 축에 나란해서 나눗셈이 언제나 정수로 떨어지기 때문이고,
비스듬한 변이 있어야 두 방법이 만드는 값이 갈립니다.

<!--proof:origin-quotient-->

| 방식 | 배정밀도 곱 | 나눗셈 | 정수가 아닌 값 | 틀린 답 |
| --- | ---: | ---: | ---: | ---: |
| 교점의 x 를 구해 비교한다 | 419,045 | 19,075 | 18,291 | 0 |
| 부호만 비교한다 | 399,970 | 0 | 0 | 0 |

입력은 꼭짓점 열 개짜리 별 하나와 좌표 -240~240 의 질의 점 20,000 개입니다. 좌표를 상한에 붙여 겨냥해 만든 배치에서는 이렇게 됩니다.

| 값 | 나눗셈 | 곱과 부호 |
| --- | ---: | ---: |
| 변 (0,0)-(999999997,1000000000) 이 높이 333,333,333 을 지나는 x | 333,333,332 | 구하지 않는다 |
| 질의 점의 x | 333,333,332 | 333,333,332 |
| 그 자리의 판정값 | — | 1 |
| 다각형 (0,0) (999999997,1000000000) (1000000000,0) 에서 (333333332,333333333) 의 답 | true | false |

별 다섯에서는 나눗셈 쪽이 틀린 답 0 개이고, 겨냥한 배치에서는 질의 1 개를 틀립니다.

<!--/proof-->

별 다섯에서는 두 방법의 답이 같습니다. 갈리는 것은 **만들어지는 값의 종류**예요. 나눗셈 쪽은 정수가 아닌 값을
만들고, 부호 쪽은 하나도 만들지 않습니다. 좌표가 상한에 붙은 배치에서는 그 차이가 답으로 나타나요. 교점의 참값은
질의 점보다 10 억분의 1 만큼 오른쪽인데, 나눗셈은 그 차를 못 담아 두 값을 같다고 보고 교차를 놓칩니다. 곱과
부호는 그 차를 정수 판정값으로 정확히 냅니다. 여기서 관찰한 것은 **교점의 좌표가 아니라 교점이 오른쪽인가
하나만 필요하다**는 것이에요.

지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **반직선 교차 세기**입니다. 묻는 점에서 오른쪽으로 반직선을 뻗고, 변마다 교차인지를
판정값의 부호와 변의 방향으로 가려 홀짝을 뒤집어요. 교차를 어떻게 세는지, 판정 하나를 어떻게 정확히 재는지,
반직선이 꼭짓점을 지날 때 그 꼭짓점을 몇 번 셀지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 반직선 교차 세기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **묻는 점에서 오른쪽으로 뻗은 반직선이 다각형의 변과 교차하는
횟수가 홀수면 내부이고, 점이 변 위에 있으면 그 자리에서 내부입니다.** 이 절은 먼저 반직선 교차가 무엇인지
그림과 값으로 보고, 그 판정을 실현하는 순서대로 네 단계를 설명합니다. 미리 만들어 두는 것이 없어서 네 단계
모두 질의마다, 변마다 해요.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 세 점의 방향 판정 | 변의 두 끝점과 점 `p` 로 판정값 `d` 를 낸다 | — |
| 2단계 변 위 검사 | `d` 가 0 이고 점이 변의 좌표 칸 안이면 그 자리에서 `true` | 1단계의 `d` |
| 3단계 반직선의 높이를 지나는 변 고르기 | 두 끝점이 높이 `p_y` 의 위와 아래로 갈린 변만 남긴다 | 2단계가 거짓일 때만 |
| 4단계 교차를 가려 홀짝 뒤집기 | `d` 의 부호와 변의 방향이 맞으면 `inside` 를 뒤집는다 | 1단계의 `d` · 3단계가 남긴 변 |

#### 먼저 알아 둘 개념 — 반직선 교차

**반직선 교차**는 점 `p` 에서 오른쪽으로 끝없이 뻗은 반직선이 다각형의 변 하나를 가로지르는 것입니다. 식으로
적으면 두 조건이 함께 참인 것이에요. 변의 두 끝점 가운데 하나는 높이 `p_y` 보다 위, 다른 하나는 위가 아니어서
변이 그 높이를 지나고, 변이 그 높이를 지나는 자리의 `x` 가 `p_x` 보다 큽니다. 높이가 `p_y` 와 정확히 같은 끝점은
「위가 아니다」 쪽으로 쳐요. 까닭은 아래 「꼭짓점에서 두 번 세는 모양과의 차이」에서 봅니다.

##### 입력 위의 교차

`q1` = `(1,1)` 의 반직선을 L 자 위에 그렸습니다. 꼭짓점 아래 말은 그 꼭짓점이 높이 1 보다 위인지이고, 변의
머리말은 그 변이 반직선과 무엇을 하는지예요.

<!--fig:build-ray-q1-->
![q1 의 반직선과 L 자의 여섯 변 — 꼭짓점 아래는 높이 1 에 대어 본 자리](./figs/build-ray-q1.svg)

반직선의 높이 1 을 지나는 변은 `e6` 과 `e2` 둘이에요. 두 끝점이 위와 아래로 갈린 변이 그 둘입니다. `e6` 은 그
높이를 점의 왼쪽에서 지나므로 반직선과 만나지 않고, `e2` 는 오른쪽에서 지나서 교차합니다.

##### 교차 하나를 읽는 법

변 하나가 교차인지는 두 물음으로 읽습니다. 두 끝점의 높이가 `p_y` 를 사이에 두는가, 그렇다면 그 높이의 `x` 가
`p_x` 보다 큰가예요. `q1` 에서 여섯 변을 읽었습니다. 셋째 열의 두 수는 앞 끝점과 뒤 끝점의 높이입니다.

<!--proof:build-read-->

| 변 | 두 끝점 | 두 끝점의 높이 | 높이 1 | 그 높이의 x | x = 1 에서 본 자리 | 반직선과 |
| --- | --- | --- | --- | ---: | --- | --- |
| e6 | (0,4)-(0,0) | 4 · 0 | 지난다 | 0 | 왼쪽 | — |
| e1 | (0,0)-(4,0) | 0 · 0 | 안 지난다 | — | — | — |
| e2 | (4,0)-(4,2) | 0 · 2 | 지난다 | 4 | 오른쪽 | 교차 |
| e3 | (4,2)-(2,2) | 2 · 2 | 안 지난다 | — | — | — |
| e4 | (2,2)-(2,4) | 2 · 4 | 안 지난다 | — | — | — |
| e5 | (2,4)-(0,4) | 4 · 4 | 안 지난다 | — | — | — |

q1 (1,1) 의 반직선과 교차하는 변은 1 개이고, 정본의 답은 true 입니다.

<!--/proof-->

`e2` 를 따라가 보면 두 끝점의 높이가 0 과 2 라 높이 1 을 사이에 두고, 그 높이의 `x` 는 4 라 `p_x` = 1 보다
오른쪽입니다. 그래서 교차예요. `e4` 는 두 끝점이 2 와 4 로 둘 다 1 보다 위라 볼 것이 없습니다.

##### 교차끼리의 관계

반직선을 점에서 오른쪽으로 따라가면 교차할 때마다 **안에서 밖으로, 또는 밖에서 안으로** 넘어갑니다. L 자 왼쪽
바깥에 점 둘 `r1` = `(-1,1)` 과 `r2` = `(-1,3)` 을 두고, 반직선을 교차하는 자리에서 끊어 조각마다 안팎을
적었어요.

<!--fig:build-alternate-->
![반직선 위의 조각 — 교차할 때마다 안과 밖이 바뀐다](./figs/build-alternate.svg)

조각의 안팎을 교차 순서대로 읽으면 이렇습니다.

<!--proof:build-alternate-->

| 점 | 좌표 | 정본의 답 | 교차하는 x | 점에서 오른쪽으로 가며 지나는 조각 |
| --- | --- | --- | --- | --- |
| r1 | (-1,1) | false | 0 · 4 | 밖 → 안 → 밖 |
| r2 | (-1,3) | false | 0 · 2 | 밖 → 안 → 밖 |

두 점 모두 교차할 때마다 조각이 안과 밖을 번갈아 오가고, 마지막 조각은 밖입니다.

<!--/proof-->

이웃한 두 조각은 언제나 안팎이 반대이고, 사이에 교차가 하나 있습니다. 가장 오른쪽 조각은 다각형의 모든
꼭짓점보다 오른쪽까지 가므로 언제나 밖이에요. 그러니 점이 있는 첫 조각의 안팎은 **그 뒤에 교차가 몇 번
있는가**의 홀짝이 정합니다.

##### 꼭짓점에서 두 번 세는 모양과의 차이

처음 떠올리기 쉬운 모양은 「변의 높이 구간 `[min, max]` 가 `p_y` 를 담으면 그 변이 높이를 지난다」입니다.
양 끝을 다 포함하는 닫힌 구간이에요. 반직선이 꼭짓점과 같은 높이를 지나면 그 꼭짓점에 붙은 두 변이 다 이
조건을 통과합니다. 높이 2 에 꼭짓점이 둘 있는 바깥 점 `(5,2)` 를 그렸어요. 변의 머리말은 두 규칙이 그 변을
세는지입니다.

<!--fig:build-vertex-->
![점 (5,2) 의 반직선이 꼭짓점 높이를 지난다 — 변의 머리말은 두 규칙이 그 변을 세는지](./figs/build-vertex.svg)

두 규칙을 여섯 변에 나란히 적용했습니다. 정본이 쓰는 규칙은 끝점마다 「`p_y` 보다 위인가」를 묻고 두 답이 다를
때만 세는 것이고, 이것이 아래 끝은 넣고 위 끝은 빼는 **반개구간**이에요.

<!--proof:build-rules-->

| 변 | 두 끝점 | 높이 구간 | 닫힌 구간 | 반개구간 | 판정값 | 닫힌 구간의 뒤집기 | 반개구간의 뒤집기 |
| --- | --- | --- | --- | --- | ---: | --- | --- |
| e6 | (0,4)-(0,0) | [0, 4] | 센다 | 센다 | 1 | — | — |
| e1 | (0,0)-(4,0) | [0, 0] | 뺀다 | 뺀다 | 1 | — | — |
| e2 | (4,0)-(4,2) | [0, 2] | 센다 | 뺀다 | -1 | — | — |
| e3 | (4,2)-(2,2) | [2, 2] | 센다 | 뺀다 | 0 | 뒤집는다 | — |
| e4 | (2,2)-(2,4) | [2, 4] | 센다 | 센다 | -1 | — | — |
| e5 | (2,4)-(0,4) | [4, 4] | 뺀다 | 뺀다 | 1 | — | — |

질의 점 (5,2) 에서 닫힌 구간은 4 변을 세어 답이 true 이고, 반개구간은 2 변을 세어 답이 false 입니다. 정본의 답은 false 입니다.

<!--/proof-->

닫힌 구간은 수평 변 `e3` 까지 세고, 그 변의 판정값이 0 이라 뒤집기 조건을 통과해 바깥 점이 안으로 나옵니다.
반개구간은 `e2` 와 `e3` 을 빼서 꼭짓점 `(4,2)` 를 한 번도 세지 않고, `(2,2)` 는 그 위로 가는 `e4` 에서 한 번만
셉니다. 꼭짓점마다 붙은 두 변 가운데 「다른 끝이 위에 있는 변」만 그 꼭짓점을 세는 셈이에요.

##### 홀짝이 안팎을 말하는 까닭

단순 다각형의 경계는 평면을 안과 밖 둘로 가르는 닫힌 선이고, 반직선 위의 조각은 교차할 때만 안팎이 바뀝니다.
반직선의 끝은 모든 꼭짓점보다 오른쪽이라 밖이므로, 점에서 끝까지 교차가 홀수 번이면 점은 안이고 짝수 번이면
밖이에요. 이 모양이 채우는 요구는 둘입니다. 다각형의 모양을 미리 몰라도 되고, 변 하나를 한 번씩만 보면 됩니다.
높이가 `p_y` 와 같은 끝점을 아래로 치는 것은 반직선을 아주 조금 위로 올려 꼭짓점을 비껴가게 한 것과 같아서,
반직선이 꼭짓점을 지나도 「교차할 때만 안팎이 바뀐다」가 그대로 남아요.

#### 1단계 — 세 점의 방향 판정

변의 앞 끝점 `a` 에서 뒤 끝점 `b` 로 가는 벡터와 `a` 에서 `p` 로 가는 벡터의 외적을 계산하고 그 부호만
돌려줍니다.

$$(b_x-a_x)(p_y-a_y)-(b_y-a_y)(p_x-a_x)$$

판정은 **부호가 정확해야** 합니다. 0 을 0 이 아닌 값으로 읽거나 그 반대가 되면 2단계가 변 위의 점을 놓치거나
변 밖의 점을 변 위로 읽고, 부호가 뒤집히면 4단계가 교차를 잘못 가려요. 그래서 판정 하나를 두 겹으로 잽니다.
먼저 배정밀도로 재서 그 절댓값이 `SAFE` 보다 크면 부호를 그대로 쓰고, 아니면 큰 정수로 다시 재요. 네 입력으로
확인했습니다.

<!--proof:build-side-->

| 입력 | 세 점 | 배정밀도 값 | SAFE 2,048 | 부호를 정한 곳 | sideOf |
| --- | --- | ---: | --- | --- | ---: |
| 전개 입력 q1 · e2 | (4,0) → (4,2) → (1,1) | 6 | 못 넘는다 | 큰 정수 | 1 |
| 전개 입력 q2 · e4 | (2,2) → (2,4) → (3,3) | -2 | 못 넘는다 | 큰 정수 | -1 |
| 좌표 상한의 정사각형 | (-1000000000,-1000000000) → (1000000000,-1000000000) → (0,0) | 2,000,000,000,000,000,000 | 넘는다 | 배정밀도 | 1 |
| 겨냥해 만든 배치 | (0,0) → (999999997,1000000000) → (333333332,333333333) | 0 | 못 넘는다 | 큰 정수 | 1 |

넷째 줄은 배정밀도 값이 0 인데 큰 정수로 다시 재면 1 이고, 정본은 뒤엣것의 부호를 돌려줍니다.

<!--/proof-->

앞의 두 줄은 좌표가 작아 값도 작으므로 큰 정수로 다시 잽니다. 셋째 줄은 값이 아주 커서 배정밀도에서 끝나요.
넷째 줄이 두 겹을 두는 까닭입니다. 참값이 1 인데 배정밀도는 두 곱을 같은 값으로 반올림해 0 을 냈어요.
반올림으로 뒤집힐 수 없는 크기가 얼마인지, 곧 `SAFE` 를 왜 2,048 로 두는지는 「수식 정의와 유도」에서 좌표
상한 `C` 로 풉니다.

#### 2단계 — 변 위 검사

판정값이 0 이라는 것은 점이 변을 늘인 **직선** 위라는 뜻까지입니다. 그 점이 두 끝점 사이, 곧 **변** 위인지는
**좌표 칸**이 정해요. 좌표 칸은 변의 두 끝점을 마주 보는 꼭짓점으로 하는 직사각형, 곧 `x` 와 `y` 가 각각 두
끝점 사이인 범위입니다. 네 자리를 재 봤어요.

<!--proof:build-boundary-->

| 자리 | 변 | 점 | 판정값 | 변의 좌표 칸 | 칸 안인가 | 결과 |
| --- | --- | --- | ---: | --- | --- | --- |
| q3 과 e4 | (2,2)-(2,4) | (2,3) | 0 | x [2, 2] · y [2, 4] | 안 | 변 위 |
| (2,5) 와 e4 | (2,2)-(2,4) | (2,5) | 0 | x [2, 2] · y [2, 4] | 밖 | 아니다 |
| (0,0) 과 e6 | (0,4)-(0,0) | (0,0) | 0 | x [0, 0] · y [0, 4] | 안 | 변 위 |
| q1 과 e1 | (0,0)-(4,0) | (1,1) | 1 | x [0, 4] · y [0, 0] | 보지 않는다 | 아니다 |

네 자리 가운데 변 위로 잡힌 것은 2 자리입니다. 판정값이 0 인데 좌표 칸 밖인 둘째 줄은 변 위가 아닙니다.

<!--/proof-->

`(2,5)` 는 `e4` 를 늘인 직선 `x = 2` 위에 있지만 `e4` 의 끝 `(2,4)` 보다 위라 좌표 칸 밖입니다. 판정값이 0 이
아닌 넷째 줄은 직선 밖이라 칸을 볼 까닭이 없어요. 변 위로 잡히면 그 자리에서 답이 `true` 로 정해지고, 남은 변은
보지 않습니다.

#### 3단계 — 반직선의 높이를 지나는 변 고르기

2단계가 거짓인 변만 여기로 옵니다. 두 끝점 각각에 「높이가 `p_y` 보다 위인가」를 묻고, 두 답이 다를 때만 그
변을 남겨요. `q2` = `(3,3)` 에서 여섯 변을 가려 봤습니다.

<!--proof:build-height-->

| 변 | 두 끝점 | 앞 끝 | 앞 끝은 위 | 뒤 끝 | 뒤 끝은 위 | 높이 판정 |
| --- | --- | --- | --- | --- | --- | --- |
| e6 | (0,4)-(0,0) | 4 > 3 | 참 | 0 > 3 | 거짓 | 남긴다 |
| e1 | (0,0)-(4,0) | 0 > 3 | 거짓 | 0 > 3 | 거짓 | 건너뛴다 |
| e2 | (4,0)-(4,2) | 0 > 3 | 거짓 | 2 > 3 | 거짓 | 건너뛴다 |
| e3 | (4,2)-(2,2) | 2 > 3 | 거짓 | 2 > 3 | 거짓 | 건너뛴다 |
| e4 | (2,2)-(2,4) | 2 > 3 | 거짓 | 4 > 3 | 참 | 남긴다 |
| e5 | (2,4)-(0,4) | 4 > 3 | 참 | 4 > 3 | 참 | 건너뛴다 |

q2 (3,3) 의 높이 3 에서 남는 변은 e6 · e4 로 2 개입니다.

<!--/proof-->

`e2` 는 두 끝점이 다 아래라, `e5` 는 두 끝점이 다 위라 건너뜁니다. 수평 변 `e1` · `e3` · `e5` 는 두 끝점의 높이가
같아 두 답이 언제나 같으므로 어떤 `p_y` 에서도 남지 않아요. 수평 변 위의 점은 2단계가 이미 잡았으므로 그래도
빠지는 것이 없습니다.

#### 4단계 — 교차를 가려 홀짝 뒤집기

3단계가 남긴 변은 높이 `p_y` 를 지납니다. 그 자리가 점의 오른쪽인지를 1단계의 판정값으로 가려요. 판정값이
양수라는 것은 점이 변의 **왼쪽**에 있다는 뜻인데, 변이 위로 가는지 아래로 가는지에 따라 「변의 왼쪽」이
가리키는 방향이 반대가 됩니다. 같은 L 자의 변 둘을 점에 대어 본 세 장면을 그렸어요.

<!--fig:build-direction-->
![판정값과 변의 방향 — 두 값이 맞을 때만 교점이 점의 오른쪽이다](./figs/build-direction.svg)

위로 가는 `e2` 는 점이 그 왼쪽(판정값 1)일 때 교점이 점의 오른쪽이고, 아래로 가는 `e6` 은 점이 그
오른쪽(판정값 -1)일 때 교점이 점의 오른쪽이에요. 코드는 이 둘을 한 줄로 적습니다 — 판정값이 양수인가
(`onLeft`)와 변이 위로 가는가(`goesUp`)가 **같으면** 교차예요. 전개 입력에서 높이를 지난 변마다 그 판정과,
판정값과 따로 푼 교점의 `x` 를 나란히 놓았습니다.

<!--proof:build-direction-->

| 질의 | 변 | 가는 방향 | 판정값 | onLeft | goesUp | 홀짝 | 교점의 x 대 점의 x | 교점 |
| --- | --- | --- | ---: | --- | --- | --- | --- | --- |
| q1 | e6 | 아래로 | 1 | 참 | 거짓 | 그대로 | 0 대 1 | 왼쪽 |

높이를 지난 변 5 개 가운데 5 개에서 「두 값이 맞아 뒤집는다」와 「교점이 오른쪽이다」가 함께 참이거나 함께 거짓입니다. 교점의 x 는 판정값과 따로 풀어 적었습니다.

<!--/proof-->

다섯 줄 모두 두 판정이 함께 갑니다. 교차하는 변마다 `inside` 를 한 번 뒤집고, 변을 다 본 뒤의 `inside` 가 답이에요.
이 대응이 모든 변에서 성립한다는 것은 「수식 정의와 유도」가 식으로 보입니다.

#### 이 방법이 기대는 전제

반직선 교차 세기는 아래 네 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 다각형이 단순하다 | 교차할 때마다 안팎이 바뀐다 | 변끼리 가로지르면 안팎이 둘로 안 갈려 홀짝 대신 감긴 횟수를 세는 다른 이야기가 된다 |
| 좌표가 정수다 | 1단계가 0 을 정확히 가린다 | 「변 위인가」가 입력만으로 안 정해지고 허용 오차를 정하는 다른 이야기가 된다 |
| 판정값의 부호가 정확하다 | 2단계의 변 위 · 4단계의 교차 | 0 이 아닌 값을 0 으로 읽으면 변 밖의 점이 변 위가 된다 |
| 경계를 내부로 센다 | 2단계가 그 자리에서 `true` 를 돌려준다 | 경계를 외부로 세는 과제면 2단계의 답을 바꿔야 한다 |

셋째 전제가 깨질 때의 모습은 「수행으로 알아보는 알고리즘」의 첫 짚고 가기에서, 2단계를 빼고 경계를 교차 수에
맡길 때의 모습은 둘째 짚고 가기에서 실행 결과로 봅니다.

#### 높이 판정을 반개구간으로 두는 까닭

높이 판정의 후보는 셋입니다. 양 끝을 다 넣는 닫힌 구간, 양 끝을 다 빼는 열린 구간, 한쪽만 넣는 반개구간이에요.
세 후보를 입력 가족 셋에 넣어 정본과 답이 어긋난 질의 점을 셌습니다. 질의 점은 가족마다 씨앗 20,260,904 로
만든 20,000 개예요.

<!--proof:build-sweep-->

| 입력 가족 | 질의 점 | 닫힌 구간 | 열린 구간 | 반개구간 |
| --- | ---: | ---: | ---: | ---: |
| L 자 · 좌표 -8~8 | 20,000 | 2,012 | 624 | 0 |
| 별 다섯 · 좌표 -240~240 | 20,000 | 53 | 53 | 0 |
| 톱니 여덟 · 좌표 -40~40 | 20,000 | 491 | 284 | 0 |

세 열의 값은 정본과 답이 어긋난 질의 점의 수입니다. 반개구간 열의 합은 0 입니다.

<!--/proof-->

닫힌 구간은 꼭짓점을 두 변에서 세고, 열린 구간은 어느 변에서도 세지 않습니다. 둘 다 반직선이 꼭짓점 높이를
지날 때만 어긋나므로 무작위 입력에서도 가족마다 수십에서 수천 개가 남아요. 반개구간은 세 가족에서 한 번도
어긋나지 않습니다. 경계가 그 높이를 가로지르는 꼭짓점은 붙은 두 변 가운데 정확히 하나가 세고, 두 변이
같은 쪽으로 꺾이는 꼭짓점은 0 번 또는 2 번 세어 홀짝이 그대로이기 때문이에요.

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 이렇습니다.

1. `inside` 를 거짓으로 두고, 마지막 꼭짓점과 첫 꼭짓점을 잇는 변부터 차례로 본다
2. 변의 두 끝점과 `p` 로 판정값 `d` 를 낸다 — 배정밀도로 먼저 재고, 오차 한계 안이면 큰 정수로 확정한다
3. `d` 가 0 이고 `p` 가 그 변의 좌표 칸 안이면 `true` 를 돌려준다
4. 두 끝점의 「`p_y` 보다 위인가」가 같으면 다음 변으로 간다
5. `d` 가 양수인 것과 변이 위로 가는 것이 같으면 `inside` 를 뒤집는다
6. 변을 다 보면 `inside` 를 돌려준다

### 수행으로 알아보는 알고리즘 — L 자 여섯 변에서 질의 셋의 답을 낸다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. L 자 다각형 하나를 잡고 질의 점 셋을 끝까지
판정하되, 조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const L: Point[] = [[0, 0], [4, 0], [4, 2], [2, 2], [2, 4], [0, 4]];
const q1: Point = [1, 1];
const q2: Point = [3, 3];
const q3: Point = [2, 3];
// 이 절이 끝나면 q1 은 true, q2 는 false, q3 은 true 가 나와야 한다
```

왜 하필 이 셋일까요? 답을 내는 갈래가 서로 달라서예요 — `q1` 은 교차 수가 홀수라 내부이고, `q2` 는 오목한
자리에 있어 한 번도 교차하지 않으며, `q3` 은 변 위라 홀짝을 세기 전에 답이 납니다. 좌표를 4 이하로 둔 것도
까닭이 있어요. 그 크기에서는 판정이 전부 큰 정수로 다시 재는 쪽으로 가서, 두 겹 가운데 뒤 겹이 실제로
실행됩니다. 앞 겹은 좌표가 큰 입력을 따로 넣어 봐요. 절차 전체는 이렇습니다.

```text
pointInPolygon(p, polygon):
    inside ← false
    변 (a, b) 마다:
        d ← sideOf(a, b, p)
        d = 0 이고 p 가 변의 좌표 칸 안이면 true 를 돌려준다      ③
        a 와 b 의 「py 보다 위인가」 가 같으면 다음 변으로       ④
        (d > 0) = (b 가 a 보다 위) 이면 inside 를 뒤집는다       ⑤
    inside 를 돌려준다                                           ⑥

sideOf(o, a, b):
    외적을 배정밀도로 재서 절댓값이 SAFE 보다 크면 그 부호    ①
    아니면 큰 정수로 다시 재서 그 부호                        ②
```

#### 1. 방향 판정 하나를 만든다

첫 조각은 1단계입니다. 세 점을 받아 회전 방향의 부호를 돌려주되, 값을 두 겹으로 잽니다.

```ts
const SAFE = 2048;

function sideOf(o: Point, a: Point, b: Point): number {
  const ux = a[0] - o[0];
  const uy = a[1] - o[1];
  const vx = b[0] - o[0];
  const vy = b[1] - o[1];
  // ① 먼저 배정밀도로 재고, 값이 오차 한계보다 크면 그 부호를 그대로 쓴다.
  const approx = ux * vy - uy * vx;
  if (approx > SAFE || approx < -SAFE) return approx > 0 ? 1 : -1;
  // ② 오차 한계 안이면 부호를 못 믿는다. 큰 정수로 다시 재서 확정한다.
  const exact = BigInt(ux) * BigInt(vy) - BigInt(uy) * BigInt(vx);
  return exact > 0n ? 1 : exact < 0n ? -1 : 0;
}
```

변 하나에 이 함수를 부를 때는 세 자리에 **변의 앞 끝점 · 변의 뒤 끝점 · 질의 점**을 넣습니다. 앞 겹인 `①` 을 이
글은 **걸러내기**라고 부릅니다 — 부호가 확실한 판정을 큰 정수로 다시 재는 쪽에서 걸러내는 자리라서예요. 세
질의가 실제로 부르는 판정을 전부 실행하면 이렇게 나옵니다.

<!--proof:walk-side-->

| 질의 | 변 | 호출 | 배정밀도 값 | 끝난 곳 | 돌려준 값 |
| --- | --- | --- | ---: | --- | ---: |
| q1 | e6 | sideOf((0,4), (0,0), (1,1)) | 4 | ② | 1 |
| q1 | e1 | sideOf((0,0), (4,0), (1,1)) | 4 | ② | 1 |
| q1 | e2 | sideOf((4,0), (4,2), (1,1)) | 6 | ② | 1 |
| q1 | e3 | sideOf((4,2), (2,2), (1,1)) | 2 | ② | 1 |
| q1 | e4 | sideOf((2,2), (2,4), (1,1)) | 2 | ② | 1 |
| q1 | e5 | sideOf((2,4), (0,4), (1,1)) | 6 | ② | 1 |
| q2 | e6 | sideOf((0,4), (0,0), (3,3)) | 12 | ② | 1 |
| q2 | e1 | sideOf((0,0), (4,0), (3,3)) | 12 | ② | 1 |
| q2 | e2 | sideOf((4,0), (4,2), (3,3)) | 2 | ② | 1 |
| q2 | e3 | sideOf((4,2), (2,2), (3,3)) | -2 | ② | -1 |
| q2 | e4 | sideOf((2,2), (2,4), (3,3)) | -2 | ② | -1 |

| q3 | e2 | sideOf((4,0), (4,2), (2,3)) | 4 | ② | 1 |
| q3 | e3 | sideOf((4,2), (2,2), (2,3)) | -2 | ② | -1 |
| q3 | e4 | sideOf((2,2), (2,4), (2,3)) | 0 | ② | 0 |

배정밀도 값의 절댓값은 가장 커도 12 라 SAFE 2,048 을 넘지 못하고, 판정 17 번 가운데 17 번이 ② 에서 끝났습니다.

<!--/proof-->

`①` 은 이 입력에서 한 번도 참이 되지 않아 모든 판정이 `②` 로 갑니다. `①` 이 참이 되는 입력은 좌표가 큰 입력이고,
1단계의 표 셋째 줄이 그 자리였어요. `q3` 의 판정이 다섯 번뿐인 것은 다섯째 변에서 답이 나서입니다.

#### 짚고 가기 — 곱을 배정밀도로 끝내도 될 것 같다

여기서 헷갈리기 쉬운 자리는 판정의 산술입니다. 「좌표가 정수이고 곱셈도 정수끼리 하니 부호가 틀릴 일이
없겠다」로 읽기 쉬워요. 그 생각대로 `②` 를 없애고 배정밀도 곱 하나로만 끝내 봅시다.

```ts
const approx = ux * vy - uy * vx;
return approx > 0 ? 1 : approx < 0 ? -1 : 0;   // 큰 정수로 다시 재는 자리를 없앴다
```

세 배치로 확인해 봅니다.

<!--proof:pause-float-->

| 배치 | 질의 점 | 정본 | 배정밀도 곱만 쓴 답 | 대조 |
| --- | --- | --- | --- | --- |
| 전개 입력 q1 | (1,1) | true | true | 같다 |
| 좌표 상한의 정사각형 | (0,0) | true | true | 같다 |
| 겨냥해 만든 배치 · 좌표 상한 | (333333332,333333333) | false | true | 어긋난다 |

셋째 줄의 변 (0,0)-(999999997,1000000000) 에서 점 (333333332,333333333) 을 두 방식으로 재면 이렇습니다.

| 항 | 큰 정수로 | 배정밀도로 |
| --- | ---: | ---: |
| 앞의 곱 ux · vy | 333,333,332,000,000,001 | 333,333,332,000,000,000 |
| 뒤의 곱 uy · vx | 333,333,332,000,000,000 | 333,333,332,000,000,000 |
| 둘의 차 | 1 | 0 |

두 곱은 각각 9,007,199,254,740,991 보다 커서 배정밀도에서 같은 값으로 반올림됩니다. 배정밀도는 차를 0 으로 내서 점이 변 위라고 답하고, 큰 정수는 1 을 내서 왼쪽이라고 답합니다.

<!--/proof-->

**앞의 두 줄은 답이 같습니다.** 전개 입력도, 좌표를 상한까지 키운 정사각형도 이 변이로 답이 안 바뀌어요.
좌표가 작거나 판정값의 절댓값이 크면 배정밀도로 잰 부호가 맞기 때문입니다. 그럼에도 고치는 까닭은 셋째
줄이에요. 참값이 1 인 판정을 배정밀도가 0 으로 내면 그 점이 변 위인 것으로 읽혀, 외부가 내부로 뒤집힙니다.
좌표의 차가 `2C` 까지 커지면 곱이 `4C²` 까지 커지고, 그 크기의 배정밀도 수는 이웃한 정수를 구별하지 못해요.

#### 2. 점이 변 위에 있는지 먼저 가른다

둘째 조각은 2단계입니다. 판정값이 0 인 변에서만 좌표 칸을 봅니다.

```ts
function inBox(a: Point, b: Point, p: Point): boolean {
  return (
    Math.min(a[0], b[0]) <= p[0] && p[0] <= Math.max(a[0], b[0]) &&
    Math.min(a[1], b[1]) <= p[1] && p[1] <= Math.max(a[1], b[1])
  );
}

// ③ 점이 변 위에 있으면 그 자리에서 참이다.
if (d === 0 && inBox(a, b, p)) return true;
```

`③` 이 참이 되는 자리를 세 질의에서 찾으면 `q3` 의 `e4` 하나입니다. 그 자리의 세 검사가 이렇게 나와요.

<!--proof:walk-boundary-->

| 검사 | 식 | 결과 |
| --- | --- | ---: |
| 판정값 | sideOf((2,2), (2,4), (2,3)) | 0 |
| 칸의 x | 2 ≤ 2 ≤ 2 | 참 |
| 칸의 y | 2 ≤ 3 ≤ 4 | 참 |

③ 이 참이 된 질의는 q3 하나이고, 그 자리는 반복문이 6 변 가운데 5 번째로 보는 변 e4 입니다. 남은 변 1 개는 보지 않습니다.

<!--/proof-->

#### 짚고 가기 — 변 위의 점은 홀짝 세기가 알아서 잡을 것 같다

여기서 헷갈리기 쉬운 자리는 경계입니다. 「경계도 다각형의 일부이니 교차 수가 알아서 홀수로 나오겠다」로 읽기
쉬워요. 그 생각대로 `③` 을 없애 봅시다.

```ts
if (d === 0 && inBox(a, b, p)) return true;   // 이 줄을 지웠다
```

네 입력으로 확인해 봅니다.

<!--proof:pause-boundary-->

| 배치 | 질의 점 | 정본 | 변 위 판정을 뺀 답 | 대조 |
| --- | --- | --- | --- | --- |
| 전개 입력 q3 · 변 위 | (2,3) | true | false | 어긋난다 |
| 꼭짓점 위 | (0,0) | true | false | 어긋난다 |
| 아래 변 위 | (2,0) | true | true | 같다 |
| 전개 입력 q1 · 내부 | (1,1) | true | true | 같다 |

격자 0~4 의 점 25 개 가운데 변 위인 점이 16 개이고, 그중 13 개에서 답이 틀립니다.

<!--/proof-->

**셋째 줄은 답이 같습니다.** 아래 변 위의 점 `(2,0)` 은 홀짝 세기만으로도 `true` 가 나와요. 그런 자리가 있어서 이
결함은 시험 몇 개로는 잡히지 않을 수 있습니다. 같은 「경계 위」인데 홀짝이 갈리는 모습을 셋째 줄까지 세 점에서
적었어요.

<!--proof:pause-boundary-why-->

| 배치 | 질의 점 | 홀짝을 뒤집은 변 | 뒤집은 횟수 | 홀짝만의 답 |
| --- | --- | --- | ---: | --- |
| 아래 변 위 | (2,0) | e2 | 1 | true |
| 전개 입력 q3 · 변 위 | (2,3) | 없다 | 0 | false |
| 꼭짓점 위 | (0,0) | e6 e2 | 2 | false |

`(2,0)` 은 오른쪽 벽 `e2` 와 한 번 교차해서 홀수가 나옵니다. `(2,3)` 은 위 팔의 벽 `e4` 위에 있는데 그 오른쪽에
교차할 변이 없어 짝수예요. 꼭짓점 `(0,0)` 은 판정값이 0 인 `e6` 까지 교차로 세어 `e2` 의 뒤집기와 상쇄됩니다.
경계 위의 점은 교차 수로 세는 것이 아니라 따로 물어야 해요.

#### 3. 반직선의 높이를 지나는 변만 골라 홀짝을 뒤집는다

셋째 조각이 3단계와 4단계입니다. 두 끝점 각각에 「높이가 `py` 보다 위인가」를 묻고, 답이 다른 변만 남긴 다음,
그 자리가 오른쪽인지를 판정값의 부호와 변의 방향으로 봅니다.

```ts
// ④ 아래 끝은 포함하고 위 끝은 빼서, 반직선의 높이를 지나는 변만 남긴다.
const aboveA = a[1] > py;
const aboveB = b[1] > py;
if (aboveA === aboveB) continue;
// ⑤ 교점이 점의 오른쪽이면 안팎이 뒤집힌다.
const onLeft = d > 0;
const goesUp = b[1] > a[1];
if (onLeft === goesUp) inside = !inside;
```

여기서 가장 중요한 줄은 `if (onLeft === goesUp) inside = !inside;` 입니다. 두 값을 맞춰 보는 이 한 줄이 「변의
왼쪽」과 「반직선의 오른쪽」을 잇는 자리예요. 세 질의에서 `④` 를 통과한 변마다 네 값을 적으면 이렇습니다.

<!--proof:walk-cross-->

```text
q1   e6  aboveA true   aboveB false  onLeft true   goesUp false  →  그대로
q1   e2  aboveA false  aboveB true   onLeft true   goesUp true   →  inside 를 뒤집는다
q2   e6  aboveA true   aboveB false  onLeft true   goesUp false  →  그대로
q2   e4  aboveA false  aboveB true   onLeft false  goesUp true   →  그대로
q3   e6  aboveA true   aboveB false  onLeft true   goesUp false  →  그대로
```

#### 짚고 가기 — 높이 구간의 양 끝을 다 세도 될 것 같다

여기서 헷갈리기 쉬운 자리는 높이 판정의 경계입니다. 「변의 높이 구간이 `py` 를 담으면 그 변은 반직선의 높이를
지난다」로 읽기 쉬워요. 그 생각대로 반개구간을 닫힌 구간으로 바꿔 봅시다.

```ts
if (!(Math.min(a[1], b[1]) <= py && py <= Math.max(a[1], b[1]))) continue;   // ④ 를 닫힌 구간으로 바꿨다
```

세 배치로 확인합니다.

<!--proof:pause-closed-->

| 배치 | 질의 점 | 정본 | 닫힌 구간으로 센 답 | 대조 |
| --- | --- | --- | --- | --- |
| 꼭짓점 높이의 바깥 점 | (5,2) | false | true | 어긋난다 |
| 꼭짓점 높이의 안쪽 점 | (1,2) | true | true | 같다 |
| 전개 입력 q1 | (1,1) | true | true | 같다 |

좌표 -8~8 의 질의 점 20,000 개 가운데 2,012 개에서 답이 틀리고, 꼭짓점과 높이가 같은 점은 3,453 개입니다.

<!--/proof-->

**둘째 줄은 답이 그대로입니다.** 닫힌 구간이 반개구간보다 더 뒤집은 변을 두 점에서 세어 봤어요.

<!--proof:pause-closed-inner-->

| 질의 점 | 닫힌 구간만 더 뒤집은 변 | 더 뒤집은 수 | 홀짝 | 닫힌 구간의 답 |
| --- | --- | ---: | --- | --- |
| (5,2) | e3 | 1 | 바뀐다 | true |
| (1,2) | e2 · e3 | 2 | 그대로 | true |

안쪽 점 `(1,2)` 에서는 닫힌 구간이 `e2` 와 `e3` 을 더 뒤집는데, 더 뒤집은 수가 둘이라 짝수여서 홀짝이 되돌아와요.
바깥 점 `(5,2)` 는 `e3` 하나만 더 뒤집어 홀짝이 바뀝니다. 「먼저 알아 둘 개념」의 꼭짓점 그림이 그 자리였어요.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 반복문의 첨자 둘뿐이에요 — `prev` 가 앞
꼭짓점, `at` 이 뒤 꼭짓점이고, 첫 바퀴에서 `prev` 가 배열의 마지막 자리를 가리켜 마지막 꼭짓점과 첫 꼭짓점을
잇는 변이 저절로 들어갑니다.

```ts
export type Point = [number, number];

const SAFE = 2048;

export function sideOf(o: Point, a: Point, b: Point): number {
  const ux = a[0] - o[0];
  const uy = a[1] - o[1];
  const vx = b[0] - o[0];
  const vy = b[1] - o[1];
  // ① 먼저 배정밀도로 재고, 값이 오차 한계보다 크면 그 부호를 그대로 쓴다.
  const approx = ux * vy - uy * vx;
  if (approx > SAFE || approx < -SAFE) return approx > 0 ? 1 : -1;
  // ② 오차 한계 안이면 부호를 못 믿는다. 큰 정수로 다시 재서 확정한다.
  const exact = BigInt(ux) * BigInt(vy) - BigInt(uy) * BigInt(vx);
  return exact > 0n ? 1 : exact < 0n ? -1 : 0;
}

/** 점 `p` 가 `a`·`b` 두 끝점이 만드는 좌표 칸 안에 있는가. */
function inBox(a: Point, b: Point, p: Point): boolean {
  return (
    Math.min(a[0], b[0]) <= p[0] &&
    p[0] <= Math.max(a[0], b[0]) &&
    Math.min(a[1], b[1]) <= p[1] &&
    p[1] <= Math.max(a[1], b[1])
  );
}

export function pointInPolygon(p: Point, polygon: Point[]): boolean {
  const py = p[1];
  let inside = false;
  for (
    let at = 0, prev = polygon.length - 1;
    at < polygon.length;
    prev = at++
  ) {
    const a = polygon[prev] as Point;
    const b = polygon[at] as Point;
    const d = sideOf(a, b, p);
    // ③ 점이 변 위에 있으면 그 자리에서 참이다.
    if (d === 0 && inBox(a, b, p)) return true;
    // ④ 아래 끝은 포함하고 위 끝은 빼서, 반직선의 높이를 지나는 변만 남긴다.
    const aboveA = a[1] > py;
    const aboveB = b[1] > py;
    if (aboveA === aboveB) continue;
    // ⑤ 교점이 점의 오른쪽이면 안팎이 뒤집힌다.
    const onLeft = d > 0;
    const goesUp = b[1] > a[1];
    if (onLeft === goesUp) inside = !inside;
  }
  // ⑥ 변을 다 본 뒤의 홀짝이 답이다.
  return inside;
}
```

<!--proof:final-calls-->

```text
pointInPolygon([1, 1], L)  ->  true
pointInPolygon([3, 3], L)  ->  false
pointInPolygon([2, 3], L)  ->  true
pointInPolygon([0, 0], L)  ->  true
pointInPolygon([5, 1], L)  ->  false
```

### 알아 두면 좋은 개념 — 반개구간 규약

전개에서 높이 판정을 「두 끝점의 `py` 보다 위인가가 다른가」로 적었습니다. 그 한 줄이 하는 일은 **변이 덮는 높이
구간의 한쪽 끝만 포함하는 것**이에요. 아래 끝은 넣고 위 끝은 빼면 구간이 `[아래, 위)` 가 되고, 이렇게 한쪽 끝만
포함하는 구간을 **반개구간**이라고 부릅니다. 경계에 놓인 한 점을 이웃한 두 구간 가운데 정확히 한쪽이 갖게
하려고 정해 두는 약속이 **반개구간 규약**이에요. 높이가 정확히 꼭짓점 높이인 점 `(1,2)` 에서 여섯 변이 그
약속을 어떻게 따르는지 적었습니다.

<!--proof:related-halfopen-->

| 변 | 앞 끝의 높이 | 뒤 끝의 높이 | 앞 끝 | 뒤 끝 | 반개구간 |
| --- | ---: | ---: | --- | --- | --- |
| e6 | 4 | 0 | 위 | 아래이거나 같음 | 센다 |
| e1 | 0 | 0 | 아래이거나 같음 | 아래이거나 같음 | 뺀다 |
| e2 | 0 | 2 | 아래이거나 같음 | 아래이거나 같음 | 뺀다 |
| e3 | 2 | 2 | 아래이거나 같음 | 아래이거나 같음 | 뺀다 |
| e4 | 2 | 4 | 아래이거나 같음 | 위 | 센다 |
| e5 | 4 | 4 | 위 | 위 | 뺀다 |

질의 점 (1,2) 의 높이 2 에 꼭짓점이 (4,2) · (2,2) 로 2 개 있는데, 반개구간이 센 변은 2 개이고 정본의 답은 true 입니다.

<!--/proof-->

높이 2 에 꼭짓점 둘이 있어 `e2` · `e3` · `e4` 셋이 그 높이에 걸쳐 있는데, 반개구간은 그중 `e4` 하나만 셉니다.
함께 세어진 `e6` 은 그 높이를 통째로 가로지르는 변이라 꼭짓점과 상관없어요. 같은 약속이 이 편 밖에서도 같은
이름으로 나옵니다.

| 다시 나오는 자리 | 경계 한 점의 주인 |
| --- | --- |
| 이진 탐색을 `[lo, hi)` 로 적는 구현 | `hi` 는 후보 밖이라 남은 폭이 `hi − lo` 로 바로 나온다 |
| 세그먼트 트리의 마디를 `[l, r)` 로 적는 구현 | 가운데 `m` 은 오른쪽 자식만 가져 두 자식이 겹치지도 비지도 않는다 |
| 시각 구간 `[시작, 끝)` 의 겹침 판정 | 끝 시각은 다음 구간의 것이라 이어 붙는 두 구간이 안 겹친다 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 이 판정을 어떤 과제에 쓰는지, 부호만으로 충분한 이유를 식으로 어떻게 닫는지,
변을 하나씩 볼 때마다 무엇이 참으로 남는지, 질의 하나가 연산을 몇 번 쓰는지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때이고, 네 조건이 코드의 모양을 그대로 정합니다.

| 조건 | 까닭 | 코드에서 |
| --- | --- | --- |
| 다각형이 단순하다 | 변끼리 가로지르면 홀짝 하나로 안팎이 안 갈린다 | 홀짝 `inside` 하나로 답한다 |
| 좌표가 정수다 | 「정확히 변 위인가」가 입력만으로 정해져 부호를 정확히 확정할 수 있다 | 판정값 0 이 「정확히 직선 위」를 뜻한다 |
| 경계를 내부로 센다 | 변 위와 꼭짓점 위를 `true` 로 봐야 변 위 검사가 제 몫을 한다 | 판정값 0 을 버리지 않고 칸으로 가른다 |
| 같은 다각형을 몇 번 안 묻거나 다각형이 계속 바뀐다 | 전처리가 없다는 성질이 그대로 이득이 된다 | 질의마다 변을 처음부터 본다 |

같은 판정을 둘러싼 과제들과 나란히 놓으면 이렇습니다.

| 과제 | 쓰는 방법 | 까닭 |
| --- | --- | --- |
| 점 하나가 다각형 안인가 | 이 절차 | 변마다 곱 둘과 비교 몇으로 끝난다 |
| 같은 다각형에 점을 아주 많이 묻는다 | 높이 구간별 변 표 · 사다리꼴 분해 | 전처리를 한 번 하고 질의마다 보는 변을 줄인다 |
| 볼록 다각형에만 묻는다 | 부채꼴 이진 탐색 | 오목한 자리가 없으면 질의 하나가 `O(log n)` 이다 |
| 다각형 둘이 겹치는가 | 변 쌍마다 교차 판정 + 이 절차 | 변이 안 만나도 하나가 다른 하나 안일 수 있다 |

넷째 줄이 이 절차의 자리를 보여 줍니다. 다각형이 여럿이 되어도 이 판정 자체는 그대로 쓰이고, 바뀌는 것은 **어느
점에 그것을 부를지 고르는 방법**이에요.

#### 문제에서 이것을 떠올리게 하는 단서

지문이나 제약에 보이는 말로 이 절차를 떠올릴지 가릅니다.

| 지문의 말 | 뜻 | 이 절차 |
| --- | --- | --- |
| 「점이 다각형 내부에 있는가」 · 「구역 안에 있는가」 | 판정 그 자체를 묻는다 | 쓴다 |
| 「경계 위도 내부로 본다」 | 변 위 검사를 꼭 둬야 한다 | 쓴다 |
| 「오목한 다각형도 주어진다」 | 볼록 전용 방법을 못 쓴다 | 쓴다 |
| 「꼭짓점은 시계 또는 반시계 어느 쪽이든」 | 방향에 매이지 않는 규칙이 필요하다 | 쓴다 |
| 「좌표가 정수이고 절댓값이 10^9 안팎」 | 부호를 정확히 정해야 한다 | 쓴다 |
| 「다각형이 자기교차할 수 있다」 | 홀짝이 안팎을 말하지 않는다 | 그대로는 안 된다 |
| 「좌표가 실수로 주어진다」 | 「정확히 변 위」가 입력만으로 안 정해진다 | 그대로는 안 된다 |
| 「같은 다각형에 질의가 아주 많다」 | 전처리를 두는 설계가 앞설 수 있다 | 대조가 필요하다 |

마지막 줄이 이 편의 경쟁 설계가 성립하는 자리이고, 그 대조를 아래에서 값으로 합니다.

#### 경쟁 설계와의 대조

이 글의 설계를 **반직선 교차 세기**라 적고, 같은 목표(점이 다각형의 내부이거나 경계 위인지를 정확히 답하는
것)를 노리는 다른 절차로 **높이 버킷**을 세웁니다. 다각형을 한 번 읽어 변을 높이 구간별로 나누어 적어 둔 다음,
질의 점의 높이가 걸리는 구간의 변만 보는 방식이에요. 스캔라인 채우기가 쓰는 변 표와 같은 자료이고, 구간 수는
`⌈√n⌉` 로 둡니다. 두 설계는 **어떤 입력에서도 같은 답**을 냅니다 — 반직선이 교차할 수 있는 변은 전부 그 구간에
들어 있기 때문이에요. 반직선 교차 세기는 질의마다 변 `n` 개를 보고 전처리가 없고, 높이 버킷은 전처리로 변을
구간마다 적어 둔 뒤 질의마다 그 구간의 변만 봅니다.

계수는 이 글의 **기본 연산** 그대로(좌표 읽기 · 배정밀도 곱 · 큰 정수 변환 · 큰 정수 곱 · 좌표 비교 각 1)이고, 높이 버킷의 변 번호 읽기만 1 로 더 셉니다. 기하 갈래의 기본 구성과 달리 방향 판정을 곱과 변환으로 풀어 세고 좌표 읽기를 넣었어요. 메모리는 **추가 칸**으로 셉니다 — 높이 버킷은 구간 칸과 구간마다 적은 변 번호를 세고, 반직선 교차 세기의 1 은 홀짝 칸 하나를 재지 않고 적은 값입니다. 변 하나를 보는 값은 두 설계가
**같은 함수**로 세므로, 갈리는 것은 그 함수를 몇 번 부르는가와 전처리에 드는 값이에요. 벽시계는 재지 않아요 —
실행마다 값이 달라 「일치」를 정의할 수 없습니다. 입력은 다각형 가족 둘과 질의 점 생성식 하나를 고정하고 **질의
수**와 **이빨 높이** `h` 둘만 바꿉니다. 톱니는 이빨 2,048 개가 한 칸씩 올라가며 높이 `h` 를 지나는 다각형(꼭짓점
4,099 개)이고, 원형은 반지름 10^6 의 원 위 4,096 점을 반올림해 이은 다각형이에요. 질의 점은 씨앗 20,260,904 로
만든 좌표 쌍이고 다각형 모양과 상관없이 같은 점을 씁니다. **전개 입력(L 자 여섯 변 · 질의 셋)도 같은 표에
넣었습니다** — 그 크기에서는 계수가 세 자리라 순서가 뒤집히는 자리가 안 나오므로, 생성식으로 규모를 키운 입력을
함께 잽니다.

이빨이 낮으면 변 하나가 구간 하나에만 들어가지만 이빨이 높아지면 여러 구간에 겹쳐 들어가서 전처리도 조회도 함께

**이 절차가 내주는 것은 질의를 많이 받을 때의 기본 연산입니다.** 같은 다각형에 질의를 수천 번 하는 자리라면 높이
버킷이 훨씬 적게 쓰고, 원형처럼 변이 높이에 고르게 흩어진 다각형에서는 질의 한 번부터 그렇습니다. 얻는 것은
**추가 칸 1 개**와 **전처리 0** 이에요 — 다각형이 매번 바뀌는 자리에서는 전처리가 매번 버려지고, 그때는 높이
버킷의 57,410 칸이 그대로 낭비가 됩니다.

### 수식 정의와 유도

반직선은 점 `p` 에서 오른쪽으로 뻗는 수평 반쪽 직선이고, 집합으로 적으면 이렇습니다.

$$R(p) \;=\; \{\,(x,\ p_y)\ :\ x > p_x\,\}$$

높이는 `p_y` 로 고정이고 `x` 는 `p_x` 보다 큰 쪽만 봐요. 변 하나가 이 반직선과 만나는지 보려면 그 변이 높이
`p_y` 를 지나는 자리의 `x` 를 알아야 합니다. 변을 매개변수로 적습니다.

$$E(t) \;=\; a + t\,(b - a), \qquad 0 \le t \le 1$$

| `t` | `E(t)` |
| --- | --- |
| 0 | 앞 끝점 `a` |
| 1 | 뒤 끝점 `b` |
| 0 과 1 사이 | 변 안의 점 |

높이가 `p_y` 가 되는 매개변수는
$t^{*} = (p_y - a_y)/(b_y - a_y)$ 이고, 그때의 `x` 는 이렇습니다.

$$x^{*} \;=\; a_x + \frac{(p_y - a_y)(b_x - a_x)}{b_y - a_y}$$

이 식은 두 자리에서 못 씁니다.

| 자리 | 까닭 | 아래 유도에서 |
| --- | --- | --- |
| 수평 변 | `b_y = a_y` 라 분모가 0 이다 | 높이를 지나는 변만 보므로 이 자리가 안 온다 |
| 나눗셈 | 정수 좌표를 넣어도 실수가 나와 반올림이 끼어든다 | 분모를 곱으로 옮기고 부호만 비교해 정수로 남는다 |

먼저 교차 판정이 쓰는 방향 판정의 식을 정의하고 작은 값에 넣어 봅니다.

$$\operatorname{side}(a,b,p) \;=\; (b_x - a_x)(p_y - a_y) - (b_y - a_y)(p_x - a_x)$$

<!--proof:math-check-->

| 변 | 질의 점 | 식이 낸 값 | 부호 | 점의 자리 |
| --- | --- | ---: | ---: | --- |
| (0,0) → (4,0) | (1,1) | 4 | 1 | 왼쪽 |
| (4,0) → (4,2) | (1,1) | 6 | 1 | 왼쪽 |
| (2,2) → (2,4) | (2,3) | 0 | 0 | 직선 위 |
| (0,4) → (0,0) | (3,3) | 12 | 1 | 왼쪽 |

이 절차가 가져가는 것은 부호 열뿐이고, 셋째 열의 크기는 어느 갈래에서도 쓰이지 않습니다. 코드의 `sideOf` 가
이 값의 부호를 돌려줘요. 이제 **왜 나눗셈이 필요 없는가**를 닫습니다. $x^{*}$ 의 식에서 양변에 `a_x` 를 빼고
`b_y − a_y` 를 곱하면 분수가 사라집니다.

$$(b_y - a_y)\,(x^{*} - a_x) \;=\; (p_y - a_y)(b_x - a_x)$$

등식이라 곱해도 성립합니다. 묻는 것은 $x^{*} > p_x$ 인가예요. 양변에서 $(b_y-a_y)(p_x-a_x)$ 를 빼면 이렇게
옮겨 갑니다.

| 걸음 | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| 분모를 곱한 뒤 | $(b_y-a_y)(x^{*}-a_x)$ | $(p_y-a_y)(b_x-a_x)$ |
| $(b_y-a_y)(p_x-a_x)$ 를 뺀 뒤 | $(b_y-a_y)(x^{*}-p_x)$ | $(p_y-a_y)(b_x-a_x)-(b_y-a_y)(p_x-a_x)$ |
| 오른쪽을 정리한 뒤 | $(b_y-a_y)(x^{*}-p_x)$ | $\operatorname{side}(a,b,p)$ |

오른쪽 둘째 줄의 두 곱을 순서만 바꿔 적으면 정의한 `side` 와 같은 식입니다.

$$(b_y - a_y)\,(x^{*} - p_x) \;=\; \operatorname{side}(a,b,p)$$

그러면 $x^{*} > p_x$ 는 $x^{*} - p_x > 0$ 이고, 이것은 양변을 $b_y - a_y$ 로 나눈 값이 양수라는 것이라 `side` 와
$b_y - a_y$ 의 부호가 **같다**는 것과 동치예요. 반직선의 높이를 지나는 변은 $b_y \ne a_y$ 이므로 나누는 값이
0 이 아닙니다.

$$x^{*} > p_x \iff \operatorname{side}(a,b,p) \cdot (b_y - a_y) > 0$$

```ts
// 식을 그대로 옮긴 조각. 실제 절차는 곱 대신 두 부호가 같은지만 본다.
const meetsOnRight = (side: number, ay: number, by: number): boolean =>
  side * (by - ay) > 0;
```

곱이 양수라는 것은 두 값의 부호가 같다는 뜻이고, `side` 는 이미 `1` · `-1` · `0` 으로 좁혀져 있어요. 그래서 판정값이
양수인가(`onLeft`)와 $b_y > a_y$ 인가(`goesUp`)가 같은지만 보면 곱을 만들지 않아도 됩니다. `side` 가 0 인 자리는
점이 그 변의 직선 위라 교점이 곧 `p` 이고 $x^{*} = p_x$ 인데, 그 자리는 변 위 검사가 먼저 가져갑니다. 입력 가족
셋에서 이 동치를 교점의 `x` 를 정수로 따로 푼 값과 대조했습니다.

<!--proof:math-side-->

| 입력 가족 | 높이를 지난 자리 | 두 조건이 일치한 자리 |
| --- | ---: | ---: |
| 원형 12 · 좌표 -1,200~1,200 | 3,306 | 3,306 |
| 별 다섯 · 좌표 -240~240 | 1,972 | 1,972 |
| 톱니 여덟 · 좌표 -40~40 | 1,198 | 1,198 |

질의 점은 가족마다 2,000 개이고, 판정값이 0 인 자리는 뺐습니다. 6,476 자리 가운데 6,476 자리에서 두 조건이 일치했습니다.

<!--/proof-->

두 번째 유도는 산술 쪽입니다. 판정 하나가 배정밀도에서 얼마나 어긋날 수 있는지를 좌표 상한 `C` 만으로 닫으면,
`SAFE` 를 무엇으로 둬야 하는지가 값으로 나옵니다. 좌표의 차는 `2C` 이하라 곱 하나의 절댓값이 `4C²` 이하이고,
배정밀도의 반올림은 담는 값의 절댓값에 `2^{-53}` 을 곱한 것보다 작아요. 반올림은 세 자리에서 일어납니다.

| 자리 | 담는 값의 절댓값 | 반올림 오차 |
| --- | --- | --- |
| 앞의 곱 `ux · vy` | `4C²` 이하 | `4C² · 2^{-53}` 이하 |
| 뒤의 곱 `uy · vx` | `4C²` 이하 | `4C² · 2^{-53}` 이하 |
| 둘의 차 | `8C²` 이하 | `8C² · 2^{-53}` 이하 |

세 자리의 오차를 더한 것이 판정 하나의 전체 한계예요.

$$\operatorname{err}(C) \;=\; 4C^2 2^{-53} + 4C^2 2^{-53} + 8C^2 2^{-53} \;=\; 16C^2 \cdot 2^{-53} \;=\; \frac{C^2}{2^{49}}$$

`16 = 2^4` 이므로 `2^{-53}` 이 `2^{-49}` 로 줄어듭니다. 판정값의 참값은 언제나 정수라, 이 한계가 1 보다 작으면
배정밀도 값과 참값이 같은 부호 쪽에 남아요. 한계가 1 을 넘는 자리를 찾고 과제의 좌표 상한을 넣었습니다.

<!--proof:math-error-->

| 좌표 상한 C | 오차 한계 C² / 2^49 | 큰 정수 되재기 |
| ---: | ---: | --- |
| 1,000,000 | 0.001776357 | 필요 없다 |
| 10,000,000 | 0.177635684 | 필요 없다 |
| 23,726,566 | 0.999999966 | 필요 없다 |
| 23,726,567 | 1.000000050 | 필요하다 |
| 1,000,000,000 | 1776.356839400 | 필요하다 |

한계가 1 보다 작은 가장 큰 좌표 상한은 23,726,566 이고, 좌표 상한 1,000,000,000 에서 한계는 1776.36 입니다. 정본의 하한 SAFE 는 그보다 큰 2 의 거듭제곱 2,048 이고, 무작위 세 점 300,000 벌에서 잰 실제 최대 편차는 256 이었습니다.

<!--/proof-->

**좌표 상한이 23,726,566 이하인 과제였다면 `②` 를 둘 까닭이 없습니다.** 한계가 1 을 안 넘어 배정밀도 부호가
언제나 참값의 부호이기 때문이에요. 이 과제의 `10^9` 에서는 한계가 1 보다 훨씬 크고, `SAFE` 를 그보다 큰 2 의
거듭제곱으로 두면 「`SAFE` 를 넘긴 값의 부호는 확실하다」가 언제나 참이 됩니다.

### 불변식 — 변을 하나 본 직후 inside 는 지금까지 본 변의 교차 수의 홀짝이다

파트 1 에서 코드가 동작하는 것을 열한 걸음으로 봤습니다. 그런데 그건 세 점에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. **변 하나를 본 직후에 무엇이 참으로 남는지**를 문장으로 세우고, 그 문장이 걸음마다 지켜지는지를
값으로 봅니다.

> 변을 하나 보고 난 직후, `inside` 는 **지금까지 본 변 가운데 반직선과 교차한 변의 수가 홀수인가**와 같습니다.
> 변 위 검사가 참이 되어 그 자리에서 돌려주는 경우는 이 문장 밖이고, 그때는 홀짝과 상관없이 답이 `true` 입니다.

| 절반 | 말하는 것 | 지키는 것 |
| --- | --- | --- |
| 앞 절반 · 홀짝 | 반복문이 끝나기 전에도 `inside` 가 뜻을 가진다 | 변을 다 보면 `inside` 가 교차 수 전체의 홀짝이다 |
| 뒤 절반 · 떼어 둔 자리 | 변 위라 돌려주는 자리는 홀짝의 몫이 아니다 | 경계 위의 점이 홀짝에 맡겨지지 않는다 |

둘이 합쳐져야 「변을 다 보면 `inside` 가 답이다」가 마지막 한 걸음으로 나옵니다. **유지되는 것부터 봅시다.**
이빨 셋짜리 톱니에서 왼쪽 바깥의 점 하나를 잡으면 반직선이 변 넷과 교차하므로, 홀짝이 여러 번 바뀌는 자리를
값으로 확인할 수 있어요.

<!--proof:invariant-states-->

| 본 변 | 두 끝점 | 그 변과 | 여기까지 교차 수 | 홀짝 | inside |
| --- | --- | --- | ---: | --- | --- |
| e9 | (0,-1)-(0,0) | 교차하지 않는다 | 0 | 짝수 | false |
| e1 | (0,0)-(1,3) | 교차한다 | 1 | 홀수 | true |
| e2 | (1,3)-(2,1) | 교차한다 | 2 | 짝수 | false |
| e3 | (2,1)-(3,4) | 교차한다 | 3 | 홀수 | true |
| e4 | (3,4)-(4,2) | 교차하지 않는다 | 3 | 홀수 | true |
| e5 | (4,2)-(5,5) | 교차하지 않는다 | 3 | 홀수 | true |
| e6 | (5,5)-(6,3) | 교차하지 않는다 | 3 | 홀수 | true |
| e7 | (6,3)-(6,-1) | 교차한다 | 4 | 짝수 | false |
| e8 | (6,-1)-(0,-1) | 교차하지 않는다 | 4 | 짝수 | false |

이빨 셋짜리 톱니 9 변에 질의 점 (-1,1) 을 줬고, 정본의 답은 false 입니다. 9 줄 가운데 9 줄에서 홀짝 열이 홀수인 것과 inside 가 true 인 것이 함께 참이거나 함께 거짓입니다.

<!--/proof-->

셋째 줄과 넷째 줄은 반직선이 꼭짓점 `(2,1)` 을 지나는 자리입니다. 그 꼭짓점에 붙은 `e2` 와 `e3` 이 둘 다 다른 끝이
위에 있어 한 번씩, 합쳐 두 번 세어지고 홀짝은 그대로예요. 변 하나를 보는 일이 상태를 바꾸는 갈래는 넷입니다.

| 갈래 | `inside` | 교차 수 |
| --- | --- | --- |
| 변 위다 | 건드리지 않고 돌려준다 | 문장이 떼어 둔 자리다 |
| 높이를 안 지난다 | 그대로 | 그대로 |
| 지나는데 교점이 왼쪽이다 | 그대로 | 그대로 |
| 지나고 교점이 오른쪽이다 | 뒤집는다 | 하나 는다 |

넷 가운데 마지막 하나만 두 값을 함께 바꿉니다. 그래서 둘이 늘 같이 가요. **완전성은 경계에서 봐야 합니다.**
꼭짓점 셋짜리 다각형, 점이 꼭짓점 위인 경우, 수평 변 위와 그 높이의 바깥 점, 좌표가 큰 경우까지 넣어 갈래와
답을 확인합니다.

<!--proof:invariant-edges-->

| 배치 | 질의 점 | 꼭짓점 | 높이를 지나는 변 | 교차하는 변 | 답을 정한 것 | 답 |
| --- | --- | ---: | ---: | ---: | --- | --- |
| 꼭짓점 셋짜리 다각형의 내부 | (1,1) | 3 | 2 | 1 | 홀수 | true |
| 꼭짓점 위 | (1,2) | 3 | 0 | 0 | 변 위 | true |
| 수평 변 위 | (2,1) | 4 | 0 | 0 | 변 위 | true |
| 수평 변의 높이인 바깥 점 | (5,1) | 4 | 0 | 0 | 짝수 | false |
| 좌표가 큰 정사각형의 한가운데 | (0,0) | 4 | 2 | 1 | 홀수 | true |
| 좌표가 큰 정사각형의 꼭짓점 | (500000000,500000000) | 4 | 0 | 0 | 변 위 | true |
| 좌표가 큰 정사각형의 바깥 | (1000000000,0) | 4 | 2 | 0 | 짝수 | false |
| 오목한 자리 | (3,3) | 6 | 2 | 0 | 짝수 | false |

8 배치 모두 변 위 판정과 홀짝 가운데 하나만 답을 정했습니다.

<!--/proof-->

**수평 변이 특수 처리 없이 처리됩니다.** 수평 변은 두 끝점의 높이가 같아 「`py` 보다 위인가」의 답이 언제나 같고,
그래서 높이를 지나는 변으로 안 세어져요. 그 변 위에 점이 있으면 판정값이 0 이 되어 변 위 검사가 먼저 잡습니다.

**이제 깨뜨려 봅시다.** 앞 절반(「교차한 변의 수」)을 지키던 줄은 홀짝을 뒤집을지 정하는 자리 하나입니다.
「판정값이 양수면 점이 왼쪽이니, 그대로 교차로 세면 되겠다」라는 생각으로 방향 보정을 빼 봅니다.

```ts
if (onLeft) inside = !inside;                  // 변이 위로 가는지 보는 자리를 뺐다
```

실행하면 이렇게 갈립니다.

<!--proof:mutant-direction-->

| 배치 | 질의 점 | 정본 | 방향 보정을 뺀 답 | 대조 |
| --- | --- | --- | --- | --- |
| 전개 입력 q1 · 내부 | (1,1) | true | false | 어긋난다 |
| 전개 입력 q2 · 오목한 자리 | (3,3) | false | true | 어긋난다 |
| 아래쪽 안 | (3,1) | true | false | 어긋난다 |

좌표 -8~8 의 질의 점 20,000 개 가운데 3,715 개에서 답이 틀립니다.

<!--/proof-->

**세 줄이 다 뒤집힙니다.** 위로 가는 변에서는 보정을 빼도 같은 조건이라 값이 안 바뀌고, 아래로 가는 변에서만
좌우가 뒤바뀌어요. L 자의 변을 방향으로 나누면 이렇습니다.

<!--proof:mutant-edges-->

| 변의 방향 | L 자의 변 | 변 수 |
| --- | --- | ---: |
| 위로 간다 | e2 (4,0)-(4,2) · e4 (2,2)-(2,4) | 2 |
| 아래로 간다 | e6 (0,4)-(0,0) | 1 |
| 수평 | e1 (0,0)-(4,0) · e3 (4,2)-(2,2) · e5 (2,4)-(0,4) | 3 |

아래로 가는 변은 `e6` 하나이고, 보정을 빼면 그 변이 반직선의 높이를 지나는 질의마다 홀짝이 통째로 반대가 됩니다.
단순 다각형은 한 바퀴 닫히므로 위로 가는 변이 있으면 아래로 가는 변도 반드시 있어서, 어느 다각형에서도 이
변이로 답이 틀리는 자리가 있어요.

### 비용 계산

#### 비용을 세는 과정

질의 하나가 하는 일은 변마다 셋입니다 — 방향 판정 하나, 높이 비교 둘, 그리고 조건이 맞을 때만 붙는 칸 검사와
방향 비교예요. 변 하나를 보면 좌표 읽기 4 · 배정밀도 곱 2 로 시작하고, `②` 로 가면 큰 정수 변환 4 · 큰 정수 곱 2
가 더 붙습니다. 판정값이 0 이면 칸 검사의 좌표 비교 4 가, 변 위가 아니면 높이 비교 2 가, 높이를 지나면 방향 비교
1 이 붙어요. 전개의 걸음으로 가르면 이렇게 나뉩니다.

<!--proof:perf-count-->

| 질의 | 걸음 | 본 변 | ② 로 간 판정 | 칸 검사 | 높이를 지난 변 | 기본 연산 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| q1 | T1~T4 | 6 | 6 | 0 | 2 | 86 |
| q2 | T5~T8 | 6 | 6 | 0 | 2 | 86 |
| q3 | T9~T11 | 5 | 5 | 1 | 1 | 73 |

세 질의의 기본 연산을 더하면 245 입니다.

<!--/proof-->

`T1`\~`T4` 와 `T5`\~`T8` 은 여섯 변을 다 보고, `T11` 은 다섯째 변에서 돌려주므로 본 변의 수가 갈려요. 실제로 본 변의
수를 `k`, `①` 로 끝난 판정의 수를 `f`, 판정값이 0 인 변의 수를 `z`, 변 위라 돌려주면 1 이고 아니면 0 인 값을 `r`,
높이를 지난 변의 수를 `s` 라 하면 질의 하나의 기본 연산은 이렇습니다.

$$14k - 6f + 4z - 2r + s$$

변마다 좌표 읽기 · 배정밀도 곱 · 큰 정수 산술 · 높이 비교가 `4 + 2 + 6 + 2 = 14` 이고, `①` 로 끝난 판정은 큰 정수 산술
6 을 안 쓰며, 돌려주는 변은 높이 비교 2 를 안 씁니다. 전개의 세 질의를 넣었습니다.

<!--proof:perf-formula-->

| 질의 | k | f | z | r | s | 14k − 6f + 4z − 2r + s |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| q1 | 6 | 0 | 0 | 0 | 2 | 86 |
| q2 | 6 | 0 | 0 | 0 | 2 | 86 |
| q3 | 5 | 0 | 1 | 1 | 1 | 73 |

세 줄 모두 총식이 낸 값과 센 값이 같습니다. 변 하나의 기본 연산은 가장 적으면 8(① 로 끝나고 칸 검사와 방향 비교가 없을 때), 가장 많으면 19(② 로 가고 칸 검사와 방향 비교가 다 붙을 때)입니다.

<!--/proof-->

**여기서 센 것은 좌표 읽기와 곱과 비교입니다.** 좌표의 차 뺄셈은 판정마다 정확히 넷, 부호 비교는 변마다 셋
이하, 홀짝 뒤집기는 교차하는 변마다 한 번이라, 셋 다 본 변의 수에 비례해 차수를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축이라 짝지어 적지 않습니다. 이 편은 갈리는
자리가 둘이에요 — 돌려주는 자리가 어디인가와, 다시 재는 판정이 몇 번 붙는가입니다.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** | `O(1)` | `Θ(1)` — 첫 변이 점을 담으면 거기서 끝난다 |
| **평균적인 경우** (입력 분포를 가정하지 않는다) | `O(n)` | `Θ(n)` |
| **최악의 경우** | `O(n)` | `Θ(n)` — 실제로 도달한다 |

최선의 경우가 `Θ(1)` 인 것은 변 위 검사 때문입니다. 점이 첫 변 위에 있으면 그 변 하나만 보고 돌려주므로 나머지
`n − 1` 개를 안 봐요. 점이 외부이거나 경계가 아닌 내부이면 돌려주는 자리가 없어서 `n` 개를 전부 봅니다. `O(n)` 은
기본 연산이 변의 수에 비례하는 값보다 크지 않다는 것만 말하는 상한이고, `Θ(n)` 은 경계가 아닌 점에서 아래로도
그만큼 든다는 것까지 말하는 타이트한 값이에요. 평균은 입력 분포를 정하지 않으면 값이 없어서, 여기서는 「어떤
분포를 가정해도 최선과 최악 사이」라는 뜻으로만 적었습니다.

| 경계 | 말하는 것 | 종류 |
| --- | --- | --- |
| `O(n)` | 기본 연산이 변의 수에 비례하는 값보다 크지 않다 | 상한 |
| `Θ(n)` | 경계가 아닌 점에서는 아래로도 그만큼 든다 | 타이트한 값 |

**총식을 한 번은 정확히 적습니다.** 시간은 기본 연산 `14k − 6f + 4z − 2r + s` 이고, 변 하나당 위의 표의 두 끝
사이입니다. 추가 메모리는 홀짝 하나와 판정 하나가 쓰는 값 몇 개이고, 큰 정수는 판정 하나가 끝나면 버려져요.
큰 정수 곱 하나의 비용은 자릿수 `⌈log₂ C⌉` 에 비례하므로 좌표 상한이 커지면 상수가 커집니다.

$$\text{시간} = \Theta(n) \text{ 기본 연산}, \qquad \text{추가 메모리} = \Theta(1)$$

**보장의 종류는 전부 최악 보장입니다.** 무작위성도, 해시도, 입력 분포 가정도 없어요. 계수를 정하는 연산 셋이
붙는 조건이 전부 입력에서 정해집니다.

| 연산 | 붙는 조건 | 정하는 것 |
| --- | --- | --- |
| 방향 판정 | 본 변마다 하나 | 입력 |
| 다시 재기 | 배정밀도 값이 `SAFE` 이하 | 입력 |
| 칸 검사 | 판정값이 0 인 변 | 입력 |

그래서 같은 점과 같은 다각형을 몇 번 물어도 계수까지 같은 값이 나와요.

#### 최악을 만드는 입력

기본 연산을 변 하나당 가장 많이 쓰는 배치가 무엇인지 재 봤습니다. 「좌표가 상한에 붙으면 최악이다」 같은 통념이
붙기 쉬운 자리라, 모양을 바꿔 가며 실제로 셌어요. 바퀴살 여덟은 원점에서 뻗는 방향 여덟에 점을 둘씩 찍어 이은
다각형이라, 변 열여섯 가운데 여덟이 원점을 지나는 직선 위에 있습니다.

<!--proof:worst-shape-->

| 배치 | 꼭짓점 | 본 변 | ② 로 간 판정 | 칸 검사 | 높이를 지난 변 | 기본 연산 | 변 하나당 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 q1 | 6 | 6 | 6 | 0 | 2 | 86 | 14.33 |
| 원형 64 · 좌표 상한 · 안쪽 | 64 | 64 | 0 | 0 | 2 | 514 | 8.03 |
| 원형 64 · 좌표 상한 · 바깥 | 64 | 64 | 0 | 0 | 2 | 514 | 8.03 |
| 원형 64 · 좌표 64 · 안쪽 | 64 | 64 | 64 | 0 | 2 | 898 | 14.03 |
| 별 열여섯 · 좌표 64 · 오목한 자리 | 32 | 32 | 32 | 0 | 2 | 450 | 14.06 |
| 톱니 서른둘 · 좌표 64 · 안쪽 | 67 | 67 | 67 | 2 | 6 | 952 | 14.21 |
| 바퀴살 여덟 · 좌표 3 · 한가운데 | 16 | 16 | 16 | 8 | 2 | 258 | 16.13 |

변 하나당 기본 연산이 가장 많은 배치는 「바퀴살 여덟 · 좌표 3 · 한가운데」 로 16.13 이고, 가장 적은 배치는 「원형 64 · 좌표 상한 · 안쪽」 으로 8.03 입니다. 기본 연산 총량이 가장 큰 배치는 「톱니 서른둘 · 좌표 64 · 안쪽」 으로 952 입니다.

<!--/proof-->

**「좌표가 크면 최악이다」는 이 절차에서 거짓입니다.** 좌표를 상한 가까이 키운 원형 다각형이 표에서 변 하나당
기본 연산이 가장 적어요 — 판정이 전부 `①` 에서 끝나 다시 재는 일이 0 번이기 때문입니다. 값을 키우는 것은 좌표의
크기가 아니라 **판정값이 작거나 0 인 배치**예요.

| 최악을 재는 축 | 그 축을 키우는 입력 | 까닭 |
| --- | --- | --- |
| 다시 재는 판정의 비율 | 좌표의 절댓값이 작은 다각형 | 판정값이 `SAFE` 를 못 넘어 판정마다 `②` 로 간다 |
| 칸 검사의 수 | 점이 여러 변의 직선 위에 있는 배치 | 판정값이 정확히 0 인 변마다 칸 검사가 붙는다 |
| 본 변의 수 | 점이 어느 변 위에도 없는 배치 | 돌려주는 자리가 없어 `n` 개를 다 본다 |

세 축의 최악이 한 입력에서 함께 나오려면 **좌표가 작으면서 점이 여러 변의 직선 위에 있고 어느 변 위도 아닌**
배치여야 합니다. 표의 바퀴살이 그것이고, 시험을 만들 때 그 배치를 빠뜨리면 칸 검사 경로가 거의 안 실행돼요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 점이 다각형 안인지는 **반직선이 변과 교차하는 횟수의 홀짝**
하나로 정해지고, 경계 위의 점만 홀짝을 세기 전에 따로 가르며, 교차를 나눗셈 없이 판정값의 부호로 가리는 것이
이 과제의 진짜 어려움입니다.

| 차례 | 하는 일 | 쓰는 것 |
| --- | --- | --- |
| 방향 판정 | 변마다 판정값 `d` 를 낸다 | 배정밀도, 모자라면 큰 정수 |
| `③` 변 위 검사 | `d` 가 0 이고 칸 안이면 `true` | 좌표 비교 넷 |
| `④` 높이 판정 | 두 끝점의 「위인가」가 다른 변만 남긴다 | 좌표 비교 둘 |
| `⑤` 교차 판정 | `onLeft` 와 `goesUp` 이 같으면 `inside` 를 뒤집는다 | 부호 둘 |
| `⑥` 답 | 변을 다 보면 `inside` | — |

먼저 답이 붙는 문제 하나입니다. 전개의 `T6` 에서 `q2` 는 변 `e1` `e2` `e3` 을 한 묶음으로 건너뛰었어요. `e2` 는
`(4,0)` 에서 `(4,2)` 로 올라가는 변이고 질의 점의 높이는 3 인데, 왜 이 변이 높이를 안 지나는 것으로 잡혔을까요?

<!--check:whyE2Skipped-->
두 끝점이 모두 질의 점보다 **아래**이기 때문입니다. 3단계의 표에서 `e2` 줄의 두 답이 둘 다 거짓이라 같고,
반개구간 규칙은 두 답이 다를 때만 그 변을 남겨요. 변이 덮는 높이 구간 `[0, 2)` 가 3 을 안 담는다는 것을 부등식
둘로 말한 것입니다. 같은 표에서 `e5` 는 두 답이 다 참이라 건너뛰고, `e4` 만 두 답이 갈려 남았어요. `e4` 가
남았지만 그 변은 질의 점의 왼쪽이라 홀짝을 안 건드렸고, 그래서 `q2` 는 교차 수가 0 이고 짝수라 외부입니다.

| 변 | 두 끝점의 자리 | 높이 판정 | 교차 |
| --- | --- | --- | --- |
| `e2` | 둘 다 아래 | 건너뛴다 | — |
| `e5` | 둘 다 위 | 건너뛴다 | — |
| `e4` | 하나만 위 | 남긴다 | 왼쪽이라 아니다 |
<!--/check-->

아래 셋에는 답을 붙이지 않았습니다. 막히면 괄호 안의 절을 다시 보세요.

- 전개의 `T3` 은 변 `e2` 에서 홀짝을 뒤집었고 `T7` 은 변 `e4` 에서 안 뒤집었습니다. 두 변 다 위로 가는 변이고 둘
  다 질의 점의 높이를 지나는데 결과가 갈렸어요. 두 걸음의 판정값을 각각 손으로 계산하고, 그 부호가 「교점이
  오른쪽인가」와 어떻게 이어지는지 부등식으로 적어 보세요. (「수식 정의와 유도」의 부등식 유도)
- 같은 다각형에 질의를 `q` 번 한다고 합시다. 반직선 교차 세기의 총 비용은 `q` 에 비례하고, 높이 버킷은 전처리
  하나에 `q` 번의 조회가 붙어요. 두 비용을 `n` · `q` · 구간 하나에 적히는 변의 평균 수로 식을 세우고, 그 식이
  실측의 뒤집히는 자리(질의 4 회)와 맞는지 확인해 보세요. (「경쟁 설계와의 대조」의 계수 표)
- 질의 점이 다각형의 꼭짓점과 정확히 같은 자리에 있으면 어떤 갈래가 답을 낼까요? 그 꼭짓점에 붙은 두 변 각각에서
  판정값이 무엇이 되는지 적고, 변 위 검사를 뺐을 때 홀짝이 어떻게 나오는지도 함께 구해 보세요. (「수행으로
  알아보는 알고리즘」의 둘째 짚고 가기)

### 점이 다각형 내부인지 판정

풀 파일: [`pointInPolygon.ts`](./pointInPolygon.ts) · 테스트: [`pointInPolygon.test.ts`](./pointInPolygon.test.ts) · 실행: `bun test src/algorithms/geometry/pointInPolygon/pointInPolygon.test.ts`

#### 한 줄 요약

> 점 `p` 와 단순 다각형 `polygon` 이 주어질 때, `p` 가 다각형의 내부 또는 경계 위에 있으면 `true`, 외부이면 `false` 를 반환한다.

#### 스토리

게임 개발팀의 유나는 2D 맵에서 플레이어의 위치가 특정 구역 안에 있는지를 매 프레임마다 판단해야 한다. 구역은 여러 꼭짓점을 직선으로 이어 만든 다각형으로 정의되며, 오목한 형태(L자, 별 모양 등)일 수도 있다.

플레이어가 구역 경계 위에 정확히 올라서 있을 때도 "구역 안"으로 처리해야 한다. 구역을 벗어난 순간만 "외부"로 간주한다.

주어진 점이 다각형 내부 또는 경계에 있는지 판정하는 함수를 만들어라.

#### 함수 인터페이스

```ts
export type Point = [number, number];

export function pointInPolygon(p: Point, polygon: Point[]): boolean;
```

- `p` — 판정할 점. `[x, y]` 형태의 2D 좌표.
- `polygon` — 단순 다각형의 꼭짓점 배열. 각 원소는 `[x, y]`. 마지막 꼭짓점과 첫 번째 꼭짓점이 자동으로 연결된다.
- 반환 — `p` 가 다각형 내부이거나 경계 위에 있으면 `true`, 외부이면 `false`.

#### 제약 조건

- $3 \leq N \leq 10^5$ — 여기서 $N$ 은 꼭짓점 배열의 길이
- $-10^9 \leq x, y \leq 10^9$ — 좌표 범위
- `polygon` 은 자기교차가 없는 단순 다각형 (볼록·오목 모두 가능)
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

점 $p = (x_0, y_0)$ 가 정점 $v_0, v_1, \ldots, v_{n-1}$ 로 이루어진 단순 다각형의 내부 또는 경계에 있는지 판정한다.

- 점이 다각형의 **변 위**에 있으면 `true` 를 반환한다.
- 점이 다각형의 **정점과 동일한 위치**에 있으면 `true` 를 반환한다.
- 점이 다각형 **내부 영역**에 있으면 `true` 를 반환한다.
- 점이 다각형 외부에 있으면 `false` 를 반환한다.
- 다각형이 오목한 모양이어도 올바른 결과를 반환해야 한다. 오목 부분의 빈 공간은 외부로 처리한다.

#### 예시

```ts
const square: Point[] = [[0, 0], [4, 0], [4, 4], [0, 4]];

// 내부
pointInPolygon([2, 2], square); // true — 정사각형 정중앙

// 외부
pointInPolygon([5, 5], square); // false — 오른쪽 위 바깥

// 변 위 — 경계는 내부로 간주
pointInPolygon([2, 0], square); // true — 아랫변 중앙

// 정점 위 — 경계는 내부로 간주
pointInPolygon([0, 0], square); // true — 좌하단 꼭짓점

// 오목 다각형 (L자)
const lShape: Point[] = [[0, 0], [4, 0], [4, 2], [2, 2], [2, 4], [0, 4]];
pointInPolygon([1, 1], lShape); // true — L자 좌하단 내부
pointInPolygon([3, 3], lShape); // false — L자의 오목 부분(파인 공간)은 외부

// 삼각형
const tri: Point[] = [[0, 0], [6, 0], [3, 6]];
pointInPolygon([3, 2], tri); // true — 삼각형 무게중심 근처
pointInPolygon([5, 5], tri); // false — 삼각형 외부 오른쪽
```
