# closestPairOfPoints — 절반으로 가른 뒤 분할선 옆 좁은 띠만 다시 봐도 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 모든 쌍을 비교하는
방법에서 출발해 분할선 띠에 이르고, 분할선 띠를 단계마다 값으로 푼 뒤, 실제로 동작하는 코드를 한 조각씩
만듭니다.

### 전체 컨셉

평면 위의 점 여러 개를 받아 **가장 가까운 두 점 사이의 거리**를 돌려줍니다. 같은 좌표의 점이 둘 있으면 답은
0 이에요. 이 글은 거리를 대부분 **제곱 거리**로 다룹니다. 두 점의 가로 차와 세로 차를 각각 제곱해 더한
수이고, 거리는 그 제곱근입니다. 제곱근은 크기 순서를 바꾸지 않으니 어느 쌍이 더 가까운지는 제곱 거리만으로
정해지고, 좌표가 정수면 제곱 거리도 정수라 비교에 오차가 끼지 않아요. 제곱근은 맨 끝에 한 번만 부릅니다.

절차는 점을 x 좌표 순서로 늘어놓고 가운데에서 세로선을 그어 반으로 가르는 것부터 시작합니다. 그 세로선을
**분할선**이라고 부릅니다. 두 절반을 각각 풀고 나면 남는 것은 두 절반에 한 점씩 걸친 쌍인데, 그중 두 절반이
찾은 거리보다 가까울 수 있는 쌍은 분할선 가까이에만 있어요. 그래서 **분할선에서 가로 거리가 두 절반의 답보다
가까운 점만 남긴 목록**을 따로 만들고, 이것을 **띠**(strip)라고 부릅니다. 이 글이 끝까지 쓰는 점 여덟 개와
맨 위 단계의 분할선 · 띠를 그렸어요. 굵은 테의 두 점이 답이고, 테가 조금 굵은 점이 띠에 든 점입니다.

<!--fig:concept-strip-->
![전개 입력 여덟 점 — 분할선 x = 5 와 그 양옆의 띠, 답인 두 점](./figs/concept-strip.svg)

두 절반은 각각 제곱 거리 8 을 답으로 냈으므로 띠의 폭은 분할선에서 좌우로 √8 이고, 여덟 점 가운데 넷이 띠에
듭니다. 답인 `(3,1)` 과 `(5,2)` 는 서로 다른 절반에 있어서 두 절반만 풀어서는 안 보이고, 띠 안에서 처음
비교됩니다. 이 절차가 여러 배치에서 모든 쌍을 비교한 것과 같은 답을 내는지 먼저 확인해 둡니다.

<!--proof:concept-answer-->

| 배치 | 점 | 모든 쌍 비교의 답 | 분할선 띠의 답 |
| --- | ---: | ---: | ---: |
| 점 둘 | 2 | 5.0000 | 5.0000 |
| 같은 좌표 둘 · 점 넷 | 4 | 0.0000 | 0.0000 |
| 분할선을 가로지르는 답 | 4 | 1.0000 | 1.0000 |
| 전개 입력 | 8 | 2.2361 | 2.2361 |
| 8 × 8 격자 | 64 | 1.0000 | 1.0000 |
| 한 세로줄 위 64 점 | 64 | 1.0000 | 1.0000 |

6 배치 가운데 6 배치에서 두 답이 같습니다. 전개 입력의 답인 두 점 (3,1) 과 (5,2) 는 분할선 x = 5 의 왼쪽 절반과 오른쪽 절반에 하나씩 있습니다.

<!--/proof-->

띠를 y 좌표 순서로 늘어놓으면, 한 점에서 뒤쪽 점을 차례로 비교하다가 세로 차가 두 절반의 답 이상이 되는
자리에서 멈출 수 있습니다. 그 뒤의 점은 세로로만 벌써 더 멀기 때문이에요. 멈추기 전에 비교하는 점이 몇
개로 묶이는 것이 이 절차의 요점이고, 비용을 결과만 적으면 점 `n` 개에 `O(n log n)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **유클리드 거리와 그 제곱.** 두 점의 가로 차와 세로 차를 각각 제곱해 더한 값이 제곱 거리이고, 거리는 그
  제곱근입니다.
- **분할 정복.** 과제를 반으로 갈라 각각을 재귀로 풀고 두 답을 합치는 방식이에요. 같은 뼈대를 정렬에 넣은
  편이 [`sortArray` 가이드](../../sorting/sortArray/sortArray-guide.md)이고, 표의 결정 자리를 좁히는 데 넣은
  편이 [`divideAndConquerDp` 가이드](../../advanced/divideAndConquerDp/divideAndConquerDp-guide.md)입니다.
- **정렬된 두 목록을 합치는 방법.** 두 목록의 앞 칸끼리 비교해 작은 쪽을 하나씩 꺼내면 정렬된 목록 하나가
  됩니다. [`sortArray` 가이드](../../sorting/sortArray/sortArray-guide.md)의 합치기가 그것이에요.
- **안정 정렬.** 비교 기준이 같은 두 원소는 입력의 앞뒤를 그대로 지킵니다. 자바스크립트의 `sort` 가 안정
  정렬이에요.
- **배정밀도 부동소수점 수가 정수를 오차 없이 담는 범위가 정해져 있다는 것.** `number` 는
  `Number.MAX_SAFE_INTEGER` 보다 큰 정수를 반올림해서 담습니다. 좌표가 크면 제곱 거리가 그 범위를 넘어요.
  같은 이야기를 방향 판정에서 다룬 편이 [`convexHull` 가이드](../convexHull/convexHull-guide.md)입니다.

### 아이디어를 떠올리는 과정 — 모든 쌍 비교에서 분할선 띠까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 점 배열을 받아 가장 가까운 두 점
사이의 거리를 돌려줍니다.

```ts
type Point = [number, number];

function closestPairOfPoints(points: Point[]): number;
```

- 입력: 평면 위의 점 배열 하나. 각 원소가 `[x, y]` 이고 순서에 아무 약속이 없습니다. 같은 좌표가 여러 번
  들어올 수 있어요.
- 출력: 가장 가까운 두 점 사이의 유클리드 거리. 0 이상의 부동소수점 수이고, 상대 오차 `10^-9` 안이면 같은
  답으로 봅니다.
- 규모: 이 글은 점 `n` 이 2 개 이상 10 만 개 이하이고 좌표가 절댓값 `10^9` 이하의 정수인 과제로 잽니다. 점
  10 만 개는 흔한 채점 환경의 예산 1 초에 대어 볼 때 점 수의 제곱이 드는 방법과 `n log n` 이 드는 방법이
  뚜렷이 갈리는 규모예요. 좌표 상한을 `10^9` 로 두는 것은 제곱 거리가 배정밀도가 정수를 오차 없이 담는 범위를
  넘게 해서, 값의 크기가 답에 끼치는 영향까지 함께 보려는 것입니다.

비용은 **기본 연산**으로 셉니다. 거리 계산(두 점의 제곱 거리를 만들어 지금까지의 최솟값과 비교한 일)과 좌표
비교(두 점의 좌표끼리, 또는 좌표 차의 제곱과 지금까지의 최솟값을 비교한 일)를 각각 1 로 센 합이고, 격자의
칸에 점을 나눠 담는 방법이 나오면 칸 하나를 찾는 일도 1 로 셉니다. 정렬은 합치기 정렬로 세요. 1 초의 예산은
초당 기본 연산 1 억 번으로 잽니다. 메모리는 **할당 칸**으로 셉니다 — 입력 밖에 배열 칸을 잡을 때마다 더한 누적 합이고, 다 쓰고 버린 칸도 셉니다. 이 글의 비용은 전부 이
두 기준으로 잰 것이에요. 이 글이 쓰는 기호는 열이고, 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `n` | 점의 개수 | 2 이상 `10^5` 이하 |
| `pts` | 재귀 한 번이 맡은 구간 — x 순서 목록의 이어진 한 토막 | 처음에는 점 전부 |
| `mid` | 구간을 가르는 가운데 첨자 | `pts.length >> 1` |
| `splitX` | 분할선의 x 좌표 — `pts[mid]` 의 x | 구간마다 다르다 |
| `best` | 지금까지 찾은 가장 짧은 거리의 **제곱** | 정수 좌표에서 정수다 |
| δ | 띠의 폭 — 두 절반이 낸 `best` 중 작은 쪽의 제곱근 | 식에서만 쓰고 코드에는 이 이름이 없다 |
| `byY` | 그 구간의 점 전부를 y 순서로 담은 목록 | 재귀가 올려 보낸다 |
| `strip` | 띠 — 분할선에서 가로 거리가 δ 보다 가까운 점만 `byY` 에서 뽑은 목록 | y 순서다 |
| `k` | 띠에 든 점의 수 | 그 구간의 점 수 이하 |
| `C` | 좌표의 절댓값 상한 | `10^9` |

가장 먼저 떠오르는 방법은 쌍을 하나도 거르지 않고 전부 재서 가장 작은 것을 고르는 것입니다. 손댈 것이 없고
언제나 맞는 답을 내요.

```ts
function allPairs(points: Point[]): number {
  let best = Number.POSITIVE_INFINITY;
  for (let i = 0; i < points.length; i++) {
    for (let j = i + 1; j < points.length; j++) {
      const dx = points[i][0] - points[j][0];
      const dy = points[i][1] - points[j][1];
      if (dx * dx + dy * dy < best) best = dx * dx + dy * dy;
    }
  }
  return Math.sqrt(best);
}
```

쌍마다 거리 계산을 한 번 하므로 기본 연산은 쌍의 수 `n(n−1)/2` 입니다. 과제의 규모를 넣으면 이렇습니다.

<!--proof:origin-brute-->

| 점 n | 기본 연산 n(n−1)/2 | 시간(초당 1 억 번) |
| ---: | ---: | ---: |
| 8 | 28 | 0.00 초 |
| 1,000 | 499,500 | 0.00 초 |
| 10,000 | 49,995,000 | 0.50 초 |
| 100,000 | 4,999,950,000 | 50.00 초 |

전개 입력 여덟 점을 실제로 모두 비교하면 거리 계산이 28 번이고 다른 기본 연산은 0 번이라, 쌍의 수와 같습니다. 점이 100,000 개면 4,999,950,000 번이고 예산 1 초의 50 배입니다.

<!--/proof-->

아주 멀리 떨어진 두 점도 어김없이 한 번씩 잽니다. 재기 전에 거르려면 점이 자리 순서로 놓여 있어야 하니, x
순서로 정렬해 봅시다. 가장 단순한 후보는 **x 순서로 이웃한 쌍만 비교하기**예요. 이 글이 끝까지 쓰는 점 여덟
개로 해 봅니다.

<!--proof:origin-neighbors-->

| x 순서로 이웃한 두 점 | 제곱 거리 |
| --- | ---: |
| (0,0)–(2,6) | 40 |
| (2,6)–(3,1) | 26 |
| (3,1)–(4,8) | 50 |
| (4,8)–(5,2) | 37 |
| (5,2)–(6,5) | 10 |
| (6,5)–(8,3) | 8 |
| (8,3)–(9,7) | 17 |

이웃한 7 쌍 가운데 가장 가까운 것은 (6,5)–(8,3) 의 제곱 거리 8 이고, 모든 쌍을 비교한 답은 (3,1)–(5,2) 의 5 입니다. 답인 두 점은 x 순서로 2 칸 떨어져 있어 이웃한 쌍에 들지 않습니다.

<!--/proof-->

x 로 가까운 두 점도 y 로는 멀 수 있고, 그 사이에 다른 점이 끼어들 수 있어서 이웃만 보면 답을 놓칩니다. 그러면
이웃 대신 **x 순서로 반씩 갈라** 봅시다. 여덟 점을 넷씩 가르면 쌍은 세 무리가 됩니다 — 왼쪽 넷 안의 쌍,
오른쪽 넷 안의 쌍, 두 절반에 한 점씩 걸친 쌍이에요. 앞의 두 무리는 재귀가 맡고, 걸친 쌍은 전부 재기로 하고
셌습니다.

<!--proof:origin-split-->

| 배치 | 점 | 모든 쌍 비교의 기본 연산 | 가르기만 한 판의 거리 계산 | 가르기만 한 판의 기본 연산 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 8 | 28 | 28 | 40 |
| 균등 256 점 | 256 | 32,640 | 32,640 | 34,372 |
| 균등 1024 점 | 1,024 | 523,776 | 523,776 | 532,712 |

전개 입력에서는 왼쪽 넷 안의 쌍 6 · 오른쪽 넷 안의 쌍 6 · 두 절반에 걸친 쌍 16 을 더해 28 이고, 세 배치 모두 거리 계산이 쌍의 수와 같습니다. 가르려고 정렬하는 좌표 비교가 더해져 기본 연산은 오히려 늘어납니다.

<!--/proof-->

균등 배치는 한 변이 `10^8` 인 정사각형에 고정한 씨앗의 난수로 흩은 점이에요. 쌍 하나는 재귀의 어느 한
단계에서만 걸친 쌍이 되므로, 가르는 것만으로는 한 쌍도 지워지지 않습니다. 줄일 자리는 걸친 쌍 하나로
좁혀졌어요. 여기서 쓸 수 있는 것이 두 절반이 이미 낸 답입니다. 둘 중 작은 쪽을 δ 라 하면 답은 δ 이하이고,
걸친 쌍이 그보다 가까우려면 가로 차부터 δ 보다 작아야 해요. 그러니 두 점 다 분할선에서 가로로 δ 안쪽에 있어야
합니다. 그 안쪽의 점만 남기고 남은 점끼리 쌍을 모두 비교하는 판을, 걸친 쌍을 모두 비교하는 판과 나란히
셌습니다.

<!--proof:origin-band-->

| 배치 | 점 | 걸친 쌍을 모두 비교하는 판 | 띠 안의 쌍을 모두 비교하는 판 |
| --- | ---: | ---: | ---: |
| 균등 1024 점 | 1,024 | 532,712 | 40,669 |
| 균등 4096 점 | 4,096 | 8,430,502 | 218,731 |
| 한 세로줄 위 1024 점 | 1,024 | 528,896 | 1,061,888 |
| 한 세로줄 위 4096 점 | 4,096 | 8,411,136 | 16,842,752 |

점을 4 배로 늘리면 균등 배치에서는 띠 안의 쌍을 모두 비교하는 판이 5.38 배로 늡니다. 한 세로줄 배치에서는 15.86 배로 늘어, 걸친 쌍을 모두 비교하는 판의 15.90 배와 차이가 없습니다.

<!--/proof-->

균등 배치에서는 분할선 가까이에 점이 드물어 비교가 크게 줄었습니다. 그런데 점이 모두 `x = 0` 위에 있는 한
세로줄 배치에서는 모든 점이 분할선 위라 띠가 구간 전체가 되고, 비교가 다시 점 수의 제곱을 따라갑니다. 여기서
관찰한 것은 하나예요. **띠에 점이 몇 개 드는지가 아니라, 띠 안에서 한 점이 몇 개와 비교하는지가 비용을
정합니다.** 한 세로줄 위의 점을 y 순서로 늘어놓으면 이웃한 점끼리만 δ 안쪽이고 나머지는 세로로 멀어요. 띠를
y 순서로 늘어놓고 세로 차가 δ 이상인 자리에서 멈추면, 한 점이 보는 상대가 줄어듭니다. 지금까지 해 본 방법을
차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 다섯 — 넷은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

넷째 방법의 점 10 만 개 값은 4,096 점에서 잰 값을 점 수의 제곱 비로 늘린 **어림**입니다. 위 표에서 점을
4 배로 할 때 16 배 언저리로 는 것이 그 근거예요. 남은 방법에 이름을 붙이면 **분할선 띠**입니다. 점을 x
순서로 한 번 정렬하고 반씩 갈라 두 절반을 재귀로 풀고, 두 절반의 답 δ 를 폭으로 분할선 양옆 띠만 남긴 뒤, 띠를
y 순서로 읽으며 세로 차가 δ 이상이면 멈춰요. 띠가 어떻게 생겼는지, 무엇을 먼저 준비하고 어떤 차례로 푸는지는
다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 분할선 띠

이 아이디어를 한 문장으로 줄이면 이렇습니다. **점을 x 순서로 한 번 정렬해 두고, 구간마다 반으로 갈라 두 절반을
재귀로 푼 뒤, 두 절반이 올려 보낸 y 순서 목록을 합치고, 두 절반의 답 δ 를 폭으로 분할선 양옆 띠만 남겨 y
순서로 읽으며 세로 차가 δ 이상이면 멈춥니다.** 이 절은 먼저 띠가 무엇인지 그림과 값으로 보고, 띠를 실현하는
순서대로 다섯 단계를 설명합니다. 1단계는 입력마다 한 번, 2단계부터 5단계는 재귀가 구간 하나를 맡을 때마다 해요.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 x 순서로 정렬하기 | 점 전부를 x 로 한 번 정렬한다 | — |
| 2단계 반으로 갈라 두 절반 풀기 | 구간을 `mid` 에서 가르고 두 절반을 재귀로 푼다. 점이 셋 이하면 직접 비교한다 | 1단계의 x 순서 목록 |
| 3단계 두 절반의 y 순서 목록 합치기 | 두 절반이 올려 보낸 `byY` 를 합쳐 이 구간의 `byY` 를 만든다 | 2단계가 받은 두 `byY` |
| 4단계 띠 고르기 | 두 절반의 `best` 중 작은 쪽을 δ² 로 잡고, 분할선에서 가로로 δ 안쪽인 점만 `byY` 에서 뽑는다 | 2단계의 두 `best` · 3단계의 `byY` |
| 5단계 띠 안에서 멈추며 비교하기 | 띠를 y 순서로 읽으며 세로 차가 δ 이상이면 멈추고, 그 전까지의 쌍만 비교한다 | 4단계의 띠와 δ² |

#### 먼저 알아 둘 개념 — 띠

띠는 **분할선에서 가로 거리가 δ 보다 가까운 점만 y 순서로 늘어놓은 목록**입니다. 평면에서 보면 분할선을
가운데 두고 폭이 2δ 인 세로 띠 안에 든 점이고, 코드에서는 `(p[0] − splitX)² < best` 인 점 `p` 를 `byY`
에서 차례로 뽑은 `strip` 이에요. 재귀가 구간 하나를 맡을 때마다 새로 만들어지고, 그 구간의 걸친 쌍 가운데 두
절반의 답보다 가까울 수 있는 쌍은 전부 이 목록 안에 있습니다.

##### 입력 위의 띠

전개 입력의 맨 위 단계에서 띠를 그렸습니다. 점 아래 수는 분할선 x = 5 에서 가로 차의 제곱이고, 흐린 대시
테의 점은 띠에 들지 않은 점이에요. 아래 두 줄이 그 단계의 `byY` 와 `strip` 입니다.

<!--fig:build-strip-->
![맨 위 단계의 띠 — 점 아래 수는 분할선 x = 5 에서 가로 차의 제곱](./figs/build-strip.svg)

`byY` 의 여덟 점 가운데 넷이 띠에 듭니다. 띠의 네 점은 `byY` 에서 순서를 지킨 채 뽑혔으므로 `strip` 도 y
순서예요.

##### 띠에 드는 점 하나를 읽는 법

점 하나가 띠에 드는지는 그 점의 가로 차의 제곱과 `best` 하나를 비교해 정합니다. `(3,1)` 이라면 분할선
x = 5 에서 가로 차가 −2 라 제곱이 4 이고, 들어온 `best` 8 보다 작아 띠에 들어요. 제곱근을 부르지 않고 제곱끼리
비교합니다. 여덟 점 전부를 `byY` 의 순서로 적으면 이렇습니다.

<!--proof:build-strip-points-->

| byY 의 점 | y | 가로 차의 제곱 | 띠에 |
| --- | ---: | ---: | --- |
| (0,0) | 0 | 25 | 25 ≥ 8 → 안 든다 |
| (3,1) | 1 | 4 | 4 < 8 → 든다 |
| (5,2) | 2 | 0 | 0 < 8 → 든다 |
| (8,3) | 3 | 9 | 9 ≥ 8 → 안 든다 |
| (6,5) | 5 | 1 | 1 < 8 → 든다 |
| (2,6) | 6 | 9 | 9 ≥ 8 → 안 든다 |
| (9,7) | 7 | 16 | 16 ≥ 8 → 안 든다 |
| (4,8) | 8 | 1 | 1 < 8 → 든다 |

분할선 x = 5 · 들어온 best 8 에서 여덟 점 가운데 4 점이 띠에 들고, 띠는 (3,1) (5,2) (6,5) (4,8) 입니다.

<!--/proof-->

`(8,3)` 과 `(2,6)` 은 가로 차의 제곱이 9 라 8 을 넘어서 빠졌습니다. 둘 다 분할선에서 가로로 3 떨어져 있어,
어느 점과 짝을 지어도 거리가 √8 보다 길어요.

##### 띠 안의 점끼리의 관계

띠 안에서는 한 점이 **자기보다 뒤에 있는 점**하고만, 그것도 앞에서부터 차례로 비교합니다. 뒤로 갈수록 y 가
커지기만 하므로, 세로 차의 제곱이 `best` 이상인 점을 만나면 그 뒤의 점은 세로로만 벌써 더 멀어요. 그 자리에서
멈추고 다음 점으로 넘어갑니다. 맨 위 띠의 네 점을 그렇게 읽은 기록입니다.

<!--proof:build-strip-scan-->

| 두 점 | 세로 차의 제곱 | 그때 best | 판정 | best 뒤 |
| --- | ---: | ---: | --- | --- |
| (3,1)–(5,2) | 1 | 8 | 1 < 8 → 비교, 제곱 거리 5 | 5 |
| (3,1)–(6,5) | 16 | 5 | 16 ≥ 5 → 멈춤 | — |
| (5,2)–(6,5) | 9 | 5 | 9 ≥ 5 → 멈춤 | — |
| (6,5)–(4,8) | 9 | 5 | 9 ≥ 5 → 멈춤 | — |

띠의 4 점을 y 순서로 읽는 동안 비교가 1 번, 멈춤이 3 번이고, best 는 8 에서 5 로 끝납니다.

<!--/proof-->

첫 비교에서 `(3,1)` 과 `(5,2)` 가 5 를 내어 `best` 가 줄었고, 줄어든 `best` 가 뒤의 멈춤을 더 일찍 걸었어요.
띠의 점끼리는 y 순서로 이웃한 몇 개하고만 이어집니다. 그 몇 개가 배치를 바꿔도 늘지 않는지를 실행으로
셌습니다. 띠가 가장 컸을 때의 점 수와, 한 점이 멈추기 전까지 비교한 이웃의 최대 개수예요.

<!--proof:build-neighbors-->

| 배치 | 점 | 가장 큰 띠의 점 수 | 한 점이 비교한 이웃의 최대 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 8 | 4 | 2 |
| 지그재그 여덟 점 | 8 | 5 | 2 |
| 균등 1024 점 | 1,024 | 19 | 2 |
| 균등 4096 점 | 4,096 | 37 | 2 |
| 한 세로줄 위 1024 점 | 1,024 | 1,024 | 0 |
| 한 가로줄 위 1024 점 | 1,024 | 1 | 0 |
| 32 × 32 격자 | 1,024 | 32 | 0 |

띠에는 점이 1,024 개까지 쌓이는데, 한 점이 비교한 이웃은 7 배치 모두 2 개를 넘지 않습니다.

<!--/proof-->

한 세로줄 배치는 띠가 구간 전체인데도 한 점이 비교한 이웃이 0 개입니다. 이웃한 두 점의 세로 차가 1 이고
두 절반의 답도 1 이라, 첫 상대에서 `1 ≥ 1` 로 바로 멈추기 때문이에요. 어떤 배치에서도 한 점이 비교하는
이웃이 7 개를 넘지 못한다는 것은 「수식 정의와 유도」에서 칸 여덟 개로 닫습니다. 띠와 띠 사이의 관계도
하나 있습니다. 아래 단계의 띠가 줄인 `best` 가 위 단계로 올라가 위 단계 띠의 폭을 정해요.

##### x 순서로 늘어놓은 띠와의 차이

처음 떠올리기 쉬운 모양은 **같은 점들을 x 순서 목록에서 뽑은 띠**입니다. 어차피 같은 점이니 손에 들고 있는
x 순서 배열에서 걸러도 될 것 같아요. 코드로는 띠를 뽑는 줄 하나가 바뀝니다.

```ts
  for (const p of pts) {                                   // ←
```

맨 위 단계에서 두 목록으로 띠를 뽑아 읽은 결과와, 같은 판으로 세 배치를 실행한 결과입니다.

<!--proof:build-strip-xorder-->

| 전개 입력의 맨 위 단계 | 띠에 든 점 | 비교한 쌍 | 낸 best |
| --- | --- | ---: | ---: |
| y 순서 목록에서 뽑는다 | (3,1) (5,2) (6,5) (4,8) | 1 | 5 |
| x 순서 목록에서 뽑는다 | (3,1) (4,8) (5,2) (6,5) | 0 | 8 |

같은 판으로 세 배치를 실행하면 이렇게 나옵니다.

| 배치 | 점 | 정본 | x 순서에서 뽑은 답 | 대조 |
| --- | ---: | ---: | ---: | --- |
| 분할선을 가로지르는 답 | 4 | 1.0000 | 1.0000 | 같다 |
| 같은 좌표 둘 · 점 넷 | 4 | 0.0000 | 0.0000 | 같다 |
| 전개 입력 | 8 | 2.2361 | 2.8284 | 어긋난다 |

<!--/proof-->

두 띠는 같은 네 점인데 순서가 다릅니다. x 순서로 늘어놓으면 y 가 1 · 8 · 2 · 5 로 오르내려서, `(3,1)` 다음이
세로 차 7 인 `(4,8)` 이라 첫 상대에서 멈추고 답인 `(5,2)` 를 한 번도 안 봐요. 멈춤 조건은 「뒤로 갈수록 y 가
커지기만 한다」를 전제합니다. 위의 두 배치는 답이 그대로인데, 네 점이 한 가로줄 위라 두 순서가 같거나 띠가
통째로 비어서 전제를 시험할 자리가 없기 때문이에요.

##### 띠가 이렇게 생긴 까닭

띠의 두 성질은 각각 아이디어의 요구 하나씩을 채웁니다. 폭이 δ 인 것은 **놓치면 안 되는 쌍을 다 담기 위해서**예요.
두 절반에 걸친 쌍의 거리가 δ 보다 짧으려면 가로 차가 δ 보다 짧아야 하고, 그러려면 두 점 다 분할선에서 가로로
δ 안쪽이어야 합니다. y 순서인 것은 **멈출 수 있게 하기 위해서**입니다. 폭만으로는 한 세로줄 배치처럼 띠가
구간 전체가 되어도 막을 수 없는데, y 순서가 있으면 세로 차로 멈춰서 띠가 커져도 한 점의 비교가 늘지 않아요.

#### 1단계 — x 순서로 정렬하기

점 전부를 x 로 한 번 정렬합니다. 그러면 목록의 앞쪽 절반은 전부 뒤쪽 절반보다 x 가 작거나 같아서, 가운데 점의
x 에 세운 세로선이 두 절반을 가릅니다. 이 정렬은 x 만 비교하므로 x 가 같은 점끼리는 입력 순서를 그대로 지켜요.
x 가 같은 점이 분할선 양쪽에 나뉘어도 답이 안 바뀌는지, 같은 여섯 점을 입력 순서만 바꿔 모두 넣어 봤습니다.

<!--proof:build-sort-ties-->

| 입력 순서 | 왼쪽 절반 | 오른쪽 절반 | 답 |
| --- | --- | --- | ---: |
| (0,3) (0,0) (4,2) (0,1) (4,6) (0,5) | (0,3) (0,0) (0,1) | (0,5) (4,2) (4,6) | 1.0000 |
| (0,3) (0,0) (4,2) (4,6) (0,5) (0,1) | (0,3) (0,0) (0,5) | (0,1) (4,2) (4,6) | 1.0000 |

같은 여섯 점을 입력 순서 720 가지로 넣었을 때 왼쪽 절반은 24 가지로 갈리지만 답은 1 가지이고, 모든 쌍을 비교한 답 1.0000 과 같습니다.

<!--/proof-->

x 가 0 인 네 점은 입력 순서에 따라 왼쪽 절반과 오른쪽 절반에 다르게 나뉩니다. 그래도 답이 같은 것은 띠가
분할선 **양쪽**의 점을 함께 받기 때문이에요. 분할선 위의 점이 어느 절반에 가든 가로 차가 0 이라 늘 띠에 들고,
띠 안에서 비교됩니다. 볼록 껍질 편은 같은 x 를 y 로 한 번 더 가려 정렬했지만, 이 절차에는 그 둘째 기준이
필요 없어요.

#### 2단계 — 반으로 갈라 두 절반 풀기

1단계의 목록에서 구간 `pts` 를 받아, 가운데 첨자 `mid` 에서 앞 절반과 뒤 절반으로 가르고 `pts[mid]` 의 x 를
분할선 `splitX` 로 둡니다. 두 절반을 같은 절차로 재귀해서 풀고, 점이 셋 이하인 구간은 더 가르지 않고 쌍을
직접 비교해요. 쌍이 많아야 셋이라 전부 재도 되고, 이 구간의 y 순서 목록도 여기서 처음 만들어집니다. 전개
입력이 갈리는 모양을 나무로 그렸어요. 마디마다 그 구간의 분할선과 그 구간이 올려 보내는 `best` 입니다.

<!--fig:build-tree-->
![재귀가 가른 구간 — 마디마다 분할선과 그 구간이 올려 보내는 best](./figs/build-tree.svg)

여덟 점이 넷씩, 넷이 둘씩 갈려 기저가 넷입니다. 구간 크기는 단계마다 절반이 되므로 가르는 단계의 수는 `log₂ n`
을 넘지 않아요. 두 절반이 각각 무엇을 올려 보내는지가 다음 두 단계의 재료입니다 — `best` 는 4단계가, `byY`
는 3단계가 받아요.

#### 3단계 — 두 절반의 y 순서 목록 합치기

두 절반이 올려 보낸 `byY` 는 각자 y 순서이므로, 두 목록의 앞 칸끼리 y 를 비교해 작은 쪽을 하나씩 꺼내면
합친 목록도 y 순서입니다. 다시 정렬하지 않아요. 전개 입력의 맨 위 단계에서 합친 모습입니다.

<!--proof:build-merge-top-->

| 목록 | 점 |
| --- | --- |
| 왼쪽 절반의 byY | (0,0) (3,1) (2,6) (4,8) |
| 오른쪽 절반의 byY | (5,2) (8,3) (6,5) (9,7) |
| 합친 byY | (0,0) (3,1) (5,2) (8,3) (6,5) (2,6) (9,7) (4,8) |

두 목록의 앞 칸끼리 y 를 7 번 비교해 여덟 점을 y 순서로 늘어놓았고, 합친 목록이 y 순서인가를 다시 보면 그렇습니다.

<!--/proof-->

한쪽 목록이 먼저 바닥나면 남은 쪽을 비교 없이 그대로 뒤에 붙이므로, 비교는 많아야 점 수보다 하나 적습니다.
이 단계는 두 입력 목록이 y 순서라는 것에 기댑니다. 기저가 그 순서를 안 만들면 무엇이 성립하지 않는지는
「불변식」에서 값으로 봐요.

#### 4단계 — 띠 고르기

2단계의 두 `best` 중 작은 쪽을 이 구간의 `best` 로 잡습니다. 이것이 δ² 이에요. 그다음 3단계의 `byY` 를
처음부터 읽으며 `(p[0] − splitX)² < best` 인 점만 `strip` 에 담습니다. `byY` 에서 순서대로 뽑으니 띠는 따로
정렬하지 않아도 y 순서예요. 맨 위 단계에서 띠를 고른 값은 「먼저 알아 둘 개념」의 표에 있습니다. 여덟 점을 한
번씩 읽어 좌표 비교가 8 번이고, 넷이 남았어요. 띠의 점 수 `k` 는 그 구간의 점 수를 넘지 않습니다.

#### 5단계 — 띠 안에서 멈추며 비교하기

띠를 앞에서부터 한 점씩 잡고, 그 점보다 뒤의 점을 차례로 봅니다. 세로 차의 제곱이 `best` 이상이면 멈추고,
아니면 제곱 거리를 재서 `best` 보다 작으면 줄여요. 비교하는 도중에 `best` 가 줄면 그 뒤의 멈춤은 줄어든
값으로 겁니다. 맨 위 단계에서 비교 1 번과 멈춤 3 번으로 `best` 가 8 에서 5 가 된 기록이 「먼저 알아 둘
개념」의 둘째 표예요. 이 단계가 끝나면 `best` 는 그 구간 전체의 답이 되고, 3단계의 `byY` 와 함께 위 단계로
올라갑니다.

#### 이 방법이 기대는 전제

분할선 띠는 아래 세 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 두 절반이 올려 보낸 `best` 가 각 절반의 답이다 | 4단계에서 δ 를 정한다 | δ 가 실제보다 크면 비교가 늘고, 오른쪽 절반의 값을 버리면 답 자체를 잃는다 |
| 두 절반의 `byY` 가 y 순서다 | 3단계 합치기와 5단계 멈춤 | 합친 목록과 띠가 y 순서가 아니어서 멈춤이 엉뚱한 자리에서 걸린다 |
| 제곱 거리의 대소 비교가 참값의 대소와 같다 | 4단계 · 5단계의 모든 비교 | 고르는 쌍이 갈릴 수 있다 |

첫째 전제가 깨지는 모습은 「수행으로 알아보는 알고리즘」의 첫 짚고 가기에서, 둘째는 「불변식」의 깨뜨리기에서,
셋째는 「불변식」의 값의 크기에서 실행 결과로 봅니다.

#### 띠의 폭을 δ 로 두는 까닭

폭을 δ 의 몇 배로 두는지가 이 방법이 정하는 값입니다. 0.5 · 1 · 2 · 4 배로 놓고 세 배치에서 답과 기본
연산을 셌어요. 멈춤도 같은 배수로 겁니다.

| --- | ---: | ---: | ---: | --- |

| 8 × 8 격자 | 2 | 1.0000 | 2,020 | 맞는다 |
| 8 × 8 격자 | 4 | 1.0000 | 5,508 | 맞는다 |
| 균등 1024 점 | 0.5 | 32136.7454 | 30,371 | 맞는다 |

<!--/proof-->

폭을 절반으로 좁히면 전개 입력에서 답인 `(3,1)` 이 띠 밖으로 빠져 3.1623 이 나옵니다. 나머지 두 배치에서
0.5 배가 맞은 것은 그 입력에 놓칠 쌍이 없었다는 뜻이지 좁혀도 된다는 근거가 아니에요. 반대로 폭을 두 배 ·
네 배로 넓히면 답은 그대로이고 기본 연산만 늡니다. 놓치지 않는 가장 좁은 폭이 δ 입니다.

#### y 순서를 합치기로 얻는 까닭

띠를 y 순서로 만드는 길은 둘입니다. 구간마다 그 자리에서 y 로 다시 정렬하거나, 두 절반이 올려 보낸 목록을
합치거나예요. 띠가 구간 전체가 되도록 한 세로줄에 y 를 뒤섞어 놓은 배치로 두 판의 기본 연산을 세고, 그 값을
`n log₂ n` 으로 나눴습니다.

<!--proof:build-resort-->

| 점 | 다시 정렬하는 판 | 합치기만 하는 판 | 다시 정렬 ÷ n log₂ n | 합치기 ÷ n log₂ n |
| ---: | ---: | ---: | ---: | ---: |
| 1,024 | 69,544 | 33,284 | 6.79 | 3.25 |
| 4,096 | 381,717 | 161,589 | 7.77 | 3.29 |
| 16,384 | 2,010,184 | 761,504 | 8.76 | 3.32 |
| 65,536 | 10,235,983 | 3,505,831 | 9.76 | 3.34 |

두 판 모두 한 세로줄에 y 를 뒤섞어 놓은 배치이고 수는 기본 연산입니다. 점을 64 배로 늘리는 동안 다시 정렬하는 판의 비율은 6.79 에서 9.76 까지 커지고, 합치기만 하는 판은 3.25 에서 3.34 사이에 머뭅니다.

<!--/proof-->

다시 정렬하는 판은 비율이 점을 4 배로 할 때마다 1 씩 커져서, 비용에 로그가 하나 더 붙습니다. 합치기만 하는
판은 비율이 거의 그대로예요. 그래서 재귀가 `best` 와 함께 `byY` 를 올려 보내고, 위 단계는 정렬 대신 합치기만
합니다.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 이렇습니다.

1. 점 전부를 x 로 한 번 정렬한다
2. 구간의 점이 셋 이하면 쌍을 직접 비교하고, 구간을 y 로 정렬해 `byY` 와 함께 돌려준다
3. 아니면 `mid` 에서 갈라 두 절반을 재귀로 풀고, 두 `best` 중 작은 쪽을 `best` 로 잡는다
4. 두 `byY` 를 합쳐 이 구간의 `byY` 를 만든다
5. `byY` 에서 가로 차의 제곱이 `best` 보다 작은 점만 뽑아 띠를 만든다
6. 띠를 y 순서로 읽으며 세로 차의 제곱이 `best` 이상이면 멈추고, 그 전의 쌍으로 `best` 를 줄인다
7. 맨 위 구간의 `best` 에 제곱근을 한 번 씌워 돌려준다

### 수행으로 알아보는 알고리즘 — 점 여덟 개에서 거리 √5 를 낸다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 점 여덟 개를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const points: Point[] = [
  [0, 0], [2, 6], [3, 1], [4, 8], [5, 2], [6, 5], [8, 3], [9, 7],
];
// 이 절이 끝나면 √5 = 2.2361 이 나와야 한다
```

왜 하필 이 여덟일까요? 갈래를 전부 실행하면서도 손으로 따라갈 만큼 작아서예요. 재귀가 두 단 내려가 기저가
넷이고, 답인 `(3,1)` 과 `(5,2)` 가 서로 다른 절반에 있어 띠의 비교가 실제로 값을 바꿉니다. 맨 위 단계에서는
띠에 안 드는 점이 넷이라 거르는 조건의 참과 거짓이 둘 다 나오고, 오른쪽 절반의 띠에서는 `best` 를 못 줄이는
비교도 나와요. 좌표를 9 이하로 둔 것은 제곱 거리가 두 자리라 손으로 계산할 수 있어서입니다. 절차 전체는
이렇습니다.

```text
closestPairOfPoints(points):
    점을 x 로 정렬한다
    solve(정렬한 목록) 의 best 에 제곱근을 한 번 씌운다

solve(pts):
    점이 셋 이하면 쌍을 전부 비교하고, pts 를 y 로 정렬해 byY 로 돌려준다      ① 기저
    mid 에서 갈라 두 절반을 solve 한다
    best ← 두 절반의 best 중 작은 쪽                                            ② 최솟값
    byY  ← 두 절반의 byY 를 합친다                                              ③ 합치기
    strip ← byY 에서 (x − splitX)² < best 인 점                                 ④ 띠 고르기
    strip 의 점마다 뒤의 점을 차례로:
        (세로 차)² ≥ best 면 멈춘다                                             ⑤ 멈춤
        제곱 거리가 best 보다 작으면 best 를 줄인다
    best 와 byY 를 돌려준다
```

첫 걸음 T1 은 x 순서 정렬이고, 이 입력은 이미 x 순서라 목록이 그대로입니다. 그 뒤로 재귀가 기저 넷과 내부
마디 셋을 지나며, 내부 마디마다 「최솟값과 합치기」와 「띠 고르기와 비교」 두 걸음을 씁니다.

#### 1. 점이 셋 이하인 구간을 직접 비교한다

첫 조각은 재귀가 멈추는 자리입니다. 점이 셋 이하면 쌍이 많아야 셋이라 전부 재도 되고, 이 구간의 y 순서 목록이
여기서 처음 만들어져요.

```ts
if (n <= 3) {
  // ① 점이 셋 이하면 모든 쌍을 대조하고, 이 구간의 y 오름차순을 여기서 처음 만든다.
  const byY = [...pts].sort((a, b) => a[1] - b[1]);
  return { best: smallest(pts), byY };
}
```

<!--proof:walk-base-->

| 걸음 | 구간 | 조건 판정 | best | 올려 보내는 byY |
| --- | --- | --- | ---: | --- |
| T2 | (0,0) (2,6) | n = 2, `n <= 3` 참 → ① | 40 | (0,0) (2,6) |
| T3 | (3,1) (4,8) | n = 2, `n <= 3` 참 → ① | 50 | (3,1) (4,8) |
| T6 | (5,2) (6,5) | n = 2, `n <= 3` 참 → ① | 10 | (5,2) (6,5) |
| T7 | (8,3) (9,7) | n = 2, `n <= 3` 참 → ① | 17 | (8,3) (9,7) |

기저 4 구간 모두 점이 둘이라 거리 계산을 한 번씩 합니다. best 는 거리의 제곱이고, 제곱근은 맨 마지막에 한 번만 부릅니다.

<!--/proof-->

네 기저가 40 · 50 · 10 · 17 을 냅니다. 형제인 두 값 중 작은 쪽이 위 단계의 시작값이 되고, 그 시작값이 곧
띠의 폭을 정해요.

#### 짚고 가기 — 두 절반 중 한쪽 결과만 써도 될 것 같다

두 재귀의 값을 합치는 자리에서, 「왼쪽 재귀가 이미 답을 냈으니 그것으로 띠를 만들면 되겠다」로 읽기 쉽습니다.
그 생각대로 한쪽만 써 봅시다.

```ts
  let best = left.best;                                    // ←
```

배치 셋에 넣어 봅니다.

| 배치 | 점 | 정본 | 왼쪽 결과만 쓴 답 | 대조 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 8 | 2.2361 | 2.2361 | 같다 |
| 같은 좌표 둘 · 점 넷 | 4 | 0.0000 | 0.0000 | 같다 |

3 배치 가운데 1 배치에서 답이 어긋납니다. 맨 위 단계의 두 절반이 낸 값은 이렇습니다.

| 배치 | 왼쪽 절반의 best | 오른쪽 절반의 best | 작은 쪽 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 8 | 8 | 8 |

| 오른쪽 끝에 답 | 2,501 | 1 | 1 |

**위의 두 줄은 답이 그대로입니다.** 전개 입력은 두 절반이 모두 8 을 내서 어느 쪽을 골라도 같고, 같은 좌표가
있는 배치는 왼쪽에서 이미 0 이 나와요. 그래서 테스트가 이 두 모양뿐이면 틀린 줄을 모르고 넘어갑니다. 셋째
줄에서 갈립니다 — 답이 오른쪽 절반 안에 있으면, 그 값을 안 받은 띠가 폭 √2501 로 넓어지고 넓은 띠 안에서 찾은
2 가 답으로 나가요. 한쪽 결과만 쓰는 것은 폭을 넓히는 데서 그치지 않고, 오른쪽 절반이 이미 찾은 답 자체를
버리는 것입니다.

#### 2. 이미 y 순서인 두 목록을 합친다

둘째 조각은 정렬을 다시 하지 않는 자리입니다. 두 재귀가 각자 y 순서 목록을 올려 보냈으니, 앞 칸끼리 비교해
작은 쪽을 하나씩 꺼내면 합친 목록도 y 순서예요.

```ts
// ② 두 절반이 낸 값 중 작은 쪽이 지금까지의 최솟값이다.
let best = Math.min(left.best, right.best);
// ③ 이미 y 오름차순인 두 목록을 합치기만 한다.
const byY = mergeByY(left.byY, right.byY);
```

<!--proof:walk-merge-->

| 걸음 | 조건 판정 | best | 합친 byY | 좌표 비교 |
| --- | --- | --- | --- | ---: |
| T4 | n = 4, `n <= 3` 거짓 → ② ③ | min(40, 50) = 40 | (0,0) (3,1) (2,6) (4,8) | 3 |
| T8 | n = 4, `n <= 3` 거짓 → ② ③ | min(10, 17) = 10 | (5,2) (8,3) (6,5) (9,7) | 3 |
| T10 | n = 8, `n <= 3` 거짓 → ② ③ | min(8, 8) = 8 | (0,0) (3,1) (5,2) (8,3) (6,5) (2,6) (9,7) (4,8) | 7 |

3 걸음 모두 두 목록의 앞 칸끼리 비교하기만 하고, 다시 정렬하는 자리가 없습니다. 마지막 걸음의 목록이 여덟 점 전부를 y 순서로 담습니다.

<!--/proof-->

세 걸음의 좌표 비교가 3 · 3 · 7 이고, 모두 그 구간의 점 수보다 하나 적습니다. 네 점짜리에서는 한쪽 목록이
먼저 바닥났는데도 3 번이 된 것은, 마지막 한 점을 비교 없이 붙였기 때문이에요.

#### 3. 분할선 옆 띠를 고르고 그 안만 비교한다

셋째 조각이 본체입니다. 합친 목록에서 분할선에 가까운 점만 남기고, 그 안을 앞에서부터 보되 세로 거리가
벌어지면 그 자리에서 멈춥니다.

```ts
// ④ 분할선에서 가로 거리의 제곱이 best 보다 작은 점만 남긴다.
const strip: Point[] = [];
for (const p of byY) {
  const dx = p[0] - splitX;
  if (dx * dx < best) strip.push(p);
}
for (let i = 0; i < strip.length; i++) {
  for (let j = i + 1; j < strip.length; j++) {
    const dy = (strip[j] as Point)[1] - (strip[i] as Point)[1];
    // ⑤ 세로 거리의 제곱이 best 이상이면 그 뒤 점은 전부 더 멀다.
    if (dy * dy >= best) break;
    const d = squared(strip[i] as Point, strip[j] as Point);
    if (d < best) best = d;
  }
}
```

<!--proof:walk-strip-->

| 걸음 | 분할선 | 들어올 때 best | 띠 | 띠 안 | 나갈 때 best |
| --- | --- | ---: | --- | --- | ---: |
| T5 | x = 3 | 40 | 4 점 (안 든 점 0) | 비교 2 · 멈춤 2 | 8 |
| T9 | x = 8 | 10 | 4 점 (안 든 점 0) | 비교 4 · 멈춤 2 | 8 |
| T11 | x = 5 | 8 | 4 점 (안 든 점 4) | 비교 1 · 멈춤 3 | 5 |

3 걸음 가운데 best 가 줄어든 걸음은 T5 · T9 · T11 입니다. 맨 위 띠 걸음 T11 에서 best 가 5 가 되고, 그 값이 답의 제곱입니다.

<!--/proof-->

T5 와 T9 는 들어온 `best` 가 커서 네 점이 다 띠에 들었고, 거기서 둘 다 8 을 찾았습니다. 두 절반이 올린 8 이
T11 의 폭을 √8 로 좁혀, 맨 위에서는 여덟 점 가운데 넷만 띠에 들어요. 가장 중요한 줄은
`if (dy * dy >= best) break;` 입니다. 띠에 점이 몇 개 쌓이든 안쪽 반복이 그 자리에서 멈춰요.

#### 짚고 가기 — 세로 거리로 끊는 줄을 빼도 될 것 같다

「거르는 줄이니 빼도 답은 맞고 조금 느려질 뿐이겠다」로 읽기 쉽습니다. 앞 절반은 맞아요. **이 줄을 빼도 답은
안 틀립니다.**

```ts
      if (dy * dy >= best) break;                           // ← 이 줄을 지운다
```

한 세로줄 배치에서 점을 4 배로 늘리면 멈춤을 뺀 판은 15.86 배, 정본은 4.86 배가 됩니다.

<!--/proof-->

여덟 점에서는 멈춤을 뺀 판이 오히려 3 번 적습니다. 멈춤 검사 자체가 좌표 비교 하나씩이고, 띠가 네 점뿐이라
멈춰서 아끼는 비교가 그보다 적었어요. 한 세로줄 배치에서는 점 1,024 개에서 이미 37 배이고, 점을 4 배로 하면
멈춤을 뺀 판만 16 배 언저리로 늡니다. 이 줄은 답을 지키는 줄이 아니라 비용을 점 수의 제곱에서 `n log n` 으로
바꾸는 줄입니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 셋이에요 — 제곱 거리를 만드는 작은 함수, 기저에서
쌍을 전부 재는 함수, 그리고 처음 한 번의 x 순서 정렬입니다.

```ts
export type Point = [number, number];

function squared(a: Point, b: Point): number {
  const dx = a[0] - b[0];
  const dy = a[1] - b[1];
  return dx * dx + dy * dy;
}

function smallest(points: Point[]): number {
  let best = Number.POSITIVE_INFINITY;
  for (let i = 0; i < points.length; i++) {
    for (let j = i + 1; j < points.length; j++) {
      const d = squared(points[i] as Point, points[j] as Point);
      if (d < best) best = d;
    }
  }
  return best;
}

function mergeByY(left: Point[], right: Point[]): Point[] {
  const out: Point[] = [];
  let i = 0;
  let j = 0;
  while (i < left.length && j < right.length) {
    const a = left[i] as Point;
    const b = right[j] as Point;
    if (a[1] <= b[1]) {
      out.push(a);
      i++;
    } else {
      out.push(b);
      j++;
    }
  }
  while (i < left.length) {
    out.push(left[i] as Point);
    i++;
  }
  while (j < right.length) {
    out.push(right[j] as Point);
    j++;
  }
  return out;
}

export interface Half {
  best: number;
  byY: Point[];
}

export function solve(pts: Point[]): Half {
  const n = pts.length;
  if (n <= 3) {
    // ① 점이 셋 이하면 모든 쌍을 대조하고, 이 구간의 y 오름차순을 여기서 처음 만든다.
    const byY = [...pts].sort((a, b) => a[1] - b[1]);
    return { best: smallest(pts), byY };
  }
  const mid = n >> 1;
  const splitX = (pts[mid] as Point)[0];
  const left = solve(pts.slice(0, mid));
  const right = solve(pts.slice(mid));
  // ② 두 절반이 낸 값 중 작은 쪽이 지금까지의 최솟값이다.
  let best = Math.min(left.best, right.best);
  // ③ 이미 y 오름차순인 두 목록을 합치기만 한다.
  const byY = mergeByY(left.byY, right.byY);
  // ④ 분할선에서 가로 거리의 제곱이 best 보다 작은 점만 남긴다.
  const strip: Point[] = [];
  for (const p of byY) {
    const dx = p[0] - splitX;
    if (dx * dx < best) strip.push(p);
  }
  for (let i = 0; i < strip.length; i++) {
    for (let j = i + 1; j < strip.length; j++) {
      const dy = (strip[j] as Point)[1] - (strip[i] as Point)[1];
      // ⑤ 세로 거리의 제곱이 best 이상이면 그 뒤 점은 전부 더 멀다.
      if (dy * dy >= best) break;
      const d = squared(strip[i] as Point, strip[j] as Point);
      if (d < best) best = d;
    }
  }
  return { best, byY };
}

export function closestPairOfPoints(points: Point[]): number {
  const pts = [...points].sort((a, b) => a[0] - b[0]);
  return Math.sqrt(solve(pts).best);
}
```

### 알아 두면 좋은 개념 — 비둘기집 원리

「먼저 알아 둘 개념」에서 한 점이 비교한 이웃이 늘 몇 개로 묶이는 것을 실행으로 봤습니다. 그것이 7 을 못
넘는 까닭은 칸 여덟 개에 「한 칸에 점 하나」를 거는 논증이고, 그 논증의 이름이 **비둘기집 원리**예요 — **칸이
`m` 개인데 물건이 `m + 1` 개면 어느 칸엔가 둘 이상이 들어간다**는 것입니다. 이 글은 그것을 거꾸로 써서, 한
칸에 둘이 들어가면 모순이므로 물건이 칸 수를 못 넘는다고 읽었어요. 실제로 센 값을 칸 수와 나란히 놓으면
이렇습니다.

<!--proof:related-pigeon-->

| 배치 | 점 | 한 점이 비교한 이웃의 최대 | 자기까지 센 점 | 칸 수 |
| --- | ---: | ---: | ---: | ---: |
| 지그재그 여덟 점 | 8 | 2 | 3 | 8 |
| 균등 1024 점 | 1,024 | 2 | 3 | 8 |
| 균등 4096 점 | 4,096 | 2 | 3 | 8 |
| 한 세로줄 위 1024 점 | 1,024 | 0 | 1 | 8 |
| 32 × 32 격자 | 1,024 | 0 | 1 | 8 |

칸은 왼쪽 반 칸 넷과 오른쪽 반 칸 넷을 더해 8 개이고, 5 배치 모두 자기까지 센 점이 칸 수를 넘지 않습니다.

<!--/proof-->

같은 원리를 다시 만나는 자리가 둘 있습니다. 하나는 정점이 `m` 개인 그래프에서 간선을 `m` 번 넘게 따라가면
같은 정점을 두 번 지난다는 논증이고([`topologicalSort` 가이드](../../graph/topologicalSort/topologicalSort-guide.md)가
순환을 찾을 때 씁니다), 다른 하나는 유한한 값 위에서 같은 함수를 되풀이 적용하면 언젠가 값이 되풀이된다는
자리예요([`pollardRho` 가이드](../../number-theory/pollardRho/pollardRho-guide.md)의 순환 탐지가 그것입니다).

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 점 집합 전체에서 가장 가까운 한 쌍만 묻는다 | 점마다 가장 가까운 이웃을 묻는 과제가 아니다 | 재귀가 값 하나와 목록 하나만 올려 보낸다 |
| 한 번만 묻는다 | 점이 들고 나며 답을 계속 갱신하지 않는다 | 전처리 없이 정렬 한 번으로 시작한다 |
| 좌표 분포에 아무 약속이 없다 | 점이 몰렸는지 흩어졌는지 모른다 | 격자 한 변을 정할 근거가 없어 분할로 간다 |
| 최악에서도 보장이 필요하다 | 어떤 입력에서도 `O(n log n)` 이어야 한다 | 무작위 표본을 쓰지 않는다 |

묻는 것이 조금만 달라져도 고르는 절차가 바뀝니다.

| 묻는 것 | 고르는 절차 | 그 이유 |
| --- | --- | --- |
| 전체에서 가장 가까운 한 쌍 | 분할선 띠 | 정렬 한 번과 층마다의 합치기로 끝난다 |
| 점마다 가장 가까운 이웃 | k-d 트리나 들로네 삼각분할 | 질의가 많으면 색인을 한 번 세우는 편이 적다 |
| 거리가 `r` 이하인 쌍 전부 | 격자나 공간 색인 | 답의 개수가 출력 크기를 정한다 |
| 점이 들고 나는 동안 계속 | 배치 동적 자료구조 | 갱신마다 전체를 다시 풀 수 없다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "가장 가까운 두 점"  "최소 거리인 쌍"       ← 이 절차 그 자체를 묻는다
  "같은 좌표가 있으면 0"                      ← 겹친 점을 갈래로 따로 두지 말라는 신호다
  "좌표가 정수다"                             ← 제곱 거리를 정수로 다룰 수 있다는 신호다
  "1 초 · 점 10^5 개"                         ← 쌍을 전부 재는 방법이 안 된다는 신호다

거꾸로 이런 말이 보이면 이 절차가 아니다
  "점마다 가장 가까운 이웃을 구하라"  ← 질의가 n 개다. 색인을 세운다
  "거리가 r 이하인 쌍을 모두 구하라"  ← 답의 개수가 출력 크기다
  "점이 계속 추가된다"                ← 갱신마다 다시 풀 수 없다
```

둘째 무리의 첫 줄이 가장 자주 헷갈리는 자리입니다. 「가장 가까운 이웃」과 「가장 가까운 쌍」은 글자가 비슷한데
답의 개수가 `n` 개와 하나로 다르고, 그래서 고르는 절차도 달라요.

#### 실제로 쓰이는 곳

- **ParGeo 의 `closestPair` 모듈.** `ParAlg` 가 공개한 병렬 계산기하 라이브러리이고, 문서가 쓰는 절차를
  명시합니다 — *"a parallel divide-and-conquer algorithm proposed by Blelloch et. al."* 이고 헤더가
  `closestPair/closestPair.h`, 예제가 `example/closestPair.cpp` 예요. 그 예제는 좌표에 아주 작은 값을 더해
  **겹친 점을 먼저 없앱니다** — 이 글이 갈래 없이 0 으로 답하는 자리를 그쪽은 전처리로 피하는 것이라, 같은
  과제의 다른 규약입니다.
  ([ParAlg/ParGeo `README.md`](https://github.com/ParAlg/ParGeo/blob/main/README.md), 조회 2026-09-06)
- **Wang · Yu · Gu · Shun, "A Parallel Batch-Dynamic Data Structure for the Closest Pair Problem"
  (SoCG 2021).** 정적 병렬 최근접 쌍 알고리즘 넷을 실제로 구현해 실측한 논문이고, 스스로를 *"the first to
  experimentally evaluate parallel closest pair algorithms, in both the static and the dynamic settings"* 라
  적습니다. 넷 중 가장 빨랐던 것은 분할 정복이 아니라 라빈의 격자 방식이었어요.
  ([arXiv:2010.02379](https://arxiv.org/abs/2010.02379), 조회 2026-09-06)
- **SciPy 의 `KDTree.query_pairs`.** 같은 물음에 공간 색인으로 답하는 자리입니다 — 문서가 *"Find all pairs of
  points in self whose distance is at most r."* 라 적어요. 거리 상한 `r` 을 받아 그 안의 쌍을 전부 돌려주므로
  이 글의 절차와 묻는 것이 다릅니다.
  ([SciPy `KDTree.query_pairs` 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.KDTree.query_pairs.html),
  조회 2026-09-06)
- **CGAL 의 `Point_set_2`.** 2 차원 근접 질의를 들로네 삼각분할 위에서 답하는 패키지예요 — 문서가 지원 질의를
  *"circular range search, triangular range search, isorectangular range search, (k) nearest neighbor(s)"* 로
  적고, 자료구조를 *"inherited from the two-dimensional CGAL Delaunay Triangulation data type"* 이라 밝힙니다.
  가장 가까운 쌍 자체를 내주는 함수는 없습니다.
  ([CGAL `2D Range and Neighbor Search` 사용자 매뉴얼](https://doc.cgal.org/latest/Point_set_2/index.html),
  조회 2026-09-06)

인용한 자리와 이 글이 갈리는 대목을 모으면 이렇습니다.

| 출처 | 그쪽 | 이 글 |
| --- | --- | --- |
| ParGeo | 병렬 분할 정복이고 겹친 점을 전처리로 없앤다 | 한 갈래로 실행하고 겹친 점을 그대로 받아 0 을 답한다 |
| SoCG 2021 논문 | 넷 중 라빈의 격자가 가장 빨랐다 | 그 격자를 경쟁 설계로 세워 비교한다 |
| SciPy | 거리 상한 `r` 을 받는다 | 상한 없이 최솟값 하나를 답한다 |
| CGAL | 들로네 삼각분할 위에서 답한다 | 색인을 세우지 않는다 |

#### 경쟁 설계와의 대조

이 글의 설계를 **분할선 띠**라 적고, 같은 목표(가장 가까운 두 점 사이의 거리를 정확히 내는 것)를 노리는
다른 절차로 **격자 나누기**를 세웁니다. x 순서로 이웃한 쌍에서 답의 상한을 먼저 얻고, 한 변이 그 상한인
격자에 점을 담은 다음, 점마다 자기 칸과 이웃 여덟 칸만 비교하는 방식이에요. 거리가 상한 미만인 두 점은
이웃한 칸 안에 반드시 함께 들어가므로 답은 두 설계가 언제나 같습니다. 위에서 인용한 SoCG 2021 논문이 가장
빠르다고 실측한 라빈의 방식과 같은 뼈대인데, 상한을 얻는 자리 하나가 달라요 — 라빈은 무작위 표본에서 얻고
이 비교는 x 순서로 이웃한 쌍에서 얻습니다. 그래서 이 판은 실행마다 같은 값을 내고, 그 대신 표본이 지켜 주던
「상한이 답에 가깝다」를 잃어요.

수는 이 글 전체와 같은 기준입니다 — 기본 연산(거리 계산 · 좌표 비교 · 칸 조회를 각각 1)과 할당 칸이고,
두 설계가 똑같이 한 번씩 하는 x 순서 정렬도 양쪽에 넣었어요. 기하 갈래의 기본 구성과 달리 방향 판정을 쓰지 않아
거리 계산과 칸 조회를 넣었습니다. 할당 칸은 분할선 띠에서 정렬 사본 · 가른 두 절반 · 합친 목록 · 띠 · 기저의 y 순서 사본을, 격자
나누기에서 정렬 사본과 격자(새 칸은 키와 목록으로 2, 있는 칸에 점을 넣으면 1)를 셉니다. 벽시계는 재지 않습니다. 입력은 가족 둘로
고정했습니다. 균등 가족은 한 변 `10^8` 인 정사각형에 씨앗 20260906 의 32 비트 xorshift 난수로 흩은 배치이고
점의 수만 바꿉니다. 세로줄 가족은 모든 점이 `x = 0` 이고 `y` 가 0 부터 1,023 까지인데, 입력 순서만 `g` 칸씩
건너뛴 것이에요. 답은 언제나 1 이고 x 순서로 이웃한 쌍의 최소 거리가 정확히 `g` 라, `g` 가 곧 격자 한 변입니다.
전개 입력 여덟 점은 계수가 두 자리 안팎이라 순서가 뒤집히는 자리가 안 나와서, 규모를 키운 가족을 함께 잽니다.

| 입력과 계수 | 분할선 띠 | 격자 나누기 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 전개 입력 · 기본 연산 | **70** | 112 | 분할선 띠 |
| 균등 1024 점 · 기본 연산 | 31,596 | **20,200** | 격자 나누기 |
| 균등 4096 점 · 기본 연산 | 153,506 | **89,001** | 격자 나누기 |
| 세로줄 `g` = 9 · 기본 연산 | 30,747 | **29,607** | 격자 나누기 |
| 세로줄 `g` = 10 · 기본 연산 | **30,867** | 31,119 | 분할선 띠 |
| 세로줄 `g` = 16 · 기본 연산 | **30,705** | 40,191 | 분할선 띠 |
| 세로줄 `g` = 16 · 거리 계산 | **520** | 24,831 | 분할선 띠 |
| 균등 1024 점 · 할당 칸 | 23,838 | **3,072** | 격자 나누기 |

**세로줄 가족에서 순서가 실제로 뒤집힙니다.** `g` 가 9 일 때는 격자가 기본 연산을 적게 쓰는데, `g` 를 10 으로
올리면 30,867 대 31,119 로 분할선 띠가 앞서요. 격자 한 변이 `g` 면 세로줄 위에서 한 칸에 점이 `g` 개쯤 쌓이고,
점마다 이웃 아홉 칸을 보므로 비교가 `g` 에 비례해 늡니다. 분할선 띠는 `g` 가 커져도 기본 연산이 30,705 ~
30,867 언저리에 머물러요 — 띠가 구간 전체여도 한 점이 비교하는 이웃이 묶여 있기 때문입니다. `g` = 16 에서
거리 계산만 보면 520 대 24,831 이에요. 경계는 「x 순서로 이웃한 쌍의 최소 거리가 답의 몇 배인가」 하나입니다.

**분할선 띠가 내주는 것은 할당 칸과 균등 배치의 기본 연산입니다.** 균등 1024 점에서 칸이 23,838 대
3,072 이고, 그 차이는 단계마다 구간을 잘라 새 배열을 만들고 목록을 합쳐 새로 담기 때문이에요. 균등 배치에서는
기본 연산도 격자가 적습니다. 얻는 것은 **입력 모양과 무관한 보장**입니다. 격자 방식은 상한이 답보다 훨씬
크면 한 칸에 점이 쌓여 비교가 늘어나는데, 분할선 띠에는 그런 자리가 없어요.

| 알고 있는 것 | 격자 한 변과 칸의 점 | 고르는 쪽 |
| --- | --- | --- |
| 점이 고르게 흩어져 있다 | 이웃한 쌍의 거리가 답에 가까워 칸마다 점이 적다 | 격자 나누기 |
| 분포를 모르거나 최악을 막아야 한다 | 이웃한 쌍이 멀면 한 칸에 점이 쌓인다 | 분할선 띠 |

이 글이 고정한 과제는 분포에 아무 약속이 없는 아래 줄이라 분할선 띠를 고릅니다. 위 줄이 보장되는 자료였다면
반대예요.

### 수식 정의와 유도

두 점 $p$ · $q$ 의 제곱 거리와 점 집합 $P$ 의 답을 정의합니다.

$$
D(p, q) \;=\; (x_p - x_q)^2 + (y_p - y_q)^2, \qquad d^{*}(P) \;=\; \sqrt{\min_{p \neq q} D(p, q)}
$$

최솟값을 고른 뒤 제곱근을 한 번 씌웁니다. 제곱근이 크기 순서를 바꾸지 않으니 제곱근 안에서 최솟값을 고른 것과
같은 값이에요. 정의를 전개 입력의 네 쌍에 넣어 계산해 봅시다.

<!--proof:math-check-->

| 두 점 p–q | x_p − x_q | y_p − y_q | D(p, q) | √D(p, q) |
| --- | ---: | ---: | ---: | ---: |
| (0,0)–(3,1) | -3 | -1 | 10 | 3.1623 |
| (3,1)–(5,2) | -2 | -1 | 5 | 2.2361 |
| (5,2)–(6,5) | -1 | -3 | 10 | 3.1623 |
| (2,6)–(4,8) | -2 | -2 | 8 | 2.8284 |

여덟 점 전체에서 D 의 최솟값은 5, d* 는 2.2361 입니다. 정수 좌표에서는 D 까지 정수이고 제곱근에서만 소수가 붙습니다.

<!--/proof-->

이제 유도로 갑니다. 먼저 **띠 안에서 한 점이 비교하는 상대가 몇 개까지인가**를 닫아요. 구간 하나에서 두
절반이 각각 δ 이상을 보장했다고 두고, 분할선의 x 를 $x_m$ 이라 적습니다. 띠의 점 $p$ 와 멈추기 전에 비교되는
상대 $q$ 는 $p$ 보다 y 순서가 뒤이고 세로 차가 δ 미만이므로 아래 영역에 놓여요.

$$
R(p) \;=\; \{\, q \;:\; |x_q - x_m| < \delta,\ \ 0 \le y_q - y_p < \delta \,\}
$$

$R(p)$ 는 가로 $2\delta$ · 세로 $\delta$ 인 직사각형입니다. 이것을 분할선에서 좌우로 가르고 각각을 한 변
$\delta/2$ 인 칸 넷으로 쪼개면 칸이 여덟이에요.

<!--fig:math-cells-->
![p 의 y 부터 위로 δ · 분할선 양옆으로 δ 인 직사각형 — δ/2 칸 여덟](./figs/math-cells.svg)

칸 하나의 대각선은 $\frac{\delta}{2}\sqrt{2} \approx 0.7071\,\delta$ 라 δ 보다 짧습니다. 같은 절반의 점 둘이 한
칸에 있으면 그 둘의 거리가 δ 미만인데, 그 절반의 최솟값이 δ 이상이라는 재귀 결과와 어긋나요. 좌우를 먼저
가르는 것이 이 자리의 요점입니다 — 왼쪽 점과 오른쪽 점은 한 칸에 함께 있어도 모순이 안 생기므로, 모순을
만들려면 같은 절반의 두 점이어야 해요. 그래서 칸마다 점이 많아야 하나이고, $p$ 자신도 그 여덟 칸 안에
있습니다.

$$
|R(p)| \;\le\; 4 + 4 \;=\; 8 \quad\Longrightarrow\quad p \text{ 가 비교하는 상대의 수} \;\le\; 7
$$

이 상한으로 크기 $m$ 인 내부 마디 하나의 기본 연산을 셉니다. 띠의 점은 $k \le m$ 개예요.

| 일 | 세는 대상 | 상한 |
| --- | --- | --- |
| 합치기 | 두 목록의 앞 칸끼리 비교 | $m - 1$ |
| 띠 거르기 | 점마다 가로 차의 제곱과 `best` | $m$ |
| 멈춤 검사 | 띠의 점마다 비교한 상대 7 과 멈춘 자리 1 | $8k$ |
| 거리 계산 | 띠의 점마다 비교한 상대 | $7k$ |

$$
(m - 1) + m + 8k + 7k \;<\; 17m
$$

재귀 나무를 층별로 펴서 전체 기본 연산 $C(n)$ 을 네 몫으로 나눠 셉니다.

| 몫 | 셈 | 상한 |
| --- | --- | --- |
| 처음 한 번의 x 정렬 | 합치기 정렬의 비교 | $n \log_2 n$ |
| 내부 마디 한 층 | 한 층의 마디 크기를 다 더해도 $n$ 이하 | $17n$ 미만 |
| 내부 마디의 층 수 $L$ | 구간이 넷 이상일 동안만 이어진다 | $\lceil \log_2 (n/3) \rceil \le \log_2 n - 0.58$ |
| 기저 전부 | 크기 $m \le 3$ 인 구간마다 y 정렬과 거리 계산이 $2m$ 이하 | $2n$ |

넷을 더합니다.

$$
\begin{aligned}
C(n) \;&\le\; n\log_2 n \;+\; 17n\,L \;+\; 2n \\
&\le\; n\log_2 n \;+\; 17n(\log_2 n - 0.58) \;+\; 2n \\
&=\; 18\,n\log_2 n \;-\; 7.86\,n \;\le\; 18\,n\log_2 n
\end{aligned}
$$

층마다 y 로 다시 정렬하는 판이면 둘째 항의 합치기 자리에 층 $d$ 마다 $n \log_2 (n/2^d)$ 이 들어가, 그 합이
$n \cdot \frac{\log_2 n\,(\log_2 n + 1)}{2}$ 이 됩니다. 로그가 하나 더 붙는 까닭이 이 합이에요. 두 식을 코드로
옮겼습니다.

```ts
// 위 두 식을 그대로 옮긴 조각.
const upper = (n: number): number => n * Math.log2(n) + 17 * n * Math.log2(n);
const resortMerge = (n: number): number =>
  (n * Math.log2(n) * (Math.log2(n) + 1)) / 2;
```

마지막은 계수입니다. 상한에 과제의 규모를 넣고, 상한이 실제 실행과 얼마나 떨어져 있는지 봅니다.

<!--proof:math-count-->

| 배치 | 점 n | 모든 쌍 비교 n(n−1)/2 | 상한 18 n log₂ n | 실제 기본 연산 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 8 | 28 | 432 | 70 |
| 균등 1024 점 | 1,024 | 523,776 | 184,320 | 31,596 |
| 균등 4096 점 | 4,096 | 8,386,560 | 884,736 | 153,506 |
| 한 세로줄 위 4096 점 | 4,096 | 8,386,560 | 884,736 | 139,265 |
| 균등 100,000 점 | 100,000 | 4,999,950,000 | 29,897,353 | 5,207,477 |

n = 100,000 에서 상한은 모든 쌍 비교의 167 분의 1 이고, 초당 1 억 번으로 0.30 초입니다. 다섯 배치 모두 실제 기본 연산이 상한 아래에 있습니다.

<!--/proof-->

상한은 입력을 전혀 안 보고 낸 값인데도 점 10 만 개에서 0.30 초라 예산 1 초 안입니다. 전개 입력처럼 작은
입력에서는 상한이 모든 쌍 비교보다 커요. 점이 적으면 로그와 상수 17 이 이득을 다 먹기 때문이에요. 실제 실행이 상한보다 훨씬 적은 것은 한 점이 비교하는 이웃이 7 에
도달하지 않기 때문이에요.

### 불변식 — 재귀가 올려 보내는 byY 는 그 구간을 y 순서로 담고 best 는 그 구간의 답이다

파트 1 에서 코드가 동작하는 것을 열두 걸음으로 봤습니다. 그건 한 입력에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. **재귀 한 번이 끝난 직후에 무엇이 참으로 남는지**를 문장으로 세우고, 그 문장이 구간마다
지켜지는지를 값으로 봅니다. 문장은 두 절반으로 되어 있고, 절반마다 맡는 일이 다릅니다.

> 구간 하나에 대한 재귀가 끝난 직후, 그 재귀가 돌려주는 `byY` 는 **그 구간의 점 전부를 y 순서로 담고**,
> `best` 는 **그 구간 안에서 가장 가까운 두 점의 제곱 거리**와 같습니다.

| 절반 | 정하는 것 | 근거가 되는 자리 |
| --- | --- | --- |
| `byY` 가 y 순서다 | 목록의 순서 | 위 단계가 정렬 대신 합치기를 쓴다 |
| `best` 가 그 구간의 답이다 | 값의 뜻 | 위 단계의 띠 폭이 옳다 |

「끝난 직후」라는 시점도 중요합니다. 띠 안에서 `best` 가 줄어드는 도중에는
뒤 절반이 아직 참이 아닙니다. **유지되는 것부터 봅시다** — 전개 입력의 일곱 구간에서, 재귀가 올린 값과 그
구간만 모든 쌍을 비교한 값을 나란히 놓았습니다.

<!--proof:invariant-states-->

| 구간 | 점 | 올려 보낸 best | 그 구간만 모든 쌍 비교 | byY 가 y 순서 |
| --- | ---: | ---: | ---: | --- |
| 왼쪽의 왼쪽 | 2 | 40 | 40 | 예 |
| 왼쪽의 오른쪽 | 2 | 50 | 50 | 예 |
| 왼쪽 절반 | 4 | 8 | 8 | 예 |
| 오른쪽의 왼쪽 | 2 | 10 | 10 | 예 |
| 오른쪽의 오른쪽 | 2 | 17 | 17 | 예 |
| 오른쪽 절반 | 4 | 8 | 8 | 예 |
| 여덟 점 전부 | 8 | 5 | 5 | 예 |

7 구간 가운데 7 구간에서 두 best 가 같고 byY 가 y 순서입니다.

<!--/proof-->

넷째 열은 재귀를 쓰지 않고 그 구간의 쌍을 전부 잰 값이라 재귀가 만든 값과 다른 경로에서 왔어요. 구간 하나가
값을 정하는 갈래는 셋이고, 셋 다 같은 문장을 지킵니다.

| 갈래 | 하는 일 | 문장이 참인 근거 |
| --- | --- | --- |
| 점이 셋 이하다 | 쌍을 전부 재서 `best` 를 정하고 구간을 y 로 정렬한다 | 두 절반 다 정의 그대로다 |
| 띠에서 못 줄였다 | 두 절반의 `best` 중 작은 쪽이 그대로 남는다 | 그보다 가까운 걸친 쌍은 띠 안에 있어야 하는데 없었다 |
| 띠에서 줄였다 | 걸친 쌍 하나가 그 값보다 짧았다 | 그 쌍이 이 구간의 답이고, 띠 밖에는 더 짧은 걸친 쌍이 없다 |

셋째 갈래가 `best` 를 줄일 때도 `byY` 는 안 바뀝니다. 목록은 합치기가 만들고 띠는 목록을 읽기만 해요.
**경계에 있는 입력도 확인하고 갑시다.** 점이 둘뿐인 경우, 같은 좌표가 있는 경우, 모든 점이 한 줄 위에 있는
경우, 격자처럼 규칙적인 경우, 같은 좌표만 있는 경우, 좌표가 상한에 붙은 경우입니다.

<!--proof:invariant-edges-->

| 배치 | 점 | 올려 보낸 best | 모든 쌍 비교 | byY 가 y 순서 |
| --- | ---: | ---: | ---: | --- |
| 점 둘 | 2 | 25 | 25 | 예 |
| 같은 좌표 둘 · 점 넷 | 4 | 0 | 0 | 예 |
| 분할선을 가로지르는 답 | 4 | 1 | 1 | 예 |
| 한 세로줄 위 32 점 | 32 | 1 | 1 | 예 |
| 한 가로줄 위 32 점 | 32 | 1 | 1 | 예 |
| 8 × 8 격자 | 64 | 1 | 1 | 예 |
| 같은 좌표만 64 점 | 64 | 0 | 0 | 예 |
| 좌표 상한 네 점 | 4 | 1 | 1 | 예 |

8 배치 가운데 8 배치에서 두 best 가 같고 byY 가 y 순서입니다.

<!--/proof-->

같은 좌표가 있으면 `best` 가 0 이 되고, 가로 차의 제곱이 0 보다 작은 점은 없으니 띠가 통째로 비어 나머지
비교가 저절로 사라져요. 빈 입력을 위한 갈래는 없습니다. 점이 둘 미만이면 기저에서 쌍이 하나도 없어 `best`
가 무한대로 남는데, 이 과제는 점을 2 개 이상으로 정해 두었으므로 그 자리는 오지 않아요.

**남은 경계는 값의 크기입니다.** 좌표의 절댓값이 `C` 이하이면 제곱 거리는 많아야 $8C^2$ 인데, `C` 가 `10^9`
이면 그 값이 배정밀도가 정수를 어긋남 없이 담는 한계를 넘어요. 값이 어긋나는 자리를 찾아 참값과
나란히 놓았습니다.

<!--proof:edge-precision-->

| 두 점의 차 | 가로 차 | 세로 차 | 참값 | 배정밀도가 담은 값 |
| --- | ---: | ---: | ---: | ---: |
| 첫째 | 2,000,000,000 | 1,999,999,998 | 7,999,999,992,000,000,004 | 7,999,999,992,000,000,000 |
| 둘째 | 1,999,999,999 | 1,999,999,999 | 7,999,999,992,000,000,002 | 7,999,999,992,000,000,000 |

참값이 2 만큼 다른 두 제곱 거리가 배정밀도로는 같은 수가 됩니다. 제곱 거리가 정수로 정확히 담기는 마지막 좌표 상한은 33,554,431 이고, 좌표 상한 1,000,000,000 에서 제곱 거리는 8,000,000,000,000,000,000 까지 커지며 그 언저리에서 배정밀도가 담는 정수의 간격은 1,024 입니다. 두 거리의 차는 3.54e-10, 상대 차는 1.25e-19 로 허용 오차 1e-9 보다 작습니다.

<!--/proof-->

좌표 상한 `10^9` 에서는 어느 쌍이 더 가까운지 못 가르는 자리가 생겨, 고르는 쌍이 갈릴 수 있습니다. 그래도
그 두 쌍의 거리 차는 상대 차로 허용 오차보다 열 자리 아래라, 답으로 나가는 값은 과제가 허용하는 오차 안에
남아요. 좌표 상한이 33,554,431 이하로 보장되는 입력이라면 이 자리조차 없습니다.

**이제 깨뜨려 봅시다.** 앞 절반(「`byY` 는 y 순서로 담는다」)을 지키던 줄은 기저의 정렬 한 줄입니다. 「점이
둘이나 셋뿐인데 정렬이 무슨 의미가 있겠나」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
    const byY = [...pts];                                  // ←
```

실행하면 이렇게 갈립니다.

<!--proof:mutant-unsorted-->

| 배치 | 점 | 정본 | 기저의 y 정렬을 뺀 답 | 대조 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 8 | 2.2361 | 2.2361 | 같다 |
| 분할선을 가로지르는 답 | 4 | 1.0000 | 1.0000 | 같다 |
| 지그재그 여덟 점 | 8 | 1.4142 | 2.2361 | 어긋난다 |

3 배치 가운데 1 배치에서 답이 어긋납니다. 지그재그 여덟 점의 기저 넷이 올려 보내는 목록은 이렇습니다.

| 절반 | 정본의 byY | y 정렬을 뺀 판의 byY |
| --- | --- | --- |
| 왼쪽 절반 | (0,0) (1,2) · (2,4) (3,6) | (0,0) (1,2) · (2,4) (3,6) |
| 오른쪽 절반 | (5,1) (4,5) · (6,3) (7,7) | (4,5) (5,1) · (6,3) (7,7) |

<!--/proof-->

**전개 입력은 답이 그대로입니다.** 이 입력은 네 기저가 모두 x 순서와 y 순서가 같아서 정렬이 아무 일도 안
해요. 지그재그 여덟 점은 x 가 한 칸씩 늘고 y 가 0 · 2 · 4 · 6 · 5 · 1 · 3 · 7 로 오르내리는 배치이고, 답은
`(3,6)` 과 `(4,5)` 의 √2 입니다. 오른쪽 절반의 첫 기저에서 x 순서 `(4,5)` `(5,1)` 과 y 순서가 어긋나고, 그 목록을
받은 합치기가 y 순서를 못 만들어 띠의 멈춤이 엉뚱한 자리에서 걸려요. 답이 1.4142 대신 2.2361 이 됩니다. 정렬
한 줄이 합치기 · 띠 · 멈춤 세 자리를 함께 떠받칩니다. 기저가 작다는 것이 이 줄을 빼도 된다는 뜻은 아니에요.

### 비용 계산

#### 비용을 세는 과정

합치는 걸음의 좌표 비교는 그 구간의 점 수에 비례하고(3 · 3 · 7), 띠 걸음은 띠를 거르는 비교(그 구간의 점 수)에

따라갑니다. 점을 4 배씩 키우며 확인했어요.

<!--proof:perf-growth-->

| 균등 배치의 점 | 기본 연산 | 앞 줄의 몇 배 | 할당 칸 | 앞 줄의 몇 배 |

| 256 | 6,200 | — | 4,764 | — |
| 1,024 | 31,596 | 5.10 | 23,838 | 5.00 |
| 4,096 | 153,506 | 4.86 | 114,000 | 4.78 |
| 16,384 | 723,570 | 4.71 | 532,197 | 4.67 |

<!--/proof-->

`n log n` 을 따르는 값은 점을 4 배로 하면 `4 × log(4n)/log n` 배가 되어 4 배를 조금 넘고, 점이 커질수록 4 에
다가갑니다. 표의 성장률이 5.10 → 4.86 → 4.71 로 줄어드는 것이 그 모습이에요. 할당 칸도 층마다 가른 두
절반과 합친 목록이 점 수만큼씩이라 같은 꼴로 늡니다.

#### 케이스별 비용과 그 경계

여기서 **케이스**는 어떤 입력이 들어왔는가를 가르고, **경계**는 그 비용을 어떤 종류의 값으로 적었는가를
가릅니다. 두 축이 다르므로 한 줄에 섞어 적지 않아요. 이 절차는 반복 횟수를 바꾸는 갈래가 띠 안의 멈춤 하나뿐이고
그 멈춤이 한 점당 비교 일곱으로 묶여 있어, 케이스 셋이 같은 차수로 모입니다.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (띠가 늘 빈다 — 같은 좌표만) | `O(n log n)` | `Θ(n log n)` — 정렬과 층마다의 합치기가 이미 그 값이다 |
| **평균적인 경우** (입력 분포를 정해야 나오는 값) | `O(n log n)` | `Θ(n log n)` |
| **최악의 경우** | `O(n log n)` | `Θ(n log n)` — 실제로 도달한다 |

세 줄이 같은 것이 이 절차의 성질입니다. 아래로도 `n log n` 이 드는 까닭은 정렬과 합치기에 있어요 — 합치기만
해도 층마다 점 수에 비례하는 비교를 하고 층이 `log₂ n` 개입니다. 평균은 입력 분포를 정해야 나오는 값인데,
어떤 분포를 정해도 최선과 최악 사이라 차수가 같아요.

**총식을 한 번은 정확히 적습니다.**

```text
총식 = Θ(n log n)  x 정렬 한 번
     + Θ(n) × log₂ n 층  층마다의 합치기 · 띠 거르기 · 띠 안 비교
     + Θ(1)  마지막 제곱근 한 번
     = Θ(n log n) 시간   — 기본 연산 전체는 18 n log₂ n 이하

할당 칸 = 층마다 가른 두 절반 · 합친 목록 · 띠  →  Θ(n log n)
```

**보장의 종류는 최악 보장입니다.** 코드에 난수도 해시도 없고 입력 분포에 대한 가정도 없어요. 칸 논증이 입력과
무관하게 성립하므로 어떤 점 배치를 넣어도 기본 연산이 `18 n log₂ n` 을 넘지 않고, 같은 입력을 몇 번 넣어도
계수까지 같은 값이 나옵니다.

#### 최악을 만드는 입력

「점이 몰려 있으면 띠가 커져서 느려진다」는 통념이 붙기 쉬운 자리라, 점 수를 4,096 개로 고정하고 모양만 여섯으로
바꿔 실제로 쟀습니다.

<!--proof:worst-shape-->

| 배치(점 4,096) | 기본 연산 | 거리 계산 | 가장 큰 띠 | 이웃의 최대 | 할당 칸 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 균등 | 153,506 | 4,683 | 37 | 2 | 114,000 |
| 한 세로줄 위 | 139,265 | 2,048 | 4,096 | 0 | 143,360 |
| y 를 뒤섞은 한 세로줄 위 | 161,589 | 3,632 | 4,096 | 1 | 143,360 |
| 한 가로줄 위 | 96,256 | 2,048 | 1 | 0 | 100,351 |
| 64 × 64 격자 | 130,817 | 2,048 | 64 | 0 | 122,816 |
| 같은 좌표만 | 96,256 | 2,048 | 0 | 0 | 98,304 |

기본 연산이 가장 많은 배치는 「y 를 뒤섞은 한 세로줄 위」 의 161,589 번이고 가장 적은 배치는 「한 가로줄 위」 의 96,256 번으로, 1.68 배 차이입니다.

<!--/proof-->

**「띠가 크면 느리다」는 이 절차에서 거짓입니다.** 한 세로줄 배치는 띠가 4,096 개로 구간 전체인데 기본 연산이
139,265 로 균등 배치의 153,506 보다 적어요. 한 점이 비교하는 이웃이 0 개라 띠가 커져도 비교가 늘지 않기
때문입니다. 가장 무거운 것은 y 를 뒤섞은 한 세로줄로, 띠가 구간 전체이면서 기저의 y 정렬과 층마다의 합치기가
실제로 비교를 하는 배치예요. 그래도 가장 가벼운 배치와 두 배 안쪽입니다. 할당 칸이 가장 많은 것은 세로줄
두 배치이고, 띠가 늘 구간 전체라 층마다 띠 칸까지 점 수만큼 잡기 때문이에요. 시험을 만들 때 띠의 크기만 키우면
「띠가 작으니 빠르겠다」는 가정이 검사되지 않습니다. 비용을 키우는 것은 띠의 크기가 아니라 정렬과 합치기가
실제로 비교를 해야 하는 y 의 뒤섞임이에요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 가장 가까운 두 점은 **x 순서로 반씩 가른 뒤 두 절반의 답 중
작은 쪽을 폭 δ 로 삼아, 분할선 옆 그 폭 안의 점만 y 순서로 읽고 세로 차가 δ 이상이면 멈추면** 나오고, 그
읽기가 한 점당 비교 일곱 이하로 묶이는 것이 이 절차의 요점입니다.

```text
구간마다 → 셋 이하면 직접 비교 → 반으로 갈라 작은 best → byY 합치기 → 띠 고르기 → 멈추며 비교
           └ byY 는 여기서 처음      └ 폭 δ 가 정해진다    └ 정렬 대신    └ 폭 안만    └ 일곱 이하
```

먼저 답이 붙는 문제 하나입니다. 전개의 `T5` 와 `T9` 는 둘 다 띠에 네 점을 다 남겼는데, 비교는 2 번과 4 번으로
달랐어요. 같은 크기의 띠인데 왜 횟수가 갈렸을까요?

<!--check:whyScanDiffers-->
멈추는 조건이 `best` 를 쓰기 때문입니다. 두 걸음의 띠를 쌍마다 적으면 이렇습니다.

<!--proof:selfcheck-scan-->

T5 — 띠 (0,0) (3,1) (2,6) (4,8)

| 두 점 | 세로 차의 제곱 | 그때 best | 판정 | best 뒤 |
| --- | ---: | ---: | --- | --- |
| (0,0)–(3,1) | 1 | 40 | 1 < 40 → 비교, 제곱 거리 10 | 10 |
| (0,0)–(2,6) | 36 | 10 | 36 ≥ 10 → 멈춤 | — |
| (3,1)–(2,6) | 25 | 10 | 25 ≥ 10 → 멈춤 | — |
| (2,6)–(4,8) | 4 | 10 | 4 < 10 → 비교, 제곱 거리 8 | 8 |

띠의 4 점을 y 순서로 읽는 동안 비교가 2 번, 멈춤이 2 번이고, best 는 40 에서 8 로 끝납니다.

T9 — 띠 (5,2) (8,3) (6,5) (9,7)

| 두 점 | 세로 차의 제곱 | 그때 best | 판정 | best 뒤 |
| --- | ---: | ---: | --- | --- |
| (5,2)–(8,3) | 1 | 10 | 1 < 10 → 비교, 제곱 거리 10 | 10 |
| (5,2)–(6,5) | 9 | 10 | 9 < 10 → 비교, 제곱 거리 10 | 10 |
| (5,2)–(9,7) | 25 | 10 | 25 ≥ 10 → 멈춤 | — |
| (8,3)–(6,5) | 4 | 10 | 4 < 10 → 비교, 제곱 거리 8 | 8 |
| (8,3)–(9,7) | 16 | 8 | 16 ≥ 8 → 멈춤 | — |
| (6,5)–(9,7) | 4 | 8 | 4 < 8 → 비교, 제곱 거리 13 | 8 |

띠의 4 점을 y 순서로 읽는 동안 비교가 4 번, 멈춤이 2 번이고, best 는 10 에서 8 로 끝납니다.

<!--/proof-->

`T5` 는 40 으로 시작하지만 첫 비교에서 `best` 가 곧바로 10 으로 줄고, 그 뒤 두 상대가 세로로 10 이상 멀어 바로
멈춰요. `T9` 는 10 으로 시작하는데 첫 두 비교가 10 을 내서 `best` 가 안 줄고, 그래서 멈춤이 늦게 걸립니다.
비교 횟수를 정하는 것은 띠의 크기가 아니라 들어올 때의 `best` 와 그 안에서 얼마나 빨리 줄었는가예요. 상한
일곱은 「최악에도 이보다 많지 않다」는 약속이지 매번 일곱을 본다는 뜻이 아닙니다.
<!--/check-->

아래 셋에는 답을 싣지 않았습니다. 막히면 옆 칸의 절을 다시 보세요.

- 이 절차를 「가장 **먼** 두 점을 찾아라」로 바꿔 생각해 봅시다. 두 절반의 답 중 큰 쪽을 폭으로 삼아 분할선 옆

### 가장 가까운 두 점 쌍

풀 파일: [`closestPairOfPoints.ts`](./closestPairOfPoints.ts) · 테스트: [`closestPairOfPoints.test.ts`](./closestPairOfPoints.test.ts) · 실행: `bun test src/algorithms/geometry/closestPairOfPoints/closestPairOfPoints.test.ts`

#### 한 줄 요약

> 2D 평면 위 점 배열이 주어질 때, 가장 가까운 두 점 사이의 **유클리드 거리**를 반환한다.

#### 스토리

무선 통신망 설계를 맡은 지훈은 도시 전역에 흩어진 기지국 좌표 목록을 가지고 있다. 가장 가까이 붙어 있는 두 기지국을 찾아 주파수 간섭 위험을 점검해야 한다.

수십만 개의 기지국 좌표를 받아 가장 짧은 기지국 간 거리를 빠르게 계산하는 함수가 필요하다.

주어진 점 집합에서 가장 가까운 두 점 사이의 거리를 구하는 함수를 만들어라.

#### 함수 인터페이스

```ts
export type Point = [number, number];

export function closestPairOfPoints(points: Point[]): number;
```

- `points` — 2D 평면 위 점 배열. 각 원소는 `[x, y]` 형태. 배열의 길이는 $N$.
- 반환 — 가장 가까운 두 점 사이의 유클리드 거리. $\geq 0$ 인 부동소수.

#### 제약 조건

- $2 \leq N \leq 10^5$ — 점의 개수는 최소 2개
- $-10^9 \leq x, y \leq 10^9$ — 좌표 범위
- 동일 좌표를 가진 점이 둘 이상 존재할 수 있으며, 이 경우 최솟값은 $0$ 이다
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

2D 평면 위 $N$ 개의 점 $P = \{p_1, \ldots, p_N\}$ 에서 서로 다른 인덱스 $i \neq j$ 인 두 점 사이의 유클리드 거리가 최소인 값을 반환한다.

$$d^{*}(P) = \min_{i \neq j} \sqrt{(x_i - x_j)^2 + (y_i - y_j)^2}$$

- 동일한 좌표를 가진 점이 둘 이상 있으면 반환값은 $0$ 이다.
- 거리는 유클리드 거리(직선 거리)를 기준으로 한다.
- 반환값은 부동소수이며 정밀도 오차가 허용된다 (상대 오차 $10^{-9}$ 이하 권장).

#### 예시

```ts
// 두 점만 있는 경우
closestPairOfPoints([[0, 0], [3, 4]]); // 5 — √(9+16) = 5

// 여러 점 중 가까운 쌍
closestPairOfPoints([[0, 0], [1, 0], [10, 10]]); // 1 — (0,0)과 (1,0) 사이 거리

// 동일 좌표 점 존재
closestPairOfPoints([[0, 0], [0, 0], [5, 5]]); // 0 — 같은 점이 두 개

// x축 방향으로 가장 가까운 쌍
closestPairOfPoints([[0, 0], [100, 0], [200, 0], [201, 0]]); // 1 — (200,0)과 (201,0)

// y축 방향으로 가까운 쌍
closestPairOfPoints([[0, 0], [10, 100], [10, 101], [50, 50]]); // 1 — (10,100)과 (10,101)

// 대각선으로 가까운 쌍
closestPairOfPoints([[0, 0], [3, 3], [3, 4]]); // 1 — (3,3)과 (3,4) 사이 거리

// 분할 경계를 가로지르는 쌍이 정답인 경우
closestPairOfPoints([[0, 0], [10, 0], [11, 0], [21, 0]]); // 1 — (10,0)과 (11,0)
```
