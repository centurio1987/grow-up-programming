# bentleyOttmann — 교차하는 두 선분은 교차 직전에 반드시 이웃이 된다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 모든 쌍을 판정하는
방법에서 출발해 이웃 교차 예약에 이르고, 그 아이디어를 단계마다 값으로 푼 뒤, 실제로 동작하는 코드를 한 조각씩
만듭니다.

### 전체 컨셉

평면 위의 선분 목록을 받아 **교차하는 선분 쌍의 개수**를 돌려줍니다. 여기서 「교차」의 뜻은 넓어요. 두 선분이
점을 하나라도 공유하면 교차입니다. X 자로 가로지르는 것만이 아니라 끝점끼리 만나는 것도, 끝점 하나가 상대 선분
위에 놓인 T 자도, 같은 직선 위에서 구간을 나눠 갖는 것도 다 한 쌍으로 셉니다.

절차는 **스위프 선**(sweep line)이라는 가상의 세로선을 왼쪽에서 오른쪽으로 옮기며 진행합니다. 스위프 선은 모든
x 를 지나지 않고 **사건점**에서만 멈춰요. 사건점은 선분의 끝점이거나 두 선분의 교차점입니다. 스위프 선이 멈출
때마다 그 선과 만나는 선분을 **아래에서 위로, 곧 그 x 에서의 y 가 작은 것부터** 늘어놓은 목록을 들고 있고, 이
목록을 **상태 배열**(코드의 `status`)이라고 부릅니다. 상태 배열에서 칸이 하나 차이 나는 두 선분이 **이웃**이에요.
두 끝점의 x 가 같은 **세로 선분**은 한 x 에서 y 가 하나로 정해지지 않아 상태 배열에 넣지 않고 따로 다룹니다.

| 이름 | 뜻 |
| --- | --- |
| 스위프 선 | 왼쪽에서 오른쪽으로 옮겨 가는 가상의 세로선. 사건점에서만 멈춘다 |
| 사건점 | 스위프 선이 멈추는 자리. 선분의 끝점이거나 두 선분의 교차점이다 |
| 상태 배열 | 스위프 선과 만나는 세로가 아닌 선분을 그 x 에서의 y 가 작은 것부터 늘어놓은 목록 |
| 이웃 | 상태 배열에서 칸이 하나 차이 나는 두 선분 |
| 세로 선분 | 두 끝점의 x 가 같은 선분. 상태 배열에 넣지 않는다 |

이 글이 끝까지 쓰는 선분 다섯 개를 그렸습니다. 강조 테의 네 점이 교차점이고, 세로 실선이 x = 1 에 세운 스위프 선,
굵은 선이 그 스위프 선과 만나는 선분입니다. 아래 두 줄이 그 자리의 상태 배열과 각 선분이 스위프 선 위에서 지나는
y 예요.

<!--fig:concept-sweep-->
![선분 다섯과 교차점 넷 — 스위프 선 x = 1 과 그 위의 상태 배열](./figs/concept-sweep.svg)

x = 1 에서 스위프 선과 만나는 선분은 셋이고, 아래부터 s0 · s1 · s3 입니다. s2 는 세로 선분이라 상태 배열에 없고, s4
는 x 가 9 부터라 아직 스위프 선 오른쪽에 있어요.

도구는 사실 하나뿐입니다. **두 선분이 교차하려면 교차하기 직전에 상태 배열에서 서로 이웃이어야 한다**는 것이에요.
사이에 다른 선분이 끼어 있으면, 두 선분의 위아래가 뒤집히기 전에 그 선분과 먼저 자리를 바꿔야 하기 때문입니다.
그래서 이 절차는 새로 이웃이 된 두 선분의 교차점만 미리 계산해 사건점으로 **예약**해 두고, 스위프 선이 그 자리에
오면 두 선분의 순서를 뒤집어요. 이 글은 이 아이디어를 **이웃 교차 예약**이라고 부릅니다. 모든 쌍을 판정하는 방법과
답이 같은지 여러 배치에서 먼저 확인해 둡니다.

<!--proof:concept-cases-->

| 배치 | 선분 | 모든 쌍 판정의 답 | 이 절차의 답 |
| --- | ---: | ---: | ---: |
| 평행하고 떨어져 있다 | 3 | 0 | 0 |
| 같은 직선 위에서 겹친다 | 2 | 1 | 1 |
| 세 선분이 한 점에서 만난다 | 3 | 3 | 3 |
| 가로 둘과 세로 둘 | 4 | 4 | 4 |
| 전개 입력 | 5 | 4 | 4 |
| 흩어 놓은 길이 16 · 512 | 512 | 1 | 1 |
| 격자무늬 256 | 256 | 16,384 | 16,384 |

7 배치 가운데 7 배치에서 두 답이 같습니다. 전개 입력의 답은 4 쌍입니다.

<!--/proof-->

답은 같고, 다른 것은 선분 짝을 몇 번 들여다보는가입니다. 비용을 결과만 적으면 선분 `n` 개와 교차 쌍 `k` 개에
`O((n + k) log n)` 이고, 상태 배열을 균형 이진 탐색 트리로 둘 때의 값이에요. 이 글의 코드는 상태 배열을 배열로 두어
칸을 옮기는 값이 더 붙습니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **두 선분의 교차 판정.** 선분 **둘**이 한 점이라도 공유하는지는 방향 판정 넷의 부호와 좌표 칸 검사로 나눗셈 없이
  정해집니다. 그 판정의 정본은 [`segmentsIntersect` 가이드](../segmentsIntersect/segmentsIntersect-guide.md)이고, 이
  글은 그것을 가장 단순한 방법과 검산 쪽에서 씁니다. 이웃 교차 예약 자체는 판정을 더 잘게 쪼개 씁니다.
- **방향 판정(세 점의 꺾임).** 점 `o` 에서 `a`, `b` 로 갈 때 왼쪽으로 꺾이면 양수, 오른쪽이면 음수, 한 직선 위면
  0 이에요. 이 글은 이 값을 「점이 선분보다 위인가 아래인가」로 씁니다. 같은 판정을 껍질 사슬에 쓴 편이
  [`convexHull` 가이드](../convexHull/convexHull-guide.md)이고, 다각형 넓이에 쓴 편이
  [`polygonArea` 가이드](../polygonArea/polygonArea-guide.md)입니다.
- **최소 힙.** 가장 작은 값을 `O(log n)` 에 꺼내는 구조예요. 정본은
  [`priorityQueue` 가이드](../../../data-structures/heap/priorityQueue/priorityQueue-guide.mdx)이고, 이 글은 사건점을
  그 구조에 담습니다.
- **균형 이진 탐색 트리.** 삽입 · 삭제 · 이웃 조회가 각각 `O(log n)` 인 구조입니다.
  [`avlTree` 가이드](../../../data-structures/tree/avlTree/avlTree-guide.mdx)가 그 정본이에요. 비용을 따질 때 이
  글의 상태 배열을 이 구조로 바꿔 봅니다.
- **유리수를 정수 둘로 다루기.** 분모가 양수인 `a/b` 와 `c/d` 의 대소는 `a·d` 와 `c·b` 의 대소와 같습니다. 나눗셈
  없이 앞뒤가 정해져요.
- **`bigint`.** 자릿수 제한이 없는 정수 타입입니다. 이 글은 판정에 쓰는 수를 전부 이 타입으로 둡니다.

같은 판정을 쓰는 이웃 과제를 함께 놓으면 이 글의 자리가 보입니다.

| 과제 | 다루는 글 |
| --- | --- |
| 선분 여러 개에서 교차하는 쌍의 수 | 이 글 |
| 두 선분이 한 점이라도 공유하는가 | [`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-guide.md) |
| 평면 위 점들에서 가장 가까운 두 점 | [`closestPairOfPoints`](../closestPairOfPoints/closestPairOfPoints-guide.md) |
| 점 집합을 감싸는 가장 작은 볼록 다각형 | [`convexHull`](../convexHull/convexHull-guide.md) |

### 아이디어를 떠올리는 과정 — 모든 쌍 판정에서 이웃 교차 예약까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 선분 배열을 받아 교차하는 쌍의 수를
돌려줍니다.

```ts
type Point = [number, number];
type Segment = [Point, Point];

function bentleyOttmann(segments: Segment[]): number;
```

- 입력: 선분 배열 하나. 각 원소가 `[[x1, y1], [x2, y2]]` 이고 순서에 아무 약속이 없습니다.
- 출력: 교차하는 선분 쌍의 개수. 0 이상의 정수예요. 같은 점에서 `m` 개가 만나면 그 안의 모든 짝을 세므로
  `m(m−1)/2` 쌍입니다.
- 규모: 이 글은 선분 `n` 이 0 개 이상 10 만 개 이하이고 좌표가 절댓값 `10^9` 이하의 정수인 과제로 잽니다. 선분
  10 만 개는 흔한 채점 환경의 예산 1 초에 대어 볼 때 쌍의 수에 비례하는 방법과 선분 수에 비례하는 방법이 뚜렷이
  갈리는 규모예요. 좌표 상한을 `10^9` 로 두는 것은 교차점의 분자와 분모가 배정밀도가 정수를 오차 없이 담는 범위를
  넘게 해서, 사건점의 앞뒤를 정확히 정하는 일까지 함께 보려는 것입니다.

비용은 **기본 연산**으로 셉니다. 판정에 쓰는 정수 곱셈(방향 판정 하나에 2 번, 두 자리의 앞뒤 비교에 2\~4 번, 교차점
계산에 6\~10 번)과 자료 접근(배열 · 사전 · 집합을 한 번 읽거나 쓰는 일)을 각각 1 로 센 합이에요. 1 초의 예산은 초당
기본 연산 1 억 번으로 잽니다. 메모리는 입력 밖에 **추가로 잡는 칸**으로 셉니다. 이 글의 비용은 전부 이 두 기준으로
잰 것이에요. 이 글이 쓰는 기호는 열이고, 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `n` | 선분의 개수 | 0 이상 `10^5` 이하 |
| `k` | 교차하는 선분 쌍의 수. 이 함수가 내는 답이다 | 최대 `n(n−1)/2` |
| `C` | 좌표의 절댓값 상한 | `10^9` |
| `E` | 처리하는 사건점의 수 | 끝점 자리에 예약한 교차점을 더한 값 |
| `m` | 한 순간 상태 배열에 든 선분의 수 | `n` 이하 |
| `s_i` | 입력의 `i` 번째 선분 | 전개에서는 `s0` 부터 `s4` 까지 |
| `now` | 지금 처리하는 사건점 | 코드의 `now` |
| `status` | 상태 배열 — 스위프 선과 만나는 세로가 아닌 선분을 y 가 작은 것부터 | 코드의 `status` |
| `upright` | 지금 열려 있는 세로 선분의 목록 | 코드의 `upright` |
| `pairs` | 지금까지 센 교차 쌍의 수 | 마지막 값이 답이다 |

가장 먼저 떠오르는 방법은 **쌍을 전부 만들어 하나씩 판정하기**입니다. 손댈 것이 없고, 어떤 입력에서도 정확한
답을 내요.

```ts
let pairs = 0;
for (let i = 0; i < segments.length; i++) {
  for (let j = i + 1; j < segments.length; j++) {
    if (segmentsIntersect(segments[i], segments[j])) pairs++;
  }
}
```

쌍 하나를 판정하려면 방향 판정 넷이 들고, 방향 판정마다 곱셈이 둘이라 쌍마다 기본 연산이 적어도 8 번입니다. 과제의
규모를 넣으면 이렇습니다.

<!--proof:origin-brute-->

| 선분 n | 쌍 n(n−1)/2 | 기본 연산의 하한 8 × 쌍 | 시간(초당 1 억 번) |
| ---: | ---: | ---: | ---: |
| 5 | 10 | 80 | 0.00 초 |
| 1,000 | 499,500 | 3,996,000 | 0.04 초 |
| 10,000 | 49,995,000 | 399,960,000 | 4.00 초 |
| 100,000 | 4,999,950,000 | 39,999,600,000 | 400.00 초 |

전개 입력 선분 5 개를 실제로 모두 판정하면 쌍 10 개에 기본 연산이 80 번이고, 교차하는 쌍은 4 개입니다. 선분이 100,000 개면 쌍만 4,999,950,000 개라 기본 연산이 적어도 39,999,600,000 번이고, 예산 1 초의 400 배입니다.

<!--/proof-->

x 구간이 겹치지도 않는 두 선분까지 어김없이 한 번씩 판정합니다. 재기 전에 거르는 가장 쉬운 방법은 x 로 거르는
것이에요. **끝점을 x 차례로 지나며, 선분이 시작하는 자리에서 지금 열려 있는 선분 전부와만 판정하는** 판을 세워
봅시다. 끝점은 최소 힙에 넣어 x 차례로 꺼냅니다. 이 판을 **x 구간 판**이라고 부르고, 모든 쌍 판정과 나란히 셌어요.

<!--proof:origin-overlap-->

| 배치 | 선분 | 교차 쌍 | 모든 쌍 판정 · 판정한 짝 | x 구간 판 · 판정한 짝 | 모든 쌍 판정 · 기본 연산 | x 구간 판 · 기본 연산 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 5 | 4 | 10 | 6 | 80 | 329 |
| 흩어 놓은 길이 16 · 512 | 512 | 1 | 130,816 | 802 | 1,046,896 | 92,073 |
| 가로로 나란한 512 | 512 | 0 | 130,816 | 130,816 | 1,046,528 | 1,414,190 |

3 배치 모두 두 판의 답이 같습니다. 가로로 나란한 512 는 교차가 0 쌍인데, x 구간 판이 판정한 짝이 130,816 개로 쌍 전부입니다.

<!--/proof-->

흩어 놓은 짧은 선분에서는 판정한 짝이 크게 줄었습니다. 그런데 상자를 가로지르는 가로 선분 512 개를 나란히 놓으면
모든 선분의 x 구간이 겹쳐서, 교차가 하나도 없는데도 쌍 전부를 판정하고 기본 연산은 오히려 모든 쌍 판정보다 많아요.
선분 다섯 개에서도 힙을 드는 값 때문에 x 구간 판이 더 많습니다. 열린 선분끼리도 **세로로 멀리 떨어진 짝**이 있고,
그 짝을 거르려면 세로 방향의 순서가 필요합니다. 전개 입력의 세 선분이 스위프 선 몇 자리에서 어떤 y 를 지나는지
적어 봤어요.

<!--proof:origin-order-->

| 스위프 선 | s0 의 y | s1 의 y | s3 의 y | 순서 |
| --- | ---: | ---: | ---: | --- |
| x = 1 | 1 | 5 | 15/2 | 아래부터 s0 s1 s3 |
| x = 3 | 3 | 3 | 13/2 | s0 s1 의 y 가 같다 |
| x = 5 | 5 | 1 | 11/2 | 아래부터 s1 s0 s3 |

x = 1 에서 아래부터 s0 s1 s3 이던 순서가 x = 5 에서는 s1 s0 s3 입니다. 그 사이 x = 3 에서 s0 과 s1 의 y 가 같아지고, 그 자리가 두 선분의 교차점입니다.

<!--/proof-->

스위프 선 위에서 선분을 y 순서로 늘어놓으면 순서가 스위프 선을 따라 바뀝니다. 위아래가 뒤집히려면 두 선분의 y 가
한 번 같아져야 하고, 그 자리가 교차점이에요. 사이에 셋째 선분이 끼어 있으면 그 선분과 먼저 자리를 바꿔야 하므로,
**뒤집히기 직전의 두 선분은 이웃**입니다. 그러면 이웃한 짝만 판정해도 될 것 같아요. 이웃 관계는 선분이 들어올 때와
나갈 때 바뀌니, **그 두 자리에서만 새로 이웃이 된 짝을 판정하는** 판을 세워 봅니다. 이 판을 **끝점 판**이라고
부릅니다.

<!--proof:origin-endpoints-->

| 배치 | 선분 | 모든 쌍 판정의 답 | 끝점 판의 답 | 끝점 판 · 판정한 짝 | 끝점 판 · 기본 연산 | 답 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 5 | 4 | 4 | 5 | 358 | 맞다 |
| 가로로 나란한 512 | 512 | 0 | 0 | 511 | 260,443 | 맞다 |
| s1 을 (12,-6) 까지 늘인 전개 입력 | 5 | 4 | 3 | 5 | 355 | 틀린다 |

s1 을 늘인 배치에서 끝점 판이 놓친 짝은 s0–s3 입니다.

<!--/proof-->

가로로 나란한 선분에서 판정한 짝이 선분 수보다 하나 적은 수로 줄었고, 전개 입력의 답도 맞습니다. 그런데 전개 입력에서
s1 만 `(12,-6)` 까지 늘이면 답이 하나 모자라요. 끝점 판이 사건점마다 들고 있던 배열을 그 x 의 실제 순서와 나란히
놓았습니다.

<!--proof:origin-stale-->

| 사건점 | 끝점 판이 든 배열 | 그 x 의 실제 아래부터 | 판정한 짝 |
| --- | --- | --- | --- |
| (0,0) | s0 | s0 | — |
| (0,6) | s0 s1 | s0 s1 | s0–s1 |
| (0,8) | s0 s1 s3 | s0 s1 s3 | s1–s3 |
| (2,1) | s0 s1 s3 | s0 s1 s3 | s0–s2, s1–s2 |
| (2,5) | s0 s1 s3 | s0 s1 s3 | — |
| (8,4) | s0 s1 | s1 s0 | — |
| (8,8) | s1 | s1 | — |
| (9,0) | s1 s4 | s1 s4 | s1–s4 |
| (11,2) | s1 | s1 | — |
| (12,-6) | (비어 있음) | (비어 있음) | — |

사건점 10 개 가운데 1 개에서 끝점 판의 배열이 실제 순서와 다르고, s0–s3 은 한 번도 판정한 짝에 들지 않습니다.

<!--/proof-->

s0 과 s3 은 x = 0 에서 s1 을 사이에 두고 들어왔고, 끝점 판은 교차점에서 아무것도 하지 않으니 배열이 그 순서 그대로
남습니다. 실제로는 s0 과 s1 이 (3,3) 에서 자리를 바꾼 뒤 s0 과 s3 이 이웃이 되지만, 그 순간이 끝점이 아니라서 아무도
판정하지 않아요. 원래 전개 입력에서 답이 맞았던 것은 s1 이 먼저 끝나면서 두 선분이 우연히 맞닿았기 때문입니다.
**순서는 교차점에서 바뀌므로, 교차점도 스위프 선이 멈추는 자리여야 합니다.** 지금까지 해 본 방법을 차례로 놓으면
이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

첫째 방법의 값은 선분 10 만 개의 쌍마다 곱셈 8 번이 반드시 든다는 하한식에서 나온 수이고, 나머지는 표의 실행에서
나온 수입니다. 남은 방법에 이름을 붙이면 **이웃 교차 예약**이에요. 스위프 선을 사건점마다 멈추며 상태 배열을 y
순서로 들고, 두 선분이 새로 이웃이 될 때마다 그 교차점을 미리 계산해 사건점으로 예약하고, 스위프 선이 그 자리에 오면
두 선분의 순서를 뒤집습니다. 무엇을 먼저 준비하고 어떤 차례로 처리하는지는 다음 절에서 실현하는 순서대로 봅니다.

### 아이디어 상세 — 이웃 교차 예약

이 아이디어를 한 문장으로 줄이면 이렇습니다. **끝점을 사전순으로 사건 큐에 넣어 두고, 사건점을 하나씩 꺼내 그 점을
지나는 선분 토막의 짝을 센 뒤, 토막을 그 점 뒤의 순서로 다시 놓고, 토막의 위아래 경계에서 새로 이웃이 된 두 선분의
교차점을 사건 큐에 예약합니다.** 이 절은 먼저 상태 배열이 무엇인지 그림과 값으로 보고, 실현하는 순서대로 여섯
단계를 설명합니다. 1단계는 입력마다 한 번, 2단계부터 6단계는 사건점 하나를 꺼낼 때마다 해요.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 끝점 사건 채우기 | 선분마다 두 끝점을 사전순으로 세우고, 끝점을 전부 사건 큐에 넣는다 | — |
| 2단계 사건점 꺼내기 | 사건 큐에서 사전순으로 가장 앞선 자리를 꺼내고, 같은 자리는 한 번만 처리한다 | 1단계의 사건 큐 · 5단계가 넣은 교차점 |
| 3단계 지나는 토막 잡기 | 상태 배열에서 사건점을 지나는 선분의 토막을 이분 탐색으로 찾고, 토막과 시작하는 선분의 짝을 센다 | 2단계의 사건점 |
| 4단계 토막 다시 놓기 | 끝나는 선분을 빼고 시작하는 선분을 넣어, 토막을 기울기 오름차순으로 갈아 끼운다 | 3단계의 토막 |
| 5단계 교차점 예약 | 새 토막의 아래 경계와 위 경계에서 두 이웃의 교차점을 계산해 사건 큐에 넣는다 | 4단계의 새 상태 배열 |
| 6단계 세로 선분 세기 | 세로 선분은 여는 자리에서 y 범위에 드는 선분과 한꺼번에 짝을 센다 | 2단계의 사건점 · 상태 배열 |

#### 먼저 알아 둘 개념 — 상태 배열

상태 배열은 **스위프 선 하나 위에서, 그 선과 만나는 세로가 아닌 선분을 그 x 에서 지나는 y 가 작은 것부터 늘어놓은
목록**입니다. 스위프 선이 옮겨 가면 들어오는 선분 · 나가는 선분 · 순서가 바뀌는 선분이 생기므로, 상태 배열은 사건점마다
고쳐 쓰는 목록이에요. 코드에서는 선분 번호의 배열 `status` 이고, 칸 `i` 의 선분은 칸 `i + 1` 의 선분보다 그 x 에서
아래에 있습니다.

##### 입력 위의 상태 배열

전개 입력에서 스위프 선을 x = 1 과 x = 5 에 세웠습니다. 아래 네 줄이 두 자리의 상태 배열과 각 칸의 선분이 그
스위프 선 위에서 지나는 y 예요.

<!--fig:build-status-->
![스위프 선 x = 1 과 x = 5 — 두 자리의 상태 배열](./figs/build-status.svg)

두 스위프 선 모두 선분 셋과 만나는데 순서가 다릅니다. x = 1 에서는 s0 이 맨 아래이고, x = 5 에서는 s1 이 맨
아래예요. 그 사이의 (3,3) 에서 두 선분이 자리를 바꿨습니다.

##### 칸 하나를 읽는 법

칸 하나는 선분 번호 하나이고, 그 칸의 값은 선분이 스위프 선 위에서 지나는 y 입니다. x = 1 의 칸 1 이라면 s1 이고,
s1 은 `(0,6)` 에서 기울기 −1 로 내려가므로 x = 1 에서 y 가 5 예요. 세 칸을 전부 읽으면 이렇습니다.

<!--proof:build-read-->

| 칸 | 선분 | 끝점 | 기울기 | x = 1 에서의 y |
| ---: | --- | --- | --- | ---: |
| 0 | s0 | (0,0)-(8,8) | 1 | 1 |
| 1 | s1 | (0,6)-(6,0) | -1 | 5 |
| 2 | s3 | (0,8)-(8,4) | -1/2 | 15/2 |

x = 1 의 상태 배열은 s0 s1 s3 이고, 칸 번호가 커질수록 y 가 커집니다. 세로 선분 s2 와 x 가 9 부터인 s4 는 이 스위프 선 위의 칸에 없습니다.

<!--/proof-->

y 는 상태 배열에 적혀 있지 않습니다. 선분의 끝점과 스위프 선의 x 에서 그때그때 계산하고, 상태 배열은 그 대소가 정한
순서만 들어요. 그래서 코드는 y 를 구하는 대신 방향 판정으로 「이 점이 칸의 선분보다 위인가」를 묻고, 그 답으로
이분 탐색합니다.

##### 이웃한 칸끼리의 관계

이웃한 두 칸은 스위프 선 위에서 사이에 다른 선분이 없는 두 선분입니다. 스위프 선을 세 자리에 세우고 이웃한 짝과,
그 짝 가운데 스위프 선 오른쪽에서 만나는 짝을 적었어요.

<!--proof:build-neighbors-->

| 스위프 선 | 상태 배열 | 이웃한 짝 | 오른쪽에서 만나는 이웃 짝 |
| --- | --- | --- | --- |
| x = 1 | s0 s1 s3 | s0–s1, s1–s3 | s0–s1 (3,3) |
| x = 4 | s1 s0 s3 | s1–s0, s0–s3 | s0–s3 (16/3,16/3) |
| x = 11/2 | s1 s3 s0 | s1–s3, s3–s0 | 없다 |

s0–s1 은 x = 1 에서, s0–s3 은 x = 4 에서 이웃이고, 둘 다 그 오른쪽에 교차점이 있습니다. x = 11/2 에서는 두 교차점을 다 지나 오른쪽에서 만날 이웃 짝이 없습니다.

<!--/proof-->

s0–s1 은 교차점 (3,3) 에 이르기 전에 이웃이고, s0–s3 은 (3,3) 을 지나 s0 이 위로 올라온 뒤에 이웃이 됩니다. 두 짝 모두
**교차하기 직전에 이웃**이에요. 까닭은 하나입니다. 교차하는 두 선분 사이에 셋째 선분이 있으면, 두 선분이 만나기
전에 그 셋째 선분이 둘 중 하나와 먼저 자리를 바꿔 사이에서 빠져나가야 합니다. 셋째 선분이 끝까지 사이에 남아 있다면
두 선분의 y 가 같아지는 순간 셋째 선분의 y 도 그 값이어야 하니, 그 점은 셋이 함께 지나는 사건점이고 그 자리에서
셋이 한 토막으로 잡힙니다. 어느 쪽이든 교차하는 짝은 이웃이 되거나 같은 토막에 들어요.

##### 왼쪽 끝점의 y 로 세운 순서와의 차이

처음 떠올리기 쉬운 모양은 **왼쪽 끝점의 y 로 한 번 세워 둔 순서**입니다. 선분이 바뀌지 않으니 순서도 한 번만 정하면
될 것 같아요. 같은 세 선분을 두 기준으로 세우고 x = 5 에서 이웃한 짝을 비교했습니다.

<!--proof:build-static-->

| 순서를 정하는 값 | 아래부터 | 이웃한 짝 | 그중 교차하는 짝 |
| --- | --- | --- | --- |
| 왼쪽 끝점의 y | s0 s1 s3 | s0–s1, s1–s3 | s0–s1 |
| x = 5 에서 지나는 y | s1 s0 s3 | s1–s0, s0–s3 | s1–s0, s0–s3 |

같은 세 선분인데 이웃한 짝이 다릅니다. s0–s3 은 스위프 선 위의 순서에서만 이웃이고, 두 선분은 (16/3,16/3) 에서 만납니다.

<!--/proof-->

왼쪽 끝점의 y 로 세운 순서는 x = 0 의 모습을 끝까지 들고 갑니다. 그 순서에서 s0 과 s3 사이에는 늘 s1 이 있어서,
s0–s3 이 이웃이 되는 순간을 알 수 없어요. 「아이디어를 떠올리는 과정」의 끝점 판이 놓친 짝이 바로 이것입니다.

##### 상태 배열이 이렇게 생긴 까닭

상태 배열의 두 성질은 아이디어의 요구를 하나씩 채웁니다. **스위프 선 위의 y 순서**인 것은 교차하는 짝이 교차 직전에
이웃이라는 사실을 쓰기 위해서예요. 순서가 스위프 선 위의 실제 순서여야 이웃한 칸이 실제로 맞닿은 두 선분입니다.
**배열**인 것은 이분 탐색으로 사건점이 들어갈 자리를 찾기 위해서입니다. 순서만 맞으면 방향 판정 몇 번으로 토막의 양
끝을 찾을 수 있어요. 세로 선분을 빼는 것은 한 x 에서 y 가 구간이라 순서를 매길 값이 없기 때문입니다.

#### 1단계 — 끝점을 사전순으로 세워 사건 큐 채우기

입력은 두 끝점만 주고 어느 쪽이 왼쪽인지 말해 주지 않습니다. x 가 작은 쪽을 앞에 두되 x 가 같으면 y 가 작은 쪽을
앞에 두면, 스위프 선이 지나가는 순서와 같은 순서가 돼요. 이 순서를 **사전순**이라고 부릅니다. 전개 입력의 다섯 선분을
세우면 이렇습니다.

<!--proof:build-normalize-->

| 선분 | 입력 | 앞선 끝점 lo | 뒤 끝점 hi | 기울기 |
| --- | --- | --- | --- | --- |
| s0 | (0,0)-(8,8) | (0,0) | (8,8) | 1 |
| s1 | (0,6)-(6,0) | (0,6) | (6,0) | -1 |
| s2 | (2,1)-(2,5) | (2,1) | (2,5) | 세로 |
| s3 | (0,8)-(8,4) | (0,8) | (8,4) | -1/2 |
| s4 | (9,0)-(11,2) | (9,0) | (11,2) | 1 |

끝점 둘 가운데 x 가 작은 쪽, x 가 같으면 y 가 작은 쪽이 lo 입니다. s2 는 두 끝점의 x 가 같아 세로 선분이고, 사건 큐에 처음 들어가는 끝점은 10 개입니다.

<!--/proof-->

끝점은 입력에 적혀 있으니 처음부터 전부 사건 큐에 넣을 수 있습니다. 끝점마다 「여기서 시작하는 선분」과 「여기서
끝나는 선분」을 사전에 적어 두어, 사건점을 꺼냈을 때 그 자리에서 무엇이 일어나는지 바로 찾게 해요. 세로 선분은 따로
적습니다.

#### 2단계 — 사건점을 사전순으로 꺼내기

사건 큐는 최소 힙이고, 꺼낼 때마다 남은 사건점 가운데 사전순으로 가장 앞선 자리가 나옵니다. 교차점은 좌표가 분수일
수 있어서 자리를 분자 둘과 분모 하나의 정수 셋으로 적어 둡니다. 두 자리의 앞뒤는 곱셈으로 정해요.

<!--proof:build-order-->

| 두 자리 | 앞 자리 x 분자 × 뒤 자리 분모 | 뒤 자리 x 분자 × 앞 자리 분모 | 꺼낼 차례 |
| --- | --- | --- | --- |
| (3,3) · (16/3,16/3) | 3 × 3 = 9 | 16 × 1 = 16 | 앞 자리가 먼저 |
| (16/3,16/3) · (6,0) | 16 × 1 = 16 | 6 × 3 = 18 | 앞 자리가 먼저 |

두 자리의 x 를 비교할 때 서로의 분모를 곱해 맞추면 나눗셈 없이 정수 둘의 비교가 됩니다. 분모가 늘 양수라 곱해도 부등호 방향이 안 바뀝니다.

<!--/proof-->

같은 자리가 사건 큐에 여러 번 들어갈 수도 있습니다. 여러 이웃 짝이 같은 교차점을 예약하면 그렇게 돼요. 꺼낼 때 같은
자리를 한꺼번에 꺼내 버리면 한 번만 처리됩니다.

<!--proof:build-dedupe-->

| 배치 | 선분 | 사건 큐에 넣은 횟수 | 처리한 사건점 | 교차 쌍 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 5 | 12 | 12 | 4 |
| 세 선분이 한 점에서 만난다 | 3 | 7 | 7 | 3 |
| 한 점에 여덟 갈래 | 8 | 23 | 17 | 28 |

한 점에 여덟 갈래에서는 사건 큐에 23 번 넣었는데 처리한 사건점은 17 개입니다. 같은 자리를 꺼낼 때 한꺼번에 꺼내 버리므로 교차점 하나를 한 번만 처리합니다.

<!--/proof-->

#### 3단계 — 사건점을 지나는 토막 잡아 짝 세기

2단계에서 꺼낸 사건점을 상태 배열에 대어 봅니다. 상태 배열은 y 순서라 사건점보다 아래인 선분이 앞쪽에 몰려 있고,
사건점을 지나는 선분이 그 뒤에 이어지고, 위인 선분이 맨 뒤에 있어요. 이분 탐색 두 번으로 「처음으로 아래가 아닌
칸」과 「처음으로 위인 칸」을 찾으면 그 사이가 토막입니다. 전개 입력에서 교차점 (3,3) 을 꺼낸 자리예요.

<!--proof:build-through-->

| 칸 | 선분 | 방향 판정 | 뜻 |
| ---: | --- | ---: | --- |
| 0 | s0 | 0 | 사건점이 선분 위 |
| 1 | s1 | 0 | 사건점이 선분 위 |
| 2 | s3 | -1 | 사건점이 선분보다 아래 |

사건점 (3,3) 에서 방향 판정이 0 인 칸이 이어진 토막은 s0 s1 이고, 토막 안의 짝은 전부 이 점에서 만납니다.

<!--/proof-->

토막 안의 선분은 전부 이 점을 지나므로 서로 다 교차합니다. 여기서 시작하는 선분도 이 점을 지나니 함께 모아 모든
짝을 세요. 이미 센 짝은 집합에 적어 두어 두 번 세지 않습니다.

#### 4단계 — 토막을 사건점 뒤의 순서로 다시 놓기

토막에서 여기서 끝나는 선분을 빼고, 여기서 시작하는 선분을 더한 뒤, 이 점 **뒤**의 순서로 세웁니다. 한 점을 지나는
선분들은 그 점 오른쪽에서 기울기가 큰 쪽이 위로 가므로, 기울기 오름차순이 곧 뒤의 순서예요. 3단계의 토막을 그렇게
다시 놓았습니다.

<!--proof:build-reorder-->

| 새 토막의 칸 | 선분 | 기울기 |
| ---: | --- | ---: |
| 0 | s1 | -1 |
| 1 | s0 | 1 |

걸음 전 상태 배열 s0 s1 s3 에서 토막 s0 s1 을 기울기 오름차순 s1 s0 으로 갈아 끼우면 s1 s0 s3 이 됩니다.

<!--/proof-->

끝나는 선분을 빼는 일, 시작하는 선분을 넣는 일, 교차점에서 위아래를 뒤집는 일이 모두 이 한 번의 갈아 끼우기로
처리됩니다. 셋 다 「이 점을 지나는 토막을 다시 놓는다」로 같기 때문이에요.

#### 5단계 — 경계 두 곳에서 교차점 예약하기

토막을 갈아 끼우면 새로 맞닿는 자리는 둘입니다. 토막 바로 아래 칸과 새 토막의 첫 칸, 새 토막의 마지막 칸과 토막 바로
위 칸이에요. 토막 안쪽의 짝은 방금 이 점에서 만났으니 다시 만날 일이 없습니다. 두 경계에서 두 이웃의 교차점을
계산했어요.

<!--proof:build-book-->

| 걸음 | 경계 | 두 이웃 | 두 직선이 만나는 자리 | 그 자리 | 사건 큐에 |
| --- | --- | --- | --- | --- | --- |
| T2 | 아래 경계 | s0–s1 | (3,3) | 두 선분 안 | 넣는다 |
| T3 | 아래 경계 | s1–s3 | (-4,10) | 선분 밖 | 안 넣는다 |
| T6 | 위 경계 | s0–s3 | (16/3,16/3) | 두 선분 안 | 넣는다 |

두 직선이 만나는 자리가 두 선분 안에 있고 지금 사건점보다 뒤일 때만 사건 큐에 넣습니다.

<!--/proof-->

두 직선이 만나는 자리가 선분 밖이면 두 선분은 만나지 않습니다. 지금 사건점보다 앞선 자리면 이미 지나온 교차라 다시
넣지 않아요. 이 두 조건을 통과한 자리만 사건 큐에 들어가므로, 예약은 실제 교차점에만 생깁니다.

#### 6단계 — 세로 선분을 y 범위로 세기

세로 선분은 상태 배열에 넣지 않습니다. 대신 여는 자리, 곧 아래 끝점에서 한꺼번에 셉니다. 상태 배열에서 그 x 에서의
y 가 세로 선분의 y 범위 안인 선분은 전부 세로 선분과 교차하고, 상태 배열이 y 순서라 그 선분들은 이어진 칸에 있어요.
이분 탐색 두 번으로 그 칸을 찾습니다. 전개 입력의 세로 선분 s2 를 여는 자리입니다.

<!--proof:build-upright-->

| 선분 | x = 2 에서의 y | s2 의 y 범위 [1, 5] |
| --- | ---: | --- |
| s0 | 2 | 범위 안 |
| s1 | 4 | 범위 안 |
| s3 | 7 | 범위 밖 |

범위 안에 든 선분은 s0 s1 2 개이고, 상태 배열에서 이어진 칸에 놓여 있습니다.

<!--/proof-->

이미 열려 있는 다른 세로 선분은 전부 같은 x 에 있고 지금 사건점을 지나므로, 그것들과도 짝을 셉니다. 세로 선분은 위
끝점에서 닫아요.

#### 이 방법이 기대는 전제

이웃 교차 예약은 아래 세 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 상태 배열이 사건점을 처리할 때마다 스위프 선 위의 y 순서다 | 3단계와 6단계의 이분 탐색 | 토막을 엉뚱한 칸에서 잡아 짝을 놓치거나 없는 짝을 센다 |
| 교차하는 두 선분은 교차 직전에 이웃이다 | 5단계가 경계 두 곳만 보는 까닭 | 경계만 보는 예약이 교차를 놓친다 |
| 사건점의 앞뒤가 정확히 정해진다 | 2단계의 꺼낼 차례와 5단계의 「지금보다 뒤」 | 교차점을 너무 일찍 또는 늦게 처리해 순서가 어긋난다 |

첫째 전제가 깨지는 모습은 「불변식」의 깨뜨리기에서, 둘째는 「수행으로 알아보는 알고리즘」의 셋째 짚고 가기에서,
셋째는 「수식 정의와 유도」의 자릿수에서 봅니다.

#### 여섯 단계를 이은 절차

여섯 단계를 코드의 순서로 다시 적으면 이렇습니다.

1. 선분마다 두 끝점을 사전순으로 세우고, 끝점 `2n` 개를 사건 큐에 넣는다
2. 사건 큐가 빌 때까지 사전순으로 가장 앞선 사건점을 꺼내고, 같은 자리는 한꺼번에 꺼낸다
3. 그 점에서 시작하는 세로 선분을 열고, 상태 배열에서 y 범위에 드는 선분과 짝을 센다
4. 상태 배열에서 그 점을 지나는 토막을 이분 탐색으로 잡고, 토막과 시작하는 선분의 모든 짝을 센다
5. 끝나는 선분을 빼고 시작하는 선분을 넣어 토막을 기울기 오름차순으로 갈아 끼운다
6. 그 점에서 끝나는 세로 선분을 닫는다
7. 새 토막의 아래 경계와 위 경계에서 두 이웃의 교차점을 계산해, 선분 안이고 지금보다 뒤면 사건 큐에 넣는다
8. 센 짝의 수를 돌려준다

### 수행으로 알아보는 알고리즘 — 선분 다섯 개에서 교차 쌍 넷을 센다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 선분 다섯 개를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const segments: Segment[] = [
  [[0, 0], [8, 8]],
  [[0, 6], [6, 0]],
  [[2, 1], [2, 5]],
  [[0, 8], [8, 4]],
  [[9, 0], [11, 2]],
];
// 이 절이 끝나면 교차 쌍 4 가 나와야 한다
```

이 다섯을 고른 이유는 **갈래를 하나도 안 남기고 전부 실행하기 때문**입니다. x = 0 에 끝점이 셋 몰려 있고, 세로 선분이
하나 있으며, 교차점이 둘인데 그중 하나는 좌표가 분수이고, 마지막 하나는 x 구간이 안 겹쳐 앞의 넷과 한 번도 판정하지
않아요. 절차 전체는 이렇습니다.

```text
bentleyOttmann(segments):
    선분마다 끝점을 사전순으로 세우고 끝점 2n 개를 사건 큐에 넣는다
    사건 큐가 빌 때까지:
        now ← 사전순으로 가장 앞선 자리 (같은 자리는 한꺼번에)
        now 에서 시작하는 세로 선분을 열고 y 범위의 선분과 짝을 센다   ① 세로 열기
        now 를 지나는 토막과 now 에서 시작하는 선분의 모든 짝을 센다   ② 짝 세기
        끝나는 것을 빼고 토막을 기울기 오름차순으로 다시 놓는다        ③ 다시 놓기
        now 에서 끝나는 세로 선분을 닫는다                             ④ 세로 닫기
        새 토막의 아래 · 위 경계에서 교차점을 예약한다                 ⑤ 예약
    pairs 를 돌려준다
```

#### 1. 끝점을 사전순으로 세워 사건 큐를 채운다

첫 조각은 두 끝점의 앞뒤를 정하는 자리입니다. x 가 작은 쪽을 앞에 두되 x 가 같으면 y 가 작은 쪽을 앞에 두고, 두 끝점의
x 가 같으면 세로 선분으로 표시해요.

```ts
function toSeg(raw: Segment, id: number): Seg {
  const [a, b] = raw;
  const front = a[0] < b[0] || (a[0] === b[0] && a[1] <= b[1]);
  const lo = front ? a : b;
  const hi = front ? b : a;
  // 두 끝점의 x 가 같으면 세로 선분이다. 상태 배열에 넣지 않는다.
  return { id, lo, hi, vertical: lo[0] === hi[0] };
}
```

그다음 끝점을 전부 사건 큐에 넣고, 끝점마다 시작하고 끝나는 선분을 사전에 적어 둡니다.

```ts
for (const s of segs) {
  const lo: Spot = { x: s.lox, y: s.loy, d: 1n };
  const hi: Spot = { x: s.hix, y: s.hiy, d: 1n };
  heapPush(events, lo);
  heapPush(events, hi);
  fileInto(s.vertical ? uprightLow : startAt, spotKey(lo), s.id);
  fileInto(s.vertical ? uprightHigh : endAt, spotKey(hi), s.id);
}
```

이 조각만 실행하면 사건 큐의 내용이 이렇게 됩니다. 꺼낼 차례대로 늘어놓았어요.

<!--proof:walk-queue-->

| 꺼낼 차례 | 사건점 | 끝점 |
| ---: | --- | --- |
| 1 | (0,0) | s0 lo |
| 2 | (0,6) | s1 lo |
| 3 | (0,8) | s3 lo |
| 4 | (2,1) | s2 lo |
| 5 | (2,5) | s2 hi |
| 6 | (6,0) | s1 hi |
| 7 | (8,4) | s3 hi |
| 8 | (8,8) | s0 hi |
| 9 | (9,0) | s4 lo |
| 10 | (11,2) | s4 hi |

처음 사건 큐에 든 것은 끝점 10 개이고, 교차점은 아직 하나도 없습니다.

<!--/proof-->

끝점은 사전순으로 나옵니다. x = 0 의 세 끝점은 y 가 작은 것부터이고, 세로 선분 s2 의 두 끝점은 x 가 같아 y 로
앞뒤가 정해져요.

#### 2. 사건점을 지나는 선분을 모아 짝을 세고 새 이웃을 예약한다

**여기가 ② 와 ⑤ 가 하는 일입니다.** 사건점을 꺼내면 상태 배열에서 그 점을 지나는 토막을 이분 탐색으로 잡고, 거기에
시작하는 선분을 더해 모든 짝을 셉니다. 토막을 다시 놓은 뒤에는 새 토막의 위아래 경계에서만 다음 교차점을 예약해요.

```ts
// ② 이 자리를 지나는 선분과 여기서 시작하는 선분을 모아 모든 짝을 센다.
const from = firstNotBelow(now);
const through = status.slice(from, firstAbove(now));
const starting = startAt.get(here) ?? [];
const meeting = [...through, ...starting];
for (let i = 0; i < meeting.length; i++) {
  for (let j = i + 1; j < meeting.length; j++) record(meeting[i], meeting[j]);
}
// ⑤ 새로 이웃이 된 두 자리에서만 다음 교차 자리를 예약한다.
scheduleAt(now, from - 1, from);
scheduleAt(now, from + after.length - 1, from + after.length);
```

전개 입력의 처음 세 걸음이 그 자리예요. x = 0 에 끝점이 셋 몰려 있어 y 가 작은 것부터 하나씩 들어갑니다.

<!--proof:walk-insert-->

| 걸음 | 사건점 | 하는 일 | 걸음 뒤 status | ⑤ 예약 판정 |
| --- | --- | --- | --- | --- |
| T1 | (0,0) | 시작 s0 | s0 | 아래 경계 없음 · 위 경계 없음 |
| T2 | (0,6) | 시작 s1 | s0 s1 | 아래 s0–s1 (3,3) 예약 · 위 경계 없음 |
| T3 | (0,8) | 시작 s3 | s0 s1 s3 | 아래 s1–s3 선분 안에서 안 만남 · 위 경계 없음 |

x = 0 의 끝점 3 개가 y 가 작은 것부터 들어가고, 예약이 붙는 걸음은 T2 하나입니다.

<!--/proof-->

`T2` 에서 s0 과 s1 이 처음으로 이웃이 되고, 두 직선이 두 선분 안의 (3,3) 에서 만나 사건 큐에 들어갑니다. `T3` 에서 s3
이 맨 위에 들어가 s1 과 이웃이 되지만, 두 직선이 만나는 자리가 선분 밖이라 예약이 없어요. 두 경계의 계산은 「아이디어
상세」의 5단계 표에 있습니다.

#### 짚고 가기 — 시작하는 선분은 자리에 넣기만 하면 될 것 같다

**방금 본 ② 에서 `starting` 을 모으는 줄 하나가 남습니다.** 새로 시작하는 선분은 상태 배열에 끼워 넣기만 하면 될 것
처럼 보여요. 어차피 다음 사건점에서 이웃으로 확인될 테니까요. 그런데 시작 끝점이 **다른 선분 위에 있는** 경우가
있습니다. T 자로 만나는 두 선분을 스위프 선 두 자리에서 봤어요.

<!--proof:pause-tee-->

| 스위프 선 | s0 의 y | s1 의 y |
| --- | ---: | ---: |
| x = 2 | 0 | 0 |
| x = 4 | 0 | 2 |

s1 이 시작하는 점 (2,0) 이 s0 위에 있고, 그 오른쪽에서는 두 선분의 y 가 갈립니다. 두 선분이 공유하는 점은 (2,0) 하나뿐입니다.

<!--/proof-->

s1 이 시작하는 점이 두 선분이 공유하는 유일한 점이라, 여기서 안 세면 그다음에는 두 선분이 이 점에서 만났다는 것을
확인할 자리가 없습니다. 시작하는 선분을 모으는 자리를 빼고 실행해 봅시다.

```ts
const meeting = [...through];   // ← 시작하는 선분을 안 모으는 판
```

<!--proof:pause-start-->

| 배치 | 선분 | 정본 | 안 모으는 판 | 대조 |
| --- | ---: | ---: | ---: | --- |
| T 자로 만난다 | 2 | 1 | 0 | 어긋난다 |
| 끝점끼리 이어 붙는다 | 2 | 1 | 0 | 어긋난다 |
| 같은 직선 위에서 겹친다 | 2 | 1 | 1 | 같다 |
| 전개 입력 | 5 | 4 | 4 | 같다 |
| 가로 둘과 세로 둘 | 4 | 4 | 4 | 같다 |

5 배치 가운데 2 배치에서 답이 어긋납니다.

<!--/proof-->

**T 자와 끝점 이어 붙기에서 답이 0 이 됩니다.** 반면 같은 직선 위에서 겹치는 배치와 전개 입력은 **답이 그대로예요.**
같은 직선 위에서 겹치는 두 선분은 겹친 구간의 다른 끝점 사건에서 토막으로 다시 잡히고, 전개 입력은 시작 끝점에서 만나는
짝이 없기 때문입니다. 답이 안 틀린다고 이 자리를 빼도 되는 것은 아닙니다. 틀리는 배치가 실제로 있고, 그 배치가 테스트에
없으면 조용히 지나갑니다.

#### 짚고 가기 — 세로 선분도 상태 배열에 넣으면 될 것 같다

**상태 배열은 「그 x 에서의 y」로 순서를 정합니다.** 그러면 세로 선분은 어디에 넣어야 할까요. 세로 선분은 한 x 에서
y 가 구간 전체라 값이 하나로 안 정해지고, 순서를 매길 자리가 없습니다. s2 는 x = 2 에서 y 가 1 부터 5 까지인데, 그
x 에서 s0 은 2, s1 은 4 를 지나요(「아이디어 상세」 6단계 표). s2 를 s0 위에 둘지 아래에 둘지는 둘 다 맞고 둘 다
틀립니다. 그래서 세로 선분은 여는 자리에서 y 범위로 한 번에 셉니다. 이때 범위의 위끝을 세로 선분의 위 끝점이 아니라
지금 사건점으로 잡으면 어떻게 되는지 실행해 봅시다.

```ts
const to = firstAbove(now);   // ← 위끝을 사건 자리로 바꾼 판
for (let at = firstNotBelow(now); at < to; at++) {
  record(id, status[at] as number);
}
```

| 배치 | 선분 | 정본 | 위끝을 바꾼 판 | 바꾼 줄 | 대조 |
| --- | ---: | ---: | ---: | --- | --- |
| 가로 둘과 세로 둘 | 4 | 4 | 0 | 지난다 | 어긋난다 |
| 전개 입력 | 5 | 4 | 2 | 지난다 | 어긋난다 |
| 세 선분이 한 점에서 만난다 | 3 | 3 | 3 | 지난다 | 같다 |
| 같은 직선 위에서 겹친다 | 2 | 1 | 1 | 안 지난다 | 같다 |
| 평행하고 떨어져 있다 | 3 | 0 | 0 | 안 지난다 | 같다 |

5 배치 가운데 2 배치에서 답이 어긋납니다. 아래 2 배치는 세로 선분이 없어 바꾼 줄을 지나지 않습니다.

<!--/proof-->

**가로 둘과 세로 둘에서 답이 0 이 됩니다.** 여는 자리는 세로 선분의 아래 끝점이라, 위끝을 그 자리로 잡으면 범위가
그 점 하나로 좁아져 위쪽의 교차를 하나도 못 셉니다. 세 선분이 한 점에서 만나는 배치는 답이 그대로예요. 세로 선분
위의 교차점이 다른 두 선분의 교차점이기도 해서, 그 사건점에서 토막이 열려 있는 세로 선분과도 짝을 세기 때문입니다. 아래 두 배치는 세로
선분이 없어 바꾼 줄까지 가지도 않으니 「같다」의 뜻이 다릅니다.

#### 3. 세로 선분은 y 범위로 한 번에 센다

**① 과 ④ 가 하는 일이 이것입니다.** 세로 선분을 여는 자리에서 두 가지를 봅니다. 이미 열려 있는 다른 세로 선분과,
상태 배열에서 y 범위에 드는 선분이에요. 위 끝점에서 닫습니다.

```ts
// ① 이 자리에서 시작하는 세로 선분을 연다.
for (const id of uprightLow.get(here) ?? []) {
  const v = segs[id] as Seg;
  for (const other of upright) record(id, other);
  const top: Spot = { x: v.hix, y: v.hiy, d: 1n };
  const to = firstAbove(top);
  for (let at = firstNotBelow(now); at < to; at++) record(id, status[at]);
}
// ④ 이 자리에서 끝나는 세로 선분을 닫는다.
for (const id of uprightHigh.get(here) ?? []) {
  const at = upright.indexOf(id);
  if (at >= 0) upright.splice(at, 1);
}
```

#### 4. 교차점에서 위아래를 뒤집는다

**③ 이 하는 일입니다.** 교차점을 꺼내면 그 점을 지나는 선분이 상태 배열에서 이어진 한 토막이에요. 그 점 **뒤**의
위아래는 기울기가 정합니다.

```ts
// ③ 여기서 끝나는 선분을 빼고, 남은 것을 이 자리 뒤의 순서로 다시 놓는다.
const ending = new Set(endAt.get(here) ?? []);
const after = [
  ...through.filter((id) => !ending.has(id)),
  ...starting,
].sort((x, y) => slopeOrder(segs[x] as Seg, segs[y] as Seg) || x - y);
status.splice(from, through.length, ...after);
```

`T6` 에서 토막 s0 s1 이 s1 s0 으로 뒤집히고, 위로 올라온 s0 이 s3 과 새 이웃이 되어 (16/3,16/3) 이 예약됩니다. 그 자리는
분수라서 배정밀도로 담으면 끝없는 소수가 잘린 값이 되고, 어느 자리가 앞인지 다투는 순간 반올림이 답을 정할 수 있어요. 그래서 자리를
정수 셋으로 적어 두고 대소는 곱셈으로 정합니다.

```ts
// a/b 와 c/d 의 대소는 a·d 와 c·b 의 대소와 같다. 분모가 양수라 부호가 안 바뀐다.
function cmpSpot(a: Spot, b: Spot): number {
  const dx = a.x * b.d - b.x * a.d;
  if (dx !== 0n) return sign(dx);
  return sign(a.y * b.d - b.y * a.d);
}
```

#### 6. 전체 코드

여기까지 만든 조각을 한 파일로 놓으면 이렇습니다. 조각에서 안 보인 것이 둘 있어요. 선분이 둘 미만이면 짝이 없으므로
바로 0 을 돌려주는 줄과, 같은 자리가 사건 큐에 여러 번 들어갔을 때 한 번만 처리하려고 같은 자리를 전부 꺼내 버리는
줄입니다.

```ts
export type Point = [number, number];
export type Segment = [Point, Point];

/** 사건이 일어나는 자리. 좌표는 `(x/d, y/d)` 이고 `d` 는 언제나 양수다. */
interface Spot {
  x: bigint;
  y: bigint;
  d: bigint;
}

/** 두 끝점을 사전순으로 세워 둔 선분. `lo` 가 앞선 끝점이다. */
interface Seg {
  id: number;
  lox: bigint;
  loy: bigint;
  hix: bigint;
  hiy: bigint;
  dx: bigint;
  dy: bigint;
  vertical: boolean;
}

/** 부호만 돌려준다. 크기는 어디서도 쓰지 않는다. */
function sign(v: bigint): number {
  return v > 0n ? 1 : v < 0n ? -1 : 0;
}

function gcd(a: bigint, b: bigint): bigint {
  let x = a < 0n ? -a : a;
  let y = b < 0n ? -b : b;
  while (y !== 0n) {
    const t = x % y;
    x = y;
    y = t;
  }
  return x;
}

/**
 * 분자 둘과 분모를 최대공약수로 나눈다.
 *
 * 같은 자리가 언제나 같은 세 수로 적혀야 사전 열쇠가 맞는다. 줄이지 않으면 `(2,2)` 가
 * 어떤 경로에서는 `4/4/2` 로 적혀 끝점 `(2,2)` 와 다른 자리로 읽힌다.
 */
function reduced(x: bigint, y: bigint, d: bigint): Spot {
  const g = gcd(gcd(x, y), d);
  return g > 1n ? { x: x / g, y: y / g, d: d / g } : { x, y, d };
}

/** 사전순 대소 — x 가 먼저이고 같으면 y 다. */
function cmpSpot(a: Spot, b: Spot): number {
  const dx = a.x * b.d - b.x * a.d;
  if (dx !== 0n) return sign(dx);
  return sign(a.y * b.d - b.y * a.d);
}

/** 자리를 문자열 하나로 적는다. 사전에서 끝점을 찾는 열쇠다. */
function spotKey(p: Spot): string {
  return `${p.x}/${p.y}/${p.d}`;
}

/**
 * 자리 `p` 가 선분 `s` 의 직선보다 위면 1, 아래면 −1, 직선 위면 0.
 *
 * 세 점의 방향 판정과 같은 식이고, 분모 `d` 가 양수라 곱해도 부호가 안 바뀐다.
 */
function orient(s: Seg, p: Spot): number {
  return sign(s.dx * (p.y - s.loy * p.d) - s.dy * (p.x - s.lox * p.d));
}

/** 기울기 대소. 상태 배열에 담기는 선분은 세로가 아니라 `dx` 가 양수다. */
function slopeOrder(a: Seg, b: Seg): number {
  return sign(a.dy * b.dx - b.dy * a.dx);
}

/** 두 끝점을 사전순으로 세운다. */
function toSeg(raw: Segment, id: number): Seg {
  const [a, b] = raw;
  const front = a[0] < b[0] || (a[0] === b[0] && a[1] <= b[1]);
  const lo = front ? a : b;
  const hi = front ? b : a;
  const lox = BigInt(lo[0]);
  const loy = BigInt(lo[1]);
  const hix = BigInt(hi[0]);
  const hiy = BigInt(hi[1]);
  return {
    id,
    lox,
    loy,
    hix,
    hiy,
    dx: hix - lox,
    dy: hiy - loy,
    vertical: lo[0] === hi[0],
  };
}

/**
 * 두 선분이 한 점에서 가로지르는 자리. 평행하거나 만나는 점이 선분 밖이면 `null`.
 *
 * 같은 직선 위의 두 선분은 분모가 0 이라 여기서 `null` 이 된다. 그 짝은 한쪽 끝점이 다른
 * 선분 위에 있으므로 끝점 사건에서 세어진다.
 */
function crossingSpot(a: Seg, b: Seg): Spot | null {
  let den = a.dx * b.dy - a.dy * b.dx;
  if (den === 0n) return null;
  const wx = b.lox - a.lox;
  const wy = b.loy - a.loy;
  let tn = wx * b.dy - wy * b.dx;
  let un = wx * a.dy - wy * a.dx;
  if (den < 0n) {
    den = -den;
    tn = -tn;
    un = -un;
  }
  if (tn < 0n || tn > den || un < 0n || un > den) return null;
  return reduced(a.lox * den + tn * a.dx, a.loy * den + tn * a.dy, den);
}

/** 최소 힙에 자리 하나를 넣는다. */
function heapPush(heap: Spot[], p: Spot): void {
  heap.push(p);
  let at = heap.length - 1;
  while (at > 0) {
    const parent = (at - 1) >> 1;
    if (cmpSpot(heap[at] as Spot, heap[parent] as Spot) >= 0) break;
    const keep = heap[at] as Spot;
    heap[at] = heap[parent] as Spot;
    heap[parent] = keep;
    at = parent;
  }
}

/** 사전순으로 가장 앞선 자리를 꺼낸다. */
function heapPop(heap: Spot[]): Spot {
  const top = heap[0] as Spot;
  const last = heap.pop() as Spot;
  if (heap.length > 0) {
    heap[0] = last;
    let at = 0;
    for (;;) {
      const left = at * 2 + 1;
      const right = left + 1;
      let small = at;
      if (
        left < heap.length &&
        cmpSpot(heap[left] as Spot, heap[small] as Spot) < 0
      ) {
        small = left;
      }
      if (
        right < heap.length &&
        cmpSpot(heap[right] as Spot, heap[small] as Spot) < 0
      ) {
        small = right;
      }
      if (small === at) break;
      const keep = heap[at] as Spot;
      heap[at] = heap[small] as Spot;
      heap[small] = keep;
      at = small;
    }
  }
  return top;
}

/**
 * 선분 배열에서 서로 교차하는 선분 쌍의 개수.
 *
 * 끝점끼리 만나기만 해도, 같은 직선 위에서 구간을 공유해도 한 쌍으로 센다.
 * 같은 점에서 `m` 개가 만나면 그 안의 모든 짝을 세므로 `m(m−1)/2` 쌍이다.
 */
export function bentleyOttmann(segments: Segment[]): number {
  const n = segments.length;
  if (n < 2) return 0;
  const segs = segments.map(toSeg);

  const events: Spot[] = [];
  const startAt = new Map<string, number[]>();
  const endAt = new Map<string, number[]>();
  const uprightLow = new Map<string, number[]>();
  const uprightHigh = new Map<string, number[]>();
  const fileInto = (
    book: Map<string, number[]>,
    at: string,
    id: number,
  ): void => {
    const got = book.get(at);
    if (got === undefined) book.set(at, [id]);
    else got.push(id);
  };
  for (const s of segs) {
    const lo: Spot = { x: s.lox, y: s.loy, d: 1n };
    const hi: Spot = { x: s.hix, y: s.hiy, d: 1n };
    heapPush(events, lo);
    heapPush(events, hi);
    fileInto(s.vertical ? uprightLow : startAt, spotKey(lo), s.id);
    fileInto(s.vertical ? uprightHigh : endAt, spotKey(hi), s.id);
  }

  /** 세로가 아닌 활성 선분. 스위프 자리에서의 y 오름차순이다. */
  const status: number[] = [];
  /** 지금 열려 있는 세로 선분. 전부 지금 사건 자리의 x 에 있다. */
  const upright: number[] = [];
  const seen = new Set<number>();
  let pairs = 0;

  const record = (a: number, b: number): void => {
    const key = a < b ? a * n + b : b * n + a;
    if (seen.has(key)) return;
    seen.add(key);
    pairs++;
  };

  /** y 가 자리보다 작은 선분은 앞쪽에 몰려 있다. 처음으로 그렇지 않은 첨자. */
  const firstNotBelow = (p: Spot): number => {
    let lo = 0;
    let hi = status.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (orient(segs[status[mid] as number] as Seg, p) > 0) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  };

  /** 처음으로 y 가 자리보다 큰 선분의 첨자. */
  const firstAbove = (p: Spot): number => {
    let lo = 0;
    let hi = status.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (orient(segs[status[mid] as number] as Seg, p) >= 0) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  };

  const scheduleAt = (now: Spot, left: number, right: number): void => {
    if (left < 0 || right >= status.length) return;
    const q = crossingSpot(
      segs[status[left] as number] as Seg,
      segs[status[right] as number] as Seg,
    );
    if (q !== null && cmpSpot(q, now) > 0) heapPush(events, q);
  };

  while (events.length > 0) {
    const now = heapPop(events);
    while (events.length > 0 && cmpSpot(events[0] as Spot, now) === 0)
      heapPop(events);
    const here = spotKey(now);

    // ① 이 자리에서 시작하는 세로 선분을 연다. 열려 있는 세로 선분은 전부 이 자리를 지나고,
    //    상태 배열에서 이 세로 선분의 y 범위 안에 있는 선분도 전부 이 세로 선분과 만난다.
    for (const id of uprightLow.get(here) ?? []) {
      const v = segs[id] as Seg;
      for (const other of upright) record(id, other);
      const top: Spot = { x: v.hix, y: v.hiy, d: 1n };
      const to = firstAbove(top);
      for (let at = firstNotBelow(now); at < to; at++)
        record(id, status[at] as number);
      upright.push(id);
    }

    // ② 이 자리를 지나는 선분을 모은다. 상태 배열에서 방향 판정이 0 인 구간이 그것이고,
    //    여기서 시작하는 선분과 열려 있는 세로 선분도 같은 자리를 지나므로 함께 센다.
    const from = firstNotBelow(now);
    const through = status.slice(from, firstAbove(now));
    const starting = startAt.get(here) ?? [];
    const meeting = [...through, ...starting];
    for (let i = 0; i < meeting.length; i++) {
      const one = meeting[i] as number;
      for (let j = i + 1; j < meeting.length; j++)
        record(one, meeting[j] as number);
      for (const v of upright) record(one, v);
    }

    // ③ 여기서 끝나는 선분을 빼고, 남은 것을 이 자리 **뒤**의 순서로 다시 놓는다.
    //    이 자리를 지나는 선분끼리는 기울기가 큰 쪽이 위로 간다.
    const ending = new Set(endAt.get(here) ?? []);
    const after = [
      ...through.filter((id) => !ending.has(id)),
      ...starting,
    ].sort((x, y) => slopeOrder(segs[x] as Seg, segs[y] as Seg) || x - y);
    status.splice(from, through.length, ...after);

    // ④ 이 자리에서 끝나는 세로 선분을 닫는다.
    for (const id of uprightHigh.get(here) ?? []) {
      const at = upright.indexOf(id);
      if (at >= 0) upright.splice(at, 1);
    }

    // ⑤ 새로 이웃이 된 두 자리에서 다음 교차 자리를 예약한다. 가운데 토막은 전부 이 자리를
    //    지나므로 다시 만날 일이 없고, 예약할 것은 토막의 양 끝뿐이다.
    scheduleAt(now, from - 1, from);
    scheduleAt(now, from + after.length - 1, from + after.length);
  }

  return pairs;
}
```

**가장 중요한 줄은 `status.splice(from, through.length, ...after)` 입니다.** 이 한 줄이 끝나는 선분을 빼고, 시작하는
선분을 넣고, 교차점을 지난 뒤의 위아래를 한꺼번에 맞춰요. 몇 가지 입력에 불러 보면 이렇습니다.

<!--proof:final-calls-->

```text
bentleyOttmann([])                                    →  0
bentleyOttmann([[[0, 0], [4, 4]], [[0, 4], [4, 0]]])  →  1
bentleyOttmann([[[0, 0], [2, 0]], [[2, 0], [4, 2]]])  →  1
bentleyOttmann([[[0, 0], [4, 0]], [[2, 0], [6, 0]]])  →  1
bentleyOttmann(segments)                              →  4
```

### 알아 두면 좋은 개념 — 출력 민감 알고리즘

파트 1 이 값으로 보인 것에 이름 하나를 붙이고 갑니다. 이 절차의 비용은 **입력의 크기만이 아니라 답의 크기에도
붙어요.** 선분 수가 같아도 교차가 없으면 끝점 사건만 처리하고, 교차가 많으면 교차점마다 사건점이 하나씩 늘어요.
이런 성질을 가진 절차를 **출력 민감(output-sensitive) 알고리즘**이라고 부릅니다. 선분 수를 512 개로 고정하고 길이만
늘려 교차를 키워 봤어요.

<!--proof:related-output-->

| 배치(선분 512) | 교차 쌍 k | 사건점 | 이 절차의 기본 연산 | 모든 쌍 판정의 기본 연산 |
| --- | ---: | ---: | ---: | ---: |
| 흩어 놓은 길이 16 | 1 | 1,025 | 106,307 | 1,046,896 |
| 흩어 놓은 길이 128 | 106 | 1,081 | 157,934 | 1,046,840 |
| 흩어 놓은 길이 1,024 | 5,270 | 3,728 | 874,680 | 1,046,840 |
| 흩어 놓은 길이 4,096 | 26,069 | 11,800 | 3,491,736 | 1,046,708 |

선분 수는 네 줄 모두 512 입니다. 교차 쌍이 1 에서 26,069 로 늘 때 이 절차의 기본 연산은 32.85 배가 되고, 모든 쌍 판정은 1.00 배입니다.

<!--/proof-->

모든 쌍 판정은 교차가 몇 개든 쌍 전부를 판정하므로 기본 연산이 거의 그대로이고, 이 절차는 교차 쌍과 사건점을 따라
늘어납니다.

| 비용이 붙는 곳 | 절차 | 답이 0 일 때 |
| --- | --- | --- |
| 입력의 크기 | 모든 쌍 판정 — 언제나 `n(n−1)/2` 쌍 | 그대로 쌍 전부를 판정한다 |
| 입력과 출력의 크기 | 이웃 교차 예약 — 사건점 `2n + k` 개 | 끝점 사건만 처리한다 |

이 이름은 이 편에만 있는 것이 아니에요. [`convexHull` 가이드](../convexHull/convexHull-guide.md)의 경쟁 설계인 선물
포장은 껍질 위의 점 수에 비용이 붙고, [`dfsAllPaths` 가이드](../../graph/dfsAllPaths/dfsAllPaths-guide.md)는 경로를
적는 데 드는 비용이 바닥이라 같은 이름을 씁니다. 비용을 입력 크기만으로 적으면 이런 절차의 성질이 통째로 사라져요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 이 절차를 어떤 과제에 쓰는지, 교차점을 정수로 적는 값이 얼마나 커지는지, 사건점마다
무엇이 늘 참인지, 비용이 얼마인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 선분이 많고 교차가 쌍의 수보다 훨씬 적다 | 비용이 교차 쌍의 수에 붙는다 | 사건점이 `2n + k` 개 |
| 교차하는 짝을 전부 알아야 한다 | 「하나라도 교차하는가」가 아니다 | 교차점을 예약하고 토막마다 짝을 센다 |
| 좌표가 정수다 | 교차점을 정수 셋으로 정확히 적을 수 있다 | 판정 경로에 배정밀도가 없다 |
| 입력이 한 번에 전부 주어진다 | 선분이 하나씩 도착하며 답을 묻지 않는다 | 끝점을 처음에 사건 큐에 다 넣는다 |

묻는 것이 조금만 달라져도 고르는 절차가 바뀝니다.

| 묻는 것 | 고르는 절차 | 그 이유 |
| --- | --- | --- |
| 교차하는 쌍의 수나 목록 | 이웃 교차 예약 | 비용이 `n` 과 `k` 로 정해진다 |
| 교차가 하나라도 있는가 | 교차점을 예약하지 않는 판 | 처음 교차를 찾으면 멈추므로 순서를 뒤집을 일이 없다 |
| 교차가 쌍 대부분이다 | 모든 쌍 판정 | 답 자체가 쌍의 수만큼이라 아낄 것이 없다 |
| 선분이 하나씩 도착한다 | 공간 색인 | 사건점을 미리 못 세운다 |

#### 문제에서 이것을 떠올리게 하는 단서

- **「선분 여러 개」와 「교차」가 한 문장에 함께 나옵니다.** 둘 사이의 교차 판정은 다른 과제이고
  ([`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-guide.md)), 여러 개가 되는 순간 쌍의 수가 제곱이 됩니다.
- **답이 「개수」이거나 「목록」입니다.** 교차하는 짝의 수나 교차점의 좌표를 요구하면 이 틀이 그대로 맞아요.
- **선분 수가 10 만 규모인데 시간이 1 초 안팎입니다.** 쌍의 수가 수십억이라 모든 쌍 판정이 빠지고, 남는 것이
  「가까운 것만 본다」류입니다.
- **도로망 · 배선 · 지도 경계 같은 말이 나옵니다.** 선분이 길고 교차가 드문 입력이라 이 절차의 조건과 맞습니다.
- **「같은 점에서 셋 이상이 만나면」이라는 단서가 붙습니다.** 퇴화 배치를 따로 물었다는 뜻이고, 이 절차는 그 자리를
  지나는 선분을 한 토막으로 잡아 처리합니다.

#### 실제로 쓰이는 곳

- **CGAL 의 `Surface_sweep_2`** — 계산기하 라이브러리 CGAL 의 곡선 교차 계산 엔진입니다. 소스 헤더가 *"Surface_sweep_2
  is a class that implements the sweep line algorithm based on the algorithm of Bentley and Ottmann. It extends the
  algorithm to support not only segments but general x-monotone curves as well and isolated points."* 라고 적고 있어요.
  1차 출처: [`Surface_sweep_2/include/CGAL/Surface_sweep_2.h`](https://raw.githubusercontent.com/CGAL/cgal/master/Surface_sweep_2/include/CGAL/Surface_sweep_2.h)
  (2026-09-07 조회).
- **Rust `geo` 크레이트의 `sweep::Intersections`** — 선분 모음의 모든 교차를 내는 구조입니다. 문서가 *"Find all
  intersections within a collection of line segments using a simplified Bentley-Ottmann sweep."* 라고 적고, 언제 모든
  쌍 판정보다 나은지도 수로 적어 뒀어요 — 선분마다 만나는 상대가 전체의 10% 미만이면 이쪽이 낫고, 선분 1,000 개라면
  교차가 10 만 개를 넘어야 모든 쌍 판정이 빨라집니다. 1차 출처:
  [`geo 0.33.1` 문서](https://docs.rs/geo/latest/geo/algorithm/sweep/struct.Intersections.html) (2026-09-07 조회).
- **원 논문** — Jon Louis Bentley · Thomas Ottmann, *"Algorithms for Reporting and Counting Geometric Intersections"*,
  IEEE Transactions on Computers 28(9), 643–647, 1979
  ([DOI 10.1109/TC.1979.1675432](https://doi.org/10.1109/TC.1979.1675432), 서지는
  [DBLP 기록](https://dblp.org/rec/journals/tc/BentleyO79.html) 2026-09-07 조회).

인용한 자리를 어디까지 확인했는지 적어 둡니다.

| 출처 | 확인한 범위 |
| --- | --- |
| CGAL 소스 헤더의 문장 | 원문을 열어 확인했다 |
| geo 크레이트 문서의 문장 | 원문을 열어 확인했다 |
| 원 논문 | 서지만 DBLP 기록으로 확인했다. 본문은 유료라 열지 못했다 |
| 지도 · CAD 제품이 이 절차를 쓴다는 말 | 1차 출처를 못 찾아 싣지 않는다 |

#### 경쟁 설계와의 대조

**경쟁 설계는 격자 나누기입니다.** 좌표 상자를 가로세로 `⌈√n⌉` 등분한 칸으로 나누고, 선분마다 자기 좌표 상자가 걸치는
칸에 이름을 적어 둔 다음, 같은 칸에 이름이 함께 적힌 짝만 교차 판정해요. 교차하는 두 선분은 교점이 든 칸에 둘 다 이름이
적히므로 이 절차도 정확합니다. 칸을 정하는 나눗셈은 배정밀도라서 좌표가 아주 커지면 칸이 어긋날 수 있는데, 여기서 잰
범위(한 변 4096)에서는 매 실행마다 정본과 답이 같은 것을 하네스가 확인합니다.

| 설계 | 후보를 거르는 방법 | 선분이 길 때 |
| --- | --- | --- |
| 이웃 교차 예약 | 스위프 선 위의 순서를 들고, 이웃이 아닌 짝은 안 본다 | 교차 수만큼만 늘어난다 |
| 격자 나누기 | 순서 없이 같은 칸에 든 짝을 전부 본다 | 좌표 상자가 칸을 여러 줄 덮어 후보가 불어난다 |

**같은 입력에서 이 글 전체와 같은 기준으로 나란히 잽니다.** 계수는 기본 연산(정수 곱셈과 자료 접근을 각각 1)과 추가로
잡는 칸이에요. 입력 가족은 둘로 고정하고 매개변수 하나만 바꿉니다. 격자무늬 가족은 상자를 가로지르는 가로 선분과 세로
선분을 반씩 놓고 선분 수를 바꾸고, 흩어 놓은 가족은 선분 512 개를 씨앗 20260907 의 32 비트 xorshift 난수로 흩되 길이만
바꿔요. 좌표 상자는 한 변 4096 입니다. 전개 입력은 계수가 세 자리라 순서가 뒤집히는 자리가 안 나와서, 규모를 키운 가족을

### 수식 정의와 유도

선분 `a` 를 점 $A_0$ 에서 방향 $r_a$ 로 가는 것으로 적고, 선분 `b` 를 점 $B_0$ 에서 방향 $r_b$ 로 가는 것으로 적습니다.
두 벡터의 외적은 $u \times v = u_x v_y - u_y v_x$ 이고, 선분 위의 점은 매개변수 $t \in [0, 1]$ 로 $A_0 + t\,r_a$ 예요.
두 직선의 교점은 다음 값으로 정해집니다.

$$
D = r_a \times r_b, \qquad w = B_0 - A_0, \qquad t = \frac{w \times r_b}{D}, \qquad u = \frac{w \times r_a}{D}
$$

$D = 0$ 이면 두 직선이 평행하고, 그렇지 않으면 교점이 하나입니다. 그 교점이 두 선분 안쪽에 있을 조건은 $0 \le t \le 1$
이고 $0 \le u \le 1$ 이에요. 전개 입력의 s0 과 s3 에 넣어 계산해 봅시다.

<!--proof:math-verify-->

| 항 | 값 |
| --- | --- |
| A₀ · r_a | (0,0) · (8,8) |
| B₀ · r_b | (0,8) · (8,-4) |
| D = r_a × r_b | 8·(-4) − 8·8 = -96 |
| w = B₀ − A₀ | (0,8) |
| w × r_b | 0·(-4) − 8·8 = -64 |
| t = (w × r_b) / D | 2/3 |
| w × r_a | 0·8 − 8·8 = -64 |
| u = (w × r_a) / D | 2/3 |
| A₀ + t · r_a | (16/3,16/3) |

t 와 u 가 둘 다 0 과 1 사이라 교점이 두 선분 안쪽이고, 교점은 (16/3,16/3) 으로 전개의 T7 사건점과 같습니다.

<!--/proof-->

교점의 좌표 $A_0 + t\,r_a$ 를 분모 $D$ 로 맞추면 정수 셋으로 적힙니다.

$$
x^{*} = \frac{A_{0x} D + (w \times r_b)\, r_{ax}}{D}, \qquad y^{*} = \frac{A_{0y} D + (w \times r_b)\, r_{ay}}{D}
$$

이 식을 그대로 코드로 옮기면 나눗셈이 한 번도 안 나와요.

```ts
let den = a.dx * b.dy - a.dy * b.dx;
if (den === 0n) return null;
let tn = (b.lox - a.lox) * b.dy - (b.loy - a.loy) * b.dx;
if (den < 0n) { den = -den; tn = -tn; }
return reduced(a.lox * den + tn * a.dx, a.loy * den + tn * a.dy, den);
```

**사건점의 수를 세어 봅시다.** 끝점 자리의 집합을 $P$, 예약된 교차점 가운데 끝점이 아닌 것의 집합을 $Q$ 라 하면 두
집합이 겹치지 않으므로 $E = |P| + |Q|$ 이고, 끝점이 겹치면 $|P| < 2n$ 입니다. 예약은 교차 쌍 하나에서 많아야 한 자리를
만드므로 $|Q| \le k$ 예요. 작은 배치 다섯에 넣어 확인합니다. 표의 P · Q 는 두 집합의 크기입니다.

<!--proof:math-check-->

| 배치 | n | 2n | 끝점 자리 P | 끝점이 아닌 교차점 Q | E |
| --- | ---: | ---: | ---: | ---: | ---: |
| 평행하고 떨어져 있다 | 3 | 6 | 6 | 0 | 6 |
| 세 선분이 한 점에서 만난다 | 3 | 6 | 6 | 1 | 7 |
| 전개 입력 | 5 | 10 | 10 | 2 | 12 |
| 가로 둘과 세로 둘 | 4 | 8 | 8 | 0 | 8 |
| 셋이 서로 다 교차한다 | 3 | 6 | 6 | 3 | 9 |

5 배치 가운데 5 배치에서 E 가 P 와 Q 의 합이고, 5 배치에서 P 가 2n 과 같습니다.

<!--/proof-->

$$
E \;=\; |P| + |Q| \;\le\; 2n + k
$$

**이제 정수들이 얼마나 커지는지 임의의 좌표 상한에서 닫습니다.** 좌표의 절댓값이 $C$ 이하이면 방향 벡터의 각 성분이
$2C$ 이하이고, 외적은 곱 둘의 차라 $2 \cdot (2C)^2$ 을 넘지 않아요.

$$
|D| = |r_{ax} r_{by} - r_{ay} r_{bx}| \le 2 \cdot (2C)^2 = 8C^2
$$

분자의 두 항을 따로 잽니다. $|A_{0x}| \le C$ 이고 $|D| \le 8C^2$ 이라 첫 항이 $8C^3$ 이하이고, $|w \times r_b| \le 8C^2$
이고 $|r_{ax}| \le 2C$ 라 둘째 항이 $16C^3$ 이하예요. 두 자리의 앞뒤를 정할 때는 분자에 상대의 분모를 곱하고, 과제의
$C = 10^9$ 을 넣은 값은 식 아래 표에 있습니다.

$$
|A_{0x} D + (w \times r_b)\, r_{ax}| \;\le\; 8C^3 + 16C^3 \;=\; 24C^3, \qquad 24C^3 \cdot 8C^2 \;=\; 192C^5
$$

<!--proof:math-digits-->

| 값 | 닫힌 형태 | C = 10^9 에서 | 비트 |
| --- | --- | ---: | ---: |
| 분모 | 8C² | 8000000000000000000 | 63 |
| 분자 | 24C³ | 24000000000000000000000000000 | 95 |
| 자리 대소의 곱 | 192C⁵ | 192000000000000000000000000000000000000000000000 | 158 |
| 배정밀도 정수 한계 | 2^53 | 9007199254740992 | 54 |

좌표 상한 1,000,000,000 안에 흩은 선분 24 개를 실제로 실행하면 가장 큰 교차점 분자가 1201171897766175270928522650, 분모가 1968527748915996635 입니다. 자리 대소를 재는 곱의 상한은 배정밀도 정수 한계의 2.13e+31 배입니다.

<!--/proof-->

158 비트짜리 곱의 부호를 배정밀도로 정하려 하면 값이 아니라 반올림이 답을 정하게 되고, 사건점의 앞뒤가 한 번 어긋나면
상태 배열의 순서가 어긋나 짝을 놓칩니다. 그래서 판정 경로에 배정밀도를 한 번도 쓰지 않아요.

**마지막으로 과제의 규모를 넣습니다.** 사건점이 $E$ 개이고 사건점마다 힙 연산이 상수 개라 힙의 몫이 $E \lceil \log_2 E
\rceil$ 을 따르고, $E \le 2n + k$ 입니다. 선분 수 상한 $10^5$ 에 교차 수 네 가지를 넣어 봅니다.

<!--proof:math-count-->

| k 의 크기 | k | E 의 상한 2n + k | ⌈log₂ E⌉ | E · ⌈log₂ E⌉ |
| --- | ---: | ---: | ---: | ---: |
| 교차가 없다 | 0 | 200,000 | 18 | 3.60e+6 |
| 교차가 n 개 | 100,000 | 300,000 | 19 | 5.70e+6 |
| 교차가 n ⌈log₂ n⌉ 개 | 1,700,000 | 1,900,000 | 21 | 3.99e+7 |
| 교차가 최대 | 4,999,950,000 | 5,000,150,000 | 33 | 1.65e+11 |

선분 수 100,000 을 넣은 값입니다. 교차가 없으면 사건점이 200,000 개이고, 교차가 최대이면 답 k 자체가 4,999,950,000 입니다.

<!--/proof-->

교차가 없으면 힙의 몫이 수백만 번이라 예산 안이고, 교차가 최대인 배치는 답 자체가 수십억 쌍이라 어떤 절차도 1 초 안에
다 셀 수 없습니다.

### 불변식 — 사건점 하나를 처리한 직후 상태 배열은 그 자리 뒤의 y 순서다

**세울 문장은 이것입니다.** 사건점 하나를 처리한 직후, 상태 배열에 든 선분들은 그 자리의 x 에서 지나는 y 가 줄지 않는
순서이고, **그 자리를 지나는 선분끼리는 기울기 오름차순**입니다. 「언제」가 중요해요. 사건점 하나를 다 처리한 직후이고,
처리하는 도중에는 성립하지 않습니다.

| 같은 y 가 나오는 경우 | 순서를 정하는 것 |
| --- | --- |
| 같은 사건점을 지나는 선분 둘 | 그 점 뒤에서 위로 가는 쪽, 곧 기울기가 큰 쪽이 뒤 |
| 같은 직선 위에서 겹치는 선분 둘 | 기울기가 같아 번호가 작은 쪽이 앞 |

같은 y 가 나올 수 있으므로 「오름차순」이 아니라 「줄지 않는 순서」라고 적습니다. **유지되는 것을 걸음마다 값으로
봅니다.** 상태 배열을 바꾸는 갈래는 시작 · 끝 · 교차점의 뒤집기이고, 세 갈래가 다 같은 한 줄 `status.splice` 를 지나요.
세로 선분을 여닫는 걸음은 상태 배열을 안 바꾸지만 함께 확인했습니다. 실행이 걸음마다 이웃한 칸을 전부 비교한 결과입니다.

<!--proof:invariant-states-->

| 걸음 | 사건점 | 하는 일 | 걸음 뒤 status | 불변식 |
| --- | --- | --- | --- | --- |
| T1 | (0,0) | 시작 s0 | s0 | 지킨다 |
| T2 | (0,6) | 시작 s1 | s0 s1 | 지킨다 |
| T3 | (0,8) | 시작 s3 | s0 s1 s3 | 지킨다 |
| T4 | (2,1) | 세로 열기 s2 | s0 s1 s3 | 지킨다 |
| T5 | (2,5) | 세로 닫기 s2 | s0 s1 s3 | 지킨다 |
| T6 | (3,3) | 교차 | s1 s0 s3 | 지킨다 |
| T7 | (16/3,16/3) | 교차 | s1 s3 s0 | 지킨다 |
| T8 | (6,0) | 끝 s1 | s3 s0 | 지킨다 |
| T9 | (8,4) | 끝 s3 | s0 | 지킨다 |
| T10 | (8,8) | 끝 s0 | (비어 있음) | 지킨다 |
| T11 | (9,0) | 시작 s4 | s4 | 지킨다 |

다른 배치도 걸음마다 같은 검사를 했습니다.

| 배치 | 걸음 | 어긋난 걸음 |
| --- | ---: | ---: |

| 세 선분이 한 점에서 만난다 | 7 | 0 |
| 같은 직선 위에서 겹친다 | 4 | 0 |

전개 입력 12 걸음 가운데 12 걸음에서 불변식이 지켜지고, 다른 7 배치에서 어긋난 걸음은 모두 합쳐 0 개입니다.

<!--/proof-->

**경계에 있는 입력도 확인합니다.** 선분이 0 개나 1 개면 짝이 없어 사건 큐를 처리하기 전에 0 을 돌려주고, 끝점끼리 이어
붙은 배치와 같은 직선에 겹쳐 쌓은 배치는 사건점 하나에 여러 선분이 모입니다. 좌표가 상한인 배치도 함께 봐요.

<!--proof:invariant-edges-->

<!--/proof-->

**깨뜨려서 확인합니다.** 불변식의 뒷부분(같은 자리를 지나는 선분끼리는 기울기 오름차순)을 지키는 줄이 정렬 비교 함수예요.
기울기 대신 선분의 이름 순으로 세우면 어떻게 되는지 봅니다.

```ts
].sort((x, y) => x - y);   // ← 기울기 대신 이름 순으로 세운 판
```

<!--proof:mutant-name-order-->

| 배치 | 선분 | 정본 | 이름 순 판 | 대조 |
| --- | ---: | ---: | ---: | --- |
| 기울기가 뒤집히는 셋 | 3 | 2 | 1 | 어긋난다 |
| 셋이 서로 다 교차한다 | 3 | 3 | 3 | 같다 |
| 전개 입력 | 5 | 4 | 4 | 같다 |
| 세 선분이 한 점에서 만난다 | 3 | 3 | 3 | 같다 |
| 같은 직선 위에서 겹친다 | 2 | 1 | 1 | 같다 |

5 배치 가운데 1 배치에서 답이 어긋납니다.

<!--/proof-->

**기울기가 뒤집히는 셋에서 답이 2 대신 1 로 나옵니다.** 첫 선분과 둘째 선분이 만나 위아래가 바뀌어야 하는데,
이름 순으로 세우면 첫 선분이 계속 아래에 남아요. 그러면 아래로 내려온 둘째 선분이 셋째 선분과 이웃이 됐다는 사실을
아무도 모르고, 그 짝의 교차점이 사건 큐에 안 들어갑니다. 순서가 어긋난 배열에 이분 탐색을 하면 그 뒤로는 찾는 토막
자체가 엉뚱해져요. 나머지 넷은 답이 그대로라, 테스트가 이런 배치뿐이면 이 줄이 틀린 것을 모르고 지나갑니다.

### 비용 계산

#### 비용을 세는 과정

**준비와 사건점마다의 값을 더합니다.** 전개의 걸음으로 가르면 `T1`\~`T3` · `T11` 이 선분이 시작하는 자리, `T4` · `T5` 가
세로 선분을 여닫는 자리, `T6` · `T7` 이 교차점, `T8`\~`T10` · `T12` 가 선분이 끝나는 자리입니다. 걸음마다 기본 연산과
추가로 잡는 칸을 셌어요.

| 걸음 | 하는 일 | 기본 연산 | 추가로 잡는 칸 |
| --- | --- | ---: | ---: |

준비는 끝점 `2n` 개를 힙에 넣는 값이고, 걸음마다의 값은 힙에서 꺼내기 · 이분 탐색 둘 · 토막 다시 놓기 · 경계 두 곳의
예약 판정으로 이루어집니다. 교차점 걸음 `T6` 이 가장 무거운 것은 토막 둘을 기울기로 다시 세우고 위 경계에서 교차점을
계산해 힙에 넣기까지 하기 때문이에요.

| 사건점 하나를 처리하는 값 | 상태 배열이 배열일 때 | 균형 이진 탐색 트리일 때 |
| --- | --- | --- |
| 힙에서 꺼내기 | `O(log E)` | `O(log E)` |
| 이분 탐색 둘 | `O(log m)` | `O(log m)` |
| 토막 다시 놓기 | `O(m)` — 뒤쪽 칸을 통째로 옮긴다 | `O(log m)` |
| 경계 두 곳의 예약 | `O(1)` 판정 + `O(log E)` 넣기 | 같다 |

짝을 세는 값은 답의 크기에 붙습니다. `T4` 처럼 세로 선분이 열리는 자리에서 세는 짝과 `T6` · `T7` 처럼 토막이 둘 이상인
자리에서 세는 짝은 전부 실제 교차예요. 실제 교차가 아닌 짝을 보는 자리는 경계 두 곳의 예약 판정뿐이라 사건점마다
상수입니다. 선분 수를 두 배씩 키우며 확인했어요.

<!--proof:perf-growth-->

| 선분 | 교차 쌍 | 사건점 E | 기본 연산 | 앞 줄의 몇 배 | n log₂ n 의 몇 배 | 추가로 잡는 칸 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 512 | 20 | 1,031 | 125,627 | — | — | 4,272 |
| 1,024 | 29 | 2,064 | 283,792 | 2.26 | 2.22 | 8,581 |
| 2,048 | 53 | 4,119 | 634,829 | 2.24 | 2.20 | 17,147 |
| 4,096 | 119 | 8,240 | 1,404,554 | 2.21 | 2.18 | 34,364 |

<!--/proof-->

교차가 선분 수에 비례하는 가족이라 사건점이 거의 정확히 두 배씩 늘고, 기본 연산의 성장률이 `n log₂ n` 의 성장률 바로
위에 붙어 있습니다.

#### 케이스별 비용과 그 경계

**축 둘을 섞지 않고 적습니다.** 하나는 입력이 어떤 모양인가(케이스)이고, 다른 하나는 그 모양에서 상한만 아는가 차수까지
아는가(경계)예요.

| 케이스 | 시간 | 경계의 종류 | 근거 |
| --- | --- | --- | --- |
| 교차가 없다 | $\Theta(n \log n)$ | 타이트 | 끝점 $2n$ 개를 사전순으로 내놓으므로 비교 정렬의 하한이 그대로 붙는다 |
| 교차가 $k$ 개 · 상태 배열을 배열로 | $O((n+k)(\log n + m))$ | 상한 | 토막을 다시 놓을 때 뒤쪽 칸을 옮긴다 |
| 교차가 $k$ 개 · 상태 배열을 균형 트리로 | $\Theta((n+k)\log n)$ | 타이트 | 사건점마다 힙과 트리 연산이 상수 개다 |
| 교차가 최대 · 상태 배열을 균형 트리로 | $\Theta(n^2 \log n)$ | 타이트 | $k = n(n-1)/2$ 를 위 줄의 식에 넣은 값이다 |

**위 표가 말하는 것은 최악 보장이지 기댓값이 아닙니다.** 이 절차에는 난수가 한 군데도 안 쓰이고, 같은 입력이면 언제나
같은 수의 기본 연산을 해요. 그래서 표의 값은 그 케이스 안의 어떤 입력에서도 넘지 않는 값입니다. 「평균」을 적으려면 선분
배치의 분포를 먼저 정해야 하는데, 이 과제는 그 분포를 정할 근거가 없어서 적지 않습니다.

**총식을 한 번 정확히 적습니다.** 끝점을 힙에 넣는 준비 $2n \log(2n)$ 에 사건점마다의 값 $E(\log E + \log m + m)$ 을 더하고,
짝을 세는 값 $k$ 를 더한 것이 전부예요. 추가로 잡는 칸은 사건 큐 $E$ · 상태 배열 $m$ · 이미 센 짝의 집합 $k$ 를 합쳐
$O(n + k)$ 입니다.

| 셈에 넣은 것 | 넣지 않은 것 |
| --- | --- |
| 힙 연산 · 이분 탐색 · 토막 다시 놓기 · 짝 세기 · 이미 센 짝의 집합 조회 | 입력을 읽는 값 — 두 설계 모두 같다 |
| 교차점을 정수 셋으로 만드는 곱셈 | `bigint` 곱셈 하나의 자릿수 — 곱셈 하나를 1 로 셌다 |

좌표가 커지면 `bigint` 곱셈 하나의 비용이 자릿수에 비례해 늘어나므로, 기본 연산 하나의 값이 상수라는 것은 좌표 상한
안에서의 이야기입니다.

「교차가 많으면 느리다」는 물려받은 통념이라 그대로 쓰지 않고, 선분 64 개를 여섯 가지 모양으로 놓아 무엇이 가장 커지는지
실제로 쟀습니다.

<!--proof:worst-shape-->

| 배치 | 교차 쌍 | 사건점 | 큐 최대 | status 최대 | 기본 연산 | 추가로 잡는 칸 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 가로로 나란한 64 | 0 | 128 | 128 | 64 | 17,548 | 576 |
| 흩어 놓은 길이 16 · 64 | 0 | 128 | 128 | 2 | 8,035 | 510 |
| 흩어 놓은 길이 1024 · 64 | 97 | 161 | 128 | 19 | 20,197 | 852 |
| 한 점에 64 갈래 | 2,016 | 129 | 128 | 64 | 23,372 | 2,847 |
| 같은 직선에 64 겹 | 2,016 | 128 | 128 | 64 | 116,107 | 14,688 |
| 격자무늬 64 | 1,024 | 127 | 128 | 32 | 19,541 | 1,597 |

선분 64 개의 쌍은 2,016 개입니다. 기본 연산이 가장 많은 배치는 「같은 직선에 64 겹」 의 116,107 번이고, 가장 적은 배치는 「흩어 놓은 길이 16 · 64」 의 8,035 번입니다.

**교차 쌍이 가장 많은 배치는 둘입니다.** 한 점에 64 갈래를 모으거나 같은 직선에 64 개를 겹쳐 쌓으면 쌍 2,016 개가 전부
교차예요. 그런데 **기본 연산이 가장 많은 배치는 그중 하나뿐입니다.** 같은 직선에 겹쳐 쌓으면 116,107 번인데, 한 점에
모으면 23,372 번이에요.

| 배치 | 사건점마다 하는 일 |
| --- | --- |
| 한 점에 64 갈래 | 그 한 점이 사건점 하나다. 거기서 토막 64 개의 모든 짝을 한 번 센다 |
| 같은 직선에 64 겹 | 겹친 구간 내내 y 가 같아, 끝점 사건마다 토막 전체를 다시 모아 짝을 센다 |

이미 센 짝은 집합이 걸러 내지만, 모아서 집합을 조회하는 값은 사건점마다 그대로 듭니다. 그래서 최악 입력은 **같은 직선
위에 겹쳐 쌓은 선분 `n` 개**예요. 교차 쌍이 `n(n−1)/2` 로 최대이면서, 끝점 사건마다 토막 전체를 다시 세므로 기본 연산이
교차 쌍의 수보다도 한 자리 더 커집니다. 이 배치에서는 어떤 절차도 답 자체가 `n²` 자리라 1 초 안에 못 냅니다.

### 스스로 점검하기

이 편이 세운 것은 한 문장입니다. 교차하는 두 선분은 **교차 직전에 반드시 이웃**이므로, 이웃 관계가 바뀌는 자리 —
선분이 들어오고 나가는 끝점과 예약한 교차점 — 만 골라 처리해도 교차를 하나도 빠뜨리지 않아요.

```text
사건점 꺼내기 → 지나는 토막 잡기 → 짝 세기 → 토막 다시 놓기 → 경계 두 곳에서 교차점 예약
                └ 사전순, 같은 자리는 한 번  └ 이분 탐색 둘              └ 기울기 순     └ 선분 안 · 지금보다 뒤
```

**확인 하나만 해 볼까요?** `T6` 에서 상태 배열이 `s1 s0 s3` 이 됐는데, 그 자리에서 예약된 것이 왜 s0–s3 이고 s1–s3 이
아닐까요?

<!--check:whyRightBoundary-->
답: `T6` 에서 갈아 끼운 토막은 `s1 s0` 둘이고, 새로 맞닿는 경계는 토막의 아래와 위 두 곳입니다. 두 걸음의 경계 판정을
적으면 이렇습니다.

<!--proof:selfcheck-boundary-->

| 걸음 | 걸음 뒤 status | 경계 | 두 이웃 | 두 직선이 만나는 자리 |
| --- | --- | --- | --- | --- |
| T3 | s0 s1 s3 | 아래 경계 | s1–s3 | (-4,10) — 선분 밖 |
| T3 | s0 s1 s3 | 위 경계 | 없다 | — |
| T6 | s1 s0 s3 | 아래 경계 | 없다 | — |
| T6 | s1 s0 s3 | 위 경계 | s0–s3 | (16/3,16/3) — 예약 |

T6 에서 새로 맞닿은 짝은 위 경계 하나이고, s1–s3 은 T3 에서 이미 이웃이었습니다.

<!--/proof-->

`s1` 은 새 토막의 첫 칸이라 아래 경계를 이루는데 그 아래에 아무것도 없어 판정할 짝이 없어요. `s1` 과 `s3` 은 `T3` 에서
이미 이웃이었고, 그때 두 직선이 만나는 자리가 선분 밖이라는 것을 확인했습니다. `T6` 뒤에 둘은 이웃이 아니니 다시 볼
까닭도 없어요.
<!--/check-->

### 여러 선분의 교차 개수

풀 파일: [`bentleyOttmann.ts`](./bentleyOttmann.ts) · 테스트: [`bentleyOttmann.test.ts`](./bentleyOttmann.test.ts) · 실행: `bun test src/algorithms/geometry/bentleyOttmann/bentleyOttmann.test.ts`

#### 한 줄 요약

> 선분 배열이 주어질 때, 서로 교차하는 선분 **쌍**의 개수를 반환한다.

#### 스토리

도시 계획부의 하은은 신규 도로 노선도를 검토하고 있다. 여러 도로 노선이 지도 위에 직선 선분으로 표시되어 있고, 두 노선이 만나는 지점마다 교차로를 설치해야 한다.

같은 지점에서 세 개 이상의 노선이 동시에 만나더라도, 관리 시스템에는 "노선 쌍" 단위로 교차로를 등록한다. 두 노선의 끝점이 딱 맞닿거나 한 노선 위에 다른 노선이 겹쳐 올라타도 교차로로 인정된다.

주어진 선분 목록에서 교차하는 쌍의 개수를 구하는 함수를 만들어라.

#### 함수 인터페이스

```ts
export type Point = [number, number];
export type Segment = [Point, Point];

export function bentleyOttmann(segments: Segment[]): number;
```

- `segments` — 선분 배열. 각 원소는 `[[x1, y1], [x2, y2]]` 형태의 두 끝점.
- 반환 — 교차하는 선분 쌍의 개수. $\geq 0$ 인 정수.

#### 제약 조건

- $0 \leq N \leq 10^5$ — 여기서 $N$ 은 선분의 개수. 선분이 0개이면 0을 반환한다.
- $-10^9 \leq x, y \leq 10^9$ — 끝점 좌표 범위
- 반환값은 $\geq 0$ 인 정수
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

$N$ 개의 선분 $S = \{s_1, s_2, \ldots, s_N\}$ 중 서로 교차하는 쌍의 수를 반환한다.

$$\text{count}(S) = \left| \{ (i, j) \mid i < j,\; s_i \cap s_j \neq \emptyset \} \right|$$

교차의 기준은 다음과 같다.

- 두 선분이 내부에서 한 점에서 만나면 교차한다.
- 끝점이 다른 선분의 끝점과 일치하면 교차한다 (공유 끝점).
- 한 선분의 끝점이 다른 선분의 내부에 있으면 교차한다 (T자).
- 두 선분이 같은 직선 위에서 구간을 공유하면 교차한다 (공선 겹침).
- 같은 점에서 $k$ 개의 선분이 동시에 만나면, 쌍의 수는 $\binom{k}{2}$ 로 계산한다.

#### 예시

```ts
// X자 교차 — 두 선분이 중앙에서 만남
bentleyOttmann([[[0, 0], [4, 4]], [[0, 4], [4, 0]]]); // 1

// 분리된 두 선분 — 교차 없음
bentleyOttmann([[[0, 0], [1, 0]], [[2, 0], [3, 0]]]); // 0

// 끝점 공유 (L자)
bentleyOttmann([[[0, 0], [1, 0]], [[1, 0], [1, 1]]]); // 1

// 공선 겹침 — 구간 [2,4]를 공유
bentleyOttmann([[[0, 0], [4, 0]], [[2, 0], [6, 0]]]); // 1

// 3개 선분이 한 점에서 만남 — 쌍은 (1,2), (1,3), (2,3) 총 3쌍
bentleyOttmann([[[0, 0], [4, 4]], [[0, 4], [4, 0]], [[2, 0], [2, 4]]]); // 3

// 격자형 — 가로 2개 × 세로 2개 → 4교차
bentleyOttmann([
  [[0, 1], [10, 1]],
  [[0, 3], [10, 3]],
  [[2, 0], [2, 5]],
  [[5, 0], [5, 5]],
]); // 4

// 선분 0개
bentleyOttmann([]); // 0
```
