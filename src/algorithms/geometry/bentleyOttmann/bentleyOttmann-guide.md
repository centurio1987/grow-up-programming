# bentleyOttmann — 교차하는 두 선분은 교차 직전에 반드시 이웃이 된다

## 파트 1 — 아이디어에서 동작하는 코드까지

선분 여러 개에서 교차하는 쌍의 수를 세는 문제를 놓고, 모든 쌍을 판정하는 방법에서 출발해
쌍을 거의 안 보고도 같은 답을 내는 절차까지 값을 따라 갑니다. 코드는 조각으로 나눠 만들고
마지막에 한 파일로 모읍니다.

### 전체 컨셉

평면 위의 선분 목록을 받아 **교차하는 선분 쌍의 개수**를 답하는 문제예요. 여기서 「교차」의
뜻은 넓습니다 — 두 선분이 점을 하나라도 공유하면 교차입니다. X 자로 가로지르는 것만이 아니라
끝점끼리 만나는 L 자도, 끝점 하나가 상대 선분 위에 놓인 T 자도, 같은 직선 위에서 구간을
나눠 갖는 것도 다 한 쌍으로 셉니다.

```text
이 글이 쓰는 다섯 낱말을 여기서 갈라 둔다

  스위프 선   왼쪽에서 오른쪽으로 자리를 옮기는 가상의 세로선
  사건 자리   스위프 선이 멈추는 점. 선분의 끝점이거나 두 선분의 교차점이다
  상태 배열   그 순간 스위프 선과 만나는 선분들을 y 오름차순으로 담은 배열
  이웃        상태 배열에서 첨자가 하나 차이 나는 두 선분
  세로 선분   두 끝점의 x 가 같은 선분. 한 x 에서 y 가 하나로 안 정해진다
└ 「교차점」은 두 선분이 공유하는 점이고 「교차 쌍」은 그런 선분 둘이다. 세는 것은 쌍이다
```

도구는 하나뿐이에요. **두 선분이 교차하려면 교차하기 직전에 상태 배열에서 서로 이웃이어야
한다**는 사실입니다. 사이에 다른 선분이 끼어 있으면 위아래가 뒤집히기 전에 그 선분과 먼저
자리를 바꿔야 하니까요. 그래서 이웃인 짝만 확인해도 교차를 하나도 빠뜨리지 않습니다.

```text
선분 다섯 개를 평면에 놓으면 (전개가 끝까지 쓰는 입력이다)

 8 |3.......0...
 7 |..3....0....
 6 |1...3.0.....
 5 |.12..03.....
 4 |..X.0...3...
 3 |..2X........
 2 |..X.1......4
 1 |.02..1....4.
 0 |0.....1..4..
   +------------
    0    5    10

  s0 = (0,0)-(8,8)  ·  s1 = (0,6)-(6,0)  ·  s2 = (2,1)-(2,5) 세로
  s3 = (0,8)-(8,4)  ·  s4 = (9,0)-(11,2)
  숫자는 그 자리를 지나는 선분의 이름이고 X 는 두 선분이 함께 지나는 자리다
└ s0 과 s1 이 (3,3) 에서, s0 과 s3 이 (16/3, 16/3) 에서 만난다. s2 는 s0 과 s1 을 가로지른다
└ s4 는 x 가 9 부터라 앞의 넷과 겹치는 구간이 없다. 답은 교차 쌍 넷이다
```

**모든 쌍을 판정하는 방법과 답이 같습니다.** 다른 것은 선분 짝을 몇 번 들여다보는가예요.
배치를 일곱 개 놓고 두 절차를 나란히 실행해 봅니다.

<!--proof:concept-cases-->

```text
배치                        선분  교차 쌍  전부 대조  짝을 본 횟수
평행하고 떨어져 있다           3        0          3             2
같은 직선 위에서 겹친다        2        1          1             2
세 선분이 한 점에서 만난다     3        3          3             6
가로 둘과 세로 둘              4        4          6             5
전개 입력                      5        4         10            10
흩어 놓은 짧은 선분 512      512        1    130,816           621
격자무늬 256                 256   16,384     32,640        16,765

7 개 배치 모두 두 절차의 답이 같다. 갈리는 것은 선분 짝을 몇 번 봤는가다
└ 선분이 512 개인 아래 두 줄에서 차이가 벌어진다 — 전부 대조만 제곱으로 커진다
```

**답은 같고 짝을 보는 횟수만 갈립니다.** 선분이 늘수록 앞엣것만 제곱으로 커져요. 얼마나
갈리는지를 선분 수를 네 배씩 키우며 봅니다.

<!--proof:concept-growth-->

```text
 선분    쌍의 수  짝을 본 횟수
   64      2,016            59
  256     32,640           534
1,024    523,776         3,009
4,096  8,386,560        14,484

선분을 4 배로  쌍의 수 성장률  이 절차의 성장률
64 → 256                16.19              9.05
256 → 1,024             16.05              5.63
1,024 → 4,096           16.01              4.81

제약의 선분 수 100,000 에서 쌍의 수 4,999,950,000
└ 쌍의 수 성장률은 16 에 머물고 이 절차는 9.05 에서 4.81 로 내려간다
```

쌍의 수는 선분을 네 배로 하면 열여섯 배가 되고, 이 절차가 짝을 보는 횟수는 그보다 훨씬 덜
자랍니다. 전체 비용은 `O((n + k) log n)` 시간 · `O(n + k)` 추가 칸이에요 — `n` 은 선분의
개수, `k` 는 답인 교차 쌍의 수이고, 상태 배열을 균형 이진 탐색 트리로 둘 때의 값입니다.
이 글의 코드는 그것을 배열로 두어 칸을 옮기는 값이 더 붙어요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **두 선분의 교차 판정.** 선분 **둘**이 교차하는지는 네 방향 판정의 부호만으로 나눗셈 없이
  정해집니다. 그 판정의 정본은
  [`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-guide.md) 편이고, 이 글은
  그것을 「전부 대조」쪽에서만 씁니다 — 스위프 본체는 판정을 더 잘게 쪼개 쓰거든요.
- **방향 판정(세 점의 꺾임).** 점 `o` 에서 `a`, `b` 로 갈 때 왼쪽으로 꺾이면 양수, 오른쪽이면
  음수, 한 직선 위면 0 입니다. 이 글은 이 값을 「점이 선분보다 위인가 아래인가」로 씁니다.
  같은 판정을 껍질 사슬에 쓴 것이 [`convexHull`](../convexHull/convexHull-guide.md) 이고,
  다각형 넓이에 쓴 것이 [`polygonArea`](../polygonArea/polygonArea-guide.md) 예요.
- **최소 힙.** 가장 작은 값을 `O(log n)` 에 꺼내는 구조예요. 구현을 정본으로 다루는 편이
  [`priorityQueue`](../../../data-structures/heap/priorityQueue/priorityQueue-guide.mdx)
  입니다. 이 글은 사건 자리를 그 구조에 담습니다.
- **균형 이진 탐색 트리.** 삽입·삭제·이웃 조회가 각각 `O(log n)` 인 구조입니다.
  [`avlTree`](../../../data-structures/tree/avlTree/avlTree-guide.mdx) 가 그 정본이에요.
  이 글의 상태 배열이 마지막에 이 구조로 바뀝니다.
- **유리수를 정수 둘로 다루기.** `a/b` 와 `c/d` 의 대소는 `a·d` 와 `c·b` 의 대소와 같습니다.
  분모가 양수이기만 하면 나눗셈 없이 앞뒤가 정해져요.
- **`bigint`.** 자릿수 제한이 없는 정수 타입입니다. 이 글은 판정에 쓰는 수를 전부 이 타입으로
  둡니다.

```text
  선분 여러 개에서 교차하는 쌍의 수                <- 이 글이 다루는 것
  선분 둘이 교차하는가                             <- 다른 글이 다루는 것
  점들을 감싸는 최소 볼록 다각형                   <- 또 다른 글이 다루는 것
  점 하나가 다각형 안에 있는가                     <- 또 다른 글이 다루는 것
  가장 가까운 두 점 사이의 거리                    <- 또 다른 글이 다루는 것
```

### 아이디어 상세 — 사건 자리와 상태 배열을 떠올리는 과정

무엇을 만드는지부터 못 박고 갑니다.

```ts
type Point = [number, number];
type Segment = [Point, Point];

function bentleyOttmann(segments: Segment[]): number;
```

- 입력: 선분 배열 하나. 각 원소가 `[[x1, y1], [x2, y2]]` 이고 순서에 아무 약속이 없습니다.
- 출력: 교차하는 선분 쌍의 개수. 0 이상의 정수예요. 같은 점에서 `m` 개가 만나면 그 안의 모든
  짝을 세므로 `m(m−1)/2` 쌍입니다.
- 제약: 선분은 0 개 이상 `10^5` 개 이하이고, 좌표는 `−10^9` 이상 `10^9` 이하의 정수입니다.
  시간 1 초, 메모리 256 MB 예요.

이 글이 쓰는 기호는 열이에요. 뒤에서 뜻이 바뀌지 않도록 여기서 한 번에 못 박습니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 선분의 개수 | 0 이상 `10^5` 이하 |
| `k` | 교차하는 선분 쌍의 수. 이 함수가 내는 답이다 | 최대 `n(n−1)/2` |
| `C` | 좌표의 절댓값 상한 | `10^9` |
| `E` | 처리하는 사건 자리의 수 | 끝점 자리에 예약한 교차 자리를 더한 값 |
| `m` | 한 순간 상태 배열에 든 선분의 수 | `n` 이하 |
| `s_i` | 첨자 `i` 번째 선분 | 전개에서는 `s0` 부터 `s4` 까지다 |
| `now` | 지금 처리하는 사건 자리 | 코드에서는 `now` 다 |
| `status` | 세로가 아닌 활성 선분을 y 오름차순으로 담은 배열 | 코드에서는 `status` 다 |
| `upright` | 지금 열려 있는 세로 선분의 목록 | 코드에서는 `upright` 다 |
| `pairs` | 지금까지 센 교차 쌍의 수 | 마지막 값이 곧 답이다 |

손댈 것이 하나도 없는 방법부터 적어 봅시다. 교차하는 쌍을 세라고 하면 **쌍을 전부 만들어
하나씩 판정하기**가 먼저 나오고, 그 방법은 어떤 입력에서도 정확한 답을 냅니다.

```ts
// 가장 단순한 방법 — 쌍을 하나도 안 거르고 전부 판정한다.
let pairs = 0;
for (let i = 0; i < segments.length; i++) {
  for (let j = i + 1; j < segments.length; j++) {
    if (segmentsIntersect(segments[i], segments[j])) pairs++;
  }
}
```

이 방법이 왜 제약을 못 견디는지는 쌍의 수를 세어 보면 그 자리에서 나옵니다.

<!--proof:build-brute-->

```text
   선분        쌍의 수  지수로 적으면
      5             10        1.00e+1
  1,000        499,500        5.00e+5
 10,000     49,995,000        5.00e+7
100,000  4,999,950,000        5.00e+9

전개 입력 선분 5 개를 전부 대조하면 판정 10 번에 교차 4 쌍
└ 제약의 상한에서 판정이 5.00e+9 번이다. 1 초 안에 못 끝낸다
└ 쌍의 수는 선분 수의 제곱에 비례한다. 선분을 4 배로 하면 대조가 16 배다
```

**막힌 것은 시간만이 아닙니다. 후보를 좁히는 장치가 아예 없어요.** x 구간이 겹치지도 않는
두 선분까지 어김없이 한 번 판정합니다. 전개가 쓸 다섯 선분에서 열 짝을 각각 어떻게 다루는지
보면 그 낭비가 값으로 나옵니다.

<!--proof:build-neighbor-->

```text
짝     한쪽         다른 쪽       전부 대조의 판정  이 절차가 본 적
s0-s1  (0,0)-(8,8)  (0,6)-(6,0)   교차              들여다봤다
s0-s2  (0,0)-(8,8)  (2,1)-(2,5)   교차              들여다봤다
s0-s3  (0,0)-(8,8)  (0,8)-(8,4)   교차              들여다봤다
s0-s4  (0,0)-(8,8)  (9,0)-(11,2)  안 만난다         한 번도 안 봤다
s1-s2  (0,6)-(6,0)  (2,1)-(2,5)   교차              들여다봤다
s1-s3  (0,6)-(6,0)  (0,8)-(8,4)   안 만난다         들여다봤다
s1-s4  (0,6)-(6,0)  (9,0)-(11,2)  안 만난다         한 번도 안 봤다
s2-s3  (2,1)-(2,5)  (0,8)-(8,4)   안 만난다         한 번도 안 봤다
s2-s4  (2,1)-(2,5)  (9,0)-(11,2)  안 만난다         한 번도 안 봤다
s3-s4  (0,8)-(8,4)  (9,0)-(11,2)  안 만난다         한 번도 안 봤다

배치                     선분  전부 대조  본 짝의 종류  한 번도 안 본 짝
전개 입력                   5         10             5                 5
흩어 놓은 짧은 선분 512   512    130,816           452           130,364

다섯 선분에서는 안 본 짝이 5 개뿐이라 차이가 크게 안 보인다
└ 선분이 512 개면 짝 130,816 개 가운데 452 개만 본다
```

**거르려면 「가깝다」를 값으로 판정할 수 있어야 합니다.** 그러려면 선분들이 자리 순서로 놓여
있어야 하고, 순서를 만드는 가장 간단한 방법이 좌표 하나를 기준으로 세우는 것이에요. 가상의
세로선을 왼쪽에서 오른쪽으로 옮기면서 그 순간 세로선과 만나는 선분만 보는 것이 그 생각입니다.

```text
스위프 선을 x = 1 · x = 3 · x = 5 에 세워 보면 (전개 입력의 s0 · s1 · s3)

  x = 1              x = 3               x = 5
  s3 --- y = 7.5     s3 --- y = 6.5      s3 --- y = 5.5
  s1 --- y = 5       s0 = s1 = 3         s0 --- y = 5
  s0 --- y = 1       (같은 자리)         s1 --- y = 1
└ x = 1 에서 아래부터 s0 s1 s3 이고 x = 5 에서는 s1 s0 s3 이다 — s0 과 s1 이 자리를 바꿨다
└ 그 사이 x = 3 에서 두 선분의 y 가 같아진다. 그 자리가 교차점이다
```

**여기서 관찰 하나가 나옵니다.** 위아래가 뒤집히려면 두 선분의 y 가 한 번 같아져야 하고, 그
자리가 곧 교차점이에요. 그리고 사이에 셋째 선분이 끼어 있으면 그 선분과 먼저 자리를 바꿔야
하므로, **뒤집히기 직전에는 반드시 이웃**입니다.

```text
비이웃 짝은 이웃을 거치지 않고 뒤집힐 수 없다

  왼쪽 순서   아래  a  c  b   위
  오른쪽 순서 아래  b  c  a   위
└ a 가 b 를 지나가려면 그 전에 c 와 한 번 자리를 바꿔야 한다
└ 그러니 이웃 짝만 확인해도 교차를 하나도 빠뜨리지 않는다
```

**그러면 언제 이웃 관계가 바뀌는가**가 다음 질문이 됩니다. 셋뿐이에요 — 선분이 새로
들어올 때, 선분이 사라질 때, 그리고 두 선분이 교차점에서 위아래를 바꿀 때입니다. 그 셋이
일어나는 x 좌표만 골라 처리하면 되고, 그 자리가 「사건 자리」예요.

<!--proof:build-events-->

```text
배치                        선분   끝점  예약한 교차 자리  처리한 사건 자리  교차 쌍
평행하고 떨어져 있다           3      6                 0                 6        0
세 선분이 한 점에서 만난다     3      6                 1                 7        3
가로 둘과 세로 둘              4      8                 0                 8        4
전개 입력                      5     10                 2                12        4
흩어 놓은 짧은 선분 512      512  1,024                 1             1,025        1
격자무늬 64                   64    128                 0               127    1,024

사건 자리는 끝점에 예약한 교차 자리를 더한 수이고, 겹치는 끝점은 하나로 합쳐진다
└ 마지막 줄은 교차가 1,024 쌍인데 예약이 0 이다 — 세로 선분이 낀 짝은 여는 자리에서 바로 센다
```

**끝점 자리는 처음부터 알 수 있고 교차 자리는 실행 중에 생깁니다.** 끝점은 입력에 적혀 있으니
`2n` 개를 미리 넣어 두면 되고, 교차 자리는 두 선분이 이웃이 된 그 순간에 계산해 넣습니다.
그래서 자리를 꺼낼 때마다 「남은 것 중 가장 왼쪽」을 골라야 하고, 그것이 최소 힙의 일이에요.

```text
사건 자리를 사전순으로 꺼낸다 — x 가 먼저이고 같으면 y 다

  처음 큐   (0,0) (0,6) (0,8) (2,1) (2,5) (6,0) (8,4) (8,8) (9,0) (11,2)
  (0,6) 을 처리하며 s0 s1 이 이웃이 되어 (3,3) 을 넣는다
  (3,3) 을 처리하며 s0 s3 이 이웃이 되어 (16/3,16/3) 을 넣는다
└ 끝점 열 개로 시작해 실행 중에 둘이 더 들어가 사건 자리가 열둘이 된다
```

**그러면 상태 배열은 어떻게 유지하는가.** 사건 자리마다 그 자리를 지나는 선분을 이분 탐색으로
찾아 갈아 끼우면 되고, 새로 이웃이 된 짝에서만 다음 교차 자리를 예약하면 됩니다. 이렇게 하면
「짝을 보는 횟수」가 교차 쌍의 수를 따라가요.

<!--proof:build-tune-->

```text
배치                 교차 쌍  전부 대조  짝을 본 횟수  횟수 ÷ 전부 대조
흩어 놓은 길이 16          1    130,816           621              0.00
흩어 놓은 길이 128       106    130,816         1,956              0.01
흩어 놓은 길이 1024    5,270    130,816        12,665              0.10
격자무늬 64            1,024      2,016         1,117              0.55
격자무늬 128           4,096      8,128         4,285              0.53
격자무늬 256          16,384     32,640        16,765              0.51

교차가 적은 배치에서 비율이 0.01 아래이고, 교차가 쌍의 절반을 넘는 배치에서 0.5 언저리다
└ 들여다본 짝이 교차 쌍의 수를 따라 커진다 — 이 절차의 비용은 답의 크기에 붙는다
```

교차가 거의 없는 배치에서는 짝을 보는 횟수가 쌍의 수의 백분의 일 아래이고, 교차가 쌍의 절반에
이르는 배치에서는 0.5 언저리입니다. **비용이 입력의 크기가 아니라 답의 크기에 붙습니다.**

### 수행으로 알아보는 알고리즘 — 선분 다섯 개에서 교차 쌍 넷을 센다

끝까지 쓸 입력은 「전체 컨셉」에서 그림으로 본 선분 다섯 개예요. 이 다섯을 고른 이유는
**갈래를 하나도 안 남기고 전부 실행하기 때문**입니다 — 세로 선분이 하나 있고, 교차 자리가
둘인데 그중 하나는 좌표가 분수이고, 마지막 하나는 x 구간이 안 겹쳐 한 번도 견주지 않아요.

```text
절차 한 장

  1    선분마다 두 끝점을 사전순으로 세우고 세로인지 아닌지를 적어 둔다
  2    끝점 2n 개를 최소 힙에 넣는다
  3    큐가 빌 때까지 3-1 부터 3-6 을 되풀이한다
  3-1  가장 앞선 자리 now 를 꺼낸다. 같은 자리가 여럿이면 한 번만 처리한다
  3-2  now 에서 시작하는 세로 선분을 열고, y 범위에 드는 선분과 짝을 센다
  3-3  now 를 지나는 선분과 now 에서 시작하는 선분을 모아 모든 짝을 센다
  3-4  now 에서 끝나는 것을 빼고, 남은 토막을 기울기 오름차순으로 다시 놓는다
  3-5  now 에서 끝나는 세로 선분을 닫는다
  3-6  토막의 위아래 두 경계에서 다음 교차 자리를 예약한다
  4    센 짝의 수를 반환한다
└ 3-2 가 ①, 3-3 이 ②, 3-4 가 ③, 3-5 가 ④, 3-6 이 ⑤ 다. 전체 코드의 라벨과 같다
```

#### 1. 끝점을 사전순으로 세워 큐를 만든다

**먼저 두 끝점의 앞뒤를 정해야 합니다.** 입력은 `[[x1,y1],[x2,y2]]` 두 점만 주고 어느 쪽이
왼쪽인지 말해 주지 않아요. x 가 작은 쪽을 앞에 두되 x 가 같으면 y 가 작은 쪽을 앞에 두면,
스위프 선이 지나가는 순서와 같은 순서가 됩니다.

```ts
function toSeg(raw: Segment, id: number): Seg {
  const [a, b] = raw;
  const front = a[0] < b[0] || (a[0] === b[0] && a[1] <= b[1]);
  const lo = front ? a : b;
  const hi = front ? b : a;
  // 두 끝점의 x 가 같으면 세로 선분이다. 상태 배열에 넣지 않는다.
  return { id, lo, hi, vertical: lo[0] === hi[0] };
}
```

전개 입력 다섯을 그대로 넣어 보면 이렇게 나옵니다.

<!--proof:walk-normalize-->

```text
이름  입력          lo     hi      기울기
s0    (0,0)-(8,8)   (0,0)  (8,8)      1/1
s1    (0,6)-(6,0)   (0,6)  (6,0)     -1/1
s2    (2,1)-(2,5)   (2,1)  (2,5)     세로
s3    (0,8)-(8,4)   (0,8)  (8,4)     -1/2
s4    (9,0)-(11,2)  (9,0)  (11,2)     1/1

끝점 둘을 사전순으로 세워 앞선 쪽을 lo 로 둔다 — x 가 먼저이고 같으면 y 다
└ s2 는 두 끝점의 x 가 같아 세로 선분이고, 상태 배열에 들어가지 않는다
```

**이제 끝점을 전부 큐에 넣습니다.** 자리의 앞뒤는 사전순 — x 가 먼저이고 같으면 y 예요.
최소 힙에 넣어 두면 꺼낼 때마다 가장 앞선 자리가 나옵니다.

```ts
for (const s of segs) {
  const lo: Spot = { x: s.lox, y: s.loy, d: 1n };
  const hi: Spot = { x: s.hix, y: s.hiy, d: 1n };
  heapPush(events, lo);
  heapPush(events, hi);
  fileInto(s.vertical ? uprightLow : startAt, spotKey(lo), s.id);
  fileInto(s.vertical ? uprightHigh : endAt, spotKey(hi), s.id);
}
```

이 조각만 실행하면 큐의 내용이 이렇게 됩니다.

```text

   2  (0,6)      s1 lo
   3  (0,8)      s3 lo
   4  (2,1)      s2 lo
   5  (2,5)      s2 hi
   6  (6,0)      s1 hi
   7  (8,4)      s3 hi
   8  (8,8)      s0 hi
   9  (9,0)      s4 lo

끝점 10 개를 사전순으로 세운 것이 처음 큐의 내용이다
└ 교차 자리는 여기 없다 — 이웃이 되고 나서야 값이 정해지므로 실행 중에 들어간다
```

#### 2. 상태 배열에 넣고 새 이웃만 예약한다

**여기가 ② 와 ⑤ 가 하는 일입니다.** 자리를 꺼내면 그 자리를 지나는 선분을 이분 탐색으로
찾아 토막을 잡고, 거기에 새로 시작하는 선분을 더해 다시 놓습니다. 그러고 나서 토막의 위아래
경계에서만 다음 교차 자리를 예약해요.

```ts
// ② 이 자리를 지나는 선분과 여기서 시작하는 선분을 모아 모든 짝을 센다.
const from = firstNotBelow(now);
const through = status.slice(from, firstAbove(now));
const starting = startAt.get(here) ?? [];
const meeting = [...through, ...starting];
for (let i = 0; i < meeting.length; i++) {
  for (let j = i + 1; j < meeting.length; j++) record(meeting[i], meeting[j]);
}
// ⑤ 새로 이웃이 된 두 자리에서만 다음 교차 자리를 예약한다.
scheduleAt(now, from - 1, from);
scheduleAt(now, from + after.length - 1, from + after.length);
```

전개 입력의 처음 세 걸음이 그 자리예요. x = 0 에 끝점이 셋 몰려 있어 y 가 작은 것부터
하나씩 들어갑니다.

<!--proof:walk-insert-->

```text
걸음  now    무엇     status    예약
T1    (0,0)  시작 s0  s0        —
T2    (0,6)  시작 s1  s0 s1     (3,3)
T3    (0,8)  시작 s3  s0 s1 s3  —

x = 0 에 끝점이 3 개 몰려 있어 y 가 작은 것부터 하나씩 들어간다
└ 예약이 붙는 걸음은 T2 이고, 그 자리에서 (3,3) 이 큐에 들어간다
```

**T2 에서 예약이 하나 붙습니다.** s0 과 s1 이 처음으로 이웃이 됐고, 두 직선이 (3,3) 에서
만나며 그 점이 두 선분 안쪽이라 큐에 들어가요. T3 에서 s3 이 맨 위에 들어가 s1 과 이웃이
되지만, 두 직선은 x = −4 에서 만나 두 선분 밖이라 예약이 없습니다.

```text
T2 에서 새로 생긴 이웃과 예약

  status  [s0, s1]      새 이웃 s0-s1
  s0: y = x             s1: y = 6 − x
  x = 6 − x  →  x = 3,  y = 3   →  (3,3) 은 s0 의 [0,8] 안이고 s1 의 [0,6] 안이다
└ 두 선분 밖에서 만나는 짝은 예약하지 않는다. T3 의 s1-s3 이 그 경우다
```

#### 멈춤 — 시작하는 선분은 자리에 넣기만 하면 될 것 같다

**방금 본 ② 에서 `starting` 을 모으는 줄 하나가 남습니다.** 새로 시작하는 선분은 상태
배열에 끼워 넣기만 하면 될 것처럼 보여요 — 어차피 다음 사건 자리에서 이웃으로 확인될
테니까요. 그런데 시작 끝점이 **다른 선분 위에 있는** 경우가 있습니다. 그때는 그 자리가
두 선분이 공유하는 유일한 점이라, 여기서 안 세면 영영 못 셉니다.

```text
T 자로 만나는 배치 — s0 = (0,0)-(4,0) · s1 = (2,0)-(4,2)

  x = 2 에서   s0 의 y = 0 · s1 의 시작 끝점이 (2,0)
  s1 이 시작하는 그 점이 s0 위에 있다 — 두 선분이 공유하는 유일한 점이다
  s1 을 넣기만 하고 지나가면 x = 4 에서 s0 의 y 는 0, s1 의 y 는 2 로 갈린다
└ 그다음 이 짝이 다시 이웃으로 확인될 자리가 없다
```

시작하는 선분을 모으는 자리를 빼고 실행해 봅시다.

```ts
const meeting = [...through];   // ← 시작하는 선분을 안 모으는 판
```

<!--proof:pause-start-->

```text
배치                     선분  정본  안 모으는 판  대조
T 자로 만난다               2     1             0  어긋난다
끝점끼리 이어 붙는다        2     1             0  어긋난다
같은 직선 위에서 겹친다     2     1             1  같다
전개 입력                   5     4             4  같다
가로 둘과 세로 둘           4     4             4  같다

시작하는 선분을 모으는 자리를 빼면 시작 끝점에서 만나는 짝이 통째로 사라진다
└ 겹치는 배치와 전개 입력은 답이 그대로다 — 뒤 사건 자리에서 같은 짝을 다시 만난다
```

**T 자와 끝점 이어 붙기에서 답이 0 이 됩니다.** 반면 같은 직선 위에서 겹치는 배치와 전개
입력은 **답이 그대로예요** — 그 배치들에서는 뒤 사건 자리에서 같은 짝이 다시 이웃이 되기
때문입니다. 답이 안 틀린다고 이 자리를 빼도 되는 것은 아닙니다. 틀리는 배치가 실제로 있고,
그 배치는 테스트에 없으면 조용히 지나갑니다.

#### 멈춤 — 세로 선분도 상태 배열에 넣으면 될 것 같다

**상태 배열은 「그 x 에서의 y」로 순서를 정합니다.** 그러면 세로 선분은 어디에 넣어야 할까요.
세로 선분은 한 x 에서 y 가 구간 전체라 값이 하나로 안 정해지고, 순서를 매길 자리가 없습니다.
그래서 세로 선분은 상태 배열에 넣지 않고 따로 여닫아요.

```text
세로 선분을 상태 배열에 넣으려고 하면

  x = 2 에서   s0 의 y = 2 · s1 의 y = 4 · s2 의 y 는 1 부터 5 까지
  s2 를 s0 위에 둘까 아래에 둘까 — 둘 다 맞고 둘 다 틀리다
└ 순서를 매길 값이 없으니 이분 탐색의 전제가 없어진다
```

**그래서 여는 자리에서 한 번에 셉니다.** 세로 선분 `v` 가 열릴 때, 상태 배열에서 「x 가 `v` 의
x 일 때의 y 가 `v` 의 y 범위에 드는 선분」은 전부 `v` 와 교차해요. 그 범위를 이분 탐색 둘로
골라내면 됩니다. 여기서 위끝을 `v` 의 위 끝점이 아니라 지금 사건 자리로 잡으면 어떻게 되는지
실행해 봅시다.

```ts
const to = firstAbove(now);   // ← 위끝을 사건 자리로 바꾼 판
for (let at = firstNotBelow(now); at < to; at++) {
  record(id, status[at] as number);
}
```

<!--proof:pause-upright-->

```text
배치                        선분  정본  위끝을 바꾼 판  바꾼 줄    대조
가로 둘과 세로 둘              4     4               0  지난다     어긋난다
전개 입력                      5     4               2  지난다     어긋난다
세 선분이 한 점에서 만난다     3     3               3  지난다     같다
같은 직선 위에서 겹친다        2     1               1  안 지난다  같다
평행하고 떨어져 있다           3     0               0  안 지난다  같다

세로 선분의 위 끝점 대신 사건 자리로 범위를 정하면 그 자리 위쪽을 못 본다
└ 가로 둘과 세로 둘은 교차 4 개가 전부 세로 선분의 아래 끝점보다 위에 있어 답이 0 이 된다
└ 아래 2 줄은 세로 선분이 없어 바꾼 줄까지 가지도 않는다. 「같다」의 뜻이 다르다
```

**답이 0 이 됩니다.** 가로 둘과 세로 둘 배치에서 네 교차가 전부 세로 선분의 아래 끝점보다
위에 있는데, 위끝을 아래 끝점 자리로 잡으면 범위가 비어 하나도 못 셉니다. 반대로 세 선분이
한 점에서 만나는 배치는 답이 그대로예요 — 거기서는 교차가 아래 끝점 위쪽에 있어도 그 점이
사건 자리라 다른 갈래가 같은 짝을 잡습니다.

#### 3. 세로 선분은 y 범위로 한 번에 센다

**① 이 하는 일이 이것입니다.** 세로 선분을 여는 자리에서 두 가지를 봅니다 — 이미 열려 있는
다른 세로 선분(전부 같은 x 에 있고 지금 자리를 지나므로 반드시 교차)과, 상태 배열에서 y
범위에 드는 선분입니다.

```ts
// ① 이 자리에서 시작하는 세로 선분을 연다.
for (const id of uprightLow.get(here) ?? []) {
  const v = segs[id] as Seg;
  for (const other of upright) record(id, other);
  const top: Spot = { x: v.hix, y: v.hiy, d: 1n };
  const to = firstAbove(top);
  for (let at = firstNotBelow(now); at < to; at++) record(id, status[at]);
}
// ④ 이 자리에서 끝나는 세로 선분을 닫는다.
for (const id of uprightHigh.get(here) ?? []) {
  const at = upright.indexOf(id);
  if (at >= 0) upright.splice(at, 1);
}
```

전개 입력의 T4 와 T5 가 그 자리예요.

<!--proof:walk-upright-->

```text
걸음  now    무엇          upright  pairs
T4    (2,1)  세로 열기 s2  s2           2
T5    (2,5)  세로 닫기 s2  —            2

선분  x = 2 에서의 y  [1, 5]
s0                 2  범위 안
s1                 4  범위 안
s3                 7  범위 밖

세로 선분은 상태 배열에 안 들어간다 — 한 x 에서 y 가 하나로 안 정해지기 때문이다
└ 대신 열리는 그 자리에서 y 범위에 드는 선분을 이분 탐색 둘로 골라낸다
```

**두 쌍이 여기서 정해집니다.** s2 는 x = 2 에서 y 가 1 부터 5 까지인데, 같은 x 에서 s0 의
y 가 2 이고 s1 의 y 가 4 라 둘 다 범위 안이에요. s3 은 y 가 7 이라 범위 밖이고, 그래서 한
번도 판정하지 않습니다.

#### 4. 교차 자리에서 위아래를 뒤집는다

**③ 이 하는 일입니다.** 교차 자리를 꺼내면 그 점을 지나는 선분이 상태 배열에서 이어진 한
토막이에요. 그 점 **뒤**의 위아래는 기울기가 정합니다 — 기울기가 큰 쪽이 위로 갑니다.

```ts
// ③ 여기서 끝나는 선분을 빼고, 남은 것을 이 자리 뒤의 순서로 다시 놓는다.
const ending = new Set(endAt.get(here) ?? []);
const after = [
  ...through.filter((id) => !ending.has(id)),
  ...starting,
].sort((x, y) => slopeOrder(segs[x] as Seg, segs[y] as Seg) || x - y);
status.splice(from, through.length, ...after);
```

```text
└ s0-s3 은 분모가 3 이라 배정밀도로는 딱 떨어지지 않는 값이다
```

**T7 의 자리는 좌표가 분수입니다.** s0 은 `y = x`, s3 은 `y = 8 − x/2` 라 만나는 x 가 16/3
이에요. 배정밀도로 담으면 5.333… 이 되어 어느 자리가 앞인지 다투는 순간 틀릴 수 있으니,
분자 둘과 분모 하나를 정수로 적어 두고 대소는 곱셈으로 정합니다.

```ts
// a/b 와 c/d 의 대소는 a·d 와 c·b 의 대소와 같다. 분모가 양수라 부호가 안 바뀐다.
function cmpSpot(a: Spot, b: Spot): number {
  const dx = a.x * b.d - b.x * a.d;
  if (dx !== 0n) return sign(dx);
  return sign(a.y * b.d - b.y * a.d);
}
```

#### 6. 전체 코드

여기까지 만든 조각을 한 파일로 놓으면 이렇습니다. 조각에서 안 보인 것이 둘 있어요 — 선분이
둘 미만이면 짝이 없으므로 바로 0 을 반환하는 줄과, 같은 자리가 큐에 여러 번 들어갔을 때
한 번만 처리하려고 같은 자리를 전부 꺼내 버리는 줄입니다.

```ts
export type Point = [number, number];
export type Segment = [Point, Point];

/** 사건이 일어나는 자리. 좌표는 `(x/d, y/d)` 이고 `d` 는 언제나 양수다. */
interface Spot {
  x: bigint;
  y: bigint;
  d: bigint;
}

/** 두 끝점을 사전순으로 세워 둔 선분. `lo` 가 앞선 끝점이다. */
interface Seg {
  id: number;
  lox: bigint;
  loy: bigint;
  hix: bigint;
  hiy: bigint;
  dx: bigint;
  dy: bigint;
  vertical: boolean;
}

/** 부호만 돌려준다. 크기는 어디서도 쓰지 않는다. */
function sign(v: bigint): number {
  return v > 0n ? 1 : v < 0n ? -1 : 0;
}

function gcd(a: bigint, b: bigint): bigint {
  let x = a < 0n ? -a : a;
  let y = b < 0n ? -b : b;
  while (y !== 0n) {
    const t = x % y;
    x = y;
    y = t;
  }
  return x;
}

/**
 * 분자 둘과 분모를 최대공약수로 나눈다.
 *
 * 같은 자리가 언제나 같은 세 수로 적혀야 사전 열쇠가 맞는다. 줄이지 않으면 `(2,2)` 가
 * 어떤 경로에서는 `4/4/2` 로 적혀 끝점 `(2,2)` 와 다른 자리로 읽힌다.
 */
function reduced(x: bigint, y: bigint, d: bigint): Spot {
  const g = gcd(gcd(x, y), d);
  return g > 1n ? { x: x / g, y: y / g, d: d / g } : { x, y, d };
}

/** 사전순 대소 — x 가 먼저이고 같으면 y 다. */
function cmpSpot(a: Spot, b: Spot): number {
  const dx = a.x * b.d - b.x * a.d;
  if (dx !== 0n) return sign(dx);
  return sign(a.y * b.d - b.y * a.d);
}

/** 자리를 문자열 하나로 적는다. 사전에서 끝점을 찾는 열쇠다. */
function spotKey(p: Spot): string {
  return `${p.x}/${p.y}/${p.d}`;
}

/**
 * 자리 `p` 가 선분 `s` 의 직선보다 위면 1, 아래면 −1, 직선 위면 0.
 *
 * 세 점의 방향 판정과 같은 식이고, 분모 `d` 가 양수라 곱해도 부호가 안 바뀐다.
 */
function orient(s: Seg, p: Spot): number {
  return sign(s.dx * (p.y - s.loy * p.d) - s.dy * (p.x - s.lox * p.d));
}

/** 기울기 대소. 상태 배열에 담기는 선분은 세로가 아니라 `dx` 가 양수다. */
function slopeOrder(a: Seg, b: Seg): number {
  return sign(a.dy * b.dx - b.dy * a.dx);
}

/** 두 끝점을 사전순으로 세운다. */
function toSeg(raw: Segment, id: number): Seg {
  const [a, b] = raw;
  const front = a[0] < b[0] || (a[0] === b[0] && a[1] <= b[1]);
  const lo = front ? a : b;
  const hi = front ? b : a;
  const lox = BigInt(lo[0]);
  const loy = BigInt(lo[1]);
  const hix = BigInt(hi[0]);
  const hiy = BigInt(hi[1]);
  return {
    id,
    lox,
    loy,
    hix,
    hiy,
    dx: hix - lox,
    dy: hiy - loy,
    vertical: lo[0] === hi[0],
  };
}

/**
 * 두 선분이 한 점에서 가로지르는 자리. 평행하거나 만나는 점이 선분 밖이면 `null`.
 *
 * 같은 직선 위의 두 선분은 분모가 0 이라 여기서 `null` 이 된다. 그 짝은 한쪽 끝점이 다른
 * 선분 위에 있으므로 끝점 사건에서 세어진다.
 */
function crossingSpot(a: Seg, b: Seg): Spot | null {
  let den = a.dx * b.dy - a.dy * b.dx;
  if (den === 0n) return null;
  const wx = b.lox - a.lox;
  const wy = b.loy - a.loy;
  let tn = wx * b.dy - wy * b.dx;
  let un = wx * a.dy - wy * a.dx;
  if (den < 0n) {
    den = -den;
    tn = -tn;
    un = -un;
  }
  if (tn < 0n || tn > den || un < 0n || un > den) return null;
  return reduced(a.lox * den + tn * a.dx, a.loy * den + tn * a.dy, den);
}

/** 최소 힙에 자리 하나를 넣는다. */
function heapPush(heap: Spot[], p: Spot): void {
  heap.push(p);
  let at = heap.length - 1;
  while (at > 0) {
    const parent = (at - 1) >> 1;
    if (cmpSpot(heap[at] as Spot, heap[parent] as Spot) >= 0) break;
    const keep = heap[at] as Spot;
    heap[at] = heap[parent] as Spot;
    heap[parent] = keep;
    at = parent;
  }
}

/** 사전순으로 가장 앞선 자리를 꺼낸다. */
function heapPop(heap: Spot[]): Spot {
  const top = heap[0] as Spot;
  const last = heap.pop() as Spot;
  if (heap.length > 0) {
    heap[0] = last;
    let at = 0;
    for (;;) {
      const left = at * 2 + 1;
      const right = left + 1;
      let small = at;
      if (
        left < heap.length &&
        cmpSpot(heap[left] as Spot, heap[small] as Spot) < 0
      ) {
        small = left;
      }
      if (
        right < heap.length &&
        cmpSpot(heap[right] as Spot, heap[small] as Spot) < 0
      ) {
        small = right;
      }
      if (small === at) break;
      const keep = heap[at] as Spot;
      heap[at] = heap[small] as Spot;
      heap[small] = keep;
      at = small;
    }
  }
  return top;
}

/**
 * 선분 배열에서 서로 교차하는 선분 쌍의 개수.
 *
 * 끝점끼리 만나기만 해도, 같은 직선 위에서 구간을 공유해도 한 쌍으로 센다.
 * 같은 점에서 `m` 개가 만나면 그 안의 모든 짝을 세므로 `m(m−1)/2` 쌍이다.
 */
export function bentleyOttmann(segments: Segment[]): number {
  const n = segments.length;
  if (n < 2) return 0;
  const segs = segments.map(toSeg);

  const events: Spot[] = [];
  const startAt = new Map<string, number[]>();
  const endAt = new Map<string, number[]>();
  const uprightLow = new Map<string, number[]>();
  const uprightHigh = new Map<string, number[]>();
  const fileInto = (
    book: Map<string, number[]>,
    at: string,
    id: number,
  ): void => {
    const got = book.get(at);
    if (got === undefined) book.set(at, [id]);
    else got.push(id);
  };
  for (const s of segs) {
    const lo: Spot = { x: s.lox, y: s.loy, d: 1n };
    const hi: Spot = { x: s.hix, y: s.hiy, d: 1n };
    heapPush(events, lo);
    heapPush(events, hi);
    fileInto(s.vertical ? uprightLow : startAt, spotKey(lo), s.id);
    fileInto(s.vertical ? uprightHigh : endAt, spotKey(hi), s.id);
  }

  /** 세로가 아닌 활성 선분. 스위프 자리에서의 y 오름차순이다. */
  const status: number[] = [];
  /** 지금 열려 있는 세로 선분. 전부 지금 사건 자리의 x 에 있다. */
  const upright: number[] = [];
  const seen = new Set<number>();
  let pairs = 0;

  const record = (a: number, b: number): void => {
    const key = a < b ? a * n + b : b * n + a;
    if (seen.has(key)) return;
    seen.add(key);
    pairs++;
  };

  /** y 가 자리보다 작은 선분은 앞쪽에 몰려 있다. 처음으로 그렇지 않은 첨자. */
  const firstNotBelow = (p: Spot): number => {
    let lo = 0;
    let hi = status.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (orient(segs[status[mid] as number] as Seg, p) > 0) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  };

  /** 처음으로 y 가 자리보다 큰 선분의 첨자. */
  const firstAbove = (p: Spot): number => {
    let lo = 0;
    let hi = status.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (orient(segs[status[mid] as number] as Seg, p) >= 0) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  };

  const scheduleAt = (now: Spot, left: number, right: number): void => {
    if (left < 0 || right >= status.length) return;
    const q = crossingSpot(
      segs[status[left] as number] as Seg,
      segs[status[right] as number] as Seg,
    );
    if (q !== null && cmpSpot(q, now) > 0) heapPush(events, q);
  };

  while (events.length > 0) {
    const now = heapPop(events);
    while (events.length > 0 && cmpSpot(events[0] as Spot, now) === 0)
      heapPop(events);
    const here = spotKey(now);

    // ① 이 자리에서 시작하는 세로 선분을 연다. 열려 있는 세로 선분은 전부 이 자리를 지나고,
    //    상태 배열에서 이 세로 선분의 y 범위 안에 있는 선분도 전부 이 세로 선분과 만난다.
    for (const id of uprightLow.get(here) ?? []) {
      const v = segs[id] as Seg;
      for (const other of upright) record(id, other);
      const top: Spot = { x: v.hix, y: v.hiy, d: 1n };
      const to = firstAbove(top);
      for (let at = firstNotBelow(now); at < to; at++)
        record(id, status[at] as number);
      upright.push(id);
    }

    // ② 이 자리를 지나는 선분을 모은다. 상태 배열에서 방향 판정이 0 인 구간이 그것이고,
    //    여기서 시작하는 선분과 열려 있는 세로 선분도 같은 자리를 지나므로 함께 센다.
    const from = firstNotBelow(now);
    const through = status.slice(from, firstAbove(now));
    const starting = startAt.get(here) ?? [];
    const meeting = [...through, ...starting];
    for (let i = 0; i < meeting.length; i++) {
      const one = meeting[i] as number;
      for (let j = i + 1; j < meeting.length; j++)
        record(one, meeting[j] as number);
      for (const v of upright) record(one, v);
    }

    // ③ 여기서 끝나는 선분을 빼고, 남은 것을 이 자리 **뒤**의 순서로 다시 놓는다.
    //    이 자리를 지나는 선분끼리는 기울기가 큰 쪽이 위로 간다.
    const ending = new Set(endAt.get(here) ?? []);
    const after = [
      ...through.filter((id) => !ending.has(id)),
      ...starting,
    ].sort((x, y) => slopeOrder(segs[x] as Seg, segs[y] as Seg) || x - y);
    status.splice(from, through.length, ...after);

    // ④ 이 자리에서 끝나는 세로 선분을 닫는다.
    for (const id of uprightHigh.get(here) ?? []) {
      const at = upright.indexOf(id);
      if (at >= 0) upright.splice(at, 1);
    }

    // ⑤ 새로 이웃이 된 두 자리에서 다음 교차 자리를 예약한다. 가운데 토막은 전부 이 자리를
    //    지나므로 다시 만날 일이 없고, 예약할 것은 토막의 양 끝뿐이다.
    scheduleAt(now, from - 1, from);
    scheduleAt(now, from + after.length - 1, from + after.length);
  }

  return pairs;
}
```

**가장 중요한 줄은 `status.splice(from, through.length, ...after)` 입니다.** 이 한 줄이 끝나는
선분을 빼고, 시작하는 선분을 넣고, 교차 자리를 지난 뒤의 위아래를 한꺼번에 맞춰요. 세 갈래가
같은 자리에서 처리되는 것은 셋 다 「이 자리를 지나는 토막을 다시 놓는다」로 같기 때문입니다.

### 알아 두면 좋은 개념 — 출력에 붙는 비용

파트 1 이 값으로 보인 것에 이름 하나를 붙이고 갑니다. 이 절차의 비용은 **입력의 크기가 아니라
답의 크기에 붙어요.** 선분이 아무리 많아도 교차가 없으면 짝을 거의 안 보고, 선분이 적어도
교차가 많으면 그만큼 봅니다. 이런 성질을 가진 절차를 **출력 민감(output-sensitive)** 하다고
부릅니다.

<!--proof:related-output-->

```text
선분  교차 쌍  사건 자리  짝을 본 횟수  짝 ÷ 교차 쌍

└ 마지막 열이 거의 안 변한다 — 비용이 답의 크기에 비례해 붙는다는 뜻이다
```

**마지막 열이 거의 안 변하는 것이 이 이름의 뜻이에요.** 선분을 네 배로 해도, 교차를 열여섯
배로 해도, 짝을 보는 횟수는 교차 쌍의 수에 비례한 자리에 머뭅니다.

```text
비용이 무엇에 붙는가

  입력에 붙는 비용   전부 대조 — 언제나 n(n−1)/2 번. 답이 0 이어도 그만큼 판정한다
  출력에 붙는 비용   이 절차 — 교차 쌍이 0 이면 짝을 거의 안 본다
└ 답이 0 이면 전부 대조는 그대로 n(n−1)/2 번이고 이 절차는 끝점 사건만 처리한다
```

이 이름은 이 편에만 있는 것이 아니에요. [`convexHull`](../convexHull/convexHull-guide.md)
편의 선물 포장도 껍질 위의 점 수 `h` 에 비용이 붙고, 정렬된 두 목록의 교집합을 앞에서부터
맞춰 가며 구하는 절차도 답의 크기에 붙습니다. **비용을 입력 크기만으로 적으면 이런 절차의
성질이 통째로 사라져요.**

## 파트 2 — 적용 조건 · 보장 · 비용

여기서부터는 앞에서 만든 절차를 따집니다 — 어떤 입력에서 이것을 고르는가, 무엇을 보장하는가,
값은 얼마인가.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **선분이 많고 교차가 적습니다.** 비용이 교차 쌍의 수에 붙으므로, 교차가 쌍의 수에 가까우면
  전부 대조와 차이가 없어져요. 파트 1 의 표에서 흩어 놓은 짧은 선분 512 개는 짝을 621 번만
  봤고 전부 대조는 130,816 번이었습니다.
- **교차 여부가 아니라 교차하는 짝을 전부 알아야 합니다.** 「하나라도 교차하는가」만 물으면
  교차 자리를 예약할 필요조차 없어 끝점 사건만으로 끝납니다.
- **좌표가 정수입니다.** 교차 자리가 유리수라 정수로 다뤄야 부호가 확정돼요. 좌표가 실수면
  같은 절차를 쓰되 자리의 앞뒤 판정을 오차 한계와 함께 다시 세워야 합니다.
- **입력이 한 번에 전부 주어집니다.** 선분이 하나씩 도착하며 그때마다 답을 물으면 사건 자리를
  미리 세울 수 없어 이 틀이 안 맞아요.

```text
이 절차가 맞는 자리와 안 맞는 자리

  선분 10 만 · 교차 1 만           맞다 — 짝을 보는 횟수가 교차 수를 따라간다
  선분 1 천 · 교차 50 만           안 맞다 — 쌍의 수 자체가 50 만이라 전부 대조가 낫다
  교차가 하나라도 있는지만 묻는다  과하다 — 끝점 사건만으로 끝난다
  선분이 하나씩 도착한다           안 맞다 — 사건 자리를 미리 못 세운다
```

#### 문제에서 이것을 떠올리게 하는 단서

- **「선분 여러 개」와 「교차」가 한 문장에 함께 나옵니다.** 둘 사이의 교차 판정은 다른 문제이고
  ([`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-guide.md)), 여러 개가 되는
  순간 쌍의 수가 제곱이 됩니다.
- **답이 「개수」이거나 「목록」입니다.** 교차하는 짝의 수나 교차점의 좌표를 요구하면 이 틀이
  그대로 맞아요.
- **제약이 `n ≤ 10^5` 인데 시간이 1 초입니다.** 쌍의 수가 50 억이라 전부 대조가 제외되고,
  그러면 남는 것이 「가까운 것만 본다」류입니다.
- **도로망 · 배선 · 지도 경계 같은 말이 나옵니다.** 실제로 선분이 길고 교차가 드문 입력이라
  이 절차의 조건과 맞습니다.
- **「같은 점에서 셋 이상이 만나면」이라는 단서가 붙습니다.** 퇴화 배치를 따로 물었다는 뜻이고,
  이 절차는 그 자리를 지나는 선분을 한 토막으로 잡아 처리합니다.

#### 경쟁 설계와의 대조

**경쟁 설계는 격자 나누기입니다.** 좌표 상자를 가로세로 `⌈√n⌉` 등분한 칸으로 나누고, 선분마다
자기 좌표 상자가 걸치는 칸에 이름을 적어 둔 다음, 같은 칸에 이름이 함께 적힌 짝만 방향 판정으로
확인해요. 교차하는 두 선분은 교점이 든 칸에 둘 다 이름이 적히므로 이 절차도 정확합니다. 칸을
정하는 나눗셈은 배정밀도라서 좌표가 아주 커지면 칸이 어긋날 수 있는데, 여기서 잰 범위(한 변
4096)에서는 매 실행마다 정본과 답이 같은 것을 하네스가 확인합니다.


아니라, 선분이 짧고 흩어져 있으면 격자, 길고 교차가 답에 비해 적으면 스위프입니다.**

### 수식 정의와 유도

기호부터 정합니다. 선분 `a` 를 점 $A_0$ 에서 방향 $r_a$ 로 가는 것으로 적고, 선분 `b` 를 점
$B_0$ 에서 방향 $r_b$ 로 가는 것으로 적습니다. 두 벡터의 외적은 $u \times v = u_x v_y - u_y v_x$
입니다.

```text
두 직선을 매개변수로 적으면

  a 위의 점   A0 + t·ra     t 가 0 이면 A0, 1 이면 a 의 다른 끝점
  b 위의 점   B0 + u·rb     u 가 0 이면 B0, 1 이면 b 의 다른 끝점
└ 두 점이 같아지는 t 와 u 를 찾으면 그것이 교점이다
```

$$D = r_a \times r_b, \qquad w = B_0 - A_0, \qquad t = \frac{w \times r_b}{D}, \qquad u = \frac{w \times r_a}{D}$$

$D = 0$ 이면 두 직선이 평행하고, 그렇지 않으면 교점이 하나입니다. 그 교점이 두 선분 안쪽에
있을 조건은 $0 \le t \le 1$ 이고 $0 \le u \le 1$ 이에요.

```text
전개 입력의 s0 과 s3 에 넣어 손으로 검산하면

  A0 = (0,0)  ra = (8,8)      B0 = (0,8)  rb = (8,-4)
  D  = 8·(−4) − 8·8 = −96     w  = (0,8)
  w × rb = 0·(−4) − 8·8 = −64        t = −64 / −96 = 2/3
  w × ra = 0·8 − 8·8 = −64           u = −64 / −96 = 2/3
└ t 도 u 도 0 과 1 사이라 교점이 두 선분 안쪽이다
└ 교점은 A0 + (2/3)·(8,8) = (16/3,16/3) — T7 의 자리와 같다
```

$$x^{*} = \frac{A_{0x} D + (w \times r_b)\, r_{ax}}{D}, \qquad y^{*} = \frac{A_{0y} D + (w \times r_b)\, r_{ay}}{D}$$

교점의 좌표는 $A_0 + t\,r_a$ 이므로 분모를 $D$ 로 맞추면 위처럼 정수 셋으로 적힙니다. 이 식을
그대로 코드로 옮기면 나눗셈이 한 번도 안 나와요.

```ts
let den = a.dx * b.dy - a.dy * b.dx;
if (den === 0n) return null;
let tn = (b.lox - a.lox) * b.dy - (b.loy - a.loy) * b.dx;
if (den < 0n) { den = -den; tn = -tn; }
return reduced(a.lox * den + tn * a.dx, a.loy * den + tn * a.dy, den);
```

**사건 자리의 수를 세어 봅시다.** 끝점 자리의 집합을 $P$, 예약된 교차 자리의 집합을 $Q$ 라
하면 $E = |P \cup Q|$ 이고, 끝점이 겹치면 $|P| < 2n$ 입니다. 작은 배치 다섯에 넣어 확인합니다.

<!--proof:math-check-->

```text
배치                        n  2n  서로 다른 끝점  교차 자리   E
평행하고 떨어져 있다        3   6               6          0   6
세 선분이 한 점에서 만난다  3   6               6          1   7
전개 입력                   5  10              10          2  12
가로 둘과 세로 둘           4   8               8          0   8
셋이 서로 다 교차한다       3   6               6          3   9

끝점이 겹치면 자리가 하나로 합쳐지므로 서로 다른 끝점 수가 2n 보다 작아진다
└ 5 개 배치 모두 마지막 열이 앞의 두 열의 합과 같다
```

**이제 그 정수들이 얼마나 커지는지 임의의 좌표 상한에서 닫습니다.** 좌표의 절댓값이 $C$
이하이면 방향 벡터의 각 성분이 $2C$ 이하이고, 제약의 $C = 10^9$ 을 넣으면 배정밀도가 정수를
통째로 담는 한계 $2^{53}$ 을 얼마나 넘는지가 수로 나옵니다.

$$|D| = |r_{ax} r_{by} - r_{ay} r_{bx}| \le 2 \cdot (2C)^2 = 8C^2$$

```text
분자의 두 항을 따로 재면

  A0x · D          C · 8C²  = 8C³
  (w × rb) · rax   8C² · 2C = 16C³
└ 둘을 더해 24C³ 이다. 두 자리의 앞뒤를 정할 때는 여기에 상대의 분모를 곱한다
```

$$|A_{0x} D + (w \times r_b) r_{ax}| \le 24C^3, \qquad 24C^3 \cdot 8C^2 = 192C^5$$

```text

분모           8C²                                     8000000000000000000    63

좌표 상한 1,000,000,000 짜리 선분 24 개를 실제로 실행해 나온 가장 큰 값
└ 분자 1201171897766175270928522650 · 분모 1968527748915996635
└ 자리 대소를 재는 곱의 상한이 배정밀도 정수 한계의 2.13e+31 배다
```

**그래서 판정 경로에 배정밀도를 한 번도 안 씁니다.** 158 비트짜리 곱의 부호를 배정밀도로
정하려 하면 값이 아니라 반올림이 답을 정하게 되고, 자리의 앞뒤가 한 번 어긋나면 상태 배열의
순서가 어긋나 짝을 놓칩니다.

```text
  배정밀도  그림에 적는 근삿값(16/3 ≈ 5.333)과 표에 적는 비율
└ 판정 경로에 배정밀도가 하나라도 있으면 그 자리에서 답이 갈릴 수 있다
```

**마지막으로 제약 규모를 넣습니다.** 사건 자리가 $E$ 개이고 자리마다 힙 연산이 상수 개이라
총 비용의 주항이 $E \log E$ 인데, $E \le 2n + k$ 이므로 $O((n+k)\log(n+k))$ 예요. 선분 수
상한 $10^5$ 에 교차 수 네 가지를 넣어 봅니다.


### 불변식 — 상태 배열은 지금 사건 자리의 x 에서 y 비내림차순이다

**세울 문장은 이것입니다.** 사건 자리 하나를 처리하고 나면, 상태 배열에 든 선분들은 그 자리의
x 에서의 y 가 비내림차순이고, **그 자리를 지나는 선분끼리는 기울기 오름차순**입니다. 「언제」가
중요해요 — 자리 하나를 다 처리한 직후이고, 처리 도중에는 성립하지 않습니다.

```text
왜 비내림차순인가 — 같은 y 가 나올 수 있다

  같은 자리를 지나는 선분 둘은 그 x 에서 y 가 정확히 같다
  같은 직선 위에서 겹치는 선분 둘은 겹치는 구간 내내 y 가 같다
└ 그래서 「오름차순」이 아니라 「비내림차순」이다. 같은 값끼리는 기울기가 순서를 정한다
```

**유지되는 것을 갈래마다 값으로 봅니다.** 상태 배열을 바꾸는 갈래는 넷이에요 — 선분이 시작할
때, 끝날 때, 교차 자리에서 토막이 뒤집힐 때, 세로 선분이 열리고 닫힐 때입니다. 넷 다 같은 한
줄(`status.splice`)을 지나고, 그 줄 뒤에서 이웃 쌍을 전부 견줘 확인합니다.

<!--proof:invariant-states-->

```text

T1    (0,0)        시작 s0       s0           오름차순

└ 실행이 매 걸음 이웃 쌍을 견줘 확인한 값이다 — 어긋난 걸음이 있으면 그 수가 0 이 아니다
```

**엣지 케이스도 같은 자리에서 봅니다.** 선분이 0 개나 1 개면 짝이 없어 큐를 처리하기 전에

### 비용 계산

#### 비용을 세는 과정

**세 가지를 곱해 더합니다** — 사건 자리의 수, 자리 하나를 처리하는 값, 그리고 짝을 세는 값이에요.
전개 입력에서 실제 계수를 먼저 봅니다.

<!--proof:perf-count-->

```text
무엇                   값
끝점 사건              10
예약한 교차 자리        2
처리한 사건 자리       12
짝을 본 횟수           10
상태 배열의 최대 크기   3
사건 큐의 최대 크기    10
교차 쌍                 4

전개 입력 선분 5 개에서 잰 값이다. 끝점 10 개에 교차 자리 2 개가 붙어 12 자리다
└ 상태 배열이 3 개를 안 넘어 이분 탐색 한 번이 2 걸음으로 끝난다
```

**사건 자리는 끝점 `2n` 개에 예약된 교차 자리를 더한 수입니다.** 전개 입력에서는 끝점 열 개에
T2 와 T6 이 예약한 둘이 붙어 열둘이었어요. 예약은 이웃이 될 때만 생기고 같은 자리를 여러 번
넣어도 꺼낼 때 한 번만 처리하므로, 예약 수는 교차 쌍의 수 `k` 를 넘지 않습니다.

```text
자리 하나를 처리하는 값

  힙에서 꺼내기          O(log E)
  이분 탐색 둘           O(log m)   상태 배열에서 토막의 아래끝과 위끝
  토막을 다시 놓기       O(m)       배열이라 뒤쪽 칸을 통째로 옮긴다
  경계 두 곳 예약        O(1) 판정 + O(log E) 넣기
└ 균형 이진 탐색 트리를 쓰면 세 번째 줄이 O(log m) 이 되고 그때 총식이 O((n+k) log n) 이다
```

**짝을 세는 값은 답의 크기에 붙습니다.** T4 처럼 세로 선분이 열리는 자리에서 세는 짝은 전부
실제 교차이고, T6·T7 처럼 토막이 둘 이상인 자리에서 세는 짝도 전부 실제 교차예요. 실제 교차가
아닌 짝을 보는 자리는 경계 두 곳의 예약 판정뿐이라 자리마다 상수입니다.

<!--proof:perf-growth-->

```text
 선분  교차 쌍  사건 자리 E  짝을 본 횟수  ⌈log₂E⌉
  512       20        1,031         1,299       11
1,024       29        2,064         3,009       12
2,048       53        4,119         6,760       13
4,096      119        8,240        14,484       14

선분을 2 배로  교차 쌍 성장률  사건 자리 성장률  짝 성장률  n log n 성장률
512 → 1,024              1.45              2.00       2.32            2.22
1,024 → 2,048            1.83              2.00       2.25            2.20
2,048 → 4,096            2.25              2.00       2.14            2.18

밀도를 고정한 가족이라 선분을 2 배로 해도 한 선분이 만나는 이웃 수가 안 변한다
└ 사건 자리는 정확히 2 배이고 짝의 성장률이 n log n 의 성장률 옆에 붙는다
```

#### 케이스별 비용과 그 경계

**축 둘을 섞지 않고 적습니다.** 하나는 입력이 어떤 모양인가(케이스)이고, 다른 하나는 그
모양에서 상한만 아는가 차수까지 아는가(경계)예요. 둘은 짝지어지는 것이 아니라 따로 붙습니다.

| 케이스 | 시간 | 경계의 종류 | 무엇이 정하는가 |
| --- | --- | --- | --- |
| 교차가 없다 | $\Theta(n \log n)$ | 타이트 | 끝점 $2n$ 개를 사전순으로 내놓으므로 비교 정렬의 하한이 그대로 붙는다 |
| 교차가 $k$ 개 · `status` 를 배열로 | $O((n+k)(\log n + m))$ | 상한 | 토막을 다시 놓을 때 뒤쪽 칸을 옮긴다 |
| 교차가 $k$ 개 · `status` 를 균형 트리로 | $\Theta((n+k)\log n)$ | 타이트 | 자리마다 힙과 트리 연산이 상수 개다 |
| 교차가 최대 · `status` 를 균형 트리로 | $\Theta(n^2 \log n)$ | 타이트 | $k = n(n-1)/2$ 를 위 줄의 식에 넣은 값이다 |

**위 표가 말하는 것은 최악 보장이지 기댓값이 아닙니다.** 이 절차에는 난수가 한 군데도 안
쓰이고, 같은 입력이면 언제나 같은 수의 연산을 해요. 그래서 표의 값은 그 케이스 안의 어떤
입력에서도 넘지 않는 값입니다. 「평균」을 적으려면 입력 분포를 먼저 정해야 하는데, 이 문제는
선분 배치의 분포를 정할 근거가 없어서 적지 않습니다.

**총식을 한 번 정확히 적습니다.** 끝점을 힙에 넣는 전처리 $2n \log(2n)$ 에 자리마다의 값
$E(\log E + \log m + m)$ 을 더하고, 짝을 세는 값 $k$ 를 더한 것이 전부예요. 추가 칸은 힙 $E$ ·
상태 배열 $m$ · 이미 센 짝의 집합 $k$ 를 합쳐 $O(n + k)$ 입니다.

```text
어느 비용을 센 값인가

  포함   힙 연산 · 이분 탐색 · 토막 다시 놓기 · 짝 세기 · 이미 센 짝의 집합 조회
  포함   교차 자리를 정수 셋으로 만드는 곱셈
  제외   입력을 읽는 값. 두 설계 모두 같아서 순서를 못 바꾼다
└ `bigint` 곱셈을 상수로 셌다. 좌표가 커지면 그 자체가 자릿수에 비례해 늘어난다
```

#### 최악을 만드는 입력

**최악을 실제로 구성해 확인합니다.** 「교차가 많으면 느리다」는 물려받은 통념이라 그대로 쓰지
않고, 선분 64 개를 여섯 가지 모양으로 놓고 무엇이 가장 커지는지 재 봅니다.

<!--proof:worst-shape-->

```text
배치                      교차 쌍  사건 자리  큐 최대  status 최대  짝을 본 횟수

흩어 놓은 길이 16 · 64          0        128      128            2             7
흩어 놓은 길이 1024 · 64       97        161      128           19           361
한 점에 64 갈래             2,016        129      128           64         2,079
같은 직선에 64 겹           2,016        128      128           64        87,360
격자무늬 64                 1,024        127      128           32         1,117

선분 64 개에서 쌍의 수는 2,016 이다. 한 점에 모으거나 겹쳐 쌓으면 그 전부가 교차다
└ 큐의 최대는 6 개 배치 모두 끝점을 전부 넣은 128 이다 — 예약이 그 위로 안 쌓였다
└ 교차 쌍이 가장 많은 배치와 짝을 가장 많이 보는 배치가 서로 다르다
```

**교차 쌍이 가장 많은 배치는 둘입니다.** 한 점에 64 갈래를 모으거나 같은 직선에 64 개를 겹쳐
쌓으면 쌍 2,016 개가 전부 교차예요. 그런데 **짝을 가장 많이 보는 배치는 그중 하나뿐입니다** —
같은 직선에 겹쳐 쌓으면 87,360 번인데, 한 점에 모으면 2,079 번입니다.

```text
왜 같은 직선에 겹쳐 쌓는 쪽이 더 많은가

  한 점에 64 갈래   그 한 점이 사건 자리 하나다. 거기서 토막 64 개의 모든 짝을 한 번 센다
  같은 직선에 64 겹  겹치는 구간 내내 y 가 같다. 끝점 사건마다 토막 전체를 다시 센다
└ 이미 센 짝은 집합이 걸러 내지만, 「본 횟수」는 그만큼 늘어난다
└ 큐의 최대 크기는 여섯 배치 모두 128 이었다. 끝점 2n 을 처음에 넣은 값이고 예약이 그 위로
  안 쌓였다
```

**그러니 최악 입력은 「같은 직선 위에 겹쳐 쌓은 선분 `n` 개」입니다.** 교차 쌍이 `n(n−1)/2` 로
최대이면서, 겹치는 구간의 끝점마다 토막 전체를 다시 세므로 짝을 보는 횟수가 교차 쌍의 수보다도
한 자리 더 커져요. 이 배치에서는 어떤 절차도 답 자체가 `n²` 자리라 1 초 안에 못 냅니다.

### 스스로 점검하기

이 편이 세운 것은 한 문장입니다. 교차하는 두 선분은 **교차 직전에 반드시 이웃**이므로,
이웃 관계가 바뀌는 자리만 골라 처리해도 교차를 하나도 빠뜨리지 않아요.

```text
사건 자리 → 토막 잡기 → 짝 세기 → 다시 놓기 → 경계 두 곳 예약
```

**확인 하나만 해 볼까요?** T6 에서 상태 배열이 `s1 s0 s3` 이 됐는데, 그 자리에서 예약된 것이
왜 s0-s3 이고 s1-s3 이 아닐까요?

아래끝이라 아래 경계를 이루는데 그 아래에 아무것도 없어 예약이 안 생겨요. 그리고 `s1` 과 `s3`
은 T3 에서 이미 이웃이었고 그때 두 직선이 x = −4 에서 만나 선분 밖이라는 것을 확인했습니다.

```text
경계 두 곳 가운데 예약이 생기는 자리

  status  s1 s0 s3      갈아 끼운 토막은 s1 s0
```
