# convexHull — 점을 한 번 정렬해 두면 껍질이 왼쪽으로만 꺾이는 사슬 둘로 갈라지는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

점을 감싸는 가장 작은 볼록 다각형의 정의에서 시작해, 좌표로 한 번 정렬해 두고 사슬 둘을
쌓는 절차까지 값으로 따라갑니다. 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

평면 위의 점 여러 개를 받아 그 점을 **전부 안에 담는 가장 작은 볼록 다각형**의 꼭짓점을
반시계 방향으로 돌려주는 문제예요. 볼록하다는 것은 다각형의 어느 변을 직선으로 늘여도
나머지가 한쪽에만 있다는 뜻이고, 그 조건을 지키는 다각형 중 가장 작은 것을 볼록 껍질이라고
부릅니다. 점을 못으로 박고 그 바깥에 고무줄을 둘렀을 때 고무줄이 멈추는 자리라고 보면
됩니다.

<!--proof:concept-drop-->

```text
점     답에    왜
(0,0)  담긴다  꼭짓점 — 여기서 껍질이 꺾인다
(0,3)  담긴다  꼭짓점 — 여기서 껍질이 꺾인다
(3,0)  빠진다  변 위의 공선 중간 점
(3,2)  빠진다  껍질 안쪽
(3,4)  담긴다  꼭짓점 — 여기서 껍질이 꺾인다
(6,0)  담긴다  꼭짓점 — 여기서 껍질이 꺾인다
(6,3)  담긴다  꼭짓점 — 여기서 껍질이 꺾인다

입력 8 개 가운데 같은 좌표가 1 개라 서로 다른 점은 7 개다
답  (0,0) (6,0) (6,3) (3,4) (0,3)
└ 반시계 방향으로 왼쪽 아래에서 시작한다
```

답에 담기지 않는 점이 두 부류입니다. 껍질 **안쪽**에 있는 점과, 껍질의 **변 위에 있지만
꺾이지 않는** 점이에요. 뒤쪽이 이 문제의 까다로운 자리인데, 그 점은 껍질의 경계 위에 있으면서도
꼭짓점은 아닙니다.

세 점의 관계를 재는 도구가 하나 있으면 이 판정이 전부 끝납니다. 점 `o` 에서 `a` 로 간 다음
`b` 로 갈 때 **왼쪽으로 꺾이는가 · 오른쪽으로 꺾이는가 · 한 직선 위인가**를 재는 것이에요.
반시계 방향으로 껍질을 이어 간다면 이웃한 세 꼭짓점은 언제나 왼쪽으로 꺾입니다.

```text
판정값의 부호가 뜻하는 것

  왼쪽으로 꺾인다 (판정값 > 0)     오른쪽으로 꺾인다 (판정값 < 0)
          b                                a
         / \                              / \
        /   \                            /   \
       o-----a                          o     b

  한 직선 위다 (판정값 = 0)
       o-----a-----b
       └ 가운데 a 는 껍질의 경계 위에 있지만 꼭짓점은 아니다

  o 에서 a 로 간 다음 b 로 갈 때 왼쪽으로 꺾이면 판정값이 양수다
```

정의를 그대로 옮기면 「모든 점 쌍을 잡고 나머지가 전부 한쪽인지 확인한다」가 되는데, 그러면
점 개수의 세제곱만큼 판정을 해야 해요. 대신 점을 `x` 를 먼저 `y` 를 그다음으로 한 번 정렬해 두면 왼쪽에서
오른쪽으로 한 번, 오른쪽에서 왼쪽으로 한 번 지나가는 것만으로 껍질이 완성됩니다. 지나가면서
「왼쪽으로 꺾이지 않는 점」을 걷어내면 남는 것이 곧 답이에요.

<!--proof:concept-scale-->

```text
입력                서로 다른 점  정의를 그대로 옮기면  사슬 둘이면  앞이 뒤의 몇 배
전개 입력                      7                   103           14              7.4
흩어진 점 100 개             100               123,544          374            330.3
흩어진 점 1,000 개         1,000            91,609,357        3,972          23063.8

└ 둘 다 방향 판정 횟수다. 서로 다른 점이 100 에서 1,000 으로 열 배가 될 때 앞은 741.5 배가 되고 뒤는 10.6 배가 된다
```

두 번 지나가는 이유는 하나입니다. 왼쪽에서 오른쪽으로만 지나가면 **아래쪽 경계**만 나오고,
위쪽 경계는 반대 방향으로 한 번 더 지나가야 나와요. 그렇게 얻은 두 사슬을 이으면 껍질 한
바퀴가 됩니다.

비용은 정렬이 결정합니다. 점 개수를 `n` 이라 하면 정렬이 `O(n log n)` 이고, 사슬을 쌓는
일은 점 개수에 비례하는 `O(n)` 이에요. 추가로 잡는 칸도 `O(n)` 인데, 그 두 값이 어디서
나오는지는 뒤에서 유도합니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **좌표평면 위의 점과 벡터.** 두 점의 차 `(a_x − o_x, a_y − o_y)` 를 방향으로 읽을 수
  있어야 해요. 이 글의 판정 하나가 그 차 둘로만 만들어집니다.
- **외적의 부호가 회전 방향을 뜻한다는 것.** 두 벡터의 외적이 양수면 앞 벡터에서 뒷 벡터로
  반시계로 돌아간 것입니다. 이 사실 하나가 껍질 판정 전부를 담당해요. 같은 판정을 선분
  교차에서 쓰는 것은 [`segmentsIntersect`](../segmentsIntersect/segmentsIntersect-problem.md)
  가 다룹니다.
- **스택의 담기와 걷어내기가 한 번에 얼마나 드는지.** 배열 끝에 담고 끝에서 걷어내는 일은
  배열 길이와 상관없이 일정합니다.
- **정렬의 비용이 `O(n log n)` 이라는 것.** 이 절차의 비용을 정렬이 결정하므로, 무엇이
  전체를 좌우하는지 알려면 이것을 알아야 해요.
- **배정밀도 부동소수점 수가 정수를 담는 범위.** 자바스크립트의 `number` 는 절댓값
  9,007,199,254,740,991 까지의 정수만 오차 없이 담습니다. 이 문제의 좌표를 곱하면 그 범위를
  넘어가고, 세 번째 멈춤이 그 자리를 다룹니다.

```text
  점 집합을 감싸는 가장 작은 볼록 다각형의 꼭짓점  <- 이 글이 다루는 것
  두 선분이 만나는지 묻는다                        <- 다른 글이 다루는 것
  점 하나가 다각형 안에 있는지 묻는다              <- 또 다른 글이 다루는 것
  다각형의 넓이를 구한다                           <- 또 다른 글이 다루는 것
```

### 아이디어 상세 — 왼쪽으로만 꺾이는 사슬 둘을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
type Point = [number, number];

function convexHull(points: Point[]): Point[];
```

- 입력: 평면 위의 점 배열 하나. 같은 좌표가 여러 번 들어올 수 있습니다.
- 출력: 볼록 껍질의 꼭짓점을 **반시계 방향**으로 담은 배열. 변 위의 공선 중간 점은 담지
  않고, 같은 좌표도 한 번만 담아요. 점이 하나면 그 점, 둘이면 둘 다, 전부 한 직선 위면
  양 끝점 둘입니다.
- 제약: 점이 최대 100,000 개이고 좌표는 `−10^9` 이상 `10^9` 이하의 정수입니다. 시간 1 초,
  메모리 256 MB 예요.

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 입력 점의 개수 | 최대 100,000 |
| `m` | 그중 서로 다른 좌표의 개수 | `m ≤ n` |
| `h` | 답의 꼭짓점 개수 | `h ≤ m` |
| `p` | 사슬에 담으려는 점 | 정렬 순서로 하나씩 온다. 판정에서는 `b` 자리에 온다 |
| `o` · `a` · `b` | 방향 판정이 받는 세 점 | `o → a → b` 순서로 꺾임을 잰다 |
| `C` | 좌표의 절댓값 상한 | `10^9` |
| `SAFE` | 배정밀도 부호를 믿을 수 있는 하한 | 2,048 |

기호 `o` · `a` · `b` 는 판정이 받는 자리의 이름이라 걸음마다 다른 점을 가리켜요. 사슬을 쌓을
때는 `o` 와 `a` 가 사슬의 끝 두 점이고 `b` 자리에 담으려는 점 `p` 가 옵니다. 코드에서는
`sideOf` 가 그 셋을 받아 판정값을 돌려줘요.

가장 먼저 떠오르는 방법으로 시작합시다. 껍질의 변이란 「그 직선의 한쪽에만 나머지 점이 있는
직선」이니, 점 쌍을 전부 잡고 나머지 점을 하나씩 확인하면 됩니다.

```ts
function byDefinition(points: Point[]): Point[] {
  const onEdge = new Set<Point>();
  for (const a of points) {
    for (const b of points) {
      if (a === b) continue;
      // 나머지가 전부 왼쪽이거나 직선 위인가
      let allLeft = true;
      for (const c of points) {
        if (c === a || c === b) continue;
        if (sideOf(a, b, c) < 0) { allLeft = false; break; }
      }
      if (allLeft) { onEdge.add(a); onEdge.add(b); }
    }
  }
  return [...onEdge];
}
```

전개 입력으로 쓸 점 여덟 개에서 이 방법이 얼마나 하는지 재 봅니다.

<!--proof:build-naive-->

```text
무엇                              값
서로 다른 점 m                     7
확인해야 하는 순서쌍 m(m−1)       42
순서쌍마다 남은 점 m−2             5
실제로 든 방향 판정              103
가지치기 없이 셀 때 m(m−1)(m−2)  210
껍질의 변으로 잡힌 순서쌍          7
버려진 순서쌍                     35

이 판정이 내는 점  (0,0) (0,3) (3,0) (3,4) (6,0) (6,3)
실제 꼭짓점       (0,0) (6,0) (6,3) (3,4) (0,3)
└ 변 위의 공선 중간 점 (3,0) 이 섞여 들어와, 꼭짓점만 남기려면 규칙이 하나 더 든다
```

**두 가지가 한꺼번에 나옵니다.** 첫째, 확인해야 하는 순서쌍이 `m(m−1)` 개이고 순서쌍마다
나머지 `m−2` 개를 보므로 가지치기를 안 하면 점이 열 배가 될 때 일이 천 배가 돼요. 가지치기를
넣어도 앞 절의 실측이 점 100 개에서 1,000 개로 갈 때 123,544 번에서 91,609,357 번으로 741.5 배가
됩니다. 제약의 최댓값 100,000 을 넣으면 가지치기 없이 999,970,000,200,000 번이라 1 초 안에
끝나지 않아요. 둘째, 이 판정이 내는 것은 꼭짓점이 아니라 **변 위의 점 전부**라 공선 중간 점을
걷어낼 규칙이 하나 더 듭니다.

그런데 위 코드가 하는 일을 다시 보면 낭비가 보여요. 껍질의 변은 `h` 개뿐인데 `m(m−1)` 개의
순서쌍을 전부 확인합니다. **점을 미리 어떤 순서로 늘어놓으면 후보를 훨씬 줄일 수 있지
않을까요?** 그러면 순서를 무엇으로 정할지가 다음 물음이 됩니다.

```text
확인한 것과 쓸모 있던 것
  확인한 순서쌍             42 개   m(m−1) 이고 m 이 일곱이다
  껍질의 변으로 잡힌 것      7 개   위 표의 여섯째 줄이 그 값이다
  버려진 것                 35 개   「한쪽에만 있지 않다」 를 확인하고 버려진다
└ 껍질의 변은 다섯인데 순서쌍이 일곱인 것은 변 위의 공선 중간 점이 만든 자리가 둘 더 있기 때문이다
```

정렬 기준 후보가 둘 있습니다. 껍질을 한 바퀴 감싸는 순서를 그대로 만들려면 **기준점에서 본
각도**로 정렬하는 것이 자연스럽고, 단순하게 가려면 **좌표**(`x` 를 먼저, 같으면 `y`)로 정렬하는
것이 있어요. 같은 입력에서 둘을 재 봅니다.

<!--proof:build-sort-basis-->

```text
입력                  좌표 정렬 비교  좌표 정렬 방향 판정  각도 정렬 비교  각도 정렬 방향 판정
전개 입력                         16                    0              13                   13
흩어진 점 1,000 개             8,726                    0           8,710                8,710
흩어진 점 100,000 개       1,536,171                    0       1,536,297            1,536,297

└ 비교 횟수는 둘이 거의 같은데, 각도 정렬은 비교마다 방향 판정이 하나씩 붙는다
```

**비교 횟수는 둘이 거의 같은데 각도 정렬은 방향 판정이 비교마다 하나씩 붙습니다.** 제약의
최댓값에서 방향 판정 1,536,297 번이 정렬 단계에서만 더 드는 것이고, 좌표 정렬 쪽은 그 자리가
0 이에요. 여기서 관찰할 것이 하나 있습니다 — 좌표 정렬은 **기하 연산을 한 번도 쓰지 않고**
순서를 정합니다.

```text
두 순서가 껍질과 어떤 관계인가
  각도 정렬  기준점을 중심으로 한 바퀴   껍질을 감싸는 순서와 방향이 같다
  좌표 정렬  왼쪽에서 오른쪽으로 한 줄   껍질의 아래쪽과 위쪽이 섞여 있다
└ 그래서 각도 정렬은 사슬 하나로 끝나고 좌표 정렬은 그렇지 않다
```

그 순서로 사슬을 하나만 쌓으면 어떻게 되는지 값으로 확인합시다.

<!--proof:build-one-chain-->

```text
무엇                           결과
왼쪽에서 오른쪽으로 사슬 하나  (0,0) (6,0) (6,3)
실제 꼭짓점                    (0,0) (6,0) (6,3) (3,4) (0,3)
사슬 하나가 놓치는 점          (3,4) (0,3)

└ 놓친 점은 전부 위쪽 경계에 있다. 왼쪽에서 오른쪽으로 한 번 지나가면 아래쪽만 남는다
```

**아래쪽 절반만 나옵니다.** 놓친 두 점은 전부 위쪽 경계에 있고, 이유는 간단해요 — 왼쪽에서
오른쪽으로 가면서 「왼쪽으로 꺾이는 것만 남긴다」를 지키면 아래로 볼록한 사슬 하나가 만들어집니다.
위쪽 경계는 오른쪽에서 왼쪽으로 지나가야 같은 규칙으로 나와요.

여기서 개념이 정해집니다. **정렬한 순서 위에서 왼쪽으로만 꺾이는 사슬을 쌓되, 방향을 바꿔 두 번
쌓는다.** 아래 사슬은 정렬 순서대로, 위 사슬은 거꾸로 지나가고, 각 사슬은 새 점을 담기 전에
「끝 두 점과 새 점이 왼쪽으로 꺾이는가」를 물어 아니면 끝점을 걷어냅니다.

```text
아래 사슬                                     위 사슬
  왼쪽 -----------> 오른쪽                    왼쪽 <----------- 오른쪽
        \         /                                ___________
         \_______/                                /           \
  └ 아래쪽 경계가 남는다                      └ 같은 규칙이 위쪽 경계를 남긴다

  두 사슬을 이으면 반시계 한 바퀴가 된다
```

**걸음마다 사슬이 어떻게 이어지는지 값으로 확인하고 갑시다.** 쉬운 경우는 걷어낼 것이 없는
걸음이고, 불안한 경우는 **한 걸음에서 두 번 걷어내는** 걸음이에요. 걷어낸 자리가 그 뒤 걸음에
어떻게 이어지는지가 이 절차를 믿을 수 있는가를 정합니다.

```text
담으려는 점  판정 횟수  걷어낸 점    담은 뒤의 사슬
(0,0)                0  없음         (0,0)
(0,3)                0  없음         (0,0) (0,3)
(3,0)                1  (0,3)        (0,0) (3,0)
(3,2)                1  없음         (0,0) (3,0) (3,2)
(3,4)                2  (3,2)        (0,0) (3,0) (3,4)
(6,0)                2  (3,4) (3,0)  (0,0) (6,0)
(6,3)                1  없음         (0,0) (6,0) (6,3)

└ 걷어내기가 두 번 난 걸음(다섯째·여섯째 줄)에서도 사슬은 이어진다. 걷어낸 점이 다시 담기는 일은 없다
```

**걷어내기가 여러 번 일어나도 사슬은 끊기지 않습니다.** 여섯째 줄에서 두 점을 걷어내는데, 걷어낸
뒤에도 사슬 끝이 언제나 두 점 이상이거나 판정을 못 할 만큼 짧아지고, 그때는 판정 없이 담아요.
그리고 한 번 걷어낸 점은 그 사슬에 다시 담기지 않습니다 — 정렬 순서를 되돌아가는 일이 없기
때문이에요.

```text
한 점이 사슬에서 겪는 일
  담긴다      사슬마다 정확히 한 번
  걷어내진다  담긴 뒤에 많아야 한 번, 그 뒤로는 이 사슬이 다시 안 본다
└ 그래서 걷어내기 총수는 담기 총수를 넘을 수 없다
```

이 사실이 비용을 정합니다. 사슬 하나에서 점이 담기는 것은 **점마다 정확히 한 번**이고 걷어내는
것은 그보다 많을 수 없어요. 그러면 방향 판정의 총수도 점 개수에 비례해야 하는데, 실제로 그런지
규모를 바꿔 가며 재 봅니다.

<!--proof:build-linear-->

```text
점 개수  서로 다른 점 m  꼭짓점 h  방향 판정  4m − h − 6   비율
    100             100        15        374         379  0.987

100,000         100,000        34    399,960     399,960  1.000

└ 점을 열 배 하면 방향 판정도 열 배가 된다. 규모가 커질수록 상한에 가까워진다
```

**점을 열 배 하면 방향 판정도 열 배가 됩니다.** 정의를 그대로 옮긴 방법이 천 배가 되던 자리예요.
제약의 최댓값에서 399,960 번이고, 같은 자리에서 정의를 옮긴 방법은 999,970,000,200,000 번입니다.

```text
얻은 절차 한 벌
  1. 점을 x 로, 같으면 y 로 정렬한다
  2. 이웃한 같은 좌표를 하나로 합친다
  3. 서로 다른 점이 둘 이하면 그대로 돌려준다
  4. 정렬 순서대로 지나가며 아래 사슬을 쌓는다 — 왼쪽으로 안 꺾이면 끝점을 걷어낸다
  5. 거꾸로 지나가며 같은 규칙으로 위 사슬을 쌓는다
  6. 두 사슬의 마지막 점을 하나씩 떼고 이어 돌려준다
       └ 제약의 최댓값에서 판정 999,970,000,200,000 번이 399,960 번이 된다
```

### 수행으로 알아보는 알고리즘 — 점 여덟 개에서 꼭짓점 다섯을 낸다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 점 여덟 개를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const points: Point[] = [[3, 2], [6, 0], [0, 0], [3, 4], [6, 3], [0, 3], [3, 0], [6, 0]];
// 이 절이 끝나면 [[0, 0], [6, 0], [6, 3], [3, 4], [0, 3]] 이 나와야 한다
```

왜 하필 이 여덟일까요? 안쪽 점 하나 · 변 위의 공선 중간 점 하나 · 같은 좌표 한 쌍이 다 들어
있고, 세로로 늘어선 `(3,0)` `(3,2)` `(3,4)` 와 가로로 늘어선 `(0,0)` `(3,0)` `(6,0)` 이 있어
판정값이 0 이 되는 자리가 세 곳 나오며, 두 사슬이 서로 다른 꼭짓점을 담는 모양이라 사슬을 왜
둘로 가르는지가 한 화면에 들어가기 때문이에요.

```text
절차 전체를 한 장으로

  T1        점을 좌표로 정렬하고 같은 좌표를 하나로 합친다
              ① 서로 다른 점이 둘 이하면 그 자리에서 돌려준다
  T2~T8     정렬 순서대로 아래 사슬을 쌓는다
              ④ 끝 두 점과 새 점이 왼쪽으로 안 꺾이면 끝점을 걷어낸다
              판정은 ② 배정밀도로 먼저 재고, 값이 작으면 ③ 큰 정수로 다시 잰다
  T9~T15    거꾸로 지나가며 같은 규칙으로 위 사슬을 쌓는다
  T16       ⑤ 두 사슬의 마지막 점을 하나씩 떼고 이어 돌려준다
```

#### 1. 정렬하고 같은 좌표를 하나로 합친다

첫 조각은 준비입니다. 좌표로 정렬하면 같은 좌표가 이웃하므로, 앞 점과만 견주어도 중복이 전부
걸러져요.

```ts
const sorted = [...points].sort((p, q) => p[0] - q[0] || p[1] - q[1]);

const uniq: Point[] = [];
for (const p of sorted) {
  const last = uniq.at(-1);
  if (last === undefined || last[0] !== p[0] || last[1] !== p[1]) uniq.push(p);
}
if (uniq.length <= 2) return uniq;                       // ① 꺾일 자리가 없다
```

`①` 은 이 입력에서 거짓이라 여기서 끝나지 않습니다. 참이 되는 것은 점이 하나뿐이거나 둘뿐이거나
같은 좌표만 여러 개 들어온 경우예요.

```text
정렬 전  (3,2) (6,0) (0,0) (3,4) (6,3) (0,3) (3,0) (6,0)
정렬 후  (0,0) (0,3) (3,0) (3,2) (3,4) (6,0) (6,0) (6,3)
합친 뒤  (0,0) (0,3) (3,0) (3,2) (3,4) (6,0) (6,3)
                                        └ 이웃한 (6,0) 둘이 하나가 됐다

① 이 참이 되는 입력
  convexHull([[3, 7]])                  서로 다른 점 1 개    답 [[3, 7]]
  convexHull([[0, 0], [5, 5]])          서로 다른 점 2 개    답 [[0, 0], [5, 5]]
  convexHull([[2, 2], [2, 2], [2, 2]])  서로 다른 점 1 개    답 [[2, 2]]
```

#### 멈춤 — `x` 좌표만으로 정렬해도 될 것 같다

여기서 헷갈리기 쉬운 포인트는 정렬 기준의 둘째 자리입니다. 「왼쪽에서 오른쪽으로 지나가는 것이
목적이니 `x` 만 맞으면 되겠다」로 읽기 쉬워요. 그 생각대로 한 줄만 바꿔 봅시다.

```ts
const sorted = [...points].sort((p, q) => p[0] - q[0]);  // y 를 견주는 자리를 없앴다
```

두 입력으로 확인해 봅니다.

세로줄 `x = 6` 의 두 점이 아래에서 위로 오지 않아 두 사슬이 `(6,3)` 을 함께 놓칩니다.

```text
└ 같은 좌표가 이웃하고 세로줄 안에서 아래에서 위로 와야 두 사슬이 제 몫을 담는다
```

#### 2. 정렬 순서대로 아래 사슬을 쌓는다

둘째 조각이 이 절차의 본체입니다. 점을 하나씩 담되, 담기 전에 사슬 끝 두 점과 새 점이 왼쪽으로
꺾이는지 묻고 아니면 끝점을 걷어내요.

```ts
function buildChain(seq: Point[]): Point[] {
  const chain: Point[] = [];
  for (const p of seq) {
    // ④ 왼쪽으로 안 꺾이면 끝점을 걷어낸다
    while (chain.length >= 2 && turnAtEnd(chain, p) <= 0) chain.pop();
    chain.push(p);
  }
  return chain;
}
const lower = buildChain(uniq);
```

`④` 의 조건은 걸음마다 여러 번 참이 될 수 있습니다. 이 입력의 아래 사슬에서는 일곱 걸음 동안
판정을 일곱 번 하고 그중 네 번이 걷어내기예요.

```text
아래 사슬이 쌓이는 모양 (판정값이 0 인 자리는 = 로 적었다)

  (0,0) (0,3)            (0,0)→(0,3)→(3,0) 이 오른쪽 꺾임      (0,3) 을 걷어낸다
  (0,0) (3,0)            (0,0)→(3,0)→(3,2) 가 왼쪽 꺾임        (3,2) 를 담는다
  (0,0) (3,0) (3,2)      (3,0)→(3,2)→(3,4) 가 =                (3,2) 를 걷어낸다
  (0,0) (3,0) (3,4)      (3,0)→(3,4)→(6,0) 이 오른쪽 꺾임      (3,4) 를 걷어낸다
  (0,0) (3,0)            (0,0)→(3,0)→(6,0) 이 =                (3,0) 을 걷어낸다
  (0,0) (6,0) (6,3)      끝
  └ 세로줄 x = 3 의 세 점이 전부 빠졌다
```

#### 3. 거꾸로 지나가며 위 사슬을 쌓는다

셋째 조각은 같은 함수를 순서만 바꿔 한 번 더 부르는 것입니다. 새 규칙이 없어요 — 오른쪽에서
왼쪽으로 가면 위쪽 경계가 「왼쪽으로만 꺾이는 사슬」이 됩니다.

```ts
const upper = buildChain([...uniq].reverse());
```

두 사슬이 담는 점이 어떻게 갈리는지 보고 갑시다. 아래 사슬은 세 점, 위 사슬은 네 점으로
끝나고 양 끝의 두 점을 서로 나눠 갖습니다.

```text
아래 사슬  (0,0) (6,0) (6,3)
위 사슬                (6,3) (3,4) (0,3) (0,0)
                       └ 겹치는 두 점이 (0,0) 과 (6,3) 이다

붙여 놓으면  (0,0) (6,0) (6,3) | (6,3) (3,4) (0,3) (0,0)
             └ 껍질 한 바퀴인데 두 점이 두 번씩 들어 있다
```

#### 멈춤 — 두 사슬을 그대로 이으면 끝점이 두 번 들어간다

여기서 헷갈리기 쉬운 포인트는 두 사슬의 경계입니다. 「사슬 둘을 만들었으니 이어 붙이면 끝」으로
읽기 쉬워요. 아래 사슬의 마지막 점을 떼지 않고 그대로 이어 봅시다.

```ts
upper.pop();
```

```text
②  배정밀도로 먼저 잰다     열네 번 실행 · 값이 전부 SAFE 이하라 여기서 끝나는 일이 없다
③  큰 정수로 다시 잰다      그래서 열네 번 다 실행된다
④  왼쪽으로 안 꺾이면 걷어낸다  일곱 번 참(걷어냄) · 일곱 번 거짓(유지)
⑤  끝점을 떼고 잇는다       T16 에서 (6,3) 과 (0,0) 을 하나씩 뗀다
                            └ ② 가 그 자리에서 끝나는 것은 좌표가 큰 입력에서다
```

`②` 의 빠른 경로가 실제로 참이 되는 입력은 바로 다음 멈춤이 다룹니다 — 좌표가 상한에 붙으면
곱이 커져 대부분의 판정이 그 자리에서 끝나고, 그때 오히려 부호를 못 믿는 자리가 생겨요.

#### 멈춤 — 좌표가 상한에 붙으면 배정밀도 곱이 정수를 통째로 못 담는다

여기서 헷갈리기 쉬운 포인트는 판정의 산술입니다. 「좌표가 정수이고 자바스크립트가 정수를 다루니
곱셈도 정확하겠다」로 읽기 쉬워요. 그 생각대로 판정을 배정밀도 곱 하나로만 끝내 봅시다.

```ts
const approx = ux * vy - uy * vx;
return approx > 0 ? 1 : approx < 0 ? -1 : 0;             // 큰 정수로 다시 재는 자리를 없앴다
```

세 입력으로 확인해 봅니다.


**기존 시험은 전부 통과합니다.** 좌표 상한 `±10^9` 을 넣은 케이스도, 전개 입력도 답이 같아요.
그럼에도 고치는 이유는 제약 안의 다른 입력에서 답이 갈리기 때문입니다 — 위 표의 셋째 줄에서
꼭짓점 하나가 통째로 빠졌어요.

빠진 이유는 곱의 크기에 있습니다. 좌표의 차가 최대 `2×10^9` 이고 그 곱이 `4×10^18` 까지 커지는데,
배정밀도가 오차 없이 담는 정수는 9,007,199,254,740,991 까지예요. 두 곱이 각각 반올림되고 그
차이가 작으면 부호가 뒤집히거나 0 이 됩니다.

```text
언제 믿을 수 있고 언제 못 믿는가
  |배정밀도로 잰 값| > SAFE   반올림 오차보다 크므로 부호가 확실하다
  |배정밀도로 잰 값| ≤ SAFE   오차 안이라 부호를 못 정한다 → 큰 정수로 다시 잰다
                              └ SAFE 를 왜 2,048 로 두는지는 「수식 정의와 유도」가 낸다

  전개 입력은 좌표가 작아 판정 열네 번이 전부 큰 정수 경로로 간다
  좌표가 상한에 붙으면 반대가 된다 — 대부분이 빠른 경로에서 끝나고 위 표의 자리만 되잰다
```

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 둘이에요 — 상수 `SAFE` 의
선언과, 판정을 `turnAtEnd` 로 감싼 한 겹입니다. 뒤엣것은 사슬이 두 점보다 짧으면 잴 것이
없으므로 그때 왼쪽 꺾임으로 답해 `④` 의 조건이 그냥 거짓이 되게 해요.

```ts
export type Point = [number, number];

const SAFE = 2048;

export function sideOf(o: Point, a: Point, b: Point): number {
  const ux = a[0] - o[0];
  const uy = a[1] - o[1];
  const vx = b[0] - o[0];
  const vy = b[1] - o[1];
  // ② 먼저 배정밀도로 재고, 값이 오차 한계보다 크면 그 부호를 그대로 쓴다.
  const approx = ux * vy - uy * vx;
  if (approx > SAFE || approx < -SAFE) return approx > 0 ? 1 : -1;
  // ③ 오차 한계 안이면 부호를 못 믿는다. 큰 정수로 다시 재서 확정한다.
  const exact = BigInt(ux) * BigInt(vy) - BigInt(uy) * BigInt(vx);
  return exact > 0n ? 1 : exact < 0n ? -1 : 0;
}

/** 사슬의 끝 두 점과 `p` 가 이루는 방향. 사슬이 두 점보다 짧으면 판정할 것이 없다. */
function turnAtEnd(chain: Point[], p: Point): number {
  const o = chain.at(-2);
  const a = chain.at(-1);
  if (o === undefined || a === undefined) return 1;
  return sideOf(o, a, p);
}

function buildChain(seq: Point[]): Point[] {
  const chain: Point[] = [];
  for (const p of seq) {
    // ④ 끝 두 점과 p 가 왼쪽으로 꺾이지 않으면 끝점을 걷어낸다.
    while (chain.length >= 2 && turnAtEnd(chain, p) <= 0) chain.pop();
    chain.push(p);
  }
  return chain;
}

export function convexHull(points: Point[]): Point[] {
  const sorted = [...points].sort((p, q) => p[0] - q[0] || p[1] - q[1]);

  const uniq: Point[] = [];
  for (const p of sorted) {
    const last = uniq.at(-1);
    if (last === undefined || last[0] !== p[0] || last[1] !== p[1])
      uniq.push(p);
  }
  // ① 서로 다른 점이 둘 이하면 그 점들이 그대로 답이다. 꺾일 자리가 없다.
  if (uniq.length <= 2) return uniq;

  const lower = buildChain(uniq);
  const upper = buildChain([...uniq].reverse());

  // ⑤ 두 사슬의 마지막 점은 상대 사슬의 첫 점과 같다. 떼고 이어야 한 번씩만 담긴다.
  lower.pop();
  upper.pop();
  return lower.concat(upper);
}
```

```text
convexHull([[3,2],[6,0],[0,0],[3,4],[6,3],[0,3],[3,0],[6,0]])  ->  [[0,0],[6,0],[6,3],[3,4],[0,3]]
convexHull([[0,0],[2,0],[4,0],[4,4],[0,4]])                    ->  [[0,0],[4,0],[4,4],[0,4]]
convexHull([[0,0],[1,0],[2,0],[3,0]])                          ->  [[0,0],[3,0]]
convexHull([[3,7]])                                            ->  [[3,7]]
convexHull([])                                                 ->  []
```

### 알아 두면 좋은 개념 — 단조 스택

전개에서 사슬은 배열 끝에만 담고 끝에서만 걷어냈습니다. 그러니까 사슬은 스택이고, 그 스택은
「안에 남은 것이 언제나 왼쪽 꺾임 순서」라는 성질을 유지했어요. 담기 전에 그 성질을 깨는 원소를
전부 걷어내는 스택을 **단조 스택**이라고 부릅니다.

<!--proof:related-stack-->

```text
입력                  담은 횟수  걷어낸 횟수  담은 − 걷어낸  두 사슬에 남은 점
전개 입력                    14            7              7                  7
흩어진 점 1,000 개        2,000        1,982             18                 18
흩어진 점 100,000 개    200,000      199,964             36                 36

└ 점 하나가 담기는 것은 사슬마다 한 번뿐이고, 걷어내는 것은 그보다 많을 수 없다
```

**담은 횟수에서 걷어낸 횟수를 빼면 남은 개수입니다.** 원소 하나가 담기는 것은 사슬마다 한
번뿐이라 담기 총수가 서로 다른 점의 두 배이고, 걷어내기는 담긴 것에서만 일어나므로 걷어내기
총수는 담기 총수를 넘을 수 없어요. 그래서 안쪽
반복문이 몇 번 실행되든 전체는 원소 개수에 비례합니다.

같은 모양이 나오는 다른 자리가 여럿이에요. 히스토그램에서 가장 큰 직사각형을 찾을 때는 높이가
줄어드는 순간 스택을 걷어내고, 「다음으로 큰 원소」를 구할 때는 새 값보다 작은 것을 전부
걷어내며, [`convexHullTrick`](../../advanced/convexHullTrick/convexHullTrick-problem.md) 은
직선의 기울기 순서로 같은 일을 합니다.

```text
같은 모양이 나오는 자리                 스택이 유지하는 성질
  볼록 껍질의 사슬                      이웃 셋이 왼쪽으로 꺾인다
  히스토그램의 가장 큰 직사각형         높이가 오름차순이다
  다음으로 큰 원소                      값이 내림차순이다
  직선 집합에서 최댓값 유지             기울기가 오름차순이다
└ 넷 다 담기 전에 성질을 깨는 원소를 걷어내고, 그래서 전체 비용이 원소 개수에 비례한다
```

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 방향 판정의 총수를 식으로 어떻게
닫는지, 무엇이 걸음마다 참으로 남는지, 그리고 기본 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **점이 전부 미리 주어집니다.** 한 번에 다 받아 정렬할 수 있어야 해요. 점이 하나씩 들어오는
  중에도 껍질을 답해야 하면 다른 자료구조가 듭니다.
- **꼭짓점 수를 미리 알 수 없습니다.** 껍질이 몇 개짜리인지 모르면 점 개수에만 매인 비용이
  안전해요.
- **좌표가 정수입니다.** 판정의 부호를 정확히 정할 수 있으면 껍질의 모양이 입력만으로 정해집니다.
- **껍질을 한 번 만들어 여러 번 씁니다.** 지름 · 최소 둘러싸는 도형 · 두 집합의 거리처럼
  껍질 위에서만 답이 나오는 문제가 그 뒤에 붙어요.

```text
네 조건이 코드의 모양을 그대로 정한다
  한 번에 다 받는다    -> 맨 앞에서 통째로 정렬한다
  h 를 모른다          -> 비용을 n 으로만 적는다
  좌표가 정수다        -> 판정을 큰 정수로 확정할 수 있다
  여러 번 쓴다         -> 꼭짓점 배열 하나를 남겨 둔다
```

세 번째 줄이 이 절차의 경계입니다. 좌표가 실수면 「한 직선 위인가」가 원래 정해지지 않고, 그때는
허용 오차를 정하는 다른 이야기가 시작돼요.

| 무엇을 묻는가 | 무엇을 쓰는가 | 왜 |
| --- | --- | --- |
| 점 집합의 껍질 전부 | 이 절차 | 정렬 한 번에 사슬 두 번이면 끝난다 |
| 껍질 위 가장 먼 두 점 | 이 절차 + 회전하는 캘리퍼스 | 껍질을 먼저 얻어야 시작한다 |
| 점 하나가 다각형 안인가 | 광선 쏘기 | 껍질을 만들 이유가 없다 |
| 점이 하나씩 들어오는 중의 껍질 | 동적 볼록 껍질 자료구조 | 정렬을 다시 할 수 없다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "모든 점을 포함하는 최소 볼록 다각형"  "울타리"  <- 껍질 그 자체를 묻는다
  "가장 먼 두 점"  "지름"                          <- 껍질 위에서만 답이 나온다
  "점들을 감싸는 최소 넓이/둘레"                   <- 껍질을 먼저 만든다
  "볼록 다각형 위의 최적화"                        <- 껍질을 만든 뒤 삼분 탐색으로 간다

제약에 이런 모양이 보이면
  점이 10^5 개 안팎이고 좌표가 정수다
  시간 1 초에 점을 여러 번 지나가도 되는 여유가 있다

반대로 이런 말이 보이면 해당하지 않는다
  "점이 하나씩 추가되며 매번 답"        <- 정렬을 다시 할 수 없다
  "다각형이 이미 볼록하다고 주어진다"   <- 껍질을 만들 필요가 없다
  "3차원 점들의 껍질"                   <- 사슬 둘로 안 갈린다. 다른 절차로 간다
```

세 번째 무리가 보이면 다른 절차로 갑니다. 이미 볼록한 다각형 위에서 지름을 묻는 것은
[`rotatingCalipersDiameter`](../rotatingCalipersDiameter/rotatingCalipersDiameter-problem.md)
쪽이고, 가장 가까운 두 점은 [`closestPairOfPoints`](../closestPairOfPoints/closestPairOfPoints-problem.md)
쪽이에요.

#### 실제로 쓰이는 곳

- **CGAL 의 `Convex_hull_2` 패키지 `ch_graham_andrew`.** 매뉴얼이 이 절차를 이름 그대로
  적습니다 — *"This function implements Andrew's variant of the Graham scan algorithm [3] and
  follows the presentation of Mehlhorn [9]. This algorithm requires O(n log n) time in the worst
  case for n input points."* 반환 규약도 같아요 — *"generates the counterclockwise sequence of
  extreme points of the points in the range [first,beyond)"* 라고 적고, 요구하는 술어에
  `Less_xy_2`(좌표 비교)와 `Left_turn_2`(왼쪽 꺾임 판정)를 명시합니다.
  ([CGAL 5.6 Convex_hull_2](https://doc.cgal.org/latest/Convex_hull_2/index.html), 조회 2026-09-04)
- **CGAL 의 커널이 술어를 정확히 재는 이유.** 매뉴얼이 *"Rounding errors introduced by an
  inaccurate arithmetic may lead to inconsistent decisions, causing unexpected failures for some
  correct input data"* 라 적고, 기본으로 권하는 커널을 *"provides exact geometric predicates, but
  geometric constructions may be inexact due to round-off errors"* 로 설명해요 — 세 번째 멈춤이
  다룬 자리를 그대로 말하는 문장입니다.
  ([CGAL 5.6 2D and 3D Geometry Kernel](https://doc.cgal.org/latest/Kernel_23/index.html), 조회 2026-09-04)
- **Shewchuk 의 로버스트 술어.** 배정밀도로 먼저 재고 모자랄 때만 정확한 산술로 되재는 방식을
  논문 제목이 그대로 적습니다 — *"Adaptive Precision Floating-Point Arithmetic and Fast Robust
  Geometric Predicates"*(Discrete & Computational Geometry 18:305-363, 1997). 배포 페이지가
  *"The algorithms are adaptive in the sense that they do only as much work as necessary to
  guarantee a correct result"* 와 *"The sign of a small determinant can typically be determined
  quickly unless the determinant is close to zero"* 라 적어요.
  ([Robust Predicates](https://www.cs.cmu.edu/~quake/robust.html), 조회 2026-09-04)
- **GEOS 의 `ConvexHull`.** 소스의 주석이 *"Use Graham scan to find convex hull."* 한 줄로
  절차를 적습니다.
  ([libgeos/geos `src/algorithm/ConvexHull.cpp`](https://github.com/libgeos/geos/blob/main/src/algorithm/ConvexHull.cpp),
  조회 2026-09-04)

```text
인용한 셋과 이 글의 차이
  CGAL         술어를 커널이 정확히 잰다        이 글은 걸러내기와 큰 정수를 직접 적는다
  Shewchuk     오차 한계를 항마다 계산한다      이 글은 좌표 상한 하나로 한계를 고정한다
  GEOS         실수 좌표를 받는다               이 글은 정수 좌표만 받는다
               └ 셋 다 「부호를 정확히 정한다」를 절차의 전제로 둔다
```

#### 경쟁 설계와의 대조

같은 목표(점 집합의 껍질 꼭짓점을 반시계 방향으로 전부 내는 것)를 노리는 다른 절차로 **선물
포장**(gift wrapping · Jarvis march)이 있습니다. 정렬을 하지 않고, 가장 왼쪽 점에서 시작해
「나머지 점이 전부 왼쪽에 오는 다음 점」을 매번 전수 검사로 골라 꼭짓점을 하나씩 이어 가는
방식이에요.

```text
두 설계가 하는 일
  정렬해 두고 사슬 둘  좌표로 한 번 정렬하고 두 방향으로 지나간다
  선물 포장            정렬 없이 꼭짓점마다 남은 점 전부를 확인한다
└ 오른쪽은 꼭짓점 하나를 정할 때마다 점 전부를 한 번씩 본다. 그래서 h 바퀴가 든다
```

입력은 생성식 하나로 고정하고 꼭짓점 수 `h` 만 바꿉니다. 껍질 꼭짓점은 포물선 `(t, 8192·t²)`
위의 `h` 개이고, 안쪽 점은 그 포물선 위·첫 점과 끝 점을 이은 현 아래에 채운 다음 고정 씨앗으로
섞어요. **전개 입력인 점 여덟 개를 그대로 넣고 규모만 키운 입력을 더했습니다** — 여덟 개에서는
두 설계의 계수가 38 대 45 로 붙어 있어 순서가 뒤집히는 자리가 안 나오기 때문이에요. 계수는 **좌표 비교와
방향 판정을 더한 기본 연산**이고, 둘 다 실행마다 같은 값이 나옵니다.

| 입력 | 정렬해 두고 사슬 둘 | 선물 포장 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 전개 입력(점 8 개 · `h` = 5) | **38** | 45 | 사슬 쪽이 7 번 적습니다 |
| 점 4,096 개 · `h` = 3 | 64,438 | **23,839** | 포장 쪽이 2.7 배 적습니다 |
| 점 4,096 개 · `h` = 13 | 64,450 | **61,626** | 포장 쪽이 2,824 번 적습니다 |
| 점 4,096 개 · `h` = 14 | **64,385** | 65,570 | **여기서 순서가 뒤집힙니다** |
| 점 4,096 개 · `h` = 350 | **63,807** | 1,441,444 | 사슬 쪽이 22.6 배 적습니다 |
| 점 100,000 개 · `h` = 350 | **2,035,713** | 35,199,693 | 사슬 쪽이 17.3 배 적습니다 |

**꼭짓점이 14 개가 되는 자리에서 순서가 뒤집힙니다.** 사슬 쪽의 계수는 `h` 가 바뀌어도 거의
그대로인데(점 4,096 개에서 63,807 부터 64,450 사이) 포장 쪽은 `h` 에 정비례해 늘어나기 때문이에요.
껍질이 작은 입력에서는 정렬 비용을 치를 이유가 없고, 껍질이 커지면 반대가 됩니다.

```text
경계가 그 자리인 이유 (점 4,096 개)
  사슬 쪽    정렬 비교 + 중복 제거 + 방향 판정    h 와 거의 무관하게 6 만 대다
  포장 쪽    중복 제거 + 시작점 찾기 + h 바퀴     h 하나에 3,944 번 늘어난다
             h = 13 이면 61,626 으로 아직 적고, h = 14 면 65,570 으로 넘어선다
```

**이 절차가 내주는 것은 잡는 칸입니다.** 정렬 사본 · 중복을 지운 목록 · 뒤집은 사본 · 사슬 둘을
들고 있어서 점 개수의 세 배쯤 쓰는데, 선물 포장은 중복을 지운 목록과 껍질만 들면 돼요.

| 입력 | 정렬해 두고 사슬 둘 | 선물 포장 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 전개 입력(점 8 개) | 27 | **19** | 포장 쪽이 8 칸 적습니다 |
| 점 100,000 개 · `h` = 350 | 300,350 | **200,350** | 포장 쪽이 10 만 칸 적습니다 |

이 문제의 제약은 점 100,000 개이고 꼭짓점 수에 대한 조건이 없습니다. 껍질이 작다는 보장이 없으면
`h` 가 점 개수에 가까워질 수 있고 그때 포장 쪽은 100 억 번이 되므로, **꼭짓점 수를 미리 아는
문제가 아니라면** 정렬해 두는 쪽이 답이에요. 지문이 「껍질이 세 점이다」처럼 `h` 를 못 박아
주면 그 판정은 다시 해야 합니다.

### 수식 정의와 유도

점 셋의 방향을 재는 값을 정의합니다. `o` 에서 `a` 로 가는 벡터와 `o` 에서 `b` 로 가는 벡터의
외적이고, 값의 절댓값은 세 점이 만드는 삼각형 넓이의 두 배예요.

$$\operatorname{cross}(o,a,b) \;=\; (a_x-o_x)(b_y-o_y)-(a_y-o_y)(b_x-o_x)$$

```text
식이 쓰는 두 벡터

          b               o 에서 a 로 가는 벡터   (a_x − o_x, a_y − o_y)
         / \              o 에서 b 로 가는 벡터   (b_x − o_x, b_y − o_y)
        /   \             두 벡터의 외적이 위 식이다
       o-----a
       └ o 에서 a 를 거쳐 b 로 가면 왼쪽으로 꺾이므로 값이 양수다
```

부호가 뜻하는 것은 셋입니다. 양수면 `o → a → b` 가 왼쪽으로 꺾이고, 음수면 오른쪽으로 꺾이며,
0 이면 세 점이 한 직선 위예요. 코드에서는 `sideOf` 가 이 값의 부호만 돌려줍니다.

<!--proof:math-check-->

```text
세 점                  식이 낸 값  부호  뜻
(0,0) → (3,0) → (3,2)           6     1  왼쪽으로 꺾인다
(0,0) → (0,3) → (3,0)          -9    -1  오른쪽으로 꺾인다
(3,0) → (3,2) → (3,4)           0     0  한 직선 위다
(0,0) → (3,0) → (6,0)           0     0  한 직선 위다

└ 값의 절댓값은 세 점이 만드는 삼각형 넓이의 두 배이고, 이 절차가 쓰는 것은 부호뿐이다
```

이제 방향 판정이 몇 번 드는지 닫습니다. 사슬 하나를 쌓을 때 점 `m` 개가 차례로 오고, 점 하나마다
안쪽 반복문이 몇 번 실행되는지는 입력에 딸리지만 **총합은 두 항으로 갈라 셀 수 있어요.**

$$\operatorname{tests} \;=\; \operatorname{pops} + \operatorname{keeps}$$

```text
판정 하나가 끝나는 두 가지 모양
  걷어내기로 끝난다   사슬 끝점이 빠지고 같은 점으로 한 번 더 잰다   pops 를 하나 올린다
  유지로 끝난다       그 점을 담고 다음 점으로 넘어간다              keeps 를 하나 올린다
└ 판정마다 둘 중 하나이므로 총수는 두 항의 합이다
```

두 항을 각각 누릅니다. 담기는 것이 점마다 한 번이므로 걷어낼 수 있는 것은 담긴 것뿐이고, 끝까지
남은 점은 걷어내지지 않았어요. 그리고 유지로 끝나는 판정은 점 하나마다 많아야 한 번인데, 첫 두
점은 사슬이 짧아 판정 자체를 하지 않습니다.

$$\operatorname{pops} \;\le\; m - |\text{사슬}| \qquad \operatorname{keeps} \;\le\; m-2$$

```text
두 항을 누르는 근거
  담기      점마다 사슬당 정확히 한 번
  걷어내기  담긴 것에서만 일어나고, 끝까지 남은 |사슬| 개는 빠진 적이 없다
  유지      점마다 많아야 한 번, 첫 두 점은 사슬이 짧아 판정 자체가 없다
└ 그래서 걷어내기는 m − |사슬| 이하이고 유지는 m − 2 이하다
```

두 부등식을 더하면 사슬 하나의 상한이 나옵니다.

$$\operatorname{tests} \;\le\; 2m - |\text{사슬}| - 2$$

```text
두 사슬의 길이를 더하면
  아래 사슬 + 위 사슬 = h + 2      양 끝의 두 점을 서로 나눠 갖는다
└ 그 둘이 겹치는 점이 정확히 둘이라 h 가 아니라 h + 2 다
```

두 사슬을 더합니다. 사슬 하나의 상한 `2m − |사슬| − 2` 를 두 벌 더하면 `4m` 에서 길이의 합
`h + 2` 를 빼고 상수 `2` 를 두 번 더 뺀 것이 되고, 그것이 이 절차 전체의 방향 판정 상한이에요.

$$\operatorname{tests}_{\text{전체}} \;\le\; 4m - (h+2) - 4 \;=\; 4m - h - 6$$

```ts
// 식을 그대로 옮긴 조각. 실제 절차는 이 값을 세지 않고 그만큼 판정하기만 한다.
const testBound = (m: number, h: number): number => 4 * m - h - 6;
```

상한과 실측을 여러 입력에서 대조합니다.

<!--proof:math-bound-->

```text
입력                            m   h   걷어냄     유지  판정 = 걷어냄 + 유지  4m − h − 6
전개 입력                       7   5        7        7                    14          17
변 위에 점이 있는 사각형        5   4        4        2                     6          10
한 직선 위의 넷                 4   2        4        0                     4           8
흩어진 점 1,000 개          1,000  16    1,982    1,990                 3,972       3,978
흩어진 점 100,000 개      100,000  34  199,964  199,996               399,960     399,960

제약의 최댓값에서 꼭짓점이 셋뿐이면 상한이 399,991 이고, 정의를 그대로 옮기면 가지치기 없이 999,970,000,200,000 이다
└ 한 직선 위인 입력은 유지로 끝나는 자리가 없어 상한의 절반에 그친다
```

이제 두 번째 유도로 갑니다. 배정밀도로 잰 값을 언제 믿을 수 있는지를 좌표 상한 `C` 로
일반화하는 것이에요. 좌표의 차는 `2C` 이하이므로 각 곱의 절댓값은 `4C^2` 이하이고, 배정밀도의
반올림은 값의 절댓값에 `2^{-53}` 을 곱한 것보다 작습니다.

$$|\text{앞의 곱 오차}| \le 4C^2 \cdot 2^{-53} \qquad |\text{뒤의 곱 오차}| \le 4C^2 \cdot 2^{-53}$$

```text
반올림이 일어나는 자리 셋
  앞의 곱   ux × vy 를 배정밀도에 담을 때
  뒤의 곱   uy × vx 를 배정밀도에 담을 때
  둘의 차   뺄셈 결과를 배정밀도에 담을 때
└ 세 자리의 오차를 더한 것이 전체 한계다
```

두 곱의 차는 절댓값이 `8C^2` 이하라 뺄셈에서 한 번 더 반올림됩니다. 세 오차를 더하면 전체
한계가 나와요.

$$\operatorname{err}(C) \;=\; 4C^2 2^{-53} + 4C^2 2^{-53} + 8C^2 2^{-53} \;=\; \frac{C^2}{2^{49}}$$

```text
세 항을 더하는 자리
  4C² · 2^-53  +  4C² · 2^-53  +  8C² · 2^-53  =  16C² · 2^-53
                                                  └ 16 = 2^4 이므로 2^-49 로 줄어든다
```

이 한계가 1 보다 작으면 배정밀도 값과 정확한 정수의 차이가 1 미만이라, 정확한 값이 0 이 아닌
정수인 이상 부호가 뒤집히지 않습니다. 그 경계를 실제로 찾고 제약의 좌표 상한을 넣어 봅니다.

<!--proof:math-error-->

```text
  좌표 상한 C  오차 한계 C² / 2^49  큰 정수 되재기가
    1,000,000             0.001776  필요 없다
   10,000,000             0.177636  필요 없다
  100,000,000            17.763568  필요하다
1,000,000,000          1776.356839  필요하다

한계가 1 보다 작은 가장 큰 좌표 상한  23,726,566  (0.999999966)
그 다음 값                            23,726,567  (1.000000050)
무작위 네 성분 300,000 벌의 실제 최대 편차  857

└ 한계는 넉넉하게 잡은 값이고, 그보다 큰 2 의 거듭제곱을 하한으로 둔다
```

**좌표가 23,726,566 이하면 걸러내기 자체가 필요 없습니다.** 그보다 크면 필요하고, 이 문제의
`10^9` 에서는 한계가 1776.36 이에요. `SAFE` 를 그보다 큰 2 의 거듭제곱인 2,048 로 두면
「배정밀도 값이 `SAFE` 보다 크면 부호가 확실하다」가 언제나 참이 됩니다.

### 불변식 — 사슬에 남은 점은 이웃 셋마다 왼쪽으로 꺾인다

파트 1 에서 코드가 동작하는 것을 열여섯 걸음으로 봤습니다. 그런데 그건 점 여덟 개에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **걸음마다 참으로 남는지**를 문장으로 세우고 그것이
실제로 유지되는지 확인해 봅시다.

> 점 하나를 사슬에 담은 직후, 사슬 안의 연속한 세 점은 **모두 왼쪽으로 꺾입니다.** 그리고 그때
> 걷어낸 점은 남은 사슬과 새 점이 만드는 영역 안에 있어 답이 될 수 없습니다.

```text
  앞 절반이 말하는 것   사슬 안이 볼록하다          꼭짓점이 아닌 것이 안 남는다
  뒤 절반이 말하는 것   걷어낸 것은 답이 아니다     빠뜨린 꼭짓점이 없다

  이 문장은 「점 하나를 담은 직후」 에 참이다   담기 전에는 새 점이 아직 사슬 밖이라 잴 것이 없다
```

문장이 두 절반인 것에 이유가 있습니다. 앞 절반은 답에 가짜가 안 섞인다는 것을 말하고, 뒤 절반은
답에서 빠지는 것이 없다는 것을 말해요. 둘이 합쳐져야 「사슬 둘을 이으면 껍질」이 됩니다.

**출발점부터 봅시다.** 사슬이 비어 있거나 점이 하나뿐이면 연속한 세 점이 없으니 앞 절반은 빈
채로 참이고, 걷어낸 점이 하나도 없으니 뒤 절반도 참이에요.

| 걸음 | 하는 일 | 앞 절반이 유지되는 근거 | 뒤 절반이 유지되는 근거 |
| --- | --- | --- | --- |
| 시작 | 사슬이 비어 있다 | 셋을 잴 자리가 없다 | 걷어낸 점이 없다 |
| 사슬이 두 점보다 짧다 | 판정 없이 담는다 | 셋을 잴 자리가 없다 | 걷어낸 점이 없다 |
| 판정값이 양수다 | 그대로 담는다 | 새로 생긴 셋이 왼쪽 꺾임이다 | 걷어낸 점이 없다 |
| 판정값이 0 이거나 음수다 | 끝점을 걷어내고 다시 잰다 | 걷어낸 뒤 다시 재므로 남는 셋은 전부 양수다 | 걷어낸 점은 `o` 와 `p` 를 이은 선분 위이거나 그 오른쪽이다 |

넷째 줄이 이 논증의 핵심입니다. 판정값이 0 이면 걷어낸 점이 `o` 와 `p` 를 이은 선분 위에 있으니
꼭짓점이 아니고, 음수면 그 선분의 오른쪽에 있으니 껍질 안쪽이에요. 어느 쪽이든 답에 들어갈 수
없는 점이라 걷어내도 잃는 것이 없습니다.

<!--proof:invariant-states-->

```text
담은 점  그 뒤의 사슬       이웃 셋의 판정값  불변식
(0,0)    (0,0)              잴 자리가 없다    참
(0,3)    (0,0) (0,3)        잴 자리가 없다    참
(3,0)    (0,0) (3,0)        잴 자리가 없다    참
(3,2)    (0,0) (3,0) (3,2)  1                 참
(3,4)    (0,0) (3,0) (3,4)  1                 참
(6,0)    (0,0) (6,0)        잴 자리가 없다    참
(6,3)    (0,0) (6,0) (6,3)  1                 참

└ 일곱 걸음 모두 참이다. 판정값이 1 이 아닌 자리는 담기 전에 걷어냈다
```

**일곱 걸음 모두 참입니다.** 판정값이 1 이 아닌 자리는 담기 전에 걷어냈으므로 사슬 안에는 왼쪽
꺾임만 남아요. 위 사슬도 같은 함수가 순서만 바꿔 쌓으므로 같은 표가 그대로 성립합니다.

```text
불변식이 잠깐 어긋나는 자리와 다시 참이 되는 자리
  걷어내기 도중   사슬 끝과 새 점이 오른쪽 꺾임이다   아직 담지 않았다
  담은 직후       남은 셋이 전부 왼쪽 꺾임이다        여기서 다시 참이다
└ 문장이 「담은 직후」 를 못 박은 이유가 그것이다
```

경계에 있는 입력도 확인하고 갑시다. 점이 없거나 하나뿐이거나 전부 같은 좌표이면 사슬을 쌓기
전에 답이 정해지고, 전부 한 직선 위이면 사슬이 두 점으로 줄어들어요.

<!--proof:invariant-edges-->

```text
입력                      점  서로 다른 점  답
점이 없다                  0             0  없음
점이 하나                  1             1  (3,7)
점이 둘                    2             2  (0,0) (5,5)
같은 좌표 셋               3             1  (2,2)
한 직선 위의 넷            4             4  (0,0) (3,0)
변 위에 점이 있는 사각형   5             5  (0,0) (4,0) (4,4) (0,4)
좌표 상한의 네 모서리      5             5  (-1000000000,-1000000000) (1000000000,-1000000000) (1000000000,1000000000) (-1000000000,1000000000)

└ 서로 다른 점이 둘 이하면 사슬을 쌓지 않고 그대로 돌려준다
```

**이제 깨뜨려 봅시다.** 앞 절반을 지키던 줄은 걷어내기 조건의 등호입니다. 「한 직선 위인 점은
껍질의 경계 위에 있으니 남겨도 되겠다」라는 생각으로 그 줄을 바꿔 봅니다.

```ts
while (chain.length >= 2 && turnAtEnd(chain, p) < 0) chain.pop();  // <= 가 아니라 <
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-keep-collinear-->

```text
입력                      정본이 낸 답                   판정값이 0 인 점을 남긴 답           대조
전개 입력                 (0,0) (6,0) (6,3) (3,4) (0,3)  (0,0) (3,0) (6,0) (6,3) (3,4) (0,3)  어긋난다

한 직선 위의 넷           (0,0) (3,0)                    (0,0) (1,0) (2,0) (3,0) (2,0) (1,0)  어긋난다
```

앞 절반이 깨지면 「사슬 안이 볼록하다」가 더는 참이 아닙니다. 셋째 줄이 그것을 가장 크게 보여
줘요 — 전부 한 직선 위인 넷에서 사슬이 하나도 줄지 않아 같은 점이 두 번씩 담깁니다.

```text
한 직선 위의 넷에서 무슨 일이 벌어지는가
  옳은 판   아래 사슬 (0,0) (3,0)              가운데 둘은 판정값이 0 이라 걷어낸다
  바뀐 판   아래 사슬 (0,0) (1,0) (2,0) (3,0)  판정값이 0 이면 안 걷어낸다
  그 뒤     위 사슬도 같은 넷을 거꾸로 담는다
            끝점을 하나씩 떼고 이으면 점 6 개가 된다
            └ 답이 「양 끝점 둘」 이어야 하는데 여섯이 나온다
```

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 세 무리입니다 — 좌표를 견주는 정렬, 앞 점과 견주는 중복 제거, 그리고
사슬을 쌓는 방향 판정이에요. 전개의 걸음으로 가르면 이렇게 나뉩니다.

<!--proof:perf-count-->

```text
무엇                          어느 걸음인가  기본 연산
좌표로 정렬한다               T1                    16
앞 점과 견주어 중복을 지운다  T1                     8
아래 사슬의 방향 판정         T2~T8                  7
위 사슬의 방향 판정           T9~T15                 7
끝점을 떼고 잇는다            T16                    0
합계                                                38

점 8 개 · 서로 다른 점 7 개 · 꼭짓점 5 개
총식 n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1 + n + (4m − h − 6) 의 각 항이 17 · 8 · 17 이다
└ 정렬 비교는 최악값이라 실측보다 크고, 방향 판정은 상한과 실측이 갈린다
```

정렬 비교 16 번은 T1 에서 나고, 방향 판정 14 번은 T2 부터 T15 까지 흩어져 있어요. T16 은 배열
끝의 값을 하나씩 떼고 잇기만 해서 견주는 일이 없습니다.

```text
총식 = 정렬 비교                        + 중복 제거  + 방향 판정
       └ n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1     └ n          └ 4m − h − 6 이하

       점 8 개면 17 + 8 + 17 = 42 이하이고 실측은 38 이다
       점 100,000 개면 1,568,929 + 100,000 + 399,991 = 2,068,920 이하다
```

**여기서 센 것은 견주기와 방향 판정입니다.** 배열에 담고 걷어내는 일과 자리 번호를 올리는 일은
안 셌어요 — 둘 다 위의 계수에 비례하므로 총식의 차수가 안 바뀝니다.

```text
안 센 것과 그 이유
  담기와 걷어내기   담기는 점마다 사슬당 한 번이고 걷어내기는 그보다 적다
  자리 번호 올리기  반복문마다 한 번이라 방향 판정에 비례한다
  배열 사본 만들기  정렬 사본과 뒤집은 사본 각각 n 번, m 번이다
                    └ 정렬이 n log n 이라 나머지 항은 차수를 안 바꾼다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안
돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** | `O(n log n)` | `Θ(n log n)` — 정렬을 건너뛸 수 없다 |
| **평균적인 경우** (입력 분포를 가정하지 않는다) | `O(n log n)` | `Θ(n log n)` |
| **최악의 경우** | `O(n log n)` | `Θ(n log n)` — 실제로 도달한다 |

세 줄이 다 같은 것은 정렬 때문입니다. 방향 판정은 입력에 따라 `2m` 에서 `4m` 사이로 갈리지만
그 항이 `n log n` 에 눌려요. 꼭짓점이 셋뿐인 입력에서도 정렬은 그대로 듭니다.

```text
상한과 경계를 가르는 자리
  O(n log n)   이 절차의 기본 연산이 그보다 크지 않다는 것만 말한다      상한이다
  Θ(n log n)   위아래로 같은 차수라 실제로 그만큼 든다는 것도 말한다     타이트한 값이다
               └ 견주기로 정렬하는 이상 아래로도 n log n 이 든다

  꼭짓점 수 h 는 차수에 안 들어간다 — 이 절차는 출력 크기에 민감하지 않다
```

**총식을 한 번은 정확히 적습니다.** 앞에 붙는 것은 정렬 하나뿐이고 뒤에 붙는 것은 없어요 —
좌표 압축도, 해시도, 답을 담는 배열 말고 다른 자료구조도 안 씁니다.

```text
총식 = Θ(n log n) 시간 + Θ(n) 추가 메모리
       │                  └ 정렬 사본 n · 중복을 지운 목록 m · 뒤집은 사본 m · 사슬 둘
       └ 기본 연산이 n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1 + n + (4m − h − 6) 이하

점 100,000 개면 기본 연산 2,068,920 번 이하, 잡는 칸은 n + 2m + h 라 최대 400,000 개다
```

**보장의 종류는 전부 최악 보장입니다.** 해시도, 무작위성도, 입력 분포 가정도 쓰지 않아요 —
같은 입력이면 언제나 같은 계수가 나오고, 판정의 부호가 큰 정수로 확정되므로 반올림에 따라
답이 갈리는 일도 없습니다.

```text
기댓값이 끼어들 자리가 없다
  정렬          견주기 정렬의 최악이 n log n 이다         분포를 가정하지 않는다
  방향 판정     걷어내기와 유지의 합이 4m − h − 6 이하다  입력만으로 정해진다
  부호 확정     큰 정수로 되재므로 오차가 답을 안 바꾼다  실행마다 같은 답이다
                └ 최악과 평균이 차수만 같은 것이 아니라 계수도 입력만으로 정해진다
```

#### 최악을 만드는 입력

방향 판정을 가장 많이 쓰는 입력이 무엇인지 재 봤습니다. 「퇴화한 입력이 최악이다」 같은 통념이
붙기 쉬운 자리라, 모양을 바꿔 가며 실제로 셌어요.

```text
모양                        서로 다른 점 m  꼭짓점 h  방향 판정  4m − h − 6   비율  잡는 칸

└ 방향 판정은 h 가 작을수록 늘고 잡는 칸은 h 가 클수록 는다. 두 축의 최악이 서로 다른 입력이다
```

**「한 직선 위이면 최악이다」는 이 절차에서 거짓입니다.** 그 입력은 유지로 끝나는 판정이 하나도
없어 상한의 절반에 그쳐요. 상한과 정확히 같아지는 것은 **서로 다른 점이 많고 껍질이 작은** 입력이고,
흩어진 점 100,000 개가 그 모양입니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 점을 좌표로 한 번 정렬해 두면 껍질이 **왼쪽으로만
꺾이는 사슬 둘**로 갈리고, 각 사슬은 새 점을 담기 전에 성질을 깨는 끝점을 걷어내므로 전체 비용을
정렬이 결정합니다.

```text
정렬한다 → 아래 사슬을 쌓는다 → 위 사슬을 쌓는다 → 끝점을 떼고 잇는다
└ n log n   └ 판정 2m − |사슬| − 2 이하   └ 같은 규칙   └ 꼭짓점 h 개
```

먼저 답이 붙는 문제 하나입니다. 전개의 T7 은 점 `(6,0)` 을 담으면서 두 점을 걷어냈어요. 그중
하나는 판정값이 음수라서, 다른 하나는 판정값이 0 이라서 걷어냈습니다. 판정값이 0 인 점을 굳이 걷어내는
이유는 무엇일까요?

```text
T7 이 걷어낸 점   (3,4) 는 판정값이 음수 · (3,0) 은 판정값이 0
그 뒤의 사슬      (0,0) (6,0)
```

<!--check:whyDropCollinear-->
문제가 **꼭짓점만** 요구하기 때문입니다. 판정값이 0 이라는 것은 세 점이 한 직선 위라는 뜻이고,
그때 가운데 점은 껍질의 경계 위에 있지만 각이 꺾이는 자리가 아니에요. `(0,0)` 과 `(6,0)` 을 이은
변 위에 `(3,0)` 이 있는 것이라, 남기면 답에 꼭짓점이 아닌 점이 하나 더 들어갑니다.

```text
판정값이 0 인 점을 남기면
  전개 입력             꼭짓점 5 개가 6 개가 된다   (3,0) 이 더 들어간다
  한 직선 위의 점 넷    꼭짓점 2 개가 6 개가 된다   같은 점이 두 번씩 담긴다
└ 「불변식」 절의 마지막 표가 그 두 답을 나란히 보인다
```

경계가 갈리는 자리도 함께 봅시다. 문제가 공선 중간 점까지 요구했다면 이 등호를 `<` 로 두는 것이
맞는 선택이고, 그때는 한 직선 위인 입력에서 같은 점이 두 번 담기지 않도록 사슬을 잇는 규칙을
따로 손봐야 합니다.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 「수식 정의와 유도」의 첫 유도    3 → 「경쟁 설계와의 대조」
  2 → 「수식 정의와 유도」의 둘째 유도
```

- T4 는 판정을 한 번 하고 한 점을 걷어냈고, T7 은 판정을 두 번 하고 두 점을 걷어냈습니다.
  걷어낸 점의 총수가 담은 점의 총수를 넘을 수 없다는 사실만으로 방향 판정의 총수를 점 개수의
  상수 배로 누를 수 있어요. 그 논증을 사슬 하나에 대해 직접 적고, 두 사슬을 더했을 때 왜
  `h + 2` 가 빠지는지도 함께 적어 보세요.
- 좌표 상한이 `10^9` 이 아니라 `10^6` 인 문제가 주어졌다고 합시다. `sideOf` 에서 큰 정수로
  되재는 자리를 지워도 되는지, 지워도 된다면 그 근거가 되는 값이 얼마인지 계산해 보세요.
  좌표 상한을 얼마까지 올릴 수 있는지도 함께 구해 보면 경계가 보입니다.
- 선물 포장은 꼭짓점 수 `h` 에 정비례해 늘었습니다. 점 개수를 4,096 으로 고정하고 `h` 를
  3 부터 350 까지 바꿔 가며 두 설계의 기본 연산을 식으로 세운 다음, 순서가 뒤집히는 `h` 를
  식으로 풀어 보세요. 실측값 14 와 맞는지 견주면 식이 맞는지 알 수 있습니다.
