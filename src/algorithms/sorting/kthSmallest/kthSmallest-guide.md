# 퀵셀렉트 — 기준값 하나의 자리가 정해지면 목표가 없는 쪽은 다시 볼 이유가 없다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 가장 작은 값을
`k` 번 빼내는 방법에서 출발해 기준값으로 가른 뒤 한쪽만 남기는 방법까지 가고, 그 방법을 단계마다 값으로 푼
뒤, 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

배열에서 `k` 번째로 작은 값 하나를 고르고 싶을 때, 줄 전체를 정렬할 필요는 없습니다. 값 하나를
**기준값**으로 고르고, 그보다 작은 값을 전부 왼쪽으로 모은 다음 기준값을 그 경계에 놓으면 됩니다. 이 일을
**분할**이라고 부릅니다. 분할이 끝나면 기준값 왼쪽의 칸 수가 곧 **그 값이 정렬된 줄에서 앉을 자리
번호**예요. 배열 `[7 10 4 3 20 15]` 을 기준값 4 로 한 번 가르면 이렇게 됩니다.

<!--proof:concept-first-split-->

| 구역 | 값 | 칸 수 |
| --- | --- | ---: |
| 4 보다 작은 값 | [3] | 1 |
| 기준값 | 4 | 1 |
| 4 이상인 값 | [15 7 20 10] | 4 |

가른 뒤 배열은 [3 4 15 7 20 10] 이고, 기준값 4 가 놓인 인덱스 1 은 정렬한 줄 [3 4 7 10 15 20] 에서 4 가 앉는 자리와 같습니다.

<!--/proof-->

작은 값이 한 개라 4 의 자리는 인덱스 1 로 정해졌습니다. 오른쪽 네 칸은 「4 이상이다」만 정해졌고 그
안의 순서는 아직 모릅니다. `k` 는 1 부터 세므로 0 부터 세는 목표 자리는 `k − 1` 번이고, 방금 정해진 자리
`p` 와 목표 자리를 비교하면 다음에 볼 곳이 세 갈래로 정해져요.

| 비교 결과 | 뜻 | 다음에 할 일 |
| --- | --- | --- |
| `p = k − 1` | 기준값이 곧 답이다 | 기준값을 돌려준다 |
| `p > k − 1` | 답은 기준값보다 작은 쪽에 있다 | 오른쪽 덩어리를 버리고 왼쪽만 가른다 |
| `p < k − 1` | 답은 기준값보다 큰 쪽에 있다 | 왼쪽 덩어리를 버리고 오른쪽만 가른다 |

버린 쪽은 다시 보지 않습니다. 같은 배열에서 `k = 4` 를 찾으면 분할이 네 번 일어나고, 바퀴마다 남는
구간이 이렇게 줄어요. 굵은 칸이 그 바퀴에 자리가 정해진 기준값이고, 괄호가 다음 바퀴가 받는 구간입니다.

<!--fig:concept-rounds-->
![kthSmallest([7 10 4 3 20 15], 4) — 바퀴마다 자리 하나가 정해지고 목표가 든 쪽만 남는다](./figs/concept-rounds.svg)

분할하고 한쪽만 남기는 일을 되풀이해 `k` 번째 값을 고르는 이 절차를 **퀵셀렉트**(quickselect)라고
부릅니다. 퀵 정렬과 분할은 같지만 갈라진 두 덩어리 중 **목표가 든 한쪽만** 이어서 가른다는 점이 달라요.
그래서 구간이 매번 절반으로 준다면 비교 횟수가 `n + n/2 + n/4 + …` 이 되어 `2n` 아래에서 멈춥니다.
다만 절반씩 준다는 보장은 없습니다. 고른 기준값이 구간의 최솟값이면 구간이 한 칸만 줄어요. 칸 100,000
개에서 두 극단과 실제 실행을 세면 이렇습니다.

<!--proof:concept-sum-->

| 갈림 | 칸 100,000 개의 비교 |
| --- | ---: |
| 가장 고른 갈림 — 목표가 든 쪽이 매번 절반 | 199,977 |
| 뒤섞인 입력에서 순번 50,000 을 실제로 실행 | 385,510 |
| 한쪽이 비는 갈림 — 구간이 매번 한 칸만 준다 | 4,999,950,000 |

가운데 줄은 생성식 `A[i] = (i × 7919) mod 100,003` 으로 만든 배열에 정본을 실제로 실행해 센 값이고, 첫 줄과 끝 줄은 갈림 모양을 비용 식에 넣어 센 값입니다.

<!--/proof-->

비용을 결과만 적으면 평균 `O(n)`, 최악 `O(n²)` 이에요. 어느 쪽이 되는지는 **기준값을 어디서 고르느냐**가
정합니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **정렬된 줄에서 「`k` 번째」가 무엇인지.** 오름차순으로 세웠을 때 앞에서 `k` 칸째이고, 같은 값이
  여럿이면 그 값들이 개수만큼 연속된 칸을 차지합니다. `k = 1` 이 최솟값이에요.
- **배열의 자리 바꾸기가 `O(1)`** 이라는 것. `A[i]` 와 `A[j]` 를 맞바꾸는 데 배열 길이는 상관없습니다.
- **분할(partition)이 무엇인지.** 기준값 하나로 배열을 「작은 쪽 · 기준값 · 크거나 같은 쪽」으로 재배열하는
  한 번의 순회예요. 흐릿하면 [퀵 정렬 가이드](../quicksort/quicksort-guide.md)의 「수행으로 알아보는
  알고리즘」 절이 같은 순회를 단계마다 값으로 보여 줍니다.
- **구간을 좁혀 가는 반복문의 꼴.** `lo` 와 `hi` 두 변수로 남은 범위를 들고, 한 바퀴마다 한쪽 끝을 옮기는
  모양입니다. [이진 탐색 가이드](../../binary-search/binarySearch/binarySearch-guide.md)가 같은 뼈대를
  씁니다.

세 번째가 흐릿하면 여기서부터 어긋납니다. 분할을 「정렬을 조금 한 것」으로 잡고 있으면, 한 번의 순회가
**값 하나의 자리를 완전히 확정한다**는 것이 무엇을 보장하는지 확인할 수 없어요. 이 글이 다루는 범위도 먼저
정해 둡니다.

| 하려는 일 | 맞는 절차 |
| --- | --- |
| 한 번 주어진 배열에서 `k` 번째 값을 한 번 고른다 | 퀵셀렉트 (이 글) |
| 수가 하나씩 들어오는 동안 중앙값을 계속 답한다 | [`medianFromDataStream`](../medianFromDataStream/medianFromDataStream-guide.md) |
| 등장 횟수 상위 `k` 개를 모두 낸다 | [`topKFrequent`](../topKFrequent/topKFrequent-guide.md) |
| 줄 전체의 순서가 필요하다 | [`quicksort`](../quicksort/quicksort-guide.md) · [`sortArray`](../sortArray/sortArray-guide.md) |

### 아이디어를 떠올리는 과정 — k 번 최솟값 찾기에서 한쪽만 남기는 분할까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정수 배열과 순번을 받아,
오름차순으로 세웠을 때 그 순번에 오는 값을 돌려줍니다.

```ts
function kthSmallest(A: number[], k: number): number;
```

- 입력: 정수 배열 `A` 와 순번 `k`. `A` 를 **제자리에서 고쳐도 됩니다** — 호출이 끝난 뒤 원소 순서는
  보장하지 않습니다.
- 출력: `A` 를 오름차순으로 세웠을 때 앞에서 `k` 번째에 오는 **값 하나**. 인덱스가 아닙니다.
- 규모: 칸 수 `n` 은 1 이상 100,000 이하, 값은 `−10⁹` 이상 `10⁹` 이하의 정수, 순번은 `1 ≤ k ≤ n` 입니다.
  값은 음수일 수 있고 같은 값이 여럿일 수 있어요. 비용은 흔한 채점 환경의 예산인 1 초에 대어 잽니다.
  칸 수 상한을 10 만으로 둔 것은 이 규모에서 정렬은 1 초 안에 들고 `k` 번 되풀이하는 방법은 넘어서, 두
  방법이 갈리는 자리가 보이기 때문입니다.

비용은 **값을 비교한 횟수**로 셉니다. 퀵셀렉트는 맞바꾸기만 하고 새 배열을 잡지 않으므로, 메모리는 새로
잡는 칸 수로 따로 셉니다. 이 글이 쓰는 기호는 열 개예요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `n` | 배열 `A` 의 칸 수 | `1 ≤ n ≤ 100,000` |
| `A` | 입력 배열. 분할하며 제자리에서 재배열된다 | `−10⁹ ≤ A[i] ≤ 10⁹` |
| `k` | 1 부터 세는 순번 | `1 ≤ k ≤ n` |
| `target` | `k − 1`. 0 부터 세는 **목표 자리** | `0 ≤ target ≤ n−1` |
| `lo` · `hi` | 아직 남아 있는 구간의 왼쪽 끝 · 오른쪽 끝. 양 끝을 포함합니다 | `0 ≤ lo ≤ hi < n` |
| `m` | 구간의 중앙 인덱스. 기준값을 여기서 고른다 | `m = lo + ⌊(hi − lo)/2⌋` |
| `pivot` | 지금 구간에서 고른 **기준값**. 산문에서는 「기준값」, 코드에서는 `pivot` 입니다 | 바퀴마다 새로 고른다 |
| `i` | 기준값보다 작은 값이 놓일 다음 자리 | `lo ≤ i ≤ hi` |
| `j` | 분할 루프가 지금 읽는 자리 | `lo` 부터 `hi−1` 까지 |
| `p` | 분할이 끝난 뒤 기준값이 자리 잡은 인덱스 | `lo ≤ p ≤ hi` |

가장 먼저 떠오르는 방법은 **`k` 번 최솟값 찾기**입니다. 남은 값 중 가장 작은 것을 찾아 앞으로 빼내는 일을
`k` 번 되풀이하면 `k` 번째에 뺀 값이 답이에요. 기법이 하나도 안 들어가고 어떤 배열에서든 통합니다.

```ts
function kthSmallestNaive(A: number[], k: number): number {
  const B = A.slice();
  for (let r = 0; r < k; r++) {
    let min = r;
    for (let t = r + 1; t < B.length; t++) {
      if ((B[t] as number) < (B[min] as number)) min = t;
    }
    [B[r], B[min]] = [B[min] as number, B[r] as number];
  }
  return B[k - 1] as number;
}
```

이 방법은 답을 틀리지 않습니다. 바퀴마다 남은 칸을 전부 비교하므로 비교가 이렇게 쌓여요.

<!--proof:origin-naive-->

| 칸 수 n | 순번 k | 비교 | 시간(초당 1 억 번) |
| ---: | ---: | ---: | ---: |
| 1,000 | 500 | 374,750 | 0.00 초 |
| 100,000 | 1 | 99,999 | 0.00 초 |
| 100,000 | 50,000 | 3,749,975,000 | 37.50 초 |

바퀴마다 남은 칸을 전부 비교하므로 비교 횟수는 k(2n − k − 1)/2 이고, 칸 1 개부터 40 개까지 모든 순번에서 실제로 세어 이 식과 대조했습니다.

<!--/proof-->

`k` 가 작으면 금방 끝나지만, 가운데 순번에서는 37.5 초로 예산 1 초를 훌쩍 넘습니다. 순번은 입력으로 들어오니
가운데가 들어오는 것을 막을 수 없어요. 그러면 정렬을 쓰면 어떨까요. `A` 를 정렬하고 `A[k-1]` 을 읽으면
됩니다. 비교 정렬이 줄 전체의 순서를 알아내려면 적어도 `log₂(n!)` 번은 비교해야 하고, 자리 하나를 정하려면
모든 칸을 적어도 한 번은 읽어야 하므로 `n − 1` 번이 하한이에요.

<!--proof:lower-bounds-->

| 칸 100,000 개에서 알아내는 것 | 비교의 하한 |
| --- | ---: |
| 줄 전체의 순서 — log₂(n!) | 1,516,704 |
| 자리 하나 — n − 1 | 99,999 |

줄 전체의 순서를 알아내는 쪽이 15.2 배 많습니다.

<!--/proof-->

정렬은 1 초 안에 들어오니 **틀린 방법이 아니라 낭비하는 방법**입니다. 묻는 것은 자리 하나인데 줄 전체의
순서를 알아내느라 하한부터 15.2 배를 씁니다. 그러면 자리 하나만 정하는 순회가 따로 있는지부터 봐야 해요.
작은 입력 `[7 10 4 3 20 15]` 에서 값 하나를 고른 뒤 **그보다 작은 값이 몇 개인지만** 세어 봅니다.

<!--proof:origin-rank-->

| 고른 값 | 그보다 작은 값 | 개수 | 정렬한 줄에서의 인덱스 |
| --- | --- | ---: | ---: |
| 7 | [3 4] | 2 | 2 |
| 4 | [3] | 1 | 1 |
| 15 | [3 4 7 10] | 4 | 4 |

정렬한 줄은 [3 4 7 10 15 20] 이고, 세 값 모두 작은 값의 개수가 정렬한 줄의 인덱스와 같습니다.

<!--/proof-->

값 하나의 자리는 「그보다 작은 값의 개수」와 같고, 그 개수는 배열을 한 번 읽으면 나옵니다. 읽으면서 작은
값을 앞쪽으로 맞바꿔 두면 개수를 세는 김에 **두 덩어리로 갈라 놓는 일까지** 끝나요. 이것이 분할입니다. 이제
비용은 「몇 번 분할하고, 그때마다 구간이 몇 칸이었는가」로 정해지고, 한 번 분할하는 비교는 구간의 칸 수보다
하나 적습니다.

```text
비교 횟수 = Σ (그 분할이 받은 구간의 칸 수 − 1)
             └ 이 식에 배열의 값이 없다. 남은 변수는 "구간이 어떻게 줄어드는가" 하나다
```

무엇이 구간을 줄이는지 두 방식으로 재 봅시다. 같은 분할 규칙으로 갈라진 두 덩어리를 **둘 다** 이어서 가를
때와, 목표가 든 **한쪽만** 이어서 가를 때입니다. 앞쪽은 퀵 정렬이고, 기준값을 고르는 줄까지 코드가 같아요.

<!--proof:split-vs-sort-->

| 칸 수 n | 양쪽을 다 가르는 퀵 정렬 | 목표가 든 쪽만 가르는 퀵셀렉트 | 차이 |
| --- | ---: | ---: | ---: |
| 6 (전개 입력, k = 4) | 11 | 11 | 1.0 배 |
| 16 | 45 | 23 | 2.0 배 |
| 64 | 347 | 126 | 2.8 배 |
| 256 | 2,015 | 449 | 4.5 배 |
| 1,024 | 11,091 | 2,979 | 3.7 배 |

첫 줄 말고는 생성식 `A[i] = (i × 7919) mod 10,007` 로 만든 배열에 순번 k = n/2 를 물었습니다.

<!--/proof-->

칸이 늘수록 차이가 벌어집니다. 갈리는 것은 분할 규칙이 아니라 **목표가 없는 쪽을 보는가** 하나예요. 전개에
쓸 여섯 칸짜리 입력에서는 차이가 없는데, 그 입력은 네 번 갈라지는 동안 버린 쪽이 매번 한 칸 이하라 양쪽을 다
가르더라도 더 할 비교가 없기 때문입니다. 여기서 관찰한 것은 하나예요. **버리는 쪽이 클수록 비용이 줄어듭니다.**

그러면 가장 단순한 방법으로 버려 보겠습니다. 값은 보지 않고 **구간을 칸 수로 반 잘라 목표 자리가 든 쪽만
보는** 것입니다. 읽을 것도 없어서 비용이 가장 작아 보여요.

<!--fig:origin-half-cut-->
![칸 수로 반 자르면 답 10 이 든 칸을 버린다](./figs/origin-half-cut.svg)

`k = 4` 의 답 10 은 인덱스 1 에 있는데, 목표 자리 3 이 오른쪽에 드니 오른쪽만 남기면 답을 버립니다. **자리
번호로 자르려면 배열이 이미 정렬돼 있어야 합니다.** 정렬돼 있지 않으면 자리 3 에 `k = 4` 번째 값이 있다는
보장이 없어요. 그래서 자르기 **전에** 자리 하나를 실제로 확정해야 하고, 방금 본 분할이 바로 그 일을 합니다.
지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **한쪽만 남기는 분할**이고, 이 절차를 퀵셀렉트라고 부릅니다. 기준값으로 구간을
갈라 그 자리를 확정하고, 목표 자리가 든 쪽만 남겨 다시 가르는 일을 목표 자리가 확정될 때까지 되풀이해요.
목표 자리를 어떻게 적는지, 분할을 어떻게 하는지, 어느 쪽을 남기는지는 다음 절에서 실현하는 순서대로
확인합니다.

### 아이디어 상세 — 한쪽만 남기는 분할

이 아이디어를 한 문장으로 줄이면 이렇습니다. **구간을 기준값으로 갈라 기준값의 자리를 확정하고, 그 자리와
목표 자리를 비교해 목표가 든 쪽만 남기는 일을 두 자리가 같아질 때까지 되풀이합니다.** 미리 만들어 두는 구조는
없고, 쥐고 있는 것은 구간 `[lo, hi]` 와 목표 자리 `target` 둘뿐이에요. 실현하는 순서대로 세 단계로 나누면
이렇습니다.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 목표 자리 정하기 | 순번 `k` 를 0 부터 세는 자리 `target` 으로 한 번만 옮긴다 | — |
| 2단계 기준값으로 구간 가르기 | 구간을 작은 쪽 · 기준값 · 크거나 같은 쪽으로 재배열해 기준값의 자리 `p` 를 확정한다 | 지금 구간 `[lo, hi]` |
| 3단계 목표가 든 쪽만 남기기 | `p` 와 `target` 을 비교해 답을 내거나 구간을 한쪽으로 줄인다 | 2단계의 `p` · 1단계의 `target` |

1단계는 호출마다 한 번이고, 2단계와 3단계가 반복 한 바퀴입니다.

#### 1단계 — 목표 자리 정하기

`k` 는 1 부터 세고 배열 인덱스는 0 부터 셉니다. 그래서 목표 자리를 `target = k − 1` 로 **맨 앞에서 한 번만**
옮겨 둡니다. 이 번호는 배열 전체를 기준으로 한 절대 번호이고, 정렬한 줄에서 답이 앉을 자리예요.

<!--proof:build-target-->

| 자리 번호 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 정렬한 줄의 값 | 3 | 4 | 7 | 10 | 15 | 20 |

k = 4 이면 target = 3 이고, 그 자리의 값 10 이 정본의 답 10 과 같습니다.

<!--/proof-->

`target` 은 호출이 끝날 때까지 바뀌지 않습니다. 구간이 줄어도 번호의 기준인 배열 전체는 그대로이기
때문이에요. 이것이 왜 괜찮은지는 3단계에서 버리는 쪽을 볼 때 값으로 확인합니다.

#### 2단계 — 기준값으로 구간 가르기

구간 `[lo, hi]` 의 중앙 `m = lo + ⌊(hi − lo)/2⌋` 의 값을 기준값으로 고르고, 먼저 `hi` 자리와 맞바꿔 끝으로
옮깁니다. 그러면 나머지 칸 `lo … hi−1` 만 한 방향으로 읽으면 돼요. 읽는 동안 구간은 세 구역으로 나뉩니다.

```text
lo            i            j           hi
|- 작은 쪽 ---|- 크거나 같은 쪽 -|- 아직 안 읽음 -|기준값|
   A[x] < pivot   A[x] ≥ pivot
```

`j` 가 읽은 값이 기준값보다 작으면 `A[i]` 와 맞바꾸고 `i` 를 한 칸 늘려 작은 쪽을 넓힙니다. 작지 않으면 그대로
두고 `j` 만 나아가요. 가장 불안한 경우는 작은 값을 만났을 때입니다. 맞바꾸는 순간 크거나 같은 쪽의 맨 앞 값이
`j` 자리로 옮겨 가는데, 그 값이 구역을 벗어나지 않는지 첫 바퀴의 상태를 전부 적어 확인해 봅시다.

<!--proof:build-zones-->

| 읽는 자리 | A[j] | A[j] < 4 | 작은 쪽 | 크거나 같은 쪽 | 배열 |
| --- | --- | --- | --- | --- | --- |
| j = 0 | 7 | 거짓 | 비었다 | [7] | [7 10 15 3 20 4] |
| j = 1 | 10 | 거짓 | 비었다 | [7 10] | [7 10 15 3 20 4] |
| j = 2 | 15 | 거짓 | 비었다 | [7 10 15] | [7 10 15 3 20 4] |
| j = 3 | 3 | 참 | [3] | [10 15 7] | [3 10 15 7 20 4] |
| j = 4 | 20 | 거짓 | [3] | [10 15 7 20] | [3 10 15 7 20 4] |

기준값 4 를 끝으로 옮긴 [7 10 15 3 20 4] 에서 시작했고, 루프가 끝났을 때 작은 쪽이 1 칸이라 기준값을 인덱스 1 에 놓아 [3 4 15 7 20 10] 이 됩니다.

<!--/proof-->

`j = 3` 에서 3 이 작은 쪽으로 들어가고, 크거나 같은 쪽의 맨 앞이던 7 이 인덱스 3 으로 옮겨 갔어요. 7 은
여전히 크거나 같은 쪽 안에 있습니다. 맞바꾸기가 작은 쪽의 끝과 크거나 같은 쪽의 끝을 한 칸씩 함께 밀기
때문에, 두 구역은 늘 이웃한 채로 남아요. 루프는 `j` 가 `hi − 1` 에 이를 때까지 모든 칸을 정확히 한 번씩 읽으므로
분류되지 않은 칸이 남지 않고, 끝났을 때 `i` 가 곧 작은 값의 개수만큼 `lo` 에서 떨어진 자리입니다. 그 자리에
기준값을 놓으면 한 번 가른 모양이 이렇게 됩니다.

<!--fig:build-partition-->
![기준값 4 로 한 번 가른 뒤 — 작은 쪽 · 기준값 · 크거나 같은 쪽](./figs/build-partition.svg)

기준값의 왼쪽에는 그보다 작은 값만, 오른쪽에는 크거나 같은 값만 있으니 기준값은 정렬한 줄에서도 이 자리에
앉습니다. 한 번 가르는 비교는 `hi − lo` 번이고, 칸이 여섯인 구간이면 다섯 번이에요.

#### 3단계 — 목표가 든 쪽만 남기기

확정된 자리 `p` 와 `target` 을 비교하면 갈래가 셋입니다.

| 비교 결과 | 하는 일 | 새 구간 |
| --- | --- | --- |
| `p = target` | 기준값이 곧 답이다 | `A[p]` 를 돌려주고 끝낸다 |
| `p > target` | 답은 기준값보다 앞자리다 | `[lo, p − 1]` |
| `p < target` | 답은 기준값보다 뒷자리다 | `[p + 1, hi]` |

기준값의 자리 `p` 도 답이 아니라고 확인됐으니 새 구간에 넣지 않습니다. 그래서 어느 갈래로 가든 구간이 적어도
한 칸 줄어요. 전개에 쓸 입력에서 바퀴마다 이 갈래를 적용하면 이렇게 됩니다.

<!--proof:build-rounds-->

| 바퀴 | 구간 | 칸 수 | 기준값 | p | 갈래 | 비교 |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| 1 | [0,5] | 6 | 4 | 1 | p < target → ⑤ [2,5] | 5 |
| 2 | [2,5] | 4 | 7 | 2 | p < target → ⑤ [3,5] | 3 |
| 3 | [3,5] | 3 | 20 | 5 | p > target → ④ [3,4] | 2 |
| 4 | [3,4] | 2 | 10 | 3 | p = target → ③ 반환 10 | 1 |

target = 3 이고, 비교는 모두 11 번이며 답은 10 입니다.

<!--/proof-->

구간이 6 → 4 → 3 → 2 칸으로 줄었고, 셋째 바퀴에서는 `p > target` 이라 오른쪽을 버렸어요. 쉬운 경우는 오른쪽을
버릴 때입니다. 남는 왼쪽 칸의 번호가 하나도 안 바뀌니 `target` 을 손댈 이유가 없어요. 불안한 경우는 **왼쪽을
버릴 때**입니다. 앞쪽 칸이 통째로 빠지는데 절대 번호를 그대로 써도 되는지, 첫 바퀴에서 확인해 봅시다.

<!--fig:build-discard-->
![왼쪽을 버려도 target 은 그대로 인덱스 3 을 가리킨다](./figs/build-discard.svg)

버린 인덱스 0 · 1 의 값 3 · 4 는 정렬한 줄의 자리 0 · 1 을 이미 차지한 값입니다. 번호는 배열 전체를 기준으로
매겨져 있어서, 앞쪽을 안 보기로 해도 뒤쪽 칸의 번호가 옮겨지지 않아요. 그래서 `target = 3` 은 남은 구간에서도
정렬한 줄의 자리 3 을 뜻합니다. 반복이 끝나는 자리는 둘뿐이에요.

| 끝나는 자리 | 조건 | 돌려주는 값 |
| --- | --- | --- |
| 목표 자리를 확정했다 | `p = target` | `A[p]` |
| 구간에 칸이 하나 남았다 | `lo = hi` | `A[lo]` |

구간은 매 바퀴 적어도 한 칸씩 주므로, 칸 `n` 개에서 시작하면 많아야 `n − 1` 바퀴 안에 둘 중 하나로 끝납니다.

#### 이 방법이 기대는 전제

한쪽만 남기는 분할은 아래 세 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 값 두 개의 크기를 늘 비교할 수 있다 | 2단계에서 작은 쪽과 크거나 같은 쪽을 가른다 | 어느 구역에도 못 넣는 값이 생겨 자리가 정해지지 않는다 |
| 아무 칸이나 인덱스로 바로 읽고 맞바꾼다 | 2단계의 맞바꾸기와 중앙 고르기 | 연결 리스트라면 중앙까지 가는 데만 구간 절반을 지난다 |
| 입력 배열을 고쳐도 된다 | 2단계가 제자리에서 재배열한다 | 사본을 떠야 하므로 새로 잡는 칸이 `n` 이 된다 |

세 번째 전제는 계약에 적혀 있습니다. 호출이 끝나면 배열의 순서가 바뀌어 있어요.

<!--proof:premise-mutate-->

```text
호출 전 A = [7 10 4 3 20 15]
kthSmallest(A, 4) → 10
호출 뒤 A = [3 4 7 10 15 20]
  └ 답은 맞고, 배열의 순서는 바뀌었다
```

반대로 값이 고르게 퍼졌는지는 전제가 아닙니다. 크기 비교만 쓰므로 값이 어떻게 놓였든 같은 규칙으로 가릅니다.
다만 값의 **배치**가 비용을 크게 바꾸는데, 그것이 다음 절의 주제예요.

#### 기준값을 구간의 중앙에서 고르는 까닭

2단계는 기준값을 구간의 중앙에서 골랐습니다. 첫 칸이나 끝 칸에서 골라도 답은 같고, 비교 횟수만 달라져요.
자리 셋을 입력 넷에 적용해 비교 횟수를 셌습니다. `k` 는 무엇이 들어올지 모르니 1 부터 8 까지 전부 더했어요.

<!--proof:pivot-places-->

| 입력 (칸 8 개) | 첫 칸 | 중앙 | 끝 칸 |
| --- | ---: | ---: | ---: |
| 정렬된 [0 1 2 3 4 5 6 7] | 168 | 76 | 168 |
| 역순 [7 6 5 4 3 2 1 0] | 168 | 82 | 168 |
| 뒤섞인 [5 2 8 1 9 3 7 4] | 82 | 138 | 84 |
| 전부 같음 [2 2 2 2 2 2 2 2] | 168 | 168 | 168 |

입력마다 순번 k = 1 부터 8 까지 여덟 번을 모두 물어 비교 횟수를 더했습니다.

<!--/proof-->

어느 자리도 네 입력 전부에서 가장 적지는 않습니다. 중앙은 정렬된 입력과 역순 입력에서 168 을 76 과 82 로
내리는데, 뒤섞인 입력에서는 138 로 첫 칸의 82 보다 많아요. 그래도 퀵셀렉트는 **중앙**을 고릅니다. 한 줄로
끝나고, 실무에서 흔히 들어오는 「이미 정렬된 배열」을 첫 칸과 끝 칸이 최악으로 만드는 것을 막기 때문이에요.
값이 전부 같은 입력은 셋 다 168 이라 자리 선택으로는 못 막습니다. 그 까닭은 「수행으로 알아보는 알고리즘」의
두 번째 짚고 가기에서 봅니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 2 · 3 · 4 가 반복 한 바퀴예요.

1. `target = k − 1`, 구간을 `[0, n−1]` 로 잡는다
2. `lo < hi` 인 동안 중앙 `m` 의 값을 기준값으로 골라 `hi` 자리로 옮긴다
3. `lo … hi−1` 을 한 번 읽어 작은 값을 왼쪽으로 모으고, 기준값을 경계 `p` 에 놓는다
4. `p = target` 이면 `A[p]` 를 돌려주고, `p > target` 이면 `hi = p − 1`, 아니면 `lo = p + 1` 로 줄인다
5. 구간에 칸이 하나 남으면 `A[lo]` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 여섯 칸을 네 번 갈라 네 번째 값을 고른다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const A = [7, 10, 4, 3, 20, 15];
const k = 4;
// 이 절이 끝나면 10 이 나와야 한다 (정렬하면 [3, 4, 7, 10, 15, 20] 의 4 번째)
```

여섯 칸에 `k = 4` 를 왜 골랐을까요? 이 입력은 네 번 갈라지고, 그 사이에 **3단계의 세 갈래가 전부
실행됩니다** — 오른쪽으로 두 번, 왼쪽으로 한 번, 그리고 마지막에 자리가 같아져요. 분할 루프의 두 갈래도 둘 다
나옵니다.

```text
kthSmallest(A, k):
    target ← k − 1
    lo ← 0,  hi ← A.length − 1
    lo < hi 인 동안:
        구간 [lo,hi] 의 중앙을 기준값으로 골라 hi 자리로 옮긴다
        i ← lo
        j 를 lo 부터 hi−1 까지:
            A[j] < 기준값 이면 A[i] 와 맞바꾸고 i 를 늘린다    ① 작다
            아니면 그대로 둔다                                  ② 크거나 같다
        기준값을 i 자리에 놓는다.  p ← i
        p = target 이면 A[p] 를 돌려준다                        ③ 자리가 같다
        p > target 이면 hi ← p − 1                              ④ 목표가 앞
        아니면        lo ← p + 1                                ⑤ 목표가 뒤
    A[lo] 를 돌려준다
```

#### 1. 순번을 자리 번호 하나로 옮긴다

`k` 는 1 부터 세고 배열 인덱스는 0 부터 셉니다. 이 변환을 **맨 앞에서 한 번만** 하고 뒤에서는 자리 번호끼리만
비교하게 두면, 비교하는 자리마다 `−1` 을 다시 챙길 이유가 없어요.

```ts
const target = k - 1;
```

실행하면 이렇게 나옵니다.

<!--proof:walk-target-->

```text
k = 4 이므로 target = k − 1 = 3
정렬한 줄 [3 4 7 10 15 20] 에서 인덱스 3 의 값은 10
```

#### 2. 기준값을 골라 끝으로 옮긴다

분할 루프는 「작은 쪽」과 「크거나 같은 쪽」 두 구역만 관리하면 됩니다. 기준값이 구간 한가운데 있으면 그
자리를 매번 비켜 가야 하므로, **먼저 끝으로 옮겨** 루프가 `hi` 앞까지만 보게 만들어요.

```ts
const m = lo + Math.floor((hi - lo) / 2);
[A[m], A[hi]] = [A[hi] as number, A[m] as number];
const pivot = A[hi] as number;
```

실행하면 T1 이 이렇게 나옵니다. 값 4 가 끝으로 갔고 원래 그 자리에 있던 15 가 안쪽으로 들어왔어요.

<!--proof:walk-pivot-->

```text
[7 10 4 3 20 15]  lo = 0, hi = 5  →  m = 0 + ⌊5/2⌋ = 2
인덱스 2 와 5 를 맞바꾼다
[7 10 15 3 20 4]  pivot = 4 가 hi = 5 에 있다
```

#### 3. 한 번 순회하며 두 구역을 넓힌다

`i` 는 「기준값보다 작은 값이 놓일 다음 자리」이고 `j` 는 읽는 자리입니다. `lo` 부터 `i − 1` 까지가 작은 쪽,
`i` 부터 `j − 1` 까지가 크거나 같은 쪽이에요.

```ts
let i = lo;
for (let j = lo; j < hi; j++) {
  if ((A[j] as number) < pivot) {
    // ① 작은 쪽으로 보내고 그 구역을 한 칸 넓힌다
    [A[i], A[j]] = [A[j] as number, A[i] as number];
    i++;
  }
  // ② 크거나 같다 — 그대로 둔다. j 만 나아간다
}
[A[i], A[hi]] = [A[hi] as number, A[i] as number];
```

T2 부터 T7 까지가 이 조각입니다. 다섯 번 비교하고 나면 `i` 가 1 이 되고, 마지막 맞바꾸기가 기준값 4 를 그
자리에 놓아요.

<!--proof:walk-partition-->

| 읽는 자리 | 비교 | 갈래 | 비교 뒤 배열 | i |
| --- | --- | --- | --- | --- |
| j = 0 | `7 < 4` 거짓 | ② | [7 10 15 3 20 4] | 0 그대로 |
| j = 1 | `10 < 4` 거짓 | ② | [7 10 15 3 20 4] | 0 그대로 |
| j = 2 | `15 < 4` 거짓 | ② | [7 10 15 3 20 4] | 0 그대로 |
| j = 3 | `3 < 4` 참 | ① | [3 10 15 7 20 4] | 0→1 |
| j = 4 | `20 < 4` 거짓 | ② | [3 10 15 7 20 4] | 1 그대로 |

[7 10 15 3 20 4] 에서 i = 0 로 시작했고, 루프가 끝난 뒤 A[1] 과 A[5] 를 맞바꿔 [3 4 15 7 20 10] 이 되며 p = 1 입니다.

<!--/proof-->

여기서 가장 중요한 줄은 `i++` 입니다. 이 줄이 작은 쪽의 오른쪽 끝을 한 칸 옮겨서, 다음에 만나는 작은 값이
앞서 넣은 값을 덮어쓰지 않게 해요. 그리고 루프가 끝났을 때 `i − lo` 가 곧 **작은 값의 개수**이므로, `i` 가
기준값의 최종 자리입니다.

#### 짚고 가기 — 오른쪽으로 갈 때 순번을 다시 세지 않는다

구간이 `[0,5]` 에서 `[2,5]` 로 줄었으니, 앞쪽 두 칸이 빠진 만큼 **목표 순번도 두 칸 당겨야 할 것 같지
않나요?** 부분 배열을 잘라 재귀로 넘기는 구현에서는 실제로 그렇게 합니다. 그 감각을 이 코드에 그대로 옮겨
보겠습니다. `target` 을 고칠 수 있게 `const` 를 `let` 으로 두고, 오른쪽으로 갈 때 버린 칸 수만큼 당깁니다.

```ts
// 오해 — 구간을 옮길 때마다 목표를 구간 안의 상대 번호로 다시 센다
else {
  target = target - (i + 1 - lo); // ← 왼쪽에서 버린 칸 수만큼 당긴다
  lo = i + 1;
}
```

전개 입력으로 실행하면 둘째 바퀴에서 갈라집니다.

<!--proof:pause-relative-->

| 바퀴 | 바른 코드 | 오해대로 한 코드 |
| --- | --- | --- |
| 1 | 구간 [0,5] · p = 1 < 3 → [2,5], target 3 | 구간 [0,5] · p = 1 < 3 → [2,5], target 3 − 2 = 1 |
| 2 | 구간 [2,5] · p = 2 < 3 → [3,5] | 구간 [2,5] · p = 2 > 1 → hi = 1 이 lo = 2 보다 작아 반복이 끝난다 |

바른 코드는 두 바퀴를 더 돌아 10 을 돌려주고, 오해대로 한 코드는 A[2] = 7 을 돌려줍니다.

<!--/proof-->

**두 셈법을 섞으면 안 된다는 것이 요점입니다.** 구간을 부분 배열로 잘라 넘기면 그 안에서 인덱스도 0 부터
다시 시작하니 당기는 것이 맞아요. 이 코드처럼 **원본 배열 위에서 `lo` · `hi` 만 옮기면** 인덱스가 원본
기준으로 남아 있으니 당기면 안 됩니다. 퀵셀렉트는 뒤쪽을 골랐고, 그래서 `target` 은 처음 한 번만 정해집니다.

#### 4. 확정된 자리와 목표 자리를 비교해 한쪽만 남긴다

분할이 끝나면 자리 하나가 확정됩니다. 그 자리와 `target` 의 대소가 다음에 볼 구간을 정해요. 세 갈래는 서로
겹치지 않고 `p` 가 가질 수 있는 값을 빠짐없이 덮습니다. 확정된 자리는 따로 변수에 담지 않고 분할 루프의 `i` 를 그대로 씁니다.

```ts
if (i === target) return A[i] as number; // ③ 확정된 자리가 곧 목표 자리다
if (i > target) hi = i - 1; //              ④ 목표가 더 앞이다 — 왼쪽만 남긴다
else lo = i + 1; //                         ⑤ 목표가 더 뒤다 — 오른쪽만 남긴다
```

T8 이 이 조각입니다. `p = 1` 이고 `target = 3` 이라 ⑤ 로 갈라지고, 구간이 여섯 칸에서 네 칸이 됩니다.

<!--proof:walk-branch-->

```text
[3 4 15 7 20 10]   p = 1,  target = 3  →  1 < 3 이라 ⑤
  버린다  인덱스 0~1   값 3 4
  남긴다  인덱스 2~5   값 15 7 20 10
          └ 다음 바퀴가 받는 구간은 4 칸이다
```

#### 5. 여섯 칸을 네 번 갈라 답 하나를 고른다

앞의 네 조각을 이어 `kthSmallest([7, 10, 4, 3, 20, 15], 4)` 를 끝까지 실행하면 걸음이 스물셋입니다. 무대의
괄호가 쥔 구간이고, 그 아래 「작음」 괄호(실선)가 작은 쪽, 「이상」 괄호(대시)가 크거나 같은 쪽이에요. 굵은 칸이
맞바꾸거나 자리가 정해진 칸, ▲ 가 비교했지만 그대로 둔 칸입니다.

자리입니다. 기준값 20 이 구간 `[3,5]` 의 최댓값이라 크거나 같은 쪽이 비었고, 확정된 자리가 `hi` 인 5 로
갔어요. 구간이 세 칸에서 두 칸으로 한 칸밖에 안 줄었고, 이 모양이 매 바퀴 되풀이되는 것이 퀵셀렉트의
최악입니다.

#### 짚고 가기 — 같은 값이 여럿이어도 답은 안 틀린다

`A[j] < pivot` 은 **작을 때만** 참이므로 기준값과 같은 값은 전부 크거나 같은 쪽으로 갑니다. 그러면 `p` 는
「기준값과 같은 값들 중 맨 앞자리」가 되는데, 이게 진짜 순위가 맞을까요? 같은 값이 여럿인 입력으로
확인해 봅시다.

<!--proof:pause-dup-->

```text
[2 1 2 1 3 1]  k = 4  → 정렬하면 [1 1 1 2 2 3] 이라 답은 2

  구간 [0,5]  중앙은 인덱스 2, 값 2 를 끝으로 → [2 1 1 1 3 2]
    2 · 1 · 1 · 1 · 3 중 2 보다 작은 값이 3 개 → p = 3
    가른 뒤 [1 1 1 2 3 2]  같은 값 2 가 오른쪽 구역에 1 개 남았다
  target = 3 이라 p = target → A[3] = 2 를 돌려준다
```

**답은 실제로 맞게 나옵니다.** 그래서 이 자리가 함정이에요 — 테스트가 통과하니 문제가 있는 줄 모르고
넘어갑니다. `p` 가 「기준값보다 **작은** 값의 개수」라는 뜻은 그대로이고, 같은 값이 여럿이면 그 값이 차지하는
자리가 여러 칸이라 그중 맨 앞자리에 놓아도 정렬한 줄과 어긋나지 않아요.

문제는 답이 아니라 **비용**입니다. 값이 전부 같으면 `A[j] < pivot` 이 한 번도 참이 아니라 `i` 가 `lo` 에
머무르고, 기준값이 구간 맨 앞으로 가서 나머지가 모두 한쪽에 남아요. `<` 를 `<=` 로 바꾸면 이번에는 같은 값이
전부 작은 쪽으로 가서 반대쪽 순번이 같은 일을 겪습니다.

<!--proof:pause-all-equal-->

| 묻는 순번 | `A[j] < pivot` | `A[j] <= pivot` |
| --- | ---: | ---: |
| k = 1 | 7 | 28 |
| k = 8 | 28 | 7 |

[2 2 2 2 2 2 2 2] 에서 센 비교 횟수이고, 네 경우 모두 답은 2 이며 비교가 가장 많을 때는 n(n−1)/2 = 28 번입니다.

<!--/proof-->

`<` 에서는 `k = 8` 이, `<=` 에서는 `k = 1` 이 한 칸씩만 줄어드는 최악이 됩니다. 두 갈래 분할로는 이 입력을
최악에서 빼낼 수 없고, 실제 해법은 구간을 셋(작음 · 같음 · 큼)으로 가르는 것이에요.

#### 6. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 **구간에 칸이 하나 남았을 때 그대로 돌려주는
마지막 줄**뿐이에요 — 칸이 하나면 그 칸이 곧 목표 자리입니다.

```ts
export function kthSmallest(A: number[], k: number): number {
  // 1부터 세는 순번 k 를 0부터 세는 자리 target 으로 한 번만 옮긴다.
  const target = k - 1;

  let lo = 0;
  let hi = A.length - 1;

  while (lo < hi) {
    // 중앙을 기준값으로 골라 끝으로 옮긴다. 그래야 분할 루프가 끝 한 칸만 비켜 두면 된다.
    const m = lo + Math.floor((hi - lo) / 2);
    [A[m], A[hi]] = [A[hi] as number, A[m] as number];
    const pivot = A[hi] as number;

    // i 는 "기준값보다 작은 값이 놓일 다음 자리". j 는 읽는 자리.
    let i = lo;
    for (let j = lo; j < hi; j++) {
      if ((A[j] as number) < pivot) {
        // ① 기준값보다 작다 — 작은 쪽 구역으로 보내고 그 구역을 한 칸 넓힌다.
        [A[i], A[j]] = [A[j] as number, A[i] as number];
        i++;
      }
      // ② 기준값보다 크거나 같다 — 그대로 둔다. j 만 나아간다.
    }

    // 기준값을 두 구역 사이(i)에 놓는다. 이 자리가 기준값의 최종 위치다.
    [A[i], A[hi]] = [A[hi] as number, A[i] as number];

    // ③ 확정된 자리가 곧 목표 자리다.
    if (i === target) return A[i] as number;
    // ④ 목표가 더 앞이다 — 왼쪽만 남긴다.
    if (i > target) hi = i - 1;
    // ⑤ 목표가 더 뒤다 — 오른쪽만 남긴다.
    else lo = i + 1;
  }

  // 구간에 칸이 하나 남았다 — 그 칸이 목표 자리다.
  return A[lo] as number;
}
```

<!--proof:final-calls-->

```text
kthSmallest([7, 10, 4, 3, 20, 15], 4)   →   10
kthSmallest([42], 1)                    →   42
kthSmallest([5, 5, 5, 5], 3)            →   5
kthSmallest([-5, 0, 5, -10, 10], 1)     →   -10
```

### 알아 두면 좋은 개념 — 감소 정복

파트 1 이 값으로 보인 것이 하나 있습니다. 구간이 6 → 4 → 3 → 2 칸으로 줄었고, 줄어들 때마다 **버린 쪽은
다시 안 봤어요.** 이렇게 한 걸음마다 문제를 작은 조각들로 가른 뒤 **그중 하나만 이어서 푸는** 틀을 **감소
정복**(decrease and conquer)이라고 합니다.

| 절차 | 한 걸음이 하는 일 | 이어서 보는 것 | 걸음당 비용 |
| --- | --- | --- | --- |
| 퀵셀렉트 | 기준값 하나의 자리를 확정한다 | 목표가 든 한쪽 구간 | 구간 크기 |
| 이진 탐색 | 가운데 칸과 찾는 값을 비교한다 | 절반 하나 | 1 |
| 유클리드 호제법 | `a mod b` 를 구한다 | 짝 `(b, a mod b)` 하나 | 나눗셈 1 |
| 퀵 정렬 | 기준값 하나의 자리를 확정한다 | **양쪽 다** | 구간 크기 |

마지막 줄이 갈림입니다. 퀵 정렬은 갈라 놓은 조각을 **전부** 이어서 풀기 때문에 분할 정복이고, 같은 분할을
쓰면서 한 조각만 남기면 감소 정복이 돼요. 「아이디어를 떠올리는 과정」에서 두 방식을 같은 입력으로 실행했을 때
칸 1,024 개에서 11,091 대 2,979 로 갈린 것이 그 차이입니다. 이진 탐색은 걸음당 비용이 1 이라 총합이
`log₂ n` 이 되고, 퀵셀렉트는 걸음당 비용이 구간 크기라 총합이 구간 크기의 합이 돼요. 「한 걸음이 얼마나
줄이는가」와 「걸음당 얼마가 드는가」를 따로 보는 것이 감소 정복을 만났을 때 비용을 세는 방법입니다.

| --- | --- | --- |
| 순위 하나만 필요하다 | 줄 전체의 순서가 필요하면 정렬이 답이다. 15.2 배의 낭비를 아끼는 것이 퀵셀렉트가 사는 자리다 | 이어서 가를 구간을 하나만 남긴다 |
| 질의가 한 번이거나 배열이 매번 바뀐다 | 같은 배열에 순위를 여러 번 물으면 한 번 정렬해 두고 읽는 쪽이 금방 앞선다 | 입력을 제자리에서 헝클어도 된다 |
| 추가 메모리를 쓰기 어렵다 | 맞바꾸기만 하고 새 배열을 잡지 않는다 | 새로 잡는 칸이 없다 |
| 평균이 중요하고 드문 최악을 감당할 수 있다 | 응답 시간에 상한을 약속해야 하는 자리라면 퀵셀렉트가 아니다 | 최악 `n(n−1)/2` 를 코드가 막지 않는다 |

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "k 번째로 작은/큰 값"   "중앙값을 구하라"   "상위 k 번째 점수"
  "정렬하지 말고"         "입력을 고쳐도 된다"

제약에 이런 모양이 보이면
  배열이 수만~수십만이고 답이 값 하나다
  k 가 입력으로 주어지고 1 부터 n 까지 아무 값이나 될 수 있다
  질의가 한 번뿐이다   ← 여러 번이면 정렬해 두는 쪽으로 기운다
```

반대로 **「최악에도 몇 밀리초 안에」** 같은 문구가 있으면 이 단서는 해당하지 않습니다. 그때는 최악까지
선형을 보장하는 절차를 골라야 해요.

#### 실제로 쓰이는 곳

- **러스트 표준 라이브러리의 `slice::select_nth_unstable`** — 모듈 머리 주석이 절차와 대비책을 함께 적어
  뒀습니다. *"It uses an introselect algorithm based on ipnsort … The fallback algorithm used for
  introselect is Median of Medians using Tukey's Ninther for pivot selection. Using this as a fallback
  ensures O(n) worst case running time with better performance than one would get using heapsort as
  fallback."* 평소에는 퀵셀렉트와 같은 분할을 쓰고, 갈림이 치우치면 중앙값의 중앙값으로 갈아탑니다.
  ([`library/core/src/slice/sort/select.rs`](https://github.com/rust-lang/rust/blob/master/library/core/src/slice/sort/select.rs),
  조회 2026-09-03)
- **넘파이의 `np.partition`** — 소스 머리 주석이 최악을 만드는 입력을 **식으로** 적어 뒀어요. *"Quick
  select with median of 3 pivot is usually the fastest, but the worst case scenario can be quadratic
  complexity, e.g. np.roll(np.arange(x), x / 2). To avoid this if it recurses too much it falls back to the
  worst case linear median of median of group 5 pivot strategy."* 기준값을 세 값의 중앙으로 고르는 구현을
  겨냥한 입력이라 이 글의 규칙과는 어긋나는데, 그 차이는 「최악을 만드는 입력」에서 값으로 확인합니다.
  ([`numpy/_core/src/npysort/selection.hpp`](https://github.com/numpy/numpy/blob/main/numpy/_core/src/npysort/selection.hpp),
  조회 2026-09-03)
- **C++ 표준 라이브러리의 `std::nth_element`** — libstdc++ 는 `__introselect` 로 넘기면서 깊이 한도를
  `std::__lg(__last - __first) * 2` 로 함께 넘기고, `__depth_limit == 0` 이 되면 `std::__heap_select` 로
  갈아탑니다. 갈아타는 조건이 **재귀 깊이 하나**로 코드에 박혀 있는 자리예요.
  ([`libstdc++-v3/include/bits/stl_algo.h`](https://github.com/gcc-mirror/gcc/blob/master/libstdc%2B%2B-v3/include/bits/stl_algo.h),
  조회 2026-09-03)

세 자리가 하는 일은 같습니다.

| 구현 | 평소의 절차 | 치우칠 때 갈아타는 절차 |
| --- | --- | --- |
| 러스트 `select_nth_unstable` | 분할로 한쪽만 남긴다 | 중앙값의 중앙값 |
| 넘파이 `np.partition` | 분할로 한쪽만 남긴다 | 중앙값의 중앙값 |
| libstdc++ `nth_element` | 분할로 한쪽만 남긴다 | 힙 선택 |

#### 경쟁 설계와의 대조

같은 목표를 노리는 **다른 절차**가 있어요 — **중앙값의 중앙값**(median of medians)입니다. 다섯 칸씩 묶어 각
묶음의 중앙값을 모으고, 그 모임의 중앙값을 같은 절차로 다시 골라 기준값으로 씁니다. 그렇게 고른 기준값은
양쪽에 칸이 늘수록 30 % 에 가까워지는 몫을 남깁니다. 묶음 중앙값의 절반 이상이 기준값 이상이고, 그런
묶음마다 기준값보다 큰 칸이 셋씩 있으니, 기준값 자신의 묶음과 모자란 마지막 묶음을 빼도 큰 쪽에
`3n/10 − 6` 칸 이상이 남아요. 작은 쪽도 같은 셈입니다(값이 모두 다를 때). 그래서 **최악에도 선형**입니다. 퀵셀렉트에는 없는 약속이에요. 이 하한은 세어서
낸 값이 아니라 방금 적은 셈으로 낸 식입니다.

`n = 1,024` 를 고정하고 입력 두 벌로 둘을 실행해 **비교 횟수와 새로 잡는 칸 수**를 셌습니다. 한 벌은 생성식
`A[i] = (i × 7919) mod 10,007` 로 만든 뒤섞인 배열에 `k = 512` 를 물은 것이고, 다른 한 벌은 **퀵셀렉트의
기준값 규칙을 겨냥해 역산한 배열**(구성은 「최악을 만드는 입력」)에 `k = 1,024` 를 물은 것입니다. 입력은 난수
없이 식으로 만들었으니 시드가 없어요.

| 설계 | 뒤섞인 입력 비교 횟수 | 최악 입력 비교 횟수 | 뒤섞인 입력 새로 잡는 칸 | 최악 입력 새로 잡는 칸 |
| --- | --- | --- | --- | --- |
| 퀵셀렉트 | **2,979** | 523,776 | **0** | **0** |
| 중앙값의 중앙값 | 4,649 | **8,445** | 317 | 624 |

전개에 쓰는 여섯 칸짜리 입력을 그대로 쓰지 않은 이유는 하나예요 — 그 크기에서는 역산한 입력을 넣어도
퀵셀렉트가 적어서 **이 대조가 재려는 뒤집힘 자체가 안 일어납니다.** 역산한 입력의 칸 수를 늘려 가며 재면
이렇습니다.

<!--proof:alt-crossover-->

| 칸 수 n | 퀵셀렉트 | 중앙값의 중앙값 |
| ---: | ---: | ---: |
| 6 | 15 | 26 |
| 11 | 55 | 60 |
| 12 | 66 | 52 |
| 18 | 153 | 162 |
| 19 | 171 | 106 |

역산한 입력 worstInput(n) 에 k = n 을 물은 비교 횟수입니다. 중앙값의 중앙값이 처음 적어지는 것은 n = 12 이고, 퀵셀렉트가 마지막으로 적은 것은 n = 18 이며, n = 19 부터 64 까지는 모두 중앙값의 중앙값이 적습니다. 칸 1,024 개의 뒤섞인 입력에서는 퀵셀렉트가 1.6 배 적고(비교 1,670 번 차이), 역산한 입력에서는 62.0 배 많습니다.

<!--/proof-->

**입력 모양 하나로 순서가 뒤집힙니다.** 칸 수가 작을 때는 퀵셀렉트가 적다가 12 칸에서 처음 뒤집히고, 18
칸에서 한 번 더 퀵셀렉트가 적은 뒤 19 칸부터 잰 끝인 64 칸까지는 중앙값의 중앙값이 계속 적어요. 축을 넷으로 갈라 적으면
이렇습니다.

| 축 | 퀵셀렉트 | 중앙값의 중앙값 | 적은 쪽 |
| --- | --- | --- | --- |
| 뒤섞인 입력 비교 횟수 | 2,979 | 4,649 | 퀵셀렉트 |
| 최악 입력 비교 횟수 | 523,776 | 8,445 | 중앙값의 중앙값 |
| 새로 잡는 칸 | 0 | 317 · 624 | 퀵셀렉트 |
| 최악 보장 | 없다 | 선형 | 중앙값의 중앙값에 있다 |

**우열이 반대가 되는 조건이 분명합니다.** 입력을 만드는 쪽이 절차를 알고 있거나(경쟁 제출 · 외부에서 들어오는
요청) 최악 응답 시간에 상한이 필요하면 중앙값의 중앙값이 답이에요. 입력이 그런 식으로 만들어질 일이 없고
평균만 요구하면 퀵셀렉트입니다. 뒤섞인 입력에서 퀵셀렉트가 내주는 것은 최악 보장 하나이고, 받는 것이 비교
1,670 번과 317 칸입니다.

### 수식 정의와 유도

크기 `n` 인 구간 하나를 끝낼 때까지의 비교 횟수를 $C(n)$ 이라 하고, 분할이 끝난 뒤 목표가 속한 쪽의 크기를
$s$ 라 둡니다. 분할 자체는 구간을 한 번 순회하므로 $n-1$ 번 비교하고, 그다음에는 그 한쪽만 이어서 처리해요.

$$C(n) = (n-1) + C(s), \qquad C(1) = 0, \qquad 0 \le s \le n-1$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $n$ | 그 순회가 받은 구간의 크기 | $1 \le n$ |
| $s$ | 목표가 속한 쪽의 크기 | $0 \le s \le n-1$ |
| $n-1-s$ | 버리는 쪽의 크기. 가운데 한 칸은 기준값이라 양쪽 어디에도 안 들어간다 | $0 \le n-1-s$ |

```text
n 칸을 세 덩어리로 가른다

  |---- s 칸 ----|- 1 칸 -|---- n−1−s 칸 ----|
     목표가 든 쪽   기준값      버리는 쪽
     └ C 로 이어진다  └ 확정    └ 다시 안 본다
```

**정의를 값에 넣어 검산해 봅시다.** 전개 입력은 구간이 6 → 4 → 3 → 2 로 줄었으니 $s$ 가 차례로 4 · 3 · 2 · 1
이었어요.

<!--proof:math-check-->

```text
C(6) = 5 + 3 + 2 + 1 + C(1) = 11
       └ 구간이 6 → 4 → 3 → 2 로 줄었고, 전개에서 센 11 번과 같다

같은 식에 두 극단을 넣으면
  가장 고른 갈림  s = ⌊n/2⌋   C(6) = 7
  한쪽이 빈다     s = n − 1   C(6) = 15
       └ 실제 11 은 그 사이에 있다
```

점화식을 그대로 코드로 옮기면 위 수들이 손 계산 없이 나옵니다. 식의 $s$ 는 코드에서 `side` 라는 함수가 정하고,
그 함수가 줄어드는 모양을 정해요.

<!--proof:math-code-->

```ts
const C = (n: number, side: (n: number) => number): number =>
  n <= 1 ? 0 : n - 1 + C(side(n), side);

C(6, (n) => Math.floor(n / 2)); // 가장 고른 갈림 → 7
C(6, (n) => n - 1); // 한쪽이 빈다 → 15
C(8, (n) => Math.floor(n / 2)); // 가장 고른 갈림 → 11
```

**이제 닫힌 형태를 유도합니다.** 한쪽이 비는 경우부터 풀면 항이 하나씩 줄어드는 단순한 합이에요.

```text
C(n) = C(n-1) + (n-1)
     = C(n-2) + (n-2) + (n-1)          C(n-1) 을 같은 식으로 한 번 더 편다
     = C(n-3) + (n-3) + (n-2) + (n-1)
     …
     = C(1) + 1 + 2 + … + (n-1)        C(1) = 0 이라 여기서 멈춘다
```

$$C(n) = \sum_{j=1}^{n-1} j = \frac{n(n-1)}{2}$$

<!--proof:math-closed-check-->

```text
n = 6  →  6·5/2 = 15    worstInput(6) 에 k = 6 을 실제로 물은 비교 15 번
n = 8  →  8·7/2 = 28    worstInput(8) 에 k = 8 을 실제로 물은 비교 28 번
```

가장 고른 갈림은 $n = 2^t$ 에서 정확히 풀립니다. 귀납으로 갑시다. 기저는 $t = 0$ 이고 $C(1) = 0 = 2^{1} - 0 - 2$
예요. $C(2^t) = 2^{t+1} - t - 2$ 를 가정하면 목표가 든 쪽이 $2^t$ 칸이라 다음 단계가 이렇게 됩니다.

$$C(2^{t+1}) = (2^{t+1} - 1) + C(2^t) = (2^{t+1} - 1) + 2^{t+1} - t - 2 = 2^{t+2} - (t+1) - 2$$

마지막 식이 $t + 1$ 에서의 가정과 같은 꼴이라 모든 $t$ 에서 성립합니다. 작은 $t$ 에서 점화식과 맞춰 보면
이렇습니다.

<!--proof:math-pow2-->

| t | n = 2^t | 2^(t+1) − t − 2 | 점화식으로 센 값 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 0 | 0 |
| 1 | 2 | 1 | 1 |
| 2 | 4 | 4 | 4 |
| 3 | 8 | 11 | 11 |
| 10 | 1,024 | 2,036 | 2,036 |

`n` 이 2 의 거듭제곱이 아닐 때는 정확한 값 대신 상한을 얻습니다. $C(n) \le 2n - 2$ 를 같은 방식으로
확인해요. 기저는 $C(1) = 0 = 2 \cdot 1 - 2$ 입니다. $\lfloor n/2 \rfloor$ 에서 상한이 성립한다고 가정하면
$C(n) = (n-1) + C(\lfloor n/2 \rfloor) \le (n-1) + 2\lfloor n/2 \rfloor - 2$ 이고, $2\lfloor n/2 \rfloor \le n$
이므로 오른쪽은 $2n - 3$ 이하예요. $2n - 3 < 2n - 2$ 라 상한 안에 들어갑니다.

```text
왜 로그가 사라지는가
  양쪽을 다 이어서 풀면   층마다 구간 크기의 합이 n 이고 층이 log₂ n 개  →  n log₂ n
  한쪽만 이어서 풀면      층마다 크기가 절반이라 n + n/2 + n/4 + …       →  2n 미만
                          └ 등비급수의 합이 유한해서 층 수가 곱해지지 않는다
```

**마지막으로 계수입니다.** 두 닫힌 형태에 규모를 넣어 계산해요.

<!--proof:cost-extremes-->

| 칸 수 n | 가장 고른 갈림 | 상한 2n − 2 | 한쪽이 비는 갈림 | 차이 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 11 | 14 | 28 | 2.5 배 |
| 16 | 26 | 30 | 120 | 4.6 배 |
| 1,024 | 2,036 | 2,046 | 523,776 | 257.3 배 |
| 100,000 | 199,977 | 199,998 | 4,999,950,000 | 25,002.6 배 |

가장 고른 갈림이 상한 2n − 2 를 넘지 않는 것은 칸 1 개부터 2,000 개까지 점화식으로 모두 세어 확인했습니다.

<!--/proof-->

칸 100,000 개에서 199,977 번과 4,999,950,000 번이 갈리고, 그 차이가 25,002.6 배입니다. 아래쪽 값은 「아이디어를
떠올리는 과정」의 `k` 번 최솟값 찾기가 가운데 순번에서 센 3,749,975,000 번보다도 많아요 — 갈림이 한쪽으로만
치우치면 퀵셀렉트는 그 방법보다 느려집니다.

### 불변식 — 매 바퀴가 시작될 때 목표 자리는 남은 구간 안에 있다

파트 1 에서 코드가 동작하는 것을 스물세 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지, 언제나 맞는다는
뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> `while` 이 한 바퀴를 시작할 때마다 `lo ≤ target ≤ hi` 이고, 구간 밖의 칸은 왼쪽이면 정렬한 줄에서
> `target` 보다 앞자리를, 오른쪽이면 뒷자리를 차지하는 값입니다.

<!--fig:invariant-range-->
![바퀴가 시작할 때 — 목표 자리는 남은 구간 안에 있다](./figs/invariant-range.svg)

「한 바퀴를 시작할 때마다」가 중요합니다. 루프가 끝난 뒤 한 번만 참인 것이 아니라 **구간을 옮길 때마다**
참이라는 뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 물려받습니다.

**출발점부터 봅시다.** 첫 바퀴 전에 `lo = 0` 이고 `hi = n−1` 이라 구간이 배열 전체이고, `target = k − 1` 은
`1 ≤ k ≤ n` 이라 `0` 과 `n−1` 사이에 있습니다. 구간 밖의 칸은 없어요. 그 뒤 한 바퀴마다 갈래 셋 중 하나가
실행됩니다.

| 갈래 | 하는 일 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| `p = target` | `A[p]` 를 돌려준다 | 분할 뒤 `A[lo..p−1]` 은 전부 `A[p]` 미만이고, 구간 왼쪽 밖의 `lo` 칸은 불변식에 따라 그보다도 앞자리 값이다. `A[p]` 앞에 오는 값이 정확히 `p` 개이니 `A[p]` 가 곧 정렬한 줄의 자리 `p = target` 의 값이다 |
| `p > target` | `hi ← p − 1` | 답의 자리 번호가 `p` 보다 작으므로 `A[p]` 와 그 오른쪽은 뒷자리 값이다. 새 구간 `[lo, p−1]` 에서 `lo ≤ target ≤ p−1` 이 그대로 참이다 |
| `p < target` | `lo ← p + 1` | 답의 자리 번호가 `p` 보다 크므로 `A[p]` 와 그 왼쪽은 앞자리 값이다. 버린 칸의 번호가 전부 `target` 미만이라 남은 칸의 번호가 옮겨지지 않는다 |

`while` 을 나오는 다른 길은 `lo = hi` 하나뿐입니다. 그 시점에도 `lo ≤ target ≤ hi` 가 참이니 `target = lo`
이고, 그래서 `A[lo]` 가 답이에요. 구간이 매 바퀴 적어도 한 칸씩 줄어드니 이 시점은 반드시 옵니다.

**경계에 있는 입력들도 확인하고 갑시다.** 결과는 정본이 낸 값이고, 모두 정렬한 줄에서 읽은 답과 같습니다.

<!--proof:invariant-edges-->

| 입력 | 처리되는 자리 | 결과 |
| --- | --- | --- |
| 칸 하나 [42], k = 1 | lo = hi = 0 이라 반복에 들어가지 않는다 | 42 |
| 칸 둘 [10 5], k = 1 | 바퀴 1 번 · 구간 2 칸 | 5 |
| k = 1 [7 10 4 3 20 15], k = 1 | 바퀴 1 번 · 구간 6 칸 | 3 (최솟값) |
| k = n [7 10 4 3 20 15], k = 6 | 바퀴 3 번 · 구간 6 → 4 → 3 칸 | 20 (최댓값) |
| 전부 같음 [5 5 5 5], k = 3 | 바퀴 3 번 · 구간 4 → 3 → 2 칸 | 5 |
| 중복 경계 [1 1 2], k = 2 | 바퀴 2 번 · 구간 3 → 2 칸 | 1 |
| 값 범위 끝 [1000000000 -1000000000 0], k = 2 | 바퀴 2 번 · 구간 3 → 2 칸 | 0 |
| 빈 배열 [], k = 1 | hi = −1 이라 반복에 들어가지 않고 A[0] 을 읽는다 | undefined — 값이 없다 |

마지막 줄이 예외입니다. `A.length` 가 0 이면 `hi = −1` 이라 반복에 안 들어가고 `A[0]` 을 읽으므로 값이
없어요. 과제의 규모가 `1 ≤ n` 이라 그 입력이 들어오지 않으니 코드가 따로 막지 않는 것이고, 빈 배열이 들어올 수
있는 자리에 이 코드를 옮긴다면 그 검사를 함께 옮겨야 합니다.

**이제 깨뜨려 봅시다.** 불변식을 세우던 줄이 어느 것인지는 바꿔 보면 확인됩니다. 다른 곳은 그대로 두고 **첫
줄의 `k - 1` 을 `k` 로만** 바꿉니다. 그러면 출발점에서 `target` 이 정렬한 줄의 한 칸 뒤를 가리켜요.

```ts
const target = k; // ← k - 1 이어야 하는 자리
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-target-->

| 입력 | k | 바른 코드 | target = k 로 바꾼 코드 |
| --- | ---: | ---: | ---: |
| [7 10 4 3 20 15] | 4 | 10 | 15 |
| [3 1 2] | 1 | 1 | 2 |
| [-5 0 5 -10 10] | 1 | -10 | -5 |
| [7 10 4 3 20 15] | 6 | 20 | undefined |

마지막 줄은 k = n 이라 바꾼 코드의 target = 6 이 배열 밖을 가리키고, 바꾼 코드는 구간이 배열 끝을 넘어간 뒤 A[6] 을 읽으므로 값이 나오지 않습니다(undefined).

<!--/proof-->

앞 세 줄은 **한 칸 뒤의 값**이 나옵니다. 예외가 나거나 프로그램이 멈추는 것이 아니라 조용히 다른 값이 나오는
것이 이 자리의 성질이에요. `[3 1 2]` 에서 두 코드가 어디서 갈리는지 따라가 보겠습니다.

<!--proof:mutant-trace-->

```text
[3 1 2]  k = 1  을 두 코드로

  두 코드의 첫 분할은 같다. 기준값 1 이 끝으로 가고 [1 2 3] 이 되어 p = 0 이다

  바른 코드   target = 0   p = 0 이 곧 목표 자리라 A[0] = 1 을 돌려준다
  바꾼 코드   target = 1   p = 0 < 1 이라 오른쪽 [1,2] 로 가고, 거기서 p = 1 이 되어 A[1] = 2 를 돌려준다
              └ 정렬한 줄 [1 2 3] 의 자리 1 은 2 다. k = 2 의 답을 낸 것이다
```

바꾼 코드는 `k` 번째가 아니라 `k + 1` 번째 값을 고릅니다. 불변식이 「`target` 은 답의 자리다」를 전제로
세워져 있으니, 출발점에서 `target` 이 한 칸 어긋나면 그 뒤의 모든 바퀴가 어긋난 자리를 충실히 좇아가요.

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 비교는 분할 루프의 `A[j] < pivot` 뿐이고, 그 횟수는 `hi − lo` 입니다. 전개의 걸음으로 확인하면
이렇습니다.

<!--proof:perf-derive-->

| 구간 | 칸 수 | 비교 | 걸음 |
| --- | ---: | ---: | --- |
| [0,5] | 6 | 5 | T2 · T3 · T4 · T5 · T6 |
| [2,5] | 4 | 3 | T10 · T11 · T12 |
| [3,5] | 3 | 2 | T16 · T17 |
| [3,4] | 2 | 1 | T21 |

바퀴마다 비교는 칸 수보다 하나 적고, 합은 11 번입니다.

<!--/proof-->

그러니 전체 비교 횟수는 **바퀴마다의 구간 크기에서 1 을 뺀 값을 다 더한 것**입니다. 그 합이 구간의 줄어드는
모양에 따라 어떻게 달라지는지가 「수식 정의와 유도」의 두 극단이에요.

```text
총식 = Σ (그 바퀴의 구간 크기 − 1)     ← 비교 횟수. 지배항
     + 맞바꾸기                        ← 비교 횟수 + 바퀴당 2 회 이하
     + 갈래 판정                       ← 바퀴당 2 회

좋은 갈림   구간이 절반씩 줄면  n + n/2 + n/4 + …      → 2n 미만
나쁜 갈림   구간이 1 씩 줄면    n + (n−1) + (n−2) + …  → n(n−1)/2
```

여기서 센 것은 **비교 횟수만**입니다. 맞바꾸기는 분할 루프 안에서 비교 한 번에 많아야 한 번이고 바퀴마다 두
번이 더 붙으며, 갈래 판정은 바퀴당 상수라 바퀴 수가 `n` 이하인 이상 지배항이 바뀌지 않아요. 새로 잡는 칸은
**0 칸**입니다 — 재귀가 아니라 반복문이라 호출 스택도 안 쌓여요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 분할에서 자리가 맞는다) | `O(n)` | `Θ(n)` — 비교 정확히 `n−1` 번 |
| **평균적인 경우** (입력 순열이 고르게 분포) | `O(n)` | `Θ(n)` |
| **최악의 경우** (매번 버리는 쪽이 비어 구간이 한 칸씩 준다) | `O(n²)` | `Θ(n²)` — 실제로 도달한다 |

최악에서 `Θ(n²)` 이라고 쓸 수 있는 것은 그 값을 **실제로 내는 입력이 있기** 때문입니다. 「최악을 만드는 입력」의
`worstInput(8)` 에 `k = 8` 을 물으면 정확히 `8 · 7 / 2` 번 비교해요.

**총식을 한 번은 정확히 적습니다.** 비교에 맞바꾸기와 바퀴당 상수가 붙고, 앞뒤로 붙는 전처리는 없습니다.

```text
총식 = Θ(비교) + O(맞바꾸기) + O(바퀴 수) + Θ(새로 잡는 칸)
       └ 평균 Θ(n)   └ 비교 이하 + 2·바퀴   └ n 이하    └ 0 칸
```

**두 줄의 보장이 종류가 다릅니다.** 최악은 최악 보장이지만 평균은 기댓값이고, 그 기댓값이 **무엇에 대한
것인지**가 이 구현에서 특별해요. 코드에 난수가 하나도 없고 기준값을 구간의 중앙에서 결정적으로 고르므로, 같은
입력을 두 번 넣으면 비교 횟수가 언제나 같습니다. 그러니 여기서 말하는 평균은 **입력 순열이 고르게 분포한다는
가정 아래의 평균**이고, 구현이 만드는 무작위성에 대한 기댓값이 아니에요.

```text
난수가 없다는 것이 재는 대상을 바꾼다
  같은 A 를 두 번 넣으면   비교 횟수가 언제나 같은 수다
  그래서 평균은            "이 코드가 A 하나에 몇 번 비교하는가" 를 A 전체에 걸쳐 평균한 값
  그래서 최악은            그 평균과 무관하게, 계산해서 넣을 수 있는 입력 하나가 정한다
```

가정 아래의 값을 실제로 세어 봅시다. 칸 8 개의 모든 순열을 `k = 1` 부터 8 까지 전부 실행한 결과입니다.

<!--proof:average-by-k-->

| 묻는 순번 | 평균 비교 | 가장 적을 때 | 가장 많을 때 | 28 번을 내는 순열 |
| --- | ---: | ---: | ---: | ---: |
| k = 1 | 10.56 | 7 | 28 | 2 |
| k = 2 | 12.25 | 7 | 28 | 14 |
| k = 3 | 13.39 | 7 | 28 | 42 |
| k = 4 | 13.95 | 7 | 28 | 70 |
| k = 5 | 13.95 | 7 | 28 | 70 |
| k = 6 | 13.39 | 7 | 28 | 42 |
| k = 7 | 12.25 | 7 | 28 | 14 |
| k = 8 | 10.56 | 7 | 28 | 2 |

칸 8 개의 순열 40,320 개를 순번마다 전부 실행했습니다.

<!--/proof-->

**`k` 가 가운데일수록 평균이 큽니다.** 양 끝은 10.56 이고 가운데는 13.95 예요. 「가장 적을 때」가 `k` 와
무관하게 7 인 것은 `n − 1 = 7` 이 첫 분할의 비교이자 하한이기 때문이고, 28 번을 내는 순열이 `k` 가 가운데로 갈수록
2 개에서 70 개로 느는 것은 최악에 걸리는 순열이 가운데 순번에서 가장 많다는 뜻입니다.

**규모를 키우면 상수가 자리를 잡습니다.** 섞은 순열 500 벌씩을 세 크기에서 실행해 비교 횟수가 `n` 의 몇
배인지 셌어요.

<!--proof:average-large-->

| 칸 수 n | k = 1 | k = n/2 + 1 | k = n |
| ---: | ---: | ---: | ---: |
| 64 | 1.87 n | 2.87 n | 1.88 n |
| 1,024 | 1.96 n | 3.34 n | 2.01 n |
| 4,096 | 2.02 n | 3.39 n | 1.97 n |

순열은 씨앗 20260903 으로 시작하는 선형 합동 생성기(곱 1103515245 · 더함 12345 · 법 2^31)로 섞었고, 칸 수마다 500 벌을 실행해 비교 횟수의 평균을 n 으로 나눴습니다.

<!--/proof-->

양 끝을 물으면 `2n` 에, 가운데를 물으면 `3.4n` 에 가까워집니다. 칸 8 개의 전수 평균이 `k` 에 따라 10.56 과
13.95 로 갈렸던 것이 규모를 키우면 이 두 상수로 굳어요. **이 구분이 갈리는 자리는 공격입니다** — 결정적
기준값은 절차를 아는 사람이 최악 입력을 계산해 넣을 수 있고, 그 계산이 다음 절입니다.

#### 최악을 만드는 입력

절차가 어느 자리를 고르는지 알고 있으므로, **그 자리에 놓일 값을 매 바퀴 그 구간의 최솟값으로** 정해 두면
분할이 매번 한쪽으로 완전히 치우칩니다. 값을 직접 적는 대신 절차를 거꾸로 실행해 순위를 배정하면 임의의 `n`
에서 그런 배열이 나와요.

```ts
export function worstInput(n: number): number[] {
  const pos = Array.from({ length: n }, (_, i) => i);
  const rank = new Array<number>(n).fill(-1);
  for (let round = 0; round < n - 1; round++) {
    const lo = round;
    const hi = n - 1;
    // 이 바퀴의 기준값 자리를 그대로 흉내 내고 (swap 은 두 칸을 맞바꾸는 함수다)
    swap(pos, lo + Math.floor((hi - lo) / 2), hi);
    // 그 값이 구간의 최솟값이었던 것처럼 lo 에 놓는다
    swap(pos, lo, hi);
    rank[pos[lo] as number] = round; // 그 칸이 round 번째로 작은 값이 된다
  }
  rank[pos[n - 1] as number] = n - 1;
  return rank;
}
```

구간이 왼쪽부터 한 칸씩 줄어드니 목표는 오른쪽 끝에 두어야 합니다 — `k = n` 이에요. `worstInput(8)` 에
`k = 8` 을 물으면 바퀴마다 이렇게 됩니다.

<!--fig:worst-rounds-->
![worstInput(8) 에 k = 8 — 구간이 한 칸씩만 준다](./figs/worst-rounds.svg)

바퀴마다 기준값이 구간 맨 앞 `lo` 에 자리 잡고, 남는 구간이 한 칸씩만 줄어요. 규모를 바꿔 실행하면 상한과
정확히 같은 값이 나옵니다.

<!--proof:worst-input-->

| 입력 | 칸 수 n | 묻는 순번 | 비교 | n(n−1)/2 |
| --- | ---: | ---: | ---: | ---: |
| worstInput(6) [2 5 0 1 3 4] | 6 | 6 | 15 | 15 |
| worstInput(8) [2 6 4 0 1 3 5 7] | 8 | 8 | 28 | 28 |
| worstInput(16) | 16 | 16 | 120 | 120 |
| worstInput(1,024) | 1,024 | 1,024 | 523,776 | 523,776 |
| 전부 같은 값 [5 5 … 5] | 1,024 | 1,024 | 523,776 | 523,776 |
| np.roll(arange(1024), 512) | 1,024 | 513 | 3,057 | 523,776 |

np.roll 입력의 비교 3,057 번은 상한 523,776 번의 0.6 % 입니다.

<!--/proof-->

표의 아래 두 줄이 갈라지는 자리입니다. **최악 입력은 기준값 규칙마다 다릅니다** — 넘파이 주석이 최악의 예로
드는 `np.roll(np.arange(x), x/2)` 는 기준값을 **세 값의 중앙**으로 고르는 구현을 겨냥한 것이라 퀵셀렉트의 중앙
규칙에는 통하지 않아요. 반대로 **값이 전부 같은 배열**은 규칙과 무관하게 상한을 내는데, 그쪽은 의도하지 않아도
실무에서 흔히 들어옵니다. 러스트와 넘파이가 갈림이 치우치는 것을 감지해 중앙값의 중앙값으로 갈아타는 것이 이
자리를 막는 방법이에요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 값 하나의 자리는 「그보다 작은 값의 개수」와 같아서 한 번의
분할로 확정되고, 그 자리와 목표 자리를 비교하면 한쪽 구간을 통째로 버릴 수 있으며, 버리는 덕분에 바퀴마다의
비용이 등비급수가 되어 합이 `2n` 아래로 멈춥니다.

```text
target = k − 1 로 목표 자리를 고정한다
   → 구간의 중앙을 기준값으로 골라 끝으로 옮긴다
   → 한 번 순회하며 작은 값을 왼쪽으로 맞바꾼다
   → 기준값을 경계에 놓아 자리 p 를 확정한다
   → p 와 target 을 비교해 한쪽 구간만 남긴다
       └ 갈림이 고르면 2n 미만, 한쪽이 비면 n(n−1)/2
```

먼저 답이 붙는 문제 하나입니다. 전개의 T15 부터 T18 에서 기준값 20 이 구간 `[3,5]` 의 최댓값이라 `p = 5` 가
됐어요. 만약 그 구간의 중앙에 10 이 있어서 `p = 3` 이 나왔다면, 그 뒤 몇 번을 더 비교하고 끝났을까요?

```text
실제로 일어난 일   구간 [3,5] 에서 p = 5 → 왼쪽 [3,4] → 다시 분할 → 끝
가정               구간 [3,5] 에서 p = 3 → ?
```

`target = 3` 이므로 `p = 3` 이면 그 자리에서 반환입니다. T16 · T17 의 비교 2 번까지만 하고 끝나므로, 실제로 든

## 실습 — 직접 풀어 보기

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### Kth Smallest Element

풀 파일: [`kthSmallest.ts`](./kthSmallest.ts) · 테스트: [`kthSmallest.test.ts`](./kthSmallest.test.ts) · 실행: `bun test src/algorithms/sorting/kthSmallest/kthSmallest.test.ts`

중요도 ★★ 중 — 빈출 · 난이도 중급

#### 한 줄 요약

> 정수 배열 `A` 와 정수 `k` 가 주어질 때, **`A` 를 오름차순으로 정렬했을 때 앞에서 `k` 번째에 오는 값**을 반환한다. (`k` 는 1부터 센다.)

#### 스토리

기상청 전산실. 오늘 전국 **`N` 개 관측 지점**에서 측정한 오늘의 최저기온(℃)이 배열 하나로 들어왔다.
한겨울이라 영하(음수)도 섞여 있고, 우연히 **같은 기온**이 찍힌 지점들도 있다.

기자에게서 전화가 온다. "오늘 **`k` 번째로 추운** 지점이 몇 도였죠?"

가장 추운 곳이 1번째, 그다음이 2번째… 이렇게 추운 순서대로 줄을 세웠을 때 **`k` 번째 자리에 있는 기온**이
바로 답이다. 같은 기온인 지점이 여럿이면 그 지점들은 줄에서 **각각 한 칸씩** 차지한다.

여러분이 할 일은, 이 측정값 배열과 순번 `k` 를 받아 **`k` 번째로 작은(=추운) 값**을 돌려주는 함수를 만드는 것이다.

#### 함수 인터페이스

```ts
export function kthSmallest(A: number[], k: number): number;
```

- `A` — 측정값(정수) 배열.
- `k` — 1부터 시작하는 순번. `k = 1` 이면 가장 작은 값, `k = N` 이면 가장 큰 값을 가리킨다.
- 반환 — `A` 를 오름차순 정렬했을 때 앞에서 `k` 번째에 오는 값 하나.

#### 제약 조건

- $1 \leq N \leq 100{,}000$ — 여기서 $N$ 은 배열 `A` 의 길이다.
- $-10^9 \leq A[i] \leq 10^9$ — 각 원소는 이 범위의 **정수**이며 **음수일 수 있다.** (실수·`NaN`·`Infinity` 는 입력으로 주어지지 않는다.)
- $1 \leq k \leq N$ — `k` 는 **1-based** 순번이라 항상 유효한 범위 안에 있다(빈 배열이나 범위 밖 `k` 는 입력으로 주어지지 않는다).
- 입력 `A` 의 순서는 **보장되지 않는다**(정렬되어 있을 수도, 아닐 수도 있다).
- **시간 제한 1초, 메모리 제한 256 MB.** (성능 기준은 단순 연산으로 CPU 가 1초에 약 $10^8$ 번 계산한다는 가정을 따른다.)
- 함수는 입력 `A` 를 **제자리에서 변경해도 된다** — 호출이 끝난 뒤 `A` 의 원소 순서는 보장하지 않는다.

#### 문제 상세

배열 `A` 를 **오름차순(작은 값 → 큰 값)** 으로 정렬한 결과를 $S$ 라 하면, 답은 다음과 같이 정의된다.

$$\text{kthSmallest}(A, k) = S[k-1] \quad (\text{0-based 인덱스})$$

즉 "**`k` 번째로 작은 값**"은 정렬된 줄에서 앞에서부터 `k` 칸째에 있는 값이다. 다음 규칙을 따른다.

- **순번은 1부터.** `k = 1` 은 최솟값, `k = N` 은 최댓값을 가리킨다. (0번째는 없다.)
- **중복은 각각 한 자리.** 같은 값이 여러 개면 정렬된 줄에서 그 값들이 **개수만큼 연속된 자리**를 차지한다.
  예를 들어 `[1, 1, 2]` 에서 `k = 2` 의 답은 (또 다른) `1` 이다.
- **음수·0 포함.** 값의 부호는 정렬 순서에만 영향을 준다. 가장 작은 음수가 맨 앞에 온다.
- **반환은 값 하나.** 인덱스가 아니라 그 자리에 있는 **원소의 값**을 돌려준다.
- 제약상 `k` 는 항상 `1..N` 범위이므로, 이 범위 밖 입력에 대한 동작은 정의하지 않는다.

#### 예시

```ts
kthSmallest([3, 1, 2], 1);              // 1  — 작은 순 [1,2,3]에서 1번째
kthSmallest([3, 1, 2], 2);              // 2  — 작은 순 [1,2,3]에서 2번째
kthSmallest([3, 1, 2], 3);              // 3  — 작은 순 [1,2,3]에서 3번째(=최댓값)

kthSmallest([7, 10, 4, 3, 20, 15], 3);  // 7  — 작은 순 [3,4,7,10,15,20]에서 3번째
kthSmallest([7, 10, 4, 3, 20, 15], 4);  // 10 — 작은 순 [3,4,7,10,15,20]에서 4번째

kthSmallest([-5, 0, 5, -10, 10], 1);    // -10 — 작은 순 [-10,-5,0,5,10]에서 1번째(가장 추운 값)

kthSmallest([2, 1, 2, 1, 3, 1], 4);     // 2  — 작은 순 [1,1,1,2,2,3]에서 4번째(중복은 각각 한 자리)

kthSmallest([5, 5, 5, 5], 3);           // 5  — 모든 값이 같으면 어떤 k든 그 값(경계: 전부 동일)

kthSmallest([42], 1);                   // 42 — 원소가 하나뿐이라 1번째가 곧 그 값(경계: N=1)

// 값 범위 경계: 원소가 ±1,000,000,000 까지 올 수 있다
kthSmallest([1_000_000_000, -1_000_000_000, 0], 2); // 0 — 작은 순 [-1000000000, 0, 1000000000]에서 2번째
```

각 예시의 설명은 **그 출력이 정의에 어떻게 들어맞는지**만 보여줄 뿐, 어떻게 구하는지(풀이 방법)는 말하지 않는다.

##### 순번으로 답을 읽는 법 (그림)

`[7, 10, 4, 3, 20, 15]`, `k = 3` 의 답이 왜 `7` 인지 — 값을 **작은 순으로 줄 세웠을 때** `k` 번째 자리를 보면 된다:

```
원래 배열:        7   10   4    3    20   15
작은 순 줄 세우기:  3    4   7    10   15   20
순번(k):          1    2   3    4    5    6
                            ↑
                           k=3  → 7
```
