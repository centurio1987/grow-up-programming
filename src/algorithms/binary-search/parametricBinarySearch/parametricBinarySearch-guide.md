# 파라메트릭 이진 탐색 — 답을 만들지 않고 「이 값이면 되는가」만 물으면 답이 후보 구간이 된다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 나눌 자리를
전부 고르는 방법에서 출발해 답의 후보 구간을 판정 함수로 절반씩 줄이는 방법까지 가고, 그 방법을
단계마다 값으로 푼 뒤, 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

배열을 연속한 묶음 `K` 개로 나누되, **묶음 합 가운데 가장 큰 값을 가장 작게** 만들고 싶다고 해
봅시다. 배열 `[7 2 5 10 8]` 을 두 묶음으로 나누는 방법은 칸 사이 네 곳 중 한 곳을 고르는 네 가지뿐이라
전부 그려 볼 수 있어요.

<!--fig:concept-splits-->
![[7 2 5 10 8] 을 두 묶음으로 나누는 네 가지와 각각의 최댓값](./figs/concept-splits.svg)

네 나눔의 최댓값은 25 · 23 · 18 · 24 이고, 가장 작은 것은 18 입니다. 다섯 칸이라 네 가지로
끝났지만, 칸이 늘고 묶음 수가 늘면 고를 자리의 가짓수가 빠르게 불어나서 전부 그려 볼 수 없게 됩니다.

그래서 이 알고리즘은 **질문을 뒤집습니다.** 나누는 방법을 찾는 대신, 답이 될 수 있는 값 하나를 `m`
이라 두고 「묶음 합이 모두 `m` 이하가 되게 `K` 개 이하로 나눌 수 있는가」만 묻습니다. 이렇게 후보값
하나를 받아 참·거짓으로 답하는 함수를 **판정 함수**라고 부르겠습니다. 왼쪽부터 원소를 지금 묶음에
이어 붙이다가, 붙이면 `m` 을 넘는 순간 새 묶음을 시작하면 배열을 한 번 순회하는 것으로 답이 나와요.
`m = 18` 과 `m = 17` 에 물어보면 이렇습니다.

<!--fig:concept-judge-->
![판정 함수에 m = 18 과 m = 17 을 묻는다 — 두 묶음이면 참, 세 묶음이면 거짓](./figs/concept-judge.svg)

18 에서는 두 묶음으로 끝나 참이고, 17 에서는 `10 8` 을 한 묶음에 둘 수 없어 세 묶음이 되니 거짓이에요.
이제 답이 될 수 있는 값을 한 줄로 늘어놓고 판정을 적어 봅시다. 가장 작은 후보는 가장 큰 원소
`max(A) = 10` 입니다. 그 원소가 든 묶음의 합은 그 원소보다 작을 수 없으니까요. 가장 큰 후보는 전부를
한 묶음으로 둔 원소의 합 `ΣA = 32` 예요. 이 두 끝 사이의 값 전체를 **후보 구간**이라고 부릅니다.

<!--fig:concept-verdict-line-->
![후보값 10 부터 32 까지의 판정 — 거짓이 이어지다가 18 에서 참으로 한 번 바뀐다](./figs/concept-verdict-line.svg)

판정이 **거짓에서 참으로 한 번만 바뀝니다.** `m` 을 키우면 앞에서 된 나눔이 그대로 통하니, 한 번 참이
된 뒤로 거짓으로 돌아갈 일이 없어요. 그리고 처음 참이 되는 값 18 이 바로 답입니다. 경계가 하나뿐이니
후보값을 하나씩 물어볼 필요가 없습니다. 이진 탐색처럼 후보 구간의 한가운데를 판정해 한쪽 절반을
통째로 빼면 돼요.

<!--proof:concept-halving-->

```text
후보값 23 → 11 → 5 → 2 → 1 → 0 개
판정 5 번으로 후보가 비고, 답은 18 이다
```

후보값 23 개가 판정 한 번마다 절반 이하로 줄어서 다섯 번 만에 비었습니다. 이 방법을 **파라메트릭 이진
탐색**이라고 부릅니다. 파라메트릭(parametric)은 답을 매개변수 `m` 으로 두고 묻는다는 뜻이에요. 배열
길이를 `N` 이라 하면 판정 한 번이 배열을 한 번 순회하니, 비용은 결과만 적으면 `O(N log(ΣA))` 입니다. 이
절차가 성립하려면 조건이 둘 필요합니다.

| 조건 | 쓰이는 곳 | 깨지면 |
| --- | --- | --- |
| 판정이 `m` 에 대해 거짓에서 참으로 한 번만 바뀐다 | 한가운데 하나를 판정하고 한쪽 절반을 통째로 뺀다 | 뺀 쪽에 답이 있을 수 있어 답이 틀린다 |
| 판정 한 번이 답을 직접 만드는 것보다 비용이 훨씬 작다 | 판정 횟수 × 판정 비용이 전체 비용이 된다 | 되묻는 쪽이 오히려 느려져 얻는 것이 없다 |

이 글이 다루는 과제에서는 원소가 음이 아니라서 판정이 한 번만 바뀌고, 판정이 배열을 한 번 순회하는 것으로
끝나서 답을 직접 만드는 것보다 비용이 작습니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **이진 탐색의 뼈대** — 후보를 폐구간 `[lo, hi]` 로 두고, 한 칸을 확인해 한쪽을 통째로 빼고,
  후보가 빌 때까지 되풀이하는 절차. 정렬된 배열 위에서 그것이 어떻게 성립하는지는
  [이진 탐색 가이드](../binarySearch/binarySearch-guide.md)에 있습니다.
- **단조 술어** — 값이 커질 때 참·거짓이 **한 번만** 바뀌는 물음. 이진 탐색 가이드의 마지막 개념
  절이 이 이름을 소개합니다. 이 글의 전부가 「우리가 만든 물음이 단조인가」에 달려 있어요.
- **탐욕 순회** — 앞에서부터 지금 결정할 수 있는 것만 정하고 뒤로 되돌아가지 않는 방식.
  같은 방식을 창 하나로 쓰는 예가
  [합이 제한 이하인 가장 긴 부분 배열 가이드](../../array/longestSubarrayAtMostSum/longestSubarrayAtMostSum-guide.md)에
  있습니다.
- **폐구간 표기** — `[a,b]` 는 양 끝을 포함합니다. 이 글에서 `[10,32]` 는 10 과 32 를 포함한
  값 23 개예요.

두 번째가 흐릿하면 이 글의 절반이 어긋납니다. 「판정이 단조다」가 참이 아니면 절반을 빼는
근거가 없고, 그 순간 이 절차는 아무것도 보장하지 않아요.

### 아이디어를 떠올리는 과정 — 나눔 전부 만들기에서 판정 함수로 답의 후보 구간 절반 줄이기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 배열과 묶음 수를 받아서,
나올 수 있는 가장 작은 최댓값을 돌려줍니다.

```ts
function parametricBinarySearch(A: number[], K: number): number;
```

- 입력: **음이 아닌** 정수 배열 `A` 와 나눌 묶음 수 `K`. 묶음은 연속한 칸의 모임이고 비어 있으면
  안 됩니다.
- 출력: `A` 를 묶음 `K` 개로 나누는 모든 방법 가운데, 묶음 합의 최댓값이 가장 작은 나눔의 그 최댓값.
- 규모: 배열 길이 `N` 은 1 이상 `10^5` 이하, 원소는 0 이상 `10^6` 이하, `K` 는 1 이상 `N`
  이하입니다. 비용은 흔한 채점 환경의 예산인 1 초에 대어, 단순 연산을 초당 1 억 번으로 잡고 잽니다.

규모를 곱해 보면 값의 크기가 먼저 눈에 들어옵니다. 원소의 합 `ΣA` 가 최대 `10^5 × 10^6 = 10^11` 이라
답이 32비트 정수 범위를 넘어요. 칸 수와 값의 크기가 따로 움직인다는 것이 뒤에서 갈림점이
됩니다. 이 글이 쓰는 기호는 열이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `N` | 배열 `A` 의 길이 | `1 ≤ N ≤ 10^5` |
| `A` | 음이 아닌 정수 배열. `A[i]` 가 `i` 번째 값 | `0 ≤ A[i] ≤ 10^6` |
| `K` | 나눌 묶음 수. 묶음은 연속한 칸의 모임이고 비어 있으면 안 된다 | `1 ≤ K ≤ N` |
| `m` | 후보값 하나. 판정 함수에 묻는 값 | `max(A) ≤ m ≤ ΣA` |
| `m*` | 답. 판정이 참이 되는 가장 작은 `m` | `max(A) ≤ m* ≤ ΣA` |
| `g(m)` | 묶음 합이 `m` 이하가 되게 나눌 때 필요한 **최소** 묶음 수 | `1 ≤ g(m) ≤ N` |
| `S` | 후보값 개수 `ΣA − max(A) + 1` | `1 ≤ S ≤ 10^11` |
| `lo` · `hi` | 후보 구간의 왼쪽 끝 · 오른쪽 끝. 양 끝을 포함한다 | 처음에 `lo = max(A)`, `hi = ΣA` |
| `mid` | 이번에 판정할 후보값 | `lo ≤ mid ≤ hi` |
| `count` · `accSum` | 판정 함수의 상태 — 지금까지 만든 묶음 수 · 지금 묶음의 합 | `1 ≤ count`, `0 ≤ accSum ≤ m` |

가장 먼저 떠오르는 방법은 나눌 자리를 전부 고르는 것입니다. 자리를 정하면 묶음이 정해지고, 묶음이
정해지면 최댓값이 나오니 그중 가장 작은 것을 고르면 돼요.

```ts
function splitNaive(A: number[], K: number): number {
  const N = A.length;
  let best = Number.POSITIVE_INFINITY;
  // 칸 사이 N-1 곳 중 K-1 곳을 고르는 모든 방법을 만든다.
  const choose = (start: number, left: number, cuts: number[]): void => {
    if (left === 0) {
      let prev = 0;
      let worst = 0;
      for (const b of [...cuts, N]) {
        let sum = 0;
        for (let i = prev; i < b; i++) sum += A[i] as number;
        worst = Math.max(worst, sum);
        prev = b;
      }
      best = Math.min(best, worst);
      return;
    }
    for (let i = start; i <= N - left; i++) choose(i + 1, left - 1, [...cuts, i]);
  };
  choose(1, K - 1, []);
  return best;
}
```

이 방법은 답을 틀리지 않습니다. 비용은 **만드는 나눔의 수**로 세는데, 칸 사이 `N − 1` 곳에서 `K − 1`
곳을 고르는 가짓수 `C(N−1, K−1)` 이라 `K` 가 절반쯤일 때 가장 많아요.

<!--proof:origin-split-count-->

| N | K | 나눔 가짓수 | 초당 1 억 개를 만들 때 |
| ---: | ---: | ---: | ---: |
| 5 | 2 | 4 | 0.01 초 미만 |
| 20 | 10 | 92,378 | 0.01 초 미만 |
| 40 | 20 | 68,923,264,410 | 689.23 초 |
| 100,000 | 50,000 | 30,101 자리 수 | — |

N = 5 · 20 두 줄은 나눔을 실제로 만들어 센 수가 식 C(N−1, K−1) 과 같았고, 가장 작은 최댓값도 정본의 답과 같았습니다. 아래 두 줄은 식으로 셌습니다.

<!--/proof-->

`N = 40` 에서 이미 689 억 가지이고, 초당 1 억 개를 만들어도 689 초입니다. 과제의 규모 `N = 10^5` 에서는
가짓수가 3 만 자리를 넘는 수라 비교할 것도 없어요.

나눔을 겹치지 않게 모아 세는 방법도 있습니다. 앞 `i` 칸을 `j` 묶음으로 나눈 최적값을 표에 적고,
마지막 묶음이 시작하는 분할점을 전부 시험해 표를 채우는 동적 계획법이에요. 가짓수는 크게 줄지만
분할점을 시험하는 횟수가 `N` 과 `K` 에 함께 붙습니다.

<!--proof:origin-dp-count-->

```text
N = K = 100,000 이면 분할점 시험 166,671,666,700,000 번
초당 1 억 번이면 1,666,716.67 초 — 19.3 일
└ 이 식은 N = 300, K = 30 에서 실제로 센 1,228,060 번과 같다
```

나열보다는 훨씬 적지만 19 일이 넘게 걸려 예산 1 초와는 거리가 멉니다. 두 방법이 막힌 자리는 같아요.
**나눔을 직접 만들려 했다**는 것입니다. 그러면 방향을 바꿔서, 나눔을 만드는 대신 **답이 될 값 하나를
놓고 되물어** 봅시다. 「최댓값을 가장 작게 만드는 나눔은 무엇인가」 대신 「최댓값이 `m` 이하인 나눔이
있는가」를 묻는 것이에요. 앞의 네 나눔을 `m = 18` 과 `m = 17` 에 넣어 보면 이렇습니다.

<!--proof:origin-flip-->

| 나눔 | 묶음 합 | 최댓값 | 18 이하 여부 | 17 이하 여부 |
| --- | --- | ---: | --- | --- |
| 7 │ 2 5 10 8 | 7 · 25 | 25 | 아니오 | 아니오 |
| 7 2 │ 5 10 8 | 9 · 23 | 23 | 아니오 | 아니오 |
| 7 2 5 │ 10 8 | 14 · 18 | 18 | 예 | 아니오 |
| 7 2 5 10 │ 8 | 24 · 8 | 24 | 아니오 | 아니오 |

「예」가 m = 18 에서 1 개, m = 17 에서 0 개입니다.

<!--/proof-->

18 이하인 나눔은 있고 17 이하인 나눔은 없으니, 답은 18 입니다. 되묻기가 답으로 이어지려면 두 가지가
필요해요. 하나는 **되묻는 비용이 작은 방법**이고, 다른 하나는 **어떤 `m` 을 물을지 고르는 방법**입니다.

앞의 것은 나눔을 전부 만들지 않고도 됩니다. 묶음 합이 `m` 을 넘지 않는 한 지금 묶음에 계속 이어 붙이고
넘칠 때만 새 묶음을 시작하면, 배열을 한 번 순회해 필요한 최소 묶음 수 `g(m)` 이 나와요. `g(m) ≤ K` 이면
참입니다. 이렇게 센 수가 왜 최소인지는 다음 절의 2단계에서 값으로 확인하고, 여기서는 판정 한 번의
비용을 배열 한 번 순회하기로 둡니다. 그러면 이 절차의 비용은 **판정 횟수**로 정해져요. 같은 입력에 두
방식을 걸고 판정 횟수를 세어 봅시다. 한 방식은 아래 끝 10 부터 1 씩 올리며 처음 참이 나올 때까지
묻고, 다른 방식은 후보 구간 `[10,32]` 의 한가운데를 물어 참이면 위쪽을, 거짓이면 아래쪽을 뺍니다.

<!--proof:origin-oneup-vs-half-->

| 판정 횟수 | 1 씩 올리는 쪽 | 한가운데를 판정하는 쪽 |
| ---: | --- | --- |
| 1 | m = 10 거짓 | [10,32] 에서 21 참 → [10,20] |
| 2 | m = 11 거짓 | [10,20] 에서 15 거짓 → [16,20] |
| 3 | m = 12 거짓 | [16,20] 에서 18 참 → [16,17] |
| 4 | m = 13 거짓 | [16,17] 에서 16 거짓 → [17,17] |
| 5 | m = 14 거짓 | [17,17] 에서 17 거짓 → 후보가 빈다 |
| 6 | m = 15 거짓 | — |
| 7 | m = 16 거짓 | — |
| 8 | m = 17 거짓 | — |
| 9 | m = 18 참 | — |

1 씩 올리는 쪽은 9 번, 한가운데를 판정하는 쪽은 5 번 판정했고, 답은 둘 다 18 입니다.

<!--/proof-->

두 방식이 내는 답도, 판정하는 함수도 같은데 판정 횟수가 9 와 5 로 갈립니다. 여기서 관찰한 것은
하나예요. **한 번 판정하고 후보에서 뺄 수 있는 값의 수**가 비용을 정합니다. 2 번째 판정에서 15 가
거짓일 때 10 부터 15 까지를 한꺼번에 뺄 수 있었던 근거는, `m` 이 작아질수록 필요한 묶음 수가 늘거나
그대로라는 것이에요. 후보값마다 최소 묶음 수를 세어 보면 그렇습니다.

<!--proof:origin-group-steps-->

| 최소 묶음 수 | 그 값이 나오는 m |
| ---: | --- |
| 4 | 10 ~ 13 |
| 3 | 14 ~ 17 |
| 2 | 18 ~ 31 |
| 1 | 32 |

m 이 커질 때 최소 묶음 수는 4 → 3 → 2 → 1 로 줄기만 하고, 2 이하로 처음 내려가는 m 은 18 입니다.

<!--/proof-->

최소 묶음 수가 줄기만 하니 「`g(m) ≤ 2` 인가」도 거짓에서 참으로 한 번만 바뀌고, 그 경계 18 이
답이에요. **가장 단순한 후보부터 시험해 봅시다.** 경계가 하나뿐이면 「아래 끝부터 1 씩 올리며 처음
참이 되는 자리를 찾자」가 곧바로 떠오릅니다. 위에서 9 번이 나온 방식이에요. 전개 입력과, 제약 규모의
입력에서 판정 횟수를 세면 이렇습니다.

<!--proof:origin-probe-count-->

| 후보값을 고르는 방식 | N = 5 | N = 100,000 |
| --- | ---: | ---: |
| 1 씩 올리며 판정한다 | 9 | 470,963,502 |
| 후보 구간을 반씩 접는다 | 5 | 36 |
| 후보값은 모두 몇 개인가 | 23 | 47,162,150,002 |

큰 입력은 A[i] = 37i mod 10^6, K = 100 입니다. 1 씩 올리는 쪽은 판정마다 100,000 칸을 순회하니 47,096,350,200,000 칸을 순회합니다.

<!--/proof-->

후보값이 23 개에서 471 억 개가 되자, 1 씩 올리는 쪽은 4 억 7 천만 번을 판정합니다. 판정마다 10 만
칸을 순회하니 1 초 안에 끝날 수가 없어요. 반씩 접는 쪽은 5 번에서 36 번으로 늘었을 뿐입니다. 지금까지
해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **판정 함수로 답의 후보 구간 절반 줄이기**입니다. 답이 놓일 수 있는 값을
후보 구간 `[max(A), ΣA]` 로 두고, 그 한가운데 값을 판정 함수에 물어 답일 수 없는 쪽을 통째로 빼는 일을
후보가 빌 때까지 되풀이해요. 판정 함수가 무엇이고 어떻게 만드는지, 후보 구간의 두 끝을 왜 그렇게
잡는지, 답을 어디서 읽는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 판정 함수로 답의 후보 구간 절반 줄이기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **답이 놓일 수 있는 값을 후보 구간 `[lo, hi]` 로 두고,
한가운데 값 `mid` 를 판정 함수에 물어 답일 수 없는 쪽을 빼는 일을 후보가 빌 때까지 되풀이한 뒤 `lo` 를
답으로 읽습니다.** 이 방법이 기대는 낯선 개념은 판정 함수 하나라 그것부터 풀고, 실현하는 순서대로 세
단계를 설명합니다. 1단계는 한 번만 하고, 3단계가 바퀴마다 2단계의 판정 함수를 부릅니다.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 후보 구간 정하기 | 답이 놓일 수 있는 값 `[max(A), ΣA]` 를 후보로 잡는다 | — |
| 2단계 판정 함수 만들기 | 후보값 `m` 하나에 「`g(m) ≤ K` 인가」를 배열 한 번 순회해 답한다 | 1단계가 정한 `m` 의 범위 `m ≥ max(A)` |
| 3단계 판정으로 후보 구간 줄이기 | `mid` 를 판정해 한쪽을 빼고, 후보가 비면 `lo` 를 돌려준다 | 1단계의 `lo` · `hi`, 2단계의 판정 함수 |

#### 먼저 알아 둘 개념 — 판정 함수

이진 탐색은 배열의 칸을 읽었는데, 여기서 읽는 것은 **후보값 하나에 대한 판정**입니다. 배열이 없는
자리에서 무엇을 읽는지가 이 글에서 가장 낯선 부분이라, 판정 함수를 여섯 가지 면에서 봅니다.

##### 판정 함수의 뜻

판정 함수는 **후보값 `m` 하나를 받아 「답이 `m` 이하일 수 있는가」를 참·거짓으로 답하는 함수**입니다.
이 과제에서는 그 물음이 「묶음 합이 모두 `m` 이하가 되게 `K` 개 이하로 나눌 수 있는가」이고, 식으로
적으면 `feasible(m) = [ g(m) ≤ K ]` 예요. 답 `m*` 는 판정이 참이 되는 가장 작은 `m` 입니다.

##### 후보값 줄 위의 판정

전개 입력 `A = [7 2 5 10 8]`, `K = 2` 의 후보값 23 개마다 `g(m)` 과 판정을 적으면 이렇습니다.

<!--fig:build-verdict-rows-->
![후보값마다 최소 묶음 수 g(m) 과 판정 g(m) ≤ 2](./figs/build-verdict-rows.svg)

칸 하나가 후보값 하나를 맡습니다. 배열의 칸이 아니라 **값 하나하나가 칸**이고, 칸에 적힌 것은 그
값으로 나눌 수 있는지의 판정이에요.

##### 판정 하나를 읽는 법

`m = 18` 칸 하나를 골라 판정이 어디서 나오는지 따라가 보겠습니다.

<!--proof:build-read-one-->

```text
m = 18
  왼쪽부터 이어 붙인 묶음   7 2 5 │ 10 8
  묶음 합                   14 · 18
  묶음 수 g(m)              2
  g(m) ≤ K = 2              참 → 답은 18 이하다
```

18 칸의 「참」은 「18 이하로 나눌 수 있다」, 곧 **답이 18 이하**라는 뜻입니다. 「답이 18 이다」가
아니라는 점을 기억해 두세요. 21 칸도 참인데, 답이 21 이라는 뜻이 아닌 것과 같아요.

##### 이웃한 후보값 사이의 관계

이웃한 두 칸 `m` 과 `m + 1` 을 보면, `m` 에서 된 나눔은 `m + 1` 에서도 그대로 됩니다. 묶음 합이 모두
`m` 이하면 `m + 1` 이하이기도 하니까요. 그래서 `g(m + 1) ≤ g(m)` 이고, 앞 절에서 센 최소 묶음 수가
4 → 3 → 2 → 1 로 줄기만 한 것이 그 모습입니다. 판정 줄은 한 번 참이 되면 오른쪽 끝까지 참이에요. 위
그림에서도 거짓 여덟 칸 뒤에 참이 끝까지 이어집니다.

##### 「답이 m 인가」와의 대조

처음 떠올리기 쉬운 물음은 「답이 `m` 인가」입니다. 같은 후보값 줄에 두 물음을 나란히 적으면 모양이
다릅니다.

<!--fig:build-exact-vs-atmost-->
![같은 후보값 줄에 두 물음 — 「답이 m 이하인가」와 「답이 m 인가」](./figs/build-exact-vs-atmost.svg)

「답이 `m` 인가」는 18 한 칸만 「예」이고 나머지가 모두 「아니오」예요. 한가운데 21 을 읽었을 때 두
물음이 빼 주는 후보값을 세어 보면 차이가 값으로 나옵니다.

<!--proof:build-one-read-removes-->

| 물음 | 21 에서의 답 | 뺄 수 있는 후보값 | 남는 후보값 수 |
| --- | --- | --- | ---: |
| 답이 21 이하인가 | 예 | 22 ~ 32 | 12 |
| 답이 21 인가 | 아니오 | 21 | 22 |

후보값 23 개에서 「이하인가」는 11 개를, 「인가」는 1 개를 뺍니다.

<!--/proof-->

「답이 21 인가」에 「아니오」가 나오면 21 하나만 빠지고, 답이 21 보다 작은지 큰지는 알 수 없어요.
「답이 21 이하인가」에 「예」가 나오면 22 부터 32 까지가 한꺼번에 빠집니다.

##### 판정 함수가 이렇게 생긴 까닭

이진 탐색이 한 칸을 읽고 한쪽 전체를 빼려면, 읽은 칸의 답이 그 칸 한쪽의 값 전부에 대해서도 말해
줘야 합니다. 정렬된 배열에서는 정렬이 그 일을 했고, 여기서는 판정을 「`m` **이하**로 되는가」로 묻는
것이 그 일을 해요. 「이하」로 물으면 `m` 이 커질수록 쉬워지는 물음이 되어 판정 줄이 한 번만 바뀌고,
「인가」로 물으면 그 성질이 사라집니다.

> 판정은 「답이 m 인가」가 아니라 「답이 m 이하일 수 있는가」로 묻는다.

#### 1단계 — 후보 구간 정하기

후보 구간은 답이 놓일 수 있는 값 전체입니다. 아래 끝은 `max(A)` 예요. 어떤 나눔이든 가장 큰 원소는
어느 묶음엔가 들어가고, 원소가 음이 아니니 그 묶음의 합은 그 원소보다 작을 수 없어요. 위 끝은 `ΣA`
입니다. 묶음 합 하나는 전체 합을 넘을 수 없고, 전부를 한 묶음으로 둔 나눔이 늘 있어요. 전개 입력에서는
이렇습니다.

<!--fig:build-candidates-->
![후보 구간 [max(A), ΣA] = [10,32] — 답이 놓일 수 있는 값 전체](./figs/build-candidates.svg)

후보값 개수는 `S = ΣA − max(A) + 1` 이고, 전개 입력에서 `32 − 10 + 1 = 23` 입니다. 배열 몇 벌에서 두
끝과 개수를 세어 보면 이렇습니다.

<!--proof:build-bounds-->

| 배열 | max(A) | ΣA | 후보값 개수 |
| --- | ---: | ---: | ---: |
| [7 2 5 10 8] | 10 | 32 | 23 |
| [5 5 5 5 5] | 5 | 25 | 21 |
| [1 1 1 1000000] | 1,000,000 | 1,000,003 | 4 |
| 값이 전부 10^6 · N = 100,000 | 1,000,000 | 100,000,000,000 | 99,999,000,001 |

마지막 줄의 ΣA 100,000,000,000 은 32비트 정수의 최댓값 2,147,483,647 보다 큽니다.

<!--/proof-->

`[1 1 1 1000000]` 처럼 한 칸만 큰 배열은 값이 100 만인데도 후보값이 넷뿐이에요. 큰 값 하나가 두 끝을
함께 올리기 때문입니다. 반대로 값이 전부 `10^6` 인 `10^5` 칸이면 후보값이 1000 억 개에 가깝고, 위 끝이
32비트를 넘으므로 `lo` · `hi` · `mid` 는 그만큼을 담는 수로 다뤄야 해요. 아래 끝을 `max(A)` 보다 낮게
잡으면 어떻게 되는지는 판정 함수를 만든 뒤에 볼 수 있어서, 「수행으로 알아보는 알고리즘」의 짚고
가기에서 실행 결과로 확인합니다.

#### 2단계 — 판정 함수 만들기

판정 함수는 후보값 `m` 이 정해지면 배열을 왼쪽부터 한 번 순회합니다. 상태는 둘이에요. 지금까지 만든
묶음 수 `count` 와 지금 묶음의 합 `accSum` 입니다. 처음에는 첫 묶음이 이미 열려 있으니 `count = 1`,
`accSum = 0` 이에요. 원소 `x` 마다 `accSum + x` 가 `m` 을 넘으면 새 묶음을 열고(`count` 를 1 올리고
`accSum` 을 0 으로), 그다음 `accSum` 에 `x` 를 더합니다. 쉬운 칸은 지금 묶음에 그냥 들어가는 칸이고,
불안한 칸은 새 묶음을 여는 칸이에요. `m = 18` 과 `m = 17` 에서 칸마다 상태를 적으면 이렇습니다.

<!--proof:build-greedy-states-->

m = 18 로 판정하면 이렇습니다.

| x | accSum + x | 18 과 비교 | count | accSum |
| ---: | --- | --- | ---: | ---: |
| 7 | 0 + 7 = 7 | 안 넘는다 | 1 | 7 |
| 2 | 7 + 2 = 9 | 안 넘는다 | 1 | 9 |
| 5 | 9 + 5 = 14 | 안 넘는다 | 1 | 14 |
| 10 | 14 + 10 = 24 | 넘는다 → 새 묶음 | 2 | 10 |
| 8 | 10 + 8 = 18 | 안 넘는다 | 2 | 18 |

m = 17 로 판정하면 이렇습니다.

| x | accSum + x | 17 과 비교 | count | accSum |
| ---: | --- | --- | ---: | ---: |
| 7 | 0 + 7 = 7 | 안 넘는다 | 1 | 7 |
| 2 | 7 + 2 = 9 | 안 넘는다 | 1 | 9 |
| 5 | 9 + 5 = 14 | 안 넘는다 | 1 | 14 |
| 10 | 14 + 10 = 24 | 넘는다 → 새 묶음 | 2 | 10 |
| 8 | 10 + 8 = 18 | 넘는다 → 새 묶음 | 3 | 8 |

g(18) = 2, g(17) = 3 이고, K = 2 와 비교하면 18 은 참, 17 은 거짓입니다.

<!--/proof-->

x = 10 에서 두 경우 모두 새 묶음을 열었어요. 0 으로 되돌린 뒤에 더하므로 `accSum` 이 10 이 되어, 새
묶음의 첫 값이 `x` 하나가 됩니다. 17 에서는 x = 8 에서 `10 + 8 = 18` 이 17 을 넘어 한 번 더 새 묶음을
열었고 `count` 가 3 이 되었어요. 원소마다 `accSum` 에 더하는 줄이 정확히 한 번씩 실행되고, 새 묶음을
여는 갈래에서도 `x` 를 건너뛰지 않습니다. 그래서 순회가 끝나면 모든 원소가 정확히 한 번씩 어느
묶음엔가 들어가 있고, `count` 를 묶음 수로 읽을 수 있어요.

남은 질문은 이렇게 센 묶음 수가 정말 **최소**인가입니다. `m = 18` 에서 탐욕이 만든 묶음과, 합이 모두
18 이하인 다른 나눔을 한 줄에 그려 보겠습니다.

<!--fig:build-greedy-ahead-->
![m = 18 — 탐욕이 만든 묶음과 다른 나눔의 묶음](./figs/build-greedy-ahead.svg)

두 나눔이 묶음 번호마다 몇 칸까지 담았는지 세면 이렇습니다.

<!--proof:build-greedy-ahead-->

| 묶음 번호 | 탐욕이 담은 칸 | 다른 나눔이 담은 칸 |
| ---: | --- | --- |
| 1 | 3 칸 | 2 칸 |
| 2 | 5 칸 | 4 칸 |
| 3 | — | 5 칸 |

m = 18 에서 탐욕의 경계가 매번 같거나 더 뒤에 있고, 묶음은 탐욕이 2 개, 다른 나눔이 3 개입니다.

<!--/proof-->

탐욕은 넘치기 전까지 계속 담으니 첫 묶음에 담는 칸 수가 어떤 나눔보다 적지 않습니다. 첫 경계가 같거나
뒤에 있으면 2 번 묶음은 같거나 더 뒤에서 시작하고, 원소가 음이 아니니 늦게 시작한 묶음이 같은 자리까지
담은 합은 같거나 작아요. 그러니 2 번 경계도 같거나 뒤에 있고, 같은 이유가 묶음마다 이어집니다. 탐욕의
경계가 한 번도 뒤처지지 않으니 묶음 수가 더 많아질 수 없어요. 후보값 전부에서 이것을 나눔을 전부 만들어
확인했습니다.

<!--proof:build-greedy-min-->

후보값 23 개 모두에서, 탐욕 순회가 센 묶음 수와 합이 m 이하인 나눔을 전부 만들어 찾은 최소 묶음 수를 비교했습니다. 둘이 어긋난 후보값은 0 개입니다.

<!--/proof-->

마지막으로 판정을 `g(m) = K` 가 아니라 `g(m) ≤ K` 로 적는 까닭이 있습니다. 묶음이 `K` 보다 적게
나왔으면 아무 묶음이나 더 잘라 개수를 `K` 로 맞출 수 있고, 원소가 음이 아니라 자른 묶음의 합은
작아지거나 그대로예요. `m = 18` 에서 `K` 를 2 부터 5 까지 올리며 확인하면 이렇습니다.

<!--proof:build-split-more-->

| K | 판정(m = 18) | K 개로 더 자른 나눔 | 최댓값 |
| ---: | --- | --- | ---: |
| 2 | 참 | 7 2 5 │ 10 8 | 18 |
| 3 | 참 | 7 │ 2 5 │ 10 8 | 18 |
| 4 | 참 | 7 │ 2 │ 5 │ 10 8 | 18 |
| 5 | 참 | 7 │ 2 │ 5 │ 10 │ 8 | 10 |

묶음을 더 잘라도 최댓값은 가장 커야 18 이라 18 을 넘지 않습니다.

<!--/proof-->

#### 3단계 — 판정으로 후보 구간 줄이기

후보 구간 `[lo, hi]` 의 한가운데를 `mid = lo + ⌊(hi − lo) / 2⌋` 로 정하고 판정 함수에 묻습니다.
한가운데를 고르는 까닭과 `lo` 를 기준으로 더하는 까닭은
[이진 탐색 가이드](../binarySearch/binarySearch-guide.md)에서 본 것과 같아요. 판정 결과에 따라 갈래가
둘입니다.

| 판정 | 빼는 후보값 | 뺄 수 있는 까닭 | 새 후보 구간 |
| --- | --- | --- | --- |
| 참 ① | `mid` 부터 `hi` 까지 | `mid` 로 나눌 수 있으니 답은 `mid` 이하다 | `[lo, mid − 1]` |
| 거짓 ② | `lo` 부터 `mid` 까지 | 판정이 한 번만 바뀌니 `mid` 이하는 전부 거짓이다. 답은 `mid` 보다 크다 | `[mid + 1, hi]` |

참인 갈래에서 `mid` 자체도 빼는 것이 눈여겨볼 자리입니다. 참이면 `mid` 가 답**일 수도** 있는데
후보에서 빼요. 그래도 답을 잃지 않는지 바퀴마다 확인해 보겠습니다.

<!--proof:build-shrink-->

| 후보 | mid | g(mid) | 판정 | 새 후보 | 새 후보 수 | 새 후보에서 18 의 자리 |
| --- | ---: | ---: | --- | --- | ---: | --- |
| [10,32] | 21 | 2 | 참 → ① | [10,20] | 11 | 안 |
| [10,20] | 15 | 3 | 거짓 → ② | [16,20] | 5 | 안 |
| [16,20] | 18 | 2 | 참 → ① | [16,17] | 2 | 밖 |
| [16,17] | 16 | 3 | 거짓 → ② | [17,17] | 1 | 밖 |
| [17,17] | 17 | 3 | 거짓 → ② | 비었다 | 0 | 밖 |

3 번째 바퀴에서 18 이 참으로 판정되어 후보 밖으로 나가고, 반복이 끝날 때 lo = 18 입니다.

<!--/proof-->

3 번째 바퀴에서 답 18 이 후보 밖으로 나갔는데, 그 뒤 16 과 17 이 거짓으로 판정되면서 `lo` 가 17, 18 로
올라와 답에 도달했어요. `hi` 는 참으로 판정된 가장 작은 값 바로 아래에 머물고, `lo` 는 거짓으로 판정된
가장 큰 값 바로 다음으로 오릅니다. 그래서 후보가 비는 순간 `lo` 는 거짓의 끝 다음 값, 곧 참이 시작하는
값에 놓여요. 반복이 끝나는 자리는 `lo > hi` 하나뿐이고, 그때 `lo` 를 답으로 돌려줍니다. 후보는 바퀴마다
적어도 하나 줄어들므로 많아야 `S` 바퀴 안에 끝나요.

#### 이 방법이 기대는 전제

파라메트릭 이진 탐색은 아래 세 전제가 있어야 성립합니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 원소가 음이 아니다 | 1단계의 아래 끝 `max(A)`, 2단계에서 탐욕이 최소라는 것과 `g(m) ≤ K` 로 충분하다는 것 | 아래 끝이 답보다 커지거나 탐욕이 묶음을 더 많이 센다 |
| 판정이 `m` 에 대해 거짓에서 참으로 한 번만 바뀐다 | 3단계에서 한쪽을 통째로 뺀다 | 뺀 쪽에 답이 있을 수 있다 |
| 판정하는 `m` 이 `max(A)` 이상이다 | 2단계가 원소 하나가 이미 `m` 을 넘는 경우를 따로 걸러 내지 않는다 | 판정이 뜻을 잃어 참이 잘못 나온다 |

음수가 섞인 배열을 넣으면 정본이 오류 없이 틀린 답을 냅니다. 나눔을 전부 만들어 낸 답과 비교하면
이렇습니다.

<!--proof:premise-negative-->

| 배열 | K | 정본의 답 | 나눔을 전부 만든 답 | 먼저 깨지는 것 |
| --- | ---: | ---: | ---: | --- |
| [5 -1 -2] | 2 | 5 | 4 | 답 4 가 아래 끝 max(A) = 5 보다 작다 |
| [3 6 4 -3] | 1 | 11 | 10 | m = 10 에서 한 묶음이면 되는데 탐욕은 묶음 2 개로 센다 |

`[5 -1 -2]` 를 두 묶음으로 나누면 `5 -1 │ -2` 의 최댓값 4 가 답인데, 후보 구간이 5 에서 시작해 4 를
볼 수조차 없어요. `[3 6 4 -3]` 을 한 묶음으로 두면 합이 10 인데, 탐욕은 `3 6` 다음에 4 를 붙이면 13 이
되어 10 을 넘으니 새 묶음을 엽니다. 뒤에 올 `-3` 이 합을 다시 줄인다는 것을 모르기 때문이에요. 세 번째
전제가 깨진 모습은 「수행으로 알아보는 알고리즘」의 「짚고 가기 — 아래 끝을 0 으로 잡아도 어떤
입력에서는 답이 그대로 나온다」에서 실행 결과로 볼 수 있습니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 네 걸음이 됩니다. 걸음 2 와 3 이 반복 한 바퀴예요.

1. 배열을 한 번 순회해 `lo = max(A)`, `hi = ΣA` 로 후보 구간을 잡는다
2. `lo ≤ hi` 인 동안 `mid = lo + ⌊(hi − lo) / 2⌋` 를 정하고 판정 함수에 묻는다
3. 참이면 `hi = mid − 1`, 거짓이면 `lo = mid + 1` 로 줄인다
4. 후보가 비면 `lo` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 다섯 칸을 두 묶음으로 나누는 가장 작은 최댓값을 찾는다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다
그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const A = [7, 2, 5, 10, 8];
const K = 2;
// 이 절이 끝나면 18 이 나와야 한다
```

`K` 를 왜 하필 2 로 뒀을까요? 갈래 셋을 **모두 실행하게** 하려는 것입니다. 판정이 참인 값과 거짓인
값이 둘 다 나와야 갈래 ① 과 ② 를 볼 수 있고, 판정 안에서 새 묶음을 여는 갈래 ③ 은 `K = 2` 라 반드시
실행돼요. 답이 후보 구간의 위 끝인 경우는 2 로는 안 나오므로, 4 번 걸음 끝에서 `K = 1` 을 한 번 더
넣습니다.

```text
parametricBinarySearch(A, K):
    lo ← max(A),  hi ← ΣA
    lo <= hi 인 동안:
        mid ← lo + ⌊(hi - lo) / 2⌋
        feasible(A, K, mid) 이면  hi ← mid - 1     ① 이 값으로 된다
        아니면                    lo ← mid + 1     ② 이 값으로는 안 된다
    lo 를 반환한다

feasible(A, K, m):
    count ← 1,  accSum ← 0
    A 의 각 원소 x 에 대해:
        accSum + x > m 이면  count ← count + 1,  accSum ← 0    ③ 새 묶음을 시작한다
        accSum ← accSum + x
    count <= K 를 반환한다
```

#### 1. 후보 구간을 답이 놓일 수 있는 값 전체로 잡는다

아래 끝은 `max(A)`, 위 끝은 `ΣA` 입니다. 둘 다 배열을 순회해야 나오는 값이라, 한 번 순회하면서 함께
구합니다.

```ts
let lo = 0;
let hi = 0;
for (const x of A) {
  if (x > lo) lo = x;
  hi += x;
}
```

실행하면 이렇게 나옵니다. 순회 한 번으로 둘을 함께 구하는 것이 이 네 줄의 두 번째 일이에요.

<!--proof:walk-init-->

```text
A = [7 2 5 10 8]   →   lo = 10,   hi = 32,   후보값 23 개
A = [5 5 5 5 5]    →   lo = 5,    hi = 25,   후보값 21 개
A = [0 0 0 0]      →   lo = 0,    hi = 0,    후보값 1 개
```

값이 전부 0 이면 두 끝이 같아 후보값이 하나뿐이고, 판정 한 번으로 끝납니다.

#### 짚고 가기 — 아래 끝을 0 으로 잡아도 어떤 입력에서는 답이 그대로 나온다

「아래 끝을 `max(A)` 로 올리는 것은 판정 횟수를 줄이는 최적화일 뿐이고, 0 으로 두어도 답은 같겠지」라고
생각하기 쉬운데 그렇지 않습니다. 전개가 쓰는 입력에서는 정말 같은 값이 나와서 더 그래요. `lo` 를 올리는
줄을 지우고 실행해 봅니다.

```ts
for (const x of A) {
  // if (x > lo) lo = x;   ← 이 줄을 지웠다. lo 가 0 에 남는다
  hi += x;
}
```

실행하면 이렇게 나옵니다.

<!--proof:lower-bound-->

| 배열 | K | 바른 코드 | 아래 끝을 0 으로 둔 코드 |
| --- | ---: | ---: | ---: |
| [10 0 0] | 3 | 10 | 0 |
| [1 4 4] | 3 | 4 | 1 |
| [3 5] | 2 | 5 | 3 |
| [7 2 5 10 8] | 2 | 18 | 18 |

네 벌 중 3 벌에서 답이 바뀝니다.

<!--/proof-->

`[7 2 5 10 8]` 에서는 두 코드가 똑같이 18 을 줍니다. 그런데 `[10 0 0]` 을 세 묶음으로 나누면 바른
코드는 10 을, 아래 끝을 0 으로 둔 코드는 **0** 을 줘요. 왜 그런지는 판정 함수를 `m = 0` 에 적용해 보면
확인됩니다.

<!--proof:lower-bound-trace-->

```text
[10 0 0] 에 m = 0 으로 판정하면
  x = 10   0 + 10 = 10 > 0   → 새 묶음,   count = 2,   accSum = 10
  x = 0    10 + 0 = 10 > 0   → 새 묶음,   count = 3,   accSum = 0
  x = 0    0 + 0 = 0 ≤ 0     → 그대로,    count = 3,   accSum = 0
  └ count = 3 이라 「3 묶음이면 된다」가 참으로 나온다

  그런데 10 이 든 묶음의 합은 10 이지 0 이 아니다
```

판정 함수는 「지금 묶음에 더 넣으면 넘치는가」만 보고, **원소 하나가 이미 `m` 을 넘는 경우를 따로
걸러 내지 않습니다.** 그래서 `m < max(A)` 에서는 이 함수가 뜻을 잃어요. 아래 끝을 `max(A)` 로 잡는
것은 속도가 아니라 **판정이 뜻을 갖는 범위**를 정하는 일입니다.

#### 2. 후보값 하나를 탐욕 순회로 판정한다

후보값 `m` 이 정해지면 「묶음 합이 `m` 이하가 되게 `K` 개 이하로 나눌 수 있는가」를 답해야 합니다.
왼쪽부터 넣을 수 있는 만큼 넣고 넘칠 때만 새 묶음을 시작하면 묶음 수가 가장 적게 나와요.

```ts
function feasible(A: number[], K: number, m: number): boolean {
  let count = 1;
  let accSum = 0;
  for (const x of A) {
    if (accSum + x > m) {
      count++; // ③ 새 묶음을 시작한다
      accSum = 0;
    }
    accSum += x;
  }
  return count <= K;
}
```

여기서 가장 중요한 줄은 `let count = 1;` 입니다. 새 묶음을 시작한 횟수가 아니라 **지금까지 만든
묶음 수**를 세는 것이라, 첫 묶음이 이미 하나 있어요. 판정 함수만 떼어 실행하면 이렇게 나옵니다.

<!--proof:walk-judge-->

```text
feasible([7, 2, 5, 10, 8], 2, 18)   →   true    (묶음 2 개)
feasible([7, 2, 5, 10, 8], 2, 17)   →   false   (묶음 3 개)
feasible([7, 2, 5, 10, 8], 3, 17)   →   true    (묶음 3 개)
```

칸마다의 `accSum` 과 `count` 는 「아이디어 상세」의 2단계 표에 있는 그대로예요. 같은 `m = 17` 이라도
`K` 가 3 이면 참이 나오는 것은, 판정이 묶음 수를 `K` 와 비교할 뿐 `m` 하나로 정해지지 않기 때문입니다.

#### 짚고 가기 — 부등호를 `>=` 로 적어도 답이 그대로인 입력이 있다

`accSum + x > m` 의 부등호를 `>=` 로 적는 것은 흔한 손버릇입니다. 「합이 `m` 과 같아지면 꽉 찼으니 새
묶음을 시작해야지」라고 읽히기 때문인데, `m` 은 **넘으면 안 되는 값**이지 **같아지면 안 되는 값**이
아니에요.

```ts
if (accSum + x >= m) { // ← 여기만 바꿨다. 원래는 accSum + x > m 이다
```

실행하면 이렇게 나옵니다.

<!--proof:or-equal-->

| 배열 | K | 바른 코드 | `>=` 로 적은 코드 |
| --- | ---: | ---: | ---: |
| [7 2 5 10 8] | 2 | 18 | 19 |
| [1 2 3 4 5] | 2 | 9 | 10 |
| [0 0 0 0] | 2 | 0 | 1 |
| [10 0 0] | 3 | 10 | 10 |

네 벌 중 3 벌에서 답이 바뀝니다.

<!--/proof-->

`[7 2 5 10 8]` 을 두 묶음으로 나누면 바른 코드는 18 을, `>=` 로 적은 코드는 19 를 줍니다. 어긋나는
자리는 두 번째 묶음이 `10 + 8 = 18` 로 `m` 과 정확히 같아지는 그 지점이에요.

<!--proof:or-equal-trace-->

```text
m = 18, accSum = 10, x = 8 에서

  accSum + x > m    18 > 18 은 거짓   → 같은 묶음에 남는다.   count = 2   → 참
  accSum + x >= m   18 >= 18 은 참    → 새 묶음을 시작한다.   count = 3   → 거짓
  └ 18 이 거짓으로 판정되니 이진 탐색이 18 을 지나쳐 더 큰 값에서 멈춘다
```

`[10 0 0]` 에서는 두 코드가 똑같이 10 을 줍니다. 우연히 맞는 경우가 섞여 있어서, 입력 하나만 확인하고
넘어가면 이 자리를 지나치기 쉬워요.

#### 3. 판정 결과로 후보 구간을 줄인다

판정이 참이면 `mid` 로 나눌 수 있으니 답은 `mid` 이하입니다. 거짓이면 `mid` 로는 못 나누니 답은
`mid` 보다 커요. 어느 쪽이든 `mid` 자체는 후보에 남기지 않습니다.

```ts
const mid = lo + Math.floor((hi - lo) / 2);

if (feasible(A, K, mid)) {
  hi = mid - 1; // ① 이 값으로 된다
} else {
  lo = mid + 1; // ② 이 값으로는 안 된다
}
```

참과 거짓이 한 번씩 나오는 바퀴 둘을 실행하면 이렇습니다.

<!--proof:walk-step3-->

```text
후보 [10,32]   mid = 21   판정 참     → hi = 20   → 후보 [10,20]   11 개
후보 [10,20]   mid = 15   판정 거짓   → lo = 16   → 후보 [16,20]   5 개
```

참인 갈래에서 `hi = mid - 1` 로 `mid` 를 버려도 되는 것은 **답을 `lo` 로 읽기** 때문입니다. `mid` 가
답이었다면 그 아래 값들은 전부 거짓이라, 뒤따르는 판정이 `lo` 를 `mid` 까지 올려놓아요. 「아이디어
상세」의 3단계 표에서 18 이 후보 밖으로 나간 뒤 `lo` 가 18 에 도달한 것이 그 모습입니다.

#### 4. 다섯 칸에서 18 을 실제로 찾는다

배열 `A` 가 아니라 후보값 10 부터 32 까지이고, 대시 칸이 후보에서 빠진 값, ▲ 가 이번에 판정한 값,
괄호가 남은 후보 구간이에요.

| T12 | 반복 조건 확인 | `18 <= 17` 이 **거짓** → lo 반환 | 18 | 17 | 0 |

**두 갈래가 모두 나왔습니다.** 판정은 T3 · T5 · T7 · T9 · T11 다섯이고 반환값은 18 이에요. 판정 안의
갈래 ③ 은 T5 · T9 · T11 처럼 묶음이 셋이 된 판정에서 두 번씩, T3 · T7 에서 한 번씩 실행됐습니다. 후보값
수가 23 → 11 → 5 → 2 → 1 → 0 으로 줄었고, T11 이 끝났을 때 `lo` 가 `hi` 를 넘어 T12 가 `lo` 를
돌려줘요.

답이 후보 구간의 위 끝인 경우도 봐야죠. 같은 배열에 `K = 1` 을 넣으면 나눌 자리가 없어 답이 `ΣA`
입니다. 여기서는 바퀴마다 한 걸음으로 적습니다.

나와 `hi` 가 31 로 내려갑니다. 후보 구간의 맨 위 값도 판정을 한 번 받고 나서야 답이 돼요.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 반복이 끝난 뒤 `lo` 를 돌려주는 마지막
줄뿐이에요.

```ts
export function parametricBinarySearch(A: number[], K: number): number {
  // 후보 구간의 아래 끝은 max(A), 위 끝은 ΣA 다. 순회 한 번으로 둘을 함께 구한다.
  let lo = 0;
  let hi = 0;
  for (const x of A) {
    if (x > lo) lo = x;
    hi += x;
  }

  while (lo <= hi) {
    // 후보 구간의 한가운데 값을 이번 판정 대상으로 삼는다.
    const mid = lo + Math.floor((hi - lo) / 2);

    if (feasible(A, K, mid)) {
      // ① 판정이 참 — mid 로 나눌 수 있다. mid 보다 큰 값은 답이 아니다.
      hi = mid - 1;
    } else {
      // ② 판정이 거짓 — 답은 mid 보다 크다.
      lo = mid + 1;
    }
  }

  // 후보 구간이 비었다. lo 가 판정이 참이 되는 가장 작은 값이다.
  return lo;
}

export function feasible(A: number[], K: number, m: number): boolean {
  let count = 1;
  let accSum = 0;

  for (const x of A) {
    if (accSum + x > m) {
      // ③ 지금 묶음에 x 를 더 넣으면 m 을 넘는다. 여기서 새 묶음을 시작한다.
      count++;
      accSum = 0;
    }
    accSum += x;
  }

  return count <= K;
}
```

<!--proof:final-calls-->

```text
parametricBinarySearch([7, 2, 5, 10, 8], 2)   →   18
parametricBinarySearch([1, 2, 3, 4, 5], 2)    →   9
parametricBinarySearch([1, 2, 3, 4, 5], 1)    →   15
parametricBinarySearch([0, 0, 0, 0], 2)       →   0
```

### 알아 두면 좋은 개념 — 탐욕이 앞선다 논법

판정 함수가 최소 묶음 수를 준다는 것을 확인할 때, 탐욕이 만든 나눔과 다른 나눔의 **경계 위치**를
묶음 번호마다 나란히 놓고 비교했습니다.

<!--proof:related-ahead-->

| 묶음 번호 | 탐욕이 담은 칸 | 다른 나눔이 담은 칸 |
| ---: | --- | --- |
| 1 | 3 칸 | 2 칸 |
| 2 | 5 칸 | 4 칸 |
| 3 | — | 5 칸 |

m = 18 에서 탐욕의 경계가 매번 같거나 더 뒤에 있고, 묶음은 탐욕이 2 개, 다른 나눔이 3 개입니다.

<!--/proof-->

같은 자원을 쓰는 두 절차를 놓고 **한쪽이 매 단계 뒤처지지 않음**을 보여 최적성을 논증하는 방식을
탐욕이 앞선다 논법이라고 합니다. 여기서 「앞선다」는 매 묶음마다 더 뒤 칸까지 담는다는 뜻이고, 그것이
유지되면 묶음 수가 더 많아질 수 없어요. 같은 논법이 다시 나오는 자리를 모으면 이렇습니다.

| 같은 논법이 다시 나오는 자리 | 앞서는 것 | 최적인 것 |
| --- | --- | --- |
| 구간 스케줄링 | 끝나는 시각이 이른 것부터 고르면 `k` 번째 선택의 종료 시각이 가장 이르다 | 고른 구간의 개수 |
| 최소 점프 횟수 | 같은 횟수로 갈 수 있는 가장 먼 칸 | 점프 횟수 |
| 이 편의 판정 함수 | `i` 번째 묶음의 경계 위치 | 묶음 수 |

세 자리 다 「매 단계 뒤처지지 않는다」를 값으로 보이고, 거기서 곧바로 최적성이 나옵니다. 탐욕이
최적이 아닌 경우도 많아서, 이 논증이 되는지를 먼저 확인하는 것이 순서예요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 판정 횟수를 임의의 입력으로 어떻게
내는지, 무엇이 매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **답이 정수 하나**이고, 그 값이 놓일 수 있는 범위를 아래위로 막을 수 있습니다. 이 과제에서는
  `max(A)` 와 `ΣA` 가 그 두 끝이에요.
- 「답이 `m` 이하인가」를 **묻는 물음으로 바꿀 수 있습니다.** 최적값을 만들지 않고 예·아니오만
  답하면 되는 형태여야 해요.
- 그 물음이 `m` 에 대해 **단조**입니다. 참·거짓이 한 번만 바뀌어야 절반을 뺄 근거가 생겨요.
- 물음에 답하는 비용이 **답을 직접 만드는 비용보다 훨씬 적습니다.** 이 과제에서는 배열을 한 번
  순회하는 것으로 끝나고, 나눔을 직접 만들면 분할점을 전부 시험해야 해요.

```text
네 조건이 코드의 모양을 그대로 정한다
  답이 정수 하나다     →  lo · hi 두 정수로 후보를 나타낸다
  물음으로 바꾼다      →  feasible 이라는 함수 하나가 생긴다
  물음이 단조다        →  한쪽을 통째로 빼는 두 줄이 성립한다
  묻는 비용이 작다     →  판정 횟수 × 판정 비용이 전체 비용이 된다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "최댓값을 최소로 하라"      "최솟값을 최대로 하라"
  "가능한 가장 작은 …를 구하라"  "…를 만족하는 최소 X는?"

제약에 이런 모양이 보이면
  답의 범위는 큰데(10^9 이상) 배열 길이는 10^5 이하다
  "가능한가"를 판정하는 것이 답을 만드는 것보다 명백히 쉽다
```

반대로 「그 나눔을 실제로 출력하라」거나 「경우의 수를 세라」는 말이 있으면 이 단서는
해당하지 않습니다. 판정만으로는 나눔 자체가 나오지 않아요. 다만 답을 찾은 뒤에 그 값으로
탐욕 순회를 한 번 더 실행하면 나눔 하나를 복원할 수는 있습니다.

한 가지 더 있습니다. **답이 실수인 문제**도 같은 틀에 들어가요. 그때는 후보 구간이 정수가
아니라 실수 구간이고, 반복을 「구간 길이가 `ε` 아래로 내려갈 때까지」로 바꿉니다.

#### 실제로 쓰이는 곳

- **Git 의 `git bisect`** — 문서의 첫 문장이 이 절차를 그대로 적습니다: *"This command uses a
  binary search algorithm to find which commit in your project's history introduced a bug."*
  후보 구간이 값이 아니라 커밋 이력이고, 판정 함수가 「이 커밋에 버그가 있는가」예요.
  ([`Documentation/git-bisect.adoc`](https://github.com/git/git/blob/master/Documentation/git-bisect.adoc), 조회 2026-08-29)
- **Go 표준 라이브러리 `sort.Search`** — 주석이 요구 조건을 단조로 적습니다: *"Search uses
  binary search to find and return the smallest index i in [0, n) at which f(i) is true, assuming
  that on the range [0, n), f(i) == true implies f(i+1) == true."* 같은 주석에 배열이 아니라
  **값 범위**에 이 절차를 적용하는 예제(`GuessingGame`)가 함께 실려 있어요 — `sort.Search(100, …)`
  로 0 부터 100 까지를 후보로 두고 사람에게 되묻습니다.
  ([`src/sort/search.go`](https://github.com/golang/go/blob/master/src/sort/search.go), 조회 2026-08-29)
- **AMReX 의 부하 분산** — 로런스 버클리 국립연구소의 격자·입자 시뮬레이션 프레임워크에서
  이 과제와 **같은 과제**를 풉니다. 논문이 새 알고리즘 둘 중 하나로 *"a painter's
  partition-based SFC algorithm"* 을 들고, 2.4 절이 *"The Painter's Partition algorithm uses a
  binary search to achieve this optimal partitioning value."* 라고 적어요. 1 차원으로 늘어놓은
  격자 덩어리를 프로세서 수만큼의 연속 조각으로 나누되 가장 무거운 조각을 가볍게 만드는 것이
  목표입니다.
  ([arXiv:2505.15122](https://arxiv.org/abs/2505.15122), 조회 2026-08-29)

셋 다 후보가 배열의 인덱스가 아니라는 점이 눈에 띕니다. 커밋 이력·정수 범위·부하 상한이
각각 후보이고, 절차는 같고 판정 함수만 다릅니다.

#### 경쟁 설계와의 대조

같은 목표를 노리는 **다른 절차**가 있어요 — **동적 계획법**입니다. 답을 후보로 두고 되묻지
않고, 앞 `i` 칸을 `j` 묶음으로 나눈 최적값을 표로 채워 올라갑니다.

```text
dp[j][i] = min over k < i of  max( dp[j-1][k],  A[k] + … + A[i-1] )
           └ 마지막 묶음이 k 칸 뒤에서 시작한다고 두고, 분할점 k 를 전부 시험한다
```

두 설계를 **같은 입력**에 적용해 결정론적 계수 둘을 셌습니다. `기본 연산` 은 상수 시간이 드는
작업 한 묶음의 수예요. 판정 쪽은 원소 하나를 보는 것(덧셈과 비교), 표 쪽은 분할점 하나를 시험하는
것(뺄셈 · 최댓값 · 비교)이 한 번이고, 두 쪽 모두 후보 구간을 정하는 첫 순회와 누적합 만들기는
넣지 않았습니다. `할당 칸` 은 입력 배열 밖에 새로 잡은 칸을 잡을 때마다 더한 값입니다. 표 쪽은
누적합 한 벌과 줄 `K + 1` 벌을 한 줄씩 버려도 모두 셌고, 스칼라 변수는 뺐어요.

전개의 다섯 칸을 그대로 쓰지 않은 이유는 하나예요 — 이 대조가 갈리는 축이 **`N` 과 값의 크기
중 어느 쪽이 큰가**인데, 다섯 칸으로는 두 축을 갈라 놓을 수 없습니다. 난수를 쓰지 않으니
시드가 없고, 두 생성식이 입력의 전부예요. 작은 입력은 `A[i] = 10^6 − i`(`i = 0 … 5`)에
`K = 3`, 큰 입력은 `A[i] = (37i mod 1000) + 1`(`i = 0 … 299`)에 `K = 30` 입니다.

| 설계 | 작은 입력 기본 연산 | 작은 입력 할당 칸 | 큰 입력 기본 연산 | 큰 입력 할당 칸 |
| --- | --- | --- | --- | --- |
| 파라메트릭 이진 탐색 (이 가이드) | 132 | **0** | **5,100** | **0** |
| 동적 계획법 | **46** | 35 | 1,228,060 | 9,632 |

두 설계의 기본 연산이 어디서 갈리는지 보려고 판정 횟수와 후보값 개수를 함께 세었습니다. 파라메트릭
쪽의 기본 연산은 `N × 판정 횟수` 이고, 동적 계획법 쪽은 값과 상관없이 `N` 과 `K` 로만 정해집니다.

<!--proof:alt-axis-->

| 입력 | N | K | 후보값 개수 | 판정 횟수 | 파라메트릭 기본 연산 | 동적 계획법 기본 연산 | 적은 쪽 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 작은 입력 | 6 | 3 | 4,999,986 | 22 | 132 | 46 | 동적 계획법 |
| 큰 입력 | 300 | 30 | 151,751 | 17 | 5,100 | 1,228,060 | 파라메트릭 |

**작은 입력에서는 동적 계획법이 적습니다** — 기본 연산이 46 대 132 예요. `N` 이 6 뿐인데 값이
`10^6` 대라 후보값이 500 만 개 가까이 되고, 판정을 22 번 해야 해서 `22 × 6` 이 됩니다. 표를 채우는
쪽은 값의 크기와 상관이 없어요.

**큰 입력에서는 순서가 뒤집힙니다.** `N = 300`, `K = 30` 에서 표를 채우는 쪽은 기본 연산이 1,228,060 번인데
판정하는 쪽은 5,100 번입니다. 판정 횟수는 후보값 개수의 로그라 17 번에 그치고, 표 쪽의 시험
횟수는 `N` 의 제곱에 `K` 를 곱한 규모로 붙어요. 음수가 섞인 배열에서도 두 설계를 실행해 보았습니다.

<!--proof:alt-negative-->

| 배열 | K | 파라메트릭 | 동적 계획법 | 나눔을 전부 만든 답 |
| --- | ---: | ---: | ---: | ---: |
| [5 -1 -2] | 2 | 5 | 4 | 4 |
| [3 6 4 -3] | 1 | 11 | 10 | 10 |

동적 계획법은 나눔을 전부 만든 답과 같은 값을 내고, 파라메트릭 쪽은 두 벌 다 틀립니다. 축을 넷으로
갈라 적으면 이렇습니다.

| 축 | 파라메트릭 이진 탐색 | 동적 계획법 | 적은 쪽 |
| --- | --- | --- | --- |
| 작은 입력 기본 연산 | 132 | 46 | 동적 계획법 |
| 큰 입력 기본 연산 | 5,100 | 1,228,060 | 파라메트릭 이진 탐색 |
| 할당 칸 | 0 | 35 · 9,632 | 파라메트릭 이진 탐색 |
| 음수가 섞인 배열 | 답이 틀린다 | 그대로 맞는다 | 동적 계획법이 더 넓게 쓰인다 |

**파라메트릭 이진 탐색이 내주는 것은 값의 크기에 붙는 판정 횟수와 적용 범위입니다.** 값이 커지면
후보값이 늘어 판정을 더 해야 하고, 원소에 음수가 섞이면 후보 구간의 아래 끝과 탐욕 판정이 둘 다
성립하지 않아 답이 틀려요. 그것을 내주고 받는 것이 둘입니다 — `N` 이 클 때 기본 연산이 `N` 의 제곱에 붙지
않고, 할당 칸이 0 이에요.

**우열이 반대가 되는 조건이 분명합니다.** `N` 과 `K` 가 작고 값이 큰 입력에서는 표를 채우는 쪽이
적고, `N` 이 크고 값이 작은 입력에서는 판정하는 쪽이 적습니다. 위 두 입력이 그 경계의 양쪽이에요.

### 수식 정의와 유도

배열 $A$ 의 길이를 $N$, 나눌 묶음 수를 $K$ 라 하고, 후보값 $m$ 에 대해 묶음 합이 $m$ 이하가
되도록 나눌 때 필요한 최소 묶음 수를 $g(m)$ 이라 합니다. 답은 판정이 참이 되는 가장 작은
값입니다.

$$m^{*} = \min \{\, m \;:\; \max(A) \le m \le \Sigma A,\; g(m) \le K \,\}$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $S$ | 후보값의 개수 | $S = \Sigma A - \max(A) + 1$ |
| $g(m)$ | 묶음 합이 $m$ 이하가 되게 나눌 때 필요한 최소 묶음 수 | $1 \le g(m) \le N$ |
| $P(s)$ | 후보값 $s$ 개를 끝낼 때까지의 최악 판정 횟수 | $P(0) = 0$ |

**정의를 값에 넣어 검산해 봅시다.** $A = [7\ 2\ 5\ 10\ 8]$ 에서 $\max(A) = 10$,
$\Sigma A = 32$ 이므로 $S = 32 - 10 + 1 = 23$ 입니다. $g(14)$ 와 $g(18)$ 을 정의대로 셉니다.

<!--proof:math-check-g-->

```text
g(14) — 묶음 합이 14 이하가 되게 왼쪽부터 이어 붙인다
  7 2 5   합 14
  10      합 10
  8       합 8
  g(14) = 3 > 2 라 거짓

g(18) — 묶음 합이 18 이하가 되게 왼쪽부터 이어 붙인다
  7 2 5   합 14
  10 8    합 18
  g(18) = 2 ≤ 2 라 참
```

$K = 2$ 이므로 $g(14) = 3 > 2$ 는 거짓이고 $g(18) = 2 \le 2$ 는 참입니다. 파트 1 에서 경계가 18
이던 것과 같은 값이에요. **이제 유도합니다.** 먼저 $g$ 가 단조인 것을 보입니다. $m_1 \le m_2$ 라
두면, $m_1$ 이하로 만든 나눔은 모든 묶음 합이 $m_1$ 이하이므로 $m_2$ 이하이기도 합니다.

$$m_1 \le m_2 \;\Longrightarrow\; \{\text{합이 } m_1 \text{ 이하인 나눔}\} \subseteq \{\text{합이 } m_2 \text{ 이하인 나눔}\} \;\Longrightarrow\; g(m_1) \ge g(m_2)$$

```text
두 집합의 포함 관계가 그대로 최솟값의 대소가 된다

  m1 이하인 나눔들   ⊆   m2 이하인 나눔들
  └ 작은 집합의 최솟값은 큰 집합의 최솟값보다 작지 않다
    그래서 g 는 m 이 커질 때 줄기만 한다
```

$g$ 가 줄기만 하면 $g(m) \le K$ 도 거짓에서 참으로 한 번만 바뀝니다. 그 경계를 찾을 때
후보값 $s$ 개에서 한가운데를 판정하면 남는 것이 양쪽 중 큰 쪽이므로, 판정 횟수는 다음
관계를 만족해요.

$$P(s) = P\Bigl(\Bigl\lceil \frac{s-1}{2} \Bigr\rceil\Bigr) + 1, \qquad P(0) = 0$$

<!--proof:math-fold-->

```text
s = 23 에서 접으면   23 → ⌈22/2⌉ = 11 → ⌈10/2⌉ = 5 → ⌈4/2⌉ = 2 → ⌈1/2⌉ = 1 → ⌈0/2⌉ = 0
└ 5 번 접어서 후보가 빈다. P(23) = 5 이다
```

후보 수가 매번 절반 이하로 주므로 $P(s)$ 는 $s$ 를 1 이하가 될 때까지 2 로 나눈 횟수에 1 을
더한 값이고, 그것이 밑이 2 인 로그의 정의라 닫힌 형태가 바로 나옵니다.

$$P(s) = \lfloor \log_2 s \rfloor + 1 \quad (s \ge 1), \qquad P(0) = 0$$

<!--proof:math-closed-->

| s | P(s) |
| ---: | ---: |
| 1 | 1 |
| 2 | 2 |
| 3 | 2 |
| 4 | 3 |
| 23 | 5 |
| 10^11 | 37 |

s = 1 부터 5,000 까지와 표의 여섯 값에서 점화식과 닫힌 형태가 같았습니다. s = 23 의 5 는 전개 입력에서 정본이 판정한 횟수 5 와 같습니다.

<!--/proof-->

판정 한 번이 배열을 한 번 순회하으므로 $\Theta(N)$ 입니다. 앞뒤로 붙는 것은 $\max(A)$ 와
$\Sigma A$ 를 구하는 순회 한 번뿐이에요.

$$T(N, S) = \Theta(N) + \Theta\bigl(N \cdot (\lfloor \log_2 S \rfloor + 1)\bigr) = \Theta(N \log S)$$

<!--proof:math-code-->

```ts
const S = (A: number[]): number =>
  A.reduce((a, b) => a + b, 0) - Math.max(...A) + 1;
const P = (s: number): number => (s <= 0 ? 0 : Math.floor(Math.log2(s)) + 1);

S([7, 2, 5, 10, 8]); // → 23
P(23); // → 5
P(10 ** 11); // → 37
```

**마지막으로 계수입니다.** 제약 규모 `N = 10^5`, `A[i] ≤ 10^6` 을 닫힌 형태에 넣습니다.

<!--proof:math-scale-->

| 양 | 값 |
| --- | --- |
| ΣA 의 최대 | 100,000 × 1,000,000 = 100,000,000,000 |
| 후보값 개수 S 의 최대 | ΣA − max(A) + 1 = 99,999,000,001 |
| 판정 횟수의 상한 P(S) | ⌊log₂ 99,999,000,001⌋ + 1 = 37 |
| 판정이 순회하는 칸의 상한 | 100,000 × 37 = 3,700,000 |

파트 1 의 표는 입력 몇 벌에서 판정 횟수를 센 것이라 그 밖으로는 아무 말도 못 합니다. 닫힌 형태는
임의의 입력에 대해 값을 내니, 제약 안의 **어떤** 입력에서도 판정이 37 번을 넘지 않는다고 말할 수
있어요. 판정이 순회하는 칸이 370 만이면 1 초 예산에 넉넉히 들어옵니다.

### 불변식 — 반복이 한 바퀴를 시작할 때마다 답은 `lo` 이상 `hi + 1` 이하다

파트 1 에서 코드가 동작하는 것을 열두 단계로 확인했습니다. 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> **반복이 한 바퀴를 시작하는 시점마다**, 답 `m*` 는 `lo <= m*` 이고 `m* <= hi + 1` 입니다.

<!--fig:invariant-zones-->
![바퀴가 시작할 때 — 거짓으로 정해진 값 · 후보 구간 · 참으로 정해진 값, 답은 lo 이상 hi + 1 이하](./figs/invariant-zones.svg)

`hi + 1` 이 오른쪽 끝인 것이 이 문장의 요점입니다. 그림은 넷째 바퀴가 시작할 때인데, 답 18 이 후보
구간 `[16,17]` 밖의 `hi + 1` 자리에 있어요. `hi` 위쪽이 전부 참으로 정해졌으면 답은 그 첫 값인
`hi + 1` 일 수 있고, 반복이 끝나면서 `lo` 가 그 값에 도달합니다.

**출발점부터 봅시다.** 반복에 들어가기 전 `lo = max(A)`, `hi = ΣA` 이고, 답은 그 사이에
있습니다. 가장 큰 원소가 든 묶음의 합은 `max(A)` 이상이고, 전부를 한 묶음으로 두면 `ΣA`
이니까요. 그다음 한 바퀴마다 갈래가 둘입니다.

| 판정 결과 | 하는 일 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| `feasible(mid)` 가 **참** | `hi = mid - 1` | `mid` 로 나눌 수 있으니 `m* <= mid` 다. 새 오른쪽 끝은 `hi' + 1 = mid` 이므로 `m* <= hi' + 1` 이 그대로 참이다. `lo` 는 그대로다 |
| `feasible(mid)` 가 **거짓** | `lo = mid + 1` | `mid` 로 못 나누고 `g` 가 단조이므로 `m* > mid`, 즉 `m* >= mid + 1` 이다. 새 왼쪽 끝은 `lo' = mid + 1 <= m*` 다. `hi` 는 그대로다 |

둘이 전부입니다 — 판정 결과에 세 번째가 없어요. 그리고 두 갱신 모두 `mid` 를 후보에서 빼므로
후보값 수가 매 바퀴 최소 1 은 줄고, 후보가 유한하니 반복은 반드시 끝납니다. 전개 입력에서 바퀴마다
두 부등식을 확인하면 이렇습니다.

<!--proof:invariant-rounds-->

| 시점 | lo | hi | lo ≤ 18 | 18 ≤ hi + 1 |
| --- | ---: | ---: | --- | --- |
| 1 바퀴 시작 | 10 | 32 | 참 | 참 |
| 2 바퀴 시작 | 10 | 20 | 참 | 참 |
| 3 바퀴 시작 | 16 | 20 | 참 | 참 |
| 4 바퀴 시작 | 16 | 17 | 참 | 참 |
| 5 바퀴 시작 | 17 | 17 | 참 | 참 |
| 반복이 끝난 뒤 | 18 | 17 | 참 | 참 |

6 시점 모두에서 두 부등식이 참입니다. 마지막 줄은 lo = 18, hi + 1 = 18 이라 답이 하나로 정해집니다.

<!--/proof-->

반복이 끝나는 시점에는 `lo > hi`, 즉 `lo >= hi + 1` 입니다. 불변식의 두 부등식을 모으면
`lo <= m* <= hi + 1 <= lo` 가 되어 `m* = lo` 하나만 남아요. 그래서 마지막 줄이 `lo` 를
돌려주는 것이 옳습니다.

**경계에 있는 입력도 확인하고 갑시다.** 아래 일곱 줄이 이 함수가 받을 수 있는 모양의 끝입니다.

<!--proof:invariant-edges-->

| 입력 | 처리되는 자리 | 결과 |
| --- | --- | --- |
| 원소 하나 `[7]`, `K = 1` | 후보 [7,7] · 판정 1 번 | 7 (아래 끝 max(A)) |
| `K = 1` — `[1 2 3 4 5]` | 후보 [5,15] · 판정 4 번 | 15 (위 끝 ΣA) |
| `K = N` — `[1 2 3 4 5]` | 후보 [5,15] · 판정 3 번 | 5 (아래 끝 max(A)) |
| 값이 전부 0 `[0 0 0 0]`, `K = 2` | 후보 [0,0] · 판정 1 번 | 0 (아래 끝 max(A)) |
| 값이 전부 같음 `[5 5 5 5 5]`, `K = 5` | 후보 [5,25] · 판정 4 번 | 5 (아래 끝 max(A)) |
| 한 칸만 큼 `[1 1 1 1000000]`, `K = 2` | 후보 [1000000,1000003] · 판정 2 번 | 1,000,000 (아래 끝 max(A)) |
| 값이 전부 10^6 · N = 100,000, `K = 2` | 후보 [1000000,100000000000] · 판정 36 번 | 50,000,000,000 (두 끝 사이) |

답이 아래 끝이든 위 끝이든 두 끝 사이든, 판정 횟수만 다를 뿐 같은 부등식으로 `lo` 가 답에 도달합니다.
마지막 줄의 답은 32비트를 넘지만 `number` 가 배정밀도라 `2^53` 아래의 정수를 정확히 담아요.

**이제 깨뜨려 봅시다.** 불변식이 답을 `m* = lo` 하나로 좁힌 근거는 반복이 끝날 때
`lo >= hi + 1` 이라는 것이었습니다. 그 조건을 만드는 줄이 반복 조건이니, 거기서 등호를 빼고
`while (lo < hi)` 로 적어 봅니다.

```ts
while (lo < hi) {
  // ← 여기서 등호를 뺐다. 원래는 while (lo <= hi) 다
```

실행하면 이렇게 나옵니다.

<!--proof:loop-condition-->

| 배열 | K | 바른 코드 | `lo < hi` 로 적은 코드 |
| --- | ---: | ---: | ---: |
| [7 2 5 10 8] | 2 | 18 | 17 |
| [7 7 7] | 2 | 14 | 13 |
| [5 8 9 7] | 2 | 16 | 15 |
| [1 2 3 4 5] | 2 | 9 | 9 |

네 벌 중 3 벌에서 답이 1 만큼 작게 나옵니다.

<!--/proof-->

`[7 2 5 10 8]` 에서 바른 코드는 18 을, 등호를 뺀 코드는 17 을 줍니다. 반복이 `lo == hi` 에서
끝나 버리는데, 그 시점에 불변식이 말해 주는 것은 `lo <= m* <= hi + 1 = lo + 1` 뿐이에요.

<!--proof:loop-condition-trace-->

```text
[7 2 5 10 8], K = 2 에서 lo = hi = 17 이 된 시점

  while (lo <= hi)   17 을 한 번 더 판정한다.   거짓이라 lo = 18.            답 18
  while (lo < hi)    판정하지 않고 끝난다.      lo = 17 을 그대로 돌려준다
  └ 17 이 참인지 거짓인지 확인한 적이 없다
```

불변식이 답을 하나로 좁히려면 `lo` 와 `hi + 1` 이 만나야 합니다. `lo == hi` 에서 멈추면 그
둘 사이가 1 만큼 벌어진 채로 끝나고, 남은 후보 둘 중 어느 쪽인지는 아무도 확인하지 않아요.
`[1 2 3 4 5]` 에서 우연히 답이 같게 나오는 것이 이 자리를 특히 어렵게 만듭니다.

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 일은 후보값 하나를 정하고 판정 함수를 한 번 부르는 것입니다. 전개의
T3 · T5 · T7 · T9 · T11 이 그 판정 다섯이고, T2 · T4 · T6 · T8 · T10 은 `mid` 를 정하는 산술이라
판정이 아니에요.

<!--proof:perf-derive-probes-->

```text
T3    판정 21   배열 5 칸을 순회한다   후보값 23 → 11
T5    판정 15   배열 5 칸을 순회한다   후보값 11 → 5
T7    판정 18   배열 5 칸을 순회한다   후보값 5 → 2
T9    판정 16   배열 5 칸을 순회한다   후보값 2 → 1
T11   판정 17   배열 5 칸을 순회한다   후보값 1 → 0
└ 판정 5 번 × 5 칸 = 25 칸
```

판정 횟수는 후보값 수를 접은 횟수이고, 판정 한 번의 비용은 배열 길이 `N` 입니다. 두 값이
따로 정해지므로 전체는 그 곱이에요. `N` 이 커지면 판정 한 번의 비용이 커지고, 값이 커지면 판정 횟수가
늘어납니다. 최악은 후보값이 `S` 개일 때 접는 횟수이고, 그 값을 임의의 입력으로 낸 것이 「수식 정의와
유도」의 닫힌 형태예요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`S = 1`, 값이 전부 같고 `K = N` 등) | `O(N)` | `Θ(N)` |
| **평균적인 경우** (입력 분포를 정해야 정의된다) | `O(N log S)` | `Θ(N log S)` |
| **최악의 경우** (후보가 빌 때까지 접는다) | `O(N log S)` | `Θ(N log S)` — 실제로 도달한다 |

최악에서 `Θ(N log S)` 라고 쓸 수 있는 것은 그 값을 **실제로 내는 입력이 있기** 때문입니다.
값이 전부 `10^6` 인 배열 `10^5` 칸을 두 묶음으로 나누면 판정이 36 번이고, 그 각각이 `10^5`
칸을 순회해요(아래 「최악을 만드는 입력」의 표).

**평균이 최악과 같은 자리에 있는 것은 이 절차의 성질입니다.** 판정 횟수는 입력의 내용이
아니라 후보값 개수 `S` 로 거의 정해지고, 판정 한 번은 항상 배열 전체를 순회합니다. 매번 작은 쪽이
남는 길과 큰 쪽이 남는 길의 판정 횟수를 세어 보면 폭이 1 을 넘지 않아요.

<!--proof:perf-band-->

후보값 개수 S 를 1 부터 4,096 까지 모두 넣고, 매번 작은 쪽이 남는 길과 큰 쪽이 남는 길의 판정 횟수를 셌습니다. 전개 입력과 N = 100,000 입력의 실제 판정 횟수도 함께 봤습니다. ⌊log₂ S⌋ 이상 ⌊log₂ S⌋ + 1 이하를 벗어난 경우는 0 개입니다.

<!--/proof-->

그래서 어떤 분포를 가정해도 평균이 `⌊log₂ S⌋` 와 `⌊log₂ S⌋ + 1` 사이에 있고, 세 케이스가 상수 안에서
같아집니다.

**총식을 한 번은 정확히 적습니다.** 앞에 붙는 항은 `max(A)` 와 `ΣA` 를 구하는 순회 하나이고,
뒤에 붙는 항은 없습니다.

```text
총식 = Θ(N)  +  Θ(N × (⌊log₂ S⌋ + 1))   =   Θ(N log S)      시간
       └ 두 끝을 구하는 순회      └ 판정 횟수 × 판정 비용

       배열은 새로 잡지 않고 스칼라는 lo · hi · mid · count · accSum 다섯뿐  →  Θ(1)   공간
```

제약 규모를 넣은 값은 「수식 정의와 유도」의 마지막 표에 있습니다. 판정 37 번, 순회하는 칸 370 만이에요.

**보장의 종류는 최악 보장입니다.** 코드에 난수가 없고 입력 분포에 대한 가정도 없어요. 제약
안의 어떤 배열과 어떤 `K` 를 넣어도 판정은 `⌊log₂ S⌋ + 1` 번을 넘지 않습니다.

```text
최악 보장   제약 안의 어떤 입력에도 판정 ≤ ⌊log₂ S⌋ + 1,  단계 ≤ N × (⌊log₂ S⌋ + 1)
기댓값      쓰지 않는다.  난수가 없어 같은 입력에 늘 같은 횟수가 나온다
            └ 「평균적인 경우」의 Θ 는 입력 분포에 대한 평균이지 구현이 만드는 무작위성이 아니다
```

#### 최악을 만드는 입력

「배열이 정렬돼 있으면 느리다」 같은 말은 이 절차에 해당하지 않습니다. 판정 횟수를 정하는
것은 배열의 순서가 아니라 **후보값이 몇 개인가**, 곧 `S = ΣA − max(A) + 1` 이에요. 입력 모양을
바꿔 가며 실제로 세면 이렇습니다.

<!--proof:probe-shapes-->

| 입력 모양 | 후보값 개수 | 판정 횟수 | ⌊log₂ 개수⌋ + 1 |
| --- | ---: | ---: | ---: |
| 값이 전부 0 · N = 4 | 1 | 1 | 1 |
| 한 칸만 큼 · N = 4 | 4 | 2 | 3 |
| 전개가 쓴 입력 · N = 5 | 23 | 5 | 5 |
| 값이 전부 10^6 · N = 5 | 4,000,001 | 22 | 22 |
| 값이 전부 10^6 · N = 100 | 99,000,001 | 27 | 27 |
| 값이 전부 10^6 · N = 100,000 | 99,999,000,001 | 36 | 37 |

최악을 만들려면 후보값 개수를 최대로 하면 됩니다. `ΣA` 를 크게 하고 `max(A)` 를 작게 해야
하는데 둘이 같은 값에 묶여 있으니, **값을 전부 최댓값으로 채우고 칸을 최대로** 두는 것이
답이에요. `A[i] = 10^6` 인 `10^5` 칸이 그것이고, 후보값이 999 억 9900 만 개입니다.

```text
후보값 개수 S = ΣA − max(A) + 1 을 최대로 만든다

  값을 키우면    ΣA 가 N 배로 늘고 max(A) 는 1 배로 는다   →  S 가 는다
  칸을 늘리면    ΣA 만 늘고 max(A) 는 그대로              →  S 가 는다
  한 칸만 크면   ΣA ≈ max(A) 라 S 가 작다                 →  판정이 몇 번으로 끝난다
```

`한 칸만 큼` 줄이 그 반대편입니다. `[1 1 1 1000000]` 은 값이 100 만인데도 후보값이 4 개뿐이라
판정이 두 번이에요 — 큰 값 하나가 `max(A)` 와 `ΣA` 를 함께 키워 둘의 차이가 작아지기
때문입니다. 그리고 마지막 줄에서 실제 판정 36 번이 상한 37 보다 하나 적은데, 닫힌 형태가
**상한**이라 그렇습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 답을 만드는 대신 「이 값이면 되는가」로
되묻고, 그 물음이 값에 대해 단조라서 후보값 전체를 폐구간으로 두고 절반씩 뺄 수 있으며,
판정 한 번이 순회 하나라 전체가 `Θ(N log S)` 가 됩니다.

```text
후보를 [max(A), ΣA] 로 → 한가운데를 판정 → 참이면 위쪽, 거짓이면 아래쪽을 뺀다 → lo 를 반환
                          └ 판정한 값 자체도 후보에서 뺀다. 그래야 후보가 실제로 준다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T7 에서 18 이 참이라 `hi` 가 17 이 됐어요. 만약 그
자리에서 `hi = mid` 로 적었다면 무슨 일이 일어날까요?

<!--proof:selfcheck-t7-->

```text
T7   후보 [16,20]   mid = 18   판정 참   →  hi = mid - 1 = 17   후보 [16,17]
                                         →  hi = mid     = 18   ← 이렇게 적었다면?
```

<!--check:hi-mid-->
후보가 `[16,18]` 로 3 개 남고, 다음 바퀴에서 17 이 거짓이라 `lo = 18` 이 돼요. 그러면 후보가
`[18,18]` 하나가 되고 18 이 다시 참이라 `hi = 18` 로 **값이 그대로**입니다. `while (lo < hi)` 를 쓰는
짜임이라면 `hi = mid` 가 맞는 짝이에요. 반복 조건과 갱신 폭은 **한 벌로 골라야** 하고, `lo <= hi` 에는
`hi = mid - 1` 이, `lo < hi` 에는 `hi = mid` 가 붙습니다. 처음부터 `hi = mid` 로 적은 반복을 바퀴마다
따라가면 이렇습니다.

<!--proof:selfcheck-himid-->

| 바퀴 | 후보 | mid | 판정 | 갱신 | 새 후보 |
| ---: | --- | ---: | --- | --- | --- |
| 1 | [10,32] | 21 | 참 | hi = 21 | [10,21] |
| 2 | [10,21] | 15 | 거짓 | lo = 16 | [16,21] |
| 3 | [16,21] | 18 | 참 | hi = 18 | [16,18] |
| 4 | [16,18] | 17 | 거짓 | lo = 18 | [18,18] |
| 5 | [18,18] | 18 | 참 | hi = 18 | [18,18] (같은 상태) |

5 번째 바퀴에서 앞 바퀴와 같은 상태로 돌아와, lo 도 hi 도 바뀌지 않은 채 반복이 끝나지 않습니다.

<!--/proof-->
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「수행으로 알아보는 알고리즘」의 T11, 「불변식」의
경계 입력 표, 「알아 두면 좋은 개념」을 다시 보세요.

- T11 에서 17 을 판정할 때 후보값이 하나뿐이었는데도 판정을 한 번 더 했습니다. 후보가 하나면
  그 값이 답이라고 바로 말할 수 없는 이유는 무엇일까요.
- `K` 를 2 로 두고 배열을 `[1 1 1 1000000]` 로 바꾸면 후보 구간이 어디부터 어디까지이고 판정이
  몇 번일까요. 그 값이 `⌊log₂ S⌋ + 1` 과 같은지도 확인해 보세요.
- 원소에 음수가 섞이면 이 절차가 성립하지 않습니다. 「탐욕이 앞선다」의 논증에서 어느 문장이 먼저
  거짓이 되는지, 전제 절의 `[3 6 4 -3]` 에서 탐욕의 경계와 한 묶음 나눔의 경계를 비교해 찾아 보세요.

### Parametric Binary Search — Split Array Largest Sum

풀 파일: [`parametricBinarySearch.ts`](./parametricBinarySearch.ts) · 테스트: [`parametricBinarySearch.test.ts`](./parametricBinarySearch.test.ts) · 실행: `bun test src/algorithms/binary-search/parametricBinarySearch/parametricBinarySearch.test.ts`

#### 한 줄 요약

> 정수 배열과 분할 수를 받아, K개의 연속 부분 배열로 나눌 때 부분 배열 합의 최댓값이 최소가 되는 값을 반환한다.

#### 스토리

물류회사 팀장 준석은 배송 기사 K명에게 일감을 분배해야 한다. 일감은 도로 위에 순서대로 나열되어 있고, 각 기사는 연속한 구간만 담당할 수 있다. 기사들을 공평하게 배분하려면 가장 힘든 기사의 업무량이 최대한 적어야 한다.

준석은 "가장 바쁜 기사의 업무량 상한을 X라고 가정하면 K명 이하로 배분이 가능한가?"라는 질문을 반복해서 던진다. X를 크게 잡으면 분명히 가능하고, 너무 작게 잡으면 불가능하다. 가능 여부를 기준 삼아 X 범위를 좁혀 나가면, 결국 정확한 최솟값을 찾을 수 있다.

#### 함수 인터페이스

```ts
export function parametricBinarySearch(A: number[], K: number): number;
```

- `A` — 음이 아닌 정수 배열
- `K` — 분할 수 (비어 있지 않은 연속 부분 배열의 개수)
- 반환 — K개 연속 부분 배열로 분할할 때 가능한 부분 배열 합의 최댓값 중 최솟값

#### 제약 조건

- $1 \leq N \leq 10^{5}$ ($N$은 배열 길이)
- $1 \leq K \leq N$
- $0 \leq A[i] \leq 10^{6}$
- 각 부분 배열은 비어 있으면 안 된다.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

음이 아닌 정수 배열 $A$와 정수 $K$가 주어진다. $A$를 $K$개의 비어있지 않은 연속 부분 배열로 분할할 때, 각 부분 배열 합의 최댓값을 최소화하는 값을 반환한다.

가능한 모든 $K$-분할 $\pi = (S_1, S_2, \ldots, S_K)$에 대해:

$$\text{parametricBinarySearch}(A, K) = \min_{\pi} \max_{1 \leq j \leq K} \sum_{i \in S_j} A[i]$$

#### 예시

```ts
parametricBinarySearch([7, 2, 5, 10, 8], 2);     // 18 — 최적 분할: [7,2,5]|[10,8], max(14,18)=18
parametricBinarySearch([1, 2, 3, 4, 5], 2);      // 9  — 최적 분할: [1,2,3]|[4,5], max(6,9)=9
parametricBinarySearch([1, 4, 4], 3);            // 4  — 각 원소가 한 묶음, max(1,4,4)=4
parametricBinarySearch([1, 2, 3, 4, 5], 1);      // 15 — K=1이면 전체 합
parametricBinarySearch([1, 2, 3, 4, 5], 5);      // 5  — K=N이면 각 원소가 한 묶음, 최댓값=5
parametricBinarySearch([7], 1);                  // 7  — 원소가 하나
```
