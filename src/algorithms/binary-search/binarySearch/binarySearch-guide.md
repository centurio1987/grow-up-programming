# 이진 탐색 — 가운데 한 칸을 읽으면 나머지 절반이 후보에서 빠진다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 한 칸씩 확인하는 방법에서
후보 구간을 절반씩 접는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로 동작하는 코드를
한 조각씩 만듭니다.

### 전체 컨셉

정렬된 배열에서 값을 찾을 때, **가운데 한 칸만 읽어도 나머지 절반 전체가 답일 수 없다**는
것이 정해집니다. 그것을 보장하는 것은 정렬 조건 `A[k] ≤ A[k+1]` 하나예요.

```text
A = [ 1   3   5   7   9  11 ]        target = 7
      0   1   2   3   4   5

가운데 A[2] = 5 를 읽는다.  5 < 7 이고 A 는 오름차순이다
      1   3   5 │ 7   9  11
      └ 이 셋은 전부 5 이하 ┘   → 7 은 여기 없다. 후보는 오른쪽 셋뿐이다
```

한 번 읽고 후보가 여섯에서 셋이 됐습니다. 남은 셋에 같은 절차를 그대로 다시 적용하면 되고,
그러려면 후보가 어디부터 어디까지인지를 두 인덱스로 나타내면 돼요.

```text
후보 수    6      3      1      0
읽은 칸        1      1      1
               └ 한 번 읽을 때마다 후보가 절반 이하로 준다
```

후보가 `N` 개에서 시작해 매번 절반 이하로 주니, 읽는 칸 수는 `N` 이 아니라 `log₂ N` 규모가
됩니다. `N = 10^6` 이면 100만 번이 20 번이에요. 다만 이 절차가 요구하는 조건이 둘 있습니다.

```text
요구하는 조건 둘
  ┗ A[k] ≤ A[k+1]         정렬돼 있어야 「이쪽 전체는 답이 아니다」를 말할 수 있다
  ┗ A[k] 를 바로 읽는다    가운데로 건너뛸 수 있어야 한다. 연결 리스트로는 안 된다
```

둘 중 하나가 깨지면 절차가 성립하지 않아요. 정렬이 어긋나 있으면 답이 틀린 채로 나오고,
인덱스로 건너뛸 수 없으면 가운데를 읽는 데만 `N/2` 칸을 지나야 해서 얻는 것이 없습니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **배열의 인덱스 접근이 `O(1)`** 이라는 것. `A[k]` 를 읽는 데 `k` 가 얼마인지도, 배열 길이가
  얼마인지도 상관없어요.
- **오름차순 정렬의 뜻** — 모든 이웃 쌍에서 `A[k] ≤ A[k+1]` 입니다. 「작은 값이 앞쪽에 많다」가
  아니라 **예외 없이** 그렇다는 뜻이에요. 정렬하는 절차 자체가 궁금하면
  [퀵 정렬 가이드](../../sorting/quicksort/quicksort-guide.md)에 있습니다.
- **밑이 2 인 로그** — `log₂ N` 은 `N` 을 2 로 몇 번 나눠야 1 이하가 되는가입니다.
  `log₂ 10^6 ≈ 19.93` 이에요.
- **반복문 불변식** — 반복이 한 바퀴를 시작할 때마다 참으로 남는 문장. 이 글의 뒷부분이
  그 문장 하나로 정확성을 설명합니다.

두 번째가 흐릿하면 이 글의 절반이 어긋납니다. 정렬을 「작은 게 앞쪽」 정도로 잡고 있으면
「이쪽 절반에는 없다」가 왜 참인지 확인할 수 없어요.

### 아이디어 상세 — 후보 구간 반토막을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function binarySearch(A: number[], target: number): number;
```

- 입력: **오름차순으로 정렬된** 정수 배열 `A` 와 찾는 값 `target`.
- 출력: `A[i] === target` 인 인덱스 `i`. 그런 `i` 가 없으면 `-1` 입니다.
- 제약: 배열 길이 `N` 은 0 이상 `10^6` 이하, 값과 `target` 은 32비트 정수 범위,
  시간 제한 1초입니다.

여기서 눈여겨볼 것이 하나 있어요. 값이 **어떤 규칙으로 놓였는지**는 문제가 말해 주지 않습니다 —
고르게 퍼졌는지 한쪽에 몰렸는지 모르는 채로 풀어야 해요.

```text
쓸 수 있는 것이 셋이다
  ┗ A[k] 를 인덱스로 바로 읽는다    읽는 비용이 k 와 무관하다
  ┗ 두 값의 크기를 비교한다         A[k] 와 target 중 어느 쪽이 큰가
  ┗ 정렬 조건 A[k] ≤ A[k+1]         칸 하나를 읽으면 그 양옆 전체를 말할 수 있다
```

이 글이 쓰는 기호는 여섯이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `N` | 배열 `A` 의 길이 | `0 ≤ N ≤ 10^6` |
| `A` | 오름차순으로 정렬된 배열. `A[k]` 가 `k` 번째 값 | `A[k] ≤ A[k+1]` |
| `target` | 찾는 값 | 32비트 정수 범위 |
| `lo` · `hi` | 후보 구간의 왼쪽 끝 · 오른쪽 끝. 폐구간입니다 | `0 ≤ lo`, `hi < N` |
| `mid` | 후보 구간에서 이번에 읽을 인덱스 | `lo ≤ mid ≤ hi` |
| `Q` | 같은 배열에 거는 조회 횟수 | 저장소 테스트가 `Q = 1,000` |

가장 먼저 떠오르는 방법은 왼쪽부터 하나씩 확인하는 것입니다. 정렬됐다는 사실을 아직 쓰지
않는, 배열이 어떤 모양이든 통하는 방법이에요.

```ts
function linearSearch(A: number[], target: number): number {
  for (let k = 0; k < A.length; k++) {
    if (A[k] === target) return k;
  }
  return -1;
}
```

이 방법은 답을 틀리지 않습니다. 문제는 비용인데, `target` 이 맨 끝에 있거나 아예 없으면 `N`
칸을 전부 읽어야 해요. `N = 10^6` 이면 최악 100만 번인데, 초당 1억 번으로 잡으면 0.01초라
**호출이 한 번뿐이라면 이 방법도 1초 안에 들어갑니다.**

그러니 한 번 호출로는 이 방법이 반박되지 않아요. 이 함수가 실제로 쓰이는 모양은 다릅니다 —
정렬된 배열 하나를 두고 조회를 `Q` 번 하는 것이고, 이 저장소의 `binarySearch.test.ts` 도
`N = 1,000,000` 배열에 `Q = 1,000` 번 호출해 100밀리초 안에 끝나기를 요구합니다.

| 조회 횟수 `Q` | 선형 탐색 비교 | 이진 탐색 비교 | 초당 1억 번 기준 |
| --- | --- | --- | --- |
| 1 | 1,000,000 | 20 | 0.01초 |
| **1,000** | **1,000,000,000** | **20,000** | **10초** |

10억 번입니다. 요구 시간은 0.1초인데 10초가 넘어요. 100배가 아니라 5만 배 차이인데, 그 차이가
어디서 나오는지 보려면 선형 탐색이 한 번 읽고 무엇을 알아내는지부터 세어 봐야 합니다.

```text
A = [ 1   3   5   7   9  11 ]     target = 7
      0   1   2   3   4   5

A[0] = 1 을 읽는다
  선형 탐색이 쓰는 것   1 ≠ 7 → 인덱스 0 은 답이 아니다            빼는 칸 1 개
  정렬 조건까지 쓰면    1 < 7 이니 A[0] 이하의 칸도 전부 아니다     빼는 칸 1 개
                       └ 인덱스 0 의 왼쪽에 칸이 없어서 더 빠지지 않는다
```

맨 앞 칸은 왼쪽에 아무것도 없어서 정렬 조건을 써도 얻는 것이 없습니다. 그러면 안쪽 칸을 읽어
봅시다.

```text
A[4] = 9 를 읽는다.  9 > 7 이고 오름차순이다
      1   3   5   7 │ 9  11
                     └ A[4] 이상은 전부 7 보다 크다 → 인덱스 4·5 를 뺀다   2 개

A[1] = 3 을 읽는다.  3 < 7 이고 오름차순이다
      1   3 │ 5   7   9  11
      └ A[1] 이하는 전부 7 보다 작다 → 인덱스 0·1 을 뺀다                  2 개
```

한 번 읽고 두 칸을 뺐어요. 읽은 칸이 안쪽일수록 한쪽이 두꺼워지니, 남은 질문은 **어느 칸을
읽을 것인가** 하나입니다. 비용도 여기서 정해져요 — 답을 낼 때까지 **읽은 칸 수**가 이 절차의
비용입니다.

같은 배열에 없는 값 `target = 12` 를 넣고 두 방식으로 세어 봅시다. 하나는 남은 후보의 첫 칸을
읽고, 하나는 가운데를 읽어요.

```text
첫 칸을 읽는다 — 6 번                  가운데를 읽는다 — 3 번
  후보 [0,5]  A[0]=1  < 12 → [1,5]      후보 [0,5]  A[2]=5  < 12 → [3,5]
  후보 [1,5]  A[1]=3  < 12 → [2,5]      후보 [3,5]  A[4]=9  < 12 → [5,5]
  후보 [2,5]  A[2]=5  < 12 → [3,5]      후보 [5,5]  A[5]=11 < 12 → 후보가 빈다
  후보 [3,5]  A[3]=7  < 12 → [4,5]
  후보 [4,5]  A[4]=9  < 12 → [5,5]           └ 후보가 6 → 3 → 1 → 0
  후보 [5,5]  A[5]=11 < 12 → 후보가 빈다
       └ 후보가 6 → 5 → 4 → 3 → 2 → 1 → 0
```

첫 칸을 읽으면 후보가 매번 1 개씩 줍니다. 가운데를 읽으면 절반씩 줄어요. 답은 두 경우 다
`-1` 로 같고 코드의 나머지도 같은데, 읽은 칸 수가 6 과 3 으로 갈립니다.

여기서 관찰한 것은 하나예요 — **한 번 읽고 남는 후보 수**가 비용을 정합니다. 그러면 그 수를
무엇으로 적을지부터 정해야 해요.

```text
후보를 두 인덱스로 나타낸다

   lo              hi          후보 수 m = hi - lo + 1
    |--- 후보 ---|
    └ 이 바깥은 이미 답이 아니라고 정해진 칸이다
```

후보가 `m` 개일 때 왼쪽에서 `k` 번째 칸을 읽으면 갈래가 셋입니다. 그 칸이 답이면 끝나고,
아니면 한쪽이 통째로 빠져요.

```text
후보 m 개에서 왼쪽부터 k 번째 칸을 읽는다

  ┃←  k-1 개  →┃ k 번째 ┃←  m-k 개  →┃
  읽은 값 > target 이면   왼쪽 k-1 개만 남는다
  읽은 값 < target 이면   오른쪽 m-k 개만 남는다
  읽은 값 = target 이면   끝난다

  최악에 남는 후보 = max(k-1, m-k)
```

**가장 단순한 후보부터 시험해 봅시다.** `k = 1`(첫 칸)이면 `max(0, m-1) = m-1` 이라 후보가
한 개만 줄고, `k = m`(마지막 칸)이면 `max(m-1, 0) = m-1` 로 똑같아요. 위에서 센 6 번이 바로
그 값입니다.

`max(k-1, m-k)` 는 `k` 가 커지면 앞 항이 늘고 뒤 항이 줍니다. 두 항이 만나는 자리가 가장 작고,
그 자리가 후보의 한가운데예요. 글에서 쓰는 `lo`·`hi`·`mid` 는 코드에서도 같은 이름이고,
가운데 자리는 `mid = lo + ⌊(hi - lo) / 2⌋` 입니다.

```text
각 값이 움직이는 범위

  lo    mid + 1 로만 커진다.   한 번에 (mid - lo + 1) 칸, 최소 1 칸
  hi    mid - 1 로만 작아진다. 한 번에 (hi - mid + 1) 칸, 최소 1 칸
  m     m → max(k-1, m-k) 이하. 가운데를 읽으면 ⌈(m-1)/2⌉ 이하
        └ 위에서 센 자취가 그대로 이 범위다. 6 → 3 → 1 → 0 이 ⌈(m-1)/2⌉ 이다
```

후보 구간이 실제로 줄어드는지 값으로 확인해 봅시다. 쉬운 경우는 후보가 셋 이상일 때예요 —
`mid` 가 `lo` 와 `hi` 사이에 있어서 어느 갈래로 가도 양쪽 끝 중 하나가 안쪽으로 들어옵니다.

```text
후보 [0,5], target = 12, mid = 2
  A[2] = 5 < 12  →  lo = 3.  후보가 6 개에서 3 개가 됐다
```

불안한 경우는 후보가 **둘**일 때입니다. `m = 2` 면 `mid = lo + ⌊1/2⌋ = lo` 라 읽는 칸이 왼쪽
끝이에요. 그러면 `hi = mid - 1` 로 가는 갈래에서 `hi` 가 `lo - 1` 이 되는데, 이것이 후보가
줄어든 것인지 상태가 어긋난 것인지부터 확인해야 합니다.

```text
A = [1 3 5 7 9 11], target = 2, 후보가 [0,1] 로 줄어든 다음

  mid = 0 + ⌊1/2⌋ = 0    A[0] = 1 < 2  →  lo = 1     후보 [1,1]   1 개
  mid = 1 + ⌊0/2⌋ = 1    A[1] = 3 > 2  →  hi = 0     후보 [1,0]   0 개
                                                       └ lo > hi 라 반복이 끝난다
```

두 갈래 다 후보가 실제로 줄었어요. `hi` 가 `lo` 보다 작아진 것은 상태가 어긋난 것이 아니라
**후보가 비었다**는 뜻이고, 반복 조건 `lo <= hi` 가 그 자리에서 거짓이 됩니다. 후보가
하나(`m = 1`)일 때도 `mid = lo = hi` 라 두 갱신 모두 후보를 비워요.

그래서 이렇게 말할 수 있습니다 — 반복이 끝나는 시점에 `lo > hi` 이고, 그때까지 모든 칸은
답으로 반환됐거나 후보에서 정확히 한 번 빠졌습니다. 건너뛴 칸이 없어요.

```text
반복이 끝나는 자리는 둘뿐이다
  읽은 값 = target   답을 찾았다   →  그 인덱스
  lo > hi            후보가 비었다 →  -1
                     └ 그 밖에는 후보가 반드시 줄어든 채로 다음 바퀴로 넘어간다
```

**이제 「가운데가 가장 적다」를 값으로 확인합시다.** 읽는 자리만 바꾸고 나머지는 그대로 둔
절차 넷을, 배열 세 벌에 있는 값과 없는 값 전부에 걸어 **최악 비교 횟수**를 셉니다.

<!--proof:spot-choice-->

```text
읽는 자리      n = 6   n = 15   n = 63
첫 칸              6       15       63
1/4 지점           5        8       12
가운데             3        4        6
마지막 칸          6       15       63
⌊log₂ n⌋ + 1       3        4        6
                                └ 가운데를 읽은 줄과 같다
```

가운데가 셋 다 가장 적고, 그 값이 `⌊log₂ n⌋ + 1` 과 정확히 같습니다. 첫 칸과 마지막 칸은
배열 길이 그대로예요 — 선형 탐색의 비교 횟수와 같은 값입니다.

1/4 지점은 그 사이에 있어요. `n = 63` 에서 12 번인데 가운데의 6 번보다 두 배입니다. **한쪽으로
치우칠수록 최악이 늘어난다**는 것이 이 표가 보이는 것이고, 임의의 `n` 에 대해 왜 한가운데가
최소인지는 「수식 정의와 유도」에서 풉니다.

```text
후보 6 개에서 최악에 남는 후보 수 max(k-1, 6-k)
  k = 1   max(0, 5) = 5        k = 4   max(3, 2) = 3
  k = 2   max(1, 4) = 4        k = 5   max(4, 1) = 4
  k = 3   max(2, 3) = 3        k = 6   max(5, 0) = 5
                                 └ 가운데 둘이 가장 작다
```

**후보 구간 반토막 한 벌이 나왔습니다.** 후보를 폐구간 `[lo, hi]` 로 두고, 그 가운데 칸을
읽어 셋 중 한 갈래로 후보를 줄이고, 후보가 빌 때까지 되풀이하는 것이에요. `N = 10^6` 에서
100만 번이던 비교가 20 번이 됩니다.

### 수행으로 알아보는 알고리즘 — 여섯 칸에서 7 의 자리를 찾는다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지
가되, 조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const A = [1, 3, 5, 7, 9, 11];
const target = 7;
// 이 절이 끝나면 3 이 나와야 한다
```

`target` 을 왜 하필 7 로 뒀을까요? 갈래 셋을 **모두 실행하게** 하려는 것입니다. 7 은 배열에
있으니 마지막에 갈래 ① 이 나오고, 그 앞의 두 비교에서 ③ 과 ② 가 한 번씩 나와요. 5 를 골랐다면
첫 비교에서 바로 끝나 나머지 둘을 못 봅니다.

```text
binarySearch(A, target):
    후보 구간을 [0, N-1] 로 잡는다
    lo <= hi 인 동안:
        mid ← lo + ⌊(hi - lo) / 2⌋
        A[mid] = target 이면  mid 를 반환한다     ① 같다
        A[mid] > target 이면  hi ← mid - 1        ② target 이 더 작다
        A[mid] < target 이면  lo ← mid + 1        ③ target 이 더 크다
    후보가 비었다 → -1 을 반환한다
```

#### 1. 후보 구간을 배열 전체로 잡는다

처음에는 어느 칸도 후보에서 빠지지 않았으니 후보는 배열 전체입니다. 폐구간이라 오른쪽 끝은
`A.length - 1` 이에요.

```ts
let lo = 0;
let hi = A.length - 1;
```

실행하면 이렇게 나옵니다. 빈 배열이 여기서 이미 처리된다는 것이 이 두 줄의 두 번째 일이에요.

```text
A = [1 3 5 7 9 11]   →   lo = 0, hi = 5,  후보 6 개
A = []               →   lo = 0, hi = -1, 후보 0 개
                          └ lo <= hi 가 처음부터 거짓이라 아래 반복에 들어가지 않는다
```

#### 2. 가운데 칸을 정한다

후보 `[lo, hi]` 의 한가운데를 정합니다. `(lo + hi) / 2` 가 아니라 `lo` 를 기준으로 더하는
형태를 써요.

```ts
const mid = lo + Math.floor((hi - lo) / 2);
```

두 식은 이 문제에서 같은 값을 냅니다. 그래도 아래 형태를 쓰는 것은 `lo + hi` 가 아무리 커져도
`hi - lo` 는 배열 길이를 넘지 않아, 중간 계산이 표현 범위 안에 남기 때문이에요.

```text
lo = 0, hi = 5   →  0 + ⌊(5-0)/2⌋ = 0 + 2 = 2        (lo+hi)/2 = ⌊5/2⌋ = 2
lo = 3, hi = 5   →  3 + ⌊(5-3)/2⌋ = 3 + 1 = 4        (lo+hi)/2 = ⌊8/2⌋ = 4
lo = 3, hi = 3   →  3 + ⌊(3-3)/2⌋ = 3 + 0 = 3        (lo+hi)/2 = ⌊6/2⌋ = 3
                    └ 세 자리 다 같다. 이 문제에서는 어느 쪽으로 적어도 답이 같다
```

#### 3. 비교 결과로 후보를 줄인다

읽은 값과 `target` 을 비교하면 갈래가 셋입니다. 같으면 답이고, 아니면 읽은 칸을 포함해 한쪽을
통째로 뺍니다.

```ts
if (A[mid] === target) {
  return mid; // ① 같다
}
if (target < (A[mid] as number)) {
  hi = mid - 1; // ② target 이 더 작다
} else {
  lo = mid + 1; // ③ target 이 더 크다
}
```

여기서 가장 중요한 것은 `mid - 1` 과 `mid + 1` 의 `1` 입니다. 읽은 칸은 이미 답이 아니라고
확인됐으니 후보에 남길 이유가 없고, 남기면 후보가 줄지 않는 자리가 생겨요.

```text
후보 [0,1] 에서 mid = 0, A[0] = 1 < 2 일 때

  lo = mid + 1 = 1  →  후보 [1,1]   1 개.  다음 바퀴가 다른 칸을 읽는다
  lo = mid     = 0  →  후보 [0,1]   2 개.  다음 바퀴가 같은 칸을 또 읽는다
                        └ 상태가 그대로라 반복이 끝나지 않는다
```

#### 멈춤 — 값이 중복되면 가장 왼쪽 인덱스가 나오지 않는다

「이진 탐색은 그 값이 처음 나오는 자리를 준다」고 알고 계실 수 있는데, 이 코드는 그렇지
않습니다. 갈래 ① 이 `mid` 를 그 자리에서 반환하니, 같은 값이 여러 칸에 있으면 **먼저 읽힌
칸**이 나와요. 실행하면 이렇게 나옵니다.

<!--proof:duplicate-index-->

```text
배열            target   이 코드가 준 인덱스   가장 왼쪽 인덱스
[1 3 3 3 3 5]        3                     2                  1
[3 3 3 3]            3                     1                  0
[2 4 4 6]            4                     1                  1
                                               └ 세 벌 중 2 벌에서 어긋난다
```

`[1 3 3 3 3 5]` 에서 3 이 있는 칸은 넷인데 이 코드는 2 를 줍니다. 계약이 「그런 인덱스 하나」를
요구하므로 **답이 틀린 것은 아니에요** — 테스트도 그대로 통과합니다. 그래서 이 자리가
함정이고, `[2 4 4 6]` 처럼 우연히 가장 왼쪽이 나오는 경우까지 섞여 있어 더 그렇습니다.

```text
[1 3 3 3 3 5] 에서 3 을 찾으면
  인덱스   0   1   2   3   4   5
  값       1   3   3   3   3   5
               └───┴───┴───┘   3 이 있는 칸은 넷이다
                   ↑ 이 코드가 주는 자리. 가장 왼쪽도 가장 오른쪽도 아니다
```

문제가 되는 것은 이 함수로 **개수를 세거나 구간을 잡을 때**예요. 「3 이 몇 개인가」를
`가장 오른쪽 - 가장 왼쪽 + 1` 로 구하려는데 반환값이 그 둘 중 어느 것도 아니면 답이 어긋납니다.
갈래 ① 에서 바로 반환하지 않고 `hi = mid - 1` 로 왼쪽을 계속 좁히면 가장 왼쪽 자리가 나오는데,
그 변형이 무엇의 사례인지는 파트 1 의 마지막에서 이름을 붙입니다.

#### 4. 여섯 칸에서 7 을 실제로 찾는다

앞의 세 조각을 이어 `binarySearch(A, 7)` 을 실행하면 반복이 세 바퀴입니다. 갈래 ①·②·③ 이
각각 어디서 실행되는지 함께 적었어요.

<!--viz:probe-->
```text
T1  후보 [0,5]  lo = 0, hi = 5.  후보 6 개
T2  mid = 0 + ⌊5/2⌋ = 2
T3  A[2] = 5    5 = 7 거짓,  7 < 5 거짓  →  ③  lo = 3
T4  mid = 3 + ⌊2/2⌋ = 4
T5  A[4] = 9    9 = 7 거짓,  7 < 9 참    →  ②  hi = 3
T6  mid = 3 + ⌊0/2⌋ = 3
T7  A[3] = 7    7 = 7 참                 →  ①  3 을 반환한다
```

<!--result:probe=3-->

한 걸음마다 조건이 어떻게 판정되는지 전부 적으면 아래 일곱 단계입니다.

| 단계 | 무슨 일 | 조건 판정 | `lo` | `hi` | 후보 수 |
| --- | --- | --- | --- | --- | --- |
| T1 | 후보를 배열 전체로 | `lo = 0`, `hi = 5` | `0` | `5` | 6 |
| T2 | 반복 진입, 가운데 계산 | `0 <= 5` 가 **참** | `0` | `5` | 6 |
| T3 | `A[2] = 5` 를 읽는다 | `5 === 7` **거짓**, `7 < 5` **거짓** → ③ | `3` | `5` | 3 |
| T4 | 반복 진입, 가운데 계산 | `3 <= 5` 가 **참** | `3` | `5` | 3 |
| T5 | `A[4] = 9` 를 읽는다 | `9 === 7` **거짓**, `7 < 9` **참** → ② | `3` | `3` | 1 |
| T6 | 반복 진입, 가운데 계산 | `3 <= 3` 이 **참** | `3` | `3` | 1 |
| T7 | `A[3] = 7` 을 읽는다 | `7 === 7` 이 **참** → ① | `3` | `3` | 1 |

**세 갈래가 모두 나왔습니다.** 비교는 T3·T5·T7 셋이고 반환값은 3 이에요. 후보 수가 6 → 3 → 1
로 줄었고, 이것이 「아이디어 상세」에서 센 `⌈(m-1)/2⌉` 자취와 같은 값입니다.

없는 값을 넣으면 반복이 어떻게 끝나는지도 봐야죠. 같은 배열에 `target = 4` 를 넣습니다.

```text
T8   후보 [0,5]  mid = 2   A[2] = 5    4 < 5 참   →  ②  hi = 1      후보 2 개
T9   후보 [0,1]  mid = 0   A[0] = 1    4 < 1 거짓 →  ③  lo = 1      후보 1 개
T10  후보 [1,1]  mid = 1   A[1] = 3    4 < 3 거짓 →  ③  lo = 2      후보 0 개
T11  lo = 2 > hi = 1 이라 반복 조건이 거짓  →  -1 을 반환한다
```

T11 에서 `lo` 가 `hi` 를 넘었어요. 이것이 「후보가 비었다」의 뜻이고, 답을 못 찾고 끝나는
자리는 이 하나뿐입니다.

#### 멈춤 — 정렬돼 있지 않은 배열을 넣어도 오류 없이 값이 나온다

「정렬 안 된 배열을 넣으면 예외가 나거나 `-1` 이 나오겠지」라고 생각하기 쉬운데, 그렇지
않습니다. 코드가 하는 일은 인덱스를 읽고 크기를 비교하는 것뿐이라, 정렬 조건이 어긋나 있어도
**끝까지 실행되고 값이 하나 나와요.** 실행하면 이렇게 나옵니다.

<!--proof:unsorted-answer-->

```text
배열          target   이 코드의 답   실제 인덱스
[5 1 3]            5             -1             0
[3 1 2]            2              2             2
[9 7 5 3 1]        1             -1             4
                                      └ 예외는 나지 않는다. 1 벌만 우연히 맞는다
```

`[5 1 3]` 에서 5 는 인덱스 0 에 있는데 이 코드는 `-1` 을 줍니다. 그런데 `[3 1 2]` 에서 2 를
찾으면 인덱스 2 로 **맞아요** — 우연히 맞는 경우가 섞여 있는 것이 이 자리를 특히 어렵게
만듭니다.

```text
[5 1 3] 에서 5 를 찾는 자취
  후보 [0,2]  mid = 1   A[1] = 1   5 < 1 거짓  →  ③  lo = 2
  후보 [2,2]  mid = 2   A[2] = 3   5 < 3 거짓  →  ③  lo = 3   후보가 빈다
                        └ 「A[1] 이하는 전부 5 보다 작다」가 거짓이다. A[0] = 5 다
```

갈래 ②·③ 이 옳은 근거는 정렬 조건 하나뿐입니다. 그 조건이 없으면 「이쪽 전체는 답이 아니다」를
말할 수 없고, 그 순간 이 절차는 아무것도 보장하지 않아요. 테스트 배열을 손으로 적을 때 정렬을
어긋나게 적어 두면 이 함수가 아니라 그 테스트가 거짓을 말합니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 반복이 끝난 뒤 `-1` 을
돌려주는 마지막 줄뿐이에요.

```ts
export function binarySearch(A: number[], target: number): number {
  // 후보 구간은 닫힌 구간 [lo, hi] 다. 빈 배열이면 hi = -1 이라 아래 반복에 들어가지 않는다.
  let lo = 0;
  let hi = A.length - 1;

  while (lo <= hi) {
    // (lo + hi) / 2 가 아니라 lo 를 기준으로 더한다. 두 인덱스의 합이 표현 범위를 넘지 않는다.
    const mid = lo + Math.floor((hi - lo) / 2);

    if (A[mid] === target) {
      // ① 같다 — 이 인덱스가 답이다.
      return mid;
    }
    if (target < (A[mid] as number)) {
      // ② target 이 더 작다 — mid 부터 오른쪽 전부를 후보에서 뺀다.
      hi = mid - 1;
    } else {
      // ③ target 이 더 크다 — mid 까지 왼쪽 전부를 후보에서 뺀다.
      lo = mid + 1;
    }
  }

  // 후보 구간이 비었다. target 은 A 안에 없다.
  return -1;
}
```

```text
binarySearch([1, 3, 5, 7, 9, 11], 7)   →   3
binarySearch([1, 3, 5, 7, 9, 11], 4)   →   -1
binarySearch([], 1)                    →   -1
binarySearch([42], 42)                 →   0
```

### 알아 두면 좋은 개념 — 단조 술어와 이분법

T3·T5·T7 에서 물은 것은 셋 다 같은 꼴이었습니다 — 「읽은 값이 `target` 보다 작은가」예요.
그 물음의 답을 인덱스마다 미리 적어 보면 모양이 하나 나옵니다.

```text
k                0     1     2     3     4     5
A[k]             1     3     5     7     9    11
A[k] < 7 인가    참    참    참   거짓  거짓  거짓
                             └──┘ 한 번 거짓이 되면 끝까지 거짓이다
                                  경계는 k = 3. 이 코드가 찾은 자리와 같다
```

인덱스가 커질 때 참에서 거짓으로 **한 번만** 바뀌는 물음을 단조 술어라고 하고, 그 경계를
절반씩 좁혀 찾는 절차를 이분법이라고 합니다. 이 편이 정렬을 요구한 것은 `A[k] < target` 이라는
물음을 단조로 만들기 위해서였어요 — 정렬 자체가 목적이 아니라 단조가 목적입니다.

| 같은 이름이 다시 나오는 자리 | 무엇이 단조인가 | 경계가 무엇인가 |
| --- | --- | --- |
| 가장 왼쪽 인덱스 찾기 | `A[k] ≥ target` | 그 값이 처음 나오는 칸 |
| 답 자체를 후보로 두는 문제 | 「무게 `w` 로 자를 수 있는가」 | 조건을 만족하는 최소 `w` |
| 실수 구간에서 `f(x) = 0` 풀기 | `f(x)` 의 부호 | 부호가 바뀌는 자리 |

세 자리 다 배열이 없거나 값이 정수가 아닌데도 같은 절차가 그대로 걸립니다. 「정렬된 배열에서
값 찾기」는 단조 술어 위의 이분법 중 **가장 익숙한 한 가지**예요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 비교 횟수를 임의의 `N` 으로
어떻게 내는지, 무엇이 매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- 배열이 **이미 정렬돼 있고**, 그 정렬 비용을 이 절차가 지지 않습니다. 정렬을 직접 해야 하는데
  조회가 한 번뿐이면 선형 탐색이 더 적어요.
- **인덱스로 아무 칸이나 바로 읽을 수 있습니다.** 연결 리스트처럼 앞에서부터 따라가야 하는
  자료에서는 가운데를 읽는 것만으로 `N/2` 칸입니다.
- 값에 **전순서**가 있습니다. 두 값 중 어느 쪽이 큰지 늘 정해져요.
- 자료가 **자주 바뀌지 않습니다.** 삽입할 때마다 정렬을 유지해야 하는데, 배열 가운데 삽입은
  `Θ(N)` 이에요.

```text
네 조건이 코드의 모양을 그대로 정한다
  이미 정렬돼 있다   →  A[k] ≤ A[k+1] 을 근거로 한쪽을 통째로 뺀다
  인덱스로 읽는다    →  mid 로 바로 건너뛴다
  전순서가 있다      →  갈래가 셋뿐이다. 네 번째 결과가 없다
  잘 안 바뀐다       →  삽입·삭제를 다루는 코드가 아예 없다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "오름차순으로 주어진다"    "정렬된 상태로 입력된다"
  "쿼리가 Q 개 주어진다"      "각 질의마다 …를 출력하라"

제약에 이런 모양이 보이면
  배열 길이가 10^5 ~ 10^6 이고 질의 수도 그만큼이다
  값의 범위는 큰데 배열 길이는 작다      ← 값이 아니라 인덱스를 후보로 둔다
```

반대로 「입력 순서를 유지해야 한다」거나 「값을 자주 넣고 뺀다」는 말이 있으면 이 단서는
해당하지 않습니다. 그때는 해시 표나 균형 이진 탐색 트리처럼 삽입·삭제를 함께 다루는
자료구조를 골라야 해요.

한 가지 더 있습니다. **「…를 만족하는 최소/최대 값을 구하라」** 는 배열이 아예 안 나오는데도
이 절차를 부르는 단서예요. 답이 될 수 있는 값의 범위를 후보 구간으로 두면, 파트 1 의 마지막에서
이름을 붙인 그 성질 덕분에 같은 절차가 그대로 걸립니다.

#### 실제로 쓰이는 곳

- **Go 표준 라이브러리 `sort.Search`** — 문서 주석이 이 절차의 조건을 그대로 적어 둡니다:
  *"Search uses binary search to find and return the smallest index i in [0, n) at which f(i) is
  true, assuming that on the range [0, n), f(i) == true implies f(i+1) == true."* 가운데는
  `h := int(uint(i+j) >> 1)` 로 정하고 그 줄에 `avoid overflow when computing h` 라는 주석이
  붙어 있어요.
  ([`src/sort/search.go`](https://github.com/golang/go/blob/master/src/sort/search.go), 조회 2026-08-29)
- **OpenJDK `java.util.Arrays.binarySearch`** — `int mid = (low + high) >>> 1;` 로 적혀
  있습니다. `>>>` 는 부호 없는 오른쪽 자리 이동이라 `low + high` 가 `int` 범위를 넘어 음수가
  되어도 가운데 인덱스가 바르게 나와요. 자바는 정수가 32비트라 이 문제가 실제로 생깁니다.
  ([`java/util/Arrays.java`](https://github.com/openjdk/jdk/blob/master/src/java.base/share/classes/java/util/Arrays.java), 조회 2026-08-29)
- **CPython 표준 라이브러리 `bisect`** — `bisect_left` 의 문서 문자열이 반환값을 이렇게
  적습니다: *"The return value i is such that all e in a[:i] have e < x, and all e in a[i:] have
  e >= x."* 값이 있는 자리가 아니라 **경계**를 돌려주는 형태예요. 가운데는
  `mid = (lo + hi) // 2` 이고, 파이썬 정수는 크기 제한이 없어 넘칠 자리가 없습니다.
  ([`Lib/bisect.py`](https://github.com/python/cpython/blob/main/Lib/bisect.py), 조회 2026-08-29)

셋 중 둘(Go·CPython)이 값의 인덱스가 아니라 **경계**를 돌려준다는 것이 눈에 띕니다. 절차는
같고 반환 규칙만 다른 것인데, 그 규칙이 중복된 값과 「이상인 첫 자리」까지 함께 답한다는 점에서
더 많은 것을 줍니다.

#### 경쟁 설계와의 대조

같은 목표를 노리는 **다른 절차**가 있어요 — **보간 탐색**입니다. 가운데를 읽는 대신 `target`
이 `A[lo]` 와 `A[hi]` 사이 어디쯤인지를 비례식으로 계산해 그 자리를 읽습니다.

```text
보간 탐색이 읽는 자리
  pos = lo + ⌊ (target - A[lo]) × (hi - lo) / (A[hi] - A[lo]) ⌋
        └ 값이 고르게 놓여 있다면 이 자리가 곧 target 의 자리다
```

같은 길이의 배열 두 벌에 둘을 걸고 **읽은 칸 수**를 셌습니다. 전개의 여섯 칸을 그대로 쓰지
않은 이유는 하나예요 — 값 여섯 개로는 「값이 고르게 놓였는가」를 말할 수 없는데, 이 대조가
갈리는 축이 바로 그것입니다.

입력은 난수 없이 식으로 만들었으니 시드가 없어요. 균등 입력은 `A[i] = 2i`, 편향 입력은
`A[i] = i²` 이고 둘 다 `i = 0 … 1,023` 입니다. 질의는 각 배열의 원소 1,024 개를 한 번씩 찾는
것이고요.

| 설계 | 균등 입력 읽은 칸 합 | 균등 입력 최악 | 편향 입력 읽은 칸 합 | 편향 입력 최악 |
| --- | --- | --- | --- | --- |
| 이진 탐색 (이 가이드) | 9,228 | 11 | **9,228** | **11** |
| 보간 탐색 | **1,024** | **1** | 10,026 | 32 |

**균등 입력에서는 보간 탐색이 훨씬 적습니다** — 읽은 칸이 1,024 대 9,228 이고 최악이 1 번이에요.
`A[i] = 2i` 에서는 비례식이 정확히 맞아떨어져 처음 읽은 칸이 늘 답입니다.

**편향 입력에서는 순서가 뒤집힙니다.** `A[i] = i²` 에서 보간 탐색은 10,026 칸을 읽고 최악이
32 번인데, 이진 탐색은 두 입력에서 똑같이 9,228 칸에 최악 11 번이에요. 값이 어떻게 놓였든
후보를 절반씩 접기 때문입니다.

```text
축을 넷으로 갈라 적으면
                          이진 탐색        보간 탐색
  균등 입력 읽은 칸        9,228            1,024      ← 보간이 적다
  편향 입력 읽은 칸        9,228           10,026      ← 이진이 적다
  최악 보장                ⌊log₂ n⌋ + 1     n          ← 이진이 강하다
  값에 요구하는 연산        비교만           뺄셈·나눗셈  ← 이진이 넓다
```

**이진 탐색이 내주는 것은 균등 입력에서의 읽은 칸 수입니다.** 1,024 대 9,228 이면 9 배 차이인데,
그것을 내주고 받는 것이 둘이에요 — 값이 어떻게 놓였든 최악이 `⌊log₂ n⌋ + 1` 로 고정되고, 값에
뺄셈·나눗셈을 요구하지 않아 문자열처럼 비교만 되는 값에도 그대로 쓸 수 있습니다.

**우열이 반대가 되는 조건이 분명합니다.** 값이 고르게 놓인다는 것을 아는 자료(균등하게 뽑은
정수, 일정 간격으로 늘어나는 시각)에는 보간 탐색이 답이고, 분포를 모르거나 한쪽으로 몰릴 수
있는 자료에는 이진 탐색이에요. 편향 입력의 최악 32 와 11 이 그 차이입니다.

### 수식 정의와 유도

후보가 $n$ 개일 때 한 번 읽고 최악에 남는 후보 수를 $R(n, k)$ 라 하고, 후보 $n$ 개를 답 하나로
줄이는 데 드는 최악 비교 횟수를 $C(n)$ 이라 합니다. $k$ 는 후보 중 왼쪽에서 몇 번째 칸을
읽는가입니다.

$$R(n, k) = \max(k-1,\; n-k)$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $n$ | 그 시점의 후보 수 | $0 \le n \le N$ |
| $k$ | 후보 중 왼쪽에서 몇 번째 칸을 읽는가 | $1 \le k \le n$ |
| $R(n,k)$ | 그 한 번을 읽고 최악에 남는 후보 수 | $0 \le R(n,k) \le n-1$ |
| $C(n)$ | 후보 $n$ 개를 끝낼 때까지의 최악 비교 횟수 | $C(0) = 0$ |

읽는 자리를 매번 최적으로 고른다고 두면 비교 횟수는 다음 관계를 만족합니다. 오른쪽의 `+1` 이
그 한 번의 비교예요.

$$C(n) = C\Bigl(\min_{1 \le k \le n} R(n,k)\Bigr) + 1, \qquad C(0) = 0$$

```text
후보 n 칸을 세 덩어리로 나눈다

  |---- k-1 칸 ----|- 1 칸 -|---- n-k 칸 ----|
       왼쪽 후보     읽는 칸     오른쪽 후보
                        ↑ 이 칸은 답이거나, 답이 아니라고 정해져 어느 쪽에도 안 들어간다
```

**정의를 값에 넣어 검산해 봅시다.** $n = 6$ 에 $k$ 여섯 자리를 전부 넣습니다.

```text
R(6,1) = max(0,5) = 5      R(6,4) = max(3,2) = 3
R(6,2) = max(1,4) = 4      R(6,5) = max(4,1) = 4
R(6,3) = max(2,3) = 3      R(6,6) = max(5,0) = 5
                             └ 최솟값 3. 파트 1 의 표에서 가운데가 6 → 3 이던 그 값이다
```

**이제 유도합니다.** $k-1$ 은 $k$ 가 커질 때 늘고 $n-k$ 는 줍니다. 한쪽만 커지면 그쪽이 최댓값이
되므로, 두 항이 만나는 자리에서 최댓값이 가장 작아요.

$$k - 1 = n - k \;\Longrightarrow\; k = \frac{n+1}{2}$$

```text
n = 6 에서 k 를 1 부터 6 까지 옮기면
  k-1     0   1   2   3   4   5      ← 늘어난다
  6-k     5   4   3   2   1   0      ← 줄어든다
  최댓값   5   4   3   3   4   5      ← 두 줄이 만나는 자리가 가장 작다
```

$n$ 이 짝수면 $k$ 가 정수로 딱 떨어지지 않으므로 양옆 둘 중 하나를 고릅니다. 어느 쪽을 골라도
최댓값이 같고, 그 값은 다음과 같아요.

$$\min_{1 \le k \le n} R(n,k) = \Bigl\lceil \frac{n-1}{2} \Bigr\rceil$$

```text
n = 6 에서 접으면   6 → ⌈5/2⌉ = 3 → ⌈2/2⌉ = 1 → ⌈0/2⌉ = 0
                    └ 세 번 접어서 후보가 빈다. C(6) = 3 이다
```

후보 수가 매번 절반 이하로 주므로, $C(n)$ 은 $n$ 을 1 이하가 될 때까지 2 로 나눈 횟수에 1 을
더한 값입니다. 그것이 밑이 2 인 로그의 정의라 닫힌 형태가 바로 나와요.

$$C(n) = \lfloor \log_2 n \rfloor + 1 \quad (n \ge 1), \qquad C(0) = 0$$

```ts
const R = (n: number, k: number): number => Math.max(k - 1, n - k);
const C = (n: number): number => (n <= 0 ? 0 : C(Math.ceil((n - 1) / 2)) + 1);

R(6, 3); // → 3
C(6); // → 3
C(1_000_000); // → 20
```

**마지막으로 계수입니다.** 제약 규모 `N = 10^6` 을 닫힌 형태에 넣습니다.

| $n$ | $\lfloor \log_2 n \rfloor + 1$ | 파트 1 에서 실제로 센 값 |
| --- | --- | --- |
| 6 | 3 | 3 |
| 15 | 4 | 4 |
| 63 | 6 | 6 |
| 1,000,000 | 20 | 세지 않았다 |

파트 1 의 표는 배열 세 벌에서 값을 센 것이라 그 세 벌 밖으로는 아무 말도 못 합니다. 닫힌
형태는 임의의 `n` 에 대해 값을 내니, 200만 개 넘는 질의를 걸어 보지 않고도 `N = 10^6` 의 답이
20 이라고 말할 수 있어요.

### 불변식 — target 이 배열에 있다면 그 인덱스는 항상 후보 구간 안에 있다

파트 1 에서 코드가 동작하는 것을 일곱 단계로 확인했습니다. 그건 입력 하나에서 맞았다는 뜻이지
언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이
실제로 유지되는지 확인해 봅시다.

> **반복이 한 바퀴를 시작하는 시점마다**, `target` 이 `A` 안에 있다면 그 인덱스는 `[lo, hi]`
> 안에 있습니다.

```text
                       lo             hi
  A =  [ 이미 뺐다  |--- 후보 ---|  이미 뺐다 ]
         └ 이 두 구역에 target 이 없다는 것이 매 바퀴 참이다
```

「반복이 한 바퀴를 시작하는 시점마다」가 중요합니다. 반복이 끝난 뒤 한 번만 참인 것이 아니라
**바퀴가 바뀔 때마다** 참이라는 뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** 반복에 들어가기 전 `lo = 0`, `hi = A.length - 1` 이라 후보가 배열
전체이고, 「`target` 이 `A` 안에 있다면 그 인덱스는 배열 안에 있다」는 참입니다. 그다음
한 바퀴마다 `A[mid]` 를 읽고 셋 중 하나를 실행해요.

| 읽은 값 | 하는 일 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| `A[mid] === target` | `mid` 를 반환한다 | 답을 실제로 찾았으니 후보를 더 볼 필요가 없다 |
| `target < A[mid]` | `hi = mid - 1` | `A` 가 오름차순이라 `A[mid]` 부터 `A[hi]` 까지는 전부 `A[mid]` 이상이고, `A[mid]` 는 `target` 보다 크다. 그 구역에 `target` 은 없다 |
| `target > A[mid]` | `lo = mid + 1` | 같은 이유로 `A[lo]` 부터 `A[mid]` 까지는 전부 `A[mid]` 이하이고 `target` 보다 작다 |

셋이 전부입니다 — 정수 비교에 네 번째 결과는 없어요. 그리고 두 갱신 모두 읽은 칸 `mid` 를
후보에서 빼므로 후보 수가 매 바퀴 최소 1 은 줄고, 유한한 배열에서 반복은 반드시 끝납니다.

반복이 끝나는 시점에는 `lo > hi` 라 후보가 비어 있어요. 불변식의 대우를 쓰면 「후보가 비었는데
`target` 이 `A` 안에 있다」가 참일 수 없으므로, 그 자리에서 `-1` 을 돌려주는 것이 옳습니다.

```text
후보 수가 매 바퀴 주는 것을 값으로

  m = 6  →  가운데를 읽고 남는 것은 max(2, 3) = 3 이하
  m = 3  →  max(1, 1) = 1 이하
  m = 1  →  max(0, 0) = 0
  m = 0  →  lo > hi.  반복 조건이 거짓이 된다
```

**경계에 있는 입력도 확인하고 갑시다.** 아래 일곱 줄이 이 함수가 받을 수 있는 모양의 끝입니다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| 빈 배열 `[]` | `hi = -1`, `lo = 0` → `lo <= hi` 가 처음부터 거짓 | 반복에 들어가지 않고 `-1` |
| 원소 하나, 일치 `[42]` 에서 `42` | `mid = 0`, 값이 같은 갈래 | `0` |
| 원소 하나, 불일치 `[42]` 에서 `7` | `lo = 1` 이 되어 후보가 빈다 | `-1` |
| 원소 둘 `[1 2]` 에서 `2` | `mid = 0` → `lo = 1` → `mid = 1` | `1` |
| 음수가 섞임 `[-10 -5 0 5 10]` 에서 `-5` | 비교 연산자만 쓰므로 부호와 무관 | `1` |
| 32비트 경계 `[-2147483648 … 2147483647]` | `number` 가 배정밀도라 정확히 표현된다 | 양 끝 다 정확 |
| 중복 `[1 3 3 3 3 5]` 에서 `3` | 먼저 읽힌 칸을 그 자리에서 반환한다 | `2` (가장 왼쪽이 아니다) |

**이제 깨뜨려 봅시다.** 불변식을 지키던 줄이 어느 것인지는 바꿔 보면 확인됩니다.
`hi = mid - 1` 은 「`mid` 부터 오른쪽은 `target` 이 아니다」까지만 말하는데, 거기서 한 칸을 더
빼 `hi = mid - 2` 로 적어 봅니다.

```ts
if (target < (A[mid] as number)) {
  hi = mid - 2; // ← 여기만 한 칸 더 뺀다. 원래는 hi = mid - 1 이다
}
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-hi-step-->

```text
배열              target   바른 코드   hi = mid - 2 로 적은 코드
[1 3 5 7 9 11]         3           1                          -1
[1 3 5 7 9 11]         7           3                          -1
[-10 -5 0 5 10]       -5           1                          -1
                                       └ 세 벌 다 답이 어긋난다
```

`[1 3 5 7 9 11]` 에서 3 을 찾으면 바른 코드는 1 을, 바꾼 코드는 `-1` 을 줍니다. 처음 읽는 칸이
인덱스 2 이고 `A[2] = 5 > 3` 이라 `hi` 가 1 이 되어야 하는데 0 이 됐어요. 그 순간 인덱스 1 이
후보에서 사라지는데, 3 은 바로 거기 있습니다.

```text
[1 3 5 7 9 11] 에서 3 을 찾는다.  mid = 2, A[2] = 5 > 3

  hi = mid - 1 = 1    후보 [0,1]   3 이 있는 인덱스 1 이 후보에 남는다
  hi = mid - 2 = 0    후보 [0,0]   인덱스 1 이 빠졌다
                                    └ 「있다면 후보 안에 있다」가 여기서 거짓이 된다
```

불변식이 요구하는 것은 「빼는 쪽에 `target` 이 없다」입니다. `A[mid] > target` 이 말해 주는
것은 `A[mid]` 부터 오른쪽까지이고, `A[mid - 1]` 에 대해서는 아무것도 말하지 않아요. 한 칸을
더 빼는 순간 근거 없이 후보를 버린 것이 됩니다.

### 비용 계산

#### 비용을 세는 과정

한 번의 반복이 하는 비교는 `A[mid]` 를 읽고 `target` 과 맞춰 보는 것뿐입니다. 전개의 T3·T5·T7
이 그 셋이고, T2·T4·T6 은 `mid` 를 정하는 산술이라 비교가 아니에요.

```text
T3  A[2] 를 읽고 7 과 비교     비교 1 번    후보 6 → 3
T5  A[4] 를 읽고 7 과 비교     비교 1 번    후보 3 → 1
T7  A[3] 을 읽고 7 과 비교     비교 1 번    답을 찾았다
                              └ 합 3 번
```

없는 값을 넣은 T8·T9·T10 도 셋입니다. 답을 찾아 끝나든 후보가 비어 끝나든 비교 횟수가 같아요 —
후보 수가 줄어드는 방식이 같기 때문입니다.

```text
후보 수     6       3       1       0
비교            1       1       1
                └ 후보 수가 ⌈(m-1)/2⌉ 로 접힐 때마다 비교가 한 번 는다
```

그러니 전체 비교 횟수는 **후보 수를 접은 횟수**이고, 최악은 후보가 0 이 될 때까지 접는
횟수입니다. `N = 10^6` 이면 20 번이고, 그 값을 임의의 `N` 으로 낸 것이 「수식 정의와 유도」의
닫힌 형태예요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 비교에서 맞는다) | `O(1)` | `Θ(1)` |
| **평균적인 경우** (찾는 값이 각 인덱스에 고르게 분포) | `O(log N)` | `Θ(log N)` |
| **최악의 경우** (후보가 빌 때까지 접는다) | `O(log N)` | `Θ(log N)` — 실제로 도달한다 |

최악에서 `Θ(log N)` 이라고 쓸 수 있는 것은 그 값을 **실제로 내는 입력이 있기** 때문입니다.
`A = [1 3 5 7 9 11]` 에 `target = 7` 을 넣으면 정확히 `3 = ⌊log₂ 6⌋ + 1` 번 비교해요.

**총식을 한 번은 정확히 적습니다.** 한 바퀴가 하는 일이 비교 하나·산술 몇 개·대입 하나라
상수 배로 묶이고, 바퀴 수가 곧 비교 횟수입니다.

```text
총식 = Θ(비교) + Θ(mid 계산) + Θ(대입)   =   Θ(log N)      시간
       추가로 잡는 칸은 lo · hi · mid 셋뿐   →   Θ(1)        공간

앞에 붙는 항이 있다면 정렬이다.  이미 정렬된 배열을 받는다는 것이 이 문제의 전제라
이 절차는 그 비용을 지지 않는다.  직접 정렬해야 한다면 Θ(N log N) 이 앞에 붙고,
조회가 한 번뿐이면 그때는 선형 탐색 Θ(N) 이 더 적다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 없고 입력 분포에 대한 가정도 없어요. 어떤
정렬된 배열과 어떤 `target` 을 넣어도 비교는 `⌊log₂ N⌋ + 1` 번을 넘지 않습니다.

```text
최악 보장   어떤 정렬된 배열과 어떤 target 에도 비교 ≤ ⌊log₂ N⌋ + 1     가정이 없다
기댓값      A = [1 3 5 7 9 11] 의 여섯 값을 각각 찾으면 2·3·1·3·2·3
            평균 14/6 ≈ 2.33 번, 최악 3 번
            └ 「찾는 값이 각 인덱스에 고르게 분포한다」는 입력 분포 가정 아래의 평균이다.
              구현이 만드는 무작위성이 아니라, 같은 입력에 늘 같은 횟수가 나온다
```

#### 최악을 만드는 입력

「정렬된 배열이 최악」 같은 말은 이 절차에 해당하지 않습니다. 입력 배열은 언제나 정렬돼 있고,
비용을 가르는 것은 배열이 아니라 **`target` 이 어디에 있는가**예요. 배열 안팎의 값을 전부
넣고 비교 횟수를 세면 이렇습니다.

<!--proof:worst-targets-->

```text
[1 3 5 7 9 11] 에 target 을 -1 부터 13 까지 넣는다

  비교 1 번   5
  비교 2 번   -1 · 0 · 1 · 9
  비교 3 번   2 · 3 · 4 · 6 · 7 · 8 · 10 · 11 · 12 · 13
              └ 가장 많은 것이 3 번 = ⌊log₂ 6⌋ + 1. 15 개 중 10 개가 여기 든다
```

가장 적은 것은 `target = 5` 의 1 번입니다. 처음 읽는 칸이 인덱스 2 이고 그 값이 5 라서요.
가장 많은 것은 3 번이고 열다섯 중 열 개가 여기 듭니다 — **최악이 드물지 않아요.**

```text
비교 1 번   5                   처음 읽는 칸(인덱스 2)의 값이다
비교 2 번   -1 · 0 · 1 · 9      두 번째로 읽는 칸에서 맞거나(1 · 9)
                                그 자리에서 후보가 비는 값(-1 · 0)이다
비교 3 번   나머지 열 개        후보 6 → 3 → 1 을 다 접어야 끝난다
```

최악을 실제로 만들려면 `target` 을 배열의 어느 값과도 다르게, 그리고 첫 두 번의 비교에서 후보가
비지 않도록 고르면 됩니다. `N` 이 커지면 이런 값이 대부분이라 **최악을 피하는 설계를 따로 하지
않아요** — 최악이 이미 `⌊log₂ N⌋ + 1` 로 작기 때문입니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 정렬 조건이 「한 칸을 읽으면 한쪽 전체가 답이
아니다」를 보장하고, 그 한쪽을 매번 빼면 후보가 절반 이하로 줄어 비교가 `⌊log₂ N⌋ + 1` 번을
넘지 않습니다.

```text
후보를 [lo, hi] 로 → 가운데를 읽는다 → 셋 중 한 갈래로 후보를 줄인다 → 후보가 비면 -1
                     └ 읽은 칸은 다시 후보에 넣지 않는다. 그래야 후보가 실제로 준다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T5 에서 `A[4] = 9` 가 `target` 보다 커서 `hi` 가 3 이
됐어요. 만약 그 자리에서 `hi = mid` 로 적었다면 무슨 일이 일어날까요?

```text
T5  후보 [3,5]  mid = 4   A[4] = 9 > 7   →  hi = mid - 1 = 3     후보 [3,3]
                                             hi = mid     = 4  ← 이렇게 적었다면?
```

<!--check:hi-mid-->
후보가 `[3,4]` 로 2 개 남고, 다음 바퀴의 `mid` 가 `3 + ⌊1/2⌋ = 3` 이라 `A[3] = 7` 을 읽어
답 3 이 그대로 나옵니다. **답도 맞고 비교 횟수도 3 번으로 같아요.** 그래서 이 자리는 테스트로
안 걸립니다. 문제는 `target` 이 배열에 없을 때예요.

```text
target = 8 을 넣으면

  hi = mid - 1    후보 [0,5] → mid=2, 5<8  → lo=3 → 후보 [3,5]
                             → mid=4, 8<9  → hi=3 → 후보 [3,3]
                             → mid=3, 8>7  → lo=4 → 후보가 빈다.  -1

  hi = mid        후보 [0,5] → mid=2, 5<8  → lo=3 → 후보 [3,5]
                             → mid=4, 8<9  → hi=4 → 후보 [3,4]
                             → mid=3, 8>7  → lo=4 → 후보 [4,4]
                             → mid=4, 8<9  → hi=4 → 후보 [4,4]   같은 상태다
                             └ 상태가 그대로라 반복이 끝나지 않는다
```
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 「수행으로 알아보는 알고리즘」의 T10       3 → 「알아 두면 좋은 개념」
  2 → 「불변식」
```

- T10 에서 후보가 1 개인데도 비교를 한 번 더 했습니다. 후보가 1 개면 그 칸이 답이라고 바로
  말할 수 없는 이유는 무엇일까요.
- 값이 같은 갈래에서 바로 반환하지 않고 `hi = mid - 1` 로 왼쪽을 계속 좁히면, 반복이 끝나는
  시점의 `lo` 는 무엇을 가리킬까요. 그 값이 배열에 없는 `target` 에 대해서는 무엇이 될까요.
- 배열이 아니라 **답의 범위**를 후보 구간으로 두는 문제 — 「무게 `w` 로 자를 수 있는가」가
  `w` 에 대해 단조라면, 조건을 만족하는 최소 `w` 를 어떻게 찾을까요.
