# 모든 단순 경로 열거 — 되돌아갈 때 표시를 지워야 다음 경로가 만들어진다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 정점 나열을 전부
만들어 놓고 거르는 방법에서 출발해, 되돌아갈 때 지우는 경로 표시까지 가고, 그 방법을 단계마다 값으로 푼 뒤,
실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**방향 그래프**는 정점들과, 한쪽으로만 지나갈 수 있는 간선으로 이루어집니다. `u → v` 간선이 있어도
`v → u` 로는 못 가요. 이 글이 만드는 것은 출발 정점에서 도착 정점까지 가는 **모든 단순 경로**이고, **단순
경로**란 같은 정점을 두 번 담지 않는 경로입니다. 정점 여섯 · 간선 여덟인 그래프에서 정점 0 을 출발, 정점 4 를
도착으로 두면 이렇게 생겼습니다.

<!--fig:concept-paths-->
![전개 입력과 그 위의 단순 경로 셋 — 띠 하나가 경로 하나](./figs/concept-paths.svg)

굵은 실선은 어느 한 경로라도 지나가는 간선입니다. 정점 5 에는 자기 자신으로 가는 간선이 하나 있지만 정점 4 로
가는 간선이 없고, 정점 3 에는 간선이 하나도 없어요. 답은 값 하나가 아니라 **경로의 목록**입니다.

<!--proof:concept-paths-->

| 경로 | 지나는 정점 | 간선 수 |
| --- | --- | ---: |
| 경로 1 | 0 → 1 → 2 → 4 | 3 |
| 경로 2 | 0 → 1 → 4 | 2 |
| 경로 3 | 0 → 2 → 4 | 2 |

정점 0 에서 4 까지의 단순 경로는 3 개입니다. 0 → 2 → 0 → 1 → 4 는 간선으로 이어지지만 정점 0 을 두 번 담아 단순 경로가 아니고, 목록에 없습니다.

<!--/proof-->

경로들을 내놓는 순서도 정해져 있습니다. **사전식 순서** — 두 경로를 앞에서부터 정점 번호끼리 비교해, 처음으로
다른 자리에서 번호가 작은 쪽이 앞섭니다. 첫 두 경로를 자리마다 비교하면 이렇습니다.

<!--proof:concept-lex-->

| 자리 | [0, 1, 2, 4] | [0, 1, 4] | 비교 |
| --- | --- | --- | --- |
| 1 번째 | 0 | 0 | 같다 |
| 2 번째 | 1 | 1 | 같다 |
| 3 번째 | 2 | 4 | 앞 경로가 작다 |

3 번째 자리에서 처음 갈리고, 거기서 번호가 작은 [0, 1, 2, 4] 가 앞섭니다.

<!--/proof-->

이 순서는 따로 정렬하지 않아도 얻을 수 있어요. 정점마다 나가는 이웃 목록을 번호 오름차순으로 두고 그 순서대로
내려가면, 먼저 완성되는 경로가 곧 사전식으로 앞선 경로입니다.

「같은 정점을 두 번 담지 않는다」를 지키는 장치는 정점마다 두는 **표시** 하나입니다. 표시는 「이 정점이 지금
만들고 있는 경로 안에 있는가」를 적어요. 경로를 한 칸 늘릴 때 새 정점의 표시를 켜고, 더 갈 곳이 없어 한 칸
되돌아갈 때 그 표시를 지웁니다. 이렇게 한 갈래를 끝까지 가 본 뒤 마지막 갈림 자리로 되돌아가 다음 후보를
고르는 방법을 **되돌리기**(backtracking)라고 불러요. 이 글의 결정적인 자리가 「되돌아갈 때 표시를 지운다」입니다.

<!--proof:concept-unmark-->

| 되돌아갈 때 | 결과 | 경로 수 |
| --- | --- | ---: |
| 표시를 지운다 | [[0,1,2,4], [0,1,4], [0,2,4]] | 3 |
| 표시를 지우지 않는다 | [[0,1,2,4]] | 1 |

표시를 지우지 않으면 경로 2 개를 잃습니다.

<!--/proof-->

비용은 두 조각입니다. 할 일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선마다 자기 루프를 빼고, 같은 이웃은 한 번만 넣는다 | 간선 수에 비례 |
| 목록 정렬 | 정점마다 이웃 목록을 번호 오름차순으로 정렬한다 | 목록 길이 `d` 에 `d log d` 규모 |
| 경로 만들기 | 한 칸씩 내려가고 되돌아오며 도착 정점에서 경로를 복사한다 | 내려간 횟수와 복사한 정점 수에 비례 |

앞의 두 줄은 그래프의 크기가 정합니다. 셋째 줄은 정점 수나 간선 수가 아니라 **그래프의 모양**이 정해요 — 정점
수가 같아도 내려가는 횟수가 몇 자릿수씩 갈립니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 정점과 간선으로 적는 방식.** 특히 **이웃 목록**(인접 리스트) — 정점마다 나가는 이웃의 목록을 하나씩
  두는 표현입니다. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **깊이 우선 방문** — 갈 수 있는 데까지 들어갔다가 더 갈 곳이 없으면 가장 최근의 갈림 자리로 되돌아가는
  절차입니다. 이 글은 그 절차 위에 「지금 경로를 적어 두고 되돌아갈 때 지운다」를 더합니다. 모르면
  [`dfsTraversal` 가이드](../dfsTraversal/dfsTraversal-guide.md)를 보세요.
- **재귀 호출이 쌓이는 방식.** 함수가 자기 자신을 부르면 부른 자리가 쌓이고, 돌아올 때 그 자리부터 이어집니다.
  이 글은 그 「돌아오는 자리」에 표시를 지우는 두 줄을 둡니다.
- **배열의 얕은 복사.** `slice()` 가 원소를 담은 새 배열을 만든다는 것. 결과에 담는 것이 복사본이 아니면 나중에
  그 배열이 바뀝니다.
- **비교 정렬의 비용이 원소 `m` 개에 `m · log m` 규모**라는 것. 모르면
  [`sortArray` 가이드](../../sorting/sortArray/sortArray-guide.md)를 보세요.

셋째가 흐릿하면 뒤가 어긋납니다. 이 글의 핵심은 **재귀에서 돌아오는 그 자리에서 무엇을 지우는가** 하나이고,
그 자리를 알아보려면 재귀가 어떻게 쌓이고 어떻게 풀리는지가 먼저 확인돼 있어야 해요.

### 아이디어를 떠올리는 과정 — 정점 나열 전부 만들어 거르기에서 되돌아갈 때 지우는 경로 표시까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 방향 그래프와 두 정점을 받아서,
두 정점 사이의 단순 경로를 전부 돌려줍니다.

```ts
function dfsAllPaths(
  n: number,
  edges: [number, number][],
  source: number,
  target: number,
): number[][];
```

- 입력: 정점 수 `n`, 방향 간선 목록 `edges`, 출발 정점 `source`, 도착 정점 `target`. 정점 번호는 0 부터 `n − 1`
  까지예요. 자기 루프(`[v, v]`)와 같은 방향의 중복 간선이 들어올 수 있습니다.
- 출력: `source` 에서 `target` 까지의 모든 단순 경로를 사전식 순서로 담은 목록. 경로 하나는 지나는 정점 번호의
  배열입니다. 경로가 없으면 빈 배열이고, `source` 와 `target` 이 같으면 길이 1 짜리 경로 하나예요.
- 규모: 정점 1,000 개 이하, 간선 10,000 개 이하이고, **단순 경로의 수가 10,000 개 이하인 입력**을 다룹니다. 비용은
  흔한 채점 환경의 예산인 1 초에 대어 잽니다.

규모 셋째 줄이 이 과제에서만 보이는 줄입니다. 답의 개수에 상한이 걸려 있어요 — 그래야 결과를 적는 것만으로
시간이 끝나지 않습니다. 절차가 쓸 수 있는 정보는 셋이에요.

| 쓸 수 있는 것 | 알려 주는 것 |
| --- | --- |
| 간선 목록 `edges` (또는 거기서 만든 이웃 목록 `adj[v]`) | 정점 `v` 에서 간선 하나로 갈 수 있는 정점들 |
| 지금 만들고 있는 경로 `path` | 출발 정점부터 지금 정점까지 지나온 정점들 |
| 경로 표시 `onPath[v]` | 정점 `v` 가 지금 `path` 안에 있는가 |

이 글이 쓰는 기호는 아홉이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` 입니다 | `1 ≤ V ≤ 1,000` |
| `E` | 간선 목록의 길이. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 10,000` |
| `s` | 출발 정점 번호. 코드의 `source` 입니다 | `0 ≤ s < V` |
| `t` | 도착 정점 번호. 코드의 `target` 입니다 | `0 ≤ t < V` |
| `adj[v]` | 정점 `v` 에서 나가는 이웃 목록 | 번호 오름차순으로 정렬해 둔다 |
| `path` | 지금 만들고 있는 경로 | 길이는 `V` 이하 |
| `onPath[v]` | 정점 `v` 가 지금 `path` 안에 있는가 | 참 또는 거짓 |
| `result` | 다 만든 경로들을 담는 목록 | 길이는 `N` |
| `N` | `s` 에서 `t` 까지의 단순 경로 수 | 10,000 이하 |

가장 먼저 떠오르는 방법으로 시작합시다. **간선을 따라가지 않고**, 두 끝 사이에 올 정점의 나열을 가능한 순서대로
전부 만들어 놓은 다음, 나열마다 실제로 간선으로 이어지는지 확인하는 것이에요. 정점 넷에서 `0 → 3` 의 후보를
만들면 이렇습니다.

<!--proof:naive-small-->

| 중간 정점 수 | 후보 | 있어야 하는 간선 |
| ---: | --- | --- |
| 0 | [0, 3] | 0 → 3 |
| 1 | [0, 1, 3] | 0 → 1 · 1 → 3 |
| 2 | [0, 1, 2, 3] | 0 → 1 · 1 → 2 · 2 → 3 |
| 1 | [0, 2, 3] | 0 → 2 · 2 → 3 |
| 2 | [0, 2, 1, 3] | 0 → 2 · 2 → 1 · 1 → 3 |

정점 4 개에서 두 끝을 뺀 정점 2 개로 만든 후보는 5 개입니다.

<!--/proof-->

이 방법은 답이 맞습니다. 그런데 후보 수가 **그래프의 모양과 상관없이** 정점 수만으로 정해져요. 두 끝을 뺀
`V − 2` 개로 만들 수 있는 나열이 전부 후보가 됩니다. 비용은 **간선 확인 횟수**로 셉니다.

<!--proof:naive-scale-->

| 정점 n | 정점 나열 후보 | 간선 확인 | 초당 1 억 번 기준 | 센 방법 |
| ---: | ---: | ---: | ---: | --- |
| 6 | 65 | 261 | 0.000 초 | 실행 |
| 8 | 1,957 | 11,743 | 0.000 초 | 실행 |
| 10 | 109,601 | 876,809 | 0.009 초 | 실행 |
| 12 | 9,864,101 | 98,641,011 | 0.986 초 | 식 |
| 14 | 1,302,061,345 | 15,624,736,141 | 156.247 초 | 식 |

모든 간선이 있는 그래프에서 센 값입니다. 실행한 3 줄이 모두 식과 일치했고, 나머지 줄은 그 식으로 낸 값입니다.

<!--/proof-->

정점 열넷에서 벌써 156 초입니다. 규모는 정점 **1,000 개**예요. 그러면 이 156 초 안에 헛일이 얼마나 섞여 있는지
봅시다. 앞의 여섯 정점 그래프를 두 방식으로 처리해 간선을 몇 번 확인했는지 셉니다. 둘째 방식은 **출발 정점에서
시작해 지금 정점의 이웃으로만 한 칸씩 경로를 늘려 가는** 것이에요.

<!--proof:follow-vs-generate-->

| 방법 | 만든 것 | 간선 확인 | 결과 |
| --- | --- | ---: | --- |
| 후보를 전부 만들어 거른다 | 나열 65 개 | 109 | [[0,1,2,4], [0,1,4], [0,2,4]] |
| 간선을 따라가며 만든다 | 진입 9 번 | 10 | [[0,1,2,4], [0,1,4], [0,2,4]] |

두 결과가 일치합니다. 후보 65 개 가운데 경로가 된 것은 3 개이고, 나머지 62 개는 간선으로 이어지지 않는다는 것을 확인하는 데만 쓰였습니다.

<!--/proof-->

답은 같은데 확인 횟수가 109 에서 10 으로 줄었습니다. 여기서 관찰한 것은 하나예요. **경로를 앞에서부터 한 칸씩
늘려 가면, 늘리는 후보가 언제나 지금 정점의 이웃 목록 안에 있습니다.** 간선으로 이어지지 않는 나열은 만들어지지도
않으니, 비용이 「후보 수」가 아니라 「실제로 내려간 횟수」가 돼요.

그런데 한 칸씩 늘리는 것만으로는 단순 경로가 보장되지 않습니다. 정점 2 에서 정점 0 으로 가는 간선이 있어서,
아무것도 거르지 않으면 경로가 끝없이 자랍니다. 이웃 목록의 첫 이웃으로 내려가는 여섯 번을 적으면 이렇습니다.

<!--proof:grow-no-mark-->

| 진입 | path | 끝 정점의 이웃 목록 | 다음에 들어가는 이웃 |
| ---: | --- | --- | --- |
| 1 | [0] | [1, 2] | 1 |
| 2 | [0, 1] | [2, 4] | 2 |
| 3 | [0, 1, 2] | [0, 4, 5] | 0 |
| 4 | [0, 1, 2, 0] | [1, 2] | 1 |
| 5 | [0, 1, 2, 0, 1] | [2, 4] | 2 |
| 6 | [0, 1, 2, 0, 1, 2] | [0, 4, 5] | 0 |

6 번째 진입에서 path 가 [0, 1, 2, 0, 1, 2] 이고, 앞의 3 칸이 그대로 되풀이됩니다.

<!--/proof-->

**지금 경로 안에 이미 있는 정점**을 걸러야 합니다. 가장 단순한 후보를 먼저 시험해 봅시다. 깊이 우선 방문이 쓰는
표시를 그대로 가져오는 것이에요 — 정점에 들어갈 때 표시를 켜고, **한 번 켠 표시는 끝까지 지우지 않는** 방식입니다.
순회에서는 그것이 정석이에요.

<!--proof:global-mark-->

| 입력 | 표시를 지우는 절차 | 표시를 끝까지 두는 절차 |
| --- | --- | --- |
| 다이아몬드 | [[0,1,3], [0,2,3]] | [[0,1,3]] |
| 전개가 쓰는 여섯 정점 | [[0,1,2,4], [0,1,4], [0,2,4]] | [[0,1,2,4]] |

다이아몬드에서 경로 2 개 가운데 1 개만 남습니다. 전개가 쓰는 여섯 정점에서 경로 3 개 가운데 1 개만 남습니다.

<!--/proof-->

답이 하나만 남습니다. 왜 그런지는 다이아몬드(`0 → 1 → 3` 과 `0 → 2 → 3`)에서 한 일마다 확인됩니다.

<!--proof:global-mark-trace-->

| 한 일 | 켜진 표시 | path | 담은 경로 수 |
| --- | --- | --- | ---: |
| 0 을 담는다 | {0} | [0] | 0 |
| 1 을 담는다 | {0, 1} | [0, 1] | 0 |
| 3 을 담는다 | {0, 1, 3} | [0, 1, 3] | 1 |
| 3 에서 되돌아간다 | {0, 1, 3} | [0, 1] | 1 |
| 1 에서 되돌아간다 | {0, 1, 3} | [0] | 1 |
| 2 를 담는다 | {0, 1, 2, 3} | [0, 2] | 1 |
| 이웃 3 이 표시돼 있어 막힌다 | {0, 1, 2, 3} | [0, 2] | 1 |
| 2 에서 되돌아간다 | {0, 1, 2, 3} | [0] | 1 |
| 0 에서 되돌아간다 | {0, 1, 2, 3} | [] | 1 |

정점 3 은 첫 경로에 한 번 담겼을 뿐인데 표시가 남아, 「이웃 3 이 표시돼 있어 막힌다」 자리에서 두 번째 경로가 없어집니다.

<!--/proof-->

순회에서는 이것이 옳아요. 정점 하나를 한 번만 처리하는 것이 순회의 정의니까요. 그런데 여기서 막아야 하는 것은
「이미 처리한 정점」이 아니라 「**지금 만들고 있는 경로 안에 있는 정점**」입니다. 그러니 표시는 정점이 `path` 안에
있는 동안에만 켜져 있어야 하고, 되돌아가는 자리에서 지워야 해요. 남은 갈림은 **되돌아갈 때 무엇을 하는가**입니다.
넷을 같은 두 입력에 실행했습니다.

<!--proof:unmark-placement-->

| 되돌아갈 때 하는 일 | 다이아몬드 | 전개가 쓰는 여섯 정점 |
| --- | --- | --- |
| 한 번 켠 표시를 끝까지 둔다 | [[0,1,3]] | [[0,1,2,4]] |
| 표시를 아예 하지 않는다 | [[0,1,3], [0,2,3]] | RangeError |
| 표시는 지우지만 경로에서 안 뺀다 | [[0,1,3], [0,1,3,2,3]] | [[0,1,2,4], [0,1,2,4,5,4], [0,1,2,4,5,4,2,4]] |
| 표시를 지우고 경로에서도 뺀다 | [[0,1,3], [0,2,3]] | [[0,1,2,4], [0,1,4], [0,2,4]] |

두 입력에서 모두 정본의 답과 같은 줄은 1 개(표시를 지우고 경로에서도 뺀다)입니다.

<!--/proof-->

둘째 줄이 특히 볼 만해요. 다이아몬드에서는 표시를 아예 안 해도 답이 그대로 나옵니다. 그 그래프에는 앞으로
돌아가는 간선이 없어 같은 정점을 두 번 담을 길 자체가 없기 때문이에요. 셋째 줄은 표시는 지웠으니 막히지는 않는데,
`path` 가 줄지 않아 두 번째 경로 앞에 첫 경로의 흔적 `[0,1,3]` 이 남았습니다. 지금까지 해 본 방법을 차례로 놓으면
이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 다섯 — 넷은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **되돌아갈 때 지우는 경로 표시**입니다. 한 칸 내려갈 때 새 정점의 표시를 켜고 `path` 에
담고, 되돌아갈 때 그 표시를 지우고 `path` 에서 빼서, 켜진 표시가 언제나 `path` 안의 정점과 같게 해요. 이 방법이
실제로 무엇을 차례로 찾아가는지, 표시를 언제 켜고 언제 지우는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 되돌아갈 때 지우는 경로 표시

이 아이디어를 한 문장으로 줄이면 이렇습니다. **출발 정점부터 이웃 목록을 따라 한 칸씩 내려가되, 들어갈 때 그
정점의 표시를 켜고 `path` 에 담고, 경로 안에 있는 이웃은 건너뛰고, 도착 정점이면 `path` 를 복사해 담고, 나올 때
표시를 지우고 `path` 에서 뺍니다.** 이 절차가 찾아가는 것은 그래프의 정점이 아니라 그래프에서 만들 수 있는 부분 경로들이고,
그 모양이 처음 보는 사람에게는 낯설어요. 그래서 그 모양을 먼저 따로 설명하고, 그다음 실현하는 순서대로 네 단계를
설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 이웃 목록 만들어 정렬하기 | 자기 루프를 빼고 같은 이웃을 한 번만 담아 번호 오름차순으로 둔다 | — |
| 정점에 들어갈 때마다 | 2단계 들어갈 때 표시 켜기 | 표시를 켜고 `path` 에 담은 뒤, 경로 안 이웃은 건너뛰고 나머지로 내려간다 | 1단계의 `adj` |
| 정점에서 나올 때마다 | 3단계 나올 때 표시 지우기 | 2단계에서 켠 표시를 지우고 `path` 에서 뺀다 | 2단계가 켠 표시와 `path` |
| 도착 정점에 들어갈 때마다 | 4단계 도착 정점에서 경로 복사하기 | `path` 를 복사해 `result` 에 담고 더 내려가지 않는다 | 2 · 3단계가 유지한 `path` |

#### 먼저 알아 둘 개념 — 상태 공간 트리

**상태 공간 트리**(state-space tree)는 **출발 정점에서 시작하는 단순 부분 경로 하나를 마디 하나로 두고, 그 경로를
한 칸 늘린 경로를 자식으로 이은 나무**입니다. 뿌리는 출발 정점 하나만 담은 경로이고, 마디에서 자식으로 가는 것이
「경로 끝에 이웃 하나를 더 붙인다」예요. 되돌리기로 모든 경로를 만드는 절차는 이 나무를 뿌리부터 깊이 우선으로
차례로 찾아가는 것과 같습니다.

##### 입력 위의 상태 공간 트리

전개 입력의 나무를 마디 하나가 진입 하나가 되게 그렸습니다. 마디 이름은 그 경로의 끝 정점이고, 마디 안의 값은
뿌리부터의 `path` 예요. 강조한 마디가 도착 정점에서 끝나 답이 된 마디이고, 점선 마디는 더 갈 곳이 없는 막다른 마디입니다.

<!--fig:build-tree-->
![전개 입력의 상태 공간 트리 — 마디 이름은 끝 정점, 값은 뿌리부터의 path](./figs/build-tree.svg)

그래프에는 정점 4 가 하나뿐인데 나무에는 마디 셋으로 나옵니다. 정점 4 에 이르는 부분 경로가 셋이기 때문이에요.

##### 마디 하나를 읽는 법

끝 정점이 같은 마디 둘을 골라 읽어 보겠습니다. 마디의 경로에서 시작해, 그 마디에 있을 때 켜진 표시와 끝 정점의
이웃 목록, 그중 자식이 되는 이웃까지 따라가요.

<!--proof:tree-read-->

| 마디 | 켜진 표시 | adj[2] | 자식이 되는 이웃 | 건너뛰는 이웃 |
| --- | --- | --- | --- | --- |
| 0 → 1 → 2 | {0, 1, 2} | [0, 4, 5] | 4 · 5 | 0 |
| 0 → 2 | {0, 2} | [0, 4, 5] | 4 · 5 | 0 |

끝 정점이 2 인 마디는 2 개이고, 켜진 표시가 뿌리에서 그 마디까지 지나온 정점과 같은 마디는 2 개입니다.

<!--/proof-->

두 마디는 끝 정점이 같아 이웃 목록도 같습니다. 이웃 0 은 두 마디 모두에서 이미 경로 안에 있어 건너뛰고, 4 와 5 가
자식이 돼요. 어느 이웃이 자식이 되는지를 정하는 것이 **그 마디의 켜진 표시**, 곧 뿌리에서 그 마디까지 지나온 정점들입니다.

##### 마디끼리의 관계

부모와 자식은 경로 한 칸 차이이고, 형제는 같은 경로에서 서로 다른 이웃을 붙인 것입니다. 전개 입력의 마디를 진입한
차례대로 모두 적으면 이렇습니다.

<!--proof:tree-nodes-->

| 마디 번호 | 마디 | 부모 | 자식 수 | 마디의 종류 |
| ---: | --- | --- | ---: | --- |
| 1 | 0 | 없음 | 2 | 가운데 마디 |
| 2 | 0 → 1 | 1 번 | 2 | 가운데 마디 |
| 3 | 0 → 1 → 2 | 2 번 | 2 | 가운데 마디 |
| 4 | 0 → 1 → 2 → 4 | 3 번 | 0 | 답 |
| 5 | 0 → 1 → 2 → 5 | 3 번 | 0 | 막다른 마디 |
| 6 | 0 → 1 → 4 | 2 번 | 0 | 답 |
| 7 | 0 → 2 | 1 번 | 2 | 가운데 마디 |
| 8 | 0 → 2 → 4 | 7 번 | 0 | 답 |
| 9 | 0 → 2 → 5 | 7 번 | 0 | 막다른 마디 |

마디 9 개 가운데 답이 된 것이 3 개, 막다른 마디가 2 개입니다. 정점 4 로 끝나는 마디가 3 개라, 그래프에서 하나인 정점이 나무에서는 여러 번 나옵니다.

<!--/proof-->

진입한 차례가 곧 나무를 깊이 우선으로 찾아가는 차례예요. 3 번 마디의 자식 둘(4 번 · 5 번)을 다 본 뒤에야 2 번 마디의
다음 자식 6 번으로 갑니다. 그 사이에 켜진 표시는 **한 마디에서 뿌리까지의 줄**만 담고 있어야 합니다 — 4 번 마디에서
켠 정점 4 의 표시가 6 번 마디에서도 켜져 있으면, 6 번 마디는 만들어지지 못해요.

##### 순회의 방문 나무와의 차이

깊이 우선 방문을 먼저 배운 사람은 이 나무를 순회가 그리는 **방문 나무**로 읽기 쉽습니다. 방문 나무는 정점마다
마디가 많아야 하나라, 같은 그래프에서 크기부터 다릅니다.

<!--proof:tree-vs-graph-->

| 모양 | 크기 | 정점 4 가 나오는 횟수 | 찾은 경로 |
| --- | --- | --- | --- |
| 그래프 | 정점 6 개 | 1 번 | — |
| 순회의 방문 나무(한 번 켠 표시를 끝까지 둔다) | 마디 5 개 | 1 번 | 1 개 |
| 상태 공간 트리 | 마디 9 개 | 3 번 | 3 개 |

같은 그래프에서 순회는 정점마다 많아야 한 번 들어가 5 번으로 끝나고, 상태 공간 트리는 9 번 들어갑니다.

<!--/proof-->

순회는 정점에 한 번 들어가면 다시 들어가지 않으니 마디가 정점 수를 넘지 못합니다. 상태 공간 트리는 **경로마다**
마디가 있어서, 같은 정점이 여러 마디에 끝 정점으로 나와요. 모든 경로를 만들려면 이 나무의 마디를 전부 봐야 합니다.

##### 이렇게 생긴 까닭

답 하나는 뿌리에서 도착 정점으로 끝나는 마디까지의 줄 하나입니다. 서로 다른 단순 경로는 서로 다른 마디에서 끝나니,
경로를 빠짐없이 적으려면 모든 마디를 한 번씩 찾아가야 해요. 그리고 마디 하나에서 「경로 안에 있는가」를 판정하는
데 필요한 것은 뿌리에서 그 마디까지의 정점뿐입니다. 나무를 깊이 우선으로 찾아가면 지금 마디에서 뿌리까지의 줄이 곧
`path` 이므로, 표시를 `path` 와 함께 켜고 지우기만 하면 판정에 필요한 것이 늘 정확히 켜져 있게 됩니다.

#### 1단계 — 이웃 목록 만들어 정렬하기

간선 목록은 「누가 누구로 가는가」를 담고 있지만, 「정점 2 에서 어디로 갈 수 있는가」에 답하려면 목록 전체를 읽어야
합니다. 정점마다 나가는 이웃 목록을 하나씩 만들어 두면 그 질문이 배열 한 칸 읽기가 돼요. 이때 자기 루프는 빼고,
같은 이웃은 한 번만 담고, 번호 오름차순으로 정렬합니다.

<!--proof:build-adj-->

| 정점 v | 간선에서 모은 이웃 | 자기 루프·중복을 뺀 뒤 | 정렬 뒤 | 길이 |
| ---: | --- | --- | --- | ---: |
| 0 | [2, 1] | [2, 1] | [1, 2] | 2 |
| 1 | [2, 4] | [2, 4] | [2, 4] | 2 |
| 2 | [0, 4, 5] | [0, 4, 5] | [0, 4, 5] | 3 |
| 3 | [] | [] | [] | 0 |
| 4 | [] | [] | [] | 0 |
| 5 | [5] | [] | [] | 0 |

길이를 모두 더하면 7 이고, 간선 8 개에서 자기 루프 1 개를 뺀 수입니다. 정렬로 차례가 바뀐 목록은 1 개입니다.

<!--/proof-->

자기 루프를 빼도 되는 것은 단순 경로가 같은 정점을 두 번 담을 수 없어서이고, 같은 이웃을 한 번만 담아도 되는 것은
반환하는 것이 **간선이 아니라 정점 나열**이어서입니다. 같은 `u → v` 간선이 몇 개든 그것으로 만들어지는 정점 나열은
하나예요. 오름차순으로 두는 것이 결과를 사전식 순서로 만드는 자리이고, 이 목록은 여기서 한 번 만들고 뒤에서는 읽기만
합니다.

#### 2단계 — 들어갈 때 표시 켜기

정점에 들어갈 때마다 그 정점의 `onPath` 를 참으로 바꾸고 `path` 끝에 담습니다. 그다음 1단계의 이웃 목록을 차례로
보면서, `onPath` 가 참인 이웃은 건너뛰고 거짓인 이웃으로 한 칸 내려가요. 전개 입력에서 첫 경로를 담을 때까지의 걸음은
이렇습니다.

<!--proof:build-enter-->

| 걸음 | 한 일 | path | 켜진 표시 |
| --- | --- | --- | --- |
| T1 | walk(0) 진입 | [0] | {0} |
| T2 | walk(1) 진입 | [0, 1] | {0, 1} |
| T3 | walk(2) 진입 | [0, 1, 2] | {0, 1, 2} |
| T4 | 이웃 0 건너뛴다 | [0, 1, 2] | {0, 1, 2} |
| T5 | walk(4) 진입 · 경로를 담는다 | [0, 1, 2, 4] | {0, 1, 2, 4} |

첫 경로를 담을 때까지 5 걸음이고, 켜진 표시가 path 안의 정점과 같은 걸음은 5 개입니다.

<!--/proof-->

T4 에서 정점 2 의 첫 이웃 0 이 건너뛰어졌습니다. 정점 0 은 출발 정점이라 T1 부터 경로 안에 있었어요. 건너뛰는 판정은
배열 한 칸만 읽고, 그 칸이 참이라는 것은 정확히 「이 이웃을 담으면 같은 정점이 두 번 들어간다」는 뜻입니다.

#### 3단계 — 나올 때 표시 지우기

한 정점의 이웃 목록을 다 보고 나면 그 정점에서 나옵니다. 나오는 자리에서 2단계에서 켠 표시를 지우고 `path` 끝에서
빼요. 쉬운 쪽은 막다른 정점입니다 — 정점 5 처럼 나가는 이웃이 없으면 담았다가 바로 빼는 것으로 끝나요. 불안한 쪽은
같은 정점이 여러 경로에 함께 들어 있는 자리입니다. 전개 입력의 정점 4 가 세 경로에 모두 들어 있어요. 첫 경로를 담은
T5 부터 마지막 경로를 담고 나온 걸음까지 적었습니다.

<!--proof:build-leave-->

| 걸음 | 한 일 | path | 켜진 표시 | 담은 경로 수 |
| --- | --- | --- | --- | ---: |
| T5 | walk(4) 진입 · 경로를 담는다 | [0, 1, 2, 4] | {0, 1, 2, 4} | 1 |
| T6 | 4 를 뺀다 | [0, 1, 2] | {0, 1, 2} | 1 |
| T7 | walk(5) 진입 | [0, 1, 2, 5] | {0, 1, 2, 5} | 1 |
| T8 | 5 · 2 를 뺀다 | [0, 1] | {0, 1} | 1 |
| T9 | walk(4) 진입 · 경로를 담는다 | [0, 1, 4] | {0, 1, 4} | 2 |
| T10 | 4 · 1 을 뺀다 | [0] | {0} | 2 |
| T11 | walk(2) 진입 | [0, 2] | {0, 2} | 2 |
| T12 | 이웃 0 건너뛴다 | [0, 2] | {0, 2} | 2 |
| T13 | walk(4) 진입 · 경로를 담는다 | [0, 2, 4] | {0, 2, 4} | 3 |
| T14 | 4 를 뺀다 | [0, 2] | {0, 2} | 3 |

정점 4 의 표시를 켠 것이 3 번, 지운 것이 3 번입니다.

<!--/proof-->

T6 에서 정점 4 의 표시를 지웠기 때문에 T9 에서 정점 1 이 이웃 4 로 다시 내려갈 수 있었고, T10 에서 다시 지웠기 때문에
T13 이 가능했습니다. T8 은 막다른 정점 5 에서 나오면서 정점 2 의 이웃 목록까지 다 봐서, 나오기 둘이 잇달아 일어난
걸음이에요.

반복이 끝나는 까닭은 코드의 종료 조건으로 말할 수 있습니다. 한 번의 진입은 자기 이웃 목록을 한 번 끝까지 보면 반드시
나오고, 나오기 직전에 자기가 켠 표시 하나를 지워요. 들어가는 이웃은 표시가 꺼진 정점뿐이라 `path` 의 길이가 `V` 를
넘지 못하고, 그래서 재귀 깊이도 `V` 이하입니다. 한 겹이 켜고 지우는 것이 정확히 한 개씩이라 표시와 `path` 가 어긋날
자리가 없어요.

#### 4단계 — 도착 정점에서 경로 복사하기

들어간 정점이 도착 정점이면 그 순간의 `path` 를 복사해 `result` 에 담고, 이웃 목록은 보지 않습니다. 도착 정점을 지나
더 가면 마지막 정점이 `t` 가 아니게 되어 세는 경로가 아니기 때문이에요.

<!--proof:build-hit-->

| 걸음 | 담은 순간의 path | result 길이 |
| --- | --- | ---: |
| T5 | [0, 1, 2, 4] | 1 |
| T9 | [0, 1, 4] | 2 |
| T13 | [0, 2, 4] | 3 |

도착 정점에 3 번 들어갔고, 그때마다 이웃 목록을 읽지 않고 되돌아갔습니다.

<!--/proof-->

담는 것이 `path` 자체가 아니라 **복사본**이라는 점이 중요합니다. `path` 는 3단계에서 곧바로 줄어들므로, 담는 순간의
내용을 새 배열로 떠 두어야 해요. 복사하지 않으면 어떻게 되는지는 다음 절의 짚고 가기에서 값으로 봅니다.

#### 이 방법이 기대는 전제

이 방법은 **답이 단순 경로라는 전제**에 기댑니다. 경로 안의 정점을 건너뛰는 판정이 있어서 `path` 가 `V` 칸을 넘지
못하고, 그래서 나무의 깊이가 유한해 절차가 끝나요. 같은 정점을 여러 번 지나도 되는 경로를 세려면 이 판정을 빼야 하는데,
그러면 사이클이 있는 그래프에서 끝나지 않습니다. 표시를 빼고 따라가기만 하는 절차를 두 입력에 실행했습니다.

<!--proof:premise-no-mark-->

| 입력 | 사이클 | 표시 없이 따라가기 | 정본 |
| --- | --- | --- | --- |
| 다이아몬드 | 없다 | [[0,1,3], [0,2,3]] | [[0,1,3], [0,2,3]] |
| 전개가 쓰는 여섯 정점 | 0 → 1 → 2 → 0 | RangeError | [[0,1,2,4], [0,1,4], [0,2,4]] |

다이아몬드에서는 정본과 같은 답이 나옵니다. 전개가 쓰는 여섯 정점에서는 RangeError 로 멈춥니다.

<!--/proof-->

사이클이 없는 그래프에서는 표시가 없어도 답이 같아요. 사이클이 하나라도 있으면 표시 없이는 끝나지 않고, 그때 경로의
수 자체가 무한합니다. 이 글의 절차는 단순 경로만 세므로 그런 입력이 없습니다.

#### 재귀로 적는 까닭

[`dfsTraversal` 가이드](../dfsTraversal/dfsTraversal-guide.md)는 깊이 우선 방문을 **반복문과 스택 배열**로 적습니다.
재귀로 적으면 호출 깊이가 정점 수만큼 쌓이고, 그 과제의 규모가 정점 100,000 개라 실행 환경의 호출 한도를 넘기
때문이에요. 이 글은 재귀로 적습니다. 3단계에서 본 대로 깊이가 `path` 의 길이이고, 그 길이가 `V` 이하이기 때문입니다.
정점을 한 줄로 이은 사슬에서 정본을 실행했습니다.

<!--proof:design-recursion-->

| 사슬의 정점 수 | 재귀로 적은 정본 |
| ---: | --- |
| 1,000 | 경로 1 개 · 길이 1,000 |
| 100,000 | RangeError 로 멈춘다 |

규모가 정점 1,000 개이니 깊이도 1,000 이하이고, 그 깊이에서는 결과가 나옵니다. 호출 한도가 정확히 몇인지는 실행
환경이 정하고 두 줄 사이 어딘가에 있어요. 재귀로 적으면 「들어갈 때 켜고 나올 때 지운다」가 함수의 첫 줄과 마지막 줄로
나란히 놓여 짝이 눈에 보입니다. 규모가 정점 100,000 개로 늘면 이 글도 반복문으로 옮겨야 해요.

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 여섯 걸음이 됩니다. 3 번부터 6 번까지가 재귀 한 겹이에요. 정점 열넷에서 156 억 번이던
간선 확인이 **실제로 들어간 부분 경로의 이웃 목록**을 읽는 만큼으로 줄어듭니다.

1. 간선 목록을 이웃 목록 `adj` 로 바꾼다 — 자기 루프를 빼고, 같은 이웃은 한 번만, 번호 오름차순으로
2. `onPath` 를 전부 거짓으로, `path` 와 `result` 를 빈 배열로 두고 `walk(s)` 를 부른다
3. `walk(u)` 에 들어가면 `onPath[u]` 를 참으로 바꾸고 `path` 끝에 `u` 를 담는다
4. `u` 가 `t` 이면 `path` 를 복사해 `result` 에 담는다
5. 아니면 `adj[u]` 의 `v` 마다, `onPath[v]` 가 참이면 건너뛰고 거짓이면 `walk(v)` 를 부른다
6. 나오기 전에 `onPath[u]` 를 거짓으로 바꾸고 `path` 끝에서 하나를 뺀다

### 수행으로 알아보는 알고리즘 — 여섯 정점에서 경로 셋을 열여섯 걸음으로 만든다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 6;
const edges: [number, number][] = [
  [0, 2], [0, 1], [1, 2], [1, 4], [2, 0], [2, 4], [2, 5], [5, 5],
];
const source = 0;
const target = 4;
// 이 절이 끝나면 [[0,1,2,4], [0,1,4], [0,2,4]] 가 나와야 한다
```

이 입력을 고른 이유는 갈래를 **모두 실행하게** 하려는 것입니다. `[0,2]` 가 `[0,1]` 보다 먼저 적혀 있어 정렬이 실제로
일하는 것이 확인되고, 정점 2 에서 정점 0 으로 가는 간선이 있어 경로 안 이웃을 건너뛰는 갈래가 실행되며, 정점 5 는
도착 정점으로 가는 간선이 없어 아무것도 담지 못하고 되돌아오는 자리가 나와요. 자기 루프 `[5,5]` 가 있어 그것을 빼는
자리도 함께 보입니다.

```text
dfsAllPaths(n, edges, source, target):
    간선 [u, v] 마다 u ≠ v 면 u 의 이웃 모임에 v 를 넣는다
    이웃 모임마다 번호 오름차순 목록으로 만든다
    onPath 를 전부 거짓으로, path 와 result 를 빈 배열로 둔다

    walk(u):
        onPath[u] ← 참, path 뒤에 u 를 담는다
        u 가 target 이면  path 를 복사해 result 에 담는다        ① 도착 정점
        아니면 adj[u] 의 v 마다:
            onPath[v] 가 참이면 건너뛴다                          ② 경로 안에 있는 이웃
            아니면 walk(v)                                        ③ 경로에 없는 이웃
        onPath[u] ← 거짓, path 끝에서 하나를 뺀다

    walk(source) 를 부르고 result 를 반환한다
```

#### 1. 간선 목록을 오름차순 이웃 목록으로 만든다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 정점마다 집합 하나를 두어 같은 이웃을 한 번만 담고, 자기 루프는
`u === v` 로 건너뛴 뒤, 집합마다 정렬한 배열로 바꿔요.

```ts
const sets: Set<number>[] = Array.from({ length: n }, () => new Set<number>());
for (const [u, v] of edges) {
  if (u === v) continue;
  (sets[u] as Set<number>).add(v);
}
const adj: number[][] = sets.map((s) => [...s].sort((a, b) => a - b));
```

전개 입력에 이 조각만 실행하면 이렇게 나옵니다. `adj[0]` 이 만들어질 때는 `[2, 1]` 이었다가 정렬 뒤에 `[1, 2]` 가 되고,
자기 루프 `[5,5]` 가 빠져 `adj[5]` 가 비어 있어요.

<!--proof:walk-adj-->

```text
         정렬 전     정렬 후
adj[0]   [2, 1]      [1, 2]
adj[1]   [2, 4]      [2, 4]
adj[2]   [0, 4, 5]   [0, 4, 5]
adj[3]   []          []
adj[4]   []          []
adj[5]   []          []
```

#### 짚고 가기 — 정렬을 빼도 경로의 모임은 그대로다

`sort` 를 빼면 어떻게 될까요? 코드는 그대로 실행되고 예외도 안 납니다. 그리고 **경로를 하나도 잃지 않아요** — 이웃을
어떤 순서로 보든 그 이웃으로 갈라지는 가지는 전부 실행되기 때문입니다. 정렬을 뺀 코드와 원래 코드를 나란히 실행했습니다.

<!--proof:unsorted-order-->

| 이웃 목록 | 결과 | 사전식으로 다시 정렬한 목록 |
| --- | --- | --- |
| 정렬한다 | [[0,1,2,4], [0,1,4], [0,2,4]] | [[0,1,2,4], [0,1,4], [0,2,4]] |
| 정렬하지 않는다 | [[0,2,4], [0,1,2,4], [0,1,4]] | [[0,1,2,4], [0,1,4], [0,2,4]] |

두 결과는 차례가 다르고, 사전식으로 다시 정렬한 두 목록은 같습니다.

<!--/proof-->

갈리는 것은 순서뿐이라, 「경로를 다 찾았는가」만 확인하는 테스트는 `sort` 를 지워도 통과합니다. 첫 내려가기부터 갈려요.

<!--proof:unsorted-trace-->

```text
정렬하지 않는다   adj[0] = [2, 1]   먼저 2 로 내려간다   처음 담는 경로 [0, 2, 4]
정렬한다          adj[0] = [1, 2]   먼저 1 로 내려간다   처음 담는 경로 [0, 1, 2, 4]
```

과제의 계약은 사전식 순서를 요구하니 정렬이 필요합니다. 끝나고 결과 목록을 따로 정렬해도 되지만, 이웃 목록을 한 번
정렬해 두면 그 비용이 `N` 개 경로가 아니라 `E` 개 간선에만 붙어요.

#### 2. 경로와 표시와 결과를 준비한다

「이 정점이 지금 경로 안에 있는가」를 배열 한 칸으로 담습니다. 경로 자체는 정점 번호를 순서대로 담는 배열이고, 다 만든
경로는 따로 모아요.

```ts
const onPath: boolean[] = Array.from({ length: n }, () => false);
const path: number[] = [];
const result: number[][] = [];
```

실행하면 이렇게 나옵니다. 출발 정점도 아직 표시가 꺼져 있어요 — 표시는 재귀 한 겹에 **들어갈 때** 켭니다.

<!--proof:walk-init-->

```text
onPath = [false, false, false, false, false, false]
path   = []
result = []
```

배열 셋을 처음에 한 번 만들고 그 뒤로는 새로 잡지 않습니다. 재귀 한 겹이 고치는 것은 `path` 의 끝 한 칸과 `onPath` 의
한 칸뿐이에요.

#### 3. 재귀 한 겹을 진입 · 갈래 · 되돌아가기로 적는다

「아이디어 상세」의 2 · 3 · 4단계가 모두 이 함수 하나에 들어갑니다. 한 겹에 들어가면 표시를 켜고 경로에 담고, 갈래 셋 중
하나를 실행한 뒤, 켠 표시를 지우고 경로에서 뺍니다.

```ts
const walk = (u: number): void => {
  // 진입 — 표시를 켜고 경로 끝에 붙인다.
  onPath[u] = true;
  path.push(u);

  if (u === target) {
    // ① 도착 정점이다 — 지금 경로를 복사해 담고 여기서 더 내려가지 않는다.
    result.push(path.slice());
  } else {
    for (const v of adj[u] as number[]) {
      // ② 지금 경로 안에 있는 정점이다 — 다시 담으면 단순 경로가 아니다.
      if (onPath[v] === true) continue;

      // ③ 아직 경로에 없는 정점이다 — 한 칸 내려간다.
      walk(v);
    }
  }

  // 되돌아가는 자리 — 켠 표시를 지우고 경로 끝에서 뺀다. 진입과 정확히 짝을 이룬다.
  onPath[u] = false;
  path.pop();
};
```

여기서 가장 중요한 것은 **맨 위 두 줄과 맨 아래 두 줄이 짝을 이룬다**는 것입니다. 위에서 켠 것을 아래에서 지우고, 위에서
담은 것을 아래에서 빼요. 넷 중 하나라도 빠지면 다음 경로가 어긋납니다 — 아래 두 줄 중 첫째가 빠지면 경로를 잃고
(「아이디어를 떠올리는 과정」의 첫 줄), 둘째가 빠지면 앞 경로의 흔적이 섞여요(같은 표의 셋째 줄). 갈래 ① 에서 **더
내려가지 않는 것**도 규칙이라 `if` 와 `else` 로 갈라 두었습니다.

#### 짚고 가기 — 경로를 복사하지 않고 담으면 결과가 전부 빈 배열이 된다

`path.slice()` 대신 `path` 를 그대로 담으면 어떻게 될까요? 타입도 맞고 실행도 되고, **담기는 개수까지 정확히 맞습니다.**
「경로를 몇 개 찾았는가」만 확인하는 테스트는 통과하는 자리예요. 두 입력에 나란히 실행했습니다.

<!--proof:shared-array-->

| 입력 | 복사본 담기 | path 그대로 담기 | 두 답 |
| --- | --- | --- | --- |
| 다이아몬드 | [[0,1,3], [0,2,3]] | [[], []] | 어긋난다 |
| 전개가 쓰는 여섯 정점 | [[0,1,2,4], [0,1,4], [0,2,4]] | [[], [], []] | 어긋난다 |

다이아몬드에서 두 결과의 길이는 2 와 2 입니다. 전개가 쓰는 여섯 정점에서 두 결과의 길이는 3 과 3 입니다.

<!--/proof-->

길이는 맞는데 내용이 전부 비어 있습니다. `path` 는 재귀가 진행되는 동안 계속 바뀌는 배열 하나이고, 그것을 그대로 담으면
결과의 모든 칸이 **같은 배열**을 가리켜요. 재귀가 다 끝나면 그 배열은 3 번 걸음의 `path.pop()` 이 다 비워 두었으므로
결과가 빈 배열의 목록이 됩니다. 복사본은 담는 순간의 내용을 새 배열로 떠 두니, 뒤에 `path` 가 바뀌어도 그대로예요.

#### 4. 여섯 정점을 처음부터 끝까지 따라간다

앞의 조각을 이어 실제로 실행하면 열여섯 걸음이 나옵니다. 걸음 하나는 walk 진입 하나, 경로 안 이웃을 건너뛰기 하나, 또는
잇달아 일어난 되돌아가기 한 묶음이에요. 걸음 재생 패널에서 정점 안의 값은 그 정점이 `path` 의 몇 번째 칸인지이고, 점선
정점은 표시가 꺼진 정점, 굵은 실선 간선은 지금 `path` 위의 간선입니다. 무대 아래 띠가 `path` 와 `result` 의 경로들이고,
이번 걸음에 표시를 켜거나 지운 정점과 새로 담은 칸을 강조했어요.

| T2 | walk(1) 진입 | `onPath[1]` 이 **거짓** → ③ | [0, 1] | 0 |
| T3 | walk(2) 진입 | `onPath[2]` 가 **거짓** → ③ | [0, 1, 2] | 0 |

| T11 | walk(2) 진입 | `onPath[2]` 가 **거짓** → ③ | [0, 2] | 2 |

| T13 | walk(4) 진입 · 경로를 담는다 | `onPath[4]` 가 **거짓** → ③ · `4 === target` 이 **참** → ① | [0, 2, 4] | 3 |
| T14 | 4 를 뺀다 | `walk(4)` 가 끝났다 → 되돌아간다 | [0, 2] | 3 |

되돌아왔습니다. 정점 5 에서 정점 4 로 가는 간선이 없기 때문인데, **그것을 미리 알 방법이 이 절차에는 없습니다.** 들어가
봐야 알아요. 상태 공간 트리의 막다른 마디 둘이 이 두 걸음입니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 `walk(source)` 를 부르고 `result` 를 그대로 반환하는 마지막
두 줄뿐이에요.

```ts
export function dfsAllPaths(
  n: number,
  edges: [number, number][],
  source: number,
  target: number,
): number[][] {
  // 자기 루프는 단순 경로에 쓸 수 없고, 같은 이웃이 여러 번 있어도 정점 나열은 하나다.
  const sets: Set<number>[] = Array.from(
    { length: n },
    () => new Set<number>(),
  );
  for (const [u, v] of edges) {
    if (u === v) continue;
    (sets[u] as Set<number>).add(v);
  }

  // 이웃을 번호 오름차순으로 둔다. 이 순서가 그대로 결과의 사전식 순서가 된다.
  const adj: number[][] = sets.map((s) => [...s].sort((a, b) => a - b));

  // `onPath[v]` 는 정점 `v` 가 **지금 만들고 있는 경로 안에** 있는가다.
  const onPath: boolean[] = Array.from({ length: n }, () => false);
  const path: number[] = [];
  const result: number[][] = [];

  const walk = (u: number): void => {
    // 진입 — 표시를 켜고 경로 끝에 붙인다.
    onPath[u] = true;
    path.push(u);

    if (u === target) {
      // ① 도착 정점이다 — 지금 경로를 복사해 담고 여기서 더 내려가지 않는다.
      result.push(path.slice());
    } else {
      for (const v of adj[u] as number[]) {
        // ② 지금 경로 안에 있는 정점이다 — 다시 담으면 단순 경로가 아니다.
        if (onPath[v] === true) continue;

        // ③ 아직 경로에 없는 정점이다 — 한 칸 내려간다.
        walk(v);
      }
    }

    // 되돌아가는 자리 — 켠 표시를 지우고 경로 끝에서 뺀다. 진입과 정확히 짝을 이룬다.
    onPath[u] = false;
    path.pop();
  };

  walk(source);
  return result;
}
```

실행하면 이렇게 나옵니다.

dfsAllPaths(6, [[0,2],[0,1],[1,2],[1,4],[2,0],[2,4],[2,5],[5,5]], 0, 4)   →   [[0,1,2,4], [0,1,4], [0,2,4]]
dfsAllPaths(4, [[0,1],[0,2],[1,3],[2,3]], 0, 3)                           →   [[0,1,3], [0,2,3]]
dfsAllPaths(4, [[0,1],[0,2],[1,2],[1,3],[2,3]], 0, 3)                     →   [[0,1,2,3], [0,1,3], [0,2,3]]

### 알아 두면 좋은 개념 — 출력 민감 알고리즘

파트 1 에서 센 값을 몇 그래프로 넓혀 나란히 놓아 봅시다. 격자는 한 변이 `m` 칸이고 오른쪽과 아래로만 간선이 있는
그래프이며, 왼쪽 위에서 오른쪽 아래까지의 경로를 셉니다.

<!--proof:related-output-->

| 그래프 | 정점 수 | 간선 수 | 경로 수 N | 출력에 적는 정점 번호 수 |
| --- | ---: | ---: | ---: | ---: |
| 전개가 쓰는 그래프 | 6 | 8 | 3 | 10 |
| 3×3 격자 | 16 | 24 | 20 | 140 |
| 7×7 격자 | 64 | 112 | 3,432 | 51,480 |

7×7 격자는 정점 예순넷에 간선 112 개인데 5 만 개가 넘는 정점 번호를 적어야 합니다. **입력은 조금 커졌는데 출력이 천 배
넘게 커졌어요.** 이런 과제에서 비용을 입력 크기만으로 적으면 아무것도 말하지 못합니다. **비용을 입력 크기와 출력 크기
둘로 적는 알고리즘**을 출력 민감 알고리즘(output-sensitive algorithm)이라고 부릅니다.

| 비용을 적는 방식 | 식의 모양 | 예 |
| --- | --- | --- |
| 보통의 알고리즘 | 입력 크기의 식 | 정렬은 `n log n` |
| 출력 민감 알고리즘 | 입력 크기와 출력 크기의 식 | 이 편은 이웃 목록 비용에 탐색 비용과 출력에 적는 숫자 수를 더한 것 |

같은 이름이 이 편 밖에서도 그대로 쓰입니다. 볼록 껍질을 구하는 과제에서 껍질 위의 점이 `h` 개일 때 `n log h` 로 끝내는
절차가 그렇고, [`bentleyOttmann` 가이드](../../geometry/bentleyOttmann/bentleyOttmann-guide.md)의 선분 교차 찾기도 그래요.
셋 다 **답을 적는 데 드는 비용이 바닥**이고, 그 바닥 위에 무엇이 얼마나 더 붙는지가 절차를 가르는 자리입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 식으로 무엇이 나오는지, 무엇이 매 순간 참으로 남는지,
그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 답이 목록이다 | 「경로가 있는가」나 「가장 짧은 경로」가 아니라 「경로를 전부 적어라」를 묻는다 | `result` 배열 하나를 두고 완성될 때마다 담는다 |
| 답의 개수에 상한이 있다 | 경로 수가 묶여 있어 출력만으로 시간이 끝나지 않는다 | 결과를 다 모아 두고 마지막에 반환한다 |
| 경로가 단순 경로다 | 같은 정점을 두 번 담지 않는다 | `onPath` 한 칸으로 「지금 경로 안에 있는가」를 판정한다 |

가장 짧은 경로 하나만 필요한 과제에 이 절차를 쓰면 무엇이 어긋나는지는 값으로 확인됩니다. 7×7 격자에서 두 질문의 답을
나란히 놓았어요.

<!--proof:fit-shortest-->

| 질문 | 답의 줄 수 | 적는 정점 번호 수 |
| --- | ---: | ---: |
| 모든 단순 경로 | 3,432 | 51,480 |
| 가장 짧은 경로 하나 | 1 | 15 |

7×7 격자에서 가장 짧은 경로와 가장 긴 경로가 모두 정점 15 개라, 모든 단순 경로가 가장 짧은 경로이기도 합니다.

<!--/proof-->

앞은 답을 다 적는 것이고 뒤는 하나만 적는 것입니다. 하나만 필요하면 꺼내는 순서를 간선 수 차례로 만드는 절차를 써요.
[`bfsShortestPath` 가이드](../bfsShortestPath/bfsShortestPath-guide.md)가 그 절차입니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "모든 경로를 출력"   "가능한 모든 방법을 나열"   "빠짐없이 뽑아"
  "같은 지점을 두 번 지나지 않는다"               "사전식 순서로 정렬해"

제약에 이런 모양이 보이면
  답의 개수 자체에 상한이 있다         ← 열거 과제라는 뜻이다
  정점 수가 1,000 규모로 작다          ← 정점 수가 아니라 경로 수가 비용을 정한다는 뜻이다
  경로 수 상한이 정점 수보다 훨씬 크다 ← 답을 적는 것이 비용의 바닥이라는 뜻이다
```

반대로 **「최소 몇 번 만에」·「경로가 존재하는가」** 가 보이면 이 단서는 해당하지 않습니다. 그때는 경로를 하나만 만들거나
도달 가능성만 판정하면 되고, 둘 다 `V + E` 규모로 끝나요. 「경로 수만 세어라」도 이 절차의 자리가 아닙니다 — 방향
그래프에서 단순 경로의 수를 세는 것은 경로를 만들지 않고는 알 수 없는 어려운 과제이지만, 사이클이 없는 그래프라면 정점마다
값을 하나씩 쌓는 것으로 `V + E` 에 끝납니다.

#### 실제로 쓰이는 곳

- **NetworkX `all_simple_paths`** — 이 글이 만든 것과 같은 함수입니다. 문서 문자열이 *"This algorithm uses a modified
  depth-first search to generate the paths. A single path can be found in $O(V+E)$ time but the number of simple paths
  in a graph can be very large."* 라 적어 「깊이 우선 탐색을 고쳐 쓴다」와 「경로 수가 매우 커질 수 있다」를 함께
  밝힙니다. 실제 열거는 `_all_simple_edge_paths` 가 하는데, 재귀가 아니라 **명시 스택**이고
  (`stack = [iter([(None, source)])]`), 지금 경로를 `current_path` 라는 사전 하나로 담아 되돌아갈 때 `stack.pop()` 과
  `current_path.popitem()` 을 짝지어 실행합니다 — 이 글의 `path.pop()` 과 `onPath[u] = false` 가 하는 일을 한 자료구조가
  겸하는 모양이에요.
  ([networkx/algorithms/simple_paths.py](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/simple_paths.py), 조회 2026-08-29)
- **igraph `igraph_get_all_simple_paths`** — C 로 쓰인 그래프 라이브러리의 같은 기능입니다. 문서 주석이 *"A path is
  simple if its vertices are unique, i.e. no vertex is visited more than once."* 로 단순 경로를 정의하고, *"Note that
  potentially there are exponentially many paths between two vertices of a graph, and you may run out of memory when
  using this function when the graph has many cycles."* 로 경로 수가 지수적으로 커진다는 것을 경고합니다. 표시는 비트
  배열 하나이고 `IGRAPH_BIT_SET(added, nei)` 로 켰다가 `IGRAPH_BIT_CLEAR(added, up)` 로 지웁니다.
  ([src/paths/simple_paths.c](https://raw.githubusercontent.com/igraph/igraph/master/src/paths/simple_paths.c), 조회 2026-08-29)

두 곳 다 **표시를 켜는 자리와 지우는 자리를 짝지어** 두었고, 둘 다 재귀가 아니라 명시 스택으로 깊이를 관리합니다.
라이브러리는 입력 크기를 미리 알 수 없어서 호출 한도에 걸리는 구현을 둘 수 없기 때문이에요.

#### 경쟁 설계와의 대조

같은 목표를 노리는 **다른 절차**가 있어요 — **도달 가능성 가지치기**입니다. 재귀 한 겹에 들어갈 때마다, 지금 경로 위의
정점을 뺀 그래프에서 도착 정점에 갈 수 있는 정점을 간선을 거꾸로 따라가며 전부 표시하고, 표시되지 않은 이웃으로는 아예
내려가지 않아요. 이 가이드의 절차는 정점 5 로 내려가 봐야 막다른 자리인 것을 알지만, 가지치기는 정점 2 에서 역방향
탐색을 한 번 해서 정점 4 에 갈 수 있는 정점에 5 가 없다는 것을 먼저 압니다.

같은 그래프에 둘을 걸고 **방문 노드 · 이웃 검사 · 할당 칸**을 셌습니다. 이웃 검사는 이웃 목록이나 역방향 목록에서
원소 하나를 읽은 횟수이고, 할당 칸은 실행 중에 새로 만든 표시 배열의 칸을 버린 것까지 모두 더한 수예요. 처음에 한 번
만드는 이웃 목록 · 역방향 목록 · 경로 표시 배열과 스택은 두 설계 모두 할당 칸에서 뺐습니다. 전개가 쓰는 여섯 정점 그래프에서는
방문 노드가 두 개밖에 안 갈려, 그 차이가 설계의 성질에서 온 것인지 그래프가 작아서 그런 것인지 구분되지 않습니다. 그래서
간선 수가 비슷한 두 그래프를 더 씁니다 — 입력은 난수 없이 식으로 만들었으니 시드가 없어요. 격자는 한 변 5 칸에 오른쪽과
아래로만 간선이 있는 그래프이고, **덫 그래프**는 정점 0 에서 도착 정점으로 바로 가는 간선 하나와, 서로 전부 이어졌지만
도착 정점으로 나가는 간선이 없는 **막다른 무리** 하나로 들어가는 간선이 있는 그래프입니다. 무리가 넷일 때 그리면 이렇습니다.

| 덫 · 방문 노드 | 13,702 | 2 | 가지치기 |

| 격자 · 할당 칸 | 0 | 24,156 | 이 가이드 |

**우열이 반대가 되는 조건은 「막다른 가지의 비율」입니다.** 방문 노드 중 경로를 하나도 못 만드는 것이 얼마인가로 갈려요.
격자에서는 그 비율이 0 이라 역방향 탐색이 통째로 헛일이 되고, 덫 그래프에서는 진입 13,702 번 가운데 답이 된 것이 하나뿐이라
역방향 탐색 한 번이 그 진입을 거의 다 없앱니다. 이 가이드가 내주는 것은 막다른 가지가 많은 그래프에서의 진입 횟수이고, 받는
것은 둘이에요 — 노드마다 표시 배열을 새로 잡지 않아 **할당 칸이 0** 이고, 코드가 스무 줄 남짓으로 끝납니다.

### 수식 정의와 유도

방향 그래프 $G=(V,E)$ 에서 출발 정점 $s$ 에서 도착 정점 $t$ 까지의 단순 경로 모임은 아래와 같아요.

$$\mathcal{P}(s,t)=\{(v_0,v_1,\dots,v_k)\;:\;v_0=s,\;v_k=t,\;(v_i,v_{i+1})\in E,\;i\neq j \Rightarrow v_i\neq v_j\}$$

| 이름 | 정의 | 재는 것 |
| --- | --- | --- |
| $N$ | $\lvert\mathcal{P}(s,t)\rvert$ | 답의 줄 수 |
| $L$ | $\sum_{p\in\mathcal{P}(s,t)}\lvert p\rvert$ | 출력에 적는 정점 번호의 개수 |
| $R$ | `walk` 에 진입한 횟수 | 상태 공간 트리의 마디 수 |

셋을 전개 입력에 넣어 검산해 봅시다.

<!--proof:math-verify-->

| 이름 | 정의 | 전개 입력에서 |
| --- | --- | --- |
| N | 단순 경로의 수 | 3 |
| L | 경로 길이의 합, 곧 출력에 적는 정점 번호의 개수 | 4 + 3 + 3 = 10 |
| R | walk 에 진입한 횟수 | 9 |

R 에서 N 을 뺀 6 번은 답이 되지 못한 부분 경로에 들어간 횟수입니다.

<!--/proof-->

$N$ 과 $L$ 은 답이 정하지만 $R$ 은 그래프의 모양이 정합니다. 여기서는 $N$ 이 얼마나 커질 수 있는지를 닫힌 형태로 내요.
서로 다른 두 정점 사이에 양쪽 방향 간선이 전부 있는 **완전 방향 그래프**를 잡으면, $s$ 에서 $t$ 로 가는 단순 경로 하나는
**나머지 $n-2$ 개 정점 중 몇 개를 골라 순서까지 정한 나열** 하나와 짝을 이룹니다. 정점 다섯에서 몇 개를 보면 이렇습니다.

<!--proof:math-n5-->

| 경로 | 가운데 정점의 나열 |
| --- | --- |
| 0 → 4 | ( ) |
| 0 → 2 → 4 | (2) |
| 0 → 1 → 3 → 4 | (1, 3) |
| 0 → 3 → 1 → 4 | (3, 1) |

정점 5 개 완전 방향 그래프에서 정본이 낸 경로는 16 개이고, 위 넷은 그중 일부입니다.

<!--/proof-->

양쪽 방향 간선이 다 있으니 어떤 나열이든 실제 경로가 되고, 순서가 다르면 다른 경로예요. 중간에 $k$ 개를 고른 나열의 수는
$\frac{(n-2)!}{(n-2-k)!}$ 이므로 합이 경로 수입니다.

$$N(n)=\sum_{k=0}^{n-2}\frac{(n-2)!}{(n-2-k)!}$$

$n = 6$ 에서 이 합을 항마다 세면 이렇습니다. 두 끝을 뺀 정점이 넷이에요.

<!--proof:math-n6-->

| 중간 정점 수 k | 항 | 값 |
| ---: | --- | ---: |
| 0 | 4!/4! | 1 |
| 1 | 4!/3! | 4 |
| 2 | 4!/2! | 12 |
| 3 | 4!/1! | 24 |
| 4 | 4!/0! | 24 |

합은 65 이고, 정점 6 개 완전 방향 그래프에 정본을 실행한 경로 수 65 와 같습니다.

<!--/proof-->

합의 첨자를 $j=n-2-k$ 로 바꾸면 분모가 $j!$ 이 되고, $(n-2)!$ 을 합 밖으로 뺄 수 있어요.

$$N(n)=\sum_{j=0}^{n-2}\frac{(n-2)!}{j!}=(n-2)!\sum_{j=0}^{n-2}\frac{1}{j!}$$

남은 합은 $e = \sum_{j\ge 0} 1/j!$ 의 급수를 앞 $n-1$ 항에서 끊은 것입니다. 그러니 $N(n)$ 은 $e\,(n-2)!$ 보다 잘린 꼬리만큼
작아요. 실제 값으로 그 차이를 보면 이렇습니다.

<!--proof:math-floor-->

| n | N(n) | e·(n−2)! | 차이 |
| ---: | ---: | ---: | ---: |
| 3 | 2 | 2.718 | 0.718 |
| 4 | 5 | 5.437 | 0.437 |
| 5 | 16 | 16.310 | 0.310 |
| 6 | 65 | 65.239 | 0.239 |
| 7 | 326 | 326.194 | 0.194 |
| 8 | 1,957 | 1957.163 | 0.163 |

잘린 꼬리에 $(n-2)!$ 을 곱한 값이 1 보다 작다는 것을 보이면 내림으로 값이 정해집니다. 꼬리의 첫 항에 $(n-2)!$ 을
곱하면 $\frac{1}{n-1}$ 이고, 그 뒤로 각 항은 앞 항의 $\frac{1}{n}$ 배 이하로 줄어드므로(첫 비율이 $\frac{1}{n}$ 이고 뒤로 갈수록
더 작아지므로) 등비급수로 묶어 위에서 누를 수 있어요.

$$(n-2)!\sum_{j=n-1}^{\infty}\frac{1}{j!}<\frac{1}{n-1}\cdot\frac{1}{1-\frac{1}{n}}=\frac{n}{(n-1)^2}\le 1 \quad (n\ge 3)$$

맨 오른쪽 값을 실제로 넣어 보면 조건 $n \ge 3$ 이 어디서 오는지 보입니다.

<!--proof:math-tail-->

| n | n/(n−1)² | 값 | 1 이하 여부 |
| ---: | --- | ---: | --- |
| 2 | 2 / 1 | 2.000 | 아니다 |
| 3 | 3 / 4 | 0.750 | 그렇다 |
| 4 | 4 / 9 | 0.444 | 그렇다 |
| 6 | 6 / 25 | 0.240 | 그렇다 |

$n = 2$ 에서만 1 을 넘고, $n$ 이 커질수록 줄어듭니다. 그래서 $n \ge 3$ 이면 꼬리가 1 을 채우지 못하고, 내림이 정확한 값을 줘요.

$$N(n)=\left\lfloor e\,(n-2)!\right\rfloor \quad (n \ge 3)$$

식을 그대로 코드로 옮기면 한 줄짜리 반복문입니다. 항을 곱해 가며 더하면 계승을 따로 구할 필요가 없어요.

```ts
function pathCount(n: number): bigint {
  let term = 1n; // k = 0 일 때의 (n-2)!/(n-2)! = 1
  let sum = 1n;
  for (let k = 1; k <= n - 2; k++) {
    term *= BigInt(n - 1 - k); // (n-2)!/(n-2-k)! 를 한 항씩 늘린다
    sum += term;
  }
  return sum;
}
```

작은 $n$ 에서 이 코드의 값과 완전 방향 그래프에 정본을 실행한 경로 수를 나란히 놓았습니다.

<!--proof:math-code-->

```text
pathCount(4)   →   5n      정본 실행 5 개
pathCount(5)   →   16n     정본 실행 16 개
pathCount(6)   →   65n     정본 실행 65 개
pathCount(7)   →   326n    정본 실행 326 개
pathCount(8)   →   1957n   정본 실행 1,957 개
```

이제 계수입니다. 경로 수 상한이 10,000 개이니, 이 모양의 그래프가 정점 몇 개까지 허용되는지가 나옵니다.

<!--proof:math-complete-->

| 정점 n | ⌊e·(n−2)!⌋ | 경로 수 10⁴ 이하 여부 |
| ---: | ---: | --- |
| 4 | 5 | 그렇다 |
| 5 | 16 | 그렇다 |
| 6 | 65 | 그렇다 |
| 7 | 326 | 그렇다 |
| 8 | 1,957 | 그렇다 |
| 9 | 13,700 | 아니다 |
| 10 | 109,601 | 아니다 |

**정점 아홉 개면 벌써 상한을 넘습니다.** 정점이 1,000 개까지 허용되는 과제인데 이 모양으로는 여덟 개가 한계예요. 같은
계산을 격자에서도 해 봅시다. 오른쪽과 아래로만 가는 $m\times m$ 격자에서, 왼쪽 위에서 오른쪽 아래까지 가는 경로 하나는
오른쪽 이동 $m$ 번과 아래 이동 $m$ 번을 늘어놓은 나열 하나와 짝을 이룹니다. $m = 2$ 격자는 이렇게 생겼어요.

<!--fig:math-grid-->
![m = 2 격자 — 오른쪽과 아래로만 간선이 있다](./figs/math-grid.svg)

경로마다 이동을 적으면 이렇습니다.

<!--proof:math-grid-seq-->

| 경로 | 이동의 나열 |
| --- | --- |
| 0 → 1 → 2 → 5 → 8 | RRDD |
| 0 → 1 → 4 → 5 → 8 | RDRD |
| 0 → 1 → 4 → 7 → 8 | RDDR |
| 0 → 3 → 4 → 5 → 8 | DRRD |
| 0 → 3 → 4 → 7 → 8 | DRDR |
| 0 → 3 → 6 → 7 → 8 | DDRR |

정본이 낸 경로는 6 개이고, C(4, 2) = 6 과 같습니다. R 은 오른쪽으로, D 는 아래로 한 칸입니다.

<!--/proof-->

길이 $2m$ 의 나열에서 오른쪽 이동이 올 자리 $m$ 개를 고르는 수이므로 $N=\binom{2m}{m}$ 입니다. 정점 수는 $V=(m+1)^2$ 이라
$m=\sqrt V-1$ 이고, 스털링 근사 $\binom{2m}{m}\sim 4^m/\sqrt{\pi m}$ 을 쓰면 $N$ 이 $\sqrt V$ 에 대해 지수적으로 커집니다.
여기에도 규모를 넣어 보죠.

<!--proof:math-grid-->

| 격자 m | 정점 수 (m+1)² | C(2m, m) | 경로 수 10⁴ 이하 여부 |
| ---: | ---: | ---: | --- |
| 1 | 4 | 2 | 그렇다 |
| 2 | 9 | 6 | 그렇다 |
| 3 | 16 | 20 | 그렇다 |
| 4 | 25 | 70 | 그렇다 |
| 5 | 36 | 252 | 그렇다 |
| 6 | 49 | 924 | 그렇다 |
| 7 | 64 | 3,432 | 그렇다 |
| 8 | 81 | 12,870 | 아니다 |

**격자는 한 변이 여덟 칸이면 상한을 넘습니다.** 그때 정점은 여든한 개뿐이에요. 두 표가 같은 것을 말합니다 — 이 과제의
규모에서 정점 수 상한 1,000 은 거의 아무것도 막지 않고, 실제로 입력의 크기를 정하는 것은 경로 수 상한 10,000 하나입니다.

### 불변식 — 되돌아간 뒤의 상태가 들어가기 직전과 같다

파트 1 에서 코드가 동작하는 것을 열여섯 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는 뜻은
아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> `walk(u)` 호출 하나가 반환한 직후, `path` 와 `onPath` 는 그 호출 직전과 글자 그대로 같습니다. 그리고 `walk` 안의 어느
> 지점에서도 `onPath[v]` 가 참인 정점의 모임은 `path` 에 담긴 정점의 모임과 같습니다.

| 문장 | 보장하는 것 | 깨지면 |
| --- | --- | --- |
| 반환 직후가 직전과 같다 | 형제 갈래가 서로 영향을 주지 않는다 | 경로가 사라지거나 앞 경로가 섞인다 |
| 표시가 `path` 안의 정점과 같다 | 같은 정점을 두 번 담지 않는다 | 같은 정점을 두 번 담은 경로가 나온다 |

「반환한 직후」가 중요합니다. 재귀가 다 끝난 뒤 한 번만 참인 것이 아니라 **한 겹이 반환할 때마다** 참이라는 뜻이에요.
그래야 형제 갈래가 그 상태를 그대로 이어받습니다.

**출발점부터 봅시다.** `walk(source)` 를 부르기 직전에 `path` 는 비어 있고 `onPath` 는 전부 거짓이라 두 모임이 둘 다
공집합으로 같습니다. 그 뒤로 상태를 바꾸는 자리는 넷이에요.

| 연산 | 상태 변화 | 두 문장이 유지되는 근거 |
| --- | --- | --- |
| 진입 | `onPath[u]` 가 참이 되고 `path` 뒤에 `u` 가 붙는다 | 한 정점이 양쪽에 동시에 더해진다. `u` 는 경로에 없는 이웃으로 내려온 것이라 직전에 두 모임 어디에도 없었다 |
| 도착 정점에서 담기 | `result` 에 복사본 하나가 더해진다 | `path` 와 `onPath` 를 건드리지 않는다 |
| 경로 안 이웃 건너뛰기 | 아무것도 안 바뀐다 | 판정만 하고 지나간다 |
| 되돌아가기 | `onPath[u]` 가 거짓이 되고 `path` 끝에서 하나가 빠진다 | 진입에서 더한 그 정점을 양쪽에서 하나씩 뺀다. 그 사이에 부른 `walk` 는 모두 반환해 상태를 되돌려 놓았으니 `path` 끝에 있는 것이 `u` 다 |

첫 줄과 넷째 줄이 정확히 맞물리는 것을 값으로 확인해 봅시다. 전개의 T5 와 T6 이 그 자리예요.

<!--proof:invariant-t5t6-->

| 걸음 | 한 일 | path | 켜진 표시 |
| --- | --- | --- | --- |
| T3 | walk(2) 진입 | [0, 1, 2] | {0, 1, 2} |
| T5 | walk(4) 진입 · 경로를 담는다 | [0, 1, 2, 4] | {0, 1, 2, 4} |
| T6 | 4 를 뺀다 | [0, 1, 2] | {0, 1, 2} |
| T7 | walk(5) 진입 | [0, 1, 2, 5] | {0, 1, 2, 5} |

T5 에 들어가기 직전(T4 직후)의 path 는 [0, 1, 2] 이고, T6 에서 되돌아온 직후의 path 도 [0, 1, 2] 로 같습니다.

<!--/proof-->

T6 이 남긴 것이 하나도 없어서 T7 이 같은 자리에서 다른 이웃으로 내려갔고, 뒤의 T9 가 정점 4 를 다시 쓸 수 있었습니다.
넷째 줄의 근거 「그 사이에 부른 `walk` 는 모두 반환해 상태를 되돌려 놓았다」는 첫 문장을 안쪽 호출에 먼저 적용한 것이에요.
가장 깊은 호출은 안에서 `walk` 를 부르지 않으니 넷째 줄만으로 성립하고, 한 단 바깥의 호출은 안쪽이 모두 성립한다는 것을
기대어 성립합니다. 입력을 넷으로 늘려 반환마다 두 문장을 다시 확인했습니다.

<!--proof:invariant-check-->

| 입력 | 확인한 반환 | 직전과 다른 반환 | 표시와 path 가 다른 시점 | 경로 수 |
| --- | ---: | ---: | ---: | ---: |
| 전개가 쓰는 여섯 정점 | 9 | 0 | 0 | 3 |
| 다이아몬드 | 5 | 0 | 0 | 2 |
| 덫 그래프 k = 5 | 67 | 0 | 0 | 1 |
| 무작위 V = 8 · E = 32 (시드 20260930) | 133 | 0 | 0 | 35 |

네 입력의 반환 214 번에서 두 문장이 깨진 시점은 0 개입니다.

<!--/proof-->

덫 그래프는 막다른 무리가 다섯인 것이고, 무작위 입력은 정점 번호 둘을 시드 20260930 의 난수로 32 번 뽑아 간선으로 삼은
것이라 자기 루프와 중복 간선이 섞여 있습니다. 출발 정점은 첫 간선의 시작 정점, 도착 정점은 마지막 간선의 끝 정점이에요.
이 불변식이 답의 정확성을 그대로 줍니다. 표시가 켜진 정점이 `path` 안의 정점과 언제나 같으므로 경로 안 이웃을 건너뛰는 갈래가 막는 것은 **정확히
지금 경로 안에 있는 정점**이고, 그래서 담기는 것이 전부 단순 경로예요. 그리고 한 겹이 반환할 때 상태를 원래대로 두므로, 같은
정점을 지나는 서로 다른 경로가 서로를 막지 않습니다. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

| 입력 | 호출 | 처리되는 자리 | 결과 | 진입 횟수 |
| --- | --- | --- | --- | ---: |
| 최소 입력 | `dfsAllPaths(1, [], 0, 0)` | 진입하자마자 도착 정점이라 복사 하나로 끝난다 | [[0]] | 1 |
| 출발과 도착이 같다 | `dfsAllPaths(3, [[0,1],[1,2]], 1, 1)` | 이웃 목록을 한 번도 읽지 않는다 | [[1]] | 1 |
| 경로가 없다 | `dfsAllPaths(3, [[0,1]], 0, 2)` | 도착 정점에서 담는 갈래가 한 번도 실행되지 않는다 | [] | 2 |
| 간선 방향이 반대다 | `dfsAllPaths(2, [[1,0]], 0, 1)` | adj[0] 이 비어 있어 바로 되돌아간다 | [] | 1 |
| 자기 루프 | `dfsAllPaths(2, [[0,0],[0,1]], 0, 1)` | 이웃 목록을 만들 때 u === v 로 빠진다 | [[0,1]] | 2 |
| 중복 간선 | `dfsAllPaths(3, [[0,1],[0,1],[1,2]], 0, 2)` | 같은 이웃이 모임에 한 번만 들어간다 | [[0,1,2]] | 3 |
| 사이클 | `dfsAllPaths(3, [[0,1],[1,2],[2,0],[0,2]], 0, 2)` | 경로 안 이웃을 건너뛰는 갈래가 2 → 0 을 막는다 | [[0,1,2], [0,2]] | 4 |

자기 루프와 중복 간선은 이웃 목록을 만드는 자리에서 처리되고 그 뒤로는 없는 것과 같아요. 사이클은 다릅니다 — 간선이
그대로 남아 있고, 경로 안 이웃을 건너뛰는 갈래가 매번 판정해서 막습니다.

**이제 깨뜨려 봅시다.** 「반환 직후가 직전과 같다」를 지키던 줄이 어느 것인지는 바꿔 보면 확인됩니다. 되돌아가는 자리의
표시를 지우는 줄 **하나만** 지웁니다.

```ts
  // onPath[u] = false;   ← 이 한 줄만 지웠다. path.pop() 은 그대로 둔다
  path.pop();
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-no-unmark-->

| 입력 | 표시 지움(정본) | 표시 남김 | 두 답 |

시험한 「한 번 켠 표시를 끝까지 둔다」와 같은 절차예요. 전개 입력에서 무엇이 언제 막히는지 그 절차로 적으면 이렇습니다.

막혔습니다. **한 줄로 이은 네 정점에서는 두 답이 같다는 것**도 함께 보세요. 경로가 하나뿐인 그래프에서는 첫 경로를 담은
뒤에 갈 곳이 없어 표시가 남든 안 남든 결과가 같습니다. 이 입력만 시험하면 지워 놓고도 통과해서, 잘못된 코드를 그대로 두게 돼요.

### 비용 계산

#### 비용을 세는 과정

한 번의 진입이 하는 일은 표시 한 칸을 켜고, 경로에 하나를 담고, 도착 정점이면 경로를 복사하고 아니면 자기 이웃 목록을 한 번
읽고, 마지막에 표시를 지우고 경로에서 하나를 빼는 것뿐입니다. 전개의 걸음으로 확인하면 이렇게 나와요.

<!--proof:perf-count-->

| 걸음 | 진입한 정점 | 한 일 | 읽은 이웃 수 |
| --- | --- | --- | ---: |
| T1 | 0 | 이웃 목록을 읽는다 | 2 |
| T2 | 1 | 이웃 목록을 읽는다 | 2 |
| T3 | 2 | 이웃 목록을 읽는다 | 3 |
| T5 | 4 | ① | 0 |
| T7 | 5 | 이웃 목록을 읽는다 | 0 |
| T9 | 4 | ① | 0 |
| T11 | 2 | 이웃 목록을 읽는다 | 3 |
| T13 | 4 | ① | 0 |
| T15 | 5 | 이웃 목록을 읽는다 | 0 |

진입 9 번에 이웃 목록에서 읽은 원소는 10 개입니다.

<!--/proof-->

① 로 들어간 T5 · T9 · T13 은 이웃 목록을 읽지 않고, 막다른 정점 5 로 들어간 T7 · T15 는 목록이 비어 있어 0 이에요. 그러니
탐색 비용은 **진입 횟수 $R$ 에, 진입한 정점마다 그 이웃 목록 길이를 더한 것**입니다. $R$ 은 상태 공간 트리의 마디 수이고,
전개 입력에서 $R = 9$ 가운데 답이 된 마디가 $N = 3$ 개예요. 진입한 정점의 이웃 목록은 길이가 `V − 1` 이하이므로 이웃 읽기는
`R · V` 이하입니다. 그 앞에 이웃 목록을 만들고 정렬하는 비용이, 뒤에 결과를 복사하는 비용이 붙어요.

```text
총식 = 이웃 목록 만들기 + 목록 정렬        + 탐색                           + 결과 복사
        Θ(V + E)          O(E · log V)      Θ(R + Σ_{진입} |adj[u]|) ≤ O(R·V)   Θ(L)

메모리 = 이웃 목록 Θ(V + E) + onPath · path Θ(V) + 재귀 스택 Θ(V) + 결과 Θ(L)
```

여기서 센 것은 **이웃 목록의 원소 읽기, 정렬 비교, 그리고 결과에 적는 숫자**입니다. 자기 루프를 빼고 중복을 접는 자리는 해시
집합이라 간선 하나에 상수 번이고, `Array.prototype.sort` 가 실제로 몇 번 비교하는지는 실행 환경이 정하므로 `O(E · log V)` 는
**비교 정렬의 상한**을 적은 것이에요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`source` 에서 나가는 간선이 없다) | `O(V + E log V)` | `Θ(V + E log V)` 이하 — 정렬 비교는 구현이 정한다 |
| **평균적인 경우** (그래프 분포를 정하지 않았다) | `O(V + E log V + R·V + L)` | 정의되지 않는다 |
| **최악의 경우** (막다른 무리가 크다) | `O(V + E log V + R·V + L)` | `R` 에 대해 타이트 — `R` 번의 진입은 빠짐없이 일어난다 |

`R` 이 식에 그대로 남아 있는 것이 이 과제의 특징입니다. `R` 을 `V` 와 `E` 만으로 적을 수가 없어요. 격자에서는 진입한 마디가
거의 전부 경로의 앞부분이 됩니다.

<!--proof:grid-count-->

| 격자 m | 정점 수 | 경로 수 | 방문 노드 | 이웃 검사 |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 9 | 6 | 19 | 18 |
| 3 | 16 | 20 | 69 | 68 |
| 4 | 25 | 70 | 251 | 250 |
| 5 | 36 | 252 | 923 | 922 |

5×5 격자에서 경로 252 개에 진입이 923 번이에요. 막다른 자리가 없는 그래프에서는 `R` 이 경로 수 `N` 과 같은 규모입니다.
**평균이 정의되지 않는 이유**를 적어 둡니다. 이 과제는 간선이 어떻게 놓이는지에 대한 분포를 주지 않아요. `R` 이 그래프의
모양에 통째로 달려 있는데 그 모양의 분포가 정해지지 않으면 기댓값을 계산할 대상이 없습니다. 정점 수와 간선 수가 비슷해도
`R` 이 갈려요.

<!--proof:perf-spread-->

| 그래프 | 정점 수 | 간선 수 | 경로 수 | 방문 노드 |
| --- | ---: | ---: | ---: | ---: |
| 5×5 격자 | 36 | 60 | 252 | 923 |
| 덫 그래프 k = 8 | 10 | 58 | 1 | 13,702 |

간선 수는 60 과 58 로 비슷한데 방문 노드는 14.8 배 갈립니다.

<!--/proof-->

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요. 같은 입력을 두 번 넣으면 진입
횟수까지 똑같이 나옵니다. 다만 그 최악 보장의 값이 `V` 와 `E` 의 식이 아니라 `R` 을 담고 있고, `R` 자체는 입력마다 재야
하는 값이에요.

경계의 종류도 갈라 적습니다. 하한은 `Ω(L)` 이고 이것은 **어떤 절차에도 걸립니다** — 답을 적는 데 숫자 `L` 개를 써야 하니까요.
최선의 경우는 이웃 목록을 만드는 비용만 남은 값이고, 이때 `R = 1` 이며 `L` 은 `s = t` 일 때만 1 이고 아니면 0 입니다.

#### 최악을 만드는 입력

`R` 을 최대로 만드는 입력을 실제로 구성해 봅시다. 「경쟁 설계와의 대조」에서 그린 덫 그래프가 그것입니다. 정점 0 에서 도착
정점으로 바로 가는 간선 하나가 유일한 경로이고, 정점 `1 … k` 가 서로 전부 이어진 막다른 무리로 들어가는 입구가 하나 있어요.
무리에서 도착 정점으로 나가는 간선은 하나도 없습니다. `k` 를 키우면서 실행했습니다.

<!--proof:worst-input-->

| 막다른 무리 k | 정점 수 | 간선 수 | 경로 수 | 방문 노드 |
| ---: | ---: | ---: | ---: | ---: |
| 6 | 8 | 32 | 1 | 328 |
| 7 | 9 | 44 | 1 | 1,959 |
| 8 | 10 | 58 | 1 | 13,702 |
| 9 | 11 | 74 | 1 | 109,603 |

**경로 수는 계속 1 인데 진입 횟수가 계승만큼 늘어납니다.** `k` 가 하나 늘 때마다 진입이 약 `k` 배가 되는 것이 표의 마지막
열에서 확인돼요. 무리 안의 단순 경로가 전부 상태 공간 트리의 마디가 되기 때문입니다. 간선 수 상한 10,000 을 다 쓰면
`k(k − 1) ≤ 10,000` 에서 `k` 를 100 까지 키울 수 있고, 그때 진입 횟수는 99 의 계승 규모예요.

| 규모 | 묶는가 | 묶이는 값 |
| --- | --- | --- |
| 정점 1,000 개 이하 | 묶는다 | `V` |
| 간선 10,000 개 이하 | 묶는다 | `E` |
| 경로 10,000 개 이하 | 묶는다 | `N` 과 `L` — 출력 크기 |
| 진입 횟수 `R` | 안 묶는다 | 위 셋을 다 지키면서 `R` 을 계승 규모로 키울 수 있다 |

「경로 수에 상한이 있으니 시간도 묶인다」는 통념은 이 절차에서 거짓입니다. 출력 크기는 묶여 있는데 그 출력을 찾아가는
비용은 안 묶여 있어요. 그것이 「경쟁 설계와의 대조」의 도달 가능성 가지치기가 있는 이유이고, 그 절차는 방문 노드가 **전부
경로 하나 이상을 만들도록** 해서 `R` 을 출력 크기 규모로 눌러 놓습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 정점 나열을 전부 만들어 놓고 거르던 것을 **간선을 따라가며 한 칸씩 늘리는
것**으로 바꿨고, 「지금 경로 안에 있는가」를 표시 한 칸이 판정하며, 그 표시는 **되돌아가는 자리에서 반드시 지워야** 다음
경로가 만들어집니다.

```text
간선 목록 → 이웃 목록(자기 루프 제외 · 중복 제거 · 오름차순) → walk(source)
  진입: 표시를 켜고 path 에 담는다 → 갈래 ①②③ → 되돌아가기: 표시를 지우고 path 에서 뺀다
    └ 켠 것 하나와 지우는 것 하나가 짝을 이룬다     └ 비용은 V + E log V + R·V + L 이하
```

먼저 답이 붙는 문제 하나입니다. 전개의 T6 에서 정점 4 에서 나오며 표시를 지우고 `path` 에서 뺐어요. 이때부터 되돌아갈
때마다 **표시는 지우고 `path.pop()` 만 하지 않았다면** 최종 결과가 무엇이 되었을까요?

<!--proof:selfcheck-t6-->

```text
T6   4 를 뺀다              path [0, 1, 2]
     ← 이 빼기를 안 하면?
```

<!--check:nopop-->
경로 수는 셋으로 같은데 뒤의 둘이 단순 경로가 아닙니다. 표시를 지웠으니 막히지는 않는데, `path` 가 줄지 않아 앞 경로의
흔적이 그대로 남아요. 정점 4 가 `path` 안에 두 번 들어가는데도 표시는 지워져 있어 ② 가 못 막습니다. 「아이디어를 떠올리는
과정」의 넷째 표 셋째 줄이 같은 것을 다이아몬드에서 보인 자리예요. 표시와 `path` 는 **같은 것을 두 방식으로 적은 것**이라,
되돌아갈 때 한쪽만 지우고 다른 쪽을 그대로 두면 그 순간부터 서로 어긋납니다. 진입마다 `path` 를 적으면 이렇게 쌓입니다.

입력」을 다시 보세요.

- T7 과 T15 에서 정점 5 로 두 번 내려갔다가 두 번 다 아무것도 담지 못하고 되돌아왔습니다. 전개 입력의 간선 하나를 지워서
  그 헛걸음을 없애려면 어느 간선을 지워야 할까요. 그때 진입 횟수가 아홉에서 몇으로 줄어드는지 세어 보세요.
- 불변식은 「반환 직후가 직전과 같다」고 말합니다. 그러면 `result` 는 왜 이 문장에 안 들어갈까요. `result` 를 넣어 문장을
  다시 쓰면 무엇이라고 적어야 하는지 생각해 보세요.
- 덫 그래프에서 진입 횟수가 계승만큼 늘어났습니다. 그 그래프에 간선을 **하나만** 더해서 진입 횟수는 거의 그대로 두고 경로
  수만 늘리려면 어디에 더해야 할까요. 반대로 간선을 하나만 지워서 진입 횟수를 크게 줄이려면 어디를 지워야 합니까.

#### 한 줄 요약

> 함수는 정점 수 `n`, 방향 간선 목록, 출발 정점 `source`, 도착 정점 `target`을 받아, `source`에서 `target`까지 **같은 정점을 두 번 지나지 않는 모든 경로**를 사전식 순서로 반환한다.

#### 스토리

물류 스타트업의 경로 기획자 세아는 도심 배송 시뮬레이터를 만들고 있다. 도시의 거점들은 일방통행 도로로 연결되어 있어서, 어떤 거점에서 다른 거점으로는 갈 수 있어도 그 반대 방향으로는 못 가는 경우가 많다.

세아는 출발 거점에서 목적지 거점까지 갈 수 있는 **모든 배송 루트**를 빠짐없이 뽑아 목록으로 만들려 한다. 단, 한 루트 안에서 같은 거점을 두 번 들르는 것은 낭비이므로 제외한다. 즉 한 루트는 거점을 **최대 한 번씩만** 지난다.

세아는 결과를 정리된 순서로 받고 싶어 한다. 그래서 각 루트는 지나는 거점 번호의 나열로 표현하고, 루트들끼리는 **사전식 순서**(앞 거점부터 번호를 차례로 비교)로 정렬해 돌려주기로 한다.

#### 함수 인터페이스

```ts
export function dfsAllPaths(
  n: number,
  edges: [number, number][],
  source: number,
  target: number,
): number[][];
```

- `n` — 정점 수. 정점 번호는 $0 \ldots n-1$
- `edges` — 방향 간선 목록. 각 원소 `[u, v]`는 `u`에서 `v`로 향하는 **일방향** 간선(`u → v`)
- `source` — 출발 정점 번호
- `target` — 도착 정점 번호
- 반환 — `source`에서 `target`까지의 모든 단순 경로. 각 경로는 지나는 정점 번호의 배열(맨 앞이 `source`, 맨 뒤가 `target`). 경로들은 사전식으로 정렬

#### 제약 조건

- $1 \leq n \leq 10^{3}$
- $0 \leq E \leq 10^{4}$ (여기서 $E$는 `edges`의 길이)
- $0 \leq \text{source}, \text{target} \leq n-1$
- 각 `edges[i] = [u, v]`에 대해 $0 \leq u, v \leq n-1$. 모든 값은 정수
- 방향 그래프. 간선 목록은 자기 루프(`u = v`)나 중복 간선을 포함할 수 있다
- 입력은 **`source`에서 `target`까지의 단순 경로 총 개수가 $10^{4}$개를 넘지 않도록** 주어진다
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

방향 그래프에서 `source`에서 시작해 `target`에서 끝나는 **단순 경로(simple path)** 를 모두 찾는다. 단순 경로란 **같은 정점을 두 번 이상 포함하지 않는** 경로이다.

- 각 경로는 `source`로 시작해서, 간선의 방향을 따라 정점을 이어가다 `target`에 도달하면 끝난다. 경로의 첫 원소는 항상 `source`, 마지막 원소는 항상 `target`이다.
- 한 경로 안에서는 어떤 정점도 두 번 나오지 않는다. 따라서 그래프에 사이클이 있어도, 사이클을 돌아 같은 정점으로 되돌아오는 경로는 만들어지지 않는다.

경로의 표현과 개수:

- 한 경로는 **지나는 정점 번호의 배열**로 나타낸다. 두 경로가 같다는 것은 **정점 배열이 완전히 일치**한다는 뜻이며, 경로의 개수는 서로 다른 정점 배열의 개수로 센다(간선을 몇 개 썼는지가 아니라 정점 나열 기준).

반환 형식(정렬 규칙):

- 경로들은 **사전식(lexicographic) 순서**로 정렬한다. 두 경로를 앞에서부터 원소끼리 비교해, 처음으로 다른 위치에서 번호가 작은 경로가 앞선다. (모든 경로가 `target`에서 끝나므로, 한 경로가 다른 경로의 온전한 앞부분이 되는 일은 없다.)

경계 동작:

- `source`에서 `target`으로 가는 경로가 하나도 없으면 빈 배열 `[]`을 반환한다.
- `source`와 `target`이 같으면, 길이 1짜리 경로 `[source]` 하나만 존재한다 → `[[source]]`.
- 자기 루프 `[v, v]`는 단순 경로에 쓰일 수 없으므로(같은 정점 재방문) 결과에 영향을 주지 않는다.
- 같은 방향의 중복 간선 `[u, v]`가 여러 번 있어도, 서로 다른 경로로 세지 않는다 — 동일한 정점 나열은 한 번만 반환한다.

#### 예시

```ts
// 다이아몬드: 0→1→3 과 0→2→3.
dfsAllPaths(4, [[0,1],[0,2],[1,3],[2,3]], 0, 3); // [[0,1,3],[0,2,3]]

// 여러 경로. 사전식으로 [0,1,2,3] < [0,1,3] < [0,2,3].
dfsAllPaths(4, [[0,1],[0,2],[1,2],[1,3],[2,3]], 0, 3); // [[0,1,2,3],[0,1,3],[0,2,3]]

// 경로 없음.
dfsAllPaths(3, [[0,1]], 0, 2); // []

// source === target.
dfsAllPaths(3, [[0,1],[1,2]], 1, 1); // [[1]]

// 사이클(2→0)이 있어도 단순 경로만: 0→1→2 와 0→2.
dfsAllPaths(3, [[0,1],[1,2],[2,0],[0,2]], 0, 2); // [[0,1,2],[0,2]]

// 자기 루프는 무시된다.
dfsAllPaths(2, [[0,0],[0,1]], 0, 1); // [[0,1]]

// 중복 간선 0→1이 두 번 있어도 같은 경로를 한 번만 센다.
dfsAllPaths(3, [[0,1],[0,1],[1,2]], 0, 2); // [[0,1,2]]
```
