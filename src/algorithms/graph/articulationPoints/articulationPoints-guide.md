# articulationPoints — 자식의 서브트리가 부모 위로 올라갈 간선이 없으면 부모를 지울 때 갈라지는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 정점을 하나씩
지워 보는 방법에서 출발해, 깊이 우선 탐색을 한 번만 하면서 정점마다 수 두 개를 적어 두는 방법까지 갑니다.
그 방법을 준비되는 차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

무향 그래프에서 정점 하나를 지운다는 것은 그 정점과 그 정점에 붙은 간선을 함께 없앤다는 뜻입니다. 지웠을
때 서로 이어져 있던 정점 묶음(**연결 성분**)의 개수가 늘어나는 정점을 **단절점**이라고 부릅니다. 삼각형
`0−1−2` 에 꼬리 `0−3−4` 가 붙은 그래프에 그려 보면 이렇습니다. 강조한 두 정점이 단절점이에요.

<!--fig:concept-cut-->
![전개 입력 — 강조한 정점 0 · 3 이 단절점](./figs/concept-cut.svg)

정점을 하나씩 지워 남는 덩어리를 세면 정의가 그대로 확인됩니다.

<!--proof:conceptDelete-->

| 지운 정점 | 남는 덩어리 | 덩어리 수 | 판정 |
| ---: | --- | --- | --- |
| 0 | {1, 2} · {3, 4} | 1 → 2 | 단절점 |
| 1 | {0, 2, 3, 4} | 1 → 1 | 아니다 |
| 2 | {0, 1, 3, 4} | 1 → 1 | 아니다 |
| 3 | {0, 1, 2} · {4} | 1 → 2 | 단절점 |
| 4 | {0, 1, 2, 3} | 1 → 1 | 아니다 |

덩어리 수가 늘어나는 정점은 0 · 3 이고, 정본이 낸 답도 [0, 3] 입니다.

<!--/proof-->

정점 1 과 2 가 단절점이 아닌 까닭이 이 글의 요점이에요. 둘은 삼각형 위에 있어서, 하나를 지워도 남은 하나가
0 과 직접 이어져 있습니다. 반대로 3 을 지우면 4 가 나머지와 이어질 길이 없어져요. 4 에 붙은 간선이 `3−4`
하나뿐이기 때문입니다.

| 정점의 자리 | 지운 결과 |
| --- | --- |
| 사이클 위 | 사이클의 나머지 길이 남아 갈라지지 않는다 |
| 두 덩어리를 잇는 유일한 정점 | 두 덩어리가 서로 이어질 길을 잃는다 |
| 간선이 하나뿐인 끝 정점 | 자기만 없어지고 나머지는 그대로다 |

이 글이 만드는 절차는 그래프를 **깊이 우선 탐색으로 한 번만** 순회합니다. 깊이 우선 탐색은 한 정점에서 처음
보는 이웃으로 계속 내려가다가 더 갈 곳이 없으면 한 칸 되돌아 나와 다음 이웃을 보는 순회예요. 처음 보는
정점으로 내려갈 때 쓴 간선(**나무 간선**)만 모으면 나무 모양이 되고, 이것을 **깊이 우선 탐색 트리**라고
부릅니다. 나무 간선이 아닌 간선은 아래 정점에서 위쪽 정점으로 이어지는데, 이것을 **되돌아가는 간선**이라고
불러요. 트리에서 `v` 바로 위 정점을 `v` 의 **부모**, 바로 아래 정점을 **나무 자식**이라고 부르고, `v` 와 그
아래에 있는 정점 전부를 `v` 의 **서브트리**라고 부릅니다.

순회하는 동안 정점마다 수 둘을 적습니다. 처음 들어간 차례를 0 부터 매긴 수가 **발견 순서** `disc[v]` 이고,
`v` 의 서브트리에서 되돌아가는 간선 하나로 이를 수 있는 가장 이른 발견 순서(없으면 자기 발견 순서)가
**low 값** `low[v]` 입니다. 같은 그래프를 깊이 우선 탐색 트리로 다시 그리고 정점 안에 두 수를 적었습니다.

<!--fig:concept-dfs-low-->
![깊이 우선 탐색 트리 — 정점 안의 두 수는 disc / low](./figs/concept-dfs-low.svg)

굵은 실선이 나무 간선이고, 대시가 되돌아가는 간선 `2−0` 이에요. 이 간선 덕분에 정점 2 의 서브트리가 발견
순서 0 까지 올라가므로 정점 1 과 2 의 low 값이 0 으로 내려갑니다. 정점 3 과 4 의 서브트리에서는 되돌아가는
간선이 하나도 나가지 않아 low 값이 자기 발견 순서 그대로예요. 판정은 두 규칙으로 합니다.

| 정점 | 단절점인 조건 | 판정이 말하는 것 |
| --- | --- | --- |
| 탐색을 시작한 정점(뿌리)이 아닌 `v` | 나무 자식 `c` 중 `low[c] ≥ disc[v]` 인 것이 있다 | `c` 의 서브트리가 `v` 를 거치지 않고는 `v` 위로 못 올라간다 |
| 뿌리 | 나무 자식이 둘 이상이다 | 뿌리 위에는 정점이 없으니 자식 서브트리끼리 뿌리를 거쳐야만 이어진다 |

두 수와 두 규칙이 전개 입력에 낸 답입니다.

<!--proof:conceptRules-->

| 정점 | disc | low | 나무 자식 | 판정의 근거 | 판정 |
| ---: | ---: | ---: | --- | --- | --- |
| 0 | 0 | 0 | 1 · 3 | 뿌리 · 나무 자식 2 개 | 단절점 |
| 1 | 1 | 0 | 2 | low[2] = 0 < disc[1] = 1 | 아니다 |
| 2 | 2 | 0 | 없음 | 나무 자식이 없다 | 아니다 |
| 3 | 3 | 3 | 4 | low[4] = 4 ≥ disc[3] = 3 | 단절점 |
| 4 | 4 | 4 | 없음 | 나무 자식이 없다 | 아니다 |

두 규칙이 낸 답은 [0, 3] 이고, 정점을 하나씩 지워 본 답도 [0, 3] 입니다.

<!--/proof-->

순회는 한 번이고, 간선 하나는 두 끝의 이웃 목록에 한 자리씩 담겨 그 자리를 정확히 한 번씩 읽습니다. 정점
하나는 들어갈 때 한 번, 이웃을 다 보고 나올 때 한 번 만져요.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선 하나를 두 끝의 목록에 넣는다 | 간선 목록 읽기 `E` 번 |
| 깊이 우선 탐색 한 번 | 이웃 자리를 한 번씩 읽으며 `disc` · `low` 를 적는다 | 이웃 자리 읽기가 간선 수의 두 배 이하 |
| 정점 빼기와 판정 | 자식의 `low` 를 부모의 `disc` 와 비교한다 | 정점마다 한 번 |
| 모두 | | `O(V + E)` |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **무향 간선과 이웃 목록.** 간선 하나를 `[u, v]` 두 수로 적고 죽 늘어놓은 것이 간선 목록이고, 같은 정보를
  정점별로 다시 묶어 한 정점의 이웃을 바로 꺼내게 만든 것이 이웃 목록입니다. 방향이 없으므로 간선 하나가
  `u` 의 목록과 `v` 의 목록 **양쪽에** 들어갑니다.
- **깊이 우선 탐색.** 방문 표를 두고 한 정점에서 처음 보는 이웃으로 계속 내려가는 순회입니다. 모르면
  [`dfsTraversal`](../dfsTraversal/dfsTraversal-guide.md) 을 먼저 보세요.
- **연결 성분.** 서로 이어져 있는 정점끼리 묶은 덩어리입니다. 단절점의 정의가 「지우면 이 덩어리 개수가
  늘어나는가」라 이 개념이 필요해요. 개수를 세는 절차는
  [`connectedComponents`](../connectedComponents/connectedComponents-guide.md) 가 다룹니다.
- **탐색 트리와 부모 건너뛰기.** 무향 그래프를 순회하면 정점마다 자기를 처음 발견하게 한 이웃(부모)이 하나
  있고, 이웃을 볼 때 방금 지나온 부모는 건너뛰어야 합니다.
  [`undirectedCycleDetection`](../undirectedCycleDetection/undirectedCycleDetection-guide.md) 이 같은 두 개념을
  씁니다.
- **스택과 재귀 호출.** 마지막에 넣은 것을 먼저 꺼내는 목록이 스택이고, 함수가 자기를 다시 부르면 부르는 쪽의
  자리가 호출 스택에 쌓입니다. 이 글은 그 호출 스택을 배열로 직접 드는데, 왜 그래야 하는지는 값으로 봅니다.
  자료구조 자체가 궁금하면 [스택 가이드](../../../data-structures/linear/stack/stack-guide.mdx) 를 보세요.

이름이 비슷한 과제를 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 그래프 | 이 글에서 |
| --- | --- | --- |
| 지우면 연결 성분이 늘어나는 정점을 전부 찾는다 | 무향 | 다룬다 |
| 지우면 연결 성분이 늘어나는 간선을 전부 찾는다 | 무향 | 다루지 않는다 — [`bridgesInGraph`](../bridgesInGraph/bridgesInGraph-guide.md) |
| 서로 오갈 수 있는 정점 묶음을 찾는다 | 방향 | 다루지 않는다 — [`stronglyConnectedComponents`](../stronglyConnectedComponents/stronglyConnectedComponents-guide.md) |
| 이어져 있는 정점 묶음을 찾는다 | 무향 | 다루지 않는다 — [`connectedComponents`](../connectedComponents/connectedComponents-guide.md) |

강한 연결 요소를 찾는 절차도 발견 순서와 low 값을 적지만, 방향 그래프라 판정도 쓰임도 다릅니다. 이 글의 low
값은 무향 그래프의 깊이 우선 탐색 트리 위에서만 정의합니다.

### 아이디어를 떠올리는 과정 — 정점마다 지워 보기에서 low 값으로 판정하기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아서
단절점의 목록을 돌려줍니다.

```ts
function articulationPoints(n: number, edges: [number, number][]): number[];
```

- 입력: 정점 수 `n` 과 원소가 `[u, v]` 인 무향 간선 목록 `edges`. 정점 번호는 `0` 부터 `n−1` 입니다. 두 끝이
  같은 간선 `[v, v]` 가 들어올 수 있고, 같은 두 정점 사이에 간선이 여럿 있을 수 있으며, 그래프가 여러 덩어리로
  나뉘어 있을 수 있어요.
- 출력: 단절점 번호를 **오름차순으로** 담은 배열. 하나도 없으면 빈 배열입니다. 덩어리가 여럿이면 덩어리마다
  따로 판정해 모읍니다.
- 규모: `1 ≤ V ≤ 10^5`, `0 ≤ E ≤ 10^5`. 비용은 흔한 채점 환경의 예산인 시간 1 초, 메모리 256 MB 에 대어
  잽니다. 이 규모로 잡은 까닭은 뒤에서 셀 두 방법이 이 크기에서 1 초 예산의 안과 밖으로 갈리기 때문이에요.

이 글에서 쓰는 기호는 아홉 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점의 개수. 코드의 `n` 입니다 | `1 ≤ V ≤ 10^5` |
| `E` | 간선 목록의 길이. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 10^5` |
| `L` | 간선 목록 가운데 두 끝이 같은 간선의 개수 | `0 ≤ L ≤ E` |
| `u` · `v` · `w` | 정점 번호. 순회 중에는 `v` 가 지금 보고 있는 정점, `w` 가 그 이웃입니다 | `0` 부터 `V−1` |
| `c` | `v` 의 나무 자식 — 깊이 우선 탐색 트리에서 `v` 바로 아래 정점 | `0` 부터 `V−1` |
| `disc[v]` | `v` 에 처음 들어간 차례(발견 순서). 코드의 `disc` 배열입니다 | 아직 안 봤으면 `-1`, 보면 `0` 부터 `V−1` |
| `low[v]` | `v` 의 low 값. 코드의 `low` 배열이고, 정의는 「아이디어 상세」가 값으로 풉니다 | `disc[v]` 이하 |
| `A` | 단절점의 집합. 답은 이것을 오름차순으로 늘어놓은 것입니다 | 원소가 `V − 2` 개 이하 |
| `deg(v)` | `v` 의 이웃 목록 길이. 두 끝이 같은 간선은 목록에 넣지 않습니다 | 모두 더하면 `2(E − L)` |

이제 아이디어를 찾아 나섭니다. 출발점은 정의를 그대로 옮기는 방법이에요. 「지우면 덩어리 개수가 늘어나는가」를
묻고 있으니, 정점 하나를 지우고 덩어리를 다시 세는 일을 정점 수만큼 되풀이합니다.

```ts
const base = components(-1);                 // 아무것도 안 지운 덩어리 수
for (let v = 0; v < n; v++) {
  if (components(v) > base) cut.push(v);     // v 를 빼고 다시 센다 — 탐색 한 번
}
```

이 방법이 얼마나 오래 걸리는지는 **탐색 횟수와 이웃 자리 읽기**로 셉니다. 이웃 자리는 이웃 목록의 칸 하나이고,
탐색 한 번은 남은 정점의 이웃 자리를 한 번씩 읽어요. 이 글은 끝까지 이 두 수로 비용을 셉니다. 사슬
`0−1− … −(V−1)` 로 규모를 키우며 세었습니다.

<!--proof:naiveScale-->

| 정점 V | 간선 E | 탐색 횟수 | 지워 보기의 이웃 자리 읽기 | 깊이 우선 탐색 한 번의 이웃 자리 읽기 | 몇 배 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 3 | 5 | 24 | 6 | 4 |
| 8 | 7 | 9 | 112 | 14 | 8 |
| 16 | 15 | 17 | 480 | 30 | 16 |
| 32 | 31 | 33 | 1,984 | 62 | 32 |
| 64 | 63 | 65 | 8,064 | 126 | 64 |

다섯 줄 중 5 줄에서 「몇 배」가 정점 수 V 와 같습니다. 규모의 상한 V = E = 100,000 에서는 탐색이 100,001 번이고, 탐색 한 번이 이웃 자리를 많아야 2E = 200,000 개 읽으니 읽기가 많아야 20,000,200,000 번입니다. 초당 1 억 번 기준 200 초입니다.

<!--/proof-->

「몇 배」 열이 정점 수를 그대로 따라갑니다. 정점을 하나 더 넣을 때마다 탐색이 한 번 더 붙고, 그 탐색이 그래프
전체를 다시 읽기 때문이에요. 느린 까닭은 **탐색 한 번이 알아낸 것을 정점 하나의 판정에만 쓰고 버리는** 데
있습니다.

| 방법 | 탐색 한 번이 알아내는 것 | 그것을 쓰는 곳 |
| --- | --- | --- |
| 지금(정점마다 지워 보기) | 정점 하나를 뺀 그래프의 덩어리 수 | 그 정점 하나의 판정 |
| 목표 | 같은 그래프의 모양 | 정점 전부의 판정 |

그러면 탐색을 한 번만 하고 거기서 모든 정점의 답을 얻을 수는 없을까요? 같은 전개 입력을 두 방식으로 처리해
계수를 나란히 놓으면 목표가 어디쯤인지 보입니다. 둘째 줄은 이 글이 만들 절차예요.

<!--proof:twoWays-->

| 방법 | 탐색 횟수 | 이웃 자리 읽기 | 답 |
| --- | ---: | ---: | --- |
| 정점마다 지워 보기 | 6 | 50 | [0, 3] |
| 깊이 우선 탐색 한 번 | 1 | 10 | [0, 3] |

두 방법의 답이 같고, 이웃 자리 읽기는 50 번과 10 번입니다. 이웃 목록의 자리는 모두 10 개입니다.

<!--/proof-->

한 번의 탐색이 남기는 것부터 봅시다. 깊이 우선 탐색이 지나간 나무 간선만 남기면 정점 전부를 덮는 나무가
하나 나오고, 나머지 간선은 되돌아가는 간선이 됩니다.

<!--proof:treeSplit-->

| 정점 | disc | 부모 | 나무 자식 | 서브트리 |
| ---: | ---: | --- | --- | --- |
| 0 | 0 | 없음 (뿌리) | 1 · 3 | {0, 1, 2, 3, 4} |
| 1 | 1 | 0 | 2 | {1, 2} |
| 2 | 2 | 1 | 없음 | {2} |
| 3 | 3 | 0 | 4 | {3, 4} |
| 4 | 4 | 3 | 없음 | {4} |

나무 간선 4 개와 되돌아가는 간선 1 개가 간선 5 개를 나눠 가집니다. 되돌아가는 간선은 2−0 입니다.

<!--/proof-->

이 나무에서 정점 `v` 를 지운다는 것은 트리에서 `v` 를 떼어 낸다는 뜻입니다. 떼어 내면 `v` 의 나무 자식마다 그
서브트리가 조각 하나로 남아요. 그 조각이 나머지와 다시 이어지려면 서브트리 안의 정점에서 `v` 가 아닌 바깥
정점으로 가는 간선이 있어야 합니다. 정점마다 세어 보았습니다.

<!--proof:observeSplit-->

| 지운 정점 v | v 의 나무 자식의 서브트리 | 그 서브트리에서 v 위로 가는 간선 | 서브트리로 센 덩어리 수 | 지운 뒤 실제 덩어리 수 |
| ---: | --- | --- | ---: | ---: |
| 0 | {1, 2} · {3, 4} | 뿌리라 위가 없다 | 2 | 2 |
| 1 | {2} | 2−0 | 1 | 1 |
| 2 | 없음 | - | 1 | 1 |
| 3 | {4} | 없음 | 2 | 2 |
| 4 | 없음 | - | 1 | 1 |

다섯 줄 중 두 수가 일치한 줄은 5 줄입니다.

<!--/proof-->

다섯 정점 모두 서브트리로 센 덩어리 수가 실제와 맞습니다. 뿌리 0 은 위가 없으니 두 서브트리가 뿌리를 거쳐야만
이어져 두 덩어리가 되고, 정점 1 의 자식 서브트리 `{2}` 는 간선 `2−0` 으로 1 의 위에 붙어 있어요. 그러니
판정할 것은 하나입니다. **자식의 서브트리에서 부모 위로 가는 간선이 있는가.**

가장 단순한 후보부터 시험합니다. 「자식의 서브트리에서 나가는 되돌아가는 간선이 하나라도 있으면 부모를 지워도
붙어 있다」입니다. 되돌아가는 간선이 둘인 그래프 — 삼각형 둘을 간선 하나가 이은 그래프 — 에 넣어 봅시다.

<!--proof:firstCandidate-->

| 나무 간선 | 자식의 서브트리 | 서브트리에서 나가는 되돌아가는 간선 | 후보가 본 서브트리 | 부모를 지운 실제 결과 |
| --- | --- | --- | --- | --- |
| 1−2 | {2, 3, 4, 5} | 2−0 · 5−3 | 붙어 있다 | 붙어 있다 |
| 2−3 | {3, 4, 5} | 5−3 | 붙어 있다 | 떨어진다 |
| 3−4 | {4, 5} | 5−3 | 붙어 있다 | 떨어진다 |
| 4−5 | {5} | 5−3 | 붙어 있다 | 붙어 있다 |

나무 간선 4 개 가운데 후보가 실제와 어긋난 것은 2 개입니다. 후보가 낸 답은 [] 이고, 정본이 낸 답은 [2, 3] 입니다.

<!--/proof-->

**후보가 거짓입니다.** 나무 간선 `2−3` 과 `3−4` 에서 판정이 뒤집혀요. 두 서브트리에 되돌아가는 간선 `5−3`
이 있기는 한데, 그 간선이 이르는 곳이 정점 3 이라 정점 2 위로도 정점 3 위로도 못 갑니다. 간선이 **있는가**가
아니라 **어디까지 가는가**를 수로 적어야 해요. 같은 나무 간선마다 되돌아가는 간선이 이르는 가장 이른 발견
순서를 적고 부모의 발견 순서와 비교했습니다.

<!--proof:candidateFix-->

| 나무 간선 | 되돌아가는 간선이 이르는 가장 이른 disc | 부모의 disc | 부모보다 위로 감 | 부모를 지운 실제 결과 |
| --- | ---: | ---: | --- | --- |
| 1−2 | 0 | 1 | 예 | 붙어 있다 |
| 2−3 | 3 | 2 | 아니오 | 떨어진다 |
| 3−4 | 3 | 3 | 아니오 | 떨어진다 |
| 4−5 | 3 | 4 | 예 | 붙어 있다 |

네 줄 모두에서 「위로 감」이 예인 줄은 붙어 있고, 아니오인 줄은 떨어집니다 — 일치한 줄이 4 줄입니다.

<!--/proof-->

네 줄 모두 맞습니다. 「가장 이른 발견 순서」가 부모의 발견 순서보다 작으면 붙어 있고, 같거나 크면 떨어져요.
그 「가장 이른 발견 순서」를 정점마다 적은 것이 low 값이고, 이 방법을 이 글에서는 「low 값으로 판정하기」라고
부릅니다. 지금까지 해 본 방법 셋을 차례로 놓으면 이렇습니다. 앞 방법이 막힌 자리에서 다음 방법이 나왔고,
둘은 버리고 하나가 남았어요.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

아직 확인하지 않은 것이 남아 있습니다. 깊이 우선 탐색 트리가 정확히 어떻게 생겼는지, low 값을 한 번의 순회로
어떻게 채우는지, 뿌리는 왜 다른 규칙을 쓰는지예요. 다음 절에서 이 방법을 실현하는 순서대로 하나씩 확인합니다.

### 아이디어 상세 — low 값으로 판정하기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **깊이 우선 탐색을 한 번 하면서 정점마다 발견 순서와 low 값을
적고, 정점을 빼는 순간 그 low 값이 부모의 발견 순서 이상이면 부모를 단절점으로 적으며, 뿌리는 나무 자식이
둘 이상일 때만 단절점으로 적습니다.** 이 방법은 깊이 우선 탐색 트리와 low 값이라는 두 개념 위에서 동작하는데,
처음 보는 사람에게는 둘 다 낯설어요. 그래서 두 개념을 먼저 따로 설명하고, 그다음 실현하는 순서대로 다섯 단계를
설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 정점에 들어갈 때 | 1단계 발견 순서 매기기 | `disc` · `low` 를 적고 호출 스택에 부모와 함께 담는다 | — |
| 이웃 자리를 읽을 때 | 2단계 low 값 줄이기 | 이웃을 보고 내려가기 · 부모 건너뛰기 · low 줄이기 중 하나를 한다 | 1단계의 `disc` 와 부모 칸 |
| 정점을 뺄 때 | 3단계 부모에게 넘기기 | 뺀 정점의 `low` 를 부모에게 준다 | 2단계의 `low` |
| 정점을 뺄 때 | 4단계 부모 판정하기 | `low[자식] ≥ disc[부모]` 이면 부모를 적는다 | 3단계에서 확정된 `low` · 1단계의 `disc` |
| 탐색이 끝날 때 | 5단계 뿌리 판정하기 | 나무 자식이 둘 이상이면 뿌리를 적는다 | 2단계에서 센 뿌리의 나무 자식 수 |

#### 먼저 알아 둘 개념 — 깊이 우선 탐색 트리

깊이 우선 탐색 트리는 **탐색이 처음 보는 정점으로 내려갈 때 쓴 간선만 남긴 나무**입니다. 내려간 간선이 나무
간선이고, 나무 간선이 아닌 간선은 읽을 때 반대쪽 끝이 이미 들어간 정점이에요. 방향 그래프의 깊이 우선 탐색은
나머지 간선을 세 종류로 가르지만, 무향 그래프에서는 한 종류뿐입니다. 이 글은 그 한 종류를 되돌아가는 간선이라고
부릅니다([`undirectedCycleDetection`](../undirectedCycleDetection/undirectedCycleDetection-guide.md) 이 「여분
간선」이라 부른 것이 이것이에요).

| 간선 종류 | 두 끝 | 그림의 선 |
| --- | --- | --- |
| 나무 | 부모와 자식 — 탐색이 내려간 간선 | 굵은 실선 |
| 되돌아감 | 조상과 자손 — 부모와 자식은 아니다 | 대시 |

##### 입력 위의 깊이 우선 탐색 트리

전개 입력을 정점 0 부터 탐색하면서 간선 다섯을 갈랐습니다. 입력 그래프의 자리를 그대로 두고, 정점 안에 발견
순서를, 간선 옆에 종류를 적었어요.

<!--fig:build-dfs-edges-->
![입력 그래프 위의 간선 종류 — 정점 안의 수는 disc](./figs/build-dfs-edges.svg)

나무 간선 넷이 정점 다섯을 모두 잇고, 삼각형의 마지막 간선 `2−0` 만 되돌아가는 간선으로 남습니다. 같은 탐색을
나무 모양으로 옮기면 깊이가 세로 자리가 돼요.

<!--fig:build-dfs-tree-->
![같은 탐색을 나무 모양으로 — y 는 깊이](./figs/build-dfs-tree.svg)

##### 정점 하나를 읽는 법

정점 3 을 골라 읽어 보겠습니다. 발견 순서가 3 이니 네 번째로 들어간 정점이고, 나무 간선 `0−3` 으로 들어왔으니
부모는 0 이에요. 나무 자식은 4 하나이고, 서브트리는 `{3, 4}` 입니다. 다섯 정점을 같은 방법으로 읽으면
이렇습니다.

<!--proof:treeVertices-->

| 정점 | disc | 부모 | 깊이 | 나무 자식 | 서브트리 | 들어간 직후의 호출 스택 |
| ---: | ---: | --- | ---: | --- | --- | --- |
| 0 | 0 | 없음 (뿌리) | 0 | 1 · 3 | {0, 1, 2, 3, 4} | [0] |
| 1 | 1 | 0 | 1 | 2 | {1, 2} | [0, 1] |
| 2 | 2 | 1 | 2 | 없음 | {2} | [0, 1, 2] |
| 3 | 3 | 0 | 1 | 4 | {3, 4} | [0, 3] |
| 4 | 4 | 3 | 2 | 없음 | {4} | [0, 3, 4] |

「들어간 직후의 호출 스택」은 뿌리에서 그 정점까지 내려온 나무 경로입니다. 이 열과 서브트리 열은 서로를 뒤집어
읽은 것이에요 — 정점 4 의 호출 스택에 있는 0 · 3 은 모두 서브트리에 4 를 담고 있습니다.

##### 간선끼리의 관계

간선 하나의 두 끝을 보면, 먼저 발견한 끝의 서브트리에 다른 끝이 드는가로 조상과 자손인지를 알 수 있습니다.
다섯 간선을 모두 재면 이렇습니다.

<!--proof:treeEdges-->

| 간선 | 두 끝의 disc | 먼저 발견한 끝 | 다른 끝이 그 서브트리 안 | 종류 |
| --- | --- | --- | --- | --- |
| 0−1 | 0 · 1 | 0 | 예 | 나무 |
| 1−2 | 1 · 2 | 1 | 예 | 나무 |
| 2−0 | 2 · 0 | 0 | 예 | 되돌아감 |
| 0−3 | 0 · 3 | 0 | 예 | 나무 |
| 3−4 | 3 · 4 | 3 | 예 | 나무 |

간선 5 개 중 두 끝이 조상과 자손인 것은 5 개입니다. 나무 간선이 4 개, 되돌아가는 간선이 1 개입니다.

<!--/proof-->

다섯 간선 모두 두 끝이 조상과 자손입니다. 무향 그래프에서는 이것이 언제나 성립해요. 간선 `a−b` 에서 `a` 에
먼저 들어갔다고 합시다. `a` 의 이웃을 다 볼 때까지 `a` 는 호출 스택에 남아 있고, 그동안 `a` 의 이웃 목록에서
`b` 를 읽게 됩니다. 그때 `b` 가 아직 안 들어간 정점이면 `a` 가 `b` 로 내려가 `b` 가 `a` 의 자식이 되고, 이미
들어간 정점이면 `a` 가 호출 스택에 있는 동안 들어간 것이라 `a` 의 서브트리 안에 있어요. 어느 쪽이든 `b` 는
`a` 의 자손입니다.

##### 너비 우선 탐색 트리와의 차이

탐색 트리를 처음 보면 **어느 순회로 만든 나무든 같은 일을 한다**고 읽기 쉽습니다. 너비 우선 탐색도 정점 전부를
덮는 나무를 만드니까요. 같은 입력을 정점 0 부터 너비 우선으로 탐색해 나무를 그렸습니다.

<!--fig:build-bfs-tree-->
![같은 입력의 너비 우선 탐색 트리 — 나무 간선이 아닌 간선이 형제를 잇는다](./figs/build-bfs-tree.svg)

너비 우선 탐색 트리에서는 나무 간선이 아닌 간선 `1−2` 가 두 형제를 잇습니다. 두 나무의 나무 간선이 아닌 간선과,
같은 두 규칙을 각 나무에 적용한 답을 나란히 재었습니다.

<!--proof:bfsContrast-->

| 나무 | 나무 간선이 아닌 간선 | 두 끝이 조상과 자손 |
| --- | --- | --- |
| 깊이 우선 탐색 트리 | 2−0 | 예 |
| 너비 우선 탐색 트리 | 1−2 | 아니오 |

같은 두 규칙을 두 나무에 적용해 답을 내면 이렇습니다.

| 입력 | 깊이 우선 탐색 트리로 낸 답 | 너비 우선 탐색 트리로 낸 답 | 정점을 지워 본 답 |
| --- | --- | --- | --- |
| 전개 입력 | [0, 3] | [0, 3] | [0, 3] |
| 사이클 하나 | [] | [0, 1] | [] |
| 꼬리가 붙은 삼각형 | [1] | [1] | [1] |
| 삼각형 둘이 정점 하나를 함께 씀 | [1] | [0, 1] | [1] |
| 삼각형 둘을 간선 하나가 이음 | [2, 3] | [0, 2, 3] | [2, 3] |

다섯 입력 중 너비 우선 탐색 트리로 낸 답이 정점을 지워 본 답과 일치한 것은 2 개입니다.

<!--/proof-->

두 읽기가 사이클 하나에서 크게 갈립니다. 너비 우선 탐색 트리에서는 형제끼리 잇는 간선이 「위로 가는 간선」으로
세어지지 않아, 사이클 위의 정점이 단절점으로 적혀요. 판정 규칙이 맞으려면 나무 간선이 아닌 간선이 **조상과
자손만** 이어야 하고, 그것을 보장하는 것이 깊이 우선 탐색입니다.

| 나무 | 나무 간선이 아닌 간선의 두 끝 | 자식 서브트리가 부모를 지우고 붙어 있는 길 |
| --- | --- | --- |
| 깊이 우선 탐색 트리 | 조상과 자손 | 부모 위의 조상으로 가는 간선뿐이다 |
| 너비 우선 탐색 트리 | 형제 · 사촌도 된다 | 옆 서브트리로 가는 간선도 있어 서브트리만 보고는 알 수 없다 |

##### 이렇게 생긴 까닭

판정하려는 것은 「`v` 를 지우면 자식의 서브트리가 떨어지는가」입니다. 깊이 우선 탐색 트리에서는 서브트리 밖으로
나가는 간선이 전부 조상으로 가므로, 서브트리가 떨어지지 않을 길은 **`v` 보다 위의 조상으로 가는 되돌아가는
간선** 하나뿐이에요. 옆 서브트리를 볼 필요가 없으니 서브트리 하나마다 수 하나로 판정할 수 있습니다.

| 요구 | 깊이 우선 탐색 트리가 주는 것 |
| --- | --- |
| 정점을 지우면 무엇이 떨어지는지 안다 | 자식마다 서브트리가 조각 하나다 |
| 조각이 다시 붙는 길을 안다 | 나무 간선이 아닌 간선이 조상으로만 간다 |
| 한 번의 순회로 모든 정점을 판정한다 | 정점을 빼는 순간 그 서브트리를 다 본 뒤다 |

#### 먼저 알아 둘 개념 — low 값

low 값은 **정점 `v` 의 서브트리에서 되돌아가는 간선 하나로 이를 수 있는 정점 중 가장 이른 발견 순서**입니다.
그런 간선이 없으면 자기 발견 순서가 그대로 남아요. 코드에서는 `low[v]` 한 칸에 적습니다. 서브트리의 정점들이
**`v` 를 거치지 않고** 얼마나 위까지 올라갈 수 있는지를 수 하나로 적은 것이에요.

##### 트리 위의 low 값

깊이 우선 탐색 트리의 정점마다 `disc / low` 를 적고, low 값을 줄인 간선을 강조했습니다. 두 수가 다른 정점은
강조 테로 그렸어요.

<!--fig:build-low-tree-->
![low 값 — 되돌아가는 간선이 서브트리의 low 를 줄인다](./figs/build-low-tree.svg)

강조한 간선 하나가 low 값을 바꾼 전부입니다. 간선 `2−0` 이 정점 2 의 값을 0 으로 내리고, 정점 2 가 정점 1 의
서브트리에 드니 정점 1 의 값도 0 이 돼요. 꼬리의 3 과 4 는 서브트리에서 나가는 되돌아가는 간선이 없어 두 수가
같습니다.

##### 정점 하나의 low 값을 읽는 법

정점 1 을 골라 정의대로 읽어 보겠습니다. 자기 발견 순서에서 시작해, 서브트리에서 나가는 되돌아가는 간선이 이르는
정점의 발견 순서를 모두 모으고 가장 작은 것을 고릅니다.

<!--proof:lowReadOne-->

| 항 | 보는 것 | 값 |
| --- | --- | --- |
| 자기 발견 순서 | disc[1] | 1 |
| 서브트리 | 정점 1 의 서브트리 | {1, 2} |
| 되돌아가는 간선 | 서브트리에서 나가는 되돌아가는 간선 | 2−0 (disc 0) |
| 가장 작은 값 | 위 발견 순서 중 가장 작은 것 | 0 |

정의에서 읽은 값은 0 이고, 절차를 실행해 얻은 low[1] 도 0 입니다.

<!--/proof-->

정점 1 의 low 값이 0 이라는 것은 「1 의 서브트리 어딘가에서 1 을 거치지 않고 발견 순서 0 인 정점으로 갈 수
있다」는 뜻입니다. 되돌아가는 간선은 1 에서 직접 나가지 않고 자식 2 에서 나갔어요. 그래서 low 값은 정점 하나가
아니라 **서브트리 전체**를 보고 정해집니다.

##### 부모와 자식의 low 값

서브트리 전체를 본다는 것은 부모의 값이 자식의 값을 담는다는 뜻입니다. 다섯 정점의 두 수와 부모의 값을 나란히
놓았어요.

<!--proof:lowTable-->

| 정점 | disc | low | 부모 | 부모의 low | low ≤ disc | 부모의 low ≤ 자기 low |
| ---: | ---: | ---: | --- | ---: | --- | --- |
| 0 | 0 | 0 | 없음 | - | 예 | - |
| 1 | 1 | 0 | 0 | 0 | 예 | 예 |
| 2 | 2 | 0 | 1 | 0 | 예 | 예 |
| 3 | 3 | 3 | 0 | 0 | 예 | 예 |
| 4 | 4 | 4 | 3 | 3 | 예 | 예 |

low ≤ disc 는 다섯 줄 중 5 줄에서, 부모의 low ≤ 자기 low 는 부모가 있는 4 줄 중 4 줄에서 성립합니다.

<!--/proof-->

두 관계가 모든 줄에서 성립합니다. `low ≤ disc` 는 자기 발견 순서에서 시작해 줄기만 하기 때문이에요. 부모의 값이
자식의 값 이하인 것은 자식의 서브트리가 부모의 서브트리 안에 들어 있어서, 자식이 이르는 곳에 부모도 이르기
때문입니다.

| 관계 | 까닭 |
| --- | --- |
| `low[v] ≤ disc[v]` | 자기 발견 순서에서 시작해 줄어들기만 한다 |
| `low[부모] ≤ low[자식]` | 자식의 서브트리가 부모의 서브트리에 든다 |
| `low[c] ≥ disc[v]` 이면 `c` 의 서브트리가 `v` 위로 못 간다 | `v` 위의 조상은 전부 발견 순서가 `disc[v]` 보다 작다 |

##### 갈 수 있는 가장 이른 정점과의 차이

low 값을 처음 보면 **갈 수 있는 정점 중 가장 이른 발견 순서**로 읽기 쉽습니다. 경로를 따라 어디든 가서 가장
이른 정점을 적는 읽기예요. 두 값을 같은 입력에서 나란히 재고, 각 값을 두 규칙에 넣어 답을 냈습니다.

<!--proof:lowVsReach-->

| 정점 | disc | low | 갈 수 있는 정점 중 가장 이른 disc |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 |
| 1 | 1 | 0 | 0 |
| 2 | 2 | 0 | 0 |
| 3 | 3 | 3 | 0 |
| 4 | 4 | 4 | 0 |

두 규칙에 low 를 넣으면 답이 [0, 3], 도달로 읽은 값을 넣으면 [0] 입니다. 정본이 낸 답은 [0, 3] 입니다.

<!--/proof-->

도달로 읽으면 다섯 정점이 모두 0 이 됩니다. 연결된 그래프에서는 어느 정점에서든 뿌리까지 갈 수 있으니까요.
그 경로는 `v` 를 지나도 되는 경로라, `v` 를 지웠을 때 남는 길이 있는지를 말해 주지 못합니다. low 값은 서브트리
안에서 되돌아가는 간선 **하나**만 쓰게 해서 `v` 를 거치지 않는 길만 셉니다.

##### 판정 규칙 둘이 나오는 까닭

뿌리가 아닌 `v` 와 그 나무 자식 `c` 를 봅시다. `v` 위의 조상은 모두 `v` 보다 먼저 발견했으니 발견 순서가
`disc[v]` 보다 작아요. 그래서 `low[c] < disc[v]` 이면 `c` 의 서브트리에서 `v` 위로 가는 간선이 있어 `v` 를
지워도 붙어 있고, `low[c] ≥ disc[v]` 이면 그런 간선이 없어 떨어집니다. 등호가 떨어지는 쪽에 드는 까닭은
`low[c] = disc[v]` 가 「가장 멀리 가도 `v` 자신」이라는 뜻이고, `v` 를 지우면 그 간선도 함께 사라지기
때문이에요.

뿌리는 위가 없으니 이 비교가 늘 참이 됩니다. 뿌리에서는 자식 서브트리끼리 이어지는가를 따로 봐야 하는데,
두 서브트리 사이의 간선은 조상과 자손을 잇지 않으니 있을 수 없어요. 그래서 뿌리는 나무 자식이 둘 이상이면
단절점입니다. 두 규칙을 모양이 다른 아홉 그래프에 적용해, 정점을 하나씩 지워 본 답과 나란히 쟀습니다.

<!--proof:criterionCheck-->

| 입력 | V | E | 두 규칙으로 낸 답 | 정점을 지워 본 답 |
| --- | ---: | ---: | --- | --- |
| 전개 입력 | 5 | 5 | [0, 3] | [0, 3] |
| 사이클 하나 | 4 | 4 | [] | [] |
| 꼬리가 붙은 삼각형 | 4 | 4 | [1] | [1] |
| 삼각형 둘이 정점 하나를 함께 씀 | 5 | 6 | [1] | [1] |
| 삼각형 둘을 간선 하나가 이음 | 6 | 7 | [2, 3] | [2, 3] |
| 떨어진 두 성분 | 7 | 4 | [1, 4] | [1, 4] |
| 사슬 (V = 8) | 8 | 7 | [1, 2, 3, 4, 5, 6] | [1, 2, 3, 4, 5, 6] |
| 별 (V = 8) | 8 | 7 | [0] | [0] |
| 완전 그래프 (V = 8) | 8 | 28 | [] | [] |

아홉 줄 중 두 답이 일치한 줄은 9 줄입니다.

<!--/proof-->

아홉 줄 모두 두 답이 같습니다. 그래서 정점을 뺄 때 두 수만 비교하면, 그래프를 다시 순회하지 않고도 부모가
단절점인지 그 자리에서 알 수 있어요. 이 비교를 이 글에서는 **부모 판정**이라고 부르고, 뿌리의 판정을 **뿌리
판정**이라고 부릅니다.

#### 1단계 — 정점에 들어가며 발견 순서 매기기

정점에 처음 들어갈 때마다 할 일은 둘입니다. 발견 순서를 매겨 `disc` 와 `low` 에 같은 수를 적고, 정점을 호출
스택에 담아요. 호출 스택은 배열 셋입니다. `callV` 가 정점, `callI` 가 그 정점의 이웃 목록에서 다음에 읽을
자리, `callP` 가 부모예요. 뿌리의 부모 칸에는 `-1` 을 넣습니다. 발견 순서는 번호표 `timer` 가 0 부터 하나씩
올라가며 매겨요. 전개 입력에서 들어간 다섯 걸음은 이렇습니다.

<!--proof:stageEnter-->

| 걸음 | 들어간 정점 | 들어온 자리 | disc = low | 들어간 뒤 callV | 들어간 뒤 callP |
| --- | --- | --- | ---: | --- | --- |
| T2 | 0 | 바깥 반복 | 0 | [0] | [-1] |
| T3 | 1 | 간선 0−1 | 1 | [0, 1] | [-1, 0] |
| T5 | 2 | 간선 1−2 | 2 | [0, 1, 2] | [-1, 0, 1] |
| T11 | 3 | 간선 0−3 | 3 | [0, 3] | [-1, 0] |
| T13 | 4 | 간선 3−4 | 4 | [0, 3, 4] | [-1, 0, 3] |

`disc` 와 `low` 에 같은 수를 적는 까닭은 low 값의 정의가 자기 발견 순서에서 시작하기 때문이에요. 아직 아무
간선도 안 읽었으니 이를 곳이 자기 자신뿐입니다. 크기도 여기서 정해집니다. 정점마다 한 번씩만 들어가므로
발견 순서는 `0` 부터 `V−1` 까지이고, 호출 스택은 많아야 `V` 칸이에요.

| 칸 | 크기 |
| --- | --- |
| `disc` · `low` · `cut` | 정점마다 한 칸씩 `V` 칸 |
| 발견 순서 | `0` 부터 `V−1` |
| 호출 스택 `callV` · `callI` · `callP` | 많아야 `V` 칸 — 뿌리에서 가장 깊은 정점까지의 경로 |

#### 2단계 — 이웃 자리마다 low 값 줄이기

지금 정점 `v` 의 이웃 목록에서 이웃 `w` 를 하나 읽을 때마다, `w` 의 상태에 따라 셋 중 하나를 합니다. 처음 보는
정점이면 1단계대로 내려가요. 부모 칸에 적힌 정점이면 건너뜁니다. 그 밖의 이미 들어갔던 정점이면 `low[v]` 를
`disc[w]` 와 비교해 작은 쪽을 남겨요.

| 이웃 `w` 의 상태 | 판정 | 하는 일 |
| --- | --- | --- |
| 처음 보는 정점 | `disc[w] = -1` | 내려간다(1단계) |
| 부모 | `w` 가 `callP` 맨 위와 같다 | 건너뛴다 |
| 이미 들어갔던 정점 | 둘 다 아니다 | `low[v] = min(low[v], disc[w])` |

전개 입력의 이웃 자리 열 개가 이 셋으로 갈리는 모습입니다. 가장 쉬운 경우는 처음 보는 정점으로 내려가는
넷이고, 가장 불안한 경우는 이미 들어갔던 정점을 만나는 둘이에요.

<!--proof:stageNeighbors-->

| 걸음 | 이웃 자리 | 이웃의 disc | 이웃의 상태 | 갈래 | 지금 정점의 low |
| --- | --- | --- | --- | --- | --- |
| T3 | 0−1 | - | 처음 봄 | 내려간다 | 0 그대로 |
| T4 | 1−0 | 0 | 부모 | 건너뛴다 | 1 그대로 |
| T5 | 1−2 | - | 처음 봄 | 내려간다 | 1 그대로 |
| T6 | 2−1 | 1 | 부모 | 건너뛴다 | 2 그대로 |
| T7 | 2−0 | 0 | 이미 들어갔던 정점 | low 를 줄인다 | 2 → 0 |
| T10 | 0−2 | 2 | 이미 들어갔던 정점 | low 를 줄인다 | 0 그대로 |
| T11 | 0−3 | - | 처음 봄 | 내려간다 | 0 그대로 |
| T12 | 3−0 | 0 | 부모 | 건너뛴다 | 3 그대로 |
| T13 | 3−4 | - | 처음 봄 | 내려간다 | 3 그대로 |
| T14 | 4−3 | 3 | 부모 | 건너뛴다 | 4 그대로 |

이웃 자리 10 개가 10 걸음에서 한 번씩 읽혔습니다. 내려간 자리가 4 개, 부모를 건너뛴 자리가 4 개, low 를 줄이는 갈래로 간 자리가 2 개이고 그중 값이 실제로 줄어든 것은 1 개입니다.

<!--/proof-->

불안한 경우 둘을 따로 봅시다. T7 은 정점 2 가 조상 0 을 읽은 것이라 `low[2]` 가 0 으로 내려가요. T10 은 거꾸로
정점 0 이 이미 들어갔다 나온 자손 2 를 읽은 것입니다. 간선 하나가 두 끝의 이웃 목록에 다 있으니 되돌아가는
간선은 두 번 읽히고, 조상 쪽에서 읽을 때는 `disc[2]` 가 `low[0]` 보다 커서 값이 그대로예요. 부모를 건너뛰는
넷은 방금 내려온 나무 간선을 반대쪽 끝에서 다시 본 것입니다. 이웃 자리를 빠짐없이 한 번씩 읽는다는 근거는 코드의
종료 조건에 있어요. 정점마다 `callI` 가 다음에 읽을 자리를 하나씩 올리고, 그 자리가 목록 길이와 같아져야 정점을
빼므로 `deg(v)` 개 자리를 정확히 한 번씩 읽습니다.

| 이웃 자리 | 이웃 | 읽을 때 이웃의 상태 | low 값 |
| --- | --- | --- | --- |
| 정점 2 에서 0 (T7) | 조상 | 이미 들어갔던 정점 | `low[2]` 가 내려간다 |
| 정점 0 에서 2 (T10) | 이미 끝난 자손 | 이미 들어갔던 정점 | `low[0]` 이 그대로다 |
| 정점 1 에서 0 (T4) | 부모 | 부모 | 건너뛴다 |

#### 3단계 — 뺀 정점의 low 값을 부모에게 넘기기

2단계는 정점이 **자기 이웃 자리**로 되돌아가는 것만 적습니다. 정점 1 은 자기 간선으로 되돌아가지 않지만, 자식
2 가 0 으로 되돌아가니 1 의 서브트리도 0 까지 올라가요. 그래서 정점의 이웃을 다 보고 호출 스택에서 뺄 때, 그
정점의 low 값을 부모에게 넘겨 부모의 값과 비교해 작은 쪽을 남깁니다. 뺀 정점은 이웃을 다 봤고 그 자식들도
먼저 빠졌으니, 넘기는 값은 서브트리 전체를 본 확정된 값이에요.

<!--proof:stagePass-->

| 걸음 | 뺀 정점 | 그 정점의 low | 부모 | 부모의 low |
| --- | --- | ---: | --- | --- |
| T8 | 2 | 0 | 1 | 1 → 0 |
| T9 | 1 | 0 | 0 | 0 → 0 |
| T15 | 4 | 4 | 3 | 3 → 3 |
| T16 | 3 | 3 | 0 | 0 → 0 |
| T17 | 0 | 0 | 없음 | - |

값이 실제로 바뀐 것은 T8 한 번입니다. 정점 2 가 빠지며 넘긴 0 이 정점 1 의 값을 1 에서 0 으로 내렸어요. T9 ·
T16 은 뿌리 0 에게 값을 넘겼지만 0 의 값이 이미 0 이라 그대로입니다. T15 는 정점 4 가 넘긴 4 가 부모 3 의 3
보다 커서 아무것도 바꾸지 않아요.

#### 4단계 — 뿌리가 아닌 부모 판정하기

값을 넘긴 바로 그 자리에서 부모를 판정합니다. 부모가 뿌리가 아니고 `low[자식] ≥ disc[부모]` 이면 부모를
단절점으로 적어요. 부모의 다른 자식이 아직 남아 있어도 이 자식 하나의 서브트리가 떨어진다는 것은 이미 정해졌으니
기다릴 필요가 없습니다. 전개 입력에서 부모가 있는 정점을 뺀 네 걸음을 모두 적었습니다.

<!--proof:stageJudge-->

| 걸음 | 뺀 자식 | 부모 | low[자식] | disc[부모] | 부모가 뿌리 | low[자식] ≥ disc[부모] | 적은 것 |
| --- | --- | --- | ---: | ---: | --- | --- | --- |
| T8 | 2 | 1 | 0 | 1 | 아니오 | 아니오 | - |
| T9 | 1 | 0 | 0 | 0 | 예 | 보지 않는다 | - |
| T15 | 4 | 3 | 4 | 3 | 아니오 | 예 | cut[3] |
| T16 | 3 | 0 | 3 | 0 | 예 | 보지 않는다 | - |

부모가 있는 정점을 뺀 4 걸음 가운데 부모를 단절점으로 적은 것은 1 걸음(정점 3)이고, 부모가 뿌리라 판정하지 않은 것이 2 걸음입니다.

<!--/proof-->

판정이 참인 것은 T15 한 번입니다. 판정 앞뒤의 모습을 무대로 보면 이렇습니다. 정점 안의 두 수가 `disc / low` 이고,
무대 아래 두 줄이 호출 스택과 단절점 목록이에요.

<!--fig:build-judge-->
![T15 · T16 · T18 — 부모 판정 둘과 뿌리 판정](./figs/build-judge.svg)

T15 에서 정점 4 를 빼며 `low[4] = 4` 를 부모 3 의 `disc[3] = 3` 과 비교해 3 을 적습니다. T16 은 같은 줄을
실행하지만 부모가 뿌리 0 이라 비교하지 않아요. 뿌리의 판정은 T18 이 따로 합니다.

#### 5단계 — 뿌리는 나무 자식 수로 판정하기

뿌리에서는 부모 판정을 쓰지 않습니다. 뿌리의 발견 순서가 그 덩어리에서 가장 작아서 `low[자식] ≥ disc[뿌리]` 가
어느 자식에서나 참이기 때문이에요. 대신 2단계에서 뿌리가 처음 보는 이웃으로 내려갈 때마다 `rootKids` 를 하나씩
세고, 탐색이 끝나면 그 수가 둘 이상인지 봅니다. 모양이 다른 다섯 입력의 뿌리를 모두 재었습니다.

<!--proof:stageRoot-->

| 입력 | 뿌리 | 나무 자식 수 | 뿌리 규칙의 판정 | 지워 본 판정 |
| --- | ---: | ---: | --- | --- |
| 전개 입력 | 0 | 2 | 단절점 | 단절점 |
| 사이클 하나 | 0 | 1 | 아니다 | 아니다 |
| 별 (V = 5) | 0 | 4 | 단절점 | 단절점 |
| 사슬 (V = 5) | 0 | 1 | 아니다 | 아니다 |
| 떨어진 두 성분 | 0 | 1 | 아니다 | 아니다 |
| 떨어진 두 성분 | 3 | 1 | 아니다 | 아니다 |
| 떨어진 두 성분 | 6 | 0 | 아니다 | 아니다 |

뿌리 7 곳 중 두 판정이 일치한 곳은 7 곳입니다.

<!--/proof-->

사이클 하나와 사슬의 뿌리는 나무 자식이 하나라 단절점이 아닙니다. 사슬 `0−1−2−3−4` 의 끝 정점 0 은 지워도
나머지가 한 줄로 남으니 맞는 판정이에요. 떨어진 두 성분에서는 바깥 반복이 탐색을 세 번 시작하고, 뿌리마다 따로
판정합니다.

#### 이 방법이 기대는 전제

low 값으로 판정하기는 아래 세 전제에 기대고 있어서, 하나라도 빠지면 답이 틀립니다. 셋 다 코드 한 줄이 지키고,
그 줄을 바꾸면 무엇이 나오는지는 「수행으로 알아보는 알고리즘」의 짚고 가기들과 「불변식」의 깨뜨려 보기가 실행
결과로 보여 줍니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 나무 간선이 아닌 간선은 조상과 자손을 잇는다 | 서브트리 하나마다 수 하나로 판정한다 | 너비 우선 탐색 트리처럼 사이클 위 정점을 단절점으로 적는다 |
| 자식은 부모보다 먼저 빠지고, 빠질 때 값을 넘긴다 | 3단계 · 4단계 | 손자의 되돌아가는 간선이 부모 판정에 안 들어가 거짓 단절점이 생긴다 |
| 뿌리는 부모 판정에서 뺀다 | 4단계 · 5단계 | 자식이 하나뿐인 뿌리까지 단절점으로 적힌다 |

#### 호출 스택을 배열로 드는 까닭

깊이 우선 탐색은 재귀로 적으면 짧습니다. 자식으로 내려가는 자리가 재귀 호출이 되고, 빠지는 자리가 함수의
끝이 돼요. 대신 내려간 깊이만큼 호출 자리가 쌓입니다. 사슬에서는 그 깊이가 정점 수와 같아서, 정점 수를 바꿔 가며
두 판을 실행해 보았습니다.

<!--proof:designRecursion-->

| 사슬의 정점 수 | 배열로 든 판의 단절점 | 재귀로 적은 판의 단절점 |
| ---: | --- | --- |
| 100 | 98 개 | 98 개 |
| 1,000 | 998 개 | 998 개 |
| 10,000 | 9,998 개 | 9,998 개 |
| 100,000 | 99,998 개 | 호출 스택이 한계를 넘어 실행이 멈춘다 |

사슬에서는 호출 깊이가 정점 수와 같습니다. 정확히 몇 개에서 멈추는지는 런타임이 정하는 값이고, 규모의 상한 V = 100,000 은 이 실행에서 멈춘 쪽에 있습니다.

<!--/proof-->

정점 1 만 개까지는 두 판의 답이 같고, 10 만 개에서는 재귀 판이 답을 못 냅니다. 이 글이 잡은 규모의 상한이
`V = 10^5` 이니 재귀로는 규모 안의 입력을 다 처리하지 못해요. 그래서 호출 스택을 배열 셋으로 직접 듭니다.

| 판 | 호출 자리가 놓이는 곳 | 사슬 `V = 10^5` 에서 |
| --- | --- | --- |
| 재귀 | 자바스크립트 호출 스택 | 한계를 넘어 멈춘다 |
| 배열 셋 | 힙에 놓인 배열의 항목 | 끝까지 실행된다 |

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 여섯 걸음이 됩니다. 정점마다 지워 보면 `(V + 1) · 2E` 번까지 가던 이웃
자리 읽기가 `2(E − L)` 번으로 줄어요.

1. 간선 목록을 두 끝의 이웃 목록에 넣고 `disc` · `low` 를 `-1` 로, `cut` 을 거짓으로 둔다
2. 바깥 반복이 아직 안 들어간 정점을 찾으면 들어가서 두 수를 적고 호출 스택에 담는다(1단계)
3. 호출 스택 맨 위 정점의 다음 이웃 자리를 읽고 내려가거나 · 부모를 건너뛰거나 · `low` 를 줄인다(2단계)
4. 이웃을 다 본 정점을 호출 스택에서 빼며 부모에게 `low` 를 넘기고, 부모가 뿌리가 아니면 판정한다(3 · 4단계)
5. 탐색 하나가 끝나면 뿌리를 나무 자식 수로 판정한다(5단계)
6. `cut` 이 참인 정점을 번호 순서로 모아 돌려준다

### 수행으로 알아보는 알고리즘 — 정점 다섯을 열아홉 걸음으로 판정한다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 그래프 하나를 정해 끝까지 가져가되, 코드
조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

```ts
const n = 5;
const edges: [number, number][] = [
  [0, 1], [1, 2], [2, 0], [0, 3], [3, 4],
];
// 이 절이 끝나면 [0, 3] 이 나와야 한다
```

왜 이 다섯 간선을 골랐을까요? 아홉 갈래를 한 입력에서 전부 실행하려는 것입니다. `2−0` 이 되돌아가는 간선
갈래를 내고, 뿌리 0 에 나무 자식이 둘 붙어 뿌리 판정이 참으로 끝나요. 정점 4 는 자식이 없어 `low` 가 자기
발견 순서에서 안 움직이고, 정점 3 에서 부모 판정이 참이 됩니다.

```text
절차 전체를 한 장으로

  T1        간선 목록을 두 끝의 이웃 목록에 나눠 담는다                  ① 이웃 목록
            disc · low 를 -1 로, cut 을 거짓으로 채운다                   ② 정점마다의 칸
            정점 번호 순서로 아직 안 들어간 정점을 찾아 들어간다:
  T2          disc 와 low 에 같은 수를 적고 호출 스택 세 배열에 담는다    ③ 진입
  T3~T17      호출 스택 맨 위 정점에 아직 안 읽은 이웃 자리가 있으면
                처음 보는 이웃이면 그 정점으로 내려가고                   ④ 내려간다
                이미 들어갔던 정점이면 low 를 줄이고                      ⑤ 줄인다
                부모면 건너뛴다                                           ⑥ 건너뛴다
              이웃을 다 봤으면 빼고 부모에게 low 를 넘긴다                ⑦ 뺀다
                자식이 부모 위로 못 가면 부모를 단절점으로 적는다         ⑧ 판정한다
  T18       뿌리는 나무 자식 수로 따로 판정한다                           ⑨ 뿌리 판정
  T19       cut 이 참인 정점을 오름차순으로 모아 돌려준다
```

#### 1. 이웃 목록과 정점마다의 칸을 만든다

첫 조각이 준비입니다. 무향 간선이라 간선 하나를 **두 끝의 목록에** 넣고, 길이 `n` 인 배열 셋을 만들어요.
`disc` 와 `low` 는 `-1` 로, `cut` 은 거짓으로 채웁니다. `-1` 이 「아직 안 들어간 정점」의 표기예요.

```ts
const adj: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  if (u === v) continue;
  (adj[u] as number[]).push(v);          // ① 이웃 목록
  (adj[v] as number[]).push(u);
}

const disc: number[] = Array.from({ length: n }, () => -1);
const low: number[] = Array.from({ length: n }, () => -1);
const cut: boolean[] = Array.from({ length: n }, () => false);
let timer = 0;                           // ② 정점마다의 칸
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walkT1-->

```text
T1 이 끝난 시점
  adj    0:[1, 2, 3]  1:[0, 2]  2:[1, 0]  3:[0, 4]  4:[3]
  disc   [-1, -1, -1, -1, -1]
  low    [-1, -1, -1, -1, -1]
  cut    [false, false, false, false, false]
  timer  0
```

간선 다섯이 두 끝의 목록에 한 자리씩 들어갔고, 목록 안의 순서는 간선 목록에 적힌 순서를 따릅니다. `①` 이 없으면
정점 하나의 이웃을 알아낼 때마다 간선 목록을 처음부터 끝까지 읽어야 해요.

#### 짚고 가기 — 두 끝이 같은 간선을 안 걸러도 답은 그대로다

여기서 헷갈리기 쉬운 부분은 `if (u === v) continue;` 한 줄입니다. 「이 줄이 없으면 답이 틀리겠지」로 읽기
쉬워요. 그 줄을 빼고 두 끝이 같은 간선이 든 그래프 넷에 실행해 봅시다.

```ts
for (const [u, v] of edges) {
  // if (u === v) continue 가 있던 자리를 비웠다
  (adj[u] as number[]).push(v);
  (adj[v] as number[]).push(u);
}
```

<!--proof:pauseSelfLoop-->

| 입력 | 두 끝이 같은 간선 | 정본 | 그 줄을 뺀 판 | 판정 | 정본의 이웃 자리 읽기 | 뺀 판의 이웃 자리 읽기 |
| --- | ---: | --- | --- | --- | ---: | ---: |
| 삼각형 + 두 끝이 같은 간선 하나 | 1 | [] | [] | 같다 | 6 | 8 |
| 전개 입력 + 두 끝이 같은 간선 둘 | 2 | [0, 3] | [0, 3] | 같다 | 10 | 14 |
| 꼬리가 붙은 삼각형 + 그 간선 하나 | 1 | [1] | [1] | 같다 | 8 | 10 |
| 두 끝이 같은 간선만 | 3 | [] | [] | 같다 | 0 | 6 |

네 입력 중 답이 일치한 것은 4 개입니다. 뺀 판은 두 끝이 같은 간선 하나마다 이웃 자리를 2 개씩 더 읽습니다.

<!--/proof-->

**네 입력 모두 답이 같습니다.** 답이 안 틀리는 까닭은 그 간선이 만드는 이웃 자리가 자기 자신을 가리키기
때문이에요. `w` 가 `v` 자신이면 `disc[w]` 는 이미 정해져 있고 부모도 아니라 `⑤` 로 가는데, 그때 하는 일이
`low[v]` 를 `disc[v]` 와 비교하는 것입니다. `low[v]` 는 처음부터 `disc[v]` 이하라 값이 안 바뀌어요. 그런데도
이 줄을 두는 까닭은 비용의 등식 때문입니다.

| 판 | 두 끝이 같은 간선 하나가 이웃 목록에 더하는 자리 | 이웃 자리 읽기 |
| --- | --- | --- |
| 정본 | 없다 | `2(E − L)` |
| 그 줄을 뺀 판 | 두 자리 — 읽어도 아무 일도 안 한다 | `2E` |

#### 2. 정점에 들어가는 일을 한 함수로 묶고 호출 스택을 배열 셋으로 든다

둘째 조각이 순회의 뼈대입니다. 재귀로 적으면 함수 호출이 해 주는 일을 배열 셋으로 직접 들어요. 그 까닭은
「아이디어 상세」의 「호출 스택을 배열로 드는 까닭」에서 값으로 봤습니다. 정점에 처음 들어가는 일이 두 자리에서
일어나고 하는 일이 똑같아서 `enter` 하나로 묶었어요.

```ts
const callV: number[] = [];
const callI: number[] = [];
const callP: number[] = [];
const enter = (v: number, parent: number): void => {   // ③ 진입
  disc[v] = timer;
  low[v] = timer;
  timer++;
  callV.push(v);
  callI.push(0);
  callP.push(parent);
};

for (let root = 0; root < n; root++) {
  if (disc[root] !== -1) continue;
  let rootKids = 0;
  enter(root, -1);
  while (callV.length > 0) {
    const v = callV[callV.length - 1] as number;
    const i = callI[callI.length - 1] as number;
    const nbrs = adj[v] as number[];
    if (i < nbrs.length) {
      callI[callI.length - 1] = i + 1;
      // … 이웃 하나를 본다 …
      continue;
    }
    callV.pop();                                       // ⑦ 뺀다
    callI.pop();
    // … 부모에게 low 를 넘기고 판정한다 …
  }
}
```

`T2` 와 `T3` 에서 이 조각을 실행하면 이렇습니다.

<!--proof:walkT2T3-->

```text
T2 — 바깥 반복이 정점 0 에 들어간다
  disc   [0, -, -, -, -]
  low    [0, -, -, -, -]
  callV  [0]
  callI  [0]
  callP  [-1]
  timer  1
T3 — 간선 0−1 을 읽고 정점 1 로 내려간다
  disc   [0, 1, -, -, -]
  low    [0, 1, -, -, -]
  callV  [0, 1]
  callI  [1, 0]
  callP  [-1, 0]
  timer  2
```

여기서 가장 중요한 줄은 `callI[callI.length - 1] = i + 1` 입니다. 이웃을 **읽기 전에** 다음 자리를 올려 두므로,
그 이웃으로 내려갔다가 돌아와도 같은 자리를 다시 읽지 않아요. T3 의 `callI` 첫 칸이 1 로 올라가 있는 것이 그
자리입니다. 이 줄이 「이웃 자리를 정확히 한 번씩 읽는다」를 지킵니다.

#### 3. 이웃 하나를 보고 세 갈래로 나눈다

셋째 조각이 2단계입니다. 읽은 이웃 `w` 가 처음 보는 정점이면 내려가고, 부모가 아닌 이미 들어갔던 정점이면
`low[v]` 를 `disc[w]` 까지 내리고, 부모면 건너뛰어요. 뿌리가 내려갈 때는 `rootKids` 를 셉니다.

```ts
const w = nbrs[i] as number;
if (disc[w] === -1) {
  if (v === root) rootKids++;
  enter(w, v);                                              // ④ 내려간다
} else if (w !== (callP[callP.length - 1] as number)) {
  low[v] = Math.min(low[v] as number, disc[w] as number);   // ⑤ 줄인다
} else {
  // ⑥ 부모라 건너뛴다
}
```

`⑥` 과 `⑤` 가 실행되는 세 걸음의 결과입니다.

<!--proof:walkT4T7T10-->

```text
T4 — 정점 1 에서 이웃 0 을 읽는다
  판정   disc[0] = 0 이라 -1 이 아니고, 부모 칸이 0 이라 부모다
  계산   건너뛴다 — low[1] 는 1 그대로
  low    [0, 1, -, -, -]
  callV  [0, 1]
T7 — 정점 2 에서 이웃 0 을 읽는다
  판정   disc[0] = 0 이라 -1 이 아니고, 부모 칸이 1 이라 부모가 아니다
  계산   low[2] = min(2, disc[0] = 0) = 0
  low    [0, 1, 0, -, -]
  callV  [0, 1, 2]
T10 — 정점 0 에서 이웃 2 를 읽는다
  판정   disc[2] = 2 라 -1 이 아니고, 부모 칸이 -1 이라 부모가 아니다
  계산   low[0] = min(0, disc[2] = 2) = 0
  low    [0, 0, 0, -, -]
  callV  [0]
```

`⑤` 에서 쓰는 것이 `low[w]` 가 아니라 `disc[w]` 라는 것을 봐 주세요. low 값의 정의가 「되돌아가는 간선 하나로
이르는 정점의 **발견 순서**」였고, 이 줄이 그것을 그대로 옮겼어요. T10 처럼 이미 끝난 자손을 읽는 경우도 같은
줄로 가지만, 자손의 발견 순서는 언제나 자기보다 커서 값이 안 바뀝니다.

#### 짚고 가기 — 부모를 안 건너뛰어도 답은 같지만 low 가 다른 수가 된다

여기서 헷갈리기 쉬운 부분은 `⑥` 갈래입니다. 「이미 들어갔던 정점이면 어차피 거기까지 갈 수 있으니 부모든
아니든 `low` 를 줄이면 되지 않나」로 읽기 쉬워요. 부모인지 보는 검사를 늘 참으로 두어 봅시다.

```ts
if (disc[w] === -1) {
  if (v === root) rootKids++;
  enter(w, v);
} else if (true) {                           // ← 부모인지 보는 검사를 늘 참으로 두었다
  low[v] = Math.min(low[v] as number, disc[w] as number);
} else {
}
```

| 정점 | disc | 정의대로의 low | 부모까지 넣은 low | 두 값의 갈림 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 0 | 0 | 0 | 아니오 |
| 1 | 1 | 0 | 0 | 아니오 |
| 2 | 2 | 0 | 0 | 아니오 |
| 3 | 3 | 3 | 0 | 예 |
| 4 | 4 | 4 | 3 | 예 |

두 값이 갈리는 정점은 3 · 4 입니다. 부모 건너뛰기를 뺀 판을 여섯 입력에 실행하면 이렇습니다.

| 입력 | 정본 | 부모 건너뛰기를 뺀 판 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 | [0, 3] | [0, 3] | 같다 |
| 사이클 하나 | [] | [] | 같다 |
| 꼬리가 붙은 삼각형 | [1] | [1] | 같다 |
| 삼각형 둘이 정점 하나를 함께 씀 | [1] | [1] | 같다 |
| 삼각형 둘을 간선 하나가 이음 | [2, 3] | [2, 3] | 같다 |
| 떨어진 두 성분 | [1, 4] | [1, 4] | 같다 |

여섯 입력 중 답이 일치한 것은 6 개입니다.

<!--/proof-->

**답은 여섯 입력 모두 같은데 `low` 는 정점 둘에서 갈립니다.** 이 판은 답이 안 틀리니 테스트만으로는 차이를
알 수 없어요. 답이 안 바뀌는 까닭은 판정이 `≥` 이기 때문입니다. 부모까지 넣으면 자식의 `low` 가 부모의
`disc` 까지 내려갈 수 있지만 그 아래로는 안 내려가고, 두 값이 같으면 등호가 판정을 그대로 참으로 둬요.

그래도 건너뛰는 까닭은 `low` 가 뜻을 잃기 때문입니다. 정점 4 의 값이 3 이라고 적히면 「4 의 서브트리가 발견
순서 3 까지 올라간다」로 읽히는데, 4 에서 3 으로 가는 길은 방금 내려온 나무 간선 하나뿐이고 그 간선은 3 을
지우면 함께 사라져요. 등호 하나가 그 차이를 덮고 있을 뿐이라, 판정을 `>` 로 바꾸는 순간(다리를 찾는
[`bridgesInGraph`](../bridgesInGraph/bridgesInGraph-guide.md) 의 판정이 그 모양이에요) 답이 갈릴 수 있습니다.

| 판 | 정점 4 의 low | 읽히는 내용 |
| --- | --- | --- |
| 정본 | 자기 발견 순서 | 서브트리가 4 를 거치지 않고는 위로 못 간다 |
| 부모까지 넣은 판 | 부모 3 의 발견 순서 | 방금 내려온 나무 간선을 되돌아가는 길로 셌다 |

#### 4. 이웃을 다 본 정점을 빼면서 부모를 판정한다

넷째 조각이 3단계와 4단계입니다. 이웃을 다 본 정점을 호출 스택에서 빼면서 자기 `low` 를 부모 칸에 넘기고, 그
자리에서 부모가 단절점인지 판정해요. 부모가 뿌리면 판정을 건너뜁니다.

```ts
callV.pop();                                              // ⑦ 뺀다
callI.pop();
const parent = callP.pop() as number;
if (parent !== -1) {
  low[parent] = Math.min(low[parent] as number, low[v] as number);
  if (parent !== root && (low[v] as number) >= (disc[parent] as number)) {
    cut[parent] = true;                                   // ⑧ 판정한다
  }
}
```

T8 과 T15 에서 이 조각을 실행한 결과입니다.

<!--proof:walkT8T15-->

```text
T8 — 정점 2 를 뺀다
  넘기기  low[1] = min(1, low[2] = 0) = 0
  판정    부모 1 은 뿌리가 아니고 low[2] = 0 ≥ disc[1] = 1 이 거짓
  cut     []
  callV   [0, 1]
T15 — 정점 4 를 뺀다
  넘기기  low[3] = min(3, low[4] = 4) = 3
  판정    부모 3 은 뿌리가 아니고 low[4] = 4 ≥ disc[3] = 3 이 참
  cut     [3]

```

여기서 가장 중요한 줄은 `low[parent] = Math.min(low[parent], low[v])` 입니다. 이 줄이 서브트리의 결과를 한
칸 위로 올려서, 부모가 빠질 때 넘기는 값이 부모의 서브트리 전체를 담게 해요. T8 에서 `low[1]` 이 0 이 된 것이
이 줄 덕분이고, 그래서 정점 1 이 빠질 때 뿌리 0 으로 올라가는 길이 기록됩니다.

#### 짚고 가기 — 등호를 빼면 단절점이 사라진다

여기서 헷갈리기 쉬운 부분은 `≥` 의 등호입니다. 「자식이 부모까지 되돌아올 수 있으면 부모를 지워도 괜찮은 것
아닌가」로 읽기 쉬워요. 등호를 빼 봅시다.

```ts
if (parent !== root && (low[v] as number) > (disc[parent] as number)) {   // ← 등호를 뺐다
  cut[parent] = true;
}
```

<!--proof:pauseEquality-->

| 나무 간선 | disc[부모] | low[자식] | low ≥ disc | low > disc | 부모의 실제 |
| --- | ---: | ---: | --- | --- | --- |
| 1−2 | 1 | 1 | 참 | 거짓 | 단절점 |
| 2−3 | 2 | 1 | 거짓 | 거짓 | 아니다 |

등호를 뺀 판을 여섯 입력에 실행하면 이렇습니다.

| 입력 | 정본 | 등호를 뺀 판 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 | [0, 3] | [0, 3] | 같다 |
| 사이클 하나 | [] | [] | 같다 |
| 꼬리가 붙은 삼각형 | [1] | [] | 다르다 |
| 삼각형 둘이 정점 하나를 함께 씀 | [1] | [] | 다르다 |
| 삼각형 둘을 간선 하나가 이음 | [2, 3] | [2] | 다르다 |
| 떨어진 두 성분 | [1, 4] | [1, 4] | 같다 |

여섯 입력 중 답이 갈린 것은 3 개입니다.

<!--/proof-->

**꼬리가 붙은 삼각형에서 단절점 1 이 사라집니다.** 나무 간선 `1−2` 에서 `low[2] = 1` 이고 `disc[1] = 1` 이라 두
값이 같은데, 등호가 있으면 참이고 없으면 거짓이에요. 정점 2 와 3 은 간선 `3−1` 로 정점 1 까지만 되돌아가고,
1 을 지우면 그 간선도 함께 사라져 0 이 떨어져 나갑니다.

| 비교 | 서브트리의 상태 | 부모를 지운 결과 |
| --- | --- | --- |
| `low[c] = disc[v]` | 서브트리가 가장 멀리 가도 `v` 자신이다 | 그 간선도 사라진다 — 떨어진다 |
| `low[c] < disc[v]` | `v` 보다 먼저 발견한 정점까지 간다 | 그 길이 남는다 — 붙어 있다 |

#### 5. 뿌리는 나무 자식 수로 판정한다

다섯째 조각이 뿌리 판정입니다. 바깥 반복의 한 바퀴가 끝난 자리, 곧 뿌리에서 시작한 탐색이 끝난 자리에서
`rootKids` 를 봐요. 그리고 모든 탐색이 끝나면 `cut` 이 참인 정점을 모아 돌려줍니다.

```ts
    if (rootKids >= 2) cut[root] = true;   // ⑨ 뿌리 판정
  }

  const result: number[] = [];
  for (let v = 0; v < n; v++) if (cut[v]) result.push(v);
  return result;
```

T16 부터 T18 까지를 실행한 결과입니다.

```text

  판정    부모 0 이 뿌리라 보지 않는다
  callV   [0]
T17 — 정점 0 을 뺀다
  넘기기  부모가 없어 넘기지 않는다
```

T16 은 T15 와 같은 줄을 실행하지만 부모가 뿌리라 판정을 건너뜁니다. 뿌리 0 이 단절점이라는 것은 T18 의 자식

#### 짚고 가기 — 뿌리에도 같은 규칙을 쓰면 뿌리가 거짓으로 단절점이 된다

여기서 헷갈리기 쉬운 부분은 `parent !== root` 조건입니다. 「규칙이 하나면 될 텐데 왜 뿌리만 빼 두나」로 읽기
쉬워요. 그 조건을 빼 봅시다.

```ts
if ((low[v] as number) >= (disc[parent] as number)) {   // ← 뿌리를 빼 두는 조건을 뺐다
  cut[parent] = true;
}
```

| 자식 1 을 뺄 때의 비교 | low[1] = 0 ≥ disc[0] = 0 이 참 |

| 사이클 하나 | [] | [0] | 다르다 |

**여섯 입력 중 다섯에서 답이 갈립니다.** 뿌리의 발견 순서는 그 덩어리에서 가장 작아서 `low[c] ≥ disc[뿌리]` 가
어느 자식에서나 참이에요. 그래서 조건을 빼면 자식이 하나뿐인 뿌리까지 단절점으로 적히고, 사이클 하나처럼
단절점이 없는 그래프에서도 `[0]` 이 나옵니다. 참이 되는 까닭이 조건이 아니라 자리라서, 뿌리에서는 이 비교가
아무것도 가르지 못해요.

#### 7. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 없어요. `enter` 를 부르는 자리가 바깥 반복과
`④` 두 곳이라는 것만 완성본에서 다시 확인해 주세요.

```ts
export function articulationPoints(
  n: number,
  edges: [number, number][],
): number[] {
  // ① 이웃 목록 — 무향 간선이라 양쪽 정점에 서로를 넣는다. 두 끝이 같은 간선은 담지 않는다.
  const adj: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    if (u === v) continue;
    (adj[u] as number[]).push(v);
    (adj[v] as number[]).push(u);
  }

  // ② 정점마다 적는 칸 — 발견 순서 `disc`, 서브트리가 되돌아가는 간선으로 이르는 가장 이른
  // 발견 순서 `low`, 그리고 단절점으로 판정됐는지를 적는 `cut`.
  const disc: number[] = Array.from({ length: n }, () => -1);
  const low: number[] = Array.from({ length: n }, () => -1);
  const cut: boolean[] = Array.from({ length: n }, () => false);
  let timer = 0;

  // ③ 호출 스택 — `callV` 가 지금 보고 있는 정점, `callI` 가 그 정점의 이웃 목록에서 다음에
  // 읽을 자리, `callP` 가 그 정점의 부모다. 뿌리의 부모 자리에는 `-1` 을 넣는다.
  const callV: number[] = [];
  const callI: number[] = [];
  const callP: number[] = [];
  const enter = (v: number, parent: number): void => {
    disc[v] = timer;
    low[v] = timer;
    timer++;
    callV.push(v);
    callI.push(0);
    callP.push(parent);
  };

  for (let root = 0; root < n; root++) {
    if (disc[root] !== -1) continue;
    let rootKids = 0;
    enter(root, -1);

    while (callV.length > 0) {
      const v = callV[callV.length - 1] as number;
      const i = callI[callI.length - 1] as number;
      const nbrs = adj[v] as number[];

      if (i < nbrs.length) {
        callI[callI.length - 1] = i + 1;
        const w = nbrs[i] as number;
        if (disc[w] === -1) {
          // ④ 처음 보는 이웃 — 나무 간선이다. 그 정점으로 내려간다.
          if (v === root) rootKids++;
          enter(w, v);
        } else if (w !== (callP[callP.length - 1] as number)) {
          // ⑤ 이미 들어갔던 정점 — 조상이면 그 발견 순서까지 되돌아갈 수 있다.
          low[v] = Math.min(low[v] as number, disc[w] as number);
        } else {
          // ⑥ 부모 — 방금 내려온 나무 간선을 거꾸로 본 것이라 건너뛴다.
        }
        continue;
      }

      // ⑦ 이웃을 다 본 정점 — 호출 스택에서 빼고, 자기 `low` 를 부모에게 넘긴다.
      callV.pop();
      callI.pop();
      const parent = callP.pop() as number;
      if (parent !== -1) {
        low[parent] = Math.min(low[parent] as number, low[v] as number);
        // ⑧ 뿌리가 아닌 부모의 판정 — 자식이 부모 위로 못 가면 그 부모가 단절점이다.
        if (parent !== root && (low[v] as number) >= (disc[parent] as number)) {
          cut[parent] = true;
        }
      }
    }

    // ⑨ 뿌리의 판정 — 나무 자식이 둘 이상이면 뿌리가 단절점이다.
    if (rootKids >= 2) cut[root] = true;
  }

  const result: number[] = [];
  for (let v = 0; v < n; v++) if (cut[v]) result.push(v);
  return result;
}
```

### 알아 두면 좋은 개념 — 블록-컷 나무

전개 입력에서 삼각형 `{0, 1, 2}` 는 안의 어느 정점을 지워도 갈라지지 않았고, 정점 0 과 3 은 지우면 갈라졌습니다.
「안의 어느 정점을 지워도 갈라지지 않는 가장 큰 조각」을 **블록**이라고 부르고, 간선 하나하나는 정확히 한 블록에
듭니다. 블록을 점으로, 단절점을 또 다른 점으로 놓고 「이 단절점이 이 블록에 든다」를 간선으로 이으면 사이클이
없는 나무가 나오는데, 이것을 **블록-컷 나무**라고 부릅니다.

사슬은 간선마다 블록 하나라 가운데 정점이 전부 두 블록에 들고, 사이클은 통째로 블록 하나라 겹치는 정점이 없어요.
블록을 가르는 절차는 이 글의 절차에 간선 스택 하나를 더한 것입니다. 정점을 뺄 때 `low[자식] ≥ disc[부모]` 가
참이면(부모가 뿌리여도) 스택에서 그 나무 간선까지 빼내고, 빼낸 간선들의 끝 정점이 블록 하나예요.

| 쓰이는 곳 | 접는 것 | 접은 뒤에 하는 일 |
| --- | --- | --- |
| 두 정점 사이 경로가 반드시 지나는 정점 질의 | 블록 하나를 점 하나로 | 나무 위 경로에 놓인 단절점을 센다 |
| 통신망의 단일 장애점 보고 | 같은 블록에 든 장비 | 블록 하나를 이중화된 구간으로 다룬다 |
| 이중 연결 성분 위의 동적 계획법 | 사이클을 이룬 정점 묶음 | 사이클이 없어졌으니 나무 위에서 한 번에 센다 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 이것을 쓰는지, low 값의 정의에서 무엇이 따라 나오는지, 무엇이
매 걸음 참으로 남는지, 그리고 연산이 몇 번인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **무향 그래프이고, 지우면 갈라지는 정점을 전부 알아야 합니다.** 정점 하나가 단절점인지만 물으면 그 정점을 빼고
  덩어리를 한 번 세는 것으로 끝나요.
- **그래프가 통째로 메모리에 들어옵니다.** 이웃 목록 `2(E − L)` 칸과 정점마다의 칸 셋을 들고, 그 목록을 정점
  번호로 건너뛰며 읽어요.
- **정점 수가 커서 정점마다 지워 보는 방법을 감당할 수 없습니다.** 지워 보면 탐색이 `V` 번에 비례하고, 탐색마다
  그래프 전체를 다시 읽습니다.

| 조건 | 코드에 나타나는 모양 |
| --- | --- |
| 무향 그래프다 | 간선 하나를 두 끝의 목록에 넣고, 부모를 건너뛴다 |
| 단절점을 전부 알아야 한다 | 바깥 반복이 정점을 차례로 읽고, 안 들어간 정점마다 탐색을 시작한다 |
| `V` 가 크다 | 정점마다 순회하지 않고 한 번의 순회에 수 둘을 함께 적는다 |

간선 하나를 지웠을 때 갈라지는지를 묻는 것은 [`bridgesInGraph`](../bridgesInGraph/bridgesInGraph-guide.md) 이고,
같은 두 수에 판정이 `low[c] > disc[v]` 로 바뀌며 뿌리 판정이 필요 없어요.

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 가리키는 것 | 이 절차 |
| --- | --- | --- | --- |
| 지문 | "고장 나면 통신이 끊기는 중계기" | 지우면 갈라지는 정점을 묻는다 | 쓴다 |
| 지문 | "이 도시를 막으면 갈 수 없게 되는 도시가 있는가" | 같은 말이다 | 쓴다 |
| 지문 | "단일 장애점" "필수 경유지" | 정점 하나에 의존하는 자리를 묻는다 | 쓴다 |
| 지문 | "지워도 안 갈라지는 가장 큰 조각으로 나눠라" | 블록으로 나누라는 말이다 | 간선 스택을 더해 쓴다 |
| 제약 | `V` 와 `E` 가 둘 다 10^5 | 정점마다 다시 순회하면 1 초에 못 든다 | 쓴다 |
| 지문 | "끊기면 통신이 안 되는 회선" | 정점이 아니라 간선을 묻는다 | 판정만 바꾼 다른 절차 |
| 지문 | "정점 하나를 정해 줄 테니 그것만 판정하라" | 그 정점을 빼고 한 번 세면 끝난다 | 더 가벼운 절차 |
| 지문 | "두 정점을 동시에 지웠을 때" | 이 절차가 답하는 범위 밖이다 | 못 쓴다 |

「정점 하나를 정해 줄 테니 그것만 판정하라」 줄이 이 절차의 쓰임을 잘 보여 줍니다. 정점 하나만 판정하라면 그
정점을 뺀 그래프에서 덩어리를 한 번 세는 쪽이 적은 일이에요. 이 절차가 값을 하는 자리는 **정점 전부의 답이 한
번의 순회에서 함께 나온다**는 데 있습니다.

#### 실제로 쓰이는 곳

- **NetworkX 의 `articulation_points`** — 파이썬 그래프 라이브러리가 이 절차를 담고 있어요. 문서 문자열이
  *"An articulation point or cut vertex is any node whose removal (along with all its incident edges) increases
  the number of connected components of a graph."* 로 이 글과 같은 정의를 적고, 같은 파일이 *"The algorithm to
  find articulation points and biconnected components is implemented using a non-recursive depth-first-search
  (DFS) that keeps track of the highest level that back edges reach in the DFS tree."* 로 **재귀를 쓰지 않는다**는
  것과 되돌아가는 간선이 이르는 가장 높은 자리를 함께 든다는 것을 나란히 밝혀요. 코드가 쓰는 이름도 이 글의
  `disc` · `low` 에 해당하는 `discovery` · `low` 이고, 호출 스택을 배열로 든 자리가 `stack` · `edge_index`
  입니다.
  ([`networkx/algorithms/components/biconnected.py`](https://github.com/networkx/networkx/blob/main/networkx/algorithms/components/biconnected.py),
  조회 2026-09-06)
- **Boost Graph Library 의 `articulation_points`** — C++ 그래프 라이브러리의 함수입니다. 공식 문서가
  *"Articulation points are vertices whose removal would increase the number of connected components in the
  graph."* 로 정의를 적고, *"The time complexity for the biconnected components and articulation points
  algorithms O(V + E)."* 로 비용을, *"The algorithm implemented is due to Tarjan."* 로 출처를 적어요. 이름
  붙은 매개변수가 `discover_time_map` 과 `lowpoint_map` 이라 이 글의 두 수가 그대로 인터페이스에 나와
  있습니다.
  ([Boost.Graph `biconnected_components`](https://www.boost.org/doc/libs/1_88_0/libs/graph/doc/biconnected_components.html),
  조회 2026-09-06)

| 출처 | 발견 순서와 low 값 | 호출 스택 | 함께 내는 것 |
| --- | --- | --- | --- |
| 이 글 | `disc` · `low` 배열 둘 | 배열 셋(`callV` · `callI` · `callP`) | 단절점 |
| NetworkX | `discovery` · `low` 사전 둘 | `stack` · `edge_index` | 블록까지 |
| Boost | `discover_time_map` · `lowpoint_map` 속성 맵 | 라이브러리 안 | 블록까지 |

**「어느 구현이 더 빠른가」는 두 출처 어디에도 없습니다.** Boost 가 적은 것은 `O(V + E)` 라는 상한 하나이고,
NetworkX 가 적은 것은 재귀를 쓰지 않는다는 구현 사실이에요. 이 글이 내미는 계수는 전부 이 저장소의 실행이 낸
값이고 다른 구현의 값이 아닙니다.

### 수식 정의와 유도

정점 `v` 의 깊이 우선 탐색 트리 자식 집합을 $C(v)$, `v` 에서 나가는 되돌아가는 간선이 이르는 조상의 집합을
$B(v)$ 라 씁니다. 그러면 low 값의 정의가 아래 식입니다. 첫째 항은 자기 발견 순서, 둘째 항은 간선 하나로 바로
이르는 조상의 발견 순서, 셋째 항은 자식이 자기 서브트리를 다 보고 넘겨준 값이에요.

$$
\operatorname{low}[v] = \min\Bigl(\{\operatorname{disc}[v]\} \cup \{\operatorname{disc}[x] : x \in B(v)\} \cup \{\operatorname{low}[c] : c \in C(v)\}\Bigr)
$$

전개 입력의 정점 다섯에 세 항을 각각 계산해, 최솟값이 실행이 낸 값과 맞는지 확인합시다.

<!--proof:mathCheck-->

| 정점 v | 첫째 항 disc[v] | 둘째 항 disc[x] | 셋째 항 low[c] | 세 항의 최솟값 | 실행이 낸 low[v] | 대조 |
| ---: | ---: | --- | --- | ---: | ---: | --- |
| 0 | 0 | 없음 | 0 · 3 | 0 | 0 | 일치 |
| 1 | 1 | 없음 | 0 | 0 | 0 | 일치 |
| 2 | 2 | 0 | 없음 | 0 | 0 | 일치 |
| 3 | 3 | 없음 | 4 | 3 | 3 | 일치 |
| 4 | 4 | 없음 | 없음 | 4 | 4 | 일치 |

다섯 정점 중 5 정점에서 일치합니다. 같은 실행에서 이웃 자리 읽기는 10 번이고 2(E − L) 은 10 입니다.

<!--/proof-->

정점 1 과 2 를 봐 주세요. 정점 2 는 둘째 항 `disc[0] = 0` 이 최솟값을 정하고, 정점 1 은 셋째 항 `low[2] = 0` 이
정해요. 식의 세 항이 절차의 세 자리 — 진입 · `⑤` · `⑦` — 와 하나씩 짝을 이룹니다.

| 항 | 코드의 자리 | 전개 입력의 예 |
| --- | --- | --- |
| 첫째 항 $\operatorname{disc}[v]$ | 진입에서 `low[v] = timer` | 정점 4 는 이 항만 있다 |
| 둘째 항 $\operatorname{disc}[x]$ | `⑤` 의 `Math.min(low[v], disc[w])` | 정점 2 에서 $B(2) = \{0\}$ |
| 셋째 항 $\operatorname{low}[c]$ | `⑦` 의 `Math.min(low[parent], low[v])` | 정점 1 에서 $C(1) = \{2\}$ |

이제 판정 규칙을 이 정의에서 끌어냅니다. 서브트리를 식에 쓰려면 이름이 필요해서, 이 절에서만 정점 `c` 의
서브트리를 $S(c)$ 라 씁니다. 뿌리가 아닌 `v` 에 대해 세울 식은 아래와 같고, 두 방향을 나눠 적습니다.

$$
v \in A \iff \exists\, c \in C(v) :\ \operatorname{low}[c] \geq \operatorname{disc}[v]
$$

1. **오른쪽이면 왼쪽.** $\operatorname{low}[c] \geq \operatorname{disc}[v]$ 인 자식 `c` 가 있다고 합시다.
   「먼저 알아 둘 개념」에서 본 대로 $S(c)$ 의 정점에서 $S(c)$ 밖으로 나가는 간선은 나무 간선 `c−v` 이거나
   조상으로 가는 되돌아가는 간선입니다. 그 조상 가운데 `v` 가 아닌 것은 `v` 의 조상이라 발견 순서가
   $\operatorname{disc}[v]$ 보다 작아요. 그런 간선이 하나라도 있으면 $\operatorname{low}[c]$ 가 그 값 이하가 되어
   가정과 어긋나므로, 없습니다. 남은 간선은 전부 `v` 로 가고, `v` 를 지우면 함께 사라지므로 $S(c)$ 가 떨어져
   덩어리가 하나 늘어납니다.
2. **왼쪽이면 오른쪽.** 거꾸로 모든 자식 `c` 에서 $\operatorname{low}[c] < \operatorname{disc}[v]$ 라고 합시다.
   그러면 $S(c)$ 안의 어떤 정점에서 `v` 의 조상 `a` 로 가는 되돌아가는 간선이 있어요. `v` 를 지워도 $S(c)$ 는
   그 간선으로 `a` 에 붙고, `a` 는 뿌리와 나무 경로로 이어져 있습니다. `v` 의 이웃은 부모 · 조상 · 어떤 $S(c)$
   안의 정점뿐이라 모두 뿌리 쪽 덩어리에 남으니, 덩어리 수가 그대로예요.

| 방향 | 가정 | 따라 나오는 것 |
| --- | --- | --- |
| 오른쪽이면 왼쪽 | 어떤 자식 `c` 에서 $\operatorname{low}[c] \geq \operatorname{disc}[v]$ | $S(c)$ 밖으로 가는 간선이 모두 `v` 로 간다 — `v` 를 지우면 $S(c)$ 가 떨어진다 |
| 왼쪽이면 오른쪽 | 모든 자식 `c` 에서 $\operatorname{low}[c] < \operatorname{disc}[v]$ | 모든 $S(c)$ 가 `v` 의 조상에 붙는다 — 덩어리 수가 그대로다 |

**여기서 본문의 값만으로는 안 나오는 것이 하나 따라 나옵니다.** 두 규칙을 쓰면 단절점 개수에 임의의 `V` 에서
성립하는 상한이 붙어요.

$$
|A| \leq \max(0,\; V - 2)
$$

상한은 아래 두 걸음으로 세웁니다.

| 걸음 | 내용 | 까닭 |
| --- | --- | --- |
| 잎은 단절점이 아니다 | 나무 자식이 없는 정점 | 부모 판정이 한 번도 참이 안 된다 |
| 덩어리마다 단절점이 아닌 정점이 둘 이상 | 뿌리의 자식이 하나면 뿌리와 잎 하나 | 뿌리 판정이 거짓이다 |
| | 뿌리의 자식이 둘 이상이면 자식마다 잎 하나 | 서브트리마다 맨 아래에 잎이 있다 |

첫째, 트리의 잎(나무 자식이 없는 정점)은 단절점이 아닙니다. 잎에는 자식이 없어
부모 판정이 한 번도 참이 안 되고, 잎이 뿌리이면 그 덩어리가 정점 하나라 자식 수가 0 이기 때문이에요. 둘째,
정점이 둘 이상인 덩어리에는 단절점이 아닌 정점이 둘 이상 있습니다. 뿌리의 자식이 하나면 뿌리가 단절점이 아니고
그 트리의 잎이 하나 더 있어요. 자식이 둘 이상이면 자식마다 서브트리에 잎이 하나씩 있습니다. 정점이 하나뿐인
덩어리는 그 정점이 단절점이 아니니, 덩어리가 몇 개든 단절점은 `V − 2` 개를 넘지 못해요.

식을 코드로 옮기면 잎을 세는 조각이 됩니다.

```ts
// 식을 그대로 옮긴 조각 — 나무의 부모 배열 `parentOf` 를 받아 잎을 센다.
const kids: number[] = Array.from({ length: n }, () => 0);
for (let v = 0; v < n; v++) {
  const p = parentOf[v] as number;
  if (p !== -1) (kids[p] as number)++;
}
const leaves = kids.filter((k) => k === 0).length;
```

상한이 실제로 지켜지는지, 그리고 어떤 모양이 그 상한과 같아지는지 여덟 모양에서 재 봅시다.

<!--proof:mathBound-->

| 입력 | V | E | 단절점 개수 | 상한 V − 2 | 상한 |
| --- | ---: | ---: | ---: | ---: | --- |
| 사슬 (V = 8) | 8 | 7 | 6 | 6 | 지킨다 |
| 사슬 (V = 64) | 64 | 63 | 62 | 62 | 지킨다 |
| 사이클 (V = 64) | 64 | 64 | 0 | 62 | 지킨다 |
| 별 (V = 64) | 64 | 63 | 1 | 62 | 지킨다 |
| 완전 그래프 (V = 64) | 64 | 2,016 | 0 | 62 | 지킨다 |
| 삼각형 16 개를 이은 그래프 | 48 | 63 | 30 | 46 | 지킨다 |
| 무작위 (V = 64, E = 96) | 64 | 96 | 7 | 62 | 지킨다 |
| 간선이 없는 그래프 (V = 64) | 64 | 0 | 0 | 62 | 지킨다 |

여덟 줄 중 8 줄이 상한을 지키고, 상한과 같은 값이 나온 것은 사슬 (V = 8) · 사슬 (V = 64) 입니다.

<!--/proof-->

사슬은 잎이 양 끝 둘뿐이라 나머지가 전부 단절점이 되는 모양이에요. 마지막으로 비용 쪽 식을 닫습니다. 정점 `v`
의 다음에 읽을 자리는 0 에서 시작해 $\deg(v)$ 까지 하나씩만 올라가고, 다 쓰면 그 정점이 호출 스택에서 빠져
다시 들어오지 않아요. 정점 하나는 진입 한 번과 빼기 한 번을 정확히 겪습니다.

$$
\text{이웃 자리 읽기} = \sum_{v} \deg(v) = 2(E - L), \qquad \text{정점 만짐} = \underbrace{V}_{\text{진입}} + \underbrace{V}_{\text{빼기}} = 2V
$$

두 식에 규모를 넣어 실측과 나란히 놓았습니다. 간선 수를 정점 수와 같게 두려고 사이클을 썼어요.

<!--proof:mathScale-->

| 사이클의 정점 V | 간선 E | 이웃 자리 읽기 | 2(E − L) | 정점 만짐 | 2V |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 1,000 | 2,000 | 2,000 | 2,000 | 2,000 |
| 10,000 | 10,000 | 20,000 | 20,000 | 20,000 | 20,000 |
| 100,000 | 100,000 | 200,000 | 200,000 | 200,000 | 200,000 |

세 줄 모두 실측 열이 그 오른쪽 식의 값과 같습니다.

<!--/proof-->

상한이 아니라 등식이라는 것이 이 식이 주는 것입니다. 이웃 자리 읽기는 `2(E − L)`, 정점 만짐은 `2V` 로 정해지고,
어떤 그래프에서도 그보다 많아지지 않아요.

### 불변식 — 호출 스택은 뿌리에서 지금 정점까지의 나무 경로이고, 뺄 때의 low 는 서브트리 전체를 담는다

파트 1 의 열아홉 걸음은 그래프 하나에서 답이 나왔다는 기록입니다. 그 하나로는 다른 입력에서도 같은 일이 일어난다는
근거가 안 되므로, **`while` 의 조건을 검사하는 시점마다 참으로 남는 문장**을 세우고 그것이 유지되는지를 값으로
확인합니다.

> `while` 의 조건을 검사하는 시점마다 둘이 참입니다. **앞 문장** — `callV` 는 뿌리에서 지금 정점까지의 나무
> 경로이고, 그래서 발견 순서 오름차순입니다. **뒤 문장** — `callV` 에 담긴 정점 `v` 는 `low[v] ≤ disc[v]` 이고,
> `v` 를 빼는 시점의 `low[v]` 는 정의대로의 low 값, 곧 서브트리 전체에서 되돌아가는 간선 하나로 이르는 가장
> 이른 발견 순서입니다.

| 문장 | 참인 것 | 지키는 코드 |
| --- | --- | --- |
| 앞 문장 | 부모가 호출 스택에서 자식 바로 앞에 있다 | 넣기와 빼기가 모두 배열 끝에서만 일어난다 |
| 뒤 문장 | 부모 판정이 비교하는 두 값이 둘 다 확정된 값이다 | 이웃을 다 본 뒤에만 빼고, 뺄 때 부모에게 넘긴다 |

문장을 둘로 나눈 까닭이 있어요. 앞 문장은 **부모가 누구인지가 호출 스택의 자리로 정해진다**는 것을 주고, 뒤
문장은 **비교하는 `low[자식]` 이 서브트리를 다 본 값**이라는 것을 줍니다. 둘이 함께 있어야 판정 한 줄이 정의와
같은 답을 내요.

**첫 검사에 들어가기 전부터 봅시다.** 그 시점의 `callV` 에는 바깥 반복이 방금 들어간 정점 하나만 있고, 그 정점의
`low` 와 `disc` 에는 같은 수가 적혀 있어요. 정점 하나짜리 경로는 뿌리에서 뿌리까지의 경로이고, `low ≤ disc` 도
등호로 참입니다. 그 뒤로 상태를 바꾸는 갈래 여섯이 두 문장을 어떻게 지키는지 적었습니다.

| 갈래 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 진입 | 세 배열에 담고 두 수를 적는다 | 부모 바로 뒤에 담는다 | 두 수를 같은 값으로 적는다 |
| 내려간다 | 자식으로 진입한다 | 진입과 같다 | 진입과 같다 |
| 줄인다 | `low` 만 줄인다 | `callV` 를 안 건드린다 | 줄이기만 하므로 `low ≤ disc` 가 남는다 |
| 건너뛴다 | 아무것도 안 한다 | 안 건드린다 | 안 건드린다 |
| 뺀다 | 맨 뒤 하나를 빼고 부모에게 넘긴다 | 뒤에서 빼므로 남는 것도 경로다 | 서브트리를 다 본 값을 부모가 받는다 |
| 판정한다 | `cut` 만 적는다 | 안 건드린다 | 안 건드린다 |

「뺀다」 줄이 이 논증에서 가장 좁은 자리예요. 빼는 정점의 값이 정의대로의 값이려면, 그 정점의 이웃 자리를 다 읽었고
자식들이 모두 먼저 빠져 값을 넘겼어야 합니다. 이웃 자리를 다 쓴 뒤에만 빼고, 자식은 호출 스택에서 부모 뒤에

정점 번호로 거르므로 부모와 자식 사이의 겹친 간선은 둘 다 건너뜁니다. 정점을 지우면 겹친 간선이 몇 개든 함께
사라지니 답에는 영향이 없어요.

**이제 그 줄을 망가뜨려 봅시다.** 뒤 문장을 지키는 자리는 정점을 뺄 때 자기 `low` 를 부모에게 넘기는 한 줄입니다.
「판정에서 자식의 `low` 를 어차피 직접 읽는데 부모 칸까지 고쳐야 하나」라는 생각으로 그 한 줄만 지워 봅니다.

```ts
const parent = callP.pop() as number;
if (parent !== -1) {
  // low[parent] = Math.min(low[parent], low[v]) 가 있던 자리를 비웠다
  if (parent !== root && (low[v] as number) >= (disc[parent] as number)) {
    cut[parent] = true;
  }
}
```

#### 비용을 세는 과정

한 번 실행할 때 하는 일은 셋입니다. 이웃 목록을 만드는 것, 정점마다의 배열 셋을 만드는 것, 그리고 호출 스택이
빌 때까지 정점을 넣고 빼며 이웃 자리를 읽는 것이에요. 전개 입력의 걸음으로 보면 이웃 자리를 읽는 걸음은 T3 부터
T14 까지 가운데 진입 · 건너뜀 · 줄임 걸음입니다.

<!--proof:perfCount-->

| 걸음 | 하는 일 | 정점 또는 간선 | 이 걸음이 읽은 자리 | 누적 |
| --- | --- | --- | ---: | ---: |
| T2 | 진입 | 0 | 0 | 0 |
| T3 | 진입 | 0−1 | 1 | 1 |
| T4 | 건너뜀 | 1−0 | 1 | 2 |
| T5 | 진입 | 1−2 | 1 | 3 |
| T6 | 건너뜀 | 2−1 | 1 | 4 |
| T7 | 줄임 | 2−0 | 1 | 5 |
| T8 | 복귀 | 2 | 0 | 5 |
| T9 | 복귀 | 1 | 0 | 5 |
| T10 | 줄임 | 0−2 | 1 | 6 |
| T11 | 진입 | 0−3 | 1 | 7 |
| T12 | 건너뜀 | 3−0 | 1 | 8 |
| T13 | 진입 | 3−4 | 1 | 9 |
| T14 | 건너뜀 | 4−3 | 1 | 10 |
| T15 | 판정 | 4 | 0 | 10 |
| T16 | 복귀 | 3 | 0 | 10 |
| T17 | 복귀 | 0 | 0 | 10 |
| T18 | 뿌리 판정 | 0 | 0 | 10 |

이웃 목록을 만들 때 간선 5 개를 한 번씩 읽고, 순회하며 읽은 이웃 자리는 10 개로 2(E − L) = 10 과 같습니다. 진입 5 번과 빼기 5 번을 더한 정점 만짐은 10 번이고 2V 는 10 입니다.

<!--/proof-->

이웃 자리를 읽는 걸음이 열이고 자리 총수가 열입니다. **같은 자리를 두 번 읽는 걸음이 없어요.** T7 이 정점 2 의
자리 하나를, T10 이 정점 0 의 자리 하나를 한 번씩 읽습니다. 간선 `2−0` 은 두 끝에 자리가 하나씩 있어 두 번
읽히지만, 자리로 세면 각각 한 번이에요. 항목마다 식과 두 규모의 값을 적으면 이렇습니다.

<!--proof:perfTotal-->

| 항목 | 식 | 전개 입력 | 사이클 (V = E = 100,000) |
| --- | --- | ---: | ---: |
| 이웃 목록 만들기 | E | 5 | 100,000 |
| 정점마다의 배열 셋 | 3V | 15 | 300,000 |
| 이웃 자리 읽기 | 2(E − L) | 10 | 200,000 |
| 정점 만짐 | 2V | 10 | 200,000 |
| 답 모으기 | V | 5 | 100,000 |
| 합 | 6V + 3E − 2L | 45 | 900,000 |

두 열의 합은 식 6V + 3E − 2L 에 넣은 값 45 · 900,000 과 같습니다.

<!--/proof-->

**여기서 센 것은 간선 목록 읽기 · 배열 칸 만들기 · 이웃 자리 읽기 · 정점 만짐 · 답 모으기 전부입니다.** 배열 칸
하나를 읽거나 쓰는 횟수와 반복 변수를 올리는 횟수는 세지 않았어요. 둘 다 위 값에 비례하므로 총식의 차수가
그대로입니다. 총식은 `6V + 3E − 2L` 이에요. 메모리도 같은 기준으로 세면 정점마다의 칸 셋 `3V`, 이웃 목록
`2(E − L)` 칸, 호출 스택 많아야 `3V` 칸입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 서로 다른 축입니다. 「최악은 `O`, 평균은 `Θ`」처럼
한쪽을 다른 쪽에 짝지으면 안 돼요. 이 절차는 두 축의 표가 단순합니다. 케이스가 이웃 자리 읽기와 정점 만짐을
바꾸지 못하기 때문이에요.

| | 이웃 자리 읽기 · 정점 만짐 — 등식 | 호출 스택 최대 | 상한 `O` | 타이트 경계 `Θ` |
| --- | --- | --- | --- | --- |
| **한 줄로 깊게 뻗는 경우** (사슬 · 사이클) | `2(E − L)` · `2V` | `V` | `O(V + E)` | `Θ(V + E)` |
| **넓게 퍼지는 경우** (별) | `2(E − L)` · `2V` | `2` | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않는다) | `2(E − L)` · `2V` | 정의하지 않는다 | `O(V + E)` | `Θ(V + E)` |

**열의 종류가 다릅니다.** 등식 열은 이 편이 유도한 **값 자체**라 케이스를 안 탑니다. 호출 스택 최대만 케이스를
타는데 그것도 `V` 에서 닫혀요. 평균을 정의하지 않는 까닭은 입력 분포가 주어지지 않았기 때문이고, 이 절차에는
난수가 하나도 없어서 무작위성이 구현에서 나오지도 않습니다. 모양을 바꿔 가며 두 등식이 그대로인지 쟀어요.

<!--proof:perfObserved-->

| 입력 | V | E | L | 이웃 자리 읽기 | 2(E − L) | 정점 만짐 | 2V | 호출 스택 최대 | 단절점 개수 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 사슬 (V = 1,024) | 1,024 | 1,023 | 0 | 2,046 | 2,046 | 2,048 | 2,048 | 1,024 | 1,022 |
| 사이클 (V = 1,024) | 1,024 | 1,024 | 0 | 2,048 | 2,048 | 2,048 | 2,048 | 1,024 | 0 |
| 별 (V = 1,024) | 1,024 | 1,023 | 0 | 2,046 | 2,046 | 2,048 | 2,048 | 2 | 1 |
| 삼각형 341 개를 이은 그래프 | 1,023 | 1,363 | 0 | 2,726 | 2,726 | 2,046 | 2,046 | 1,023 | 680 |
| 완전 그래프 (V = 64) | 64 | 2,016 | 0 | 4,032 | 4,032 | 128 | 128 | 64 | 0 |
| 무작위 (V = 1,024, E = 2,048) | 1,024 | 2,048 | 2 | 4,092 | 4,092 | 2,048 | 2,048 | 642 | 83 |

여섯 줄 중 읽기가 2(E − L) 과 같은 줄이 6 줄, 정점 만짐이 2V 와 같은 줄이 6 줄입니다.

<!--/proof-->

**읽기 열과 `2(E − L)` 열이 줄마다 같습니다.** 간선이 2,016 개인 완전 그래프에서도, 1,023 개인 사슬에서도
그렇고, 무작위 그래프처럼 두 끝이 같은 간선이 섞여 있으면 그만큼 빠진 값과 같아요. 정점 만짐 열은 `2V` 에 고정돼
있습니다.

| 진술 | 종류 | 내용 |
| --- | --- | --- |
| 이웃 자리 읽기 = `2(E − L)` · 정점 만짐 = `2V` | 등식 — 최악 보장 | 어떤 그래프와 어떤 간선 순서에서도 이 값이다 |
| `Θ(V + E)` | 타이트 경계 | 전체가 그 차수로 자란다 |
| `O(V + E)` | 상한 | 전체가 그보다 크지 않다 |
| 호출 스택 최대 | 입력을 타는 값 | 별이면 2, 사슬이면 `V` |

**보장의 종류는 최악 보장입니다.** 기댓값이 아니에요. 등식 둘은 어떤 입력에서도 같고, 난수도 입력 분포에 기대는
진술도 없습니다.

#### 최악을 만드는 입력

「케이스별 비용과 그 경계」가 읽기와 정점 만짐을 등식으로 닫았으니, 최악을 만들 수 있는 축은 둘만 남습니다.
**호출 스택이 가장 깊어지는 것**과 **단절점이 가장 많아지는 것**이에요. 정점 수를 512 로 두고 모양만 일곱 가지로
바꿔 재 봅시다.

<!--proof:worstShape-->

| 모양 (V = 512) | 간선 E | 이웃 자리 읽기 | 정점 만짐 | 호출 스택 최대 | 단절점 개수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 간선 없음 | 0 | 0 | 1,024 | 1 | 0 |
| 사슬 | 511 | 1,022 | 1,024 | 512 | 510 |
| 사슬을 간선 목록에 거꾸로 적은 것 | 511 | 1,022 | 1,024 | 512 | 510 |
| 사이클 | 512 | 1,024 | 1,024 | 512 | 0 |
| 별 — 정점 하나에서 나머지 전부로 | 511 | 1,022 | 1,024 | 2 | 1 |
| 삼각형 170 개를 이은 것 + 홀로 있는 정점 둘 | 679 | 1,358 | 1,024 | 510 | 338 |
| 완전 그래프 | 130,816 | 261,632 | 1,024 | 512 | 0 |

일곱 모양의 정점 만짐은 모두 1,024 입니다.

<!--/proof-->

**「간선이 많으면 정점 만짐이 늘어난다」는 이 절차에서 성립하지 않습니다.** 일곱 모양의 간선 수가 0 에서
130,816 까지 갈리는데 정점 만짐은 모두 같아요. 이웃 자리 읽기는 간선 수의 두 배를 그대로 따라가고, 사슬을 간선
목록에 거꾸로 적어도 계수가 하나도 안 바뀝니다. 갈리는 두 축이 무엇에 달렸는지 적으면 이렇습니다.

| 축 | 정하는 것 | 일곱 모양에서 |
| --- | --- | --- |
| 호출 스택 최대 | 한 번에 몇 정점이 나무 경로 위에 놓이는가 | 별은 가운데에서 잎으로 내려갔다 바로 빠져 2, 사슬과 사이클은 끝까지 한 줄로 내려가 `V` |
| 단절점 개수 | 트리의 잎이 몇 개인가 | 사슬은 잎이 둘이라 `V − 2`, 사이클은 되돌아가는 간선 하나가 모든 부모 판정을 거짓으로 만들어 0 |

호출 스택이 가장 깊고 단절점도 가장 많은 사슬을 규모마다 재 보면 값이 어떻게 자라는지가 나옵니다.

<!--proof:worstGrowth-->

| 사슬의 정점 V | 읽기 + 만짐 | 직전 줄의 몇 배 | 호출 스택 최대 | 직전 줄의 몇 배 | 단절점 개수 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 64 | 254 | - | 64 | - | 62 |
| 256 | 1,022 | 4.02 | 256 | 4.00 | 254 |
| 1,024 | 4,094 | 4.01 | 1,024 | 4.00 | 1,022 |
| 4,096 | 16,382 | 4.00 | 4,096 | 4.00 | 4,094 |

네 줄 중 읽기 + 만짐이 4V − 2 와 같은 줄은 4 줄입니다.

<!--/proof-->

**정점 수를 네 배로 늘리면 세 열이 모두 네 배 언저리가 됩니다.** 읽기와 만짐의 합이 `4V − 2` 라 정확히 네 배가
아니라 조금 크고, 호출 스택 최대와 단절점 개수는 각각 `V` 와 `V − 2` 라 규모를 그대로 따라가요.

| 최악으로 만들 축 | 그 축을 최대로 만드는 입력 | 값 |
| --- | --- | --- |
| 호출 스택 최대 깊이 | 정점 `V` 개짜리 사슬 하나 또는 사이클 하나 | `V` |
| 단절점 개수 | 정점 `V` 개짜리 사슬 하나 | `V − 2` |
| 이웃 자리 읽기 | 어느 입력이든 같다 | 정확히 `2(E − L)` |
| 정점 만짐 | 어느 입력이든 같다 | 정확히 `2V` |

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하겠습니다. 깊이 우선 탐색을 한 번 하면서 정점마다 발견 순서와 low 값을 적고,
정점을 뺄 때 `low[자식] ≥ disc[부모]` 이면 뿌리가 아닌 부모를 단절점으로 적으며, 뿌리는 나무 자식이 둘 이상일
때만 적습니다. 답이 맞는 근거는 「호출 스택은 뿌리에서 지금 정점까지의 나무 경로이고, 뺄 때의 low 는 서브트리
전체를 담는다」이고, 연산 수는 이웃 자리 읽기 `2(E − L)` 번 · 정점 만짐 `2V` 번이에요.

| 순서 | 하는 일 | 규모 |
| ---: | --- | --- |
| 1 | 간선 목록을 두 끝의 목록에 담고 `disc` · `low` 를 `-1` 로 둔다 | `E` + `3V` |
| 2 | 안 들어간 정점마다 들어가서 두 수를 적고 호출 스택에 담는다 | 진입 `V` 번 |
| 3 | 이웃이 처음 보는 정점이면 내려가고, 부모면 건너뛰고, 그 밖이면 `low` 를 그 `disc` 까지 줄인다 | 이웃 자리 읽기 `2(E − L)` 번 |
| 4 | 이웃을 다 보면 부모에게 `low` 를 넘기고, 뿌리가 아닌 부모를 판정한다 | 빼기 `V` 번 |
| 5 | 뿌리는 나무 자식이 둘 이상일 때만 단절점이다 | 탐색마다 한 번 |

먼저 답이 붙는 문제 하나입니다. T15 에서 정점 4 를 빼며 정점 3 을 단절점으로 적었는데, 바로 뒤 T16 에서 정점 3 을
뺄 때는 부모인 뿌리 0 을 적지 않았어요. 두 걸음이 같은 줄을 실행하는데 왜 결과가 갈릴까요?

<!--proof:selfcheckT16-->

| 걸음 | 뺀 정점 | 부모 | 부모가 뿌리 | 맞대는 두 값 | 적은 것 |
| --- | --- | --- | --- | --- | --- |
| T15 | 4 | 3 | 아니오 | low[4] = 4 · disc[3] = 3 | cut[3] |
| T16 | 3 | 0 | 예 | low[3] = 3 · disc[0] = 0 | - |

<!--check:whyRootSkipped-->
`parent !== root` 가 **먼저** 거짓이 되기 때문입니다. T16 에서 정점 3 의 부모는 뿌리 0 이고, 그 자리에서는 뒤의
부등식을 아예 보지 않아요. 그리고 그것이 옳은 까닭은 뿌리의 발견 순서가 그 덩어리에서 가장 작아
`low[3] ≥ disc[0]` 이 언제나 참이기 때문입니다 — 조건이 아니라 자리 때문에 참이 되는 비교라, 그대로 두면 자식이
하나뿐인 뿌리까지 단절점이 돼요. 뿌리 0 이 단절점인 근거는 T18 의 나무 자식 수에서 따로 나옵니다.
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 오른쪽 열의 절을 다시 보세요.

| 문제 | 막히면 다시 볼 절 |
| --- | --- |
| 「최악을 만드는 입력」의 별은 호출 스택 최대가 2 였고 사슬은 512 였습니다. 호출 스택 최대가 정확히 `V/2` 가 되는 그래프를 하나 만들어 보고, 그 그래프의 단절점 개수가 사슬보다 많을지 적을지 먼저 예측한 다음 실제로 세어 보세요. | 「최악을 만드는 입력」 |
| 부모 건너뛰기를 뺀 판은 판정이 `≥` 라서 답이 안 갈렸습니다. 판정을 `>` 로 바꾼 판에서 부모 건너뛰기를 빼면 T14 에서 `low[4]` 가 얼마가 되고, 정점 3 의 판정이 어떻게 되는지 예측한 다음 실제로 세어 보세요. | 「수행으로 알아보는 알고리즘」의 둘째 짚고 가기 |
| 전개 입력의 블록-컷 나무에서 잎에 해당하는 블록을 찾고, 원래 그래프에 간선 하나를 그어 그 잎 둘을 한 블록으로 합치려면 어떤 간선을 넣어야 하는지 예측한 다음 실제로 세어 보세요. | 「알아 두면 좋은 개념」 |

### Articulation Points (단절점)

#### 한 줄 요약

> 함수는 정점 수 `n`과 무향 간선 목록을 받아, 제거 시 그래프가 분리되는 정점 번호 목록을 오름차순으로 반환한다.

#### 스토리

도시 간 도로망을 관리하는 팀이 있다. 어느 날 팀장은 "교통 인프라에서 하나의 교차로가 폐쇄됐을 때 일부 지역이 완전히 고립될 수 있다"는 보고를 받았다. 그런 교차로를 미리 파악해 두면 재난 대비 계획을 세울 수 있다.

팀은 도시의 도로망 지도를 들고 앉아 교차로마다 "이 교차로가 없어지면 어떻게 될까?"를 따져보기 시작했다. 어떤 교차로는 없어져도 우회로가 있어 모두 연결되지만, 어떤 교차로는 없어지는 순간 동네 전체가 뚝 끊겼다.

팀이 찾고 싶은 것은 바로 그런 '없어지면 연결이 끊기는' 교차로 목록이다.

#### 함수 인터페이스

```ts
export function articulationPoints(
  n: number,
  edges: [number, number][],
): number[];
```

- `n` — 정점 수. 정점 번호는 $0 \ldots n-1$
- `edges` — 무향 간선 목록. 각 원소 `[u, v]`는 정점 `u`와 `v` 사이의 무향 간선
- 반환 — 단절점 정점 번호를 오름차순으로 정렬한 배열. 단절점이 없으면 빈 배열

#### 제약 조건

- $1 \leq V \leq 10^{5}$ (여기서 $V = n$)
- $0 \leq E \leq 10^{5}$ (여기서 $E$는 `edges`의 길이)
- 무방향 그래프
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

무향 그래프에서 **단절점(articulation point, cut vertex)** 을 모두 찾는다.

정점 $v$가 단절점이라는 것은, $v$를 그래프에서 제거했을 때 연결 성분의 개수가 증가한다는 의미이다.

반환 형식은 단절점 정점 번호를 오름차순으로 정렬한 배열이다.

경계 동작:
- 정점이 1개이면 단절점은 없다.
- 간선이 없는 그래프는 단절점이 없다.
- 자기 루프 `[v, v]`는 단절점 판별에 영향을 주지 않는다.
- 그래프가 이미 분리되어 있어도 각 성분 내에서 단절점을 찾는다.

#### 예시

```ts
// 체인 그래프: 0 - 1 - 2
// 정점 1을 제거하면 {0}과 {2}로 분리 → 단절점
articulationPoints(3, [[0, 1], [1, 2]]); // [1]

// 두 사이클이 한 정점으로 연결
// {0,1,2} 사이클 + {2,3,4} 사이클, 2가 공유
// 정점 2를 제거하면 두 사이클이 분리 → 단절점
articulationPoints(5, [[0,1],[1,2],[2,0],[2,3],[3,4],[4,2]]); // [2]

// 삼각형 그래프: 0-1-2-0
// 어떤 정점을 제거해도 나머지 두 정점은 연결 유지
articulationPoints(3, [[0, 1], [1, 2], [2, 0]]); // []

// 간선 없는 그래프 — 어떤 정점을 제거해도 분리되지 않음
articulationPoints(5, []); // []

// V=1 — 단절점 없음
articulationPoints(1, []); // []
```
