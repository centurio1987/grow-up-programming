# 유향 사이클 탐지 — 지금 따라가는 경로 위의 정점으로 되돌아오는 간선이 사이클의 증거다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 경로를 전부 따라가
보는 방법에서 출발해, 정점마다 색 하나를 칠하는 삼색 표시까지 갑니다. 그 방법을 준비되는 차례대로 값으로 풀고,
마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**유향 그래프**는 정점들과 **방향이 있는 간선**으로 이루어집니다. 간선 `[u, v]` 는 `u → v` 를 뜻하고, `u` 에서
`v` 쪽으로만 갈 수 있어요. 패키지 의존 관계라면 「`u` 를 설치하려면 `v` 가 먼저 있어야 한다」가 간선 하나입니다.
이 글이 끝까지 쓰는 그래프는 정점 여섯 · 간선 여덟이에요.

<!--fig:concept-graph-->
![전개 입력 — 강조한 간선 3 개가 사이클 0 → 2 → 5 → 0](./figs/concept-graph.svg)

간선을 따라가다가 **출발한 정점으로 되돌아오는 경로**를 **사이클**이라고 부릅니다. 이 글이 답하는 것은 그런
경로가 하나라도 있는가 하나이고, 있으면 `true`, 없으면 `false` 를 돌려줍니다. 위 그래프에는 강조한 간선 셋이
이루는 사이클이 있어요. 같은 그래프의 세 걸음짜리 경로 둘을 나란히 놓으면 되돌아오는 것과 아닌 것이 갈립니다.

<!--proof:concept-paths-->

| 경로 | 끝 정점에서 나가는 간선 | 출발점으로 가는 간선 | 판정 |
| --- | --- | --- | --- |
| 0 → 2 → 5 | 1 개 | 있다 (5 → 0) | 사이클이다 |
| 0 → 2 → 3 → 4 | 0 개 | 없다 | 사이클이 아니다 |

둘째 경로도 간선을 세 번 따라갔지만, 정점 4 에서 나가는 간선이 하나도 없어서 0 으로 되돌아올 방법이 없습니다.
자기 자신을 가리키는 간선 `[v, v]` 는 길이 1 짜리 사이클이에요.

사이클을 찾는 방법의 핵심은 경로를 따라가다가 만난 정점이 **지금 따라가고 있는 그 경로 위에** 있는지, 아니면
**전에 확인을 끝낸 적이 있을 뿐인지**를 가르는 것입니다. 그래서 정점마다 색을 하나씩 칠해 둡니다. 이것을
**삼색 표시**라고 부릅니다. 한 갈래를 갈 수 있는 데까지 따라간 다음 되돌아 나오는 순회(깊이 우선 탐색)를 하면서,
아직 확인하지 않은 정점은 **흰색**, 지금 따라가는 경로 위의 정점은 **회색**, 나가는 간선을 전부 확인하고 끝난
정점은 **검은색**으로 둡니다. 탐색이 이 그래프에서 사이클을 찾는 순간의 삼색 표시를 그리면 이렇습니다.

<!--fig:concept-colors-->
![T12 — 회색 정점이 지금 경로이고, 간선 하나가 그 위로 되돌아온다](./figs/concept-colors.svg)

정점 안의 앞말이 색이고, 뒤의 두 수는 「지금까지 확인한 나가는 간선 / 나가는 간선 전부」입니다. 회색인 0 · 2 · 5
가 무대 아래 스택에 든 정점과 같고, 그 차례가 곧 지금 따라가는 경로 `0 → 2 → 5` 예요. 대시로 그린 간선 `5 → 0`
이 그 경로 위의 회색 정점 0 으로 되돌아가므로 사이클입니다. 검은색인 1 · 3 · 4 는 이미 끝난 정점이라, 그리로 가는
간선은 사이클의 증거가 되지 않아요. 할 일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 나가는 목록 만들기 | 간선 하나를 출발 정점의 목록에 한 번 넣는다 | 간선마다 한 번 |
| 색 칠하기 | 정점마다 흰색 → 회색 → 검은색으로 한 번씩 바꾼다 | 정점마다 두 번 |
| 간선 확인하기 | 간선마다 도착 정점의 색을 한 번 읽는다 | 간선마다 한 번 |
| 모두 | | `Θ(V + E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 정점과 간선으로 적는 방식.** 특히 **인접 리스트** — 정점마다 이웃 목록 하나를 두는 표현입니다.
  모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **깊이 우선 탐색이 무엇인가.** 한 갈래를 갈 수 있는 데까지 따라간 다음 되돌아 나와서 다음 갈래를 확인하는
  순회입니다. 이 글은 그 순회에 색을 덧붙인 것이라, 순회 자체가 흐릿하면 뒤가 어긋나요. 모르면
  [`dfsTraversal` 가이드](../dfsTraversal/dfsTraversal-guide.md)를 보세요.
- **스택이 나중에 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기 · 꺼내기가 각각 `O(1)` 입니다. 모르면
  [`stack` 가이드](../../../data-structures/linear/stack/stack-guide.mdx)를 보세요.
- **유향 그래프에서 들어오는 간선과 나가는 간선이 다르다는 것.** 간선 `[u, v]` 는 `u` 의 나가는 간선이면서
  동시에 `v` 의 들어오는 간선입니다. 이 글은 나가는 쪽만 자료로 만듭니다.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점이 지금 무슨 색인가」를 배열 한 칸을 읽어 판정합니다.

두 번째와 세 번째가 흐릿하면 뒤가 어긋납니다. 이 글은 깊이 우선 탐색을 재귀가 아니라 배열 둘(`stack` 과
`cursor`)로 적는데, 그 둘이 재귀의 무엇을 대신하는지 알고 있어야 왜 그렇게 적는지 읽혀요. 이름이 비슷한 과제와
나란히 놓으면 이 글의 범위가 갈립니다.

| 과제 | 그래프 | 이 글에서 |
| --- | --- | --- |
| 사이클이 하나라도 있는지 판정한다 | 방향 | 다룬다 |
| 사이클이 없을 때 정점을 순서대로 늘어놓는다 | 방향 | 다루지 않는다 — [`topologicalSort`](../topologicalSort/topologicalSort-guide.md) |
| 서로 오갈 수 있는 정점 묶음을 찾는다 | 방향 | 다루지 않는다 — [`stronglyConnectedComponents`](../stronglyConnectedComponents/stronglyConnectedComponents-guide.md) |
| 사이클이 하나라도 있는지 판정한다 | 무향 | 다루지 않는다 — [`undirectedCycleDetection`](../undirectedCycleDetection/undirectedCycleDetection-guide.md) |

### 아이디어를 떠올리는 과정 — 경로를 전부 따라가기에서 삼색 표시까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아서, 사이클이
있는지를 돌려줍니다.

```ts
function directedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean;
```

- 입력: 정점 수 `n`, 유향 간선 목록 `edges`. 정점 번호는 0 부터 `n − 1` 까지예요. 자기 자신을 가리키는 간선
  `[v, v]` 와 같은 간선의 중복이 들어올 수 있고, 그래프가 여러 조각으로 나뉘어 있을 수 있습니다.
- 출력: 어느 조각에라도 사이클이 하나 있으면 `true`, 하나도 없으면 `false`. 사이클을 찾아 출력하는 것이 아니라
  있는지만 답하므로, 사이클 하나를 확인하는 순간 나머지를 안 봐도 됩니다.
- 규모: 정점 수와 간선 수가 각각 100,000 이하입니다. 비용은 흔한 채점 환경의 예산인 1 초에 대어 잽니다.

이 글이 쓰는 기호는 여섯이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` 입니다 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 100,000` |
| `next[u]` | `u` 에서 나가는 간선의 도착 정점 목록 | 길이를 다 더하면 `E` |
| `color[v]` | 정점 `v` 의 삼색 표시 — 흰색 · 회색 · 검은색 | 처음에는 전부 흰색 |
| `cursor[u]` | `next[u]` 에서 다음에 확인할 자리 | 0 에서 시작해 목록 길이까지 |
| `stack` | 지금 따라가는 경로 위의 정점들 | 아래에서 위로 경로의 차례 |

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. **정점 하나를 잡고 갈 수 있는 경로를 전부 따라가
보면서**, 지금 따라온 경로에 있는 정점을 다시 만나면 사이클이라고 판정해요. 경로 위의 정점에만 표시를 두고,
되돌아 나올 때 표시를 지웁니다.

```ts
const onPath: boolean[] = Array.from({ length: n }, () => false);
function go(u: number): void {
  onPath[u] = true;
  for (const v of next[u]) {
    if (onPath[v]) found = true; // 지금 경로 위에 있다 — 사이클이다
    else go(v);
  }
  onPath[u] = false; // 되돌아 나오면서 표시를 지운다
}
```

이 방법은 답이 맞습니다. 그런데 표시를 지우기 때문에, 같은 정점을 다른 경로로 다시 만나면 그 아래를 **처음부터
다시** 따라가요. 갈래가 갈렸다가 다시 만나는 가장 작은 모양(다이아몬드)을 둘 이으면, 끝 정점까지 가는 경로가
다이아몬드마다 두 배로 늘어납니다.

<!--fig:origin-diamonds-->
![다이아몬드 둘을 이은 그래프 — 정점 안의 수는 정점 0 에서 오는 경로의 수](./figs/origin-diamonds.svg)

이 방법의 비용은 **따라간 간선 수**로 셉니다. 다이아몬드를 `k` 개 이을 때 사이클이 없는 그래프를 끝까지 확인하며
세어 보면 이렇습니다.

<!--proof:naive-scale-->

| 다이아몬드 k | 정점 V | 간선 E | 경로 수 2^k | 따라간 간선 수 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 4 | 4 | 2 | 6 |
| 2 | 7 | 8 | 4 | 28 |
| 4 | 13 | 16 | 16 | 200 |
| 8 | 25 | 32 | 256 | 4,000 |
| 12 | 37 | 48 | 4,096 | 65,400 |
| 16 | 49 | 64 | 65,536 | 1,048,400 |

규모 안에서 k 는 25,000 까지 늘릴 수 있고(정점 75,001 · 간선 100,000), 그때 경로 수 2^k 는 7,526 자리 수입니다.

<!--/proof-->

정점 49 개짜리 그래프에서 이미 간선을 백만 번 넘게 따라갑니다. 규모 상한에서는 경로의 수를 적는 것조차 7,526
자리예요. 느린 까닭은 하나입니다 — **같은 정점 아래를 경로마다 다시 따라가는데, 두 번째에 나오는 답이 첫 번째와
똑같다**는 것. 그 아래의 그래프가 그대로이니까요. 그러면 「끝난 정점」에 표시를 남겨 두고 다시 내려가지 않으면
됩니다.

가장 단순한 후보부터 시험합시다. **표시를 하나로 두고 지우지 않는** 방법이에요. 한 번 본 정점에 「본 적 있음」을
남기고, 본 적 있는 정점을 다시 만나면 사이클이라고 판정합니다. 이 후보가 걸리는 자리는 갈래가 합쳐지는 곳입니다.
마름모 `0 → 1 → 3`, `0 → 2 → 3` 에서 정점 3 을 두 번 만나는 순간을 보면 이렇습니다.

<!--proof:diamond-meet-->

| 걸음 | 확인한 간선 | 그 순간의 경로 정점 | 지금 경로에 3 | 본 적 있는 정점에 3 |
| --- | --- | --- | --- | --- |
| T3 | 1 → 3 | [0, 1] | 없다 | 없다 |
| T7 | 2 → 3 | [0, 2] | 없다 | 있다 |

두 번째 만남(`2 → 3`)에서 정점 3 은 「본 적 있는 정점」이지만 **지금 경로 위에는 없습니다.** 되돌아온 것이 아니라
갈래 둘이 합쳐진 것이에요. 「본 적 있음」 하나로는 그 둘을 가를 수 없으니 이 후보는 사이클이 없는 마름모에
`true` 를 답합니다. 표시 하나가 두 가지 일 — 「지금 경로 위에 있다」와 「이미 끝났다」 — 을 한꺼번에 하고 있었던
거예요. 그러면 두 표시를 가르면 됩니다. 세 방법을 같은 입력에 실행해 따라간 간선 수와 답을 나란히 놓았습니다.

<!--proof:origin-compare-->

| 입력 | 간선 E | 경로에만 표시 — 따라간 간선 · 답 | 본 적 있음 하나 — 따라간 간선 · 답 | 두 표시를 가른다 — 확인한 간선 · 답 |
| --- | ---: | --- | --- | --- |
| 전개가 쓰는 여섯 정점 | 8 | 9 · true | 4 · true | 8 · true |
| 마름모 네 정점 | 4 | 6 · false | 4 · true | 4 · false |
| 가로지르는 간선 0→1 · 0→2 · 1→2 | 3 | 4 · false | 3 · true | 3 · false |
| 다이아몬드 16 개 | 64 | 1,048,400 · false | 34 · true | 64 · false |
| 사슬 1,000 | 999 | 499,500 · false | 999 · false | 999 · false |

정본의 답은 모든 줄에서 두 표시를 가른 방법의 답과 같습니다. 「본 적 있음」 하나로 표시한 방법은 3 개 입력(마름모 네 정점, 가로지르는 간선 0→1 · 0→2 · 1→2, 다이아몬드 16 개)에서 답이 정본과 다릅니다.

<!--/proof-->

두 표시를 가른 방법은 답이 정본과 늘 같고, 따라간 간선이 간선 수와 같습니다. 다이아몬드 16 개에서 1,048,400 이
64 가 됐어요. 「본 적 있음」 하나는 간선 수 이하로 빠르지만 사이클이 없는 그래프 셋에 `true` 를 답합니다.
지금까지 해 본 방법을 차례로 놓으면 이렇습니다. 앞 방법이 막힌 자리에서 다음 방법이 나왔어요.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **삼색 표시**입니다. 아직 안 본 정점은 흰색, 지금 경로 위의 정점은 회색, 끝난 정점은
검은색으로 두고, **회색 정점으로 가는 간선만** 사이클로 판정해요. 세 색이 한 순간에 어떻게 놓이는지, 누가 언제 색을
바꾸는지, 왜 회색 정점의 모임이 늘 지금 경로와 같은지는 다음 절에서 실현하는 순서대로 확인합니다.

> 회색 정점으로 가는 간선만 사이클이다. 검은색 정점으로 가는 간선은 합쳐진 것일 뿐이다.

### 아이디어 상세 — 삼색 표시

이 아이디어를 한 문장으로 줄이면 이렇습니다. **깊이 우선 탐색을 하면서 경로에 넣는 정점을 회색으로, 나가는
간선을 다 확인해 경로에서 뺀 정점을 검은색으로 칠하고, 도착 정점이 회색인 간선을 만나는 순간 사이클이라고
답합니다.** 세 색이 무엇을 뜻하고 서로 어떻게 이어지는지가 처음 보는 사람에게는 낯설어요. 그래서 삼색 표시를
먼저 따로 설명하고, 그다음 실현하는 순서대로 다섯 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는
순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 나가는 목록 만들기 | 간선 목록을 정점마다의 `next` 로 옮긴다 | — |
| 정점에 들어갈 때마다 | 2단계 회색으로 칠해 스택에 넣기 | 흰색 정점을 회색으로 칠하고 스택 위에 올린다 | 1단계의 `next` 를 가리킬 `cursor` |
| 간선마다 | 3단계 도착 정점의 색으로 가르기 | 꼭대기의 다음 간선 하나를 확인해 셋 중 하나를 한다 | 1단계의 `next` · 2단계의 스택과 `cursor` |
| 정점을 끝낼 때마다 | 4단계 검은색으로 칠해 빼기 | 목록을 다 본 꼭대기를 검은색으로 칠하고 뺀다 | 3단계가 끝까지 올린 `cursor` |
| 스택이 빌 때마다 | 5단계 흰색 정점에서 다시 시작하기 | 남은 흰색 정점을 찾아 2단계부터 되풀이한다 | 4단계까지 칠한 `color` |

#### 먼저 알아 둘 개념 — 삼색 표시

삼색 표시는 **깊이 우선 탐색이 진행되는 동안 정점마다 붙여 두는 세 상태 중 하나**입니다. 흰색은 「아직 한 번도 확인하지
않았다」, 회색은 「지금 따라가는 경로 위에 있다」, 검은색은 「나가는 간선을 전부 확인하고 끝났다」예요. 코드에서는
`color[v]` 한 칸에 0 · 1 · 2 로 적고, 이름은 `WHITE` · `GRAY` · `BLACK` 입니다. 색은 흰색 → 회색 → 검은색 차례로만
바뀌고 되돌아가지 않습니다.

##### 입력 위의 삼색 표시

전개 입력에서 세 색이 한꺼번에 있는 순간을 골라 그렸습니다. 정점 안의 앞말이 색이고, 뒤의 두 수는 「확인한
나가는 간선 / 나가는 간선 전부」예요. 흰색 정점은 점선 테, 아직 확인하지 않은 간선은 흐린 선입니다.

<!--fig:build-colors-->
![T10 직후 — 흰색 · 회색 · 검은색이 다 있는 순간](./figs/build-colors.svg)

회색인 0 과 2 가 무대 아래 스택에 들어 있고, 스택을 아래에서 위로 읽은 `0 → 2` 가 지금 따라가는 경로입니다. 검은색인
1 · 3 · 4 는 이미 끝났고, 흰색인 5 는 아직 아무도 들르지 않았어요. 이 순간 확인한 간선 `2 → 3` 은 검은색 정점
3 으로 가므로 사이클이 아닙니다.

##### 정점 하나를 읽는 법

같은 순간의 정점을 하나씩 읽습니다. 색에서 출발해 언제 그 색이 됐는지, 목록을 어디까지 확인했는지, 그래서 무엇을
뜻하는지까지 따라가요.

<!--proof:colors-read-->

| 정점 | 색 | 칠한 걸음 | cursor / 목록 길이 | 뜻 |
| --- | --- | --- | --- | --- |
| 0 | 회색 | 회색 T1 | 3 / 3 | 지금 경로의 1 번째 정점이다 |
| 1 | 검은색 | 회색 T2 · 검은색 T7 | 1 / 1 | 나가는 간선을 다 확인하고 끝났다 |
| 2 | 회색 | 회색 T9 | 1 / 2 | 지금 경로의 2 번째 정점이다 |
| 3 | 검은색 | 회색 T3 · 검은색 T6 | 1 / 1 | 나가는 간선을 다 확인하고 끝났다 |
| 4 | 검은색 | 회색 T4 · 검은색 T5 | 0 / 0 | 나가는 간선을 다 확인하고 끝났다 |
| 5 | 흰색 | — | 0 / 1 | 아직 한 번도 확인하지 않았다 |

T10 직후의 스택은 [0, 2] 입니다.

<!--/proof-->

정점 2 를 골라 읽어 보겠습니다. T9 에 회색이 됐고 아직 검은색이 된 적이 없으니 지금 경로 위에 있고, 스택에서
두 번째라 경로 `0 → 2` 의 끝입니다. `cursor / 목록 길이` 가 `1 / 2` 이니 나가는 간선 둘 중 `2 → 3` 하나를 확인했고
`2 → 5` 가 남았어요. 정점 4 는 목록이 비어 있어 `0 / 0` 인 채로 검은색이 됐습니다. 검은색은 「목록을 다 봤다」는
뜻이지 「간선을 몇 개 봤다」는 뜻이 아닙니다.

##### 색끼리의 관계

세 색은 서로 아무렇게나 놓이지 않습니다. 회색 정점끼리는 스택의 차례대로 간선으로 이어져 경로 하나를 이루고,
검은색 정점에서 나가는 간선은 흰색 정점으로 가지 않아요 — 검은색이 되려면 나가는 간선을 다 확인해야 하고, 흰색
정점을 만나면 그리로 내려가 그 정점부터 끝내기 때문입니다. 전개 입력의 걸음마다 세 관계를 쟀습니다.

<!--proof:colors-relation-->

| 관계 | 확인한 걸음 | 어긋난 걸음 |
| --- | ---: | ---: |
| 회색인 정점의 모임이 스택의 정점 모임과 같다 | 12 | 0 |
| 스택에서 이웃한 두 정점 사이에 간선이 있다 | 12 | 0 |
| 검은색 정점에서 흰색 정점으로 가는 간선이 없다 | 12 | 0 |

T1 부터 T12 까지 12 걸음마다 세 관계를 쟀고, 어긋난 자리는 0 개입니다.

<!--/proof-->

첫째 관계가 이 글의 요점입니다. 회색 정점의 모임이 스택과 같으니, 「이 정점이 회색인가」를 묻는 것이 「이 정점이
지금 경로 위에 있는가」를 배열 한 칸으로 묻는 것이 돼요. 둘째 관계 때문에 그 경로는 실제로 간선을 따라 이어진
경로이고, 셋째 관계 때문에 검은색 정점 아래에는 더 확인할 것이 남아 있지 않습니다.

##### 「본 적 있음」과의 차이

삼색 표시를 처음 보면 회색과 검은색을 합쳐 「본 적 있음」 하나로 읽기 쉽습니다. 두 색 다 흰색이 아니니까요. 마름모의
걸음마다 두 모임을 나란히 놓았습니다.

<!--proof:colors-vs-seen-->

| 걸음 | 한 일 | 본 적 있는 정점 | 회색 정점 |
| --- | --- | --- | --- |
| T1 | 0 에서 시작 | [0] | [0] |
| T2 | 0 → 1 · 흰색 · ② 내려간다 | [0, 1] | [0, 1] |
| T3 | 1 → 3 · 흰색 · ② 내려간다 | [0, 1, 3] | [0, 1, 3] |
| T4 | 3 을 뺀다 | [0, 1, 3] | [0, 1] |
| T5 | 1 을 뺀다 | [0, 1, 3] | [0] |
| T6 | 0 → 2 · 흰색 · ② 내려간다 | [0, 1, 2, 3] | [0, 2] |
| T7 | 2 → 3 · 검은색 · ③ 넘어간다 | [0, 1, 2, 3] | [0, 2] |
| T8 | 2 를 뺀다 | [0, 1, 2, 3] | [0] |
| T9 | 0 을 뺀다 | [0, 1, 2, 3] | [] |

9 걸음 가운데 두 모임이 다른 걸음은 6 개입니다. 반환값은 false 입니다.

<!--/proof-->

T7 이 두 읽기가 갈리는 자리입니다. 간선 `2 → 3` 을 확인할 때 정점 3 은 「본 적 있는 정점」에 들어 있지만 회색 정점에는
없어요. 「본 적 있음」으로 읽으면 사이클이고, 회색으로 읽으면 이미 끝난 정점으로 합쳐진 것입니다. 마름모에는
사이클이 없으니 회색으로 읽는 쪽이 맞습니다.

##### 이렇게 생긴 까닭

사이클을 판정하려면 「지금 경로 위에 있는가」를 알아야 하고, 비용을 간선 수로 묶으려면 「이미 끝났는가」를 알아야
합니다. 거기에 「아직 안 들렀는가」가 있어야 내려갈 정점을 고를 수 있어요. 세 물음이 서로 다른 답을 요구하니 색도
셋입니다. 정점이 경로에 들어가는 순간과 경로에서 나오는 순간이 정점마다 한 번씩뿐이라, 색이 바뀌는 횟수도 정점마다
두 번으로 정해져요.

| 물음 | 답하는 색 | 없으면 |
| --- | --- | --- |
| 이 정점으로 내려가야 하는가 | 흰색 | 끝난 정점 아래를 다시 따라간다 |
| 이 간선이 사이클을 닫는가 | 회색 | 합쳐진 갈래를 사이클로 읽는다 |
| 이 정점 아래를 다시 볼 필요가 있는가 | 검은색 | 끝난 정점을 회색으로 남겨 되돌아온 것으로 읽는다 |

#### 1단계 — 나가는 목록 만들기

간선 목록은 「누가 누구를 가리키는가」를 담고 있지만, 「정점 0 에서 나가는 간선이 무엇인가」에 답하려면 목록 전체를
다시 읽어야 합니다. 간선을 한 번 읽으면서 출발 정점별로 도착 정점을 모아 `next` 를 만들어요. 전개 입력에서는
이렇게 나옵니다.

<!--proof:build-next-->

| 정점 u | next[u] | 길이 |
| ---: | --- | ---: |
| 0 | [1, 4, 2] | 3 |
| 1 | [3] | 1 |
| 2 | [3, 5] | 2 |
| 3 | [4] | 1 |
| 4 | [] | 0 |
| 5 | [0] | 1 |

길이를 모두 더하면 8 이고, 간선 수 8 과 같습니다.

<!--/proof-->

간선 목록에 적힌 차례가 그대로 목록 안의 차례가 됩니다. `next[0]` 이 `[1, 4, 2]` 인 것은 `[0,1]` · `[0,4]` · `[0,2]`
가 그 차례로 적혀 있어서예요. 이 목록은 여기서 한 번 만들고 뒤에서는 읽기만 합니다.

#### 2단계 — 회색으로 칠해 스택에 넣기

정점에 들어갈 때는 흰색을 회색으로 바꾸고, 그 정점을 스택 위에 올립니다. 두 일을 **같은 자리에서 함께** 하므로
회색 정점의 모임과 스택이 어긋날 틈이 없어요. 정점마다 `cursor` 칸도 하나 있는데, `next[u]` 에서 다음에 확인할
자리를 가리킵니다. 재귀로 적었다면 「돌아온 지점」이 하던 일이에요. 전개 입력에서 정점에 들어간 걸음을 모았습니다.

<!--proof:build-descend-->

| 걸음 | 내려간 자리 | 회색으로 칠한 정점 | 스택(아래 → 위) | cursor |
| --- | --- | --- | --- | --- |
| T1 | 바깥 반복 s = 0 | 0 | [0] | [0, 0, 0, 0, 0, 0] |
| T2 | 0 → 1 | 1 | [0, 1] | [1, 0, 0, 0, 0, 0] |
| T3 | 1 → 3 | 3 | [0, 1, 3] | [1, 1, 0, 0, 0, 0] |
| T4 | 3 → 4 | 4 | [0, 1, 3, 4] | [1, 1, 0, 1, 0, 0] |
| T9 | 0 → 2 | 2 | [0, 2] | [3, 1, 0, 1, 0, 0] |
| T11 | 2 → 5 | 5 | [0, 2, 5] | [3, 1, 2, 1, 0, 0] |

정점은 여섯 번 들어갔고, 매번 흰색이던 정점입니다. 들어가는 자리는 둘이에요 — 바깥 반복이 흰색 정점을 잡을 때
(T1)와, 꼭대기에서 확인한 간선의 도착 정점이 흰색일 때(나머지)입니다. T9 에서 스택이 `[0, 2]` 로 짧아진 것은
그 사이 1 · 3 · 4 가 끝나서 빠졌기 때문이에요.

#### 3단계 — 도착 정점의 색으로 가르기

여기가 판정이 일어나는 자리입니다. 스택 꼭대기 정점 `u` 를 꺼내지 않고 **보기만** 하고, `next[u]` 에서 `cursor[u]`
가 가리키는 간선 하나를 확인해요. `cursor[u]` 를 하나 올린 뒤 도착 정점 `v` 의 색에 따라 셋 중 하나를 합니다.
회색이면 사이클이라 `true` 를 돌려주고, 흰색이면 2단계로 내려가며, 검은색이면 아무것도 하지 않아요.

<!--proof:build-branches-->

| 걸음 | 확인한 간선 | 도착 정점의 색 | 갈래 |
| --- | --- | --- | --- |
| T2 | 0 → 1 | 흰색 | ② 내려간다 |
| T3 | 1 → 3 | 흰색 | ② 내려간다 |
| T4 | 3 → 4 | 흰색 | ② 내려간다 |
| T8 | 0 → 4 | 검은색 | ③ 넘어간다 |
| T9 | 0 → 2 | 흰색 | ② 내려간다 |
| T10 | 2 → 3 | 검은색 | ③ 넘어간다 |
| T11 | 2 → 5 | 흰색 | ② 내려간다 |
| T12 | 5 → 0 | 회색 | ① 사이클이다 |

간선을 확인한 걸음은 8 개이고, 흰색이라 내려간 것이 5 번, 검은색이라 넘어간 것이 2 번, 회색이라 사이클로 판정한 것이 1 번입니다.

<!--/proof-->

쉬운 경우는 도착 정점이 흰색인 간선입니다. 처음 보는 정점이니 내려가면 되고, 다섯 번이 그랬어요. 불안한 경우는
**같은 정점을 두 번째로 만나는** 간선입니다. 정점 3 이 그 자리예요. T3 에 `1 → 3` 으로 처음 만났을 때는 흰색이라
내려갔고, T10 에 `2 → 3` 으로 다시 만났을 때는 T6 에 이미 끝나 검은색이라 넘어갔습니다. 정점 4 도 T4 에
`3 → 4` 로 내려간 뒤 T8 에 `0 → 4` 로 다시 만나 넘어갔어요. 두 번째 만남이 사이클로 읽히지 않는 것은 그 정점이
검은색이기 때문이고, 검은색인 것은 4단계가 먼저 끝냈기 때문입니다.

#### 4단계 — 검은색으로 칠해 빼기

꼭대기 정점의 `cursor` 가 목록 길이와 같아지면 나가는 간선을 다 확인한 것입니다. 그 정점을 검은색으로 칠하고
스택에서 빼요. 이것도 두 일을 같은 자리에서 함께 하므로 회색 정점의 모임과 스택이 계속 같습니다.

<!--proof:build-finish-->

| 걸음 | 검은색으로 칠한 정점 | cursor / 목록 길이 | 뺀 뒤의 스택 |
| --- | --- | --- | --- |
| T5 | 4 | 0 / 0 | [0, 1, 3] |
| T6 | 3 | 1 / 1 | [0, 1] |
| T7 | 1 | 1 / 1 | [0] |

정점 4 는 목록이 비어 있어 들어가자마자 다음 걸음에 빠졌고, 3 과 1 은 목록 하나씩을 다 본 뒤 빠졌습니다. 빠질 때마다
스택 꼭대기가 한 칸 아래 정점으로 돌아가, 그 정점의 `cursor` 가 가리키는 다음 간선부터 이어서 확인해요.

반복이 끝나는 까닭은 코드의 종료 조건으로 말할 수 있습니다. 정점 하나는 흰색일 때만 스택에 들어가고 빠질 때
검은색이 되므로, 스택에 들어가는 총수가 `V` 를 넘지 않아요. 간선 하나는 `cursor` 가 그 자리를 지나가는 한 번만
확인되므로 확인 총수가 `E` 를 넘지 않습니다. 반복 한 바퀴는 간선 하나를 확인하거나 정점 하나를 빼므로, 반복은 많아야
`V + E` 바퀴 뒤에 스택이 비어 끝납니다.

#### 5단계 — 흰색 정점에서 다시 시작하기

스택이 비었다고 그래프를 다 본 것은 아닙니다. 유향 그래프에는 시작 정점에서 간선을 따라 갈 수 없는 정점이 있을
수 있어요. 그래서 바깥 반복이 정점 0 부터 차례로 보며 아직 흰색인 정점을 찾아 2단계부터 다시 합니다. 조각이 둘인
입력에서 바깥 반복이 한 일을 적었습니다.

<!--proof:build-restart-->

| 바깥 반복 | 그때의 색 | 한 일 |
| --- | --- | --- |
| s = 0 | 흰색 | 회색으로 칠해 시작한다 — T4 에 스택이 빈다 |
| s = 1 | 검은색 | 넘어간다 |
| s = 2 | 흰색 | 회색으로 칠해 시작한다 — T8 에 4 → 2 가 회색을 만난다 |

간선 목록은 [[0,1],[2,3],[3,4],[4,2]] 이고, 반환값은 true 입니다.

<!--/proof-->

`s = 0` 에서 시작한 탐색은 정점 0 · 1 만 보고 끝납니다. `s = 1` 은 이미 검은색이라 넘어가고, `s = 2` 가 흰색이라 다시
시작해 사이클 `2 → 3 → 4 → 2` 를 찾아요. 흰색 정점이 하나도 안 남을 때까지 이렇게 되풀이하고, 끝까지 회색을 만나지
못하면 `false` 입니다.

#### 이 방법이 기대는 전제

이 방법은 **간선에 방향이 있다**는 전제에 기댑니다. 회색 정점으로 가는 간선이 곧 사이클인 것은, 그 간선이 경로를
거슬러 올라가는 새 간선이기 때문이에요. 간선에 방향이 없는 그래프를 두 방향 간선으로 적어 넣으면 이 전제가
깨집니다. 방금 내려온 간선을 반대로 읽기만 해도 부모 정점이 회색이니까요.

<!--proof:premise-undirected-->

| 무향 그래프 | 두 방향으로 적은 간선 목록 | 정본의 답 | 무향 사이클 |
| --- | --- | --- | --- |
| 간선 하나 0-1 | [[0,1],[1,0]] | true | 없다 |
| 경로 0-1-2 | [[0,1],[1,0],[1,2],[2,1]] | true | 없다 |
| 삼각형 0-1-2-0 | [[0,1],[1,0],[1,2],[2,1],[2,0],[0,2]] | true | 있다 |

입력 3 개 가운데 정본의 답이 무향 사이클의 유무와 어긋나는 입력은 2 개입니다.

<!--/proof-->

간선 하나짜리 그래프에도 `true` 가 나옵니다. `0 → 1` 로 내려간 뒤 `1 → 0` 을 확인하면 0 이 회색이기 때문이에요.
무향 그래프에서는 「방금 온 간선」을 따로 기억해 빼야 하고, 그 판정은
[`undirectedCycleDetection` 가이드](../undirectedCycleDetection/undirectedCycleDetection-guide.md)가 다룹니다.

#### 스택 배열과 cursor 로 경로를 드는 까닭

깊이 우선 탐색은 재귀로 적는 쪽이 짧습니다. 「회색으로 칠하고, 이웃마다 회색이면 사이클, 흰색이면 자기 자신을
부르고, 끝나면 검은색으로 칠한다」면 끝나요. 그런데 재귀로 적으면 지금 경로의 길이가 그대로 **호출 깊이**가 되고,
호출 깊이는 실행 환경이 잡아 둔 한도를 받습니다. 가장 깊어지는 사슬에서 두 방식을 실행했습니다.

<!--proof:design-recursion-->

| 사슬 길이 | 재귀로 적은 사본 | 스택 배열(정본) |
| ---: | --- | --- |
| 1,000 | false | false |
| 100,000 | RangeError 로 멈춘다 | false |

길이 1,000 에서는 둘이 같은 답을 내는데 100,000 에서 갈립니다. 규모가 정점 10 만 개까지이니 이 입력은 실제로
들어올 수 있어요. 호출 한도가 정확히 몇인지는 실행 환경이 정하고 이 두 줄 사이 어딘가에 있습니다. 스택 배열로
경로를 들면 깊이는 배열 길이가 되고, 재귀가 「돌아온 지점」으로 기억하던 다음 간선의 자리는 `cursor` 배열이
기억합니다.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 이렇습니다. 3 번부터 5 번까지가 반복 한 바퀴예요. 이렇게 하면 다이아몬드
16 개에서 1,048,400 번이던 간선 따라가기가 간선 수 64 번이 됩니다.

1. 간선 목록을 나가는 목록 `next` 로 옮기고, `color` 를 전부 흰색으로, `cursor` 를 전부 0 으로 둔다
2. 바깥 반복이 정점 `s` 를 0 부터 차례로 보며, 흰색이면 회색으로 칠하고 스택에 넣는다
3. 스택이 비지 않은 동안 꼭대기 `u` 를 보고, `cursor[u]` 가 목록 길이와 같으면 검은색으로 칠해 뺀다
4. 아니면 `next[u][cursor[u]]` 를 읽고 `cursor[u]` 를 올린 뒤, 도착 정점이 회색이면 `true` 를 돌려주고 흰색이면 회색으로 칠해 스택에 넣고 검은색이면 넘어간다
5. 바깥 반복이 끝날 때까지 회색을 만나지 못하면 `false` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 간선 여덟 개를 차례로 확인한다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 6;
const edges: [number, number][] = [[0, 1], [1, 3], [3, 4], [0, 4], [0, 2], [2, 3], [2, 5], [5, 0]];
// 이 절이 끝나면 true 가 나와야 한다
```

이 입력을 고른 까닭은 간선 여덟 개가 **네 갈래를 모두 실행하기 때문**입니다. 흰색으로 내려가는 갈래와 목록을 다 봐서
검은색으로 칠하는 갈래가 여러 번 나오고, 검은색이라 넘어가는 갈래가 두 번(`0 → 4` 와 `2 → 3`), 마지막 간선 `5 → 0`
에서 회색을 만나는 갈래가 한 번 나와요. 절차 전체를 한 장으로 적으면 이렇습니다.

```text
directedCycleDetection(n, edges):
    간선 [u, v] 마다 next[u] 에 v 를 넣는다
    color 를 전부 흰색으로, cursor 를 전부 0 으로 둔다
    정점 s 를 0 부터 n-1 까지 보면서:
        s 가 흰색이 아니면 넘어간다
        s 를 회색으로 칠하고 stack 에 넣는다
        stack 이 비지 않은 동안:
            u ← stack 의 꼭대기
            cursor[u] 가 next[u] 의 길이와 같으면:
                u 를 검은색으로 칠하고 stack 에서 뺀다              ④ 목록을 다 확인했다
            아니면:
                v ← next[u][cursor[u]] 를 읽고 cursor[u] 를 하나 올린다
                v 가 회색이면 true 를 반환한다                      ① 되돌아왔다
                v 가 흰색이면 회색으로 칠하고 stack 에 넣는다       ② 내려간다
                v 가 검은색이면 아무것도 하지 않는다                ③ 넘어간다
    false 를 반환한다
```

#### 1. 간선 목록을 나가는 목록으로 옮기고 색을 준비한다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 정점마다 빈 목록을 만들어 두고, 간선을 한 번 읽으면서 출발 정점의 목록
뒤에 도착 정점을 넣어요. 색 · `cursor` · 스택도 여기서 준비합니다.

```ts
const next: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) (next[u] as number[]).push(v);

const color: number[] = Array.from({ length: n }, () => WHITE);
const cursor: number[] = Array.from({ length: n }, () => 0);
const stack: number[] = [];
```

전개 입력에 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walk-next-->

```text
next[0] = [1, 4, 2]           0 → 1 · 0 → 4 · 0 → 2
next[1] = [3]                 1 → 3
next[2] = [3, 5]              2 → 3 · 2 → 5
next[3] = [4]                 3 → 4
next[4] = []                  나가는 간선이 없다
next[5] = [0]                 5 → 0

color = [0, 0, 0, 0, 0, 0]    전부 흰색
cursor = [0, 0, 0, 0, 0, 0]   아직 확인한 간선이 없다
stack = []                    비어 있다
```

#### 2. 스택 꼭대기의 간선을 하나씩 확인한다

「아이디어 상세」의 3단계와 4단계, 판정이 일어나는 자리입니다. 스택 꼭대기를 꺼내지 않고 보기만 하고, 목록을 다
봤으면 검은색으로 칠해 빼고, 아니면 `cursor` 가 가리키는 간선 하나를 확인해요.

```ts
while (stack.length > 0) {
  const u = stack[stack.length - 1] as number;
  const list = next[u] as number[];
  const i = cursor[u] as number;

  if (i === list.length) {
    // ④ 나가는 간선을 다 확인했다. 검은색으로 칠하고 경로에서 뺀다.
    color[u] = BLACK;
    stack.pop();
    continue;
  }

  cursor[u] = i + 1;
  const v = list[i] as number;

  // ① 회색 정점으로 가는 간선이다. 지금 경로 위의 정점으로 되돌아왔으므로 사이클이다.
  if (color[v] === GRAY) return true;

  // ② 흰색이면 아직 안 본 정점이다. 회색으로 칠하고 그 정점으로 내려간다.
  if (color[v] === WHITE) {
    color[v] = GRAY;
    stack.push(v);
  }

  // ③ 검은색이면 이미 끝난 정점이다. 아무것도 하지 않고 다음 간선으로 넘어간다.
}
```

여기서 가장 중요한 줄은 `if (color[v] === GRAY) return true;` 입니다. 회색인지만 묻고 검은색인지는 묻지 않는 것이
삼색 표시의 요점이에요. `cursor[u] = i + 1` 은 그 줄과 짝입니다 — 확인한 간선을 다시 확인하지 않게 자리를 하나
올려 두는 것이고, 꼭대기가 다른 정점으로 바뀌었다가 돌아와도 이어서 확인할 자리가 남아 있습니다. 정점 0 이 꼭대기에
올 때마다 `next[0] = [1, 4, 2]` 를 차례로 확인한 자취는 이렇습니다.

<!--proof:walk-top0-->

```text
T2   cursor[0] = 0   v = 1   1 이 흰색     ② 내려간다
T8   cursor[0] = 1   v = 4   4 가 검은색   ③ 넘어간다
T9   cursor[0] = 2   v = 2   2 가 흰색     ② 내려간다
```

T2 와 T8 사이에는 정점 1 아래(1 · 3 · 4)를 다 확인하고 되돌아오는 걸음들이 있습니다. 그동안 `cursor[0]` 은 1 에 머물러
있다가, 꼭대기가 다시 0 이 되자 두 번째 간선 `0 → 4` 부터 이어서 확인해요.

#### 짚고 가기 — 본 적 있는 정점을 만나면 사이클이라고 읽기 쉽다

`if (color[v] === GRAY)` 를 `if (color[v] !== WHITE)` 로 적고 싶어집니다. 사이클을 「이미 지나온 정점을 다시 만나는 것」이라고
읽으면 그것으로 충분해 보이니까요. 「아이디어를 떠올리는 과정」에서 버린 「본 적 있음」 후보가 코드 한 줄로는 이 모양입니다.

```ts
if (color[v] !== WHITE) return true; // ← 「흰색이 아니면 사이클」
```

이 코드는 예외를 내지 않습니다. 그리고 **어떤 입력에서는 답까지 같아요.**

<!--proof:mutant-two-color-->

| 입력 | 회색만 사이클 (정본) | 흰색이 아니면 사이클 | 두 답 |
| --- | --- | --- | --- |
| 전개가 쓰는 여섯 정점 | true | true | 같다 |
| 마름모 네 정점 | false | true | 어긋난다 |
| 가로지르는 간선 0→1 · 0→2 · 1→2 | false | true | 어긋난다 |
| 한 줄로 이은 네 정점 | false | false | 같다 |
| 간선이 없는 네 정점 | false | false | 같다 |

첫 줄과 마지막 두 줄이 그 자리입니다. 사이클이 진짜 있는 그래프와, 갈래가 한 번도 합쳐지지 않는 그래프에서는 두 코드가
같은 답을 내요. **테스트가 이런 입력만 담고 있으면 색을 둘로 줄여 놓고도 통과합니다.** 가로지르는 간선 하나짜리 그래프를
두 코드로 나란히 실행하면 어긋나는 걸음이 보여요.

<!--proof:mutant-two-color-trace-->

| 걸음 | 회색만 사이클 (정본) | 흰색이 아니면 사이클 |
| --- | --- | --- |
| T1 | 0 에서 시작 | 0 에서 시작 |
| T2 | 0 → 1 · 흰색 · ② 내려간다 | 0 → 1 · 흰색 · ② 내려간다 |
| T3 | 1 → 2 · 흰색 · ② 내려간다 | 1 → 2 · 흰색 · ② 내려간다 |
| T4 | 2 를 뺀다 | 2 를 뺀다 |
| T5 | 1 을 뺀다 | 1 을 뺀다 |
| T6 | 0 → 2 · 검은색 · ③ 넘어간다 | 0 → 2 · 검은색 · ① 사이클이다 |
| T7 | 0 을 뺀다 | — |

반환값은 앞이 false, 뒤가 true 입니다.

<!--/proof-->

T6 에서 두 코드가 처음 갈립니다. 간선 `0 → 2` 를 확인할 때 정점 2 는 T4 에 이미 끝나 검은색인데, 한쪽은 넘어가고 다른
쪽은 사이클로 판정했어요. 이 그래프에는 사이클이 없으니 넘어가는 쪽이 맞습니다.

#### 3. 여섯 정점의 간선 여덟 개를 처음부터 끝까지 확인한다

앞의 두 조각을 이어 실제로 실행하면 열두 걸음이 나옵니다. T1 이 바깥 반복의 시작이고, 그 뒤로 반복 한 바퀴가 걸음
하나예요. 걸음 재생 패널에서 정점 안의 앞말이 색이고 뒤의 두 수가 「확인한 간선 / 나가는 간선」입니다. 흰색 정점은 점선
테, 아직 확인하지 않은 간선은 흐린 선이에요. 확인한 간선은 내려간 것이 굵은 실선, 회색 정점으로 간 것이 대시, 넘어간
것이 가는 실선이고, 무대 아래 띠가 스택(아래 → 위를 왼쪽 → 오른쪽으로)입니다.

<!--viz:dfsColorWalk-->
<!--fig:walk-film-->
![directedCycleDetection(6, [[0,1],[1,3],[3,4],[0,4],[0,2],[2,3],[2,5],[5,0]]) 의 열두 걸음 T1~T12](./figs/walk-film.svg)

<!--result:dfsColorWalk=true-->

한 걸음마다 조건이 어떻게 판정되는지 전부 적으면 이렇습니다.

<!--proof:walk-trace-->

| 걸음 | 확인한 간선 | 도착 정점의 색 | 조건 판정 | cursor | stack |
| --- | --- | --- | --- | --- | --- |
| T1 | — | — | `color[0]` 흰색 → 시작한다 | [0, 0, 0, 0, 0, 0] | [0] |
| T2 | 0 → 1 | 흰색 | `color[1] === GRAY` 거짓 · `=== WHITE` 참 → ② | [1, 0, 0, 0, 0, 0] | [0, 1] |
| T3 | 1 → 3 | 흰색 | `color[3] === GRAY` 거짓 · `=== WHITE` 참 → ② | [1, 1, 0, 0, 0, 0] | [0, 1, 3] |
| T4 | 3 → 4 | 흰색 | `color[4] === GRAY` 거짓 · `=== WHITE` 참 → ② | [1, 1, 0, 1, 0, 0] | [0, 1, 3, 4] |
| T5 | — | — | `cursor[4] === next[4].length` 참 → ④ | [1, 1, 0, 1, 0, 0] | [0, 1, 3] |
| T6 | — | — | `cursor[3] === next[3].length` 참 → ④ | [1, 1, 0, 1, 0, 0] | [0, 1] |
| T7 | — | — | `cursor[1] === next[1].length` 참 → ④ | [1, 1, 0, 1, 0, 0] | [0] |
| T8 | 0 → 4 | 검은색 | `color[4] === GRAY` 거짓 · `=== WHITE` 거짓 → ③ | [2, 1, 0, 1, 0, 0] | [0] |
| T9 | 0 → 2 | 흰색 | `color[2] === GRAY` 거짓 · `=== WHITE` 참 → ② | [3, 1, 0, 1, 0, 0] | [0, 2] |
| T10 | 2 → 3 | 검은색 | `color[3] === GRAY` 거짓 · `=== WHITE` 거짓 → ③ | [3, 1, 1, 1, 0, 0] | [0, 2] |
| T11 | 2 → 5 | 흰색 | `color[5] === GRAY` 거짓 · `=== WHITE` 참 → ② | [3, 1, 2, 1, 0, 0] | [0, 2, 5] |
| T12 | 5 → 0 | 회색 | `color[0] === GRAY` 참 → ① | [3, 1, 2, 1, 0, 1] | [0, 2, 5] |

② 는 T2 · T3 · T4 · T9 · T11 에서 5 번, ③ 은 T8 · T10 에서 2 번, ④ 는 T5 · T6 · T7 에서 3 번, ① 은 T12 에서 1 번 실행됐습니다. 간선 확인은 8 번이고 간선 수 8 과 같습니다. 반환값은 true 입니다.

<!--/proof-->

**네 갈래가 모두 나왔습니다.** 헷갈리기 쉬운 자리는 T8 이에요. `0 → 4` 를 확인할 때 정점 4 는 이미 검은색입니다. T4 에서
`3 → 4` 로 내려가 T5 에서 끝냈기 때문이에요. 간선 `0 → 4` 는 그래프에 분명히 있지만 이 절차는 그것을 따라 내려가지 않고
넘어갑니다. 그 간선이 사이클을 닫을 수 없는 것은 4 가 지금 경로 `[0]` 위에 없기 때문입니다.

#### 짚고 가기 — 정점 0 에서 한 번만 시작해도 될 것 같다

바깥 `for` 문이 왜 필요한지 흐릿합니다. 정점 0 에서 시작해 간선을 따라가면 그래프 전체를 볼 수 있을 것 같으니까요. 그
오해대로 적으면 바깥 반복이 사라집니다.

```ts
// 정점 0 에서 한 번만 시작한다
color[0] = GRAY;
stack.push(0);
while (stack.length > 0) { /* 위와 같다 */ }
return false;
```

유향 그래프는 **정점 0 에서 도달할 수 없는 정점**을 가질 수 있습니다. 그래프가 여러 조각으로 나뉘어 있을 수도 있고,
한 조각 안에서도 방향 때문에 못 가는 자리가 있어요. 네 입력에 두 코드를 나란히 실행했습니다.

<!--proof:component-values-->

| 입력 | 정점 0 에서만 시작 | 흰색 정점마다 시작 (정본) | 두 답 |
| --- | --- | --- | --- |
| 0→1 과 사이클 2→3→4→2 | false | true | 어긋난다 |
| 자기 루프가 정점 3 에 있다 | false | true | 어긋난다 |
| 사이클이 0 에서 이어진다 0→1→2→0 | true | true | 같다 |
| 전개가 쓰는 여섯 정점 | true | true | 같다 |

전개 입력을 포함한 아래 두 줄에서는 답이 같아서, 그런 입력만 시험하면 바깥 반복을 지워 놓고도 통과합니다. 첫 줄이
반례예요. 정점 0 에서 갈 수 있는 곳은 1 뿐인데 사이클은 2 · 3 · 4 에 있습니다.

<!--proof:component-trace-->

```text
0 에서만 시작     걸음 4 개 뒤 스택이 빈다       흰색으로 남은 정점 2 · 3 · 4            false
s = 2 에서 다시   4 → 2 를 확인할 때 2 가 회색   바깥 for 문이 흰색 정점을 다시 잡았다   true
```

#### 짚고 가기 — cursor 없이 목록을 매번 처음부터 확인해도 된다

`cursor` 배열이 없어도 될 것 같습니다. 꼭대기를 볼 때마다 `next[u]` 를 처음부터 확인하면서 흰색 정점이 나오면 내려가고,
끝까지 흰색이 없으면 검은색으로 칠하면 되니까요. **이 방식은 답이 틀리지 않습니다.** 이미 확인한 간선의 도착 정점은
회색이거나 검은색이라 다시 확인해도 같은 갈래로 가고, 사이클이 있으면 여전히 회색을 만나요.

```ts
// cursor 없이 — 꼭대기를 볼 때마다 목록을 처음부터 확인한다
for (const v of next[u] as number[]) {
  if (color[v] === GRAY) return true;
  if (color[v] === WHITE) { color[v] = GRAY; stack.push(v); descended = true; break; }
}
if (!descended) { color[u] = BLACK; stack.pop(); }
```

답이 안 틀리는데도 고치는 이유는 걸음 수입니다. 정점 `u` 가 꼭대기에 오는 횟수가 「내려간 횟수 + 1」이고 그때마다
목록 앞부분을 다시 읽으므로, 읽은 원소 수가 목록 길이의 제곱에 비례해요.

<!--proof:cursor-values-->

| 입력 | E | cursor 있음 | 매번 처음부터 | 두 답 |
| --- | ---: | ---: | ---: | --- |
| 전개가 쓰는 여섯 정점 | 8 | 8 | 11 | 같다 (true) |
| 마름모 네 정점 | 4 | 4 | 8 | 같다 (false) |
| 별 모양 1,000 | 999 | 999 | 500,499 | 같다 (false) |
| 별 모양 10,000 | 9,999 | 9,999 | 50,004,999 | 같다 (false) |
| 사슬 10,000 | 9,999 | 9,999 | 19,998 | 같다 (false) |

**답 칸이 다섯 줄 다 「같다」입니다.** 갈리는 것은 읽은 원소 수예요. 정점 0 이 나머지 전부를 가리키는 별 모양에서
999 가 50 만이 되고, 정점을 열 배로 늘리면 5,000 만이 됩니다. 별 모양 1,000 에서 정점 0 이 꼭대기에 올 때마다 읽은 수를
따라가면 합이 이렇게 나와요.

<!--proof:cursor-star-->

```text
정점 0 이 꼭대기에 오는 횟수 1,000 번

1 번째       next[0] 에서 1 개 읽는다
2 번째       next[0] 에서 2 개 읽는다
3 번째       next[0] 에서 3 개 읽는다
999 번째     next[0] 에서 999 개 읽는다
1,000 번째   next[0] 에서 999 개 읽는다

합 = (1 + 2 + … + 999) + 999 = 499,500 + 999 = 500,499
```

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 **바깥 `for` 문과 마지막 `return false` 한 줄**뿐이에요
— 앞의 조각들은 한 출발점에서의 탐색만 적었고, 흰색 정점이 남았는지 확인하고 끝을 내는 자리가 여기입니다. 정본의
최상위 상수 `WHITE` · `GRAY` · `BLACK` 도 함께 싣습니다.

```ts
const WHITE = 0;
const GRAY = 1;
const BLACK = 2;

export function directedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean {
  // 간선 목록을 정점마다의 나가는 목록으로 옮긴다.
  const next: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) (next[u] as number[]).push(v);

  const color: number[] = Array.from({ length: n }, () => WHITE);
  // cursor[u] 는 next[u] 에서 다음에 확인할 자리다. 재귀에서 「돌아온 지점」이 하던 일을 한다.
  const cursor: number[] = Array.from({ length: n }, () => 0);
  const stack: number[] = [];

  for (let s = 0; s < n; s++) {
    if (color[s] !== WHITE) continue;
    color[s] = GRAY;
    stack.push(s);

    while (stack.length > 0) {
      const u = stack[stack.length - 1] as number;
      const list = next[u] as number[];
      const i = cursor[u] as number;

      if (i === list.length) {
        // ④ 나가는 간선을 다 확인했다. 검은색으로 칠하고 경로에서 뺀다.
        color[u] = BLACK;
        stack.pop();
        continue;
      }

      cursor[u] = i + 1;
      const v = list[i] as number;

      // ① 회색 정점으로 가는 간선이다. 지금 경로 위의 정점으로 되돌아왔으므로 사이클이다.
      if (color[v] === GRAY) return true;

      // ② 흰색이면 아직 안 본 정점이다. 회색으로 칠하고 그 정점으로 내려간다.
      if (color[v] === WHITE) {
        color[v] = GRAY;
        stack.push(v);
      }

      // ③ 검은색이면 이미 끝난 정점이다. 아무것도 하지 않고 다음 간선으로 넘어간다.
    }
  }

  return false;
}
```

실행하면 이렇게 나옵니다.

<!--proof:walk-result-->

```text
directedCycleDetection(6, [[0,1],[1,3],[3,4],[0,4],[0,2],[2,3],[2,5],[5,0]])   →   true
directedCycleDetection(4, [[0,1],[0,2],[1,3],[2,3]])                           →   false
directedCycleDetection(3, [[0,1],[0,2],[1,2]])                                 →   false
directedCycleDetection(4, [[0,1],[1,2],[2,3],[3,1]])                           →   true
directedCycleDetection(2, [[0,1],[1,0]])                                       →   true
directedCycleDetection(1, [[0,0]])                                             →   true
directedCycleDetection(5, [])                                                  →   false
```

### 알아 두면 좋은 개념 — 깊이 우선 탐색의 간선 분류

전개에서 간선 여덟 개를 확인할 때마다 도착 정점의 색이 셋 중 하나였습니다. 그 색이 간선의 종류를 정해요. 깊이 우선
탐색이 방향 그래프의 간선을 넷으로 가르는 방식이고, 이 편이 찾는 것은 그중 하나입니다.

<!--proof:edge-classes-->

| 걸음 | 간선 | 확인할 때 도착 정점의 색 | 종류 | 사이클 |
| --- | --- | --- | --- | --- |
| T2 | 0 → 1 | 흰색 | 나무 간선 | 아니다 |
| T3 | 1 → 3 | 흰색 | 나무 간선 | 아니다 |
| T4 | 3 → 4 | 흰색 | 나무 간선 | 아니다 |
| T8 | 0 → 4 | 검은색 | 순방향 간선 | 아니다 |
| T9 | 0 → 2 | 흰색 | 나무 간선 | 아니다 |
| T10 | 2 → 3 | 검은색 | 교차 간선 | 아니다 |
| T11 | 2 → 5 | 흰색 | 나무 간선 | 아니다 |
| T12 | 5 → 0 | 회색 | 되돌아가는 간선 | 닫는다 |

간선 8 개를 모두 갈랐고, 정본이 멈추는 자리까지의 분류는 끝까지 간 분류와 같습니다.

<!--/proof-->

넷의 이름은 이렇습니다. **나무 간선**은 탐색이 실제로 따라 내려간 간선이고, **되돌아가는 간선**은 지금 경로 위의 정점으로
되돌아오는 간선이에요. 검은색으로 가는 간선은 둘로 갈리는데, 도착 정점이 출발 정점보다 늦게 발견된 자손이면
**순방향 간선**, 아니면 **교차 간선**입니다. 전개 입력 위에 선 모양으로 그리면 이렇게 보여요.

<!--fig:related-edge-kinds-->
![전개 입력의 간선 여덟 — 굵은 실선이 나무 간선이고 나머지 셋은 이름을 붙였다](./figs/related-edge-kinds.svg)

**유향 그래프에 사이클이 있다는 것과 되돌아가는 간선이 있다는 것이 같은 말입니다.** 이 편의 절차는 그 하나만 찾는 것이고,
순방향과 교차는 찾을 필요가 없어서 ③ 한 갈래로 묶여 있어요. 같은 분류가 편 밖에서도 그대로 쓰입니다 —
[`stronglyConnectedComponents` 가이드](../stronglyConnectedComponents/stronglyConnectedComponents-guide.md)는 이 넷으로 깊이 우선
탐색 트리를 설명하고, 무향 그래프의 단절점과 다리를 찾을 때도 같은 이름으로 논증합니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 식으로 무엇이 나오는지, 무엇이 매 순간 참으로 남는지,
그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 있는가 없는가를 묻는다 | 사이클을 전부 세거나 가장 짧은 것을 찾으라는 것이 아니다 | 회색을 만나는 순간 반환한다. 나머지 간선을 안 확인해도 된다 |
| 간선에 방향이 있다 | 무향이면 방금 온 간선을 되돌아 읽는 것이 사이클이 아니다 | 온 간선을 기억하지 않는다. 색 하나로 판정된다 |
| 그래프를 미리 다 받아 둘 수 있다 | 간선을 한 번에 받아 나가는 목록을 만들고 시작한다 | `next` 를 먼저 만들고 그 뒤로는 새 간선을 받지 않는다 |

첫 조건이 깨지면 규모가 통째로 달라집니다. 사이클이 없는 다이아몬드 16 개에서 두 질문을 나란히 셌습니다.

<!--proof:fit-count-->

| 질문 | 하는 일 | 다이아몬드 16 개에서 센 값 |
| --- | --- | --- |
| 사이클이 있는가 | 간선을 한 번씩 확인한다 | 확인한 간선 64 개 · 답 false |
| 서로 다른 경로가 몇 개인가 | 경로를 하나씩 센다 | 정점 0 에서 끝까지 가는 경로 65,536 개 |

있는지 묻는 쪽은 간선 64 개를 확인하고 끝나는데, 경로를 세는 쪽은 사이클이 하나도 없는 그래프에서도 65,536 개를 셉니다.
사이클을 세는 과제는 이 절차를 그대로 쓸 수 없어요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "순환 의존"   "circular dependency"   "데드락"   "빌드가 불가능한 경우"
  "설치할 수 없으면 -1"                  "가능/불가능만 출력"

규모와 출력에 이런 모양이 보이면
  정점과 간선이 각각 10만 규모이고 시간이 1~2초   ← V + E 규모의 절차를 찾으라는 뜻이다
  답이 true / false 하나다                        ← 찾는 즉시 반환해도 된다는 뜻이다
  자기 자신을 가리키는 간선이 있을 수 있다        ← 길이 1 짜리 사이클을 빼먹지 말라는 뜻이다
```

반대로 **「실제 순서를 출력하라」·「무향 그래프에서」** 가 보이면 이 절차를 그대로 쓰지 않습니다. 앞은 사이클이 없을 때
나열까지 만들어야 하는 과제라 [`topologicalSort` 가이드](../topologicalSort/topologicalSort-guide.md)의 절차가 답이고, 뒤는
간선에 방향이 없어 판정 자체가 달라져 [`undirectedCycleDetection` 가이드](../undirectedCycleDetection/undirectedCycleDetection-guide.md)가
다루는 과제가 됩니다.

#### 실제로 쓰이는 곳

- **ninja 빌드 시스템** — 의존 그래프에 순환이 있는지 확인하는 데 이 글과 같은 색 셋을 씁니다. `src/graph.h` 가 `Edge`
  안에 *"enum VisitMark : char { VisitNone, VisitInStack, VisitDone };"* 를 두고 `VisitMark mark_ = VisitNone;` 로
  초기화하는데, 셋이 각각 이 글의 흰색 · 회색 · 검은색과 같아요. `src/graph.cc` 의 `VerifyDAG` 가
  `if (edge->mark_ != Edge::VisitInStack) return true;` 로 「지금 스택에 있는가」만 묻고, 그 조건이 참일 때
  `*err = "dependency cycle: ";` 로 순환을 알립니다 — 이 글의 ① 갈래 그대로입니다.
  ([ninja-build/ninja src/graph.h](https://raw.githubusercontent.com/ninja-build/ninja/master/src/graph.h) ·
  [src/graph.cc](https://raw.githubusercontent.com/ninja-build/ninja/master/src/graph.cc), 조회 2026-09-03)
- **PostgreSQL 의 데드락 검출** — 「누가 누구를 기다리는가」를 유향 그래프로 두고 사이클을 찾습니다.
  `src/backend/storage/lmgr/deadlock.c` 의 `FindLockCycle` 주석이 *"Scan outward from the given proc to see if there is a
  cycle in the waits-for graph that includes this proc. Return true if a cycle is found, else false."* 라 적어 반환값이 이
  글과 같은 `bool` 임을 밝히고, 실제 탐색을 하는 `FindLockCycleRecurse` 가 *"If we return to starting point, we have a
  deadlock cycle"* 로 판정 자리를 적습니다.
  ([postgres/postgres src/backend/storage/lmgr/deadlock.c](https://raw.githubusercontent.com/postgres/postgres/master/src/backend/storage/lmgr/deadlock.c), 조회 2026-09-03)

두 곳 다 **깊이 우선 탐색으로 내려가면서 「지금 스택에 있는 정점인가」를 묻는** 방식입니다. ninja 는 색 셋을 이름까지
그대로 두었고, PostgreSQL 은 출발점 하나로 되돌아오는지를 묻는 형태로 같은 판정을 합니다.

#### 경쟁 설계와의 대조

같은 답을 내는 다른 절차가 있습니다. **진입차수 세기**예요 — 정점마다 들어오는 간선 수를 세어 두고 그 수가 0 인 정점을
큐에 담아 하나씩 꺼내면서 도착 정점의 수를 줄입니다. 큐가 빈 뒤에 꺼낸 정점 수가 `n` 보다 작으면 남은 정점들이 사이클을
이루고 있어요. ([`topologicalSort` 가이드](../topologicalSort/topologicalSort-guide.md)가 그 절차를 만듭니다.) 두 절차는
사이클을 판정하는 자리가 다릅니다.

| 절차 | 판정하는 순간 | 끝나는 때 |
| --- | --- | --- |
| 삼색 표시 | 회색 정점으로 가는 간선을 만나는 순간 | 그 자리에서 반환할 수 있다 |
| 진입차수 세기 | 큐가 빈 뒤 꺼낸 정점 수를 `n` 과 비교할 때 | 정점을 전부 처리한 다음이다 |

**전개가 쓰는 입력을 첫 줄에서 그대로 잽니다.** 다만 정점이 여섯이면 「사이클이 정점 0 에서 몇 걸음 떨어져 있는가」를
바꿔 볼 자리가 없어 순서가 뒤집히는 것을 보일 수 없어요. 그래서 규모 상한인 정점 100,000 을 쓰는 생성식 셋을 함께
씁니다 — 사슬은 `0→1→…→99,999`, 되돌아가는 간선은 `p+1 → p` 를 목록 맨 앞에, 진입차수 0 인 정점을 없애는 것은
`99,999 → 0` 이고, 셋 다 `directedCycleDetection-guide.alt.ts` 에 상수로 두었습니다. 재는 계수는 배열 칸을 읽고 쓴 횟수인
**칸 접근**과 **추가 칸**이에요. 칸 접근은 배열을 처음 채우는 쓰기도 셉니다. 추가 칸은 입력 간선 목록을 빼고, 입력으로
지은 이웃 목록 · 색 배열 · 커서 배열(진입차수 쪽은 남은 선행 수 배열) · 스택이나 큐가 가장 길었을 때의 길이를 넣은 값입니다.

<!--proof:alt-flip-->

| 재는 것 | 삼색 표시 | 진입차수 세기 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 전개가 쓰는 여섯 정점에서 칸 접근 | 110 | 50 | 진입차수 세기 |
| 사이클이 정점 0 에서 두 걸음일 때 칸 접근 | 500,025 | 700,006 | 삼색 표시 |
| 사이클이 정점 0 에서 99,992 걸음일 때 칸 접근 | 1,299,945 | 1,299,946 | 삼색 표시 |
| 사이클이 정점 0 에서 99,993 걸음일 때 칸 접근 | 1,299,953 | 1,299,952 | 진입차수 세기 |
| 사이클이 씨앗을 전부 막을 때 칸 접근 | 1,300,001 | 700,000 | 진입차수 세기 |
| 사이클이 없는 사슬에서 칸 접근 | 1,899,992 | 1,299,994 | 진입차수 세기 |
| 사이클이 없는 사슬에서 추가 칸 | 499,999 | 399,999 | 진입차수 세기 |

**순서가 실제로 뒤집힙니다.** 전개 입력에서는 110 대 50 으로 진입차수 세기가 적은데, 사이클이 정점 0 에서 두 걸음인
큰 입력에서는 500,025 대 700,006 으로 삼색 표시가 적어요. 사이클이 진입차수 0 인 정점을 전부 막으면 1,300,001 대
700,000 으로 다시 진입차수 세기이고, 사이클이 아예 없으면 1,899,992 대 1,299,994 로 역시 진입차수 세기입니다. 두 계수는
사이클까지의 거리 `p` 에 대해 기울기 8 과 6 인 직선이라 뒤집히는 자리가 하나뿐이고, 그 자리를 값으로 대면 이렇습니다.

<!--proof:alt-boundary-->

| 사이클까지 확인하는 거리 | 삼색 표시 | 진입차수 세기 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 99,992 걸음 | 1,299,945 | 1,299,946 | 삼색 표시 |
| 99,993 걸음 | 1,299,953 | 1,299,952 | 진입차수 세기 |

경계는 「탐색이 사이클에 도달하기까지 확인하는 간선 수」입니다. **내주는 축이 둘이에요.** 하나는 사이클이 없을 때의
계수 — 삼색 표시는 정점마다 색 배열과 `cursor` 배열 둘을 쓰므로 1,899,992 대 1,299,994 로 많습니다. 다른 하나는 새로
잡는 칸으로, 499,999 대 399,999 로 `cursor` 배열 한 벌만큼 늘 더 씁니다. 대신 얻는 것은 **중간에 끝낼 수 있다는
것**과 **사이클을 이루는 정점이 스택에 그대로 남는다는 것**이에요 — 「어디가 순환인가」를 같이 물으면 삼색 표시는 스택을
그대로 출력하면 되고, 진입차수 세기는 남은 정점을 따로 모아야 합니다.

### 수식 정의와 유도

정점 집합 $\mathcal{V}$ 와 간선 집합 $\mathcal{E}$ 로 이루어진 유향 그래프를 $G$ 라 적습니다. $t$ 번째 간선을 확인한 직후
회색인 정점을 스택 아래에서 위로 늘어놓은 열이 $P_t$ 예요. 열의 길이를 $m = |P_t|$ 라 적고, 그 원소를
$P_t = (x_0, x_1, \dots, x_{m-1})$ 로 적습니다. **$V$ 와 $E$ 는 파트 1 에서 정한 그대로 정점 수와 간선 수이고, 집합이
아니라 수입니다** — 집합과 열의 크기는 $|\mathcal{V}|$ · $|P_t|$ 처럼 세로줄로 적습니다.

| 이름 | 정의 | 전개 입력에서 |
| --- | --- | --- |
| $G = (\mathcal{V}, \mathcal{E})$ | 유향 그래프 | $\|\mathcal{V}\| = V$, $\|\mathcal{E}\| = E$ |
| $P_t$ | $t$ 번째 간선을 확인한 직후 회색인 정점의 열 | 아래 표 |
| $c_t(v)$ | 그때 정점 $v$ 의 색 | 코드의 `color[v]` |
| $A(V, E)$ | 절차가 읽고 쓴 배열 칸의 총수 | 아래에서 센다 |

먼저 $P_t$ 가 무엇을 만족하는지 정의 그대로 적습니다. 열의 이웃한 두 정점 사이에는 반드시 간선이 있어야 해요 — 회색으로
칠하는 자리가 「바깥 반복의 시작」과 「간선을 따라 내려갈 때」 둘뿐이고, 앞의 것은 스택이 빌 때만 일어나기 때문입니다. 이것을
식으로 적고, 전개 입력의 간선 확인 여덟 번마다 검산했습니다.

$$P_t = (x_0, x_1, \dots, x_{m-1}) \;\Longrightarrow\; (x_{i}, x_{i+1}) \in \mathcal{E} \quad (0 \le i < m-1)$$

<!--proof:math-path-check-->

| t | 걸음 | P_t | 이웃한 두 정점 사이의 간선 |
| ---: | --- | --- | --- |
| 1 | T2 | (0, 1) | 있다 |
| 2 | T3 | (0, 1, 3) | 있다 |
| 3 | T4 | (0, 1, 3, 4) | 있다 |
| 4 | T8 | (0) | 있다 |
| 5 | T9 | (0, 2) | 있다 |
| 6 | T10 | (0, 2) | 있다 |
| 7 | T11 | (0, 2, 5) | 있다 |
| 8 | T12 | (0, 2, 5) | 있다 |

열 8 개 가운데 이웃한 두 정점 사이에 간선이 없는 열은 0 개입니다.

<!--/proof-->

이제 **회색 정점으로 가는 간선이 있다는 것과 사이클이 있다는 것이 같다**를 유도합니다.

$$\exists\, (u, v) \in \mathcal{E} : c_t(v) = \text{회색} \;\;\Longleftrightarrow\;\; G \text{ 에 사이클이 있다}$$

**왼쪽에서 오른쪽.** 간선 $(u, v)$ 를 확인하는 순간 $u$ 는 스택 꼭대기 $x_{m-1}$ 이고 $v$ 는 회색입니다. 회색 정점의
모임이 스택과 같으니(불변식) $v$ 는 스택 어딘가 $x_i$ 에 있어요. 위 식으로 $x_i \to x_{i+1} \to \dots \to x_{m-1} = u$ 라는
경로가 있고, 거기에 간선 $(u, v)$ 를 붙이면 $v$ 에서 출발해 $v$ 로 되돌아오는 경로가 됩니다. 사이클이에요. 전개가 회색을
만난 걸음에 이 이어 붙이기를 그대로 해 보면 이렇습니다.

<!--proof:math-back-edge-->

```text
T12 에 확인한 간선           (u, v) = (5, 0)
그때의 스택                  P_8 = (0, 2, 5)
v 의 자리                    i = 0
x_i 부터 꼭대기까지          0 → 2 → 5
간선 (u, v) 를 붙이면        0 → 2 → 5 → 0
이어 붙인 간선이 다 있는가   있다 — 사이클이다
```

**오른쪽에서 왼쪽.** 사이클 $C$ 가 있는데 이 절차가 회색을 한 번도 못 만났다고 가정해 모순을 냅니다. $C$ 위의 정점 중
**가장 먼저 회색이 된 것**을 $w$ 라 두고, $C$ 를 $w$ 에서부터 따라간 차례를 $w = w_0 \to w_1 \to \dots \to w_k \to w_0$ 로
적습니다. $w$ 가 회색이 된 순간 $w_1, \dots, w_k$ 는 모두 흰색이에요 — $w$ 가 가장 먼저이니까요. 그리고 **$w$ 가 스택에 있는
동안 회색이 된 정점은 모두 $w$ 위에 쌓이므로 $w$ 보다 먼저 빠집니다.** 이 둘로 「$w_1, \dots, w_k$ 가 모두 $w$ 가 스택에 있는
동안 회색이 된다」를 귀납으로 보입니다.

- **기저 $w_1$.** $w$ 는 목록을 다 확인해야 빠지므로, 빠지기 전에 간선 $(w, w_1)$ 을 확인합니다. 그때 $w_1$ 이 흰색이면 회색으로
  칠해 $w$ 위에 쌓아요. 회색일 수는 없습니다 — 가정이 회색을 못 만났다고 했으니까요. 검은색이면 $w$ 가 회색이 된 뒤에(그때는
  흰색이었으니) 회색이 되었다가 끝난 것이라, 역시 $w$ 가 스택에 있는 동안 회색이 된 것입니다.
- **단계 $w_i \to w_{i+1}$.** $w_i$ 가 $w$ 가 스택에 있는 동안 회색이 됐다면 $w$ 보다 먼저 빠지고, 빠지기 전에 간선
  $(w_i, w_{i+1})$ 을 확인합니다. 그때 $w$ 는 아직 스택에 있어요. 기저와 같은 까닭으로 $w_{i+1}$ 은 흰색이라 지금 회색이 되거나,
  이미 검은색이라 $w$ 가 회색이 된 뒤에 회색이 된 것입니다. 어느 쪽이든 $w$ 가 스택에 있는 동안이에요.
- **결론.** 그러면 $w_k$ 도 $w$ 가 스택에 있는 동안 회색이 되고, 빠지기 전에 간선 $(w_k, w_0)$ 을 확인합니다. 그 순간
  $w_0 = w$ 는 아직 스택에 있으니 회색이에요. 회색을 한 번도 못 만났다는 가정과 어긋나므로, 사이클이 있으면 회색 정점으로
  가는 간선을 반드시 만납니다. 전개가 찾은 사이클에서 이 사슬을 따라가면 아래 표와 같습니다.

<!--proof:math-cycle-order-->

| 정점 | 회색이 된 걸음 | 그때 스택의 w = 0 | 다음 간선 | 확인한 걸음 | 그때 다음 정점의 색 |
| --- | --- | --- | --- | --- | --- |
| w_0 = 0 | T1 | 자기 자신 | 0 → 2 | T9 | 흰색 |
| w_1 = 2 | T9 | 있다 | 2 → 5 | T11 | 흰색 |
| w_2 = 5 | T11 | 있다 | 5 → 0 | T12 | 회색 |

사이클 위에서 가장 먼저 회색이 된 정점은 0 이고, 마지막 간선을 확인할 때 0 이 회색이었습니다.

<!--/proof-->

가정과 달리 실제 실행은 회색을 만나므로, 마지막 줄이 바로 그 만남이에요. 이제 칸 접근 수 $A(V, E)$ 를 코드에서 그대로
셉니다. 사이클이 없어 끝까지 확인하는 경우이고, 줄마다 만드는 칸 접근 수를 먼저 적으면 이렇습니다.

```ts
// 각 항이 어느 줄에서 나오는지 — 왼쪽 수가 그 줄이 만드는 칸 접근 수다.
//  3V   Array.from 세 번 — next · color · cursor
//  2E   next[u] 읽기 + push
//   V   for (let s = 0; s < n; s++) 의 color[s] 읽기
// 3V+3E 꼭대기를 볼 때마다 stack 읽기 + next[u] 읽기 + cursor[u] 읽기
//  2V   color[u] 쓰기 + stack.pop
//  3E   cursor[u] 쓰기 + list[i] 읽기 + color[v] 읽기
//  2V   color[v] 쓰기 + stack.push — 시작점과 ② 갈래를 합쳐 정점당 한 번
const cellsPerVertex = 11;
const cellsPerEdge = 8;
const closedForm = (V: number, E: number): number =>
  cellsPerVertex * V + cellsPerEdge * E;
```

$$A(V, E) = \underbrace{3V}_{\text{배열 셋}} + \underbrace{2E}_{\text{목록 만들기}} + \underbrace{V}_{\text{바깥 for}} + \underbrace{3(V + E)}_{\text{꼭대기 확인}} + \underbrace{2V}_{\text{검은색으로}} + \underbrace{3E}_{\text{간선 하나}} + \underbrace{2V}_{\text{내려가기}} = 11V + 8E$$

「꼭대기 확인」이 $3(V + E)$ 인 것은 반복 한 바퀴마다 꼭대기를 한 번 보고, 바퀴 수가 사이클이 없을 때 간선 확인 $E$ 번과
빼기 $V$ 번을 더한 것이기 때문입니다. 식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

| 입력 | V | E | 실제 칸 접근 | 11V + 8E |
| --- | ---: | ---: | ---: | ---: |
| 마름모 네 정점 | 4 | 4 | 76 | 76 |
| 다이아몬드 16 개 | 49 | 64 | 1,051 | 1,051 |
| 사슬 1,000 | 1,000 | 999 | 18,992 | 18,992 |
| 별 모양 1,000 | 1,000 | 999 | 18,992 | 18,992 |
| 사슬 100,000 | 100,000 | 99,999 | 1,899,992 | 1,899,992 |

5 줄 가운데 두 값이 같은 줄은 5 개입니다.

<!--/proof-->

셋째 줄과 넷째 줄이 같은 값이라는 것도 함께 보세요 — 사슬과 별 모양은 모양이 완전히 다른데 계수가 같습니다. 이 식에 정점
수도 간선 수도 아닌 항이 없기 때문이에요. 마지막으로 규모 상한을 넣습니다.

<!--proof:math-scale-->

| 항 | 세는 것 | V = E = 100,000 에서 |
| --- | --- | ---: |
| 11V | 배열 셋 · 바깥 반복 · 꼭대기 확인 · 색 칠하기 | 1,100,000 |
| 8E | 목록 만들기 · 간선 하나 확인하기 | 800,000 |
| A(V, E) | 두 항의 합 | 1,900,000 |
| 경로를 하나씩 세기 | 다이아몬드 25,000 개의 경로 수 2^25,000 | 7,526 자리 수 |

190 만 번과 7,526 자리 수를 나란히 놓으면 이 절차가 무엇을 바꿨는지가 수로 나옵니다. 경로를 하나씩 세는 과제를 **간선을
한 번씩 확인하는 과제로** 바꾼 것이에요.

### 불변식 — 회색 정점의 모임은 지금 따라가는 경로다

파트 1 에서 코드가 동작하는 것을 열두 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는 뜻은
아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> 반복문의 한 바퀴가 끝날 때마다, 회색인 정점의 모임은 `stack` 에 들어 있는 정점의 모임과 **정확히 같습니다.** 그리고
> `stack` 을 아래에서 위로 읽으면 이웃한 두 정점 사이에 간선이 있어, 정점 하나에서 출발해 지금 꼭대기까지 온 경로 하나가
> 됩니다.

<!--proof:invariant-deepest-->

```text
T4 직후   회색 정점   [0, 1, 3, 4]
          stack       [0, 1, 3, 4]
          경로        0 → 1 → 3 → 4
```

위는 전개에서 스택이 가장 깊었던 순간이고, 두 모임이 글자 그대로 같습니다. 「한 바퀴가 끝날 때마다」가 중요합니다. 반복이 다 끝난 뒤 한 번만 참인 것이 아니라 **간선 하나를 확인하거나 정점 하나를
뺀 직후마다** 참이라는 뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** 바깥 `for` 문이 흰색 정점 `s` 를 회색으로 칠하고 `stack` 에 넣는 순간, 회색인 정점은 `s` 하나이고
`stack` 도 `[s]` 하나입니다. 스택이 빈 뒤에만 이 일이 일어나므로 다른 회색 정점은 없고, 길이 1 짜리 경로는 이웃 조건을
만족해요. 그 뒤로 상태를 바꾸는 갈래는 셋이고, 전개에서 갈래마다 처음 나온 걸음의 전과 뒤를 적었습니다.

<!--proof:invariant-ops-->

| 걸음 | 갈래 | 전 — 회색 정점 · 스택 | 뒤 — 회색 정점 · 스택 | 두 모임 |
| --- | --- | --- | --- | --- |
| T2 | 내려간다 | [0] · [0] | [0, 1] · [0, 1] | 같다 |
| T5 | 검은색으로 뺀다 | [0, 1, 3, 4] · [0, 1, 3, 4] | [0, 1, 3] · [0, 1, 3] | 같다 |
| T8 | 넘어간다 | [0] · [0] | [0] · [0] | 같다 |

| 갈래 | 두 성질이 유지되는 근거 |
| --- | --- |
| 흰색 정점으로 내려간다 | 칠하기와 넣기를 같은 자리에서 함께 하므로 두 모임이 어긋나지 않는다. 그 직전 꼭대기가 `u` 이고 간선 `(u, v)` 를 확인한 것이라 이웃 조건도 지켜진다 |
| 목록을 다 확인해 뺀다 | 칠하기와 빼기를 같은 자리에서 함께 한다. 꼭대기 하나만 빠지므로 남은 열의 이웃 관계는 그대로다 |
| 검은색 정점을 만난다 | 색도 `stack` 도 안 바뀌므로 유지된다 |

입력을 다섯으로 늘려 걸음마다 다시 확인했습니다. 무작위 입력은 정점 번호 둘을 시드 20260930 의 난수로 120 번 뽑아
간선으로 삼은 것이고, 사이클 없는 쪽은 간선을 작은 번호에서 큰 번호로만 두었어요.

<!--proof:invariant-check-->

| 입력 | 확인한 걸음 | 회색 모임과 스택이 다른 걸음 | 스택 이웃 사이에 간선이 없는 걸음 | 반환값 |
| --- | ---: | ---: | ---: | --- |
| 전개가 쓰는 여섯 정점 | 12 | 0 | 0 | true |
| 마름모 네 정점 | 9 | 0 | 0 | false |
| 다이아몬드 16 개 | 114 | 0 | 0 | false |
| 사이클 없는 무작위 V = 60 · E = 120 (시드 20260930) | 199 | 0 | 0 | false |
| 무작위 V = 60 · E = 120 (시드 20260930) | 5 | 0 | 0 | true |

입력 5 개의 339 걸음에서 불변식이 깨진 걸음은 0 개입니다.

<!--/proof-->

이 불변식이 답의 정확성을 그대로 줍니다. 회색 정점으로 가는 간선을 만났다는 것은 **지금 경로 위의 정점으로 가는 간선을
만났다**는 뜻이고, 경로를 따라 그 정점까지 이어 붙이면 사이클이 되니까요. 반대로 검은색 정점으로 가는 간선은 경로 위에
없는 정점을 가리키므로 사이클을 만들지 않습니다. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

| 입력 | 호출 | 끝난 자리 | 결과 |
| --- | --- | --- | --- |
| 정점 하나 | `directedCycleDetection(1, [])` | 시작 1 번 · 정점 1 개가 모두 검은색 | false |
| 간선 없음 | `directedCycleDetection(5, [])` | 시작 5 번 · 정점 5 개가 모두 검은색 | false |
| 자기 루프 | `directedCycleDetection(1, [[0,0]])` | 0 → 0 을 확인할 때 0 이 회색 | true |
| 크기 2 왕복 | `directedCycleDetection(2, [[0,1],[1,0]])` | 1 → 0 을 확인할 때 0 이 회색 | true |
| 중복 간선 | `directedCycleDetection(2, [[0,1],[0,1]])` | 시작 1 번 · 정점 2 개가 모두 검은색 | false |
| 나뉜 조각 | `directedCycleDetection(5, [[0,1],[2,3],[3,4],[4,2]])` | 4 → 2 를 확인할 때 2 가 회색 | true |

자기 루프가 이 절차의 경계입니다. 간선 `[v, v]` 는 `v` 가 꼭대기일 때 확인되는데 그때 `v` 는 회색이라, 따로 처리하는
코드 없이 사이클로 판정돼요. 중복 간선은 첫 번째에 내려가고 두 번째에는 검은색을 만나므로 결과를 바꾸지 않습니다. 간선이
없는 그래프는 정점마다 한 번씩 시작해 곧바로 검은색이 됩니다.

**이제 깨뜨려 봅시다.** 「회색인 정점의 모임 = `stack` 의 정점」을 지키던 줄은 목록을 다 확인하고 뺄 때 색을 검은색으로
바꾸는 줄입니다. `stack` 에서는 빼면서 색은 회색으로 남겨 두면 어떻게 되는지 봅시다.

```ts
color[u] = GRAY; // ← 뺄 때 검은색으로 칠하지 않고 회색으로 둔다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-stay-gray-->

| 입력 | 뺄 때 검은색 (정본) | 뺄 때도 회색 | 두 답 |
| --- | --- | --- | --- |
| 전개가 쓰는 여섯 정점 | true | true | 같다 |
| 마름모 네 정점 | false | true | 어긋난다 |
| 가로지르는 간선 0→1 · 0→2 · 1→2 | false | true | 어긋난다 |
| 한 줄로 이은 네 정점 | false | false | 같다 |
| 간선이 없는 네 정점 | false | false | 같다 |

사이클이 없는 두 그래프에서 `true` 가 나옵니다. 끝난 정점이 회색으로 남으니까 「회색 = 지금 경로 위」가 거짓이 되고, 다른
갈래에서 그 정점을 다시 만났을 때 되돌아온 것으로 판정하기 때문이에요. 마름모에서 걸음마다 스택과 회색 정점을 나란히
놓으면 불변식이 깨지는 자리가 보입니다.

<!--proof:mutant-stay-gray-trace-->

| 걸음 | 한 일 | 스택 | 회색 정점 |
| --- | --- | --- | --- |
| T1 | 0 에서 시작 | [0] | [0] |
| T2 | 0 → 1 · 흰색 · 내려간다 | [0, 1] | [0, 1] |
| T3 | 1 → 3 · 흰색 · 내려간다 | [0, 1, 3] | [0, 1, 3] |
| T4 | 3 을 뺀다 | [0, 1] | [0, 1, 3] |
| T5 | 1 을 뺀다 | [0] | [0, 1, 3] |
| T6 | 0 → 2 · 흰색 · 내려간다 | [0, 2] | [0, 1, 2, 3] |
| T7 | 2 → 3 · 회색 · 사이클이다 | [0, 2] | [0, 1, 2, 3] |

반환값은 true 이고, 정본의 답은 false 입니다.

<!--/proof-->

T4 가 불변식이 처음 깨지는 자리입니다. 3 을 뺐는데 3 이 여전히 회색이라 스택 `[0, 1]` 과 회색 정점 `[0, 1, 3]` 이 갈라져요.
그 틈이 T7 에서 사이클 판정으로 나옵니다. **한 줄로 이은 네 정점에서는 두 값이 같다는 것**도 함께 보세요. 사슬은 갈래가
한 번도 합쳐지지 않아 끝난 정점을 다시 만나는 일이 없고, 그 입력만 시험하면 바꿔 놓고도 통과합니다.

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 일은 스택 꼭대기를 보고, `cursor` 가 가리키는 간선 하나를 확인하거나, 목록을 다 확인했으면 검은색으로 칠해
빼는 것뿐입니다. 전개의 걸음으로 확인하면 바퀴마다 이렇게 모여요.

<!--proof:perf-derive-->

| 바퀴 | 한 일 | 뺀 정점 | 확인한 간선 | 걸음 |
| ---: | --- | --- | --- | --- |
| 1 | 간선 하나를 확인한다 | — | 0 → 1 | T2 |
| 2 | 간선 하나를 확인한다 | — | 1 → 3 | T3 |
| 3 | 간선 하나를 확인한다 | — | 3 → 4 | T4 |
| 4 | 목록을 다 봐서 뺀다 | 4 | — | T5 |
| 5 | 목록을 다 봐서 뺀다 | 3 | — | T6 |
| 6 | 목록을 다 봐서 뺀다 | 1 | — | T7 |
| 7 | 간선 하나를 확인한다 | — | 0 → 4 | T8 |
| 8 | 간선 하나를 확인한다 | — | 0 → 2 | T9 |
| 9 | 간선 하나를 확인한다 | — | 2 → 3 | T10 |
| 10 | 간선 하나를 확인한다 | — | 2 → 5 | T11 |
| 11 | 간선 하나를 확인한다 | — | 5 → 0 | T12 |

반복은 11 바퀴이고, 간선 확인이 8 번으로 간선 수 8 과 같습니다. 빼기는 3 번으로 정점 수 6 보다 적습니다.

<!--/proof-->

간선을 확인하는 횟수는 T2 · T3 · T4 · T8 · T9 · T10 · T11 · T12 의 여덟 번으로 **간선 수와 같고**, 빼는 횟수는 T5 · T6 · T7
의 세 번으로 **검은색이 된 정점 수**와 같습니다. 사이클이 없으면 뒤의 값이 `V` 이고, 사이클을 먼저 만나면 그만큼 작아져요.
그 앞에 나가는 목록을 만드는 비용이 붙습니다.

```text
총식 = 배열 셋 만들기 + 목록 채우기 + 바깥 for + 꼭대기 확인 + 간선 확인 + 색 칠하기
       Θ(V)            Θ(E)          Θ(V)       Θ(V + E')    Θ(E')      Θ(V)
                                                 ↑ E' 는 반환하기 전까지 확인한 간선 수
     = Θ(V + E)

메모리 = next Θ(V + E) + color · cursor · stack Θ(V) = Θ(V + E)
```

여기서 센 것은 **배열 칸을 읽고 쓴 횟수**입니다. `next[u].push(v)` 와 `stack.push(v)` 가 안에서 칸을 다시 잡는 비용은 세지
않았어요 — 정점 하나가 스택에 들어가는 것도 간선 하나가 목록에 들어가는 것도 전체에서 한 번씩이라, 분할 상환하면 위 식의
규모를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 간선이 자기 루프다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(V + E)` | `Θ(V + E)` |
| **최악의 경우** (사이클이 없다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값입니다.** 어떤 입력이 와도 나가는 목록을 만드는 데 `Θ(V + E)` 가 들고, 그것이 그대로 하한이에요. 간선
하나를 목록에 넣지 않고 넘어가는 경로가 없기 때문입니다. 케이스가 갈리는 것은 규모가 아니라 상수배예요. 정점과 간선 수를
규모 상한으로 고정하고 두 케이스를 쟀습니다.

<!--proof:perf-cases-->

| 케이스 | 입력 | 칸 접근 |
| --- | --- | ---: |
| 사이클이 없다 | 사슬 + 순방향 간선 하나 (사이클 없음) | 1,900,000 |
| 사이클이 두 걸음 앞에 있다 | 사이클이 정점 0 에서 두 걸음 | 500,025 |

두 입력 다 V = 100,000 · E = 100,000 이고, 칸 접근은 3.8 배 차이가 납니다.

<!--/proof-->

**평균을 따로 계산할 대상이 없습니다.** 사이클을 언제 만나는가가 주 반복의 길이를 바꾸기는 하지만, 그 앞에 놓인 목록 만들기와
배열 셋이 어떤 입력에서도 치러지므로 기댓값이 `Θ(V + E)` 를 벗어날 수 없어요. 「평균이 정의되지 않는다」가 아니라 **분포와
무관하게 같다**는 쪽입니다.

```text
최악 보장     어떤 입력에도 V + E 규모를 넘지 않는다         ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다  ← 이 절차는 여기 해당하지 않는다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요. 같은 입력을 두 번 넣으면
반환값도 칸 접근 수도 똑같이 나옵니다. 경계의 종류로 보면 `Θ(V + E)` 는 상한이자 하한이에요 — 간선을 한 번씩은 목록에
넣어야 하므로 그보다 적게 할 방법이 없고, 위에서 센 대로 그보다 많이 하지도 않습니다.

#### 최악을 만드는 입력

「깊은 그래프가 최악」이라는 통념부터 확인합시다. 사슬은 스택이 가장 깊어지는 그래프이고 별 모양은 가장 얕은 그래프예요.
정점 여섯으로 줄여 두 모양을 그리면 이렇습니다.

<!--fig:worst-shapes-->
![정점 여섯으로 줄여 그린 두 모양 — 정점 안의 수는 스택에 들어갈 때의 깊이](./figs/worst-shapes.svg)

두 모양을 정점 100,000 개로 키우고, 순방향 간선 하나씩을 더해 간선 수를 규모 상한 100,000 까지 채워 실행했습니다. 사이클이
있는 두 입력도 같은 규모로 함께 쟀어요.

<!--proof:shape-values-->

| 입력 모양 | V | E | 스택의 최대 깊이 | 가장 긴 목록 | 칸 접근 | 반환값 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 사슬 + 순방향 간선 하나 (사이클 없음) | 100,000 | 100,000 | 100,000 | 2 | 1,900,000 | false |
| 별 모양 + 순방향 간선 하나 (사이클 없음) | 100,000 | 100,000 | 3 | 99,999 | 1,900,000 | false |
| 사슬이 닫힌다 99,999 → 0 | 100,000 | 100,000 | 100,000 | 1 | 1,300,001 | true |
| 사이클이 정점 0 에서 두 걸음 | 100,000 | 100,000 | 3 | 2 | 500,025 | true |

**앞의 두 줄이 정확히 같은 칸 접근 수입니다.** 스택의 최대 깊이는 100,000 대 3 으로 완전히 다른데 비용은 같아요. 통념은 이
절차에서 성립하지 않습니다 — 반복문으로 적었으므로 호출 깊이가 없고, 스택에 동시에 들어 있는 개수는 비용이 아니라 배열 길이일
뿐이라 어느 쪽이든 `V` 를 넘지 않아요. 최악을 만드는 조건은 모양이 아니라 **크기와 사이클의 유무**입니다. `V` 와 `E` 를 규모
상한까지 채우고 사이클을 없애면 `11V + 8E` 가 그대로 치러지고, 사슬이든 별이든 다이아몬드든 같은 값이 나옵니다.

가장 적은 일을 하는 입력은 반대쪽입니다. 사이클이 정점 0 에서 두 걸음이면 190 만이 50 만으로 내려가요. 그래도 규모는 그대로
`Θ(V + E)` 입니다 — 나가는 목록을 만드는 `3V + 2E` 는 어떤 입력에서도 치러야 하니까요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 경로를 하나씩 세던 것을 **정점마다 색 하나를 칠하는 삼색 표시**로 바꿨고,
색을 셋으로 가른 덕분에 「지금 경로 위에 있다」와 「이미 끝났다」가 갈리며, 회색 정점으로 가는 간선 하나를 만나는 순간 답이
정해집니다.

```text
간선 목록 → next → 흰색 정점에서 시작 → 회색으로 칠하며 내려간다 → 목록을 다 보면 검은색
                    └ 바깥 for 가 V 번  └ cursor 로 간선마다 한 번   └ 회색을 만나면 true
```

먼저 답이 붙는 문제 하나입니다. T8 에서 간선 `0 → 4` 를 확인했을 때 정점 4 는 검은색이었고, 그래서 ③ 으로 넘어갔어요.
그런데 그것은 `[0,4]` 가 간선 목록의 **네 번째**에 적혀 있었기 때문입니다. `[0,4]` 를 목록 맨 앞으로 옮기면 간선들의 종류와
반환값이 어떻게 될까요?

```text
edges = [[0,4], [0,1], [1,3], [3,4], [0,2], [2,3], [2,5], [5,0]]   ← next[0] = [4, 1, 2]
```

<!--check:orderSwap-->
종류는 둘이 바뀌고 반환값은 그대로 `true` 입니다. `0 → 4` 는 4 가 흰색일 때 확인되므로 나무 간선이 되고, 그 대신 `3 → 4` 가
검은색을 만나 교차 간선이 됩니다. **되돌아가는 간선은 `5 → 0` 하나로 그대로입니다.** 간선을 적은 순서가 바뀌면 탐색이 내려가는
차례가 바뀌고 그래서 나무 · 순방향 · 교차 간선의 이름표가 자리를 바꾸지만, 사이클이 있다는 사실 자체는 입력의 순서와
무관해요. 반환값이 순서에 안 흔들리는 것이 그 뜻입니다.

<!--proof:order-swap-->

| 간선 | 전개 입력의 순서에서 | [0,4] 를 맨 앞에 둔 순서 | 변화 |
| --- | --- | --- | --- |

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### Directed Cycle Detection (유향 그래프 사이클 탐지)

풀 파일: [`directedCycleDetection.ts`](./directedCycleDetection.ts) · 테스트: [`directedCycleDetection.test.ts`](./directedCycleDetection.test.ts) · 실행: `bun test src/algorithms/graph/directedCycleDetection/directedCycleDetection.test.ts`

#### 한 줄 요약

> 함수는 정점 수 `n`과 유향 간선 목록을 받아, 그래프에 사이클이 존재하면 `true`, 없으면 `false`를 반환한다.

#### 스토리

소프트웨어 패키지 관리 시스템을 개발하는 팀이 있다. 각 패키지는 다른 패키지에 의존할 수 있는데, A가 B에 의존하고 B가 다시 A에 의존하면 설치가 불가능한 순환 의존성이 생긴다.

팀은 새 패키지를 등록할 때마다 "이 의존 관계 그래프에 순환 고리가 생기지 않는가"를 확인해야 한다. 순환 고리가 하나라도 있으면 전체 설치 과정이 멈춘다.

설치 단계에 진입하기 전에 이 검사를 통과해야만 배포가 진행된다.

#### 함수 인터페이스

```ts
export function directedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean;
```

- `n` — 정점 수. 정점 번호는 $0 \ldots n-1$
- `edges` — 유향 간선 목록. 각 원소 `[u, v]`는 $u \to v$ 방향의 간선
- 반환 — 사이클이 존재하면 `true`, 존재하지 않으면 `false`

#### 제약 조건

- $1 \leq V \leq 10^{5}$ (여기서 $V = n$)
- $0 \leq E \leq 10^{5}$ (여기서 $E$는 `edges`의 길이)
- 방향 그래프
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

유향 그래프에 **사이클이 존재하는지 여부** 를 판별한다.

사이클이란 같은 정점에서 출발해 방향을 따라 이동했을 때 다시 그 정점으로 돌아올 수 있는 경로이다.

경계 동작:
- 자기 루프 `[v, v]`는 사이클로 간주한다.
- 무향 그래프와 달리, 방향이 반대인 두 간선 `[u, v]`와 `[v, u]`는 사이클을 형성한다.
- 교차 간선(이미 완료된 서로 다른 경로를 연결하는 간선)은 사이클이 아니다.
- 그래프가 분리된 여러 성분으로 이루어진 경우, 어느 하나에라도 사이클이 있으면 `true`를 반환한다.
- 간선이 없으면 사이클이 없다.

#### 예시

```ts
// 유향 사이클: 0→1→2→0
directedCycleDetection(3, [[0,1],[1,2],[2,0]]); // true

// 자기 루프: 0→0
directedCycleDetection(1, [[0,0]]); // true

// 양방향 간선: 0→1, 1→0 — 유향 사이클 형성
directedCycleDetection(2, [[0,1],[1,0]]); // true

// 선형 DAG: 0→1→2→3 — 사이클 없음
directedCycleDetection(4, [[0,1],[1,2],[2,3]]); // false

// 다이아몬드 DAG: 0→1, 0→2, 1→3, 2→3 — 교차 간선, 사이클 아님
directedCycleDetection(4, [[0,1],[0,2],[1,3],[2,3]]); // false

// 간선 없음
directedCycleDetection(5, []); // false
```
