# 유향 사이클 탐지 — 지금 따라가는 경로 위의 정점으로 되돌아오는 간선이 사이클의 증거다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 경로를 전부 따라가 보던
방법에서 정점마다 색 하나를 칠하는 방법까지 가는 과정을 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**유향 그래프**는 정점들과 **방향이 있는 간선**으로 이루어집니다. 간선 `[u, v]` 는 `u → v` 를
뜻해요. 패키지 의존 관계라면 `u` 를 설치하려면 `v` 가 먼저 있어야 한다는 뜻입니다.

```text
    ┌──────────────────────────────────┐
    │                                  │
    v                                  │
    0 ────> 1 ────> 3 ────> 4          │        간선 여덟
    │               ^       ^          │          0→1 · 1→3 · 3→4 · 0→4
    │               │       │          │          0→2 · 2→3 · 2→5 · 5→0
    ├───────────────┼───────┘          │
    │               │                  │        맨 바깥을 크게 두르는 선이
    └────> 2 ───────┘                  │        5→0 이다
           │                           │
           └────> 5 ───────────────────┘
```

이 글이 답하는 것은 **간선을 따라가다가 출발한 정점으로 되돌아오는 경로가 있는가** 하나입니다.
그런 경로를 **사이클**이라고 부르고, 있으면 `true`, 없으면 `false` 를 돌려줍니다. 위 그래프에는
그런 경로가 있어요.

```text
사이클 하나를 따라가 본다

  0 ──> 2      간선 0→2 가 있다
  2 ──> 5      간선 2→5 가 있다
  5 ──> 0      간선 5→0 이 있다
               └ 출발한 정점 0 으로 되돌아왔다. 이것이 사이클이다
```

**되돌아오지 않는 경로와 헷갈리기 쉽습니다.** 위 그래프에서 `0 → 2 → 3 → 4` 도 세 걸음이지만
사이클이 아니에요. 정점 4 에서 나가는 간선이 하나도 없어서 0 으로 되돌아올 방법이 없습니다.
자기 자신을 가리키는 간선 `[v, v]` 는 길이 1 짜리 사이클입니다.

```text
같은 그래프에서 세 걸음짜리 경로 둘

  0 → 2 → 5 → 0     마지막에 출발점으로 되돌아온다        사이클이다
  0 → 2 → 3 → 4     4 에서 나가는 간선이 하나도 없다      사이클이 아니다
```

**이 글의 결정적인 관찰은 하나입니다.** 경로를 따라가다가 만난 정점이 **지금 따라가고 있는 그
경로 위에** 있으면 사이클이고, 그냥 **전에 확인한 적이 있을 뿐**이면 사이클이 아닙니다. 둘을
가르지 않으면 답이 틀려요. 정점마다 상태를 셋으로 갈라 두면 그 자리에서 판정됩니다.

```text
정점의 상태 셋 — 색 이름으로 부른다

  흰색      아직 한 번도 확인하지 않았다
  회색      지금 따라가는 경로 위에 있다          ← 이리로 가는 간선이 사이클이다
  검은색    나가는 간선을 전부 확인하고 끝났다    ← 이리로 가는 간선은 사이클이 아니다
```

경로를 한 걸음 나아갈 때 그 정점을 회색으로 칠하고, 그 정점의 나가는 간선을 전부 확인하고
돌아 나올 때 검은색으로 칠합니다. 그러면 어느 순간에도 **회색인 정점의 모임이 곧 지금 따라가는
경로**이에요. 회색 정점을 가리키는 간선을 만나는 순간 답이 `true` 로 정해집니다.

```text
0 에서 나가는 간선 셋 중 0→2 를 골라 따라가며 색을 칠해 본다

  0 을 회색으로   경로 [0]        0 을 출발점으로 잡는다
  2 를 회색으로   경로 [0,2]      0→2 를 따라 내려왔다
  5 를 회색으로   경로 [0,2,5]    2→5 를 따라 내려왔다
  5→0 을 확인     0 이 회색이다   지금 경로 위의 정점이라 사이클이다. true
```

색을 칠하고 확인하는 일은 정점마다 한 번, 간선마다 한 번씩만 일어납니다. 정점 `V` 개와
간선 `E` 개짜리 그래프에서 전체가 `Θ(V + E)` 에 비례하고, 정점 100,000 개와 간선 100,000 개라는
제약에서 여유 있게 1 초 안에 끝나요.

```text
정점 수 V, 간선 수 E 일 때

  나가는 목록 만들기   간선 하나를 한 번씩 읽는다              E 에 비례
  색 배열 만들기       정점마다 칸 하나                        V 에 비례
  색 칠하기            정점마다 흰색 → 회색 → 검은색 한 번씩   V 에 비례
  간선 확인하기        간선마다 정확히 한 번씩                 E 에 비례
                       └ 전체가 V + E 에 비례한다
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 정점과 간선으로 적는 방식.** 특히 **인접 리스트** — 정점마다 이웃 목록 하나를 두는
  표현입니다. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **깊이 우선 탐색이 무엇인가.** 한 갈래를 갈 수 있는 데까지 따라간 다음 되돌아 나와서 다음
  갈래를 확인하는 순회입니다. 이 글은 그 순회에 색을 덧붙인 것이라, 순회 자체가 흐릿하면
  뒤가 어긋나요. 모르면 [`dfsTraversal` 가이드](../dfsTraversal/dfsTraversal-guide.md)를 보세요.
- **스택이 나중에 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기·꺼내기가 각각 `O(1)` 입니다.
  모르면 [`stack` 가이드](../../../data-structures/linear/stack/stack-guide.mdx)를 보세요.
- **유향 그래프에서 들어오는 간선과 나가는 간선이 다르다는 것.** 간선 `[u, v]` 는 `u` 의
  나가는 간선이면서 동시에 `v` 의 들어오는 간선입니다. 이 글은 나가는 쪽만 자료로 만듭니다.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점이 지금 무슨 색인가」를 배열 한 칸을 읽어
  판정합니다.

두 번째와 세 번째가 흐릿하면 뒤가 어긋납니다. 이 글은 깊이 우선 탐색을 재귀가 아니라 배열
둘(`stack` 과 `cursor`)로 적는데, 그 둘이 재귀의 무엇을 대신하는지 알고 있어야 왜 그렇게
적는지 읽혀요.

### 아이디어 상세 — 색 셋과 스택을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function directedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean;
```

- 입력: 정점 수 `n`, 유향 간선 목록 `edges`. 정점 번호는 0 부터 `n - 1` 까지예요.
- 출력: 사이클이 하나라도 있으면 `true`, 하나도 없으면 `false`.
- 제약: 정점 100,000 개 이하, 간선 100,000 개 이하, 시간 1 초, 메모리 256 MB.
  자기 자신을 가리키는 간선 `[v, v]` 가 들어올 수 있고, 그래프가 여러 조각으로 나뉘어 있을 수
  있습니다. 어느 조각에라도 사이클이 있으면 `true` 입니다.

**답이 `true` 와 `false` 둘 중 하나뿐**이라는 것이 이 문제의 성질입니다. 사이클을 찾아서
출력하라는 것이 아니라 있는지만 묻는 것이라, 사이클 하나를 확인하는 순간 나머지를 안 봐도
됩니다.

```text
답이 둘 중 하나라는 것이 절차의 끝을 정한다

  사이클을 전부 찾아라   마지막 간선까지 확인해야 끝난다
  가장 짧은 것을 찾아라  후보를 다 만들어 견주어야 끝난다
  하나라도 있는가        첫 하나를 확인하는 순간 끝난다      ← 이 문제
```

이 글이 쓰는 기호는 여섯이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `V` | 정점 수 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수 | `0 ≤ E ≤ 100,000` |
| `next[u]` | `u` 에서 나가는 간선의 도착 정점 목록 | 길이를 다 더하면 `E` |
| `color[v]` | 정점 `v` 의 색 — 흰색 · 회색 · 검은색 | 처음에는 전부 흰색 |
| `cursor[u]` | `next[u]` 에서 다음에 확인할 자리 | 0 에서 시작해 목록 길이까지 |
| `stack` | 지금 따라가는 경로 위의 정점들 | 회색 정점의 모임과 같다 |

정점 수 `V` 는 코드에서 `n` 입니다. 색은 흰색 0 · 회색 1 · 검은색 2 로 적어 배열 한 칸에
담아요.

```text
기호가 어디에 사는가

  V           함수 인자 n           값이 바뀌지 않는다
  E           edges 의 길이         값이 바뀌지 않는다
  next[u]     배열의 배열           한 번 만들고 나면 바뀌지 않는다
  color[v]    배열 한 칸            흰색 → 회색 → 검은색 순서로만 바뀐다
  cursor[u]   배열 한 칸            0 에서 목록 길이까지 하나씩 올라간다
  stack       배열 하나             뒤에 넣고 뒤에서 꺼낸다
```

가장 먼저 떠오르는 방법으로 시작합시다. **정점 하나를 잡고 갈 수 있는 경로를 전부 따라가 보는
것**이에요. 지금 따라온 경로에 있는 정점을 다시 만나면 사이클이고, 아니면 다음 갈래로 갑니다.
기법이 하나도 안 들어간 풀이입니다.

```ts
// 표시를 지금 따라가는 경로에만 둔다. 되돌아 나올 때 표시를 지운다.
const onPath: boolean[] = Array.from({ length: n }, () => false);
function go(u: number): void {
  onPath[u] = true;
  for (const v of next[u]) {
    if (onPath[v]) found = true;   // 지금 경로 위에 있다 — 사이클이다
    else go(v);
  }
  onPath[u] = false;               // 되돌아 나오면서 표시를 지운다
}
```

이 방법은 답이 맞아요. 그런데 되돌아 나올 때 표시를 지우기 때문에, 같은 정점을 다른 경로로
다시 만나면 그 아래를 **처음부터 다시** 따라갑니다. 갈래가 합쳐지는 그래프를 이어 붙이면
걸음 수가 어떻게 되는지 실제로 세어 봅시다.

```text
다이아몬드 하나 — 갈래가 갈렸다가 다시 만나는 가장 작은 모양

  0 ──> 1 ──> 3              0 에서 3 으로 가는 경로가 둘이다
  │           ^              0 → 1 → 3
  └──> 2 ─────┘              0 → 2 → 3

다이아몬드 k 개를 이으면 0 에서 끝까지 가는 경로가 2^k 개가 된다
```

<!--proof:naive-scale-->

```text
다이아몬드 k   정점 V   간선 E   경로 수 2^k   따라간 간선 수
           1        4        4             2                6
           2        7        8             4               28
           4       13       16            16              200
           8       25       32           256            4,000
          12       37       48         4,096           65,400
          16       49       64        65,536        1,048,400
        └ 제약 안에서 k 를 25,000 까지 늘릴 수 있고(정점 75,001 · 간선 100,000),
          그때 경로 수 2^k 는 7,526 자리다
```

정점 49 개짜리 그래프에서 이미 간선을 백만 번 넘게 따라갑니다. 제약 상한에서는 경로 수를
적는 것조차 7,526 자리예요. 경로를 하나씩 세는 방식으로는 시작할 수 없습니다.

```text
방향을 바꾼다 — 같은 정점 아래를 두 번 따라가지 않는다

  정점 3 아래를 두 번 따라간다      0 → 1 → 3 에서 한 번, 0 → 2 → 3 에서 한 번
  두 번째에 나오는 답은 무엇인가    첫 번째와 똑같다. 3 아래의 그래프가 그대로다
    ┗ 그러니 두 번째는 따라갈 이유가 없다. 「끝났다」를 표시해 두면 된다
```

여기가 준비의 끝입니다. 절차의 모양이 정해졌어요 — 「끝난 정점에는 다시 안 내려간다」를
표시 하나로 적습니다. 남은 것은 **그 표시를 지금 따라가는 경로의 표시와 어떻게 가르는가**이고,
답이 맞고 틀리는 것이 전부 거기서 갈립니다. 먼저 표시를 더한 값이 얼마나 달라지는지 봅시다.

```text
두 방식을 같은 입력에 실행해 따라간 간선 수를 센다

  방식 A   표시를 지금 따라가는 경로에만 둔다
           되돌아 나오면서 표시를 지우므로 같은 정점 아래를 여러 번 따라간다
  방식 B   끝난 정점에 「검은색」 표시를 남긴다
           검은색 정점을 만나면 그 아래로 안 내려간다
```

```text
입력                        V     E   표시를 경로에만 둔다   끝난 정점을 검은색으로         배수
전개가 쓰는 여섯 정점       6     8                      9                        8       1.1 배
마름모 네 정점              4     4                      6                        4       1.5 배
다이아몬드 8 개            25    32                  4,000                       32     125.0 배
다이아몬드 16 개           49    64              1,048,400                       64   16381.3 배
사슬 1,000              1,000   999                499,500                      999     500.0 배
```

답은 두 방식이 같은데 걸음 수가 갈립니다. 다이아몬드 16 개에서 1,048,400 이 64 가 됐고, 사슬
1,000 에서는 499,500 이 999 가 됐어요. 방식 B 는 간선 하나를 정확히 한 번만 따라가므로 걸음 수가
`E` 로 고정됩니다.

> 끝난 정점에 **검은색** 표시를 남긴다. 검은색 정점으로 가는 간선을 만나면 그 아래로 다시
> 내려가지 않는다.

```text
표시 하나가 두 가지 일을 한꺼번에 하고 있다

  지금 따라가는 경로 위에 있다   되돌아온 것이라 사이클이다   방식 A 가 적은 것
  이미 끝났다                    다시 내려갈 이유가 없다      방식 B 가 더한 것
                                 └ 두 표시를 한 칸에 담으면 어떻게 되는가
```

여기서 관찰한 것은 하나입니다. 가장 단순한 후보는 그 둘을 하나로 합치는 것이에요 — **본 적이
있으면 전부 사이클로 판정하는** 방식입니다. 실제로 실행해 봅시다.

<!--proof:color-count-values-->

```text
입력                        색 둘 — 본 적 있으면 사이클   색 셋 — 정본
전개가 쓰는 여섯 정점       true                          true
마름모 네 정점              true                          false
교차 간선 0→1 · 0→2 · 1→2   true                          false
한 줄로 이은 네 정점        false                         false
간선이 없는 네 정점         false                         false
```

**둘째 줄과 셋째 줄에서 답이 틀립니다.** 마름모에는 사이클이 하나도 없는데 `true` 가 나왔어요.
`0 → 1 → 3` 을 따라가 3 을 끝낸 다음 `0 → 2 → 3` 으로 3 을 다시 만나는데, 그때 3 은 「본 적
있는 정점」이지만 **지금 경로 위에 있지는 않습니다.**

```text
마름모에서 3 을 두 번 만난다 — 두 번의 뜻이 다르다

  0 → 1 → 3         3 을 처음 만난다. 지금 경로는 [0,1,3]   3 아래를 따라간다
  1 로 되돌아온다   3 을 끝냈다. 지금 경로는 [0,1]          3 은 경로 위에 없다
  0 → 2 → 3         3 을 다시 만난다. 지금 경로는 [0,2]     3 은 경로 위에 없다
                    └ 여기서 사이클이라고 하면 틀린다. 되돌아온 것이 아니라 합쳐진 것이다
```

> 표시를 셋으로 가른다. **흰색**은 아직 확인하지 않았다, **회색**은 지금 따라가는 경로 위에 있다,
> **검은색**은 나가는 간선을 전부 확인하고 끝났다. **회색 정점으로 가는 간선만** 사이클이다.

각 색이 언제 칠해지는지를 여기서 정합니다. 위에서 실제로 확인한 것이 그 근거예요.

```text
  흰색 → 회색     그 정점을 경로에 넣을 때                      정점마다 한 번
  회색 → 검은색   그 정점의 목록을 다 확인하고 경로에서 뺄 때   정점마다 한 번
  검은색 → ?      다시 바뀌지 않는다                            한 번 끝나면 끝난 채로 남는다
                  └ 색이 바뀌는 횟수가 정점당 두 번으로 정해져 있다
```

**같은 정점을 여러 갈래에서 만나는 경우를 값으로 확인해 봅시다.** 쉬운 경우는 들어오는 갈래가
하나뿐인 자리예요 — 정점 1 은 `0 → 1` 로만 들어오므로 한 번 회색이 되고 한 번 검은색이 됩니다.
불안한 경우는 정점 3 입니다. `1 → 3` 과 `2 → 3` 둘로 들어오는데, 두 번째에 무슨 일이 일어나는지가
답을 가릅니다.

```text
정점 3 을 두 번 만나는 과정 — 색 배열 전체를 걸음마다 빠짐없이 적는다

  시작          0:흰 1:흰 2:흰 3:흰 4:흰 5:흰   경로 []          아직 아무것도 확인하지 않았다
  0 을 회색     0:회 1:흰 2:흰 3:흰 4:흰 5:흰   경로 [0]
  1 을 회색     0:회 1:회 2:흰 3:흰 4:흰 5:흰   경로 [0,1]
  3 을 회색     0:회 1:회 2:흰 3:회 4:흰 5:흰   경로 [0,1,3]     3 을 처음 만났다
  4 를 회색     0:회 1:회 2:흰 3:회 4:회 5:흰   경로 [0,1,3,4]
  4 를 검은색   0:회 1:회 2:흰 3:회 4:검 5:흰   경로 [0,1,3]     4 의 목록이 비었다
  3 을 검은색   0:회 1:회 2:흰 3:검 4:검 5:흰   경로 [0,1]       3 을 끝냈다
  1 을 검은색   0:회 1:검 2:흰 3:검 4:검 5:흰   경로 [0]
  0→4 를 확인   0:회 1:검 2:흰 3:검 4:검 5:흰   경로 [0]         4 가 검은색이라 넘어간다
  2 를 회색     0:회 1:검 2:회 3:검 4:검 5:흰   경로 [0,2]
  2→3 을 확인   0:회 1:검 2:회 3:검 4:검 5:흰   경로 [0,2]       3 이 검은색이라 넘어간다
```

왜 이것이 맞는지는 반복문의 종료 조건이 말해 줍니다. 정점 하나는 흰색일 때만 경로에 들어가고
경로에서 뺄 때 검은색이 되므로, 경로에 들어가는 총수가 `V` 로 정해져 있어요. 그리고 간선 하나는
`cursor` 가 그 자리를 지나가는 한 번만 확인되므로 확인 총수가 `E` 로 정해져 있습니다.

```text
회색 정점의 모임이 곧 스택이다

  경로에 넣는다   stack 뒤에 넣고 흰색을 회색으로 칠한다
  경로에서 뺀다   stack 뒤에서 꺼내고 회색을 검은색으로 칠한다
  지금 경로       stack 을 아래에서 위로 읽은 것
                  └ 그래서 「회색인가」를 묻는 것과 「스택에 있는가」를 묻는 것이 같다
```

**절차가 나왔습니다.** 간선 목록을 나가는 목록으로 옮기고, 흰색 정점 하나를 회색으로 칠해
스택에 넣고, 스택 꼭대기 정점의 목록을 `cursor` 로 하나씩 확인합니다. 회색을 만나면 `true`,
흰색을 만나면 회색으로 칠해 내려가고, 검은색이면 넘어가요. 목록을 다 확인하면 검은색으로
칠하고 뺍니다. 흰색 정점이 하나도 안 남을 때까지 이것을 되풀이하고, 끝까지 회색을 만나지
못하면 `false` 입니다.

### 수행으로 알아보는 알고리즘 — 간선 여덟 개를 차례로 확인한다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const n = 6;
const edges: [number, number][] = [[0, 1], [1, 3], [3, 4], [0, 4], [0, 2], [2, 3], [2, 5], [5, 0]];
// 이 절이 끝나면 true 가 나와야 한다
```

정점을 왜 여섯으로 뒀을까요? 간선 여덟 개가 **네 갈래를 모두 실행하기 때문**입니다. 흰색으로
내려가는 갈래가 다섯 번, 검은색이라 넘어가는 갈래가 두 번(`0 → 4` 와 `2 → 3`), 목록을 다 봐서
검은색으로 칠하는 갈래가 세 번 나오고, 마지막 간선 `5 → 0` 에서 회색을 만나 `true` 가 됩니다.

```text
directedCycleDetection(n, edges):
    간선 [u, v] 마다 next[u] 에 v 를 넣는다
    color 를 전부 흰색으로, cursor 를 전부 0 으로 둔다
    정점 s 를 0 부터 n-1 까지 보면서:
        s 가 흰색이 아니면 넘어간다
        s 를 회색으로 칠하고 stack 에 넣는다
        stack 이 비지 않은 동안:
            u ← stack 의 꼭대기
            cursor[u] 가 next[u] 의 길이와 같으면:
                u 를 검은색으로 칠하고 stack 에서 뺀다              ④ 목록을 다 확인했다
            아니면:
                v ← next[u][cursor[u]] 를 읽고 cursor[u] 를 하나 올린다
                v 가 회색이면 true 를 반환한다                      ① 되돌아왔다
                v 가 흰색이면 회색으로 칠하고 stack 에 넣는다       ② 내려간다
                v 가 검은색이면 아무것도 하지 않는다                ③ 넘어간다
    false 를 반환한다
```

#### 1. 간선 목록을 나가는 목록으로 옮기고 색을 준비한다

간선 목록은 「누가 누구를 가리키는가」를 담고 있지만 「정점 0 에서 나가는 간선이 무엇인가」를
묻기에는 불편합니다. 그 질문에 답하려면 목록 전체를 다시 읽어야 하니까요. 간선을 한 번 읽으면서
출발점별로 도착점을 모아 둡니다.

```ts
const next: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) (next[u] as number[]).push(v);

const color: number[] = Array.from({ length: n }, () => 0); // 0 흰색 · 1 회색 · 2 검은색
const cursor: number[] = Array.from({ length: n }, () => 0);
const stack: number[] = [];
```

실행하면 이렇게 나옵니다. 간선을 적은 순서가 그대로 목록의 순서가 되는 것이 보여요.

```text
edges = [[0,1], [1,3], [3,4], [0,4], [0,2], [2,3], [2,5], [5,0]]

  next[0] = [1, 4, 2]     0 에서 나가는 간선 셋. 적힌 순서대로 1 · 4 · 2
  next[1] = [3]           1→3
  next[2] = [3, 5]        2→3 과 2→5
  next[3] = [4]           3→4
  next[4] = []            나가는 간선이 없다
  next[5] = [0]           5→0
                          └ 목록 길이의 합 8 = E

  color  = 0:흰 1:흰 2:흰 3:흰 4:흰 5:흰    전부 흰색
  cursor = [0,0,0,0,0,0]                    아직 아무 목록도 확인하지 않았다
```

#### 2. 스택 꼭대기의 간선을 하나씩 확인한다

여기가 판정이 일어나는 자리입니다. 스택 꼭대기 정점을 꺼내지 않고 **보기만** 하고, 그 정점의
목록에서 `cursor` 가 가리키는 간선 하나를 확인해요. 확인한 간선의 도착 정점 색에 따라 셋 중
하나를 합니다.

```ts
while (stack.length > 0) {
  const u = stack[stack.length - 1] as number;
  const list = next[u] as number[];
  const i = cursor[u] as number;

  if (i === list.length) {
    // ④ 나가는 간선을 다 확인했다. 검은색으로 칠하고 경로에서 뺀다.
    color[u] = 2;
    stack.pop();
    continue;
  }

  cursor[u] = i + 1;
  const v = list[i] as number;

  if (color[v] === 1) return true;              // ① 회색 — 되돌아왔다
  if (color[v] === 0) { color[v] = 1; stack.push(v); }  // ② 흰색 — 내려간다
  // ③ 검은색 — 아무것도 하지 않는다
}
```

가장 중요한 줄은 `if (color[v] === 1) return true;` 입니다. 회색인지만 묻고 검은색인지는 묻지
않는 것이 이 절차의 핵심이에요. `cursor[u] = i + 1` 은 그 줄과 짝입니다 — 확인한 간선을 다시
확인하지 않게 자리를 하나 올려 두는 것이고, 재귀로 적었다면 「돌아온 지점」이 하던 일입니다.

```text
정점 0 을 꼭대기에 두고 next[0] = [1, 4, 2] 를 차례로 확인한다

  cursor[0] = 0   v = 1   1 이 흰색이다     ② 회색으로 칠하고 stack 에 넣는다
  (1 아래를 다 확인하고 되돌아온 다음)
  cursor[0] = 1   v = 4   4 가 검은색이다   ③ 아무것도 하지 않는다
  cursor[0] = 2   v = 2   2 가 흰색이다     ② 회색으로 칠하고 stack 에 넣는다
  cursor[0] = 3   목록 길이 3 과 같다       ④ 여기 오면 0 을 검은색으로 칠한다
```

#### 멈춤 — 본 적 있는 정점을 만나면 사이클이라고 읽기 쉽다

`color` 를 「봤다 · 안 봤다」 두 값으로 두고 싶어집니다. 사이클을 「이미 지나온 정점을 다시
만나는 것」이라고 읽으면 그것으로 충분해 보이니까요. 그 오해대로 적으면 이렇게 됩니다.

```ts
// 오해대로 적은 코드 — 회색인지 검은색인지 가르지 않는다
if (color[v] !== 0) return true; // ← 「흰색이 아니면 사이클」
```

이 코드는 예외를 내지 않습니다. 그리고 **어떤 입력에서는 답까지 같아요.**

<!--proof:mutant-two-color-->

```text
                            회색만 사이클로 본다   흰색이 아니면 사이클로 본다
전개가 쓰는 여섯 정점       true                   true
마름모 네 정점              false                  true
교차 간선 0→1 · 0→2 · 1→2   false                  true
한 줄로 이은 네 정점        false                  false
간선이 없는 네 정점         false                  false
```

첫 줄과 마지막 두 줄이 그 자리입니다. 사이클이 진짜 있는 그래프와, 갈래가 한 번도 합쳐지지
않는 그래프에서는 두 코드가 같은 답을 냅니다. **테스트가 이런 입력만 담고 있으면 색을 둘로
줄여 놓고도 통과해요.** 둘째·셋째 줄에서는 사이클이 없는 그래프에 `true` 를 답합니다.

```text
교차 간선 0→1 · 0→2 · 1→2 에서 무슨 일이 일어나는가

  0 을 회색         경로 [0]
  0→1 을 확인       1 이 흰색   회색으로 칠하고 내려간다   경로 [0,1]
  1→2 를 확인       2 가 흰색   회색으로 칠하고 내려간다   경로 [0,1,2]
  2 · 1 을 검은색   경로 [0]    두 정점을 끝냈다
  0→2 를 확인       2 가 검은색
                    ┗ 색이 셋이면 ③ 으로 넘어간다.                        false
                    ┗ 색이 둘이면 「본 적 있다」라 사이클로 판정한다.     true
```

#### 3. 여섯 정점의 간선 여덟 개를 처음부터 끝까지 확인한다

앞의 두 조각을 이어 실제로 실행하면 열두 단계가 나옵니다. 갈래 `①`·`②`·`③`·`④` 가 각각
어디서 실행되는지를 함께 적었어요.

마지막에 ① 이 한 번 실행됩니다. 반환값은 `true` 입니다.

```text
①  회색이라 사이클이다        T12                       한 번. 여기서 즉시 반환한다
②  흰색이라 내려간다          T2 · T3 · T4 · T9 · T11   다섯 번 = 흰색이던 정점 수
③  검은색이라 넘어간다        T8 · T10                  두 번
④  목록을 다 확인해 뺀다      T5 · T6 · T7              세 번

간선 확인 8 = E,  ② + 시작 = 6 = V,  ④ 는 아직 셋뿐이다 — ① 에서 즉시 반환했기 때문이다
```

여기서 헷갈리기 쉬운 지점은 T8 입니다. `0 → 4` 를 확인할 때 정점 4 는 이미 검은색이에요.
T4 에서 `3 → 4` 로 내려가 T5 에서 끝냈기 때문입니다. 간선 `0 → 4` 는 그래프에 분명히 있지만
이 절차는 그것을 따라 내려가지 않고 넘어갑니다.

#### 멈춤 — 정점 0 에서 한 번만 시작해도 될 것 같다

바깥 `for` 문이 왜 필요한지 흐릿합니다. 정점 0 에서 시작해 간선을 따라가면 그래프 전체를 볼 수
있을 것 같으니까요. 그 오해대로 적으면 바깥 반복이 사라집니다.

```ts
// 오해대로 적은 코드 — 정점 0 에서 한 번만 시작한다
color[0] = 1;
stack.push(0);
while (stack.length > 0) { /* 위와 같다 */ }
return false;
```

유향 그래프는 **정점 0 에서 도달할 수 없는 정점**을 가질 수 있습니다. 그래프가 여러 조각으로
나뉘어 있을 수도 있고, 한 조각 안에서도 방향 때문에 못 가는 자리가 있어요.

<!--proof:component-values-->

```text
입력                               0 에서 한 번만 시작한다   모든 흰색 정점에서 시작한다
0→1 과 사이클 2→3→4→2              false                     true
자기 루프가 정점 3 에 있다         false                     true
사이클이 0 에서 이어진다 0→1→2→0   true                      true
전개가 쓰는 여섯 정점              true                      true
```

첫 줄이 반례입니다. 정점 0 에서 갈 수 있는 곳은 1 뿐인데 사이클은 2·3·4 에 있어요. 아래 세 줄에서는
두 코드의 답이 같아서, 그런 입력만 시험하면 바깥 반복을 지워 놓고도 통과합니다.

```text
0→1 과 사이클 2→3→4→2 에서 무슨 일이 일어나는가

  0 에서만 시작     0 을 회색, 1 을 회색, 1 의 목록이 비어 검은색, 0 도 검은색
                    ┗ 2·3·4 는 흰색인 채로 남는다.                              false
  s = 2 에서 다시   2 를 회색, 3 을 회색, 4 를 회색, 4→2 를 확인하니 회색
                    ┗ 바깥 for 문이 흰색 정점을 다시 잡아 준다.                 true
```

#### 멈춤 — cursor 없이 목록을 매번 처음부터 확인해도 된다

`cursor` 배열이 없어도 될 것 같습니다. 스택 꼭대기를 볼 때마다 `next[u]` 를 처음부터 확인하면서
흰색 정점이 나오면 내려가고, 끝까지 흰색이 없으면 검은색으로 칠하면 되니까요. **이 방식은 답이
틀리지 않습니다.** 이미 확인한 간선의 도착 정점은 회색이거나 검은색이라 다시 확인해도 같은
갈래로 가고, 사이클이 있으면 여전히 회색을 만나요.

```ts
// cursor 없이 적은 코드 — 꼭대기를 볼 때마다 목록을 처음부터 확인한다
for (const v of next[u] as number[]) {
  if (color[v] === 1) return true;
  if (color[v] === 0) { color[v] = 1; stack.push(v); descended = true; break; }
}
if (!descended) { color[u] = 2; stack.pop(); }
```

답이 안 틀리는데도 고치는 이유는 걸음 수입니다. 정점 `u` 가 꼭대기에 오는 횟수가 「내려간
횟수 + 1」이고 그때마다 목록 앞부분을 다시 읽으므로, 읽은 원소 수가 목록 길이의 제곱에
비례해요.

<!--proof:cursor-values-->

```text
입력                        E   cursor 를 둔다   매번 처음부터   답이 같은가
전개가 쓰는 여섯 정점       8                8              11   같다 (true)
마름모 네 정점              4                4               8   같다 (false)
별 모양 1,000             999              999         500,499   같다 (false)
별 모양 10,000          9,999            9,999      50,004,999   같다 (false)
사슬 10,000             9,999            9,999          19,998   같다 (false)
```

**답 칸이 다섯 줄 다 「같다」입니다.** 갈리는 것은 읽은 원소 수예요. 정점 0 이 나머지 전부를
가리키는 별 모양에서 999 가 50 만이 되고, 정점을 열 배로 늘리면 5,000 만이 됩니다.

```text
별 모양 1,000 에서 정점 0 이 꼭대기에 오는 횟수는 1,000 번이다

  첫 번째      next[0] 의 0 번 자리가 흰색이다       1 개 읽는다
  두 번째      0 번은 검은색, 1 번이 흰색이다        2 개 읽는다
  세 번째      0·1 번은 검은색, 2 번이 흰색이다      3 개 읽는다
  999 번째     997 번까지 검은색, 998 번이 흰색이다  999 개 읽는다
  1,000 번째   999 개가 전부 검은색이다              999 개 읽고 0 을 검은색으로 칠한다
               └ (1 + 2 + … + 999) + 999 = 499,500 + 999 = 500,499 다
```

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 **바깥 `for` 문과 마지막
`return false` 한 줄**뿐이에요 — 앞의 조각들은 한 출발점에서의 탐색만 적었고, 흰색 정점이
남았는지 확인하고 끝을 내는 자리가 여기입니다.

```ts
export function directedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean {
  // 간선 목록을 정점마다의 나가는 목록으로 옮긴다.
  const next: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) (next[u] as number[]).push(v);

  const color: number[] = Array.from({ length: n }, () => WHITE);
  // cursor[u] 는 next[u] 에서 다음에 확인할 자리다. 재귀에서 「돌아온 지점」이 하던 일을 한다.
  const cursor: number[] = Array.from({ length: n }, () => 0);
  const stack: number[] = [];

  for (let s = 0; s < n; s++) {
    if (color[s] !== WHITE) continue;
    color[s] = GRAY;
    stack.push(s);

    while (stack.length > 0) {
      const u = stack[stack.length - 1] as number;
      const list = next[u] as number[];
      const i = cursor[u] as number;

      if (i === list.length) {
        // ④ 나가는 간선을 다 확인했다. 검은색으로 칠하고 경로에서 뺀다.
        color[u] = BLACK;
        stack.pop();
        continue;
      }

      cursor[u] = i + 1;
      const v = list[i] as number;

      // ① 회색 정점으로 가는 간선이다. 지금 경로 위의 정점으로 되돌아왔으므로 사이클이다.
      if (color[v] === GRAY) return true;

      // ② 흰색이면 아직 안 본 정점이다. 회색으로 칠하고 그 정점으로 내려간다.
      if (color[v] === WHITE) {
        color[v] = GRAY;
        stack.push(v);
      }

      // ③ 검은색이면 이미 끝난 정점이다. 아무것도 하지 않고 다음 간선으로 넘어간다.
    }
  }

  return false;
}
```

`WHITE`·`GRAY`·`BLACK` 은 0·1·2 를 가리키는 이름입니다. 실행하면 이렇게 나옵니다.

<!--proof:walk-result-->

```text
directedCycleDetection(6, [[0,1],[1,3],[3,4],[0,4],[0,2],[2,3],[2,5],[5,0]])   →   true
directedCycleDetection(4, [[0,1],[0,2],[1,3],[2,3]])                           →   false
directedCycleDetection(3, [[0,1],[0,2],[1,2]])                                 →   false
directedCycleDetection(4, [[0,1],[1,2],[2,3],[3,1]])                           →   true
directedCycleDetection(2, [[0,1],[1,0]])                                       →   true
directedCycleDetection(1, [[0,0]])                                             →   true
directedCycleDetection(5, [])                                                  →   false
```

### 알아 두면 좋은 개념 — 깊이 우선 탐색의 간선 분류

전개에서 간선 여덟 개를 확인할 때마다 도착 정점의 색이 셋 중 하나였습니다. 그 색이 그대로
간선의 종류를 정해요. 깊이 우선 탐색이 그래프의 간선을 넷으로 가르는 방식이고, 이 편이 찾는
것은 그중 하나입니다.

<!--proof:edge-classes-->

```text
간선    확인할 때 도착 정점의 색   분류          사이클인가
0 → 1   흰색                       나무 간선     아니다
1 → 3   흰색                       나무 간선     아니다
3 → 4   흰색                       나무 간선     아니다
0 → 4   검은색                     순방향 간선   아니다
0 → 2   흰색                       나무 간선     아니다
2 → 3   검은색                     교차 간선     아니다
2 → 5   흰색                       나무 간선     아니다
5 → 0   회색                       역방향 간선   그렇다
```

넷의 이름은 이렇습니다. **나무 간선**은 탐색이 실제로 따라 내려간 간선이고, **역방향 간선**은
지금 경로 위의 정점으로 되돌아오는 간선입니다. 검은색으로 가는 간선은 둘로 갈리는데, 도착 정점이
출발 정점의 자손이면 **순방향 간선**, 아니면 **교차 간선**이에요.

| 분류 | 도착 정점의 색 | 이 편에서 | 넷 중 사이클을 뜻하는 것 |
| --- | --- | --- | --- |
| 나무 간선 | 흰색 | ② 로 내려간 다섯 간선 | 아니다 |
| 역방향 간선 | 회색 | `5 → 0` 하나 | **그렇다** |
| 순방향 간선 | 검은색 | `0 → 4` — 4 는 `0 → 1 → 3 → 4` 로 이어진 자손이다 | 아니다 |
| 교차 간선 | 검은색 | `2 → 3` — 3 은 2 의 자손이 아니다 | 아니다 |

**유향 그래프에 사이클이 있다는 것과 역방향 간선이 있다는 것이 같은 말입니다.** 이 편의 절차는
그 하나만 찾는 것이고, 나머지 셋은 찾을 필요가 없어서 `③` 한 갈래로 묶여 있어요. 같은 분류가
편 밖에서도 그대로 쓰입니다 — 강한 연결 요소를 찾을 때, 무향 그래프의 단절점과 다리를 찾을 때
모두 이 넷을 기준으로 논증합니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 식으로 무엇이 나오는지, 무엇이
매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **묻는 것이 있는가 없는가입니다.** 사이클이 있는지만 답하면 되고, 사이클을 전부 세거나
  가장 짧은 것을 찾으라는 것이 아니어야 해요. 세는 문제는 규모가 통째로 다릅니다.
- **간선에 방향이 있습니다.** 무향 그래프에서는 같은 간선을 되돌아오는 것이 사이클이 아니라
  방금 온 경로라, 부모를 기억하는 다른 판정이 필요해요.
- **그래프를 미리 다 받아 둘 수 있습니다.** 간선을 한 번에 받아 나가는 목록을 만들고 시작하니까요.

```text
세 조건이 코드의 모양을 그대로 정한다
  있는지만 묻는다   → 회색을 만나는 순간 반환한다. 나머지 간선을 안 확인해도 된다
  방향이 있다       → 온 경로를 기억할 필요가 없다. 색 하나로 판정된다
  미리 다 받는다    → next 를 먼저 만들고 그 뒤로는 새 간선을 받지 않는다
```

사이클을 **세는** 문제로 바뀌면 이 절차를 그대로 쓸 수 없다는 것은 값으로 확인됩니다. 다이아몬드
16 개를 이은 그래프는 사이클이 하나도 없는데도 서로 다른 경로가 65,536 개예요. 사이클이 있는
그래프라면 그 규모의 사이클을 전부 세는 일이 됩니다.

```text
같은 그래프에서 두 질문의 비용

  사이클이 있는가      간선을 한 번씩 확인한다         V + E 에 비례한다
  사이클이 몇 개인가   경로를 하나씩 세어야 한다       2^k 규모가 된다
                       └ 앞은 간선 64 개를 확인하고 끝나고, 뒤는 65,536 개를 센다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "순환 의존"   "circular dependency"   "데드락"   "빌드가 불가능한 경우"
  "설치할 수 없으면 -1"                  "가능/불가능만 출력"

제약에 이런 모양이 보이면
  정점과 간선이 각각 10만 규모이고 시간이 1~2초   ← V + E 규모의 절차를 찾으라는 뜻이다
  답이 true / false 하나다                        ← 찾는 즉시 반환해도 된다는 뜻이다
  자기 자신을 가리키는 간선이 있을 수 있다        ← 길이 1 짜리 사이클을 빼먹지 말라는 뜻이다
```

반대로 **「실제 순서를 출력하라」·「무향 그래프에서」** 가 보이면 이 절차를 그대로 쓰지
않습니다. 앞은 사이클이 없을 때 나열까지 만들어야 하는 문제라
[`topologicalSort` 가이드](../topologicalSort/topologicalSort-guide.md)의 절차가 답이고, 뒤는
간선에 방향이 없어 판정 자체가 달라져
[`undirectedCycleDetection` 가이드](../undirectedCycleDetection/undirectedCycleDetection-guide.mdx)가
다루는 문제가 됩니다.

#### 실제로 쓰이는 곳

- **ninja 빌드 시스템** — 의존 그래프에 순환이 있는지 확인하는 데 이 글과 같은 색 셋을 씁니다.
  `src/graph.h` 가 `Edge` 안에 *"enum VisitMark : char { VisitNone, VisitInStack, VisitDone };"*
  를 두고 `VisitMark mark_ = VisitNone;` 로 초기화하는데, 셋이 각각 이 글의 흰색·회색·검은색과
  같아요. `src/graph.cc` 의 `VerifyDAG` 가 `if (edge->mark_ != Edge::VisitInStack) return true;`
  로 「지금 스택에 있는가」만 묻고, 그 조건이 참일 때 `*err = "dependency cycle: ";` 로 순환을
  알립니다 — 이 글의 ① 갈래 그대로입니다.
  ([ninja-build/ninja src/graph.h](https://raw.githubusercontent.com/ninja-build/ninja/master/src/graph.h) ·
  [src/graph.cc](https://raw.githubusercontent.com/ninja-build/ninja/master/src/graph.cc), 조회 2026-09-03)
- **PostgreSQL 의 데드락 검출** — 「누가 누구를 기다리는가」를 유향 그래프로 두고 사이클을
  찾습니다. `src/backend/storage/lmgr/deadlock.c` 의 `FindLockCycle` 주석이
  *"Scan outward from the given proc to see if there is a cycle in the waits-for graph that
  includes this proc. Return true if a cycle is found, else false."* 라 적어 반환값이 이 글과
  같은 `bool` 임을 밝히고, 실제 탐색을 하는 `FindLockCycleRecurse` 가
  *"If we return to starting point, we have a deadlock cycle"* 로 판정 자리를 적습니다.
  ([postgres/postgres src/backend/storage/lmgr/deadlock.c](https://raw.githubusercontent.com/postgres/postgres/master/src/backend/storage/lmgr/deadlock.c), 조회 2026-09-03)

두 곳 다 **깊이 우선 탐색으로 내려가면서 「지금 스택에 있는 정점인가」를 묻는** 방식입니다.
ninja 는 색 셋을 이름까지 그대로 두었고, PostgreSQL 은 출발점 하나로 되돌아오는지를 묻는
형태로 같은 판정을 합니다.

#### 경쟁 설계와의 대조

같은 답을 내는 다른 절차가 있습니다. **진입차수 세기**예요 — 정점마다 들어오는 간선 수를 세어
두고 그 수가 0 인 정점을 큐에 담아 하나씩 꺼내면서 도착 정점의 수를 줄입니다. 큐가 빈 뒤에
꺼낸 정점 수가 `n` 보다 작으면 남은 정점들이 사이클을 이루고 있어요.
([`topologicalSort` 가이드](../topologicalSort/topologicalSort-guide.md)가 그 절차를 만듭니다.)

```text
두 절차가 사이클을 판정하는 자리가 다르다

  삼색 표시       회색 정점으로 가는 간선을 만나는 순간           그 자리에서 반환한다
  진입차수 세기   큐가 빈 뒤 꺼낸 정점 수를 n 과 견줄 때          전부 처리한 다음이다
                  └ 앞은 중간에 끝날 수 있고 뒤는 끝까지 가야 한다
```

**전개가 쓰는 입력을 첫 줄에서 그대로 잽니다.** 다만 정점이 여섯이면 「사이클이 정점 0 에서
몇 걸음 떨어져 있는가」를 바꿔 볼 자리가 없어 순서가 뒤집히는 것을 보일 수 없어요. 그래서
제약 상한인 정점 100,000 을 쓰는 생성식 셋을 함께 씁니다 — 사슬은 `0→1→…→99,999`, 되돌아가는
간선은 `p+1 → p` 를 목록 맨 앞에, 씨앗을 막는 것은 `99,999 → 0` 이고, 셋 다
`directedCycleDetection-guide.alt.ts` 에 상수로 두었습니다.

<!--proof:alt-flip-->

```text
재는 것                                              삼색 표시   진입차수 세기   어느 쪽이 적은가
전개가 쓰는 여섯 정점에서 배열 칸 접근                     110              50   진입차수 세기
사이클이 정점 0 에서 두 걸음일 때 배열 칸 접근         500,025         700,006   삼색 표시
사이클이 정점 0 에서 99,992 걸음일 때 배열 칸 접근   1,299,945       1,299,946   삼색 표시
사이클이 정점 0 에서 99,993 걸음일 때 배열 칸 접근   1,299,953       1,299,952   진입차수 세기
사이클이 씨앗을 전부 막을 때 배열 칸 접근            1,300,001         700,000   진입차수 세기
사이클이 없는 사슬에서 배열 칸 접근                  1,899,992       1,299,994   진입차수 세기
사이클이 없는 사슬에서 새로 잡는 칸                    499,999         399,999   진입차수 세기
```

**순서가 실제로 뒤집힙니다.** 전개 입력에서는 110 대 50 으로 진입차수 세기가 앞서는데, 사이클이
정점 0 에서 두 걸음인 큰 입력에서는 500,025 대 700,006 으로 삼색 표시가 앞서요. 사이클이 진입차수
0 인 정점을 전부 막으면 1,300,001 대 700,000 으로 다시 진입차수 세기이고, 사이클이 아예 없으면
1,899,992 대 1,299,994 로 역시 진입차수 세기입니다.

```text
뒤집히는 경계를 값으로 댄다 — 두 계수는 p 에 대해 기울기 8 과 6 인 직선이라 자리가 하나뿐이다

  p = 99,991   사이클이 정점 0 에서 99,992 걸음   1,299,945 대 1,299,946   삼색 표시가 적다
  p = 99,992   사이클이 정점 0 에서 99,993 걸음   1,299,953 대 1,299,952   진입차수 세기가 적다
               └ 경계는 「탐색이 사이클에 도달하기까지 확인하는 간선 수」다
```

**내주는 축이 둘입니다.** 하나는 사이클이 없을 때의 계수예요 — 삼색 표시는 정점마다 색 배열과
`cursor` 배열 둘을 쓰므로 1,899,992 대 1,299,994 로 밀립니다. 다른 하나는 새로 잡는 칸으로,
499,999 대 399,999 로 `cursor` 배열 한 벌만큼 늘 더 씁니다. 대신 얻는 것은 **중간에 끝낼 수
있다는 것**과 **사이클을 이루는 정점이 스택에 그대로 남는다는 것**이에요 — 「어디가 순환인가」를
같이 물으면 삼색 표시는 스택을 그대로 출력하면 되고, 진입차수 세기는 남은 정점을 따로 모아야
합니다.

### 수식 정의와 유도

정점 집합 $\mathcal{V}$ 와 간선 집합 $\mathcal{E}$ 로 이루어진 유향 그래프를 $G$ 라 적습니다.
$t$ 번째 간선을 확인한 직후 회색인 정점을 스택 아래에서 위로 늘어놓은 열이 $P_t$ 예요.
열의 길이를 $m = |P_t|$ 라 적고, 그 원소를 $P_t = (x_0, x_1, \dots, x_{m-1})$ 로 적습니다.
**$V$ 와 $E$ 는 파트 1 에서 정한 그대로 정점 수와 간선 수이고, 집합이 아니라 수입니다** —
집합과 열의 크기는 $|\mathcal{V}|$ · $|P_t|$ 처럼 세로줄로 적습니다.

| 이름 | 정의 | 이 그래프에서 |
| --- | --- | --- |
| $G = (\mathcal{V}, \mathcal{E})$ | 유향 그래프 | $\|\mathcal{V}\| = V = 6$, $\|\mathcal{E}\| = E = 8$ |
| $P_t$ | $t$ 번째 간선을 확인한 직후 회색인 정점의 열 | $P_1 = (0, 1)$ |
| $c_t(v)$ | 그때 정점 $v$ 의 색 | 코드에서는 `color[v]` 다 |
| $A(V, E)$ | 절차가 읽고 쓴 배열 칸의 총수 | 아래에서 센다 |

먼저 $P_t$ 를 정의 그대로 적어 검산합시다. 열의 이웃한 두 정점 사이에는 반드시 간선이 있어야
해요 — 회색으로 칠하는 자리가 「간선을 따라 내려갈 때」 하나뿐이기 때문입니다.

$$P_t = (x_0, x_1, \dots, x_{m-1}) \;\Longrightarrow\; (x_{i}, x_{i+1}) \in \mathcal{E} \quad (0 \le i < m-1)$$

```text
전개 입력에서 확인한다 — t 는 간선을 확인한 차례다

  t = 1   T2 직후    P_1 = (0, 1)          간선 0→1 이 있다
  t = 2   T3 직후    P_2 = (0, 1, 3)       0→1 과 1→3 이 있다
  t = 3   T4 직후    P_3 = (0, 1, 3, 4)    0→1 · 1→3 · 3→4 가 있다
  t = 6   T10 직후   P_6 = (0, 2)          0→2 가 있다
  t = 8   T12 직후   P_8 = (0, 2, 5)       0→2 와 2→5 가 있다
          └ 어느 열에서도 이웃한 두 정점 사이에 간선이 있다
```

이제 **회색 정점으로 가는 간선이 있다는 것과 사이클이 있다는 것이 같다**를 유도합니다. 두
방향을 각각 봅시다.

$$\exists\, (u, v) \in \mathcal{E} : c_t(v) = \text{회색} \;\;\Longleftrightarrow\;\; G \text{ 에 사이클이 있다}$$

```text
왼쪽에서 오른쪽 — 회색으로 가는 간선이 있으면 사이클이 있다

  간선 (u, v) 를 확인하는 순간 u 는 스택 꼭대기이고 v 는 회색이다
  v 가 회색이므로 v 는 스택 어딘가에 있다. 그 자리를 i 라 하자
  스택은 이웃끼리 간선으로 이어져 있다(위 정의)
    ┗ v = x_i → x_{i+1} → … → x_{m-1} = u 라는 경로가 있다
    ┗ 거기에 간선 (u, v) 를 붙이면 v 에서 출발해 v 로 되돌아오는 경로가 된다
```

반대 방향은 반대로 가정해서 유도합니다. 사이클 $C$ 가 있는데 이 절차가 회색을 한 번도 못
만났다고 하면, $C$ 위의 정점 중 **가장 먼저 회색이 된 것**을 $w$ 라 두겠습니다. 절차가 끝날
때 모든 정점이 검은색이므로 $w$ 도 검은색이 됐고, 검은색이 되려면 $w$ 의 나가는 간선을 전부
확인해야 해요.

```text
오른쪽에서 왼쪽 — 사이클이 있으면 회색으로 가는 간선을 반드시 만난다

  C 위에서 w 다음 정점을 w' 라 하자. 간선 (w, w') 는 w 의 나가는 간선이다
  w 를 검은색으로 칠하기 전에 (w, w') 를 확인한다
  그때 w' 의 색은 셋 중 하나다
    흰색이면      w' 로 내려간다. 그러면 w' 가 회색이 되는데 w 보다 늦다 — 가정과 맞다
    검은색이면    w' 가 w 보다 먼저 회색이 됐어야 한다 — w 가 가장 먼저라는 가정과 어긋난다
    회색이면      회색으로 가는 간선을 만난 것이라 처음 가정과 어긋난다
  흰색인 경우를 C 를 따라 되풀이하면 마지막에는 w 로 돌아오는 간선을 확인하게 된다
    ┗ 그때 w 는 아직 회색이다. 나가는 간선을 다 확인하기 전이기 때문이다
```

이제 배열 칸 접근 수 $A(V, E)$ 를 코드에서 그대로 셉니다. 사이클이 없어 끝까지 확인하는
경우예요.

$$A(V, E) = \underbrace{3V}_{\text{배열 셋}} + \underbrace{2E}_{\text{목록 만들기}} + \underbrace{V}_{\text{바깥 for}} + \underbrace{3(V + E)}_{\text{꼭대기 확인}} + \underbrace{2V}_{\text{검은색으로}} + \underbrace{3E}_{\text{간선 하나}} + \underbrace{2V}_{\text{내려가기}} = 11V + 8E$$

```ts
// 각 항이 어느 줄에서 나오는지 — 왼쪽 수가 그 줄이 만드는 칸 접근 수다.
//  3V   Array.from 세 번 — next · color · cursor
//  2E   next[u] 읽기 + push
//   V   for (let s = 0; s < n; s++) 의 color[s] 읽기
// 3V+3E 꼭대기를 볼 때마다 stack 읽기 + next[u] 읽기 + cursor[u] 읽기
//  2V   color[u] 쓰기 + stack.pop
//  3E   cursor[u] 쓰기 + list[i] 읽기 + color[v] 읽기
//  2V   color[v] 쓰기 + stack.push — 시작점과 ② 갈래를 합쳐 정점당 한 번
const cellsPerVertex = 11;
const cellsPerEdge = 8;
const closedForm = (V: number, E: number): number =>
  cellsPerVertex * V + cellsPerEdge * E;
```

식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

```text
입력                     V        E   실제 배열 칸 접근    11V + 8E
마름모 네 정점           4        4                  76          76
다이아몬드 16 개        49       64               1,051       1,051
사슬 1,000           1,000      999              18,992      18,992
별 모양 1,000        1,000      999              18,992      18,992
사슬 100,000       100,000   99,999           1,899,992   1,899,992
```

**다섯 줄이 전부 정확히 맞습니다.** 셋째 줄과 넷째 줄이 같은 값이라는 것도 함께 보세요 — 사슬과
별 모양은 모양이 완전히 다른데 계수가 같습니다. 이 식에 정점 수도 간선 수도 아닌 항이 없기
때문이에요.

마지막으로 제약 규모를 넣습니다. $V = E = 100{,}000$ 이면 $A = 1{,}100{,}000 + 800{,}000$ 입니다.

| 항 | 무엇을 세는가 | 그때의 값 |
| --- | --- | --- |
| $11V$ | 배열 셋 · 바깥 반복 · 꼭대기 확인 · 색 칠하기 | 1,100,000 |
| $8E$ | 목록 만들기 · 간선 하나 확인하기 | 800,000 |
| $A$ | 합 | 1,900,000 |
| 경로를 하나씩 세기 | 다이아몬드 25,000 개의 $2^{25{,}000}$ 가지 | 7,526 자리 |

190 만과 7,526 자리를 견주면 이 절차가 무엇을 바꿨는지가 수로 나옵니다. 경로를 하나씩 세는 문제를
**간선을 한 번씩 확인하는 문제로** 바꾼 것이에요.

### 불변식 — 회색 정점의 모임은 지금 따라가는 경로다

파트 1 에서 코드가 동작하는 것을 열두 단계로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> 반복문의 한 바퀴가 끝날 때마다, 회색인 정점의 모임은 `stack` 에 들어 있는 정점의 모임과
> **정확히 같습니다.** 그리고 `stack` 을 아래에서 위로 읽으면 이웃한 두 정점 사이에 간선이
> 있어, 그것이 정점 하나에서 출발해 지금 자리까지 온 경로 하나가 됩니다.

```text
                     회색인 정점            stack
                   ┌────────────────┐   ┌────────────────┐
   T4 직후         │  0 · 1 · 3 · 4 │ = │   [0,1,3,4]    │
                   └────────────────┘   └────────────────┘
                          │                     │
                          └─────────────────────┴─ 0 → 1 → 3 → 4 라는 경로 하나
```

「한 바퀴가 끝날 때마다」가 중요합니다. 반복이 다 끝난 뒤 한 번만 참인 것이 아니라 **간선 하나를
확인한 직후마다** 참이라는 뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** 바깥 `for` 문이 흰색 정점 `s` 를 회색으로 칠하고 `stack` 에 넣는 순간,
회색인 정점은 `s` 하나이고 `stack` 도 `[s]` 하나입니다. 길이 1 짜리 경로는 이웃 조건을 만족해요.
그 뒤로 상태를 바꾸는 갈래는 셋입니다.

| 무슨 일 | 무엇이 바뀌는가 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| 흰색 정점 `v` 로 내려간다 | `v` 를 회색으로 칠하고 `stack` 에 넣는다 | 둘을 같은 자리에서 함께 하므로 두 모임이 어긋나지 않는다. 그 직전 꼭대기가 `u` 이고 간선 `(u, v)` 를 확인한 것이라 이웃 조건도 지켜진다 |
| 목록을 다 확인해 뺀다 | `u` 를 검은색으로 칠하고 `stack` 에서 뺀다 | 이것도 같은 자리에서 함께 한다. 꼭대기 하나만 빠지므로 남은 열의 이웃 관계는 그대로다 |
| 검은색 정점을 만난다 | 아무것도 하지 않는다 | 색도 `stack` 도 안 바뀌므로 유지된다 |

첫 줄과 둘째 줄의 「함께 한다」가 어디서 오는지 값으로 확인해 봅시다. 전개의 T4 와 T5 가 그
자리예요.

```text
T4 직후   회색 0·1·3·4   stack [0,1,3,4]   4 를 칠하는 줄과 넣는 줄이 붙어 있다   같다
T5 직후   회색 0·1·3     stack [0,1,3]     4 를 칠하는 줄과 빼는 줄이 붙어 있다   같다
```

이 불변식이 답의 정확성을 그대로 줍니다. 회색 정점으로 가는 간선을 만났다는 것은 **지금 경로 위의
정점으로 가는 간선을 만났다**는 뜻이고, 경로를 따라 그 정점까지 이어 붙이면 사이클이 되니까요.
반대로 검은색 정점으로 가는 간선은 경로 위에 없는 정점을 가리키므로 사이클을 만들지 않습니다.

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| 정점 하나 `directedCycleDetection(1, [])` | `next[0]` 이 비어 바로 검은색이 된다 | `false` |
| 간선 없음 `directedCycleDetection(5, [])` | 다섯 정점이 각각 회색 → 검은색으로 한 번씩 | `false` |
| 자기 루프 `directedCycleDetection(1, [[0,0]])` | `0` 이 회색인 채로 `0 → 0` 을 확인한다 | `true` |
| 크기 2 왕복 `directedCycleDetection(2, [[0,1],[1,0]])` | `1` 이 꼭대기일 때 `0` 이 회색이다 | `true` |
| 중복 간선 `directedCycleDetection(2, [[0,1],[0,1]])` | 두 번째 `0 → 1` 은 검은색을 만난다 | `false` |
| 나뉜 조각 `directedCycleDetection(5, [[0,1],[2,3],[3,4],[4,2]])` | 바깥 `for` 가 `s = 2` 를 다시 잡는다 | `true` |

자기 루프가 이 절차의 경계입니다. 간선 `[v, v]` 는 `v` 가 꼭대기일 때 확인되는데 그때 `v` 는
회색이라, 따로 처리하는 코드 없이 사이클로 판정돼요. 중복 간선은 첫 번째에 내려가고 두 번째에는
검은색이나 회색을 만나므로 결과를 바꾸지 않습니다.

**이제 깨뜨려 봅시다.** 「회색인 정점의 모임 = `stack` 의 정점」을 지키던 줄은 목록을 다 확인하고
뺄 때 색을 검은색으로 바꾸는 줄입니다. `stack` 에서는 빼면서 색은 회색으로 남겨 두면 어떻게
되는지 봅시다.

```ts
color[u] = GRAY; // ← 뺄 때 검은색으로 칠하지 않고 회색으로 둔다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-stay-gray-->

```text
                            뺄 때 검은색으로 칠한다   뺄 때도 회색으로 둔다
전개가 쓰는 여섯 정점       true                      true
마름모 네 정점              false                     true
교차 간선 0→1 · 0→2 · 1→2   false                     true
한 줄로 이은 네 정점        false                     false
간선이 없는 네 정점         false                     false
```

사이클이 없는 두 그래프에서 `true` 가 나옵니다. 끝난 정점이 회색으로 남으니까 「회색 = 지금 경로
위」가 거짓이 되고, 다른 갈래에서 그 정점을 다시 만났을 때 되돌아온 것으로 판정하기 때문이에요.

```text
마름모 0→1 · 0→2 · 1→3 · 2→3 에서 뺄 때도 회색으로 두면

  0 · 1 · 3 을 회색으로   경로 [0,1,3]
  3 을 뺀다               경로 [0,1]     3 은 여전히 회색이다   ← 여기가 거짓이 되는 자리
  1 을 뺀다               경로 [0]       1 도 여전히 회색이다
  0→2 로 내려간다         경로 [0,2]
  2→3 을 확인             3 이 회색이다  사이클이라고 판정한다  true — 사이클이 없는데 그렇다
```

**한 줄로 이은 네 정점에서는 두 값이 같다는 것**도 함께 보세요. 사슬은 갈래가 한 번도 합쳐지지
않아 끝난 정점을 다시 만나는 일이 없습니다. 그때는 「검은색으로 칠한다」와 「회색으로 둔다」가
같은 결과를 내므로, 이 입력만 시험하면 바꿔 놓고도 통과해요.

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 일은 스택 꼭대기를 보고, `cursor` 가 가리키는 간선 하나를 확인하거나, 목록을 다
확인했으면 검은색으로 칠해 빼는 것뿐입니다. 전개의 값으로 확인하면 간선 확인이 T2·T3·T4·T8·T9·T10·T11·T12
의 여덟 번이고 빼기가 T5·T6·T7 의 세 번이었어요.

```text
바퀴   무슨 일          꺼낸 것    확인한 간선                해당 단계
1      간선 확인        —          0→1                        T2
2      간선 확인        —          1→3                        T3
3      간선 확인        —          3→4                        T4
4      검은색으로 뺀다  4          —                          T5
5      검은색으로 뺀다  3          —                          T6
6      검은색으로 뺀다  1          —                          T7
7~10   간선 확인        —          0→4 · 0→2 · 2→3 · 2→5      T8 · T9 · T10 · T11
11     간선 확인        —          5→0                        T12 — 여기서 반환한다
       └ 간선 확인 8 = E, 빼기 3 ≤ V. 사이클이 없으면 빼기가 정확히 V 다
```

그러니 간선을 확인하는 횟수는 **간선 수와 정확히 같고**, 빼는 횟수는 **검은색이 된 정점 수**와
같습니다. 사이클이 없으면 뒤의 값이 `V` 이고, 사이클을 먼저 만나면 그만큼 작아져요. 그 앞에
나가는 목록을 만드는 비용이 붙습니다.

```text
총식 = 배열 셋 만들기 + 목록 채우기 + 바깥 for + 꼭대기 확인 + 간선 확인 + 색 칠하기
       Θ(V)            Θ(E)          Θ(V)       Θ(V + E')    Θ(E')      Θ(V)
                                                 ↑ E' 는 반환하기 전까지 확인한 간선 수
     = Θ(V + E)

메모리 = next Θ(V + E) + color·cursor·stack Θ(V) = Θ(V + E)
```

여기서 센 것은 **배열 칸을 읽고 쓴 횟수**입니다. `next[u].push(v)` 와 `stack.push(v)` 가 안에서
칸을 다시 잡는 비용은 세지 않았어요 — 정점 하나가 스택에 들어가는 것도 간선 하나가 목록에
들어가는 것도 전체에서 한 번씩이라, 분할 상환하면 위 식의 규모를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 간선이 자기 루프다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(V + E)` | `Θ(V + E)` |
| **최악의 경우** (사이클이 없다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값입니다.** 어떤 입력이 와도 나가는 목록을 만드는 데 `Θ(V + E)` 가 들고, 그것이
그대로 하한이에요. 간선 하나를 목록에 넣지 않고 넘어가는 경로가 없기 때문입니다.

```text
케이스가 갈리는 것은 규모가 아니라 상수배다 — V = 100,000 · E = 100,000 으로 고정하고 잰다

  사이클이 없다                 목록 만들기 + 배열 셋 + 주 반복 전부      11V + 8E = 1,900,000
  사이클이 두 걸음 앞에 있다    목록 만들기 + 배열 셋 + 주 반복 몇 바퀴   500,025
                                └ 규모는 둘 다 V + E 이고 계수만 3.8 배 갈린다
```

**평균을 따로 계산할 대상이 없습니다.** 사이클을 언제 만나는가가 주 반복의 길이를 바꾸기는
하지만, 그 앞에 놓인 `3V + 2E` 가 어떤 입력에서도 치러지므로 기댓값이 `Θ(V + E)` 를 벗어날
수 없어요. 「평균이 정의되지 않는다」가 아니라 **분포와 무관하게 같다**는 쪽입니다.

```text
최악 보장     어떤 입력에도 V + E 규모를 넘지 않는다         ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다  ← 이 절차는 여기 해당하지 않는다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요.
같은 입력을 두 번 넣으면 반환값도 칸 접근 수도 똑같이 나옵니다. 경계의 종류로 보면 `Θ(V + E)` 는
상한이자 하한이에요 — 간선을 한 번씩은 목록에 넣어야 하므로 그보다 적게 할 방법이 없고, 위에서
센 대로 그보다 많이 하지도 않습니다.

#### 최악을 만드는 입력

「깊은 그래프가 최악」이라는 통념부터 확인합시다. 사슬은 스택이 가장 깊어지는 그래프이고 별
모양은 가장 얕은 그래프인데, 정점 수와 간선 수를 맞춰 두 극단을 실제로 실행해 보면 값이 같습니다.

```text
정점 100,000 개 · 간선 99,999 개짜리 두 극단
아래 표는 여기에 순방향 간선 하나씩을 더해 간선 수를 제약 상한 100,000 까지 채운 것이다

  사슬                                별 모양

    0 → 1 → 2 → … → 99,999               0
                                      /  |  \
                                      v  v  v
                                      1  2  3  …  99,999

                            사슬       별 모양
  스택의 최대 깊이          100,000    2
  가장 긴 목록의 길이       1          99,999
  검은색이 되는 정점 수     100,000    100,000
```

<!--proof:shape-values-->

```text
입력 모양                                        V         E   배열 칸 접근   반환값
사슬 + 순방향 간선 하나 (사이클 없음)      100,000   100,000      1,900,000   false
별 모양 + 순방향 간선 하나 (사이클 없음)   100,000   100,000      1,900,000   false
사슬이 닫힌다 99,999 → 0                   100,000   100,000      1,300,001   true
사이클이 정점 0 에서 두 걸음               100,000   100,000        500,025   true
```

**앞의 두 줄이 정확히 같습니다.** 통념은 이 절차에서 성립하지 않아요 — 깊이는 비용에 들어가지
않습니다. 반복문으로 적었으므로 호출 깊이가 없고, 스택에 동시에 들어 있는 개수도 비용이 아니라
배열 길이일 뿐이라 어느 쪽이든 `V` 를 넘지 않아요.

```text
최악을 만드는 조건은 모양이 아니라 크기와 사이클 유무다

  V 와 E 를 제약 상한까지 채운다   100,000 · 100,000   11V + 8E = 1,900,000
  사이클이 없어야 한다             있으면 만나는 자리에서 주 반복이 끝난다
  모양은 아무래도 좋다             사슬이든 별이든 다이아몬드든 같은 값이다
                                   └ 셋째 줄이 통념을 부정하는 자리다
```

가장 적은 일을 하는 입력은 반대쪽입니다. 사이클이 정점 0 에서 두 걸음이면 190 만이 50 만으로
내려가요. 그래도 규모는 그대로 `Θ(V + E)` 입니다 — 나가는 목록을 만드는 `3V + 2E` 는 어떤
입력에서도 치러야 하니까요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 경로를 하나씩 세던 것을 **정점마다 색 하나를
칠하는 것**으로 바꿨고, 색을 셋으로 가른 덕분에 「지금 경로 위에 있다」와 「이미 끝났다」가
갈리며, 회색 정점으로 가는 간선 하나를 만나는 순간 답이 정해집니다.

```text
간선 목록 → next → 흰색 정점에서 시작 → 회색으로 칠하며 내려간다 → 목록을 다 보면 검은색
                    └ 바깥 for 가 V 번  └ cursor 로 간선마다 한 번   └ 회색을 만나면 true
```

먼저 답이 붙는 문제 하나입니다. T8 에서 간선 `0 → 4` 를 확인했을 때 정점 4 는 검은색이었고,
그래서 ③ 으로 넘어갔어요. 그런데 그것은 `[0,4]` 가 간선 목록의 **네 번째**에 적혀 있었기
때문입니다. `[0,4]` 를 목록 맨 앞으로 옮기면 간선들의 분류와 반환값이 어떻게 될까요?

```text
edges = [[0,4], [0,1], [1,3], [3,4], [0,2], [2,3], [2,5], [5,0]]   ← next[0] = [4, 1, 2]
```

<!--check:orderSwap-->
분류는 둘이 바뀌고 반환값은 그대로 `true` 입니다. `0 → 4` 는 4 가 흰색일 때 확인되므로 나무
간선이 되고, 그 대신 `3 → 4` 가 검은색을 만나 교차 간선이 됩니다.

<!--proof:order-swap-->

```text
간선     본문 순서에서   [0,4] 를 맨 앞으로 옮기면
0 → 4    순방향 간선     나무 간선                   바뀐다
0 → 1    나무 간선       나무 간선                   그대로
1 → 3    나무 간선       나무 간선                   그대로
3 → 4    나무 간선       교차 간선                   바뀐다
0 → 2    나무 간선       나무 간선                   그대로
2 → 3    교차 간선       교차 간선                   그대로
2 → 5    나무 간선       나무 간선                   그대로
5 → 0    역방향 간선     역방향 간선                 그대로
반환값   true            true                        그대로
```

**역방향 간선은 `5 → 0` 하나로 그대로입니다.** 간선을 적은 순서가 바뀌면 탐색이 내려가는 차례가
바뀌고 그래서 나무·순방향·교차 간선의 이름표가 자리를 바꾸지만, 사이클이 있다는 사실 자체는
입력의 순서와 무관해요. 반환값이 순서에 안 흔들리는 것이 그 뜻입니다.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 수행으로 알아보는 알고리즘 절의 T8 과 T10   3 → 최악을 만드는 입력
  2 → 불변식
```

- T8 과 T10 은 둘 다 검은색 정점을 만나 ③ 으로 넘어간 자리인데, 앞은 순방향 간선이고 뒤는 교차
  간선입니다. 코드는 그 둘을 가르지 않아요. 만약 순방향 간선과 교차 간선을 갈라서 보고해야
  한다면 무엇을 더 기록해야 합니까.
- 불변식은 「회색인 정점의 모임 = `stack` 의 정점」이라고 말합니다. 그러면 어느 순간에도 회색인
  정점 수가 몇을 넘을 수 없습니까. 그리고 그 수가 실제로 그 값이 되는 입력을 하나 만들어 보세요.
- 최악을 만드는 입력에서 사슬과 별 모양의 칸 접근이 190 만으로 같았습니다. 정점 100,000 개와
  간선 100,000 개를 그대로 두고 사이클 하나만 그래프의 **가장 뒤쪽**에 두면 그 값이 어떻게 될까요.
  그리고 그 값이 사이클이 없을 때와 거의 같아지는 이유는 무엇입니까.
