# 깊이 우선 방문 순서 — 큰 번호부터 스택에 넣어야 작은 번호부터 나온다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 다음에 갈 정점을 매번 간선
목록 전체에서 찾던 방법에서 스택 하나로 끝내는 방법까지 가는 경로를 따라갑니다. 마지막에는
실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**무향 그래프**는 정점들과 그 사이를 잇는 간선으로 이루어집니다. 간선에 방향이 없어서 `u` 에서
`v` 로 갈 수 있으면 `v` 에서 `u` 로도 갈 수 있어요. **깊이 우선 방문**은 한 정점에서 갈 수 있는
데까지 들어간 다음, 더 갈 곳이 없으면 마지막 갈림길로 되돌아가 다음 후보로 들어가는 방법입니다.

```text
        0
      /   \
     1     2        간선 넷 — 0-1 · 0-2 · 1-3 · 2-4
     |     |        정점 5 는 어느 간선에도 들어 있지 않다
     3     4    5
```

이 글이 만드는 것은 **정점을 처음 방문한 순서**입니다. 위 그래프를 정점 0 에서 시작해 규칙대로
방문하면 순서가 하나로 정해져요.

```text
0 에서 시작한다                  order = [0]
0 의 이웃 {1, 2} 중 작은 1        order = [0, 1]
1 의 이웃 {0, 3} 중 새 정점 3     order = [0, 1, 3]
3 은 더 갈 곳이 없다              0 이 남겨 둔 2 로 되돌아간다
2 를 방문한다                     order = [0, 1, 3, 2]
2 의 이웃 {0, 4} 중 새 정점 4     order = [0, 1, 3, 2, 4]
```

규칙은 둘입니다. ① 갈 수 있는 이웃이 여럿이면 **번호가 가장 작은 것**을 먼저 방문합니다.
② 한 번 방문한 정점은 다시 넣지 않아요. 이 둘 때문에 출력은 간선 목록이 어떤 순서로 적혀
있든 **하나로 정해집니다**.

```text
간선 목록이 [[0,2],[0,1],[1,3],[2,4]] 여도
간선 목록이 [[0,1],[0,2],[1,3],[2,4]] 여도
  ┗ 정점 0 의 이웃은 {1, 2} 로 같다 → 1 을 먼저 방문한다 → 결과가 같다
```

시작 정점에서 간선을 따라 도달할 수 없는 정점은 결과에 넣지 않습니다. 위 그림의 정점 5 가
그 경우예요. 「도달할 수 있는가」는 정점 단위로 정해지고, 도달할 수 없는 정점은 그 이웃 목록을
한 번도 읽지 않습니다.

「갈림길로 되돌아간다」를 만드는 장치가 **스택**입니다. 나중에 넣은 것을 먼저 꺼내는 통이에요.
갈림길에서 아직 안 간 이웃들을 통에 넣어 두면, 지금 들어간 길이 끝났을 때 그 통의 맨 위가
바로 마지막 갈림길이 남긴 후보입니다.

```text
스택은 나중에 넣은 것을 먼저 꺼낸다

  이웃 [1, 2] 를 1 · 2 순으로 넣으면   스택 [1, 2]   맨 위가 2 → 2 가 먼저 나온다
  이웃 [1, 2] 를 2 · 1 순으로 넣으면   스택 [2, 1]   맨 위가 1 → 1 이 먼저 나온다
```

여기가 이 글의 결정적인 자리입니다. 작은 번호를 먼저 방문하려면 이웃을 **큰 번호부터** 넣어야
해요. 정렬해 둔 목록을 그대로 넣으면 정반대 순서가 나옵니다.

```text
정점 수 V, 간선 수 E 일 때
  이웃 목록 만들기   간선마다 두 정점의 목록에 한 번씩       2E
  목록 정렬          목록마다 한 번씩 정렬한다               합쳐서 2E · log V 이하
  스택 넣기·꺼내기   정점을 처음 꺼낼 때 그 이웃 수만큼      합쳐서 1 + 2E 이하
                     └ 전체는 V + E · log V 에 비례한다
```

정렬이 들어가는 것이 이 문제의 특징입니다. 깊이 우선 방문 자체는 `V + E` 에 비례하는데,
「작은 번호부터」라는 규칙 하나가 목록마다 정렬을 요구해서 `log` 가 붙어요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 정점과 간선으로 적는 방식.** 특히 **인접 리스트** — 정점마다 이웃 목록 하나를 두는
  표현입니다. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **스택이 나중에 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기·꺼내기가 각각 `O(1)` 입니다.
  모르면 [`stack` 가이드](../../../data-structures/linear/stack/stack-guide.mdx)를 보세요.
- **비교 정렬의 비용이 원소 `m` 개에 `m · log m` 규모**라는 것. 이웃 목록을 정렬하는 데 이
  값을 그대로 씁니다. 모르면 [`sortArray` 가이드](../../sorting/sortArray/sortArray-guide.md)를 보세요.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점을 이미 방문했는가」를 배열 한 칸을 읽어
  판정합니다.

마지막 둘이 흐릿하면 뒤가 어긋납니다. 이 글은 비용을 두 항으로 갈라 적는데, 하나가 정렬이고
하나가 배열 접근이라 둘의 규모를 각각 알고 있어야 그 식이 읽혀요.

### 아이디어 상세 — 정렬해 둔 이웃 목록과 스택을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function dfsTraversal(
  n: number,
  edges: [number, number][],
  start: number,
): number[];
```

- 입력: 정점 수 `n`, 무향 간선 목록 `edges`, 시작 정점 `start`. 정점 번호는 0 부터 `n - 1` 까지예요.
- 출력: 시작 정점에서 깊이 우선으로 방문했을 때 정점을 **처음 방문한 순서**를 담은 배열.
  도달할 수 없는 정점은 넣지 않으므로 길이가 `n` 보다 작을 수 있습니다.
- 제약: 정점 100,000 개 이하, 간선 100,000 개 이하, 시간 1초. 자기 루프(`[v, v]`)와 같은 정점
  쌍의 중복 간선이 들어올 수 있어요.

여기서 눈여겨볼 것이 하나 있습니다. 출력이 **하나로 정해져 있다**는 것이에요. 「깊이 우선으로
방문하면 된다」가 아니라 「이웃 중 작은 번호를 먼저」라는 규칙이 붙어 있어서, 답이 여러 개일
여지가 없습니다.

```text
쓸 수 있는 정보가 둘뿐이다
  ┗ 어떤 정점의 이웃이 누구인가        간선 목록에서 만들어 둔다
  ┗ 어떤 정점을 이미 방문했는가        visited[v] 를 읽는다
```

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `V` | 정점 수 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수 | `0 ≤ E ≤ 100,000` |
| `s` | 시작 정점 번호 | `0 ≤ s < V` |
| `deg(v)` | 정점 `v` 에 붙은 간선 수 | 모든 정점을 더하면 `2E` |
| `adj[v]` | 정점 `v` 의 이웃 목록 | 번호 오름차순으로 정렬해 둔다 |
| `order` | 처음 방문한 순서를 담는 결과 배열 | 길이는 `V` 이하 |
| `visited[v]` | 정점 `v` 를 이미 `order` 에 넣었는가 | 참 또는 거짓 |

정점 수 `V` 와 시작 정점 `s` 는 코드에서 `n` 과 `start` 예요.

가장 먼저 떠오르는 방법으로 시작합시다. **이웃 목록을 따로 만들지 않고**, 다음에 갈 정점을
고를 때마다 간선 목록 전체를 처음부터 다시 읽어 「지금 정점과 이어져 있고 아직 방문하지 않은
정점 중 번호가 가장 작은 것」을 찾는 것이에요. 갈 곳이 없으면 지나온 정점으로 하나씩 되돌아가며
같은 검사를 되풀이합니다.

```text
간선 목록 [[0,2],[0,1],[1,3],[2,4]] 에서 정점 0 의 다음 목적지를 고른다

  [0,2] 를 읽는다   0 과 이어져 있다. 2 는 아직 안 갔다        후보 2
  [0,1] 을 읽는다   0 과 이어져 있다. 1 이 2 보다 작다          후보 1
  [1,3] 을 읽는다   0 이 없다                                   그대로
  [2,4] 를 읽는다   0 이 없다                                   그대로
                    └ 간선 넷의 끝점 여덟 개를 다 읽어야 후보 하나가 정해진다
```

이 방법은 답이 맞습니다. 그런데 **고르기 한 번마다 간선 목록 전체**를 다시 읽어요. 고르기는
정점마다 앞으로 갈 때 한 번, 되돌아올 때 한 번씩 일어나니 정점 수에 비례하고, 그래서 전체는
정점 수 × 간선 수가 됩니다. 정점을 한 줄로 이은 사슬 그래프에 제약 규모를 넣어 보죠.

<!--proof:naive-scale-->

```text
 정점 V   간선 E    고르기   간선 끝점 읽기   초당 1억 번 기준
     10        9        19              342            0.000초
  1,000      999     1,999        3,994,002            0.040초
 10,000    9,999    19,999      399,940,002            3.999초
100,000   99,999   199,999   39,999,400,002          399.994초
```

약 400 초입니다. 제약이 10만인데 1초에 못 들어가요. 그러면 이 400 억 안에 헛일이 얼마나 섞여
있는지 봅시다. 앞의 여섯 정점 그래프를 실제로 처리해서 고르기마다 무슨 일이 있었는지 적어
보는 것이에요.

```text
고르기 아홉 번 — 정점 0·1·3·2·4 를 방문하며 각각 앞으로 한 번, 되돌아오며 한 번

  0 에서 고른다   후보 1 을 찾았다        간선 끝점 8 개를 읽었다
  1 에서 고른다   후보 3 을 찾았다        간선 끝점 8 개를 읽었다
  3 에서 고른다   후보가 없다             간선 끝점 8 개를 읽었다   ← 아무것도 안 나온다
  1 에서 고른다   후보가 없다             간선 끝점 8 개를 읽었다   ← 아무것도 안 나온다
  0 에서 고른다   후보 2 를 찾았다        간선 끝점 8 개를 읽었다
  …
                  └ 아홉 번 중 새 정점을 찾은 것은 네 번뿐이다
```

읽은 끝점 여덟 개 중 후보가 된 것은 2 와 1 둘뿐이었습니다. 나머지 여섯은 「이 끝점이 0 자신
이다」거나 「이 간선은 0 과 상관없다」를 확인하는 데만 쓰였어요. 그러면 **정점마다 자기 이웃
목록을 한 번 만들어 두면** 그 여섯을 안 읽어도 되지 않을까요?

```text
간선 목록을 한 번만 읽어 정점별 목록으로 옮겨 둔다

  [0,2] → adj[0] 에 2, adj[2] 에 0
  [0,1] → adj[0] 에 1, adj[1] 에 0
  [1,3] → adj[1] 에 3, adj[3] 에 1
  [2,4] → adj[2] 에 4, adj[4] 에 2
          └ 끝점 여덟 개를 한 번 읽는 것으로 끝난다
```

두 방법을 같은 그래프에서 실행하고 **읽은 원소 수**를 세면 이렇게 나옵니다.

<!--proof:sweep-vs-list-->

```text
                               읽은 원소   되풀이한 횟수   결과
간선 목록을 매번 다시 읽는다   72          고르기 9        [0, 1, 3, 2, 4]
이웃 목록을 한 번 만든다       16          꺼내기 9        [0, 1, 3, 2, 4]
```

답은 같은데 72 가 16 이 됐습니다. 16 의 내역은 둘이에요 — 이웃 목록을 만들 때 읽은 간선 끝점
8 개와, 방문한 정점들의 이웃 목록에서 읽은 원소 8 개입니다. 앞의 8 은 `2E` 이고 뒤의 8 은 방문한
정점들의 `deg` 를 더한 값이에요.

```text
adj[0] = [1, 2]     deg 2      0 을 꺼낼 때 두 개를 읽는다
adj[1] = [0, 3]     deg 2      1 을 꺼낼 때 두 개를 읽는다
adj[2] = [0, 4]     deg 2      2 를 꺼낼 때 두 개를 읽는다
adj[3] = [1]        deg 1      3 을 꺼낼 때 한 개를 읽는다
adj[4] = [2]        deg 1      4 를 꺼낼 때 한 개를 읽는다
adj[5] = []         deg 0      한 번도 안 꺼낸다
                    └ 합 8 = 2E. 간선 하나가 목록 두 곳에 들어 있기 때문이다
```

여기서 관찰한 것은 하나입니다. **고르기 한 번의 비용이 `E` 에서 `deg(v)` 로 줄었다.** 그런데
고르기는 여전히 남아 있어요 — 목록 안에서 「아직 안 간 것 중 가장 작은 번호」를 찾는 일이
정점 `v` 마다 `deg(v) + 1` 번 일어납니다.

```text
정점 v 에서 고르기가 몇 번 일어나는가
  이웃 하나로 들어갈 때마다 한 번     deg(v) 번 이하
  더 갈 곳이 없다고 판정할 때 한 번   1 번
                                      └ 한 번의 비용이 deg(v) 라 정점 하나에 deg(v)·(deg(v)+1)
```

가장 단순한 후보를 먼저 시험해 봅시다. **목록을 정렬하지 않고, 고를 때마다 그 목록을 처음부터
읽어 최솟값을 찾는** 방식이에요. 이웃이 많은 정점이 하나 있는 그래프에서 갈립니다.

<!--proof:pick-min-vs-order-->

```text
                                  목록에서 읽은 원소   결과의 앞 네 개
고를 때마다 최솟값을 찾는다                  999,999   [0, 1, 2, 3] …
미리 정렬하고 앞에서부터 읽는다                1,998   [0, 1, 2, 3] …
```

정점 1,000 개짜리 별 모양 그래프(정점 0 이 나머지 999 개와 전부 이어져 있다)입니다. 답은 같은데
읽은 원소가 999,999 대 1,998 로 약 500 배 갈렸어요. 정점 0 의 목록 999 칸을 1,000 번 다시 읽어
999,000 이 되고, 거기에 나머지 999 개 정점이 자기 목록 한 칸씩을 읽은 999 가 더해진 값입니다.

> 이웃 목록을 **한 번 번호 오름차순으로 정렬해 둔다.** 그러면 「아직 안 간 것 중 가장 작은
> 번호」를 찾는 일이 「목록의 다음 칸을 본다」가 된다.

```text
정렬 전  adj[0] = [2, 1]      최솟값을 찾으려면 매번 두 칸을 다 읽어야 한다
정렬 후  adj[0] = [1, 2]      앞에서부터 한 칸씩만 보면 된다
                              └ 999 칸짜리 목록이면 999 번 읽기가 1 번 읽기가 된다
```

정렬을 하면 「다음 칸이 어디였는지」를 기억할 자리가 필요합니다. 정점마다 첨자를 하나씩 두는
대신, **아직 안 본 이웃들을 스택에 넣어 두는** 방법을 씁니다. 스택 하나가 모든 정점의 「다음
칸」을 한꺼번에 담아요.

```text
각 상태 변수가 얼마나 움직이는가

  스택에 들어가는 총 원소 수   시작 정점 1 개 + 처음 꺼낸 정점마다 deg(v) 개   1 + 2E 이하
  스택에서 꺼내는 횟수         들어간 만큼만                                   1 + 2E 이하
  order 의 길이                정점당 정확히 0 또는 1 번                       V 이하
  visited 를 참으로 바꾸는 횟수 한 번 참이 되면 다시 안 바뀐다                  V 이하
```

**같은 정점이 스택에 두 번 들어가는 경우를 값으로 확인해 봅시다.** 쉬운 경우는 갈림이 없는
자리예요 — 정점 3 처럼 이웃이 하나뿐이면 하나 넣고 하나 꺼내는 것으로 끝납니다. 불안한 경우는
사이클이 있어 같은 정점이 두 곳에서 후보로 올라올 때입니다.

```text
네 정점 그래프 — 간선 [[0,3],[0,1],[0,2],[1,3]]. 정점 0·1·3 이 삼각형을 이룬다

  adj[0] = [1, 2, 3]   adj[1] = [0, 3]   adj[2] = [0]   adj[3] = [0, 1]

  0 을 꺼낸다   order [0]      이웃을 큰 번호부터 넣는다   스택 [3, 2, 1]
  1 을 꺼낸다   order [0, 1]   이웃을 큰 번호부터 넣는다   스택 [3, 2, 3, 0]
                                                            └ 3 이 두 번 들어 있다
```

정점 3 이 두 번 들어 있는 상태에서 어느 것이 먼저 나오는지, 그리고 두 번째 것이 어떻게 되는지가
관건입니다. 단계마다 값을 적으면 이렇게 되고, `visited` 를 **꺼낼 때** 확인하는 것이 그 답이에요.

```text
  0 을 꺼낸다   visited[0] 이 참이다      버린다               스택 [3, 2, 3]
  3 을 꺼낸다   visited[3] 이 거짓이다    order [0, 1, 3]      스택 [3, 2, 1, 0]
  0 을 꺼낸다   참이다                    버린다               스택 [3, 2, 1]
  1 을 꺼낸다   참이다                    버린다               스택 [3, 2]
  2 를 꺼낸다   거짓이다                  order [0, 1, 3, 2]   스택 [3, 0]
  0 을 꺼낸다   참이다                    버린다               스택 [3]
  3 을 꺼낸다   참이다                    버린다               스택 []
```

왜 이것이 맞는지는 반복문의 종료 조건이 말해 줍니다. 스택에 들어가는 총 원소 수가 `1 + 2E` 를
넘지 않고 한 바퀴마다 정확히 하나를 꺼내므로, 반복은 반드시 끝나요. 그리고 `order` 에 들어가는
것은 `visited` 가 거짓인 정점뿐이라 같은 정점이 두 번 들어갈 수 없습니다.

```text
남은 갈림 둘
  이웃 목록을 정렬하는가                  정렬하지 않는다 · 오름차순으로 정렬한다
  목록의 어느 쪽부터 스택에 넣는가        작은 번호부터 · 큰 번호부터
                                          └ 두 갈림의 조합이 넷이다
```

네 조합을 같은 두 입력에 실제로 실행해 결과를 냅니다.

<!--proof:combo-values-->

```text
이웃 목록          스택에 넣는 순서   여섯 정점         네 정점
입력 순서 그대로   작은 번호부터      [0, 1, 3, 2, 4]   [0, 2, 1, 3]
입력 순서 그대로   큰 번호부터        [0, 2, 4, 1, 3]   [0, 3, 1, 2]
오름차순 정렬      작은 번호부터      [0, 2, 4, 1, 3]   [0, 3, 1, 2]
오름차순 정렬      큰 번호부터        [0, 1, 3, 2, 4]   [0, 1, 3, 2]
정본               —                  [0, 1, 3, 2, 4]   [0, 1, 3, 2]
```

**정답을 두 입력에서 모두 내는 조합은 하나뿐입니다.** 여섯 정점 그래프에서는 첫 줄도 정답을
내는데, 그건 그 입력의 `adj[0]` 이 `[2, 1]` 이라 「정렬 안 함 + 작은 번호부터 넣기」가 우연히
「정렬 + 큰 번호부터 넣기」와 같은 순서가 됐기 때문이에요. 네 정점 그래프에서 그 우연이 풀립니다.

```text
여섯 정점에서 두 줄이 같은 값을 낸 이유

  정렬 안 함 + 작은 번호부터   adj[0] = [2, 1] 을 2 · 1 순으로 넣는다   스택 [2, 1]
  정렬     + 큰 번호부터       adj[0] = [1, 2] 를 2 · 1 순으로 넣는다   스택 [2, 1]
                               └ 넣은 결과가 같다. 입력이 달라지면 갈린다
```

**절차가 나왔습니다.** 간선 목록을 이웃 목록으로 옮기고, 목록마다 번호 오름차순으로 정렬하고,
시작 정점을 스택에 넣은 뒤, 스택에서 꺼낸 정점이 처음 꺼내는 것이면 결과에 넣고 그 이웃을
**큰 번호부터** 스택에 넣는 것이에요.

### 수행으로 알아보는 알고리즘 — 여섯 정점의 방문 순서를 만든다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const n = 6;
const edges: [number, number][] = [[0, 2], [0, 1], [1, 3], [2, 4]];
const start = 0;
// 이 절이 끝나면 [0, 1, 3, 2, 4] 가 나와야 한다
```

정점을 왜 여섯으로 뒀을까요? 간선 목록에 `[0,2]` 가 `[0,1]` 보다 먼저 적혀 있어 **정렬이 실제로
일하는 것**을 볼 수 있고, 정점 0 에서 두 갈래가 갈려 **되돌아가는 갈래**가 반드시 실행되며,
간선이 하나도 없는 정점 5 가 있어 결과에서 빠지는 경로까지 함께 확인되기 때문입니다.

```text
dfsTraversal(n, edges, start):
    간선 [u, v] 마다 adj[u] 에 v 를, adj[v] 에 u 를 넣는다
    adj 의 목록마다 번호 오름차순으로 정렬한다
    visited 를 전부 거짓으로, order 를 빈 배열로, 스택을 [start] 로 둔다
    스택이 비지 않은 동안:
        node ← 스택의 맨 위를 꺼낸다
        visited[node] 가 참이면 그대로 버린다                    ② 이미 결과에 있다
        아니면 visited[node] ← 참, order 뒤에 node 를 넣고         ① 처음 꺼낸다
               adj[node] 를 뒤에서 앞으로 스택에 넣는다
    order 를 반환한다
```

#### 1. 간선 목록을 오름차순 이웃 목록으로 만든다

간선 목록은 「누가 누구와 이어져 있는가」를 담고 있지만 「정점 2 의 이웃이 누구인가」를 묻기에는
불편합니다. 그 질문에 답하려면 목록 전체를 다시 읽어야 하니까요. 정점마다 이웃 목록을 하나씩
만들고, 그 목록을 번호 오름차순으로 정렬해 둡니다.

```ts
const adj: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  (adj[u] as number[]).push(v);
  (adj[v] as number[]).push(u);
}
for (const list of adj) list.sort((a, b) => a - b);
```

실행하면 이렇게 나옵니다. `adj[0]` 이 만들어질 때는 `[2, 1]` 이었다가 정렬 뒤에 `[1, 2]` 가 되는
것이 보여요.

```text
edges = [[0,2], [0,1], [1,3], [2,4]]

정렬 전                정렬 후
  adj[0] = [2, 1]        adj[0] = [1, 2]
  adj[1] = [0, 3]        adj[1] = [0, 3]
  adj[2] = [0, 4]        adj[2] = [0, 4]
  adj[3] = [1]           adj[3] = [1]
  adj[4] = [2]           adj[4] = [2]
  adj[5] = []            adj[5] = []
                         └ 칸 수를 다 더하면 8 = 2E
```

#### 멈춤 — 간선을 오름차순으로 적어 두면 정렬이 필요 없다고 읽기 쉽다

`list.sort` 한 줄이 없으면 어떻게 될까요? 코드는 그대로 실행되고 예외도 안 납니다. 그리고
**어떤 입력에서는 답까지 같아요** — 간선 목록이 이미 정점 번호 오름차순으로 적혀 있으면
이웃 목록이 저절로 정렬돼 있기 때문입니다.

<!--proof:mutant-unsorted-->

```text
입력 간선 목록              정렬한다          정렬하지 않는다
[[0,2],[0,1],[1,3],[2,4]]   [0, 1, 3, 2, 4]   [0, 2, 4, 1, 3]
[[0,1],[0,2],[1,3],[2,4]]   [0, 1, 3, 2, 4]   [0, 1, 3, 2, 4]
```

아래 줄이 그 자리입니다. `[0,1]` 이 `[0,2]` 보다 먼저 적혀 있어 `adj[0]` 이 만들어질 때부터
`[1, 2]` 라, 정렬해도 안 해도 결과가 같아요. **테스트가 이 입력만 담고 있으면 정렬을 지워도
통과합니다.** 위 줄에서야 갈리는데, 그때는 정점 2 를 정점 1 보다 먼저 방문해 순서가 완전히
어긋납니다.

```text
[[0,2],[0,1],…] 에서 정렬하지 않으면

  adj[0] = [2, 1]        만들어진 순서 그대로다
  큰 번호부터 넣는다     뒤에서 앞으로 1 · 2 순으로 넣는다   스택 [1, 2]
  맨 위를 꺼낸다         2 가 나온다                          order [0, 2]
                         └ 규칙은 1 을 먼저 방문하라고 한다
```

문제 지문이 「간선 목록의 나열 순서와 무관하게 결과가 하나로 정해진다」고 못 박은 것이 바로
이 자리예요. 입력이 어떤 순서로 오든 같은 답을 내려면 정렬이 필요합니다.

#### 2. 방문 표시와 결과 배열, 스택을 준비한다

「이 정점을 이미 결과에 넣었는가」를 배열 한 칸으로 담습니다. 최단 거리를 구하는 문제라면 거리
배열이 그 표시를 겸할 수 있지만, 여기서는 정점에 붙는 값이 없어서 참·거짓 배열을 따로 둬요.

```ts
const visited: boolean[] = Array.from({ length: n }, () => false);
const order: number[] = [];
const stack: number[] = [start];
```

실행하면 이렇게 나옵니다. 시작 정점은 아직 `visited` 가 거짓이에요 — 표시는 **꺼낼 때** 합니다.

```text
visited = [false, false, false, false, false, false]
order   = []
stack   = [0]
           ↑ 맨 위
           └ start 를 넣기만 했다. visited[0] 은 아직 거짓이다
```

#### 3. 스택에서 꺼내고 이웃을 큰 번호부터 넣는다

여기가 순서를 만드는 자리입니다. 스택 맨 위를 꺼내고, 처음 꺼내는 정점이면 결과에 넣은 뒤 그
이웃 목록을 **뒤에서 앞으로** 스택에 넣어요.

```ts
while (stack.length > 0) {
  const node = stack.pop() as number;

  // ② 이미 결과에 들어간 정점 — 스택에 두 번 들어갔던 것이라 그대로 버린다.
  if (visited[node] === true) continue;

  // ① 처음 꺼내는 정점 — 방문 표시를 하고 결과에 넣는다.
  visited[node] = true;
  order.push(node);

  const list = adj[node] as number[];
  for (let i = list.length - 1; i >= 0; i--) stack.push(list[i] as number);
}
```

가장 중요한 줄은 `for (let i = list.length - 1; i >= 0; i--)` 입니다. 이 줄이 목록을 뒤에서
앞으로 넣어서, 스택 맨 위에 **가장 작은 번호**가 오게 만들어요. 첨자를 0 부터 올리도록 바꾸면
정반대 순서가 나옵니다.

```text
adj[0] = [1, 2] 를 스택에 넣는다

  뒤에서 앞으로   2 를 넣고 1 을 넣는다   스택 [2, 1]   맨 위 1   ✓ 작은 번호부터 방문
  앞에서 뒤로     1 을 넣고 2 를 넣는다   스택 [1, 2]   맨 위 2   ✗ 큰 번호부터 방문
```

#### 멈춤 — 방문 표시를 꺼낼 때가 아니라 넣을 때 해도 답이 맞는 입력이 있다

스택에 같은 정점이 두 번 들어가는 것이 낭비로 읽힙니다. 그래서 **넣기 전에** `visited` 를 보고
이미 방문한 것은 안 넣고, 넣는 그 자리에서 `visited` 를 참으로 바꾸는 방식을 떠올리기 쉬워요.
너비 우선 탐색은 실제로 그렇게 합니다.

```text
넣을 때 표시한다 (다른 절차)          꺼낼 때 표시한다 (이 글의 코드)
  0 을 꺼낸다 → 1, 2 를 넣고 표시       0 을 꺼낸다 → 1, 2 를 넣기만 한다
  1 을 꺼낸다 → 3 만 넣고 표시          1 을 꺼낸다 → 0, 3 을 넣기만 한다
  3 을 꺼낸다 → 넣을 것이 없다          0 을 꺼낸다 → 이미 결과에 있어 버린다
  2 를 꺼낸다 → 4 만 넣고 표시          3 을 꺼낸다 → 1 을 넣기만 한다
  4 를 꺼낸다 → 넣을 것이 없다          1 을 꺼낸다 → 이미 결과에 있어 버린다
```

**이 입력에서는 답이 안 틀립니다.** 두 방식이 같은 배열을 내놓아요. 그런데 정점 하나가 여러
갈래와 이어져 있고 그 갈래끼리도 이어져 있으면 갈립니다.

<!--proof:mark-on-push-->

```text
                        꺼낼 때 표시한다   넣을 때 표시한다
전개가 쓰는 여섯 정점   [0, 1, 3, 2, 4]    [0, 1, 3, 2, 4]
네 정점 그래프          [0, 1, 3, 2]       [0, 1, 2, 3]
```

네 정점 그래프에서 갈리는 이유는 정점 3 이 두 곳에서 후보로 올라오기 때문입니다. 넣을 때
표시하면 정점 0 을 꺼내는 그 순간 1·2·3 이 한꺼번에 표시돼, 나중에 정점 1 을 통해 3 으로
들어가는 길이 없어져요.

```text
넣을 때 표시하면
  0 을 꺼낸다   1 · 2 · 3 을 전부 표시하고 넣는다   스택 [3, 2, 1]
  1 을 꺼낸다   이웃 0 · 3 이 둘 다 표시돼 있다     넣을 것이 없다
  2 를 꺼낸다   이웃 0 이 표시돼 있다               order [0, 1, 2]   ← 3 보다 먼저다
                └ 깊이 우선이 아니라 "0 의 이웃을 번호순으로" 가 됐다
```

「답이 안 틀린다」가 이 자리의 함정입니다. 전개가 쓰는 입력만으로 시험하면 통과하니 무엇이
달라졌는지 모르고 넘어가요. 이 글은 **꺼낼 때 표시합니다** — 스택이 커지는 대신 깊이 우선
순서가 지켜집니다.

#### 4. 여섯 정점을 처음부터 끝까지 따라간다

앞의 세 조각을 이어 실제로 실행하면 열한 단계가 나옵니다. 분기 `①`·`②` 가 각각 어디서
실행되는지를 함께 적었어요.

<!--viz:dfsWalk-->
```text
T1   시작            스택에 0 을 넣는다      스택 [0]         order []
T2   0 을 꺼낸다     ① order 에 0           스택 [2, 1]      이웃 [1,2] 를 큰 번호부터
T3   1 을 꺼낸다     ① order 에 1           스택 [2, 3, 0]   이웃 [0,3] 을 큰 번호부터
T4   0 을 꺼낸다     ② 이미 결과에 있다      스택 [2, 3]      버린다
T5   3 을 꺼낸다     ① order 에 3           스택 [2, 1]      이웃 [1] 하나만
T6   1 을 꺼낸다     ② 이미 결과에 있다      스택 [2]         버린다
T7   2 를 꺼낸다     ① order 에 2           스택 [4, 0]      T2 가 남긴 2 다
T8   0 을 꺼낸다     ② 이미 결과에 있다      스택 [4]         버린다
T9   4 를 꺼낸다     ① order 에 4           스택 [2]         이웃 [2] 하나만
T10  2 를 꺼낸다     ② 이미 결과에 있다      스택 []          버린다
T11  종료            스택이 비었다            스택 []          정점 5 는 빠진다
```

<!--result:dfsWalk=[0,1,3,2,4]-->

한 걸음마다 조건이 어떻게 판정되는지 전부 적으면 아래 표입니다.

| 단계 | 꺼낸 정점 | 조건 판정 | `order` | 스택 |
| --- | --- | --- | --- | --- |
| T1 | — | 스택에 `start` 를 넣는다 | `[]` | `[0]` |
| T2 | 0 | `visited[0]` 이 **거짓** → ① | `[0]` | `[2,1]` |
| T3 | 1 | `visited[1]` 이 **거짓** → ① | `[0,1]` | `[2,3,0]` |
| T4 | 0 | `visited[0]` 이 **참** → ② | `[0,1]` | `[2,3]` |
| T5 | 3 | `visited[3]` 이 **거짓** → ① | `[0,1,3]` | `[2,1]` |
| T6 | 1 | `visited[1]` 이 **참** → ② | `[0,1,3]` | `[2]` |
| T7 | 2 | `visited[2]` 가 **거짓** → ① | `[0,1,3,2]` | `[4,0]` |
| T8 | 0 | `visited[0]` 이 **참** → ② | `[0,1,3,2]` | `[4]` |
| T9 | 4 | `visited[4]` 가 **거짓** → ① | `[0,1,3,2,4]` | `[2]` |
| T10 | 2 | `visited[2]` 가 **참** → ② | `[0,1,3,2,4]` | `[]` |
| T11 | — | `stack.length > 0` 이 **거짓** | `[0,1,3,2,4]` | `[]` |

**두 갈래가 모두 나왔습니다.** 꺼내기는 T2 부터 T10 까지 아홉 번이고, 그중 ① 이 다섯 번,
② 가 네 번이에요. 반환값은 `[0, 1, 3, 2, 4]` 입니다.

```text
①  처음 꺼낸다        T2 · T3 · T5 · T7 · T9      다섯 번 = 도달 가능한 정점 수
②  이미 결과에 있다   T4 · T6 · T8 · T10          네 번

꺼내기 9 = 1 + (deg(0)+deg(1)+deg(3)+deg(2)+deg(4)) = 1 + (2+2+1+2+1)
```

여기서 헷갈리기 쉬운 포인트는 T7 입니다. 정점 2 는 T2 에서 스택에 들어가 다섯 단계를 기다렸다가
꺼내졌어요. 그 다섯 단계 동안 왼쪽 갈래(1 → 3)를 끝까지 처리했고, 끝나자마자 스택 맨 위가 다시
정점 2 가 된 것이 「갈림길로 되돌아가기」입니다.

#### 멈춤 — 재귀로 적으면 호출 깊이가 그대로 정점 수가 된다

깊이 우선 방문은 재귀로 적는 쪽이 짧습니다. 「정점을 표시하고 결과에 넣은 뒤, 이웃마다 아직
안 갔으면 자기 자신을 부른다」로 다섯 줄이면 끝나요.

```ts
const go = (v: number): void => {
  visited[v] = true;
  order.push(v);
  for (const w of adj[v] as number[]) {
    if (visited[w] === false) go(w);
  }
};
```

이 코드는 답이 맞습니다. 그런데 정점이 한 줄로 이어진 입력에서는 `go` 가 자기 자신을 정점 수만큼
겹쳐 부르게 되고, 그 깊이가 실행 환경이 잡아 둔 호출 한도를 넘습니다.

<!--proof:recursion-depth-->

```text
체인 길이   재귀로 적는다     스택 배열로 적는다
    1,000   길이 1,000 배열   길이 1,000 배열
  100,000   RangeError        길이 100,000 배열
```

길이 1,000 에서는 둘이 같은 답을 내는데 100,000 에서 갈립니다. 문제의 제약이 정점 100,000 개
까지이므로 이 입력은 실제로 들어올 수 있어요. 호출 한도가 정확히 몇인지는 실행 환경이 정하고
이 표의 두 줄 사이 어딘가에 있습니다.

```text
재귀로 적으면          호출 깊이 = 지금 들어가 있는 경로의 길이   환경이 잡아 둔 한도를 받는다
스택 배열로 적으면     배열 길이 = 아직 안 꺼낸 후보의 수         메모리 한도까지 늘어난다
                       └ 깊이를 코드가 관리하면 그 한도가 없어진다
```

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 **결과를 그대로 반환**하는 마지막
줄뿐이에요 — `order` 를 따로 손보지 않고 그대로 내보냅니다.

```ts
export function dfsTraversal(
  n: number,
  edges: [number, number][],
  start: number,
): number[] {
  // 간선 목록을 이웃 목록으로 바꾼다. 무향이라 양쪽 정점에 다 넣는다.
  const adj: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    (adj[u] as number[]).push(v);
    (adj[v] as number[]).push(u);
  }

  // 목록마다 번호 오름차순으로 정렬한다. 이 순서가 곧 방문 우선순위다.
  for (const list of adj) list.sort((a, b) => a - b);

  // `visited` 는 결과에 이미 넣었는가를 담는다. 스택에 넣을 때가 아니라 꺼낼 때 본다.
  const visited: boolean[] = Array.from({ length: n }, () => false);
  const order: number[] = [];
  const stack: number[] = [start];

  while (stack.length > 0) {
    const node = stack.pop() as number;

    // ② 이미 결과에 들어간 정점 — 스택에 두 번 들어갔던 것이라 그대로 버린다.
    if (visited[node] === true) continue;

    // ① 처음 꺼내는 정점 — 방문 표시를 하고 결과에 넣는다.
    visited[node] = true;
    order.push(node);

    // 스택은 나중에 넣은 것을 먼저 꺼낸다. 작은 번호를 먼저 꺼내려면 큰 번호부터 넣는다.
    const list = adj[node] as number[];
    for (let i = list.length - 1; i >= 0; i--) stack.push(list[i] as number);
  }

  return order;
}
```

실행하면 이렇게 나옵니다.

<!--proof:walk-result-->

```text
dfsTraversal(6, [[0,2],[0,1],[1,3],[2,4]], 0)   →   [0, 1, 3, 2, 4]
dfsTraversal(4, [[0,1],[1,2],[2,3]], 2)         →   [2, 1, 0, 3]
dfsTraversal(5, [[0,1],[2,3]], 0)               →   [0, 1]
dfsTraversal(3, [[0,0],[0,1],[0,1]], 0)         →   [0, 1]
dfsTraversal(3, [[0,1]], 2)                     →   [2]
dfsTraversal(1, [], 0)                          →   [0]
```

### 알아 두면 좋은 개념 — 되돌리기(백트래킹)

전개의 T5 에서 정점 3 을 결과에 넣고 나면 그 정점의 이웃은 1 하나뿐이고 이미 결과에 있습니다.
왼쪽 갈래가 끝난 것이에요. T6 에서 그 1 을 버리고 나면 스택에 남은 것은 T2 에서 정점 0 이 넣어
둔 2 하나입니다.

```text
스택에 쌓인 구간과 되돌아가기

  T2 직후   [2, 1]        정점 0 이 남긴 후보 두 개
  T3 직후   [2 | 3, 0]    정점 1 이 남긴 후보가 그 위에 쌓인다
  T5 직후   [2 | 1]       정점 1 의 후보가 다 빠지고 정점 3 의 후보 하나가 쌓였다
  T6 직후   [2]           정점 3 의 후보도 빠졌다 — 남은 것은 정점 0 이 남긴 것뿐
  T7        2 를 꺼낸다   갈림길 0 으로 되돌아간 것이 이 한 번의 꺼내기다
```

후보를 하나 골라 끝까지 가 보고, 더 갈 곳이 없으면 마지막 갈림길로 되돌아가 다음 후보를 고르는
방법을 **되돌리기**(backtracking)라고 합니다. 이 글의 스택은 「각 갈림길이 남긴 후보들」을
쌓아 둔 것이고, 되돌아가기는 그 스택에서 하나 더 꺼내는 것으로 끝나요.

| 이 편에서 | 되돌리기 일반 |
| --- | --- |
| 갈림길 | 방금 결과에 넣은 정점 |
| 후보 | 그 정점의 이웃 목록 |
| 후보를 버리는 조건 | `visited[w]` 가 참이다 |
| 되돌아가는 시점 | 지금 갈래의 후보가 다 빠졌을 때 |

같은 뼈대가 이 편 밖에서도 그대로 쓰입니다. [`nQueens` 가이드](../../advanced/nQueens/nQueens-guide.md)는 「갈림길」 자리에
「지금 채우는 줄」이 오고 「후보」 자리에 「그 줄에 놓을 수 있는 칸」이 오는 문제예요. 부분집합을
전부 만드는 문제나 스도쿠를 채우는 문제도 같은 모양입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 비용을 식으로 어떻게 적는지,
무엇이 매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **방문 순서 자체가 답입니다.** 정점까지의 거리나 개수가 아니라 「어떤 순서로 지나갔는가」를
  묻는 문제예요. 거리를 묻는 문제라면 다른 절차를 씁니다.
- **이웃을 고르는 규칙이 지문에 못 박혀 있습니다.** 「번호가 작은 이웃부터」처럼 순서가 정해져
  있어야 답이 하나로 정해져요.
- **그래프를 미리 다 받아 둘 수 있습니다.** 이웃 목록을 한 번 만들어 두고 시작하니까요.

```text
세 조건이 코드의 모양을 그대로 정한다
  순서가 답이다        → order 배열 하나면 된다. 정점에 붙는 값이 없다
  규칙이 정해져 있다   → adj 를 한 번 정렬해 두고 그 순서를 그대로 쓴다
  미리 다 받는다       → adj 를 먼저 만들고 그 뒤로는 안 고친다
```

거리를 묻는 문제에 이 절차를 쓰면 무엇이 어긋나는지는 값으로 확인됩니다. 전개가 쓴 그래프에서
정점 2 까지의 최단 간선 수는 1 인데, 이 절차는 정점 2 를 네 번째로 방문해요.

```text
같은 그래프에서 두 질문의 답
  처음 방문한 순서       [0, 1, 3, 2, 4]       정점 2 는 네 번째로 나온다
  0 에서의 최단 간선 수  [0, 1, 1, 2, 2, -1]   정점 2 는 간선 하나 거리다
                          └ 앞은 정점을 나열한 것이고 뒤는 정점마다 값을 적은 것이다.
                            길이도 다르다 — 도달할 수 없는 정점 5 가 뒤에만 있다
```

거리를 구하려면 꺼내는 순서를 거리 오름차순으로 만들어야 하고, 그것은 스택이 아니라 큐가
합니다. [`bfsShortestPath` 가이드](../bfsShortestPath/bfsShortestPath-guide.md)가 그 절차예요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "방문한 순서"   "탐색 순서를 출력"   "들어간 순서대로"
  "더 갈 곳이 없으면 되돌아간다"       "가능한 한 깊이"

제약에 이런 모양이 보이면
  이웃을 고르는 규칙이 명시돼 있다               ← 답이 하나로 정해진다는 뜻이다
  정점과 간선이 각각 10만 규모이고 시간이 1~2초   ← V + E 규모의 절차를 찾으라는 뜻이다
  정점이 한 줄로 이어질 수 있다                   ← 재귀 깊이를 조심하라는 뜻이다
```

반대로 **「최소 몇 번 만에」·「가장 짧은 경로」** 가 보이면 이 단서는 해당하지 않습니다. 그때는
꺼내는 순서를 거리 순서로 만드는 절차가 따로 있어요. 「모든 경로를 나열하라」면 방문 표시를
되돌리는 절차가 또 따로 있습니다.

#### 실제로 쓰이는 곳

- **NetworkX `dfs_preorder_nodes`** — 이 글이 만든 것과 같은 함수입니다. 같은 모듈의
  `dfs_edges` 가 재귀가 아니라 **명시 스택**으로 구현돼 있고(`stack = [(start, get_children(start))]`),
  이웃 순서를 정하는 `sort_neighbors` 매개변수를 받습니다. 그 매개변수 설명이
  *"A function that takes an iterator over nodes as the input, and returns an iterable of the
  same nodes with a custom ordering. For example, `sorted` will sort the nodes in increasing
  order."* 예요 — 이 문제의 「번호가 작은 이웃부터」가 그 `sorted` 에 해당합니다.
  ([networkx/algorithms/traversal/depth_first_search.py](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/traversal/depth_first_search.py), 조회 2026-08-29)
- **LLVM `llvm/ADT/DepthFirstIterator.h`** — 컴파일러가 제어 흐름 그래프를 차례로 읽을 때 쓰는
  반복자입니다. 헤더 주석이 *"Normal depth-first iteration - visit a node and then all of its
  children."* 라 적어 「정점을 먼저 방문하고 그 자식들을 방문한다」는 순서를 규정하고, 내부에
  `VisitStack` 멤버를 두어 재귀 없이 깊이를 관리합니다.
  ([llvm/include/llvm/ADT/DepthFirstIterator.h](https://raw.githubusercontent.com/llvm/llvm-project/main/llvm/include/llvm/ADT/DepthFirstIterator.h), 조회 2026-08-29)

두 곳 다 **재귀가 아니라 스택 자료구조**로 깊이를 관리합니다. 라이브러리는 입력 크기를 미리
알 수 없어서 호출 한도에 걸리는 구현을 둘 수 없기 때문이에요.

### 수식 정의와 유도

정점 $v$ 와 간선으로 이어진 정점들의 모임을 $N(v)$ 라 적고, 그 크기를 $\deg(v)$ 라 적습니다.
시작 정점 $s$ 에서 간선을 따라 도달할 수 있는 정점들의 모임은 $R(s)$ 예요.

| 이름 | 정의 | 이 그래프에서 |
| --- | --- | --- |
| $N(v)$ | 정점 $v$ 와 간선으로 이어진 정점들의 모임 | $N(0) = \{1, 2\}$ |
| $\deg(v)$ | $N(v)$ 에 든 정점의 수 | $\deg(0) = 2$ |
| $R(s)$ | $s$ 에서 간선을 따라 도달할 수 있는 정점들의 모임 | $R(0) = \{0,1,2,3,4\}$ |
| $Q(s)$ | 스택에 들어가는 총 원소 수 | 아래에서 센다 |
| $\Delta$ | 모든 정점의 $\deg$ 중 최댓값 | $\Delta = 2$ |

$Q(s)$ 를 정의 그대로 세어 봅시다. 스택에 원소가 들어가는 자리는 둘뿐이에요 — 시작할 때 한 번,
그리고 ① 갈래가 실행될 때 그 정점의 이웃 수만큼입니다.

$$Q(s) = 1 + \sum_{v \in R(s)} \deg(v)$$

```text
전개가 쓴 그래프에 넣어 검산한다 — R(0) 이 {0, 1, 2, 3, 4} 이고 각 deg 가 2 · 2 · 2 · 1 · 1 이다

  Q(0) = 1 + (2 + 2 + 2 + 1 + 1) = 9

  전개에서 실제로 꺼낸 횟수   T2 부터 T10 까지 아홉 번
  정점 5 는 R(0) 에 없다      deg(5) = 0 이라 더해도 값이 안 바뀐다
```

① 갈래를 실행하는 정점이 정확히 $R(s)$ 라는 것이 이 식의 근거입니다. 정점 하나는 `visited` 가
거짓인 동안에만 ① 로 들어가고 그 즉시 참이 되므로 **많아야 한 번** 실행되고, $s$ 에서 도달할 수
있는 정점은 그 경로 위의 정점이 차례로 이웃을 넣어 주므로 **반드시 한 번** 실행돼요.

```ts
let inserts = 1;
for (const v of reachable) inserts += (adj[v] as number[]).length;
inserts; // 9 — 전개의 T2~T10 에서 실제로 꺼낸 횟수와 같다
```

$R(s)$ 를 모든 정점으로 넓히면 합이 $2E$ 가 되므로 상한이 나옵니다.

$$Q(s) \le 1 + \sum_{v} \deg(v) = 1 + 2E$$

```text
등호가 되는 자리
  R(s) 밖의 정점이 전부 deg 0 이다   그 정점들이 합에 0 만 더하기 때문이다
  전개가 쓴 그래프가 그 경우다        정점 5 만 밖이고 deg(5) = 0 이라 Q(0) = 9 = 1 + 2×4
  [[0,1],[2,3]] 은 아니다             R(0) 이 {0, 1} 이라 Q(0) = 3 이고 1 + 2×2 = 5 다
```

이제 정렬 항으로 갑니다. 목록 하나를 비교 정렬하는 데 드는 비교 횟수는 그 목록 길이 $d$ 에 대해
$d \log_2 d$ 규모이고, 목록이 정점마다 하나씩 있으니 전부 더해야 해요.

$$S = \sum_{v} \deg(v) \log_2 \deg(v)$$

```text
전개가 쓴 그래프에서 S 를 센다 — deg 가 2 · 2 · 2 · 1 · 1 · 0 이다

  deg 2 인 정점 셋     2 × log₂ 2 = 2      합 6
  deg 1 인 정점 둘     1 × log₂ 1 = 0      합 0
  deg 0 인 정점 하나   목록이 비어 있다    0
                       └ S = 6
```

각 항의 $\log_2 \deg(v)$ 를 그중 가장 큰 값 $\log_2 \Delta$ 로 바꾸면 각 항이 커지거나 같으므로
합도 커지거나 같습니다. 그러면 $\log_2 \Delta$ 를 합 밖으로 뺄 수 있어요.

$$S \le \sum_{v} \deg(v) \log_2 \Delta = (\log_2 \Delta) \sum_{v} \deg(v) = 2E \log_2 \Delta$$

| 그래프 | $\Delta$ | $S$ | 상한 $2E \log_2 \Delta$ |
| --- | --- | --- | --- |
| 별 모양 ($V$ 정점, $E = V-1$) | $V-1$ | $(V-1)\log_2(V-1)$ | $2(V-1)\log_2(V-1)$ |
| 사슬 ($V$ 정점, $E = V-1$) | 2 | $2(V-2)$ | $2(V-1)$ |
| 전개가 쓴 그래프 | 2 | 6 | 8 |

**이 상한이 헐겁지 않다는 것을 표의 첫 줄이 보입니다.** 정점 하나에 간선이 전부 몰리면 목록
하나가 $V-1$ 칸이 되어 $S$ 자체가 상한과 같은 규모가 돼요. 반대로 사슬은 목록이 두 칸 이하라
$\log$ 가 1 이고, 그때는 정렬 항이 $2E$ 규모로 내려갑니다.

마지막으로 계수입니다. 제약 규모 $V = E = 100{,}000$ 을 넣으면 각 항이 얼마인지 나와요.

| 항 | 무엇을 세는가 | 그때의 값 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선마다 두 번 넣는다 | 200,000 |
| 목록 정렬 | $2E \log_2 \Delta$, $\Delta \le 99{,}999$ | 3,400,000 이하 |
| 스택 넣기·꺼내기 | $Q(s) \le 1 + 2E$ | 200,001 이하 |
| 배열 만들기 | 정점마다 `visited` 한 칸 | 100,000 |

**정렬 항이 나머지를 다 합친 것보다 큽니다.** 깊이 우선 방문 자체는 $V + E$ 규모인데, 「번호가
작은 이웃부터」라는 규칙 하나가 $\log$ 를 붙여요. 그 규칙이 없으면 정렬을 지우고 $V + E$ 로
내려갈 수 있습니다.

### 불변식 — 스택은 방문한 순서대로 쌓인 이웃 구간이고 구간 안은 번호 내림차순이다

파트 1 에서 코드가 동작하는 것을 열한 단계로 봤습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지
언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로
유지되는지 확인해 봅시다.

> 반복문의 한 바퀴가 끝날 때마다, 스택은 구간 여럿이 아래에서 위로 쌓인 모양입니다. 아래에서
> `k` 번째 구간은 `order` 의 `k` 번째 정점이 넣은 이웃들 중 아직 안 꺼낸 것이고, 한 구간 안에서는
> 번호가 큰 것이 아래에 있습니다.

```text
스택 = [ 첫 번째로 방문한 정점이 넣은 것 | … | 마지막으로 방문한 정점이 넣은 것 ]
                                                                            ↑ 맨 위
       └ 구간 안은 번호 내림차순이므로, 맨 위 구간의 맨 위가 그 구간에서 가장 작은 번호다
```

「한 바퀴가 끝날 때마다」가 중요합니다. 반복이 다 끝난 뒤 한 번만 참인 것이 아니라 **정점 하나를
처리한 직후마다** 참이라는 뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** 스택에 `start` 하나만 있을 때는 구간이 하나이고 원소가 하나뿐이라
내림차순 조건이 저절로 맞습니다. 그 뒤로 상태를 바꾸는 갈래는 셋이에요.

| 무슨 일 | 스택이 어떻게 바뀌는가 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| ① 처음 꺼낸다 | 맨 위 구간에서 하나가 빠지고, 새 구간 하나가 맨 위에 쌓인다 | 빼는 것은 맨 위라 남은 구간이 여전히 내림차순이다. 새 구간은 정렬된 목록을 **뒤에서 앞으로** 넣은 것이라 아래가 큰 번호다 |
| ② 이미 결과에 있다 | 맨 위 구간에서 하나가 빠진다 | 맨 위를 뗀 것이라 내림차순이 그대로다. 구간이 비면 그 구간이 없어질 뿐이다 |
| 스택이 빈다 | 구간이 하나도 안 남는다 | 남은 후보가 없다는 뜻이고, 반복이 끝난다 |

첫 줄의 「뒤에서 앞으로 넣은 것이라 아래가 큰 번호」가 어디서 오는지 값으로 확인해 봅시다.
전개의 T2 와 T3 이 그 자리예요.

```text
T2 직후   adj[0] = [1, 2] 를 뒤에서 앞으로 넣었다   스택 [2, 1]         구간 하나, 내림차순
T3 직후   adj[1] = [0, 3] 을 뒤에서 앞으로 넣었다   스택 [2 | 3, 0]     구간 둘, 각각 내림차순
T4 직후   맨 위 0 을 버렸다                          스택 [2 | 3]        여전히 내림차순
T5 직후   adj[3] = [1] 을 넣었다                     스택 [2 | 1]        정점 1 의 구간이 비었다
          └ 어느 시점에도 각 구간 안이 내림차순이고, 맨 위가 그 구간의 최솟값이다
```

이 불변식이 답의 정확성을 그대로 줍니다. 맨 위 구간은 **가장 최근에 방문한 정점**이 남긴
후보들이고 그 맨 위가 **그중 가장 작은 번호**이므로, 꺼내는 순서가 「가장 깊은 곳에서, 가장 작은
번호부터」가 돼요. 그것이 이 문제가 요구한 순서 그대로입니다.

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| 정점 하나 `dfsTraversal(1, [], 0)` | 0 을 꺼내 결과에 넣지만 넣을 이웃이 없어 스택이 빈다 | `[0]` |
| 간선 없음 `dfsTraversal(2, [], 1)` | `adj[1]` 이 빈 목록이라 새 구간이 안 쌓인다 | `[1]` |
| 고립된 시작 정점 `dfsTraversal(3, [[0,1]], 2)` | 정점 0·1 은 스택에 한 번도 안 들어간다 | `[2]` |
| 분리된 그래프 `dfsTraversal(5, [[0,1],[2,3]], 0)` | 정점 2·3·4 가 `R(0)` 밖이다 | `[0, 1]` |
| 자기 루프 `dfsTraversal(2, [[0,0],[0,1]], 0)` | `adj[0]` 에 0 이 두 번 들어가지만 꺼낼 때 ② 로 버려진다 | `[0, 1]` |
| 중복 간선 `dfsTraversal(2, [[0,1],[0,1]], 0)` | 같은 이웃이 목록에 두 번 들어가고 정렬해도 나란히 남는다 | `[0, 1]` |

자기 루프와 중복 간선이 이 절차의 경계입니다. 둘 다 이웃 목록을 길게 만들지만 결과는 안 바꿔요 —
꺼낼 때 `visited` 를 보므로 두 번째부터는 ② 로 버려지기 때문입니다. 대신 스택에 들어가는 총
원소 수 `1 + 2E` 에는 그대로 반영됩니다.

**이제 깨뜨려 봅시다.** 불변식의 「구간 안은 번호 내림차순」을 지키던 줄이 어느 것인지는 바꿔
보면 확인됩니다. 이웃 목록을 넣는 반복문 **한 줄만** 앞에서 뒤로 넣도록 바꿉니다.

```ts
for (let i = 0; i < list.length; i++) stack.push(list[i] as number); // ← 첨자 방향만 바꿨다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-push-order-->

```text
                        큰 번호부터 넣는다   작은 번호부터 넣는다
전개가 쓰는 여섯 정점   [0, 1, 3, 2, 4]      [0, 2, 4, 1, 3]
네 정점 그래프          [0, 1, 3, 2]         [0, 3, 1, 2]
한 줄로 이은 네 정점    [0, 1, 2, 3]         [0, 1, 2, 3]
```

앞에서 뒤로 넣으면 구간 안이 **오름차순**이 되고, 그러면 맨 위가 그 구간의 최댓값입니다. 여섯
정점 그래프에서 정점 0 의 구간이 `[1, 2]` 가 되어 2 가 먼저 꺼내지고, 결과가 `[0, 2, 4, 1, 3]`
으로 어긋나요.

```text
구간 [1, 2] 에서 꺼내면       2 가 나온다   order [0, 2]   ← 규칙은 1 을 먼저 요구한다
구간 [2, 1] 에서 꺼내면       1 이 나온다   order [0, 1]   ✓
```

**한 줄로 이은 네 정점에서는 두 값이 같다는 것**도 함께 보세요. 사슬은 갈림길이 없어 구간에
후보가 둘 이상 쌓이는 일이 없습니다. 이 입력만 시험하면 바꿔 놓고도 통과해서, 잘못된 코드를
그대로 두게 돼요.

### 비용 계산

#### 비용을 세는 과정

한 번의 반복이 하는 일은 스택에서 하나를 꺼내고, ① 갈래면 그 정점의 이웃 목록을 한 번 읽어
스택에 넣는 것뿐입니다. 전개의 값으로 확인하면 T2 가 정점 0 의 이웃 둘, T3 이 정점 1 의 이웃 둘,
T5 가 정점 3 의 이웃 하나, T7 이 정점 2 의 이웃 둘, T9 가 정점 4 의 이웃 하나였어요.

```text
꺼낸 정점   갈래   이웃 목록 길이   해당 단계
  0          ①            2         T2
  1          ①            2         T3
  3          ①            1         T5
  2          ①            2         T7
  4          ①            1         T9
  0 · 1 · 0 · 2   ②       —         T4 · T6 · T8 · T10   버리기만 한다
  5                       —         스택에 안 들어갔다. 목록을 읽지 않는다
                          └ 넣은 것 합 8, 처음 넣은 하나를 더해 꺼내기 9
```

그러니 꺼내기 횟수는 **1 더하기 도달 가능한 정점들의 이웃 목록 길이의 합**입니다. 그래프가
하나로 이어져 있으면 그 값이 `1 + 2E` 이고, 도달할 수 없는 부분이 있으면 그만큼 작아져요.
그 앞에 이웃 목록을 만드는 비용과 정렬 비용이 붙습니다.

```text
총식 = 배열 만들기 + 이웃 목록 만들기 + 목록 정렬        + 스택 연산
        Θ(V)         Θ(V + E)          O(E · log Δ)       Θ(1 + Σ deg(v))
                     ↑ 빈 목록 V 개 + 간선마다 두 번 넣기   ↑ v 는 R(s) 위에서
     = Θ(V + E) + O(E · log V)

메모리 = visited·order Θ(V) + 이웃 목록 Θ(V + E) + 스택 Θ(1 + 2E) = Θ(V + E)
```

여기서 센 것은 **꺼내기와 이웃 목록 읽기, 그리고 정렬 비교**입니다. `Array.prototype.sort` 가
실제로 몇 번 비교하는지는 실행 환경의 정렬 구현이 정하므로, 위 식의 `O(E · log Δ)` 는
**비교 정렬의 상한**을 적은 것이에요.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (간선이 하나도 없다) | `O(V)` | `Θ(V)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(V + E log V)` | 정의되지 않는다 |
| **최악의 경우** (한 정점에 간선이 몰린다) | `O(V + E log V)` | `Θ(V + E log V)` |

**평균이 정의되지 않는 이유**를 적어 둡니다. 이 문제는 간선이 어떻게 배치되는지에 대한 분포를
주지 않아요. 정렬 항이 `Σ deg(v) log deg(v)` 라 간선이 몇 정점에 몰려 있는지에 따라 값이 갈리는데,
그 「몰린 정도」의 분포가 정해지지 않으면 기댓값을 계산할 대상이 없습니다.

```text
간선 수가 같아도 정렬 항이 갈린다 — V = 100,000, E = 99,999

  별 모양   목록 하나가 99,999 칸   S = 99,999 × log₂ 99,999 ≈ 166만
  사슬      목록마다 2 칸 이하      S = 2 × 99,998 ≈ 20만
            └ 같은 E 인데 약 8 배 갈린다. 어느 쪽이 얼마나 자주 오는지는 문제가 안 정한다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요.
같은 입력을 두 번 넣으면 꺼내기 횟수까지 똑같이 나옵니다.

```text
최악 보장     어떤 입력에도 V + E log V 규모를 넘지 않는다   ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다   ← 이 절차는 여기 해당하지 않는다
```

경계의 종류도 갈라 적습니다. 최악의 `Θ(V + E log V)` 는 상한이자 하한이에요 — 별 모양 입력에서
목록 하나를 정렬하는 데만 `(V-1) log₂ (V-1)` 규모의 비교가 필요하므로 그보다 적게 할 방법이
없습니다. 반면 최선의 `Θ(V)` 는 정렬할 것이 없어 배열을 만드는 비용만 남은 값이에요.

#### 최악을 만드는 입력

두 축이 갈립니다 — 정렬 비교를 최대로 만드는 입력과, 스택이 동시에 담는 원소 수를 최대로 만드는
입력이에요. 정점 100,000 개를 잇는 데 필요한 간선은 최소 99,999 개이고, 그 최소로 이은 두 극단을
봅시다.

```text
정점 100,000 개 · 간선 99,999 개짜리 두 극단

  별 모양                        사슬
    0 이 나머지 99,999 개와        0-1-2-…-99,999 를 한 줄로
    전부 이어져 있다

        1  2  3  …                 0 - 1 - 2 - … - 99,999
         \ | /
           0
```

두 그래프는 정점 수도 간선 수도 같습니다. 그런데 정렬 항과 스택 동시 재고가 완전히 갈려요.

| 입력 | 목록 길이의 최댓값 | 정렬 항 $S$ | 스택 동시 재고 최대 | 최대 깊이 |
| --- | --- | --- | --- | --- |
| 별 모양 | 99,999 | 약 166만 | **99,999** | 1 |
| 사슬 | 2 | 약 20만 | **2** | 99,999 |

**별 모양이 두 축 모두에서 최악입니다.** 정점 0 을 꺼내는 한 번에 99,999 개가 한꺼번에 스택에
들어가고, 그 목록 하나를 정렬하는 데 `99,999 × log₂ 99,999` 규모의 비교가 필요해요.

```text
별 모양에서 스택이 가장 커지는 자리
  0 을 꺼낸다 → 이웃 99,999 개가 전부 스택에 들어간다
  그 뒤로는 꺼낼 때마다 이웃이 0 하나뿐이고, 그 0 은 이미 결과에 있어 ② 로 버려진다

사슬에서
  i 를 꺼낸다 → 이웃 둘을 넣지만 한 바퀴 뒤에 i-1 이 ② 로 버려진다
             └ 스택에 언제나 두 개 이하
```

「깊은 그래프가 최악」이라는 통념은 이 절차에서 거짓입니다. 사슬은 가장 깊은 그래프인데 스택이
가장 작아요. 재귀로 구현했다면 호출 깊이가 10 만이 되어 「재귀로 적으면」에서 본 그대로 실패하지만,
이 글의 코드는 반복문이라 깊이가 비용에 들어가지 않습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 다음 정점을 매번 간선 목록 전체에서 찾던 것을
**정렬해 둔 이웃 목록에서 앞에서부터 읽는 것**으로 바꿨고, 「어디까지 읽었는가」를 스택이
대신하며, 작은 번호를 먼저 꺼내려면 목록을 **뒤에서 앞으로** 넣어야 합니다.

```text
간선 목록 → 이웃 목록 → 목록마다 정렬 → start 를 스택에 → 맨 위를 꺼낸다 → 처음 꺼낸 것만 결과에
                          └ 2E log Δ 이하        └ 꺼내기 1 + 2E 이하   └ 이웃을 큰 번호부터 넣는다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T3 에서 정점 1 을 꺼내 결과에 넣고 이웃 `[0, 3]` 을 큰
번호부터 넣었어요. 그 한 걸음에서 **이웃 0 을 넣지 않았다면** 최종 결과가 무엇이 되었을까요?

```text
T3   1 을 꺼낸다   ① order 에 1   스택 [2, 3, 0]   ← 이 0 을 안 넣으면?
```

<!--check:skip0-->
결과는 `[0, 1, 3, 2, 4]` 그대로입니다. 달라지는 것은 꺼내기 횟수뿐이에요.

```text
0 을 안 넣으면   스택 [2, 3]      T4 가 통째로 없어진다
3 을 꺼낸다      order [0, 1, 3]  스택 [2, 1]
1 을 꺼낸다      이미 결과에 있다  스택 [2]
2 를 꺼낸다      order [0,1,3,2]  스택 [4, 0]
                 └ 꺼내기가 9 에서 8 로 줄고 결과는 같다
```

정점 0 은 이미 결과에 들어 있어서 어차피 ② 로 버려질 것이었기 때문입니다. 이것이 「넣을 때
거르면 안 되는가」를 다시 묻게 하는 자리인데, 답은 **어떤 이웃을 거르는가에 달려 있다**예요.
이미 결과에 있는 이웃만 거르면 안전하고, 「스택에 넣으면서 표시」까지 하면 「방문 표시를 꺼낼
때가 아니라 넣을 때 해도」에서 본 대로 순서가 어긋납니다.
