# 위상 정렬 — 진입 차수가 0 이 되는 순간 큐에 담으면 맨 앞에 놓을 정점을 다시 찾지 않는다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 정점의 나열을
전부 만들어 검사하는 방법에서 출발해, 정점마다 진입 차수 하나를 세어 두고 그 값이 0 이 되는 순간 큐에
담는 방법까지 갑니다. 그 방법을 준비되는 차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한
조각씩 만듭니다.

### 전체 컨셉

**유향 그래프**는 정점들과 **방향이 있는 간선**으로 이루어집니다. 간선 `[u, v]` 는 `u → v` 를 뜻하고, 이
글에서는 「`u` 가 `v` 보다 먼저 와야 한다」는 제약으로 읽어요. 강의 목록이라면 `u` 는 선수 과목이고 `v` 는
그것을 들은 뒤에야 들을 수 있는 강의입니다. 정점 여섯 · 간선 여섯인 그래프를 그리면 이렇습니다.

<!--fig:concept-graph-->
![정점 여섯 · 간선 여섯 — 간선 u→v 는 u 가 v 보다 먼저라는 제약](./figs/concept-graph.svg)

이 글이 만드는 것은 **모든 간선의 방향을 지키는 정점 나열**입니다. 정점을 왼쪽부터 한 줄로 늘어놓았을 때
간선 `u → v` 마다 `u` 가 `v` 보다 왼쪽에 있으면 그 나열이 답이고, 이것을 **위상 순서**라고 불러요. 이 글의
절차가 낸 답을 왼쪽부터 놓아 보면 간선이 모두 오른쪽을 향합니다. 정점 아래 수가 나열에서의 자리예요.

<!--fig:concept-order-->
![답 하나를 왼쪽부터 놓으면 간선이 모두 오른쪽을 향한다](./figs/concept-order.svg)

간선마다 두 끝의 자리를 재면 확인됩니다.

<!--proof:concept-check-->

| 간선 u→v | u 의 자리 | v 의 자리 | 방향 |
| --- | ---: | ---: | --- |
| 5→2 | 1 | 2 | 지킨다 |
| 5→0 | 1 | 3 | 지킨다 |
| 4→0 | 0 | 3 | 지킨다 |
| 4→1 | 0 | 5 | 지킨다 |
| 2→3 | 2 | 4 | 지킨다 |
| 3→1 | 4 | 5 | 지킨다 |

나열 [4, 5, 2, 0, 3, 1] 에서 간선 6 개 가운데 6 개가 방향을 지킵니다.

<!--/proof-->

**답이 하나로 정해지지는 않습니다.** 정점 4 와 5 는 서로 이어져 있지 않아서 어느 쪽을 먼저 놓아도 간선을
하나도 어기지 않아요. 같은 그래프에서 유효한 나열 셋을 꺼내고, 유효한 것이 모두 몇 가지인지 세었습니다.

<!--proof:concept-many-->

| 나열 | 간선 방향 |
| --- | --- |
| [4, 5, 2, 0, 3, 1] | 모두 지킨다 |
| [5, 2, 3, 4, 1, 0] | 모두 지킨다 |
| [4, 5, 0, 2, 3, 1] | 모두 지킨다 |

정점 6 개를 늘어놓는 나열 720 가지 가운데 모든 간선을 지키는 것은 13 가지입니다.

<!--/proof-->

하나만 내면 되니 전부 만들 까닭은 없어요. 그리고 유효한 나열이 **하나도 없는** 경우도 있습니다. 정점
0 · 1 · 2 가 `0 → 1 → 2 → 0` 으로 고리를 이루면 「0 이 1 보다 먼저」, 「1 이 2 보다 먼저」, 「2 가 0 보다 먼저」
를 함께 지켜야 하고, 셋을 이으면 0 이 0 보다 먼저여야 합니다. 그런 나열은 없어요. 간선을 따라가다 출발한
정점으로 되돌아오는 길을 **사이클**이라고 부르고, 사이클이 하나라도 있으면 답이 없습니다. 이 글의 함수는
그때 `null` 을 돌려줘요. 자기 자신을 가리키는 간선 `[v, v]` 도 길이 1 짜리 사이클입니다.

이 글이 기대는 수는 정점마다 하나, **진입 차수**입니다. 진입 차수는 **그 정점으로 들어오는 간선의 수**예요.
진입 차수가 0 인 정점은 먼저 와야 할 정점이 하나도 없으니 맨 앞에 놓아도 됩니다. 정점 안에 진입 차수를
적고, 0 인 정점을 강조했습니다.

<!--fig:concept-indegree-->
![정점 안의 수는 진입 차수 — 그 정점으로 들어오는 간선의 수](./figs/concept-indegree.svg)

정점 하나를 결과에 넣으면 그 정점에서 나가는 간선은 이미 지켜진 것이라 **지운 셈** 칠 수 있습니다. 그러면
그 간선의 머리 정점들은 진입 차수가 하나씩 줄어요. 정점 4 와 5 를 차례로 넣으면서 진입 차수를 적었습니다.

<!--proof:concept-remove-->

| 시점 | 정점 0 1 2 3 4 5 의 진입 차수 | 결과에 없고 진입 차수가 0 인 정점 |
| --- | --- | --- |
| 처음 | 2 2 1 1 0 0 | [4, 5] |
| 4 를 넣은 뒤 | 1 1 1 1 - 0 | [5] |
| 5 를 넣은 뒤 | 0 1 0 1 - - | [0, 2] |

결과에 넣은 정점은 「-」 로 적었습니다.

<!--/proof-->

5 를 넣은 뒤 정점 0 과 2 의 진입 차수가 0 이 됐습니다. 진입 차수가 0 이 되는 순간은 **그 값을 줄이는 바로
그 자리**뿐이라, 0 인 정점을 매번 다시 찾지 않고 줄이다 0 이 되면 그 자리에서 **큐**(먼저 넣은 것을 먼저
꺼내는 목록)에 담으면 됩니다. 큐에서 하나씩 꺼내 결과에 넣기를 되풀이하고, 큐가 비었을 때 결과에 정점이
다 들어갔으면 그것이 답이에요. 못 들어간 정점이 남으면 그 정점들이 사이클에 걸려 있습니다. 이 절차는
**칸 알고리즘**(Kahn's algorithm)이라는 이름으로 알려져 있어요. 할 일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 진입 차수 세기 | 간선 하나를 나가는 목록 한 칸과 진입 차수 한 칸에 옮긴다 | 간선마다 한 번 |
| 큐에 넣고 꺼내기 | 진입 차수가 0 인 정점을 뒤에 넣고 앞에서 꺼낸다 | 정점마다 많아야 한 번씩 |
| 진입 차수 줄이기 | 꺼낸 정점의 나가는 목록을 한 번 읽는다 | 목록 길이의 합, 곧 간선 수 이하 |
| 모두 | | `O(V + E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 정점과 간선으로 적는 방식.** 특히 **이웃 목록** — 정점마다 이어진 정점의 목록을 하나씩 두는
  표현입니다. 이 글의 `next[u]` 가 그것이에요. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **유향 그래프에서 들어오는 간선과 나가는 간선이 다르다는 것.** 간선 `[u, v]` 는 `u` 의 나가는 간선이면서
  `v` 의 들어오는 간선입니다. 이 글은 두 방향을 서로 다른 자료에 담으므로 둘을 섞으면 뒤가 어긋나요.
- **큐가 먼저 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기와 꺼내기가 각각 `O(1)` 입니다. 모르면
  [`queue` 가이드](../../../data-structures/linear/queue/queue-guide.mdx)를 보세요. 배열 하나와 다음에 읽을
  자리 `head` 로 큐를 드는 모양은 [`bfsShortestPath`](../bfsShortestPath/bfsShortestPath-guide.md) 와 같습니다.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점의 진입 차수가 0 인가」를 배열 한 칸을 읽어 판정합니다.

이름이 비슷한 과제를 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 이 글에서 |
| --- | --- |
| 사이클이 없는 유향 그래프의 정점을 간선 방향대로 늘어놓는다 | 다룬다 |
| 유향 그래프에 사이클이 있는지만 판정한다 | 결과 길이 비교로 함께 나온다. 판정만이 목적이면 [`directedCycleDetection`](../directedCycleDetection/directedCycleDetection-guide.md) |
| 서로 오갈 수 있는 정점 묶음을 찾는다 | 다루지 않는다 — [`stronglyConnectedComponents`](../stronglyConnectedComponents/stronglyConnectedComponents-guide.md) |
| 간선 수로 센 최단 거리를 구한다 | 다루지 않는다 — [`bfsShortestPath`](../bfsShortestPath/bfsShortestPath-guide.md) |

둘째 줄이 이 글의 부산물입니다. 순서를 만들다 보면 사이클이 있는지가 저절로 확인돼요. 그 까닭은 뒤에서
값으로 봅니다.

### 아이디어를 떠올리는 과정 — 순열 전수 검사에서 진입 차수가 0 이 된 정점을 담는 큐까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아서
위상 순서 하나를 돌려줍니다.

```ts
function topologicalSort(
  n: number,
  edges: [number, number][],
): number[] | null;
```

- 입력: 정점 수 `n`, 유향 간선 목록 `edges`. 정점 번호는 0 부터 `n − 1` 까지예요. 자기 자신을 가리키는 간선과
  같은 간선이 두 번 적힌 것도 들어올 수 있습니다.
- 출력: 모든 간선 `[u, v]` 에 대해 `u` 가 `v` 보다 앞에 오는 길이 `n` 의 정점 나열. 그런 나열이 없으면 `null`
  입니다. 유효한 나열이 여럿이면 그중 어느 것을 내도 됩니다.
- 규모: 정점 수와 간선 수가 각각 100,000 이하입니다. 비용은 흔한 채점 환경의 예산인 1 초에 대어 잽니다.

「어느 것을 내도 된다」가 이 과제의 계약이라, 이 글이 만들 절차는 어느 나열을 고를지 정하는 데 비용을 쓰지
않아요. 이 글이 쓰는 기호는 여덟이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` 입니다 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 100,000` |
| `u` · `v` | 정점 번호. 간선 `[u, v]` 에서 `u` 가 꼬리, `v` 가 머리입니다 | `0` 부터 `V − 1` |
| `deg⁻(v)` | 정점 `v` 로 들어오는 간선의 수. 간선을 다 읽은 직후의 진입 차수입니다 | 모든 정점을 더하면 `E` |
| `indegree[v]` | 정점 `v` 의 진입 차수 — 아직 결과에 안 들어간 정점에서 오는 간선만 셉니다 | 처음 값이 `deg⁻(v)` |
| `next[u]` | `u` 에서 나가는 간선의 머리 정점 목록 | 길이를 다 더하면 `E` |
| `queue` | 진입 차수가 0 이 된 정점을 담는 큐 | 담기는 총수는 `V` 이하 |
| `order` | 결과 나열을 담는 배열 | 길이가 `V` 이면 답 |

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. **정점의 나열을 전부 만들어 하나씩 검사**하는
것이에요. 나열 하나를 만들고 간선을 모두 지키는지 보고, 하나라도 어기면 다음 나열로 갑니다.

```ts
for (const perm of 모든_순열(n)) {                       // 사전순으로 하나씩
  if (edges.every(([u, v]) => at(perm, u) < at(perm, v))) return perm;
}
return null;
```

위의 여섯 정점 그래프에 실제로 실행하면 이렇게 나옵니다.

<!--proof:brute-walk-->

| 센 것 | 값 |
| --- | ---: |
| 검사한 순열 수 | 580 |
| 읽은 간선 끝점 수 | 2,024 |
| 처음 찾은 유효한 순열 | [4, 5, 0, 2, 3, 1] |

순열 720 개 가운데 580 번째에서 멈췄습니다.

<!--/proof-->

답은 맞아요. 문제는 나열의 개수입니다. 정점이 `V` 개면 나열은 `V!` 가지이고, 답이 없는 입력에서는 그것을
**전부** 검사하고서야 `null` 을 낼 수 있습니다. 정점이 고리를 이룬 그래프에 넣어 검사한 순열을 세었어요.
나열 하나를 만드는 데 연산 한 번만 든다고 쳐도 이만큼 걸립니다.

<!--proof:naive-scale-->

| 정점 V | 검사한 순열 | 초당 1 억 개 기준 | 센 방법 |
| ---: | ---: | ---: | --- |
| 6 | 720 | 0.000 초 | 실행 |
| 7 | 5,040 | 0.000 초 | 실행 |
| 8 | 40,320 | 0.000 초 | 실행 |
| 10 | 3,628,800 | 0.036 초 | V! |
| 15 | 1,307,674,368,000 | 13,077 초 | V! |
| 20 | 2.433e+18 | 771 년 | V! |

입력은 정점 V 개가 고리를 이룬 그래프입니다. 실행한 3 줄에서 검사한 순열이 모두 V! 과 같았고, 나머지 줄은 V! 로 낸 값입니다. 정점이 100,000 개면 V! 만 적어도 456,574 자리입니다.

<!--/proof-->

정점 20 개에서 이미 수백 년이고, 규모의 상한인 정점 10 만 개에서는 나열의 개수를 적는 것조차 수십만 자리가
됩니다. 나열을 통째로 고르는 방식으로는 시작할 수 없어요. 방향을 바꿔 **한 자리씩** 정해 봅시다. 맨 앞 자리에
놓아도 되는 정점은 자기보다 먼저 와야 하는 정점이 없는 정점, 곧 **들어오는 간선이 없는 정점**입니다. 그
정점을 놓고 나면 그 정점에서 나가는 간선은 이미 지켜졌으니 지운 셈 치고, 남은 그래프에서 같은 질문을 다시
합니다.

<!--proof:origin-peel-->

| 차례 | 남은 간선 | 들어오는 간선이 없는 정점 | 고른 정점 |
| ---: | ---: | --- | ---: |
| 1 | 6 | 4 · 5 | 4 |
| 2 | 4 | 5 | 5 |
| 3 | 2 | 0 · 2 | 2 |
| 4 | 1 | 0 · 3 | 0 |
| 5 | 1 | 3 | 3 |
| 6 | 0 | 1 | 1 |

6 차례 가운데 후보가 없었던 차례는 0 번이고, 고른 순서 [4, 5, 2, 0, 3, 1] 는 정본의 답과 같습니다.

<!--/proof-->

여섯 차례 모두 고를 정점이 있었습니다. 절차의 모양이 정해졌어요 — 「들어오는 간선이 없는 정점을 하나 고르고,
그 정점과 거기서 나가는 간선을 지운다」를 정점 수만큼 되풀이합니다. 남은 것은 그 정점을 **어떻게 찾는가**이고,
비용은 전부 거기서 나옵니다. 찾는 방법 둘을 같은 입력에 실행해 읽은 원소를 세었습니다. 하나는 자리를 정할
때마다 간선 목록 전체를 다시 읽어 아직 안 뺀 정점에서 오는 간선이 없는 정점을 고르는 방법이고, 다른 하나는
정점마다 진입 차수를 배열에 한 번 세어 두고 정점을 뺄 때마다 그 정점이 가리키는 칸만 하나씩 줄이는 방법입니다.

<!--proof:scan-vs-count-->

| 방법 | 전개 입력에서 읽은 원소 | 결과 | 사슬 1,000 에서 읽은 원소 |
| --- | ---: | --- | ---: |
| 간선 목록을 매번 다시 읽는다 | 93 | [4, 5, 0, 2, 3, 1] | 2,498,500 |
| 진입 차수를 세어 둔다 | 39 | [4, 5, 0, 2, 3, 1] | 503,497 |

두 방법의 결과가 같습니다.

<!--/proof-->

답은 같은데 여섯 정점에서 93 이 39 가 됐고, 정점 1,000 개짜리 사슬에서는 약 250 만이 약 50 만이 됐습니다.
앞의 방법은 자리를 하나 정할 때마다 간선 `E` 개를 전부 다시 읽고, 뒤의 방법은 간선을 처음에 한 번만 읽어요.
여기서 관찰한 것은 하나입니다. **한 자리를 정하는 비용이 `E` 에서 뺀 정점의 나가는 간선 수로 줄었어요.**

그런데 찾는 일이 아직 남아 있습니다 — 진입 차수가 0 인 정점을 어떻게 찾을 것인가. 가장 단순한 후보부터
시험해 봅시다. **매 바퀴 진입 차수 배열 `V` 칸을 앞에서부터 읽어 0 인 칸을 찾는** 방법이에요. 이미 뺀 칸도,
아직 0 이 아닌 칸도 다시 읽습니다. 진입 차수가 0 이 되는 순간은 그 값을 줄이는 자리뿐이니, **그 자리에서 0 이
됐는지 보고 0 이면 큐에 담는** 방법과 나란히 실행했습니다.

<!--proof:array-vs-queue-->

| 방법 | 전개 입력 | 사슬 1,000 | 사슬 10,000 |
| --- | ---: | ---: | ---: |
| 진입 차수 배열을 매 바퀴 앞에서부터 읽는다 | 39 | 503,497 | 50,034,997 |
| 0 이 되는 자리에서 큐에 담는다 | 24 | 3,997 | 39,997 |

두 방법이 모두 유효한 나열을 낸 입력은 3 개 가운데 3 개입니다.

<!--/proof-->

사슬 1,000 에서 약 50 만 대 약 4 천이고, 10,000 으로 늘리면 약 5 천만 대 약 4 만입니다. 배열을 매 바퀴 읽는
방법은 `k` 번째 자리를 정할 때 앞쪽 `k` 칸을 다시 읽어서, 정점 수를 열 배로 늘리면 값이 백 배가 돼요. 세 방법이
사슬에서 읽는 원소를 식으로 적고 규모의 상한에 넣으면 이렇습니다.

<!--proof:origin-scale-->

| 방법 | 사슬 V 에서 읽는 원소 | V = 100,000 | 초당 1 억 번 기준 |
| --- | --- | ---: | ---: |
| 간선 목록을 매번 다시 읽는다 | 2V(V − 1) + V(V + 1)/2 | 24,999,850,000 | 250 초 |
| 진입 차수 배열을 매 바퀴 읽는다 | 3(V − 1) + V(V + 1)/2 | 5,000,349,997 | 50.003 초 |
| 0 이 되는 자리에서 큐에 담는다 | 3(V − 1) + V | 399,997 | 0.004 초 |

세 식은 사슬 10 · 100 · 1,000 을 실행한 값과 모두 일치했고, V = 100,000 열은 그 식으로 낸 값입니다.

<!--/proof-->

큐에 담는 방법만 예산 1 초 안에 듭니다. 지금까지 해 본 방법을 차례로 놓으면, 앞 방법이 막힌 자리에서 다음
방법이 나왔고 셋은 버리고 하나가 남았어요.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **진입 차수가 0 이 된 정점을 담는 큐**입니다. 칸 알고리즘이 바로 이것이에요.
진입 차수를 어떻게 세는지, 큐를 무엇으로 시작하는지, 줄이는 일이 왜 정점을 빠뜨리지도 두 번 담지도 않는지,
사이클을 어디서 알아보는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 진입 차수가 0 이 된 정점을 담는 큐

이 아이디어를 한 문장으로 줄이면 이렇습니다. **간선을 한 번 읽어 정점마다 진입 차수를 세고, 진입 차수가 0 인
정점을 큐에 담은 뒤, 큐에서 꺼낸 정점을 결과에 붙이며 그 정점이 가리키는 정점의 진입 차수를 하나씩 줄여 0 이
되는 순간 큐에 담는 일을 큐가 빌 때까지 되풀이합니다.** 진입 차수와 큐는 둘 다 앞 절에서 값으로 보았어요. 이
절은 그 방법을 실현하는 순서대로 네 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 진입 차수 세기 | 간선 목록을 `next` 와 `indegree` 로 옮긴다 | — |
| 시작할 때 한 번 | 2단계 처음 후보 담기 | 진입 차수가 0 인 정점을 번호 순서로 큐에 담는다 | 1단계의 `indegree` |
| 큐가 빌 때까지 | 3단계 꺼내며 진입 차수 줄이기 | 꺼낸 정점을 `order` 에 붙이고, 머리의 진입 차수를 줄여 0 이면 담는다 | 1단계의 `next` · `indegree`, 2단계의 큐 |
| 끝날 때 한 번 | 4단계 결과 길이로 사이클 가려내기 | `order` 의 길이가 `V` 인지 본다 | 3단계의 `order` |

#### 1단계 — 진입 차수 세기

간선 목록은 「누가 누구보다 먼저인가」를 담고 있지만, 「정점 1 보다 먼저여야 하는 정점이 몇 개인가」에 답하려면
목록 전체를 읽어야 합니다. 간선 `[u, v]` 하나를 읽으면서 나가는 쪽은 `next[u]` 에 `v` 로, 들어오는 쪽은
`indegree[v]` 를 하나 올리는 것으로 담아 둡니다. 간선마다 두 자료에 한 번씩 들어가요.

<!--proof:build-count-->

| 정점 v | next[v] | indegree[v] | 들어오는 간선 |
| ---: | --- | ---: | --- |
| 0 | [] | 2 | 5→0 · 4→0 |
| 1 | [] | 2 | 4→1 · 3→1 |
| 2 | [3] | 1 | 5→2 |
| 3 | [1] | 1 | 2→3 |
| 4 | [0, 1] | 0 | 없음 |
| 5 | [2, 0] | 0 | 없음 |

next 목록 길이의 합은 6 이고 indegree 의 합은 6 입니다. 간선은 6 개입니다.

<!--/proof-->

크기도 여기서 정해집니다. `indegree` 는 정점마다 한 칸이라 `V` 칸이고, `next` 는 목록 칸을 다 더하면 간선 수
`E` 예요. 진입 차수의 합도 `E` 인데, 간선 하나가 머리 정점 하나의 진입 차수를 정확히 하나 올리기 때문입니다.
두 합이 둘 다 `E` 라는 것은 세는 방향이 맞는지 확인하는 데에는 쓸 수 없어요. 나가는 간선을 세어도 합은 `E` 이고,
그 차이는 「수행으로 알아보는 알고리즘」에서 실행 결과로 봅니다.

#### 2단계 — 처음 후보 담기

진입 차수가 0 인 정점은 먼저 와야 할 정점이 없으니 지금 당장 결과에 넣어도 됩니다. 그런 정점을 정점 번호
순서로 읽어 큐에 담아요. 큐는 배열 하나와 **다음에 꺼낼 자리** `head` 로 들고, 꺼낸 칸을 지우지 않고 `head` 만
옮깁니다.

<!--proof:build-seed-->

| 정점 v | indegree[v] | 처음 큐에 |
| ---: | ---: | --- |
| 0 | 2 | 담지 않는다 |
| 1 | 2 | 담지 않는다 |
| 2 | 1 | 담지 않는다 |
| 3 | 1 | 담지 않는다 |
| 4 | 0 | 담는다 |
| 5 | 0 | 담는다 |

큐는 [4, 5] 로 시작합니다.

<!--/proof-->

번호 순서로 담는 것은 필수가 아닙니다. 계약이 「어느 것을 내도 된다」이니 처음 후보를 어떤 순서로 담아도 답이
돼요. 이 글은 결과가 입력만으로 하나로 정해지도록 번호 순서를 씁니다.

#### 3단계 — 꺼내며 진입 차수 줄이기

큐 앞에서 정점 `u` 를 꺼내 `order` 뒤에 붙이고, `next[u]` 의 정점 `v` 마다 `indegree[v]` 를 하나 줄입니다.
줄인 값이 0 이면 그 자리에서 큐 뒤에 담고, 아직 0 이 아니면 담지 않아요. 쉬운 경우는 진입 차수가 1 인 정점입니다
— 한 번 줄면 바로 0 이 돼요. 불안한 경우는 진입 차수가 2 인 정점 0 과 1 입니다. 첫 번째로 줄 때는 아직 후보가
아니고 두 번째로 줄 때에야 후보가 되는데, 그 사이에 잊히지 않을까요? 정점 4 와 5 를 꺼낸 뒤의 모습부터 봅시다.
결과에 넣은 정점과 그 정점에서 나가는 간선을 흐리게, 방금 0 이 된 정점을 강조해 그렸어요.

<!--fig:build-remove-->
![T3 뒤 — 결과에 넣은 정점 4 · 5 와 그 간선을 지운 셈 친다](./figs/build-remove.svg)

정점 0 은 4 에서 한 번, 5 에서 한 번 줄어 0 이 됐습니다. 꺼낼 때마다 진입 차수 배열 전체와 큐를 적으면 이렇게
나와요.

<!--proof:build-decrease-->

| 걸음 | 꺼낸 정점 | 줄인 진입 차수 | 정점 0 1 2 3 4 5 의 진입 차수 | 새로 담은 정점 | 큐에서 안 꺼낸 부분 |
| --- | --- | --- | --- | --- | --- |
| T1 | - | 없음 | 2 2 1 1 0 0 | 4 · 5 | [4, 5] |
| T2 | 4 | 0 이 2→1 · 1 이 2→1 | 1 1 1 1 - 0 | 없음 | [5] |
| T3 | 5 | 2 가 1→0 · 0 이 1→0 | 0 1 0 1 - - | 2 · 0 | [2, 0] |
| T4 | 2 | 3 이 1→0 | 0 1 - 0 - - | 3 | [0, 3] |
| T5 | 0 | 없음 | - 1 - 0 - - | 없음 | [3] |
| T6 | 3 | 1 이 1→0 | - 0 - - - - | 1 | [1] |
| T7 | 1 | 없음 | - - - - - - | 없음 | [] |

결과에 넣은 정점은 「-」 로 적었습니다. 진입 차수를 줄인 횟수는 6 번이고 간선은 6 개입니다.

<!--/proof-->

정점 1 이 가장 불안한 자리입니다. T2 에서 2 → 1 로 줄었지만 담기지 않았고, T3 부터 T5 까지 세 걸음 동안 아무도 1 을
건드리지 않다가 T6 에서 1 → 0 이 되어 그 자리에서 담겼어요. 값이 배열 칸에 그대로 남아 있으니 잊힐 일이 없습니다.
정점마다 몇 번 줄었고 언제 담겼는지 모으면 이렇습니다.

<!--proof:build-once-->

| 정점 | 처음 진입 차수 | 줄어든 걸음 | 0 이 된 걸음 | 큐에 담긴 횟수 |
| ---: | ---: | --- | --- | ---: |
| 0 | 2 | T2 · T3 | T3 | 1 |
| 1 | 2 | T2 · T6 | T6 | 1 |
| 2 | 1 | T3 | T3 | 1 |
| 3 | 1 | T4 | T4 | 1 |
| 4 | 0 | 없음 | T1 | 1 |
| 5 | 0 | 없음 | T1 | 1 |

큐에 담긴 횟수가 1 이 아닌 정점은 0 개입니다.

<!--/proof-->

모든 정점이 처음 진입 차수만큼 줄었고, 0 이 된 걸음에 정확히 한 번 담겼습니다. 두 번 담기는 일이 없는 까닭은
코드에 있어요. 값을 줄이는 줄이 `indegree[v]` 를 하나씩 내리기만 하므로 한 번 0 이 된 값이 다시 0 이 되는
일이 없고, 담는 자리는 그 값이 막 0 이 된 순간 하나뿐입니다. 반복이 끝나는 까닭도 종료 조건이 말해 줍니다.
한 바퀴마다 `head` 가 한 칸 나아가고 큐에 담기는 총수가 `V` 이하라서, 많아야 `V` 바퀴 뒤에 `head` 가 큐 길이에
이르러 멈춥니다. 그사이 담긴 정점은 모두 한 번씩 꺼내져 나가는 목록이 읽히므로, 줄이는 횟수는 꺼낸 정점들의
나가는 간선 수의 합이에요.

#### 4단계 — 결과 길이로 사이클 가려내기

반복이 끝나면 `order` 의 길이를 `V` 와 비교합니다. 같으면 모든 정점이 들어갔으니 그것이 답이고, 작으면 `null`
을 돌려줘요. 사이클이 있는 입력에서 큐가 담은 정점 수와 반환값을 세었습니다.

<!--proof:cycle-values-->

| 입력 | 큐가 담은 정점 수 | 정점 수 n | 반환값 |
| --- | ---: | ---: | --- |
| 사이클만 있다 0→1→2→0 | 0 | 3 | null |
| 앞에 정점 하나 3→0, 사이클 0→1→2→0 | 1 | 4 | null |
| 자기 자신을 가리키는 간선 0→0 | 0 | 1 | null |
| 사이클이 없다 (전개 입력) | 6 | 6 | [4, 5, 2, 0, 3, 1] |

큐가 담은 정점 수가 n 과 같은 입력은 4 개 가운데 1 개이고, 그 입력만 null 이 아닌 답을 냈습니다.

<!--/proof-->

사이클 위의 정점은 진입 차수가 0 이 되지 못합니다. 사이클 위 정점의 진입 차수가 줄려면 사이클에서 그 앞에
있는 정점이 결과에 들어가야 하는데, 그 정점도 같은 까닭으로 들어가지 못하기 때문이에요. 둘째 줄이 그 모습입니다.
정점 3 은 들어오는 간선이 없어 담겼고, 꺼내면서 0 의 진입 차수를 2 에서 1 로 줄였지만 거기서 멈췄어요. 0 · 1 · 2
는 서로를 기다리며 끝까지 1 로 남습니다. 그러니 **사이클을 찾는 코드를 따로 두지 않아도** 길이 비교 한 줄이
그 일을 해요.

#### 이 방법이 기대는 전제

진입 차수가 0 인 정점을 담는 큐는 **간선이 앞뒤만 정하고 간격은 정하지 않는다**는 전제에 기댑니다. 결과에서의
자리는 「몇 번째로 놓였는가」일 뿐 「언제 처리할 수 있는가」가 아니에요. 같은 그래프에서 정점마다 가장 이른
차례 — 선행 정점을 다 끝낸 직후의 차례 — 를 따로 구해 결과의 자리와 나란히 놓았습니다.

<!--proof:premise-level-->

| 정점 | order 에서의 자리 | 가장 이른 차례 |
| ---: | ---: | ---: |
| 4 | 0 | 0 |
| 5 | 1 | 0 |
| 2 | 2 | 1 |
| 0 | 3 | 1 |
| 3 | 4 | 2 |
| 1 | 5 | 3 |

「가장 이른 차례」는 선행 정점의 차례 중 가장 큰 값에 1 을 더한 것이고, 선행 정점이 없으면 0 입니다. 정점 6 개 가운데 두 값이 다른 정점은 5 개입니다.

<!--/proof-->

두 값이 거의 다 다릅니다. 정점 4 와 5 는 결과에서는 0 번과 1 번 자리이지만 둘 다 가장 이른 차례가 0 이라 함께
처리할 수 있어요. 「선수 과목을 다 들은 가장 이른 학기」처럼 간격을 묻는 과제에는 이 절차가 낸 나열만으로 답할
수 없고, 그 나열을 따라가며 값을 물려주는 계산을 한 번 더 해야 합니다. 두 번째 전제는 **그래프를 미리 다 받는다**는
것이에요. 간선을 모두 읽어 진입 차수를 세고 시작하므로, 반복 도중에 간선이 더 들어오면 이미 담은 정점의 진입
차수가 틀린 값이 됩니다.

#### 후보를 큐로 꺼내는 까닭

진입 차수가 0 인 정점이 여럿 담겨 있을 때 무엇을 먼저 꺼낼지가 남은 선택입니다. 먼저 담은 것을 먼저 꺼내는
큐, 나중에 담은 것을 먼저 꺼내는 스택, 담긴 것 중 번호가 가장 작은 것을 고르는 방법 셋을 같은 입력에 실행하고,
정점 0 이 나머지 999 개를 가리키는 별 모양에서 읽은 원소를 세었습니다.

<!--proof:container-values-->

| 꺼내는 규칙 | 전개 입력의 결과 | 유효한가 | 별 모양 1,000 에서 읽은 원소 |
| --- | --- | --- | ---: |
| 큐 | [4, 5, 2, 0, 3, 1] | 예 | 3,997 |
| 스택 | [5, 2, 3, 4, 1, 0] | 예 | 3,997 |
| 번호가 가장 작은 것 (후보를 다 읽어 고른다) | [4, 5, 0, 2, 3, 1] | 예 | 502,498 |

세 규칙 가운데 유효한 나열을 낸 것은 3 개이고, 정본의 답은 [4, 5, 2, 0, 3, 1] 입니다.

<!--/proof-->

**셋 다 유효한 나열을 냅니다.** 결과는 서로 다른데 전부 답이에요. 진입 차수가 0 인 정점끼리는 어느 쪽이 먼저
와도 간선을 어기지 않기 때문입니다. 갈리는 것은 비용이에요. 큐와 스택은 꺼내기가 한 번의 연산이라 계수가
같고, 번호가 가장 작은 것을 후보를 다 읽어 고르면 별 모양에서 약 4 천이 약 50 만이 됩니다. 정점 0 을 꺼내는 순간
후보 999 개가 한꺼번에 담기고, 그 뒤로 꺼낼 때마다 남은 후보를 전부 읽기 때문이에요. 번호가 가장 작은 나열이
꼭 필요하면 힙으로 고르는 비용을 치러야 하고, 그렇지 않으면 큐로 충분합니다. 이 글은 큐를 씁니다.

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 셋째와 넷째가 반복 한 바퀴예요. 이렇게 하면 정점
10 만 개짜리 사슬에서 약 50 억 개이던 읽기가 약 40 만 개가 됩니다.

1. 간선 `[u, v]` 마다 `next[u]` 에 `v` 를 넣고 `indegree[v]` 를 하나 올린다
2. 진입 차수가 0 인 정점을 번호 순서로 큐에 담고 `head` 를 0 으로 둔다
3. 큐에 안 꺼낸 정점이 남아 있는 동안 앞에서 하나 꺼내 `order` 뒤에 붙인다
4. 꺼낸 정점의 `next` 마다 진입 차수를 하나 줄이고, 0 이 되면 큐 뒤에 담는다
5. `order` 의 길이가 `V` 이면 `order` 를, 아니면 `null` 을 돌려준다

### 수행으로 알아보는 알고리즘 — 정점 여섯의 순서를 여덟 걸음으로 만든다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 6;
const edges: [number, number][] = [[5, 2], [5, 0], [4, 0], [4, 1], [2, 3], [3, 1]];
// 이 절이 끝나면 [4, 5, 2, 0, 3, 1] 이 나와야 한다
```

정점을 왜 이 여섯으로 뒀을까요? 갈래를 **모두 실행하게** 하려는 것입니다. 진입 차수가 0 인 정점이 둘(4 · 5)이라
큐가 여럿을 담고 시작하고, 정점 0 과 1 은 진입 차수가 2 라 「줄였는데 아직 0 이 아니다」 갈래가 반드시 나오며,
정점 0 과 1 은 나가는 간선이 없어 목록이 빈 경우까지 함께 확인돼요. 사이클이 있을 때의 갈래는 이 입력에서
나오지 않아서, 뒤의 짚고 가기에서 따로 실행합니다.

```text
topologicalSort(n, edges):
    간선 [u, v] 마다 next[u] 에 v 를 넣고 indegree[v] 를 하나 올린다
    indegree 가 0 인 정점을 번호가 작은 것부터 queue 에 담는다
    order 를 빈 배열로, head 를 0 으로 둔다
    head 가 queue 의 길이보다 작은 동안:
        u ← queue[head] 를 꺼내고 head 를 하나 올린다
        order 뒤에 u 를 넣는다
        next[u] 의 정점 v 마다:
            indegree[v] 를 하나 내린다
            0 이 됐으면 queue 에 담는다                        ① 0 이 된 그 순간
            아니면 담지 않는다                                 ② 아직 남았다
    order 의 길이가 n 이면 order 를, 아니면 null 을 반환한다   ③ 전부 들어갔다 / ④ 남았다
```

#### 1. 간선 목록을 next 와 indegree 로 옮긴다

「아이디어 상세」의 1단계입니다. 간선을 한 번 읽으면서 나가는 쪽은 목록에, 들어오는 쪽은 진입 차수에 각각
담아 둡니다.

```ts
const next: number[][] = Array.from({ length: n }, () => []);
const indegree: number[] = Array.from({ length: n }, () => 0);
for (const [u, v] of edges) {
  (next[u] as number[]).push(v);
  indegree[v] = (indegree[v] as number) + 1;
}
```

전개 입력에 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walk-build-->

```text
next[0] = []       indegree[0] = 2
next[1] = []       indegree[1] = 2
next[2] = [3]      indegree[2] = 1
next[3] = [1]      indegree[3] = 1
next[4] = [0, 1]   indegree[4] = 0
next[5] = [2, 0]   indegree[5] = 0
목록 길이의 합 6 · indegree 의 합 6 · 간선 6 개
```

#### 짚고 가기 — 세는 방향을 뒤집기 쉽다

간선 `[u, v]` 는 「`u` 가 먼저」라는 뜻이라 `u` 가 주인공처럼 읽힙니다. 그래서 `indegree[u]` 를 올리는 코드를
쓰기 쉬워요. 그 오해대로 적으면 이렇게 됩니다.

```ts
for (const [u, v] of edges) {
  (next[u] as number[]).push(v);
  indegree[u] = (indegree[u] as number) + 1; // ← 머리가 아니라 꼬리를 센다
}
```

이 코드는 예외를 내지 않습니다. 그리고 **어떤 입력에서는 결과까지 같아요.** 두 판을 네 입력에 나란히 실행했습니다.

<!--proof:pause-out-->

| 입력 | 들어오는 간선 세기 (정본) | 나가는 간선 세기 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 | [4, 5, 2, 0, 3, 1] | null | 다르다 |
| 마름모 네 정점 | [0, 1, 2, 3] | null | 다르다 |
| 한 줄로 이은 네 정점 | [0, 1, 2, 3] | null | 다르다 |
| 간선이 없는 네 정점 | [0, 1, 2, 3] | [0, 1, 2, 3] | 같다 |

마지막 줄이 그 자리입니다. 간선이 하나도 없으면 두 방향 다 셀 것이 없어 결과가 같아요. **시험이 이 입력만 담고
있으면 방향을 뒤집어 놓고도 통과합니다.** 위 세 줄에서는 사이클이 하나도 없는 그래프에 `null` 이 나오는데, 한 줄로
이은 네 정점에서 무슨 일이 일어나는지 보면 까닭을 확인할 수 있어요.

<!--proof:pause-out-trace-->

```text
사슬 0→1→2→3
나가는 간선을 센 값   [1, 1, 1, 0]
그 값이 0 인 정점     3
반환값                null
```

나가는 간선을 세면 값이 0 인 정점은 **나가는 간선이 없는** 정점, 곧 맨 뒤에 와야 할 정점입니다. 그 정점을
꺼내도 `next` 가 비어 있어 줄일 것이 없고, 정작 맨 앞에 와야 할 0 은 후보가 된 적이 없어요. 앞 단계에서 본 대로
진입 차수의 합은 어느 쪽으로 세어도 `E` 라서 합으로는 확인되지 않고, **칸 하나하나의 값**을 들어오는 간선과
맞대야 합니다.

#### 2. 진입 차수가 0 인 정점을 큐에 담는다

「아이디어 상세」의 2단계입니다. 진입 차수가 0 인 정점을 번호가 작은 것부터 담고, 꺼낸 자리를 지우는 대신 `head`
첨자를 하나씩 올려서 큐를 만듭니다.

```ts
const queue: number[] = [];
for (let v = 0; v < n; v++) if (indegree[v] === 0) queue.push(v);

const order: number[] = [];
let head = 0;
```

실행하면 이렇게 나옵니다. 결과 배열은 아직 비어 있어요.

<!--proof:walk-seed-->

```text
indegree   [2, 2, 1, 1, 0, 0]
queue      [4, 5]
head       0
order      []
```

#### 3. 큐에서 꺼내며 진입 차수를 줄인다

「아이디어 상세」의 3단계, 순서를 만드는 자리입니다. 큐에서 하나 꺼내 결과에 넣고, 그 정점이 가리키는 칸들의
진입 차수를 하나씩 줄이되 **0 이 된 것만** 큐에 담아요.

```ts
while (head < queue.length) {
  const u = queue[head] as number;
  head++;
  order.push(u);

  for (const v of next[u] as number[]) {
    indegree[v] = (indegree[v] as number) - 1;

    // ① 진입 차수가 0 이 된 그 순간에 큐에 담는다.
    // ② 아직 0 이 아니면 담지 않는다. 남은 간선이 이 정점의 진입 차수를 다시 줄여 줄 것이다.
    if (indegree[v] === 0) queue.push(v);
  }
}
```

여기서 가장 중요한 줄은 `if (indegree[v] === 0) queue.push(v);` 입니다. 이 줄이 **찾는 일을 없애는** 자리예요. 진입
차수가 0 이 되는 순간이 여기뿐이므로, 여기서 담아 두면 나중에 0 인 칸을 다시 찾을 이유가 없습니다. 처음 두 번
꺼낸 결과입니다.

<!--proof:walk-take-->

```text
T2 — 정점 4 를 꺼내고 next[4] = [0, 1] 의 진입 차수를 줄인다
  indegree[0]  2 → 1   ② 아직 0 이 아니다 — 담지 않는다
  indegree[1]  2 → 1   ② 아직 0 이 아니다 — 담지 않는다
  queue [4, 5] · head 1 · order [4]
T3 — 정점 5 를 꺼내고 next[5] = [2, 0] 의 진입 차수를 줄인다
  indegree[2]  1 → 0   ① 0 이 됐다 — 담는다
  indegree[0]  1 → 0   ① 0 이 됐다 — 담는다
  queue [4, 5, 2, 0] · head 2 · order [4, 5]
```

#### 4. 여섯 정점을 처음부터 끝까지 따라간다

앞의 세 조각을 이어 실제로 실행하면 여덟 걸음이 나옵니다. T1 이 준비, 큐에서 꺼내기 한 번이 걸음 하나, 마지막
걸음이 큐가 비어 끝나는 자리예요. 걸음 재생 패널에서 정점 안의 수가 진입 차수이고, 결과에 넣은 정점과 그
정점에서 나가는 간선은 지운 셈 쳐서 대시로 흐리게 그렸습니다. 무대 아래 두 띠가 큐 배열 전체와 `order` 이고,
큐에서 이미 꺼낸 칸도 흐리게 그렸어요.

| --- | --- | --- | --- | --- | --- |
| T1 | - | 진입 차수가 0 인 정점 4 · 5 | 2 2 1 1 0 0 | [] | [4, 5] |
| T2 | 4 | indegree[0] === 0 이 거짓 → ② · indegree[1] === 0 이 거짓 → ② | 1 1 1 1 - 0 | [4] | [5] |

헷갈리기 쉬운 자리는 T4 입니다. T3 에서 정점 2 와 0 이 같은 걸음에 담겼는데, 꺼낼 때는 2 가 먼저 나와요. 큐가
**먼저 담은 것을 먼저 꺼내기** 때문이고, `next[5]` 가 `[2, 0]` 순서라 2 가 먼저 담겼기 때문입니다. 네 갈래가
두 입력에서 몇 번씩 실행됐는지 세면 이렇습니다.

| --- | --- | ---: | ---: |
| ① | 0 이 된 그 순간에 담는다 | 4 | 0 |
| ② | 줄였지만 아직 0 이 아니라 담지 않는다 | 2 | 1 |
| ③ | 전부 들어가 order 를 돌려준다 | 1 | 0 |

두 입력을 합치면 갈래 4 개 가운데 4 개가 한 번 이상 실행됐습니다.

**네 갈래가 모두 나왔습니다.** 전개 입력에서 ① 이 네 번인 것은 처음 후보 둘을 뺀 나머지 정점이 하나씩 0 이 되어
담긴 것이고, ② 가 두 번인 것은 진입 차수가 2 인 정점 둘이 첫 번째로 줄 때예요. ④ 는 사이클 앞에 정점 하나를
붙인 입력에서 한 번 나옵니다.

#### 짚고 가기 — 사이클을 찾는 코드가 따로 있어야 할 것 같다

위 코드 어디에도 「사이클을 찾는다」는 부분이 없습니다. 그래서 사이클이 있는 입력에서는 무슨 일이 일어날지 알
수 없게 읽히고, 방문 표시를 두어 되돌아온 자리를 잡아내는 코드를 따로 붙이고 싶어져요. 그 오해대로 생각하면
「사이클이면 반복이 끝나지 않는다」까지 가게 됩니다. 사이클만 있는 입력을 실제로 넣어 봅시다.

<!--proof:pause-cycle-->

```text
사이클 0→1→2→0
indegree         [1, 1, 1]   세 정점 다 들어오는 간선이 하나씩 있다
queue            []          진입 차수가 0 인 정점이 없다
반복             0 번        head < queue.length 가 처음부터 거짓이다
order            []          길이 0 ≠ n = 3
반환값           null
```

**반복은 끝나지 않기는커녕 한 번도 실행되지 않습니다.** 세 정점 다 진입 차수가 1 이라 처음 후보가 없고, 큐가 빈
채로 시작해 `head < queue.length` 가 처음부터 거짓이에요. 반복은 언제나 끝납니다. 큐에 담기는 총수가 `V` 이하이고
한 바퀴마다 `head` 가 정확히 하나 올라가니까요. 사이클 위의 정점은 진입 차수가 0 이 되지 못해 큐에 담기지 못하고,
그래서 `order` 에도 못 들어갑니다. **사이클 검출은 마지막 한 줄이 전부예요** — `order.length === n` 이 거짓이면
④ 갈래로 `null` 을 돌려줍니다.

| 길이 비교 | 뜻 | 갈래 |
| --- | --- | --- |
| `order.length === n` | 모든 정점이 들어갔다 — 사이클이 없다 | ③ `order` 를 돌려준다 |
| `order.length < n` | 못 들어간 정점이 있다 — 사이클이 있다 | ④ `null` 을 돌려준다 |

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 **마지막 길이 비교 한 줄**뿐이에요 — 앞의 조각들은
결과를 만들기만 했고, 그것이 답인지 판정하는 자리가 여기입니다.

```ts
export function topologicalSort(
  n: number,
  edges: [number, number][],
): number[] | null {
  // 간선 목록을 둘로 옮긴다 — 정점마다 나가는 간선의 도착 정점 목록과, 진입 차수.
  const next: number[][] = Array.from({ length: n }, () => []);
  const indegree: number[] = Array.from({ length: n }, () => 0);
  for (const [u, v] of edges) {
    (next[u] as number[]).push(v);
    indegree[v] = (indegree[v] as number) + 1;
  }

  // 진입 차수가 0 인 정점이 맨 앞에 놓아도 되는 정점이다. 번호가 작은 것부터 담는다.
  const queue: number[] = [];
  for (let v = 0; v < n; v++) if (indegree[v] === 0) queue.push(v);

  const order: number[] = [];
  let head = 0;
  while (head < queue.length) {
    const u = queue[head] as number;
    head++;
    order.push(u);

    for (const v of next[u] as number[]) {
      indegree[v] = (indegree[v] as number) - 1;

      // ① 진입 차수가 0 이 된 그 순간에 큐에 담는다.
      // ② 아직 0 이 아니면 담지 않는다. 남은 간선이 이 정점의 진입 차수를 다시 줄여 줄 것이다.
      if (indegree[v] === 0) queue.push(v);
    }
  }

  // ③ 정점이 전부 결과에 들어갔으면 그것이 위상 순서다.
  // ④ 하나라도 남았으면 남은 정점들이 사이클을 이루고 있다.
  return order.length === n ? order : null;
}
```

실행하면 이렇게 나옵니다.

<!--proof:walk-result-->

```text
topologicalSort(6, [[5,2],[5,0],[4,0],[4,1],[2,3],[3,1]])   →   [4, 5, 2, 0, 3, 1]
topologicalSort(4, [[0,1],[0,2],[1,3],[2,3]])               →   [0, 1, 2, 3]
topologicalSort(4, [[0,1],[1,2],[2,3]])                     →   [0, 1, 2, 3]
topologicalSort(4, [])                                      →   [0, 1, 2, 3]
topologicalSort(3, [[0,1],[1,2],[2,0]])                     →   null
topologicalSort(1, [[0,0]])                                 →   null
topologicalSort(1, [])                                      →   [0]
```

### 알아 두면 좋은 개념 — 선형 확장

「전체 컨셉」에서 여섯 정점 그래프의 유효한 나열이 여럿이라는 것을 봤고, 「후보를 큐로 꺼내는 까닭」에서는
꺼내는 규칙을 바꿔도 전부 답이 되는 것을 봤습니다. 간선이 정하는 것은 **일부 쌍의 앞뒤**뿐이라 나머지 쌍은
자유롭기 때문이에요. 정점 쌍마다 간선을 이어 가는 길이 있는지 쟀습니다.

<!--proof:related-pairs-->

| 정점 쌍 | 간선을 이어 가는 길 | 앞뒤 |
| --- | --- | --- |
| 5 와 2 | 5 → 2 | 정해진다 |
| 2 와 3 | 2 → 3 | 정해진다 |
| 5 와 3 | 5 → 3 | 정해진다 |
| 4 와 5 | 없다 | 정해지지 않는다 |
| 0 과 2 | 없다 | 정해지지 않는다 |

정점 쌍 15 개 가운데 앞뒤가 정해진 쌍은 9 개이고, 정해지지 않은 쌍은 6 개입니다. 유효한 나열은 13 가지입니다.

<!--/proof-->

일부 쌍의 앞뒤만 정해 놓은 관계를 **부분 순서**라 하고, 그 관계를 어기지 않으면서 모든 쌍의 앞뒤를 정해 한 줄로
만든 것을 그 부분 순서의 **선형 확장**(linear extension)이라고 부릅니다. 이 글이 만드는 위상 순서가 바로 선형
확장 하나예요.

| 이 글에서 | 선형 확장 일반 |
| --- | --- |
| 간선 `[u, v]` 를 이어서 만든 「먼저」 관계 | 부분 순서 |
| 함수가 반환하는 나열 | 선형 확장 하나 |
| 이어지는 길이 없는 쌍(4 와 5, 0 과 2)이 있다 | 선형 확장이 여럿인 까닭 |
| 사이클이 있어 어떤 쌍이 서로를 앞서야 한다 | 선형 확장이 없는 경우 |

같은 이름이 이 글 밖에서도 그대로 쓰입니다. 작업 스케줄링에서 「의존 관계를 지키는 실행 순서」가 선형 확장이고,
부분 순서의 선형 확장이 **몇 개인가**를 세는 것은 조합론에서 따로 다루는 주제예요. 위 블록의 「유효한 나열」
수가 그 수입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 이것을 쓰는지, 식으로 무엇이 나오는지, 무엇이 매 걸음 참으로
남는지, 그리고 비용이 얼마인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **제약이 「먼저 · 나중」 쌍으로만 주어집니다.** 「A 를 B 보다 먼저」 같은 두 대상 사이의 앞뒤 제약이고, 「A 와
  B 사이에 세 칸을 둔다」 같은 간격 제약이 없어야 해요.
- **답이 여럿이어도 됩니다.** 하나만 내면 되는 과제라야 이 절차를 그대로 씁니다. 번호가 가장 작은 나열을 요구하면
  후보를 힙으로 꺼내야 하고 `log` 가 붙어요.
- **그래프를 미리 다 받아 둘 수 있습니다.** 간선을 한 번에 받아 진입 차수를 세고 시작하니까요.

| 조건 | 코드에 나타나는 모양 |
| --- | --- |
| 앞뒤 제약뿐이다 | 정점마다 진입 차수 하나면 된다. 간격을 담을 자리가 필요 없다 |
| 답이 여럿이어도 된다 | 진입 차수가 0 인 후보 중 아무거나 꺼내도 된다. 큐로 충분하다 |
| 미리 다 받는다 | 진입 차수를 먼저 세고 그 뒤로는 새 간선을 받지 않는다 |

간격을 묻는 과제에서 무엇이 어긋나는지는 「아이디어 상세」의 「이 방법이 기대는 전제」가 값으로 보였습니다.
결과에서의 자리와 가장 이른 차례는 대부분의 정점에서 다르고, 차례를 구하려면 위상 순서를 따라가며 값을 물려주는
계산을 한 번 더 해야 해요. 간선에 길이가 붙고 최단 거리를 물으면 그것은 또 다른 절차입니다 —
[`bfsShortestPath` 가이드](../bfsShortestPath/bfsShortestPath-guide.md)가 그중 하나예요.

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 뜻 | 이 절차 |
| --- | --- | --- | --- |
| 지문 | "선수 과목" "먼저 처리해야 한다" "의존 관계" "빌드 순서" | 간선이 앞뒤 제약이다 | 쓴다 |
| 지문 | "가능한 순서를 아무거나 출력" | 후보를 고를 자유가 있다 | 쓴다 |
| 지문 | "순환이면 불가능을 출력" | 길이 비교 한 줄로 끝난다 | 쓴다 |
| 제약 | 정점과 간선이 각각 10 만 규모 · 시간 1 ~ 2 초 | `V + E` 규모의 절차를 찾으라는 뜻이다 | 쓴다 |
| 지문 | "사전순으로 가장 빠른 순서" | 후보를 번호순으로 꺼내야 한다 | 큐 대신 힙 |
| 지문 | "최소 몇 단계" "가장 이른 학기" | 순서가 아니라 간격을 묻는다 | 위상 순서 위에 계산을 더한다 |
| 지문 | "사이클이 있는지만 판정하라" | 순서까지 만들 것은 없다 | 다른 절차도 된다 |

사이클이 있는지만 묻는다면 [`directedCycleDetection` 가이드](../directedCycleDetection/directedCycleDetection-guide.md)의
절차도 답이 됩니다. 이 절차는 순서를 만들다가 사이클을 부산물로 알아보는 쪽이에요.

#### 실제로 쓰이는 곳

- **CPython 표준 라이브러리 `graphlib.TopologicalSorter`** — 이 글이 만든 것과 같은 절차입니다. 클래스 독스트링이
  *"Provides functionality to topologically sort a graph of hashable nodes"* 이고, 정점마다
  `self.npredecessors = 0` 로 선행 정점 수를 두고 그래프를 받을 때 `nodeinfo.npredecessors += len(predecessors)` 로
  올립니다. 처음 후보는 `self._ready_nodes = [i.node for i in self._node2info.values() if i.npredecessors == 0]` 으로
  모으고, 정점 하나를 끝낼 때마다 `successor_info.npredecessors -= 1` 한 뒤 `if successor_info.npredecessors == 0:`
  일 때만 후보에 담아요 — 이 글의 ① 갈래 그대로입니다.
  ([python/cpython Lib/graphlib.py](https://raw.githubusercontent.com/python/cpython/main/Lib/graphlib.py), 조회 2026-08-30)
- **GNU coreutils `tsort`** — 텍스트로 적은 「먼저 · 나중」 쌍을 받아 한 줄로 나열해 주는 명령입니다. 소스 앞머리
  주석이 *"The topological sort is done according to Algorithm T (Topological sort) in Donald E. Knuth, The Art of
  Computer Programming, Volume 1/Fundamental Algorithms, page 262."* 라 적어 근거를 밝히고, 관계를 기록하는
  `record_relation` 이 `k->count++` 로 도착 쪽의 수를 올린 다음 나열하는 동안 `p->suc->count--` 로 하나씩 줄입니다.
  ([coreutils src/tsort.c](https://raw.githubusercontent.com/coreutils/coreutils/master/src/tsort.c), 조회 2026-08-30)

| 출처 | 진입 차수에 해당하는 것 | 0 이 된 정점을 모으는 곳 |
| --- | --- | --- |
| 이 글 | `indegree[v]` | `queue` |
| CPython `graphlib` | `npredecessors` | `_ready_nodes` |
| coreutils `tsort` | `count` | 나열하는 동안의 후보 목록 |

두 곳 다 **정점마다 진입 차수 하나를 세어 두고 그것을 줄이는** 방식입니다. 이름만 다를 뿐 이 글의 `indegree` 와 같은
것이고, 0 이 되는 순간에 후보로 올리는 자리도 같아요.

### 수식 정의와 유도

정점 $v$ 로 들어오는 간선의 수를 $\deg^-(v)$ 라 적습니다. $t$ 바퀴가 끝난 뒤 아직 결과에 안 들어간 정점들의 모임은
$R_t$ 예요. $V$ 와 $E$ 는 파트 1 에서 정한 그대로 정점 수와 간선 수이고, 모임의 크기는 $|R_t|$ 처럼 세로줄로 적습니다.

| 이름 | 정의 | 코드에서 |
| --- | --- | --- |
| $\deg^-(v)$ | $v$ 로 들어오는 간선의 수 | 간선을 다 읽은 직후의 `indegree[v]` |
| $R_t$ | $t$ 바퀴가 끝난 뒤 결과에 안 들어간 정점들 | `order` 에 없는 정점 |
| $r_t(v)$ | $R_t$ 안의 정점에서 $v$ 로 오는 간선의 수 | $t$ 바퀴 뒤의 `indegree[v]` |
| $A(V, E)$ | 절차가 읽고 쓴 배열 칸의 총수 | 아래에서 센다 |

먼저 $\deg^-$ 를 정의 그대로 세어 검산합시다. 간선 하나는 머리가 정확히 하나이므로, 모든 정점의 $\deg^-$ 를 더하면
간선 수가 나와야 해요.

$$\sum_{v} \deg^-(v) = E$$

<!--proof:math-deg-->

| 입력 | V | E | 모든 정점의 deg⁻ 의 합 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 6 | 6 | 6 |
| 마름모 | 4 | 4 | 4 |
| 사이클 앞에 정점 하나 | 4 | 4 | 4 |
| 별 모양 1,000 | 1,000 | 999 | 999 |

4 입력 가운데 합이 E 와 같은 것은 4 개입니다.

<!--/proof-->

이제 이 절차가 **사이클이 없으면 반드시 정점 전부를 결과에 넣는다**는 것을 유도합니다. 핵심은 하나예요. 정점이
남아 있는 한 $r_t$ 가 0 인 정점이 반드시 있다는 것입니다.

$$R_t \neq \varnothing \;\wedge\; \text{사이클이 없다} \;\Longrightarrow\; \exists v \in R_t : r_t(v) = 0$$

전개 입력에서 먼저 확인합니다.

<!--proof:math-rt-->

| t | R_t | r_t(v) = 0 인 정점 |
| ---: | --- | --- |
| 0 | {0, 1, 2, 3, 4, 5} | 4 · 5 |
| 1 | {0, 1, 2, 3, 5} | 5 |
| 2 | {0, 1, 2, 3} | 0 · 2 |
| 3 | {0, 1, 3} | 0 · 3 |
| 4 | {1, 3} | 3 |
| 5 | {1} | 1 |

남은 정점이 있는 6 시점 가운데 r_t 가 0 인 정점이 없었던 시점은 0 개입니다.

<!--/proof-->

반대로 가정해서 유도합시다. $R_t$ 의 모든 정점 $v$ 에 대해 $r_t(v) \ge 1$ 이라면, 아무 정점 $x_0 \in R_t$ 를 골랐을 때
$R_t$ 안에서 $x_1 \to x_0$ 인 $x_1$ 이 있습니다 — $r_t(x_0) \ge 1$ 이니까요. 같은 이유로 $x_2 \to x_1$ 인 $x_2$ 가 있고,
이렇게 $|R_t| + 1$ 개를 고를 수 있어요. 고른 것은 $|R_t| + 1$ 개인데 서로 다른 정점은 $|R_t|$ 개뿐이므로, 비둘기집
원리로 $x_i = x_j$ 인 $i < j$ 가 있습니다. 사이클 앞에 정점 하나를 붙인 입력에서 정점 3 이 결과에 들어간 뒤 실제로
따라가면 이렇습니다.

<!--proof:math-chase-->

| 고른 차례 | 정점 | 그 정점으로 들어오는 R_t 안의 간선 |
| --- | --- | --- |
| x_0 | 0 | 2→0 |
| x_1 | 2 | 1→2 |
| x_2 | 1 | 0→1 |
| x_3 | 0 | 2→0 |

order 에 [3] 이 들어간 뒤 R_t 는 {0, 1, 2} 이고, 크기 3 인 모임에서 4 개를 고르자 정점 0 이 두 번 나왔습니다.

<!--/proof-->

$x_i = x_j$ 이면 $x_j \to x_{j-1} \to \dots \to x_i$ 가 출발한 정점으로 되돌아오는 길이라 사이클입니다. 위 표에서는
$x_3 \to x_2 \to x_1 \to x_0$ 이 `0 → 1 → 2 → 0` 이에요. 사이클이 없다는 가정과 어긋나므로, 처음 가정인 「모든 정점의
$r_t$ 가 1 이상」이 거짓입니다. 그러니 $r_t$ 가 0 인 정점이 있고, 그 정점은 줄어드는 순간(또는 처음 후보를 담을 때)
큐에 담겨 다음 바퀴들 안에 결과로 들어가요. 이 한 줄과 4단계의 논증을 합치면 양쪽 방향이 다 섭니다.

$$|\,order\,| = V \iff \text{사이클이 없다}$$

| 방향 | 근거 |
| --- | --- |
| 사이클이 없다 ⇒ 길이가 $V$ | 남은 정점이 있는 한 $r_t$ 가 0 인 정점이 있고(위 유도) 그 정점이 큐에 담기므로, 남은 정점이 0 개가 될 때까지 반복이 이어진다 |
| 길이가 $V$ ⇒ 사이클이 없다 | 사이클 $C$ 가 있으면 $C$ 위의 정점은 $C$ 에서 자기 앞 정점이 결과에 들어가야 $r_t$ 가 주는데, 그 정점도 같은 이유로 못 들어간다. 그래서 $C$ 위의 정점은 하나도 결과에 못 들어가고 길이가 $V$ 보다 작다 |

이제 배열 칸 접근 수 $A(V, E)$ 를 코드에서 그대로 셉니다. 사이클이 없는 경우예요.

$$A(V, E) = \underbrace{2V}_{\text{배열 둘}} + \underbrace{4E}_{\text{간선 한 번씩}} + \underbrace{V}_{\text{후보 찾기}} + \underbrace{3V}_{\text{꺼내기}} + \underbrace{2E}_{\text{줄이기}} + \underbrace{V}_{\text{담기}} = 7V + 6E$$

```ts
// 각 항이 어느 줄에서 나오는지 — 왼쪽 수가 그 줄이 만드는 칸 접근 수다.
// 2V   Array.from 두 번
// 4E   next[u] 읽기 + push · indegree[v] 읽기 + 쓰기
//  V   for (let v = 0; v < n; v++) if (indegree[v] === 0)
// 3V   queue[head] 읽기 + order.push · next[u] 읽기
// 2E   indegree[v] 읽기 + 쓰기
//  V   queue.push — 처음 후보와 ① 갈래를 합쳐 정점당 한 번
const cellsPerVertex = 7;
const cellsPerEdge = 6;
const closedForm = (V: number, E: number): number =>
  cellsPerVertex * V + cellsPerEdge * E;
```

식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

| 입력 | V | E | 실제 배열 칸 접근 | 7V + 6E |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 6 | 78 | 78 |
| 마름모 네 정점 | 4 | 4 | 52 | 52 |
| 사슬 1,000 | 1,000 | 999 | 12,994 | 12,994 |
| 별 모양 1,000 | 1,000 | 999 | 12,994 | 12,994 |
| 사슬 100,000 | 100,000 | 99,999 | 1,299,994 | 1,299,994 |

5 입력 가운데 두 값이 같은 것은 5 개입니다.

<!--/proof-->

**다섯 줄이 전부 정확히 맞습니다.** 셋째 줄과 넷째 줄이 같은 값이라는 것도 봐 주세요. 사슬과 별 모양은 모양이 완전히
다른데 계수가 같아요. 이 식에 정점 수도 간선 수도 아닌 항이 없기 때문입니다. 이것이 본문의 값만으로는 안 나오는 것이에요
— 전개 입력 한 벌의 78 이 아니라, **어떤 사이클 없는 그래프에서도** 칸 접근이 정확히 $7V + 6E$ 라는 등식입니다. 규모의
상한을 넣으면 이렇습니다.

<!--proof:math-scale-->

| 항 | V = E = 100,000 에서 |
| --- | ---: |
| 7V | 700,000 |
| 6E | 600,000 |
| A(V, E) = 7V + 6E | 1,300,000 |
| 순열 전수 검사의 순열 수 V! | 456,574 자리 수 |

130 만과 수십만 자리 수를 나란히 놓으면 이 절차가 무엇을 바꿨는지가 수로 나옵니다. 나열을 고르는 과제를 **간선을 한 번씩
읽는 과제로** 바꾼 것이에요.

### 불변식 — 큐에 담긴 정점은 진입 차수가 0 이고 한 번씩만 담긴다

파트 1 에서 코드가 동작하는 것을 여덟 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. 무엇이 **매 걸음 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해 봅시다.

> `while` 의 조건을 검사하는 시점마다 둘이 참입니다. **앞 문장** — `order` 에 없는 정점 `v` 마다 `indegree[v]` 는
> **`order` 에 없는 정점에서 `v` 로 오는 간선의 수**와 같습니다. **뒤 문장** — 큐에서 안 꺼낸 부분에 든 정점은 모두
> 진입 차수가 0 이고, 같은 정점이 두 번 들어 있지 않습니다.

<!--fig:invariant-state-->
![T3 뒤 — order 밖 정점의 진입 차수는 order 밖에서 오는 간선의 수](./figs/invariant-state.svg)

T3 이 끝난 시점을 그리면 앞 문장이 이렇게 보입니다. 테 안이 `order` 밖 정점이고, 정점 안의 수가 테 안에서 오는 간선의
수와 같아요. 정점 1 의 진입 차수가 1 인 것은 1 을 가리키는 4 · 3 가운데 테 안에 있는 것이 3 뿐이기 때문입니다.

「검사하는 시점마다」가 중요합니다. 반복이 다 끝난 뒤 한 번만 참인 것이 아니라 **정점 하나를 처리한 직후마다** 참이라는
뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 이어받습니다. **첫 검사부터 봅시다.** 반복이 시작되기 전에는 `order`
가 비어 있어서 모든 정점이 `order` 밖이고, 그때 `v` 로 오는 간선의 수는 $\deg^-(v)$ 입니다. 코드가 세어 둔 값이 정확히
그것이라 앞 문장이 참이고, 처음 후보는 진입 차수가 0 인 정점을 번호 순서로 한 번씩 담았으니 뒤 문장도 참이에요. 그 뒤로
상태를 바꾸는 갈래는 셋입니다.

| 갈래 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 꺼낸다 | `u` 를 `order` 에 넣는다 | `u` 가 `order` 밖에서 빠지므로, 바로 뒤에 `next[u]` 의 머리마다 진입 차수를 하나씩 줄여 `u` 에서 오던 간선을 뺀다 | 큐에서 한 칸 빠질 뿐 새로 넣지 않는다 |
| 줄여 0 이 됐다 | 그 정점을 큐에 담는다 | 줄인 뒤의 값이 이미 `order` 밖 간선 수와 같다 | 담긴 정점은 진입 차수가 0 이고, 값이 내려가기만 해서 0 이 되는 순간은 한 번뿐이다 |
| 줄였는데 0 이 아니다 | 아무것도 담지 않는다 | 줄인 뒤의 값이 이미 `order` 밖 간선 수와 같다 | 큐를 건드리지 않는다 |

첫 갈래의 「빠지자마자 줄인다」가 앞 문장을 지키는 자리입니다. 전개 입력의 여덟 시점에서 두 문장을 모두 쟀습니다.

<!--proof:invariant-watch-->

| 걸음 | order | order 밖 정점의 진입 차수 | 큐에서 안 꺼낸 부분 | 앞 문장 | 뒤 문장 |
| --- | --- | --- | --- | --- | --- |
| T1 | [] | 0:2 1:2 2:1 3:1 4:0 5:0 | [4, 5] | 지킨다 | 지킨다 |
| T2 | [4] | 0:1 1:1 2:1 3:1 5:0 | [5] | 지킨다 | 지킨다 |
| T3 | [4, 5] | 0:0 1:1 2:0 3:1 | [2, 0] | 지킨다 | 지킨다 |
| T4 | [4, 5, 2] | 0:0 1:1 3:0 | [0, 3] | 지킨다 | 지킨다 |
| T5 | [4, 5, 2, 0] | 1:1 3:0 | [3] | 지킨다 | 지킨다 |
| T6 | [4, 5, 2, 0, 3] | 1:0 | [1] | 지킨다 | 지킨다 |
| T7 | [4, 5, 2, 0, 3, 1] | 없음 | [] | 지킨다 | 지킨다 |

7 시점 가운데 두 문장이 다 지켜진 시점은 7 개입니다. 앞 문장은 order 밖 정점마다 진입 차수와 order 밖 정점에서 오는 간선 수를 맞대어 쟀습니다.

<!--/proof-->

이 불변식이 답의 정확성을 그대로 줍니다. 큐에서 꺼낸 정점은 뒤 문장으로 진입 차수가 0 이고, 앞 문장으로 그 0 은
「`order` 밖에서 오는 간선이 하나도 없다」는 뜻이에요. 곧 자기보다 먼저 와야 하는 정점이 **이미 전부 `order` 에 들어가
있는** 정점이므로, 그 뒤에 붙이면 그 정점으로 오는 간선이 전부 지켜집니다. 모든 정점이 그렇게 들어가면 나열 전체가 모든
간선을 지켜요. 경계에 있는 입력도 확인하고 갑시다.

<!--proof:invariant-edges-->

| 입력 | 처음 진입 차수 | 처음 후보 | 결과 |
| --- | --- | --- | --- |
| `topologicalSort(1, [])` | [0] | [0] | [0] |
| `topologicalSort(4, [])` | [0, 0, 0, 0] | [0, 1, 2, 3] | [0, 1, 2, 3] |
| `topologicalSort(1, [[0,0]])` | [1] | [] | null |
| `topologicalSort(3, [[0,1],[1,2],[2,0]])` | [1, 1, 1] | [] | null |
| `topologicalSort(4, [[0,1],[2,3]])` | [0, 1, 0, 1] | [0, 2] | [0, 2, 1, 3] |
| `topologicalSort(2, [[0,1],[0,1]])` | [0, 2] | [0] | [0, 1] |

자기 자신을 가리키는 간선과 같은 간선이 두 번 적힌 입력이 이 절차의 경계입니다. 자기 자신을 가리키는 간선 `[v, v]` 는
`indegree[v]` 를 올리면서 `next[v]` 에도 `v` 를 넣는데, `v` 가 결과에 들어가야 `indegree[v]` 가 줄고 `indegree[v]` 가
0 이라야 결과에 들어가므로 어느 쪽도 먼저 일어날 수 없어요. 같은 간선이 두 번이면 진입 차수를 2 로 올리고 `next` 에도
두 번 들어가 두 번 줄여서, 결과를 바꾸지 않습니다.

**이제 깨뜨려 봅시다.** 뒤 문장의 「큐에 든 정점은 진입 차수가 0」을 지키는 줄은 큐에 담는 조건입니다. 그 **한 줄만**
0 이 아니라 1 이하일 때 담도록 바꿉니다.

```ts
if ((indegree[v] as number) <= 1) queue.push(v); // ← 조건만 바꿨다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-early-push-->

| 입력 | 0 일 때 담기 (정본) | 1 이하일 때 담기 | 판정 |
| --- | --- | --- | --- |
| 전개 입력 | [4, 5, 2, 0, 3, 1] | null | 다르다 |
| 마름모 네 정점 | [0, 1, 2, 3] | null | 다르다 |
| 한 줄로 이은 네 정점 | [0, 1, 2, 3] | [0, 1, 2, 3] | 같다 |
| 간선이 없는 네 정점 | [0, 1, 2, 3] | [0, 1, 2, 3] | 같다 |

진입 차수가 2 인 정점이 있는 두 입력에서 `null` 이 나옵니다. 마름모에서 한 걸음씩 따라가면 까닭이 보여요.

<!--proof:mutant-early-trace-->

| 걸음 | 줄인 진입 차수 | 큐에서 안 꺼낸 부분 | order |
| --- | --- | --- | --- |
| 0 을 꺼낸다 | 1 이 1→0 · 담는다 · 2 가 1→0 · 담는다 | [1, 2] | [0] |
| 1 을 꺼낸다 | 3 이 2→1 · 담는다 | [2, 3] | [0, 1] |
| 2 를 꺼낸다 | 3 이 1→0 · 담는다 | [3, 3] | [0, 1, 2] |
| 3 을 꺼낸다 | 없음 | [3] | [0, 1, 2, 3] |
| 3 을 꺼낸다 | 없음 | [] | [0, 1, 2, 3, 3] |

order 의 길이가 5 라 n = 4 와 달라 반환값은 null 입니다.

<!--/proof-->

정점 3 은 진입 차수가 2 라 1 을 꺼낼 때 2 → 1 이 되었는데, 1 이하라서 담겼습니다. 아직 2 가 결과에 없는데 3 을 담은
것이라 뒤 문장이 이 자리에서 깨져요. 2 를 꺼낼 때 1 → 0 이 되어 또 담기고, 3 이 두 번 꺼내져 `order` 의 길이가 `n` 을
넘으니 마지막 길이 비교가 거짓이 됩니다. **한 줄로 이은 네 정점에서는 두 값이 같다는 것**도 봐 주세요. 사슬은 어느
정점도 진입 차수가 2 이상이 아니라 1 에서 0 으로 한 번에 갑니다. 그때는 「0 일 때」와 「1 이하일 때」가 같은 조건이라,
이 입력만 시험하면 바꿔 놓고도 통과해요.

### 비용 계산

#### 비용을 세는 과정

한 번의 반복이 하는 일은 큐에서 하나를 꺼내 결과에 넣고, 그 정점의 나가는 목록을 한 번 읽어 칸마다 진입 차수를 하나씩
줄이는 것뿐입니다. 전개의 T2 부터 T7 까지 여섯 걸음에서 읽은 목록을 적으면 이렇습니다.

<!--proof:perf-derive-->

| 걸음 | 꺼낸 정점 | 나가는 목록 길이 | 새로 담은 정점 |
| --- | ---: | ---: | ---: |
| T2 | 4 | 2 | 0 |
| T3 | 5 | 2 | 2 |
| T4 | 2 | 1 | 1 |
| T5 | 0 | 0 | 0 |
| T6 | 3 | 1 | 1 |
| T7 | 1 | 0 | 0 |

목록 길이의 합은 6 이고 간선은 6 개입니다. 새로 담은 정점의 합은 4 이고, 처음 후보 2 개를 더하면 6 으로 정점 수 6 과 같습니다.

<!--/proof-->

그러니 진입 차수를 줄이는 횟수는 **꺼낸 정점들의 나가는 간선 수의 합**이고, 사이클이 없으면 그것이 **간선 수와 정확히
같습니다.** 꺼내기 횟수는 결과에 들어간 정점 수와 같아서, 사이클이 없으면 `V` 이고 사이클이 있으면 그만큼 작아져요. 그
앞에 두 자료를 만드는 비용이 붙습니다. 꺼낸 정점의 나가는 간선 수를 $E'$ 이라 쓰면 총식은 이렇습니다.

$$\underbrace{\Theta(V)}_{\text{배열 만들기}} + \underbrace{\Theta(E)}_{\text{진입 차수 세기}} + \underbrace{\Theta(V)}_{\text{후보 찾기}} + \underbrace{O(V)}_{\text{큐 연산}} + \underbrace{O(E')}_{\text{줄이기}} = \Theta(V + E), \qquad E' \le E$$

| 자료 | 크기 | 비용에서 |
| --- | --- | --- |
| `next` | 정점마다 목록 하나, 칸의 합 `E` | `Θ(V + E)` 칸 |
| `indegree` · `queue` · `order` | 정점마다 많아야 한 칸 | `Θ(V)` 칸 |
| 메모리 전체 | | `Θ(V + E)` |

여기서 센 것은 **배열 칸을 읽고 쓴 횟수**입니다. `Array.prototype.push` 가 안에서 칸을 다시 잡는 비용은 세지 않았어요
— 분할 상환하면 한 번의 넣기가 상수라, 위 식의 규모를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 서로 다른 축입니다. 「최악은 `O`, 평균은 `Θ`」처럼 한쪽을
다른 쪽에 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **가장 적게 하는 경우** (사이클이 처음 후보를 거의 다 막는다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않는다) | `O(V + E)` | `Θ(V + E)` |
| **최악의 경우** (사이클이 없다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값이라는 것이 이 절차의 성질입니다.** 어떤 입력이 와도 두 자료를 만드는 데 `Θ(V + E)` 가 들고, 그것이
그대로 하한이에요. 간선 하나를 읽지 않고 넘어가는 길이 없기 때문입니다. 케이스가 가르는 것은 규모가 아니라 상수배예요.
정점 수와 간선 수를 맞춘 두 입력을 몫별로 재 보았습니다.

<!--proof:perf-cases-->

| 입력 (V = 100,000 · E = 99,999) | 두 자료 만들기 | 처음 후보 찾기 | 주 반복 | 합 |
| --- | ---: | ---: | ---: | ---: |
| 사이클이 없다 (사슬) | 599,996 | 100,001 | 599,997 | 1,299,994 |
| 사이클 0→1→2→0 이 앞을 막는다 | 599,996 | 100,001 | 3 | 700,000 |

두 합의 비는 1.86 배입니다.

<!--/proof-->

두 자료 만들기와 후보 찾기는 두 입력에서 똑같고, 주 반복만 갈립니다. 사이클이 앞을 막으면 주 반복이 한 바퀴로 끝나요.
**평균을 따로 계산할 대상이 없습니다.** 가장 적게 하는 경우와 최악이 같은 규모라 입력 분포를 어떻게 잡아도 기댓값이
`Θ(V + E)` 예요. 「평균이 정의되지 않는다」가 아니라 **분포와 무관하게 같다**는 쪽이고, 둘은 다른 진술입니다.

| 보장 | 뜻 | 이 절차 |
| --- | --- | --- |
| 최악 보장 | 어떤 입력에도 `V + E` 규모를 넘지 않는다 | 해당한다 |
| 기댓값 보장 | 구현이 만드는 무작위성이나 입력 분포에 기댄다 | 해당하지 않는다 |

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요. 같은 입력을 두 번 넣으면
반환값도 칸 접근 수도 똑같이 나옵니다. 경계의 종류로 보면 `Θ(V + E)` 는 상한이자 하한이에요 — 간선을 한 번씩은 읽어야
하므로 그보다 적게 할 방법이 없고, 「수식 정의와 유도」에서 센 대로 그보다 많이 하지도 않습니다.

#### 최악을 만드는 입력

「깊은 그래프가 최악」이라는 통념부터 확인합시다. 사슬은 가장 깊은 그래프이고 별 모양은 가장 얕은 그래프예요. 정점
여섯으로 줄여 그리면 두 모양이 이렇습니다.

<!--fig:worst-shapes-->
![정점 여섯으로 줄여 그린 두 모양 — 정점 안의 수는 진입 차수](./figs/worst-shapes.svg)

정점 10 만 개로 두 극단을 만들어 깊이와 큐의 길이를 재면 서로 정반대입니다.

<!--proof:worst-props-->

| 모양 (V = 100,000) | 가장 긴 경로의 간선 수 | 큐에서 안 꺼낸 부분의 최대 길이 | 나가는 목록의 최대 길이 |
| --- | ---: | ---: | ---: |
| 사슬 | 99,999 | 1 | 1 |
| 별 모양 | 1 | 99,999 | 99,999 |

그런데 정점 수와 간선 수를 맞춰 두 극단을 실제로 실행하면 칸 접근 수가 같습니다.

<!--proof:shape-values-->

| 입력 모양 (V = 100,000) | E | 배열 칸 접근 | order 에 들어간 정점 | 반환값 |
| --- | ---: | ---: | ---: | --- |
| 사슬 0→1→…→99,999 | 99,999 | 1,299,994 | 100,000 | 길이 100,000 인 순서 |
| 별 모양 — 0 이 나머지 전부를 가리킨다 | 99,999 | 1,299,994 | 100,000 | 길이 100,000 인 순서 |
| 사이클 0→1→2→0 이 앞을 막는다 | 99,999 | 700,000 | 1 | null |

**앞의 두 줄이 정확히 같습니다.** 통념은 이 절차에서 거짓이에요 — 깊이는 비용에 들어가지 않습니다. 반복문으로 적었으므로
호출 깊이가 없고, 큐에 한꺼번에 담긴 개수도 비용이 아니라 배열 길이일 뿐이라 어느 쪽이든 `V` 를 넘지 않아요. 최악을 만드는
조건은 모양이 아니라 **크기와 사이클 유무**입니다.

| 조건 | 까닭 |
| --- | --- |
| `V` 와 `E` 를 규모의 상한까지 채운다 | 칸 접근이 정확히 $7V + 6E$ 라 두 수가 클수록 크다 |
| 사이클이 없어야 한다 | 있으면 결과에 못 들어간 정점만큼 주 반복이 줄어든다 |
| 모양은 아무래도 좋다 | 사슬이든 별이든 같은 값이다 |

가장 적은 일을 하는 입력은 반대쪽입니다. 셋째 줄처럼 사이클이 처음 후보를 거의 다 막으면 주 반복이 거의 실행되지 않아요.
그래도 규모는 그대로 `Θ(V + E)` 입니다 — 두 자료를 만드는 비용은 어떤 입력에서도 치러야 하니까요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하겠습니다. 나열을 통째로 만들어 검사하던 것을 **한 자리씩 정하는 것**으로 바꿨고, 「지금
놓아도 되는 정점」을 정점마다 진입 차수 하나로 판정하며, 그 값이 0 이 되는 순간이 값을 줄이는 자리뿐이라 후보를 다시 찾지
않고 그 자리에서 큐에 담습니다. 답이 맞는 근거는 「큐에 담긴 정점은 진입 차수가 0 이고 한 번씩만 담긴다」이고, 칸 접근은
사이클이 없을 때 정확히 $7V + 6E$ 예요.

| 순서 | 하는 일 | 규모 |
| ---: | --- | --- |
| 1 | 간선마다 `next` 에 넣고 진입 차수를 올린다 | 간선 `E` 번 |
| 2 | 진입 차수가 0 인 정점을 번호 순서로 큐에 담는다 | 정점 `V` 칸 읽기 |
| 3 | 큐에서 꺼내 `order` 에 붙인다 | 꺼내기 `V` 번 이하 |
| 4 | 꺼낸 정점의 나가는 간선마다 진입 차수를 줄이고, 0 이면 담는다 | 줄이기 `E` 번 이하 |
| 5 | `order` 의 길이를 `n` 과 비교해 돌려준다 | 한 번 |

먼저 답이 붙는 문제 하나입니다. 전개의 T3 에서 정점 5 를 꺼내 `next[5] = [2, 0]` 을 줄였고, 정점 2 와 0 이 같은 걸음에
큐에 담겼어요. 간선 목록에 `[5, 0]` 이 `[5, 2]` 보다 먼저 적혀 있어서 **`next[5]` 가 `[0, 2]` 순서였다면** 최종 결과는 무엇이
되었을까요?

<!--check:pushOrder-->
답은 이렇습니다. 큐가 먼저 담은 것을 먼저 꺼내므로 0 이 2 보다 먼저 나오고, 그 뒤가 한 칸씩 옮겨집니다.

<!--proof:selfcheck-push-order-->

```text
next[5] = [0, 2] 이면 T3 뒤 큐에서 안 꺼낸 부분이 [0, 2] 이다

2 를 꺼낸다   3 이 1→0               order [4, 5, 0, 2]         queue [3]
3 을 꺼낸다   1 이 1→0               order [4, 5, 0, 2, 3]      queue [1]
1 을 꺼낸다   next[1] 이 비어 있다   order [4, 5, 0, 2, 3, 1]   queue []
결과 [4, 5, 0, 2, 3, 1] — 간선 6 개를 모두 지킨다
```

마지막 줄이 답입니다. **두 결과가 다 유효한 나열이에요.** 간선 목록의 적힌 순서가 바뀌면 `next` 의 순서가 바뀌고 반환값도 바뀌어요. 과제의 계약이
「유효하면 어느 것이든」이라 그것이 허용됩니다. 「아이디어를 떠올리는 과정」에서 순열 전수 검사가 처음 찾은 나열이 바로
이 나열이에요.

### Topological Sort (위상 정렬)

풀 파일: [`topologicalSort.ts`](./topologicalSort.ts) · 테스트: [`topologicalSort.test.ts`](./topologicalSort.test.ts) · 실행: `bun test src/algorithms/graph/topologicalSort/topologicalSort.test.ts`

#### 한 줄 요약

> 함수는 정점 수 `n`과 유향 간선 목록을 받아, 모든 간선의 방향을 존중하는 정점 순열을 반환하거나, 사이클이 있어 불가능하면 `null`을 반환한다.

#### 스토리

교육 플랫폼을 운영하는 팀이 강의 커리큘럼을 설계하고 있다. 어떤 강의는 선수 과목이 있어서, 수강 전에 반드시 먼저 들어야 하는 강의가 정해져 있다. 예를 들어 "알고리즘 심화"를 듣기 전에 "자료구조 기초"를 먼저 수강해야 한다.

팀은 학생들이 규칙을 어기지 않고 모든 강의를 들을 수 있는 수강 순서를 자동으로 생성하고 싶다. 단, 설계 실수로 "강의 A → 강의 B → 강의 A"처럼 서로가 서로의 선수 과목이 되는 순환 관계가 만들어지면 어떤 순서로도 수강이 불가능하다.

이 경우 플랫폼은 "수강 순서를 만들 수 없다"는 신호를 내보내야 한다.

#### 함수 인터페이스

```ts
export function topologicalSort(
  n: number,
  edges: [number, number][],
): number[] | null;
```

- `n` — 정점 수. 정점 번호는 $0 \ldots n-1$
- `edges` — 유향 간선 목록. 각 원소 `[u, v]`는 "$u$가 $v$보다 먼저여야 한다"는 $u \to v$ 방향의 제약
- 반환 — 유효한 위상 순서인 길이 `n`의 정점 순열. 사이클이 있으면 `null`. 유효한 순서가 여러 개이면 그중 어느 것을 반환해도 된다

#### 제약 조건

- $1 \leq V \leq 10^{5}$ (여기서 $V = n$)
- $0 \leq E \leq 10^{5}$ (여기서 $E$는 `edges`의 길이)
- 방향 그래프
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

유향 그래프의 정점들을 모든 간선 $(u, v)$에 대해 $u$가 $v$보다 앞에 오도록 일렬로 나열한다.

반환하는 순열 $[v_0, v_1, \ldots, v_{n-1}]$은 다음 조건을 만족해야 한다: 모든 간선 $(u, v)$에 대해 $u$의 위치가 $v$의 위치보다 앞이어야 한다.

경계 동작:
- 사이클이 하나라도 있으면 `null`을 반환한다.
- 자기 루프 `[v, v]`도 사이클로 간주해 `null`을 반환한다.
- 간선이 없으면 임의의 순열이 유효하다.
- 유효한 순열이 여러 개 존재할 수 있으므로 테스트는 순열의 유효성만 검사한다.

#### 예시

```ts
// 선형 체인: 0→1→2→3 — 유일한 유효 순서
topologicalSort(4, [[0,1],[1,2],[2,3]]); // [0,1,2,3]

// 다이아몬드 DAG: 0→1, 0→2, 1→3, 2→3
// [0,1,2,3]과 [0,2,1,3] 모두 유효
topologicalSort(4, [[0,1],[0,2],[1,3],[2,3]]); // 유효한 순열 중 하나

// 사이클 포함: 0→1→2→0
topologicalSort(3, [[0,1],[1,2],[2,0]]); // null

// 자기 루프: 0→0
topologicalSort(1, [[0,0]]); // null

// 간선 없음 — 모든 순열 유효
topologicalSort(4, []); // 유효한 순열 중 하나

// V=1, 간선 없음
topologicalSort(1, []); // [0]
```
