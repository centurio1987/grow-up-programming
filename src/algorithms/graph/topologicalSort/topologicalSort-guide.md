# 위상 정렬 — 남은 선행 정점 수를 세어 두면 후보를 다시 찾지 않아도 된다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 순열을 전부 만들어 검사하던
방법에서 정점마다 수 하나를 세어 두는 방법까지 가는 경로를 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**유향 그래프**는 정점들과 **방향이 있는 간선**으로 이루어집니다. 간선 `[u, v]` 는 `u → v` 를
뜻하고, 이 문제에서는 「`u` 가 `v` 보다 먼저 와야 한다」는 제약으로 읽어요. 강의 커리큘럼이라면
`u` 가 선수 과목이고 `v` 는 그것을 들은 뒤에야 수강할 수 있는 강의입니다.

```text
  5 ──> 2 ──> 3 ──> 1        간선 여섯 — 5→2 · 5→0 · 4→0 · 4→1 · 2→3 · 3→1
  │                 ^
  └──> 0            │        들어오는 간선이 없는 정점   4 · 5
       ^            │        들어오는 간선이 하나인 정점 2 · 3
       │            │        들어오는 간선이 둘인 정점   0 · 1
  4 ───┴────────────┘
```

이 글이 만드는 것은 **모든 간선의 방향을 지키는 정점 나열**입니다. 정점을 한 줄로 놓았을 때
간선 `[u, v]` 마다 `u` 가 `v` 보다 왼쪽에 있으면 그 나열이 답이고, 이것을 **위상 순서**라고
불러요. 위 그래프의 답 하나를 놓고 간선 여섯 개를 하나씩 확인해 봅시다.

```text
답 하나          4  5  2  0  3  1
자리 번호        0  1  2  3  4  5

  5→2   5 는 1 번, 2 는 2 번   1 < 2   지킨다
  5→0   5 는 1 번, 0 은 3 번   1 < 3   지킨다
  4→0   4 는 0 번, 0 은 3 번   0 < 3   지킨다
  4→1   4 는 0 번, 1 은 5 번   0 < 5   지킨다
  2→3   2 는 2 번, 3 은 4 번   2 < 4   지킨다
  3→1   3 은 4 번, 1 은 5 번   4 < 5   지킨다
```

**답이 하나로 정해지지 않습니다.** 여기가 이 문제의 첫 번째 특징이에요. 위 그래프에서
정점 4 와 5 는 서로 간선으로 이어져 있지 않아서 둘 중 어느 쪽을 먼저 놓아도 제약을 하나도
어기지 않아요. 문제 지문도 「유효한 순서가 여러 개이면 그 중 어느 것을 반환해도 된다」로
그것을 인정합니다.

```text
같은 그래프의 유효한 나열 몇 개

  4 5 2 0 3 1        5 4 2 0 3 1        4 5 0 2 3 1
  └ 4 와 5 의 앞뒤가 바뀌어도 되고, 0 과 2 의 앞뒤가 바뀌어도 된다
```

정점 여섯 개의 나열은 모두 720 가지인데 그중 유효한 것이 13 가지입니다. 하나만 내면 되므로
전부 만들 이유는 없어요. 그리고 유효한 것이 **하나도 없는** 경우도 있습니다.

```text
0 → 1 → 2 → 0 세 정점이 고리를 이루면

  0 이 1 보다 먼저   1 이 2 보다 먼저   2 가 0 보다 먼저
  └ 세 조건을 함께 지키려면 0 이 0 보다 먼저여야 한다. 그런 나열은 없다
```

간선을 따라가다가 출발한 정점으로 되돌아오는 길을 **사이클**이라고 부릅니다. 사이클이 하나라도
있으면 답이 없고, 그때 함수는 `null` 을 돌려줘요. 자기 자신을 가리키는 간선 `[v, v]` 도 길이 1
짜리 사이클입니다.

**이 글의 결정적인 관찰은 하나입니다.** 맨 앞에 놓아도 되는 정점은 「들어오는 간선이 없는
정점」이고, 어떤 정점을 결과에 넣고 나면 그 정점에서 나가는 간선들이 없어진 셈이 됩니다.
그러니 정점마다 「아직 결과에 안 들어간 선행 정점이 몇 개인가」를 **수 하나로 세어 두고**,
정점을 결과에 넣을 때마다 그 수를 하나씩 줄이면 됩니다.

```text
정점마다 수 하나 — 아직 결과에 안 들어간 선행 정점의 수

  처음      0:2  1:2  2:1  3:1  4:0  5:0     0 인 4 와 5 가 출발 후보다
  4 를 넣고 0:1  1:1  2:1  3:1  4:-  5:0     4 가 가리키던 0 과 1 이 하나씩 준다
  5 를 넣고 0:0  1:1  2:0  3:1  4:-  5:-     0 과 2 가 0 이 됐다. 새 후보 둘이다
```

수가 0 이 되는 순간은 **그 수를 줄이는 바로 그 자리**뿐입니다. 그래서 0 인 정점을 매번 다시
찾을 필요 없이, 줄이다가 0 이 되면 그 자리에서 **후보를 담는 통**에 넣어 두면 돼요. 아래에서는
이것을 그냥 「통」이라고 부릅니다. 통에서 하나씩 꺼내 결과에 넣기를 되풀이하고, 통이 비었을 때
결과 길이가 정점 수와 같으면 그것이 답입니다.

```text
정점 수 V, 간선 수 E 일 때

  두 배열 만들기       나가는 목록 하나와 남은 수 하나           V 에 비례
  간선 한 번씩 읽기    목록에 넣고 남은 수를 하나 올린다         E 에 비례
  통에 넣고 꺼내기     정점마다 많아야 한 번씩                   V 에 비례
  남은 수 줄이기       간선마다 정확히 한 번씩                   E 에 비례
                       └ 전체가 V + E 에 비례한다
```

간선 하나를 정확히 두 번 읽는 것으로 끝나는 것이 이 절차의 성질입니다. 전체 비용은
`Θ(V + E)` 이고, 정점 100,000 개와 간선 100,000 개라는 제약에서 여유 있게 1 초 안에 끝나요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 정점과 간선으로 적는 방식.** 특히 **인접 리스트** — 정점마다 이웃 목록 하나를 두는
  표현입니다. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **유향 그래프에서 들어오는 간선과 나가는 간선이 다르다는 것.** 간선 `[u, v]` 는 `u` 의
  나가는 간선이면서 동시에 `v` 의 들어오는 간선입니다. 이 글은 두 방향을 서로 다른 자료에
  담으므로 둘을 섞으면 뒤가 어긋나요.
- **큐가 먼저 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기·꺼내기가 각각 `O(1)` 입니다.
  모르면 [`queue` 가이드](../../../data-structures/linear/queue/queue-guide.mdx)를 보세요.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점의 선행 정점이 몇 개 남았는가」를 배열 한
  칸을 읽어 판정합니다.

두 번째와 세 번째가 흐릿하면 뒤가 어긋납니다. 이 글은 간선 하나를 「나가는 쪽 목록」과
「들어오는 쪽 개수」 둘에 나누어 담는데, 그 둘이 무엇인지 알고 있어야 왜 한 번 읽는 것으로
충분한지 읽혀요.

### 아이디어 상세 — 남은 선행 정점 수와 큐를 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function topologicalSort(
  n: number,
  edges: [number, number][],
): number[] | null;
```

- 입력: 정점 수 `n`, 유향 간선 목록 `edges`. 정점 번호는 0 부터 `n - 1` 까지예요.
- 출력: 모든 간선 `[u, v]` 에 대해 `u` 가 `v` 보다 앞에 오는 길이 `n` 의 정점 나열.
  그런 나열이 없으면 `null` 입니다. 유효한 나열이 여럿이면 그중 어느 것을 내도 됩니다.
- 제약: 정점 100,000 개 이하, 간선 100,000 개 이하, 시간 1 초, 메모리 256 MB.
  자기 자신을 가리키는 간선 `[v, v]` 가 들어올 수 있어요.

앞 절과 다른 것이 하나 있습니다. 여기서는 **답이 여럿이라도 된다**는 것을 계약으로 못 박고
갑니다. 그래서 이 글이 만들 절차는 「어느 것을 내는가」를 정하는 일에 비용을 쓰지 않아요.

```text
쓸 수 있는 정보가 둘뿐이다
  ┗ 어떤 정점에서 어떤 정점으로 나가는가       간선 목록에서 만들어 둔다
  ┗ 어떤 정점의 선행 정점이 몇 개 남았는가     수 하나를 정점마다 둔다
```

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `V` | 정점 수 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수 | `0 ≤ E ≤ 100,000` |
| `deg⁻(v)` | 정점 `v` 로 들어오는 간선 수 | 모든 정점을 더하면 `E` |
| `next[u]` | `u` 에서 나가는 간선의 도착 정점 목록 | 길이를 다 더하면 `E` |
| `remaining[v]` | 아직 결과에 안 들어간 `v` 의 선행 정점 수 | 처음 값이 `deg⁻(v)` |
| `queue` | 남은 선행 정점 수가 0 인 정점을 담는 통 | 담기는 총수는 `V` 이하 |
| `order` | 결과 나열을 담는 배열 | 길이가 `V` 이거나 `null` |

정점 수 `V` 는 코드에서 `n` 입니다. `deg⁻(v)` 는 `remaining[v]` 의 처음 값이라 따로 배열을
두지 않아요.

```text
기호가 어디에 사는가

  V            함수 인자 n                   값이 바뀌지 않는다
  E            edges 의 길이                 값이 바뀌지 않는다
  deg⁻(v)      remaining[v] 의 처음 값       따로 담아 두지 않는다
  remaining[v] 배열 한 칸                    간선을 지울 때마다 준다
  queue·order  배열 하나씩                   뒤에 붙기만 하고 줄지 않는다
```

가장 먼저 떠오르는 방법으로 시작합시다. **정점의 모든 나열을 만들어 하나씩 검사하는 것**이에요.
나열 하나를 만들고 간선 여섯 개를 다 지키는지 보고, 하나라도 어기면 다음 나열로 갑니다.
기법이 하나도 안 들어간 풀이입니다.

<!--proof:brute-walk-->

```text
                                        값
검사한 순열 수                         580
읽은 간선 끝점 수                    2,024
처음 찾은 유효한 순열   [4, 5, 0, 2, 3, 1]
유효한 순열의 총 개수             13 / 720
```

여섯 정점에서는 580 번 만에 답이 나옵니다. 이 방법은 답이 맞아요. 그런데 나열의 개수가
정점 수의 계승 `V!` 이라, 정점이 조금만 늘어도 그 수가 감당할 수 없게 커집니다. 사슬 그래프에
제약 규모를 넣어 봅시다.

<!--proof:naive-scale-->

```text
정점 V          순열 수 V!   순열마다 간선 검사           총 검사 수   초당 1억 번 기준
     5                 120                    4                  480            0.000초
    10           3,628,800                    9           32,659,200            0.327초
    15   1,307,674,368,000                   14   18,307,441,152,000              2.1일
    20           2.433e+18                   19            4.623e+19           14,658년
        └ 정점이 100,000 개면 순열 수 V! 만 456,574 자리다
```

정점 20 개에서 이미 14,658 년입니다. 제약은 100,000 개인데 그때는 나열의 개수를 적는 것조차
456,574 자리가 돼요. 나열을 통째로 고르는 방식으로는 시작할 수 없습니다.

```text
방향을 바꾼다 — 나열 전체를 고르지 말고 한 자리씩 정한다

  맨 앞 자리에 놓아도 되는 정점은 무엇인가
    ┗ 자기보다 먼저 와야 하는 정점이 하나도 없는 정점
    ┗ 곧 들어오는 간선이 하나도 없는 정점이다
```

여섯 정점 그래프에서 그 정점은 4 와 5 입니다. 4 를 맨 앞에 놓아 봅시다. 그러면 4 에서 나가는
간선 `4→0` 과 `4→1` 은 이미 지켜진 것이므로 없는 셈 쳐도 됩니다. 남은 그래프에서 같은 질문을
다시 하면 두 번째 자리가 정해져요.

```text
한 자리씩 정하며 남는 그래프

  처음         간선 여섯   들어오는 간선이 없는 정점   4 · 5      4 를 고른다
  4 를 빼고    간선 넷     4→0 · 4→1 이 없어졌다       5          5 를 고른다
  5 를 빼고    간선 둘     5→2 · 5→0 이 없어졌다       0 · 2      2 를 고른다
  2 를 빼고    간선 하나   2→3 이 없어졌다             0 · 3      0 을 고른다
               └ 고를 때마다 후보가 하나 이상 있으면 끝까지 갈 수 있다
```

**여기가 준비의 끝입니다.** 절차의 모양이 정해졌어요 — 「들어오는 간선이 없는 정점을 하나
고르고, 그 정점과 거기서 나가는 간선을 지운다」를 정점 수만큼 되풀이합니다. 남은 것은 그
정점을 **어떻게 찾는가**이고, 비용은 전부 거기서 나옵니다.

```text
찾는 방법 둘을 같은 입력에 실행해 읽은 원소 수를 센다

  방식 A   간선 목록 전체를 매번 다시 읽는다
           아직 안 뺀 정점이 출발점인 간선의 도착점을 모으고, 거기 없는 정점을 고른다
  방식 B   정점마다 들어오는 간선 수를 배열에 한 번 세어 둔다
           정점을 뺄 때마다 그 정점이 가리키는 칸을 하나씩 줄인다
```

<!--proof:scan-vs-count-->

```text
                                여섯 정점에서 읽은 원소   결과                 사슬 1,000 에서 읽은 원소
간선 목록을 매번 다시 읽는다                         93   [4, 5, 0, 2, 3, 1]                   2,498,500
남은 선행 정점 수를 세어 둔다                        39   [4, 5, 0, 2, 3, 1]                     503,497
```

답은 같은데 93 이 39 가 됐고, 정점 1,000 개짜리 사슬에서는 249 만이 50 만이 됐습니다. 방식 A 는
자리를 하나 정할 때마다 간선 `E` 개를 전부 다시 읽어 `V · E` 가 되고, 방식 B 는 간선을 처음에
한 번만 읽습니다.

> 정점마다 **아직 결과에 안 들어간 선행 정점의 수**를 배열 한 칸에 세어 둔다.
> 정점을 결과에 넣을 때 그 정점이 가리키는 칸만 하나씩 줄인다.

```text
간선 목록을 한 번만 읽어 두 자료로 옮긴다

  [5,2] → next[5] 에 2,  remaining[2] 를 1 로
  [5,0] → next[5] 에 0,  remaining[0] 을 1 로
  [4,0] → next[4] 에 0,  remaining[0] 을 2 로
  [4,1] → next[4] 에 1,  remaining[1] 을 1 로
  [2,3] → next[2] 에 3,  remaining[3] 을 1 로
  [3,1] → next[3] 에 1,  remaining[1] 을 2 로
          └ 간선 여섯 개를 한 번 읽는 것으로 두 자료가 다 만들어진다
```

여기서 관찰한 것은 하나입니다. **한 자리를 정하는 비용이 `E` 에서 그 정점의 나가는 간선 수로
줄었다.** 그런데 찾는 일이 아직 남아 있어요 — 「남은 수가 0 인 정점」을 어떻게 찾을 것인가입니다.
가장 단순한 후보를 먼저 시험해 봅시다. **매 바퀴 `remaining` 배열 `V` 칸을 앞에서부터 차례로
읽어 0 인 칸을 찾는** 방식이에요. 사슬 그래프에서 갈립니다.

<!--proof:array-vs-queue-->

```text
                                  여섯 정점   사슬 1,000   사슬 10,000
매 바퀴 배열 전체를 다시 읽는다          39      503,497    50,034,997
0 이 되는 자리에서 큐에 담는다           24        3,997        39,997
```

정점 1,000 개 사슬에서 50 만 대 4 천이고, 10,000 개로 늘리면 5,000 만 대 4 만입니다. 앞의 방식은
`k` 번째 자리를 정할 때 배열 앞쪽 `k` 칸을 다시 읽으므로 합이 `V²/2` 규모가 되고, 정점 수를 열
배로 늘리면 값이 백 배가 돼요.

```text
사슬 0→1→…→999 에서 배열을 앞에서부터 읽으면

  첫 자리    0 번 칸이 0 이다                    1 칸 읽는다
  둘째 자리  0 번은 이미 뺐다, 1 번이 0 이다     2 칸 읽는다
  셋째 자리  0·1 번은 뺐다, 2 번이 0 이다        3 칸 읽는다
             └ 1 + 2 + … + 1,000 = 500,500 칸. 이미 뺀 칸을 매번 다시 읽는다
```

낭비가 어디에 있는지가 이 그림에 나옵니다. 이미 뺀 칸을 다시 읽고, 아직 0 이 아닌 칸도 다시
읽어요. **어떤 칸이 0 이 되는 순간은 그 칸을 줄이는 바로 그 자리 하나뿐**인데 말입니다.

> 값을 줄이는 그 자리에서 0 이 됐는지 보고, 0 이면 그 정점을 **후보 통에 담는다.**
> 그러면 「0 인 정점 찾기」가 「통에서 하나 꺼내기」가 된다.

```text
값이 0 이 되는 자리는 하나뿐이다

  remaining[v] 가 줄어드는 자리   v 로 들어오는 간선의 출발점을 결과에 넣을 때
  그 자리에서 0 이 되면           v 는 지금부터 후보다
  그 자리 밖에서 0 이 될 일       없다. 값을 바꾸는 코드가 거기뿐이다
```

각 자료가 얼마나 움직이는지 여기서 정합니다. 위에서 실제로 센 값이 그 근거예요.

```text
  remaining[v] 가 줄어드는 횟수   v 로 들어오는 간선 수만큼           합쳐서 E 번
  통에 들어가는 총 원소 수        정점당 많아야 한 번                 V 이하
  통에서 꺼내는 횟수              들어간 만큼만                       V 이하
  order 의 길이                   꺼낸 만큼                           V 이하
```

**같은 정점의 수가 여러 번 줄어드는 경우를 값으로 확인해 봅시다.** 쉬운 경우는 선행 정점이
하나뿐인 자리예요 — 정점 3 은 `remaining[3]` 이 1 이라 한 번 줄면 바로 0 이 됩니다. 불안한
경우는 선행 정점이 둘인 정점 1 입니다. 첫 번째 감소에서는 후보가 아니고, 두 번째 감소에서야
후보가 돼요.

```text
정점 1 의 수가 두 번 줄어드는 과정 — remaining 배열 전체를 단계마다 적는다

  처음         0:2  1:2  2:1  3:1  4:0  5:0    후보는 4 · 5
  4 를 넣는다  0:1  1:1  2:1  3:1  4:-  5:0    1 이 2→1. 아직 0 이 아니라 담지 않는다
  5 를 넣는다  0:0  1:1  2:0  3:1  4:-  5:-    0 과 2 가 0 이 됐다. 둘을 담는다
  2 를 넣는다  0:0  1:1  2:-  3:0  4:-  5:-    3 이 0 이 됐다. 담는다
  0 을 넣는다  0:-  1:1  2:-  3:0  4:-  5:-    0 은 나가는 간선이 없다. 줄일 것이 없다
  3 을 넣는다  0:-  1:0  2:-  3:-  4:-  5:-    1 이 1→0. 두 번째 감소에서 담긴다
```

왜 이것이 맞는지는 반복문의 종료 조건이 말해 줍니다. `remaining[v]` 를 줄이는 일은 `v` 로
들어오는 간선마다 정확히 한 번씩 일어나므로 전체 감소 횟수가 `E` 로 정해져 있고, 그래서 반복은
반드시 끝나요. 그리고 통에 담기는 것은 값이 0 이 **되는 그 순간**뿐이라 같은 정점이 두 번
담길 수 없습니다.

```text
남은 갈림 하나 — 후보 통을 무엇으로 두는가
  먼저 담은 것을 먼저 꺼낸다      큐
  나중에 담은 것을 먼저 꺼낸다    스택
  담긴 것 중 번호가 작은 것부터   최소 힙
                                  └ 셋 다 답이 되는지, 비용이 어떻게 갈리는지 값으로 본다
```

세 통을 같은 두 입력에 실제로 실행해 결과와 계수를 냅니다.

<!--proof:container-values-->

```text
후보 통   여섯 정점의 결과     유효한가   마름모의 결과   별 모양 1,000 에서 읽은 원소
큐        [4, 5, 2, 0, 3, 1]   예         [0, 1, 2, 3]                           3,997
스택      [5, 2, 3, 4, 1, 0]   예         [0, 2, 1, 3]                           3,997
최소 힙   [4, 5, 0, 2, 3, 1]   예         [0, 1, 2, 3]                         502,498
정본      [4, 5, 2, 0, 3, 1]   예         [0, 1, 2, 3]                               —
```

**셋 다 유효한 나열을 냅니다.** 결과는 서로 다른데 전부 답이에요 — 이 문제가 「여럿이면 어느
것이든」이라고 정했기 때문입니다. 갈리는 것은 비용입니다. 큐와 스택은 꺼내기가 한 번의 연산
이라 계수가 같고, 최소 힙 자리에 「담긴 후보를 전부 읽어 최솟값을 고르는 방식」을 놓으면
별 모양 그래프에서 3,997 이 502,498 이 됩니다.

```text
정점 0 이 나머지 999 개를 가리키는 별 모양에서

  0 을 결과에 넣는다        후보 999 개가 한꺼번에 통에 담긴다
  큐·스택으로 꺼낸다        한 번에 하나씩, 통 전체를 읽지 않는다
  최솟값을 골라 꺼낸다      꺼낼 때마다 남은 후보를 전부 읽는다   999 + 998 + … = 약 50 만
```

**절차가 나왔습니다.** 간선 목록을 나가는 목록과 남은 선행 정점 수로 옮기고, 그 수가 0 인
정점을 큐에 담고, 큐에서 꺼낼 때마다 결과에 넣고 그 정점이 가리키는 칸의 수를 하나씩 줄이되
0 이 되는 것만 다시 큐에 담습니다. 큐가 비었을 때 결과 길이가 `n` 과 같으면 그것이 답이고
아니면 `null` 입니다.

### 수행으로 알아보는 알고리즘 — 정점 여섯 개의 순서를 만든다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const n = 6;
const edges: [number, number][] = [[5, 2], [5, 0], [4, 0], [4, 1], [2, 3], [3, 1]];
// 이 절이 끝나면 [4, 5, 2, 0, 3, 1] 이 나와야 한다
```

정점을 왜 여섯으로 뒀을까요? 들어오는 간선이 없는 정점이 **둘(4·5)** 이라 큐가 여럿을 담고
시작하는 자리가 실행되고, 정점 0 과 1 은 선행 정점이 **둘씩**이라 「줄였는데 아직 0 이 아니다」
갈래가 반드시 실행되며, 정점 0 과 1 은 나가는 간선이 없어 목록이 빈 경우까지 함께 확인되기
때문입니다.

```text
topologicalSort(n, edges):
    간선 [u, v] 마다 next[u] 에 v 를 넣고 remaining[v] 를 하나 올린다
    remaining 이 0 인 정점을 번호가 작은 것부터 queue 에 담는다
    order 를 빈 배열로, head 를 0 으로 둔다
    head 가 queue 의 길이보다 작은 동안:
        u ← queue[head] 를 꺼내고 head 를 하나 올린다
        order 뒤에 u 를 넣는다
        next[u] 의 정점 v 마다:
            remaining[v] 를 하나 내린다
            0 이 됐으면 queue 에 담는다                        ① 0 이 된 그 순간
            아니면 담지 않는다                                 ② 아직 남았다
    order 의 길이가 n 이면 order 를, 아니면 null 을 반환한다   ③ 전부 들어갔다 / ④ 남았다
```

#### 1. 간선 목록을 나가는 목록과 남은 선행 정점 수로 옮긴다

간선 목록은 「누가 누구보다 먼저인가」를 담고 있지만 「정점 1 보다 먼저여야 하는 정점이 몇 개
인가」를 묻기에는 불편합니다. 그 질문에 답하려면 목록 전체를 다시 읽어야 하니까요. 간선을 한
번 읽으면서 나가는 쪽은 목록에, 들어오는 쪽은 개수에 각각 담아 둡니다.

```ts
const next: number[][] = Array.from({ length: n }, () => []);
const remaining: number[] = Array.from({ length: n }, () => 0);
for (const [u, v] of edges) {
  (next[u] as number[]).push(v);
  remaining[v] = (remaining[v] as number) + 1;
}
```

실행하면 이렇게 나옵니다. 간선 하나가 두 자료에 한 번씩 반영되는 것이 보여요.

```text
edges = [[5,2], [5,0], [4,0], [4,1], [2,3], [3,1]]

  next[0] = []          remaining[0] = 2      5→0 과 4→0 이 들어온다
  next[1] = []          remaining[1] = 2      4→1 과 3→1 이 들어온다
  next[2] = [3]         remaining[2] = 1      5→2 가 들어온다
  next[3] = [1]         remaining[3] = 1      2→3 이 들어온다
  next[4] = [0, 1]      remaining[4] = 0      들어오는 간선이 없다
  next[5] = [2, 0]      remaining[5] = 0      들어오는 간선이 없다
                        └ 목록 길이의 합 6 = E, remaining 의 합 6 = E
```

#### 멈춤 — 세는 방향을 뒤집기 쉽다

간선 `[u, v]` 는 「`u` 가 먼저」라는 뜻이라, `u` 가 주인공처럼 읽힙니다. 그래서 `remaining[u]`
를 올리는 코드를 쓰기 쉬워요. 그 오해대로 적으면 이렇게 됩니다.

```ts
for (const [u, v] of edges) {
  (next[u] as number[]).push(v);
  remaining[u] = (remaining[u] as number) + 1; // ← 도착점이 아니라 출발점을 세면
}
```

이 코드는 예외를 내지 않습니다. 그리고 **어떤 입력에서는 결과까지 같아요.**

<!--proof:mutant-out-degree-->

```text
                        들어오는 간선을 센다   나가는 간선을 센다
전개가 쓰는 여섯 정점   [4, 5, 2, 0, 3, 1]     null
마름모 네 정점          [0, 1, 2, 3]           null
한 줄로 이은 네 정점    [0, 1, 2, 3]           null
간선이 없는 네 정점     [0, 1, 2, 3]           [0, 1, 2, 3]
```

마지막 줄이 그 자리입니다. 간선이 하나도 없으면 두 방향 다 세는 것이 없어 결과가 같아요.
**테스트가 이 입력만 담고 있으면 방향을 뒤집어 놓고도 통과합니다.** 위 세 줄에서는 전부
`null` 이 나오는데, 사이클이 하나도 없는 그래프에 「순서를 만들 수 없다」를 답하는 것이라
어긋난 정도가 큽니다.

```text
사슬 0→1→2→3 에서 나가는 간선을 세면

  remaining = [1, 1, 1, 0]     0·1·2 는 나가는 간선이 하나씩, 3 은 없다
  0 인 정점                    3 하나뿐이다
  3 을 결과에 넣는다           next[3] 이 비어 있어 줄일 것이 없다
  큐가 빈다                    order = [3], 길이 1 ≠ 4 이므로 null
                               └ 정작 맨 앞에 와야 할 0 은 후보가 된 적이 없다
```

세는 방향을 확인하는 방법은 하나입니다. `remaining` 의 합이 `E` 와 같은지 보는 거예요.
들어오는 간선을 세든 나가는 간선을 세든 합은 `E` 로 같지만, **각 칸의 값**은 완전히 다릅니다.

#### 2. 남은 수가 0 인 정점을 큐에 담는다

이제 출발 후보를 모읍니다. `remaining` 이 0 인 정점이 「자기보다 먼저 와야 하는 정점이 하나도
없는 정점」이에요. 번호가 작은 것부터 담고, 꺼낸 자리를 지우는 대신 `head` 첨자를 하나씩
올려서 큐를 만듭니다.

```ts
const queue: number[] = [];
for (let v = 0; v < n; v++) if (remaining[v] === 0) queue.push(v);

const order: number[] = [];
let head = 0;
```

실행하면 이렇게 나옵니다. 정점 4 와 5 가 담기고 결과 배열은 아직 비어 있어요.

```text
remaining = [2, 2, 1, 1, 0, 0]
             0  1  2  3  4  5
                         ^  ^
                         └──┴─ 0 인 칸 둘. 번호가 작은 4 를 먼저 담는다

queue = [4, 5]     head = 0     order = []
         ^ head 가 가리키는 자리
```

#### 3. 큐에서 꺼내며 도착 정점의 수를 줄인다

여기가 순서를 만드는 자리입니다. 큐에서 하나 꺼내 결과에 넣고, 그 정점이 가리키는 칸들의 수를
하나씩 줄이되 **0 이 된 것만** 다시 큐에 담아요.

```ts
while (head < queue.length) {
  const u = queue[head] as number;
  head++;
  order.push(u);

  for (const v of next[u] as number[]) {
    remaining[v] = (remaining[v] as number) - 1;

    // ① 남은 선행 정점이 0 이 된 그 순간에 큐에 담는다.
    // ② 아직 0 이 아니면 담지 않는다. 남은 간선이 이 정점을 다시 줄여 줄 것이다.
    if (remaining[v] === 0) queue.push(v);
  }
}
```

가장 중요한 줄은 `if (remaining[v] === 0) queue.push(v);` 입니다. 이 줄이 **찾는 일을 없애는**
자리예요. 값이 0 이 되는 순간이 여기뿐이므로, 여기서 담아 두면 나중에 0 인 칸을 다시 찾을
이유가 없습니다.

```text
정점 4 를 꺼낸 직후 — next[4] = [0, 1] 을 차례로 줄인다

  remaining[0]  2 → 1    0 이 아니다   ② 담지 않는다
  remaining[1]  2 → 1    0 이 아니다   ② 담지 않는다
                         └ queue 는 [4, 5] 그대로, head 만 1 로 올라간다

정점 5 를 꺼낸 직후 — next[5] = [2, 0] 을 차례로 줄인다

  remaining[2]  1 → 0    0 이 됐다     ① 담는다
  remaining[0]  1 → 0    0 이 됐다     ① 담는다
                         └ queue 가 [4, 5, 2, 0] 이 된다
```

#### 4. 여섯 정점을 처음부터 끝까지 따라간다

앞의 세 조각을 이어 실제로 실행하면 여덟 단계가 나옵니다. 갈래 `①`·`②`·`③` 이 각각 어디서
실행되는지를 함께 적었어요.

<!--viz:topoWalk-->
```text
T1   준비            remaining [2,2,1,1,0,0]   queue [4,5]      order []
T2   4 를 꺼낸다     0·1 을 2→1 로 줄인다 ②    queue [5]        order [4]
T3   5 를 꺼낸다     2·0 이 0 이 됐다 ①        queue [2,0]      order [4,5]
T4   2 를 꺼낸다     3 이 0 이 됐다 ①          queue [0,3]      order [4,5,2]
T5   0 을 꺼낸다     next[0] 이 비어 있다      queue [3]        order [4,5,2,0]
T6   3 을 꺼낸다     1 이 0 이 됐다 ①          queue [1]        order [4,5,2,0,3]
T7   1 을 꺼낸다     next[1] 이 비어 있다      queue []         order [4,5,2,0,3,1]
T8   종료            길이 6 = n 이다 ③         queue []         order [4,5,2,0,3,1]
```

| --- | --- | --- | --- | --- | --- |
| T1 | — | `remaining` 이 0 인 칸 둘 | `2 2 1 1 0 0` | `[]` | `[4,5]` |
| T2 | 4 | `1 === 0` 이 **거짓** 두 번 → ② | `1 1 1 1 0 0` | `[4]` | `[5]` |
| T3 | 5 | `0 === 0` 이 **참** 두 번 → ① | `0 1 0 1 0 0` | `[4,5]` | `[2,0]` |
| T4 | 2 | `0 === 0` 이 **참** → ① | `0 1 0 0 0 0` | `[4,5,2]` | `[0,3]` |
| T5 | 0 | `next[0]` 이 비어 갈래가 없다 | `0 1 0 0 0 0` | `[4,5,2,0]` | `[3]` |
| T6 | 3 | `0 === 0` 이 **참** → ① | `0 0 0 0 0 0` | `[4,5,2,0,3]` | `[1]` |
| T7 | 1 | `next[1]` 이 비어 갈래가 없다 | `0 0 0 0 0 0` | `[4,5,2,0,3,1]` | `[]` |
| T8 | — | `head < queue.length` 가 **거짓** | `0 0 0 0 0 0` | `[4,5,2,0,3,1]` | `[]` |

**세 갈래가 모두 나왔습니다.** 꺼내기는 T2 부터 T7 까지 여섯 번이고, 감소는 T2 에서 두 번,
T3 에서 두 번, T4 와 T6 에서 한 번씩 해서 모두 여섯 번 — 간선 수와 같아요. ① 이 네 번,
② 가 두 번, 마지막에 ③ 이 한 번 실행됩니다. 반환값은 `[4, 5, 2, 0, 3, 1]` 입니다.

```text
①  0 이 된 그 순간에 담는다    T3 에서 두 번 · T4 · T6      네 번 = 씨앗이 아닌 정점 수
②  줄였지만 아직 0 이 아니다   T2 에서 두 번                두 번
③  길이 6 = n 이라 반환한다    T8                           한 번

감소 6 = E,  꺼내기 6 = V,  큐에 담긴 총수 6 = 씨앗 2 + ① 네 번
```

여기서 헷갈리기 쉬운 포인트는 T4 입니다. T3 에서 정점 2 와 0 이 같은 순간에 큐에 담겼는데,
꺼낼 때는 2 가 먼저 나와요. 큐가 **먼저 담은 것을 먼저 꺼내기** 때문이고, `next[5]` 가
`[2, 0]` 순서라 2 가 먼저 담겼기 때문입니다.

#### 멈춤 — 사이클을 찾는 코드가 따로 있어야 할 것 같다

위 코드 어디에도 「사이클을 찾는다」는 부분이 없습니다. 그래서 사이클이 있는 입력에서는 무슨
일이 일어날지 알 수 없게 읽히고, 반복문 안에서 방문 표시를 두어 되돌아온 자리를 잡아내는
코드를 따로 붙이고 싶어져요. 그 오해대로 생각하면 「사이클이면 반복이 끝나지 않는다」까지
가게 됩니다.

```text
0 → 1 → 2 → 0 인 그래프에서 무슨 일이 일어나는가

  remaining = [1, 1, 1]      세 정점 다 들어오는 간선이 하나씩 있다
  0 인 칸                    하나도 없다
  queue                      비어 있다
  head < queue.length        처음부터 거짓이라 반복이 한 번도 실행되지 않는다
                             └ 끝나지 않기는커녕 아무 일도 하지 않고 끝난다
```

**반복은 언제나 끝납니다.** 큐에 담기는 총수가 `V` 이하이고 한 바퀴마다 `head` 가 정확히
하나 올라가니까요. 사이클 위의 정점은 `remaining` 이 0 이 되는 일이 없어 큐에 담기지 못하고,
그래서 `order` 에도 못 들어갑니다. 실제로 세어 보면 이렇습니다.

<!--proof:cycle-values-->

```text
입력                                 큐가 담은 정점 수   정점 수 n   반환값
사이클만 있다 0→1→2→0                0                   3           null
앞에 정점 하나 3→0, 사이클 0→1→2→0   1                   4           null
자기 루프 0→0                        0                   1           null
사이클이 없다 (전개 입력)            6                   6           [4, 5, 2, 0, 3, 1]
```

**사이클 검출은 마지막 한 줄이 전부입니다** — `order.length === n` 을 보는 것이죠. 큐가 담은
정점 수가 `n` 보다 작으면 그 차이만큼이 사이클에 갇혀 있는 정점이고, 그때 ④ 갈래로 `null` 을
돌려줍니다. 둘째 줄이 그 자리예요 — 정점 3 은 결과에 들어갔지만 나머지 셋이 못 들어가
길이 1 로 끝났습니다.

```text
길이 비교 한 줄이 두 갈래를 가른다

  order.length === n   전부 들어갔다    사이클이 없다   ③ order 를 반환한다
  order.length <  n    남은 것이 있다   사이클이 있다   ④ null 을 반환한다
                       └ 남은 정점을 세지 않아도 된다. 들어간 것을 세는 것으로 같다
```

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 **마지막 길이 비교 한 줄**
뿐이에요 — 앞의 조각들은 결과를 만들기만 했고, 그것이 답인지 판정하는 자리가 여기입니다.

```ts
export function topologicalSort(
  n: number,
  edges: [number, number][],
): number[] | null {
  // 간선 목록을 둘로 옮긴다 — 정점마다 나가는 간선의 도착 정점 목록과, 들어오는 간선 수.
  const next: number[][] = Array.from({ length: n }, () => []);
  const remaining: number[] = Array.from({ length: n }, () => 0);
  for (const [u, v] of edges) {
    (next[u] as number[]).push(v);
    remaining[v] = (remaining[v] as number) + 1;
  }

  // 선행 정점이 하나도 없는 정점이 맨 앞에 놓아도 되는 정점이다. 번호가 작은 것부터 담는다.
  const queue: number[] = [];
  for (let v = 0; v < n; v++) if (remaining[v] === 0) queue.push(v);

  const order: number[] = [];
  let head = 0;
  while (head < queue.length) {
    const u = queue[head] as number;
    head++;
    order.push(u);

    for (const v of next[u] as number[]) {
      remaining[v] = (remaining[v] as number) - 1;

      // ① 남은 선행 정점이 0 이 된 그 순간에 큐에 담는다.
      // ② 아직 0 이 아니면 담지 않는다. 남은 간선이 이 정점을 다시 줄여 줄 것이다.
      if (remaining[v] === 0) queue.push(v);
    }
  }

  // ③ 정점이 전부 결과에 들어갔으면 그것이 위상 순서다.
  // ④ 하나라도 남았으면 남은 정점들이 사이클을 이루고 있다.
  return order.length === n ? order : null;
}
```

실행하면 이렇게 나옵니다.

<!--proof:walk-result-->

```text
topologicalSort(6, [[5,2],[5,0],[4,0],[4,1],[2,3],[3,1]])   →   [4, 5, 2, 0, 3, 1]
topologicalSort(4, [[0,1],[0,2],[1,3],[2,3]])               →   [0, 1, 2, 3]
topologicalSort(4, [[0,1],[1,2],[2,3]])                     →   [0, 1, 2, 3]
topologicalSort(4, [])                                      →   [0, 1, 2, 3]
topologicalSort(3, [[0,1],[1,2],[2,0]])                     →   null
topologicalSort(1, [[0,0]])                                 →   null
topologicalSort(1, [])                                      →   [0]
```

### 알아 두면 좋은 개념 — 선형 확장

전체 컨셉에서 여섯 정점 그래프의 유효한 나열이 720 가지 중 13 가지라는 것을 봤고, 후보 통을
바꾸자 `[4, 5, 2, 0, 3, 1]` · `[5, 2, 3, 4, 1, 0]` · `[4, 5, 0, 2, 3, 1]` 셋이 전부 답이 되는
것도 봤습니다. 간선이 정하는 것은 **일부 쌍의 앞뒤**뿐이라 나머지 쌍은 자유롭기 때문이에요.

```text
간선이 정하는 것과 정하지 않는 것

  5 와 2 의 앞뒤    5→2 가 있다             정해진다
  2 와 3 의 앞뒤    2→3 이 있다             정해진다
  5 와 3 의 앞뒤    5→2→3 으로 이어진다     정해진다 (간선을 이어서)
  4 와 5 의 앞뒤    이어지는 길이 없다      정해지지 않는다  ← 어느 쪽이든 답
  0 과 2 의 앞뒤    이어지는 길이 없다      정해지지 않는다  ← 어느 쪽이든 답
```

일부 쌍의 앞뒤만 정해 놓은 관계를 **부분 순서**라 하고, 그 관계를 어기지 않으면서 모든 쌍의
앞뒤를 정해 한 줄로 만든 것을 그 부분 순서의 **선형 확장**(linear extension)이라고 부릅니다.
이 편이 만드는 위상 순서가 바로 선형 확장 하나예요.

| 이 편에서 | 선형 확장 일반 |
| --- | --- |
| 부분 순서를 주는 것 | 간선 `[u, v]` 를 이어서 만든 「먼저」 관계 |
| 선형 확장 하나 | 함수가 반환하는 나열 `[4, 5, 2, 0, 3, 1]` |
| 선형 확장이 여럿인 이유 | 이어지는 길이 없는 쌍(4 와 5, 0 과 2)이 있다 |
| 선형 확장이 없는 경우 | 사이클이 있어 어떤 쌍이 서로를 앞서야 한다 |

같은 이름이 이 편 밖에서도 그대로 쓰입니다. 작업 스케줄링에서 「의존 관계를 지키는 실행
순서」가 선형 확장이고, 부분 순서의 선형 확장이 **몇 개인가**를 세는 문제는 조합론에서 따로
다루는 주제예요. 이 편의 답이 13 개였던 그 수가 그것입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 식으로 무엇이 나오는지, 무엇이
매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **제약이 「먼저·나중」 쌍으로만 주어집니다.** 「A 를 B 보다 먼저」 같은 두 대상 사이의 앞뒤
  제약이고, 「A 와 B 사이에 세 칸을 둔다」 같은 거리 제약이 없어야 해요.
- **답이 여럿이어도 됩니다.** 하나만 내면 되는 문제라야 이 절차를 그대로 씁니다. 사전순으로
  가장 작은 것을 요구하면 후보 통을 최소 힙으로 바꿔야 하고 `log` 가 붙어요.
- **그래프를 미리 다 받아 둘 수 있습니다.** 간선을 한 번에 받아 `remaining` 을 세고 시작하니까요.

```text
세 조건이 코드의 모양을 그대로 정한다
  앞뒤 제약뿐이다      → 정점마다 수 하나면 된다. 거리를 담을 자리가 필요 없다
  답이 여럿이어도 된다 → 후보 통에서 아무거나 꺼내도 된다. 큐로 충분하다
  미리 다 받는다       → remaining 을 먼저 세고 그 뒤로는 새 간선을 받지 않는다
```

거리 제약이 붙은 문제에 이 절차를 쓰면 무엇이 어긋나는지는 값으로 확인됩니다. 전개가 쓴
그래프에서 정점 1 은 결과의 여섯 번째인데, 「선행 과목을 다 들은 다음 학기」를 묻는다면 답이
달라요.

```text
같은 그래프에서 두 질문의 답

  위상 순서             [4, 5, 2, 0, 3, 1]        정점 1 은 여섯 번째다
  가장 이른 학기 번호   0:1 1:3 2:1 3:2 4:0 5:0   정점 1 의 학기 번호는 3 이다
                        └ 앞은 정점을 나열한 것이고 뒤는 정점마다 값을 적은 것이다.
                          학기 번호는 선행 정점들의 번호 중 최댓값에 1 을 더해 나온다
```

학기 번호를 구하려면 위상 순서대로 정점을 보면서 값을 물려주는 계산을 한 번 더 덧붙여야 합니다.
간선에 길이가 붙고 최단 거리를 물으면 그것은 또 다른 절차예요 —
[`bfsShortestPath` 가이드](../bfsShortestPath/bfsShortestPath-guide.md)가 그중 하나입니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "선수 과목"   "먼저 처리해야 한다"   "의존 관계"   "빌드 순서"
  "가능한 순서를 아무거나 출력"        "불가능하면 -1 또는 null"

제약에 이런 모양이 보이면
  정점과 간선이 각각 10만 규모이고 시간이 1~2초   ← V + E 규모의 절차를 찾으라는 뜻이다
  답이 여러 개면 아무거나 좋다고 적혀 있다        ← 후보 통을 고를 자유가 있다는 뜻이다
  순환이면 불가능을 출력하라고 적혀 있다          ← 길이 비교 한 줄로 끝난다는 뜻이다
```

반대로 **「사전순으로 가장 빠른 순서」·「단계 수를 최소로」** 가 보이면 이 절차를 그대로 쓰지
않습니다. 앞은 후보 통을 최소 힙으로 바꾸는 문제이고, 뒤는 위상 순서 위에서 값을 물려주는
계산을 한 겹 더 덧붙이는 문제예요. 사이클이 있는지만 묻는다면
[`directedCycleDetection` 가이드](../directedCycleDetection/directedCycleDetection-guide.mdx)의 절차도 답이 됩니다.

#### 실제로 쓰이는 곳

- **CPython 표준 라이브러리 `graphlib.TopologicalSorter`** — 이 글이 만든 것과 같은 절차입니다.
  클래스 독스트링이 *"Provides functionality to topologically sort a graph of hashable nodes"*
  이고, 정점마다 `self.npredecessors = 0` 로 선행 정점 수를 두고 그래프를 받을 때
  `nodeinfo.npredecessors += len(predecessors)` 로 올립니다. 처음 후보는
  `self._ready_nodes = [i.node for i in self._node2info.values() if i.npredecessors == 0]`
  으로 모으고, 정점 하나를 끝낼 때마다 `successor_info.npredecessors -= 1` 한 뒤
  `if successor_info.npredecessors == 0:` 일 때만 후보에 담아요 — 이 글의 ① 갈래 그대로입니다.
  ([python/cpython Lib/graphlib.py](https://raw.githubusercontent.com/python/cpython/main/Lib/graphlib.py), 조회 2026-08-30)
- **GNU coreutils `tsort`** — 텍스트로 적은 「먼저·나중」 쌍을 받아 한 줄로 나열해 주는 명령입니다.
  소스 앞머리 주석이 *"The topological sort is done according to Algorithm T (Topological sort)
  in Donald E. Knuth, The Art of Computer Programming, Volume 1/Fundamental Algorithms,
  page 262."* 라 적어 근거를 밝히고, 관계를 기록하는 `record_relation` 이 `k->count++` 로
  도착 쪽의 수를 올린 다음 나열하는 동안 `p->suc->count--` 로 하나씩 줄입니다.
  ([coreutils src/tsort.c](https://raw.githubusercontent.com/coreutils/coreutils/master/src/tsort.c), 조회 2026-08-30)

두 곳 다 **정점마다 수 하나를 세어 두고 그것을 줄이는** 방식입니다. 이름만 다를 뿐
(`npredecessors` · `count`) 이 글의 `remaining` 과 같은 것이고, 0 이 되는 순간에 후보로
올리는 자리도 같아요.

### 수식 정의와 유도

정점 $v$ 로 들어오는 간선의 수를 $\deg^-(v)$ 라 적습니다. $t$ 바퀴가 끝난 뒤 아직 결과에 안
들어간 정점들의 모임은 $R_t$ 예요. **$V$ 와 $E$ 는 파트 1 에서 정한 그대로 정점 수와 간선
수이고, 모임이 아니라 수입니다** — 모임의 크기는 $|R_t|$ 처럼 세로줄로 적습니다.

| 이름 | 정의 | 이 그래프에서 |
| --- | --- | --- |
| $\deg^-(v)$ | $v$ 로 들어오는 간선의 수 | $\deg^-(0) = 2$ |
| $R_t$ | $t$ 바퀴가 끝난 뒤 결과에 안 들어간 정점들 | $R_0 = \{0,1,2,3,4,5\}$ |
| $r_t(v)$ | $R_t$ 안의 정점에서 $v$ 로 오는 간선의 수 | 코드의 `remaining[v]` |
| $A(V, E)$ | 절차가 읽고 쓴 배열 칸의 총수 | 아래에서 센다 |

먼저 $\deg^-$ 를 정의 그대로 세어 검산합시다. 간선 하나는 도착점이 정확히 하나이므로, 모든
정점의 $\deg^-$ 를 더하면 간선 수가 나와야 해요.

$$\sum_{v} \deg^-(v) = E$$

```text
전개가 쓴 그래프에 넣어 검산한다 — 간선은 5→2 · 5→0 · 4→0 · 4→1 · 2→3 · 3→1 여섯이다

  deg⁻(0) = 2      5→0 과 4→0
  deg⁻(1) = 2      4→1 과 3→1
  deg⁻(2) = 1      5→2
  deg⁻(3) = 1      2→3
  deg⁻(4) = 0      들어오는 간선이 없다
  deg⁻(5) = 0      들어오는 간선이 없다
                   └ 합 6 = E. 코드의 remaining 초기값 합과 같다
```

이제 이 절차가 **사이클이 없으면 반드시 정점 전부를 결과에 넣는다**는 것을 유도합니다.
핵심은 하나예요 — 정점이 남아 있는 한 $r_t$ 가 0 인 정점이 반드시 있다는 것입니다.

$$R_t \neq \varnothing \;\wedge\; \text{사이클이 없다} \;\Longrightarrow\; \exists v \in R_t : r_t(v) = 0$$

```text
전개 입력에서 먼저 확인한다 — R_t 는 t 개를 결과에 넣은 뒤 남은 정점들이다

  t = 0   R_0 = {0,1,2,3,4,5}   r_0 이 0 인 정점   4 · 5
  t = 1   R_1 = {0,1,2,3,5}     r_1 이 0 인 정점   5
  t = 2   R_2 = {0,1,2,3}       r_2 가 0 인 정점   0 · 2
  t = 4   R_4 = {1,3}           r_4 가 0 인 정점   3
          └ 남은 정점이 있는 한 후보가 비지 않는다. 그것을 아래에서 유도한다
```

반대로 가정해서 유도합시다. $R_t$ 의 모든 정점 $v$ 에 대해 $r_t(v) \ge 1$ 이라면, 아무 정점
$x_0 \in R_t$ 를 골랐을 때 $R_t$ 안에서 $x_1 \to x_0$ 인 $x_1$ 이 있습니다. 같은 이유로
$x_2 \to x_1$ 인 $x_2$ 가 있고, 이렇게 $|R_t| + 1$ 개를 고를 수 있어요.

```text
거꾸로 따라가며 정점을 고른다 — R_t 의 크기가 m 이라 하자

  x_0        아무 정점 하나
  x_1 → x_0  r_t(x_0) ≥ 1 이므로 반드시 있다
  x_2 → x_1  r_t(x_1) ≥ 1 이므로 반드시 있다
  …
  x_m        m + 1 개를 골랐는데 서로 다른 정점은 m 개뿐이다
             └ 비둘기집 원리로 x_i = x_j 인 i < j 가 있다
```

$x_i = x_j$ 이면 $x_j \to x_{j-1} \to \dots \to x_i$ 가 출발한 정점으로 되돌아오는 길이라
사이클입니다. 사이클이 없다는 가정과 어긋나므로, 처음 가정인 「모든 정점의 $r_t$ 가 1 이상」이
거짓이에요. 그러니 $r_t$ 가 0 인 정점이 있고, 그 정점은 큐에 담겨 다음 바퀴에 결과로 들어갑니다.

$$|order| = V \iff \text{사이클이 없다}$$

```text
두 방향을 각각 확인한다

  사이클이 없다 → 길이가 V 다
    남은 정점이 있는 한 r_t 가 0 인 정점이 있고(위에서 유도했다), 그 정점이 큐에 담긴다.
    그러니 남은 정점이 0 이 될 때까지 반복이 이어진다

  길이가 V 다 → 사이클이 없다
    사이클 C 가 있다고 하자. C 위의 정점 v 는 자기 앞의 C 위 정점이 결과에 들어가야
    r_t 가 줄어드는데, 그 정점도 같은 이유로 못 들어간다. 그래서 C 위의 정점은 하나도
    결과에 못 들어가고 |order| < V 다 — 길이가 V 라는 것과 어긋난다
```

이제 배열 칸 접근 수 $A(V, E)$ 를 코드에서 그대로 셉니다. 사이클이 없는 경우입니다.

$$A(V, E) = \underbrace{2V}_{\text{배열 둘}} + \underbrace{4E}_{\text{간선 한 번씩}} + \underbrace{V}_{\text{씨앗 찾기}} + \underbrace{3V}_{\text{꺼내기}} + \underbrace{2E}_{\text{줄이기}} + \underbrace{V}_{\text{담기}} = 7V + 6E$$

```ts
// 각 항이 어느 줄에서 나오는지 — 왼쪽 수가 그 줄이 만드는 칸 접근 수다.
// 2V   Array.from 두 번
// 4E   next[u] 읽기 + push · remaining[v] 읽기 + 쓰기
//  V   for (let v = 0; v < n; v++) if (remaining[v] === 0)
// 3V   queue[head] 읽기 + order.push · next[u] 읽기
// 2E   remaining[v] 읽기 + 쓰기
//  V   queue.push — 씨앗과 ① 갈래를 합쳐 정점당 한 번
const cellsPerVertex = 7;
const cellsPerEdge = 6;
const closedForm = (V: number, E: number): number =>
  cellsPerVertex * V + cellsPerEdge * E;
```

식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

```text
입력                          V        E   실제 배열 칸 접근     7V + 6E
전개가 쓰는 여섯 정점         6        6                  78          78
마름모 네 정점                4        4                  52          52
사슬 1,000                1,000      999              12,994      12,994
별 모양 1,000             1,000      999              12,994      12,994
사슬 100,000            100,000   99,999           1,299,994   1,299,994
```

**다섯 줄이 전부 정확히 맞습니다.** 그리고 셋째 줄과 넷째 줄이 같은 값이라는 것도 함께 보세요 —
사슬과 별 모양은 모양이 완전히 다른데 계수가 같습니다. 이 식에 정점 수도 간선 수도 아닌
항이 없기 때문이에요.

마지막으로 제약 규모를 넣습니다. $V = E = 100{,}000$ 이면 $A = 700{,}000 + 600{,}000$ 입니다.

| 항 | 무엇을 세는가 | 그때의 값 |
| --- | --- | --- |
| $7V$ | 배열 둘 · 씨앗 찾기 · 꺼내기 · 담기 | 700,000 |
| $6E$ | 간선 한 번씩 읽기 · 남은 수 줄이기 | 600,000 |
| $A$ | 합 | 1,300,000 |
| 순열 전수 검사 | $V!$ 가지 나열 | 456,574 자리 |

130 만과 456,574 자리를 견주면 이 절차가 무엇을 바꿨는지가 수로 나옵니다. 나열을 고르는 문제를
**간선을 한 번씩 읽는 문제로** 바꾼 것이에요.

### 불변식 — 큐에 담긴 정점은 선행 정점이 하나도 남지 않았다

파트 1 에서 코드가 동작하는 것을 여덟 단계로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> 반복문의 한 바퀴가 끝날 때마다, `remaining[v]` 는 **아직 `order` 에 안 들어간 정점 중
> `v` 를 가리키는 정점의 수**와 같습니다. 그리고 `queue` 에 담긴 정점은 그 수가 0 이 된
> 정점들뿐이고, 각 정점은 많아야 한 번 담깁니다.

```text
                    아직 order 에 없는 정점               remaining[v] 가 세는 것
                  ┌────────────────────────┐
   order [4, 5]   │  0   1   2   3         │              그 안에서 v 로 오는 간선의 수
                  └────────────────────────┘
                         ^                                remaining[1] = 1
                         └ 1 을 가리키는 것은 3 뿐이다    (4 는 이미 order 에 있다)
```

「한 바퀴가 끝날 때마다」가 중요합니다. 반복이 다 끝난 뒤 한 번만 참인 것이 아니라 **정점 하나를
처리한 직후마다** 참이라는 뜻이에요. 그래야 다음 바퀴가 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** 반복이 시작되기 전에는 `order` 가 비어 있어서 「아직 안 들어간 정점」이
전부이고, 그때 `v` 로 오는 간선의 수는 `deg⁻(v)` 입니다. 코드가 세어 둔 초기값이 정확히
그것이에요. 그 뒤로 상태를 바꾸는 갈래는 셋입니다.

| 무슨 일 | 무엇이 바뀌는가 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| 정점 `u` 를 `order` 에 넣는다 | `u` 가 「아직 안 들어간 정점」에서 빠진다 | `u` 가 가리키던 칸들의 값이 하나씩 커진 채로 남으면 안 되므로, 바로 다음에 `next[u]` 의 칸들을 하나씩 줄인다 |
| 값을 줄여 0 이 됐다 | 그 정점을 `queue` 에 담는다 | 값이 0 이 되는 자리가 여기뿐이라 담기는 시점이 하나로 정해진다. 한 번 0 이 된 값은 다시 줄 일이 없어 두 번 담기지 않는다 |
| 값을 줄였는데 0 이 아니다 | 아무것도 하지 않는다 | 아직 안 들어간 선행 정점이 남았다는 뜻이라, 지금 결과에 넣으면 그 간선을 어긴다 |

첫 줄의 「빠지자마자 줄인다」가 어디서 오는지 값으로 확인해 봅시다. 전개의 T2 와 T3 이 그
자리예요.

```text
T2 직후   order [4]        4 를 뺐고 next[4] = [0,1] 을 줄였다   remaining 0:1 1:1
          └ 0 을 가리키는 것은 5 하나 남았다. 1 을 가리키는 것은 3 하나 남았다    맞다

T3 직후   order [4, 5]     5 를 뺐고 next[5] = [2,0] 을 줄였다   remaining 0:0 2:0
          └ 0 을 가리키던 4·5 가 둘 다 order 에 있다. 2 를 가리키던 5 도 있다     맞다
```

이 불변식이 답의 정확성을 그대로 줍니다. 큐에서 꺼낸 정점은 자기보다 먼저 와야 하는 정점이
**이미 전부 `order` 에 들어가 있는** 정점이므로, 그 뒤에 붙이면 그 정점에 걸린 간선이 전부
지켜져요. 모든 정점이 그렇게 들어가면 나열 전체가 모든 간선을 지킵니다.

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| 정점 하나 `topologicalSort(1, [])` | `remaining[0]` 이 0 이라 씨앗이 된다 | `[0]` |
| 간선 없음 `topologicalSort(4, [])` | 네 정점이 전부 씨앗이라 번호순으로 담긴다 | `[0, 1, 2, 3]` |
| 자기 루프 `topologicalSort(1, [[0,0]])` | `remaining[0]` 이 1 이라 씨앗이 하나도 없다 | `null` |
| 사이클 `topologicalSort(3, [[0,1],[1,2],[2,0]])` | 세 칸이 전부 1 이라 큐가 빈 채로 시작한다 | `null` |
| 분리된 두 조각 `topologicalSort(4, [[0,1],[2,3]])` | 씨앗이 0 과 2 둘이고 각각 따라간다 | `[0, 2, 1, 3]` |
| 중복 간선 `topologicalSort(2, [[0,1],[0,1]])` | `remaining[1]` 이 2 가 되고 두 번 줄어 0 이 된다 | `[0, 1]` |

자기 루프와 중복 간선이 이 절차의 경계입니다. 자기 루프 `[v, v]` 는 `remaining[v]` 를 올리면서
`next[v]` 에도 `v` 를 넣는데, `v` 가 결과에 들어가야 `remaining[v]` 가 줄어들고 `remaining[v]`
가 0 이라야 결과에 들어가므로 어느 쪽도 먼저 일어날 수 없어요. 중복 간선은 값을 2 로 올리고
두 번 줄여서 결과를 바꾸지 않습니다.

**이제 깨뜨려 봅시다.** 불변식의 「큐에 담긴 정점은 선행 정점이 하나도 남지 않았다」를 지키던
줄이 어느 것인지는 바꿔 보면 확인됩니다. 큐에 담는 조건 **한 줄만** 0 이 아니라 1 이하일 때
담도록 바꿉니다.

```ts
if ((remaining[v] as number) <= 1) queue.push(v); // ← 조건만 바꿨다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-early-push-->

```text
                        0 이 될 때만 담는다   1 이 남아도 담는다
전개가 쓰는 여섯 정점   [4, 5, 2, 0, 3, 1]    null
마름모 네 정점          [0, 1, 2, 3]          null
한 줄로 이은 네 정점    [0, 1, 2, 3]          [0, 1, 2, 3]
간선이 없는 네 정점     [0, 1, 2, 3]          [0, 1, 2, 3]
```

선행 정점이 둘 이상인 정점이 있는 두 입력에서 `null` 이 나옵니다. 그 정점이 감소할 때마다
큐에 담겨 결과에 두 번 이상 들어가고, 그러면 길이가 `n` 을 넘어 마지막 길이 비교가 거짓이
되기 때문이에요.

```text
마름모 0→1 · 0→2 · 1→3 · 2→3 에서 1 이하일 때 담으면

  0 을 꺼낸다     1 과 2 가 0 이 됐다             queue [1, 2]
  1 을 꺼낸다     3 이 2→1. 1 이하라 담는다       queue [2, 3]   ← 2 가 아직 결과에 없는데 3 을 담았다
  2 를 꺼낸다     3 이 1→0. 또 담는다             queue [3, 3]
  3 을 꺼낸다     order [0, 1, 2, 3]
  3 을 또 꺼낸다  order [0, 1, 2, 3, 3]           길이 5 ≠ 4 이므로 null
```

**한 줄로 이은 네 정점에서는 두 값이 같다는 것**도 함께 보세요. 사슬은 어느 정점도 선행 정점이
둘 이상이 아니라 `remaining` 이 1 에서 0 으로 한 번에 갑니다. 그때는 「0 일 때」와 「1 이하일
때」가 같은 조건이라, 이 입력만 시험하면 바꿔 놓고도 통과해요.

### 비용 계산

#### 비용을 세는 과정

한 번의 반복이 하는 일은 큐에서 하나를 꺼내 결과에 넣고, 그 정점의 나가는 목록을 한 번 읽어
칸마다 값을 하나씩 줄이는 것뿐입니다. 전개의 값으로 확인하면 T2 가 정점 4 의 목록 둘, T3 이
정점 5 의 목록 둘, T4 가 정점 2 의 목록 하나, T5 가 정점 0 의 빈 목록, T6 이 정점 3 의 목록
하나, T7 이 정점 1 의 빈 목록이었어요.

```text
꺼낸 정점   나가는 목록 길이   담긴 정점   해당 단계
  4                  2            0        T2
  5                  2            2        T3
  2                  1            1        T4
  0                  0            0        T5
  3                  1            1        T6
  1                  0            0        T7
                     └ 목록 길이 합 6 = E, 담긴 정점 합 4 = V − 씨앗 2
```

그러니 값을 줄이는 횟수는 **간선 수와 정확히 같고**, 꺼내기 횟수는 **결과에 들어간 정점 수**와
같습니다. 사이클이 없으면 뒤의 값이 `V` 이고, 사이클이 있으면 그만큼 작아져요. 그 앞에 두 자료를
만드는 비용이 붙습니다.

```text
총식 = 배열 만들기 + 두 자료 채우기 + 씨앗 찾기 + 큐 연산    + 값 줄이기
       Θ(V)          Θ(E)             Θ(V)        Θ(V)         Θ(E')
                     ↑ 간선마다 목록 하나와 수 하나            ↑ E' 는 꺼낸 정점의 나가는 간선 수
     = Θ(V + E)

메모리 = next Θ(V + E) + remaining·queue·order Θ(V) = Θ(V + E)
```

여기서 센 것은 **배열 칸을 읽고 쓴 횟수**입니다. `Array.prototype.push` 가 안에서 칸을 다시
잡는 비용은 세지 않았어요 — 분할 상환하면 한 번의 넣기가 상수라, 위 식의 규모를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (사이클이 모든 정점을 막는다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(V + E)` | `Θ(V + E)` |
| **최악의 경우** (사이클이 없다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값이라는 것이 이 절차의 성질입니다.** 어떤 입력이 와도 두 자료를 만드는 데
`Θ(V + E)` 가 들고, 그것이 그대로 하한이에요. 간선 하나를 읽지 않고 넘어가는 길이 없기
때문입니다.

```text
케이스가 갈리는 것은 규모가 아니라 상수배다 — V = 100,000 · E = 99,999 로 고정하고 잰다

  사이클이 없다          두 자료 만들기 + 씨앗 찾기 + 주 반복 전부     7V + 6E
  사이클이 앞을 막는다   두 자료 만들기 + 씨앗 찾기 + 주 반복 한 바퀴  2V + 4E + V + 4
                         └ 규모는 둘 다 V + E 이고 계수만 1.86 배 갈린다
```

**평균을 따로 계산할 대상이 없습니다.** 최선과 최악이 같은 규모라 입력 분포를 어떻게 잡아도
기댓값이 `Θ(V + E)` 예요. 「평균이 정의되지 않는다」가 아니라 **분포와 무관하게 같다**는
쪽입니다. 둘은 다른 진술이고, 여기서는 뒤쪽이 참입니다.

```text
최악 보장     어떤 입력에도 V + E 규모를 넘지 않는다         ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다  ← 이 절차는 여기 해당하지 않는다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요.
같은 입력을 두 번 넣으면 반환값도 칸 접근 수도 똑같이 나옵니다. 경계의 종류로 보면
`Θ(V + E)` 는 상한이자 하한이에요 — 간선을 한 번씩은 읽어야 하므로 그보다 적게 할 방법이 없고,
위에서 센 대로 그보다 많이 하지도 않습니다.

#### 최악을 만드는 입력

「깊은 그래프가 최악」이라는 통념부터 확인합시다. 사슬은 가장 깊은 그래프이고 별 모양은 가장
얕은 그래프인데, 정점 수와 간선 수를 맞춰 두 극단을 실제로 실행해 보면 값이 같습니다.

```text
정점 100,000 개 · 간선 99,999 개짜리 두 극단

  사슬                                별 모양

    0 → 1 → 2 → … → 99,999               0
                                      /  |  \
                                      v  v  v
                                      1  2  3  …  99,999

                            사슬     별 모양
  가장 긴 경로의 길이       99,999   1
  큐에 동시에 담긴 정점     1 개     99,999 개
  나가는 목록의 최대 길이   1        99,999
```

<!--proof:shape-values-->

```text
입력 모양                                   V        E   배열 칸 접근   결과에 들어간 정점
사슬 0→1→…→99,999                     100,000   99,999      1,299,994   100,000
별 모양 0 이 나머지 전부를 가리킨다   100,000   99,999      1,299,994   100,000
0→1→2→0 사이클이 앞을 막는다          100,000   99,999        700,000   0 (null 을 반환한다)
```

**앞의 두 줄이 정확히 같습니다.** 통념은 이 절차에서 거짓이에요 — 깊이는 비용에 들어가지
않습니다. 반복문으로 적었으므로 호출 깊이가 없고, 큐에 동시에 담긴 개수도 비용이 아니라
배열 길이일 뿐이라 어느 쪽이든 `V` 를 넘지 않아요.

```text
최악을 만드는 조건은 모양이 아니라 크기와 사이클 유무다

  V 와 E 를 제약 상한까지 채운다     100,000 · 100,000    7V + 6E = 1,300,000
  사이클이 없어야 한다               있으면 주 반복이 그만큼 줄어든다
  모양은 아무래도 좋다               사슬이든 별이든 격자든 같은 값이다
                                     └ 셋째 줄이 통념을 부정하는 자리다
```

가장 적은 일을 하는 입력은 반대쪽입니다. 사이클이 씨앗을 전부 막으면 주 반복이 거의 실행되지
않아 130 만이 70 만으로 내려가요. 그래도 규모는 그대로 `Θ(V + E)` 입니다 — 두 자료를 만드는
`2V + 4E` 는 어떤 입력에서도 치러야 하니까요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 나열을 통째로 만들어 검사하던 것을 **한 자리씩
정하는 것**으로 바꿨고, 「지금 놓아도 되는 정점」을 정점마다 수 하나로 판정하며, 그 수가 0 이
되는 순간이 값을 줄이는 자리뿐이라 후보를 다시 찾을 필요가 없습니다.

```text
간선 목록 → next 와 remaining → 0 인 정점을 큐에 → 꺼내서 order 에 → 가리키는 칸을 줄인다
                └ 간선 한 번씩          └ 씨앗 찾기 V     └ 꺼내기 V     └ 줄이기 E, 0 이면 담는다
                                                                          └ 마지막에 길이를 n 과 견준다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T3 에서 정점 5 를 꺼내 `next[5] = [2, 0]` 을 줄였고
정점 2 와 0 이 같은 순간에 큐에 담겼어요. 그 한 걸음에서 **`next[5]` 가 `[0, 2]` 순서였다면**
최종 결과가 무엇이 되었을까요?

```text
T3   5 를 꺼낸다   2 와 0 이 0 이 됐다   queue [2, 0]   ← 이 순서가 [0, 2] 였다면?
```

<!--check:pushOrder-->
결과는 `[4, 5, 0, 2, 3, 1]` 이 됩니다. 큐가 먼저 담은 것을 먼저 꺼내므로 0 이 2 보다 먼저
나오고, 그 뒤가 밀립니다.

```text
queue [0, 2] 로 시작하면
  0 을 꺼낸다   next[0] 이 비어 있다      order [4, 5, 0]            queue [2]
  2 를 꺼낸다   3 이 0 이 됐다            order [4, 5, 0, 2]         queue [3]
  3 을 꺼낸다   1 이 0 이 됐다            order [4, 5, 0, 2, 3]      queue [1]
  1 을 꺼낸다                             order [4, 5, 0, 2, 3, 1]
                └ 유효한 나열이다. 간선 여섯 개를 다 지킨다
```

**두 결과가 다 답입니다.** 간선 목록에 `[5,2]` 가 `[5,0]` 보다 먼저 적혀 있어서 `next[5]` 가
`[2, 0]` 이 된 것이고, 입력의 적힌 순서가 바뀌면 반환값도 바뀌어요. 이 문제는 「유효하면
어느 것이든」이라 그것이 허용됩니다. 앞 절에서 순열 전수 검사가 찾은 `[4, 5, 0, 2, 3, 1]` 이
바로 이 나열이에요.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 수행으로 알아보는 알고리즘 의 T2       3 → 최악을 만드는 입력
  2 → 불변식
```

- T2 에서 정점 0 과 1 의 수가 2 에서 1 로 줄었지만 큐에 담기지 않았습니다. 정점 100,000 개로,
  마지막 정점 하나가 나머지 99,999 개를 전부 선행으로 갖는 그래프를 만들어 보세요. 그 정점은
  몇 번 줄어든 뒤에 큐에 담기고, 그동안 큐에는 무엇이 들어 있습니까.
- 불변식은 「큐에 담긴 정점은 선행 정점이 하나도 남지 않았다」고 말합니다. 그러면 큐에 동시에
  담겨 있는 정점들끼리는 어떤 관계입니까 — 그중 두 정점 사이에 간선이 있을 수 있을까요.
- 사이클이 앞을 막는 입력에서 칸 접근이 130 만에서 70 만으로 내려갔습니다. 사이클을 그래프의
  가장 뒤쪽에 두면 그 값이 어떻게 될까요. 그리고 그 값이 최악과 같아지는 이유는 무엇입니까.
