# 무향 사이클 탐지 — 방금 지나온 이웃 하나만 빼면 표시 한 벌로 판정된다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 간선을 하나씩 지워
보는 방법에서 출발해, 정점마다 부모 하나를 기억하는 부모 건너뛰기 탐색까지 갑니다. 그 방법을 준비되는
차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**무향 그래프**는 정점들과 **방향이 없는 간선**으로 이루어집니다. 간선 `[u, v]` 는 `u` 와 `v` 사이를 어느
쪽으로든 오갈 수 있다는 뜻이고, `[u, v]` 와 `[v, u]` 는 같은 간선이에요. 공원 산책로라면 어느 쪽 끝에서든
걸어 들어갈 수 있는 길 하나입니다. 이 글이 끝까지 쓰는 그래프는 정점 여섯 · 간선 다섯이에요.

<!--fig:concept-graph-->
![전개 입력 — 강조한 간선 3 개가 사이클 3 → 4 → 5 → 3](./figs/concept-graph.svg)

이 글이 답하는 것은 하나입니다. **어느 정점에서 출발해 같은 간선을 두 번 쓰지 않고 제자리로 돌아오는 길이
있는가.** 그런 길을 **사이클**이라고 부르고, 있으면 `true`, 없으면 `false` 를 돌려줍니다. 같은 그래프에서
제자리로 돌아오는 길 둘을 나란히 놓으면 사이클인 것과 아닌 것이 갈려요.

<!--proof:concept-walks-->

| 닫힌 길 | 쓴 간선 | 두 번 쓴 간선 | 판정 |
| --- | --- | --- | --- |
| 3 → 4 → 5 → 3 | [3,4] · [4,5] · [5,3] | 없다 | 사이클이다 |
| 0 → 1 → 0 | [0,1] · [0,1] | [0,1] | 사이클이 아니다 |

전개 입력에 정본을 실행한 답은 true 입니다.

<!--/proof-->

둘째 길도 제자리로 돌아오기는 했지만, 간선 `[0,1]` 을 갔다가 같은 간선으로 되돌아왔을 뿐입니다. **여기가
방향이 있는 그래프와 갈리는 자리예요.** 방향이 있으면 되돌아오려면 반대 방향 간선이 따로 있어야 하는데, 방향이
없으면 방금 지나온 간선 하나로 언제든 되돌아갈 수 있습니다. 그 되돌아가기를 사이클로 세면 간선 하나짜리
그래프도 `true` 가 돼요. 반대로 자기 자신을 잇는 간선 `[v, v]` 와 같은 정점 쌍을 두 번 잇는 간선은 사이클로
봅니다. 둘 다 제자리로 돌아오는 길이 간선 하나를 되풀이하지 않고 생기기 때문이에요.

<!--proof:concept-special-->

| 입력 | 간선 목록 | 이웃 목록 | 정본의 답 |
| --- | --- | --- | --- |
| 자기 자신을 잇는 간선 | [[0,0]] | nbr[0] = [0, 0] | true |
| 같은 쌍을 두 번 이은 간선 | [[0,1],[0,1]] | nbr[0] = [1, 1] · nbr[1] = [0, 0] | true |
| 간선 하나 | [[0,1]] | nbr[0] = [1] · nbr[1] = [0] | false |

<!--/proof-->

찾는 방법의 요점은 하나입니다. 정점마다 「확인했다」는 **표시**를 한 벌만 두고, 이웃을 따라가며 표시 없는
정점을 표시해 나갑니다. 이때 정점 `v` 를 처음 표시하게 한 이웃을 `v` 의 **부모**라고 부르고, 정점마다 부모를
기억해 둡니다. 어떤 정점의 이웃을 확인하다가 **부모가 아닌데 이미 표시된 이웃**이 나오면, 그 순간 사이클이
확정됩니다. 부모는 방금 지나온 간선의 반대쪽 끝이라 건너뛰어요. 이 방법을 이 글에서는 **부모 건너뛰기
탐색**이라고 부릅니다.

| 이웃의 모양 | 뜻 | 하는 일 |
| --- | --- | --- |
| 부모다 | 방금 지나온 간선을 반대쪽에서 읽었다 | 건너뛴다 |
| 부모가 아닌데 표시돼 있다 | 그 이웃까지 가는 길이 따로 있다 | `true` 를 돌려준다 |
| 표시가 없다 | 처음 만난 정점이다 | 표시하고 부모를 적은 뒤 나중에 확인한다 |

표시된 정점과, 정점마다 부모와 이어 주는 간선을 모으면 나무 모양 하나가 생깁니다. 이것을 **탐색 트리**라고
부르고, 그 간선 하나하나를 **나무 간선**이라고 부릅니다. 탐색 트리는 연결 성분(간선을 따라 서로 오갈 수 있는
정점의 무리)마다 하나씩 생겨요. 전개 입력에서 사이클이 확정되는 순간의 탐색 트리를 그리면 이렇습니다. 정점
안의 값이 부모이고, 무대 아래 두 띠는 아직 이웃을 확인하지 않은 정점(`stack`)과 그 정점의 부모(`from`)예요.

<!--fig:concept-tree-->
![T9 — 굵은 실선이 나무 간선, 강조한 대시 간선이 표시된 두 정점을 다시 잇는다](./figs/concept-tree.svg)

굵은 실선 넷이 나무 간선입니다. 정점 5 의 이웃 4 는 5 의 부모(3)가 아닌데 이미 표시돼 있어요. 나무 간선만으로
5 에서 3 을 거쳐 4 로 가는 길이 이미 있으니, 간선 `[4,5]` 를 더하면 제자리로 돌아옵니다. 할 일을 나누어 보면
이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선 하나를 양 끝 정점의 목록에 한 번씩 넣는다 | 간선마다 두 번 |
| 시작 정점 찾기 | 정점마다 표시를 한 번 읽는다 | 정점마다 한 번 |
| 표시하기 | 정점마다 한 번 표시하고 스택에 한 번 넣는다 | 정점마다 한 번 |
| 이웃 확인하기 | 꺼낸 정점의 이웃 항목마다 부모인지 · 표시됐는지 본다 | 간선마다 두 번 이하 |
| 모두 | | `Θ(V + E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **인접 리스트.** 정점마다 이웃 번호를 담은 목록 하나를 두는 그래프 표현입니다. 무향 간선 `[u, v]` 는 `u` 의
  목록과 `v` 의 목록에 한 번씩, 모두 두 번 들어가요. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **깊이 우선 탐색.** 한 갈래를 갈 수 있는 데까지 따라간 다음 되돌아 나오는 순회입니다. 이 글은 스택으로 드는
  순회에 표시와 부모를 덧붙인 것이라, 순회 자체가 흐릿하면 뒤가 어긋나요. 모르면
  [`dfsTraversal` 가이드](../dfsTraversal/dfsTraversal-guide.md)를 보세요.
- **연결 성분과 시작 정점 건너뛰기.** 정점 번호 순서로 시작 정점을 보면서, 앞 탐색이 이미 표시해 둔 정점은
  건너뛰는 바깥 반복입니다. 그래프는 여러 연결 성분으로 나뉠 수 있고, 이 글은 **어느 연결 성분에라도** 사이클이
  있으면 `true` 예요. 모르면 [`connectedComponents` 가이드](../connectedComponents/connectedComponents-guide.md)를 보세요.
- **스택이 나중에 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기와 꺼내기가 각각 `O(1)` 입니다. 모르면
  [`stack` 가이드](../../../data-structures/linear/stack/stack-guide.mdx)를 보세요.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점이 표시됐는가」를 배열 한 칸 읽기로 답합니다.

첫째와 셋째가 흐릿하면 뒤가 어긋납니다. 무향 간선이 목록 둘에 들어간다는 것과, 그래서 이웃 목록의 길이를 모두
더하면 `2E` 가 된다는 것이 이 글의 계산에 계속 나와요. 이름이 비슷한 과제와 나란히 놓으면 이 글의 범위가 갈립니다.

| 과제 | 그래프 | 이 글에서 |
| --- | --- | --- |
| 사이클이 하나라도 있는지 판정한다 | 무향 | 다룬다 |
| 사이클이 하나라도 있는지 판정한다 | 방향 | 다루지 않는다 — [`directedCycleDetection`](../directedCycleDetection/directedCycleDetection-guide.md) |
| 서로 오갈 수 있는 정점의 무리를 찾는다 | 무향 | 다루지 않는다 — [`connectedComponents`](../connectedComponents/connectedComponents-guide.md) |
| 정점을 두 쪽으로 나눠 모든 간선이 두 쪽을 가르게 할 수 있는가 | 무향 | 다루지 않는다 — [`isBipartite`](../../graph-flow/isBipartite/isBipartite-guide.md) |

### 아이디어를 떠올리는 과정 — 간선을 하나씩 지워 보기에서 부모 건너뛰기 탐색까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아서, 사이클이
있는지를 돌려줍니다.

```ts
function undirectedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean;
```

- 입력: 정점 수 `n`, 무향 간선 목록 `edges`. 정점 번호는 0 부터 `n − 1` 까지예요. 자기 자신을 잇는 간선
  `[v, v]` 와 같은 쌍을 여러 번 잇는 간선이 들어올 수 있고, 그래프가 여러 연결 성분으로 나뉘어 있을 수 있습니다.
- 출력: 어느 연결 성분에라도 사이클이 하나 있으면 `true`, 전체에 하나도 없으면 `false`. 사이클을 이루는 정점을
  적어 내는 것이 아니라 있는지만 답하므로, 사이클 하나를 확인하는 순간 남은 간선을 안 봐도 됩니다.
- 규모: 정점 100,000 개 이하, 간선 100,000 개 이하. 비용은 흔한 채점 환경의 예산인 1 초 · 256 MB 에 대어 잽니다.

이 글이 쓰는 기호는 여덟 개입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` 입니다 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 100,000` |
| `k` | 연결 성분의 수 | `1 ≤ k ≤ V` |
| `u` · `v` | 정점 번호. 이웃을 보는 자리에서는 `u` 가 꺼낸 정점, `v` 가 그 이웃입니다 | `0` 부터 `V − 1` |
| `nbr[u]` | 정점 `u` 의 이웃 번호를 담은 목록 | 길이를 모두 더하면 `2E` |
| `visited[v]` | 정점 `v` 를 표시했는가 | 처음에는 전부 거짓 |
| `stack` | 표시했지만 아직 이웃을 확인하지 않은 정점들 | 뒤에 넣고 뒤에서 꺼낸다 |
| `from` | `stack` 과 같은 자리끼리 짝지은 배열. 그 정점의 부모를 담는다 | 시작 정점에는 `-1` |

가장 먼저 떠오르는 방법은 사이클의 정의를 그대로 옮기는 것입니다. 사이클이 있다는 것은 **어떤 두 정점 사이에
길이 둘 이상 있다**는 뜻이니, 간선을 하나씩 지워 보고 그 간선의 두 끝이 **아직 이어져 있는지** 확인하면 돼요.
이어져 있으면 그 간선 말고 다른 길이 있다는 것이고, 그 길과 지운 간선을 이으면 사이클입니다.

```ts
// 간선 하나를 지우고 두 끝이 아직 이어져 있는지 확인한다.
for (let removed = 0; removed < edges.length; removed++) {
  const [u, v] = edges[removed];
  // removed 번 간선만 빼고 u 에서 갈 수 있는 곳을 전부 표시한다
  const seen = reachableWithout(u, removed);
  if (seen[v]) return true; // 지운 간선 없이도 v 까지 간다 — 사이클이다
}
return false;
```

이 방법은 답이 맞습니다. 비용은 **이웃 목록에서 읽은 이웃 수**로 셉니다. 목록을 한 번 만드는 비용은 어느
방식이든 같아서 세지 않았어요. 정점을 한 줄로 이은 그래프에서 정점을 늘려 가며 세어 봅시다.

<!--proof:naive-scale-->

| 입력 | 정점 V | 간선 E | 읽은 이웃 수 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 6 | 5 | 10 |
| 한 줄로 이은 10 정점 | 10 | 9 | 81 |
| 한 줄로 이은 100 정점 | 100 | 99 | 9,801 |
| 한 줄로 이은 1,000 정점 | 1,000 | 999 | 998,001 |
| 한 줄로 이은 2,000 정점 | 2,000 | 1,999 | 3,996,001 |

한 줄 입력 4 줄은 읽은 이웃 수가 모두 E × E 와 같습니다. 규모 상한의 한 줄(간선 99,999 개)을 그 식에 넣으면 9,999,800,001 입니다.

<!--/proof-->

간선이 999 개인 한 줄에서 이미 백만 번 가까이 읽고, 규모 상한에서는 100 억 번입니다. 1 초 안에 끝나는 규모가
아니에요. 간선 하나마다 그래프를 처음부터 다시 순회하기 때문인데, 그 다시 순회하는 일이 무엇을 되풀이하는지 한 줄로
이은 네 정점에서 간선마다 따라가 봅시다.

<!--proof:naive-repeat-->

| 지운 간선 | 출발한 끝 | 갈 수 있는 정점 | 다른 끝 | 읽은 이웃 수 |
| --- | --- | --- | --- | ---: |
| [0,1] | 0 | [0] | 1 에 못 이른다 | 1 |
| [1,2] | 1 | [0, 1] | 2 에 못 이른다 | 3 |
| [2,3] | 2 | [0, 1, 2] | 3 에 못 이른다 | 5 |

뒤 줄이 갈 수 있는 정점은 앞 줄이 갈 수 있는 정점을 모두 품고 있습니다. 읽은 이웃 수는 모두 합해 9 이고, 정본의 답은 false 입니다.

<!--/proof-->

지운 간선이 뒤로 갈수록 출발한 끝에서 갈 수 있는 정점이 늘어나는데, 늘어난 쪽이 앞 줄에서 이미 읽은 자리를
그대로 품고 있습니다. **같은 연결 관계를 간선마다 다시 확인한 것**이에요. 그렇다면 표시를 한 벌만 두고 그래프를
**한 번만** 순회하면 됩니다. 판정은 아직 정하지 않고, 한 번 순회하는 비용만 먼저 같은 입력에서 세어 봅시다.

<!--proof:mark-values-->

| 입력 | E | 간선 지워 보기 | 한 번 순회 | 2E | 정본의 답 |
| --- | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 5 | 10 | 10 | 10 | true |
| 한 줄로 이은 10 정점 | 9 | 81 | 18 | 18 | false |
| 별 모양 1,000 정점 | 999 | 1,995,003 | 1,998 | 1,998 | false |
| 한 줄로 이은 1,000 정점 | 999 | 998,001 | 1,998 | 1,998 | false |
| 고리 1,000 정점 | 1,000 | 2,000 | 2,000 | 2,000 | true |

5 줄 모두 한 번 순회할 때 읽은 이웃 수가 2E 와 같습니다. 한 줄로 이은 1,000 정점에서는 998,001 과 1,998 로 499.5 배 차이입니다.

<!--/proof-->

한 번 순회는 이웃 항목 하나를 한 번씩만 읽어서 `2E` 로 정해지고, 간선을 지워 보는 쪽은 `E × E` 를 따라갑니다.
고리 1,000 정점에서 두 값이 같은 것은 지워 보는 쪽이 첫 간선에서 사이클을 찾고 끝났기 때문이에요. 갈리는 것은
**사이클이 없어 끝까지 확인해야 할 때**입니다. 여기서 관찰한 것은 하나예요. **비용은 같은 부분을 몇 번 다시
읽는가가 정하고, 표시를 한 벌 두면 그것이 한 번으로 줄어듭니다.**

그러면 한 번 순회하는 동안 **무엇을 만나면 사이클인가**를 정해야 합니다. 가장 단순한 후보부터 시험해 봅시다.
이미 표시된 정점을 다시 만났다면 그리로 가는 길이 이미 하나 있다는 뜻이니, 그 순간 사이클이라고 답하는 거예요.
간선 하나짜리 그래프 `[[0,1]]` 에서 이 후보가 하는 일을 걸음마다 적었습니다.

<!--proof:first-candidate-->

| 걸음 | 꺼낸 정점 | 이웃 | 그 이웃의 표시 | 한 일 |
| --- | --- | --- | --- | --- |
| T1 | — | — | — | 정점 0 을 표시하고 넣는다 |
| T2 | 0 | 1 | 없다 | 1 을 표시하고 넣는다 |
| T3 | 1 | 0 | 있다 | 사이클이라고 답한다 |

이 후보의 답은 true 입니다. 간선이 하나뿐이라 사이클이 없고, 정본의 답은 false 입니다.

<!--/proof-->

T3 에서 틀립니다. 정점 1 의 이웃 목록에는 방금 지나온 0 이 들어 있어요. 무향 간선은 양쪽 목록에 다 들어 있기
때문입니다. 그러니 **무엇을 건너뛸 것인가**가 이 절차의 갈림점입니다. 후보는 셋이에요 — 아무것도 건너뛰지
않거나, 표시된 이웃을 전부 건너뛰거나, 그 정점을 표시하게 한 이웃 하나만 건너뛰거나. 셋째의 그 이웃을 앞으로
**부모**라고 부르겠습니다. 여섯 입력에 셋을 실행했습니다.

<!--proof:skip-choice-->

| 입력 | 아무것도 안 건너뛰기 | 표시된 이웃 전부 건너뛰기 | 부모 하나만 건너뛰기 | 옳은 답 |
| --- | --- | --- | --- | --- |
| 전개 입력 | true | false | true | true |
| 한 줄로 이은 네 정점 | true | false | false | false |
| 별 모양 네 정점 | true | false | false | false |
| 삼각형 | true | false | true | true |
| 같은 쌍을 두 번 이은 간선 | true | false | true | true |
| 자기 자신을 잇는 간선 | true | false | true | true |

옳은 답은 유니온 파인드로 따로 낸 값입니다. 입력 6 개 가운데 옳은 답과 다른 줄은 아무것도 안 건너뛰는 후보가 2 개, 표시된 이웃을 전부 건너뛰는 후보가 4 개, 부모 하나만 건너뛰는 후보가 0 개입니다.

<!--/proof-->

첫째 후보는 사이클이 없는 그래프에 `true` 를 답하고, 둘째 후보는 사이클이 있는 그래프에 `false` 를 답합니다.
첫째는 방금 지나온 간선을 거꾸로 지난 것을 사이클로 세는 것이고, 둘째는 그 간선을 빼려다 **사이클을 닫는 간선까지 함께**
건너뛰는 거예요. 부모 하나만 건너뛰는 셋째만 여섯 입력 모두에서 옳은 답과 같습니다. 지금까지 해 본 방법을
차례로 놓으면 이렇습니다. 앞 방법이 막힌 자리에서 다음 방법이 나왔어요.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **부모 건너뛰기 탐색**입니다. 정점마다 표시와 부모를 두고, 꺼낸 정점의 이웃을 확인할 때 부모는
건너뛰며, 부모가 아닌데 표시된 이웃이 나오면 `true` 를 돌려줘요. 부모를 어떻게 기억하는지, 표시를 언제 해야
정점이 스택에 두 번 들어가지 않는지, 왜 부모가 아닌 표시된 이웃이 곧 사이클인지는 다음 절에서 실현하는
순서대로 확인합니다.

> 건너뛰는 것은 그 정점을 표시하게 한 이웃 하나뿐이다. 나머지 표시된 이웃은 사이클이다.

### 아이디어 상세 — 부모 건너뛰기 탐색

이 아이디어를 한 문장으로 줄이면 이렇습니다. **정점 번호 순서로 표시 없는 정점을 찾아 표시하고, 스택에서
정점을 꺼낼 때마다 짝지어 꺼낸 부모는 건너뛰고, 나머지 이웃 중 표시 없는 것은 표시하고 부모를 적어 스택에
넣으며, 표시된 것이 나오면 `true` 를 돌려줍니다.** 이 방법이 만드는 「탐색 트리」는 처음 보는 사람에게 낯설 수
있어서 먼저 따로 설명하고, 그다음 실현하는 순서대로 다섯 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서
쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 이웃 목록 만들기 | 간선 하나를 두 목록에 넣는다 | — |
| 시작 후보마다 | 2단계 표시 없는 정점에서 시작하기 | `visited[s]` 가 거짓이면 표시하고 `from` 에 `-1` 과 함께 스택에 넣는다 | 1단계 뒤 거짓으로 채운 `visited` |
| 꺼낸 정점의 이웃마다 | 3단계 처음 보는 이웃을 표시해 넣기 | 표시 없는 이웃을 표시하고 부모를 `from` 에 적어 넣는다 | 1단계의 `nbr` · 2단계의 스택 |
| 꺼낸 정점의 이웃마다 | 4단계 부모 건너뛰기 | 이웃이 짝지어 꺼낸 부모이면 넘어간다 | 3단계가 적은 `from` |
| 꺼낸 정점의 이웃마다 | 5단계 표시된 이웃에서 끝내기 | 부모가 아닌데 표시된 이웃이면 `true` 를 돌려준다 | 3단계가 한 표시 · 4단계의 건너뛰기 |

#### 먼저 알아 둘 개념 — 탐색 트리

탐색 트리는 **표시된 정점들과, 정점마다 자기를 처음 표시하게 한 이웃(부모)과 잇는 간선을 모은 것**입니다. 시작
정점은 부모가 없고, 나머지 표시된 정점은 부모가 꼭 하나예요. 부모와 잇는 간선을 **나무 간선**이라고 부르고,
나무 간선이 아닌 간선을 **나무 밖 간선**이라고 부릅니다. 코드에서 부모는 `from` 배열에 담겨 스택과 함께 움직여요.

##### 입력 위의 탐색 트리

전개 입력에서 정점 여섯이 모두 표시된 순간을 골랐습니다. 점선 테 하나가 탐색 트리 하나이고, 정점 안의 값이
부모예요. 굵은 실선이 나무 간선, 흐린 선이 아직 확인하지 않은 간선입니다.

<!--fig:build-tree-->
![T8 직후 — 탐색 트리 둘, 스택 [4, 5]](./figs/build-tree.svg)

연결 성분이 둘이라 탐색 트리도 둘입니다. 정점 0 에서 시작한 트리는 한 줄 `0 − 1 − 2` 이고, 정점 3 에서 시작한
트리는 3 에서 4 와 5 로 두 갈래를 뻗었어요. 간선 `[4,5]` 는 아직 아무도 확인하지 않아서 흐린 선으로 남아 있습니다.

##### 정점 하나를 읽는 법

같은 순간의 정점을 하나씩 읽습니다. 언제 표시됐는지, 부모가 누구인지, 부모와 잇는 나무 간선이 무엇인지, 이웃
확인을 마쳤는지까지 따라가요.

<!--proof:tree-read-->

| 정점 | 표시한 걸음 | 부모 | 부모와 잇는 나무 간선 | 꺼냈는가 |
| --- | --- | --- | --- | --- |
| 0 | T1 | 없음 | — | 꺼냈다 |
| 1 | T2 | 0 | [0,1] | 꺼냈다 |
| 2 | T4 | 1 | [1,2] | 꺼냈다 |
| 3 | T6 | 없음 | — | 꺼냈다 |
| 4 | T7 | 3 | [3,4] | 스택에 있다 |
| 5 | T8 | 3 | [5,3] | 스택에 있다 |

T8 직후 스택은 [4, 5], from 은 [3, 3] 입니다.

<!--/proof-->

정점 5 를 골라 읽어 보겠습니다. T8 에 표시됐고 부모는 3 이에요. 3 의 이웃 목록을 확인하다가 5 를 처음 만났다는
뜻이고, 그때 쓴 간선 `[5,3]` 이 나무 간선입니다. 5 는 아직 스택에 있으니 이웃을 확인하지 않았어요. 스택에서 5 를
꺼낼 때 `from` 에서 함께 꺼내는 값이 바로 이 부모 3 입니다.

##### 정점끼리의 관계

탐색 트리의 정점은 아무렇게나 놓이지 않습니다. 정점 하나가 표시될 때마다 나무 간선이 하나씩 늘고, 시작 정점만
나무 간선 없이 표시돼요. 그래서 나무 간선 수는 늘 「표시된 정점 수 − 시작한 횟수」이고, 나무 간선만 따라가면
제자리로 돌아오는 길이 없습니다. 전개 입력의 걸음마다 네 관계를 쟀습니다.

<!--proof:tree-relation-->

| 관계 | 확인한 걸음 | 어긋난 걸음 |
| --- | ---: | ---: |
| 나무 간선 수 = 표시된 정점 수 − 시작한 횟수 | 9 | 0 |
| 시작 정점이 아닌 표시된 정점은 부모가 하나 있고, 그 부모도 표시돼 있다 | 9 | 0 |
| 나무 간선만 따라가면 사이클이 없다 | 9 | 0 |
| stack 과 from 의 길이가 같다 | 9 | 0 |

T1 부터 T9 까지 9 걸음마다 관계 4 개를 쟀고, 어긋난 자리는 0 개입니다.

<!--/proof-->

셋째 관계가 이 글의 요점입니다. 나무 간선만으로는 사이클이 생기지 않으니, 사이클이 있다면 **나무 간선이 아닌
간선**이 그것을 닫아야 해요. 그리고 나무 간선이 아닌 간선의 두 끝은 둘 다 탐색 트리 안에 있어서, 나무 간선만
따라서도 서로 오갈 수 있습니다. 그 간선 하나를 더하면 길이 둘이 되는 거예요.

##### 스택과의 차이

탐색 트리를 처음 보면 **스택에 든 정점들이 곧 지금 따라가는 길**이라고 읽기 쉽습니다. 방향 그래프의 사이클
탐지에서는 스택을 아래에서 위로 읽으면 지금 경로가 되니까요. 이 글의 스택은 다릅니다. 전개의 걸음마다 스택과
스택에 든 정점의 부모를 나란히 놓았습니다.

<!--proof:tree-vs-stack-->

| 걸음 | 스택 | 스택에 든 정점의 부모 | 부모와 함께 스택에 든 정점 |
| --- | --- | --- | --- |
| T1 | [0] | [없음] | 없다 |
| T2 | [1] | [0] | 없다 |
| T4 | [2] | [1] | 없다 |
| T6 | [3] | [없음] | 없다 |
| T7 | [4] | [3] | 없다 |
| T8 | [4, 5] | [3, 3] | 없다 |
| T9 | [4] | [3] | 없다 |

스택이 비지 않은 걸음 7 개 가운데 부모와 자식이 스택에 함께 든 걸음은 0 개입니다.

<!--/proof-->

부모와 자식이 스택에 함께 든 걸음이 한 번도 없습니다. 이 절차는 정점을 **꺼낸 다음에** 그 이웃을 표시해 넣으니,
자식이 스택에 들어갈 때 부모는 이미 스택을 떠나 있어요. T8 의 스택 `[4, 5]` 도 경로가 아니라 **3 의 두 자식이
확인을 기다리는 줄**입니다. 그래서 「지금 경로」를 스택에서 읽지 않고, 정점마다 부모를 따로 기억해 둡니다.

##### 이렇게 생긴 까닭

사이클을 판정하려면 「이 이웃이 방금 지나온 간선의 반대쪽 끝인가」를 알아야 하고, 한 번만 순회하려면 「이 정점을
전에 본 적이 있는가」를 알아야 합니다. 거기에 「아직 이웃을 확인하지 않은 정점이 남았는가」가 있어야 끝을 낼 수
있어요. 세 물음이 서로 다른 칸을 요구하니 배열도 셋입니다.

| 물음 | 답하는 칸 | 없으면 |
| --- | --- | --- |
| 이 정점을 처음 보는가 | `visited` | 같은 연결 관계를 여러 번 순회한다 |
| 이 이웃이 방금 지나온 간선의 반대쪽 끝인가 | `from` 에서 꺼낸 부모 | 되돌아가기를 사이클로 읽는다 |
| 이웃을 확인할 정점이 남았는가 | `stack` | 표시한 정점의 이웃을 확인하지 못한다 |

#### 1단계 — 이웃 목록 만들기

간선 목록을 그대로 두고 「정점 3 과 이어진 정점」을 물으면 목록 전체를 다시 읽어야 합니다. 게다가 `[5,3]` 처럼
3 이 뒤에 적힌 간선도 있어서 두 자리를 다 봐야 해요. 간선을 한 번 읽으면서 양 끝의 목록에 한 번씩 넣어 두면 두
가지가 함께 없어집니다. 전개 입력에서 만든 이웃 목록이에요.

<!--proof:build-lists-->

| 정점 u | nbr[u] | 길이 |
| ---: | --- | ---: |
| 0 | [1] | 1 |
| 1 | [0, 2] | 2 |
| 2 | [1] | 1 |
| 3 | [4, 5] | 2 |
| 4 | [3, 5] | 2 |
| 5 | [4, 3] | 2 |

길이를 모두 더하면 10 이고, 간선 5 개의 두 배입니다.

<!--/proof-->

간선 목록에 적힌 차례가 그대로 목록 안의 차례가 됩니다. `nbr[5]` 가 `[4, 3]` 인 것은 `[4,5]` 가 `[5,3]` 보다 먼저
적혀 있어서예요. 이 차례가 뒤에서 어느 이웃을 먼저 확인하는지를 정합니다. 같은 단계에서 `visited` 를 길이 `V`
로 만들어 전부 거짓으로 채우고, `stack` 과 `from` 은 빈 배열로 둡니다.

#### 2단계 — 표시 없는 정점에서 시작하기

바깥 반복이 정점 번호 순서로 시작 후보 `s` 를 봅니다. `visited[s]` 가 거짓이면 새 연결 성분의 첫 정점이라,
표시하고 스택에 넣고 `from` 에는 부모가 없다는 뜻으로 `-1` 을 넣어요. 정점 번호가 0 부터라 `-1` 은 어느 정점과도
같지 않습니다. 전개 입력에서 바깥 반복이 본 시작 후보예요.

<!--proof:build-starts-->

| 시작 후보 s | 그때의 visited[s] | 한 일 | 걸음 |
| ---: | --- | --- | --- |
| 0 | 거짓 | 표시하고 스택에 넣는다 | T1 |
| 1 | 참 | 넘어간다 | — |
| 2 | 참 | 넘어간다 | — |
| 3 | 거짓 | 표시하고 스택에 넣는다 | T6 |

바깥 반복은 정점 4 개를 본 뒤 멈췄고, 그중 시작한 것은 2 번입니다. 정점 4 부터 5 까지는 그 전에 답이 나와 보지 않았습니다.

<!--/proof-->

정점 1 · 2 는 정점 0 에서 시작한 탐색이 이미 표시해서 넘어갔고, 정점 3 은 표시가 없어 두 번째 연결 성분을
시작했습니다. 시작 후보를 정점 4 · 5 까지 보지 않은 것은 5단계에서 답이 먼저 나왔기 때문이에요.

#### 3단계 — 처음 보는 이웃을 표시해 넣기

스택에서 정점 `u` 와 짝지은 부모를 함께 꺼내고, `nbr[u]` 의 이웃 `v` 를 차례로 확인합니다. `v` 에 표시가 없으면
처음 만난 정점이라 표시하고 스택에 넣고, `from` 에는 `u` 를 적어요. 이 순간 `u` 가 `v` 의 부모가 되고, 둘을 잇는
간선이 나무 간선이 됩니다. 전개 입력에서 이 갈래가 실행된 걸음을 모았습니다. 걸음 번호 `T#` 는 「수행으로
알아보는 알고리즘」의 걸음과 같아요.

<!--proof:build-mark-->

| 걸음 | 꺼낸 정점 | 이웃 | 그 이웃의 표시 | 넣은 뒤 stack | 넣은 뒤 from |
| --- | --- | --- | --- | --- | --- |
| T2 | 0 | 1 | 없다 | [1] | [0] |
| T4 | 1 | 2 | 없다 | [2] | [1] |
| T7 | 3 | 4 | 없다 | [4] | [3] |
| T8 | 3 | 5 | 없다 | [4, 5] | [3, 3] |

③ 은 4 번 실행됐고, 매번 from 맨 뒤에 넣은 값이 그 걸음에 꺼낸 정점과 같습니다.

<!--/proof-->

표시와 스택에 넣기를 **같은 자리에서** 합니다. 그래서 스택에 든 정점은 모두 표시돼 있고, 표시된 정점은 스택에
다시 들어가지 않아요. 크기도 여기서 정해집니다. 정점 하나가 스택에 한 번 들어가고 한 번 나오며, 꺼낼 때 그
정점의 이웃 목록을 한 번 끝까지 읽으니, 사이클이 없으면 이웃 항목을 확인한 수가 목록 길이의 합과 같아야 합니다.
모양이 다른 입력 다섯으로 확인했어요.

<!--proof:edge-scan-values-->

| 입력 | V | E | 확인한 이웃 항목 | 2E | 스택에 넣은 횟수 | 정본의 답 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 한 줄로 이은 10 정점 | 10 | 9 | 18 | 18 | 10 | false |
| 별 모양 10 정점 | 10 | 9 | 18 | 18 | 10 | false |
| 정점 10 개를 둘씩 짝지은 숲 | 10 | 5 | 10 | 10 | 10 | false |
| 한 줄로 이은 1,000 정점 | 1,000 | 999 | 1,998 | 1,998 | 1,000 | false |
| 별 모양 1,000 정점 | 1,000 | 999 | 1,998 | 1,998 | 1,000 | false |

사이클이 없는 입력 5 개 모두 확인한 이웃 항목이 2E 와, 스택에 넣은 횟수가 V 와 같습니다.

<!--/proof-->

한 줄이든 별 모양이든 여러 연결 성분으로 나뉜 숲이든, 사이클이 없으면 이웃 항목 확인이 `2E`, 스택에 넣기가 `V`
로 정확히 맞습니다. 빠뜨리는 이웃이 없다는 근거는 안쪽 반복의 종료 조건에 있어요. 표시된 정점은 모두 스택에
들어갔고 스택이 빌 때까지 꺼내므로, 스택이 빈 순간 그 연결 성분의 이웃 목록은 모두 끝까지 읽혔습니다.

#### 4단계 — 부모 건너뛰기

3단계에서 `u` 를 표시하게 한 부모 `p` 는 `u` 의 이웃 목록에도 들어 있습니다. 간선 `[p, u]` 가 두 목록에 다
들어가기 때문이에요. 그 항목은 방금 지나온 나무 간선을 반대쪽 끝에서 읽은 것일 뿐이라, 이웃이 짝지어 꺼낸
부모와 같으면 건너뜁니다. 전개 입력에서 건너뛴 걸음이에요.

<!--proof:build-skip-->

| 걸음 | 꺼낸 정점 | 부모 | 이웃 | 그 항목의 간선 | 그 간선이 나무 간선이 된 걸음 |
| --- | --- | --- | --- | --- | --- |
| T3 | 1 | 0 | 0 | [0,1] | T2 |
| T5 | 2 | 1 | 1 | [1,2] | T4 |

건너뛴 2 번 모두 꺼낸 정점을 표시할 때 쓴 나무 간선을 반대쪽 끝에서 읽은 것입니다.

<!--/proof-->

T3 과 T5 둘 다, 그 정점이 표시될 때 쓴 간선을 반대쪽에서 다시 읽은 자리입니다. 정점 1 은 T2 에 간선 `[0,1]` 로
표시됐고, T3 에 자기 목록에서 0 을 만났어요. 이 건너뛰기가 없으면 T3 에서 0 이 표시돼 있다는 이유로 사이클이라고
답합니다. 「아이디어를 떠올리는 과정」의 첫 후보가 틀린 자리가 바로 여기예요.

#### 5단계 — 표시된 이웃에서 끝내기

이웃이 부모가 아닌데 이미 표시돼 있으면 `true` 를 돌려줍니다. 쉬운 경우는 전개 입력의 T9 이고, 불안한 경우는
**아직 꺼내지도 않은 정점을 다른 이웃에서 다시 만나는 자리**예요. 사각형 `[0,1] · [1,2] · [2,3] · [3,0]` 이 그
모양입니다. 걸음마다 상태를 전부 적었어요.

<!--proof:build-square-->

| 걸음 | 한 일 | visited | stack | from |
| --- | --- | --- | --- | --- |
| T1 | 정점 0 에서 시작 | 0:✓ 1:· 2:· 3:· | [0] | [-1] |
| T2 | 0 의 이웃 1 · ③ 표시하고 넣는다 | 0:✓ 1:✓ 2:· 3:· | [1] | [0] |
| T3 | 0 의 이웃 3 · ③ 표시하고 넣는다 | 0:✓ 1:✓ 2:· 3:✓ | [1, 3] | [0, 0] |
| T4 | 3 의 이웃 2 · ③ 표시하고 넣는다 | 0:✓ 1:✓ 2:✓ 3:✓ | [1, 2] | [0, 3] |
| T5 | 3 의 이웃 0 · ① 부모라 건너뛴다 | 0:✓ 1:✓ 2:✓ 3:✓ | [1, 2] | [0, 3] |
| T6 | 2 의 이웃 1 · ② 사이클이다 | 0:✓ 1:✓ 2:✓ 3:✓ | [1] | [0] |

T6 에서 정점 1 은 스택 [1] 에 든 채 아직 꺼내지 않았지만 T2 에 표시돼 있어, 정점 2 가 그 표시를 읽고 true 를 돌려줍니다.

<!--/proof-->

정점 1 은 T2 에 0 이 표시해 스택 맨 아래에 넣었고, 이웃을 한 번도 확인하지 않았습니다. 그래도 표시는 돼 있어서
T6 의 판정이 그 표시를 그대로 씁니다. 「확인을 마쳤는가」가 아니라 「표시했는가」가 기준이라 이렇게 동작해요.
그때 두 길 `0 − 1` 과 `0 − 3 − 2` 가 정점 0 에서 만나고, 간선 `[1,2]` 가 두 끝을 이어 제자리로 돌아옵니다.

표시된 이웃이 왜 사이클인지는 부모를 따라 올라가 보면 값으로 나옵니다. 전개 입력의 T9 에서 확인한 두 정점에서
각각 부모를 따라 올라갔습니다.

<!--proof:build-close-->

```text
T9 에 확인한 이웃 항목       5 의 목록에서 4 — 간선 [4,5]
5 에서 부모를 따라 오른 길   5 → 3
4 에서 부모를 따라 오른 길   4 → 3
두 길이 만나는 정점          3
이어 붙인 닫힌 길            5 → 3 → 4 → 5
같은 간선을 두 번 썼는가     아니다 — 사이클이다
```

두 정점이 같은 탐색 트리에 있으니, 부모를 따라 올라가면 반드시 한 정점에서 만납니다. 그 두 길과 지금 확인한 간선
하나를 이으면 닫힌 길이 되고, 확인한 간선은 부모와 잇는 간선이 아니라서 나무 간선 쪽 길과 겹치지 않아요. 그래서
같은 간선을 두 번 쓰지 않는 사이클입니다.

#### 이 방법이 기대는 전제

부모 건너뛰기 탐색은 **간선 하나가 두 목록에 다 들어 있다**는 전제에 기댑니다. 간선에 방향이 없다는 것을 코드가
지키는 자리가 그것이에요. 한쪽 목록에만 넣으면 적힌 앞 끝에서만 걸어갈 수 있게 되어, 같은 그래프라도 간선을
적은 순서에 따라 답이 달라집니다. `(nbr[v] as number[]).push(u);` 한 줄을 지운 사본과 정본을 나란히 실행했습니다.

<!--proof:mutant-one-sided-->

| 입력 | 두 목록에 넣기 (정본) | 한쪽 목록에만 넣기 | 두 답 |
| --- | --- | --- | --- |
| 전개 입력 | true | true | 같다 |
| 같은 쌍을 [0,1] 과 [1,0] 으로 적은 것 | true | false | 어긋난다 |
| 이어지지 않은 두 간선 [0,1] · [2,0] | false | true | 어긋난다 |
| 이어지지 않은 두 간선 [0,1] · [2,1] | false | true | 어긋난다 |
| 한 줄로 이은 네 정점 | false | false | 같다 |

<!--/proof-->

둘째 줄에서 사이클을 놓치고, 셋째 · 넷째 줄에서는 없는 사이클을 만들어 냅니다. 전개 입력을 포함한 두 줄에서는
답이 같아서, 그런 입력만 시험하면 한쪽에만 넣어 놓고도 통과해요. 셋째 줄에서 무슨 일이 일어나는지 따라가면
이렇습니다.

<!--proof:one-sided-trace-->

```text
한쪽 목록에만 넣으면   nbr[0] = [1]   nbr[1] = []   nbr[2] = [0]
정점 0 에서 시작       0 을 꺼내 이웃 1 을 표시한다
정점 1                 이미 표시돼 있어 바깥 반복이 넘어간다
정점 2 에서 시작       이웃 0 은 부모가 아니고 표시돼 있다 → true
정본의 답              false
```

정점 2 는 0 과 이어져 있는데, 0 의 목록에 2 가 없어서 0 에서 시작한 탐색이 2 를 만나지 못했습니다. 그래서 2 가
새 연결 성분처럼 다시 시작하고, 이웃 0 을 「다른 길로 이미 표시된 정점」으로 읽어요. 간선에 방향이 없다는 것은
**적은 순서에 뜻이 없다**는 말이고, 목록 둘에 넣는 것이 그것을 지키는 자리입니다. 반대로 간선에 정말 방향이
있는 그래프라면 부모를 건너뛸 까닭부터 없어지고, 그 판정은
[`directedCycleDetection` 가이드](../directedCycleDetection/directedCycleDetection-guide.md)가 다룹니다.

#### 표시를 스택에 넣을 때 하는 까닭

표시는 정점을 스택에 **넣을 때** 할 수도 있고 **꺼낼 때** 할 수도 있습니다. 꺼낼 때 표시하면 정점이 스택 안에서
기다리는 동안 표시가 없는 채라, 다른 이웃이 그 정점을 처음 보는 정점으로 읽고 한 번 더 넣어요. 두 판을 여섯
입력에 실행해 넣은 횟수를 세었습니다.

<!--proof:mark-when-->

| 입력 | V | 넣을 때 표시 — 넣은 횟수 | 꺼낼 때 표시 — 넣은 횟수 | 넣을 때 표시 — 답 | 꺼낼 때 표시 — 답 |
| --- | ---: | ---: | ---: | --- | --- |
| 전개 입력 | 6 | 6 | 7 | true | true |
| 사각형 | 4 | 4 | 5 | true | true |
| 삼각형 | 3 | 3 | 4 | true | true |
| 정점 넷을 모두 이은 것 | 4 | 4 | 6 | true | true |
| 한 줄로 이은 네 정점 | 4 | 4 | 4 | false | false |
| 별 모양 네 정점 | 4 | 4 | 4 | false | false |

답이 갈린 입력은 0 개입니다. 넣은 횟수가 V 를 넘은 입력은 넣을 때 표시하는 판에서 0 개, 꺼낼 때 표시하는 판에서 4 개입니다.

<!--/proof-->

답은 두 판이 같지만, 넣을 때 표시하는 판만 넣은 횟수가 언제나 `V` 이하입니다. 사각형에서 꺼낼 때 표시하는 판은
스택 안에서 기다리던 정점을 다른 이웃이 한 번 더 넣어서 넣은 횟수가 `V` 를 넘어요. 「정점 하나가 스택에 한 번 들어가고 한 번 나온다」가 여기서 서고,
3단계의 `2E` 와 비용 계산이 그 사실에 기댑니다. 그래서 부모 건너뛰기 탐색은 `visited[v] = true` 와
`stack.push(v)` 를 같은 자리에 둡니다.

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 순서로 다시 적으면 이렇습니다. 셋째부터 다섯째까지가 스택에서 정점 하나를 꺼낸 한 바퀴예요.
간선마다 그래프를 다시 순회하던 일이 이웃 항목 `2E` 개를 한 번씩 보는 일로 줄어듭니다.

1. 간선마다 `nbr[u]` 에 `v` 를, `nbr[v]` 에 `u` 를 넣고, `visited` 를 전부 거짓으로 둔다
2. 시작 후보 `s` 를 0 부터 `V − 1` 까지 보며, `visited[s]` 가 거짓이면 표시하고 `stack` 에, `-1` 을 `from` 에 넣는다
3. 스택이 빌 때까지 정점 `u` 와 부모 `parent` 를 함께 꺼내 `nbr[u]` 의 이웃 `v` 를 차례로 본다
4. `v` 가 `parent` 와 같으면 건너뛰고, `v` 가 표시돼 있으면 `true` 를 돌려주고, 아니면 표시하고 `v` 를 `stack` 에, `u` 를 `from` 에 넣는다
5. 바깥 반복이 끝날 때까지 표시된 이웃을 만나지 못하면 `false` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 여섯 정점의 이웃 항목 일곱 개를 확인한다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 6;
const edges: [number, number][] = [[0, 1], [1, 2], [3, 4], [4, 5], [5, 3]];
// 이 절이 끝나면 true 가 나와야 한다
```

이 입력을 고른 까닭은 **세 갈래와 바깥 반복의 다시 시작하기가 한 입력에서 모두 실행되기 때문**입니다. 정점 0 ·
1 · 2 는 한 줄이라 사이클이 없고, 거기서 스택이 한 번 비어 바깥 반복이 정점 3 을 새로 잡아요. 3 · 4 · 5 는
삼각형이라 마지막에 표시된 이웃을 만나 `true` 가 됩니다. 절차 전체를 한 장으로 적으면 이렇습니다.

```text
undirectedCycleDetection(n, edges):
    간선 [u, v] 마다 nbr[u] 에 v 를, nbr[v] 에 u 를 넣는다
    visited 를 전부 거짓으로 둔다
    정점 s 를 0 부터 n-1 까지 보면서:
        s 가 표시돼 있으면 넘어간다
        s 를 표시하고 stack 에 넣는다. 짝지은 from 에는 -1 을 넣는다
        stack 이 비지 않은 동안:
            u ← stack 에서 꺼낸 정점, parent ← 짝지은 from 값
            nbr[u] 의 이웃 v 를 차례로:
                v 가 parent 와 같으면 건너뛴다                        ① 부모다
                v 가 표시돼 있으면 true 를 반환한다                   ② 사이클이다
                v 를 표시하고 stack 에 넣는다. from 에는 u 를 넣는다  ③ 처음 본다
    false 를 반환한다
```

#### 1. 간선 목록을 이웃 목록으로 옮기고 표시를 준비한다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 정점마다 빈 목록을 만들어 두고, 간선 하나를 양 끝의 목록에 한 번씩
넣어요. 표시 배열은 거짓으로 채우고, 스택과 `from` 은 빈 배열로 둡니다.

```ts
const nbr: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  (nbr[u] as number[]).push(v);
  (nbr[v] as number[]).push(u);
}

const visited: boolean[] = Array.from({ length: n }, () => false);
const stack: number[] = [];
const from: number[] = [];
```

전개 입력에 이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walk-lists-->

```text
nbr[0] = [1]                                           [0,1] 에서 넣었다
nbr[1] = [0, 2]                                        [0,1] · [1,2] 에서 넣었다
nbr[2] = [1]                                           [1,2] 에서 넣었다
nbr[3] = [4, 5]                                        [3,4] · [5,3] 에서 넣었다
nbr[4] = [3, 5]                                        [3,4] · [4,5] 에서 넣었다
nbr[5] = [4, 3]                                        [4,5] · [5,3] 에서 넣었다
목록 길이의 합                                         10 = 2E
visited = [false, false, false, false, false, false]   아직 아무것도 표시하지 않았다
stack = []                                             from = []
```

간선을 적은 순서가 그대로 목록의 순서입니다. `nbr[3]` 이 `[4, 5]` 인 것은 `[3,4]` 가 `[5,3]` 보다 먼저 적혀
있어서예요.

#### 2. 스택에서 꺼내 이웃을 확인한다

「아이디어 상세」의 3단계부터 5단계까지, 판정이 일어나는 자리입니다. 스택에서 정점 하나와 짝지은 `from` 값을 함께
꺼내고, 그 정점의 이웃 목록을 차례로 확인해요. 이웃 하나마다 세 갈래 중 하나를 합니다.

```ts
while (stack.length > 0) {
  const u = stack.pop() as number;
  const parent = from.pop() as number;

  for (const v of nbr[u] as number[]) {
    // ① 지나온 이웃이다. 무향 간선은 양쪽 목록에 있어 되돌아가는 것이 사이클이 아니다.
    if (v === parent) continue;

    // ② 이미 표시된 정점이다. 그 정점까지 가는 길이 하나 더 있다는 뜻이라 사이클이다.
    if (visited[v]) return true;

    // ③ 처음 보는 정점이다. 표시하고 스택에 넣는다.
    visited[v] = true;
    stack.push(v);
    from.push(u);
  }
}
```

여기서 가장 중요한 줄은 `if (v === parent) continue;` 입니다. 이 한 줄이 방향 없는 간선의 되돌아가기를 판정에서
빼는 자리예요. 그 아래 `visited[v] = true;` 가 `stack.push(v)` 와 붙어 있는 것도 짝입니다 — 표시와 넣기를 같은
자리에서 해야 스택에 같은 정점이 두 번 들어가지 않아요. 정점 3 을 꺼내 `nbr[3]` 을 차례로 확인한 자취는 이렇습니다.

<!--proof:walk-pop3-->

```text
T7   v = 4   4 === -1 거짓 · visited[4] 거짓   ③ 표시하고 넣는다   stack [4]      from [3]
T8   v = 5   5 === -1 거짓 · visited[5] 거짓   ③ 표시하고 넣는다   stack [4, 5]   from [3, 3]
```

정점 3 은 바깥 반복이 시작한 정점이라 부모가 `-1` 이고, 두 이웃 모두 부모가 아니며 표시도 없어 ③ 으로 넣었어요.
`from` 에는 두 번 다 3 이 들어갔습니다. 나중에 4 와 5 를 꺼낼 때 둘 다 부모 3 과 함께 나온다는 뜻이에요.

#### 짚고 가기 — 부모의 「정점 번호」로는 중복 간선을 놓칠 것 같다

건너뛰는 기준을 부모의 정점 번호로 둔 것이 불안합니다. 같은 정점 쌍을 두 번 잇는 간선이 있으면 목록에 같은
번호가 두 번 들어가고, `v === parent` 는 그 둘을 **모두** 건너뛰니까요. 그러면 두 번째 간선이 만드는 사이클을 못
보는 것 아닐까요. 지나온 **간선 번호**를 기억하면 그 걱정이 없어 보입니다.

```ts
// 걱정대로 고친 판 — 부모의 정점 번호 대신 지나온 간선 번호를 건너뛴다
for (let i = 0; i < list.length; i += 2) {
  const v = list[i] as number;
  const id = list[i + 1] as number; // 목록에 간선 번호를 함께 담아 둔다
  if (id === entered) continue;
  // … 나머지는 같다 …
}
```

**이 입력 범위에서는 답이 안 틀립니다.** 두 판을 여섯 입력에 실행하고, 작은 다중그래프를 전부 만들어 대조했어요.

<!--proof:parent-vs-edge-->

| 입력 | 부모의 정점 번호 건너뛰기 (정본) | 지나온 간선 번호 건너뛰기 | 옳은 답 |
| --- | --- | --- | --- |
| 같은 쌍을 두 번 이은 간선 | true | true | true |
| 가운데 쌍만 두 번 이은 한 줄 | true | true | true |
| 같은 쌍을 세 번 이은 간선 | true | true | true |
| 자기 자신을 잇는 간선 | true | true | true |
| 전개 입력 | true | true | true |
| 한 줄로 이은 네 정점 | false | false | false |

옳은 답은 유니온 파인드로 따로 낸 값입니다. 정점이 넷이고 간선이 넷 이하인 그래프 11,111 개(같은 쌍을 여러 번 잇는 것과 자기 자신을 잇는 것을 포함한다)를 전부 만들어 세 값을 대조했고, 하나라도 다른 그래프는 0 개입니다.

<!--/proof-->

걱정한 일이 일어나지 않는 까닭은 목록을 **꺼낸 정점 하나에서 한꺼번에 확인하기 때문**입니다. 같은 쌍을 두 번 이은
간선에서 두 번째 간선이 어디서 확인되는지 따라가면 이렇습니다.

<!--proof:parent-vs-edge-trace-->

```text
T1   정점 0 에서 시작          nbr[0] = [1, 1] · nbr[1] = [0, 0]
T2   0 의 목록 1 번째 이웃 1   부모 -1 · 표시 없다 → ③ 표시하고 넣는다
T3   0 의 목록 2 번째 이웃 1   부모 -1 · 표시 있다 → ② 사이클이다
     정점 1 을 꺼냈는가        아니다 — 0 의 목록에서 답이 먼저 나왔다
```

같은 쌍을 잇는 간선 둘은 **먼저 꺼내는 끝점의 목록에 나란히** 있습니다. 그 목록을 확인하는 동안 첫째가 상대를
표시하고 둘째가 그 표시를 보므로, 상대 쪽에서 건너뛸 기회가 오기 전에 답이 정해져요. 그럼에도 간선 번호로 바꾸지
않는 까닭은 값을 더 치르기 때문입니다. 이웃 목록에 간선 번호를 함께 담으면 목록 칸이 두 배가 되는데 답은 그대로예요.

#### 3. 여섯 정점의 간선 다섯 개를 처음부터 끝까지 확인한다

앞의 두 조각을 이어 실제로 실행하면 아홉 걸음이 나옵니다. 바깥 반복이 정점을 잡는 일 하나, 이웃 항목 하나를
확인하는 일 하나가 걸음 하나예요. 걸음 재생 패널에서 정점 안의 값이 부모이고, 점선 정점은 아직 표시가 없는
정점입니다. 굵은 실선이 나무 간선, 흐린 선이 아직 나무 간선이 아닌 간선, 대시가 사이클을 닫은 간선이에요. 무대
아래 두 띠가 `stack` 과 `from` 이고, 같은 자리끼리 짝입니다.

#### 짚고 가기 — 정점 0 에서 한 번만 시작해도 될 것 같다

바깥 `for` 문이 왜 필요한지 흐릿합니다. 정점 0 에서 시작해 간선을 따라가면 그래프 전체를 볼 수 있을 것 같으니까요.
그 오해대로 적으면 바깥 반복이 정점 0 하나에서 끝납니다.

```ts
for (let s = 0; s < 1; s++) {  // ← 정점 0 에서만 시작한다
```

무향 그래프는 **여러 연결 성분으로 나뉠 수 있습니다.** 정점 0 에서 갈 수 있는 곳은 0 의 연결 성분뿐이에요. 네 입력에
두 코드를 나란히 실행했습니다.

<!--proof:component-values-->

| --- | --- | --- | --- |
| 0-1 과 삼각형 2-3-4 | true | false | 어긋난다 |
| 자기 자신을 잇는 간선이 정점 3 에 | true | false | 어긋난다 |
| 삼각형이 정점 0 에 붙어 있다 | true | true | 같다 |
| 전개 입력 | true | false | 어긋난다 |

<!--/proof-->

셋째 줄에서는 답이 같습니다. 사이클이 정점 0 의 연결 성분에 있으면 0 에서만 시작해도 만나니까요. 그런 입력만 시험하면
바깥 반복을 지워 놓고도 통과합니다. 전개 입력도 어긋나는 쪽에 있어요 — 삼각형이 정점 3 의 연결 성분에 있기 때문입니다.
첫째 줄을 따라가면 이렇습니다.

#### 4. 전체 코드

조각 둘을 하나로 잇습니다. 앞에서 안 나온 것은 **바깥 반복과 마지막 `return false`** 인데, T6 에서 정점 3 을 다시
잡은 것이 바로 그 바깥 반복이었어요. 표시되지 않은 정점이 남았는지 확인하고 끝을 내는 자리를 여기서 코드로 적습니다.
정본의 최상위 상수 `NO_PARENT` 도 함께 싣습니다.

```ts
const NO_PARENT = -1;

export function undirectedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean {
  // 무향 간선 하나는 양쪽에서 걸어갈 수 있다. 두 목록에 한 번씩 넣는다.
  const nbr: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    (nbr[u] as number[]).push(v);
    (nbr[v] as number[]).push(u);
  }

  const visited: boolean[] = Array.from({ length: n }, () => false);
  // stack 과 from 은 같은 자리끼리 짝이다. from[i] 는 stack[i] 를 표시하게 한 이웃이다.
  const stack: number[] = [];
  const from: number[] = [];

  for (let s = 0; s < n; s++) {
    if (visited[s]) continue;
    visited[s] = true;
    stack.push(s);
    from.push(NO_PARENT);

    while (stack.length > 0) {
      const u = stack.pop() as number;
      const parent = from.pop() as number;

      for (const v of nbr[u] as number[]) {
        // ① 지나온 이웃이다. 무향 간선은 양쪽 목록에 있어 되돌아가는 것이 사이클이 아니다.
        if (v === parent) continue;

        // ② 이미 표시된 정점이다. 그 정점까지 가는 길이 하나 더 있다는 뜻이라 사이클이다.
        if (visited[v]) return true;

        // ③ 처음 보는 정점이다. 표시하고 스택에 넣는다.
        visited[v] = true;
        stack.push(v);
        from.push(u);
      }
    }
  }

  return false;
}
```

`NO_PARENT` 는 `-1` 을 가리키는 이름입니다. 정점 번호가 0 부터라 어느 정점과도 같지 않아요. 여러 입력에 실행하면
이렇게 나옵니다.

<!--proof:walk-result-->

```text
undirectedCycleDetection(6, [[0,1],[1,2],[3,4],[4,5],[5,3]])   →   true
undirectedCycleDetection(3, [[0,1],[1,2],[2,0]])               →   true
undirectedCycleDetection(4, [[0,1],[1,2],[2,3]])               →   false
undirectedCycleDetection(6, [[0,1],[1,2],[3,4],[4,5]])         →   false
undirectedCycleDetection(2, [[0,0]])                           →   true
undirectedCycleDetection(2, [[0,1],[0,1]])                     →   true
undirectedCycleDetection(5, [])                                →   false
undirectedCycleDetection(1, [])                                →   false
```

### 알아 두면 좋은 개념 — 회로 랭크

전개에서 ③ 으로 지나간 간선은 나무 간선이 됐고, T9 에서 만난 간선 `[4,5]` 는 이미 표시된 두 정점을 이었습니다. 끝까지
멈추지 않고 모든 간선을 가르면 전개 입력의 간선 다섯이 이렇게 나뉘어요.

<!--fig:related-extra-->
![전개 입력의 간선 5 개 — 굵은 실선이 나무 간선 4 개, 대시가 나무 밖 간선 1 개](./figs/related-extra.svg)

나무 간선의 수는 연결 성분마다 「정점 수 − 1」이라 모두 `V − k` 이고(
[`connectedComponents` 가이드](../connectedComponents/connectedComponents-guide.md)의 「탐색이 만드는 숲」이 같은 수를
셉니다), 나머지가 나무 밖 간선입니다. 그래서 나무 밖 간선의 수는 `E − V + k` 가 돼요. 여러 그래프에서 실제로 갈라 셌습니다.

<!--proof:circuit-rank-->

| 입력 | V | E | 연결 성분 k | 나무 간선 | 나무 밖 간선 | E − V + k |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 5 | 2 | 4 | 1 | 1 |
| 한 줄로 이은 네 정점 | 4 | 3 | 1 | 3 | 0 | 0 |
| 삼각형 | 3 | 3 | 1 | 2 | 1 | 1 |
| 삼각형 둘을 나란히 둔 것 | 6 | 6 | 2 | 4 | 2 | 2 |
| 사각형에 대각선 하나를 더한 것 | 4 | 5 | 1 | 3 | 2 | 2 |
| 정점 넷을 모두 이은 것 | 4 | 6 | 1 | 3 | 3 | 3 |
| 별 모양 1,000 정점 | 1,000 | 999 | 1 | 999 | 0 | 0 |

7 줄 모두 나무 밖 간선 칸과 E − V + k 칸이 같습니다. 나무 밖 간선이 1 이상인 줄과 정본의 답이 true 인 줄은 정확히 겹칩니다.

<!--/proof-->

`E − V + k` 에는 이름이 있습니다. **회로 랭크**라고 부르고, 그래프에서 서로 독립인 고리의 개수를 뜻해요. 나무 밖 간선
하나마다 나무 간선과 함께 고리 하나를 닫기 때문입니다. 사이클이 있는가라는 물음은 「회로 랭크가 1 이상인가」와 같은
물음이에요.

같은 개념이 이 편 밖에서도 그대로 쓰입니다. **맥케이브 순환 복잡도**는 프로그램의 제어 흐름 그래프에서 `E − V + 2k`
를 세어 분기의 복잡도로 삼는데, 여기서 센 `E − V + k` 에 연결 성분 수를 한 번 더 더한 값이에요. **전기 회로망**에서는
이 값이 키르히호프 전압 법칙으로 세울 수 있는 독립한 고리 방정식의 개수입니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 있는가 없는가를 묻는다 | 사이클을 전부 세거나 가장 짧은 것을 찾으라는 것이 아니다 | 표시된 이웃을 만나는 순간 반환한다 |
| 간선에 방향이 없다 | 방향이 있으면 되돌아가는 간선이 따로 있어야 사이클이 된다 | 부모 하나를 `from` 에 기억해 건너뛴다 |
| 그래프를 미리 다 받아 둘 수 있다 | 간선을 한 번에 받아 이웃 목록을 만들고 시작한다 | `nbr` 을 먼저 만들고 그 뒤로는 새 간선을 받지 않는다 |

첫 조건이 깨지면 규모가 통째로 달라집니다. 나무 밖 간선이 `r` 개인 그래프에서 서로 다른 사이클은 나무 밖 간선을 고르는
조합에서 나오므로 많아야 `2^r − 1` 개예요. 사이클을 전부 세어 두 물음의 비용을 나란히 놓았습니다.

<!--proof:fit-count-->

| 입력 | E | 나무 밖 간선 r | 2^r − 1 | 서로 다른 사이클 수 | 있는지 답할 때 확인한 이웃 항목 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 5 | 1 | 1 | 1 | 7 |
| 사각형에 대각선 하나를 더한 것 | 5 | 2 | 3 | 3 | 4 |
| 정점 넷을 모두 이은 것 | 6 | 3 | 7 | 7 | 5 |
| 정점 다섯을 모두 이은 것 | 10 | 6 | 63 | 37 | 6 |
| 정점 여섯을 모두 이은 것 | 15 | 10 | 1,023 | 197 | 7 |

5 줄 모두 사이클 수가 2^r − 1 을 넘지 않습니다. 정점 여섯을 모두 이은 것에서는 사이클이 197 개인데, 있는지 답하는 데는 이웃 항목 7 개를 확인했습니다.

<!--/proof-->

있는지 묻는 쪽은 이웃 항목 몇 개를 확인하고 끝나는데, 세는 쪽은 나무 밖 간선이 늘수록 사이클 수가 곱절로 늘 수 있습니다.
사이클을 세는 과제는 이 절차를 그대로 쓸 수 없어요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "트리인지 확인하라"   "중복 시공"   "닫힌 고리"   "양방향 도로"
  "어떤 두 지점 사이에도 경로가 하나뿐인가"        "네트워크에 순환이 있는가"

규모와 출력에 이런 모양이 보이면
  정점과 간선이 각각 10만 규모이고 시간이 1~2초   ← V + E 규모의 절차를 찾으라는 뜻이다
  답이 true / false 하나다                        ← 고리를 적어 낼 필요가 없다는 뜻이다
  자기 자신을 잇는 간선이 있을 수 있다            ← 길이 1 짜리 사이클을 빼먹지 말라는 뜻이다
  같은 쌍을 두 번 잇는 간선이 있을 수 있다        ← 이웃 목록에 같은 번호가 두 번 들어간다
```

반대로 **「간선에 방향이 있다」·「사이클을 이루는 정점을 출력하라」** 가 보이면 이 절차를 그대로 쓰지 않습니다. 앞은
되돌아가는 간선의 뜻이 달라져 [`directedCycleDetection` 가이드](../directedCycleDetection/directedCycleDetection-guide.md)가
다루는 과제가 되고, 뒤는 두 끝에서 부모를 따라 올라가 정점을 모으는 일이 더 붙어요.

#### 실제로 쓰이는 곳

- **NetworkX 의 `cycle_basis`** — 파이썬 그래프 라이브러리입니다. 무향 그래프의 독립한 고리를 모으는 함수인데, 그 안이
  이 글과 같은 모양이에요. `networkx/algorithms/cycles.py` 가 `while stack:  # walk the spanning tree finding cycles` 로
  순회를 열고 `z = stack.pop()  # use last-in so cycles easier to find` 로 스택에서 정점을 꺼냅니다. 이웃을 확인하는
  자리는 `if nbr not in used:  # new node` 와 `elif nbr == z:  # self loops` 와 `elif nbr not in zused:  # found a cycle`
  로 갈리는데, 첫째가 이 글의 ③ 이고 셋째가 ② 예요. 표시를 넣는 자리도 `used[nbr] = {z}` 로 **스택에 넣을 때**입니다.
  ([networkx/networkx networkx/algorithms/cycles.py](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/cycles.py), 조회 2026-09-03)
- **petgraph 의 `is_cyclic_undirected`** — 러스트 그래프 라이브러리이고, 이 글과 **다른 절차**를 골랐습니다.
  `crates/petgraph/src/algo/mod.rs` 의 그 함수는 `let mut edge_sets = UnionFind::new(g.node_bound());` 로 유니온 파인드를
  만들고, 간선마다 `if !edge_sets.union(g.to_index(a), g.to_index(b)) { return true; }` 로 두 끝이 이미 같은 무리였는지
  묻습니다. 문서 주석이 비용을 `Time complexity: amortized **O(|E|)**` 와 `Auxiliary space: **O(|V|)**` 로 적어 두었는데,
  뒤의 값이 이 글의 절차와 갈리는 자리예요 — 아래 대조에서 값으로 봅니다.
  ([petgraph/petgraph crates/petgraph/src/algo/mod.rs](https://raw.githubusercontent.com/petgraph/petgraph/master/crates/petgraph/src/algo/mod.rs), 조회 2026-09-03)

두 곳이 **같은 과제에 서로 다른 절차를 골랐다**는 것이 이 두 인용의 값입니다. 고리를 모아서 돌려줘야 하는 NetworkX 는
순회를 골랐고, 있는지만 답하는 petgraph 는 유니온 파인드를 골랐어요.

#### 경쟁 설계와의 대조

같은 답을 내는 다른 절차가 있습니다. **유니온 파인드**예요 — 이웃 목록을 만들지 않고 간선을 하나씩 받아 두 끝의
대표를 비교합니다. 대표가 같으면 두 끝이 이미 같은 덩어리라는 뜻이라 그 간선이 사이클을 닫아요. 위에서 본 petgraph 가
고른 절차이고, [`kruskalMst` 가이드](../../graph-flow/kruskalMst/kruskalMst-guide.md)가 같은 판정으로 간선을 거르며,
[`unionFind` 가이드](../../../data-structures/disjoint-set/unionFind/unionFind-guide.mdx)가 그 자료구조를 다룹니다. 두 절차는
사이클을 판정하는 자리가 다릅니다.

| 절차 | 판정하는 순간 | 먼저 치르는 것 |
| --- | --- | --- |
| 부모 건너뛰기 탐색 | 표시된 이웃을 만나는 순간 | 이웃 목록 전체를 먼저 만든다 |
| 유니온 파인드 | 간선을 하나 받아 두 끝의 대표가 같을 때 | 없다 — 간선마다 나눠 치른다 |

**전개가 쓰는 입력을 첫 줄에서 그대로 잽니다.** 다만 간선이 다섯뿐이라 「사이클을 닫는 간선이 목록의 몇 번째에
있는가」를 바꿔 볼 자리가 없어 순서가 뒤집히는 것을 보일 수 없어요. 그래서 규모 상한인 정점 100,000 을 쓰는 생성식
셋을 함께 씁니다 — 사이클이 없는 것은 `0-1-…-99,999` 한 줄, 사이클이 있는 것은 정점 0 · 1 · 2 를 삼각형으로 잇고
나머지를 한 줄로 이은 그래프이며 **삼각형 간선 셋을 목록의 어느 자리에 끼우는가**만 바꾸고, 마지막 하나는 같은 삼각형을
정점 번호 맨 뒤(99,997 · 99,998 · 99,999)에 둔 것입니다. 셋 다 `undirectedCycleDetection-guide.alt.ts` 에 상수로
두었어요. 계수는 칸 접근 수이고, 칸을 한 번 읽으면 1 · 한 번 쓰면 1 로 두 절차에 같은 규칙을 썼습니다. 배열을
처음 채우는 쓰기도 셉니다. **추가 칸**은 입력 간선 목록을 빼고, 입력으로 지은 이웃 목록 · `visited` · 스택과 `from` 이
가장 길었을 때의 길이를 넣은 값이에요. 유니온 파인드 쪽은 대표 배열과 크기 배열 `2V` 입니다.

<!--proof:alt-flip-->

| 재는 것 | 부모 건너뛰기 탐색 | 유니온 파인드 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 전개가 쓰는 여섯 정점에서 칸 접근 | 81 | 58 | 유니온 파인드 |
| 삼각형 간선이 목록 맨 앞일 때 칸 접근 | 600,018 | 200,026 | 유니온 파인드 |
| 삼각형 간선이 33,334 번째일 때 칸 접근 | 600,018 | 600,018 | 같다 |
| 삼각형 간선이 33,335 번째일 때 칸 접근 | 600,018 | 600,030 | 부모 건너뛰기 탐색 |
| 삼각형 간선이 목록 맨 뒤일 때 칸 접근 | 600,018 | 1,399,974 | 부모 건너뛰기 탐색 |
| 삼각형이 정점 번호 맨 뒤에 있을 때 칸 접근 | 1,599,985 | 200,026 | 유니온 파인드 |
| 사이클이 없는 한 줄에서 칸 접근 | 1,599,993 | 1,399,984 | 유니온 파인드 |
| 사이클이 없는 한 줄에서 추가 칸 | 400,000 | 200,000 | 유니온 파인드 |

삼각형 간선이 목록 맨 앞이면 유니온 파인드 쪽이 3.0 배 적고, 목록 맨 뒤면 부모 건너뛰기 탐색 쪽이 2.3 배 적습니다.

<!--/proof-->

**순서가 실제로 뒤집힙니다.** 부모 건너뛰기 탐색 쪽 값이 삼각형 간선의 자리와 무관하게 같은 것은 삼각형을 정점 번호
0 · 1 · 2 에 두었기 때문이에요 — 바깥 반복이 0 에서 시작하므로 목록의 어디에 적혀 있든 곧바로 만납니다. 유니온
파인드는 삼각형의 마지막 간선을 받을 때까지 앞의 간선을 모두 처리하므로, 그 자리가 뒤로 갈수록 값이 커져요. 뒤집히는
자리를 값으로 대면 이렇습니다.

<!--proof:alt-boundary-->

| 삼각형 간선의 자리 | 부모 건너뛰기 탐색 | 유니온 파인드 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 33,334 번째 | 600,018 | 600,018 | 같다 |
| 33,335 번째 | 600,018 | 600,030 | 부모 건너뛰기 탐색 |

<!--/proof-->

경계는 「유니온 파인드가 사이클을 닫는 간선에 이르기까지 처리한 간선 수」입니다. **내주는 것이 셋이에요.** 하나는
**사이클을 정점 번호 뒤쪽에 둔 입력**입니다 — 삼각형을 정점 99,997 · 99,998 · 99,999 에 두면 탐색은 한 줄 전체를
지나가야 해서 값이 크게 늘어요. 둘째는 **사이클이 없는 입력**이고, 셋째는 **추가 칸**입니다. 이웃 목록의 `2E`
칸이 그 차이이고, petgraph 주석의 `Auxiliary space: **O(|V|)**` 가 가리키는 자리가 이것이에요. 대신 얻는 것은
**사이클이 목록 뒤쪽에서 닫히는 입력**과 **사이클을 이루는 정점을 낼 수 있다는 것**입니다. 유니온 파인드는 어느 간선이
사이클을 닫았는지만 알려 주고 그 고리의 정점은 따로 찾아야 하는데, 이 절차는 두 끝에서 부모를 따라 올라가면 그대로
나와요.

### 수식 정의와 유도

정점 집합 $\mathcal{V}$ 와 간선 집합 $\mathcal{E}$ 로 이루어진 무향 그래프를 $G$ 라 적습니다. 절차가 ③ 으로 지나간 간선의
모임, 곧 나무 간선의 모임을 $F$ 라 적어요. **전개의 걸음 라벨 `T1`\~`T9` 와 겹치지 않게 나무 간선의 모임에는 $F$ 를
씁니다.** $V$ · $E$ · $k$ 는 기호표에서 정한 그대로 **수**이고 집합이 아니에요. 집합의 크기를 말할 때는
$|\mathcal{V}|$ · $|F|$ 처럼 세로줄로 적어 둘을 가릅니다.

| 이름 | 정의 | 전개 입력에서 |
| --- | --- | --- |
| $G = (\mathcal{V}, \mathcal{E})$ | 무향 그래프 | $\|\mathcal{V}\| = V$, $\|\mathcal{E}\| = E$ |
| $F$ | ③ 으로 지나간 간선의 모임 — 나무 간선 | 아래 표 |
| $A(V, E, k)$ | 절차가 읽고 쓴 배열 칸의 총수 | 아래에서 센다 |

먼저 $|F|$ 를 정의 그대로 셉니다. 간선이 $F$ 에 들어가는 것은 ③ 이 실행될 때뿐이고, ③ 은 표시되지 않은 정점을 표시하는
자리예요. 정점은 바깥 반복이 시작하며 표시하거나 ③ 이 표시하거나 둘 중 하나로 한 번씩만 표시되므로, 끝까지 확인하면
$|F| = V - k$ 입니다. 전개 입력에서 표시가 일어난 자리를 전부 적었습니다.

$$|F| = V - k$$

<!--proof:math-forest-count-->

| 표시한 자리 | 정점 | 수 |
| --- | --- | ---: |
| 바깥 반복 | [0, 3] | 2 |
| ③ 갈래 | [1, 2, 4, 5] | 4 |
| 모두 | [0, 1, 2, 3, 4, 5] | 6 |

연결 성분은 2 개이고, |F| = 6 − 2 = 4 입니다. 끝까지 가른 나무 간선도 4 개입니다.

<!--/proof-->

이제 **나무 밖 간선이 하나라도 있다는 것과 사이클이 있다는 것이 같다**를 유도합니다. 나무 밖 간선의 수는 $F$ 에 들지 않은
간선의 수예요.

$$|\mathcal{E}| - |F| = E - V + k \;\ge\; 1 \;\;\Longleftrightarrow\;\; G \text{ 에 사이클이 있다}$$

왼쪽에서 오른쪽으로 가는 방향은 나무 밖 간선 하나에서 사이클을 직접 만들어 보입니다.

```text
왼쪽에서 오른쪽 — 나무 밖 간선이 있으면 사이클이 있다

  나무 밖 간선 (u, v) 를 잡는다. u 와 v 는 같은 연결 성분에 있다
  F 는 연결 성분마다 그 성분의 정점을 모두 잇는다
    ┗ 나무 간선은 표시된 정점을 부모와 이어, 부모를 따라가면 시작 정점에 이른다
  그러니 F 만 따라가도 u 에서 v 로 가는 길이 있다
  그 길에 간선 (u, v) 를 이어 붙이면 u 에서 u 로 돌아온다
    ┗ (u, v) 는 F 에 없으므로 같은 간선을 두 번 쓰지 않는다 — 사이클이다
```

**오른쪽에서 왼쪽.** 나무 밖 간선이 하나도 없다고 가정합니다. 그러면 모든 간선이 $F$ 에 있고, $F$ 는 연결 성분 하나에
정점이 $c$ 개면 간선 $c - 1$ 개로 그 $c$ 개를 모두 잇습니다. $c$ 개를 $c - 1$ 개로 이으면 어느 두 정점 사이의 길이
정확히 하나예요. 길이 둘인 쌍이 있다고 해 봅시다. 두 길이 다르니 한 길에만 있는 간선 $e$ 가 있고, $e$ 를 빼도 $e$ 의 두
끝은 다른 길을 돌아 여전히 이어지므로 $c - 2$ 개로 $c$ 개를 잇게 됩니다. 그런데 간선 하나를 더할 때마다 이어진 무리의
수는 많아야 하나 줄어서, 정점 $c$ 개(무리 $c$ 개)를 한 무리로 만들려면 간선이 $c - 1$ 개 이상 있어야 해요. 어긋나므로
길이 둘 이상인 쌍은 없고, 그러니 사이클도 없습니다. 작은 값에 넣어 확인했습니다.

<!--proof:math-small-->

| 입력 | V | E | k | E − V + k | 정본의 답 |
| --- | ---: | ---: | ---: | --- | --- |
| 삼각형 | 3 | 3 | 1 | 3 − 3 + 1 = 1 | true |
| 한 줄로 이은 세 정점 | 3 | 2 | 1 | 2 − 3 + 1 = 0 | false |
| 전개 입력 | 6 | 5 | 2 | 5 − 6 + 2 = 1 | true |

E < V 인데도 정본의 답이 true 인 줄은 1 개(전개 입력)입니다.

<!--/proof-->

전개 입력은 $E < V$ 인데도 사이클이 있습니다. 한편 **간선 수만 보고 답이 나오는 경우**가 딸려 나와요. 사이클이 없으면
$E = V - k \le V - 1$ 이므로, 간선이 정점만큼 있으면 순회를 하기 전에 이미 답이 정해져 있습니다.

$$E \ge V \;\;\Longrightarrow\;\; E - V + k \ge k \ge 1 \;\;\Longrightarrow\;\; G \text{ 에 사이클이 있다}$$

첫 부등식은 $E - V \ge 0$ 에 $k$ 를 더한 것이고, 둘째는 정점이 하나 이상이라 연결 성분도 하나 이상이기 때문이에요.
$E \ge V$ 는 충분 조건이지 필요 조건이 아닙니다 — 위 표의 전개 입력이 그 반례예요. 이제 칸 접근 수 $A(V, E, k)$
를 코드에서 그대로 셉니다. 사이클이 없어 끝까지 확인하는 경우이고, 줄마다 만드는 칸 접근 수를 먼저 적으면 이렇습니다.

```ts
// 각 항이 어느 줄에서 나오는지 — 왼쪽 수가 그 줄이 만드는 칸 접근 수다.
//   2V   Array.from 두 번 — nbr · visited
//   4E   nbr[u] 읽기 + push + nbr[v] 읽기 + push
//    V   for (let s = 0; s < n; s++) 의 visited[s] 읽기
//   3k   연결 성분마다 visited[s] 쓰기 + stack.push + from.push
//   3V   꺼낼 때마다 stack.pop + from.pop + nbr[u] 읽기 — 정점마다 한 번씩
//   2E   이웃 항목마다 그 항목 읽기
// 4(V−k) ③ 마다 visited[v] 읽기 + visited[v] 쓰기 + push 둘
const cellsPerVertex = 10;
const cellsPerEdge = 6;
const closedForm = (V: number, E: number, k: number): number =>
  cellsPerVertex * V + cellsPerEdge * E - k;
```

$$A(V, E, k) = \underbrace{2V}_{\text{배열 둘}} + \underbrace{4E}_{\text{목록 만들기}} + \underbrace{V}_{\text{바깥 for}} + \underbrace{3k}_{\text{시작하기}} + \underbrace{3V}_{\text{꺼내기}} + \underbrace{2E + 4(V-k)}_{\text{이웃 확인}} = 10V + 6E - k$$

「이웃 확인」에서 ① 이 아닌 항목이 모두 ③ 인 것은 사이클이 없어 ② 가 한 번도 실행되지 않기 때문이에요. ③ 은 시작 정점이
아닌 정점마다 한 번이라 $V - k$ 번이고, ① 은 그 정점들이 제 목록에서 부모를 한 번씩 만나는 자리라 역시 $V - k$ 번입니다.
두 수를 더하면 이웃 항목 수 $2E = 2(V - k)$ 와 맞아요. 식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

| 입력 | V | E | 연결 성분 k | 실제 칸 접근 | 10V + 6E − k |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력에서 간선 [5,3] 을 뺀 것 | 6 | 4 | 2 | 82 | 82 |
| 간선이 없는 다섯 정점 | 5 | 0 | 5 | 45 | 45 |
| 한 줄로 이은 1,000 정점 | 1,000 | 999 | 1 | 15,993 | 15,993 |
| 별 모양 1,000 정점 | 1,000 | 999 | 1 | 15,993 | 15,993 |
| 1,000 정점을 넷씩 가른 숲 | 1,000 | 750 | 250 | 14,250 | 14,250 |
| 한 줄로 이은 100,000 정점 | 100,000 | 99,999 | 1 | 1,599,993 | 1,599,993 |

6 줄 가운데 두 값이 같은 줄은 6 개입니다.

<!--/proof-->

셋째 줄과 넷째 줄이 같은 값이라는 것도 함께 보세요 — 한 줄과 별 모양은 모양이 완전히 다른데 계수가 같습니다. 이 식에
정점 수 · 간선 수 · 연결 성분 수가 아닌 항이 없기 때문이에요. 마지막으로 규모 상한을 넣습니다. 사이클이 없을 때가 끝까지
확인하는 경우이고, 그때는 $E \le V - 1$ 이라 $V = 100{,}000$ · $E = 99{,}999$ · $k = 1$ 이 상한이에요.

<!--proof:math-scale-->

| 항 | 세는 것 | V = 100,000 · E = 99,999 · k = 1 에서 |
| --- | --- | ---: |
| 10V | 배열 둘 · 바깥 반복 · 꺼내기 · 표시하기 | 1,000,000 |
| 6E | 목록 만들기 · 이웃 확인하기 | 599,994 |
| −k | 연결 성분 하나 | −1 |
| A(V, E, k) | 한 줄에서 실제로 센 칸 접근 | 1,599,993 |
| 간선을 하나씩 지워 보기 | 한 줄 입력에서 E × E | 9,999,800,001 |

<!--/proof-->

160 만 번과 100 억 번을 나란히 놓으면 이 절차가 무엇을 바꿨는지가 수로 나옵니다. 간선마다 그래프 전체를 다시 확인하던
것을 **이웃 항목마다 한 번씩 확인하는 과제로** 바꾼 것이에요.

### 불변식 — 표시된 정점은 나무 간선으로만 이어져 있고, 나무 간선 수는 표시된 정점 수에서 시작한 횟수를 뺀 값이다

파트 1 에서 코드가 동작하는 것을 아홉 걸음으로 봤습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 전개 입력의 걸음마다 그 문장에 든 세 수를 적었습니다.

> 걸음 하나 — 바깥 반복의 시작 하나, 또는 이웃 항목 하나의 확인 — 가 끝날 때마다, 나무 간선의 수는 **표시된 정점 수에서
> 지금까지 바깥 반복이 시작한 횟수를 뺀 값**과 정확히 같습니다. 그리고 나무 간선만 보면 사이클이 없습니다.

<!--proof:invariant-steps-->

| 걸음 | 한 일 | 표시된 정점 | 나무 간선 | 시작한 횟수 | 식 |
| --- | --- | ---: | ---: | ---: | --- |
| T1 | 시작 | 1 | 0 | 1 | 1 = 0 + 1 |
| T2 | 표시하고 넣는다 | 2 | 1 | 1 | 2 = 1 + 1 |
| T3 | 부모라 건너뛴다 | 2 | 1 | 1 | 2 = 1 + 1 |
| T4 | 표시하고 넣는다 | 3 | 2 | 1 | 3 = 2 + 1 |
| T5 | 부모라 건너뛴다 | 3 | 2 | 1 | 3 = 2 + 1 |
| T6 | 시작 | 4 | 2 | 2 | 4 = 2 + 2 |
| T7 | 표시하고 넣는다 | 5 | 3 | 2 | 5 = 3 + 2 |
| T8 | 표시하고 넣는다 | 6 | 4 | 2 | 6 = 4 + 2 |
| T9 | 사이클이다 | 6 | 4 | 2 | 6 = 4 + 2 |

9 걸음 가운데 식이 어긋난 걸음은 0 개입니다.

<!--/proof-->

「걸음 하나가 끝날 때마다」가 중요합니다. 순회가 끝난 뒤 한 번만 참인 것이 아니라 **갈래 하나를 실행한 직후마다** 참이라는
뜻이에요. 그래야 다음 걸음이 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** 바깥 `for` 문이 표시되지 않은 정점 `s` 를 표시하는 순간, 표시된 정점이 하나 늘고 시작한 횟수도
하나 늘어 차가 그대로입니다. 그 연결 성분에서는 표시된 정점이 `s` 하나이고 나무 간선이 없으니 사이클도 없어요. 그 뒤로
상태를 바꾸는 갈래는 셋입니다.

| 갈래 | 바뀌는 것 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| 부모라 건너뛴다 | 아무것도 바뀌지 않는다 | 표시도 나무 간선도 그대로다 |
| 표시된 이웃을 만난다 | `true` 를 반환하고 끝난다 | 상태를 바꾸지 않는다. 이 간선은 $F$ 에 들어가지 않는다 |
| 표시 없는 이웃을 표시한다 | 표시가 하나, 나무 간선이 하나 는다 | 양쪽이 하나씩 늘어 식이 그대로다. 새 간선의 한 끝은 방금까지 표시되지 않은 정점이라 그 간선이 고리를 만들 수 없다 |

셋째 줄의 「고리를 만들 수 없다」가 이 불변식의 핵심입니다. 표시 없는 이웃을 표시하는 갈래가 잇는 두 정점 중 하나는
**그 순간까지 어느 나무 간선과도 이어지지 않은 정점**이라, 그 정점을 지나는 나무 간선은 방금 만든 하나뿐이에요. 나무
간선이 하나뿐인 정점은 나무 간선만으로 된 고리에 들어갈 수 없습니다. 입력을 늘려 걸음마다 다시 확인했어요.

<!--proof:invariant-check-->

| 입력 | 확인한 걸음 | 개수 식이 어긋난 걸음 | 나무 간선에 사이클이 생긴 걸음 | 반환값 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 | 9 | 0 | 0 | true |
| 한 줄로 이은 네 정점 | 7 | 0 | 0 | false |
| 별 모양 네 정점 | 7 | 0 | 0 | false |
| 삼각형 | 4 | 0 | 0 | true |
| 같은 쌍을 두 번 이은 간선 | 3 | 0 | 0 | true |
| 자기 자신을 잇는 간선 | 2 | 0 | 0 | true |
| 사각형 | 6 | 0 | 0 | true |
| 정점 넷을 모두 이은 것 | 6 | 0 | 0 | true |
| 한 줄로 이은 1,000 정점 | 1,999 | 0 | 0 | false |
| 별 모양 1,000 정점 | 1,999 | 0 | 0 | false |

입력 10 개의 4,042 걸음에서 불변식이 깨진 자리는 0 개입니다. 정점 1,000 개짜리 두 입력은 나무 간선의 사이클을 마지막 걸음에서만 쟀습니다.

<!--/proof-->

이 불변식이 답의 정확성을 그대로 줍니다. 표시된 이웃을 만났다는 것은 나무 간선만으로 이미 이어져 있는 두 정점을 잇는
간선을 하나 더 찾았다는 뜻이라 사이클이고, 끝까지 표시된 이웃을 만나지 못했다면 모든 간선이 나무 간선이라 사이클이
없어요. **모든 간선이 나무 간선이 되는지는 한 번 더 확인해야 합니다.** 간선 하나는 이웃 항목 둘로 나타나는데, 표시된
이웃을 한 번도 만나지 않고 끝났다면 그 둘이 각각 건너뛰기이거나 표시하기예요. 둘 다 건너뛰기인 간선은 있을 수 없습니다.

```text
간선 (u, v) 의 두 항목이 모두 건너뛰기라고 하면

  u 의 목록에서 v 를 건너뛰었다    부모가 v 다 = u 는 v 에서 표시됐다
  v 의 목록에서 u 를 건너뛰었다    부모가 u 다 = v 는 u 에서 표시됐다
                                    └ 서로가 서로보다 먼저 표시됐다는 말이라 성립하지 않는다
                                      그러니 한쪽은 표시하기이고, 그 간선은 나무 간선이다
```

경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariant-edges-->

| 입력 | 호출 | 끝난 자리 | 결과 |
| --- | --- | --- | --- |
| 정점 하나 | `undirectedCycleDetection(1, [])` | 시작 1 번 · 걸음 1 개 뒤 끝난다 | false |
| 간선 없음 | `undirectedCycleDetection(5, [])` | 시작 5 번 · 걸음 5 개 뒤 끝난다 | false |
| 자기 자신을 잇는 간선 | `undirectedCycleDetection(2, [[0,0]])` | T2 — 0 의 목록에서 표시된 0 을 만난다 | true |
| 같은 쌍을 두 번 | `undirectedCycleDetection(2, [[0,1],[0,1]])` | T3 — 0 의 목록에서 표시된 1 을 만난다 | true |
| 나뉜 연결 성분 | `undirectedCycleDetection(5, [[0,1],[2,3],[3,4],[4,2]])` | T7 — 4 의 목록에서 표시된 3 을 만난다 | true |
| 한 줄 100,000 정점 | 정점 0 부터 99,999 까지 한 줄 | 스택에 100,000 번 넣고 이웃 항목 199,998 개를 확인한다 | false |

<!--/proof-->

자기 자신을 잇는 간선이 이 절차의 경계입니다. 간선 `[v, v]` 는 `nbr[v]` 에 `v` 를 **두 번** 넣는데, `v` 는 스택에 들어갈
때 이미 표시됐으므로 첫 항목에서 바로 표시된 이웃을 만나요. 시작 정점이면 부모가 `-1` 이라 건너뛰기로 새지도 않습니다.
한 줄 100,000 정점은 스택 깊이가 배열 길이라 호출 깊이 제한을 받지 않아요.

**이제 깨뜨려 봅시다.** 「나무 간선만 보면 사이클이 없다」를 지키던 줄은 부모를 건너뛰는 줄입니다. 그 줄이 없으면
되돌아가는 이웃 항목이 표시된 이웃을 만나는 갈래로 들어가고, 나무 간선 하나가 나무 밖 간선으로 잘못 세어져요.

```ts
// if (v === parent) continue;   ← 이 줄을 지운다
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-no-skip-->

| 입력 | 부모 건너뛰기 (정본) | 건너뛰지 않기 | 두 답 |
| --- | --- | --- | --- |
| 전개 입력 | true | true | 같다 |
| 한 줄로 이은 네 정점 | false | true | 어긋난다 |
| 별 모양 네 정점 | false | true | 어긋난다 |
| 삼각형 | true | true | 같다 |
| 같은 쌍을 두 번 이은 간선 | true | true | 같다 |
| 자기 자신을 잇는 간선 | true | true | 같다 |

<!--/proof-->

사이클이 없는 두 그래프에서 `true` 가 나옵니다. **나머지 네 줄에서 두 값이 같다는 것**도 함께 보세요. 사이클이 있는
그래프는 어차피 `true` 라 답이 갈리지 않고, 그런 입력만 시험하면 이 줄을 지워 놓고도 통과해요. 한 줄로 이은 네 정점에서
두 코드를 나란히 실행하면 어긋나는 걸음이 보입니다.

<!--proof:mutant-no-skip-trace-->

| 걸음 | 부모 건너뛰기 (정본) | 건너뛰지 않기 |
| --- | --- | --- |
| T1 | 0 에서 시작 | 0 에서 시작 |
| T2 | 0 의 이웃 1 · 부모 없음 · 표시하고 넣는다 | 0 의 이웃 1 · 부모 없음 · 표시하고 넣는다 |
| T3 | 1 의 이웃 0 · 부모 0 · 부모라 건너뛴다 | 1 의 이웃 0 · 부모 0 · 사이클이다 |
| T4 | 1 의 이웃 2 · 부모 0 · 표시하고 넣는다 | — |
| T5 | 2 의 이웃 1 · 부모 1 · 부모라 건너뛴다 | — |
| T6 | 2 의 이웃 3 · 부모 1 · 표시하고 넣는다 | — |
| T7 | 3 의 이웃 2 · 부모 2 · 부모라 건너뛴다 | — |

T3 에서 처음 갈립니다. 건너뛰지 않는 판은 0 이 1 의 부모인데도 표시만 보고 사이클이라고 답해, 반환값이 true 입니다. 정본의 답은 false 입니다.

<!--/proof-->

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 일은 스택에서 정점 하나를 꺼내 그 이웃 목록을 확인하는 것뿐입니다. 전개의 걸음으로 확인하면 바퀴마다
이렇게 모여요.

<!--proof:perf-derive-->

| 바퀴 | 꺼낸 정점 | 부모 | 확인한 이웃 | 걸음 |
| ---: | --- | --- | --- | --- |
| 1 | 0 | 없음 | 1 | T2 |
| 2 | 1 | 0 | 0 · 2 | T3 · T4 |
| 3 | 2 | 1 | 1 | T5 |
| 4 | 3 | 없음 | 4 · 5 | T7 · T8 |
| 5 | 5 | 3 | 4 | T9 — 여기서 반환한다 |

꺼낸 정점은 5 개로 표시된 정점 6 개보다 적고, 이웃 확인은 7 번으로 목록 길이의 합 10 보다 적습니다. 표시됐지만 꺼내기 전에 반환한 정점은 [4] 입니다.

<!--/proof-->

정점 4 는 T7 에 표시됐지만 꺼내기 전에 T9 가 반환했습니다. 그러니 꺼내는 횟수는 **표시된 정점 수 이하**이고, 이웃을
확인하는 횟수는 **목록 길이의 합 `2E` 이하**입니다. 사이클이 없으면 둘 다 등호가 되고, 사이클을 먼저 만나면 그만큼
작아져요. 그 앞에 이웃 목록을 만드는 비용이 붙습니다.

```text
총식 = 배열 둘 만들기 + 목록 채우기 + 바깥 for + 꺼내기 + 이웃 확인 + 표시하기
       Θ(V)            Θ(E)          Θ(V)       Θ(V)     Θ(E')      Θ(V)
                                                          ↑ E' 는 반환하기 전까지 확인한 이웃 항목 수
     = Θ(V + E)

메모리 = nbr Θ(V + E) + visited · stack · from Θ(V) = Θ(V + E)
```

여기서 센 것은 **배열 칸을 읽고 쓴 횟수**입니다. `nbr[u].push(v)` 와 `stack.push(v)` 가 안에서 칸을 다시 잡는 비용은 세지
않았어요 — 정점 하나가 스택에 들어가는 것도 간선 하나가 목록에 들어가는 것도 전체에서 정해진 횟수라, 분할 상환하면
위 식의 규모를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 이웃 항목이 자기 자신을 잇는 간선이다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(V + E)` | `Θ(V + E)` |
| **최악의 경우** (사이클이 없다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값입니다.** 어떤 입력이 와도 이웃 목록을 만드는 데 `Θ(V + E)` 가 들고, 그것이 그대로 하한이에요. 간선
하나를 목록에 넣지 않고 넘어가는 경로가 없기 때문입니다. 케이스가 갈리는 것은 규모가 아니라 상수배예요. 정점 수를 규모
상한으로 고정하고 두 케이스를 쟀습니다.

<!--proof:perf-cases-->

| 케이스 | 입력 | E | 칸 접근 | 반환값 |
| --- | --- | ---: | ---: | --- |
| 사이클이 없다 | 한 줄로 이은 100,000 정점 | 99,999 | 1,599,993 | false |
| 사이클이 정점 0 에 있다 | 정점 0 · 1 · 2 가 삼각형, 나머지는 한 줄 | 99,999 | 600,018 | true |

두 입력 다 V = 100,000 이고, 칸 접근은 2.7 배 차이가 납니다.

<!--/proof-->

**평균을 따로 계산할 대상이 없습니다.** 사이클을 언제 만나는가가 순회의 길이를 바꾸기는 하지만, 그 앞에 놓인 `2V + 4E`
가 어떤 입력에서도 치러지므로 기댓값이 `Θ(V + E)` 를 벗어날 수 없어요. 「평균이 정의되지 않는다」가 아니라 **분포와
무관하게 같다**는 쪽입니다.

```text
최악 보장     어떤 입력에도 V + E 규모를 넘지 않는다         ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다  ← 이 절차는 여기 해당하지 않는다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 없고 입력 분포에 대한 가정도 없어서, 같은 간선 목록을 두 번 넣으면
반환값도 계수도 글자 그대로 같은 값이 나와요. 경계의 종류로 보면 `Θ(V + E)` 가 상한이자 하한입니다 — 간선 하나를 목록
둘에 넣는 일을 건너뛸 수 없으므로 그보다 적게 할 방법이 없고, 위에서 센 대로 그보다 많이 하지도 않습니다.

#### 최악을 만드는 입력

「정점과 간선을 둘 다 규모 상한까지 채우면 최악」이라는 통념부터 확인합시다. 정점 100,000 개와 간선 100,000 개를 함께
채우면 $E \ge V$ 이고, 「수식 정의와 유도」에서 본 대로 그런 그래프에는 **사이클이 반드시 있어요.** 사이클이 있으면
만나는 자리에서 순회가 끝나므로 오히려 일이 줄어듭니다. 모양을 바꿔 가며 쟀습니다.

<!--proof:shape-values-->

| 입력 모양 | V | E | 칸 접근 | 반환값 |
| --- | ---: | ---: | ---: | --- |
| 한 줄 (사이클 없음) | 100,000 | 99,999 | 1,599,993 | false |
| 별 모양 (사이클 없음) | 100,000 | 99,999 | 1,599,993 | false |
| 둘씩 짝지은 숲 (사이클 없음) | 100,000 | 50,000 | 1,250,000 | false |
| 한 줄의 양 끝을 이은 고리 | 100,000 | 100,000 | 1,499,995 | true |
| 한 줄에 간선 [99999,99997] 을 더한 것 | 100,000 | 100,000 | 1,499,995 | true |
| 별 모양에 간선 [1,2] 를 더한 것 | 100,000 | 100,000 | 1,499,996 | true |

한 줄에 간선 [i, i+2] 를 더하고 i 를 997 칸씩 옮겨 가며 잰 최댓값은 i = 99,700 에서 1,497,322 이고, 사이클이 없는 한 줄의 1,599,993 보다 적습니다.

<!--/proof-->

**앞의 두 줄이 정확히 같습니다.** 한 줄은 스택에 한 번에 한 정점만 들어가고 목록 하나가 많아야 2 칸인데, 별 모양은
스택에 정점이 거의 다 한꺼번에 들어가고 `nbr[0]` 하나가 목록 대부분을 차지해요. 그런데도 값이 같습니다 — 반복문으로
적었으므로 호출 깊이가 없고, 스택에 동시에 들어 있는 개수도 비용이 아니라 배열 길이일 뿐이라 어느 쪽이든 `V` 를 넘지
않으니까요. 넷째 · 다섯째 · 여섯째 줄은 간선을 100,000 개까지 채운 그래프인데 전부 사이클이 있어 값이 더 작고, 간선
하나를 붙이는 자리를 옮겨 가며 잰 최댓값도 첫 줄에 못 미칩니다.

```text
최악을 만드는 조건은 모양이 아니라 「사이클이 없는 채로 간선을 최대한 채우는 것」이다

  V 를 상한까지 채운다        10V 항이 최대가 된다
  사이클이 없어야 한다        E ≤ V − 1 — 있으면 순회가 중간에 끝난다
  연결 성분은 하나여야 한다   k = 1 — k 가 크면 E 가 그만큼 줄어든다
```

가장 적은 일을 하는 입력은 반대쪽입니다. 정점 0 에 자기 자신을 잇는 간선을 하나 두면 첫 이웃 항목에서 반환하니까요.
그래도 규모는 그대로 `Θ(V + E)` 입니다 — 이웃 목록을 만드는 `2V + 4E` 는 어떤 입력에서도 치러야 하니까요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 간선을 하나씩 지워 그래프 전체를 다시 확인하던 것을 **정점마다 표시
하나를 두는 것**으로 바꿨고, 무향 간선이 양쪽 목록에 들어가므로 **부모 하나만 건너뛰면**, 부모가 아닌 표시된 이웃을
만나는 순간 답이 정해집니다.

```text
간선 목록 → nbr 둘로 나눠 넣기 → 표시 없는 정점에서 시작 → 꺼내서 이웃 확인 → 표시하고 부모와 함께 넣기
              └ 목록 길이 합 2E    └ 바깥 for 가 V 번       └ ① 부모는 건너뛰기  └ ② 표시된 이웃이면 true
```

먼저 답이 붙는 문제 하나입니다. 전개에서는 한 줄이 정점 0 · 1 · 2 이고 삼각형이 3 · 4 · 5 였습니다. T6 에서 바깥
반복이 정점 3 을 다시 잡은 것이 그 때문이었어요. 정점 번호를 서로 바꿔 삼각형을 0 · 1 · 2 에, 한 줄을 3 · 4 · 5 에
두면 확인한 이웃 항목 수와 반환값이 어떻게 될까요?

```text
edges = [[3,4], [4,5], [0,1], [1,2], [2,0]]   ← 같은 그래프에 번호만 바꿔 붙였다
```

<!--check:vertexSwap-->
반환값은 그대로 `true` 이고, 확인한 이웃 항목 수는 줄어듭니다. 바깥 반복이 정점 0 에서 시작하는데 그 정점이 삼각형에
있어, 한 줄 쪽을 한 번도 확인하지 않고 끝나기 때문이에요.
**사이클이 있는지 없는지는 번호와 무관한데 비용은 번호에 달렸습니다.** 경쟁 설계와의 대조에서 삼각형을 정점 번호 맨 뒤에
둔 입력이 부모 건너뛰기 탐색에 불리했던 것이 같은 성질이에요.

<!--proof:vertex-swap-->

| 입력 | 확인한 이웃 항목 | 칸 접근 | 반환값 |
| --- | ---: | ---: | --- |
| 전개 입력 — 한 줄이 0 · 1 · 2, 삼각형이 3 · 4 · 5 | 7 | 81 | true |
| 번호를 바꾼 입력 — 삼각형이 0 · 1 · 2, 한 줄이 3 · 4 · 5 | 3 | 54 | true |

<!--/proof-->
<!--/check-->

아래 셋은 답을 싣지 않았습니다. 막히면 차례대로 「수행으로 알아보는 알고리즘」의 T8 과 T9, 「불변식」, 「알아 두면
좋은 개념」을 다시 보세요.

- T8 에서 정점 5 를 표시해 스택에 넣었고 T9 에서 그 5 를 꺼냈습니다. 만약 스택이 아니라 큐를 써서 먼저 넣은 것을 먼저
  꺼낸다면 T9 에서 꺼내는 정점은 무엇이고, 반환값은 달라집니까.
- 불변식은 「나무 간선 수 = 표시된 정점 수 − 시작한 횟수」라고 말합니다. 그러면 순회가 `false` 로 끝났을 때 시작한
  횟수는 무엇의 개수입니까. 그 값을 함께 돌려주도록 코드를 고치려면 어디에 한 줄을 더해야 합니까.
- 나무 밖 간선의 개수는 `E − V + k` 였습니다. 정점 100,000 개와 간선 100,000 개인 그래프에서 이 값이 가장 작아지는 것은
  어떤 모양일 때이고, 그때에도 사이클이 반드시 있다고 말할 수 있습니까.

## 실습 — 직접 풀어 보기

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### Undirected Cycle Detection (무향 그래프 사이클 탐지)

풀 파일: [`undirectedCycleDetection.ts`](./undirectedCycleDetection.ts) · 테스트: [`undirectedCycleDetection.test.ts`](./undirectedCycleDetection.test.ts) · 실행: `bun test src/algorithms/graph/undirectedCycleDetection/undirectedCycleDetection.test.ts`

#### 한 줄 요약

> 함수는 정점 수 `n`과 무향 간선 목록을 받아, 그래프에 사이클이 존재하면 `true`, 없으면 `false`를 반환한다.

#### 스토리

도시 계획팀이 새로운 공원 산책로 네트워크를 설계하고 있다. 산책로는 양방향으로 걸을 수 있고, 각 교차점이 하나의 정점이다. 팀은 산책로가 트리 구조인지 — 즉 어떤 두 지점 사이에도 경로가 딱 하나뿐인지 — 를 확인하고 싶다.

경로가 하나보다 많다는 것은 어딘가에 순환 고리(사이클)가 있다는 뜻이다. 사이클이 있으면 같은 구간을 중복 시공한 셈이므로 예산을 낭비한 것이다.

또한 같은 두 교차점을 잇는 산책로가 두 개 이상 있거나, 한 지점에서 그냥 맴도는 루프가 있어도 역시 불필요한 중복이다.

#### 함수 인터페이스

```ts
export function undirectedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean;
```

- `n` — 정점 수. 정점 번호는 $0 \ldots n-1$
- `edges` — 무향 간선 목록. 각 원소 `[u, v]`는 정점 `u`와 `v` 사이의 무향 간선
- 반환 — 사이클이 존재하면 `true`, 존재하지 않으면 `false`

#### 제약 조건

- $1 \leq V \leq 10^{5}$ (여기서 $V = n$)
- $0 \leq E \leq 10^{5}$ (여기서 $E$는 `edges`의 길이)
- 무방향 그래프
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

무향 그래프에 **사이클이 존재하는지 여부** 를 판별한다.

사이클은 3개 이상의 서로 다른 정점으로 이루어진 닫힌 경로이다.

추가 규칙:
- 자기 루프 `[v, v]`도 사이클로 간주한다.
- 같은 정점 쌍에 대한 다중 간선(중복 간선)이 있으면 사이클로 간주한다.
- 그래프가 분리된 여러 성분으로 이루어진 경우, 어느 하나에라도 사이클이 있으면 `true`를 반환한다.
- 간선이 없으면 사이클이 없다.

#### 예시

```ts
// 삼각형: 0-1-2-0
undirectedCycleDetection(3, [[0,1],[1,2],[2,0]]); // true

// 자기 루프: 0-0
undirectedCycleDetection(2, [[0,0]]); // true

// 중복 간선: [0,1]이 두 번
undirectedCycleDetection(2, [[0,1],[0,1]]); // true

// 선형 트리: 0-1-2-3
undirectedCycleDetection(4, [[0,1],[1,2],[2,3]]); // false

// 포레스트: 0-1-2 | 3-4-5 (두 개의 트리)
undirectedCycleDetection(6, [[0,1],[1,2],[3,4],[4,5]]); // false

// 간선 없음
undirectedCycleDetection(5, []); // false
```
