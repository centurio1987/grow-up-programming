# 무향 사이클 탐지 — 방금 지나온 이웃 하나만 빼면 표시 한 벌로 판정된다

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 간선을 하나씩 지워 보던
방법에서 정점마다 표시 하나를 두는 방법까지 가는 과정을 따라갑니다. 마지막에는 실제로
동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**무향 그래프**는 정점들과 **방향이 없는 간선**으로 이루어집니다. 간선 `[u, v]` 는 `u` 와 `v`
사이를 양쪽으로 오갈 수 있다는 뜻이에요. 공원 산책로라면 어느 쪽에서든 걸어 들어갈 수 있는
길 하나입니다.

```text
정점 여섯 개짜리 그래프 — 간선에 방향이 없다

    0 ──── 1 ──── 2              간선 다섯
                                   [0,1] · [1,2]
        3                          [3,4] · [4,5] · [5,3]
       ╱ ╲
      ╱   ╲                      0·1·2 는 한 줄로 이어져 있고
     4 ─── 5                     3·4·5 는 고리를 이룬다
```

이 글이 답하는 것은 **어느 정점에서 출발해 같은 간선을 두 번 쓰지 않고 제자리로 돌아오는 길이
있는가** 하나입니다. 그런 길을 **사이클**이라고 부르고, 있으면 `true`, 없으면 `false` 를
돌려줍니다. 위 그래프에는 그런 길이 있어요.

```text
사이클 하나를 확인한다

  3 ─ 4    간선 [3,4] 를 쓴다
  4 ─ 5    간선 [4,5] 를 쓴다
  5 ─ 3    간선 [5,3] 을 쓴다
           └ 출발한 정점 3 으로 돌아왔고 같은 간선을 두 번 쓰지 않았다. 사이클이다

  0 ─ 1    간선 [0,1] 을 쓴다
  1 ─ 0    같은 간선을 한 번 더 쓴 것이라 사이클이 아니다
```

**여기가 방향이 있는 그래프와 갈리는 자리입니다.** 방향이 있으면 `u → v` 를 따라간 뒤 `v → u`
로 돌아오려면 그런 간선이 따로 있어야 해요. 방향이 없으면 방금 지나온 간선 하나로 언제든 되돌아
갈 수 있고, **그 되돌아가기를 사이클로 세면 간선 하나짜리 그래프도 `true` 가 됩니다.**

```text
간선 하나짜리 그래프 [0,1] 에서

  0 ── 1    0 에서 1 로 간다
  1 ── 0    되돌아간다. 쓴 간선은 여전히 [0,1] 하나뿐이다
            └ 사이클이 아니다. 사이클은 같은 간선을 두 번 쓰지 않는 닫힌 길이다
```

**이 글의 결정적인 관찰은 하나입니다.** 정점마다 「확인했다」는 표시를 한 벌만 두고, 어떤
정점에서 이웃을 확인할 때 **그 정점을 표시하게 한 이웃 하나만 건너뛰면**, 나머지 이웃 중
표시된 것이 나오는 순간 사이클이 확정됩니다. 상태는 색이 아니라 표시 하나면 되고, 갈리는 것은
「지나온 이웃인가」뿐이에요.

```text
정점 하나를 확인할 때 이웃은 셋 중 하나다

  지나온 이웃      그 정점을 표시하게 한 바로 그 이웃      건너뛴다
  표시된 이웃      다른 길로 이미 표시된 정점              ← 사이클이다
  표시 안 된 이웃  아직 한 번도 확인하지 않은 정점         표시하고 뒤에 확인한다
```

표시된 이웃이 왜 사이클인지는 길 둘을 나란히 놓으면 확인됩니다. 지금 정점까지 오는 데 쓴 길이
하나 있고, 그 이웃도 이미 표시돼 있으니 같은 덩어리 안에서 그 이웃까지 가는 길이 따로 있어요.
두 길을 이어 붙이면 제자리로 돌아옵니다.

```text
정점 5 에서 이웃 4 를 확인하는 순간

  3 ─ 5    5 는 3 에서 표시됐다. 지나온 이웃은 3 이다
  3 ─ 4    4 도 3 에서 표시됐다. 4 는 5 의 지나온 이웃이 아니다
  5 ─ 4    지금 확인하는 간선
           └ 5 ─ 3 ─ 4 라는 길과 간선 [4,5] 를 이으면 5 에서 5 로 돌아온다. 사이클이다
```

자기 자신을 잇는 간선 `[v, v]` 와 같은 정점 쌍을 두 번 잇는 간선도 사이클로 봅니다. 둘 다
「제자리로 돌아오는 길이 하나 더 있다」에 해당하고, 위 판정이 따로 손대지 않아도 그렇게
답해요.

```text
두 가지 특별한 간선

  [0,0]           0 의 이웃 목록에 0 이 두 번 들어간다. 0 은 이미 표시돼 있다   사이클
  [0,1] 두 번     1 을 표시한 뒤 같은 목록의 다음 자리에서 1 을 또 만난다      사이클
                  └ 지나온 이웃은 하나만 건너뛰므로 두 번째 자리가 남는다
```

표시하고 확인하는 일은 정점마다 한 번, 이웃 항목마다 한 번씩만 일어납니다. 이웃 항목이 `2E`
개이므로 전체가 `Θ(V + E)` 에 비례하고, 제약 상한인 정점 100,000 개에서 배열 칸을 읽고 쓴
횟수가 160 만을 넘지 않아요. 1 초 안에 넉넉히 들어옵니다.

```text
정점 수 V, 간선 수 E 일 때

  이웃 목록 만들기   간선 하나를 양쪽 목록에 한 번씩 넣는다   E 에 비례
  표시 배열 만들기   정점마다 칸 하나                        V 에 비례
  표시하기           정점마다 한 번씩                        V 에 비례
  이웃 확인하기      이웃 항목마다 정확히 한 번씩            2E 에 비례
                     └ 전체가 V + E 에 비례한다
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **인접 리스트** — 정점마다 이웃 번호를 담은 목록 하나를 두는 표현입니다. 이 글은 간선
  `[u, v]` 하나를 `u` 의 목록과 `v` 의 목록에 **한 번씩 두 번** 넣어요. 모르면
  [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **깊이 우선 탐색** — 한 갈래를 갈 수 있는 데까지 확인한 다음 되돌아 나오는 순회입니다. 이
  글은 그 순회에 표시 하나와 건너뛰기 규칙을 덧붙인 것이라, 순회 자체가 흐릿하면 뒤가
  어긋나요. 모르면 [`dfsTraversal` 가이드](../dfsTraversal/dfsTraversal-guide.md)를 보세요.
- **연결 덩어리** — 간선을 따라 서로 오갈 수 있는 정점들의 모임입니다. 그래프는 여러 덩어리로
  나뉠 수 있고, 이 문제는 **어느 덩어리에라도** 사이클이 있으면 `true` 예요. 모르면
  [`connectedComponents` 가이드](../connectedComponents/connectedComponents-guide.md)를 보세요.
- **스택이 나중에 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기·꺼내기가 각각 `O(1)` 입니다.
  모르면 [`stack` 가이드](../../../data-structures/linear/stack/stack-guide.mdx)를 보세요.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점이 표시됐는가」를 배열 한 칸을 읽어
  판정합니다.

첫째와 둘째가 흐릿하면 뒤가 어긋납니다. 무향 간선을 목록 둘에 넣는다는 것과, 그래서 이웃
목록의 길이를 다 더하면 `2E` 가 된다는 것이 이 글의 계산에 계속 나와요.

```text
간선 [3,4] 하나가 목록 둘에 들어간다

  nbr[3] 에 4 를 넣는다      3 에서 4 로 갈 수 있다
  nbr[4] 에 3 을 넣는다      4 에서 3 으로 갈 수 있다
                            └ 그래서 목록 길이의 합이 2E 다
```

### 아이디어 상세 — 표시 한 벌과 건너뛸 이웃을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function undirectedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean;
```

- 입력: 정점 수 `n`, 무향 간선 목록 `edges`. 정점 번호는 0 부터 `n - 1` 까지예요.
- 출력: 어느 덩어리에라도 사이클이 있으면 `true`, 전체가 숲이면 `false`.
- 제약: 정점 100,000 개 이하, 간선 100,000 개 이하, 시간 1 초, 메모리 256 MB.
  자기 자신을 잇는 간선 `[v, v]` 와 같은 쌍을 여러 번 잇는 간선이 들어올 수 있고, 그래프가
  여러 덩어리로 나뉘어 있을 수 있습니다. 어느 덩어리에라도 사이클이 있으면 `true` 예요.

**묻는 것이 있는가 없는가뿐**이라는 것이 이 문제의 성질이에요. 어느 정점들이 고리를 이루는지
적어 내라는 것이 아니므로, 고리 하나를 확인하는 순간 남은 간선을 안 봐도 답이 정해집니다.

```text
묻는 것이 무엇이냐가 절차의 끝을 정한다

  사이클을 전부 나열하라   마지막 간선까지 확인해야 끝난다
  가장 짧은 것을 찾아라    후보를 다 만들어 견주어야 끝난다
  하나라도 있는가          첫 하나를 확인하는 순간 끝난다      ← 이 문제
```

이 글이 쓰는 기호는 여섯이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `V` | 정점 수 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수 | `0 ≤ E ≤ 100,000` |
| `nbr[u]` | `u` 와 간선으로 이어진 정점들의 목록 | 길이를 다 더하면 `2E` |
| `visited[v]` | 정점 `v` 를 표시했는가 | 처음에는 전부 거짓 |
| `stack` | 이웃을 아직 확인하지 않은 정점들 | 뒤에 넣고 뒤에서 꺼낸다 |
| `from` | `stack` 과 짝지어, 그 정점을 표시하게 한 이웃 | 시작 정점에는 `-1` |

정점 수 `V` 는 코드에서 `n` 입니다. `stack` 과 `from` 은 같은 자리끼리 짝이라 언제나 길이가
같아요.

```text
기호가 어디에 사는가

  V              함수 인자 n              값이 바뀌지 않는다
  E              edges 의 길이            값이 바뀌지 않는다
  nbr[u]         배열의 배열              한 번 만들고 나면 바뀌지 않는다
  visited[v]     배열 한 칸               거짓에서 참으로 한 번만 바뀐다
  stack · from   배열 둘                  같은 자리끼리 짝이고 길이가 같다
```

가장 먼저 떠오르는 방법으로 시작합시다. 사이클이 있다는 것은 **어떤 두 지점 사이에 길이 둘
이상 있다**는 뜻이니, 간선을 하나씩 지워 보고 그 간선의 두 끝이 **아직 이어져 있는지** 확인하면
됩니다. 이어져 있으면 그 간선 말고 다른 길이 있다는 것이고, 그 길과 지운 간선을 이으면 사이클이
에요. 사이클의 정의를 그대로 옮긴 풀이입니다.

```ts
// 간선 하나를 지우고 두 끝이 아직 이어져 있는지 확인한다.
for (let removed = 0; removed < edges.length; removed++) {
  const [u, v] = edges[removed];
  // removed 번 간선만 빼고 u 에서 갈 수 있는 곳을 전부 표시한다
  const seen = reachableWithout(u, removed);
  if (seen[v]) return true; // 지운 간선 없이도 v 까지 간다 — 사이클이다
}
return false;
```

이 방법은 답이 맞아요. 그런데 간선 하나마다 그래프 전체를 다시 확인하므로, 같은 이웃 목록을
`E` 번 되풀이해 읽습니다. 정점을 한 줄로 이은 그래프에서 실제로 몇 번 읽는지 세어 봅시다.

<!--proof:naive-scale-->

```text
입력                      정점 V   간선 E   확인한 이웃 수
전개가 쓰는 여섯 정점          6        5               10
한 줄로 이은 10 정점          10        9               81
한 줄로 이은 100 정점        100       99            9,801
한 줄로 이은 1,000 정점    1,000      999          998,001
한 줄로 이은 2,000 정점    2,000    1,999        3,996,001
        └ 한 줄 입력 네 줄이 전부 E × E 와 같다: true
          제약 상한인 간선 99,999 개를 그 식에 넣으면 9,999,800,001 이다
```

간선이 999 개인 그래프에서 이미 백만 번 가까이 읽고, 제약 상한에서는 100 억 번입니다. 1 초
안에 끝나는 규모가 아니에요. 세는 것은 **이웃 목록에서 읽은 이웃 수**이고, 목록을 한 번
만드는 비용은 어느 방식이든 같으므로 세지 않았습니다.

```text
왜 이렇게 커지는가 — 한 줄로 이은 1,000 정점에서

  간선 999 개를 하나씩 지운다                    999 번 되풀이한다
  지울 때마다 한쪽 덩어리를 처음부터 확인한다    한 번에 평균 999 개를 읽는다
                                                 └ 999 × 999 = 998,001 이 된 자리다
```

**되풀이가 낭비인 이유는 답이 매번 같은 것을 다시 확인하기 때문입니다.** 한 줄로 이은 네 정점
에서 간선 `[0,1]` 을 지워 확인한 것과 `[1,2]` 를 지워 확인한 것이 무엇을 공유하는지 보면
그렇습니다.

```text
0 ─ 1 ─ 2 ─ 3 에서 간선을 하나씩 지워 본다

  [0,1] 을 지운다   0 에서 갈 수 있는 곳은 0 뿐이다. 1 에 못 간다        길이 하나뿐
  [1,2] 를 지운다   1 에서 갈 수 있는 곳은 0 과 1 이다. 2 에 못 간다     길이 하나뿐
  [2,3] 을 지운다   2 에서 갈 수 있는 곳은 0·1·2 다. 3 에 못 간다        길이 하나뿐
                    └ 세 번 다 「정점 0·1·2 가 한 덩어리」라는 같은 사실을 다시 확인했다
```

한 번의 순회로 그 사실을 한 벌만 만들어 두면 됩니다. **정점을 표시하며 이웃을 따라가다가 이미
표시된 정점을 만나면**, 그 정점까지 오는 길이 이미 있는데 지금 간선으로 또 갈 수 있다는 뜻이라
그 자리에서 사이클이 확정돼요. 두 방식을 같은 입력에 실행해 읽은 이웃 수를 나란히 세어 봅시다.

<!--proof:mark-values-->

```text
입력                          E   간선을 지워 본다   표시를 한 벌 둔다       배수   답
전개가 쓰는 여섯 정점         5                 10                   7     1.4 배   true
한 줄로 이은 10 정점          9                 81                  18     4.5 배   false
별 모양 1,000 정점          999          1,995,003               1,998   998.5 배   false
한 줄로 이은 1,000 정점     999            998,001               1,998   499.5 배   false
고리 1,000 정점           1,000              2,000               1,997     1.0 배   true
```

**답은 두 방식이 같은데 읽은 수가 갈립니다.** 별 모양 1,000 정점에서 1,995,003 이 1,998 이
됐고, 한 줄로 이은 1,000 정점에서는 998,001 이 1,998 이 됐어요. 고리 1,000 정점에서 배수가
1.0 인 것도 함께 보세요 — 답이 `true` 인 그래프에서는 지우기 방식도 첫 간선에서 끝나므로,
갈리는 것은 **답이 `false` 일 때**입니다.

```text
한 줄로 이은 1,000 정점에서 무엇이 갈렸는가

  간선을 하나씩 지워 본다   같은 사실을 간선마다 다시 확인한다   998,001
  표시를 한 벌 둔다         한 번 확인하고 표시로 남긴다         1,998
                            └ 답은 둘 다 false 로 같다
```

> 정점마다 표시를 한 벌 두고, 이웃 목록을 한 번씩만 확인한다. 표시된 정점을 만나면 그리로 가는
> 길이 하나 더 있다는 뜻이다.

**그런데 이대로 적으면 답이 틀립니다.** 무향 간선은 양쪽 목록에 들어 있어서, 정점 1 을 표시하고
그 이웃 목록을 확인하면 방금 지나온 0 이 거기 들어 있어요. 0 은 이미 표시돼 있으니 위 판정이
그대로 사이클이라고 답합니다.

```text
0 ─ 1 하나짜리 그래프에서 무슨 일이 일어나는가

  0 을 표시한다          표시 {0}
  0 의 이웃 1 을 본다    표시 안 됐다. 표시하고 뒤에 확인한다      표시 {0,1}
  1 의 이웃 0 을 본다    이미 표시돼 있다
                         └ 여기서 사이클이라고 하면 틀린다. 방금 지나온 그 간선이다
```

**그러니 무엇을 건너뛸 것인가가 이 절차의 갈림점입니다.** 가장 단순한 후보부터 값으로 시험해
봅시다. 후보는 셋이에요 — 아무것도 건너뛰지 않거나, 지나온 이웃 하나를 건너뛰거나, 표시된
이웃을 전부 건너뛰거나.

<!--proof:skip-choice-->

```text
입력                        아무것도 안 건너뛴다   지나온 이웃 하나   표시된 이웃 전부   옳은 답
전개가 쓰는 여섯 정점       true                   true               false              true
한 줄로 이은 네 정점        true                   false              false              false
별 모양 네 정점             true                   false              false              false
삼각형 세 정점              true                   true               false              true
같은 쌍을 두 번 이은 간선   true                   true               false              true
자기 자신을 잇는 간선       true                   true               false              true
```

**첫째 후보는 사이클이 없는 그래프를 전부 `true` 라고 답하고, 셋째 후보는 사이클이 있는
그래프를 전부 `false` 라고 답합니다.** 가운데만 여섯 입력에서 옳은 답과 같아요. 첫째는 되돌아
가는 간선을 사이클로 세는 것이고, 셋째는 되돌아가는 간선을 건너뛰려다 **사이클을 만드는 간선
까지 함께** 건너뜁니다.

```text
셋째 후보가 삼각형에서 무엇을 놓치는가 — 표시된 이웃을 전부 건너뛴다

  0 을 표시            표시 {0}
  0 의 이웃 1 · 2      둘 다 표시하고 뒤에 확인한다               표시 {0,1,2}
  2 의 이웃 1 · 0      둘 다 이미 표시돼 있다 → 전부 건너뛴다
                       └ 사이클을 이루는 간선 [1,2] 도 함께 건너뛰어 false 가 나온다
```

> 건너뛰는 것은 **그 정점을 표시하게 한 이웃 하나**다. 그 이웃 번호를 정점마다 기억해 두고,
> 나머지 이웃 중 표시된 것이 나오면 사이클이다.

이제 표시가 여러 갈래에서 어떻게 유지되는지 값으로 확인해 봅시다. 쉬운 경우는 이웃이 하나뿐인
정점이에요 — 한 줄로 이은 그래프에서는 확인할 이웃이 지나온 이웃 하나뿐이라 건너뛰고 끝납니다.
불안한 경우는 **같은 정점을 두 이웃에서 만나는 자리**이고, 네 정점짜리 사각형이 그 모양이에요.

```text
사각형 [0,1] · [1,2] · [2,3] · [3,0] — 표시 배열 전체를 걸음마다 적는다

  시작            표시 0:· 1:· 2:· 3:·   스택 []        아직 아무것도 확인하지 않았다
  0 을 표시       표시 0:✓ 1:· 2:· 3:·   스택 [0]       from [-1]
  0 의 이웃 1     표시 0:✓ 1:✓ 2:· 3:·   스택 [1]       from [0]
  0 의 이웃 3     표시 0:✓ 1:✓ 2:· 3:✓   스택 [1,3]     from [0,0]
  3 을 꺼낸다     표시 0:✓ 1:✓ 2:· 3:✓   스택 [1]       지나온 이웃은 0 이다
  3 의 이웃 2     표시 0:✓ 1:✓ 2:✓ 3:✓   스택 [1,2]     from [0,3]
  3 의 이웃 0     표시 0:✓ 1:✓ 2:✓ 3:✓   지나온 이웃이라 건너뛴다
  2 를 꺼낸다     표시 0:✓ 1:✓ 2:✓ 3:✓   스택 [1]       지나온 이웃은 3 이다
  2 의 이웃 1     1 이 표시돼 있고 지나온 이웃 3 이 아니다 → true
                  └ 정점 1 은 스택에 남아 있고 아직 이웃을 확인하지 않았는데, 표시는 이미
                    돼 있어서 판정에 그대로 쓰인다
```

**표시를 스택에 넣는 자리에서 하는 것이 여기서 값을 합니다.** 정점 1 은 아직 꺼내지도 않았는데
2 가 그것을 표시된 정점으로 읽었고, 그래서 `0 ─ 1` 과 `0 ─ 3 ─ 2 ─ 1` 이라는 두 길이 있다는
사실이 그 자리에서 확정됐어요. 꺼낼 때 표시하면 1 이 아직 표시되지 않은 상태라 이 판정이
성립하지 않습니다.

```text
표시를 언제 하는가에 따라 스택에 들어가는 횟수가 갈린다

  넣을 때 표시한다   정점 하나가 스택에 정확히 한 번 들어간다
  꺼낼 때 표시한다   표시되지 않은 채로 여러 이웃이 같은 정점을 넣을 수 있다
                     └ 사각형에서 정점 1 이 0 과 2 에서 각각 한 번씩 들어간다
```

이 규칙에서는 이웃 항목 하나가 정확히 한 번만 읽힙니다. 표시된 정점은 스택에 다시 들어가지
않으므로 꺼내는 것도 정점마다 한 번이에요. 사이클이 없는 입력 몇 개로 확인해 봅시다.

<!--proof:edge-scan-values-->

```text
입력                            E   확인한 이웃 수      2E   답
한 줄로 이은 10 정점            9               18      18   false
별 모양 10 정점                 9               18      18   false
정점 10 개를 둘씩 짝지은 숲     5               10      10   false
한 줄로 이은 1,000 정점       999            1,998   1,998   false
별 모양 1,000 정점            999            1,998   1,998   false
```

**다섯 줄이 전부 2E 와 같습니다.** 한 줄이든 별 모양이든 여러 덩어리로 나뉜 숲이든, 사이클이
없으면 읽은 이웃 수가 목록 길이의 합과 정확히 같아요. 사이클이 있으면 그 자리에서 반환하므로
그보다 적어집니다 — 전개가 쓰는 여섯 정점에서 7 이었고 목록 길이의 합은 10 이었습니다.

```text
확인한 이웃 수를 두 방식으로 견주면

  간선을 하나씩 지워 본다   한 줄 1,000 정점에서 998,001    E 에 비례하는 일을 E 번 한다
  표시를 한 벌 둔다         한 줄 1,000 정점에서 1,998      항목마다 한 번씩 읽는다
                            └ 999 개의 간선을 999 번이 아니라 한 번 확인한다
```

**절차가 나왔습니다.** 간선 목록을 이웃 목록 둘로 옮기고, 표시되지 않은 정점 하나를 표시해
스택에 넣습니다. 스택에서 정점을 꺼내 이웃 목록을 확인하되 지나온 이웃 하나는 건너뛰고, 표시된
이웃을 만나면 `true`, 표시되지 않은 이웃은 표시해 스택에 넣어요. 스택이 비면 표시되지 않은
다음 정점에서 다시 시작하고, 끝까지 표시된 이웃을 만나지 못하면 `false` 입니다.

### 수행으로 알아보는 알고리즘 — 여섯 정점의 간선 다섯 개를 차례로 확인한다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const n = 6;
const edges: [number, number][] = [[0, 1], [1, 2], [3, 4], [4, 5], [5, 3]];
// 이 절을 끝까지 따라가면 true 가 나온다
```

정점을 왜 여섯으로 뒀을까요? **세 갈래와 바깥 반복의 다시 시작하기가 한 입력에서 모두 실행되기
때문**입니다. 정점 0·1·2 는 한 줄이라 사이클이 없고, 거기서 스택이 한 번 비어 바깥 반복이 정점
3 을 새로 잡습니다. 3·4·5 는 삼각형이라 마지막에 표시된 이웃을 만나 `true` 가 돼요.

```text
undirectedCycleDetection(n, edges):
    간선 [u, v] 마다 nbr[u] 에 v 를, nbr[v] 에 u 를 넣는다
    visited 를 전부 거짓으로 둔다
    정점 s 를 0 번부터 차례로 보면서:
        s 가 표시돼 있으면 넘어간다
        s 를 표시하고 stack 에 넣는다. 짝지은 from 에는 -1 을 넣는다
        stack 이 비지 않은 동안:
            u ← stack 에서 꺼낸 정점, parent ← 짝지은 from 값
            nbr[u] 의 이웃 v 를 차례로:
                v 가 parent 와 같으면 건너뛴다                      ① 지나온 이웃이다
                v 가 표시돼 있으면 true 를 반환한다                 ② 사이클이다
                v 를 표시하고 stack 에 넣는다. from 에는 u 를 넣는다 ③ 처음 본다
    false 를 반환한다
```

#### 1. 간선 목록을 이웃 목록으로 옮긴다

간선 목록에서 「정점 3 과 이어진 정점」을 찾으려면 목록 전체를 다시 읽어야 합니다. 게다가
간선이 `[5,3]` 처럼 적혀 있으면 3 은 뒤쪽에 있어서, 두 자리를 다 확인해야 해요. 간선을 한 번
읽으면서 양쪽 목록에 한 번씩 넣어 두면 그 두 가지가 함께 없어집니다.

```ts
const nbr: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  (nbr[u] as number[]).push(v);
  (nbr[v] as number[]).push(u);
}

const visited: boolean[] = Array.from({ length: n }, () => false);
const stack: number[] = [];
const from: number[] = [];
```

실행하면 이렇게 나옵니다. 간선을 적은 순서가 그대로 목록의 순서가 되는 것이 보여요.

```text
edges = [[0,1], [1,2], [3,4], [4,5], [5,3]]

  nbr[0] = [1]        간선 [0,1] 에서 넣었다
  nbr[1] = [0, 2]     [0,1] 에서 0 을, [1,2] 에서 2 를 넣었다
  nbr[2] = [1]        [1,2] 에서 넣었다
  nbr[3] = [4, 5]     [3,4] 에서 4 를, [5,3] 에서 5 를 넣었다
  nbr[4] = [3, 5]     [3,4] 에서 3 을, [4,5] 에서 5 를 넣었다
  nbr[5] = [4, 3]     [4,5] 에서 4 를, [5,3] 에서 3 을 넣었다
                      └ 목록 길이의 합 10 = 2E

  visited = 0:· 1:· 2:· 3:· 4:· 5:·     아직 아무것도 표시하지 않았다
  stack   = []                          from = []
```

#### 멈춤 — 간선을 한쪽 목록에만 넣어도 될 것 같다

`nbr[v].push(u)` 한 줄이 없어도 될 것 같습니다. 간선 `[u, v]` 를 `u` 의 목록에만 넣어도 어차피
`u` 에서 시작하면 `v` 로 갈 수 있고, 목록 길이의 합이 `E` 로 줄어 일도 절반이 되니까요. 그
오해대로 적으면 이렇게 됩니다.

```ts
// 오해대로 적은 코드 — 적힌 순서대로 한쪽 목록에만 넣는다
for (const [u, v] of edges) (nbr[u] as number[]).push(v);
```

이 코드는 예외를 내지 않습니다. 그리고 **어떤 입력에서는 답까지 같아요.**

<!--proof:mutant-one-sided-->

```text
입력                                    양쪽 목록에 넣는다   한쪽 목록에만 넣는다
전개가 쓰는 여섯 정점                   true                 true
같은 쌍을 [0,1] 과 [1,0] 으로 적은 것   true                 false
이어지지 않은 두 간선 [0,1] · [2,0]     false                true
이어지지 않은 두 간선 [0,1] · [2,1]     false                true
한 줄로 이은 네 정점                    false                false
```

**둘째 줄에서 사이클을 놓치고, 셋째·넷째 줄에서는 없는 사이클을 만들어 냅니다.** 첫째와
다섯째 줄에서는 두 코드의 답이 같아요 — 전개가 쓰는 입력이 그중 하나라, 이 입력만 시험하면
한쪽만 넣어 놓고도 통과합니다.

```text
같은 쌍을 [0,1] 과 [1,0] 으로 적은 것에서 무슨 일이 일어나는가

  양쪽에 넣으면   nbr[0] = [1, 1]   0 의 목록에서 1 을 두 번 만난다        true
  한쪽에만 넣으면 nbr[0] = [1]      0 → 1 로 가고 nbr[1] = [0] 에서 0 은
                                    지나온 이웃이라 건너뛴다              false
                  └ 같은 간선을 두 번 적은 것인데 그것을 못 본다
```

```text
이어지지 않은 두 간선 [0,1] · [2,0] 에서 무슨 일이 일어나는가

  한쪽에만 넣으면   nbr[0] = [1]   nbr[2] = [0]   nbr[1] = []
    0 에서 시작     1 을 표시한다                          표시 {0,1}
    2 에서 시작     2 의 이웃 0 은 이미 표시돼 있다         true — 사이클이 없는데 그렇다
                    └ 정점 2 는 0 에서 갈 수 없는 자리라 다른 덩어리로 읽혔다
```

간선에 방향이 없다는 것은 **적은 순서에 뜻이 없다**는 말입니다. `[2,0]` 과 `[0,2]` 는 같은
간선이어야 하고, 목록 둘에 넣는 것이 그것을 지키는 자리예요.

#### 2. 스택에서 꺼내 이웃을 확인한다

여기가 판정이 일어나는 자리입니다. 스택에서 정점 하나와 짝지은 `from` 값을 함께 꺼내고, 그
정점의 이웃 목록을 차례로 확인해요. 이웃 하나마다 세 갈래 중 하나를 합니다.

```ts
while (stack.length > 0) {
  const u = stack.pop() as number;
  const parent = from.pop() as number;

  for (const v of nbr[u] as number[]) {
    // ① 지나온 이웃이다. 무향 간선은 양쪽 목록에 있어 되돌아가는 것이 사이클이 아니다.
    if (v === parent) continue;

    // ② 이미 표시된 정점이다. 그 정점까지 가는 길이 하나 더 있다는 뜻이라 사이클이다.
    if (visited[v]) return true;

    // ③ 처음 보는 정점이다. 표시하고 스택에 넣는다.
    visited[v] = true;
    stack.push(v);
    from.push(u);
  }
}
```

가장 중요한 줄은 `if (v === parent) continue;` 입니다. 이 한 줄이 방향 없는 간선의 되돌아
가기를 판정에서 빼는 자리예요. 그 아래 `visited[v] = true;` 가 `stack.push(v)` 와 붙어 있는
것도 짝입니다 — 표시와 넣기를 같은 자리에서 해야 스택에 같은 정점이 두 번 들어가지 않아요.

```text
정점 3 을 꺼내고 nbr[3] = [4, 5] 를 차례로 확인한다 — 지나온 이웃은 -1 이다

  v = 4   parent 가 아니다. 표시 안 됐다   ③ 표시하고 스택에 넣는다   from 에 3 을 넣는다
  v = 5   parent 가 아니다. 표시 안 됐다   ③ 표시하고 스택에 넣는다   from 에 3 을 넣는다
          └ 목록이 끝나면 다음 바퀴가 스택에서 5 를 꺼낸다
```

#### 멈춤 — 지나온 「이웃 번호」로는 중복 간선을 놓칠 것 같다

건너뛰는 기준을 이웃 번호로 둔 것이 불안합니다. 같은 정점 쌍을 두 번 잇는 간선이 있으면 목록에
같은 번호가 두 번 들어가고, `v === parent` 는 그 둘을 **모두** 건너뛰니까요. 그러면 두 번째
간선이 만드는 사이클을 못 보는 것 아닐까요. 지나온 **간선 번호**를 기억하면 그 걱정이 없습니다.

```ts
// 걱정대로 고친 코드 — 이웃 번호 대신 지나온 간선 번호를 건너뛴다
for (let i = 0; i < list.length; i += 2) {
  const v = list[i] as number;
  const id = list[i + 1] as number; // 목록에 간선 번호를 함께 담아 둔다
  if (id === entered) continue;
  ...
}
```

두 판정을 같은 입력들에 실행해 봅시다.

```text

같은 쌍을 두 번 이은 간선      true                     true                     true
```

**여섯 줄이 전부 같고, 정점 넷·간선 넷 이하인 다중그래프 11,111 개를 전부 만들어 대조해도 갈린
그래프가 0 개입니다.** 걱정한 일은 일어나지 않아요. 이유는 목록을 **꺼낸 정점 하나에서 한꺼번에
확인하기 때문**입니다.

```text
같은 쌍을 두 번 이은 [0,1] · [0,1] 에서 두 번째 간선이 어디서 확인되는가

  nbr[0] = [1, 1]      nbr[1] = [0, 0]
  0 을 꺼낸다          지나온 이웃은 -1 이라 건너뛸 것이 없다
    첫 이웃 1          표시 안 됐다 → 표시하고 스택에 넣는다
    둘째 이웃 1        이미 표시돼 있고 -1 이 아니다 → true
                       └ 1 을 꺼내기도 전에 0 의 목록에서 확인된다.
                         1 쪽에서 0 을 두 번 건너뛰는 일은 일어나지 않는다
```

같은 쌍을 잇는 간선 둘은 **먼저 꺼내는 끝점의 목록에 나란히** 있습니다. 그 목록을 확인하는
동안 첫 번째가 상대를 표시하고 두 번째가 그 표시를 보므로, 상대 쪽에서 건너뛸 기회가 오기 전에
답이 정해져요. 그래서 이 글은 배열 하나(`from`)로 적고, 목록에 간선 번호를 함께 담지 않습니다.

#### 3. 고정 입력 하나를 아홉 단계로 따라간다

앞의 두 조각을 이어 실제로 실행하면 아홉 단계가 나옵니다. 갈래 `①`·`②`·`③` 이 각각 어디서
실행되는지를 함께 적었어요.

| --- | --- | --- | --- | --- | --- |
| T1 | — | — | — | `visited[0]` 이 **거짓**이라 시작한다 | — |

| T9 | 5 | 3 | 4 | `4 === 3` 이 **거짓**, `visited[4]` 가 **참** | ② |

**세 갈래가 모두 나왔습니다.** 이웃 확인은 T2·T3·T4·T5·T7·T8·T9 의 일곱 번이고, ③ 이 네 번
(T2·T4·T7·T8), ① 이 두 번(T3·T5), 마지막에 ② 가 한 번 실행됩니다. 표시된 정점은 여섯이고
그중 둘(0 과 3)은 바깥 반복이 표시했어요.

```text
①  지나온 이웃이라 건너뛴다      T3 · T5        두 번
②  표시된 정점이라 사이클이다    T9             한 번. 여기서 즉시 반환한다
③  처음 보는 정점이라 표시한다   T2·T4·T7·T8    네 번

이웃 확인 7 < 2E = 10,  ③ 4 + 바깥 반복 2 = 6 = V
                        └ 사이클을 만나 T9 에서 끝났으므로 이웃 항목 셋이 남았다
```

여기서 헷갈리기 쉬운 지점은 T9 입니다. 정점 4 는 T7 에서 표시됐지만 **아직 스택에서 꺼내지
않았어요.** 이웃을 확인하지 않은 정점인데도 표시는 돼 있고, T9 의 판정은 그 표시만 봅니다.
「확인을 마쳤는가」가 아니라 「표시했는가」가 기준이라 이렇게 동작해요.

#### 4. 전체 코드

조각 둘을 하나로 잇습니다. 앞에서 안 나온 것은 **바깥 반복과 마지막 `return false`** 인데,
T6 에서 정점 3 을 다시 잡은 것이 바로 그 바깥 반복이었어요. 표시되지 않은 정점이 남았는지
확인하고 끝을 내는 자리를 여기서 코드로 적습니다.

```ts
export function undirectedCycleDetection(
  n: number,
  edges: [number, number][],
): boolean {
  // 무향 간선 하나는 양쪽에서 걸어갈 수 있다. 두 목록에 한 번씩 넣는다.
  const nbr: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    (nbr[u] as number[]).push(v);
    (nbr[v] as number[]).push(u);
  }

  const visited: boolean[] = Array.from({ length: n }, () => false);
  // stack 과 from 은 같은 자리끼리 짝이다. from[i] 는 stack[i] 를 표시하게 한 이웃이다.
  const stack: number[] = [];
  const from: number[] = [];

  for (let s = 0; s < n; s++) {
    if (visited[s]) continue;
    visited[s] = true;
    stack.push(s);
    from.push(NO_PARENT);

    while (stack.length > 0) {
      const u = stack.pop() as number;
      const parent = from.pop() as number;

      for (const v of nbr[u] as number[]) {
        // ① 지나온 이웃이다. 무향 간선은 양쪽 목록에 있어 되돌아가는 것이 사이클이 아니다.
        if (v === parent) continue;

        // ② 이미 표시된 정점이다. 그 정점까지 가는 길이 하나 더 있다는 뜻이라 사이클이다.
        if (visited[v]) return true;

        // ③ 처음 보는 정점이다. 표시하고 스택에 넣는다.
        visited[v] = true;
        stack.push(v);
        from.push(u);
      }
    }
  }

  return false;
}
```

`NO_PARENT` 는 `-1` 을 가리키는 이름입니다. 정점 번호가 0 부터라 어느 정점과도 같지 않아요.
실행하면 이렇게 나옵니다.

```text
undirectedCycleDetection(4, [[0,1],[1,2],[2,3]])                   →   false

```

### 알아 두면 좋은 개념 — 여분 간선의 개수

전개에서 ③ 으로 지나간 간선이 넷이었고 T9 에서 만난 간선 `[4,5]` 는 그중에 없었습니다. 앞의
넷은 표시를 하나씩 늘렸고 마지막 하나는 이미 표시된 정점 둘을 이었어요. 이 갈림에는 이름이
있습니다 — 앞을 **나무 간선**, 뒤를 **여분 간선**이라고 부릅니다.

<!--proof:circuit-rank-->

```text
입력                                V     E   성분 k   나무 간선   여분 간선   E − V + k
전개가 쓰는 여섯 정점               6     5        2           4           1           1
한 줄로 이은 네 정점                4     3        1           3           0           0
삼각형 세 정점                      3     3        1           2           1           1
고리 둘을 나란히 둔 것              6     6        2           4           2           2
삼각형에 대각선을 더한 사각형       4     5        1           3           2           2
별 모양 1,000 정점              1,000   999        1         999           0           0
```

**여분 간선 칸과 `E − V + k` 칸이 여섯 줄에서 모두 같습니다.** 이 값을 **회로 랭크**라고 부르고,
그래프에서 서로 독립인 고리의 개수를 뜻해요. 사이클이 있는가라는 질문은 「회로 랭크가 1 이상
인가」와 같은 질문입니다.

같은 개념이 이 편 밖에서도 그대로 쓰입니다. **맥케이브 순환 복잡도**는 프로그램의 제어 흐름
그래프에서 `E − V + 2k` 를 세어 분기의 복잡도로 삼는데, 그것은 여기서 센 `E − V + k` 에
덩어리 수를 한 번 더 더한 값이에요. **전기 회로망**에서는 이 값이 그대로 키르히호프 전압
법칙으로 세울 수 있는 독립한 고리 방정식의 개수입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 식으로 무엇이 나오는지, 무엇이
매 순간 참으로 남는지, 그리고 비용이 얼마인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **묻는 것이 있는가 없는가입니다.** 사이클이 있는지만 답하면 되고, 사이클을 전부 세거나 가장
  짧은 것을 찾으라는 것이 아니어야 해요. 세는 문제는 규모가 통째로 다릅니다.
- **간선에 방향이 없습니다.** 방향이 있으면 되돌아가는 간선이 따로 있어야 사이클이 되므로
  판정 자체가 달라져요.
- **그래프를 미리 다 받아 둘 수 있습니다.** 간선을 한 번에 받아 이웃 목록을 만들고 시작하니까요.

```text
세 조건이 코드의 모양을 그대로 정한다
  있는지만 묻는다   → 표시된 이웃을 만나는 순간 반환한다. 나머지를 안 봐도 된다
  방향이 없다       → 지나온 이웃 하나를 기억해야 한다. from 배열이 그 자리다
  미리 다 받는다    → nbr 을 먼저 만들고 그 뒤로는 새 간선을 받지 않는다
```

사이클을 **세는** 문제로 바뀌면 이 절차를 그대로 쓸 수 없다는 것은 값으로 확인됩니다. 여분
간선이 `r` 개인 그래프에는 서로 다른 사이클이 최대 `2^r − 1` 개 있어요 — 회로 랭크가 독립한
고리의 개수이고 그것들을 섞어 새 고리를 만들 수 있기 때문입니다.

```text
같은 그래프에서 두 질문의 비용

  사이클이 있는가      이웃 항목을 한 번씩 확인한다        V + E 에 비례한다
  사이클이 몇 개인가   고리의 조합을 세어야 한다           2^r 규모가 된다
                       └ 정점 100,000 · 간선 100,000 이면 r 이 덩어리 수와 같아 1 이상이고,
                         정점을 50,001 개만 쓰고 한 덩어리로 두면 r 이 50,000 이 된다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "트리인지 확인하라"   "중복 시공"   "닫힌 고리"   "양방향 도로"
  "어떤 두 지점 사이에도 경로가 하나뿐인가"        "네트워크에 순환이 있는가"

제약에 이런 모양이 보이면
  정점과 간선이 각각 10만 규모이고 시간이 1~2초   ← V + E 규모의 절차를 찾으라는 뜻이다
  답이 true / false 하나다                        ← 고리를 적어 낼 필요가 없다는 뜻이다
  자기 자신을 잇는 간선이 있을 수 있다            ← 길이 1 짜리 사이클을 빼먹지 말라는 뜻이다
  같은 쌍을 두 번 잇는 간선이 있을 수 있다        ← 이웃 목록에 같은 번호가 두 번 들어간다
```

반대로 **「간선에 방향이 있다」·「사이클을 이루는 정점을 출력하라」** 가 보이면 이 절차를 그대로
쓰지 않습니다. 앞은 되돌아가는 간선의 뜻이 달라져
[`directedCycleDetection` 가이드](../directedCycleDetection/directedCycleDetection-guide.md)가
다루는 문제가 되고, 뒤는 `from` 을 거슬러 정점을 모으는 일이 더 붙어요.

#### 실제로 쓰이는 곳

- **NetworkX 의 `cycle_basis`** — 파이썬 그래프 라이브러리입니다. 무향 그래프의 독립한 고리를
  모으는 함수인데, 그 안이 이 글과 같은 모양이에요. `networkx/algorithms/cycles.py` 가
  `while stack:  # walk the spanning tree finding cycles` 로 순회를 열고
  `z = stack.pop()  # use last-in so cycles easier to find` 로 스택에서 정점을 꺼냅니다.
  이웃을 확인하는 자리는 `if nbr not in used:  # new node` 와 `elif nbr == z:  # self loops`
  와 `elif nbr not in zused:  # found a cycle` 로 갈리는데, 첫째가 이 글의 ③ 이고 셋째가
  ② 예요. 표시를 넣는 자리도 `used[nbr] = {z}` 로 **스택에 넣을 때**입니다.
  ([networkx/networkx networkx/algorithms/cycles.py](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/cycles.py), 조회 2026-09-03)
- **petgraph 의 `is_cyclic_undirected`** — 러스트 그래프 라이브러리이고, 이 글과 **다른 절차**를
  골랐습니다. `crates/petgraph/src/algo/mod.rs` 의 그 함수는
  `let mut edge_sets = UnionFind::new(g.node_bound());` 로 서로소 집합을 만들고, 간선마다
  `if !edge_sets.union(g.to_index(a), g.to_index(b)) { return true; }` 로 두 끝이 이미 같은
  무리였는지 묻습니다. 문서 주석이 비용을 `Time complexity: amortized **O(|E|)**` 와
  `Auxiliary space: **O(|V|)**` 로 적어 두었는데, 뒤의 값이 이 글의 절차와 갈리는 축이에요 —
  아래 대조에서 값으로 봅니다.
  ([petgraph/petgraph crates/petgraph/src/algo/mod.rs](https://raw.githubusercontent.com/petgraph/petgraph/master/crates/petgraph/src/algo/mod.rs), 조회 2026-09-03)

두 곳이 **같은 문제에 서로 다른 절차를 골랐다**는 것이 이 두 인용의 값입니다. 고리를 모아서
돌려줘야 하는 NetworkX 는 순회를 골랐고, 있는지만 답하는 petgraph 는 서로소 집합을 골랐어요.

#### 경쟁 설계와의 대조

같은 답을 내는 다른 절차가 있습니다. **서로소 집합**이에요 — 이웃 목록을 만들지 않고 간선을
하나씩 받아 두 끝의 뿌리를 견줍니다. 뿌리가 같으면 이미 이어져 있다는 뜻이라 그 간선이 사이클을
닫아요. 위에서 본 petgraph 가 고른 절차이고,
[`unionFind` 가이드](../../../data-structures/disjoint-set/unionFind/unionFind-guide.mdx)가 그
자료구조를 다룹니다.

```text
두 절차가 사이클을 판정하는 자리가 다르다

  이웃 목록 탐색   목록을 다 만든 다음 정점을 따라가다가 표시된 이웃을 만날 때
  서로소 집합      간선을 하나 받을 때마다, 두 끝의 뿌리가 같은지 물을 때
                   └ 앞은 목록을 만드는 값을 먼저 치르고, 뒤는 간선 하나마다 나눠 치른다
```

**전개가 쓰는 입력을 첫 줄에서 그대로 잽니다.** 다만 간선이 다섯뿐이라 「사이클을 닫는 간선이
목록의 몇 번째에 있는가」를 바꿔 볼 자리가 없어 순서가 뒤집히는 것을 보일 수 없어요. 그래서
제약 상한인 정점 100,000 을 쓰는 생성식 셋을 함께 씁니다 — 사이클이 없는 것은 `0-1-…-99,999`
한 줄, 사이클이 있는 것은 정점 0·1·2 를 삼각형으로 잇고 나머지를 한 줄로 이은 그래프이며
**삼각형 간선 셋을 목록의 어느 자리에 끼우는가**만 바꾸고, 마지막 하나는 같은 삼각형을 정점
번호 맨 뒤(99,997·99,998·99,999)에 둔 것입니다. 셋 다
`undirectedCycleDetection-guide.alt.ts` 에 상수로 두었어요. 계수는 배열 칸 접근 수이고, 칸을 한
번 읽으면 1 · 한 번 쓰면 1 로 두 절차에 같은 규칙을 썼습니다.

<!--proof:alt-flip-->

```text
재는 것                                           이웃 목록 탐색   서로소 집합   어느 쪽이 적은가
전개가 쓰는 여섯 정점에서 배열 칸 접근                        81            58   서로소 집합
삼각형 간선이 목록 맨 앞일 때 배열 칸 접근               600,018       200,026   서로소 집합
삼각형 간선이 33,334 번째일 때 배열 칸 접근              600,018       600,018   같다
삼각형 간선이 33,335 번째일 때 배열 칸 접근              600,018       600,030   이웃 목록 탐색
삼각형 간선이 목록 맨 뒤일 때 배열 칸 접근               600,018     1,399,974   이웃 목록 탐색
삼각형이 정점 번호 맨 뒤에 있을 때 배열 칸 접근        1,599,985       200,026   서로소 집합
사이클이 없는 한 줄에서 배열 칸 접근                   1,599,993     1,399,984   서로소 집합
사이클이 없는 한 줄에서 새로 잡는 칸                     400,000       200,000   서로소 집합
```

**순서가 실제로 뒤집힙니다.** 삼각형 간선이 목록 맨 앞이면 600,018 대 200,026 으로 서로소
집합이 3.0 배 적은데, 맨 뒤면 600,018 대 1,399,974 로 이웃 목록 탐색이 2.3 배 적어요. 탐색 쪽
값이 자리와 무관하게 600,018 로 같은 것은 삼각형을 정점 번호 0·1·2 에 두었기 때문입니다 —
바깥 반복이 0 에서 시작하므로 목록의 어디에 적혀 있든 곧바로 만납니다.

```text
뒤집히는 경계를 값으로 댄다 — 탐색 쪽은 자리에 대해 기울기 0, 서로소 집합은 12 인 직선이다

  33,334 번째   600,018 대 600,018   정확히 같다
  33,335 번째   600,018 대 600,030   여기서부터 이웃 목록 탐색이 적다
                └ 경계는 「서로소 집합이 그 간선에 이르기까지 처리한 간선 수」다
```

**내주는 축이 셋입니다.** 하나는 **사이클을 정점 번호 뒤쪽에 둔 입력**이에요 — 삼각형을 정점
99,997·99,998·99,999 에 두면 탐색은 한 줄 전체를 지나가야 해서 1,599,985 대 200,026 으로 크게
밀립니다. 둘째는 **사이클이 없는 입력**으로 1,599,993 대 1,399,984 예요. 셋째는 **새로 잡는
칸**이고 400,000 대 200,000 으로, 이웃 목록의 `2E` 칸이 그 차이입니다 — petgraph 주석의
`Auxiliary space: **O(|V|)**` 가 가리키는 자리가 이것이에요.

```text
어느 축에서 무엇을 내주고 무엇을 얻는가

  사이클이 목록 뒤쪽에서 닫힌다     이웃 목록 탐색이 적다     자리와 무관하게 값이 같다
  사이클이 정점 번호 뒤쪽에 있다    서로소 집합이 적다        탐색은 거기까지 따라가야 한다
  사이클이 없다                     서로소 집합이 적다        1,599,993 대 1,399,984
  새로 잡는 칸                      서로소 집합이 적다        400,000 대 200,000
  사이클을 이루는 정점을 낸다       이웃 목록 탐색이 낸다     from 을 거슬러 모으면 된다
```

**얻는 축은 사이클이 목록 뒤쪽에서 닫히는 입력과 사이클을 이루는 정점을 낼 수 있다는 것**입니다.
서로소 집합은 어느 간선이 사이클을 닫았는지만 알려 주고 그 고리를 이루는 정점 목록은 따로
찾아야 하는데, 이 절차는 `from` 을 거슬러 올라가면 그대로 나와요.

### 수식 정의와 유도

정점 집합 $\mathcal{V}$ 와 간선 집합 $\mathcal{E}$ 로 이루어진 무향 그래프를 $G$ 라 적습니다.
절차가 ③ 으로 지나간 간선의 모임을 $F$, 그래프의 연결 덩어리 수를 $k$ 라 적어요.
**전개의 단계 라벨 `T1`~`T9` 와 겹치지 않게 나무 간선의 모임에는 $F$ 를 씁니다.**
$V$ 와 $E$ 는 기호표에서 정한 그대로 **수**이고 집합이 아니에요. 집합의 크기를 말할 때는
$|\mathcal{V}|$ · $|F|$ 처럼 세로줄로 적어 둘을 가릅니다.

| 이름 | 정의 | 이 그래프에서 |
| --- | --- | --- |
| $G = (\mathcal{V}, \mathcal{E})$ | 무향 그래프 | $\|\mathcal{V}\| = V = 6$, $\|\mathcal{E}\| = E = 5$ |
| $F$ | ③ 으로 지나간 간선의 모임 — 나무 간선 | $\|F\| = 4$ |
| $k$ | 연결 덩어리 수 | $k = 2$ |
| $A(V, E, k)$ | 절차가 읽고 쓴 배열 칸의 총수 | 아래에서 센다 |

먼저 $|F|$ 를 정의 그대로 세어 검산합시다. 간선이 $F$ 에 들어가는 것은 ③ 이 실행될 때뿐이고,
③ 은 표시되지 않은 정점을 표시하는 자리예요.

$$|F| = V - k$$

```text
전개 입력에서 확인한다 — 표시가 일어나는 자리를 전부 적는다

  바깥 반복이 표시한 정점   0 과 3            k = 2 개
  ③ 이 표시한 정점          1 · 2 · 4 · 5     4 개
  표시된 정점의 총수         6 = V            정점마다 한 번뿐이다
                             └ |F| = 6 − 2 = 4 이고 위 표의 나무 간선 칸과 같다
```

이제 **여분 간선이 하나라도 있다는 것과 사이클이 있다는 것이 같다**를 유도합니다. 여분 간선의
수는 $F$ 에 들지 않은 간선의 수예요.

$$|\mathcal{E}| - |F| = E - V + k \;\ge\; 1 \;\;\Longleftrightarrow\;\; G \text{ 에 사이클이 있다}$$

```text
왼쪽에서 오른쪽 — 여분 간선이 있으면 사이클이 있다

  여분 간선 (u, v) 를 잡는다. u 와 v 는 둘 다 표시된 정점이다
  F 는 각 덩어리에서 정점 수보다 하나 적은 간선으로 그 덩어리를 잇는다 (위의 |F| = V − k)
    ┗ 그러니 F 만 따라가도 u 에서 v 로 가는 길이 있다
    ┗ 그 길에 간선 (u, v) 를 이어 붙이면 u 에서 u 로 돌아온다. 같은 간선을 두 번 쓰지 않는다
```

반대 방향은 반대로 가정해서 유도합니다. 여분 간선이 하나도 없다고 하면 모든 간선이 $F$ 에
들어 있고, $F$ 는 각 덩어리에서 정점 수보다 하나 적은 수의 간선으로 그 덩어리를 잇습니다.

```text
오른쪽에서 왼쪽 — 여분 간선이 없으면 사이클도 없다

  덩어리 하나에 정점이 c 개면 F 의 간선은 c − 1 개이고 그 c 개를 전부 잇는다
  c 개를 잇는 데 c − 1 개면 어느 두 정점 사이의 길이 정확히 하나다
    ┗ 길이 둘 이상인 정점 쌍이 없으므로 사이클도 없다
    ┗ 그런 모양을 나무라고 부르고, 덩어리마다 나무 하나가 되어 전체가 숲이 된다
```

여기서 **간선 수만 보고 답이 나오는 경우**가 딸려 나옵니다. 사이클이 없으면 $E = V - k \le V - 1$
이므로, 간선이 정점만큼 있으면 순회를 하기 전에 이미 답이 정해져 있어요.

$$E \ge V \;\;\Longrightarrow\;\; E - V + k \ge k \ge 1 \;\;\Longrightarrow\;\; G \text{ 에 사이클이 있다}$$

```text
작은 값에 넣어 확인한다

  V = 3, E = 3   삼각형          k = 1   여분 간선 3 − 3 + 1 = 1   사이클이 있다
  V = 3, E = 2   한 줄           k = 1   여분 간선 2 − 3 + 1 = 0   사이클이 없다
  V = 6, E = 5   전개가 쓰는 것   k = 2   여분 간선 5 − 6 + 2 = 1   사이클이 있다
                 └ 셋째 줄은 E < V 인데도 사이클이 있다. E ≥ V 는 충분 조건이지 필요 조건이 아니다
```

이제 배열 칸 접근 수 $A(V, E, k)$ 를 코드에서 그대로 셉니다. 사이클이 없어 끝까지 확인하는
경우예요.

$$A(V, E, k) = \underbrace{2V}_{\text{배열 둘}} + \underbrace{4E}_{\text{목록 만들기}} + \underbrace{V}_{\text{바깥 for}} + \underbrace{3k}_{\text{시작하기}} + \underbrace{3V}_{\text{꺼내기}} + \underbrace{2E + 4(V-k)}_{\text{이웃 확인}} = 10V + 6E - k$$

```ts
// 각 항이 어느 줄에서 나오는지 — 왼쪽 수가 그 줄이 만드는 칸 접근 수다.
//   2V   Array.from 두 번 — nbr · visited
//   4E   nbr[u] 읽기 + push + nbr[v] 읽기 + push
//    V   for (let s = 0; s < n; s++) 의 visited[s] 읽기
//   3k   덩어리마다 visited[s] 쓰기 + stack.push + from.push
//   3V   꺼낼 때마다 stack.pop + from.pop + nbr[u] 읽기 — 정점마다 한 번씩
//   2E   이웃 항목마다 그 항목 읽기 + visited[v] 읽기 (① 이면 앞의 하나만)
// 4(V−k) ③ 마다 visited[v] 쓰기 + push 둘, 그리고 그 항목의 visited 읽기
const cellsPerVertex = 10;
const cellsPerEdge = 6;
const closedForm = (V: number, E: number, k: number): number =>
  cellsPerVertex * V + cellsPerEdge * E - k;
```

식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

```text
입력                                      V        E   성분 k   실제 칸 접근   10V + 6E − k
전개 입력에서 간선 [5,3] 을 뺀 것         6        4        2             82             82
간선이 없는 다섯 정점                     5        0        5             45             45
한 줄로 이은 1,000 정점               1,000      999        1         15,993         15,993
별 모양 1,000 정점                    1,000      999        1         15,993         15,993
1,000 정점을 넷씩 가른 숲             1,000      750      250         14,250         14,250
한 줄로 이은 100,000 정점           100,000   99,999        1      1,599,993      1,599,993
```

**여섯 줄이 전부 정확히 맞습니다.** 셋째 줄과 넷째 줄이 같은 값이라는 것도 함께 보세요 — 한
줄과 별 모양은 모양이 완전히 다른데 계수가 같습니다. 이 식에 정점 수도 간선 수도 덩어리 수도
아닌 항이 없기 때문이에요.

마지막으로 제약 규모를 넣습니다. 사이클이 없을 때가 끝까지 확인하는 경우이고, 그때는
$E \le V - 1$ 이라 $V = 100{,}000$ · $E = 99{,}999$ · $k = 1$ 이 상한이에요.

| 항 | 무엇을 세는가 | 그때의 값 |
| --- | --- | --- |
| $10V$ | 배열 둘 · 바깥 반복 · 꺼내기 · 표시하기 | 1,000,000 |
| $6E$ | 목록 만들기 · 이웃 확인하기 | 599,994 |
| $-k$ | 덩어리 하나 | −1 |
| $A$ | 합 | 1,599,993 |
| 간선을 하나씩 지워 보기 | 한 줄 입력에서 $E \times E$ | 9,999,800,001 |

160 만과 100 억을 견주면 이 절차가 무엇을 바꿨는지가 수로 나옵니다. 간선마다 그래프 전체를
다시 확인하던 것을 **이웃 항목마다 한 번씩 확인하는 문제로** 바꾼 것이에요.

### 불변식 — 표시된 정점은 나무 간선으로만 이어져 있다

파트 1 에서 코드가 동작하는 것을 아홉 단계로 봤습니다. 그런데 그건 입력 하나에서 맞았다는
뜻이지 언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고,
그것이 실제로 유지되는지 확인해 봅시다.

> 이웃 하나를 확인하고 넘어갈 때마다, 지금까지 표시된 정점들은 처음 보는 이웃을 표시하며 지나온
> 간선만으로 서로 이어져 있고, 그 간선의 수는 **표시된 정점 수에서 지금까지 바깥 반복이 시작한
> 횟수를 뺀 값**과 정확히 같습니다. 그리고 그 간선들만 보면 사이클이 없습니다.

```text
                     표시된 정점             표시하며 지나온 간선
                   ┌───────────────┐   ┌─────────────────────────┐
   T8 직후         │  0·1·2·3·4·5  │   │ [0,1] [1,2] [3,4] [5,3] │
                   └───────────────┘   └─────────────────────────┘
                          6          =              4              +      2
                     표시된 정점 수           나무 간선 수            시작한 횟수
```

「이웃 하나를 확인하고 넘어갈 때마다」가 중요합니다. 순회가 끝난 뒤 한 번만 참인 것이 아니라
**갈래 하나를 실행한 직후마다** 참이라는 뜻이에요. 그래야 다음 확인이 그 성질을 그대로
이어받습니다.

**출발점부터 봅시다.** 바깥 `for` 문이 표시되지 않은 정점 `s` 를 표시하고 스택에 넣는 순간,
그 덩어리에서 표시된 정점은 `s` 하나이고 지나온 간선은 없습니다. 1 = 1 + 0 이고 간선이 없으니
사이클도 없어요. 그 뒤로 상태를 바꾸는 갈래는 셋입니다.

| 무슨 일 | 무엇이 바뀌는가 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| 지나온 이웃이라 건너뛴다 | 아무것도 바뀌지 않는다 | 표시도 간선 모임도 그대로다 |
| 표시된 이웃을 만난다 | `true` 를 반환하고 끝난다 | 상태를 바꾸지 않는다. 이 간선은 $F$ 에 들어가지 않는다 |
| 표시되지 않은 이웃을 표시한다 | 표시가 하나 늘고 간선이 하나 는다 | 양쪽이 하나씩 늘어 차가 그대로다. 새 간선의 한 끝은 방금까지 표시되지 않은 정점이라 그 간선이 고리를 만들 수 없다 |

셋째 줄의 「고리를 만들 수 없다」가 이 불변식의 핵심입니다. 표시되지 않은 이웃을 표시하는 갈래가
잇는 두 정점 중 하나는 **그 순간까지 어느 간선과도 이어지지 않은 정점**이라, 그 정점을 지나는
길은 방금 만든 간선 하나뿐이고, 길이 하나뿐인 정점은 고리에 들어갈 수 없어요.

```text
T7 과 T8 에서 차가 유지되는 것을 값으로 확인한다

  T6 직후   표시 4 개 (0·1·2·3)     나무 간선 2 개 ([0,1] [1,2])   시작 2 회   4 = 2 + 2
  T7 직후   표시 5 개 (…·4)         나무 간선 3 개 (+[3,4])        시작 2 회   5 = 3 + 2
  T8 직후   표시 6 개 (…·5)         나무 간선 4 개 (+[5,3])        시작 2 회   6 = 4 + 2
            └ 표시하는 갈래가 표시와 간선을 같은 자리에서 하나씩 늘리므로 차가 안 바뀐다
```

이 불변식이 답의 정확성을 그대로 줍니다. 표시된 이웃을 만났다는 것은 나무 간선만으로 이미 이어져
있는 두 정점을 잇는 간선을 하나 더 찾았다는 뜻이라 사이클이고, 끝까지 표시된 이웃을 만나지
못했다면 모든 간선이 나무 간선이라 사이클이 없어요.

**모든 간선이 나무 간선이 되는지는 한 번 더 확인해야 합니다.** 간선 하나는 이웃 항목 둘로
나타나는데, 표시된 이웃을 한 번도 만나지 않고 끝났다면 그 둘이 각각 건너뛰기이거나 표시하기예요.
둘 다 건너뛰기인 간선은 있을 수 없습니다.

```text
간선 (u, v) 의 두 항목이 모두 건너뛰기라고 하면

  u 의 목록에서 v 를 건너뛰었다    from 이 v 다 = u 는 v 에서 표시됐다
  v 의 목록에서 u 를 건너뛰었다    from 이 u 다 = v 는 u 에서 표시됐다
                                    └ 서로가 서로보다 먼저 표시됐다는 말이라 성립하지 않는다
                                      그러니 한쪽은 표시하기이고, 그 간선은 나무 간선이다
```

경계에 있는 입력들도 확인하고 갑시다.

| 입력 | 어디서 처리되는가 | 결과 |
| --- | --- | --- |
| 정점 하나 `undirectedCycleDetection(1, [])` | `nbr[0]` 이 비어 바로 스택이 빈다 | `false` |
| 간선 없음 `undirectedCycleDetection(5, [])` | 다섯 정점이 각각 한 번씩 시작한다 | `false` |
| 자기 자신 `undirectedCycleDetection(2, [[0,0]])` | `nbr[0]` 에 0 이 두 번 들어가고 첫 항목에서 표시된 이웃을 만난다 | `true` |
| 같은 쌍 두 번 `undirectedCycleDetection(2, [[0,1],[0,1]])` | `nbr[0]` 의 둘째 항목에서 표시된 이웃을 만난다 | `true` |

| 한 줄 100,000 정점 | 스택 깊이가 배열 길이라 호출 깊이 제한을 받지 않는다 | `false` |

자기 자신을 잇는 간선이 이 절차의 경계입니다. 간선 `[v, v]` 는 `nbr[v]` 에 `v` 를 **두 번**
넣는데, `v` 는 스택에 들어갈 때 이미 표시됐으므로 첫 항목에서 바로 표시된 이웃을 만나요. 시작
정점이면 `from` 이 `-1` 이라 건너뛰기로 새지도 않습니다.

**이제 깨뜨려 봅시다.** 「표시된 정점은 나무 간선으로만 이어져 있다」를 지키던 줄은 지나온
이웃을 건너뛰는 줄입니다. 그 줄이 없으면 되돌아가는 이웃 항목이 표시된 이웃을 만나는 갈래로
들어가고, 나무 간선 하나가 여분 간선으로 잘못 세어져요.

답이 갈리지 않습니다. 그런 입력만 시험하면 이 줄을 지워 놓고도 통과해요.

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 일은 스택에서 정점 하나를 꺼내 그 이웃 목록을 확인하는 것뿐입니다. 전개의
값으로 확인하면 꺼낸 정점이 0·1·2·3·5 의 다섯이었고, 이웃 확인이 T2·T3·T4·T5·T7·T8·T9 의
일곱 번이었어요.

```text
바퀴   꺼낸 정점   확인한 이웃          해당 단계
1      0           1                    T2
2      1           0 · 2                T3 · T4
3      2           1                    T5
4      3           4 · 5                T7 · T8
5      5           4                    T9 — 여기서 반환한다
       └ 정점 4 는 T7 에서 표시됐지만 꺼내기 전에 T9 가 반환했다
```

그러니 꺼내는 횟수는 **표시된 정점 수 이하**이고, 이웃을 확인하는 횟수는 **목록 길이의 합
`2E` 이하**입니다. 사이클이 없으면 둘 다 등호가 되고, 사이클을 먼저 만나면 그만큼 작아져요.
그 앞에 이웃 목록을 만드는 비용이 붙습니다.

```text
총식 = 배열 둘 만들기 + 목록 채우기 + 바깥 for + 꺼내기 + 이웃 확인 + 표시하기
       Θ(V)            Θ(E)          Θ(V)       Θ(V)     Θ(E')      Θ(V)
                                                          ↑ E' 는 반환하기 전까지 확인한 이웃 항목 수
     = Θ(V + E)

메모리 = nbr Θ(V + E) + visited·stack·from Θ(V) = Θ(V + E)
```

여기서 센 것은 **배열 칸을 읽고 쓴 횟수**입니다. `nbr[u].push(v)` 와 `stack.push(v)` 가 안에서
칸을 다시 잡는 비용은 세지 않았어요 — 정점 하나가 스택에 들어가는 것도 간선 하나가 목록에
들어가는 것도 전체에서 정해진 횟수라, 분할 상환하면 위 식의 규모를 바꾸지 않습니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면 안 돼요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (첫 이웃 항목이 자기 자신을 잇는 간선이다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않았다) | `O(V + E)` | `Θ(V + E)` |
| **최악의 경우** (사이클이 없다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값입니다.** 어떤 입력이 와도 이웃 목록을 만드는 데 `Θ(V + E)` 가 들고, 그것이
그대로 하한이에요. 간선 하나를 목록에 넣지 않고 넘어가는 경로가 없기 때문입니다.

```text
케이스가 갈리는 것은 규모가 아니라 상수배다 — 정점 100,000 으로 고정하고 잰다

  사이클이 없다 (E = 99,999)          목록 만들기 + 배열 둘 + 순회 전부    1,599,993
  정점 0·1·2 가 삼각형이다            목록 만들기 + 배열 둘 + 두 바퀴      600,018
                                       └ 규모는 둘 다 V + E 이고 계수만 2.7 배 갈린다
```

**평균을 따로 계산할 대상이 없습니다.** 사이클을 언제 만나는가가 순회의 길이를 바꾸기는 하지만,
그 앞에 놓인 `2V + 4E` 가 어떤 입력에서도 치러지므로 기댓값이 `Θ(V + E)` 를 벗어날 수 없어요.
「평균이 정의되지 않는다」가 아니라 **분포와 무관하게 같다**는 쪽입니다.

```text
최악 보장     어떤 입력에도 V + E 규모를 넘지 않는다         ← 이 절차
기댓값 보장   구현이 만드는 무작위성이나 입력 분포에 기댄다  ← 이 절차는 여기 해당하지 않는다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 없고 입력 분포에 대한 가정도 없어서, 같은
간선 목록을 두 번 넣으면 반환값도 계수도 글자 그대로 같은 값이 나와요. 경계의 종류로 보면
`Θ(V + E)` 가 상한이자 하한입니다 — 간선 하나를 목록 둘에 넣는 일을 건너뛸 수 없으므로
그보다 적게 할 방법이 없고, 위에서 센 대로 그보다 많이 하지도 않습니다.

#### 최악을 만드는 입력

「제약 상한을 둘 다 채우면 최악」이라는 통념부터 확인합시다. 정점 100,000 개와 간선 100,000 개를
함께 채우면 $E \ge V$ 이고, 위에서 유도한 대로 그런 그래프에는 **사이클이 반드시 있어요.**
사이클이 있으면 만나는 자리에서 순회가 끝나므로 오히려 일이 줄어듭니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 간선을 하나씩 지워 그래프 전체를 다시 확인하던
것을 **정점마다 표시 하나를 두는 것**으로 바꿨고, 무향 간선이 양쪽 목록에 들어가므로 **지나온
이웃 하나만 건너뛰면**, 표시된 이웃을 만나는 순간 답이 정해집니다.

```text
간선 목록 → nbr 둘로 나눠 넣기 → 표시 안 된 정점에서 시작 → 꺼내서 이웃 확인 → 표시하고 넣기
              └ 목록 길이 합 2E   └ 바깥 for 가 V 번   └ ① 건너뛰기   └ ② 만나면 true
```

먼저 답이 붙는 문제 하나입니다. 전개에서는 한 줄이 정점 0·1·2 이고 삼각형이 3·4·5 였습니다.
T6 에서 바깥 반복이 정점 3 을 다시 잡은 것이 그 때문이었어요. 정점 번호를 서로 바꿔 삼각형을
0·1·2 에, 한 줄을 3·4·5 에 두면 확인한 이웃 수와 반환값이 어떻게 될까요?


- 불변식은 「표시된 정점 수 = 나무 간선 수 + 시작한 횟수」라고 말합니다. 그러면 순회가 `false`

- 여분 간선의 개수는 `E − V + k` 였습니다. 정점 100,000 개와 간선 100,000 개인 그래프에서 이
  값이 가장 작아지는 것은 어떤 모양일 때이고, 그때에도 사이클이 반드시 있다고 말할 수 있습니까.
