# 최대 유량 — 역방향 항목으로 앞서 보낸 유량을 되돌리고, 레벨 그래프로 최단 경로만 골라 한 라운드에 다 보낸다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 유량을
전수로 배정해 보는 방법에서 출발해 레벨 그래프의 차단 유량을 쓰는 디닉까지 가고, 그 방법을 준비되는
차례대로 값으로 풉니다. 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**유량 네트워크**는 간선마다 **용량**이 붙은 방향 그래프입니다. 용량은 그 간선으로 보낼 수 있는 양의
상한이에요. 정점 하나가 소스(출발), 다른 하나가 싱크(도착)이고, 소스에서 싱크로 얼마나 보낼 수
있는지를 묻습니다. 정점 여섯 · 간선 일곱인 네트워크에 그리면 이렇습니다.

<!--fig:concept-network-->
![전개 입력 — 간선 옆 수는 용량](./figs/concept-network.svg)

간선마다 실제로 보낸 양을 **유량**이라고 부릅니다. 유량은 두 조건을 지켜야 해요.

| 조건 | 지켜야 하는 것 | 어기면 |
| --- | --- | --- |
| 용량 제한 | 간선마다 유량이 용량 이하다 | 간선이 감당하지 못하는 양을 보낸 것이 된다 |
| 보존 | 소스와 싱크를 뺀 정점마다 들어온 양과 나간 양이 같다 | 중간 정점에 쌓이거나, 없던 양이 생긴다 |

두 조건을 지키면서 싱크에 도착하는 양을 가장 크게 만든 것이 **최대 유량**입니다. 같은 네트워크의 최대
유량 한 벌을 그렸어요. 굵은 선은 용량만큼 찬 간선입니다.

<!--fig:concept-maxflow-->
![최대 유량 한 벌 — 간선 옆 수는 유량/용량](./figs/concept-maxflow.svg)

정점마다 들어온 양과 나간 양을 세어 두 조건을 확인하면 이렇습니다.

<!--proof:conceptFlow-->

| 정점 | 들어온 유량 | 나간 유량 | 들어온 것 − 나간 것 |
| --- | ---: | ---: | ---: |
| 0 (소스) | 0 | 5 | -5 |
| 1 | 4 | 4 | 0 |
| 2 | 2 | 2 | 0 |
| 3 | 1 | 1 | 0 |
| 4 | 3 | 3 | 0 |
| 5 (싱크) | 5 | 0 | 5 |

소스가 내보낸 양은 5 이고 싱크가 받은 양은 5 입니다. 중간 정점 4 개는 모두 들어온 양과 나간 양이 같고, 용량을 넘은 간선은 0 개입니다. 정본이 낸 최대 유량은 5 입니다.

<!--/proof-->

답을 만드는 배정은 하나뿐이 아닐 수 있지만, 그 최댓값은 네트워크가 정합니다. 이 글은 그 값을 **경로를
하나씩 찾아 보내는 방식**으로 구합니다. 소스에서 싱크까지 가는 길을 찾고, 그 길의 남은 용량 가운데 가장
작은 값(**병목**)만큼 보내요.

이때 쓰는 구조가 **잔여 그래프**입니다. 간선마다 「더 보낼 수 있는 양」과 「앞서 보낸 것 중 되돌릴 수
있는 양」을 따로 적어 둔 그래프예요. 원래 간선 `u → v` 하나가 정방향 항목 `u → v`(잔여 = 용량 −
유량)와 역방향 항목 `v → u`(잔여 = 유량) 둘이 됩니다. 두 항목에 적힌 수를 **잔여 용량**이라고 불러요.
경로 `0 → 1 → 2 → 5` 에 2 를 보낸 직후의 잔여 그래프가 이렇습니다.

<!--fig:concept-residual-->
![경로 하나를 보낸 뒤의 잔여 그래프](./figs/concept-residual.svg)

실선이 정방향 항목, 대시 선이 역방향 항목입니다. 보낸 경로의 정방향 잔여가 2 씩 줄었고, 같은 자리의
역방향 항목에 2 가 생겼어요. 흐린 선은 잔여가 0 이라 지금은 지날 수 없는 항목입니다. 역방향 항목이 있으면
나중에 찾은 경로가 앞서 보낸 유량을 줄일 수 있습니다.

잔여 그래프에서 잔여가 양수인 항목만 따라 소스에서 싱크까지 가는 길을 **증가 경로**라고 부릅니다. 증가
경로가 하나도 없으면 더 보낼 방법이 없고, 그때의 유량이 최대예요. 남은 것은 증가 경로를 어떤 차례로
고르는가이고, 이 글의 절차 **디닉**(Dinic)은 소스에서 간선 수가 가장 적은 경로부터 고릅니다. 그
차례를 정하는 것이 **레벨**입니다. 잔여 그래프에서 소스로부터 각 정점까지의 최단 간선 수예요.

<!--fig:concept-levels-->
![라운드 1 의 레벨](./figs/concept-levels.svg)

레벨이 정확히 한 칸 오르는 항목만 남긴 그래프를 **레벨 그래프**라고 부릅니다. 레벨 그래프 위의 경로는
전부 간선 수가 싱크의 레벨과 같고, 그것이 최단입니다. 디닉은 레벨을 한 번 매기고, 그 레벨 그래프에서
증가 경로를 더 못 찾을 때까지 보내요. 레벨을 한 번 매겨 하는 이 일 한 벌을 **라운드**라고 부르고,
한 라운드가 끝난 유량을 **차단 유량**이라고 부릅니다. 같은 네트워크에서 라운드마다 한 일을 적었어요.

<!--proof:conceptRounds-->

| 라운드 | 싱크의 레벨 | 보낸 증가 경로 목록 | 보낸 양 | 누적 유량 |
| --- | ---: | --- | ---: | ---: |
| 라운드 1 | 3 | 0 → 1 → 2 → 5 · 0 → 1 → 4 → 5 | 4 | 4 |
| 라운드 2 | 5 | 0 → 3 → 2 → 1 → 4 → 5 | 1 | 5 |
| 라운드 3 | 없음 | 없음 | 0 | 5 |

싱크의 레벨이 라운드마다 3 → 5 로 커지고, 라운드 3 에서 싱크에 레벨이 붙지 않아 끝납니다. 최대 유량은 5 입니다.

<!--/proof-->

라운드가 하나 끝날 때마다 싱크의 레벨이 반드시 커지고, 그 레벨은 정점 수를 넘지 못합니다. 그래서 라운드
수가 정점 수보다 작고, 전체 비용은 정점 수의 제곱에 간선 수를 곱한 값 안쪽인 $O(V^2 E)$ 입니다.

| 할 일 | 하는 일 | 몇 번 |
| --- | --- | --- |
| 잔여 그래프 만들기 | 간선마다 정방향 · 역방향 항목 한 쌍 | 한 번 |
| 레벨 매기기 | 잔여 그래프에 BFS | 라운드마다 한 번 |
| 차단 유량 만들기 | 레벨이 한 칸씩 오르는 경로를 찾아 병목만큼 보낸다 | 라운드마다 더 못 찾을 때까지 |
| 끝내기 | 싱크에 레벨이 안 붙으면 멈춘다 | 한 번 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **너비 우선 탐색(BFS)으로 최단 간선 수를 구하는 법.** 큐에 넣고 앞에서 꺼내면 꺼내는 차례가 거리
  오름차순이 된다는 성질을 씁니다. 모르면 [`bfsShortestPath` 가이드](../../graph/bfsShortestPath/bfsShortestPath-guide.md)를 보세요.
- **깊이 우선 탐색과 재귀 호출.** 증가 경로를 찾을 때 한 정점에서 항목 하나를 골라 내려갔다가, 실패하면
  돌아와 다음 항목을 고릅니다.
- **인접 리스트.** 정점마다 나가는 간선 목록 하나를 두는 표현입니다. 모르면
  [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **배열의 첨자 접근이 `O(1)` 이라는 것.** 이 글은 항목 하나를 목록 안의 **자리 번호**로 가리키고, 그
  번호로 짝이 되는 항목을 한 번에 찾아갑니다.

이름이 비슷한 과제를 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 이 글에서 |
| --- | --- |
| 소스에서 싱크로 보낼 수 있는 최대 양 | 다룬다 |
| 소스와 싱크를 가르려면 끊어야 하는 용량의 최솟값 | 끝에서 이름만 붙인다 — [`minCut`](../minCut/minCut-guide.md) |
| 두 무리를 짝지어 만들 수 있는 최대 쌍 수 | 다루지 않는다 — [`maxBipartiteMatching`](../maxBipartiteMatching/maxBipartiteMatching-guide.md) |
| 간선마다 단위 비용이 붙은 최대 유량의 최소 비용 | 다루지 않는다 — [`minCostMaxFlow`](../minCostMaxFlow/minCostMaxFlow-guide.md) |

### 아이디어를 떠올리는 과정 — 유량 배정 전수 조사에서 레벨 그래프의 차단 유량까지

아이디어를 찾기 전에 무엇을 만들지부터 정해 둡시다. 함수 하나가 네트워크를 받아 최대 유량을 돌려줍니다.

```ts
function maxFlow(
  n: number,
  edges: [number, number, number][],
  source: number,
  sink: number,
): { flow: number };
```

- 입력: 정점 수 `n`, 방향 간선 목록 `edges`(원소 `[u, v, c]` 는 `u` 에서 `v` 로 가는 용량 `c` 의 간선),
  소스 `source`, 싱크 `sink`. 정점 번호는 0 부터 `n − 1` 까지예요.
- 출력: `{ flow }`. `flow` 는 소스에서 싱크로 보낼 수 있는 최대 유량이고, 소스와 싱크가 같으면 0 입니다.
- 규모: 정점 500 개 · 간선 10,000 개 · 용량 1,000,000 까지로 잡습니다. 정점이 간선보다 한 자릿수 이상
  적은 네트워크이고, 이 크기에서 방법마다 연산 수가 자릿수로 갈리는 것을 보일 수 있어서 이 값을 골랐어요.
  비용은 흔한 채점 환경의 예산인 1 초에 대어 잽니다.

입력에는 이런 모양이 섞여 들어올 수 있고, 코드는 셋 다 받아 내야 합니다.

| 모양 | 생김새 | 예 |
| --- | --- | --- |
| 평행 간선 | 같은 두 정점 사이에 간선이 여럿 | `[0,1,5]` 와 `[0,1,7]` |
| 자기 루프 | `u` 와 `v` 가 같은 간선 | `[0,0,100]` |
| 용량 0 | 처음부터 보낼 수 없는 간선 | `[0,1,0]` |

이 글에서 쓰는 기호는 여덟 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` | `2 ≤ V ≤ 500` |
| `E` | 간선 수. 코드의 `edges.length` | `0 ≤ E ≤ 10,000` |
| `c(u,v)` | 간선 `u → v` 의 용량 | `0 ≤ c ≤ 1,000,000` |
| `s` | 소스 정점 번호. 코드의 `source` | `0 ≤ s < V` |
| `t` | 싱크 정점 번호. 코드의 `sink` | `0 ≤ t < V` |
| `cap(u,v)` | 항목 `u → v` 의 잔여 용량. 코드의 간선 항목 `cap` 필드 | 정방향은 `c(u,v)`, 역방향은 0 에서 시작 |
| `level[v]` | 잔여 그래프에서 `s` 부터 `v` 까지의 최단 간선 수. 코드의 `level` 배열 | 도달 못 하면 `-1` |
| `iter[v]` | 이 라운드에서 `v` 의 목록 중 다음에 볼 자리. 코드의 `iter` 배열 | 0 에서 시작해 뒤로만 간다 |

가장 먼저 떠오르는 방법으로 시작합시다. 「간선마다 얼마를 보낼지 0 부터 용량까지 하나씩 넣어 보고,
두 조건을 지키는 배정 중 싱크 도착량이 가장 큰 것을 고른다」예요. 가짓수가 유한하니 답은 반드시 나옵니다.
가짓수는 간선마다 `c + 1` 가지를 곱한 값입니다.

<!--proof:bruteScale-->

| 간선 E | 용량 상한 c | 유량 배정의 가짓수 (c+1)^E | 자릿수 |
| ---: | ---: | ---: | ---: |
| 2 | 3 | 16 | 2 |
| 5 | 10 | 161,051 | 6 |
| 100 | 1,000 | 1,001^100 | 301 |
| 10,000 | 1,000,000 | 1,000,001^10,000 | 60,001 |

규모의 상한에서 배정의 가짓수가 60,001 자리입니다. 1 초에 10 억 개씩 본다고 해도 자릿수가 아홉만 줄어 59,992 자리 초가 걸립니다.

<!--/proof-->

배정을 한꺼번에 고르지 말고 **경로를 하나 찾아 보내고, 또 찾아 보내는** 쪽으로 가 봅시다. 용량이 전부
1 인 정점 넷 그래프(다리 그래프)에서 해 볼게요. 위 갈래 `0 → 1 → 3` 과 아래 갈래 `0 → 2 → 3` 을 다리
`1 → 2` 가 잇습니다.

<!--fig:origin-bridge-->
![다리 그래프](./figs/origin-bridge.svg)

길을 찾아 병목만큼 보내고 그 길의 남은 용량을 줄이는 것만 하면 이렇게 됩니다.

<!--proof:greedyBridge-->

| 차례 | 찾은 경로 | 병목 | 누적 유량 | 잔여가 0 이 된 간선 |
| --- | --- | ---: | ---: | --- |
| 경로 1 | 0 → 1 → 2 → 3 | 1 | 1 | 0→1 · 1→2 · 2→3 |
| 경로 2 | 찾지 못한다 | - | 1 | - |

되돌리지 않으면 경로 1 개를 보내고 멈춰 유량이 1 입니다. 정본이 낸 답은 2 입니다.

<!--/proof-->

첫 경로가 다리 `1 → 2` 를 써 버렸고, 그 뒤로는 소스에서 나가는 `0 → 2` 가 남아 있어도 `2 → 3` 이 막혀
더 갈 곳이 없습니다. 위 갈래와 아래 갈래를 하나씩 쓰면 2 인데, **앞서 보낸 것을 고칠 자리가 없어서** 1
에서 멈춘 거예요. 그래서 보낸 만큼 반대 방향 항목의 잔여를 늘려 둡니다. 같은 그래프에 다시 걸면 이렇습니다.

<!--proof:cancelBridge-->

| 차례 | 찾은 경로 | 병목 | 지난 반대 방향 항목 | 누적 유량 |
| --- | --- | ---: | --- | ---: |
| 경로 1 | 0 → 1 → 2 → 3 | 1 | 안 지난다 | 1 |
| 경로 2 | 0 → 2 → 1 → 3 | 1 | 2→1 | 2 |

두 번째 경로가 반대 방향 항목 2→1 을 지나고, 유량 2 가 정본의 답 2 와 같습니다.

<!--/proof-->

두 번째 경로의 `2 → 1` 이 첫 경로가 다리로 보낸 1 을 되돌립니다. 두 경로를 합치면 다리에는 아무것도 안
실리고, 위 갈래와 아래 갈래에 1 씩 실린 것과 같아요. 되돌리는 쪽과 안 되돌리는 쪽을 입력 셋에서
실행해 답을 나란히 놓았습니다.

<!--proof:cancelValues-->

| 입력 | 되돌리지 않는 쪽 | 되돌리는 쪽 | 정본 |
| --- | ---: | ---: | ---: |
| 다리 그래프 | 1 | 2 | 2 |
| 전개 입력 | 4 | 5 | 5 |
| 용량이 다른 다리 그래프 | 5 | 5 | 5 |

세 입력 중 2 개에서 되돌리지 않는 쪽의 답이 정본보다 작고, 1 개에서는 답이 같습니다.

<!--/proof-->

답이 같은 입력이 있다는 것을 봐 주세요. 되돌릴 자리를 안 만들어도 통과하는 입력이 있어서, 답을 대조하지
않으면 잘못된 코드를 그대로 두게 됩니다.

이제 비용이 무엇에 달렸는지 봅시다. 위 방법은 「길을 하나 찾는다」에서 **어느 길인지**를 정하지 않았어요.
다리 그래프의 네 갈래 간선에 용량 `c` 를 주고, 간선 목록의 차례만 두 가지로 둔 채 경로 수를 셌습니다.
다리를 나중에 보는 차례는 `[0→1, 1→3, 0→2, 2→3, 1→2]`, 먼저 보는 차례는 `[0→1, 0→2, 1→2, 1→3, 2→3]`
입니다.

<!--proof:edgeOrder-->

| 용량 c | 다리를 나중에 본다 · 경로 수 | 간선 검사 | 다리를 먼저 본다 · 경로 수 | 간선 검사 | 유량 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 2 | 9 | 2 | 15 | 2 |
| 4 | 2 | 9 | 4 | 24 | 8 |
| 100 | 2 | 9 | 4 | 24 | 200 |
| 1,000,000 | 2 | 9 | 4 | 24 | 2,000,000 |

용량 4 에서 순서만 바꾸면 경로 수가 2 개에서 4 개로 늘고, 용량을 1,000,000 으로 키워도 두 순서의 경로 수가 그대로입니다.

<!--/proof-->

값을 정한 것은 용량이 아니라 **경로를 고르는 차례**였습니다. 차례가 값을 정한다면 차례를 규칙으로 정해야
해요. 후보는 셋입니다. 되돌릴 자리를 두고 처음 찾은 경로에 보내는 「아무 경로」(포드–풀커슨), 경로 하나마다
BFS 로 간선 수가 가장 적은 경로를 다시 찾는 「경로마다 BFS」(에드먼즈–카프), 그리고 BFS 한 번이 매긴 레벨로
경로를 여러 개 찾는 「레벨 그래프」입니다. 넷 모두 같은 규칙으로 **항목을 한 번 읽은 횟수**(간선 검사)를
셌어요.

<!--proof:threeRules-->

| 입력 | 아무 경로 | 경로마다 BFS | 레벨 그래프 | 유량 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 (V=6 · E=7) | 33 | 54 | 73 | 5 |
| 격자 (V=202 · E=570) | 1,402 | 11,466 | 1,662 | 100 |
| 계단 (V=51 · E=99) | 6,225 | 10,048 | 18,723 | 50 |
| 부채꼴 128 (V=131 · E=257) | 8,769 | 65,793 | 1,156 | 128 |

간선 검사가 가장 적은 규칙은 네 입력 중 아무 경로가 3 개, 경로마다 BFS 가 0 개, 레벨 그래프가 1 개입니다.

<!--/proof-->

어느 규칙이 적은지는 입력마다 갈립니다. 그러면 무엇으로 고를까요. 같은 모양에서 크기만 키웠을 때 **몇
배가 되는가**입니다. 소스에서 나온 길이 여러 가닥으로 갈리는 부채꼴 그래프에서 가닥 수만 늘렸어요.

<!--proof:branchScale-->

| 부채꼴 가닥 | 정점 V | 간선 E | 아무 경로 | 경로마다 BFS | 레벨 그래프 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 7 | 9 | 27 | 73 | 40 |
| 16 | 19 | 33 | 201 | 1,057 | 148 |
| 64 | 67 | 129 | 2,337 | 16,513 | 580 |
| 128 | 131 | 257 | 8,769 | 65,793 | 1,156 |

가닥을 4 에서 128 로 32 배 늘렸을 때 간선 검사가 아무 경로는 325 배, 경로마다 BFS 는 901 배, 레벨 그래프는 29 배가 됩니다.

<!--/proof-->

셋의 차이는 BFS 를 몇 번 하는가에서 나옵니다. 네 입력에서 BFS 횟수를 세면 이렇습니다.

<!--proof:bfsCounts-->

| 입력 | 증가 경로 수 | 경로마다 BFS 의 BFS 횟수 | 레벨 그래프의 BFS 횟수 |
| --- | ---: | ---: | ---: |
| 전개 입력 | 3 | 4 | 3 |
| 격자 | 10 | 11 | 2 |
| 계단 | 50 | 51 | 51 |
| 부채꼴 128 | 128 | 129 | 2 |

네 입력 모두 경로마다 BFS 의 BFS 횟수가 증가 경로 수보다 1 많습니다. 부채꼴 128 에서는 BFS 가 129 번 대 2 번입니다.

<!--/proof-->

경로마다 BFS 를 하는 규칙은 BFS 횟수가 언제나 증가 경로 수보다 하나 많습니다. 레벨 그래프 규칙은 BFS
횟수가 라운드 수이고, 계단처럼 라운드마다 경로가 하나뿐인 모양에서만 둘이 같아져요. 지금까지 해 본
방법 다섯을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 다섯](./figs/origin-approaches.svg)

남은 방법이 **레벨 그래프의 차단 유량**이고, 이것을 쓰는 절차가 디닉입니다. 아직 확인하지 않은 것이
있어요. 잔여 그래프와 레벨 그래프가 정확히 어떻게 생겼는지, 한 라운드 안에서 경로를 어떻게 빠짐없이
찾는지, 왜 라운드가 끝나는지입니다. 다음 절에서 실현하는 차례대로 확인합니다.

### 아이디어 상세 — 레벨 그래프의 차단 유량

이 아이디어를 한 문장으로 줄이면 이렇습니다. **간선마다 정방향 · 역방향 항목을 둔 잔여 그래프에 BFS 로
레벨을 매기고, 레벨이 한 칸씩 오르는 항목만 따라 증가 경로를 더 못 찾을 때까지 보내는 일을 싱크에 레벨이
안 붙을 때까지 되풀이합니다.** 이 방법은 잔여 그래프와 레벨 그래프라는 두 개념 위에서 동작하는데, 처음
보는 사람에게는 둘 다 낯설어요. 두 개념을 먼저 따로 설명하고, 그다음 앞 단계에서 만든 것을 뒤 단계에서
쓰는 차례로 다섯 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 잔여 그래프 만들기 | 간선마다 항목 한 쌍과 짝의 자리 | — |
| 라운드마다 | 2단계 레벨 매기기 | 잔여가 양수인 항목으로 BFS | 1단계의 잔여 용량 |
| 라운드 안에서 경로마다 | 3단계 증가 경로 하나 보내기 | 레벨이 한 칸 오르는 항목으로 DFS, 병목만큼 두 잔여 고치기 | 2단계의 레벨 · 1단계의 짝 자리 |
| 라운드 안에서 | 4단계 차단 유량까지 되풀이하기 | `iter` 로 실패한 항목을 건너뛰며 0 이 올라올 때까지 | 3단계 |
| 라운드가 끝날 때 | 5단계 끝낼지 정하기 | 싱크에 레벨이 없으면 끝낸다 | 2단계의 레벨 |

#### 먼저 알아 둘 개념 — 잔여 그래프

잔여 그래프는 **간선마다 더 보낼 수 있는 양과 되돌릴 수 있는 양을 따로 적은 그래프**입니다. 원래 간선
`u → v` 하나가 항목 둘이 돼요. 정방향 항목 `u → v` 에는 `c(u,v) − 유량` 을, 역방향 항목 `v → u` 에는
유량을 적습니다. 잔여가 0 인 항목은 지금 지날 수 없는 항목이에요.

##### 입력 위의 잔여 그래프

전개 입력에서 라운드 1 이 끝난 직후의 잔여 그래프입니다. 항목 14 개를 모두 그렸어요.

<!--fig:build-residual-->
![라운드 1 이 끝난 잔여 그래프](./figs/build-residual.svg)

정방향 항목 셋(`0 → 1` · `1 → 2` · `2 → 5`)이 흐린 선입니다. 그 자리의 역방향 항목에는 잔여가 생겼어요.
보낸 유량이 없는 `0 → 3` · `3 → 2` 는 정방향만 잔여가 있고 역방향은 흐린 선입니다.

##### 항목 한 쌍을 읽는 법

간선 `1 → 2` 를 골라 두 항목을 읽어 보겠습니다. 용량에서 정방향 잔여를 빼면 지금 실린 유량이고, 그 값이
역방향 잔여와 같아요.

<!--proof:residualReadOne-->

| 읽는 것 | 자리 | 그 자리의 수 |
| --- | --- | ---: |
| 용량 | c(1,2) | 2 |
| 지금 실린 유량 | 용량 − 정방향 잔여 | 2 |
| 정방향 항목의 잔여 | 1→2 | 0 |
| 역방향 항목의 잔여 | 2→1 | 2 |

1 에서 2 로 더 보낼 수 있는 양이 0 이고, 앞서 보낸 2 가운데 2 쪽에서 1 쪽으로 되돌릴 수 있는 양이 2 입니다.

<!--/proof-->

##### 짝끼리의 관계

같은 간선에서 나온 두 항목은 서로 짝입니다. 한쪽으로 `d` 를 보내면 그 항목의 잔여가 `d` 줄고 짝의 잔여가
`d` 늘어요. 그래서 두 잔여의 합은 언제나 처음 용량입니다. 일곱 쌍을 모두 재면 이렇습니다.

<!--proof:residualPairs-->

| 간선 | 용량 | 유량 | 정방향 잔여 | 역방향 잔여 | 두 잔여의 합 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0→1 | 4 | 4 | 0 | 4 | 4 |
| 1→2 | 2 | 2 | 0 | 2 | 2 |
| 2→5 | 2 | 2 | 0 | 2 | 2 |
| 0→3 | 3 | 0 | 3 | 0 | 3 |
| 3→2 | 4 | 0 | 4 | 0 | 4 |
| 1→4 | 5 | 2 | 3 | 2 | 5 |
| 4→5 | 3 | 2 | 1 | 2 | 3 |

7 쌍 중 7 쌍에서 두 잔여의 합이 용량과 같습니다. 항목 14 개 중 잔여가 양수인 항목은 9 개입니다.

<!--/proof-->

평행 간선이 있으면 간선마다 쌍이 따로 생깁니다. 같은 두 정점 사이에 쌍이 둘 있어도 서로의 잔여를 건드리지
않아요.

##### 용량만 줄인 그래프와의 차이

잔여 그래프를 처음 보면 **원래 그래프에서 보낸 만큼 용량만 줄인 그래프**로 읽기 쉽습니다. 역방향 항목을
빼고 읽는 거예요. 같은 상태에서 두 그래프로 소스에서 갈 수 있는 정점을 재 보았습니다.

<!--proof:residualVsShrunk-->

| 그래프 | 소스에서 갈 수 있는 정점 | 싱크까지 가는 길 | 끝까지 보냈을 때의 유량 |
| --- | --- | --- | ---: |
| 잔여 그래프 (역방향 항목 포함) | {0, 1, 2, 3, 4, 5} | 0 → 3 → 2 → 1 → 4 → 5 | 5 |
| 용량만 줄인 그래프 | {0, 2, 3} | 없음 | 4 |

같은 상태에서 역방향 항목을 빼면 소스에서 정점 3 개까지만 가고 싱크에 못 갑니다. 역방향 항목을 넣으면 정점 6 개에 모두 가고, 싱크까지 경로가 남아 있습니다.

<!--/proof-->

용량만 줄인 그래프에서는 라운드 1 뒤에 싱크로 가는 길이 없어 유량이 4 에서 멈춥니다. 잔여 그래프에서는
역방향 항목 `2 → 1` 을 지나는 길이 남아 있어요. 그 길이 앞서 `1 → 2` 로 보낸 것을 줄이면서 1 을 더
보냅니다.

##### 이렇게 생긴 까닭

앞서 보낸 유량이 나중에 잘못이었다고 판명될 수 있기 때문입니다. 「아이디어를 떠올리는 과정」의 다리
그래프에서 첫 경로가 다리를 쓴 것이 그랬어요. 역방향 항목이 그 유량을 되돌릴 자리이고, 잔여를 한 쌍으로
두면 되돌리는 일도 「잔여가 양수인 항목을 지난다」는 같은 규칙 하나로 처리됩니다.

| 모양 | 앞서 보낸 유량 | 다리 그래프의 답 |
| --- | --- | --- |
| 용량만 줄인 그래프 | 고칠 수 없다 | 1 |
| 잔여 그래프 | 역방향 항목으로 줄일 수 있다 | 2 |

#### 먼저 알아 둘 개념 — 레벨 그래프

레벨 그래프는 **잔여 그래프에서 레벨이 정확히 한 칸 오르는 항목만 남긴 그래프**입니다. 레벨은 잔여가
양수인 항목만 지나며 BFS 로 잰 소스로부터의 최단 간선 수예요. 레벨이 같거나 내려가는 항목, 잔여가 0 인
항목은 뺍니다.

##### 입력 위의 레벨 그래프

전개 입력의 라운드 1 과 라운드 2 의 레벨 그래프를 한 장씩 그렸습니다. 정점 안의 수가 레벨이에요.

<!--fig:build-levels-->
![라운드마다의 레벨 그래프](./figs/build-levels.svg)

라운드 1 에서는 원래 간선 일곱이 모두 남습니다. 라운드 2 에서는 잔여가 양수인 항목이 늘었는데도 남은
항목이 다섯이고, 그중 하나가 역방향 항목 `2 → 1` 이에요.

##### 정점 하나의 레벨을 읽는 법

라운드 2 의 정점 1 을 골라 레벨이 어디서 왔는지 따라가 보겠습니다. BFS 가 레벨을 적게 한 항목을
소스까지 거슬러 올라가면 이렇습니다.

<!--proof:levelReadOne-->

| 정점 | 레벨 | 레벨을 적게 한 항목 | 항목의 방향 | 그 항목의 잔여 |
| --- | ---: | --- | --- | ---: |
| 0 | 0 | 시작 | - | - |
| 3 | 1 | 0→3 | 정방향 | 3 |
| 2 | 2 | 3→2 | 정방향 | 4 |
| 1 | 3 | 2→1 | 역방향 | 2 |

라운드 2 에서 정점 1 의 레벨은 3 이고, 마지막에 지난 항목이 역방향 항목입니다. 라운드 1 에서 정점 1 의 레벨은 1 이었습니다.

<!--/proof-->

정점 1 은 소스에서 곧바로 가는 `0 → 1` 이 이미 차서 라운드 2 에서는 멀리 돌아 들어옵니다. 레벨은 잔여
그래프가 바뀌면 다시 재야 하는 값이에요.

##### 항목끼리의 관계

레벨 그래프에 남은 항목은 모두 레벨을 정확히 한 칸 올립니다. 그러니 레벨 그래프 위에서 소스부터 싱크까지
가는 경로는 어느 것이든 간선 수가 싱크의 레벨과 같아요. 두 라운드에서 남긴 항목과 뺀 항목, 경로 수를
셌습니다.

<!--proof:levelEdges-->

| 라운드 | 싱크의 레벨 | 잔여가 양수인 항목 | 레벨 그래프에 남긴 항목 | 뺀 항목 | 소스→싱크 경로 수 |
| --- | ---: | ---: | --- | ---: | ---: |
| 라운드 1 | 3 | 7 | 0→1 · 1→2 · 2→5 · 0→3 · 3→2 · 1→4 · 4→5 | 0 | 3 |
| 라운드 2 | 5 | 9 | 0→3 · 3→2 · 1→4 · 4→5 · 2→1 | 4 | 1 |

두 라운드 모두 레벨 그래프의 소스→싱크 경로가 전부 싱크의 레벨만큼 간선을 지납니다.

<!--/proof-->

##### BFS 트리와의 차이

레벨 그래프를 처음 보면 **BFS 트리**, 곧 BFS 가 각 정점에 레벨을 적게 한 항목만 남긴 나무로 읽기
쉽습니다. 라운드 1 의 BFS 트리를 그렸어요.

<!--fig:build-bfs-tree-->
![라운드 1 의 BFS 트리](./figs/build-bfs-tree.svg)

두 모양에서 소스→싱크 경로를 세면 이렇습니다.

<!--proof:levelVsTree-->

| 모양 | 항목 수 | 소스→싱크 경로 목록 | 경로 수 |
| --- | ---: | --- | ---: |
| BFS 트리 | 5 | 0 → 1 → 2 → 5 | 1 |
| 레벨 그래프 | 7 | 0 → 1 → 2 → 5 · 0 → 1 → 4 → 5 · 0 → 3 → 2 → 5 | 3 |

BFS 트리에는 소스→싱크 경로가 1 개이고 레벨 그래프에는 3 개입니다. 레벨 그래프의 경로는 모두 간선 3 개를 지납니다.

<!--/proof-->

BFS 트리는 정점마다 들어오는 항목을 하나만 남기므로, `3 → 2` 처럼 같은 레벨 차이를 잇는 다른 항목을
버립니다. 레벨 그래프는 그런 항목을 전부 남기므로 BFS 한 번으로 경로를 여러 개 찾을 수 있어요.

##### 이렇게 생긴 까닭

두 요구를 한 번에 채우려는 것입니다. 하나는 **BFS 한 번으로 최단 경로를 여러 개** 쓰는 것이고, 이것은
BFS 트리가 아니라 한 칸 오르는 항목 전부가 있어야 됩니다. 다른 하나는 경로가 **같은 정점을 두 번 지나지
않는** 것이에요. 레벨이 매 걸음 한 칸씩 오르면 되돌아갈 수 없으니, 경로를 찾는 재귀의 깊이가 싱크의 레벨을
넘지 않습니다.

| 요구 | 레벨 그래프가 채우는 방법 |
| --- | --- |
| 최단 경로를 BFS 한 번으로 여럿 | 한 칸 오르는 항목을 모두 남긴다 |
| 경로가 같은 정점을 되풀이하지 않는다 | 레벨이 걸음마다 한 칸씩 오른다 |

#### 1단계 — 간선 하나를 정방향 · 역방향 두 항목으로 담기

정점마다 목록을 하나 두고, 간선 `u → v` 마다 `u` 의 목록에 정방향 항목을, `v` 의 목록에 역방향 항목을
넣습니다. 두 항목은 짝이 상대 목록에서 몇 번째 자리에 있는지(`rev`)를 서로 적어 둬요. 유량을 보낼 때 짝을
찾으러 목록을 다시 읽지 않으려는 것입니다. 전개 입력에서 만든 목록은 이렇습니다.

<!--proof:stageBuild-->

| 정점 | 정방향 항목 | 역방향 항목 | 목록 길이 |
| --- | --- | --- | ---: |
| 0 | 0→1 잔여 4 · 0→3 잔여 3 | 없음 | 2 |
| 1 | 1→2 잔여 2 · 1→4 잔여 5 | 1→0 잔여 0 | 3 |
| 2 | 2→5 잔여 2 | 2→1 잔여 0 · 2→3 잔여 0 | 3 |
| 3 | 3→2 잔여 4 | 3→0 잔여 0 | 2 |
| 4 | 4→5 잔여 3 | 4→1 잔여 0 | 2 |
| 5 | 없음 | 5→2 잔여 0 · 5→4 잔여 0 | 2 |

목록 길이의 합은 14 이고 간선 7 개의 두 배입니다. 역방향 항목 7 개는 모두 잔여 0 으로 시작합니다.

<!--/proof-->

크기는 여기서 정해집니다. 항목은 정확히 `2E` 개이고, 목록 길이의 합도 `2E` 예요. 자기 루프는 두 항목이 같은
목록에 들어가므로, 짝의 자리는 넣기 직전의 목록 길이를 **각각** 읽어 두어야 합니다.

#### 2단계 — BFS 로 레벨 매기기

라운드를 시작할 때 `level` 을 전부 `-1` 로 지우고 소스에만 0 을 적은 뒤, 큐에서 정점을 꺼내 목록의 항목을
읽습니다. 잔여가 양수이고 머리에 아직 레벨이 없으면 레벨을 하나 올려 적고 큐 뒤에 넣어요. 가장 쉬운 경우인
라운드 1 과, 역방향 항목이 레벨을 잇는 라운드 2 를 함께 적었습니다.

<!--proof:stageBfs-->

| 라운드 | 꺼낸 정점 | 레벨을 적은 정점 (지난 항목) | 꺼낸 뒤 큐 |
| --- | --- | --- | --- |
| 라운드 1 | 0 | 1 에 1 (0→1) · 3 에 1 (0→3) | [1, 3, 2, 4, 5] |
|  | 1 | 2 에 2 (1→2) · 4 에 2 (1→4) | [3, 2, 4, 5] |
|  | 3 | 없음 | [2, 4, 5] |
|  | 2 | 5 에 3 (2→5) | [4, 5] |
|  | 4 | 없음 | [5] |
|  | 5 | 없음 | [] |
| 라운드 2 | 0 | 3 에 1 (0→3) | [3, 2, 1, 4, 5] |
|  | 3 | 2 에 2 (3→2) | [2, 1, 4, 5] |
|  | 2 | 1 에 3 (2→1 역방향) | [1, 4, 5] |
|  | 1 | 4 에 4 (1→4) | [4, 5] |
|  | 4 | 5 에 5 (4→5) | [5] |
|  | 5 | 없음 | [] |

레벨을 적으며 지난 역방향 항목은 라운드 1 에서 0 개, 라운드 2 에서 1 개입니다.

<!--/proof-->

라운드 2 에서 정점 1 은 역방향 항목 `2 → 1` 로 레벨 3 을 받습니다. BFS 는 정방향과 역방향을 가리지 않고
「잔여가 양수인가」만 봐요. 큐는 한 라운드에 정점을 많아야 `V` 개 담고, BFS 는 목록 길이의 합인 `2E` 개
항목을 많아야 한 번씩 읽습니다.

#### 3단계 — 증가 경로 하나를 찾아 병목만큼 보내기

DFS 가 소스에서 출발해, 잔여가 양수이고 레벨이 정확히 한 칸 큰 항목을 골라 내려갑니다. 내려갈 때마다
지금까지의 병목을 그 항목의 잔여와 비교해 작은 쪽을 들고 가요. 싱크에 도착하면 병목을 올려보내고,
올라오는 길의 항목마다 잔여를 병목만큼 줄이고 짝의 잔여를 병목만큼 늘립니다. 라운드 1 의 첫 경로에서
항목마다 바뀐 잔여는 이렇습니다.

<!--proof:stagePath-->

| 지난 항목 | 레벨 | 그 항목의 잔여 | 짝 항목의 잔여 |
| --- | --- | --- | --- |
| 0→1 | 0 → 1 | 4 → 2 | 1→0 0 → 2 |
| 1→2 | 1 → 2 | 2 → 0 | 2→1 0 → 2 |
| 2→5 | 2 → 3 | 2 → 0 | 5→2 0 → 2 |

병목은 min(4, 2, 2) = 2 이고, 경로의 항목 3 개가 모두 잔여가 2 줄고 짝의 잔여가 2 늘었습니다.

<!--/proof-->

짝의 잔여가 늘어나는 것이 곧 1단계에서 둔 되돌릴 자리를 채우는 일이에요. 병목만큼 줄이므로 병목이 된
항목은 잔여가 0 이 되고, 그 항목은 이 라운드에서 다시 지날 수 없습니다.

#### 4단계 — 차단 유량이 될 때까지 되풀이하기

3단계를 0 이 올라올 때까지 되풀이하면 그 라운드의 차단 유량이 됩니다. 되풀이할 때 이미 실패한 항목을 다시
읽지 않으려고, 정점마다 「다음에 볼 자리」 `iter[v]` 를 둡니다. 성공한 항목에서는 `iter` 를 옮기지 않고,
조건에 안 맞거나 아래에서 0 이 올라온 항목에서만 한 칸 옮겨요. 가장 쉬운 경우인 라운드 1 과, 역방향 항목을
지나는 경로가 나오는 라운드 2 를 함께 적었습니다.

<!--proof:stageBlock-->

| 걸음 | 라운드 | 증가 경로 | 병목 | 잔여가 0 이 된 항목 | 누적 유량 |
| --- | --- | --- | --- | --- | ---: |
| T3 | 라운드 1 | 0 → 1 → 2 → 5 | min(4, 2, 2) = 2 | 1→2 · 2→5 | 2 |
| T4 | 라운드 1 | 0 → 1 → 4 → 5 | min(2, 5, 3) = 2 | 0→1 | 4 |
| T5 | 라운드 1 | 0 이 올라온다 (들어간 정점 0 → 3 → 2) | - | - | 4 |
| T7 | 라운드 2 | 0 → 3 → 2 → 1 → 4 → 5 | min(3, 4, 2, 3, 1) = 1 | 4→5 | 5 |
| T8 | 라운드 2 | 0 이 올라온다 (들어간 정점 0 → 3 → 2 → 1 → 4) | - | - | 5 |

라운드 1 은 경로 2 개, 라운드 2 는 경로 1 개를 보낸 뒤 0 이 올라와 끝납니다. 역방향 항목을 지난 경로는 라운드 2 의 1 개입니다.

<!--/proof-->

`iter` 가 뒤로만 가도 되는 근거는 한 라운드 안에서 판정이 바뀌지 않는다는 데 있습니다.

| 판정에 쓰는 것 | 라운드 안에서 | 그래서 |
| --- | --- | --- |
| 레벨 | 라운드 시작에 한 번만 적힌다 | 레벨 조건의 판정이 고정된다 |
| 정방향 항목의 잔여 | 보낼 때 줄기만 한다 | 0 이 된 항목은 0 으로 남는다 |
| 늘어나는 짝의 잔여 | 레벨이 한 칸 아래를 가리키는 항목이다 | 레벨 조건에서 걸러진다 |

라운드 1 동안 `iter` 가 지나온 자리를 세면 이렇습니다.

<!--proof:stageIter-->

| 정점 | 목록 길이 | 라운드 1 동안 iter | 라운드 1 이 끝날 때 |
| --- | ---: | --- | ---: |
| 0 | 2 | 0 → 2 | 2 |
| 1 | 3 | 0 → 1 → 2 | 2 |
| 2 | 3 | 0 → 1 → 3 | 3 |
| 3 | 2 | 0 → 2 | 2 |
| 4 | 2 | 0 → 1 | 1 |
| 5 | 2 | 0 | 0 |

라운드 1 이 끝날 때 iter 의 합은 10 이고 목록 길이의 합 14 를 넘지 않습니다. 자리를 앞으로 되돌린 정점은 0 개입니다.

<!--/proof-->

한 라운드의 `iter` 는 정점마다 많아야 목록 길이만큼 가므로, 실패한 항목을 읽는 횟수가 라운드당 `2E` 를
넘지 않습니다.

#### 5단계 — 싱크에 레벨이 안 붙으면 끝내기

차단 유량이 되면 다시 2단계로 가서 레벨을 새로 매깁니다. BFS 가 싱크에 레벨을 못 적으면 잔여 그래프에
증가 경로가 없다는 뜻이라 반복을 끝내요. 라운드마다 레벨이 붙은 정점을 적었습니다.

<!--proof:stageStop-->

| 라운드 | level | 레벨이 붙은 정점 | 다음 일 |
| --- | --- | --- | --- |
| 라운드 1 | [0, 1, 2, 1, 2, 3] | {0, 1, 2, 3, 4, 5} | 증가 경로를 찾는다 |
| 라운드 2 | [0, 3, 2, 1, 4, 5] | {0, 1, 2, 3, 4, 5} | 증가 경로를 찾는다 |
| 라운드 3 | [0, 3, 2, 1, 4, -1] | {0, 1, 2, 3, 4} | 반복을 끝낸다 |

라운드 3 에서 싱크 5 에 레벨이 붙지 않아 반복이 끝납니다. 라운드 수 3 은 정점 수 6 보다 작습니다.

<!--/proof-->

「전체 컨셉」의 라운드 표에서 싱크의 레벨이 3 에서 5 로 커졌습니다. 라운드가 끝날 때마다 싱크의 레벨이
반드시 커진다는 것은 「수식 정의와 유도」에서 유도하고, 여기서는 그 결과만 씁니다. 싱크의 레벨은 `V − 1`
을 넘을 수 없으니 유량을 보내는 라운드는 `V − 1` 번 이하예요.

#### 이 방법이 기대는 전제

레벨 그래프의 차단 유량은 아래 세 전제에 기대고 있어서, 하나라도 빠지면 답이 틀리거나 끝나지 않습니다.
셋 다 코드 한 줄이 지키고, 그 줄을 바꾸면 무엇이 나오는지는 「수행으로 알아보는 알고리즘」의 짚고 가기 둘과
「불변식」의 깨뜨려 보기가 실행 결과로 보여 줍니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 보낸 만큼 짝의 잔여가 늘어난다 | 3단계의 두 잔여 고치기 | 앞서 보낸 유량을 되돌리지 못해 답이 작아진다 |
| DFS 는 레벨이 정확히 한 칸 오르는 항목만 지난다 | 3단계의 내려가기 | 왔던 정점으로 되돌아가 재귀가 끝나지 않는다 |
| `iter` 는 라운드마다 0 으로 돌아간다 | 4단계 | 다음 라운드에서 아무 항목도 안 읽어 반복이 끝나지 않는다 |

#### 다섯 단계를 이은 절차

다섯 단계를 코드의 차례로 다시 적으면 이렇습니다.

1. 간선마다 정방향 항목(잔여 = 용량)과 역방향 항목(잔여 0)을 짝지어 넣는다(1단계)
2. BFS 로 `level` 을 적는다(2단계)
3. `level[t]` 가 `-1` 이면 지금까지의 유량을 돌려주고 끝낸다(5단계)
4. `iter` 를 0 으로 두고, DFS 로 증가 경로를 찾아 병목만큼 보내기를 0 이 올라올 때까지 되풀이한다(3 · 4단계)
5. 2 로 돌아간다

### 수행으로 알아보는 알고리즘 — 정점 여섯 네트워크에서 두 라운드로 유량 5 를 보낸다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 정해 끝까지 가져가되, 조각을
하나 만들 때마다 그 조각만 실행한 결과를 확인하고 넘어갑니다.

```ts
const n = 6;
const edges: [number, number, number][] = [
  [0, 1, 4], [1, 2, 2], [2, 5, 2], [0, 3, 3], [3, 2, 4], [1, 4, 5], [4, 5, 3],
];
const source = 0;
const sink = 5;
// 이 절이 끝나면 { flow: 5 } 가 나와야 한다
```

이 입력을 고른 까닭은 두 번째 라운드가 **역방향 항목을 실제로 지나기** 때문입니다. 뒤에서 역방향을 안 늘리는
변이를 적용해 보면 이 입력에서만 답이 갈리는데, 그런 입력으로 전개하지 않으면 이 알고리즘의 핵심 갈래가 한
번도 실행되지 않아요.

```text
maxFlow(n, edges, source, sink):
    간선 [u, v, c] 마다 정방향(잔여 c)과 역방향(잔여 0)을 짝지어 넣는다
    반복:
        BFS 로 level 을 적는다                                   ① 레벨을 적는다
        level[sink] 가 -1 이면 지금까지의 유량을 돌려준다        ⑥ 끝낸다
        iter 를 전부 0 으로 둔다
        반복:
            DFS 로 증가 경로 하나를 찾아 병목만큼 보낸다          ② 내려간다 · ③ 싱크 · ④ 두 잔여를 고친다 · ⑤ 다음 항목
            0 이 올라오면 이 라운드를 끝낸다
```

#### 1. 간선 하나를 두 항목으로 나눠 담는다

간선 `u → v` 하나가 잔여 그래프에서는 항목 **둘**이 됩니다. 둘이 서로의 자리 번호를 알고 있어야 유량을 보낼
때 한 번에 양쪽을 고칠 수 있어요.

```ts
interface Edge { to: number; cap: number; rev: number }

const graph: Edge[][] = Array.from({ length: n }, () => []);
const link = (u: number, v: number, c: number): void => {
  const out = graph[u] as Edge[];
  const back = graph[v] as Edge[];
  const iOut = out.length;
  out.push({ to: v, cap: c, rev: 0 });
  const iBack = back.length;
  back.push({ to: u, cap: 0, rev: iOut });
  (out[iOut] as Edge).rev = iBack;
};
for (const [u, v, c] of edges) link(u, v, c);
```

실행하면 이렇게 나옵니다. 정점 1 의 목록에 정방향 둘과 역방향 하나가 섞여 있어요.

<!--proof:walkGraph-->

```text
graph[0] = [ {to:1, cap:4, rev:0}, {to:3, cap:3, rev:0} ]
graph[1] = [ {to:0, cap:0, rev:0}, {to:2, cap:2, rev:0}, {to:4, cap:5, rev:0} ]
graph[2] = [ {to:1, cap:0, rev:1}, {to:5, cap:2, rev:0}, {to:3, cap:0, rev:1} ]
graph[3] = [ {to:0, cap:0, rev:1}, {to:2, cap:4, rev:2} ]
graph[4] = [ {to:1, cap:0, rev:2}, {to:5, cap:3, rev:1} ]
graph[5] = [ {to:2, cap:0, rev:1}, {to:4, cap:0, rev:1} ]
항목 14 개 = 간선 7 개 × 2
```

여기서 가장 중요한 줄은 `const iBack = back.length;` 입니다. `iOut` 과 `iBack` 을 push 직전에 각각 읽어
두는 것이 자기 루프 때문이에요. `u` 와 `v` 가 같으면 두 항목이 같은 목록에 들어가는데, 짝의 자리를 한 번만
읽으면 정방향이 자기 자신을 가리키게 됩니다.

#### 2. BFS 로 레벨을 적는다

레벨은 **잔여가 양수인 항목만** 지나며 잰 최단 간선 수입니다. 잔여가 0 인 항목을 지나면 실제로는 못 가는
길에 레벨이 붙고, 그 레벨을 믿고 내려간 DFS 는 아무것도 못 보낸 채 되돌아옵니다.

```ts
const level: number[] = Array.from({ length: n }, () => -1);

function bfs(): void {
  level.fill(-1);
  level[source] = 0;
  const queue: number[] = [source];
  let head = 0;
  while (head < queue.length) {
    const u = queue[head++] as number;
    for (const e of graph[u] as Edge[]) {
      // ① 잔여 용량이 있고 아직 레벨이 없는 정점 — 레벨을 적고 큐 뒤에 넣는다.
      if (e.cap > 0 && (level[e.to] as number) === -1) {
        level[e.to] = (level[u] as number) + 1;
        queue.push(e.to);
      }
    }
  }
}
```

#### 3. 레벨이 한 칸 오르는 항목만 따라 내려간다

DFS 는 지금 정점에서 「잔여가 있고 레벨이 정확히 한 칸 큰」 항목을 골라 내려갑니다. 싱크에 도착하면 지금까지의
병목을 올려보내고, 올라온 값이 양수면 그 항목의 잔여를 줄이고 짝의 잔여를 늘려요.

```ts
function dfs(u: number, pushed: number): number {
  // ③ 싱크에 도착했다 — 여기까지의 병목값을 그대로 올려보낸다.
  if (u === sink) return pushed;
  for (const e of graph[u] as Edge[]) {
    // ② 잔여 용량이 있고 레벨이 정확히 한 칸 큰 간선 — 그 간선으로 내려간다.
    if (e.cap > 0 && (level[e.to] as number) === (level[u] as number) + 1) {
      const d = dfs(e.to, Math.min(pushed, e.cap));
      // ④ 아래에서 양수가 올라왔다 — 짝지은 두 잔여 용량을 갱신하고 그대로 올려보낸다.
      if (d > 0) {
        const back = (graph[e.to] as Edge[])[e.rev] as Edge;
        e.cap -= d;
        back.cap += d;
        return d;
      }
    }
  }
  return 0;
}
```

라운드 1 에서 이 조각만 두 번 부르면 이렇게 나옵니다. 괄호 안이 그 항목의 잔여예요.

<!--proof:walkDfs-->

```text
1 번째   0 →(4)→ 1 →(2)→ 2 →(2)→ 5   병목 2   0→1 2 · 1→2 0 · 2→5 0
2 번째   0 →(2)→ 1 →(5)→ 4 →(3)→ 5   병목 2   0→1 0 · 1→4 3 · 4→5 1
누적 유량 4
```

#### 짚고 가기 — 레벨 조건은 속도를 위한 것이라 빼도 답은 맞을 것 같다

`level[e.to] === level[u] + 1` 을 `level[e.to] !== -1` 로 느슨하게 바꾸면 어떻게 될까요? 레벨이 있는 정점이면
어디로든 내려가니 경로를 더 쉽게 찾을 것 같습니다. 실제로 용량이 다른 다리 그래프에서는 **답이 그대로
나옵니다.** 그래도 고쳐야 하는 까닭이 나머지 두 입력에 있어요.

<!--proof:looseLevel-->

| 입력 | 정본 | 레벨이 있기만 하면 내려가는 판 | 판정 |
| --- | ---: | --- | --- |
| 용량이 다른 다리 그래프 | 5 | 5 | 같다 |
| 다리 그래프 | 2 | 재귀가 끝나지 않는다 | 다르다 |
| 전개 입력 | 5 | 재귀가 끝나지 않는다 | 다르다 |

세 입력 중 둘은 끝나지 않습니다. 레벨 조건을 빼면 왔던 정점으로 돌아가는 항목도 조건을 통과하고, 그 자리에서
재귀가 같은 정점들을 계속 부르게 돼요. 전개 입력에서 재귀가 들어간 정점을 적으면 이렇습니다.

<!--proof:looseCycle-->

| 자취 | 정점 |
| --- | --- |
| 재귀가 마지막으로 들어간 정점 열두 개 | 3 → 2 → 1 → 0 → 3 → 2 → 1 → 0 → 3 → 2 → 1 → 0 |
| 되풀이하는 마디 | 3 → 2 → 1 → 0 → 3 |

재귀 깊이를 400 에서 잘랐고, 그때까지 같은 마디가 되풀이됐습니다.

<!--/proof-->

마디의 `1 → 0` 은 라운드 1 의 `0 → 1` 에 실린 유량을 되돌리는 역방향 항목입니다. **레벨 조건은 속도가 아니라
끝나는 것을 보장하는 조건이에요.** 레벨이 한 칸씩만 오르면 경로가 같은 정점을 두 번 지날 수 없어서, 재귀
깊이가 `level[t]` 를 넘지 않습니다.

#### 4. 실패한 항목을 그 라운드에서 다시 안 본다

3 번의 `dfs` 는 부를 때마다 `graph[u]` 를 **처음부터** 읽습니다. 같은 라운드 안에서는 한 번 걸러진 항목의
판정이 안 바뀌므로 그 읽기는 그대로 낭비예요. 정점마다 「다음에 볼 자리」를 `iter[u]` 에 두면 그 낭비가
없어집니다.

```ts
const iter: number[] = Array.from({ length: n }, () => 0);

function dfsWithIter(u: number, pushed: number): number {
  if (u === sink) return pushed;
  const list = graph[u] as Edge[];
  for (; (iter[u] as number) < list.length; iter[u] = (iter[u] as number) + 1) {
    const e = list[iter[u] as number] as Edge;
    if (e.cap > 0 && (level[e.to] as number) === (level[u] as number) + 1) {
      const d = dfsWithIter(e.to, Math.min(pushed, e.cap));
      if (d > 0) {
        const back = (graph[e.to] as Edge[])[e.rev] as Edge;
        e.cap -= d;
        back.cap += d;
        return d;
      }
    }
    // ⑤ 조건에 안 맞거나 0 이 올라왔다 — `iter[u]` 를 한 칸 옮겨 다음 간선을 본다.
  }
  return 0;
}
```

여기서 가장 중요한 것은 `return d` 앞에서 `iter[u]` 를 안 올린다는 점입니다. 성공한 항목은 잔여가 아직 남아
있을 수 있으니 다음 경로에서 또 쓸 수 있어요. 라운드 1 동안 `iter` 가 지나온 자리입니다.

<!--proof:walkIter-->

```text

iter[1]   0 → 1 → 2   목록 1→0(역) · 1→2 · 1→4
iter[2]   0 → 1 → 3   목록 2→1(역) · 2→5 · 2→3(역)
iter[3]   0 → 2       목록 3→0(역) · 3→2
iter[4]   0 → 1       목록 4→1(역) · 4→5
iter[5]   0           목록 5→2(역) · 5→4(역)
```

#### 짚고 가기 — `iter` 는 속도를 위한 것이라 언제 0 으로 두어도 될 것 같다

`iter` 가 낭비를 줄이려고 둔 배열이라면, 언제 0 으로 두든 답은 같을 것 같습니다. 후보가 셋이에요 — 라운드가
바뀔 때만, DFS 를 부를 때마다, 아예 안 두기입니다.

<!--proof:iterThree-->

| iter 를 0 으로 두는 때 | 유량 | 항목 검사 | BFS 횟수 |
| --- | ---: | ---: | --- |
| 라운드가 바뀔 때만 (정본) | 5 | 73 | 3 |
| DFS 를 부를 때마다 | 5 | 80 | 3 |

<!--/proof-->

DFS 를 부를 때마다 0 으로 두면 **답은 틀리지 않습니다.** 매번 처음부터 읽어도 판정이 같으니 같은 경로를
찾기 때문이에요. 그래도 고치는 까닭은 이미 실패한 자리를 다시 읽는 만큼이 그대로 더해지기 때문이고, 이
작은 입력에서도 항목 검사가 늘었습니다. 아예 안 두면 라운드 2 에서 `iter[0]` 이 이미 목록 끝이라 DFS 가
곧바로 0 을 올려보내는데, BFS 는 여전히 싱크에 레벨을 적으므로 바깥 반복이 끝나지 않아요.

#### 6. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 **소스와 싱크가 같을 때 0 을 돌려주는
첫 줄**뿐이에요.

```ts
interface Edge {
  to: number;
  cap: number;
  rev: number;
}

export function maxFlow(
  n: number,
  edges: [number, number, number][],
  source: number,
  sink: number,
): { flow: number } {
  if (source === sink) return { flow: 0 };

  // 잔여 그래프. 원래 간선 하나가 정방향(잔여 `c`)과 역방향(잔여 0) 두 항목이 된다.
  const graph: Edge[][] = Array.from({ length: n }, () => []);
  const link = (u: number, v: number, c: number): void => {
    const out = graph[u] as Edge[];
    const back = graph[v] as Edge[];
    const iOut = out.length;
    out.push({ to: v, cap: c, rev: 0 });
    const iBack = back.length;
    back.push({ to: u, cap: 0, rev: iOut });
    (out[iOut] as Edge).rev = iBack;
  };
  for (const [u, v, c] of edges) link(u, v, c);

  // `level[v]` 는 지금 잔여 그래프에서 소스부터 `v` 까지의 최단 간선 수다. `-1` 은 도달 못 함.
  const level: number[] = Array.from({ length: n }, () => -1);
  // `iter[v]` 는 이 라운드에서 `v` 의 목록 중 다음에 볼 자리다. 라운드 안에서 뒤로만 간다.
  const iter: number[] = Array.from({ length: n }, () => 0);

  function bfs(): void {
    level.fill(-1);
    level[source] = 0;
    const queue: number[] = [source];
    let head = 0;
    while (head < queue.length) {
      const u = queue[head++] as number;
      for (const e of graph[u] as Edge[]) {
        // ① 잔여 용량이 있고 아직 레벨이 없는 정점 — 레벨을 적고 큐 뒤에 넣는다.
        if (e.cap > 0 && (level[e.to] as number) === -1) {
          level[e.to] = (level[u] as number) + 1;
          queue.push(e.to);
        }
      }
    }
  }

  function dfs(u: number, pushed: number): number {
    // ③ 싱크에 도착했다 — 여기까지의 병목값을 그대로 올려보낸다.
    if (u === sink) return pushed;
    const list = graph[u] as Edge[];
    for (
      ;
      (iter[u] as number) < list.length;
      iter[u] = (iter[u] as number) + 1
    ) {
      const e = list[iter[u] as number] as Edge;
      // ② 잔여 용량이 있고 레벨이 정확히 한 칸 큰 간선 — 그 간선으로 내려간다.
      if (e.cap > 0 && (level[e.to] as number) === (level[u] as number) + 1) {
        const d = dfs(e.to, Math.min(pushed, e.cap));
        // ④ 아래에서 양수가 올라왔다 — 짝지은 두 잔여 용량을 갱신하고 그대로 올려보낸다.
        if (d > 0) {
          const back = (graph[e.to] as Edge[])[e.rev] as Edge;
          e.cap -= d;
          back.cap += d;
          return d;
        }
      }
      // ⑤ 조건에 안 맞거나 0 이 올라왔다 — `iter[u]` 를 한 칸 옮겨 다음 간선을 본다.
    }
    return 0;
  }

  let total = 0;
  for (;;) {
    bfs();
    // ⑥ BFS 가 싱크에 레벨을 못 적었다 — 증가 경로가 없으므로 반복을 끝낸다.
    if ((level[sink] as number) === -1) return { flow: total };
    iter.fill(0);
    for (;;) {
      const f = dfs(source, Number.POSITIVE_INFINITY);
      if (f === 0) break;
      total += f;
    }
  }
}
```

```text
maxFlow(6, [[0,1,4],[1,2,2],[2,5,2],[0,3,3],[3,2,4],[1,4,5],[4,5,3]], 0, 5)   →   { flow: 5 }
maxFlow(4, [[0,1,3],[0,2,2],[1,2,1],[1,3,2],[2,3,3]], 0, 3)                   →   { flow: 5 }
maxFlow(4, [[0,1,1],[0,2,1],[1,2,1],[1,3,1],[2,3,1]], 0, 3)                   →   { flow: 2 }
maxFlow(2, [], 0, 1)                                                          →   { flow: 0 }
maxFlow(3, [[0,1,5]], 0, 2)                                                   →   { flow: 0 }
maxFlow(2, [[0,1,5],[0,1,7]], 0, 1)                                           →   { flow: 12 }
maxFlow(2, [[0,0,100],[0,1,5]], 0, 1)                                         →   { flow: 5 }
maxFlow(3, [[0,1,1000000],[1,2,1000000]], 0, 2)                               →   { flow: 1,000,000 }
```

### 알아 두면 좋은 개념 — 최대 유량 최소 컷 정리

T9 에서 마지막 BFS 가 정점 `{0, 1, 2, 3, 4}` 까지 도달하고 싱크에는 도달하지 못했습니다. 이렇게 정점을 소스
쪽 무리와 싱크 쪽 무리로 가른 것을 **컷**이라고 하고, 소스 쪽에서 싱크 쪽으로 가는 원래 간선의 용량을 다
더한 값을 그 컷의 **용량**이라고 부릅니다.

<!--fig:related-mincut-->
![마지막 BFS 가 가른 컷](./figs/related-mincut.svg)

<!--proof:minCut-->

| 컷의 구성 | 전개 입력의 마지막 BFS 에서 |
| --- | --- |
| 소스 쪽 정점 (마지막 BFS 가 도달한 정점) | {0, 1, 2, 3, 4} |
| 싱크 쪽 정점 | {5} |
| 경계 간선 2→5 | 용량 2 · 유량 2 |
| 경계 간선 4→5 | 용량 3 · 유량 3 |
| 경계 간선 용량의 합 (컷의 용량) | 5 |
| 최대 유량 | 5 |

컷의 용량 5 와 최대 유량 5 가 같습니다. 경계 간선 2 개가 모두 용량만큼 차 있고, 싱크 쪽에서 소스 쪽으로 가는 원래 간선은 0 개입니다.

<!--/proof-->

컷의 용량과 최대 유량이 같은 것은 우연이 아닙니다. **최대 유량 최소 컷 정리**가 그것이에요 — 어떤
네트워크에서도 최대 유량은 컷 용량의 최솟값과 같고, 마지막 BFS 가 도달한 정점 집합이 그 최솟값을 내는 컷을
그대로 줍니다.

| 진술 | 까닭 |
| --- | --- |
| 유량 ≤ 어떤 컷의 용량 | 소스에서 싱크로 가는 유량은 경계를 한 번은 넘어야 한다 |
| 마지막 컷의 용량 = 유량 | 경계 간선은 전부 잔여 0(용량만큼 참)이고, 거꾸로 가는 경계 간선은 전부 유량 0 이다 |
| 그래서 그 컷이 최솟값 | 유량이 모든 컷 용량의 하한이면서 이 컷의 용량과 같다 |

이 정리는 이 편 밖에서 더 자주 쓰입니다. 「무엇을 최소로 끊어야 두 무리가 나뉘는가」를 묻는 과제를 유량
과제로 바꿔 푸는 자리예요.

| 쓰이는 곳 | 유량으로 바꾸는 법 |
| --- | --- |
| 최소 컷 | 이 글의 마지막 BFS 가 그대로 준다 — [`minCut`](../minCut/minCut-guide.md) |
| 이분 매칭 | 간선마다 용량 1 을 두면 최대 매칭 수가 최대 유량이다 — [`maxBipartiteMatching`](../maxBipartiteMatching/maxBipartiteMatching-guide.md) |
| 프로젝트 선택 | 이익과 비용을 소스 · 싱크 쪽 간선으로 두면 최대 이익이 최소 컷에서 나온다 |

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 이것을 쓰는지, 라운드 수가 왜 정점 수보다 작은지, 무엇이
매 순간 참으로 남는지, 그리고 비용이 얼마인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **간선마다 상한이 있고, 중간 정점에서 들어온 양과 나간 양이 같아야 합니다.** 이 두 조건이 없으면 유량
  과제가 아니에요.
- **소스와 싱크가 각각 하나입니다.** 여럿이면 가상의 소스 · 싱크를 하나씩 더 만들어 용량이 큰 간선으로 잇는
  변환이 필요합니다.
- **용량이 정수이거나, 적어도 비교와 덧셈 · 뺄셈만 하면 됩니다.** 이 절차는 용량을 더하고 빼고 비교하기만
  합니다.
- **정점 수가 간선 수에 비해 작습니다.** 비용이 $V^2 E$ 안쪽이라 정점이 늘어나는 쪽이 간선이 늘어나는 쪽보다
  비용을 더 키웁니다.

잘 안 맞는 모양도 있어요.

| 모양 | 이 절차의 한계 |
| --- | --- |
| 간선마다 단위당 비용이 따로 있다 | 최소 비용 최대 유량 과제라 이 절차만으로는 안 된다 |
| 유량 말고 다른 정수 조건이 더 붙는다 | 정수 최대 유량은 나오지만 다른 조건은 따로 다뤄야 한다 |
| 간선이 한꺼번에 주어지지 않는다 | 잔여 그래프를 미리 만들어 두고 시작해야 한다 |

용량이 전부 정수면 이 절차가 내는 답도, 간선마다의 유량도 정수입니다. 처음 잔여가 전부 정수이고, 병목은
경로 위 잔여의 최솟값이라 정수이며, 갱신은 정수를 더하고 빼는 것뿐이라 잔여가 계속 정수로 남기 때문이에요.

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 이 절차 |
| --- | --- | --- |
| 지문 | 「한 번에 지날 수 있는 양이 정해져 있고, 출발지에서 도착지로 **최대 얼마**를 보낼 수 있는가」 | 쓴다 |
| 지문 | 「**최소 몇 개를 끊어야** 출발지에서 도착지로 못 가게 되는가」 | 쓴다 — 최소 컷 |
| 지문 | 「두 무리를 **짝지어 최대 몇 쌍**」 | 쓴다 — 용량 1 인 유량 |
| 지문 | 「항목마다 이익과 비용이 있고 **순이익 최대**」 | 쓴다 — 프로젝트 선택의 최소 컷 |
| 제약 | 정점 수백 · 간선 만 단위 · 시간 1~2 초 | $V^2 E$ 규모의 절차 |
| 지문 | 「출발지에서 도착지까지 가장 짧은 길」 | 못 쓴다 — 최단 경로 과제 |
| 지문 | 「간선마다 단위 비용이 있고 총비용 최소」 | 이 절차만으로는 부족하다 — 최소 비용 최대 유량 |

#### 실제로 쓰이는 곳

- **SciPy** — `scipy.sparse.csgraph.maximum_flow` 가 `method` 인자로 두 절차를 두고 있고 **기본값이
  디닉**입니다. 공식 문서가 *"'dinic': Dinic's algorithm"* 과 *"Default is 'dinic'."* 라고 적고, 시간 복잡도를
  $O(|V|^2 |E|)$ 로, 또 하나인 `'edmonds_karp'` 를 $O(|V| |E|^2)$ 로 적습니다.
  ([공식 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csgraph.maximum_flow.html), 조회일 2026-09-04)
- **NetworkX** — `networkx.algorithms.flow.dinitz` 가 같은 절차입니다. 공식 문서가
  *"Find a maximum single-commodity flow using Dinitz' algorithm."* 로 시작하고
  *"This algorithm has a running time of $O(n^2 m)$ for $n$ nodes and $m$ edges"* 라고 적어요.
  ([공식 문서](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.flow.dinitz.html), 조회일 2026-09-04)
- **AtCoder Library** — 경진 프로그래밍용 표준 라이브러리의 `mf_graph<Cap>` 이 최대 유량을 냅니다. 문서에
  절차 이름은 안 적혀 있고 복잡도만 적혀 있는데, 그 값이 용량이 전부 1 일 때 $O(\min(n^{2/3} m,\, m^{3/2}))$,
  일반이면 $O(n^2 m)$ 으로 이 글이 유도하는 값과 같습니다.
  ([공식 문서](https://atcoder.github.io/ac-library/production/document_en/maxflow.html), 조회일 2026-09-04)

| 출처 | 원문에서 확인한 것 |
| --- | --- |
| SciPy | 기본값이 디닉이고 에드먼즈–카프를 함께 두어 고를 수 있게 했다 |
| NetworkX | 함수 이름 자체가 절차 이름이고 복잡도를 $n^2 m$ 으로 적는다 |
| AtCoder | 절차 이름 없이 복잡도만 적는다 |

위 세 줄만 원문에서 확인했고, 세 라이브러리가 무엇을 더 제공하는지는 확인하지 않았습니다. SciPy 가 두
절차를 나란히 두고 `method` 로 고르게 해 둔 것은 **한쪽이 언제나 적지는 않다**는 뜻이고, 다음 절이 그
자리를 다룹니다.

#### 경쟁 설계와의 대조

경쟁 설계는 **에드먼즈–카프(Edmonds–Karp)** 입니다. 같은 잔여 그래프를 쓰고 최단 증가 경로를 고르는 것까지
같은데, **증가 경로 하나마다 BFS 를 다시 합니다.** 레벨을 다시 쓰지 않으므로 라운드라는 것이 없고 `iter`
배열도 없어요.

| 설계 | BFS 를 하는 때 | 한 번 매긴 거리의 쓰임 |
| --- | --- | --- |
| 디닉 | 라운드마다 한 번 | 그 라운드의 경로 여럿에 쓴다 |
| 에드먼즈–카프 | 증가 경로마다 한 번 | 경로 하나에 쓰고 버린다 |

**입력은 전개 입력과 다릅니다.** 두 설계가 갈리는 곳이 「한 라운드가 담는 증가 경로 수」인데 전개 입력은
정점 6 · 간선 7 이라 그 수를 1 에서 수십까지 바꿀 자리가 없어요. 그래서 소스에서 싱크까지의 경로 길이가
1, 2, …, 20 으로 스무 가지인 계단(정점 21 개)을 세우고, 길이가 같은 경로를 `w` 개씩 둡니다. 라운드는
언제나 20 이고 한 라운드가 담는 경로가 정확히 `w` 라, 난수 없이 `w` 하나로 조건을 바꿀 수 있습니다.

<!--fig:alt-stair-->
![대조에 쓴 계단](./figs/alt-stair.svg)

기본 연산은 **배열 · 객체 칸을 읽거나 쓴 한 번, 그리고 비교 한 번**을 각각 하나로 셉니다. 파트 1 이 쓰던
「항목을 읽은 횟수」보다 넓게 세는데, 두 설계가 갈리는 자리 중 하나가 라운드(또는 경로)마다 배열을
초기값으로 채우는 비용이라 항목 검사만 세면 그것이 빠지기 때문이에요.

| 라운드당 경로 `w` | 디닉 | 에드먼즈–카프 | 적은 쪽 |
| --- | --- | --- | --- |
| `w = 1` | 12,365 | 9,385 | 에드먼즈–카프 |
| `w = 2` | 17,495 | 23,295 | 디닉 — 여기서 순서가 바뀐다 |
| `w = 3` | 22,625 | 42,005 | 디닉 |
| `w = 10` | 58,535 | 307,375 | 디닉 |
| `w = 40` | 212,435 | 4,108,675 | 디닉 |

**순서가 바뀌는 자리를 값으로 댈 수 있습니다.** 한 라운드가 담는 경로가 하나뿐이면 레벨을 다시 써서 아끼는
BFS 가 없는데, `iter` 배열을 라운드마다 0 으로 채우는 비용은 그대로 들어요. 둘부터는 아끼는 BFS 가 생기고,
경로 수가 늘수록 그 차이가 커집니다.

| 셈 | `w` 를 늘린 결과 |
| --- | --- |
| 에드먼즈–카프의 BFS 횟수 = 경로 수 | 그대로 늘어난다 |
| 디닉의 BFS 횟수 = 라운드 수 | 20 그대로다 |
| 디닉이 더 치르는 것 = `iter` 초기화, 라운드마다 `V` 칸 | `w` 와 상관없이 고정이다 |

**디닉이 내주는 것이 둘 있습니다.** 하나는 방금 본 「라운드당 경로가 하나뿐인 그래프에서의 기본 연산」이에요.
다른 하나는 구현 난이도입니다. 재귀 DFS 와 `iter` 배열과 이중 반복이 필요한데, 에드먼즈–카프는 BFS 하나와
직전 간선 배열이면 끝납니다.

| 라운드당 경로 `w` | 디닉 저장 칸 | 에드먼즈–카프 저장 칸 |
| --- | --- | --- |
| `w = 1` | 276 | 297 |
| `w = 40` | 4,956 | 4,977 |

저장 칸은 **어느 `w` 에서도 순서가 안 바뀝니다.** 잔여 그래프는 둘이 같은 것을 쓰고, 그 위에 디닉은 배열
둘(`level` · `iter`)로 `2V`, 에드먼즈–카프는 방문 배열과 직전 간선 배열로 `3V` 를 더 쓰거든요. 차이가 정점
수인 21 칸으로 고정입니다.

**디닉이 얻는 것도 적어 둡시다.** 라운드 수가 `V − 1` 로 묶여 있어 BFS 횟수의 상한이 입력 크기만으로
정해지고, 에드먼즈–카프는 그 상한이 증가 경로 수라 `V · E` 로 묶입니다. 두 상한을 규모의 상한에 넣은 값은
「수식 정의와 유도」에서 냅니다.

### 수식 정의와 유도

유량 $f$ 하나가 정해졌을 때 그 위에서 정의되는 것 넷을 기호로 적습니다. $V$ · $E$ · $s$ · $t$ · $c(u,v)$ 는
기호표의 뜻 그대로예요.

| 기호 | 정의 |
| --- | --- |
| $c_f(u,v)$ | $u \to v$ 방향의 잔여 용량. 원래 간선이면 $c(u,v) - f(u,v)$, 반대 방향이면 $f(v,u)$ |
| $G_f$ | $c_f(u,v) > 0$ 인 항목만 모은 잔여 그래프 |
| $d_f(v)$ | $G_f$ 에서 $s$ 부터 $v$ 까지의 최단 간선 수. 도달 못 하면 $\infty$ |
| $L_f$ | $G_f$ 의 항목 중 $d_f(v) = d_f(u) + 1$ 인 $(u,v)$ 만 모은 레벨 그래프 |

정의를 $f = 0$ 에 넣어 검산해 봅시다. $f = 0$ 이면 $c_f$ 가 원래 용량이고, $d_f$ 는 코드의 `level` 과 같아야
합니다. $d_f$ 를 BFS 가 아니라 모든 쌍 최단 거리 계산으로 따로 재서 비교했어요.

<!--proof:mathCheck-->

| 정점 v | 정의대로 센 d_f(v) | 코드의 level[v] | 대조 |
| --- | ---: | ---: | --- |
| 0 | 0 | 0 | 일치 |
| 1 | 1 | 1 | 일치 |
| 2 | 2 | 2 | 일치 |
| 3 | 1 | 1 | 일치 |
| 4 | 2 | 2 | 일치 |
| 5 | 3 | 3 | 일치 |

여섯 정점 중 6 개가 일치합니다. f = 0 이면 원래 간선의 c_f 는 용량 그대로이고 역방향은 0 이라, L_f 에 드는 항목은 원래 간선 7 개입니다.

<!--/proof-->

이제 유도합니다. 한 라운드가 만드는 것은 $L_f$ 안에 $s \to t$ 경로가 더 없는 상태예요. 그 상태의 유량을
$f'$ 라 하면 주장은 하나입니다.

$$
d_{f'}(t) > d_f(t)
$$

| 보일 것 | 식 |
| --- | --- |
| 어떤 정점에서도 거리가 줄지 않는다 | $d_{f'}(v) \ge d_f(v)$ |
| 싱크의 거리는 같을 수 없다 | $d_{f'}(t) \ne d_f(t)$ |

둘을 합치면 싱크의 거리가 반드시 커집니다. 먼저 **거리가 줄지 않는다**는 것을 $d_{f'}(v)$ 에 대한 귀납으로
보입니다. 기저는 $v = s$ 이고 양쪽이 0 이에요. 단계에서는 $G_{f'}$ 에서 $s$ 부터 $v$ 까지의 최단 경로의
마지막 항목을 $(u,v)$ 라 하면 $d_{f'}(v) = d_{f'}(u) + 1$ 이고, 귀납 가정으로 $d_{f'}(u) \ge d_f(u)$ 입니다.
항목 $(u,v)$ 가 어디서 왔는가로 두 갈래예요.

| 갈래 | 식 |
| --- | --- |
| $G_f$ 에도 있었다 | $d_f(v) \le d_f(u) + 1 \le d_{f'}(u) + 1 = d_{f'}(v)$ |
| $G_f$ 에는 없었다 | 이 라운드에 $(v,u)$ 로 보내서 생긴 것이고 $(v,u)$ 는 $L_f$ 의 항목이라 $d_f(u) = d_f(v) + 1$. 그래서 $d_f(v) = d_f(u) - 1 \le d_{f'}(u) - 1 < d_{f'}(v)$ |

위 갈래의 앞 부등식은 $G_f$ 의 항목 하나가 거리를 많아야 1 올린다는 BFS 거리의 성질이고, 뒤 부등식은
귀납 가정입니다. 두 갈래 모두 $d_{f'}(v) \ge d_f(v)$ 예요.

다음으로 **거리가 같을 수 없다**는 것을 보입니다. $d_{f'}(t) = d_f(t) = k$ 라고 해 봅시다. $G_{f'}$ 에서 길이
$k$ 인 $s \to t$ 경로를 $v_0 = s,\; v_1,\; \dots,\; v_k = t$ 라 하면, 경로의 항목마다
$d_f(v_i) \le d_f(v_{i-1}) + 1$ 이 성립합니다. 그 항목이 $G_f$ 에 있었으면 BFS 거리의 성질이고, 없었으면 위 표의 아래 갈래처럼 $d_f$ 가
오히려 1 내려가기 때문이에요.

| 걸음 | 내용 |
| --- | --- |
| 양 끝 | $d_f(v_0) = 0$, $d_f(v_k) = k$ 이고 한 걸음에 많아야 1 씩 커진다 |
| 그래서 | 모든 $i$ 에서 $d_f(v_i) = d_f(v_{i-1}) + 1$ 이다 — 한 번이라도 덜 커지면 $k$ 에 못 미친다 |
| 그래서 | 모든 항목이 $G_f$ 에 있었다 — 없었던 항목은 $d_f$ 를 1 내리므로 이 등식과 맞지 않는다 |
| 그래서 | 그 경로는 $L_f$ 에 그대로 있는 $s \to t$ 경로다 |
| 모순 | 라운드가 끝난 상태는 $L_f$ 에 $s \to t$ 경로가 없는 상태였다 |

거리가 줄지 않고 같지도 않으므로 반드시 커집니다. 거리는 정수이고 $s \to t$ 경로의 간선 수가 $V - 1$ 을 넘을
수 없으므로, 유량을 실제로 보낸 라운드 수 $R$ 은 $V - 1$ 이하예요. 라운드 $r$ 이 보낸 경로 수를 $P_r$ 이라
쓰면 전체 비용은 아래 식입니다.

$$
T(V, E) = \Theta(V + E) + \sum_{r=1}^{R} \bigl[\Theta(V + E) + O(V \cdot P_r + E)\bigr], \qquad R \le V - 1, \quad P_r \le E
$$

$P_r \le E$ 인 까닭은 경로 하나가 병목 항목 하나 이상의 잔여를 0 으로 만들고, 그 항목은 같은 라운드에서
다시 쓰이지 않기 때문입니다. 경로 하나의 길이는 $V$ 를 넘지 않아요. 두 상한을 식으로 옮기면 이렇습니다.

```ts
const rounds = V - 1;
const perRound = V * E + (V + E);
const bound = rounds * perRound;
```

규모의 상한을 넣으면 이렇게 나옵니다.

<!--proof:mathScale-->

| 식 | V = 500 · E = 10,000 에서 |
| --- | ---: |
| 라운드 수의 상한 V − 1 | 499 |
| 라운드 하나의 상한 V · E + (V + E) | 5,010,500 |
| 곱 (V − 1) · (V · E + V + E) | 2,500,239,500 |
| 경로마다 BFS 를 다시 하는 절차의 상한 V · E² | 50,000,000,000 |

디닉의 상한은 2,500,239,500 이고, 경로마다 BFS 를 다시 하는 절차의 상한은 50,000,000,000 이라 자릿수가 1 개 더 붙습니다.

<!--/proof-->

이 값은 **상한**이고, 실제로 그만큼 드는 입력은 「최악을 만드는 입력」에서 따로 구성합니다.

### 불변식 — 짝지은 두 잔여 용량의 합은 언제나 처음 용량과 같다

파트 1 에서 코드가 동작하는 것을 아홉 걸음으로 확인했습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지
언제나 맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 아래 문장으로 세우고, 간선 `1 → 2` 의 두 잔여를
걸음마다 따라가 그것이 유지되는지 확인해 봅시다.

> 증가 경로 하나를 처리한 직후마다, 원래 간선 `u → v` 마다 `cap(u,v) + cap(v,u)` 가 그 간선의 처음 용량
> `c(u,v)` 와 같습니다.

<!--proof:invariantPair-->

| 걸음 | cap(1,2) | cap(2,1) | 합 |
| --- | ---: | ---: | ---: |
| T1 | 2 | 0 | 2 |
| T2 | 2 | 0 | 2 |
| T3 | 0 | 2 | 2 |
| T4 | 0 | 2 | 2 |
| T5 | 0 | 2 | 2 |
| T6 | 0 | 2 | 2 |
| T7 | 1 | 1 | 2 |
| T8 | 1 | 1 | 2 |
| T9 | 1 | 1 | 2 |

간선 1→2 의 두 잔여는 걸음 9 개 모두에서 합이 처음 용량 2 와 같습니다. 간선 7 개 × 걸음 9 개 = 63 곳을 모두 재면 합이 처음 용량과 어긋난 곳은 0 곳입니다.

<!--/proof-->

이 합이 왜 답의 정확성을 주는지가 요점입니다. `cap(v,u)` 가 곧 「지금 `u → v` 로 보낸 유량」이고, 합이
`c(u,v)` 로 고정이면 그 유량이 용량을 넘을 수 없어요. 그리고 **경로 위 모든 항목에서 같은 값 `d` 를 빼고
더하므로** 중간 정점에서 들어온 양과 나간 양이 같이 움직입니다. 역방향 항목을 지난 걸음 앞뒤로 정점마다
들어온 유량과 나간 유량을 쟀어요.

<!--proof:invariantConserve-->

| 정점 | 들어온 유량 (T6 → T7) | 나간 유량 (T6 → T7) |
| --- | --- | --- |
| 0 (소스) | 0 → 0 | 4 → 5 |
| 1 | 4 → 4 | 4 → 4 |
| 2 | 2 → 2 | 2 → 2 |
| 3 | 0 → 1 | 0 → 1 |
| 4 | 2 → 3 | 2 → 3 |
| 5 (싱크) | 4 → 5 | 0 → 0 |

중간 정점 4 개는 T7 앞뒤 모두 들어온 양과 나간 양이 같고, 소스가 내보낸 양과 싱크가 받은 양은 4 에서 5 로 늘었습니다.

<!--/proof-->

정점 1 과 2 를 봐 주세요. T7 은 `2 → 1` 역방향 항목을 지났는데, 정점 2 에서는 `3 → 2` 로 들어온 1 과 `1 → 2`
에서 줄어든 1 이 서로 상쇄되고, 정점 1 에서는 `1 → 2` 로 나가던 1 이 `1 → 4` 로 옮겨 갔어요. 상태를 바꾸는
갈래는 둘뿐이고 둘 다 이 합을 지킵니다.

| 갈래 | 바뀌는 잔여 용량 | 합이 유지되는 근거 |
| --- | --- | --- |
| 잔여 그래프를 만든다 | `cap(u,v) = c(u,v)`, `cap(v,u) = 0` | 합이 `c(u,v)` 로 시작한다 |
| 경로에 `d` 를 보낸다 | `cap(u,v)` 가 `d` 줄고 `cap(v,u)` 가 `d` 는다 | 한쪽에서 뺀 만큼 다른 쪽에 더하므로 합이 그대로다 |

경계에 있는 입력들도 확인하고 갑시다.

<!--proof:invariantEdges-->

| 입력 | 처리되는 자리 | 정본의 결과 |
| --- | --- | --- |
| 간선 없음 `maxFlow(2, [], 0, 1)` | 첫 BFS 가 소스만 보고 끝난다 | `{ flow: 0 }` |
| 경로 없음 `maxFlow(3, [[0,1,5]], 0, 2)` | `level[2]` 가 `-1` 이라 첫 라운드에서 끝난다 | `{ flow: 0 }` |
| 정점 둘 `maxFlow(2, [[0,1,1]], 0, 1)` | 라운드 하나에 경로 하나 | `{ flow: 1 }` |
| 용량 0 인 간선 `[[0,1,0],[0,2,5],[2,1,5]]` | `cap > 0` 이 거짓이라 BFS 가 그 항목을 안 지난다 | `{ flow: 5 }` |
| 평행 간선 `[[0,1,5],[0,1,7]]` | 항목 쌍이 둘이라 각각 따로 찬다 | `{ flow: 12 }` |
| 자기 루프 `[[0,0,100],[0,1,5]]` | `level[0]` 이 이미 0 이라 BFS 가 안 지나고, DFS 도 레벨 조건에서 거른다 | `{ flow: 5 }` |
| 용량 상한 `[[0,1,1e6],[1,2,1e6]]` | 병목이 한 번에 다 보내진다 | `{ flow: 1000000 }` |
| 소스와 싱크가 같다 `maxFlow(2, [[0,1,5]], 0, 0)` | 첫 줄이 0 을 돌려준다 | `{ flow: 0 }` |

자기 루프가 이 절차의 경계입니다. `link` 가 두 자리를 따로 읽어 두지 않으면 정방향 항목의 `rev` 가 자기
자신을 가리키는데, 레벨 조건 때문에 그 항목이 한 번도 안 쓰여서 답은 맞게 나와요.

**이제 깨뜨려 봅시다.** 합을 지키던 줄은 짝의 잔여를 늘리는 줄입니다. 잔여를 줄이는 줄은 그대로 두고 **짝을
늘리는 한 줄만** 지웁니다.

```ts
// back.cap += d;   ← 이 한 줄을 지운다
```

<!--proof:mutantBackflow-->

| 입력 | 정본 | 역방향을 안 늘리는 판 | 판정 |
| --- | ---: | ---: | --- |
| 전개 입력 | 5 | 4 | 다르다 |
| 다리 그래프 | 2 | 2 | 같다 |
| 용량이 다른 다리 그래프 | 5 | 5 | 같다 |
| 격자 20 × 10 | 100 | 100 | 같다 |

전개 입력에서 5 가 4 가 됐습니다. 네 입력 중 셋은 답이 같다는 것도 봐 주세요. 되돌릴 필요가 없는 차례로
경로가 잡혀서, 그 세 입력만 시험하면 지운 채로 통과합니다. 전개 입력에서 합이 깨진 자리를 보면 이렇습니다.

<!--proof:mutantPair-->

| 시점 | cap(1,2) | cap(2,1) | 두 잔여의 합 | 라운드 2 의 level | 최종 유량 |
| --- | ---: | ---: | ---: | --- | ---: |
| 라운드 1 이 끝난 뒤 | 0 | 0 | 0 | [0, -1, 2, 1, -1, -1] | 4 |

라운드 1 이 끝났을 때 `1 → 2` 의 두 잔여가 모두 0 이라 합이 처음 용량 2 가 아닙니다. 역방향 `2 → 1` 이 없으니
라운드 2 의 BFS 가 정점 1 에 레벨을 못 적고, 싱크에도 레벨이 안 붙어 라운드 2 가 아예 없어져요.

### 비용 계산

#### 비용을 세는 과정

한 라운드가 하는 일은 BFS 한 번과, 그 레벨로 찾을 수 있는 증가 경로를 전부 보내는 것입니다. 전개의 값으로
확인하면 T2 · T3 · T4 · T5 가 라운드 1, T6 · T7 · T8 이 라운드 2, T9 가 마지막 BFS 예요. 걸음마다 항목을 읽은
횟수를 라운드로 묶었습니다.

<!--proof:walkCost-->

| 라운드 | 걸음 | 항목 검사 | 그중 BFS | 그중 DFS | 보낸 경로 수 |
| --- | --- | ---: | ---: | ---: | ---: |
| 1 | T2 · T3 · T4 · T5 | 30 | 14 | 16 | 2 |
| 2 | T6 · T7 · T8 | 31 | 14 | 17 | 1 |
| 3 | T9 | 12 | 12 | 0 | 0 |
| 합 |  | 73 | 40 | 33 | 3 |

합 73 은 계수만 세는 사본이 낸 값 73 과 같습니다. 라운드 1 · 2 의 BFS 는 항목 14 개를 한 번씩 읽었고, 라운드 3 의 BFS 는 싱크의 목록을 안 읽어 12 번입니다.

<!--/proof-->

한 라운드의 비용을 항으로 가르면 이렇습니다.

| 항 | 한 라운드에서 하는 일 | 상한 |
| --- | --- | --- |
| BFS | 큐에 들어간 정점의 목록을 한 번씩 읽는다 | `2E` |
| `iter` 초기화 | 정점마다 한 칸 | `V` |
| DFS 의 헛걸음 | `iter` 가 뒤로 안 가므로 목록 길이의 합만큼 | `2E` |
| DFS 의 성공 | 경로 하나가 많아야 `V` 개 항목을 지난다 | `V · P_r` |

라운드마다 $O(V \cdot P_r + E)$ 이고, 라운드가 $R \le V - 1$ 번, $P_r \le E$ 이므로 총식은 아래와 같습니다.
앞뒤로 붙는 잔여 그래프 만들기와 마지막 BFS 까지 넣었어요.

$$
T = \underbrace{\Theta(V + E)}_{\text{잔여 그래프}} + \sum_{r=1}^{R} \bigl[\Theta(V + E) + \Theta(V) + O(V \cdot P_r + E)\bigr] + \underbrace{\Theta(V + E)}_{\text{마지막 BFS}} = O(V^2 E)
$$

메모리는 잔여 그래프 $\Theta(V + E)$ 에 `level` · `iter` · 큐가 각각 $\Theta(V)$ 라 $\Theta(V + E)$ 입니다. 여기서
센 것은 **항목을 한 번 읽은 것**이고, 재귀 호출 자체의 비용은 세지 않았어요. 호출 깊이가 `level[t] ≤ V − 1`
이라 호출 스택이 정점 수에 비례합니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 한쪽을 다른 쪽에 짝지으면 안 돼요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (소스에서 싱크로 가는 경로가 없다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포가 정의되지 않는다) | — | — |
| **최악의 경우** (라운드가 `V − 1` 까지 간다) | `O(V² · E)` | 이 글은 판정하지 않는다 |

최선은 BFS 한 번으로 끝나는 경우이고 상한과 하한이 같습니다. 잔여 그래프를 만드는 데 이미 `Θ(V + E)` 가 들고
BFS 도 그만큼이라, 그보다 적게 할 방법이 없어요. 최악 칸을 `Θ` 로 적지 않은 까닭은 `O(V² · E)` 가 `R ≤ V − 1` 과 `P_r ≤ E` 를 각각 가장 크게 잡아 곱한 값이기
때문입니다. 두 최대가 같은 입력에서 함께 일어나는지는 따로 따질 일이고, 아래에서 구성한 입력은 라운드는
`V − 1` 을 채우는데 `P_r` 이 1 이라 그 곱에 한참 못 미칩니다.

**평균은 정의되지 않습니다.** 정점 수와 간선 수를 고정해도 용량의 분포와 간선의 배치를 무엇으로 잡느냐에 따라
라운드 수가 1 에서 `V − 1` 까지 갈리는데, 이 과제에는 표준으로 삼을 입력 분포가 없어요. **보장의 종류는 최악
보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어서, 같은 입력을 두 번 넣으면 라운드 수와
항목 검사 횟수까지 똑같이 나옵니다.

| 보장 | 뜻 | 이 절차 |
| --- | --- | --- |
| 최악 보장 | 어떤 입력에도 라운드가 `V − 1` 을 넘지 않는다 | 해당한다. 용량과 상관없다 |
| 기댓값 보장 | 구현이 만드는 무작위성이나 입력 분포에 기댄다 | 해당하지 않는다 |
| 용량 의존 | 반복 횟수가 유량 값에 달려 있다 | 해당하지 않는다. 경로를 아무거나 고르는 방식이 그렇다 |

따로 구성하고 마지막에 합칩니다. 먼저 라운드 수를 가장 크게 만드는 계단 그래프입니다.

| 200 | 201 | 399 | 200 | 200 | 299,898 |
| 499 | 500 | 997 | 499 | 499 | 1,867,256 |

다섯 줄 모두 유량을 보낸 라운드가 상한 V − 1 과 같습니다.

<!--/proof-->

이 그래프는 간선이 `2m − 1` 개뿐이라 라운드 하나의 비용이 작습니다. 라운드 수를 그대로 두고 간선만 늘리려면
**번호가 큰 중간 정점에서 작은 쪽으로 가는 간선**을 넣으면 돼요. 그 간선은 더 짧은 경로를 만들지 않으므로
라운드 수를 안 바꾸고, BFS 가 라운드마다 읽기만 합니다.

<!--proof:worstScale-->

| 입력 | 정점 V | 간선 E | BFS 횟수 | 항목 검사 |
| --- | ---: | ---: | ---: | ---: |
| 계단만 | 500 | 997 | 500 | 1,867,256 |
| 계단 + 뒤로 가는 간선 1,000 개 | 500 | 1,997 | 500 | 3,865,256 |
| 계단 + 뒤로 가는 간선 5,000 개 | 500 | 5,997 | 500 | 11,857,256 |
| 계단 + 뒤로 가는 간선 9,000 개 | 500 | 9,997 | 500 | 19,849,256 |
| 격자 20 × 10 | 202 | 570 | 2 | 1,662 |

가장 큰 계단의 항목 검사는 19,849,256 번이고 격자의 11,943 배입니다. 정점은 2.5 배, 간선은 17.5 배이고 BFS 횟수는 500 번 대 2 번입니다. 이 값은 상한 2,500,239,500 의 0.8 % 입니다.

<!--/proof-->

차이를 만드는 것은 크기가 아니라 라운드 수입니다. 격자는 한 라운드에 경로를 여럿 보내고, 계단은 라운드마다
경로를 하나씩만 보내요. 라운드 수를 정하는 것은 「서로 다른 최단 간선 수가 몇 가지나 나오는가」입니다. 이 글이
구성한 입력은 라운드 수는 `V − 1` 을 채웠지만 라운드당 경로 수 $P_r$ 이 1 이라 곱의 다른 쪽을 못 채웠고, 두
쪽을 함께 채우는 입력은 구성하지 못했어요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 간선 하나를 정방향 · 역방향 두 항목으로 나눠 되돌릴 자리를
만들고, 라운드마다 BFS 로 레벨을 매겨 **레벨이 한 칸 오르는 항목만** 따라가며 그 레벨로 찾을 수 있는 경로를
전부 보냅니다. 답이 맞는 근거는 「짝지은 두 잔여의 합은 언제나 처음 용량이다」이고, 비용은 $O(V^2 E)$ 예요.

| 차례 | 하는 일 | 규모 |
| ---: | --- | --- |
| 1 | 잔여 그래프를 만든다 | 항목 `2E` 개 |
| 2 | BFS 로 레벨을 적는다 | 라운드마다 항목 `2E` 번 이하 |
| 3 | 레벨을 지키는 경로를 더 못 찾을 때까지 보낸다 | 라운드마다 `O(V · P_r + E)` |
| 4 | 싱크에 레벨이 없으면 끝낸다 | 라운드 `V − 1` 번 이하 |

먼저 답이 붙는 문제 하나입니다. 전개의 T7 에서 경로 `0 → 3 → 2 → 1 → 4 → 5` 에 1 을 보냈어요. 병목이 1 이었고
마지막 1 이 `4 → 5` 의 잔여였습니다. 간선 `4 → 5` 의 용량이 3 이 아니라 5 였다면 그 경로의 병목과 최종 유량이
각각 얼마가 될까요?

<!--check:cap45-->
병목은 2 가 되고 최종 유량은 6 이 됩니다. 병목을 정하던 자리가 `4 → 5` 에서 역방향 `2 → 1` 로 옮겨 가요.
`2 → 1` 의 잔여 2 가 새 상한입니다.

<!--proof:selfcheckCap45-->

| 라운드 | 보낸 경로 | 병목 | 누적 유량 |
| --- | --- | --- | ---: |
| 라운드 1 | 0 → 1 → 2 → 5 | min(4, 2, 2) = 2 | 2 |
| 라운드 1 | 0 → 1 → 4 → 5 | min(2, 5, 5) = 2 | 4 |
| 라운드 2 | 0 → 3 → 2 → 1 → 4 → 5 | min(3, 4, 2, 3, 3) = 2 | 6 |

최종 유량은 6 이고 정본이 같은 입력에 낸 값도 6 입니다.

### 최대 유량 (Maximum Flow)

풀 파일: [`maxFlow.ts`](./maxFlow.ts) · 테스트: [`maxFlow.test.ts`](./maxFlow.test.ts) · 실행: `bun test src/algorithms/graph-flow/maxFlow/maxFlow.test.ts`

#### 한 줄 요약

> 유량 네트워크의 정점 수 `n`, 방향 간선 목록 `edges`, 소스 `source`, 싱크 `sink` 를 받아, 소스에서 싱크로 흘릴 수 있는 **최대 유량**을 `{ flow }` 형태로 반환한다.

#### 스토리

도시 외곽 물류 센터에서 항구까지 여러 경로로 화물을 보낼 수 있다. 각 도로마다 한 번에 통과할 수 있는 화물 트럭 대수(용량)가 다르다. 어떤 경유 도시를 거쳐 가더라도 들어온 트럭 수와 나가는 트럭 수가 같아야 한다(유량 보존). 물류 센터에서 출발한 트럭이 항구에 도달하는 수가 곧 이익이다.

물류 팀장은 묻는다. "이 도로망에서 한 시간에 최대 몇 대를 항구까지 보낼 수 있죠?"

트럭을 보낼 때 일부 경로에서 이미 지나가던 트럭을 다른 경로로 돌릴 수 있다면 전체 수송량을 더 늘릴 수도 있다. 네트워크 전체를 보고 가장 많은 트럭을 항구까지 보내는 방법을 찾아야 한다.

#### 함수 인터페이스

```ts
export function maxFlow(
  n: number,
  edges: [number, number, number][],
  source: number,
  sink: number,
): { flow: number };
```

- `n` — 정점의 개수. 정점 번호는 $0 \ldots n-1$.
- `edges` — 방향 가중치 간선 목록. 각 원소 `[u, v, c]` 는 정점 `u` 에서 `v` 로 향하는 용량 `c` 의 간선이다.
- `source` — 소스 정점 번호.
- `sink` — 싱크 정점 번호.
- 반환 — `{ flow }`. 소스에서 싱크로의 최대 유량.

#### 제약 조건

- $2 \leq n \leq 500$
- $0 \leq E \leq 10^4$ (여기서 $E$ 는 간선의 수)
- $0 \leq c(u, v) \leq 10^6$
- $0 \leq \text{source},\, \text{sink} < n,\;\; \text{source} \neq \text{sink}$
- 정점 번호는 $0 \ldots n-1$.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

유량 네트워크 $G = (V, E, c)$ 와 소스 $s$, 싱크 $t$ 가 주어졌을 때, 다음 조건을 모두 만족하는 유량 함수 $f: E \to \mathbb{R}_{\geq 0}$ 의 총 유량을 최대화한다.

- 용량 제약: $0 \leq f(u, v) \leq c(u, v)$
- 유량 보존: $\forall v \in V \setminus \{s, t\},\; \sum_{u} f(u, v) = \sum_{w} f(v, w)$

총 유량:

$$|f| = \sum_{v:\, (s, v) \in E} f(s, v) - \sum_{u:\, (u, s) \in E} f(u, s)$$

$$\text{maxFlow}(G, s, t) = \max_{f \text{ feasible}} |f|$$

- 소스에서 싱크로 향하는 경로가 없으면 유량은 `0` 이다.
- 평행 간선(같은 두 정점 사이의 여러 간선)은 용량이 합산되는 효과를 낸다.
- 용량 `0` 인 간선은 유량을 흘릴 수 없다.
- 자기 루프는 유량에 영향을 주지 않는다.

#### 예시

```ts
maxFlow(
  4,
  [[0, 1, 3], [0, 2, 2], [1, 2, 1], [1, 3, 2], [2, 3, 3]],
  0, 3,
); // { flow: 5 } — 경로 0→1→3으로 2, 경로 0→2→3으로 2, 경로 0→1→2→3으로 1

maxFlow(2, [[0, 1, 10]], 0, 1); // { flow: 10 } — 소스와 싱크가 직접 연결, 용량이 곧 최대 유량

maxFlow(3, [[0, 1, 5]], 0, 2); // { flow: 0 } — 정점 1과 싱크 2 사이 간선 없어 경로 없음

maxFlow(2, [], 0, 1); // { flow: 0 } — 간선 없음

maxFlow(
  4,
  [[0, 1, 3], [0, 2, 3], [1, 2, 2], [1, 3, 3], [2, 3, 3]],
  0, 3,
); // { flow: 6 } — 역방향 간선 활용 시 최대 유량 6

maxFlow(3, [[0, 1, 1_000_000], [1, 2, 1_000_000]], 0, 2); // { flow: 1000000 } — 직렬 경로, 병목 용량이 최대 유량
```
