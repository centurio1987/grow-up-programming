# 최소 비용 최대 유량 — 역방향 항목에 반대 부호의 단위 비용을 달면 경로 비용이 가장 작은 증가 경로만 보내도 보낸 양마다 총비용이 최소인 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 유량 배정을
전부 만들어 보는 방법에서 출발해 최소 비용 증가 경로까지 가고, 그 방법을 준비되는 차례대로 값으로 풉니다.
마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**유량 네트워크**는 간선마다 **용량**이 붙은 방향 그래프입니다. 용량은 그 간선으로 보낼 수 있는 양의 상한이에요.
정점 하나가 소스(출발), 다른 하나가 싱크(도착)입니다. 이 글의 네트워크에는 간선마다 수가 하나 더 붙습니다.
그 간선으로 **한 단위를 보낼 때 치르는 값**, 곧 **단위 비용**이에요. 정점 넷 · 간선 다섯인 네트워크에 그리면
이렇습니다.

<!--fig:concept-network-->
![전개 입력 — 간선 옆 수는 용량 · 단위 비용](./figs/concept-network.svg)

간선마다 실제로 보낸 양을 **유량**이라고 부릅니다. 유량은 두 조건을 지켜야 하고, 간선마다 「유량 × 단위 비용」을
더한 값이 그 배정의 **총비용**입니다.

| 조건 | 지켜야 하는 것 | 어기면 |
| --- | --- | --- |
| 용량 제한 | 간선마다 유량이 0 이상 용량 이하다 | 간선이 감당하지 못하는 양을 보낸 것이 된다 |
| 보존 | 소스와 싱크를 뺀 정점마다 들어온 양과 나간 양이 같다 | 중간 정점에 쌓이거나, 없던 양이 생긴다 |

두 조건을 지키면서 싱크에 도착하는 양을 가장 크게 만든 것이 **최대 유량**입니다. 이 글의 과제는 **최대 유량을
만드는 배정 가운데 총비용이 가장 작은 것**을 찾는 것이에요. 두 조건을 지키는 배정을 전부 만들어 유량 값마다
세면 이렇습니다.

<!--proof:conceptSplit-->

| 유량 값 | 그 값을 만드는 배정 | 총비용의 최솟값 | 총비용의 최댓값 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 0 | 0 |
| 1 | 3 | 3 | 7 |
| 2 | 6 | 6 | 14 |
| 3 | 9 | 11 | 21 |
| 4 | 8 | 16 | 26 |
| 5 | 5 | 23 | 31 |
| 6 | 2 | 32 | 36 |

두 조건을 지키는 배정이 모두 34 개이고 최대 유량은 6 입니다. 유량 6 을 만드는 배정은 2 개인데 총비용이 32 와 36 으로 갈립니다. 정본이 낸 답은 { flow: 6, cost: 32 } 입니다.

<!--/proof-->

최대 유량을 만드는 배정 둘을 나란히 그렸습니다. 굵은 선은 용량만큼 찬 간선이에요.

<!--fig:concept-two-flows-->
![유량 6 을 만드는 배정 둘](./figs/concept-two-flows.svg)

두 배정은 소스에서 나가는 양도, 싱크로 들어오는 양도 같습니다. 다른 것은 정점 1 에 들어온 양을 간선 `1 → 2` 와
`1 → 3` 에 어떻게 나눴는가이고, 단위 비용이 큰 `1 → 3` 에 더 많이 실은 쪽의 총비용이 큽니다. 최대 유량만 맞추는
절차는 이 둘을 가리지 못해요.

이 글은 최대 유량을 **증가 경로를 하나씩 찾아 보내는 방식**으로 만듭니다. 쓰는 구조는 **잔여 그래프**예요. 원래
간선 `u → v` 하나가 항목 둘이 됩니다. 정방향 항목 `u → v` 에는 더 보낼 수 있는 양(용량 − 유량)을, 역방향 항목
`v → u` 에는 앞서 보낸 것 중 되돌릴 수 있는 양(유량)을 적어요. 두 항목에 적힌 수가 **잔여 용량**입니다. 이 글은
여기에 단위 비용을 더합니다. 정방향 항목의 단위 비용은 간선의 단위 비용 `a` 그대로이고, 역방향 항목의 단위 비용은
**부호를 바꾼 `−a`** 예요. 경로 `0 → 1 → 2 → 3` 에 보낸 직후의 잔여 그래프가 이렇습니다.

<!--fig:concept-residual-->
![경로 하나를 보낸 뒤의 잔여 그래프](./figs/concept-residual.svg)

실선이 정방향 항목, 대시 선이 역방향 항목이고, 흐린 선은 잔여 용량이 0 이라 지금은 지날 수 없는 항목입니다. 보낸
경로의 역방향 항목에 잔여 용량이 생겼고, 그 항목의 단위 비용은 음수예요. 잔여 용량이 양수인 항목만 따라 소스에서
싱크까지 가는 길이 **증가 경로**이고, 그 길의 잔여 용량 가운데 가장 작은 값이 **병목**입니다. 증가 경로 위 항목의
단위 비용을 더한 값을 **경로 비용**이라고 부를게요. 그 경로로 한 단위를 더 보낼 때 늘어나는 총비용입니다.

이 글의 절차는 **경로 비용이 가장 작은 증가 경로**를 찾아 병목만큼 보내는 일을, 증가 경로가 없어질 때까지
되풀이합니다. 경로 하나를 찾아 보내는 일 한 벌을 **라운드**라고 불러요. 역방향 항목의 단위 비용이 음수라서
최단 경로를 찾는 자리에는 **음수 가중치를 받는 최단 경로 절차**가 필요하고, 이 글은 **SPFA**(값이 줄어든 정점만
큐에 넣어 그 정점의 항목을 다시 보는 최단 경로 절차)를 씁니다. 같은 네트워크에서 라운드마다 한 일을 적었어요.

<!--proof:conceptRounds-->

| 라운드 | 증가 경로 | 경로 비용 | 병목 | 누적 유량 | 누적 총비용 |
| --- | --- | ---: | ---: | ---: | ---: |
| 라운드 1 | 0 → 1 → 2 → 3 | 3 | 2 | 2 | 6 |
| 라운드 2 | 0 → 2 → 3 | 5 | 2 | 4 | 16 |
| 라운드 3 | 0 → 1 → 3 | 7 | 1 | 5 | 23 |
| 라운드 4 | 0 → 2 → 1 → 3 | 9 | 1 | 6 | 32 |
| 라운드 5 | 없음 | - | - | 6 | 32 |

경로 비용이 라운드마다 3 → 5 → 7 → 9 로 커지고, 라운드 5 에서 증가 경로가 없어 끝납니다. 답은 { flow: 6, cost: 32 } 입니다.

<!--/proof-->

라운드 수를 `R`, 정점 수를 `V`, 간선 수를 `E` 라고 하면 전체 비용은 $O(E + R \cdot V \cdot E)$ 이고, 추가로 쓰는
칸은 $O(V + E)$ 입니다.

| 할 일 | 하는 일 | 몇 번 |
| --- | --- | --- |
| 잔여 그래프 만들기 | 간선마다 단위 비용이 반대 부호인 항목 한 쌍 | 한 번 |
| 증가 경로 찾기 | 잔여 그래프에 SPFA | 라운드마다 한 번 |
| 병목만큼 보내기 | 경로를 거슬러 두 잔여를 고치고 총비용에 병목 × 경로 비용을 더한다 | 라운드마다 한 번 |
| 끝내기 | 싱크에 이르는 증가 경로가 없으면 멈춘다 | 한 번 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **잔여 그래프 · 증가 경로 · 병목.** 역방향 항목이 왜 있어야 하는지, 증가 경로가 없으면 왜 최대 유량인지는
  [`maxFlow` 가이드](../maxFlow/maxFlow-guide.md)가 다룹니다. 이 글은 그 위에 단위 비용 하나를 더합니다.
- **완화와 음수 가중치를 받는 최단 경로.** 간선 `u → v` 를 보고 `dist[u] + w` 가 `dist[v]` 보다 작으면 `dist[v]`
  를 그 값으로 고치는 일이 완화이고, 값이 줄어든 정점만 큐에 넣어 되풀이하는 절차가 SPFA 예요. 모르면
  [`spfa` 가이드](../../shortest-path/spfa/spfa-guide.md)를, 완화만 따로 보려면
  [`bellmanFord` 가이드](../../shortest-path/bellmanFord/bellmanFord-guide.md)를 보세요.
- **다익스트라가 기대는 전제.** 가중치가 음수가 아니면 값이 가장 작은 정점을 꺼낸 순간 그 값이 확정된다는
  전제입니다. [`dijkstra` 가이드](../../shortest-path/dijkstra/dijkstra-guide.md)가 그 자리이고, 이 글은 그 전제가
  역방향 항목 때문에 깨지는 것을 보입니다.
- **음수 사이클.** 단위 비용의 합이 0 보다 작은 순환 경로입니다. 이 글은 그런 사이클이 잔여 그래프에 생기지
  않는다는 것을 실행으로 확인해요.

이름이 비슷한 과제를 나란히 두면 이 글이 다루는 범위가 갈립니다.

| 과제 | 이 글에서 |
| --- | --- |
| 용량만 있는 네트워크의 최대 유량 | 다루지 않는다 — [`maxFlow`](../maxFlow/maxFlow-guide.md) |
| 용량과 단위 비용이 있는 네트워크에서 최대 유량을 만드는 배정 중 총비용이 가장 작은 것 | 다룬다 |
| 두 무리를 짝지으며 짝마다 비용이 다를 때의 최소 비용 배정 | 이 절차에 용량 1 네트워크로 옮겨 푼다 — 짝의 수만 보려면 [`maxBipartiteMatching`](../maxBipartiteMatching/maxBipartiteMatching-guide.md) |
| 유량을 포기해도 되니 총비용만 가장 작게 | 다루지 않는다 |

### 아이디어를 떠올리는 과정 — 유량 배정 전수 조사에서 최소 비용 증가 경로까지

아이디어를 찾기 전에 무엇을 만들지부터 정해 둡시다. 함수 하나가 네트워크를 받아 최대 유량과 그때의 최소 총비용을
돌려줍니다.

```ts
type FlowEdge = [number, number, number, number];

function minCostMaxFlow(
  n: number,
  edges: FlowEdge[],
  source: number,
  sink: number,
): { flow: number; cost: number };
```

- 입력: 정점 수 `n`, 방향 간선 목록 `edges`, 소스 `source`, 싱크 `sink`. 원소 `[u, v, cap, cost]` 는 `u` 에서 `v`
  로 가는 용량 `cap` · 단위 비용 `cost` 의 간선이고, 정점 번호는 0 부터 `n − 1` 까지예요.
- 출력: `{ flow, cost }`. `flow` 는 최대 유량, `cost` 는 그 유량을 만드는 배정 중 가장 작은 총비용입니다. 소스에서
  싱크로 가는 경로가 없으면 `{ flow: 0, cost: 0 }` 이에요.
- 규모: 정점 200 개 · 간선 2,000 개 · 용량과 단위 비용 10,000 까지로 잡고, 셋 다 0 이상의 정수입니다. 라운드마다
  최단 경로를 새로 재는 절차라 정점이 간선보다 한 자릿수 적은 네트워크를 골랐고, 이 크기에서 방법마다 연산 수가
  자릿수로 갈리는 것과 총비용이 배정밀도 수의 정수 범위 안에 드는 것을 함께 보일 수 있어서 이 값을 정했어요.
  **원래 간선의 단위 비용은 음수가 아닙니다.** 비용은 흔한 채점 환경의 예산인 1 초에 대어 잽니다.

이 글에서 쓰는 기호는 열두 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 뜻 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` | `2 ≤ V ≤ 200` |
| `E` | 간선 수. 코드의 `edges.length` | `0 ≤ E ≤ 2,000` |
| `s` | 소스 정점 번호. 코드의 `source` | `0 ≤ s < V` |
| `t` | 싱크 정점 번호. 코드의 `sink` | `0 ≤ t < V` |
| `c(u,v)` | 간선 `u → v` 의 용량. 간선 목록의 셋째 값 | `0 ≤ c ≤ 10,000` |
| `a(u,v)` | 간선 `u → v` 의 단위 비용. 간선 목록의 넷째 값 | `0 ≤ a ≤ 10,000` |
| `f(u,v)` | 간선 `u → v` 에 실은 유량 | 0 이상 `c(u,v)` 이하의 정수 |
| `cap(u,v)` | 항목 `u → v` 의 잔여 용량. 코드의 항목 `cap` 필드 | 정방향은 `c(u,v)`, 역방향은 0 에서 시작 |
| `d(v)` | 그 라운드에서 `s` 부터 `v` 까지의 가장 작은 경로 비용. 코드의 `dist` 배열 | 이를 수 없으면 ∞ |
| `δ` | 그 라운드가 보내는 양, 곧 병목. 코드의 `push` | 1 이상의 정수 |
| `F` | 최대 유량. 코드의 `flow` 가 이 값으로 끝난다 | `F ≤ E · 10,000` |
| `R` | 유량을 보낸 라운드의 수 | `R ≤ F` |

가장 먼저 떠오르는 방법으로 시작합시다. 과제의 정의를 그대로 옮기면 「간선마다 유량을 0 부터 용량까지 하나씩 넣어
보고, 두 조건을 지키는 배정 중 유량이 가장 크고 그중 총비용이 가장 작은 것을 고른다」예요. 가짓수가 유한하니
답은 반드시 나옵니다.

```ts
// 가장 단순한 방법 — 간선마다 0 부터 용량까지를 다 넣어 보고 두 조건을 확인한다.
function walk(i: number, f: number[]): void {
  if (i === edges.length) {
    if (conserves(f)) record(value(f), totalCost(f));
    return;
  }
  for (let x = 0; x <= edges[i][2]; x++) walk(i + 1, [...f, x]);
}
```

가짓수는 간선마다 `c + 1` 가지를 곱한 값입니다. 작은 입력 넷과 규모의 상한에서 세면 이렇습니다.

<!--proof:bruteScale-->

| 입력 | 간선 E | 배정의 가짓수 (c+1)^E | 두 조건을 지키는 배정 |
| --- | ---: | ---: | ---: |
| 간선 하나 | 1 | 8 | 8 |
| 직렬 경로 둘 | 2 | 36 | 6 |
| 비용이 작은 좁은 경로와 큰 넓은 경로 | 4 | 36 | 6 |
| 전개 입력 | 5 | 960 | 34 |
| 규모의 상한 | 2,000 | 10,001^2,000 | - |

규모의 상한에서 배정의 가짓수가 8,001 자리입니다. 1 초에 10 억 개씩 본다고 해도 자릿수가 아홉만 줄어 7,992 자리 초가 걸립니다.

<!--/proof-->

배정을 한꺼번에 고르지 말고 **증가 경로를 하나 찾아 보내고, 또 찾아 보내는** 쪽으로 가 봅시다. 최대 유량 편의
절차가 바로 그 모양이에요. 단위 비용은 보지 않고, 잔여 그래프에서 너비 우선 탐색이 처음 찾은 증가 경로에 병목만큼
보냅니다. 전개 입력에서 실행하면 이렇게 나옵니다.

<!--proof:anyPath-->

| 라운드 | 증가 경로 | 경로 비용 | 병목 | 누적 유량 | 누적 총비용 |
| --- | --- | ---: | ---: | ---: | ---: |
| 라운드 1 | 0 → 1 → 3 | 7 | 3 | 3 | 21 |
| 라운드 2 | 0 → 2 → 3 | 5 | 3 | 6 | 36 |
| 라운드 3 | 없음 | - | - | 6 | 36 |

최대 유량 6 은 맞지만 총비용이 36 이라, 전수 조사가 낸 최솟값 32 보다 4 큽니다.

<!--/proof-->

최대 유량은 맞았는데 총비용이 커졌습니다. 첫 라운드가 단위 비용이 큰 `1 → 3` 을 지나는 경로에 먼저 보냈고, 그 뒤로는
되돌릴 이유가 없어서 그대로 끝났어요. **어느 증가 경로를 먼저 보내는가가 총비용을 정한 것**입니다. 그러면 차례를
규칙으로 정해 봅시다. 가장 먼저 떠오르는 규칙은 「라운드마다 경로 비용이 가장 작은 증가 경로를 보낸다」예요. 같은
입력을 두 규칙으로 처리해 계수를 나란히 놓았습니다. **항목 검사**는 잔여 그래프의 항목 하나를 읽은 한 번이고,
최단 경로 절차가 조건을 보려고 읽은 것과 경로를 거슬러 올라가며 읽은 것을 모두 셉니다.

<!--proof:twoWays-->

| 계수 | 경로 비용이 가장 작은 경로 먼저 | 아무 증가 경로 먼저 |
| --- | ---: | ---: |
| 최대 유량 | 6 | 6 |
| 총비용 | 32 | 36 |
| 라운드 수 | 4 | 2 |
| 항목 검사 | 62 | 30 |
| 라운드마다의 경로 비용 | 3 · 5 · 7 · 9 | 7 · 5 |

최대 유량은 두 방식이 6 으로 같고 총비용은 32 와 36 으로 갈립니다. 경로 비용이 가장 작은 쪽은 라운드마다의 경로 비용이 한 번도 줄지 않고, 아무 증가 경로 쪽은 7 에서 5 로 줄어듭니다.

<!--/proof-->

경로 비용이 가장 작은 쪽은 라운드는 많지만 총비용이 전수 조사의 최솟값과 같습니다. 여기서 관찰할 것은
**라운드마다의 경로 비용이 한 번도 줄지 않는다**는 점이에요. 아무 증가 경로를 고른 쪽은 경로 비용이 줄어드는
자리가 있는데, 그것은 먼저 치른 값이 나중 값보다 컸다는 뜻이라 차례를 바꿔 더 줄일 여지가 남아 있었던 것입니다.

다만 「경로 비용이 가장 작다」를 재려면 잔여 그래프의 항목마다 단위 비용이 있어야 합니다. 가장 단순한 후보부터
시험해 봅시다. 첫째는 **정방향 항목만** 따라 경로 비용이 가장 작은 경로를 찾는 것이에요. 원래 간선에만 단위 비용이
있으니 가장 곧은 방법입니다.

<!--proof:forwardOnly-->

| 라운드 | 증가 경로 | 경로 비용 | 병목 | 누적 유량 | 누적 총비용 |
| --- | --- | ---: | ---: | ---: | ---: |
| 라운드 1 | 0 → 1 → 2 → 3 | 3 | 2 | 2 | 6 |
| 라운드 2 | 0 → 2 → 3 | 5 | 2 | 4 | 16 |
| 라운드 3 | 0 → 1 → 3 | 7 | 1 | 5 | 23 |
| 라운드 4 | 없음 | - | - | 5 | 23 |

정방향 항목만 따라가면 라운드 4 에서 증가 경로가 없어 유량 5 로 멈춥니다. 최대 유량은 6 입니다.

<!--/proof-->

유량이 최대에 못 미칩니다. 라운드 3 까지는 경로 비용이 가장 작은 쪽과 같은 경로를 보냈는데, 그 뒤에 남은 길은
라운드 1 이 `1 → 2` 로 보낸 것을 되돌려야만 싱크에 이릅니다. 최대 유량 편이 역방향 항목을 둔 까닭과 같아요. 그러니
역방향 항목도 지나야 하고, 거기에 붙일 단위 비용을 정해야 합니다. 둘째 후보는 **역방향 항목에도 원래 간선의 단위 비용
`a` 를 그대로 다는 것**이에요. 정본의 한 줄을 이렇게 바꿉니다.

```ts
    to.push({ to: u, cap: 0, cost: cost, rev: from.length - 1 });   // ← 같은 부호로 둔 판
```

<!--proof:sameSign-->

| 입력 | 정본 유량 / 총비용 | 같은 부호로 둔 판 | 대조 |
| --- | ---: | ---: | --- |
| 전개 입력 | 6 / 32 | 6 / 34 | 어긋난다 |
| 역방향 항목이 꼭 필요한 넷 | 2 / 14 | 2 / 16 | 어긋난다 |
| 비용이 작은 좁은 경로와 큰 넓은 경로 | 3 / 22 | 3 / 22 | 같다 |
| 직렬 경로 둘 | 5 / 25 | 5 / 25 | 같다 |

유량은 최대인데 총비용이 커지는 입력이 있습니다. 역방향 항목을 지나는 것은 앞서 보낸 한 단위를 **되돌리는** 일인데,
그 항목에 `+a` 를 달면 되돌리는 데 값을 한 번 더 치르는 셈이 되기 때문이에요. 되돌린 한 단위는 치른 `a` 를
되돌려 받아야 하므로 역방향 항목의 단위 비용은 `−a` 여야 합니다. 지금까지 해 본 방법 다섯을 차례로 놓으면
이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 다섯](./figs/origin-approaches.svg)

남은 방법이 **최소 비용 증가 경로**입니다. 역방향 항목에 `−a` 를 단 잔여 그래프에서 경로 비용이 가장 작은 증가
경로를 찾아 병목만큼 보내요. 아직 확인하지 않은 것이 있습니다. 음수 단위 비용이 있는 잔여 그래프에서 최단 경로를
어떻게 재는지, 라운드마다 가장 작은 것만 골랐는데 왜 끝에 가서 총비용 전체가 가장 작은지입니다. 다음 절에서
실현하는 차례대로 확인합니다.

### 아이디어 상세 — 최소 비용 증가 경로

이 아이디어를 한 문장으로 줄이면 이렇습니다. **간선마다 단위 비용이 `a` 인 정방향 항목과 `−a` 인 역방향 항목을 둔
잔여 그래프에서, 음수 비용을 받는 최단 경로 절차로 경로 비용이 가장 작은 증가 경로를 찾아 병목만큼 보내는 일을
증가 경로가 없어질 때까지 되풀이합니다.** 잔여 그래프 자체는 최대 유량 편에서 왔지만, 그 항목에 음수 단위 비용이
붙는 것은 처음 보는 사람에게 낯설어요. 그 개념을 먼저 따로 설명하고, 그다음 앞 단계에서 만든 것을 뒤 단계에서 쓰는
차례로 네 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 항목 한 쌍 담기 | 간선마다 단위 비용이 반대 부호인 두 항목과 짝의 자리 | — |
| 라운드마다 | 2단계 증가 경로 찾기 | 잔여 용량이 양수인 항목만 지나는 SPFA 로 `dist` 와 직전 항목 | 1단계의 잔여 용량과 단위 비용 |
| 라운드마다 | 3단계 병목만큼 보내기 | 경로를 거슬러 병목을 재고, 두 잔여를 고치고, 총비용에 병목 × 경로 비용 | 2단계의 직전 항목과 `d(t)` · 1단계의 짝 자리 |
| 라운드가 시작될 때 | 4단계 끝낼지 정하기 | `d(t)` 가 ∞ 이면 끝낸다 | 2단계의 `dist` |

#### 먼저 알아 둘 개념 — 잔여 그래프의 단위 비용

잔여 그래프의 단위 비용은 **그 항목으로 한 단위를 옮길 때 총비용이 얼마나 바뀌는가**를 적은 수입니다. 정방향 항목
`u → v` 로 한 단위를 옮기면 간선에 유량이 하나 늘어 총비용이 `a(u,v)` 늘고, 역방향 항목 `v → u` 로 한 단위를
옮기면 간선의 유량이 하나 줄어 총비용이 `a(u,v)` 줄어요. 그래서 두 항목에 `a` 와 `−a` 를 답니다.

##### 입력 위의 단위 비용

전개 입력에서 라운드 3 을 보낸 직후의 잔여 그래프입니다. 항목 10 개를 모두 그렸어요.

<!--fig:build-residual-->
![라운드 3 을 보낸 직후의 잔여 그래프](./figs/build-residual.svg)

역방향 항목 다섯에 모두 잔여 용량이 생겼고, 그 단위 비용이 모두 음수입니다. 정방향 항목 셋(`0 → 1` · `1 → 2` ·
`2 → 3`)은 잔여 용량이 0 이라 흐린 선이에요.

##### 항목 한 쌍을 읽는 법

간선 `1 → 2` 를 골라 두 항목을 읽어 보겠습니다. 용량에서 정방향 잔여를 빼면 지금 실린 유량이고, 그 값이 역방향
잔여와 같아요.

<!--proof:residualReadOne-->

| 읽는 것 | 자리 | 잔여 용량 | 단위 비용 |
| --- | --- | ---: | ---: |
| 간선의 용량과 단위 비용 | c(1,2) · a(1,2) | 2 | 1 |
| 정방향 항목 | 1→2 | 0 | 1 |
| 역방향 항목 | 2→1 | 2 | -1 |

1 에서 2 로 더 보낼 수 있는 양이 0 이고, 앞서 보낸 2 가운데 되돌릴 수 있는 양이 2 입니다. 되돌리면 한 단위마다 -1 이 더해져 앞서 치른 1 을 되돌려 받습니다.

<!--/proof-->

##### 짝끼리의 관계

같은 간선에서 나온 두 항목은 서로 짝입니다. 한쪽으로 `δ` 를 보내면 그 항목의 잔여가 `δ` 줄고 짝의 잔여가 `δ`
늘어요. 그래서 두 잔여의 합은 언제나 처음 용량이고, 두 단위 비용의 합은 언제나 0 입니다. 다섯 쌍을 모두 재면
이렇습니다.

<!--proof:residualPairs-->

| 간선 | 용량 | 정방향 잔여 · 비용 | 역방향 잔여 · 비용 | 두 잔여의 합 | 두 비용의 합 |
| --- | ---: | --- | --- | ---: | ---: |
| 0→1 | 3 | 0 · 1 | 3 · -1 | 3 | 0 |
| 0→2 | 3 | 1 · 4 | 2 · -4 | 3 | 0 |
| 1→2 | 2 | 0 · 1 | 2 · -1 | 2 | 0 |
| 1→3 | 3 | 2 · 6 | 1 · -6 | 3 | 0 |
| 2→3 | 4 | 0 · 1 | 4 · -1 | 4 | 0 |

5 쌍 중 5 쌍에서 두 잔여의 합이 용량과 같고, 5 쌍에서 두 비용의 합이 0 입니다.

<!--/proof-->

두 단위 비용의 합이 0 이라는 것은 경로가 역방향 항목을 지날 때 그 비용이 **빠진다**는 뜻입니다. 이 그래프에서 다음
라운드가 고르는 증가 경로를 항목마다 적었어요.

<!--proof:roundFourCost-->

| 지난 항목 | 방향 | 단위 비용 |
| --- | --- | ---: |
| 0→2 | 정방향 | 4 |
| 2→1 | 역방향 | -1 |
| 1→3 | 정방향 | 6 |

세 항목의 단위 비용을 더한 경로 비용은 9 로 SPFA 가 싱크에 적은 값 d(3) = 9 와 같습니다.

<!--/proof-->

경로 비용이 곧 총비용의 변화량이라는 것은 끝난 뒤의 배정으로 확인할 수 있습니다. 간선마다 `f(u,v) × a(u,v)` 를
더한 값과, 라운드마다 병목 × 경로 비용을 더해 온 값을 나란히 놓았습니다.

<!--proof:finalCost-->

| 간선 | 용량 | 단위 비용 | 유량 | 유량 × 단위 비용 |
| --- | ---: | ---: | ---: | ---: |
| 0→1 | 3 | 1 | 3 | 3 |
| 0→2 | 3 | 4 | 3 | 12 |
| 1→2 | 2 | 1 | 1 | 1 |
| 1→3 | 3 | 6 | 2 | 12 |
| 2→3 | 4 | 1 | 4 | 4 |

간선마다의 곱을 더하면 32 이고, 라운드마다 병목 × 경로 비용을 더해 온 변수 cost 도 32 입니다. 간선 1→2 에는 라운드 1 이 보낸 2 가운데 라운드 4 가 되돌리고 남은 1 이 실려 있습니다.

<!--/proof-->

##### 같은 부호로 단 모양과의 차이

역방향 항목의 단위 비용을 처음 보면 「비용은 비용이니 `a` 를 그대로 단다」로 읽기 쉽습니다. 「아이디어를 떠올리는
과정」에서 그 판의 총비용이 커지는 것을 봤어요. 어느 라운드에서 갈리는지 두 판을 라운드마다 나란히 놓았습니다.

<!--proof:signRounds-->

| 라운드 | 증가 경로 | 반대 부호의 경로 비용 | 같은 부호의 경로 비용 | 차이 |
| --- | --- | ---: | ---: | ---: |
| 라운드 1 | 0 → 1 → 2 → 3 | 3 | 3 | 0 |
| 라운드 2 | 0 → 2 → 3 | 5 | 5 | 0 |
| 라운드 3 | 0 → 1 → 3 | 7 | 7 | 0 |
| 라운드 4 | 0 → 2 → 1 → 3 | 9 | 11 | 2 |

두 판이 고른 증가 경로는 4 라운드 중 4 라운드에서 같고, 경로 비용이 갈리는 라운드는 1 개입니다. 총비용은 32 와 34 로 2 차이가 납니다.

<!--/proof-->

두 판은 같은 경로를 고르고, 역방향 항목을 지나는 라운드 4 에서만 경로 비용이 갈립니다. 되돌린 한 단위에서 치렀던
`a(1,2)` 를 빼는 대신 한 번 더 더하므로, 그 차이가 `2 · a(1,2)` 이고 그대로 총비용의 차이가 돼요.

##### 이렇게 생긴 까닭

경로 비용이 **그 경로로 한 단위를 보낼 때 총비용이 실제로 늘어나는 양**과 같아야 「경로 비용이 가장 작은 증가
경로」가 뜻을 갖기 때문입니다. 역방향 항목을 지나면 원래 간선의 유량이 줄고, 줄어든 만큼의 비용은 총비용에서
빠져요. 그 빠지는 양을 항목에 적은 것이 `−a` 입니다.

| 항목 | 한 단위를 옮기면 간선의 유량 | 총비용의 변화 | 그래서 다는 단위 비용 |
| --- | --- | --- | --- |
| 정방향 `u → v` | `f(u,v)` 가 1 늘어난다 | `a(u,v)` 만큼 는다 | `a(u,v)` |
| 역방향 `v → u` | `f(u,v)` 가 1 줄어든다 | `a(u,v)` 만큼 준다 | `−a(u,v)` |

#### 1단계 — 간선마다 단위 비용이 반대 부호인 항목 한 쌍 담기

정점마다 목록을 하나 두고, 간선 `u → v` 마다 `u` 의 목록에 정방향 항목(잔여 `c` · 단위 비용 `a`)을, `v` 의 목록에
역방향 항목(잔여 0 · 단위 비용 `−a`)을 넣습니다. 두 항목은 짝이 상대 목록에서 몇 번째 자리에 있는지(`rev`)를 서로
적어 둬요. 전개 입력에서 만든 목록은 이렇습니다.

<!--proof:stageBuild-->

| 정점 | 정방향 항목 | 역방향 항목 | 목록 길이 |
| --- | --- | --- | ---: |
| 0 | 0→1 잔여 3 · 비용 1 · 0→2 잔여 3 · 비용 4 | 없음 | 2 |
| 1 | 1→2 잔여 2 · 비용 1 · 1→3 잔여 3 · 비용 6 | 1→0 잔여 0 · 비용 -1 | 3 |
| 2 | 2→3 잔여 4 · 비용 1 | 2→0 잔여 0 · 비용 -4 · 2→1 잔여 0 · 비용 -1 | 3 |
| 3 | 없음 | 3→1 잔여 0 · 비용 -6 · 3→2 잔여 0 · 비용 -1 | 2 |

목록 길이의 합은 10 이고 간선 5 개의 두 배입니다. 역방향 항목 5 개는 모두 잔여 0 으로 시작하고, 단위 비용은 짝의 부호를 바꾼 값입니다.

<!--/proof-->

크기는 여기서 정해집니다. 항목은 정확히 `2E` 개이고 목록 길이의 합도 `2E` 예요. 역방향 항목은 잔여 용량이 0 이라
처음 라운드에서는 어느 경로에도 쓰이지 않습니다.

#### 2단계 — 음수 비용을 받는 최단 경로로 증가 경로 찾기

라운드를 시작할 때 `dist` 를 전부 ∞ 로 두고 소스에만 0 을 적은 뒤 SPFA 를 실행합니다. 잔여 용량이 양수인 항목만
지나며, `dist[u] + 단위 비용` 이 `dist[v]` 보다 작으면 값을 고치고 **그 항목의 자리를 직전 항목으로 적어 둬요.**
직전 정점만 적으면 두 정점 사이에 간선이 여럿일 때 어느 항목을 지나왔는지 모릅니다. 라운드마다 SPFA 가 낸 값은
이렇습니다.

<!--proof:stageSpfa-->

| 라운드 | dist | 증가 경로 | 경로 비용 | 지난 역방향 항목 |
| --- | --- | --- | ---: | --- |
| 라운드 1 | [0, 1, 2, 3] | 0 → 1 → 2 → 3 | 3 | 안 지난다 |
| 라운드 2 | [0, 1, 4, 5] | 0 → 2 → 3 | 5 | 안 지난다 |
| 라운드 3 | [0, 1, 4, 7] | 0 → 1 → 3 | 7 | 안 지난다 |
| 라운드 4 | [0, 3, 4, 9] | 0 → 2 → 1 → 3 | 9 | 2→1 |
| 라운드 5 | [0, ∞, ∞, ∞] | 없음 | - | - |

역방향 항목을 지난 라운드는 라운드 4 하나이고, 그 라운드에서 정점 1 의 값이 3 입니다. 마지막 라운드는 싱크의 값이 ∞ 로 남습니다.

<!--/proof-->

라운드 1 에서 3 까지는 잔여 용량이 있는 역방향 항목이 있어도 증가 경로가 그것을 지나지 않습니다. 가장 불안한
경우인 라운드 4 를 SPFA 가 꺼낸 차례대로 적었어요.

<!--proof:stageSpfaFour-->

| 꺼낸 정점 | 값을 줄인 정점 (지난 항목) | 꺼낸 뒤 큐 |
| --- | --- | --- |
| 0 | 2 에 4 (0→2) | [2] |
| 2 | 1 에 3 (2→1 역방향) | [1] |
| 1 | 3 에 9 (1→3) | [3] |
| 3 | 없음 | [] |

라운드 4 에서 정점 1 은 역방향 항목 2→1 을 지나 값 3 을 받습니다. 정방향 항목 0→1 은 잔여가 0 이라 지날 수 없습니다.

<!--/proof-->

정점 1 의 값이 정점 2 의 값보다 작습니다. 정점 2 를 거쳐 음수 항목으로 들어가면 간선을 하나 더 지나도 값이 더
작아지는 것이 음수 단위 비용이 있는 그래프의 모양이에요. SPFA 는 값을 확정하지 않고, 값이 줄어든 정점을 큐에
다시 넣어 그 정점의 항목을 다시 봅니다. 큐가 비는 순간에는 더 줄일 수 있는 항목이 없으므로 `dist` 가 가장 작은
경로 비용이에요.

#### 3단계 — 병목만큼 보내고 총비용 더하기

싱크에서 소스로 직전 항목을 따라 거슬러 올라가며 잔여 용량의 최솟값 `δ` 를 잽니다. 같은 길을 한 번 더 거슬러
올라가며 그 항목의 잔여에서 `δ` 를 빼고 짝의 잔여에 `δ` 를 더해요. 경로 위 모든 단위가 같은 경로 비용 `d(t)` 를
치르므로 총비용에는 `δ × d(t)` 를 더합니다. 라운드 1 을 보낸 결과는 이렇습니다.

<!--proof:stagePush-->

| 지난 항목 | 그 항목의 잔여 | 짝 항목의 잔여 |
| --- | --- | --- |
| 0→1 | 3 → 1 | 1→0 0 → 2 |
| 1→2 | 2 → 0 | 2→1 0 → 2 |
| 2→3 | 4 → 2 | 3→2 0 → 2 |

병목은 min(3, 2, 4) = 2 이고 경로 비용은 3 입니다. 총비용에 2 × 3 = 6 이 더해져 누적 총비용이 6 이 됩니다.

<!--/proof-->

이 단계에서 이 아이디어가 맞는 근거가 되는 성질이 처음 쓰입니다. **라운드가 끝날 때마다 누적 총비용이 그 유량
값을 만드는 배정 가운데 가장 작은 총비용과 같다**는 것이에요. 전수 조사로 유량 값마다의 최소 총비용을 구해,
라운드가 끝난 자리의 누적 총비용과 맞대 보았습니다.

<!--proof:marginal-->

| 유량 값 | 전수 조사의 최소 총비용 | 한 단위 더 보내는 값 | 그 유량 값에 이른 라운드 | 그때의 누적 총비용 |
| ---: | ---: | ---: | --- | ---: |
| 0 | 0 | - | 시작 | 0 |
| 1 | 3 | 3 | 지나간다 | - |
| 2 | 6 | 3 | 라운드 1 | 6 |
| 3 | 11 | 5 | 지나간다 | - |
| 4 | 16 | 5 | 라운드 2 | 16 |
| 5 | 23 | 7 | 라운드 3 | 23 |
| 6 | 32 | 9 | 라운드 4 | 32 |

라운드가 끝난 4 자리 중 4 자리에서 누적 총비용이 전수 조사의 최솟값과 같습니다. 한 단위 더 보내는 값 3 3 5 5 7 9 는 라운드마다의 경로 비용 3 5 7 9 를 병목 2 2 1 1 만큼 펼친 3 3 5 5 7 9 와 같습니다.

<!--/proof-->

두 줄이 같다는 것은 이 절차가 **한 단위 더 보내는 데 드는 최소값을 작은 것부터 차례로 치르고 있다**는 뜻입니다.
그래서 어느 라운드에서 멈추든 그때의 유량 값에서 가장 작은 총비용을 들고 있어요. 이 성질이 어느 입력에서도
유지되는 까닭은 「수식 정의와 유도」에서 유도합니다.

#### 4단계 — 증가 경로가 없으면 끝내기

SPFA 가 끝났는데 `d(t)` 가 ∞ 이면 잔여 그래프에 싱크로 가는 증가 경로가 없다는 뜻이라 반복을 끝냅니다. 그때의
유량이 최대 유량이에요. 전개 입력의 마지막 라운드는 이렇습니다.

<!--proof:stageStop-->

| 소스에서 나가는 정방향 항목 | 잔여 용량 | 실린 유량 |
| --- | ---: | ---: |
| 0→1 | 0 | 3 |
| 0→2 | 0 | 3 |

라운드 5 의 dist 는 [0, ∞, ∞, ∞] 입니다. 소스에서 나가는 정방향 항목의 잔여가 모두 0 이라 SPFA 가 소스 하나만 꺼내고 끝나고, d(3) = ∞ 라 반복을 끝냅니다.

<!--/proof-->

정수 용량에서는 라운드마다 병목이 1 이상이라 유량이 1 이상 늘어나므로, 유량을 보낸 라운드 수 `R` 은 `F` 를 넘지
못하고 반복이 반드시 끝납니다.

#### 이 방법이 기대는 전제

최소 비용 증가 경로는 아래 세 전제에 기대고 있어서, 하나라도 빠지면 답이 틀리거나 끝나지 않습니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 원래 간선의 단위 비용이 음수가 아니다 | 처음 잔여 그래프에 음수 사이클이 없어야 2단계의 최단 경로가 정해진다 | 음수 사이클이 있으면 최단 경로 비용이 정해지지 않는다 |
| 라운드마다 경로 비용이 **가장 작은** 증가 경로로 보낸다 | 3단계의 「보낸 양마다 최소」 | 음수 사이클이 남아, 유량은 그대로 두고 총비용만 줄일 수 있는 상태로 끝난다 |
| 용량이 정수다 | 4단계의 「반드시 끝난다」 | 병목이 한없이 작아져 라운드가 끝나지 않을 수 있다 |

둘째 전제가 깨지는 모습을 값으로 봅시다. 라운드마다 단위 비용을 안 보고 아무 증가 경로나 보낸 판과 정본에서,
라운드를 시작할 때 잔여 그래프에 음수 사이클이 있었는지를 셌어요.

<!--proof:premiseAny-->

| 입력 | 정본 총비용 | 아무 증가 경로의 총비용 | 정본에서 음수 사이클이 있던 라운드 | 아무 증가 경로에서 음수 사이클이 있던 라운드 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 32 | 36 | 0 | 2 |
| 역방향 항목이 꼭 필요한 넷 | 14 | 14 | 0 | 1 |
| 정점 다섯 · 용량이 전부 1 | 6 | 6 | 0 | 1 |
| 비용이 작은 좁은 경로와 큰 넓은 경로 | 22 | 22 | 0 | 0 |
| 직렬 경로 둘 | 25 | 25 | 0 | 0 |
| 간선 하나 | 21 | 21 | 0 | 0 |

정본은 입력 6 개 모두 음수 사이클이 있던 라운드가 0 이고, 아무 증가 경로를 고른 판은 3 개 입력에서 0 이 아닙니다.

<!--/proof-->

음수 사이클이 남아 있다는 것은 그 사이클을 따라 한 단위를 옮기면 정점마다 들어온 양과 나간 양이 그대로인 채 총비용만
사이클의 합만큼 준다는 뜻입니다. 정본은 그런 사이클을 한 번도 남기지 않아요.

#### 네 단계를 이은 절차

네 단계를 코드의 차례로 다시 적으면 이렇습니다.

1. 간선마다 정방향 항목(잔여 `c` · 단위 비용 `a`)과 역방향 항목(잔여 0 · 단위 비용 `−a`)을 짝지어 넣는다(1단계)
2. SPFA 로 `dist` 와 직전 항목을 적는다(2단계)
3. `dist[t]` 가 ∞ 이면 지금까지의 유량과 총비용을 돌려주고 끝낸다(4단계)
4. 경로를 거슬러 병목 `δ` 를 재고, 두 잔여를 고치고, 총비용에 `δ × dist[t]` 를 더한다(3단계)
5. 2 로 돌아간다

### 수행으로 알아보는 알고리즘 — 정점 넷 네트워크에서 네 라운드로 유량 6 을 총비용 32 에 보낸다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 정해 끝까지 가져가되, 조각을 하나
만들 때마다 그 조각만 실행한 결과를 확인하고 넘어갑니다.

```ts
const n = 4;
const edges: FlowEdge[] = [
  [0, 1, 3, 1], [0, 2, 3, 4], [1, 2, 2, 1], [1, 3, 3, 6], [2, 3, 4, 1],
];
const source = 0;
const sink = 3;
// 이 절이 끝나면 { flow: 6, cost: 32 } 가 나와야 한다
```

이 입력을 고른 까닭은 **코드의 갈래 여섯이 한 번씩 다 실행되기** 때문입니다. 병목이 2 인 라운드와 1 인 라운드가
둘씩 나오고, 역방향 항목을 지나는 라운드가 하나 있으며, 마지막 라운드가 증가 경로를 못 찾아 반복을 끝내요.

```text
minCostMaxFlow(n, edges, source, sink):
    간선 [u, v, cap, cost] 마다 정방향(잔여 cap · 비용 cost)과 역방향(잔여 0 · 비용 -cost)을 짝지어 넣는다   ① 담는다
    반복:                                                                                              ② 라운드
        SPFA 로 dist 와 직전 항목을 적는다                                                               ③ 값을 줄인다
        dist[sink] 가 ∞ 이면 { flow, cost } 를 돌려준다                                                  ④ 끝낸다
        직전 항목을 거슬러 병목 push 를 잰다                                                             ⑤ 병목
        같은 길을 거슬러 잔여를 빼고 짝에 더하고, cost 에 push × dist[sink] 를 더한다                       ⑥ 보낸다
```

#### 1. 간선 하나를 비용이 반대 부호인 두 항목으로 담는다

간선 `u → v` 하나가 잔여 그래프에서는 항목 **둘**이 됩니다. 둘이 서로의 자리 번호를 알고 있어야 유량을 보낼 때
한 번에 양쪽을 고칠 수 있어요.

```ts
interface Arc {
  to: number;
  cap: number;
  cost: number;
  rev: number;
}

// ① 간선 하나를 두 항목으로 나눠 담는다 — 역방향 항목은 용량 0 에 단위 비용이 반대 부호다.
const graph: Arc[][] = Array.from({ length: n }, () => []);
for (const [u, v, cap, cost] of edges) {
  const from = graph[u] as Arc[];
  const to = graph[v] as Arc[];
  from.push({ to: v, cap, cost, rev: to.length });
  to.push({ to: u, cap: 0, cost: -cost, rev: from.length - 1 });
}
```

실행하면 이렇게 나옵니다. 정점 1 의 목록에 정방향 둘과 역방향 하나가 섞여 있어요.

<!--proof:walkInit-->

```text
graph[0] = [ {to:1, cap:3, cost:1, rev:0}, {to:2, cap:3, cost:4, rev:0} ]
graph[1] = [ {to:0, cap:0, cost:-1, rev:0}, {to:2, cap:2, cost:1, rev:1}, {to:3, cap:3, cost:6, rev:0} ]
graph[2] = [ {to:0, cap:0, cost:-4, rev:1}, {to:1, cap:0, cost:-1, rev:1}, {to:3, cap:4, cost:1, rev:1} ]
graph[3] = [ {to:1, cap:0, cost:-6, rev:2}, {to:2, cap:0, cost:-1, rev:2} ]
항목 10 개 = 간선 5 개 × 2
```

여기서 가장 중요한 줄은 `cost: -cost` 입니다. 이 한 글자가 빠지면 되돌리는 데 값을 한 번 더 치르게 되고, 「아이디어를
떠올리는 과정」에서 본 대로 총비용이 커지는 입력이 생겨요.

#### 2. SPFA 로 경로 비용이 가장 작은 증가 경로를 찾는다

라운드마다 배열 넷을 새로 만듭니다. `dist` 는 가장 작은 경로 비용, `waiting` 은 지금 큐에 있는가, `fromV` · `fromE` 는
직전 정점과 그 목록 안의 항목 자리예요. 잔여 용량이 0 인 항목은 지날 수 없으므로 완화 조건이 `arc.cap > 0` 을
함께 봅니다.

```ts
const dist = Array.from({ length: n }, () => Number.POSITIVE_INFINITY);
const waiting = Array.from({ length: n }, () => false);
const fromV = Array.from({ length: n }, () => -1);
const fromE = Array.from({ length: n }, () => -1);
dist[source] = 0;
const queue: number[] = [source];
waiting[source] = true;

// ③ 완화 큐 — 값이 줄어든 정점만 다시 넣는다. 음수 비용 항목도 그대로 다룬다.
while (queue.length > 0) {
  const u = queue.shift() as number;
  waiting[u] = false;
  const arcs = graph[u] as Arc[];
  for (let i = 0; i < arcs.length; i++) {
    const arc = arcs[i] as Arc;
    const next = (dist[u] as number) + arc.cost;
    if (arc.cap > 0 && next < (dist[arc.to] as number)) {
      dist[arc.to] = next;
      fromV[arc.to] = u;
      fromE[arc.to] = i;
      if (!waiting[arc.to]) {
        queue.push(arc.to);
        waiting[arc.to] = true;
      }
    }
  }
}
```

라운드 1 에서 이 조각을 실행하면 이렇게 나옵니다.

<!--proof:walkFirst-->

```text
0 을 꺼낸다   1 을 1 로 · 2 를 4 로                    큐 [1, 2]
1 을 꺼낸다   2 를 2 로 · 3 을 7 로 · 2 는 이미 큐에   큐 [2, 3]
2 를 꺼낸다   3 을 3 으로 · 3 은 이미 큐에             큐 [3]
3 을 꺼낸다   줄인 값이 없다                           큐 []
dist = [0, 1, 2, 3]
```

정점 1 을 꺼냈을 때 정점 2 의 값이 4 에서 2 로 줄었는데, 정점 2 는 이미 큐에 있어서 `!waiting[2]` 가 거짓이라 다시
넣지 않습니다. 값만 고쳐 두면 큐에서 꺼낼 때 고친 값으로 읽히기 때문이에요. 간선을 하나 더 지나는 `0 → 1 → 2` 가 곧장
가는 `0 → 2` 보다 경로 비용이 작다는 것도 봐 주세요. 이 과제에서는 간선 수가 아니라 경로 비용이 작은 경로를 찾아야
합니다.

#### 짚고 가기 — 최단 경로니까 다익스트라를 써도 될 것 같다

최단 경로를 구하는 자리이니 값이 가장 작은 정점을 꺼내고, 한 번 꺼낸 정점은 다시 보지 않는 다익스트라가 자연스러워
보입니다. 한 라운드에 정점을 한 번씩만 꺼내니 일도 줄어들 것 같아요. SPFA 를 이렇게 바꿔 봅시다.

```ts
// 값이 가장 작은 정점을 꺼내고, 한 번 꺼낸 정점은 다시 안 보는 판
let at = -1;
for (let v = 0; v < n; v++) {
  if (done[v] || dist[v] === Number.POSITIVE_INFINITY) continue;
  if (at < 0 || dist[v] < dist[at]) at = v;
}
done[at] = true;
```

입력 여섯에 실행해 정본과 비교하면 **대부분의 입력에서 답이 안 틀립니다.** 전개 입력도 답이 같아서, 전개만 따라가면
이 자리를 그냥 지나가요.

| 입력 | 정본 유량 / 총비용 | 다익스트라로 바꾼 판 | 대조 |
| --- | ---: | ---: | --- |
| 전개 입력 | 6 / 32 | 6 / 32 | 같다 |

| 직렬 경로 둘 | 5 / 25 | 5 / 25 | 같다 |

| --- | --- | --- | --- | --- |

<!--/proof-->

라운드 2 에서 정본은 정점 2 의 값을 정점 3 을 거친 역방향 항목으로 더 줄이는데, 다익스트라 판은 정점 2 를 먼저 꺼내
확정해 버려서 그 값을 못 고칩니다. 「꺼낸 값이 확정」이라는 전제는 모든 단위 비용이 음수가 아닐 때만 성립하고, 잔여
그래프에는 음수 단위 비용인 역방향 항목이 있어요. 그래서 정본은 값을 확정하지 않고, 값이 줄어든 정점을 큐에 다시
넣습니다. 잠재값으로 단위 비용을 다시 매기면 이 전제를 되살릴 수 있는데, 그 유도는 「수식 정의와 유도」가 합니다.

#### 3. 경로를 거슬러 병목을 재고 두 잔여와 총비용을 고친다

증가 경로를 찾았으면 얼마나 보낼지 정합니다. 싱크의 값이 ∞ 가 아니면 `fromV` · `fromE` 를 따라 싱크에서 소스까지
거슬러 올라가며 잔여 용량의 최솟값을 재고, 같은 길을 한 번 더 거슬러 올라가며 두 잔여를 고쳐요.

```ts
// ④ 싱크의 값이 그대로면 더 보낼 경로가 없다 — 그때의 유량이 최대 유량이다.
if ((dist[sink] as number) === Number.POSITIVE_INFINITY) break;

// ⑤ 경로를 거슬러 올라가며 잔여 용량이 가장 작은 항목을 찾는다.
let push = Number.POSITIVE_INFINITY;
for (let v = sink; v !== source; v = fromV[v] as number) {
  const arcs = graph[fromV[v] as number] as Arc[];
  push = Math.min(push, (arcs[fromE[v] as number] as Arc).cap);
}

// ⑥ 그만큼 정방향 항목에서 덜고 짝이 되는 역방향 항목에 더한다.
for (let v = sink; v !== source; v = fromV[v] as number) {
  const arcs = graph[fromV[v] as number] as Arc[];
  const arc = arcs[fromE[v] as number] as Arc;
  arc.cap -= push;
  ((graph[v] as Arc[])[arc.rev] as Arc).cap += push;
}

flow += push;
cost += push * (dist[sink] as number);
```

라운드 1 에서 이 조각을 실행하면 이렇게 나옵니다. 라운드 1 은 `dist[3]` 이 ∞ 가 아니라서 ④ 의 조건이 거짓이고 아래로
내려갑니다.

<!--proof:walkPush-->

```text
push = min(3, 2, 4) = 2
0→1   cap 3 → 1   1→0 cap 0 → 2
1→2   cap 2 → 0   2→1 cap 0 → 2
2→3   cap 4 → 2   3→2 cap 0 → 2
flow = 2 · cost = 0 + 2 × 3 = 6
```

#### 짚고 가기 — 병목만큼 한 번에 보내지 않고 한 단위씩 보내도 될 것 같다

병목을 한꺼번에 보내면 그중 일부는 다른 경로로 보내는 편이 더 작지 않을까 의심이 듭니다. 한 번에 한 단위씩만 보내고
증가 경로를 매번 다시 찾는 편이 안전해 보여요. 정본의 한 줄을 이렇게 바꿉니다.

```ts
    let push = 1;   // ← 병목을 안 쓰고 한 단위씩만 보내는 판
```

<!--proof:pauseUnit-->

| 입력 | 정본 유량 / 총비용 | 한 단위씩만 보내는 판 | 대조 |
| --- | ---: | ---: | --- |
| 전개 입력 | 6 / 32 | 6 / 32 | 같다 |
| 역방향 항목이 꼭 필요한 넷 | 2 / 14 | 2 / 14 | 같다 |
| 비용이 작은 좁은 경로와 큰 넓은 경로 | 3 / 22 | 3 / 22 | 같다 |
| 직렬 경로 둘 | 5 / 25 | 5 / 25 | 같다 |
| 간선 하나 | 7 / 21 | 7 / 21 | 같다 |

입력 다섯 모두 **답이 안 틀립니다.** 경로 하나 위의 모든 단위가 같은 경로 비용 `d(t)` 를 치르므로, `δ` 단위를 한 번에
보내나 한 단위씩 `δ` 번 보내나 더해지는 값이 `δ × d(t)` 로 같아요. 그래도 병목을 한 번에 보내는 까닭은 **라운드 수**에
있습니다.

| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 4 | 6 | 62 | 92 |

<!--/proof-->

사슬 4×2 는 용량이 1,000 인 사슬 넷이라 정본은 라운드마다 병목을 한 번에 보내는데, 한 단위씩 보내는 판은 같은 증가
경로를 매번 다시 찾습니다. 한 단위씩 보내면 라운드 수가 최대 유량만큼 늘어나고, 최대 유량은 용량을 따라 커져요.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 확인한 것 말고 새로 들어간 것은 **누적 유량 `flow` 와 누적 총비용 `cost` 를 0 으로
두는 두 줄과 끝의 `return`** 뿐이에요.

```ts
export type FlowEdge = [number, number, number, number];

interface Arc {
  to: number;
  cap: number;
  cost: number;
  rev: number;
}

export function minCostMaxFlow(
  n: number,
  edges: FlowEdge[],
  source: number,
  sink: number,
): { flow: number; cost: number } {
  // ① 간선 하나를 두 항목으로 나눠 담는다 — 역방향 항목은 용량 0 에 단위 비용이 반대 부호다.
  const graph: Arc[][] = Array.from({ length: n }, () => []);
  for (const [u, v, cap, cost] of edges) {
    const from = graph[u] as Arc[];
    const to = graph[v] as Arc[];
    from.push({ to: v, cap, cost, rev: to.length });
    to.push({ to: u, cap: 0, cost: -cost, rev: from.length - 1 });
  }

  let flow = 0;
  let cost = 0;

  // ② 라운드 — 싱크에 이르는 경로가 있는 동안 되풀이한다.
  for (;;) {
    const dist = Array.from({ length: n }, () => Number.POSITIVE_INFINITY);
    const waiting = Array.from({ length: n }, () => false);
    const fromV = Array.from({ length: n }, () => -1);
    const fromE = Array.from({ length: n }, () => -1);
    dist[source] = 0;
    const queue: number[] = [source];
    waiting[source] = true;

    // ③ 완화 큐 — 값이 줄어든 정점만 다시 넣는다. 음수 비용 항목도 그대로 다룬다.
    while (queue.length > 0) {
      const u = queue.shift() as number;
      waiting[u] = false;
      const arcs = graph[u] as Arc[];
      for (let i = 0; i < arcs.length; i++) {
        const arc = arcs[i] as Arc;
        const next = (dist[u] as number) + arc.cost;
        if (arc.cap > 0 && next < (dist[arc.to] as number)) {
          dist[arc.to] = next;
          fromV[arc.to] = u;
          fromE[arc.to] = i;
          if (!waiting[arc.to]) {
            queue.push(arc.to);
            waiting[arc.to] = true;
          }
        }
      }
    }

    // ④ 싱크의 값이 그대로면 더 보낼 경로가 없다 — 그때의 유량이 최대 유량이다.
    if ((dist[sink] as number) === Number.POSITIVE_INFINITY) break;

    // ⑤ 경로를 거슬러 올라가며 잔여 용량이 가장 작은 항목을 찾는다.
    let push = Number.POSITIVE_INFINITY;
    for (let v = sink; v !== source; v = fromV[v] as number) {
      const arcs = graph[fromV[v] as number] as Arc[];
      push = Math.min(push, (arcs[fromE[v] as number] as Arc).cap);
    }

    // ⑥ 그만큼 정방향 항목에서 덜고 짝이 되는 역방향 항목에 더한다.
    for (let v = sink; v !== source; v = fromV[v] as number) {
      const arcs = graph[fromV[v] as number] as Arc[];
      const arc = arcs[fromE[v] as number] as Arc;
      arc.cap -= push;
      ((graph[v] as Arc[])[arc.rev] as Arc).cap += push;
    }

    flow += push;
    cost += push * (dist[sink] as number);
  }

  return { flow, cost };
}
```

실행하면 이렇게 나옵니다.

```text

minCostMaxFlow(2, [[0,1,5,2]], 0, 1)                                           →   { flow: 5, cost: 10 }
minCostMaxFlow(3, [[0,1,5,2],[1,2,5,3]], 0, 2)                                 →   { flow: 5, cost: 25 }
minCostMaxFlow(4, [[0,1,1,1],[1,3,1,1],[0,2,2,5],[2,3,2,5]], 0, 3)             →   { flow: 3, cost: 22 }
minCostMaxFlow(3, [[0,1,10,5]], 0, 2)                                          →   { flow: 0, cost: 0 }
```

여기서 가장 중요한 줄은 `cost += push * (dist[sink] as number)` 입니다. `dist[sink]` 는 **한 단위**를 보낼 때의 경로
비용이라 `push` 단위를 보냈으면 그만큼 곱해야 해요. 곱셈을 빼도 병목이 1 인 라운드에서는 맞는 값이 나오므로, 용량이
전부 1 인 입력만 시험하면 그 실수가 안 보입니다.

### 알아 두면 좋은 개념 — 볼록한 비용 곡선

「아이디어 상세」의 3단계에서 유량 값마다의 최소 총비용을 냈고, 이웃한 두 값의 차이 곧 **한 단위 더 보내는 데 드는
최소값이 한 번도 줄지 않았습니다.** 유량 값을 가로, 그 값에서의 최소 총비용을 세로로 놓으면 기울기가 오른쪽으로
갈수록 커지는 곡선이 되고, 이런 곡선을 **볼록하다**고 부릅니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 이것을 쓰는지, 라운드마다의 최소가 왜 전체의 최소가 되는지, 무엇이
매 순간 참으로 남는지, 그리고 비용이 얼마인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **최대 유량이 먼저 정해지고 그다음이 총비용입니다.** 유량을 조금 줄여서 총비용을 크게 줄일 수 있어도 이 절차는
  그쪽을 고르지 않아요. 「최대로 보내는 방법 중에서 가장 적은 비용」이 목표일 때 맞습니다.
- **원래 간선의 단위 비용이 음수가 아닙니다.** 음수 간선이 있으면 처음부터 잔여 그래프에 음수 사이클이 있을 수 있고,
  그러면 라운드 하나가 가장 작은 경로 비용을 정하지 못합니다.
- **용량과 단위 비용이 정수입니다.** 병목이 1 이상이라 라운드가 반드시 끝나고, 총비용에 실수 오차가 생기지 않아요.
- **서로 다른 경로 조합의 수가 감당할 만큼 작습니다.** 라운드 수는 최대 유량을 넘지 않지만, 실제로 라운드 수를 정하는
  것은 경로가 몇 갈래로 갈리는가입니다(「최악을 만드는 입력」).

잘 맞는 모양과 안 맞는 모양을 나란히 놓으면 이렇습니다.

| 모양 | 이 절차 |
| --- | --- |
| 일감 N 개를 사람 N 명에게 하나씩 맡기고 총비용을 최소로 | 맞다 — 용량이 전부 1 인 네트워크로 옮긴다 |
| 물류망에서 최대 물량을 보내되 통행료를 최소로 | 맞다 — 최대 유량이 먼저이고 총비용이 그다음이다 |
| 물량을 줄여도 되니 총비용만 최소로 | 안 맞다 — 목표가 다르다 |
| 통행료가 음수인 구간이 있다 | 이 절차만으로는 안 된다 — 처음부터 음수 사이클이 있을 수 있다 |

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 이 절차 |
| --- | --- | --- |
| 지문 | 간선마다 「최대 몇 개까지」와 「하나당 얼마」가 함께 주어진다 | 용량과 단위 비용 둘이다 |
| 지문 | 「최대한 많이 보내되 그중 가장 적은 비용으로」 | 두 목표의 차례가 이 절차의 전제와 같다 |
| 지문 | 왼쪽 항목을 오른쪽 자리에 짝지으며 짝마다 값이 다르다 | 소스와 싱크를 붙여 용량 1 네트워크로 옮긴다 |
| 지문 | 「같은 답이 여럿인데 그중 가장 좋은 것」 | 최대 유량만으로는 답이 하나로 안 정해진다는 신호다 |
| 제약 | 정점 수백 · 간선 수천 | 라운드마다 최단 경로를 다시 재도 감당된다 |
| 지문 | 「간선마다 비용이 있고 출발지에서 도착지까지 비용이 가장 작은 길 하나」 | 유량이 없는 최단 경로 과제다 |

- **Boost Graph Library 의 `cycle_canceling`** — 같은 라이브러리가 함께 싣는 다른 설계입니다. 문서가 *"The
  cycle_canceling() function calculates the minimum cost flow of a network with given flow."* 와 *"In each round algorithm
  augments the negative cycle (in terms of weight) in the residual graph. If there is no negative cycle in the network,

  ([Boost.Graph `cycle_canceling` 문서](https://www.boost.org/doc/libs/1_86_0/libs/graph/doc/cycle_canceling.html), 조회일 2026-09-07)

  ([`networkx/algorithms/flow/mincost.py`](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/flow/mincost.py), 조회일 2026-09-07)

  ([OR-Tools 「Minimum Cost Flows」](https://developers.google.com/optimization/flow/mincostflow), 조회일 2026-09-07)

Boost 가 두 설계를 나란히 두었다는 것은 **한쪽이 언제나 적지는 않다**는 뜻이고, 다음 절이 그 자리를 다룹니다.

#### 경쟁 설계와의 대조

경쟁 설계는 **음수 사이클 소거**입니다. 단위 비용을 안 보고 너비 우선 탐색으로 최대 유량을 먼저 만든 다음, 잔여
그래프에서 단위 비용 합이 음수인 사이클을 찾아 그 사이클로 병목만큼 옮기는 일을 되풀이해요. 음수 사이클이 하나도
없으면 그 유량은 그 값에서 총비용이 가장 작습니다. 재는 하네스가 실행할 때마다 이 설계의 답을 정본의 답과 맞대므로,
아래 계수는 같은 과제를 푼 두 설계의 값이에요.

| 설계 | 먼저 만드는 것 | 최소 총비용이 되는 때 |
| --- | --- | --- |
| 최소 비용 증가 경로 절차 | 유량 0 에서 라운드마다 경로 비용이 가장 작은 증가 경로로 늘린다 | 라운드가 끝날 때마다 |
| 음수 사이클 소거 | 최대 유량을 먼저 만들고 총비용을 나중에 줄인다 | 마지막 사이클을 없앤 뒤에만 |

**두 설계에 같은 입력을 주고 같은 자로 잽니다.** 자는 둘이에요. **기본 연산**은 잔여 항목 하나를 읽은 것과 경로 ·
사이클을 따라 한 칸을 옮기거나 항목 하나를 고친 것을 각각 하나로 센 값입니다. 이 절차 쪽은 파트 1 의 항목 검사와 같은
값이고, 소거 쪽은 사이클을 찾아 거슬러 오르는 걸음도 함께 셉니다. 배열을 채우는 초기화 쓰기는 세지 않았어요.
**추가 칸**은 라운드가 쓰는 배열 칸에 큐가 가장 길어졌을 때의 길이를 더한 값이에요. 큐 항목 하나를 한 칸으로 셌고,
배열을 라운드마다 다시 잡으므로 라운드 가운데 가장 큰 값을 냅니다. 잔여 그래프는 넣지 않았어요. 두 설계가 잔여 그래프를 같은 인접 목록으로 담고 둘 다 우선순위 큐를 안 씁니다.

**입력은 전개 입력과 다릅니다.** 두 설계가 갈리는 곳이 「경로끼리 얼마나 얽혀 있는가」인데 전개 입력은 정점이 넷뿐이라
얽힘을 조절할 자리가 없어요. 그래서 병렬 경로 16 개(`소스 → A_i → B_i → 싱크`, 용량 64, 단위 비용 0 이상 20 이하, 씨앗
`20250907`)를 세우고 가로지르는 간선 `A_i → B_j`(용량 1)의 **개수 하나만** 바꿉니다. 전개 입력의 값도 함께 냈어요.

| 입력 | 계수 | 이 절차 | 음수 사이클 소거 | 적은 쪽 |
| --- | --- | --- | --- | --- |
| 전개 입력(정점 4) | 기본 연산 | 62 | 113 | 이 절차 |
| 전개 입력(정점 4) | 추가 칸 | 18 | 14 | 소거 |
| 가로 간선 0 | 기본 연산 | 1,648 | 1,936 | 이 절차 |
| 가로 간선 1 | 기본 연산 | 1,973 | 1,974 | 이 절차 |
| 가로 간선 2 | 기본 연산 | 2,015 | 2,012 | **소거** — 여기서 순서가 바뀐다 |
| 가로 간선 22 | 기본 연산 | 6,392 | 3,192 | 소거 |
| 가로 간선 23 | 기본 연산 | 6,721 | 8,258 | **이 절차** — 여기서 다시 바뀐다 |
| 가로 간선 180 | 기본 연산 | 79,865 | 476,896 | 이 절차 |
| 가로 간선 180 | 추가 칸 | 165 | 131 | 소거 |

**순서가 두 번 뒤집힙니다.** 소거가 처음 앞서는 가로 간선 수는 2 이고 마지막으로 앞서는 수는 22 예요. 근거는 두 설계의
라운드 수가 서로 다른 속도로 늘어나는 데 있습니다.

| 가로 간선 | 0 | 1 | 2 | 22 | 23 | 180 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 이 절차의 라운드 | 16 | 18 | 18 | 35 | 36 | 121 |
| 이 절차에서 사이클을 없앤 라운드 | 0 | 0 | 0 | 0 | 0 | 0 |
| 소거 설계의 라운드 | 16 | 16 | 16 | 16 | 17 | 46 |
| 소거 설계에서 사이클을 없앤 라운드 | 0 | 0 | 0 | 0 | 1 | 30 |

가로 간선이 늘면 이 절차는 경로 조합이 늘어 라운드가 함께 늘어납니다. 소거 설계는 가로 간선 22 까지 사이클을 한
번도 안 없애요 — 너비 우선 탐색이 만든 유량이 이미 최소 비용이기 때문입니다. 23 에서 그 라운드가 생기고, 사이클을
찾는 한 번이 잔여 항목 전체를 정점 수만큼 다시 읽게 만듭니다.

**이 절차가 내주는 것이 둘입니다.** 하나는 추가 칸이에요. 잰 두 자리 모두 소거가 적은데, 이 절차는 라운드마다 배열
넷(`dist` · `waiting` · `fromV` · `fromE`)이 필요하고 소거의 두 단계는 각각 셋이면 되기 때문입니다. 다른 하나는 경로가
조금만 얽힌 구간(가로 간선 2 에서 22)의 기본 연산이에요.

| 축 | 최소 비용 증가 경로 절차 | 음수 사이클 소거 |
| --- | --- | --- |
| 추가 칸 | 라운드마다 배열 넷 | 단계마다 배열 셋 |
| 경로가 조금 얽힌 입력의 기본 연산 | 더 많다 | 더 적다 |
| 라운드 하나의 일 | 최단 경로 한 번 | 음수 사이클 찾기 — 잔여 항목 전체를 정점 수만큼 다시 읽는다 |
| 중간에 멈췄을 때의 유량 | 그 유량 값에서 총비용이 가장 작다 | 가장 작다는 보장이 없다 |

**이 절차가 얻는 것은 라운드 하나의 값이 정해져 있다는 것입니다.** 소거의 라운드 하나는 음수 사이클을 찾느라 잔여
항목 전체를 정점 수만큼 다시 읽고, 그런 라운드가 몇 번 나올지는 처음 만든 유량이 최소 비용에서 얼마나 먼가에 달려
있어요. 이 절차의 라운드 하나는 최단 경로 한 번이고, 그 수는 유량 값을 넘지 않습니다. 그리고 어느 라운드에서 멈춰도
그 유량 값의 최소 총비용을 들고 있으므로, 「정확히 `k` 단위」를 묻는 과제로 바로 옮길 수 있어요. **경로 조합이
단순하고 메모리가 빠듯하면 소거이고, 경로가 많이 얽히면 이 절차입니다.**

### 수식 정의와 유도

정점 $v$ 에 붙는 수 $\pi(v)$ 를 **잠재값**(potential)이라 부르고, 그것으로 항목의 단위 비용을 다시 매긴 값을 $a'$ 라
적습니다. $a(u,v)$ 는 기호표의 뜻 그대로이고, 역방향 항목이면 짝의 부호를 바꾼 값이에요.

$$
a'(u, v) = a(u, v) + \pi(u) - \pi(v)
$$

| 기호 | 정의 |
| --- | --- |
| $\pi(v)$ | 정점 $v$ 의 잠재값. 이 절에서는 직전 라운드의 $d(v)$ 로 둔다 |
| $a'(u,v)$ | 잠재값으로 다시 매긴 항목 $u \to v$ 의 단위 비용 |
| $d_k(v)$ | 라운드 $k$ 의 $d(v)$ |

정의를 작은 값에 넣어 검산해 봅시다. 라운드 1 을 보낸 직후의 잔여 그래프에서, 잔여가 양수인 항목마다 $\pi = d_1$ 로
다시 매긴 값을 계산했어요.

<!--proof:mathReweight-->

| 항목 | a | π(u) | π(v) | a + π(u) − π(v) |
| --- | ---: | ---: | ---: | ---: |
| 0→1 | 1 | 0 | 1 | 0 |
| 0→2 | 4 | 0 | 2 | 2 |
| 1→3 | 6 | 1 | 3 | 4 |
| 2→3 | 1 | 2 | 3 | 0 |
| 1→0 | -1 | 1 | 0 | 0 |
| 2→1 | -1 | 2 | 1 | 0 |
| 3→2 | -1 | 3 | 2 | 0 |

잔여가 양수인 항목 7 개 중 다시 매긴 값이 음수인 것이 0 개이고, 정확히 0 인 것이 5 개입니다. 잠재값 π 는 라운드 1 의 dist [0, 1, 2, 3] 을 그대로 쓴 것이고, 이번 라운드에 새로 열린 역방향 항목 1→0 · 2→1 · 3→2 는 모두 0 입니다.

<!--/proof-->

이제 유도합니다. 첫째로 **경로 하나의 값은 양 끝의 잠재값만큼만 옮겨집니다.** 경로 $P = u_0 \to u_1 \to \cdots \to u_k$ 의
다시 매긴 값을 더하면 가운데 항이 한 번은 더하는 쪽, 한 번은 빼는 쪽으로 나와 지워져요. 그래서 $s$ 에서 $t$ 로 가는
경로는 어느 것이든 $\pi(s) - \pi(t)$ 만큼 옮겨지고, 다시 매긴 그래프에서 가장 작은 경로가 원래 그래프에서도 가장
작습니다. 사이클은 $u_0 = u_k$ 라 두 항이 지워지므로 사이클의 합은 다시 매겨도 그대로예요.

$$
\sum_{i=0}^{k-1} a'(u_i, u_{i+1}) = \sum_{i=0}^{k-1} a(u_i, u_{i+1}) + \pi(u_0) - \pi(u_k)
$$

| 항목 | 붙는 잠재값 항 |
| --- | --- |
| $u_0 \to u_1$ | $+\pi(u_0) - \pi(u_1)$ |
| $u_1 \to u_2$ | $+\pi(u_1) - \pi(u_2)$ |
| $u_{k-1} \to u_k$ | $+\pi(u_{k-1}) - \pi(u_k)$ |

둘째로 **$\pi = d$ 로 두면 잔여가 양수인 항목의 다시 매긴 값이 0 이상입니다.**

$$
a(u, v) + d(u) - d(v) \ge 0 \iff d(v) \le d(u) + a(u, v)
$$

오른쪽 부등식이 참인 까닭을 한 줄씩 적으면 이렇습니다.

| 걸음 | 내용 |
| --- | --- |
| 경로 하나 | $u$ 까지 가장 작게 간 뒤 항목 $(u, v)$ 를 지나는 경로의 비용이 $d(u) + a(u, v)$ 다 |
| 가장 작은 값 | $d(v)$ 는 $v$ 까지 가는 모든 경로 비용의 최솟값이라 어떤 경로 하나의 비용보다 크지 않다 |
| 그래서 | $d(v) \le d(u) + a(u, v)$ 이고, 잔여가 양수인 모든 항목에서 그렇다 |

셋째로 **보낸 뒤 새로 열리는 역방향 항목도 0 입니다.** 이번 라운드의 증가 경로 위 항목 $(u, v)$ 로 보내면 짝 $(v, u)$
에 잔여가 생겨요.

| 걸음 | 식 |
| --- | --- |
| $(u, v)$ 는 가장 작은 경로 위의 항목이다 | $d(v) = d(u) + a(u, v)$ — 등호가 성립한다 |
| 짝의 단위 비용 | $a(v, u) = -a(u, v)$ |
| 짝을 다시 매긴 값 | $a(v, u) + d(v) - d(u) = -a(u, v) + \bigl(d(u) + a(u, v)\bigr) - d(u) = 0$ |

다시 매긴 값이 모든 항목에서 0 이상이면 어떤 사이클의 합도 0 보다 작을 수 없고, 사이클의 합은 다시 매겨도 그대로이므로
**원래 단위 비용으로도 음수 사이클이 없습니다.** 무작위 네트워크에서 이 셋을 라운드마다 확인했어요.

<!--proof:mathNonneg-->

| 센 것 | 값 |
| --- | ---: |
| 무작위 네트워크 | 2,000 |
| 라운드 합 | 1,754 |
| 보낸 뒤 다시 매긴 잔여 항목 | 14,394 |
| 그중 다시 매긴 값이 음수인 것 | 0 |
| 새로 열린 역방향 항목 | 3,690 |
| 그중 다시 매긴 값이 정확히 0 인 것 | 3,690 |
| 잔여 그래프에 음수 사이클이 있던 라운드 | 0 |
| 경로 비용이 앞 라운드보다 줄어든 자리 | 0 |

정점 4 개에서 11 개 · 간선 3 개에서 23 개인 네트워크 2,000 개를 만들어 라운드마다 쟀습니다. 다시 매긴 값이 음수인 항목이 0 개, 음수 사이클이 있던 라운드가 0 번이고, 새로 열린 역방향 항목 3,690 개 중 3,690 개가 다시 매긴 값 0 입니다.

<!--/proof-->

마지막으로 **경로 비용이 라운드마다 줄지 않습니다.** 라운드 $k+1$ 에서 다시 매긴 가장 작은 경로 비용 $d'(t)$ 는 모든 항목이
0 이상이라 0 이상이고, 첫째 식으로 원래 값으로 되돌리면 이렇습니다.

$$
d_{k+1}(t) = d'(t) - \pi(s) + \pi(t) = d'(t) - d_k(s) + d_k(t) = d'(t) + d_k(t) \ge d_k(t)
$$

$d_k(s) = 0$ 이고 $d'(t) \ge 0$ 이라 마지막 부등식이 성립합니다. 파트 1 의 「볼록한 비용 곡선」이 이 부등식이에요. 잠재값을
배열 `pi` 에 들고 있다면 다시 매긴 단위 비용은 이 한 줄이고, 이 값이 0 이상이면 다익스트라의 「꺼낸 값이 확정」이 다시
성립합니다. 정본은 이 배열을 쓰지 않아요.

```ts
const reduced = arc.cost + pi[u] - pi[arc.to];
```

규모의 상한을 넣어 총비용이 정수로 정확히 다뤄지는지 봅시다.

<!--proof:mathScale-->

| 식 | V = 200 · E = 2,000 · c, a ≤ 10,000 에서 |
| --- | ---: |
| 최대 유량의 상한 E · c_max | 20,000,000 |
| 경로 비용의 상한 (V − 1) · a_max | 1,990,000 |
| 둘의 곱 | 39,800,000,000,000 |
| 간선마다 용량 × 단위 비용을 더한 상한 E · c_max · a_max | 200,000,000,000 |
| 배정밀도 수가 정수를 정확히 담는 한계 2^53 − 1 | 9,007,199,254,740,991 |

총비용은 두 상한 모두 9,007,199,254,740,991 안쪽입니다. 헐거운 쪽으로 잡아도 226.31 배 여유가 있고, 조인 쪽으로 잡으면 45,035 배 여유입니다.

<!--/proof-->

헐거운 상한은 「최대 유량 × 경로 비용의 상한」이고 조인 상한은 「간선마다 용량 × 단위 비용을 다 더한 값」입니다. 어느
쪽으로 잡아도 총비용을 배정밀도 수의 정수로 다뤄 값이 정확해요.

### 불변식 — 라운드가 끝날 때마다 누적 총비용은 그 유량 값을 만드는 배정 중 가장 작은 총비용이다

파트 1 에서 코드가 동작하는 것을 열 걸음으로 확인했습니다. 그런데 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는
뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 아래 문장으로 세웁니다.

> 라운드 하나가 끝난 직후마다, 변수 `cost` 는 그 시점의 유량 값 `flow` 를 만드는 모든 배정 가운데 가장 작은 총비용과
> 같습니다.

| 걸음 | 참인 것 | 근거 |
| --- | --- | --- |
| 시작 | 유량 0 · 총비용 0 이 최소다 | 유량 0 을 만드는 배정은 모든 간선에 0 을 싣는 하나뿐이다 |
| 이어감 | 지금 유량이 최소이면 경로 비용이 가장 작은 증가 경로로 보낸 뒤에도 최소다 | 「수식 정의와 유도」 — 보낸 뒤에도 잔여 그래프에 음수 사이클이 없다 |

라운드 도중이 아니라 **끝난 직후**이고, 마지막 라운드에서만이 아니라 **라운드마다** 성립합니다. 유지되는 까닭은 위 두
걸음의 짝이에요. 상태를 바꾸는 갈래는 둘입니다. 잔여 그래프를 만드는 갈래는 유량과 총비용을 0 으로 두고, 보내는 갈래는 `flow` 에 병목을,
`cost` 에 병목 × 경로 비용을 더해요. 유지되는 것을 라운드마다 값으로 봅시다. 전수 조사로 유량 값마다의 최소 총비용을 미리
구해 두고, 라운드가 끝날 때마다 누적 총비용을 그 값과 맞댔습니다.

| 입력 | 라운드 | 최대 유량 | 총비용 | 최소가 아니었던 라운드 | 음수 사이클이 있던 라운드 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 4 | 6 | 32 | 0 | 0 |
| 역방향 항목이 꼭 필요한 넷 | 2 | 2 | 14 | 0 | 0 |
| 비용이 작은 좁은 경로와 큰 넓은 경로 | 2 | 3 | 22 | 0 | 0 |
| 직렬 경로 둘 | 1 | 5 | 25 | 0 | 0 |
| 간선 하나 | 1 | 7 | 21 | 0 | 0 |

입력 5 개를 라운드마다 전수 조사와 맞대 보니 최소가 아니었던 라운드가 0 번이고, 같은 자리에서 잔여 그래프에 음수 사이클이 있던 라운드도 0 번입니다.

<!--/proof-->

두 열이 함께 0 인 데는 까닭이 있습니다. 음수 사이클이 남아 있으면 그 사이클을 따라 한 단위를 옮길 수 있고, 사이클이라
정점마다 들어온 양과 나간 양이 같아 유량 값은 그대로인 채 총비용만 사이클의 합만큼 줄어요. 그러니 음수 사이클이 있으면
최소가 아닙니다. 거꾸로 「최소가 아니면 음수 사이클이 있다」는 최소 비용 유량의 표준 정리이고, 이 글은 그 방향을
증명하지 않고 위 표로 값만 확인했습니다.

**작은 입력과 경계값도 이 자리에서 함께 봅니다.** 간선이 하나도 없는 입력부터 용량과 단위 비용이 규모의 상한인 입력까지
여덟입니다.

경로가 없는 입력은 첫 라운드의 SPFA 가 싱크의 값을 못 고쳐 `{ flow: 0, cost: 0 }` 으로 끝납니다. 자기 자신으로 가는 간선은
`dist[u] + a` 가 `dist[u]` 보다 작을 수 없어(`a ≥ 0`) 완화 조건을 한 번도 통과하지 않아요. 같은 두 정점 사이에 간선이 둘인
입력은 직전 항목의 자리를 따로 적어 두었기 때문에 단위 비용이 작은 간선부터 채워집니다.

**이제 깨뜨려 봅시다.** 불변식이 기댄 자리는 「`cost` 가 그 유량 값의 최소 총비용과 같다」이고, 그 등식을 지키는 줄은
누적 총비용을 고치는 한 줄입니다. 거기서 병목을 곱하는 것을 뺍니다.

```ts
    cost += (dist[sink] as number);   // ← 병목을 안 곱하는 판
```

네 입력 모두 간선 용량이 1 이라 병목이 늘 1 이고, 라운드 수가 최대 유량과 같은 입력이 4 개 중 4 개입니다.

<!--/proof-->

한 변을 두 배로 하면 라운드 수도 두 배 언저리가 되고, 라운드마다 읽는 항목도 늘어 항목 검사는 네 배 언저리가 됩니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 한쪽을 다른 쪽에 짝지으면 안 돼요.

| 케이스 | 라운드 수 | 경계의 종류 | 근거 |
| --- | --- | --- | --- |
| 용량이 정수다 | $O(F)$ | 상한 | 라운드마다 유량이 1 이상 늘어 $F$ 를 넘지 못한다 |
| 용량이 전부 1 이다 | $\Theta(F)$ | 타이트 | 병목이 늘 1 이라 라운드 수가 최대 유량과 같다 — 배정 네트워크 넷에서 같았다 |
| 경로끼리 간선을 나눠 쓰지 않는다 | 경로 수 | 타이트 | 경로 하나가 라운드 하나로 끝난다 — 병렬 16 · 가로 0 에서 라운드 16 |
| 라운드 하나 | $O(V \cdot E)$ | 상한 | SPFA 가 정점 하나를 많아야 $V$ 번 꺼내고 그때마다 그 정점의 항목을 읽는다 |

**총식을 한 번 정확히 적습니다.** 잔여 그래프를 만드는 $E$ 에, 라운드 $R + 1$ 번(마지막 한 번은 경로를 못 찾는 라운드)마다
배열 넷과 SPFA 와 두 번의 거슬러 오르기를 더합니다.

$$
T = \underbrace{\Theta(E)}_{\text{잔여 그래프}} + \sum_{r=1}^{R+1} \bigl[\Theta(V) + O(V \cdot E) + O(V)\bigr] = O(E + R \cdot V \cdot E), \qquad R \le F
$$

추가 칸은 잔여 그래프 $2E$ 에 라운드가 쓰는 배열 넷 $4V$ 와 큐 $V$ 를 합친 $\Theta(V + E)$ 예요.

| 센 것 | 안 센 것 |
| --- | --- |
| 잔여 그래프 만들기 · SPFA 의 항목 읽기 · 경로 거슬러 올라가기 · 잔여 고치기 | 간선 목록을 읽어 들이는 일 — 어느 설계로 짜든 같은 양이다 |
| 라운드마다 배열 넷을 새로 만드는 일 | 누적 유량과 총비용을 더하는 일 — 라운드마다 곱셈과 덧셈 한 번씩이라 라운드 수에 묻힌다 |

**위 표는 최악 보장이고 기댓값이 아닙니다.** 절차 어디에도 난수가 없어서 입력이 같으면 연산 수가 언제나 똑같아요. 평균을
적으려면 무엇에 대한 평균인지(그래프의 모양 · 용량의 분포 · 단위 비용의 분포)를 먼저 정해야 하는데, 이 과제에는 표준으로
삼을 입력 분포가 없습니다. 그래서 평균 칸을 두지 않아요.

#### 최악을 만드는 입력

「용량이 크면 느리다」는 말은 물려받은 것이라 값으로 확인하기 전에는 쓰지 않습니다. 모양이 다른 여섯을 놓고 무엇이 가장
커지는지 재 봅시다.

<!--proof:worstShape-->

| 입력 | 정점 | 간선 | 최대 유량 | 라운드 | 항목 검사 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 병렬 16 · 가로 0 | 34 | 48 | 1,024 | 16 | 1,648 |
| 병렬 16 · 가로 64 | 34 | 112 | 1,024 | 59 | 18,396 |
| 병렬 16 · 가로 180 | 34 | 228 | 1,024 | 121 | 79,865 |
| 배정 32×32 | 66 | 184 | 29 | 29 | 15,227 |
| 사슬 8×4 · 용량 1 | 34 | 40 | 8 | 8 | 728 |
| 사슬 8×4 · 용량 10,000 | 34 | 40 | 80,000 | 8 | 728 |

항목 검사가 가장 많은 입력은 병렬 16 · 가로 180 이고 79,865 번이며, 라운드가 가장 많은 입력도 병렬 16 · 가로 180 이고 121 번입니다.

<!--/proof-->

**용량을 만 배로 키워도 라운드가 안 늘어납니다.** 사슬 8×4 는 용량이 1 일 때와 10,000 일 때 라운드와 항목 검사가 같아요.
병목이 용량과 함께 커지기 때문이고, 그래서 최악을 만드는 것은 용량이 아니라 **경로 조합의 수**입니다. 최대 유량을 1,024 로
고정한 채 가로지르는 간선만 늘린 세 줄에서 라운드가 함께 늘어난 것이 그 자리예요. 규모의 상한을 꽉 채운 입력에서도 재 봅니다.

<!--proof:worstLimit-->

| 입력 | 정점 | 간선 | 최대 유량 | 라운드 | 항목 검사 | 라운드당 항목 검사 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 병렬 16 | 34 | 288 | 160,000 | 144 | 134,779 | 936.0 |
| 병렬 32 | 66 | 1,088 | 320,000 | 517 | 1,950,410 | 3772.6 |
| 병렬 64 | 130 | 2,000 | 640,000 | 951 | 6,572,710 | 6911.4 |
| 병렬 80 | 162 | 2,000 | 800,000 | 978 | 6,890,719 | 7045.7 |
| 병렬 99 | 200 | 2,000 | 990,000 | 972 | 6,673,668 | 6865.9 |

라운드가 가장 많은 입력은 병렬 80 이고 978 번이라, 그 입력의 최대 유량 800,000 의 0.12 % 입니다. 항목 검사가 가장 많은 입력은 병렬 80 이고 6,890,719 번입니다.

<!--/proof-->

규모의 상한을 채워도 라운드 수가 최대 유량의 1 % 에도 못 미칩니다. $R \le F$ 는 정수 용량에서 늘 참인 헐거운 상한이고,
라운드 수가 실제로 따라가는 것은 유량 값이 아니라 경로가 몇 갈래로 갈리는가예요. 라운드 수를 `F` 에 가깝게 끌어올리는
입력(용량이 큰 간선과 용량 1 인 가로 간선을 섞어 병목이 매번 1 이 되게 하는 입력)은 이 글이 구성하지 못했습니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 간선 하나를 단위 비용이 `a` 인 정방향 항목과 `−a` 인 역방향 항목으로
나눠 담고, 라운드마다 SPFA 로 경로 비용이 가장 작은 증가 경로를 찾아 병목만큼 보냅니다. 답이 맞는 근거는 「라운드가
끝날 때마다 누적 총비용이 그 유량 값의 최소 총비용이다」이고, 비용은 $O(E + R \cdot V \cdot E)$ 예요.

| 차례 | 하는 일 | 규모 |
| ---: | --- | --- |
| 1 | 잔여 그래프를 만든다 | 항목 `2E` 개 |
| 2 | SPFA 로 경로 비용이 가장 작은 증가 경로를 찾는다 | 라운드마다 `O(V · E)` |
| 3 | 싱크의 값이 ∞ 이면 끝낸다 | 라운드 `R + 1` 번 |
| 4 | 병목만큼 보내고 총비용에 병목 × 경로 비용을 더한다 | 라운드마다 `O(V)` |

먼저 답이 붙는 문제 하나입니다. T7 이 끝난 시점에 소스에서 나가는 정방향 항목 가운데 잔여가 남은 것은 `0 → 2` 하나이고
그 단위 비용은 4 예요. 그런데 T8 이 고른 증가 경로의 경로 비용은 왜 그보다 훨씬 클까요?

### 최소 비용 최대 유량 (Min-Cost Max-Flow)

풀 파일: [`minCostMaxFlow.ts`](./minCostMaxFlow.ts) · 테스트: [`minCostMaxFlow.test.ts`](./minCostMaxFlow.test.ts) · 실행: `bun test src/algorithms/graph-flow/minCostMaxFlow/minCostMaxFlow.test.ts`

#### 한 줄 요약

> 단위 유량당 비용이 있는 유량 네트워크의 정점 수 `n`, 간선 목록 `edges`, 소스 `source`, 싱크 `sink` 를 받아, **최대 유량을 흘리는 모든 방법 중 총 비용이 최소인 값**을 `{ flow, cost }` 형태로 반환한다.

#### 스토리

물류 회사가 공장에서 항구까지 제품을 운송한다. 도로마다 한 번에 실을 수 있는 최대 물량(용량)이 다르고, 물량 한 단위를 운반할 때마다 도로 통행료(단위 비용)도 다르다. 회사는 항구로 보낼 수 있는 **최대한 많은 물량**을 보내야 하지만, 그 물량을 보내는 방법이 여러 가지라면 **운송 비용이 가장 적게 드는 경로 조합**을 선택하고 싶다.

운송 계획 팀이 도로망 정보를 넘겨주면, 최대로 보낼 수 있는 물량과 그때의 최소 비용을 함께 알려주는 함수가 필요하다. 최대 물량을 포기하면서 비용을 줄이는 것은 허용되지 않는다.

#### 함수 인터페이스

```ts
export function minCostMaxFlow(
  n: number,
  edges: [number, number, number, number][],
  source: number,
  sink: number,
): { flow: number; cost: number };
```

- `n` — 정점의 개수. 정점 번호는 $0 \ldots n-1$.
- `edges` — 방향 간선 목록. 각 원소 `[u, v, c, a]` 는 정점 `u` 에서 `v` 로 향하는 용량 `c`, 단위 비용 `a` 의 간선이다.
- `source` — 소스 정점 번호.
- `sink` — 싱크 정점 번호.
- 반환 — `{ flow, cost }`. `flow` 는 소스에서 싱크로의 최대 유량, `cost` 는 그때의 최소 총 비용.

#### 제약 조건

- $2 \leq n \leq 200$
- $0 \leq E \leq 2 \cdot 10^3$ (여기서 $E$ 는 간선의 수)
- $0 \leq c(u, v) \leq 10^4$ (용량)
- $0 \leq a(u, v) \leq 10^4$ (단위 비용)
- $0 \leq \text{source},\, \text{sink} < n,\;\; \text{source} \neq \text{sink}$
- 정점 번호는 $0 \ldots n-1$.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

비용이 있는 유량 네트워크 $G = (V, E, c, a)$ 에서 $c(u, v)$ 는 용량, $a(u, v)$ 는 단위 유량당 비용이다.

유량 함수 $f$ 의 총 비용:

$$\text{cost}(f) = \sum_{(u, v) \in E} a(u, v) \cdot f(u, v)$$

목적: 최대 유량 $|f^*|$ 을 달성하는 유량 함수들 중 총 비용이 가장 작은 것을 구한다.

$$\text{minCostMaxFlow}(G, s, t) = \min_{\substack{f \text{ feasible}\\ |f| = |f^*|}} \text{cost}(f)$$

- 소스에서 싱크로 가는 경로가 없으면 `{ flow: 0, cost: 0 }` 을 반환한다.
- 용량 `0` 인 간선은 사용할 수 없다.
- 비용 `0` 인 간선은 용량만큼 비용 없이 흘릴 수 있다.
- 최대 유량이 동일하다면, 그 중에서 비용이 더 낮은 경로 조합을 선택한다.

#### 예시

```ts
minCostMaxFlow(2, [[0, 1, 5, 2]], 0, 1);
// { flow: 5, cost: 10 } — 유량 5를 단위 비용 2짜리 직통 경로로 모두 전달, 총 비용 5×2=10

minCostMaxFlow(3, [[0, 1, 5, 2], [1, 2, 5, 3]], 0, 2);
// { flow: 5, cost: 25 } — 직렬 경로, 단위당 비용 2+3=5, 총 비용 5×5=25

minCostMaxFlow(
  4,
  [[0, 1, 1, 1], [1, 3, 1, 1], [0, 2, 2, 5], [2, 3, 2, 5]],
  0, 3,
);
// { flow: 3, cost: 22 } — 최대 유량 3; 싼 경로(비용 2)로 1단위, 비싼 경로(비용 10)로 2단위

minCostMaxFlow(3, [[0, 1, 10, 5]], 0, 2);
// { flow: 0, cost: 0 } — 싱크 2로 향하는 경로 없음

minCostMaxFlow(2, [[0, 1, 1, 0]], 0, 1);
// { flow: 1, cost: 0 } — 단위 비용 0, 유량 1, 비용 없음

minCostMaxFlow(
  4,
  [[0, 1, 2, 1], [1, 3, 2, 1], [0, 2, 3, 10], [2, 3, 3, 10]],
  0, 3,
);
// { flow: 5, cost: 64 } — 싼 경로(단위 비용 2)로 2단위, 비싼 경로(단위 비용 20)로 3단위
```
