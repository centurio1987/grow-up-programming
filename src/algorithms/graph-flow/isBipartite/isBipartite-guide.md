# 이분 그래프 판정 — 한 정점의 쪽을 정하면 연결 성분 전체의 쪽이 따라 정해지는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 쪽 나눔을 전부
시험하는 방법에서 출발해, 정점마다 쪽 하나를 적어 나가는 방법까지 갑니다. 그 방법을 준비되는 차례대로
값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**무향 그래프**는 정점과 간선으로 적은 자료입니다. 간선 `[u, v]` 는 정점 `u` 와 `v` 가 직접 이어져 있다는
뜻이고, 방향이 없어서 `[u, v]` 와 `[v, u]` 는 같은 간선이에요. 이 글이 답하는 물음은 하나입니다. **정점
전체를 두 무리로 나누되, 모든 간선이 서로 다른 무리의 두 정점을 잇게 할 수 있는가.** 그렇게 나눌 수 있는
그래프를 **이분 그래프**라고 부르고, 두 무리 하나하나를 이 글에서는 **쪽**이라고 부릅니다. 쪽은 0 과 1
두 값으로 적어요.

정점 일곱 · 간선 일곱인 그래프에 이 글의 절차가 적은 쪽을 그려 보면 이렇습니다. 정점 안의 「쪽 0」·「쪽 1」
이 그 정점에 적힌 쪽이고, 점선 테 하나가 **연결 성분**(간선을 따라 서로 오갈 수 있는 정점의 무리) 하나예요.

<!--fig:concept-sides-->
![전개 입력 — 정점 안은 절차가 멈춘 시점에 적힌 쪽](./figs/concept-sides.svg)

왼쪽 네 정점은 쪽 0 과 쪽 1 이 번갈아 적혀서 간선 넷이 모두 두 쪽을 가릅니다. 오른쪽 세 정점은 어떻게
적어도 둘이 같은 쪽에 들어가고, 그 둘 사이에 간선이 있어요. 간선마다 두 끝의 쪽을 적으면 이렇습니다.

<!--proof:concept-edges-->

| 간선 | 연결 성분 | 두 끝의 쪽 | 두 끝의 비교 |
| --- | --- | --- | --- |
| [0,1] | 시작 정점 0 의 성분 | 0 · 1 | 다르다 |
| [1,2] | 시작 정점 0 의 성분 | 1 · 0 | 다르다 |
| [2,3] | 시작 정점 0 의 성분 | 0 · 1 | 다르다 |
| [3,0] | 시작 정점 0 의 성분 | 1 · 0 | 다르다 |
| [4,5] | 시작 정점 4 의 성분 | 0 · 1 | 다르다 |
| [5,6] | 시작 정점 4 의 성분 | 1 · 1 | 같다 |
| [6,4] | 시작 정점 4 의 성분 | 1 · 0 | 다르다 |

절차가 멈춘 시점의 쪽 배열은 0:0 1:1 2:0 3:1 4:0 5:1 6:1 입니다. 간선 7 개 가운데 두 끝의 쪽이 같은 간선은 [5,6] 한 개이고, 정본의 답은 false 입니다.

<!--/proof-->

간선 하나라도 두 끝의 쪽이 같으면 그 나눔은 실패입니다. 이 절차가 쪽을 적는 규칙은 하나예요. **아직 쪽이
없는 정점 하나에 쪽 0 을 적고, 쪽이 적힌 정점의 이웃에는 반대쪽을 적습니다.** 이웃에 적을 쪽이 고를 것
없이 정해지므로, 한 정점의 쪽을 정하면 그 연결 성분 전체의 쪽이 따라 정해져요. 이미 쪽이 적힌 이웃을
만나면 그 쪽이 자기와 같은지만 봅니다.

| 이웃에 적힌 쪽 | 뜻 | 하는 일 |
| --- | --- | --- |
| 자기와 같다 | 이 간선의 두 끝이 한 쪽에 들어간다 | `false` 를 돌려준다 |
| 자기와 다르다 | 이 간선은 두 쪽을 가른다 | 넘어간다 |
| 아직 없다 | 이 이웃의 쪽이 여기서 정해진다 | 반대쪽을 적는다 |

정점마다 적힌 쪽을 담는 배열을 이 글에서는 **쪽 배열**이라고 부르고, 코드에서는 `side` 입니다. `side[v]` 는
정점 `v` 에 적힌 쪽이고, 아직 적지 않았으면 `-1` 이에요. 쪽 배열 하나로 판정하는 이 절차를 **쪽 배열 탐색**
이라고 부릅니다. 할 일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선 하나를 양 끝 정점의 목록에 한 번씩 넣는다 | 간선마다 두 번 |
| 시작 정점 찾기 | 정점마다 쪽 배열을 한 번 읽는다 | 정점마다 한 번 |
| 쪽 적기 | 정점마다 쪽을 한 번 적고 스택에 한 번 넣는다 | 정점마다 한 번 |
| 이웃 확인 | 꺼낸 정점의 이웃마다 쪽을 한 번 비교한다 | 간선마다 두 번 이하 |
| 모두 | | `O(V + E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **이웃 목록.** 정점마다 이어진 정점의 목록을 하나씩 두는 그래프 표현입니다. 무향 간선 `[u, v]` 는 목록
  둘에 한 번씩, 모두 두 번 들어가요. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를 보세요.
- **연결 성분과 시작 정점 건너뛰기.** 정점 번호 순서로 시작 정점을 보면서, 이미 앞 탐색이 표시해 둔 정점은
  건너뛰는 바깥 반복입니다. 이 글은 그 표시 자리에 쪽을 적어요. 모르면 [`connectedComponents` 가이드](../../graph/connectedComponents/connectedComponents-guide.md)를 먼저 보세요.
- **너비 우선 탐색.** 한 정점에서 시작해 처음 만난 이웃만 표시하고 목록에 넣는 일을 목록이 빌 때까지
  되풀이하는 순회입니다. 이 글은 목록을 큐 대신 스택으로 드는데, 그래도 되는지는 전개 중에 값으로 확인해요.
  모르면 [`bfsShortestPath` 가이드](../../graph/bfsShortestPath/bfsShortestPath-guide.md)를 보세요.
- **스택이 나중에 넣은 것을 먼저 꺼내는 자료구조**라는 것. 넣기와 꺼내기가 각각 `O(1)` 입니다. 모르면
  [`stack` 가이드](../../../data-structures/linear/stack/stack-guide.mdx)를 보세요.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점의 쪽이 무엇인가」를 배열 한 칸 읽기로 답합니다.

둘째가 흐릿하면 뒤가 어긋납니다. 쪽은 연결 성분마다 따로 정하고, 연결 성분 하나라도 두 쪽으로 못 나뉘면
그래프 전체의 답이 `false` 이기 때문이에요.

| 비슷한 과제 | 묻는 것 | 이 글에서 |
| --- | --- | --- |
| 정점을 두 쪽으로 나눠 모든 간선이 두 쪽을 가르게 할 수 있는가 | 참 · 거짓 | 다룬다 |
| 서로 오갈 수 있는 정점의 무리를 찾는다 | 무리의 목록 | 다루지 않는다 — [`connectedComponents`](../../graph/connectedComponents/connectedComponents-guide.md) |
| 두 쪽 사이에서 짝을 가장 많이 짓는다 | 짝의 수 | 다루지 않는다 — [`maxBipartiteMatching`](../maxBipartiteMatching/maxBipartiteMatching-guide.md) |

### 아이디어를 떠올리는 과정 — 쪽 나눔 전부 시험에서 쪽 배열 탐색까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아서
이분 그래프인지를 돌려줍니다.

```ts
function isBipartite(n: number, edges: [number, number][]): boolean;
```

- 입력: 정점 수 `n`, 무향 간선 목록 `edges`. 정점 번호는 0 부터 `n − 1` 까지예요. 간선이 하나도 없을 수
  있고, 자기 자신을 잇는 간선 `[v, v]` 와 같은 쌍을 두 번 잇는 간선이 들어올 수 있습니다.
- 출력: 정점 전체를 두 쪽으로 나눠 모든 간선이 두 쪽을 가르게 할 수 있으면 `true`, 없으면 `false`.
  연결 성분 하나라도 못 나뉘면 `false` 입니다.
- 규모: 정점 100,000 개 이하, 간선 200,000 개 이하. 비용은 흔한 채점 환경의 예산인 1 초 · 256 MB 에 대어
  잽니다.

이 글에서 쓰는 기호는 일곱 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점 수. 코드의 `n` 입니다 | `1 ≤ V ≤ 100,000` |
| `E` | 간선 수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ 200,000` |
| `k` | 연결 성분의 수 | `1 ≤ k ≤ V` |
| `u` · `v` | 정점 번호. 이웃을 보는 자리에서는 `u` 가 꺼낸 정점, `v` 가 그 이웃입니다 | `0` 부터 `V − 1` |
| `nbr[u]` | 정점 `u` 의 이웃 번호를 담은 목록 | 길이를 모두 더하면 `2E` |
| `side[v]` | 쪽 배열에서 정점 `v` 의 칸 | `0` 또는 `1`, 아직 없으면 `-1` |
| `stack` | 쪽은 적혔지만 아직 꺼내지 않은 정점들 | 뒤에 넣고 뒤에서 꺼낸다 |

가장 먼저 떠오르는 방법은 정의를 그대로 옮기는 것입니다. 정점마다 쪽 0 과 쪽 1 중 하나를 고르는 나눔을
전부 만들어 보고, 나눔마다 간선을 차례로 확인해 두 끝의 쪽이 같은 것이 나오면 그 나눔을 버려요. 하나라도
끝까지 살아남으면 `true` 입니다.

```ts
// 쪽 나눔 하나를 비트 하나씩으로 적는다. mask 의 v 번째 비트가 정점 v 의 쪽이다.
for (let mask = 0; mask < 2 ** n; mask++) {
  let ok = true;
  for (const [u, v] of edges) {
    if (((mask >> u) & 1) === ((mask >> v) & 1)) { ok = false; break; }
  }
  if (ok) return true;
}
return false;
```

이 방법은 답이 맞습니다. 비용은 **확인한 간선 수**로 셉니다. 나눔이 정점 하나마다 두 배로 늘어나므로, 한
줄로 이은 그래프에서 정점을 늘려 가며 세어 봅시다.

<!--proof:naive-scale-->

| 입력 | 정점 V | 간선 E | 쪽 나눔 후보 | 확인한 간선 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 7 | 7 | 128 | 268 |
| 한 줄로 이은 10 정점 | 10 | 9 | 1,024 | 2,044 |
| 한 줄로 이은 15 정점 | 15 | 14 | 32,768 | 65,532 |
| 한 줄로 이은 20 정점 | 20 | 19 | 1,048,576 | 2,097,148 |
| 한 줄로 이은 22 정점 | 22 | 21 | 4,194,304 | 8,388,604 |
| 한 줄로 이은 100,000 정점 | 100,000 | 99,999 | 30,103 자리 수 | (실행하지 않음) |

실행한 다섯 줄에서 확인한 간선 수는 후보 수의 2.0 배에서 2.1 배 사이입니다. 마지막 줄의 후보 수 2^100,000 은 30,103 자리 수라 실행하지 않았습니다.

<!--/proof-->

정점 22 개에서 이미 간선 확인이 800 만 번을 넘고, 규모의 상한인 정점 10 만 개에서는 후보 수만 3 만 자리가
넘는 수입니다. 1 초 안에 끝나는 규모가 아니에요. 느린 까닭은 **후보마다 쪽을 전부 새로 고르는** 데 있습니다.
그런데 쪽을 정말로 정점마다 골라야 할까요? 한 줄로 이은 네 정점 `0 - 1 - 2 - 3` 에서 정점 0 의 쪽만 0 으로
고르고, 간선이 시키는 대로 나머지를 적어 봅시다.

<!--proof:forced-chain-->

| 걸음 | 보는 간선 | 이 걸음이 한 일 | side |
| --- | --- | --- | --- |
| T1 | — | 정점 0 의 쪽을 0 으로 고른다 | 0:0 1:· 2:· 3:· |
| T2 | [0,1] | 정점 1 에 1 을 적는다 | 0:0 1:1 2:· 3:· |
| T3 | [1,0] | 정점 0 에 이미 0 이 있어 넘어간다 | 0:0 1:1 2:· 3:· |
| T4 | [1,2] | 정점 2 에 0 을 적는다 | 0:0 1:1 2:0 3:· |
| T5 | [2,1] | 정점 1 에 이미 1 이 있어 넘어간다 | 0:0 1:1 2:0 3:· |
| T6 | [2,3] | 정점 3 에 1 을 적는다 | 0:0 1:1 2:0 3:1 |
| T7 | [3,2] | 정점 2 에 이미 0 이 있어 넘어간다 | 0:0 1:1 2:0 3:1 |

고른 것은 한 번이고, 나머지 세 정점의 쪽은 간선이 정했습니다. 정본의 답은 true 입니다.

<!--/proof-->

간선 `[0,1]` 을 지키려면 정점 1 은 쪽 1 말고는 될 수 없고, 그러면 정점 2 는 쪽 0 말고는 될 수 없어요.
고른 것은 정점 0 의 쪽 하나였고 나머지는 **정해졌습니다.** 정점 0 에 쪽 1 을 골랐다면 네 값이 모두 뒤집힌
나눔이 나왔을 거예요. 그렇다면 모든 간선을 가르는 나눔은 연결 성분마다 두 가지뿐일 것입니다. 후보를 전부
세어서 확인해 봅시다.

<!--proof:valid-splits-->

| 입력 | 후보 2^V | 연결 성분 k | 모든 간선을 가르는 나눔 | 2^k | 정본 |
| --- | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 128 | 2 | 0 | — | false |
| 전개 입력에서 간선 [6,4] 를 뺀 것 | 128 | 2 | 4 | 4 | true |
| 길이 4 짜리 고리 | 16 | 1 | 2 | 2 | true |
| 한 줄로 이은 네 정점 | 16 | 1 | 2 | 2 | true |
| 간선이 없는 다섯 정점 | 32 | 5 | 32 | 32 | true |
| 삼각형 | 8 | 1 | 0 | — | false |

정본이 true 인 네 줄 가운데 모든 간선을 가르는 나눔의 수가 2^k 와 같은 줄은 네 줄입니다.

<!--/proof-->

모든 간선을 가르는 나눔의 수가 `2^k` 와 같습니다. 간선이 없는 다섯 정점은 연결 성분이 다섯이라 32 가지가
모두 살아남고, 길이 4 짜리 고리는 연결 성분이 하나라 두 가지뿐이에요. 고를 것은 **연결 성분마다 시작 정점의
쪽 하나**이고 나머지는 간선이 정합니다. 그러니 나눔을 만들어 볼 것이 아니라, 시작 정점에서 이웃으로 쪽을
**전파**하다가 어긋나는 간선이 나오는지만 보면 됩니다. 두 방식을 같은 입력에 실행해 세어 봅시다.

<!--proof:two-ways-->

| 입력 | E | 전수 시험의 간선 확인 | 전파의 이웃 항목 확인 | 2E | 정본 |
| --- | ---: | ---: | ---: | ---: | --- |
| 전개 입력 | 7 | 268 | 11 | 14 | false |
| 한 줄로 이은 10 정점 | 9 | 2,044 | 18 | 18 | true |
| 한 줄로 이은 15 정점 | 14 | 65,532 | 28 | 28 | true |
| 길이 20 짜리 고리 | 20 | 2,097,150 | 40 | 40 | true |
| 완전 이분 그래프 (왼쪽 10 · 오른쪽 10) | 100 | 2,106,346 | 200 | 200 | true |

다섯 줄 모두 두 방식의 답이 같고, 전파의 이웃 항목 확인이 2E 를 넘은 줄은 0 줄입니다.

<!--/proof-->

답은 같은데 들여다본 횟수가 갈립니다. 전파는 간선 하나를 양 끝에서 한 번씩 볼 뿐이라 `2E` 를 넘지 않고,
전수 시험은 후보 수를 따라갑니다. 여기서 관찰한 것은 하나예요. **비용은 고를 것이 몇 개인가가 정하고, 고를
것은 연결 성분마다 하나뿐입니다.**

그런데 전파하면서 정점에 **무엇을 적을지**가 아직 안 정해졌습니다. 가장 단순한 후보부터 시험해 봅시다.
너비 우선 탐색처럼 「봤다」 하나만 적고 퍼져 나가는 판이에요. 이미 본 이웃을 만났을 때 할 일은 두 가지뿐이라
둘 다 시험했습니다.

<!--proof:one-mark-->

| 입력 | 본 이웃에서 false 를 내는 판 | 본 이웃을 넘어가는 판 | 정본 |
| --- | --- | --- | --- |
| 전개 입력 | false | true | false |
| 길이 4 짜리 고리 | false | true | true |
| 삼각형 | false | true | false |
| 길이 5 짜리 고리 | false | true | false |
| 한 줄로 이은 네 정점 | false | true | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | false | true | true |
| 자기 자신을 잇는 간선 | false | true | false |

간선이 있는 입력 일곱 개에서 앞 판은 세 개, 뒤 판은 네 개의 답이 정본과 다릅니다.

<!--/proof-->

둘 다 틀립니다. 본 이웃에서 `false` 를 내면 길이 4 짜리 고리처럼 두 쪽으로 잘 나뉘는 그래프도 `false` 가
되고, 넘어가면 삼각형도 `true` 가 돼요. 「봤다」 하나로는 **그 이웃이 어느 쪽인지** 모르기 때문입니다.
그러니 「봤다」 대신 그 정점의 쪽을 적어야 합니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다. 앞
방법이 막힌 자리에서 다음 방법이 나왔고, 둘은 버리고 하나가 남았어요.

<!--fig:origin-approaches-->
![시도한 방법 셋 — 둘은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **쪽 배열 탐색**입니다. 정점마다 쪽 0 · 1 을 적고, 이웃에는 반대쪽을 적으며, 이미 적힌 이웃의
쪽이 자기와 같으면 `false` 를 돌려줘요. 쪽을 왜 꼭 두 값으로 적어야 하는지, 언제 적어야 스택에 같은 정점이
두 번 들어가지 않는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 쪽 배열 탐색

이 아이디어를 한 문장으로 줄이면 이렇습니다. **쪽 배열 `side` 를 `-1` 로 채우고, 정점 번호 순서로 쪽이 없는
정점을 찾아 쪽 0 을 적은 뒤, 스택에서 정점을 꺼낼 때마다 이웃의 쪽을 자기 쪽과 비교해 같으면 `false`,
없으면 반대쪽을 적어 스택에 넣습니다.** 이 방법이 기대는 「쪽 나눔」이라는 개념은 처음 보는 사람에게 낯설 수
있어서 먼저 따로 설명하고, 그다음 실현하는 순서대로 네 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서
쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 이웃 목록과 쪽 배열 만들기 | 간선을 두 목록에 넣고 `side` 를 `-1` 로 채운다 | — |
| 시작 정점마다 | 2단계 쪽 없는 정점에서 시작하기 | `side[s]` 가 `-1` 이면 쪽 0 을 적고 스택에 넣는다 | 1단계의 `side` |
| 꺼낸 정점의 이웃마다 | 3단계 이웃에 반대쪽 적기 | 이웃의 쪽이 없으면 반대쪽을 적고, 반대쪽이면 넘어간다 | 1단계의 `nbr` · 2단계의 스택 |
| 꺼낸 정점의 이웃마다 | 4단계 같은 쪽 이웃에서 끝내기 | 이웃의 쪽이 자기와 같으면 `false` 를 돌려준다 | 3단계가 적은 `side` |

#### 먼저 알아 둘 개념 — 쪽 나눔

쪽 나눔은 **정점마다 쪽 0 과 쪽 1 중 하나를 붙인 것**이고, 이 글이 찾는 것은 그중 **모든 간선의 두 끝이 서로
다른 쪽인 나눔**입니다. 식으로 적으면 모든 간선 `[u, v]` 에서 `side[u] ≠ side[v]` 예요.

##### 입력 위의 쪽 나눔

전개 입력의 왼쪽 연결 성분인 길이 4 짜리 고리를 쪽마다 한 줄로 다시 그렸습니다. 위 줄이 쪽 0, 아래 줄이 쪽 1
이에요.

<!--fig:build-rows-->
![길이 4 짜리 고리를 쪽마다 한 줄로 — 모든 간선이 두 줄 사이를 잇는다](./figs/build-rows.svg)

간선 넷이 모두 위 줄과 아래 줄 사이를 잇고, 한 줄 안을 잇는 간선은 하나도 없습니다. 이분 그래프는 이렇게
두 줄로 다시 그릴 수 있는 그래프예요.

##### 정점 하나를 읽는 법

정점 2 를 골라 읽어 보겠습니다. `side[2]` 에서 쪽을 읽고, `nbr[2]` 에서 이웃을 읽고, 이웃마다 쪽을 읽어
비교해요.

<!--proof:concept-read-->

| 읽는 것 | 보는 칸 | 값 |
| --- | --- | --- |
| 정점 2 의 쪽 | side[2] | 0 |
| 정점 2 의 이웃 | nbr[2] | [1, 3] |
| 이웃의 쪽 | side[1] · side[3] | 1 · 1 |
| 간선마다 두 끝의 비교 | [2,1] · [2,3] | 다르다 · 다르다 |

정점 2 에 이어진 간선 두 개가 모두 두 끝의 쪽이 다릅니다. 길이 4 짜리 고리의 쪽 배열은 0:0 1:1 2:0 3:1 입니다.

<!--/proof-->

정점 2 는 쪽 0 이고, 이웃 1 과 3 은 둘 다 쪽 1 입니다. 정점 하나를 읽는 일은 결국 **그 정점에 붙은 간선마다
두 끝의 쪽을 비교하는 일**이에요.

##### 쪽끼리의 관계

이웃끼리는 쪽이 반대입니다. 그래서 한 연결 성분 안에서는 정점 하나의 쪽이 나머지 전부를 정하고, 서로 다른
연결 성분은 아무 간선도 공유하지 않으니 따로 고릅니다. 전개 입력에서 삼각형을 닫는 간선 `[6,4]` 를 빼면
두 쪽으로 나뉘는 그래프가 되는데, 그 그래프에서 모든 간선을 가르는 나눔을 전부 늘어놓았습니다.

<!--proof:concept-splits-->

| 나눔 | 쪽 0 | 쪽 1 | 정점 0 의 쪽 | 정점 4 의 쪽 |
| --- | --- | --- | --- | --- |
| 나눔 1 | [1, 3, 4, 6] | [0, 2, 5] | 쪽 1 | 쪽 0 |
| 나눔 2 | [0, 2, 4, 6] | [1, 3, 5] | 쪽 0 | 쪽 0 |
| 나눔 3 | [1, 3, 5] | [0, 2, 4, 6] | 쪽 1 | 쪽 1 |
| 나눔 4 | [0, 2, 5] | [1, 3, 4, 6] | 쪽 0 | 쪽 1 |

후보 128 가지 가운데 모든 간선을 가르는 나눔은 네 가지입니다. 연결 성분이 두 개이고, 정점 0 · 4 의 쪽이 두 가지씩이라 2 × 2 = 4 입니다.

<!--/proof-->

네 나눔은 정점 0 의 쪽과 정점 4 의 쪽을 어떻게 골랐는가로만 갈립니다. 정점 0 의 쪽이 같은 두 나눔은 정점 0 ·
1 · 2 · 3 의 쪽이 똑같고, 정점 0 의 쪽이 다르면 네 정점의 쪽이 모두 뒤집혀요.

| 관계 | 네 나눔에서 | 까닭 |
| --- | --- | --- |
| 이웃끼리는 쪽이 반대 | 모든 간선에서 성립 | 쪽 나눔의 정의가 그렇다 |
| 한 연결 성분은 통째로 뒤집힌다 | 정점 0 · 1 · 2 · 3 이 함께 바뀐다 | 한 정점을 바꾸면 이웃이, 그 이웃의 이웃이 따라 바뀐다 |
| 연결 성분끼리는 따로 고른다 | 2 × 2 가지 | 두 성분 사이에 간선이 없다 |

##### 연결 성분과의 차이

쪽 나눔을 처음 보면 **두 쪽을 두 연결 성분**으로 읽기 쉽습니다. 둘 다 「정점을 무리로 나눈다」라서 그렇게
보여요. 같은 그래프를 두 기준으로 묶고, 묶음 안을 잇는 간선을 세었습니다.

<!--proof:concept-vs-components-->

| 묶는 기준 | 묶음 | 정점 | 묶음 안을 잇는 간선 |
| --- | --- | --- | ---: |
| 쪽 | 쪽 0 | [0, 2, 4, 6] | 0 |
| 쪽 | 쪽 1 | [1, 3, 5] | 0 |
| 연결 성분 | 정점 0 의 성분 | [0, 1, 2, 3] | 4 |
| 연결 성분 | 정점 4 의 성분 | [4, 5, 6] | 2 |

쪽 묶음 안을 잇는 간선은 0 · 0 개이고, 연결 성분 안을 잇는 간선은 4 · 2 개입니다. 간선은 모두 6 개입니다.

<!--/proof-->

두 기준이 정반대입니다. 연결 성분은 간선이 **묶음 안을 잇도록** 나눈 것이라 간선이 전부 묶음 안에 있고, 쪽은
간선이 **묶음 사이를 잇도록** 나눈 것이라 묶음 안의 간선이 0 개예요. 그래서 연결 성분이 몇 개인가와 두 쪽으로
나뉘는가는 서로 다른 물음이고, 이 글은 연결 성분마다 두 쪽을 따로 정합니다.

##### 쪽이 두 값인 까닭

찾는 것이 「모든 간선이 두 무리를 가르는 나눔」이라 무리가 둘이고, 그래서 값도 둘입니다. 값이 둘이면 「내 쪽이
아닌 쪽」이 하나뿐이라 이웃에 적을 쪽이 고를 것 없이 정해져요. 앞 절에서 본 「고를 것이 연결 성분마다 하나」가
이 사실에서 나옵니다. 값을 셋 이상으로 늘리면 무엇이 성립하지 않는지는 뒤의 「쪽을 두 값으로 두는 까닭」에서
값으로 봅니다.

| 값의 가짓수 | 이웃에 적을 값 | 이미 적힌 이웃과 다를 때의 뜻 |
| --- | --- | --- |
| 2 | 하나로 정해진다 | 그 간선은 두 쪽을 가른다 |
| 3 이상 | 둘 이상이다 | 「다르다」가 「두 쪽을 가른다」를 뜻하지 않는다 |

#### 1단계 — 이웃 목록과 쪽 배열 만들기

`edges` 를 그대로 두고 「정점 3 의 이웃」을 물으면 간선 목록을 처음부터 끝까지 읽어야 하고, `[2,3]` 처럼 3 이
뒤에 적힌 간선도 있어서 두 자리를 다 봐야 합니다. 간선을 한 번 읽으면서 양 끝의 목록에 넣어 두면 두 가지가
함께 없어져요. 전개 입력에서 만든 이웃 목록입니다.

<!--proof:build-lists-->

| 정점 v | nbr[v] | 길이 |
| ---: | --- | ---: |
| 0 | [1, 3] | 2 |
| 1 | [0, 2] | 2 |
| 2 | [1, 3] | 2 |
| 3 | [2, 0] | 2 |
| 4 | [5, 6] | 2 |
| 5 | [4, 6] | 2 |
| 6 | [5, 4] | 2 |

길이를 모두 더하면 14 이고, 간선 7 개의 두 배입니다.

<!--/proof-->

같은 단계에서 쪽 배열 `side` 를 길이 `V` 로 만들고 전부 `-1` 로 채웁니다. 쪽이 0 과 1 두 값이라 그 둘과 겹치지
않는 값이 「아직 없음」이 돼요. 크기도 여기서 정해집니다. 이웃 목록은 모두 `2E` 칸, 쪽 배열은 `V` 칸이고,
스택은 정점 하나가 한 번씩만 들어가므로 많아야 `V` 칸이에요(그 근거는 「쪽을 스택에 넣을 때 적는 까닭」에서
값으로 봅니다).

<!--proof:build-sizes-->

| 구조 | 크기 | 전개 입력에서 |
| --- | --- | --- |
| `nbr` | 목록 `V` 개, 칸 `2E` 개 | 목록 7 개, 칸 14 개 |
| `side` | `V` 칸 | 7 칸 |
| `stack` | 많아야 `V` 칸 | 가장 길 때 2 칸 |

#### 2단계 — 쪽 없는 정점에서 시작하기

바깥 반복이 정점 번호 순서로 시작 후보 `s` 를 봅니다. `side[s]` 가 `-1` 이면 새 연결 성분의 첫 정점이라 쪽 0 을
적고 스택에 넣어요. `-1` 이 아니면 앞 탐색이 이미 쪽을 적은 정점이니 넘어갑니다. 연결 성분의 첫 정점에 어느
쪽을 적어도 되는 까닭은 「쪽끼리의 관계」에서 본 대로 연결 성분이 통째로 뒤집혀도 모든 간선을 가르기 때문이에요.
전개 입력에서 바깥 반복이 본 시작 후보입니다.

<!--proof:stage-starts-->

| 시작 후보 s | 그때의 side[s] | 한 일 | 걸음 |
| ---: | ---: | --- | --- |
| 0 | -1 | 쪽 0 을 적고 스택에 넣는다 | T1 |
| 1 | 1 | 넘어간다 | — |
| 2 | 0 | 넘어간다 | — |
| 3 | 1 | 넘어간다 | — |
| 4 | -1 | 쪽 0 을 적고 스택에 넣는다 | T10 |

바깥 반복은 정점 다섯 개를 본 뒤 멈췄고, 그중 시작한 것은 두 번입니다. 정점 5 부터 6 까지는 그 전에 답이 나와 보지 않았습니다.

<!--/proof-->

정점 1 · 2 · 3 은 정점 0 에서 시작한 탐색이 이미 쪽을 적어 넘어갔고, 정점 4 는 쪽이 없어 두 번째 연결 성분을
시작했습니다. 시작 후보를 정점 6 까지 보지 않은 것은 4단계에서 답이 먼저 나왔기 때문이에요.

#### 3단계 — 이웃에 반대쪽 적기

스택에서 정점 `u` 를 꺼내고, 자기 쪽 `side[u]` 를 읽고, `nbr[u]` 의 이웃 `v` 를 차례로 봅니다. `side[v]` 가 `-1`
이면 `1 − side[u]` 를 적고 스택에 넣어요. `side[v]` 가 자기와 다른 쪽이면 이 간선은 이미 두 쪽을 가르므로
넘어갑니다. 쉬운 경우는 쪽이 없는 이웃에 적는 걸음이고, 불안한 경우는 **이미 쪽이 적힌 이웃을 다시 만나는
걸음**이에요. 전개 입력의 길이 4 짜리 고리 부분을 걸음마다 적었습니다. 걸음 번호 `T#` 는 「수행으로 알아보는
알고리즘」의 걸음과 같아요.

<!--proof:stage-spread-->

| 걸음 | 꺼낸 정점 | 이웃 | 갈래 | side | stack |
| --- | --- | --- | --- | --- | --- |
| T1 | — | — | 시작 | 0:0 1:· 2:· 3:· 4:· 5:· 6:· | [0] |
| T2 | 0 | 1 | ③ 쪽이 없다 | 0:0 1:1 2:· 3:· 4:· 5:· 6:· | [1] |
| T3 | 0 | 3 | ③ 쪽이 없다 | 0:0 1:1 2:· 3:1 4:· 5:· 6:· | [1, 3] |
| T4 | 3 | 2 | ③ 쪽이 없다 | 0:0 1:1 2:0 3:1 4:· 5:· 6:· | [1, 2] |
| T5 | 3 | 0 | ② 이미 반대쪽 | 0:0 1:1 2:0 3:1 4:· 5:· 6:· | [1, 2] |
| T6 | 2 | 1 | ② 이미 반대쪽 | 0:0 1:1 2:0 3:1 4:· 5:· 6:· | [1] |
| T7 | 2 | 3 | ② 이미 반대쪽 | 0:0 1:1 2:0 3:1 4:· 5:· 6:· | [1] |
| T8 | 1 | 0 | ② 이미 반대쪽 | 0:0 1:1 2:0 3:1 4:· 5:· 6:· | [] |
| T9 | 1 | 2 | ② 이미 반대쪽 | 0:0 1:1 2:0 3:1 4:· 5:· 6:· | [] |

T1 부터 T9 까지 ③ 이 3 번(T2 · T3 · T4), ② 가 5 번(T5 · T6 · T7 · T8 · T9) 실행됐고 ① 은 0 번입니다. T9 가 끝났을 때 스택은 [] 입니다.

<!--/proof-->

불안한 걸음은 다섯이고, 둘로 갈립니다. T5 · T8 은 자기에게 쪽을 적어 준 이웃을 다시 본 것이에요. 정점 3 은
T3 에서 정점 0 이 쪽을 적어 줬고, T5 에서 이웃 목록을 보다가 0 을 다시 만납니다. 0 의 쪽은 정의상 3 의 반대라
그대로 넘어가요. T6 은 다른 길로 쪽이 정해진 이웃을 처음 만난 것입니다. 정점 1 은 T2 에서 0 이 쪽 1 을 적어
줬고, T6 에서 정점 2 가 1 을 처음 만나는데 그 쪽이 2 의 반대라 넘어가요. **길이 4 짜리 고리가 닫히는 자리가
T6** 이고, 고리가 있어도 두 길의 걸음 수 홀짝이 같으면 쪽이 어긋나지 않습니다.

| 다시 만난 이웃 | 걸음 | 그 이웃의 쪽이 정해진 곳 | 결과 |
| --- | --- | --- | --- |
| 쪽을 적어 준 이웃 | T5 · T8 | 이 간선 자신 | 반대쪽이라 넘어간다 |
| 다른 길로 쪽이 정해진 이웃 | T6 · T7 · T9 | 다른 간선 | 반대쪽이라 넘어간다 — 고리가 닫힌다 |

빠뜨리는 이웃이 없다는 근거는 안쪽 반복의 종료 조건에 있습니다. 쪽이 적힌 정점은 모두 스택에 들어갔고, 스택이
빌 때까지 꺼내므로 모두 한 번씩 꺼내져 이웃 목록이 끝까지 읽혀요. 그러니 스택이 빈 순간 그 연결 성분의 간선은
양 끝에서 모두 확인됐습니다.

#### 4단계 — 같은 쪽 이웃에서 끝내기

3단계의 비교에서 이웃의 쪽이 **자기와 같으면** 그 간선의 두 끝이 한 쪽에 들어간 것입니다. 쪽은 한 번 적으면
바뀌지 않으니 이 나눔으로는 그 간선을 가를 수 없고, 연결 성분 전체가 이 쪽 아니면 통째로 뒤집은 쪽뿐이라 다른
나눔으로도 가를 수 없어요. 그래서 그 자리에서 `false` 를 돌려줍니다. 전개 입력의 삼각형 부분입니다.

<!--proof:stage-clash-->

| 걸음 | 꺼낸 정점 | 이웃 | 갈래 | side | stack |
| --- | --- | --- | --- | --- | --- |
| T10 | — | — | 시작 | 0:0 1:1 2:0 3:1 4:0 5:· 6:· | [4] |
| T11 | 4 | 5 | ③ 쪽이 없다 | 0:0 1:1 2:0 3:1 4:0 5:1 6:· | [5] |
| T12 | 4 | 6 | ③ 쪽이 없다 | 0:0 1:1 2:0 3:1 4:0 5:1 6:1 | [5, 6] |
| T13 | 6 | 5 | ① 쪽이 같다 | 0:0 1:1 2:0 3:1 4:0 5:1 6:1 | [5] |

T13 에서 꺼낸 정점 6 의 쪽 1 과 이웃 5 의 쪽 1 이 같아 false 를 반환합니다. 그때 스택에는 [5] 가 남아 있고, 정본의 답도 false 입니다.

<!--/proof-->

T11 과 T12 에서 정점 4 가 두 이웃 5 와 6 에 똑같이 쪽 1 을 적었고, 둘 사이에 간선 `[5,6]` 이 있어요. 끝나기
전 세 걸음을 무대로 보면 이렇습니다. 굵은 실선이 쪽을 적어 준 간선이고, 강조한 간선이 이번 걸음에 본 간선이에요.

<!--fig:build-clash-->
![T11 · T12 · T13 — 정점 4 가 두 이웃에 같은 쪽을 적고, 두 이웃이 이어져 있다](./figs/build-clash.svg)

정점 5 는 T11 에서 쪽을 받고 스택에 들어갔지만 꺼내지기 전에 답이 나왔습니다. 그래서 스택에 정점 5 가 남은
채로 끝나요. 남은 정점을 끝까지 꺼내도 답은 바뀌지 않으니 치를 필요가 없는 일입니다.

#### 이 방법이 기대는 전제

쪽 배열 탐색은 두 전제에 기댑니다. 하나라도 빠지면 답이 틀려요.

첫째는 **간선이 무향이고, 그래서 간선 하나를 두 목록에 다 넣는다**는 것입니다. 한쪽 목록에만 넣으면 뒤 끝에서
시작한 탐색이 앞 끝의 쪽을 모른 채 지나가요. 같은 경로를 간선을 적는 방향만 바꿔 넣고 두 판을 실행했습니다.

<!--proof:premise-one-list-->

| 입력 | 두 목록에 넣는 판 (정본) | 앞 끝의 목록에만 넣는 판 |
| --- | --- | --- |
| [[0,1],[1,2]] | true | true |
| [[1,0],[2,1]] | true | false |
| 전개 입력 | false | false |
| 길이 4 짜리 고리 | true | true |

답이 갈린 입력은 [[1,0],[2,1]] 한 개입니다. 첫 두 줄은 같은 경로 0 - 1 - 2 를 간선을 적는 방향만 바꿔 넣은 것입니다.

<!--/proof-->

`[[1,0],[2,1]]` 에서는 정점 0 의 목록이 비어 있어 0 에서 시작한 탐색이 곧바로 끝나고, 정점 1 이 새 연결 성분처럼
다시 쪽 0 으로 시작해 이웃 0 과 같은 쪽이 돼요. 둘째 전제는 **나눌 무리가 둘**이라는 것입니다. 이웃에 적을 쪽이
하나로 정해지는 것이 이 전제에서 나오고, 무리가 셋이면 그 자리가 성립하지 않아요. 바로 아래 절이 그것을 값으로 봅니다.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 간선 하나를 두 목록에 넣는다 | 1단계 · 3단계 | 한쪽 끝에서 시작한 탐색이 다른 끝의 쪽을 모른다 |
| 나눌 무리가 둘이다 | 3단계의 `1 − side[u]` | 이웃에 적을 쪽이 정해지지 않는다 |

#### 쪽을 두 값으로 두는 까닭

정점에 `0 … q−1` 중 하나를 적고 이웃에는 `(자기 값 + 1) mod q` 를 적되, 이웃의 값이 자기와 같으면 `false` 를
내는 판을 만들어, `q` 를 1 · 2 · 3 · 4 로 놓고 같은 여덟 입력에 실행했습니다. `q = 2` 가 쪽 배열 탐색이에요.

<!--proof:mark-width-->

| 입력 | 1 값 | 2 값 | 3 값 | 4 값 | 정본 |
| --- | --- | --- | --- | --- | --- |
| 전개 입력 | false | false | false | false | false |
| 길이 4 짜리 고리 | false | true | true | true | true |
| 삼각형 | false | false | false | false | false |
| 길이 5 짜리 고리 | false | false | true | true | false |
| 한 줄로 이은 네 정점 | false | true | true | true | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | false | true | true | true | true |
| 간선이 없는 다섯 정점 | true | true | true | true | true |
| 자기 자신을 잇는 간선 | false | false | false | false | false |

여덟 줄이 모두 정본과 같은 가짓수는 2 하나입니다. 가짓수마다 정본과 같은 줄 수는 1 값 5 · 2 값 8 · 3 값 7 · 4 값 7 입니다.

<!--/proof-->

한 값 판은 간선이 하나라도 있으면 이웃과 값이 같아 `false` 를 내고, 세 값 판과 네 값 판은 길이 5 짜리 고리를
`true` 라고 답합니다. 그 고리에 두 판이 실제로 무엇을 적는지 간선마다 나란히 봅시다.

<!--proof:mark-three-values-->

| 간선 | 두 값 판의 두 끝 | 두 값 판 | 세 값 판의 두 끝 | 세 값 판 |
| --- | --- | --- | --- | --- |
| [0,1] | 0 · 1 | 다르다 | 0 · 1 | 다르다 |
| [1,2] | 1 · 1 | 같다 | 1 · 0 | 다르다 |
| [2,3] | 1 · 0 | 다르다 | 0 · 2 | 다르다 |
| [3,4] | 0 · 1 | 다르다 | 2 · 1 | 다르다 |
| [4,0] | 1 · 0 | 다르다 | 1 · 0 | 다르다 |

끝까지 채우면 두 값 판은 0:0 1:1 2:1 3:0 4:1 을, 세 값 판은 0:0 1:1 2:0 3:2 4:1 을 적습니다. 두 끝의 값이 같은 간선은 두 값 판에 1 개, 세 값 판에 0 개입니다.

<!--/proof-->

두 값 판은 간선 `[1,2]` 에서 같은 값을 만나고, 세 값 판은 다섯 간선 어디에서도 못 만납니다. 값이 셋이면 「내
값이 아닌 것」이 둘이라, 고리를 한 바퀴 돌아와도 두 값이 서로 다를 수 있어요. 그래서 「다르다」가 「두 쪽을
가른다」를 뜻하지 않게 되고 판정이 성립하지 않습니다.

#### 쪽을 스택에 넣을 때 적는 까닭

쪽은 정점을 스택에 **넣을 때** 적을 수도 있고 **꺼낼 때** 적을 수도 있습니다. 꺼낼 때 적으면 정점이 스택 안에
있는 동안 쪽이 없는 채라, 다른 이웃이 그 정점을 쪽 없는 정점으로 보고 한 번 더 넣어요. 두 판을 여덟 입력에
실행해 넣은 횟수를 세었습니다.

<!--proof:write-when-->

| 입력 | V | 넣을 때 적는 판의 넣기 | 꺼낼 때 적는 판의 넣기 | 넣을 때 적는 판의 답 | 꺼낼 때 적는 판의 답 |
| --- | ---: | ---: | ---: | --- | --- |
| 전개 입력 | 7 | 7 | 9 | false | false |
| 길이 4 짜리 고리 | 4 | 4 | 5 | true | true |
| 삼각형 | 3 | 3 | 4 | false | false |
| 길이 5 짜리 고리 | 5 | 5 | 6 | false | false |
| 한 줄로 이은 네 정점 | 4 | 4 | 4 | true | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | 5 | 5 | 7 | true | true |
| 간선이 없는 다섯 정점 | 5 | 5 | 5 | true | true |
| 자기 자신을 잇는 간선 | 2 | 1 | 1 | false | false |

답이 갈린 입력은 0 개입니다. 답이 true 인 네 입력에서 넣을 때 적는 판의 넣기 횟수가 V 와 같은 것은 네 개이고, 꺼낼 때 적는 판이 V 보다 많이 넣은 것은 두 개입니다.

<!--/proof-->

답은 두 판이 같지만, 넣을 때 적는 판만 답이 `true` 인 입력에서 넣기 횟수가 정확히 `V` 입니다. 「정점 하나가
스택에 정확히 한 번 들어가고 한 번 나온다」가 여기서 서고, 비용 계산이 그 사실에 기대요. 그래서 쪽 배열
탐색은 `side[v] = …` 와 `stack.push(v)` 를 같은 자리에 둡니다.

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 셋째부터 다섯째까지가 바깥 반복 한 바퀴예요. 전수
시험에서 후보마다 하던 간선 확인이 이웃 항목 `2E` 개를 한 번씩 보는 일로 줄어듭니다.

1. 간선마다 `nbr[u]` 에 `v` 를, `nbr[v]` 에 `u` 를 넣고, `side` 를 `-1` 로 채운다
2. 시작 후보 `s` 를 0 부터 `V − 1` 까지 보며, `side[s]` 가 `-1` 이 아니면 넘어간다
3. `side[s]` 가 `-1` 이면 쪽 0 을 적고 스택에 넣는다
4. 스택이 빌 때까지 정점 `u` 를 꺼내 이웃 `v` 마다 — `side[v]` 가 `side[u]` 와 같으면 `false` 를 돌려주고, `-1` 이 아니면 넘어가고, `-1` 이면 `1 − side[u]` 를 적고 스택에 넣는다
5. 바깥 반복이 끝나면 `true` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 정점 일곱에 열세 걸음으로 쪽을 적는다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 그래프 하나를 정해 끝까지 가져가되, 코드
조각을 하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

```ts
const n = 7;
const edges: [number, number][] = [[0, 1], [1, 2], [2, 3], [3, 0], [4, 5], [5, 6], [6, 4]];
// 이 절이 끝나면 false 가 나와야 한다
```

왜 이 일곱 간선을 골랐을까요? 세 갈래와 바깥 반복의 두 갈래를 **한 입력에서 모두 실행하려는** 것입니다. 정점
0 · 1 · 2 · 3 은 길이 4 짜리 고리라 두 쪽으로 나뉘고, 그 탐색이 끝나 스택이 비면 바깥 반복이 정점 1 · 2 · 3 을
넘어간 뒤 정점 4 에서 다시 시작해요. 4 · 5 · 6 은 삼각형이라 마지막에 같은 쪽 이웃을 만나 `false` 가 됩니다.

```text
isBipartite(n, edges):
    간선 [u, v] 마다 nbr[u] 에 v 를, nbr[v] 에 u 를 넣는다
    side 를 전부 -1 로 둔다
    시작 후보 s 를 0 부터 n-1 까지:
        side[s] 가 -1 이 아니면 넘어간다
        side[s] 에 0 을 적고 stack 에 넣는다
        stack 이 비지 않은 동안:
            u ← stack 에서 꺼낸 정점,  su ← side[u],  other ← 1 - su
            nbr[u] 의 이웃 v 마다:
                side[v] 가 su 와 같으면 false 를 돌려준다   ① 두 끝이 한 쪽에 들어간다
                side[v] 가 -1 이 아니면 넘어간다            ② 이미 반대쪽이다
                side[v] 에 other 를 적고 stack 에 넣는다    ③ 쪽이 아직 없다
    true 를 돌려준다
```

#### 1. 이웃 목록과 쪽 배열을 만든다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 정점마다 빈 목록을 만들어 두고, 간선 하나를 양 끝의 목록에 한
번씩 넣어요. 쪽 배열은 `-1` 로 채우고, 스택은 빈 배열로 둡니다.

```ts
const nbr: number[][] = Array.from({ length: n }, () => []);
for (const [u, v] of edges) {
  (nbr[u] as number[]).push(v);
  (nbr[v] as number[]).push(u);
}

const side: number[] = Array.from({ length: n }, () => -1);
const stack: number[] = [];
```

이 조각만 실행하면 이렇게 나옵니다.

<!--proof:walk-open-->

```text
이웃 목록과 쪽 배열을 만든 직후
  nbr[0]  [1, 3]
  nbr[1]  [0, 2]
  nbr[2]  [1, 3]
  nbr[3]  [2, 0]
  nbr[4]  [5, 6]
  nbr[5]  [4, 6]
  nbr[6]  [5, 4]
  side    [-1, -1, -1, -1, -1, -1, -1]
  stack   []
```

`edges` 에 적은 순서가 그대로 목록 안의 순서가 됐습니다. `nbr[3]` 이 `[2, 0]` 인 것은 간선 `[2,3]` 이 `[3,0]`
보다 먼저 적혔기 때문이에요. 이 순서가 뒤에서 어느 이웃을 먼저 보는지를 정합니다.

#### 2. 쪽 없는 정점에서 시작한다

둘째 조각이 바깥 반복입니다. 시작 후보 `s` 를 정점 번호 순서로 보면서, 쪽이 이미 있으면 넘어가고, 없으면 쪽 0 을
적고 스택에 넣은 뒤 안쪽 반복을 실행해요.

```ts
for (let s = 0; s < n; s++) {
  if (side[s] !== -1) continue;
  side[s] = 0;
  stack.push(s);
  while (stack.length > 0) {
    // … 정점 하나를 꺼내 이웃을 본다 …
  }
}
```

T1 에서 이 조각을 실행하면 이렇습니다.

<!--proof:walk-start-->

```text
T1 — 바깥 반복이 s = 0 을 본다
  판정   side[0] 이 -1 이라 시작한다
  side   [0, -1, -1, -1, -1, -1, -1]
  stack  [0]
```

쪽을 적는 줄과 스택에 넣는 줄이 붙어 있다는 것을 봐 두세요. 「아이디어 상세」의 「쪽을 스택에 넣을 때 적는 까닭」
에서 본 대로, 이 두 줄이 떨어지면 같은 정점이 스택에 두 번 들어갑니다.

#### 3. 꺼낸 정점의 이웃과 쪽을 비교한다

셋째 조각이 판정이 일어나는 자리입니다. 스택에서 정점 하나를 꺼내 자기 쪽 `su` 와 이웃에 적을 쪽 `other` 를
정하고, 이웃 목록을 차례로 보면서 이웃마다 세 갈래 중 하나를 해요.

```ts
while (stack.length > 0) {
  const u = stack.pop() as number;
  const su = side[u] as number;
  const other = 1 - su;

  for (const v of nbr[u] as number[]) {
    // ① 쪽이 같다. 이 간선의 두 끝이 한 쪽에 함께 들어가므로 이분이 아니다.
    if (side[v] === su) return false;

    // ② 이미 반대쪽이다. 이 간선의 두 끝이 서로 다른 쪽에 있으므로 넘어간다.
    if (side[v] !== -1) continue;

    // ③ 아직 쪽이 없다. 반대쪽을 적고 스택에 넣는다.
    side[v] = other;
    stack.push(v);
  }
}
```

정점 4 를 꺼내 이웃 둘을 보는 T11 · T12 에서 이 조각을 실행하면 이렇습니다.

<!--proof:walk-pop4-->

```text
T11 — 정점 4 의 이웃 5
  판정   side[5] === 0 이 거짓, side[5] !== -1 이 거짓 → ③ 쪽이 없다
  계산   side[5] = 1 - 0 = 1
  side   [0, 1, 0, 1, 0, 1, -1]
  stack  [5]
T12 — 정점 4 의 이웃 6
  판정   side[6] === 0 이 거짓, side[6] !== -1 이 거짓 → ③ 쪽이 없다
  계산   side[6] = 1 - 0 = 1
  side   [0, 1, 0, 1, 0, 1, 1]
  stack  [5, 6]
```

여기서 가장 중요한 줄은 `const other = 1 - su;` 입니다. 쪽이 두 값뿐이라 반대쪽이 뺄셈 하나로 나와요. 이 줄이
틀리면 무엇이 되는지는 「불변식」에서 값으로 봅니다. T12 가 끝났을 때 정점 5 와 6 이 모두 쪽 1 이고, 둘 사이에는
간선이 있습니다. 그 간선을 누가 먼저 보는지가 T13 을 정해요.

#### 짚고 가기 — 지나온 이웃을 따로 기억해야 할 것 같다

여기서 헷갈리기 쉬운 부분은 무향 간선이 양쪽 목록에 다 들어 있다는 것입니다. 정점 3 을 꺼내 이웃 목록을 보면
3 에 쪽을 적어 준 정점 0 이 거기 들어 있어요. 그러면 그 간선을 한 번 더 판정하게 되니, 어느 이웃에서 왔는지를
정점마다 기억해 두고 그 하나를 건너뛰어야 할 것 같습니다. 무향 사이클 탐지가 드는 배열 하나(`from`)를 그대로
들여와 봅시다.

```ts
// 걱정대로 고친 판 — stack 과 짝지은 from 에 「쪽을 적게 한 이웃」을 담아 건너뛴다
const parent = from.pop() as number;
for (const v of nbr[u] as number[]) {
  if (v === parent) continue;
  // … 나머지는 같다 …
}
```

**이 입력 범위에서는 답이 안 틀립니다.** 두 판을 여덟 입력에 실행하고, 정점 넷 · 간선 넷 이하인 그래프를 전부
만들어 대조했어요.

<!--proof:skip-parent-->

| 입력 | 지나온 이웃을 그냥 두는 판 (정본) | 지나온 이웃을 건너뛰는 판 |
| --- | --- | --- |
| 전개 입력 | false | false |
| 길이 4 짜리 고리 | true | true |
| 삼각형 | false | false |
| 길이 5 짜리 고리 | false | false |
| 한 줄로 이은 네 정점 | true | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | true | true |
| 간선이 없는 다섯 정점 | true | true |
| 자기 자신을 잇는 간선 | false | false |

정점이 넷이고 간선이 넷 이하인 그래프 11,111 개(같은 쌍을 여러 번 잇는 것과 자기 자신을 잇는 것을 포함한다)를 전부 만들어 두 판을 대조했고, 반환값이 다른 그래프는 0 개입니다.

<!--/proof-->

걱정한 일이 일어나지 않는 까닭은 **쪽을 적어 준 이웃이 정의상 반대쪽**이기 때문입니다. T5 에서 정점 3 이 이웃
0 을 다시 봤을 때 `side[0]` 은 0, `side[3]` 은 1 이라 ① 이 아니라 ② 가 처리했어요. 그럼에도 이 배열을 두지
않는 까닭은 값을 더 치르기 때문입니다. 정점마다 `from` 칸이 하나씩 붙어 `V` 칸이 늘고, 꺼낼 때마다 `from.pop()` 이
한 번 더 실행되는데 답은 그대로예요.

| 표시 | 이미 표시된 이웃에서 아는 것 | 지나온 이웃 기억 |
| --- | --- | --- |
| 「봤다」 하나 (무향 사이클 탐지) | 어느 쪽인지 모른다 | 필요하다 |
| 쪽 두 값 (이 글) | 쪽을 그대로 비교한다 | 필요 없다 |

#### 짚고 가기 — 쪽이 적혀 있는지를 먼저 물어도 될 것 같다

①과 ② 의 순서가 임의로 보입니다. 「쪽이 적혀 있으면 넘어간다」가 더 넓은 물음이니 그것을 앞에 두고, 남은
경우에만 쪽을 비교하면 될 것 같아요. 그 오해대로 적으면 이렇게 됩니다.

```ts
// 오해대로 적은 판 — 쪽이 적혀 있는지를 먼저 묻는다
for (const v of nbr[u] as number[]) {
  if (side[v] !== -1) continue;
  if (side[v] === su) return false;
  side[v] = other;
  stack.push(v);
}
```

이 판도 예외 없이 끝납니다. 그리고 두 쪽으로 나뉘는 입력에서는 답까지 같아요.

<!--proof:order-swapped-->

| 입력 | 쪽이 같은지를 먼저 보는 판 (정본) | 쪽이 있는지를 먼저 보는 판 |
| --- | --- | --- |
| 전개 입력 | false | true |
| 길이 4 짜리 고리 | true | true |
| 삼각형 | false | true |
| 길이 5 짜리 고리 | false | true |
| 한 줄로 이은 네 정점 | true | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | true | true |
| 간선이 없는 다섯 정점 | true | true |
| 자기 자신을 잇는 간선 | false | true |

답이 갈린 입력은 네 개이고, 그중 정본이 false 인 입력이 네 개입니다.

<!--/proof-->

**두 쪽으로 못 나뉘는 입력이 전부 `true` 로 나옵니다.** 쪽이 같은 이웃은 **쪽이 적힌 이웃이기도 하므로**, 앞의
갈래가 먼저 데려가 버려요. 삼각형에서 순서를 바꾼 판이 하는 일을 걸음마다 적었습니다.

<!--proof:order-swapped-trace-->

| 꺼낸 정점 | 자기 쪽 | 이웃 | 그때 이웃의 쪽 | 순서를 바꾼 판이 한 일 | side |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 1 | · | 쪽 1 을 적는다 | 0:0 1:1 2:· |
| 0 | 0 | 2 | · | 쪽 1 을 적는다 | 0:0 1:1 2:1 |
| 2 | 1 | 1 | 1 | 넘어간다 | 0:0 1:1 2:1 |
| 2 | 1 | 0 | 0 | 넘어간다 | 0:0 1:1 2:1 |
| 1 | 1 | 0 | 0 | 넘어간다 | 0:0 1:1 2:1 |
| 1 | 1 | 2 | 1 | 넘어간다 | 0:0 1:1 2:1 |

넘어간 이웃 네 개 가운데 쪽이 꺼낸 정점과 같았던 것이 두 개인데, 순서를 바꾼 판은 true 를 냅니다.

<!--/proof-->

정점 2 를 꺼내 이웃 1 을 볼 때 둘 다 쪽 1 이지만, 판은 「쪽이 있다」만 보고 넘어갑니다. 둘째 갈래는 쪽이 `-1` 인
이웃만 만나게 되고, `-1` 은 `su` 와 같을 수 없어서 한 번도 참이 되지 않아요. 두 쪽으로 나뉘는 입력만 시험하면 이
순서를 바꿔 놓고도 통과합니다.

#### 짚고 가기 — 큐로 바꿔도 되는가

너비 우선 탐색에 익숙하면 「왜 큐가 아니라 스택인가, 순서가 바뀌면 쪽이 달라지지 않나」가 걸립니다. 스택을 큐로
바꾼 판을 같은 여덟 입력에 실행해 답 · 확인한 이웃 항목 수 · 끝난 뒤의 쪽 배열을 나란히 놓았습니다.

<!--proof:queue-same-->

| 입력 | 스택 (정본) | 큐 | 스택의 이웃 항목 확인 | 큐의 이웃 항목 확인 | 끝난 뒤 쪽 배열 |
| --- | --- | --- | ---: | ---: | --- |
| 전개 입력 | false | false | 11 | 12 | — |
| 길이 4 짜리 고리 | true | true | 8 | 8 | 같다 |
| 삼각형 | false | false | 3 | 4 | — |
| 길이 5 짜리 고리 | false | false | 7 | 8 | — |
| 한 줄로 이은 네 정점 | true | true | 6 | 6 | 같다 |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | true | true | 12 | 12 | 같다 |
| 간선이 없는 다섯 정점 | true | true | 0 | 0 | 같다 |
| 자기 자신을 잇는 간선 | false | false | 1 | 1 | — |

답이 갈린 입력은 0 개이고, 이웃 항목 확인 수가 갈린 입력은 세 개(전개 입력 · 삼각형 · 길이 5 짜리 고리)입니다.

<!--/proof-->

**답과 쪽 배열은 같고, 확인한 이웃 항목 수만 갈립니다.** 쪽 배열이 같은 까닭은 「쪽끼리의 관계」에 있어요. 두
쪽으로 나뉘는 연결 성분에서는 시작 정점의 쪽이 나머지를 모두 정하므로, 어느 순서로 퍼져 나가도 같은 값이 적힙니다.
확인 수가 갈리는 입력은 전부 두 쪽으로 못 나뉘는 입력이에요. 어긋나는 간선을 **언제 만나는가**가 순서를 따라
달라지고, 그만큼 일찍 또는 늦게 끝납니다.

| 무엇 | 순서에 따른 차이 | 까닭 |
| --- | --- | --- |
| 반환값 | 따르지 않는다 | 어긋나는 간선은 어느 순서로든 언젠가 확인된다 |
| 끝난 뒤 쪽 배열 (`true` 일 때) | 따르지 않는다 | 시작 정점의 쪽이 나머지를 정한다 |
| 확인한 이웃 항목 수 (`false` 일 때) | 따른다 | 어긋나는 간선을 만나는 때가 달라진다 |

이 글이 스택을 쓰는 것은 배열 끝에서 넣고 빼는 일이 짧게 적히기 때문이고, 큐를 써도 판정은 같습니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 안 나온 것은 마지막 `return true` 와 두 상수 이름뿐이에요. `NO_SIDE` 는 `-1`,
`FIRST_SIDE` 는 연결 성분의 첫 정점에 적는 쪽 `0` 입니다.

```ts
/** 아직 어느 쪽도 정하지 않은 정점. 쪽은 0 과 1 두 값이라 음수를 쓴다. */
const NO_SIDE = -1;

/** 연결 성분의 첫 정점에 적는 쪽. 0 과 1 중 어느 것을 골라도 반환값이 같다. */
const FIRST_SIDE = 0;

export function isBipartite(n: number, edges: [number, number][]): boolean {
  // 무향 간선 하나는 양쪽에서 걸어갈 수 있다. 두 목록에 한 번씩 넣는다.
  const nbr: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    (nbr[u] as number[]).push(v);
    (nbr[v] as number[]).push(u);
  }

  const side: number[] = Array.from({ length: n }, () => NO_SIDE);
  const stack: number[] = [];

  for (let s = 0; s < n; s++) {
    if (side[s] !== NO_SIDE) continue;
    side[s] = FIRST_SIDE;
    stack.push(s);

    while (stack.length > 0) {
      const u = stack.pop() as number;
      const su = side[u] as number;
      const other = 1 - su;

      for (const v of nbr[u] as number[]) {
        // ① 쪽이 같다. 이 간선의 두 끝이 한 쪽에 함께 들어가므로 이분이 아니다.
        if (side[v] === su) return false;

        // ② 이미 반대쪽이다. 이 간선의 두 끝이 서로 다른 쪽에 있으므로 넘어간다.
        if (side[v] !== NO_SIDE) continue;

        // ③ 아직 쪽이 없다. 반대쪽을 적고 스택에 넣는다.
        side[v] = other;
        stack.push(v);
      }
    }
  }

  return true;
}
```

여러 입력에 실행하면 이렇게 나옵니다.

isBipartite(3, [[0,1],[1,2],[2,0]])                          ->  false

### 알아 두면 좋은 개념 — 그래프 채색

전개가 끝났을 때 쪽 배열에는 정점마다 값 하나가 적혀 있었고, 그 값의 규칙은 **간선으로 이어진 두 정점의 값이
서로 달라야 한다** 하나였습니다. 이 규칙에는 이름이 있어요. 정점에 값을 붙이되 이웃끼리 값이 다르게 하는 것을
**그래프 채색**이라고 부르고, 그 값을 색이라고 부릅니다. 이분 그래프는 **색 두 가지로 칠할 수 있는 그래프**예요.
그래프마다 필요한 색의 가짓수를 전수로 세어 보면 대응이 보입니다.

<!--proof:colors-needed-->

| 입력 | V | E | 필요한 값의 가짓수 | 정본 |
| --- | ---: | ---: | ---: | --- |
| 간선이 없는 다섯 정점 | 5 | 0 | 1 | true |
| 한 줄로 이은 네 정점 | 4 | 3 | 2 | true |
| 길이 4 짜리 고리 | 4 | 4 | 2 | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | 5 | 6 | 2 | true |
| 삼각형 | 3 | 3 | 3 | false |
| 길이 5 짜리 고리 | 5 | 5 | 3 | false |
| 정점 넷을 모두 이은 것 | 4 | 6 | 4 | false |

일곱 줄 가운데 「가짓수가 2 이하」와 「정본이 true」가 함께 참이거나 함께 거짓인 줄은 일곱 줄입니다.

<!--/proof-->

가짓수가 2 이하인 줄과 두 쪽으로 나뉘는 줄이 정확히 겹칩니다. 필요한 최소 가짓수를 그 그래프의 **채색 수**라고
불러요. 같은 개념이 이 편 밖에서도 쓰입니다.

| 쓰이는 곳 | 정점 | 간선 | 색 |
| --- | --- | --- | --- |
| 레지스터 할당 | 변수 | 동시에 살아 있는 두 변수 | 레지스터 |
| 시험 시간표 | 과목 | 같은 학생이 듣는 두 과목 | 시간대 |
| 주파수 배정 | 기지국 | 서로 간섭하는 두 기지국 | 주파수 |

색이 둘일 때는 이웃의 색이 정해져 버려서 이 글의 절차가 `V + E` 규모로 답하지만, 세 색으로 칠할 수 있는가는
다항 시간 절차가 알려져 있지 않은 문제(NP-완전)입니다. 「쪽을 두 값으로 두는 까닭」에서 본 대로, 색이 하나 늘면
이웃에 적을 색이 둘이 되어 「따라 정해진다」가 성립하지 않기 때문이에요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 이것을 쓰는지, 쪽의 정의에서 무엇이 따라 나오는지, 무엇이 매
걸음 참으로 남는지, 그리고 연산이 몇 번인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

세 조건이 함께 맞을 때입니다.

- **나눌 무리가 둘입니다.** 셋 이상으로 나누는 과제로 바뀌면 이웃에 적을 값이 하나로 정해지지 않아 절차의 근거가
  없어져요.
- **간선에 방향이 없거나, 방향을 무시해도 됩니다.** 「두 끝이 서로 다른 무리」라는 조건은 방향과 무관해서, 방향
  그래프도 방향을 지우고 같은 판정을 합니다.
- **간선을 미리 다 받아 둘 수 있습니다.** 이웃 목록을 다 채운 다음에 첫 정점을 잡으므로, 간선이 하나씩 들어오며
  그때마다 답을 알아야 하면 그대로 쓰지 못해요.

| 조건 | 코드에서 그 조건을 쓰는 자리 |
| --- | --- |
| 무리가 둘이다 | `const other = 1 - su;` 한 줄로 이웃의 쪽이 정해진다 |
| 방향이 없다 | 간선 하나를 두 목록에 넣고, 그 뒤로 방향을 보지 않는다 |
| 미리 다 받는다 | `nbr` 을 다 채운 뒤에 첫 정점을 잡는다 |

두 무리로 나뉜다는 것을 확인한 다음 **그 나눔 자체**가 필요한 과제로 넘어가는 경우가 많습니다. 이 절차는 답이
`true` 일 때 쪽 배열에 나눔이 그대로 남아요.

| 과제 | 이 절차로 하는 일 |
| --- | --- |
| 두 쪽으로 나뉘는가 | 반환값 하나로 된다 |
| 두 무리를 적어 내라 | 쪽 배열을 그대로 돌려주면 된다 |
| 두 무리 사이에서 짝을 가장 많이 지어라 | 나눔을 얻은 뒤 별도 절차가 붙는다 — [`maxBipartiteMatching`](../maxBipartiteMatching/maxBipartiteMatching-guide.md) |

#### 문제에서 이것을 떠올리게 하는 단서

- 「두 편으로 나눌 수 있는가」, 「서로 아는 사람끼리 같은 조에 두지 마라」, 「적과 아군으로 가를 수 있는가」
- 「각 간선의 두 끝을 다르게 칠하라」, 「홀수 길이 고리가 있는가」
- 답이 참 · 거짓 하나이고, 정점 10 만 · 간선 20 만 규모라 `V + E` 에 비례하는 절차가 필요한 제약
- 그래프가 이어져 있지 않을 수 있다는 말 — 연결 성분마다 따로 시작하라는 뜻입니다
- 자기 자신을 잇는 간선이 있을 수 있다는 말 — 길이 1 짜리 고리를 빠뜨리지 말라는 뜻입니다

반대로 「세 무리로 나눠라」·「무리의 크기를 맞춰라」가 보이면 이 절차를 그대로 쓰지 않습니다. 앞은 이웃에 적을 값이
정해지지 않아 다른 과제가 되고, 뒤는 나눌 수 있는가를 넘어 **어떤 나눔을 고를 것인가**를 묻는 것이라 연결 성분마다
두 나눔 중 하나를 고르는 일이 더 붙어요.

#### 실제로 쓰이는 곳

- **NetworkX 의 `bipartite.color`** — 파이썬 그래프 라이브러리이고, `is_bipartite` 가 이 함수를 불러 예외가 나는지로
  답합니다. `networkx/algorithms/bipartite/basic.py` 가 시작 정점에 `color[n] = 1  # nodes seen with color (1 or 0)`
  로 값을 적고, 정점을 꺼낼 때 `c = 1 - color[v]  # opposite color of node v` 로 이웃에 적을 값을 냅니다 — 이 글의
  `const other = 1 - su;` 와 같은 한 줄이에요. 이웃을 보는 자리는 `if color[w] == color[v]:` 로 갈려
  `raise nx.NetworkXError("Graph is not bipartite.")` 를 내고, 아니면 `color[w] = c` 와 `queue.append(w)` 를 한
  자리에서 합니다. 담는 그릇도 `queue = [n]` 에 `v = queue.pop()` 이라 뒤에서 꺼내는 스택이고요. 갈리는 것은 고립
  정점 처리 하나입니다 — `if n in color or len(G[n]) == 0:  # skip isolates` 로 건너뛴 뒤 마지막에
  `color.update(dict.fromkeys(nx.isolates(G), 0))` 로 0 을 채웁니다.
  ([networkx/networkx networkx/algorithms/bipartite/basic.py](https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/bipartite/basic.py), 조회 2026-09-03)
- **Boost Graph Library 의 `is_bipartite`** — C++ 그래프 라이브러리입니다. 같은 판정을 깊이 우선 탐색의 방문자 두
  개로 갈라 놓은 것이 이 글과 다른 자리예요. `include/boost/graph/bipartite.hpp` 의 `bipartition_colorize` 는
  `on_tree_edge` 에서 실행되어 `put(partition_map_, target_vertex, color_traits::black())` 로 반대 색을 적고,
  `bipartition_check` 는 `on_back_edge` 에서 실행되어
  `if (get(partition_map_, source_vertex) == get(partition_map_, target_vertex))` 일 때
  `throw bipartite_visitor_error<...>` 를 냅니다. 문서 주석이 비용을 `Runs in linear time in the size of the graph,
  if access to the property maps is in constant time.` 로 적어 두었어요.
  ([boostorg/graph include/boost/graph/bipartite.hpp](https://raw.githubusercontent.com/boostorg/graph/develop/include/boost/graph/bipartite.hpp), 조회 2026-09-03)

| 구현 | 반대쪽을 내는 자리 | 어긋남을 잡는 자리 |
| --- | --- | --- |
| NetworkX | `c = 1 - color[v]` | `if color[w] == color[v]:` |
| Boost | `on_tree_edge` 에서 `black()` 을 적는다 | `on_back_edge` 에서 두 색이 같으면 던진다 |
| 이 글 | `const other = 1 - su;` | `if (side[v] === su) return false;` |

두 곳이 같은 한 줄을 각자의 언어로 적었습니다. 둘 다 「이웃에 적을 것은 반대쪽 하나뿐」이라는 같은 성질에 기대요.

#### 경쟁 설계와의 대조

같은 답을 내는 다른 절차가 있습니다. **쪽 관계 서로소 집합**이에요. 이웃 목록을 만들지 않고, 간선 `[u, v]` 를
「`u` 와 `v` 는 서로 다른 쪽」이라는 **관계**로 읽어 정점마다 대표까지의 홀짝을 함께 유지하는 서로소 집합에 넣습니다.
이미 한 무리인데 홀짝이 같으면 그 간선이 어긋나는 간선이라 `false` 예요. 그 자료구조는
[`unionFind` 가이드](../../../data-structures/disjoint-set/unionFind/unionFind-guide.mdx)가 다룹니다.

| 절차 | 판정하는 때 |
| --- | --- |
| 쪽 배열 탐색 | 목록을 다 만든 다음, 정점을 따라가다 이웃의 쪽을 비교할 때 |
| 쪽 관계 서로소 집합 | 간선을 하나 받을 때마다, 두 끝의 대표와 홀짝을 물을 때 |

전개가 쓰는 입력을 첫 줄에서 그대로 잽니다. 다만 정점이 일곱뿐이라 「간선 수가 정점 수에 비해 얼마인가」를 바꿔 볼
자리가 없어요. 그래서 정점을 규모의 상한인 100,000 으로 고정하고 **간선 수만 0 부터 200,000 까지 바꾸는** 생성식을
함께 씁니다. 번호 차가 홀수인 짝만 이어 붙이므로 간선을 몇 개 넣어도 두 쪽으로 나뉘고, 생성식은
`isBipartite-guide.alt.ts` 에 상수로 두었습니다. 계수는 배열 칸 접근 수와 새로 잡는 칸 수 둘이고, 칸을 한 번 읽으면
1 · 한 번 쓰면 1 로 두 절차에 같은 규칙을 썼어요.

<!--proof:alt-flip-->

| 재는 것 | 쪽 배열 탐색 | 쪽 관계 서로소 집합 | 적은 쪽 |
| --- | ---: | ---: | --- |
| 전개가 쓰는 정점 일곱에서 배열 칸 접근 | 111 | 104 | 쪽 관계 서로소 집합 |
| 간선 0 개에서 배열 칸 접근 | 800,000 | 300,000 | 쪽 관계 서로소 집합 |
| 간선 100,005 개에서 배열 칸 접근 | 1,800,050 | 1,800,049 | 쪽 관계 서로소 집합 |
| 간선 100,006 개에서 배열 칸 접근 | 1,800,060 | 1,800,061 | 쪽 배열 탐색 |
| 간선 200,000 개에서 배열 칸 접근 | 2,800,000 | 2,999,985 | 쪽 배열 탐색 |
| 간선 0 개에서 새로 잡는 칸 | 200,001 | 300,000 | 쪽 배열 탐색 |
| 간선 49,999 개에서 새로 잡는 칸 | 299,999 | 300,000 | 쪽 배열 탐색 |
| 간선 50,000 개에서 새로 잡는 칸 | 300,001 | 300,000 | 쪽 관계 서로소 집합 |
| 간선 200,000 개에서 새로 잡는 칸 | 666,667 | 300,000 | 쪽 관계 서로소 집합 |

**두 축이 각각 뒤집히고, 뒤집히는 방향이 서로 반대입니다.** 배열 칸 접근은 간선이 100,005 개일 때 서로소 집합이
하나 적다가 100,006 개에서 뒤집혀, 상한인 200,000 개에서는 쪽 배열 탐색이 적어요. 새로 잡는 칸은 반대로 49,999
개까지 쪽 배열 탐색이 적다가 50,000 개에서 뒤집힙니다.

| 재는 축 | 쪽 배열 탐색 | 쪽 관계 서로소 집합 |
| --- | --- | --- |
| 새로 잡는 칸 | `nbr` 의 `V` + 이웃 항목 `2E` + `side` 의 `V` + 스택 최대 깊이 | 대표 · 홀짝 · 크기 배열 셋 `3V` |
| 뒤집히는 자리 | `2V + 2E + 1 > 3V` 가 되는 첫 `E` | — |

**내주는 축이 둘입니다.** 하나는 간선이 정점보다 적은 그래프의 칸 접근이에요. 간선이 없어도 이 절차는 이웃 목록
배열과 쪽 배열을 만들고 바깥 반복이 정점을 전부 한 번씩 보는데, 서로소 집합은 배열 셋을 만들고 끝납니다. 둘째는
간선이 많을 때 새로 잡는 칸이고, 이웃 목록의 `2E` 칸이 그 차이예요. **얻는 축은 간선이 많은 그래프의 칸 접근과
나눔을 그대로 낸다는 것**입니다. 두 무리를 적어 내라는 과제로 바뀌면 쪽 배열이 그대로 답이 되고, 서로소 집합은
정점마다 대표를 다시 물어 홀짝을 읽는 일이 한 벌 더 붙어요.

| 조건 | 적은 쪽 | 까닭 |
| --- | --- | --- |
| 간선이 100,006 개 이상 (칸 접근) | 쪽 배열 탐색 | 간선마다 대표를 두 번 찾지 않는다 |
| 간선이 100,005 개 이하 (칸 접근) | 쪽 관계 서로소 집합 | 이웃 목록을 만들지 않는다 |
| 간선이 49,999 개 이하 (새로 잡는 칸) | 쪽 배열 탐색 | `2V + 2E` 가 `3V` 보다 작다 |
| 간선이 50,000 개 이상 (새로 잡는 칸) | 쪽 관계 서로소 집합 | `3V` 로 고정이다 |
| 간선을 하나씩 받으며 그때마다 답을 안다 | 쪽 관계 서로소 집합 | 이 절차는 처음부터 다시 한다 |
| 두 무리를 적어 낸다 | 쪽 배열 탐색 | 쪽 배열이 곧 답이다 |

간선을 하나씩 받는 축의 계수는 싣지 않았습니다. 같은 작업 목록을 두 절차가 같은 규칙으로 세는 자리가 아니기
때문이고, 대신 갈리는 조건을 위 표에 적었어요.

### 수식 정의와 유도

무향 그래프 $G$ 는 정점 집합 $\mathcal{V}$ 와 간선 집합 $\mathcal{E}$ 의 짝입니다. **쪽 배정**은 정점마다 0 또는 1 을
정해 주는 함수 $c$ 이고, 그 함수가 **이분 조건**을 만족한다는 것은 모든 간선의 두 끝에서 값이 다르다는 뜻이에요.
$|\mathcal{V}| = V$, $|\mathcal{E}| = E$ 입니다.

$$c : \mathcal{V} \to \{0, 1\}, \qquad \forall\, (u, v) \in \mathcal{E} : c(u) \neq c(v)$$

| 간선 하나의 두 끝 | 이분 조건 |
| --- | --- |
| $c(u) = 0$, $c(v) = 1$ | 지킨다 |
| $c(u) = 1$, $c(v) = 0$ | 지킨다 |
| $c(u) = c(v)$ | 깨뜨린다 |

값이 둘뿐이라 「다르다」가 곧 「하나는 0, 하나는 1」입니다. 아래 이름 둘을 더 씁니다. $d(v)$ 는 연결 성분의 시작
정점에서 $v$ 까지 쪽을 적어 온 걸음 수, 곧 쪽을 적어 준 간선만 따라간 **나무 경로**의 길이예요. 시작 정점은
$d = 0$ 이고, ③ 이 $v$ 에 쪽을 적을 때 $d(v) = d(u) + 1$ 입니다. 절차가 만드는 쪽 배정은 이 걸음 수의 홀짝이에요.

$$c(v) = d(v) \bmod 2$$

시작 정점은 쪽 0 을 받고, 한 걸음마다 반대쪽이 되어 홀짝이 한 번 바뀌기 때문입니다. 이 식을 전개 입력에 넣어
검산합시다.

<!--proof:depth-parity-->

| 정점 v | 성분 시작 정점 | d(v) | d(v) mod 2 | c(v) |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 | 0 |
| 1 | 0 | 1 | 1 | 1 |
| 2 | 0 | 2 | 0 | 0 |
| 3 | 0 | 1 | 1 | 1 |
| 4 | 4 | 0 | 0 | 0 |
| 5 | 4 | 1 | 1 | 1 |
| 6 | 4 | 1 | 1 | 1 |

일곱 정점 가운데 d(v) mod 2 와 c(v) 가 같은 정점은 일곱 개입니다. 이 표는 어긋나는 간선을 만나도 멈추지 않고 끝까지 채우는 판으로 적었습니다.

<!--/proof-->

정점 2 는 시작 정점 0 에서 3 을 거쳐 왔으므로 $d(2) = 2$ 이고 $2 \bmod 2 = 0$ 이 실제로 적힌 쪽과 같아요. 연결 성분이
둘이라 정점 4 는 자기가 시작 정점이고 $d(4) = 0$ 입니다.

이제 이분 조건을 만족하는 $c$ 가 **있는가**를 고리의 길이로 바꿔 적습니다. 고리란 서로 다른 정점
$v_0, v_1, \ldots, v_{L-1}$ 이 차례로 이어지고 $v_{L-1}$ 이 다시 $v_0$ 과 이어진 것이고, $L$ 이 그 길이예요. 고리
하나만 있는 그래프를 길이별로 실행하면 이렇습니다.

<!--proof:cycle-lengths-->

| 입력 | L | L 의 홀짝 | 정본 |
| --- | ---: | --- | --- |
| 길이 3 짜리 고리 | 3 | 홀수 | false |
| 길이 4 짜리 고리 | 4 | 짝수 | true |
| 길이 5 짜리 고리 | 5 | 홀수 | false |
| 길이 6 짜리 고리 | 6 | 짝수 | true |

네 줄 가운데 「L 이 짝수」와 「정본이 true」가 함께 참이거나 함께 거짓인 줄은 네 줄입니다.

<!--/proof-->

$$G \text{ 에 이분 조건을 만족하는 } c \text{ 가 있다} \iff G \text{ 에 길이가 홀수인 고리가 없다}$$

**왼쪽에서 오른쪽.** $c$ 가 있다고 하고 길이 $L$ 짜리 고리를 하나 잡습니다. 고리를 따라 한 걸음마다 값이 바뀌므로
$i$ 번째 정점의 값은 $c(v_i) = c(v_0) \oplus (i \bmod 2)$ 예요. 길이 4 짜리 고리에서 쪽 배열 탐색이 적은 값과
나란히 놓았습니다.

<!--proof:cycle-walk-->

| i | i mod 2 | c(v_0) ⊕ (i mod 2) | side[v_i] |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 |
| 1 | 1 | 1 | 1 |
| 2 | 0 | 0 | 0 |
| 3 | 1 | 1 | 1 |

네 줄 가운데 두 값이 같은 줄은 네 줄입니다. 닫는 간선 [3,0] 의 두 끝은 1 · 0 이라 다릅니다.

<!--/proof-->

$$c(v_{L-1}) = c(v_0) \oplus \big((L-1) \bmod 2\big)$$

닫는 간선 $(v_{L-1}, v_0)$ 도 두 끝이 달라야 하므로 $(L-1) \bmod 2 = 1$, 곧 $L$ 은 짝수입니다. 홀수 고리가 있으면
$c$ 가 없어요. **오른쪽에서 왼쪽.** 홀수 고리가 없다고 두고 $c(v) = d(v) \bmod 2$ 가 이분 조건을 만족함을 보입니다. 어긋나는 간선
$(u, v)$ 가 있다고 하면 $c(u) = c(v)$ 이므로 $d(u) + d(v)$ 가 짝수예요. 두 나무 경로가 갈라지는 마지막 정점을 $w$ 라고
하면, $w$ 에서 $u$ 까지 · $w$ 에서 $v$ 까지의 나무 경로와 간선 $(u, v)$ 가 고리 하나를 이룹니다.

$$L = \big(d(u) - d(w)\big) + \big(d(v) - d(w)\big) + 1 = d(u) + d(v) + 1 - 2\,d(w)$$

$d(u) + d(v)$ 가 짝수이고 $2\,d(w)$ 도 짝수라 $L$ 은 홀수입니다 — 가정과 어긋나요. 전개 입력의 삼각형이 그 모양입니다.

<!--fig:math-odd-cycle-->
![어긋나는 간선과 두 나무 경로가 이루는 고리](./figs/math-odd-cycle.svg)

$w = 4$, $d(5) = d(6) = 1$ 이라 $L = 1 + 1 + 1 - 0 = 3$ 입니다. $u = v$ 인 간선, 곧 자기 자신을 잇는 간선은 그
하나가 길이 1 짜리 고리라 같은 결론이 나와요.

```ts
// 고리 길이 식을 그대로 옮긴 조각 — w 는 두 나무 경로가 갈라지는 마지막 정점이다.
const cycleLength = (du: number, dv: number, dw: number): number =>
  du + dv + 1 - 2 * dw;
```

마지막으로 배열 칸 접근 수 $A(V, E)$ 를 코드에서 그대로 셉니다. 답이 `true` 일 때, 곧 모든 이웃 항목을 끝까지 확인할
때의 값이에요. 연결 성분 수 $k$ 가 항에 나옵니다.

$$A(V, E) = \underbrace{2V}_{\text{배열 둘}} + \underbrace{4E}_{\text{목록 만들기}} + \underbrace{V}_{\text{바깥 반복}} + \underbrace{2k}_{\text{시작하기}} + \underbrace{3V}_{\text{꺼내기}} + \underbrace{6E}_{\text{이웃 비교}} + \underbrace{2(V-k)}_{\text{쪽 적기}} = 8V + 10E$$

| 항 | 코드의 자리 |
| --- | --- |
| $2V$ | `Array.from` 두 번 — `nbr` · `side` |
| $4E$ | `nbr[u]` 읽기 + `push` + `nbr[v]` 읽기 + `push` |
| $V$ | 바깥 반복의 `side[s]` 읽기 |
| $2k$ | 연결 성분마다 `side[s]` 쓰기 + `stack.push` |
| $3V$ | 꺼낼 때마다 `stack.pop` + `side[u]` 읽기 + `nbr[u]` 읽기 |
| $6E$ | 이웃 항목 $2E$ 개마다 항목 읽기 + `side[v]` 읽기 둘 |
| $2(V-k)$ | 쪽을 적을 때마다 `side[v]` 쓰기 + `stack.push` |

$k$ 가 식에서 사라지는 것을 보세요. 시작할 때마다 2 칸을 쓰고 쪽을 적는 자리는 $V - k$ 번이라, 2 칸씩 곱하면 $2k$ 가
정확히 지워집니다. 식이 맞는지는 실제로 세어서 대조합니다.

<!--proof:cost-closed-form-->

| 입력 | V | E | k | 실제 칸 접근 | 8V + 10E |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력에서 간선 [6,4] 를 뺀 것 | 7 | 6 | 2 | 116 | 116 |
| 간선이 없는 다섯 정점 | 5 | 0 | 5 | 40 | 40 |
| 한 줄로 이은 1,000 정점 | 1,000 | 999 | 1 | 17,990 | 17,990 |
| 1,000 정점을 넷씩 가른 숲 | 1,000 | 750 | 250 | 15,500 | 15,500 |
| 완전 이분 그래프 (왼쪽 100 · 오른쪽 100) | 200 | 10,000 | 1 | 101,600 | 101,600 |
| 정점 100,000 · 간선 200,000 | 100,000 | 200,000 | 1 | 2,800,000 | 2,800,000 |

여섯 줄 가운데 실제 칸 접근이 8V + 10E 와 같은 줄은 여섯 줄입니다.

<!--/proof-->

셋째 줄과 넷째 줄은 정점 수가 같고 연결 성분 수가 1 과 250 으로 크게 갈리는데, 값의 차이는 간선 수에서만 나옵니다.
규모의 상한을 넣으면 $8 \cdot 100{,}000 + 10 \cdot 200{,}000 = 2{,}800{,}000$ 이고, 마지막 줄이 그 값이에요. 쪽 나눔 전부
시험의 후보 수가 3 만 자리를 넘는 수였던 것과 비교하면, 나눔을 만들어 보던 일이 이웃 항목마다 값 하나를 비교하는
일로 바뀐 것이 수로 나옵니다.

### 불변식 — 쪽이 적힌 정점의 쪽은 나무 경로 걸음 수의 홀짝과 같고, 확인을 마친 이웃 항목은 두 끝의 쪽이 다르다

파트 1 에서 코드가 동작하는 것을 열세 걸음으로 봤습니다. 그건 입력 하나에서 맞았다는 뜻이지 언제나 맞는다는 뜻은
아니에요. 매 걸음 참으로 남는 것을 아래 문장으로 세우고, 전개의 열세 걸음에서 두 성질을 걸음마다 셌습니다.

> 이웃 항목 하나를 확인하고 넘어갈 때마다, 쪽이 적힌 정점 $v$ 의 쪽은 $d(v) \bmod 2$ 와 같습니다. 그리고 지금까지
> 확인을 마친 이웃 항목은 모두 두 끝의 쪽이 서로 다릅니다.

<!--proof:invariant-steps-->

| 걸음 | 쪽이 적힌 정점 | 홀짝과 쪽이 어긋난 정점 | 확인을 마친 이웃 항목 | 그중 두 끝의 쪽이 같은 항목 |
| --- | ---: | ---: | ---: | ---: |
| T1 | 1 | 0 | 0 | 0 |
| T2 | 2 | 0 | 1 | 0 |
| T3 | 3 | 0 | 2 | 0 |
| T4 | 4 | 0 | 3 | 0 |
| T5 | 4 | 0 | 4 | 0 |
| T6 | 4 | 0 | 5 | 0 |
| T7 | 4 | 0 | 6 | 0 |
| T8 | 4 | 0 | 7 | 0 |
| T9 | 4 | 0 | 8 | 0 |
| T10 | 5 | 0 | 8 | 0 |
| T11 | 6 | 0 | 9 | 0 |
| T12 | 7 | 0 | 10 | 0 |
| T13 | 7 | 0 | 10 | 0 |

13 걸음 모두 뒤의 두 셈이 0 입니다. T13 에서 만난 쪽이 같은 이웃은 확인을 마친 항목으로 세지 않았습니다.

<!--/proof-->

「이웃 항목 하나를 확인하고 넘어갈 때마다」가 중요합니다. 순회가 끝난 뒤 한 번만 참인 것이 아니라 **갈래 하나를
실행한 직후마다** 참이라는 뜻이에요. **출발점부터 봅시다.** 바깥 반복이 쪽 없는 정점 `s` 에 쪽 0 을 적는 순간, 그 연결 성분에서 쪽이 적힌 정점은 `s`
하나이고 $d(s) = 0$ 이라 홀짝도 0 입니다. 확인을 마친 이웃 항목은 그 성분에 아직 없어서 둘째 성질은 앞 성분의
것만 남아 있어요. 그 뒤로 상태를 바꾸는 갈래는 셋입니다.

| 갈래 | 바뀌는 것 | 두 성질이 유지되는 근거 |
| --- | --- | --- |
| 쪽이 같은 이웃 | `false` 를 돌려주고 끝난다 | 상태를 바꾸지 않는다. 이 항목은 확인을 마친 것으로 세지 않는다 |
| 이미 반대쪽인 이웃 | 없다 | 쪽 배열이 그대로다. 이 항목은 두 끝의 쪽이 다르다 |
| 쪽이 없는 이웃 | 쪽 하나가 새로 정해진다 | $d(v) = d(u) + 1$ 이고 적는 값이 `1 - side[u]` 라 홀짝과 쪽이 함께 바뀐다 |

셋째 줄의 「함께 바뀐다」가 이 불변식의 핵심입니다. T3 과 T4 에서 두 값을 나란히 놓으면 이렇습니다.

<!--proof:invariant-t3t4-->

| 걸음 | 쪽을 받은 정점 v | 꺼낸 정점 u | d(v) | d(v) mod 2 | side[v] |
| --- | ---: | ---: | --- | ---: | --- |
| T3 | 3 | 0 | 0 + 1 = 1 | 1 | 1 - 0 = 1 |
| T4 | 2 | 3 | 1 + 1 = 2 | 0 | 1 - 1 = 0 |

걸음 수가 1 늘 때마다 홀짝이 뒤집히고 적는 쪽도 함께 뒤집혀서, 둘의 관계가 그대로 남아요. 이 불변식이 답의
정확성을 줍니다. 쪽이 같은 이웃을 만났다는 것은 홀짝이 같은 두 정점을 잇는 간선을 찾았다는 뜻이고, 「수식 정의와
유도」가 그 자리에서 길이가 홀수인 고리가 나온다는 것을 보였어요. 끝까지 그런 이웃을 만나지 못했다면 모든 이웃
항목이 둘째 성질에 들었으니 모든 간선이 두 쪽을 가른 것입니다.

| 끝난 모양 | 불변식이 말하는 것 | 답 |
| --- | --- | --- |
| 쪽이 같은 이웃을 만났다 | 홀짝이 같은 두 정점을 간선이 잇는다 — 홀수 고리 | `false` |
| 끝까지 못 만났다 | 모든 간선이 두 끝의 쪽이 다르다 — 이분 조건 그대로 | `true` |

**시작 쪽이 답을 바꾸지 않는 것도 여기서 나옵니다.** 불변식이 말하는 것은 「시작 정점의 쪽에서 걸음 수만큼 떨어진
값」이라 시작 쪽 자체는 어느 것이어도 됩니다. 정본의 `side[s] = FIRST_SIDE;` 를 `side[s] = 1 - FIRST_SIDE;` 로 바꿔
실행했습니다.

<!--proof:flip-start-->

| 시작 쪽 | 쪽 배열 (끝까지 채운 판) |
| --- | --- |
| 0 | 0:0 1:1 2:0 3:1 4:0 5:1 6:1 |
| 1 | 0:1 1:0 2:1 3:0 4:1 5:0 6:0 |

정점마다 값이 모두 뒤집혔습니다. 같은 변경을 정본의 한 줄에 적용해 여덟 입력에 실행하면 이렇습니다.

| 입력 | 쪽 0 에서 시작하는 판 (정본) | 쪽 1 에서 시작하는 판 |
| --- | --- | --- |
| 전개 입력 | false | false |
| 길이 4 짜리 고리 | true | true |
| 삼각형 | false | false |
| 길이 5 짜리 고리 | false | false |
| 한 줄로 이은 네 정점 | true | true |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | true | true |
| 간선이 없는 다섯 정점 | true | true |
| 자기 자신을 잇는 간선 | false | false |

반환값이 갈린 입력은 0 개입니다.

<!--/proof-->

정점 일곱의 쪽이 전부 뒤집혔는데 여덟 입력의 반환값이 하나도 안 바뀝니다. 경계에 있는 입력들도 확인하고 갑시다.

<!--proof:edge-cases-->

| 경계 | 호출 | 시작 횟수 | nbr[0] | 첫 이웃 확인의 갈래 | 가장 긴 스택 | 정본 |
| --- | --- | ---: | --- | --- | ---: | --- |
| 정점 하나 | `isBipartite(1, [])` | 1 | [] | 없음 | 1 | true |
| 간선 없음 | `isBipartite(10, [])` | 10 | [] | 없음 | 1 | true |
| 자기 자신을 잇는 간선 | `isBipartite(1, [[0,0]])` | 1 | [0, 0] | 쪽이 같다 | 1 | false |
| 같은 쌍 두 번 | `isBipartite(3, [[0,1],[0,1],[1,2]])` | 1 | [1, 1] | 쪽이 없다 | 1 | true |
| 나뉜 성분 | `isBipartite(5, [[0,1],[2,3]])` | 3 | [1] | 쪽이 없다 | 1 | true |
| 한 줄 100,000 정점 | `isBipartite(100000, 한 줄)` | 1 | 길이 1 | 쪽이 없다 | 1 | true |

자기 자신을 잇는 간선이 이 절차의 경계입니다. `[v, v]` 는 `nbr[v]` 에 `v` 를 **두 번** 넣고, `v` 를 꺼낼 때 그 첫
항목이 비교하는 두 값이 둘 다 `side[v]` 라 언제나 같아요. 쪽을 스택에 넣는 자리에서 적어 두었기 때문에 `v` 가
꺼내지는 시점에 이미 값이 있습니다. 한 줄로 이은 10 만 정점에서 가장 긴 스택이 1 칸인 것은 꺼낸 정점의 이웃 중 쪽이
없는 것이 늘 하나뿐이기 때문이고, 재귀를 쓰지 않으니 호출 깊이 제한도 받지 않아요.

**이제 깨뜨려 봅시다.** 「걸음 하나에 홀짝이 한 번 바뀐다」를 지키던 줄은 이웃에 적을 쪽을 정하는 줄입니다. 그 줄이
반대쪽 대신 같은 쪽을 내면 걸음을 아무리 가도 홀짝과 쪽이 따로 놀아요.

```ts
// const other = 1 - su;   ← 이 줄을 아래처럼 바꾼다
const other = su;
```

<!--proof:mutant-same-side-->

| 입력 | 이웃에 반대쪽을 적는 판 (정본) | 이웃에 같은 쪽을 적는 판 |
| --- | --- | --- |
| 전개 입력 | false | false |
| 길이 4 짜리 고리 | true | false |
| 삼각형 | false | false |
| 길이 5 짜리 고리 | false | false |
| 한 줄로 이은 네 정점 | true | false |
| 완전 이분 그래프 (왼쪽 둘 · 오른쪽 셋) | true | false |
| 간선이 없는 다섯 정점 | true | true |
| 자기 자신을 잇는 간선 | false | false |

반환값이 갈린 입력은 세 개입니다.

<!--/proof-->

**두 쪽으로 나뉘고 간선이 있는 그래프가 전부 `false` 로 바뀝니다.** 한 줄로 이은 네 정점에서는 정점 0 에 쪽 0 을 적고
이웃 1 에도 쪽 0 을 적은 다음, 1 을 꺼내 이웃 0 을 볼 때 둘 다 쪽 0 이라 그 자리에서 반환해요. 나머지 다섯 줄에서
두 값이 같다는 것도 함께 보세요. 간선이 없는 다섯 정점은 비교할 이웃이 없어 둘 다 `true` 이고, 두 쪽으로 못 나뉘는
그래프는 어차피 `false` 라 답이 갈리지 않습니다. 그런 입력만 시험하면 이 줄을 바꿔 놓고도 통과해요.

### 비용 계산

#### 비용을 세는 과정

한 바퀴가 하는 일은 스택에서 정점 하나를 꺼내 그 이웃 목록을 차례로 비교하는 것뿐입니다. 전개의 걸음으로 세면
이렇습니다.

<!--proof:derive-pops-->

| 바퀴 | 꺼낸 정점 | 본 이웃 | 걸음 |
| ---: | ---: | --- | --- |
| 1 | 0 | 1 · 3 | T2 · T3 |
| 2 | 3 | 2 · 0 | T4 · T5 |
| 3 | 2 | 1 · 3 | T6 · T7 |
| 4 | 1 | 0 · 2 | T8 · T9 |
| 5 | 4 | 5 · 6 | T11 · T12 |
| 6 | 6 | 5 | T13 |

꺼낸 정점은 6 개이고 두 번 꺼낸 정점은 0 개, 본 이웃 항목은 11 개입니다.

<!--/proof-->

꺼낸 정점은 0 · 3 · 2 · 1 · 4 · 6 이고, 바퀴마다 본 이웃이 T2 부터 T9 까지와 T11 · T12 · T13 이에요. 정점 5 는 T11
에서 쪽을 받았지만 꺼내기 전에 T13 이 반환했습니다. 그러니 꺼내는 횟수는 **쪽이 적힌 정점 수 이하**이고, 정점마다 한
번씩만 스택에 들어가므로 같은 정점을 두 번 꺼내지 않아요. 이웃을 비교하는 횟수는 **목록 길이의 합 `2E` 이하**입니다.
답이 `true` 면 둘 다 등호가 되고, 같은 쪽 이웃을 먼저 만나면 그만큼 작아져요. 그 앞에 이웃 목록을 만드는 값이 붙습니다.

| 항 | 규모 | 그 수를 정하는 것 |
| --- | --- | --- |
| 배열 둘 만들기 | `Θ(V)` | 정점마다 칸 하나씩 |
| 목록 채우기 | `Θ(E)` | 간선마다 두 번 |
| 바깥 반복 | `O(V)` | 시작 후보마다 한 번 |
| 꺼내기 · 쪽 적기 | `O(V)` | 정점마다 많아야 한 번 |
| 이웃 비교 | `O(E)` | 이웃 항목마다 많아야 한 번 |
| 모두 | `Θ(V + E)` | 목록 채우기가 늘 `Θ(V + E)` 를 치른다 |

여기서 센 것은 **배열 칸을 읽고 쓴 횟수** 하나입니다. `push` 가 안에서 칸을 다시 잡는 값은 세지 않았어요. 정점 하나가
스택에 들어가는 횟수도 간선 하나가 목록에 들어가는 횟수도 전체에서 정해져 있어서, 분할 상환하면 위 규모가
그대로입니다. 메모리는 `nbr` 의 `Θ(V + E)` 와 `side` · `stack` 의 `Θ(V)` 를 더해 `Θ(V + E)` 예요.

#### 케이스별 비용과 그 경계

**케이스**는 어떤 입력이 왔는가이고, **경계**는 그 값을 어떤 종류로 적었는가입니다. 두 축이 다른 것이라 표로 갈라
적어요.

| 케이스 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| 최선의 경우 (정점 0 에 자기 자신을 잇는 간선이 있다) | `O(V + E)` | `Θ(V + E)` |
| 평균적인 경우 (입력 분포를 정하지 않았다) | `O(V + E)` | `Θ(V + E)` |
| 최악의 경우 (두 쪽으로 나뉘어 끝까지 확인한다) | `O(V + E)` | `Θ(V + E)` |

**세 칸이 같은 값입니다.** 이웃 목록을 만드는 `2V + 4E` 칸은 어떤 입력에서도 치러야 하고, 그것이 그대로 하한이에요.
간선 하나를 목록에 안 넣고 지나가는 길이 코드에 없기 때문입니다. 케이스가 가르는 것은 규모가 아니라 상수배이고,
그 값은 아래 「최악을 만드는 입력」의 표가 보여요. 평균도 따로 계산할 대상이 없습니다. 같은 쪽 이웃을 언제 만나는가가
순회의 길이를 바꾸기는 하지만, 그 앞에 놓인 `2V + 4E` 가 늘 치러지므로 어떤 분포에서도 기댓값이 `Θ(V + E)` 를 벗어날
수 없어요.

| 보장의 종류 | 이 절차 |
| --- | --- |
| 최악 보장 — 어떤 입력에도 `V + E` 규모를 넘지 않는다 | 해당한다 |
| 기댓값 보장 — 입력 분포나 구현의 무작위성에 기댄다 | 해당하지 않는다 |

**보장의 종류는 최악 보장입니다.** 코드에 난수가 없어서 같은 간선 목록을 두 번 넣으면 반환값도 계수도 글자 그대로
같아요. `Θ(V + E)` 가 상한이자 하한입니다.

#### 최악을 만드는 입력

「규모의 상한을 둘 다 채우면 최악」이라는 통념부터 확인합시다. 정점 100,000 개와 간선 200,000 개를 함께 채운
그래프 중에 두 쪽으로 나뉘는 것이 **실제로 있어요.** 번호 차가 홀수인 짝만 이으면 정점 번호의 홀짝이 그대로 쪽이
되니까요. 그렇게 만든 입력입니다.

<!--proof:worst-build-->

| 간선 모양 | 번호 차 | 간선 수 |
| --- | ---: | ---: |
| [i, i+1] | 1 | 99,999 |
| [i, i+3] | 3 | 99,997 |
| [i, i+5] | 5 | 4 |

모두 합쳐 간선 200,000 개이고, 두 끝의 번호 홀짝이 다른 간선은 200,000 개입니다. 정본의 답은 true 입니다.

<!--/proof-->

그런 입력은 끝까지 확인하고 `true` 를 냅니다. 답이 `true` 라는 것이 곧 이웃 항목을 하나도 남기지 않고 확인한다는
뜻이니, 통념이 이 과제에서는 **맞습니다.** 모양을 바꿔 가며 실제로 세어 봅시다.

<!--proof:shape-values-->

| 입력 모양 | V | E | 배열 칸 접근 | 반환값 |
| --- | ---: | ---: | ---: | --- |
| 간선 200,000 개짜리 이분 그래프 | 100,000 | 200,000 | 2,800,000 | true |
| 완전 이분 그래프 (왼쪽 632 · 오른쪽 316) | 100,000 | 199,712 | 2,797,120 | true |
| 한 줄로 이은 100,000 정점 | 100,000 | 99,999 | 1,799,990 | true |
| 간선이 없는 100,000 정점 | 100,000 | 0 | 800,000 | true |
| 삼각형을 정점 0·1·2 에 두고 나머지를 이분으로 채운 것 | 100,000 | 200,000 | 1,000,021 | false |
| 같은 삼각형을 정점 번호 맨 뒤에 옮긴 것 | 100,000 | 200,000 | 2,799,985 | false |

가장 큰 값은 첫째 줄의 2,800,000 이고, 8·100,000 + 10·200,000 = 2,800,000 입니다.

<!--/proof-->

완전 이분 그래프는 간선이 첫 줄보다 조금 적어 값도 못 미칩니다. 모양이 아니라 `V` 와 `E` 두 수가 값을 정한다는 것이
여기서 보여요. 다섯째 줄과 여섯째 줄은 삼각형을 정점 번호 앞쪽에 두었는가 뒤쪽에 두었는가만 다른 같은 모양인데,
앞쪽이면 두 번째 바퀴에서 반환하고 뒤쪽이면 거의 끝까지 확인합니다.

| 최악을 만드는 조건 | 까닭 |
| --- | --- |
| `V` 와 `E` 를 상한까지 채운다 | `8V + 10E` 가 가장 커진다 |
| 두 쪽으로 나뉘어야 한다 | 못 나뉘면 어긋나는 간선에서 일찍 반환한다 |

가장 적은 일을 하는 입력은 그 반대입니다. 정점 0 에 `[0,0]` 을 하나 두면 첫 이웃 항목에서 바로 반환해요. 그래도 규모는
그대로 `Θ(V + E)` 입니다. 이웃 목록을 만드는 일은 어떤 입력에서도 치러야 하니까요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 쪽 나눔을 `2^V` 가지 만들어 보던 것을 **정점마다 두 값 중 하나를
적는 것**으로 바꿨고, 값이 둘뿐이라 이웃에 적을 쪽이 뺄셈 하나로 정해지며, 이미 적힌 이웃을 만났을 때 「같은가」가 그
자리에서 답을 정합니다.

| 걸음 | 세는 것 |
| --- | --- |
| 간선을 `nbr` 둘에 넣는다 | 목록 길이의 합이 `2E` |
| 쪽이 없는 정점에서 시작한다 | 바깥 반복이 정점을 많아야 `V` 번 본다 |
| 꺼내서 이웃의 쪽과 비교한다 | 같으면 `false` · 다르면 넘어간다 |
| 쪽이 없는 이웃에만 반대쪽을 적는다 | 쪽을 적는 일이 `V − k` 번 |

먼저 답이 붙는 문제 하나입니다. 전개는 마지막 간선이 `[6,4]` 라 정점 4 · 5 · 6 이 삼각형을 이뤘고 T13 에서 `false` 가
나왔습니다. 그 간선의 한쪽 끝만 옮겨 `[6,3]` 으로 바꾸면 반환값과 확인한 이웃 항목 수는 어떻게 될까요?

edges = [[0,1], [1,2], [2,3], [3,0], [4,5], [5,6], [6,3]]   ← 마지막 간선의 4 를 3 으로 바꿨다

### 이분 그래프 판정 (Bipartite Check)

풀 파일: [`isBipartite.ts`](./isBipartite.ts) · 테스트: [`isBipartite.test.ts`](./isBipartite.test.ts) · 실행: `bun test src/algorithms/graph-flow/isBipartite/isBipartite.test.ts`

#### 한 줄 요약

> 무방향 그래프를 나타내는 정점 수 `n` 과 간선 목록 `edges` 를 받아, 그래프가 **이분 그래프**이면 `true`, 아니면 `false` 를 반환한다.

#### 스토리

학교 동아리 임원 선발 위원회. 투표 용지를 한 장씩 들고 회의실에 모인 사람들이 있다. 위원회 규정상, 같은 쪽 사람끼리는 서로 아는 관계가 있으면 안 된다 — 서로 아는 두 사람은 반드시 **다른 쪽**에 속해야 공정한 평가가 이뤄진다.

총무는 참석자들이 "서로 안다"는 관계를 쭉 적어왔다. 이제 이 사람들을 두 그룹으로 나눌 수 있는지 확인해야 한다. 두 그룹으로 나눴을 때 **그룹 내부에 서로 아는 쌍이 없어야** 규정을 통과한다.

아는 관계가 전혀 없는 사람은 어느 쪽에 넣어도 상관없다. 여러 개의 독립된 소그룹이 있어도 각 소그룹마다 조건을 만족해야 전체가 통과된다.

#### 함수 인터페이스

```ts
export function isBipartite(n: number, edges: [number, number][]): boolean;
```

- `n` — 정점의 개수. 정점 번호는 $0 \ldots n-1$.
- `edges` — 무방향 간선 목록. 각 원소 `[u, v]` 는 정점 `u` 와 `v` 사이에 간선이 있음을 의미한다.
- 반환 — 그래프가 이분 그래프이면 `true`, 아니면 `false`.

#### 제약 조건

- $1 \leq n \leq 10^5$
- $0 \leq E \leq 2 \cdot 10^5$ (여기서 $E$ 는 간선의 수)
- 그래프가 연결되어 있지 않을 수 있다. 모든 컴포넌트에 대해 판정한다.
- 정점 번호는 $0 \ldots n-1$.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

무방향 그래프 $G = (V, E)$ 가 이분 그래프인지 판정한다.

이분 그래프란, 정점 집합을 서로소인 두 부분 $A$, $B$ 로 분할하여 모든 간선이 $A$ 와 $B$ 사이를 잇도록 만들 수 있는 그래프다. 즉:

$$\exists\, (A, B):\; V = A \cup B,\; A \cap B = \emptyset,\; \forall (u, v) \in E,\; (u \in A \land v \in B) \lor (u \in B \land v \in A)$$

- 그래프가 연결되어 있지 않을 경우, **모든 연결 컴포넌트**가 이분 그래프여야 `true` 를 반환한다.
- 간선이 없는 고립 정점은 어느 쪽 집합에도 넣을 수 있으므로 이분 조건을 위반하지 않는다.
- 자기 루프 `[v, v]` 가 있으면 이분 그래프가 될 수 없다.

#### 예시

```ts
isBipartite(4, [[0, 1], [1, 2], [2, 3], [3, 0]]); // true  — 길이 4짜리 사이클, 두 집합 {0,2}와 {1,3}으로 분할 가능
isBipartite(3, [[0, 1], [1, 2], [2, 0]]);         // false — 길이 3짜리 사이클, 두 집합으로 분할 불가능
isBipartite(5, [[0, 1], [2, 3]]);                 // true  — 연결되지 않은 두 컴포넌트, 각각 분할 가능
isBipartite(1, []);                               // true  — 간선 없음, 정점 하나는 자명하게 이분
isBipartite(1, [[0, 0]]);                         // false — 자기 루프, 분할 불가능
isBipartite(6, [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5]]); // true — 트리는 항상 이분 그래프
```
