# 프림 최소 신장 트리 — 경계를 넘는 가장 가벼운 간선을 우선순위 큐가 들고 있어 매번 다시 찾지 않는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 신장 트리를 전부
만들어 보는 방법에서 출발해, 경계 간선을 우선순위 큐에 담아 가장 가벼운 것부터 꺼내는 방법까지 갑니다. 그
방법을 준비되는 차례대로 값으로 풀고, 마지막에는 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

**가중치 무방향 그래프**는 정점들과, 두 정점을 잇되 방향이 없는 간선들로 이루어집니다. 간선마다 수 하나가
붙어 있고 그것을 **가중치**라고 불러요. 마을 여러 곳에 도로를 놓는다면 마을이 정점, 공사할 수 있는 구간이
간선, 그 구간의 공사비가 가중치입니다. 이 글이 끝까지 쓰는 그래프를 그리면 이렇습니다.

<!--fig:concept-graph-->
![전개 입력 — 정점 여섯 · 간선 일곱, 간선 옆 수는 가중치](./figs/concept-graph.svg)

간선은 양 끝 정점 번호에 가중치를 붙여 `(0,1)=1` 처럼 적고, 작은 번호를 언제나 앞에 둡니다. 정점 번호와
가중치가 둘 다 수라서 헷갈리지 않게 하려는 표기예요.

이 글이 만드는 것은 **모든 정점을 잇되 가중치 합이 가장 작은 간선 부분집합**입니다. 그런 부분집합을 **최소
신장 트리**라고 부릅니다. 이름에 트리가 들어가는 까닭이 있어요. 사이클이 하나라도 있으면 그 사이클의 간선
하나를 빼도 정점들은 여전히 이어져 있고 가중치 합만 줄어듭니다. 그러니 가장 가벼운 답에는 사이클이 없고,
사이클 없이 정점 `V` 개를 모두 잇는 그래프가 **트리**이며 그 간선은 정확히 `V − 1` 개입니다. 같은 그래프에서
최소 신장 트리를 굵게 그렸습니다.

<!--fig:concept-mst-->
![최소 신장 트리 — 굵은 간선 다섯](./figs/concept-mst.svg)

<!--proof:conceptCount-->

| 센 것 | 전개 입력 |
| --- | ---: |
| 정점 | 6 |
| 간선 | 7 |
| 최소 신장 트리의 간선 | 5 |
| 최소 신장 트리의 가중치 합 | 17 |

이 글의 절차는 간선을 (0,1)=1 · (1,2)=3 · (2,3)=2 · (3,4)=6 · (4,5)=5 차례로 골랐고, 전체 코드가 낸 답도 17 입니다.

<!--/proof-->

이 글의 절차(프림)는 **정점 하나에서 시작해 트리를 한 정점씩 불려 갑니다.** 지금 트리에 든 정점의 모임을
`S` 라 부를게요. 한 걸음마다 한쪽 끝은 `S` 안에, 다른 쪽 끝은 `S` 밖에 있는 간선 중 가장 가벼운 것을 골라 그
밖 끝점을 트리에 넣습니다. 한쪽 끝만 트리 안에 있는 간선을 **경계 간선**이라고 부르고, 그 모임을 `C(S)` 로
적습니다. `S` 가 커질 때마다 내용이 바뀌는 모임이라 `S` 를 함께 적어요. 정점 0 과 1 이 트리에 든 순간을
그렸습니다.

<!--fig:concept-cut-->
![트리 안 정점이 0 · 1 일 때의 경계 간선과 우선순위 큐](./figs/concept-cut.svg)

테 안이 `S` 이고, 테를 가로지르는 간선 셋이 경계 간선입니다. 간선마다 두 끝점이 테 안인지 밖인지 적으면 이렇게
갈려요.

<!--proof:conceptCut-->

| 간선 | 두 끝점 — 트리 안 · 밖 | 판정 |
| --- | --- | --- |
| (0,1)=1 | 안 · 안 | 아니다 |
| (0,3)=4 | 안 · 밖 | 경계 간선 |
| (0,5)=7 | 안 · 밖 | 경계 간선 |
| (1,2)=3 | 안 · 밖 | 경계 간선 |
| (2,3)=2 | 밖 · 밖 | 아니다 |
| (3,4)=6 | 밖 · 밖 | 아니다 |
| (4,5)=5 | 밖 · 밖 | 아니다 |

트리 안 정점이 {0, 1} 일 때 경계 간선은 3 개이고, 그중 가장 가벼운 것은 (1,2)=3 입니다. 이 간선의 트리 밖 끝점 2 가 다음에 트리에 들어갑니다.

<!--/proof-->

경계 간선 중 가장 가벼운 것을 **매번 빨리** 찾는 것이 이 절차의 전부입니다. 그림 아래 두 줄이 그 일을 맡는
**우선순위 큐**예요. 우선순위 큐는 항목마다 키가 붙어 있고, 꺼낼 때 **키가 가장 작은 항목**을 먼저 내주는
목록입니다. 이 절차는 정점 하나를 트리에 넣을 때 그 정점의 트리 밖 이웃마다 항목 `정점(키)` 를 넣는데, 키가
그 정점까지 잇는 간선의 가중치예요. 그림에서 `2(3)` 은 간선 `(1,2)=3` 이 넣은 항목이고, 큐는 항목을 꺼낼
차례대로 늘어놓았습니다. 큐가 경계 간선을 그대로 들고 있으니 걸음마다 간선 목록을 다시 볼 필요가 없어요. 할
일을 나누어 보면 이렇습니다.

| 할 일 | 하는 일 | 드는 비용 |
| --- | --- | --- |
| 이웃 목록 만들기 | 간선 하나를 양 끝점의 목록에 한 번씩 적는다 | 간선마다 두 번 |
| 우선순위 큐에서 꺼내기 | 키가 가장 작은 항목을 꺼내 그 정점이 트리 밖이면 트리에 넣는다 | 넣은 항목마다 많아야 한 번, 한 번에 `log` 번의 비교 |
| 후보 넣기 | 트리에 넣은 정점의 이웃 중 트리 밖인 것을 항목으로 넣는다 | 간선마다 많아야 한 번, 한 번에 `log` 번의 비교 |
| 모두 | | `O(V + E log E)` — `V` 는 정점 수, `E` 는 간선 수 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **그래프를 간선 목록과 이웃 목록으로 적는 방식.** 간선 하나를 `[u, v, w]` 세 수로 적고 늘어놓은 것이 간선
  목록이고, 정점마다 이어진 이웃을 모아 둔 것이 이웃 목록입니다. 이 절차는 간선 목록을 받아 이웃 목록으로
  바꿔 씁니다. 모르면 [`graphAdjList` 가이드](../../../data-structures/graph-repr/graphAdjList/graphAdjList-guide.mdx)를
  보세요.
- **트리가 무엇인지.** 사이클이 없으면서 모든 정점이 이어진 그래프이고, 정점이 `V` 개면 간선이 정확히 `V − 1`
  개입니다. 이 절차가 멈추는 조건이 「정점 `V` 개를 다 넣었다」라서, 이 성질이 흐릿하면 종료 조건이 어긋나
  보입니다.
- **우선순위 큐와 이진 힙.** 키가 가장 작은 항목을 먼저 내주는 목록이고, 이진 힙은 그것을 배열 하나로 만드는
  흔한 방법입니다. 넣기와 꺼내기가 각각 항목 수의 `log` 번 비교로 끝나요. 자료구조 자체가 궁금하면
  [`minHeap` 가이드](../../../data-structures/heap/minHeap/minHeap-guide.mdx)를 보세요.
- **배열의 첨자 접근이 `O(1)`** 이라는 것. 「이 정점이 트리에 들어갔는가」를 배열 칸 하나를 읽어 판정합니다.

같은 우선순위 큐를 쓰는 [`dijkstra`](../../shortest-path/dijkstra/dijkstra-guide.md) 를 먼저 읽었다면 뼈대가
낯익을 거예요. 이름이 비슷한 과제를 나란히 두면 이 글의 범위가 갈립니다.

| 과제 | 이 글에서 |
| --- | --- |
| 모든 정점을 잇는 간선 합을 가장 작게 한다 — 정점을 하나씩 붙여서 | 다룬다 |
| 같은 트리를 간선을 가벼운 것부터 보며 만든다 | 다루지 않는다 — [`kruskalMst`](../kruskalMst/kruskalMst-guide.md) |
| 두 정점 사이의 가장 짧은 길을 찾는다 | 다루지 않는다 — [`dijkstra`](../../shortest-path/dijkstra/dijkstra-guide.md) |
| 이어져 있는 정점 묶음만 찾는다 | 다루지 않는다 — [`connectedComponents`](../../graph/connectedComponents/connectedComponents-guide.md) |

### 아이디어를 떠올리는 과정 — 신장 트리 전부 만들기에서 경계 간선을 우선순위 큐에 담아 꺼내기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 정점 수와 간선 목록을 받아 최소 신장
트리의 가중치 합을 돌려줍니다.

```ts
function primMst(
  n: number,
  edges: [number, number, number][],
): number;
```

- 입력: 정점 수 `n` 과 무방향 가중치 간선 목록 `edges`. 원소 `[u, v, w]` 는 정점 `u` 와 `v` 를 잇는 가중치
  `w` 의 간선이고, 정점 번호는 `0` 부터 `n − 1` 까지예요. 같은 두 정점을 잇는 간선이 여럿 들어올 수 있고, 자기
  자신을 잇는 간선도 들어올 수 있습니다.
- 출력: 최소 신장 트리의 가중치 합. 모든 정점을 잇는 트리를 만들 수 없으면 `-1` 입니다. 정점이 하나뿐이면 간선
  없이 트리가 완성되므로 `0` 이에요.
- 규모: `1 ≤ V ≤ 10,000`, `0 ≤ E ≤ V(V − 1)/2`, 가중치는 `0` 이상 `10^9` 이하. 간선이 정점 쌍의 수까지 갈 수
  있어서 촘촘한 그래프도 들어옵니다. 비용은 흔한 채점 환경의 예산인 시간 1 초, 메모리 256 MB 에 대어 잽니다.

이 글에서 쓰는 기호는 여덟 개입니다. 여기서 정한 뜻을 글 끝까지 그대로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `V` | 정점의 개수. 코드의 `n` 입니다 | `1 ≤ V ≤ 10,000` |
| `E` | 간선의 개수. 코드의 `edges.length` 입니다 | `0 ≤ E ≤ V(V − 1)/2` |
| `(u,v)=w` | 정점 `u` 와 `v` 를 잇는 간선과 그 가중치 `w` | `0 ≤ w ≤ 10^9` |
| `adj[x]` | 정점 `x` 의 이웃 목록. 원소 하나를 `이웃(가중치)` 꼴로 적습니다 | 간선 하나가 양쪽에 한 번씩 적힌다 |
| `inTree[x]` | 정점 `x` 가 트리에 들어갔는가 | 한 번 참이 되면 다시 거짓이 되지 않는다 |
| `pq` | 우선순위 큐. 항목 하나를 `정점(키)` 꼴로 적습니다 | 키가 가장 작은 항목을 먼저 내준다 |
| `total` | 지금까지 트리에 넣은 간선의 가중치 합. 끝나면 이 값이 답입니다 | `0` 이상 |
| `joined` | 트리에 들어간 정점의 개수 | `V` 가 되면 끝난다 |

`S`(트리에 든 정점의 모임)와 `C(S)`(경계 간선의 모임)는 표에 넣지 않았습니다. 코드의 변수가 아니라 그림과
논증에서만 쓰는 이름이라, 「전체 컨셉」에서 정한 뜻 그대로 끝까지 씁니다. `S` 는 `inTree` 가 참인 정점의
모임과 같아요.

출발점은 정의를 그대로 옮기는 방법이에요. 답의 간선이 `V − 1` 개라는 것은 알고 있으니, **간선 `E` 개에서
`V − 1` 개를 고르는 모든 방법을 만들어** 그것이 사이클 없이 모든 정점을 잇는지 — 곧 신장 트리인지 — 보고,
맞으면 가중치 합을 재서 가장 작은 것을 남깁니다. 기법이 하나도 안 들어간 풀이입니다. 전개 입력에 그대로
넣었습니다.

<!--proof:bruteWalk-->

| 센 것 | 전개 입력 |
| --- | ---: |
| 크기 5 인 간선 부분집합 | 21 |
| 그중 신장 트리인 것 | 15 |
| 검사하며 읽은 간선 끝점 | 206 |
| 가장 작은 가중치 합 | 17 |
| 가장 큰 가중치 합 | 23 |

가장 작은 합 17 이 전체 코드가 낸 답 17 과 같습니다.

<!--/proof-->

크기를 `V − 1` 로 고정한 것은 앞에서 확인한 「답의 간선 수는 정점 수보다 하나 적다」를 이미 쓴 것입니다.
그것마저 안 쓰면 부분집합 전부를 만들어야 해요. 전개 입력에서 두 가짓수는 이렇습니다.

<!--proof:subsetCount-->

| 부분집합을 고르는 법 | 전개 입력에서 만드는 부분집합 |
| --- | ---: |
| 크기를 정하지 않는다 — 2^E | 128 |
| 크기를 V − 1 로 고정한다 — C(E, V − 1) | 21 |

<!--/proof-->

답은 맞아요. 그런데 정점이 늘면 신장 트리의 개수 자체가 감당할 수 없게 커집니다. 모든 정점 쌍을 이은 완전
그래프에서 정점 수를 올려 가며 재 봅시다.

<!--proof:naiveScale-->

| 정점 V | 간선 E | 신장 트리 수 V^(V−2) | 초당 1 억 개를 검사할 때 | 센 방법 |
| ---: | ---: | ---: | ---: | --- |
| 6 | 15 | 1,296 | 0.000 초 | 실행 |
| 10 | 45 | 100,000,000 | 1.0 초 | 식 |
| 15 | 105 | 1.946e+15 | 225.3 일 | 식 |
| 20 | 190 | 2.621e+23 | 83,125,317 년 | 식 |

정점 3 · 4 · 5 · 6 개짜리 완전 그래프에서 신장 트리를 전부 세어 V^(V−2) 와 일치하는 것을 확인했고, 「식」 줄은 그 식으로 낸 값입니다. 정점 10,000 개짜리 완전 그래프면 신장 트리 수를 적는 데만 39,993 자리가 듭니다.

<!--/proof-->

정점 20 개짜리 완전 그래프에서 **신장 트리를 검사만 해도** 8 천만 년이 넘습니다. 트리를 통째로 고르는
방식으로는 시작할 수 없어요. 방향을 바꿔, **정점 하나에서 시작해 한 정점씩 붙여** 봅시다. 정점 하나짜리 트리는
어느 신장 트리에도 들어 있으니 출발점으로 안전합니다. 붙일 때는 지금 트리와 잇는 간선, 곧 경계 간선 중 가장
가벼운 것을 골라요. 트리 안끼리 잇는 간선은 붙일 정점이 없으니 후보가 아닙니다. 전개 입력을 이 규칙대로
처리했습니다.

<!--proof:greedyWalk-->

| 차례 | 트리 안 정점 S | 경계 간선 | 그중 가장 가벼운 것 | 새로 넣은 정점 |
| ---: | --- | --- | --- | --- |
| 1 | {0} | (0,1)=1 · (0,3)=4 · (0,5)=7 | (0,1)=1 | 1 |
| 2 | {0, 1} | (0,3)=4 · (0,5)=7 · (1,2)=3 | (1,2)=3 | 2 |
| 3 | {0, 1, 2} | (0,3)=4 · (0,5)=7 · (2,3)=2 | (2,3)=2 | 3 |
| 4 | {0, 1, 2, 3} | (0,5)=7 · (3,4)=6 | (3,4)=6 | 4 |
| 5 | {0, 1, 2, 3, 4} | (0,5)=7 · (4,5)=5 | (4,5)=5 | 5 |

고른 간선 5 개의 가중치 합은 1 + 3 + 2 + 6 + 5 = 17 입니다.

<!--/proof-->

부분집합 21 개를 다 본 방법과 같은 17 이 나왔습니다. 이 규칙이 언제나 가장 가벼운 트리를 주는지는 파트 2 의
불변식이 따지고, 여기서는 규칙을 **빠르게 실행하는 법**을 찾습니다. 셋째 줄을 보세요. `S = {0, 1, 2}` 일 때 가장
가벼운 경계 간선 `(2,3)=2` 는 `S` 가 `{0}` 이었을 때 경계 간선이 아니었어요. **경계 간선은 트리가 커질 때마다
바뀝니다.** 그러면 그 목록을 어떻게 다룰지가 비용을 정합니다. 두 방식을 같은 입력에 적용해 기본 연산(비교 한
번과 배열 칸을 읽거나 쓴 한 번을 각각 하나로 센다)을 셌습니다. 앞 방식은 정점을 붙일 때마다 간선 목록 전부를
다시 읽어 경계 간선을 찾고, 뒤 방식은 트리 밖 정점마다 「트리와 잇는 가장 가벼운 간선 하나」를 배열에 적어 두고
걸음마다 트리 밖 정점을 전부 봅니다.

<!--proof:frontierCost-->

| 입력 | V | E | 경계 간선을 매번 다시 찾기 | 정점마다 가장 가벼운 간선 하나 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 7 | 88 | 113 |
| 한 줄로 이은 100 정점 | 100 | 99 | 19,800 | 20,595 |
| 별 모양 100 정점 | 100 | 99 | 24,651 | 20,595 |
| 완전 그래프 40 정점 | 40 | 780 | 71,539 | 6,525 |

두 방식 모두 네 입력에서 정본과 같은 합계를 냈습니다.

<!--/proof-->

**성긴 그래프에서는 두 방식이 같은 자릿수이고, 촘촘한 그래프에서 크게 갈립니다.** 완전 그래프 40 정점에서
앞 방식은 71,539 번, 뒤 방식은 6,525 번이에요. 앞 방식은 걸음마다 간선 `E` 개를 전부 판정하니 `(V − 1) × E` 에
비례하고, 뒤 방식은 정점을 넣을 때 그 정점의 간선만 보니 간선 하나를 한 번씩만 봅니다. 대신 뒤 방식에는
「걸음마다 트리 밖 정점을 전부 본다」가 남아서, 한 줄로 이은 그래프처럼 간선이 적어도 정점 수의 제곱만큼
일합니다.

| 방식 | 간선을 읽는 횟수 | 걸음마다 따로 하는 일 | 값을 정하는 것 |
| --- | --- | --- | --- |
| 경계 간선을 매번 다시 찾기 | 걸음마다 `E` 개 전부 | — | `(V − 1) × E` |
| 정점마다 가장 가벼운 간선 하나 | 간선마다 두 번 | 트리 밖 정점을 전부 본다 | `V × V` |

뒤 방식이 걸음마다 정점을 전부 보는 까닭은 하나예요. **후보 가운데 가장 가벼운 것 하나를 고르기** 위해서입니다.
후보를 담아 두었다가 가장 작은 것을 바로 내주는 저장소가 있으면 그 전수 검사가 필요 없어요. 그 저장소가
우선순위 큐입니다. 정점을 넣을 때마다 그 정점의 트리 밖 이웃을 항목으로 넣고, 걸음마다 키가 가장 작은 항목을
꺼내는 방식을 같은 네 입력에서 뒤 방식과 나란히 쟀습니다.

<!--proof:frontierQueue-->

| 입력 | V | E | 정점마다 가장 가벼운 간선 하나 | 후보를 우선순위 큐에 담기 |
| --- | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 7 | 113 | 63 |
| 한 줄로 이은 100 정점 | 100 | 99 | 20,595 | 595 |
| 별 모양 100 정점 | 100 | 99 | 20,595 | 2,562 |
| 완전 그래프 40 정점 | 40 | 780 | 6,525 | 8,209 |

우선순위 큐는 이진 힙으로 만들었고, 네 입력에서 정본과 같은 합계를 냈습니다.

<!--/proof-->

한 줄로 이은 100 정점에서 20,595 번이 595 번이 됩니다. 한 번에 큐에 담긴 항목이 적으면 꺼내기가 몇 번의 비교로
끝나기 때문이에요. 완전 그래프 40 정점에서는 우선순위 큐가 오히려 더 많이 일합니다 — 간선이 정점 수의 제곱에
가까우면 항목도 그만큼 쌓이기 때문이고, 그 자리는 「아이디어 상세」의 설계 선택과 파트 2 의 경쟁 설계에서 다시
봅니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법을 이 글에서는 「경계 간선을 우선순위 큐에 담아 가장 가벼운 것부터 꺼내기」라고 부를게요. 아직
확인하지 않은 것이 남아 있습니다. 큐에 든 항목이 정말 경계 간선과 같은지, 트리가 커져 쓸모없어진 항목은 어떻게
하는지, 언제 멈추는지예요. 다음 절에서 이 방법을 실현하는 순서대로 하나씩 확인합니다.

### 아이디어 상세 — 경계 간선을 우선순위 큐에 담아 가장 가벼운 것부터 꺼내기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **정점 하나를 트리에 넣을 때마다 그 정점의 트리 밖 이웃을 간선
가중치를 키로 우선순위 큐에 넣고, 키가 가장 작은 항목을 꺼내 그 정점이 아직 트리 밖이면 트리에 넣는 일을 정점이
다 찰 때까지 되풀이합니다.** 이 방법은 경계 간선이라는 모임 위에서 동작하는데, 트리 안과 밖을 가르는 이
생각은 처음 보는 사람에게 낯설어요. 그래서 경계 간선을 먼저 따로 설명하고, 그다음 실현하는 순서대로 네 단계를
설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 시작할 때 한 번 | 1단계 이웃 목록과 시작 항목 | 이웃 목록 `adj` 를 만들고 `inTree` 를 거짓으로 채우고 큐에 `0(0)` 을 넣는다 | — |
| 큐가 빌 때까지 | 2단계 키가 가장 작은 항목 꺼내기 | 꺼낸 정점이 트리 안이면 버리고, 밖이면 트리에 넣고 `total` 에 키를 더한다 | 1단계의 `pq` · `inTree` |
| 정점을 넣을 때마다 | 3단계 트리 밖 이웃을 후보로 넣기 | 새 정점의 이웃 중 트리 밖인 것을 항목 `이웃(가중치)` 로 넣는다 | 1단계의 `adj` · 2단계가 넣은 정점 |
| 넣을 때마다와 끝에 | 4단계 정점 수로 끝내기 | `joined` 가 `V` 면 `total` 을 돌려주고, 큐가 비면 `-1` | 2단계의 `joined` |

#### 먼저 알아 둘 개념 — 경계 간선

경계 간선은 **두 끝점 중 한쪽만 트리 안에 있는 간선**입니다. 트리 안 정점의 모임 `S` 와 그 바깥을 가르는 금을
그으면, 그 금을 가로지르는 간선이 경계 간선이에요. 식으로 적으면 `C(S)` 는 `inTree[u]` 와 `inTree[v]` 가 서로
다른 간선 `(u,v)` 의 모임입니다.

##### 입력 위의 경계 간선

전개 입력에서 정점 셋이 트리에 든 T4 직후를 그렸습니다. 테 안이 `S` 이고, 굵은 간선이 이미 트리에 넣은 간선,
테를 가로지르는 간선이 경계 간선, 그중 가장 가벼운 것이 강조한 간선이에요. 두 끝이 다 밖인 간선은 흐리게
그렸습니다.

<!--fig:build-cut-->
![T4 뒤의 경계 간선](./figs/build-cut.svg)

경계 간선이 셋이고, 트리에 넣은 간선 둘은 테 안에 있습니다. 테 밖끼리 잇는 간선 둘은 아직 이 절차와 상관이
없어요. 한 끝이 트리에 들어오는 순간에야 경계 간선이 됩니다.

##### 간선 하나가 경계 간선인지 읽는 법

간선 `(u,v)` 하나를 판정하는 데 필요한 것은 배열 칸 둘, `inTree[u]` 와 `inTree[v]` 입니다. 둘이 다르면 경계
간선이고, 같으면 아니에요. 같은 T4 직후에 간선 일곱을 모두 판정했습니다.

<!--proof:cutRead-->

| 간선 (u,v)=w | inTree[u] | inTree[v] | 판정 |
| --- | --- | --- | --- |
| (0,1)=1 | 참 | 참 | 아니다 |
| (0,3)=4 | 참 | 거짓 | 경계 간선 |
| (0,5)=7 | 참 | 거짓 | 경계 간선 |
| (1,2)=3 | 참 | 참 | 아니다 |
| (2,3)=2 | 참 | 거짓 | 경계 간선 |
| (3,4)=6 | 거짓 | 거짓 | 아니다 |
| (4,5)=5 | 거짓 | 거짓 | 아니다 |

T4 가 끝난 뒤 S = {0, 1, 2} 에서 경계 간선은 (0,3)=4 · (0,5)=7 · (2,3)=2 의 3 개입니다.

<!--/proof-->

`(2,3)=2` 를 따라가 봅시다. `inTree[2]` 가 참이고 `inTree[3]` 이 거짓이라 경계 간선이에요. `(1,2)=3` 은 둘 다
참이라 트리 안끼리 잇는 간선이고, `(3,4)=6` 은 둘 다 거짓이라 트리 밖끼리 잇는 간선입니다.

##### 정점 하나를 넣을 때 경계 간선이 바뀌는 모양

정점 `x` 하나를 트리에 넣으면 `x` 를 끝점으로 하는 간선만 판정이 뒤집힙니다. `x` 와 트리를 잇던 간선은 두 끝이 다 안이
되어 빠지고, `x` 와 트리 밖 정점을 잇는 간선은 한 끝이 안이 되어 들어와요. 정점을 넣은 걸음마다 빠진 것과
들어온 것을 셌습니다.

<!--proof:cutGrow-->

| 걸음 | 새로 넣은 정점 | 빠진 경계 간선 | 들어온 경계 간선 | 그 뒤 경계 간선 수 |
| --- | --- | --- | --- | ---: |
| T2 | 0 | 없음 | (0,1)=1 · (0,3)=4 · (0,5)=7 | 3 |
| T3 | 1 | (0,1)=1 | (1,2)=3 | 3 |
| T4 | 2 | (1,2)=3 | (2,3)=2 | 3 |
| T5 | 3 | (0,3)=4 · (2,3)=2 | (3,4)=6 | 2 |
| T7 | 4 | (3,4)=6 | (4,5)=5 | 2 |

빠지거나 들어온 간선 가운데 새로 넣은 정점을 끝점으로 갖지 않는 간선은 0 개입니다.

<!--/proof-->

T5 가 가장 눈여겨볼 걸음입니다. 정점 3 을 넣자 `(2,3)=2` 뿐 아니라 `(0,3)=4` 도 함께 빠졌어요. 정점 3 과
트리를 잇는 간선이 둘이었기 때문입니다. 이 사실이 3단계의 「지나간 후보」를 낳습니다.

| 관계 | 전개 입력에서 | 뜻 |
| --- | --- | --- |
| 새 정점과 트리를 잇던 간선은 빠진다 | T5 에서 `(0,3)=4` · `(2,3)=2` | 빠진 간선이 둘 이상일 수 있다 |
| 새 정점과 밖을 잇는 간선은 들어온다 | T5 에서 `(3,4)=6` | 들어오는 간선은 새 정점의 이웃 목록에 다 있다 |
| 새 정점을 끝점으로 갖지 않는 간선은 그대로다 | `(0,5)=7` 은 T2 부터 T7 까지 경계 간선 | 판정을 다시 할 필요가 없다 |

##### 끝점이 트리 안에 있는 간선 전부와의 차이

경계 간선을 처음 보면 **끝점이 트리 안에 있는 간선 중 가장 가벼운 것을 고르면 되지 않나**로 읽기 쉽습니다. 한
끝이라도 트리 안에 있는 간선 전부를 후보로 두는 모양이에요. 걸음마다 두 모임의 가장 가벼운 간선을 나란히 놓았습니다.

<!--proof:cutVsTouch-->

| 트리 안 정점 S | 끝점이 S 안에 있는 간선 중 가장 가벼운 것 | 붙는 새 정점 | 경계 간선 중 가장 가벼운 것 |
| --- | --- | --- | --- |
| {0} | (0,1)=1 | 1 | (0,1)=1 |
| {0, 1} | (0,1)=1 | 없다 — 두 끝이 다 트리 안 | (1,2)=3 |
| {0, 1, 2} | (0,1)=1 | 없다 — 두 끝이 다 트리 안 | (2,3)=2 |
| {0, 1, 2, 3} | (0,1)=1 | 없다 — 두 끝이 다 트리 안 | (3,4)=6 |
| {0, 1, 2, 3, 4} | (0,1)=1 | 없다 — 두 끝이 다 트리 안 | (4,5)=5 |

걸음 5 개 가운데 「끝점이 S 안에 있는 간선 중 가장 가벼운 것」으로는 새 정점이 안 붙는 걸음이 4 번입니다.

<!--/proof-->

끝점이 트리 안에 있는 간선 중 가장 가벼운 것은 둘째 걸음부터 늘 `(0,1)=1` 입니다. 이미 트리에 넣은 간선이라 두 끝이 다 안에
있고, 골라도 새 정점이 하나도 안 붙어요. 트리에 붙일 수 있는 것은 한 끝이 밖에 있는 간선뿐이라서, 후보를 경계
간선으로 좁혀야 걸음마다 정점 하나가 늘어납니다.

| 후보로 두는 모임 | 담는 간선 | 가장 가벼운 것을 골랐을 때 |
| --- | --- | --- |
| 끝점이 트리 안에 있는 간선 | 한 끝이라도 트리 안 | 트리 안끼리 잇는 간선이 뽑혀 정점이 안 붙는다 |
| 경계 간선 | 한 끝만 트리 안 | 언제나 트리 밖 정점 하나가 붙는다 |

##### 경계 간선을 보는 까닭

트리를 한 정점씩 불리려면 한 걸음에 붙일 간선이 한 끝은 트리에, 다른 끝은 트리 밖에 있어야 합니다. 그 조건을
그대로 적은 것이 경계 간선이에요. 그리고 그중 가장 가벼운 것을 골라도 가장 가벼운 트리를 놓치지 않는다는 것 —
경계 간선 중 가장 가벼운 것은 어떤 최소 신장 트리에 반드시 들어간다는 것 — 은 파트 2 의 불변식이 바꿔치기
논증으로 보입니다. 아래 네 단계는 이 모임을 우선순위 큐 하나로 유지하는 방법이에요.

#### 1단계 — 이웃 목록과 시작 항목 준비하기

간선 목록을 이웃 목록 `adj` 로 바꿉니다. 이 절차가 걸음마다 묻는 것은 「새로 넣은 정점의 이웃이 누구인가」인데,
간선 목록에서는 그것을 찾으려면 목록 전부를 읽어야 하기 때문이에요. 무방향이라 간선 하나를 양 끝점의 목록에 한
번씩 적습니다. 그리고 `inTree` 를 모두 거짓으로 두고, 우선순위 큐에 정점 0 을 키 0 짜리 항목으로 넣어요.

<!--proof:stageStart-->

| 정점 x | adj[x] — 이웃(가중치) | inTree[x] |
| --- | --- | --- |
| 0 | 1(1) 3(4) 5(7) | 거짓 |
| 1 | 0(1) 2(3) | 거짓 |
| 2 | 1(3) 3(2) | 거짓 |
| 3 | 0(4) 2(2) 4(6) | 거짓 |
| 4 | 3(6) 5(5) | 거짓 |
| 5 | 0(7) 4(5) | 거짓 |

이웃 목록의 칸은 모두 14 개로 간선 수 7 의 두 배이고, 우선순위 큐에는 항목 0(0) 하나가 들어 있습니다.

<!--/proof-->

시작 항목의 키가 0 인 것에는 뜻이 있습니다. 이 키는 꺼낼 때 `total` 에 그대로 더해지는데, 첫 정점은 어떤 간선으로도
트리에 들어오지 않았으니 더할 값이 0 이에요.

#### 2단계 — 키가 가장 작은 항목 꺼내기

우선순위 큐에서 키가 가장 작은 항목 `u(w)` 를 꺼냅니다. 갈래는 둘이에요. `u` 가 아직 트리 밖이면 `inTree[u]` 를
참으로 바꾸고 `total` 에 `w` 를 더하고 `joined` 를 하나 올립니다. `u` 가 이미 트리 안이면 그 항목은 **지나간
후보**라 버려요. 지나간 후보는 `u` 가 다른, 더 가벼운 간선으로 먼저 트리에 들어가는 바람에 쓸모가 없어진
항목입니다. 전개 입력의 꺼내기 일곱 번을 전부 적으면 이렇습니다.

<!--proof:stagePop-->

| 걸음 | 꺼낸 항목 | inTree[u] | 판정 | 그 뒤 total | 그 뒤 joined |
| --- | --- | --- | --- | ---: | ---: |
| T2 | 0(0) | 거짓 | 트리에 넣는다 | 0 | 1 |
| T3 | 1(1) | 거짓 | 트리에 넣는다 | 1 | 2 |
| T4 | 2(3) | 거짓 | 트리에 넣는다 | 4 | 3 |
| T5 | 3(2) | 거짓 | 트리에 넣는다 | 6 | 4 |
| T6 | 3(4) | 참 | 지나간 후보 — 버린다 | 6 | 4 |
| T7 | 4(6) | 거짓 | 트리에 넣는다 | 12 | 5 |
| T8 | 5(5) | 거짓 | 트리에 넣는다 | 17 | 6 |

꺼낸 항목 7 개 가운데 트리에 넣은 것이 6 개, 버린 것이 1 개이고, 꺼내지 않은 채 남은 항목은 5(7) 입니다.

<!--/proof-->

T6 이 버린 항목 `3(4)` 는 간선 `(0,3)=4` 가 T2 에 넣은 것입니다. 정점 3 은 T5 에서 더 가벼운 `(2,3)=2` 로 이미
들어갔어요. 앞에서 본 대로 T5 가 정점 3 을 넣는 순간 `(0,3)=4` 는 경계 간선이 아니게 됐는데, 큐는 그 항목을
지우지 않았습니다. 이진 힙에서 가운데 있는 항목을 찾아 지우려면 따로 자리 표가 있어야 해서, 이 글은 지우지 않고
꺼내는 자리에서 거릅니다.

| 꺼낸 정점 `u` | 뜻 | 하는 일 |
| --- | --- | --- |
| `inTree[u]` 가 거짓 | 이 항목이 경계 간선 중 가장 가벼운 것이다 | 트리에 넣고 `total` 에 키를 더한다 |
| `inTree[u]` 가 참 | 트리가 커지며 경계 간선이 아니게 된 항목이다 | 이웃을 안 보고 버린다 |

#### 3단계 — 새로 넣은 정점의 트리 밖 이웃을 후보로 넣기

2단계가 정점 `u` 를 넣었으면 `adj[u]` 를 읽으며 이웃마다 봅니다. 이웃 `v` 가 트리 밖이면 항목 `v(가중치)` 를 넣고,
트리 안이면 넣지 않아요. 넣는 키가 **간선 하나의 가중치**라는 것을 봐 주세요. 이 절차가 재는 것은 「시작 정점에서
여기까지의 거리」가 아니라 「그 정점을 트리에 붙이는 데 드는 값」입니다. 걸음마다 넣은 항목과, 걸음이 끝난 뒤 큐를
꺼낼 차례대로 적었습니다.

<!--proof:stagePush-->

| 걸음 | 넣은 항목 | 걸음이 끝난 뒤 큐 — 꺼낼 차례 | 그중 지나간 후보 |
| --- | --- | --- | --- |
| T1 | 0(0) | 0(0) | 없음 |
| T2 | 1(1) 3(4) 5(7) | 1(1) 3(4) 5(7) | 없음 |
| T3 | 2(3) | 2(3) 3(4) 5(7) | 없음 |
| T4 | 3(2) | 3(2) 3(4) 5(7) | 없음 |
| T5 | 4(6) | 3(4) 4(6) 5(7) | 3(4) |
| T6 | 없음 | 4(6) 5(7) | 없음 |
| T7 | 5(5) | 5(5) 5(7) | 없음 |
| T8 | 없음 | 5(7) | 5(7) |

넣은 항목은 모두 8 개이고 간선은 7 개입니다. 큐에 한 번에 담긴 항목은 가장 많을 때 3 개였습니다.

<!--/proof-->

T4 에서 정점 3 짜리 항목이 둘이 됩니다. 키 4 는 T2 가 간선 `(0,3)` 으로, 키 2 는 T4 가 간선 `(2,3)` 으로 넣은
것이에요. 가장 불안한 순간인 T5 직후를 그렸습니다. 큐 맨 앞이 지나간 후보이고, 대시 테로 흐리게 그렸어요.

<!--fig:build-queue-->
![T5 뒤 — 큐 맨 앞이 지나간 후보](./figs/build-queue.svg)

그렇다면 큐가 정말 경계 간선을 들고 있는 걸까요? 걸음마다 큐에서 지나간 후보를 걷어 낸 항목이 온 간선과, 정의대로
간선 목록에서 센 경계 간선을 맞대었습니다.

<!--proof:queueVsCut-->

| 걸음 | 지나간 후보를 뺀 큐 항목이 온 간선 | 정의에서 센 경계 간선 | 대조 |
| --- | --- | --- | --- |
| T2 | (0,1)=1 · (0,3)=4 · (0,5)=7 | (0,1)=1 · (0,3)=4 · (0,5)=7 | 일치 |
| T3 | (0,3)=4 · (0,5)=7 · (1,2)=3 | (0,3)=4 · (0,5)=7 · (1,2)=3 | 일치 |
| T4 | (0,3)=4 · (0,5)=7 · (2,3)=2 | (0,3)=4 · (0,5)=7 · (2,3)=2 | 일치 |
| T5 | (0,5)=7 · (3,4)=6 | (0,5)=7 · (3,4)=6 | 일치 |
| T6 | (0,5)=7 · (3,4)=6 | (0,5)=7 · (3,4)=6 | 일치 |
| T7 | (0,5)=7 · (4,5)=5 | (0,5)=7 · (4,5)=5 | 일치 |

정점을 다 채우기 전의 반복 걸음 6 개 가운데 두 목록이 일치한 걸음이 6 개입니다.

<!--/proof-->

**지나간 후보를 빼면 큐가 곧 경계 간선입니다.** 그래서 큐 맨 앞이 지나간 후보가 아닐 때, 그 항목이 온 간선이
경계 간선 중 가장 가벼운 것이에요. 이것이 이 방법의 핵심 성질이고, 어떤 그래프에서도 그렇다는 논증은 파트 2 의
「수식 정의와 유도」가 합니다. 반복이 끝나는 근거도 여기서 나와요. 간선 `(u,v)` 가 항목이 되는 것은 두 끝점 중
**먼저** 트리에 든 쪽의 걸음뿐입니다. 나중 걸음에서는 상대가 이미 트리 안이라 넣지 않으니, 넣는 항목은 간선 수에
시작 항목 하나를 더한 것을 넘지 않고, 꺼낼 때마다 하나씩 주므로 큐는 언젠가 빕니다.

#### 4단계 — 트리에 넣은 정점 수로 끝내기

정점 `V` 개를 다 넣으면 트리가 완성된 것이라 큐에 남은 항목을 볼 필요가 없어요. 그래서 2단계에서 정점을 넣은
직후 `joined === n` 이면 그 자리에서 `total` 을 돌려줍니다. 반대로 큐가 비었는데 `joined` 가 `V` 보다 작으면, 시작
정점의 덩어리에서 나머지 정점으로 가는 간선이 없는 것이라 `-1` 을 돌려줘요. 전개 입력과, 둘씩만 이어진 정점
넷에서 걸음마다 쟀습니다.

<!--proof:stageStop-->

| 입력 | 걸음 | joined | 그 뒤 큐 항목 수 | 그 뒤 |
| --- | --- | ---: | ---: | --- |
| 전개 입력 | T2 | 1 | 3 | 다음 항목 |
| 전개 입력 | T3 | 2 | 3 | 다음 항목 |
| 전개 입력 | T4 | 3 | 3 | 다음 항목 |
| 전개 입력 | T5 | 4 | 3 | 다음 항목 |
| 전개 입력 | T6 | 4 | 2 | 다음 항목 |
| 전개 입력 | T7 | 5 | 2 | 다음 항목 |
| 전개 입력 | T8 | 6 | 1 | joined === n — total 을 돌려준다 |
| 둘씩 이어진 정점 넷 | T2 | 1 | 1 | 다음 항목 |
| 둘씩 이어진 정점 넷 | T3 | 2 | 0 | 큐가 비었다 — joined < n 이라 -1 |

전개 입력은 joined 이 6 이 된 T8 에서 17 을 돌려주고, 둘씩 이어진 정점 넷은 큐가 빌 때 joined 이 2 라 -1 을 돌려줍니다.

<!--/proof-->

큐가 비었다는 것은 시작 정점의 덩어리를 다 넣었다는 뜻입니다. 3단계는 트리 안 정점의 이웃만 넣으니, 덩어리 밖
정점에 이르는 항목은 애초에 큐에 들어올 수 없어요. 그래서 `joined` 하나로 연결 여부가 함께 판정됩니다.

| 조건 | 뜻 | 반환 |
| --- | --- | --- |
| 정점을 넣은 직후 `joined === n` | 모든 정점이 트리에 들어왔다 | 그 자리에서 `total` |
| 큐가 비었고 `joined < n` | 시작 정점의 덩어리가 그래프 전체가 아니다 | `-1` |
| `V = 1` | 시작 항목 하나를 꺼내면 곧바로 `joined === n` | `0` |

#### 이 방법이 기대는 전제

경계 간선을 우선순위 큐에 담아 꺼내기는 아래 세 전제에 기댑니다. 하나라도 빠지면 답이 틀리고, 셋 다 코드 한
줄이 지킵니다. 그 줄을 바꾸면 무엇이 나오는지는 「수행으로 알아보는 알고리즘」의 짚고 가기 둘과 「불변식」의
깨뜨려 보기가 실행 결과로 보여 줍니다.

| 전제 | 지키는 줄 | 없을 때 |
| --- | --- | --- |
| 큐의 키는 간선 하나의 가중치다 | `pq.push(v, ew)` | 꺼낸 최소가 경계 간선의 최소가 아니게 되어 다른 트리가 나온다 |
| 꺼낸 정점이 이미 트리 안이면 버린다 | `if (inTree[u] === true) continue;` | 같은 정점을 두 번 세어 정점이 덜 찬 채 끝난다 |
| 끝에 정점 수를 확인한다 | `joined === n ? total : -1` | 이어지지 않은 그래프에 덩어리 하나의 합을 답한다 |

#### 우선순위 큐를 이진 힙으로 만드는 까닭

남은 것은 우선순위 큐를 **무엇으로 만드느냐**입니다. 가장 먼저 떠오르는 것은 항목을 키 오름차순으로 늘어놓은
배열이에요. 가장 작은 것이 늘 맨 앞이라 꺼내기가 한 번이지만, 넣을 때 자리를 찾아 뒤쪽 항목을 한 칸씩 옮겨야
합니다. 이진 힙은 「부모의 키가 자식 이하」 하나만 지키고, 넣기와 꺼내기가 각각 트리 높이만큼의 비교로 끝나요.
두 방식을 같은 입력에서 쟀습니다.

<!--proof:storeSorted-->

| 입력 | V | E | 정렬 배열로 만든 우선순위 큐 | 그중 뒤로 옮긴 칸 | 이진 힙으로 만든 우선순위 큐 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전개 입력 | 6 | 7 | 72 | 6 | 63 |
| 한 줄로 이은 200 정점 | 200 | 199 | 1,395 | 0 | 1,195 |
| 별 모양 200 정점 | 200 | 199 | 38,302 | 8,505 | 6,070 |
| 완전 그래프 100 정점 | 100 | 4,950 | 12,611,218 | 6,045,354 | 46,389 |

두 방식 모두 네 입력에서 정본과 같은 합계를 냈습니다.

<!--/proof-->

**뒤로 옮긴 칸을 보세요.** 한 줄로 이은 그래프에서는 0 칸인데 — 큐에 항목이 한 번에 하나뿐이라 옮길 것이 없어요 —
완전 그래프 100 정점에서는 6,045,354 칸이고, 그것이 정렬 배열의 12,611,218 번 중 절반쯤입니다. 정렬 배열은 「전부
정렬돼 있다」를 지키느라 넣기가 항목 수에 비례하고, 우선순위 큐에는 그런 요구가 없습니다.

| 우선순위 큐를 만드는 방법 | 꺼낼 때 | 넣을 때 |
| --- | --- | --- |
| 정렬 배열 | 맨 앞 하나 | 뒤쪽 항목을 한 칸씩 옮긴다 |
| 이진 힙 | 트리 높이만큼 비교한다 | 트리 높이만큼 비교한다 |

다만 「아이디어를 떠올리는 과정」에서 본 것처럼, 촘촘한 그래프에서는 트리 밖 정점마다 가장 가벼운 간선 하나를
배열에 적어 두는 방식이 이진 힙보다 적게 일했습니다. 그 차이가 규모에 따라 어떻게 되는지 한 줄 그래프와 완전
그래프에서 정점 수를 올려 가며 쟀어요.

<!--proof:storeChoice-->

| 입력 | E | 정점마다 가장 가벼운 간선 하나 | 이진 힙으로 만든 우선순위 큐 | 적은 쪽 |
| --- | ---: | ---: | ---: | --- |
| 한 줄로 이었다 V=50 | 49 | 5,295 | 295 | 이진 힙 |
| 완전 그래프다 V=50 | 1,225 | 10,179 | 12,579 | 정점마다 하나 |
| 한 줄로 이었다 V=200 | 199 | 81,195 | 1,195 | 이진 힙 |
| 완전 그래프다 V=200 | 19,900 | 160,955 | 173,889 | 정점마다 하나 |
| 한 줄로 이었다 V=400 | 399 | 322,395 | 2,395 | 이진 힙 |
| 완전 그래프다 V=400 | 79,800 | 642,203 | 688,750 | 정점마다 하나 |

<!--/proof-->

**성긴 그래프에서는 이진 힙이 두 자릿수 배로 적고, 촘촘한 그래프에서는 배열 쪽이 조금 적습니다.** 정점 400 개를
한 줄로 이은 그래프에서 322,395 대 2,395 이고, 정점 400 개짜리 완전 그래프에서 642,203 대 688,750 이에요. 이
과제의 입력은 간선 목록이고 간선 수가 정점 한 개의 이웃 몇 개 수준인 성긴 그래프부터 완전 그래프까지 다 올 수
있습니다. 성긴 쪽에서 잃는 폭이 촘촘한 쪽에서 잃는 폭보다 훨씬 커서 이진 힙을 씁니다.

| 입력 | 적게 일하는 쪽 | 까닭 |
| --- | --- | --- |
| 간선이 정점 수와 비슷하다 | 이진 힙 | 배열 쪽은 걸음마다 정점을 전부 본다 |
| 간선이 정점 수의 제곱에 가깝다 | 정점마다 가장 가벼운 간선 하나 | 이진 힙은 항목이 간선 수만큼 쌓여 꺼낼 때마다 `log` 가 붙는다 |

#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 다섯 걸음이 됩니다. 셋째와 넷째가 반복 한 바퀴예요. 걸음마다 간선 목록 전부를
다시 읽던 일이 간선마다 항목 하나를 넣고 꺼내는 일로 줄어요.

1. 간선 목록을 이웃 목록 `adj` 로 바꾸고, `inTree` 를 거짓으로 채우고, 큐에 `0(0)` 을 넣는다(1단계)
2. 큐가 빌 때까지 키가 가장 작은 항목 `u(w)` 를 꺼낸다(2단계)
3. `u` 가 트리 안이면 버리고 2 로 돌아가고, 밖이면 트리에 넣고 `total` 에 `w` 를 더한다(2단계)
4. `joined` 가 `V` 면 `total` 을 돌려주고, 아니면 `u` 의 트리 밖 이웃 `v` 마다 `v(가중치)` 를 넣는다(3 · 4단계)
5. 큐가 비면 `joined` 가 `V` 인지 보고, 아니면 `-1` 을 돌려준다(4단계)

### 수행으로 알아보는 알고리즘 — 여섯 정점을 여덟 걸음으로 잇는다

아이디어를 확인했으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 정해 끝까지 가져가되, 코드 조각을
하나 만들 때마다 그 조각만 실행한 결과를 확인하고 다음으로 넘어갑니다.

```ts
const n = 6;
const edges: [number, number, number][] = [
  [0, 1, 1], [0, 3, 4], [0, 5, 7], [1, 2, 3], [2, 3, 2], [3, 4, 6], [4, 5, 5],
];
// 이 절이 끝나면 17 이 나와야 한다
```

왜 이 입력을 골랐을까요? 갈래를 한 입력에서 되도록 많이 실행하려는 것입니다. 정점 3 이 **간선 둘로 두 번 후보에
오르고**(가중치 4 와 2) 그중 무거운 쪽이 **지나간 후보로 버려지는 갈래**가 실행되며, 마지막 정점을 넣는 순간 큐에
항목이 남은 채로 **정점 수로 끝내는 갈래**가 실행돼요. 그리고 이 그래프는 [`kruskalMst` 가이드](../kruskalMst/kruskalMst-guide.md)가
쓰는 것과 같은 그래프라, 두 절차가 같은 다섯 간선을 다른 차례로 고르는 것을 같은 값으로 대조할 수 있습니다. 큐가
비어 `-1` 로 끝나는 갈래만 이 입력에서 안 나와서, 그것은 짚고 가기에서 따로 봅니다.

```text
절차 전체를 한 장으로

  T1       간선 목록을 이웃 목록 adj 로 바꾼다
           inTree[x] = false, total = 0, joined = 0 으로 둔다
           항목 0(0) 을 큐에 넣는다                               ① 시작값
  T2~T8    큐에 항목이 남아 있는 동안:                            ② 반복 조건
             키가 가장 작은 항목 u(w) 를 꺼낸다
             u 가 이미 트리 안이면 버린다                         ③ 지나간 후보
             아니면 u 를 트리에 넣고 total 에 w 를 더한다
             joined 가 n 이면 total 을 반환한다                   ⑤ 다 찼다
             u 의 이웃 중 트리 밖인 것을 후보로 넣는다            ④ 후보 넣기
           (큐가 비면) joined 가 n 이면 total, 아니면 -1           ⑥ 못 채웠다
```

#### 1. 간선 목록을 이웃 목록으로 바꾸고 시작 항목을 넣는다

「아이디어 상세」의 1단계를 코드로 옮깁니다. 간선 하나를 양쪽 끝점의 목록에 한 번씩 적고, 정점 0 을 키 0 짜리
항목으로 큐에 넣어요.

```ts
const adj: [number, number][][] = Array.from({ length: n }, () => []);
for (const [u, v, w] of edges) {
  (adj[u] as [number, number][]).push([v, w]);
  (adj[v] as [number, number][]).push([u, w]);
}

const inTree: boolean[] = Array.from({ length: n }, () => false);
const pq = new MinHeap();
pq.push(0, 0);                    // ① 트리의 첫 정점은 값을 치르지 않는다
```

`T1` 에서 이 조각만 실행하면 이렇게 나옵니다.

간선 일곱 개가 이웃 목록에 두 번씩 적혔어요. 큐 항목을 이웃 목록과 같은 `정점(키)` 꼴로 적는 까닭이 여기 있습니다.
3단계가 넣는 것이 이웃 목록의 그 칸이기 때문이에요.

#### 짚고 가기 — 시작 정점을 0 으로 고정하면 답이 달라질 것 같다

여기서 헷갈리기 쉬운 포인트는 시작 정점입니다. 이 절차는 매 걸음 「지금 트리에서 가장 가까운 정점」을 고르니,
어디서 시작하느냐에 따라 고르는 간선이 달라지고 합계도 달라질 것처럼 읽혀요. 그 생각대로 시작 정점만 바꿔 여섯
판을 실행해 봅시다.

```ts
pq.push(3, 0);   // ← 시작 정점만 3 으로 바꿨다
```

**답은 한 판도 안 바뀝니다.** 고른 간선의 모임까지 여섯 판이 같고 차례만 달라요. 시작 정점 4 에서 시작한 판은
`(4,5)=5` 를 가장 먼저 고르는데, 그 간선은 정점 0 에서 시작한 판이 마지막에 고른 것입니다. 합계가 안 달라지는 것은
이 입력의 우연이 아니에요. 어느 정점에서 시작하든 넣은 간선이 언제나 어떤 최소 신장 트리 안에 있다는 것을 파트 2 의
불변식이 논증으로 보이고, 그 논증은 시작 정점이 무엇인지 쓰지 않습니다. 시작 정점을 인자로 받지 않고 0 으로
고정해 둔 것은 그래서예요. 간선의 모임까지 같은 것은 따로 까닭이 있습니다. 이 그래프는 가중치가 전부 달라서 최소
신장 트리가 하나뿐이에요. 가중치가 같은 간선이 있으면 시작 정점마다 다른 간선 모임이 나올 수 있고, 그때도 합계는
같습니다.

#### 2. 키가 가장 작은 항목을 내주는 이진 힙을 만든다

둘째 조각은 우선순위 큐입니다. 배열 하나로 완전 이진 트리를 담고, 자리 `i` 의 부모를 `(i-1)/2` 의 몫으로 둬요.
넣을 때는 맨 끝에 두고 부모보다 작은 동안 부모와 맞바꿔 올립니다.

```ts
push(node: number, key: number): void {
  this.items.push([node, key]);
  let i = this.items.length - 1;
  while (i > 0) {
    const parent = (i - 1) >> 1;
    if (this.key(i) >= this.key(parent)) break;   // 부모가 더 작거나 같으면 자리를 지킨다
    this.swap(i, parent);
    i = parent;
  }
}
```

꺼낼 때는 뿌리를 내주고, 마지막 항목을 뿌리로 옮긴 뒤 자식 중 작은 쪽보다 크면 맞바꿔 내립니다. T2 가 넣는 항목
셋으로 실행하면 배열이 이렇게 바뀌어요.

<!--proof:walkHeap-->

```text
T2 가 넣는 항목 1(1) · 3(4) · 5(7) — 배열에 놓인 순서 그대로
  넣기 전          []
  1(1) 을 넣은 뒤  [1(1)]
  3(4) 을 넣은 뒤  [1(1) 3(4)]
  5(7) 을 넣은 뒤  [1(1) 3(4) 5(7)]
  한 번 꺼낸 뒤    [3(4) 5(7)]  꺼낸 항목 1(1)

꺼낸 뒤 부모의 키가 자식 이하인 자리 1 / 1
```

배열이 정렬돼 있지 않아도 뿌리는 늘 키가 가장 작습니다. 이 자료구조가 지키는 것은 「부모의 키가 자식 이하」
하나뿐이고, 그 하나만으로 뿌리가 가장 작다는 것이 나와요. 그래서 이 글의 그림들은 우선순위 큐를 배열 순서가
아니라 **꺼낼 차례대로** 늘어놓습니다 — 알아야 할 것은 다음에 무엇이 나오는가이지 배열 안의 자리가 아니기
때문이에요.

#### 3. 꺼낸 정점을 트리에 넣고 트리 밖 이웃을 후보로 넣는다

셋째 조각이 본체입니다. 큐에서 항목을 꺼내고, 이미 트리에 있는 정점이면 버리고, 아니면 트리에 넣은 뒤 그 정점의
이웃 중 트리 밖인 것을 후보로 넣어요.

```ts
while (pq.size() > 0) {                       // ② 큐에 후보가 남아 있는가
  const [u, w] = pq.pop() as [number, number];
  if (inTree[u] === true) continue;           // ③ 지나간 후보면 버린다

  inTree[u] = true;
  total += w;
  joined++;
  if (joined === n) return total;             // ⑤ 정점을 다 넣었다

  for (const [v, ew] of adj[u] as [number, number][]) {
    if (inTree[v] !== true) pq.push(v, ew);   // ④ 트리 밖 정점만 후보로 넣는다
  }
}
```

여기서 가장 중요한 줄은 `④` 입니다. 넣는 키가 꺼낸 항목의 키 `w` 를 더한 값이 아니라 **간선 하나의 가중치 `ew`**
예요. `T3` 과 `T4` 만 실행하면 이렇게 나옵니다.

<!--proof:walkT3T4-->

```text
T3  꺼낸 항목 1(1)  트리 밖이다 -> 넣는다. total = 0 + 1 = 1
    이웃 0(1)       이미 트리 안이라 안 넣는다
    이웃 2(3)       트리 밖이라 항목 2(3) 을 넣는다
    큐 — 꺼낼 차례  2(3) 3(4) 5(7)
T4  꺼낸 항목 2(3)  트리 밖이다 -> 넣는다. total = 1 + 3 = 4
    이웃 1(3)       이미 트리 안이라 안 넣는다
    이웃 3(2)       트리 밖이라 항목 3(2) 을 넣는다
    큐 — 꺼낼 차례  3(2) 3(4) 5(7)

T4 가 끝난 뒤 정점 3 짜리 항목 2 개 — 3(2) · 3(4)
```

두 항목 모두 지울 수 없습니다. 어느 쪽이 쓸모없어질지는 정점 3 이 어느 간선으로 먼저 들어가느냐가 정하고, 그것은
꺼내 봐야 알아요.

#### 짚고 가기 — 트리 밖 정점만 넣으니 꺼낼 때 다시 볼 필요가 없을 것 같다

여기서 헷갈리기 쉬운 포인트는 `③` 한 줄입니다. `④` 가 이미 트리 밖 정점만 후보로 넣으니, 큐에서 꺼낸 항목은
언제나 트리 밖 정점을 가리킬 것 같고 `③` 은 없어도 되는 줄처럼 읽혀요. 그 생각대로 `③` 을 지워 봅시다.

삼각형과 사각형은 지나간 후보를 꺼내기 전에 정점이 다 차서 `③` 이 한 번도 실행되지 않고, 이어지지 않은 그래프는
어느 판이든 `joined` 를 못 채워 `-1` 이에요. **이 입력들만 시험하면 `③` 을 지워 놓고도 통과합니다.**

#### 4. 여덟 걸음을 처음부터 끝까지 실행한다

세 조각을 이어 고정 입력에 실행하면 여덟 걸음이 나옵니다. T1 이 준비, T2 부터 T8 까지가 큐에서 항목을 하나씩 꺼내는
반복이에요. 걸음 재생 패널에서 정점 안의 「트리 · 키」는 트리에 넣을 때 치른 값, 「후보 · 키」는 그 정점짜리
항목 중 가장 작은 키이고, 점선 정점은 아직 항목이 없는 정점입니다. 굵은 간선이 트리에 넣은 간선, 대시 간선이
지나간 후보로 버린 간선, 테가 트리 안 정점이에요. 무대 아래 두 줄이 우선순위 큐를 꺼낼 차례대로 늘어놓은 것이고,

다음이 `(2,3)=2` 이고, 이쪽은 트리에 붙일 수 있는 것만 보므로 `(0,1)=1` 다음이 `(1,2)=3` 입니다.

마지막 줄의 개수 검사는 없어도 되는 줄처럼 읽혀요. 그 생각대로 마지막 줄을 합계만 돌려주게 바꾸어 봅시다.

| T1 | - | 큐에 0(0) | 0 | 0 | 0(0) |
| T2 | 0(0) | 정점을 넣는다 · 후보 1(3) | 1 | 0 | 1(3) |
| T3 | 1(3) | 정점을 넣는다 · 넣을 후보 없음 | 2 | 3 | 비어 있음 |

큐가 빈 뒤 joined 은 2, n 은 4 입니다. 정본은 -1 을, 개수를 안 보는 판은 3 을 돌려줍니다.

<!--/proof-->

바꾼 판이 돌려준 값은 시작 정점이 속한 덩어리 하나의 가중치 합이라 트리의 합이 아닙니다. **개수 검사는 연결 여부
검사예요.** 4단계에서 본 대로 큐가 비었다는 것은 시작 정점의 덩어리를 다 넣었다는 뜻이니, `joined === n` 한 줄이
덩어리를 따로 세는 일을 대신합니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞에서 안 나온 것은 마지막 줄 하나예요. 반복이 끝난 뒤 `joined` 가 `n` 인지 보고, 아니면
`-1` 을 돌려줍니다.

```ts
export type Edge = [number, number, number];

export function primMst(n: number, edges: Edge[]): number {
  // 간선 목록을 이웃 목록으로 바꾼다. 무방향이라 양쪽에 적는다.
  const adj: [number, number][][] = Array.from({ length: n }, () => []);
  for (const [u, v, w] of edges) {
    (adj[u] as [number, number][]).push([v, w]);
    (adj[v] as [number, number][]).push([u, w]);
  }

  // 트리에 이미 들어간 정점 표시. 처음에는 아무도 안 들어가 있다.
  const inTree: boolean[] = Array.from({ length: n }, () => false);
  const pq = new MinHeap();

  // ① 시작값 — 정점 0 을 비용 0 으로 넣는다. 트리의 첫 정점은 값을 치르지 않는다.
  pq.push(0, 0);

  let total = 0;
  let joined = 0;

  // ② 큐에 후보가 남아 있는가 — 없으면 더 넣을 정점이 없다.
  while (pq.size() > 0) {
    const [u, w] = pq.pop() as [number, number];

    // ③ 이미 트리에 든 정점이면 이 항목은 지나간 후보다. 버린다.
    if (inTree[u] === true) continue;

    inTree[u] = true;
    total += w;
    joined++;

    // ⑤ 정점을 다 넣었으면 큐에 남은 후보는 볼 필요가 없다.
    if (joined === n) return total;

    for (const [v, ew] of adj[u] as [number, number][]) {
      // ④ 트리 밖 정점만 후보로 넣는다. 트리 안끼리 잇는 간선은 후보가 아니다.
      if (inTree[v] !== true) pq.push(v, ew);
    }
  }

  // ⑥ 큐가 비었는데 정점을 다 못 넣었으면 시작 정점의 덩어리가 전부가 아니다.
  return joined === n ? total : -1;
}

class MinHeap {
  private items: [number, number][] = [];

  size(): number {
    return this.items.length;
  }

  push(node: number, key: number): void {
    this.items.push([node, key]);
    let i = this.items.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.key(i) >= this.key(parent)) break;
      this.swap(i, parent);
      i = parent;
    }
  }

  pop(): [number, number] | undefined {
    const top = this.items[0];
    const last = this.items.pop();
    if (top === undefined || last === undefined) return undefined;
    if (this.items.length > 0) {
      this.items[0] = last;
      let i = 0;
      for (;;) {
        const left = 2 * i + 1;
        const right = 2 * i + 2;
        let small = i;
        if (left < this.items.length && this.key(left) < this.key(small)) {
          small = left;
        }
        if (right < this.items.length && this.key(right) < this.key(small)) {
          small = right;
        }
        if (small === i) break;
        this.swap(i, small);
        i = small;
      }
    }
    return top;
  }

  private key(i: number): number {
    return (this.items[i] as [number, number])[1];
  }

  private swap(a: number, b: number): void {
    const t = this.items[a] as [number, number];
    this.items[a] = this.items[b] as [number, number];
    this.items[b] = t;
  }
}
```

primMst(3, [[0,1,1],[1,2,2],[0,2,3]])                                  -> 3

**자기 자신을 잇는 간선과 평행 간선을 거르는 줄이 없다는 것을 봐 주세요.** 둘 다 이미 있는 갈래가 처리합니다.

| 입력 | `adj` 에 적히는 모양 | 처리하는 갈래 |
| --- | --- | --- |
| 자기 자신을 잇는 간선 `[v, v, w]` | `adj[v]` 에 `v` 가 두 번 | `v` 를 트리에 넣은 뒤에야 그 목록을 보므로 `④` 의 조건이 거짓이다 |
| 평행 간선 `[u, v, w1]` · `[u, v, w2]` | 둘 다 후보가 된다 | 가벼운 쪽이 먼저 나오고 무거운 쪽은 `③` 이 버린다 |

### 알아 두면 좋은 개념 — 최적 우선 탐색

지금까지 한 일을 한 문장으로 적으면 「이미 확정한 정점의 모임에 붙어 있는 후보를 저장소에 담아 두고, 규칙 하나로
그중 하나를 꺼내 확정하기를 되풀이한다」입니다. 저장소가 우선순위 큐이고 규칙이 「키가 가장 작은 것」일 때 이
틀을 **최적 우선 탐색(best-first search)** 이라고 부릅니다. 이 편이 특별한 것은 틀이 아니라 **키에 무엇을
넣는가** 하나예요. 저장소와 꺼내는 규칙을 나란히 놓으면 이렇습니다.

| 절차 | 저장소 | 꺼내는 규칙 | 항목에 딸린 키 |
| --- | --- | --- | --- |
| 너비 우선 탐색 | 큐(먼저 넣은 것부터) | 가장 먼저 넣은 것 | 없다 — 꺼내는 차례가 곧 층 번호다 |
| 깊이 우선 탐색 | 스택(나중에 넣은 것부터) | 가장 나중에 넣은 것 | 없다 — 꺼내는 차례가 곧 방문 차례다 |
| 다익스트라 | 우선순위 큐 | 키가 가장 작은 것 | 시작 정점부터 그 정점까지의 거리 |
| 프림 | 우선순위 큐 | 키가 가장 작은 것 | 그 정점을 트리에 붙이는 간선 하나의 가중치 |

아래 두 줄이 갈리는 자리는 큐에 넣는 키 한 줄뿐입니다. 다익스트라는 꺼낸 항목의 키에 간선 가중치를 더한 값을 넣고,
프림은 간선 가중치만 넣어요.

```ts
pq.push(v, w + ew);   // 다익스트라 — 시작 정점부터 v 까지의 길이
pq.push(v, ew);       // 프림 — v 를 트리에 붙이는 값 하나
```

한 줄이 다르면 만드는 나무도 다릅니다. 전개 입력에서 두 나무가 어떻게 갈리는지는 파트 2 의 불변식이 이 줄을 바꿔
값으로 냅니다. Boost Graph Library 가 이 관계를 코드로 그대로 적어 두었어요. 공식 문서가 프림 구현을 *"The
implementation is simply a call to dijkstra_shortest_paths() with the appropriate choice of comparison and combine
functors."* 라고 적습니다. 같은 이름이 [`aStarSearch`](../../shortest-path/aStarSearch/aStarSearch-guide.md) 편에도
나와요. 그쪽은 키를 「지금까지의 비용 + 남은 비용의 추정」으로 바꾼 자리입니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 절차를 따져 봅니다. 어떤 과제에 이것을 쓰는지, 큐가 왜 경계 간선의 최소를 내주는지, 무엇이 매
걸음 참으로 남는지, 그리고 연산이 몇 번인지를 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **모든 정점을 잇는 최소 비용을 묻습니다.** 두 정점 사이의 최단 거리가 아니라 전체 가중치 합이 목표일 때예요.
  두 목표는 답이 다릅니다.
- **간선이 정점 수의 제곱보다 훨씬 적습니다.** 비용이 `E log E` 에 지배되므로 `E` 가 작을수록 유리해요. 도로망 ·
  전력망 · 통신망처럼 정점 하나가 이웃 몇 개하고만 이어진 그래프가 그 모양입니다.
- **그래프가 이어져 있는지 미리 몰라도 됩니다.** 큐가 비었을 때 `joined` 가 `V` 에 못 미치는 것으로 판정이 같이
  나오니, 연결 성분을 따로 세는 절차를 앞에 둘 필요가 없어요.
- **이웃을 그때그때 물어볼 수 있으면 됩니다.** 이 절차는 트리에 넣은 정점의 이웃만 보고 간선 전체를 줄 세우지
  않으므로, 이웃 목록을 필요할 때 만들어 주는 입력에도 그대로 씁니다.

| 조건 | 코드에 나타나는 모양 |
| --- | --- |
| 전체 가중치 합 | `total += w` 가 간선 하나의 가중치만 더한다 |
| 성긴 그래프 | 가장 큰 항이 항목을 넣고 꺼내는 `E log E` 다 |
| 연결 여부를 모른다 | 끝 줄의 `joined === n ? total : -1` 이 판정한다 |
| 이웃을 물어본다 | 반복이 읽는 것은 `adj[u]` 하나뿐이다 |

이 절차가 잘 안 맞는 모양도 있습니다. 셋째 줄을 특히 잘못 읽기 쉬워요.

| 모양 | 까닭 |
| --- | --- |
| 간선이 정점 수의 제곱에 가깝다 | 항목이 간선 수만큼 쌓여 꺼낼 때마다 `log` 가 붙는다. 정점마다 가장 가벼운 간선 하나를 배열에 두는 방식이 조금 적다 |
| 간선이 가중치 순으로 정렬돼 주어진다 | 경쟁 설계인 크러스컬의 가장 큰 항(정렬)이 사라진다 |
| 트리가 아니라 두 정점 사이의 길 하나가 필요하다 | 최소 신장 트리 안의 길이 가장 짧은 길은 아니다 |

최소 신장 트리는 **전체 가중치 합**을 가장 작게 하는 구조이지 두 정점 사이의 거리를 가장 작게 하는 구조가 아니에요.
정점 셋짜리 그래프 `(0,1)=2` · `(1,2)=2` · `(0,2)=3` 에서 두 구조를 나란히 놓았습니다.

<!--proof:mstVsPath-->

| 구조 | 담은 간선 | 가중치 합 | 0 에서 2 까지의 길이 |
| --- | --- | ---: | ---: |
| 최소 신장 트리 | (0,1)=2 · (1,2)=2 | 4 | 4 |
| 그래프 전체의 최단 경로 | (0,2)=3 | - | 3 |

최소 신장 트리는 (0,2)=3 을 담지 않아서, 트리 안에서 0 에서 2 로 가는 길이 4 로 가장 짧은 길 3 보다 깁니다.

<!--/proof-->

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 뜻 | 이 절차 |
| --- | --- | --- | --- |
| 지문 | 「모든 지점을 잇되 총비용을 가장 작게」 | 최소 신장 트리의 정의다. 전선 · 수도관 · 도로 부설이 같은 모양이다 | 쓴다 |
| 지문 | 「연결하는 데 필요한 최소 비용, 불가능하면 -1」 | 연결 판정까지 함께 묻는다. 이 절차의 끝 줄과 그대로 맞는다 | 쓴다 |
| 입력 | 이웃 목록 · 인접 행렬 · 「어떤 두 지점 사이에도 길이 있다」 | 정점을 축으로 받는 입력이다. 촘촘하면 우선순위 큐 대신 배열로 후보를 드는 판도 함께 잰다 | 쓴다 |
| 지문 | 「지점을 하나씩 늘려 가며 그때마다 비용」 | 정점을 하나씩 넣는 이 절차의 걸음이 그대로 답이 된다 | 쓴다 |
| 지문 | 「가장 무거운 간선을 가장 작게」 | 최소 병목 신장 트리다 | 단서로만 — 아래 문단 |
| 지문 | 「A 에서 B 까지 가장 짧은 길」 | 최단 경로 과제다. 큐에 넣는 키가 다르다 | 못 쓴다 |

「어떤 두 지점 사이 경로의 가장 무거운 간선이 가장 가볍게」 같은 병목 조건도 최소 신장 트리로 풀린다고 알려져
있습니다. 이 글은 그 사실을 증명하지 않으므로 단서로만 적어 둡니다.

#### 실제로 쓰이는 곳

- **NetworkX** — 파이썬 그래프 라이브러리가 `minimum_spanning_edges` 의 `algorithm` 인자로 프림을 고르게 합니다.
  공식 문서가 *"The algorithm to use when finding a minimum spanning tree. Valid choices are 'kruskal', 'prim', or
  'boruvka'. The default is 'kruskal'."* 라 적고, 소스의 `prim_mst_edges` 는 `from heapq import heappop, heappush` 로
  최소 힙을 가져와 `heappush(frontier, (wt, next(c), u, v, k, d))` 로 넣습니다 — 키의 첫 칸이 간선 가중치 `wt` 라
  이 글의 `④` 와 같은 자리예요.
  ([공식 문서](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.tree.mst.minimum_spanning_edges.html) ·
  [소스](https://networkx.org/documentation/stable/_modules/networkx/algorithms/tree/mst.html), 조회일 2026-09-02)
- **Boost Graph Library** — C++ 그래프 라이브러리가 `prim_minimum_spanning_tree()` 를
  `boost/graph/prim_minimum_spanning_tree.hpp` 에 두고 있고, 문서가 시간 복잡도를 *"The time complexity is O(E log
  V)."* 로 적습니다. 구현에 대해서는 *"The implementation is simply a call to dijkstra_shortest_paths() with the
  appropriate choice of comparison and combine functors."* 라고 적어요.
  ([공식 문서](https://www.boost.org/doc/libs/1_87_0/libs/graph/doc/prim_minimum_spanning_tree.html), 조회일 2026-09-02)
- **JGraphT** — 자바 그래프 라이브러리의 `PrimMinimumSpanningTree` 가 같은 절차를 다른 힙으로 씁니다. 문서가 *"The
  algorithm was developed by Czech mathematician V. Jarník and later independently by computer scientist Robert C.
  Prim and rediscovered by E. Dijkstra. This implementation relies on a Fibonacci heap, and runs in O(|E| +
  |V|log(|V|))."* 라 적어요.
  ([공식 문서](https://jgrapht.org/javadoc/org.jgrapht.core/org/jgrapht/alg/spanning/PrimMinimumSpanningTree.html), 조회일 2026-09-02)

| 출처 | 원문에서 확인한 것 | 이 글과의 관계 |
| --- | --- | --- |
| NetworkX | 프림을 고를 수 있고 소스가 `heapq` 를 쓴다 | 키의 첫 칸이 간선 가중치다 |
| Boost | `O(E log V)` · 다익스트라 호출로 구현했다 | 뼈대가 같다는 것을 코드로 적었다 |
| JGraphT | 피보나치 힙으로 `O(\|E\| + \|V\|log(\|V\|))` | 우선순위 큐를 바꾸면 상한이 내려간다 |

세 문서에서 확인한 것은 위 세 줄뿐이고, 각 라이브러리가 무엇을 더 제공하는지는 확인하지 않았습니다. 셋째 줄을 봐
주세요. 이 글이 쓴 이진 힙 판은 `O(E log E)` 이고, 그 차이는 「후보 하나를 넣는 값」에서 나옵니다.

#### 경쟁 설계와의 대조

경쟁 설계는 **크러스컬(Kruskal)** 입니다. 같은 최소 신장 트리를 만들되 축이 반대예요. 트리에 붙일 수 있는 간선만
보는 대신, 간선 전부를 가중치 오름차순으로 놓고 하나씩 보면서 두 끝점이 서로 다른 덩어리일 때만 고릅니다. 덩어리는
유니온 파인드(정점마다 같은 덩어리의 정점 하나를 가리키는 배열)로 들고 있어요.

| 설계 | 축 | 하는 일 | 비용이 달린 것 |
| --- | --- | --- | --- |
| 프림 | 정점 | 트리에 붙는 후보만 우선순위 큐에 담는다 | 큐에 쌓이는 항목 수 |
| 크러스컬 | 간선 | 간선 전부를 한 번 줄 세우고 유니온 파인드로 판정한다 | 정렬할 간선 수 |

**입력은 전개 입력과 다릅니다.** 두 설계가 갈리는 축이 간선 밀도인데 전개 입력은 정점 6 · 간선 7 이라 밀도를 바꿀
자리가 없어요. 그래서 정점을 200 으로 고정하고 간선 수만 199(한 줄로 이은 최소)에서 19,900(완전 그래프)까지
바꿉니다. 먼저 `0—1—…—199` 를 깔아 연결을 보장하고 남은 자리를 정점 번호 순으로 채우며, 가중치는
`(i × 31 + j × 17) mod 997 + 1` 이라 같은 간선 수면 언제나 같은 그래프예요. 기본 연산은 `tools/bench-alt.ts` 로
세었고, 비교 한 번과 배열 칸을 읽거나 쓴 한 번을 각각 하나로 셉니다. 크러스컬의 정렬은 비교 횟수를 셀 수 있게 병합
정렬로 직접 적었습니다. 간선 수를 199 부터 하나씩 올려 가며 재서 적은 쪽이 바뀌는 자리를 찾았고, 그 자리마다 앞뒤
간선 수를 함께 실었어요.

**적은 쪽이 두 번 바뀝니다.** 간선 280 개까지는 프림이 적고, 281 개부터 4,322 개까지는 크러스컬이 적으며, 4,323
개부터 완전 그래프까지는 다시 프림이 적어요. 갈리는 것은 프림이 우선순위 큐에서 항목을 몇 번 꺼내는가입니다. 넣기는
어느 밀도에서나 간선 수만큼 일어나고 한 번이 대개 비교 한두 번으로 끝나지만(부모보다 크면 그 자리에서 멈춥니다),
꺼내기는 자식 둘을 비교하며 내려가는 일이라 값이 커요. 그 꺼내기 횟수를 세 자리에서 쟀습니다.

| 정점 200 · 간선 수 | 프림이 우선순위 큐에서 꺼낸 항목 | 그때의 프림 기본 연산 |

큐에 한 번에 담긴 항목, 표시 배열을 들고 있어야 하고, 크러스컬은 간선 사본 `3E` 와 배열 둘 `2V` 를 들고 있으면 됩니다.

119,146 대 60,100 으로 갈려요. 연산 수가 두 번 뒤집히는 동안 저장 칸의 순서는 한 번도 안 바뀌므로 **어느 축을
보는지 정해야 답이 나옵니다.**

`kruskalMst` 편의 대조표와 값이 다른 데는 까닭이 있습니다. 그 편은 경쟁 설계로 인접 행렬을 두고 라운드마다
정점을 전수로 보는 프림을 세웠고, 이 편이 가르치는 것은 우선순위 큐를 쓰는 프림이에요. 두 프림은 같은 트리를
만들지만 계수가 달라서, 이 편은 같은 생성식의 그래프를 다시 재서 값을 냈습니다.

### 수식 정의와 유도

트리 안 정점의 모임을 $S$ 라 하고, 나머지를 $\bar S$ 라 합니다. 경계 간선의 모임과 간선 집합의 가중치 합을 다음과
같이 정의합니다.

$$C(S) \;=\; \bigl\{\, (u,v) \in E \;:\; u \in S,\; v \in \bar S \,\bigr\}, \qquad W(T) \;=\; \sum_{e \in T} w(e)$$

| 기호 | 정의 |
| --- | --- |
| $S$ | 트리에 들어간 정점의 모임. 정점을 넣을 때마다 원소가 하나씩 는다 |
| $C(S)$ | 두 끝점 중 **한쪽만** $S$ 안에 있는 간선의 모임 |
| $W(T)$ | 간선 집합 $T$ 의 가중치 합 |
| $Q$ | 큐에 넣은 항목 전부. 항목 하나는 정점 $v$ 와 키 $k$ 의 쌍이고 본문은 $v(k)$ 로 적는다 |

정의를 전개 입력의 걸음마다 적용해 검산합니다. 걸음마다 $C(S)$ 의 간선 수를 간선 목록에서 직접 세고, 큐에 남은
항목과 그중 지나간 후보를 셌어요.

<!--proof:queueItems-->

| 걸음 | 트리 안 정점 S | C(S) 의 간선 수 | 큐에 남은 항목 | 그중 지나간 후보 |
| --- | --- | ---: | ---: | ---: |
| T1 | {} | 0 | 1 | 0 |
| T2 | {0} | 3 | 3 | 0 |
| T3 | {0, 1} | 3 | 3 | 0 |
| T4 | {0, 1, 2} | 3 | 3 | 0 |
| T5 | {0, 1, 2, 3} | 2 | 3 | 1 |
| T6 | {0, 1, 2, 3} | 2 | 2 | 0 |
| T7 | {0, 1, 2, 3, 4} | 2 | 2 | 0 |
| T8 | {0, 1, 2, 3, 4, 5} | 0 | 1 | 1 |

큐에 넣은 항목은 모두 8 개이고 간선은 7 개입니다. 한 번에 담긴 항목이 가장 많았던 때가 3 개입니다.

<!--/proof-->

**T1 을 빼면, 큐에 남은 항목에서 지나간 후보를 뺀 수가 언제나 $C(S)$ 의 간선 수와 같습니다.** T1 의 항목
`0(0)` 은 간선에서 온 것이 아니라 시작값이에요. T5 는 3 에서 1 을 빼 2 이고, 반복 안에서 끝난 T8 은 1 에서 1 을
빼 0 입니다. 큐에 넣은 항목이 8 개인데 간선이 7 개라서, $|Q| = E + 1$ 이 이
입력에서 등호로 나옵니다. 이제 이 두 관찰을 어떤 그래프에서나 성립하는 주장으로 세웁니다.

| 주장 | 무엇 | 주는 것 |
| --- | --- | --- |
| (가) | 큐에 남은 항목 중 트리 밖 정점을 가리키는 것이 온 간선의 모임이 $C(S)$ 와 같다 | 힙이 내주는 최소가 곧 경계 간선의 최소다 |
| (나) | 큐에 넣은 항목 전부의 개수가 $E + 1$ 을 넘지 않는다 | 비용의 총식이 $E$ 로만 적힌다 |

**(가) 의 한쪽 포함부터 봅시다.** $(u,v) \in C(S)$ 라 하고 $u \in S$ 라 합시다. $u$ 는 어느 걸음에서 트리에
들어갔고, 그 걸음의 후보 넣기가 $u$ 의 이웃을 봤어요. 그때 $v$ 가 트리 안이었다면 지금도 트리 안이라 $v \in \bar S$
와 어긋납니다. 그러니 그 시점에 $v$ 는 트리 밖이었고 항목 $v(w(u,v))$ 가 큐에 들어갔어요. 그 항목이 그 뒤에
꺼내졌다면 그때 $v$ 는 트리 밖이라 트리에 들어갔을 텐데, $v \in \bar S$ 이므로 그럴 수 없습니다. 따라서 그 항목은
아직 큐에 남아 있어요. 이 한쪽 포함을 차례대로 적으면 이렇습니다.

| 시점 | 참인 것 | 근거 |
| --- | --- | --- |
| `u` 를 넣은 걸음 | `v` 는 트리 밖이었다 | 그때 트리 안이었다면 지금도 트리 안이다 |
| 그 걸음의 후보 넣기 | 항목 $v(w(u,v))$ 가 큐에 들어갔다 | `inTree[v] !== true` 가 참이다 |
| 지금 | 그 항목이 큐에 남아 있다 | 꺼내졌다면 `v` 가 트리에 들어갔을 것이다 |

**반대쪽도 같은 자리에서 나옵니다.** 큐에 남은 항목 $v(k)$ 의 정점이 $v \in \bar S$ 라면, 그 항목은 어떤 정점 $u$
가 트리에 들어갈 때 후보 넣기가 넣은 것이고 $k = w(u,v)$ 예요. 그 $u$ 는 트리에 들어갔으므로 $u \in S$ 이고,
$v \in \bar S$ 이므로 $(u,v) \in C(S)$ 입니다. 두 쪽을 합치면 이렇게 됩니다.

$$\{\, \text{큐에 남은 항목 중 } v \in \bar S \text{ 인 것이 온 간선} \,\} \;=\; C(S)$$

힙은 남은 항목 중 키가 가장 작은 것을 내주고, 키가 그 간선의 가중치입니다. 지나간 후보는 꺼내는 자리에서 버리므로,
이 절차가 트리에 넣는 간선은 언제나 $C(S)$ 의 가중치가 가장 작은 간선이에요.

| (가) 에서 이어지는 것 | 내용 |
| --- | --- |
| 지나간 후보를 걷어 낸 큐 | 경계 간선 전부이고, 그것뿐이다 |
| 힙이 내주는 항목 | 남은 항목 중 키가 가장 작은 것 |
| 그 키 | 항목이 온 간선의 가중치 |
| 그래서 트리에 넣는 간선 | $C(S)$ 에서 가중치가 가장 작은 간선 |

**(나) 로 갑니다.** 간선 $(u,v)$ 가 후보 넣기에서 항목이 되는 것은 $u$ 가 트리에 들어가는 걸음이거나 $v$ 가 들어가는
걸음, 둘 중 하나예요. 둘 중 **먼저** 들어간 쪽의 걸음에서만 상대가 트리 밖이고, 나중 걸음에서는 상대가 이미 트리
안이라 조건이 거짓입니다. 코드의 그 줄이 이것입니다.

```ts
if (inTree[v] !== true) pq.push(v, ew);   // 나중에 들어간 쪽에서는 이 조건이 거짓이다
```

그러니 간선 하나가 항목이 되는 횟수는 많아야 1 이고, 시작 항목 하나를 더하면 $|Q| \le E + 1$ 입니다. 등호가 성립하는
조건도 나와요. 간선이 항목이 되지 못하는 경우는 두 끝점이 모두 시작 정점의 덩어리 밖이거나, 자기 자신을 잇는
간선이거나입니다. 자기 자신을 잇는 간선은 그 정점이 트리에 들어간 뒤에야 이웃 목록을 보므로 조건이 언제나 거짓이에요.
그러니 **자기 자신을 잇는 간선이 없고 그래프가 이어져 있으면 $|Q| = E + 1$** 이고, 위 검산의 8 = 7 + 1 이 그
자리입니다.

여기에 규모를 넣습니다. 항목이 $E+1$ 개이면 힙의 크기가 그 값을 넘지 않으므로 넣기 한 번이
$\lceil \log_2 (E{+}1) \rceil$ 번의 비교 이하이고, 꺼내기 한 번은 자식 둘을 비교하므로 그 두 배 이하예요. 이웃 목록을
만드는 $2E$ 와 이웃을 보는 $2E$ 를 더하면 아래 총식이 나와요. 이 값을 걸음마다 경계 간선을 다시 찾는 방식의 판정 수
$(V-1)E$ 와 나란히 놓고 규모를 올렸습니다.

$$2E \;+\; 2E \;+\; (E+1)\lceil \log_2(E+1) \rceil \;+\; 2(E+1)\lceil \log_2(E+1) \rceil \;=\; 4E + 3(E+1)\lceil \log_2(E+1) \rceil$$

<!--proof:crossingScale-->

| 정점 V | 간선 E | 경계 간선을 매번 다시 찾을 때 (V−1)E | 큐에 넣는 항목 E+1 | 몇 배 |
| ---: | ---: | ---: | ---: | ---: |
| 6 | 7 | 35 | 8 | 4.4 배 |
| 100 | 4,950 | 490,050 | 4,951 | 99.0 배 |
| 10,000 | 49,995,000 | 499,900,005,000 | 49,995,001 | 9,999.0 배 |

첫 줄은 전개 입력이고 뒤 두 줄은 완전 그래프입니다. 규모 상한 V = 10,000 · E = 49,995,000 에서 총식 4E + 3(E+1)⌈log₂(E+1)⌉ 은 4,099,590,078 입니다.

<!--/proof-->

규모 상한에서 이 절차는 41 억 번 이하이고, 걸음마다 경계 간선을 다시 찾는 방식은 판정만 4,999 억 번입니다. 마지막
칸 9,999.0 배가 정점 수보다 하나 적은 수인 것은 식에서 바로 나와요. $(V-1)E$ 를 $E+1$ 로 나눈 값은 $E$ 가 클수록
$V-1$ 에 가까워지기 때문입니다.

### 불변식 — 넣은 간선 집합은 언제나 어떤 최소 신장 트리의 부분집합이다

파트 1 의 여덟 걸음은 입력 하나에서 답이 나왔다는 기록입니다. 그 하나로는 다른 입력에서도 같은 일이 일어난다는 근거가
안 되므로, **정점 하나를 트리에 넣은 직후마다 참으로 남는 문장**을 세우고 그것이 유지되는지 확인합니다.

> 정점 하나를 트리에 넣은 직후마다 둘이 참입니다. **앞 문장** — 지금까지 트리에 넣은 간선의 집합 `F` 는 이 그래프의
> 어떤 최소 신장 트리에 통째로 들어 있습니다. **뒤 문장** — `inTree` 가 참인 정점의 모임 `S` 는 `F` 가 잇는 정점의
> 모임과 정확히 같습니다.

| 문장 | 참인 것 | 이 문장이 주는 것 |
| --- | --- | --- |
| 앞 문장 | `F` 가 어떤 최소 신장 트리 안에 있다 | 정점이 다 찼을 때 넣은 `V − 1` 개가 곧 최소 신장 트리다 |
| 뒤 문장 | `S` 가 `F` 가 잇는 정점과 같다 | `inTree` 한 칸이 「이 정점이 트리에 붙었는가」와 같은 말이다 |

「정점 하나를 넣은 직후마다」가 중요해요. 반복이 다 끝난 뒤 한 번만 참인 것이 아니라 정점을 넣을 때마다 참이어야
다음 걸음이 그 성질을 그대로 이어받습니다. 전개 입력에서 정점을 넣은 여섯 걸음마다 두 문장을 재 봤어요. 셋째 열은
우선순위 큐를 안 쓰고, 걸음마다 `F` 를 모두 담는 간선 부분집합을 전부 검사해서 낸 값입니다.

<!--proof:invariantWatch-->

| 걸음 | 넣은 간선 F | F 를 품은 신장 트리의 최소 합 | F 를 품은 최소 신장 트리 | inTree 가 참인 정점 S | F 가 잇는 정점과 대조 |
| --- | --- | ---: | --- | --- | --- |
| T2 | 없음 | 17 | 있다 | {0} | 일치 |
| T3 | (0,1)=1 | 17 | 있다 | {0, 1} | 일치 |
| T4 | (0,1)=1 (1,2)=3 | 17 | 있다 | {0, 1, 2} | 일치 |
| T5 | (0,1)=1 (1,2)=3 (2,3)=2 | 17 | 있다 | {0, 1, 2, 3} | 일치 |
| T7 | (0,1)=1 (1,2)=3 (2,3)=2 (3,4)=6 | 17 | 있다 | {0, 1, 2, 3, 4} | 일치 |
| T8 | (0,1)=1 (1,2)=3 (2,3)=2 (3,4)=6 (4,5)=5 | 17 | 있다 | {0, 1, 2, 3, 4, 5} | 일치 |

최소 신장 트리의 합은 17 이고 셋째 열은 걸음마다 F 를 모두 담는 크기 5 간선 부분집합을 전부 검사해 낸 값입니다.

<!--/proof-->

**여섯 걸음 모두 두 문장이 유지됩니다.** 이제 왜 유지되는지를 갈래마다 세웁니다. **출발점**에서는 정점 0 을 넣은
직후 `F` 가 비어 있고, 빈 집합은 어떤 최소 신장 트리에도 들어 있어요. `S` 는 `{0}` 이고 간선 없이 시작 정점 하나를
잇는 모임과 같습니다. 그 뒤로 상태를 바꾸는 갈래는 셋이에요.

| 갈래 | 바뀌는 것 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 꺼낸 정점이 이미 트리 안이라 버린다 | 없다 | `F` 가 그대로다 | `S` 도 그대로다 |
| 트리 밖 이웃을 후보로 넣는다 | 큐만 | 후보는 아직 고른 것이 아니다 | `S` 가 그대로다 |
| 꺼낸 정점을 트리에 넣는다 | `F` 에 간선 하나 · `S` 에 정점 하나 | 아래 「바꿔치기」 논증 | 넣은 간선이 새 정점을 `S` 에 잇는다 |

셋째 줄의 근거를 세웁니다. 지금 꺼낸 항목이 정점 `v` 를 가리키고, 그 항목을 넣은 정점을 `u` 라 합시다. 항목의 키는
후보 넣기가 넣은 간선 `e = (u,v)` 의 가중치이고, 앞 절의 (가) 에 따라 `e` 는 `C(S)` 의 원소이며 힙이 내준 것이므로
그중 가중치가 가장 작아요. 전개 입력에서 끝에서 두 번째로 정점을 넣는 T7 을 그렸습니다.

<!--fig:invariant-cut-->
![T7 직전 — 경계 간선 중 가장 가벼운 것을 꺼낸다](./figs/invariant-cut.svg)

<!--proof:invariantCut-->

| 걸음 | S | 바깥 | 경계 간선 | 꺼낸 항목이 온 간선 |
| --- | --- | --- | --- | --- |
| T7 | {0, 1, 2, 3} | {4, 5} | (0,5)=7 · (3,4)=6 | (3,4)=6 |

꺼낸 항목 4(6) 이 온 간선이 경계 간선 2 개 가운데 가장 가볍습니다.

<!--/proof-->

**여기서 논증이 한 걸음 나갑니다.** 가정에 따라 `F` 를 품은 최소 신장 트리 `T` 가 있어요. `T` 가 `e` 를 품고 있으면
끝입니다. 품지 않는다고 해 봅시다. `T` 는 모든 정점을 잇는 트리이므로 `u` 에서 `v` 로 가는 길이 `T` 안에 있고, 그
길은 `S` 에서 시작해 바깥에서 끝나니 `S` 와 바깥을 어디선가 건넙니다. 건너는 간선을 `f` 라 하면 `f` 도 경계
간선이므로 `F` 에 없고(`F` 의 간선은 뒤 문장에 따라 두 끝이 다 `S` 안이에요), 가중치가 `w(e)` 이상입니다. `T` 에서
`f` 를 빼고 `e` 를 넣은 것을 $T - f + e$ 라 쓰면 이렇습니다.

$$w(f) \;\ge\; w(e) \quad\Longrightarrow\quad W\bigl(T - f + e\bigr) \;=\; W(T) - w(f) + w(e) \;\le\; W(T)$$

부등식의 각 항을 봅시다. `w(f) − w(e)` 는 0 이상이에요. `e` 가 경계 간선 중 가장 가볍고 `f` 도 경계 간선이니까요.
그러니 `W(T)` 에서 그만큼을 빼면 `W(T)` 이하입니다.

| 비교 | `T` | $T - f + e$ |
| --- | --- | --- |
| 간선 수 | `V − 1` | `V − 1` — 하나 빼고 하나 넣었다 |
| 가중치 합 | $W(T)$ | $W(T)$ 이하 |
| 품은 간선 | `F` | `F` 와 `e` 둘 다 — `f` 는 `F` 에 없었다 |

새 트리가 신장 트리인 근거도 적어 둡니다. `f` 를 빼면 `T` 는 두 조각으로 갈리고 `u` 와 `v` 가 서로 다른 조각에
놓여요. `f` 가 `u` 에서 `v` 로 가는 유일한 길 위에 있었기 때문입니다. 그 두 조각을 `e` 가 다시 이으니 간선은 여전히
`V − 1` 개이고 모든 정점이 이어집니다. `T` 가 최소였으니 합이 그보다 작을 수 없어 새 트리도 최소이고, `F` 와 `e`
를 모두 품어요. 뒤 문장은 함께 나옵니다. 정점 `v` 를 넣을 때 `v` 를 `S` 에 잇는 간선 `e` 하나가 `F` 에 늘어나므로,
`S` 는 언제나 `F` 가 잇는 정점의 모임이에요. 경계에 있는 입력도 확인하고 넘어갑시다.

<!--proof:invariantEdges-->

| 입력 | 넣은 항목 | 꺼낸 항목 | 그중 버린 것 | 끝에 남은 항목 | 반환값 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 정점 하나 · 간선 없음 | 1 | 1 | 0 | 0 | 0 |
| 정점 넷 · 간선 없음 | 1 | 1 | 0 | 0 | -1 |
| 자기 자신을 잇는 간선이 섞인 정점 둘 | 2 | 2 | 0 | 0 | 5 |
| 평행 간선 100 과 1 | 3 | 2 | 0 | 1 | 1 |
| 가중치 0 이 섞인 정점 셋 | 3 | 3 | 0 | 0 | 5 |
| 가중치가 같은 사각형 | 5 | 4 | 0 | 1 | 3 |

<!--/proof-->

정점이 하나면 시작 항목 하나를 꺼내자마자 `joined === n` 이 참이라 `0` 을 돌려줍니다. 간선이 없는 정점 넷은 시작
정점을 넣고 나면 넣을 후보가 없어 큐가 비고 `-1` 이에요. 자기 자신을 잇는 간선은 이웃 목록에 적히지만 그 정점이
트리에 든 뒤에야 보므로 항목이 되지 않습니다. 평행 간선은 둘 다 항목이 되고 가벼운 쪽이 먼저 나온 뒤 정점이 다 차서,
무거운 쪽은 꺼내지도 않아요. 가중치 0 도 다른 키와 똑같이 비교됩니다. 가중치가 전부 같은 사각형은 어느 셋을 골라도
합계가 같아 답이 하나로 정해져요.

**이제 깨뜨려서 확인해 봅시다.** 앞 문장을 지키던 줄은 **큐에 넣는 키가 간선 하나의 가중치라는 것**입니다. 앞 절의
(가) 가 그 키를 근거로 「꺼낸 것이 경계 간선의 최소」를 냈으니까요. 그 줄의 키만 꺼낸 항목의 키에 간선 가중치를 더한
값, 곧 시작 정점부터의 누적 합으로 바꿉니다.

```ts
if (inTree[v] !== true) pq.push(v, w + ew);   // ← 키를 누적 합으로 바꿨다
```

<!--proof:mutantCumulative-->

| 입력 | 정본 | 누적 합을 키로 쓰는 판 |
| --- | ---: | ---: |
| 전개 입력 | 17 | 26 |
| 삼각형 | 3 | 4 |
| 가중치가 같은 사각형 | 3 | 4 |
| 정점 셋에 간선 하나 | -1 | -1 |

<!--/proof-->

**첫 줄에서 26 이 나옵니다.** 이 판이 만드는 것은 최소 신장 트리가 아니라 정점 0 에서의 최단 경로 나무예요. 두 판이
고른 간선을 나란히 놓으면 갈린 자리가 보입니다.

<!--proof:cumulativeTrees-->

| 큐에 넣는 키 | 고른 간선을 고른 차례 | 고른 간선의 가중치 합 | 반환값 |
| --- | --- | ---: | ---: |
| 간선 하나의 가중치 — 정본 | (0,1)=1 (1,2)=3 (2,3)=2 (3,4)=6 (4,5)=5 | 17 | 17 |
| 꺼낸 항목의 키 + 간선 가중치 | (0,1)=1 (0,3)=4 (1,2)=3 (0,5)=7 (3,4)=6 | 21 | 26 |

두 판이 고른 간선 5 개 가운데 2 개가 서로 다릅니다.

<!--/proof-->

아래쪽은 정점 0 에서의 거리를 가장 작게 하는 나무입니다. 반환값이 고른 간선의 합과도 다른 것은 이 판이 `total` 에
더한 것이 간선 가중치가 아니라 거리이기 때문이에요. 삼각형과 사각형에서도 3 과 4 로 갈립니다. 이어지지 않은 그래프만
두 판이 같은 `-1` 을 내는데, 그쪽은 애초에 트리를 못 만드는 입력이라 키의 뜻이 답에 들어가지 않습니다.

### 비용 계산

#### 비용을 세는 과정

한 번 실행할 때 하는 일은 넷입니다. 이웃 목록을 만들고, 표시 배열을 만들고, 항목을 꺼내고, 트리에 넣은 정점의 이웃을
보며 항목을 넣어요. 전개 입력의 걸음으로 보면 T1 이 이웃 목록 만들기와 시작 항목이고, T2 · T3 · T4 · T5 · T7 이
정점을 넣고 이웃을 본 걸음, T6 이 지나간 후보를 버린 걸음, T8 이 정점을 넣고 끝낸 걸음입니다. 걸음마다 센 값이에요.

<!--proof:perfCount-->

| 걸음 | 한 일 | 꺼낸 항목 | 넣은 항목 | 본 이웃 | 넣은 항목 누적 |
| --- | --- | ---: | ---: | ---: | ---: |
| T1 | 이웃 목록 만들기 · 시작 항목 | 0 | 1 | 0 | 1 |
| T2 | 정점을 넣고 이웃을 본다 | 1 | 3 | 3 | 4 |
| T3 | 정점을 넣고 이웃을 본다 | 1 | 1 | 2 | 5 |
| T4 | 정점을 넣고 이웃을 본다 | 1 | 1 | 2 | 6 |
| T5 | 정점을 넣고 이웃을 본다 | 1 | 1 | 3 | 7 |
| T6 | 지나간 후보를 버린다 | 1 | 0 | 0 | 7 |
| T7 | 정점을 넣고 이웃을 본다 | 1 | 1 | 2 | 8 |
| T8 | 정점을 넣고 끝낸다 | 1 | 0 | 0 | 8 |

이웃 목록에 간선 7 개를 14 번 적었고, 꺼낸 항목이 모두 7 개, 넣은 항목이 8 개, 본 이웃이 12 개입니다.

<!--/proof-->

T6 과 T8 은 이웃을 하나도 안 봤습니다. 버린 걸음은 이웃을 안 보고, 끝낸 걸음은 이웃을 보기 전에 돌려주기 때문이에요.
이제 이 값을 `V` 와 `E` 로 일반화합니다. 세어야 하는 것이 넷이에요.

| 항목 | 몇 번 | 근거 |
| --- | --- | --- |
| 이웃 목록 만들기 | `2E` 번 적는다 | 간선 하나를 양쪽 목록에 한 번씩 적는다 |
| 표시 배열 만들기 | `V` 칸 | `inTree` 가 `V` 칸이다 |
| 이웃 검사 | 모두 `2E` 번 이하 | 정점 하나를 넣을 때 그 정점의 이웃 전부를 본다. 차수의 합이 `2E` 다 |
| 큐 연산 | 넣기 `E + 1` 번 이하, 꺼내기도 그만큼 | 넣기 한 번이 `⌈log₂(E+1)⌉` 번의 비교 이하이고, 꺼내기는 그 두 배 이하다(「수식 정의와 유도」) |

넷을 더하면 총식이 나옵니다. `E ≤ V(V − 1)/2` 이므로 `log E ≤ 2 log V` 이고, 그래서 Boost 문서가 적은 `O(E log V)` 와
같은 차수예요.

$$\Theta(E) \;+\; \Theta(V) \;+\; O(E) \;+\; O(E \log E) \;=\; O(V + E \log E)$$

**큐 연산 항이 나머지를 덮는다는 것이 이 절차의 성질입니다.** 그래서 우선순위 큐를 바꾸면 상한이 바로 바뀌어요.
JGraphT 가 피보나치 힙으로 `O(|E| + |V|log(|V|))` 를 적는 것이 그 자리입니다.

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 서로 다른 축입니다. 「최악은 `O`, 평균은 `Θ`」처럼 한쪽을
다른 쪽에 짝지으면 안 돼요.

| | 상한 `O` | 타이트 경계 `Θ` |
| --- | --- | --- |
| **가장 적게 하는 경우** (큐에 항목이 한 번에 하나뿐이다) | `O(V + E)` | `Θ(V + E)` |
| **평균적인 경우** (입력 분포를 정하지 않는다) | `O(V + E log E)` | 분포를 정해야 값이 나온다 |
| **가장 많이 하는 경우** (큐에 항목이 간선 수만큼 쌓인다) | `O(V + E log E)` | `Θ(V + E log E)` |

**가장 적게 하는 경우와 가장 많이 하는 경우가 갈립니다.** 큐에 항목이 한 번에 하나뿐이면 넣기와 꺼내기가 비교 없이
끝나 `log` 항이 사라져요. 정점 수와 간선 수가 같은 두 그래프로 확인했습니다.

<!--proof:pathVsStar-->

| 입력 | V | E | 큐에 한 번에 담긴 항목 최대 | 기본 연산 |
| --- | ---: | ---: | ---: | ---: |
| 한 줄로 이은 200 정점 | 200 | 199 | 1 | 1,195 |
| 별 모양 200 정점 | 200 | 199 | 199 | 6,070 |

<!--/proof-->

`V` 도 `E` 도 같은데 기본 연산이 다섯 배쯤 갈립니다. 갈리는 것은 큐에 한 번에 담긴 항목 수 하나예요. 평균은 정의할 수
있는데 값을 적을 수 없습니다. 이 절차에는 난수가 없고 같은 입력이면 같은 계수가 나오므로 「입력 분포를 주면 기댓값이
정해진다」는 참이지만, 이 과제는 입력 분포를 정하지 않았어요. 「평균이 정의되지 않는다」가 아니라 **분포를 정해야
값이 나온다**는 쪽이고, 둘은 다른 진술입니다.

| 보장 | 뜻 | 이 절차 |
| --- | --- | --- |
| 최악 보장 | 어떤 입력에도 `V + E log E` 규모를 넘지 않는다 | 해당한다 |
| 기댓값 보장 | 구현이 만드는 무작위성이나 입력 분포에 기댄다 | 해당하지 않는다 — 코드에 난수가 없다 |

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 입력 분포에 대한 가정도 없어요. 같은 입력을 두 번 넣으면
반환값도 기본 연산 수도 똑같이 나옵니다.

#### 최악을 만드는 입력

「깊은 그래프가 최악」이라는 통념부터 확인합시다. 한 줄로 이은 그래프는 가장 깊고 별 모양은 가장 얕아요. 정점 수를
20,000 으로 맞추고 두 극단과 그 변형을 실제로 실행했습니다. 가장 무거운 간선은 가중치를 이 과제의 상한인 `10^9` 로
둔 것이에요.

<!--proof:shapeValues-->

| 입력 모양 | V | E | 큐에 한 번에 담긴 항목 최대 | 넣은 항목 | 기본 연산 | 반환값 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 한 줄로 이었다 | 20,000 | 19,999 | 1 | 20,000 | 119,995 | 9,978,415 |
| 별 모양이다 | 20,000 | 19,999 | 19,999 | 20,000 | 1,151,851 | 9,979,212 |
| 한 줄로 잇고 같은 간선을 한 벌 더 | 20,000 | 39,998 | 9 | 39,999 | 633,499 | 9,978,415 |
| 한 줄로 잇고 가장 무거운 간선을 한 벌 더 | 20,000 | 39,999 | 20,001 | 40,000 | 1,021,934 | 9,978,415 |
| 앞의 절반만 잇는다 | 20,000 | 9,999 | 1 | 10,000 | 59,996 | -1 |

<!--/proof-->

**앞의 두 줄이 열 배쯤 갈리고, 값이 큰 쪽은 얕은 별 모양입니다.** 통념은 이 절차에서 거짓이에요. 그래프의 깊이는
비용에 들어가지 않고, 값을 정하는 것은 큐에 한 번에 담기는 항목 수입니다. 별 모양은 첫 걸음에서 항목 19,999 개를
한꺼번에 넣어 그 뒤 모든 꺼내기가 큰 힙에서 내려가요. `kruskalMst` 편에서는 같은 통념이 「모양이 값을 안 바꾼다」로
부정됐는데, 이 절차에서는 모양이 값을 정하되 통념과 반대 방향입니다.

셋째 줄과 넷째 줄을 비교해 보세요. 둘 다 간선을 두 배로 늘렸는데 가장 무거운 간선을 더한 쪽이 기본 연산이 더
많습니다. 크러스컬이라면 무거운 간선은 정렬 뒤 전부 뒤로 가서 앞에서 트리가 차면 하나도 안 보는데, 이 절차는
**가중치와 상관없이 트리 밖 이웃이면 후보로 넣기 때문**이에요. 넷째 줄의 반환값이 첫째 줄과 같다는 것을 봐 주세요.
무거운 간선은 답에 하나도 안 들어갔는데 큐만 커졌습니다.

| 조건 | 커지는 항 |
| --- | --- |
| 간선 수를 규모 상한까지 채운다 | 넣은 항목 `E + 1` |
| 간선을 한 정점에 몰거나 무거운 간선을 두루 더해 큐를 한꺼번에 키운다 | 꺼낼 때마다 붙는 `log` |
| 그래프를 이어 놓아 정점을 전부 넣게 한다 | 반복 횟수 — 덩어리가 절반이면 절반만 보고 끝난다 |

가장 적게 하는 입력은 반대쪽입니다. 한 줄로 이어 큐에 항목이 늘 하나이면 `log` 항이 통째로 사라져요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하겠습니다. 신장 트리를 통째로 고르던 것을 정점을 하나씩 붙이는 것으로 바꿨고,
「경계 간선 중 가장 가벼운 것」을 매번 다시 찾는 대신 새로 넣은 정점의 트리 밖 이웃을 우선순위 큐에 담아 두었다가
꺼냈으며, 쓸모없어진 항목은 꺼내는 자리에서 버렸습니다. 답이 맞는 근거는 「넣은 간선 집합은 언제나 어떤 최소 신장
트리의 부분집합이다」이고, 비용은 큐 연산이 덮는 `O(V + E log E)` 예요.

| 순서 | 하는 일 | 규모 |
| ---: | --- | --- |
| 1 | 간선 목록을 이웃 목록으로 바꾸고 시작 항목을 넣는다 | `E + V` |
| 2 | 키가 가장 작은 항목을 꺼낸다 | 넣은 항목마다 한 번, 한 번에 `log` |
| 3 | 트리 안이면 버리고, 밖이면 넣고 `total` 에 키를 더한다 | 한 번 |
| 4 | 새 정점의 트리 밖 이웃을 후보로 넣는다 | 간선마다 많아야 한 번 |
| 5 | 정점이 다 차면 `total`, 큐가 비면 `-1` | 한 번 |

정점 3 항목이 그대로 남아 T6 에서 버려졌어요. 그러면 **간선 `(0,3)` 의 가중치를 4 가 아니라 1 로 바꾸면** 그 항목은
언제 어떻게 처리되고, 합계는 얼마가 될까요?

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### Prim 최소 신장 트리

풀 파일: [`primMst.ts`](./primMst.ts) · 테스트: [`primMst.test.ts`](./primMst.test.ts) · 실행: `bun test src/algorithms/graph-flow/primMst/primMst.test.ts`

#### 한 줄 요약

> 가중치 무방향 그래프의 정점 수 `n` 과 간선 목록 `edges` 를 받아, 모든 정점을 연결하는 간선 부분집합의 **가중치 합이 최소인 신장 트리**의 합계를 반환한다. 그래프가 연결되지 않으면 `-1` 을 반환한다.

#### 스토리

신도시 개발 계획. 여러 구역을 하나의 도로망으로 연결해야 한다. 구역 사이에는 도로 건설 후보 경로가 여러 개 있고, 각 경로마다 공사비가 다르다. 목표는 **모든 구역이 도로로 연결되면서 공사비 합계가 가장 적게** 드는 도로망을 찾는 것이다.

이미 이어진 구역에서 이웃한 미연결 구역으로 한 칸씩 뻗어 나가는 방식으로 도로를 만들어 간다. 연결할 때마다 아직 연결되지 않은 구역과 이을 수 있는 경로 중 공사비가 가장 싼 경로를 고른다. 이 과정을 모든 구역이 연결될 때까지 반복하면 최소 공사비 도로망이 완성된다.

구역이 여러 덩어리로 분리되어 있어 전체를 하나로 이을 수 없다면, 도로망 완성이 불가능하다는 신호를 돌려준다.

#### 함수 인터페이스

```ts
export function primMst(n: number, edges: [number, number, number][]): number;
```

- `n` — 정점의 개수. 정점 번호는 $0 \ldots n-1$.
- `edges` — 무방향 가중치 간선 목록. 각 원소 `[u, v, w]` 는 정점 `u` 와 `v` 를 잇는 가중치 `w` 의 간선이다.
- 반환 — 최소 신장 트리의 가중치 합. 그래프가 연결되지 않아 신장 트리를 구성할 수 없으면 `-1`.

#### 제약 조건

- $1 \leq n \leq 10^4$
- $0 \leq E \leq n \cdot (n-1) / 2$ (여기서 $E$ 는 간선의 수)
- $0 \leq w(u, v) \leq 10^9$
- 정점 번호는 $0 \ldots n-1$.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

가중치 무방향 그래프 $G = (V, E, w)$ 에서 신장 트리 $T \subseteq E$ 는 모든 정점을 포함하고 사이클이 없는 간선 부분집합이다. 최소 신장 트리는 가중치 합이 가장 작은 신장 트리다.

$$W(T) = \sum_{(u, v) \in T} w(u, v), \qquad \text{primMst}(G) = \min_{T \in \mathcal{T}(G)} W(T)$$

여기서 $\mathcal{T}(G)$ 는 $G$ 의 모든 신장 트리의 집합이다.

- 신장 트리는 정확히 $n - 1$ 개의 간선으로 이루어진다.
- 그래프가 연결되지 않으면 신장 트리를 구성할 수 없으므로 `-1` 을 반환한다.
- 정점이 1개인 경우 신장 트리는 간선 없이 정점 하나만으로 구성되며, 가중치 합은 `0` 이다.
- 자기 루프 `[v, v, w]` 는 신장 트리에 포함될 수 없으므로 무시한다.
- 평행 간선(같은 두 정점을 잇는 여러 간선)이 있을 경우 그중 가중치가 작은 것만 고려된다.

#### 예시

```ts
primMst(4, [
  [0, 1, 1],
  [1, 2, 2],
  [2, 3, 3],
  [0, 3, 10],
]); // 6 — 간선 (0,1)=1, (1,2)=2, (2,3)=3 선택; (0,3)=10은 포함하면 사이클

primMst(3, [[0, 1, 5]]); // -1 — 정점 2가 어떤 간선과도 연결되지 않아 신장 트리 불가

primMst(1, []); // 0 — 정점이 1개이면 간선 없이 신장 트리 완성, 합 = 0

primMst(2, [[0, 1, 100], [0, 1, 1]]); // 1 — 평행 간선 중 가중치가 작은 것을 선택

primMst(2, [[0, 0, 100], [0, 1, 5]]); // 5 — 자기 루프는 신장 트리에 포함되지 않음

primMst(3, [[0, 1, 0], [1, 2, 5]]); // 5 — 가중치 0 간선도 정상 처리
```
