# lowestSetBit — 자리올림이 최하위 1 비트에서 멈춰 검사 없이 답이 나오는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

정수 하나에서 가장 낮은 1 비트를 꺼내는 문제를, 자리를 차례로 검사하는 방법에서 시작해
검사를 아예 없애는 방법까지 만들어 봅니다. 마지막에는 실제로 동작하는 코드를 한 조각씩
잇습니다.

### 전체 컨셉

32 비트 정수 `x` 를 받아 **가장 낮은 자리의 1 비트만 남긴 값**을 돌려주는 문제예요. 나머지
자리는 전부 0 으로 만들고, 1 비트가 하나도 없으면(입력이 0) 0 을 돌려줍니다.

```text
입력과 출력
  x    32 비트 정수.  -2^31 ≤ x ≤ 2^31 - 1 이다
  답   x 에서 가장 낮은 1 비트만 남기고 나머지 자리를 0 으로 만든 값

  lowestSetBit(40) 이면 8
  └ 40 은 자리 3 과 자리 5 가 1 인데, 낮은 쪽은 자리 3 이고 그 자리의 값이 2^3 = 8 이다
```

여기서 쓰는 것은 **`x` 와 `-x` 를 비트 AND 로 겹치는 것**입니다. 기계는 음수를 32 비트 2 의
보수로 나타내는데, 그것은 모든 자리를 뒤집고 1 을 더한 값이에요. 그 덧셈이 자리를 아래에서
위로 올라가다가 **가장 낮은 1 비트가 있던 자리에서 멈춥니다.**

<!--proof:conceptIsolate-->

```text
아래 여덟 자리만 그린 그림 (십진값은 32 비트 정수 그대로다)
  x  x 의 자리  ~x 의 자리  -x 의 자리  x & -x 의 자리  답
 40   00101000    11010111    11011000        00001000   8
 12   00001100    11110011    11110100        00000100   4
  8   00001000    11110111    11111000        00001000   8
  1   00000001    11111110    11111111        00000001   1
  0   00000000    11111111    00000000        00000000   0
-12   11110100    00001011    00001100        00000100   4

└ x 가 0 이 아닌 줄에서는 다섯째 열에 1 이 하나뿐이고, 그 자리가 x 의 가장 낮은
  1 비트 자리와 같다. x 가 0 인 줄은 넷째 열도 전부 0 이라 다섯째 열에 1 이 없다
```

왜 자리 하나만 남는지는 자리를 세 구간으로 갈라 보면 확인됩니다. 가장 낮은 1 비트가 있는
자리를 `p` 라 할 때, 그 아래에서는 `x` 자신이 전부 0 이고, 그 위에서는 두 값이 서로 반대라
겹치는 자리가 없어요.

<!--proof:conceptRanges-->

```text
x = 40 의 자리마다 (p = 3)
        구간         x  -x  x & -x
자리 7  자리 p 위    0   1       0
자리 6  자리 p 위    0   1       0
자리 5  자리 p 위    1   0       0
자리 4  자리 p 위    0   1       0
자리 3  자리 p       1   1       1
자리 2  자리 p 아래  0   0       0
자리 1  자리 p 아래  0   0       0
자리 0  자리 p 아래  0   0       0

└ 자리 p 아래는 x 가 0 이라 AND 가 0 이고, 자리 p 위는 두 값이 서로 반대라 AND 가 0 이다.
  자리 p 한 줄만 두 값이 함께 1 이다
```

자리를 하나씩 검사하는 반복문도, 값의 크기를 재는 비교도 없습니다. 부호를 뒤집는 연산
하나와 비트 AND 하나로 끝나므로 시간이 `O(1)` 이고, 답 밖에 새로 잡는 칸이 없어요.

```text
이 절차가 쓰는 것
  연산       부호 뒤집기 하나와 비트 AND 하나, 모두 2 번
  새로 잡는 칸  없다 — 결과 값 하나 말고 들고 있는 것이 없다
  갈래       없다 — 조건문도 반복문도 없어서 어떤 입력이든 같은 연산을 실행한다
  └ 입력이 0 이든 자리 31 하나만 켜진 값이든 실행하는 것이 똑같다
```

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **비트 AND(`&`).** 자리마다 따로 걸리는 연산이라, 어떤 자리의 결과는 그 자리의 두 비트로만
  정해집니다. 양쪽이 다 1 인 자리에만 1 이 놓여요.
- **자릿값.** 자리 `j` 에 놓인 1 이 `2^j` 를 뜻한다는 것입니다. 이 문제가 답으로 요구하는 것은
  자리 번호가 아니라 **그 자리의 값**이에요.
- **32 비트 2 의 보수.** 음수를 「모든 자리를 뒤집고 1 을 더한 값」으로 나타내는 방법이에요.
  이 글의 절차가 기대는 성질이 전부 여기서 나옵니다.
- **덧셈의 자리올림.** 한 자리에서 1 + 1 이 되면 그 자리가 0 이 되고 1 이 위로 넘어가는
  것입니다. 이 글은 그 자리올림이 **어디서 멈추는가**만 봅니다.
- **JavaScript 에서 `&` 와 단항 `-` 가 피연산자를 32 비트로 자른다는 것.** 이 계약이 답을
  32 비트 정수로 돌려주기로 한 근거이고, 그 자리에서 답의 부호가 정해집니다.

같은 저장소 안에서 뺄셈이 만드는 자리내림을 AND 로 잘라 쓰는 문제는
[`enumerateSubmasks`](../enumerateSubmasks/enumerateSubmasks-guide.md) 이고, 비트 연산의
상쇄 성질로 값을 지우는 문제는
[`singleNumberXor`](../singleNumberXor/singleNumberXor-guide.md) 예요.

```text
이 글의 자리와 이웃한 글의 자리
  1 을 더한 값을 겹쳐 자리 하나를 꺼낸다    <- 이 글
  1 을 뺀 값을 걸러 다음 후보로 건너뛴다    <- enumerateSubmasks
  같은 값을 두 번 겹쳐 자리를 원래대로 둔다  <- singleNumberXor
```

### 아이디어 상세 — 자리를 검사하지 않고 자리 하나만 남기는 방법을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function lowestSetBit(x: number): number;
```

- 입력: `x` 는 32 비트 정수입니다. 음수도 들어옵니다.
- 출력: `x` 에서 가장 낮은 1 비트만 남긴 값 하나입니다. 1 비트가 없으면 0 이에요.
- 제약: `-2^31 ≤ x ≤ 2^31 - 1` 입니다. 시간 1 초, 메모리 256 MB.

이 글이 쓰는 기호는 일곱입니다. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `x` | 입력으로 받는 32 비트 정수 | `-2^31 ≤ x ≤ 2^31 - 1` |
| `j` | 자리를 가리키는 번호. 오른쪽 끝이 0 이고 왼쪽으로 갈수록 커진다 | `0 ≤ j ≤ 31` |
| `p` | `x` 에서 1 인 자리 중 가장 낮은 것의 번호 | `x ≠ 0` 일 때 `0 ≤ p ≤ 31` |
| `~x` | `x` 의 모든 자리를 뒤집은 값 | 값 하나 |
| `-x` | `~x` 에 1 을 더한 값. 32 비트 2 의 보수다 | 값 하나 |
| `w` | 자리 폭. 계약이 정한 값이고, 그림은 그중 아래 여덟 자리만 그린다 | 32 |
| `N` | 호출 횟수. 1 부터 `N` 까지의 정수를 한 번씩 넣는 자리에서 쓴다 | 기존 시험이 재는 자리가 `10^6` 이다 |

아래에서 「바퀴」라 부르는 것은 반복문 본문을 한 번 실행하는 일입니다. 정본에는 반복문이 없고,
비교 대상으로 세울 방법에만 나와요. 그 방법은 자리 0 부터 차례로 1 인지 검사하는 것입니다.

```ts
function scanEachBit(x: number): number {
  for (let j = 0; j < 32; j++) {
    // 자리 하나마다 검사 한 번. 처음 1 을 만난 자리가 답이다.
    if (((x >>> j) & 1) === 1) return 1 << j;
  }
  return 0;
}
```

이 방법이 하는 일의 양은 **답이 있는 자리 번호**를 따라갑니다. 그 번호를 0 에서 31 까지
옮겨 가며 일곱 자리에서 기본 연산을 세어 봅시다.

<!--proof:costScan-->

```text
1 비트가 자리 p 하나뿐인 입력에서 두 방법의 기본 연산 수
자리 p               x  자리마다 검사  5p + 6  정본  몇 배인가
     0               1              6       6     2        3.0
     1               2             11      11     2        5.5
     2               4             16      16     2        8.0
     3               8             21      21     2       10.5
    15          32,768             81      81     2       40.5
    30   1,073,741,824            156     156     2       78.0
    31  -2,147,483,648            161     161     2       80.5

x = 0 은 1 비트가 없어 자리 31 까지 다 검사한다 — 162 번이고 정본은 2 번이다

└ 셋째 열과 넷째 열이 일곱 줄 모두 같아서 닫힌 형태가 실측과 어긋나지 않는다.
  다섯째 열은 자리 번호와 무관하게 2 로 고정된다
```

**이 방법은 시간 제한을 넘지 않습니다.** 자리가 32 개뿐이라 1 비트가 있으면 최악이 161 번,
1 비트가 없으면 162 번이고, 1 초 안에 얼마든지 끝나요. 그러니 반박은 「느리다」가 아니라
**「비용이 무엇에 달렸는가」** 여야 합니다.

```text
반박의 자리
  최악이 자리 폭을 따라간다      자리가 w 개면 최악이 5w + 2 다. 32 비트면 162 번, 64 비트면 322 번
  같은 호출 수인데 값이 갈린다   답이 자리 0 이면 6 번, 자리 31 이면 161 번이다
  └ 정본은 두 줄 어디에서도 2 번이다. 자리 폭이 늘어도, 입력이 바뀌어도 안 늘어난다
```

**여기가 준비의 끝입니다.** 이 절차의 비용이 무엇으로 정해지는지가 나왔어요 — 자리 하나를
검사하는 것이 걸음 하나이므로 걸음 수가 곧 답이 있는 자리 번호입니다. 이제 같은 호출 수를
두 입력 모양으로 처리하고 실제 계수를 나란히 세어 봅시다.

<!--proof:costTwoShapes-->

```text
호출을 1,000,000 번 하되 넣는 값의 모양만 바꾼다
무엇을 넣는가                   자리마다 검사       정본  몇 배인가
1 부터 1,000,000 까지의 정수       10,999,965  2,000,000        5.5
-2,147,483,648 만 1,000,000 번    161,000,000  2,000,000       80.5

└ 둘째 열은 입력 모양에 따라
  10,999,965 에서 161,000,000 까지 14.6 배 갈리는데 셋째 열은 두 줄이 같다.
  자리 수의 합은 999,993 이고 그것이 둘째 열 첫 줄을 정한다
```

관찰할 것은 둘입니다 — **한쪽은 계수가 입력을 따라 움직이고 한쪽은 안 움직입니다.** 그리고
움직이지 않는 쪽이 두 입력 모양에서 모두 계수가 작아요.

| 방식 | 기본 연산이 따라가는 것 | 두 입력 모양에서 |
| --- | --- | --- |
| 자리마다 검사 | 답이 있는 자리 번호 `p` — 닫힌 형태로 `5p + 6` | 5.5 배와 80.5 배로 갈린다 |
| `x` 와 `-x` 를 겹치기 | 아무것도 안 따라간다 — 언제나 2 | 두 모양에서 같다 |

그 관찰을 개념으로 세우기 전에, **어떤 값을 만들어 AND 해야 하는지부터 실제로 실행해
봅시다.** 찾는 것은 「자리 `p` 아래를 전부 0 으로 만들면서 자리 `p` 자신은 1 로 두는 값」
하나이고, 만들기 쉬운 후보 여섯을 같은 입력에 넣어 봅니다.

<!--proof:maskCandidates-->

```text
후보 식을 5 개 입력에 실행한 값 (맨 아래 줄이 옳은 답이다)
식                 연산 수  x = 40  x = 12  x = 1  x = 0  x = -12  0 이상 65,536 미만 전수
x & ~x                   2       0       0      0      0        0  다르다
x & (x - 1)              2      32       8      0      0      -16  다르다
x & (x + 1)              2      40      12      0      0      -12  다르다
x & ~(x - 1)             3       8       4      1      0        4  전부 같다
x ^ (x & (x - 1))        3       8       4      1      0        4  전부 같다
x & -x                   2       8       4      1      0        4  전부 같다
옳은 답                  —       8       4      1      0        4  —

└ 마지막 열이 「전부 같다」인 식은 셋이고, 그중 연산 수가 가장 적은 것은 x & -x 다.
  위의 세 식은 이 다섯 입력 중 x = 0 에서만 답과 겹치고 나머지에서 갈린다
```

세 후보가 어긋나는 이유는 각각 다릅니다. `x & ~x` 는 모든 자리가 반대라 어느 자리도 못
남기고, `x & (x - 1)` 은 자리 `p` 를 **지운** 값이라 남기려던 것과 정반대예요. `x & (x + 1)`
은 자리 `p` 가 0 보다 위면 `x + 1` 이 자리 0 만 켜는데 그 자리가 `x` 에서 0 이라 `x` 를
그대로 돌려주고(40 → 40 · 12 → 12), 자리 `p` 가 0 이면 거꾸로 그 자리가 꺼져 0 이 됩니다
(1 → 0).

```text
개념 — 자리 p 를 경계로 아래를 전부 0 으로 만드는 값 하나

  자리 p 아래   x 에서 전부 0 이다        무엇과 AND 해도 0 이다
  자리 p        x 에서 1 이다             이 자리만 1 로 남기면 된다
  자리 p 위     x 에서 임의의 값이다      반대 값과 AND 하면 전부 0 이 된다
  └ 그러므로 「자리 p 아래는 0, 자리 p 는 1, 그 위는 x 의 반대」인 값 하나면 충분하다.
    모든 자리를 뒤집고 1 을 더한 값이 정확히 그 모양이다
```

이 개념이 각 값의 자리 범위를 정합니다. `~x` 는 자리마다 `x` 의 반대이고, 거기에 1 을 더하면
자리 `p` 아래의 1 들이 전부 0 이 되면서 자리올림이 자리 `p` 에서 멈춰요.

| 값 | 자리 `p` 아래 | 자리 `p` | 자리 `p` 위 |
| --- | --- | --- | --- |
| `x` | 전부 0 | 1 | 임의 |
| `~x` | 전부 1 | 0 | `x` 의 반대 |
| `-x` | 전부 0 | 1 | `x` 의 반대 |
| `x & -x` | 전부 0 | 1 | 전부 0 |

이 개념이 자리 번호와 무관한지 값으로 확인합시다. 자리 `p` 를 0 에서 31 까지 여덟 자리에서
재고, 이어서 값을 하나도 빠뜨리지 않고 전수로 대조했어요.

<!--proof:allPositions-->

```text
1 비트가 자리 p 하나뿐인 입력에서
자리 p               x    정본이 낸 답  2^p 를 32 비트로 적은 값  정본의 기본 연산
     0               1               1                         1                 2
     1               2               2                         2                 2
     3               8               8                         8                 2
     7             128             128                       128                 2
    15          32,768          32,768                    32,768                 2
    23       8,388,608       8,388,608                 8,388,608                 2
    30   1,073,741,824   1,073,741,824             1,073,741,824                 2
    31  -2,147,483,648  -2,147,483,648            -2,147,483,648                 2

전수 대조                일치한 값    전체  정본의 기본 연산
0 이상 65,536 미만          65,536  65,536  어느 값에서도 2
부호를 뒤집은 자리 0~31         32      32  어느 값에서도 2

└ 셋째 열과 넷째 열이 여덟 줄 모두 같고, 아래 표는 값을 하나도 빠뜨리지 않았다는 것이다.
  자리 31 만 십진값이 음수인데, 그 자리가 32 비트 정수의 부호 비트이기 때문이다.
  마지막 열은 자리 번호가 0 이든 31 이든 안 바뀐다
```

자리 번호가 0 이든 31 이든 연산 수가 2 로 같습니다. 그래서 「가장 낮은 1 비트를 찾는다」는
말에 들어 있던 **찾는 일 자체가 없어졌어요** — 자리를 하나도 검사하지 않습니다.

```text
얻은 절차 한 벌
  1. x 의 모든 자리를 뒤집는다
  2. 거기에 1 을 더한다 — 그 값이 32 비트 2 의 보수의 -x 다
  3. x 와 그 값을 AND 해 돌려준다
     └ 자리를 세는 반복문이 없어졌고 연산 수가 입력과 무관해졌다
```

### 수행으로 알아보는 알고리즘 — 두 연산으로 자리 하나만 남긴다

아이디어를 세웠으니 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각마다 그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

```ts
const x = 40;
// 이 절이 끝나면 8 이 나와야 한다
```

왜 하필 `40` 일까요? 셋 때문이에요. ① 가장 낮은 1 비트가 자리 3 이라 자리올림이 자리 0·1·2
를 지나 자리 3 에서 멈추는 것을 세 걸음으로 확인할 수 있고(자리 0 이면 한 걸음에 끝나 그
전파가 안 보입니다), ② 자리 3 위에 1 비트가 하나 더 있어서(자리 5) 그 위 구간이 뒤집힌 채로
남는 것이 함께 확인되며, ③ 값과 뒤집은 값과 답이 전부 여덟 자리 안에 들어옵니다.

```text
절차 전체를 한 장으로

  T1      x 를 받는다                                    — 입력
  T2      모든 자리를 뒤집는다                            ① ~x
  T3~T7   1 을 더한다 — 자리올림이 어디서 멈추는지 본다   ② -x
  T8      두 값이 함께 1 인 자리만 남긴다                 ③ AND
  T9      그 값을 돌려준다                                 ③ 반환
```

#### 1. 모든 자리를 뒤집는다

첫 조각은 `~x` 하나입니다. 자리 `p` 아래가 `x` 에서 전부 0 이었으므로 뒤집으면 전부 1 이
되고, 자리 `p` 자신은 1 이었으므로 0 이 돼요.

```ts
const flipped = ~x;   // ① 모든 자리를 뒤집는다
```

<!--proof:walkFlip-->

```text
           아래 여덟 자리  십진
x                00101000    40
뒤집은 값        11010111   -41

└ 자리 3 아래(자리 0·1·2)가 전부 1 이 되고 자리 3 자신은 0 이 됐다.
  x 에서 그 아래가 전부 0 이었으므로 뒤집으면 전부 1 이 된다
```

여기까지는 `x` 와 겹치는 자리가 하나도 없습니다. 뒤집은 값은 자리마다 `x` 의 반대라, 지금
AND 하면 어느 자리도 안 남아요. 자리 `p` 를 되살리는 것이 다음 조각입니다.

조각이 잡는 이름과 이 글의 기호는 이렇게 맞물립니다. 코드에서는 `flipped` 와 `negated` 이고
글에서는 `~x` 와 `-x` 인데, 전체 코드에서는 두 이름이 다 없어지고 표현식 하나로 적혀요.

#### 멈춤 — 지우는 식과 남기는 식을 바꿔 쓰면 답이 갈린다

여기서 헷갈리기 쉬운 지점은 **`x & (x - 1)` 과 이 절차를 바꿔 쓰는 것**입니다. 둘 다 유명한
식이고 이름도 비슷해서 「가장 낮은 1 비트를 다루는 식」으로 한데 묶어 외우기 쉬워요. 그
생각대로 적어 봅시다.

```ts
function clearInsteadOfKeep(x: number): number {
  return x & (x - 1);   // 「가장 낮은 1 비트」를 이 식으로 적었다
}
```

이 식이 무엇을 내는지 여섯 입력에 실행해 봅니다.

```text

  1 인데 0 과 AND 하면 어느 식이든 0 이 나온다. 나머지 다섯 줄은 답과 갈린다
```

여섯 줄 중 다섯에서 답이 갈립니다. `x - 1` 은 자리 `p` 를 0 으로 만들고 그 아래를 전부 1 로
만드는데, 그 값을 `x` 와 AND 하면 **자리 `p` 만 지워진** 값이 남기 때문이에요. 두 식은 서로
여집합이라 한쪽에서 다른 쪽을 얻으려면 연산이 하나 더 듭니다.

```text
  한쪽에서 다른 쪽을 얻으려면 연산이 하나 더 든다
```

#### 2. 1 을 더해 자리올림이 어디서 멈추는지 본다

둘째 조각은 덧셈 하나입니다. 자리 0 부터 자리올림이 올라가는데, 뒤집은 값의 자리가 1 인
동안은 계속 넘어가고 0 을 만나면 거기서 멈춰요.

```ts
const negated = flipped + 1;   // ② 1 을 더한다. 이 값이 32 비트 2 의 보수의 -x 다
```

`②` 가 하는 일을 자리마다 갈라 보면 자리올림이 자리 0·1·2 에서는 위로 넘어가고 자리 3 에서
0 이 됩니다. 그 자리가 `x` 에서 1 이었던 가장 낮은 자리예요.

```text
11010111 에 1 을 더하면

  자리 0   1 + 1 = 10   자리는 0, 자리올림 1 을 위로
  자리 1   1 + 1 = 10   자리는 0, 자리올림 1 을 위로
  자리 2   1 + 1 = 10   자리는 0, 자리올림 1 을 위로
  자리 3   0 + 1 =  1   자리는 1, 넘길 자리올림이 없다   <- 여기서 멈춘다
  자리 4~7 자리올림이 0 이라 뒤집은 값 1101 이 그대로 남는다
  결과     11011000 = -40
```

멈추는 자리가 자리 `p` 인 이유는 `~x` 의 자리가 1 인 구간이 정확히 자리 `p` 아래이기
때문입니다. `x` 에서 자리 `p` 아래가 전부 0 이었으니 뒤집으면 전부 1 이고, 자리 `p` 는
1 이었으니 뒤집으면 0 이라 거기서 자리올림이 흡수돼요.

#### 멈춤 — 제약 안에 답이 음수인 입력이 하나 있다

여기서 간과하기 쉬운 지점은 **답의 부호**입니다. 「가장 낮은 1 비트만 남긴 값」이라면 언제나
0 이상일 것 같아서, 결과가 음수로 나오면 코드가 잘못됐다고 읽기 쉬워요. 그 생각대로 부호를
뒤집어 돌려주는 판을 적어 봅시다.

```ts
function forcePositive(x: number): number {
  const r = x & -x;
  return r < 0 ? -r : r;   // 「답은 언제나 0 이상」이라는 생각대로 고쳤다
}
```

두 판을 경계에 있는 입력들에 실행해 봅니다.

쉬워요. 갈리는 한 줄은 `x = -2^31` 이고, 그때 답인 `2^31` 은 32 비트 부호 있는 정수의 범위를
한 칸 넘습니다. 그 값을 32 비트로 적으면 자리 31 하나만 켜진 `-2,147,483,648` 이에요.

```text
  └ 이 계약이 32 비트 정수를 돌려주기로 한 이상, 그 값이 답을 적는 유일한 방법이다
```

#### 3. 두 값을 AND 해 답을 낸다

셋째 조각은 AND 하나입니다. 앞의 두 조각이 만든 값을 원래 값과 겹치면 함께 1 인 자리만 남아요.

```ts
return x & negated;   // ③ 두 값이 함께 1 인 자리만 남긴다
```

세 조각을 이어 고정 입력에 실행하면 아홉 걸음이 나옵니다. T1 이 입력, T2 가 뒤집기,
T3 부터 T7 까지가 덧셈, T8 이 AND, T9 가 반환이에요.

걸음이에요. 아래 표의 마지막 줄이 이 절차의 특징입니다 — `②` 의 다섯 걸음은 사람이 읽으려고

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 `~x` 와 `+1` 로 갈라 본 두 걸음은 `-x` 한 번으로 적히므로,
완성된 코드에는 그것이 표현식 하나로 들어가요.

```ts
export function lowestSetBit(x: number): number {
  // ① 모든 자리를 뒤집는다 — 자리 p 아래가 전부 1 이 되고 자리 p 자신은 0 이 된다.
  // ② 거기에 1 을 더한다 — 자리올림이 자리 p 에서 멈추고, 그 값이 32 비트 2 의 보수다.
  // ③ 두 값이 함께 1 인 자리만 남긴다. 입력이 0 이면 부호를 뒤집어도 0 이라 결과가 0 이다.
  return x & -x;
}
```

```text
lowestSetBit(40)            ->  8
lowestSetBit(12)            ->  4
lowestSetBit(1)             ->  1
lowestSetBit(0)             ->  0
lowestSetBit(-12)           ->  4
lowestSetBit(2147483647)    ->  1
lowestSetBit(-2147483648)   ->  -2147483648
```

### 알아 두면 좋은 개념 — 법 2^32 에서의 덧셈 역원

앞에서 「모든 자리를 뒤집고 1 을 더한다」로 적은 것에는 다른 이름이 하나 더 있습니다. 32 비트
정수를 **`2^32` 로 나눈 나머지**로 보면 `-x` 는 「더해서 0 이 되는 값」, 곧 **덧셈 역원**이고
그 값이 `2^32 - x` 예요. 2 의 보수는 그 나머지 연산을 자리 뒤집기와 1 더하기로 실행합니다.

<!--proof:relatedModulo-->

```text
32 비트 부호 없는 값으로 읽으면
x (32 비트 정수)  x (부호 없는 값)  -x (부호 없는 값)       2^32 - x  판정
              40                40      4,294,967,256  4,294,967,256  같다
              12                12      4,294,967,284  4,294,967,284  같다
               8                 8      4,294,967,288  4,294,967,288  같다
               1                 1      4,294,967,295  4,294,967,295  같다
               0                 0                  0              0  같다
             -12     4,294,967,284                 12             12  같다

└ 셋째 열과 넷째 열이 여섯 줄 모두 같다. x 가 0 인 줄은 2^32 를 2^32 로 나눈 나머지가
  0 이라 그 자리도 맞는다
```

이 나머지 연산은 이 글 밖에서도 같은 이름으로 다시 만납니다. 넘친 자리를 버리는 것이 오류가
아니라 **정의된 동작**이라는 것이 그때마다의 공통점이에요.

| 어디서 | 무엇이 `2^32` 로 나눈 나머지인가 | 그래서 얻는 것 |
| --- | --- | --- |
| 이 글의 절차 | `-x` 가 `2^32 - x` 다 | 뺄셈 없이 자리 하나를 꺼낸다 |
| 기계의 뺄셈 | `a - b` 를 `a + (2^32 - b)` 로 계산한다 | 덧셈기 하나로 뺄셈까지 처리한다 |
| 해시 혼합 함수 | 곱셈 결과의 위 자리를 버린다 | 값이 항상 32 비트 안에 머무른다 |
| 크기가 2 의 거듭제곱인 순환 버퍼 | `(i - 1) & (n - 1)` 로 뒤로 간다 | 음수 인덱스를 따로 막지 않아도 된다 |

이 이름을 몰라도 앞의 절차는 그대로 따라갈 수 있습니다. 다만 「값이 넘치면 위 자리를
버린다」는 자리를 다른 문제에서 만났을 때 그것이 전부 `2^32` 로 나눈 나머지라는 것을 알면,
넘친 값을 예외로 다루지 않아도 돼요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅시다. 어떤 문제에 이것을 쓰는지, 자리 번호를 식으로 어떻게
닫는지, 무엇이 언제나 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **값이 고정 폭 정수로 나타내집니다.** 자리 폭이 정해져 있어야 뒤집기가 뜻을 갖고, 음수를
  2 의 보수로 적어야 자리올림이 이 글이 말한 자리에서 멈춥니다.
- **필요한 것이 자리 번호가 아니라 그 자리의 값입니다.** 「자리 몇 번인가」를 물으면 표
  조회나 앞자리 0 세기가 한 번 더 붙어요.
- **갈래 없는 상수 시간이 요구됩니다.** 조건문이 없어서 어떤 입력에서도 같은 연산을
  실행하므로, 실행 시간이 입력에 안 달립니다.
- **자리 폭이 커질 수 있습니다.** 64 비트로 옮겨도 연산이 2 번 그대로예요.

```text
네 조건이 코드의 모양을 그대로 정한다
  고정 폭 정수다        -> 부호 뒤집기와 AND 로 자리를 다룰 수 있다
  자리의 값이 필요하다  -> 자리 번호로 되돌리는 단계가 없어진다
  갈래가 없어야 한다    -> 조건문도 반복문도 안 쓴다
  자리 폭이 커진다      -> 연산 수가 자리 폭과 무관하다
```

둘째 조건이 이 절차의 경계입니다. 「가장 낮은 1 비트가 **몇 번째 자리**인가」로 문제가
바뀌면 이 값에서 자리 번호를 얻는 단계가 더 필요해요.

```text
같은 입력, 다른 질문
  가장 낮은 1 비트의 값은?      이 절차가 답한다              연산 2 번
  그 비트가 몇 번 자리인가?     이 값에서 한 단계 더 간다     표 조회나 앞자리 0 세기
  가장 높은 1 비트의 값은?      이 절차로는 답이 없다         반대 방향은 자리올림이 안 걸린다
  1 비트가 몇 개인가?           이 절차로는 답이 없다         자리 하나만 남기고 나머지를 버렸다
  └ 아래 두 줄은 이 식이 남기지 않은 것을 묻는다. 그때는 다른 절차로 간다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "가장 낮은 1 비트"  "가장 오른쪽에 켜진 비트"  "우선순위가 가장 높은 플래그"
  "비트마스크에서 원소 하나를 꺼낸다"  "집합에서 아무 원소나 하나"      <- x & -x 다

제약에 이런 모양이 보이면
  값이 32 비트 또는 64 비트 정수로 못 박혀 있다   <- 비트 단위 절차를 염두에 둔 것이다
  추가 공간 O(1) 을 요구한다                      <- 표 조회도 못 쓴다
  분기 없는 상수 시간을 요구한다                  <- 자리를 검사하는 반복문이 막힌다
  집합을 정수 하나로 주고받는다                   <- 원소를 꺼내는 연산이 필요하다

반대로 이런 말이 보이면 해당하지 않는다
  "가장 높은 1 비트"                              <- 자리올림이 반대 방향으로는 안 걸린다
  "1 비트의 개수"                                 <- 자리 하나만 남기는 것으로는 못 센다
  "몇 번째 자리인지 출력하라"                     <- 값에서 번호로 가는 단계가 더 필요하다
```

위 무리의 마지막 줄이 가장 자주 나오는 신호입니다. 집합을 정수 하나로 주고받는 문제는
「원소를 하나 꺼내고 그것을 지운다」를 반복하게 되는데, 꺼내는 쪽이 이 식이에요.

```text
집합을 정수 하나로 든 반복문
  꺼낸다   b = m & -m        m 에 남은 원소 중 자리 번호가 가장 낮은 것
  지운다   m = m ^ b         꺼낸 자리를 끈다
  멈춘다   m 이 0 이 되면    남은 원소가 없다
  └ 바퀴 수가 자리 폭이 아니라 실제 원소 개수와 같아진다
```

### 수식 정의와 유도

정수 하나를 2 의 거듭제곱과 홀수의 곱으로 적습니다. `x ≠ 0` 이면 이 갈래가 유일해요.

$$x = 2^{\nu(x)} \cdot q, \qquad q \text{ 는 홀수}$$

| 기호 | 무엇 | 값을 넣으면 |
| --- | --- | --- |
| $\nu(x)$ | $x$ 를 2 로 나눌 수 있는 최대 횟수 | $40 = 2^3 \cdot 5$ 이므로 $\nu(40) = 3$ |
| $q$ | 그렇게 나누고 남은 홀수 | $x = 40$ 이면 5 |
| $s_2(N)$ | $N$ 의 이진 표기에 있는 1 의 개수 | $N = 10$ 이면 2 |
| $A(N)$ | 자리마다 검사하는 방법이 $x = 1 \dots N$ 에서 쓰는 기본 연산의 합 | 아래에서 닫는다 |

$\nu(x)$ 는 「2 로 몇 번 나눠지는가」이고, 앞에서 `p` 라 부른 자리 번호와 같은 것입니다.
답은 그 자리의 값이므로 $2^{\nu(x)}$ 예요. 정의를 값에 넣어 검산하고, 이어서 1 부터 $N$
까지의 $\nu$ 를 실제로 더해 봅니다.

<!--proof:mathCheck-->

```text
정의를 값에 넣으면
    x  ν(x)  2^ν(x)  정본이 낸 답
   40     3       8             8
   12     2       4             4
    1     0       1             1
1,024    10   1,024         1,024
    0  없다       0             0

1 부터 N 까지의 ν 를 실제로 더하면
    N  Σ ν(x)  s₂(N)  N − s₂(N)
    8       7      1          7
   10       8      2          8
  100      97      3         97
1,000     994      6        994

└ 위 표의 셋째 열과 넷째 열이 다섯 줄 모두 같고, 아래 표의 둘째 열과 넷째 열이
  네 줄 모두 같다
```

아래 표의 규칙을 유도합니다. $\nu(x)$ 를 「$x$ 가 $2^j$ 로 나누어떨어지는 $j \ge 1$ 의
개수」로 다시 세면, 합의 순서를 바꿔 $j$ 마다 셀 수 있어요.

$$\sum_{x=1}^{N} \nu(x) = \sum_{j \ge 1} \#\{x \le N : 2^j \mid x\} = \sum_{j \ge 1} \left\lfloor \frac{N}{2^j} \right\rfloor$$

```text
순서를 바꾼다는 것이 무엇인가 — N = 8 에서

  x 마다 세면   ν(1)+…+ν(8) = 0+1+0+2+0+1+0+3               여덟 항
  j 마다 세면   ⌊8/2⌋ + ⌊8/4⌋ + ⌊8/8⌋ = 4 + 2 + 1           세 항
  합            둘 다 7 이다
  └ 같은 것을 세로로 세느냐 가로로 세느냐의 차이라 합이 안 바뀐다
```

이제 오른쪽을 닫습니다. $N$ 을 이진 표기로 $N = \sum_i 2^{a_i}$ 라 두면 $\lfloor N/2^j \rfloor$
는 $a_i \ge j$ 인 항만 남기므로, 두 합의 순서를 다시 바꿔 각 $i$ 마다 등비수열을 더할 수 있어요.

$$\sum_{j \ge 1} \left\lfloor \frac{N}{2^j} \right\rfloor = \sum_i \sum_{j=1}^{a_i} 2^{a_i - j} = \sum_i (2^{a_i} - 1) = N - s_2(N)$$

```text
등호 셋이 각각 무엇을 했는가
  첫째   ⌊N/2^j⌋ 를 자리별 항의 합으로 폈다      a_i < j 인 항은 합쳐도 1 이 안 돼 버려진다
  둘째   j 에 대한 합을 안쪽으로 옮겼다          유한한 합이라 순서를 바꿔도 값이 같다
  셋째   등비수열 1+2+…+2^(a_i-1) 을 닫았다      각 항이 2^a_i − 1 이 된다
  └ 항이 s_2(N) 개이므로 1 을 그만큼 뺀 것이 N − s_2(N) 이다
  └ 첫째에서 항마다 버리는 것이 아니다 — a_i 가 서로 다르므로 그 항들의 합이
    (2^j − 1)/2^j < 1 이고, 그래서 버림이 그 몫을 통째로 걷어 낸다
```

```ts
// 위 식을 그대로 옮긴 것. 왼쪽은 ν 를 직접 더하고 오른쪽은 닫힌 형태다.
const sumNu = (n: number): number => {
  let total = 0;
  for (let x = 1; x <= n; x++) for (let t = x; t % 2 === 0; t /= 2) total++;
  return total;
};
const closed = (n: number): number => {
  let ones = 0;
  for (let t = n; t > 0; t = Math.floor(t / 2)) ones += t % 2;
  return n - ones;
};
```

닫힌 형태를 자리마다 검사하는 방법의 비용에 넣습니다. 그 방법이 `x` 하나에 쓰는 연산이
$5\nu(x) + 6$ 이므로, $x = 1 \dots N$ 을 전부 넣으면 $A(N) = 5(N - s_2(N)) + 6N$ 이에요.

<!--proof:mathScale-->

```text
호출 1,000,000 번을 닫힌 형태로 계산하면
무엇                        식                                  값
자리 수의 합                N − s₂(N) = 1,000,000 − 7      999,993
자리 수의 평균              (N − s₂(N)) / N               0.999993
1 부터 N 까지 넣었을 때     5(N − s₂(N)) + 6N           10,999,965
최악 입력만 N 번 넣었을 때  (5·31 + 6) N               161,000,000
정본                        2N                           2,000,000

견주는 자리       자리마다 검사       정본  몇 배인가
1 부터 N 까지        10,999,965  2,000,000        5.5
최악 입력만 N 번    161,000,000  2,000,000       80.5

└ 자리 수의 평균이 1 에 가까워서 1 부터 N 까지 넣으면 5.5 배에 그치는데,
  최악 입력만 넣으면 80.5 배가 된다. 정본은 두 줄이 같은 값이다
```

본문의 값만으로는 안 나오는 것이 여기서 나옵니다. **자리 수의 평균이 1 로 수렴한다**는 것
이에요 — $s_2(N) \le \log_2 N + 1$ 이므로 $(N - s_2(N))/N$ 은 $N$ 이 커질수록 1 에
가까워집니다. 그래서 1 부터 $N$ 까지를 한 번씩 넣으면 자리마다 검사하는 방법이 **5.5 배밖에
안 커지는데**, 같은 방법의 최악은 80.5 배예요. 두 수의 거리가 이 절차가 사는 자리입니다.

### 불변식 — x 와 -x 가 함께 1 인 자리는 가장 낮은 1 비트 하나뿐이다

파트 1 은 `x = 40` 하나를 아홉 걸음으로 따라가 답이 8 이라는 것을 확인했습니다. 확인한 것은
그 값 하나이지 32 비트 정수 전부가 아니에요. 무엇이 **모든 입력에서 참으로 남는지**를 문장으로
세우고 그것이 실제로 유지되는지 확인해 봅시다.

> `x ≠ 0` 이고 가장 낮은 1 비트가 자리 `p` 일 때, `-x` 의 자리 `j` 비트는 `j < p` 면 0,
> `j = p` 면 1, `j > p` 면 `x` 의 그 자리 비트의 반대입니다. `x = 0` 이면 `-x` 도 0 이에요.

```text
  이 문장이 뜻하는 것   -x 는 자리 p 를 경계로 두 층으로 갈라진다
  뜻하지 않는 것        -x 가 x 의 반대라는 것 — 자리 p 와 그 아래에서는 반대가 아니다

  이 문장은 「연산이 끝난 시점」의 것이다   덧셈이 자리 p 까지 올라가는 도중에는 성립하지 않는다
```

**출발점부터 봅시다.** `~x` 는 모든 자리에서 `x` 의 반대입니다. 자리 `p` 아래는 `x` 가 전부
0 이므로 `~x` 에서 전부 1 이고, 자리 `p` 는 `x` 가 1 이므로 `~x` 에서 0 이에요.

| 구간 | `x` | `~x` | 1 을 더하면 | 왜 그런가 |
| --- | --- | --- | --- | --- |
| 자리 `p` 아래 | 전부 0 | 전부 1 | 전부 0 | 1 + 1 이 되어 그 자리가 0 이 되고 자리올림이 위로 간다 |
| 자리 `p` | 1 | 0 | 1 | 0 에 자리올림 1 을 더해 1 이 되고 넘길 것이 없어진다 |
| 자리 `p` 위 | 임의 | `x` 의 반대 | `x` 의 반대 | 자리올림이 0 이라 더할 것이 없다 |

가운데 줄이 이 논증의 전부입니다. 자리 `p` 아래가 전부 1 이라 자리올림이 끊기지 않고
올라가고, 자리 `p` 가 0 이라 거기서 흡수돼요. 전개 입력에서 세 구간을 자리마다 대조해 봅니다.

<!--proof:invariantRanges-->

```text
x = 40 에서 (p = 3)
        구간    x 의 비트  -x 의 비트  불변식이 말하는 값  판정
자리 7  위              0           1                   1  맞다
자리 6  위              0           1                   1  맞다
자리 5  위              1           0                   0  맞다
자리 4  위              0           1                   1  맞다
자리 3  자리 p          1           1                   1  맞다
자리 2  아래            0           0                   0  맞다
자리 1  아래            0           0                   0  맞다
자리 0  아래            0           0                   0  맞다

└ 넷째 열과 다섯째 열이 여덟 줄 모두 같다. 아래 구간은 0, 자리 p 는 1,
  위 구간은 셋째 열의 반대다
```

전개 입력 하나로는 세 구간이 다 나오지 않는 경계들이 있습니다. 정의를 그대로 옮긴 답(2 로
나눌 수 있는 최대 횟수를 세어 그 자리의 값을 내는 것)과 나란히 놨어요.

<!--proof:invariantEdges-->

```text
경계                               x     p    정의가 낸 답    정본이 낸 답  판정
값이 0                             0  없다               0               0  같다
1 비트가 자리 0 하나               1     0               1               1  같다
1 비트가 전부 켜짐                -1     0               1               1  같다
전개 입력                         40     3               8               8  같다
음수                             -12     2               4               4  같다
제약의 위쪽 끝         2,147,483,647     0               1               1  같다
제약의 아래쪽 끝      -2,147,483,648    31  -2,147,483,648  -2,147,483,648  같다
자리 30 하나           1,073,741,824    30   1,073,741,824   1,073,741,824  같다

└ 여덟 줄 모두 같다. 값이 0 인 줄은 1 비트가 없어 p 가 정의되지 않는데,
  그 자리에서 정본은 막는 줄 없이 0 을 낸다
```

**이제 깨뜨려 봅시다.** 이 문장을 유지하던 것은 **1 을 더하는 자리** 하나예요. 「어차피 자리를
뒤집으면 되는 것 아닌가」라는 생각으로 그 덧셈을 지우고 `~x` 를 그대로 AND 해 봅니다.

```ts
export function lowestSetBit(x: number): number {
  return x & ~x;   // 1 을 더하지 않았다
}
```

실행하면 이렇게 나옵니다.

```text
값이 0                             0               0                        0  같다
```

여덟 줄이 전부 0 이 나오고 그중 일곱에서 답과 갈립니다. 1 을 더하지 않으면 불변식의 세 구간
중 **아래 둘이 통째로 무효**가 되기 때문이에요 — 자리 `p` 아래가 1 로 남고 자리 `p` 가 0 으로
남습니다.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 네 무리입니다 — 입력을 읽는 것, `-x` 를 만드는 것, 두 값을 AND 하는
것, 값을 돌려주는 것이에요. 전개의 걸음으로 확인하면 이렇게 나뉩니다.

<!--proof:perfCount-->

```text
무리              어느 걸음인가    걸음 수  부호 뒤집기  비트 AND  기본 연산
입력을 읽는다     T1                     1            0         0          0
-x 를 만든다      T2 부터 T7 까지        6            1         0          1
두 값을 AND 한다  T8                     1            0         1          1
값을 돌려준다     T9                     1            0         0          0
합계                                     9            1         1          2

└ 걸음은 9 개인데 기본 연산은 2 개다. 자리마다의 덧셈은 한 연산 안에서
  일어나는 일이라 걸음 수가 늘어도 연산 수가 안 늘어난다
```

**전개의 걸음 수와 기계의 연산 수가 다릅니다.** T2 부터 T7 까지 여섯 걸음은 사람이 읽으려고
뒤집기 한 걸음(T2)과 자리올림 다섯 걸음(T3~T7)으로 갈라 놓은 것이고, 기계에서는 부호를
뒤집는 연산 한 번이에요.

```text
총식 = 부호 뒤집기 + 비트 AND

  부호 뒤집기   1 번      자리 폭과 무관하다
  비트 AND      1 번      자리 폭과 무관하다
  기본 연산     2 번      어떤 입력이든 같다
  새로 잡는 칸  0 개      결과 값 하나 말고 들고 있는 것이 없다
  └ 여기서 세는 단위는 「부호 뒤집기 · 비트 AND · 오른쪽 밀기 · 비교 · 대입 · 증가 한 번」이다
```

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 섞어서 짝지으면
안 돼요. 다만 이 절차에서는 한 축이 아예 안 갈립니다 — 케이스가 하나뿐이에요.

| 케이스 (입력 크기는 자리 폭 `w` = 32 로 고정) | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (어떤 정수든) | `O(1)` | `Θ(1)` — 연산이 2 번이다 |
| **최악의 경우** (어떤 정수든) | `O(1)` | `Θ(1)` — 연산이 2 번이다 |
| **평균** (입력 분포를 안 가정한다) | `O(1)` | `Θ(1)` — 연산이 2 번이다 |

세 줄이 같은 값인 것은 이 절차에 갈래가 하나도 없어서예요. 조건에 따라 건너뛰거나 되풀이할
자리가 없으니, 어떤 32 비트 정수를 넣어도 실행되는 연산이 글자 그대로 같습니다.

```text
상한과 타이트한 값을 가르는 자리
  O(1)   이 절차의 기본 연산이 그보다 많지 않다는 것만 말한다      상한이다
  Θ(1)   위아래로 같은 차수라 실제로 그만큼 든다는 것도 말한다     타이트한 값이다
  └ 기본 연산이 정확히 2 라 아래로도 상수다. 그래서 Θ 로 적을 수 있다
```

**총식을 한 번은 정확히 적습니다.** 앞뒤로 붙는 전처리가 하나도 없다는 것이 이 절차의
특징이에요 — 미리 만드는 표도, 자리 수를 세는 단계도 없습니다.

```text
총식 = 기본 연산 2 번 + 새로 잡는 칸 0 개

  w 는 자리 폭                 이 문제에서는 32
  기본 연산                    어떤 정수든 2 번. w 가 64 가 되어도 2 번이다
  자리마다 검사하는 방법       최악이 5w + 2 라 w = 32 에서 162, w = 64 에서 322 이다
  └ 이 절차만 w 가 총식에 안 나온다
```

**보장의 종류는 최악 보장입니다.** 해시도, 무작위성도, 분할 상환도 쓰지 않아요 — 어떤 32 비트
정수를 넣어도 기본 연산이 2 번입니다.

```text
기댓값이 끼어들 자리가 없다
  연산 수      입력을 보기도 전에 2 로 정해진다     입력 분포를 가정하지 않는다
  갈래         없다                                 평균을 낼 대상 자체가 없다
  새로 잡는 칸  0 개                                 값을 보기도 전에 정해진다
  └ 아래로도 이 값이 하한이다. 입력을 한 번은 읽어야 하고, 그 값에서 답을 만들려면
    적어도 연산 하나는 필요하다
```

#### 최악을 만드는 입력

이 절차에는 **최악을 만드는 입력이 없습니다.** 그것을 값으로 확인하고, 같은 입력들이
자리마다 검사하는 방법에서는 어떻게 갈리는지 나란히 봅시다.

<!--proof:worstShape-->

```text
입력의 모양                                  x     p  정본의 기본 연산  자리마다 검사              답
값이 0 이다                                  0  없다                 2            162               0
1 비트가 자리 0 에 있다                      1     0                 2              6               1
1 비트가 자리 31 에 있다        -2,147,483,648    31                 2            161  -2,147,483,648
1 비트가 서른두 자리에 다 있다              -1     0                 2              6               1
```

**「값이 크면 비용이 크다」와 「1 비트가 많으면 비용이 크다」는 둘 다 성립하지 않습니다.**

횟수가 적고, 다섯째 줄은 값이 가장 큰데 검사가 여섯 번입니다.

```text

  1 비트가 있을 때의 최악  x = -2,147,483,648       161 번. 가장 낮은 1 비트가 자리 31 이다
  └ 둘째 줄은 서른두 바퀴를 다 실행한 뒤 조건을 한 번 더 검사하고,
    셋째 줄은 서른두째 바퀴에서 답을 찾아 거기서 끝난다. 그 차이가 한 번이다
```

| --- | --- | --- |
| 정본의 기본 연산 | 어떤 32 비트 정수든 | 2 번 |
| 자리마다 검사의 기본 연산 | `x = 0` | 162 번 |

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 자리를 **검사하지 않고** 자리 하나만 남겼고,
그 일을 한 것은 부호를 뒤집는 덧셈의 자리올림이며, 연산 수는 값에도 자리 폭에도 안 달립니다.

```text
1.   모든 자리를 뒤집으면 가장 낮은 1 비트 아래가 전부 1 이 된다     자리 p 자신은 0 이 된다
2.   1 을 더하면 자리올림이 그 구간을 지나 자리 p 에서 멈춘다        자리 p 가 다시 1 이 된다
3.   두 값을 AND 하면 자리 p 하나만 남는다                          그 자리의 값이 답이다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T6 에서 자리올림이 0 이 되는데, T7 은 그 위 자리를
「뒤집은 값 그대로」라고만 적고 넘어갑니다. 그 자리들을 실제로 확인하지 않아도 답이 맞는다고
말할 수 있을까요?

<!--proof:checkAbove-->

```text

자리 7          0            1           1    0
자리 6          0            1           1    0
자리 5          1            0           0    0
자리 4          0            1           1    0

└ 셋째 열과 넷째 열이 네 줄 모두 같다 — 자리올림이 0 이 된 뒤라 더한 것이 없다.
  둘째 열과 넷째 열은 네 줄 모두 반대라 마지막 열이 전부 0 이다
```

<!--check:carryStops-->
말할 수 있습니다. 근거가 둘이에요. 첫째, T6 에서 자리올림이 0 이 됐으므로 그 위 자리에는
더할 것이 없고, 그래서 `-x` 의 자리 4 이상은 `~x` 의 그 자리와 **같은 값**입니다. 둘째,
`~x` 는 정의상 자리마다 `x` 의 반대이므로 그 구간에서 두 값이 함께 1 인 자리가 있을 수
없어요. 위 표의 셋째 열과 넷째 열이 같고, 둘째 열과 넷째 열이 반대인 것이 그 둘입니다.

```text
자리 4 이상을 확인하지 않아도 되는 이유

  T6 에서 얻은 것    자리올림 = 0
  그래서             자리 4 이상은 뒤집은 값이 그대로다        더한 것이 없다
  뒤집은 값은        자리마다 x 의 반대다                      정의가 그렇다
  그러므로           그 구간의 AND 는 자리마다 0 이다          1 과 0 을 AND 한 것이다
  └ 확인해야 하는 자리는 자리올림이 지나간 구간(T3~T6)뿐이고, 그 위는 정의로 끝난다
```

값이 몇이든 자리 폭이 몇이든 이 논증이 그대로 성립합니다. 그래서 T7 한 걸음이 「자리 4 부터
위」를 한꺼번에 처리할 수 있는 것이고, 자리 폭이 64 가 되어도 걸음이 안 늘어나요.
