# x & -x — 자리올림이 최하위 1 비트에서 멈춰 검사 없이 그 비트만 남는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 자리를 하나씩
검사하는 방법에서 출발해 검사를 아예 없애는 `x & -x` 까지 가고, 그 식이 기대는 `-x` 의 모양을 단계마다 값으로
푼 뒤, 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

32 비트 정수 `x` 에서 **1 인 자리 가운데 가장 낮은 자리 하나만 남기고** 나머지 자리를 전부 0 으로 만든 값을
구하는 방법입니다. 이 글은 그 자리의 1 을 **최하위 1 비트**라고 부르고, 그 자리 번호를 `p` 라고 적습니다.
40 은 이진수로 `00101000₂` 라 자리 3 과 자리 5 가 1 이고, 최하위 1 비트는 자리 3 이에요. 그래서 답은 그 자리의
값 `2^3 = 8` 입니다. 1 인 자리가 하나도 없으면(입력이 0) 답은 0 이에요.

쓰는 식은 **`x & -x`** 하나입니다. `-x` 는 기계가 음수를 적는 방식인 **32 비트 2 의 보수**로 읽은 값이고, 그
값은 `x` 의 모든 자리를 뒤집은 뒤 1 을 더한 것과 같아요. 40 에서 그 넷을 자리마다 늘어놓으면 이렇습니다.

<!--fig:concept-bits-->
![x = 40 의 아래 여덟 자리 — x 와 -x 가 함께 1 인 자리는 최하위 1 비트 자리 3 하나](./figs/concept-bits.svg)

뒤집은 값 `~x` 에 1 을 더하면 자리 0 부터 자리올림이 올라가다가 **자리 3 에서 멈춥니다.** 그 결과 `-x` 는 자리 3
과 그 아래가 `x` 와 같고, 자리 3 위는 `x` 의 반대가 돼요. 그래서 두 값을 AND 하면 자리 3 하나만 남습니다. 다른
입력에서도 그런지 여섯 값을 실행해 보았습니다.

<!--proof:concept-samples-->

| x | x 의 아래 여덟 자리 | -x 의 아래 여덟 자리 | x & -x 의 아래 여덟 자리 | x & -x | 최하위 1 비트의 자리 p |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 40 | 00101000₂ | 11011000₂ | 00001000₂ | 8 | 3 |
| 12 | 00001100₂ | 11110100₂ | 00000100₂ | 4 | 2 |
| 8 | 00001000₂ | 11111000₂ | 00001000₂ | 8 | 3 |
| 1 | 00000001₂ | 11111111₂ | 00000001₂ | 1 | 0 |
| 0 | 00000000₂ | 00000000₂ | 00000000₂ | 0 | 없음 |
| -12 | 11110100₂ | 00001100₂ | 00000100₂ | 4 | 2 |

x 가 0 이 아닌 다섯 줄에서 x & -x 에는 1 비트가 하나씩 있고, 그 자리가 p 와 일치합니다. x 가 0 인 줄은 -x 도 0 이라 답이 0 입니다.

<!--/proof-->

자리를 하나씩 검사하는 반복문도, 값의 크기를 재는 비교도 없습니다. 비용은 결과만 적으면 시간 `O(1)` 이고, 정본이
실제로 쓰는 것을 정본 소스에서 세면 이렇습니다.

<!--proof:concept-cost-->

| 정본이 쓰는 것 | 수 |
| --- | ---: |
| 부호 뒤집기 `-` | 1 번 |
| 비트 AND `&` | 1 번 |
| 반복문 · 조건문 | 0 개 |
| 입력 밖에 새로 잡는 칸 | 0 칸 |

정본 소스의 반환식 `x & -x` 에서 센 값입니다. 기본 연산은 모두 2 번이고, 어떤 입력이 들어와도 같은 연산을 실행합니다.

<!--/proof-->

이 절차가 기대는 조건은 둘이에요.

| 조건 | 쓰이는 곳 | 깨지면 |
| --- | --- | --- |
| 음수를 고정 폭 2 의 보수로 적는다 | `-x` 가 「뒤집고 1 을 더한 값」이다 | 자리올림이 자리 `p` 에서 멈추지 않아 다른 모양이 나온다 |
| 값이 32 비트 정수 범위 안이다 | JavaScript 의 `&` 가 값을 32 비트로 바꿔 계산한다 | 자리 32 위의 1 비트가 잘려 없어진다 |

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **이진 표기와 자리 번호.** 정수를 2 의 거듭제곱의 합으로 적는 법입니다. 가장 낮은 자리가 자리 0 이고, 자리
  `j` 의 1 은 `2^j` 를 뜻해요. 이 글이 답으로 내는 것은 자리 번호가 아니라 **그 자리의 값**입니다.
- **비트 AND(`&`)와 비트 뒤집기(`~`).** 두 연산 모두 자리마다 따로 계산됩니다. `&` 는 두 수의 같은 자리가 둘 다
  1 일 때만 1 을 두고, `~` 는 모든 자리의 0 과 1 을 바꿔요.
- **덧셈의 자리올림.** 한 자리에서 1 + 1 이 되면 그 자리가 0 이 되고 1 이 위 자리로 넘어갑니다. 이 글은 그
  자리올림이 **어디서 멈추는가**만 봅니다.
- **32 비트 2 의 보수.** 음수 `-x` 를 「`x` 의 모든 자리를 뒤집고 1 을 더한 값」으로 적는 방법이에요. 자리 31 이
  부호 자리라 그 자리가 1 이면 음수로 읽힙니다.
- **JavaScript 의 비트 연산은 값을 32 비트 부호 있는 정수로 바꾼 다음 계산한다는 것.** 이 사실이 「수행으로
  알아보는 알고리즘」의 두 번째 짚고 가기와 「이 방법이 기대는 전제」에서 쓰입니다.

이 글이 쓰는 식 몇 개를 실제로 계산하면 이렇습니다.

<!--proof:prereq-ops-->

| 식 | 계산 | 결과 |
| --- | --- | ---: |
| `40 & 12` | 101000₂ 과 001100₂ 에서 둘 다 1 인 자리만 1 | 8 (001000₂) |
| `~40` | 모든 자리를 뒤집는다 | -41 |
| `~40 + 1` | 뒤집은 값에 1 을 더한다 | -40 |
| `-40` | 부호를 뒤집는다 | -40 |
| `7 + 1` | 0111₂ 에서 자리올림이 세 자리를 넘어간다 | 8 (1000₂) |
| `(2 ** 31) \| 0` | 자리 31 이 부호 자리로 읽힌다 | -2147483648 |
| `(2 ** 32 + 8) \| 0` | 자리 32 위가 잘린다 | 8 |

`~40 + 1` 과 `-40` 이 둘 다 -40 입니다. 아래 두 줄은 비트 연산이 값을 먼저 32 비트 정수로 바꾼 뒤 계산한다는 것을 보입니다.

<!--/proof-->

같은 갈래에서 `x & -x` 와 모양이 닮은 식을 쓰는 가이드가 둘 있습니다. 1 을 뺀 값을 AND 로 걸러 다음 후보로
건너뛰는 [`enumerateSubmasks`](../enumerateSubmasks/enumerateSubmasks-guide.md) 와, 같은 값을 두 번 겹쳐 지우는
[`singleNumberXor`](../singleNumberXor/singleNumberXor-guide.md) 예요. 이 글을 읽는 데 두 가이드가 필요하지는
않습니다.

### 아이디어를 떠올리는 과정 — 자리마다 검사하기에서 x & -x 까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 32 비트 정수를 받아서, 최하위 1 비트만
남긴 값을 돌려줍니다.

```ts
function lowestSetBit(x: number): number;
```

- 입력: 32 비트 정수 `x` 하나. 음수도 들어옵니다. 범위는 `-2^31 ≤ x ≤ 2^31 - 1` 이에요.
- 출력: `x` 에서 최하위 1 비트만 남기고 나머지 자리를 0 으로 만든 값. 1 비트가 없으면 0 입니다. 답도 32 비트
  정수로 돌려주므로, 답이 자리 31 이면 음수로 적힙니다.
- 규모: 호출 한 번은 값 하나를 다루지만, 이 연산은 반복문 안에서 불립니다. 펜윅 트리는 질의마다, 비트마스크로
  든 집합은 원소를 꺼낼 때마다 이것을 불러요. 그래서 규모를 **호출 횟수 `N`** 으로 적고, `N = 10^7` 번 호출을
  흔한 채점 환경의 예산인 1 초에 대어 잽니다. 단순 연산을 1 초에 1 억 번으로 어림합니다.

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `x` | 입력으로 받는 32 비트 정수 | `-2^31 ≤ x ≤ 2^31 - 1` |
| `j` | 자리 번호. 가장 낮은 자리가 0 이다 | `0 ≤ j ≤ 31` |
| `p` | `x` 의 최하위 1 비트의 자리 번호 | `x ≠ 0` 일 때 `0 ≤ p ≤ 31` |
| `~x` | `x` 의 모든 자리를 뒤집은 값 | 값 하나 |
| `-x` | `~x` 에 1 을 더한 값. 32 비트 2 의 보수로 적은 `x` 의 음수다 | 값 하나 |
| `w` | 자리 폭. 그림과 표는 그중 아래 여덟 자리만 그린다 | 32 |
| `N` | 호출 횟수 | `10^7` |

가장 먼저 떠오르는 방법은 자리 0 부터 차례로 1 인지 보는 것입니다. 아무 자료구조도 쓰지 않는, 가장 단순한
방법이에요.

```ts
function scanEachBit(x: number): number {
  for (let j = 0; j < 32; j++) {
    // 자리 하나마다 검사 한 번. 처음 1 을 만난 자리가 답이다.
    if (((x >>> j) & 1) === 1) return 1 << j;
  }
  return 0;
}
```

이 방법은 답을 틀리지 않습니다. 비용은 **기본 연산**으로 세는데, 이 글은 부호 뒤집기 · 비트 AND · 비트 뒤집기 ·
오른쪽 밀기 · 왼쪽 밀기 · 비교 · 대입 · 증가를 한 번씩 기본 연산으로 셉니다. 1 비트가 자리 `p` 하나뿐인 입력으로
`p` 를 옮겨 가며 세고, 같은 입력을 `N` 번 부를 때의 합도 적었습니다.

<!--proof:origin-scan-cost-->

| 자리 p | x | 호출 한 번의 기본 연산 | 5p + 6 | N = 10,000,000 번의 기본 연산 | 초당 1 억 번 기준 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 1 | 6 | 6 | 60,000,000 | 0.60 초 |
| 1 | 2 | 11 | 11 | 110,000,000 | 1.10 초 |
| 2 | 4 | 16 | 16 | 160,000,000 | 1.60 초 |
| 3 | 8 | 21 | 21 | 210,000,000 | 2.10 초 |
| 15 | 32,768 | 81 | 81 | 810,000,000 | 8.10 초 |
| 30 | 1,073,741,824 | 156 | 156 | 1,560,000,000 | 15.60 초 |
| 31 | -2,147,483,648 | 161 | 161 | 1,610,000,000 | 16.10 초 |
| 없음 | 0 | 162 | — | 1,620,000,000 | 16.20 초 |

1 비트가 있는 일곱 줄 모두 센 값과 5p + 6 이 일치합니다. x = 0 은 1 비트가 없어 자리 31 까지 다 검사하므로 162 번입니다.

<!--/proof-->

예산 1 초 안에 드는 것은 답이 자리 0 인 줄뿐이고, 답이 높은 자리에 있을수록 한 줄씩 더 오래 걸립니다. 호출 한
번의 비용이 **답이 있는 자리 번호**를 따라가기 때문이에요. 무엇을 되풀이하는지 전개 입력 40 에서 봅시다.

<!--proof:origin-scan-walk-->

| j | x >>> j | (x >>> j) & 1 | 판정 | 누적 기본 연산 |
| ---: | ---: | ---: | --- | ---: |
| 0 | 40 (00101000₂) | 0 | 0 — 다음 자리로 | 5 |
| 1 | 20 (00010100₂) | 0 | 0 — 다음 자리로 | 10 |
| 2 | 10 (00001010₂) | 0 | 0 — 다음 자리로 | 15 |
| 3 | 5 (00000101₂) | 1 | 1 — `1 << 3` 을 돌려준다 | 21 |

j = 3 에서 1 을 만나 8 을 돌려줍니다. 기본 연산은 21 번이고, 그 앞의 검사 세 번은 자리 3 아래가 0 이라는 것을 한 자리씩 확인한 것입니다.

<!--/proof-->

검사 네 번 가운데 앞의 세 번은 「이 자리는 0」을 확인하는 데 쓰였습니다. 최하위 1 비트의 정의가 「그 아래가 전부
0 인 1」이니, 이 방법은 정의를 한 자리씩 그대로 확인하고 있는 셈이에요. 같은 호출 수를 두 입력 모양으로 넣고, 뒤에서
세울 `x & -x` 와 나란히 세어 보았습니다.

<!--proof:origin-two-shapes-->

| 넣는 값 | 자리마다 검사의 기본 연산 | 초당 1 억 번 기준 | x & -x 의 기본 연산 | 초당 1 억 번 기준 |
| --- | ---: | ---: | ---: | ---: |
| 1 부터 10,000,000 까지 한 번씩 | 109,999,960 | 1.10 초 | 20,000,000 | 0.20 초 |
| -2,147,483,648 만 10,000,000 번 | 1,610,000,000 | 16.10 초 | 20,000,000 | 0.20 초 |

호출 수가 같은데 자리마다 검사는 두 모양 사이에서 14.6 배 차이가 나고, x & -x 는 두 줄이 같은 값입니다. 1 부터 N 까지 넣었을 때 자리 p 를 모두 더하면 9,999,992 입니다.

<!--/proof-->

1 부터 `N` 까지를 넣으면 자리 번호가 대부분 작아서 예산 가까이에서 끝나지만, 답이 자리 31 인 값만 넣으면 예산을
훨씬 넘습니다. `x & -x` 는 두 모양에서 같은 값이에요. 여기서 관찰한 것이 이것입니다. **비용을 정하는 것은 값의 크기가 아니라 `p` 이고, `p` 를 찾는 일 자체가
비용입니다.** 그렇다면 `p` 를 찾지 않고도 「`p` 아래는 0, `p` 는 1」을 한 번에 쓰는 산술이 있으면 됩니다.

가장 단순한 후보부터 시험해 봅시다. 자리 `p` 만 남기려면 `x` 와 AND 할 값 하나가 있으면 되고, 흔한 모양을 여섯
만들어 같은 입력에 넣어 보았습니다.

<!--proof:origin-candidates-->

| 식 | 연산 수 | x = 40 | x = 12 | x = 1 | x = 0 | x = -12 | 0 이상 65,536 미만과 경계 여덟 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| `x & ~x` | 2 | 0 | 0 | 0 | 0 | 0 | 틀림 |
| `x & (x - 1)` | 2 | 32 | 8 | 0 | 0 | -16 | 틀림 |
| `x & (x + 1)` | 2 | 40 | 12 | 0 | 0 | -12 | 틀림 |
| `x & ~(x - 1)` | 3 | 8 | 4 | 1 | 0 | 4 | 전부 맞음 |
| `x ^ (x & (x - 1))` | 3 | 8 | 4 | 1 | 0 | 4 | 전부 맞음 |
| `x & -x` | 2 | 8 | 4 | 1 | 0 | 4 | 전부 맞음 |
| 정의가 낸 답 | — | 8 | 4 | 1 | 0 | 4 | — |

마지막 열이 「전부 맞음」인 식은 세 개이고, 그중 연산 수가 가장 적은 것은 `x & -x` 로 2 번입니다.

<!--/proof-->

`x & ~x` 는 모든 자리가 반대라 어느 자리도 못 남깁니다. `x & (x - 1)` 은 자리 `p` 를 **지운** 값이라 남기려던
것과 정반대예요. `x & (x + 1)` 은 `p` 가 0 보다 크면 `x + 1` 이 자리 0 만 켜는데 그 자리가 `x` 에서 0 이라 `x`
를 그대로 돌려주고(40 → 40), `p` 가 0 이면 거꾸로 그 자리가 꺼져 0 이 됩니다(1 → 0). 남은 셋은 모두 맞고, 그중
연산이 가장 적은 것이 `x & -x` 입니다. 지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법이 **`x & -x`** 입니다. 자리를 하나도 검사하지 않고, 부호 뒤집기 한 번과 AND 한 번으로 최하위 1 비트만
남깁니다. 이 식이 왜 맞는지, `-x` 가 자리마다 어떻게 생겼는지는 다음 절에서 실현하는 순서대로 풉니다.

### 아이디어 상세 — x & -x

이 아이디어를 한 문장으로 줄이면 이렇습니다. **`x` 를 뒤집고 1 을 더하면 자리올림이 최하위 1 비트에서 멈춥니다. 그래서 `-x` 는 자리 `p` 와 그 아래가 `x` 와 같고
위가 `x` 의 반대가 되고, `x` 와 AND 하면 자리 `p` 하나만 남습니다.**
이 방법이 기대는 것은 `-x` 가 자리마다 어떻게 생겼는가라서 그것부터 따로 설명하고, 그다음 세 단계를 실현 순서대로
설명합니다. 미리 만들어 두는 것이 없어서 세 단계 모두 호출마다 합니다.

| 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- |
| 1단계 모든 자리 뒤집기 | `~x` 를 만든다 | — |
| 2단계 1 을 더해 -x 만들기 | `~x + 1`, 곧 `-x` 를 만든다 | 1단계의 `~x` |
| 3단계 x 와 AND 하기 | `x & -x` 를 돌려준다 | 2단계의 `-x` |

#### 먼저 알아 둘 개념 — -x 의 세 구간

##### 쉬운 말로 한 정의

`-x` 를 자리마다 보면, `x` 의 최하위 1 비트 자리 `p` 를 경계로 **세 구간**으로 갈립니다. 자리 `p` 아래는 `x` 처럼
전부 0 이고, 자리 `p` 는 `x` 처럼 1 이며, 자리 `p` 위는 `x` 와 자리마다 반대예요. 「`-x` 는 `x` 의 반대」라고 한마디로
외우면 이 가운데 위 구간만 맞습니다.

##### 전개 입력 위에 놓은 모습

전개 입력 40 과 그 `-x` 를 자리마다 놓고, 세 구간을 괄호로 묶었습니다. 강조한 칸이 자리 `p` 예요.

<!--fig:build-regions-->
![x = 40 에서 -x 의 세 구간 — 최하위 1 비트 자리 p = 3 을 경계로](./figs/build-regions.svg)

##### 자리 하나를 읽는 법

자리 5 를 골라 그 자리만 따라가 봅시다. 먼저 어느 구간인지 정하고, 그 구간의 규칙으로 `-x` 의 비트를 읽습니다.

<!--proof:build-read-one-->

| 읽는 순서 | 값 |
| --- | --- |
| 고른 자리 | j = 5 |
| x 의 최하위 1 비트 | p = 3 |
| 어느 구간인가 | j = 5 > p = 3 — 자리 p 위 |
| x 의 자리 5 | 1 |
| 위 구간의 규칙 | -x 의 비트는 x 의 비트의 반대 |
| -x 의 자리 5 | 0 (-40 = 11011000₂) |
| x & -x 의 자리 5 | 0 |

자리 5 는 p 보다 위라서 -x 의 비트가 x 의 비트 1 의 반대인 0 이고, 두 비트가 함께 1 이 아니라 x & -x 의 자리 5 는 0 입니다.

<!--/proof-->

읽는 순서는 늘 같습니다. `p` 를 찾아 구간을 정하고, 아래면 0, `p` 면 1, 위면 `x` 의 반대로 읽어요. 이 읽기는
`-x` 를 실제로 계산하지 않고도 그 비트를 알게 해 줍니다.

##### 자리끼리의 관계

이웃한 자리끼리 보면 아래 구간은 전부 같은 값(0)이고, 위 구간은 자리마다 따로 `x` 를 뒤집을 뿐 서로 얽히지
않습니다. 두 구간을 가르는 것은 `~x` 에 더한 1 이에요. `~x` 와 `-x` 를 자리마다 나란히 놓았습니다.

<!--proof:build-neighbors-->

| 구간 | 자리 | x | ~x | -x | ~x 와 -x |
| --- | --- | ---: | ---: | ---: | --- |
| 자리 p 위 | 자리 7 | 0 | 1 | 1 | 같음 |
| 자리 p 위 | 자리 6 | 0 | 1 | 1 | 같음 |
| 자리 p 위 | 자리 5 | 1 | 0 | 0 | 같음 |
| 자리 p 위 | 자리 4 | 0 | 1 | 1 | 같음 |
| 자리 p | 자리 3 | 1 | 0 | 1 | 다름 |
| 자리 p 아래 | 자리 2 | 0 | 1 | 0 | 다름 |
| 자리 p 아래 | 자리 1 | 0 | 1 | 0 | 다름 |
| 자리 p 아래 | 자리 0 | 0 | 1 | 0 | 다름 |

~x 와 -x 가 다른 자리는 자리 3 · 2 · 1 · 0 으로, 자리 p 와 그 아래뿐입니다. 자리 p 위의 네 자리는 두 값이 일치합니다.

<!--/proof-->

1 을 더한 효과는 자리 `p` 와 그 아래에만 남고, 위 구간에는 아무 흔적이 없습니다. 자리올림이 자리 `p` 에서 멈추기
때문이에요. 그래서 위 구간의 자리는 이웃이 어떻든 `~x` 의 그 자리, 곧 `x` 의 반대로 정해집니다.

##### x - 1 의 모양과의 차이

최하위 1 비트를 다루는 식이라면 `x - 1` 을 먼저 떠올리기 쉽습니다. 같은 입력에서 세 구간이 두 값에서 어떻게
다른지 나란히 놓았습니다.

<!--proof:build-vs-minus-one-->

| 값 | 자리 p 위 (7 ~ 4) | 자리 p (3) | 자리 p 아래 (2 ~ 0) | x 와 AND 한 값 |
| --- | ---: | ---: | ---: | ---: |
| `x` | 0010 | 1 | 000 | — |
| `x - 1` | 0010 | 0 | 111 | 32 |
| `-x` | 1101 | 1 | 000 | 8 |

`x - 1` 은 자리 p 와 그 아래를 뒤집고 위를 그대로 두어서, x 와 AND 하면 자리 p 가 지워진 32 가 남습니다. `-x` 는 거꾸로 자리 p 와 그 아래를 x 와 같게 두고 위를 뒤집어서, AND 하면 자리 p 하나인 8 이 남습니다. 32 자리 전부에서 이 규칙을 확인했습니다.

<!--/proof-->

두 값은 뒤집는 구간이 정확히 엇갈립니다. `x - 1` 은 아래쪽을, `-x` 는 위쪽을 뒤집어요. 그래서 `x - 1` 을 한 번 더
뒤집은 `~(x - 1)` 이 `-x` 와 같은 값이 됩니다. 「설계 선택」에서 이 사실을 전수로 확인합니다.

##### 이렇게 생긴 까닭

`x` 와 AND 해서 자리 `p` 하나만 남기려면 구간마다 요구가 다릅니다. `-x` 는 그 요구를 구간마다 정확히 채워요.

| 구간 | `x` 의 모양 | AND 에서 필요한 것 | `-x` 가 주는 것 |
| --- | --- | --- | --- |
| 자리 `p` 아래 | 전부 0 | 무엇이든 된다 | 전부 0 |
| 자리 `p` | 1 | 1 | 1 |
| 자리 `p` 위 | 아무 값 | `x` 가 1 인 자리마다 0 | `x` 의 반대 |

자리 `p` 위에서 `x` 가 1 인 자리를 모두 지우려면 그 자리를 하나하나 찾아야 할 것 같지만, 반대 값과 AND 하면 찾지
않고도 전부 0 이 됩니다. 자리 `p` 가 어디인지 모르는 채로 자리 `p` 에만 1 을 두는 일을 자리올림이 대신해 줘요.

#### 1단계 — 모든 자리 뒤집기

`~x` 를 만듭니다. `x` 에서 자리 `p` 아래는 전부 0 이었으니 뒤집으면 전부 1 이 되고, 자리 `p` 는 1 이었으니 0 이
돼요. 이 모양이 2단계의 자리올림이 멈출 자리를 정합니다. 여러 입력에서 확인했습니다.

<!--proof:build-flip-->

| x | p | ~x 의 아래 여덟 자리 | ~x | ~x 의 자리 p 아래 | ~x 의 자리 p |
| ---: | ---: | ---: | ---: | --- | ---: |
| 40 | 3 | 11010111₂ | -41 | 전부 1 (3 자리) | 0 |
| 12 | 2 | 11110011₂ | -13 | 전부 1 (2 자리) | 0 |
| 1 | 0 | 11111110₂ | -2 | 없음 (p = 0) | 0 |
| -12 | 2 | 00001011₂ | 11 | 전부 1 (2 자리) | 0 |
| 0 | 없음 | 11111111₂ | -1 | 없음 | — |

x 가 0 이 아닌 네 줄 모두 ~x 의 자리 p 아래가 전부 1 이고 자리 p 가 0 입니다. x = 0 은 뒤집으면 32 자리 전부 1 인 -1 입니다.

<!--/proof-->

`p = 0` 인 1 은 아래 구간이 없어 자리 0 부터 곧바로 0 입니다. `x = 0` 은 자리 `p` 가 없어서 32 자리가 전부 1 이
돼요. 이 경우가 2단계에서 가장 불안한 경우입니다.

#### 2단계 — 1 을 더해 -x 만들기

`~x` 에 1 을 더합니다. 자리 0 부터 올라가며 그 자리가 1 이면 1 + 1 이라 0 이 되고 자리올림을 넘기고, 0 이면
0 + 1 이라 1 이 되고 멈춰요. 1단계에서 `~x` 는 자리 `p` 아래가 전부 1 이고 자리 `p` 가 0 이었으니, 자리올림은 아래
구간을 다 넘어가 **자리 `p` 에서 처음으로 멈춥니다.** 쉬운 경우부터 가장 불안한 경우까지 다섯을 재 보았습니다.

<!--proof:build-carry-cases-->

| 경우 | x | p | 자리올림이 넘어간 자리 | 자리올림이 멈춘 자리 | 자리마다 더한 결과 | 자리 31 밖으로 나간 자리올림 |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| 쉬운 경우 — p = 0 | 41 | 0 | 0 자리 | 자리 0 | -41 | 0 |
| 전개 입력 | 40 | 3 | 3 자리 | 자리 3 | -40 | 0 |
| p = 30 | 1,073,741,824 | 30 | 30 자리 | 자리 30 | -1,073,741,824 | 0 |
| 가장 긴 경우 — p = 31 | -2,147,483,648 | 31 | 31 자리 | 자리 31 | -2,147,483,648 | 0 |
| 1 비트가 없다 | 0 | 없음 | 32 자리 | 없음 | 0 | 1 |

1 비트가 있는 네 줄 모두 자리올림이 멈춘 자리가 p 와 일치하고, 다섯 줄 모두 자리마다 더한 결과가 -x 와 일치합니다. x = 0 만 자리올림이 32 자리를 다 넘어가 밖으로 나가고, 남은 32 자리가 전부 0 입니다.

<!--/proof-->

쉬운 경우는 `p = 0` 입니다. 자리 0 에서 곧바로 멈춰요. 불안한 경우는 둘인데, 자리올림이 가장 멀리 가는 `p = 31`
과, 멈출 자리가 아예 없는 `x = 0` 입니다. 둘을 자리마다 적었습니다.

<!--proof:build-carry-long-->

| x | 자리 | ~x 의 비트 | 들어온 자리올림 | 그 자리의 결과 | 넘긴 자리올림 |
| ---: | --- | ---: | ---: | --- | ---: |
| -2,147,483,648 | 자리 0 ~ 30 | 1 | 1 | 0 | 1 |
| -2,147,483,648 | 자리 31 | 0 | 1 | 1 | 0 |
| -2,147,483,648 | 자리 31 밖 | — | 0 | — | — |
| 0 | 자리 0 ~ 31 | 1 | 1 | 0 | 1 |
| 0 | 자리 31 밖 | — | 1 | 버린다 | — |

x = -2,147,483,648 은 자리 0 부터 30 까지 자리올림이 넘어가고 자리 31 에서 멈춥니다. x = 0 은 32 자리 모두 1 + 1 이라 자리올림이 자리 31 밖으로 나가고, 32 비트 정수에는 그 자리가 없어 버려집니다.

<!--/proof-->

`x = 0` 에서 자리올림은 멈추지 않고 32 비트 밖으로 나가는데, 32 비트 정수에는 그 자리가 없어 그대로 버려집니다.
남은 32 자리가 전부 0 이라 `-0 = 0` 이 되고, 따로 막는 줄이 없어도 3단계가 0 을 냅니다.

건너뛰는 자리가 없다는 것은 덧셈의 모양으로 말할 수 있습니다. 자리올림은 1 인 자리를 만나는 동안만 넘어가고
처음 0 인 자리에서 멈추는데, `~x` 에서 처음 0 인 자리가 자리 `p` 입니다. 그 위로는 자리올림이 0 이라 `~x` 의 비트가
그대로 남아요.

| 덧셈이 끝난 시점 | 자리 | 근거 |
| --- | --- | --- |
| 0 이 된 자리 | 자리 `p` 아래 전부 | `~x` 가 전부 1 이라 1 + 1 이 되었다 |
| 1 이 된 자리 | 자리 `p` 하나 | `~x` 의 첫 0 이 자리올림 1 을 받았다 |
| 그대로 남은 자리 | 자리 `p` 위 전부 | 자리올림이 0 이라 더한 것이 없다 |

#### 3단계 — x 와 AND 하기

`x & -x` 를 돌려줍니다. 앞의 세 구간이 그대로 결과가 돼요. 아래 구간은 둘 다 0, 자리 `p` 는 둘 다 1, 위 구간은
서로 반대라 0 입니다. 경우를 나눠 실행했습니다.

<!--proof:build-and-cases-->

| 경우 | x | p | x & -x | 2^p 를 32 비트로 적은 값 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| p = 0 | 41 | 0 | 1 | 1 | 같다 |
| 전개 입력 | 40 | 3 | 8 | 8 | 같다 |
| 1 비트가 전부 켜짐 | -1 | 0 | 1 | 1 | 같다 |
| p = 30 | 1,073,741,824 | 30 | 1,073,741,824 | 1,073,741,824 | 같다 |
| p = 31 | -2,147,483,648 | 31 | -2,147,483,648 | -2,147,483,648 | 같다 |
| 1 비트가 없다 | 0 | 없음 | 0 | 0 | 같다 |

입력을 빠짐없이 넣어 대조하면 이렇습니다.

| 대조한 입력 | 맞은 값 | 전체 |
| --- | ---: | ---: |
| 0 이상 65,536 미만 | 65,536 | 65,536 |
| 1 비트가 자리 p 하나뿐인 값과 그 부호를 뒤집은 값 | 64 | 64 |
| 1 부터 10,000,000 까지 | 10,000,000 | 10,000,000 |

모든 줄에서 x & -x 가 정의대로 적은 2^p 와 일치합니다. p = 31 인 줄만 값이 음수인데, 자리 31 이 32 비트 정수의 부호 자리이기 때문입니다.

<!--/proof-->

`-1` 은 32 자리가 전부 1 이라 1 비트가 가장 많은 값인데, 최하위 1 비트가 자리 0 이라 답이 1 입니다. `p = 31` 인
줄은 답 `2^31` 이 32 비트 부호 있는 정수로 `-2,147,483,648` 로 적혀요. 이 값이 이 계약이 그 답을 적는 유일한
방법입니다.

#### 이 방법이 기대는 전제

`x & -x` 는 아래 전제가 있어야 답을 냅니다. 하나라도 빠지면 틀린 값이 오류 없이 나와요.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 음수를 2 의 보수로 적는다 | 2단계에서 `-x` 가 `~x + 1` 이다 | `-x` 가 다른 모양이 되어 자리 `p` 가 안 남는다 |
| 넘친 자리올림을 버린다 | 2단계의 `x = 0` | `-0` 이 0 이 되지 않는다 |
| 값이 32 비트 정수 범위 안이다 | 3단계의 `&` | 자리 32 위가 잘린다 |

첫 줄은 「불변식」에서 1 을 더하지 않은 판으로 실행해 봅니다. 셋째 줄을 32 비트 밖의 값으로 확인해 보았습니다.

<!--proof:build-premise-->

| x | 십진 | 정의가 낸 답 | x & -x | 판정 |
| --- | ---: | ---: | ---: | --- |
| 2^31 - 1 (범위의 끝) | 2,147,483,647 | 1 | 1 | 같다 |
| 2^32 | 4,294,967,296 | 4,294,967,296 | 0 | 어긋난다 |
| 2^32 + 8 | 4,294,967,304 | 8 | 8 | 같다 |
| 2^33 | 8,589,934,592 | 8,589,934,592 | 0 | 어긋난다 |
| 2^40 + 2^35 | 1,133,871,366,144 | 34,359,738,368 | 0 | 어긋난다 |

다섯 줄 중 세 줄이 어긋납니다. 2^32 + 8 은 자리 32 가 잘려도 최하위 1 비트가 자리 3 에 남아서 답이 맞았고, 어긋난 세 줄은 1 비트가 모두 자리 32 위에 있어 잘린 뒤 0 이 남았습니다.

<!--/proof-->

32 비트를 넘는 값을 다루려면 `BigInt` 로 옮겨야 합니다. `BigInt` 는 자리 폭이 없는 2 의 보수처럼 `&` 와 단항 `-`
를 계산해서, 같은 식 `x & -x` 가 그대로 최하위 1 비트를 남겨요.

#### -x 를 쓰는 까닭

자리 `p` 만 남기는 식은 `x & -x` 말고도 둘이 더 있었습니다. 셋을 같은 입력에서 나란히 실행했습니다.

<!--proof:build-choice-->

| 식 | 연산 수 | 0 이상 65,536 미만에서 맞은 값 | 경계 여덟에서 맞은 값 |
| --- | ---: | ---: | ---: |
| `x & -x` | 2 | 65,536 / 65,536 | 8 / 8 |
| `x & ~(x - 1)` | 3 | 65,536 / 65,536 | 8 / 8 |
| `x ^ (x & (x - 1))` | 3 | 65,536 / 65,536 | 8 / 8 |

세 식 모두 모든 입력에서 답이 맞고, 연산 수만 차이가 납니다. `-x` 와 `~(x - 1)` 은 대조한 65,544 개 값에서 모두 같은 값이었습니다.

<!--/proof-->

셋 다 답이 맞으니 가르는 것은 연산 수뿐입니다. `~(x - 1)` 은 1 을 빼고 뒤집는 두 연산인데, 2 의 보수에서는 그
값이 `-x` 와 같아서 부호 뒤집기 한 번으로 줄어요. `x ^ (x & (x - 1))` 은 자리 `p` 를 지운 값을 만든 뒤 되살리는
길이라 연산이 하나 더 듭니다.

#### 세 단계를 이은 절차

세 단계를 코드의 순서로 다시 적으면 이렇습니다. 전체 코드에서는 1단계와 2단계가 `-x` 한 번으로 적혀요.

1. `x` 의 모든 자리를 뒤집어 `~x` 를 만든다
2. `~x` 에 1 을 더한다 — 그 값이 `-x` 다
3. `x & -x` 를 돌려준다

### 수행으로 알아보는 알고리즘 — 40 에서 자리올림이 자리 3 에 멈춰 8 이 남는다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다 그
조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const x = 40;
// 이 절이 끝나면 8 이 나와야 한다
```

이 입력을 고른 까닭은 셋입니다. 최하위 1 비트가 자리 3 이라 자리올림이 자리 0 · 1 · 2 를 넘어가 자리 3 에서
멈추는 것을 세 걸음으로 볼 수 있어요(자리 0 이면 한 걸음에 끝나 넘어가는 모습이 안 보입니다). 자리 3 위에 1
비트가 하나 더 있어서(자리 5) 위 구간이 뒤집힌 채 남는 것이 함께 보입니다. `x` · `~x` · 답이 전부 아래 여덟
자리 안에 들어와요.

```text
lowestSetBit(x):
    ~x 를 만든다                         ① 모든 자리를 뒤집는다
    ~x 에 1 을 더해 -x 를 만든다         ② 자리올림이 자리 p 에서 멈춘다
    x & -x 를 돌려준다                   ③ 함께 1 인 자리만 남긴다
```

#### 1. 모든 자리를 뒤집는다

첫 조각은 `~x` 하나입니다. 자리 `p` 아래를 전부 1 로, 자리 `p` 를 0 으로 만들어 2단계의 자리올림이 멈출 자리를
마련해요.

```ts
const flipped = ~x; // ① 모든 자리를 뒤집는다
```

실행하면 이렇게 나옵니다.

<!--proof:walk-flip-->

```text
x   = 00101000₂ = 40
~x  = 11010111₂ = -41    (위 24 자리는 전부 1)
```

여기까지는 `x` 와 함께 1 인 자리가 하나도 없습니다. 뒤집은 값은 자리마다 `x` 의 반대라 지금 AND 하면 어느 자리도
안 남아요. 자리 3 을 되살리는 것이 다음 조각입니다. 조각에서는 `flipped` 와 `negated` 라는 이름을 쓰지만 전체
코드에서는 두 이름이 없어지고 `-x` 한 번으로 적힙니다.

#### 짚고 가기 — x & (x - 1) 과 바꿔 쓰면 답이 어긋난다

여기서 헷갈리기 쉬운 지점은 **`x & (x - 1)` 과 이 식을 바꿔 쓰는 것**입니다. 둘 다 최하위 1 비트를 다루는 유명한
식이라 「최하위 1 비트를 꺼내는 식」으로 한데 묶어 외우기 쉬워요. 그 생각대로 적은 판입니다.

```ts
function clearInsteadOfKeep(x: number): number {
  return x & (x - 1); // 「최하위 1 비트」를 이 식으로 적었다
}
```

이 판과 정본을 여섯 입력에 함께 실행해 보았습니다.

<!--proof:pause-clear-->

| 입력 | x 의 아래 여덟 자리 | 정본 | x & (x - 1) | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 40 | 00101000₂ | 8 | 32 | 어긋난다 |
| 12 | 00001100₂ | 4 | 8 | 어긋난다 |
| 8 | 00001000₂ | 8 | 0 | 어긋난다 |
| 1 | 00000001₂ | 1 | 0 | 어긋난다 |
| 0 | 00000000₂ | 0 | 0 | 같다 |
| -12 | 11110100₂ | 4 | -16 | 어긋난다 |

여섯 줄 중 다섯 줄에서 답이 어긋나고, x 가 0 인 줄에서만 두 값이 일치합니다. 그때 `x - 1` 은 모든 자리가 1 인 -1 이지만, 0 과 AND 하면 어느 식이든 0 이 나옵니다.

<!--/proof-->

`x - 1` 은 자리 `p` 와 그 아래를 뒤집으므로, `x` 와 AND 하면 **자리 `p` 만 지워진** 값이 남습니다. 최하위 1 비트를
남기는 식이 아니라 지우는 식이에요. 두 식이 어떤 관계인지 지운 값에서 답을 되찾아 보았습니다.

<!--proof:pause-clear-fix-->

| 입력 | x & (x - 1) | x ^ (x & (x - 1)) | 정본 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 40 | 32 | 8 | 8 | 같다 |
| 12 | 8 | 4 | 4 | 같다 |
| 8 | 0 | 8 | 8 | 같다 |
| 1 | 0 | 1 | 1 | 같다 |
| 0 | 0 | 0 | 0 | 같다 |
| -12 | -16 | 4 | 4 | 같다 |

여섯 줄 모두 지운 값을 x 에서 덜어 낸 값이 정본의 답과 일치합니다. 지우는 식과 남기는 식은 x 의 1 비트를 나눠 가진 짝이라, 한쪽에서 다른 쪽을 얻으려면 XOR 이 하나 더 듭니다.

<!--/proof-->

#### 2. 1 을 더해 자리올림이 멈추는 자리를 본다

둘째 조각은 덧셈 하나입니다. 자리 0 부터 자리올림이 올라가는데, 뒤집은 값의 자리가 1 인 동안은 계속 넘어가고
0 을 만나면 거기서 멈춰요.

```ts
const negated = flipped + 1; // ② 1 을 더한다. 이 값이 32 비트 2 의 보수의 -x 다
```

자리마다 갈라 실행하면 이렇게 나옵니다.

<!--proof:walk-carry-->

| 자리 | ~x 의 비트 | 들어온 자리올림 | 더하기 | 결과 비트 | 넘긴 자리올림 |
| --- | ---: | ---: | --- | ---: | --- |
| 자리 0 | 1 | 1 | 1 + 1 = 2 | 0 | 1 — 위로 넘긴다 |
| 자리 1 | 1 | 1 | 1 + 1 = 2 | 0 | 1 — 위로 넘긴다 |
| 자리 2 | 1 | 1 | 1 + 1 = 2 | 0 | 1 — 위로 넘긴다 |
| 자리 3 | 0 | 1 | 0 + 1 = 1 | 1 | 0 — 여기서 멈춘다 |
| 자리 4 ~ 31 | ~x 그대로 | 0 | 더할 것이 없다 | ~x 그대로 | 0 |

자리 3 에서 자리올림이 멈춥니다. 자리마다 모은 32 자리는 -40 이고, `-x` 와 일치합니다.

<!--/proof-->

멈춘 자리가 자리 3 인 까닭은 `~x` 에서 자리 3 아래가 전부 1 이고 자리 3 이 처음 0 인 자리이기 때문입니다. 1단계의
조각이 정확히 그 모양을 만들어 두었어요.

#### 짚고 가기 — 과제의 범위 안에 답이 음수인 입력이 하나 있다

여기서 간과하기 쉬운 지점은 **답의 부호**입니다. 「최하위 1 비트만 남긴 값」이라면 언제나 0 이상일 것 같아서,
결과가 음수로 나오면 코드가 잘못됐다고 읽기 쉬워요. 그 생각대로 부호를 고쳐 돌려주는 판을 적어 봅시다.

```ts
function forcePositive(x: number): number {
  const r = x & -x;
  return r < 0 ? -r : r; // 「답은 언제나 0 이상」이라는 생각대로 고쳤다
}
```

두 판을 경계에 있는 입력들에 실행해 보았습니다.

<!--proof:pause-negative-->

| 경계 | x | 정본 | 부호를 뒤집어 낸 값 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 값이 0 | 0 | 0 | 0 | 같다 |
| 1 비트가 자리 0 하나 | 1 | 1 | 1 | 같다 |
| 1 비트가 전부 켜짐 | -1 | 1 | 1 | 같다 |
| 전개 입력 | 40 | 8 | 8 | 같다 |
| 음수 | -12 | 4 | 4 | 같다 |
| 범위의 위쪽 끝 | 2,147,483,647 | 1 | 1 | 같다 |
| 범위의 아래쪽 끝 | -2,147,483,648 | -2,147,483,648 | 2,147,483,648 | 어긋난다 |
| 자리 30 하나 | 1,073,741,824 | 1,073,741,824 | 1,073,741,824 | 같다 |

여덟 줄 중 일곱 줄은 두 값이 일치하고, 어긋나는 줄은 한 줄입니다. 1 비트가 자리 p 하나뿐인 값 32 개 가운데 답이 음수인 것은 1 개이고, 그 자리는 31 입니다.

<!--/proof-->

**표의 거의 모든 줄에서 답이 안 틀립니다.** 그래서 이 판은 시험을 대부분 통과한 채로 넘어가기 쉬워요.
어긋나는 한 줄은 `x = -2^31` 이고, 그때 답인 `2^31` 은 32 비트 부호 있는 정수의 범위를 한 칸 넘습니다. 그 값을
32 비트로 적은 것이 자리 31 하나만 켜진 `-2,147,483,648` 이고, 부호를 뒤집은 `2,147,483,648` 은 32 비트 정수가
담을 수 없는 값이에요.

| 따져 볼 것 | 값 |
| --- | --- |
| 답이 자리 31 이려면 | 자리 0 부터 30 까지가 전부 0 이어야 한다 |
| 그런 32 비트 정수 | 자리 31 하나만 켜진 `-2^31` 하나뿐이다 |
| 그때 답 | 같은 값 `-2^31`. 자리 31 이 부호 자리라 음수로 적힌다 |

답을 32 비트 정수로 돌려주기로 한 이상 음수 답은 고칠 결함이 아니라 그 답을 적는 방법입니다.

#### 3. 두 값을 AND 해 답을 낸다

셋째 조각은 AND 하나입니다. 앞의 두 조각이 만든 값을 원래 값과 겹치면 함께 1 인 자리만 남아요.

```ts
return x & negated; // ③ 두 값이 함께 1 인 자리만 남긴다
```

세 조각을 이어 고정 입력에 실행하면 아홉 걸음이 나옵니다. `T1` 이 입력, `T2` 가 뒤집기, `T3` 부터 `T7` 까지가
덧셈, `T8` 이 AND, `T9` 가 반환이에요. 무대의 맨 윗줄이 `x` 의 아래 여덟 자리인데, 칸 `j` 가 자리 `j` 라 이진
표기와 좌우가 거꾸로입니다. 그 아래 세 줄이 `~x` · `-x` · `x & -x` 이고, 아직 정해지지 않은 자리는 비어 있어요.
괄호 「보는 자리」가 그 걸음이 다루는 자리, ▲ 가 이번에 읽은 자리, 강조 칸이 이번에 새로 정한 자리입니다.

| T1 | — 입력 | — | — | ???????? | — | — |

`T3` 부터 `T5` 까지 자리올림이 1 이라 위로 넘어가고, `T6` 에서 `0 + 1` 이 1 이 되며 자리올림이 0 이 됩니다. `T7` 은
자리올림이 0 이라 자리 4 부터 위를 한꺼번에 `~x` 그대로 둬요. 갈래마다 실행된 걸음을 모으면 모든 갈래가 한 번
이상 나왔습니다.

<!--proof:walk-branches-->

| 갈래 | 하는 일 | 걸음 | 걸음 수 |
| --- | --- | --- | ---: |
| ① | 모든 자리를 뒤집는다 | T2 | 1 걸음 |
| ② | 1 을 더해 -x 를 만든다 | T3 T4 T5 T6 T7 | 5 걸음 |
| ③ | 두 값을 AND 해 돌려준다 | T8 T9 | 2 걸음 |

세 갈래가 모두 한 번 이상 실행됐습니다. 그중 기계가 실행하는 기본 연산은 부호 뒤집기와 AND 를 합쳐 2 번입니다.

<!--/proof-->

`②` 의 다섯 걸음은 사람이 읽으려고 자리마다 갈라 놓은 것이지 기계가 다섯 번 실행하는 것이 아닙니다. 기계에서는
`-x` 가 부호 뒤집기 한 번이에요.

#### 4. 전체 코드

조각을 하나로 잇습니다. 위에서 `~x` 와 `+ 1` 로 갈라 본 두 걸음은 `-x` 한 번으로 적히고, 조각에서 잡았던 두 이름도
없어져요.

```ts
export function lowestSetBit(x: number): number {
  // ① 모든 자리를 뒤집는다 — 자리 p 아래가 전부 1 이 되고 자리 p 자신은 0 이 된다.
  // ② 거기에 1 을 더한다 — 자리올림이 자리 p 에서 멈추고, 그 값이 32 비트 2 의 보수다.
  // ③ 두 값이 함께 1 인 자리만 남긴다. 입력이 0 이면 부호를 뒤집어도 0 이라 결과가 0 이다.
  return x & -x;
}
```

여러 입력에 실행한 결과입니다.

<!--proof:walk-final-->

```text
lowestSetBit(40)            →   8
lowestSetBit(12)            →   4
lowestSetBit(1)             →   1
lowestSetBit(0)             →   0
lowestSetBit(-12)           →   4
lowestSetBit(2147483647)    →   1
lowestSetBit(-2147483648)   →   -2147483648
```

### 알아 두면 좋은 개념 — 법 2^32 에서의 덧셈 역원

앞에서 「모든 자리를 뒤집고 1 을 더한다」로 적은 것에는 다른 이름이 있습니다. 32 비트 정수를 부호 없이 읽은 값
`u` 를 **`2^32` 로 나눈 나머지**로 보면, `-x` 는 `x` 와 더해서 0 이 되는 값, 곧 **덧셈 역원**이고 그 값이 `2^32 - u`
예요. 2 의 보수는 그 나머지 셈을 자리 뒤집기와 1 더하기로 실행합니다. 이 글의 여섯 입력으로 확인했습니다.

<!--proof:related-modulo-->

| x | x 를 부호 없이 읽은 값 u | -x 를 부호 없이 읽은 값 | (2^32 - u) 를 2^32 로 나눈 나머지 | 두 값의 합을 2^32 로 나눈 나머지 | 판정 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 40 | 40 | 4,294,967,256 | 4,294,967,256 | 0 | 같다 |
| 12 | 12 | 4,294,967,284 | 4,294,967,284 | 0 | 같다 |
| 8 | 8 | 4,294,967,288 | 4,294,967,288 | 0 | 같다 |
| 1 | 1 | 4,294,967,295 | 4,294,967,295 | 0 | 같다 |
| 0 | 0 | 0 | 0 | 0 | 같다 |
| -12 | 4,294,967,284 | 12 | 12 | 0 | 같다 |

여섯 줄 모두 -x 가 2^32 - u 와 일치하고, x 와 더해 2^32 로 나눈 나머지가 0 입니다.

<!--/proof-->

`x = 0` 인 줄은 `2^32 - 0 = 2^32` 를 `2^32` 로 나눈 나머지가 0 이라 맞습니다. 2단계에서 자리올림이 32 비트 밖으로
나가 버려진 것이 바로 이 나머지 셈이에요. 넘친 자리를 버리는 것이 오류가 아니라 **정의된 동작**이라는 점이 다른
자리에서도 같은 이름으로 쓰입니다.

| 쓰이는 자리 | `2^32` 로 나눈 나머지인 것 | 얻는 것 |
| --- | --- | --- |
| `x & -x` | `-x` 가 `2^32 - u` 다 | 뺄셈 없이 자리 하나를 꺼낸다 |
| 기계의 뺄셈 | `a - b` 를 `a + (2^32 - b)` 로 계산한다 | 덧셈기 하나로 뺄셈까지 처리한다 |
| 해시 혼합 함수 | 곱셈 결과의 위 자리를 버린다 | 값이 늘 32 비트 안에 머문다 |
| 크기가 2 의 거듭제곱인 원형 버퍼 | `(i - 1) & (n - 1)` 로 뒤로 간다 | 음수 인덱스를 따로 막지 않아도 된다 |

이 이름을 몰라도 `x & -x` 는 그대로 읽힙니다. 다만 「값이 넘치면 위 자리를 버린다」는 자리를 다른 곳에서 만났을 때
그것이 `2^32` 로 나눈 나머지라는 것을 알면, 넘친 값을 예외로 다루지 않아도 돼요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 `x & -x` 를 쓰는지, 자리마다 검사의 비용을 식으로 어떻게 닫는지,
무엇이 늘 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때 `x & -x` 가 가장 알맞습니다.

- **값이 고정 폭 정수로 나타내집니다.** 자리 폭이 정해져 있어야 뒤집기가 뜻을 갖고, 음수를 2 의 보수로 적어야
  자리올림이 자리 `p` 에서 멈춥니다.
- **필요한 것이 자리 번호가 아니라 그 자리의 값입니다.** 「몇 번 자리인가」를 물으면 표 조회나 앞자리 0 세기가
  한 단계 더 붙어요.
- **호출마다 같은 비용이 요구됩니다.** 조건문이 없어서 어떤 입력에서도 같은 연산을 실행하므로, 비용이 값에 안
  달립니다.
- **자리 폭이 커질 수 있습니다.** 64 비트로 옮겨도 연산이 부호 뒤집기와 AND 그대로예요.

| 조건 | 코드에 나타나는 모양 |
| --- | --- |
| 고정 폭 정수다 | 부호 뒤집기와 AND 로 자리를 다룬다 |
| 자리의 값이 필요하다 | 자리 번호로 되돌리는 단계가 없다 |
| 비용이 값에 안 달려야 한다 | 조건문도 반복문도 없다 |
| 자리 폭이 커진다 | 연산 수가 자리 폭과 상관없다 |

둘째 조건이 이 절차의 경계입니다. 질문이 바뀌면 최하위 1 비트 하나로는 답이 안 나와요.

| 같은 값에 묻는 것 | `x & -x` 의 답 | 필요한 것 |
| --- | --- | --- |
| 최하위 1 비트의 값 | 답한다 | 연산 두 번 |
| 그 비트가 몇 번 자리인가 | 한 단계 더 간다 | 표 조회나 앞자리 0 세기 |
| 가장 높은 1 비트의 값 | 답하지 못한다 | 자리올림은 아래에서 위로만 간다 |
| 1 비트가 몇 개인가 | 답하지 못한다 | 하나만 남기고 나머지를 버렸다 |

#### 문제에서 이것을 떠올리게 하는 단서

| 보이는 곳 | 이런 말이나 모양 | 뜻 | `x & -x` 사용 |
| --- | --- | --- | --- |
| 지문 | "가장 낮은 1 비트" "가장 오른쪽에 켜진 비트" "우선순위가 가장 높은 플래그" | 최하위 1 비트의 값을 묻는다 | 쓴다 |
| 지문 | "비트마스크에서 원소 하나를 꺼낸다" "집합에서 아무 원소나 하나" | 1 인 자리 하나가 필요하다 | 쓴다 |
| 구조 | 펜윅 트리의 `i += i & -i` · `i -= i & -i` | 칸이 맡는 구간의 길이가 최하위 1 비트다 | 쓴다 |
| 제약 | 값이 32 비트 또는 64 비트 정수로 정해져 있다 | 비트 연산의 폭과 맞는다 | 쓴다 |
| 지문 | "가장 높은 1 비트" | 자리올림이 반대 방향으로는 안 걸린다 | 쓰지 않는다 |
| 지문 | "1 비트의 개수" "몇 번째 자리인지 출력하라" | 값 하나로는 답이 안 된다 | 한 단계를 더 붙인다 |

집합을 정수 하나로 든 반복문이 가장 자주 나오는 모양입니다. 「원소를 하나 꺼내고 그것을 지운다」를 되풀이하는데,
꺼내는 쪽이 `x & -x` 예요.

```ts
// 집합 m 의 원소를 자리 번호가 낮은 것부터 하나씩 꺼낸다. 바퀴 수가 원소 수와 같다.
for (let m = mask; m !== 0; m ^= m & -m) {
  const b = m & -m; // 남은 원소 중 자리 번호가 가장 낮은 것
}
```

펜윅 트리는 같은 갈래가 아닌 [`fenwickRangeSum`](../../array/fenwickRangeSum/fenwickRangeSum-guide.md) 가이드가
다루고, 그 정본이 `k & -k` 를 `lowbit` 라는 이름으로 씁니다.

### 수식 정의와 유도

정수 하나를 2 의 거듭제곱과 홀수의 곱으로 적습니다. `x ≠ 0` 이면 이 갈래가 하나뿐이에요.

$$x = 2^{\nu(x)} \cdot q, \qquad q \text{ 는 홀수}$$

| 기호 | 무엇 | 값을 넣은 예 |
| --- | --- | --- |
| $\nu(x)$ | $x$ 를 2 로 나눌 수 있는 최대 횟수 | $40 = 2^3 \cdot 5$ 이므로 $\nu(40) = 3$ |
| $q$ | 그렇게 나누고 남은 홀수 | $x = 40$ 이면 5 |
| $s_2(N)$ | $N$ 의 이진 표기에 있는 1 의 개수 | $N = 10$ 이면 2 |
| $A(N)$ | 자리마다 검사가 $x = 1 \dots N$ 에서 쓰는 기본 연산의 합 | 아래에서 닫는다 |

$\nu(x)$ 는 「2 로 몇 번 나눠지는가」이고, 앞에서 `p` 라 부른 자리 번호와 같은 것입니다. 답은 그 자리의 값이므로
$2^{\nu(x)}$ 예요. 정의를 값에 넣어 검산하고, 이어서 1 부터 $N$ 까지의 $\nu$ 를 실제로 더해 봅니다.

<!--proof:math-check-->

| x | ν(x) | 2^ν(x) | 정본 |
| ---: | ---: | ---: | ---: |
| 40 | 3 | 8 | 8 |
| 12 | 2 | 4 | 4 |
| 1 | 0 | 1 | 1 |
| 1,024 | 10 | 1,024 | 1,024 |
| 0 | 없음 | 0 | 0 |

1 부터 N 까지의 ν 를 실제로 더하면 이렇습니다.

| N | Σ ν(x) | s₂(N) | N - s₂(N) |
| ---: | ---: | ---: | ---: |
| 8 | 7 | 1 | 7 |
| 10 | 8 | 2 | 8 |
| 100 | 97 | 3 | 97 |
| 1,000 | 994 | 6 | 994 |

위 표의 셋째 열과 넷째 열이 다섯 줄 모두 일치하고, 아래 표의 둘째 열과 넷째 열이 네 줄 모두 일치합니다.

<!--/proof-->

아래 표의 규칙을 유도합니다. $\nu(x)$ 를 「$x$ 가 $2^j$ 로 나누어떨어지는 $j \ge 1$ 의 개수」로 다시 세면, 합의
순서를 바꿔 $j$ 마다 셀 수 있어요.

$$\sum_{x=1}^{N} \nu(x) = \sum_{j \ge 1} \#\{x \le N : 2^j \mid x\} = \sum_{j \ge 1} \left\lfloor \frac{N}{2^j} \right\rfloor$$

작은 $N$ 에서 두 방향으로 실제로 세어 보았습니다.

<!--proof:math-regroup-->

| 세는 방향 | 항 | 항 수 | 합 |
| --- | --- | ---: | ---: |
| x 마다 ν(x) | 0 + 1 + 0 + 2 + 0 + 1 + 0 + 3 | 8 | 7 |
| j 마다 ⌊N / 2^j⌋ | 4 + 2 + 1 | 3 | 7 |

N = 8 에서 두 방향의 합이 둘 다 7 입니다. 같은 것을 x 마다 세느냐 j 마다 세느냐의 차이라 합이 안 바뀝니다.

<!--/proof-->

이제 오른쪽을 닫습니다. $N$ 을 이진 표기로
$N = \sum_i 2^{a_i}$ 라 두면 $\lfloor N/2^j \rfloor$ 는 $a_i \ge j$ 인 항만 남기므로, 두 합의 순서를 다시 바꿔 각
$i$ 마다 등비수열을 더할 수 있어요.

$$\sum_{j \ge 1} \left\lfloor \frac{N}{2^j} \right\rfloor = \sum_i \sum_{j=1}^{a_i} 2^{a_i - j} = \sum_i (2^{a_i} - 1) = N - s_2(N)$$

| 변형 | 한 일 | 근거 |
| --- | --- | --- |
| 첫째 등호 | $\lfloor N/2^j \rfloor$ 를 자리별 항의 합으로 폈다 | $a_i < j$ 인 항들은 서로 다른 거듭제곱이라 합이 $(2^j - 1)/2^j < 1$ 이고, 버림이 그 몫을 통째로 걷어 낸다 |
| 둘째 등호 | $j$ 에 대한 합을 안쪽으로 옮겼다 | 유한한 합이라 순서를 바꿔도 값이 같다 |
| 셋째 등호 | 등비수열 $1 + 2 + \dots + 2^{a_i - 1}$ 을 닫았다 | 각 항이 $2^{a_i} - 1$ 이 되고, 항이 $s_2(N)$ 개라 1 을 그만큼 뺀다 |

위 식을 그대로 옮긴 코드 조각은 이렇습니다.

```ts
// 위 식을 그대로 옮긴 것. 왼쪽은 ν 를 직접 더하고 오른쪽은 닫힌 형태다.
const sumNu = (n: number): number => {
  let total = 0;
  for (let x = 1; x <= n; x++) for (let t = x; t % 2 === 0; t /= 2) total++;
  return total;
};
const closed = (n: number): number => {
  let ones = 0;
  for (let t = n; t > 0; t = Math.floor(t / 2)) ones += t % 2;
  return n - ones;
};
```

닫힌 형태를 자리마다 검사의 비용에 넣습니다. 그 방법이 `x` 하나에 쓰는 기본 연산이 $5\nu(x) + 6$ 이므로, $x = 1
\dots N$ 을 전부 넣으면 $A(N) = 5(N - s_2(N)) + 6N$ 이에요.

<!--proof:math-scale-->

| 무엇 | 식 | 값 |
| --- | --- | ---: |
| 자리 p 의 합 | N - s₂(N) = 10,000,000 - 8 | 9,999,992 |
| 자리 p 의 평균 | (N - s₂(N)) / N | 0.9999992 |
| 자리마다 검사, 1 부터 N 까지 | 5(N - s₂(N)) + 6N | 109,999,960 |
| 자리마다 검사, p = 31 만 N 번 | (5·31 + 6) N | 1,610,000,000 |
| x & -x | 2N | 20,000,000 |

N = 10,000,000 에서 자리마다 검사는 1 부터 N 까지 넣으면 x & -x 의 5.5 배이고, p = 31 만 넣으면 80.5 배입니다.

<!--/proof-->

본문의 값만으로는 안 나오는 것이 여기서 나옵니다. **자리 번호의 평균이 1 로 다가간다**는 것이에요. $s_2(N) \le
\log_2 N + 1$ 이므로 $(N - s_2(N))/N$ 은 $N$ 이 커질수록 1 에 가까워집니다. 그래서 1 부터 $N$ 까지를 한 번씩 넣으면
자리마다 검사가 호출마다 평균 한 자리쯤만 더 검사하는데, 최악인 `p = 31` 은 호출마다 서른한 자리를 더 검사해요.
위 표의 두 배수가 그 차이이고, 「아이디어를 떠올리는 과정」에서 두 입력 모양의 비용이 크게 갈린 까닭이 이것입니다.

### 불변식 — x & -x 의 1 비트는 x 의 최하위 1 비트 하나뿐이다

파트 1 은 `x = 40` 하나를 아홉 걸음으로 따라가 답이 8 이라는 것을 확인했습니다. 그것은 입력 하나에서 맞았다는
뜻이지 32 비트 정수 전부에서 맞는다는 뜻은 아니에요. **모든 입력에서 참으로 남는 것**을 문장으로 세우고, 그것이
실제로 유지되는지 확인해 봅시다.

> `-x` 를 다 만든 시점에, `x ≠ 0` 이고 최하위 1 비트가 자리 `p` 이면 `-x` 의 자리 `j` 비트는 `j < p` 면 0,
> `j = p` 면 1, `j > p` 면 `x` 의 그 자리 비트의 반대입니다. `x = 0` 이면 `-x` 도 0 이에요. 그래서 `x & -x` 에는
> 자리 `p` 하나만 1 로 남고, `x = 0` 이면 0 입니다.

| 문장 | 뜻하는 것 | 뜻하지 않는 것 |
| --- | --- | --- |
| `-x` 는 세 구간으로 갈린다 | 자리 `p` 를 경계로 아래 · 자리 `p` · 위의 규칙이 다르다 | `-x` 가 `x` 의 반대라는 것 — 자리 `p` 와 그 아래에서는 반대가 아니다 |
| `-x` 를 다 만든 시점 | 덧셈이 32 자리를 다 거친 뒤 | 자리올림이 올라가는 도중 — 그때는 위 구간이 아직 `~x` 와 같은지 정해지지 않았다 |

**출발점부터 봅시다.** `~x` 는 모든 자리에서 `x` 의 반대입니다. 자리 `p` 아래는 `x` 가 전부 0 이므로 `~x` 에서 전부
1 이고, 자리 `p` 는 `x` 가 1 이므로 `~x` 에서 0 이에요. 연산마다 세 구간이 어떻게 바뀌는지 적으면 이렇습니다.

| 구간 | `x` | `~x` | 1 을 더한 뒤 | 근거 |
| --- | --- | --- | --- | --- |
| 자리 `p` 아래 | 전부 0 | 전부 1 | 전부 0 | 1 + 1 이 되어 그 자리가 0 이 되고 자리올림이 위로 간다 |
| 자리 `p` | 1 | 0 | 1 | 0 에 자리올림 1 을 더해 1 이 되고 넘길 것이 없어진다 |
| 자리 `p` 위 | 아무 값 | `x` 의 반대 | `x` 의 반대 | 자리올림이 0 이라 더할 것이 없다 |

가운데 줄이 이 논증의 전부입니다. 자리 `p` 아래가 전부 1 이라 자리올림이 끊기지 않고 올라가고, 자리 `p` 가 0 이라
거기서 멈춰요. 마지막 AND 는 구간마다 `0 & 0`, `1 & 1`, 반대끼리의 AND 라 자리 `p` 만 1 이 됩니다. 전개 입력에서
세 구간을 자리마다 대조했습니다.

<!--proof:invariant-ranges-->

| 자리 | 구간 | x 의 비트 | -x 의 비트 | 불변식이 말하는 값 | 판정 |
| --- | --- | ---: | ---: | ---: | --- |
| 자리 7 | 위 | 0 | 1 | 1 | 같다 |
| 자리 6 | 위 | 0 | 1 | 1 | 같다 |
| 자리 5 | 위 | 1 | 0 | 0 | 같다 |
| 자리 4 | 위 | 0 | 1 | 1 | 같다 |
| 자리 3 | 자리 p | 1 | 1 | 1 | 같다 |
| 자리 2 | 아래 | 0 | 0 | 0 | 같다 |
| 자리 1 | 아래 | 0 | 0 | 0 | 같다 |
| 자리 0 | 아래 | 0 | 0 | 0 | 같다 |

그린 여덟 자리를 포함해 32 자리 중 32 자리에서 -x 의 비트가 불변식이 말하는 값과 일치합니다.

<!--/proof-->

전개 입력 하나로는 나오지 않는 경계들도 확인하고 넘어갑시다. 정의대로 센 답(2 로 나눌 수 있는 최대 횟수를 세어 그
자리의 값을 내는 것)과 나란히 놓았습니다.

<!--proof:invariant-edges-->

| 경계 | x | p | 정의가 낸 답 | 정본 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| 값이 0 | 0 | 없음 | 0 | 0 | 같다 |
| 1 비트가 자리 0 하나 | 1 | 0 | 1 | 1 | 같다 |
| 1 비트가 전부 켜짐 | -1 | 0 | 1 | 1 | 같다 |
| 전개 입력 | 40 | 3 | 8 | 8 | 같다 |
| 음수 | -12 | 2 | 4 | 4 | 같다 |
| 범위의 위쪽 끝 | 2,147,483,647 | 0 | 1 | 1 | 같다 |
| 범위의 아래쪽 끝 | -2,147,483,648 | 31 | -2,147,483,648 | -2,147,483,648 | 같다 |
| 자리 30 하나 | 1,073,741,824 | 30 | 1,073,741,824 | 1,073,741,824 | 같다 |

여덟 줄 모두 일치합니다. 값이 0 인 줄은 1 비트가 없어 p 가 정해지지 않는데, 그 자리에서 정본은 따로 막는 줄 없이 0 을 냅니다.

<!--/proof-->

`-1` 은 1 비트가 서른두 개인데 자리 0 이 1 이라 `p = 0` 이고, 아래 구간이 없어 2단계가 자리 0 에서 곧바로 멈춥니다.
범위의 아래쪽 끝은 자리올림이 서른한 자리를 넘어가는 가장 긴 경우이고, 값이 0 인 줄은 자리올림이 32 비트 밖으로
나가 버려지는 경우예요. 세 경우 모두 문장이 그대로 성립합니다.

**이제 코드 한 곳을 바꿔 확인해 봅시다.** 이 문장을 지키던 것은 **1 을 더하는 자리** 하나예요. 「어차피 부호를
뒤집는 것은 자리를 뒤집는 것 아닌가」라는 생각으로 그 덧셈을 지우고 `~x` 를 그대로 AND 해 봅니다.

```ts
return x & ~x; // ← return x & -x 대신. 1 을 더하지 않았다
```

<!--proof:mutant-no-carry-->

| 경계 | x | 정본 | 1 을 안 더한 판 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 값이 0 | 0 | 0 | 0 | 같다 |
| 1 비트가 자리 0 하나 | 1 | 1 | 0 | 어긋난다 |
| 1 비트가 전부 켜짐 | -1 | 1 | 0 | 어긋난다 |
| 전개 입력 | 40 | 8 | 0 | 어긋난다 |
| 음수 | -12 | 4 | 0 | 어긋난다 |
| 범위의 위쪽 끝 | 2,147,483,647 | 1 | 0 | 어긋난다 |
| 범위의 아래쪽 끝 | -2,147,483,648 | -2,147,483,648 | 0 | 어긋난다 |
| 자리 30 하나 | 1,073,741,824 | 1,073,741,824 | 0 | 어긋난다 |

여덟 줄 중 일곱 줄에서 답이 어긋납니다.

<!--/proof-->

1 을 안 더하면 뒤집은 값이 모든 자리에서 `x` 의 반대로 남아, 함께 1 인 자리가 어디에도 없습니다. 불변식의 세 구간
가운데 아래 둘이 통째로 무효가 되는 거예요. 값이 0 인 줄만 답이 같은 까닭은 정본의 답도 0 이기 때문입니다. 전개
입력에서 자리 3 이 두 판에서 어떻게 갈리는지 보았습니다.

<!--proof:mutant-no-carry-bits-->

| 값 | 자리 5 | 자리 4 | 자리 3 | 자리 2 | 자리 1 | 자리 0 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `x` | 1 | 0 | 1 | 0 | 0 | 0 |
| `~x` | 0 | 1 | 0 | 1 | 1 | 1 |
| `-x` | 0 | 1 | 1 | 0 | 0 | 0 |
| 1 을 안 더한 판이 낸 값 | 0 | 0 | 0 | 0 | 0 | 0 |
| 정본이 낸 값 | 0 | 0 | 1 | 0 | 0 | 0 |

~x 의 자리 3 은 0 이고 -x 의 자리 3 은 1 입니다. 1 을 안 더한 판은 0 을 내고, 정본은 자리 3 하나가 남아 8 을 냅니다.

<!--/proof-->

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 네 무리입니다. 입력을 읽고, `-x` 를 만들고, 두 값을 AND 하고, 값을 돌려줘요. 「아이디어를
떠올리는 과정」과 같은 기준으로 기본 연산을 세고, 전개의 걸음으로 나누면 이렇습니다.

<!--proof:perf-count-->

| 무리 | 걸음 | 걸음 수 | 부호 뒤집기 | 비트 AND | 기본 연산 |
| --- | --- | ---: | ---: | ---: | ---: |
| 입력을 읽는다 | T1 | 1 | 0 | 0 | 0 |
| -x 를 만든다 | T2 ~ T7 | 6 | 1 | 0 | 1 |
| 두 값을 AND 한다 | T8 | 1 | 0 | 1 | 1 |
| 값을 돌려준다 | T9 | 1 | 0 | 0 | 0 |
| 합계 |  | 9 | 1 | 1 | 2 |

걸음은 9 개인데 기본 연산은 2 개입니다.

<!--/proof-->

**전개의 걸음 수와 기계의 연산 수가 다릅니다.** `T2` 부터 `T7` 까지 여섯 걸음은 사람이 읽으려고 뒤집기 한 걸음(`T2`)
과 덧셈 다섯 걸음(`T3`~`T7`)으로 갈라 놓은 것이고, 기계에서는 부호를 뒤집는 연산 한 번이에요. 자리마다의
덧셈은 그 한 연산 안에서 일어나므로 걸음이 늘어도 연산 수는 안 늘어납니다.

| 무엇 | 횟수 | 까닭 |
| --- | --- | --- |
| 부호 뒤집기 | 1 | `-x` 한 번 |
| 비트 AND | 1 | `x & -x` 한 번 |
| 입력 밖에 잡는 칸 | 0 | 전체 코드가 새로 두는 이름이 없다 — 조각의 `flipped` · `negated` 는 읽으려고 잡은 이름이다 |

#### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 서로 다른 축입니다. 「최악은 `O`, 평균은 `Θ`」처럼 한쪽을
다른 쪽에 짝지으면 안 돼요. 이 절차는 갈래가 없어서 케이스가 갈리지 않습니다.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (어떤 32 비트 정수든) | `O(1)` | `Θ(1)` — 기본 연산 2 번 |
| **평균적인 경우** (입력 분포를 정하지 않아도 같다) | `O(1)` | `Θ(1)` — 기본 연산 2 번 |
| **최악의 경우** (어떤 32 비트 정수든) | `O(1)` | `Θ(1)` — 기본 연산 2 번 |

세 줄이 같은 까닭은 건너뛰거나 되풀이하는 자리가 없기 때문입니다. 어떤 32 비트 정수를 넣어도 실행되는 연산이
글자 그대로 같아요. 기본 연산이 정확히 2 번이라 아래로도 상수이므로 `Θ` 로 적을 수 있습니다.

**총식을 한 번은 정확히 적어 둡니다.** 앞뒤로 붙는 전처리가 없어서 미리 만드는 표도, 자리 수를 세는 단계도
없어요.

| 자원 | 총식 | 자리마다 검사의 총식 |
| --- | --- | --- |
| 시간 | 기본 연산 2 번 = `Θ(1)`. `N` 번 호출하면 `2N` | 최악 `5w + 2` 번 — 자리 폭 `w` 를 따라 늘어난다 |
| 추가 메모리 | `Θ(1)` — 0 칸 | 반복 번호 `j` 한 칸 |

`x & -x` 만 자리 폭 `w` 가 총식에 안 나옵니다. **보장의 종류는 최악 보장입니다.** 해시도, 난수도, 분할 상환도 쓰지
않아서 어떤 입력을 넣어도 기본 연산이 2 번이에요.

| 보장의 종류 | 뜻 | 이 절차 |
| --- | --- | --- |
| 기댓값이면 | 같은 규모라도 입력이나 난수에 따라 상한을 넘을 수 있다 | 해당하지 않는다 |
| 최악 보장이면 | 어떤 입력이든 상한 아래다 | 이쪽이다. 연산 수가 입력을 보기 전에 정해진다 |

아래로도 이것이 하한입니다. 답은 입력 값에 달려 있으니 입력을 한 번은 읽어야 하고, 그 값에서 다른 값을 만들려면
연산이 적어도 하나는 필요해요.

#### 최악을 만드는 입력

이 절차에는 **최악을 만드는 입력이 없습니다.** 그것을 값으로 확인하고, 같은 입력들이 자리마다 검사에서는 어떻게
갈리는지 나란히 봅시다.

<!--proof:perf-worst-->

| 입력의 모양 | x | p | 1 비트 수 | x & -x 의 기본 연산 | 자리마다 검사의 기본 연산 | 답 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 값이 0 이다 | 0 | 없음 | 0 | 2 | 162 | 0 |
| 1 비트가 자리 0 에 있다 | 1 | 0 | 1 | 2 | 6 | 1 |
| 1 비트가 자리 31 에 있다 | -2,147,483,648 | 31 | 1 | 2 | 161 | -2,147,483,648 |
| 1 비트가 서른두 자리에 다 있다 | -1 | 0 | 32 | 2 | 6 | 1 |
| 범위의 위쪽 끝이다 | 2,147,483,647 | 0 | 31 | 2 | 6 | 1 |
| 자리 30 하나뿐이다 | 1,073,741,824 | 30 | 1 | 2 | 156 | 1,073,741,824 |
| 전개 입력이다 | 40 | 3 | 2 | 2 | 21 | 8 |

x & -x 의 기본 연산은 일곱 줄 모두 2 번입니다. 자리마다 검사는 6 번에서 162 번까지 차이가 납니다.

<!--/proof-->

**「값이 크면 비용이 크다」와 「1 비트가 많으면 비용이 크다」는 둘 다 자리마다 검사에서도 성립하지 않습니다.** 1
비트가 서른두 개인 `-1` 과 값이 가장 큰 범위의 위쪽 끝은 둘 다 `p = 0` 이라 가장 적은 검사로 끝나요. 자리마다 검사의 비용을
정하는 것은 `p` 하나이고, 1 비트가 하나도 없는 0 이 끝까지 검사해 가장 큽니다.

| 최악으로 만들 축 | 입력 | 값 |
| --- | --- | --- |
| `x & -x` 의 기본 연산 | 어떤 32 비트 정수든 | 2 번 |
| 자리마다 검사의 기본 연산 | `x = 0` | `5w + 2` 번 |
| 1 비트가 있을 때 자리마다 검사 | `x = -2^31` | `5(w - 1) + 6` 번 |
| `x & -x` 가 입력 밖에 잡는 칸 | 어떤 입력이든 | 0 칸 |

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하겠습니다. 자리를 **검사하지 않고** 최하위 1 비트만 남겼고, 그 일을 한 것은 부호를
뒤집는 덧셈의 자리올림이며, 연산 수는 값에도 자리 폭에도 안 달립니다.

| 순서 | 하는 일 | 그 결과 |
| ---: | --- | --- |
| 1 | 모든 자리를 뒤집는다 | 자리 `p` 아래가 전부 1, 자리 `p` 가 0 이 된다 |
| 2 | 1 을 더한다 | 자리올림이 자리 `p` 에서 멈춰 `-x` 가 된다 |
| 3 | `x` 와 AND 한다 | 자리 `p` 하나만 남는다 |

먼저 답이 붙은 문제 하나입니다. 전개의 `T6` 에서 자리올림이 0 이 되는데, `T7` 은 그 위 자리를 「`~x` 그대로」라고만
적고 넘어갑니다. 그 자리들을 하나하나 확인하지 않아도 답이 맞는다고 말할 수 있을까요?

<!--proof:check-above-->

| 자리 | x 의 비트 | ~x 의 비트 | -x 의 비트 | AND |
| --- | ---: | ---: | ---: | ---: |
| 자리 7 | 0 | 1 | 1 | 0 |
| 자리 6 | 0 | 1 | 1 | 0 |
| 자리 5 | 1 | 0 | 0 | 0 |
| 자리 4 | 0 | 1 | 1 | 0 |

네 자리 모두 ~x 의 비트와 -x 의 비트가 일치하고, x 의 비트와는 반대라 마지막 열이 전부 0 입니다.

<!--/proof-->

<!--check:carryStops-->
답: 말할 수 있습니다. 근거가 둘이에요. 첫째, `T6` 에서 자리올림이 0 이 됐으므로 그 위 자리에는 더할 것이 없고, 그래서
`-x` 의 자리 4 이상은 `~x` 의 그 자리와 **같은 값**입니다. 둘째, `~x` 는 정의상 자리마다 `x` 의 반대이므로 그 구간에서
두 값이 함께 1 인 자리가 있을 수 없어요. 위 표의 셋째 열과 넷째 열이 같고, 둘째 열과 넷째 열이 반대인 것이 그

| 단계 | 사실 | 근거 |
| --- | --- | --- |
| `T6` 에서 얻은 것 | 자리올림이 0 이다 | `0 + 1 = 1` 이라 넘길 것이 없다 |
| 그래서 | 자리 4 이상은 `~x` 가 그대로다 | 더한 것이 없다 |
| `~x` 는 | 자리마다 `x` 의 반대다 | 뒤집기의 정의 |

값이 몇이든 자리 폭이 몇이든 이 논증이 그대로 성립합니다. 그래서 `T7` 한 걸음이 「자리 4 부터 위」를 한꺼번에
처리할 수 있고, 자리 폭이 64 가 되어도 걸음이 안 늘어나요.

### 최하위 1비트 (Lowest Set Bit)

풀 파일: [`lowestSetBit.ts`](./lowestSetBit.ts) · 테스트: [`lowestSetBit.test.ts`](./lowestSetBit.test.ts) · 실행: `bun test src/algorithms/bit-manipulation/lowestSetBit/lowestSetBit.test.ts`

#### 한 줄 요약

> 32비트 정수를 받아, 가장 낮은 위치의 1비트만 남기고 나머지를 0으로 만든 값을 반환한다.

#### 스토리

항법 엔지니어 민준은 선박의 GPS 좌표 오류를 수정하는 소프트웨어를 개발한다. 오류 코드는 비트마스크로 표현되며, 여러 오류가 동시에 발생했을 때 가장 우선순위가 높은 오류(가장 낮은 비트)를 먼저 처리해야 한다.

오류 코드 `x`에서 가장 낮은 비트 위치의 오류만 꺼내, 그 오류 하나만 담은 새 코드를 만들어야 한다. 나머지 오류는 차례로 처리하기 위해 그대로 남겨 둔다.

#### 함수 인터페이스

```ts
export function lowestSetBit(x: number): number;
```

- `x` — 임의의 32비트 정수
- 반환 — `x`에서 가장 낮은 위치의 1비트만 남긴 값. `x === 0`이면 `0`을 반환.

#### 제약 조건

- $-2^{31} \leq x \leq 2^{31} - 1$ (32비트 정수)
- $x = 0$이면 `0`을 반환한다.
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

32비트 정수 $x$가 주어질 때, $x$의 이진 표현에서 가장 낮은 자리에 있는 1비트만 남기고 그 외 모든 비트를 0으로 만든 값을 반환한다.

예를 들어 $x = 12 = 0\text{b}00001100$이면 가장 낮은 1비트는 2번 위치(값 4)이므로 결과는 $4 = 0\text{b}00000100$이다.

$x = 0$이면 1비트가 없으므로 $0$을 반환한다.

#### 예시

```ts
lowestSetBit(12);     //  4 — 0b1100에서 가장 낮은 1비트는 0b0100 = 4
lowestSetBit(6);      //  2 — 0b0110에서 가장 낮은 1비트는 0b0010 = 2
lowestSetBit(1);      //  1 — 0b0001, 최하위 비트가 유일한 1비트
lowestSetBit(16);     // 16 — 0b10000, 단일 비트이므로 자기 자신
lowestSetBit(0);      //  0 — 1비트가 없음
lowestSetBit(-1);     //  1 — 2의 보수 표현에서 -1은 모든 비트가 1, 최하위는 값 1
lowestSetBit(-12);    //  4 — 2의 보수에서 -12의 최하위 1비트는 4
```
