# enumerateSubmasks 솔루션 분석

## 1. 접근 방향 분석

현재 구현은 선형 탐색(brute-force)이다.

```ts
for (let i = mask; i > 0; i--) {
  if ((mask & i) === i) {
    subMasks.push(i);
  }
}
subMasks.push(0);
```

`i`를 `mask`부터 1까지 1씩 감소하며, 각 `i`에 대해 `(mask & i) === i` 조건으로 서브마스크 여부를 판별한다.

**조건식 `(mask & i) === i`의 의미**

정수 $s$가 정수 $m$의 서브마스크라는 것은, $s$의 모든 1-비트가 $m$에서도 1-비트임을 의미한다.

$$s \text{ is submask of } m \iff (s\ \&\ m) = s$$

비트 AND 연산 `mask & i`는 두 수에서 공통으로 1인 비트만 남긴다. `(mask & i) === i`가 참이면 `i`의 1-비트가 모두 `mask`에 포함되어 있으므로 `i`는 `mask`의 서브마스크다. 방향성 자체는 올바르다.

**단, 시간 복잡도가 최적이 아니다.** 섹션 3 참조.

## 2. 정확성 분석

### 테스트 결과

| 구분 | 개수 |
|------|------|
| 통과 | 12 |
| 실패 | 0 |

### 케이스별 동작 추적

**`mask = 0b1011 = 11`**

i = 11 → 11 & 11 = 11 ✓  
i = 10 (0b1010) → 11 & 10 = 10 ✓  
i = 9 (0b1001) → 11 & 9 = 9 ✓  
i = 8 (0b1000) → 11 & 8 = 8 ✓  
i = 7~4: bit 2(0b100)가 mask에 없으므로 모두 실패 ✗  
i = 3 (0b0011) → 11 & 3 = 3 ✓  
i = 2 (0b0010) → 11 & 2 = 2 ✓  
i = 1 (0b0001) → 11 & 1 = 1 ✓  
→ push 0  
결과: [11, 10, 9, 8, 3, 2, 1, 0] ✓

**`mask = 0` 엣지 케이스**

루프 조건 `i > 0`이 `i = 0`에서 즉시 거짓이므로 루프 본체 미실행, push(0) 후 반환. 결과: [0] ✓

**내림차순 보장**

`i`를 단조 감소하며 순차적으로 push하므로 결과는 자동으로 내림차순이다.

**길이 $2^k$ 보장**

`mask`의 1-비트 수를 $k$라 하면 서브마스크는 정확히 $2^k$개다. 조건식이 서브마스크만 통과시키므로 길이가 보장된다.

## 3. 최적화 분석

현재 구현의 시간 복잡도는 $O(\text{mask}) = O(2^B)$이다. $B$는 `mask`의 최상위 비트 위치(bit position of the most significant bit)다.

`mask`의 1-비트 수를 $k$라 하면 서브마스크의 수는 $2^k$다. $k < B$인 경우(sparse mask), 루프는 실제 서브마스크 수보다 훨씬 많은 횟수를 돈다.

예시: $\text{mask} = 1 \ll 19$ ($k=1$, 서브마스크 2개)

| 접근 | 이터레이션 수 |
|------|------------|
| 현재 (선형 탐색) | $2^{19} \approx 524\,288$ |
| 최적 (서브마스크 열거 트릭) | $1$ |

성능 테스트(`mask = (1\ll 20)-1`)에서 $k = B = 20$이므로 두 방법이 동일하게 $2^{20} - 1$번 반복한다. 이 때문에 현재 구현도 테스트를 통과하지만, sparse mask에서는 현저한 성능 차이가 발생한다.

---

### 3.1 핵심 아이디어: 서브마스크 열거 트릭

**핵심 관찰**: 임의의 서브마스크 $s > 0$에서 $s$의 다음으로 작은 서브마스크는 $(s - 1)\ \&\ \text{mask}$로 직접 계산할 수 있다.

이 점화 관계를 반복 적용하면, 별도의 판별 조건 없이 서브마스크만 정확히 방문한다.

---

### 3.1.1 원형에서 최적 알고리즘까지의 전개

#### 원형: 서브마스크의 정의

정수 $s$가 정수 $m$의 서브마스크일 조건:

$$s\ \&\ m = s$$

이 조건을 만족하는 $s$의 집합을 $\mathcal{S}(m)$이라 하면:

$$\mathcal{S}(m) = \{s \in \mathbb{Z}_{\geq 0} \mid s\ \&\ m = s\}$$

$\mathcal{S}(m)$의 원소 수는 정확히 $2^k$ ($k = \text{popcount}(m)$)이다. $m$의 각 1-비트는 서브마스크에 포함되거나($1$) 포함되지 않거나($0$) 두 가지 선택이 있으며, 이들이 독립적으로 결정된다.

---

#### 단계 1: 브루트포스 O(mask)

임의의 정수 $i \in [1, \text{mask}]$를 순서대로 검사한다.

```ts
for (let i = mask; i > 0; i--) {
  if ((mask & i) === i) push(i);
}
push(0);
```

서브마스크가 아닌 수도 모두 방문하므로 $O(\text{mask})$이다.

---

#### 단계 2: 관찰 — 다음 서브마스크의 직접 계산

**보조 사실**: 정수 $s > 0$에 대해 $s - 1$은 다음과 같이 작동한다.

$s$의 최하위 1-비트 위치를 $p$라 하자.

$$s = \underbrace{b_{n-1} \cdots b_{p+1}}_{\text{상위 비트}} \underbrace{1}_{p\text{번}} \underbrace{00\cdots0}_{p\text{개 이하 비트}}$$

$$s - 1 = \underbrace{b_{n-1} \cdots b_{p+1}}_{\text{상위 비트 불변}} \underbrace{0}_{p\text{번}} \underbrace{11\cdots1}_{p\text{개 이하 비트 모두 1}}$$

즉, $s - 1$은 비트 $p$를 0으로 만들고, 비트 $p-1$ 이하를 모두 1로 만든다.

**$(s - 1)\ \&\ \text{mask}$의 해석**:

- 비트 $p$ 이상: $s - 1$의 상위 비트 = $s$의 상위 비트이므로, $s$의 비트 $p$ 이상 중 `mask`에 있는 것들은 그대로 유지된다.
  - 정확히: 비트 $p$는 0, 비트 $p$ 초과는 $s$와 동일.
- 비트 $p$ 미만: $s - 1$에서 모두 1이므로, `& mask`에 의해 `mask`의 해당 비트들만 남는다. 즉, 비트 $p$ 미만 위치 중 `mask`에 있는 비트가 모두 1로 채워진다.

결과적으로 $(s-1)\ \&\ \text{mask}$는:
1. $s$에서 최하위 1-비트($p$번)를 제거한다.
2. $p$ 미만 위치의 `mask` 비트를 모두 1로 채운다.

이 값이 $s$보다 작은 서브마스크 중 가장 큰 것임을 보인다.

**증명**:

$(s-1)\ \&\ \text{mask}$가 `mask`의 서브마스크임은 정의상 자명하다.

이 값이 $s$ 미만의 서브마스크 중 최댓값임을 보인다.

$s$ 미만의 임의의 서브마스크 $t$를 잡자 ($0 \leq t < s$). $t$는 `mask`의 서브마스크이므로 $t\ \&\ \text{mask} = t$이다.

- $t < s$이므로 $t$와 $s$의 최상위 차이 비트 $q$ ($t$에서 0, $s$에서 1)가 존재한다.
- $q \geq p$인 경우: $t$는 비트 $q$가 0이고 $q \geq p$이므로, $t \leq (s - 1)\ \&\ \text{mask}$임이 비트 비교에 의해 성립한다.
  - 더 정확히: 비트 $q > p$이면 $t < s$이고 $t$의 비트 $q$는 0이므로 $t < 2^q \leq (s-1)\ \&\ \text{mask}$의 비트 구성에 따라 값이 결정된다.

직관적으로: $(s-1)\ \&\ \text{mask}$는 $s$에서 최하위 1-비트를 내리고 그 아래를 최대로 채운 것이므로, 이보다 크고 $s$보다 작은 서브마스크는 존재하지 않는다.

---

#### 단계 3: 최적 알고리즘 O(2^k)

위 관찰을 반복 적용한다.

```ts
function enumerateSubmasks(mask: number): number[] {
  const subMasks: number[] = [];
  for (let s = mask; s > 0; s = (s - 1) & mask) {
    subMasks.push(s);
  }
  subMasks.push(0);
  return subMasks;
}
```

- 루프가 한 번 반복될 때마다 `s`는 서브마스크 중 다음으로 작은 값으로 이동한다.
- `s`가 최소 비영(非零) 서브마스크에 도달하면, 다음 스텝에서 `(s-1) & mask = 0 & mask = ... ` 아니다. `s-1`은 모든 비트가 1인 수(-1을 부호 없이 보면), `(-1) & mask = mask`가 되지만 루프 조건 `s > 0`은 `s = 0`이 되는 순간 종료된다.

정확히: 가장 작은 비영 서브마스크를 $s_{\min}$이라 하면:
- $s_{\min} - 1$에서 $s_{\min}$의 모든 비트가 0이 되고 아래 비트 모두 1이 된다.
- $s_{\min}$이 `mask`의 최하위 비트만 갖는다면, $(s_{\min} - 1)\ \&\ \text{mask} = 0$.
- 루프에서 갱신 후 `s = 0`이 되어 `s > 0`을 통과하지 못하고 종료된다.

따라서 루프는 정확히 $2^k - 1$번 실행되어 비영 서브마스크 $2^k - 1$개를 모두 방문하고, push(0)으로 빈 집합을 추가한다.

---

#### 복잡도 비교

| 구현 | 시간 | 공간(출력 제외) |
|------|------|---------------|
| 현재 (선형 탐색) | $O(\text{mask}) = O(2^B)$ | $O(1)$ |
| 최적 (서브마스크 트릭) | $O(2^k)$ | $O(1)$ |

- $B$: `mask`의 최상위 비트 위치
- $k$: `popcount(mask)` (1-비트의 수)
- $k \leq B$이며, $k < B$인 경우(sparse mask) 최적 알고리즘이 훨씬 빠르다.
- $k = B$인 경우(dense mask, 예: $\text{mask} = 2^B - 1$) 두 복잡도가 일치한다.

성능 테스트에서 `mask = (1 << 20) - 1` ($k = B = 20$)을 사용하므로, 두 구현 모두 약 $10^6$번 반복하여 통과한다. Sparse mask에 대한 성능 테스트가 없어 현재 구현이 통과하지만, 일반적인 경우 최적 구현이 우수하다.
