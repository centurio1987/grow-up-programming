# 트리 재루팅 — 뿌리를 이웃으로 한 칸 옮기면 그쪽 부분트리만 가까워진다

## 파트 1 — 아이디어에서 동작하는 코드까지

문제를 고정하고, 답 하나에서 나머지 전부를 얻는 규칙을 세우고, 그 규칙이 실제로 동작하는
코드까지 갑니다.

### 전체 컨셉

사이클이 없고 모두 이어진 그래프를 **트리**라고 부릅니다. 정점이 `N` 개면 간선이 `N-1` 개예요.
두 정점 사이의 **거리**는 그 둘을 잇는 경로 위의 간선 수이고, 트리에서는 두 정점을 잇는 경로가
하나뿐이라 이 값이 유일하게 정해집니다.

풀어야 하는 것은 **정점마다의 거리 합**이에요. 정점 `v` 하나를 고르고 나머지 정점까지의 거리를
전부 더한 값을 `S(v)` 라 하면, 답은 `S(0)` 부터 `S(N-1)` 까지를 담은 배열입니다.

```text
정점 다섯짜리 트리와 그 답

        0            간선 (0,1) (0,2) (1,3) (1,4)
       / \
      1   2          S(0) = 1 + 1 + 2 + 2 = 6
     / \             S(1) = 1 + 2 + 1 + 1 = 5
    3   4            S(2) = 1 + 2 + 3 + 3 = 9
                     S(3) = 2 + 1 + 3 + 2 = 8
                     S(4) = 2 + 1 + 3 + 2 = 8
```

정점 하나의 답을 구하는 것은 쉽습니다 — 그 정점에서 너비 우선 탐색을 한 번 실행하고 나온 거리를
더하면 되고, 간선을 두 번씩 읽으니 `O(N)` 이에요. 문제는 그것을 `N` 번 해야 한다는 것이고,
`N` 이 10 만이면 `N^2` 이 이미 100 억이라 1 초 안에 안 끝납니다.

**이 알고리즘의 관찰은 이웃한 두 답의 차이가 상수 시간에 나온다는 것입니다.** 정점 `p` 의 답을
알고 있을 때 이웃 `c` 의 답이 얼마나 달라지는지 보면, `c` 쪽에 있는 정점은 전부 정확히 한 칸
가까워지고 나머지는 전부 정확히 한 칸 멀어져요. 트리라서 `p` 와 `c` 를 잇는 간선 하나를 지우면
그래프가 두 조각으로 갈리고, 모든 정점이 둘 중 한 조각에만 속하기 때문입니다.

```text
간선 (0,1) 을 지우면 정점 다섯이 두 조각으로 갈린다

  0 쪽 조각   {0, 2}      두 개    0 에서 1 로 뿌리를 옮기면 한 칸씩 멀어진다
  1 쪽 조각   {1, 3, 4}   세 개    0 에서 1 로 뿌리를 옮기면 한 칸씩 가까워진다

  S(1) = S(0) - 3 + 2 = 6 - 3 + 2 = 5   위 표의 S(1) = 5 와 같다
```

`c` 쪽 조각의 정점 수를 `size(c)` 라 쓰면 이 규칙이 한 줄로 적힙니다 —
`S(c) = S(p) + N - 2 x size(c)` 예요. 가까워지는 `size(c)` 개를 빼고 멀어지는 `N - size(c)` 개를
더한 것이라, 두 항을 합치면 `N - 2 x size(c)` 가 됩니다.

그래서 절차가 셋으로 정리됩니다. 첫째로 기준이 될 정점 하나를 정해 그 답을 직접 구하고,
둘째로 모든 정점의 `size` 를 구하고, 셋째로 기준에서 이웃으로 · 그 이웃에서 다시 이웃으로
규칙을 적용해 나머지 답을 채웁니다. 셋 다 트리를 상수 번 지나가는 것이라 전체가 `O(N)` 이고, 답 배열 자체가
`N` 칸이라 이보다 적게 읽을 수는 없어요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **간선 목록과 이웃 목록의 차이** — 간선 `[u, v]` 를 정점마다의 목록으로 옮겨 두면 한 정점의
  이웃을 바로 읽을 수 있습니다. 모르면
  [깊이 우선 순회](../../graph/dfsTraversal/dfsTraversal-guide.md) 의 첫 절을 보세요.
- **가중치 없는 그래프에서의 거리** — 간선 수로 재는 거리이고 너비 우선 탐색이 그것을 구합니다.
  [너비 우선 탐색으로 최단 거리](../../graph/bfsShortestPath/bfsShortestPath-guide.md) 가 그
  절차입니다.
- **부분트리** — 뿌리를 하나 정하면 각 정점 아래로 매달린 정점들의 무리가 정해집니다. 이 글은
  그 무리의 정점 수만 씁니다. [트리의 지름](../treeDiameter/treeDiameter-guide.md) 이 같은
  전처리를 씁니다.
- **재귀 없이 트리를 지나가는 법** — 스택 배열 하나로 깊이 우선 순회를 적을 수 있다는 것.
  이 글은 이유가 있어서 재귀를 쓰지 않습니다.

여기서 알 필요가 **없는** 것도 적어 둘게요. 세그먼트 트리·펜윅 트리 같은 구간 자료구조는
이 문제에 쓰지 않고, 최소 공통 조상도 쓰지 않습니다.

### 아이디어 상세 — 부분트리 크기로 이웃한 답을 잇는 규칙을 떠올리는 과정

**첫째, 문제를 고정합니다.**

```ts
export function treeRerooting(n: number, edges: [number, number][]): number[];
```

- 입력 `n` 은 정점 수이고 정점 번호는 `0` 부터 `n-1` 까지입니다.
- 입력 `edges` 는 길이 `n-1` 인 무방향 간선 목록이고, 주어진 그래프는 언제나 이어진 트리입니다.
  `[u, v]` 와 `[v, u]` 는 같은 간선이에요.
- 반환은 길이 `n` 인 배열이고 자리 `v` 에 `S(v)` 가 들어갑니다.
- 제약은 `1 <= N <= 100,000` 이고 시간 제한 1 초 · 메모리 제한 256 MB 입니다. 간선 수를
  `E` 라 쓰면 트리에서는 언제나 `E = N - 1` 이라 따로 세지 않습니다.

이 글이 끝까지 쓰는 **기호는 아홉이에요.** 뒤에서 바꾸지 않습니다.

| 기호 | 무엇 |
| --- | --- |
| `N` | 정점 수. 코드의 매개변수 이름은 `n` 입니다 |
| `d(v, u)` | 정점 `v` 와 `u` 를 잇는 경로 위의 간선 수 |
| `S(v)` | `v` 에서 나머지 정점 전부까지 거리의 합. 구해야 하는 답입니다 |
| `near[v]` | 정점 `v` 의 이웃 목록 |
| `order` | 첫 순회가 정점을 꺼낸 순서를 적어 둔 배열 |
| `parent[v]` | 기준 뿌리 0 에서 봤을 때 `v` 의 부모. 뿌리 자신은 `-1` 입니다 |
| `depth[v]` | 기준 뿌리 0 에서 `v` 까지의 거리 |
| `size[v]` | 기준 뿌리 0 에서 봤을 때 `v` 의 부분트리에 든 정점 수. 자신을 포함합니다. 식에서는 `size(v)` 로 적고 코드에서는 `size` 배열의 `v` 번 칸입니다 |
| `answer[v]` | 코드가 `S(v)` 를 담는 배열 |

**둘째, 가장 단순한 방법을 세우고 수치로 반박합니다.** 아무 기법 없이 푸는 방법은 정점마다 너비
우선 탐색을 한 번씩 실행하는 것이에요. 답이 맞는다는 것은 정의 그대로라 확실하고, 문제는
횟수입니다.

<!--proof:naiveScale-->

```text
정점 N   간선  탐색 한 번  정점마다 탐색  이 글이 세울 절차
     8      7          29            246                 65
    64     63         253         16,318                569
   512    511       2,045      1,048,062              4,601
 4,096  4,095      16,381     67,104,766             36,857

트리는 간선이 E = N - 1 이라 탐색 한 번이 4N - 3 번이고 그것을 N 번 한다
  N = 8 에서 2(N-1) + N(4N-3) = 246 이고 위 표의 246 과 같다
제약 규모 N = 100,000 이면
  정점마다 탐색  2(N-1) + N(4N-3) = 39,999,899,998 번
  이 글이 세울 절차  899,993 번
```

**400 억 번은 1 초 안에 안 끝납니다.** 정점 4,096 짜리 입력에서 이미 6,710 만 번이고, 정점 수를
스물네 배 늘리면 횟수가 596 배가 돼요. 이 방법이 하는 일 중 낭비를 찾아야 합니다.

```text
정점 다섯짜리 트리에서 이 방법이 되풀이하는 것

  정점 0 에서 탐색   간선 넷을 전부 읽는다
  정점 1 에서 탐색   같은 간선 넷을 전부 읽는다
  정점 2 에서 탐색   같은 간선 넷을 전부 읽는다
  정점 3 에서 탐색   같은 간선 넷을 전부 읽는다
  정점 4 에서 탐색   같은 간선 넷을 전부 읽는다

  다섯 번 모두 같은 트리를 지나간다. 달라지는 것은 출발점 하나뿐이다
```

**셋째, 답 하나는 순회 한 번으로 나옵니다.** 정점 0 을 기준으로 삼으면 `S(0)` 은 `depth` 를 그대로
더한 값이에요. `depth[v]` 의 정의가 「정점 0 에서 `v` 까지의 거리」라서 그렇습니다.

<!--proof:rootByDepth-->

```text
정점    정점 0 에서의 거리
정점 0                   0
정점 1                   1
정점 2                   1
정점 3                   2
정점 4                   2

합 0 + 1 + 1 + 2 + 2 = 6
너비 우선 탐색으로 직접 구한 S(0) = 6
```

그러니까 문제는 `S(0)` 이 아니라 나머지 넷입니다. **넷째, 그 넷을 각각 처음부터 구하는 대신 이미
구한 `S(0)` 에서 얼마나 달라지는지를 두 경우로 재 봅시다.** 뿌리를 0 에서 이웃 1 로 옮길 때와
이웃 2 로 옮길 때, 몇 개가 가까워지고 몇 개가 멀어지는지 직접 셉니다.

<!--proof:moveOne-->

```text
옮긴 방향  가까워지는 정점  멀어지는 정점  S(0) 에서 고친 값  직접 구한 값
0 -> 1                   3              2  6 - 3 + 2 = 5      5
0 -> 2                   1              4  6 - 1 + 4 = 9      9

가까워지는 정점은 옮겨 간 쪽 부분트리 안에 있는 것이고 나머지가 멀어진다
```

두 줄에서 같은 모양이 나왔어요. **가까워지는 정점 수 + 멀어지는 정점 수 = 5** 이고, 가까워지는
정점은 언제나 옮겨 간 방향의 조각입니다. 이 관찰이 규칙의 재료이고, 같은 관찰을 계수로 옮기면
두 방식이 이렇게 갈려요.

<!--proof:costTwoWays-->

```text
정점 N  정점마다 탐색  한 번 순회하고 전파      비율
     8            246                   65    3.8 배
    64         16,318                  569   28.7 배
   512      1,048,062                4,601  227.8 배
```

**다섯째, 「옮겨 간 방향의 조각」을 개념으로 정의합니다.** 가장 단순한 후보는 「옮길 때마다 그 조각을
세어 본다」예요. 조각의 정점 수를 세려면 그 조각을 한 번 지나가야 하니, 옮김 한 번이 조각 크기에
비례합니다. 실제로 재 보면 이렇습니다.

<!--proof:recountCost-->

```text
정점 N  옮길 때마다 세면  크기를 미리 두면      비율
     8                16                 7    2.3 배
    64             1,024                63   16.3 배
   512            65,536               511  128.3 배

옮김 횟수는 두 방식이 N - 1 로 같고, 한 번의 옮김에 드는 것이 갈린다
```

**옮김 횟수가 아니라 한 번의 옮김 비용이 큰 것이 문제입니다.** 그래서 조각 크기를 **미리 한 벌**
만들어 두기로 합니다. 이때 「어느 조각인가」를 정하는 방법이 결정적이에요 — 기준 뿌리를 **정점
0 하나로 고정**하고, 그 뿌리에서 본 부분트리 크기 `size[v]` 를 한 벌만 만듭니다. 대신
「현재 뿌리에서 본 크기」로 정의하면 안 되는 이유를 값으로 보겠습니다.

<!--proof:basisFixed-->

```text
기준              size 배열
뿌리 0 으로 고정  5 4 3 2 1

옮겨 잡을 때마다 다시 재면  size 배열
뿌리 0 기준                 5 4 3 2 1
뿌리 1 기준                 1 5 3 2 1
뿌리 2 기준                 1 2 5 2 1
뿌리 3 기준                 1 2 3 5 1
뿌리 4 기준                 1 2 3 4 5

다섯 벌을 각각 만들려면 한 벌마다 순회가 한 번씩 더 든다
```

**뿌리를 옮겨 잡을 때마다 `size` 배열 전체가 달라집니다.** 다섯 벌을 각각 만들면 순회가 다섯 번
필요하고, 그것은 정점마다 탐색하는 방법과 같은 비용이에요. 기준을 하나로 고정하면 배열이 한 벌이고, 간선
`(p, c)` 에서 `c` 가 `p` 의 자식일 때 `c` 쪽 조각의 크기가 곧 `size[c]` 입니다.

이 정의로 각 상태 변수의 범위도 정해집니다.

| 상태 변수 | 범위 | 그 끝값이 나오는 자리 |
| --- | --- | --- |
| `size[v]` | `1` 이상 `N` 이하 | 잎에서 `1` · 기준 뿌리에서 `size[0] = N` |
| `depth[v]` | `0` 이상 `N-1` 이하 | 기준 뿌리에서 `0` · 사슬의 반대쪽 끝에서 `N-1` |
| `answer[v]` | `N-1` 이상 | 별의 가운데 정점에서 `N-1` |

**여섯째, 규칙의 결론을 값으로 냅니다.** 정점 일곱짜리 트리에서 여섯 간선 전부를 놓고, 실제 답의
차이와 `N - 2 x size(c)` 가 같은지 대조합니다.

<!--proof:deltaAll-->

```text
옮긴 방향  자식의 size  S(부모)  S(자식)  실제 차이  식이 낸 값
0 -> 2               3       11       12          1  7 - 2 x 3 = 1
2 -> 5               2       12       15          3  7 - 2 x 2 = 3
5 -> 6               1       15       20          5  7 - 2 x 1 = 5
0 -> 1               3       11       12          1  7 - 2 x 3 = 1
1 -> 4               1       12       17          5  7 - 2 x 1 = 5
1 -> 3               1       12       17          5  7 - 2 x 1 = 5

여섯 간선 전부에서 실제 차이와 식이 낸 값이 같다
행 순서는 방문 순서 order 를 따른다
```

**여섯 자리 모두 맞습니다.** `size(c)` 가 `N/2` 보다 작으면 차이가 양수라 답이 커지고, 크면
음수라 답이 작아져요. 정점 일곱에서 `size = 3` 이면 `7 - 6 = 1` 만큼 커지고 `size = 1` 이면
`7 - 2 = 5` 만큼 커집니다.

### 수행으로 알아보는 알고리즘 — 정점 일곱 개짜리 트리를 열 걸음으로 처리한다

끝까지 쓸 고정 입력은 정점 일곱 · 간선 여섯짜리 트리입니다. 이 모양을 고른 이유는 갈래를 한
입력에서 전부 실행하기 위해서예요 — 뿌리에 자식이 둘이라 스택에 두 정점이 함께 담기는 자리가
나오고, 한쪽은 잎 둘을 단 깊이 2 이며 다른 쪽은 깊이 3 까지 한 줄로 이어져서 부분트리 크기가
`1 · 2 · 3 · 7` 로 갈립니다.

```text
treeRerooting(7, [[0,1],[0,2],[1,3],[1,4],[2,5],[5,6]])

        0
       / \
      1   2
     / \   \
    3   4   5
             \
              6

절차 한 장

  ① near 만들기      간선 여섯을 정점마다의 이웃 목록으로
  ② 첫 순회          배열 스택으로 order · parent · depth
  ③ 크기 누적        order 를 뒤에서 앞으로 읽으며 size
  ④ 기준 뿌리의 답   depth 의 합
  ⑤ 답 전파          order 를 앞에서 뒤로 읽으며 answer
```

<!--viz:rerootWalk-->

```text
T1   이웃 목록을 만든다        near 항목 12 개                       ①
T2   정점 0 을 꺼낸다          스택 [1, 2]        order [0]          ②
T3   정점 2 · 5 · 6 을 꺼낸다  스택 [1]           order [0,2,5,6]    ②
T4   정점 1 · 4 · 3 을 꺼낸다  스택 []            order [0,2,5,6,1,4,3]  ②
T5   크기 누적 i = 6, 5, 4     size 4 3 1 1 1 1 1                    ③
T6   크기 누적 i = 3, 2, 1     size 7 3 3 1 1 2 1                    ③
```

#### 1. 이웃 목록을 만들고 배열 스택으로 한 번 따라간다

```ts
const near: number[][] = Array.from({ length: n }, () => []);
for (const [a, b] of edges) {
```

#### 멈춤 — 재귀로 적으면 사슬 트리에서 답이 안 나온다

여기서 헷갈리기 쉬운 포인트는 **왜 재귀를 안 쓰는가**입니다. 트리 순회는 재귀로 적는 것이
짧고 읽기도 쉬워서, 배열 스택은 취향 문제로 읽히기 쉬워요. 재귀로 적은 사본을 만들어 사슬
트리에 실행해 봅시다.

```ts
const down = (v: number, p: number): void => {
  for (const c of near[v] as number[]) {
    if (c === p) continue;
    depth[c] = (depth[v] as number) + 1;
    down(c, v);                            // 여기서 호출 깊이가 트리 깊이만큼 쌓인다
    size[v] = (size[v] as number) + (size[c] as number);
  }
};
```

```text
사슬 정점 수  필요한 호출 깊이  재귀 사본        배열 스택 최대 길이
       1,000               999  끝까지 실행된다                    1
      10,000             9,999  끝까지 실행된다                    1

배열 스택은 사슬에서 길이가 1 을 넘지 않는다 — 자식이 하나뿐이라 담자마자 꺼낸다
```

**제약 상한인 정점 10 만짜리 사슬에서 `RangeError` 가 납니다.** 사슬은 각 정점의 자식이 하나뿐인
트리라 뿌리에서 반대쪽 끝까지의 깊이가 `N - 1` 이고, 재귀 구현의 호출 깊이가 그대로 99,999 가 돼요. 실행 환경이 허용하는
깊이는 그보다 작습니다.

**경계가 실행마다 달라지는 것이 이 자리의 성질입니다.** 위 표의 1,000 과 10,000 은 통과하고
100,000 은 실패하는데, 그 사이 어디가 경계인지는 호출 프레임 크기와 그때의 스택 사용량에 달려
있어 고정된 수가 아니에요. 그래서 「어느 크기까지 재귀로 괜찮다」를 값으로 적을 수 없고, 배열
스택으로 옮기면 그 질문 자체가 없어집니다. 배열 스택의 최대 길이는 사슬에서 1 이고, 가장 길어지는
입력에서도 정점 수를 넘지 않아요.

#### 멈춤 — 스택을 큐로 바꿔도 답이 안 틀린다

여기서 헷갈리기 쉬운 포인트는 **첫 순회가 깊이 우선이어야 하는가**입니다. 이 절차를 「깊이 우선
탐색 두 번」으로 요약하면 스택을 큐로 바꾸는 순간 성립하지 않는 것처럼 읽혀요. 꺼내는 자리 한
줄만 바꿔 봅시다.

```ts
while (stack.length > 0) {

  order.push(u);
  for (const w of near[u] as number[]) {
    if (seen[w]) continue;
    seen[w] = true;
    parent[w] = u;
    depth[w] = (depth[u] as number) + 1;
    stack.push(w);
  }
}
```

재지 않았습니다.

#### 2. 방문 순서를 뒤에서 앞으로 읽어 부분트리 크기를 누적한다

둘째 조각은 `size` 입니다. `order` 는 부모가 자식보다 **앞에** 있는 순서라, 거꾸로 읽으면 자식이
부모보다 먼저 나와요. 자기 크기가 완성된 정점이 부모에게 그 값을 더해 주면 됩니다.

```ts
// ③ 방문 순서의 뒤에서 앞으로 오면서 자식의 크기를 부모에 더한다. 자식이 언제나 부모보다
// 뒤에 있으므로 부모 차례가 왔을 때 그 부분트리 크기가 이미 완성돼 있다.
for (let i = order.length - 1; i >= 1; i--) {
  const w = order[i] as number;
  const p = parent[w] as number;
  size[p] = (size[p] as number) + (size[w] as number);
}
```

#### 3. 기준 뿌리의 답을 깊이의 합으로 구한다

셋째 조각은 한 줄짜리입니다. 기준 뿌리 0 에서 정점 `v` 까지의 거리가 `depth[v]` 이므로, 깊이를
그대로 더하면 `S(0)` 이 나와요.

```ts
// ④ 기준 뿌리의 답은 깊이의 합이다. 뿌리에서 정점 v 까지의 거리가 곧 depth[v] 다.
const answer: number[] = Array.from({ length: n }, () => 0);
let atRoot = 0;
for (let v = 0; v < n; v++) atRoot += depth[v] as number;
answer[0] = atRoot;
```

그대로 구하고, 나머지는 전부 차이로 얻습니다.**

#### 4. 방문 순서대로 부모의 답에서 자식의 답을 낸다

마지막 조각이 규칙을 적용하는 자리입니다. `order` 를 앞에서 뒤로 읽으면 부모가 언제나 먼저
나오므로, 읽는 시점에 `answer[p]` 는 이미 정해져 있어요.

```ts
// ⑤ 방문 순서대로 부모의 답에서 자식의 답을 낸다. 자식 쪽 size[w] 개가 한 칸 가까워지고
// 나머지 n - size[w] 개가 한 칸 멀어진다.
for (let i = 1; i < order.length; i++) {
  const w = order[i] as number;
  const p = parent[w] as number;
  answer[w] = (answer[p] as number) + n - 2 * (size[w] as number);
}
```

#### 5. 전체 코드

앞 조각들을 순서대로 붙인 것입니다. 조각에 안 나온 것은 `parent` · `depth` · `size` 세 배열의
선언 자리 하나뿐이고, 정점이 하나뿐인 입력은 특례 없이 그대로 처리됩니다 — `order` 가 `[0]`
한 칸이라 ③ 과 ⑤ 의 반복문이 한 번도 실행되지 않고 ④ 의 깊이 합 0 이 그대로 답이 돼요.

```ts
export function treeRerooting(n: number, edges: [number, number][]): number[] {
  // ① 간선 목록을 정점마다의 이웃 목록으로 옮긴다. 무방향이라 양쪽에 넣는다.
  const near: number[][] = Array.from({ length: n }, () => []);
  for (const [a, b] of edges) {
    (near[a] as number[]).push(b);
    (near[b] as number[]).push(a);
  }

  const parent: number[] = Array.from({ length: n }, () => -1);
  const depth: number[] = Array.from({ length: n }, () => 0);
  const size: number[] = Array.from({ length: n }, () => 1);

  // ② 기준 뿌리 0 에서 한 번 따라가며 방문 순서·부모·깊이를 정한다. 이미 지나온 정점은
  // 자식이 아니다 — 이웃 목록이 양방향이라 부모가 거기 들어 있다.
  const order: number[] = [];
  const seen: boolean[] = Array.from({ length: n }, () => false);
  const stack: number[] = [0];
  seen[0] = true;
  while (stack.length > 0) {
    const u = stack.pop() as number;
    order.push(u);
    for (const w of near[u] as number[]) {
      if (seen[w]) continue;
      seen[w] = true;
      parent[w] = u;
      depth[w] = (depth[u] as number) + 1;
      stack.push(w);
    }
  }

  // ③ 방문 순서의 뒤에서 앞으로 오면서 자식의 크기를 부모에 더한다. 자식이 언제나 부모보다
  // 뒤에 있으므로 부모 차례가 왔을 때 그 부분트리 크기가 이미 완성돼 있다.
  for (let i = order.length - 1; i >= 1; i--) {
    const w = order[i] as number;
    const p = parent[w] as number;
    size[p] = (size[p] as number) + (size[w] as number);
  }

  // ④ 기준 뿌리의 답은 깊이의 합이다. 뿌리에서 정점 v 까지의 거리가 곧 depth[v] 다.
  const answer: number[] = Array.from({ length: n }, () => 0);
  let atRoot = 0;
  for (let v = 0; v < n; v++) atRoot += depth[v] as number;
  answer[0] = atRoot;

  // ⑤ 방문 순서대로 부모의 답에서 자식의 답을 낸다. 자식 쪽 size[w] 개가 한 칸 가까워지고
  // 나머지 n - size[w] 개가 한 칸 멀어진다.
  for (let i = 1; i < order.length; i++) {
    const w = order[i] as number;
    const p = parent[w] as number;
    answer[w] = (answer[p] as number) + n - 2 * (size[w] as number);
  }

  return answer;
}
```

### 알아 두면 좋은 개념 — 트리의 무게 중심

파트 1 이 값으로 보인 것 중에 이름이 붙어 있는 것이 하나 있습니다. **답이 가장 작은 정점**이에요.
사슬 다섯에서 답이 `[10, 7, 6, 7, 10]` 이라 가운데 정점 2 가 가장 작았고, 별 다섯에서는
`[4, 7, 7, 7, 7]` 이라 가운데 정점 0 이 가장 작았습니다.

이 정점을 **트리의 무게 중심**이라고 부릅니다. 「그 정점을 떼면 남는 조각이 전부 정점 수의 절반
이하」인 정점이고, 위 표의 「그 정점을 뗀 최대 조각」 열과 「N/2 의 내림」 열이 네 입력에서 그 조건이
성립하는 것을 보입니다. 이 글의
규칙으로 보면 이유도 간단해요 — 부모에서 자식으로 옮길 때 답이 `N - 2 x size(c)` 만큼 달라지니,
`size(c)` 가 절반을 넘는 방향으로만 답이 작아지고 그런 방향이 없는 자리가 곧 가장 작은 자리입니다.

같은 이름을 다른 자리에서 다시 만납니다. 무게 중심을 떼고 남은 조각에 같은 일을 되풀이하는
**무게 중심 분할**은 트리 위의 경로 문제를 조각으로 나누어 푸는 뼈대이고, 「모든 지점에서의
이동 거리 합이 가장 작은 자리를 고른다」는 시설 배치 문제도 같은 것을 묻습니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 이 세운 절차를 놓고 어디에 맞는지 · 무엇이 보장되는지 · 얼마나 드는지를 따집니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

- **입력이 트리입니다.** 사이클이 하나라도 있으면 간선을 지웠을 때 두 조각으로 갈린다는 전제가
  성립하지 않고, 그 전제가 이 규칙 전부예요.
- **모든 정점의 답을 요구합니다.** 정점 하나의 답만 필요하면 그 정점에서 탐색을 한 번 하는 것이
  더 적게 듭니다. 이 절차의 값은 `N` 개를 한 번에 채우는 데 있어요.
- **이웃한 두 답의 차이가 상수 개의 미리 계산된 값으로 적힙니다.** 거리 합에서는 그 값이
  `size` 하나이고, 그래서 규칙이 `S(p) + N - 2 x size(c)` 한 줄이 됩니다.
- **트리가 바뀌지 않습니다.** 간선이 붙었다 떨어졌다 하면 `size` 를 매번 다시 만들어야 하고,
  그때는 이 전처리가 값을 잃습니다.

#### 문제에서 이것을 떠올리게 하는 단서

- 「**모든 정점에 대해**」 · 「각 노드를 기준으로」 · 「정점 `i` 를 뿌리로 삼았을 때」 같은 말이
  문제 지문에 있고, 그 대상이 트리인 경우.
- 정점 하나에 대한 답은 순회 한 번으로 쉽게 나오는데 그것을 `N` 번 하면 제한을 넘는 경우.
  정점 수가 `10^5` 언저리이고 시간 제한이 1~2 초면 `O(N^2)` 은 못 씁니다.
- 「뿌리를 옮기면」 · 「어느 정점을 중심으로 잡아야」 같은 말이 그대로 나오는 경우.
- 부분트리에 대한 값은 아래에서 위로 한 번에 모이는데 **정답에는 부모 쪽 정보도 필요한** 경우.
  거리 합에서는 「부모 쪽에 몇 개가 있는가」가 `N - size(v)` 로 적힙니다.

#### 실제로 쓰이는 곳

- **NetworkX 의 `wiener_index`** — 파이썬 그래프 라이브러리가 **모든 정점 짝의 거리 합**을
  구하는 함수입니다. 독스트링이 그 값을 *"The Wiener index of a graph is the sum of the
  shortest-path (weighted) distances between each pair of reachable nodes."* 로 정의하고,
  본문은 `spl = nx.shortest_path_length(G, weight=weight)` 로 **모든 짝**의 거리를 구한 뒤
  `total / 2` 를 반환합니다. 이 글의 답을 전부 더한 값이 그 두 배예요.
  ([`networkx/algorithms/wiener.py`](https://github.com/networkx/networkx/blob/main/networkx/algorithms/wiener.py),
  조회 2026-09-05)
- **NetworkX 의 `closeness_centrality`** — 같은 라이브러리가 정점 하나의 중심성을
  *"the reciprocal of the average shortest path distance to `u` over all `n-1` reachable nodes"*
  로 정의하고 식을 `C(u) = (n - 1) / Σ d(v, u)` 로 적습니다. 분모가 이 글의 `S(u)` 그대로예요.
  구현은 `for n in nodes:` 안에서 정점마다 `path_length(G, n)` 을 부르고 `totsp =
  sum(sp_node.values())` 로 더합니다 — **정점마다 탐색을 한 번씩** 하는 방법입니다.
  ([`networkx/algorithms/centrality/closeness.py`](https://github.com/networkx/networkx/blob/main/networkx/algorithms/centrality/closeness.py),
  조회 2026-09-05)
- **Harry Wiener 의 1947 년 논문** — 「분자 안 모든 탄소 원자 짝 사이 거리의 합」을 끓는점 예측에
  쓴 자리이고, 그 값이 위 `wiener_index` 의 이름이 됐습니다. *Structural determination of
  paraffin boiling points*, *Journal of the American Chemical Society* 69 권 1 호 17–20 쪽,
  DOI `10.1021/ja01193a005`, PMID 20291038.
  ([서지 정보](https://api.semanticscholar.org/graph/v1/paper/DOI:10.1021/ja01193a005), 조회
  2026-09-05)

```text

    ┗ 「고리 없는 탄화수소의 분자 그래프가 트리다」는 트리의 정의에서 바로 나오는 것이지
```

**두 라이브러리가 정점마다 탐색을 하는 것은 잘못이 아닙니다.** 둘 다 트리가 아닌 일반 그래프를
받고 가중치도 받는데, 이 글의 규칙은 **간선 하나가 그래프를 두 조각으로 가른다**는 트리의 성질에
매여 있어요. 입력이 트리라는 것을 아는 쪽이 그만큼 더 적게 쓸 수 있는 자리입니다.

### 수식 정의와 유도

정점 집합을 $V$, 간선 집합을 $E$ 라 하고 $|V| = N$ 으로 둡니다. 두 정점을 잇는 경로 위의 간선
수를 $d(v, u)$ 라 쓰고, 기준 뿌리를 정점 $0$ 으로 고정한 뒤 $\operatorname{ch}(v)$ 를 $v$ 의 자식
집합이라 씁니다. 이 절이 쓰는 정의는 셋이에요.

$$S(v) = \sum_{u \in V} d(v, u) \qquad \operatorname{size}(v) = 1 + \sum_{c \in \operatorname{ch}(v)} \operatorname{size}(c) \qquad \operatorname{depth}(v) = d(0, v)$$

```text
세 정의를 전개 입력의 정점 1 에 넣어 봅니다

  ch(1) = {3, 4}  ->  size(1) = 1 + size(3) + size(4) = 1 + 1 + 1 = 3
  depth(1)         =  d(0, 1) = 1
  S(1)             =  d(1,0) + d(1,2) + d(1,3) + d(1,4) + d(1,5) + d(1,6)
                   =  1 + 2 + 1 + 1 + 3 + 4 = 12
```

일곱 정점 전부에 같은 계산을 하면 이렇게 나옵니다.

**유도 하나 — 이웃한 두 답의 관계.** 간선 $(p, c)$ 에서 $c$ 가 $p$ 의 자식이라 하고 $V$ 를 두
무리로 가릅니다. $A$ 는 $c$ 의 부분트리에 든 정점이고 $B$ 는 나머지라, $|A| = \operatorname{size}(c)$
이고 $|B| = N - \operatorname{size}(c)$ 예요.

```text
간선 (p, c) 를 지우면 트리가 두 조각으로 갈린다

     ...  나머지  ...        A 로 가는 경로는 반드시 c 를 지난다
            |                B 로 가는 경로는 반드시 p 를 지난다
            p    <- B 쪽
            |                A 와 B 는 겹치지 않고 합치면 V 전부다
            c    <- A 쪽     |A| = size(c) 이고 |B| = N - size(c) 다
           / \
        ... ...
```

트리에서 두 정점을 잇는 경로가 하나뿐이므로 $u \in A$ 이면 $d(p, u) = 1 + d(c, u)$ 이고
$u \in B$ 이면 $d(c, u) = 1 + d(p, u)$ 입니다. 이 둘을 $S(c)$ 의 정의에 넣고 두 무리로 갈라
더하면 식이 닫혀요.

$$S(c) = \sum_{u \in A} \bigl(d(p,u) - 1\bigr) + \sum_{u \in B} \bigl(d(p,u) + 1\bigr) = S(p) - |A| + |B| = S(p) + N - 2\operatorname{size}(c)$$

```ts
// 위 식을 그대로 옮긴 한 줄. 코드에서는 자식이 `w` 이고 부모가 `p` 다.
answer[w] = (answer[p] as number) + n - 2 * (size[w] as number);
```

**유도 둘 — 답 전부의 합.** 위 식은 이웃한 두 답의 **관계**라서 답 하나가 있어야 나머지가
나옵니다. 그런데 답 전부의 합만 보면 답 하나 없이도 닫힌 형태가 나와요. $\sum_{v \in V} S(v)$ 는
순서 있는 정점 짝 $(v, u)$ 전부의 거리를 더한 것이고 $d(v, u)$ 는 그 짝을 잇는 경로 위의 간선
수이므로, **간선마다 그 간선을 쓰는 짝이 몇 개인지**를 세면 같은 값이 됩니다. 간선 $e$ 를 지우면
트리가 $a_e$ 개와 $N - a_e$ 개로 갈리고, $e$ 를 쓰는 순서 있는 짝은 정확히 $2 a_e (N - a_e)$
개예요.

$$\sum_{v \in V} S(v) = \sum_{e \in E} 2\,a_e (N - a_e)$$

```text
  간선 (1,2)  조각 2 개와 3 개  ->  2 x 2 x 3 = 12
  간선 (2,3)  조각 3 개와 2 개  ->  2 x 3 x 2 = 12
  간선 (3,4)  조각 4 개와 1 개  ->  2 x 4 x 1 = 8
                                    합 40

  전개 앞에서 실행한 사슬 다섯의 답 [10, 7, 6, 7, 10] 도 합이 40 이다
```

**유도 셋 — 사슬에서의 닫힌 형태.** 정점 $0, 1, \dots, N-1$ 이 한 줄로 이어진 트리에서 정점
$v$ 의 왼쪽에는 $v$ 개가 거리 $1$ 부터 $v$ 까지 놓여 있고 오른쪽에는 $N-1-v$ 개가 거리 $1$ 부터
$N-1-v$ 까지 놓여 있습니다. 양쪽을 등차수열의 합으로 닫으면 이렇게 돼요.

$$S(v) = \frac{v(v+1)}{2} + \frac{(N-1-v)(N-v)}{2}$$

$S(0) = \frac{N(N-1)}{2}$ 입니다. 이것이 **사슬에서의** 최댓값이에요 — 모든 트리를 통틀어 사슬이
가장 큰 값을 내는지는 이 글이 확인하지 않았고, 아래에서 재는 다섯 모양 중에서는 사슬이 가장

```text
불변식 — 언제 · 무엇이

  언제   전파 반복문의 한 바퀴가 끝난 시점. 걸음 중간이 아니다
  무엇   order[0] 부터 order[i] 까지의 정점은 answer 값이 정의 그대로의 S 와 같고
         order[i+1] 부터 끝까지의 정점은 answer 값이 아직 0 이다
```

**유지되는 것을 상태값으로 확인합니다.** 걸음마다 이번에 값을 적은 정점과, 그 시점에 값이
정해진 정점의 목록과, 정의대로 직접 구한 값을 나란히 놓습니다.

<!--proof:invariantHold-->

```text
걸음   이번에 적은 정점  읽은 자리  값이 정해진 정점       적은 값  직접 구한 값  판정
i = 1  정점 2            부모 0     [0, 2]                      12            12  같다
i = 2  정점 5            부모 2     [0, 2, 5]                   15            15  같다
i = 3  정점 6            부모 5     [0, 2, 5, 6]                20            20  같다
i = 4  정점 1            부모 0     [0, 2, 5, 6, 1]             12            12  같다
i = 5  정점 4            부모 1     [0, 2, 5, 6, 1, 4]          17            17  같다
i = 6  정점 3            부모 1     [0, 2, 5, 6, 1, 4, 3]       17            17  같다

값이 정해진 정점의 목록이 방문 순서의 앞부분과 언제나 같다
```

값을 바꾸는 갈래는 둘뿐이에요. **읽는 자리**는 `answer[p]` 하나이고 `p` 는 `order` 에서 `w` 보다
앞에 있으므로 불변식에 따라 이미 정확합니다. **쓰는 자리**는 `answer[w]` 하나이고, 유도한 식이
그 값을 `S(w)` 로 만듭니다. 그래서 목록이 한 칸 늘어난 뒤에도 불변식이 그대로 성립하고, 같은
방식으로 엣지 케이스도 봅니다 — 정점 하나 · 정점 둘 · 가장 작은 사슬과 별, 그리고 제약 상한인
정점 10 만짜리 두 모양입니다.

<!--proof:invariantEdge-->

```text
입력                 절차가 낸 값                       손으로 세운 값                     판정
정점 하나            [0]                                [0]                                같다
정점 둘              [1, 1]                             [1, 1]                             같다
사슬 (정점 3)        [3, 2, 3]                          [3, 2, 3]                          같다
별 (정점 3)          [2, 3, 3]                          [2, 3, 3]                          같다
사슬 (정점 100,000)  [4,999,950,000, 4,999,850,002, …]  [4,999,950,000, 4,999,850,002, …]  같다
별 (정점 100,000)    [99,999, 199,997, …]               [99,999, 199,997, …]               같다

정점 하나면 전파가 한 번도 실행되지 않고 깊이의 합 0 이 그대로 답이다
```

**깨뜨려서 확인합니다.** 불변식을 지키는 줄은 전파의 대입문 하나예요. 그 줄이 「가까워지는
`size[w]` 개를 빼고 멀어지는 `n - size[w]` 개를 더한다」를 `n - 2 * size[w]` 로 적고 있는데,
빼는 항을 빠뜨리고 멀어지는 정점만 더해 봅시다.

```ts
answer[w] = (answer[p] as number) + n - (size[w] as number);   // ← 가까워지는 정점을 안 뺐다
```

<!--proof:mutantHalfDelta-->

```text
입력                정본                          가까워지는 정점을 뺀 판       판정
전개 입력 (정점 7)  [11, 12, 12, 17, 17, 15, 20]  [11, 15, 15, 21, 21, 20, 26]  다르다
사슬 (정점 5)       [10, 7, 6, 7, 10]             [10, 11, 13, 16, 20]          다르다
별 (정점 5)         [4, 7, 7, 7, 7]               [4, 8, 8, 8, 8]               다르다
정점 하나           [0]                           [0]                           같다
```

**세 입력 모두 답이 커집니다.** 정점 일곱에서 정점 6 의 답이 20 이어야 하는데 26 이 나오고,
사슬에서는 가운데가 가장 작아야 하는데 `[10, 11, 13, 16, 20]` 으로 한쪽으로만 커져요. 정점이
하나뿐인 입력에서만 값이 같은데, 그 입력에서는 전파 반복문이 한 번도 실행되지 않기 때문입니다.

### 비용 계산

#### 비용을 세는 과정

기본 연산을 이렇게 셉니다 — 이웃 목록에 항목 하나를 넣는 것 · 이웃 목록의 항목 하나를 읽는 것 ·
스택에 정점 하나를 넣거나 꺼내는 것 · 배열 칸 하나에 값을 적는 것을 각각 하나로 셉니다. 전개의
T1 부터 T10 까지를 라벨별로 나누면 이렇게 됩니다.

<!--proof:perfDerive-->

```text
라벨  하는 일                                 이 입력의 횟수  N 과 E 로
①     이웃 목록을 만든다                                  12  2E
②     첫 순회로 방문 순서·부모·깊이를 정한다              25  N + 2E + (N-1)
③     부분트리 크기를 부모에 더한다                        6  N-1
④     기준 뿌리의 답을 깊이의 합으로 구한다                7  N
⑤     부모의 답에서 자식의 답을 낸다                       6  N-1

다섯 라벨의 합 56 — 실행이 센 기본 연산도 56 이다
트리라 E = N - 1 이므로 총식은 9N - 7 이고, N = 7 에서 56 이다
```

T1 이 ① 이고 T2~T4 가 ② 이며 T5~T6 이 ③, T7 이 ④, T8~T10 이 ⑤ 입니다. **이웃 목록을 읽는
자리는 ② 한 번뿐이에요** — ① 은 간선 목록을 이웃 목록으로 옮겨 담는 자리이고, ③ 과 ⑤ 는
`order` 와 `parent` 만 읽습니다. 트리라 `E = N - 1` 이라는 것을 넣으면 총식이 `9N - 7` 로
닫힙니다.

#### 케이스별 비용과 그 경계

**케이스와 경계는 다른 축입니다.** 케이스는 어떤 입력인가이고, 경계는 그 케이스에서 비용을 어떻게
적었는가예요. 이 절차는 두 축 모두에서 특이한 자리에 있습니다.

<!--proof:perfBounds-->

```text
모양            정점 N  기본 연산   9N - 7  스택 최대 길이
사슬             1,000      8,993    8,993               1
사슬           100,000    899,993  899,993               1
별               1,000      8,993    8,993             999
별             100,000    899,993  899,993          99,999
완전 이진        1,000      8,993    8,993               9
완전 이진      100,000    899,993  899,993              16
애벌레           1,000      8,993    8,993               2
애벌레         100,000    899,993  899,993               2
생성식 무작위    1,000      8,993    8,993              29
생성식 무작위  100,000    899,993  899,993              68

기본 연산은 다섯 모양에서 모두 9N - 7 이고 스택 최대 길이만 모양에 달렸다
```

**모든 케이스에서 기본 연산이 정확히 `9N - 7` 입니다.** 위 표가 다섯 모양에서 그 값을 보이는데,
그것이 표본의 우연이 아닌 근거는 앞 절의 라벨별 횟수예요 — 다섯 라벨이 전부 `N` 과 `E` 만으로
정해지고 트리에서는 `E = N - 1` 이라, 모양이 달라도 값이 같습니다. 그래서 경계를 **타이트한
값**으로 적을 수 있어요 — 상한만 말하는 $O(N)$ 이 아니라 $\Theta(N)$ 이고, 상수까지 적으면
정확히 `9N - 7` 번입니다.

**보장의 종류는 최악 보장입니다.** 기댓값이 아니에요 — 이 절차에는 무작위가 없고, 입력 분포에
대한 가정도 없습니다. 어떤 트리를 넣어도 같은 횟수가 나오는 것을 위 표가 다섯 모양에서 보이고,
저장 칸만 이야기가 다릅니다.

| 무엇 | 칸 수 | 모양에 달렸는가 |
| --- | --- | --- |
| `near` | `2E = 2(N-1)` | 아니다 |
| `parent` · `depth` · `size` · `seen` · `answer` · `order` | 각각 `N`, 합해서 `6N` | 아니다 |
| `stack` | 사슬에서 `1` · 별에서 `N-1` | **그렇다** |

앞의 둘을 더하면 모양과 무관하게 `8N - 2` 칸이고, 거기에 스택만 모양에 따라 붙습니다.

#### 최악을 만드는 입력

**「최악을 만드는 입력」이 축마다 다른 답을 냅니다.** 기본 연산으로 재면 최악이 없고, 스택 길이로
재면 별이며, 답의 크기로 재면 사슬이에요. 셋을 한 표에서 봅니다.

<!--proof:perfWorst-->

```text
정점 100,000 짜리 입력    기본 연산  스택 최대 길이    답의 최댓값
별, 간선 목록 그대로        899,993          99,999        199,997
별, 간선 목록을 뒤집어서    899,993          99,999        199,997
사슬                        899,993               1  4,999,950,000
별                          899,993          99,999        199,997
완전 이진                   899,993              16      2,918,804
애벌레                      899,993               2  2,500,099,998
생성식 무작위               899,993              68      2,426,477

스택이 가장 길어지는 것은 별이고 그 길이는 99,999 이다
답이 가장 커지는 것은 사슬이고 그 값은 4,999,950,000 이다
간선 목록의 순서를 뒤집어도 기본 연산과 스택 최대 길이가 둘 다 안 바뀐다
```

**별 트리가 스택을 가장 길게 만듭니다.** 뿌리 하나를 꺼내면서 나머지 99,999 개를 한꺼번에 담기
때문이에요. 그래도 칸 수로는 `8N - 2` 에 `N - 1` 이 붙어 `9N - 3` 이고, 정점 10 만짜리 별과
사슬을 `treeRerooting-guide.test.ts` 가 실제로 실행해 통과합니다. 칸 하나가 몇 바이트인지와
전체가 256 MB 안에 드는지는 이 글이 바이트로 재지 않았습니다.

**사슬 트리가 답을 가장 크게 만듭니다.** 양 끝 정점의 답이 `N(N-1)/2` 로 50 억에 가까워요.
이것은 비용이 아니라 값의 크기이고, 32 비트 정수 배열을 골랐다면 여기서 실패합니다.

| 재는 축 | 최악을 만드는 입력 | 정점 100,000 에서의 값 |
| --- | --- | --- |
| 기본 연산 | 없다 — 다섯 모양 전부 같다 | 899,993 |
| 스택 최대 길이 | 별 | 99,999 |
| 답의 크기 | 사슬 | 4,999,950,000 |

**간선 목록의 순서는 계수를 안 바꿉니다.** 위 표의 「별, 간선 목록 그대로」 행과 「별, 간선
목록을 뒤집어서」 행이 그 확인이에요 — 기본 연산도 스택 최대 길이도 같습니다. 목록 순서가 바꾸는 것은 `near` 안의 이웃
순서이고, 그래서 `order` 는 달라지지만 각 정점의 이웃을 한 번씩 읽는다는 사실은 그대로입니다.

### 스스로 점검하기

**회수.** 이 절차는 답 하나를 정의대로 구하고(T7), 나머지는 이웃한 두 답의 차이로 채웁니다
(T8~T10). 그 차이가 `N - 2 x size(c)` 한 줄로 적히는 것은 트리에서 간선 하나가 그래프를 정확히
두 조각으로 가르기 때문이에요.

```text
1.  간선 목록을 정점마다의 이웃 목록으로 옮긴다
2.  기준 뿌리 0 에서 배열 스택으로 한 번 지나가며 order · parent · depth 를 적는다
3.  order 를 뒤에서 앞으로 읽으며 자식의 size 를 부모에 더한다
4.  depth 를 전부 더해 answer[0] 을 적는다
5.  order 를 앞에서 뒤로 읽으며 answer[w] = answer[p] + N - 2 x size[w] 를 적는다
```

먼저 답이 붙는 문제 하나입니다. 아래 정점 여섯짜리 트리에서 정점 1 과 정점 3 중 답이 더 작은
것은 어느 쪽이고 그 이유는 무엇일까요? 기준 뿌리를 0 으로 잡고 `size` 부터 세어 보세요.

```text
edges = [[0,1],[1,2],[1,3],[3,4],[3,5]]

        0
        |
        1
       / \
      2   3
         / \
        4   5
```

<!--check:c1-->
답: **둘 다 7 로 같습니다.** 기준 뿌리를 0 으로 잡으면 `size[3] = 3` 이고 `N = 6` 이라, 정점 1
에서 3 으로 옮길 때 답이 `6 - 2 x 3 = 0` 만큼 달라져요. 규칙이 내는 차이가 0 이면 두 답이 같고,
그 조건은 `size(c) = N/2` 입니다.

<!--proof:selfcheckAnswer-->

```text
v  size(v)  depth(v)  answer[v]
0        6         0         11
1        5         1          7
2        1         2         11
3        3         2          7
4        1         3         11
5        1         3         11

방문 순서 [0, 1, 3, 5, 4, 2]
반환값 [11, 7, 11, 7, 11, 11]
```

표의 `answer[v]` 열이 이 트리의 답이고 `size(v)` 열의 3 이 위에서 쓴 값이에요. 정점 0 · 2 · 4 ·
5 는 전부 잎이라 답이 11 로 같고, 가지인 1 과 3 이 7 로 같습니다.

<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요

  1 번 문제  전개의 T5 · T6 과 그 뒤의 「멈춤」
  2 번 문제  「수식 정의와 유도」의 유도 하나
  3 번 문제  「알아 두면 좋은 개념」
```

- 전개의 T5 와 T6 은 `order` 를 뒤에서 앞으로 읽습니다. `order` 대신 정점 번호 순서
  `0, 1, ..., N-1` 로 읽으면 `size` 가 언제 맞고 언제 틀릴까요? 맞는 입력 하나와 틀리는 입력
  하나를 만들어 보세요.
- 이 문제를 **간선마다 가중치가 있는 트리**로 바꾸면 규칙의 어느 부분이 달라질까요? `depth` 의
  정의와 전파 식 중 무엇을 고쳐야 하는지, 그리고 `size` 는 그대로 써도 되는지 확인해 보세요.
- 「각 정점에서 가장 먼 정점까지의 거리」를 모든 정점에 대해 구하려면 이 뼈대의 어디를 고쳐야
  할까요? 부모 쪽에서 자식에게 물려주는 값이 `size` 로 충분한지부터 확인해 보세요.
