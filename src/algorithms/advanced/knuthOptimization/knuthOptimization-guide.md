# 크누스 최적화 — 이웃 두 칸의 최적 가르는 자리가 후보 범위의 양 끝이 되는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 병합 순서를 전부 만드는
방법에서 출발해 크누스 최적화에 이르고, 그 방법을 단계마다 값으로 푼 뒤, 실제로 동작하는 코드를 한 조각씩
만듭니다.

### 전체 컨셉

일렬로 늘어선 파일 `n` 개를 **이웃한 두 묶음씩** 합쳐 하나로 만듭니다. 두 묶음을 한 번 합치는 비용은 두 묶음의
크기 합이고, 합칠 때마다의 비용을 전부 더한 합이 가장 작아지는 순서를 찾는 것이 목표예요. 떨어져 있는 두 묶음은
합칠 수 없습니다. 크기가 `freq = [1, 3, 5, 2]` 인 파일 넷을 합치는 순서를 전부 적어 보면 이렇습니다.

<!--proof:concept-orders-->

| 합치는 순서 | 합칠 때마다의 비용 | 합 |
| --- | --- | ---: |
| ((1+3)+(5+2)) | 4 + 7 + 11 | 22 |
| (((1+3)+5)+2) | 4 + 9 + 11 | 24 |
| (1+(3+(5+2))) | 7 + 10 + 11 | 28 |
| ((1+(3+5))+2) | 8 + 9 + 11 | 28 |
| (1+((3+5)+2)) | 8 + 10 + 11 | 29 |

순서 5 가지 가운데 가장 작은 합은 22 고, 정본 knuthOptimization 도 22 를 돌려줍니다.

<!--/proof-->

같은 파일을 합치는데 순서에 따라 합이 22 부터 29 까지 갈립니다. 순서가 늘어나면 이렇게 전부 적을 수 없으니,
작은 입력의 답을 칸에 적어 두는 **DP 테이블**을 씁니다. 칸 `dp[i][j]` 에 「파일 `i` 부터 `j` 까지인 구간 `[i,j]` 를
하나로 합치는 가장 작은 비용」을 적어요. 어느 순서든 마지막 합치기는 한 번이고, 그 합치기가 왼쪽 묶음 `[i,k]` 와
오른쪽 묶음 `[k+1,j]` 를 합쳤다면 두 묶음은 겹치지 않는 두 구간이에요. 이 `k` 를 **가르는 자리**라 부릅니다. 마지막
합치기의 비용은 어디서 갈라도 구간 전체의 합 `S(i, j)` 라서, 가르는 자리마다 `dp[i][k] + dp[k+1][j]` 를 계산해
가장 작은 값에 `S(i, j)` 를 더하면 칸의 값이 됩니다. 칸 `dp[0][3]` 을 가르는 자리마다 계산하면 이렇습니다.

<!--proof:concept-cell-->

| 가르는 자리 | 나뉜 모양 | dp[0][k] + dp[k+1][3] | 값 |
| --- | --- | --- | ---: |
| k = 0 | 왼쪽 [0,0] · 오른쪽 [1,3] | 0 + 17 | 17 |
| k = 1 | 왼쪽 [0,1] · 오른쪽 [2,3] | 4 + 7 | 11 |
| k = 2 | 왼쪽 [0,2] · 오른쪽 [3,3] | 13 + 0 | 13 |

가장 작은 값은 k = 1 의 11 이고, 마지막 합치기의 비용 S(0, 3) = 11 을 더해 dp[0][3] = 22 입니다.

<!--/proof-->

그 가장 작은 값을 만든 가르는 자리를 그 칸의 **최적 가르는 자리**라 부르고 `opt[i][j]` 로 적습니다. 같은 값을
내는 자리가 여럿이면 가장 작은 `k` 를 고릅니다. 칸마다 값 하나와 최적 가르는 자리 하나가 붙는 셈이라, 이 글은 DP
테이블을 두 벌 둡니다 — 값을 적는 `dp` 와 자리를 적는 `opt` 예요. 이 입력의 두 벌을 한 장에 그렸습니다. 줄이 구간의
시작 `i`, 열이 구간의 끝 `j` 이고, 대시 칸은 `i > j` 라 구간이 아닌 칸입니다. 맨 아래 `freq` 줄이 입력이에요.

<!--fig:concept-table-->
![freq = [1, 3, 5, 2] 의 DP 테이블 — 칸 [0,3] 의 후보를 두 이웃의 자리로 가둔다](./figs/concept-table.svg)

`opt` 의 줄을 왼쪽에서 오른쪽으로 읽으면 자리가 줄지 않고, 열을 위에서 아래로 읽어도 줄지 않습니다. 칸 `[0,3]` 의
**왼쪽 이웃** `[0,2]`(끝을 한 칸 줄인 구간)의 자리가 1 이고 **아래 이웃** `[1,3]`(시작을 한 칸 늘린 구간)의 자리도
1 이에요. 그래서 칸 `[0,3]` 의 최적 가르는 자리는 1 이상 1 이하, 곧 1 뿐이고, 후보 셋 가운데 하나만 넣으면 됩니다.
칸마다 후보를 **왼쪽 이웃과 아래 이웃의 최적 가르는 자리 사이**로 가두는 이 방법을 **크누스 최적화**라고 부릅니다.

```text
DP 테이블의 칸 [i, j] 하나를 채우는 차례

  하한   왼쪽 이웃 [i, j−1] 의 최적 가르는 자리    opt[i][j−1]
  상한   아래 이웃 [i+1, j] 의 최적 가르는 자리    opt[i+1][j]
  그 사이의 가르는 자리만 넣어 가장 작은 값과 그 자리를 적는다
  두 이웃이 먼저 채워져 있도록 구간 길이가 짧은 칸부터 채운다
```

이 「갇힌다」는 아무 비용에서나 성립하지 않습니다. 구간 합 `S` 가 두 성질을 갖춰야 해요. 하나는 **사각 부등식** —
지표 `a ≤ b ≤ c ≤ d` 마다 `S(a, c) + S(b, d) ≤ S(a, d) + S(b, c)` — 이고, 다른 하나는 **단조성** — 안쪽 구간의 합이
바깥 구간의 합을 넘지 않는 것, `S(b, c) ≤ S(a, d)` — 입니다. 파일 크기가 0 이상이면 둘 다 성립하고, 이 글은 쓰는
입력마다 두 성질을 지표 조합을 전부 확인해서 씁니다. 비용을 결과만 적으면 칸이 `n(n−1)/2` 개이고 칸 하나가 후보를
두 개 남짓 넣어 전체가 `O(n²)` 입니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **DP 테이블과 가르는 자리, 구간 길이 차례로 채우기.** 구간마다 칸 하나를 두고, 가르는 자리를 하나씩 넣어 짧은
  칸 둘에서 긴 칸을 만드는 틀입니다. 모르면
  [행렬 체인 곱셈 최소 비용](../../dp/matrixChainMultiplication/matrixChainMultiplication-guide.md)을 먼저 보세요.
  이 글은 거기서 쓴 「DP 테이블」 · 「가르는 자리」 · 「대각선」이라는 말을 그대로 씁니다.
- **최적 가르는 자리와 사각 부등식.** 칸의 값을 만든 자리를 따로 적어 두고, 그 자리가 칸을 따라 한쪽으로만
  움직이는 성질로 후보를 줄이는 생각입니다. 줄 하나 안에서 그 성질을 쓰는 이웃 편이
  [분할 정복 최적화](../divideAndConquerDp/divideAndConquerDp-guide.md)예요.
- **구간 합.** 이 글의 비용은 구간 합이라 앞 누적으로 만듭니다. 모르면
  [구간 합 질의](../../array/prefixSumRangeQuery/prefixSumRangeQuery-guide.md)를 보세요.

몰라도 되는 것은 사각 부등식을 다루는 요령입니다. 이 글은 두 성질에서 이웃 관계가 나오는 유도를 파트 2 의 「수식
정의와 유도」에서 한 줄씩 풀고, 입력이 두 성질을 만족하는지는 지표 조합을 전부 확인해서 봅니다.

### 아이디어를 떠올리는 과정 — 병합 순서 전부 만들기에서 크누스 최적화까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 파일 크기 배열을 받아 가장 작은 비용 합을 돌려주는
함수입니다.

```ts
function knuthOptimization(freq: number[]): number;
```

- 입력: 파일 크기 배열 `freq`. `freq[i]` 는 `i` 번 파일의 크기이고, 번호 차례가 곧 늘어선 차례입니다. 크기는 0
  이상의 정수로 둡니다 — 이 과제가 기대는 전제이고, 깨지면 무엇이 되는지는 「아이디어 상세」에서 실행으로 봅니다.
- 출력: 이웃한 두 묶음만 되풀이해 합쳐 하나로 만들 때 드는 비용 합의 최솟값. 파일이 하나 이하면 합칠 것이 없어
  0 입니다.
- 규모: `1 ≤ n ≤ 2,000` 으로 둡니다. 이 방법은 `dp` 와 `opt` 두 벌을 `n × n` 으로 잡으므로, 흔한 채점 환경의 예산인
  1 초 · 256 MB 에 대어 보면 이렇습니다.

<!--proof:origin-budget-->

| n | dp 와 opt 의 칸 2n² | 칸마다 8 바이트(어림) |
| ---: | ---: | ---: |
| 500 | 500,000 | 4 MB |
| 1,000 | 2,000,000 | 16 MB |
| 2,000 | 8,000,000 | 64 MB |
| 5,000 | 50,000,000 | 400 MB |

`n` 이 2,000 이면 두 벌이 64 MB 라 예산 안에 넉넉히 들고, 5,000 이면 400 MB 로 예산을 넘습니다. 그래서 이 글은
`n` 을 2,000 까지로 둡니다. 칸 하나에 드는 바이트는 배열을 잡는 방식에 달려 있어서, 8 바이트는 어림이에요. 비용은
이 글 끝까지 **후보 수** 하나로 셉니다. 가르는 자리 `k` 하나를 넣어 `dp[i][k] + dp[k+1][j]` 를 만들고 지금까지의
최솟값과 비교한 한 번이 1 이에요. 후보 하나는 읽기 둘 · 덧셈 하나 · 비교 하나로 끝나는 일이라, 1 초에 후보 1 억
개를 처리한다고 어림합니다. 이 글이 끝까지 쓰는 기호는 아홉입니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `n` | 파일의 개수. 코드의 `freq.length` 입니다 | `1 ≤ n ≤ 2,000` |
| `freq[i]` | `i` 번 파일의 크기 | 0 이상의 정수 |
| `i` · `j` | 구간의 시작 번호와 끝 번호 | `0 ≤ i ≤ j < n` |
| `S(i, j)` | 구간 `[i, j]` 의 파일 크기 합 | 0 이상 |
| `dp[i][j]` | 구간 `[i, j]` 를 하나로 합치는 가장 작은 비용 | `i = j` 이면 0 |
| `k` | 가르는 자리 — 마지막 합치기에서 왼쪽 묶음의 마지막 파일 번호 | `i ≤ k < j` |
| `opt[i][j]` | 최적 가르는 자리 — `dp[i][j]` 를 만든 가르는 자리 중 가장 작은 것 | `i ≤ opt[i][j] < j`, `i = j` 이면 `i` |
| `len` | 지금 채우는 대각선의 구간 길이 `j − i + 1` | `2` 부터 `n` 까지 |
| `INF` | 아직 후보를 하나도 넣지 않았다는 표기. 코드의 `Number.POSITIVE_INFINITY` 입니다 | 칸마다 처음 한 번 |

가장 먼저 떠오르는 방법은 **합치는 순서를 전부 만들어** 합이 가장 작은 것을 고르는 것입니다. 마지막 합치기가
가르는 자리 하나를 고르고, 양쪽 묶음이 다시 저마다 순서를 고르므로 순서의 수가 빠르게 불어나요. 작은 입력에서
실제로 만들어 세고, 과제 규모는 같은 점화식으로 수만 세었습니다.

<!--proof:origin-orders-->

| n | 병합 순서의 수 | 출처 |
| ---: | ---: | --- |
| 4 | 5 | 만들어서 센 값 |
| 8 | 429 | 만들어서 센 값 |
| 9 | 1,430 | 만들어서 센 값 |
| 2,000 | 1,199 자리 수 | 점화식으로 센 수의 자릿수 |

만들어서 센 세 줄은 크기가 freq[i] = (i × 7 mod 5) + 1 인 배열이고, 세 줄 모두 가장 작은 합이 정본의 답과 같습니다.

<!--/proof-->

`n = 2,000` 이면 순서가 1,199 자리 수라 하나씩 만들 수 없습니다. 그런데 순서들을 보면 같은 구간을 여러 번 합치고
있어요. 그래서 구간마다 가장 작은 비용만 DP 테이블의 칸에 적어 두고, 칸마다 가르는 자리 `k = i … j−1` 을 전부
넣어 봅니다. 그 방법의 후보 수를 세었습니다.

<!--proof:origin-full-->

| n | 후보 수 | 출처 | 시간(초당 1 억 개 · 어림) |
| ---: | ---: | --- | ---: |
| 8 | 84 | 센 값 | 0.00 초 |
| 64 | 43,680 | 센 값 | 0.00 초 |
| 256 | 2,796,160 | 센 값 | 0.03 초 |
| 2,000 | 1,333,333,000 | 식 — n(n²−1)/6 | 13 초 |

센 값 세 줄은 식 n(n²−1)/6 과 같습니다. 이 방법은 칸마다 가르는 자리를 전부 넣으므로 후보 수가 입력의 값과 무관합니다.

<!--/proof-->

`n` 이 2,000 이면 어림으로 13 초가 걸려 예산 1 초를 훨씬 넘습니다. 칸이 `n(n−1)/2` 개라는 것은 과제가 정하고,
줄일 곳은 **칸 하나가 넣어 보는 가르는 자리의 수** 하나예요. 그 수를 줄이려면 칸마다 최적 가르는 자리가 어디쯤인지
알아야 합니다. 크기가 `freq = [1, 3, 5, 2, 4, 1, 3, 5]` 인 파일 여덟 개에서 칸마다 최적 가르는 자리를 전부 구해
봅시다.

<!--proof:origin-opt-->

| opt[i][j] | j = 0 | j = 1 | j = 2 | j = 3 | j = 4 | j = 5 | j = 6 | j = 7 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| i = 0 | 0 | 0 | 1 | 1 | 2 | 2 | 2 | 2 |
| i = 1 | · | 1 | 1 | 1 | 2 | 2 | 2 | 4 |
| i = 2 | · | · | 2 | 2 | 2 | 2 | 3 | 4 |
| i = 3 | · | · | · | 3 | 3 | 3 | 4 | 4 |
| i = 4 | · | · | · | · | 4 | 4 | 4 | 6 |
| i = 5 | · | · | · | · | · | 5 | 5 | 6 |
| i = 6 | · | · | · | · | · | · | 6 | 6 |
| i = 7 | · | · | · | · | · | · | · | 7 |

freq = [1, 3, 5, 2, 4, 1, 3, 5] 에서 가르는 자리를 전부 넣어 구한 값입니다. 「·」 는 i > j 라 구간이 아닌 칸입니다.

<!--/proof-->

줄을 따라 오른쪽으로 읽어도, 열을 따라 아래로 읽어도 자리가 한 번도 줄지 않습니다. 첫 줄이 0 0 1 1 2 2 2 2 이고
마지막 열이 2 4 4 4 6 6 6 7 이에요. 자리가 이렇게 고르게 움직이니 가장 단순한 생각은 **자리 하나만 찍는 것**입니다.
구간의 가운데 `⌊(i+j)/2⌋` 하나만 넣거나, 왼쪽 이웃의 최적 가르는 자리 `opt[i][j−1]` 하나만 넣어 보았어요.

<!--proof:origin-one-pick-->

| 입력 | 가장 작은 합 | 구간의 가운데 하나 | 왼쪽 이웃의 자리 하나 |
| --- | ---: | ---: | ---: |
| 전개 입력 [1, 3, 5, 2] | 22 | 22 | 28 |
| [10, 20, 30] | 90 | 90 | 110 |
| 크기가 모두 같은 배열 (n = 8) | 24 | 24 | 35 |
| 생성식 배열 (n = 16) | 183 | 184 | 390 |
| 첫 파일만 큰 배열 (n = 9) | 1,032 | 4,025 | 1,043 |

입력 5 개 가운데 「구간의 가운데 하나」는 2 개, 「왼쪽 이웃의 자리 하나」는 5 개에서 가장 작은 합과 다른 값을 냅니다.

<!--/proof-->

**둘 다 틀린 답을 냅니다.** 「구간의 가운데 하나」는 첫 파일만 큰 배열에서 1,032 대신 4,025 를 내고, 「왼쪽 이웃의
자리 하나」는 전개 입력에서도 22 대신 28 을 내요. 가장 작은 값을 만드는 자리가 찍은 그 하나가 아니면 곧장
틀립니다. 그래서 점이 아니라 **범위**로 가둡니다. 줄을 따라 자리가 줄지 않으니 왼쪽 이웃의 자리가 하한이 되고,
열을 따라 줄지 않으니 아래 이웃의 자리가 상한이 돼요. 같은 여덟 파일을 두 방식으로 처리해 첫 줄 `i = 0` 의 칸마다
넣은 후보를 나란히 적었습니다.

<!--proof:origin-two-->

| 칸 | 전부 넣는 후보 | 이웃 두 칸 사이의 후보 | opt[0][j] |
| --- | --- | --- | --- |
| [0,1] | [0,0] · 1 개 | [0,0] · 1 개 | 0 |
| [0,2] | [0,1] · 2 개 | [0,1] · 2 개 | 1 |
| [0,3] | [0,2] · 3 개 | [1,1] · 1 개 | 1 |
| [0,4] | [0,3] · 4 개 | [1,2] · 2 개 | 2 |
| [0,5] | [0,4] · 5 개 | [2,2] · 1 개 | 2 |
| [0,6] | [0,5] · 6 개 | [2,2] · 1 개 | 2 |
| [0,7] | [0,6] · 7 개 | [2,4] · 3 개 | 2 |

줄 i = 0 에서 전부 넣으면 후보 28 개, 이웃 두 칸 사이만 넣으면 11 개입니다. 칸 28 개를 모두 더하면 84 개와 50 개이고, 두 방식의 답은 71 로 같습니다.

<!--/proof-->

관찰한 것은 하나예요. **범위의 두 끝이 이미 채운 두 칸에서 나옵니다.** 칸 `[0,7]` 의 후보가 `[2,4]` 인데, 하한 2
는 왼쪽 이웃 `[0,6]` 의 자리이고 상한 4 는 아래 이웃 `[1,7]` 의 자리예요. 두 이웃은 구간 길이가 하나 짧아서, 구간
길이가 짧은 칸부터 채우면 늘 먼저 채워져 있습니다. 이 방법을 규모를 키워 시험하면 이렇습니다.

<!--proof:origin-sweep-->

| 입력 | n | 전부 넣기 | 이웃 두 칸 사이 | 전부 넣기에 대한 비 |
| --- | ---: | ---: | ---: | ---: |
| 생성식 배열 | 64 | 43,680 | 3,980 | 9.1 % |
| 생성식 배열 | 256 | 2,796,160 | 65,003 | 2.3 % |
| 첫 파일만 큰 배열 | 64 | 43,680 | 4,744 | 10.9 % |
| 첫 파일만 큰 배열 | 256 | 2,796,160 | 78,360 | 2.8 % |

**전부 넣기에 대한 비가 규모를 키울수록 내려갑니다.** 생성식 배열에서 9.1 % 가 2.3 % 가 되고, 첫 파일만 큰
배열에서도 10.9 % 가 2.8 % 가 돼요. 칸 하나가 넣는 후보가 `n` 을 따라 늘지 않기 때문입니다. 과제 규모에서 세면
이렇습니다.

<!--proof:origin-scale-->

| 방법 | 후보 수 | 출처 | 시간(초당 1 억 개 · 어림) |
| --- | ---: | --- | ---: |
| 가르는 자리 전부 넣기 | 1,333,333,000 | 식 — n(n²−1)/6 | 13 초 |
| 이웃 두 칸 사이만 넣기 | 3,996,176 | 센 값 | 0.04 초 |

생성식 배열 freq[i] = (i × 7 mod 5) + 1 을 n = 2,000 으로 만든 값입니다. 두 수의 비는 334 배입니다.

<!--/proof-->

지금까지 해 본 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **크누스 최적화**입니다. DP 테이블을 구간 길이가 짧은 칸부터 채우되, 칸마다 후보를 왼쪽
이웃과 아래 이웃의 최적 가르는 자리 사이로 가둬요. 두 이웃이 왜 범위의 양 끝이 되는지, 범위를 어떻게 적는지, 길이
2 칸처럼 이웃이 파일 하나짜리 구간인 칸은 어떻게 되는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 크누스 최적화

이 아이디어를 한 문장으로 줄이면 이렇습니다. **DP 테이블을 구간 길이가 짧은 칸부터 채우되, 칸 `[i, j]` 에는
가르는 자리를 왼쪽 이웃 `[i, j−1]` 과 아래 이웃 `[i+1, j]` 의 최적 가르는 자리 사이만 넣고, 그 칸의 값과 함께
최적 가르는 자리를 적어 뒤 칸의 범위로 씁니다.** 이 방법이 기대는 것은 칸의 두 이웃이라는 자리인데, 그 두 칸이
DP 테이블의 어디에 있고 왜 하필 그 둘인지가 처음 보는 사람에게는 낯설어요. 그래서 두 이웃을 먼저 따로 설명하고,
그다음 실현하는 순서대로 네 단계를 설명합니다.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 한 번 | 1단계 기저 칸 세우기 | 파일 하나짜리 구간에 `dp = 0` · `opt = 자기 번호`를 적는다 | — |
| 칸마다 | 2단계 이웃 두 칸으로 후보 범위 잡기 | `[opt[i][j−1], min(opt[i+1][j], j−1)]` 을 정한다 | 1단계의 기저, 또는 앞 대각선의 칸 |
| 칸마다 | 3단계 범위 안에서 칸 채우기 | 범위의 가르는 자리만 넣어 가장 작은 값에 `S(i, j)` 를 더하고 그 자리를 적는다 | 2단계의 범위 |
| 대각선마다 | 4단계 구간 길이 차례로 되풀이하기 | 길이 2 부터 `n` 까지 대각선 하나씩 3단계로 채운다 | 3단계가 채운 앞 대각선 |

#### 먼저 알아 둘 개념 — 이웃 두 칸의 최적 가르는 자리

칸 `[i, j]` 의 **왼쪽 이웃**은 끝을 한 칸 줄인 구간 `[i, j−1]` 이고, **아래 이웃**은 시작을 한 칸 늘린 구간
`[i+1, j]` 입니다. 둘 다 칸 `[i, j]` 보다 파일이 하나 적은 구간이에요. 크누스 최적화는 두 이웃의 최적 가르는 자리를
칸 `[i, j]` 의 최적 가르는 자리의 하한과 상한으로 씁니다. 식으로는 `opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j]` 예요.

##### 입력 위의 두 이웃

파일 여덟 개에서 칸 `[2,6]` 과 그 두 이웃이 입력을 어디서 가르는지 막대로 그렸습니다. 한 칸마다 막대가 둘이고,
위 막대가 왼쪽 묶음 `[i, opt]`, 아래 막대가 오른쪽 묶음 `[opt + 1, j]` 예요. 두 막대의 경계가 그 칸의 최적 가르는
자리입니다.

<!--fig:build-split-bars-->
![freq = [1, 3, 5, 2, 4, 1, 3, 5] — 칸 [2,6] 과 두 이웃이 입력을 가르는 자리](./figs/build-split-bars.svg)

왼쪽 이웃 `[2,5]` 는 2 뒤에서, 칸 `[2,6]` 은 3 뒤에서, 아래 이웃 `[3,6]` 은 4 뒤에서 가릅니다. 가운데 칸의 경계가
두 이웃의 경계 사이에 있어요. 파일이 하나 늘어난 쪽으로 경계가 따라가되, 두 이웃의 경계를 넘지는 않습니다.

##### 칸 하나를 읽는 법

칸 `[2,6]` 을 골라 가르는 자리를 전부 넣어 읽어 보겠습니다. 가르는 자리 `k` 마다 왼쪽 묶음 `[2,k]` 의 값과 오른쪽
묶음 `[k+1,6]` 의 값을 더합니다.

<!--proof:build-read-->

| 가르는 자리 | 왼쪽 · 오른쪽 조각 | dp[2][k] + dp[k+1][6] | 값 | 비교 |
| --- | --- | --- | ---: | --- |
| k = 2 | [2,2] · [3,6] | 0 + 20 | 20 |  |
| k = 3 | [2,3] · [4,6] | 7 + 12 | 19 | 가장 작다 |
| k = 4 | [2,4] · [5,6] | 17 + 4 | 21 |  |
| k = 5 | [2,5] · [6,6] | 24 + 0 | 24 |  |

가장 작은 값은 19 고 opt[2][6] = 3 입니다. S(2, 6) = 15 를 더해 dp[2][6] = 34 입니다.

<!--/proof-->

칸 하나를 읽는 순서는 늘 같습니다. 이름 `opt[i][j]` 에서 구간 `[i, j]` 를 찾고, 그 값 `k` 로 입력을 왼쪽 묶음
`[i, k]` 와 오른쪽 묶음 `[k+1, j]` 로 가르면 두 묶음의 값에 `S(i, j)` 를 더한 것이 칸의 값 `dp[i][j]` 가 돼요. 칸
`[2,6]` 이라면 `[2,3]` 과 `[4,6]` 으로 갈라 7 + 12 에 15 를 더한 34 입니다.

##### 이웃한 칸끼리의 관계

같은 입력의 `opt` 전부를 그리고, 칸 `[2,6]` 과 두 이웃을 짚었습니다. 강조색 굵은 테가 칸 `[2,6]`, 진한 테가 두
이웃이에요.

<!--fig:build-opt-table-->
![freq = [1, 3, 5, 2, 4, 1, 3, 5] 의 opt 전부 — 칸 [2,6] 과 두 이웃](./figs/build-opt-table.svg)

왼쪽 이웃은 **같은 줄의 한 칸 왼쪽**, 아래 이웃은 **같은 열의 한 칸 아래**에 있습니다. 둘 다 칸 `[2,6]` 이 놓인
대각선보다 하나 앞 대각선의 칸이에요. 여러 입력에서 칸마다 `opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j]` 가 성립하는지
세었습니다. 가르는 자리는 `j − 1` 을 넘을 수 없으므로 상한 쪽은 `min(opt[i+1][j], j−1)` 과 비교했어요.

<!--proof:build-neighbors-->

| 입력 | 확인한 칸 | 이웃 관계를 어긴 칸 | 처음 어긴 칸 |
| --- | ---: | ---: | --- |
| [1, 3, 5, 2, 4, 1, 3, 5] | 28 | 0 | — |
| 크기가 모두 같은 배열 (n = 8) | 28 | 0 | — |
| 첫 파일만 큰 배열 (n = 9) | 36 | 0 | — |
| 뒤로 갈수록 커지는 배열 (n = 7) | 21 | 0 | — |
| 전개 입력 [1, 3, 5, 2] | 6 | 0 | — |
| 음수가 섞인 배열 [1, 1, 2, -2] | 6 | 1 | [0,3] |

크기가 0 이상인 입력 다섯은 칸을 전부 확인해도 이웃 관계를 어긴 칸이 없고, 크기에 음수가 섞인 입력 하나만 칸
`[0,3]` 에서 어깁니다. 그 입력은 「이 방법이 기대는 전제」에서 다시 봅니다.

##### 구간의 가운데와의 차이

최적 가르는 자리를 처음 보면 「구간을 반으로 가르는 자리 근처에 있겠지」로 읽기 쉽습니다. 첫 파일만 큰 배열에서
구간의 가운데와 최적 가르는 자리를 나란히 놓았어요.

<!--proof:build-contrast-->

| 칸 | 구간의 가운데 ⌊(i+j)/2⌋ | opt[0][j] |
| --- | ---: | ---: |
| [0,2] | 1 | 0 |
| [0,4] | 2 | 0 |
| [0,6] | 3 | 0 |
| [0,8] | 4 | 0 |

첫 파일만 큰 배열 (n = 9) 입니다. 이 입력에서 「구간의 가운데 하나」만 넣으면 4,025 가 나오고, 가장 작은 합은 1,032 입니다.

<!--/proof-->

구간이 길어질수록 가운데는 1 · 2 · 3 · 4 로 뒤로 가는데, 최적 가르는 자리는 0 에 머뭅니다. 큰 파일 하나를 늦게
합칠수록 그 파일의 크기가 덜 여러 번 더해지기 때문이에요. **최적 가르는 자리는 구간의 모양이 아니라 크기의 배치가
정합니다.** 그래서 자리를 식으로 짐작하지 않고, 이미 채운 이웃 칸에서 실제 값을 읽어 옵니다.

##### 두 이웃이 이 방법에 쓰이는 까닭

칸 `[i, j]` 를 채울 때 필요한 것은 하한과 상한 두 개입니다. 하한은 그 칸보다 자리가 작거나 같은 칸에서, 상한은 자리가
크거나 같은 칸에서 와야 해요. 줄을 따라 자리가 줄지 않으니 같은 줄의 왼쪽 칸들이 하한을 주고, 열을 따라 줄지 않으니
같은 열의 아래 칸들이 상한을 줍니다. 그중 칸 `[i, j]` 에 가장 가까운 것이 두 이웃이라 범위가 가장 좁아요.

```text
칸 [i, j] 를 채우는 시점에 이미 채워져 있는 칸

  같은 줄 왼쪽   [i, i] … [i, j−1]      자리가 opt[i][j] 이하   가장 가까운 것이 왼쪽 이웃
  같은 열 아래   [i+1, j] … [j, j]      자리가 opt[i][j] 이상   가장 가까운 것이 아래 이웃

  두 이웃은 파일이 하나 적은 구간이라, 구간 길이 차례로 채우면 바로 앞 대각선에 있다
```

#### 1단계 — 기저 칸 세우기

파일 하나짜리 구간 `[i, i]` 는 합칠 것이 없어 `dp[i][i] = 0` 입니다. 가르는 자리가 없는 칸이지만 `opt[i][i] = i` 로
자기 번호를 적어 둡니다. 길이 2 칸 `[i, i+1]` 의 두 이웃이 바로 이 칸들이기 때문이에요. 전개 입력의 길이 2 칸 셋에서
범위가 어떻게 정해지는지 적었습니다.

<!--proof:build-base-->

| 칸 | 하한 | 아래 이웃의 자리 | j − 1 로 자른 상한 | 후보 범위 |
| --- | --- | --- | --- | --- |
| [0,1] | opt[0][0] = 0 | opt[1][1] = 1 | min(1, 0) = 0 | [0,0] |
| [1,2] | opt[1][1] = 1 | opt[2][2] = 2 | min(2, 1) = 1 | [1,1] |
| [2,3] | opt[2][2] = 2 | opt[3][3] = 3 | min(3, 2) = 2 | [2,2] |

하한은 `opt[i][i] = i` 가 그대로 주고, 상한은 `opt[i+1][i+1] = i+1` 을 `j − 1 = i` 로 한 번 더 자른 값이라 범위가
`[i, i]` 한 자리가 됩니다. 길이 2 칸의 가르는 자리는 `k = i` 하나뿐이니 맞는 범위예요. 이 기저를 안 적으면 무엇이
되는지는 전개의 「짚고 가기」에서 봅니다.

#### 2단계 — 이웃 두 칸으로 후보 범위 잡기

칸 `[i, j]` 의 범위를 `[opt[i][j−1], min(opt[i+1][j], j−1)]` 로 잡습니다. 범위 안에 그 칸의 최적 가르는 자리가
들어 있으면, 범위 안의 가장 작은 값이 곧 칸의 값이에요. 칸 `[2,6]` 을 네 범위로 채워 보았습니다.

<!--proof:build-range-->

| 후보 범위 | 가르는 자리 | 후보 수 | 칸의 값 | 찾은 자리 |
| --- | --- | ---: | ---: | ---: |
| 전부 | [2,5] | 4 | 34 | 3 |
| opt[2][5] 부터 | [2,5] | 4 | 34 | 3 |
| opt[3][6] 까지 | [2,4] | 3 | 34 | 3 |
| 두 이웃 사이 | [2,4] | 3 | 34 | 3 |

네 범위 모두 칸의 값 34 와 찾은 자리 3 이 같고, 후보 수만 4 개와 3 개로 갈립니다. 이 칸에서는 하한 `opt[2][5] = 2`
가 구간의 시작 2 와 같아 하한이 자르는 것이 없고, 상한 `opt[3][6] = 4` 가 5 를 잘랐어요. 하한과 상한 가운데 어느
쪽이 일하는지는 칸마다 다릅니다 — 「아이디어를 떠올리는 과정」의 칸 `[0,7]` 에서는 하한이 0 · 1 을 잘랐습니다.

#### 3단계 — 범위 안에서 칸 채우기

범위의 가르는 자리를 작은 쪽부터 넣으며, 지금까지의 최솟값보다 **작을 때만** 값과 자리를 고칩니다. 같은 값이면
먼저 넣은 작은 `k` 가 남아, `opt[i][j]` 가 가장 작은 최적 가르는 자리가 돼요. 구간 합 `S(i, j)` 는 가르는 자리와
무관하므로 가장 작은 값을 찾은 뒤 한 번만 더합니다. 칸 `[2,6]` 을 채우는 과정입니다.

<!--proof:build-fill-->

| 가르는 자리 | dp[i][k] + dp[k+1][j] | 최솟값과의 비교 | 고친 것 |
| --- | ---: | --- | --- |
| k = 2 | 20 | 20 < INF 참 | best = 20 · bestK = 2 |
| k = 3 | 19 | 19 < 20 참 | best = 19 · bestK = 3 |
| k = 4 | 21 | 21 < 19 거짓 | 그대로 |

칸 [2,6] 의 후보 범위는 [2,4] 입니다. 가장 작은 값 19 에 S(2, 6) = 15 를 한 번 더해 dp[2][6] = 34 를, opt[2][6] 에는 3 을 적습니다.

<!--/proof-->

칸의 값과 함께 **자리도 적는 것**이 이 단계의 요점입니다. 값만 적으면 뒤 칸 `[2,7]` 과 `[1,6]` 이 이 칸을 이웃으로
읽을 때 범위의 끝으로 쓸 수가 없어요.

#### 4단계 — 구간 길이 차례로 되풀이하기

구간 길이 `len` 을 2 부터 `n` 까지 올리며, 길이마다 시작 `i` 를 0 부터 옮겨 대각선 하나를 3단계로 채웁니다. 칸
`[i, j]` 의 두 이웃은 길이 `len − 1` 이라 앞 대각선에서 이미 채워져 있어요. 여덟 파일의 길이 3 · 4 · 5 대각선에서
칸마다 넣은 후보 범위를 막대로 그렸습니다.

<!--fig:build-diagonal-->
![freq = [1, 3, 5, 2, 4, 1, 3, 5] — 구간 길이 3 · 4 · 5 대각선의 후보 범위](./figs/build-diagonal.svg)

같은 대각선에서 이웃한 두 칸의 막대는 **많아야 끝점 하나만** 겹칩니다. 칸 `[i, j]` 의 상한이 `opt[i+1][j]` 이고,
바로 다음 칸 `[i+1, j+1]` 의 하한이 같은 `opt[i+1][j]` 이기 때문이에요. 그래서 대각선 하나의 후보 수를 더하면
「칸 수 + (마지막 상한 − 처음 하한)」을 넘지 않습니다. 대각선마다 세었습니다.

<!--proof:build-diagonal-->

| 구간 길이 | 칸 수 | 후보 수 합 | 처음 하한 → 마지막 상한 | 그 차 | 칸 수 + 그 차 |
| ---: | ---: | ---: | --- | ---: | ---: |
| 2 | 7 | 7 | 0 → 7 | 7 | 14 |
| 3 | 6 | 12 | 0 → 6 | 6 | 12 |
| 4 | 5 | 10 | 1 → 6 | 5 | 10 |
| 5 | 4 | 9 | 1 → 6 | 5 | 9 |
| 6 | 3 | 5 | 2 → 4 | 2 | 5 |
| 7 | 2 | 4 | 2 → 4 | 2 | 4 |
| 8 | 1 | 3 | 2 → 4 | 2 | 3 |

freq = [1, 3, 5, 2, 4, 1, 3, 5] 입니다. 후보 수는 모두 50 이고, 가르는 자리를 전부 넣으면 84 입니다.

<!--/proof-->

길이 3 부터는 「칸 수 + 그 차」가 후보 수 합과 같습니다. 길이 2 만 7 대 14 로 갈리는데, 그 대각선은 상한이 `j − 1` 로
한 번 더 잘려 칸마다 후보가 하나라서예요. 대각선 하나가 칸 수에 `n` 남짓을 더한 만큼이고 대각선이 `n − 1` 개라 전체가
`n²` 규모입니다. 닫힌 상한은 파트 2 의 「수식 정의와 유도」에서 냅니다.

#### 이 방법이 기대는 전제

크누스 최적화는 **칸마다 최적 가르는 자리가 두 이웃의 자리 사이에 있다**는 전제 위에서만 맞습니다. 그 전제는 구간
합이 사각 부등식과 단조성을 만족하면 성립하고(유도는 파트 2 의 「수식 정의와 유도」), 이 글이 쓰는 입력들이 실제로
그런지 지표 넷의 조합을 전부 확인했습니다.

<!--proof:build-premise-quad-->

| 입력 | 확인한 지표 조합 | 사각 부등식을 어긴 조합 | 단조성을 어긴 조합 | 처음 어긴 단조성 (a, b, c, d) |
| --- | ---: | ---: | ---: | --- |
| 전개 입력 (n = 4) | 35 | 0 | 0 | — |
| [1, 3, 5, 2, 4, 1, 3, 5] (n = 8) | 330 | 0 | 0 | — |
| 생성식 배열 (n = 16) | 3,876 | 0 | 0 | — |
| 첫 파일만 큰 배열 (n = 9) | 495 | 0 | 0 | — |
| 음수가 섞인 배열 [1, 1, 2, -2] | 35 | 0 | 5 | 0, 0, 2, 3 |

**사각 부등식은 다섯 입력 전부에서 어긴 조합이 0 입니다** — 음수가 섞인 입력까지 그래요. 구간 합은 이 부등식을 언제나
등호로 만족하기 때문입니다. 양변 모두 `[a, b)` 를 한 번, `[b, c]` 를 두 번, `(c, d]` 를 한 번 더한 값이라 글자 그대로
같은 수예요. 갈리는 것은 단조성이고, 음수가 섞인 입력에서 첫 조합 `(0, 0, 2, 3)` 의 안쪽 `S(0, 2) = 4` 가 그것을 품는
바깥 `S(0, 3) = 2` 보다 큽니다. 그 입력에 크누스 최적화를 실행하면 이렇게 나옵니다.

<!--proof:build-premise-break-->

opt[0][2] = 1 이라 칸 [0,3] 의 하한이 1 이고, 후보 범위는 [1,1] 입니다.

| 가르는 자리 | dp[0][k] + dp[k+1][3] | 값 | 크누스 최적화 |
| --- | --- | ---: | --- |
| k = 0 | 0 + 1 | 1 | 범위 밖 |
| k = 1 | 2 + 0 | 2 | 넣는다 |
| k = 2 | 6 + 0 | 6 | 범위 밖 |

진짜 최적 가르는 자리는 0 인데 범위 밖이라, 크누스 최적화는 4 를 돌려주고 가장 작은 합은 3 입니다.

<!--/proof-->

칸 `[0,2]` 의 최적 가르는 자리가 1 이라 칸 `[0,3]` 은 하한 1 을 받았는데, 칸 `[0,3]` 의 진짜 최적 가르는 자리는 0
이었어요. 가장 작은 값을 내는 후보가 범위 밖으로 나가 이 절차는 틀린 답을 냅니다. **파일 크기가 0 이상이라는 전제가
단조성을 보장하고, 단조성이 이웃 관계를 받칩니다.** 전제가 없으면 가르는 자리를 전부 넣는 쪽으로 가야 합니다.

#### 네 단계를 이은 절차

네 단계를 코드의 차례로 다시 적으면 이렇습니다. 파일이 2,000 개일 때 어림으로 13 초이던 계산이 0.04 초가 돼요.

1. 파일이 하나 이하면 0 을 돌려준다
2. 앞 누적 `prefix` 를 만들고 `dp[i][i] = 0` · `opt[i][i] = i` 를 적는다
3. 구간 길이 `len = 2 … n` 마다 시작 `i` 를 0 부터 옮기며 칸 `[i, j]` 를 고른다(`j = i + len − 1`)
4. 칸마다 `lo = opt[i][j−1]` · `hi = min(opt[i+1][j], j−1)` 로 범위를 잡고, `k = lo … hi` 를 넣어 가장 작은 값과
   그 자리 `bestK` 를 찾는다
5. `dp[i][j]` 에 가장 작은 값 + `S(i, j)`, `opt[i][j]` 에 `bestK` 를 적고, 마지막에 `dp[0][n−1]` 을 돌려준다

### 수행으로 알아보는 알고리즘 — 파일 넷을 여덟 걸음으로 합친다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력을 끝까지 고정해 두고, 조각마다 그 조각만
실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const freq = [1, 3, 5, 2];
// 이 절이 끝나면 22 가 나와야 한다
```

이 입력을 고른 까닭은 하한과 상한이 **둘 다** 좁아져 후보 셋 가운데 하나만 넣는 칸이 나오는 가장 작은 크기이기
때문입니다. 크기 0~9 로 만들 수 있는 배열을 파일 수마다 전부 만들어 세었어요.

<!--proof:walk-input-choice-->

| 파일 수 | 크기 0~9 로 만든 배열 전부 | 후보가 줄어든 배열 | 하한과 상한이 함께 좁아진 칸이 있는 배열 |
| ---: | ---: | ---: | ---: |
| 2 | 100 | 0 | 0 |
| 3 | 1,000 | 0 | 0 |
| 4 | 10,000 | 7,525 | 2,475 |

전개 입력 [1, 3, 5, 2] 에서 그런 칸은 [0,3] 하나입니다.

<!--/proof-->

파일이 셋 이하이면 어떤 배열에서도 후보가 한 번도 줄지 않습니다. 넷이 되어야 줄어드는 배열이 생기고, 그중 넷에 하나
남짓이 두 끝이 함께 좁아지는 칸을 가져요. 여섯 갈래 가운데 조기 반환 하나는 이 입력에서 실행되지 않아, 파일 하나짜리
입력으로 따로 확인합니다.

```text
n ≤ 1 이면 0 을 돌려준다                                           ① 조기 반환
prefix ← freq 의 앞 누적                                            ② 구간 합
dp[i][i] ← 0 · opt[i][i] ← i                                        ③ 기저
len = 2 부터 n 까지, i = 0 부터:
    j ← i + len − 1
    lo ← opt[i][j−1] · hi ← min(opt[i+1][j], j−1)                   ④ 후보 범위
    k = lo … hi 마다 dp[i][k] + dp[k+1][j] 를 만들고
        지금까지보다 작으면 값과 자리 bestK 를 고친다               ⑤ 최솟값 갱신
    dp[i][j] ← 가장 작은 값 + S(i, j) · opt[i][j] ← bestK          ⑥ 칸 채우기
dp[0][n−1] 을 돌려준다
```

#### 1. 구간 합과 기저를 준비한다

첫 조각은 준비입니다. `S(i, j)` 를 칸마다 다시 더하면 그 자체로 `n` 에 비례하는 일이 되므로, 앞 누적 `prefix` 를
만들어 두 값의 차로 얻어요. 그리고 DP 테이블 두 벌을 만들어 기저를 적습니다.

```ts
const n = freq.length;
// ① 병합이 없는 입력 — 파일이 하나 이하면 합칠 상대가 없다.
if (n <= 1) return 0;

// ② 구간 합 — prefix[j+1] - prefix[i] 가 S(i, j) 다.
const prefix = new Array<number>(n + 1).fill(0);
for (let i = 0; i < n; i++)
  prefix[i + 1] = (prefix[i] as number) + (freq[i] as number);

const dp: number[][] = Array.from({ length: n }, () =>
  new Array<number>(n).fill(0),
);
const opt: number[][] = Array.from({ length: n }, () =>
  new Array<number>(n).fill(0),
);
// ③ 기저 — 길이 1 구간은 합칠 것이 없어 비용이 0 이고 가르는 자리가 자기 번호다.
for (let i = 0; i < n; i++) (opt[i] as number[])[i] = i;
```

실행하면 이렇게 나옵니다.

<!--proof:walk-prep-->

| 배열 | T1 뒤의 값 | 적은 까닭 |
| --- | --- | --- |
| prefix | 0 1 4 9 11 | S(1, 3) = prefix[4] − prefix[1] = 11 − 1 = 10 |
| dp[i][i] | 0 0 0 0 | 파일 하나짜리 구간은 합칠 것이 없다 |
| opt[i][i] | 0 1 2 3 | 가르는 자리를 자기 번호로 둔다 |

`dp` 는 처음부터 0 으로 채워 두었으니 대각선은 따로 적지 않아도 0 이에요. `opt` 의 대각선만 자기 번호로 바꿉니다.

#### 2. 칸 하나를 이웃 두 칸 사이에서 채운다

둘째 조각이 본체입니다. 칸 `[i, j]` 의 범위를 두 이웃으로 잡고, 그 안에서 가장 작은 값과 그 자리를 찾은 다음, 구간
합을 더해 두 벌에 적어요.

```ts
const j = i + len - 1;
let best = INF;
let bestK = i;
// ④ 후보 범위 — 하한은 왼쪽 이웃 칸의 최적 가르는 자리다.
const lo = (opt[i] as number[])[j - 1] as number;
// 상한은 아래 이웃 칸의 최적 가르는 자리를 j-1 로 한 번 더 자른 값이다.
const hi = Math.min((opt[i + 1] as number[])[j] as number, j - 1);
for (let k = lo; k <= hi; k++) {
  const val =
    ((dp[i] as number[])[k] as number) +
    ((dp[k + 1] as number[])[j] as number);
  // ⑤ 최솟값 갱신 — 값과 그 값이 나온 가르는 자리를 함께 남긴다.
  if (val < best) {
    best = val;
    bestK = k;
  }
}
// ⑥ 칸 채우기 — 구간 합은 가르는 자리와 무관하므로 마지막에 한 번만 더한다.
(dp[i] as number[])[j] =
  best + ((prefix[j + 1] as number) - (prefix[i] as number));
(opt[i] as number[])[j] = bestK;
```

`len = 2` 로 이 조각을 세 번 실행하면 이렇게 나옵니다.

<!--proof:walk-len2-->

```text
T2 — 칸 [0,1]
  후보 범위  [opt[0][0], min(opt[1][1], 0)] = [0, min(1, 0)] = [0,0]
  k = 0      dp[0][0] + dp[1][1] = 0
  채움       dp[0][1] = 0 + S(0, 1) = 4 · opt[0][1] = 0

T3 — 칸 [1,2]
  후보 범위  [opt[1][1], min(opt[2][2], 1)] = [1, min(2, 1)] = [1,1]
  k = 1      dp[1][1] + dp[2][2] = 0
  채움       dp[1][2] = 0 + S(1, 2) = 8 · opt[1][2] = 1

T4 — 칸 [2,3]
  후보 범위  [opt[2][2], min(opt[3][3], 2)] = [2, min(3, 2)] = [2,2]
  k = 2      dp[2][2] + dp[3][3] = 0
  채움       dp[2][3] = 0 + S(2, 3) = 7 · opt[2][3] = 2
```

여기서 가장 중요한 줄은 `Math.min(…, j - 1)` 입니다. 길이 2 칸에서 아래 이웃의 자리 `opt[i+1][i+1]` 은 `i+1` 인데
가르는 자리는 `j − 1 = i` 이하여야 해요. 자르지 않으면 `k = j` 가 후보가 되어 아직 채우지 않은 `dp[i][j]` 와 구간이
아닌 `dp[j+1][j]` 를 읽고, 마지막 열에서는 `dp[n]` 이라는 없는 줄까지 읽습니다. 길이 3 부터는 아래 이웃의 자리가 이미
그 구간 안쪽이라 이 자르기가 값을 바꾸지 않아요.

#### 짚고 가기 — 기저의 최적 가르는 자리를 안 세우면 길이 2 는 맞고 길이 3 부터 틀린다

여기서 헷갈리기 쉬운 포인트는 1번 조각의 `opt[i][i] = i` 줄입니다. 「`opt` 를 이미 0 으로 채워 두었는데 굳이 대각선을
다시 적어야 하나」로 읽기 쉬워요. 그 줄을 빼고 세 입력에 실행했습니다.

```ts
// for (let i = 0; i < n; i++) (opt[i] as number[])[i] = i;   ← 이 줄을 뺐다
```

<!--proof:pause-no-base-->

| 입력 | 정본 | 기저를 뺀 판 | 판정 |
| --- | ---: | ---: | --- |
| 전개 입력 | 22 | 21 | 다르다 |
| 크기가 모두 같은 입력 | 12 | 9 | 다르다 |
| [10, 20, 30] | 90 | 110 | 다르다 |

**세 입력 모두에서 답이 갈립니다.** 그런데 어디서 갈리는지가 중요해요. 정본과 뺀 판의 두 벌을 나란히 놓았습니다.

<!--proof:pause-no-base-rows-->

| 줄 | 정본 dp | 기저를 뺀 판 dp | 정본 opt | 기저를 뺀 판 opt |
| --- | --- | --- | --- | --- |
| i = 0 | 0 4 13 22 | 0 4 17 21 | 0 0 1 1 | 0 0 0 0 |
| i = 1 | · 0 8 17 | · 0 8 10 | · 1 1 1 | · 0 0 0 |
| i = 2 | · · 0 7 | · · 0 7 | · · 2 2 | · · 0 0 |
| i = 3 | · · · 0 | · · · 0 | · · · 3 | · · · 0 |

길이 2 칸의 dp 는 두 판이 같고, 반환값은 22 와 21 입니다.

<!--/proof-->

**길이 2 칸의 `dp` 는 두 판이 같습니다.** 기저를 빼면 길이 2 칸의 범위가 `[opt[i][i], min(opt[i+1][i+1], i)] =
[0, 0]` 이 되어 `k = 0` 하나만 넣어요. `i > 0` 인 칸에서 그 `k` 는 구간 밖인데, 읽는 두 칸이 모두 아직 0 이라 합 0
이 그대로 가장 작은 값이 되고 **값은 우연히 맞습니다.** 갈리는 것은 `opt` 뿐이고 그것이 전부 0 이 돼요. 그 0 이 다음
대각선의 범위가 되면서 어긋남이 값으로 나옵니다.

<!--proof:pause-no-base-why-->

```text
기저를 뺀 판의 칸 [0,2]
  후보 범위  [opt[0][1], min(opt[1][2], 1)] = [0, min(0, 1)] = [0,0]
  k = 0      dp[0][0] + dp[1][2] = 8
  채움       8 + S(0, 2) = 8 + 9 = 17

기저를 뺀 판의 칸 [0,3]
  후보 범위  [opt[0][2], min(opt[1][3], 2)] = [0, min(0, 2)] = [0,0]
  k = 0      dp[0][0] + dp[1][3] = 10
  채움       10 + S(0, 3) = 10 + 11 = 21
```

칸 `[0,2]` 가 13 이 아니라 17 이고, 마지막 칸이 22 대신 21 이에요. 21 은 **어떤 합치는 순서로도 만들 수 없는 값**입니다
— 전체 컨셉에서 순서 다섯을 전부 적었을 때 가장 작은 합이 22 였어요. `dp[1][3]` 이 17 이 아니라 10 인 것은 칸
`[1,3]` 도 범위 `[0,0]` 을 받아 구간 밖의 `k = 0` 을 넣었기 때문입니다.

#### 3. 구간 길이 차례로 되풀이한다

셋째 조각은 새로 만들 것이 없습니다. 2번 조각을 구간 길이와 시작 번호의 두 겹 반복으로 감싸면 되고, 길이 3 부터
**하한이 구간의 시작보다 커지는 칸**이 나와요.

```ts
for (let len = 2; len <= n; len++) {
  for (let i = 0; i + len - 1 < n; i++) {
    // 2번 조각이 그대로 들어간다
  }
}
```

길이 3 의 두 칸을 실행한 결과입니다.

<!--proof:walk-len3-->

```text
T5 — 칸 [0,2]
  후보 범위  [opt[0][1], min(opt[1][2], 1)] = [0, min(1, 1)] = [0,1]
  k = 0      dp[0][0] + dp[1][2] = 8
  k = 1      dp[0][1] + dp[2][2] = 4   ← 최솟값
  채움       dp[0][2] = 4 + S(0, 2) = 13 · opt[0][2] = 1

T6 — 칸 [1,3]
  후보 범위  [opt[1][2], min(opt[2][3], 2)] = [1, min(2, 2)] = [1,2]
  k = 1      dp[1][1] + dp[2][3] = 7   ← 최솟값
  k = 2      dp[1][2] + dp[3][3] = 8
  채움       dp[1][3] = 7 + S(1, 3) = 17 · opt[1][3] = 1
```

T6 의 하한 1 은 T5 가 아니라 T3 이 적은 `opt[1][2]` 입니다. 왼쪽 이웃은 같은 대각선의 앞 칸이 아니라 **같은 줄의 한 칸
왼쪽**이에요. 반복이 대각선 하나를 다 채운 뒤 다음 대각선으로 가므로, 두 이웃이 늘 먼저 채워져 있습니다.

가져와야 하나」로 읽기 쉬워요. 상한을 `j − 1` 로만 두고 세 입력에 실행했습니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 앞의 조각들을 두 겹 반복 안에 모은 것이고, 새로 보는 것은 `INF` 를 맨 위의 상수로 뺀 것
하나예요. 칸마다 `best` 를 그 값으로 시작하므로, 범위의 첫 후보가 언제나 `val < best` 를 참으로 만듭니다.

```ts
// 아직 확정하지 않은 칸에 넣어 두는 값. 어떤 유한한 비용보다 크다.
export const INF = Number.POSITIVE_INFINITY;

export function knuthOptimization(freq: number[]): number {
  const n = freq.length;
  // ① 병합이 없는 입력 — 파일이 하나 이하면 합칠 상대가 없다.
  if (n <= 1) return 0;

  // ② 구간 합 — prefix[j+1] - prefix[i] 가 S(i, j) 다.
  const prefix = new Array<number>(n + 1).fill(0);
  for (let i = 0; i < n; i++)
    prefix[i + 1] = (prefix[i] as number) + (freq[i] as number);

  const dp: number[][] = Array.from({ length: n }, () =>
    new Array<number>(n).fill(0),
  );
  const opt: number[][] = Array.from({ length: n }, () =>
    new Array<number>(n).fill(0),
  );
  // ③ 기저 — 길이 1 구간은 합칠 것이 없어 비용이 0 이고 가르는 자리가 자기 번호다.
  for (let i = 0; i < n; i++) (opt[i] as number[])[i] = i;

  for (let len = 2; len <= n; len++) {
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1;
      let best = INF;
      let bestK = i;
      // ④ 후보 범위 — 하한은 왼쪽 이웃 칸의 최적 가르는 자리다.
      const lo = (opt[i] as number[])[j - 1] as number;
      // 상한은 아래 이웃 칸의 최적 가르는 자리를 j-1 로 한 번 더 자른 값이다.
      const hi = Math.min((opt[i + 1] as number[])[j] as number, j - 1);
      for (let k = lo; k <= hi; k++) {
        const val =
          ((dp[i] as number[])[k] as number) +
          ((dp[k + 1] as number[])[j] as number);
        // ⑤ 최솟값 갱신 — 값과 그 값이 나온 가르는 자리를 함께 남긴다.
        if (val < best) {
          best = val;
          bestK = k;
        }
      }
      // ⑥ 칸 채우기 — 구간 합은 가르는 자리와 무관하므로 마지막에 한 번만 더한다.
      (dp[i] as number[])[j] =
        best + ((prefix[j + 1] as number) - (prefix[i] as number));
      (opt[i] as number[])[j] = bestK;
    }
  }

  return (dp[0] as number[])[n - 1] as number;
}
```

여러 입력에 실행해 가르는 자리를 전부 넣은 답과 대조한 결과입니다.

### 알아 두면 좋은 개념 — 망원합

4단계에서 대각선 하나의 후보 수를 더했을 때 가운데 항이 모두 사라졌습니다. **이웃한 항이 부호만 다르게 두 번 나와
서로 지워지고 양 끝만 남는 합**을 **망원합**이라고 불러요. 이 편에서 그 합은 「대각선 하나에서 칸마다의 후보 수를
전부 더한 값」이고, 남는 양 끝은 그 대각선이 읽은 처음 하한과 마지막 상한입니다. 한 대각선을 항마다 적으면 이렇습니다.

<!--proof:related-telescope-->

| 칸 | 하한 | 상한 | 상한 − 하한 + 1 | 실제 후보 수 |
| --- | --- | --- | --- | ---: |
| [0,3] | opt[0][2] = 1 | opt[1][3] = 1 | 1 − 1 + 1 = 1 | 1 |
| [1,4] | opt[1][3] = 1 | opt[2][4] = 2 | 2 − 1 + 1 = 2 | 2 |
| [2,5] | opt[2][4] = 2 | opt[3][5] = 3 | 3 − 2 + 1 = 2 | 2 |
| [3,6] | opt[3][5] = 3 | opt[4][6] = 4 | 4 − 3 + 1 = 2 | 2 |
| [4,7] | opt[4][6] = 4 | opt[5][7] = 6 | 6 − 4 + 1 = 3 | 3 |

freq = [1, 3, 5, 2, 4, 1, 3, 5] 의 구간 길이 4 대각선입니다. 칸마다의 상한이 다음 칸의 하한과 같아서, 합은 칸 수 5 에 마지막 상한 6 과 처음 하한 1 의 차를 더한 10 이고, 실제 후보 수 합도 10 입니다.

<!--/proof-->

칸 `[1,4]` 의 상한 2 가 다음 칸 `[2,5]` 의 하한으로 다시 나오고, 칸 `[2,5]` 의 상한 3 이 칸 `[3,6]` 의 하한으로 다시
나와요. 더하면 가운데 자리들이 한 번은 더해지고 한 번은 빼져 사라집니다. 같은 이름이 이 편 밖에서 다시 나옵니다.

| 다시 만나는 자리 | 지워지는 항 | 남는 것으로 하는 일 |
| --- | --- | --- |
| 구간 합 질의 | 앞 누적 `P[l]` 이 두 번 나온다 | 구간 합을 뺄셈 한 번으로 얻는다 |
| 분할 상환 분석 | 포인터가 앞으로 간 칸과 돌아온 칸 | 전체 이동이 `n` 에 비례한다는 결론을 얻는다 |
| 급수의 부분합 | `1/k − 1/(k+1)` 의 가운데 항 | 부분합의 닫힌 형태를 얻는다 |

구간 합 질의는 이 저장소에도 있어요 — [구간 합 질의](../../array/prefixSumRangeQuery/prefixSumRangeQuery-guide.md)
편이 그 자리이고, 분할 상환 분석은
[구간 길이 최대화](../../array/longestSubarrayAtMostSum/longestSubarrayAtMostSum-guide.md) 편이 맡습니다. 이름을
알아 두면 「이 합이 왜 `n` 에 비례하지」를 다시 물을 때 지워지는 항부터 찾게 돼요.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 이웃 관계가 어디서 나오고 후보 수의 상한이 어떻게
닫히는지, 무엇이 칸마다 참으로 남는지, 그리고 후보 수가 얼마인지 차례로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다. 조건마다 그 조건이 코드의 어느 모양으로 나타나는지 함께 적었어요.

| 조건 | 풀어 쓴 뜻 | 코드에 나타나는 모양 |
| --- | --- | --- |
| 구간 동적 계획법이다 | 상태가 구간 `[i, j]` 이고 전이가 가르는 자리 하나를 고른다 | 반복이 구간 길이와 시작 번호 두 겹이다 |
| 구간의 비용이 가르는 자리와 무관하다 | 마지막 합치기의 비용이 `S(i, j)` 하나다 | `S(i, j)` 를 반복 밖에서 한 번만 더한다 |
| 비용이 사각 부등식과 단조성을 만족한다 | 칸의 최적 가르는 자리가 두 이웃의 자리 사이에 있다 | 범위를 `opt` 의 두 이웃으로 잡는다 |
| 파일 수가 커서 `n³` 을 감당할 수 없다 | 칸 하나가 후보 `n` 개를 넣으면 예산을 넘는다 | `opt` 한 벌을 더 들이고 후보를 가둔다 |

셋째 조건이 이 절차의 자리이자 위험입니다. 조건이 없으면 가르는 자리를 전부 넣어야 해요. 넷째 조건이 없으면 굳이 `opt`
한 벌을 더 들일 까닭이 없습니다 — 파일 여덟 개라면 전부 넣어도 후보가 84 개예요.

**이 과제 하나만 풀면 되는 자리에는 전용 절차가 따로 있습니다.** 인접 병합의 가장 작은 비용은 순서를 지켜야 하는 최적
이진 트리(최적 알파벳 이진 트리)와 같은 문제이고, 그 문제만을 위한 Hu-Tucker · Garsia-Wachs 계열 절차가 있어요 — 아래
「실제로 쓰이는 곳」의 라이브러리가 그중 하나를 씁니다. 그럼에도 이 절차를 배우는 까닭은 **범용성**입니다. 비용이 사각
부등식과 단조성만 만족하면 최적 이진 검색 트리처럼 비용이 다른 구간 동적 계획법에도 같은 틀을 그대로 써요. 구간을 정확히
`k` 개로 나누는 줄 단위 동적 계획법에도 같은 생각이 쓰이고, 그 자리의 경쟁 설계가 아래 「경쟁 설계와의 대조」입니다.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "인접한 두 묶음만" "이웃한 것끼리만"   ← 가르는 자리 하나로 경계를 적을 수 있다
  "합치는 비용은 두 묶음의 크기 합"      ← 구간에 붙는 비용이 구간 합이다
  "일렬로 늘어선" "순서를 바꿀 수 없다"  ← 구간 동적 계획법의 모양이다
  "크기는 0 이상의 정수"                 ← 단조성이 보장된다

점화식에 이런 모양이 보이면
  dp[i][j] = min_k (dp[i][k] + dp[k+1][j]) + w(i, j)   ← 구간 하나를 가르는 자리 하나로 나눈다
  w 가 구간 합 · 구간 길이의 볼록 함수                 ← 사각 부등식을 만족하는 전형이다

반대로 이런 말이 보이면 해당하지 않는다
  "아무 두 묶음이나 합칠 수 있다"      ← 가르는 자리로 경계를 적을 수 없다
  "크기가 음수일 수 있다"              ← 단조성이 성립하지 않는다
  "구간마다 비용이 제멋대로 주어진다"  ← 두 성질을 보장할 수 없다
```

마지막 무리가 보이면 다른 절차로 갑니다. 아무 두 묶음이나 합칠 수 있으면 허프만 부호화 쪽이고, 구간을 나누기만 하고
자르는 자리마다 값이 붙으면 [회문 분할 최소 컷](../../dp/palindromePartitioningMinCut/palindromePartitioningMinCut-guide.md)
쪽입니다.

#### 실제로 쓰이는 곳

- **Knuth, "Optimum binary search trees", Acta Informatica 1(1), 14–25 (1971)** — 이 최적화가 처음 나온 자리입니다.
  최적 이진 검색 트리를 만드는 `O(n³)` 동적 계획법에서 뿌리의 자리가 이웃 두 부분 문제의 뿌리 사이에 있다는 것을 보여
  `O(n²)` 으로 줄였어요. ([DOI 10.1007/BF00264289](https://doi.org/10.1007/BF00264289), 조회 2026-09-06)
- **Yao, "Efficient dynamic programming using quadrangle inequalities", STOC '80, 429–435 (1980)** — 같은 성질을 특정
  문제가 아니라 **비용의 조건**으로 일반화했습니다. 이 글이 쓰는 사각 부등식이라는 이름이 그 논문의 것이에요.
  ([DOI 10.1145/800141.804691](https://doi.org/10.1145/800141.804691), 조회 2026-09-06)
- **libCSD 의 `StringDictionaryHTFC`** — 문자열 사전을 압축하는 C++ 라이브러리가 **이 글과 같은 과제**를 실제로 풉니다.
  헤더 주석이 *"This class implements a Compressed String Dictionary which differentially encodes the strings using
  (Plain) Front-Coding and the resulting representation is finally compressed with Hu-Tucker"* 라 적고, 근거로 Knuth 의
  *"The Art of Computer Programming, volume 3: Sorting and Searching"* 를 답니다. 다만 그 구현이 쓰는 것은 이 글의 절차가
  아니라 **Hu-Tucker** 예요.
  ([`libCSD/StringDictionaryHTFC.h`](https://github.com/migumar2/libCSD/blob/master/StringDictionaryHTFC.h), 조회 2026-09-06)

셋이 이 글과 갈리는 자리를 나란히 놓으면 이렇습니다.

| 출처 | 보인 것 | 이 글과의 관계 |
| --- | --- | --- |
| Knuth 1971 | 최적 이진 검색 트리에서 뿌리의 자리가 이웃 사이에 있다 | 문제 하나에 대한 결과 |
| Yao 1980 | 비용이 사각 부등식을 만족하면 그렇다 | 조건으로 일반화 |
| libCSD | 같은 과제를 Hu-Tucker 로 푼다 | 절차가 다르다 |

**이 최적화를 그대로 쓰는 실제 소프트웨어 도입 사례는 확인하지 못했습니다.** 확인한 것은 위 두 논문과, 같은 과제를 다른
절차로 푸는 라이브러리 하나입니다.

#### 경쟁 설계와의 대조

이 글의 과제(이웃한 두 묶음 합치기)에는 같은 전제에서 같은 목표를 노리는 다른 범용 절차가 없습니다. 가르는 자리를 전부
넣는 방법은 「아이디어를 떠올리는 과정」이 이미 반박했어요. 경쟁은 이웃 두 칸으로 가두는 같은 생각을 **줄 단위 분할**에
쓸 때 생깁니다. 칸 `n` 개를 이어진 구역 `k` 개로 나누는 과제에서, 칸 `[0, i]` 를 구역 `g` 개로 나눈 가장 작은 비용을
`dp[g][i]`, 그 값을 만든 마지막 구역의 바로 앞 칸을 `opt(g, i)` 라 하면, 크누스 최적화는 `opt(g−1, i) ≤ opt(g, i) ≤
opt(g, i+1)` 을 써서 칸 `i` 의 후보를 그 사이로 가둬요. 같은 과제를 [분할 정복 최적화](../divideAndConquerDp/divideAndConquerDp-guide.md)
는 같은 줄 안의 관계만 써서 가운데 칸부터 채웁니다. 전제는 둘 다 비용 행렬의 사각 부등식이에요.

**입력을 왜 전개 입력으로 안 골랐는지 먼저 적습니다.** 전개 입력은 파일 넷의 인접 병합이라 구역 수가 없는 과제예요. 그래서
대조는 분할 정복 최적화 편이 쓴 입력과 잣대를 그대로 씁니다 — 칸 `n = 2,000` 을 고정하고 **구역 수 `k` 만** 바꿉니다.

```text
a      [1, 2, …, 2,000]
cost   cost[i][j] = (a[i] + … + a[j])²      구역 [i, j] 를 묶는 비용 — 사각 부등식을 만족한다
k      2 부터 2,000 까지 전부

후보 수   두 설계 모두 가르는 자리 하나를 넣어 값을 만들고 비교한 한 번을 1 로 센다
추가 칸   입력 밖에 새로 잡아 동시에 들고 있는 칸의 최댓값 — 비용 행렬 n × n 은 입력이라 두 설계 모두
          세지 않는다. 분할 정복 최적화의 재귀 호출 틀 하나를 1 칸으로 센다
```

두 설계를 같은 입력에서 세었습니다.

정해지지 않은 구간 동적 계획법 — 이 글의 과제 — 에서는 분할 정복 최적화의 틀이 맞지 않아 이 절차만 남습니다. 위 수치는
분할 정복 최적화 편의 `divideAndConquerDp-guide.alt.ts` 를 `tools/bench-alt.ts` 로 실행해 얻은 것이고, 이 가이드의
`knuthOptimization-guide.alt.ts` 는 그 실행을 그대로 받아 이름만 이 가이드 쪽에서 붙입니다. 두 편이 같은 실행에서 수를
받으므로 서로 어긋나지 않아요. 두 설계 다 결정론적이라 같은 입력이면 몇 번을 실행해도 같은 계수가 나옵니다.

### 수식 정의와 유도

`dp[i][j]` 의 점화식과 `opt[i][j]` 를 정의하고, 그 정의를 전개 입력에 넣어 검산하고, 두 성질에서 이웃 관계를 유도한
뒤, 후보 수를 임의의 `n` 에서 닫습니다.

**먼저 정의입니다.** 구간 `[i, j]` 의 파일을 하나로 합치는 가장 작은 비용을 $dp[i][j]$, 마지막 합치기에서 왼쪽 묶음의
마지막 파일 번호를 $k$ 라 씁니다. 마지막 합치기의 비용은 두 묶음의 크기 합, 곧 구간 전체의 합 $S(i, j)$ 예요.

$$
dp[i][i] = 0, \qquad dp[i][j] = \min_{i \le k < j} \bigl( dp[i][k] + dp[k+1][j] \bigr) + S(i, j)
$$

```text
점화식이 자르는 자리

  i ───────────── k │ k+1 ───────── j
  └── 먼저 하나로 ──┘ │ └ 먼저 하나로 ┘
        dp[i][k]              dp[k+1][j]

  마지막 합치기는 두 묶음을 하나로 만든다 — 그 비용이 S(i, j) 이고 k 와 무관하다
```

그 최솟값을 만드는 $k$ 가운데 가장 작은 것이 $\mathrm{opt}[i][j]$ 입니다. 아래에서 자주 쓰도록, 가르는 자리 $k$ 하나로
만든 값을 $D_k(i, j)$ 로 적어 둡니다.

$$
D_k(i, j) = dp[i][k] + dp[k+1][j] + S(i, j), \qquad \mathrm{opt}[i][j] = \min \bigl\{\, k \;:\; D_k(i, j) = dp[i][j] \,\bigr\}
$$

**정의를 값에 넣어 검산해 봅시다.** 전개 입력의 마지막 칸입니다.

<!--proof:math-check-->

S(0, 3) = prefix[4] − prefix[0] = 11 − 0 = 11 입니다.

| 가르는 자리 | 더하는 칸 | 값 | 합 |
| --- | --- | --- | ---: |
| k = 0 | dp[0][0] + dp[1][3] | 0 + 17 | 17 |
| k = 1 | dp[0][1] + dp[2][3] | 4 + 7 | 11 |
| k = 2 | dp[0][2] + dp[3][3] | 13 + 0 | 13 |

가장 작은 합 11 에 S(0, 3) 을 더해 dp[0][3] = 22 고 opt[0][3] = 1 입니다. 정본 knuthOptimization 도 22 를 돌려줍니다.

<!--/proof-->

**다음은 두 성질입니다.** 사각 부등식과 단조성은 $a \le b \le c \le d$ 인 지표 넷에 대한 조건이에요.

$$
S(a, c) + S(b, d) \;\le\; S(a, d) + S(b, c), \qquad S(b, c) \;\le\; S(a, d)
$$

구간 합에서 사각 부등식은 등호입니다 — 양변 모두 `[a, b)` 를 한 번, `[b, c]` 를 두 번, `(c, d]` 를 한 번 더한 값이에요.
단조성은 $S(a, d) - S(b, c)$ 가 `[a, b)` 와 `(c, d]` 의 크기 합이라, 크기가 0 이상이면 그 차가 0 이상이라 성립합니다.

```text
지표 넷이 만드는 구간 넷

  a ──── b ──── c ──── d

  왼쪽 항    S(a, c) + S(b, d)   두 구간이 겹치되 어느 쪽도 다른 쪽을 품지 않는다
  오른쪽 항  S(a, d) + S(b, c)   한쪽이 다른 쪽을 통째로 품는다
  단조성     S(b, c) ≤ S(a, d)   품기는 구간의 합이 품는 구간의 합을 넘지 않는다
```

**첫째 유도는 $dp$ 자신이 사각 부등식을 만족한다는 것입니다.** $i \le i' \le j \le j'$ 마다 다음을 보입니다.

$$
dp[i][j] + dp[i'][j'] \;\le\; dp[i][j'] + dp[i'][j]
$$

$j' - i$ 에 대한 귀납으로 갑니다. **기저는 $i = i'$ 이거나 $j = j'$ 인 경우**예요 — 그때 양변이 같은 두 항이라 등호입니다.
$j' - i = 0$ 이면 네 지표가 모두 같으니 기저에 듭니다. 이제 $i < i'$ 이고 $j < j'$ 이며, $j' - i$ 가 더 작은 모든 지표에서
부등식이 성립한다고 둡니다. 갈래가 셋이에요.

```text
갈래를 가르는 것

  i' = j 인가   → 갈래 1 (가운데 구간이 파일 하나)
  i' < j 이면   z = opt[i][j'] (가장 넓은 구간의 자리) 와 y = opt[i'][j] (가장 좁은 구간의 자리) 를 비교한다
                z ≤ y → 갈래 2 · z > y → 갈래 3
```

**갈래 1 — $i' = j$.** 오른쪽이 $dp[i][j'] + dp[j][j] = dp[i][j']$ 이므로 $dp[i][j] + dp[j][j'] \le dp[i][j']$ 를
보이면 됩니다. $z = \mathrm{opt}[i][j']$ 라 하면 $dp[i][j'] = D_z(i, j')$ 예요. $z < j$ 이면 $z$ 는 $[i, j]$ 의 가르는
자리도 되므로 $dp[i][j] \le D_z(i, j)$ 이고, 귀납 가정을 $(z+1, j, j, j')$ 에 쓰면 $dp[z+1][j] + dp[j][j'] \le
dp[z+1][j']$ 입니다($j' - (z+1) < j' - i$). 둘을 더하고 단조성 $S(i, j) \le S(i, j')$ 를 쓰면 이렇게 돼요.

$$
dp[i][j] + dp[j][j'] \;\le\; dp[i][z] + dp[z+1][j'] + S(i, j) \;\le\; dp[i][z] + dp[z+1][j'] + S(i, j') = dp[i][j']
$$

$z \ge j$ 이면 거꾸로 $z$ 가 $[j, j']$ 의 가르는 자리가 되어 $dp[j][j'] \le D_z(j, j')$ 이고, 귀납 가정을 $(i, j, j, z)$ 에
쓰면 $dp[i][j] + dp[j][z] \le dp[i][z]$ 입니다($z - i < j' - i$). 더하고 단조성 $S(j, j') \le S(i, j')$ 를 쓰면 같은 결론이
나와요. **단조성이 쓰이는 곳은 이 갈래뿐입니다.**

```text
갈래 1 을 z = opt[i][j′] 의 자리로 다시 가른다

  z < j   z 가 [i, j] 의 가르는 자리가 된다     귀납 가정을 (z+1, j, j, j′) 에 쓴다
  z ≥ j   z 가 [j, j′] 의 가르는 자리가 된다    귀납 가정을 (i, j, j, z) 에 쓴다
  두 경우 모두 마지막에 단조성으로 좁은 구간의 S 를 [i, j′] 의 S 로 바꾼다
```

**갈래 2 — $i' < j$ 이고 $z \le y$.** $z < j$ 라 $z$ 는 $[i, j]$ 의 가르는 자리이고, $y \ge i'$ 라 $y$ 는 $[i', j']$ 의 가르는
자리입니다. 그래서 $dp[i][j] \le D_z(i, j)$ 와 $dp[i'][j'] \le D_y(i', j')$ 를 더할 수 있어요.

$$
dp[i][j] + dp[i'][j'] \;\le\; dp[i][z] + dp[z+1][j] + dp[i'][y] + dp[y+1][j'] + S(i, j) + S(i', j')
$$

오른쪽의 $dp[z+1][j] + dp[y+1][j']$ 에 귀납 가정을 $(z+1, y+1, j, j')$ 로 쓰면 $dp[z+1][j'] + dp[y+1][j]$ 이하가 되고, 두
$S$ 에 $S$ 의 사각 부등식을 쓰면 $S(i, j') + S(i', j)$ 이하가 됩니다. 남은 항을 묶으면 $D_z(i, j') + D_y(i', j) =
dp[i][j'] + dp[i'][j]$ 예요.

```text
갈래 2 에서 귀납 가정을 쓰는 지표

  지표의 차례    z+1  ≤  y+1  ≤  j  ≤  j'       z ≤ y 이고 y < j 라서
  길이           j' − (z+1) < j' − i            z ≥ i 라서
```

**갈래 3 — $i' < j$ 이고 $z > y$.** 이번에는 $y$ 가 $[i, j]$ 의 가르는 자리가 되고($i \le i' \le y < j$), $z$ 가 $[i', j']$ 의
가르는 자리가 됩니다($i' \le y < z < j'$). 같은 방법으로 더하면 귀납 가정을 $(i, i', y, z)$ 에 써서 $dp[i][y] + dp[i'][z]
\le dp[i][z] + dp[i'][y]$ 로 바꾸고($z - i < j' - i$), 남은 항이 다시 $D_z(i, j') + D_y(i', j)$ 로 묶입니다.

세 갈래에서 부등식이 성립하니 귀납이 닫힙니다. 이 결론을 실제 표에서 확인했어요. 지표 넷 $i \le i' \le j \le j'$ 의
조합을 전부 넣었습니다.

<!--proof:math-dp-quad-->

| 입력 | 확인한 지표 조합 | 어긴 조합 | 처음 어긴 조합 (i, i′, j, j′) |
| --- | ---: | ---: | --- |
| 전개 입력 [1, 3, 5, 2] | 35 | 0 | — |
| [1, 3, 5, 2, 4, 1, 3, 5] | 330 | 0 | — |
| 크기가 모두 같은 배열 (n = 8) | 330 | 0 | — |
| 첫 파일만 큰 배열 (n = 9) | 495 | 0 | — |
| 음수가 섞인 배열 [1, 1, 2, -2] | 35 | 3 | 0, 1, 2, 3 |

크기가 0 이상인 입력 넷은 어긴 조합이 없습니다. 음수가 섞인 입력은 단조성이 깨져 갈래 1 이 막히고, `dp` 도 사각 부등식을
어겨요. 둘째 유도가 기대는 것이 바로 이 `dp` 의 사각 부등식입니다.

**둘째 유도는 이웃 관계입니다.** 먼저 하한 $\mathrm{opt}[i][j-1] \le \mathrm{opt}[i][j]$ 입니다. $k' = \mathrm{opt}[i][j-1]$
이라 하고 $k < k'$ 인 아무 $k$ 를 잡습니다. $dp$ 의 사각 부등식을 $(k+1, k'+1, j-1, j)$ 에 쓸 수 있어요 — $k' < j - 1$ 이라
$k'+1 \le j-1$ 입니다.

```text
하한 쪽에서 dp 의 사각 부등식에 넣는 자리

  지표의 차례   k+1  ≤  k′+1  ≤  j−1  ≤  j      k < k′ 이고 k′ < j−1 이라서
  부등식의 자리  a        b        c      d
```

$$
dp[k+1][j-1] + dp[k'+1][j] \;\le\; dp[k+1][j] + dp[k'+1][j-1]
$$

양변에 $dp[i][k] + dp[i][k'] + S(i, j-1) + S(i, j)$ 를 더하면 $D$ 의 꼴로 묶입니다.

$$
D_k(i, j-1) + D_{k'}(i, j) \;\le\; D_k(i, j) + D_{k'}(i, j-1)
$$

$k'$ 은 칸 $[i, j-1]$ 에서 가장 작은 값을 내는 자리 가운데 가장 작은 것이라, 그보다 작은 $k$ 는 **엄격히** 큰 값을 냅니다 —
$D_{k'}(i, j-1) < D_k(i, j-1)$ 이에요. 위 식을 옮기면 $D_{k'}(i, j) - D_k(i, j) \le D_{k'}(i, j-1) - D_k(i, j-1) < 0$ 이라,
칸 $[i, j]$ 에서도 $k$ 는 $k'$ 보다 큰 값을 냅니다. 그러니 $\mathrm{opt}[i][j]$ 는 $k'$ 보다 작을 수 없어요.

```text
하한 쪽의 결론

  k < k′ 인 k 는 칸 [i, j−1] 에서 k′ 보다 큰 값을 낸다          k′ 이 가장 작은 최적 가르는 자리라서
  k′ 이 앞서는 만큼이 칸 [i, j] 로 가도 줄지 않는다              dp 의 사각 부등식
  → 칸 [i, j] 에서도 k 는 답이 아니다 → opt[i][j] ≥ opt[i][j−1]
```

상한 $\mathrm{opt}[i][j] \le \mathrm{opt}[i+1][j]$ 도 같은 꼴입니다. $k'' = \mathrm{opt}[i+1][j]$ 라 하고 $k > k''$ 인 아무
$k$ 를 잡으면, $k'' \ge i+1$ 이라 $dp$ 의 사각 부등식을 $(i, i+1, k'', k)$ 에 쓸 수 있습니다.

$$
dp[i][k''] + dp[i+1][k] \;\le\; dp[i][k] + dp[i+1][k'']
$$

양변에 $dp[k''+1][j] + dp[k+1][j] + S(i, j) + S(i+1, j)$ 를 더해 묶으면 $D_{k''}(i, j) - D_k(i, j) \le D_{k''}(i+1, j) -
D_k(i+1, j) \le 0$ 이에요. 뒤의 부등호는 $k''$ 가 칸 $[i+1, j]$ 에서 가장 작은 값을 내기 때문입니다. 칸 $[i, j]$ 에서 $k''$
는 뒤쪽의 어떤 $k$ 보다도 작거나 같은 값을 내므로, 가장 작은 값을 내는 자리 가운데 가장 작은 것은 $k''$ 보다 클 수 없어요.

```text
상한 쪽에서 dp 의 사각 부등식에 넣는 자리

  지표의 차례   i  ≤  i+1  ≤  k″  ≤  k      k″ ≥ i+1 이고 k > k″ 라서
  부등식의 자리  a     b       c      d
```

세 유도가 잇는 것을 한 줄씩 적으면 이렇습니다.

| 단계 | 성립하는 것 |
| --- | --- |
| 두 성질 | 구간 합이 사각 부등식과 단조성을 만족한다 |
| 첫째 유도 | 그러면 DP 테이블 `dp` 도 사각 부등식을 만족한다 |
| 둘째 유도 | 그러면 칸의 최적 가르는 자리가 두 이웃의 자리 사이에 있다 |

**셋째 유도는 후보 수입니다.** 길이 $len$ 대각선에서 칸 $i$ 가 맡는 구간은 $[i,\; i+len-1]$ 이고, 그 칸이 넣는 후보 수는
넘겨받은 범위의 길이예요. 상한을 자르는 $\min$ 을 잠시 빼고, 길이 $len-1$ 대각선의 값을 $g(i) = \mathrm{opt}[i][i+len-2]$
로 두면 칸 $i$ 의 하한은 $g(i)$, 상한은 $g(i+1)$ 입니다.

$$
(\text{칸 } i \text{ 의 후보 수}) \;=\; g(i+1) - g(i) + 1
$$

칸 번호 $i$ 가 $0$ 부터 $n-len$ 까지 움직이므로 대각선의 칸이 $n-len+1$ 개이고, 더하면 가운데 항이 서로 지워집니다.

$$
\sum_{i=0}^{\,n-len} \bigl( g(i+1) - g(i) + 1 \bigr) \;=\; (n-len+1) + g(n-len+1) - g(0)
$$

```text
남은 두 끝이 어디까지 갈 수 있는가

  len ≥ 3  g 가 길이 2 이상 구간의 최적 가르는 자리라 0 이상 n−2 이하다
           그래서 g(n−len+1) − g(0) 이 n−2 를 넘지 않는다
  len = 2  상한이 j−1 로 잘려 칸마다 후보가 하나다 → 그 대각선의 합이 칸 수 n−1 이다

  두 경우 다 대각선 하나가 「칸 수 + (n−2)」 를 넘지 않는다
```

대각선이 $n-1$ 개이므로 칸 수의 합과 차의 합을 각각 더하면 상한이 닫힙니다.

$$
\text{후보 수} \;\le\; \frac{n(n-1)}{2} + (n-1)(n-2), \qquad \text{전부 넣으면} \;=\; \frac{n(n^2-1)}{6}
$$

```ts
// 식을 그대로 옮긴 조각. n 이 파일 수다.
const cellCount = (n: number): number => (n * (n - 1)) / 2;
const narrowBound = (n: number): number => cellCount(n) + (n - 1) * (n - 2);
const fullBound = (n: number): number => (n * (n * n - 1)) / 6;
```

**마지막으로 계수입니다.** 식에 규모를 넣어, 실제로 센 후보 수와 나란히 놓았습니다.

<!--proof:math-bound-->

| n | 센 후보 수 | n(n−1)/2 + (n−1)(n−2) | 그 비 | 전부 넣은 후보 수 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 221 | 330 | 0.670 | 680 |
| 64 | 3,980 | 5,922 | 0.672 | 43,680 |
| 256 | 65,003 | 97,410 | 0.667 | 2,796,160 |
| 1,024 | 1,046,740 | 1,569,282 | 0.667 | 178,956,800 |

생성식 배열에서 센 값입니다. 과제 규모 n = 2,000 에서 상한은 5,993,002, 전부 넣으면 1,333,333,000 이라 222.5 배이고, 같은 규모에서 실제로 센 후보 수는 3,996,176 입니다.

**여기서 본문의 값만으로는 안 나오는 것이 나옵니다.** 앞의 실측은 입력 몇 벌의 값인데, 위 유도는 **임의의 `n` 과 두
성질을 만족하는 임의의 비용에 대해** 후보 수가 `n(n−1)/2 + (n−1)(n−2)` 를 넘지 않는다는 닫힌 형태를 줘요. 생성식 배열의
비는 규모를 키워도 0.67 언저리에 머뭅니다.

### 불변식 — 넣은 후보 범위 안에 진짜 최적 가르는 자리가 있다

파트 1 의 여덟 걸음은 입력 하나에서 답이 나왔다는 기록입니다. 그 하나로는 다른 입력에서도 같은 일이 일어난다는 근거가
안 되므로, **칸을 몇 개 채우든 참으로 남는 문장**을 세우고 그것이 유지되는지를 값으로 확인합니다.

> 길이 `len` 대각선의 칸 `[i, j]` 를 채우는 **시점마다** 둘이 참입니다. **앞 문장** — 길이가 `len` 보다 짧은 모든 구간의
> `dp` 와 `opt` 가 이미 맞게 채워져 있습니다. **뒤 문장** — 그 칸의 진짜 최적 가르는 자리가
> `[opt[i][j−1], min(opt[i+1][j], j−1)]` 안에 있습니다.

```text
앞 문장이 정하는 것   후보 값 dp[i][k] + dp[k+1][j] 가 맞는 값으로 만들어진다
뒤 문장이 정하는 것   잘라 낸 후보 가운데 답이 없다

둘이 함께 있으면     범위 안의 가장 작은 값이 그 칸의 값이다 → 대각선 len 이 통째로 맞다
대각선마다 이어 붙이면 길이 1 이 맞고, 길이 len−1 까지 맞으면 길이 len 도 맞다 → dp[0][n−1] 이 답이다
```

**첫 대각선에 들어가기 전부터 봅시다.** 길이 2 대각선의 첫 칸은 `[0,1]` 이고, 그 시점에 길이 1 구간은 전부 `dp = 0` ·
`opt = 자기 번호` 로 채워져 있습니다. 가르는 자리는 `0` 이상 `j − 1 = 0` 이하여야 하므로 범위 `[0, min(1, 0)] = [0,0]` 이
가능한 가르는 자리 전부라 뒤 문장이 참이에요. 갈래마다 두 문장이 어떻게 유지되는지 적으면 이렇습니다.

| 갈래 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 구간 합을 준비한다 | `prefix` 를 채운다 | `dp` 를 안 건드린다 | 아직 아무 범위도 안 잡았다 |
| 기저를 세운다 | 길이 1 칸에 `dp = 0` · `opt = i` | 길이 1 이 맞게 채워진다 | 길이 2 칸의 범위가 `[i, i]` 가 된다 |
| 후보 범위를 잡는다 | 두 이웃의 `opt` 를 읽는다 | 짧은 구간만 읽는다 | 「수식 정의와 유도」의 이웃 관계 |
| 상한을 `j − 1` 로 자른다 | 구간 밖의 `k` 를 뺀다 | 값을 안 바꾼다 | 가르는 자리는 원래 `j − 1` 이하다 |
| 가장 작은 값을 고친다 | `best` 와 `bestK` 를 바꾼다 | 맞게 채워진 값만 더한다 | 범위 안에서만 고른다 |
| 칸을 채운다 | `dp` 와 `opt` 에 적는다 | 그 칸이 맞게 채워진다 | 다음 대각선이 이 `opt` 를 읽는다 |

「칸을 채운다」 줄이 이 논증에서 가장 좁은 자리예요. `bestK` 는 **넘겨받은 범위 안에서** 찾은 가장 작은 값의 자리
가운데 가장 작은 것입니다. 뒤 문장이 진짜 최적 가르는 자리가 범위 안에 있다고 주므로, 범위 안의 가장 작은 값이 진짜
값이고 `bestK` 가 식의 `opt[i][j]` 와 같아요. 그 `opt[i][j]` 가 다음 대각선의 두 칸 `[i, j+1]` 과 `[i−1, j]` 의 범위
끝이 되므로, 이 줄이 틀리면 뒤 칸들의 뒤 문장도 함께 성립하지 않게 됩니다. 전개 입력의 칸마다, 가르는 자리를 전부 넣어 따로 구한
진짜 자리가 넣은 범위 안에 있는지 보았어요.

<!--proof:invariant-watch-->

| 걸음 | 칸 | 넣은 범위 | 진짜 opt | 불변식 |
| --- | --- | --- | ---: | --- |
| T2 | [0,1] | [0,0] | 0 | 지킨다 |
| T3 | [1,2] | [1,1] | 1 | 지킨다 |
| T4 | [2,3] | [2,2] | 2 | 지킨다 |
| T5 | [0,2] | [0,1] | 1 | 지킨다 |
| T6 | [1,3] | [1,2] | 1 | 지킨다 |
| T7 | [0,3] | [1,1] | 1 | 지킨다 |

여섯 칸 모두 진짜 자리가 넣은 범위 안에 있습니다. T7 의 칸 `[0,3]` 은 범위가 `[1,1]` 한 자리로 좁아졌는데 진짜 자리가
1 이라 안에 들어 있어요. 경계 입력에서도 같은 문장이 유지되는지 봅시다.

<!--proof:invariant-edges-->

| 입력 | n | 반환값 | 전부 넣은 답 | 후보 수 | 이웃 관계를 어긴 칸 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 파일 하나 | 1 | 0 | 0 | 0 | — |
| 파일 둘 | 2 | 12 | 12 | 1 | 0 |
| 크기가 전부 0 | 4 | 0 | 0 | 9 | 0 |
| 0 이 섞인 입력 | 3 | 10 | 10 | 4 | 0 |
| 크기가 모두 같은 입력 | 4 | 80 | 80 | 9 | 0 |
| 첫 파일만 큰 입력 (n = 5) | 5 | 1,012 | 1,012 | 17 | 0 |

파일이 하나면 조기 반환이 그 자리를 맡아 반복에 한 번도 들어가지 않고 후보 수가 0 입니다. 크기가 전부 0 이면 어떤
순서로 합쳐도 비용이 0 이라 답도 0 이고, 그때도 이웃 관계를 어긴 칸이 0 이에요 — 같은 값이면 가장 작은 자리를 고른다는
규칙이 그 자리를 정합니다. 여섯 줄 모두 반환값이 가르는 자리를 전부 넣은 답과 같습니다.

**이제 그 줄을 망가뜨려 봅시다.** 뒤 문장을 떠받치는 자리는 칸을 채우는 `opt[i][j] = bestK` 한 줄입니다. 「어차피 `dp` 만
있으면 답이 나오는데 자리까지 적어야 하나」라는 생각으로 그 줄만 지웁니다.

```ts
      (dp[i] as number[])[j] =
        best + ((prefix[j + 1] as number) - (prefix[i] as number));
      // (opt[i] as number[])[j] = bestK;   ← 이 줄을 지웠다
```

<!--proof:mutant-no-opt-write-->

| 입력 | 정본 | 자리를 안 적는 판 | 판정 |
| --- | ---: | ---: | --- |
| 전개 입력 | 22 | 21 | 다르다 |
| 크기가 모두 같은 입력 | 12 | 9 | 다르다 |
| [10, 20, 30] | 90 | 110 | 다르다 |

세 입력 모두에서 답이 갈립니다. 전개 입력에서 21 이 나오는데, 가장 작은 합이 22 이므로 이것은 **어떤 합치는 순서로도
만들 수 없는 값**이에요. `opt` 를 안 적으면 길이 3 이상의 칸이 전부 처음 값 0 을 하한과 상한으로 읽어, 범위가
`[0, min(0, j−1)] = [0,0]` 이 되고 후보가 `k = 0` 하나가 됩니다. 범위를 좁히는 규칙 자체는 건드리지 않았어요. 그런데 그
규칙이 읽는 `opt` 가 채운 값이 아니라 처음 값이라, 뒤 문장이 말하는 「진짜 최적 가르는 자리가 범위 안에 있다」가 성립하지
않습니다.

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 셋입니다. 구간 합을 만드는 것, DP 테이블 두 벌을 만드는 것, 그리고 칸마다 후보를 넣는 것이에요.
전개의 여덟 걸음에서 후보 수를 셉니다.

<!--proof:perf-walk-->

| 걸음 | 칸 | 후보 범위 | 이 걸음의 후보 수 | 누적 |
| --- | --- | --- | ---: | ---: |
| T1 | — | — | 0 | 0 |
| T2 | [0,1] | [0,0] | 1 | 1 |
| T3 | [1,2] | [1,1] | 1 | 2 |
| T4 | [2,3] | [2,2] | 1 | 3 |
| T5 | [0,2] | [0,1] | 2 | 5 |
| T6 | [1,3] | [1,2] | 2 | 7 |
| T7 | [0,3] | [1,1] | 1 | 8 |
| T8 | — | — | 0 | 8 |

채운 칸 6 개 · 후보 수 8 이고, 가르는 자리를 전부 넣으면 10 입니다.

<!--/proof-->

걸음마다 후보 수가 다릅니다. **칸 하나가 넣는 후보가 하나이거나 둘이에요.** T2 · T3 · T4 는 길이 2 라 상한이 `j − 1` 로
잘려 하나씩 넣었고, T5 와 T6 은 둘씩 넣었어요. T7 은 가르는 자리가 셋인데 범위가 한 자리라 하나만 넣었고, T1 과 T8 은 후보를
넣는 걸음이 아닙니다. 후보 말고 드는 것은 준비입니다.

| 항 | 횟수 | 세는 것 |
| --- | --- | --- |
| 구간 합 | `n` | `prefix` 를 한 칸씩 채운다 |
| DP 테이블 두 벌 | `2n²` | `dp` 와 `opt` 를 0 으로 채운다 |
| 기저 | `n` | `opt[i][i] = i` 를 적는다 |
| 칸 채우기 | `n(n−1)/2` | 칸마다 범위를 잡고 두 벌에 적는다 |
| 후보 | `C ≤ n(n−1)/2 + (n−1)(n−2)` | 「수식 정의와 유도」의 상한 |

`C` 의 상한을 넣으면 총식이 `2n + 2n² + n(n−1)/2 + n(n−1)/2 + (n−1)(n−2)` 를 넘지 않습니다. 다섯 항이 모두 `n²` 이하라
총식의 차수는 `n²` 이에요. 이 글이 비용을 후보 수 하나로 센 것은 칸 채우기와 후보가 알고리즘의 선택을 담는 항이기
때문이고, DP 테이블을 0 으로 채우는 `2n²` 은 어떤 입력에서도 같은 준비입니다. 메모리는 DP 테이블 두 벌의 `2n²` 칸이
전부이고, `n = 2,000` 에서 칸마다 8 바이트로 어림하면 「아이디어를 떠올리는 과정」의 64 MB 입니다.

#### 케이스별 비용과 그 경계

어떤 입력인가를 말하는 **케이스**와 어떤 종류의 값인가를 말하는 **경계**는 축이 다릅니다. 한 축의 이름을 다른 축에 붙이면
두 정보가 함께 사라져요.

| 케이스 | 상한 $O$ | 타이트 $\Theta$ |
| --- | --- | --- |
| **최선의 경우** (`n ≤ 1`) | $O(1)$ | $\Theta(1)$ — 조기 반환으로 끝난다 |
| **평균적인 경우** (입력 분포를 정의하지 않는다) | $O(n^2)$ | 정의하지 않는다 |
| **최악의 경우** (`n ≥ 2` — 크기가 무엇이든) | $O(n^2)$ | $\Theta(n^2)$ — 칸 `n(n−1)/2` 개를 빠짐없이 채운다 |

평균을 정의하지 않는 이유는 **입력 분포가 과제에 없기** 때문입니다. 이 절차에는 난수가 하나도 없어서 무작위성이 구현에서
나오지도 않아요. 「평균」이라는 말을 쓰려면 어떤 크기 배열을 어떤 확률로 뽑는지를 먼저 정해야 하는데, 그런 정의가 이 과제에
없습니다. `n ≥ 2` 이면 칸 `n(n−1)/2` 개를 하나씩 채우고 칸마다 후보를 적어도 하나 넣으므로, 어떤 배열에서도 후보 수가
칸 수 아래로 내려가지 않아요. 배열 모양을 바꿔 가며 재 보았습니다.

<!--proof:perf-observed-->

| 배열 | n | 후보 수 | 칸 하나당 | 전부 넣은 후보 수 |
| --- | ---: | ---: | ---: | ---: |
| 크기가 모두 같은 배열 | 128 | 16,129 | 1.98 | 349,504 |
| 크기가 모두 같은 배열 | 512 | 261,121 | 2.00 | 22,369,536 |
| 생성식 배열 | 128 | 16,147 | 1.99 | 349,504 |
| 생성식 배열 | 512 | 261,088 | 2.00 | 22,369,536 |
| 첫 파일만 큰 배열 | 128 | 19,384 | 2.38 | 349,504 |
| 첫 파일만 큰 배열 | 512 | 315,096 | 2.41 | 22,369,536 |

**「칸 하나당」 열이 `n = 128` 에서 1.98 부터 2.38, `n = 512` 에서 2.00 부터 2.41 입니다.** 배열 모양을 바꿔도 칸 하나가
후보를 두 개 남짓 넣는다는 뜻이에요 — 전체가 `2 × n(n−1)/2 = n²` 언저리에 머뭅니다. 가르는 자리를 전부 넣는 쪽은 같은
규모에서 `n³/6` 을 따라 커져요.

```text
「관측」과 「보장」을 가르는 문장

  관측  세 배열 모양에서 칸 하나당 후보가 2 개 남짓이었다
  보장  사각 부등식과 단조성을 만족하는 어떤 비용에서도 후보 수가 n(n−1)/2 + (n−1)(n−2) 를 넘지 않는다

  앞엣것은 배열을 바꾸면 값이 바뀐다. 뒤엣것은 안 바뀐다
  위의 상한은 전부 최악 보장이다 — 기댓값이 아니라 상한이고, 입력 분포를 쓰지 않는다
```

#### 최악을 만드는 입력

후보 수를 크게 만들려면 범위가 되도록 안 좁아져야 합니다. 이 절차는 범위를 좁히는 규칙이 **입력의 값이 아니라 최적
가르는 자리의 배치**에만 달려 있어요. 배치를 바꿔 가며 재 봅시다.

<!--proof:perf-worst-shape-->

| 배열 (n = 256) | 후보 수 | 상한에 대한 비 |
| --- | ---: | ---: |
| 크기가 모두 같은 배열 | 65,025 | 0.668 |
| 생성식 배열 | 65,003 | 0.667 |
| 뒤로 갈수록 커지는 배열 | 63,009 | 0.647 |
| 첫 파일만 큰 배열 | 78,360 | 0.804 |
| 마지막 파일만 큰 배열 | 83,821 | 0.860 |

상한 n(n−1)/2 + (n−1)(n−2) 는 97,410 입니다. 한 파일만 큰 배열을 큰 파일의 자리마다 256 벌 만들어 재면 후보 수가 최소 56,960 · 최대 83,821 이고, 최대를 만드는 자리는 255 번 파일입니다.

<!--/proof-->

**마지막 파일만 큰 배열이 후보를 가장 많이 만듭니다.** 큰 파일의 자리를 256 군데로 옮겨 가며 전부 재 봤는데 가장 많은
자리가 마지막 번호였어요 — 손으로 「이게 최악일 것」이라 적지 않고 전부 재서 고른 값입니다. 큰 파일이 끝에 있으면 칸마다
최적 가르는 자리가 구간의 끝 쪽으로 몰리고, 두 이웃의 자리가 서로 멀어져 범위가 넓어집니다. 그 배열로 규모를 4 배씩 늘려
상한에 대한 비를 재면 이렇습니다.

<!--proof:perf-worst-growth-->

| n | 마지막 파일만 큰 배열의 후보 수 | n(n−1)/2 + (n−1)(n−2) | 그 비 | 전부 넣은 후보 수 |
| ---: | ---: | ---: | ---: | ---: |
| 32 | 1,221 | 1,426 | 0.856 | 5,456 |
| 128 | 20,749 | 24,130 | 0.860 | 349,504 |
| 512 | 336,941 | 391,426 | 0.861 | 22,369,536 |
| 2,048 | 5,006,764 | 6,284,290 | 0.797 | 1,431,655,424 |

**「그 비」 열이 0.797 에서 0.861 사이에 있고 1 을 넘지 않습니다.** 규모를 64 배 늘려도 상한의 0.8 배 언저리에 이르므로, 후보
수가 `n²` 과 **같은 차수로** 늘어나고 최악이 상한과 같은 차수에 실제로 이릅니다. `n = 2,048` 에서 비가 0.861 에서 0.797 로
내려간 까닭까지는 이 글이 증명하지 않았어요.

| 최악으로 만들 축 | 그 축을 크게 만드는 입력 | 값 |
| --- | --- | --- |
| 후보 수 | 마지막 파일만 큰 배열 — 최적 가르는 자리가 끝 쪽에 몰린다 | 「그 비」 0.8 배 언저리 |
| 추가 칸 | 파일 수를 과제 규모의 상한까지 올린다 | `2n²` — 「아이디어를 떠올리는 과정」의 표 |
| 전체 | 위 둘을 겹친다 | 「수식 정의와 유도」의 상한 `n(n−1)/2 + (n−1)(n−2)` 을 넘지 않는다 |

**여기서 잰 무리는 크기가 0 이상인 배열들입니다.** 크기가 음수인 배열은 이 절차를 쓸 수 없으므로 대상이 아니고, 확인한
것은 「이 무리에서 후보 수가 상한을 넘지 않고, 상한의 0.8 배 언저리까지 이른다」까지예요.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. DP 테이블을 구간 길이가 짧은 칸부터 채우되, 칸마다 후보 범위를 왼쪽
이웃과 아래 이웃의 최적 가르는 자리로 가두고 그 안에서만 가장 작은 값을 찾습니다. 가둬도 되는 근거는 「구간 합이 사각
부등식과 단조성을 만족하면 최적 가르는 자리가 두 이웃의 자리 사이에 있다」이고, 후보 수의 상한은
`n(n−1)/2 + (n−1)(n−2)` 예요.

```text
prefix 를 만들고 opt[i][i] = i 를 적는다 → 구간 길이 2 부터 n 까지 대각선을 채운다
→ 칸마다 [opt[i][j−1], min(opt[i+1][j], j−1)] 의 후보를 넣는다 → 가장 작은 값 + S(i, j) 와 그 자리를 적는다
→ dp[0][n−1] 을 돌려준다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T7 은 `dp[0][3] = 22` 를 채우면서 `k = 0` 과 `k = 2` 를 한 번도 넣지 않았어요. 그
둘이 진짜 답이 아니라는 것을 이 절차는 어떻게 알았을까요?

<!--check:whyRangeIsSafe-->
**T5 와 T6 이 적은 두 자리와 이웃 관계 때문입니다.** 왼쪽 이웃 관계가 `opt[0][3] ≥ opt[0][2] = 1` 을 주므로 `k = 0` 은 최적
가르는 자리일 수 없고, 아래 이웃 관계가 `opt[0][3] ≤ opt[1][3] = 1` 을 주므로 `k = 2` 도 아니에요. 두 자리를 적은 시점에
**나머지 둘이 답이 아니라는 것이 함께 정해집니다.** 이웃 관계가 없으면 둘 가운데 하나가 가장 작은 값을 낼 수도 있고, 그때
이 절차는 답을 놓쳐요 — 「이 방법이 기대는 전제」의 음수가 섞인 배열이 그 경우였습니다. 이 입력에서 실제로 넣어 보면
이렇습니다.

<!--proof:check-range-->

```text
k = 0 과 k = 2 를 실제로 넣어 보면

  k = 0   dp[0][0] + dp[1][3] = 0 + 17 = 17
  k = 1   dp[0][1] + dp[2][3] = 4 + 7 = 11   ← 채운 값
  k = 2   dp[0][2] + dp[3][3] = 13 + 0 = 13
```
<!--/check-->

아래 셋에는 답을 붙이지 않았습니다. 막히면 차례대로 전개의 「짚고 가기 — 상한을 이웃 칸으로 안 좁혀도 답이 안 틀린다」,
T2 · T5, 「최악을 만드는 입력」을 다시 보세요.

- 상한을 `j − 1` 로만 두면 답이 안 틀리고 후보만 늘었습니다. 그렇다면 **하한** 쪽을 `opt[i][j−1]` 대신 `i` 로 두면 답이
  갈릴지 후보 수가 갈릴지를 먼저 예측하고, 파일 여덟 개에서 후보 수가 어느 쪽으로 얼마나 움직일지 적어 보세요.
- 전개의 T2 와 T5 에서 하한과 상한을 서로 바꿔 써서 `lo` 에 `opt[i+1][j]` 를, `hi` 에 `opt[i][j−1]` 을 넣으면 무엇이 나올지
  예측해 보세요. T2 의 칸 `[0,1]` 에서 `lo` 와 `hi` 가 각각 얼마가 되는지를 적으면 반복이 몇 번 실행되는지가 나오고,
  거기서 반환값까지 이어집니다.
- 「최악을 만드는 입력」에서 한 파일만 큰 배열의 후보 수가 56,960 부터 83,821 사이였습니다. 위쪽 끝을 더 올리려면 최적
  가르는 자리의 배치를 어떻게 만들어야 할지 예측해 보세요. 대각선 하나의 합이 「칸 수 + (n−2)」를 넘지 못한다는 것이
  위쪽을 막고, 칸마다 적어도 하나를 넣는다는 것이 아래쪽을 막습니다.

이 글의 알고리즘으로 풀어 볼 문제입니다. 스텁을 채운 뒤 테스트로 확인하세요.

### 최적 파일 병합

풀 파일: [`knuthOptimization.ts`](./knuthOptimization.ts) · 테스트: [`knuthOptimization.test.ts`](./knuthOptimization.test.ts) · 실행: `bun test src/algorithms/advanced/knuthOptimization/knuthOptimization.test.ts`

#### 한 줄 요약

> 파일 크기 배열을 받아, 인접한 파일을 반복 병합하여 하나로 합칠 때 드는 최소 총 비용을 반환한다.

#### 스토리

백업 시스템을 관리하는 서버 엔지니어 태양은 여러 개의 데이터 파일을 하나로 합치는 작업을 자동화하려 한다. 파일은 일렬로 나열되어 있으며, 한 번에 **인접한 두 파일 묶음**만 합칠 수 있다. 두 묶음을 합칠 때 드는 시간은 두 묶음의 크기 합에 비례한다.

예를 들어 크기 10, 20, 30인 파일이 있을 때, 10과 20을 먼저 합치면 비용 30이 들고 이후 30과 30을 합치면 비용 60이 들어 총 90이다. 반면 20과 30을 먼저 합치면 비용 50, 이후 10과 50을 합치면 60이 들어 총 110이다. 어떤 순서로 합치느냐에 따라 총 비용이 달라진다.

태양은 $n$개의 파일을 하나로 합칠 때 가능한 모든 순서 중 총 비용이 가장 작아지는 순서를 찾아야 한다. 파일 수는 2,000 개까지다.

#### 함수 인터페이스

```ts
export function knuthOptimization(freq: number[]): number;
```

- `freq` — 각 파일의 크기를 나타내는 비음수 정수 배열 (인접한 순서로 나열)
- 반환 — 모든 파일을 하나로 합칠 때 드는 최소 총 비용

#### 제약 조건

- $1 \leq n \leq 2000$ (여기서 $n$은 `freq`의 길이)
- $\text{freq}[i] \geq 0$
- 반환값은 $\geq 0$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

$n$개의 인접한 파일 크기 `freq[0..n-1]`가 주어진다. 한 번의 병합 연산은 인접한 두 그룹을 하나로 합치며, 이때 비용은 두 그룹의 크기 합이다. 모든 파일이 하나의 그룹이 될 때까지 병합을 반복한다.

가능한 모든 병합 순서 중 **총 비용의 최솟값**을 반환하라.

- 길이 1인 배열은 병합할 대상이 없으므로 0을 반환한다.
- 모든 크기가 0이면 어떤 순서로 병합해도 비용은 0이다.

#### 예시

```ts
knuthOptimization([10]);          // 0 — 파일 하나, 병합 불필요
knuthOptimization([10, 20]);      // 30 — 한 번 병합: 10+20=30
knuthOptimization([1, 2, 3]);     // 9 — (1+2)=3 비용, 이후 (3+3)=6 비용, 총 9
knuthOptimization([10, 20, 30]);  // 90 — (10+20)=30, 이후 (30+30)=60, 총 90

// 경계 케이스
knuthOptimization([0, 5, 0]);         // 10 — (0+5)=5, 이후 (5+0)=5, 총 10
knuthOptimization([0, 0, 0, 0]);      //  0 — 모두 0, 비용 없음
knuthOptimization([10, 10, 10, 10]);  // 80 — 균등 병합 최적
```
