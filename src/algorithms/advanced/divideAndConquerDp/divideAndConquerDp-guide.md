# divideAndConquerDp — 최적 분할점이 뒤로만 가면 후보 범위를 절반씩 접을 수 있는 이유

## 파트 1 — 아이디어에서 동작하는 코드까지

전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 것을 확인한 다음, 분할점 후보를 전부 검사하는
방법에서 가운데 칸을 먼저 확정해 좌우의 후보 범위를 접는 방법까지 가는 경로를 따라갑니다.
마지막에는 실제로 작동하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

일렬로 늘어선 거점 `n` 개를 **연속된 `k` 개의 구역**으로 나누되 비용 합이 가장 작아지는 분할을
찾는 문제예요. 구간 `[i, j]` 를 한 구역으로 묶는 값이 표 `cost[i][j]` 로 미리 주어지고, 답은
그 값들의 합입니다. 겹치지 않고, 빠짐없이, 순서대로 이어지는 분할만 셉니다.

```text
거점 넷을 세 구역으로 나누는 방법과 그 비용
  a = [1, 2, 3, 4] · cost[i][j] = (a[i] + … + a[j])^2

  [0,0] [1,1] [2,3]    1 +  4 + 49 = 54
  [0,0] [1,2] [3,3]    1 + 25 + 16 = 42
  [0,1] [2,2] [3,3]    9 +  9 + 16 = 34   <- 이쪽이 작다

  구역 경계를 「마지막 구역이 시작하기 직전 거점」 하나로 적을 수 있다 — 그 수를 분할점이라 부른다
```

정직하게 푸는 방법은 정해져 있어요. `[0, i]` 를 `g` 개 구역으로 나눈 최솟값을 `dp[g][i]` 라
두고, 마지막 구역이 어디서 시작하는지를 뜻하는 **분할점** `j` 를 전부 검사하면 됩니다. 그러면
`dp[g][i]` 는 `dp[g-1][j] + cost[j+1][i]` 중 가장 작은 값이에요.

| 이름 | 무엇을 하는가 | 이 글의 표기 |
| --- | --- | --- |
| 계층 | 구역 수 `g` 를 고정하고 `dp[g][*]` 를 전부 채우는 한 단계 | 「계층 `g`」 로 적습니다 |
| 분할점 | 마지막 구역이 시작하기 직전 거점의 번호 `j` | 「분할점」 으로 적습니다 |
| 최적 분할점 | 그 칸의 최솟값을 만드는 분할점 | `opt(g, i)` 로 적습니다 |
| 사각 부등식 | `a ≤ b ≤ c ≤ d` 인 지표 넷마다 `cost[a][c] + cost[b][d] ≤ cost[a][d] + cost[b][c]` 가 성립하는 것 | 「사각 부등식」 으로 적습니다 |
| `INF` | 그 분할을 만들 수 없다는 표기. 코드의 `Number.POSITIVE_INFINITY` 입니다 | `INF` 로 적습니다 |

문제는 그 검사가 몇 번이냐입니다. 거점이 500 개이고 구역도 500 개인 제약 상한에서 실제로 세면
6,225 만 번이고, 1 초 안에 끝내기 아슬아슬한 크기예요. 여기서 접을 자리를 하나 찾습니다 —
**`i` 가 커질 때 `opt(g, i)` 도 뒤로만 간다면**, 가운데 칸의 최적 분할점을 먼저 알아낸 뒤에는
왼쪽 칸들의 후보가 그보다 앞, 오른쪽 칸들의 후보가 그보다 뒤로 갇힙니다.

```text
계층 하나에서 후보 범위가 접히는 모습 (거점 16)

  solve(0, 15, 0, 14)   칸 [0,15] 을 맡고 분할점이 [0,14] 안이라고 넘겨받았다
                        가운데 칸 7 의 최적 분할점을 후보 [0, 6] 에서 찾는다 -> 3
                 |
      +----------+----------+
      v                     v
  solve(0, 6, 0, 3)      solve(8, 15, 3, 14)
  분할점이 [0,3] 안이다   분할점이 [3,14] 안이다
      |                     |
     ...                   ...

  왼쪽으로 갈수록 넘겨받는 범위의 위쪽이 잘리고 오른쪽으로 갈수록 아래쪽이 잘린다
  한 깊이에 놓인 범위들은 끝점만 겹치므로 그 길이의 합이 거점 수와 같은 자릿수에 머무른다
```

이 「뒤로만 간다」가 공짜로 성립하지는 않아요. 비용 행렬이 **사각 부등식**이라는 조건을
만족할 때만 성립하고, 문제가 그 조건을 보장해 줍니다. 조건이 깨지면 이 절차는 최솟값을 놓치는데,
그 자리도 아래에서 실제 값으로 보입니다.

```text
두 방법의 검사 횟수 (거점 500 · 구역 3)

  후보를 전부 검사      249,500 번
  범위를 접으면           8,862 번

  갈리는 것은 답이 아니라 검사 횟수다. 두 방법의 반환값은 같다
```

검사 횟수가 계층마다 `n log n` 언저리로 내려가고, 계층이 `k-1` 개이므로 전체가 `O(k n log n)`
입니다. **이 절차가 새로 쓰는 저장 칸**은 이전 계층과 이번 계층 두 줄이라 `O(n)` 이에요 —
비용 행렬 자체는 `n x n` 이므로 입력이 이미 `n^2` 칸을 차지합니다.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **구간 합과 그것으로 만든 비용.** 이 글이 쓰는 비용 행렬은 `cost[i][j] = (a[i] + … + a[j])^2`
  입니다. 구간 합을 빠르게 얻는 방법이 궁금하면
  [구간 합 질의 가이드](../../array/prefixSumRangeQuery/prefixSumRangeQuery-guide.md)를 보세요.
- **계층으로 나눈 동적 계획법.** 「이전 계층의 값만 읽어 이번 계층을 채운다」 는 구조를 이미
  알고 있어야 합니다. 표를 한 줄씩 채우는 예가 필요하면
  [배낭 문제 가이드](../../dp/knapsack01/knapsack01-guide.md)가 같은 모양이에요.
- **재귀로 범위를 절반씩 가르기.** `mid = (lo + hi) >> 1` 로 가운데를 잡고 좌우로 재귀하는
  꼴을 이 절차가 그대로 씁니다. 그 꼴 자체가 낯설면
  [이분 탐색 가이드](../../binary-search/binarySearch/binarySearch-guide.md)를 먼저 보세요.
- **최솟값과 그 최솟값을 만든 지표를 함께 기록하는 것.** 값만 기록하면 범위를 좁힐 근거가
  없어집니다. 이 절차는 값과 `opt(g, i)` 를 함께 들고 갑니다.

이 글이 다루는 것은 **비용 행렬이 사각 부등식을 만족할 때의 최소 비용 `k` 분할**이고, 사각
부등식을 만족하지 않는 비용 행렬은 다루지 않아요. 조건이 없으면 후보를 전부 검사하는 쪽으로
가야 합니다.

```text
연속 구간 k 개로 나누고 비용 합을 최소로 한다 · 사각 부등식이 성립한다  <- 이 글이 다루는 것
같은 문제인데 사각 부등식이 성립하지 않는다                             <- 다른 방법이 필요한 것
구간을 나누는 것이 아니라 괄호를 치는 순서를 정한다                     <- 다른 글이 다루는 것
구역 수 k 가 정해져 있지 않고 구역 하나마다 고정 비용이 붙는다          <- 또 다른 글이 다루는 것
```

괄호를 치는 순서를 정하는 문제는
[행렬 곱 순서 가이드](../../dp/matrixChainMultiplication/matrixChainMultiplication-guide.md)가,
구역마다 고정 비용이 붙어 직선 하나로 정리되는 문제는
[볼록 껍질 트릭 가이드](../convexHullTrick/convexHullTrick-guide.md)가 그 자리를 맡습니다.

### 아이디어 상세 — 최적 분할점의 단조성을 떠올리는 과정

먼저 무엇을 만드는지 고정하고 갑시다.

```ts
function divideAndConquerDp(cost: number[][], k: number): number;
```

- 입력: `n x n` 비용 행렬 `cost` 와 나눌 구역 수 `k`. `cost[i][j]` 는 구간 `[i, j]` 를 한
  구역으로 묶는 비용이고 `i ≤ j` 에서만 뜻이 있습니다.
- 출력: 거점 `[0, n-1]` 을 정확히 `k` 개의 연속 구역으로 나눴을 때 비용 합의 최솟값.
- 제약: `1 ≤ n ≤ 500`, `1 ≤ k ≤ n`, `0 ≤ cost[i][j]`. 비용 행렬은 사각 부등식을 만족합니다.
  시간 1 초, 메모리 256 MB.

본문이 끝까지 쓰는 기호는 일곱이에요. 절이 바뀌어도 뜻은 바꾸지 않습니다.

| 기호 | 무엇인가 | 이 문제에서 |
| --- | --- | --- |
| `n` | 거점의 개수. 코드의 `cost.length` 입니다 | `1 ≤ n ≤ 500` |
| `k` | 나눌 연속 구역의 개수 | `1 ≤ k ≤ n` |
| `cost[i][j]` | 구간 `[i, j]` 를 한 구역으로 묶는 비용 | 0 이상의 정수. `i ≤ j` |
| `g` | 지금 채우는 계층의 구역 수 | `1` 부터 `k` 까지 |
| `dp[g][i]` | 거점 `[0, i]` 를 정확히 `g` 개 구역으로 나눈 최소 비용 | 만들 수 없으면 `INF` |
| `j` | 마지막 구역이 시작하기 직전 거점. 분할점입니다 | `0 ≤ j < i` |
| `opt(g, i)` | `dp[g][i]` 를 최소로 만드는 분할점 `j` | 칸마다 하나 |

`dp[g][i]` 와 `opt(g, i)` 를 갈라 두는 것이 이 글의 뼈대입니다. 앞은 그 칸의 **값**이고 뒤는
그 값을 만든 **자리**예요. 값만 기록하는 절차는 후보를 매번 전부 검사해야 하고, 자리를 함께
기록해야 다음 칸의 후보 범위를 좁힐 근거가 생깁니다.

```text
한 칸에 붙는 값 둘
  dp[g][i]   그 칸의 최소 비용이다        답을 만들 때 쓰는 값
  opt(g, i)  그 값을 만든 분할점이다      다음 칸의 후보 범위를 정하는 값

opt 줄이 이 알고리즘의 눈금이다. 값이 아니라 자리가 비용을 정한다
```

아무 기법 없이 푸는 법부터 세웁니다. **분할을 하나도 빠뜨리지 않고 전부 만들어** 비용 합이
가장 작은 것을 고르면 돼요. 거기서 한 걸음만 나아간 것이 위 점화식을 그대로 채우는 방법이고,
그때는 칸 하나마다 후보 `j` 를 `0` 부터 `i-1` 까지 전부 넣어 봅니다. 셋을 나란히 셉니다.

<!--proof:naiveScale-->

```text
거점 n  구역 k  분할의 개수  후보 검사 (전부)  후보 검사 (범위를 좁히면)
     6       3           10                30                         22
    50       3        1,176             2,450                        549
   200       3       19,701            39,800                      3,073
   500       3      124,251           249,500                      8,862

제약 상한 n = 500 에서
  분할의 개수 (k = 250)               149 자리 수
  분할의 개수 (k = 500)               1 개 — 거점마다 구역이 하나다
  후보 검사 (전부, k = 500)           62,250,250 번
  후보 검사 (범위를 좁히면, k = 500)  1,945,682 번
```

**분할을 전부 만드는 방법이 먼저 실패합니다.** 거점 500 · 구역 250 이면 분할이 149 자리 수라
배열에 담을 수조차 없어요. 점화식을 채우는 방법은 그 자리를 **분할 수가 아니라 후보 검사 수**로
바꾸어 놓습니다 — 같은 거점 500 에 구역이 셋이면 분할 12 만 4,251 개가 검사 24 만 9,500 번이
되고, 둘의 차수가 갈립니다. 다만 구역도 500 개까지 늘리면 검사가 6,225 만 번이라 1 초 제한
안에서 아슬아슬해요. 오른쪽 열이 이 글이 만들 절차의 실측이고 같은 제약에서 194 만 번,
32 배 적습니다.

```text
검사 횟수가 어디서 늘어나는가

  계층 하나가 칸 n 개                  n 에 비례한다
  칸 하나가 후보 최대 n-1 개           다시 n 에 비례한다
  계층이 k-1 개                        k 에 비례한다
                                       -> k n^2 규모

  줄일 자리는 「칸 하나가 후보 몇 개를 보는가」 하나뿐이다. 칸 수와 계층 수는 문제가 정한다
```

후보를 줄이려면 「이 칸의 최적 분할점이 어디쯤인지」를 미리 알아야 합니다. 그것을 실제로
계산해서 나열해 봅시다. 배열 `[1, 2, 3, 4, 5, 6, 7, 8]` 의 구간 합 제곱을 비용으로 삼고 계층
2 와 계층 3 의 `opt(g, i)` 를 전부 냅니다.

<!--proof:optMonotone-->

```text
구간 끝 i     0     1  2  3  4  5  6  7
opt(2, i)  없음     0  1  2  2  3  4  4
opt(3, i)  없음  없음  1  2  3  4  5  5

배열 [1, 2, 3, 4, 5, 6, 7, 8] · 비용은 구간 합의 제곱
「없음」 은 구역 수보다 거점이 적어 만들 수 없는 칸이다
```

**두 줄 다 한 번도 앞으로 되돌아가지 않습니다.** 계층 2 는 `0 1 2 2 3 4 4` 로 같은 값이 이어지
거나 커지기만 하고 계층 3 도 `1 2 3 4 5 5` 로 그렇습니다. 이것이 이 글이 쓸 성질이에요 —
`i1 < i2` 이면 `opt(g, i1) ≤ opt(g, i2)` 입니다.

```text
단조성이 없으면 무엇을 못 하는가

  opt(2, 3) = 2 를 알아냈다
  단조성이 있으면   칸 4 · 5 · 6 · 7 의 후보는 2 이상이다      아래쪽을 잘라도 된다
                    칸 0 · 1 · 2 의 후보는 2 이하다            위쪽을 잘라도 된다
  단조성이 없으면   어느 칸의 후보도 못 자른다                 전부 검사로 되돌아간다
```

그런데 이 성질은 배열을 잘 골라서 나온 우연일 수도 있어요. 성질을 보장하는 조건이 **사각
부등식**입니다 — `a ≤ b ≤ c ≤ d` 인 모든 지표 넷에 대해 `cost[a][c] + cost[b][d] ≤
cost[a][d] + cost[b][c]` 가 성립하는 것이고, 이 글이 쓰는 비용 행렬들이 실제로 그런지를 지표
조합 전수로 확인합니다.

<!--proof:quadrangleCheck-->

```text
비용 행렬                           검사한 지표 조합  위반  첫 위반 (a, b, c, d)
전개 입력 (거점 4)                                35     0  -
값이 모두 같은 배열 (거점 8)                     330     0  -
생성식 배열 (거점 16)                          3,876     0  -
앞이 큰 배열 (거점 9)                            495     0  -
사각 부등식이 깨지는 행렬 (거점 4)                35     1  1, 2, 2, 3
```

**앞의 네 행렬은 지표 조합을 전수로 검사해 위반이 0 입니다.** 이 글이 쓰는 비용은 전부 구간
합의 제곱이고, 그 꼴이 언제나 이 조건을 만족한다는 일반 증명은 이 글이 하지 않아요 — 확인한
것은 위 네 벌뿐입니다. 마지막 행이 일부러 만든 반례인데, 위반이 지표 조합 `(1, 2, 2, 3)`
하나뿐인데도 단조성이 성립하지 않습니다 — 그 자리는 전개 절에서 값으로 봅니다.

```text
사각 부등식이 말하는 것

  지표 순서:  a ──── b ──── c ──── d

  왼쪽 항  cost[a][c] + cost[b][d]   안쪽 구간과 바깥 구간을 하나씩
  오른쪽 항  cost[a][d] + cost[b][c]   가장 넓은 구간과 가장 좁은 구간

  넓은 쪽으로 몰아 담을수록 비용 합이 커지거나 그대로다 — 그것이 이 조건이다
```

단조성을 어떻게 쓸지 가장 단순한 후보부터 시험합시다. **`i` 를 왼쪽에서 오른쪽으로 처리하면서
후보의 시작을 직전 칸의 최적 분할점에 두는 것**이에요. 단조성이 하한을 보장하니 그 아래는
검사할 필요가 없습니다. 그런데 상한은 그대로 `i-1` 이라 아무것도 안 잘려요.

```text

값이 모두 같은 배열      64      4,032        1,841        781
```

**하한만 옮기는 방법은 전부 검사에 대한 비가 거점이 커져도 안 내려갑니다.** 값이 모두 같은
배열에서 거점 64 일 때 1,841 / 4,032 = 46 % 이고 거점 256 일 때 27,857 / 65,280 = 43 % 예요.
앞이 큰 배열에서는 3,071 / 4,032 = 76 % 와 49,151 / 65,280 = 75 % 로 더 높습니다. 첫 칸만 큰
배열은 최적 분할점이 뒤로 안 가서 하한이 안 올라가기 때문인데, 그 사실은 실제로 계산해
확인했어요 — 거점 64 에서 `opt(2, i)` 의 마지막 여덟 칸이 전부 0 입니다.

```text
하한만 옮겼을 때 남는 것

  칸 i 의 후보 범위 = [opt(g, i-1), i-1]
  opt 가 0 에 머무르면 이 범위가 [0, i-1] 이고 길이가 i 다
  -> 칸마다 i 번, 계층 하나의 합이 n(n-1)/2 로 전부 검사와 같은 차수가 된다

  잘린 것은 아래쪽뿐이고 위쪽은 그대로다. 위쪽을 자르려면 「뒤 칸의 최적 분할점」이 필요하다
```

그래서 순서를 바꿉니다. **가운데 칸을 먼저 확정하면 그 칸의 최적 분할점이 왼쪽 절반의 상한과
오른쪽 절반의 하한을 동시에 줍니다.** 왼쪽 절반은 `[optLo, bestOpt]` 안에서, 오른쪽 절반은
`[bestOpt, optHi]` 안에서 답을 찾으면 되고, 각 절반이 다시 같은 일을 되풀이해요. 이것이 이
절차의 이름이 분할 정복인 이유입니다.

```text
범위 하나가 둘로 갈리는 규칙

  solve(lo, hi, optLo, optHi)          칸 [lo, hi] 의 최적 분할점이 [optLo, optHi] 안이다
    mid = (lo + hi) / 2
    후보 범위 [optLo, min(optHi, mid - 1)] 에서 최솟값과 그 자리 bestOpt 를 찾는다
    왼쪽  solve(lo, mid - 1, optLo, bestOpt)     위쪽이 bestOpt 로 잘린다
    오른쪽 solve(mid + 1, hi, bestOpt, optHi)    아래쪽이 bestOpt 로 잘린다

  min(optHi, mid - 1) 의 mid - 1 은 「분할점은 그 칸보다 앞이어야 한다」 를 지키는 자리다
```

### 수행으로 알아보는 알고리즘 — 거점 넷을 열두 걸음으로 나눈다

아이디어를 세웠으니 **실제로 작동하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되,
조각을 하나 만들 때마다 그것만 실행한 결과를 보고 다음으로 갑니다.

```ts
const a = [1, 2, 3, 4];
const cost = buildCost(a); // cost[i][j] = (a[i] + … + a[j])^2
const k = 3;
// 이 절이 끝나면 34 가 나와야 한다
```

왜 하필 거점 넷에 구역 셋일까요? 일곱 갈래를 한 입력에서 전부 실행하려고 고른 입력이기
때문이에요. `k = 3` 이라 계층 교체가 실제로 두 번 일어나고, `mid = 0` 인 호출이 나와 「후보가
하나도 없는 칸」 갈래가 나오며, 계층 3 에서 `INF` 를 후보로 읽는 자리까지 나옵니다.


#### 1. 기저 계층을 채운다

첫 조각이 준비입니다. 구역이 하나뿐인 계층은 선택의 여지가 없어요 — `[0, i]` 를 통째로 한
구역으로 묶는 것 말고 방법이 없으니 `dp[1][i]` 가 `cost[0][i]` 그대로입니다.

```ts
const n = cost.length;

const base = cost[0] as number[];
let prev: number[] = new Array<number>(n).fill(INF);
for (let i = 0; i < n; i++) prev[i] = base[i] as number;   // ① 기저 계층
```

`prev` 라는 이름을 쓴 이유가 있어요. 계층 `g` 를 채울 때 읽는 것은 계층 `g-1` 뿐이라 표 전체를
들고 있을 필요가 없고, **직전 계층 한 줄만** 있으면 됩니다. 코드에서는 그 한 줄이 `prev` 이고
지금 채우는 줄이 `cur` 입니다.

```text
T1 이 끝난 시점
  prev   [1, 9, 36, 100]        dp[1][0..3] 이다
  a      [1, 2, 3, 4]           prev[3] = (1+2+3+4)^2 = 100 이다

계층 표에 드는 저장 칸이 계층 수와 무관하게 2n 이다. 비용 행렬 n x n 은 입력이라 따로 센다
```

#### 2. 가운데 칸 하나를 확정한다

둘째 조각이 본체입니다. 범위 `[lo, hi]` 를 받아 그 가운데 칸 `mid` 의 값을 확정해요. 후보는
`[optLo, optHi]` 안에서 고르되 **분할점이 `mid` 보다 앞이어야 하므로** 상한을 `mid - 1` 로
한 번 더 자릅니다.

```ts
if (lo > hi) return;                          // ③ 빈 범위
const mid = (lo + hi) >> 1;
let bestCost = INF;
let bestOpt = optLo;
const upper = Math.min(optHi, mid - 1);       // ④ 후보 상한
for (let j = optLo; j <= upper; j++) {
  const row = cost[j + 1] as number[];
  const val = (prev[j] as number) + (row[mid] as number);
  if (val < bestCost) {                       // ⑤ 최솟값 갱신
    bestCost = val;
    bestOpt = j;
  }
}
cur[mid] = bestCost;
```

첫 호출만 실행하면 이렇게 나옵니다. `solve(0, 3, 0, 2)` 의 `mid` 가 1 이고 상한이
`min(2, 0) = 0` 이라 후보가 `j = 0` 하나예요.

```text
T2 — 계층 2 의 칸 1 을 확정한다
  후보 범위  [0, min(2, 0)] = [0, 0]
  j = 0      prev[0] + cost[1][1] = 1 + 4 = 5

  확정한 값  cur[1] = 5
  bestOpt    0
```

#### 3. 좌우로 재귀하며 후보 범위를 접는다

셋째 조각이 범위를 접는 자리입니다. `mid` 의 최적 분할점 `bestOpt` 를 알아냈으니 왼쪽 절반은
그보다 앞에서, 오른쪽 절반은 그보다 뒤에서 답을 찾으면 돼요.

```ts
solve(lo, mid - 1, optLo, bestOpt);           // ⑥ 좌우 재귀
solve(mid + 1, hi, bestOpt, optHi);
```

`bestOpt` 가 왼쪽에는 **상한**으로, 오른쪽에는 **하한**으로 들어간다는 것을 봐 주세요. 같은
값이 두 자리에 쓰이므로 두 재귀가 받는 범위의 길이 합이 원래 범위보다 1 만큼만 큽니다.

**T3 에서 이미 어긋납니다.** 칸 0 에 `INF` 를 적는 순간 같은 배열의 `prev[0]` 이 1 에서
`INF` 로 바뀌고, T4 가 그 자리를 읽어 칸 2 를 18 이 아니라 14 로 확정해요. T5 가 칸 3 을
52 가 아니라 30 으로 적고, 계층 3 이 그 표를 읽으며 칸이 하나씩 `INF` 로 지워집니다.
「이번 계층을 채우는 동안 지난 계층은 안 바뀐다」 가 깨지면 읽는 값 자체가 달라져요.

이 자리를 지키는 줄이 둘이에요. 계층마다 `cur` 를 새로 만드는 줄(`② 계층 배열`)과 계층 끝에서
`prev = cur` 로 바꾸는 줄(`⑦ 계층 교체`)입니다. 앞의 것이 없으면 지금 본 것처럼 어긋나고,
뒤의 것이 없으면 다음 계층이 계층 1 을 계속 읽어요.

#### 멈춤 — 사각 부등식이 깨지면 이 절차는 최솟값을 놓친다

여기서 헷갈리기 쉬운 포인트는 「비용 행렬이면 아무거나 넣어도 되나」입니다. 문제가 사각
부등식을 보장한다고 적어 두었는데, 그 보장이 없으면 무엇이 어떻게 되는지 값으로 봅시다.

<!--proof:pauseQuadrangle-->

```text
구간 끝 i     0  1  2  3
opt(2, i)  없음  0  1  0

사각 부등식 검사 35 조합 중 위반 1 개 — (a, b, c, d) = 1, 2, 2, 3
  cost[1][2] + cost[2][3] = 0 + 4 = 4
  cost[1][3] + cost[2][2] = 1 + 0 = 1

칸 3 의 후보를 전부 넣어 보면
  j = 0  dp[1][0] + cost[1][3]  = 5 + 1 = 6  진짜 최솟값
  j = 1  dp[1][1] + cost[2][3]  = 4 + 4 = 8
  j = 2  dp[1][2] + cost[3][3]  = 1 + 7 = 8

분할 정복이 낸 값 8 · 후보를 전부 검사한 값 6
```

**`opt(2, i)` 가 `0 1 0` 으로 되돌아갑니다.** 칸 2 의 최적 분할점이 1 인데 칸 3 의 최적 분할점이
0 이에요. 그래서 칸 2 를 먼저 확정하고 오른쪽에 하한 1 을 넘기면 칸 3 의 진짜 답인 `j = 0` 이
범위 밖으로 나가고, 절차는 8 을 답이라고 내놓습니다. 정답은 6 이에요.

```text
어느 값이 이 반례를 만드는가

  cost  =  [[5, 4, 1, 7],
            [-, 4, 0, 1],
            [-, -, 0, 4],
            [-, -, -, 7]]        - 는 i > j 라 문제가 정의하지 않는 자리다

  사각 부등식은 cost[1][2] + cost[2][3] ≤ cost[1][3] + cost[2][2] 를 요구한다
  왼쪽 4 · 오른쪽 1 이라 4 ≤ 1 이 성립하지 않는다

  위 블록의 「칸 3 의 후보」 표에서 j = 0 이 최솟값인데, 하한이 1 이라 범위 밖이다
```

이 함수는 **사각 부등식 판정을 하지 않습니다.** 문제가 그 조건을 보장하기 때문에 안 하는
것이고, 보장이 없는 문제에는 그대로 쓸 수 없어요. 조건이 없는 자리에서는 후보를 전부 검사하는
쪽으로 가야 합니다.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 **첫 호출**
`solve(0, n - 1, 0, n - 2)` 하나예요. 넷째 인자가 `n - 2` 인 것은 분할점 `j` 에 대해
`j + 1 ≤ n - 1` 이 필요하기 때문이고, 그래서 처음에 넘기는 범위가 가능한 분할점 전부입니다.
나머지는 조각 셋을 계층 반복으로 감싼 것이고 동작은 그대로예요.

```ts
// 아직 확정하지 않은 칸의 값. 어떤 유한한 비용보다 크다.
export const INF = Number.POSITIVE_INFINITY;

export function divideAndConquerDp(cost: number[][], k: number): number {
  const n = cost.length;

  // ① 기저 계층 — 구간이 하나뿐이면 [0, i] 를 통째로 묶는 것 말고 선택이 없다.
  const base = cost[0] as number[];
  let prev: number[] = new Array<number>(n).fill(INF);
  for (let i = 0; i < n; i++) prev[i] = base[i] as number;

  for (let g = 2; g <= k; g++) {
    // ② 이번 계층의 배열 — 계층마다 새로 만든다. 지난 계층의 값을 고치지 않는다.
    const cur: number[] = new Array<number>(n).fill(INF);

    const solve = (
      lo: number,
      hi: number,
      optLo: number,
      optHi: number,
    ): void => {
      // ③ 빈 범위 — 확정할 칸이 없으면 여기서 끝낸다. 재귀의 유일한 종료 조건이다.
      if (lo > hi) return;
      const mid = (lo + hi) >> 1;
      let bestCost = INF;
      let bestOpt = optLo;
      // ④ 후보 상한 — 분할점은 mid 보다 앞이어야 하므로 mid - 1 로 자른다.
      const upper = Math.min(optHi, mid - 1);
      for (let j = optLo; j <= upper; j++) {
        const row = cost[j + 1] as number[];
        const val = (prev[j] as number) + (row[mid] as number);
        // ⑤ 최솟값 갱신 — 값과 그 값을 만든 분할점을 함께 기록한다.
        if (val < bestCost) {
          bestCost = val;
          bestOpt = j;
        }
      }
      cur[mid] = bestCost;
      // ⑥ 좌우 재귀 — 왼쪽 절반의 후보 상한과 오른쪽 절반의 후보 하한이 둘 다 bestOpt 다.
      solve(lo, mid - 1, optLo, bestOpt);
      solve(mid + 1, hi, bestOpt, optHi);
    };

    solve(0, n - 1, 0, n - 2);
    // ⑦ 계층 교체 — 다음 계층이 이번 계층을 이전 계층으로 읽는다.
    prev = cur;
  }

  return prev[n - 1] as number;
}
```

```text
divideAndConquerDp(buildCost([1, 2, 3, 4]), 3)  -> 34
divideAndConquerDp(buildCost([1, 2, 3, 4]), 1)  -> 100
divideAndConquerDp(buildCost([1, 2, 3, 4]), 4)  -> 30
divideAndConquerDp(buildCost([5, 10, 15]), 3)   -> 350
divideAndConquerDp([[7]], 1)                    -> 7
```

### 알아 두면 좋은 개념 — 완전 단조 행렬

이 절차가 후보 범위를 접을 수 있었던 근거에는 이름이 붙어 있습니다. 행마다 최솟값의 자리가
있고 **그 자리가 행을 따라 오른쪽으로만 가는 행렬**을 **단조 행렬**이라 부르고, 그 성질이
어떤 부분행렬에서도 성립하면 **완전 단조 행렬**이라고 불러요. 이 편에서 그 행렬은 「행이
칸 `i`, 열이 분할점 `j`, 값이 `dp[g-1][j] + cost[j+1][i]` 인 표」이고, 최솟값의 자리가 곧
`opt(g, i)` 입니다.

```text
이 편의 어느 값이 완전 단조 행렬이었는가

  행 i        구간 끝                    계층 하나의 칸 하나
  열 j        분할점                     그 칸의 후보 하나
  값 M[i][j]  dp[g-1][j] + cost[j+1][i]  후보 검사가 만든 수
  행의 최솟값 자리                       opt(g, i) 다

  opt(2, i) = 0 1 2 2 3 4 4 로 오른쪽으로만 간 것이 「단조」 의 값이다
  이 편이 값으로 보인 것은 단조성까지이고, 완전 단조는 그것이 어떤 부분행렬에서도 성립한다는
  더 강한 성질이다. 분할 정복은 단조성만 있으면 되고 SMAWK 는 완전 단조를 요구한다
```

같은 이름이 이 편 밖에서 다시 나옵니다. 셋 다 「행마다 최솟값의 자리를 찾되 그 자리가 뒤로만
간다」를 같은 모양으로 씁니다.

| 어디서 또 만나는가 | 무엇이 행이고 무엇이 열인가 | 최솟값의 자리로 무엇을 하는가 |
| --- | --- | --- |
| 크누스 최적화 | 행은 구간 `[i, j]`, 열은 그 구간을 가르는 자리 | 이웃 두 칸의 자리로 범위를 좁힌다 |
| SMAWK 행렬 탐색 | 이 편과 같은 행렬 | 완전 단조를 전제로 최솟값 자리를 한꺼번에 고른다 |
| 몽주 행렬과 수송 문제 | 행은 공급지, 열은 수요지 | 비용이 가장 작은 짝을 대각선 순서로 정한다 |

크누스 최적화는 이 저장소에도 있어요 —
[최적 파일 병합 문제](../knuthOptimization/knuthOptimization-problem.md)가 그 자리이고, 구간을
가르는 자리를 이웃 칸 둘로 가두는 점만 다릅니다. **이름을 알아 두면 다시 만났을 때 「무엇이
행이고 무엇이 열인가」 부터 물을 수 있어요** — 그 둘만 정하면 나머지는 이 편과 같습니다.

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 문제에 이것을 쓰는지, 단조성이 왜 성립하고 비용의
상한이 어떻게 닫히는지, 무엇이 매 호출 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **연속 구간으로 나누는 문제입니다.** 구역이 이어져 있어야 「분할점 하나」로 구역 경계를
  적을 수 있어요. 원소를 골라 담는 문제는 분할점이라는 개념 자체가 없습니다.
- **구역 수 `k` 가 문제에 주어집니다.** 계층을 `k-1` 번 되풀이하는 것이 이 절차의 뼈대라
  구역 수가 정해져 있지 않으면 계층 수를 정할 수 없어요.
- **비용 행렬이 사각 부등식을 만족합니다.** 이것이 단조성의 근거이고, 없으면 이 절차는 답을
  놓칩니다. 이 글이 전수로 확인한 것은 구간 합의 제곱 네 벌이고, 다른 비용 계열이 이 조건을
  만족하는지는 그때마다 따로 확인해야 해요.
- **거점 수가 커서 `k n^2` 을 감당할 수 없습니다.** 거점이 여덟 개 이하이면 후보를 전부
  검사하는 쪽이 연산이 더 적어요 — 그 경계는 아래에서 값으로 잽니다.

```text
네 조건이 코드의 모양을 그대로 정한다
  연속 구간이다              -> 상태가 (구역 수 g, 구간 끝 i) 둘로 끝난다
  k 가 주어진다              -> 바깥 반복이 g = 2 부터 k 까지다
  사각 부등식이 성립한다     -> bestOpt 를 좌우 재귀에 넘길 수 있다
  n 이 크다                  -> 재귀 호출 값을 치르고도 이득이다

  셋째 줄이 이 절차의 자리이자 이 절차의 위험이다
```

「사각 부등식이 성립한다」 줄이 이 절차의 자리입니다. 조건이 없으면 후보를 전부 검사해야 하고,
구역마다 고정 비용이 붙어 비용이 직선 하나로 정리되면
[볼록 껍질 트릭](../convexHullTrick/convexHullTrick-guide.md) 쪽이 더 적은 연산으로 끝나요.

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "일렬로 늘어선" "연속된" "구간으로 나눈다"   <- 분할점 하나로 경계를 적을 수 있다
  "정확히 k개의 그룹"                          <- 계층 수가 k-1 로 정해진다
  "구간 [i, j] 를 묶는 비용이 주어진다"        <- 비용 행렬이 입력이다
  "비용은 구간 합의 제곱"                      <- 사각 부등식을 만족하는 전형이다

제약에 이런 모양이 보이면
  n 이 수백이고 k 도 수백이다                  <- 후보 검사가 6 천만 번을 넘어 아슬아슬하다
  1 초 · 256 MB                                <- 비용 행렬 n x n 말고는 두 줄이면 된다

반대로 이런 말이 보이면 해당하지 않는다
  "원소를 골라 담는다" "순서를 바꿔도 된다"    <- 분할점이라는 개념이 없다
  "그룹 수에 제한이 없다"                      <- 계층 수를 정할 수 없다
  "비용이 구간마다 제멋대로 주어진다"          <- 사각 부등식을 보장할 수 없다
```

마지막 무리가 보이면 다른 절차로 갑니다. 그룹 수에 제한이 없고 구역 하나마다 고정 비용이
붙으면 [볼록 껍질 트릭](../convexHullTrick/convexHullTrick-guide.md) 이 그 자리를 맡고, 구간을
나누는 것이 아니라 자르는 자리마다 값이 붙으면
[회문 분할 가이드](../../dp/palindromePartitioningMinCut/palindromePartitioningMinCut-guide.md)
쪽입니다.

#### 실제로 쓰이는 곳

- **`Ckmeans.1d.dp` 의 `fill_row_q_log_linear`** — 1 차원 자료를 `k` 개 군집으로 최적 분할하는
  CRAN 의 R 패키지가 이 절차를 그대로 씁니다. 소스 파일 첫 줄 주석이
  *"fill_log_linear.cpp --- a divide-and-conquer algorithm to compute a row in the dynamic
  programming matrix in O(n lg n) time."* 이고, 함수 본문이 `int i = (imin + imax) / 2;` 로
  가운데 칸을 잡은 다음 `int jhigh = i - 1; // the upper end for j` 로 후보 상한을 자릅니다 —
  이 글의 `mid` 와 `Math.min(optHi, mid - 1)` 이 같은 자리예요. 좌우 재귀에 넘기는 값도
  같습니다: 왼쪽 앞에서 `jmax = (int)J[q][i];`, 오른쪽 앞에서 `jmin = (int)J[q][i];` 입니다.
  ([`Ckmeans.1d.dp/src/fill_log_linear.cpp`](https://github.com/cran/Ckmeans.1d.dp/blob/master/src/fill_log_linear.cpp),
  조회 2026-09-05)
- **`kmeans1d` 의 SMAWK 구현** — 같은 문제를 푸는 파이썬 확장인데, 후보 범위를 절반씩 접는
  대신 **다른 탐색 절차**를 씁니다. 주석이 *"Interface for the SMAWK algorithm, for
  finding the minimum value in each row of an implicitly-defined totally monotone matrix."*
  라 적고, 알고리즘의 출처를 *"Algorithm as presented in section 2.2 of (Gronlund et al.,
  2017)."* 로 밝혀요. 같은 성질(완전 단조)을 쓰면서 탐색 방법만 갈리는 자리입니다.
  ([`kmeans1d/kmeans1d/_core.cpp`](https://github.com/dstein64/kmeans1d/blob/master/kmeans1d/_core.cpp),
  조회 2026-09-05)

```text
두 구현이 이 글과 갈리는 자리

  이 글        가운데 칸을 확정하고 좌우로 재귀한다     계층 하나가 n log n 이라고 이 글이 쟀다
  Ckmeans      같은 절차를 C++ 로 적었다                 파일 첫 줄 주석이 O(n lg n) 이라 적는다
  kmeans1d     SMAWK 로 행마다 최솟값 자리를 찾는다      복잡도를 소스가 적어 두지 않았다

셋 다 「행마다 최솟값의 자리가 뒤로만 간다」 를 전제로 쓰고, 그 자리를 찾는 방법에서 갈린다
SMAWK 가 로그 인자를 없앤다는 것은 이 글이 1 차 출처로 확인하지 못했다
```

**「분할 정복 최적화가 실무에서 널리 쓰인다」 를 1 차 출처로 확인하지 못했습니다.** 확인한 것은
위 두 구현 하나씩이고, 둘 다 1 차원 군집 문제입니다. 그 밖의 도입 사례는 이 글이 확인하지
못했어요.

#### 경쟁 설계와의 대조

같은 목표(연속 구간 `k` 분할의 최소 비용)를 노리는 다른 절차로 **후보 범위를 안 좁히고 분할점을
전부 검사하는 설계**가 있습니다. 재귀도 `opt` 기록도 없이 칸마다 `j` 를 `0` 부터 `i-1` 까지
넣어 보는 방식이에요.

```text
두 설계가 한 계층에서 하는 일
  이 가이드의 절차  가운데 칸부터 확정하고 좌우 범위를 접는다  호출 값을 치르고 검사를 줄인다
  전부 검사하는 설계  칸을 왼쪽부터 차례로 채운다              호출이 없고 검사가 n^2/2 다

앞은 「검사 하나를 줄이려고 호출 하나를 치른다」 이고, 뒤는 그 거래를 하지 않는다
```

같은 입력·같은 작업에 두 설계를 세우고 **기본 연산 수**(분할점 후보 하나를 검사한 한 번 ·
`solve` 를 한 번 부른 것 · 칸 하나를 처리하려고 바깥 반복에 들어간 한 번)를 셌습니다. 배열은
`a[i] = (i * 7 % 5) + 1` 이고 비용은 구간 합의 제곱, 구역 수는 `k = 3` 으로 고정하고 거점 수만
바꿨어요. **전개 입력을 그대로 쓰지 않은 이유**는 거점이 넷이라 두 계수의 순서가 갈리는 자리를
보일 수 없기 때문이고, 전개 입력의 값도 표 첫 줄에 남깁니다.

| 입력 | 이 가이드의 절차 | 후보 범위를 안 좁히는 설계 | 어느 쪽이 적은가 |
| --- | --- | --- | --- |
| 전개 입력 (거점 4 · `k = 3`) | 28 | **20** | 전부 검사가 적습니다 |
| 거점 8 개 | 73 | **72** | 전부 검사가 근소하게 적습니다 |
| 거점 9 개 | **84** | 90 | **여기서 순서가 뒤집힙니다** |
| 거점 500 개 | **10,864** | 250,500 | 이 절차가 23 배 적습니다 |

**저장 칸도 이 절차가 더 씁니다.** 거점 500 개에서 1,010 개 대 1,000 개인데, 늘어난 10 칸이
재귀가 가장 깊었을 때의 호출 틀 수예요. 계층 배열 두 줄은 두 설계가 같고, 비용 행렬
`n x n` 은 입력이라 두 설계 모두에서 세지 않았습니다.

```text
경계가 그 자리인 이유 — 거점을 하나 더할 때 두 설계가 늘어나는 값

  거점 8 -> 9 로 늘렸을 때 계층 둘의 값 (k = 3)

  이 절차     후보 검사  39 -> 46 (+7)    호출  34 -> 38 (+4)    합 73 -> 84 (+11)
  전부 검사   후보 검사  56 -> 72 (+16)   바깥 반복  16 -> 18 (+2)   합 72 -> 90 (+18)

  전부 검사 쪽은 셈이 딱 떨어진다 — 칸 하나(번호 8)가 늘면 계층 하나당 후보 8 개와
  바깥 반복 1 번이 늘고, 계층이 둘이니 (8+1) x 2 = 18 이다
  이 절차 쪽은 호출이 계층마다 둘씩 늘어 +4 이고 검사는 깊이 수 언저리만 늘어 +7 이다
  거점 500 에서는 10,864 대 250,500 이다
```

**두 설계의 답은 같지만 쓸 수 있는 조건이 갈립니다.** 전부 검사하는 설계는 후보를 하나도
빼지 않으므로 사각 부등식이 필요 없고, 그래서 **어떤 비용 행렬에서도** 최솟값을 냅니다. 이 절차는 그 조건이 성립할 때만 맞아요 —
앞에서 본 반례에서 이 절차가 8 을 냈고 전부 검사한 쪽이 6 을 냈습니다. 그러니 이 절차가 내주는
것은 저장 칸 10 개와 **일반성**이고, 얻는 것이 거점이 커질 때의 계수입니다.

```text
어느 조건에서 어느 쪽인가

  거점이 8 개 이하다                   전부 검사가 적다 (72 대 73)
  거점이 9 개 이상이다                 이 절차가 적다 (84 대 90)
  사각 부등식을 보장받지 못했다        전부 검사만 맞는 답을 낸다
  거점이 500 개다                      이 절차가 10,864 · 전부 검사가 250,500

문제가 사각 부등식을 보장하지 않으면 거점이 아무리 커도 이 절차를 고를 수 없다
```

### 수식 정의와 유도

구간 `[0, i]` 를 정확히 `g` 개의 연속 구역으로 나눈 최소 비용을 $dp[g][i]$ 라 하고, 마지막
구역이 시작하기 직전 거점을 $j$ 라 씁니다. 마지막 구역은 $[j+1, i]$ 이고 그 앞은 $[0, j]$ 를
$g-1$ 개로 나눈 문제이므로 점화식이 이렇게 됩니다.

$$dp[1][i] = cost[0][i], \qquad dp[g][i] = \min_{g-2 \le j < i} \bigl( dp[g-1][j] + cost[j+1][i] \bigr)$$

```text
점화식이 자르는 자리

  0 ───────────────── j │ j+1 ───────── i
  └── g-1 개 구역으로 ──┘ │ └ 마지막 구역 ┘
        dp[g-1][j]              cost[j+1][i]

  j 를 하나 고르는 것이 마지막 구역의 왼쪽 끝을 하나 고르는 것이다
  j 의 아래 끝이 g-2 인 것은 앞을 g-1 개로 나누려면 거점이 g-1 개는 있어야 하기 때문이다
```

그 최솟값을 만드는 $j$ 를 $\operatorname{opt}(g, i)$ 로 씁니다. 최솟값이 여럿이면 가장 작은
$j$ 를 고릅니다.

$$\operatorname{opt}(g, i) \;=\; \min \Bigl\{\, j \;:\; dp[g-1][j] + cost[j+1][i] = dp[g][i] \,\Bigr\}$$

```text
정의를 전개 입력의 칸 하나에 넣어 봅니다 — 계층 2 의 칸 3

  j = 1   dp[1][1] + cost[2][3] =  9 + 49 = 58
  j = 2   dp[1][2] + cost[3][3] = 36 + 16 = 52   <- 최솟값

  dp[2][3] = 52 이고 opt(2, 3) = 2 다
```

두 정의가 계층 하나를 통째로 만드는지 값으로 확인합니다. 후보 범위를 좁힌 절차와 후보를 전부
검사한 절차가 같은 표를 만드는지가 이 검산의 내용이에요.
<!--proof:mathCheck-->

```text
       분할 정복           후보를 전부 검사    판정
dp[1]  [1, 9, 36, 100]     [1, 9, 36, 100]     같다
dp[2]  [INF, 5, 18, 52]    [INF, 5, 18, 52]    같다
dp[3]  [INF, INF, 14, 34]  [INF, INF, 14, 34]  같다

계층마다의 후보 검사  계층 2: 5 · 계층 3: 5
합계 10 · 전부 검사하면 12
```

세 계층이 칸 하나까지 같습니다. 이제 **왜 범위를 좁혀도 같은 표가 나오는지**를 식으로
유도합니다. 사각 부등식은 $a \le b \le c \le d$ 인 지표 넷에 대한 조건이에요.

$$cost[a][c] + cost[b][d] \;\le\; cost[a][d] + cost[b][c]$$

```text
지표 넷이 만드는 구간 넷

  a ──── b ──── c ──── d

  왼쪽 항   cost[a][c] + cost[b][d]   두 구간이 겹치되 어느 쪽도 다른 쪽을 품지 않는다
  오른쪽 항  cost[a][d] + cost[b][c]   한쪽이 다른 쪽을 통째로 품는다

  품는 쪽으로 몰아 담을수록 비용 합이 커지거나 그대로다 — 그것이 이 부등식이다
```

$j_1 < j_2$ 이고 $i_1 < i_2$ 라 두고, 칸 $i_1$ 에서 $j_2$ 가 $j_1$ 보다 작거나 같은 값을 만들었다고
합시다. 즉 $dp[g-1][j_2] + cost[j_2+1][i_1] \le dp[g-1][j_1] + cost[j_1+1][i_1]$ 입니다.
$j_1 + 1 \le j_2 + 1 \le i_1 \le i_2$ 순서에 사각 부등식을 그대로 넣으면 다음이 나옵니다.

$$cost[j_1+1][i_1] + cost[j_2+1][i_2] \;\le\; cost[j_1+1][i_2] + cost[j_2+1][i_1]$$

```text
유도가 말하는 것을 한 줄씩

  전제      i1 에서  dp[g-1][j2] + cost[j2+1][i1] ≤ dp[g-1][j1] + cost[j1+1][i1]
  사각 부등식  cost[j2+1][i2] - cost[j2+1][i1] ≤ cost[j1+1][i2] - cost[j1+1][i1]
  두 줄을 더하면
            i2 에서  dp[g-1][j2] + cost[j2+1][i2] ≤ dp[g-1][j1] + cost[j1+1][i2]

  「i1 에서 뒤쪽이 앞섰으면 i2 에서도 앞선다」 -> 최적 분할점이 앞으로 되돌아갈 수 없다
```

양변을 옮겨 적으면 $cost[j_2+1][i_2] - cost[j_2+1][i_1] \le cost[j_1+1][i_2] - cost[j_1+1][i_1]$
이고, 이것은 **$i$ 를 $i_1$ 에서 $i_2$ 로 늘릴 때 뒤쪽 분할점 $j_2$ 의 비용이 앞쪽 분할점 $j_1$ 의
비용보다 덜 커진다**는 뜻이에요. 그래서 $i_1$ 에서 이미 작거나 같았던 $j_2$ 는 $i_2$ 에서도
작거나 같고, 이것을 정리하면 $\operatorname{opt}(g, i_1) \le \operatorname{opt}(g, i_2)$ 입니다.

단조성이 있으면 후보 범위를 접을 수 있고, 그때 검사가 몇 번인지를 닫힌 형태로 냅니다. 깊이
$d$ 에 놓인 호출들이 넘겨받는 범위 $[optLo, optHi]$ 는 **끝점만 겹치므로** 길이의 합이
$n + 2^d$ 를 넘지 않고, 깊이는 0 부터 세어 층수가 $\lceil \log_2 (n+1) \rceil$ 을 넘지 않아요.
앞의 두 주장을 값으로 확인합니다.

```text
   256       5                281      288  넘지 않는다
   256       6                315      320  넘지 않는다
   256       7                380      384  넘지 않는다
   256       8                129      512  넘지 않는다

계층 하나의 상한 n ceil(log2(n+1)) + 2n 은 거점 16 에서 112 · 64 에서 576 · 256 에서 2,816 이다
```

깊이마다의 합을 전부 더하면 상한이 닫힙니다. 층수를 $L = \lceil \log_2 (n+1) \rceil$ 이라 하면
$n$ 이 $L$ 번 더해지고, $2^d$ 를 $d = 0$ 부터 $L-1$ 까지 더한 값이 $2^L - 1 \le 2n$ 이므로 계층
하나의 후보 검사가 다음을 넘지 않아요.

$$\text{계층 하나의 후보 검사} \;\le\; n \lceil \log_2 (n+1) \rceil + 2n, \qquad \text{전체} \;\le\; (k-1)\bigl( n \lceil \log_2 (n+1) \rceil + 2n \bigr)$$

```ts
// 식을 그대로 옮긴 조각. 코드에서는 `n` 이 거점 수이고 `k` 가 구역 수다.
const layerBound = (n: number): number =>
  n * Math.ceil(Math.log2(n + 1)) + 2 * n;
const total = (n: number, k: number): number => (k - 1) * layerBound(n);
```

식에 제약 규모를 넣어 수치를 냅니다.

<!--proof:mathScale-->

```text
거점 n  계층 하나의 후보 검사  n ceil(log2(n+1)) + 2n  그 비
    50                    281                     400  0.703
   100                    671                     900  0.746
   200                  1,554                   2,000  0.777
   500                  4,476                   5,500  0.814

제약 상한에서
  후보 검사의 상한  (k-1) [n ceil(log2(n+1)) + 2n] = 2,744,500 번
  전부 검사하면     (k-1) n (n-1) / 2 = 62,250,250 번
```

**여기서 본문의 값만으로는 안 나오는 것이 나옵니다.** 전개 입력은 후보 검사가 10 번인 한
벌짜리 값이고 앞의 실측은 거점 500 까지인데, 위 유도는 **임의의 `n` 과 `k` 에 대해** 검사가
`(k-1)(n ceil(log2(n+1)) + 2n)` 를 넘지 않는다는 닫힌 형태를 줍니다. 제약 상한에서 그 값이
274 만 번이고 전부 검사하는 쪽의 6,225 만 번보다 22 배 적어요.

### 불변식 — 넘긴 후보 범위 안에 진짜 최적 분할점이 있다

파트 1 의 열두 걸음은 입력 하나에서 답이 나왔다는 기록입니다. 그 하나로는 다른 입력에서도 같은
일이 일어난다는 근거가 안 되므로, **호출이 몇 번 실행되든 참으로 남는 문장**을 세우고 그것이
유지되는지를 값으로 확인합니다.

> `solve(lo, hi, optLo, optHi)` 를 부르는 시점마다 둘이 참입니다. **앞 문장** — `prev` 는 계층
> `g-1` 의 값을 담고 있고 이번 계층이 그것을 고치지 않습니다. **뒤 문장** — `lo ≤ i ≤ hi` 인
> 모든 칸 `i` 의 진짜 최적 분할점 `opt(g, i)` 가 `[optLo, optHi]` 안에 있습니다.

```text
  앞 문장이 뜻하는 것   후보 값 prev[j] + cost[j+1][mid] 가 계층 g-1 의 값으로 만들어진다
  뒤 문장이 뜻하는 것   잘라 낸 후보 중에 답이 없다

  뒤 문장의 대우가 이 절차의 정확성이다
  범위 밖에 답이 없다 -> 범위 안의 최솟값이 그 칸의 답이다 -> 계층 g 가 통째로 맞다

  거기서 답까지 한 걸음이 더 있다
  계층 1 이 맞고 계층 g-1 이 맞으면 계층 g 도 맞다 -> 계층 k 의 마지막 칸이 답이다
```

문장을 둘로 나눈 이유가 있어요. 앞 문장은 후보 값이 **무엇으로 만들어지는가**를 정하고, 뒤
문장은 그 후보 중에 **답이 들어 있는가**를 정합니다. 둘이 함께 있어야 「범위 안의 최솟값이 그
칸의 답이다」 가 나와요.

**첫 호출에 들어가기 전부터 봅시다.** 계층 `g` 의 첫 호출은 `solve(0, n-1, 0, n-2)` 이고, 그
시점에 `prev` 는 계층 `g-1` 을 다 채운 배열이며 `cur` 는 전부 `INF` 인 새 배열입니다. 분할점은
`0` 이상 `n-2` 이하여야 하므로 — `j+1 ≤ n-1` 이 필요합니다 — 넘긴 범위가 가능한 분할점 전부라
뒤 문장이 참이에요.

| 갈래 | 하는 일 | 앞 문장이 유지되는 근거 | 뒤 문장이 유지되는 근거 |
| --- | --- | --- | --- |
| 계층 배열을 만든다 | `cur` 를 `INF` 로 채운다 | `prev` 를 안 건드린다 | 아직 아무 범위도 안 넘겼다 |
| 빈 범위에서 반환한다 | 아무것도 안 한다 | `prev` 를 안 건드린다 | 담당할 칸이 없다 |
| 후보를 검사한다 | `prev[j] + cost[j+1][mid]` 를 만든다 | `prev` 를 읽기만 한다 | 넘겨받은 범위를 그대로 쓴다 |
| 칸을 확정한다 | `cur[mid]` 에 최솟값을 적는다 | `cur` 는 `prev` 와 다른 배열이다 | `mid` 의 답이 정해진다 |
| 왼쪽으로 재귀한다 | `[optLo, bestOpt]` 를 넘긴다 | `prev` 를 안 건드린다 | 단조성이 `opt(g, i) ≤ bestOpt` 를 준다 |
| 오른쪽으로 재귀한다 | `[bestOpt, optHi]` 를 넘긴다 | `prev` 를 안 건드린다 | 단조성이 `opt(g, i) ≥ bestOpt` 를 준다 |
| 계층을 교체한다 | `prev = cur` | 다음 계층의 `prev` 가 이번 계층이 된다 | 다음 계층의 첫 호출이 범위를 새로 연다 |

「왼쪽으로 재귀한다」 줄이 이 논증에서 가장 좁은 자리예요. `bestOpt` 는 **넘겨받은 범위 안에서**
찾은 최솟값의 자리이지 `mid` 의 진짜 최적 분할점이라는 보장이 따로 있는 것이 아닙니다. 그런데
뒤 문장이 「`mid` 의 진짜 최적 분할점이 범위 안에 있다」 를 이미 주고, 상한 자르기가 그 범위를
`min(optHi, mid - 1)` 로 줄여도 진짜 값은 `mid` 보다 앞이라 그대로 남아요. 그래서 검사한 범위
안의 최솟값이 곧 진짜 최솟값입니다. 식의 `opt(g, mid)` 가 코드에서는 `bestOpt` 이고, 둘이 같은
값이 되는 것이 이 문단의 결론이에요.

<!--proof:invariantWatch-->

```text
호출               계층  mid  진짜 opt  넘긴 범위  불변식
solve(0, 3, 0, 2)     2    1         0  [0, 2]     지킨다
solve(0, 0, 0, 0)     2    0      없음  [0, 0]     지킨다
solve(2, 3, 0, 2)     2    2         1  [0, 2]     지킨다
solve(3, 3, 1, 2)     2    3         2  [1, 2]     지킨다
solve(0, 3, 0, 2)     3    1      없음  [0, 2]     지킨다
solve(0, 0, 0, 0)     3    0      없음  [0, 0]     지킨다
solve(2, 3, 0, 2)     3    2         1  [0, 2]     지킨다
solve(3, 3, 1, 2)     3    3         2  [1, 2]     지킨다
```

**여덟 호출 모두 진짜 최적 분할점이 넘긴 범위 안에 있습니다.** 「진짜 opt」 열은 후보를 전부
검사해서 따로 구한 값이에요. 계층 2 의 `solve(3, 3, 1, 2)` 줄을 봐 주세요 — 범위가 `[1, 2]` 로
좁아졌는데 진짜 값이 2 라 안에 들어 있습니다. 경계 입력에서도 같은 문장이 유지되는지 봅시다.

<!--proof:invariantEdges-->

```text
입력                   n  k     반환값  후보 검사  호출
거점 하나, 구역 하나   1  1         49          0     0
구역이 하나            4  1        100          0     0
구역이 거점 수와 같다  4  4         30         16    27
값이 모두 같은 배열    5  3          9         17    22
앞이 큰 배열           5  2  1,000,016         10    11
비용이 전부 0          4  2          0          6     9
```

**`k = 1` 이면 계층 반복이 한 번도 실행되지 않습니다.** 기저 계층을 채운 `prev` 를 그대로
반환하므로 후보 검사가 0 번이고 호출도 0 번이에요. 「거점 하나, 구역 하나」 줄은 배열 `[7]` 의
구간 합 제곱이라 `cost[0][0] = 49` 이고, 「앞이 큰 배열」 줄은 `[1000, 1, 1, 1, 1]` 을 두
구역으로 나눈 값 `1000^2 + 4^2` 입니다. 비용이 전부 0 이면 어떤 분할이든 0 이라 답도 0 이에요.

**이제 그 줄을 망가뜨려 봅시다.** 앞 문장을 떠받치는 자리는 계층 끝의 `prev = cur` 한 줄입니다.
「어차피 `cur` 를 계층마다 새로 만드는데 굳이 바꿔 넣어야 하나」 라는 생각으로 그 줄만 빼 봅니다.

```ts
    solve(0, n - 1, 0, n - 2);
    // prev = cur 가 있던 자리를 비웠다
  }
```

<!--proof:mutantNoRoll-->

```text
입력                 k  정본  계층을 안 바꾼 판  판정
전개 입력            3    34                100  다르다
값이 모두 같은 배열  3     9                 25  다르다
다른 비용 행렬       2     3                  8  다르다
```

세 입력에서 모두 답이 갈립니다. 전개 입력에서 100 이 나오는데, 이것은 `dp[1][3]` 즉 거점 넷을
한 구역으로 묶은 값이에요. `prev` 가 계층 1 에 머물러 있으니 계층 2 도 계층 3 도 계층 1 을
읽었고, 마지막에 반환한 것도 계층 1 이라 구역을 하나도 안 나눈 값이 나옵니다.

```text
앞 문장이 어디서 깨지는가

  계층 2 를 채운 직후   prev 는 여전히 [1, 9, 36, 100] 이다 (계층 1)
                        계층 3 이 읽어야 할 것은 [INF, 5, 18, 52] 인데 그것이 아니다
                        cur 에 적은 값은 아무도 안 읽고 버려진다

  범위를 좁히는 규칙 자체는 안 건드렸다. 그런데 그 규칙이 쓰는 bestOpt 가 계층 g-1 이 아닌
  표에서 나온 자리라, 뒤 문장이 말하는 「진짜 최적 분할점」과 이어지지 않는다
  앞 문장이 깨지면 뒤 문장이 기대는 근거도 함께 사라진다
```

### 비용 계산

#### 비용을 세는 과정

한 번의 실행이 하는 일은 셋입니다. 기저 계층을 채우는 것, 계층마다 배열을 하나 만드는 것,
그리고 `solve` 를 부르며 후보를 검사하는 것이에요. 전개의 열두 걸음에서 그 셋을 셉니다.

<!--proof:perfCount-->

```text
걸음  확정한 칸  후보 범위  이 걸음의 검사  누적
T1    -          -                       0     0
T2    mid = 1    [0, 0]                  1     1
T3    mid = 0    [0, -1]                 0     1
T4    mid = 2    [0, 1]                  2     3
T5    mid = 3    [1, 2]                  2     5
T6    -          -                       0     5
T7    mid = 1    [0, 0]                  1     6
T8    mid = 0    [0, -1]                 0     6

T11   -          -                       0    10
T12   -          -                       0    10

비지 않은 호출 8 번 · 빈 호출 10 번 · 후보 검사 10 번
```

걸음마다 검사 수가 다르다는 것을 봐 주세요. **후보 범위의 길이가 0 부터 2 까지 갈립니다.**
T3 과 T8 은 `mid = 0` 이라 상한이 `-1` 이 되어 한 번도 검사하지 않았고, T4 와 T5 는 둘씩
검사했어요. T1 · T6 · T11 · T12 는 후보를 검사하는 걸음이 아닙니다.

```text
총식 = 기저 계층 + 계층 배열 만들기 + 호출 수 + 후보 검사

  기저 계층        n              cost[0][i] 를 한 번씩 옮긴다
  계층 배열        (k-1) n        계층마다 n 칸을 INF 로 채운다
  호출 수          (k-1)(2n+1)    계층마다 비지 않은 호출 n 개와 빈 호출 n+1 개
  후보 검사 C      계층마다 n log n 언저리

  합               n + (k-1)(3n + 1) + C

  n = 4, k = 3 이면    4 + 2 x 13 + 10 = 40
  C 의 상한을 넣으면   n + (k-1)(3n+1) + (k-1)(n ceil(log2(n+1)) + 2n)
```

**여기서 센 것은 후보 검사와 호출 전부입니다.** 배열 칸을 읽고 쓰는 횟수와 반복 변수를 올리는
횟수는 세지 않았어요 — 둘 다 위 값에 비례하므로 총식의 차수가 그대로입니다.

#### 케이스별 비용과 그 경계

어떤 입력인가를 말하는 **케이스**와 어떤 종류의 값인가를 말하는 **경계**는 축이 다릅니다.
한 축의 이름을 다른 축에 붙이면 두 정보가 함께 사라져요.

| | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **최선의 경우** (`k = 1`) | `O(k n log n)` | `Θ(n)` — 기저 계층만 채우고 끝난다 |
| **평균적인 경우** (입력 분포를 정의하지 않는다) | `O(k n log n)` | 정의하지 않는다 |
| **최악의 경우** (`k ≥ 2` — 비용 행렬이 무엇이든) | `O(k n log n)` | `Θ(k n log n)` — 아래에서 잰 무리가 상한의 0.8 배에 이른다 |

평균을 정의하지 않는 이유는 **입력 분포를 문제가 주지 않기** 때문입니다. 이 절차에는 난수가
하나도 없어서 무작위성이 구현에서 나오지도 않아요. 그래서 「평균」이라는 말을 쓰려면 어떤 비용
행렬 무리를 어떤 확률로 뽑는지를 먼저 정해야 하는데, 그런 정의가 문제에 없습니다.

```text
상한과 타이트한 값을 가르는 자리
  O(k n log n)      후보 검사가 그보다 크지 않다는 것만 말한다        상한이다
  Theta(n)          k = 1 이면 기저 계층 n 칸이 전부다                타이트한 값이다

이 절차는 최선과 최악의 차이가 작다. k ≥ 2 이면 첫 호출 하나가 이미 floor((n-1)/2) 번을
검사하고 — 거점 256 에서 127 번이다 — 그 아래로는 어떤 비용 행렬에서도 내려가지 않는다
아래가 그 폭을 실제로 잰 것이다
```

<!--proof:perfObserved-->

```text
배열                 거점 n  후보 검사  계층 하나 / n  전부 검사하면
값이 모두 같은 배열     128      1,843           7.35         16,256
값이 모두 같은 배열     512      9,512           9.45        261,632
생성식 배열             128      1,838           7.35         16,256
생성식 배열             512      9,506           9.45        261,632
앞이 큰 배열            128      1,948           7.88         16,256
앞이 큰 배열            512      9,938           9.96        261,632
```

**「계층 하나 / n」 열이 거점 128 에서 7.35~7.88, 거점 512 에서 9.45~9.96 입니다.** 앞은
`log2 128 = 7` 이고 뒤는 `log2 512 = 9` 예요 — 배열 모양을 바꿔도 그 값이 `log2 n` 근처에
머무릅니다. 전부 검사하는 쪽은 같은 규모에서 16,256 과 261,632 로 `n^2/2` 를 따라 커져요.

```text
「관측」과 「보장」을 가르는 문장

  관측  세 배열 모양에서 계층 하나의 검사가 n 의 7.35~9.96 배였다
  보장  어떤 비용 행렬에서도 계층 하나의 검사가 n ceil(log2(n+1)) + 2n 를 넘지 않는다

  앞엣것은 배열을 바꾸면 값이 바뀐다. 뒤엣것은 안 바뀐다
  위의 상한은 전부 최악 보장이다 — 기댓값이 아니라 상한이고, 입력 분포를 쓰지 않는다
```

#### 최악을 만드는 입력

연산 수를 최대로 만들려면 후보 범위가 최대한 안 좁아져야 합니다. 그런데 이 절차는 범위를 좁히는
규칙이 **입력의 값이 아니라 최적 분할점의 배치**에만 달려 있어요. 배치를 바꿔 가며 재 봅시다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 계층을 `2` 부터 `k` 까지 되풀이하되, 계층마다
가운데 칸의 최적 분할점을 먼저 찾고 그 자리를 왼쪽 절반의 상한과 오른쪽 절반의 하한으로 넘겨
후보 범위를 접습니다. 접어도 되는 근거는 「사각 부등식이 성립하면 최적 분할점이 뒤로만 간다」
이고, 비용의 상한은 `(k-1)(n ceil(log2(n+1)) + 2n)` 이에요.

```text
1.  dp[1][i] = cost[0][i] 로 기저 계층을 채운다
2.  계층 g 마다 새 배열을 만들고 solve(0, n-1, 0, n-2) 를 부른다
3.  범위가 비면 반환하고, 아니면 mid 의 후보를 [optLo, min(optHi, mid-1)] 에서 검사한다
4.  최솟값과 그 자리 bestOpt 를 기록하고 좌우로 재귀한다
5.  계층이 끝나면 prev = cur 로 바꾼다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T5 는 `dp[2][3] = 52` 를 확정하면서 `j = 0` 을 한 번도
검사하지 않았어요. `j = 0` 이 진짜 답이 아니라는 것을 이 절차는 어떻게 알았을까요?

```text
T4 의 결과   mid = 2 · 후보 [0, 1] · bestOpt = 1
T5 의 범위   mid = 3 · 후보 [1, 2]  <- 하한이 0 이 아니라 1 이다
```

<!--check:whyLowerBoundIsSafe-->
**T4 가 알아낸 `opt(2, 2) = 1` 과 단조성 때문입니다.** 칸 3 은 칸 2 보다 뒤에 있으므로
`opt(2, 3) ≥ opt(2, 2) = 1` 이고, 그러면 `j = 0` 은 칸 3 의 최적 분할점일 수 없어요. 검사하지
않은 것이 아니라 **검사할 필요가 없다는 것이 이미 정해진** 것입니다.

```text
j = 0 을 실제로 넣어 보면
  j = 0   dp[1][0] + cost[1][3] =  1 + 81 = 82
  j = 1   dp[1][1] + cost[2][3] =  9 + 49 = 58
  j = 2   dp[1][2] + cost[3][3] = 36 + 16 = 52   <- 확정한 값

82 가 58 보다 크다. 단조성이 없으면 이 82 가 최솟값일 수도 있고, 그때 이 절차는 답을 놓친다
```

그 「그때」 가 「사각 부등식이 깨지면 이 절차는 최솟값을 놓친다」 절에서 본 반례예요. 거기서는
`opt(2, i)` 가 `0 1 0` 으로 되돌아갔고, 절차가 8 을 냈지만 정답이 6 이었습니다.
