# N-Queens — 충돌이 확정된 행에서 멈추면 그 아래 배치를 하나도 만들지 않는다

## 파트 1 — 아이디어에서 동작하는 코드까지

이 파트에서는 전체 그림을 먼저 보고, 그 그림을 읽는 데 필요한 지식을 확인합니다. 그다음 판의 칸을
아무렇게나 고르는 방법에서 출발해 충돌이 확정된 자리에서 멈추는 방법까지 가고, 그 방법을 단계마다 값으로
푼 뒤, 실제로 동작하는 코드를 한 조각씩 만듭니다.

### 전체 컨셉

퀸은 같은 행 · 같은 열 · 같은 대각선에 있는 칸을 거리와 상관없이 공격합니다. 4×4 판의 (1,2) 에 퀸
하나를 놓으면 공격받는 칸은 이렇습니다. 칸의 글자가 그 칸을 공격하는 방향이에요. `\` 는 왼쪽 위에서
오른쪽 아래로 가는 대각선이고, `/` 는 오른쪽 위에서 왼쪽 아래로 가는 대각선입니다.

<!--fig:concept-attack-->
![(1,2) 에 놓은 퀸이 공격하는 칸](./figs/concept-attack.svg)

N-Queens 는 `n × n` 판에 퀸 `n` 개를 어느 두 퀸도 서로 공격하지 않게 놓는 **배치**가 몇 개인지 세는
과제입니다. 같은 행에 퀸 둘이 있으면 무조건 공격이니, 퀸 `n` 개를 `n` 행에 놓으려면 **행마다 정확히
하나**예요. 그래서 배치 하나는 「행마다 어느 열인가」를 적은 목록 하나로 적을 수 있습니다. `n = 4` 의
배치는 둘입니다.

<!--fig:concept-solutions-->
![n = 4 의 배치 두 개](./figs/concept-solutions.svg)

목록을 행 0 부터 한 행씩 채워 가는 도중의 상태, 곧 앞의 몇 행만 채운 목록을 **부분 배치**라고
부르겠습니다. 부분 배치에서 한 행을 더 채운 것을 자식으로 이으면 나무가 하나 생기는데, 이것을 **상태
공간 트리**라고 해요. 뿌리는 빈 판이고, 깊이 `k` 의 마디는 `k` 행을 채운 부분 배치입니다. 이 글의
절차가 `n = 4` 에서 실제로 만든 나무는 이렇습니다. 마디 이름은 마지막에 놓은 퀸이고, 굵은 테 마디가
완성 배치, 대시 마디는 다음 행의 어느 열에도 놓을 수 없어 더 내려가지 못한 부분 배치예요.

<!--fig:concept-tree-->
![n = 4 의 부분 배치 나무](./figs/concept-tree.svg)

이 절차의 요점은 **충돌이 확정된 부분 배치의 아래를 만들지 않는 것**입니다. 행 0 과 행 1 만 채워도 두
퀸이 부딪히는지는 그 자리에서 알 수 있고, 이미 부딪힌 부분 배치 아래에 무엇을 채워도 배치가 되지
않아요. 순열을 끝까지 만든 뒤 검사하는 방식과 한 행을 채울 때마다 검사하는 방식이 만든 부분 배치 수를
세면 이렇습니다.

<!--proof:concept-count-->

| n | 순열을 끝까지 만든 뒤 검사 | 한 행을 채울 때마다 검사 |
| ---: | ---: | ---: |
| 4 | 65 | 17 |
| 6 | 1,957 | 153 |
| 8 | 109,601 | 2,057 |

한 행마다 검사하려면 이미 놓인 퀸들이 쓴 **열**과 두 방향의 **대각선**을 기억해 두면 됩니다. 이 글은 그
셋을 정수 세 개의 비트에 담아, 확인도 표시도 연산 한 번으로 끝냅니다. 만드는 부분 배치의 수는 `n` 에
따라 빠르게 늘고, 비용을 결과만 적으면 상한이 `O(n · n!)` 이에요.

### 시작하기 전에 — 이미 알고 있어야 하는 것

- **재귀 호출**이 자기와 같은 모양의 더 작은 과제를 푼다는 것. 여기서는 「행 `row` 부터 `n−1` 까지
  채운다」가 그 작은 과제예요.
- **상태 공간 트리와 되돌리기** — 부분 해를 마디로 둔 나무를 깊이 우선으로 찾아가며, 들어갈 때 켠
  표시를 나올 때 지우는 절차입니다. [모든 경로 나열 가이드](../../graph/dfsAllPaths/dfsAllPaths-guide.md)의
  「먼저 알아 둘 개념 — 상태 공간 트리」가 그 나무를 처음부터 설명합니다. 이 글은 같은 나무를 판 위의 부분
  배치로 그리고, 되돌리기가 판을 되돌리는 모습을 값으로 다시 보입니다.
- **비트 연산 다섯** — `1 << k`(`k` 번 비트만 켠 값), `|`(켜기), `^`(같은 비트를 다시 끄기),
  `>>`(자리 옮겨 읽기), `& 1`(맨 아래 비트 하나 읽기). 이 저장소에 따로 된 가이드가 없어서 여기서 쓰는
  만큼은 본문에서 다시 설명합니다.
- **순열과 조합의 수** — `n` 개 중 `k` 개를 고르는 방법이 `C(n, k)` 가지이고, `n` 개를 줄 세우는
  방법이 `n!` 가지라는 것.

두 번째와 세 번째가 흐릿해도 읽는 데 지장은 없습니다. 네 번째가 흐릿하면 「단순한 방법이 왜 안 되는가」를
수치로 확인하는 자리에서 막혀요.

### 아이디어를 떠올리는 과정 — 칸 n 개 고르기에서 가지치기까지

아이디어를 찾기 전에 무엇을 만들어야 하는지부터 정해 둡시다. 함수 하나가 판의 한 변 길이를 받아 배치의
수를 돌려줍니다.

```ts
function nQueens(n: number): number;
```

- 입력: 판의 한 변 길이 `n`. 놓을 퀸의 수도 `n` 입니다.
- 출력: `n × n` 판에 퀸 `n` 개를 어느 두 퀸도 서로 공격하지 않게 놓는 **배치의 수**. 배치 자체가 아니라
  개수만 돌려줍니다.
- 규모: `n` 은 1 이상 12 이하입니다. 비용은 흔한 채점 환경의 예산인 1 초(단순 연산 1 초에 1 억 번)에
  대어 잽니다.

이 글이 쓰는 기호는 일곱이에요. 여기서 정하고 끝까지 같은 뜻으로 씁니다.

| 기호 | 무엇인가 | 이 과제에서 |
| --- | --- | --- |
| `n` | 판의 한 변 길이이자 놓을 퀸의 수 | `1 ≤ n ≤ 12` |
| `row` | 지금 채우는 행 번호 | `0 ≤ row ≤ n` |
| `c` | 그 행에서 시도하는 열 번호 | `0 ≤ c ≤ n − 1` |
| `d1` | 칸 `(row, c)` 가 놓인 `\` 대각선의 번호 `row − c + (n − 1)` | `0 ≤ d1 ≤ 2n − 2` |
| `d2` | 칸 `(row, c)` 가 놓인 `/` 대각선의 번호 `row + c` | `0 ≤ d2 ≤ 2n − 2` |
| `cols` · `diag1` · `diag2` | 이미 쓴 열 · `\` 대각선 · `/` 대각선을 비트로 담은 정수 셋 | 비트마다 0 또는 1 |
| `count` | 지금까지 센 배치의 수 | 0 이상 |

가장 먼저 떠오르는 방법은 과제를 글자 그대로 읽는 것입니다. 「`n²` 칸 중에서 `n` 칸을 고르는 조합을
모두 만들고, 그중 어느 두 퀸도 공격하지 않는 것을 센다」예요. 고르는 방법은 `C(n², n)` 가지이고, 한
벌마다 퀸 쌍 `C(n, 2)` 개를 대조해야 합니다.

<!--proof:origin-naive-->

| n | 고르는 방법 C(n², n) | 퀸 쌍 대조 횟수 | 초당 1 억 번 기준 |
| ---: | ---: | ---: | ---: |
| 4 | 1,820 | 10,920 | 0.0001 초 |
| 6 | 1,947,792 | 29,216,880 | 0.2922 초 |
| 8 | 4,426,165,368 | 123,932,630,304 | 21 분 |
| 12 | 103,619,293,824,707,388 | 6,838,873,392,430,687,608 | 2,169 년 |

`n = 12` 에서 퀸 쌍 대조가 683 경 번을 넘고, 초당 1 억 번이면 2,169 년입니다. 예산 1 초와는 비교할 수도
없어요. 그러면 이 수 안에 헛일이 얼마나 섞여 있는지 봅시다. 같은 행에 퀸 둘을 고른 조합은 만들어 볼 것도
없이 충돌이니, 살아남는 조합은 **행마다 정확히 하나씩**인 것뿐입니다. 그러면 고르는 방법이 `n^n` 이 되고,
두 행이 **같은 열**을 써도 충돌이니 목록의 값이 서로 달라야 해서 `n!` 로 한 번 더 줄어요.

<!--proof:origin-shrink-->

| 고르는 방법 | n = 4 | n = 8 | n = 12 |
| --- | ---: | ---: | ---: |
| 칸 n 개를 아무렇게나 | 1,820 | 4,426,165,368 | 103,619,293,824,707,388 |
| 행마다 하나씩 n^n | 256 | 16,777,216 | 8,916,100,448,256 |
| 열도 서로 다르게 n! | 24 | 40,320 | 479,001,600 |
| 실제 배치 수 | 2 | 92 | 14,200 |

n = 12 에서 순열 479,001,600 개를 하나마다 퀸 쌍 66 번까지 대조하면 31,614,105,600 번이고, 초당 1 억 번이면 5 분 입니다.

<!--/proof-->

`n = 4` 에서 1,820 이 24 가 되고, 그중 실제 배치는 2 개입니다. 대각선 때문에 22 개가 버려져요. 그런데
순열까지 줄여도 `n = 12` 에서는 여전히 분 단위라 예산 안에 들지 않습니다. 이제 비용은 「만든 부분 배치의
수」와 「대각선을 비교한 횟수」로 세면 되고, 남은 질문은 **대각선을 언제 검사하느냐** 하나예요. 같은 입력
`n = 6` 에 두 방식을 적용해 봅시다. (가) 순열을 끝까지 만든 다음 대각선을 검사하고, (나) 한 행을 채울
때마다 그 행의 퀸을 이미 놓은 퀸 전부와 대조합니다.

<!--proof:two-ways-->

```text
                    만든 부분 배치  대각선 비교
끝까지 만들고 검사           1,957        3,010
한 행마다 검사                 153          866
```

만든 부분 배치가 1,957 개와 153 개로 12 배 넘게 차이 납니다. (가)의 1,957 은 순열 나무의 마디 전부이고,
(나)의 153 은 그중 「여기까지는 안 부딪힌다」가 참인 마디만이에요. 차이가 난 자리를 하나 골라 두 방식이
그 아래에 만든 것을 세 보겠습니다. 행 0 에 열 0, 행 1 에 열 1 을 놓은 부분 배치 (0,0)(1,1) 은 두 퀸이
같은 `\` 대각선에 있어 이미 충돌이에요.

<!--proof:origin-prefix-->

| 방식 | (0,0)(1,1) | 그 아래 부분 배치 | 그중 완성 배치 |
| --- | --- | ---: | ---: |
| 끝까지 만들고 검사 | 만든다 | 64 | 24 |
| 한 행마다 검사 | 만들지 않는다 | 0 | 0 |

관찰은 이것입니다 — **충돌이 확정되는 시점은 마지막 행이 아니라 그 충돌을 만든 행**이고, 그 아래로는
무엇을 채워도 배치가 되지 않아요. (가)는 (0,0)(1,1) 아래에 부분 배치 64 개를 더 만들었고 그중 24 개는
끝까지 채운 순열이었지만, 하나도 답이 아니었습니다.

그러면 한 행을 채울 때 무엇과 대조해야 할까요. 가장 단순한 후보부터 시험해 봅시다 — 「대각선은 **바로
앞 행**의 퀸과만 대조하면 되지 않나」예요. 이웃한 두 행의 퀸이 대각선으로 부딪히려면 열 차이가 1 이어야
하니, 열 차이가 1 인지만 보면 된다는 생각입니다. 이 규칙이 `n = 5` 에서 받아들인 배치 하나를 정의대로
다시 확인하면 이렇습니다.

<!--proof:origin-prev-case-->

```text
n = 5 에서 앞 행만 보는 규칙이 받아들인 배치 (0,1)(1,3)(2,0)(3,4)(4,2)
  이웃한 행의 열 차이   |1-3| = 2 · |3-0| = 3 · |0-4| = 4 · |4-2| = 2   전부 1 이 아니라 통과
  (0,1) · (3,4)         행 차이 3 · 열 차이 3                           같은 \ 대각선
  (2,0) · (4,2)         행 차이 2 · 열 차이 2                           같은 \ 대각선
  └ 두 행 이상 떨어진 두 퀸 2 쌍을 못 보고 이 배치를 답으로 센다
```

`n` 을 올려 가며 이 규칙으로 세면 답이 어디서부터 달라지는지 확인됩니다.

<!--proof:prev-row-only-->

```text
n  바른 답  앞 행만 검사
4        2             2
5       10            14
6        4            90
8       92         5,242
```

`n = 4` 에서는 답이 우연히 맞지만, `n = 5` 에서는 14 개 중 10 개만 진짜 답이고 `n = 8` 이면 92 개여야 할
답이 5,242 개가 됩니다. 앞 행만 보면 **두 행 이상 떨어진 대각선**을 못 봐요. 그래서 대조할 상대는 이미
놓은 퀸 전부여야 합니다. 지금까지 시도한 방법을 차례로 놓으면 이렇습니다.

<!--fig:origin-approaches-->
![시도한 방법 넷 — 셋은 버렸고 하나가 남았다](./figs/origin-approaches.svg)

남은 방법에 이름을 붙이면 **가지치기**입니다. 한 행을 놓을 때마다 이미 놓은 퀸 전부와 대조하고, 충돌이면
그 부분 배치 아래를 하나도 만들지 않아요. 놓인 퀸 전부와의 대조를 퀸 수만큼 되풀이하지 않고 한 번에
끝내는 방법과, 다음 행에서 돌아올 때 무엇을 지우는지는 다음 절에서 실현하는 순서대로 확인합니다.

### 아이디어 상세 — 가지치기

이 아이디어를 한 문장으로 줄이면 이렇습니다. **행 0 부터 한 행씩 열을 하나 골라 놓되, 놓을 때 그 퀸의
열과 두 대각선 번호를 세 정수의 비트로 켜 두고, 시도하는 열의 세 비트 중 하나라도 켜져 있으면 그 열을
건너뛰고, 다음 행에서 돌아오면 켠 비트를 끕니다.** 이 방법이 기대는 구조는 대각선마다 붙인 번호인데,
칸마다 번호를 붙여 대각선을 부르는 방식은 처음 보는 사람에게 낯설어요. 그래서 그 번호를 먼저 따로
설명하고, 그다음 실현하는 순서대로 네 단계를 설명합니다. 앞 단계에서 만든 것을 뒤 단계에서 쓰는 순서예요.

| 언제 | 단계 | 하는 일 | 앞 단계에서 받아 쓰는 것 |
| --- | --- | --- | --- |
| 호출마다 | 1단계 행 하나씩 채우기 | `place(row)` 가 행 `row` 의 열 `0 … n−1` 을 차례로 시도하고, `row = n` 이면 배치 하나를 센다 | — |
| 퀸을 놓을 때마다 | 2단계 열과 대각선 표시하기 | 놓은 퀸의 `c` · `d1` · `d2` 번 비트를 세 정수에 켠다 | 1단계의 `row` · `c` |
| 열을 시도할 때마다 | 3단계 표시 보고 건너뛰기 | 시도하는 열의 세 비트 중 하나라도 켜져 있으면 그 열을 건너뛴다 | 2단계의 세 정수 |
| 다음 행에서 돌아올 때마다 | 4단계 돌아와서 표시 끄기 | 2단계에서 켠 세 비트를 끈다 | 2단계에서 켠 자리 |

#### 먼저 알아 둘 개념 — 대각선 번호

**대각선 번호**는 판의 칸마다, 그 칸을 지나는 `\` 대각선과 `/` 대각선에 하나씩 붙인 번호입니다. 같은
대각선 위의 칸은 모두 같은 번호를 받고, 다른 대각선의 칸은 다른 번호를 받아요. `\` 대각선을 따라 한 칸
내려가면 행과 열이 함께 1 씩 늘어 `행 − 열` 이 그대로이고, `/` 대각선을 따라 내려가면 행은 늘고 열은 줄어
`행 + 열` 이 그대로입니다. 그래서 번호를 이렇게 정합니다.

```text
d1 = row − c + (n − 1)     \ 대각선 번호. n − 1 을 더해 가장 작은 번호가 0 이 되게 한다
d2 = row + c               / 대각선 번호
```

##### 판 위의 대각선 번호

`n = 4` 판의 칸마다 두 번호를 적었습니다. 굵은 테 칸이 (1,2) 이고, 옅게 칠한 칸이 (1,2) 와 번호가 같은
칸이에요.

<!--fig:build-diag-numbers-->
![n = 4 판의 칸마다 적은 d1 과 d2](./figs/build-diag-numbers.svg)

`d1` 판에서는 왼쪽 위에서 오른쪽 아래로 같은 수가 늘어서고, `d2` 판에서는 오른쪽 위에서 왼쪽 아래로 같은
수가 늘어섭니다. 한 줄로 늘어선 같은 수가 곧 대각선 하나예요.

##### 칸 하나의 번호를 읽는 법

칸 (1,2) 하나를 골라 번호에서 그 대각선 위의 칸까지 따라가 보겠습니다.

<!--proof:build-diag-read-->

| 방향 | 칸 (1,2) 의 번호 | 번호가 같은 칸 |
| --- | --- | --- |
| `\` 대각선 | d1 = 1 − 2 + 3 = 2 | (0,1) (1,2) (2,3) |
| `/` 대각선 | d2 = 1 + 2 = 3 | (0,3) (1,2) (2,1) (3,0) |

(1,2) 에 퀸이 있으면 이 표에서 (1,2) 자신을 뺀 칸들이 대각선으로 공격받습니다. 「전체 컨셉」의 첫 그림에서
`\` 와 `/` 로 표시한 칸과 같아요.

##### 번호끼리의 관계

번호마다 그 번호를 받은 칸이 몇 개인지 세면 이렇습니다.

<!--proof:build-diag-lines-->

| 번호 | d1 이 이 번호인 칸 | d2 가 이 번호인 칸 |
| ---: | ---: | ---: |
| 0 | 1 | 1 |
| 1 | 2 | 2 |
| 2 | 3 | 3 |
| 3 | 4 | 4 |
| 4 | 3 | 3 |
| 5 | 2 | 2 |
| 6 | 1 | 1 |

n = 4 에서 번호는 방향마다 7 가지이고, 칸 수를 더하면 방향마다 16 칸입니다.

<!--/proof-->

가운데 번호 3 이 판을 가로지르는 가장 긴 대각선이고, 양 끝 번호 0 과 6 은 모서리 칸 하나짜리
대각선입니다. 이웃한 칸으로 옮기면 번호가 일정하게 바뀌어요.

<!--proof:build-diag-moves-->

| 옮기는 방향 | d1 의 변화 | d2 의 변화 | 확인한 칸 |
| --- | ---: | ---: | ---: |
| 한 행 아래 (row + 1, c) | +1 | +1 | 12 |
| 한 열 오른쪽 (row, c + 1) | −1 | +1 | 12 |

한 행 아래로 가면 두 번호가 모두 1 늘고, 한 열 오른쪽으로 가면 `d1` 은 1 줄고 `d2` 는 1 늡니다. 그래서 같은
행의 칸들은 `d1` 도 `d2` 도 서로 다르고, 한 행 안에서 열을 바꿔 가며 시도하면 매번 다른 대각선 두 개를 보게
돼요.

##### 퀸끼리 하나씩 대조하는 모양과의 차이

대각선 충돌을 처음 떠올릴 때는 보통 두 퀸의 행 차이와 열 차이가 같은지를 봅니다. 「아이디어를 떠올리는
과정」의 (나)가 그렇게 했어요. 그 모양은 새 퀸을 놓을 때마다 이미 놓은 퀸 전부와 하나씩 비교해야 합니다.
번호를 쓰면 이미 놓은 퀸이 쓴 번호를 표시해 두고, 새 칸의 번호 둘만 확인하면 돼요. 같은 `n = 6` 에서 두
모양을 나란히 세었습니다.

<!--proof:build-diag-vs-pair-->

| 대각선을 판정하는 모양 | n = 6 에서 대각선을 확인한 횟수 |
| --- | ---: |
| 놓인 퀸과 하나씩 행 차이 · 열 차이 비교 | 866 |
| 대각선 번호 비트 두 개 읽기 | 591 |

두 모양은 같은 부분 배치 153 개를 만들었고 후보마다 판정이 하나도 갈리지 않았습니다. 6 × 6 판의 칸 쌍 630 개에서 「번호가 같다」와 「행 차이 = 열 차이」를 대조했고, 어긋난 쌍은 0 개입니다.

<!--/proof-->

확인 횟수가 866 번에서 591 번으로 줄었는데, 더 중요한 차이는 **후보 하나의 대각선 판정이 이미 놓은 퀸
수와 상관없이 많아야 두 번**이라는 점입니다. 퀸이 많이 놓인 깊은 행일수록 하나씩 비교하는 쪽은 비교가
늘지만, 번호 쪽은 그대로예요.

##### 이렇게 생긴 까닭

퀸은 대각선 위라면 몇 칸 떨어져 있든 공격합니다. 그러니 판정에 필요한 것은 「이 칸이 놓인 퀸과 **같은
대각선**에 있는가」 하나이고, 그 물음에 한 번에 답하려면 대각선마다 이름이 하나씩 있어야 해요. 번호가 그
이름입니다. `n − 1` 을 더하는 것은 `행 − 열` 이 음수가 되는 칸이 있어서입니다.

```text
행 − 열 이 가장 작은 칸   행 0 · 열 n−1   →   0 − (n − 1) = −(n − 1)
여기에 n − 1 을 더하면    d1 = 0            →   번호가 0 부터 시작해 비트 자리로 바로 쓸 수 있다
```

오프셋을 빼면 무엇이 달라지는지는 「수행으로 알아보는 알고리즘」의 두 번째 짚고 가기에서 실행 결과로 봅니다.

#### 1단계 — 행 하나씩 채우기

행마다 퀸이 정확히 하나이니, 배치를 행 0 부터 한 행씩 채웁니다. `place(row)` 는 행 `0 … row−1` 이 이미
채워진 상태에서 행 `row` 의 열 `0 … n−1` 을 차례로 시도하는 호출이에요. 열 하나를 고를 때마다
`place(row + 1)` 을 부르고, `row` 가 `n` 이 되면 모든 행을 채운 것이니 배치 하나를 셉니다. 무엇도
건너뛰지 않으면 무엇이 세어지는지, 정본에서 건너뛰는 줄(`continue;`)만 지운 코드를 실행해 확인했습니다.

<!--proof:build-rows-->

| n | 건너뛰기를 뺀 코드의 count | n^n | 바른 답 |
| ---: | ---: | ---: | ---: |
| 1 | 1 | 1 | 1 |
| 2 | 4 | 4 | 0 |
| 3 | 27 | 27 | 0 |
| 4 | 256 | 256 | 2 |

건너뛰는 것이 없으면 행마다 열 `n` 개가 다 통과해 count 가 `n^n` 이 됩니다. 1단계가 정하는 것은 **무엇을
차례로 시도하는가**(행 하나에 열 `n` 개)와 **언제 세는가**(`row = n`)까지이고, 무엇을 건너뛸지는 3단계가
정해요.

#### 2단계 — 열과 대각선 표시하기

퀸을 놓을 때마다 그 퀸이 쓴 열 하나와 대각선 둘을 기억해 둡니다. 기억할 것이 「몇 번 열을 썼는가」 ·
「몇 번 `\` 대각선을 썼는가」 · 「몇 번 `/` 대각선을 썼는가」 셋이라 정수 세 개를 두고, 번호 `k` 를 썼으면
그 정수의 `k` 번 비트를 1 로 켭니다. `cols` 는 열, `diag1` 은 `d1`, `diag2` 는 `d2` 를 담아요. 이 글은
정수를 켜진 비트 자리의 모음으로 적습니다 — `cols {0, 2}` 는 0 번과 2 번 비트가 켜졌다는 뜻이에요.

<!--proof:build-set-->

```text
(0,0) 을 놓는다 (n = 4)   d1 = 0 - 0 + 3 = 3 · d2 = 0 + 0 = 0
  놓기 전   cols {} · diag1 {} · diag2 {}
  놓은 뒤   cols {0} · diag1 {3} · diag2 {0}

퀸 셋 (0,0)(1,3)(2,1) 을 놓은 뒤의 cols
  0b1011 = 11   켜진 자리 {0, 1, 3} = 놓인 열 {0, 1, 3}
```

(0,0) 하나를 놓으면 세 정수에 비트가 하나씩 켜지고, 퀸이 셋이면 `cols` 에 자리 셋이 켜집니다. 켜진 자리가 곧
놓인 열이에요. 세 정수가 차지하는 자리 수는 번호의 범위가 정합니다.

<!--proof:build-bits-->

| n | cols 의 자리 수 | diag1 · diag2 의 자리 수 | 실행에서 켜진 가장 큰 자리 |
| ---: | ---: | ---: | ---: |
| 4 | 4 | 7 | 5 |
| 8 | 8 | 15 | 14 |
| 12 | 12 | 23 | 22 |

n = 12 에서도 가장 큰 자리가 22 번이라 32 비트 정수 하나에 들어갑니다.

<!--/proof-->

`cols` 는 열 번호만큼 `n` 자리, 두 대각선은 번호가 `0 … 2n−2` 라 `2n − 1` 자리가 필요합니다. 과제 규모의
상단 `n = 12` 에서도 세 정수가 모두 32 비트 정수 하나에 들어가요.

#### 3단계 — 표시 보고 건너뛰기

열 `c` 를 시도할 때는 그 칸의 번호 `d1` · `d2` 를 계산하고, 세 정수에서 `c` · `d1` · `d2` 번 비트를
읽습니다. 하나라도 1 이면 이미 놓인 퀸 중 누군가와 같은 열이나 같은 대각선에 있다는 뜻이라 그 열을
건너뛰어요. 셋 다 0 이면 이미 놓인 퀸 전부와 부딪히지 않습니다. (0,0) 하나가 놓인 판에서 행 1 의 열 넷을
판정하면 이렇습니다.

<!--proof:build-judge-->

| 열 c | d1 | d2 | 켜져 있던 비트 | 판정 |
| ---: | ---: | ---: | --- | --- |
| 0 | 4 | 1 | cols 의 0 번 | 건너뛴다 |
| 1 | 3 | 2 | diag1 의 3 번 | 건너뛴다 |
| 2 | 2 | 3 | 없음 | 놓는다 |
| 3 | 1 | 4 | 없음 | 놓는다 |

열 0 은 (0,0) 과 같은 열이라 `cols` 에, 열 1 은 (0,0) 과 같은 `\` 대각선이라 `diag1` 에 막혔어요. 열 2 와
열 3 은 세 비트가 모두 꺼져 있어 놓을 수 있습니다. 이 판정이 이미 놓은 퀸 전부와 하나씩 대조한 결과와
같다는 것은 「퀸끼리 하나씩 대조하는 모양과의 차이」의 표가 `n = 6` 의 모든 후보에서 확인했어요.

#### 4단계 — 돌아와서 표시 끄기

2단계에서 켠 비트는 그 퀸이 판에 있는 동안만 참입니다. 다음 행에서 돌아오면 이 행은 다음 열 후보를
시도하는데, 그때 판에는 방금 돌아온 퀸이 없어야 해요. 그래서 돌아오면 켠 세 비트를 끕니다. 쉬운 경우는
내려갈 때입니다 — 세 비트를 켜고 `row` 를 하나 늘리면 끝이에요. 불안한 경우는 **돌아올 때**라, 행 1 에서
(1,2) 를 놓고 내려갔다가 돌아와 (1,3) 을 시도하는 자리의 세 정수를 시점마다 적었습니다.

<!--proof:build-undo-->

| 시점 | cols | diag1 | diag2 |
| --- | --- | --- | --- |
| 행 1 에 들어올 때 | {0} | {3} | {0} |
| (1,2) 를 놓고 행 2 로 내려갈 때 | {0, 2} | {2, 3} | {0, 3} |
| 돌아와 세 비트를 끈 뒤 | {0} | {3} | {0} |
| (1,3) 을 놓고 행 2 로 내려갈 때 | {0, 3} | {1, 3} | {0, 4} |

돌아와 끈 뒤의 세 정수는 행 1 에 들어올 때와 같습니다. n = 4 에서 되돌린 16 번 모두 그 호출에 들어올 때의 세 정수로 돌아갔습니다.

<!--/proof-->

돌아와 끈 뒤의 값이 행 1 에 들어올 때와 같아서, (1,3) 은 (0,0) 하나만 놓인 판에서 판정을 받습니다. 끄는
자리가 맞는 이유는 켤 때와 **같은 식으로 계산되기** 때문이에요. `d1` 과 `d2` 는 `row` 와 `c` 만으로 정해지고,
이 호출의 `row` 와 `c` 는 다음 행에서 돌아온 뒤에도 그대로라 `1 << d1` 이 가리키는 자리도 그대로입니다. 그
자리는 직전에 이 호출이 켰으니 반드시 1 이고, 1 인 비트에 `^` 를 하면 0 이 돼요.

```text
켤 때   d1 = row − c + (n − 1)   →  diag1 의 d1 번 비트를 1 로
끌 때   d1 = row − c + (n − 1)   →  같은 비트에 ^ 1 을 해 0 으로
    └ row 도 c 도 다음 행에서 돌아오는 동안 바뀌지 않으므로 같은 식이 같은 자리를 낸다
```

#### 이 방법이 기대는 전제

가지치기는 아래 세 전제가 있어야 성립합니다. 하나라도 빠지면 답이 틀리거나 건너뛸 수 있는 것이 없어요.

| 전제 | 쓰이는 곳 | 없을 때 |
| --- | --- | --- |
| 제약이 두 퀸 사이의 관계다 — 부분 배치만으로 충돌이 정해진다 | 3단계에서 행 하나를 놓자마자 판정한다 | 「공격하는 쌍이 정확히 `k` 개」처럼 배치 전체를 봐야 정해지는 조건이면 끝까지 채우기 전에는 건너뛸 수 없다 |
| 새 퀸을 놓인 퀸 **전부**와 대조한다 | 3단계의 세 정수가 놓인 퀸 전부의 열 · 대각선을 담는다 | 바로 앞 행과만 대조하면 `n = 8` 에서 답이 92 가 아니라 5,242 다 |
| 번호가 비트 자리 `0 … 31` 안에 든다 | 2단계에서 번호를 비트 자리로 쓴다 | 가장 큰 번호 `2n − 2` 가 32 이상이면 자바스크립트의 `<<` 가 자리 수를 32 로 나눈 나머지로 써서, 서로 다른 대각선이 한 비트를 나눠 쓴다 |

두 번째 줄의 값은 「아이디어를 떠올리는 과정」의 「앞 행만 검사」 표에 있습니다. 세 번째 전제는
`2n − 2 ≤ 31`, 곧 `n ≤ 16` 이면 지켜지고, 과제 규모 `n ≤ 12` 는 그 안이에요. 오프셋을 뺀 코드가 `n = 17`
부터 비트를 겹쳐 쓰는 모습은 「수행으로 알아보는 알고리즘」의 두 번째 짚고 가기에서 봅니다.

#### 매 행마다 검사하는 까닭

가지치기가 정하는 값은 **검사를 몇 행마다 하느냐**입니다. (가)는 마지막에 한 번, (나)는 매 행이었는데 그
사이도 가능해요 — `k` 행마다 한 번씩 검사하는 것입니다. `n = 8` 에서 `k` 를 넷으로 놓고 만든 부분 배치를
셌습니다.

<!--proof:check-timing-->

```text
검사 시점  답  만든 부분 배치  1 행마다 대비
1 행마다   92           2,057          1.0배
2 행마다   92           3,765          1.8배
4 행마다   92          14,597          7.1배
8 행마다   92          69,373         33.7배
```

**가장 이른 쪽이 가장 적습니다.** 중간 어딘가가 최소인 모양이 아니라 `k` 가 커질수록 늘어나요. 검사를 한 행
미루면 이미 충돌한 부분 배치가 그 행의 후보 수만큼 자식을 더 만들고, 미루는 행이 늘수록 그 수가 곱해지기
때문입니다. 그러면 `k = 1` 로 고정하고, 이 방식이 `n` 이 커질 때 얼마나 깎아 내는지 대각선 검사를 뺀
쪽(열만 검사)과 나란히 셌습니다.

<!--proof:tree-size-->


#### 네 단계를 이은 절차

네 단계를 코드의 순서로 다시 적으면 네 걸음이 됩니다. 이렇게 하면 `n = 12` 에서 만드는 부분 배치가
856,189 개예요.

1. `place(0, 0, 0, 0)` 으로 빈 판에서 시작한다
2. `row = n` 이면 배치 하나를 세고 돌아간다
3. 아니면 열 `c = 0 … n−1` 마다 `d1` · `d2` 를 계산하고, `cols` · `diag1` · `diag2` 의 `c` · `d1` · `d2` 번
   비트 중 하나라도 1 이면 그 열을 건너뛴다
4. 셋 다 0 이면 세 비트를 켜고 `place(row + 1, …)` 을 부른 뒤, 돌아오면 세 비트를 끈다

### 수행으로 알아보는 알고리즘 — 4×4 판에서 배치 둘을 센다

아이디어를 세웠으니 이제 **실제로 동작하는 코드**로 옮겨 봅시다. 입력 하나를 잡고 끝까지 가되, 조각마다
그 조각만 실행해서 나온 값을 확인하고 넘어갑니다.

<!--proof:walk-input-->

```ts
const n = 4;
// 이 절이 끝나면 2 가 나와야 한다
```

`n` 을 왜 하필 4 로 뒀을까요? **세 갈래 ①②③ 과, 돌아와서 다른 열을 시도하는 일까지** 모두 실행하게 하는
가장 작은 값이기 때문입니다. `n = 1` 은 열 후보가 하나뿐이라 다른 후보로 넘어가는 일이 없고, `n = 2` 와
`n = 3` 은 배치가 하나도 없어서 「다 채웠다」 갈래가 실행되지 않아요.

```text
place(row, cols, diag1, diag2):
    row 가 n 이면 count 를 하나 늘리고 반환한다              ① 다 채웠다
    c 를 0 부터 n-1 까지:
        d1 ← row - c + (n-1),  d2 ← row + c
        cols·diag1·diag2 중 하나라도 쓰였으면 건너뛴다        ② 충돌이다
        세 비트를 켜고 place(row+1, …) 를 부른 뒤 세 비트를 끈다  ③ 놓는다
```

#### 1. 행 하나에 퀸을 놓는 골격을 적는다

행 `row` 를 채운다는 것은 열 `0` 부터 `n-1` 까지 하나씩 시도한다는 뜻입니다. `row` 가 `n` 이면 행이 하나도
안 남았다는 뜻이니 배치 하나가 완성된 것이고, 그때 세는 것이 답이에요. 판정은 다음 걸음에서 넣고, 지금은
열마다 다음 행으로 내려가기만 합니다.

```ts
function place(
  row: number,
  cols: number,
  diag1: number,
  diag2: number,
): void {
  if (row === n) {
    // ① 행을 전부 채웠다
    count++;
    return;
  }
  for (let c = 0; c < n; c++) {
    // 판정은 다음 걸음에서 이 자리에 넣는다
    place(row + 1, cols, diag1, diag2);
  }
}
```

이 골격만 `n = 2` 로 실행하면 이렇게 나옵니다.

<!--proof:walk-skeleton-->

```text
n = 2 에서 판정 없이 끝까지 간 목록
  [0 0]   count = 1
  [0 1]   count = 2
  [1 0]   count = 3
  [1 1]   count = 4
  └ 바른 답은 0 이다. 목록 4 개 중 4 개가 같은 열이나 대각선을 쓴다
```

판정이 없으니 목록 넷이 모두 세어졌어요. 넷 다 같은 열이나 대각선을 쓰는 목록이라 바른 답은 0 입니다. 그
넷을 빼는 것이 다음 걸음의 판정이에요.

#### 2. 이미 쓴 열과 대각선을 세 정수로 판정한다

판정에 필요한 것은 「열 `c` 가 쓰였나」 · 「`\` 대각선 `d1` 이 쓰였나」 · 「`/` 대각선 `d2` 가 쓰였나」
셋입니다. 세 정수의 해당 비트를 읽어서 하나라도 1 이면 이 열은 못 씁니다.

```ts
const d1 = row - c + (n - 1);
const d2 = row + c;
if (
  ((cols >> c) & 1) === 1 ||
  ((diag1 >> d1) & 1) === 1 ||
  ((diag2 >> d2) & 1) === 1
) {
  // ② 충돌이라 이 열은 건너뛴다
  continue;
}
```

행 0 에 열 0 을 놓은 상태에서 행 1 의 네 열을 판정하면 이렇게 나옵니다.

<!--proof:walk-judge-->

```text
cols {0} · diag1 {3} · diag2 {0}   (행 0 의 열 0 이 켜 둔 비트)

  c=0   d1 = 1-0+3 = 4 · d2 = 1+0 = 1   cols 의 0 번 비트가 1    → ② 열 충돌
  c=1   d1 = 1-1+3 = 3 · d2 = 1+1 = 2   diag1 의 3 번 비트가 1   → ② \ 충돌
  c=2   d1 = 1-2+3 = 2 · d2 = 1+2 = 3   셋 다 0                  → 놓을 수 있다
  c=3   d1 = 1-3+3 = 1 · d2 = 1+3 = 4   셋 다 0                  → 놓을 수 있다
```

`||` 는 앞에서부터 보고 처음 참인 곳에서 멈추므로, `c=0` 은 `cols` 에서 멈춰 대각선 비트를 읽지도 않아요.

#### 짚고 가기 — 대각선 둘을 정수 하나에 합치면 없는 충돌이 생긴다

「`\` 대각선과 `/` 대각선을 왜 따로 두나 — 둘 다 「이 대각선이 이미 쓰였나」인데 정수 하나에 같이 담으면
안 되나」 싶은 자리입니다. 코드로 만들면 이렇게 돼요.

```ts
// diag 하나에 d1 과 d2 를 같이 담는다
if (
  ((cols >> c) & 1) === 1 ||
  ((diag >> d1) & 1) === 1 ||
  ((diag >> d2) & 1) === 1
) {
  continue;
}
// 놓을 때도 한 정수에 두 자리를 켠다
diag |= (1 << d1) | (1 << d2);
```

**`n = 4` 부터 답이 0 이 됩니다.** 실행하면 이렇게 나옵니다.

<!--proof:merged-diag-->

```text
n  바른 답  대각선을 합친 코드
1        1                   1
4        2                   0
5       10                   0
6        4                   0
7       40                   0
8       92                   0
```

0 이 나오는 이유는 **없는 충돌이 생기기** 때문이에요. `n = 4` 의 진짜 답 하나를 이 코드로 판정해 보면 두
번째 퀸에서 이미 막힙니다.

<!--proof:merged-case-->

```text
n = 4 의 답 (0,1)(1,3)(2,0)(3,2) 를 합친 정수로 판정하면

  (0,1)   d1 = 0-1+3 = 2 · d2 = 0+1 = 1   diag 의 2 번과 1 번 비트를 켠다
  (1,3)   d1 = 1-3+3 = 1                  1 번 비트가 이미 1 → 충돌로 판정한다

  (0,1) 이 켠 1 번은 「/ 대각선 1」이고 (1,3) 이 보는 1 번은 「\ 대각선 1」이다
       └ 서로 다른 대각선이 같은 비트를 나눠 써서 없는 충돌이 생겼다
```

`d1` 도 `d2` 도 범위가 `0` 부터 `2n − 2` 라 두 번호 체계가 통째로 겹칩니다. `n = 1` 만 답이 안 달라지는 것은
퀸을 하나만 놓고 끝나서 두 번째 판정이 아예 없기 때문이에요. 그래서 정수를 둘로 나눠 두고, `diag1` 은 `\`
만 `diag2` 는 `/` 만 담습니다.

#### 3. 놓고 내려갔다가 켠 비트를 끈다

판정을 통과했으면 세 비트를 켜고 다음 행으로 내려갑니다. 돌아온 뒤에는 **켠 그 세 자리만** 끄고 다음 열
후보로 넘어가요.

```ts
// ③ 놓는다 — 세 비트를 켜고 다음 행으로 내려간다
cols |= 1 << c;
diag1 |= 1 << d1;
diag2 |= 1 << d2;

place(row + 1, cols, diag1, diag2);

cols ^= 1 << c;
diag1 ^= 1 << d1;
diag2 ^= 1 << d2;
```

여기서 가장 중요한 줄은 `cols ^= 1 << c;` 로 시작하는 마지막 세 줄입니다. 이 세 줄이 **같은 행의 다음 열
후보에게 판을 원래대로 넘겨줘요.** 행 1 에서 (1,2) 를 놓았다가 돌아온 직후를 두 경우로 실행했습니다.

<!--proof:walk-undo-->

```text
행 1 에서 (1,2) 를 놓았다가 돌아온 직후 (n = 4)
  끄는 코드     cols {0} · diag1 {3} · diag2 {0}
  끄지 않으면   cols {0, 2} · diag1 {2, 3} · diag2 {0, 3}

끄지 않은 채 (1,3) 을 놓고 행 2 로 내려가면
  (2,1)   끄는 코드에서는 놓을 수 있다   끄지 않으면 (1,2) 가 남긴 비트에 막힌다
```

끄지 않으면 (1,2) 의 비트가 남아, 판에 없는 퀸 때문에 (2,1) 이 막힙니다. (2,1) 은 바른 코드에서
(0,0)(1,3)(2,1) 까지 내려가는 칸이에요.

#### 4. n = 4 를 열일곱 걸음으로 끝까지 따라간다

앞의 세 조각을 이어 `nQueens(4)` 를 실행하면 재귀가 어떻게 내려가고 돌아오는지 값으로 확인됩니다. **걸음
하나는 `place` 호출 하나**예요. 무대의 「놓은 열」 줄이 행마다 놓은 퀸의 열이고, 괄호가 이미 채운
행입니다. 그 아래 세 줄이 `cols` · `diag1` · `diag2` 의 비트이고, 맨 위 눈금이 「놓은 열」 줄에서는 행
번호, 세 정수 줄에서는 비트 자리예요. 옅게 칠한 비트가 이번 판정에서 열을 막은 비트, 굵은 테 비트가 부모가
방금 켠 비트이고, 맨 아래 「판정」 줄이 행 `row` 의 열마다 판정입니다.

#### 짚고 가기 — 대각선 번호에서 n − 1 을 빼도 n ≤ 16 에서는 답이 그대로다

`d1 = row - c + (n - 1)` 의 `+ (n - 1)` 은 음수를 막으려고 붙인 것입니다. 그러면 「어차피 `1 << -2` 같은 건
안 나올 테니 빼도 되지 않나」 싶은데, 실제로는 `row < c` 이면 `d1` 이 음수가 돼요. 그럼에도 이 과제의 규모
안에서는 답이 달라지지 않습니다.

```ts
const d1 = row - c; // ← + (n - 1) 을 뺐다
```

<!--proof:mutant-offset-->

```text
n   바른 코드  오프셋을 뺀 코드
4           2                 2
6           4                 4
8          92                92
10        724               724
12     14,200            14,200
```

**답이 안 달라지는 것이 이 자리의 함정입니다.** 자바스크립트의 `<<` 와 `>>` 는 자리 수를 32 로 나눈
나머지로 취급해요. 그래서 음수 `d1` 들은 위쪽 비트 자리로, 양수 `d1` 들은 아래쪽 비트 자리로 갈라져
앉습니다. `1 << d1` 이 실제로 켜는 자리를 실행해 모으면 이렇습니다.

<!--proof:offset-bits-->

```text
n   d1 의 범위    비트 자리
12    -11 … 11  21…31, 0…11            안 겹친다
16    -15 … 15  17…31, 0…15            안 겹친다
17    -16 … 16  16…31, 0…16  16 번 자리가 겹친다
```

`n = 17` 이 되면 `d1 = -16` 이 16 번 자리로 가고 `d1 = 16` 도 16 번 자리로 가서, 서로 다른 두 대각선이 한
비트를 나눠 쓰게 됩니다. 이 과제의 규모는 `n ≤ 12` 라 그 일이 생기지 않지만, **같은 코드를 `n` 이 더 큰
과제로 옮기는 순간 조용히 틀립니다.** 오프셋을 두는 이유가 그것이고, 오프셋이 있으면 `d1` 이 항상 `0`
이상이라 자리 계산에 나머지 규칙이 끼어들지 않아요.

#### 5. 전체 코드

조각을 하나로 잇습니다. 위에서 확인한 것 말고 새로 들어간 것은 `count` 를 담을 자리와 `place(0, 0, 0, 0)` 첫
호출뿐이에요 — 세 정수가 0 이라 「아무것도 안 놓인 판」이 됩니다.

```ts
export function nQueens(n: number): number {
  let count = 0;

  function place(
    row: number,
    cols: number,
    diag1: number,
    diag2: number,
  ): void {
    if (row === n) {
      // ① 행을 전부 채웠다 — 배치 하나가 완성됐다.
      count++;
      return;
    }

    for (let c = 0; c < n; c++) {
      // `\` 대각선과 `/` 대각선의 번호. 음수가 안 되게 n-1 을 더한다.
      const d1 = row - c + (n - 1);
      const d2 = row + c;

      if (
        ((cols >> c) & 1) === 1 ||
        ((diag1 >> d1) & 1) === 1 ||
        ((diag2 >> d2) & 1) === 1
      ) {
        // ② 열이나 대각선 중 하나가 이미 쓰였다 — 이 열은 건너뛴다.
        continue;
      }

      // ③ 놓는다 — 세 비트를 켜고 다음 행으로 내려간다.
      cols |= 1 << c;
      diag1 |= 1 << d1;
      diag2 |= 1 << d2;

      place(row + 1, cols, diag1, diag2);

      // 돌아왔으면 켠 비트를 그대로 끈다. 다음 열 후보가 이 행을 비어 있는 것으로 봐야 한다.
      cols ^= 1 << c;
      diag1 ^= 1 << d1;
      diag2 ^= 1 << d2;
    }
  }

  place(0, 0, 0, 0);
  return count;
}
```

실행하면 이렇게 나옵니다.

```text
nQueens( 2)  →   0
nQueens( 3)  →   0
nQueens( 4)  →   2
nQueens( 5)  →  10
nQueens( 6)  →   4
nQueens( 7)  →  40
nQueens( 8)  →  92
```

### 알아 두면 좋은 개념 — 제약 충족 문제

파트 1 에서 한 일을 다시 보면, 정한 것이 셋이었습니다 — **무엇을 하나씩 정해 나가는가**(행), **각 자리에
올 수 있는 값이 무엇인가**(열 `0 … n−1`), **어떤 조합이 금지되는가**(같은 열, 같은 `\` 대각선, 같은 `/`
대각선). 이 셋으로 적히는 과제를 **제약 충족 문제**라고 부릅니다.

| 이름 | 이 편에서 무엇이었나 | 값 |
| --- | --- | --- |
| 변수 | 행 하나하나 | `row = 0 … n−1`, `n` 개 |
| 도메인 | 그 행에 놓을 수 있는 열 | `c = 0 … n−1`, 후보 `n` 개 |
| 제약 | 두 퀸이 부딪히는 조건 | 같은 `c` · 같은 `d1` · 같은 `d2` |
| 부분 해 | 앞 `row` 개 변수만 값을 정한 상태 | T4 의 `(0,0)(1,3)` 같은 것 |

이름을 붙이고 나면 「한 행마다 검사한다」가 N-Queens 만의 요령이 아니라는 것이 확인됩니다. 변수에 값을 하나
배정할 때마다 제약을 확인하고 어기면 그 아래를 만들지 않는 절차를 **백트래킹**이라고 부르고, 제약 충족
문제면 무엇이든 같은 모양으로 적을 수 있어요.

```text
같은 세 칸을 다른 과제에 채워 보면

           변수              도메인            제약
  스도쿠   빈 칸 하나하나    숫자 1 … 9        같은 행·열·3×3 상자에 같은 숫자 금지
  색칠     그래프의 정점     색 1 … k          이웃한 두 정점은 다른 색
  시간표   과목 하나하나     (요일, 교시)      같은 교실·같은 교수 시간 겹침 금지
     └ 셋 다 「하나 정할 때마다 확인하고 어기면 그 아래를 안 만든다」가 그대로 통한다
```

## 파트 2 — 적용 조건 · 보장 · 비용

파트 1 에서 만든 것을 따져 봅니다. 어떤 과제에 이것을 쓰는지, 만드는 부분 배치의 수가 어떤 식으로 닫히는지,
무엇이 매 순간 참으로 남는지, 그리고 연산이 몇 번인지 순서로 봅니다.

### 이 알고리즘이 최적의 솔루션인 경우

#### 최적인 문제의 모양

네 조건이 함께 맞을 때입니다.

- **답을 한 자리씩 정해 나갈 수 있습니다.** 「행 0 의 열, 행 1 의 열, …」처럼 순서를 정해 하나씩 채울 수
  있어야 해요.
- **다 채우기 전에 「이건 이미 안 된다」가 판정됩니다.** 부분 배치만으로 제약 위반을 알 수 있어야
  가지치기가 일을 합니다.
- **답이 조합적으로 많아 공식이 없습니다.** 세는 공식이 있으면 그것을 쓰면 되고, 답을 전부 방문해야 한다면
  이 절차가 남아요.
- **입력 규모가 작습니다.** 이 과제는 `n ≤ 12` 이고, 이 상한이 있어야 지수적인 탐색이 1 초에 들어갑니다.

```text
네 조건이 코드의 모양을 그대로 정한다
  한 자리씩 정한다      → place(row, …) 의 row 가 그 순서다
  부분 배치로 판정      → 세 비트를 확인하는 if 한 덩어리가 전부다
  공식이 없다           → 답을 세는 자리가 ① 하나뿐이다
  규모가 작다           → 상태를 32비트 정수 셋에 담아도 된다
```

#### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "서로 공격하지 않게"  "겹치지 않게"  "조건을 만족하는 배치의 수"
  "가능한 모든 경우를 세어라"  "조건을 만족하는 순열의 수"

제약에 이런 모양이 보이면
  n ≤ 15 안팎으로 작다        ← 지수적 탐색을 허용하겠다는 신호다
  답이 공식으로 안 나온다
  부분적으로 채운 상태에서 이미 위반을 판정할 수 있다
```

반대로 **입력이 수만 이상**이면 이 단서는 해당하지 않아요. 그때는 답을 세는 공식을 찾거나 동적 계획법으로
상태를 합치는 쪽을 봐야 합니다.

#### 실제로 쓰이는 곳

- **Google OR-Tools 의 제약 프로그래밍 문서** — 「The N-queens Problem」 이 CP-SAT 로 N-Queens 를 푸는
  예제이고, 값을 배정할 때마다 제약을 전파하고 막히면 되돌아가는 절차를 4-Queens 그림으로 설명합니다.
  ([The N-queens Problem](https://developers.google.com/optimization/cp/queens), 조회 2026-08-29)
- **Knuth, 「Dancing Links」(2000)** — 정확한 덮개 문제를 되돌아가며 푸는 자료구조를 제안하고, 그 성능
  측정에 N-Queens 를 `n = 18` 까지 씁니다.
  ([arXiv cs/0011047](https://arxiv.org/abs/cs/0011047), 조회 2026-08-29)
- **PCRE2 정규식 엔진** — 되돌아가는 자리를 명시적인 메모리 프레임에 기억해 두고, 그 깊이와 메모리에 상한을
  둡니다. 이 편의 「켜고 내려갔다가 끈다」와 같은 자리예요.
  ([pcre2perform](https://www.pcre.org/current/doc/html/pcre2perform.html), 조회 2026-08-29)

N-Queens 자체가 제품에 들어간 사례는 찾지 못했습니다. 위 셋 중 앞의 둘은 N-Queens 를 **예제와 성능 측정**으로
쓰는 자리이고, 마지막 하나가 같은 절차가 제품에 들어간 자리예요.

#### 경쟁 설계와의 대조

같은 목표를 노리는 **다른 절차**가 있어요 — **앞을 내다보는 검사**(forward checking)입니다. 퀸을 놓을
때마다 아직 안 채운 **모든 행**의 후보 열에서 그 열과 두 대각선을 지우고, 후보가 하나도 안 남는 행이 생기면
그 행까지 내려가기 전에 여기서 멈춥니다.

```text
이 가이드            (0,0) 을 놓는다 → 세 비트를 켠다 → 행 1 로 내려간다
                                      └ 행 2·3 의 후보는 그때 가서 본다

앞을 내다보는 검사   (0,0) 을 놓는다 → 행 1·2·3 의 후보에서 열 0 과 두 대각선을 지운다
                                      └ 후보가 빈 행이 생기면 행 1 로 내려가지 않는다
```

전개에 쓰는 `n = 4` 에서 먼저 세어 보면 차이가 몇 개에 그칩니다.

<!--proof:alt-small-->

| 설계 | n = 4 방문 노드 | n = 4 기본 연산 |
| --- | ---: | ---: |
| 이 가이드의 절차 | 17 | 228 |
| 앞을 내다보는 검사 | 13 | 127 |

방문 노드가 몇 개 차이라서, 그 차이가 절차의 성질에서 온 것인지 판이 작아서 그런 것인지 갈리지 않아요.
그래서 같은 입력 `n = 8` 에 둘을 적용해 **방문 노드 · 기본 연산 · 할당 칸**을 셌습니다. 입력은 난수 없이
`n` 하나라 시드가 없습니다. 두 설계는 상태를 다른 꼴로 들고 있어서 **기본 연산**의 1 이 다릅니다. 이 가이드는
비트 하나를 검사하거나 켜는 일(열 후보마다 검사 셋, 놓을 때 켜기 셋)이고, 앞을 내다보는 검사는 후보 배열의 칸을
다루는 일(노드마다 자기 행 후보 읽기 하나, 사본을 만들 때 칸마다 하나, 남은 행마다 읽기와 쓰기 둘)이에요.
**할당 칸**은 사본을 잡을 때마다 더한 누적 합이고, 가지를 접어 버린 사본도 셉니다. 재귀 스택은 넣지 않았어요.

| 설계 | 방문 노드 | 기본 연산 | 할당 칸 |
| --- | --- | --- | --- |
| 이 가이드의 절차 | 2,057 | 53,328 | **0** |
| 앞을 내다보는 검사 | **1,165** | **23,625** | 13,792 |

<!--proof:alt-unit-->

저쪽 남은 행 하나의 지우기를 칸 읽기 하나 · 비트 지우기 셋 · 칸 쓰기 하나로, 사본을 칸마다 읽기와 쓰기 둘로 잘게 쪼개 세면 앞을 내다보는 검사의 기본 연산이 23,625 에서 50,557 로 늘어납니다. 이 가이드의 53,328 보다는 여전히 적습니다.

<!--/proof-->

**두 축에서 앞을 내다보는 검사가 적습니다** — 방문 노드가 1,165 대 2,057 이고 기본 연산이 23,625 대 53,328
이에요. 이 가이드의 절차가 받는 것은 세 번째 축입니다. 후보 목록을 행마다 따로 둘 필요가 없어서 할당
칸이 **0** 이고, 저쪽은 재귀 한 단마다 길이 8 짜리 배열을 새로 만들어 **13,792 칸**을 씁니다.

```text
축을 넷으로 갈라 적으면
                    이 가이드            앞을 내다보는 검사
  방문 노드         2,057                1,165       ← 저쪽이 적다
  기본 연산         53,328               23,625      ← 저쪽이 적다
  할당 칸           0                    13,792      ← 이쪽이 적다
  한 노드의 일      비트 검사 3n 번      후보 지우기 n 번 + 배열 복사 n 칸
```

**우열이 반대가 되는 조건은 「한 노드를 방문하는 비용」입니다.** 이 과제에서 노드 하나가 하는 일은 비트
검사 `3n` 번이라, 방문 노드를 2,057 에서 1,165 로 줄이려고 13,792 칸을 새로 잡는 것이 남는 거래가 아니에요.
반대로 스도쿠처럼 한 칸을 판정하는 데 같은 행 · 열 · 상자의 칸을 여럿 확인해야 하는 과제라면 노드 수가 곧
총비용이 되어 순서가 뒤집힙니다. 어느 쪽이 우월한지가 아니라 **노드 하나가 얼마나 무거운가**가 선택을 정해요.

### 수식 정의와 유도

대각선 검사를 뺀 절차가 만드는 부분 배치의 수는 닫힌 형태로 적힙니다. 그 값이 이 절차의 상한이고, 실제로
방문하는 노드 수가 그 상한에서 얼마나 떨어져 있는지가 가지치기의 몫이에요.

```text
정의   깊이 k 에 있는 부분 배치의 수를 순열의 수로 적는다
  ↓
검산   그 정의를 n = 1 … 10 에 넣어 실제로 만든 수와 대조한다
  ↓
유도   깊이 0 부터 n 까지 더해 닫힌 형태로 만든다
  ↓
계수   그 식에 규모의 상단 n = 12 를 넣어 수치를 낸다
```

**먼저 정의입니다.** 열만 검사하는 절차에서 깊이 $k$ 의 부분 배치는 「서로 다른 열 $k$ 개를 행
$0 \dots k-1$ 에 순서를 지어 배정한 것」입니다. 그 수는 $n$ 개에서 $k$ 개를 뽑아 줄 세우는 경우의 수예요.

$$P(n, k) = \frac{n!}{(n-k)!}, \qquad k = 0, 1, \dots, n$$

| 기호 | 뜻 | 범위 |
| --- | --- | --- |
| $k$ | 지금까지 채운 행의 수, 곧 부분 배치의 깊이 | $0 \le k \le n$ |
| $P(n,k)$ | 깊이 $k$ 의 부분 배치 수 | $P(n,0) = 1$, $P(n,n) = n!$ |
| $S(n)$ | 깊이 0 부터 $n$ 까지를 다 더한 값, 곧 **열만 검사할 때의 노드 수** | 아래에서 닫는다 |

<!--proof:math-depths-->

```text
n = 4 의 깊이별 부분 배치 수 (열만 검사)

  깊이 0   1 개    4!/4! = 1   (빈 판)
  깊이 1   4 개    4!/3! = 4
  깊이 2   12 개   4!/2! = 12
  깊이 3   24 개   4!/1! = 24
  깊이 4   24 개   4!/0! = 24
            └ 합 65
```

**정의를 값에 넣어 검산해 봅시다.** 정의대로면 $S(n) = \sum_{k=0}^{n} P(n,k)$ 이고, 이 값이 실제로 만들어진
부분 배치 수와 같아야 합니다. 그 둘을 나란히 세면 이렇게 나와요.

<!--proof:closed-form-->

```text
n          n!  실제 노드    Σ n!/k!
1           1          2          2  같다
2           2          5          5  같다
3           6         16         16  같다
4          24         65         65  같다
6         720      1,957      1,957  같다
8      40,320    109,601    109,601  같다
10  3,628,800  9,864,101  9,864,101  같다
```

식을 그대로 코드로 옮기면 손 계산 없이 같은 수가 나옵니다. **뒤에서부터 곱해 올라가면** 큰 계승을 따로
구하지 않아도 돼요.

<!--proof:math-code-->

```ts
const 노드수 = (n: number): number => {
  let 합 = 0;
  let 항 = 1; // n!/n! = 1 에서 시작한다
  for (let k = n; k >= 0; k--) {
    합 += 항;
    항 *= k === 0 ? 1 : k; // n!/k! 에서 n!/(k-1)! 로 간다
  }
  return 합;
};

노드수(8); // → 109601
```

**이제 닫힌 형태를 유도합니다.** 합의 항을 $j = n - k$ 로 바꿔 쓰면 계승이 분모로만 남아요.

$$S(n) = \sum_{k=0}^{n} \frac{n!}{(n-k)!} = \sum_{j=0}^{n} \frac{n!}{j!} = n! \sum_{j=0}^{n} \frac{1}{j!}$$

<!--proof:math-reorder-->

```text
n = 4 로 확인하면 같은 항을 반대 순서로 더한 것이다
  Σ 4!/(4-k)!   k = 0 … 4   1 + 4 + 12 + 24 + 24 = 65
  Σ 4!/j!       j = 0 … 4   24 + 24 + 12 + 4 + 1 = 65
```

$\sum_{j=0}^{\infty} 1/j!$ 은 $e$ 입니다. 그러니 $S(n)$ 은 $e \cdot n!$ 에서 꼬리를 뺀 값이고, 그 꼬리가 얼마나
작은지를 재면 됩니다.

```text
꼬리 = e·n! - S(n) = n!·( 1/(n+1)! + 1/(n+2)! + … )
     = 1/(n+1) + 1/((n+1)(n+2)) + 1/((n+1)(n+2)(n+3)) + …

각 항을 위로 눌러 보면
     ≤ 1/(n+1) + 1/(n+1)² + 1/(n+1)³ + …      각 분모의 두 번째 인수부터가 n+1 이상이라
     = (1/(n+1)) / (1 - 1/(n+1))               공비 1/(n+1) 인 등비급수다
     = 1/n                                     n ≥ 1 이면 1 이하다
       └ 두 번째 항부터는 부등호가 엄격하다: 1/((n+1)(n+2)) < 1/(n+1)²
```

꼬리는 0 보다 크고 1 보다 작습니다. 0 보다 큰 것은 첫 항 $1/(n+1)$ 이 양수이기 때문이고, 1 보다 작은 것은 두
걸음을 거칩니다 — 두 번째 항부터 부등호가 엄격해서 꼬리가 $1/n$ 보다 **작고**, $n \ge 1$ 이면 $1/n$ 이 1
이하니까요. 정수 $S(n)$ 에 1 미만의 양수를 더한 것이 $e \cdot n!$ 이므로, $S(n)$ 은 $e \cdot n!$ 의 정수
부분입니다.

$$S(n) = \left\lfloor e \cdot n! \right\rfloor, \qquad n \ge 1$$

<!--proof:math-e4-->

```text
n = 4 로 검산하면
  e · 4!         2.71828… × 24 = 65.2388…   정수 부분 65
  실제 노드 수                              65
```

**마지막으로 계수입니다.** 규모의 상단 `n = 12` 를 넣고, 대각선 가지치기가 실제로 방문한 노드 수와 나란히
놓습니다.

<!--proof:n12-gap-->

```text
                                            노드 수
대각선 가지치기가 없을 때 (Σ 12!/k!)  1,302,061,345
실제 방문 노드                              856,189
차이                                         1521배
```

13억이 86만이 됐어요. 대각선 검사 세 줄이 하는 일이 이 차이이고, 상한 $\lfloor e \cdot n! \rfloor$ 은 **대각선이
아무것도 못 거를 때의 값**이라 N-Queens 에서는 도달하지 않습니다.

### 불변식 — 재귀 한 단을 부를 때마다 세 정수는 위 행들이 쓴 열·대각선과 정확히 같다

파트 1 에서 코드가 동작하는 것을 열일곱 걸음으로 봤습니다. 그런데 그건 `n = 4` 에서 맞았다는 뜻이지 언제나
맞는다는 뜻은 아니에요. 무엇이 **매 순간 참으로 남는지**를 문장으로 세우고, 그것이 실제로 유지되는지 확인해
봅시다.

> `place(row, cols, diag1, diag2)` 를 부르는 **그 시점마다**, `cols` 의 켜진 자리는 행 `0 … row−1` 에 놓인 퀸
> `row` 개의 열 번호 전부와 같고, `diag1` · `diag2` 의 켜진 자리는 그 퀸들의 `d1` · `d2` 번호 전부와 같으며,
> 그 `row` 개의 퀸끼리는 서로 공격하지 않는다.

<!--proof:invariant-state-->

```text
place(2) 에 들어오는 시점 (n = 4, (0,1)(1,3) 을 놓은 상태)
  cols    {1, 3}   놓인 열 {1, 3}
  diag1   {1, 2}   (0,1) → 0-1+3 = 2 · (1,3) → 1-3+3 = 1
  diag2   {1, 4}   (0,1) → 0+1 = 1 · (1,3) → 1+3 = 4
  두 퀸 — 열 · d1 · d2 가 모두 다르다
```

한 시점만 본 것이니, `n = 4 … 8` 의 모든 호출에서 들어오는 시점의 세 정수를 놓인 퀸에서 다시 계산해 대조했습니다.

<!--proof:invariant-all-->

| n | 대조한 호출 | 세 정수가 어긋난 호출 | 서로 공격하는 퀸이 있던 호출 |
| ---: | ---: | ---: | ---: |
| 4 | 17 | 0 | 0 |
| 5 | 54 | 0 | 0 |
| 6 | 153 | 0 | 0 |
| 7 | 552 | 0 | 0 |
| 8 | 2,057 | 0 | 0 |

「부르는 그 시점마다」가 중요합니다. 루프가 끝난 뒤 한 번만 참인 것이 아니라 **재귀가 한 단 내려갈 때마다**
참이라는 뜻이에요. 그래야 다음 단이 그 성질을 그대로 이어받습니다.

**출발점부터 봅시다.** `place(0, 0, 0, 0)` 에서 `row = 0` 이라 「행 `0 … −1` 에 놓인 퀸」이 하나도 없고, 세
정수도 전부 0 입니다. 「비어 있는 것끼리 같다」와 「퀸 0 개가 서로 안 부딪힌다」는 둘 다 참이에요. 그 뒤 이
호출이 상태를 다루는 자리는 넷입니다.

| 갈래 | 하는 일 | 불변식이 유지되는 근거 |
| --- | --- | --- |
| 다 채웠다 | `count++` 하고 반환 | 세 정수를 안 건드린다. 이 호출은 상태를 그대로 두고 끝난다 |
| 충돌이다 | `continue` | 세 정수를 안 건드린다. 판정만 하고 다음 열로 간다 |
| 놓는다 | 세 비트를 켜고 `place(row+1, …)` | 켠 자리는 `c` · `d1` · `d2` 셋이고, 이 셋은 판정을 통과했으니 켜기 전에 전부 0 이었다. 그래서 켠 뒤의 켜진 자리 수가 정확히 하나 늘고, 새 퀸이 기존 퀸들과 열 · `d1` · `d2` 어느 쪽으로도 겹치지 않는다 |
| 돌아왔다 | 세 비트를 `^` 로 끈다 | `d1` · `d2` 는 `row` · `c` 만으로 정해져 재귀 뒤에도 같은 값이다. 그 자리는 직전에 이 호출이 켰으므로 1 이고, 1 인 자리에 `^ 1` 을 하면 0 이다 |

네 갈래 중 어느 것도 「행 `0 … row−1` 이 쓴 것」과 세 정수를 어긋나게 하지 않아요. 그러니 `row = n` 에 도달한
시점의 상태는 퀸 `n` 개가 서로 안 부딪히는 배치이고, 그때만 `count` 가 늘어납니다. 경계에 있는 입력들도 같은
정의 위에서 확인됩니다.

<!--proof:invariant-edges-->

| 입력 | 만든 부분 배치 | 가장 깊이 채운 행 수 | 켜진 가장 큰 대각선 자리 | 결과 |
| --- | ---: | ---: | ---: | ---: |
| n = 1 | 2 | 1 | 0 | 1 |
| n = 2 | 3 | 1 | 1 | 0 |
| n = 3 | 6 | 2 | 3 | 0 |
| n = 12 | 856,189 | 12 | 22 | 14,200 |

`n = 1` 은 빈 판과 (0,0) 두 부분 배치로 끝나고, `n = 2` 는 행 하나를 채운 뒤 더 내려가지 못하며, `n = 3` 은 행
둘까지 채우고 막힙니다. `n = 12` 에서 켜진 가장 큰 대각선 자리도 32 비트 안이에요.

**이제 깨뜨려 봅시다.** 불변식을 지키던 줄이 어느 것인지는 지워 보면 확인됩니다. 세 비트를 켜는 쪽과 재귀
호출은 그대로 두고, **되돌리기 세 줄 중 `cols` 한 줄만** 없앱니다.

```ts
place(row + 1, cols, diag1, diag2);

// cols ^= 1 << c;   ← 이 줄만 지운다
diag1 ^= 1 << d1;
diag2 ^= 1 << d2;
```

실행하면 이렇게 나옵니다.

<!--proof:mutant-restore-->

```text
n  바른 코드  되돌리기를 뺀 코드
1          1                   1
4          2                   0
5         10                   1
6          4                   0
7         40                   0
8         92                   0
```

`n = 4` 부터 답이 틀리고, `n = 1` 만 1 로 남아요. `n = 1` 이 안 달라지는 이유는 형제 후보가 없기
때문입니다 — 행 0 에서 열 0 하나를 놓고 바로 `row = n` 에 도달해서, `cols` 가 남아 있어도 그것을 다시 읽는
호출이 없어요. `n = 4` 에서 무엇이 어긋나는지 값으로 보면 이렇습니다.

<!--proof:invariant-mutant-case-->

```text
행 0 에서 c=0 을 시도하고 돌아온 직후의 cols
  바른 코드                 {}
  cols 되돌리기를 뺀 코드   {0}

이어서 c=1 에 놓고 place(1) 에 넘기는 cols
  바른 코드                 {1}
  cols 되돌리기를 뺀 코드   {0, 1}
  └ 놓인 퀸은 (0,1) 하나인데 뺀 코드의 cols 에는 2 자리가 켜져 있다
```

불변식의 앞부분이 어긋난 것입니다. `place(1)` 에 들어온 시점의 `cols` 에 켜진 자리가 둘인데, 실제로 놓인 퀸은
(0,1) 하나뿐이에요. 열 0 이 그 아래 행에서 영영 「이미 쓰임」으로 남아 멀쩡한 배치가 세어지지 않습니다.

### 비용 계산

#### 비용을 세는 과정

한 번의 `place(row, …)` 호출이 하는 일은 열 `0` 부터 `n−1` 까지 판정하는 루프뿐입니다. 전개의 값으로 확인하면
T1 은 열 넷을 시도해 넷 다 ③ 이었고, T3 은 넷을 시도해 넷 다 ② 였으며, T9 는 `row === n` 이라 루프에 아예
들어가지 않았어요.

<!--proof:perf-tries-->

```text
T1   열 시도 4 번   ③ 4 번 · ② 0 번   자식 4
T3   열 시도 4 번   ③ 0 번 · ② 4 번   자식 0
T9   열 시도 0 번                     잎이다
     └ 잎이 아닌 호출은 예외 없이 정확히 n 번 시도한다
```

그러니 열 시도의 총합은 **`n` 곱하기 (노드 수 − 해의 수)** 입니다. 잎은 해가 나온 호출이고 그 수가 곧 답이에요.
세 크기에서 열 시도를 실제로 센 값이 이 식과 같습니다.

<!--proof:perf-total-->

```text
n = 4    4 × (17 - 2)              = 4 × 15         = 60
n = 8    8 × (2,057 - 92)          = 8 × 1,965      = 15,720
n = 12   12 × (856,189 - 14,200)   = 12 × 841,989   = 10,103,868
```

시도 한 번은 비트 검사 세 번이고, 통과했을 때 비트 설정이 세 번 더 붙습니다. 설정이 일어나는 횟수는 ③ 의
수인데, 그것은 뿌리를 뺀 노드 수와 같아요 — 자식 노드 하나마다 ③ 이 하나입니다.

<!--proof:perf-ops-->

```text
총 연산 = 3 × (열 시도) + 3 × (노드 수 - 1)

n = 8    3 × 15,720 + 3 × (2,057 - 1) = 47,160 + 6,168 = 53,328
         └ 「경쟁 설계와의 대조」 가 실측으로 낸 53,328 과 같은 값이다
```

#### 케이스별 비용과 그 경계

**N-Queens 는 케이스가 갈리지 않습니다.** 입력이 정수 `n` 하나라, 같은 `n` 이면 같은 순서로 같은 열을 시도해
언제나 같은 값이 나와요. 최선 · 평균 · 최악이 한 값입니다.

```text
왜 평균이 따로 정의되지 않는가
  크기 n 인 입력이 여러 개라야 그것들에 대한 평균을 말할 수 있다
  여기서는 크기 n 인 입력이 정확히 하나(= n 자신)뿐이다
       └ 평균 낼 모집단이 없다. 정렬에서 「입력 순열이 고르게 분포하면」에 해당하는 것이 없다
```

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축입니다. 케이스가 하나뿐이니 갈리는 것은
경계 쪽이에요.

| 판정 규칙 | 상한 `O` | 타이트 `Θ` |
| --- | --- | --- |
| **퀸** (같은 `n` 이면 한 값) | `O(n · n!)` | **알려져 있지 않다** |
| 대각선이 아무것도 못 거를 때 | `O(n · n!)` | `Θ(n · n!)` — 실제로 도달한다 |

상한이 `O(n · n!)` 인 근거는 앞 절의 닫힌 형태입니다. 노드 수가 $\lfloor e \cdot n! \rfloor$ 이하이고 노드
하나가 열을 `n` 번 시도하니, 곱한 것이 상한이에요. 타이트한 값이 알려져 있지 않다는 것은 실측 성장률로
확인됩니다.

<!--proof:growth-->

```text
n   방문 노드  직전 대비  n! 이었다면
4          17          —         4.00
5          54       3.18         5.00
6         153       2.83         6.00
7         552       3.61         7.00
8       2,057       3.73         8.00
9       8,394       4.08         9.00
10     35,539       4.23        10.00
11    166,926       4.70        11.00
12    856,189       5.13        12.00
```

직전 대비가 `n` 보다 한참 작고 천천히만 올라갑니다 — `n = 12` 에서도 5.13 이라 12 의 절반이 안 돼요. `n = 6`
에서 한 번 2.83 으로 내려가는데, 해의 수도 `n = 5` 의 10 개에서 `n = 6` 의 4 개로 줄어드는 자리입니다.
**총식을 한 번은 정확히 적습니다.**

```text
총 연산 = 3n · (N(n) - A(n))  +  3 · (N(n) - 1)
          └ 열 시도 3 번씩       └ 비트 설정 3 번씩

  N(n) = 실제 방문 노드 수    A(n) = 해의 수(= 이 함수의 답)
  「수식 정의와 유도」의 S(n) 은 열만 검사할 때의 노드 수이고, N(n) ≤ S(n) = ⌊e·n!⌋ 이다
  추가로 잡는 메모리는 없고 재귀 깊이가 정확히 n + 1 이다
```

**보장의 종류는 최악 보장입니다.** 코드에 난수가 하나도 없고 열을 `0` 부터 순서대로 시도해서, 같은 `n` 을 두 번
넣으면 언제나 같은 횟수가 나와요. 기대값이 아니라 확정값이고, 그래서 「평균은 빠른데 운이 나쁘면 느리다」 같은
위험이 이 절차에는 없습니다.

#### 최악을 만드는 입력

입력이 정수 하나라 최악을 만드는 일은 **규모의 상단을 고르는 것**입니다. `n = 12` 를 넣고 실제로 세면 이렇게
돼요.

<!--proof:perf-worst-->

```text
n = 12
  방문 노드   856,189
  열 시도     10,103,868 = 12 × (856,189 - 14,200)
  총 연산     32,880,168 = 3 × 10,103,868 + 3 × 856,188
       └ 초당 1 억 번 기준으로 0.3288 초. 1 초 안이다
```

그러면 상한 `O(n · n!)` 에 실제로 도달하는 입력은 무엇일까요? 이 코드에 넣을 수 있는 `n` 중에는 없고, **판의
규칙을 바꾸면** 있습니다. 퀸 대신 룩을 놓는 과제, 곧 대각선 제약이 없는 과제가 그것이에요 — 대각선 검사 두
줄이 아무것도 못 거르니 노드 수가 정확히 $\lfloor e \cdot n! \rfloor$ 이 됩니다(「수식 정의와 유도」가 `n ≤ 10`
에서 실제로 세어 대조했습니다).

<!--proof:perf-rook-->

```text
같은 절차, 판의 규칙만 다르게
  퀸 (대각선 제약 있음)   n = 12   856,189 노드
  룩 (대각선 제약 없음)   n = 12   1,302,061,345 노드 = ⌊e·12!⌋
       └ 상한은 룩 쪽에서 타이트하고, 퀸 쪽에서는 1521배 헐겁다
```

「`n` 이 홀수면 느리다」 같은 말은 이 실측에 없습니다. 직전 대비가 한 번 내려가는 자리는 `n = 6` 이고, 홀짝이
아니라 해의 수가 줄어드는 자리와 겹쳐요 — `n = 5` 는 해가 10 개인데 `n = 6` 은 4 개입니다.

### 스스로 점검하기

여기까지 다룬 것을 한 줄로 정리하면 이렇습니다. 배치를 끝까지 만들고 검사하던 것을 **한 행마다 검사하는
것**으로 바꿨고, 검사에 필요한 상태는 열과 두 대각선 셋이며, 그 셋을 정수의 비트에 담으면 확인도 설정도
되돌리기도 연산 한 번으로 끝납니다.

```text
행마다 하나씩 → 놓기 전에 세 비트 확인 → 켜고 내려간다 → 돌아와서 끈다
        └ 충돌이면 그 아래를 안 만든다      └ 이 한 줄이 다음 후보에게 판을 넘긴다
```

먼저 답이 붙는 문제 하나입니다. 전개의 T2 에서 행 1 의 네 열을 판정했는데 `c=0` 은 열 충돌, `c=1` 은 `\`
대각선 충돌이었어요. 만약 `c=1` 에서 `diag1` 대신 `diag2` 를 잘못 확인했다면 그 자리의 판정이 어떻게
바뀔까요?

<!--proof:selfcheck-t2-->

```text
T2  행 1, c=1 의 두 대각선 번호 — cols {0} · diag1 {3} · diag2 {0}
  d1 = 1 - 1 + 3 = 3   diag1 의 3 번 비트   1 → 충돌
  d2 = 1 + 1 = 2       diag2 의 2 번 비트   0 → 통과
```

<!--check:t2diag-->
`c=1` 이 통과해 버립니다. `diag2` 쪽 번호는 `d2 = 1 + 1 = 2` 인데, 행 0 의 퀸 (0,0) 이 켠 `diag2` 비트는 0
번뿐이라 2 번 비트가 꺼져 있기 때문이에요. (0,0) 과 (1,1) 은 실제로 같은 `\` 대각선이라 `d1` 을 봐야 잡힙니다.
<!--/check-->

```text
아래 셋은 답을 싣지 않았습니다. 막히면 이 절들을 다시 보세요
  1 → 수행으로 알아보는 알고리즘 의 T3      3 → 최악을 만드는 입력
  2 → 아이디어 상세 의 「매 행마다 검사하는 까닭」과 수식 정의와 유도
```

- T3 은 자식이 하나도 없는데 왜 노드 하나로 세는지, 그리고 세지 않으면 「비용을 세는 과정」의 열 시도 식이
  어떻게 어긋나는지 설명해 보세요.
- 「매 행마다 검사하는 까닭」의 표에서 `8 행마다` 검사하는 줄과, 「수식 정의와 유도」의 `n = 8` 열만 검사한

### N-Queens

풀 파일: [`nQueens.ts`](./nQueens.ts) · 테스트: [`nQueens.test.ts`](./nQueens.test.ts) · 실행: `bun test src/algorithms/advanced/nQueens/nQueens.test.ts`

#### 한 줄 요약

> $n$을 받아 $n \times n$ 체스판에 $n$개의 퀸을 서로 공격할 수 없게 놓는 방법의 수를 반환한다.

#### 스토리

체스 클럽 운영자 도윤은 신입 회원들에게 퀸의 공격 범위를 가르치는 교육 도구를 만들고 있다. 퀸은 같은 행, 같은 열, 같은 대각선 방향으로 얼마든지 이동할 수 있어서 서로를 공격할 수 있다.

도윤은 $n \times n$ 크기의 가상 체스판에 $n$개의 퀸을 올려놓되, 어느 두 퀸도 서로를 공격할 수 없도록 배치하는 예제를 여러 가지 보여주고 싶다. 그러기 위해 먼저 배치 방법이 몇 가지나 있는지를 미리 계산해두어야 한다.

$n$이 커질수록 가능한 배치가 폭발적으로 늘어나기 때문에, 중복 탐색 없이 빠르게 전체 경우의 수를 세는 방법이 필요하다.

#### 함수 인터페이스

```ts
export function nQueens(n: number): number;
```

- `n` — 체스판의 한 변의 길이이자 배치할 퀸의 수
- 반환 — $n$개의 퀸을 서로 공격할 수 없게 배치하는 방법의 수

#### 제약 조건

- $1 \leq n \leq 12$
- 시간 제한: 1초, 메모리 제한: 256 MB

#### 문제 상세

$n \times n$ 크기의 체스판에 $n$개의 퀸을 배치하되, 어느 두 퀸 $(r_1, c_1)$, $(r_2, c_2)$도 아래 세 조건 중 어느 하나도 만족하지 않아야 한다.

$$r_1 = r_2 \quad \text{(같은 행)}$$
$$c_1 = c_2 \quad \text{(같은 열)}$$
$$|r_1 - r_2| = |c_1 - c_2| \quad \text{(같은 대각선)}$$

이를 만족하는 배치의 수를 모두 세어 반환하라.

- $n = 2, 3$이면 해가 없으므로 0을 반환한다.
- $n = 1$이면 유일하게 하나의 배치만 존재한다.

#### 예시

```ts
nQueens(1);  //   1 — 1×1 보드, 유일한 배치
nQueens(2);  //   0 — 해 없음
nQueens(3);  //   0 — 해 없음
nQueens(4);  //   2 — 두 가지 배치 존재
nQueens(5);  //  10
nQueens(6);  //   4
nQueens(7);  //  40
nQueens(8);  //  92 — 고전적인 8-Queens 정답
nQueens(9);  // 352
nQueens(10); // 724
```
