# HashSet — 값 자리를 지운 해시맵

## 한눈에 보는 컨셉

집합은 "중복 없는 원소의 모음"이고, "이 원소가 있는가?"라는 질문에 빠르게 답하는 것이 핵심이에요. `HashSet`은 이미 O(1) 평균으로 키를 저장·조회하는 해시맵(`HashMapChaining`)을 그대로 재사용하되, 값 자리에는 의미 없는 더미(sentinel)만 채워 넣어 "키의 존재 여부"만 남깁니다. 그 결과 추가·조회·삭제는 O(1) 평균, 두 집합 사이의 합집합·교집합·차집합도 중첩 반복 없이 O(원소 수)에 끝나요.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 보이면 `HashSet`을 떠올리세요.

- "중복 없는 원소 모음"이 필요하고, "이 값이 이미 있는가?"라는 질문이 반복된다
- 두 그룹 사이의 **공통 원소(교집합)**, **전체 합(합집합)**, **한쪽에만 있는 원소(차집합)**를 자주 계산해야 한다
- 원소의 **정렬 순서**나 **등장 순서**는 중요하지 않다(순서가 필요하면 다른 구조를 고려)
- 원소 수가 커서($n$이 수만~수십만) 배열 선형 탐색으로는 버겁다

배열 기반 naive 접근과 비교하면 왜 해시가 필요한지 체감이 됩니다. 두 집합의 크기가 각각 $n$, $m$일 때:

```text
방식                     추가(add)        조회(has)        교집합(A ∩ B)
배열(중복 검사 없음)        O(1)            O(n) 선형탐색      O(n × m)
배열(중복 검사 포함)        O(n) includes    O(n) 선형탐색      O(n × m)
정렬 배열 + 이진 탐색       O(n) 이동        O(log n)          O(n log m)
HashSet(해시)              O(1) 평균        O(1) 평균          O(n)  ← other.has(x)를 O(1)로 재사용
```

제약이 $n \le 10^5$이면, naive 교집합은 $n \times m$이 최대 $10^{10}$에 달해 1초 안에 끝날 수 없습니다(대략 초당 $10^8$회 연산을 처리한다고 봐도 100배 넘게 초과). `HashSet`으로 바꾸면 $O(n)$이라 $10^5$ 규모로 줄어들어 여유 있게 통과합니다.

비슷한 용도의 다른 자료구조와는 이렇게 구분하세요: 정렬 순서를 유지하며 범위 질의("low 이상 high 이하 전부")까지 필요하면 정렬 트리 계열을, 원소마다 값도 함께 저장해야 하면 해시맵을, 등장 횟수까지 세야 하면 멀티셋을 대신 고려합니다. `HashSet`은 순수하게 "있다/없다"만 필요할 때가 정답이에요.

### 문제 사례와 적용 예시

- **소셜 네트워크 팔로우 추천**: 두 사용자가 공통으로 팔로우하는 계정(교집합), 둘 중 하나라도 팔로우하는 전체 계정(합집합), 한쪽만 팔로우하는 계정(차집합)을 계산해 추천에 활용합니다.
- **ETL 파이프라인의 중복 제거**: 대량 레코드를 적재하기 전에 이미 처리한 ID 집합에 있는지 확인해 중복 삽입을 막습니다.
- **그래프 탐색의 방문 집합**: BFS/DFS에서 "이 노드를 이미 방문했는가?"를 O(1)에 확인해 무한 루프를 막습니다.
- **컴파일러·린터의 예약어 집합**: 토큰이 예약어 집합에 속하는지 빠르게 확인해 파싱 분기를 결정합니다.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

**속성(내부 상태)** — `HashSet`은 자체 저장소를 두지 않고, 값 타입을 `true`로 고정한 해시맵 하나만 감쌉니다.

```text
HashSet(T)                        내부적으로 감싸는 HashMapChaining(T, true)

  ┌────────────────┐              buckets: 배열 (칸 수 = capacity)
  │   HashSet      │  ---wraps--->  각 칸은 [key, sentinel] 체인
  │   map: ......  │              sentinel 자리는 항상 true로 고정
  └────────────────┘

"값"이 필요 없으니 값 자리를 true로 못박아 버린 해시맵 = 집합
```

지켜야 할 불변식은 세 가지입니다.

1. 집합의 정의: 저장된 원소는 유일합니다.
   $$\forall x, y \in S,\ x \neq y \text{인 두 인덱스가 같은 값을 가리키지 않는다 (중복 없음)}$$
2. 멤버십과 내부 맵의 동치:
   $$x \in S \iff \text{map.has}(x) = \text{true}$$
3. 크기 일치:
   $$|S| = \text{map.size}()$$

**액션(연산)** — 이 가이드가 정의하는 인터페이스는 다음 여덟 가지입니다.

| 액션 | 시그니처 | 하는 일 | 비용 | 엣지 케이스 |
|------|---------|---------|------|-------------|
| `add` | `(item: T) -> void` | 원소 추가(이미 있으면 무시) | O(1) 평균 | 중복 추가 → size 불변 |
| `has` | `(item: T) -> boolean` | 존재 여부 확인 | O(1) 평균 | 빈 집합 → false |
| `delete` | `(item: T) -> boolean` | 원소 삭제, 성공 여부 반환 | O(1) 평균 | 없는 항목 → false |
| `size` | `() -> number` | 저장된 원소 수 | O(1) | 빈 집합 → 0 |
| `values` | `() -> T[]` | 모든 원소 배열로 반환 | O(n) | 빈 집합 → 빈 배열 |
| `union` | `(other: HashSet) -> HashSet` | 합집합을 새 집합으로 반환 | O(n + m) | 한쪽이 빈 집합 → 다른 쪽 복사본 |
| `intersection` | `(other: HashSet) -> HashSet` | 교집합을 새 집합으로 반환 | O(n) | 공통 원소 없음 → 빈 집합 |
| `difference` | `(other: HashSet) -> HashSet` | this에만 있는 원소를 새 집합으로 반환 | O(n) | other가 this를 포함 → 빈 집합 |

핵심 연산 두 개를 자세히 봅니다. 예시로 `alice = {"bob", "charlie", "dave"}`, `bobFollows = {"alice", "charlie", "eve"}`를 씁니다.

**① intersection — this를 순회하며 other.has로 거른다.**

$$A \cap B = \{\, x \mid x \in A \land \text{B.has}(x) \,\}$$

```text
Before: alice = {"bob", "charlie", "dave"},  bobFollows = {"alice", "charlie", "eve"}
        result = {}  (빈 새 HashSet)

alice의 각 원소를 bobFollows.has()로 확인:
  "bob"     → bobFollows.has("bob")     = false → 버림
  "charlie" → bobFollows.has("charlie") = true  → result.add("charlie")
  "dave"    → bobFollows.has("dave")    = false → 버림

After: result = {"charlie"}     (alice, bobFollows는 그대로 — 원본 불변)
```

**② union — 양쪽을 모두 add하고, 중복은 add가 알아서 무시한다.**

$$A \cup B = \{\, x \mid x \in A \lor x \in B \,\}$$

```text
Before: alice = {"bob","charlie","dave"}, bobFollows = {"alice","charlie","eve"}
        result = {}

alice 전부 add:       result = {"bob","charlie","dave"}
bobFollows 전부 add:  "alice"→추가, "charlie"→이미 있어 무시, "eve"→추가

After: result = {"bob","charlie","dave","alice","eve"}   size = 5
```

### 왜 모순 없이 작동하는가

**"중복 없음" 불변식이 보존되는 이유**는 `add`의 동작 하나로 귀납적으로 설명됩니다. `add(item)`은 항상 `map.set(item, true)`를 호출하는데, 이미 있는 키에 대한 `set`은 값을 덮어쓸 뿐 새 항목을 만들지 않습니다(맵의 정의). 빈 집합(불변식 성립)에서 시작해 `add`를 몇 번 호출하든, 매 호출이 불변식을 깨지 않으므로 임의 시퀀스 이후에도 집합은 여전히 중복이 없습니다.

**집합 연산이 원본을 바꾸지 않는 이유**는 `union`·`intersection`·`difference` 모두 새 `HashSet`을 만들고 그 결과에만 `add`를 호출하기 때문입니다. `this`와 `other`에 대해서는 `values()`(읽기)와 `has()`(읽기)만 호출하고, 어느 쪽도 삭제·수정하는 메서드를 부르지 않습니다.

**교집합의 정확성**은 "this를 순회하며(조건 1: $x \in A$) other.has(x)를 만족하는 것만 담는다(조건 2: $x \in B$)"는 구현이 $A \cap B$의 정의를 그대로 코드로 옮긴 것이기 때문에 성립합니다. 빠진 원소가 없다는 것은 this의 모든 원소를 순회하기 때문이고, 잘못 담긴 원소가 없다는 것은 `other.has(x)`를 통과한 것만 담기 때문입니다.

여기서 헷갈리기 쉬운 포인트 세 가지를 짚습니다.

- **sentinel 값을 falsy로 고르면 위험합니다.** `map.set(item, true)`가 아니라 실수로 `false`나 `0`을 sentinel로 쓰고, `has()` 대신 저장된 값을 그대로 진리값처럼 검사하면 어떻게 될까요? 실제로 `"x"`를 sentinel `false`로 저장한 뒤 "값이 있으면 true"라는 식으로 `found ? found[1] : false`를 계산하면, `"x"`가 분명히 저장돼 있는데도 결과는 `false`입니다("x"가 존재하는데 존재하지 않는 것처럼 보이는 거짓 음성). 존재 확인은 반드시 `has()`로 하거나, 값이 `undefined`인지로 비교해야 안전합니다.
- **`T`가 객체 타입이면 참조와 내용이 뒤섞입니다.** 문자열화(`String(key)`)로 해시를 계산하는 방식은 모든 일반 객체를 같은 문자열로 뭉갭니다. 그런데 같은 버킷 안에서 항목을 구분하는 비교는 참조 비교(`===`)입니다. 그래서 내용이 완전히 같은 객체(`{ id: 1 }`)를 서로 다른 리터럴로 두 번 `add`하면, 해시는 충돌해도 참조가 다르므로 **둘 다 저장돼 size가 2**가 됩니다 — 논리적으로는 같은 원소를 넣었다고 생각했는데 집합에는 둘이 들어있는 것입니다. 객체를 원소로 쓰려면 문자열 키로 정규화하거나 별도의 동등성 비교가 필요합니다.
- **`intersection`이 어느 쪽을 순회하는지가 비용을 가릅니다.** 지금 구현은 항상 `this`를 순회합니다. `this`가 100,000개, `other`가 3개짜리 집합이면 100,000번의 `has` 호출이 발생하는데, 반대로 순회했다면 3번으로 끝났을 일입니다. 결과값은 똑같이 옳지만(정확성은 그대로), 크기를 비교해 더 작은 쪽을 순회하도록 다듬을 여지가 있습니다.

잠깐, 확인 하나만 해 볼까요? `A`와 `B`가 완전히 같은 집합이라면 `A.difference(B)`는 무엇일까요? 정답은 빈 집합입니다 — `A`의 모든 원소가 `B`에도 있으니 `!other.has(x)` 조건을 하나도 통과하지 못하기 때문입니다.

엣지 케이스를 점검해 봅니다.

```text
빈 집합에 has/delete           → false (버킷은 있지만 체인이 비어있음)
빈 other와 union               → this의 복사본 그대로
빈 other와 intersection        → 반드시 빈 집합(공집합)
other가 this를 완전히 포함(⊇)  → this.difference(other) = 빈 집합
같은 원소를 여러 번 add        → size 변하지 않음(멱등)
```

## 아이디어를 코드로 옮기기

가이드가 정의한 인터페이스(생성자 기본 용량 16, 제네릭 타입 매개변수 `T`)에 맞춰 구현합니다. 먼저 원형(naive) 코드로 왜 O(n × m)이 문제인지 직접 확인하고, `has()` 기반으로 개선한 뒤, 최종 `HashSet` 클래스를 완성합니다.

**원형 — 배열 두 개를 중첩 순회.**

```ts
function naiveIntersection(a: string[], b: string[]): string[] {
  const result: string[] = [];
  for (const x of a) {
    if (b.includes(x)) result.push(x); // includes는 매번 최대 O(m) 선형 탐색
  }
  return result;
}
```

길이 2,000짜리 배열 두 개(겹치는 구간 없이 딱 절반만 겹치도록 구성)로 실측하면, `includes`가 일치하는 순간 멈추는 조기 종료 덕분에 이론상 상한 $n \times m = 4{,}000{,}000$보다는 적지만, 그래도 **총 2,500,500번**의 문자열 비교가 발생합니다(상한의 약 62%). 문제의 제약대로 $n = m = 10^5$이면 이 방식은 $10^{10}$ 자릿수까지 커져 1초 안에 끝나지 않습니다.

**개선 — 배열 순회는 그대로 두되, 안쪽 탐색을 O(1)로 바꾼다.**

```ts
function betterIntersection<T>(a: HashSetLike<T>, b: HashSetLike<T>): T[] {
  const result: T[] = [];
  for (const x of a.values()) {
    if (b.has(x)) result.push(x); // has는 O(1) 평균 — 선형 탐색이 사라진다
  }
  return result;
}
```

바깥 순회 횟수는 그대로 $n$번이지만, 안쪽 `includes`(O(m))가 `has`(O(1) 평균)로 바뀌면서 전체가 O(n × m)에서 O(n)으로 떨어집니다. 이 관찰을 그대로 담은 것이 최종 구현입니다.

**최종 — HashMapChaining을 감싸는 HashSet.**

```ts
class HashMapChaining<K, V> {
  private buckets: Array<Array<[K, V]>>;
  private capacity: number;
  private count = 0;
  private readonly LOAD_FACTOR = 0.75;

  constructor(initialCapacity: number = 16) {
    this.capacity = initialCapacity;
    this.buckets = Array.from({ length: this.capacity }, () => []);
  }

  private hash(key: K): number {
    const s = String(key);
    let h = 0;
    for (let i = 0; i < s.length; i++) {
      h = (h * 31 + s.charCodeAt(i)) % this.capacity;
    }
    return h;
  }

  private resize(): void {
    const old = this.buckets;
    this.capacity *= 2;
    this.buckets = Array.from({ length: this.capacity }, () => []);
    this.count = 0;
    for (const chain of old) {
      for (const [k, v] of chain) this.set(k, v);
    }
  }

  set(key: K, value: V): void {
    const idx = this.hash(key);
    const chain = this.buckets[idx]!;
    for (const pair of chain) {
      if (pair[0] === key) {
        pair[1] = value;
        return;
      }
    }
    chain.push([key, value]);
    this.count++;
    if (this.count / this.capacity > this.LOAD_FACTOR) this.resize();
  }

  has(key: K): boolean {
    const chain = this.buckets[this.hash(key)]!;
    return chain.some(([k]) => k === key);
  }

  delete(key: K): boolean {
    const chain = this.buckets[this.hash(key)]!;
    const idx = chain.findIndex(([k]) => k === key);
    if (idx === -1) return false;
    chain.splice(idx, 1);
    this.count--;
    return true;
  }

  size(): number {
    return this.count;
  }

  keys(): K[] {
    const result: K[] = [];
    for (const chain of this.buckets) for (const [k] of chain) result.push(k);
    return result;
  }
}

class HashSet<T> {
  private map: HashMapChaining<T, true>;

  constructor(initialCapacity: number = 16) {
    this.map = new HashMapChaining<T, true>(initialCapacity);
  }

  add(item: T): void {
    this.map.set(item, true);
  }

  has(item: T): boolean {
    return this.map.has(item);
  }

  delete(item: T): boolean {
    return this.map.delete(item);
  }

  size(): number {
    return this.map.size();
  }

  values(): T[] {
    return this.map.keys();
  }

  union(other: HashSet<T>): HashSet<T> {
    const result = new HashSet<T>();
    for (const x of this.values()) result.add(x);
    for (const x of other.values()) result.add(x);
    return result;
  }

  intersection(other: HashSet<T>): HashSet<T> {
    const result = new HashSet<T>();
    for (const x of this.values()) {
      if (other.has(x)) result.add(x);
    }
    return result;
  }

  difference(other: HashSet<T>): HashSet<T> {
    const result = new HashSet<T>();
    for (const x of this.values()) {
      if (!other.has(x)) result.add(x);
    }
    return result;
  }
}
```

가장 중요한 부분은 `add`의 `this.map.set(item, true)` 한 줄입니다 — 값 자리를 항상 `true`로 고정해서 "키의 존재"만 남기고 "값의 의미"를 지워버리는 지점이 바로 여기예요. 놓치기 쉬운 부분을 짚어 둡니다.

- `union`·`intersection`·`difference`는 셋 다 **새 `HashSet`을 만들고 그 결과에만 add**합니다. `this`나 `other`에 직접 `add`/`delete`를 부르는 순간 원본 불변 원칙이 깨집니다.
- `intersection`·`difference`는 겉보기엔 거의 같은 코드지만 조건이 정반대입니다. `other.has(x)`면 담는 것이 교집합, `!other.has(x)`면 담는 것이 차집합이에요. `!`를 빠뜨리면 두 연산이 뒤바뀝니다.
- sentinel은 항상 `true`로 고정하세요. 값 타입을 바꾸고 싶어질 수 있지만, falsy 값을 쓰면 위 "헷갈리기 쉬운 포인트"에서 본 거짓 음성이 재현됩니다.

> 값이 필요 없으면 값 자리를 비우고, 존재만 물어보면 된다 — 그게 Set이다.

## 실행 시각화

용량(capacity) 8인 `alice` 집합에 `"bob"`, `"charlie"`, `"dave"`를 차례로 추가한 뒤, `"alice"`, `"charlie"`, `"eve"`를 담은 `bobFollows`와 교집합을 계산합니다. 본문의 `hash(key) = (h × 31 + charCode) % capacity` 공식을 손으로 계산하면 다음과 같습니다(모두 실제 코드 실행 결과와 일치).

```text
hash("bob", capacity=8):
  h = 0
  'b'(98):  h = (0×31 + 98)  % 8 = 2
  'o'(111): h = (2×31 + 111) % 8 = 5
  'b'(98):  h = (5×31 + 98)  % 8 = 5
  → 최종 버킷 = 5

같은 방식으로: hash("charlie", 8) = 2,  hash("dave", 8) = 4
```

버킷 배치가 삽입 순서와 다르므로, `alice.values()`가 내부 버킷 순서(2 → 4 → 5)로 도는 실제 순회 결과는 `["charlie", "dave", "bob"]`입니다. 이 순서 그대로 `bobFollows.has(x)`를 확인하면 `alice.intersection(bobFollows).values()`는 `["charlie"]`, `alice.union(bobFollows).size()`는 `5`, `alice.difference(bobFollows).values()`(정렬)는 `["bob", "dave"]`입니다 — 모두 실제 실행값입니다.

정리하면, `HashSet`은 이미 O(1) 평균을 보장하는 해시맵의 값 자리를 `true`로 고정해 얻는 자료구조입니다. `add`·`has`·`delete`가 O(1) 평균인 것은 내부 해시맵의 성능을 그대로 물려받기 때문이고, `union`이 O(n + m), `intersection`·`difference`가 O(n)인 것은 안쪽 탐색을 배열 선형 탐색이 아니라 `has()` 호출로 바꿨기 때문입니다. naive 배열 방식의 O(n × m)과 비교하면, $n = m = 10^5$ 규모에서 격차는 $10^{10}$ 대 $10^5$로 다섯 자릿수 차이가 나며, 이것이 애초에 이 자료구조를 쓰는 이유입니다.
