# IntervalTree — 구간의 끝점을 트리에 함께 새겨넣기

## 한눈에 보는 컨셉

구간(`[low, high]`) 집합을 BST로 관리하되, 각 노드에 "이 아래 서브트리에 있는 구간들의 최대 high 값(`maxHigh`)"을 하나 더 저장하는 자료구조예요. 이 값 하나 덕분에 "이 서브트리엔 답이 없다"를 즉시 판단하고 가지를 통째로 잘라낼 수 있습니다. 결과적으로 삽입·삭제·단건 겹침 확인은 $O(\log n)$, 겹치는 구간 전부를 모으는 질의는 $O(k + \log n)$($k$ = 결과 수)에 끝납니다.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 보이면 구간 트리를 떠올리세요.

- 구간들이 **계속 삽입·삭제**되면서 동시에 "이 점/구간과 겹치는 것 전부"를 반복해서 물어야 한다
- 정렬 배열 + 이진 탐색을 시도했는데, "start로 정렬해도 end가 들쭉날쭉해서" 어디까지 훑어야 할지 판단이 안 선다
- 겹침 판정이 **단순 크기 비교가 아니라 두 조건의 AND**(`l₁ ≤ h₂ AND l₂ ≤ h₁`)라 이진 탐색의 단조성이 깨진다

비용을 naive 접근과 비교하면 이렇습니다.

```text
                    배열 순회        정렬 배열+이분탐색       구간 트리
삽입                O(1)            O(n) (재정렬)           O(log n)
삭제                O(n)            O(n)                    O(log n)
단건 겹침 확인      O(n)            O(n) ← start만 정렬해선   O(log n)
                                     end 분포 때문에 못 자름
전체 겹침 반환      O(n)            O(n)                     O(k + log n)
```

k = 결과로 나오는 구간 수. 겹치는 구간이 적을수록 구간 트리의 이점이 커집니다.

비슷한 용도의 **세그먼트 트리**와는 쓰임이 갈립니다 — 좌표가 미리 정해진 고정 배열 위에서 "구간 합/최솟값"처럼 값을 접어야 한다면 세그먼트 트리, 구간 자체가 동적으로 삽입·삭제되고 "어떤 구간들이 겹치는가"를 물어야 한다면 구간 트리입니다.

### 문제 사례와 적용 예시

- **회의실/캘린더 예약 충돌 감지**: `[startTime, endTime]`로 저장된 예약들 중 새 요청과 겹치는 것을 즉시 찾아냅니다.
- **컴퓨터 지오메트리 스윕 라인**: 도형을 x축으로 쓸어가며 "지금 이 x에서 y축 구간들이 서로 겹치는가"를 유지해야 할 때 구간 트리가 스윕 상태를 담습니다.
- **유전체(genomic) 구간 겹침 분석**: 염기서열 구간(엑손, 변이 위치 등)들이 특정 영역과 겹치는지 대량으로 질의하는 생물정보학 도구.
- **코딩 테스트 맥락**: "구간이 실시간으로 추가·삭제되는 와중에 특정 점/구간과 겹치는 것 전부를 반환하라" — 정적인 "겹치는 구간 병합" 문제와 달리 동적 삽입·삭제가 섞이면 정렬 후 병합만으로는 부족해 구간 트리가 필요해집니다.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

**속성(내부 상태)** — 노드 하나는 이렇게 생겼습니다.

```ts
class ITNode {
  low: number;        // 구간 시작 (BST 정렬 기준)
  high: number;        // 구간 끝
  maxHigh: number;      // 이 노드를 루트로 하는 서브트리 전체의 high 최댓값
  data: unknown;        // 구간에 연결할 임의 데이터
  left: ITNode | null;
  right: ITNode | null;
}
```

트리 전체는 `root`와 원소 수 `_size`를 유지합니다. 지켜야 할 불변식은 세 가지예요.

1. **BST 순서**: 모든 노드에서, 왼쪽 서브트리의 모든 구간은 `low`가 이 노드보다 작거나(같으면 `high`가 더 작고), 오른쪽 서브트리는 그 반대다.
2. **maxHigh 정의**: $\text{node.maxHigh} = \max(\text{node.high},\ \text{node.left?.maxHigh},\ \text{node.right?.maxHigh})$ — 이 노드 자신의 high와 양쪽 서브트리의 maxHigh 중 최댓값.
3. **비어있지 않은 구간**: 모든 저장된 구간은 $low \leq high$.

`t=root`부터 작은 예로 그려보면:

```text
              [9, 11]  maxHigh=16
                    \
                  [14, 16]  maxHigh=16
                    /
                [10, 12]  maxHigh=12

루트의 maxHigh(16)는 자기 high(11)가 아니라
오른쪽 서브트리 어딘가에 있는 16에서 왔다 — 자기 값이 최댓값이 아닐 수 있다!
```

**액션(연산)**은 다음 다섯 가지입니다.

| 액션 | 하는 일 | 비용 |
|------|---------|------|
| `insert(low, high, data?)` | BST 위치에 삽입 후 경로 상 maxHigh 갱신 | $O(\log n)$ |
| `delete(low, high)` | 정확히 일치하는 구간을 찾아 제거, 성공 여부 반환 | $O(\log n)$ |
| `stabQuery(point)` | `low ≤ point ≤ high`인 구간 전부 반환 | $O(k + \log n)$ |
| `overlapQuery(low, high)` | 주어진 구간과 겹치는 구간 전부 반환 | $O(k + \log n)$ |
| `size()` | 저장된 구간 수 | $O(1)$ |

핵심 연산 두 개만 자세히 볼게요.

**① insert — maxHigh를 되돌아오며 갱신**. `[9,11]` → `[14,16]` → `[10,12]` 순서로 넣으면:

```text
insert(9,11):        [9,11] maxHigh=11                (루트)

insert(14,16):       9 < 14 → 오른쪽 자식
                      [9,11] maxHigh=max(11,16)=16
                            \
                          [14,16] maxHigh=16

insert(10,12):        9 < 10 → 오른쪽,  14 > 10 → 왼쪽
                      [9,11] maxHigh=16 (변화 없음, 이미 16이 더 큼)
                            \
                          [14,16] maxHigh=max(16,12)=16 (변화 없음)
                            /
                        [10,12] maxHigh=12
```

재귀 호출이 되돌아 나올 때마다(리프에서 루트 방향으로) `maxHigh`를 다시 계산하는 것이 핵심이에요 — 삽입 방향으로 내려갈 때가 아니라 **돌아 나올 때** 갱신합니다.

**② overlapQuery — maxHigh로 가지치기**. 위 트리에서 `overlapQuery(10, 12)`를 실행하면:

```text
1단계: 루트[9,11]. maxHigh=16 ≥ lo(10) → 진입.
       9≤12 AND 10≤11 → 겹침! [9,11] 채택.
       왼쪽 자식 없음 → 스킵.
       node.low(9) ≤ hi(12) → 오른쪽 자식 진입.

2단계: [14,16]. maxHigh=16 ≥ 10 → 진입(가지치기 안 됨).
       왼쪽 자식 [10,12] 먼저 재귀:
         10≤12 AND 10≤12 → 겹침! [10,12] 채택.
       [14,16] 자신은 low(14) ≤ hi(12)? 거짓 → 겹침 아님, 오른쪽도 스킵.

결과: [[9,11], [10,12]]   ([14,16]은 방문은 했지만 제외)
```

### 왜 모순 없이 작동하는가

**maxHigh 불변식이 삽입마다 보존되는 이유**: 빈 트리는 자명하게 성립합니다(노드가 없음). 삽입은 새 리프를 붙인 뒤 그 경로를 되짚어 올라오며 `node.maxHigh = max(node.high, left?.maxHigh, right?.maxHigh)`를 다시 계산합니다. 이 재계산은 정의 그 자체이므로, 경로 상의 모든 조상이 재계산을 거치면 트리 전체가 다시 불변식을 만족합니다. 삭제도 마찬가지로 — 노드를 제거하거나 successor로 대체한 뒤 같은 경로를 되짚어 올라오며 재계산합니다.

**가지치기가 안전한 이유**: `maxHigh`는 서브트리 안 **모든** 구간의 high 중 최댓값입니다. `stabQuery`가 point를 포함하려면 어떤 구간이든 `high ≥ point`를 만족해야 하는데, `maxHigh < point`라면 그 서브트리의 어떤 구간도 이 조건을 만족할 수 없습니다 — 최댓값조차 point에 못 미치니까요. `overlapQuery`도 같은 논리로, `maxHigh < lo`면 서브트리의 모든 구간이 질의 구간보다 먼저 끝나 겹칠 수 없습니다.

**여기서 헷갈리기 쉬운 포인트는 "왼쪽과 오른쪽을 대칭으로 가지치기해도 되는가"입니다.** 정답은 아니오예요. BST 순서상 오른쪽 서브트리는 `low`가 이 노드보다 크거나 같으므로, `node.low > point`(또는 `hi`)라면 오른쪽 서브트리 전체가 `low > point`라 매칭이 불가능합니다 — 그래서 `if (node.low <= point) { ... 오른쪽 재귀 ... }`로 오른쪽만 조건부로 들어갑니다. 그러나 **왼쪽 서브트리는 `low`가 이 노드보다 작을 뿐** 얼마나 작은지, `high`가 얼마나 큰지는 전혀 보장이 없습니다. 그래서 왼쪽은 `maxHigh` 가지치기에만 의존해 **항상** 재귀해야 합니다.

이 구분을 놓치면 실제로 결과를 놓칩니다. `maxHigh`가 없는 순수 BST에 "low가 이미 질의 범위보다 크면 이 아래는 다 스킵"이라는 성급한 가지치기를 넣으면 어떻게 될까요? 루트가 `[20,25]`, 그 왼쪽 자식이 `[5,8]`인 트리에서 `overlapQuery(3, 6)`을 실행해 봅시다. 진짜 정답은 `[5,8]`(5≤6 AND 3≤8 → 겹침)이지만, `node.low(20) > hi(6)`이라는 이유로 루트에서 곧바로 멈추면 **왼쪽 자식 [5,8]은 아예 방문되지 않고** 결과는 빈 배열이 됩니다. 왼쪽 서브트리의 low는 루트보다 작을 뿐 hi와 아무 관계가 없다는 것을 잊은 대가입니다.

엣지 케이스 점검:

```text
빈 트리                   → stabQuery/overlapQuery는 [], delete는 false
노드 1개                  → maxHigh = 자기 high, 정상 동작
경계에서 접하는 구간       → overlapQuery(10,12)에 저장된 [9,11]: 겹침(교집합 {11} 존재)
동일 low, 다른 high        → high를 보조 기준으로 BST 순서 결정(작은 high가 왼쪽)
음수 구간                  → low/high 비교는 정수 비교와 동일해 그대로 성립
두 자식을 가진 노드 삭제   → 오른쪽 서브트리의 최솟값(successor)으로 값을 옮기고 그 successor를 재귀 삭제
```

잠깐 확인 하나만 해 볼까요? 루트가 `[9,11]`(오른쪽 자식 `[14,16]`, 그 왼쪽에 `[10,12]`)인 트리에서 `stabQuery(11)`을 호출하면 무엇이 나올까요? → `[9,11]`과 `[10,12]` 둘 다 11을 포함하므로 `[[9,11], [10,12]]`입니다(뒤에서 실행 결과로 다시 확인합니다).

> 기억법: "오른쪽은 low로 자른다, 왼쪽은 maxHigh로만 자른다."

## 아이디어를 코드로 옮기기

가장 만만한 원형부터 시작해서, 흔한 실수를 거쳐, 최종 구현까지 단계별로 올라가 볼게요.

**원형(brute force)** — 배열에 구간을 넣고 매번 선형 스캔합니다.

```ts
function arrayOverlap(
  intervals: Array<[number, number]>,
  lo: number,
  hi: number,
): Array<[number, number]> {
  return intervals.filter(([l, h]) => !(hi < l || h < lo));
}
```

`[[20,25],[5,8]]`에 `overlapQuery(3,6)`을 걸면 `[[5,8]]`이 나옵니다 — 맞는 답이지만 매번 전체를 훑으니 $O(n)$입니다.

**개선(하지만 버그가 있는 시도)** — "그럼 BST로 정렬해서 자르면 되지 않을까?"라는 생각으로, `maxHigh` 없이 `low`만으로 가지치기를 시도해 봅니다.

```ts
function naiveOverlapBuggy(
  node: NaiveITNode | null,
  lo: number,
  hi: number,
  result: Array<[number, number]>,
): void {
  if (node === null) return;
  if (node.low > hi) return; // 버그: 왼쪽 서브트리까지 통째로 포기해 버린다
  if (node.low <= hi && lo <= node.high) result.push([node.low, node.high]);
  naiveOverlapBuggy(node.left, lo, hi, result);
  naiveOverlapBuggy(node.right, lo, hi, result);
}
```

앞서 본 대로, 루트 `[20,25]`·왼쪽 자식 `[5,8]`인 트리에서 `overlapQuery(3,6)`을 걸면 이 코드는 루트에서 `node.low(20) > hi(6)`이 참이라 **즉시 return**해 버립니다. 실제 실행 결과는 `[]` — 정답 `[[5,8]]`을 완전히 놓칩니다. `low > hi`라는 조건은 "이 노드 자신"에 대해서는 의미가 있어도, 왼쪽 서브트리 전체를 포기할 근거는 전혀 못 됩니다.

**최종(augmented BST)** — `maxHigh`를 추가해 "이 서브트리 전체에 답이 있을 수 있는가"를 정확히 판단합니다.

```ts
class ITNode {
  low: number;
  high: number;
  maxHigh: number;
  data: unknown;
  left: ITNode | null = null;
  right: ITNode | null = null;

  constructor(low: number, high: number, data?: unknown) {
    this.low = low;
    this.high = high;
    this.maxHigh = high;
    this.data = data;
  }
}

class IntervalTree {
  private root: ITNode | null = null;
  private _size = 0;
  private deletedFlag = false;

  insert(low: number, high: number, data?: unknown): void {
    this.root = this.insertNode(this.root, low, high, data);
    this._size++;
  }

  private insertNode(node: ITNode | null, low: number, high: number, data?: unknown): ITNode {
    if (node === null) return new ITNode(low, high, data);

    if (low < node.low || (low === node.low && high < node.high)) {
      node.left = this.insertNode(node.left, low, high, data);
    } else {
      node.right = this.insertNode(node.right, low, high, data);
    }
    // 삽입 경로를 되돌아 나오면서 maxHigh를 상향식으로 갱신 — 가장 중요한 줄
    node.maxHigh = Math.max(node.high, node.left?.maxHigh ?? -Infinity, node.right?.maxHigh ?? -Infinity);
    return node;
  }

  delete(low: number, high: number): boolean {
    this.deletedFlag = false;
    this.root = this.deleteNode(this.root, low, high);
    if (this.deletedFlag) this._size--;
    return this.deletedFlag;
  }

  private deleteNode(node: ITNode | null, low: number, high: number): ITNode | null {
    if (node === null) return null;

    if (low < node.low || (low === node.low && high < node.high)) {
      node.left = this.deleteNode(node.left, low, high);
    } else if (low > node.low || (low === node.low && high > node.high)) {
      node.right = this.deleteNode(node.right, low, high);
    } else {
      // low === node.low && high === node.high → 이 노드가 삭제 대상
      this.deletedFlag = true;
      if (node.left === null) return node.right;
      if (node.right === null) return node.left;
      // 자식이 둘 다 있으면 오른쪽 서브트리의 최솟값(inorder successor)으로 값만 교체하고
      // 그 successor를 오른쪽 서브트리에서 실제로 지운다.
      let successor = node.right;
      while (successor.left !== null) successor = successor.left;
      node.low = successor.low;
      node.high = successor.high;
      node.data = successor.data;
      node.right = this.deleteNode(node.right, successor.low, successor.high);
    }
    node.maxHigh = Math.max(node.high, node.left?.maxHigh ?? -Infinity, node.right?.maxHigh ?? -Infinity);
    return node;
  }

  stabQuery(point: number): Array<[number, number]> {
    const result: Array<[number, number]> = [];
    this.stabNode(this.root, point, result);
    return result;
  }

  private stabNode(node: ITNode | null, point: number, result: Array<[number, number]>): void {
    if (node === null || node.maxHigh < point) return; // 가지치기: 이 서브트리엔 답이 없다
    this.stabNode(node.left, point, result); // 왼쪽은 항상 — maxHigh로만 판단 가능
    if (node.low <= point) {
      if (point <= node.high) result.push([node.low, node.high]);
      this.stabNode(node.right, point, result); // 오른쪽은 low<=point일 때만
    }
  }

  overlapQuery(low: number, high: number): Array<[number, number]> {
    const result: Array<[number, number]> = [];
    this.overlapNode(this.root, low, high, result);
    return result;
  }

  private overlapNode(
    node: ITNode | null,
    lo: number,
    hi: number,
    result: Array<[number, number]>,
  ): void {
    if (node === null || node.maxHigh < lo) return;
    this.overlapNode(node.left, lo, hi, result);
    if (node.low <= hi) {
      if (lo <= node.high) result.push([node.low, node.high]);
      this.overlapNode(node.right, lo, hi, result);
    }
  }

  size(): number {
    return this._size;
  }
}
```

가장 중요한 부분은 `insertNode`/`deleteNode` 맨 끝의 `node.maxHigh = Math.max(...)` 한 줄입니다. 이 줄이 빠지면 삽입·삭제 후 조상 노드들의 `maxHigh`가 낡은 값으로 남고, 이후의 모든 질의가 그 낡은 값을 근거로 가지치기하다가 존재하는 답을 조용히 놓칩니다.

놓치기 쉬운 지점 세 가지:

- **오른쪽만 `node.low <= threshold`로 가지치기하고, 왼쪽은 항상 재귀합니다.** 앞서 본 버그 사례가 바로 이 원칙을 어겼을 때 벌어지는 일입니다.
- **동일 low 처리**: `low === node.low && high < node.high` 일 때만 왼쪽, 나머지(`high`가 같거나 큰 경우 포함)는 오른쪽 — 그래야 `delete`가 정확히 같은 `(low, high)` 노드를 유일하게 찾아갑니다.
- **삭제에서 자식이 둘인 경우 successor로 값만 옮기고, successor 자체는 오른쪽 서브트리에서 재귀 삭제로 지웁니다.** `node.right = this.deleteNode(node.right, successor.low, successor.high)`를 빠뜨리면 successor가 트리에 중복으로 남습니다.

## 실행 시각화
