# GraphAdjList — 정점마다 제 이웃만 들고 다니기

## 한눈에 보는 컨셉

그래프의 각 정점이 "나와 연결된 이웃 목록"만 따로 들고 있는 표현 방식이에요. 정점 $v$를 키로, `{이웃 정점, 가중치}` 배열을 값으로 하는 `Map`이 구조의 전부입니다. 존재하는 간선만 저장하므로 공간이 $O(V+E)$로 끝나고, 이웃 순회(BFS/DFS)가 "그 정점의 배열만 훑으면 되는" 자연스러운 연산이 됩니다.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 보이면 인접 리스트를 떠올리세요.

- 정점 수 $V$는 크지만 간선 수 $E$는 그보다 훨씬 작다(희소 그래프, Sparse Graph) — 소셜 네트워크, 도로망, 의존성 그래프가 전형적입니다.
- "이 정점과 연결된 이웃들만 보고 싶다"는 질의(순회, BFS/DFS)가 반복된다.
- 정점 번호가 듬성듬성하거나 미리 몇 개인지 모른 채 점진적으로 추가된다(`addVertex`를 나중에 호출).

인접 행렬(모든 정점 쌍을 $V \times V$ 표에 저장)과 비교하면 차이가 뚜렷합니다.

```text
연산                 인접 리스트(adjList)   인접 행렬(matrix)   간선 리스트(edge list)
공간                 O(V + E)               O(V²)               O(E)
addEdge              O(1)                   O(1)                O(1)
hasEdge(u, v)        O(degree(u))           O(1)                O(E)
neighbors(v) 순회     O(degree(v))           O(V)                O(E)
BFS / DFS 전체        O(V + E)               O(V²)               O(V·E)
```

정점 100만 개짜리 소셜 그래프를 인접 행렬로 담으면 $10^{12}$ 칸이 필요해요 — 애초에 불가능합니다. 반면 각자 평균 친구 수가 수백 명이면 인접 리스트는 그 실제 연결 수만큼만 공간을 씁니다.

**선택 기준**: 간선이 조밀해서 $E \approx V^2$에 가깝거나 "두 정점이 연결됐는가"를 $O(1)$에 자주 물어야 하면 인접 행렬이 유리합니다. 간선이 희소하고 "이 정점의 이웃 전부"를 자주 순회한다면 인접 리스트를 씁니다.

### 문제 사례와 적용 예시

- **소셜 네트워크 친구 추천**: A가 B를 팔로우하면 A→B 간선을 추가하고, BFS로 "내 친구의 친구"(2-hop 이웃)를 찾아 추천합니다.
- **지도/내비게이션 도로망**: 교차로가 정점, 도로가 간선입니다. 실제 도로망은 각 교차로가 몇 개 도로와만 만나는 극도로 희소한 그래프예요.
- **빌드 시스템·패키지 매니저 의존성 그래프**: 패키지 A가 B에 의존하면 A→B 간선. DFS로 의존성을 순회하거나 위상 정렬의 기초 자료가 됩니다.
- **코딩 테스트 맥락**: "간선 목록이 주어지고 두 정점 사이 경로가 있는지, 혹은 BFS 방문 순서를 구하라"는 문제의 표준 입력 표현입니다.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

**속성(내부 상태)** — 이 가이드에서 정의하는 인터페이스입니다.

```ts
interface Edge {
  vertex: number; // 이웃 정점 번호
  weight: number; // 간선 가중치 (기본값 1)
}

class GraphAdjList {
  private adjList: Map<number, Edge[]>; // 정점 → 이웃 목록
  private directed: boolean; // true면 방향 그래프
  private _edgeCount: number; // 논리 간선 수(호출 기준)
}
```

지켜야 할 불변식은 다섯 가지예요.

1. `addVertex(v)`가 한 번이라도 호출된 정점은 `adjList`에 키로 존재하며, 간선이 없어도 빈 배열로 남는다(고립 정점 허용).
2. 무방향($\text{directed} = \text{false}$)이고 $u \neq v$이면, 다음 대칭이 항상 성립한다.
   $$\#\{e \in adjList[u] : e.vertex = v\} = \#\{e \in adjList[v] : e.vertex = u\}$$
3. 자기 루프($u = v$)는 대칭 복제를 하지 않는다 — `addEdge(u, u)` 한 번은 `adjList[u]`에 항목을 1개만 남긴다.
4. 멀티 엣지를 허용한다 — 같은 $(u, v)$ 쌍에 `addEdge`를 $k$번 호출하면 목록에 $k$개의 항목이 그대로 쌓인다(중복 제거 없음).
5. $\text{\_edgeCount} = (\text{성공한 addEdge 호출 수}) - (\text{성공한 removeEdge 호출 수})$ — 무방향이라 내부적으로 항목이 2개 늘어도 논리 간선은 1개로 센다.

간선 `0-1`, `0-2`, `1-3`, `1-4`(무방향)를 넣은 뒤의 실제 상태를 그려 보면 이렇습니다.

```text
adjList: Map<number, Edge[]>
┌─────┬─────────────────────────────────────────────────┐
│ key │ value (인접 목록)                                  │
├─────┼─────────────────────────────────────────────────┤
│  0  │ [{vertex:1,weight:1}, {vertex:2,weight:1}]        │
│  1  │ [{vertex:0,weight:1}, {vertex:3,weight:1}, {vertex:4,weight:1}]
│  2  │ [{vertex:0,weight:1}]                             │
│  3  │ [{vertex:1,weight:1}]                             │
│  4  │ [{vertex:1,weight:1}]                             │
└─────┴─────────────────────────────────────────────────┘
```

**액션(연산)** — 이 가이드가 구현하는 9종 전부입니다.

| 액션 | 하는 일 | 비용 |
|------|---------|------|
| `addVertex(v)` | 정점 키를 빈 배열로 등록(이미 있으면 무시) | $O(1)$ |
| `addEdge(u, v, w=1)` | u의 목록에 v 추가, 무방향이면 v의 목록에도 u 추가 | $O(1)$ |
| `removeEdge(u, v)` | u→v 항목 1개 제거(무방향이면 v→u도 1개) | $O(\deg(u))$ |
| `neighbors(v)` | v의 인접 목록 참조 반환 | $O(1)$ (순회하면 $O(\deg(v))$) |
| `bfs(start)` | 너비 우선 방문 순서 | $O(V+E)$ |
| `dfs(start)` | 깊이 우선 방문 순서 | $O(V+E)$ |
| `hasPath(u, v)` | u에서 v로 도달 가능한지 | $O(V+E)$ |
| `vertexCount()` | 정점 수 | $O(1)$ |
| `edgeCount()` | 논리 간선 수 | $O(1)$ |

핵심 연산 두 개만 변형 과정을 자세히 볼게요.

**① `addEdge` — 무방향 간선은 쌍둥이로 추가된다.** 빈 그래프에 `addEdge(0, 1)`을 호출하면:

```text
Before: adjList[0] = [],              adjList[1] = []

After:  adjList[0] = [{1, w:1}],      adjList[1] = [{0, w:1}]
                     ↑ u→v                          ↑ v→u (대칭 쌍둥이)
```

자기 루프는 예외예요. `addEdge(2, 2)`는:

```text
Before: adjList[2] = []

After:  adjList[2] = [{2, w:1}]      ← 항목 1개만! 쌍둥이를 만들면 안 된다
```

**② `bfs` — 거리 순으로 큐가 자란다.** 정점 $v$의 방문 거리를 $d(v)$라 하면, BFS는 항상

$$d(v) = \min_{u \in N(v),\ u\text{가 먼저 방문됨}} d(u) + 1$$

순서로 큐에 쌓입니다. 앞의 그래프에서 `bfs(0)`을 실행하면 큐가 이렇게 자랍니다.

```text
Before: visited={0},        queue=[0]

pop 0 → result=[0]
  이웃 [1,2] 모두 미방문 → 등록
After:  visited={0,1,2},    queue=[1,2]
```

### 왜 모순 없이 작동하는가

**불변식 2(무방향 대칭)가 유지되는 이유**: `addEdge`는 무방향이고 $u \neq v$일 때 항상 두 줄을 함께 실행합니다 — `adjList[u]`에 `v`를 추가하는 줄과 `adjList[v]`에 `u`를 추가하는 줄이 한 몸으로 묶여 있어요. 따라서 어느 시점에 관찰해도 한쪽만 추가되고 다른 쪽이 빠지는 중간 상태가 없습니다(귀납적으로: 빈 그래프는 대칭을 공허하게 만족하고, 매 `addEdge` 호출이 대칭을 보존하므로 항상 성립). `removeEdge`도 마찬가지로 무방향이면 양쪽에서 각 1개씩만 제거해 대칭을 유지합니다.

**불변식 5(edgeCount)가 유지되는 이유**: `_edgeCount`는 실제 저장된 배열 항목 수가 아니라 **호출 횟수**를 셉니다. `addEdge`가 성공할 때마다 무조건 1 증가, `removeEdge`가 실제로 뭔가를 지웠을 때만 1 감소하도록 정의했기 때문에, 무방향에서 항목이 2개씩 늘어나도 카운터는 논리 간선 수를 그대로 반영합니다.

여기서 헷갈리기 쉬운 포인트를 세 가지 짚어 둘게요.

- **edgeCount는 저장된 항목 수의 절반이 아닙니다.** 무방향 그래프에 `addEdge(0, 1)`을 한 번 호출하면 `neighbors(0).length === 1`, `neighbors(1).length === 1`이지만 `edgeCount()`는 `1`이에요("항목 2개 ÷ 2"라고 계산하면 우연히 맞아 보이지만, 자기 루프가 섞이는 순간 이 계산은 깨집니다 — 자기 루프는 항목이 1개뿐이라 나눗셈이 어긋나요).
- **멀티 엣지에서 `removeEdge`는 딱 하나만 지웁니다.** 같은 두 정점 사이에 `addEdge(0, 1)`을 두 번 호출하면 `neighbors(0)`에 `{vertex:1}` 항목이 2개 쌓입니다. 이 상태에서 `removeEdge(0, 1)`을 한 번 호출하면 1개만 사라지고 1개가 남아요 — "필터로 vertex===1인 항목을 전부 제거"하도록 짜면 멀티 엣지 하나를 지우려다 나머지까지 몽땅 날아가는 실수가 됩니다.
- **`hasPath(u, u)`는 그래프에 없는 정점이어도 `true`입니다.** "자기 자신에게는 항상 경로가 있다"는 정의를 우선 검사로 두었기 때문이에요. `u !== v`일 때만 실제로 두 정점이 그래프에 존재하는지, 그리고 BFS로 도달 가능한지를 확인합니다.

> 확인 하나만 해 볼까요? 무방향 그래프에서 `addEdge(0, 1)`을 두 번 호출하면 `edgeCount()`는 얼마가 될까요? — 정답은 `2`입니다. 저장된 항목 수(각 정점당 2개씩)와 무관하게, `addEdge` 호출 한 번은 항상 논리 간선 1개로 셉니다.

> 기억법: "무방향 간선은 쌍둥이, 자기 루프는 외동이."

엣지 케이스를 점검해 볼게요.

```text
빈 그래프에서 bfs(존재하지 않는 정점)         → []
정점은 있지만 간선이 없는 고립 정점 v          → neighbors(v) = [], bfs(v) = [v]
hasPath(u, u)                                → true (u가 그래프에 없어도)
hasPath(u, v), u 또는 v가 그래프에 없음        → false
멀티 엣지: addEdge(u,v) 두 번                 → neighbors(u)에 v 항목 2개, edgeCount = 2
자기 루프: addEdge(u,u)                      → neighbors(u)에 u 항목 1개(쌍둥이 없음), edgeCount = 1
```

## 아이디어를 코드로 옮기기

앞서 정의한 인터페이스 그대로 구현합니다. 가장 중요한 부분은 `addEdge`/`removeEdge`의 "무방향이고 자기 루프가 아닐 때만 대칭 처리"라는 조건이에요 — 이 조건 하나가 불변식 2와 3을 동시에 지킵니다.

```ts
interface Edge {
  vertex: number;
  weight: number;
}

class GraphAdjList {
  private adjList: Map<number, Edge[]> = new Map();
  private directed: boolean;
  private _edgeCount = 0;

  constructor(directed: boolean = false) {
    this.directed = directed;
  }

  addVertex(v: number): void {
    if (!this.adjList.has(v)) this.adjList.set(v, []);
  }

  addEdge(u: number, v: number, weight: number = 1): void {
    this.addVertex(u);
    this.addVertex(v);
    this.adjList.get(u)!.push({ vertex: v, weight });
    if (!this.directed && u !== v) {
      this.adjList.get(v)!.push({ vertex: u, weight }); // 대칭 쌍둥이
    }
    this._edgeCount++;
  }

  removeEdge(u: number, v: number): void {
    const uList = this.adjList.get(u);
    if (!uList) return;
    const idx = uList.findIndex((e) => e.vertex === v);
    if (idx === -1) return; // 없는 간선 제거 요청은 무시
    uList.splice(idx, 1); // 딱 1개만 제거 (멀티 엣지 대응)
    if (!this.directed && u !== v) {
      const vList = this.adjList.get(v)!;
      const vIdx = vList.findIndex((e) => e.vertex === u);
      if (vIdx !== -1) vList.splice(vIdx, 1);
    }
    this._edgeCount--;
  }

  neighbors(v: number): Array<{ vertex: number; weight: number }> {
    return this.adjList.get(v) ?? [];
  }

  bfs(start: number): number[] {
    if (!this.adjList.has(start)) return [];
    const visited = new Set<number>([start]);
    const queue: number[] = [start];
    const result: number[] = [];
    while (queue.length > 0) {
      const v = queue.shift()!;
      result.push(v);
      for (const { vertex: w } of this.adjList.get(v)!) {
        if (!visited.has(w)) {
          visited.add(w);
          queue.push(w);
        }
      }
    }
    return result;
  }

  dfs(start: number): number[] {
    if (!this.adjList.has(start)) return [];
    const visited = new Set<number>();
    const result: number[] = [];
    const explore = (v: number) => {
      visited.add(v);
      result.push(v);
      for (const { vertex: w } of this.adjList.get(v)!) {
        if (!visited.has(w)) explore(w);
      }
    };
    explore(start);
    return result;
  }

  hasPath(u: number, v: number): boolean {
    if (u === v) return true; // 자기 자신은 항상 도달 가능
    if (!this.adjList.has(u) || !this.adjList.has(v)) return false;
    return this.bfs(u).includes(v);
  }

  vertexCount(): number {
    return this.adjList.size;
  }

  edgeCount(): number {
    return this._edgeCount;
  }
}
```

놓치기 쉬운 구현부를 짚어 둘게요.

- **`addEdge`/`removeEdge`의 `!this.directed && u !== v` 조건.** 이 조건을 빼먹으면 방향 그래프에도 역방향 간선이 생기거나, 자기 루프가 두 번 저장되는 버그가 생깁니다.
- **`removeEdge`는 `filter`가 아니라 `findIndex` + `splice`.** `filter(e => e.vertex !== v)`로 짜면 멀티 엣지 상황에서 일치하는 항목을 전부 지워 버려요. 하나만 지우려면 첫 일치 위치를 찾아 그 자리만 잘라내야 합니다.
- **`bfs`/`dfs`에서 방문 처리 시점.** `visited.add(w)`를 큐/스택에 넣는 시점에 바로 하는 것이 핵심이에요. "꺼낼 때 방문 처리"로 미루면 같은 정점이 큐에 중복으로 들어가 결과가 부풀려집니다.
- **`hasPath`의 `u === v` 우선 검사.** 존재하지 않는 정점끼리 비교(`u === v`)해도 `true`를 반환해야 하므로, 그래프 존재 확인보다 먼저 와야 합니다.
