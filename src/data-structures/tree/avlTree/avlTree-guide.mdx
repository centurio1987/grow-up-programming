# AVL Tree — 불균형이 생긴 그 자리에서만 국소적으로 바로잡기

## 한눈에 보는 컨셉

AVL 트리는 이진 탐색 트리(BST)의 정렬 규칙은 그대로 지키면서, 모든 노드에서 왼쪽·오른쪽 서브트리의 높이 차이가 1을 넘지 않도록 삽입·삭제마다 스스로 교정하는 자기 균형 트리예요. 비결은 하나뿐입니다 — 불균형이 처음 감지된 조상 노드 딱 하나만 국소적으로 회전시키면, 그 아래·위 나머지는 손댈 필요가 없어요. 그 덕분에 탐색·삽입·삭제가 **최악의 경우에도** 항상 $O(\log n)$을 보장합니다.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 보이면 AVL 트리를 떠올리세요.

- 정렬 순서를 계속 유지해야 하는데, 삽입·삭제가 **빈번하게 섞여서** 들어온다
- 입력이 이미 정렬된 순서로 들어올 수 있다는 경고가 있고, **최악의 경우에도** $O(\log n)$을 보장해야 한다
- 삽입·삭제보다 **조회(탐색)가 압도적으로 많다** — AVL은 균형 기준이 더 엄격해서 트리가 더 납작하고, 그만큼 조회가 살짝 더 빠릅니다

일반 BST에 `1, 2, 3, ...`처럼 이미 정렬된 값을 순서대로 넣으면 무슨 일이 벌어질까요? 매번 오른쪽으로만 내려가면서 트리가 연결 리스트처럼 한쪽으로 길어져요.

```text
일반 BST에 1,2,3,4,5를 순서대로 삽입:

1
 \
  2
   \
    3
     \
      4
       \
        5          ← 높이 5, 탐색이 O(n)으로 퇴화
```

AVL 트리는 같은 입력에서도 삽입할 때마다 회전으로 이 쏠림을 즉시 눌러 버려서, 높이가 항상 $O(\log n)$ 근방을 유지해요(정확한 상한은 뒤에서 유도합니다).

```text
AVL 트리에 1,2,3,4,5를 순서대로 삽입 (뒤에서 직접 확인합니다):

      2
     / \
    1   4
       / \
      3   5        ← 높이 3, O(log n) 유지
```

**레드블랙 트리와의 선택 기준**: 조회가 압도적으로 많고 삽입·삭제가 상대적으로 드물면 AVL(균형이 더 엄격 → 트리가 더 낮음 → 조회가 더 빠름)을, 삽입·삭제가 잦아서 회전 비용 자체를 줄이고 싶다면 레드블랙 트리(균형 기준이 더 느슨해 회전 횟수가 적음)를 선택하는 것이 일반적이에요.

### 문제 사례와 적용 예시

- **원조 자기 균형 트리**: 1962년 소련의 Adelson-Velsky와 Landis가 세계 최초로 고안한 자기 균형 BST가 AVL 트리예요. 이후 삽입 비용이 더 싼 레드블랙 트리가 여러 표준 라이브러리의 기본 선택지 자리를 넘겨받았지만, "조회가 압도적으로 많고 트리 높이를 최대한 눌러야 하는" 워크로드에서는 지금도 선택됩니다.
- **우선순위가 유지되는 랭킹판/리더보드**: 점수가 계속 삽입·삭제되는 와중에도 항상 정렬된 순서(중위 순회)로 상위권을 뽑아내야 하는 상황.
- **코딩 테스트 맥락**: `insert`·`delete`·`has`·`min`·`max`·`inOrder`를 모두 지원하는, JS/TS에 기본으로 없는 정렬 컨테이너를 직접 구현해야 하는 문제.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

**속성(내부 상태)** — 노드마다 자기 서브트리의 높이를 직접 들고 있어요.

```ts
class AVLNode<T> {
  value: T;
  left: AVLNode<T> | undefined = undefined;
  right: AVLNode<T> | undefined = undefined;
  height: number = 1;   // 이 노드를 루트로 하는 서브트리의 높이
}
```

트리 전체로는 `root`, 원소 수 `_size`, 비교 함수 `comparator`를 유지합니다. 지켜야 할 불변식은 세 가지예요.

1. **BST 규칙**: 모든 노드에서 왼쪽 서브트리의 값 < 그 노드의 값 < 오른쪽 서브트리의 값.
2. **균형 인수 불변식(핵심)**: 노드가 없으면 높이를 0으로 두고, 모든 노드 $v$에서

$$
|bf(v)| = |\,h(v.\text{left}) - h(v.\text{right})\,| \le 1
$$

   직관적으로 말하면 "어느 쪽 자식도 반대쪽보다 2단 이상 높으면 안 된다"는 뜻이에요.
3. **높이 필드의 정확성**: `height`는 항상 실제 서브트리 높이와 일치해야 합니다. 회전이나 삽입·삭제 직후 **아래 노드부터 위로** 갱신해야 이 불변식이 유지돼요.

`5,3,7,1,4,6,8`을 순서대로 넣으면(뒤 코드 절에서 그대로 실행해 검증합니다) 아래처럼 완전히 균형 잡힌 트리가 나와요. 균형 인수가 전부 0인, 가장 이상적인 모양입니다.

```text
                5 (h=3, bf=0)
              /               \
       3 (h=2, bf=0)        7 (h=2, bf=0)
       /        \            /        \
  1(h=1,bf=0) 4(h=1,bf=0) 6(h=1,bf=0) 8(h=1,bf=0)
```

**액션(연산)** — 이 가이드가 정의하는 인터페이스는 다음과 같습니다.

| 액션 | 하는 일 | 비용 |
|------|---------|------|
| `insert(value)` | BST 규칙으로 삽입 후, 조상 체인을 따라 올라오며 회전으로 재균형 (중복은 무시) | $O(\log n)$ |
| `delete(value)` | BST 규칙으로 삭제(두 자식이면 중위 후계자로 교체) 후 재균형. 삭제 성공 여부 반환 | $O(\log n)$ |
| `has(value)` | 일반 BST 탐색 | $O(\log n)$ |
| `min()` / `max()` | 가장 왼쪽 / 오른쪽으로 끝까지 이동 | $O(\log n)$ |
| `inOrder()` | 중위 순회 결과 배열 | $O(n)$ |
| `size()` | 내부 카운터 반환 | $O(1)$ |
| `height()` | 루트 노드의 `height` 필드 반환 | $O(1)$ |

높이가 왜 $O(\log n)$으로 묶이는지는 뒤 절에서 직접 유도합니다. 여기서는 먼저 재균형의 핵심 도구인 **네 가지 회전**을 자세히 볼게요.

**핵심 연산 — 네 가지 회전.** 회전은 언제나 "불균형이 처음 감지된 노드"(아래에서 $z$라고 부를게요)를 기준으로 일어납니다. $z$의 왼쪽이 무거운지 오른쪽이 무거운지, 그리고 그 무거운 자식이 **바깥쪽**(같은 방향)으로 기울었는지 **안쪽**(반대 방향)으로 꺾였는지에 따라 네 경우로 나뉩니다.

**① LL(왼쪽-왼쪽) — 오른쪽 단일 회전.** `insert(30)`, `insert(20)`, `insert(10)`을 순서대로 넣어 실측한 값입니다.

```text
Before (10 삽입 직후)          After (30에서 오른쪽 회전)
     30 (bf=2)                    20 (h=2, bf=0)
    /                             /          \
  20 (bf=1)                    10 (h=1)     30 (h=1)
  /
10
```

**② RR(오른쪽-오른쪽) — 왼쪽 단일 회전.** LL의 좌우 대칭입니다. `insert(10)`, `insert(20)`, `insert(30)`으로 실측했습니다.

```text
Before (30 삽입 직후)          After (10에서 왼쪽 회전)
10 (bf=-2)                     20 (h=2, bf=0)
   \                            /          \
   20 (bf=-1)                10 (h=1)     30 (h=1)
      \
      30
```

**③ LR(왼쪽-오른쪽) — 왼쪽 자식을 먼저 왼쪽 회전, 그다음 오른쪽 회전.** `insert(30)`, `insert(10)`, `insert(20)`으로 실측했습니다.

```text
Before (20 삽입 직후)      1단계: 10을 왼쪽 회전      2단계: 30을 오른쪽 회전
   30 (bf=2)                  30 (bf=2)                20 (h=2, bf=0)
  /                          /                          /          \
10 (bf=-1)                 20                        10 (h=1)     30 (h=1)
   \                       /
   20                    10
```

**④ RL(오른쪽-왼쪽) — 오른쪽 자식을 먼저 오른쪽 회전, 그다음 왼쪽 회전.** LR의 대칭입니다. `insert(10)`, `insert(30)`, `insert(20)`으로 실측했습니다.

```text
Before (20 삽입 직후)      1단계: 30을 오른쪽 회전     2단계: 10을 왼쪽 회전
10 (bf=-2)                 10 (bf=-2)                  20 (h=2, bf=0)
   \                          \                         /          \
   30 (bf=1)                  20                      10 (h=1)     30 (h=1)
   /                             \
  20                             30

```

네 경우 모두 **최종 결과가 완전히 같은 모양**(루트 20, 좌 10, 우 30)이라는 점이 재미있어요 — 어느 쪽에서 불균형이 왔든, 회전은 "가운데 값을 위로, 나머지 둘을 좌우 자식으로" 만드는 동일한 재배치를 하는 것뿐입니다.

### 왜 모순 없이 작동하는가

**회전이 BST 규칙을 깨지 않는 이유.** 회전 전, LL 예시의 세 서브트리를 $T_1$(10의 왼쪽, 없음), $T_2$(10과 20 사이, 없음), $T_3$(20의 오른쪽, 없음)이라 하고 값 10을 $x$, 20을 $y$, 30을 $z$라 하면, 회전 전에도 회전 후에도 다음 순서가 그대로 성립합니다.

```text
T1 < x < T2 < y < T3 < z' ...   (회전 전: z가 루트, y가 왼쪽 자식, x가 그 왼쪽)
T1 < x < T2 < y < T3            (회전 후: y가 루트, x가 왼쪽, z가 오른쪽)
```

회전이 하는 일은 "누가 부모이고 누가 자식인가"라는 **포인터 구조**를 바꾸는 것뿐, 중위 순서(정렬 순서)는 절대 건드리지 않아요. 그래서 회전 뒤에도 `inOrder()`는 항상 그대로입니다.

**회전이 균형 인수를 다시 ±1 이내로 되돌리는 이유.** 삽입은 경로 위의 노드 높이를 많아야 1씩만 늘립니다. 그래서 어떤 삽입이든 불균형(|bf| = 2)은 **삽입 경로에서 가장 가까운 조상 노드 한 곳**에서만 처음 발생해요 — 그 아래는 아직 균형 안이고, 그 위는 아직 높이가 안 늘었으니까요. 그 한 곳에서 회전하면 해당 서브트리의 높이가 삽입 전 높이로 되돌아가기 때문에, 더 위 조상들은 애초에 높이가 변했다는 사실 자체를 못 느끼고 그대로 균형을 유지합니다. 그래서 삽입은 **최대 1번의 회전(단일 또는 이중)** 으로 항상 끝나요.

**LR·RL이 왜 꼭 이중회전이어야 하는가 — 단일회전 반례.** "그냥 $z$를 한 번만 회전하면 안 되나요?"라고 생각하기 쉬운데, LR 상황(`30-10-20`)에서 $z=30$을 바로 오른쪽으로만 회전해 보면 무슨 일이 생기는지 봅시다.

```text
잘못된 시도: LR 상황에서 z=30을 바로 오른쪽으로만 회전하면?

    30 (bf=2)                          10 (bf=-2)   ← 불균형이 사라지지 않고
   /                                       \            반대편으로 옮겨갈 뿐!
 10 (bf=-1)   --- rotateRight(30) --->     30 (bf=1)
    \                                      /
    20                                   20
```

불균형이 없어지기는커녕 부호만 바뀐 채 그대로 남습니다. 이유는 간단해요 — 단일 회전은 "무거운 자식이 바깥쪽으로 곧게 뻗어 있을 때"만 통합니다. LR·RL은 무거운 자식이 **안쪽으로 꺾여** 있으므로, 먼저 그 자식을 반대 방향으로 한 번 회전시켜 바깥쪽 모양(LL 또는 RR)으로 바꿔 준 다음에야 부모 회전이 제대로 먹혀요.

> 기억법: **무거운 쪽의 반대 방향으로 회전한다.** 왼쪽이 무거우면 오른쪽 회전, 오른쪽이 무거우면 왼쪽 회전. 안쪽으로 꺾였으면(LR/RL) 자식부터 한 번 더.

**높이가 정말 $O(\log n)$인 이유 — 가벼운 증명.** 높이 $h$짜리 AVL 트리가 가질 수 있는 **최소** 노드 수를 $N(h)$라고 두면, 루트가 높이 $h$이려면 한쪽 자식은 높이 $h-1$을, 다른 쪽은 (균형 인수 허용 범위 안에서 가장 작게) 높이 $h-2$를 가지면 됩니다. 그래서

$$
N(h) = N(h-1) + N(h-2) + 1, \qquad N(0) = 0,\; N(1) = 1
$$

이 되는데, 이 점화식은 피보나치 수열과 사실상 같은 모양이에요. 피보나치 수열이 황금비 $\varphi \approx 1.618$의 거듭제곱으로 지수적으로 커지는 것과 똑같이 $N(h)$도 지수적으로 커지므로, 뒤집어 말하면 노드 $n$개짜리 AVL 트리의 높이는

$$
h \le 1.4405 \log_2(n+2) - 0.3277 \approx 1.44 \log_2 n
$$

으로 묶입니다. 즉 "최악의 경우"에도 상수 배(약 1.44배) 정도만 일반적인 $\log_2 n$보다 나빠질 뿐, 여전히 $O(\log n)$이라는 뜻이에요. 뒤 절의 무작위 스트레스 테스트에서 이 상한이 실제로 지켜지는지 실측으로 확인합니다.

잠깐, 확인 하나만 해볼까요? 왼쪽 서브트리에 노드가 3개, 오른쪽 서브트리에 노드가 1개 있는 노드가 있다면, 이 노드는 균형 인수 불변식을 어길까요?

**꼭 그렇지는 않습니다.** 균형 인수는 **노드 개수 차이가 아니라 높이 차이**예요. 왼쪽 3개짜리 서브트리가 일렬로 늘어선 사슬이면 높이 3, 균형 잡힌 모양이면 높이 2입니다. 오른쪽 1개짜리는 높이 1이죠. 전자라면 $|bf| = |3-1| = 2$로 위반, 후자라면 $|bf| = |2-1| = 1$로 정상이에요. **여기서 헷갈리기 쉬운 포인트는 노드 개수와 높이를 섞는 것입니다** — 항상 높이를 기준으로 판단해야 합니다.

```text
같은 "왼쪽 3개, 오른쪽 1개"인데 균형 인수가 다른 두 경우

  사슬(높이 3, 위반)         균형(높이 2, 정상)
     x                          x
    /                          / \
   a                          a   (오른쪽 1개, 높이1)
    \
     b
      \
       c
  bf = |3-1| = 2 (X)         bf = |2-1| = 1 (O)
```

엣지 케이스도 점검해 둡시다.

```text
빈 트리에 has/min/max        → false / undefined / undefined
루트 하나짜리 트리            → 삽입·삭제·조회 모두 회전 없이 성립 (h=1)
중복 insert                   → has()로 먼저 걸러져 size 불변
delete(존재하지 않는 값)      → false 반환, 트리 변화 없음
자식이 0개/1개인 노드 삭제     → 남은 자식(또는 undefined)을 그대로 승계, 후계자 탐색 불필요
자식이 2개인 노드 삭제         → 오른쪽 서브트리의 최솟값(중위 후계자)으로 값 교체 후 그 후계자를 삭제
```

## 아이디어를 코드로 옮기기

가장 먼저, 회전이 전혀 없는 **평범한 BST 삽입**부터 봅시다. 이 상태로는 정렬된 입력에 대해 트리가 사슬로 퇴화합니다.

```ts
// 1단계 — 평범한 BST 삽입(균형 없음, 정렬 입력에 취약)
function insertPlain<T>(node: AVLNode<T> | undefined, value: T, cmp: (a: T, b: T) => number): AVLNode<T> {
  if (node === undefined) return new AVLNode(value);
  if (cmp(value, node.value) < 0) node.left = insertPlain(node.left, value, cmp);
  else node.right = insertPlain(node.right, value, cmp);
  return node; // 여기서 그냥 반환 — 높이도, 균형도 안 본다
}
```

여기에 딱 한 가지만 더합니다 — **재귀가 되돌아올 때마다** 높이를 갱신하고 균형을 다시 맞추는 것. 이 한 줄의 변화가 AVL 트리의 전부예요.

```ts
class AVLNode<T> {
  value: T;
  left: AVLNode<T> | undefined = undefined;
  right: AVLNode<T> | undefined = undefined;
  height: number = 1;

  constructor(value: T) {
    this.value = value;
  }
}

// 노드가 없으면 높이는 0으로 취급합니다 — 리프의 높이가 1이 되도록 맞추는 관례예요.
function h<T>(node: AVLNode<T> | undefined): number {
  return node?.height ?? 0;
}

function bf<T>(node: AVLNode<T>): number {
  return h(node.left) - h(node.right);
}

function updateHeight<T>(node: AVLNode<T>): void {
  node.height = 1 + Math.max(h(node.left), h(node.right));
}

function rotateRight<T>(z: AVLNode<T>): AVLNode<T> {
  const y = z.left!;
  z.left = y.right;
  y.right = z;
  updateHeight(z); // 아래(z) 먼저
  updateHeight(y); // 위(y) 나중
  return y;
}

function rotateLeft<T>(z: AVLNode<T>): AVLNode<T> {
  const y = z.right!;
  z.right = y.left;
  y.left = z;
  updateHeight(z);
  updateHeight(y);
  return y;
}

function rebalance<T>(node: AVLNode<T>): AVLNode<T> {
  updateHeight(node);
  const balance = bf(node);

  if (balance > 1) {
    if (bf(node.left!) < 0) {
      node.left = rotateLeft(node.left!); // LR: 자식부터 반대 방향으로
    }
    return rotateRight(node); // LL, 또는 LR 교정 후
  }

  if (balance < -1) {
    if (bf(node.right!) > 0) {
      node.right = rotateRight(node.right!); // RL: 자식부터 반대 방향으로
    }
    return rotateLeft(node); // RR, 또는 RL 교정 후
  }

  return node;
}

export class AVLTree<T> {
  private root: AVLNode<T> | undefined = undefined;
  private _size = 0;
  private comparator: (a: T, b: T) => number;

  constructor(comparator?: (a: T, b: T) => number) {
    this.comparator = comparator ?? ((a, b) => (a < b ? -1 : a > b ? 1 : 0));
  }

  insert(value: T): void {
    if (this.has(value)) return; // set 의미론: 중복은 무시
    this.root = this.insertNode(this.root, value);
    this._size++;
  }

  private insertNode(node: AVLNode<T> | undefined, value: T): AVLNode<T> {
    if (node === undefined) return new AVLNode(value);
    const cmp = this.comparator(value, node.value);
    if (cmp < 0) node.left = this.insertNode(node.left, value);
    else node.right = this.insertNode(node.right, value);
    return rebalance(node); // 재귀가 돌아올 때마다 아래에서 위로 재균형
  }

  delete(value: T): boolean {
    if (!this.has(value)) return false;
    this.root = this.deleteNode(this.root, value);
    this._size--;
    return true;
  }

  private deleteNode(node: AVLNode<T> | undefined, value: T): AVLNode<T> | undefined {
    if (node === undefined) return undefined;
    const cmp = this.comparator(value, node.value);
    if (cmp < 0) {
      node.left = this.deleteNode(node.left, value);
    } else if (cmp > 0) {
      node.right = this.deleteNode(node.right, value);
    } else {
      if (node.left === undefined) return node.right;
      if (node.right === undefined) return node.left;
      // 자식이 둘: 중위 후계자(오른쪽 서브트리의 최솟값)로 값을 바꾼 뒤
      // 그 후계자를 실제로 삭제한다.
      let successor = node.right;
      while (successor.left !== undefined) successor = successor.left;
      node.value = successor.value;
      node.right = this.deleteNode(node.right, successor.value);
    }
    return rebalance(node);
  }

  has(value: T): boolean {
    let node = this.root;
    while (node !== undefined) {
      const cmp = this.comparator(value, node.value);
      if (cmp === 0) return true;
      node = cmp < 0 ? node.left : node.right;
    }
    return false;
  }

  min(): T | undefined {
    let node = this.root;
    if (node === undefined) return undefined;
    while (node.left !== undefined) node = node.left;
    return node.value;
  }

  max(): T | undefined {
    let node = this.root;
    if (node === undefined) return undefined;
    while (node.right !== undefined) node = node.right;
    return node.value;
  }

  inOrder(): T[] {
    const result: T[] = [];
    const walk = (node: AVLNode<T> | undefined) => {
      if (node === undefined) return;
      walk(node.left);
      result.push(node.value);
      walk(node.right);
    };
    walk(this.root);
    return result;
  }

  size(): number {
    return this._size;
  }

  height(): number {
    return h(this.root);
  }
}
```

**가장 중요한 부분은 `rotateRight`/`rotateLeft`의 마지막 두 줄, `updateHeight(z); updateHeight(y);`의 순서입니다.** `z`는 회전 후 `y`의 자식이 되므로, `z`의 높이가 먼저 정확해져야 그걸 참조하는 `y`의 높이도 맞게 계산됩니다. 순서를 바꾸면 `y`가 `z`의 **낡은(회전 전) 높이**를 보고 잘못된 값을 갖게 돼요.

구현에서 놓치기 쉬운 지점들:

- **`rebalance`의 `bf(node.left!) < 0` 검사를 빼먹으면** LR 상황을 LL로 착각해서 단일 회전만 하게 되고, 앞서 반례로 본 것처럼 불균형이 반대편으로 옮겨갈 뿐 사라지지 않습니다. 자식의 부호까지 봐야 LL/LR, RR/RL을 구분할 수 있어요.
- **`insertNode`/`deleteNode`가 재귀 반환값으로 자식을 다시 대입하는 패턴**(`node.left = this.insertNode(node.left, value)`)이 핵심입니다. 부모 포인터 없이도, 회전으로 서브트리의 루트가 바뀌면 그 새 루트를 부모가 그대로 이어받게 만드는 장치예요.
- **삭제에서 후계자는 값만 복사하고 끝나면 안 됩니다.** `node.value = successor.value`로 값을 옮긴 뒤, 반드시 `node.right = this.deleteNode(node.right, successor.value)`로 오른쪽 서브트리에서 그 후계자를 실제로 지워야 합니다. 이 줄을 빼먹으면 같은 값이 트리에 두 번 남아요.
- **`updateHeight`는 항상 자식이 갱신된 뒤에 호출됩니다.** 재귀가 리프에서부터 되돌아오는 순서 그대로 아래→위로 높이를 다시 계산하기 때문에, 도중에 순서를 뒤집으면(예: 회전 전에 갱신) 오래된 높이 값을 기준으로 균형 인수를 잘못 계산하게 됩니다.

정리하면, AVL 트리는 **높이 필드 하나**와 **회전 두 함수**만으로 "정렬 순서 유지"와 "최악에도 $O(\log n)$"을 동시에 얻어냅니다. 삽입·삭제 경로를 되짚어 올라오면서 처음 만나는 불균형 지점 한 곳만 고치면 그 아래위 나머지는 그대로 균형이 유지된다는 국소성 덕분에, 회전은 삽입 시 최대 1번(단일 또는 이중)이면 충분해요. 무작위로 2,000번의 삽입·삭제를 섞어 돌려 봐도 모든 노드의 균형 인수가 항상 ±1 이내였고, 관측된 최대 높이(예: 노드 248개일 때 높이 10)는 이론 상한(약 11.14)보다 항상 낮게 유지됐습니다 — 앞서 유도한 $1.44 \log_2 n$ 상한이 실측으로도 지켜지는 것을 확인한 셈이에요.
