# Binary Search Tree — 왼쪽엔 작은 값, 오른쪽엔 큰 값, 정렬은 공짜로 따라온다

## 한눈에 보는 컨셉

이진 탐색 트리(BST)는 각 노드가 왼쪽 서브트리에는 자신보다 작은 값만, 오른쪽 서브트리에는 자신보다 큰 값만 두도록 데이터를 배치하는 트리예요. 이 규칙 하나 덕분에 탐색이 "왼쪽이냐 오른쪽이냐"를 반복하는 이진 결정이 되어 평균 $O(\log n)$에 끝나고, 왼쪽 → 현재 → 오른쪽 순서로 훑는 중위 순회는 별다른 정렬 작업 없이 오름차순 결과를 그대로 내놓습니다. 정렬 배열의 빠른 탐색과 연결 리스트의 빠른 삽입·삭제, 이 둘을 동시에 노리는 절충안이라고 보면 됩니다.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 겹치면 BST를 떠올리세요.

- 조회(검색)뿐 아니라 **삽입·삭제도 반복적으로** 일어난다
- 그럼에도 **항상 정렬된 순서**로 전체를 훑거나(중위 순회), 최솟값·최댓값을 자주 물어야 한다
- 데이터 개수가 계속 바뀌는 동적인 상황이라, 매번 $O(n)$ 이동 비용을 감당하기 어렵다

naive한 대안들과 비교해 보면 BST가 왜 절충안인지 보입니다.

```text
                 검색        삽입           삭제              정렬 순회
비정렬 배열      O(n)        O(1)           O(n)              O(n log n) 재정렬 필요
정렬 배열        O(log n)    O(n) 이동      O(n) 이동         O(n) (이미 정렬)
연결 리스트      O(n)        O(1)           O(n) 탐색+O(1)    O(n log n) 재정렬 필요
BST (균형 가정)  O(log n)    O(log n)       O(log n)          O(n) (중위 순회만)
```

삽입·삭제가 거의 없고 조회만 반복된다면 정렬 배열이 메모리 지역성도 좋아 더 빠릅니다. 삽입·삭제만 잦고 순서가 필요 없다면 해시 테이블이 낫고요. **삽입·삭제와 정렬 순회를 모두 자주 해야 하는 상황에서만 BST를 선택하세요.** 단, 입력이 이미 정렬된 순서로(오름차순·내림차순) 들어올 걸 미리 안다면 일반 BST는 한쪽으로 기울어져 최악 $O(n)$이 되므로, AVL 트리나 레드블랙 트리 같은 자가 균형 변형을 대신 고려해야 합니다.

이 프로젝트가 요구하는 규모($n \le 10^5$)에서 균형이 잡혀 있다면 평균 $\log_2(10^5) \approx 17$번의 비교로 탐색이 끝나지만, 정렬된 키가 그대로 삽입되면 트리가 사슬처럼 늘어져 최악 $10^5$번의 비교가 필요해집니다. 이 격차 자체가 "왜 자가 균형 트리가 발명됐는가"의 동기이기도 합니다.

### 문제 사례와 적용 예시

- **도서관 장서 관리 시스템**: ISBN을 키로 삽입·대출/반납(삭제)·조회가 매일 반복되고, 특정 범위를 정렬된 목록으로 인쇄해야 하는 상황에 BST가 세 요구를 동시에 충족합니다.
- **언어 런타임의 정렬 컨테이너**: Java의 `TreeMap`/`TreeSet`, C++의 `std::map`/`std::set`은 내부적으로 균형 잡힌 BST(레드블랙 트리)로 구현되어 있습니다.
- **실시간 랭킹·리더보드**: 점수가 계속 갱신(삽입·삭제)되는 와중에도 상위 k명을 정렬된 순서로 뽑아야 하는 시스템.
- **코딩 테스트 맥락**: "삽입·삭제가 섞인 스트림에서 k번째로 작은 값을 구하라", "특정 범위 [low, high]의 원소를 정렬 순으로 내놓아라" 같은 순서 통계(order statistics) 문제가 BST 구현을 직접 요구합니다.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

**속성(내부 상태)**은 노드 하나와 트리 전체로 나뉩니다.

```ts
class Node {
  key: number;
  left: Node | null = null;
  right: Node | null = null;
  constructor(key: number) {
    this.key = key;
  }
}

class BinarySearchTree {
  private root: Node | null = null;
}
```

지켜야 할 불변식은 세 가지입니다.

1. **BST 성질.** 모든 노드 $v$에 대해, $v$의 왼쪽 서브트리에 속한 모든 노드 $u$는 $u.key < v.key$이고, 오른쪽 서브트리에 속한 모든 노드 $w$는 $w.key > v.key$입니다.

$$\forall v \in T:\ \forall u \in \mathrm{left}(v),\ u.key < v.key \quad\text{그리고}\quad \forall w \in \mathrm{right}(v),\ w.key > v.key$$

2. **중복 키 없음.** 이미 존재하는 키를 다시 삽입하면 트리는 변하지 않습니다(멱등).
3. **빈 트리는 `root === null`로 표현합니다.** 노드가 하나도 없는 상태를 나타내는 별도 sentinel은 없습니다.

`insert(5); insert(3); insert(7); insert(1); insert(4)`를 순서대로 실행하면 이런 모양이 됩니다.

```text
        5
       / \
      3   7
     / \
    1   4
```

**액션(연산)**은 문제가 요구하는 6종입니다.

| 연산 | 하는 일 | 평균 비용 | 최악 비용 |
|------|---------|----------|----------|
| `insert(key)` | BST 성질을 지키며 삽입. 중복이면 무시 | $O(\log n)$ | $O(n)$ |
| `search(key)` | 키 존재 여부 확인 | $O(\log n)$ | $O(n)$ |
| `delete(key)` | 키 제거. 자식이 둘이면 in-order successor로 대체 | $O(\log n)$ | $O(n)$ |
| `inorder()` | 왼쪽 → 현재 → 오른쪽 순회로 오름차순 배열 반환 | $O(n)$ | $O(n)$ |
| `min()` | 최솟값(루트에서 왼쪽 끝까지) | $O(h)$ | $O(n)$ |
| `max()` | 최댓값(루트에서 오른쪽 끝까지) | $O(h)$ | $O(n)$ |

$h$는 트리 높이입니다. 무작위 삽입 순서에서는 $h = O(\log n)$이 기대되지만, 정렬된 순서로 삽입하면 $h = O(n)$까지 나빠집니다.

핵심 연산 두 개는 자세히 볼 가치가 있습니다.

**① `insert` — 비교하며 내려가다 빈 자리에 심기.** 위 트리에 `insert(4)`가 일어나는 과정을 따라가 볼게요. `4 < 5`이므로 왼쪽(3)으로, `4 > 3`이므로 오른쪽으로 내려가는데 그 자리가 비어 있으니(`null`) 새 노드를 답니다.

```text
Before:                    After insert(4):
        5                          5
       / \                        / \
      3   7          ==>         3   7
     /                          / \
    1                          1   4
```

**② `delete` — 자식이 둘인 경우, in-order successor로 대체.** 자식이 0개나 1개면 그 자리를 빈 자리 또는 남은 자식으로 바로 메우면 되지만, 자식이 둘이면 두 서브트리를 동시에 만족하는 대체자가 필요합니다. 그 후보가 **오른쪽 서브트리의 최솟값(in-order successor)**입니다. `delete(3)`을 실행하면:

```text
Before:                    After delete(3):
        5                          5
       / \                        / \
      3   7          ==>         4   7
     / \                        /
    1   4                      1
```

3의 오른쪽 서브트리는 `{4}` 하나뿐이라 successor는 4입니다. 3의 자리에 4를 놓고, 4가 있던 원래 자리(3의 오른쪽 자식)는 비웁니다.

### 왜 모순 없이 작동하는가

**삽입이 불변식을 보존하는 이유**를 귀납적으로 봅시다. 빈 트리는 노드가 없으니 불변식이 공허하게 참입니다. 어떤 트리가 불변식을 만족한다고 가정하고 `insert(key)`를 실행하면, 재귀는 매 단계 `key`와 현재 노드를 비교해 왼쪽 또는 오른쪽으로만 내려가고, `null`에 도달했을 때만 새 노드를 답니다. 이 경로 위의 모든 조상 노드에서 "작으면 왼쪽, 크면 오른쪽"이라는 비교가 지켜졌으므로, 새 노드는 정확히 자신이 있어야 할 위치(모든 조상보다 작아야 할 곳에서는 작게, 커야 할 곳에서는 크게)에 들어갑니다. 기존 노드들 사이의 대소 관계는 전혀 건드리지 않았으니 불변식은 그대로 유지됩니다.

**삭제(자식 둘) 정확성**도 부등식으로 확인할 수 있습니다. 삭제할 노드를 $v$, 선택한 successor를 $s$라 하면 $s$는 $v$의 오른쪽 서브트리 안의 최솟값이므로

$$(\text{모든 } u \in \mathrm{left}(v)) \; < \; v.key \; < \; s.key \; \le \; (\text{모든 } w \in \mathrm{right}(v))$$

가 성립합니다. 따라서 $v$의 자리를 $s.key$로 바꿔도 왼쪽 서브트리는 여전히 그보다 작고 오른쪽 서브트리는 여전히 그 이상입니다. $s$ 자신은 정의상 왼쪽 자식이 없으므로(있었다면 그게 더 작은 값이라 최솟값이 아니게 됨) $s$를 지우는 일은 항상 "자식 0개 또는 1개" 케이스로 귀결되어 재귀적으로 안전합니다.

여기서 **헷갈리기 쉬운 포인트**가 하나 있습니다. successor의 키만 복사해 오고, **successor가 있던 자리를 재귀적으로 삭제하는 과정을 생략**하는 실수입니다. 트리 `5, 3, 8, 1, 4, 7, 9`(레벨 순서로 삽입)를 예로 들어 볼게요.

```text
        5
       / \
      3   8
     / \  / \
    1  4 7   9
```

`delete(5)`를 실행하면 successor는 `5`의 오른쪽 서브트리(`8, 7, 9`)에서 최솟값인 `7`입니다. 올바른 구현은 `5`를 `7`로 바꾼 뒤 **오른쪽 서브트리 안에서 `7`을 재귀적으로 삭제**해 `inorder() === [1, 3, 4, 7, 8, 9]`를 만듭니다. 그런데 "successor의 오른쪽 자식을 그대로 이어받으면 되겠지"라고 생각해 `node.right = successor.right`(즉 `7.right`, 여기선 `null`)로 **직접 끊어버리면**, `8`과 `9`를 통째로 담고 있던 서브트리 자체가 사라져 `inorder()`가 `[1, 3, 4, 7]`이 되어 버립니다 — 존재하던 노드 두 개(`8`, `9`)가 흔적도 없이 유실되는 겁니다. 재귀 삭제를 생략할 수 없는 이유가 바로 이겁니다.

> 확인 질문 하나만 해 볼까요? 트리에 `7, 3, 11, 1, 5, 9, 13`이 이 순서로 삽입됐다면 `search(9)`는 어떤 경로를 지나갈까요? — 정답: `7`에서 `9 > 7`이라 오른쪽(`11`)으로, `11`에서 `9 < 11`이라 왼쪽(`9`)으로 가서 발견합니다. 경로 `7 → 11 → 9`, 비교 3번.

엣지 케이스를 점검해 봅시다.

```text
빈 트리                      → search: false, min/max: undefined, inorder: []
빈 트리에 delete             → 아무 일도 일어나지 않음(무시)
노드 1개짜리 트리에서 삭제   → 빈 트리로 돌아감
중복 insert                  → 무시, 트리 모양 불변
없는 키 delete                → 트리 순회만 하고 무시
오름차순 삽입(1,2,3,4,5)     → 오른쪽 자식만 있는 사슬, 높이 = n (최악 케이스)
```

## 아이디어를 코드로 옮기기

문제가 요구하는 인터페이스(`insert` / `search` / `delete` / `inorder` / `min` / `max`)에 맞춰 구현합니다. 삽입·삭제는 "이 서브트리에 연산을 적용한 결과, 새 서브트리의 루트를 반환한다"는 재귀 패턴을 쓰면 부모 포인터 없이도 깔끔합니다.

```ts
class Node {
  key: number;
  left: Node | null = null;
  right: Node | null = null;
  constructor(key: number) {
    this.key = key;
  }
}

class BinarySearchTree {
  private root: Node | null = null;

  insert(key: number): void {
    this.root = this.insertNode(this.root, key);
  }

  private insertNode(node: Node | null, key: number): Node {
    if (node === null) return new Node(key);
    if (key < node.key) node.left = this.insertNode(node.left, key);
    else if (key > node.key) node.right = this.insertNode(node.right, key);
    return node; // key === node.key: 중복이면 그대로 반환
  }

  search(key: number): boolean {
    let current = this.root;
    while (current !== null) {
      if (key === current.key) return true;
      current = key < current.key ? current.left : current.right;
    }
    return false;
  }

  delete(key: number): void {
    this.root = this.deleteNode(this.root, key);
  }

  private deleteNode(node: Node | null, key: number): Node | null {
    if (node === null) return null;
    if (key < node.key) {
      node.left = this.deleteNode(node.left, key);
    } else if (key > node.key) {
      node.right = this.deleteNode(node.right, key);
    } else {
      if (node.left === null) return node.right;   // 자식 0 또는 오른쪽만
      if (node.right === null) return node.left;    // 왼쪽만
      const successor = this.findMinNode(node.right);
      node.key = successor.key;
      node.right = this.deleteNode(node.right, successor.key);
    }
    return node;
  }

  private findMinNode(node: Node): Node {
    let current = node;
    while (current.left !== null) current = current.left;
    return current;
  }

  inorder(): number[] {
    const result: number[] = [];
    this.inorderTraverse(this.root, result);
    return result;
  }

  private inorderTraverse(node: Node | null, result: number[]): void {
    if (node === null) return;
    this.inorderTraverse(node.left, result);
    result.push(node.key);
    this.inorderTraverse(node.right, result);
  }

  min(): number | undefined {
    if (this.root === null) return undefined;
    return this.findMinNode(this.root).key;
  }

  max(): number | undefined {
    if (this.root === null) return undefined;
    let current = this.root;
    while (current.right !== null) current = current.right;
    return current.key;
  }
}
```

가장 중요한 부분은 `deleteNode`의 **자식 둘 케이스** 세 줄입니다.

```ts
const successor = this.findMinNode(node.right);
node.key = successor.key;
node.right = this.deleteNode(node.right, successor.key);
```

앞서 본 것처럼, 세 번째 줄을 `node.right = successor.right`로 바꿔치기하면 `5, 3, 8, 1, 4, 7, 9` 트리에서 `delete(5)`가 `8`과 `9`를 통째로 날려버립니다(`inorder()`가 `[1,3,4,7,8,9]`가 아니라 `[1,3,4,7]`이 됩니다). **반드시 재귀 `deleteNode`를 다시 호출**해야 오른쪽 서브트리에 남은 나머지 노드들이 보존됩니다.

놓치기 쉬운 구현 포인트를 더 짚어 둘게요.

- `insertNode`와 `deleteNode`는 모두 **"수정된 서브트리의 루트를 반환하고, 호출부가 그 값을 부모의 `left`/`right`에 다시 대입"**하는 패턴입니다. 이 반환값 대입을 빠뜨리면(예: `insertNode(node.left, key)`만 호출하고 대입을 생략) 새로 만든 노드가 트리에 붙지 않고 사라집니다.
- `search`의 비교 순서는 `key === current.key`를 **먼저** 검사해야 합니다. 순서를 바꿔 부등호 비교부터 하면 정확히 일치하는 키를 찾고도 계속 내려가다 `null`을 만나 `false`를 반환하게 됩니다.
- `min`/`max`는 재귀보다 반복(iterative)이 간결하고 $O(1)$ 스택만 씁니다 — 왼쪽/오른쪽으로 끝까지 가면 끝입니다.

> 기억법: "삭제는 값만 훔쳐오지 말고, 훔쳐온 자리도 직접 청소한다."

## 실행 시각화

아래 시뮬레이션은 `insert(5) → insert(3) → insert(7) → insert(1) → insert(4) → search(4) → delete(3)`을 순서대로 실행합니다. 실제 반환값은 `search(4) === true`이고, `delete(3)` 직후 `inorder()`는 `[1, 4, 5, 7]`입니다. 패널의 `array`는 트리를 **레벨 순서 배열**(index 0=루트, 왼쪽 자식=`2i+1`, 오른쪽 자식=`2i+2`, `0`=빈 슬롯)로 펼친 스냅샷이고, `highlight`는 그 단계에서 바뀌거나 방문한 인덱스를 가리킵니다.
