# RedBlackTree — 노드 색 하나로 균형을 사는 자기 균형 이진 탐색 트리

## 한눈에 보는 컨셉

레드-블랙 트리는 모든 노드를 RED 또는 BLACK 두 색으로 채색해서, 뿌리에서 리프까지 가는 모든 경로의 **Black 노드 개수(Black 높이)** 만 똑같이 맞추는 자기 균형 이진 탐색 트리예요. 비결은 "완벽한 균형"을 노리지 않는 것입니다 — Red 노드는 Black 노드 사이에만 낄 수 있다는 규칙 하나만 지키면, 아무리 삐뚤어져도 높이가 폭주하지 않아요. 그 결과 삽입·삭제·탐색이 모두 $O(\log n)$이면서 회전은 삽입 최대 2회, 삭제 최대 3회로 끝나서, C++ `std::map`/`std::set`이나 Java `TreeMap` 같은 실무 정렬 컨테이너의 표준 선택이 됐습니다.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 겹치면 레드-블랙 트리를 떠올리세요.

- 삽입·삭제가 **끊임없이 섞여** 들어오는데도 탐색은 계속 $O(\log n)$을 유지해야 한다
- 정렬 순서를 유지한 채로 값을 **중위 순회**해서 뽑아낼 일이 있다
- "초당 수만 건" 같은 표현으로 **쓰기 성능**이 강조된다 — 문제 스토리의 인메모리 데이터베이스 인덱스가 정확히 이 상황이에요

naive 대안들과 비교하면 왜 이 구조가 필요한지 체감됩니다.

```text
정렬 배열 insert/delete   O(n)      ← 삽입 위치 뒤 원소를 통째로 밀어야 함
일반 BST(균형 없음)        O(n) 최악  ← 편향(스큐)되면 사실상 연결 리스트로 퇴화
AVL 트리                  O(log n)  ← 높이 ≈ 1.44 log2 n로 더 낮지만, 삭제 시 회전이
                                     루트까지 연쇄될 수 있어 최악 O(log n)회
레드-블랙 트리             O(log n)  ← 높이 ≤ 2 log2(n+1)로 AVL보다 느슨하지만,
                                     삽입 회전 ≤2회 · 삭제 회전 ≤3회로 상한이 고정
```

**선택 기준**: 조회가 압도적으로 많고 삽입·삭제가 드물면 더 낮은 높이를 주는 AVL이 유리하고, 삽입·삭제가 잦으면 회전 횟수가 작은 상수로 묶여 있는 레드-블랙 트리가 유리합니다.

### 문제 사례와 적용 예시

- **C++ STL / Java 표준 라이브러리** — `std::map`, `std::set`, `TreeMap`, `TreeSet`은 모두 레드-블랙 트리로 구현돼 있어요. 정렬 순서를 유지하는 범용 컨테이너의 기본값입니다.
- **Linux 커널 스케줄러** — CFS(Completely Fair Scheduler)가 실행 대기 중인 프로세스를 `vruntime` 순으로 레드-블랙 트리에 담아, 다음에 실행할 프로세스를 $O(\log n)$에 골라냅니다.
- **인메모리 데이터베이스 인덱스** — 문제 스토리처럼 초당 수만 건의 삽입·삭제가 발생해도 정렬 인덱스를 유지해야 하는 상황에 정확히 들어맞습니다.
- **코딩 테스트 맥락** — "정렬 상태를 유지하며 삽입·삭제·탐색·범위 조회를 반복하라"는 요구에, 정렬 컨테이너가 내장돼 있지 않은 JS/TS에서는 직접 구현 대상이 됩니다.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

**속성(내부 상태)** — 노드 하나는 이렇게 생겼습니다.

```ts
type RBColor = "RED" | "BLACK";

class RBNode<T> {
  value: T;
  color: RBColor;
  left: RBNode<T>;
  right: RBNode<T>;
  parent: RBNode<T>;
}
```

모든 리프의 바깥쪽 자식 자리는 실제 `undefined` 대신 **NIL 센티넬** 노드 하나를 공유해서 채웁니다. NIL은 항상 BLACK이고, `left`/`right`/`parent`가 전부 자기 자신을 가리켜요. 이렇게 하면 "자식이 있는지" 매번 `undefined` 체크를 하는 대신 `node !== NIL`만 보면 되고, 삭제 픽스업에서 "가상의 이중 흑색 노드"를 NIL 자리에 그대로 세워둘 수 있어 코드가 간결해집니다.

지켜야 할 불변식은 다섯 가지예요.

1. **채색**: 모든 노드는 RED 또는 BLACK이다.
2. **루트**: 루트는 반드시 BLACK이다.
3. **NIL**: 센티넬 NIL은 항상 BLACK이다.
4. **Red 규칙**: $\forall v.\ \mathrm{color}(v) = \mathrm{RED} \Rightarrow \mathrm{color}(\mathrm{left}(v)) = \mathrm{color}(\mathrm{right}(v)) = \mathrm{BLACK}$ — RED가 두 번 연속될 수 없다.
5. **Black 높이**: 임의 노드 $v$에서 그 서브트리의 모든 NIL까지 가는 경로마다 만나는 Black 노드 수 $bh(v)$가 동일하다.

다섯 노드짜리 트리 예로 그려보면(괄호 안이 색):

```text
            10(B)
           /     \
        5(B)      15(B)
       /    \
    3(R)   7(R)
```

루트(10)에서 리프(NIL)까지 어느 경로를 따라가도 Black 노드 수가 같습니다 — `10→5→NIL`은 10, 5 두 개, `10→5→3→NIL`도 10, 5 두 개(3은 RED라 안 셈), `10→15→NIL`도 10, 15 두 개. 이게 속성 5가 말하는 "Black 높이 동일"입니다.

**왜 높이가 $O(\log n)$으로 잡히는가**를 가볍게 따져볼게요.

- 서브트리 $x$의 black-height가 $bh(x)$라면, 그 서브트리는 내부 노드를 최소 $2^{bh(x)} - 1$개 갖습니다(귀납: 리프는 $2^0-1=0$개, 한 단계 내려갈 때마다 최소 두 자식 서브트리가 각각 $bh-1$ 이상을 만족).
- 속성 4(연속 RED 금지) 덕분에, 루트에서 리프까지 어떤 경로든 **절반 이상이 BLACK**입니다. 그래서 실제 높이 $h \le 2\, bh(root)$.
- 두 식을 합치면 $n \ge 2^{bh(root)} - 1 \Rightarrow bh(root) \le \log_2(n+1) \Rightarrow h \le 2\log_2(n+1)$.

문제의 제약 $n \le 10^4$을 넣으면 $h \le 2\log_2(10001) \approx 26.6$, 즉 높이가 26을 넘지 않는다는 뜻이에요.

**액션(연산)** — 이 가이드가 정의하는 인터페이스 전부입니다.

| 액션 | 하는 일 | 비용 |
|------|---------|------|
| `insert(value)` | BST 삽입 → RED로 채색 → `fixupInsert`(회전 최대 2회) | $O(\log n)$ |
| `delete(value)` | BST 삭제(필요 시 후속자로 교체) → `fixupDelete`(회전 최대 3회) | $O(\log n)$ |
| `has(value)` | 일반 BST 탐색 | $O(\log n)$ |
| `min()` / `max()` | 최좌 / 최우 노드 값 | $O(\log n)$ |
| `inOrder()` | 중위 순회 배열 | $O(n)$ |
| `size()` | 저장된 원소 수 | $O(1)$ |

핵심 연산 두 개를 자세히 볼게요. 새 노드는 **항상 RED로** 삽입합니다(BLACK으로 넣으면 그 경로 전체의 black-height가 깨져 버리니까요). RED로 넣으면 최악의 경우도 "부모가 RED라 속성 4가 깨지는" 국소적인 문제 하나만 생깁니다.

**① 삽입 픽스업 — 3가지 케이스**

| 케이스 | 조건 | 해결 |
|--------|------|------|
| 1 | 삼촌이 RED | 부모·삼촌 → BLACK, 조부모 → RED, 조부모에서 재귀 |
| 2 | 삼촌 BLACK, 삼각형(triangle) 형태 | 부모 기준 회전 → 케이스 3 형태로 변환 |
| 3 | 삼촌 BLACK, 직선(line) 형태 | 조부모 기준 회전 + 부모↔조부모 색 교환 |

`insert(10), insert(5), insert(15), insert(3)`까지 실행하면 부모(5)도 삼촌(15)도 RED라 케이스 1이 발동합니다.

```text
케이스 1 (삼촌 RED, before → after):
      10(B)                  10(R)→강제 BLACK
     /     \                /      \
   5(R)   15(R)     →    5(B)     15(B)
   /                      /
  3(R,새로삽입)           3(R)
```

이어서 `insert(4)`를 하면 4는 3의 오른쪽 자식으로 들어가서, 부모(3)는 RED인데 삼촌(5의 오른쪽 NIL)은 BLACK인 **삼각형(LR)** 모양이 됩니다.

```text
삽입 직후 (부모 3, 조부모 5, 삼촌은 NIL=BLACK):
        5(B)
       /
     3(R)
       \
        4(R)      ← 삼각형: 조부모 기준 왼쪽 자식(3) 아래의 오른쪽 자식(4)

케이스 2: 3(부모) 기준 왼쪽 회전 →
        5(B)
       /
     4(R)
     /
   3(R)

케이스 3: 5(조부모) 기준 오른쪽 회전 + 색 교환 →
        4(B)
       /    \
     3(R)   5(R)
```

이 로컬 서브트리가 실제로는 10의 왼쪽 자식 자리에 있으므로, 전체 트리는 `10(B) - 좌:4(B) - 4의 자식: 3(R),5(R) - 10의 우:15(B)`가 됩니다.

**② 삭제 픽스업 — Double Black**

BLACK 노드를 지우면 그 경로의 black-height가 하나 모자라집니다. 이 "모자란 검정"을 double black이라 부르고, 4가지 케이스로 해소합니다.

| 케이스 | 조건 | 해결 |
|--------|------|------|
| 1 | 형제가 RED | 형제·부모 색 교환 + 부모 기준 회전 → 케이스 2~4로 진입 |
| 2 | 형제 BLACK, 형제의 두 자식 모두 BLACK | 형제 → RED, 이중 흑색을 부모로 전파(부모에서 다시 판정) |
| 3 | 형제 BLACK, 가까운 자식만 RED | 형제 자식·형제 색 교환 + 회전 → 케이스 4 형태로 변환 |
| 4 | 형제 BLACK, 먼 자식이 RED | 형제 ← 부모 색, 부모·먼 자식 → BLACK, 부모 기준 회전으로 즉시 해소 |

`insert(10,5,15,3,7)`로 만든 트리에서 `delete(15)`를 실행하면, 15 자리에 검정 하나가 비고 형제(5)의 먼 자식(3)이 RED라 케이스 4가 곧바로 발동합니다.

```text
Before delete(15):                 delete(15) → 케이스4 즉시 발동
            10(B)                        (형제 5의 먼 자식 3이 RED)
           /     \
        5(B)     15(B) ← 삭제 대상
       /    \
    3(R)   7(R)

After (5가 부모 자리로, 3은 BLACK으로 흡수, 7은 그대로 이동):
            5(B)
           /    \
        3(B)   10(B)
                 /
               7(R)
```

### 왜 모순 없이 작동하는가

**케이스 1이 안전한 이유**: 재채색 전에는 조부모가 BLACK(+1), 부모·삼촌은 RED(+0)였습니다. 재채색 후에는 조부모가 RED(+0), 부모·삼촌은 BLACK(+1)이 됩니다. 조부모를 거쳐 내려가는 어느 경로든 "조부모 기여 + 자식 기여" 합은 $1+0$에서 $0+1$로 바뀔 뿐 **총합은 그대로**예요. 그래서 black-height가 안 깨지고, 문제는 "조부모가 RED인데 조부모의 부모도 RED일 수 있다"는 형태로 한 단계 위로만 옮겨갑니다 — 그래서 `z = z.parent.parent`로 재귀하는 것이고, 트리 높이가 $O(\log n)$이니 이 전파도 $O(\log n)$ 안에 끝납니다.

**케이스 2·3이 안전한 이유**: 회전은 "왼쪽 < 가운데 < 오른쪽"이라는 BST 순서를 절대 깨지 않는 연산입니다(회전 전후로 서브트리들의 상대 순서가 그대로 보존돼요). 케이스 3에서는 회전 직전에 "부모→BLACK, 조부모→RED"로 색을 바꾸는데, 이러면 새로 그 자리에 올라서는 노드(옛 부모)의 색이 옛 조부모가 갖고 있던 색(BLACK)과 똑같아집니다. 그래서 그 지점을 거쳐 가는 black-height가 회전 전후로 동일하고, 동시에 RED-RED 위반도 완전히 사라져 더 이상 위로 전파되지 않고 끝납니다.

**삭제 케이스들이 안전한 이유**: double black은 "이 경로에 검정 하나가 빚졌다"는 장부상의 표시일 뿐이에요. 케이스 2는 형제를 RED로 바꿔 그 빚을 부모에게 넘기고(black-height 총합은 그대로, 대신 부모가 새로 빚을 짐), 케이스 1과 3은 회전으로 상황을 케이스 4로 만들어주고, 케이스 4는 회전 한 번으로 빚을 완전히 갚습니다 — 그래서 케이스 4에서 `x = this.root`로 즉시 루프를 종료시킬 수 있는 거예요.

여기서 헷갈리기 쉬운 포인트를 두 가지 짚어 둘게요.

- **"삼촌이 없다"와 "삼촌이 BLACK이다"는 같은 말입니다.** NIL 센티넬은 항상 BLACK이라서, 삼촌 자리가 비어 있어도 회전(케이스 2·3) 경로로 들어갑니다. 실제로 `insert(10), insert(5), insert(3)`을 해 보면 3의 삼촌은 아예 존재하지 않는데도(NIL), BLACK 취급되어 케이스 3(직선)이 곧바로 발동합니다 — 결과는 `5(BLACK)`이 새 부분 루트, `3(RED)`이 왼쪽, `10(RED)`이 오른쪽(실측 확인됨). "삼촌이 없으니 케이스 판단이 필요 없다"고 넘기면 이 회전을 놓칩니다.
- **케이스 2를 생략하면 RED-RED가 사라지지 않고 남습니다.** "삼촌이 BLACK이면 무조건 조부모 기준으로 한 번만 회전하면 되지 않을까?"라고 생각하기 쉬운데, 삼각형 모양에서 그렇게 하면 회전축이 틀려서 위반이 남아요. 아래 코드 절의 원형 예시에서 구체적으로 확인합니다.

빈 구조, 크기 1, 중복 등 엣지 케이스도 점검해 둡니다.

```text
빈 트리에서 has/min/max/delete   → false / undefined / undefined / false
노드 1개 트리에서 delete          → 빈 트리로, size 0, min/max undefined
중복 insert                      → has로 먼저 확인 후 무시(size 불변)
삭제 대상이 자식을 둘 다 가짐      → 오른쪽 서브트리의 최솟값(중위 후속자)으로 값만 교체
```

잠깐, 확인 하나만 해 볼까요? 케이스 1이 조부모까지 재귀적으로 반복돼서 루트까지 올라가면 루트 색은 어떻게 될까요? 답은 "상관없이 항상 BLACK"입니다 — `fixupInsert` 마지막 줄에서 `root.color = "BLACK"`을 무조건 한 번 더 강제하기 때문에, 케이스 1의 재귀가 루트를 RED로 남겨도 그 줄이 덮어써 줍니다.

## 아이디어를 코드로 옮기기

케이스 2(삼각형 → 직선 변환)를 왜 빼먹으면 안 되는지, 실제로 빼먹은 **원형** 코드로 확인해 봅시다. `insert(10,5,15,3,4)`를 이 원형에 통과시키면 어떻게 되는지가 핵심입니다.

```ts
// 원형: 케이스 2(삼각형 감지 → 부모 기준 회전)를 빼먹고 항상 케이스 3만 수행
function fixupInsertBuggy(z: RBNode<number>): void {
  while (z.parent.color === "RED") {
    const parent = z.parent;
    const grandparent = parent.parent;
    if (parent === grandparent.left) {
      const uncle = grandparent.right;
      if (uncle.color === "RED") {
        parent.color = "BLACK";
        uncle.color = "BLACK";
        grandparent.color = "RED";
        z = grandparent;
      } else {
        // ⚠ 케이스 2 분기(z === parent.right일 때 먼저 회전)가 빠져 있다
        parent.color = "BLACK";
        grandparent.color = "RED";
        rotateRight(grandparent);
      }
    }
    // (오른쪽 대칭 분기는 생략)
  }
}
```

`insert(10), insert(5), insert(15), insert(3)`까지는 전부 케이스 1만 타서 정상입니다. 문제는 `insert(4)`예요 — 4는 3의 오른쪽 자식(삼각형)으로 들어가는데, 이 원형은 삼각형 여부를 확인하지 않고 곧장 조부모(5) 기준으로 회전해 버립니다. 실제로 돌려 보면:

```text
버그 버전 실행 결과 (실측):
colors: 10=BLACK 5=RED 15=BLACK 3=BLACK 4=RED
연속 RED 위반: ["5-4"]   ← 5(RED)의 왼쪽 자식이 4(RED). 속성4 위반이 그대로 남았다!
```

회전축을 잘못 잡으니 3과 5의 위치만 뒤바뀔 뿐, 원래 있던 "부모-자식 RED 연속" 문제가 **다른 두 노드(5-4) 사이로 옮겨갈 뿐 사라지지 않습니다**. 케이스 2가 먼저 "삼각형을 직선으로 펴 주는" 역할을 해야, 케이스 3의 회전축이 정확히 위반을 없애는 자리에 놓입니다.

최종 구현은 이 삼각형 판정(`z === z.parent.right`)을 포함합니다. 아래는 이 가이드가 정의한 인터페이스(`insert`/`delete`/`has`/`min`/`max`/`inOrder`/`size`, 제네릭 `T`, 선택적 `comparator`) 전체 구현입니다.

```ts
type RBColor = "RED" | "BLACK";

class RBNode<T> {
  value: T;
  color: RBColor;
  left: RBNode<T>;
  right: RBNode<T>;
  parent: RBNode<T>;

  constructor(value: T, color: RBColor, self?: RBNode<T>) {
    this.value = value;
    this.color = color;
    this.left = self ?? (this as unknown as RBNode<T>);
    this.right = self ?? (this as unknown as RBNode<T>);
    this.parent = self ?? (this as unknown as RBNode<T>);
  }
}

class RedBlackTree<T> {
  private NIL: RBNode<T>;
  private root: RBNode<T>;
  private _size = 0;
  private compare: (a: T, b: T) => number;

  constructor(comparator?: (a: T, b: T) => number) {
    this.NIL = new RBNode<T>(undefined as unknown as T, "BLACK");
    this.NIL.left = this.NIL;
    this.NIL.right = this.NIL;
    this.NIL.parent = this.NIL;
    this.root = this.NIL;
    this.compare = comparator ?? ((a, b) => (a < b ? -1 : a > b ? 1 : 0));
  }

  private rotateLeft(x: RBNode<T>): void {
    const y = x.right;
    x.right = y.left;
    if (y.left !== this.NIL) y.left.parent = x;
    y.parent = x.parent;
    if (x.parent === this.NIL) this.root = y;
    else if (x === x.parent.left) x.parent.left = y;
    else x.parent.right = y;
    y.left = x;
    x.parent = y;
  }

  private rotateRight(x: RBNode<T>): void {
    const y = x.left;
    x.left = y.right;
    if (y.right !== this.NIL) y.right.parent = x;
    y.parent = x.parent;
    if (x.parent === this.NIL) this.root = y;
    else if (x === x.parent.right) x.parent.right = y;
    else x.parent.left = y;
    y.right = x;
    x.parent = y;
  }

  private findNode(value: T): RBNode<T> {
    let node = this.root;
    while (node !== this.NIL) {
      const cmp = this.compare(value, node.value);
      if (cmp === 0) return node;
      node = cmp < 0 ? node.left : node.right;
    }
    return this.NIL;
  }

  has(value: T): boolean {
    return this.findNode(value) !== this.NIL;
  }

  insert(value: T): void {
    if (this.has(value)) return; // set 의미론: 중복 무시

    const z = new RBNode<T>(value, "RED", this.NIL);
    let y = this.NIL;
    let x = this.root;
    while (x !== this.NIL) {
      y = x;
      x = this.compare(z.value, x.value) < 0 ? x.left : x.right;
    }
    z.parent = y;
    if (y === this.NIL) this.root = z;
    else if (this.compare(z.value, y.value) < 0) y.left = z;
    else y.right = z;

    this._size++;
    this.fixupInsert(z);
  }

  private fixupInsert(z: RBNode<T>): void {
    while (z.parent.color === "RED") {
      if (z.parent === z.parent.parent.left) {
        const uncle = z.parent.parent.right;
        if (uncle.color === "RED") {
          // 케이스 1
          z.parent.color = "BLACK";
          uncle.color = "BLACK";
          z.parent.parent.color = "RED";
          z = z.parent.parent;
        } else {
          if (z === z.parent.right) {
            // 케이스 2: 삼각형 → 직선으로 변환
            z = z.parent;
            this.rotateLeft(z);
          }
          // 케이스 3: 직선 → 회전 + 색 교환
          z.parent.color = "BLACK";
          z.parent.parent.color = "RED";
          this.rotateRight(z.parent.parent);
        }
      } else {
        const uncle = z.parent.parent.left;
        if (uncle.color === "RED") {
          z.parent.color = "BLACK";
          uncle.color = "BLACK";
          z.parent.parent.color = "RED";
          z = z.parent.parent;
        } else {
          if (z === z.parent.left) {
            z = z.parent;
            this.rotateRight(z);
          }
          z.parent.color = "BLACK";
          z.parent.parent.color = "RED";
          this.rotateLeft(z.parent.parent);
        }
      }
    }
    this.root.color = "BLACK";
  }

  private minimumNode(node: RBNode<T>): RBNode<T> {
    while (node.left !== this.NIL) node = node.left;
    return node;
  }

  min(): T | undefined {
    if (this.root === this.NIL) return undefined;
    return this.minimumNode(this.root).value;
  }

  max(): T | undefined {
    if (this.root === this.NIL) return undefined;
    let node = this.root;
    while (node.right !== this.NIL) node = node.right;
    return node.value;
  }

  private transplant(u: RBNode<T>, v: RBNode<T>): void {
    if (u.parent === this.NIL) this.root = v;
    else if (u === u.parent.left) u.parent.left = v;
    else u.parent.right = v;
    v.parent = u.parent;
  }

  delete(value: T): boolean {
    const z = this.findNode(value);
    if (z === this.NIL) return false;

    let y = z;
    let yOriginalColor = y.color;
    let x: RBNode<T>;

    if (z.left === this.NIL) {
      x = z.right;
      this.transplant(z, z.right);
    } else if (z.right === this.NIL) {
      x = z.left;
      this.transplant(z, z.left);
    } else {
      y = this.minimumNode(z.right); // 중위 후속자
      yOriginalColor = y.color;
      x = y.right;
      if (y.parent === z) {
        x.parent = y; // NIL x라도 부모를 세팅해 둬야 fixup이 위치를 안다
      } else {
        this.transplant(y, y.right);
        y.right = z.right;
        y.right.parent = y;
      }
      this.transplant(z, y);
      y.left = z.left;
      y.left.parent = y;
      y.color = z.color;
    }

    this._size--;
    if (yOriginalColor === "BLACK") this.fixupDelete(x);
    return true;
  }

  private fixupDelete(x: RBNode<T>): void {
    while (x !== this.root && x.color === "BLACK") {
      if (x === x.parent.left) {
        let sibling = x.parent.right;
        if (sibling.color === "RED") {
          // 케이스 1
          sibling.color = "BLACK";
          x.parent.color = "RED";
          this.rotateLeft(x.parent);
          sibling = x.parent.right;
        }
        if (sibling.left.color === "BLACK" && sibling.right.color === "BLACK") {
          // 케이스 2: 이중 흑색을 부모로 전파
          sibling.color = "RED";
          x = x.parent;
        } else {
          if (sibling.right.color === "BLACK") {
            // 케이스 3: 케이스 4 형태로 변환
            sibling.left.color = "BLACK";
            sibling.color = "RED";
            this.rotateRight(sibling);
            sibling = x.parent.right;
          }
          // 케이스 4: 즉시 해소
          sibling.color = x.parent.color;
          x.parent.color = "BLACK";
          sibling.right.color = "BLACK";
          this.rotateLeft(x.parent);
          x = this.root;
        }
      } else {
        let sibling = x.parent.left;
        if (sibling.color === "RED") {
          sibling.color = "BLACK";
          x.parent.color = "RED";
          this.rotateRight(x.parent);
          sibling = x.parent.left;
        }
        if (sibling.right.color === "BLACK" && sibling.left.color === "BLACK") {
          sibling.color = "RED";
          x = x.parent;
        } else {
          if (sibling.left.color === "BLACK") {
            sibling.right.color = "BLACK";
            sibling.color = "RED";
            this.rotateLeft(sibling);
            sibling = x.parent.left;
          }
          sibling.color = x.parent.color;
          x.parent.color = "BLACK";
          sibling.left.color = "BLACK";
          this.rotateRight(x.parent);
          x = this.root;
        }
      }
    }
    x.color = "BLACK";
  }

  inOrder(): T[] {
    const result: T[] = [];
    const walk = (node: RBNode<T>) => {
      if (node === this.NIL) return;
      walk(node.left);
      result.push(node.value);
      walk(node.right);
    };
    walk(this.root);
    return result;
  }

  size(): number {
    return this._size;
  }
}
```

가장 중요한 부분은 `rotateLeft`/`rotateRight`에서 **부모 포인터를 세 방향 모두** 갱신하는 것입니다 — 자식→부모(`y.parent = x.parent`), 부모→자식(`x.parent.left/right = y` 또는 `this.root = y`), 그리고 회전축 자신(`x.parent = y`). 하나라도 빠지면 위쪽에서 내려오는 탐색이 회전된 서브트리를 못 찾거나, 픽스업이 엉뚱한 조부모를 가리키게 됩니다.

놓치기 쉬운 지점을 더 짚어볼게요.

- **`delete`의 `if (y.parent === z)` 분기.** 삭제 대상 `z`가 두 자식을 가질 때, 후속자 `y`가 `z`의 바로 오른쪽 자식이면 `y.right`를 따로 `transplant`할 필요가 없습니다. 이 분기를 놓치면 `x.parent`가 옛 위치를 가리켜 `fixupDelete`가 완전히 엉뚱한 형제를 봅니다.
- **케이스 판정 순서.** 삽입 픽스업의 케이스 2는 반드시 케이스 3보다 먼저 검사해야 합니다 — 위 원형 예시(`5-4` RED-RED 잔존)가 그 이유를 보여줍니다.
- **`fixupDelete`의 좌우 대칭.** `x === x.parent.left`로 시작하는 블록과 `else` 블록은 완전한 거울상입니다. 왼쪽 케이스에서 `sibling.right`를 보는 자리는 오른쪽 케이스에서 `sibling.left`가 됩니다 — 복사하면서 한쪽만 못 바꾸면 무작위 삭제에서 드물게만 터지는 버그가 됩니다.

> 기억법: "삽입은 밑에서 위로 색을 정리하고(fixupInsert), 삭제는 위에서 새는 검정 하나를 형제에게서 꿔 오거나(케이스 1~3) 그 자리에서 갚습니다(케이스 4)."

## 실행 시각화

`insert(10), insert(5), insert(15), insert(3)`까지는 항상 케이스 1(삼촌 RED)만 발동해서 10·5·15가 모두 BLACK, 3만 RED로 정리됩니다. 이어서 `insert(4)`를 하면 4가 3의 오른쪽 자식으로 들어가 삼각형이 만들어지고, 케이스 2(3 기준 왼쪽 회전) → 케이스 3(5 기준 오른쪽 회전 + 색 교환)이 순서대로 발동해 최종 레벨-오더 배열은 `[10, 4, 15, 3, 5, 0, 0]`(빈 자리는 0)이 됩니다 — 즉 10이 여전히 전체 루트이고, 그 왼쪽 자식이 5에서 4로 바뀝니다. 앞의 다섯 프레임은 "지금까지 삽입한 값" 순서 그대로를 보여주고, 마지막 프레임만 회전 결과를 확인할 수 있도록 레벨-오더 트리 스냅샷으로 전환됩니다. `highlight`는 지금 처리 중인 노드, `marked`는 함께 영향을 받은 노드입니다.
