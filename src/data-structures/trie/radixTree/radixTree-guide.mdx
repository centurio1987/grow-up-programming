# RadixTree — 갈림길만 노드로 남기고, 외길은 문자열 하나로 접기

## 한눈에 보는 컨셉

Trie는 "romane"라는 단어 하나를 저장하는 데도 r→o→m→a→n→e, 6개의 노드가 필요해요. 그런데 이 중 갈림길(분기)이 없는 구간은 압축해도 정보 손실이 없습니다 — 자식이 하나뿐인 노드들을 이어 붙여 에지에 문자 하나 대신 **문자열 전체**를 저장하면 됩니다. 이렇게 압축한 구조가 Radix Tree(= Patricia Trie)이고, 노드 수가 전체 문자 수가 아니라 **저장된 단어 수**에 비례하게 줄어듭니다. Linux 커널의 IP 라우팅 테이블(`ip_fib_trie`)이 수십만 개의 IP 접두사를 이 구조로 관리해요.

## 언제, 왜 쓰는가

### 이런 단서가 보이면

다음 신호가 겹치면 Radix Tree를 떠올리세요.

- 문자열 **집합**에 대해 정확히 일치(`search`)뿐 아니라 **접두사 검색**(`startsWith`, `wordsWithPrefix`)도 필요하다
- 저장할 단어들이 **길고**, 서로 공유하는 접두사가 상대적으로 **적다**(URL, 파일 경로, IP 접두사처럼)
- 삽입·삭제가 반복되는 와중에도 메모리를 단어 수에 비례하게 유지해야 한다(임베디드·라우터처럼 메모리가 빠듯한 환경)

일반 Trie와 비교하면 차이가 뚜렷합니다.

```text
naive Trie: 단어 "romane" 저장                Radix Tree: 같은 단어
r -> o -> m -> a -> n -> e(END)               "romane"(END)  ← 에지 하나
6개 노드, 전부 자식 1개(직선 경로)             1개 노드
```

일반화하면 이렇습니다($n$ = 삽입된 단어 수, $L$ = 전체 문자 총합).

```text
Trie 노드 수         O(L)     ← 공유 안 되는 글자도 각각 노드
Radix Tree 노드 수   O(n)     ← 분기점 + 리프만 노드
insert / search / startsWith / delete   둘 다 O(단어 길이)
```

**선택 기준**: 알파벳 크기가 작고 접두사 공유가 두껍게 겹치면(사전 순 자동완성처럼) 일반 Trie도 이미 조밀해서 압축 이득이 작습니다. 반대로 단어가 길고 공유되는 접두사가 적으면(IP 주소, 파일 경로) Radix Tree가 메모리를 크게 아낍니다. 정확히 일치만 필요하고 접두사 질의가 아예 없다면 Hash Set이 더 간단해요(평균 O(1)이지만 접두사 검색은 아예 불가능합니다).

### 문제 사례와 적용 예시

- **Linux 커널 IP 라우팅 테이블**: `ip_fib_trie`가 수십만 개의 IP 접두사를 Radix Tree로 관리하며 최장 접두사 매칭(LPM)을 고속으로 수행합니다.
- **파일 시스템 경로 인덱스**: `/usr/local/bin`, `/usr/local/lib`처럼 공통 디렉터리 접두사가 많은 경로 집합을 압축 저장합니다.
- **코딩 테스트 맥락**: "문자열 집합을 저장하고, 특정 접두사로 시작하는 단어를 모두 나열하라"는 요구에 메모리 제한이 타이트하게 걸려 있을 때 — 일반 Trie로 짜면 메모리 초과가 나는 상황에서 Radix Tree 압축이 필요해집니다.

## 자료구조 자세히 들여다보기

### 전체 스펙: 속성과 액션

이 가이드에서는 다음 인터페이스를 기준으로 설명합니다.

```ts
interface RadixNode {
  children: Map<string, RadixNode>; // 에지 첫 문자 → 자식 노드
  label: string;                    // 이 에지의 레이블(문자열 전체)
  isEnd: boolean;                   // 루트~이 노드 경로가 완성된 단어의 끝인지
}
```

트리 전체는 `root`(빈 레이블의 더미 노드)와 저장된 단어 수 `count`를 유지합니다.

지켜야 할 불변식은 세 가지입니다.

1. **경로 = 문자열.** 루트에서 어떤 노드 $v$까지 내려가며 거친 에지 레이블을 순서대로 이어 붙이면, 그 결과가 $v$가 나타내는 문자열입니다.
2. **키는 첫 문자와 일치.** `children`의 각 항목 (key, child)에 대해 $\text{key} = \text{child.label}[0]$입니다 — 그래서 O(1)에 다음 에지를 고를 수 있어요.
3. **압축 조건(핵심 불변식).** 루트가 아닌 노드 $v$에 대해:

$$
v.\text{isEnd} = \text{false} \implies |v.\text{children}| \geq 2
$$

말로 풀면 "종료 지점이 아닌 노드는 반드시 분기점이어야 한다"입니다. 자식이 하나뿐이면서 종료 지점도 아닌 노드는 존재 이유가 없어요 — 있다면 즉시 자식과 합쳐 압축해야 합니다.

트리 전체 모양은 이렇게 그려집니다(아래에서 계속 다룰 예시의 완성 형태).

```text
ROOT
 └─"r"───┬─"om"──┬─"an"──┬─"e"(END)
         │        │        └─"us"(END)
         │        └─"ulus"(END)
         └─"uber"(END)

경로 ROOT→"r"→"om"→"an"→"e" 를 이어붙이면 "r"+"om"+"an"+"e" = "romane" (END 도달 = 단어 완성)
"rom"이나 "roman"에서 멈추면 문자열 자체는 만들어지지만 END가 아니므로 단어는 아니다
```

**액션(연산)** — 이 자료구조가 제공하는 전부입니다.

| 액션 | 하는 일 | 비용 |
|------|---------|------|
| `insert(word)` | 공통 접두사에서 에지를 분할하며 삽입 | $O(m)$, $m$ = 단어 길이 |
| `search(word)` | 경로를 소비하며 내려가 `isEnd` 확인 | $O(m)$ |
| `startsWith(prefix)` | 접두사 경로가 끝까지 존재하는지만 확인 | $O(m)$ |
| `delete(word)` | 종료 표시 해제 후 죽은 에지 제거·병합 | $O(m)$ |
| `wordsWithPrefix(prefix)` | 접두사 노드부터 서브트리 전체 DFS 수집 | $O(m + k)$, $k$ = 결과 문자 총합 |
| `size()` | 저장된 단어 수 | $O(1)$ |

핵심 연산 두 개를 자세히 봅니다.

**① insert의 에지 분할** — `romane`가 이미 있는 상태에 `romanus`를 넣는 상황입니다.

```text
Before: ROOT --"romane"(END)--

remaining = "romanus", child.label = "romane"
공통 접두사 계산: r-o-m-a-n 까지 같고 6번째서 e≠u → common = "roman" (5글자)
common.length(5) < child.label.length(6) → 완전 일치 아님 → 분할해야 함

After:  ROOT --"roman"(분기점, isEnd=false)--┬--"e"(END)
                                              └--"us"(END)
```

기존 에지 레이블 "romane"를 공통 부분 "roman"과 나머지 "e"로 자르고, "roman" 자리에 새 중간 노드를 끼운 뒤 "e"(기존 자식)와 "us"(새 단어의 나머지)를 그 자식으로 겁니다.

**② delete의 노드 병합** — `cat`, `car`가 있는 상태에서 `cat`을 지우는 상황입니다.

```text
Before: ROOT --"c"--"a"(분기점)--┬--"t"(END)
                                  └--"r"(END)

delete("cat"): "t" 노드의 isEnd를 false로 내림. "t"는 이제 isEnd=false, 자식 0개
              → 압축 조건 위반(분기점도 아닌데 존재) → 통째로 제거

After 1단계: ROOT --"c"--"a"(분기점)--"r"(END)   ← "a" 노드가 자식 1개, isEnd=false → 또 위반!

After 2단계(병합): ROOT --"car"(END)             ← "a"+"r" 레이블을 이어붙여 노드 하나로
```

### 왜 모순 없이 작동하는가

**압축 조건이 항상 유지되는 이유**를 삽입과 삭제 양쪽에서 귀납적으로 봅니다.

- **삽입(분할)이 불변식을 지키는 이유**: 분할이 일어나는 경우는 공통 접두사가 기존 에지 레이블보다 짧을 때뿐입니다. 이때 새로 생기는 중간 노드는 자식을 **정확히 2개**(기존 자식 하나 + 새 단어의 나머지 하나) 갖고 시작하거나, 새 단어가 공통 접두사에서 끝나면 그 자리에서 바로 `isEnd = true`가 됩니다. 두 경우 모두 압축 조건 $\lnot isEnd \Rightarrow |children| \geq 2$을 즉시 만족해요.
- **삭제(병합)가 불변식을 지키는 이유**: 삭제는 `isEnd`를 내리는 것만으로 끝나지 않습니다. 그 결과 위반이 생기면(자식 0개인데 비종료, 또는 자식 1개인데 비종료) 즉시 고칩니다 — 자식 0개면 에지 자체를 제거하고, 자식 1개면 레이블을 이어 붙여 병합합니다. 병합·제거 직후에는 그 자리에 조건을 위반하는 노드가 남지 않으므로, 트리는 항상 압축 상태로 복귀합니다.

귀납적으로 보면: 빈 트리(불변식 자명 성립) → 매 `insert`/`delete` 호출이 불변식을 보존 → 어느 시점에도 트리는 압축 상태입니다. 그래서 노드 수가 항상 현재 저장된 단어 수 $n$에 대해 $O(n)$에 머물러요.

**여기서 헷갈리기 쉬운 포인트**를 세 가지 짚습니다.

- **분기점 경로에 도달했다고 단어가 있는 게 아닙니다.** 위 그림에서 "roman"까지는 경로가 존재하지만 그 노드의 `isEnd`는 `false`입니다. 실제로 `search("roman")`, `search("rom")` 모두 `false`예요 — 둘 다 분기점일 뿐 삽입된 단어가 아니거든요. 반면 `startsWith("roman")`은 `true`입니다 — 접두사 검사는 경로 존재만 확인하지 `isEnd`를 보지 않기 때문이에요.
- **`children` 맵의 순회 순서는 삽입 순서를 따르지, 알파벳 순이 아닙니다.** JS의 `Map`은 삽입 순서를 보존하므로 `wordsWithPrefix`가 DFS로 훑는 순서도 "어떤 순서로 삽입됐는가"에 좌우됩니다. `zebra`, `apple`, `zoo` 순서로 삽입하면 `wordsWithPrefix("")`는 `["zebra", "zoo", "apple"]`을 반환해요 — 알파벳 순이라고 가정하면 틀립니다. 정렬이 필요하면 반환값에 명시적으로 `.sort()`를 호출해야 합니다.
- **삭제에서 "자식 0개"와 "자식 1개"는 서로 다른 처리가 필요합니다.** 두 경우를 "자식 1개 이하면 병합"으로 뭉뚱그리면, 자식 0개인데 병합 코드를 타면서 존재하지 않는 손자를 참조해 오동작합니다. 반대로 자식 0개 케이스를 아예 빼먹고 죽은 에지를 트리에 남겨두면 — 위 `cat`/`car` 예시에서 `delete("cat")` 후에도 죽은 "t" 에지가 남아 있다고 하면 `startsWith("cat")`이 잘못 `true`를 반환합니다(실측으로 확인한 올바른 결과는 `false`입니다). "자식 0개·비종료 → 에지 제거", "자식 1개·비종료 → 레이블 병합"은 반드시 서로 다른 분기로 나눠야 합니다.

잠깐, 확인 하나만 해 볼까요? `romane`, `romanus`, `romulus`, `ruber`가 들어있는 트리에서 `search("rube")`를 호출하면 결과가 뭘까요? — "ruber" 에지는 "r" 다음 "uber" 하나로 통짜입니다. "rube"까지 소비하려면 "uber" 에지의 앞부분 "ube"까지는 맞아떨어지지만 4번째 글자에서 에지 레이블과 어긋나 버려요. 에지 레이블 도중에 끊기면 그 지점에서 바로 실패이므로 답은 `false`입니다.

엣지 케이스 점검:

```text
빈 트리에서 search / startsWith / delete   → false / false / false
빈 트리에서 wordsWithPrefix("")            → []
단일 문자 단어("a") 삽입/삭제               → 정상 동작, 삭제 후 size 0
중복 삽입("dup" 두 번)                     → size 불변 (isEnd가 이미 true라 count 증가 없음)
한 단어가 다른 단어의 접두사("test"/"testing") → 둘 다 검색 가능, "test" 삭제해도 "testing" 유지
```

## 아이디어를 코드로 옮기기

본격적인 구현 전에, "원형"에서 무엇이 바뀌었는지 타입으로 한 번 더 확인해 볼게요.

```ts
// 원형(naive Trie): 에지가 문자 하나
interface TrieNode {
  children: Map<string, TrieNode>; // 키 = 문자 1개
  isEnd: boolean;
}

// 최종(Radix Tree): 에지가 문자열 전체
interface RadixNode {
  children: Map<string, RadixNode>; // 키 = 에지의 첫 문자
  label: string;                    // 에지 전체 문자열 — naive Trie엔 없던 필드
  isEnd: boolean;
}
```

차이는 `label` 필드 하나예요. 이 필드 덕분에 자식이 하나뿐인 구간을 통째로 한 노드에 몰아넣을 수 있습니다 — naive Trie는 글자마다 노드를 새로 만들 수밖에 없었지만, Radix Tree는 "다음 분기가 나올 때까지"의 모든 글자를 `label`에 담아버려요.

이제 전체 구현입니다.

```ts
interface RadixNode {
  children: Map<string, RadixNode>; // 에지 첫 문자 → 자식 노드
  label: string;                    // 이 에지의 레이블(문자열 전체)
  isEnd: boolean;                   // 루트~이 노드 경로가 완성된 단어의 끝인지
}

function commonPrefixLength(a: string, b: string): number {
  const max = Math.min(a.length, b.length);
  let i = 0;
  while (i < max && a[i] === b[i]) i++;
  return i;
}

function makeNode(label: string, isEnd: boolean): RadixNode {
  return { children: new Map(), label, isEnd };
}

export class RadixTree {
  private root: RadixNode;
  private count: number;

  constructor() {
    this.root = makeNode("", false);
    this.count = 0;
  }

  insert(word: string): void {
    this.insertHelper(this.root, word);
  }

  private insertHelper(node: RadixNode, remaining: string): void {
    if (remaining === "") {
      if (!node.isEnd) {
        node.isEnd = true;
        this.count++;
      }
      return;
    }

    const firstChar = remaining[0]!;
    const child = node.children.get(firstChar);

    if (child === undefined) {
      node.children.set(firstChar, makeNode(remaining, true));
      this.count++;
      return;
    }

    const common = commonPrefixLength(child.label, remaining);

    if (common === child.label.length) {
      // 에지 전체를 소비했으니 자식으로 내려간다
      this.insertHelper(child, remaining.slice(common));
      return;
    }

    // 부분 일치: common 지점에서 에지를 분할한다
    const mid = makeNode(child.label.slice(0, common), false);
    child.label = child.label.slice(common);          // ① 먼저 자르고
    mid.children.set(child.label[0]!, child);          // ② 잘린 결과의 첫 글자를 키로 등록

    const rest = remaining.slice(common);
    if (rest === "") {
      mid.isEnd = true;
    } else {
      mid.children.set(rest[0]!, makeNode(rest, true));
    }
    this.count++;
    node.children.set(firstChar, mid);
  }

  search(word: string): boolean {
    const node = this.findExactNode(word);
    return node !== undefined && node.isEnd;
  }

  startsWith(prefix: string): boolean {
    return this.findPrefixNode(prefix) !== undefined;
  }

  private findExactNode(word: string): RadixNode | undefined {
    let node = this.root;
    let remaining = word;
    while (remaining !== "") {
      const child = node.children.get(remaining[0]!);
      if (child === undefined || !remaining.startsWith(child.label)) return undefined;
      remaining = remaining.slice(child.label.length);
      node = child;
    }
    return node;
  }

  // prefix가 에지 중간에서 끝나도(= 아직 분기점 이전이어도) 그 에지의 노드를 반환한다.
  private findPrefixNode(prefix: string): RadixNode | undefined {
    let node = this.root;
    let remaining = prefix;
    while (remaining !== "") {
      const child = node.children.get(remaining[0]!);
      if (child === undefined) return undefined;
      if (child.label.startsWith(remaining)) return child;
      if (!remaining.startsWith(child.label)) return undefined;
      remaining = remaining.slice(child.label.length);
      node = child;
    }
    return node;
  }

  delete(word: string): boolean {
    return this.deleteHelper(this.root, word);
  }

  private deleteHelper(node: RadixNode, remaining: string): boolean {
    if (remaining === "") {
      if (!node.isEnd) return false;
      node.isEnd = false;
      this.count--;
      return true;
    }

    const firstChar = remaining[0]!;
    const child = node.children.get(firstChar);
    if (child === undefined || !remaining.startsWith(child.label)) return false;

    const deleted = this.deleteHelper(child, remaining.slice(child.label.length));
    if (!deleted) return false;

    // 자식 0개(비종료)면 에지 자체를 제거, 자식 정확히 1개(비종료)면 레이블을 이어붙여 압축
    if (!child.isEnd && child.children.size === 0) {
      node.children.delete(firstChar);
    } else if (!child.isEnd && child.children.size === 1) {
      const [, grandchild] = [...child.children.entries()][0]!;
      child.label = child.label + grandchild.label;
      child.isEnd = grandchild.isEnd;
      child.children = grandchild.children;
    }
    return true;
  }

  wordsWithPrefix(prefix: string): string[] {
    let node = this.root;
    let remaining = prefix;
    let matchedSoFar = "";
    while (remaining !== "") {
      const child = node.children.get(remaining[0]!);
      if (child === undefined) return [];
      if (child.label.startsWith(remaining)) {
        return this.collect(child, matchedSoFar + child.label);
      }
      if (!remaining.startsWith(child.label)) return [];
      matchedSoFar += child.label;
      remaining = remaining.slice(child.label.length);
      node = child;
    }
    return this.collect(node, matchedSoFar);
  }

  private collect(node: RadixNode, prefixSoFar: string): string[] {
    const result: string[] = [];
    if (node.isEnd) result.push(prefixSoFar);
    for (const child of node.children.values()) {
      result.push(...this.collect(child, prefixSoFar + child.label));
    }
    return result;
  }

  size(): number {
    return this.count;
  }
}
```

가장 중요한 부분은 **`insertHelper`의 분기 조건 하나**입니다 — `common === child.label.length`. 이게 참이면 에지를 통째로 소비했다는 뜻이라 그냥 재귀로 내려가면 되고, 거짓이면 에지 중간에서 끊겼다는 뜻이라 분할이 필요합니다. 이 한 줄이 "재귀냐 분할이냐"를 가릅니다.

구현에서 놓치기 쉬운 지점들:

- **분할 시 `child.label = child.label.slice(common)`을 먼저 실행하고, 그 다음에 `mid.children.set(child.label[0]!, child)`를 실행해야 합니다.** 순서를 바꿔서 자르기 전의 `child.label[0]`을 키로 등록하면, 나중에 그 키로 찾아도 실제 레이블의 첫 글자와 어긋나는 잘못된 맵이 만들어집니다. 기억법: **"자르고 나서 잇는다."**
- **`delete`의 세 갈래(자식 0개 / 자식 1개 / 자식 2개 이상 또는 isEnd)를 하나로 뭉치면 안 됩니다.** 위 "왜 모순 없이 작동하는가"에서 본 `cat`/`car` 예시가 바로 이 지점의 함정입니다.
- **`findPrefixNode`는 `search`용 `findExactNode`와 다른 함수입니다.** 접두사가 에지 중간에서 끝나도(`child.label.startsWith(remaining)`) 성공으로 봐야 하기 때문에, 완전 일치만 확인하는 `findExactNode`를 그대로 재사용할 수 없습니다.
