## 솔루션 src/$ARGUMENTS.ts에 대해 분석한다.

1. 문제 해결 접근 방법에 대한 방향성이 올바른지 분석한다.
2. !`bun test src/$ARGUMENTS.test.ts 2>&1; true` 테스트 결과에 기반하여, 정확성 측면에서 분석한다.
3. 최적화 측면에서 분석한다.
   3.1. 개선 가능하다면, 핵심 아이디어에 대해 자세히 설명한다.
   3.1.1 알고리즘 원형이 존재한다면, 원형에서 문제 해결책을 유도하는 전개 과정을 꼼꼼히 기술한다.

4. 분석 보고서를 쓰기 전에 먼저 rereview-canvas.md를 열어 읽어라. 골격은 거기에 있다.
   $ARGUMENTS 끝에 `.ts`가 붙어 있으면 떼고 경로를 만든다.
   예: 인자가 algorithms/sorting/countingSort/countingSort이면
       루트 보고서는 src/algorithms/sorting/countingSort/countingSort-analysis.md이고
       재검토 디렉터리는 src/algorithms/sorting/countingSort/countingSort-analysis/ 다.
   4-1. 최초 분석이면 루트 보고서 하나만 만든다. 이 문서가 1회차다.
   4-2. 재검토는 버그 수정이든 컨셉 변경이든, 루트 보고서에 덧붙이지 말고 새 파일 하나를 만들어라.
        경로는 src/$ARGUMENTS-analysis/r<NN>-<YYYY-MM-DD>-<bugfix|concept>.md 다.
        <NN>은 두 자리 회차다. 회차를 정하려면 두 곳을 다 봐라 —
        루트 보고서의 `## 재검토 이력` 표에 적힌 최대 회차와,
        src/$ARGUMENTS-analysis/ 안에 있는 파일 이름의 최대 회차.
        둘 중 큰 값 + 1이 이번 회차다. 표만 보거나 디렉터리만 보면 회차가 겹친다.
        유형 슬러그는 버그 수정이면 bugfix, 컨셉 변경이면 concept 다.
   4-3. 재검토 파일의 `##` 헤딩은 rereview-canvas.md의 `## 재검토 파일` 절을 그대로 쓴다.
        문구와 순서를 바꾸지 말아라.
   4-4. 재검토 파일을 만들었으면 루트 보고서의 머리 블록을 갱신해라.
        `<!-- analysis-head:시작 -->`와 `<!-- analysis-head:끝 -->` 사이가 갱신 구역이다.
        `## 현재 상태`는 이번 회차 기준으로 통째로 새로 쓰고,
        `## 재검토 이력` 표에는 이번 회차 한 행을 맨 아래에 추가한다.
        마커와 두 블록이 아직 없으면 H1 바로 아래에 새로 만든다. 형식은 rereview-canvas.md에 있다.
   4-5. `## 현재 상태`의 각 줄은 이렇게 채운다.
        - 테스트: 2번에서 실행한 결과의 pass/fail 수를 그대로 옮긴다.
          결과를 얻지 못했으면 `미실행`이라고 적는다.
        - 판정: `해결` / `일부 해결` / `미해결` / `미확정` 중 하나에 한 문장 근거를 붙인다.
          실패가 하나라도 있으면 `해결`을 쓰지 말아라. 테스트가 `미실행`이면 `미확정`이다.
        - 남은 항목: 이번 회차 파일의 `## 3. 남은 버그`를 한 줄로 옮긴다. 없으면 `없음`.
        - 최신 재검토: 이번 회차 파일로 가는 상대 링크.

## 참조 파일

- `rereview-canvas.md` — 루트 보고서 머리 블록과 재검토 파일의 골격

## 제약 조건

- 재실행인데 마지막 회차 파일에 적힌 코드 변경 사항·테스트 결과가 지금 것과 같으면 무시해라.
  즉 src/$ARGUMENTS.ts가 그때 그대로이고 테스트 결과도 같으면 새 회차를 만들지 말아라.
- '개인 정리' 항목은 수정하지 말아라. 재검토 파일에는 '개인 정리'를 만들지 말아라.
- 루트 보고서에서 고쳐도 되는 곳은 analysis-head 마커 사이뿐이다.
  `## 1.` 이후의 본문은 낡았더라도 고치지 말아라. 지금 상태는 `## 현재 상태`가 말한다.
- 문서끼리 거는 링크는 상대 경로로 적고, 다 적었으면 `bun run tools/check-links.ts check`로 확인해라.
- 파일의 최신 상태를 보고 있는지 확인 해라
- 핵심 아이디어 설명 시, 초등학생도 이해할 수 있을 정도로 꼼꼼하게 설명한다. 단, 비유나 묘사 없이, 정식 표기법과 용어만 사용한다.
