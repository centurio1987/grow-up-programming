## 알고리즘 가이드와 무엇이 다른가

**문제에 종속되지 않는 독립 가이드**다. 알고리즘 가이드가 *"순진한 방법에서 출발해 관찰로
단서를 얻고 최적화로 바꾸는"* 유도 서사라면, 이쪽은 **스펙 전수 설명 + 언제 쓰는가**가 중심이다.

```
컨셉 → 언제·왜 쓰는가(단서) → 스펙 전수(속성·액션) → 구현 → 시뮬 → 스스로 점검
```

그래서 `clue`·`optimize`·`optcode` 같은 최적화 절이 없고, 대신 `when.clue`(선택 단서)와
`detail.spec`(스펙 전수)이 있다. **알고리즘 캔버스를 그대로 흉내 내지 마라** — 없는 유도 과정을
억지로 만들면 글이 늘어지기만 한다.

## 항목별 작성 방법

### 제목 + 부제 (`title`)

`# {자료구조 이름} — {직관을 담은 부제}`

부제는 **이 구조의 "비결"을 한 구절로** 예고한다.

### 한눈에 보는 컨셉 (`concept`)

**3문장 이하.** 셋을 담는다 — **무엇을 하는 구조인지 · 비결 한 가지 · 대표 효과**(복잡도/실사용처).
복잡도는 코드 스팬(`O(...)`)으로 표기한다.

### 언제, 왜 쓰는가 (`when`) — 컨테이너

이 절 자체에는 본문을 길게 쓰지 않는다.

#### 이런 단서가 보이면 (`when.clue`)

**문제에서 어떤 근거·단서가 보일 때 이 자료구조를 떠올려야 하는지** 쓴다.
이 가이드의 실전 가치가 대부분 여기서 나온다 — 스펙은 검색하면 나오지만
"언제 이걸 꺼내야 하는가"는 안 나온다.

- 단서를 **구체적인 문제 상황**으로 적는다. "빠른 조회가 필요할 때"는 단서가 아니다.
- 비슷한 단서에서 **다른 구조를 고르게 되는 경우**도 함께 짚으면 좋다.

### 자료구조 자세히 들여다보기 (`detail`) — 컨테이너

#### 전체 스펙: 속성과 액션 (`detail.spec`)

**스펙을 빠짐없이 설명한다.** 이름만 나열하고 넘어가면 미흡이다.

- 각 **속성**이 무엇을 보장하는가(불변식).
- 각 **액션**이 무엇을 하고, 복잡도가 **왜** 그렇게 되는가.
- 상태가 변하는 액션은 **before/after 도식**으로 보인다.
- 핵심 개념 직후에 그림을 둔다 — 산문 3~4문단이 그림 없이 이어지면 신호 위반이다.

### 아이디어를 코드로 옮기기 (`impl`)

가이드가 정의한 인터페이스에 맞춘 TypeScript 구현 + 설명.
**코드는 본문 자체로 실행·검증한다** — 원본 `.ts` 에 종속되지 않는다.

- **모든 액션을 코드로 싣는 것이 기본**이다. 분량이 과도한 보조 연산은 흐름 서술로 대체할 수 있으나,
  **그 사실을 본문에 명시**한다("분량상 코드 대신 흐름만").
- **"가장 중요한 부분은 ~입니다"** 포인팅.
- **놓치기 쉬운 구현부**를 불릿으로 짚는다 — 순서가 생명인 두 줄, 경계 비교 연산자, 인덱스 변환.
- **기억법 한 줄** 권장.
- 절 끝에서 **복잡도 결론**을 정리한다(C2 충족 지점).

### 실행 시각화 (`sim`)

알고리즘 가이드의 같은 절과 **동일 규칙**이다.

- 기존 가이드의 `export const steps` 를 가져와 **본문 서사와 프레임 값이 1:1로 맞는지 대조**한다.
- `#guide-sim` import + 선언형 `steps` 만 쓴다. 문제별 JSX/Hook·외부 라이브러리 금지.
- 도입 문단에 **고정 입력 · 패널 읽는 법 · 실제 반환값**을 명시한다.
- 호출부 위에 `> 대화형 시뮬레이션은 MDX 런타임에서 표시됩니다.` 안내.

### 스스로 점검하기 (`selfcheck`)

문제 **2~3개**. 세 종류를 섞는다.

1. **손 계산/그리기 문제** — 직접 상태를 그려 보게 한다.
2. **오해를 건드리는 문제** — 왜 틀리는지 추적하게 한다.
3. **구현 순서 문제** — 두 줄의 순서를 바꾸면 무엇이 조용히 깨지는지.

**본문을 정독해야 풀리는 문제**여야 한다.

## 조건부 절 규칙

해당 사항이 없으면 **절 자체를 생략**한다. 문서 안에 "해당 없음" 메모를 남기지 않는다 —
독자용 문서에 집필 메타를 싣지 않는다(활성 voice 의 금지 목록과도 일치).
생략 사유는 **품질 게이트 보고에만** 기록한다.
