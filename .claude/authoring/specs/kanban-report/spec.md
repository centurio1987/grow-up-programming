# 칸반 계획 리포트 (`kanban-report`)

카드 하나를 착수하기 전에, **그 계획을 유저가 읽고 고를 수 있게** 만드는 글이다.
`manage-kanban` 스킬의 §4.7(착수 전 계획)과 §5.7(계획 리포트)이 이 명세를 부른다.

## 무엇을 위한 글인가

유저는 이 리포트 하나를 읽고 **두 수행안 중 하나를 고른다.** 그러니 이 글의 성패는
"잘 썼는가"가 아니라 **유저가 고를 수 있게 됐는가**로 갈린다. 두 안의 차이가 안 보이면
실패한 글이고, 한쪽만 자세히 쓰면 고르게 한 게 아니라 결론을 밀어붙인 것이다.

## 사실은 어디서 오는가

**`report-data` JSON 하나뿐이다.**

```
python3 <skill>/scripts/kanban.py report-data <project-root> --card KAN-013
```

여기 없는 수치를 쓰지 않는다(KR2). 특히 다음 셋은 어디에도 측정된 적이 없으므로
**절대 지어내지 않는다** — 소요 시간, 필요 인원, 비용. "배치 하나는 한 세션 예산의 절반"은
work 개수 기준이지 시간 기준이 아니다.

## 절 여섯

| 절 | 답해야 할 질문 |
|---|---|
| 이 카드가 무엇을 끝내려는가 | 이 일이 끝나면 무엇이 달라지는가. 카드 제목을 되풀이하지 않는다 |
| 왜 이 접근인가 | 문서 `## 전략` 절을 독자용으로 편다. 버린 대안이 있으면 왜 버렸는지까지 |
| 무엇을 어떤 순서로 | work 목록의 **의미**를 말한다. 표는 렌더러가 그리므로 다시 그리지 않는다 |
| 두 가지 수행안 | 단일 에이전트 · 오케스트레이션. **같은 분량·같은 항목**으로 나란히 |
| 막힐 만한 지점 | 배치가 예산을 넘길 지점, 되돌리기 어려운 지점, 루트 독립성 |
| 무엇이 되면 끝인가 | 문서 `## 검증` 절. 실행 가능한 형태로 |

## 렌더러와의 분업

이 글은 **산문만** 쓴다. 차트 셋(WBS 간트 · 배치 2안 비교 · 루트 독립성 맵)과 표는
`report.py`가 같은 JSON에서 직접 그린다. 본문에서 표를 다시 그리면 두 벌이 갈라지고,
숫자가 어긋나는 순간 둘 다 못 믿게 된다.

## 독립성이 깨졌을 때

`report-data`의 `independence`가 비어 있지 않고 `waived: false`가 하나라도 있으면,
**첫 절에서 그 사실을 말한다**(KR5). 계획서 뒤쪽에 묻으면 유저는 착수한 뒤에 발견한다.
그때는 이미 브랜치가 갈라져 있다.
