이 방식이 왜 막히는지 작은 예시로 체감해 봅시다. $N = 5$면 구간이 $15$개뿐이라 멀쩡하지만, 제약의 상한 $N = 100{,}000$을 넣으면 사정이 달라져요.

N = 5   → 구간 수 ≈ N²/2 =    12~15개           → 즉시 끝남
N = 100,000 → 구간 수 ≈ N²/2 = 5 × 10^9개        → 1초 제한에서 시간 초과

(b) 절차 층위:
합의 Kadane's algorithm은 "위치 $i$에서 끝나는 구간의 최대 합"만 기억하면 충분했습니다. 곱에서도 똑같이 해 볼까요?

```ts
function maximumProductSubarrayBrokenSingleVar(A: number[]): number {
  let curMax = A[0]!;
  let best = A[0]!;
  for (let i = 1; i < A.length; i++) {
    curMax = Math.max(A[i]!, curMax * A[i]!); // 합 Kadane을 곱에 그대로 옮긴 것
    best = Math.max(best, curMax);
  }
  return best;
}
```

작은 예로 바로 검증해 봅시다. `A = [3, -2, -5]`를 넣으면:

```text
i=0: curMax=3,  best=3
i=1: A[1]=-2 → candidates(-2, 3*-2=-6)   → curMax=-2,  best=3
i=2: A[2]=-5 → candidates(-5, -2*-5=10) → curMax=10,  best=10

단일 변수 결과: 10
```

그런데 진짜 정답은 전체 구간 `[3,-2,-5]`의 곱 $3 \times (-2) \times (-5) = 30$이에요. 단일 변수 버전은 `10`을 반환해 **정답 `30`을 놓칩니다.**"
