# ORD-006 병렬 실행 WBS (KAN-027 안쪽 · KAN-032 독립)

> **이 문서는 「누가 무엇을 잡았는가」를 적지 않는다.** 상태를 문서에 적으면 병렬 세션이 그
> 문서를 함께 고치게 되고, 병렬화가 막으려던 충돌이 상태 관리에서 그대로 돌아온다.
> 진실은 파일 시스템이다 — 구조의 `_reference/` 가 있으면 그 구조는 끝났다.
>
> ```bash
> bun run tools/ord006-wbs.ts        # 트랙별 상태 + 트랙당 claim 후보 하나
> bun run tools/ord006-wbs.ts --all  # 전 유닛 + 유닛별 주의사항
> ```
>
> 배치 진입 절차는 `docs/ORD-006-runbook.md`, 확정 규약은 `docs/ORD-006-conventions.md`.
> 이 문서는 **병렬로 돌리는 방법만** 적는다. 집필 규칙을 여기에 다시 쓰지 않는다.

## 1. 단위

**유닛 하나 = 계약 하나 = 배치 하나 = 세션 하나 = 커밋 경계.** 배치 규약(런북)이 그대로
살아 있고, 이 문서가 더하는 것은 **배치를 동시에 몇 개 돌릴 수 있는가**뿐이다.

B군 42종 중 재집필이 남은 **37종을 32 유닛**으로 접었다. 접은 근거는 B17·B18·B19 판정
셋이고, 계약이 접힌 자리에서는 **정본 하나 + 성격 전환 여럿**이 한 유닛이 된다.

| 상태 | 뜻 | claim 가능 |
|---|---|---|
| `open` | 정본에 `_reference/` 가 없다 | 그렇다 |
| `partial` | 정본은 섰고 성격 전환이 남았다 | 그렇다 — **`open` 보다 먼저 잡는다** |
| `done` | 정본 + 전환 전부 `_reference/` 보유 | — |

`partial` 을 먼저 잡는 이유는 그 계약의 스위트가 정본 하나로만 검증된 채 남기 때문이다.
B22 가 정본 셋을 나란히 재서 「계약이 재균형 기법을 처방하지 않는다」를 실증했고(불변 사실
76), 전환이 미완이면 그 실증이 없다.

## 2. 트랙

트랙은 **동시에 돌려도 서로의 파일을 안 건드리는 묶음**이다. 같은 계약 덩어리는 같은
트랙에 둔다 — 정본과 전환 사이에 순서가 있기 때문이다.

| 트랙 | 이름 | 유닛 | 종 | 런북 불변 사실 번호 대역 |
|---|---|---|---|---|
| T1 | 탐색 트리 | 7 | 7 | 100–119 |
| T2 | 우선순위 큐 | 5 | 9 | 120–139 |
| T3 | 사전·집합·분리집합 | 5 | 6 | 140–159 |
| T4 | 구간 질의·공간 | 7 | 7 | 160–179 |
| T5 | 선형·확률·기타 | 8 | 8 | 180–199 |

**번호 대역이 이 표에서 가장 중요한 열이다.** 런북의 불변 사실 번호는 다른 문서가
「불변 사실 78」처럼 번호로 인용하므로, 두 세션이 같은 번호를 쓰면 인용이 조용히 어긋난다.
번호를 커밋 순서로 다시 매기는 것은 이미 나간 인용을 깨뜨리므로 하지 않는다. 대역을 미리
갈라 두면 충돌 자체가 없다. 번호가 82–99 를 건너뛰는 것은 의도한 것이다 — 그 대역은
트랙 도입 전 단일 세션 몫으로 비워 둔다.

### 동시 실행 수

**권장은 2~3 트랙이다.** 상한을 정하는 것은 의존성이 아니라 §4 의 공유 파일이고, 그중
`KANBAN.md` 갱신은 직렬화된다(§4 마지막 줄).

### 트랙을 넘는 의존 하나

**`T5-04 skipList` 는 `T1-02 treap` 완료를 확인하고 착수한다.** 둘 다 「정렬 집합 ·
expected O(log n)」이라 계약이 같을 수 있고, 그렇다면 `T5-04` 는 재집필이 아니라 성격
전환이 된다. 이 외에 트랙을 넘는 선행은 없다.

## 3. 배치 절차 (세션이 그대로 따른다)

1. `git status` — 워킹트리가 깨끗한지 확인한다(배치 규약).
2. `bun run tools/ord006-wbs.ts` — 트랙별 claim 후보를 받는다. 다른 세션이 도는 중이면
   그 트랙을 피해 다른 트랙의 후보를 잡는다.
3. `bun run tools/ord006-wbs.ts --all` 로 잡은 유닛의 `!` 주의사항을 읽는다. 유닛마다
   걸리는 것이 다르다(불변 구조 넷 · Bound 확장 · 판정 미완 · 한정자 시나리오).
4. 런북 불변 사실 + `docs/ORD-006-conventions.md` §규약1 을 읽고 집필한다.
   **성격 전환이면 §규약1 「성격 전환은 이렇게 적는다」가 실행 규격이다** — 스위트를
   복사하지 않고 `{...정본Contract, name}` 다섯 줄로 같은 객체를 쓴다.
5. `bun run tools/ci.ts all` 통과.
6. 종료 산출 넷을 남긴다 — §5.

## 4. 공유 파일과 충돌 회피

구조 디렉터리 안(`<name>.ts` · `.contract.ts` · `.test.ts` · `_reference/` · 가이드)은
유닛마다 갈리므로 충돌이 없다. 밖으로 나가는 것이 여섯이고, 그중 하나는 **실제로 충돌이
났다** — B20 이 `tools/emit-vectors.ts` 등록을 같은 시각 B21 세션의 편집과 섞여 빼야 했고,
B22 가 다음 배치에서 따로 닫았다.

| 파일 | 무엇이 부딪히는가 | 규약 |
|---|---|---|
| `docs/ORD-006-runbook.md` 불변 사실 | 같은 번호를 둘이 씀 | §2 의 트랙별 대역만 쓴다 |
| `docs/ORD-006-runbook.md` 배치 지도·진입 카드 | 같은 표에 행 추가 | 자기 트랙 행만 고친다. 「다음」 표시를 쓰지 않는다 — 다음은 도구가 정한다 |
| `docs/ORD-006-conventions.md` | 같은 절을 고침 | **절을 새로 추가만 한다.** 기존 절을 고쳐야 하면 고치지 말고 칸반 메모에 그 사실을 적어 다음 배치로 넘긴다 |
| `tools/emit-vectors.ts` | vector 등록 목록 | 등록 위치를 **구조 경로 알파벳 순**으로 고정한다. 순서가 고정이면 충돌이 나도 양쪽을 살리는 해결이 유일하다 |
| `tools/ord006-inventory.ts` `VERIFICATION_GRADES` | 등급 확정 기입 | 같은 규칙 — 키가 다르므로 알파벳 순 유지 |
| `src/data-structures/_contract/_fixtures/` | fixture 가 계약을 넘어 공유됨 | **읽기만 한다.** 고쳐야 하면 새 파일을 만든다 — `splayingSearchTree` 가 두 계약에서 쓰이므로 고치면 다른 계약의 자기시험 기대값이 말없이 바뀐다 |

앞의 다섯은 병합 충돌로 드러나므로 조용히 새지 않는다. 여섯째만 다르다 — 그래서 규약이
「읽기만」이다.

**`KANBAN.md` 갱신은 직렬화한다.** `manage-kanban` 스크립트가 `KANBAN.state.json` 을
함께 쓰므로 두 세션이 동시에 돌리면 스냅샷이 어긋난다. 배치 종료 시 `git pull --rebase`
직후 단독으로 돌린다.

## 5. 배치 종료 산출 (넷)

런북의 셋에 하나가 붙는다.

1. `KANBAN.md` KAN-027 메모에 결과 — **유닛 id 로 시작한다**(`T2-01 완료 —` 꼴).
   다음 세션이 메모를 역순으로 훑어 어디까지 갔는지 본다. `manage-kanban` 경유.
2. 규약이 바뀌었으면 `docs/ORD-006-conventions.md` — 절 추가만.
3. 런북에 그 배치 결과 — 자기 트랙 대역의 불변 사실 번호로.
4. **유닛이 접히거나 갈리면 `tools/ord006-wbs.ts` 의 `UNITS` 를 고친다.** 판정 결과
   두 유닛이 한 계약이면 하나를 다른 쪽 `transitions` 로 옮긴다. 이 파일이 WBS 의 정본이고
   이 문서의 표는 사람이 읽는 사본이다.

## 6. 레인 4 — KAN-032 (독립)

`KAN-032`(분석 보고서 재검토 섹션 34개를 회차별 파일로 분할)는 **ORD-006 파일을 하나도
건드리지 않는다.** §4 의 여섯 중 어느 것과도 겹치지 않으므로 트랙 수 제한 밖이고, B군
배치와 언제든 동시에 돈다.

- 대상 우선순위는 (줄 수 × 재검토 수) 순 셋 — `dijkstra`(845/8) · `insertionSort`(834/5) ·
  `kthSmallest`(641/6). 나머지 여섯은 400줄 미만이라 분할 이득이 작다.
- 분할 시 루트 이력표의 「위치」 열을 원 제목 문자열에서 `r<NN>` 파일 상대 링크로 바꾼다.
- 겹치는 유일한 파일은 `KANBAN.md` 다 — §4 마지막 줄의 직렬화 규약을 그대로 따른다.

## 7. 이 WBS 밖

`KAN-026`(A군 16종) · `KAN-028`(C군 1종)은 트랙에 넣지 않았다. 임계 경로가 B군이라
동시에 돌려도 전체 완료 시점이 안 줄고, 두 카드 모두 `docs/ORD-006-conventions.md` 를
건드린다. B군이 끝나 트랙이 비면 그때 같은 형식으로 유닛을 뽑는다.

`KAN-031`(카테고리 재편)은 **69종 계약이 전부 확정된 뒤에만** 돈다(B12 인계). 경로가
바뀌면 이 문서의 유닛 경로와 `UNITS` 도 함께 고쳐야 하고, 도구의 경로 가드가 그 누락을
`exit 1` 로 잡는다.
