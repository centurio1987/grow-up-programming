# 0/1 배낭 — 조합을 세지 않고, 용량별 최선을 한 줄씩 적어 내려간다

## 시작하기 전에 — 이미 알고 있어야 하는 것

| 알아야 하는 것 | 왜 |
| --- | --- |
| 부분집합의 개수가 `2^n` 이라는 셈 | 이 글이 무너뜨릴 출발점이다 |
| `dp[i][c]` 같은 2차원 첨자 읽기 | 표의 행·열을 좌표로 가리킨다 |
| 두 값 중 큰 쪽 고르기 | 한 칸을 정하는 데 이것만 쓴다 |

몰라도 되는 것은 재귀·메모이제이션·그래프다. 이 글은 표를 왼쪽 위에서 오른쪽 아래로
채우는 반복문만 쓴다.

## 전체 컨셉

물건마다 무게와 가치가 있고 배낭에는 무게 한도가 있다. 같은 물건은 하나뿐이라 **담거나
두고 가거나 둘 중 하나**이고, 무게 합이 한도를 넘지 않게 하면서 가치 합을 가장 크게
만드는 것이 목표다.

```text
물건 4개                     배낭 용량 7
  ① 무게1 가치1
  ② 무게3 가치4              담을 조합 = 2^4 = 16 가지
  ③ 무게4 가치5              물건이 100개면 2^100 가지
  ④ 무게5 가치7
```

곧바로 떠오르는 방법은 모든 조합을 만들어 보는 것이다. 넷이면 16가지라 손으로도 세지만,
백이면 `2^100` 이라 사람이 셀 수 있는 크기가 아니다.

핵심 관찰은 이것이다. **조합을 통째로 볼 필요가 없다.** 물건을 하나씩 늘려 가면서
"앞의 `i` 개만 놓고 골랐을 때 용량 `c` 로 얻는 최대 가치"를 표에 적어 두면, 다음 물건을
볼 때 그 표만 보면 된다.

```text
표 한 칸 = "앞의 i 개로 용량 c 를 채운 최선"

        c=0  1  2  3  4  5  6  7
  i=0     0  0  0  0  0  0  0  0     ← 물건이 없으면 전부 0
  i=1     0  1  1  1  1  1  1  1     ← 무게1·가치1 을 본 뒤
  i=2     0  1  1  4  5  5  5  5     ← 무게3·가치4 를 본 뒤
  i=3     0  1  1  4  5  6  6  9     ← 무게4·가치5 를 본 뒤
  i=4     0  1  1  4  5  7  8  9     ← 무게5·가치7 을 본 뒤
                                ↑ 답
```

새 물건 하나에 대한 선택지는 언제나 둘뿐이다 — 두고 가거나, 담거나. 그래서 한 칸을 정하는
규칙도 둘로 갈린다.

| 상황 | 그 칸에 적을 값 |
| --- | --- |
| 남은 용량 `c` 가 무게 `w` 보다 작다 | **바로 윗 칸**을 그대로 물려받는다 |
| 담을 수 있다 | 두고 갔을 때(윗 칸)와 담았을 때(**무게만큼 왼쪽으로 간 윗 칸** + 가치) 중 큰 쪽 |

"무게만큼 왼쪽으로 간 윗 칸"이 이 알고리즘의 전부다. 이 물건을 담으면 용량이 `w` 만큼
줄어드니, 줄어든 용량을 **앞의 물건들만으로** 채운 최선을 이어받는 것이다.

```text
dp[3][7] 을 정하는 장면 (무게4·가치5 를 볼 차례)

  두고 간다 →  dp[2][7] = 5
  담는다    →  dp[2][7-4] + 5 = dp[2][3] + 5 = 4 + 5 = 9
                     ↑ 윗 줄에서 가져온다. 같은 줄에서 가져오면
                       이 물건을 두 번 담게 된다.
  큰 쪽 9 를 적는다
```

표는 `(물건 수 + 1) × (용량 + 1)` 칸이고 한 칸에 비교 한 번이면 되므로, `2^n` 이 `n × W` 로
내려온다. 물건 100개·용량 10,000 이면 1,010,101 칸이라 1초 안에 끝난다.

이 절차는 입력이 무엇이든 표 전체를 한 번씩 채운다. 운이 좋아 빨라지는 일도, 나빠서
느려지는 일도 없다.

## 아이디어 상세

### 표 채우기 — 생각이 닿는 경로

**① 문제를 고정한다.**

```ts
export function knapsack01(
  weights: number[],
  values: number[],
  W: number,
): number;
```

`weights[i]` 와 `values[i]` 가 같은 물건의 무게와 가치이고, 반환은 **최대 가치 합 하나**다.
어떤 물건을 골랐는지는 묻지 않는다.

| 제약 | 값 |
| --- | --- |
| 물건 수 `n` | `1 ≤ n ≤ 100` |
| 무게·가치 | 각각 `1 ≤ · ≤ 10^4` |
| 용량 `W` | `1 ≤ W ≤ 10^4` |
| 시간·메모리 | 1초 · 256MB |
| 빈 입력 · `W = 0` | `0` 을 돌려준다 |

**② 가장 단순한 방법을 세우고 수치로 무너뜨린다.**

각 물건을 담을지 말지 정하는 것이므로, 모든 결정 조합을 만들어 무게 합이 `W` 이하인 것 중
가치 합이 가장 큰 것을 고르면 된다.

```text
물건 4개 → 조합 2^4 = 16 가지
  {} {1} {2} {3} {4} {1,2} {1,3} {1,4} {2,3} {2,4} {3,4}
  {1,2,3} {1,2,4} {1,3,4} {2,3,4} {1,2,3,4}

물건 100개 → 2^100 ≈ 1.27 × 10^30 가지
  1초에 10^9 가지를 본다 해도
  1.27 × 10^21 초 ≈ 4 × 10^13 년   ← 우주 나이보다 길다
```

**조합을 하나씩 보는 길은 여기서 끊긴다.** 넷이면 되는 방법이 백에서 안 되는 이유는
가짓수가 물건 하나마다 두 배가 되기 때문이다.

**③ 거기서 아이디어까지 간다.** 16가지를 다시 보면 `{1,2}` 와 `{1,2,3}` 과 `{1,2,4}` 가
앞부분 `{1,2}` 를 공유하는데, 그 무게 합과 가치 합을 세 번 다시 세고 있다.

```text
{1,2}       무게 1+3=4   가치 1+4=5
{1,2,3}     무게 4+4=8   가치 5+5=10     ← 앞의 4 와 5 를 다시 셌다
{1,2,4}     무게 4+5=9   가치 5+7=12     ← 또 다시 셌다
```

같은 것을 다시 세지 않으려면 **무엇을 기억할지**를 정해야 한다. 조합 자체를 기억하면
`2^n` 개라 아무것도 줄지 않는다.

```text
기억할 것 =  "앞의 i 개만 놓고 골랐을 때,
              무게 합이 c 이하라면 가치 합의 최대는 얼마인가"

              ↑ 조합이 아니라 (i, c) 두 수로만 적힌다 → 칸 수가 n × W
```

조합이 달라도 `(i, c)` 가 같으면 앞으로 할 수 있는 일이 완전히 같다. 뒤에 오는 물건들은
"앞에서 무엇을 골랐는가"를 묻지 않고 **남은 용량만** 묻기 때문이다.

```text
{1,2} 와 {3} 은 다른 조합이지만
  {1,2} → 무게 4 씀, 남은 용량 3, 가치 5
  {3}   → 무게 4 씀, 남은 용량 3, 가치 5
앞으로 할 수 있는 일이 같다 → (i, c) 한 칸에 값 하나만 남긴다
```

작은 입력으로 굴려 본다. 무게 `[1, 3, 4, 5]`, 가치 `[1, 4, 5, 7]`, 용량 `7` 이다.
`i = 1` 줄은 무게1·가치1 하나만 있는 세계라, 용량 0이면 못 담아 `0`, 1 이상이면 담아 `1` 이다.

```text
i=1     0  1  1  1  1  1  1  1
```

`i = 2` 줄(무게3·가치4 추가)로 가면, 용량이 3 이상인 칸부터 이 물건을 얹을 자리가 생긴다.
얹을 때 이어받는 값이 **윗 줄의 왼쪽 칸**이라는 것만 보면 된다.

```text
i=1     0  1  1  1  1  1  1  1
i=2     0  1  1  4  5  5  5  5
              ↑     ↑
              │     └ 용량 4 : 윗 줄 왼쪽 dp[1][1]=1 을 이어받아 1+4 = 5
              └ 용량 3 : 윗 줄 왼쪽 dp[1][0]=0 을 이어받아 0+4 = 4
```

줄을 하나 더 내려가면 `dp[3][7]` 이 `dp[2][3] + 5 = 9` 로 정해진다. 표를 끝까지 채우고
**오른쪽 아래 칸**을 읽으면 그것이 답이고, 각 칸이 어느 갈래로 정해졌는지는 뒤에서
한 입력으로 끝까지 따라가며 본다.

### 수식 정의와 유도

상태를 이렇게 정의한다.

$$dp[i][c] = \text{앞의 } i \text{ 개만 놓고 골랐을 때, 무게 합이 } c \text{ 이하인 최대 가치 합}$$

```text
경계  dp[0][c] = 0        물건이 없으면 어떤 용량에서도 가치가 0
답    dp[n][W]            표의 오른쪽 아래 칸
```

| 기호 | 뜻 |
| --- | --- |
| $i$ | 지금까지 본 물건 수 (표의 행) |
| $c$ | 남은 용량 (표의 열) |
| $w_i$ · $v_i$ | $i$ 번째 물건의 무게와 가치 |

$$
dp[i][c] =
\begin{cases}
dp[i-1][c] & (c < w_i) \\
\max\bigl(dp[i-1][c],\; dp[i-1][c-w_i] + v_i\bigr) & (c \ge w_i)
\end{cases}
$$

정의마다 계산을 하나 붙인다. 위 입력에서 $i=3$($w_3 = 4$, $v_3 = 5$), $c = 7$ 을 넣으면
이렇게 풀린다.

```text
dp[3][7] = max( dp[2][7],  dp[2][7-4] + 5 )
         = max( 5,         4 + 5 )
         = 9
```

답은 $dp[n][W]$ 이고, 표의 칸 수가 $(n+1)(W+1)$ 이며 칸마다 상수 시간이므로 총 비용이
$\Theta(nW)$ 라는 것이 이 정의에서 바로 나온다.

### 왜 항상 옳은가

$i$ 에 대한 귀납으로 보인다. **기저**는 $dp[0][c] = 0$ 이다 — 물건이 하나도 없으면 고를
것이 없고, $c$ 가 무엇이든 가치 합은 0이다.

**귀납 가정**은 $dp[i-1][\cdot]$ 의 모든 칸이 "앞의 $i-1$ 개로 그 용량에서 얻는 최대
가치"라는 것이다. 이제 앞의 $i$ 개로 용량 $c$ 를 쓰는 최적해 하나를 잡는다.

```text
그 해는 i 번째 물건을
  ├ 안 담았다 → 앞의 i-1 개만으로 용량 c 를 쓴 해
  │             → 가치 ≤ dp[i-1][c]
  └ 담았다    → w_i 를 쓰고 남은 c-w_i 를 앞의 i-1 개로 채운 해
                → 가치 ≤ dp[i-1][c-w_i] + v_i     (c ≥ w_i 일 때만 가능)

셋째 경우는 없다 — 0/1 배낭이라 "반만 담기" 가 없다.
```

최적해는 두 값 중 하나 이하이므로 $dp[i][c] \le \max(\cdot,\cdot)$ 이고, 반대로 두 값은
각각 실제로 만들 수 있는 해의 가치이므로 $dp[i][c] \ge \max(\cdot,\cdot)$ 다. 따라서 같다.

**윗 줄에서 가져오는 것이 이 증명의 핵심이다.** $dp[i-1][c-w_i]$ 는 "$i$ 번째 물건을 아직
안 본 세계"의 값이라 거기에 $v_i$ 를 더해도 같은 물건이 두 번 들어갈 수 없다.

| 엣지 케이스 | 표에서 일어나는 일 | 반환 |
| --- | --- | --- |
| `weights=[]`, `values=[]`, `W=10` | 0번째 줄만 있고 루프가 안 돈다 | `0` |
| `W = 0` | 열이 `c=0` 하나뿐, 모든 물건이 `c < w` | `0` |
| 모두 `W` 보다 무겁다 (`[10,20,30]`, `W=5`) | 모든 칸이 윗 줄 복사 | `0` |
| 하나가 정확히 `W` (`[5]`, `[42]`, `W=5`) | `c=5` 에서 `max(0, 0+42)` | `42` |

넷 다 특별 분기 없이 같은 전이식으로 처리된다. 빈 배열도 `n = 0` 이라 $dp[0][W] = 0$ 이
그대로 답이 된다.

### 흔한 오해와 그것이 거짓인 이유

**오해: "가치/무게 비율이 높은 것부터 담으면 된다."** 분수 배낭(물건을 쪼갤 수 있는 문제)
에서는 이 그리디가 실제로 최적이라, 0/1 에서도 될 것 같다.

그 오해대로 전개해 본다. 무게 `[3, 4]`, 가치 `[4, 5]`, 용량 `4` 다.

```text
비율   물건1 = 4/3 ≈ 1.33      물건2 = 5/4 = 1.25
       └ 높은 쪽을 먼저 담는다

담기   물건1(무게3) 담음 → 남은 용량 1
       물건2(무게4)는 1 에 안 들어감 → 버린다
       그리디 답 = 4        ✗

정답   물건2 하나만 담으면 무게 4 로 딱 맞고 가치 5
       정답     = 5        ✓
```

그리디는 비율이 높은 쪽을 담느라 **남은 용량 1을 버렸다.** 쪼갤 수 없으니 남은 용량은
그냥 낭비다.

**쪼갤 수 없다는 조건 하나가 그리디를 무너뜨린다.** 지금의 이득이 나중의 손해로 바뀌는지
그 자리에서는 알 수 없기 때문이다.

```text
분수 배낭이라면        물건1 담고, 남은 1 에 물건2 를 1/4 만큼 담는다
                       가치 4 + 5×(1/4) = 5.25   ← 그리디가 최적

0/1 배낭이라면        남은 1 은 그냥 버려진다
                       가치 4                    ← 그리디가 최적이 아니다
```

물건을 쪼갤 수 있는지 없는지가 같은 절차를 최적에서 오답으로 바꾼다.

### 이해 점검

위 표에서 `dp[2][4] = 5` 였다. 이 값은 어떤 선택을 뜻하는가?

무게 합 1+3 = 4  ← 용량 4 에 딱 맞다
가치 합 1+4 = 5
전이식  dp[1][4-3] + 4 = dp[1][1] + 4 = 1 + 4 = 5
```

```

## 이 알고리즘이 최적인 자리

### 최적인 문제의 모양

| 조건 | 왜 필요한가 |
| --- | --- |
| 선택이 **이진**이다 | 담거나 만다. 여러 개 담을 수 있으면 전이식이 달라진다 |
| 용량이 **정수이고 작다** | 표의 열이 용량이다. 실수이거나 `10^9` 이면 표를 못 만든다 |
| 제약이 **한 축**이다 | 부피까지 함께 막으면 표가 3차원이 된다 |
| 답이 **값 하나**다 | 최대 가치만 물으면 표 하나로 끝난다 |

`n × W` 가 대략 `10^7` 아래면 그대로 돈다. 이 문제의 제약(`100 × 10^4 = 10^6`)은 그 안에
넉넉히 들어간다.

### 문제에서 이것을 떠올리게 하는 단서

```text
지문에 이런 말이 보이면
  "각 물건은 한 번만 사용할 수 있다"  "가져가거나 두고 간다"
  "무게 한도를 넘지 않게"  "예산 안에서"  "시간 안에서"
  "최대 가치 · 최대 만족도 · 최대 이익"

제약에 이런 모양이 보이면
  용량 상한이 명시돼 있고 그 값이 10^4 안팎    ← 표를 만들 수 있다는 신호
  물건 수가 100 안팎                          ← 2^n 은 불가능, n×W 는 가능
```

반대로 "물건을 쪼갤 수 있다"가 보이면 그리디이고, "같은 물건을 여러 개"가 보이면
무한 배낭이라 전이식의 첨자가 달라진다.

### 실제로 쓰이는 곳

**Google OR-Tools** 의 배낭 솔버가 이 절차를 한 옵션으로 그대로 싣는다. `SolverType`
열거에 `KNAPSACK_DYNAMIC_PROGRAMMING_SOLVER` 가 있고, 소스 주석이 이렇게 적는다.

```text
"Limited to one dimension, this solver is based on a dynamic programming
 algorithm. The time and space complexity is O(capacity * number_of_items)."

  — ortools/algorithms/knapsack_solver.h (조회 2026-08-20)
```

이 글이 유도한 $\Theta(nW)$ 와 같은 식이고, "Limited to one dimension" 이 위에서 적은
「제약이 한 축」 조건을 그대로 말한다.

| 같은 열거의 다른 솔버 | 언제 쓰는가 |
| --- | --- |
| `KNAPSACK_DYNAMIC_PROGRAMMING_SOLVER` | 제약이 한 축. 이 글의 절차 |
| `KNAPSACK_MULTIDIMENSION_BRANCH_AND_BOUND_SOLVER` | 제약이 여러 축. 공식 문서 예제의 기본값 |

제약이 여러 축이면 표를 만들 수 없어서 갈라지는 것이고, 이 경계가 곧 「최적인 문제의 모양」
에서 적은 조건이다.

- 소스: [`ortools/algorithms/knapsack_solver.h`](https://raw.githubusercontent.com/google/or-tools/stable/ortools/algorithms/knapsack_solver.h) (조회 2026-08-20)
- 문서: [Google OR-Tools — Knapsack](https://developers.google.com/optimization/pack/knapsack) (조회 2026-08-20)

### 경쟁 설계와의 대조

같은 답을 내는 **완전히 다른 표**가 있다 — **가치 축 DP** 다. 축을 뒤집어
`dp[가치] = 그 가치를 만드는 데 필요한 최소 무게` 를 채우고, 마지막에 무게가 `W` 이하인
가장 큰 가치를 읽는다.

$$dp[i][g] = \min\bigl(dp[i-1][g],\; dp[i-1][g - v_i] + w_i\bigr)$$

```text
무게 축   표 크기 (n+1)(W+1)        열 = 용량
가치 축   표 크기 (n+1)(Σv+1)       열 = 가치 합
          ↑ 둘 다 옳고 둘 다 표 하나를 채운다. 다른 것은 표의 크기뿐이다.
```

같은 입력(`n = 50`, `W = 1000`, 무게·가치는 고정 생성식)에 둘을 걸고 **채운 표 칸 수**를 셌다.
전개에 쓰는 `n = 4, W = 7` 이 아니라 이쪽을 쓴다 — 그 크기에서는 **40 대 108**, 방향은
같아도 2.7배라 이 문제의 제약에서 실제로 벌어지는 차이를 나타내지 못한다.

| 설계 | 표 칸 |
| --- | --- |
| **무게 축 DP (이 가이드)** | **51,051** |
| 가치 축 DP | 617,552 |

**무게 축이 12.1배 적다.** 이 문제의 제약에서 용량은 `10^4` 인데 가치 합은 최대
`100 × 10^4 = 10^6` 이라, 가치 축 표가 그만큼 길어지기 때문이다.

```text
어느 축이 짧은가로 고른다

  용량 10^4, 가치 합 10^6   →  무게 축 (열 10001 개)      ← 이 문제
  용량 10^9, 가치 합 100    →  가치 축 (열 101 개)
```

**뒤집히는 자리가 분명하다.** 가치가 전부 1이고 용량이 `10^9` 이면 무게 축은 표를 만들
수조차 없지만 가치 축은 열이 101개뿐이다 — 고르는 기준은 알고리즘의 우열이 아니라
**어느 축이 짧은가** 하나다.

## 코드로 옮기기

### 수도 코드로 본 전체

```text
표 dp 를 (n+1) × (W+1) 로 만들고 전부 0 으로 둔다

i 를 1 부터 n 까지:
    w ← i 번째 물건의 무게
    v ← i 번째 물건의 가치
    c 를 0 부터 W 까지:
        만약 c < w 이면:
            dp[i][c] ← dp[i-1][c]                     ① 못 담는다
        아니면:
            두고감 ← dp[i-1][c]
            담음   ← dp[i-1][c - w] + v
            dp[i][c] ← 두고감 ≥ 담음 ? 두고감 : 담음   ② 두고 간다 · ③ 담는다

dp[n][W] 를 돌려준다
```

### 0번째 줄을 0으로 깐다

전이식의 기저가 $dp[0][c] = 0$ 이다. 이 줄이 없으면 `i = 1` 을 채울 때 물려받을 윗 줄이 없다.

```ts
const dp = Array.from({ length: n + 1 }, () =>
  Array.from({ length: W + 1 }, () => 0),
);
```

| 왜 `+1` 인가 | |
| --- | --- |
| 줄이 `n + 1` 개 | 0번째 줄("물건이 없다")을 실제 칸으로 둔다 |
| 열이 `W + 1` 개 | 용량 0 칸("아무것도 못 담는다")을 실제 칸으로 둔다 |

둘 다 "아무것도 없는 상태"를 표 안에 넣는 것이라, 코드에 빈 입력 분기가 따로 안 생긴다.

### 한 물건을 놓고 한 줄을 채운다

바깥 루프가 물건, 안쪽 루프가 용량이다.

```ts
for (let i = 1; i <= n; i++) {
  const w = weights[i - 1] as number;
  const v = values[i - 1] as number;
  const prev = dp[i - 1] as number[]; // 윗 줄 — 이 물건을 아직 안 본 세계
  const cur = dp[i] as number[]; // 이번 줄 — 이 물건까지 본 세계

  for (let c = 0; c <= W; c++) {
    // 여기서 한 칸이 정해진다
  }
}
```

두 줄에 이름을 붙여 두는 것은 편의가 아니다. **`prev` 에서만 읽는다**는 것이 이 알고리즘의
규칙 전부인데, 첨자로 쓰면 그 규칙이 `i - 1` 이라는 숫자 뒤로 숨는다.

순서를 바꾸면 안 된다 — 한 줄은 통째로 윗 줄에 기대고 있으므로, 윗 줄이 다 차기 전에
아랫 줄을 건드리면 아직 안 채워진 칸을 읽는다.

```text
i 바깥 · c 안쪽 (옳다)        c 바깥 · i 안쪽 (틀린다)
  i=1 줄을 왼→오 로 완성        c=0 열을 위→아래 로 완성
  i=2 줄을 왼→오 로 완성        c=1 열을 채울 때 dp[i-1][c-w] 가
  ...                            아직 안 채워진 열을 가리킬 수 있다
```

`weights[i - 1]` 인 것은 표의 `i` 가 1부터인데 배열은 0부터이기 때문이다. 표의 `i` 번째
줄은 "앞의 `i` 개를 본 뒤"라서, 방금 추가된 물건이 배열의 `i - 1` 번이다.

### 칸 하나를 세 갈래로 정한다

갈림길을 셋으로 벌려 둔다. `Math.max` 한 줄로 접으면 짧아지지만 **어느 쪽이 이겼는지**가
코드에 남지 않아, 표를 따라갈 때 확인할 것이 사라진다.

```ts
if (c < w) {
  // ① 못 담는다 — 남은 용량이 이 물건의 무게보다 작다
  cur[c] = prev[c] as number;
} else {
  const skip = prev[c] as number;              // 두고 간다
  const take = (prev[c - w] as number) + v;    // 담는다
  // ② 두고 가는 쪽이 크거나 같다 · ③ 담는 쪽이 크다
  cur[c] = skip >= take ? skip : take;
}
```

`take` 가 **`prev`** 에서 오는 것이 이 알고리즘의 급소다. 같은 물건을 두 번 담지 않게
막는 자리가 코드 전체에서 여기 하나뿐이다.

```text
prev[c-w] + v      이 물건을 아직 안 본 세계에서 이어받는다  ✓
cur [c-w] + v      이 물건을 이미 담았을 수도 있는 값에 또 더한다  ✗
```

동점(`skip === take`)에서 두고 가는 쪽을 고르는 것은 값에 영향이 없다. 다만 **어떤 물건을
골랐는지**를 나중에 되짚을 때 답이 갈리므로 한쪽으로 고정해 두는 편이 낫다.

### 완성 코드

```ts
export function knapsack01(
  weights: number[],
  values: number[],
  W: number,
): number {
  const n = values.length;

  // dp[i][c] = 앞의 i 개만 놓고 골랐을 때, 용량 c 로 얻는 최대 가치.
  // 0 번째 줄은 "물건이 하나도 없다" 라 전부 0 이다.
  const dp = Array.from({ length: n + 1 }, () =>
    Array.from({ length: W + 1 }, () => 0),
  );

  for (let i = 1; i <= n; i++) {
    const w = weights[i - 1] as number;
    const v = values[i - 1] as number;
    const prev = dp[i - 1] as number[]; // 윗 줄 — 이 물건을 아직 안 본 세계
    const cur = dp[i] as number[]; // 이번 줄 — 이 물건까지 본 세계

    for (let c = 0; c <= W; c++) {
      if (c < w) {
        // ① 못 담는다 — 남은 용량이 이 물건의 무게보다 작다. 윗 줄을 그대로 물려받는다.
        cur[c] = prev[c] as number;
      } else {
        const skip = prev[c] as number;
        const take = (prev[c - w] as number) + v;
        // ② 두고 가는 쪽이 크거나 같다 · ③ 담는 쪽이 크다
        cur[c] = skip >= take ? skip : take;
      }
    }
  }

  return (dp[n] as number[])[W] as number;
}
```

## 한 입력으로 끝까지 굴려 보기

`knapsack01([1, 3, 4, 5], [1, 4, 5, 7], 7)` 을 끝까지 따라간다. 표는 5줄 × 8칸이고,
오른쪽에 그 칸이 어느 갈래로 정해졌는지를 함께 적었다.

<!--viz:table-->
```text
        c=0  1  2  3  4  5  6  7      갈래
  i=0     0  0  0  0  0  0  0  0      ········   (기저)
  i=1     0  1  1  1  1  1  1  1      ①③③③③③③③
  i=2     0  1  1  4  5  5  5  5      ①①①③③③③③
  i=3     0  1  1  4  5  6  6  9      ①①①①②③③③
  i=4     0  1  1  4  5  7  8  9      ①①①①①③③②
                                ↑ dp[4][7] = 9
```

<!--result:table=9-->

| 단계 | 무슨 일 | 조건 판정 | 정해진 값 |
| --- | --- | --- | --- |
| T1 | `i=1` (w=1,v=1), `c=0` | `0 < 1` 참 → ① | `dp[1][0] = dp[0][0] = 0` |
| T2 | `i=1`, `c=1` | `1 < 1` 거짓 · `skip=0`, `take=dp[0][0]+1=1` · `0 >= 1` 거짓 → ③ | `dp[1][1] = 1` |
| T3 | `i=2` (w=3,v=4), `c=2` | `2 < 3` 참 → ① | `dp[2][2] = dp[1][2] = 1` |
| T4 | `i=2`, `c=3` | `skip=1`, `take=dp[1][0]+4=4` · `1 >= 4` 거짓 → ③ | `dp[2][3] = 4` |
| T5 | `i=3` (w=4,v=5), `c=4` | `skip=5`, `take=dp[2][0]+5=5` · `5 >= 5` 참 → ② | `dp[3][4] = 5` |
| T6 | `i=3`, `c=7` | `skip=5`, `take=dp[2][3]+5=9` · `5 >= 9` 거짓 → ③ | `dp[3][7] = 9` |
| T7 | `i=4` (w=5,v=7), `c=5` | `skip=6`, `take=dp[3][0]+7=7` · `6 >= 7` 거짓 → ③ | `dp[4][5] = 7` |
| T8 | `i=4`, `c=7` | `skip=9`, `take=dp[3][2]+7=8` · `9 >= 8` 참 → ② | `dp[4][7] = 9` |
| T9 | 읽기 | — | `dp[4][7] = 9` 를 돌려준다 |

**세 갈래가 모두 나왔다.** `①`은 T1·T3, `②`는 T5·T8, `③`은 T2·T4·T6·T7 이다.

```text
표 전체 32칸의 갈래 분포
  ①  못 담는다        13 칸
  ②  두고 가는 쪽     2 칸    ← 가장 드물다
  ③  담는 쪽          17 칸
```

T5가 이 알고리즘의 미묘한 자리다. 두고 가도 5, 담아도 5라 값이 같다 — 무게4·가치5 하나를
담는 것과 무게1·가치1 + 무게3·가치4 를 담는 것이 같은 가치이고, 동점이라 `>=` 가 두고 가는
쪽을 골랐다.

T8은 **마지막 물건이 답에 안 들어간다**는 것을 보인다. 무게5·가치7 을 담으면 남은 용량이
2뿐이라 `dp[3][2] = 1` 밖에 못 얹어 8이고, 두고 가면 9다.

## 비용 계산

### 비용을 세는 과정

한 번의 호출이 하는 일은 셋이고, 셋을 다 더해야 총식이 된다.

| 하는 일 | 비용 |
| --- | --- |
| 표 만들기 | `(n+1)(W+1)` 칸을 0으로 채운다 |
| 표 채우기 | 바깥 `n` 번 × 안쪽 `W+1` 번. T1~T8 이 그 칸 하나하나다 |
| 읽기 | `dp[n][W]` 한 칸. `O(1)` |

칸마다 하는 일은 비교 한두 번과 덧셈 한 번이라 상수다. T1~T8 어느 칸을 봐도 `①` 이든
`③` 이든 하는 일이 같아서, 입력이 바뀌어도 칸당 비용이 흔들리지 않는다.

```text
총식 = O((n+1)(W+1))  +  O(n(W+1))  +  O(1)   =  Θ(nW)
             ↑ 할당           ↑ 채우기      ↑ 읽기

n = 100, W = 10^4  →  101 × 10001 = 1,010,101 칸
```

**메모리도 같은 크기다** — $\Theta(nW)$ 칸을 실제로 들고 있다. 이 제약에서는
`1,010,101 × 8바이트 ≈ 8MB` 라 256MB 안에 들어간다.

답만 필요하면 줄 두 개(`prev`·`cur`)로 줄여 $\Theta(W)$ 로 만들 수 있다. 그러면 표를
되짚어 "무엇을 골랐는지"를 복원할 수 없게 되는 것이 값이다.

### 케이스별 비용과 그 경계

**케이스**(어떤 입력인가)와 **경계**(어떤 종류의 값인가)는 다른 축이다.

| | 상한 $O$ | 타이트 $\Theta$ |
| --- | --- | --- |
| **최선** (예: 모든 물건이 `W` 보다 무겁다) | $O(nW)$ | $\Theta(nW)$ |
| **평균** (입력을 아무렇게나 뽑아도) | $O(nW)$ | $\Theta(nW)$ |
| **최악** (어떤 입력이든) | $O(nW)$ | $\Theta(nW)$ |

**세 줄이 같다.** 이 알고리즘은 입력을 보고 일찍 끝내는 자리가 없어 표 `(n+1)(W+1)` 칸을
언제나 한 번씩 채운다. 모든 물건이 용량보다 무거워 답이 0이어도 칸 수는 그대로다 —
그때도 `①` 갈래로 윗 칸을 복사하는 일을 칸마다 한다.

**보장의 종류는 최악 보장이다.** 기대값이 아니다 — 코드에 무작위성이 없고 입력 분포를
가정하지도 않는다. 같은 입력에 몇 번을 돌려도 같은 칸 수를 채운다.

```text
nW 의 W 는 입력의 "크기" 가 아니라 "값" 이다

  용량 10000 을 적는 데 글자 5 개        →  표의 열 10001 개
  용량 1000000000 을 적는 데 글자 10 개  →  표의 열 10^9 + 1 개
        ↑ 글자는 두 배인데 표는 10^5 배
```

그래서 이 알고리즘은 **의사다항(pseudo-polynomial)** 이라고 불린다. 입력을 적은 글자 수를
기준으로 보면 지수적이다.

### 최악을 만드는 입력

"어떤 입력이 최악인가"라는 물음이 이 알고리즘에서는 **입력의 내용과 무관**하다. 무게와
가치를 어떻게 배치해도 채우는 칸 수가 같기 때문이다.

```text
최악 = 크기 둘이 제약 최대일 때
       n = 100 · W = 10^4  →  101 × 10001 = 1,010,101 칸

이때 물건 값은 아무래도 좋다. 아래 둘은 칸 수가 정확히 같다.
  weights = [1,1,...,1]          values = [1,1,...,1]          → 1,010,101 칸
  weights = [10^4,...,10^4]      values = [10^4,...,10^4]      → 1,010,101 칸
       ↑ 전부 담긴다                    ↑ 하나만 담긴다
```

앞의 것은 모든 물건이 담기고 뒤의 것은 하나만 담기는데, 걸리는 일은 같다. "정렬된 입력이
최악"처럼 자료의 모양을 탓하는 통념이 여기서는 통하지 않는다.

**진짜 최악은 제약 밖에 있다.** 이 문제는 `W ≤ 10^4` 로 막아 두었지만, 같은 코드에
`W = 10^9` 을 주면 표 할당에서 먼저 죽는다 — `100 × 10^9` 칸은 배열로 잡을 수 없다.
**이 알고리즘의 최악은 용량 값 하나가 정한다.**

## 한 곳을 바꿔 보면

담는 쪽 값을 가져오는 줄을 **윗 줄에서 같은 줄로** 한 글자만 바꿔 본다.

```ts
const take = (cur[c - w] as number) + v;
//             ↑ prev 였다
```

무게 `[1, 3, 4, 5]`, 가치 `[1, 4, 5, 7]`, **용량 10** 으로 돌리면 이렇게 나온다.

```text
바른 코드   13
한 줄 바꿈  14      ← 있지도 않은 가치가 1 더 나왔다
```

`14` 는 무게1·가치1 짜리를 **두 번** 담아서 나온 값이다. `cur[c - w]` 는 "지금 물건까지
이미 고려한" 값이라, 거기에 다시 가치를 더하면 같은 물건을 한 번 더 담게 된다.

```text
같은 입력, 용량 7 에서는

바른 코드    9
한 줄 바꿈   9      ← 값이 같다. 버그가 안 보인다
```

용량 7에서는 중복해 담을 여유가 없어 버그가 드러나지 않는다. **한 입력에서 값이 같다고
코드가 옳은 것은 아니다** — 무엇을 바꿨는지 알고 있어야 어디를 봐야 하는지도 안다.

덧붙이면 이 변형은 틀린 코드가 아니라 **다른 문제의 정답**이다. 물건이 무한히 있는
무한 배낭에서는 같은 물건을 여러 번 담는 것이 허용되므로, 그 문제에서는 이쪽이 옳다.

## 스스로 점검하기

이 알고리즘의 전부는 문장 하나다.

```text
"앞의 i 개로 용량 c 를 쓴 최선" 을 표에 적어 두면
새 물건 하나에 대한 선택은 두고 가거나 담거나 둘뿐이고
둘 다 윗 줄만 보면 된다.
        ↑ 윗 줄이 같은 물건을 두 번 담지 않게 막는다
```

**문제 1.** 무게 `[2, 3]`, 가치 `[3, 4]`, 용량 `5` 의 표를 손으로 채우고 답을 구하라.

<!--check:s1-->
답: `7` 이다.

```text
        c=0  1  2  3  4  5
  i=0     0  0  0  0  0  0
  i=1     0  0  3  3  3  3      (무게2·가치3)
  i=2     0  0  3  4  4  7      (무게3·가치4)

dp[2][5] :  skip = 3
            take = dp[1][5-3] + 4 = dp[1][2] + 4 = 3 + 4 = 7   ← 담는 쪽
```

마지막 칸이 담는 쪽을 골랐으므로 둘 다 담은 것이고, 무게 5·가치 7이다.
<!--/check-->

```text
물음 2.  본문 T5 에서 skip 과 take 가 둘 다 5 였다.
         코드가 skip >= take 대신 skip > take 였다면
         dp[3][4] 의 "값" 이 달라지는가?
```

<!--check:s2-->
답: 값은 안 달라진다. 두 후보가 같은 값이면 어느 쪽을 골라도 그 칸에 같은 수가 적힌다.

```text
같은 값이 두 경로에서 나올 때
  한쪽을 고르든 다른 쪽을 고르든  →  칸에 적히는 수는 같다
  달라지는 것은 "그 수가 어떤 선택을 뜻하는가" 뿐이다
```

최대 가치만 반환하는 이 함수에서는 차이가 없고, 표를 되짚어 고른 물건 목록을 복원하는
코드를 얹을 때만 답이 갈린다.
<!--/check-->

```text
물음 3.  용량이 10^9 이고 물건이 10 개뿐인 입력이 왔다.
         이 표를 그대로 쓸 수 있는가?
```

<!--check:s3-->
답: 쓸 수 없다. 열이 `10^9 + 1` 개라 표를 만들 수조차 없다.

```text
물건 10개  →  조합 2^10 = 1,024 가지
              「생각이 닿는 경로」 에서 버렸던 완전 열거가 오히려 답이다

물건이 더 많다면  →  가치 축으로 뒤집는다 (가치 합이 작으면 표가 짧아진다)
```
<!--/check-->
