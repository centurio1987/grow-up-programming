## 3. 사람이 봐야 하는 것

기계가 못 잡는 것 중 **판정이 갈리지 않는 것만** 남긴다. 확인 질문의 답이 사람마다 다르면
그 줄은 여기 두지 않는다 — 그런 줄이 열둘이었고 R19 로 전부 걷어냈다.

**2026-08-29 로 셋이 기계로 내려갔다**(`L38`~`L40` · `P11`~`P13`). 줄을 지우지 않고 **내려간 몫만 뺐다** — 같은 줄에 남은 몫이 있고, 지우면 그것이 아무 데도 안 남는다.

**「옛 `V…`」 로 시작하는 넷은 이해 시험이 걷히면서 내려온 것이다**(2026-08-29 유저 지시,
`SPEC` §0). 걷어낸 규칙을 되살린 것이 아니라, 외부 모델이 보던 몫 중 **실행으로 못 내리는
것**이 여기로 온 것이다. 값을 보던 몫은 `check-proof.ts` 가 진다.

## 5. 조건부 절 판정 — 편마다 실제로 확인한 결과

`L34`·`L35`·`L36`(2026-08-28 지시 R20~R22)은 **절을 실을지 말지**를 정하는 규칙이라, 편마다
판정을 남긴다. 판정을 안 적으면 다음 편에서 「그냥 넣던 대로」 넣게 된다.

| 편 | `purpose.alt` (`L34`) | `related` (`L35`) | `deep.math` (`L36`) |
| --- | --- | --- | --- |
| `mosAlgorithm` | **싣는다** — 펜윅과 `n=5` 에서 11 대 25, `n=400` 에서 6,895 대 4,850 으로 **순서가 뒤집힌다** | **싣는다** — 제곱근 분할 | **싣는다** — `qB = n²/B` 를 풀어 `B = √n` 을 낸다 |
| `knapsack01` | **싣는다** — 가치 축과 용량·가치 합의 크기에 따라 갈린다(용량 `10^9`·가치 합 100 이면 뒤집힌다) | **싣는다** — 마르코프 성질 | **싣는다** — 집합 정의로 전이식을 유도하고 `n` 을 일반화해 칸 수 대 `2^n` 을 낸다 |
| `quicksort` | **싣는다** — 병합 정렬과 비교 49 대 52 · 추가 칸 64 대 0 으로 **축마다 갈린다** | **싣는다** — 선택 알고리즘 | **싣는다** — `T(n)` 을 두 극단에서 닫힌 형태로 푼다 |
| `babyStepGiantStep` | **싣는다** — rho 와 곱셈 155 대 408 · 저장 101 대 6. `m` 이 커지면 이쪽이 실행 불가 | **싣는다** — 중간에서 만나기 | **싣는다** — `n = m/n` 을 풀어 `n = √m` 을 낸다 |
| `binarySearch` | **싣는다** — 보간 탐색과 균등 입력에서 읽은 칸 1,024 대 9,228, 편향 입력에서 10,026 대 9,228 로 **순서가 뒤집힌다** | **싣는다** — 단조 술어와 이분법 | **싣는다** — `R(n,k) = max(k-1, n-k)` 를 최소화해 `C(n) = ⌊log₂ n⌋ + 1` 을 낸다 |
| `longestSubarrayAtMostSum` | **생략** — 경쟁 설계(접두사 합 + 이분 탐색 · 답 길이 이분)가 시간·메모리 **두 축 모두에서** 밀리고 입력·제약을 바꿔도 안 뒤집힌다 | **싣는다** — 분할 상환 분석 | **싣는다** — `lo(r)` 의 비감소를 유도하고 망원 합으로 `n + (lo(n−1) − lo(0)) ≤ 2n` 을 닫는다 |
| `bfsShortestPath` | **생략** — 다익스트라는 무가중치에서 모든 축이 열세이고, 가중치가 붙는 것은 우열이 뒤집히는 것이 아니라 BFS 가 **그 문제를 못 푸는 것**이다 | **싣는다** — 거리 층 | **싣는다** — 악수 보조정리로 `V+E` 를 임의의 `V`·`E` 로 일반화한다 |
| `nQueens` | **싣는다** — 앞을 내다보는 검사와 `n=8` 에서 방문 노드 2,057 대 1,165 · 새로 잡는 칸 0 대 13,792 로 **축마다 갈린다** | **싣는다** — 제약 충족 문제(CSP) | **싣는다** — `S(n) = ⌊e·n!⌋` 을 닫고 `n=12` 에서 1,521배를 낸다 |

| `parametricBinarySearch` | **싣는다** — 동적 계획법과 작은 입력에서 기본 단계 46 대 132, 큰 입력에서 5,100 대 1,228,060 으로 **순서가 뒤집힌다**. 경계는 `NK` 와 `log(ΣA)` 의 대소다 | **싣는다** — 탐욕이 앞선다 논법 | **싣는다** — 판정 함수의 단조성을 유도하고 `P(s) = ⌊log₂ s⌋ + 1` 을 닫아 `T(N,S) = Θ(N log S)` 를 낸다 |

**넷 다 세 절을 유지한다.** `L34` 의 판정 질문(우열이 실제로 뒤집히는가)에 넷 다 값이나
조건으로 답이 있었고, `L36` 의 질문(본문 값만으로는 안 나오는 것을 주는가)에도 넷 다 답이
있었다 — 앞의 셋은 최적값을 풀거나 닫힌 형태를 내고, `knapsack01` 은 임의의 `n` 으로 일반화한
칸 수를 낸다.

**`knapsack01` 의 `deep.math` 가 가장 아슬아슬했다.** 전이식 자체는 파트 1 이 이미 값으로 다
보였으므로, 그 절이 주는 것은 ① 집합 정의(본문에 없다) ② `S` 를 두 무리로 가르는 유도
③ `n = 4·20·100` 에서 칸 수와 `2^n` 을 나란히 놓은 표(본문에 없다) 셋이다. 이 셋이 없어지면
절을 뺐어야 한다.

**W1 배치1 에서 `purpose.alt` 가 처음 생략됐다(2026-08-29).** `longestSubarrayAtMostSum` 과
`bfsShortestPath` 둘이고 **사유가 서로 다르다** — 앞은 SPEC 표의 「모든 축에서 한쪽이 낫다」이고,
뒤는 대조가 아니라 **적용 범위**의 이야기다(가중치가 붙으면 BFS 가 그 문제를 못 푼다).
둘 다 `.alt.ts`·`.bench.json` 을 만들지 않아 `P10` 이 잡을 잔여물이 없다. 파일럿 넷이 전부 세 절을
유지했으므로 생략 경로가 실제로 돈 것은 여기가 처음이다.

**배치1 의 판정 4행이 §4 재작성률 표에 잘못 붙어 있던 것을 배치2 에서 이 표로 옮겼다
(2026-08-29).** 열 구성이 다른 표라 그대로 두면 §4 가 깨진 채로 서고, 다음 배치가 그 자리를
보고 또 §4 에 넣는다. 행의 내용은 한 글자도 고치지 않았다.

**W1 배치2 에서 `purpose.alt` 생략이 세 번째로 돌았다(2026-08-29).** `maxCounters` 하나이고
사유는 `longestSubarrayAtMostSum` 과 같은 부류다 — SPEC 표의 「모든 축에서 한쪽이 낫다」.
다만 **여기서는 경쟁 후보를 세우는 일 자체가 갈렸다**: 이 문제의 느린 풀이(즉시 채우기)는
경쟁 설계가 아니라 같은 설계의 최악이고 그 대조는 `deep.math` 가 이미 값으로 하고 있다.
경쟁 설계로 세울 수 있는 것은 구간 갱신 자료구조뿐인데 그것이 모든 축에서 밀린다.
**「대조할 것이 없다」와 「대조했더니 한쪽이 다 낫다」는 다른 판정이고, 둘 다 생략으로 간다.**

**공통 원인은 최소 변경이다.** 지적을 인스턴스로 처리하고 부류로 처리하지 않았다. §3 목록을
편마다 대조하는 것이 그 대책이고, 기계로 옮길 수 있는 것은 옮긴다.
