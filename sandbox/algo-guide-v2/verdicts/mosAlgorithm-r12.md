[V1] PASS
> 인용: "질의마다 그 구간을 처음부터 다시 훑어 집합에 넣는다. 구간 하나가 최대 n 칸이니 이렇게 쌓인다." / "질의 하나에 최대 n 칸  →  q × n = 10^4 × 10^4 = 100,000,000 칸"

[V2] FAIL
> 인용: "같은 입력(n = 400, q = 200, 고정 시드)에 둘을 걸고 기본 연산 횟수를 셌다... Mo (블록 + r) | 포인터 이동 칸 | 6,895 ... 펜윅 트리 | 트리 노드 방문 | 4,850 ... **이 문제에서는 펜윅이 이긴다.** 1.4배 적다."
> V2는 "왜 이 알고리즘이 이기는지가 같은 입력의 수치로 대조돼 있는가"를 묻는데, 원문의 수치 대조는 정반대로 **Mo가 진다**는 것을 보여줍니다. Mo를 택하는 이유("일반성이다")는 같은 입력의 수치 비교가 아니라 질의 종류별 된다/안 된다 표(정성적 근거)로 제시됩니다. 요구된 것(같은 입력에서 이 알고리즘이 이기는 수치)이 본문에 없고, 오히려 반대 사실이 적혀 있습니다.

[V3] PASS
> 인용: "창이 비어 있을 때(curL = 0, curR = -1) 맵도 비어 있고 distinct = 0 이라 성립한다. 그 뒤 창은 한 칸씩만 바뀌고, 한 칸이 바뀔 때 add 나 remove 가 정확히 한 번 불린다. add 는 개수를 1 늘리고 그 값이 0에서 1이 될 때만 가짓수를 늘리며, remove 는 반대다." / 엣지 케이스 표: "`n = 1` | `block = max(1, ⌊√1⌋) = 1` | 0으로 나누는 일이 없다"

[V4] PASS
> 인용: "창 [0,2] = [1 1 2]      Set = {1, 2}        size 2  ✓ ... 창 [1,2] = [1 2]        Set = {2}           size 1  ✗  (답은 2)" / "count 맵  [3, 2, 3, 2, 2]      ← 정답 ... Set       [3, 2, 2, 1, 1]      ← 뒤 세 개가 틀렸다"

[V5] PASS

[V7] PASS

VERDICT: FAIL
