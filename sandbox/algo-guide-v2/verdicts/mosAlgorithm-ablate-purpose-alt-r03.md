## [V1] PASS
> 인용: "질의하나에 최대 n 칸 → q × n = 10^4 × 10^4 = 100,000,000 칸" / "1억 칸이다"

단순한 방법(각 질의마다 구간 처음부터 다시 훑기)과 그 비용이 구체 수치로 제시됨.

---

## [V2] 근거 없음
> 다른 절차의 실명이 없음

본문은 "다시 세기"와 "창 옮기기" 같은 설명만 제시할 뿐, 다른 알고리즘의 이름을 명시하지 않습니다. "이해 점검"에서 "정렬하지 않은 경우(43,409칸) vs 블록+r 정렬(6,895칸)"을 비교하지만, 둘 다 같은 알고리즘(창 옮기기)이고 정렬 여부만 다릅니다. 세그먼트 트리·펜윅 트리 같은 다른 알고리즘은 명시되지 않았습니다.

---

## [V3] PASS
> 인용 (논증): "창이 비어 있을 때(curL = 0, curR = -1) 맵도 비어 있고 distinct = 0 이라 성립한다. 그 뒤 창은 한 칸씩만 바뀌고, 한 칸이 바뀔 때 add 나 remove 가 정확히 한 번 불린다. ... 매 칸 이동 뒤에도 두 문장이 유지된다"

> 인용 (엣지): 표로 제시된 네 경우(질의 0개, l=r, 모든 값이 같음, n=1)와 각 처리 방법

---

## [V4] PASS
> 인용 (오해): "Set 하나면 된다. 넓힐 때 add, 좁힐 때 delete, 답은 set.size"

> 인용 (반례): "arr = [1 1 2 1 3] / 창 [0,2] = [1 1 2] Set = {1, 2} size 2 ✓ / 창 [1,2] = [1 2] Set = {2} size 1 ✗ (답은 2)"

구체 입력, 오해의 결과값(1), 정답(2)이 모두 제시됨.

---

## [V5] PASS
> 인용: "const add = (value: number): void => { ... distinct++; // ← if (next === 1) 을 지웠다 }; / 바른 코드 [3, 2, 3, 2] / 조건 지움 [6, 3, 6, 4]"

한 곳 바꾼 코드와 잘못된 결과값(실제 값 [6, 3, 6, 4])이 제시됨.

---

## [V6] PASS
> 인용: 13개 단계(T1~T13)의 표. 각 행이 "조건 판정 → ① 또는 ②" → 상태값(창·distinct) 형태로 구성. 마지막 "①은 T1·T2·T3·T5·T8·T9에서, ②는 T6·T11·T12에서 밟았다"

각 단계의 상태값, 분기 조건의 참/거짓(예: `curR = -1 < 2` 참), 넓히기①과 좁히기② 모두 나타남.

---

## [V7] PASS
> 인용 (세기): "총식 = O(q log q) + O((n + q)√n) + O(이동 칸 수 × 맵 1회)"

> 인용 (경계): "| **최악의 경우** | O((n+q)√n) | Θ((n+q)√n) — 이동 상한을 실제로 채우는 질의 집합이 있다 |"

> 인용 (보장): "창 이동 상한은 최악 보장이지만, 셈 갱신에 쓰는 해시 맵의 한 번 두드리기는 평균 O(1) 이다"

비용 세기의 근거(정렬·이동·맵), 경계의 종류(O vs Θ), 보장의 종류(최악 vs 평균)이 구분됨.
