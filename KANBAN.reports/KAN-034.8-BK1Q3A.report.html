3. 스캐너 구멍을 W3 앞에 두는 이유

S1~S7 을 W3 뒤로 미루면 남은 30편이 같은 구멍을 그대로 통과해 쌓인다. 원문자 라벨은 이미 21편에 남았고 그 21편은 전부 W1·W2·W3 앞부분에서 나온 것이다 — 규칙이 없는 동안 쓰인 편은 예외 없이 그 상태다. 규칙을 지금 세우면 30편은 교정 대상이 되지 않는다.

반대 방향의 비용은 작다. S1~S7 이 건드리는 것은 tools/ 와 이미 선 81편이고, W3 이 건드리는 것은 아직 안 선 30편이다. 겹치는 파일은 FEEDBACK.md 와 KANBAN.md 둘뿐이며 둘 다 줄 단위 추가라 편별 되돌리기가 서로를 깨지 않는다(KAN-034.7 전략 11항과 같은 판단).

4. 교정이 규칙보다 먼저다

규칙을 먼저 세우면 bun run tools/ci.ts all 이 기존 21편 때문에 빨간 채로 남고, 그동안 W3 편을 닫는 세션이 그 빨강을 자기 것으로 오인한다. 그래서 순서는 교정 → 규칙 → 회귀 시험 이다. S1(교정)과 S2(규칙)를 나눈 것, S3(교정)과 S4(규칙)를 나눈 것이 그 이유다.

S5~S7 은 새 검사라 위반이 몇 편에 있는지가 착수 전에 안 나온다. 각 work 의 첫 걸음이 전수 스윕이고, 스윕 결과가 그 work 안에서 교정으로 이어진다.

5. 원문자 라벨 — 무엇으로 바꾸는가는 60편이 정한다

SPEC.md:566 이 invariant 절에서 원문자 라벨을 금지한다. 사유는 P4 가 deep.walk 에서 같은 토큰을 뽑기 때문에 절 경계가 오염된다는 것이다. 그런데 P4 는 deep.walk.final 의 코드 펜스에서만 라벨을 모으므로(tools/check-v2.ts:934) 다른 절의 원문자는 넷 다 초록으로 지나간다.

10. 규칙의 구멍은 그 규칙을 쓰는 쪽이 본다 — S11·S12 가 그것이다

2026-09-05 에 work 둘이 뒤에 붙었다. 근거는 이 카드가 아니라 형제 카드가 이 카드의 규칙을 실제로 써 본 결과다(KAN-034.7 배치4).

규칙을 세운 배치는 자기 규칙이 새는 자리를 못 본다. S7 이 변이 대조를 세운 날에는 78 개 블록이 중화에서 건너뛰어지는 것을 「변이에 매여 있음」으로 분류했고, S4 가 어간화한 날에는 관형형이 남은 것을 아무도 몰랐다. 둘 다 새 편 넷을 그 규칙으로 실제로 써 본 다음날 나왔다. 배치3 종료 문서가 「앞 work 가 세운 규칙이 뒤 work 의 글에 적용된다」로 적어 둔 것의 카드 사이 판본이고, 그래서 이 카드는 W3 이 도는 동안 닫히지 않는다 — 남은 26편이 같은 방식으로 구멍을 더 낼 수 있다.

S11 은 판단이 먼저다. 사이드카가 모듈 최상위에서 자기검사로 예외를 내면 중화 대조가 조용히 꺼지는데, 고칠 자리가 둘이라 어느 쪽인지 정해야 한다.

| 길 | 무엇을 | 대가 | | --- | --- | --- | | 도구 | check-proof 가 중화 실행의 예외를 삼키지 않고 위반으로 낸다 | 78 개 블록이 한꺼번에 빨개진다. 그 편들의 사이드카를 전부 고쳐야 통과한다 | | 관행 | 사이드카가 중화 여부를 값에서 알아내 자기검사만 건너뛴다(spfa 방식) | 새 편은 지키지만 옛 편 78 은 그대로 꺼진 채 남는다. 그것을 아는 방법이 문서뿐이다 |

S12 는 감사가 먼저다. 관형형 하나를 고치는 것이 아니라 어간 음절이 바뀌는 부류 전체를 찾아야 한다 — 「싼」을 막으면 다음에 「쌀」이 나오고 그것을 막으면 다른 어간에서 같은 모양이 나온다. S3 이 「부류가 아니라 패턴 자체의 문제」라고 적은 것과 같은 자리이고, 이번에는 패턴이 아니라 한글 활용의 형태 변화가 축이다. 11 부류 전부를 그 축으로 다시 훑는다.

bun test tools/check-v2.test.ts                      # 규칙을 세운 work
bunx --bun @biomejs/biome check <고친 경로>          # 새로 쓴 파일은 경고 0

규칙을 세운 work 는 회귀 시험이 없으면 안 닫힌다. 규칙을 코드에만 두면 다음 사람이 그것을 넓히다 조용히 되돌린다 — 은유 규칙이 다섯 번 샌 것이 그 이력이다.

배치 하나를 닫을 때

bun run tools/check-v2.ts --all                      # 원문자·은유·열 정렬·ref 대조
bun run tools/check-metaphor.ts --all                # 규격·이력 산문까지
bun run tools/check-proof.ts --all
bun run tools/check-links.ts check

카드를 닫을 때 — 넷이 동시에 참이어야 한다

# ① 살아 있는 v1 산출이 0
find src/algorithms -name '*-guide.mdx' -not -path '*_deprecated*' -not -path '*_scratch*' | wc -l   # 0

# ② rhythm baseline 에 알고리즘 부채가 0
grep -c 'src/algorithms' tools/_baseline/guide-rhythm.tsv                                             # 0

# ③ _deprecated 알고리즘 몫이 0
find src/algorithms -path '*_deprecated*' -type f | wc -l                                             # 0

# ④ 전체 게이트
bun run tools/ci.ts all

②·③ 은 S9·S8 이 닫혀야 참이고 그 둘은 W3 에 걸린다. 배치3 까지 끝나도 카드는 안 닫힌다 — 그 상태가 정상이고, 보드에서는 배치4 가 남은 것으로 보인다.

파일을 지우거나 옮기기 전에

bun run tools/check-links.ts refs <경로|디렉터리>

손 grep 은 패턴을 빠뜨린다. _deprecated/ 107장 처분(S8)과 이월 셋(S10)이 이 스윕을 먼저 지난다.
