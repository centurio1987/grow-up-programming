전략

1. 그림 자리를 셋으로 가른다 — 도식은 필요한 곳에만. 이번 지적의 뿌리는 「ASCII 가 나쁘다」보다 「표·수식·도식이 될 것을 전부 ASCII 로 그렸다」에 있다. guideline 의 첫 규칙이 이것이다. 유저 결정(2026-09-28): 스크린샷 두 자리(「지금까지 버린 방법과 남은 방법」·「끝 둘을 다 자유롭게 두면」)를 포함한 비교 목록은 표로 바꾼다.

| 내용 | 형식 | 파일럿 | | --- | --- | --- | | 비교·대응 목록, 값 표 | 마크다운 표 | B 29 · 증명 값 표 10 | | 식 전개 | 수식 블록(KaTeX, 이미 파이프라인에 있음) | C 17 | | 절차 | 번호 목록 또는 ProcessSteps | D 4 | | 배열·구간·층의 공간 관계, 걸음 추적 | 새 패턴 도식 | 약 18 | | 규모별 수치 | 표 + BarChart(로그 척도) | 증명 규모 7 | | 변이 대조 | 표 유지 | 5 |

2. 도식은 정적 SVG 한 벌을 md·HTML 이 함께 쓴다. <name>-guide.fig.tsx 가 그림을 정의하고, 빌드가 SVG 파일(figs/<id>.svg)로 뽑아 커밋한다. md 는 ` + 이미지 링크, HTML 은 같은 SVG 를 인라인. 대화형 패널(viz)은 그대로 두고 그 폴백만 ASCII 대신 이 SVG 로 바꾼다. **책 빌더(tools/book/*)는 이 카드에서 손대지 않는다** — pre.gs-ascii 를 전제로 한 자리가 넷(build-book.ts:57·print-css.ts:155-245·fragment.ts:23·build-sample.ts:164`)이라 곁가지가 크고 파일럿 판정에 필요 없다. 「책에서 SVG 를 어떻게 인쇄하는가」는 KAN-058 앞의 별건으로 카드를 따로 만든다(fig 로 바뀐 파일럿이 책 빌드에서 어떻게 나오는지만 S14 에 기록).

3. 그림 데이터는 손으로 적지 않는다. 증명 블록 원칙을 그림으로 넓힌다 — 그림에 들어가는 값은 .ref.ts 실행에서 받고, SVG 를 다시 뽑아 커밋본과 글자 단위로 대조한다(신선도 게이트). 증명 대조는 펜스뿐 아니라 마크다운 표도 받게 넓힌다.

4. 렌더 경로는 스파이크로 먼저 정한다. 패키지의 칠 스타일시트는 useInsertionEffect 로 주입되고 그 상수가 export 되지 않아(~/resume/scripts/render-core.ts:4-8) 서버 렌더(renderToStaticMarkup)로는 칠이 안 나온다 — effect 가 안 돈다. 후보 순서: ① happy-dom(이미 devDependency)에서 createRoot 로 클라이언트 mount 한 뒤 주입된 <style> 과 계산된 CSS 변수(vvar)를 SVG 속성으로 굳혀 자립 SVG 로 뽑는다. 글자 폭은 resume 의 text-metrics 방식(고정 폭 표)을 따른다 → ② 안 되면 resume 처럼 Playwright 캡처. 판정 기준은 「같은 입력이면 바이트가 같은 SVG, 칠 있음」이다. CI 게이트는 경로에 따라 갈린다 — ①이면 원격 CI 가 재렌더해 커밋본과 대조, ②면 원격 CI 에 브라우저가 없으므로 .fig.tsx·데이터·토큰의 해시를 SVG 머리에 박아 커밋본 해시를 대조하고 재렌더 대조는 로컬 ci.ts 에서만 한다(S7 완료 기준).

5. 스타일 가이드는 코드가 정본, 생김새는 claude-design 이 준다. design/viz/(resume 의 design/style-guide 와 같은 자리)에 tokens.ts → algo.viz.tsx(VisualizationStyleGuide: foundations · extendedFoundations · guidelines · visualMotif · components). 시안이 오기 전에는 지금 가이드 토큰(--gs-*, build-html.ts:530)에서 임시 foundation 을 파생해 패턴·파이프라인을 먼저 세우고, 시안이 오면 토큰만 갈아 끼운다 — 시안을 기다리며 멈추지 않는다.

6. 새 패턴은 넷, 이 저장소에. src/_viz/patterns/ 에 P1 ArrayStrip · P2 RangeCover · P3 LevelTable · P4 StepTrace. 패키지 원형(Canvas·Node·Edge·useVizFoundation)으로 짓고, 패키지 type-meta 와 같은 모양(useWhen·avoidWhen·dataShape)의 메타를 달아 나중 승격을 쉽게 한다. 기존 유형(BarChart·ProcessSteps)은 스타일 가이드만 입혀 쓴다.

7. 규칙은 그림 정의부터 고친다. SPEC §4·§9·L10·L11·L19·deep.walk.step·deep.math, voice 규칙 3 과 device, 검사기의 「그림」 정의(P1·P6·P7·P15)를 「펜스 · 표 · `」로 넓힌다. voice 규칙 3 「모든 핵심 개념 직후 ascii art」는 **과장된 해석이었다**(유저, 2026-09-28: *"ascii art만 쓰도록 강요한 적은 없다"*) — 원뜻 「핵심 개념 직후 그림을 보인다(내용에 맞는 형식)」로 되돌린다. 원본 ~/.claude/authoring/voices/algorithm-guide-writer/` 개정은 유저 승인됨. ASCII 는 금지하지 않는다 — 코드 옆 짧은 실행 결과처럼 등폭이 맞는 자리는 남는다. 금지하는 것은 「표·수식·도식이 될 것을 ASCII 로 그리기」이고, 이것은 guideline + 검토가 진다(기계로 가르기 어려운 판단이라 게이트로 올리지 않는다).

버린 대안. ① 클라이언트 렌더만(HTML 에서만 그림, md·책은 ASCII 유지) — md·책에 문제가 그대로 남는다. ② 전부 Playwright — 원격 CI 에 브라우저를 올려야 하고 느리다(스파이크에서 ①이 안 될 때만). ③ 110편 동시 전환 — KAN-058 과 겹치고 파일럿 승인 전 규모를 키운다. ④ 새 패턴을 bbangto-ui 에 바로 — 유저가 저장소 먼저를 골랐다.
