   **중첩 들여쓰기가 뜻인 의사코드·나무 그림**(이 배치).
2. **`←` 를 정본에 있는 줄에 달면 `mutantSiteFailures` 가 검사를 건너뛴다**
   (`s === "" || inRef.has(s)` → `continue`). 지운 줄을 주석형으로 보여도 `s === ""` 로 역시
   건너뛴다 — **drop 변이는 자리 대조가 구조적으로 안 돈다.**
3. **기호의 「차원」이 어긋나는 부류** — `B` 를 바이트로 정의하고 개수로 쓴 자리를 스캐너 넷이
   전부 통과시켰다. `L21` 에 **단위 일치**를 명시적으로 넣을 자리다.
4. **정렬하며 세는 편은 「정렬 뒤 자리」와 「원래 자리」가 섞인다** — `countInversions` 에서
   `i`·`j` 를 `p`·`q` 로 적은 자리가 났다. `sortArray`·`insertionSort`·`kthSmallest`·
   `externalMergeSort` 가 같은 위험을 갖는다.
5. **비용 축이 메모리 안이 아닌 편의 `perf.bounds` 는 두 표가 필요하다** — 입출력 축은 `4N`
   이라 케이스가 안 갈리고 견주기 축만 갈린다. 한 표에 우겨 넣으면 「최선·평균·최악이 같다」만
   남는다.
6. **`check-proof --all` 이 2분 안에 안 끝난다**(111편 × 사이드카 두 번 호출). 편별 실행은
   즉시 끝난다. **CI 시간 예산을 볼 자리다.**

### 레일 실렌더 — 검토 4항 반려로 **42편 전수**를 다시 확인했다 (2026-09-10)

배치7 종료 뒤에 **한 편만** 열어 보고 닫았는데, 검토에서 「전부 열어 봐라」로 반려됐다.
127.0.0.1 로 원고 HTML 을 띄우고 42편을 순회하며 창 1440×900 에서 쟀다.

| 무엇 | 42편 실측 |
| --- | --- |
| 레일이 뜨는가 | 42/42 — `display`·`visibility` 정상, 폭 > 0 |
| 자리 | 42/42 — `position: fixed` · 오른쪽 절반 |
| 항목 수 | 42/42 — **12** |
| 끊어진 앵커 | 42/42 — **0** |

| 현재 절 표시 | 42/42 — 이동 뒤 그 항목 하나에만 붙는다 |

**한 편만 본 것으로는 못 봤을 것이 있었나 — 없었다.** 42편이 같은 렌더러를 쓰므로 결과가
같은 것이 자연스럽고, 헤딩 위치가 42편 전부 정확히 24px 인 것이 그 근거다. **그래도 전수를
본 값이 「한 편을 봤다」보다 세다** — 검토자가 그것을 요구한 자리다.

**측정 코드가 한 번 틀렸다.** 클릭한 앵커와 위치를 잰 헤딩이 달라서(`a:last-of-type` 이
부모별 마지막이라 실제 마지막 링크와 다르다) 42편 전부가 거짓 실패로 나왔다. 클릭하는 그
`href` 를 그대로 기억해 재도록 고치니 42편 전부 통과했다. **검사기가 틀려서 난 빨강을 원고의
빨강으로 읽지 않는 것**이 이 자리의 교훈이고, 배치9~11 이 `P15` 검사기에서 겪은 것과 같은
부류다.
