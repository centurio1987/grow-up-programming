## 2. 의존과 순서

`S2` → (`S3` ∥ `S4`).

- `S3` 은 `S2` 뒤여야 한다. `S3` 이 고칠 스캐너(`check-v2.ts` 외)가 `S2` 가 `tools/` 로 옮기는

## 3. 리스크

- **`S2` 가 되돌리기 가장 어려운 work 다.** 파일을 옮기고 `.mdx` 4개를 지우고 인덱스 링크를
  바꾼다. 지우기 전에 `bun run tools/check-links.ts refs <경로>` 로 참조를 훑는다 —
  손 grep 은 상대 import 를 놓친다(`KAN-031` 카드 메모의 실측 실패).
- **대상 파일이 0개면 `bun test <경로>` · `biome check <디렉터리>` 가 exit 1 이다.** 이관 도중
  빈 디렉터리가 생기면 통과가 실패로 보인다.
- **`bunx biome` 을 쓰지 않는다.** npm 의 `biome` 은 이 저장소가 설정한 `@biomejs/biome` 와
  다른 패키지이고 아무것도 검사하지 않고 exit 0 을 준다. `bunx --bun @biomejs/biome check` 다.
- `S3` 이 규칙을 너무 세게 걸면 파일럿 4편이 자기 규칙에 걸린다. **위반 0건이 곧 판정**이므로
  규칙을 통과시키려고 원고를 고치지 않는다 — 그 방향이면 규칙이 틀린 것이다.
