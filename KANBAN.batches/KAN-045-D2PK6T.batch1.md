### 확정한 명령 — 배치2 가 그대로 쓴다

```bash
bun run tools/check-citations.ts            # 존재 + 표류 검사. exit 0 통과 · 1 실패
bun run tools/check-citations.ts --update   # 대장을 지금 상태로 다시 쓴다
bun run tools/check-citations.ts --tsv      # 지금 상태의 대장을 stdout 으로
```

대장은 `tools/_baseline/citations.tsv` 하나이고 경로를 플래그로 받지 않는다. 플래그는 위 둘뿐이다.

### 이 work 가 남기는 위험 둘

1. **보류 134 건은 오늘 고치지 않는다.** 카드의 「하지 않는 것」대로다. 대신 **래칫**(대장 머리 주석
   `# bare 463 held detached=71 unresolved=48 naked-name=15`)이 늘지 못하게 묶는다. 래칫이 없으면 보류는
   조용히 자라는 쓰레기통이 되고, 「경로 없는 인용도 본다」는 둘째 기둥이 글자만 남는다.
2. **자기 해석이 틀리는 자리가 남는다.** 앞 줄에서 문장이 넘어와 같은 줄에 경로가 없는데 남의 파일을 가리키는
   인용은 기계가 가리지 못한다. 게이트 메시지가 **해석 근거(붙임/자기)** 를 함께 내서 사람이 `--update` 대신
   경로를 적도록 돌리는 것이 이 규격의 답이고, 총량은 `# bare 463` 래칫이 묶는다.

### 규격을 쓰면서 부딪힌 것 하나 — 기록

규격을 적는 문서가 **규격의 검사 대상이기도 하다.** 예시에 진짜 줄 번호를 쓰면 게이트가 그것을 인용으로 세고,
`# bare` 래칫 기준선이 이 문서 때문에 올라간다. 그래서 새 절의 예시는 전부 `NN` · `MM` 으로 적었고, 실측에서
경로 없는 인용이 463 그대로인 것이 그것이 먹었다는 증거다. 경로 인용은 13 건 늘었다(1,137 → 1,150).
