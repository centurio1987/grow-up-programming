## 1. 작업 패키지

### WP1 · `S5` 파일럿 ① `linear/deque`

**work 하나가 배치 하나인 이유는 이 편이 규격의 실물 시험이기 때문이다.** `KAN-033` 이
파일럿을 순차로 돌린 것과 같은 판단이다 — 첫 편에서 SPEC 이 흔들리면 배치1 의 `S2` 로
돌아간다. 셋을 함께 돌리면 그때 셋을 다 다시 쓴다.

**`deque` 를 첫 편으로 고른 근거**: 등급 `complexity` · 연산 8개 · **불변식 없음** ·
`ds-guide` spec 이 지정한 8단계 모범 예시다(`.claude/authoring/specs/ds-guide/spec.md:6-7`).
같은 구조의 8단계본과 v2본이 나란히 서므로 **두 골격의 직접 대조**가 된다. 불변식이 없어
`invariant` 절의 어려운 자리를 첫 편에서 만나지 않는다.

산출물은 여섯이다.

```
src/data-structures/linear/deque/
  deque-guide.md         원천. <!--viz:--> 마커가 md↔web 갈림점
  deque-guide.sim.ts     { view, steps, title, result }
  deque-guide.proof.ts   증명 블록의 출처. _reference/deque.ts 를 import 해야 한다
  deque-guide.test.ts    기존 테스트의 입출력 케이스를 정본에 재실행
  deque-guide.alt.ts     purpose.alt 를 싣는 경우에만 (조건부 — L34)
  deque-guide.bench.json 같은 조건
```

`.ref.ts` 를 만들지 않는다 — ds 의 정본은 `_reference/deque.ts` 이고 그것이 이미 서 있다.
`deep.walk.final` 은 그 파일의 `#region guide:core`(18~113행) 추출본이다.

## 3. 리스크

- **`deep.walk.step` 을 연산 8개마다 반복하면 편이 매우 길어진다.** 요청서가 분량 면제를
  명시했으므로 줄이지 않는다. 대신 **연산을 어떻게 묶는가**가 이 배치에서 정해진다 —
  `pushFront`/`pushBack`/`popFront`/`popBack` 을 한 묶음으로 볼지 넷으로 볼지는 규격이
  정하지 않았고, 여기서 실물로 정해 `S2` 의 SPEC 에 되먹인다.
- **SPEC 되먹임이 이 배치의 정상 산출이다.** 「규격이 안 흔들리는 것」을 목표로 두지 않는다 —
  흔들린 자리를 SPEC 에 반영하고 그 사실을 수행 내역에 남긴다.
- **`.mdx` 하나를 빼는 것이 `check-links` 를 깨뜨릴 수 있다.** 가이드 인덱스·문제_가이드_목록·
  상호 링크가 그 파일을 가리킨다. `refs` 를 **지우기 전에** 돌린다 — 손 grep 은 상대 경로를
  빠뜨린다(`tools/check-links.ts` 가 B11 에서 그 구멍을 메운 이력이 있다).
