## 1. 작업 패키지

### WP1 · `S3` 판정 장치 확장 — 파일 다섯 + 확인 둘

**`tools/section.ts` 가 먼저다.** 나머지 넷의 입력이다.

| 순서 | 파일 | 무엇을 |
| --- | --- | --- |
| 1 | `tools/section.ts` | `FIXED`·`PATTERNED`(`:34-68`)가 알고리즘 문구 하드코딩. `parseSections(text)` 에 `kind` 를 넣고 호출부 둘(`check-v2.ts:2211,2293`)을 옮긴다 |
| 2 | `tools/guide-v2-targets.ts` | 대상 집합에 `src/data-structures/**/*-guide.md` 추가. `v2Guides()` 는 `string[]` 유지, `kindOf(path)` 별도 export |
| 3 | `tools/check-v2.ts` | `kind` 로 매핑 분기 + ds 조항 둘 신설 + **P16 처리** |
| 4 | `tools/check-proof.ts` | ds 정본을 `_reference/<name>.ts` 로 가르고 `inRef` 앞에 `stripInstrumentation` |
| 5 | `tools/guide-core.ts` | 추출을 `deep.walk.final` 에 결속, 시뮬 검사(`:357`)를 `.md` 로 확장 |

**`tools/section.ts` 를 안 고치면 ds 편이 판정 자체를 못 받는다** — `:141` 이 미해소 헤딩을
`unresolved` 로 올려 그 자리에서 중단시킨다. 조용히 통과하는 것이 아니라 멈춘다.

**`v2Guides()` 반환형을 안 바꾸는 이유**는 호출부가 넷이기 때문이다 — `check-v2.ts:2294` ·
`check-proof.ts:925` · `check-metaphor.ts:385` · `build-html.ts:708-709`. `tools/ci.ts`
GATES 가 그 넷을 전부 `--all` 로 돌리므로 객체 배열로 바꾸면 한 커밋에서 넷이 같이 움직인다.
`kindOf(path)` 를 따로 내보내면 셋이 안 바뀐다.

**P16 이 이 WP 의 핵심이다.** 지금은 `${stem}.ref.ts` **파일 전체**를 정규화 비교하는데
(`:1179-1231`, 호출 `:2157`, 로드 `:2226`), ds 편에는 그 파일이 없어 `:2282` 의 「미실행」
참고 문구로 빠진다 — **안 잰 것이 통과로 읽힌다.** ds 에서는 `guide-core` 경로
(`#region guide:core` + `stripInstrumentation`)로 돌리고 정본 부재를 위반으로 올린다.

**`check-proof` 의 `__cost`**: ds `_reference/*.ts` 35편은 전부 `__cost` 를 갖는데 그 줄은
추출 때 걷히므로 원고가 절대 보여 주지 않는다. `mutantSiteFailures`(`:652-672`)가 `inRef` 를
구성하기 전에 `stripInstrumentation` 을 통과시키지 않으면, 대조 기준선이 원고가 볼 수 없는
줄을 포함한다.

**확인만**: `tools/check-metaphor.ts` · `tools/build-html.ts` — 2 의 방침이 지켜지면 변경이
없다. `bun run tools/ci.ts gates` 로 실제 무변경을 확인한다(안 본 것을 「변경 없음」으로
보고하지 않는다).

**완료 기준**: `bun test tools` 통과 + 고친 다섯 각각에 회귀 신설 +
`bun run tools/check-v2.ts --all` 이 알고리즘 111편에서 회귀 0.

### WP2 · `S4` 시뮬 이관 규격

`.mdx` 의 `export const steps` → `<name>-guide.sim.ts` + `<!--viz:{id}-->` 마커
(`tools/build-html.ts:178` 이 읽는 형식). ds `.mdx` **69/69** 가 `AlgorithmSimulation` 을
쓰므로 규격 없이는 전개가 막힌다.

`.sim.ts` 계약은 algo 와 같다 — `{ view, steps, title, result }`. **`steps` 는 인라인 배열
리터럴이어야 한다**(변수 참조·함수 호출·spread 금지). `ts-morph` 가 spread 를 과소 계수해
얇은 전개를 통과시킨 실측이 algo SPEC §5 에 있다.

ds 특유의 자리 하나: 자료구조는 연산이 복수라 **뷰 하나로 한 연산만 보이면 부족하다.**
`view` 를 배열로 주거나 `extraViews` 를 쓸지는 파일럿에서 정한다 — 규격에 미리 예외를 열지
않는다.

**완료 기준**: 파일럿 3편에서 실증되고 `bun test src/_guide-sim` 통과. 마커 id ↔ `.sim.ts`
export 키 ↔ ascii 펜스가 3자로 일치한다.

## 3. 리스크

- **`--all` 게이트 넷이 함께 흔들린다.** `v2Guides()` 반환형을 지키지 않으면 한 커밋이
  네 파일을 건드리고, 그중 하나가 틀리면 `ci.ts gates` 가 통째로 멈춘다.
- **알고리즘 111편 회귀.** `section.ts` 시그니처를 넓히는 것이 algo 판정에 영향이 없어야
  한다. `check-v2 --all` 을 `S3` 완료 기준에 넣은 이유다.
- **이 배치가 예산을 넘길 지점**은 `check-v2.ts` 다 — 2000줄이 넘고 ds 조항 둘 + P16 을
  함께 고친다. 넘치면 P16 을 `S3` 에 남기고 ds 조항 둘을 배치3 앞머리로 미룬다.
