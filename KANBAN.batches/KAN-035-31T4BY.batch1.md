### WP2 · `S2` `sandbox/ds-guide-v2/SPEC.md` — 델타 명세

algo SPEC 을 base 로 삼고 **갈리는 것만** 적는다. 공통 조항(`L24` 은유 · `L32` 헤딩
존댓말 · `L25` 표기 일관 · `L1` 분량 면제)은 절 번호로 걸고 옮겨 적지 않는다.

담는 것 다섯이다.

1. **항목 표** — order · id · 헤딩 · 필수 · fixed · parent. algo 23항목에서 갈리는 것은
   `deep.walk.step`(연산 묶음마다 반복) · `purpose.fit`·`purpose.cue`(직무 재정의) ·
   에스컬레이션(조건부 하위 절) 셋이다.
2. **id↔헤딩 매핑** — `tools/section.ts` 가 기계로 읽으므로 **완전해야 한다.** 델타 규칙의
   유일한 예외다.
3. **갈리는 절의 작성법** — 위 셋 + `deep.walk.final`(`_reference/` 추출) +
   `invariant`·`perf.*`(계약 헤더 결속).
4. **조건부 절 규약** — algo 셋(`related`·`deep.math`·`purpose.alt`)에 에스컬레이션이 붙어
   넷이 된다. 에스컬레이션의 조건은 **집필자가 고르지 않는다** — 규약4 등급이 켠다.
5. **L 조항** — 계승분은 algo SPEC 절 번호로 인용하고, ds 신설분은 `L41` 부터. **번호를
   재부여하지 않는다.**

에스컬레이션은 `docs/ORD-006-conventions.md:1171`(8단계 표 6번 행)과 `:1252-1275`(발동 조건 ·
첫 사례 `xorLinkedList` · 내용 셋)를 **인용**한다. 규격을 여기 다시 쓰면 그 자체가 이 명세가
내건 원칙의 위반이다.

**완료 기준**: `bun test tools` 에 회귀 하나가 새로 서고 통과한다 — ds SPEC 의 항목 전부가
`tools/section.ts` 매핑을 갖는가. 사람 대조가 아니라 종료코드로 판정한다.
